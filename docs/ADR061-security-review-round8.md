# Security review round 8: codex-security repository scan (2026-08-15)

**Status:** implemented (5 of 12 fixed in place; the rest repeats or extensions of standing dispositions) · **Scope:** disposition of the 12 findings (3 high, 7 medium, 2 low) from the codex-security static repository scan `eW0p9o` against revision `4561a4e7` (HEAD). Eighth pass in the ADR028 → ADR045 → ADR055 → ADR056 → ADR057 → ADR072 lineage.

## Round note

The three highs are all repeats of standing supply-chain deferrals (digest pinning, bootstrap-artifact verification) or extensions of round-6's operator-RBAC follow-up — no new high-severity class. The actionable core is five mediums that complete two seams this lineage has been tightening for three rounds: **decision freshness** (round-7 made the gateway resolvers fresh; this round extends fresh checks to the nine reveal/mint/destructive API sinks the scans kept missing — and makes the native-SSH transport re-authorize per channel, not per handshake) and **bounded upstream reads** (the observability sources were the last unbounded HTTP clients). Plus one new durable control: the signed git webhook now claims each delivery body, closing the replay the HMAC could never see. The recurring lesson from round 7 repeats itself: the four repeat findings are all _inventory_ problems (which images, which downloads, which identities), which is exactly why the deferrals carry explicit inventories now.

## Fixed in place

- **5** — `lego/backend/internal/sshgateway/nativessh/server.go`: round-7 #7 made `ResolveSSHSession` itself fresh, but it ran only at transport authentication (`VerifiedPublicKeyCallback`); the resolved target was serialized into `ssh.Permissions` and every later channel — up to the full `BEX_SSH_SESSION_TIMEOUT` (4h) — exec'd against that snapshot with no re-check. Every channel open (single- and multi-channel paths) now re-runs the two transport-auth checks through `Server.reauthorize`: the fingerprint's key is re-read from the store (deleting the key mid-connection stops new channels; the fingerprint rides the transport in a new `bex.fingerprint` permission) and the target is re-resolved through the same fresh-asserting resolvers — so each channel execs against the **current** pod, never the serialized one. A failure — key gone, membership revoked, target deleted, or the store unreachable (fail closed, like every fresh check) — rejects the channel with `Prohibited` and ends the whole transport with the new audit result `revoked`; in the multiplexed path a cancellable view of the session context tears down **active** channels too (cancel fires before the channel `wg.Wait`, so the wait cannot deadlock on channels that only end with their context). New metric `bex_ssh_gateway_channel_reauthorizations_total{result}`. Honest residual, unchanged in kind: a channel opened one second before a revocation still runs its own exec to completion — what closes is every _subsequent_ channel, which was the finding's ask.
- **7** — `lego/backend/internal/sshgateway/limiter.go`: the session limiter counts transports, but the expensive privileged resource is each pods/exec stream, and `BEX_SSH_MAX_CHANNELS_PER_CONN` (16) multiplied the budget: 5 connections × 16 channels = 80 streams per identity, 1,600 process-wide at the defaults. New `ChannelLimiter` (global `BEX_SSH_MAX_CHANNELS` default 512, per-identity `BEX_SSH_MAX_CHANNELS_PER_IDENTITY` default 32) acquired by **every** accepted session channel in both paths and released when its exec ends — a concurrency bound, not a lifetime quota (slots are reusable). The single-exec transports (webshell, sandboxsse, agentattach) stay bounded by the session limiter: their one exec IS their session slot. Shed channels get `ResourceShortage` without tearing down the connection (`bex_ssh_gateway_limit_rejections_total{scope="channel_global"|"channel_identity"}`), and a new `bex_ssh_gateway_active_channels` gauge exposes live exec streams — the observability the finding asked for.
- **8** — the round-5/6 freshness seam held an invariant ("reveal, durable-issuance, and destructive verbs re-check uncached") that these nine sinks never got; each now re-asserts immediately before its effect, using the established audit-silent `Authorize*Fresh` pattern. Two new core helpers mirror `AuthorizeAppFresh` for the datastores (`AuthorizeDatabaseFresh`, `AuthorizeKeyValueFresh` — the resource's own workspace via `core.LabelTenant`): `secrets.readAuthorizedEnvMap` (covers ListEnvVars/ListEnvVarsPage/GetEnvVar) and `secrets.GetSecretFile` (env/secret-file reveals), `postgres.CreateUser` (login mint + one-time password), `postgres.PostgresConnectionInfo` and `keyvalue.KeyValueConnectionInfo` (credential reveals), `envgroups.GetEnvGroupVar` (per-key reveal, against the group's owning workspace with the legacy fallback), `billing.Checkout` **and** `Portal` (hosted financial sessions — `Portal` is the same class and rode the same cached gate), `apps.Delete` (irreversible store+CR+OpenBao teardown), `members.Remove` (irreversible membership removal, the `Invite`/`ChangeRole` pattern). Residual, noted again: per-sink fresh checks are still applied by hand — the round-7 "no guard test enumerates credential-returning verbs" gap remains open, and this round's nine are evidence for prioritizing it.
- **9** — `lego/backend/internal/apps/webhook.go` + `store/migrations/0074`: the HMAC verified the body's bytes but nothing about freshness, and the only dedup key (`X-GitHub-Delivery`) is an unsigned header used for event facts — a captured (body, signature) pair resent with any header re-entered `redeployMatching`, stamping a new deploy generation (and a full rebuild) per replay. Mutating deliveries (push and the `delete` event) now claim `sha256(verified-key-class || body)` in the new `git_webhook_replays` table before acting: concurrent duplicates collapse to one mutation, a replay is answered 200 `{replayed: true}` so the host stops retrying, and a claim is released only when the branch answered 5xx (the host will redeliver, and that retry must not be swallowed by a claim whose work never happened). GitHub's deliberate "Redeliver" of the same body becomes idempotent — the intended semantics. Migration `0104` later bound the ledger without weakening that guarantee: unmatched repositories allocate nothing; claims are scoped per workspace, capped across live signing epochs, and a rotated epoch is purged only after no API-replica lease still accepts its secret. The finite pre-`0104` legacy partition remains because its original scope and epoch cannot be reconstructed safely. Store-less single-tenant operation (nil `Replays`) keeps byte-identical prior behavior; the claim is wired only when `BEX_CP_DB_URI` is set.
- **10** — `lego/backend/internal/core/http.go` + the observability packages: every Loki/Prometheus/egress source resolved a nil client to `http.DefaultClient` (no timeout) and decoded straight off `resp.Body` with no byte bound — request-_shape_ caps did not bound backend _output_, and the API's own WriteTimeout creates no upstream deadline. All nine constructors' nil-guards now resolve to the shared `core.UpstreamClient` (total 30s — these are buffered JSON reads, not streams — over the pooled `OryTransport`), and every decode goes through `core.DecodeUpstreamJSON`, which reads through `io.LimitReader` at 64 MiB and rejects oversized bodies explicitly (`ErrUpstreamResponseTooLarge`, never a silent truncation). The metrics-server snapshot path gets a per-call `context.WithTimeout(core.UpstreamTimeout)` (the shared clientset deliberately keeps no global deadline — watches ride it). Same fix in `egressquery` (which the usage/billing rollup calls per spec) and `usage.NewService`. Residual: client-go's buffered `DoRaw` body has no size cap (an in-cluster platform service; would need a rest-client response-size limit that doesn't exist) — documented, not fixed.

## Accepted, with rationale

- **4 (`onbex.co` cookie isolation)** — fifth report of the owner-waived risk, unchanged since ADR055 F9: control-plane cookies are host-only on the separate `api.bex.co` registrable domain, the blast radius is strictly tenant-to-tenant among `*.onbex.co`, and fail-closing the validator would take down all tenant hosting. The PSL submission remains the standing remedy and is tracked (`.pm/w1/050.md`, blocked on the external operator step).
- **12 (DNS registry names)** — the documented residual of round-7 #6's fix, restated by this scan at low: `ValidImage` refuses non-public IP literals and `localhost`, but an internal DNS name is lexically indistinguishable from a public one and stays allowed (BYO-image hosts are a deliberate ADR018 divergence). Closing it needs the node-level registry-origin policy / registry proxy the round-7 disposition already describes; nothing new to add.

## Deferred, with rationale

- **1 (mutable image inputs)** — same owner as ADR055 F7 / ADR057 #12 / round-7 #10: pinning needs the reviewed-digest update automation (multi-arch resolution + bump workflow) so pins don't rot, and that blocker is unchanged. This scan's affected-line list **extends the inventory** (completing it as the round-7 amendment did): the three Dockerfile `FROM`s (`lego/Dockerfile`, `dashboard/Dockerfile`, `lego/agent-image/Dockerfile` — the composed control-plane images), kpack's imported Paketo builder + stack (`deploy/gitops/charts/kpack/platform.yaml`), the barman-cloud-plugin upstream manifest image, the CNPG/barman job images in `database_controller.go` / `database_exports.go`, and `keyvalue_backup.go`'s busybox — in addition to the already-tracked BuildKit/git/cosign/skopeo/AWS-CLI set, the six `nativeRuntimeImages` language bases, and `nativePreparerImage` (pinned in round 7).
- **2 (day-to-day RBAC → node root)** — round-6 #4 deferred the operator's cluster-wide workload authoring to a `ValidatingAdmissionPolicy` follow-up because per-tenant dynamic namespaces preclude static Role scoping; this finding is the same authority reachable through the **day-to-day** credential (`operator-daytoday-rbac.yaml` holds cluster-wide Job creation + pods/exec, and the admission grammar matches only controller-manager). Mitigations already in place: round-6 #5 cut that token's TTL to 12h, and exploitation still requires credential theft. The round-6 #4 milestone's scope is hereby recorded as covering **every workload-authoring identity** (controller-manager and the day-to-day role): constrain Job creation, exec, privileged/host mounts, nodeName, tolerations, and service-account impersonation at admission, or scope the day-to-day role to read-mostly diagnostics.
- **3 (bootstrap downloads)** — the exact workflow lines were F14 of the 2026-08-10 scan, dispositioned as a grouped supply-chain residual in `.pm/w1/046.md`: "promote as a single milestone if a plausible upstream-compromise signal ever appears, or fold opportunistically into work that already touches these files." The two kubeconfig-fetch lines cited (app-cluster.yml:51, deploy.yml:479) are the exception — they already verify fail-closed via the mandatory SSH host-key pin (ADR055 F10, live since w1/m68). The repo's two verification precedents (`packer-plugin-install.sh`'s repo-pinned checksum file, `install-bex.sh`'s release `checksums.txt`) are the template for that milestone.
- **6 (admission invariants)** — the constructive half of round-6 #4: the `bex-build` namespace must stay privileged-Pod-Security for BuildKit, so containment has to come from the admission grammar, not the baseline. The grammar to build (recorded for the milestone): require `hostUsers=false` and exact tenant-node placement for privileged builds; reject `nodeName`, non-build tolerations, unapproved capabilities, and unconfined profiles; permit only the exact hardened BuildKit template as the exception — with user namespaces and tenant placement simultaneously enforced.
- **11 (metrics-server `--kubelet-insecure-tls`) — Closed by `w2/m81` (2026-08-19).** Was: unchanged from round-7 #5 — prod kubelets rotated self-signed serving certs and no kubelet-serving CSR approver existed. `w2/m81` executed the standing plan verbatim: CSR approver (`deploy/gitops/base/kubelet-csr-approver.yaml`) → `--kubelet-certificate-authority` (`deploy/gitops/base/metrics-server.yaml`, mounted from `kube-root-ca.crt`) → the local-overlay bypass dropped. See round-7 #5's full disposition (`docs/ADR072-security-review-round7.md`) for the residual: already-running prod nodes keep self-signed certs until a kubelet restart or the next ADR053 template rotation — not forced by this milestone.
