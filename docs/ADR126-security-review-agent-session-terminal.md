# ADR126: Security review — an agent session's Terminal ticket and the held WebSocket

- **Status**: Accepted (2026-11-23, w10/m615)
- **Trigger**: w10/m615 gives an agent session's page a Terminal ([ADR054 D10](ADR054-open-in-zed.md#d10--the-session-pages-terminal-wakes-a-closed-session-w10m615-2026-11-23)). The Browser Web Shell ([ADR035](ADR035-ssh.md#browser-web-shell)) gains a second target kind, bex-api's ticket mint starts a closed sandbox as the caller, and the gateway holds the WebSocket while the sandbox starts.
- **Lineage**: the gateway review chain, after [ADR124](ADR124-security-review-ssh-session-wake.md) reviewed the SSH wake (w10/m597). It keeps the Web Shell's invariants (ADR035): bex-api authorizes and signs but never holds `pods/exec`, the gateway re-authorizes every shell as the ticket's subject, the ticket is single-use across replicas, and no terminal content is logged or stored.

## Scope

`lego/backend/internal/shellticket/shellticket.go` (the `SessionID` claim and `Verify`); `agentsessions.Service.CreateShellSession` and `terminalSandbox` (`agentsessions/terminal.go`), its REST route (`rest.go`), GraphQL mutation (`graphql.go`) and the `terminalEnabled` capability; the route tables (`api/scope_matrix_ops.go`, `scope_matrix_overrides.go`, `key_permission_ops.go`); the gateway's Web Shell (`sshgateway/webshell/websocket.go`, `wake.go`) and its wiring (`cmd/ssh-gateway/main.go`); the idle close's activity query (`store/sshsessions.go` `AgentSessionSSHActivity`); the dashboard's Terminal (`dashboard/src/features/agent-sessions/components/session-terminal-sheet.tsx`, `common/components/shell-terminal.tsx`).

## What changed in the trust model

Before, a Web Shell ticket could name only a service, and the gateway's Web Shell could reach only `srv-…` instances. Now a ticket can name an agent session, and the gateway opens `/bin/sh` in that session's sandbox, the same exec an `ssh ags-…@ssh.bex.co` shell gets. Nothing new reaches the gateway: its role already reads `agent_sessions`, it already holds `pods/exec` in every `<ws>-sandbox` namespace (ADR054 D7), and native SSH already opens this exact target through the same resolver.

bex-api gains one effect behind the mint: it may start a closed sandbox, through the same `Service.Resume` the dashboard's and API's `resume` run, as the caller. It holds the caller's own identity when it does, so the start passes that caller's checks and is billed and audited as theirs. This is the reason the Terminal needs no gateway verb: unlike D9's wake, nothing has to vouch for an identity bex-api already authenticated.

## Verdicts

| # | Attack | Verdict | Evidence |
| --- | --- | --- | --- |
| 1 | A ticket for one session is used on another session, or on a service | Blocked | the session is a signed claim the gateway resolves, never a request parameter; `Verify` refuses a ticket naming both a session and a service, neither, or a session field that is not an `ags-…` id (`TestSessionTicketNamesOneAgentSession`); the gateway routes by the field, so a service ticket that names an `ags-…` id reaches the service resolver, which refuses it (`TestTerminalTicketsAreRoutedByTheirFieldAndSingleUse`) |
| 2 | The `srv-…` contract widens by accident (a new frame, a cap, a different refusal) | Not a gap | a service ticket takes the unchanged path: no wait, no cap, the same frames and refusals, and its JSON body is byte-identical (`TestServiceTicketEncodingIsUnchanged`); every pre-existing Web Shell test passes unchanged |
| 3 | A member who may not view the sandbox (a Contributor, a Viewer, another workspace) gets a shell, or learns the session exists | Blocked | the mint authorizes `can_view_sensitive` on the session before it reads the row, so a missing and a foreign session answer the same `403` (`TestTerminalNeedsCanViewSensitive`, `TestTerminalStartsAClosedSessionOnceAcrossTabsPG`); the gateway re-authorizes as the ticket's subject, cached and fresh, and refuses with one bare sentence (`TestTerminalRefusesAtConnect`); `TestRepresentativeVerbsGateOnExpectedRelation` pins the mint's relation |
| 4 | A member who may view the sandbox but not start a session forces a start | Blocked | a closed sandbox starts only through `Resume`, which checks `can_operate` and a fresh `can_create`; the mint refuses with D9's banner and starts nothing (`TestTerminalRefusesToStartAClosedSessionForAViewer`, `TestTerminalStartsAClosedSessionOnceAcrossTabsPG`) |
| 5 | A bex API key outside its grant opens a shell or starts a sandbox | Blocked | the mint needs Sandbox execution (`key_permission_ops.go`); the start inside it needs Agents manage too, read uncached (`TestTerminalHoldsABexAPIKeyToItsGrant`); the ticket names `sandboxes.exec`, which the gateway re-asks at connect, on every poll of a wait and on every revalidation tick (`TestTerminalWaitEndsWhenTheKeysGrantNarrows`, `TestStreamTicketMintsNeedTheActionTheGatewayHoldsThemTo`) |
| 6 | An OAuth delegation with `bex.sensitive` but not `bex.write` starts a sandbox through the shell mint | Blocked | the mint's scope class is `sensitive`, and `Resume`'s own `can_operate` check needs `bex.write`; its insufficient-scope refusal passes through with its code (`TestTerminalHoldsAnOAuthDelegationToItsScopes`) |
| 7 | A workspace login requirement (two-factor, Google sign-in) is bypassed through the browser | Blocked twice | the mint's request passes bex-api's gate, and `Resume`'s authorization runs it again; the gateway's resolver asks it as the ticket's subject with method `shell` before any shell opens (`TestTerminalHonorsTheWorkspacesLoginRequirement`) |
| 8 | A captured ticket is replayed, or used after its lifetime | Blocked | the same 90-second ticket and nonce claimed once across replicas in `shell_ticket_nonces` (`TestTerminalTicketsAreRoutedByTheirFieldAndSingleUse` refuses a second redemption with `401`); the wait happens after the nonce is consumed, so a slow start never needs a longer ticket |
| 9 | A member whose access or key grant ends keeps a held or open Terminal | Blocked | the wait re-resolves as the subject (fresh `can_view_sensitive`, login requirements) and re-asks the grant every 2 seconds, and ends `revoked` (`TestTerminalWaitEndings` "the subject's access ends meanwhile", `TestTerminalWaitEndsWhenTheKeysGrantNarrows`); an open shell keeps the Web Shell's revalidation watchdog |
| 10 | Many tabs or retries start many sandboxes, or pass the live-sandbox cap | Blocked | `Resume` returns a `resuming` session unchanged and `BeginAgentSessionEditorStart` is a compare-and-set: two mints, one start; admission refuses as for a turn and keeps its code (`TestTerminalStartsAClosedSessionOnceAcrossTabsPG`, `TestTerminalOnAClosedSessionStartsItOnceAsTheCaller`, `TestTerminalKeepsAdmissionsRefusal`) |
| 11 | Held WebSockets exhaust the gateway | Bounded | a waiting Terminal holds its session-limiter slot (5 per identity, 100 per process) from before the wait, as an open shell does, and frees it when the browser leaves (`TestTerminalClosedMidWaitFreesItsSlot`); the wait ends at the start's 16-minute ceiling, the 4-hour cap or the drain bound (`TestTerminalWaitEndings`) |
| 12 | A cross-site page opens the WebSocket, or makes a member's browser start a sandbox | Not a gap | the ticket, not the origin, is the credential, as on the service path; a cross-site page cannot mint one: the session cookie is `SameSite=Lax` (ADR012) and bex-api answers CORS only to its allowed origins (`withCORS`), so neither a forced mint nor reading a ticket works from another site |
| 13 | Terminal content reaches logs or audit rows | Not a gap | the wait reads the browser's frames only to drop keystrokes and queue resizes, and logs none; the `ssh_sessions` row has no content column; the gateway logs a resolution's error, never a frame |
| 14 | A sandbox is kept running by a Terminal no one uses | Bounded, accepted | an open Terminal's `web_shell` row holds the sandbox from its idle close, as an SSH login's does (`TestTheConversationStreamIsNotAnEditorPG`); the Terminal is capped at `BEX_SSH_SESSION_TIMEOUT` (4 hours) and the idle close ignores rows older than that; the sheet closing ends the shell; Cancel always wins |
| 15 | A rolling deploy pairs a new bex-api with an old gateway | Fails closed | an older gateway's `Verify` reads a session ticket as malformed (no service) and answers `401`; nothing opens, and the start the mint began settles as any `resume` does |
| 16 | A ticket minted while the sandbox was up is redeemed after the idle close, and the gateway starts the sandbox | Not a gap | the gateway starts nothing: it reads the closed session as a start that ended, says `no_sandbox`, and Reconnect mints again, which authorizes the start afresh (`TestTerminalRefusesAtConnect`) |
| 17 | An open Terminal widens what a finished turn's sandbox can push | Bounded, as for an SSH login | the Git mint admits a finished turn's own sandbox while a person's shell into the session is open (ADR054 D8, w6/175), and it reads the same activity as the idle close, so a Terminal counts as an SSH login does; only Git, only the session's `bex-agent/*` branch, only that exact Pod, only while the Terminal is open (`TestPGGitMintAdmitsAFinishedTurnsSandboxWhileAnSSHLoginIsOpen` opens and closes one); the model and `gh` mints keep the live-phase allowlist |

## Residuals

- **A member may leave a Terminal open in a background tab and keep a sandbox running for up to 4 hours.** Accepted, as for an SSH login (ADR054 D6): the time is the member's own workspace's, metered and visible in usage, and Cancel reclaims it at once.
- **A refusal before the shell opens reaches a viewer as the resolver's English sentence when the dashboard has no words of its own for it** (a cancel or archive that happens mid-wait). It is said only after `can_view_sensitive` passed, so it tells no more than the member's own read of the session.

One finding was fixed in the change: the wait's first draft re-asked the key's grant only once the sandbox was up, so a key whose grant narrowed mid-wait still got a shell. The wait now asks the grant on every poll before it reads the sandbox (row 5, `TestTerminalWaitEndsWhenTheKeysGrantNarrows`).
