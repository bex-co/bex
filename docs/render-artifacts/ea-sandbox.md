# Render CLI `ea sandbox` wire shape (w3/m32 t008)

Captured from the official `render-oss/cli` source and verified with v2.21.0, so bex-api's `/v1/sandboxes*` adapter (m32/m33, ADR042 D2) matches the real wire behavior and `render ea sandbox create/exec/list/stop` works unmodified. Rows 238–241 of [cli-compatibility-checklist.md](../cli-compatibility-checklist.md) are green.

All requests carry the workspace as an `ownerId` query parameter (Render's team id, `tea-…`); the server base path is `/v1/`.

## Endpoints

| CLI command | Method + path | Request | Response |
| --- | --- | --- | --- |
| `ea sandbox create` | `POST /v1/sandboxes?ownerId=` | `{ "plan": <plan>, "image"?: <ref>, "networkPolicy"?: {…} }` | `Sandbox` |
| `ea sandbox list` | `GET /v1/sandboxes?ownerId=&cursor=&status=` | — (repeat `status=` per filter; `--all` sends every status) | `[{ sandbox, cursor }]` (cursor pagination) |
| (get by id) | `GET /v1/sandboxes/{sandboxId}?ownerId=` | — | `Sandbox` |
| `ea sandbox exec` (v2.24.0+, step 1) | `POST /v1/sandboxes/{sandboxId}/runs/{operation}/token?ownerId=` (`operation` = `stream`) | `{ "command": "…" }` | `201` `SandboxConnectResponse` `{ executionId: "exe-…", expiresAt, method: "POST", token, uri }` |
| `ea sandbox exec` (v2.24.0+, step 2) | `POST <uri>` = `/v1/sandboxes/{sandboxId}/runs/{executionId}/stream`, `Authorization: Bearer <token>`, `Accept: text/event-stream` | `{ "command": "…" }` (must equal the minted command) | `200` SSE `output` events followed by `exit` with `exit_code`, or `error` with `{status, message}` |
| `ea sandbox exec` (≤ v2.21.0, legacy) | `POST /v1/sandboxes/{sandboxId}/exec?ownerId=` | `{ "command": "…" }` | same SSE stream, single step |
| execution history (SDK, no CLI command; w32/m298) | `GET /v1/sandboxes/{sandboxId}/execs?cursor=&limit=` · `GET /v1/sandboxes/{sandboxId}/execs/{execId}` | — | `200` `[{execution, cursor}]` newest first · one `execution` (`id, sandboxId, type, operation, command, userId, startedAt, stoppedAt?, exitCode?`) |
| `ea sandbox stop` | `POST /v1/sandboxes/{sandboxId}/terminate?ownerId=` | — | 200/204 |
| (logs) | `GET /v1/sandboxes/{sandboxId}/logs?ownerId=` | — | log events |
| (files, `ea sandboxes copy`) | `POST /v1/sandboxes/{sandboxId}/files/{operation}/token` (`upload`/`download`) then the returned `uri` | **none** — `ownerId` and `path` are query parameters (corrected w7/m150 t001; the mint sends no body) | 201 connect token; PUT upload / GET download on the returned URI — bounded subset implemented by w7/m150; live pinned-CLI roundtrip verified on dev-7 2026-10-03 |

Since v2.24.0 the CLI flow is two requests (`pkg/sandbox/repo.go` `connect` + `ExecSandboxStream`): the mint returns a connect token and the `uri` to redeem it at, and the redeem's response body is the SSE stream. The connect token is not an OAuth credential — bex signs it with a key derived from the gateway exec secret, binds it to the workspace, sandbox, `executionId`, operation, and the exact command bytes, expires it within 60 s, and consumes it once across replicas — so the redeem route is served outside the OAuth gate (classified in the always-public inventory) and re-applies the exec gate under the token's minter at redeem time. Refusals there are JSON `{"message"}` bodies with a precise status: 401 not a connect token, 403 wrong sandbox/execution/command, 409 already used, 410 expired, 404 `SANDBOX_NOT_FOUND` if the sandbox vanished, 429 from the IP limiter. Each `event: output` carries `{"stream":"stdout|stderr","data":"…"}`; the terminal `event: exit` carries `{"exit_code":N}` (the key `pkg/sandbox/sse.go` has decoded at every pin — bex emitted `exitCode` before w7/m147, which the CLI read as 0), and `event: error` carries `{"status":N,"message":"…"}` (404 terminated target, 403 access revoked mid-stream, 503 exec failed to start), which the CLI prints as `sandbox exec stream error status N: message`. bex adds the internal `exitCode`/`error`/`code` keys beside them for one release so a bex-api reader that rolls out apart from the gateway decodes either. A missing exit event is a CLI error. bex-api performs workspace plus durable owner/admin authorization, signs a short-lived single-use ticket binding the exact command and sandbox namespace, and reverse-proxies the isolated ssh-gateway's stream. Only that gateway holds namespace-scoped `pods/exec`. MCP `sandbox_exec` consumes the same SSE path and returns buffered stdout/stderr/exit code.

## Bounded file transfers (w7/m150)

The pinned launcher (`v1.1.3-0.20260909214233-a764810a7682`) uploads a single file as `application/octet-stream` with its exact Content-Length (the empty-file case may be chunked), or streams a directory as `application/x-tar` with gzip encoding and unknown length. Downloads retain those content types and use gzip for both shapes. The gateway closes the gzip trailer only after validation and successful sandbox execution, so a late failure cannot become a successful truncated copy. The API preserves the compressed bytes end to end.

The file mint and transfer routes reuse sandbox exec's workspace create permission, durable owner/admin boundary, and sensitive agent-session permission. Minting requires the API write scope even for downloads. The public file token and internal gateway ticket use separate signing keys derived from the existing exec secret; neither authorizes OAuth, shell, or run routes. Tokens expire within 60 seconds, bind the exact operation and path, and are single-use through the shared nonce store. Missing durable replay protection makes file transfer unavailable. The gateway rechecks permissions when a transfer begins and during its lifetime.

Supported remote paths are clean absolute paths below `/`, at most 4096 bytes and 64 levels, without traversal or control characters; existing symlink ancestors are refused. This deliberately excludes the pinned client's home-relative forms. Transfers allow at most 256 MiB in each of the wire and decoded streams, 10,000 archive entries, and five minutes. Archives accept directories and regular files only, with unique names and parents preceding children; links, devices, duplicate entries, missing end markers, and damaged gzip trailers are refused. This is stricter than the pinned client, which preserves symlinks and can create an outward-pointing link during extraction, although its `os.Root` refuses subsequent traversal through it.

A directory destination must not already exist; merging an existing tree is unsupported. Single files may replace a regular file. The destination parent must exist. Uploads stream into a private staging path and publish only after the complete input and sandbox execution succeed. Cancellation attempts bounded cleanup; if the sandbox disappears, a hidden `.bex-copy-*` staging directory can remain, but no incomplete upload is published at the requested destination. Download errors after headers have been sent end with an incomplete gzip stream; the CLI reports failure rather than silently accepting the partial body.

The shared contract and real handler/launcher tests live in `lego/cli/testdata/sandbox-file-contract.json`, `lego/cli/sandbox_contract_test.go`, and `lego/backend/internal/sandbox/file_roundtrip_test.go`. Those are local transport checks. **Live verification (2026-10-03, dev-7):** the pinned launcher built from `lego/cli` uploaded and downloaded a 3 MiB random file, an empty file and a nested directory through a real OpenSandbox sandbox via the in-cluster gateway's Kubernetes Executor; all were byte-identical (sha256 inside the sandbox and `cmp`/`diff -r` locally). Live refusals: traversal and relative paths `400`, foreign workspace `403`, another identity's sandbox `404 SANDBOX_NOT_FOUND`, replayed token `409`, wrong path or method `403`, an OAuth token on the transfer URI `401`, a declared 256 MiB + 1 byte upload `413`, chunked nonempty raw upload `411`, missing source or parent `404`, existing directory destination `409`. Killing the CLI mid-upload of 150 MiB published nothing and left no staging directory or transfer process in the sandbox. The dev-7 mock runs runc, not gVisor; the production gVisor path was exercised the same day by w9/m94 t004 (`copy` upload and download roundtrip on `bex-canary`). Sandbox groups, snapshots, and App SSH file access remain outside this work.

## Models

**Sandbox** — `{ id: <SandboxId>, plan: <SandboxPlan>, networkPolicy: <SandboxNetworkPolicy>, status: <SandboxStatus> }` (plus timestamps).

**SandboxPlan** (compute size): `1c-2g` · `2c-4g` · `4c-8g` · `8c-16g`, plus the deprecated `starter` · `standard` · `pro` (sized like the Workflow plans of the same name). Since w2/m263 each plan sets the sandbox container's CPU/memory limit (`starter` 0.5 CPU/512 MiB, `standard` = `1c-2g`, `pro` = `2c-4g`); see [ADR018 § Sandbox create flags](../ADR018-render-parity.md#sandbox-create-flags-w2m263) for `idleTimeoutSeconds`, `timeoutSeconds: 0`, groups and images.

**SandboxStatus**: `creating` · `running` · `suspending` · `suspended` · `resuming` · `errored` · `terminated`.

Note: Render's sandbox lifecycle has a `suspending`/`suspended`/`resuming` set (idle suspension and wake-on-exec) distinct from `terminated`. bex maps OpenSandbox `Pausing` ⇄ `suspending`, `Paused` ⇄ `suspended`, `Resuming` ⇄ `resuming` (rootfs-only on the k8s substrate, ADR042 D5) and delete ⇄ `terminated`. Since w2/m278 bex suspends a sandbox after `idleTimeoutSeconds` (default 900) with no exec or file transfer, and the next exec or file transfer resumes it ([ADR014 D4](../ADR014-sandboxes.md#d4--idle-hibernate--gateway-observed-autopause)).

## Deliberate bex divergences

- **`plan` → size**: each accepted plan maps to a fixed sandbox CPU/memory limit (w2/m263); an unknown plan is `SANDBOX_PLAN_INVALID`. The value is echoed back on `Sandbox`, and billing follows the resources through the weighted compute meter.
- **`networkPolicy`**: matches Render since w32/m283 ([ADR042 § Sandbox network policies](../ADR042-sandbox-cluster-substrate.md#sandbox-network-policies-w32m283)). An omitted policy is `allow-all`; `type` (or its deprecated alias `default`) is `allow-all`, `deny-all` or `allow-list`, and `allow-list` takes `rules` of `{domain, protocol: "https"}`. Invalid input — rules on a non-allow-list policy, an allow-list without rules, a domain with a scheme/port/path, uppercase, an inner wildcard, an IP literal, a cluster-local name, a duplicate or more than 100 rules — fails before any runtime call with `SANDBOX_NETWORK_POLICY_INVALID` across REST, GraphQL, MCP and the CLI. Cilium enforces each posture outside gVisor, above a platform floor (nodes, the Kubernetes API, metadata, private ranges, other Pods) that no policy opens.
- **Visibility/ownership**: Render's `ownerId` is a team boundary. bex adds a per-caller boundary inside that workspace: ordinary members list/get/exec/stop only sandboxes whose reserved owner/workspace metadata matches their resolved identity and whose sandbox-regime plus enforced-policy stamps are intact; an explicit workspace admin may operate all fully hardened owned sandboxes in the workspace. Foreign, ownerless, and incompletely hardened objects are indistinguishable from missing ones (`SANDBOX_NOT_FOUND`).
- **`image`**: bex's `Create` is template-based (ADR014 D2 / ADR042 D2) — the image is fixed at template registration, not taken from an arbitrary request ref.
