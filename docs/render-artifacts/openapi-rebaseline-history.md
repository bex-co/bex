# Render upstream drift re-baseline history (rounds 2–7)

Archived verbatim from [ADR018-render-parity.md](../ADR018-render-parity.md) to keep the main parity ledger under the repository's 1 MiB blob ceiling. Round 8 stays in ADR018; round 9 lives in [openapi-rebaseline-round9.md](openapi-rebaseline-round9.md).

**Upstream drift re-baseline round 7 (2026-11-13, w3/m367).** Render's live contracts moved again, so all three pins were refreshed together.

- **OpenAPI** (sha256 `6229bc62…`): **263** operations, eight more than round 6 and none removed.
  - `delete-sandbox-build` is served on REST, GraphQL `deleteSandboxImage` and MCP `delete_sandbox_image`. A deleted build leaves every read and the create by id or name, its registry image is deleted, and a repeat answers 204. `409 image_in_use` (the new `errorCode` value) names up to ten sandboxes that have not terminated or errored and started from it. bex had no snapshots then, Render's other dependents; since w32/m285 it has filesystem snapshots, which are full copies and do not hold the image (`w22/025`).
  - The seven `sandbox-groups/{id}/credentials*` operations are omissions. They answer `SANDBOX_CREDENTIALS_UNSUPPORTED`, because render.com/sandboxes still marks brokering early access ([ADR104](../ADR104-sandbox-render-parity.md)).
  - Operations bex serves gained two things, now honored: `trigger-build-source-build`'s optional `clearCache`, and sandbox builds' nullable `failureCode` (the codes of Render's SDK enum).
  - `connect-sandbox-run` dropped its `{command}` body, but the pinned CLI v2.36 still sends it, so bex keeps it as a declared extension (`renderRequestBodyExtensions`). The v2.37.0 pin (w22/m444) no longer sends it; the extension stays for released launchers at older pins.
  - The `429RateLimit` description, the sandbox error responses and the snapshot `ttlSeconds`/`name` (snapshots stay refused) changed without a handler change.
  - The guard counts are now 164 paths, 170 schemas and 263/74 operations/request bodies (+1 extension).
- **Blueprint schema** (`6c6721a6…`): `cronService` gained `buildSource`. A cron job runs the build source's image on its schedule, and the source fields it would set are refused beside it. `rootDir` joined the fields refused beside a server's `buildSource`.
- **MCP** (`main@23fb3360`): upstream registers 48 tools.
  - The 20 new ones are Render Workflows (`—` non-goal) in `mcpKnownUpstreamOnly`.
  - `list_logs` gained the Workflows `task`/`taskRun` filters, an accepted divergence (bex has no task runs).

**Upstream drift re-baseline round 6 (2026-11-08).** The weekly drift job found Render's live OpenAPI (sha256 `98b0ce65…`) at **255** operations, three more than round 5 and none removed. All three are sandbox builds, which back the CLI's `sandbox-groups images` commands: `create-sandbox-build`, `list-sandbox-builds` and `retrieve-sandbox-build`. bex has no imported sandbox images, so all three are omissions under _Render sandbox groups, snapshots and executions_. The create and retrieve routes already answered `SANDBOX_IMAGES_UNSUPPORTED` (w2/m263), and the list now answers the same. The same diff touched sandbox operations bex serves. `create-sandbox` gained `name`, `buildId` and `buildName`, and `list-sandboxes` gained a `name` filter and cursor/limit paging, and the sandbox response gained a nullable `name`. bex serves sandbox names (w5/m287) and refused `buildId`/`buildName` by name, so no handler changed then; w2/m358 (2026-11-12) serves the three build operations and the two create fields. The pin now declares `name`, `cursor` and `limit` on `list-sandboxes`, so their temporary query extension is dropped. The connect-token mints also document a `409`. The pin, the guard counts (160 paths, 170 schemas, 255/71 operations/request bodies) and the scope matrix are refreshed.

**Upstream drift re-baseline round 5 (w2/m251, 2026-11-02).** Render's live OpenAPI (`api-docs.render.com`, sha256 `6ac5d3d4…`) now has **252** operations against the 2026-09-11 pin's **208**: 44 added, none removed. The additions are three families: **Build Sources** (20 operations, plus `buildSourceId` on `service`, `servicePATCH` and every `*DetailsPOST`, deploy `buildId`, three new error codes and five audit-log events) → new row below, owner **w2/m254**; **Workflows flows** (`/flows`, `/flow-runs`, 8) → the existing Workflows `—` row; and **sandboxes** (`/sandboxes`, `/sandbox-groups`, 16), of which bex already served six (create, list, get, terminate, run and file connect tokens) under pillar 5. Changed schemas on operations bex serves: `autoDeployTrigger` on services (already served; `autoDeploy` marked deprecated upstream); Blueprint responses now **require `ownerId`** and PATCH accepts `branch` (→ **w2/065**); `list-blueprint-syncs` gains `cursor`/`limit` (already served); `parameterOverrides` is **removed** from Render's Postgres create/update/detail (bex retired it to match, 2026-11-04 — **w2/066**); the webhook/event enum gains `disk_snapshot_restored` with `{diskId, instanceId?, snapshotCreatedAt, triggeredByUser}`, where bex records the same restore as its own `disk_restored` (→ **w2/064**); the pinned events also name `service_disk_usage_high`/`service_disk_usage_recovered` (`{diskId, diskName, mountPath, usagePercent, thresholdPercent}`), which bex does not emit (→ **w2/m255**); the audit-log enum adds `UpdateWorkspacePaymentMethodEvent` (bex records no payment-method change → **w2/067**; the organization variant does not apply) and drops `CreateArtifactSourceEvent`; the `errorCode` enum adds the Build Source codes (w2/m254), `insufficient_token_scope` (bex's scope refusal answers `INSUFFICIENT_SCOPE` → **w2/068**), and sandbox-group codes bex does not serve. The pin is refreshed (`renderOpenAPISHA256`); the refresh would have 400'd every existing sandbox call — Render's `sandboxId` pattern is 25 characters after `sbx-` and bex mints 20, and `list-sandboxes` requires `ownerId` — so both are widened in `render_openapi.go` and pinned by `TestSandboxCallsPassTheRenderGate`. Build Sources answer a named 404 (`bex does not offer Render Build Sources yet`) and `buildSourceId` is refused by name on create and PATCH; flows and the unserved sandbox operations are listed in § Render operation omissions. The MCP tool surface is unchanged (`render-mcp` drift job green 2026-11-02). CLI v2.29.0 → v2.35.0 is assessed in [cli-compatibility-checklist.md](../cli-compatibility-checklist.md): its new public-alpha `ea blueprints create|plan|approve|update` call Blueprint routes bex does not serve (→ **w2/m256**). Why nothing reported the 44 operations: the weekly `render-schema-drift` job compared only the Blueprint schema and the webhook enum, and it had been red since 2026-10-26 on `disk_snapshot_restored` alone. It now also compares the REST operation list, and the webhook fixture is re-captured as `render-webhook-vocabulary-2026-11-02.json` (68 public values; the dashboard picker keeps its 2026-08-17 walk) with `disk_snapshot_restored` dispositioned as planned (w2/064, since shipped: 2026-11-03).
