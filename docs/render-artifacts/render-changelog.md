# Render changelog dispositions

Every entry on [Render's changelog](https://render.com/changelog), back to its first on 2023-03-31, with what bex does about it (w4/m553). The API pins see only contracts: the Blueprint schema, the OpenAPI operations, the webhook events and the MCP tools. A feature Render ships only in its dashboard changes none of them. Bulk suspend and resume, Postgres admin apps and the log line detail view went 11 to 29 months unnoticed that way (w4/m550–m552). Render announces each of those on its changelog, so this table gives each changelog entry an owner.

`scripts/render-changelog-drift.sh` reads Render's Atom feed (`https://render.com/changelog/feed.xml`, the ten newest entries) and the changelog page (every entry). The `render-changelog` job in [`render-schema-drift.yml`](../../.github/workflows/render-schema-drift.yml) runs it every Monday. It fails when an entry has no row, when a row's entry is no longer on the changelog, or when a row breaks the rules below. It never writes this file: a person reads the entry and adds the row. `scripts/render-changelog-drift.test.sh` checks the script against fixture feeds, and this table's rules on every push. A feature Render ships in its dashboard without a changelog entry, or keeps behind a per-workspace flag, is caught by [dashboard-operations.md](dashboard-operations.md) instead: every GraphQL operation and flag gate in Render's public dashboard bundle, read by the weekly `render-dashboard-ops` job (w1/m645). A runtime's default version, which Render moves on its per-language version pages without a changelog entry, is compared with bex's dated tables by the daily [`render-version-drift`](../../.github/workflows/render-version-drift.yml) job (`scripts/render-version-drift.sh`, w3/m637). Any other docs page Render rewrites without a changelog entry is caught by [docs-pages.md](docs-pages.md): a row and a text hash for every page in Render's `llms.txt`, read by the weekly `render-docs` job (w4/m688).

Read 2026-11-22: 175 entries.

## Dispositions

Each row has one disposition, and its pointer says why:

- `matched`: bex ships what the entry announces. The pointer is the ADR018 row, ADR, artifact, shipped board item or code that shows it.
- `partial`: bex ships part of it. The pointer says what bex has and names the board item that owns the rest, or the ADR018 row that records the divergence.
- `gap`: bex lacks it. The pointer names the open or parked board item that owns it (`wN/mN` or `wN/NNN`); a gap with no owner is filed with `/pm add` before its row lands.
- `non-goal`: bex declines it. The pointer cites the [`DO_NOT_DO.md`](../../.pm/DO_NOT_DO.md) line or the [ADR018](../ADR018-render-parity.md) `—` row.
- `n/a`: there is nothing for bex to match. The pointer gives the reason: a Render-internal change, a region launch, a Render bug fix with no bex counterpart, or a build-speed figure with no contract.

A digest entry from 2023 ("April 14, 2023 - Changelog") lists several changes. Its row takes the disposition of the most significant one bex lacks, and names the rest.
