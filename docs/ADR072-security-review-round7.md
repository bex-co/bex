## Round note

The severity profile keeps falling (round 5: 8 high / 7 medium; round 6: 2 high / 5 medium; this round: 0 high / 3 medium — and one of the three is a re-report). No new instance of the ADR055 root cause (`App.Name` as global identity) and no new decision-freshness _class_ — instead this round's four fixable findings share two smaller themes: **enumeration completeness** (F2's denylist knew `auto_explain.log_analyze` but not `debug_print_plan` — fixed by classifying whole prefixes, not names) and **credential-class awareness at capability issuance** (F3: the relation gates answered _who_ may mint but never _what the request rides on_). F7 is completeness of the round-6 freshness seam (the gateway's web-shell/native-SSH resolvers never got the fresh reauthorization agent-attach tickets got); F8 closes the one _guessable_ input to a 403/404 oracle while deliberately keeping the unguessable tiers distinct.

## Fixed in place

- **2** — `lego/backend/internal/postgres/service.go`: the round-5 (w1/m68) statement-logging gate enumerated ten exact names, so `debug_print_parse`/`debug_print_rewritten`/`debug_print_plan` — whose parse/rewrite/plan trees carry every SQL literal — flowed through `UpdatePostgres` under plain `can_operate` into CNPG, and `can_view_logs` (contributor) could read the result: exactly the disclosure `ExecuteQuery`/`TopQueries` reserve for developer-and-up. The classifier now also matches the prefixes `debug_print_` and `auto_explain.` (case/space-normalized), so future knobs in those families inherit the gate instead of waiting for an enumeration to notice them. The exact-name map keeps the non-family names (`log_statement`, `log_parameter_max_length`, …); allowlist inversion was rejected because ADR009's parameter surface is the open per-plan tuning axis and eight tuning knobs are test-pinned as contributor-writable. Tests: new rows in `m68_logging_params_test.go` (`debug_print_*`, `auto_explain.log_nested_statements`, `auto_explain.sample_rate`, uppercase/space robustness) plus `debug_pretty_print` pinned as _not_ sensitive (formatting only — the prefix must not over-match).
- **3** — `lego/backend/internal/core`: new `Base.AuthorizeMintClass` + `PlatformClientResolver`. The relation gates (checked fresh since round 5) answered who may mint but nothing about the credential the request rides on, so (a) a compromised API key — a `client_credentials` Hydra client that legitimately holds `can_manage_keys` as a workspace developer — could self-replicate before revocation, and (b) a consented third-party OAuth client (DCR is open by design, ADR025; the live `BEX_OAUTH_REQUIRE_AUDIENCE=1` narrows only the _audience-less_ hole) could mint an API key or enroll an SSH key that persists after its consent is revoked — the gateway later authenticates the key by fingerprint with zero dependence on what minted it. `CreateAPIKey` and `sshkeys.Create` now call the class gate before their auditing Authorize: only a direct Kratos session, or a human OAuth token from a client Hydra's own record marks `bex.co/platform-client` (the official CLI, bex-mobile — resolved lazily through the same admin-API TTL cache the audience rule uses, exposed as `oryAuth.IsPlatformClient` and stamped onto the shared Base in `newAuthGate`), may mint. Machine callers, third-party clients, and (fail-closed) any human OAuth caller with no resolver wired are refused; an unreachable Hydra surfaces as 503, never a silent downgrade. `sshkeys.Create` also gained the round-5 finding-4 `AuthorizeFresh` symmetry `CreateAPIKey` already had. A class refusal is deliberately unaudited — it is not a workspace decision, the same way an unauthenticated request is not. Tests: `mint_class_test.go` in both packages (machine / third-party / no-resolver / platform / session matrix), `TestCreateFreshAssertsMembership`, and the HTTP-surface pins (machine bearer 403 on create while reads still 200). Follow-up to red-team: whether Hydra 2.x DCR can plant `bex.co/platform-client` metadata through the registration endpoint (the platformClient comment asserts it cannot; that is an upstream-behavior claim, not repo-verifiable).

  **Amendment (2026-08-15) — the fix was incomplete; deploy hooks are the third durable credential.** The original pass gated the two verbs the finding named and stopped there, which is exactly the ad-hoc application F3's own preventive control warned against ("centralize class-aware durable-capability issuance policy"). A re-triage found a third credential with the same independent-authentication property: the **deploy-hook URL**. `DeployHookHandler` is an open, unauthenticated endpoint keyed only on the token in the path, and a replay carries `ref`/`imgURL` — i.e. deploy an arbitrary image to that service — so the token is a durable capability with zero dependence on the caller that obtained it, the identical property the API-key/SSH-key gate exists to protect. `GetDeployHook` and `RegenerateDeployHook` gated on relations only (`can_view_sensitive` / `can_create`, both fresh since round 5), so a `client_credentials` machine key or a consented third-party OAuth client holding developer could convert revocable access into a capability outliving its own revocation. **Both** verbs now call `AuthorizeMintClass` before their auditing `Authorize` — not rotation alone, because an attacker needs a working token, not a fresh one, so gating rotation only would leave the identical capability one `GET` away; and on a service with no hook yet the read is itself the mint (`writeDeployHookToken` creates lazily). Behavior change: machine API keys and third-party OAuth clients (including DCR-registered MCP agents, ADR025) can no longer read or rotate a deploy hook; Kratos sessions (dashboard) and platform clients (official CLI, bex-mobile) are unaffected. Tests: `deploys/mint_class_test.go` (both verbs × the machine / third-party / no-resolver / platform / session matrix, each asserting a refused class also wrote no token); `TestDeployHookRevealAndRotationFailClosedOnFreshRevocation` re-pinned with `Method: "session"` so it still exercises the freshness seam rather than stopping at the new class gate. Still open as a preventive control: no guard test enumerates credential-returning verbs, which is why this third one was missed — a new one can still be added ungated without failing a build.

- **7** — round 6's `AttachRevalidator` covered agent-attach tickets only; `git show a378eaff` confirms webshell/nativessh were untouched, and both redeemed through the ordinary cached `Check` (30s cross-replica `PositiveTTL`) into 4h pods/exec sessions. `apps.ResolveSSHSession` (the shared sink for native SSH, the Browser Web Shell, and Zed remoting) now re-asserts `can_view_sensitive` through `AuthorizeAppFresh` after its auditing `AuthorizeApp`; `agentsessions/SSHResolver.ResolveSSHSession` does the same via `AuthorizeFreshOn` — the `attach_revalidate.go` pattern. Honest scope note: this closes the _inconsistency_ (primed cache + revocation + connect within the window) more than the worst case — a session opened one second before revocation still runs its full `BEX_SSH_SESSION_TIMEOUT`, as it does everywhere. Tests: `TestResolveSSHSessionReassertsFreshAuthorization`, `TestSSHResolverReassertsFreshAuthorization` (cached-allows/fresh-denies checkers), and the call-shape assertions in the existing tests updated to one cached + one fresh observation.
- **8** — `lego/backend/internal/core/base.go`: service/project/environment/env-group lookups intentionally distinguish foreign (403) from absent (404), and the cited resources are addressed by crypto-seeded 20-char xids — blind probing is infeasible, so the typed-id tiers keep their 403 (test-pinned since w1: `TestAuthzGuardsEveryVerb`'s 403-before-404 rule; the distinction also tells a legitimate dual-member caller their access was the problem). The one _guessable_ input is the App **by-name** sweep (`LabelServiceName` — "does any workspace run `web`?"): in both `AuthorizeApp`'s fallback and `GetApp`, an all-denied name probe now collapses to the absent-resource answer (same acting-workspace gate, then `ErrNotFound`), making a foreign App's existence indistinguishable from nobody's. Non-`ErrForbidden` denials (authz outage) stay distinct errors — an outage is not absence; the per-candidate denial audit rows (w4/015 capped) keep the forensic trail; the acting workspace resolves exactly once (w4/m30/t003 call-count contract preserved). Tests: renamed `TestGetAppCrossTenantByNameIsNotFound` plus five updated cross-workspace tests, the cap test's row counts (+1 trailing acting-workspace denial row, mirroring the truly-absent path), and the workspace-pins/explicit-workspace tests re-pinned to 404. `GetApp`'s doc (the "not yours, not doesn't exist" bullet) now records the split rule.
- **9** — `mobile/src/features/notifications/notifications-provider.tsx`: the module-scope OS notification handler presented banners unconditionally. Logout's push unregistration is deliberately fire-and-forget (the runbook documents that logout must not depend on the network), so a failed unregister leaves the server subscription active — and the prior account's deploy events would banner on a signed-out or account-switched device. The handler now gates banner/list/sound on `authManager.getState().status === "signedIn"` (synchronous singleton state; cold-start `loading` fails closed; the in-app receive path was already gated; the tap-through cold-start case is handled by `getLastNotificationResponse` inside the signed-in effect). Severity was genuinely low: the feature is release-gated behind w11/m5 physical-device qualification (no EAS project id, no provider transport) and payloads are ADR052 D3c's closed four-field envelope with fixed copy — worst case was a service name on a banner. The durable-unregister-retry and account-bound envelopes from the scan's remediation stay recorded as optional companions for the w11/m5 qualification work.
- **6 (slice)** — `lego/backend/internal/store/api.go` `ValidImage`: the image regex is character hygiene only, and the kubelet pulls tenant images from the node's network context — outside every pod egress policy (ADR022's controls are Cilium endpoint policy on pods; node-level firewalling is explicitly out of scope per DO*NOT_DO) — with pull errors surfaced verbatim into tenant-visible App status. A reference whose registry host component is a **non-public IP literal** (loopback, RFC1918, link-local/metadata, CGNAT, special-purpose) or `localhost` — classified by `lego/types/netutil.UnsafeOriginIP` — is now refused at all three create/update surfaces that share `ValidImage`. Public registries, public IP literals, and DNS hostnames (including `zot.bex-registry.svc:5000`, the platform's own registry) are unaffected; the documented residual is that an \_internal DNS name* is lexically indistinguishable from a public one and stays allowed (BYO-image hosts are a deliberate ADR018 parity divergence; closing that needs the node-level registry-origin policy the scan's full remediation describes). Tests: eleven new `TestValidImage` rows; the overstated "SSRF class is closed at the admission prefix boundary" comment rewritten (that boundary covers registry _masquerade_ only).
- **10 (part)** — `lego/operator/internal/build/native.go`: `nativePreparerImage` pinned to `busybox:1.37.0@sha256:9db7b599…` (the 1.37.0 multi-arch OCI index, resolved from Docker Hub). This one image is the direct full-bundle secret reader — the initContainer mounts and base64s the entire OpenBao-backed runtime-env — so it is the highest value-per-digest of the deferred set, and pure platform plumbing with no floating-version semantics.

## Accepted, with rationale

- **1 (`onbex.co` cookie isolation)** — the fourth report of the same owner-waived risk (ADR045 round-3 exclusion → ADR055 F9 → ADR056 #9): `onbex.co` is not on the browser PSL, sibling tenant origins can set `Domain=onbex.co` cookies at each other, and the manager's WARNING-and-continue startup path is quoted verbatim in the prior dispositions. Control-plane cookies are host-only on `api.bex.co` (a different registrable domain), so the blast radius is strictly tenant-to-tenant among `*.onbex.co`. Fail-closing the validator would take down all tenant hosting and is not an autonomous change; the standing remedies remain the PSL submission (external, multi-week, then a `golang.org/x/net` bump) or per-tenant registrable domains.
- **4 (deploy-hook tokens in raw edge logs)** — the token is a path-segment bearer by documented Render parity (Render's own hooks ride the URL), Traefik's JSON access log keeps `RequestPath` (headers are dropped — the credential moved into the path re-enters the line), and the raw logs are reachable only by node root / cluster admins: the Alloy shipper drops every non-tenant-app line before Loki, bex-api's pods/log RBAC is namespace-scoped away from Traefik, and no other export exists. Blanket `RequestPath` redaction would kill ADR010's documented tenant-facing path-filter feature. `RegenerateDeployHook` is the rotation path for a suspected leak. Custody note (recorded here): **raw Traefik edge logs are credential-bearing — any future log export/shipper must revisit this before shipping them anywhere broader.**
- **8's residual + 6's residual** — typed-id 403 semantics stay distinct by design (see above); internal DNS names as image hosts stay allowed (see F6).

## Deferred, with rationale

- **5 (metrics-server `--kubelet-insecure-tls` in prod)** — real and confirmed: the flag sits in the shared GitOps base for CAPD compatibility and the prod overlay inherits it with no patch. But every prod kubelet already runs `rotate-server-certificates: "true"` and **no kubelet-serving CSR approver exists**, so the serving certs stay self-signed — removing the flag today breaks the operator's metrics-driven autoscaling (fail-safe skip) and tenant resource metrics (503). The plan: deploy a kubelet-serving CSR approver, mount the cluster CA, set `--kubelet-certificate-authority`, then drop the flag from the base (local CAPD may keep it). That aligns the cluster with what ADR036 §92 already claims. East-west is Cilium-WireGuard-encrypted on the private Hetzner net and a spoof feeds only false metrics (wrong scaling / wrong tenant-visible numbers), hence low.
- **10 (remainder)** — the six `nativeRuntimeImages` language bases and `keyvalue_backup.go`'s `busybox:1.37` join the ADR055 F7 / ADR057 #12 digest-pinning inventory, whose blocker remains the reviewed-digest update automation (multi-arch resolution + bump workflow) so pins don't rot; the language bases legitimately float patch versions (`node:24-bookworm`), so a static pin without automation trades an upstream-compromise risk for a stale-image risk. This ADR's inventory amendment completes the deferred scope: `nativePreparerImage` (now pinned), `elixir/golang/node/python/ruby/rust` bases, `keyvalue_backup.go` busybox, plus the original BuildKit/git/cosign/skopeo/AWS-CLI set.
