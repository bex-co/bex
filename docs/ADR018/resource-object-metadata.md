# Resource-object metadata parity (w6/m28)

This is the Resource-object metadata parity (w6/m28) part of the [Render parity matrix](../ADR018-render-parity.md) (ADR018), moved out of it on 2026-11-23 (w10/m607) to keep the ledger under the 1 MiB blob limit. The matrix's legend, method and evidence sources apply here. Amend these rows in this file, not in ADR018.

Service, Postgres, and Key Value REST responses now carry truthful Render-compatible metadata from one shared backend contract: tenant-store `owner` objects, configured `BEX_REGION`, configured `BEX_DASHBOARD_URL` routes, and authoritative `updatedAt` values. Owner lookup is caller-scoped and batched; unresolved or unauthorized workspaces are omitted rather than guessed. Region and dashboard URL are also omitted when unconfigured. Dashboard links resolve to the existing `/services/{id}`, `/databases/{id}`, and `/keyvalue/{id}` pages. API writes stamp `app.bex.co/updated-at`; legacy reconciled resources may use Kubernetes managed-field time, and resources with neither source omit `updatedAt` instead of copying creation time.

**w6/m28** enriched REST only; GraphQL/MCP carried flat `ownerId` but not `region`/`dashboardUrl`/`updatedAt`. **w2/m46** extended all three to GraphQL (`Database`/`KeyValue` types) and MCP (tool structured outputs) via shared `PostgresView`/`KeyValueView` fields populated in the same `view()` path REST uses. **w9/m42/t003** added `TestGraphQLPostgresMetadataParity`, `TestMCPPostgresMetadataParity`, `TestGraphQLKeyValueMetadataParity`, and `TestMCPKeyValueMetadataParity` to lock the fields cross-surface; all pass. GraphQL/MCP continue to use flat `ownerId` (no nested `owner` object) — this is intentional dialect parity with Render's own GraphQL surface. The pinned official CLI renders workspace and region in Postgres and Key Value text output. Its generated Service text type exposes owner ID and dashboard URL but has no workspace-name or region fields, so the live verifier checks the complete Service metadata directly on the raw REST response after the unmodified CLI has decoded and created the resource. See [ADR006 § Resource metadata contract](../ADR006-bex-api.md#resource-metadata-contract-w6m28) and the [CLI compatibility checklist](../cli-compatibility-checklist.md#systemic-root-causes).
