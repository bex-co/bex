# Managed Postgres

This is the Managed Postgres part of the [Render parity matrix](../ADR018-render-parity.md) (ADR018), moved out of it on 2026-11-23 (w10/m607) to keep the ledger under the 1 MiB blob limit. The matrix's legend, method and evidence sources apply here. Amend these rows in this file, not in ADR018.

**List pagination (w8/m13):** ✅ across the applicable contracts. REST `GET /v1/postgres` returns Render's `{postgres, cursor}` item envelope and honors stable exclusive `cursor`/`limit` pages; omitted paging params answer Render's first page of 20 (w8/191). The bex-only top-level GraphQL `databases(cursor, limit)` uses the same boundaries while retaining `[Database]` for dashboard compatibility. Render's `list_postgres_instances` MCP tool accepts only the shared optional `workspaceId` and returns all instances in that workspace; bex matches that signature. Full-walk, unknown-cursor, omitted-body, and REST↔GraphQL parity tests cover the contract.

**Grow-only plan/storage correction (w2/m60):** plan writes remain available on REST/GraphQL/MCP/UI, while manual `diskSizeGB` update follows Render's REST/official-CLI contract. The operator now keeps a status/live-CNPG high-water mark independent of plan, so `basic-1gb -> basic-256mb` never projects `5 GiB -> 1 GiB`. A smaller explicit REST/CLI request returns a named 400 before mutation; an accepted grow is visible immediately through the shared `PostgresView.DiskSizeGB` on REST, GraphQL, MCP, CLI, and dashboard while CNPG converges. Blueprint database updates apply the same guard. This closed a mechanism defect. m60 also left GraphQL without a disk-resize write, on the reading that Render exposes none, but Render's dashboard does (Plan → Storage → Edit, "any multiple of 5 GB greater than the current storage capacity"), and bex's dashboard reaches the API only through GraphQL. **w2/m307 (2026-11-10)** added GraphQL `updateDatabaseDiskSize` through the same grow-only guard (MCP `update_postgres` already carried `diskSizeGB`) and the dashboard's Plan-section Storage edit, which accepts only a multiple of 5 GB above the current size. **w2/m317 (2026-11-10):** the API applies Render's sizes too. Create takes 1 GB or a multiple of 5 GB. An increase is a multiple of 5 GB above the current size, at most once every 6 hours (manual or autoscaled), refused `POSTGRES_STORAGE_STEP_INVALID` / `POSTGRES_STORAGE_INCREASE_TOO_SOON` on REST, GraphQL, MCP and Blueprint (ADR009 § Render's storage sizes).
