# Account deletion (w2/m84, ADR086)

This is the Account deletion (w2/m84, ADR086) part of the [Render parity matrix](../ADR018-render-parity.md) (ADR018), moved out of it on 2026-11-23 (w10/m607) to keep the ledger under the 1 MiB blob limit. The matrix's legend, method and evidence sources apply here. Amend these rows in this file, not in ADR018.

Render makes account deletion discoverable at the bottom of profile/settings but publishes no self-delete operation in its public OpenAPI. bex matches that danger-zone placement and irreversible confirmation while deliberately exposing REST and GraphQL self-delete because ADR008 forbids dashboard-only behavior. bex also previews delete/leave/block disposition across every workspace; Render's public contract does not document equivalent multi-workspace behavior. MCP is omitted as an intentional irreversible-boundary restriction.

### List-query census (w4/164, 2026-09-27)

The composed REST server now tests suspension filters with Render's `suspended` / `not_suspended` vocabulary, including repeated values. Boolean strings remain invalid. Services also honor repeated `env` values as runtime filters (the deprecated Render runtime alias); static sites never match a runtime filter. `region` compares literally with the region each service reads back: the Render region it was created with (w9/105), else the placement's alias (`frankfurt` for production `fsn1`, w8/218). The pinned Render query enum still rejects `fsn1`; omit `region` to list every service. GraphQL and MCP service-list contracts do not expose these REST filters.

`TestListOperationsConsumeAdmittedQueries` checks the gate's admitted query inventory against reachable handler reads across all 36 served Render list operations (derived directly from the pinned OpenAPI document and cross-checked against `unpagedListPages`, expanded from the original 9-operation subset in `w5/m580`, 2026-11-23). It also enforces that every `explode=false` array query parameter is parsed through `core.QueryList` or `core.QueryNameList` (and `core.QueryNameList` for `explode=false` `name` arrays). At contract load time (`w5/199`, 2026-11-23), the REST OpenAPI gate precomputes every operation's `form`/`explode=false` array query parameters (excluding `name`, which keeps raw percent-encoded commas per `w8/m55`, and including `renderCommaListQueryCompatibility` rewrites such as `list-events` `type`) and joins repeated keys on the validation clone so every repeated value reaches `kin-openapi`'s enum/schema checks (replacing the earlier datastore-`region`-only special case). Behavioral composed-server tests (`service_list_filters_test.go`, `list_query_behavior_test.go`) cover actual filter results, including multi-value `ownerId` on `list-notification-overrides`, `name` comma/percent-encoded parsing on `list-build-sources`, multi-value `status` on `list-job`, repeated `type` on `list-events`, repeated invalid second enum values across `list-services`, `list-events`, `list-routes`, `list-job`, `list-postgres`, `list-registry-credentials`, and sandbox lists, and `ownerId` workspace scoping on `list-logs`/`list-logs-values`. Deliberate omissions remain: services and build sources ignore `includePreviews` because bex has no preview services; Postgres ignores `includeReplicas` because replicas are not separate list records. These omissions are explicit in `listQueryOmissions`, so newly admitted and unread parameters fail the guard.

Postgres and Key Value now honor REST `region` filters (w6/075, 2026-10-02). Repeated and comma-separated values are OR'd and compare literally with each resource's reported `region`; the region condition is AND'd with name, environment, suspension and timestamp filters before cursor pagination. The validation clone combines repeated `explode=false` array query keys across all operations (w5/199, generalizing w6/075's datastore `region` join) so every supplied value reaches the unchanged pinned enum check. An omitted filter preserves the full list, and an unknown placement does not match a supplied region. This adds filtering of the configured placement, not multi-region provisioning. As with services, the region each resource reads back is the Render region it was created with (w9/105), else the placement's alias (`frankfurt` for production `fsn1`, w8/218), and the pinned query enum still rejects requesting `fsn1` itself. GraphQL and MCP gain no region arguments.

**Literal commas in `name` arrays (w8/m55, 2026-10-09; expanded in w5/m580, 2026-11-23).** Render declares every `explode=false` list `name` filter a `form`/`explode=false` string array, and the pinned CLI's generated builder (`NewListServicesRequest`) joins elements with raw commas while percent-encoding a comma inside a name: `[a, b]` → `name=a,b`, `["a,b"]` → `name=a%2Cb`, `["a%2C"]` → `name=a%252C`. bex used to decode before splitting, so an accepted display name containing a comma became two fragments and `services update <name>` / `services create --from <name>` refused with "No service named". `core.QueryNameList` now splits the raw query on unescaped commas and decodes each element once; repeated keys, trimming, deduplication and AND composition with other filters are unchanged, and an undecodable element is kept literally so it matches nothing rather than widening the list. It reads `name` on services, build sources, static headers, custom domains, disks, Postgres, Key Value, projects, environments, env groups and registry credentials; every other `explode=false` list filter (IDs, enums, regions, header `path`/`value`) keeps `core.QueryList`. Callers that percent-encode a whole comma list (`url.Values{"name": {"a,b"}}.Encode()`) now ask for one literal name — the pinned CLI never does, and repository callers use repeated keys. Owners' `name` (`explode=true`) and Render's live API were not exercised. Guards: `TestServiceNameFilterRawEncoding` (lego/cli, pinned bytes), `TestListNameFilterKeepsEncodedCommas` (composed services list; fails against decode-first), `TestQueryNameListSplitsRawCommasBeforeDecoding`, `TestListBuildSourcesNameFilterComposed`, and `TestListOperationsConsumeAdmittedQueries`.
