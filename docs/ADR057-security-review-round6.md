# Security review round 6: codex-security repository scan (2026-08-14)

**Status:** implemented (10 of 16 fixed in place) · **Scope:** disposition of the 16 findings (2 high, 5 medium, 9 low) from the codex-security static repository scan against revision `af97baae`. Sixth pass in the ADR028 → w1/m53 → ADR045 → ADR055 → ADR056 → this lineage. Ten findings are fixed in place with regression tests; one was already resolved operationally the day before the scan (the scan is static and cannot see deployed environment); three of the five deferrals are re-confirmed repeats of ADR055/ADR056 dispositions, and two are new platform-privilege items gated on live-cluster migrations.

## Round note

The severity profile keeps dropping (round 5: 8 high / 7 medium; this round: 2 high / 5 medium, and one of the two highs was a CI-workflow guard). No new instance of the ADR055/ADR056 root cause (`App.Name` as a global identity) appeared beyond the two already-tracked migration-gated sinks — the mechanism-level fixes from round 5 held. The new theme this round is **decision freshness at redemption/exercise time**: three findings (6, 11, 16) are variants of "an authorization decision frozen at mint/cache time outlives the state that justified it", and the fixes all converge on the round-5 `FreshChecker` seam.

## Fixed in place

- **1** — `.github/workflows/snapshot.yml`: the `bake` job (holds `HCLOUD_TOKEN`, executes repository scripts and the Packer template from the dispatched ref) now carries `if: github.ref == 'refs/heads/main'` — the same guard the sibling credentialed workflows (`app-cluster.yml`, `deploy.yml`) already had. A collaborator can no longer dispatch an unreviewed branch into a cloud-credentialed job.
- **2** — `lego/backend/internal/sshgateway/agentattach/agentattach.go`: the gateway's driver-facing HTTP client sets `CheckRedirect: http.ErrUseLastResponse` (a malicious in-sandbox driver answering 307/308 toward a peer sandbox's driver — reachable cluster-wide from the gateway identity — is no longer followed, and the preserved POST body is never re-sent), and both call sites (`dialDriverStream` for the GET splice, `forwardAgentTurn` for the POST turn) reject every non-`200 OK` driver answer. Test: `TestAgentAttachNeverFollowsDriverRedirects` (fake driver redirects to a victim server; asserts zero victim dials on both verbs). Driver-side per-request session binding remains a defense-in-depth follow-up; the crossing itself is closed at the gateway.
- **5** — `scripts/operator-kubeconfig.sh`: the day-to-day ServiceAccount token drops from `--duration=8760h` (1 year) to a 12h default (`BEX_OPERATOR_TOKEN_TTL` overrides). The role can exec/attach/port-forward cluster-wide, so theft of the kubeconfig is now bounded to hours; re-minting is one script run against the break-glass admin kubeconfig.
- **7** — `lego/backend/internal/store/store.go`: `clampPageLimit` maps an absent limit (`<=0`) to `core.MaxPageLimit` (100) instead of "no LIMIT clause", so `ListDeploys` and `ListJobs` can never materialize an unbounded history (DB + memory + JSON + the jobs path's per-row Kubernetes status sync). The pre-m31 "omitted limit = full history" contract is retired; callers page with the existing keyset cursor. Adapter/translator comments updated across REST/GraphQL/MCP (one shared translator each for deploys and jobs, so all three surfaces inherit the bound). Test: `TestListDeploysLimitClampsToMaxPageLimit` now pins the bounded contract.
- **9** — `lego/backend/internal/apps/webhook.go`: `scopeFor` fails closed for a GitHub-App-signed delivery in multitenant mode when the installation resolver is unwired **or** the payload carries no installation id — previously both fell back to the manual key's intentionally-global empty scope, letting a partial configuration (GitHub webhook secret + store, no GitHub service) scan and mutate matching Apps in every workspace. Single-tenant behavior is unchanged. Test: `TestScopeForFailsClosedInMultitenantPartialConfig`.
- **11** — new `agentsessions.AttachRevalidator` wired into the gateway (`cmd/ssh-gateway`): after ticket verification and the nonce burn, the gateway re-runs the exact mint relation (`can_operate` for read, `can_create` for turn) as the ticket's subject through `AuthorizeFreshOn` (uncached), and re-requires a live session phase for turns (read tickets replay terminal sessions by design). Mirrors the web shell's redemption-time reauthorization; a member revoked or a session canceled inside the 90s+30s ticket window is refused instead of getting one last read/turn. Tests: `TestAgentAttachRevalidatesAtRedemption` (transport), `TestAttachRevalidatorUsesFreshAuthorization` / `…MirrorsMintRelations` / `…TurnRequiresLivePhase` (policy).
- **13** — `lego/backend/internal/store/api.go`: `ValidRepo` rejects URL userinfo (`https://user:token@…` and the PAT-as-username form) on create and update across all surfaces; the one exception is a password-less `ssh://` username (`ssh://git@…` — an account selector, not a bearer secret; the SCP form has no password syntax). New `RedactRepoURL` strips userinfo from legacy rows at the `AppView` projection so a same-workspace viewer can no longer read another member's embedded token. Tests: four new `TestValidRepo` rejection rows + `TestRedactRepoURL`.
- **14** — `lego/backend/internal/apps/blueprint.go`: `UpdateBlueprint` runs every path mutation through `approvedBlueprintPath` (the discovery-time clean-path + `render.yaml`/`bex.yml` basename allowlist) and stores only the normalized result; `runSync` re-validates the stored path before the installation-token fetch, so a legacy row written before the rule cannot become an arbitrary private-repository file read either. Tests: `TestUpdateBlueprintEnforcesApprovedPath`, `TestSyncBlueprintRefusesLegacyUnapprovedPath` (asserts the fetcher is never reached).
- **15** — `dashboard/vite.config.ts`: the shared `readBody` helper for the dev-only Kratos/API tunnels enforces a 2 MiB cap (matching bex-api's `BEX_MAX_BODY_BYTES` default) — an oversized declared `Content-Length` is refused up front, and a streaming byte counter aborts mid-body otherwise; both proxy routes answer 413 instead of buffering without bound.
- **16** — two layers. `lego/backend/internal/workspaces/service.go`: `Delete` re-asserts `can_manage` through `AuthorizeFreshOn` after the audited check (the members-issuance pattern from round-5 finding 4), so a just-revoked admin cannot ride a ≤`PositiveTTL` cached positive on any replica into workspace destruction. `lego/backend/internal/authz/authz.go`: `RevokeWorkspaceMember` evicts every cached positive for the revoked subject via the new `core.TTLCache.DeleteKeyIf` (the key layout is `subject\x00relation\x00object`, so the subject prefix covers workspace **and** derived resource decisions), making same-replica revocation immediate for ordinary verbs too; other replicas drain within the TTL. Tests: `TestDelete_UsesFreshAuthorization`, `TestRevokeWorkspaceMemberEvictsCachedPositives`.

## Resolved operationally

- **6 (OAuth audience)** — the control was code-complete and flagged as inert in rounds 4–5; it was activated on 2026-08-13, the day before this scan's snapshot (w1/m68 t007, recorded in ADR012 §7): the live Hydra records for the Render CLI and bex-mobile carry `bex.co/platform-client`, and production bex-api runs with `BEX_OAUTH_REQUIRE_AUDIENCE=1`, so an audience-less human token from an unmarked DCR client is refused. The scan is static and cannot observe deployed environment — the code path it flagged is the documented opt-in, and the opt-in is now on. The startup warning for the off state stays (local dev runs without Hydra platform-client stamping).

## Deferred, with rationale

- **3 (default-namespace secret RBAC)** — real and confirmed: the self-managed pivot (m19.1, ADR019) put the CAPI PKI (`bex-ca`/`bex-etcd`/`bex-proxy`/`bex-sa`) and `bex-kubeconfig` in the app cluster's `default` namespace, which is also the legacy tenant-apps namespace where bex-api and the operator hold namespace-wide Secret verbs for per-app credentials — so compromise of either service can read the cluster's crown jewels. The fix is moving the CAPI-owned Secrets (and the Cluster/Machine objects that own them) to a dedicated restricted namespace — a `clusterctl move`-class live-cluster migration with rollback planning, not a manifest patch — plus optionally labeling per-app Secrets and scoping the Roles by selector. Tracked as a dedicated milestone; `docs/runbooks/operator-kubeconfig-isolation.md` already covers the adjacent admin-kubeconfig custody question.
- **4 (operator cluster-wide workload authoring)** — the operator legitimately writes workloads in dynamically created namespaces (the legacy apps namespace, `BEX_BUILD_NAMESPACE`, and every ADR043 per-tenant `<ws>`/`<ws>-sandbox` namespace bex-api's NamespaceReconciler mints on demand), so statically enumerated namespace-scoped RoleBindings cannot express the grant. The meaningful hardening is a `ValidatingAdmissionPolicy` constraining what the operator identity may create (allowed namespaces by label, allowed serviceAccountNames, no foreign Secret volume mounts) independent of controller code — a new mechanism, tracked as a follow-up alongside 3. The reconcile paths themselves construct constrained workloads (ADR039's audit), so exploitation requires operator compromise first.
- **8 (registry identity) and 10 (static object keys)** — the same two migration-gated sinks as ADR055 F3/F2 and ADR056 #1/#3, re-confirmed unchanged: re-keying Zot repositories invalidates every running Deployment's image ref, and re-keying S3 prefixes orphans published static sites until redeploy; both need the coordinated dual-read → migrate → redeploy → drop-fallback rollout already tracked. Exploitation still requires raw/legacy App CR creation outside the store-backed path (which tenant-prefixes names).
- **12 (mutable platform-phase image tags)** — same as ADR055 F7: pinning BuildKit/git/cosign/busybox/AWS-CLI phase images to digests needs the reviewed-digest update automation (multi-arch resolution + bump workflow) so pins don't rot; the skopeo phase demonstrates the mechanism. Tracked; not a patch-size change.
