# Security review round 5: codex-security repository scan (2026-08-13)

**Status:** implemented (13 of 17 fixed in place) · **Scope:** disposition of the 17 findings (8 high, 7 medium, 2 low) from the codex-security static repository scan against revision `444faf82`. Fifth pass in the ADR028 → w1/m53 → ADR045 → ADR055 → this lineage. Thirteen findings are fixed in place with regression tests; two are deferred as data-migration-gated (the same F2/F3 dispositioned in ADR055, re-confirmed unchanged); two are accepted/external (PSL and the GitHub installation-token scope model).

## Root-cause note

Four of the eight high findings (1, 3, 5, 8) are the ADR055 root cause recurring at four more shared sinks: a **workspace-local `App.Name` used as a global identity**. Because bex runs one namespace per workspace (ADR043), two tenants can own the same App name; any sink keyed on the bare name collides across tenants. This round splits them by whether the fix renames a persistent artifact: **cancellation (5) and NetworkPolicy (8) are logic/mechanism fixes** — the build/pre-deploy Jobs and pods already carry the immutable `app.bex.co/app-uid` / `app.bex.co/workspace` labels, so scoping the selector to them is safe and needs no migration — whereas **registry repos (1) and static S3 prefixes (3) rename live artifacts** (ImagePullBackOff / orphaned sites) and stay migration-gated exactly as in ADR055.

## Fixed in place

- **2** — `lego/backend/internal/metrics/service.go` adds `maxPointsPerSeries = 11000` (Prometheus's own `query_range` cap, so nothing that Prometheus serves today is newly rejected) and `checkPointBudget`, called after `normalized()` in both `Metrics` and `DatastoreMetrics` (`datastore.go`). `checkWindow` bounded only elapsed hours, so a viewer could pin a 1-second step across the full `BEX_MAX_QUERY_HOURS` window. Test: `TestCheckPointBudget`.
- **4** — `lego/backend/internal/core/base.go` defines the optional `FreshChecker` capability + `checkAuthzFresh`/`AuthorizeFresh`/`AuthorizeFreshOn`; `authz.CheckFresh` bypasses the ≤`PositiveTTL` positive cache. `members.Invite`, `members.ChangeRole`, and `apikeys.CreateAPIKey` re-assert their write relation uncached before issuing a durable capability, so a caller downgraded/revoked inside the cache window cannot mint replacement access. Tests: `TestAuthorizeFreshBypassesStalePositive`, `TestAuthorizeFreshFallsBackWhenNoFreshChecker`.
- **5** — `build.CancelActiveBuilds` / `cancelActiveKpackImages` / `predeploy.CancelSuperseded` take an `appUID` and add `app.bex.co/app-uid` to the `List` selector; the callers pass `string(app.UID)`. The Jobs/Images already carry that label (via `execution.PodLabels`), so this is a migration-free ownership scope. Tests assert a same-named foreign-UID Job survives (`TestCancelActiveBuilds`, `TestCancelSupersededDeletesOtherActiveRunsButKeepsCurrent`).
- **6** — `lego/agent-image/driver/src/session.ts` moves `scrubPersistedState()` **before** `deliverBranch`, and `deliverBranch` (`delivery.ts`) runs a fail-closed `git log -p base..branch` scan through the new `credentialManager.containsSecret` (`credentials.ts`), throwing before `git push` if any commit still carries the credential (a compressed git object the byte-scrubber cannot reach). Test: `deliverBranch refuses to push when a commit carries the model credential`.
- **7** — `lego/backend/internal/apps/domains.go`: `canonicalHostname` rejects any `*` host. The collision check and the store's `UNIQUE(host)` compare literals, so a wildcard and a concrete host beneath it looked non-colliding and both went live. Render offers no tenant wildcard custom domain; platform wildcards (`*.onbex.co`) come from the operator, not this boundary. Test: `TestAddDomainRejectsWildcard`.
- **8** — `app_controller.go`'s `reconcileExecutionNetworkPolicy` scopes the source `PodSelector` to `{labelApp, labelWorkspace: ws}` (ws is non-empty on this path and matches the destination scope). A same-named foreign-workspace build pod is no longer selected by this App's egress grant. The policy is rebuilt each reconcile, so no migration.
- **10** — `lego/backend/internal/agentsession/mint.go`: `"canceling"` added to `terminalPhases`. Cancel persists `canceling` before external teardown and leaves it on a teardown failure, so a retained/compromised sandbox in that state must not refresh a one-hour `contents:write` token. Test row added to `TestMinterRefusesTerminalOrForeignSession`.
- **11** — `lego/backend/internal/apps/service.go`: `SetRoutes`/`SetHeaders`/`SetPublishPath` raised from `can_operate` to `can_create` (content/security is developer, not lifecycle). `validateRoutes` rejects network-path redirect destinations (`//host`, `/\host`, control bytes); `validateHeaders` rejects non-token header names and CRLF values (response splitting). `validatePublishPath` rejects control chars but keeps absolute paths (image-backed sites serve a known in-image dir). Test: `TestStaticSetterValidationHardening`.
- **12** — `lego/backend/internal/environments/service.go`: `SetACL`, the ACL half of `Update`, and the ACL-bearing `CreateWithACL` require `can_manage` against the resource's own workspace; ordinary create/rename stay `can_create`. Protected-environment status arms the destructive-verb guard and network isolation, which the model classifies as admin. Test: `TestACLMutationsRequireCanManage`.
- **13** — `lego/backend/internal/agentsessions/service.go`: `AttachTicket` gates `action=turn` on `liveSandboxPhase(record.Phase)` + `RequireBillingMutation`, so a terminal/canceling session retained through the ADR054 editor grace window cannot run un-metered off-lifecycle turns. Read (transcript-replay) tickets stay phase-free. Test: `TestAttachTicketTurnRequiresLivePhase`.
- **15** — `lego/backend/internal/core/cidr.go`: `MaxAllowListEntries = 1000` fail-closes both shared validators (`ValidateCIDRs`, `ValidateAllowList`), so every REST/GraphQL/MCP write inherits the bound. `pg-sni-proxy`'s `resolve` now matches the exact SNI name before scanning that one entry's allowlist (mirroring the kv-proxy), so a handshake no longer scans every database's list under the router lock. Test: `TestValidateAllowListRejectsExcessCardinality`.
- **16** — `lego/backend/internal/api/tenancy.go` (`reconcileInviteRole`) and `lego/backend/internal/members/service.go` (`reconcileExactRole`): an OpenFGA `Check` error no longer folds into "role absent" (`err != nil || !has`). On an indeterminate check the loop attempts the idempotent revoke (or surfaces the error) instead of silently keeping a stale higher-role tuple. Test: `TestReconcileExactRoleRevokesOnCheckError`.
- **17** — `lego/backend/internal/logs/service.go`: `parseContainerLogLine` truncates a message above `maxLogMessageBytes = 64 KiB` (UTF-8-safe) at the source, bounding every downstream client (which cap by record count, not bytes) at once. Test: `TestParseContainerLogLineTruncatesHugeMessage`. Client-side aggregate-byte budgets (dashboard/mobile) remain a follow-up — lower leverage once the source is bounded.

## Deferred / accepted, with rationale

- **1 (registry keys) and 3 (static object keys) — migration-gated, unchanged from ADR055 F3/F2.** Confirmed current code still keys every Zot artifact and every S3 prefix on bare `app.Name`. Re-keying is destructive to change blindly: re-pathing the registry repo invalidates the image ref baked into every running Deployment (ImagePullBackOff until rebuild+re-push), and re-keying the S3 prefix orphans every already-published static site until it redeploys; the Zot htpasswd/ACL entries carry no owner record for a migration-free guard. These need a coordinated dual-read → migrate → redeploy → drop-fallback rollout, tracked for a dedicated milestone. The name-collision-defense hardening for the shared platform-builder repo (ADR055) remains the only in-place mitigation.
- **9 (`onbex.co` cookie isolation) — accepted risk (external), unchanged from ADR055 F9.** `onbex.co` is not on the browser Public Suffix List, so sibling tenant sites can set `Domain=onbex.co` cookies at each other. `hostingdomain.ValidateSharedSuffix` already logs this and continues by design; fail-closing it in production would take down all tenant hosting under the base domain. Real fixes are a PSL submission (external, multi-week) or per-tenant registrable domains (major architecture change).
- **14 (branch-confined agent credential) — GitHub token-scope limitation.** GitHub App installation tokens have no ref/branch scoping, so the in-sandbox agent can `git push origin HEAD:main` with a repository-scoped `contents:write` token even though the credential broker only ever presents the declared `bex-agent/*` branch. This is already acknowledged in `agentsession/contract.go` and ADR047, which delegate default/release-branch protection to tenant GitHub rulesets. A preventive fix requires a bex-operated `git-receive-pack` proxy that validates the destination ref server-side — a new component, tracked as a milestone, not a patch.
