## Objective

The image checks prove `wormhole` works, not only that it is present.

## Context

- `deploy/native-base/check-tools.py` (the per-tool checks, e.g. `pigz`, `zip`), `deploy/native-base/check.Dockerfile`, `.github/scripts/native-common-qualify.py`
- A CI runner should not depend on the public relay; the `magic-wormhole-mailbox-server` and `magic-wormhole-transit-relay` packages run a local pair.

## Steps

1. Add a check: `wormhole --version`; start a local mailbox and transit relay; send a file whose name has a space and non-ASCII characters; receive it with `--accept-file`; compare sha256.
2. Run it on amd64 and arm64 and on every runtime family the qualification covers.

## Files

- deploy/native-base/check-tools.py and its harness

## Acceptance criteria

- [x] The check passes on both architectures and fails when wormhole is removed
- [x] It needs no network beyond the runner

## Out of scope

## Record (2026-11-21)

Shipped in `c64b14cfd`.

- **The check:** [`deploy/native-base/check-wormhole.py`](../../../../deploy/native-base/check-wormhole.py). It requires `command -v wormhole` to be `/usr/bin/wormhole` with a `/usr/bin/python3` shebang and `wormhole --version` to equal dpkg's `magic-wormhole` record, then starts Bookworm's own `python3-magic-wormhole-mailbox-server` `0.4.1-2` and `magic-wormhole-transit-relay` `0.2.1-1` on loopback, sends an 8 MiB random file named `disk backup naïve ☃.bin` with `--no-listen` on both ends (so every byte crosses the transit relay), receives it with `--accept-file` and compares SHA-256, and requires a mistyped code (`8-bex-disk` against `8-bex-wrong`) to fail on both ends with nothing written. The servers are unpacked from their `.deb`s in a separate check stage and bind-mounted read-only: the candidate's packages and dpkg state are untouched, and the transfer step runs `--network=none`.
- **Where it runs:** `deploy/native-base/check.Dockerfile` (every candidate either factory publishes, linux/amd64) and `deploy/native-common/check-local.Dockerfile` (the common image's ARM64 smoke, which now has `deploy` as context and admits only this script through `check-local.Dockerfile.dockerignore`). Every family's generated image also runs a Shell's probe in `runImage` (`nativeWormholeProbe`): the same path and shebang checks, `wormhole --version`, and NaCl `SecretBox` and SPAKE2 round trips on the system interpreter, after the selected runtime is copied in; its output is the case's `wormhole.log` and `wormhole_probed` in `receipt.json`.
- **Results:** amd64, `magic-wormhole 0.12.0 sent 8388608 bytes through a local transit relay and refused a wrong code without network` in the publish jobs of push run [44906746328](https://github.com/bex-co/bex/actions/runs/44906746328) and families run [44906752907](https://github.com/bex-co/bex/actions/runs/44906752907); arm64, the same line in families run 44906752907's `common-arm64-local`. The generated-image probe printed `magic-wormhole 0.12.0` / `wormhole client loads on the system interpreter` for `node-compute`, `python313-original` (Python 3.13 primary and its virtualenv) and `python3148-default` in that run's utility cohort; the family legs are t003's record.
- **Fails when wormhole is removed:** the first assertion (`command -v wormhole`) fails with no `/usr/bin/wormhole`, in both the check and the probe; t007 records the full table.
