## Objective

Add an apps service-layer instance projection that authorizes the target App for `can_view`, lists its Kubernetes Pods via `core.PodLabelApp`, and maps the exact Render `ServiceInstance` fields (`id`, `createdAt`) without exposing Kubernetes details beyond the public contract.

## Context

- The operator stamps `app.bex.co/app` on long-running workload Pod templates; the backend constant is `core.PodLabelApp`.
- The official CLI's generated `ServiceInstance` contains only `id` and `createdAt` and sorts the returned array newest-first itself.
- Define and test deliberate inclusion semantics for rollout/terminating/completed Pods; do not accidentally include cron Job Pods or unrelated tenants solely because a name collides.

## Steps

1. Add a Render-shaped service-instance view and a `ListInstances` service method.
2. Fetch/authorize the App through `AuthorizeApp` before listing Pods.
3. Return an allocated empty slice when there are no eligible Pods and stable instance identifiers derived from the actual Pod identity.

## Files

- `lego/backend/internal/apps/`
- `lego/backend/internal/core/base.go` only if a shared label/helper needs adjustment

## Acceptance criteria

- [ ] One eligible Pod maps to exactly `{id, createdAt}`; zero eligible Pods maps to `[]`, never `null`.
- [ ] The service's own workspace authorization happens before Pod data can be observed.
- [ ] Rollout, terminating, cron, and completed-Pod inclusion semantics are explicit and covered rather than incidental.

## Out of scope

- Exec, SSH, shell access, or one-off jobs; those remain deliberate anti-goals.
