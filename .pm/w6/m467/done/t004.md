## Objective

`<id>-ro-<name>.<domain>` reaches only that replica's reader, and each replica's pooled public hostname reaches only its own PgBouncer.

## Context

- pg-sni-proxy: `dbRouter` in `lego/operator/cmd/pg-sni-proxy/main.go` adds every `<id>-ro-<replica>` label with backend `ro` (`:213`) and one `<id>-pool-ro` label with backend `pooler-ro` (`:209`), each with its admission capacity.
- Certificates: `databaseServerAltDNSNames` (`database_controller.go:1068`) and the issued public certificate (`database_public_tls.go`) name `<id>-pool-ro`.
- Status: `poolerExternalHost` is `<id>-pool-ro.<domain>` for every replica (`updateExternalAddressStatus`). `replicaPoolerLabel` (`:1090`) explains why a per-replica `-pool` suffix does not fit one DNS label.
- Admission: `readReplicaNameMaxLength` (`lego/backend/internal/postgres/admission.go:138`) derives from the replica id.

## Steps

1. Route each `<id>-ro-<name>` label to its replica's Service, and each replica's pooled label (t001's name) to its pooler, with the capacities m457 and m458 set (`maxConnections` direct, `tiers.PostgresPoolerMaxClientConn` pooled).
2. Put every per-replica name in the certificate names and in each replica's `externalHost` and `poolerExternalHost`. Drop `<id>-pool-ro`.
3. If the label scheme changes the longest name a replica may have, change `readReplicaNameMaxLength` with it, and keep names bex already accepted working.

## Files

- `lego/operator/cmd/pg-sni-proxy/main.go`, `lego/operator/internal/controller/database_controller.go`, `database_public_tls.go`
- `lego/backend/internal/postgres/admission.go` only if the bound changes

## Acceptance criteria

- [x] pg-sni-proxy tests: `a`'s direct and pooled labels resolve to `a`'s backends and `b`'s to `b`'s, each with its capacity; a removed replica's labels stop resolving.
- [x] Controller tests: the certificate names and replica statuses carry each replica's own public hosts.
- [x] `make test`, `make lint` and, if touched, `cd lego/backend && go test ./internal/postgres/...` pass.

## Out of scope

- The edge load balancer (w6/136).

## Result — 2026-11-18

pg-sni-proxy routes `<id>-ro-<name>` and `<id>-rp-<name>` to the Services of the same names (`TestRouterResolve`, `TestRouterHostnameIndexIsExact`, `TestRouterCarriesEachRoutesCapacityFromThePlan`); the certificate names and statuses carry each replica's own hosts (`TestDatabaseServerAltDNSNames`, `TestDatabasePublicFrontDoorStatus`). `readReplicaNameMaxLength` is unchanged: `-rp-` is as long as `-ro-`.
