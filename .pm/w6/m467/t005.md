## Objective

Show on dev-6 that two pooled replicas are two readers with two pools, and record the shipped behavior.

## Context

- dev-6 shares the cluster's bex operator (m458's shared-cluster limit), so apply the specs the tree's operator generates (as m458 t002 and t004 did), or run the tree's manager scoped to `dev-6` if that can be done without touching other workstreams' stacks.
- Plans: replicas need 0.5 CPU and 10 GB, HA needs 1 CPU (ADR009 § HA). `basic-4gb` with 10 GB carries both. HA's required anti-affinity puts each instance of the HA Cluster on its own node; `bash scripts/mock-cluster.sh scale N` adds workers if the local cluster has too few.
- Load: `pgbench` from a pod in `dev-6`, as m458 t002.

## Steps

1. Create an HA database with replicas `a` and `b` and pooling.
2. Through `a`'s and `b`'s pooled URLs at once, run 1,000 clients each: `SHOW POOLS` on each PgBouncer and `pg_stat_activity` on each replica's instance read 90 server connections; no failed transaction.
3. `inet_server_addr()` through each of `a`'s URLs is `a`'s instance and never the HA standby or the primary; the same for `b`.
4. Switch over, then delete the primary Pod: every replica URL stays on a non-primary instance that is not the HA standby.
5. Change the plan and remove `b`: no primary Pod rolls, and `a`'s clients stay connected.
6. Update ADR009 § Named read replicas and § Managed PgBouncer settings, and ADR018's HA row, with the behavior and this evidence. Delete the probe.
