## Objective

Using t001's settled Stripe semantics, fix `lego/backend/internal/billing/read.go` so `currentCost.amountUsd` (and the equivalent for finalized invoices) always reports the gross current-period charge, never silently netted to zero by credit-grant consumption — and expose "credit consumed this period" as its own explicit value so the two are never conflated again.

## Context

- `currentInvoice()`, `lego/backend/internal/billing/read.go:255-272`, line 265: `amount, err := normalizedStripeAmount(inv.Total, inv.Currency)`.
- `finalizedInvoices()`, `lego/backend/internal/billing/read.go:274-306`, line 288: same pattern, same bug class, for historical invoices.
- `normalizedStripeAmount()`, `read.go:308-317` — pure minor-units-to-string formatter; reusable regardless of which Stripe field feeds it.
- `creditsFor()`, `read.go:138-168` and the `Credits`/`CreditGrant` types (`read.go:42-51`) — the existing, deliberately-separate, non-invoice-preview-derived credit read. This task should NOT duplicate that mechanism; it's about fixing what `currentCost`/`Invoice.amountUsd` themselves report.
- GraphQL wiring: `lego/backend/internal/usage/graphql.go:131` (`currentCost.amountUsd`) and `:143` (`invoices[].amountUsd`) — confirmed the only consumers (no REST/MCP).
- `docs/ADR040-billing-metronome.md:76` currently says "`currentCost` comes from Stripe's current Subscription invoice preview" without specifying gross vs. net — update this line once the fix lands so the contract is documented, not just implemented.

## Steps

Decide the schema shape for "credit consumed this period": either (a) add a new field to `Billing`/`Amount` (e.g. `CreditsAppliedUSD` on `CurrentCost`), or (b) confirm the existing separate `Credits` block already gives the dashboard what it needs once `currentCost` itself is gross — pick based on what t003's dashboard reconciliation actually needs, coordinate with that task.

## Outcome

Schema shape: **option (a)** — two new fields on both `billing.Amount` and `billing.Invoice`, so the current period and invoice history read the same way:

- `amountUsd` — gross rated charge, now `inv.Subtotal` (was `inv.Total`).
- `creditsAppliedUsd` — Σ `inv.TotalPretaxCreditAmounts[].Amount` where `Type == credit_balance_transaction` (`appliedCreditGrants`, `read.go`).
- `amountDueUsd` — `inv.AmountDue`, Stripe's own figure for what is collected.

`currentInvoice()` and `finalizedInvoices()` both go through one `invoiceFigures(inv)` helper, so the two call sites cannot drift again. `normalizedStripeAmount` (which returned a whole `Amount` just to format a number) became `normalizedStripeUSD` + a pure `usdString` formatter, still shared with the credit reads. GraphQL exposes both new fields on `BillingAmount`/`BillingInvoice`; REST and MCP serialize `*billing.Billing` directly, so they carry them with no adapter change. `docs/ADR040-billing-metronome.md` § 4 now states the gross/credit/due contract and that Mode B comps are not counted as credit.
