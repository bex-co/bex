## Objective

Add tests that would have failed before this milestone and would fail again if any surface drifts back. Assert real behavior and failure modes; do not snapshot the whole object.

## Context

- The gap this milestone closes was invisible to the existing tests because each surface was tested **against itself**: `TestRESTDisplayNamePatchRoundTripAndOmission`, `TestGraphQLDisplayNameRoundTrip` and `TestMCPDisplayNameRoundTrip` (cited in `w6/m101/t004`) each assert one surface's `name`/`displayName` pair, and all three passed throughout. A cross-surface assertion is the missing shape.
- `c95a952d test(webhooks): pin the renamed-service projection (w6/m101)` is the precedent for the webhook half.

## Steps

1. Add a test that reads the same renamed service through the REST, GraphQL and MCP fragments in one case and asserts the `name` values are equal — not that each equals a literal, which is what let them drift apart.
2. Add the control: a service with no `displayName`, asserting all three still return the immutable name.
3. Cover the five App-CR-backed types (`web_service`, `private_service`, `background_worker`, `cron_job`, `static_site`) — they share `AppView`, so a table test is enough, but it should be explicit that all five are covered.
4. Cover t003's field and t004's resolution behavior, including the duplicate-display-name case and the forbidden-vs-nonexistent indistinguishability.
5. Confirm the new tests fail with t002 reverted.
