## Objective

Write down, once, which string a service's `name` is on a read surface — and where the other two strings live. Every later task in this milestone is a mechanical consequence of this decision, and without it the milestone is satisfiable by normalizing all four surfaces onto whichever value is easiest to reach.

## Context

- Three strings exist per service today: the **immutable workspace-unique name** (`AppView.Name`, carried in `core.LabelServiceName`, `core/base.go:175-182`), the **mutable display label** (`AppView.DisplayName`, `spec.displayName`), and the **platform-unique host segment** (`AppView.Slug` = `a.Spec.PlatformSubdomain(a.Name)`, `apps/service.go:846`).
- `renderServiceName` (`apps/render.go:508-515`) already encodes one answer for `name`: display label when set, else immutable name. Its comment cites Render's contract, "where service.name itself is mutable".
- Render's own contract, for comparison: `name` is mutable; `slug` is derived at creation and stable; `GET /v1/services/{serviceId}` accepts **only** the `srv-…` id.
- `AppView.Slug`'s doc (`apps/service.go:346-353`) is explicit that slug is **not** a synonym for the immutable name: after a cross-tenant collision it is `<name>-<4-char suffix>`.

## Steps

1. Decide the value of `name` on every read surface. The default answer is `renderServiceName` (matches Render, matches REST/MCP/webhooks today, matches the dashboard's own `ServiceView.name` doc comment) — record the reasoning, not just the choice.
2. Decide where the immutable workspace-unique name is readable from. It is currently only GraphQL's `name`; after t002 it will be nowhere. `slug` is not a valid answer (see Context).
3. Decide whether name-based addressing is part of bex's contract at all, or a legacy-CR compatibility shim (`w1/m46`) that should be documented as id-only going forward. This is what t004 implements.
4. Write the decision into `docs/ADR006-bex-api.md` next to the existing service-object description, and add or update the rename row in `docs/ADR018-render-parity.md`. `w6/m101/t004` already amended both files for the webhook half; extend that text rather than starting a second account.
