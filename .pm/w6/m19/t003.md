## Objective

Give the operator visibility into Environment membership by projecting it onto App CRs as a label, mirroring the existing `core.LabelProject` pattern.

## Context

- `lego/backend/internal/core/base.go:101` defines `core.LabelProject = "app.bex.co/project-id"`, consumed nowhere by NetworkPolicy generation today.
- Environment membership currently lives **only** in Postgres (`apps.environment_id`, `lego/backend/internal/store/environments.go:116-140`, `SetEnvironmentServices`/`ListEnvironmentServices`) and is never projected onto the App CR — a deliberate scope cut noted in `docs/ADR032-environments.md`.
- This label is a prerequisite for t004 (operator NetworkPolicy) and for `w6/m20` (Database/KeyValue environment coverage).

## Steps

1. ~~Add `core.LabelEnvironment = "app.bex.co/environment-id"` to `lego/backend/internal/core/base.go`.~~ **Already done** — `w6/m20` needed the constant to exist for its own `SetEnvironmentID` verbs (postgres/keyvalue) and added it as a shared prerequisite ahead of this task (`lego/backend/internal/core/base.go`, next to `LabelProject`). This task's remaining scope is steps 2-3 below (the App-CR projector), which `w6/m20` explicitly left out of scope.
2. In `environments/service.go`, when `SetEnvironmentServices` assigns/unassigns an App to/from an Environment, write/clear the label on the App CR (same call site pattern as `postgres.Service.SetProjectID`, `lego/backend/internal/postgres/service.go:494-510`).
3. Backfill: on read, if an App is a member per Postgres but the label is missing (pre-existing assignments), write it lazily or via a one-time reconcile pass.
