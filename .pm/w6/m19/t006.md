## Objective

When an Environment sets an `ipAllowList`, apply it to member Database/KeyValue resources' existing per-resource external-endpoint allowlist.

## Context

- Per-resource `ipAllowList` already exists: `lego/backend/internal/postgres/access.go:48-74` (`GetIPAllowList`/`SetIPAllowList`, `Database.Spec.IPAllowList`), mirrored for KeyValue.
- This task composes environment-level allowlist with the existing per-resource mechanism rather than replacing it.
- Depends on `w6/m20` conceptually for full Database/KeyValue environment membership, but a Database/KeyValue can already be looked up per-App-environment indirectly if needed; scope this task to Apps' associated datastores if `w6/m20` hasn't landed yet, and note the fuller version once it has.

## Steps

1. Add a helper that computes the effective `ipAllowList` for a Database/KeyValue as environment ∪ resource-level entries (or environment as the source of truth for member resources — decide additive vs. override at implementation time and record the choice in the PR).
2. Apply the effective list when reconciling the CR's external endpoint firewall rules.
3. Recompute when the environment's `ipAllowList` changes.

## Files

- `lego/backend/internal/postgres/access.go`
- `lego/backend/internal/keyvalue/` (mirror path)
- `lego/backend/internal/environments/service.go`

## Acceptance criteria

- [ ] Changing an Environment's `ipAllowList` updates effective access for member datastores without a manual per-resource edit.
- [ ] Resource-level `ipAllowList` edits still work standalone (no regression) for resources with no environment.

## Out of scope

- Full Database/KeyValue environment-membership model (see `w6/m20`).
