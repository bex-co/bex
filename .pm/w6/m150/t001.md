## Design notes — 2026-10-21 (measured, not yet reviewed)

Generated containerd v2.3.1's `contrib/seccomp.DefaultProfile` for `render-v1`'s bounding set (CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETUID, SYS_CHROOT) on linux/amd64 and linux/arm64. That is exactly what RuntimeDefault applies to a `render-v1` pod today.

- **Today's profile:** default action `SCMP_ACT_ERRNO` and 14 rules.
  - `clone` is allowed only when `flags & 0x7E020000 == 0`, i.e. no `CLONE_NEWNS|NEWUTS|NEWIPC|NEWUSER|NEWPID|NEWNET|NEWCGROUP`.
  - `clone3` returns `ENOSYS`, so glibc falls back to `clone`.
  - `unshare`, `setns`, `mount`, `umount2`, `pivot_root` and the `io_uring_*` syscalls are not allowed. containerd grants the namespace/mount set only with `CAP_SYS_ADMIN`.
- **Proposed `bex-render-v1.json`:** the generated profile, unchanged, plus three changes.
  1. `clone` without the namespace-flag mask. The kernel still refuses namespace creation except for a new user namespace and the namespaces nested inside it.
  2. An allow rule for `unshare`, `setns`, `mount`, `umount`, `umount2`, `pivot_root`, `mount_setattr`, `move_mount`, `open_tree`, `fsopen`, `fsconfig`, `fsmount`, `fspick`, `sethostname` and `setdomainname`. These are what bubblewrap and the Chromium sandbox use inside their own user namespace; the kernel scopes each one to namespaces the caller owns.
  3. An allow rule for `io_uring_setup`, `io_uring_enter` and `io_uring_register`.
- **Kept blocked:** `bpf`, `perf_event_open`, `fanotify_init`, `lookup_dcookie`, `quotactl`, `syslog`, `kexec_*`, module loading, `keyctl`/`add_key`, `userfaultfd`, and `clone3`, which stays `ENOSYS`.
- **Distribution:** write the profile through the Cluster API node bootstrap `files:` (`infra/clusterapi/overlays/hetzner-caph/cluster.yaml` already ships files there) to `/var/lib/kubelet/seccomp/profiles/bex-render-v1.json`. The file then exists before the kubelet admits any pod, with no DaemonSet race. The cost is a tenant MachineDeployment rollout.
- **Still to do for t001:** record the tenant-node kernel version and its userns knobs (`user.max_user_namespaces`, any `kernel.unprivileged_userns_clone`), write the residual-risk statement in ADR089, and commit the generator (`scripts/`, own `go.mod`) so the profile is reproducible.
