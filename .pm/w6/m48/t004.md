## Objective

Confirm the null-vs-empty-string fix (t001) is consistent across REST, GraphQL, and MCP for every field it touches, and that the dashboard (t002, t003) agrees with all three. Compare against render.com's equivalent behavior and flag any drift as follow-up rather than silently diverging.

## Context

- REST already omits the field via `omitempty` — the fix in t001 is GraphQL catching up to REST, not the reverse. Confirm MCP (which likely serializes the same view structs) agrees too.
- `docs/ADR006-bex-api.md` — bex-api's REST/GraphQL/MCP surfaces are meant to be equivalent.
- **Code-confirmed (2026-08-23), not yet independently live tool-called:** `get_postgres`/`get_key_value`/`get_env_group` (and their `create_`/`list_` siblings) all return the same `View` struct REST uses — `PostgresView`, `KeyValueView`, `EnvGroupView`, each with `EnvironmentID string \`json:"environmentId,omitempty"\`` — with no reshaping in between (e.g. `lego/backend/internal/postgres/mcp.go:105-110`'s `get_postgres` handler returns `v` from `s.GetPostgres` directly). `lego/backend/internal/mcputil/mcputil.go:40-46`'s `AddTool` is a thin wrapper over the go-sdk's `mcp.AddTool` with no custom marshaling that would bypass the struct tag. So MCP should already agree with REST (i.e. already correct, not part of this bug) for all four types — this needs one real MCP tool-call probe per type to convert "code says it's fine" into "confirmed live," not a re-derivation of the code argument above.

## Steps

1. For `envGroup`/`envGroups` and each migrated resource type (`service`/`postgres`/`keyValue`), confirm the MCP tool output (list + get) also nulls/omits the unset field, matching REST and the now-fixed GraphQL.
2. Compare against render.com's documented behavior for the equivalent optional relationship fields (Render's API generally omits/nulls unset optional fields) — note any deliberate bex divergence in `docs/ADR018-render-parity.md` if one is found; otherwise confirm agreement.
3. Confirm the dashboard's env-groups UI (t002) and the shared create-form hint (t003) both reflect the corrected backend contract live.
