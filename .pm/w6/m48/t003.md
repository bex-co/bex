## Objective

`ProjectEnvironmentSelector` (shared by the New Service, New Database, and New Key Value forms) presents "Project" as an independently meaningful selector — its own label, its own accessible name, its own "No project" option, laid out parallel to "Environment" — but selecting a Project alone has zero effect: the mutation input has no standalone `projectId`, the backend's `CreateRequest` has no `ProjectID` field, and the component's own doc comment says so plainly ("only the Environment id is submitted because assignment auto-joins its parent Project"). The hint text below the two selectors reads "Optional. Selecting an environment also adds the resource to its project." — the word "also" tells the reader that picking a Project already did something, which it did not. Rewrite the copy to state the actual mechanism, so a user arriving at "+ New Service" from inside a Project's own page and leaving Environment unset isn't misled into thinking their resource joined that project.

Selecting an environment also adds the resource to its project." Mirror in `dashboard/src/features/environments/locales/zh.ts`.
