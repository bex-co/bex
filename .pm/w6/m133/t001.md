## Objective

`spec.parameters` — what the tenant actually declared — is readable on **no** API surface, which is why the dashboard editor had nothing correct to bind to. Expose it. Nothing downstream can be fixed until a correct read exists.

## Context

- `GetParameterSpec` (`lego/backend/internal/postgres/insights.go:392`) is already written and documented: "returns the currently stored parameter overrides from the Database CR (spec.parameters), not from pg_settings. Use ParameterOverrides for the live database view." It returns `map[string]string{}` when `d.Spec.Parameters` is nil.
- It is exposed nowhere: `grep -rn "GetParameterSpec\|parameterSpec\|ParameterSpec" lego/backend/internal/postgres/{graphql,rest,mcp}.go` returns nothing.
- `parameters` is also absent from the Postgres view — the `POST /v1/postgres` response's complete top-level key list is `id, name, plan, version, status, databaseName, databaseUser, diskSizeGB, diskAutoscalingEnabled, highAvailabilityEnabled, readReplicas, suspended, createdAt, updatedAt, region, dashboardUrl, public, ipAllowList, poolerEnabled, connectionPool, backupsEnabled, ownerId, owner`.
- Consequence today: `spec.parameters` is effectively **write-only** — a tenant can declare overrides and never read back what they declared.
- The three-surface rule applies (`internal/api/CLAUDE.md`): a new verb goes in `service.go` and each of `rest.go` / `graphql.go` / `mcp.go` maps it.

## Steps

1. Add the read to GraphQL, REST and MCP, naming it so it cannot be confused with the `pg_settings` view — the two must be distinguishable by name alone, since conflating them is the whole defect.
2. Decide whether the declared set also belongs on the Postgres view object, or stays a separate read.
3. Confirm it returns empty for a freshly created database and the declared set after a write.

## Files

- `lego/backend/internal/postgres/{service,graphql,rest,mcp}.go`
- `lego/backend/internal/postgres/insights.go` (the existing `GetParameterSpec`)

## Acceptance criteria

- [ ] The declared overrides are readable on GraphQL, REST and MCP.
- [ ] A fresh database returns an empty declared set.
- [ ] After setting one parameter, the read returns exactly that one.
- [ ] The new read's name is unambiguous against the `pg_settings` view.
