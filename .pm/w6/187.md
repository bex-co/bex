# 187 — A Node service's build and start commands cannot run a package's own binary by name, which Render's `deploy-blitz` guide does

Why: Render's own Blitz guide gives `buildCommand: … && blitz prisma generate && blitz build …` and `startCommand: blitz start`, so a project that calls its dependencies' binaries directly is meant to build on Render, while on bex every such command exits 127.

- **Source:** w6/m653 t003 (2026-11-26), the live run of the 49 remaining no-value `render-examples` templates ([render-examples-live.md](../../docs/render-artifacts/render-examples-live.md)).
- **Seen** on production pin `9b91284a4a2e`, in `bex-canary`, with `scripts/render-examples-live.sh blitzjs` (render-examples/blitzjs@ccff87a). `yarn --frozen-lockfile --prod=false` installed `blitz` into `node_modules/.bin`, then the build log reads `/bin/bash: line 2: blitz: command not found` and `error: build command '…' exited with code 127`. The fixture was deleted by ID (404).
- **Not the template's outcome:** with `node_modules/.bin` on `PATH`, the same build on `node:24.22.1-bookworm` (Render's default Node on Debian 12) stops at `blitz prisma generate` with `Unknown binaryTarget debian-openssl-3.0.x`, because Prisma 2.27 predates OpenSSL 3. So `blitzjs` fails on Render too, and its row says so. This note is only about the `PATH`.
- **Where:** the native Node image sets no `PATH` entry for the project's `node_modules/.bin` (`nativeBuildDefaults`, `lego/operator/internal/build/native.go`), while it puts Go's `GOPATH/bin`, Python's virtualenv and Ruby's gem `bin` first. An npm, yarn or pnpm script gets the directory from its package manager, so only a bare command is affected.
- **Render:** its docs do not state the `PATH`. Its maintained `deploy-blitz` guide (updated to the `0.5c-512mb` plan ids) calls `blitz` bare in both commands. Heroku's Node buildpack, the model for Render's native runtimes, puts `node_modules/.bin` on `PATH` for the build and at runtime. Read `PATH` on a render.com Node service (build and runtime) before changing anything.
- **Do:** if Render's `PATH` carries `/opt/render/project/src/node_modules/.bin`, put it in the same place for a Node service's build command, pre-deploy command and start command, and record the read in ADR018's native runtime row.
- **Acceptance:**
  - [ ] Render's Node `PATH` is recorded, read from a live render.com build and start.
  - [ ] If it carries `node_modules/.bin`, a Node service whose build command runs a dependency's binary by name builds on bex, with a regression test in the native build's tests.
- **Estimate:** ~45m once Render's `PATH` is read.
