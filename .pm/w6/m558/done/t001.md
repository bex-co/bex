## Objective

Write down Render's evidence for where a native service with a root directory runs and keeps its virtualenv and dependency caches, count production's affected services, and decide how an existing service's disk under `/opt/render/project/src/…` keeps landing in its tree.

## Context

- `lego/operator/internal/build/native.go`: `nativeSourceDir` (:579), `nativeGoSourceDir` (:616, its segment validation), `nativeSourceLink` (:594), `nativePythonVenv` (:563).
- `lego/operator/internal/build/depscache.go:88-110` (`nativeDependencyDirs`: Rust `target`, Elixir `deps`/`_build`, the Python virtualenv; the seed and save steps).
- `lego/operator/internal/build/nativestaticdeps.go:162` (the publish check `cd`s to `nativeWorkdir`), `lego/operator/internal/publish/publish.go:653` (the extract reads `PUBLISH_PATH` from the image's `WORKDIR`).
- w6/m546's [t001 record](../done/m546/README.md#t001-record-renders-go-source-path-and-the-layout-2026-11-21) and [t004 record](../done/m546/done/t004.md): containerd and runc resolve a mount path's links inside the image (measured on production).
- The new directory sits inside `/opt/render/project/src`, so m546's whole-directory link cannot apply.

## Steps

1. Quote Render with the date read: [monorepo-support](https://render.com/docs/monorepo-support), the [disks](https://render.com/docs/disks) table, [environment-variables](https://render.com/docs/environment-variables) (`VENV_ROOT`), Render's build cache docs (Rust's "any target directory at your repo root", Elixir), Python's Poetry/uv docs, and build logs Render users published that name `/opt/render/project/src/<rootDir>/…` or a `.venv` path. Mark each rule verified, inferred or unverified.
2. Decide, per runtime: the `WORKDIR`, the virtualenv, Rust's `target`, Elixir's `deps` and `_build`, and a static site's build directory with the publish check and the extract. Go stays as m546 left it.
3. Count production's native services (not Go, not Docker) with a root directory, and those with a disk, with their mount paths (`bash scripts/fetch-app-kubeconfig.sh <path outside the repo>`, `kubectl get apps.app.bex.co -A -o json`).
4. Choose how an existing disk follows, and what a new service with a disk at `/opt/render/project/src/uploads` and root directory `backend` gets (on Render that path is outside its tree). Candidates:
   - (a) the image links each top-level entry of the root directory, `/opt/render/project/src/<entry>` → `<rootDir>/<entry>`. This misses a directory the app makes at runtime.
   - (b) the operator mounts a disk under `/opt/render/project/src/` but outside `<rootDir>/` at the translated path, for a service whose disk predates the change.
   - (c) native-init links what is mounted at start.
   Measure the chosen one on production's runtime before relying on it.
