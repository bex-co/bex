## Objective

Stop this defect class landing a third time. `w4/m19` fixed it on the create response and added a per-site regression test; Generate Blueprint shipped later (`w8/m22`, `487eab31`) with the same bug, because a per-site test cannot cover a site that does not exist yet.

## Context

- `w4/m19`'s summary: "a real name-leak bug — the create response echoing the tenant-prefixed CR name instead of the public service name — found and fixed in the t009 simplify pass, with a regression test" (`TestCreate_ResponseNameIsThePublicNameNotTheCRName`, `createowner_test.go`).
- The tenant prefix has a fixed, greppable shape: `tea-` + a 20-char id + `-`. Any user-facing payload containing it is almost certainly wrong.
- This is a guard task, not a rewrite: the goal is one check that fails loudly, not an audit that goes stale.

## Steps

1. Decide the guard's form and say why: a test that walks every user-facing serializer's output for a `tea-…` prefix, a lint over `a.Name` uses in `internal/apps`, or an assertion helper the existing response tests all call. Prefer whichever fails on a *new* surface without that surface opting in.
2. Enumerate today's user-facing name emitters and confirm each is correct — `grep -rn "a\.Name\|app\.Name" lego/backend/internal/apps --include='*.go' | grep -v _test` and classify: internal (k8s lookups, selectors — correct) vs user-facing payload (must be the public name).
3. Implement the guard and prove it red: revert `t001`'s fix locally, watch the guard fail, restore.
4. Record the emitter classification in the milestone README so the next reader sees which `a.Name` uses are deliberate.

## Files

- `lego/backend/internal/apps/` (tests + whichever emitters the classification flags)

## Acceptance criteria

- [ ] The guard exists and was proven red against the pre-fix behavior, not just green after it.
- [ ] Every user-facing `a.Name` emitter is classified internal-vs-user-facing, with the list recorded.
- [ ] `w4/m19`'s existing regression test still passes untouched.
- [ ] The guard catches a hypothetical new surface without that surface having to opt in.

## Out of scope

- Renaming or restructuring `CRName` itself.
