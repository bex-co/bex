## Objective

Make the exported `name` the value a user would type to create the same service, and establish how many entrypoints reach this generator — the filing exercised only the dashboard dialog.

## Context

- `lego/backend/internal/apps/blueprint_generate.go:177` emits `"name": a.Name`, the CR object name `core.CRName(tenantID, name)` (`core/base.go:1379`, applied `apps/service.go:1736`).
- The public name is available on the same object: `core.LabelServiceName` (`core/base.go:175-182`) is documented as carrying "an App CR's **PUBLIC** name (w4/m19)".
- **Edge case that must not be broken:** a legacy bare-object-named App (pre-w4/m19, "never renamed in place" per `core/base.go:1381-1393`) carries no `LabelServiceName`, and the `tenantID == ""` path skips the prefix entirely. For those, `a.Name` already *is* the public name, so the fallback must be `a.Name`, not an empty string.
- Three names exist at once on a service — `name` (public, workspace-unique), `slug` (globally unique subdomain), `displayName` (mutable label). Only `name` round-trips through create, so it is the one the manifest must carry; say so explicitly in the code comment.
- The siblings already do this correctly: databases `d.Spec.Name` (`:361`), key-values `kv.Spec.Name` (`:397`), cross-refs a resolved `display` (`:328`, `:347`).

## Steps

1. Emit the public name, with the documented fallback for the legacy unprefixed case.
2. Add a comment naming *which* of the three names this is and why, so the next reader does not "fix" it to `displayName`.
3. `grep -rn "GenerateBlueprint" lego/backend --include='*.go' | grep -v _test` — record the exact caller count and every entrypoint (REST? GraphQL? MCP? dashboard-only?), and put the number in the milestone README per DoD bullet 6.
4. Re-run the live loop: generate from a service, feed the output verbatim to `validateBlueprint`, expect `valid: true`.
5. Confirm no `tea-` string survives anywhere in the output, not just in `name`.
