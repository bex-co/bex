## Objective

When a delete or suspend on a protected-Environment Database/KeyValue is rejected by the backend's new 400, the dashboard should catch it and prompt the exact server-issued confirmation phrase — reusing the pattern Services already ships, not inventing a new one.

## Context

- `dashboard/src/features/services/components/protected-confirmation-dialog.tsx` is the existing, working component: takes `requiredConfirmation` (parsed from the server's error message) and an `onConfirm(confirmation)` callback that retries the mutation with `confirm` set.
- `dashboard/src/features/services/components/service-row-actions.tsx` / `delete-service-card.tsx` show how it's currently wired: catch the 400, extract the required phrase, open the dialog.
- Target files: `dashboard/src/features/databases/components/database-row-actions.tsx` (already has a typed-name delete confirm dialog — this is a **second**, separate dialog that appears only when the first one's delete call comes back protected) and the equivalent Key Value row-actions component (`dashboard/src/features/keyvalue/components/` — find the exact file).
- Decide whether to generalize `ProtectedConfirmationDialog` (rename the `serviceName` prop to something resource-neutral) and move it to `common/components/`, or keep three near-identical copies — follow the codebase's existing precedent (`w6/m20`'s closeout declined over-generifying a similar duplication; use judgment based on how much the three copies would actually diverge).

## Steps

1. Wire the suspend flow (already has a simple confirm dialog in `database-row-actions.tsx:176-216`) to catch a protected-environment 400 and open the phrase-confirmation dialog instead of just failing.
2. Wire the delete flow similarly — after the existing typed-name confirm succeeds locally, if the backend rejects with the protected-environment 400, surface the second dialog instead of a generic error toast.
3. Repeat for the Key Value feature's row-actions component.
4. Add/extend translation keys (`databases.protectedConfirmation*`, `keyvalue.protectedConfirmation*` or shared `common.*` keys, per `dashboard/CLAUDE.md`'s i18n rules — every user-visible string goes through `t()`).

## Files

- `dashboard/src/features/databases/components/database-row-actions.tsx`
- `dashboard/src/features/databases/hooks/use-delete-database.ts` (and a suspend-equivalent hook)
- `dashboard/src/features/keyvalue/components/*-row-actions.tsx`
- `dashboard/src/features/services/components/protected-confirmation-dialog.tsx` (reused or generalized)

## Acceptance criteria

- [ ] Deleting or suspending a Database/KeyValue in a protected Environment surfaces the exact required phrase and blocks the action until it's typed correctly.
- [ ] An unprotected Database/KeyValue's delete/suspend flow is unchanged.
- [ ] `yarn typecheck && yarn lint && yarn test` pass.

## Out of scope

- Any new dashboard surface for viewing/editing an Environment's `protectedStatus` itself — that's out of this milestone; only the destructive-verb consumer side is in scope.
