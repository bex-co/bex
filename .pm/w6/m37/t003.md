## Objective

Block `keyvalue.Service.Delete` and its suspend path on a Key Value instance that belongs to a protected Environment, unless the caller echoes back the matching confirmation phrase — mirroring t002's Postgres implementation and `apps.Service`'s original guard.

## Context

- Same reference implementation as t002: `lego/backend/internal/apps/protection.go`.
- Use `"key value"` (or whatever word the Render-parity capture in `docs/render-artifacts/key-value.md` uses for the resource) as the `ProtectedConfirmation` resource word.
- If t002 promoted the confirm-context helpers to `core`, reuse them here rather than re-implementing.
- Resume stays unguarded, matching Apps/Postgres.

## Steps

1. Add `requireUnprotected(ctx, kv *v1alpha1.KeyValue, verb string) error` to `keyvalue`, using t001's `GetEnvironmentProtectedStatus` + CR label read.
2. Wire it into `Delete` and the suspend verb, before the mutating call.
3. Match the same error shape as t002 for adapter consistency.

## Files

- `lego/backend/internal/keyvalue/protection.go` (new)
- `lego/backend/internal/keyvalue/service.go`

## Acceptance criteria

- [ ] Deleting/suspending a Key Value instance in an unprotected (or environment-less) Environment behaves byte-identically to today.
- [ ] Deleting/suspending one in a protected Environment without `confirm` returns a named 400 naming the exact required phrase.
- [ ] The same call with the correct `confirm` phrase succeeds.
- [ ] Resume is not guarded.

## Out of scope

- REST/GraphQL/MCP wiring of the `confirm` parameter itself — t004/t005/t006.
