## Objective

Apply t001's decision on every path that can set a replica count. A cap on `Scale` alone is reachable around.

## Context

- `lego/backend/internal/apps/service.go:3010-3038` (`Scale`) — the main path. Validates `replicas < 1 || replicas > store.MaxReplicas` only. Reached from REST `POST …/scale`, GraphQL `scaleService`, and MCP `scale_service`: one implementation, three surfaces (ADR018 row 68).
- **Create** also sets replicas, without going through `Scale` — find its validation and gate it the same way, or a caller simply creates at N instead of scaling to N.
- **Autoscaling** `minInstances`/`maxInstances` (ADR018 row 69) is the third writer: the operator's autoscaler drives `replicas` within that range, so an uncapped `maxInstances` reintroduces the same outcome by a different door.
- If t001 put the limit in `ComputeTier`, read it from there rather than testing for the literal `"free"` — the plan catalog is where the CPU/memory bounds already live.

## Steps

1. Add the cap to `Scale`, refusing with a message that names the plan and the limit — the shape `errNoPublicIngress` established for the sibling type refusal, not a bare 400.
2. Apply the same bound on the create path.
3. Apply it to autoscaling `minInstances`/`maxInstances`.
4. Implement t001's plan-downgrade answer (refuse, or clamp) in `SetPlan`.
5. Confirm the three surfaces all inherit the refusal — they share the verb, but confirm rather than assume, since create and autoscaling are separate entrypoints.
