## Objective

t004 found two ways round the send-only deny on production. A cron run's pods carried no `app.bex.co/workspace` label, so `deny-send-only-private-ingress` and `deny-free-plan-private-ingress`, which know a tenant source by that label, let a cron run reach a background worker and a free web service. And a served release's template restored over a canceled deploy is applied verbatim on every pass, so a record from before w6/m640 runs without the send-only label (a woken free web service did). Give cron run templates the workspace label, as Deployment templates have it, and give a restored template the network labels of the plan it runs.

## Context

- The cron template's labels are set beside `cronPodSpec`'s caller in `lego/operator/internal/controller/app_controller.go` (the App and environment labels only); manual runs take the CronJob's template.
- The restore paths: `applyServingDeployment` (`release_config_snapshot.go`) and the cron reconcile's `restore` branch. `recordServedTier` already reads the served plan from the restored template (`templateTier`).
- Nothing else selects pods by the workspace label: the egress meter attributes by App id, build Job counts select the build component, and the admission policies read the namespace's label.

## Acceptance criteria

- [x] A cron run's template carries the workspace label and the send-only label, also when restored over a canceled deploy.
- [x] A worker's template restored from a record without the send-only label regains it; a restored template follows the plan it runs, not the plan the canceled release saved.
- [x] Each test fails with its fix reverted.

**Done 2026-11-26:** the cron reconcile adds `app.bex.co/workspace` to the template labels, and both restore paths call `syncRestoredPolicyLabels` (the cron one also syncs the workspace label). Tests: `TestCronRunPodsCarryTheWorkspaceLabel`, `TestSyncRestoredPolicyLabelsFollowTheServedPlan` (`private_network_label_test.go`), and `send_only_restore_envtest_test.go` (a worker's and a cron job's restored template). Reverting the cron label fails the first, reverting the Deployment restore sync fails the worker spec, and reverting the cron restore sync fails the cron spec. Rollout: every cron job's CronJob template gains the label at the operator upgrade, and runs already in flight keep theirs; an App restoring a pre-label record rolls once, a hibernated one at its next wake.
