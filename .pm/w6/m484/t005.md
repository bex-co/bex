## Objective

Show on production that a deploy moving the operator image keeps an edge-cached service's pods and cache.

## Context

- Gate: a production pin whose producer contains this milestone's commit; the deploy after that one is the first that should keep the fixture (the shipping deploy itself moves the image once).
- Production access: `scripts/fetch-app-kubeconfig.sh` with `BEX_SSH_KNOWN_HOSTS_FILE` pointing at a temp file holding `* <key>` from `~/.ssh/bex_cp_host_ed25519.pub` (w3/m472). Signed-in API calls go through `bash scripts/qa-login.sh`.

## Steps

1. Record how many production Apps serve an edge cache (`spec.cacheProfile`), read-only.
2. Create a paid web service in `bex-canary` with edge caching on a static path; fetch the path until it answers as a cache hit.
3. Across the next deploy that moves the operator image, record the Deployment's ReplicaSet, the pod UIDs and the sidecar image; fetch the path again.
4. Delete the fixture by id (`GET` answers 404).
