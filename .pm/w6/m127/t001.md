## Objective

The create form forces `persistenceMode: "off"` for the free plan and tells the user it is because "The Free plan has no persistent disk". bex's free Key Value tier has a 1 GB disk, so the constraint is Render's and the explanation is false here. Remove the forcing, or keep a lock that rests on something true.

## Context

- `dashboard/src/routes/keyvalue.new.tsx:104-108` — the comment ("Render's exact behavior") and `const effectivePersistence = isFree ? "off" : persistenceMode;`
- `:122` sends `effectivePersistence` on create; `:200` and `:228` set `disabled={isFree}`; `:243` picks the free-specific hint.
- `dashboard/src/features/keyvalue/locales/en.ts:190` — "The Free plan has no persistent disk, so persistence is off." The zh locale carries the sibling string (`zh.ts` around `:190`).
- `lego/types/tiers/tiers.yaml` valkey free: `storageGB: 1`, with the catalog's own note that "Render's KV free tier is 25MB / no persistence; bex's is more generous at 128Mi".
- The REST path defaults a free store to `journal_snapshot` — measured live this run — so that is the incumbent answer for what a free store *should* be.
- **`maxmemoryPolicy` is locked by the same `isFree` flag** (`:200`) but is a different setting with a different rationale (eviction, not durability). Decide it on its own merits; do not sweep it along with persistence, and do not leave it locked by accident once `isFree` stops meaning what it meant.

## Steps

1. Decide the free plan's persistence default and whether the control stays locked. If it stays locked, lock it to a statement that is true of bex.
2. Remove or rewrite the forcing at `:108` so the form and the API agree.
3. Rewrite `keyvalue.fieldPersistenceFreeHint` in **en and zh**, following the repo's i18n rules (feature-prefixed keys, `description` fields for translators).
4. Re-decide the `maxmemoryPolicy` lock explicitly and record the reasoning in the code comment that currently cites "Render's exact behavior".
5. Update the comment at `:104-106` so the next reader does not re-derive the same false premise from Render's artifact.
