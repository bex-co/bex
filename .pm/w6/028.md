# 028 — Metrics page: "1 requests" + 10 unbatched Metrics queries per load (sub-hour)

Why: the Total Requests card says "1 requests" to every user whose service served exactly one request in the window — the same pluralization class `w9/m92` t006 fixed for "N turns" — and the same page fires ten separate `Metrics` GraphQL operations per load, which is the kind of self-inflicted request fan-out `w9/m92` t008 trimmed for the sessions poll.

From the live `/qa-find-bugs` hunt of `dashboard.bex.co`, 2026-08-22.

- **"1 requests"** — `/services/<id>/metrics`, Network Metrics → Total Requests summary. Reproduced on `srv-d9ndt8hmcglc739fkp50` with a 12-hour window. Needs the same singular/plural handling the rest of the dashboard uses (i18n plural forms, not a hand-rolled `+ "s"`). Owner file: `dashboard/src/features/metrics/components/network-metrics-card.tsx`.
- **10 `Metrics` operations per page load** — `application-metrics-card.tsx:61-76` issues seven (`cpu`, `memory`, `cpu_limit`, `memory_limit`, `cpu_target`, `memory_target`, `instance_count`) and `network-metrics-card.tsx:121-131` three more (`http_requests`, `http_latency`, `bandwidth`), each its own HTTP POST — Apollo is wired with a plain `HttpLink` (`dashboard/src/common/apollo/factory.client.ts:20`), no batching. Measured: 20 GraphQL requests for one Metrics page load, and each `useMetrics` re-polls every 30s (`use-metrics.ts:106`). GraphQL aliases or a batch link would collapse these into one round trip. Not a bug on its own — steady-state polling stays well under the 500/min `BEX_RATE_LIMIT` — so this is efficiency, not correctness.

Not filed as bugs from the same hunt (recorded so a later pass doesn't re-litigate them): the 429s seen mid-hunt were self-inflicted by the sweep's own navigation rate, not reachable by a real user's pace; `/services/<id>/headers` and `/redirects` redirecting to `/settings` is correct for a web service (those tabs are static-site surfaces); the `/notifications` switches all have proper accessible names via `label[for]` (an initial heuristic flagged them, the accessibility tree cleared them); and `api.bex.co` answering `403` to a `Python-urllib/*` User-Agent is Cloudflare bot protection — curl with a normal UA gets a proper `401`.
