# Decide: should Background Worker have a Free instance tier at all?

From the 2026-08-21 live bex-vs-Render Background Worker QA pass
(https://claude.ai/code/artifact/29934e6e-7bd8-4fa0-8a86-26327bb72932, finding
3). bex's `/services/new` instance-type picker offers **Free — 512 MB / 0.1
CPU** for Background Worker, pre-selected by default. Render's equivalent
picker has no free option for this service type at all — its cheapest tier is
Starter, $7/month.

This might be a deliberate bex differentiator, or an accidental gap nobody
decided on — worth a conscious call rather than either silently diverging
further or "fixing" it without checking it wasn't intentional.

Two data points to weigh:

- A Free-tier worker already can't use the dashboard Shell — that page reads
  "Shell access requires a running paid web, private, or background
  service," so a Free background worker's experience is already partial in
  practice.
- `docs/ADR030-pricing.md` documents a general "30%-off-Render" pricing
  policy, not "free where Render has no free tier" — this specific gap isn't
  recorded there or in `docs/ADR018-render-parity.md`'s Background Worker
  row.

If the decision is "keep the Free tier," record it explicitly in
ADR030/ADR018 so it reads as a decision, not drift. If the decision is
"remove it" or "cap what it can do," that becomes a small follow-up task in
whichever workstream is free next (pricing-picker default + instance-type
list live in `dashboard/src/features/services/`).
