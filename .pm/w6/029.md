# Danger Zone delete copy claims a URL for service types that never had one

Why: the delete-confirmation copy on the service Settings tab is user-facing and factually wrong for 3 of 5 service types, which erodes trust in a destructive-action dialog right when a user is deciding whether to proceed.

`services.dangerZoneDescription` (`dashboard/src/features/services/locales/en.ts:2473`) is a single hardcoded string — "Deleting a service permanently removes it, its deployment, and its URL. This can't be undone." — rendered unconditionally by `DeleteServiceCard` (`dashboard/src/features/services/components/delete-service-card.tsx:86`) for **all 5 service types**, via the one shared route `dashboard/src/routes/services.$serviceId.settings.tsx:384`.

Only `web_service` and `static_site` actually serve a public URL:

- `private_service` shows a Service Address / `internalAddress`, not a public URL — per `isPrivateService`'s own doc comment (`service-type.ts:92-95`).
- `background_worker` has "no public URL" — per `isWorker`'s own doc comment (`service-type.ts:77`).
- `cron_job` is schedule-only with no port — `servesHttp()` (`service-type.ts:110-112`) excludes both `worker` and `cron`.

So for private services, background workers, and cron jobs, this text falsely claims a URL is being deleted.

**Verified live** 2026-08-22 during a `/qa-find-bugs` hunt (dashboard.bex.co): created and deleted a `qa-20260822-` static site and a `qa-20260822-` cron job. The cron job's delete confirmation showed this exact "and its URL" copy despite the cron job never having had a URL (its own detail page shows Schedule / Next run, no URL field anywhere).

**Fix:** branch the final clause of `services.dangerZoneDescription` (or add a URL-aware variant) on a new predicate in `service-type.ts`, following the pattern already established by `isCron` / `isWorker` / `isPrivateService` / `servesHttp`, so non-URL types get accurate copy. Note that `serviceSudoPhrase` (same file) already gets per-type naming right in the confirmation phrase itself ("sudo delete cron job \<name\>") — only this danger-zone description lags behind.

**Blast radius:** one component, one call site, one locale key — low risk, single-file-ish change.

**Dedupe:** no `.pm` hit for this specific "its URL" / "no public URL" copy mismatch in `w5/m14` (`DeleteServiceCard`'s origin milestone) or `w6/m3` (Danger Zone standardization). Not listed in `.pm/DO_NOT_DO.md`.

Estimate: ~20-30 min (locale string branch + `service-type.ts` predicate + `delete-service-card.test.tsx` coverage for a non-URL type).
