## Objective

Establish Render's observable behavior before bex deletes any customer datastore. render.com/docs/projects says "Deleting a project deletes all of its associated environments and services. Deleting an environment deletes all of its associated services" but the same page lists resources as "services, environment groups, etc.", so whether datastores and env groups are deleted, detached or kept is not stated.

## Context

- Render docs: https://render.com/docs/projects (Important callout; protected environments section)
- bex today detaches: `lego/backend/internal/environments/service.go:947-996` (services deleted since w4/done/m264, datastores/env groups detached at :950-952), `lego/backend/internal/projects/service.go:583`
- Render credentials, if any, come from `.env` (never print them); if no Render account is usable, record that and use the Render public API reference + dashboard confirmation text as the best available evidence

## Steps

1. Create project P → environment E containing a free Postgres, a free Key Value, an env group and a free web service (API or dashboard).
2. Delete E; poll `GET /v1/postgres`, `/v1/key-value`, `/v1/env-groups`, `/v1/services` and record each resource's final state (deleted / still present, environmentId).
3. Repeat with a project delete (P2 with one env containing the same resource kinds).
4. Record the dashboard's confirmation wording for both deletes.
5. Write the evidence (text only, no screenshots in git — DO_NOT_DO #NO-ARTIFACTS-IN-GIT) into this milestone README under `## Render evidence`; clean up the Render resources.
