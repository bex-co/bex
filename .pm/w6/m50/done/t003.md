## Objective

Make an `Error` row in the Blueprint detail page's Sync History table
actually show why, instead of only `Commit / State / Started / Completed`
with no explanation anywhere in the UI or on click.

## Context

- `dashboard/src/routes/blueprints.$blueprintId.tsx:424-430` — the Sync
  History table's column headers (`syncColCommit`, `syncColState`,
  `syncColStarted`, `syncColCompleted`) — no error/reason column exists.
- Live repro on `blp-d9nqg95cavls73fp8m10` (`discourse_docker`): 9 rows show
  `state: "error"` with zero detail anywhere; clicking a row does nothing (no
  navigation, no modal — confirmed via Playwright, `page.url()` unchanged
  after a row click).
- `dashboard/src/features/blueprints/hooks/use-blueprint-syncs.ts` and
  `dashboard/src/features/blueprints/lib/views.ts` are the data-fetching/view
  layer this route consumes — t002's regenerated field needs to flow through
  both.

## Steps

1. Add a column (or an expandable/tooltip detail, if a full column is too
   wide for long messages — match this table's existing density) showing the
   error message for `state === "error"` rows, empty/dash for others.
2. Add the locale key(s) in `dashboard/src/features/blueprints/locales/en.ts`
   (+ `zh.ts` per this repo's i18n convention — every user-visible string
   goes through `t()`).
3. Verify live against `blp-d9nqg95cavls73fp8m10` once t001+t002 are merged
   and a new failing sync has occurred (or backfill/re-trigger one
   deliberately in a test environment — do not manufacture a failure against
   this specific production blueprint without separate authorization).
