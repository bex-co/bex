## Objective

Expose the newly-persisted `error_message` on every surface that already
reads blueprint sync history, so it isn't a store-only field nobody can see.

## Context

- The dashboard's live query for this data,
  `BlueprintSyncs` (`query BlueprintSyncs($id: String!, $ownerId: String,
  $cursor: String, $limit: Int) { blueprintSyncs(...) { id commitId state
  startedAt completedAt } }`), is defined in the dashboard's GraphQL
  operations and only asks for these five fields — captured live from the
  actual network request the Blueprint detail page makes.
- `lego/backend/internal/apps/graphql.go` — find the `blueprintSyncs`
  resolver/type (search for `BlueprintSync` — same name used at
  `graphql.go:1629` for the `SyncBlueprint` mutation) and add the new field
  there, mirroring however `state`/`commitId` are already resolved.
- REST and MCP surfaces for blueprint syncs also need the field — grep
  `lego/backend/internal/apps/rest.go` and `lego/backend/internal/apps/mcp.go`
  for the blueprint-sync list/get handlers (same pattern as
  `SyncBlueprint`'s three call sites found in t001's research: `rest.go:1237`,
  `mcp.go:1022`, `graphql.go:1629` — the read-path handlers sit near these).
- `ListBlueprintSyncs` in `lego/backend/internal/apps/blueprint.go:~704` is
  the service-layer read this data flows through — check its return type
  (`[]BlueprintSyncView`) picks up the new store field.

## Steps

1. Add the error field to whatever view/DTO type `ListBlueprintSyncs` returns
   (`BlueprintSyncView` or equivalent).
2. Wire it into the GraphQL type + resolver for blueprint syncs.
3. Wire it into the REST JSON response for the equivalent endpoint.
4. Wire it into the MCP tool response for the equivalent tool, if one exists
   for reading sync history (check `mcp.go` for a blueprint-sync-history
   tool; if none exists, note that in the render-parity task rather than
   inventing new MCP surface here).
5. Regenerate the dashboard's GraphQL codegen types
   (`dashboard/CLAUDE.md`'s offline-codegen recipe) so t003 has a typed field
   to consume — don't hand-edit `definitions.ts`.
