# Settings-page field edits swallow the backend's specific validation error behind a generic toast

Why: a user who mistypes a Settings field (e.g. a Health Check Path missing its leading `/`) gets "Couldn't update the health check path." instead of the backend's actual, actionable reason — they have no way to know what to fix.

`useFieldMutation` (`dashboard/src/features/services/hooks/use-field-mutation.ts:38-40`) — the shared body for every single-field Settings mutation on a service — has a bare `catch { toast.error(t(keys.error)) }` that discards whatever the server actually said and always shows the hook's one fixed generic message.

**Live-confirmed:** setting Health Check Path to `no-leading-slash` via the dashboard (`srv-da5uhsgbjjms73fvfrpg`, 2026-08-24 QA workspace) returns a real backend validation message over GraphQL:

```
mutation { setHealthCheckPath(id: "srv-da5uhsgbjjms73fvfrpg", path: "no-leading-slash") { id } }

{
  "data": { "setHealthCheckPath": null },
  "errors": [{ "message": "bad request: health check path must start with /", "path": ["setHealthCheckPath"] }]
}
```

— but the UI toast reads only "Couldn't update the health check path."

**Blast radius (confirmed by code, one shared helper):** 14 hooks share this exact shape via `useFieldMutation`: `use-branch.ts`, `use-build-command.ts`, `use-build-filter.ts`, `use-dockerfile-path.ts`, `use-health-check-path.ts`, `use-idle-timeout.ts`, `use-max-shutdown-delay.ts`, `use-pre-deploy-command.ts`, `use-root-dir.ts`, `use-service-notifications.ts`, `use-set-image.ts`, `use-set-repo.ts`, `use-start-command.ts`, `use-subdomain-policy.ts`.

**Distinct from `w6/m49`:** that milestone's bare `catch {}` shapes are on separate resource-_creation_ hooks (Key Value/Postgres/Project/Environment/API-key/registry-credential) — not this one shared Settings-field-edit helper. No file overlap.

**Fix direction:** extract the GraphQL error and toast it, falling back to the generic message only when the error is unreadable — the same pattern already used elsewhere in this codebase for surfacing a specific server message. One change in `use-field-mutation.ts` fixes all 14 callers at once.
