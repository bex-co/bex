# 051 — Deploy rows label every deploy's creation time as "Deployed {timestamp}", including Canceled and Build Failed ones

Why: the Deploys tab tells the user a deploy that never shipped was "Deployed", and even for a successful one the timestamp it shows is when the row opened, not when the release went live.

## What's wrong

`dashboard/src/features/deploys/components/deploys-list-page.tsx:174-175` formats `d.createdAt`, and line 216 renders it under an unconditional label:

```tsx
const createdAt = hydrated ? formatDeployTimestamp(d.createdAt) : null;
…
{t("deploys.deployedAt", { timestamp: createdAt })}
```

`deploys.deployedAt` is `"Deployed {timestamp}"` (`dashboard/src/features/deploys/locales/en.ts:90-91`; zh: `"部署于 {timestamp}"`, `locales/zh.ts:90-91`). Nothing gates it on status, and the string's own `description` field already admits the conflation: `"Deploy row: created/deployed timestamp"`.

## Live repro (2026-08-27)

`https://dashboard.bex.co/services/srv-d9bkcspg9s7c73d0n8ug/deploys` — `agentmarketcap-1`:

- `dep-d9ru9s85rbhs73ch0ll0` — status badge **Build Failed**, subtitle "Deployed August 8, 2026 at 7:24 PM"
- `dep-d9ru61ileubs73da8jqg` — status badge **Canceled**, subtitle "Deployed August 8, 2026 at 7:16 PM"

Fourteen more Canceled rows on the same page read the same way.

## Fix sketch

Pick the label from the deploy's terminal state rather than using one string for all of them — created / queued / canceled / failed / deployed each want their own verb, and the timestamp for a live deploy should be its finish time, not `createdAt`. Both `en` and `zh` catalogs move together. Check the deploy **detail** page for the same conflation before fixing only the list — not verified this run.
