# 021 — `usage_threshold` is an advertised delivery event whose producer was retired

Filed by `/pm-brainstorm for w6` 2026-08-17 (second round). Sub-hour; API-surface honesty, not a user-visible dead control.

`USAGE_THRESHOLD` is advertised on the notification delivery-event enum but **nothing can ever emit it**:

- `lego/backend/internal/notifications/delivery_policy.go:71` — `DeliveryEventUsageThreshold DeliveryEvent = "usage_threshold"`
- `lego/backend/internal/notifications/graphql.go:52` — exposed on the GraphQL enum
- flows into `dashboard/src/graphql/definitions.ts:2067` and `mobile/src/generated-graphql/index.ts:26` as generated types

Its producer was `w8/001` (Hobby-plan usage caps + approaching/exceeded notifications), **retired without implementation 2026-08-16** — see `.pm/w8/done/001.md` § "Final triage". The evidence gate failed after the full waiting period: 2 of 17 workspaces had any `build_seconds` rows, the 28-day build window totalled exactly 0 minutes, and the single represented bandwidth workspace totalled ~1,457 GiB against Render's 5 GiB anchor. It is closed, not pending.

`docs/ADR052-notifications.md` D5 is "Honest disabled states, everywhere", and its § Consequences item 4 still describes this as "policy-selectable but no producer emits it (the w8/001 producer is the referenced owner)" — that pointer is now stale, since the owner was retired.

**Do:** either drop the enum value (regenerating the dashboard/mobile types) or keep it and document it as knowingly inert, then correct ADR052 § Consequences item 4 to say the producer was retired rather than pending.

**Narrower than it first looks:** no dashboard picker and no `push_notifications` DB CHECK reference it, so there is no dead user-facing checkbox and no migration needed — unlike the five-mirror closed set ADR052 § Consequences item 1 describes.

**Do NOT** re-open Hobby cap enforcement as part of this. `w8/001`'s own retirement text forbids carrying that cap design forward and requires a fresh proposal only "when broad tenant coverage and non-zero build activity exist" — neither holds today.
