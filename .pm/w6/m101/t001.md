## Objective

Give the control-plane Postgres `apps` table a queryable copy of the App CR's `spec.displayName`, so store-side queries (like the webhook feed) can resolve the current human-facing label without a per-row k8s read.

## Context

- `lego/backend/internal/apps/service.go:3588-3598` — `SetDisplayName` patches only `a.Spec.DisplayName` via `s.patch(ctx, core.RelCanOperate, name, ...)`; its own comment states "displayName is not owned by the control-plane row projector."
- `lego/backend/internal/apps/service.go:3676-3693` — `patchFetched`/`patchTracked` already funnel every mutation through `s.rollouts(trigger).Patch(ctx, s.Client, a, ...)`; the `Service` struct already holds `Store` (used by `rollouts`), so a synchronous store write from the same verb is architecturally cheap — no new composition root or separate reconciler pass needed.
- `lego/backend/internal/store/store.go:1589-1699` — the existing `UPDATE apps SET <col> = $2, updated_at = now() WHERE id = $1` family (`suspended`, `tier`, `replicas`, `idle_ttl_seconds`, …) is the precedent to follow for a new `display_name` column + setter.
- No `display_name` column exists today — confirmed via `grep -rn "display_name" lego/backend/internal/store/*.go` (zero hits outside this task's own future migration).

## Steps

1. Add a `display_name TEXT NOT NULL DEFAULT ''` column to the `apps` table via a new numbered migration (follow the existing migration-file convention in `lego/backend/internal/store/`).
2. Add a store method (e.g. `SetAppDisplayName(ctx, appID, displayName string) error`) mirroring `store.go`'s existing single-column setters.
3. Call it from `apps.Service.SetDisplayName` immediately after (or alongside) the existing CR patch, so the store row and the CR agree without waiting on the reconciler's resync loop. Keep the CR as the authoritative value the operator/dashboard direct-reads use — this is a read-projection mirror, not a new source of truth.
4. Handle the store-unavailable case (`s.Store == nil`, CR-only mode) the same way every other store-optional verb in this file does — the CR patch must still succeed.

## Files

- `lego/backend/internal/store/` (new migration + setter)
- `lego/backend/internal/apps/service.go` (`SetDisplayName`)

## Acceptance criteria

- [ ] `apps.display_name` exists and is populated for a renamed service without requiring a manual backfill for existing rows to start working going forward (empty default is fine — `COALESCE(NULLIF(display_name,''), name)` at read time, per t002, handles the empty case).
- [ ] Calling `SetDisplayName` with `BEX_CP_DB_URI` unset still succeeds (store write is best-effort/skipped, not a hard dependency).
- [ ] A direct Postgres query (`SELECT display_name FROM apps WHERE id = $1`) reflects the new label immediately after `SetDisplayName` returns — no reconciler resync delay.

## Out of scope

- Backfilling historical `display_name` for services renamed before this migration ships (their webhook payloads keep showing the old name until they're renamed again, or a one-time backfill script is run separately — not required for this milestone's DoD).
