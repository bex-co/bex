## Objective

Lock in the fix with a test that fails on the old behavior: a service with `display_name` set to something other than `name` must produce webhook events whose `ServiceName` is the display label.

## Context

- `lego/backend/internal/store/webhooks_test.go` (or the sibling test file for `webhookEventsQuery`) — existing fixtures already set both `ServiceID`/`ServiceName` in test rows (see `lego/backend/internal/webhooks/worker_test.go:454-653` for the shape convention used across the package).
- `lego/backend/internal/webhooks/worker_test.go:687` shows the exact wire-body shape the delivered payload must match: `{"type":"...","timestamp":"...","data":{"id":"...","serviceId":"...","serviceName":"..."}}`.

## Steps

1. Add a store-level test (real or fake Postgres per the existing package convention) that creates an app with `name = "orig-name"` and `display_name = "renamed-label"`, then asserts `ListWebhookEvents` returns rows with `ServiceName == "renamed-label"` for each of the 4 fixed arms (deploy started/ended, app-scoped audit, a fact row).
2. Add/extend a `worker_test.go` case asserting the end-to-end dispatched payload's `data.serviceName` matches the display label, not the immutable name.
3. Add a case where `display_name` is empty — assert the fallback to `name` still works (no regression for never-renamed services).
