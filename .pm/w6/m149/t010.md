## Objective

Execute DoD 2–6 on production in a workspace that was never on the allowlist, with the unchanged upstream sources. Record raw requests and responses.

## Context

- Unchanged Blueprint `render-examples/clickhouse@355817b1d95c1a9f2b088474437593234f4027f4`. The byte-identical fixture is `lego/backend/internal/apps/testdata/render-clickhouse/`.
- w6/m148/t007 proves the multi-port network half. This task needs both milestones' code deployed.
- QA credentials: `QA_EMAIL`/`QA_PASSWORD` from `.env` or `muse.env`. Revoke the QA session at the end.

## Steps

1. **ClickHouse.** Validate, plan and apply the unchanged Blueprint, then:
   - reach Live;
   - from a same-workspace peer, get `Ok.` from `:8123/ping` and `SELECT 1` over `:9000`;
   - insert a sentinel row, Restart, read it back, Manual Deploy, and read it back again.
2. **Pod values.** Read inside the pod through exec (`bex ssh` or `kubectl exec`, read-only):
   - `/proc/1/status` `CapBnd`/`NoNewPrivs`/`Seccomp`;
   - `/proc/1/uid_map`.

   Compare them with ADR089.
3. **nginx.** Create the unchanged official `nginx` image as a web service on the t006 port (80 if allowed), then check `curl -sSI https://<slug>.onbex.co/` returns 200.
4. **Isolation.** From the new-policy pod, probe:
   - another workspace's pod and Postgres;
   - the node kubelet `:10250`;
   - `169.254.169.254`;
   - a platform service.

   Each must be denied. Check that the ClickHouse service has no public Ingress.
5. **Legacy.** Using a pre-upgrade `strict-v1` fixture, or a read-only existing App:
   - confirm the pod template and ReplicaSet hash are unchanged;
   - run the t008 migration on a QA-owned `strict-v1` service: dry run, then real run, then Live.
6. Record everything in `docs/render-artifacts/container-privileges.md`. Delete every fixture by exact ID and revoke the QA session.
