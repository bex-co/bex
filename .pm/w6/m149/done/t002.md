## Objective

Before the ADR adopts pod user namespaces (`hostUsers: false`) as the confinement that offsets the wider capability set, prove they work for a long-running service pod with a persistent disk, a root-init image, and every sidecar path the runtime uses.

## Context

- Build, publish and pre-deploy pods already run with `hostUsers: false` (`lego/operator/internal/execution/security.go:96-98`). Runtime Deployments and CronJobs do not.
- Tenant kubelets have `UserNamespacesSupport=true` (`infra/clusterapi/overlays/hetzner-caph/cluster.yaml:105`) and run containerd v2.3.3 (`:135`).
- Disks are LUKS `hcloud-volumes` PVCs (ADR082). The local CAPD cluster has no Hetzner CSI, so this spike proves the mechanism on local storage. t009 proves it on Hetzner.
- Local clusters and `dev-6` are pre-approved (root `AGENTS.md`). Production is not.

## Steps

1. On the local cluster, apply the generated runtime objects for a disk-backed service. Patch the pod template by hand to add `hostUsers: false` and Render's measured capability set (`CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETUID, SYS_CHROOT`; see `docs/render-artifacts/container-privileges.md`). Use unchanged `yandex/clickhouse-server:21`. On an arm64 host it may need emulation; if it cannot run, use `postgres:17`, whose entrypoint chowns and uses `gosu` in the same way.
2. Verify the following:
   - the first start succeeds on a fresh volume;
   - the pod restarts against an already-owned volume;
   - ownership as seen from the host (`stat` on the node mount) is the in-container UID, not a shifted one;
   - a volume written **without** a user namespace (simulating an existing service) is readable and writable after switching. This settles whether migration (t008) needs a chown step.
3. Exercise the rest:
   - `/etc/secrets` secret files and environment;
   - `emptyDir`;
   - SIGTERM shutdown;
   - exec as used by the SSH gateway;
   - the disk snapshot and restore Jobs (`disk_backup.go`) against the same PVC.
4. Record a go or no-go per path, with the exact failure output, in the evidence artifact (`docs/render-artifacts/container-privileges.md` § bex user namespaces).

## Closure — 2026-10-20

Results are in `docs/render-artifacts/container-privileges.md` § bex user namespaces.

- **ext4: go on every path.** A pre-existing non-userns disk works after switching, with no chown step.
- **Local overlayfs `local-path`: no-go.** runc fails with `MOUNT_ATTR_IDMAP … invalid argument` because that filesystem cannot be idmapped.
- **t009 must check `hcloud-volumes` idmap support** before projecting `hostUsers: false`.
