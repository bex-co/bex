## Objective

Turn the user's 2026-10-17 decision ("Render parity outranks the earlier security hardening") into the governing contract **before** any code changes. That means accepting ADR089 with D2 amended and rewriting the ADR022 sections it supersedes.

## Context

- ADR089 is **Proposed**. Its D2 allows only `CHOWN, DAC_OVERRIDE, SETUID, SETGID`. Its "Alternatives considered" section rejects "restore every Docker capability globally", and it says "do not silently widen the allowlist".
- ADR022 "Tenant container hardening" says "all Linux capabilities dropped … Deliberate posture (kept over Render parity)".
- ADR070 `:159` and ADR004 repeat the drop-ALL and no-low-ports claims.
- Evidence: t001 (Render and bex profiles), t002 (user-namespace go/no-go).

## Re-scope — 2026-10-20

Under Render parity first, the seccomp answer is **RuntimeDefault**. Record it as a named divergence, with relaxation tracked by w6/085; do not ask the user again.

- `hostUsers` is not adopted for `render-v1`. Record the t002 result and point to w6/086.
- The criterion "the seccomp choice records the user's answer" is satisfied by this re-scope.

## Steps

1. **Parity criterion.** Adopt "every image that starts on Render starts on bex unchanged", unless t001 evidence argues for a narrower criterion. State it in ADR089.
2. **Capability set.** Use Render's measured set: `CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETUID, SYS_CHROOT`. This is `image-v1` plus `FOWNER` and `SYS_CHROOT` (live probe of 2026-10-17, `docs/render-artifacts/container-privileges.md`).
   - Do not add Docker-default capabilities that Render lacks (`NET_BIND_SERVICE`, `KILL`, `SETPCAP`, `SETFCAP`, `FSETID`, `MKNOD`, `AUDIT_WRITE`, `NET_RAW`). Record each as matching Render.
3. **Seccomp: needs a user decision.** Render runs with **no** seccomp filter, so `io_uring` and `unshare(CLONE_NEWUSER)` work there (used by the Chromium sandbox, bubblewrap and io_uring-based servers). bex's RuntimeDefault blocks both.
   - Options:
     - keep RuntimeDefault and name the divergence;
     - a Localhost profile, which is RuntimeDefault plus the `io_uring` syscalls and `unshare(CLONE_NEWUSER)`;
     - `Unconfined`.

     PSS baseline forbids an explicit `Unconfined`, so that option would also need a namespace policy change.
   - Ask the user. Do not choose for them: unprivileged user namespaces combined with no syscall filter is a common kernel-exploit entry point on shared nodes. If the user picks anything but RuntimeDefault, file it as its own milestone with a security review.
4. **Confinement.** Render uses no pod user namespace, so `hostUsers: false` is bex-only defense in depth. It is not parity. Adopt it on each path t002 marked go, unless t002 shows it breaks a Render-runnable image (for example, `chown` to a uid outside the mapped range).
   - For each no-go path (for example, disk-backed services), record the residual explicitly.
   - Per the user decision, a no-go narrows the mitigation; it does not block the capability change.
5. **Remaining knobs** (from the live probe):
   - `allowPrivilegeEscalation: false` stays; it matches Render's measured `NoNewPrivs=1`.
   - Low ports: Render measured `ip_unprivileged_port_start=0`, so ports below 1024 must be bindable on bex too. If t001's bex measurement is `0`, pin `enable_unprivileged_ports = true` explicitly in node bootstrap so a containerd default change cannot regress it. Otherwise choose that pin or a per-pod safe sysctl. t006 implements the decision.
6. **Policy identity and scope.**
   - Name the new versioned policy; working name `render-v1`.
   - Scope is the same as today's predicate: new Docker/image/Dockerfile services, not static sites and not native runtimes.
   - New services only. `strict-v1` and `image-v1` rows never change on upgrade.
   - Migration is an explicit operator-run operation (t008). Specify its unit (one service id), dry run, and refusal states.
7. **Rollout and rollback.** The creation default moves to every workspace in t009, after the `bex` canary. Rollback reverts the creation default only; it never migrates services already created.
8. **Write it down.**
   - ADR089: status Accepted, D2 rewritten, Alternatives entry updated, the checkpoint amended, and the decision date and user decision cited.
   - ADR022: rewrite the hardening section to cover both contracts and remove "kept over Render parity".
   - ADR004 and ADR070: correct the low-port and drop-ALL claims.
   - ADR018 `:79`: a short note pointing to t011.
   - `docs/AGENTS.md`: the ADR089 one-liner is no longer "proposed".
   - Rewrite t004–t008 steps if a decision differs from them.
