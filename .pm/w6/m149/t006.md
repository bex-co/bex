## Objective

bex stops refusing, or misdiagnosing, a port that the node would let the container bind. A Render user's image that listens on 80 works whenever it would work on Render.

## Context

- `minTenantPort = 1024` and its refusal (`lego/backend/internal/apps/service.go:4569,4585`). The doc comment justifies it with ADR022's drop-ALL claim.
- Crash diagnosis: "tenant containers cannot bind ports below 1024 (all Linux capabilities are dropped)" (`lego/operator/internal/controller/app_controller.go:5134`).
- The w6/m148 image-port primary floor `primary < 1024` (`image_network.go:78`, and m148 t001's `≥ 1024` rule).
- **Measured 2026-10-19 (t001):** production tenant pods read `ip_unprivileged_port_start=0` (the containerd v2.3.3 default), and a `strict-v1` root process binds `:80`. Render reads `0` too. Step 1 applies.
- This run's deploy events carried the false diagnosis verbatim: `stallReason` "…tenant containers cannot bind ports below 1024 (all Linux capabilities are dropped)."

## Steps

1. **t001 measured `0` (this path).**
   - Remove the `< 1024` floor for every policy, because the node already allows the bind.
   - Keep the reserved-port and range checks.
   - Pin `enable_unprivileged_ports = true` in both tenant `KubeadmConfigTemplate`s in `infra/clusterapi/overlays/hetzner-caph/cluster.yaml`, and add a guard in `scripts/clusterapi-validate.sh` that fails if the pin is missing.
   - Update the diagnosis text.
2. **Fallback, not taken unless a node pool reads otherwise.** Implement t003's choice: the node pin, or a per-pod `securityContext.sysctls` for the new policy, which PSS baseline admits as a safe sysctl. Relax the floor only for services that actually get it.
3. Coordinate with w6/m148. If its primary floor shipped, relax it in the same change. If not, update m148 t001/t003 so they never introduce it.
