## Objective

The hourly rollup already resolves each service's Traefik router names and app id; persist the last ones it used, so a deleted service's egress can still be read.

## Context

- `usage.queryEgressBytesEvidence` needs the App CR for `TraefikRouterNames`; the CR and its Ingress go with the deletion
- `store.RetiredUsageResource` keeps name, tier and times only
- `egressquery.App(appID, routers, direct)`

## Steps

1. Store the routers and the `direct` flag each successful hour (a small table, or the retired-resource record at deletion).
2. Read them back for a retired service.

- lego/backend/internal/store/
- lego/backend/internal/store/migrations/

## Acceptance criteria

- [x] A retired service's egress identity is readable after its CR is gone

## Done 2026-11-12

- Migration `0233_usage_retired_egress_identity` adds `usage_egress_identities` (`service_id`, `routers`, `direct`). These are observed cluster state, so they live beside the `apps` row, not on it.
- `store.RecordAppEgressIdentity` upserts the identity and writes nothing when it is unchanged. `ListRetiredUsageResources` LEFT JOINs it into `RetiredUsageResource.Egress`, which is nil when never resolved. `PruneRetiredUsageResources` removes an identity once its App is neither live nor retired.
- Test: the PG `TestRetiredAppCarriesItsEgressIdentityPG` covers carry, never-resolved, known-empty, no rewrite of an unchanged identity, and prune.
