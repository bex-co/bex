## Objective

Prove in envtest and unit tests that the projected strategy keeps every old replica through a rollout, and that writing it rolls nothing.

## Context

- Existing projection and rollout tests: `lego/operator/internal/controller/deployment_projection_test.go`, `first_deploy_rollout_envtest_test.go`, `failed_rollout_phase_test.go`, `disk_rollout_test.go`.
- envtest runs no kube-controller-manager, so a rollout is asserted on the projected Deployment spec (strategy, `pod-template-hash`), not by watching pods.
- `app_types.go:792`: replicas maximum 100.

## Steps

1. Unit-test the projection for 1, 3, 4 and 100 replicas, with and without a disk, held and unheld.
2. envtest: an existing Deployment carrying the API-server default `25%`/`25%` reconciles to the new strategy with an unchanged template hash.
3. envtest: a code deploy, a restart (`spec.restartedAt`) and a release that fails its health check each project a template change under `maxUnavailable: 0`.

## Files

- lego/operator/internal/controller/deployment_projection_test.go
- lego/operator/internal/controller/ (a new or existing envtest file for the strategy rewrite)
