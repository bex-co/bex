# A disk service that probes by exec still waits up to 1 s for the kubelet's relist after its health-probe installer exits

Why: under `Recreate` every second before the new instance is Ready is downtime, and with the installer's CPU fixed (w6/170) the only term left between a service that probes by exec and a named-port twin is the kubelet's 1 s relist, which put the windows of half the measured runs 1.0–1.5 s above the twin's.

- **Found by:** w6/170's production measure, pin `ff5de0a130e6`, 2026-11-24, on the disk-bearing Starter image service `w6-170` (disposable) in `bex-canary`, on `bex-tenant-0-zdp6v-swgkf`, beside its own named-port configuration on the same node ([w6/170](done/170.md)).
- **What was measured.** The `bex-health-probe-install` init container now starts in 0.10–0.15 s and runs 0.01–0.03 s. From its exit to the app image's `PullImage`, the kubelet took 0.08–0.17 s in five runs and 0.97–1.04 s in six. With the long wait, the app ran 2.55–2.64 s after its pod reached the node and the windows were 4.99–5.50 s. With the short wait, it ran in 1.67–1.80 s and the windows were 4.25–4.75 s. The named-port twin, with no init container, ran in 1.35–1.52 s and its windows were 3.99–4.25 s.
- **Mechanism.** The kubelet's generic PLEG relists the node's containers every second. It notices the installer's exit on its next relist, and that pass starts the app. No pod field shortens the wait, and only a pod with no init container avoids it (w6/170's 2026-11-23 record).
- **Who pays:** every pod that carries the helper (`usesHealthProbeBinary`, `lego/operator/internal/controller/deployment_projection.go`). That means a service with a Health Check Path, or a code deploy of a web image service that names no port. Under `Recreate` the wait is downtime. A rolling service pays it only as a slower rollout.
- **Directions to weigh.**
  - Mount the helper from bex's image with an `image` volume (KEP-4639) instead of copying it in an init container. `ImageVolume` is off on production's Kubernetes v1.34.9, so this needs the feature gate on the API servers and kubelets ([w6/m595](done/m595/README.md) rejected it for the pre-pull for the same reason).
  - Turn on the kubelet's `EventedPLEG`, which reports the exit at once. It is beta and off by default.
  - Any other design that puts the binary in the app container without an init container.
  - Check each option's cost before choosing: the cluster roll it needs, the containerd version it needs (2.3.3 runs there now), and its effect on every other pod on the node.
- **Done when:** on production, code deploys and restarts of a disk-bearing Starter web image service in `bex-canary` with a Health Check Path, and with no `PORT`, each have a window within 0.5 s of a named-port twin's on the same node, measured as in w6/170. Otherwise ADR082 records the wait as the bound for a service that probes by exec.
