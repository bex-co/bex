## Objective

Add the payment-method marker check at agent-session create/steer **admission**, so a cardless caller gets the synchronous, interceptable 402 instead of an admitted session that dies asynchronously in background dispatch.

## Context

- Today admission runs only the dunning gate (`RequireBillingMutation`, `lego/backend/internal/agentsessions/service.go:388` and the steer/resume sites at :933/:1317/:1447); the card check fires later inside `runDispatch` → `CreateAgentSessionSandbox` → `createResolved` (`lego/backend/internal/sandbox/service.go:356`), which surfaces as "sandbox create failed" with no 402 for the dashboard's interception dialog (ADR075 D7 scope correction 1).
- Every sandbox shape is metered, so every agent-session dispatch is paid intent (ADR046 Consequences) — the admission check applies in **both** `1` and `all` modes, mirroring the sandbox feature's unconditional `RequirePaymentMethod`.
- The dispatch-time check in `createResolved` stays — defense in depth for the async path.

## Steps

1. Add `RequirePaymentMethod` beside each `RequireBillingMutation` at the agent-session admission sites (create, steer, resume paths that provision compute).
2. Confirm the coded 402 crosses all three surfaces with the same shape as the other gated verbs.
3. Regression test: unbound workspace → agent-session create refused 402 synchronously; bound workspace → admitted (fake lifecycle).
