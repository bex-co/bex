## Objective

Enable both gates on production in the recorded order, with no surprise refusals for existing first-party workspaces and the D8 hybrid flow (signed-in verification, login backstop) verified live.

## Context

- ADR075 D7 scope correction 2: flipping `all` turns every unbound workspace refused-on-next-create; the ~17 first-party workspaces must be comped (Mode-B — `PaymentGate.AllowsPaidIntent` already honors the exemption) or card-bound **before** the flip.
- ADR075 D8 as revised 2026-08-20 (hybrid): NO session revocation at enablement — an unverified session is the normal in-flow signup state now; the login backstop (`require_verified_address`) refuses stale unverified accounts at their next login, which is the whole enforcement.
- Production config paths: `.env` → `scripts/gh-secrets.sh` for `BEX_REQUIRE_PAYMENT_METHOD`; `scripts/auth-secrets.sh` re-run + Argo sync for the Kratos Secret fragment; kratos.values.yaml ships via GitOps.

## Steps

1. Inventory production workspaces' payment eligibility (bound / comped / neither); comp or bind the remainder; record the list.
2. Apply the D8 hybrid Kratos config to production (values sync + `auth-secrets.sh` re-run — both registration hooks AND both login backstop hooks).
3. Flip `BEX_REQUIRE_PAYMENT_METHOD=all`; verify live: an unbound test workspace's free-tier create 402s and the dashboard dialog resolves it; a comped workspace creates normally; a fresh signup lands on the verification page SIGNED IN and continues seamlessly after the code; a stale unverified identity's new login is refused into verification (backstop).
4. Record rollback: `all`→`1` is one env flip; the Kratos hooks revert by restoring the two config blocks (both documented in the milestone README's evidence).

## Files
