## Objective

`PostgresView.IPAllowList` (`lego/backend/internal/postgres/service.go:124`) and `PostgresView.ReadReplicas` (`service.go:107`) both carry `json:"...,omitempty"` even though Render's pinned OpenAPI schema marks both `required` on the `postgres` object. When either slice is nil (the common case: no CIDR allowlist, no read replicas), the JSON key is dropped entirely instead of serializing as `[]`. Fix both fields so the key is always present, matching GraphQL (which already returns `[]` for both) and the fix pattern already shipped for the identical field on `Environment`.

## Context

- `lego/backend/internal/postgres/service.go:107` — `ReadReplicas []ReadReplicaView \`json:"readReplicas,omitempty"\``
- `lego/backend/internal/postgres/service.go:124` — `IPAllowList []core.IPAllowListEntry \`json:"ipAllowList,omitempty"\``
- `PostgresView` is embedded directly into REST's `renderPostgres` (`postgres/rest.go:38-41`) and returned directly by 8 MCP tool handlers in `postgres/mcp.go` (`get_postgres`, `list_postgres_instances` via `listPostgresResult{Postgres []PostgresView}`, `create_postgres`, `suspend_postgres`, the two verbs at L222/L229, `recover_postgres`, `update_postgres`) — fixing this one struct covers every one of those call sites.
- Reference fix pattern already shipped in this codebase for the same field name on a sibling resource: `lego/backend/internal/environments/rest.go:72` (`json:"ipAllowList"`, no omitempty) + `toRenderEnvironment` at `rest.go:80-84` (`allowList := e.IPAllowList; if allowList == nil { allowList = []core.IPAllowListEntry{} }`).
- Live-verified bug (2026-08-26 hunt): `GET https://api.bex.co/v1/postgres/dpg-d9nqg95cavls73fp8m20` has neither key; `tools/call get_postgres {postgresId:"dpg-d9nqg95cavls73fp8m20"}` has neither key; GraphQL `database(id:...){ ipAllowListEntries{cidrBlock} readReplicas{name} }` returns `[]`/`[]` correctly for the same resource.

## Steps

1. Remove `,omitempty` from both `service.go:107` and `service.go:124`'s json tags.
2. Find (or add) the single point where a `PostgresView` is constructed for an external response (the function(s) that populate `IPAllowList`/`ReadReplicas` from the underlying App/Database CR or store row) and nil-coalesce both slices to their `[]T{}` zero value before returning, mirroring `toRenderEnvironment`'s two-line pattern exactly.
3. Verify every construction site (there may be more than one — grep `PostgresView{` across `postgres/*.go`) applies the same coalescing, not just the primary read path, so create/update/suspend/recover responses are covered too, not just `GetPostgres`.
4. Locally curl or re-run this task's live probe shape against a dev/local instance (or trust t003's new tests) to confirm the key is now always present.
