# Every `lego/types/v1alpha1` edit rolls both SNI proxies and closes their external clients older than an hour

Why: since w6/m518 each deploy that changes an SNI binary closes every external Key Value and Postgres connection still open 1 h after its old pod's `SIGTERM`, without notice. Both binaries link the whole CRD package, so an unrelated type edit is enough to do it. Render breaks such connections only in announced maintenance ([platform maintenance](https://render.com/docs/platform-maintenance), read 2026-11-19).

- **Filed by** w6/m518 t009 (2026-11-20), from that milestone's § Design "What it does not fix". No board item covered it.
- **Evidence.**
  - `go list -deps ./cmd/kv-sni-proxy ./cmd/pg-sni-proxy` (in `lego/operator`, 2026-11-20) includes `lego/types/v1alpha1`, `tiers`, `env`, `netutil`, `proxyproto` and `k8sname`.
  - `cmd/kv-sni-proxy/main.go` registers `appv1alpha1.AddToScheme` and watches `KeyValue`. `cmd/pg-sni-proxy` does the same for `Database`.
  - The deploy's write-back (`scripts/operator-pins.sh`, `deploy.yml` "build the SNI proxy pin comparison") moves a proxy's pin whenever its binary differs. So a field added to any CRD type moves both pins and rolls both DaemonSets.
  - Up to about 40% of pins move an SNI pin (22 of 56, ADR021 § 10). Five of the six pins w6/m470 t006 read moved both pins, each for a `lego/types/v1alpha1` change.
  - Since w6/m518, a stream that ends within the hour survives the roll. A pool or a permanent subscriber is closed once per roll, at the bound: production pin `4e37ec03f` closed two held clients on each proxy exactly 3,600 s after their old pods' `SIGTERM` (w6/m518 t006 § Step 2).
- **Directions to weigh.**
  - Have each proxy read only the fields it routes by, through a minimal local type or `unstructured`, so that an edit elsewhere in `v1alpha1` leaves `/kv-sni-proxy` and `/pg-sni-proxy` byte-identical.
  - Keep the routing contract pinned by a test, so that a field the proxies do read still rolls them when it changes.
  - Check what else the binaries link that changes often.
- **Done when:**
  - An edit to a `lego/types/v1alpha1` field neither proxy reads leaves both binaries byte-identical. A test or a `scripts/` check proves it, for example by building both before and after a synthetic field edit.
  - The write-back logs `kept` for both proxies on the first production deploy that carries such an edit.
  - ADR021 § 10's "gap that remains" says so.
