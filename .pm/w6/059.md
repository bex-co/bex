# Static-site Redirects and Headers editors: all six row controls have no accessible name, and lean on hardcoded English placeholders

Why: these are the only controls on two dedicated Manage pages, so a screen-reader user editing a redirect hears "combobox" and two textboxes named after example values — and once a field holds a value, the placeholder-as-name is stale rather than merely thin.

## What's wrong

`dashboard/src/features/services/components/static-site-section.tsx` — six form controls, none with a label, `aria-label`, or `aria-labelledby`:

| control | line | what it has |
| --- | --- | --- |
| route type `<Select>` | 189-201 | `<SelectValue />` only — **no name at all** |
| route source `<Input>` | 204-209 | `placeholder="/old/*"` |
| route destination `<Input>` | 211-216 | `placeholder="/index.html"` |
| header path `<Input>` | 301-306 | `placeholder="/*"` |
| header name `<Input>` | 308-313 | `placeholder="X-Frame-Options"` |
| header value `<Input>` | 315-320 | `placeholder="DENY"` |

The table's `<th>`s (`Type`/`Source`/`Destination`, `Path`/`Name`/`Value`) label the **cells**, not the inputs inside them, so they do not supply an accessible name.

## Verified with the accessibility tree, not a DOM heuristic

Checked the way this skill's own Phase-3 trap prescribes — `await page.locator('main').ariaSnapshot()`, on a fresh page load of `/static/srv-…/redirects` with a saved rule:

```
- table:
  - rowgroup:
    - row "Type Source Destination":
      - columnheader "Type"
      - columnheader "Source"
      - columnheader "Destination"
  - rowgroup:
    - row "/qa-old /main.go Remove rule":
      - cell:
        - combobox: Redirect                       ← no name; "Redirect" is its VALUE
      - cell "/qa-old":
        - textbox "/old/*": /qa-old                ← name is the placeholder, value is the data
      - cell "/main.go":
        - textbox "/index.html": /main.go
      - cell "Remove rule":
        - button "Remove rule"                     ← correctly named
```

and the Headers page has the identical shape (`textbox "/*"`, `textbox "X-Frame-Options"`, `textbox "DENY"`).

**The control is in the same rows.** `button "Remove rule"` / `button "Remove header"` come back properly named because they use `aria-label={t("services.routeRemove")}` (line ~222 and its headers twin) — the file's author applied the pattern to the buttons and not to the inputs. Elsewhere in the app the pattern is followed consistently: `combobox "Log type"`, `combobox "Log history range"`, `textbox "Search logs"` all return real names.

## The i18n half, which is why placeholder-as-name matters here

The file is otherwise translated — `grep -c 't("services\.' static-site-section.tsx` → **29**, including `t("services.publishPathPlaceholder")` (:121), `t("services.routeRewrite")`, `t("services.routeRedirect")`, `t("services.routeRemove")`. But these five placeholders are **hardcoded English literals**. That is tolerable while a placeholder is only a hint; it is not tolerable while it is doubling as the accessible name, because a non-English user's screen reader then announces an untranslated string as the field's label.

## Fix sketch

Give each of the six an `aria-label` from the existing `services.*` translation namespace (the column headings already have translated text to reuse — Type / Source / Destination / Path / Name / Value). Keep the placeholders as examples; decide separately whether the example values themselves want translating (`/old/*` and `/*` are path syntax and probably should not; `X-Frame-Options`/`DENY` are header literals). `en` and `zh` move together.

## Verified working in the same journey (recorded so it is not re-probed)

Journey 9's core promise holds — the rules take effect on the served response. On a real static site (`qa-20260827-static`, publish path `.`, deleted afterwards):

```
$ curl -sS -D- -o /dev/null https://qa-20260827-static.onbex.co/qa-old
HTTP/2 301
location: /main.go          ← redirect rule applied; the page's "a redirect returns 301" copy is accurate
x-qa-marker: hunt30         ← header rule applied to the redirect response too

$ curl -sS -D- -o /dev/null https://qa-20260827-static.onbex.co/main.go
HTTP/2 200
x-qa-marker: hunt30         ← header rule applied to a normal response
```

Both rules also survive a reload of their editor (`GET /v1/services/<id>/routes` and `/headers` match what the UI shows), and `/static/<id>/redirects`+`/headers` are real pages for a static site rather than the settings redirect the web-service route family does.
