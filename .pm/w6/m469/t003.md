## Objective

Run real proxies on the local CAPD cluster through operator upgrades. An operator rebuilt with an unrelated change rolls no proxy, and a client held through the proxy keeps its connection. A proxy code change still rolls it, and so does enabling internal authentication, which still closes the unauthenticated client.

## Context

- `bash scripts/mock-cluster.sh operator` builds and imports `bex-operator:dev`. One fixed tag never changes the template's `image` string, which hides both the roll and the hold. Tag each build distinctly (for example `bex-operator:dev-<n>`), as production's digests are, and say how in the task record.
- Use a free probe store in dev-6's tenant namespace, as w6/139 and w6/m463 t003 did.
- A held client is one connection: `CLIENT ID` before and after proves it is the same. `valkey-cli` reconnects by itself, so a `PONG` alone proves nothing.

## Steps

1. Deploy build A. Create the probe store and wait for its proxy. Open one client through `<id>:6379` and note its `CLIENT ID`.
2. Deploy build B, which changes only something outside the proxy (a log line in the manager). Check that the proxy Deployment's ReplicaSets, pod name and image are unchanged, the annotation records the hash, and the held client answers `PING` with the same `CLIENT ID`.
3. Deploy build C, which changes the proxy binary (a throwaway local change, never committed). Check that the proxy rolls once onto C.
4. Enable internal authentication on the store. Check that the proxy rolls on the held image and the held unauthenticated client is closed (w6/m463).
5. Delete the probe store and every probe object.

## Files

- none committed beyond the task record (the build C change is discarded)

## Acceptance criteria

- [ ] Build B: no new ReplicaSet, same pod, same `CLIENT ID`, `PING` answered
- [ ] Build C: the proxy rolls once
- [ ] Internal auth: the proxy rolls and the unauthenticated client is closed; no Valkey pod restarts
- [ ] The probes are deleted
