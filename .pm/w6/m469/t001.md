## Objective

`reconcileKeyValueInternalProxy` keeps the image of an existing `<id>-internal` Deployment while that image runs the same `/kv-internal-proxy` as the manager's own image. A new operator image that leaves the proxy binary alone then changes nothing in the proxy's pod template, and no proxy rolls. A changed binary sets the manager's image as today.

## Context

- `reconcileKeyValueInternalProxy` (`lego/operator/internal/controller/keyvalue_internal_proxy.go`) sets `Image: r.InternalProxyImage` on every reconcile. `InternalProxyImage` is the manager's own image (`backupHelperImage` → `selfimage.Resolve`, `cmd/manager/main.go`), so every deploy changes it.
- The manager's image contains `/kv-internal-proxy` (`lego/Dockerfile`), and the manager runs from `/`, so it can hash the file it would deploy at startup. Production builds are byte-reproducible (README § Findings), so the hash changes exactly when the proxy's code or toolchain does.
- Precedents for holding a template field so an operator upgrade rolls nothing: `holdDatastorePriority` and `holdIsolationLabel` (same function).
- The `before` copy of the template is already taken at the top of the mutate func.

## Steps

1. In `cmd/manager`, read `/kv-internal-proxy` once at startup, hash it with sha256, and pass the hex digest to `KeyValueReconciler` as a new field (for example `InternalProxyBinary`). If the file is missing (`make run`, envtest), the field is empty and nothing is held: today's behavior.
2. In the mutate func, the existing Deployment's `metadata.annotations["app.bex.co/kv-internal-proxy-sha256"]` records the binary its template's image carries. When it equals the manager's hash and the existing `internal-proxy` container has an image, keep that image. Otherwise set `r.InternalProxyImage` and record the manager's hash.
3. Never put the hash in the pod template (README § Design constraints).
4. Keep every other template field as rendered today, so internal auth, credential-revision, plan-limit and suspend changes still roll the proxy, on the held image.
5. Do not touch `kvinternalauth` or `cmd/kv-internal-proxy`.

## Acceptance criteria

- [ ] envtest: a reconciler with a new `InternalProxyImage` and the same binary hash leaves the proxy Deployment's template (and its generation) unchanged
- [ ] envtest: a different hash sets the new image and records the new hash on the Deployment's metadata
- [ ] envtest: enabling internal auth on a held proxy changes its env and keeps the held image
- [ ] An empty hash behaves exactly as before (image follows `InternalProxyImage`)
- [ ] `make test` and `make lint` pass
