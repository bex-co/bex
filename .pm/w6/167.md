# Do the routines still need `agent-4c-8g`? Measure a week of their CPU and memory, then recommend a template per routine

Why: every `rt-*` automation runs on a 4 CPU / 8 GiB sandbox. That is twice the memory charge of `agent` (2 CPU / 4 GiB) once m566 bills on use, and no one has measured what the routines use since m354 chose it.

- **Background.** [m354](done/m354/README.md) (user decision 2026-11-12) moved the routines to `agent-4c-8g` after five of eight died with their sandbox, some out of memory, on a `cx33`. The size was chosen for headroom, not from a measurement of each routine.
- **Start when** m566 t001 has recorded `sandbox_cpu_seconds` for agent sandboxes for 7 days. Until then park this note with a date gate.
- **Memory.** Check whether Prometheus keeps a pod memory series for `*-sandbox` namespaces (the cadvisor job in `deploy/gitops/base/prometheus.yaml` renames and keeps the pod CPU row). If it keeps none, file the relabel that keeps the pod's working-set peak; this note needs peak memory, not allocated memory.
- **Output.** Per routine (`agent_automations.name` joined through `agent_sessions.automation_id`): turns, p50/p95 CPU cores used during turns, peak memory, and turn duration. Recommend `agent` for a routine whose peak memory stays well under 4 GiB and `agent-4c-8g` otherwise. Record the table in [ADR105](../../docs/ADR105-agent-sandbox-hetzner-bare-metal.md).
- **Decision.** Changing a routine's template reverses part of the user's m354 decision: present the recommendation to the user (`/unblock w6`), and do not change any automation without their decision.
- **Stakes.** Weighted today: $0.434 per hour for 4c-8g against $0.217 for 2c-4g. Billed on use (m566): memory $0.106 per hour against $0.053, plus the CPU actually used.
