## Objective

Cover the `idleTTLSeconds: 0` case explicitly. Its absence is why this shipped: the existing auto-sleep tests all use nonzero values, so every one of them passes under either meaning of `0`.

## Context

- The bug is not that hibernation is broken — this run measured it working (`60s` → `Hibernated` in 61s; wake in 15s with the documented `503`/`retry-after: 5` interstitial). The bug is that the untested default value disables it.
- `w6/m47`'s post-mortem records the same shape of gap on the neighbouring code: "every hibernate test ran in namespace `default`, where the defect is invisible." A test that only ever exercises the configured-happy-path cannot see the shipped default.

## Steps

1. Add an operator test that asserts the decided behavior for an App with `idleTTLSeconds: 0` on the free tier — it must fail if `0`'s meaning is flipped.
2. Cover all three `autoSleepEligible` callers for the `0` case, including the Ingress-backend choice at `:2031`, which has never executed for a `0` App.
3. Keep a nonzero case as the control, asserting the current 61s-style behavior is unchanged.
4. Cover the worker exclusion so a future change to the predicate cannot make workers eligible.
5. If t001 kept "off" expressible, assert a literal `0` round-trips through `SetIdleTTL` unrewritten.
