## Objective

Add a `SetEnvironmentID` verb to `postgres.Service` and `keyvalue.Service` that writes `core.LabelEnvironment` on the CR, mirroring the existing `SetProjectID` pattern.

## Context

- `lego/backend/internal/postgres/service.go:97,225,475-484` — `SetProjectID` writes `core.LabelProject` on the Database CR.
- `lego/backend/internal/keyvalue/service.go:95-97,172,349-360` — mirrors the same pattern for KeyValue.
- `core.LabelEnvironment` is introduced in `w6/m19/t003`; this task depends on it existing.
- Database/KeyValue have no Postgres store row (CR-only), unlike Apps — so this is purely a label write, no store migration needed.

## Steps

1. Add `SetEnvironmentID(ctx, name, environmentID string) error` to `postgres.Service`, writing/clearing `core.LabelEnvironment` on the Database CR.
2. Mirror for `keyvalue.Service`.
3. Validate the environment belongs to the same workspace/project as the resource before allowing assignment.

## Files

- `lego/backend/internal/postgres/service.go`
- `lego/backend/internal/keyvalue/service.go`

## Acceptance criteria

- [ ] Assigning/unassigning a Database or KeyValue to an Environment sets/clears the CR label.
- [ ] Cross-workspace/cross-project assignment is rejected.
