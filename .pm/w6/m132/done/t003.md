## Objective

Journey 8's promise is "attaches, **or fails with a real reason**". A user hitting this fault gets `Connection closed by 49.12.20.236 port 22` and nothing else. Decide what a **pre-authentication** refusal should tell the client — without weakening the deliberate non-disclosure that applies **after** authentication begins.

## Context

- **Do not re-litigate `ADR035:106`.** It deliberately makes *authentication* failures non-disclosive: "Authentication fails without revealing whether the cause was an unknown/deleted key, malformed username, missing/foreign service, insufficient role, unsupported/free/suspended service, missing live revision, or missing/non-Ready/stale instance." That is a security decision and stands.
- This failure is **before** that point: the client never receives a KEXINIT, so it never reaches the stage that policy governs. An infrastructure fault is currently indistinguishable from an authorization refusal — and it is not a security boundary, so it need not be.
- SSH permits a `SSH_MSG_DISCONNECT` carrying a reason code and message, and OpenSSH surfaces a server banner to the user, so there are protocol-legitimate ways to say something.
- **The bar is already set in-product.** Verified live this run: a free service's Shell tab reads "Shell access isn't available — Shell access requires a running paid web, private, or background service and an active SSH gateway", with a Manage SSH public keys link. The dashboard explains the plan-gated case well; the SSH edge explains nothing.

## Steps

1. Decide what a pre-auth refusal emits — a DISCONNECT with a reason, a banner, or deliberately nothing — and write the reasoning down.
2. Confirm the decision cannot leak any of the post-auth causes `ADR035:106` protects.
3. Implement it, or record explicitly why the pipeline fix alone suffices.

## Outcome

Decision recorded in ADR035 (§ "Pre-authentication faults are distinguishable from authorization refusals"): a pre-`KEXINIT` fault is not a security boundary and is kept structurally distinguishable from an authorization refusal (transport dies before auth vs. `Permission denied` after). No new in-band SSH message — SSH forbids one before the transport exists — so the pipeline fix plus a content-free `bex_ssh_gateway_handshakes_total{result}` counter carries it (loud + distinguishable server-side). `ADR035:106`'s post-auth non-disclosure is untouched (`authentications_total` unchanged), asserted by `TestServeConnUnstrippedProxyV2HeaderBreaksHandshake` and the existing opacity tests.
