## Objective

Implement ADR022's documented behavior: when `BEX_REGISTRY_PULL_SECRET` is set, every operator-generated pod spec that pulls a tenant image (App Deployments, CronJobs, and the static-publish/pre-deploy Jobs if they pull tenant images) carries it under `imagePullSecrets`. Unset ⇒ byte-identical output to today.

## Context

- `lego/operator/internal/controller/app_controller.go` (Deployment/CronJob generation) + the Job builders (`bld-`/`predeploy-` generation paths).
- The env var already exists and is documented (root `CLAUDE.md` env table, docs/ADR022 §Registry access control); the Secret (`bex-registry-pull`) is minted by `scripts/registry-secrets.sh` in the apps namespace.
- Wire the env var into the operator's prod deployment manifest (`lego/operator/config/manager/` and/or `deploy/gitops/base/bex.yaml`) so prod actually sets it.

## Steps

1. Add the `imagePullSecrets` injection at the shared pod-spec construction seam (one place if possible).
2. Thread `BEX_REGISTRY_PULL_SECRET` through the operator config the same way `BEX_REGISTRY_PUSH_SECRET` already flows.
3. Set the env var in the prod operator deployment manifests.

## Files

- `lego/operator/internal/controller/` (workload generation)
- `lego/operator/config/` + `deploy/gitops/base/bex.yaml`

## Acceptance criteria

- [ ] With the var set, generated Deployment/CronJob (+ relevant Job) specs carry the secret; with it unset, generated specs are byte-identical to before (envtest-diff).
