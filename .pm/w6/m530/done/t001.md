## Objective

A package that, given a procfs root, a pod UID and the pod's IP, returns the TCP ports the pod listens on at an address other than loopback. It is the answer the connect sweep gives today, without a connection.

## Context

- The connect sweep: `lego/operator/internal/portscan/portscan.go` (512 workers, 400 ms per connect, ports 1–65535, likely HTTP ports first). Its callers are `internal/controller/private_ports.go` and `internal/controller/port_detect.go`.
- The table parser in the pod: `internal/healthprobe/openport.go` `listeningPorts` reads `/proc/net/tcp{,6}` rows in state `0A` and keeps the port only. Share one parser: it must also return the local address, and `healthprobe` keeps its own behavior (it leaves loopback to its connect).
- Finding the pod's processes from the node's PID namespace: each line of `/proc/<pid>/cgroup` names the pod's cgroup. With the systemd driver it reads `…kubepods-<qos>-pod<uid with _ for ->.slice/cri-containerd-<id>.scope`, Guaranteed pods have no QoS segment, and the cgroupfs driver writes `pod<uid>` with dashes. A private cgroup namespace prefixes the path with `/..` segments. Every container of a pod, the sandbox's pause process included, shares the pod's network namespace.
- `/proc/<pid>/ns/net` is ptrace-guarded and unreadable without privilege, so the pod IP is how a read proves it found the right namespace: `/proc/<pid>/net/fib_trie` lists the namespace's local IPv4 addresses (`/32 host LOCAL`), `/proc/<pid>/net/if_inet6` its IPv6 ones.
- A process can exit between finding it and reading its tables; try the next one.

## Steps

1. Extract the `/proc/net/tcp` row parser to return `(local address, port)` for LISTEN rows, IPv4 and IPv6 (the kernel prints addresses as host-order hex words). Keep `healthprobe.Listening` on it with unchanged results.
2. `Listeners(procRoot, podUID, podIP)`: find a PID whose cgroup names the pod (both drivers, all QoS classes), check that the pod IP is local in its namespace, read `net/tcp` and `net/tcp6`, keep the LISTEN ports whose address is `0.0.0.0`, `::`, the pod IP (or its v4-mapped form), or any other non-loopback address. Sorted, deduplicated. Errors that tell apart "no such pod on this node", "the namespace does not hold that IP" and "unreadable".
3. Test against a fake procfs tree under `t.TempDir()`: both cgroup drivers, the three QoS classes, the `/..` prefix, a pod with several containers, loopback-only listeners (v4, v6 and v4-mapped), a listener bound to the pod IP only, `tcp6` absent, a PID that vanishes mid-read, a PID of another pod with the same port open, and a wrong IP.
4. Check on a real kernel: from a container with only `hostPID`, uid 65534, no capability and a read-only root, read a pod on the local cluster (`bash scripts/mock-cluster.sh`) and a pod with `hostUsers: false` there if the local nodes support it. Record what you read in this task; production's kernel is checked in t006.

## Record (2026-11-20)

- **Shipped:** `internal/procnet` parses a `/proc/net/tcp{,6}` table into LISTEN sockets with their local address (host-order words decoded through `binary.NativeEndian`), stdlib only, because the health-probe binary is copied into tenant pods. `healthprobe.listeningPorts` keeps its result on it (its test passes unchanged). `internal/listeners.Read(ctx, procRoot, podUID, podIP)` walks `/proc`, matches the pod by a whole cgroup path segment (`pod<uid>` or `…-pod<uid_>.slice`), opens each candidate's `/proc/<pid>` once through `os.OpenRoot` so a recycled PID can never answer for the pod, checks the pod IP in `net/fib_trie` (`/32 host LOCAL`) or `net/if_inet6`, and keeps LISTEN ports not on loopback (`127.0.0.0/8`, `::1`, `::ffff:127.0.0.0/104`). Errors: `ErrPodNotFound`, `ErrAddressMismatch`, `ErrUnreadable`, `ErrBadRequest` (UID not a lowercase UUID, IP loopback or unspecified).
- **Tests** (`internal/listeners/procfs_test.go`, `internal/procnet/procnet_test.go`): both drivers × three QoS classes, the `/..` prefix, kind's `kubelet-kubepods-…` prefix, cgroup v1 files, a pod of three processes, loopback v4/v6/v4-mapped, pod-IP-only and v4-mapped-pod-IP listeners, `tcp6` absent, a PID that vanished mid-read (next PID answers; all gone is `ErrUnreadable`), another pod with the same port open, a wrong IP, an IPv6 pod IP, malformed requests.
- **Real kernel (Docker Desktop, Linux 7.0.12-linuxkit arm64, containerd 2.3.1 in the CAPD nodes):** `cmd/listener-reader` built for linux/arm64 ran with `docker run --pid=host --user 65534:65534 --cap-drop ALL --read-only --security-opt no-new-privileges` (no AppArmor on linuxkit). It read real CAPD pods: `bex-activator` `[8888]`, `bex-kv-sni-proxy` `[6379,9093]`, `bex-controller-manager` `[8080,8081,9443]`, `coredns` `[53,8080,8181,9153]`, `bex-ssh-gateway` `[2222,8080…8085,9090]`; the activator's UID with another pod's IP answered 409, an unknown UID 404, a malformed UID 400. Two busybox pods in `dev-6` binding `0.0.0.0:8123`, `127.0.0.1:8124`, `[::1]:8125` and `[::]:8126` both read `[8123,8126]`: one with `hostUsers: true`, and **one with `hostUsers: false`** (its `uid_map` `0 1813643264 65536`), so a user-namespaced pod reads the same locally. Production's Ubuntu 6.8 kernel under containerd's AppArmor profile is still t006's check.
