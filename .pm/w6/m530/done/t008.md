## Record (2026-11-20, after t006)

`/simplify` over `84e2bfe08`'s Go code (the reader, `procnet`, `healthprobe`, the operator's client and the scan paths), with one reviewer each for reuse, quality and efficiency.

- **The question, answered:** partial-sweep handling already runs only on the fallback. On the reader path, `podListeners` returns before the sweep. Only `portscan`'s scan yields `ErrPartial`, so `private_ports.go`'s partial merge and `declaredPortsClosed`, `web_image_http.go`'s partial log and `scanBoundPort`'s partial-to-success turn never see a reader's answer. Nothing needed narrowing. What did not fit was `podListeners`'s `complete` result: it was false for a sweep that finished, so it meant "an unnarrowed reader answer", and two of its three callers discarded it.
- **Applied, behavior-preserving:**
  - `podListeners` returns `([]int, error)`. `boundPortListeners` narrows unless its sweep callback ran.
  - `fullSweep`'s comment now says why it is a method: the method value `r.PortScanner.Scan` panics on a nil `PortScanner` before `podListeners` checks it.
  - The operator's read timeout is the reader's own exported `listeners.ReadTimeout` (5 s), not a second constant.
  - `listening()` drops a redundant `.Unmap()` (t009's equivalent mutant).
- **Skipped:**
  - `httpclient.DecodeJSON` in the client: it rejects trailing bytes and would add packages to the node agent.
  - One table for the three sentinel-to-status mappings: low payoff.
  - A shared `procnet` port loop with `healthprobe`: it handles a missing table differently.
  - `MaxIdleConnsPerHost` 1 to 4: no measurable gain.
  - Making `scanBoundPort`'s partial sweeps count as `result="partial"` rather than `ok`: it changes the metric, and only the fallback emits it.
- **Checks:** `go test ./internal/listeners/ ./internal/procnet/ ./internal/healthprobe/` and the controller's listener, port-detection and private-port tests pass; `make test` (exit 0) and `make lint` (exit 0, all four modules) pass on the change.
