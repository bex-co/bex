## Objective

Private-port discovery and bound-port detection get a pod's listeners from the reader on the pod's node. The connect sweep stays only for a node that has no reader pod at all, and that case is logged and counted, so it is visible rather than silent.

## Context

- `portscan.Scanner` takes only an IP (`Scan(ctx, ip)`), and the optional `ScanPorts` bounded phase (`port_detect.go` `portsScanner`). The callers know the pod: `readyPodIP` (`private_ports.go`) finds a Ready pod and returns its IP; `unreadyPod` (`port_detect.go`) returns the pod. Pass the pod (UID, IP, node) instead.
- Paths that read listeners today: `sweepPrivatePorts` and `declaredPortsClosed` (`private_ports.go`), `scanForBoundPort` and `scanForPrivatePrimary` through `scanBoundPort` (`port_detect.go`). The web path then HTTP-checks the open ports (`httpListeners`, `internal/httpport`): a handful of connects, which stays.
- A reader's answer is complete, so the partial-sweep merges (`ErrPartial`, `mergePorts` with the previous record or the image's declared ports, `declaredPortsClosed`) apply to the fallback only. "Nothing listens" becomes a definite empty answer; `noOpenPortMessage` stays the stall text.
- The rescan cadence (2 minutes doubling to 16, two rescans at once: `privatePortScanInterval`, `privatePortBackoffDoublings`, `privatePortRescanSlots`) was set for the sweep's CPU cost (w21/m421 t002). Leave it as it is; shortening it is a follow-up, not this milestone.
- `portDetectTimeout` (15 s) bounds a scan; a reader request needs far less, so give it its own short timeout.

## Steps

1. A reader client: find the Ready reader pod on `pod.Spec.NodeName` (the manager's cache, label selector), `GET` it with a pooled client, decode the ports.
2. Selection per scan:
   - the node has a Ready reader: use its answer. A failed request or a 5xx keeps the last record (private ports) or retries at the next interval (detection), and never sweeps;
   - 404 or 409 from the reader (the pod moved or is gone): treat as a failed read, never a sweep;
   - the node has no reader pod at all: log once per node and interval, count it (`bex_operator_port_listener_reads_total{source="reader|sweep", result=…}` or similar), and run today's connect scan.
3. Keep the Scanner seam so the controller tests still supply canned answers; adapt `private_ports_test.go`, `private_ports_backoff_test.go`, `private_ports_envtest_test.go` and `port_detect_test.go` to the pod-based call.
4. Tests for step 2's cases, including that a node with a Ready reader whose request fails is never swept (mutation: make it sweep and watch the test fail).

## Record (2026-11-20)

- **Client:** `controller.NodeListenerReader` lists the reader pods (`app.bex.co/component=listener-reader` in the operator's namespace, from the manager's cache) and asks the Ready one on `pod.Spec.NodeName` through `listeners.Client`, a pooled client keeping one idle connection per reader. A node with no reader pod is `errNoListenerReader`; one whose reader pods are all unready is `errListenerReaderNotReady`. Wired in `cmd/manager/main.go` as `AppReconciler.Listeners`, beside `PortScanner`.
- **Selection** (`AppReconciler.podListeners`, `internal/controller/listener_reads.go`): the reader's answer within a 5 s bound when the node has a reader pod. Any failure (request, 5xx, 404, 409, not Ready) is an error and never a sweep: private ports keep the last record, and detection gives its no-open-port hint and reads again at the next interval. Only `errNoListenerReader` sweeps the pod IP, within `portDetectTimeout`, logged once per node and `privatePortScanInterval` (`CompareAndSwap`, so two concurrent sweeps log once) and counted. The counter is `bex_port_listener_reads_total{source="reader"|"sweep", result=…}`: results `ok`, `pod_not_found`, `address_mismatch`, `reader_not_ready` and `failed` for the reader; `ok`, `partial`, `unreachable` and `failed` for a sweep.
- **Paths moved to the pod:** `sweepPrivatePorts` (now `readyPod`), `scanForBoundPort` and `scanForPrivatePrimary` (`boundPortListeners`), and a third caller the milestone did not name, the web image HTTP discovery in `selectWebImageHTTP` (`webImageCandidate`). A reader's answer is complete, so `ErrPartial`, the merge with the previous or declared ports and `declaredPortsClosed` now run only on a sweep. Detection narrows a reader's answer as the sweep's two phases did: the common HTTP ports plus the probed port when any listens there, else all. So detection rules are unchanged, as the task requires, and a web service binding 8000 and a metrics port is still adopted on 8000. The rescan cadence is unchanged.
- **Tests** (`listener_reads_test.go`): private ports come from the reader with no sweep; an empty answer clears the record; for each of request failure, 5xx, 404, 409 and not-Ready, neither private ports nor detection sweeps, the last record stands and the reader result is counted; a node without a reader is swept and counted; detection's narrowing (5 cases); a web service on 8000 is detected through the reader; web image HTTP discovery reads the reader; `NodeListenerReader` asks the pod's own node with its UID and IP, refuses a reader elsewhere or not Ready, and reads the Ready pod during a surge roll. **Mutation:** the reader branch changed to sweep on any error turned `TestAFailedReadNeverSweeps` red in all five cases. The existing sweep tests run unchanged as the no-reader path.
- **Grep:** `grep -rn 'PortScanner\.\|ScanPorts\|scanBoundPort(' internal/controller/*.go` (non-test) finds the sweep only in `fullSweep` and in `boundPortListeners`' sweep closure, both called solely by `podListeners`' no-reader branch, plus `declaredPortsClosed`'s bounded dial, which runs only on a sweep's `ErrPartial`.
