## Objective

A tenant sees "Services 11 / 100" and can find six services. Make the two numbers tell one story, without turning a truthful number into a flattering one.

## Context

- The divergence: `workspaces/service.go:953` counts every App CR; `apps/service.go:1131` drops any App with a `DeletionTimestamp`. Same objects, opposite treatment.
- **`t003` decides the shape of this task.** If the ResourceQuota counts terminating objects (expected), the displayed number is honest and the fix is to make the consumption **discoverable**. If it does not, the display is simply wrong and should be filtered to match.
- **Do not "fix" this by filtering the counter without checking t003.** Under the expected outcome that would make the number look right and turn it into a lie — the user would be refused a create at 6/100 with no explanation at all.
- The two coherent shapes:
  - **(a) make terminating resources visible** — in the list, or via a dedicated "finishing deletion" affordance — so quota consumption is discoverable and the counter stays truthful. This reverses `w3/m46/t002`'s deliberate hide, so it is a decision to revisit with its author's reasoning in hand, not an oversight to patch.
  - **(b) exclude terminating resources from the quota** — which requires the **enforcement** side to match. Since enforcement is a Kubernetes ResourceQuota and k8s cannot be told to ignore terminating objects, this likely requires replacing that mechanism outright. Record that infeasibility explicitly rather than leaving a future reader to rediscover it.
- Whatever is chosen: **the number displayed and the number that gates creates must remain the same number.**

## Steps

1. Read `t003`'s measured result and pick the shape it implies.
2. Implement it, keeping display and enforcement on one source of truth.
3. If (a): decide where terminating resources appear and what they are called, and reconcile with `w3/m46/t002`'s comment so the two do not contradict each other in code.
4. Record the decision — including why the rejected option was rejected — where the next reader will find it.
