# The agent sandbox's TMPDIR moves off gVisor's memory-backed /tmp

Why: under gVisor `/tmp` is memory and counts against the sandbox's 8 GiB limit, and Claude Code and Node write their temporary files there. Only Go's work directory was moved (w6/124), and a routine was OOM-killed again on 2026-11-13.

- **Evidence.** Routine transcripts show Claude Code's background-task output under `/tmp/claude-10001/-workspace/<session>/tasks/*.output`. ADR105 records that gVisor keeps `/tmp` in memory. `lego/agent-image/Dockerfile` (~141-144) sets `GOTMPDIR=/var/tmp/go-tmp` but no `TMPDIR`. `rt-flatten-abstractions` (session `ags-dbrhfr0k58is73auo6a0`) failed after 1 h 25 min with `the sandbox ran out of memory (exit 128)`. Its transcript did not survive (w6/m398), so the link to `/tmp` is not proven.
- **Fix.** Set `ENV TMPDIR=/var/tmp` in the agent image. `/var/tmp` is on the rootfs, which the 30Gi ephemeral limit bounds. Then confirm in a sandbox that `node -e 'console.log(require("os").tmpdir())'` prints `/var/tmp` and that Claude Code writes its task output there.
- **Done when:** a routine session's temporary files land under `/var/tmp`, and its memory working set no longer grows with background-task output.
