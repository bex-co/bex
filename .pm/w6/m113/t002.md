## Objective

`r.fail` has 47 non-test call sites and every one inherits the unconditional `PhaseFailed`. They are not interchangeable, so the guard cannot be applied blindly — this task produces the list that decides where it goes.

## Context

- `grep -rn "r\.fail(" lego/operator/internal/controller/*.go | grep -v _test` → **47** (measured at filing; re-measure, do not trust this number blind).
- Some fire before any release could exist: `BadSpec` (`app_controller.go:621`, `:673`), `ProtectedSecretReference` (`:500`), the registry-credential family (`:551`, `:555`, `:559`).
- Others can fire with a healthy release already serving: `ReasonBuildFailed` (`:731`, `:737`, `:755`, `:760`, `:765`, `:793`, `:849`), `DeployFailed` (`:1766`), `IngressFailed` (`:1731`), `ServiceFailed` (`:1685`, `:1783`), `NetworkPolicyFailed` (`:1695`, `:1772`), `MaintenanceRoutingFailed` (`:1807`).
- The existing precedent guard is `app_controller.go:577` — `if app.Status.Image != "" { return r.dispatchRuntime(...) }` — the only `Status.Image != ""` check in the file. Whether `Status.Image != ""` is the right predicate for "a release is serving", or whether readiness/replica state is needed, is part of this task: a stale `Status.Image` with zero ready pods would make the guard lie in the other direction.
- Call sites that report `Failed` correctly today do so **because** no release exists. They are the regression surface.

## Steps

1. Re-run the grep, record the exact count, and enumerate every call site with its reason string.
2. Classify each: can a healthy release be serving when this fires, yes or no?
3. Decide the predicate for "a release is serving" and justify it against the stale-`Status.Image` case.
4. Record the classification table in the milestone README — DoD bullet 7 requires it there, not just in the diff.
