# Dashboard has no UI for dockerfilePath, and startCommand is create-only

Filed by `w6/m21` (2026-07-14), from its t005 Render-parity check.

`w6/m21` closed the backend/operator gap for `App.Spec.DockerfilePath` and
`App.Spec.StartCommand`: both fields are now consistently readable/writable
across REST, GraphQL, and MCP create+update, bex.yml ingestion, the BuildKit
build arg, and the reconciled Deployment's container command. Out of scope for
that milestone was building any new dashboard UI — but the check surfaced two
gaps worth a follow-up:

- **`dockerfilePath` is not surfaced anywhere in `dashboard/src`** — not in the
  service-create wizard (`services.new.tsx`), even though `runtime: "docker"`
  is a selectable option there, and not in the Build & Deploy settings section
  (`features/services/components/build-deploy-section.tsx`). A user deploying a
  Dockerfile at a non-default path has no dashboard path to set it — bex.yml,
  REST, GraphQL, or MCP only.
- **`startCommand` is create-only in the dashboard** — set in the create
  wizard (`services.new.tsx`, wired through `use-create-service.ts` +
  `services.graphql`'s `createService` mutation) but never exposed in Settings
  → Build & Deploy afterward, unlike `rootDir`/`preDeployCommand`/`autoDeploy`
  which each have their own inline-edit hook + `.graphql` mutation file in that
  section.

A future milestone should add both fields to Settings → Build & Deploy
(mirroring the existing `use-root-dir.ts`/`root-dir.graphql` inline-edit
pattern — pencil → input → confirm), and add `dockerfilePath` to the
service-create wizard's docker-runtime branch alongside the existing
`startCommand` field.
