## Objective

Fix the 3 call sites that currently have **no** hydration guard at all — each of these throws a live, unsuppressed React error #418 on a fresh page load AND displays the wrong (SSR-container-timezone) value until an unrelated re-render happens. `recovery-panel.tsx` is the highest-stakes instance in the whole milestone.

## Context

- `dashboard/src/features/databases/components/recovery-panel.tsx:96,102` — calls `formatDateTime(info.earliestRecoveryTime)` / `formatDateTime(info.latestRecoveryTime)`, rendered via the local `Field` component (`:317-324`: `<dd className="truncate text-sm font-medium">{value}</dd>`, no guard). The component's own comment: "Exact restore-point boundaries, not relative ages — the user picks a point-in-time against these." A wrong value here is the most consequential instance in this milestone.
- `dashboard/src/features/webhooks/components/webhook-row.tsx:50,81` — `const exactLatest = formatDateTime(entry.latestSentAt)`, rendered as visible text: `<span>{exactLatest ?? entry.latestSentAt}</span>` (and also as the `title=` attribute on the same `<time>`, which self-heals — the `<span>` is the part that doesn't).
- `dashboard/src/features/webhooks/components/webhook-deliveries-card.tsx:247,319` — `const exactSentAt = formatDateTime(delivery.sentAt)`, rendered as `<span className="text-xs">{exactSentAt ?? delivery.sentAt}</span>`. This sits on the exact same `<time>` element as `w6/m102`'s already-filed `formatRelativeAge(delivery.sentAt)` sibling bug at line 317 — two different root causes, two different fixes, on adjacent lines. Do not conflate the two: this task only touches the `formatDateTime`/`exactSentAt` line; leave the `formatRelativeAge` line for `w6/m102`'s own fix.

## Steps

1. Replace each raw `formatDateTime(...)` call + manual text render with t001's shared primitive.
2. For `webhook-row.tsx`/`webhook-deliveries-card.tsx`, keep the `title=` attribute using the raw (non-guarded) `formatDateTime` value if simplest — attribute mismatches self-correct during hydration, so only the visible `<span>` text needs the primitive. Confirm this assumption holds (no console error from the attribute alone) as part of this task's verification.
3. Live-verify (fresh `page.goto`, not client nav) that each of the 3 routes no longer logs React error #418 and displays the viewer-local time.
