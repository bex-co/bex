## Objective

Create one shared primitive that every `formatDateTime`/`formatDateLong` call site can route through, guaranteeing the SSR pass and the pre-hydration client render emit byte-identical markup — so React never has a text-content mismatch to warn about, and the wrong (SSR-container-timezone) value is never visible even for one frame. The real, viewer-local text appears only once it is guaranteed correct.

## Context

- Root cause: `dashboard/src/common/lib/format/format-date-time.ts:10-16` (`formatDateTime`) and `:25-31` (`formatDateLong`) call `date-fns`'s `format()`, which reads the JS `Date` through the executing runtime's own local-timezone getters — Node's zone (effectively UTC) during SSR, the browser's zone during CSR.
- Two valid implementation shapes — pick one:
  1. **Mount-gated client-only render.** A hook (e.g. `useClientFormattedDate(value, formatter)`) or component (e.g. `<ClientFormattedDate value={...} formatter={formatDateTime} placeholder="—">`) that renders a stable placeholder during SSR and the initial client render, then calls `formatDateTime`/`formatDateLong` inside `useEffect` (post-mount, client-only) and re-renders with the real text. SSR markup and the pre-mount client markup are identical (both the placeholder), so no hydration mismatch is possible by construction.
  2. **Timezone-hint cookie.** Mirror this codebase's own existing precedent for the identical class of problem — SSR language detection (`dashboard/CLAUDE.md`'s Internationalization section: URL → cookie → `Accept-Language` header → default, with the client's `<html lang>` fallback keeping hydration in agreement). Do the same for timezone: persist the viewer's IANA zone (`Intl.DateTimeFormat().resolvedOptions().timeZone`) in a cookie on first client visit, read it server-side, and format with `date-fns-tz`'s `formatInTimeZone` pinned to that zone on both server and client. A first-ever visit with no cookie yet needs a documented fallback (e.g. UTC, or defer to option 1 for that one render).
- Whichever is chosen must work for BOTH `formatDateTime` and `formatDateLong` (same root cause, same fix).
- No existing `ClientOnly`/mount-gate utility exists in this codebase (checked: no hit for `ClientOnly`/`useHasMounted`/`useIsMounted` in `dashboard/src/common`) — this task creates the first one, in `dashboard/src/common/components/` or `dashboard/src/common/hooks/` per `dashboard/CLAUDE.md`'s directory conventions.

## Steps

1. Decide between the two shapes above (or propose a third if a cleaner one exists) — document the choice and why in a comment on the new primitive.
2. Implement it as a small, well-named, reusable primitive under `dashboard/src/common/`.
3. Unit test it directly: assert SSR-simulated output and post-mount client output for a fixed instant, under a mocked non-UTC `TZ`, produce the placeholder then the correct client-local text — never the wrong value at any point.
