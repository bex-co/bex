## Objective

Update every reference to the three renumbered ADRs so no citation anywhere in the repo points at a stale number or a stale filename. References live in far more places than `docs/` — the sweep must be exhaustive or the milestone's definition of done is unmet.

## Context

- Reference forms in use, all of which must be caught:
  - relative markdown links, e.g. `[ADR049-render-yaml-parity.md](ADR049-render-yaml-parity.md)` and `docs/ADR060-…md`
  - bare prose citations, e.g. "ADR060 D5", "ADR049 fail-closed", "per ADR040 §7"
  - Go comments and doc comments citing ADR numbers (`lego/**`)
  - shell scripts (`scripts/**`) and GitOps manifests referencing ADR anchors
- High-density reference sites: `CLAUDE.md`'s docs index, `docs/ADR018-render-parity.md`, `.pm/DO_NOT_DO.md`, `.pm/FUTURE-MAYBE.md`, and the security-review chain (each round cites its predecessors by number).
- **Do not blind-`sed`.** A bare `ADR040` in prose may refer to *either* file in the pair — that ambiguity is the very defect. Each prose hit must be read in context and pointed at the right document.
- `.pm/DO_NOT_DO.md` items `#18`, `#28`, and `#PSL` carry stable labels other docs cite; the anchors are labels, not ADR numbers, so leave them alone.

## Steps

1. Take the three old→new mappings from `t001`.
2. Sweep for every form: `grep -rn "ADR040\|ADR049\|ADR060" .` across `docs/`, `.pm/`, `CLAUDE.md`, `scripts/`, `lego/`, `dashboard/`, `deploy/`, `.github/`.
3. Resolve each prose hit by reading its context to decide which document of the pair it means, then point it at the correct number.
4. Update link targets and filenames alongside the numbers.
5. Re-run the sweep and confirm every remaining hit is intentional and unambiguous.

## Files

- `docs/**`, `.pm/**`, `CLAUDE.md`, `scripts/**`, `lego/**`, `deploy/**`, `.github/**` — wherever the sweep lands
