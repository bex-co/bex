# Typed plan-limit error code instead of the dashboard's "plan" substring match

Filed by `w6/m15` (2026-07-13), from its `/simplify` altitude pass.

The invite dialog decides between "generic failure toast" and "inline alert +
change-plan CTA" by testing whether the backend's error message contains the
substring `plan` (`dashboard/src/features/team/hooks/use-invite-member.ts`).
That heuristic pre-dates `m15`, but `m15` made it load-bearing: it now gates a
whole UI branch and a navigation, not just which of two toast strings shows.

Mitigated, not fixed: `members_test.go`'s `TestInvitePlanRefusalsNameThePlan`
now pins that both invite plan refusals (the seat cap and the role gate) keep
saying "plan", so a reword fails loudly instead of silently demoting the CTA.

The real fix is a typed code the client keys on instead of prose. The seam
already exists — `internal/api/ratelimit.go` emits
`"extensions": {"code": "RATE_LIMITED"}` in the GraphQL envelope, and graphql-go
honors `gqlerrors.ExtendedError` — so a `core.ErrPlanLimit` sentinel (wrapping
`ErrBadRequest`) carrying `{code: "PLAN_LIMIT", plan, limit}` would surface
without a schema change. The hook then keys on the code and renders localized
copy with the params, which also fixes the secondary wart that the alert body is
the backend's English string even for a `zh` user.

Not a milestone on its own: it touches `core/errors.go`, both `members` guards,
the GraphQL error formatter, and the hook — a shared-error-envelope change worth
grouping with any other typed-error work, and worth doing once rather than once
per feature.
