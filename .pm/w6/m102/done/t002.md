## Result

**Done — 27 call sites migrated, not just the 22.** `formatRelativeAge(`/`formatRelativeUntil(` now appear in exactly one place outside their own module: the t001 wrapper. The milestone README's proximity-check script returns **zero lines at all** (it only reports on files that still call the formatters directly, and none do).

Beyond the 22 unguarded sites, two extra groups were folded in rather than left as exceptions:

- **The 2 incidentally-guarded sites** (`resource-table.tsx:224,235`) — migrated so the guard is deliberate rather than a side effect of unrelated work, which is the whole point of the milestone. Their two now-redundant `<TableCell suppressHydrationWarning>` props were dropped; the guard moved inward with the value.
- **The 3 fact-object sites** (`service-detail-header.tsx:454`, `databases.$databaseId.tsx:380`, `keyvalue.$keyValueId.tsx:285`). t002's step 2 alternative held — their consumers *were* already guarding (`MetadataList`'s `<dd suppressHydrationWarning>`, `HeaderFacts`' own `<dd>`) — but `MetadataRow.value` is already a `ReactNode`, so passing `<RelativeAge …>` costs nothing and makes each value carry its own guard. `HeaderFacts`' `facts` array was retyped `string` → `ReactNode` and its now-redundant `<dd>` guard removed (every other fact there is a deterministic string). **`MetadataList`'s `<dd>` guard was deliberately kept** — it is shared by many callers, some of which pass timezone-formatted values that still need it (w6/m107).

**SSR-reachability, the README's open "Unverified" question — partially answered:**

- `webhook-deliveries-card.tsx` **is** rendered in the blocking SSR pass: the t006 regression test asserts the server HTML literally contains `>now<`. This is the live-reproduced site, now pinned.
- `recovery-panel.tsx` (2 sites) is **not**: `databases.$databaseId.tsx:49` loads it through `React.lazy`, so it never renders server-side and could not have been producing #418. Migrated anyway for uniformity, but it should not be counted as a fixed live defect.
- The rest were not individually probed; the wrapper makes SSR-reachability moot for them.

**Deliberately out of scope — the `formatDateTime`/`formatDateLong` sites on the same elements.** Guarding them was tried and then reverted. `w6/m107` owns that class, and its own analysis is that `suppressHydrationWarning` is the *wrong* fix there: it freezes the server's UTC text instead of letting React's mismatch re-render correct the value to the viewer's local time. Adding guards would have silenced the console error while making the displayed value worse. One unavoidable side effect remains: `services.$serviceId.events.tsx:389` carried `title={exactTimestamp}` on the *same element* as the relative age, so the wrapper's guard now covers that attribute too — **w6/m107 should re-check that tooltip.**

**Behavioral nuance (visible text unchanged):** sites written `x ? format(x) : "—"` now route an unparseable-but-non-empty `x` to the fallback instead of to the formatter's own `"—"`. Same rendered text everywhere except `resource-table`'s updated-at column, which renders `<UnknownValue />` rather than `"—"` in that case — a strict improvement.
