## Objective

Make the account-menu language switcher (`user-nav.tsx`) follow the same lazy-load contract every other `changeLanguage` call site in the app already follows, so selecting a language actually renders it immediately instead of silently staying on the fallback language until a later reload.

## Context

- `dashboard/src/common/components/user-nav.tsx:96-98` — `handleLanguage` calls `persistLanguage(lang)` then `void i18n.changeLanguage(lang)` with no `ensureLanguage` await. This is the only one of 4 real `changeLanguage(` call sites in `dashboard/src` missing it (exhaustive grep, excluding tests/comments):
  - `dashboard/src/features/i18n/language-switcher.tsx:29` — `void ensureLanguage(lang).then(() => i18n.changeLanguage(lang));` (correct shape to match)
  - `dashboard/src/routes/__root.tsx:34-35` — `await ensureLanguage(language); await i18n.changeLanguage(language);`
  - `dashboard/src/i18n/use-language-hydration-sync.ts:29-31` — same await shape
  - `dashboard/src/common/components/user-nav.tsx:98` — missing (this task's fix)
- `dashboard/src/i18n/init.ts:31-38`'s `ensureLanguage(lang)` registers the lazy-loaded, non-default locale's catalog via `addResourceBundle` before it's safe to switch to — its own doc comment: "Callers must `await` this before `changeLanguage(lang)` (w9/m60 t003) so the UI never renders raw keys."
- Live-reproduced impact: clicking 中文 in the account menu leaves the page fully in English immediately after the click (only a later hard reload — which re-runs `__root.tsx`'s own correct `ensureLanguage`+`changeLanguage` pair from a fresh module state — actually shows Chinese).

## Steps

1. In `user-nav.tsx`, change `handleLanguage` to await `ensureLanguage(lang)` before calling `i18n.changeLanguage(lang)`, matching `language-switcher.tsx`'s shape (`void ensureLanguage(lang).then(() => i18n.changeLanguage(lang))` or an `async`/`await` equivalent — match whichever pattern reads better against the existing `onClick={() => handleLanguage(lang)}` call site at line 208).
2. Import `ensureLanguage` from `@/i18n/init` in `user-nav.tsx` (already imported in `language-switcher.tsx` — same import path).
3. Manually verify locally: switch language via the account menu without reloading, confirm the visible UI updates on the same interaction (no full navigation needed).
