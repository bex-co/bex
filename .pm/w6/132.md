# A disk meter pass cut off mid-window leaves that window's remaining disks unmetered for good

Why: provisioned disk is billed from these rows. Every pass a rollout or an upsert error cuts off is unbilled disk on the invoice, and 49 h later it is a `disk` degraded caveat on the workspace's Billing page for the rest of the month. Render bills provisioned disk capacity for all of its lifetime (ADR082 D8) and shows no such caveat.

- **Seen:** 2026-11-17, production, read-only (w6/m333 t008).
  - Window 2026-11-17 02:00Z has disk rows for 4 of the 7 live disks. In `bex` (`tea-d98210cbbpdc73dcrkvg`), `srv-d9nqg9dcavls73fp8m2g` (10 GB), `srv-dbko6q88rods73dicapg` (15 GB) and `srv-dbko6rg8rods73dicarg` (1 GB) have rows at 00:00Z and 01:00Z but none at 02:00Z. Their disks and size periods are live and unchanged.
  - Their `disk_gb_seconds` streams are still open. A pass that finished would have closed them in `CloseIdleUsageSourceStreams`, because they were not metered, so the pass that wrote window 02:00Z (at about 03:43Z) never reached its end. bex-api rolled out three times between 02:49Z and 03:48Z.
  - The two `srv-dbko6…` disks also have a hole at 2026-11-08 13:00Z.
- **Cause:** `usage.meterDiskWindow` (`lego/backend/internal/usage/service.go`) upserts one `usage_hourly` row per disk outside a transaction, then runs the idle close. `catchUpDisksThrough` resumes from `store.LatestUsageWindowForKind`, which is `MAX(window_start)` over every disk row. Once any row of a window exists, the next pass starts at the following window, so the disks a cut-off pass had not reached are never metered for that window. The loop's "stop at the first failure so the gap is retried oldest-first" holds only for a failure before the window's first row. An upsert error mid-window skips the rest the same way.
- **Effect:** 26 GB-hours (93,600 GB-seconds) unbilled in window 2026-11-17 02:00Z alone. The 2026-11-08 holes already read `disk` degraded in `bex`'s November coverage.
- **Fix direction:** write a window's disk rows, their health and the idle close in one transaction, so a cut-off pass writes nothing and the next pass retries the window. A per-disk cursor is the other option.
- **Backfill:** the meter is idempotent over committed size periods. Re-metering 2026-11-17 02:00Z fills the three holes while that window is inside the 48 h rewrite window, until about 2026-11-19 02:00Z. 2026-11-08 13:00Z is already past it.
- **Done when:** a test cuts a disk pass off between two rows (or fails one upsert mid-window), and the next pass meters every disk for that window. The 2026-11-17 02:00Z holes are filled if the fix lands in time, or recorded as an accepted undercount if it does not. ~1h.
