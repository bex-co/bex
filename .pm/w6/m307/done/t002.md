## Objective

The duration starts at the Job's `startTime`, which the Job controller sets before the pod is scheduled, so the tenant pays for the platform's wait for a build node. The operator already sees the placement moment (it feeds `bex_build_queue_seconds`). Stamp it on the Job and let usage start the clock there.

## Context

- `lego/operator/internal/controller/build_metrics.go:224` (`buildQueueSeconds.Observe(sig.QueueSeconds)`)
- `lego/backend/internal/usage/service.go:1601-1606` (`ct.Sub(job.Status.StartTime.Time)`)
- label/annotation constants: `lego/types/v1alpha1/jobnames.go`

## Steps

1. Add an annotation constant in `lego/types` (for example `app.bex.co/build-pod-started-at`) and have the operator write it once, at the first observed placement.
2. Usage uses the annotation when present and falls back to `startTime` (Jobs from before the change).
3. Tests on both paths, and on an annotation later than completion (ignored).

## Files

- lego/types/v1alpha1/jobnames.go

- lego/backend/internal/usage/service.go

## Acceptance criteria

- [ ] Old Jobs without the annotation meter as before
