## Objective

A `Recreate` rollout prefers the node the volume is attached to, so the volume does not move and the image is already local.

## Context

- `lego/operator/internal/controller/disk.go:96-107` (the `Recreate` projection), the App's PVC and its `VolumeAttachment` (or the running pod's `spec.nodeName`).
- Hetzner volumes are bound to a location, not a node, so the scheduler may pick any node there today.

## Steps

1. Project a `preferredDuringSchedulingIgnoredDuringExecution` node affinity for the current node onto the pod template of a disk-bearing App; leave it out when no node is known yet (first deploy).
2. Do not let the hint churn the template on every reconcile (changing it would itself roll the pod); update it only when the rollout is already rolling.
3. Fall back when the node is cordoned, draining or out of room (a preference, never a requirement).
4. Tests for each case.

## Files

- lego/operator/internal/controller/disk.go and tests

## Acceptance criteria

- [ ] A disk-bearing App's next pod prefers its volume's node; a cordoned node is skipped
- [ ] A reconcile without a rollout does not change the pod template
- [ ] `make test` and `make lint` pass

## Out of scope

- Moving a volume on purpose
