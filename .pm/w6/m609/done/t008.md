## Objective

Cover the saved plan where it meets the work already shipped around save-only writes.

## Steps

1. A REST plan PATCH made within seconds of a dashboard Settings deploy waits for that deploy's adoption (`rollout.AwaitAdoptionBeforeHold`, w6/163), and the plan stays pending behind it.
2. After an `imageUrl` deploy, a saved plan and the deploy that applies it keep serving the deploy's image (`keepSelectedImage`, w6/159).
3. A saved plan on a suspended service stays saved through Resume. A Restart or rollback applies it (t002, 2026-11-23: Render calls a restart "a special form of manual deploy"), which the operator envtest already covers for Restart; cover rollback.
4. A dry-run plan PATCH still previews the saved plan and writes nothing.

## Acceptance criteria

- [x] Each test fails with its behavior reverted.
- [x] `cd lego/backend && go test ./...` and `make test` pass.

## Done (2026-11-24)

- **Step 1:** `TestAnUpdateServiceSaveWaitsForTheDeployAheadToBeAdopted` (`lego/backend/internal/apps/push_wait_test.go`) gains a `plan` case: a REST/MCP plan PATCH behind an unadopted settings deploy writes only after release 3 is adopted, keeps release 3 stamped, saves `spec.tier`, and stays pending at 4 with no deploy row. Fails with the plan row deploying at once (the pre-m609 behavior): release 4 stamped and one deploy row.
- **Step 2:** `TestTheDeployThatAppliesASavedPlanKeepsTheOverridesImage` (`plan_image_override_test.go`): after an `imageUrl` deploy, a saved Standard plan and the dashboard Settings deploy that applies it release Standard on the override's digest (`settings_change` row on that digest), and the saved image stays the created tag. Fails with `keepSelectedImage` disabled (the release falls back to the override's old selection).
- **Step 3:** operator envtest "keeps a saved plan through Suspend and Resume, and a rollback applies it (w6/m609)" (`save_only_settings_envtest_test.go`): Standard saved while suspended keeps the resumed pods on Starter with `status.servedTier: starter` and `undeployedChanges: true`; a rollback to generation 1 runs its image on Standard and moves `servedTier` to `standard`. Fails with `pendingReleaseView` disabled (the resume rolls Standard) and with a rollback that keeps its target's plan.
- **Step 4:** `TestRESTDryRunPlanPreviewsTheSaveAndWritesNothing` (`dryrun_test.go`) replaces the weaker `TestRESTDryRunPatchServicePlan`: the dry run answers `serviceDetails.plan: standard` and leaves the App's spec, annotations and resourceVersion, the store and the audit log untouched (no `plan_changed`). Fails when the dry run applies the patch.
