## Objective

Confirm, and fold into t001/t002's scope, that this milestone's root-cause pattern — an App CR spec patch that forces the operator to rebuild/redeploy without ever going through `triggerDeploy` / the `deploys` package — is not confined to `lego/backend/internal/apps/service.go`'s `SetXxx` family. It recurs in at least one other package, and the fix (t002) must not be scoped narrowly enough to miss it.

## Context

- **Live-confirmed this run (2026-08-24, workspace `bex`):** created a fresh `qa-20260824-envprec` web service with a direct env var `MYVAR=direct_value`, deployed it to `Live` (`dep-da6bi90bjjms73fvga40`), then created an Environment Group `qa-20260824-envgroup` with `MYVAR=group_value` and linked it to the service **at group-creation time** (the "Linked Services" picker in the create-group dialog). Immediately after creation, `service.phase` (GraphQL) transitioned `Running` → `Building` → `Running` and the service detail page's `Revision` field bumped `rev-1` → `rev-2` — but `deploys(serviceId: ...)` never gained a second row; it stayed at the original single `dep-da6bi90bjjms73fvga40` throughout. Same missing-tracking shape as `SetCommands` et al., via a completely different mutation.
- **Root cause, precisely located:** `lego/backend/internal/envgroups/service.go:947-957` (`linkFetched`, the shared body of both `LinkService` — the dashboard/API path — and `LinkEnvGroup` — the Blueprint-apply path) does:
  ```go
  base := client.MergeFrom(a.DeepCopy())
  a.Spec.EnvFromSecrets = addString(a.Spec.EnvFromSecrets, envSecretName(gid))
  a.Spec.FilesFromSecrets = addString(a.Spec.FilesFromSecrets, filesSecretName(gid))
  ```

## Findings (2026-08-24)

`linkFetched`/`detachFetched` confirmed build-relevant: they write `EnvFromSecrets` + `FilesFromSecrets` (both `identityRelease`) and `RestartedAt` (`identityArtifact|identityRelease`). Any one of the three rolls a new release; all three together certainly do.

The fix is shared, not per-package: `lego/backend/internal/rollout` holds the one `Tracker.Patch` seam (snapshot → mutate → stamp release generation → merge-patch → open row), and `apps`, `envgroups`, and `secrets` all write through it. `envgroups` and `secrets` gained a `Rollout *rollout.Tracker` field wired from `internal/api/server.go`; `apps` derives its tracker from the `IntentStore` it already holds, so a second composition root cannot silently build an untracked Service.

Live-verifying `detachFetched` end to end needs the fix deployed; `TestEnvGroupWritesOpenDeployHistory` covers link, group-value change, and unlink (plus the idempotent re-link that must open nothing).
