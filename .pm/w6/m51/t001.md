## Objective

Determine precisely which `App.Spec`-patching `Service.SetXxx` verbs actually cause the operator to rebuild/redeploy without ever calling the `deploys` package's create-deploy path — the exact set the fix in t002 must cover, no more and no less.

## Context

- `lego/backend/internal/apps/service.go` has ~23 `SetXxx` verbs (grep `func (s \*Service) Set`); each ends in `s.patchFetched(ctx, a, func(a *appv1alpha1.App) { ... })` which patches the App CR spec and returns — none call `triggerDeploy` / the `deploys` package.
- `dashboard/src/features/services/components/manual-deploy-button.tsx:31-32` states "any spec change increments the generation and unconditionally re-enters the build path" — written in the context of the Restart action specifically; confirm whether this is literally true for every `App.Spec` field or only build-relevant ones (repo/branch/image, commands, root dir, runtime, dockerfile path) by reading the operator's reconcile diff logic, not by re-deriving it from this comment alone.
- Live-confirmed this run: `SetCommands`'s `startCommand` half (`service.go:3137-3160`) does force a real rebuild (build logs showed a genuine `go build`/image-push cycle) with zero `deploys` row created.
- Candidate build-relevant verbs by field shape (not yet independently live-verified): `SetRootDir` (`:3034`), `SetDockerfilePath` (`:3060`), `SetPreDeployCommand` (`:3116`) — note: a Pre-Deploy Command change may or may not require an image rebuild, verify — `SetSourceAndRegistryCredential` (`:3189`, repo/branch/image change).
- Candidate non-build verbs (should NOT need this fix, confirm they genuinely don't rebuild): `SetPlan`, `SetIdleTTL`, `SetDisplayName`, `SetAutoDeploy`, `SetNotifyOnFail`/`SetNotificationsToSend`, `SetIPAllowList`, `SetMaintenanceMode`, `SetHealthCheckPath`, `SetMaxShutdownDelay`, `SetSubdomainPolicy`, `SetAutoscaling`, static-site-only `SetRoutes`/`SetHeaders`/`SetPublishPath`.

## Steps

1. Read the operator's App reconcile loop (`lego/operator/internal/controller/app_controller.go`, around the `PhaseBuilding`/`reasonBuilding` lines found this run at `:658-832`) to find the actual spec-diff check that decides whether a resync triggers a rebuild vs. a cheap in-place update.
2. For each candidate verb above, trace whether the field it patches is part of that diff check.
3. Live-verify at least the two or three highest-risk cases (e.g. `SetRootDir`, `SetSourceAndRegistryCredential`) on a `qa-<yyyymmdd>-` test service the same way this run verified `SetCommands`: change the field via Settings, immediately query `deploys(serviceId:)` before/after, confirm whether a rebuild actually happens (build logs / phase transition) with no new deploy row.
4. Produce the final, confirmed list this milestone's fix (t002) must cover.
