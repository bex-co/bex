## Objective

`use-create-api-key.ts` and `use-create-registry-credential.ts` share the same bare-`catch {}` shape as the confirmed-broken hooks, but a grep of `lego/backend/internal/apikeys/` and `lego/backend/internal/registrycreds/` found **no** `ErrConflict`/uniqueness handling at all — unlike projects/environments, there isn't even circumstantial evidence these two resource types enforce workspace-unique names. Determine that first; a bare `catch {}` swallowing a conflict message that never exists is not a bug worth fixing.

## Context

- `dashboard/src/features/api-keys/hooks/use-create-api-key.ts:39,53-54` and `dashboard/src/features/registry-credentials/hooks/use-create-registry-credential.ts:52-53` both use unconditional `toast.error(t("<type>.createError", ...))` on any failure, with no message extraction.
- API keys are commonly not name-unique in comparable products (multiple keys can share a display label, distinguished by id/prefix instead) — this is a real possibility, not just an oversight, and would mean there is nothing to fix here.
- Registry credentials (container registry auth) may or may not enforce unique names per registry host — unconfirmed.

## Steps

1. Sign in to the live QA workspace. Create an API key named `qa-20260823-dup`, then attempt to create a second API key with the identical name. Record the exact result (succeeds twice with distinct ids? rejected? something else?).
2. Do the same for a registry credential named `qa-20260823-dup` (a fake/placeholder registry host and dummy credentials are fine — do not use a real credential; this is only testing name-uniqueness enforcement, not connectivity, and nothing should be submitted that could reach a real registry).
3. If either genuinely enforces uniqueness and returns a specific conflict message: wire t001's shared conflict-detection helper into that hook, mirroring t002-t005.
4. If neither enforces uniqueness: mark this task done with "not applicable — confirmed no uniqueness constraint" and the exact live evidence (both create attempts' responses) recorded in the completion notes. Do not invent a constraint that doesn't exist.
5. Clean up all `qa-`-prefixed resources created for this check (delete both API keys / registry credentials regardless of outcome).
