## Objective

Projects' create hook doesn't extract the GraphQL error message at all — every failure gets the same generic toast. Fix that, and separately confirm whether the backend's project-conflict message (which today omits the attempted name entirely) needs to be improved for the surfaced text to be genuinely useful.

## Context

- Live-confirmed today: creating `qa-20260823-projdup` twice (via `createProject(name: $name, ownerId: $ownerId)`) → second call's GraphQL response: `{"data":{"createProject":null},"errors":[{"message":"conflict: project: already exists","path":["createProject"]}]}`. Note this message does **not** repeat the attempted name, unlike keyvalue/postgres's messages — it comes from the generic `store.ErrConflict` path (`lego/backend/internal/store/store.go:56`: `errors.New("already exists")`), not a hand-authored per-type message.
- `dashboard/src/features/projects/hooks/use-create-project.ts:28,41`:
  ```
  toast.error(t("projects.createError", { name }));
  ...
  } catch {
    toast.error(t("projects.createError", { name }));
  }
  ```
  Note the bare `catch {}` — no error variable is even bound, so there is nothing to branch on yet.

## Steps

1. Change `catch {}` to `catch (err) {}` and wire t001's shared conflict-detection helper.
2. Decide: is "conflict: project: already exists" (or a cleaned-up version of it, stripping the "conflict:" transport prefix the way `refusalReason()` in `graphql-error.ts` already does for other flows) specific enough to show the user as-is, given the create form already has the attempted name visible in the input field the user just typed into? Or does the backend message genuinely need the name added for the frontend fix alone to be sufficient UX? Record the decision — if the backend message needs a name, find where `store.ErrConflict` gets wrapped for the project create path (`lego/backend/internal/projects/`) and add it there, consistent with how keyvalue/postgres already include the name in their hand-authored messages.
3. Surface the (possibly-improved) message inline or via a specific toast.
4. Reproduce live: create a project, then attempt the same name again from the UI, confirm the improved message is shown.
5. Clean up any `qa-`-prefixed resources created for this check.
