## Objective

On the local CAPD cluster, with an operator built from this tree, show that a roll of each SNI DaemonSet caused by a binary change:

- lets an external TLS client mid-command get its reply: a Key Value `BLPOP` through `kv-sni-proxy` and a Postgres `SELECT pg_sleep(…)` through `pg-sni-proxy`;
- keeps new external clients connecting throughout the roll;
- closes a held idle client no earlier than the chosen bound.

## Context

- `bash scripts/mock-cluster.sh operator` builds and deploys the tree. w6/m512 t005 (`.pm/w6/done/m512/done/t005.md`) forced a binary change with a throwaway log line and distinct image tags (`BEX_OPERATOR_IMG=bex-operator:m515-<x>`). Reuse its method, and never commit the throwaway line.
- The local cluster has no `bex-*-sni-proxy-public` NodePort, because that is in `config/prod`. Drive the clients the way production does: through a NodePort with `externalTrafficPolicy: Local` shaped like production's, applied for the proof or moved into the base if the local edge needs it anyway. Record which.
- Clients with no PROXY header keep their socket source (ADR021 § 3), so each probe's IP allowlist must admit the client's address.
- External Key Value is TLS with SNI `<id>.kv.bex.co`. Postgres is `sslmode=require` with SNI `<id>.db.bex.co` (libpq sends SNI by default). Each needs the store or database to be public.
- Use dev-6's tenant namespace (`.pm/w6/README.md` § Local dev environment). The local cluster is shared: leave other workstreams' objects alone, and leave the operator on a build of this tree.

## Steps

1. Create a public free Key Value store and a public free Postgres database. Hold one `BLPOP` client and one idle client on the store, and one `pg_sleep` client and one idle `psql` session on the database. Start a loop that opens a new connection to each every second and logs the result with timestamps.
2. Deploy a build whose SNI binaries differ. Record each pod's `SIGTERM` time, the `BLPOP` reply (pushed from another client after `SIGTERM`), the `pg_sleep` result, when each idle client was closed, and every failure in the new-connection loop.
3. Delete the probes and client pods.

- [ ] No new connection failed during either roll.
- [ ] Each idle client closed at the bound, not before.
- [ ] No probe is left on the cluster.

## Result (2026-11-19, local CAPD cluster; the code shipped once w6/m470 closed)

**Setup.**

- **Builds.** `bex-operator:m515-a` was this tree plus a throwaway `Info` line in both SNI mains, reverted after the build and never committed. `bex-operator:m515-b` is the clean tree. Their `/kv-sni-proxy` and `/pg-sni-proxy` hashes differ (`66ed8c5c…` and `ebccfa0c…` against `a78e34fe…` and `e6979cde…`).
  - `BEX_OPERATOR_IMG=bex-operator:m515-a bash scripts/mock-cluster.sh operator` deployed A.
  - Each measured roll was then a plain `kubectl set image` on both DaemonSets, one roll each, as a production pin moves them.
- **The probes**, in dev-6's tenant namespace `tea-dbtf3l1jg4ra1r0m4ur0`: the public free KeyValue `red-m515probe` and the public free Database `dpg-m515probe` (Postgres 16), each with allowlist `0.0.0.0/0`.
  - The store's public certificate cannot issue locally (`letsencrypt-prod`), so Valkey had no TLS port. A self-signed `red-m515probe-kv-tls` Secret stood in, and clients used `--insecure`.
- **The edge.** The two `config/prod` NodePorts (`externalTrafficPolicy: Local`, 31892 and 31056) were applied for the proof only, labelled `bex.co/probe=m515`. The local cluster needs no NodePort otherwise, so nothing moved into the base.
- **The clients** were Docker containers on the CAPD `kind` network, outside the cluster, dialling the platform node `172.22.0.5`. Their source address is preserved, and no PROXY header is sent.
  - `valkey-cli 8.1 --tls --sni red-m515probe.kv.bex.co`, and `psql 17` with `sslmode=require` and `host=dpg-m515probe.db.bex.co`.
  - Held: a `BLPOP m515 0`, a `SUBSCRIBE`, an idle `psql` session (its socket state read from `/proc/net/tcp`), and a `pg_sleep(25)` started 1 s before the roll.
  - Two loops opened a new connection about every 0.6 s each (`PING`, `SELECT 1`).

**Run 1 (no `preStop` pause yet), roll B at 13:29:13Z.**

- The old pods got `SIGTERM` at 13:29:21Z.
- `pg_sleep(20)` returned through the old pod at 13:29:33.7Z.
- The held clients closed at 13:29:51.3Z, at +30 s.
- One new Postgres client was **refused** at 13:29:21.375Z: kube-proxy still sent connections to the old pod after its listener closed. That led to t003's 5 s pause.
- (The run's `RPUSH` came late through a script error, so its `BLPOP` was closed at the bound unanswered.)

**Run 2 (the shipped shape: pause 5 s, bound 30 s, grace 40 s), B → A by `set image` at 13:38:07.7Z:**

| time (Z) | event |
| --- | --- |
| 13:38:16 | both new pods Ready |
| 13:38:17 | both old pods deleted (`Killing`; `deletionTimestamp` 13:38:57 minus the 40 s grace); the `preStop` pause starts |
| ≈13:38:22 | `SIGTERM` to both old pods, after the pause |
| 13:38:26.868 | `RPUSH m515 v` through a new client, so through the new pod |
| 13:38:26.922 | **the `BLPOP` client read `m515 v` through the old pod**, about 4.9 s after its `SIGTERM` |
| 13:38:34.480 | **`pg_sleep(25)` (started 13:38:06.5) returned its result through the old pod**, about 12.5 s after its `SIGTERM` |
| 13:38:52.167 | **the `SUBSCRIBE` client read "Server closed the connection", and the idle `psql` socket went to `CLOSE_WAIT`**, about 30.2 s after `SIGTERM`: at the bound, not before |
| 13:38:52 | the old pods exit (their readiness probe then reads "connection refused") |

- **New connections.** No failure in either loop during the roll. 175 `PING`s and 154 `SELECT 1`s ran, about 90 of each from 13:38:07 to 13:39:00. The widest gap across the deletion and `SIGTERM` was 0.78 s.
  - One `SELECT 1` took 5.6 s, from 13:38:03.8 to 13:38:09.45, before any new pod existed. Two connections stalled the same way in run 1, at 13:29:00 and 13:29:03, with no roll in progress. Each stall coincided with a client container starting on the `kind` network, so it is the Docker network, not the proxy.
- **Cleanup.** All probe containers, both probes (CNPG's PVC and Valkey's included), the self-signed Secret and both NodePorts are deleted. Nothing labelled `bex.co/probe=m515` is left, and the copied credentials are removed from `/tmp`.
  - The scratch DaemonSet `m515-surge-probe` (t003) is deleted.
  - The KeyValue's `kv-tls-cleanup` finalizer first refused the hand-made Secret ("refusing foreign or unproven KeyValue TLS Secret"). After the Secret was deleted, it finished.
- **The operator is left on `bex-operator:m515-b`**, this milestone's code (`BEX_OPERATOR_IMG=bex-operator:m515-b bash scripts/mock-cluster.sh operator`), so both SNI proxies now run on the local cluster. A deploy from `main` would bring the `hostPort` back, and PodSecurity would refuse the pods again.

**Acceptance.** `BLPOP` and `pg_sleep` read their results after `SIGTERM` (met). No new connection failed during the run-2 roll (met). The idle clients closed at the bound (met). No probe is left (met).
