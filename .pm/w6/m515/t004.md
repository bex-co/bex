## Objective

On the local CAPD cluster, with an operator built from this tree, show that a roll of each SNI DaemonSet caused by a binary change:

- lets an external TLS client mid-command get its reply: a Key Value `BLPOP` through `kv-sni-proxy` and a Postgres `SELECT pg_sleep(…)` through `pg-sni-proxy`;
- keeps new external clients connecting throughout the roll;
- closes a held idle client no earlier than the chosen bound.

## Context

- `bash scripts/mock-cluster.sh operator` builds and deploys the tree. w6/m512 t005 (`.pm/w6/blocked/m512/done/t005.md`) forced a binary change with a throwaway log line and distinct image tags (`BEX_OPERATOR_IMG=bex-operator:m515-<x>`). Reuse its method, and never commit the throwaway line.
- The local cluster has no `bex-*-sni-proxy-public` NodePort, because that is in `config/prod`. Drive the clients the way production does: through a NodePort with `externalTrafficPolicy: Local` shaped like production's, applied for the proof or moved into the base if the local edge needs it anyway. Record which.
- Clients with no PROXY header keep their socket source (ADR021 § 3), so each probe's IP allowlist must admit the client's address.
- External Key Value is TLS with SNI `<id>.kv.bex.co`. Postgres is `sslmode=require` with SNI `<id>.db.bex.co` (libpq sends SNI by default). Each needs the store or database to be public.
- Use dev-6's tenant namespace (`.pm/w6/README.md` § Local dev environment). The local cluster is shared: leave other workstreams' objects alone, and leave the operator on a build of this tree.

## Steps

1. Create a public free Key Value store and a public free Postgres database. Hold one `BLPOP` client and one idle client on the store, and one `pg_sleep` client and one idle `psql` session on the database. Start a loop that opens a new connection to each every second and logs the result with timestamps.
2. Deploy a build whose SNI binaries differ. Record each pod's `SIGTERM` time, the `BLPOP` reply (pushed from another client after `SIGTERM`), the `pg_sleep` result, when each idle client was closed, and every failure in the new-connection loop.
3. Delete the probes and client pods.
