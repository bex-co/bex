## Objective

`cmd/kv-sni-proxy` and `cmd/pg-sni-proxy` drain on their first `SIGTERM` or `SIGINT` for a bound read from the environment, then exit as soon as no stream is open. A second signal closes everything at once. With the variable unset or `0`, they close at once, as today. A malformed value refuses to start.

## Context

- Both mains build their context from `ctrl.SetupSignalHandler()`, which cancels on the first signal and exits the process on the second. The manager stops with that context, and the listener is closed from the same goroutine.
- Env names follow each proxy's prefix: `BEX_KV_PROXY_*` for `kv-sni-proxy`, `BEX_PROXY_*` for `pg-sni-proxy` (`lego/operator/AGENTS.md`). For example `BEX_KV_PROXY_DRAIN_SECONDS` and `BEX_PROXY_DRAIN_SECONDS`, whole seconds as `BEX_KV_DRAIN_SECONDS` (w6/m512).
- `sniproxy.EnvDuration` and `EnvInt` log and fall back on a bad value. A drain bound should fail closed instead, as `kv-internal-proxy`'s `drainSeconds` does.
- Keep the metrics listener up while draining, so the old pod's relayed bytes are still scraped.

## Steps

1. Parse the drain bound in each main, failing startup on a negative or non-numeric value.
2. On the first signal, close the listener and start t001's drain. On the second, close everything. Exit when the drain returns.
3. If the manager exits on its own (no signal), keep today's behavior.
