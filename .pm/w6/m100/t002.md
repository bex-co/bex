## Objective

t001 fixes the operator-side generation mis-attribution. This task proves the fix end to end: the live-shaped repro from this hunt, the w2/m82 anti-regression, the backend's `supersededDeployStatus` consumer actually promoting a queued row once the operator advances `ReleaseGeneration` (today only tested/observed to wait forever), and at least one more call site beyond "manual deploy" that shares the identical `patchApp`/`stampReleaseGeneration` race shape.

## Context

- This hunt's exact live repro (see `.pm/w6/m100/README.md` Background) used `deploys.Service.triggerFetched` (manual "Deploy latest commit") for both the first and second deploy. `Rollback` (`lego/backend/internal/deploys/service.go:704-755`, stamp at line 742) shares the identical `patchApp`/`stampReleaseGeneration` shape and is the cheapest second call site to add coverage for.
- `lego/backend/internal/store/reconciler.go:1036-1089` (`supersededDeployStatus`) and its `OverlapPending` branch at 1058-1060 is the backend function that must correctly promote a queued row once `appReleaseGeneration(app)` (line ~1104-1109) actually advances post-fix. Find its existing test file (likely `lego/backend/internal/store/reconciler_test.go` or similar) and check whether it currently only asserts the "waits forever" half.
- `lego/backend/internal/store/store.go:1739-1772` (`prepareDeployCreate`) is where `OverlapPending`/`DeployQueued` get set on create — useful for constructing the test fixture's queued row.

## Steps
