## Objective

Design the `Project` (groups N services within a workspace) and `Environment` (a named subset of a project's services, e.g. staging/production) resources — control-plane Postgres tables, mirroring the workspace-lifecycle design shape `w6/m1` already established.

## Context

- `w6/m1` (`.pm/w6/done/m1/README.md`) — the workspace model & lifecycle-verbs design this should mirror in approach (tenant-scoped tables, verb-driven mutations, no parallel store).
- Render's `/projects` + `/environments` API (api-docs.render.com) — the target shape to mirror field-for-field where sensible.
- `docs/ADR003-control-plane.md` — the control-plane Postgres store this composes with, no parallel store.

## Steps

1. Decide the `Project` table shape: id, workspace (tenant) scope, name, timestamps.
2. Decide the `Environment` table shape: id, project scope, name, timestamps.
3. Decide the `service_environment` join shape: which existing `apps` rows can belong to which environment (one service, at most one environment, per Render's model — confirm this constraint against Render's docs).
4. Document the decision (feeds t002's migration).
