# 190 — A Blueprint lists a service whose name is longer than 30 characters by a shortened slug, not by its name

Why: `GET /v1/blueprints/{id}` answers `resources[].name` `wrapped-for-linkedin-sc-74a57f` for the service the file and `GET /v1/services/{id}` both call `wrapped-for-linkedin-screenshots`. A client that matches a Blueprint's resources to its `render.yaml` by name, as `scripts/render-examples-live.sh` did, cannot find the service.

- **Source:** w6/m653 t003 (2026-11-26), the live run of the 49 remaining no-value `render-examples` templates ([render-examples-live.md](../../docs/render-artifacts/render-examples-live.md)).
- **Seen** on production pin `9b91284a4a2e`, in `bex-canary`, with `scripts/render-examples-live.sh wrapped-for-linkedin`. The Blueprint (render-examples/wrapped-for-linkedin) declares the web service `wrapped-for-linkedin-screenshots` (32 characters). Its detail listed `{"type": "web_service", "name": "wrapped-for-linkedin-sc-74a57f"}`, so the run failed at stage `check` with "the Blueprint created no resource named wrapped-for-linkedin-screenshots". The service itself answered `name: wrapped-for-linkedin-screenshots`. The same shortening named `gitpod-openvscode-server-example` `gitpod-openvscode-serve-6f07e2` in that run's result line. The fixtures were deleted by ID (404). The script now falls back to each service's own name, so the template's checks run.
- **Where:** `resolveBlueprintResourcesFromIR` (`lego/backend/internal/apps/blueprint.go`) reports each service as `Name: resource.Name`, the normalized resource slug. `capResourceSlug` (`blueprint_names.go`) shortens a slug past `MaxResourceNameLength` (30) to its start plus a 6-hex hash, while the service keeps its full name as its label (`serviceNameLabel`). w6/m114 fixed the same confusion in the exporter, and w6/m125 in the planner (`appServiceName`).
- **Render:** `resources[]` items are `{id, name, type}` (Render's public OpenAPI, `GET /blueprints/{blueprintId}`), and the name is the resource's name, as the dashboard's Blueprint page shows it.
- **Do:** every surface that lists a Blueprint's resources (REST detail, GraphQL, MCP `get_blueprint`, the dashboard's Blueprint page) names a service by its name, whatever its length.
- **Acceptance:**
  - [ ] A unit test: a Blueprint whose service name is longer than 30 characters lists that name in its resources.
  - [ ] On production, `GET /v1/blueprints/{id}` for a fixture with a long service name lists the full name, and REST, GraphQL and MCP agree.
- **Estimate:** ~45m, with a Render parity check across the four surfaces.
