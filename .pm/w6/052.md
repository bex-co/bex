# 052 — "External host" renders a blank value on Postgres and Key Value detail pages: `?? "—"` over a backend that returns `""`

Why: a labelled row with no value at all reads as a loading failure, and the codebase's own placeholder and its own row-omission pattern both sit two lines away.

## What's wrong

`dashboard/src/routes/databases.$databaseId.tsx:369-372`:

```tsx
{
  label: t("databases.metaExternalHost"),
  value: database.externalHost ?? "—",
},
```

and the identical shape at `dashboard/src/routes/keyvalue.$keyValueId.tsx:275-277`. `??` only catches `null`/`undefined`; the backend returns an **empty string** for a database with no public access, so the fallback never fires and the `<dd>` renders literally `""`.

Live capture (in-page authenticated `fetch`, 2026-08-27):

```
query { databases { id name public externalHost } }
=> all 3: { "public": false, "externalHost": "" }

query { keyValues { id name public externalHost } }
=> both:  { "public": false, "externalHost": "" }
```

DOM on `https://dashboard.bex.co/databases/dpg-d9nqg95cavls73fp8m20` — every other `<dd>` in the same `<dl>` has text; `External host` is `""`:

```
["Public access", "\"No\""]
["External host", "\"\""]
["Region", "\"fsn1\""]
```

Same on `https://dashboard.bex.co/keyvalue/red-d9p49kdrtmes73c34ovg`.

## The fix pattern already ships here

The very next entry in both files omits its row entirely when the value is absent:

```tsx
...(database.region ? [{ label: …, value: database.region }] : []),
```

So the decision is which of the two established patterns applies — a truthiness check feeding the `—` placeholder, or the conditional spread that drops the row when the resource has no public access at all. Render shows external connection details only when public access is on, which argues for the spread. Whichever is chosen, `??` is wrong here because the backend's contract for this field is empty-string, not null.

Both resource types move together; the two files are the entire blast radius for this field (`grep -rn 'externalHost ?? ' dashboard/src` → 2 hits, both above). `ha-panel.tsx:136` already uses a truthiness check (`r.connectionInfo.externalHost ? …`) for the replica variant of the same field — a third, correct precedent in the same feature.

## Repro

1. Open `https://dashboard.bex.co/databases/dpg-d9nqg95cavls73fp8m20` (any database with Public access = No).
2. In Details, read the row labelled **External host** — it has no value, not even the `—` the code intends.
3. Same on any Key Value detail page.
