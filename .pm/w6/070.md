# Mobile: consume the per-resource action projections instead of client lifecycle heuristics

Why: w6/m136 shipped `serverActions`/`deployActions`/`databaseActions`/`keyValueActions` (permission tri-state + blocking precondition per verb, computed by the execute paths' own predicates), but w6/m138's mobile gating combines workspace-level `viewerCapabilities` with the pre-existing client lifecycle heuristics (`serviceLifecycleCapabilities`, `isRollbackableDeployStatus`, suspended checks). Swapping those heuristics for the server projections would surface the preconditions the client cannot know (protected-environment confirmation requirements, billing dunning blocks, server-side rollback eligibility) as disabled-with-reason controls instead of tap-time errors, and removes a parallel eligibility implementation that can drift from enforcement. Scope: add the four codegen'd queries + scope-allowlist entries, map `core.Precond*` codes onto translated reasons (unknown code → generic blocked, fail closed), and delete the client-side predicates the projections replace. ADR087 §Required contract work item 3 is the contract; the mobile consumption is the remaining half.
