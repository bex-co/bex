## Objective

When `App.Spec.Builder == "buildpack"`, dispatch a real kpack build instead of hard-erroring, mirroring the shape of the existing BuildKit Job dispatch.

## Context

- `lego/operator/internal/build/build.go:164` currently hard-errors: `"build: buildpack (CNB) builds are not yet supported in-cluster — add a Dockerfile or wait for kpack (w1/m5 follow-up)"`.
- Package doc at `build.go:24-27` explains why this exists (no k8s-native builder deployed yet — now addressed by `w6/m22/t001`).
- BuildKit dispatch (Job named `bld-<name>-gen-<generation>`) is the shape to mirror: `lego/operator/internal/build/build.go:216-264`.

## Steps

1. Replace the error branch with logic that creates a kpack `Image` CR (name `bld-<name>-gen-<generation>`, matching the BuildKit Job naming convention so `BEX_BUILD_NAMESPACE`/Cancel logic — `w2/m10` — keeps working) pointing at the repo/branch/rootDir.
2. Watch the kpack `Image`'s status for build completion; extract the resulting image digest on success, surface errors on failure (same status/observability contract as the BuildKit path).
3. Ensure the build namespace, registry push secret, and generation-based naming all match the existing BuildKit Job conventions so downstream code (Cancel, build status polling) doesn't need to special-case builder type.

## Files

- `lego/operator/internal/build/build.go`

## Acceptance criteria

- [ ] An App with `spec.builder: buildpack` triggers a kpack `Image`/`Build`, and a successful build results in the App reconciling to a running revision.
- [ ] Failure surfaces through the same status/error path as BuildKit failures.
- [ ] Existing Dockerfile/auto builder behavior is completely unchanged.

## Out of scope

- Build-time env var passthrough (t003).
