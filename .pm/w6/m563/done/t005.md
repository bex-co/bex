## Objective

Check that the idle setting and the close behave the same on REST, GraphQL, MCP and the dashboard (same field, semantics and error shapes), and compare with Devin's observable behavior. Flag any drift as follow-up work.

## Acceptance criteria

- [x] Each surface reads and writes the same value and refuses the same inputs with the same code.
- [x] Any difference from Devin beyond the one recorded in the README (automations close at once) is filed.

## Result (2026-11-22)

REST, GraphQL and MCP serve one `Environment`/`EnvironmentInput` field pair, `idleTimeoutMinutes` and `idleTimeoutConfigurable` (`TestEnvironmentSurfacesShareOneShape` holds GraphQL to the JSON fields), and refuse 4, 121 and a non-Enterprise write with the same codes on all three (`TestEnvironmentValidationErrorsOnEverySurface`, `TestTheIdleTimeoutIsEnterpriseOnly`); the dashboard and `bex agent env` read and write the same field. Against Devin: the default (5 minutes), the bounds (5–120) and the Enterprise-only setting match; Devin sets it through its account team while bex makes it an admin setting (an addition, not a restriction); child sessions close at the harvest like automations (the README's recorded divergence covers both, now in ADR018); Devin's 30-minute Windows/GPU row has no bex counterpart. Nothing else to file. Checked in code and tests before the production deploy; t004 is the live check.
