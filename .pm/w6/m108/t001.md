## Objective

Make `patchEnvironmentAuthorized`'s per-linked-service rollout loop tolerate `core.ErrNotFound` exactly the way `rollLinked` already does, so a since-deleted linked service never counts as a rollout failure.

## Context

- `lego/backend/internal/envgroups/patch.go:273-293` loops over `m.links` and, for each `serviceID`, calls `s.rollOne(ctx, serviceID, s.now())` (`SaveModeDeploy`) or `s.RebuildService(ctx, serviceID)` (`SaveModeRebuild`). Any non-nil `actionErr` — including `core.ErrNotFound` for a deleted service — is appended to `result.FailedServiceIDs`, and `result.RolledOut = len(result.FailedServiceIDs) == 0`.
- `lego/backend/internal/envgroups/service.go:1037-1046` (`rollLinked`) already implements the correct tolerance pattern for this exact scenario: `if errors.Is(err, core.ErrNotFound) { continue // a since-deleted linked service is skipped }`. `rollLinked` is dead code (never called) — do not just "start calling it"; either inline its tolerance into `patch.go`'s loop or refactor `patch.go` to reuse a shared helper, whichever keeps `RebuildService`'s error path (which is not itself a `rollOne` call) covered too.
- `s.RebuildService` is a func field (`lego/backend/internal/envgroups/service.go:78`), wired in production to `deploysSvc.Trigger` (`lego/backend/internal/api/server.go:726-729`) — confirm what error `Trigger` returns for a deleted service (should also be/wrap `core.ErrNotFound`; if it does not, that is a second gap to close in this same task, not a separate finding).
- Live-verified GraphQL repro (this hunt): a group with one linked, then-deleted service returns `{"rolledOut":false,"failedServiceIds":["srv-..."]}` from `patchEnvGroupEnvironment` with `saveMode:"deploy"`.

## Steps

1. Confirm `deploysSvc.Trigger`'s error for an unknown/deleted service id is `core.ErrNotFound` (or wraps it) — trace `lego/backend/internal/deploys/service.go`'s `Trigger`. If it returns something else, normalize it or add a second check.
2. In `patch.go`'s loop (~line 276-291), skip a service id whose action error is `core.ErrNotFound` for **both** the `rollOne` and `RebuildService` branches — do not append it to `FailedServiceIDs`.
3. Leave every other error path (a genuine, non-`NotFound` failure on an existing service) completely unchanged — it must still land in `FailedServiceIDs` and set `RolledOut=false`.

## Files

- `lego/backend/internal/envgroups/patch.go`
- `lego/backend/internal/envgroups/service.go` (reference `rollLinked`'s pattern; remove it only if genuinely folded in, not left orphaned)
- `lego/backend/internal/deploys/service.go` (only if `Trigger`'s not-found error needs normalizing)

## Acceptance criteria

- [ ] A `PatchEnvironment` call (`SaveModeDeploy`) whose only linked-service problem is a deleted service returns `rolledOut: true`, `failedServiceIds: []`.
- [ ] The same holds for `SaveModeRebuild`.
- [ ] `TestPatchEnvironmentReportsPartialRebuildForRolloutOnlyRetry` (`patch_test.go:216-247`) still passes unmodified — a genuine injected failure on an existing service is unaffected.
