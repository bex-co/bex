## Objective

The Events tab renders `events ∩ catalog`, so any event type the backend emits that the dashboard's catalog does not list is invisible — and, because the filter's option list is built from the same catalog, unselectable. Invert the default so the feed renders what the API returned, and the catalog decides only how a row is grouped and labelled.

## Context

- `dashboard/src/routes/services.$serviceId.events.tsx:82-84` — `useState<Set<string>>(() => new Set(SERVICE_EVENT_TYPES))`, the fail-closed default.
- `:106-108` — `const visibleEvents = events.filter((event) => selectedTypes.has(event.type ?? ""))`, the intersection.
- **The correct semantics already exist one file over.** `dashboard/src/features/events/lib/timeline.ts:20-41` is fail-open: `if (filter === "all") return true;`, and its last branch returns true for any type in neither `DEPLOY_TYPES` nor `LIFECYCLE_TYPES`. Match it; do not invent a third convention.
- The label layer is already fail-open too — `serviceEventLabelKey` (`service-event-catalog.ts:153-155`) returns `LABEL_KEYS[type] ?? "services.eventsTypeServiceChanged"`. So an uncatalogued row can already render with a sensible generic label; only visibility blocks it.
- `service-event-filter.tsx:87` builds select-all as `new Set(SERVICE_EVENT_TYPES)` and carries the identical assumption — it must move with this change or "select all" will re-hide exactly the rows this task reveals.

## Steps

1. Decide the filter's representation and write the decision down. Recommended: track **deselected** types (an exclusion set) rather than selected ones, so an unknown type is visible by default and needs no catalog entry to appear.
2. Apply it at `:106-108`, and update the select-all/tri-state logic in `service-event-filter.tsx` (`:52`, `:68`, `:87`) to agree.
3. State what an uncatalogued row renders as — generic label plus a neutral icon — and make sure `event-icon.tsx` has a fallback rather than rendering nothing.
4. Fix the count badge (`:122-126`) to count what the feed returned for the window, not the post-intersection subset.
5. Decide where an event with a missing/empty `type` lands, so the fix does not turn malformed rows into unlabelled noise.
