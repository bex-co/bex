## Objective

Cover the behaviour this milestone shipped: unknown types render, the five new types render and filter correctly, and select-all does not re-hide anything.

## Context

- `t003` is the structural drift guard (vocabulary ⊆ catalog). This task is the behavioural half — that the feed actually renders what it received.
- The existing filter test is self-referential (`service-event-filter.test.tsx:9` seeds from `SERVICE_EVENT_TYPES`); the new tests must not repeat that shape, or they will be equally blind.
- Interesting failure modes: an unknown type silently dropped; select-all excluding uncatalogued types; the count badge counting the intersection; an event with an empty `type`.

## Steps

1. Render the feed with a synthetic event whose type is in no catalog and assert it appears with the generic label.
2. Assert each of the five new types renders with its own label and is selectable.
3. Assert select-all keeps uncatalogued types visible.
4. Assert the count badge equals the feed's length for the window.
5. Assert an empty/missing `type` lands where `t001` decided.

## Files

- `dashboard/src/features/events/components/__tests__/`
- `dashboard/src/routes/__tests__/` if the route-level filter is tested there

## Acceptance criteria

- [ ] `cd dashboard && yarn test` passes.
- [ ] A test fails if the feed goes back to intersecting with the catalog.
- [ ] No test derives its notion of "all types" from the catalog it is meant to be checking.
