## Objective

Three guards already cover this feed and none crosses the Go/TypeScript boundary, which is why five types drifted in unnoticed. Add the missing one: a test that fails when the backend's emitted event vocabulary is not a subset of the dashboard catalog.

## Context

Why the existing guards cannot catch it:

- `scripts/events-verify.sh` — backend E2E against the CAPD cluster (correspondence, ordering, cursor, redaction), with a hardcoded type list at `:302`. It never opens the dashboard.
- `TestEventSurfaceParity` (`lego/backend/internal/api/events_surface_test.go:116`) — holds REST/GraphQL/MCP to one `Service.List`. All three are backend surfaces.
- `dashboard/src/features/events/components/__tests__/service-event-filter.test.tsx:9` — seeds from `SERVICE_EVENT_TYPES` itself, so its "all types" **is** the catalog. Structurally incapable of noticing the catalog is short.

**The vocabulary is split across two packages** — `plan_changed` is declared in `lego/backend/internal/eventvocab/datastore.go:25`, not in `internal/events/service.go`. A guard reading only `service.go` would miss that half and give false confidence. Cover both, or state explicitly which is canonical and why the other is out of scope.

Enumerate **from the Go source** (or from a generated artifact committed to the repo). A restated TypeScript list is the exact failure mode being fixed — it would just move the drift one file over.

## Steps

1. Decide the mechanism: parse the Go constants in a test, or add a codegen step emitting a JSON vocabulary the dashboard test imports. Prefer whichever the repo can run in `dashboard`'s vitest job without a Go toolchain — a committed generated artifact plus a backend test asserting it is current usually satisfies both.
2. Assert **backend ⊆ catalog**, not equality: the dashboard may legitimately know a type the backend has stopped emitting, and removing a backend type must not break the build.
3. Wire it into `dashboard/yarn test` (CI-enforced on `dashboard/**`).
4. Demonstrate it works: add a throwaway backend constant, watch the test go red, remove it.

## Files

- `dashboard/src/features/events/__tests__/` — the new guard
- `lego/backend/internal/events/service.go`, `lego/backend/internal/eventvocab/datastore.go` — the sources it reads
- a generated vocabulary artifact, if that mechanism is chosen

## Acceptance criteria

- [ ] Adding a type to either backend vocabulary package without cataloguing it fails `cd dashboard && yarn test` — demonstrated by doing it, not asserted.
- [ ] The guard enumerates from the Go source or a generated artifact; no hand-restated list of types exists in the test.
- [ ] Both `internal/events` and `internal/eventvocab` are covered, or the omission is justified in a comment.
- [ ] Removing a backend type does not fail the build.

## Out of scope

- Extending the guard to datastore/other event feeds beyond service events — note it as follow-up if the split vocabulary suggests it.
