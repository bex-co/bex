## Objective

Check that the spend and charge fields read the same on REST, GraphQL, MCP and the dashboard, and compare the experience with Devin's observable billing for agent sessions (render.com has no agent-model billing). File any drift as follow-up work.

## Found 2026-11-13 (t016 review)

- **Check that the dashboard's "reached" verdict matches the mint's.** `SpendStatus.Reached` now holds month-to-date spend against the workspace's own cap, and T0's ceiling against unbilled spend (the charge window, ADR091 D10.2a).
- **The dashboard composer still re-derives the verdict.** It works it out as month-to-date ≥ the effective cap (`dashboard/src/features/agent-environment/lib/spend.ts`, `blocksCreate`), so a T0 workspace whose cycle invoice billed part of the month can be blocked there while the mint would serve it.
- **Fix:** expose the verdict, for example `agentModelSpendCapReached` on REST, GraphQL and MCP, and have the dashboard read it.

## Done 2026-11-13

- **REST, GraphQL and MCP read the same struct.** All three come from one `agentsessions.Environment` filled by `withSpend`. Each now also carries `agentModelSpendCapReached` (`SpendStatus.RefusesAtCap`): the own cap is reached, or the tier ceiling is with no charge due to lift it. Each also carries `agentModelChargesAtThreshold` (`SpendStatus.ChargesAtThreshold`): reaching the next threshold charges the card. It is false where bex cannot charge (no subscription, excluded, comped), on the workspace's own key, or under a hold. The MCP golden is regenerated.
- **The dashboard reads the verdict.** The composer blocks on `agentModelSpendCapReached` and falls back to month-to-date ≥ cap only for an older API. Before this, a chargeable T0 workspace at $10 was blocked in the composer even though its next request would have charged the card and continued. When the cap is a T0 charge point that bex can charge (`agentModelChargesAtThreshold`), the 80% warning now says the card is charged there and sessions keep running (en, zh).
- **Tests.** `TestEnvironmentReportsTheMintsCapVerdict`, plus dashboard `spend.test.ts` and `new-session-composer.test.tsx`.
- **Devin reference.** Devin's self-serve billing tops up credits automatically when the balance drops below an admin-set threshold. Sessions keep running; they halt only when the balance reaches zero with no reload ([Devin docs: self-serve plans](https://docs.devin.ai/admin/billing/self-serve), [release notes](https://docs.devin.ai/release-notes/overview), [fast.io summary](https://fast.io/resources/devin-ai-credits/)). bex's charge-to-continue matches: charged at the threshold, refused only when the charge fails. Not verified: what Devin does when an auto-reload payment is declined; no public source says.
- render.com has no agent-model billing.
