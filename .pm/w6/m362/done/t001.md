## Objective

Every workspace's trust counters (`lifetime_paid_cents`, `paid_cycle_invoices`) reflect all of its paid, non-zero bex invoices, including those paid before `billing_trust` existed (migration 0194, 2026-11-05).

## Context

- `lego/backend/internal/billing/trust.go:159` records an `invoice.paid` only when `AmountPaid > 0`; `stripe_billing_events` stores no amounts and is purged after 90 days (ADR091 D10.1 "State").
- Production on 2026-11-13: no `billing_trust` row at all, against 31 `invoice.paid` events since 2026-09-16 (two for the bex workspace on 2026-10-16). Whether those were $0 invoices is unknown.

## Steps

1. A one-off, idempotent backfill (an admin command in bex-api, or a job run in-cluster with the live Stripe key): list each mapped customer's invoices with `status=paid`, sum `amount_paid > 0` into `lifetime_paid_cents`, and count `billing_reason=subscription_cycle` ones into `paid_cycle_invoices`, keyed by invoice id so that a rerun or a later webhook never double-counts.
2. Run it on production; record each workspace's tier before and after in this task.
3. Confirm the live recorder counts a new non-zero `invoice.paid` (the t006 charge serves as the check).

## Acceptance criteria

- [ ] Rerunning the backfill changes nothing.
- [ ] Each workspace with a paid non-zero invoice has a row whose sums match Stripe.

## Out of scope

- Disputes and failure locks from before 0194 (note any found).

## Done 2026-11-13

Shipped in `e0ba016b5` and deployed by run 43362959682. Both bex-api replicas logged `billing trust backfill: counted 0 paid invoices across 13 workspaces` (04:21 UTC) with no error: every paid bex invoice in Stripe was $0, so no workspace had paid yet, and the empty `billing_trust` table was correct. The bex workspace therefore leaves T0 only through a threshold charge (t003). The backfill runs once per start on one replica at a time (`RunExclusive`), so it repeats on each rollout; the ledger keeps that a no-op.
