## Objective

The two billing rhythms fail independently: a declined threshold charge stops platform-model spend (`BILLING_BALANCE_DUE`) and never opens hosting's grace and enforcement (ADR040 §7); a failed hosting (cycle) invoice still opens hosting's grace and holds model spend at T0 (ADR091 D10.1, D10.3).

## Context

- `lego/backend/internal/billing/lifecycle.go` (~97, ~120: `invoice.payment_failed` / `payment_action_required` → dunning), `trust.go` (failure → T0 lock and balance due).

## Steps

1. The lifecycle handler recognises a threshold invoice (its metadata or billing reason) and leaves hosting's dunning state alone; trust still records the failure.
2. Tests for both directions.

## Acceptance criteria

- [ ] A declined threshold charge leaves the workspace's services running and its dunning state healthy.

## Done 2026-11-13

`Lifecycle` refuses an invoice event that carries `bex_agent_model_charge=true` as not a contract invoice, so a declined model charge never opens hosting's grace or enforcement; `Trust` still records it (balance due, T0 hold) through the invoice's metadata. A failed hosting (cycle) invoice keeps its existing path. Tests in `lego/backend/internal/billing`.
