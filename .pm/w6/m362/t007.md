## Objective

Check that the spend and charge fields read the same on REST, GraphQL, MCP and the dashboard, and compare the experience with Devin's observable billing for agent sessions (render.com has no agent-model billing). File any drift as follow-up work.

## Found 2026-11-13 (t016 review)

- **Check that the dashboard's "reached" verdict matches the mint's.** `SpendStatus.Reached` now holds month-to-date spend against the workspace's own cap, and T0's ceiling against unbilled spend (the charge window, ADR091 D10.2a).
- **The dashboard composer still re-derives the verdict.** It works it out as month-to-date ≥ the effective cap (`dashboard/src/features/agent-environment/lib/spend.ts`, `blocksCreate`), so a T0 workspace whose cycle invoice billed part of the month can be blocked there while the mint would serve it.
- **Fix:** expose the verdict, for example `agentModelSpendCapReached` on REST, GraphQL and MCP, and have the dashboard read it.
