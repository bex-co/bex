## Objective

Show that a request held through a cold start survives the activator pod being replaced, and record how often the activator holds requests.

## Context

- Gate: a production pin whose producer contains this milestone's commit.
- Production access: `scripts/fetch-app-kubeconfig.sh` with `BEX_SSH_KNOWN_HOSTS_FILE` pointing at a temp file holding `* <key>` from `~/.ssh/bex_cp_host_ed25519.pub` (w3/m472). Signed-in API calls go through `bash scripts/qa-login.sh`.
- Lining a held request up with a production deploy is timing-sensitive; the local cluster (`bash scripts/mock-cluster.sh operator`, then `kubectl rollout restart` of the activator) is an accepted substitute, recorded as such.

## Steps

1. Read the activator's held-request volume over a recent day (logs or metrics), read-only.
2. Hibernate a free fixture web service in `bex-canary` (or on the local cluster) and send a non-HTML request; while it is held, replace the activator pod that holds it.
3. Record the response (status, time) and the pod events.
4. Delete the fixture by id (`GET` answers 404).
