## Objective

Make a project-create audit row say which project was created. Today it names none, on any surface.

## Context

- Live REST capture, 2026-08-27, immediately after creating `qa-20260827-proj` (`prj-da7qdbnkrsvc73c3m2cg`):

  ```
  { "id": "aud-da7qdbnkrsvc73c3m2c0", "timestamp": "2026-08-27T02:53:34Z",
    "event": "CreateProjectEvent", "status": "success",
    "actor": { "type": "user", "id": "c73bb20d-…" },
    "metadata": { "relation": "can_create" },
    "resource": "workspace:tea-d98210cbbpdc73dcrkvg" }
  ```

  No project key. Contrast `environments.SetServices`, whose `metadata` does carry `"service": "tea-…-qa-…"` — so `renderMetadata` works; this producer simply never sets `Target`.
- **The action name is not the defect.** `lego/backend/internal/audit/service.go:141` maps `"projects.Create" → "CreateProjectEvent"` deliberately — it is Render's own event name, guarded by `TestRenderEventVerbsExist` in `vocabulary_test.go`. Leave it alone.
- This is distinct from t001: t001 exposes an already-populated column over GraphQL; this fixes a producer that stores nothing to expose.
- t001's step 4 enumerates every verb's `Target`-setting status. Whatever else it finds empty and shouldn't be belongs here or in its own row — decide global-vs-per-verb and say which.

## Steps

1. Set `Target` (and `TargetName` where a display name exists) on the `projects.Create` audit event, following the shape `RecordDatabaseEffect`/`RecordKeyValueEffect` already use (`lego/backend/internal/core/audit.go:463,507`).
2. Apply the same to any sibling verb t001's enumeration flagged, or record why each is legitimately target-less (a genuinely workspace-wide verb has no target, and that is correct).
3. Verify REST's `metadata` gains the project key without disturbing the keys already there.
