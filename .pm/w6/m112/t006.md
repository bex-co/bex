## Objective

Cover the behavior this milestone shipped, including the surfaces that are correct today only because of the current shape.

## Context

- The audit package already has `vocabulary_test.go` guarding the Render event-name mapping against drift — extend that discipline to the target side rather than testing a single verb.
- The row-count defect (t002) is only visible as a **count**, so a test must assert the number of rows one mutation writes, not merely that a row exists.
- `projects.Create` writes exactly one row today and `environments.CreateWithACL` writes two — the one-row case is the regression surface, not the control to ignore.

## Steps

1. Assert the GraphQL `AuditLog` type exposes the target and that a row with a stored target returns it non-null.
2. Assert REST's `metadata` shape is unchanged for a verb that already carried its target.
3. Assert row **counts**: one Save with one resource ⇒ one row; environment create ⇒ the intended number; project create ⇒ one.
4. Assert `projects.Create` stores a target, and add a guard over the set of verbs expected to carry one so a future verb cannot silently ship target-less.
5. `cd lego/backend && go test ./...` and `cd dashboard && yarn test`.

## Files

- `lego/backend/internal/audit/` tests
- `lego/backend/internal/environments/`, `lego/backend/internal/projects/` tests
- `dashboard/src/features/audit/` tests

## Acceptance criteria

- [ ] Target exposure is covered on GraphQL and unchanged on REST.
- [ ] Row counts are asserted, not just row existence.
- [ ] A verb-level guard prevents a new verb shipping without a target.
- [ ] Both suites pass.

## Out of scope

- Coverage of code this milestone did not change.
