## Objective

`withCORS` advertises the literal `"GET, POST, OPTIONS"` for every route, while the router registers 53 distinct patterns on `DELETE` (26), `PATCH` (17) and `PUT` (10). Replace the literal with a list derived from what the mux actually serves, so the preflight cannot drift from the router again. A literal is precisely what drifted here; a second hand-maintained literal would only reset the clock.

## Context

- `lego/backend/internal/api/auth.go:725` — `w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")`, inside `withCORS` (`:708-734`).
- The middleware wraps the whole REST router, so it does not today know which route the request targets. Deriving a **per-route** list means consulting the mux; deriving a **global** list means unioning every registered verb. Either is acceptable — pick one and say why in the code comment. The global union is simpler and strictly sufficient for the DoD; per-route is more precise but requires a mux lookup on the preflight path.
- Go 1.22+ `http.ServeMux` patterns are `"VERB /path"`, which is what makes enumeration feasible; `mux.Handler(r)` can be used to probe a synthesized request if the per-route form is chosen.
- `e2394e52` ("preserve Vary: Accept-Encoding through the CORS middleware") is why `Vary` uses `Add` and not `Set` — do not regress that while editing this block.

## Steps

1. Decide global-union vs per-route and record the reasoning in a comment above the header write.
2. Build the verb set from the router's registered patterns rather than restating them.
3. Keep `OPTIONS` in the advertised set (the preflight itself), and keep `HEAD` consistent with whatever the mux does for GET routes.
4. Confirm the non-allowlisted-origin path is untouched: no CORS headers at all when `allowed[origin]` is false.

## Files

- wherever the REST mux is constructed, if the verb set must be threaded into the middleware

## Acceptance criteria

- [ ] `OPTIONS` with `Access-Control-Request-Method: DELETE` on a route that serves DELETE returns an `Allow-Methods` containing `DELETE`; same for `PATCH` and `PUT`.
- [ ] The advertised set is computed from the router, not written out a second time by hand.
- [ ] A non-allowlisted `Origin` still receives no CORS headers.
- [ ] `Vary: Origin` and `Vary: Accept-Encoding` both still survive the middleware (`e2394e52`'s guarantee).

## Out of scope

- The header list (`t002`) and `Max-Age` — same code block, separate decision.
- Changing which origins are allowed. The origin allowlist is correct and stays exactly as-is.
