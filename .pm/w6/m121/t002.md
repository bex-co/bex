## Objective

`Access-Control-Allow-Headers` is the second literal in the same block and has the same drift exposure. It advertises `Authorization, Content-Type, X-Session-Token`; the handlers read at least one inbound browser-relevant header that is missing. Also add an `Access-Control-Max-Age`, since none is set today and every preflight therefore costs a full round trip.

## Context

Measured on the 55th `/qa-find-bugs` run against the 37 distinct `r.Header.Get(...)` names in `lego/backend/internal/`:

- **`Idempotency-Key` — add it.** Read at `lego/backend/internal/webhooks/rest.go:213`. Its route's verb is POST, which the method list already allows, so the header is the only thing blocking it; a browser client silently loses idempotency today.
- **`Last-Event-ID` — decide from `t003`.** Read at `lego/backend/internal/logs/rest.go:159` for SSE log-stream resume. Add it only if `t003`'s live test shows a cross-origin `EventSource` reconnect needs it advertised.
- **`X-Api-Key` — do NOT add it.** It appears only at `internal/sshgateway/modelproxy/modelproxy.go:380,384`, where the gateway sets a credential on an **outbound** upstream request. A raw grep of header names makes it look like an inbound auth header; it is not. Leave a comment saying so, because the next person running the same grep will reach the same wrong conclusion.
- Excluded and why: webhook-signature headers (`webhook-id`/`webhook-timestamp`/`webhook-signature`, `Stripe-Signature`, `X-Hub-Signature-256`, `X-GitHub-*`) are server-to-server inbound and never browser-sent; `X-Vault-Token`, `X-Goog-Api-Key`, `OPEN-SANDBOX-API-KEY` are outbound; `X-Forwarded-*`, `Cookie`, `Origin`, `Accept-Encoding`, `Content-Length` are infrastructure- or browser-managed (several are forbidden header names a browser refuses to let script set at all).

## Steps

1. Add `Idempotency-Key` to the advertised list.
2. Take `t003`'s answer on `Last-Event-ID` and act on it; record the answer in the comment either way.
3. Add an `Access-Control-Max-Age`. Pick a value deliberately — browsers cap it (Chromium 7200s, Firefox 86400s) — and note that a long cache means a future list change takes that long to reach clients that already preflighted.
4. Write the "why not `X-Api-Key`" comment next to the list.
