## Objective

Stop a service losing its Memory, CPU and Total Instances metrics because its name is long enough that Kubernetes truncated the generated pod name out of the two-segment shape the PromQL selector assumes.

## Context

- Exhaustive grep — `grep -rn '\[a-z0-9\]{5}' lego/ --include='*.go' | grep -v _test` returns exactly **4 lines in 3 files**:
  - `lego/backend/internal/metrics/source.go:256` (cpu / memory / instance_count for the Metrics page)
  - `lego/backend/internal/usage/service.go:884` (`queryInstanceSeconds`)
  - `lego/operator/internal/controller/autoscale.go:101` and `:104` (`NewPrometheusMetricsReader`)
- `k8s.io/apiserver@v0.35.0/pkg/storage/names/generate.go`: `MaxGeneratedNameLength = 63 - 5 = 58`; a base longer than 58 is truncated, then a 5-char suffix is appended. The ReplicaSet controller's base is `"<deployment>-<podTemplateHash>-"`, so past the threshold the separating hyphen is eaten and the pod name has **one** segment after the app name, not two.
- Live, in the QA workspace: `tea-d98210cbbpdc73dcrkvg-qa-20260826-webhook-svc-55d855bcb7sxgd` (one segment, 63 chars) vs `tea-d98210cbbpdc73dcrkvg-block-eden-mono-5f557c45fd-ll7x9` (two segments, 57 chars).
- `podTemplateHash` length varies (6–10 observed live in this workspace), so a service near the threshold can flip between working and broken **across deploys**. Any test must cover both hash lengths, not just one.
- `ValidAppName` (`lego/backend/internal/store/api.go:588`) allows up to 30 characters, so roughly a third of the legal name space is affected.

## Steps

1. Apply t001's chosen selector to all three call sites, as a shared helper or as three deliberate copies per t001's decision.
2. Re-derive and record the cross-App collision-safety argument for the chosen form against a real adversarial pair in the same namespace (App `web` vs App `web-api`, both truncated and untruncated pod shapes).
3. Update `docs/ADR010-observability.md`'s heuristic paragraph — its current text asserts a two-segment guarantee Kubernetes does not make.
4. Update `lego/backend/internal/metrics/source.go:243-253`'s own explanatory comment, and `usage/service.go:878-882`'s ("Used for App (ReplicaSet) pods whose names follow the two-segment pattern"), which state the false assumption verbatim.
5. Re-probe live: `metrics(query: { filters: [{field:"RESOURCE", values:["srv-da7o6ovvqdcc73bpn9hg"]}], name:"MEMORY", … })` returns ≥1 series, and the Metrics page renders numbers instead of "No data in range".
