## Objective

Confirm the new push-deliverability signal is consistent across REST, GraphQL, MCP, and the dashboard UI (same field, same semantics, same value for a given service on all four), and record how this compares to Render's own model.

## Context

- Render requires a repo to belong to a connected account before a service can be created from it at all — Render has no equivalent of bex's Public Git URL tab accepting an arbitrary github.com URL outside the connected installation. This divergence is deliberate (bex's Public Git URL feature, and its `w6/m97` workaround role) and should be recorded, not treated as a gap to close.
- `docs/ADR006-bex-api.md` (REST/GraphQL/MCP parity contract) and `docs/ADR026-github-integration.md` (the feature this milestone touches).

## Steps

1. Verify the new field's name, type, and values are identical across REST, GraphQL, and MCP responses for the same service (re-run this hunt's exact MCP `tools/call get_service` alongside a REST `GET` and a GraphQL query against the same `id`).
2. Verify the dashboard hint text agrees with what the field says (no UI-vs-API disagreement).
3. Record the Render-comparison note in this milestone's README or a doc pointer: Render has no direct equivalent scenario (no unconnected-repo creation path), so there is nothing to match — the parity requirement here is internal (bex's own four surfaces agreeing), not external.

## Files

- No code changes expected beyond what t001-t003 already made; this task is verification + a short written note.
