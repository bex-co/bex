# Owners API parity drift — from w6/m2/t006

Field-level diff of the shipped `/v1/owners` REST + MCP surface against the pinned schema (`docs/render-artifacts/owners-api.md`) found three intentional divergences, each already commented at its source:

1. **`own-` user-id resolution is caller-only.** Render's `GET /v1/owners/{ownerId}` resolves ANY user id to THAT user's default workspace; bex mints no `own-` id registry (`Identity.Subject` is a raw Kratos/Hydra string), so any `own-`-prefixed id is read as "the caller's own id" and resolves via `core.Base.Tenant` — the same w1/m9 resolver `apps`/`postgres` List use to auto-scope, reconciled mid-milestone when w1/m9's tenant onboarding landed (`lego/backend/internal/workspaces/service.go`, `ownIDPrefix`/`defaultWorkspace`). Closing the remaining gap (resolving a PEER's own- id) needs a real `own-` id ⇄ subject registry — its own task once another actor needs to look up a workspace by someone else's user id (no current consumer).
2. **No cursor pagination.** `GET /v1/owners` returns the full envelope shape (`{owner, cursor}[]`) but ignores the spec's `cursor`/`limit` query params — every caller's workspace list is returned in one page. Fine at m1/m2 scale (a caller's workspace count is small); revisit if/when that stops being true.
3. **`databaseName`'s `ownerId` filter is a documented no-op today.** Database CRs aren't yet projected from the tenant-scoped control plane (no create path stamps `core.LabelTenant` on them, unlike Apps — see `store/reconciler.go`'s `stampLabels`) — see `PostgresView.OwnerID`'s doc comment. `GET /v1/postgres?ownerId=…` authorizes the id but returns empty rather than fabricating scoped results. Real fix needs Database CRs to carry the same tenant-id labeling Apps already got (`w6/m2/t004`, and now w1/m9's `core.LabelTenant`), itself gated on managed Postgres growing a store-backed multi-tenant create path (parallel to `store/api.go`'s Apps).

None of these are silent — each is commented at its source and reflected in `docs/render-artifacts/owners-api.md`. No REST/GraphQL/MCP mutation exists under `/v1/owners` (verified: `internal/workspaces/rest.go` registers GET only).

Source: w6/m2/t006 parity pass, 2026-07-09.
