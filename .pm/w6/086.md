# Adopt pod user namespaces (`hostUsers: false`) for `render-v1` runtime pods

Why: Render runs without a pod user namespace, so this is bex-only defense in depth for the wider `render-v1` capability set. It was split out of w6/m149 so that it does not gate Render parity.

- **Spike (w6/m149 t002, `docs/render-artifacts/container-privileges.md` § bex user namespaces):**
  - ext4 volumes pass every path, including a pre-existing non-userns disk, with no chown needed;
  - an overlayfs `local-path` volume fails closed (`MOUNT_ATTR_IDMAP … invalid argument`).
- **Gate:** prove that Hetzner `hcloud-volumes` (LUKS ext4, ADR082) accept idmapped mounts on a production tenant node before projecting.
- **Work:**
  - operator projection on the Deployment, CronJob, manual-run and predeploy paths;
  - admission requiring `hostUsers == false` for `render-v1`;
  - the explicit migration path for existing services.

  This is more than an hour: promote it to a milestone when scheduled.
