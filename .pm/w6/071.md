# Fix mobile GraphQL token-refresh recovery

Why: a recoverable GraphQL 401 currently retries with the expired bearer after a successful token refresh, then signs the user out and interrupts mobile supervision.

**Estimate:** 45m; keep as an inbox note. **Priority:** 1 in the 2026-09-07 mobile-review handoff; work before the related provider/recovery milestones where practical.

**Source:** user requested a mobile review, then handed all five $pm-brainstorm proposals to w6. Reviewed at `e609e9322`; this is proposal 1 and a targeted follow-up to `w11/m2`, not a new auth flow. Goal linkage: ADR008 API-first operations and ADR048 dependable supervision.

## Evidence

`mobile/src/common/apollo/apollo-client.ts:17` skips header recomputation whenever operation context already carries authorization. The 401 recovery at line 37 forwards that same operation after forceRefresh.

An isolated probe loaded the actual TypeScript Apollo link chain with a fake auth manager and HTTP transport, using only synthetic credentials. It observed two requests with the same expired bearer, one successful forceRefresh, and one signOut. The expected second request uses the refreshed bearer and returns data. The outer catch also covers failures from the retried request, so non-auth API failures need to be distinguished from a failed refresh.

## Work and acceptance

- Replace stale automatic bearer context on the one authorized 401 retry; preserve explicitly supplied credentials used by logout cleanup.
- Keep serialized refresh and bounded retry behavior. A subsequent non-auth network/API failure must not discard a valid refreshed session.
- Add a regression through the actual Apollo link chain: expired-token 401 → successful refresh → fresh-token success; refresh failure; repeat 401; non-auth retry failure; explicit logout credentials.
- Run the focused tests and mobile typecheck. No real credentials may enter test output.

**Done when:** the refreshed request succeeds without logout, definitive authentication failure follows the reviewed sign-out contract, and transient transport failure preserves the valid session.

**Out of scope:** changing PKCE, SecureStore, native scopes, dashboard cookie authentication, or the Render CLI refresh endpoint.
