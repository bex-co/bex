# Every operator deploy closes every external Key Value and Postgres connection

Why: `bex-kv-sni-proxy` and `bex-pg-sni-proxy` run from the operator's image and close every stream they relay when they stop, so each production deploy drops every external TLS client of every Key Value store and Postgres database; Render does not drop a datastore's clients when it ships its own platform.

- **Split from** w6/m469 (2026-11-18), which keeps a store's `kv-internal-proxy` image while its binary is byte-identical (ADR021 § 10). This is the external half that w6/140 named.
- **Evidence (production, read-only, 2026-11-18).** Both DaemonSets run 3 replicas: `RollingUpdate`, `maxUnavailable: 1`, a 30 s grace period and `hostPort`, so a pod cannot surge (`lego/operator/config/kv-sni-proxy/daemonset.yaml`, `lego/operator/config/pg-sni-proxy/daemonset.yaml`). `bex-kv-sni-proxy` was at revision 809. All three of each rolled at 01:31–01:32Z on 2026-11-18 with the 01:32Z operator deploy. On `SIGTERM` both close the listener and return from `main`, which closes every stream (`cmd/kv-sni-proxy/main.go`, `cmd/pg-sni-proxy/main.go`). Streams are already capped at 24 h lifetime and 1 h idle.
- **Their binaries change more often than the internal proxy's.** They link `k8s.io` and controller-runtime. Hashed out of GHCR: identical in pins `336b647b1`, `5e0fb5ad8` and `fc4fbf28a`, different in `9c79201b4`, `e36296ae8` and `359aee37d`. The build is reproducible (w6/m469 § Findings), so a hash comparison is sound.
- **Where the image comes from.** Kustomize gives both DaemonSets the `controller=` pin (`deploy/gitops/base/bex.yaml`). `deploy.yml`'s step "wait for PROXY-compatible datastore proxies" requires the new operator digest on both and must change with any hold.
- **Directions:**
  1. In `deploy.yml`, keep each DaemonSet's current digest when its `/kv-sni-proxy` (`/pg-sni-proxy`) is byte-identical in the new image, and wait only for a DaemonSet whose binary changed. The hashing can reuse `registry.ImageFileSHA256` (w6/m469) or a small script.
  2. Or publish each SNI proxy as its own content-addressed image, so its digest changes only when its binary does.
- **Render:** a datastore's connections break when the customer changes it (a plan change, a restart), not when Render ships its platform ([Key Value](https://render.com/docs/key-value)).
- **Done when:** on production, an external TLS client held to a Key Value store (and one to a Postgres database) across an operator deploy that leaves the SNI binaries alone still answers afterwards (`PING`, `SELECT 1`) on the same connection, and the DaemonSet keeps its pods and revision. A deploy that changes a binary still rolls that DaemonSet, and `deploy.yml` still waits for it.
