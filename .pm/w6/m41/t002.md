## Objective

Record an unhealthy edge only when its condition transition is genuinely newer than the last healthy checkpoint for that service. A conclusion that time-traveled — one whose `LastTransitionTime` predates the checkpoint — is a stale re-read, not a new outage, and must not page anyone.

## Context

- The preferred shape per the milestone README: an **ordering guard**, not a direct-quorum confirm read. `LastTransitionTime` is already on the condition the reconciler reads, so the guard adds no client, no apiserver load, and no stall risk.
- Compose with `w3/m78`'s mitigations rather than replacing them: `RolloutSettling` exclusion and `debounceUnhealthy` both stay. The ordering guard is a third, orthogonal filter.
- `debounceUnhealthy`'s per-process state (`reconciler.go:188`) is deliberately memory-only — "a restart just re-observes". Whatever checkpoint the guard compares against must survive a restart safely or fail *open toward recording real outages*: a missing checkpoint must never suppress a genuine failure.
- Asymmetry to preserve from m78: recovery is immediate; only the unhealthy direction is debounced. The guard applies to the unhealthy edge only.

## Steps

1. Establish the last-healthy-checkpoint reference for a service (reuse existing recorded state if it already carries a usable timestamp; add one only if not).
2. Gate the unhealthy edge on the condition's `LastTransitionTime` being newer than that checkpoint.
3. Ensure a missing/unknown checkpoint records the edge (fail toward reporting real outages, never toward silence).
4. Leave `RolloutSettling` handling and the recovery path untouched.
5. Confirm `t001`'s reproduction now passes and every m78 test stays green.
