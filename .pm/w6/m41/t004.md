## Objective

Confirm the suppression is consistent everywhere an availability edge is observable, and that no surface still shows a phantom the others now suppress.

## Context

- `server_failed` / `server_available` are typed events in the composed feed and reach tenants through four paths: REST `GET /v1/services/{id}/events`, GraphQL `serviceEvents`, MCP `list_service_events`, and the dashboard events UI — plus **outbound webhooks** and **push** (`docs/ADR052-notifications.md` D3).
- No field or verb shape changes here, so this is a cross-surface consistency check rather than a Render diff. Render's own service-events row in [`docs/ADR018-render-parity.md`](../../../docs/ADR018-render-parity.md) already documents bex's typed observed events as truthful-source extensions.
- The suppression happens once, at the source (the store reconciler), so all six consumers should inherit it — **verify that rather than assume it**: `w3/m78`'s own lesson was that the closed event set lived in *five* mirrors and one was missed until an integration test found it.
- ADR052 § Consequences item 2 should be updated: this milestone resolves the residual it records.

## Steps

1. Trace an availability edge from the reconciler to each of the six consumers and confirm each reads the suppressed source rather than re-deriving.
2. Confirm no consumer has its own availability derivation that bypasses the guard.
3. Update `docs/ADR052-notifications.md` § Consequences item 2 to record the residual as resolved.
4. Flag any drift found as follow-up work rather than silently diverging.

## Files

- `docs/ADR052-notifications.md`
- read-only trace across `lego/backend/internal/` event/webhook/push projections and the dashboard events surface

## Acceptance criteria

- [ ] All six consumers verified to inherit the suppression from the single source.
- [ ] No consumer re-derives availability independently; any that does is filed as follow-up.
- [ ] ADR052 § Consequences item 2 updated to reflect the resolved residual.

## Out of scope

- Changing event field shapes, the event vocabulary, or notification policy.
