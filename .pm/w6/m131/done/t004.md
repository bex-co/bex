## Objective

`w3/m8` verified the request pipeline against a containerized Alloy fixture and passed; production was never checked, and nothing anywhere asserts that `type=request` produces rows in a real cluster. Close that gap so the stream cannot silently return to zero.

## Context

- The fixture-level verification was real and is not the problem — it proved the pipeline's logic. What is missing is any assertion tied to a **live** cluster.
- `scripts/logs-verify.sh` exists and is the natural carrier, but it was never wired to a gate that actually runs; `w3/m8` closed with it owed.
- **Shared carrier now exists (`w6/m132/t004`, 2026-08-28):** `.github/workflows/ssh-edge-liveness.yml` runs the credential-free SSH KEXINIT synthetic (`scripts/ssh-kexinit-probe.sh`) on a schedule and opens/closes a tracking issue. Land this task's request-log liveness check as a sibling step/job in that workflow rather than a second, parallel mechanism — that is the "prefer one mechanism" reconciliation `w6/m132/t004` asks for.
- The symptom is silent by construction: zero rows is a valid response shape, so no error surfaces and no alert fires.
- Cleanup to fold in here (recorded during the 69th hunt, **not a user-facing defect** and deliberately not its own task): `lokiTypeMatcher` (`logs/loki.go`) carries three build-plus-other branches — `wantApp && wantRequest && wantBuild` → `""`, `wantApp && wantBuild`, `wantRequest && wantBuild` — that `validate()` makes unreachable, since combining `build` with any other type returns `400 log type "build" must be requested on its own`. Its `len(q.Types)==0` comment also claims "Build logs are only included when the caller explicitly requests them — `type=build` **or `type=all`**", but `NormalizeTypes` maps `all` to `nil`, landing in that same branch and excluding build. Live: `type=all` returns app-only (1 line) where `type=build` returns 100. Remove the dead branches or make them reachable, and fix the comment.

## Steps

1. Decide the guard's form — extending `scripts/logs-verify.sh` into a gate that actually runs against a live cluster, or a monitored assertion on the stream's presence.
2. Implement it so a zero-row `type=request` on a service with known traffic is loud rather than silent.
3. Fold in the `lokiTypeMatcher` dead-branch and comment cleanup above.

## Outcome (2026-08-28)

**The guard exists, runs on its own, and covers the case the old one structurally could not.**

The key finding: **`scripts/logs-verify.sh` would NOT have caught this outage even if it had been run in production.** It deploys its fixture into `APP_NS=default` and asserts `type=request` there — and `default` is precisely the one namespace the broken regex still matched. The milestone's premise that the owed production run would have caught it is wrong; the guard had to assert something the fixture never could.

- `scripts/request-logs-liveness.sh` (new): reads Loki's label index and fails unless a `type=request` stream exists **for a `tea-<xid>` tenant namespace** — not just `default` or the `dashboard` allowlist bucket, both of which kept flowing throughout the outage. No fixture, no traffic generation, no API credential; the platform's real traffic is the fixture.
- Scheduled as the `request-logs-liveness` job in `.github/workflows/ssh-edge-liveness.yml` — the sibling slot `w6/m132/t004` reserved — opening/closing a `request-logs-down` tracking issue exactly as the SSH probe does.
- `scripts/logs-verify.sh` now also asserts the **live deployed** ConfigMap's `ServiceName` regex attributes a tenant namespace (and still `default`, and still rejects `kube-system`). That is the check that answers "did the GitOps change reach the running shipper?", including the `w3/m13` Argo-freeze failure mode.
- `lokiTypeMatcher`'s three unreachable build-plus-other branches removed; the rule that makes them unreachable is now pinned by `TestBuildTypeIsNeverCombined` instead of three tests asserting dead code.
