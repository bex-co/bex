# Docker Command runs through `sh -c` on bex but is exec'd on Render

Why: a Render user's working Docker Command can crash-loop on bex, and the reverse, because the two platforms launch the same string differently. Docker Command is a core field of every image service and of Blueprint `dockerCommand`.

Evidence (2026-10-17/19, `docs/render-artifacts/container-privileges.md` § Findings 5):

- **The same command, opposite results.** `python3 -c exec(__import__(chr(98)+…).b64decode(…))` started on Render (`srv-dba3nmjrjlhs738ponp0`). On bex it crash-looped with `/bin/sh: 1: Syntax error: "(" unexpected` (`srv-dbaqn82d108c73fur01g`, `srv-dbaqn8dvjvcc73a4gp7g`; deleted).
- **Render keeps quotes literally.** `sh -c "echo $P | … ; exec python3 /tmp/p.py"` failed on Render with `sh: 1: echo … : File name too long`. Render tokenizes the command into argv, keeps the quote characters, and uses no shell.
- **bex wraps the command in a shell.** It runs `[shellBinary, "-c", command]` (`shellCommand`, `lego/operator/internal/controller/deployment_projection.go:217`; also pre-deploy, ADR004 `:268`).

To do (sub-hour research, then decide):

1. Pin Render's exact tokenizer with three or four probe commands on a free web service:
   - quotes;
   - `$VAR`;
   - `&&`;
   - an escaped space.
2. Decide whether bex should match it, accept it as a documented divergence (`sh -c` is more permissive for most real commands), or translate Render-shaped argv. Record the answer in ADR018's Runtime row and ADR004.
3. If bex changes behavior, persist it per service, as ADR089 does for policies: existing services' commands must not change meaning on upgrade.

**Done 2026-10-19: documented divergence, no code change.** Three more live Render probes (deleted, 404) pinned the tokenizer:

- no shell;
- `<program> -c <rest>` passes the rest verbatim, quote characters included, which is why the quoted `sh -c "…"` failed;
- otherwise shell-style word splitting with quote and backslash removal;
- `$VAR` is rewritten to Kubernetes' `$(VAR)`.

bex keeps `sh -c`. The two agree on plain commands and `$PORT`. bex also runs quoted `sh -c "…"` scripts and `&&` chains, which Render breaks. Only an unquoted literal `(`, `;`, `&` or `|` fails on bex. Changing bex would alter commands existing services run. Recorded in `docs/render-artifacts/docker-command.md`, ADR004 and ADR018 (Runtime row). Revisit with a per-service launch mode if a migrating user hits it.
