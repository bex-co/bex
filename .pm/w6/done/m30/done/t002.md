## Objective

Give bex the per-host redirect mechanism ADR005 says it lacks: for each auto-paired sibling host, the operator renders a Traefik redirect middleware (RedirectRegex, preserving path/query per t001's capture) + a router/Ingress rule on the sibling host that applies it, while cert-manager still issues for the sibling (a redirect over an invalid cert is a broken redirect). The canonical host — the one the tenant explicitly added — keeps serving directly.

## Context

- Pairing source of truth: m23's `wwwSibling`/`isApex` logic in the operator's host reconciliation (`lego/operator/internal/controller/`, the `effectiveHosts` path).
- Middleware precedent in-tree: w7/m5 (Key Value access) and w7/m32 (service ipAllowList) render Traefik middlewares from App state — reuse that plumbing.
- The sibling must flip to direct-serving if the tenant later adds it explicitly as its own host (it stops being an auto-pair).

## Files

- `lego/operator/internal/controller/` (Ingress/middleware generation)

## Acceptance criteria

- [x] Envtest: a paired App renders the sibling router+middleware and the canonical plain router; explicit-both-hosts renders no redirect; live curl on the mock cluster matches t001.
