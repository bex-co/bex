## Objective

`/services/new`'s `<h1>` and subtitle only branch for `cron_job`
("New Cron Job" / "Run a command on a recurring schedule."). Every other
type — Web Service, Private Service, Background Worker, Static Site — falls
through to the generic pair ("New Service" / "Deploy a web service from a Git
repo or Docker image."), even though the page's own `Service Type` radio
group directly below it correctly names and describes all five. Selecting
Background Worker and reading "Deploy a **web service**..." right above it is
a small, avoidable mismatch on the first screen a new worker/private-service
user sees.

## Context

- `dashboard/src/routes/services.new.tsx:55-62` (route `head`) and
  `:108-122` (the actual `<h1>`/`CardDescription`) both branch only on
  `shape.isCronType`, ternary-falling back to `services.createTitle` /
  `services.createDescription` for every non-cron type.
- `shape.isCronType` comes from `buildShape()` in
  `dashboard/src/features/services/lib/create-service-input.ts:66-73`.
- The cron-specific strings already exist as the precedent to follow:
  `services.createCronTitle` / `services.createCronDescription`
  (`dashboard/src/features/services/locales/en.ts:2514-2521`).
- The type picker itself already has per-type name + one-line description for
  all five types (`ServiceTypePicker`,
  `dashboard/src/features/services/components/service-type-picker.tsx`) —
  reuse that copy's wording rather than inventing new phrasing that could
  drift from it.

## Steps

1. Decide the shape: either (a) add a title/description string per service
   type (`services.createWorkerTitle`/`Description`,
   `services.createPrivateTitle`/`Description`,
   `services.createStaticTitle`/`Description`, mirroring the existing
   `createCronTitle`/`createCronDescription` pair), or (b) replace the
   generic default with type-neutral copy ("New Service" / "Deploy a service
   from a Git repo or Docker image.") and drop the special-casing to a single
   cron-only branch as it is today. Prefer (a) if it doesn't meaningfully
   grow the locale file — it matches the level of care the rest of the page
   already has.
2. Update the `head()` search-param branch and the in-component
   `<h1>`/`CardDescription` branch in `services.new.tsx` together — they must
   stay consistent (the browser tab title and the on-page heading currently
   agree; don't let this fix split them).
3. Add the new locale keys to `dashboard/src/features/services/locales/en.ts`
   (and any other locale file the repo keeps in sync, e.g. `zh.ts` if it
   mirrors `en.ts` 1:1 today — check before assuming).

- [ ] Selecting each of the five service types on `/services/new` shows a
      title/subtitle pair that accurately describes that type (or a
      demonstrably generic, type-neutral one — no service type reads "web
      service" copy while a different type is selected).
- [ ] The route `head()` browser-tab title stays in sync with the on-page
      `<h1>` for every type.

## Out of scope
