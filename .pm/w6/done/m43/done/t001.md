## Objective

The New Service wizard's "Existing Image" source tab shows "The container must
listen on $PORT (default 3000) and cannot bind ports below 1024." underneath
the image-URL field regardless of which service type is selected. For a
`background_worker` (no port, no HTTP surface — confirmed by the operator's
own design, `app_controller.go`'s `reconcileWorkerStatus`) this directly
contradicts the "This service type has no public URL." note rendered a few
fields lower on the exact same page. Gate the hint on service types that
actually bind an HTTP port.

## Context

- `ServiceSourcePicker` (`dashboard/src/features/services/components/service-source-picker.tsx:258`)
  renders `t("services.createImagePortHint")` unconditionally inside the
  `image` tab's `TabsContent`, whenever the caller supplies an `image` prop —
  it has no `serviceType` input at all, so it can't distinguish web/private
  from background_worker/cron_job.
- `dashboard/src/routes/services.new.tsx` already computes exactly the
  boolean this needs: `shape.showNoUrlNote` (from
  `buildShape()` in `dashboard/src/features/services/lib/create-service-input.ts:83-85`,
  true for `private_service`/`background_worker`) gates the sibling
  "This service type has no public URL." note at `services.new.tsx:391-395`.
- The port hint string lives at
  `dashboard/src/features/services/locales/en.ts:2593-2599`
  (`services.createImagePortHint`).
- `ServiceSourcePicker` is also used by the create-Blueprint form
  (`dashboard/src/routes/blueprints.new.tsx` — check its usage before
  changing the prop shape so that call site isn't broken).

## Steps

1. Add a boolean prop to `ServiceSourcePicker` (e.g. `hasHttpPort` or
   `showPortHint`) that the port-hint `<p>` is conditioned on, defaulting to
   `true` so existing callers that don't pass it keep today's behavior.
2. In `services.new.tsx`, pass `!shape.showNoUrlNote` (or equivalent) through
   to `ServiceSourcePicker` so `web_service`/`private_service` still see the
   hint and `background_worker` doesn't.
3. Check `static_site` and `cron_job`: neither has an HTTP port either.
   `showNoUrlNote` doesn't currently cover them (it's
   `private_service`/`background_worker` only) — confirm whether the Existing
   Image tab is even reachable for those two types today, and if it is, fold
   them into the same gate rather than leaving a second copy of this bug.
4. Update the create-Blueprint call site to pass an explicit value (Blueprints
   describe multiple services of mixed types up front — decide what's correct
   there, e.g. omit the hint or key it per-service if the picker is rendered
   per-service).
