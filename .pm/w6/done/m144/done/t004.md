## Objective

Make existing dashboard controls and m143 action flows honor the shared freshness/recovery decision consistently.

## Context

- Existing consumers mix direct booleans with loaded && !canX checks; changing a hook default alone will not close every permissive path.
- m143 supplies resource-bound operation decisions and confirmation rechecks; integrate them with the common access generation.

## Steps

1. Inventory current useCapabilities consumers and update action/sensitive-reveal gates and handler checks to the new decision contract.
2. Connect m143 confirmation checks to the shared access generation and refresh lifecycle, reusing rather than duplicating its safeguards.
3. Clear affected pending operations on confirmed access loss and show neutral unavailable copy for failed checks.
4. Preserve ordinary navigation and stable non-sensitive pending geometry; do not replay any mutation after reconnect.

## Acceptance criteria

- [ ] No existing action/sensitive-read consumer enables access via stale or unknown booleans or a loaded=false bypass.
- [ ] Confirmed downgrade during an open m143 confirmation prevents dispatch; outages produce recovery copy without pretending the user's role changed.
- [ ] Authorized flows recover after successful refresh without reloading the page, and reconnect never automatically submits a mutation.

## Out of scope

- New operation families, general dashboard redesign, and unrelated client cleanup.
