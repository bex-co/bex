## Objective

Replace ambiguous dashboard permission booleans with a current decision model while preserving compatibility during consumer migration.

## Context

- viewerCapabilities already exposes grants and fresh evaluation in members/graphql.go.
- useCapabilities currently defaults unknown values to allowed and consumes only cache-first booleans; the user has approved changing this UI policy.

## Steps

1. Extend the dashboard capability query to request grant outcomes/reasons and support a fresh evaluation.
2. Represent allowed/denied/unavailable/loading/stale explicitly; expose a safe action decision to consumers.
3. Regenerate relevant documents and add English/Chinese denial and recovery explanations, preserving server authority.
