## Objective

Maintain a bounded capability snapshot with one refresh lifecycle scoped to the current dashboard access context.

## Context

- The shared polling helpers already suppress hidden-tab polling.
- Many controls call useCapabilities; independent timers would multiply load and race recovery.

## Steps

1. Coordinate a refresh at least every 30 seconds while visible and on focus/reconnect, reusing existing visibility/polling conventions.
2. Track the requesting identity/workspace generation and ignore obsolete responses; use the server fresh-evaluation path for recovery.
3. Expire action/sensitive-read eligibility at the freshness boundary even when the next read fails; retain stable non-sensitive presentation.
4. Coalesce overlapping refresh requests and clean up listeners/work when the active context ends.

## Files

- dashboard/src/features/capabilities/hooks/use-capabilities.ts
- dashboard/src/features/capabilities/ (shared coordinator/provider as needed)
- dashboard/src/common/providers/root-provider.tsx
- dashboard/src/common/lib/polling.ts

## Acceptance criteria

- [ ] No action remains enabled solely by an answer older than 30 seconds.
- [ ] Focus/reconnect requests fresh access and a late workspace-A response cannot enable workspace-B controls.
- [ ] Mounted consumers share refresh work; failures expose unavailable/retry state without a false access-change announcement.

## Out of scope

- Mutation retry queues, global logout on transient errors, and a new authorization cache service.
