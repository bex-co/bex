## Objective

Connect successful membership changes to selected-workspace and protected-state invalidation, including removal from the final workspace.

## Context

- useWorkspaces already polls memberships; WorkspaceProvider returns early when workspaces.length is zero.
- The root callback currently invalidates routes; capability and sensitive local/cache state must participate in the same access transition.

## Steps

1. Distinguish a successful membership result from loading/error/partial data and handle a verified empty result explicitly.
2. On confirmed removal, clear the invalid selection/cookie and route to a verified remaining workspace or the existing empty-workspace destination.
3. Invalidate affected capability results, sensitive cached/local state, ongoing reads/streams, and pending action context on confirmed access loss.
4. Keep transient outages as unavailable recovery states and preserve valid sessions for users who have no workspaces.

## Acceptance criteria

- [ ] Successful last-workspace removal clears currentWorkspaceId and cannot restore the removed workspace through browser history or a stale response.
- [ ] Membership transport errors do not clear a valid selection as if removal were confirmed.
- [ ] Confirmed permission loss stops affected protected work and clears its transient data and pending confirmations.

## Out of scope

- New workspace lifecycle APIs, a forced logout policy for zero memberships, and changes to other workstreams' dev environments.
