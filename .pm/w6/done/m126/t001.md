## Objective

Five of the seven project handlers return the internal `ProjectView` instead of the Render-shaped `renderProject`, so creating, renaming or re-linking a project yields a body missing three Render-required fields and carrying four Render does not define. Make every handler emit one shape, in a way a future handler cannot skip.

## Context

`lego/backend/internal/projects/rest.go` — correct today:

- `:95-97` `GET /v1/projects` (list) → `renderProjectWithCursor{Project: rendered}`
- `:112-118` `GET /v1/projects/{id}` → `s.renderProject(...)`

Wrong today, all writes:

- `:101-110` `POST /v1/projects` → `s.Create(...)` (returns `ProjectView`, `service.go:332`)
- `:120-129` `PATCH /v1/projects/{id}` → `s.Rename(...)` (returns `ProjectView`, `service.go:382`)
- `:138`/`:139`/`:140` the three `PUT .../{service,database,keyvalue}-links` → `core.HandleLinks(…, identity)`, where `identity` is the explicit pass-through defined at `:77`

**The obvious approach does not compile.** `core.HandleMapped` (`internal/core/http.go:360-368`) takes `view func(T) V` — no ctx, no error — while `renderProject` (`rest.go:67-73`) needs both, because it calls `s.environmentIDs(ctx, p.ID)` to populate Render's required `environmentIds`. Environments can use the helper (`environments/rest.go:169-179`) only because `toRenderEnvironment` is a pure function.

## Steps

1. Choose the mechanism and record why: a ctx+error-aware mapper variant beside `HandleMapped`, or explicit `renderProject` calls in all seven handlers.
2. Apply it to `POST`, `PATCH`, and the three links `PUT`s.
3. Make the omission structurally detectable — a new project handler that forgets the mapper must fail a test, not ship. That guard is the durable half of this task.
4. Leave the LIST response's `{project, cursor}` nesting exactly as-is.
5. If a ctx+error variant is added, leave existing `HandleMapped` callers untouched.

## Files

- `lego/backend/internal/projects/rest.go`
- `lego/backend/internal/core/http.go` if a mapper variant is added

- [ ] `GET` (single + list) are unchanged.
