## Objective

The plan carries an `estimatedPricing` block alongside its actions. If that figure is derived from the action list, a plan that wrongly believes it is creating resources may quote the cost of new infrastructure when the resources already exist. This task establishes whether that is true — it was **not** demonstrated during the hunt.

## Context

- Observed shape: `"estimatedPricing":{"totalUsd":"0.00","lines":[],"variable":[]}`.
- **Why it is unverified:** the fixture used a free service, where the figure is `0.00` whether the operation is a create or an update. The hunt deliberately did not exercise a paid plan (its rules forbid buying anything), so this is a reasoned suspicion, not an observation. Treat it as its own claim.
- If the suspicion holds, the user-visible consequence is a re-apply of an existing paid stack quoting its full monthly cost as if new.

## Steps

1. Trace how `estimatedPricing` is computed, and whether it reads the action list or the parsed manifest.
2. If it reads the actions, confirm on a paid-tier plan **computation** (unit test or local run — do not provision paid resources on production) that an update no longer quotes a create's cost.
3. If it reads the manifest independently of the actions, record that it was never affected and close the task with that finding.

## Files

- wherever `estimatedPricing` is computed for the Blueprint plan

## Acceptance criteria

- [ ] A written answer: is pricing affected by the create/update misclassification, yes or no, with the code path named.
- [ ] If yes, an update no longer quotes a create's cost, demonstrated in a test rather than on production.
