## Objective

When an operator setting says the cluster serves `image` volumes, a pod that carries bex's health-probe helper mounts the binary from bex's image at `/bex-health/health-probe` through an `image` volume, and has no init container. With the setting off, it keeps `bex-health-probe-install` as today.

## Context

- `lego/operator/internal/controller/health_probe.go`: `healthProbeInstallContainer`, `healthProbeVolume`, `storedHealthProbeInstaller`, `storedHealthProbeImage`. The probe, open-port and drain commands all exec `healthProbeBinary` (`/bex-health/health-probe`), so they keep working when only the volume changes.
- `deployment_projection.go`: `usesHealthProbeBinary`; `projectDeployment` sets the volume and the init container (around line 995); `keepStoredTemplate` adopts the helper's image and the installer's resources lazily (`probeStale`, `installStale`).
- `release_config_snapshot.go:783` sets `params.healthProbeImage = r.BackupHelperImage`, which is bex's own image (`cmd/manager/main.go`, `backupHelperImage`). The binary sits at `/health-probe` in it (`lego/Dockerfile:84`).
- `disk_prepull.go:192,219` collect the images of a template's init containers and containers. An image volume's reference must join them. Otherwise a disk service's first deploy after an operator upgrade pulls bex's new image inside its Recreate window.
- The API server drops `VolumeSource.Image` when its `ImageVolume` gate is off, and the Deployment's pods would then fail validation. A kubelet with the gate off cannot mount the volume either. So the setting is explicit, and it is on only where t003 has set the gate on every node that runs an App.

## Steps

1. Add the setting, for example `BEX_HEALTH_PROBE_IMAGE_VOLUME`, off by default. Add it to the environment inventory in `lego/operator/AGENTS.md`, and turn it on in the local CAPD overlay, where Kubernetes v1.36.1 has the feature GA.
2. With the setting on, project `Volume{Name: bex-health, Image: {Reference: <bex image>, PullPolicy: IfNotPresent}}`. Mount it in the app container at `/bex-health/health-probe` with `subPath: health-probe`, or mount the whole image at `/bex-health` if t002 finds that a file `subPath` does not work. Project no init container.
3. Adopt the change lazily, as w6/170 did for the installer's CPU. A stored template keeps its installer, or its image volume and reference, until a deploy, restart or settings change rolls it, so turning the setting on rolls no service. `storedHealthProbeImage` reads either form.
4. Add the image volume's reference to the disk pre-pull's image list.
5. Keep the `/bex-health` disk mount-path refusal: the helper's mount stays at that path.

## Acceptance criteria

- [ ] With the setting on, the template of a service with a Health Check Path, and of one checking any open port, has the image volume and its mount and no init container. With it off, the template is today's.
- [ ] Turning the setting on leaves a stored template unchanged until another change rolls it. A test fails when the lazy adoption is removed.
- [ ] The disk pre-pull's image list includes the image volume's reference.
- [ ] `make test` and `make lint` pass.

## Done (2026-11-24)

- **Shipped.** `BEX_HEALTH_PROBE_IMAGE_VOLUME=true` (exactly `true`; anything else keeps the installer) sets `AppReconciler.HealthProbeImageVolume`. A pod that carries the helper then gets `Volume{bex-health, Image{<bex image>, IfNotPresent}}`, mounted read-only at `/bex-health` with `subPath: bex-health`, and no init container (`healthProbeImageVolume`, `healthProbeMount` in `health_probe.go`; `projectDeployment`). The probes, the open-port check and the drain exec the same `/bex-health/health-probe`.
- **Deviation from step 2: a directory, not the file.** containerd 2.3 refuses a file `subPath` from an image volume (`only directory subpath is supported`, t002). Mounting the whole image at `/bex-health` would have shown every bex binary to the app, so `lego/Dockerfile` also copies the helper to `/bex-health/health-probe`, a directory of its own, and the pod mounts that directory. `/health-probe` stays for the installer, whose own volume shadows `/bex-health`.
- **Lazy adoption.** `keepStoredTemplate` keeps a stored template's form (`imageVolumeStale`): an installer stays an installer and an image volume stays a volume until a deploy, restart or settings change rolls it, in both directions. `storedHealthProbeImage` reads either form.
- **Pre-pull.** `podImages` and `prePullPolicy` read image volumes, so a disk service's code deploy pulls a new operator image onto the volume's node before Recreate (`IfNotPresent`, as the volume pulls).
- **Local overlay.** `config/deploy/kustomization.yaml` (what `make deploy` and `mock-cluster.sh operator` apply) turns it on; `config/prod` does not. `lego/operator/AGENTS.md` lists the variable.
- **`/bex-health` refusal kept.** A disk there would still duplicate the mount.
- **Tests.** `TestHealthProbeImageVolumeReplacesTheInstaller` (Health Check Path, any open port, drain only; setting on and off; worker and no-image), `TestHealthProbeImageVolumeIsAdoptedOnTheNextRollNotOnUpgrade` (web, disk and TCP-drain services, both directions, plus a new operator image), `TestDiskPrePullPullsTheHelpersImageVolume`, and the envtest "Health-probe helper from an image volume (w6/m624)", where kube-apiserver v1.37 stores the projection unchanged and the next pass does not write. Forcing `imageVolumeStale` false, or dropping `kept.healthProbeImageVolume`, fails the adoption test ("rolls every such service at once"); dropping the volume from `podImages` fails the pre-pull test. `make test` and `make lint` pass.
