## Objective

Make the reconciled Deployment's container `Command`/`Args` reflect `App.Spec.StartCommand` when set, overriding the image's default `ENTRYPOINT`/`CMD`.

## Context

- The operator's Deployment-building code currently lets the image's own `ENTRYPOINT`/`CMD` run as-is; no `Command`/`Args` override exists on the App CRD today.

## Steps

1. When `App.Spec.StartCommand` is set, parse it (shell-word split, e.g. via `shellwords`/`shlex`-equivalent or a simple documented convention) into the container's `Command`/`Args`.
2. Unset `StartCommand` leaves `Command`/`Args` empty (image default), unchanged from today.

## Files

- `lego/operator/internal/controller/app_controller.go`

## Acceptance criteria

- [x] Setting `StartCommand` on an App changes the running container's process to that command.
- [x] Unset behaves identically to today.
- [x] envtest coverage for both states.

## Out of scope

- DockerfilePath (t002).

## Resolution

Found already shipped by an earlier, unrelated commit — `app_controller.go` already set
`container.Command = []string{"/bin/sh", "-c", app.Spec.StartCommand}` for Deployments and
the equivalent for `cronPodSpec`. t006's simplify pass found the override gate was too
narrow (`Runtime == "docker"` only, missing the legacy `Builder: dockerfile` path with no
explicit `Runtime`) and broadened it to `effectiveBuilder(spec) != native/buildpack`.
envtest coverage for both states (plus the legacy-builder and native-runtime cases) added
in t007 (`internal/controller/startcommand_test.go`).
