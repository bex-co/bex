## Objective

Extend the capability projection so a client can ask, for a specific resource, which existing verbs (restart, suspend/resume, bare redeploy, cancel deploy, rollback-target eligibility, cron run/cancel, session cancel, create) are permitted and what preconditions block them — computed with the same helpers the execution paths use.

## Context

- ADR087 requirement 3: workspace `canOperate` alone cannot promise a specific resource can be suspended.
- Execution-path helpers to reuse (never reimplement): `lego/backend/internal/apps/protection.go` (protected-confirmation preconditions), `lego/backend/internal/core/confirmation.go`, `lego/backend/internal/postgres/lifecycle.go`, `lego/backend/internal/keyvalue/service.go`, `lego/backend/internal/deploys/service.go` (rollback-target eligibility), `lego/backend/internal/agentsessions/service.go` (phase restrictions).
- Probes must be read-only: no billing, provisioning, or mutation side effects.

## Steps

1. Define the bounded action-id vocabulary matching ADR087's detail matrix (unknown ids fail closed client-side).
2. For each action, project permitted/denied/unavailable + precondition (e.g. `protected_confirmation_required`, `no_eligible_rollback_target`, `unsupported_state`) by calling the execution path's own predicate.
3. Wire into the resource-scoped capability entry point from t003.

## Files

- `lego/backend/internal/members/` (projection)
- `lego/backend/internal/apps/`, `postgres/`, `keyvalue/`, `deploys/`, `agentsessions/` (exported predicates where needed)

## Acceptance criteria

- [ ] For a protected App, suspend projects the confirmation precondition — identical to what the execute path enforces (one shared helper, asserted by test).
- [ ] A service with no eligible rollback target reports that precondition to a `can_create` caller.
- [ ] Projection issues no writes (test asserts store/K8s untouched).

## Out of scope

- New lifecycle verbs; desktop-only creation workflows; transcript/steering tickets (future ADR048 milestones).
