## Objective

Capability evaluation always binds the client-supplied workspace, and resource-scoped decisions additionally bind the exact resource kind/id — rejecting targets outside that context instead of silently substituting the caller's default workspace.

## Context

- ADR087 requirement 2. The default-workspace substitution class of bug is the same one w6/m14/m17 closed for verbs (`core.Base.AuthorizeApp` family, `core.WithWorkspace`); the capability read path must match.
- `lego/backend/internal/members/graphql.go` — `viewerCapabilities(ownerId)` already takes an owner; verify it never falls back to a default workspace when the arg is absent/foreign.
- Identity comes from authentication, never a client-supplied subject.

## Steps

1. Audit the capability path for default-workspace fallback; make workspace explicit and mandatory.
2. Add resource context (kind/id) to the resource-scoped decision entry point (shape shared with t004) and reject a target not owned by the supplied workspace.
3. Cover the non-member and foreign-resource cases: both must read as denied/unavailable, not as another workspace's answer.

## Files

- `lego/backend/internal/members/service.go`
- `lego/backend/internal/members/graphql.go`
- `lego/backend/internal/core/` (reuse the existing resource→workspace attribution helpers)

## Acceptance criteria

- [ ] A capability query naming workspace B with a resource owned by A is rejected; nothing about A leaks.
- [ ] Omitted workspace does not resolve to the caller's default for resource decisions.
- [ ] Regression test alongside `TestMultiWorkspaceTargetingE2E`'s pattern (fake-based is fine).

## Out of scope

- New verbs or authorization changes; this binds context for reads of existing decisions.
