## Objective

Extend the shared capability projection so each grant reports allowed / denied / unavailable plus a bounded, non-sensitive reason code (missing OAuth scope vs insufficient permission vs authorization-service failure), instead of today's error-collapsed boolean.

## Context

- `lego/backend/internal/members/service.go:310` `Capabilities` and `lego/backend/internal/members/graphql.go:128` `viewerCapabilities(ownerId)` — eight booleans + best-effort role.
- `lego/backend/internal/core/base.go` — `Core.Can` maps checker errors to `false`; false today does not establish that the role caused the refusal (ADR087 requirement 1).
- `lego/backend/internal/core/scope.go` — OAuth scope intersection; a missing scope must be distinguishable from an FGA denial.
- Legacy `false` stays restrictive but reason-unknown; unknown reason enums must fail closed client-side.

## Steps

1. Add an additive tri-state + reason shape beside the existing booleans (keep boolean fields for current callers).
2. Thread checker errors and scope-intersection outcomes into the new shape without logging sensitive detail.
3. Ensure a failed checker yields `unavailable`, never `denied` with an invented role reason.
