# The session page keeps a started sandbox's live conversation stream open after the start settles, holding one of the person's five gateway sessions for up to 4 hours

Why: w6/m564 t004's production run (2026-11-23) found that after Connect > Start the sandbox, the session page's conversation stream that attached while the session read `resuming` stays open once the start settles, until the tab leaves the page. Since m564 t009 it no longer keeps the sandbox, but the gateway counts it against the person's concurrent sessions (`BEX_SSH_MAX_SESSIONS_PER_IDENTITY`, 5, one limiter shared by SSH, web shell and agent attach), so a few started sessions left open in tabs can refuse the person's own Zed with `session limit reached` for up to the 4-hour cap.

- **Evidence.** Session `ags-dc22jkehv52s73bqmmt0` in the `bex` workspace (disposable). Three starts from the dashboard each left one `ssh_sessions` row of the agent attach open from the `resuming` phase on: `ssn-dc22ompknr1s73a6bkog` (12:06:51Z, ended 12:07:36Z only when the tab navigated away, gateway log `agent attach: live splice ended … context canceled`) and `ssn-dc22s9hknr1s73a6bld0` (12:14:30Z to the navigation at 12:22:15Z). The re-attach after the settle wrote its own row, which closed within milliseconds (12:06:56Z, 12:14:35Z), so the first stream is never aborted.
- **Where.** The dashboard's in-place re-attach (`session-conversation-impl.tsx`, the `attachSignal` effect calls `resumeStream()` without ending the stream it replaces), or the gateway's live splice to a sandbox resume started for an editor (`lego/backend/internal/sshgateway/agentattach`), whose driver runs no turn and so never ends the stream (ADR054 D8). Find which one holds it before fixing; ending the replaced stream in the dashboard is the likely one.
- **Done when** a dashboard test shows the re-attach ends the stream it replaces, and on production a start from Connect, with the tab left on the session page, leaves no open agent-attach row once the start has settled.

## 2026-11-23 — the fix shipped; the production check waits for the pin

- **Which side held it.** The dashboard. The gateway's live splice ends only when the request's context does: the client hanging up, or `SessionTimeout`, the 4-hour cap (`lego/backend/internal/sshgateway/agentattach/agentattach.go`, `timedCtx`). The page never hung up: the AI SDK's `HttpChatTransport.reconnectToStream` sends its GET with no abort signal, so neither the `attachSignal` re-attach's `resumeStream()` nor `chat.stop()` could end a stream it had opened, and `useChat` stops nothing on unmount. The settled session's own re-attach is a replay that ends in milliseconds, which is why its rows closed at once.
- **Fix (`40a947b2db`).** `AgentSessionTransport` (`dashboard/src/features/agent-sessions/lib/transport.ts`) does its own reconnect GET with an `AbortController`. Each reconnect ends the stream it replaces before it mints. One replaced before it connected resolves to `null`, the SDK's "nothing to resume", never to an error. `close()` ends the last one, and the conversation column calls it on unmount and on a session switch, which also ends the stream a page left open when the person navigated elsewhere in the dashboard. The column's settled-resume marker is keyed on the attach target too, so an empty conversation reads as connecting through a re-attach instead of flashing "No conversation yet.". ADR047 D9's transport bullet records it.
- **Tests.** `transport.test.ts`: a reconnect ends the one it replaces and `close()` ends the last; a replaced reconnect resolves to `null`; a refused one still errors. `session-conversation-impl.test.tsx`: the `resuming` → sandbox bound → settled re-attaches leave only the newest stream open, unmounting ends it, and an empty conversation stays connecting through a re-attach. Each fails with its part of the fix reverted. `yarn lint` and `yarn test` (845 files) passed.
- **Next.** Once production's pin carries `40a947b2db`, sign in as the QA user, let a session in the `bex` workspace close at its idle timeout, start it by connecting from the Connect menu (since ADR054 D9 the `ssh` login it offers wakes it), and leave the tab on the session page. Once the start has settled, `ssh_sessions` must hold no open `transport = 'agent_attach'` row (no end time) for the session, and the gateway log must show the replaced stream's `agent attach: live splice ended … context canceled` at the settle, not at the tab's departure. Record the times here and close it.
