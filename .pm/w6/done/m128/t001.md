## Objective

`Service.Cancel` closes the deploy row directly, so a deploy canceled mid-build never gets its `build_ended` fact — the feed keeps a `build_started` that never closes. Emit the close on that path, reusing the computation that already exists.

## Context

- `lego/backend/internal/deploys/service.go:706` — `s.Store.CloseDeploy(ctx, deployID, store.DeployCanceled, "")`, the only caller of `CloseDeploy` outside the interface declarations and the PGStore implementation.
- The facts are otherwise produced by `lego/backend/internal/store/reconciler.go:630-665` (`recordDeploy`), which only processes **open** deploys. Once `CloseDeploy` sets `FinishedAt`, the row is terminal and never revisited.
- **The rule already exists — do not write a second one.** `buildEndedStatus` (`reconciler.go:832-851`) handles both cancel cases: `isBuildPhase(current)` → `EventStatusCanceled`, otherwise `EventStatusSucceeded` ("build had finished before the cancel landed"). `buildLifecycleFacts` (`:760-785`) assembles the fact with its `SourceKey` of `"deploy:" + open.ID + ":build_ended"`.
- **Idempotency matters here.** Every fact is idempotent by `source_key` so re-observation across resyncs is a no-op; keep that property so a later reconciler pass cannot double-insert.
- **Do not emit a lone `build_ended`.** `buildStartedAt`'s `dispatched` gate (`reconciler.go:761-764`) withholds *both* facts for a deploy canceled while still queued — there is no build to close. That behaviour is correct and must survive.

## Steps

1. At the cancel path, compute the build lifecycle facts for the row's pre-cancel status and insert them alongside the close.
2. Reuse `buildLifecycleFacts`/`buildEndedStatus` rather than duplicating the outcome rule; if the helpers need to move or be exported for the deploys package to reach them, prefer that over a copy.
3. Preserve idempotency by `source_key`.
4. Confirm the queued-cancel case still emits neither fact.
5. Confirm the ordering is sane: `build_ended` must not predate its own `build_started`.

## Files

- `lego/backend/internal/deploys/service.go` (`Cancel`, around `:706`)
- `lego/backend/internal/store/reconciler.go` if the helpers need exporting

## Acceptance criteria

- [ ] A deploy canceled while `build_in_progress` produces `build_ended` with a canceled outcome.
- [ ] A deploy canceled while queued produces neither `build_started` nor `build_ended`.
- [ ] A deploy canceled after its build finished produces `build_ended` with a succeeded outcome.
- [ ] No double-insert when the reconciler runs afterwards.
- [ ] Cancel's existing behaviour — 200, `status: canceled`, honest duration, consistent detail/list/`deploy_ended` — is unchanged.
