## Objective

A Blueprint consumer's `fromService` `port`/`hostport` carries the target's real serving port, never the parse-time `DefaultPort`. That covers configured-port targets whose port was edited after creation, and image-port targets whose port is only known after build. Mechanism: t001 / ADR089 § Port slice decisions, item 4. References are backend-resolved literals plus the `app.bex.co/service-refs` annotation.

## Context

- Blueprint services compile with `Port: 0` (`lego/backend/internal/apps/deploy.go:2661`), so `idx.servicePorts[req.Name]` is always `DefaultPort` (`:2125-2131`).
- `port` resolves at parse through `resolveRef(..., idx.servicePorts, ...)` (`:2338`, `:3160`). `host`/`hostport` defer only the **slug** (`:2310-2320`). `hostRef.env` formats `<slug>:<parse-time port>` (`:612`) in `resolveServiceRefs` (`:1080`) and `patchDeferredStackServices` (`:1056`).
- `port`/`hostport` may only target a sibling declared in the same Blueprint (`allowExistingServiceHost`, `:2287`). An undeclared existing App can be referenced by `host` only.
- Live bug on `main`: create a Blueprint web→pserv `hostport` pair, then `PATCH /v1/services/{pserv} port=8080` (w4/m121), then resync. The consumer still holds `<slug>:3000`.

## Steps

1. Write failing tests first: the `SetPort` + resync defect, and an image-port target on first apply that must never produce `:3000`.
2. Classify `port` like `hostport`: a deferred `serviceRef`, resolved at apply rather than at parse.
3. At apply, resolve from the target's port:
   - an existing App: `ServicePort()`;
   - a target created in this apply: its CreateRequest's port mode and port. Configured mode gives `EffectivePort()`; image mode gives unknown.

   When the port is known, write the literal: `<slug>:<port>` or `<port>`. When it is unknown, omit the variable.
4. Write `app.bex.co/service-refs` on the consumer: a JSON list of `{key, target (App CR name), property}`, sorted, one entry per `port`/`hostport` reference. Writing the same refs again must be a no-op patch.
5. Keep validation, preview and plan honest. The plan shows `<resolved at deploy>` for an unknown port, never `3000`.
