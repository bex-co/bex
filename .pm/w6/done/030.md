# React hydration error (#418) reproducible on the Environment Group detail page

Why: an uncaught React error on a normal, unauthenticated-free navigation is a real defect signal even before it's root-caused — worth a quick look before it's forgotten.

Navigating to `/env-groups/<id>` (an existing group's detail page) reliably logs a browser console error, reproduced twice in the same session, both times on a fresh `page.goto`:

```
Error: Minified React error #418; visit https://react.dev/errors/418?args[]=text&args[]= for the full message or use the non-minified dev environment for full errors and additional helpful warnings.
```

React error #418 is a hydration mismatch — the server-rendered markup didn't match the client's first render, specifically involving a text node. Not root-caused this run — no time was spent finding which piece of the page's server-rendered text diverges from the client render (candidates worth checking first: the relative/absolute timestamp formatting under "Group Metadata" — `Created`/`Updated`, e.g. "August 22, 2026 at 10:15 PM" — since locale/timezone-dependent date formatting is the single most common cause of this exact React error).

**Not a regression of `w1/done/m81/done/t002.md`** (which already fixed a sitewide #418 caused by `global-search.tsx` reading `navigator.platform` ungated during render). Checked live: `dashboard/src/common/components/dashboard-layout/global-search.tsx:24-33,71` still has that fix's mount-gated `isMac` state — the original cause is fixed and present in the current codebase. Since React error #418 is a generic "hydration text mismatch" code (any diverging text node can trigger it, not just the search-shortcut label), this is a distinct, page-specific mismatch that needs its own root-causing, not a reopening of t002's fix.

Reproduce: sign in, open any existing Environment Group's detail page (`/env-groups/<id>`), check `browser_console_messages` after the page settles.

**Fixed and closed 2026-08-26 (19th `/qa-find-bugs` run).** Root-caused and fixed by `d247d210` ("date-fns format renders in the runtime's timezone... guarded that text node and three same-shape siblings"), which is a confirmed ancestor of the successfully-deployed `8bbc87639b24`. Live re-verified on production: created a fresh `qa-20260826-hydration` Environment Group and loaded its detail page twice from a cold `page.goto` — `browser_console_messages` returned zero errors both times (was a reliable 100% repro before). Fixture deleted during cleanup.
