## Objective

Make the implicit caller→workspace resolution deterministic. `TenantForIdentity` (`lego/backend/internal/store/store.go:275`) is a bare `tenants ⋈ tenant_members` join scanned into a single row — with two memberships, Postgres returns an arbitrary one. Order by membership `created_at` (oldest first) so a multi-workspace caller's implicit workspace is their **default** (first) workspace, matching Render's documented behavior (research finding 7: passing a user id "returns that user's default workspace").

## Context

- `lego/backend/internal/store/store.go:275-282` — the query; `store.go:136-140` — the interface doc to update.
- `w6/done/m11/README.md` t003 — the live observation ("no ORDER BY/deterministic tie-break").
- `.pm/w6/RESEARCH-workspaces.md` finding 7.

## Steps

1. Add `ORDER BY m.created_at, t.id LIMIT 1` (tenant id as the stable tie-break for same-instant rows).
2. Update the interface comment on `TenantForIdentity` to state the default-workspace contract.
3. Extend the real-Postgres store test: an identity with two memberships resolves to the older one, stably across repeated calls.
