# A validator fails when an alert's backing series is dropped by its scrape job's keep-list

Why: `UsageHourNearlyUnmeterable` (w6/m334) shipped with its gauge, its promtool tests, a panel and a passing `obs-coverage-check.sh`, yet Prometheus never stored the series. The bex-api scrape job keeps only `bex_(billing|agent_session|agent_platform_model|sandbox|webhooks|push|api)_.*` (`deploy/gitops/base/prometheus.yaml`). The same job's comment records this failure twice before (webhooks; w2/m72's build alerts on the operator job), so this is its third occurrence. Every check passes because none of them reads the keep-lists.

- **Do:** extend `scripts/obs-coverage-check.sh`, which already extracts each alert's backing series, or `gitops-validate.sh`. For each `bex_*` series an alert reads, require a scrape job whose `metric_relabel_configs` keep regex matches it. Fail closed, naming the alert and the job. Add a regression case with the series removed from the regex. ~45m.
- **Source:** w6/m334's production check, 2026-11-12.

- **2026-11-12 (loopx w6):** done.
  - `scripts/obs-scrape-keep-check.sh` resolves every `bex_*` series an alert reads, through recording rules too. Each must be kept by a scrape job's `__name__` keep regex, or belong to a declared keep-all source: `bex_ssh_` from bex-ssh-gateway, `bex_zot_` from alloy, `bex_cnpg_` from kube-state-metrics. Anything else fails closed and names the alert.
  - `scripts/obs-scrape-keep-check.test.sh` removes `usage` from the bex-api keep-list and expects the failure to name `bex_usage_oldest_unmetered_hour_timestamp_seconds`.
  - Both run in `gitops-validate.sh`, which passes, and are in `gitops.yml`'s path filters.
