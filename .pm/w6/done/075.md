# 075 — Honor Render region filters on Postgres and Key Value lists

Why: Render-compatible callers request a filtered inventory, but bex currently accepts and ignores the datastore region filters while services already honor them.

**Estimate:** ~1h; inbox-sized. **Worker:** worker6. Approved by the user on 2026-09-30 as item 2 of the Render-only w6 proposal.

## Evidence and goal

- Render documents region arrays on [List Postgres instances](https://api-docs.render.com/reference/list-postgres) and [List Key Value instances](https://api-docs.render.com/reference/list-key-value), checked 2026-09-30.
- `lego/backend/internal/postgres/rest.go` and `lego/backend/internal/keyvalue/rest.go` do not consume region. `lego/backend/internal/api/list_query_contract_test.go` explicitly exempts both routes.
- ADR018's List-query census records this unimplemented placement filter. This closes that specific gap under Postgres CRUD and Key Value CRUD, advancing ADR008 Render-compatible REST; it does not introduce multi-region provisioning.

## Scope

1. Read region arrays with the existing list-query convention and apply literal matching against each resource's reported region before pagination, following service-list semantics.
2. Cover repeated/comma-separated input as supported by the composed contract, composition with name/environment/time filters, omitted region, matching and nonmatching placement, and paging.
3. Remove only the two region exemptions from the query census guard and update ADR018's recorded omission. Preserve the separate includeReplicas omission.

## Acceptance

- [x] A nonmatching region returns an empty list; omission preserves the ordinary inventory.
- [x] Multiple regions use OR matching and compose with other filters before cursor/limit selection.
- [x] Match the real configured placement; never equate `fsn1` with Render's `frankfurt`. Preserve the reviewed REST enum gate and document any remaining inability to request a bex-specific region through that gate.
- [x] Focused handler and composed-server tests pass, including a matching-region fixture; query census no longer exempts region for these endpoints.
- [x] ADR018 documents the exact result without claiming multi-region deployment or full region-enum parity.

No new GraphQL/MCP parameters, deployment regions, region aliases, replica-list work, or infrastructure changes. Render parity applies to the existing REST list filter only.

## Completed — 2026-10-02
