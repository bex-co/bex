1. Render's `^exs-…` pattern vs bex's `blp-` ids → `400 invalid path parameter "blueprintId"`.
2. Render's four blueprint operations declare no `ownerId`, which every bex handler reads → `400 request contains an unsupported query parameter` for any call naming a workspace.
3. Blueprint verbs returned raw store errors → `500 internal error` instead of 404, on REST **and** GraphQL **and** MCP.

Fixing only (1) would have moved the failure one line down; fixing (1)+(2) would have satisfied "no longer 400" while turning it into a 500, which the DoD's "correct **distinct** outcome (404 / 403)" bullet explicitly rules out. All three are fixed, each proven red pre-fix by disabling its own effect in isolation.
