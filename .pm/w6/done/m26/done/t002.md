## Objective

Serve `GET /v1/services/{serviceId}/instances` with the array shape the generated Render client decodes, while preserving bex's established not-found and authorization behavior.

## Context

- `cli/pkg/client/client_gen.go` issues an unactioned GET to `/services/{serviceId}/instances` and requires HTTP 200 plus a JSON array.
- Service REST routes are registered together in `lego/backend/internal/apps/rest.go`; decide explicitly whether the bex `/v1/apps/{id}/instances` alias should mirror the new handler.

## Steps

1. Add the thin REST handler over the service-layer method.
2. Register the Render route with the existing service route family.
3. Use `core.WriteErr` for missing/forbidden/internal failures and `core.WriteJSON` for the successful array.

## Files

- `lego/backend/internal/apps/rest.go`
- `lego/backend/internal/apps/` service-instance implementation

## Acceptance criteria

- [x] The official generated client's request path receives HTTP 200 and a decodable `[]ServiceInstance` body.
- [x] Missing and unauthorized services use established bex error envelopes and do not leak Pod data.
- [x] Any `/v1/apps` alias decision is documented and tested.

## Out of scope

- Changing or regenerating the unmodified Render CLI client.
