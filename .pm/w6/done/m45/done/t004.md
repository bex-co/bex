## Objective

Three smaller, lower-confidence observations from the same hunt, each needing fresh reproduction and root-causing (unlike t001-t003, none is pinned to an exact file:line yet). Fix each, or write up why it's not a bug.

## Context

1. **Live-tail reconnect duplicates log lines.** During the `qa-20260822-hello-py` build, the log panel showed every line duplicated at the identical displayed timestamp immediately after a "Live tail disconnected — reconnecting…" indicator. `dashboard/src/features/logs/hooks/use-live-logs.ts` already has a dedupe keyed on `timestamp|instance|message` (`dashboard/src/features/logs/lib/map.ts:15-21`, `logLineKey`). Investigate why it didn't catch this — plausible: the reconnect replay re-timestamps at receipt rather than preserving the original emission time, defeating the key (unconfirmed — raw SSE payloads for the duplicate pair were not inspected this run).
2. **New Web Service form doesn't re-run runtime auto-detect on Root Directory change.** Selecting a repo (e.g. `bex-co/bex`) defaults Runtime to "Node" with `npm install`/`npm start`. Setting Root Directory to a Go subdirectory (`examples/hello-go`) leaves Runtime on "Node" and the Build/Start Command on the npm defaults — the user must manually reselect Runtime (which then correctly fills `go build -o app .` / `./app`). Find the auto-detect trigger in the New Service form and make it re-run on Root Directory change, or document why it's create-time/repo-selection-only.
3. **Deploy detail page: commit message + date render with no separator.** `"...Docker build contextAugust 22, 2026 at 6:16 PM"` — screenshot `qa-deploys-1-text-concat.png`. Find the component rendering the deploy's commit-message + timestamp paragraph and add a separator/line break between them.

## Outcome

1. **Live-tail reconnect duplicates log lines — ALREADY FIXED, no new change.** Root cause was exactly the suspected one, and it was fixed hours before this milestone was filed: commit `6e35aa9a` (w9/053) made `logLineKey` normalize the timestamp to epoch milliseconds (`dashboard/src/features/logs/lib/map.ts:26-33`) so a reconnect replay whose stamp was re-rendered at a coarser sub-second precision keys identically and dedupes. Both consumers benefit: `use-live-logs.ts`'s buffer dedupe (its key set deliberately survives a retry — `attempt` is not part of `subKey`) and `use-deploy-logs.ts`'s `historyKeys` straddle filter. Regression tests already exist and fail without the fix: `map.test.ts:29` ("is timestamp-precision invariant within a millisecond") and `use-live-logs.test.ts:138` ("dedupes a reconnect replay whose timestamp lost sub-millisecond precision"). No further work.

2. **Root Directory runtime auto-detect — NOT A BUG; a missing feature, recorded as a parity divergence.** The premise ("auto-detect exists but doesn't re-run") is false: bex has no runtime detection anywhere. `useBuildRuntimeFields` (`dashboard/src/features/services/hooks/use-build-runtime-fields.ts:18-20`) seeds `runtime: "node"` plus the matching `RUNTIME_COMMANDS.node` build/start commands as a **static initial value**, and no backend query inspects the repo tree (`grep -ri 'detectRuntime|autoDetect'` across `dashboard/src` and `lego/backend/internal` returns nothing). So selecting a Go subdirectory leaves Runtime on Node with the npm defaults, exactly as observed — but nothing re-runnable exists to fix. Render does infer the language from the repo, so this is a real divergence: recorded as a new **Gap backlog** row in `docs/ADR018-render-parity.md` (closing it needs a repo-tree probe for go.mod / Cargo.toml / package.json / requirements.txt / Gemfile / mix.exs behind a new query, scoped by Root Directory — well beyond this 30m polish task).

3. **Commit message/date spacing — FIXED.** `dashboard/src/features/deploys/components/deploy-header.tsx` separated the commit date from the commit message with a `ml-2` **margin only**, leaving the `<p>` one unbroken text run: the accessibility tree (and any copy of the line) read `"…Docker build contextAugust 22, 2026 at 6:16 PM"`. Replaced with a real ` · ` text separator. Regression test `deploy-header.test.tsx` "separates the commit message from the commit date with real text", proven red on the pre-fix code (`expected 'abc1234 fix: Docker build contextJuly…' to match /Docker build context\s+·\s+\S/`).
