## Outcome

`/simplify` run over the t001-t005 diff (three parallel reuse / quality /
efficiency reviews). Applied:

- **`secrets/files.go` — one projection mechanism, not two.** The new env-var
  leg had copy-pasted `prepareSecretFiles`'s 22-line write tail. Extracted
  `prepareProjection` (store put → ownerless Secret → roll the store path back
  if the Secret write fails), `adoptPreparedSecret` (the Get/SetControllerReference
  /Update the commit phase does), and `abortProjection`. `commitSecretFiles`/
  `abortSecretFiles` now delegate to them, so the files leg lost its duplicate
  copies too — net simpler than before this milestone.
- **Symmetric empty-input guards.** `prepareSecretFiles` grew the same
  `len(x) == 0 → nil` top guard `prepareCreateEnvVars` had, so the adapter is two
  unconditional calls instead of one guarded and one not.
- **Param sprawl.** `envLiterals` was threaded beside `req.SecretFiles` through
  `materializeNewApp`/`writeNewApp`. Both are now one `createSeed{files, env}` —
  the things a service is born with that do NOT live on its spec — and
  `writeNewApp` lost a parameter rather than gaining one.
- **Dashboard: the refetch triple lived twice.** Hoisted to
  `DEPLOY_REFETCH_QUERIES` in `common/lib/fetch-policy.ts`, consumed by
  `deploy-actions.tsx` and `use-trigger-deploy.ts`. Duplication is what let the
  two drift apart into this milestone's bug.
- **Test duplication.** `TestSecretFilesThreadThroughGraphQLAndMCPCreate` and the
  new env-var surface test were near-identical; merged into
  `TestCreateTimeSecretsThreadThroughEverySurface`, which asserts both payloads
  on all three surfaces (REST included, which the old test lacked).
- **Stale docs** from the `SecretFileSeeder` → `CreateSecretsSeeder` rename, and
  a comment that restated the doc comment five lines below it.

Declined, with reasoning:

- **Guard `AbortCreateSecrets` by the spec references** (saves 2 round-trips on
  a failed create). Kept unconditional: it is the second chance to clean up when
  `prepareProjection`'s own inline rollback fails *before* the spec reference is
  set. Failure-path-only cost; the shared helper removed the duplicated
  `scopeApp` that motivated most of the finding.
- **Replace the commit phase's Get+Update with a merge patch.** Once-per-service
  path, and it would rewrite pre-existing code for no measurable gain.
- **Pre-check in `takeCreateEnvLiterals` to avoid an allocation.** One small
  slice per create.
- **Delete `TestCreationTimeEnvVarIsVisibleOnEverySecretsReadSurface` as
  redundant.** It is the explicit t005 deliverable and is not covered elsewhere:
  the existing `TestREST_EnvVars`/`TestMCP_EnvVars` write through their own
  verbs, never through the create-time seeder.
- **Add `"Server"` to `use-service-lifecycle.ts`'s restart refetch.** Not a bug —
  see t003's note; it refreshes the header through the caller's `refetch`.
- **`events.tsx`'s redundant `onChanged` refetch.** Pre-existing, unrelated to
  this milestone's diff.
