## Objective

Add the failing test first: an edge-cached web service projected with helper image A, then re-projected with image B and nothing else changed, must keep its pod template.

## Context

- Model: `TestNoRedirectProbeIsAdoptedOnTheNextRollNotOnUpgrade` (`lego/operator/internal/controller/health_probe_test.go:126`), helpers `project`, `execParams`, `httpHealthApp`, `equalPodTemplate`.
- An edge-cached app: `Spec.Tier = "pro"`, `Spec.CacheProfile = appv1alpha1.CacheProfileStatic`; set `deploymentParams.edgeCacheImage`.
- The brainstorm's scratch test showed both the `edge-cache` container and the `bex-health-probe-install` init container moving to image B.

## Steps

1. Write `TestEdgeCacheImageIsAdoptedOnTheNextRollNotOnUpgrade`: unchanged on upgrade; a restart (`Spec.RestartedAt`) or a new release adopts B for both images.
2. Confirm it fails on current main.

## Done — 2026-11-19 (already met by w3/m489)

- On `e9890d5ad` a sidecar-era version of this test failed for a controlled and a pre-w3/m486 sidecar, and for a purge, a switch and turning caching off over a new image. Each failure named both moved containers: `container bex-health-probe-install image: "…1111" -> "…2222"; container edge-cache image: "…1111" -> "…2222"`.
- While this item was in flight, w3/m489 (`a6b1658fb`, 2026-11-19 03:27Z) replaced the sidecar with a per-service cache tier, and its rule is this milestone's. A pod template stored with the sidecar keeps it exactly as stored, image included, while nothing else changes. That is `TestAnUpgradeKeepsAStoredEdgeCacheSidecarUntilTheTemplateChanges`, whose "a helper image" case is this test. The tier keeps its image until a successful deploy (`TestTheTierKeepsItsImageUntilASuccessfulDeploy`). So the sidecar-era test was not shipped. t003's guard is the red-then-green proof on the new design: it fails on `e9890d5ad` and passes on `fcab36ede`.
