## Objective

As in deploy.yml (`f258c8a49`): one `setup-trivy`, then scans reuse it; run 42037362778 failed on a Trivy install.

## Context

- `.github/workflows/native-base-image.yml` (TRIVY_CMD wrapper ~157-221)

## Acceptance criteria

- [x] No nested setup-trivy download per scan

## Done — 2026-11-16

- **Deviation:** native-base has only one Trivy scan. A separate `setup-trivy` plus `skip-setup-trivy` (the deploy.yml pattern) would still fetch Trivy through `contrib/install.sh` in a single curl attempt, and that is the download that failed run 42037362778 (attempt 1, "scan amd64 candidate", install.sh exit 1).
- **What shipped instead:** `scripts/install-trivy.py` installs the reviewed Trivy 0.70.0 archive. That is the version trivy-action v0.36.0 and deploy.yml install. Its `Linux-64bit` and `Linux-ARM64` sizes and sha256s match both `trivy_0.70.0_checksums.txt` and the GitHub asset digests (checked 2026-11-16).
- **Shared core:** the installer reuses install-syft.py's transport retries, integrity checks and single-binary extraction (`install_release`).
- **The scan:** it runs with `skip-setup-trivy: true`, so the job makes no nested setup-trivy download.
- **Verified:** a real install of both installers in Linux arm64 and amd64 containers produced `trivy --version` 0.70.0 and `syft version` 1.55.0.
