## Done (2026-11-20, after t006)

- **The manager-exit rule now has a seam and tests.** Both mains ran the same goroutine: wait for `mgr.Start` to return, leave Serve alone when the signal stopped it, otherwise log the error and hard-stop Serve. It is now `sniproxy.HardStopOnManagerExit` (`internal/sniproxy/serve.go`), and both mains call it. Without a test, dropping its signal check would have turned every release's drain into a hard stop, and only a live roll would have shown it.
  - `TestAManagerStoppedByTheSignalLeavesTheDrainRunning` wires it to the harness's `Serve` the way the mains do: one context is the drain's start and the manager's stop. After the signal and the manager's return, Serve is still running and the open stream reads a reply written after the signal.
  - `TestAManagerThatExitsOnItsOwnStopsServeAtOnce`, with an error and cleanly: the stream closes within 1 s, Serve returns, every slot is free, and only the error is reported.
- **Each rule reverted in turn, and a test failed:**
  - no signal check: `the manager's return on the signal hard-stopped the drain`;
  - no hard stop: `still open after 1s` (both subtests);
  - no error report: `the manager's error lost the API server was not reported`;
  - a nil error reported: `a clean exit reported <nil>`.
- **The second signal gets no seam.** `ctrl.SetupSignalHandler` exits the process on a second signal, which controller-runtime documents and tests itself. Serve's half, a hard stop during a drain closing at once, is `TestAHardStopDuringADrainClosesAtOnce`. Kubernetes never sends a second signal: the kubelet sends `SIGKILL` when the 40 s grace ends.
- **The rest of the § Progress record still holds** on the shipped code (`go test -race ./internal/sniproxy/ ./cmd/kv-sni-proxy/ ./cmd/pg-sni-proxy/`).
- **No trivial, tautological or snapshot-only test was added.** Both new tests drive real TCP streams through `Serve` and fail on the reverts above.
- **The change moves both SNI pins on its deploy.** `internal/sniproxy` is linked by both binaries, so the next pin rolls both DaemonSets. Both sides of that roll run the drain, which t006 § Step 2 measured on production.
