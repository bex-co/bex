# A native service with a root directory runs from `/opt/render/project/src`, not Render's `/opt/render/project/src/<rootDir>`

Why: a Node, Python, Ruby, Elixir or Rust service with a root directory, whose disk is mounted where Render puts the root directory, writes its relative files into the image on bex and loses them on every deploy. This is the same silent data loss w6/m546 fixed for Go.

- **Render:** the repository is at `/opt/render/project/src`, and "Render runs commands and interacts with files relative to your service's root directory" ([render.com/docs/monorepo-support](https://render.com/docs/monorepo-support), read 2026-11-20). Build errors Render users published for a root directory `backend` name `/opt/render/project/src/backend/…`, and Render's own advice for such a service sets `PYTHONPATH=/opt/render/project/src/backend`. So a service with root directory `backend` runs in `/opt/render/project/src/backend`, and a disk for its `uploads/` belongs at `/opt/render/project/src/backend/uploads`.
- **bex:** the build context is the root directory alone. `nativeDockerfile` copies it into `nativeWorkdir` (`lego/operator/internal/build/native.go`), so the service runs in `/opt/render/project/src`, and its `uploads/` is `/opt/render/project/src/uploads`. A disk at Render's path then holds nothing the app writes. Since w6/m546, Go appends the root directory (`nativeGoSourceDir`) and the other runtimes do not.
- **Do:** give every native runtime `/opt/render/project/src/<rootDir>` as its working directory. Keep the root directory's contents there. An existing service's disk under `/opt/render/project/src/…` must keep landing in its tree, for example through a link from the old path to the new one. Picking that mechanism is the design step. Then move what is keyed to `nativeWorkdir` along with it: the Python virtualenv (`nativePythonVenv`, Render's `src/.venv`), the Rust and Elixir dependency directories (`depscache.go`), the static publish check, and the publish Job's extract. Check first whether Render's virtualenv and caches sit at `src/` or at `src/<rootDir>/`.
- **Done when:** on production, a Starter Node service in `bex-canary` with root directory `backend` logs `pwd=/opt/render/project/src/backend`. A file it writes to `uploads/` by relative path, under a disk at `/opt/render/project/src/backend/uploads`, survives a deploy. The same file written by a service built before the change survives that service's next deploy.
