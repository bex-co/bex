## Objective

`use-create-environment.ts` shares the identical bare-`catch {}` shape as projects' pre-fix hook, and a grep of `lego/backend/internal/environments/` found no per-type conflict message — meaning environments very likely route through the same generic `store.ErrConflict` path projects do. This was **not** independently live-tested this run. Confirm it first; only then apply the fix.

## Context

- `dashboard/src/features/environments/hooks/use-create-environment.ts:40-41`:
  ```
  } catch {
    toast.error(t("environments.createError", { name }));
  }
  ```
- No `ErrConflict`/uniqueness-check hits in a grep of `lego/backend/internal/environments/*.go` — unlike projects, which also had no local `ErrConflict` reference but was confirmed live to return one anyway (routed through the shared store layer). Environments plausibly work the same way, but this is inference from code shape, not a live result.

## Live probe result (2026-08-23, live QA hunt, `/loop 30m` session)

Confirmed live — this is the same bug: created `qa-20260823-duptest` as an Environment in a scratch project (`qa-20260823-envcascade`), then attempted to create a second Environment with the identical name in the same project (confirming the uniqueness scope is per-project, matching projects' own scope). The UI showed the generic `"Failed to create environment \"qa-20260823-duptest\"."` toast. A direct GraphQL probe of the same mutation (`createEnvironment(name, projectId)`) returned:

```json
{"data":{"createEnvironment":null},"errors":[{"message":"conflict: environment: already exists","locations":[...],"path":["createEnvironment"]}]}
```

So the backend does return a specific, if terse, conflict message (`"conflict: environment: already exists"`) — `use-create-environment.ts:40-41`'s bare `catch {}` discards it exactly as inferred. Not a silent-upsert or different-shape finding; step 3's fix applies as designed. All `qa-20260823-*` resources from this probe were deleted (Key Value instance, both projects/environments created for this check and the sibling `w6/033` cascade-deletion test run in the same session).

## Decision

Same as t004 for projects: the backend message needed the name added — "conflict: environment: already exists" named nothing. Added the identical `conflictOrMapError` pattern to `lego/backend/internal/environments/service.go`'s `create` helper (both the transactional-quota and plain branches), returning `core.NewConflictError("CONFLICT", fmt.Sprintf("an environment named %q already exists in this project", name), nil)` on `errors.Is(err, store.ErrConflict)`. `use-create-environment.ts`'s bare `catch {}` is now `catch (err)`, branching on `isNameConflictError(err)` to `toast.error(refusalReason(err))`.

Toast changed from the old generic error to: **"An environment named "m49-env-ui" already exists in this project"**. Test resources deleted after.
