## Objective

Regardless of what caused `t001`'s specific incident, the operator's reconcile currently has no type-level backstop preventing a `private_service` from getting a public Ingress route — it relies entirely on `spec.Expose` staying `false` forever, with no second gate. Add the same kind of hard type check `background_worker` already gets, so a future bad `Expose`/`Host` value (a bug, a race, a malicious/compromised caller with API access) can never again route a private service publicly.

## Context

- `lego/operator/internal/controller/app_controller.go:1606-1608`:
  ```go
  // A background_worker runs the image with no HTTP port: a bare Deployment, no
  // Service, no Ingress, no URL, no auto-sleep (nothing routes traffic to wake it).
  worker := app.Spec.Type == appv1alpha1.TypeBackgroundWorker
  ```
  Only `background_worker` (and, earlier in the same function, `cron_job` and `static_site` via separate early returns) diverge from the general path. `private_service` and `web_service` both fall through identically to `applyClusterIPService` (line 1660) and then unconditional `hosts := effectiveHosts(app, r.BaseDomain)` (line 1669) → `reconcileIngressWithMiddlewares` (line 1678).
- `lego/types/v1alpha1/app_types.go:700-717` (`EffectiveHosts`):
  ```go
  func (s AppSpec) EffectiveHosts(name, baseDomain string) []string {
      var hosts []string
      ...
      add(s.Host)  // <-- unconditional, no Expose check, no Type check
      if s.Expose && baseDomain != "" && s.SubdomainPolicy != SubdomainPolicyDisabled {
          add(s.PlatformSubdomain(name) + "." + baseDomain)
      }
      for _, h := range s.Hosts {
          add(h)
      }
      return hosts
  }
  ```
  Note `add(s.Host)` and the `s.Hosts` loop fire with **no gate at all** — even if `Expose` is correctly `false`, a directly-set `spec.Host` or `spec.Hosts` entry (e.g. a custom domain add on a private service — check whether the dashboard/API even blocks that today) would still get Ingress-routed.

## Steps

1. Add a `spec.Type == appv1alpha1.TypePrivateService` check that short-circuits host computation to zero hosts before any Ingress is created — either inside `reconcileKubernetes` (mirroring the `worker` pattern) or inside `EffectiveHosts` itself (cleaner: one function every consumer already calls, including the static-server resolver and bex-api's own `maintenanceHosts`/pending-URL projection per its doc comment).
2. Decide and document: should a private service be allowed to set `spec.Host`/`spec.Hosts` at all (custom domains), or should that be rejected at the API layer for that type too? At minimum, the operator must never turn any of `Host`/`Hosts`/`Expose`-derived-subdomain into a live Ingress rule for `private_service`.
3. Add a controller-envtest: create a `private_service` App, then directly patch `spec.Expose = true` (bypassing bex-api entirely, simulating any future bad write) and separately `spec.Host = "should-not-route.example.com"` — assert in both cases that no Ingress object is ever created for that App, and reconcile does not error.
4. Confirm `web_service` and `static_site` are unaffected (their existing envtest coverage should still pass unchanged).
