## Objective

When the gateway process gets SIGTERM, it closes its SSH and Web Shell listeners so no new connection reaches it, and keeps every established SSH and Shell session running until the session ends on its own, its access is revoked, its instance stops, or a drain bound of one hour passes. Then it closes what is left and exits.

## Context

- `lego/backend/cmd/ssh-gateway/main.go:84` builds `ctx` from SIGINT/SIGTERM; `gateway.Serve(ctx, listener)` (`main.go:520`) returns when `ctx` ends, then `main` returns and kills every goroutine.
- `lego/backend/internal/sshgateway/nativessh/server.go:305-314`: `Serve` closes the listener on `ctx.Done()`, and each connection inherits `ctx` ("cannot outlive a terminating gateway process"). This contract changes.
- The Web Shell runs on `startAuxListener("web shell", …)` (`main.go:436`, `internal/sshgateway/webshell/websocket.go`). Its sessions are hijacked WebSocket connections, which `http.Server.Shutdown` neither tracks nor waits for, so they need their own wait group.
- Access revalidation (w4/m352, `internal/sshgateway/revalidate.go`) and the 4 h session cap (`webshell/websocket.go:116`) must keep running on a draining pod.
- Render: "Render gives existing connections one hour before automatically closing them" ([render.com/docs/ssh](https://render.com/docs/ssh)).

## Steps

1. Split the lifetime in two: a listen context cancelled by SIGTERM (stops accepting), and a session context that ends at the drain bound (`BEX_SSH_DRAIN_SECONDS`, default 3600) or on a second signal.
2. In `nativessh.Server`, track live connections and let `Serve` return only after they finish or the session context ends; keep revalidation ticking.
3. Do the same for Web Shell WebSocket sessions.
4. At the bound, close each remaining session with an end reason the Shell page already classifies (w4/m352 t002), not a bare EOF.
5. Log the drain start, the number of sessions held, and each exit.

## Out of scope

- Moving sessions between pods
- Not restarting the gateway when its binary is unchanged (the w6/m470 approach): the backend changes almost every deploy

## Record (2026-11-18)

Done. `cmd/ssh-gateway/main.go` now runs two lifetimes: `ctx` (the listeners', ended by the first SIGTERM/SIGINT through `drainOnSignal`) and `sessionCtx` (the sessions', ended with `sshgateway.ErrGatewayShutdown` at the bound or by a second signal). `nativessh.Server.Shutdown(ctx)` closes the listener and waits for the open connections (counted by the new `sshgateway.Inflight`), which keep running under `Serve`'s context; `serve()` + `drain()` in `main.go` wait up to the bound, end the rest, and give them 10 s (`drainGrace`) to send their end reason and audit row. The Web Shell rides the auxiliary-listener drain (t002): its requests run under `sessionCtx` (`http.Server.BaseContext`) and `Inflight.Handler` counts the hijacked WebSockets; at the bound a Shell ends with the `timeout` reason the Shell page already names. `/readyz` on `:9090` turns 503 once the listeners close. Revalidation and the 4 h cap are untouched and keep running on a draining pod. Logs: drain start with each listener's open-session count, each session end while draining, the bound, and `drained`.

Deviation: the bound is `BEX_SSH_SHUTDOWN_TIMEOUT` (a Go duration, default `1h`), not `BEX_SSH_DRAIN_SECONDS`: every sibling (`BEX_SSH_SESSION_TIMEOUT`, `…_HANDSHAKE_TIMEOUT`) is a duration, and `BEX_SSH_DRAIN_BUFFER_*` already means the exec output buffer (w6/099). Documented in `lego/backend/AGENTS.md`.
