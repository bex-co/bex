## Objective

After a roll that replaces every control plane, the kubeconfig fetch still succeeds with strict host-key checking and nobody edits `BEX_SSH_KNOWN_HOSTS`.

## Context

t004 (2026-10-29) showed that the mid-roll retry covers partial rolls only. Choose one of the t001 options (see README § Gate — 2026-10-29): (a) stable host keys from an in-cluster secret, written by KCP `files`/`preKubeadmCommands`; (b) automated re-pin over the authenticated kube API, which needs a GitHub credential able to write environment secrets; (c) a CI-custodied kubeconfig. **Chosen 2026-10-29: option (a)** (README § Decision — 2026-10-29 (t008)).

## Acceptance criteria

- [x] The chosen mechanism is implemented and tested, and ADR019 is updated.
- [x] No step in a routine roll needs a human (proven live by t009).
