## Objective

Prove the refreshed builder and run images build and run real apps before production picks them up.

## Context

- `bash scripts/dev-env.sh 6 up`

1. Bring up dev-6.
2. Build and run hello-go; build and run a Node or Python buildpack app.
3. Run the build qualification checks ADR060 names.

## Done — 2026-11-16

- **Setup:**
  - The shared mock cluster was down: every node had exited after a Docker restart. The plain bring-up could not restart it in place, so it was rebuilt with `bash scripts/mock-cluster.sh reprovision`, as its own diagnostic directed. That wiped every dev-N's data on it; none was running.
  - `mock-cluster.sh operator` deployed `bex-operator:dev` built from this change's tree, whose config carries the new builder digest. `dev-env.sh 6 up` brought up dev-6.
- **Builds:** three native services were created through dev-6's REST API from `bex-co/bex` main, each with its own build and start commands. All three reached `live` with `Build successful 🎉`:
  - `examples/hello-go` built as `runtime: go`. Its log reads `Using Go 1.27 (default)`, and the running image reports `go1.27.4`.
  - `examples/hello-node` built as `runtime: node` (`engines.node >=20`). Its log reads `Using Node 26.13.1`, and the container runs Node v26.13.1, pnpm 10.34.9 and Yarn 1.22.22.
  - `examples/hello-python` built as `runtime: python`. Its log reads `Using Python 3.14.10 (default)` and `Using Node 24.22.3 (default)`, and the container runs Python 3.14.10, the v24.22.3 companion and pnpm 10.34.9.
- **HTTP:**
  - All three answered `200 hello from <name>` on their Services.
  - Through the Traefik edge (`https://<name>.onbex.co`), the Go app answered 200, but the Node and Python apps returned 504. This is not the toolchain. Those two pods ran on the tenant-pool node, and the Traefik pod cannot reach any pod on that node, even though the namespace's `allow-traefik-ingress` admits it. The same pods answer cross-node from inside their own namespace.
- **Real BuildKit checks** (`BEX_BUILDKIT_INTEGRATION=1`, run on a local buildx builder):
  - Passed: `TestNativeGoBuildsCurrentAndOldModules`, `TestNativeImageStartsWithEmptyPATH`, `TestNativeImageRunsPoetry`, `TestNativeImageRunsPnpm`, plus the remaining runs listed in t006.
  - These pulls went through `mirror.gcr.io` (same digests), because this host's anonymous Docker Hub quota was at 0 of 100/h.
- **Not covered here:** the kpack buildpack path (the new Paketo builder and stack). The mock cluster installs no kpack, so the ClusterBuilder is first exercised by production after deploy (Closeout).
- The three probe services were deleted afterwards.
