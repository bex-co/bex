## Objective

On SIGTERM the activator keeps serving through the endpoint-withdrawal window, then stops accepting and waits for held and proxied requests up to a bound before it exits.

## Context

- `lego/operator/cmd/activator/main.go:147-157` (`http.Server`, `ListenAndServe`, `os.Exit(1)`); `hold.go` (`holdBound` 90 s, hold slots, `proxyResponseHeaderTimeout`).
- Every path belongs to the tenant (`main.go:165`), and readiness is a TCP probe, so the drain cannot flip an HTTP readiness path; Kubernetes withdraws a terminating pod's endpoint itself, and Traefik needs a moment to notice.
- The operator may not import `lego/backend/internal/serve` (depguard); implement here, or move a shared helper into `lego/types` if that is simpler and allowed.
- `Shutdown` does not wait for hijacked connections (a WebSocket proxied through a hold); record that limit.

## Steps

1. Catch SIGTERM/SIGINT; keep serving for a short window (e.g. 5 s, configurable), then call `srv.Shutdown` with a bound of `holdBound` plus a margin.
2. Exit 0 on a clean drain.

## Record

Done 2026-11-18. `cmd/activator/drain.go`: `listenAndDrain` installs `ctrl.SetupSignalHandler` (a second signal exits at once) and `serveUntilDrained` keeps accepting for the window (`BEX_ACTIVATOR_DRAIN_SECONDS`, default 10 s, documented in `lego/operator/AGENTS.md`), then calls `Shutdown` with a 120 s bound (`holdBound` + 30 s) and exits 0 once idle. Deviation: the drain also counts running handlers, because `Shutdown` forgets hijacked connections and the reverse proxy hijacks every upgrade, so a WebSocket shorter than the bound ends on its own terms.
