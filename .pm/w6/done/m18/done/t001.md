## Objective

Add an optional `ownerId` query/body param to the REST endpoints for usage, API keys, and GitHub connections, threading it through to `core.WithWorkspace` so a membership-checked non-default workspace can be targeted explicitly — mirroring the `w6/m14` create-path pattern.

## Context

- `lego/backend/internal/usage/service.go:118`, `lego/backend/internal/apikeys/service.go:107`, `lego/backend/internal/github/service.go:79` — all currently resolve via `Base.Tenant(ctx)` (caller's default workspace only).
- `w6/m14`'s `core.Base.resolveWorkspace` / `core.WithWorkspace` already implements the membership-checked override — these three call sites need to *pass* an explicit `ownerId` through to it, not new authz logic.
- Naming a workspace the caller isn't a member of must 403, per the established convention (`core.Base.resolveWorkspace`).

## Steps

1. Add `ownerId` query param to `GET /v1/usage`.
2. Add `ownerId` query param to API-key list, and `ownerId` body field to API-key create (which workspace the new key binds to).
3. Add `ownerId` query param to the GitHub connection status/list endpoint.
4. Thread each through `core.WithWorkspace(ctx, ownerId)` before calling the existing service methods.

## Files

- `lego/backend/internal/usage/rest.go`
- `lego/backend/internal/apikeys/rest.go`
- `lego/backend/internal/github/rest.go`

## Acceptance criteria

- [ ] `GET /v1/usage?ownerId=tea-B` for a caller who is a member of both A and B returns B's usage, not A's.
- [ ] Naming a workspace the caller is not a member of returns 403 on all three endpoints.
- [ ] Omitting `ownerId` preserves today's default-workspace behavior (byte-identical).

- GraphQL/MCP (t002/t003), dashboard threading (t004).
