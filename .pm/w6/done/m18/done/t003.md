## Objective

Make `get_usage`, the api-key tools, and the GitHub-connection tool honor the established MCP workspace-targeting precedence (explicit `ownerId` arg > the session's `select_workspace` selection > default), matching how `create_web_service`/`create_cron_job`/`create_static_site` already behave per `w6/m14`.

## Context

- `lego/backend/internal/usage/mcp.go`, `lego/backend/internal/apikeys/mcp.go`, `lego/backend/internal/github/mcp.go`.
- `core.SelectedWorkspace` is the existing precedence helper `w6/m14` introduced for create tools.

## Steps

1. Add an optional `owner_id` arg to `get_usage`, `create_api_key`/`list_api_keys`/`revoke_api_key`, and the GitHub connection tool.
2. Route each through `core.SelectedWorkspace` the same way the create tools do.

## Files

- `lego/backend/internal/usage/mcp.go`
- `lego/backend/internal/apikeys/mcp.go`
- `lego/backend/internal/github/mcp.go`

## Acceptance criteria

- [ ] An agent that calls `select_workspace(tea-B)` then `get_usage` (no explicit arg) gets B's usage.
- [ ] An explicit `owner_id` arg on any of these tools overrides the session's selected workspace.

## Out of scope

- REST/GraphQL (t001/t002), dashboard threading (t004).
