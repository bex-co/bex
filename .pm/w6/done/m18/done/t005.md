## Objective

Prove, against a real Postgres + OpenFGA, that a multi-workspace caller reaches the named workspace's usage/api-keys/GitHub-connection data when targeting it explicitly, and their default workspace's otherwise — mirroring `w6/m14`'s `TestMultiWorkspaceTargetingE2E`.

## Context

- `TestMultiWorkspaceTargetingE2E` (from `w6/m14`) is the precedent to extend or sibling.
- Needs `BEX_TEST_DB_URI`/`BEX_TEST_OPENFGA_URL` (integration test gate, per repo CI conventions).

## Steps

1. Set up a caller with membership in workspace A (default, oldest) and workspace B.
2. Assert: `GET /v1/usage?ownerId=B` returns B's rollups; omitting `ownerId` returns A's.
3. Assert: `create_api_key` with `owner_id=B` binds the new key to B (verified via a subsequent `list_api_keys(owner_id=B)`).
4. Assert: naming a workspace C the caller does not belong to 403s on all three surfaces.

## Acceptance criteria

- [ ] Test passes against real Postgres + OpenFGA in CI.
- [ ] Test fails if any of the three surfaces regresses to default-workspace-only resolution.
