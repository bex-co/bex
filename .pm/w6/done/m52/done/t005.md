## Findings (2026-08-24)

**Cross-surface: agree by construction, asserted anyway.** `AppView.Phase` (`apps/service.go:347`) is one field with one `json:"phase"` tag. REST serializes `AppView`, MCP returns it, GraphQL projects `a.Phase` (`apps/graphql.go:321`) — there is no per-surface phase mapping that could fold `Canceled` back into `Failed`. `TestCanceledPhaseReachesEverySurface` pins the value through the view and the shared JSON wire shape; `TestDeletingPhaseStillWinsOverCanceled` pins that the `Deleting` override still wins, so a service being torn down never reports the stale value.

**Render comparison recorded in `docs/ADR018-render-parity.md`** (Get-service row): Render exposes no service-level status at all — its header renders the latest deploy's status, which for this case reads "Canceled". bex's `phase` is a bex-only extra, which is precisely why it was free to drift out of agreement with the deploy record. Adding the value closes the observable gap without touching a Render-compatible field. No deliberate divergence to track.
