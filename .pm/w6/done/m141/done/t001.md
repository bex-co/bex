## Objective

Introduce typed clients for the existing service/deploy/Postgres/Key Value action projections with a restrictive shared decision representation.

## Context

- w6/m136 exposes serverActions, deployActions, databaseActions, and keyValueActions from execution-side permission/precondition predicates.
- The native operation inventory and generated GraphQL must remain explicit and codegen-owned.

## Steps

1. Select the minimum fields required for target/action permission, blocking precondition, and confirmation; bind reads to the current selected context and exact target.
2. Generate typed documents and update the reviewed scope inventory.
3. Normalize supported action/outcome/reason vocabulary in one small helper; unknown values stay blocked with a generic reason.

## Acceptance criteria

- [ ] All four typed queries validate against the backend schema and contain no sensitive/configuration fields.
- [ ] Unknown action IDs/outcomes/reasons cannot enable an operation.
- [ ] Target decisions cannot be reused for another resource or workspace.

## Out of scope

- Inventing new backend verbs or broad mobile permission scopes.
- Hand-editing generated GraphQL.
