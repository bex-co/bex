# Each read replica has its own endpoint and connection pool, as on Render

Why: Render runs each read replica as its own instance with its own URL and "its own independent connection pool"; bex's named replicas are aliases of one reader Service, so two replicas share one reader pool of `max_connections` − 10 where Render's give each replica its own.

- **Render** ([connection pooling](https://render.com/docs/postgresql-connection-pooling) and [read replicas](https://render.com/docs/postgresql-read-replicas), read 2026-11-17): "Each read replica has its own independent connection pool"; a replica is connected to "just like you do your primary instance, using its internal or external connection URL"; Render's `readReplica` schema has its own `id`.
- **bex** (w6/m458, 2026-11-17): every `<id>-ro-<name>` hostname and the internal host resolve to CNPG's shared `<id>-ro` Service, which also includes an HA standby. Pooling adds one `type: ro` Pooler, `<id>-pooler-ro`, whose pool is one replica's (90 on every current plan). kube-proxy spreads its server connections over the readers, so no reader passes its limit. But with two replicas, they hold 90 together, where Render's hold 90 each. A pool of 90 × readers would not fix it: a ClusterIP spreads connections at random, so at saturation one of two readers would pass its 97 tenant slots in roughly one case in four, and m458 did not size it that way. ADR018's HA row records "names remain aliases to a shared reader pool" without a user sign-off.
- **Do:** give each named replica its own addressable reader: a Service selecting one CNPG instance (`cnpg.io/instanceName`) bound to the name, kept on the same instance across reconciles, and excluding the HA standby. Then give each its own pooler, sized `max_connections` − 10. CNPG's Pooler only targets `rw`/`ro`/`r`, so a per-replica PgBouncer needs either a Deployment bex owns or a CNPG feature; read the deployed CNPG first.
- **Done when:** on dev-6, a database with two named replicas and pooling holds 90 server connections on each replica at once through their pooled URLs, `<id>-ro-<a>` reads only replica `a`'s instance, and the HA standby serves no replica URL. Otherwise, ADR018 records the shared reader pool with the user's sign-off.
