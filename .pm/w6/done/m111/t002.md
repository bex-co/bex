## Objective

Stop the Logs tab asserting "This service hasn't produced any logs yet" about a service that produced logs the selected window excluded — and fix it in a way a third widening of the same predicate cannot miss again.

## Context

- `dashboard/src/features/logs/components/log-viewer.tsx:151,180-183` picks the copy from `filtered = hasActiveLogFilters(queryFilters)`.
- `dashboard/src/features/logs/types.ts:125-131` checks `type`, `text` and `STRUCTURED_FILTER_KEYS` — **the range is not in `LogFilters`**, it is a separate `RangeSelection` (`log-viewer.tsx:134-135`). The chooser structurally cannot see the input that excluded the rows.
- The range is always bounded: `RANGE_PRESETS` (`dashboard/src/features/metrics/lib/range.ts:16-26`) is `30m · 1h · 4h · 12h · 24h · 2d · 7d · 14d · 30d` plus custom absolute windows — no "all time". The Logs tab defaults to `1h` (`dashboard/src/features/logs/lib/log-search.ts:134`). So `logs.emptyBody` (`locales/en.ts:134-136`, `locales/zh.ts:132-134`) makes a claim the page cannot verify.
- **This predicate has been widened twice and missed the range both times:** `w6/m47/t003` added `logs.emptyFilteredTitle` after finding the title and body contradicting each other, and commit `717143ae` ("treat instance filter as active for empty-state copy") folded `instance` in. Widening it a third time repeats the pattern — the shape of the type is the defect.
- Four states already exist or are needed: store-unavailable (already its own branch, `log-viewer.tsx:156-165`), never-logged, empty-window, empty-under-filters.

## Steps

1. Decide where the range belongs so the empty-state chooser sees it by construction — folded into the filter type, or an explicit state enum computed from both. Prefer whichever makes "add a new narrowing input" fail loudly rather than silently, and say why in the milestone README.
2. Place all four states, including which one wins when both a filter and a narrow range are active.
3. Settle what happens to `logs.emptyBody`. If no bounded query can establish "this service has never logged", the honest options are to remove the string or to derive the claim from something that does know. Do not keep asserting it on a guess.
4. Add whatever strings the new machine needs to **both** `en.ts` and `zh.ts`.
5. Re-verify live on `srv-da7o6ovvqdcc73bpn9hg`: Live off + range `Last hour` must not say the service never logged; widening to 6h must then show the nine rows.
