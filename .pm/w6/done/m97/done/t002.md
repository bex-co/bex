## Objective

Prove the t001 fix is exactly as narrow as claimed: an App's own clone/pull secret is accepted, but nothing else that looks similar is.

## Context

- Test file: `lego/operator/internal/controller/protected_secret_test.go`. `TestRejectProtectedSecretRefs` currently only builds the malicious case (`a.Spec.CloneSecret = "bex-tenant-postgres"`, a pre-existing, unrelated protected Secret) inside its `map[string]func(*appv1alpha1.App){...}` table at the "cloneSecret"/"externalRegistryPullSecret" entries — see the file for the exact table shape to extend.
- The four backend call sites that set `spec.CloneSecret` on a real trigger path (for context/blast-radius sign-off, not necessarily each needing its own new operator-level test, since they all converge on the same `rejectProtectedSecretRefs` call in `app_controller.go`'s `Reconcile`):
  - `lego/backend/internal/apps/service.go:1979` (`CreateApp`)
  - `lego/backend/internal/apps/service.go:2665` (`redeployFetched`)
  - `lego/backend/internal/apps/deploy.go:2652` (blueprint-sync redeploy)
  - `lego/backend/internal/deploys/service.go:477` (`triggerFetched` — manual/hook/rollback)

## Steps

1. In `protected_secret_test.go`, add a new test (or extend `TestRejectProtectedSecretRefs`) with a fake client seeded with two additional Secrets in namespace `tea-a`: `web-clone` (labeled protected, simulating this App's own clone secret) and `web-registry-pull` (labeled protected, simulating this App's own pull secret), for an App named `web`.
2. Assert `a.Spec.CloneSecret = "web-clone"` and `a.Spec.ExternalRegistryPullSecret = "web-registry-pull"` (on App `web`) are **accepted** (nil error).
3. Add the sibling **control** case in the same namespace: a second App named `other` with `a.Spec.CloneSecret = "web-clone"` (a *different* App naming App `web`'s own clone secret) must still be **refused** — this is the case that proves the carve-out is self-name-equality, not "any name shaped like `<x>-clone`."
4. Keep the existing "cloneSecret"/"externalRegistryPullSecret" subtests in the malicious-reference table (naming `bex-tenant-postgres`) passing unmodified — they must still refuse.
5. Add a short backend-side test (in `lego/backend/internal/apps` or `lego/backend/internal/deploys`, wherever existing coverage for these call sites lives — check `clonesecret_test.go` in both `deploys` and `apps` packages) asserting that `ensureCloneSecret`'s returned name matches the exact `cloneSecretName(app)` shape the operator-side test now allowlists — closing the loop so a future rename of either function can't silently drift the two sides apart again.
6. Run `go test ./...` in `lego/operator/` and `lego/backend/`.
