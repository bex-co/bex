## Objective

Pass a private service only when another service in the same workspace connects to it over the private network, as Render's guides check it. Reading its internal address is not enough.

## Context

- Today the script's `addr` check reads the internal address and the port the first deploy detected. The result page says why: "A private service's guide checks it from a peer, by connecting to it over the private network. bex runs no one-off jobs … so the script cannot start that peer; `addr` stands in."
- A peer can be an ordinary service. The script can create a small background worker in the same workspace from a public image (for example `busybox`, which has `wget` and `nc`) whose start command connects to `<host>:<port>` and prints the answer, then read that line through `GET /v1/logs`.
- Workers receive no private traffic but can open connections to private services (w6/m640 changed only ingress).

## Steps

1. Add a `peer <service> <port> [text]` check. It creates a worker named `render-examples-live-peer-<repo>` beside the template's resources, waits for its log line, and deletes it in the same cleanup as everything else.
2. Use it in t001's table for every private service, in place of `addr`.
3. Keep `addr` as a fallback only for a template whose port speaks a protocol the peer cannot open in one command, and say so in its row.
