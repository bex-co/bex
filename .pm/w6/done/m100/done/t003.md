## Result

**No wire-shape change, only a liveness fix** — and one deliberate behavioral correction on the *failed* sibling, recorded in `docs/ADR018-render-parity.md`.

- **REST / GraphQL / MCP agree by construction, verified by reading the code, not assumed**: all three read one `DeployView`. MCP literally calls REST's `toRenderDeploy` (`internal/deploys/mcp.go:137,154`), and GraphQL maps `status`/`failureReason` straight off the same view (`graphql.go:37`). The fix changes only which value the shared row holds and when — no field added, removed, or retyped, and the eleven-value status vocabulary is untouched. The existing surface-parity sweeps (`TestEveryDeployStatusFilterMatchesEverySurface`, `TestDeployLifecycleTimestampFilterSurfaceParity`) still pass.
- **Dashboard: no code change needed, confirmed rather than assumed.** `src/features/deploys/lib/deploy-status.ts` already handles all eleven statuses, treats `queued` as cancelable and non-terminal, and stops polling on terminal — so a row that now actually progresses renders and stops correctly with no edit. The Events feed's "Deploy started / In Progress" label renders the `deploy_started` **fact** by type (`src/features/events/components/event-icon.tsx:34`, `service-event-catalog.ts:13`); it is a historical event, never a live-status claim, so it stops being misleading on its own once the row progresses. Confirms the milestone's "no separate UI task needed".
- **Drift recorded** in `docs/ADR018-render-parity.md` (new paragraph beside the w6/m95 one in the Deploys section) and in `docs/ADR004-app-deployment.md` (release-identity bullet for `status.conditions[Build]`, plus the deploy-projection paragraph). The one thing worth calling out for parity: the deploy whose build failed still closes **`build_failed` with its build error**, not `canceled` — Render's behaviour, and what bex did before this milestone by accident; keeping it required the durable condition, because the operator now adopts the queued generation milliseconds after recording the failure while bex-api resyncs every 30s.
