## Result

- **Operator envtest** — `lego/operator/internal/controller/build_failed_pending_release_envtest_test.go`, three specs:
  1. *the race*: gen-1 building → a second trigger lands (metadata.generation 2, `PendingReleaseGeneration=2`, release pinned at 1) → gen-1's Job fails via `PodFailurePolicy`/exit 90 → asserts the verdict is stamped at generation **1**, then that the next reconcile advances `Status.ReleaseGeneration` to **2**, dispatches the gen-2 build Job, and that the gen-1 verdict survives gen-2 starting (Ready has already moved on — which is exactly why Ready cannot be the durable record). Then completes gen-2 and asserts it rolls out.
  2. *w2/m82 anti-regression*: a solo failed generation must not advance, must not re-error, must not requeue, and must meter exactly once.
  3. *operational churn*: a scale bump after a build failure must **not** re-run the doomed build under a new revision (this one is a strict improvement — the old `metadata.generation` comparison would have re-dispatched it).
- **Red-before/green-after, actually run**: with `terminalBuildFailureRecorded` reverted to the pre-fix Ready/`metadata.generation` reading, spec 1 fails and specs 2–3 still pass (`Ran 3 of 151 Specs … 2 Passed | 1 Failed`). With the fix: `3 Passed`.
- **Backend** — `lego/backend/internal/store/queued_behind_failure_test.go`:
  - `TestQueuedRowIsPromotedOnceReleaseGenerationAdvances` closes the DoD's named gap: the `OverlapPending` branch (`reconciler.go`) was only ever tested in its *waiting* state. It now also asserts the row is **promoted** to `build_in_progress` once `appReleaseGeneration(app)` advances — the half that used to wait forever.
  - `TestFailedRowClosesBuildFailedEvenAfterTheReleaseMovedOn` plus the negative cases (no verdict → still `canceled`; another generation's verdict is never borrowed).
  - `TestQueuedDeployBehindFailedBuildReachesTerminalStates` drives the real `Reconciler.recordObservations` over both rows against the post-fix CR: the failed row closes `build_failed` **carrying the operator's build error**, the queued row reaches `build_in_progress` with `started_at` stamped and `overlap_pending` cleared.
  - `TestRollbackQueuedBehindFailedBuildReachesTerminalState` — the same fixture with `CreateRollbackDeploy`, i.e. the second call site the milestone asked for.
  - `TestRecordedBuildFailureNeverRepaintsAClosedRow` — the durable verdict is read only for rows still in a build phase, so Cancel's terminal (and `live`/`update_*`) is never repainted.
  - Red-before verified the same way: with the `supersededDeployStatus` branch removed, three of these go red on `first deploy = "canceled", want "build_failed"`.
- **Cancel**: existing `internal/deploys` Cancel tests re-run green (`go test ./internal/deploys/` ok).
