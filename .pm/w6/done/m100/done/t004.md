## Result

`/simplify` run over the t001+t002 diff with all three reviewers (reuse, quality, efficiency). Findings applied:

**Applied**

- **Collapsed the two build gates onto one accessor.** `terminalBuildFailureRecorded` and `buildOutcomeAlreadyRecorded` now both read `recordedBuildVerdict(app) (reason, ok)`, which removes the third helper and the `reason == ""`-means-any wildcard the first cut needed. The gates can no longer disagree about which generation a verdict belongs to. Kept them as two *named* functions — the names are what makes the call sites readable (dispatch gate vs metering gate), and the doc comment exists to contrast them.
- **Kept the "Build condition present ⇒ decide on it alone" fork explicit**, per the reuse reviewer's warning: folding the nil-check into the match would let a Build condition stamped with a *different* generation fall through to the legacy Ready marker — which post-fix names the *queued* generation, i.e. the exact stranding this milestone fixes. Also documented when `legacyReadyBuildFailure`'s successor branch can be deleted.
- **Fixed a stale comment** at `app_controller.go`'s `PhaseFailed` branch that still called the Ready condition the durable marker after this change moved that role to `ConditionBuild`.
- **Backend reader now uses `meta.FindStatusCondition`** instead of a hand-rolled loop, so both halves of one feature read the condition the same way (`meta` is already used elsewhere in the backend module and is not depguard-restricted).
- **Hoisted the cheap `isBuildPhase` test ahead of the condition scan** in `supersededDeployStatus`, and dropped a redundant `ok` in `recordDeploy` (`recordedBuildFailure` returns a message only when it returns true).
- **Extracted `build_envtest_helpers_test.go`** — `buildJobFor`/`failBuildJob`/`completeBuildJob`. `failBuild` was on its **third** verbatim copy and `completeBuild` its second, and both encode API-server Job-status grammar (FailureTarget must precede Failed; no `completionTime` on a failed Job) that is a real correctness trap. `build_supersede_envtest_test.go` and `build_terminal_requeue_envtest_test.go` now use them — behavior identical, both re-run green.
- **Backend test reuse:** `onlyDeploy`, `buildingApp`, and `newTestReconciler` replaced hand-rolled equivalents; `TriggerAPI`/`TriggerRollback` constants replaced string literals; the fragile `Conditions[:1]` slice (which silently depended on the Build condition being index 1) became a named `crSupersededWithoutBuildVerdict` constructor; `deployStatus` renamed `reloadDeploy` (it returns a `Deploy`, and the old name collided conceptually with `observedDeployStatus`/`supersededDeployStatus`/`timedOutDeployStatus`).
- **Trimmed two comments** that restated `ConditionBuild`'s own doc rather than adding local WHY.
- **Pinned two invariants in the `ConditionBuild` doc** that were previously assumed: it is written only as `False` (readers guard on `IsBuildFailureReason`), and it is a single slot bounded exactly like `status.preDeploy` — see t005 for the residual that bound leaves.

**Declined**

- Collapsing the two gates into one parameterized function (see above — the names carry meaning).
- Extracting `reconcile1`/`reconcileN`/`getApp` from the envtest suites: those are per-suite closures over `nn`/`name` and are the established convention across ~20 files in the package. Extracting them would fight the house style for no correctness gain.

Tests re-run after every change: `make test` (operator) and `cd lego/backend && go test ./...` green; `make lint` 0 issues across all four modules.
