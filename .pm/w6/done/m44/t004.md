## Objective

Confirm the dead-id contract this milestone establishes is consistent across every surface that exposes it, and matches render.com where a comparable behavior exists.

## Context

- bex-api is meant to be Render-compatible (`docs/ADR006-bex-api.md`). Render answers a dead resource id with **404**, never 200 + an empty resource.
- `w9/m55` t005 recorded that Render's *dashboard* dead-id behavior was unverified and that bex's redirect-home-with-toast is a deliberate, user-decided divergence — that decision stands; this task is about the **API** contract plus keeping the UI consistent with itself.
- Surfaces to check for each of services / postgres / key-value: REST `GET /v1/<kind>/<dead>`, GraphQL single-resource verb, MCP tool, dashboard route.

## Steps

1. For each resource kind, exercise all four surfaces with a dead id and record the response.
2. Compare the REST status/body against render.com's documented 404 shape; note any deliberate divergence in `docs/ADR018-render-parity.md` rather than diverging silently.
3. Confirm the GraphQL error envelope is identical across `server`, `service`, `database`, `keyValue`, and `deploys`.
4. Flag anything inconsistent that this milestone did not fix as follow-up work.
