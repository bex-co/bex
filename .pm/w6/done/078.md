# Signed-out login page keeps calling `api.bex.co/graphql` and logs a 401 each time

Why: a signed-out tab keeps sending authenticated API traffic that can never succeed. That is console noise for every visitor, needless load on bex-api, and a sign that some query or poller does not stop when there is no session.

Evidence: on 2026-10-18 a Playwright tab sat on `https://dashboard.bex.co/auth/login?next=%2F` for about 18h. It logged about 2,200 lines of `Failed to load resource: the server responded with a status of 401 () @ https://api.bex.co/graphql`, roughly one every 30s. The log is the gitignored `.playwright-mcp/console-2026-10-18T07-10-22-915Z.log`. The same tab also showed Kratos's "会话已结束。请重试。" when submitting the stale login form; reloading fixed it. That part is expected Kratos flow expiry and is noted only for context.

To do:

1. Reproduce in a fresh signed-out tab with DevTools open. Identify the operation name and the component or poller issuing it (suspect a global query or a `pollInterval` that also mounts on the auth layout).
2. Skip, or stop polling, when there is no session. Keep the existing redirect-on-401 behavior for signed-in pages.
3. Add a test that the login route issues no GraphQL request while signed out.

**Done 2026-10-19.** Reproduced: the signed-out login page sent `ViewerCapabilities` on load and every 30s.

- **Cause:** `WorkspaceProvider` and `CapabilitiesProvider` are mounted in `RootProvider`, above public pages. With no session the workspace list is skipped (not ready), so `WorkspaceProvider` kept handing out the selection cookie's id. That cookie outlives the session, and `CapabilitiesProvider` fetched and polled with it.
- **Fix:** `useWorkspaces` now reports `authenticated`, and `WorkspaceProvider` returns no current workspace without a session. Every always-mounted consumer therefore stays quiet.
- **Tests:** `capabilities-startup.test.tsx` "sends nothing on a signed-out page that kept a workspace cookie", which fails on the pre-fix code, and "starts checking with a fresh read once a session appears without a reload"; plus a `WorkspaceProvider` signed-out test. Dashboard `yarn test` (5,284) and `yarn lint` pass.
- **Adjacent gap filed as `w6/079`:** an unverified session on `/auth/verification` still polls.
