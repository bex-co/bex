## Objective

Pin the reconciled behaviour, and pin the counters that look correct today only because nothing is mid-delete.

## Context

- The defect was invisible in tests because no test had a resource with a `DeletionTimestamp` set while asserting on the counter. That is the fixture shape required — set the timestamp explicitly rather than hoping to catch a real teardown.
- Postgres and Key Value need the same fixture even though they look fine today; their Hobby cap of 1 makes them the higher-stakes case.
- Assert the relationship, not the constant: the test should say "the counter and the list agree under rule X", so it keeps meaning something if the counts change.

## Steps

1. Counter with a terminating App present → asserts `t001`'s chosen rule.
2. The list under the same fixture → asserts the two surfaces agree.
3. Same for a terminating Database and a terminating KeyValue.
4. Fully-finalized resource → leaves both surfaces.
5. Suspended resource → still counted, still listed.
6. Cap-hit create → the existing named error, unchanged.
