## Objective

Give `postgres.Service` and `keyvalue.Service` a way to resolve whether a given Database/KeyValue CR currently belongs to a `protectedStatus=protected` Environment, mirroring what `apps.PGStore.GetAppProtectedStatus` already does for Apps — but adapted for how Database/KeyValue Environment membership is actually stored.

## Context

- `lego/backend/internal/store/store.go:661-681` — `GetAppProtectedStatus(ctx, appID)` resolves via a SQL join (`apps a LEFT JOIN environments e ON e.id = a.environment_id`), because Apps have a control-plane `apps` table row with an `environment_id` column.
- Database/KeyValue have **no equivalent control-plane table row**. Per `.pm/w6/done/m20/README.md` closeout note (t004), their Environment membership lives as a **CR label** (`core.LabelEnvironment`, `"app.bex.co/environment-id"`), read directly off the Database/KeyValue object — there is no `environment_id` column to join from.
- So the new resolution path is two steps: (1) read `core.LabelEnvironment` off the Database/KeyValue CR in Go (already-established pattern from `environments.Service`), (2) look up that environment id's `protected_status` directly.
- Add a new store method, e.g. `GetEnvironmentProtectedStatus(ctx context.Context, environmentID string) (string, error)`, querying `SELECT protected_status FROM environments WHERE id = $1`, returning `"unprotected"` for a NULL/empty column exactly like `GetAppProtectedStatus` does (same `0024_environment_acl.up.sql` default).
- `s.Store` may be nil (DB-less/hand-applied mode) — every caller must treat that as a no-op returning unprotected, matching `apps.requireUnprotected`'s existing `if s.Store == nil { return nil }` short-circuit.

## Steps

1. Add `GetEnvironmentProtectedStatus` to `store.PGStore` (and the `store.Store` interface it implements) in `lego/backend/internal/store/store.go`, next to `GetAppProtectedStatus`.
2. Handle `store.ErrNotFound` (deleted/nonexistent environment) the same way `GetAppProtectedStatus` handles a missing row — safe to treat as unprotected, matching Delete's "row-first" deletion-race reasoning already documented in `apps/protection.go:90-98`.
3. Write a small package-level helper (in `postgres`/`keyvalue`, or a tiny shared spot if it turns out identical for both — follow t002/t003's judgment) that reads `core.LabelEnvironment` off a CR and calls the new store method, returning `"unprotected"` when the label is absent.

## Files

- `lego/backend/internal/store/store.go`

## Acceptance criteria

- [ ] `GetEnvironmentProtectedStatus` returns the real `protected_status` for a known environment id.
- [ ] Returns `"unprotected"` for an environment with a NULL/empty `protected_status` column and for an unknown/deleted environment id.
- [ ] A Database/KeyValue CR with no `core.LabelEnvironment` label resolves as unprotected without a store call (mirrors `GetAppProtectedStatus`'s "no environment_id ⇒ unprotected" branch).

## Out of scope

- Wiring this into `Delete`/`Suspend` — that's t002 (postgres) and t003 (keyvalue).
