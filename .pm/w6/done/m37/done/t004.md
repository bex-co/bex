## Objective

Expose t002/t003's new `confirm` gate on the REST surface, matching how Apps already accept `?confirm=` on its guarded routes.

## Context

- Find the Apps REST wiring for `?confirm=` (grep `confirm` in `lego/backend/internal/apps/rest.go`) as the reference shape.
- Routes to update: `DELETE /v1/postgres/{id}` (+ its `/v1/databases/{id}` alias), `POST /v1/postgres/{id}/suspend`, `DELETE /v1/key-value/{id}`, `POST /v1/key-value/{id}/suspend`.
- The handler reads `r.URL.Query().Get("confirm")` and threads it into the service call via `core.WithConfirm`(or the package-local equivalent decided in t002).

## Steps

1. Update `lego/backend/internal/postgres/rest.go`'s delete and suspend handlers to read and thread `confirm`.
2. Update `lego/backend/internal/keyvalue/rest.go`'s delete and suspend handlers the same way.
3. Confirm the `/v1/databases` alias route (if it's a separate handler rather than a shared one) picks up the same wiring.
