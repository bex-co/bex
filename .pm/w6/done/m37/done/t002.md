## Objective

Block `postgres.Service.Delete` and the suspend path on a Postgres database that belongs to a protected Environment, unless the caller echoes back the matching confirmation phrase — the same shape `apps.Service` already enforces.

## Context

- `lego/backend/internal/apps/protection.go` is the reference implementation: `withConfirm`/`confirmFrom` (context-carried confirmation phrase), `ProtectedConfirmation(verb, name)` (`"sudo " + verb + " service " + name"`), and `requireUnprotected(ctx, a, verb)` (looks up protected status, no-ops when unprotected/no store/no row, else demands the exact phrase).
- `lego/backend/internal/postgres/service.go:484-490` — `DeletePostgres`/`DeleteDatabase` core verb (exact name may differ slightly; grep for the `Delete` verb in this file).
- The suspend verb lives in the same package (`Suspend`/`SuspendPostgres` — grep for it); resume is deliberately **not** guarded (matches Apps' precedent: `apps/protection.go:2840-2842` comment "resume is never [guarded]").
- Confirmation-phrase wording: use `"database"` as the resource word (e.g. `"sudo delete database <name>"`) — distinct from Apps' `"service"` word, so a confirm typed for one resource type can't accidentally arm another (same reasoning as `ProtectedConfirmation`'s per-verb parameterization).
- Whether to promote `withConfirm`/`confirmFrom` into `core` (since now 3 packages need them) or duplicate the small context-key pattern per package is an implementation call — `apps/protection.go`'s own comment explains why it was originally package-local (no other package needed it); that assumption no longer holds. Prefer promoting the confirm-phrase context helpers to `core` if it avoids duplicating context-key wiring three times; keep `ProtectedConfirmation`'s resource-word parameterization per-package (each package's own phrasing).

## Steps

1. Decide the confirm-context seam (promote to `core`, or duplicate) and implement it.
2. Add `requireUnprotected(ctx, db *v1alpha1.Database, verb string) error` to `postgres`, using t001's `GetEnvironmentProtectedStatus` + CR label read.
3. Wire it into `Delete` and the suspend verb, before the mutating call, exactly where `apps.Service.Delete`/`setSuspended` call `s.requireUnprotected`.
4. Return the same `%w: %q is a member of a protected environment; retry with confirm=%q to %s it` error shape (via `core.ErrBadRequest`) so REST/GraphQL/MCP adapters can surface it identically to the Apps case.

## Acceptance criteria

- [ ] Deleting/suspending a Postgres database in an unprotected (or environment-less) Environment behaves byte-identically to today — no confirm required.
- [ ] Deleting/suspending one in a protected Environment without `confirm` returns a named 400 naming the exact required phrase.
- [ ] The same call with the correct `confirm` phrase succeeds.
- [ ] Resume is not guarded.

## Out of scope
