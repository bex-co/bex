## Objective

Make the operator refuse to run more instances than the plan allows, regardless of what `spec.replicas` says — so a hand-applied CR, a projector bug, or a future API regression cannot reintroduce the outcome.

## Context

- This is exactly the shape `w6/m46/t002` used: "Operator defense-in-depth: hard-gate Ingress/host creation for `private_service` regardless of `Expose`". That milestone's own post-mortem is the argument for doing it here — the API create path was correct all along and a **projector** write (`projectSpec` hardcoding `Expose: true`) re-stamped the wrong value on every resync. An API-layer cap alone would have been bypassed the same way.
- The enforcement point is `lego/operator/internal/controller/app_controller.go:3560-3568` (`effectiveReplicas`) and/or `clampReplicas` (`:3574-3582`), which already exists precisely to bound "attacker-controlled integers" from a hand-applied CR — its comment says so. This is the same threat, one field over.
- `clampReplicas`'s existing callers must be enumerated before changing it; a plan-aware clamp needs the App's tier, which `clampReplicas(n int32)` does not currently receive.

## Steps

1. Enumerate `effectiveReplicas` and `clampReplicas` callers and paste the counts.
2. Add the plan-aware bound, reading the limit from wherever t001 put it.
3. Decide what a CR already over the cap does: clamp silently, or clamp and surface a condition the tenant can see. Prefer visible — an invisible clamp is the "mutation reports success and did nothing" shape.
4. Confirm autoscaling cannot drive past the cap (`applyAutoscaling` writes the replica annotation, not `spec.replicas`).
5. `make test` from `lego/operator/`.
