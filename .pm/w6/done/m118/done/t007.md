## Objective

Cover the boundary on both layers, and the paths that reach around `Scale`.

## Context

- Nothing today asserts a plan-aware replica bound, because none exists — so every new test is a genuinely new assertion rather than a tightened one.
- The reach-arounds are the interesting cases: create-at-N, autoscaling-max-at-N, and a plan downgrade that leaves replicas over the new cap.

## Steps

1. Backend: free plan at the cap (allowed) and one past it (refused, with the plan and limit in the message), for `Scale`, create, and autoscaling max.
2. Backend: the plan-downgrade case behaves as t001 decided.
3. Operator envtest: a CR with `spec.replicas` past the cap never yields a Deployment above it — red before t004.
4. Enumerate the resource-type family explicitly (`web_service`, `private_service`, `background_worker`, `cron_job`, `static_site`) — a cron job has no replicas and a static site has no pods, so the test should state what each is expected to do rather than silently covering only web.
5. `cd lego/backend && go test ./...` and `make test` from `lego/operator/`.
