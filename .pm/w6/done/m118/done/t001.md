## Objective

`w2/m56` excluded "silently changing free-plan replica policy **without separate parity evidence**". Supply that evidence and make the decision. Everything else in this milestone implements whatever this task decides.

## Context

- The hunt that filed this did **not** check Render's behavior — it reasoned from the dashboard's own "billed accordingly" copy and the industry convention that scaling is a paid feature. That reasoning is not evidence, and this task must not inherit it as one.
- What is established: a free bex service accepted `numInstances: 3` and ran three pods; `MaxReplicas` is 100; the free compute rate is `usdPerSecond: 0.0` (`pricing/pricing.yaml:40-41`); no layer caps by plan.
- `docs/ADR018-render-parity.md` row 68 documents manual scale across all four surfaces and records no plan gate in either direction, so the ledger currently has nothing to say here.

## Steps

1. Establish what Render does: can a free-instance-type service scale past one instance, and what does its API return if you try? Use Render's public docs, its OpenAPI, and the repo-pinned `render-oss/cli` client — the same sources `docs/render-artifacts/` is built from. Write the finding into a `docs/render-artifacts/` note if it is not already covered.
2. Decide bex's policy. It need not match Render — `docs/ADR018-render-parity.md` records deliberate divergences — but the decision must be explicit, with the cost reasoning stated (a free instance is rated `0.0`, so N free instances are N× the capacity for the same $0).
3. If a cap is chosen, pick where it lives. `ComputeTier` (`lego/types/tiers/tiers.go:45-62`) has no instance field today; adding one puts the limit in the plan catalog where the CPU/memory bounds already are, rather than hardcoding "free" in a verb.
4. Record the decision in `docs/ADR030-pricing.md` and add/extend the ADR018 row.
5. Decide the downgrade case explicitly: a paid service running 5 instances downgraded to a plan capped lower — refuse the downgrade, or clamp the replicas? Both are defensible; leaving it undefined strands a running service.
