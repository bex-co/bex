## Objective

This milestone changes a Render-defined field on a user-facing surface. Confirm the surfaces agree, and record the two different relationships to Render: one gap closed, one divergence kept.

## Context

- **Closing a gap:** `persistenceMode` is on Render's `keyValuePATCHInput`; adding it to bex's PATCH makes bex match Render, not diverge from it.
- **Keeping a divergence:** bex's free Key Value has a 1 GB disk where Render's has none. That is deliberate and already noted in `lego/types/tiers/tiers.yaml`. It must be recorded in the ledger as a divergence rather than quietly reverted to Render's shape.
- **The ledger currently misstates both.** `docs/ADR018-render-parity.md:150` gives "no persistent disk" as bex's reason for the free-plan lock, and documents post-create updatability for `maxmemoryPolicy` only. The `:17` re-baseline lists Key Value `persistenceMode` as a covered surface, which was true at create and not at update.

## Steps

1. Read one store through REST, GraphQL and MCP; confirm `options.persistenceMode` agrees on all three before and after a patch.
2. Rewrite the ADR018 Key Value row: the true post-create update surface, and the free-tier disk divergence stated as a divergence.
3. Confirm the dashboard reflects the new value wherever it displays persistence.
4. Check whether `redis*` aliases (`redisPATCHInput` is the legacy twin of `keyValuePATCHInput`) need the same treatment, or record why not.
