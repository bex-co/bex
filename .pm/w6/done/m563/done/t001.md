## Objective

Make the Completer's idle grace depend on who started the session: 5 minutes by default for a session a person started, none for an automation's session or a child session. Keep the open-editor pin and the retention save.

## Context

- The grace: `lego/backend/internal/agentsessions/completion.go`, the block after `AgentSessionSSHActivity` (`skipGrace := record.ArchivedAt != nil || record.Phase == PhaseFailed`, then `c.idleTTL()`), and `retainOnClose` right after it.
- The default: `cfg.AgentSandboxIdleTTL = p.zeroableDuration("BEX_AGENT_SANDBOX_IDLE_TTL", 2*time.Hour)` in `lego/backend/cmd/api/config.go:691`.
- The origin: `agent_sessions.automation_id` and `parent_session_id` (`store.AgentSession`).
- Production sets no `BEX_AGENT_SANDBOX_IDLE_TTL` (`lego/operator/config/api/deployment.yaml`), so changing the default changes production.

## Steps

1. Change the default to 5 minutes.
2. Add the automation and child cases to `skipGrace`, keeping the SSH pin above it and `retainOnClose` below it.
3. Leave `BEX_AGENT_SANDBOX_IDLE_TTL` as the operator's override for a person's sessions.

## Files

- `lego/backend/internal/agentsessions/completion.go`
- `lego/backend/cmd/api/config.go`

## Acceptance criteria

- [x] A real-Postgres Completer test: a person's completed session is kept at 4m59s and reaped at 5m01s after its turn; an automation's and a child's are reaped at the first tick after harvest; each one with an open SSH session is kept.
- [x] A completed automation turn with an uncommitted file still saves its disk at that close (the m491 test pattern).
- [x] `go test ./internal/agentsessions/... ./cmd/api/...` passes.

## Out of scope

- The Enterprise setting (t002). Waking a closed session for Zed (m564).

## Result (2026-11-22)

- `cmd/api/config.go`: `BEX_AGENT_SANDBOX_IDLE_TTL` defaults to `agentsessions.DefaultIdleTimeout` (5m); it stays the operator's override for a person's sessions.
- `completion.go`: `Completer.idleGrace` returns no grace for an archived, failed, automation (`automation_id`) or child (`parent_session_id`) session; the open-editor pin runs before it and `retainOnClose` after it, unchanged.
- Tests: `TestTheIdleCloseDependsOnWhoStartedTheSessionPG` and `TestAnAutomationsUndeliveredWorkIsKeptAtTheHarvestClose` (`idle_timeout_pg_test.go`, real Postgres), and the fake-store twin `TestTheIdleCloseDependsOnWhoStartedTheSession`. Removing the automation/child condition fails both unit tests (checked).
