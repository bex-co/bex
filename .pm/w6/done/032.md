# `config/rbac` grants no `replicasets`, so any `make deploy` operator reconciles nothing

Why: the operator's informer cache cannot sync without it, so the manager comes up Ready, logs only a repeating watch error, and silently reconciles **zero** Apps. Production is unaffected, but every `make deploy` / local cluster gets a dead operator — and the failure looks like "the operator is fine, my App is just stuck."

Found 2026-08-23 while raising the live leg for `w6/m47` (it blocked that verification until granted by hand).

## What happens

`lego/operator/internal/controller/app_controller.go` lists ReplicaSets through the **cached** client:

```go
var rss appsv1.ReplicaSetList
```

added 2026-08-09 by `c7b6a680` (w7/m79, "say why a service cannot start or cannot be reached"). A cached `List` starts a cluster-wide ReplicaSet informer, but `lego/operator/config/rbac/role.yaml` carries no `replicasets` rule — there is no `+kubebuilder:rbac` marker for it. controller-runtime then blocks on cache sync forever:

```
ERROR controller-runtime.cache.UnhandledError Failed to watch
  {"type": "*v1.ReplicaSet", "error": "failed to list *v1.ReplicaSet: replicasets.apps is forbidden:
   User \"system:serviceaccount:bex-system:bex-controller-manager\" cannot list resource
   \"replicasets\" in API group \"apps\" at the cluster scope"}
```

Observed symptom: the manager pod is `1/1 Running`, but a spec change that bumps `metadata.generation` produces **no reconcile at all** and no App-scoped log line. Adding the grant and restarting made the same App reconcile within one second.

## Why production is fine

`deploy/gitops/base/operator-daytoday-rbac.yaml:59` already grants it (`resources: [deployments, statefulsets, daemonsets, replicasets, controllerrevisions]`). Only the kubebuilder-generated role used by `make deploy` is short, so the two RBAC sources have drifted — which is itself the more interesting finding: nothing gates them against each other, and the code's real requirements are only expressed in one of them.

## Fix sketch

Add the marker beside the other `apps` markers in `app_controller.go` and re-run `make manifests`:

```go
// +kubebuilder:rbac:groups=apps,resources=replicasets,verbs=get;list;watch
```

Worth considering alongside it: a check that `config/rbac/role.yaml` is a subset of the gitops day-to-day role, so a future cached `List` of a new kind cannot pass CI while breaking every non-gitops deploy. `scripts/gitops-validate.sh` is the natural home.

## Resolved (verified 2026-08-25)

Fixed by `80bae887` ("fix(operator): grant ReplicaSet read access"). `lego/operator/config/rbac/role.yaml:83-90` now carries the `apps`/`replicasets` `get;list;watch` rule, and it is generated from a real marker — `app_controller.go:341`'s `// +kubebuilder:rbac:groups=apps,resources=replicasets,verbs=get;list;watch` — so `make manifests` regenerates it rather than dropping it on the next codegen run. Closed without further work.
