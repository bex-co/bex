# `bex agent ssh` and `bex desktop` start a closed session's sandbox instead of refusing it

Why: since w6/m564 (ADR054 D8) the dashboard's Open in Zed on a session whose sandbox closed at its idle timeout calls `resume`, waits for `sshAddress` and opens it, as opening a sleeping Devin session's workspace wakes it. The CLI still reads the session once and refuses when it has no `sshAddress` ("The sandbox must be running"), so `bex agent ssh <id>` five minutes after a turn fails where the dashboard succeeds.

- **Where.** `lego/cli/internal/desktop/session.go` (`fetchSSHAddress`) and `desktop.go`, and `bex agent ssh` in `lego/cli/internal/agent/`. The CLI imports no backend package: it calls REST, `POST /v1/agent-sessions` with `{"resumeSessionId": "<id>"}`, then polls `GET /v1/agent-sessions/{id}` until `sshAddress` appears or the session leaves `resuming` without one.
- **Copy.** Say that the sandbox is starting, as the dashboard does, and when a start ends without a sandbox say so instead of hanging. Only `capabilities.sshEnabled` deployments start anything.
- **Done when** a CLI test against a fake API resumes a closed session, waits through `resuming` and opens the address it gets, refuses a canceled session with the API's `AGENT_SESSION_NOT_RESUMABLE`, and `lego/cli/testdata/agent-cli-contract.json` records the call.

## Done (2026-11-23)

The mechanism changed under the note: w10/m597 (`9f5f70e8e0`, [ADR054 D9](../../../docs/ADR054-open-in-zed.md#d9--an-ssh-login-wakes-a-closed-session-w10m597-2026-11-23)) gives every session that is neither canceled nor archived its `sshAddress` and wakes a closed sandbox at the gateway's SSH login, as SSH into a sleeping Devin session wakes it, and the dashboard dropped Start the sandbox for the same reason. So the CLI calls no `resume` and polls nothing: `bex agent ssh`, `bex edit ags-…` and `bex agent open` run `ssh` on the address, and the gateway says on stderr that the sandbox is starting, or that it did not start. What this change fixes is the CLI that still described the old world:

- Help text: `bex agent ssh` no longer says the sandbox runs only while a turn does, `bex edit` no longer says it must be running, and `bex agent open` says a closed sandbox starts when bex desktop connects. Same in `docs/bex-cli.md` and ADR106 D5.
- Refusals: a session with no `sshAddress` says why in the gateway's words (`desktop.NoSSHAddress`): canceled ("takes no more messages"), archived (`bex agent unarchive`, then connect again), or a server that offers no SSH. It no longer tells a canceled or archived session to send a message.
- Contract: the CLI now reads `phase` and `archivedAt`; `agent-cli-contract.json` and `agent-session-ssh-contract.json` pin them, and the backend twin `TestViewMatchesCLIEditContract` checks they stay.
- Tests: `TestSSHConnectsToAClosedSessionAndRefusesOneThatCannotOpen` (a closed session connects with no create or steer, canceled, canceling and archived are refused), `TestFetchSSHAddress`, `TestOpenPrefersTheDesktopForASessionWithAnSSHAddress`. Restoring the old refusal fails the first two.

The live check of a plain `ssh` into a closed session on production is w10/m597 t006 (pin must carry `0b80058275`); the CLI adds nothing for production to run.
