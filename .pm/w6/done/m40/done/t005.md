## Outcome (2026-08-17)

`/simplify` reviewed the guard + self-test against the four sibling validators (`skill-layout-validate.sh`, `github-actions-validate.sh` + its self-test, `platform-deprecations-validate.sh`). It confirmed the standalone-validator shape was followed correctly and that there is no shared test library to reuse — `scripts/lib/` holds production logic only, and six `*.test.sh` each define their own local `assert()`. Applied:

- **Duplicate detection → associative array.** Replaced two parallel arrays + an inner loop (O(n²)) with `declare -A claimed_by`, which also drops the `"${seen_nums[@]:-}"` empty-array-under-`set -u` workaround that injected a phantom first iteration, and ~144 `basename`/`sed` forks via `${path##*/}` + `BASH_REMATCH`. `declare -A` is already a repo idiom (`gitops-validate.sh`, `backup-s3-credentials.sh`). Behavior identical; a ≥3-way collision now reports n−1 pairs instead of n(n−1)/2, still naming every colliding file — verified live against a 3-way fixture. Not a perf win (the whole duplicate scan is sub-ms; ~6s of the 10s runtime is check 3's single `grep` sweep) — a readability win.
- **Hoisted the duplicated grep filter list.** It was spelled out twice and the second copy silently dropped `--exclude-dir=dist --exclude-dir=bin`, so the evidence listing could surface a reference the detector itself could not see.
- **Deleted a dead write in the self-test** — two consecutive truncating `>` writes to the same fixture path meant the first never reached the validator.
- **Extracted `run <dir>`** in the self-test; the fixture-scoped invocation was spelled out twice.
- **Three comment fixes.** The override rationale was stated three times across the two files (kept one). One comment claimed the scan "skips the ADR files' own rename notes" via an exclusion that does not exist — the real mechanism is that the pattern requires the full `-<slug>.md`, so bare-number prose is inert by construction. Another justified keeping a heading "so the file still parses as an ADR", a constraint the validator does not have (it never reads an ADR body).
- **Dropped the trailing `ADR registry validation FAILED` line** — no sibling emits one, and it was inconsistent with this script's own two early exits.
- **SC2069.** The extracted `run()` used `2>&1 >/dev/null`; rewritten as `{ …; } 2>&1` per shellcheck's own suggestion. Both scripts are shellcheck-clean and are now in `scripts.yml`'s explicit shellcheck list.

**Declined:** collapsing `ADR_DIR`/`ADR_INDEX`/`SCAN_ROOT` into one `ADR_ROOT`. It would shrink the assert helper but forces fixtures to name their index `CLAUDE.md` and makes the failure message report `./CLAUDE.md`; three explicit seams state more precisely what each one scopes.
