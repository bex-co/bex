## Objective

Prove the guard actually catches what it claims. A guard that has never been shown to fail is indistinguishable from a guard that always passes — and this milestone's whole durable value rests on it.

## Context

- Three failure modes to prove independently: duplicate number, missing index entry, dangling link.
- The self-test must construct each violation in a scratch fixture and assert the guard exits non-zero with a message naming the offender, then assert it exits zero on the clean tree.
- Precedent: the repo's existing validators pair with self-tests in the same style; `w7/m65`'s pinning guard is the closest analogue.
- Do not game this: asserting only the exit code without asserting the guard rejects the *right* thing would pass a guard that fails on everything.

## Steps

1. Add a red case per check, each isolated so a single guard bug cannot make all three pass.
2. Add the green case against the real tree.
3. Assert failure messages name the offending file/number, not just a non-zero exit.
4. Wire the self-test where the sibling validators' tests run.

## Files

- the guard's self-test, alongside `scripts/`'s existing validator tests

## Acceptance criteria

- [ ] Duplicate-number violation → guard exits non-zero and names both files.
- [ ] Missing-index violation → guard exits non-zero and names the file.
- [ ] Dangling-link violation → guard exits non-zero and names source and target.
- [ ] Clean tree → guard exits zero.
- [ ] Each red case fails for its own reason, verified by removing the corresponding check.

## Out of scope

- Testing prettier or unrelated CI steps.
