## Objective

Build the durable half of this milestone: a fail-closed CI guard that makes a fourth collision impossible to merge. The renumbering is a one-off; the guard is what stops the process that produced three collisions from producing a fourth.

## Context

- Three checks, all fail-closed:
  1. **No duplicate ADR number** — two `docs/ADR*.md` files claiming one number is an error.
  2. **Every ADR is indexed** — a `docs/ADR*.md` absent from `CLAUDE.md`'s docs index is an error.
  3. **No dangling ADR reference** — an `ADRnnn-…` link target that does not exist is an error.
- Precedent for shape and rigor: the repo already ships validation scripts in this style — `scripts/skill-layout-validate.sh` (repo rule enforced after skill changes), `scripts/gitops-validate.sh` (fails closed on an empty prod domain), and `scripts/clusterapi-validate.sh`. Follow their conventions rather than inventing a new one.
- `w7/m65`'s 40-hex GitHub-Actions pinning guard is the closest precedent for a "reject a reintroduced pattern" check with its own self-test.
- Wire it into CI the way the existing validators are wired, and make failure messages name the offending file(s) and number — a guard whose output does not say what to fix gets disabled.

## Steps

1. Write the guard script alongside the existing validators in `scripts/`.
2. Implement the three checks with specific, actionable failure messages.
3. Wire it into the CI workflow that runs the sibling validators.
4. Run it against the post-`t002`/`t003` tree and confirm it passes.
5. Confirm it is deterministic and has no false positives against legitimate prose (e.g. a bare "ADR060 D5" citation with the file present must pass).

## Files

- `scripts/` — the new guard, named after its siblings
- `.github/workflows/` — the workflow running the existing validators

## Acceptance criteria

- [ ] Guard fails on a duplicate ADR number, naming both files.
- [ ] Guard fails on an ADR missing from `CLAUDE.md`'s index, naming the file.
- [ ] Guard fails on a dangling `ADRnnn-…` link, naming the source and the missing target.
- [ ] Guard passes on the current tree after `t002`/`t003`.
- [ ] Guard runs in CI, not only locally.
- [ ] No false positive on a valid bare-number prose citation.

## Out of scope

- The guard's red/green self-test — that is `t006`.
- Extending the guard to non-ADR docs.
