# `git push` from Zed works in a finished turn's sandbox during its idle window, not only in a sandbox resume started

Why: w6/168 lets the Git mint admit only a sandbox `resume` started or kept for a person's editor (`editor_sandbox_id`). Most Zed opens come within 5 minutes of a turn (20 of 25 in w6/m564's production sample), while the turn's own sandbox is still up in its idle window. An SSH login there opens that sandbox directly, with no `resume` (the ADR054 D9 wake runs only for a `closed` session), so its `git push` is still refused with `remote: forbidden`. A Devin machine's terminal pushes whenever the machine is awake.

- **Where.** `editorGitCaller` in `lego/backend/internal/agentsession/mint.go` admits `sandbox_id = editor_sandbox_id` only. `KeepAgentSessionSandboxForEditor` (`lego/backend/internal/store/agentsession_editor.go`) marks a finished turn's live sandbox as an editor's, but only `Service.Resume` calls it. The gateway's login path (`lego/backend/internal/sshgateway`, ADR054 D9) calls `POST /v1/agent-session-wake` only for a `closed` session.
- **Candidates.** (a) The wake verb, or a sibling under the same `wake-session` MAC domain, also runs `resume` for a login into a finished session whose sandbox is up, which marks it as the editor's and restarts its idle clock, as the dashboard's resume already does. (b) The Git mint admits any finished, unarchived session's sandbox while an SSH login to it is open (`ssh_sessions.transport = 'ssh'`, as the idle close reads it).
- **Security.** Unlike an editor's start, the turn's own sandbox may still run processes the agent left behind, and they could push the session branch while it is admitted. The branch rule (`validateReceivePack`) and the gateway-held token bound that write to what the turn itself could do. Record the choice in ADR054 D8 § Pushing from it, with the negative tests (no login, an archived session, the model and `gh` routes).
- **Done when** a real-Postgres test admits the Git mint for a finished turn's sandbox after an SSH login into it, and refuses it with no login. On production, an `ssh ags-…@ssh.bex.co` within 5 minutes of a turn pushes a commit to the session branch.
- **Filed by** w6/168, 2026-11-23.

## Parked (2026-11-23)

Verdict: work, with candidate (b). `d1464668cd` ships the code: the Git mint (`agentsession.Minter.Mint`, `finishedGitCaller` in `lego/backend/internal/agentsession/mint.go`) also admits a `completed` or `failed`, unarchived session's current sandbox while a person's SSH login into the session is open. That is an `ssh_sessions` row for it with no end, `transport = 'ssh'`, started within the gateway's 4-hour cap (`agentsession.SSHLoginCap`): the read the idle close already makes (`AgentSessionSSHActivity`). It is still bound to the exact Pod and UID and to the session's own `bex-agent/*` branch. The model mint, both `gh` mints and every other verb keep the live-phase allowlist.

- **Why (b), not (a).** (a) marks nothing for a login opened while the turn ran and still open after it ended, since `resume` returns a live session unchanged. It would also add a gateway-to-bex-api call to every login, and keep the sandbox admitted until the idle close rather than only while the login is open. The role set is the same either way: `can_view_sensitive` (the SSH login's) is developer or admin, as `resume`'s `can_create` is. The reasoning is in [ADR054 D8 § Pushing from it](../../../docs/ADR054-open-in-zed.md#d8--a-closed-session-wakes-for-an-editor-w6m564-2026-11-22), and ADR055 F12 notes the narrowing.
- **First half of the definition of done holds.** `TestPGGitMintAdmitsAFinishedTurnsSandboxWhileAnSSHLoginIsOpen` (real Postgres) grants a Git token to a finished turn's own sandbox with an SSH login open. It refuses it with no login, with only an `agent_attach` row, after the login ended, for a row older than the cap, on the `gh` read and write routes and the model route, and for an archived session. `TestMinterAdmitsGitToAFinishedTurnsSandboxWhileAnSSHLoginIsOpen` covers the phases, another Pod or branch, an unwired or failing login read, and no login read for a live turn. Both fail with the fix reverted.
- **Production check, once the pin carries `d1464668cd`.** Sign in as the QA user (`bash scripts/qa-login.sh`, with a temporary SSH key on the QA user, deleted afterwards). In the `bex` workspace, run a session on the private fixture `bex-co/bex-hello-go-live` (disposable). Within 5 minutes of its turn ending, while its own sandbox is still up and before any `resume`, run `ssh ags-…@ssh.bex.co`. In `/workspace`, commit a file on the session's `bex-agent/<id>` branch and `git push`: it must succeed, with the branch head on GitHub at that commit. `git push origin HEAD:main` from the same terminal must be refused. Record the times and the pushed SHA here, delete the session and the key, and close.
