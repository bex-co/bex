## Objective

Implement a single reusable policy answering "may this recipient currently see this notification's destination?" — checking current resource access (e.g. agent events require the session-read gate `can_operate` on the workspace), not a role copied into the event at emit time.

## Context

- `lego/backend/internal/notifications/delivery_policy.go:494-497` — `roleEligible` returns true when eligibility is nil (all roles). A nil default must stop meaning "everyone" for events with a gated destination.
- `lego/backend/internal/agentsessions/service.go` — the actual session-read gate is `can_operate`; the policy must reuse the same relation, not re-derive it from role names.
- ADR087: "Check current resource access rather than merely copying the old recipient role into an event."

## Steps

1. Add a destination-eligibility function keyed by event family → required relation on the target (service/deploy/cron supervision = target read; agent events = session-read gate).
2. Make unknown event families fail closed for gated content.
3. Keep the existing preference/urgency/quiet-hours policy orthogonal — interest ≠ permission.

## Files

- `lego/backend/internal/notifications/delivery_policy.go`

## Acceptance criteria

- [ ] One exported policy entry point; no caller re-implements role→permission mapping.
- [ ] Unit tests cover each event family, unknown family (fail closed), and authz error (defer/suppress, never broaden).

## Out of scope

- Wiring the call sites (t002/t003); new event types; preference UI.
