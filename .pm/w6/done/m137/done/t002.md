## Objective

Apply the t001 policy when projecting push recipients and again immediately before any deferred/retried delivery, closing the agent fan-out gap.

## Context

- `lego/backend/internal/notifications/push_worker.go` — `projectAgentSessionPush` (~:387) and its `DeliveryInput` (~:337) never set `EligibleRoles`, so agent pushes currently fan out to all roles with matching preferences.
- ADR087: reuse the policy "when projecting recipients, immediately before deferred/retried delivery"; a delivery queued before a downgrade must be re-checked at send time.
- Authorization outages defer or suppress; they never broaden recipients.

## Steps

1. Set destination eligibility on agent-session push projection via the t001 policy.
2. Add the pre-send re-check on the deferred/retry path.
3. Sweep other projections (service/deploy/cron) for the same nil-eligibility default and align them.

- `lego/backend/internal/notifications/push_worker.go`
- `lego/backend/internal/notifications/delivery_policy.go`

## Acceptance criteria

- [ ] Test proven red pre-fix: a Viewer/Billing member with agent-event preferences receives no agent push.
- [ ] Push queued before a downgrade is dropped at send time (test with the recipient's grant revoked between enqueue and delivery).
- [ ] FGA outage during send defers the item; recipients are never widened.
