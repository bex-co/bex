## Objective

Audit push payload content so OS-rendered text stays generic — no repository names, prompts, log excerpts, credentials, or resource details — and confirm the open-time revalidation path still runs after a successful send-time check.

## Context

- ADR087: "Keep lock-screen text generic … fetch the authorized detail after opening. Preserve the existing closed routing envelope. Revalidate at open even after a successful send-time check."
- Delivery providers and delivered OS notifications cannot be recalled; minimization is the only durable defense.
- `mobile/src/features/notifications/deep-link.ts` — existing subject/workspace/session binding on open (client side; verify server counterpart).

## Steps

1. Inventory every push payload field; strip or generalize anything naming repositories, prompts, or log content.
2. Verify the routing envelope carries only opaque ids; detail is fetched post-open through the normal authorized read.
3. Confirm open-time revalidation covers the newly gated agent events.

## Files

- `lego/backend/internal/notifications/push_worker.go` (payload construction)

## Acceptance criteria

- [ ] A test asserts agent push payloads contain no repository/PR-title/prompt strings.
- [ ] Open of a stale notification after downgrade lands on the generic unavailable path, not cached detail.

## Out of scope

- Redesigning the notification envelope; mobile rendering (w6/m138).
