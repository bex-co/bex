## Objective

Give the operator visibility into an App's environment-isolation state by projecting it onto the App CR as a label, mirroring the existing `core.LabelProject`/`core.LabelWorkspace` pattern.

## Context

- `lego/backend/internal/core/base.go:101` defines `core.LabelProject = "app.bex.co/project-id"`, consumed nowhere by NetworkPolicy generation today.
- Environment membership currently lives **only** in Postgres (`apps.environment_id`, `lego/backend/internal/store/environments.go:116-140`, `SetEnvironmentServices`/`ListEnvironmentServices`) and is never projected onto the App CR — a deliberate scope cut noted in `docs/ADR032-environments.md`.
- This label is a prerequisite for t004 (operator NetworkPolicy).
- **Naming collision discovered during implementation:** `w6/m20` (shipped concurrently, same week) independently needed "an environment id on a CR label" too — for Database/KeyValue membership, unconditional, mirroring `LabelProject` exactly — and landed `core.LabelEnvironment = "app.bex.co/environment-id"` first. This task's own label has different semantics (App-only, present ONLY while the environment's `networkIsolationEnabled` is true — its mere presence is the signal, not just its value), so it was named `core.LabelNetworkIsolation = "app.bex.co/network-isolation"` instead of reusing `core.LabelEnvironment`. See `docs/ADR032-environments.md` § w6/m20 extension for the full reconciliation note.

## Steps

1. ~~Add `core.LabelEnvironment = "app.bex.co/environment-id"` to `lego/backend/internal/core/base.go`.~~ Landed as `core.LabelNetworkIsolation = "app.bex.co/network-isolation"` instead — see the naming-collision note above.
2. In `environments/service.go`, project the label onto member App CRs whenever `SetServices` changes membership or `SetACL` toggles `networkIsolationEnabled` (`applyAppEnvironmentLabels`/`setAppEnvironmentLabel`, via the same `AuthorizeApp`-then-merge-patch seam `apps.Service` itself uses).
3. Backfill: not needed — the label is derived state (present iff isolation is currently on), not a durable fact requiring reconciliation; every `SetServices`/`SetACL` call resyncs it from scratch for the affected Apps.

## Files

- `lego/backend/internal/core/base.go`
- `lego/backend/internal/environments/service.go`

## Acceptance criteria

- [x] Assigning an App to an environment with `networkIsolationEnabled=true` (via any surface) sets the CR label; unassigning, or the environment having isolation off, clears/omits it.
- [x] Label stays consistent with the Postgres-backed environment state after create/rename/delete/SetACL — verified in `lego/backend/internal/environments/acl_test.go`.

## Out of scope

- Database/KeyValue label projection — already shipped separately as `w6/m20`'s `core.LabelEnvironment`/`SetEnvironmentID`.
