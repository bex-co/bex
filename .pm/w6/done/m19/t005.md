## Objective

When an Environment's `protectedStatus` is `protected`, block unguarded destructive verbs (delete, suspend, direct-deploy-override) on its member Apps.

## Context

- Destructive verbs live in `lego/backend/internal/apps` (delete/suspend) and the deploy override path.
- Mirrors Render's protected-environment behavior (confirmation required for destructive actions).

## Steps

1. In the relevant apps-service verbs, before executing a destructive action, check the App's environment (via `core.LabelEnvironment` or the Postgres `apps.environment_id` lookup) and its `protectedStatus`.
2. If protected and no explicit confirmation flag is passed, return a typed error (see `lego/backend/internal/errors` typed error-code envelope, `w2/m28`) rather than executing.
3. Add the confirmation flag/param to REST/GraphQL/MCP call signatures for the affected verbs.

## Files

- `lego/backend/internal/apps/*.go` (delete/suspend/deploy-override verbs)
- `lego/backend/internal/environments/service.go` (protection lookup helper)

## Acceptance criteria

- [ ] Deleting/suspending/overriding a deploy on an App in a protected Environment without confirmation returns a typed error, no side effect.
- [ ] The same action with explicit confirmation succeeds.
- [ ] Apps in unprotected/no-environment stay unaffected.

## Out of scope

- ipAllowList enforcement (t006).
