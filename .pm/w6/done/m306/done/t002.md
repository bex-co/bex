## Objective

The build census lists only Jobs, so a held release is in neither `bex_builds_queued` nor `bex_build_queue_oldest_seconds`, and `BuildQueuedTooLong` cannot fire on an admission or datastore stall. Count held releases beside unplaced Jobs, and let the oldest-age gauge report the oldest of either.

## Context

- `lego/operator/internal/controller/build_census.go` (30 s recount, uncached build-plane client) and `lego/operator/internal/build/census.go`
- `deploy/gitops/base/rules/alerting_rules.yml:693` `BuildQueuedTooLong` (`bex_build_queue_oldest_seconds > 480` for 2m), `deploy/gitops/base/rules/alerts_test.yml`
- `deploy/gitops/base/values/grafana.values.yaml` ("Live admission picture" panel, ~line 5138)

## Steps

1. Extend the census with Apps whose current release carries the t001 held-since timestamp and has no Job (a bounded `stage` label such as `held`/`unplaced` on `bex_builds_queued`).
2. Make `bex_build_queue_oldest_seconds` the oldest of held releases and unplaced Jobs.
3. Update the alert description and the Grafana panel text; add an alert unit test that fires on a held-only stall.
