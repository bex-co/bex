# ADR004 still says every container must listen on `$PORT` and bex never detects ports

Why: w6/m148 made image-derived ports the default for new Git-built Docker private services, but ADR004's deploy contract still describes only the single configured-port model, which the m148 contract table assigned to t001 and which did not change.

- **Stale text.** `docs/ADR004-app-deployment.md:156`: "**The container must listen on `$PORT`** (the platform default is 3000) … unlike Render there is no listening-port auto-detection." For an image-port private service, `PORT` is the primary selected from the image's declared TCP ports, and every declared TCP port is published (`lego/operator/internal/controller/image_network.go:66-88`).
- **Stale text.** `docs/ADR004-app-deployment.md:160`: "A blueprint-created service keeps the platform default and is repointed through the update verb like any other." A Blueprint-created Git-built Docker private service now gets `portMode image-v1` (`lego/backend/internal/apps/service.go:2446`), so its port comes from the image.
- **Contract row.** `.pm/w6/done/m148/README.md:70` lists "ADR004 (`PORT` = resolved primary for image-port services)". `git show --stat 94533d795` has no ADR004 change.
- **Fix.** Append a dated w6/m148 note to both paragraphs. Cover the primary rule (explicit port wins, else 3000 if declared, else the lowest declared, else 3000), the TCP readiness check on the primary, and the configured-port contract that web, prebuilt-image, native and pre-m148 private services keep. Link ADR089 § Port slice decisions and the ADR018 Open ports row. Leave the historical text in place.

Closed 2026-10-20 inside w6/m148 (same ship as its closeout): ADR004 now carries a dated w6/m148 note on image-port private services (primary rule, TCP check, declared-port divergence).
