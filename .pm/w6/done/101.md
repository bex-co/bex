# The SSH gateway's exec drain buffer has no metrics, so its silent fallback goes unnoticed

Why: w6/099's 64 MiB per-channel / 128 MiB process buffer silently writes straight through once the process budget is spent, and that is exactly when the kube-apiserver tail loss can return. Nothing records it.

- **Evidence:** `lego/backend/internal/sshgateway/metrics.go` has no drain metrics. `drain.go` falls back to `direct()` without logging or counting it.
- **Do:**
  - Add gauges and counters to `Metrics`: buffered bytes in use (process), channels buffering, and `drain_fallback_total` (writes that went straight through because the process budget was spent).
  - Add a Prometheus alert when fallbacks keep happening (e.g. >0 for 15 min).
  - Unit tests drive the fallback and assert the counter.
- **Expected:** a saturated buffer is visible before a customer reports a short export.

## Done — 2026-11-03

- `bex_ssh_gateway_drain_buffered_bytes` (gauge, process-wide) and `bex_ssh_gateway_drain_fallback_writes_total` (counter) in `internal/sshgateway/metrics.go`. Both are label-free and added to the privacy-safe metrics allowlist test. `DrainBudget.Metrics` is set in `cmd/ssh-gateway/main.go`. Buffering adds bytes, the forwarder subtracts them (discarded chunks included), and a spent process budget counts a fallback.
- `SSHGatewayDrainBudgetExhausted` (warning): `sum(increase(bex_ssh_gateway_drain_fallback_writes_total[15m])) > 0` for 15m, in `deploy/gitops/base/rules/alerting_rules.yml`, with `ssh_gateway_alerts_test.yml` (sustained fallbacks fire, a one-off burst stays quiet). The SSH gateway Grafana panel 7 gained the fallback series (ADR088 §6 coverage). `gitops-validate.sh` passes.
- Test `TestDrainBudgetReportsBufferedBytesAndFallbacks` (`-race`): buffered bytes rise while a client stalls and return to 0 after the drain; a spent budget counts one fallback.
