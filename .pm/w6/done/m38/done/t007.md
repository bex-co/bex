## Objective

Verify that custom Postgres bootstrap identity behaves consistently across every surface and matches the observable Render create contract, and file any remaining drift rather than silently broadening this milestone.

## Context

- Render's official CLI/API contract makes `databaseName` and `databaseUser` optional and server-generated independently when omitted.
- bex additionally exposes GraphQL, MCP, Blueprint, and dashboard adapters over the same core.
- Datadog functional support remains deliberately excluded by `.pm/DO_NOT_DO.md`; the parity outcome there is honest explicit rejection, not a false green check.

## Steps

1. Compare REST field names, omission/default semantics, validation errors, readback, and connection info with current Render documentation/evidence.
2. Verify GraphQL/MCP/UI/Blueprint carry equivalent intent without inventing incompatible semantics.
3. Check rename, recovery, additional-user, pooler, and read-replica paths for physical-name drift.
4. Update ADR018 and file any uncovered adjacent gap as a w6 inbox note via `$pm` rather than expanding implementation during closeout.

- [x] The two supported fields have consistent semantics on all exposed surfaces.
- [x] Existing rename/recovery/user/pooler/replica behavior remains correct with custom names.
- [x] Datadog's explicit unsupported status is documented accurately and no API reports success for ignored intent.
- [x] No remaining parity drift was found that requires follow-up work.
