## Objective

Extend the leaf `Database` CRD contract with optional, durable names for the initial PostgreSQL database and its owner role, while preserving stable-id-derived behavior for every existing CR and every create request that omits the new fields.

## Context

- `lego/types/v1alpha1/database_types.go` currently stores only the mutable display `spec.name`; backend and operator independently derive physical names from immutable `metadata.name`.
- PostgreSQL/CNPG bootstrap identity is not safely mutable after initialization. The two new values therefore represent create-time intent, not rename fields.
- Empty fields must mean the existing defaults (`normalize(metadata.name)` and that value plus `_user`) so old CRs, hand-applied manifests, recovery objects, and default CLI creates do not change.
- Validation must be shared or provably identical across the backend and CRD admission contract and must reject identifiers CNPG/PostgreSQL cannot safely use as unquoted database/role names.

## Steps

1. Add optional `DatabaseName` and `DatabaseUser` fields (wire names `databaseName`/`databaseUser`) to `DatabaseSpec`, with clear create-time/immutability/default comments and schema validation.
2. Add shared helpers in `lego/types` for resolving an effective physical database and owner from `(spec, metadata.name)` so backend and operator cannot drift.
3. Add admission immutability protection for non-empty persisted values, while allowing legacy empty fields to retain default behavior and be backfilled safely if the chosen design requires it.
4. Regenerate deepcopy and CRD manifests from `lego/operator/`.

## Acceptance criteria

- [x] A Database may omit both fields and resolves to exactly today's stable-id-derived names.
- [x] Either field may be supplied independently; the omitted sibling gets its existing derived default.
- [x] Invalid or unsafe PostgreSQL identifiers are rejected before reconciliation with a specific message/schema error.
- [x] Once a custom physical name is persisted, an ordinary CR patch cannot silently retarget an initialized cluster.
- [x] Generated deepcopy and CRD output are current.

## Out of scope

- Backend request/adapters and CNPG projection (t002/t003).
- Renaming an initialized SQL database or owner role.
