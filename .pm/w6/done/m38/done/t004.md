## Objective

Expose custom initial database/owner names consistently on every supported creation surface, all delegating to the same core validation and persistence path.

## Context

- ADR008 requires API-first behavior, and the PM workflow's parity gate requires REST/GraphQL/MCP/UI consistency for tenant-facing fields.
- `createDatabase` GraphQL and `create_postgres` MCP currently omit both inputs even though their result types already expose `databaseName`/`databaseUser`.
- `lego/backend/internal/apps/deploy.go` explicitly lists Blueprint `databaseName` and `user` as ignored; the same CRD mechanism can now honor them (`user` is Render's Blueprint spelling).
- The dashboard database create form should keep the fields optional/advanced so existing default creation stays simple.

## Steps

1. Add optional `databaseName`/`databaseUser` arguments to GraphQL `createDatabase` and MCP `create_postgres` and delegate unchanged to core.
2. Honor Render Blueprint `databases[].databaseName` and `databases[].user`, including stack dry-run/sync idempotency.
3. Add optional advanced fields to the dashboard create dialog and ensure generated GraphQL types/operations include them.
4. Add a cross-adapter test proving identical persistence, defaults, and validation errors.

## Acceptance criteria

- [x] REST, GraphQL, MCP, Blueprint, and dashboard creates persist the same custom names through one core path.
- [x] Omitted inputs preserve the existing generated defaults on all five surfaces.
- [x] Blueprint uses `databaseName` + `user` without changing the REST/GraphQL/MCP `databaseUser` spelling.
- [x] No adapter accepts a value that core later ignores or rewrites silently.

## Out of scope

- Exposing post-create physical-name mutation controls.
