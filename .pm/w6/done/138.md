# Render's Postgres Active Connections chart: does it read the plan's limit?

Why: Render's Key Value Active Connections chart reads "Limit 250" beside its title, and bex's has since w6/m459; no capture shows whether Render's Postgres chart, the same graph, reads its plan's `max_connections` (100/200/400/500), so bex's Postgres chart shows none.

- **Render** (read 2026-11-17, [postgres-connection-limit.md](../../docs/render-artifacts/postgres-connection-limit.md)): render.com/docs/service-metrics § Database activity lists Active Connections for Postgres, "also available for Render Key Value instances"; the Key Value screenshot `kv-active-connections.png` shows "Limit 250"; no Postgres screenshot shows the chart's header.
- **bex:** `DatastoreMetricsPanel` (`dashboard/src/features/metrics/components/datastore-metrics-panel.tsx`) passes a Key Value's plan limit to its Active Connections chart (`connectionLimit`); the Postgres chart gets none, and `DatabaseInstanceType` (`lego/backend/internal/postgres/graphql.go`) carries no `maxConnections`.
- **Gate:** a live Render dashboard session (no Render login is in `.env`), to open a Postgres database's Metrics page.
- **Do:** capture the Postgres Active Connections header into `docs/render-artifacts/postgres-connection-limit.md`. If it reads a limit, add `DatabaseInstanceType.maxConnections: Int!` from `tiers.PostgresTier.MaxConnections` and pass the database's plan figure to the chart as the Key Value route does (`KeyValueMetrics` in `dashboard/src/routes/keyvalue.$keyValueId.tsx`).
- **Done when:** the capture is recorded with its date, and the Postgres chart matches it: "Limit 100" on a `basic-1gb` database if Render shows one, none otherwise.

**Done 2026-11-18.** Render does show the limit: its public dashboard code (`DatabaseMetrics-BbWQy-0B.js`, loaded by `dashboard.render.com/login` without a session) gives the Postgres Active Connections chart a "Limit" subtitle and the plan's figure (its `CONNECTIONS_LIMIT` series, else `planSpec.maxConnections`), as the Key Value chart's "Limit 250". That cleared the live-session gate. Recorded in [postgres-connection-limit.md](../../../docs/render-artifacts/postgres-connection-limit.md#the-active-connections-chart-w6138-2026-11-18). GraphQL `DatabaseInstanceType.maxConnections: Int!` now comes from `tiers.PostgresTier.MaxConnections`, and the database page passes the plan's figure to the chart, so a `basic-1gb` database reads "Limit 100".
