# Every operator deploy closes every tenant connection to every Key Value store

Why: `kv-internal-proxy` runs from the operator's own image and closes every connection it holds on `SIGTERM`, so each production deploy (11 on 2026-11-17) drops every client of every Key Value store at once; Render does not drop a store's clients when it ships its own platform.

- **Found** by w6/m463 t005 on production, 2026-11-18. At pin `359aee37d` every store's `<id>-internal` Deployment rolled at 01:32Z, and the new pod template differed from the old one only in `image` (`bex-operator@sha256:f7b06e9c…` → `b4104643…`). Each of the three `starter` stores has 11 ReplicaSets from 2026-11-17 04:41Z to 2026-11-18 01:32Z, one per operator deploy. Their Valkey pods did not restart.
- **Why it drops clients.** `Serve` (`lego/operator/internal/kvinternalauth/proxy.go`) closes every active connection as soon as its context is cancelled, and `cmd/kv-internal-proxy/main.go` cancels it on `SIGTERM`. The Deployment's image is `r.InternalProxyImage`, the manager's own image (`keyvalue_internal_proxy.go`), so every manager release changes it. On the local cluster (m463 t003) a client held through the proxy read EOF the moment the old pod went. Long-lived Redis clients (pub/sub, blocking commands, pools) reconnect, but each deploy fails their in-flight commands.
- **Same pattern on the external path.** `bex-kv-sni-proxy` and `bex-pg-sni-proxy` are DaemonSets on the operator image too, and all three of each rolled at 01:31–01:32Z, which closes external Key Value and Postgres connections on each deploy. Check their shutdown before scoping.
- **Render:** a store's connections break when the customer changes it (a plan change, enabling internal authentication: "Render restarts your Key Value instance", [Key Value](https://render.com/docs/key-value)), not when Render ships.
- **Possible directions:** give the proxies an image that changes only when their code does; drain on `SIGTERM` (stop accepting, keep existing streams until the client closes or a long grace period, `terminationGracePeriodSeconds` to match); or both.
- **Done when:** on production, a client held through a store's internal URL across an operator deploy that does not change the proxy's code still answers `PING` afterwards. The same holds for an external TLS client across a deploy, or the SNI-proxy part is filed separately with its evidence.
