# Decide whether `render-v1` relaxes seccomp toward Render's unconfined runtime

Why: Render applies no seccomp filter, so `io_uring` servers and the unprivileged-user-namespace sandboxes used by Chromium and bubblewrap run there. bex's RuntimeDefault blocks both: a Render parity gap left open when w6/m149 shipped `render-v1` on RuntimeDefault.

- **Evidence:** `docs/render-artifacts/container-privileges.md` (Render `Seccomp: 0`, bex `Seccomp: 2`; probe results for `io_uring` and `unshare(CLONE_NEWUSER)`).
- **Options:**
  - a Localhost profile, i.e. RuntimeDefault plus the `io_uring` syscalls and `unshare(CLONE_NEWUSER)`;
  - `Unconfined`, which PSS baseline forbids, so the namespace policy would also change.
- **Default under Render parity first:** close the gap with the Localhost profile. Promote this note to a milestone that includes:
  - a security review (unprivileged user namespaces with no syscall filter is a known kernel-exploit entry point on shared nodes);
  - node profile distribution;
  - admission;
  - live probes for `io_uring` and `unshare`.
