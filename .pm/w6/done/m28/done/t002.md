## Objective

Resolve a resource's nested Render owner from its own `ownerId` through one narrow, authorization-safe abstraction shared by Service, Postgres, and Key Value REST adapters.

## Context

- `lego/backend/internal/workspaces/render.go` already knows Render's `{id,name,email,type}` owner shape, but its types/functions are package-private.
- `lego/backend/internal/api/server.go` currently constructs resource services before or independently of the workspace service.
- The lookup must use the resource's workspace, not the caller's default workspace, and must not turn list responses into an avoidable N+1 query path.

## Steps

1. Introduce the smallest reusable owner lookup/value contract without creating package cycles or coupling neutral core views to REST wire structs.
2. Reorder or factor server construction so apps, postgres, and keyvalue receive that dependency explicitly.
3. Resolve names and optional email consistently, with batching/caching where list endpoints require it.
4. Preserve authorization and omission behavior for hand-applied legacy resources with no tenant label.
5. Add focused wiring and cross-workspace lookup tests.

## Files

- `lego/backend/internal/workspaces/`

- `lego/backend/internal/postgres/`

- `lego/backend/internal/api/*test.go`

## Acceptance criteria

- [x] All three packages consume one owner lookup contract and return the real workspace name instead of duplicating id-as-name adapters.
- [x] A resource in a non-default workspace resolves that workspace's owner metadata without revealing another workspace.
- [x] List endpoints do not issue one unbounded database/identity lookup per resource.
- [x] Store-off and unlabeled legacy objects have documented, tested omission behavior.

## Out of scope

- Changing workspace membership, roles, or the `/v1/owners` lifecycle contract.
