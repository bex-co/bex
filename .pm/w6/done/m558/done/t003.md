## Record (2026-11-21)

- **Mechanism (t001's candidate b), in `lego/operator/internal/controller/disk.go`.**
  - `createDiskPVC` stamps every new claim `app.bex.co/disk-layout: root-directory`.
  - `earlierDiskMove` reads the claim, from the cache, only when `movedDiskMount` finds a move. That needs a native service other than Go, or a service linked to such a build source, whose working directory is `/opt/render/project/src/<rootDir>` and whose disk path is under `/opt/render/project/src/` but outside `<rootDir>/`. A claim without the mark moves.
  - `diskMountPaths` mounts that disk at its path and at the same path under the root directory, or only at the new place when its path is the root directory or one of its parents.
  - `applyServingDeployment` passes the move in `deploymentParams.diskMove`. `applyDeploymentSpec` keeps a stored template's single mount until the template rolls for another reason, so the upgrade itself rolls no disk service. An unreadable claim fails the pass, so no mount is dropped.
- **Tests:** `disk_layout_test.go`.
  - `TestMovedDiskMountIsTheOldPathInTheRootDirectory` covers each runtime and path case.
  - `TestEarlierDiskMountMovesWithTheNextRoll` covers no roll on upgrade, both mounts on the next roll, one volume and the hiding case.
  - `TestEarlierDiskMoveReadsTheClaimsMark` covers an unmarked claim, a marked one, none, a linked service, no read when nothing moves, and an unreadable claim.
  - `TestNewDiskClaimIsMarkedWithTheRootDirectoryLayout`.
  - `TestServingDeploymentMountsAnEarlierDiskInTheRootDirectory` runs the serving pass through `applyServingDeployment` with a fake client.
  - t007's table records the reverts.
