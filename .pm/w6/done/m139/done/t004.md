## Objective

Prevent a confirmation opened under an old access context from dispatching, and explain temporary blocks consistently.

## Context

- SafeActionPanel retains a selected operation until confirmation; fresh access, connectivity, and generation need to remain valid at dispatch.
- m141 will add resource preconditions to this shared action gate.

## Steps

1. Bind confirmation intent to the current session/workspace/access generation and exact target; dismiss it when that context changes.
2. Check current access and online/foreground availability immediately before dispatch while preserving single-flight and authoritative ambiguous-outcome handling.
3. Provide translated accessible checking/unavailable/offline reasons; never replay a previously confirmed action when connectivity returns.

## Acceptance criteria

- [x] A confirmation opened before downgrade, workspace switch, or logout cannot submit afterwards.
- [x] Offline/stale/unknown access disables dispatch with a readable reason; reconnect never submits automatically.
- [x] An authorized action still submits once, and server rejection or ambiguous delivery retains the existing honest feedback.

## Out of scope

- Server resource-action query/mapping changes, owned by m141.
- Adding dangerous actions or weakening confirmations.
