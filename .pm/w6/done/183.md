# 183 — A Blueprint whose `dockerCommand` is longer than 4096 bytes is refused, so Render's `pg_pinecone_render` template cannot deploy

Why: Render's own template fails validate, plan and apply on bex, and the weekly corpus guard reports it as valid, so nothing has flagged it.

- **Source:** w6/m644 t003 (2026-11-26), the live run of twenty `render-examples` templates ([render-examples-live.md](../../../docs/render-artifacts/render-examples-live.md)).
- **Seen:** on production pin `2bd6e1f415d3`, in `bex-canary`, `scripts/render-examples-live.sh pg_pinecone_render` stopped at the plan with `spec.startCommand: Too long: may not be more than 4096 bytes`. `POST /v1/blueprints/validate` gives the same refusal. The file's `dockerCommand` is 4,717 bytes: a start script inlined as base64 lines, as its comments explain (render-examples/pg_pinecone_render@699d5d604c9e).
- **Where:** the App CRD caps `startCommand`, which carries a Docker or image service's `dockerCommand`, and `buildCommand` at 4096 bytes (`+kubebuilder:validation:MaxLength=4096`, `lego/types/v1alpha1/app_types.go` around line 776, with more caps at lines 952, 963, 1538, 1727 and 1937). The API server enforces it on the server-side dry run that production validation runs. `TestRenderExamplesCorpus` validates against a fake client that has no CRD schema, so it reads the file as valid (170 of 185 on 2026-11-25).
- **Render:** its public API schema puts no length limit on `startCommand`, `dockerCommand`, `buildCommand` or `preDeployCommand` (`lego/backend/internal/api/openapi/render-public-api-1.json`). The template's README quotes `render blueprints validate` output for this same file, so it was validated on Render.
- **Do:**
  1. Accept commands of any length Render accepts, on every path that writes them (Blueprint, REST create and PATCH, GraphQL, MCP). If the CRD needs a bound for etcd's sake, keep the command where the bound is generous enough, for example well above Kubernetes' own `args` sizes, and record it in ADR018 with the user's sign-off if it is below what Render accepts.
  2. Make the corpus guard see CRD schema refusals, or add a test that validates each corpus file's commands against the CRD caps, so the next refusal of this class fails the weekly job.
- **Acceptance:**
  - [x] `bash scripts/render-examples-live.sh pg_pinecone_render` passes validate and plan on production; if it then fails at a later stage, that stage is filed or fixed.
  - [x] A regression test with a 4,717-byte `dockerCommand` passes validate, plan and apply.
- **Estimate:** ~1h. A Render parity task applies (REST, GraphQL, MCP and the dashboard's command fields).
