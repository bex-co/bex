## Done

Done 2026-11-10 on production (the 21:47 UTC deploy of `a0d580259`; QA workspace `bex`). The four probe services of `w6/blocked/m306`'s t006 record each built twice in the 21:00 UTC hour; after the 22:4x rollup their `build_seconds` read identically on REST `GET /v1/usage`, GraphQL `usage` and MCP `get_usage`, and the billing page's Charges listed them at $0.00 (inside Scale's included minutes):

| service | `build_seconds` | deploys' wait before the build started (not metered) |
| --- | --- | --- |
| `qa-20261110-w6-a` | 101 | 144 s + 61 s |
| `qa-20261110-w6-b` | 100 | 130 s + 13 s |
| `qa-20261110-w6-c` | 48 | 81 s + 13 s |
| `qa-20261110-w6-fail` (missing Dockerfile, both builds `build_failed`) | 29 (17 s + under 22 s) | 80 s + 73 s |

So a failed build bills its run, as Render's "all pipeline tasks consume pipeline minutes" reads, and the wait for admission or a node is excluded: each total fits the builds' own `startedAt`→end, and counting the waits would have more than doubled it. `bex_build_queue_seconds` could not be read (ops Grafana); the deploys' own `createdAt`→`startedAt` stood in for it. Pre-deploy was not run live: a pre-deploy command needs a paid plan (Render's rule, `errPreDeployCommandFreePlan`), and QA rules forbid buying one; `TestBuildSecondsCountsPreDeployRunsInTheAppsNamespace` covers it. The probe services were deleted afterwards. No drift to file.
