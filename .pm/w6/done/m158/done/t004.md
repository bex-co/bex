## Objective

Let `build` start alongside the test jobs; `deploy` (pin write-back) still needs every test job and the secret scan.

## Acceptance criteria

- [ ] A failing test still blocks the pin; a passing run saves the test duration from the critical path.
- [ ] `scripts/github-actions-validate.sh` wiring checks (supersession, ref guard) still pass.

## Done — 2026-11-06

`build` needs only `secret-scan` and `check-supersession` (the scan still gates it: the images are public); `deploy`, which pins, needs `build` and all four test suites, so a failing suite still blocks the pin while their 10–30 min leave the critical path. A red suite now costs one wasted build. Note that the build (bex-production, 12 CPUs) and the suites (bex-ci, 4 × 4 CPUs) now overlap on the same 24-CPU Docker VM.
