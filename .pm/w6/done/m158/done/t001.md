## Objective

Run compile stages natively on the ARM64 runner and target `linux/amd64` via `GOARCH`/copied output, so no compiler runs under emulation.

## Context

- `lego/Dockerfile` builder stage has no `--platform=$BUILDPLATFORM` (8 `go build` steps); `dashboard/Dockerfile` and `lego/agent-image/Dockerfile` node build stages likewise.

## Steps

1. Add `FROM --platform=$BUILDPLATFORM` to compile stages; keep runtime stages on the target platform.
2. Confirm the produced binaries are x86-64 (`file`) and images still build from the pinned bases.

## Acceptance criteria

- [ ] Images build for `linux/amd64`; binaries are x86-64; operator image build time drops measurably.

## Done — 2026-11-06

- `lego/Dockerfile` and `deploy/opensandbox/controller.Dockerfile` builders run on `$BUILDPLATFORM` (every build is `CGO_ENABLED=0 GOARCH=${TARGETARCH}`); the agent image's `driver-build` (tsc to JS; the final stage reinstalls `node_modules` on the target) does too. The dashboard builder is left on the target platform: its `.output` may carry platform-specific `node_modules`.
- `GOMAXPROCS` is an `ARG` (default 4); `deploy.yml` passes 12 for the operator and controller builds.
- Verified: a local `docker buildx build --platform linux/amd64` of `lego/` produced static x86-64 binaries; a review build of `native-init` and `drain-guard` natively on arm64 and under amd64 emulation gave identical sha256s. `govulncheck.yml`'s image derivation skips the `--platform` flag (fixture updated); `make docker-buildx` no longer sed-inserts a duplicate `--platform`.
