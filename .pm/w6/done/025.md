# Remove the Free instance tier for Background Workers

Why: Background Workers must use paid compute; removing the Free option avoids an unintended zero-cost capacity commitment and resolves the worker-tier product decision.

## Decision (2026-09-06)

**Background Workers must not have a Free instance tier.** The user explicitly
rejected that option. Use the lowest eligible paid tier as the default for a new
Background Worker, with pricing from bex's tier catalog.

This supersedes the 2026-09-03 triage recommendation to keep Free workers as a
differentiator. The product decision is settled; implementation remains pending.

## Context

The 2026-08-21 live bex-vs-Render Background Worker QA pass
(https://claude.ai/code/artifact/29934e6e-7bd8-4fa0-8a86-26327bb72932, finding 3)
reported that bex's `/services/new` picker offered **Free — 512 MB / 0.1 CPU**,
pre-selected for Background Workers, while Render's equivalent picker started
at a paid tier. The 2026-09-03 source triage confirmed the picker had no
per-service-type exclusion for its Free group.

## Implementation follow-up

- In `dashboard/src/features/services/`, exclude Free from Background Worker
  creation and instance-type changes. Default to the lowest eligible paid tier;
  switching from another service type must not carry a Free selection into a
  Background Worker submission.
- Enforce the same eligibility in `lego/backend/` for worker creation and plan
  changes, including Blueprint input, so REST, GraphQL, and MCP cannot bypass
  the dashboard restriction. Omitted plans must resolve to an eligible paid
  default; explicitly requesting Free must return a clear validation error.
- Record the paid-only worker policy in `docs/ADR030-pricing.md` and
  `docs/ADR018-render-parity.md` alongside the implementation.
- Identify existing Free workers and document their transition before rollout;
  do not silently convert them to billed instances.
- Add regression coverage for worker defaults, service-type switching, Free
  creation/downgrade rejection, and continued eligibility of service types
  that support Free.

## Acceptance criteria

- Background Worker create and instance-type pickers never offer Free and use
  an eligible paid default.
- Worker creation and plan changes cannot persist a Free plan through the
  supported API or Blueprint paths.
- Pricing/parity documentation reflects this decision, and existing Free
  workers have an explicit transition path.

## Resolution (2026-09-06)

Implemented end to end, all acceptance criteria met:

- **Backend** (`lego/backend/internal/apps/`): `normalizeTierForType` in
  `service.go` — the plan-resolution step of `specFromCreate`, which REST,
  GraphQL, MCP `create_web_service(type: background_worker)`, and the
  Blueprint apply/validate paths all funnel through — defaults a plan-less
  worker to the catalog's cheapest paid rung (`defaultPaidTierID()` →
  `starter`) and refuses explicit free with a named 400 listing only paid
  plans (`errWorkerFreePlan`). `SetPlan` and `PreviewSetPlan` (REST PATCH,
  GraphQL `updateServicePlan`, MCP `update_service` all fold into them)
  refuse a worker downgrade to free identically. The Blueprint billing probe
  `stackHasPaidPlan` and `blueprintEstimatedPricing` resolve plans
  type-aware, so a plan-less worker trips the ADR046 payment-method gate and
  is priced at the paid default. MCP plan-arg jsonschema documents the rule.
- **Dashboard** (`dashboard/src/features/services/`): shared
  `offeredInstanceTypes` (`lib/instance-type.ts`) filters Free out for
  workers in both the create form's plan grid (`use-new-service-form.ts` —
  paid default, and an ineligible Free override never survives a type switch
  into a worker submission) and the existing-service `InstanceTypePicker`
  (now takes `serviceType`).
- **Docs**: policy, enforcement seams, and the existing-free-worker
  transition recorded in ADR030 §7 (paid-only workers; identification SQL,
  no silent conversion — run the query against production before rollout)
  and the ADR018 Background Worker parity row.
- **Regression coverage**: backend `worker_plan_test.go` (paid default,
  create/SetPlan/Preview/Blueprint refusals, billing+pricing probes) +
  updated `instance_cap_test.go` type family (web/private keep Free);
  dashboard tests for the picker (no Free group for a worker), form hook
  (paid default, no Free carry-over, restore on switch-back), and the
  create route (grid, default, worker submission after Free was picked).
  Full backend `go test ./...`, backend golangci-lint, dashboard
  `yarn test` (3010 tests) + `yarn lint` + typecheck all pass.

Existing free workers (if any in production) are untouched by construction —
enforcement applies to new writes only; the transition path is documented in
ADR030 §7.
