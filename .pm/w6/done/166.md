# A listener read can go to the reader pod the DaemonSet is deleting, so one read fails at each reader roll

Why: at each pin's roll a node runs its old and its new listener reader for a moment, and the operator can pick the old one after its port has closed. A private service's port read then fails, and its update waits for the next 2-minute scan.

- **Where:** `NodeListenerReader.PodListeners` (`lego/operator/internal/controller/listener_reads.go`) reads through the first reader pod on the pod's node that is `Running` and Ready. It never checks `deletionTimestamp`.
  - The DaemonSet `bex-listener-reader` rolls with `maxSurge: 1` and `maxUnavailable: 0`. So the new reader is Ready before the old one is deleted.
  - The old one stays `Running` and Ready in the operator's cache for a moment after its listener closes.
- **Seen on production (w6/m530 t007, the day from 2026-11-20T22:46Z):** two reads failed, both `connection refused` at a pin's roll.
  - **02:25:11Z.** The read went through `bex-listener-reader-b47s4` on `bex-tenant-0-wldb9-khm29`.
  - **22:02:57Z.** The read went through `bex-listener-reader-nkhph` on `bex-tenant-0-zdp6v-85xrs`, in the second the DaemonSet deleted it: `Killing` at 22:02:57Z, one second after its replacement `gdb7g` started.
  - **What each did.** Each counted `source="reader",result="failed"` and logged `private network port scan failed; keeping the last listeners`. It kept the last record and swept nothing. Found in t008's review, then seen in t007's read.
- **Fix sketch:** among a node's Ready readers, prefer one with no `deletionTimestamp`. Read through a terminating one only when it is the node's only Ready reader, never sweep.
- **Done when:** a unit test in `listener_reads_test.go` puts two Ready reader pods on one node, the first with a `deletionTimestamp`, and sees the read go to the second. A node whose only reader is terminating still reads through it or answers the not-ready error, and does not sweep.

Done 2026-11-23: `NodeListenerReader.PodListeners` (`lego/operator/internal/controller/listener_reads.go`) now asks, of a node's Ready readers, one with no `deletionTimestamp`, and a terminating reader only when it is the node's only Ready one. `TestNodeListenerReaderSkipsAReaderBeingDeleted` (`listener_reads_test.go`) dials the old reader's closed port as `connection refused`: the read goes to the new reader whichever is listed first, and a node whose only Ready reader is terminating reads through it and fails without `errNoListenerReader`, so it never sweeps. Without the fix the test fails with the production error. ADR089 D3 phase 2 item 7 and the listener-reader row of `lego/operator/AGENTS.md` record the rule.
