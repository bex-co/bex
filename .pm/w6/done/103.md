# Argo CD reports 27 orphaned resources on bex-operator, a standing warning that hides real drift

Why: during the w6/100 outage the real `ComparisonError` sat next to a permanent `OrphanedResourceWarning`. Standing warnings train readers to ignore the condition list.

- **Evidence (2026-11-02):** `kubectl -n argocd get application bex-operator` → `OrphanedResourceWarning: Application has 27 orphaned resources`. The app runs `automated.prune: true` with ServerSideApply, so orphans are resources in its namespaces that no manifest owns.
- **Do:** list the 27 (`argocd app resources bex-operator --orphaned`, or the Application's `status`). For each, decide: delete a leftover, add it to a manifest, or mark it `argocd.argoproj.io/compare-options: IgnoreExtraneous` / add the project's orphaned-resources ignore list, with a reason. Then confirm the warning is gone.
- **Expected:** `bex-operator` shows no standing warning, so the next real condition stands out.

## Done — 2026-11-03

The 27 orphans were all bex-system objects installed out of band by design: 26 credential Secrets from CI/.env custody (`bex-stripe`, `bex-smtp`, `bex-openfga`, `bex-ssh-host-key`, `bex-registry-*`, …, plus `webhook-server-cert`), the `bex-ssh` ConfigMap (bex-api's public SSH host, `lego/operator/config/api/deployment.yaml:63`) and CNPG's `cnpg-default-monitoring`. None was a leftover to delete, and none belongs in git (ADR019). The `bex-platform` AppProject now ignores exactly those (`Secret bex-*`, `Secret webhook-server-cert`, two named ConfigMaps) — `e53505211`. After Argo synced the project and refreshed `bex-operator`, its condition list is empty; any new orphan still warns.
