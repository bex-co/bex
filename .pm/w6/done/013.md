## Note

**Reproduced, not theorised** (probe run 2026-07-13 during w6/m14; pre-existing, not introduced by it).

A resource-scoped verb runs two gates:

1. `s.Authorize(ctx, rel)` → checks `rel` against the **caller's default workspace**.
2. `s.GetApp(ctx, rel, name)` / `fetchDatabase` / `fetchKeyValue` → w6/m14 made these check `rel` against the **resource's own workspace**.

Effective permission is therefore the **intersection** of two unrelated workspaces' roles, and gate 1 can only produce false negatives. m14 fixed gate 2 (its DoD's clause) and left gate 1.

**Why it bites real users.** `internal/api/tenancy.go` `EnsureTenant` redeems pending invites **before** minting the personal tenant, so for someone who signs up _because_ they were invited, the **invited workspace is their oldest membership — i.e. their default**. If they were invited as a `viewer` or `contributor`, their default workspace lacks `can_operate`/`can_create`. They then cannot restart, suspend, delete, or set env vars on services in **their own personal workspace**:

```
bob: default = tea-team (invited VIEWER), own = tea-mine (admin), service "mine-web" in tea-mine
svc.Restart(bob, "mine-web") => forbidden        # can_operate checked against tea-team
```

The dashboard sends `ownerId` only on **lists** and **creates**, so every per-service operation (detail, logs, metrics, deploys, env vars, restart/suspend/delete) hits this. It also costs an extra `IsMember` SELECT + OpenFGA `Check` per verb for any caller working outside their default workspace.

## Fix (designed, not applied)

Collapse the two gates into one seam for resource-scoped verbs — `core.Base.AuthorizeApp(ctx, relation, name) (*App, error)`: fetch the resource, derive its workspace from `core.LabelTenant`, authorize `relation` **there** once, audit there once (target = the resource name), return it. Replaces `Authorize` + `GetApp` at the ~45 call sites; the relation is then named **once**, so it cannot drift, and `core.Base.AuthorizeLabeled` (added by m14) is already the check it needs.

Two things to preserve:

- **403-before-404**: today `Authorize` runs before the fetch, so an unauthorized caller gets `ErrForbidden` for a name that doesn't exist. `TestAuthzGuardsEveryVerb` sweeps verbs against an empty fake client and expects `ErrForbidden` — a naive fetch-first `AuthorizeApp` returns `ErrNotFound` and fails that sweep. Authorize against the acting workspace when the fetch 404s.
- `TestEveryTargetedVerbIsNamedOrExcused` keys off `AuthorizeTarget` usage; the events vocabulary must follow the new entry point.

An alternative (or complement), from the same review: populate `core.WithWorkspace` **once at the request boundary** (the auth gate, from an `X-Bex-Workspace` header / `?ownerId=`; MCP from the session selection) rather than only in the three create verbs. Then a request _acts in_ one workspace for its whole life, `Authorize` gates against the workspace the user is actually looking at, and this largely dissolves. Caveat: the dashboard's selection lives in `localStorage`, so the header path needs it in a cookie for SSR.

## Also found in the same review (smaller)

- **`List(ownerID)` is a weaker spelling of the same question** (`apps/service.go`, `postgres/service.go`, `keyvalue/service.go`): it gates a named `ownerId` with `AuthorizeOn(can_view, workspace:<id>)` — OpenFGA **only, no `IsMember`**. With `Authz == nil` (authorization off), `List(ctx, "tea-someone-elses")` returns that workspace's resources. m14 built the correct mechanism (`core.WithWorkspace` → `resolveWorkspace` → membership **and** OpenFGA) and left the older one beside it. Fold `List` onto it.
- **The default-workspace rule itself is arguable.** "Oldest membership" is deterministic (w6/m14/t001) but, per the invite-ordering above, it is often the workspace the user cares _least_ about. Better: order by the tenant they **own** (`tenants.owner_identity_id`, `TenantForOwner` already exists) before `created_at` — or persist the selection (the dashboard already keeps one in `localStorage`; it belongs in the store, where the API and MCP could share it).
