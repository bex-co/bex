# A compute-plan or serving-pool edit in `lego/types/tiers` rolls both SNI proxies and closes their external clients older than an hour

Why: since w6/150 a CRD edit no longer moves the SNI pins, and the `tiers` catalog is now the largest outside input both binaries link whole. Each move closes every external Key Value and Postgres connection still open 1 h after the old pod's `SIGTERM`, without notice, where Render breaks such connections only in announced maintenance ([platform maintenance](https://render.com/docs/platform-maintenance), read 2026-11-19).

- **Filed by** w6/150 (2026-11-20), from its check of what else the binaries link ([ADR021 § 10](../../../docs/ADR021-keyvalue-management.md#10-a-platform-deploy-rolls-no-stores-proxy-w6m469-w6m470-2026-11-18), "What moves an SNI binary").
- **Evidence.**
  - Both proxies read only `tiers.Valkey.Resolve(plan).ConnectionLimit`, `tiers.Postgres.Resolve(plan).MaxConnections` and `tiers.PostgresPoolerMaxClientConn` (`lego/operator/cmd/kv-sni-proxy/main.go`, `cmd/pg-sni-proxy/main.go`). The package embeds the whole `tiers.yaml` and every compute tier, and a binary changes with any source edit in a package it links (the Go build ID hashes every file).
  - Of the 128 production pins from 2026-11-01 to 2026-11-20, 8 followed a `tiers` edit and no change to the proxies' own code, so they moved both pins. Most of those edits touched only compute plans or serving pools (`daa286c97`, `9df72fafd`, `cea85222d`, `c0c9d880b`, `e1c7d08cc`) or refactors (`f05cc9694`, `ab14f1232`). `0eed45bcb`, `22287e974` and `5f5af11fc` changed the datastore plans or their limits, which the routes do read.
- **Directions to weigh.**
  - Have the operator publish each datastore's resolved connection limit on the CR, so the routing views in `lego/operator/internal/sniproxy/crd.go` read it there and neither binary links `tiers`. Check how a status that lags a plan change sizes a route meanwhile.
  - Or give the datastore limits a package of their own that `tiers` builds on, with a test that keeps the two in step.
- **Done when:**
  - An edit to a compute tier or a serving pool in `lego/types/tiers` leaves `/kv-sni-proxy` and `/pg-sni-proxy` byte-identical. `TestACRDFieldEditLeavesBothProxiesByteIdentical`'s allowed package list no longer holds `types/tiers`, or a test proves it the same way.
  - A datastore plan's connection limit still sizes its route, and a change to it still rolls the proxies or reaches them without a roll.
  - ADR021 § 10 says so.

## Outcome (2026-11-20)

Done: the datastore connection limits have a package of their own, `lego/types/tiers/connlimit`, and both SNI proxies link it and nothing else of `tiers`. This is the second direction above. The first, a limit the operator publishes on the CR, was rejected: it needs a CRD field, it lags a plan change, and the proxies would still need a size for a route whose status the operator has not written yet (a new store, or every store while a deploy rolls the proxies before the operator).

- `connlimit` holds `Valkey` and `Postgres` (each plan's limit and the family default) and `PostgresPoolerMaxClientConn`. `tiers` fills each datastore tier's `ConnectionLimit` and `MaxConnections` from it, and refuses to load a datastore plan without a limit, or a default other than `connlimit`'s. `tiers.yaml` carries no limit, and its strict decoding refuses `maxConnections` and `connectionLimit`. The proxies size routes with `connlimit.Valkey.Resolve` and `connlimit.Postgres.Resolve`, the same rule as `tiers`' `Resolve`.
- `TestACRDFieldEditLeavesBothProxiesByteIdentical`'s allowed list holds `types/tiers/connlimit` instead of `types/tiers`. `TestACatalogEditLeavesBothProxiesByteIdentical` builds both proxies before and after an overlay that changes the free compute tier's CPU, `pro-plus`'s serving pool and `tiers.go`, and the binaries are byte-identical. After a `connlimit` edit, both change. With `kv-sni-proxy` reading `tiers` again, both tests fail. Built for `linux/amd64` with `CGO_ENABLED=0` and `GOWORK=off`, as the image builds them, the same `tiers` edit changed both binaries at `d9c5bfed1` and neither on the tree.
- `TestConnectionLimitsAreTheCatalogs` (tiers) checks that each ladder names exactly the catalog's plans, and that every plan, `""` and an unknown plan resolve to the same limit on both sides. `TestRouterCarriesEachStoresCapacityFromThePlan` (new, kv-sni-proxy) and `TestRouterCarriesEachRoutesCapacityFromThePlan` (pg-sni-proxy) check that the routes of every plan the catalog or `connlimit` names admit twice the operator's figure.
- ADR021 § 10 has a new "Connection limits (w6/154)" bullet, and ADR009 and ADR021 § 9 name `connlimit` as the figure's home.
- The pin that carries this commit moves both SNI pins once, because both proxies' own code changed. After that, a `tiers` edit keeps both pins. w6/150's planned check is unaffected: it needs a later pin whose range edits `lego/types/v1alpha1` and nothing else either proxy links, and this pin is not one.
