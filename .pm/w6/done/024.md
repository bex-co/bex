# Open-signup funnel observability counters

Why: ADR075 makes these three readable counters a launch precondition, so open signup must not ship without a way to see where users stall between verification, payment binding, and first deploy.

From `docs/ADR075-user-onboarding.md` Consequences (2026-08-20 review): activation is now a three-step funnel (verify email → bind card → first deploy) with no measurement. Before open signup, minimal counters must be readable — no new framework:

- identities unverified > 24h (Kratos admin API / `verifiable_addresses`),
- workspaces with no `payment_method_bound_at` > 24h and not comped (`billing_provider_mappings`),
- workspaces at zero resources (apps/databases/keyvalues count).

Cheapest shape: a small scripted read (SQL + Kratos admin call) or three Prometheus gauges if a scrape already passes by. Sub-hour; pairs with `w6/m42` (the gates themselves) but is not a blocker for implementing them — it IS a blocker for the open-signup launch per the ADR.

## Resolution (2026-09-03)

Implemented as `scripts/funnel-counters.sh` — the ADR075 three-counter scripted read (Kratos admin identities-unverified >24h with Link-header pagination; workspaces unbound >24h via the exact `PaymentEligibility` predicate — `payment_method_bound_at IS NULL AND NOT billing_comped AND NOT billing_excluded` per migrations 0046/0051/0058; zero-resource workspaces via the `apps` table plus Database/KeyValue CRs by the `bex.co/tenant` label). Mirrors the sibling scripts' config (BEX_CP_DB_URI-or-CNPG-exec, KRATOS_ADMIN_URL-or-port-forward); registered in `scripts.yml` shellcheck; shellcheck + bash -n clean, jq/pagination/comm logic fixture-tested offline. No Prometheus gauges — the note's cheapest-shape option chosen.
