## Objective

Add broader test coverage for the i18n switching/SSR-isolation behavior this milestone shipped, beyond the two targeted regression tests in t003.

## Context

- t003 covers the two specific bugs found live. This task covers the surrounding behavior a reviewer would expect to see asserted: that the shared-helper extraction (if t005 did one) is covered from all three call sites, that `ensureLanguage` genuinely no-ops when the catalog is already loaded (no duplicate `import()`), and that the per-request isolation mechanism doesn't leak between requests for more than just the two-language case (e.g., a third rapid request in the original/default language after two non-default ones).

## Steps

1. Add tests for `ensureLanguage`'s idempotency (calling it twice for the same language doesn't re-fetch/re-register).
2. If t005 extracted a shared `switchLanguage()` helper, add a test asserting all 3 call sites route through it (e.g. via a spy/mock on the helper).
3. Extend t002's concurrency test with a 3-request interleaving (not just 2) to raise confidence the isolation mechanism generalizes past the minimal repro.
4. Ensure tests fail meaningfully (not tautologically) — each new test must be provably capable of catching a regression, not just re-asserting current output.

## Files

- Same test files as t003, extended; new test files only if a genuinely separate concern needs one (e.g. `ensureLanguage` idempotency belongs in `dashboard/src/i18n/__tests__/init.test.ts` if one exists, else create it).

- [ ] `ensureLanguage` idempotency covered.
