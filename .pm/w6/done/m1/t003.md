## Objective

User-initiated workspace creation and rename as Core verbs. CreateWorkspace(name, plan) writes the `tenants` row (`tea-` id), a `tenant_members` row for the caller, and the OpenFGA admin tuple — atomically, reusing w1/m9's mint path (one write path, not two). It refuses the caller's 6th Hobby workspace. RenameWorkspace updates the display name, admin-only.

## Context

- w1/m9 t001's tenant-mint code is the template: same tables, same FGA tuple shape (`workspace:tea-<id>`, model in `deploy/gitops/authz/model.fga`).
- Core is the single business-logic layer (`lego/backend/internal/core/`); REST/GraphQL/MCP are thin adapters (docs/bex-api.md).
- Render semantics: creation asks name + plan (RESEARCH-workspaces.md finding 2); 5-Hobby cap is per user (finding 3); rename semantics per t001's captured artifact.
- Authorization: create needs only an authenticated identity; rename requires workspace admin (`core.Authorize`).
