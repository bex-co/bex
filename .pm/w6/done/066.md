## Journey 7's filter half — swept, all correct, recorded so it is not re-run

Probed `GET /v1/logs` on `beancount-cms-v2` over a 24h window, and the dashboard's Logs tab:

- **Text search is a true substring match, not a fuzzy one.** `text=character metrics` → 100 rows, every one containing the phrase. The subsequence `chrtr` → **0 rows**. This is the class `w9/m92` found in the agents sidebar ("subsequence fuzzy-match over-matches prose"); it does **not** recur here.
- **Matching is case-insensitive, and genuinely so rather than the filter being skipped.** `text=CHARACTER` → 100 rows, all containing lowercase `character`, **none** containing uppercase `CHARACTER`. A nonsense token returns 0, proving the filter is applied.
- **It narrows below the page limit.** `text=listening` → **21** rows, `hasMore: false`, all containing it. `text=Main-Regular` → 100 with `hasMore: true`, correctly paginated.
- **`instance=` and `type=` are exact.** Filtering to one of the two live instances returned 100 rows all carrying that instance label; `type=app` and `type=build` each returned rows whose `type` label matched.
- **An empty result is honestly empty.** `beancount-forum` returned 0 rows over a 6h window — its newest log is `10:19:48Z`, over seven hours old. Checked against the other four services in the workspace, all of which return logs over 24h, so the pipeline is healthy and that service is simply quiet. My initial 6h probe reading zero was **not** a defect.
