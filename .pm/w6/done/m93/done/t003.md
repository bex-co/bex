## Findings (2026-08-25)

**t001 — parity by construction, verified.** `PostgresConnectionInfo` is one verb returning one struct. REST serves it at `GET /v1/postgres/{id}/connection-info` (`rest.go:191`, via `core.HandleByID`) and GraphQL projects the same struct field-by-field (`graphql.go:175-179`), so `internalConnectionString` and `psqlCommand` cannot disagree between the two surfaces. **MCP deliberately exposes no connection-info tool** — the connection strings _are_ the password (`service.go`'s own `can_view_sensitive` re-assertion comment), and that reveal is kept off the agent surface. That is an existing deliberate divergence, not one this milestone introduces.

**t002 — all three transports resume.** `Last-Event-ID` is read in the shared `subscribeLogs` handler _before_ the transport branch, so SSE, NDJSON, and the Render-CLI WebSocket upgrade all get the bound. Only SSE emits `id:` frames (NDJSON and WS have no such framing), which is correct: the header is a browser-EventSource mechanism, and the other two transports' clients drive their own reconnects with an explicit `startTime`.

**Render comparison.** Render's log stream is a WebSocket, not SSE, so it has no `Last-Event-ID` equivalent to match — bex's SSE transport is already a recorded deliberate divergence (`ADR018`, and this task's own out-of-scope note). Nothing new to record: the resume cursor is an internal efficiency property of bex's own transport, invisible in the response shape. The Postgres connection-string change is likewise shape-preserving — the same field, a different host spelling — so no Render-facing contract moved.
