## Findings (2026-08-25)

Reviewed this milestone's own diff. It is small (≈4 production lines in `postgres/service.go`, a threaded parameter plus one option in `logs/`), so there was little to collapse — but the review caught two real defects in my own first cut, both now fixed and both covered by tests:

1. **`%!(EXTRA string=…)` on every NDJSON line.** The first version reused the existing single format-string-per-transport pattern and passed the frame id as a second `Fprintf` argument. SSE consumed it via `%[2]s`; NDJSON's unindexed `%s` did not, so Go appended `%!(EXTRA string=…)` to each line — corrupting the JSON for CLI clients while the SSE path looked perfect. Verified the behavior in a scratch program rather than trusting recall of `fmt`'s rules.
2. **An empty `id:` silently disabling resume.** A log line with no parseable timestamp produced `id: ` — and per the SSE spec an empty `id:` field _sets_ the client's last-event-id buffer to empty, after which the browser stops sending the header entirely. One stray stamp-less line would have turned resume off for the rest of the tail.

Both are gone: the two format strings were replaced by a single `frame(payload, id)` helper that renders per transport and omits the id line when there is no stamp. That is also simpler than what it replaced — one function instead of two parallel format strings whose argument arity had to stay in sync.

Not changed: `PostgresConnectionInfo` still hardcodes `:5432` in the new internal string, matching all five sibling strings in the same function rather than introducing a lone `d.Status.Port` read; mixing the two conventions in one function would be worse than either.
