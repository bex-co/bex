## Objective

Make the in-cluster BuildKit Job authenticate private `FROM` pulls with the App's bound registry credential, using the same security boundary as the push secret: a docker-config mounted into the buildkitd/cosign container filesystem only — never a Docker build arg, a BuildKit secret, or anything a tenant Dockerfile `RUN` step can read.

## Context

- Precedent: `BEX_REGISTRY_PUSH_SECRET` (CLAUDE.md env table; `docs/ADR022-tenant-isolation.md` § Registry access control) mounts a docker-config Secret into the build Job for the push — the exact boundary this credential needs for the pull side.
- The workspace-scoped `dockerconfigjson` Secret already exists (m31 materializes `<app>-registry-pull` for the runtime pull path); the build Job needs it merged with the push config (both may be needed in one build: private base pull + Zot push).
- Build Job assembly lives in `lego/operator/internal/` (the BuildKit Job builder; grep for the push-secret mount).

## Steps

1. Thread the CR's credential binding into the build-Job spec: mount/merge the credential's docker config alongside the push secret's, into the buildkitd container only.
2. Handle the merge when both configs carry auths (distinct hosts; last-writer must not clobber the push host).
3. Ensure the Secret reference is namespace-correct (`BEX_BUILD_NAMESPACE` vs the App namespace — copy/mirror the way the push secret handles it).

## Files

- `lego/operator/internal/` build-Job builder (locate via the `BEX_REGISTRY_PUSH_SECRET` mount)
- `lego/operator/` reconciler threading from the App CR field

## Acceptance criteria

- [x] A build with a bound credential gets the merged docker config in the buildkitd container fs; unit test asserts the mount lands only there.
- [x] Push auth still works when both configs are present (no auths clobbering).
- [x] Unset binding ⇒ byte-identical Job spec to today.

## Evidence

`prepareBuildRegistrySecret` copies the explicit App-namespace docker config, merges the optional build-namespace push config, and writes `bld-<app>-registry-auth`. Later push auth wins collisions. BuildKit mounts the derived Secret at `/docker-config`; the finalizer deletes it. The derived config also makes the already-insecure cluster-local output registry usable as a private base source on development stacks.

## Out of scope

- kpack (CNB) builds — Render's field is Docker-runtime-only; note the divergence if kpack private bases ever matter.
