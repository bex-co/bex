## Objective

Accept Render's `serviceDetails.envSpecificDetails.registryCredentialId` on create and patch for repository-backed Docker-runtime services, persist the binding (store + App CR), and retire the named 400 that `w6/m31` shipped for this context — across REST, GraphQL, and MCP.

## Context

- `lego/backend/internal/apps/pullsecret.go:66-70` returns the named 400 (`registryCredentialId currently applies only to an image-backed service`); `service.go` (~line 2506) carries the deferral comment.
- `w6/m31` already built the whole validation path (workspace-scoped lookup, tri-state PATCH decode, `SetSourceAndRegistryCredential` verb, `TypeSourceChanged` events, OpenFGA `RelCanOperate`) for the image context — extend, don't duplicate.
- The App CR already carries the binding field (migration 0036 + `lego/types/v1alpha1/app_types.go` from m31); check whether the repo-backed case needs a distinct field or reuses it with the source-type discriminator.
- Render contract capture: `docs/render-artifacts/registry-credential-service-binding.md`.

## Steps

1. Extend the create/patch accept paths (REST `rest.go`, GraphQL `graphql.go`, MCP `mcp.go`) to admit the nested field when the service is repo-backed with Docker runtime; keep rejecting it for non-Docker runtimes with a named error (Render scopes it to `envSpecificDetails` = Docker).
2. Persist through the store and CR projection so the operator (t002) can see the binding on build.
3. Echo the field on reads across all three surfaces, mirroring m31's read shape.
