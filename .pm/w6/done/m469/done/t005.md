- Use the README § Findings method (`skopeo inspect` plus `curl` of the `kv-internal-proxy` layer) to hash a producer's binary before reading the result.

## Steps

1. Before the deploy, record each store's `<id>-internal` image, ReplicaSet list, and pod name and start time. Also hash the producer's `/kv-internal-proxy`. If it differs from `d1a7d7d0e8ecc328…`, name the commit and expect one roll.
2. After the deploy: the same pods, the same image, no new ReplicaSet, and the annotation recording the hash on each Deployment (t002's adoption).
3. Create a free probe store in `bex-canary`. Hold one client through `<id>:6379` from a pod in that namespace, noting `CLIENT ID`, across the next deploy whose producer leaves the binary alone. Afterwards check `PING` and the same `CLIENT ID`.
4. Then enable internal authentication on the probe (DoD bullet 4 on production): the proxy rolls once, onto the held digest and not the manager's, and the held unauthenticated client reads EOF.
5. Delete the probe store by ID (then `GET` answers 404) and the client pod.
