## Objective

After the cutover, `Cost.ComputeUSD` and the per-session spend ceiling count each of the session's sandboxes at what the bill charges for it.

## Context

- `Cost` and `ComputeUSD` (`lego/backend/internal/agentsessions/models.go`), computed in `outcome.go` from `AgentSessionComputeMilliSeconds` (`agent_session_sandboxes.compute_milli_seconds`, `lego/backend/internal/store/sandbox_meter.go`).
- The ceiling: `lego/backend/internal/agentsessions/spendceiling.go`, `spend.go` (ADR094 D7/D8).

## Steps

1. Attribute each agent sandbox's CPU and memory to its session, as compute milli-seconds are attributed.
2. Price a session's compute as the bill does on each side of the cutover.

## Files

- `lego/backend/internal/agentsessions/outcome.go`, `spend.go`, `spendceiling.go`, `lego/backend/internal/store/sandbox_meter.go`, a migration for the new attribution columns

## Acceptance criteria

- [x] A test: a session that ran across the cutover reports a cost equal to the sum of its rows. (The ceiling half does not apply; see below.)

## Done (2026-11-24, `b8510dadf2`)

- **Attribution.** Migration 0345 adds `agent_session_sandboxes.cpu_seconds` and `memory_gb_seconds` beside `compute_milli_seconds`. The meter adds each billed CPU and memory row's quantity in the transaction that writes it.
  - A CPU reading takes the meter's per-sandbox advisory lock first, as the cursor does, so it lands in the trigger's seed or the binding.
  - The binding trigger seeds all three totals from the sandbox's `usage_hourly` rows not marked `unbilled`.
  - The total follows each row's own mark, so an hour an older binary marked stays out of the session's cost too.
- **Price.** `pricing.Sheet.SandboxSessionMicroUSD` sums weighted milli-seconds × `sandbox.usdPerWeightedSecond`, CPU-seconds × `usdPerCPUSecond` and GiB-seconds × `usdPerMemoryGBSecond` exactly, and rounds once to the micro-dollar. `outcome.cost.computeUSD` uses it on REST, GraphQL, MCP and the webhook, which all read the one `outcomeCost`.
- **Premise corrected: the `maxSpendUSD` ceiling never counted sandbox compute.** ADR094 D8 bounds the session's platform model spend: `AgentSessionCeilingHeadroom` sums `agent_model_usage_events` only. So the ceiling counts the same sandbox CPU and memory as the bill on both sides of the switch: none. Nothing changed there, and ADR094 D7 now says so. Counting compute in the ceiling would be a new product decision, not a parity gap, and is not filed.
- **Tests.**
  - `TestAgentSessionUsageAcrossAgentSwitchPG` (real Postgres): two turns' sandboxes across the instant. It checks the seed before adoption (weighted half hour, billed memory, CPU read before adoption), the later accruals, an hour an older binary marked, and the session's totals equal to the sums of its billed rows by kind.
  - `TestOutcomeCostFoldsSandboxComputeIntoOneTotal`: $0.04475 + $0.021 + $0.1064 = `computeUSD` 0.17215.
  - `TestSandboxSessionMicroUSD`: one rounding, not three.
