## Objective

`kv-internal-proxy` can front a store whose tenants authenticate themselves: its plain listener forwards the client's bytes unchanged (no injected `AUTH`), still holds the plan's limit in the budget it shares with the TLS listener, and answers the client past it with Valkey's `-ERR max number of clients reached` in plain text. Its readiness check works in that mode.

## Context

- `kvinternalauth.Config.Passthrough` exists, but only for the external TLS path: `refuse` (`lego/operator/internal/kvinternalauth/proxy.go`) completes a TLS handshake with the store's certificate before writing the refusal when `Passthrough` is set, and `Check` refuses to run with it ("a check requires internal authentication"). A plain passthrough listener needs its own mode: no injection, plain-text refusal.
- `cmd/kv-internal-proxy/main.go` requires `VALKEY_PASSWORD` for every run and always builds the plain listener with `Password`.
- The check today is an authenticated `PING` that must read `+PONG` (w1/m166: a `-LOADING` or `NOAUTH` reply fails readiness). An unauthenticated `PING` reads `-NOAUTH` from Valkey before its loading check, so it cannot see `-LOADING`. Decide between keeping the password in the pod for the check only (the proxy already holds it today) and a check that needs none; record why.
- On the plain path the upstream's own refusal must still reach the client (m456's forwarding), which plain passthrough gives for free.

## Steps

1. Add a plain passthrough mode to `kvinternalauth` (a config field or a mode enum, not an overload of `Passthrough`), selected in `main.go` by an env var the operator sets (e.g. `BEX_KV_INTERNAL_AUTH=client`).
2. Keep one `Budget` across both listeners in that mode.
3. Make `--check` work in that mode per the decision above.
4. Tests: unit tests with a fake upstream (no `AUTH` is written upstream; the client's own `AUTH` passes through; the budget is shared with the TLS listener; the client past it reads the plain refusal bytes), and a `BEX_TEST_VALKEY=1` test against the pinned Valkey images (an unauthenticated client reads `-NOAUTH`, an authenticated one works, `maxclients` reached reads Valkey's error).
5. Add the new env var to the operator env inventory in `lego/operator/AGENTS.md`.

## Result — 2026-11-17

- `kvinternalauth.Config.Passthrough` is replaced by `Config.Mode`: `InjectAuth` (w8/204), `PlainPassthrough` (new) and `TLSPassthrough` (the external listener). `PlainPassthrough` writes nothing of its own upstream and refuses the client past the budget in plain text; only `TLSPassthrough` answers inside TLS. An unknown mode fails `Serve`.
- `kv-internal-proxy` selects the plain listener's mode from `BEX_KV_INTERNAL_AUTH`: unset is `InjectAuth`, `client` is `PlainPassthrough`, and anything else fails startup and `--check`. Both listeners share one `Budget`, as before.
- **The check decision: keep the password, for the check only.** `Check` is the same authenticated `PING` in every mode. Valkey answers an unauthenticated `PING` with `-NOAUTH` before it looks at loading, so a password-free check could not tell a loading server from a ready one, and w1/m166's readiness would regress. The proxy pod already held `VALKEY_PASSWORD`, so it gains no authority. Recorded in ADR021 § 9.
- Tests, each failing against its reverted change (checked by mutating the code):
  - `TestPlainPassthroughForwardsTheClientsOwnAuth`: no `AUTH` upstream even with the password configured; an unauthenticated client reads `-NOAUTH`, an authenticated one is served, and the upstream's own maxclients refusal reaches the client.
  - `TestPlainPassthroughSharesTheBudgetAndRefusesInPlainText`: one budget across the plain passthrough and TLS listeners; the plain refusal is plain text, the TLS one is inside TLS.
  - `TestCheckRequiresAuthenticatedPong` runs in both modes (`+PONG` ready, `-LOADING` not).
  - `TestRunClientModeForwardsTheClientsOwnAuth` and `TestRunRefusesAnUnknownInternalAuthMode` (`cmd/kv-internal-proxy`): the env var selects the mode, and the check still authenticates.
  - `TestValkeyBehindAPlainPassthroughProxy` (`BEX_TEST_VALKEY=1`, both pinned images, in `internal/controller`): `-NOAUTH` without the password, served with it, 50 admitted and the 51st refused, and the server's own refusal forwarded.
- `lego/operator/AGENTS.md` lists `BEX_KV_INTERNAL_AUTH`.
