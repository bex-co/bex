## Objective

Eight surfaces say `0` is "the controller default"; the operator says `0` is off. Pick one and record it. Every other task in this milestone is a consequence, and without this decision the milestone is satisfiable by making the docs match a behavior nobody chose.

## Context

- The two options are both coherent, and they are not equal in cost:
  - **A — `0` means off.** Cheapest: no operator change, correct the 8 sites, and make the Settings hint conditional so it does not assert sleep-and-wake next to a control set to "never". But it leaves ADR003's free-tier economics ("a sleeping pod occupies nothing… Free approaches \$0") describing something that does not happen for any service created normally, so ADR003 needs amending too — this option is not doc-free, it just moves which doc is wrong.
  - **B — `0` means a real default.** Matches all eight existing statements, ADR003, ADR007, and Render (whose free spin-down is fixed and always on). Requires a default constant, a change to `autoSleepEligible`, and an explicit decision about **already-running free services**, which would start sleeping.
- No ADR currently names a default value. `docs/ADR007-restart-suspend-and-resume.md:18` records the pre-implementation state ("`spec.idleTTLSeconds` … currently unread"); nothing supersedes it with a number.
- The dashboard's shortest offered window is 300s (`IDLE_TIMEOUT_PRESETS = [0, 300, 900, 1800, 3600, 7200]`), which is the natural anchor if B picks a value.

## Steps

1. Choose A or B. The recommendation on the evidence is **B** — the mechanism is built, live and healthy (this milestone's captures show hibernate in 61s and wake in 15s), ADR003 depends on it, and Render's equivalent is always-on — but this is a product and cost decision, so record the reasoning either way.
2. If B: pick the default value and say why. Note that the constant belongs in the operator, since that is the only component that can act on it, and that the API must keep round-tripping a literal `0` rather than rewriting it to the default on write (otherwise "off" becomes inexpressible — the exact one-way-field trap `w7/m80` hit with health-check paths).
3. If A: decide how a user expresses "sleep on the platform's schedule", or record that they cannot and that every free service is always-on by default.
4. Write the decision into `docs/ADR003-control-plane.md` (its `sleep = free` paragraph) and `docs/ADR007-restart-suspend-and-resume.md`, and note whether ADR018 gains a parity row.

## Outcome

**Chose B: `idleTTLSeconds: 0` means the platform default idle window of 15 minutes.** Rationale: ADR003's `sleep = free` economics are load-bearing and depend on free services actually hibernating; the mechanism is built, live and healthy (this run's captures); all eight surfaces already advertised "0 = the controller default"; and Render's free spin-down is fixed-and-always-on. 15 min mirrors Render's window and is an existing preset. **"Can a user still express off?"** — no, deliberately: a free web service always auto-hibernates (on the default if it sets nothing), matching Render, so "off" is inexpressible for the free tier; the literal `0` round-trips **unrewritten** (operator resolves it, so the default can evolve without migrating Apps). Written into ADR003 (`sleep = free` para), ADR007 (dedicated "what `0` means" bullet + the stale "currently unread" removed), and ADR018 (free-tier-sleep parity row).
