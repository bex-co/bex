## Objective

Confirm the change is consistent across REST, GraphQL, MCP and the dashboard, and record where bex deliberately differs from render.com on free-tier sleep.

## Context

- bex diverges from Render twice here, and only one half is intentional: Render's free spin-down window is **fixed** (no user knob) and **always on**. bex adds the knob — a documented extension (`setIdleTimeout`, ADR006:252, w1/m4.5) — and, before this milestone, shipped it defaulted to a value meaning "never". The knob is the deliberate divergence; the default was not a decision anyone recorded.
- The field surfaces on all four: REST `idleTTLSeconds` (`render.go:116`), GraphQL `idleTTLSeconds` (`graphql.go:329`) and `setIdleTimeout`, MCP `update_service`'s `idleTTLSeconds` (`mcp.go:96`), and the dashboard Settings row.

## Steps

1. Read `idleTTLSeconds` for one free service through REST, GraphQL and MCP and confirm the same value and the same documented meaning.
2. Confirm the write path agrees across surfaces: `setIdleTimeout` (GraphQL), `PATCH` (REST), `update_service` (MCP) all reach `SetIdleTTL` — verify rather than assume.
3. Record the free-tier-sleep divergence in `docs/ADR018-render-parity.md`: the knob is deliberate, and state what bex's default now is against Render's fixed always-on window.
4. Re-run this milestone's live sequence end to end on a fresh free service: create → observe the default behavior → set a short window → hibernate → wake.
