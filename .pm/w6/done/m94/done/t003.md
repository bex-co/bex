## Findings (2026-08-25)

**The publicly observable contract is unchanged, which is the whole point of this check.** This milestone changes only _which backend the Ingress names_ and _when the Deployment scales_; it adds no field, no status value, and no response shape. The wake response itself is produced by the activator (`cmd/activator/main.go`), which was not touched — the same `503` + `Retry-After: 5` + `{"error":"service hibernated","retryAfter":5}` for a non-HTML `Accept`, per `docs/render-artifacts/wake-interstitial.md`.

What changes is how _often_ a caller sees that contract rather than raw Traefik output: strictly more often, never less. There is no REST/GraphQL/MCP surface to reconcile because none of the three exposes the Ingress backend — `server.phase` reports `Hibernated` from status exactly as before, and the hold pass leaves the phase alone (it returns before `parkKubernetes` stamps `Hibernated`), so a service mid-hold reports the same `Running` it already did.

**Render comparison:** Render's free-tier spin-down serves its own branded wake page from its edge; bex's activator interstitial is the already-recorded bex equivalent (`w6/m47`'s parity work, `wake-interstitial.md`). Nothing here moves that comparison — a routing race is invisible in the contract both sides publish. No new divergence to record.
