# Global search's "Navigation" section header renders even when zero navigation items match the query

Why: every other empty-result state in the dashboard (the project-level resource search, this same dialog's own "Try a different search or resource type" — actually the project-level one specifically) shows nothing or an honest message rather than a floating, empty section label; this dialog is the one place a section heading survives with zero children under it.

Live-reproduced: open the global search (`⌘K`/topbar Search button), type a query that matches only a Resources-group item and zero Navigation-group items (e.g. `redis`) — the dialog renders the `Navigation` section heading with an empty `<group>` underneath it (no items), directly above the `Resources` heading, which does have matches. Confirmed via accessibility snapshot (`group "Navigation"` with no child options) and a screenshot (`.playwright-mcp/qa-search-global-1.png`) showing the bare "Navigation" label floating above the two matching Key Value results with no separator content between it and "Resources".

Root cause: `dashboard/src/common/components/dashboard-layout/global-search-dialog.tsx:188-199` renders `<CommandGroup heading={t("common.topbarNavigation")}>{filteredPages.map(...)}</CommandGroup>` unconditionally — there is no `filteredPages.length > 0 &&` guard around it (or around the `<CommandSeparator />` immediately after it), unlike how empty states are handled elsewhere. The `Resources` `CommandGroup` at line 201 has the same shape and would show the identical empty-heading artifact if a query matched zero resources.

Fix shape: guard both `CommandGroup`s (and the `CommandSeparator` between them) on their respective filtered-list length, matching the pattern used for the project-level resource search's honest empty state.

## Resolution (2026-09-03)

`global-search-dialog.tsx` now renders each CommandGroup only when it has content (`showNavigation`/`showResources`) and the separator only between two rendered groups. 2 regression tests added (resources-only query hides Navigation+separator; nav-only query hides Resources).
