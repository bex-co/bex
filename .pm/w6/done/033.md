# Deleting a Project silently destroys its Environments, contradicting the delete confirmation's "nothing is deleted" promise

Why: the confirmation copy for an irreversible action tells the user the opposite of what happens — a real, named Environment and its own config (IP allowlist) are permanently destroyed while the dialog says nothing is deleted, so a user has no warning before losing it.

Live-confirmed 2026-08-23 during a `/qa-find-bugs` adversarial deletion-cascade test: created project `qa-20260823-cascadetest`, added environment `qa-20260823-env` inside it, deleted the project via Settings → Delete Project. The confirmation dialog and the Danger Zone description both say "Its services, databases, and key value stores become unassigned — nothing is deleted" (`dashboard/src/features/projects/locales/en.ts:278,292`) — Environments aren't mentioned at all. After confirming, a GraphQL query for the environment (`query { environment(id: "env-…") { id name projectId } }`) returned `null` with error `"app not found: environment: not found"` — it was hard-deleted, not unassigned.

**Root cause:** `environments.project_id` is `NOT NULL REFERENCES projects(id) ON DELETE CASCADE` (`lego/backend/internal/store/migrations/0019_environments.up.sql:20`), versus `apps.project_id` which is `REFERENCES projects(id) ON DELETE SET NULL` (`lego/backend/internal/store/migrations/0014_projects.up.sql:12`) — the exact asymmetry the UI copy correctly describes for apps but silently ignores for environments. Grepped the full migrations tree: only these two tables reference `projects(id)`, so this is exhaustive — no other project-scoped table has the same undisclosed-CASCADE shape.

**This is not a backend bug.** CASCADE is the only valid FK action given `environment_id`'s `NOT NULL` constraint — an environment cannot exist without a project by design (confirmed via the migration's own header comment). The defect is the UX copy's incompleteness: it needs to disclose that Environments (and their environment-scoped config — environments carry their own IP allowlist, see `lego/backend/internal/core/environment.go` / `lego/backend/internal/environments/service.go`'s ACL) are destroyed, not preserved.

**Severity:** major — misleads about an irreversible destructive action with real config loss, not merely cosmetic.

**Fix:** update both copy strings at `dashboard/src/features/projects/locales/en.ts:278` and `:292` to disclose that Environments in the project are deleted along with their configuration. No backend change needed.

**Estimate:** 20–30 minutes.
