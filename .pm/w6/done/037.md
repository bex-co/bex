# Settings-page field edits swallow the backend's specific validation error behind a generic toast

Why: a user who mistypes a Settings field (e.g. a Health Check Path missing its leading `/`) gets "Couldn't update the health check path." instead of the backend's actual, actionable reason — they have no way to know what to fix.

`useFieldMutation` (`dashboard/src/features/services/hooks/use-field-mutation.ts:38-40`) — the shared body for every single-field Settings mutation on a service — has a bare `catch { toast.error(t(keys.error)) }` that discards whatever the server actually said and always shows the hook's one fixed generic message.

**Live-confirmed:** setting Health Check Path to `no-leading-slash` via the dashboard (`srv-da5uhsgbjjms73fvfrpg`, 2026-08-24 QA workspace) returns a real backend validation message over GraphQL:

```
mutation { setHealthCheckPath(id: "srv-da5uhsgbjjms73fvfrpg", path: "no-leading-slash") { id } }

{
  "data": { "setHealthCheckPath": null },
  "errors": [{ "message": "bad request: health check path must start with /", "path": ["setHealthCheckPath"] }]
}
```

— but the UI toast reads only "Couldn't update the health check path."

**Blast radius (confirmed by code, one shared helper):** 14 hooks share this exact shape via `useFieldMutation`: `use-branch.ts`, `use-build-command.ts`, `use-build-filter.ts`, `use-dockerfile-path.ts`, `use-health-check-path.ts`, `use-idle-timeout.ts`, `use-max-shutdown-delay.ts`, `use-pre-deploy-command.ts`, `use-root-dir.ts`, `use-service-notifications.ts`, `use-set-image.ts`, `use-set-repo.ts`, `use-start-command.ts`, `use-subdomain-policy.ts`.

**Distinct from `w6/m49`:** that milestone's bare `catch {}` shapes are on separate resource-_creation_ hooks (Key Value/Postgres/Project/Environment/API-key/registry-credential) — not this one shared Settings-field-edit helper. No file overlap.

**Fix direction:** extract the GraphQL error and toast it, falling back to the generic message only when the error is unreadable — the same pattern already used elsewhere in this codebase for surfacing a specific server message. One change in `use-field-mutation.ts` fixes all 14 callers at once.

**Incidental, for `w6/m51/t001` to fold in (not independently re-investigated here):** while testing, setting a syntactically-valid Health Check Path (`/qa-nonexistent-404`) on the same service put it into phase `Building` — live confirmation that `SetHealthCheckPath` does force an operator rebuild, which `w6/m51/README.md`'s blast-radius list explicitly flagged as unconfirmed ("SetHealthCheckPath... not assumed in scope — t001 must confirm"). Did not chase whether it also skips the deploy-tracking row, to stay in scope.

## Closed 2026-08-27 — both branches live-verified (35th `/qa-find-bugs` run)

`d247d210`: *"New `serverRefusalReason` surfaces the server's words and keeps the generic copy for transport failures. One change, all 14 `useFieldMutation` callers."*

**The shipped code.** `use-field-mutation.ts:50` is now `toast.error(serverRefusalReason(err) || t(keys.error))`, and the hook's doc comment states the contract this note asked for: *"`keys.error` is the fallback, not the message… The generic copy is for a transport failure, where there is nothing specific to relay (w6/037)."* `serverRefusalReason` (`common/lib/graphql-error.ts:40-42`) is deliberately narrower than `refusalReason`: it returns `""` unless the server actually answered, because *"a transport failure's 'Failed to fetch' names nothing the user can act on"*. `refusalReason` then strips the `bad request:` prefix and capitalizes.

**Branch 1 — the server refused.** Backend, unchanged from this note's original capture:

```
mutation { setHealthCheckPath(id: "srv-da7o6ovvqdcc73bpn9hg", path: "no-leading-slash") { id } }
=> { "data": { "setHealthCheckPath": null },
     "errors": [{ "message": "bad request: health check path must start with /",
                  "path": ["setHealthCheckPath"] }] }
```

Driving the same edit through Settings → Health Checks and sampling the toast every 200 ms from the click:

> **`Health check path must start with /`**

The server's own sentence, prefix stripped, capitalized. Under the filed bug this read *"Couldn't update the health check path."*

**Branch 2 — the control, and the one a careless fix would break.** A fix that always showed the server's message would leave a transport failure with nothing to say. Forced one by aborting the mutation at the network layer (`page.route('**/graphql')` → `route.abort('failed')` for `setHealthCheckPath` only, everything else continuing):

> **`Couldn't update the health check path.`**

The generic copy, exactly as the contract specifies. Both arms of `serverRefusalReason(err) || t(keys.error)` exercised, not just the fixed one.
