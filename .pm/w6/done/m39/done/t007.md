## Objective

Close the App-side half of the same bug. The namespace fix alone does not meet this milestone's goal: two `dev-N` harnesses would still delete and recreate each other's **App CRs** on every 30-second resync.

Added mid-milestone by `t004`'s `/simplify` review, which found the projector has the identical cluster-scoped delete-by-absence with no ownership filter. This is scope completion, not scope creep — without it the milestone's headline claim ("parallel multi-worker `dev-N` development stops being serialized") is false.

## Context

- `lego/backend/internal/store/reconciler.go` `Reconciler.ReconcileOnce` lists App CRs **cluster-wide** (`client.MatchingLabels{LabelManagedBy: ManagedByValue}`) because ADR043 spreads them across every `<ws>` namespace, then deletes every App whose id is absent from `seen` — which is built from **its own** database.
- App ids are per-database xids, so another control plane's Apps are never in `seen`. Every precondition for the `w3/017` bug holds.
- **Worse than the namespace half:** the namespace bug is a one-shot delete; this one is a perpetual delete/recreate flap, since each control plane re-creates its own App on the next pass. That is probably why `w3/017` only recorded the namespace symptom.
- These are the only two cluster-scoped managed-by List+delete-by-absence sites in the backend. The four workspace purgers (`core.PurgeByTenant`, `apps/postgres/keyvalue` purgers) are cluster-wide but target one known tenant id, so they prune nothing by absence and carry no cross-control-plane exposure.

## Steps

1. Move `ControlPlaneLabel`/`DefaultControlPlaneIdentity` next to `LabelManagedBy` in `reconciler.go` — the canonical ownership constants — and add the shared `ownedBy(labels, identity)` predicate as their only reader.
2. `ownsNamespace` collapses into `ownedBy`.
3. `Reconciler` gains `Identity` + `identity()`; `stampLabels` stamps `ControlPlaneLabel`.
4. Filter the delete-by-absence loop on `ownedBy`.
5. Refuse to converge an App owned by a **different** identity (the adopt-vs-prune asymmetry).
6. Wire `rec.Identity` from the same validated `BEX_CP_IDENTITY` read.
