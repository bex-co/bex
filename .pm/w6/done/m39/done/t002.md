## Objective

Make `pruneOrphans` delete only namespaces belonging to **this** control plane, while keeping production's ability to reclaim genuine orphans — including namespaces provisioned before `t001` that carry no identity label at all. This is the design call at the centre of the milestone: get it wrong in one direction and dev-N stacks keep cross-pruning; get it wrong in the other and production leaks orphaned tenant namespaces forever.

## Context

- `lego/backend/internal/store/namespaces.go:279` `pruneOrphans` — today it lists on `client.MatchingLabels{LabelManagedBy: ManagedByValue}` alone, skips namespaces with an empty `LabelWorkspace` or a present `DeletionTimestamp`, and deletes everything else not in `desired`.
- Called from the reconcile loop at `:143` with the `desired` set built from this control plane's own database.
- The asymmetry to preserve: a `dev-N` control plane must **never** delete a namespace it did not create; the `production` control plane must still reclaim pre-`t001` namespaces, which have no identity label.
- Recommended shape: prune a namespace only when its identity label equals ours, **plus** treat an absent label as ours only when we are the `production` identity. Record whichever rule is chosen in the code comment — the reasoning matters more than the branch.

## Steps

1. Extend the prune selector/filter to compare the namespace's identity label against this control plane's own.
2. Decide and implement the unlabeled-namespace rule (see Context), and write the rationale into the function's doc comment.
3. Keep the existing guards intact: empty `LabelWorkspace` skip, `DeletionTimestamp` skip, `desired`-set skip.
4. Verify the production path is unchanged for a control plane with no identity configured plus no labels present anywhere — the pre-`t001` world must prune byte-identically.
5. Record the behavior in [`docs/ADR043-tenant-namespace-isolation.md`](../../../docs/ADR043-tenant-namespace-isolation.md) alongside the `NamespaceReconciler`'s pruning contract.

## Acceptance criteria

- [ ] A control plane with identity `dev-6` does not delete a namespace labelled `dev-5`, even though that workspace is absent from its database.
- [ ] A control plane with identity `dev-6` does not delete an **unlabeled** managed namespace.
- [ ] The `production` control plane still deletes an unlabeled managed namespace whose workspace is gone (the pre-`t001` orphan case).
- [ ] The `production` control plane still deletes its own labelled orphan.
- [ ] A namespace whose workspace is present in `desired` is never deleted regardless of identity.
- [ ] The chosen unlabeled rule is stated in the `pruneOrphans` doc comment and in ADR043.
- [ ] `cd lego/backend && go build ./... && go test ./...` green.
