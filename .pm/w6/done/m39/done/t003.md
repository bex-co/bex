## Objective

Make every `dev-N` stack set its own control-plane identity automatically, so the fix is real for the workflow it exists to unblock, and remove the now-obsolete "only one dev-N control plane at a time" restriction from the docs that carry it.

## Context

- Each workstream ships an isolated stack under `.pm/wN/dev-N/` (`up.sh`, `status.sh`, `down.sh`, `ports.env`) that runs a locally built bex-api against the shared kind/CAPD cluster.
- `.pm/w3/017.md` closes with: *"Until fixed, at most one dev-N control plane may run against the shared cluster at a time; note this in `.pm/*/dev-*/README.md` when touched next."* Find every place that restriction was actually recorded before editing — do not assume it is only in one file.
- The natural identity value is the harness's own name (`dev-6` for `.pm/w6/dev-6/`), derivable from the directory rather than hardcoded per copy.

## Steps

1. `grep` the `.pm` tree for the one-at-a-time restriction and for the dev-N bex-api launch to find every harness that needs the variable.
2. Set the identity in each `dev-N` harness's environment (alongside the existing `ports.env`-derived settings), deriving the value from the harness name.
3. Have `status.sh` surface the active identity in its inventory so a mis-set harness is visible rather than silent.
4. Update every `.pm/*/dev-*/README.md` (and any other file found in step 1) to state that concurrent dev-N control planes are now safe, replacing the restriction.

## Files

- `.pm/wN/dev-N/up.sh` and `status.sh` across the dev-N harnesses (and `ports.env` if the identity belongs there)
- `.pm/*/dev-*/README.md`
- any other file surfaced by the step-1 grep

## Acceptance criteria

- [ ] Every `dev-N` harness launches bex-api with an identity matching its own name.
- [ ] `status.sh` reports the active control-plane identity.
- [ ] No file under `.pm/` still states that only one dev-N control plane may run at a time.
- [ ] `bash .pm/w6/dev-6/up.sh` followed by `bash .pm/w6/dev-6/status.sh` is green.

## Out of scope

- Changing dev-N port allocation, namespaces, or any other isolation axis.
- Running two harnesses simultaneously as a proof — that is `t005`.
