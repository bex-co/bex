## Objective

Pin the milestone's central claim with tests that fail against the pre-fix code: two control planes with distinct identities sharing one cluster each prune only their own namespaces, and production still reclaims genuine orphans.

## Context

- The regression this prevents was observed live, not theorized: the dev-5 session's bex-api pruned this session's freshly provisioned `tea-…` namespace within one 60s resync, and symmetrically (`.pm/w3/017.md`).
- Existing prune coverage in `lego/backend/internal/store/` is the baseline to extend — it must stay green, since "production still prunes its orphans" is half the definition of done.
- The cross-prune scenario needs two reconcilers with different identities and different `desired` sets over one shared namespace list.

## Steps

1. Add the two-identity cross-prune test: reconciler A (`dev-5`) and reconciler B (`dev-6`), each with a namespace the other does not know about; assert each survives the other's prune pass.
2. Add the unlabeled-legacy cases both ways: `production` reclaims an unlabeled orphan; a `dev-N` identity does not touch it.
3. Add the negative control: a namespace in `desired` is never deleted regardless of identity.
4. Confirm the pre-existing prune tests still pass unmodified.
5. Verify each new test actually fails when the `t002` filter is reverted.
