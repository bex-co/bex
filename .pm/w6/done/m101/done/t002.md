## Objective

Make every UNION arm of `webhookEventsQuery` that reports a service name resolve `COALESCE(NULLIF(a.display_name,''), a.name)` instead of the bare immutable `a.name`, so webhook payloads agree with the dashboard/REST/GraphQL.

## Context

- `lego/backend/internal/store/webhooks.go:700-808` — `webhookEventsQuery`. Exactly 4 of its 5 `UNION ALL` arms join `apps a` and select `a.name AS service_name`:
  - deploy-started arm, ~line 707
  - deploy-ended arm, ~line 726
  - app-scoped audit arm, ~line 745
  - `service_event_facts` arm, ~line 790
  - (the 5th arm — datastore audit for Postgres/Key Value, ~line 765 — does NOT join `apps` and is unaffected; leave it alone.)
- `lego/backend/internal/store/webhooks.go:643-674` — `WebhookEventRow.ServiceName` doc comment: "ServiceID is the PUBLIC service id ... ServiceName is the human app name." Update this comment once the fix lands so it's explicit that ServiceName is display-label-aware.
- `lego/backend/internal/webhooks/worker.go:349,469` — confirms `ServiceName` is a straight passthrough into the delivered JSON's `data.serviceName` field; no other transform needs to change.

## Steps

1. In each of the 4 named arms, change `a.name AS service_name` / `a.name,` to `COALESCE(NULLIF(a.display_name,''), a.name) AS service_name` / the equivalent inline form.
2. Update the `ServiceName` field doc comment on `WebhookEventRow` to describe the fallback.
3. Verify `SELECT ... FROM feed` at the bottom of the query (the outer `SELECT`) still just passes `service_name` through unchanged — no second place needs the same fix.

## Result

- New `appDisplayLabel` const in `webhooks.go` — `COALESCE(NULLIF(a.display_name, ''), a.name)`, the SQL spelling of `renderServiceName` (`internal/apps/render.go:498`), the fallback the dashboard/REST/GraphQL already read through.
- **All four apps-joined arms** now select it: deploy-started (aliased `AS service_name`), deploy-ended, app-scoped audit, and `service_event_facts` (the last three positionally). Verified by re-reading the query, not by counting — `grep -c "AS service_name"` is 1 because only the first arm carries the alias.
- **The fifth (datastore) arm is untouched**, still `COALESCE(NULLIF(e.target_name, ''), split_part(e.target, ':', 2))`: no `apps` join, no rename feature for Postgres/Key Value.
- `service_id` (`t.name || '-' || a.name`) and the audit arm's three target spellings still read `a.name` — those are identity, not label, and must not move with a rename.
- `WebhookEventRow.ServiceName`'s doc now states the fallback; the outer `SELECT … FROM feed` passes `service_name` through unchanged, so there is no second site.
- **Cost:** `EXPLAIN (VERBOSE, COSTS OFF)` old vs new on PG 17 gives structurally identical plans — the expression appears only in target lists, nothing filters, joins or sorts on it, and `apps` has no index on `name` to defeat (only `apps_tenant_id_idx`, `apps_slug_idx`).
