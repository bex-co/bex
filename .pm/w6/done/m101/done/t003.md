## Objective

Lock in the fix with a test that fails on the old behavior: a service with `display_name` set to something other than `name` must produce webhook events whose `ServiceName` is the display label.

## Context

- `lego/backend/internal/store/webhooks_test.go` (or the sibling test file for `webhookEventsQuery`) — existing fixtures already set both `ServiceID`/`ServiceName` in test rows (see `lego/backend/internal/webhooks/worker_test.go:454-653` for the shape convention used across the package).
- `lego/backend/internal/webhooks/worker_test.go:687` shows the exact wire-body shape the delivered payload must match: `{"type":"...","timestamp":"...","data":{"id":"...","serviceId":"...","serviceName":"..."}}`.

## Steps

1. Add a store-level test (real or fake Postgres per the existing package convention) that creates an app with `name = "orig-name"` and `display_name = "renamed-label"`, then asserts `ListWebhookEvents` returns rows with `ServiceName == "renamed-label"` for each of the 4 fixed arms (deploy started/ended, app-scoped audit, a fact row).
2. Add/extend a `worker_test.go` case asserting the end-to-end dispatched payload's `data.serviceName` matches the display label, not the immutable name.
3. Add a case where `display_name` is empty — assert the fallback to `name` still works (no regression for never-renamed services).

## Result

- **`store/webhooks_display_name_pg_test.go` — `TestPGWebhookFeedReportsDisplayNameAfterRename`** (real Postgres). Seeds one row per apps-joined arm (the create deploy closed to `live` lights up both deploy arms, an `apps.Restart` audit row, a `server_available` fact) plus a datastore audit row, then asserts the label three times: before any rename (every arm falls back to the immutable `name`), after `SetAppDisplayName("renamed-label")` (all four arms report the label), and after clearing it (fallback restored). The datastore arm must keep reporting the audit row's own `target_name` throughout, and `ServiceID` must stay the immutable `<tenantName>-<appName>` across the rename.
- **Verified RED against the pre-fix query:** temporarily reverting `appDisplayLabel` to `a.name` fails the test on all four arms by name (`arm deploy:started reported "web-…", want the display label "renamed-label"`, and the same for `deploy:ended`, `audit`, `fact`). Green with the fix.
- Empty-`display_name` fallback is covered twice — before the first rename and after the clear.
- `TestPGSetAppDisplayNameMissingApp` — the setter's `ErrNotFound` path.
- **`webhooks/worker_test.go` — `TestProjectRenamedServiceKeepsLabelAndIDApart`**: a renamed row projects `data.serviceName` = the label and `data.serviceId` = the immutable `srv-…` id, so the two can never be conflated as a rename moves one of them.
- **Deviation from step 2, on review:** the originally-written full `dispatch()` end-to-end test was replaced by that `project()`-level case. No worker code changed in this milestone — `worker.go:469` is a straight `ServiceName: r.ServiceName` copy — so the heavier fixture (fake store, watermark, endpoint, dispatch, JSON unmarshal) only re-derived what `TestProjectServiceEventUsesCanonicalAppID` and the existing payload-unmarshal loop already pin. The guarantee is tested where it is actually produced: the SQL (PG test) and the projection (this test).
- `go test ./internal/store/... ./internal/webhooks/...` green.
