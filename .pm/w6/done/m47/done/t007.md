## Outcome

Closed 2026-08-23 after the live leg. t001's hibernate→wake cycle was verified before/after on one real App in a tenant namespace on the shared CAPD cluster (full transcript in `done/t001.md`): the pre-fix operator produced an Ingress backend that does not resolve in its own namespace, the fixed operator produces an App-owned alias that does, and the sleeping service answers a request with the `Retry-After: 5` wake page and is serving its own `HTTP 200` within about six seconds.

t002's SQL was additionally proven against a **real Postgres**, not just the in-memory fake — which mattered: `TestPushWorkerEnqueuesObservedLifecycleFacts` is `BEX_TEST_DB_URI`-gated and had been silently skipping, and it caught that the auto-hibernate leg no longer enqueues a `service_suspended` push. That is the intended behavior change (an idle sleep is not a suspension), so the test's Hibernated leg is now marked as a genuine user suspension, mirroring its in-memory sibling. Migration 0097 applies cleanly and the whole backend suite passes on a pristine database.

Production is unaffected — its gitops RBAC grants it.
