## Objective

Allow build-time environment variables (buildpacks' `BP_*`/`BPE_*` convention) to be set on an App and threaded into the kpack `Image` spec's `build.env`.

## Context

- Buildpacks don't have an arbitrary shell "build command" the way Dockerfiles do — their configuration surface is build-time env vars (e.g. `BP_NODE_VERSION`, `BP_GO_TARGETS`). This is the real analog of Render's `buildCommand` for buildpack/native-runtime services, deliberately deferred here from `w6/m21`.
- App's existing env-vars mechanism (`docs/ADR013-secrets.md`, env groups) is runtime env, not build-time — this needs a distinct build-time env surface or a documented reuse of the existing one.

## Steps

1. Decide and document whether build-time env reuses the App's existing env-var store (filtered/prefixed) or is a new dedicated field; implement accordingly.
2. Thread the resolved values into the kpack `Image.Spec.Build.Env`.

## Files

- `lego/operator/internal/build/build.go`
- `lego/backend/internal/apps/*.go` (if a new field is needed on create/update surfaces)

## Acceptance criteria

- [ ] A `BP_*` env var set on an App changes the resulting buildpack build's behavior (verified with a real buildpack that honors one, e.g. `BP_NODE_VERSION`).

## Out of scope

- General runtime env var changes (already covered by existing env-vars/env-groups work).
