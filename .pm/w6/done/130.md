# The Muse adapter answers the prompt while background work still runs, so Muse workflows stay off

Why: bex turns Muse's Workflow tool off ([ADR108 D8](../../docs/ADR108-muse-code-agent.md), w6/129). muse-code-acp 0.11.0 answers `session/prompt` while a workflow is still running, so the workflow's result never reaches a turn. Parallel fan-out on Muse comes back only once the adapter holds the prompt open until that work is reported.

- **What the adapter does** (`bex-co/muse-code-acp` 0.11.0):
  - `session/prompt` resolves when Muse's foreground turn ends.
  - `release()` in `src/muse-sdk-host.ts` keeps the Muse host for 60 s (`idleTimeoutMs ?? 60_000`) and then closes it whatever is still running. `lostWork()` reports every unresolved card as `failed` with an unknown outcome.
  - Muse starts its own turn to report finished work ("wakes you even after you end the turn"). The adapter does not stream that turn. An ordinary prompt during it fails with "Muse is executing a host-owned turn" (`src/sdk-prompt-turn.ts` ~251; `docs/async-tasks.md`, `docs/goal-extension.md`).
- **The same failure without workflows.** Muse 1.4.14's `bash` sends a command to the background once it outlasts its foreground wait (`yield_time_ms`, at most 300000), and tells the model to end the turn when nothing else remains. A build or test that runs longer than that can end a bex turn the same way. This has not been seen on production: in w6/129 every routine run that did not call `workflow` finished.
- **Fix in the adapter.** Add an opt-in client capability. Under it, `session/prompt` resolves only once no workflow, subagent or background tool call is in progress and no host-owned turn is running. The host-owned turn's updates stream into the same prompt, and the host is never closed while such work runs. Then:
  - release the adapter and bump `@bex-co/muse-code-acp` in `lego/backend/internal/agentsession/agent-profiles.json`;
  - negotiate the capability in `lego/agent-image/driver/src/acp.ts`;
  - set `run.workflow_trigger_mode` back to `auto` in `writeMuseSettings`, and amend ADR108 D8.
- **Done when:**
  - a driver test has the agent's prompt stay open while a workflow tool call is in progress, and the workflow's result is recorded before the turn ends;
  - a production Muse routine run that calls `workflow` opens its PR or reports that it has nothing to change.

Promoted to [m434](../m434/README.md) on 2026-11-16: an adapter capability, its live test and npm release in `bex-co/muse-code-acp`, the bex pin, the driver negotiation and test, the Workflow tool back on with ADR108 D8 amended, and a production check (11 tasks).
