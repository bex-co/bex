## Objective

Replace `build-deploy-section.tsx`'s `viaGitHub` heuristic with the authoritative per-repo signal from t001, so the "via the GitHub app" hint is only ever shown for a repo the connected installation actually grants.

## Context

- `dashboard/src/features/services/components/build-deploy-section.tsx:135`:
  ```ts
  const viaGitHub = !!connection?.connected && /github\.com[/:]/i.test(repo);
  ```
  computes the hint from workspace-level connection state plus a host regex on the repo string — never checking whether this specific `repo` is granted.
- Lines 179-181 select `services.autoDeployViaGitHub` vs `services.autoDeployViaWebhook` based on `viaGitHub`.
- The component already fetches the granted-repo list via `useRepos()` (feeds `repoOptions`, `~line 144`) but never cross-references `repo` against it.
- t001 adds a server-computed signal (`GET`/GraphQL/MCP `autoDeployCapable`-shaped field) available on the service object this component already receives as props — prefer wiring the prop through over re-deriving from `useRepos()` client-side, since the server-side check is the one guaranteed to match `mintCloneSecret`'s actual deploy-time behavior (a client-side repo-list match could drift from it — e.g. pagination, multi-installation unions not fully loaded).

## Steps

1. Add the new field to `BuildDeploySectionProps` (or wherever the service data flows in from) and thread it from the GraphQL query this route already runs.
2. Replace `viaGitHub`'s definition with a direct read of that field instead of the `connection?.connected && regex` heuristic.
3. Keep the `useRepos()`-fed `repoOptions` for the Source picker (unrelated, unaffected) — only the hint's boolean changes.
4. Update `services.autoDeployViaGitHub`/`services.autoDeployViaWebhook` copy only if the new field's semantics need slightly different wording (e.g. if it's a three-state enum rather than a boolean); otherwise the existing two strings likely still fit.

## Acceptance criteria

- [ ] For a service whose repo is not in the grant list, the Auto-Deploy row shows the manual-webhook hint even when the workspace has an active GitHub connection and the repo string is a github.com URL.
- [ ] For a service whose repo IS in the grant list (the `w2/m9` control case), the row still shows the "via GitHub app" hint — unchanged.
- [ ] For a service with no GitHub connection at all, or a non-github.com repo, behavior is unchanged (already correct today).

## Out of scope
