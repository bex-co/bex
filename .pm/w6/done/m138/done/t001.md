## Objective

Add a shared mobile capability provider/hook that consumes the m136 tri-state `viewerCapabilities` contract fail-closed: unknown, expired, or errored permission reads as a neutral checking/unavailable state — never as allowed, and never inferred from the role label.

## Context

- The dashboard's `use-capabilities.ts` is **permissive-while-unknown** (`value !== false`) — ADR087 explicitly forbids copying it for mobile.
- `mobile/src/features/workspaces/workspace-provider.tsx` carries a role today but no capabilities; keep the role for display ("Role unavailable" fallback), never for gating.
- Snapshots stay in memory (never AsyncStorage — `mobile/CLAUDE.md` auth rule), keyed by identity/session, workspace, and DataBoundary generation (`mobile/src/common/apollo/data-boundary.ts`).
- Generated GraphQL via codegen only; extend the exact scope allowlist for the reviewed capability operations only.
- Unknown action ids/reason enums fail closed with generic localized copy.

## Steps

1. Add the codegen'd capability query (tri-state outcome + reason + resource-action fields from m136), selecting only required fields.
2. Implement the provider/hook with tri-state semantics and boundary-generation keying; expose `canView`/`canViewLogs`/`canOperate`/`canCreate` + per-resource action decisions.
3. Wire cold start ordering: authentication → verified membership → capabilities → protected queries mount.

## Files

- `mobile/src/features/capabilities/` (new)
- `mobile/src/features/workspaces/workspace-provider.tsx`
- codegen config + generated output; scope allowlist

## Acceptance criteria

- [ ] Unit tests: loading, error, unknown-enum, and null-snapshot all gate as not-allowed with the neutral state; no permissive default exists.
- [ ] No capability data or credential persists to AsyncStorage.
- [ ] `yarn typecheck` + `yarn lint` + `yarn test:unit` green.

## Out of scope

- A second role-to-permission engine or deriving roles from boolean combinations (forbidden by ADR087).
