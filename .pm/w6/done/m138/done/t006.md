## Objective

Ship the ADR087 `access.*` string table in English and Chinese via `useTranslations()`, with reasons visible and screen-reader accessible — never conveyed by hover, color, or a lock icon alone.

## Context

- Keys and suggested copy: `access.checking`, `access.unavailable`, `access.changed`, `access.cannotOpen`, `access.requestHelp`, `access.offlineAction`, `access.nativeLimit`, `access.roleUnknown` (table in ADR087 §Show, hide, disable, and explain).
- After a permission-driven redirect: move focus to the destination heading and announce the change.
- No scattered "upgrade"/"ask an admin" placeholders — the drawer's role explanation is the general discoverability; request-access guidance only after an explicit denied navigation/action with a reliable reason.
- Theme tokens, scalable text, reduced motion, `useWindowDimensions` (repo rules).
- Capability-dependent pending layouts preserve ready-state geometry once visible regions are known; before that, a neutral shell without restricted labels/counts.

## Steps

1. Add all keys to both locale resources; replace any raw server error surfaced by t002–t005 with these strings.
2. Add accessibility semantics (role/state/announcement) to disabled controls and redirect flows.
3. Verify narrow-width + large-text rendering of reason text on both platforms.

## Files

- `mobile/src/translations/en/*`, `mobile/src/translations/zh/*`
- components touched by t002–t005

## Acceptance criteria

- [ ] Every new user-visible string exists in both locales; the translations test/lint passes.
- [ ] Screen reader announces the reason for a disabled control and the post-redirect access change.
- [ ] No raw API error text reaches the UI on any gated path.

## Out of scope

- An access-request submission flow (no API exists; explicitly out of ADR087).
