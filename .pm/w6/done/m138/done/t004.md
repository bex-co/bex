## Objective

Service, Postgres, Key Value, cron, and session actions follow the ADR087 detail matrix: hide on confirmed absence of permission, disable-with-reason only for authorized-but-temporarily-blocked, and never render an empty Actions card.

## Context

- `mobile/src/features/services/service-actions-card.tsx` builds controls from lifecycle/deploy state only — add the permission dimension via t001's per-resource action decisions (m136 t004 preconditions).
- Matrix: bare redeploy/cancel/restart/suspend/resume/cron run+cancel/session cancel = `canOperate` (Contributor+); rollback = `canCreate` (Developer/Admin only); composer/create = `canCreate` + feature readiness; Viewer/Billing = no controls at all.
- `show = in scope AND confirmed permission`; `enable = show AND feature available AND resource eligible AND online AND confirmation complete AND no operation pending`. Lifecycle predicates explain readiness; they never manufacture authorization.
- Protected resources: present the exact action/target + required confirmation via the existing safe-action flow; never implement `protected && !admin`, never auto-fill a confirmation from an error and retry.
- Before dispatch: freeze subject/workspace/resource/verb/target revision, recheck freshness/eligibility; any boundary change dismisses the confirmation. Never queue mutations for post-reconnect execution.

## Steps

1. Thread capability + per-action precondition decisions into the service actions card and the Postgres/KV lifecycle controls.
2. Apply the same gating to cron run/cancel and session cancel; hide the composer without `canCreate`.
3. Implement the disabled-with-reason presentation (visible text near the control, `access.*`/existing lifecycle copy).
4. Add the pre-dispatch freeze/recheck to the shared mutation helper.
