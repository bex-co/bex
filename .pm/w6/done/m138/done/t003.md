## Objective

Gate query **mounting**, not just rendering: hidden means no fetch, poll, SSE, prefetch, count, or cached preview — and a refused restricted read must never blank an otherwise readable screen.

## Context

- `mobile/src/features/postgres/postgres-insights-card.tsx` requests `MobilePostgresProcessesDocument` (`databaseProcesses`) alongside capacity/sizes/scans — but the native token lacks `bex.sensitive`, so it can never succeed. Remove the process-list request entirely (matrix row: Hide for every role); keep capacity, sizes, and table-scan cards.
- Logs require `canViewLogs`: gate both the historical HTTP query and the live SSE connection before mount for Viewer/Billing.
- Session composer readiness/repository queries mount only with `canCreate` — a "ready" integration is not a permission grant.
- A resource load must prove access to the exact target in the selected workspace before title/previews/actions appear; never list-then-filter client-side.

## Steps

1. Split the insights card's document so the process-list selection is gone (codegen, not hand-edit); verify remaining cards refetch independently.
2. Wrap Logs (query + SSE) and composer-readiness queries in capability gates from t001.
3. Audit remaining detail screens for restricted selections bundled into supervision documents; split where refusal would blank permitted cards.

## Files

- `mobile/src/features/postgres/postgres-insights-card.tsx` + `postgres/api/insights.graphql`

## Acceptance criteria

- [ ] Network-level test: a Viewer's service/Postgres detail issues zero logs/process/session requests.
- [ ] Postgres screen still shows capacity/sizes/scans for all roles; no `databaseProcesses` request exists in the bundle.
- [ ] A restricted-read refusal leaves permitted cards rendered (no blanked screen).

## Out of scope

- Requesting `bex.sensitive` or a redacted process endpoint (separate scope decision per ADR087).
