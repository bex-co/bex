# A disk owner cannot tell that its nightly snapshots are not running

Why: a backup that silently does not happen is the worst kind of failure. The operator sets `DiskReady=False` with `SnapshotImageUnresolved`/`SnapshotCredentialUnavailable` and says "the owner can see that snapshots are not running", but nothing in bex-api reads `ConditionDiskReady` (`grep` in `lego/backend` finds no reader).

- **Evidence:** w6/089 (2026-10-22). The bex-canary ClickHouse disk got no snapshot in its 02:xx window. The API showed only `[]`, which looks the same as "first snapshot not due yet", and there were no events.
- **Fix candidates:**
  - mirror a false `DiskReady` (and a failed `dskbak-` Job) into a service event or the service's status message, the way stall diagnosis does (`store/reconciler.go`);
  - and/or show "no snapshot in the last 26h" on the dashboard disk card.
- **Render comparison:** Render's API shows only the snapshot list. Check what Render shows when a snapshot fails before choosing a surface, and keep REST shapes Render-compatible.
