## Objective

Apply t001's decision at the right one of three predicates, and stop stamping a message that is untrue for the type.

## Context

- `app_controller.go:1710` — `worker := app.Spec.Type == appv1alpha1.TypeBackgroundWorker`, consumed by `desiredReplicas` (`:1983`) as `autoHibernating = !worker && …`. This is the line that excludes workers and not private services, while the comment above it (`:1981-1982`) gives a reason — "it has no Ingress, so a request could never wake it" — that covers both.
- `autoSleepEligible` (`:1638`) has **three** call sites answering different questions, and the fix belongs in exactly one of them:
  - `:1642` (`shouldAutoHibernate`) — *should it sleep yet?* The scheduling question.
  - `:2031` (`ingressBackend`) — *is the activator this App's backend right now?* Routing.
  - `:2098` — *is `last-active` stamped at all?*
  The decision belongs in `autoSleepEligible` itself so scheduling, routing, and activity stamping cannot drift by type. `shouldAutoHibernate` remains separate because elapsed-idle state is a different question.
- `parkKubernetes:1865` stamps `"idle ≥%ds on free tier; wakes on next request"` on the hibernated App. If t001 keeps private-service sleep with a new wake path, this stays true; if it excludes the type, the message becomes unreachable for it — either way, confirm no type can receive it falsely.
