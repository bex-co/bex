## Objective

Enable both gates on production in the recorded order, with no surprise refusals for existing first-party workspaces and the D8 hybrid flow (signed-in verification, login backstop) verified live.

## Context

- ADR075 D7 scope correction 2: flipping `all` turns every unbound workspace refused-on-next-create; the ~17 first-party workspaces must be comped (Mode-B — `PaymentGate.AllowsPaidIntent` already honors the exemption) or card-bound **before** the flip.
- ADR075 D8 as revised 2026-08-20 (hybrid): NO session revocation at enablement — an unverified session is the normal in-flow signup state now; the login backstop (`require_verified_address`) refuses stale unverified accounts at their next login, which is the whole enforcement.
- Production config paths: `.env` → `scripts/gh-secrets.sh` for `BEX_REQUIRE_PAYMENT_METHOD`; `scripts/auth-secrets.sh` re-run + Argo sync for the Kratos Secret fragment; kratos.values.yaml ships via GitOps.

## Steps

1. Inventory production workspaces' payment eligibility (bound / comped / neither); comp or bind the remainder; record the list.
2. Apply the D8 hybrid Kratos config to production (values sync + `auth-secrets.sh` re-run — both registration hooks AND both login backstop hooks).
3. Flip `BEX_REQUIRE_PAYMENT_METHOD=all`; verify live: an unbound test workspace's free-tier create 402s and the dashboard dialog resolves it; a comped workspace creates normally; a fresh signup lands on the verification page SIGNED IN and continues seamlessly after the code; a stale unverified identity's new login is refused into verification (backstop).
4. Record rollback: `all`→`1` is one env flip; the Kratos hooks revert by restoring the two config blocks (both documented in the milestone README's evidence).

## Rollout evidence (2026-08-20/21, executed live on production)

1. **Installer gap fixed first:** `scripts/stripe-billing-secret.sh` only
   accepted 0|1 — `all` added to the enum (+ header docs), DRY_RUN verified
   `payment_gate=all`.
2. **Inventory + exemption:** prod bex-db showed 20 workspaces — 1 bound
   (`bex`), 1 already excluded, 18 neither. All 19 non-bound first-party
   workspaces set Mode-A `billing_excluded` through the sanctioned internal
   API (`PATCH /v1/tenants/{id}/billing-excluded`, actor
   `w6/m42-t007-first-party-exclusion`, audited); re-query confirms
   **neither=0 / total=20** — no surprise refusals possible.
3. **Flip:** `bex-system/bex-stripe` Secret key `BEX_REQUIRE_PAYMENT_METHOD`
   patched `1` → `all` (single-key patch; the rest of the out-of-band bundle
   untouched), bex-api rollout-restarted: Running, 0 restarts, clean logs,
   `api.bex.co/healthz` 200. Behavioral proof the mode took: the gate
   fail-closes with `log.Fatalf` on an unrecognized value and requires the
   Stripe key + CP DB — a pod that boots healthy has parsed `all`.
4. **D8 hybrid on prod:** Argo had already synced the git-tracked half
   (`require_verified_address` on password login, `show_verification_ui`+
   `session` on registration, `template_override_path`, 4 branded email
   template ConfigMaps — confirmed in the rendered kratos-config). The
   out-of-band OIDC fragment (enabled in prod) still carried pre-hybrid
   hooks and the local .env lacks the Kratos secrets, so instead of re-running
   auth-secrets.sh the fragment's `flows:` block was surgically patched
   in-pipe (providers/credentials untouched, never printed) to the same three
   hooks; kratos rolled, both replicas healthy, `auth.bex.co/health/alive` 200.
5. **No session revocation** — deleted by the same-day hybrid revision
   (unverified sessions are the normal in-flow signup state; the login
   backstop handles stale accounts).

**Honest limitation:** the literal "cardless free-tier create returns 402"
cannot be demonstrated live — every production identity now belongs to an
exempt workspace, and creating a throwaway prod identity would send real
SendGrid mail. The refusal behavior is pinned by the payment-gate test
matrix (apps/postgres/keyvalue/sandbox/agentsessions + billing_config) and
was the shipped `1`-mode behavior for paid tiers all along.

**Rollback:** `all`→`1` is one `kubectl -n bex-system patch secret bex-stripe`
+ `rollout restart deploy/bex-api`; the OIDC fragment reverts by restoring the
previous `flows:` block (or a full `auth-secrets.sh` re-run once .env custody
is restored on this machine — noted: local .env lacks KRATOS_SECRETS_* and
BEX_STRIPE_SECRET_KEY, so full re-installs need the custody copy).
