## Objective

Make email verification a hard gate at the door in Kratos config: `require_verified_address` on **both** login method after-hooks, and the registration `session` hook removed in **both** places it exists — the git-tracked values file (password) and the script-written out-of-band Secret fragment (OIDC).

## Context

- ADR075 D8, as corrected 2026-08-20: the earlier draft named only `kratos.values.yaml:147-150`; the OIDC mirror lives in `scripts/auth-secrets.sh`'s `oidc_fragment()` (lines ~113-120), which writes `registration.after.oidc.hooks: session` into the out-of-band `kratos` Secret — leaving it would let GitHub signups mint sessions at the door.
- The OIDC path is hooked symmetrically, **not trusted**: the Jsonnet mapper maps only `email`/`name` traits and marks nothing verified; either Kratos's provider claims handling (`email_verified`) marks the address verified (hook passes untouched) or the user completes the same code flow.
- The `dev-6` stack (`scripts/dev-env.sh 6`) has its own Kratos + Mailpit for safe iteration.

## Steps

1. `deploy/gitops/base/values/kratos.values.yaml`: add `selfservice.flows.login.after.password.hooks: [require_verified_address]`; delete the registration `after.password.hooks: session` block (update its explanatory comment — sign-up now deliberately lands unauthenticated in the verification flow).
2. `scripts/auth-secrets.sh` `oidc_fragment()`: add `login.after.oidc.hooks: [require_verified_address]`; remove the `registration.after.oidc.hooks: session` mirror; update the fragment's comments.
3. Apply to `dev-6` and verify by hand: password sign-up → no session, verification flow entered; unverified login refused into verification; verified login succeeds.
4. Record the production apply step (re-run `auth-secrets.sh` + Argo sync) in t007's runbook notes.
