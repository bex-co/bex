## Objective

Prove t001's fix and lock the corrected shape in place so this cannot silently regress back to the root-level placement — the existing test currently asserts the *wrong* (pre-fix) shape and would have to change meaning, not just pass.

## Context

- `lego/backend/internal/apps/ip_allow_list_test.go:127-165` (`TestRESTCreateWithIPAllowListAndReadBack`) currently decodes the GET response into a struct with only a top-level `IPAllowList` field (lines 154-158) and asserts against that — this is the test that encoded the bug. It must be rewritten to decode `serviceDetails.ipAllowList` instead (or both, if t001 keeps a transitional root alias).
- No existing test exercises the PATCH response shape for `ipAllowList`, or a create/PATCH/get three-way consistency check.
- No existing test asserts a `private_service`/`background_worker`/`cron_job` never gets an `ipAllowList` key in `serviceDetails` — the closest existing coverage is `deploy.go:2025-2026`'s create-time rejection, which is a different guarantee (rejects the *input*; this task covers the *output* shape for a type that could never have a non-empty list in the first place, guarding against a future regression that removes the input gate without checking the output gate too).

## Steps

1. Rewrite `TestRESTCreateWithIPAllowListAndReadBack` to decode and assert `serviceDetails.ipAllowList` on the create response and on a subsequent `GET`.
2. Add a PATCH leg: create a web service with no allowlist, `PATCH` in `serviceDetails.ipAllowList`, assert the PATCH response and a following `GET` both show the nested shape identically.
3. Add a negative test: create (or fixture-construct) a `private_service` and a `cron_job`, confirm `GET`'s `serviceDetails` never contains an `ipAllowList` key (not merely an empty one — the key must be absent, matching Render's schema for those types).
4. Add a list leg: `GET /v1/services` with at least one allow-listed web service in the result set, confirm the list item's `service.serviceDetails.ipAllowList` matches the single-resource GET.
