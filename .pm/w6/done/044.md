# Per-row Copy button on env-var/secret-file reveal rows uses the bulk "Copy env vars" label and toast

Why: a screen-reader user gets a misleading accessible name and every user gets a misleading success toast when copying a single value, and the same mislabeling extends to secret files, which aren't env vars at all.

`dashboard/src/features/services/components/service-environment-editor.tsx:957` hardcodes `aria-label={t("services.envCopy")}` (message "Copy env vars", described as "Copy the complete dotenv export") on `SensitiveViewItem`'s per-row Clipboard icon button. That component is shared by both the env-var-row copy (line 635, `onCopy={() => copyFresh("env", key)}`) and the secret-file-row copy (line 715, `onCopy={() => copyFresh("file", name)}`) — so a screen-reader user copying one named variable, or one secret file's content, hears "Copy env vars" for an action that copies exactly one value.

`copyFresh` (lines 482-494) also fires `toast.success(t("services.envCopySuccess"))` — "Environment copied" — on success (line 487), the identical toast `exportEnvironment("copy")` (the real bulk dotenv-export action, line 422) fires. So copying a single secret file's content pops "Environment copied", which is doubly wrong: only one value moved, and it isn't an environment variable.

**Live-reproduced** 2026-08-25 on `qa-20260825-rollback` (`srv-da75qchgoibs73ah006g`, deleted during cleanup): added secret file `qa-secret.txt`, revealed it, clicked its Copy icon (accessible name "Copy env vars" per the live accessibility snapshot), got toast "Environment copied". Evidence: `.playwright-mcp/qa-env-1-secretfile-copy-mislabeled.png`.

**Fix:** give `SensitiveViewItem`'s per-row copy button and `copyFresh`'s success toast their own translation key parameterized by name/kind (e.g. "Copy {name}" / "{name} copied"), distinct from the bulk `envCopy`/`envCopySuccess` strings. Both call sites (env-var row and secret-file row) move together since they share the one component and the one `copyFresh` helper — a fix that touches only one call site leaves the other with the same bug. No existing test asserts this row's accessible name or toast copy (checked `service-environment-editor.test.tsx`).

**Dedupe:** not a duplicate of `w2/m73` t008 or `w5/m44` t004 — those are the original tasks that built the bulk "Copy env vars"/dotenv-export feature itself; this is a reuse bug where a later per-row component borrowed that string instead of getting its own.

**Severity:** minor (cosmetic/accessibility copy bug — no data loss, no blocked journey; the copy itself still puts the correct single value on the clipboard).

**Estimate:** 20-30 min.

## Resolution (2026-09-03)

`SensitiveViewItem`'s per-row button and `copyFresh`'s toast got their own parameterized keys — `services.envCopyOne` ("Copy {name}") / `services.envCopyOneSuccess` ("{name} copied"), en+zh — shared by the env-var and secret-file rows, distinct from the bulk envCopy/envCopySuccess. Test asserts the per-row accessible names, per-name toasts, and that no row button carries "Copy env vars".
