## Objective

Preserved from `.pm/w6/063.md`. `setSubdomainPolicy` on a non-routable service refuses with an instruction the product then forbids the caller from following. The outcome is correct — the mutation *should* be refused — only the reason is wrong, and an agent told to add a custom domain here will loop.

## Context

Live on a private service (46th `/qa-find-bugs` run, 2026-08-27):

```
mutation { setSubdomainPolicy(id:"srv-da84g6oueu1c7395iqkg", policy:"disabled"){ id renderSubdomainPolicy } }
=> {"data":{"setSubdomainPolicy":null},
    "errors":[{"message":"bad request: renderSubdomainPolicy cannot be disabled without at least one custom domain"}]}
```

A caller who follows that instruction hits the other guard:

```
POST /v1/services/{id}/custom-domains {"name":"qa-priv-20260827.example.com"}
=> 400 bad request: a private_service has no ingress and cannot have custom domains
```

- Root cause: `lego/backend/internal/apps/service.go:3560-3577` (`SetSubdomainPolicy`) has **no type gate**. Its guard is `a.Spec.Host == "" && len(a.Spec.Hosts) == 0`, and its doc comment's rationale — "that would leave the service silently unreachable" — only makes sense for a publicly-routable type.
- The message to match: `errNoPublicIngress` (`lego/backend/internal/apps/domains.go:627-631`), used from the create path (`apps/service.go:2332`) and the add-domain verb (`apps/domains.go:863`).
- The family is the complement of `TypePubliclyRoutable` (`lego/types/v1alpha1/app_types.go:828-835`, an allowlist returning true only for `""`, `web_service`, `static_site`): `private_service`, `background_worker`, `cron_job`.
- Sibling with the same shape: `SetIPAllowList` (`service.go:3579-3583`) carries the comment "Only meaningful for web_service and static_site" and also has no gate. A no-op allowlist write is harmless where this one emits a misleading instruction — decide explicitly whether it gets the same treatment rather than leaving it unexamined.

## Steps

1. Add the type gate to `SetSubdomainPolicy`, refusing a non-routable type with a type-specific reason built from the same fact `errNoPublicIngress` states, so the two guards word one fact the same way.
2. Decide, and record, whether `SetIPAllowList` gets the same gate.
3. Verify live per type — private service, background worker, cron job — not by inferring the other two from one.

## Files

- `lego/backend/internal/apps/service.go`
- `lego/backend/internal/apps/domains.go` (message shape only)

## Acceptance criteria

- [ ] `setSubdomainPolicy` on each of `private_service`, `background_worker`, `cron_job` is refused with a type-specific reason that does not instruct the caller to add a custom domain — each verified live.
- [ ] A routable service with custom hosts can still set `disabled`.
- [ ] A routable service with no custom host still gets today's 400 guard, unchanged.
- [ ] The `SetIPAllowList` decision is recorded either way.

## Out of scope

- Whether the field is *reported* for these types — `t002` owns that.
