## Objective

The cause sits in shared projection code, so the fix must be applied against a counted list of emission sites rather than the one that surfaced the bug — and the types that behave correctly today need regression tests, because they are correct *because of* current behaviour and a global change could silently alter them.

## Context

Enumerated sites (counted, not estimated):

- **REST detail and list** both flow through `renderService` (`lego/backend/internal/apps/render.go:439`), which the list loop calls at `:454`. `renderServiceDetails` (`:298`) has one call site, `:262`, but is reached by both paths.
- **GraphQL** registers the field separately: `lego/backend/internal/apps/graphql.go:438`.
- **MCP** accepts it as `update_service` input: `lego/backend/internal/apps/mcp.go:116` (declaration + jsonschema description), provided-map `:737`, applied `:811`. The description text is a contract an agent reads — if `t002` changes per-type semantics, this string must move with it.
- **Dashboard** consumers, all reading the GraphQL flat field: `dashboard/src/features/services/types.ts:187` → `custom-domains-section.tsx:92,169` → `platform-subdomain-section.tsx:18,23,28`, plus `use-subdomain-policy.ts`.

**Why the existing guard did not catch this**, and what to do about it: `lego/backend/internal/api/conformance_allowlist_test.go` allowlists, for both `retrieve-service` and `list-services`, the blanket entry `serviceDetails: does not match the documented union`. That single entry swallows every serviceDetails-shaped divergence for those operations. The extra top-level property cannot fail at all — the pinned `service` schema leaves `additionalProperties` unset, so OpenAPI permits unknown properties. This is why the defect survived two prior passes of the same fix pattern (`w1/m86`, `w6/m106`).

## Steps

1. Confirm the enumeration above by re-running the greps, and paste the counts — do not carry the numbers over on trust.
2. Decide global-vs-allowlisted for the response change and state which it is.
3. Add regression tests covering `web_service` and `static_site` — the types that are correct today — not only the three that are wrong.
4. State what the conformance allowlist should look like afterwards. If the blanket `serviceDetails` entry is narrowed, confirm the remaining genuine divergences still pass; the allowlist's own rules require every entry to cite a real ADR018 row and forbid entries that no longer match a real divergence.
