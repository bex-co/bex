## Objective

Add any meaningful test coverage gaps beyond t001's component unit test, for the behavior this milestone shipped.

## Steps

1. Review whether any of the 22 migrated call sites had an existing snapshot/render test whose expected output needs updating for the new wrapper markup (a `<time>` wrapper element).
2. Add a regression test for at least one previously-unguarded, now-guarded site (e.g. `webhook-deliveries-card.test.tsx`) asserting the guarded element exists.

## Acceptance criteria

- [x] `yarn test` (dashboard) green with no snapshot drift left unexplained.
- [x] At least one migrated call site has a test asserting the guard is present.

## Result

**Done.** Suite went 2689 → 2692 tests, 372 files, all green.

**Step 1 — snapshot/render drift: none.** No existing test needed updating. The wrapper adds a `<time>` element around text that was previously bare, and every affected assertion goes through `getByText`/`toHaveTextContent`, which match on text content regardless of the wrapping element. There are no DOM snapshots over these components. Verified by running the full suite before and after with no expectation edits.

**Step 2 — regression tests on migrated sites, three of them:**

- `webhook-deliveries-card.test.tsx` — the live repro, pinned. A delivery with `sentAt` 55s before the SSR pass, hydrated 61s after it, crossing the exact `"now"` → `"1m"` boundary from the hunt. Asserts React raises zero recoverable errors, **and** that the server HTML contains `>now<` — which is what proves the site is reached in the *blocking* SSR pass, the precondition for #418 to be possible here at all. Confirmed meaningful by temporarily removing the guard: the test fails with one recoverable error.
- `api-key-row.test.tsx` — a second migrated surface, crossing the `"59m"` → `"1h"` boundary, covering the plain-`<TableCell>` shape and the custom-`fallback` path.
- `service-detail-header.test.tsx` — pins the cron header's last-run/next-run block (the `service-detail-header.tsx:213,221` sites) to `<time dateTime="…">` elements carrying both instants, so a regression back to a plain `<span>` fails here rather than silently.

The guard itself can't be asserted from the DOM — React never emits `suppressHydrationWarning` as an attribute — so every guard claim in this milestone is proven behaviourally, by hydrating real SSR markup across a bucket boundary, never by inspecting props.
