## Objective

Use server decisions at existing service lifecycle and deployment entry points so permission is visible before interaction.

## Context

- `use-service-lifecycle.ts` routes Restart through triggerDeploy; its decision must match that execution path.
- List, header, settings, and Manual Deploy controls share operations but have separate presentation.

## Steps

1. Trace the actual mutation used by each affected control, including bare deploy versus commit/image overrides.
2. Compose decision reasons with existing busy, type, suspension, and protection behavior.
3. Guard handlers as well as presentation; use focusable disabled-with-reason controls.

## Acceptance criteria

- [ ] A viewer cannot open a prohibited lifecycle/deploy flow or cause its mutation callback.
- [ ] Contributors retain every operation the invoked backend verb allows; executable-content overrides preserve their stronger relation.
- [ ] Authorized callers can use the existing list/detail/settings entry points with accessible explanations for temporarily blocked controls.

## Out of scope

- Datastore controls, new verbs, and changing the server role matrix.
