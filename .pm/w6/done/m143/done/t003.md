## Objective

Apply action permissions and preconditions to the shared DeployActions component without replacing exact-target eligibility with a service-wide history summary.

## Context

- DeployActions serves the Events list and deploy detail and currently checks only status.
- `deploys.ActionCapabilities` scans the latest 20 service deploys; RollbackEligible is the execution-side status/image predicate.

## Steps

1. Use the server's operation permission and applicable resource preconditions for Cancel and Rollback.
2. Retain the exact selected deploy ID/status/image eligibility; verify older history rows and a service with several candidate deploys.
3. If the available projection cannot express the selected-target decision, make the smallest correction sharing execute-path predicates and preserve existing caller compatibility.
4. Show operation-specific translated reasons while keeping cancellation independent of billing/suspension gates its verb does not require.

## Acceptance criteria

- [ ] The same selected row yields consistent behavior on Events and deploy detail.
- [ ] Contributor rollback and viewer cancellation dispatch no mutation; allowed cancellation remains usable under billing restrictions when the server permits it.
- [ ] An ineligible selected row does not become eligible because a different row is rollbackable; an older eligible row is not rejected solely by the latest-20 summary.

## Out of scope

- New rollback behavior, automatic replay, or client-side reimplementation of billing/authorization policy.
