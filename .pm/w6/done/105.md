# Every CI checkout downloads the 1.45 GB `.pm` tree, so short jobs hold runners for half an hour

Why: a 5-second probe spent 31 minutes in `actions/checkout` on a production runner (w6/104), and every one of the repo's 62 checkout steps pays the same cost on all three pools. That cost is now the main thing starving deploys of runners.

- **Evidence (2026-11-03):** `Production edge liveness` run 41594756773 held both busy `bex-production` runners in checkout from 07:12 to 07:43. `git fetch --depth=1` plus `index-pack` ran for over 8 min. `.pm` is 1,448 of 1,553 tracked MB (w6/100). A blobless + sparse clone of the same repo is 22 MB and took 47 s (measured for w6/m156's watchdog).
- **Do:**
  - Give every `actions/checkout` step that does not read `.pm` the options `filter: blob:none`, `sparse-checkout-cone-mode: false` and `sparse-checkout: "/*\n!/.pm/"`.
  - Keep a full checkout only for the jobs whose scripts read `.pm`: `github-actions-validate.sh`, `adr-registry-validate.sh`, `clusterapi-validate.sh` and any others found by grep.
  - Add a `github-actions-validate.sh` rule so a new checkout cannot silently fetch `.pm` again.
- **Expected:** checkouts take seconds, not tens of minutes, so deploys and probes stop queueing behind them.
- **Relation:** a CI-side mitigation needing no decision. w6/100's (A)/(B)/(C) choice still decides Argo and the repo layout.
