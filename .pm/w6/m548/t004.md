## Objective

Every way to attach a disk leaves the service at the default delay, recorded as a setting change, and the operator never projects a custom grace for a disk-bearing App.

## Context

- Attach paths: REST `POST /v1/disks` and GraphQL `addDisk` and MCP `add_disk` (`lego/backend/internal/apps/disks.go:104,619,722`), a create with `serviceDetails.disk`, a Blueprint adding a disk.
- Operator grace: `terminationGracePeriodSeconds(shutdownDelay, drain)` in `lego/operator/internal/controller/deployment_projection.go`.
- t001's production count of Apps holding both.

## Steps

1. On attach, clear a custom `maxShutdownDelaySeconds` in the same write, with the setting-change event the other settings record.
2. The operator uses the default for a disk-bearing App whatever the spec holds.
3. Return the Apps t001 counted to 30 s through the same path, once, and record their ids here.
4. Tests for each attach path and the operator projection.

## Files

- lego/backend/internal/apps/disks.go, deploy.go, blueprint_plan.go, lego/operator/internal/controller/deployment_projection.go and tests

## Acceptance criteria

- [ ] Each attach path reads back 30 s and records the change; the projected grace is 30 for a disk App with a custom spec value
- [ ] The production Apps holding both are back at 30 s, ids recorded
- [ ] Backend and operator suites and `make lint` pass

## Out of scope

- Restoring a delay on detach
