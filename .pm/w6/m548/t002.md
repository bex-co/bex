## Objective

One check in the shared service refuses a custom delay while the service has a disk, so every surface returns the same `400`.

## Context

- `lego/backend/internal/apps/service.go:4070-4090` (`supportsMaxShutdownDelay`, `validateMaxShutdownDelaySeconds`), `:5568` (`SetMaxShutdownDelay`)
- The create and update paths: REST `deploy.go:412` (service details), GraphQL `graphql.go:834` (update input) and `:1887` (`setMaxShutdownDelay`), MCP `mcp.go:106,213,925` (create and `update_service`)

## Steps

1. Extend the validation with the App's disk (and a create's `serviceDetails.disk`), returning a message that names the disk and Render's rule.
2. Make every entry point call it; a request that sets the delay to 30 explicitly is accepted as a no-op or refused, as t001 records.
3. Handler tests per surface: refused with a disk, accepted without.
