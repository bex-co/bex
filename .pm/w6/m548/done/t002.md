## Objective

One check in the shared service refuses a custom delay while the service has a disk, so every surface returns the same `400`.

## Context

- `lego/backend/internal/apps/service.go:4070-4090` (`supportsMaxShutdownDelay`, `validateMaxShutdownDelaySeconds`), `:5568` (`SetMaxShutdownDelay`)
- The create and update paths: REST `deploy.go:412` (service details), GraphQL `graphql.go:834` (update input) and `:1887` (`setMaxShutdownDelay`), MCP `mcp.go:106,213,925` (create and `update_service`)

## Steps

1. Extend the validation with the App's disk (and a create's `serviceDetails.disk`), returning a message that names the disk and Render's rule.
2. Make every entry point call it; a request that sets the delay to 30 explicitly is accepted as a no-op or refused, as t001 records.
3. Handler tests per surface: refused with a disk, accepted without.

## Record (2026-11-21)

Done. `validateMaxShutdownDelaySeconds` (`lego/backend/internal/apps/service.go`) takes whether the service has a disk and refuses any value but 30 with Render's sentence, `diskShutdownDelayRefusal` in `disks.go`: "max shutdown delay is not supported for services with a disk". Its three callers pass the disk: create (`validateTypeSpecificCreate`, from `serviceDetails.disk`), `SetMaxShutdownDelay` (GraphQL `setMaxShutdownDelay`, the REST and MCP patch rows) and the `ServicePatch` row's preflight (`settings.go`), which is what refuses a dry-run. Per t001, exactly 30 is accepted on a disk service and stores nothing (`storedMaxShutdownDelaySeconds`): a no-op when the spec holds none, else it clears a value left from before the rule and records `max_shutdown_delay_changed`. Reads report 30 for a disk App whatever its spec holds (`AppSpec.ShutdownDelaySeconds`). GraphQL and MCP create take no disk, so a create carrying both exists on REST only. The MCP field descriptions and `add_disk` say the rule.

Tests (`disk_shutdown_delay_test.go`): `TestDiskServiceRefusesACustomShutdownDelayOnEverySurface` (REST PATCH, REST dry-run, GraphQL, MCP: the sentence, no CR change, no event), `TestDiskServiceTakesOnlyTheDefaultShutdownDelay` (30 is a no-op, 30 clears 120, a service without a disk keeps 1 and 300), `TestDiskServiceReadsTheDefaultShutdownDelay`, `TestCreateWithADiskRefusesACustomShutdownDelay`. `cd lego/backend && go test ./...` and `make lint` pass.
