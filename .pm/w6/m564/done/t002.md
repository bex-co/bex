## Objective

Implement t001's decision in bex-api so REST, GraphQL and MCP `resume` start an editing sandbox on a completed session that has none.

## Steps

1. Extend `Resume` to dispatch the editor spec when `record.SandboxID == ""` on a completed session.
2. Claim a kept retained image as a turn's dispatch does, and release it once the sandbox is up.
3. Make the Completer treat the editor sandbox like a finished turn's: the SSH pin, then m563's idle timeout from the last disconnect.

## Files

- `lego/backend/internal/agentsessions/service.go`, `completion.go`, `retention.go`
- `lego/backend/internal/agentsessions/rest.go`, `graphql.go`, `mcp.go` (descriptions)

## Acceptance criteria

- [x] A real-Postgres test with the sandbox fake: resume on a closed session boots from its kept image when one exists, else from the branch, and runs no turn; a concurrent `Steer` is refused or queued, not raced.
- [x] A bex-api restart during the start leaves no session stuck in a starting phase.

## Result (2026-11-22)

`Service.Resume` (`lego/backend/internal/agentsessions/editor.go`) now: returns a session whose turn runs or starts unchanged; keeps a finished session's live sandbox for the editor (`KeepAgentSessionSandboxForEditor`, idle clock restarted); starts one for a finished session with none (`admitDispatch`, then the `BeginAgentSessionEditorStart` CAS, then `startEditorSandbox` in the background, bound by `BindAgentSessionEditorSandbox` only while still `resuming` and unarchived, else the sandbox is ended); refuses canceling/canceled (`AGENT_SESSION_NOT_RESUMABLE`) and archived (`AGENT_SESSION_ARCHIVED`). The kept disk is claimed as a turn's dispatch claims it and spent once bound; `BeginAgentSessionRetention` admits a `continued` turn for the editor's own sandbox, so its close keeps the disk again. The Completer settles `resuming` rows (`settleEditorStart`), gives an editor's sandbox a person's idle timeout whoever started the session, reads its checkout in the sandbox at the close and harvests no transcript from it. The SSH resolver and `sshAddress` accept a finished, unarchived session's sandbox (`openableSandbox`) and wait for a start to settle; Stop during a start is `AGENT_SESSION_NO_TURN_RUNNING`; capabilities gain `sshEnabled` on REST, GraphQL and MCP; the MCP description says what resume does. Driver: `BEX_AGENT_EDITOR=1` writes `{"state":"ready"}` after setup and runs no turn. Deleted as dead: `ResumeAgentSessionSandbox`, `setLifecycleIfActive`, `SetAgentSessionFailure`. Real-Postgres tests: `TestResumeStartsAClosedSessionFromItsKeptDiskPG`, `TestResumeStartsAClosedSessionFromItsBranchPG`, `TestAMessageWaitsForTheEditorStartPG`, `TestARestartDuringTheEditorStartLeavesNoResumingSessionPG`; reverting the retention predicate fails the first.
