# Unset BEX_IMAGE_COMPATIBILITY_WORKSPACES should mean render-v1, not strict

Why: production now creates every new Docker/image service as render-v1, but self-hosted bex and every dev-N stack still default to strict-v1 when the variable is unset. Unchanged root-init images (nginx, ClickHouse, Postgres) crash-loop there, which breaks Render parity for the open-source product (ADR008 § Render parity first).

- **Evidence (2026-10-21):** on dev-6, unchanged `nginx:1.27` crash-loops with `chown("/var/cache/nginx/client_temp", 101) failed (Operation not permitted)` under `capabilities: {drop: [ALL]}`, while the same image serves 200 in production under render-v1.
- **Fix:**
  - `lego/backend/cmd/api/config.go` treats unset as `*`, and an explicit `off` (or an empty list) restores strict;
  - update `lego/backend/AGENTS.md` and drop the explicit `*` from `lego/operator/config/prod/kustomization.yaml`;
  - test the parse.
- Do the same for `BEX_RENDER_V1_USER_NAMESPACES` only where the node runtime supports user namespaces (local overlayfs `local-path` fails closed). Keep that one explicit.
