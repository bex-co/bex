## Objective

If cx53 is in stock only outside fsn1, run the xl pool in that eu-central location, so Pro Plus and Pro Max get a node without changing the type the user chose.

## Context

- CAPH derives failure domains from `HetznerCluster.spec.controlPlaneRegions`; check whether a worker MachineDeployment may use a location outside them, or whether the region list can grow on a live cluster (the network is CAPH-owned and immutable)
- Every location of eu-central (fsn1, nbg1, hel1) shares the private network zone; check the placement group and the load balancer's private targets across locations
- `scripts/clusterapi-validate.sh` guards the pools

## Steps

1. Confirm CAPH accepts the worker location without touching the immutable network; if not, park this milestone with the exact gate.
2. Move `bex-tenant-xl` (min 0) to the stocked location, with the validator updated.
3. Scale it from zero once with a `pro_plus` service and confirm the node joins and the pod runs.
