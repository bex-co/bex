## Objective

Make the selected native workspace reach every workspace-scoped notification operation and be validated by the shared backend membership checks.

## Context

- The mobile registration/inbox/count/read documents supply no ownerId, while notification service methods resolve the workspace from context.
- The client's selected-workspace binding currently can disagree with the workspace used for persisted device and inbox rows.

## Steps

1. Add compatible optional ownerId handling to the existing GraphQL notification operations using the repository's Core workspace-resolution seam; examine corresponding REST selectors and preserve default callers.
2. Thread the selected workspace through register/list/unregister, inbox/unread count, and mark-read; ensure auth-clear cleanup targets the original registration context.
3. Regenerate native GraphQL documents and extend the exact scope-operation inventory only for the reviewed arguments/operations.

## Acceptance criteria

- [ ] A non-default workspace registers and reads its own notifications; no operation silently falls back to the caller's default after an explicit selection.
- [ ] Unknown/nonmember ownerId is refused; authenticated subject is never accepted from client input.
- [ ] Omitted ownerId remains backward compatible, and unregister/mark-read cannot alter another caller's or workspace's rows.
- [ ] Generated output comes from codegen rather than hand edits.

## Out of scope

- Changing the device-token privacy contract or native OAuth scopes.
- Adding a device-token API to MCP.
