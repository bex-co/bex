## Objective

A store's server enforces its plan's limit, with room for the platform's own clients, and a new or restarted store starts with it.

## Context

- `valkeyArgs(spec, plan)` in `lego/operator/internal/controller/keyvalue_controller.go` builds the server flags and sets no `--maxclients` today, so Valkey's default 10,000 applies.
- `applyKeyValueStatefulSet` (`keyvalue_maxmemory_runtime.go`) keeps a template's maxmemory policy when it is the only change, so a policy edit rolls nothing (w4/m330).
- Valkey counts every client against `maxclients`, the platform user's too, and refuses the next with `-ERR max number of clients reached`.

## Steps

1. Append `--maxclients <limit + reserve>`, the reserve covering t001's platform clients, so the tenant gets exactly the plan's figure.
2. Keep an existing StatefulSet's template when `--maxclients` is the only difference, as the policy is kept, so the operator upgrade rolls no store; t004 brings running servers to the value.
3. Tests: every plan's args carry its flag; an existing template that differs only by it does not roll.
