# Project/Environment create-form hint promises an inline "create Environment" action that doesn't exist

Why: the copy tells a user they can "pick or create an Environment" right there, but the control only ever offers "No environment" or an existing one — following the copy's own instruction sends the user on a dead-end detour that discards whatever they'd already filled in on the create form.

Repro:

1. Sign in, create a fresh Project (or use one with zero Environments).
2. Go to `/services/new` (or `/keyvalue/new`, or the New Database dialog) and select that Project.
3. Open the Environment dropdown.

Expected (per the hint text right below the selector): a way to "create" an Environment inline, or copy that doesn't claim one exists.

Actual: the Environment `<Select>` only ever renders `SelectItem`s for `"unassigned"` ("No environment") and whatever `useEnvironments(projectId)` returns — confirmed live via `document.querySelectorAll('[role="option"]')` returning exactly `["No environment"]` for a project with zero Environments. There is no "+ Create environment" affordance anywhere in the component. The only way to create one is to abandon the create-service/database/keyvalue form — losing every field already filled in (repo URL, name, root directory, build/start commands, env vars, secret files) — go to the Project's own Overview page, click "New Environment" there, then come back and refill the whole form from scratch.

Root cause:

- `dashboard/src/features/environments/components/project-environment-selector.tsx:99-119` — the Environment `<Select>` renders only the `"unassigned"` item plus the fetched `environments` list; no create action exists anywhere in the component.
- `dashboard/src/features/environments/locales/en.ts:318-322` (`environments.assignmentHint`) is the string making the false promise: "A resource joins a Project only through an Environment. Selecting a Project alone narrows the list below — pick or create an Environment to actually add this resource to it." Same string duplicated in `zh.ts`.

This is a distinct gap from `w6/m48` t003, which fixed a different inaccuracy in this exact same string (the earlier copy's "also" wording implied Project-only selection already joined the project — that fix is confirmed still correct live: selecting a Project with no Environment genuinely leaves the resource unassigned). m48 rewrote the hint but never audited whether the replacement copy's own new claim ("or create") was actually true.

Blast radius: this component is shared by exactly 3 create flows (`grep -rln ProjectEnvironmentSelector dashboard/src`): `dashboard/src/routes/services.new.tsx`, `dashboard/src/routes/keyvalue.new.tsx`, `dashboard/src/features/databases/components/create-database-dialog.tsx`. Fixing the one shared locale string fixes all three call sites at once — no per-site allowlisting needed.

Fix: soften `environments.assignmentHint` (both `en.ts` and `zh.ts`) to describe only what the control can do — e.g. drop "or create" and point at the Project page instead ("...select an Environment to add this resource to it; create one from the Project's page first if none exist yet"). Copy-only change, no behavior change intended (adding a genuine inline "+ Create Environment" affordance is a bigger feature call, out of scope here). Extend `w6/m48`'s existing regression test for this string to also assert the option list has no phantom "create" affordance.

Evidence: `.playwright-mcp/qa-newservice-env-dropdown.png` (New Web Service form, Environment dropdown open on a zero-Environment project, only option "No environment").

Severity: minor. Estimate: 15-20 minutes.
