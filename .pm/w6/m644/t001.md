## Objective

Pick 20 of Render's own `render-examples` Blueprints that bex can deploy unchanged. Between them they must cover every runtime and service type. Write down, for each one, how its README or its Render guide says to tell that it works.

## Context

- `bash scripts/render-examples-corpus.sh <dir>` fetches every `render.yaml` in github.com/render-examples. On 2026-11-26 it fetched 185 files.
- A template can be deployed unchanged when it has:
  - no `sync: false` variable (that would ask for a value, usually a third-party key);
  - no `type: workflow` service (a `DO_NOT_DO` non-goal);
  - no previews (a `DO_NOT_DO` anti-goal).
- 97 files qualified on 2026-11-26. Across them, runtimes appear as docker 27, node 17, python 7, image 6, static 5, ruby 3 and go 2. Service types appear as web 56, pserv 14, worker 5, redis 3 and cron 1. 21 files declare databases and 23 declare a disk.
- The weekly corpus guard (`TestRenderExamplesCorpus`, w33/001) already says which files bex validates. Choose only files it accepts.
- Render's guides live at `https://render.com/docs/deploy-<name>`. Each template repo's README usually gives the URL path to open and what it shows.

## Steps

1. Fetch the corpus and filter it by the rule above.
2. Choose 20 files. Together they must include:
   - every runtime above;
   - at least one each of a private service, a background worker, a cron job, a Key Value instance, a Postgres database and a disk;
   - at least one multi-service template.
   Prefer templates with a Render guide.
3. For each file, record: repo, runtime(s), service types, plans, whether it has a database or a disk, and the check (URL path + expected status/text, or for a worker or cron job the log line or side effect to look for).
4. Write the list to `docs/render-artifacts/render-examples-live.md`, with a short header saying how the files were chosen and on which date the corpus was fetched.

## Files

- `docs/render-artifacts/render-examples-live.md` (new)

## Acceptance criteria

- [ ] 20 templates listed, covering every runtime and service type named above, each with a concrete check.
- [ ] None of them has a `sync: false` variable, a workflow or previews.
- [ ] `bash scripts/docs-links-validate.sh` exits 0.

## Out of scope

- Templates that need a third-party secret (those with a `sync: false` variable). They can be a later round with first-party keys.
