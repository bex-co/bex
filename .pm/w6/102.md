# Web Shell closes before the browser's close reply, so the tail of its output can be lost

Why: w6/096 fixed native SSH's server-closes-first truncation. The browser Web Shell has the same shape, a Render-visible surface, so a command's last output can vanish there too.

- **Evidence:** `lego/backend/internal/sshgateway/webshell/websocket.go:420` sends a WebSocket close frame and the handler's `defer conn.Close()` (`:207`) runs immediately, without reading the browser's close reply. With unread browser frames pending, the TCP close resets, dropping output still in flight (w6/096 review, 2026-10-29).
- **Do:** after sending the close frame, read until the peer's close frame or ~1 s, then close. Add a regression test: large output followed by immediate exit must arrive whole through a slow reader.
- **Render parity:** Render's dashboard shell must not drop output either, so this is a parity fix on the UI surface.
