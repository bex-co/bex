## Objective

Write down what Render documents for a Go service's source path and how bex derives each part of it, then decide how existing Go services move.

## Context

- [Render — Persistent Disks](https://render.com/docs/disks): Go source path `/opt/render/project/go/src/github.com/<owner>/<repo>`, example mount `…/<repo>/data`; the other runtimes use `/opt/render/project/src`.
- `lego/operator/internal/build/native.go:555` (`nativeWorkdir`), `:168` (`nativeGoPath`); the build `Options` carry the repository URL and root directory.
- A service with a root directory: Render's WORKDIR holds the root directory (the `nativeWorkdir` comment says the same for bex).

## Steps

1. Quote Render's table and Go example with the date read; check Render's Go deploy and monorepo docs for a root-directory or non-GitHub case.
2. Decide and record in the milestone README: the host/owner/repo source (repository URL, case kept or lowered), a public Git URL and a non-GitHub host (`<host>/<owner>/<repo>`, unverified against Render), a root directory (appended, as Render does for the other runtimes), and existing services (recommendation: all move, `/opt/render/project/src` a symlink to the new directory).
3. Count native Go services on production (`kubectl get apps.app.bex.co -A` with the runtime field) and how many carry a disk under `/opt/render/project/src`.
