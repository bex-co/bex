## Objective

The native Dockerfile generator gives a Go service Render's Go source directory as its `WORKDIR`, with `/opt/render/project/src` a symlink to it, and every consumer of `nativeWorkdir` follows the service's real directory.

## Context

- `lego/operator/internal/build/native.go` `nativeDockerfile` (`WORKDIR %s` from `nativeWorkdir`), `nativePythonVenv`
- `depscache.go:107-108` (Rust target and Elixir deps cache under `nativeWorkdir`), `nativestaticdeps.go:162` and `nativepublishcheck_test.go` (the publish check)
- `nativeGoPath` is already Render's GOPATH, so the new directory sits under it

## Steps

1. Replace the constant with a per-service function (Go: `nativeGoPath + "/src/" + <host>/<owner>/<repo>` per t001; every other runtime unchanged).
2. Create the parent directories and the `/opt/render/project/src` symlink in the image for Go.
3. Move each consumer to the function; keep caches keyed so an existing cache still seeds.
4. Unit tests: the generated Dockerfile for Go and for one other runtime.

## Files

- lego/operator/internal/build/native.go, depscache.go, nativestaticdeps.go and their tests

## Acceptance criteria

- [ ] A Go service's generated Dockerfile has Render's Go `WORKDIR` and the symlink; other runtimes' are byte-identical to before
- [ ] `make test` and `make lint` pass

## Out of scope

- Buildpack and Docker-runtime services
