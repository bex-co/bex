## Objective

The native Dockerfile generator gives a Go service Render's Go source directory as its `WORKDIR`, with `/opt/render/project/src` a symlink to it, and every consumer of `nativeWorkdir` follows the service's real directory.

## Context

- `lego/operator/internal/build/native.go` `nativeDockerfile` (`WORKDIR %s` from `nativeWorkdir`), `nativePythonVenv`
- `depscache.go:107-108` (Rust target and Elixir deps cache under `nativeWorkdir`), `nativestaticdeps.go:162` and `nativepublishcheck_test.go` (the publish check)
- `nativeGoPath` is already Render's GOPATH, so the new directory sits under it

## Steps

1. Replace the constant with a per-service function (Go: `nativeGoPath + "/src/" + <host>/<owner>/<repo>` per t001; every other runtime unchanged).
2. Create the parent directories and the `/opt/render/project/src` symlink in the image for Go.
3. Move each consumer to the function; keep caches keyed so an existing cache still seeds.
4. Unit tests: the generated Dockerfile for Go and for one other runtime.

## Files

- lego/operator/internal/build/native.go, depscache.go, nativestaticdeps.go and their tests

## Acceptance criteria

- [ ] A Go service's generated Dockerfile has Render's Go `WORKDIR` and the symlink; other runtimes' are byte-identical to before
- [ ] `make test` and `make lint` pass

## Out of scope

- Buildpack and Docker-runtime services

## Record (2026-11-21)

- `nativeSourceDir(o)` (`lego/operator/internal/build/native.go`) replaces the constant in the generated `WORKDIR`. A Go service (not a static site) gets `nativeGoSourceDir(o.Repo, o.RootDir)`, which is GOPATH's `src/<host>/<owner>/<repo>[/<rootDir>]` under the t001 rules. Every other image keeps `nativeWorkdir`.
- `nativeSourceLink` adds `RUN ln -s <dir> /opt/render/project/src` right after `WORKDIR`, which has made the directory and its parents. It adds nothing when the directory is `/opt/render/project/src`, so every other runtime's Dockerfile is byte-identical to before.
- **Consumers:** none needed a change. `depscache.go`'s Rust target and Elixir deps are not Go, and Go's own cache is GOPATH's `pkg`, outside the source, so an existing cache still seeds. Go's build cache may miss once. `nativePythonVenv` is Python only. The publish check (`nativestaticdeps.go`) runs on static sites only, which keep `/opt/render/project/src`, as does the publish Job's extract, which reads relative to the image's `WORKDIR`. `native-init`'s secret-file links use its working directory.
- **Tests:** `nativesourcedir_test.go`. `TestNativeGoSourceDirIsRendersGoPath` covers the URL forms, the root directory and the fallbacks. `TestNativeDockerfileWorkdirIsTheRuntimesSourcePath` covers Go's `WORKDIR` plus the link, every other runtime unchanged, a Go build source, a monorepo, a Go static site and an unsafe root directory. `go test ./internal/build/...` passes, and so do `make test` and `make lint`. `make test` ran with a `docker` on PATH that fails at once. The wedged local daemon hung `docker inspect` in `TestCanceledReleaseWithAPriorReleaseKeepsServing` until the 30-minute timeout, and that test has nothing to do with this change.
