## Objective

Make Render-shaped Service list/get/create/update responses carry the resolved nested owner and truthful region, dashboard URL, and update timestamp while preserving bex-native fields.

## Context

- `lego/backend/internal/apps/render.go` is the REST wire boundary and already contains partial `dashboardUrl`, `createdAt`, and `updatedAt` fields.
- An app's public `status.url` is a data-plane endpoint, not a dashboard detail link.
- Service mutations and operator status changes need an authoritative freshness source selected by t001.

## Steps

1. Extend the Render service adapter with the nested owner and configured region contract.
2. Build dashboard links from `BEX_DASHBOARD_URL` plus an existing stable service route, omitting them when either side is unavailable.
3. Project the authoritative creation/update timestamps across list, get, create, patch, deploy, suspend/resume, and status refresh paths.
4. Preserve `ownerId`, cursors, app URL fields, ids, and official-CLI decoding.
5. Cover legacy/store-off and unset-config behavior.

## Files

- `lego/backend/internal/apps/render.go`
- `lego/backend/internal/apps/service.go`
- `lego/backend/internal/apps/rest.go`
- `lego/backend/internal/apps/*test.go`
- `lego/backend/internal/api/server.go`
- `lego/types/api/v1alpha1/app_types.go`

## Acceptance criteria

- [ ] Service REST responses contain the real nested owner and truthful optional metadata.
- [ ] `dashboardUrl` is never the hosted app URL and resolves to a real dashboard route when present.
- [ ] `updatedAt` advances after an observable service change and remains stable on a read-only fetch.
- [ ] Existing Render CLI service commands and bex-native response fields remain compatible.

## Out of scope

- Changing service URL/custom-domain behavior or adding new dashboard pages solely to manufacture a link.
