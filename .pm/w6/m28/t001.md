## Objective

Turn the CLI finding into one explicit metadata contract before adding more fields, including exact wire shapes, truthful sources, omission rules, and lifecycle semantics for Service, Postgres, and Key Value.

## Context

- `.pm/w6/done/016.md` records the live official-CLI symptom and the partial fixes that landed concurrently.
- `lego/backend/internal/apps/render.go` currently uses the app URL as `dashboardUrl` and copies `createdAt` into `updatedAt`; `lego/backend/internal/keyvalue/rest.go` uses the tenant id as both owner id and owner name.
- bex is single-region today but has no general resource-region configuration; a plausible-looking constant is not authoritative data.

## Steps

1. Pin the expected owner/region/dashboardUrl/timestamp shapes from the Render OpenAPI, pinned CLI types, and observed CLI rendering.
2. Inventory real sources and mutation points for all three resources, including dashboard routes and Kubernetes/control-plane timestamps.
3. Decide the explicit platform-region configuration and unset behavior without reusing the unrelated S3 region.
4. Define whether authoritative update times live in CR metadata/status, control-plane rows, or another shared source, including legacy-object fallback.
5. Record REST-boundary versus core/GraphQL/MCP ownership so later tasks do not leak Render-only nesting into neutral views.

## Acceptance criteria

- [ ] Every target field has an exact wire shape, authoritative source, unset/legacy rule, and owning layer.
- [ ] Region is never derived from `BEX_STATIC_S3_REGION` or a fabricated Render region code.
- [ ] Dashboard URLs correspond to routes that actually resolve in the dashboard.
- [ ] `updatedAt` has a defined event that advances it and is not an alias for creation time.

## Out of scope

- Multi-region scheduling or moving a resource between regions.
