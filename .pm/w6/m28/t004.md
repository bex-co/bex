## Objective

Introduce a dedicated Render Postgres wire adapter that enriches list/get/create/update responses with real owner, region, dashboard URL, and update-time metadata without exposing credentials or weakening tenant checks.

## Context

- `lego/backend/internal/postgres/service.go` currently uses `PostgresView` as both neutral/core data and the REST representation.
- `ownerId` is already read from `core.LabelTenant`; it supplies the resource workspace for the shared owner lookup.
- Connection info and credential reveal are separate authenticated surfaces and must remain separate from metadata enrichment.

## Steps

1. Add a REST-boundary Render Postgres type and mapping rather than forcing nested REST shapes into GraphQL/MCP views.
2. Populate resolved owner and the t001 region/dashboard/timestamp contract on list and single-resource responses.
3. Preserve pagination, stable ids, project/environment membership, plans, connection-info separation, and error shapes.
4. Verify cross-workspace and missing-owner-label behavior.
5. Exercise JSON and text rendering with the pinned CLI.

## Acceptance criteria

- [ ] Postgres REST list/get objects expose the real nested workspace owner and truthful optional metadata.
- [ ] Official CLI text output includes the Workspace line and does not show a misleading blank/configured Region.
- [ ] Metadata enrichment never includes passwords or bypasses resource-workspace authorization.
- [ ] Existing GraphQL/MCP contracts and connection-info verbs remain unchanged unless t007 identifies a semantic gap.

## Out of scope

- Postgres rename/stable-id work and any data-plane region migration.
