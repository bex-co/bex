## Objective

`lego/operator/internal/controller/app_controller.go:1206`'s `rejectProtectedSecretRefs` must stop refusing an App whose `spec.CloneSecret` or `spec.ExternalRegistryPullSecret` names **its own** platform-minted, deterministically-named Secret (`<app.Name>-clone` or `<app.Name>-registry-pull`), while continuing to refuse those same two fields when they name any **other** Secret carrying `LabelProtectedFromTenantMount` — including another App's own clone/pull secret in the same namespace, and the out-of-band operational Secrets (`RegistryPullSecret`, `RegistryPushSecret`, etc., already handled by name above the label lookup).

## Context

- Guard: `lego/operator/internal/controller/app_controller.go:1206-1279` (`rejectProtectedSecretRefs`). The label-lookup loop at `:1265-1278` is the one that must special-case `CloneSecret`/`ExternalRegistryPullSecret`.
- The two deterministic self-names to recognize:
  - `cloneSecretName(app) = app + "-clone"` — `lego/backend/internal/apps/clonesecret.go:52`. Written (with the protected label) by `writeCloneSecret`, `clonesecret.go:69-87`.
  - `pullSecretName(appName) = appName + "-registry-pull"` — `lego/backend/internal/registrycreds/pullsecret.go:48`. Written (with the protected label at line 153) inside `materializePullSecret`, `pullsecret.go:79`.
- The operator package (`lego/operator/...`) cannot import the backend package (`lego/backend/...`) — do not add a cross-module dependency. Reimplement the two deterministic name functions locally in the operator (or, if a types-level shared helper already exists in `lego/types/v1alpha1`, use that) — check `lego/types/v1alpha1/app_types.go` (it appears in the earlier `grep -rl cloneSecretName` results) before duplicating.
- `app.Name` here is the App CR's own k8s object name (already tenant-namespaced, e.g. `tea-<tenantHash>-<slug>`), available as `app.Name` inside `rejectProtectedSecretRefs`.
- Live-observed real values for reference (already deleted, but useful for a unit-test fixture): App name `tea-d98210cbbpdc73dcrkvg-qa-20260825-web`, clone Secret name `tea-d98210cbbpdc73dcrkvg-qa-20260825-web-clone`.

## Steps

1. Add a small local helper (or reuse a shared one from `lego/types/v1alpha1` if it already exists) computing the two deterministic self-secret names for a given App name.
2. In the `cl.Get` loop (`:1266-1278`), before returning the "protected operator Secret" error, check whether the offending `name` came from **either** `app.Spec.CloneSecret` or `app.Spec.ExternalRegistryPullSecret` **and** equals that App's own deterministic self-name. If so, skip the rejection for that specific field's value — but the same protected-label lookup must still catch it if it's referenced through any *other* field (`envFromSecret(s)`, `filesFromSecrets`, `env[].valueFrom.secretKeyRef`, the two pending annotations) via the existing `names` set membership, since the running App's own container must still never mount its transient clone token.
3. Preserve exact behavior for every other case: an App naming an out-of-band operational Secret by configured name (existing check above the loop, unchanged), and an App naming *any* protected Secret through the six other fields (must still be refused even if it happens to look like `"<something>-clone"` textually — only exact self-name equality on exactly these two fields is exempted).
4. Update the function's godoc comment to state the narrowed rule precisely (the existing comment already explains the F1/F7 history; extend it rather than replacing it).
