## Objective

Pick 20 templates with at least one `sync: false` key. Between them they must cover the runtimes and service types. Fix the rule for what value each key gets, and write down each template's check.

## Context

- Same corpus and exclusions as w6/m644 ([result page](../../../docs/render-artifacts/render-examples-live.md)), but keeping files that have `sync: false` keys. About 66 qualified on 2026-11-26.
- ADR049 § Manual env vars: a plan's `requiredManualEnvVars` lists `{serviceType, serviceName, key}` for each `sync: false` key without a value on a service the plan creates. The approval must answer each one and nothing else.

## Steps

1. Choose 20 files.
   - Cover every runtime and type in the corpus.
   - Prefer files with a Render guide.
   - Include at least one file whose keys are only third-party API keys, one with an OAuth client, and one with `RENDER_API_KEY`.
2. Write the value rule:
   - a third-party key gets a placeholder that cannot be a real credential (for example `bex-placeholder-not-a-key`);
   - a key that configures the app (a provider name, a URL, a repository) gets the value its README suggests, or a harmless one;
   - `RENDER_API_KEY` gets nothing real. Record what the template does with it.
3. For each file, record: repo, runtimes, types, plans, the keys with their values (placeholders only), and the check. Use the template's own check where it needs no real key; otherwise use "starts and serves its health path".
4. Add a section for this run to the result page.
