## Objective

The Blueprint planner indexes existing services by their Kubernetes object name, which is tenant-prefixed, while it looks them up by the manifest's public name. Every lookup misses, so every service plans as a `create`. Key the map by the public name, and give the services loop the duplicate-name guard its datastore siblings already have.

## Context

- `lego/backend/internal/apps/blueprint_state_plan.go:83` — `resolver.services[app.Name] = app`.
- Lookup at `:119` — `app, ok := r.services[name]`, where `name` comes from the manifest.
- `:150-152` — a miss becomes `BlueprintPlanCreate`.
- **The correct accessor already exists:** `appServiceName(a)` (`blueprint_ownership.go:165-170`) returns `a.Labels[core.LabelServiceName]`, falling back to `a.Name` for the legacy hand-applied App whose object name **is** the public name.
- **The control is in the same function:** `:97` keys databases by `database.Spec.Name` and `:111` keys key-values by `keyValue.Spec.Name`, and both raise a `core.ErrConflict` when a name repeats. Services do neither.
- Apps have no `Spec.Name` — see `lego/types/v1alpha1/app_types.go:260-264`. Use `appServiceName`, not a `Spec.Name` swap.
- Keep the tenant filter at `:80` (`if scoped && app.Labels[core.LabelTenant] != tenantID { continue }`) exactly as-is: the fix must make names match **within** a workspace, never across them.

## Steps

1. Key `resolver.services` by `appServiceName(app)`.
2. Add the duplicate-name conflict, mirroring `:94-97` and `:109-111` so the three resource kinds behave alike.
3. Confirm the legacy no-label App still resolves (the fallback covers it).
4. Re-run the fixture from the milestone DoD and confirm the second plan is no longer a `create`.
