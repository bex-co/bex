## Objective

Make the operator set the new distinct signal (from t002) in the exact case this milestone is about — a canceled build with no prior successful release — instead of `appv1alpha1.PhaseFailed`.

## Context

- `lego/operator/internal/controller/app_controller.go:552-573`, `settleCanceledRelease`:
  ```go
  if app.Status.Image != "" {
      return r.dispatchRuntime(ctx, app, app.Status.Image, port)
  }
  app.Status.Phase = appv1alpha1.PhaseFailed
  app.Status.ObservedGeneration = app.Generation
  meta.SetStatusCondition(&app.Status.Conditions, metav1.Condition{
      Type: appv1alpha1.ConditionReady, Status: metav1.ConditionFalse, Reason: "BuildCanceled",
      Message: "build canceled before a release became available", ObservedGeneration: app.Generation,
  })
  return ctrl.Result{}, r.Status().Update(ctx, app)
  ```
  This is the exact branch to change — only reached when `app.Status.Image == ""` (no prior release), which is what makes this specifically the "first-ever deploy" case.
- The build-outcome metering (`recordBuildOutcome(buildOutcomeCanceled)`, a few lines above at `:539-541`) already correctly counts this as a cancel, not a failure — don't touch that, it's already right.
- Single call site (`app_controller.go:510` calls `settleCanceledRelease`) — confirm no other path sets `PhaseFailed` for this same "canceled, no release" case before considering the fix complete.

## Steps

1. Change the `app.Status.Phase = appv1alpha1.PhaseFailed` line to set the new signal from t002 instead.
2. Confirm the Condition's `Reason`/`Message` stay accurate (they already are — "BuildCanceled" / "build canceled before a release became available").
3. Grep for any other reconcile path that could reach `PhaseFailed` for a canceled-with-no-release App, to confirm this is genuinely the single call site.
