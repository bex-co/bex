## Objective

Add meaningful regression tests for the behavior this milestone ships — must assert real behavior and failure modes, not trivial/tautological/snapshot-everything tests.

## Context

- The critical adjacent-class control case: a service reaching `PhaseFailed` through a genuine build/deploy error must keep showing "Failed" — this needs its own explicit test, not just a happy-path test for the new canceled-first-deploy case.
- `settleCanceledRelease` is a pure-ish function of App status fields — an operator-level unit test proving `app.Status.Image == ""` + cancel produces the new signal (not `PhaseFailed`) should be straightforward and fast, proven red against the pre-fix code first.
- Dashboard: a test on `deriveStatus`/`PHASE_STATUS` proving the new signal resolves to the new non-destructive badge, and a sibling test proving the unchanged genuine-failure case still resolves to `"failed"`/destructive.

## Steps

1. Operator test: canceled build, no prior release → new signal set, not `PhaseFailed`. Prove it fails against the pre-fix code.
2. Operator test (control case): canceled build WITH a prior successful release (the `app.Status.Image != ""` branch, `dispatchRuntime`) is unaffected — this milestone only touches the no-release branch.
3. Dashboard test: `deriveStatus` on a ServiceView carrying the new signal resolves to the new key/variant.
4. Dashboard test (control case): `deriveStatus` on a ServiceView with `phase: "Failed"` and no new signal still resolves to `{key: "failed", variant: "destructive"}`.
5. Run the full suite for both modules (`make test` from `lego/operator/`, `cd lego/backend && go test ./...` if backend types changed, `yarn test` in `dashboard/`) to confirm nothing else broke.

## Files

- `lego/operator/internal/controller/*_test.go`
- `dashboard/src/features/services/lib/__tests__/status.test.ts` (or wherever the existing suite lives)

## Acceptance criteria

- [ ] A test proving the canceled-first-deploy case produces the new signal, red pre-fix / green post-fix.
- [ ] A test proving the genuine-failure control case is unaffected.
- [ ] Full test suites pass for every touched module.

## Out of scope

- Broad new test infrastructure — reuse existing test patterns in each touched file.
