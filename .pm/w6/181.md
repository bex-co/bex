# 181 — An image whose `EXPOSE` names a reserved port, more than 75 TCP ports or SCTP fails to deploy; on Render it deploys

Why: such an image deploys on Render and fails on bex with `ImageMetadataUnavailable`, and [ADR018](../../docs/ADR018/services-lifecycle.md)'s Open ports row records it as a divergence (7) that the user never signed off.

- **Source:** `/pm-brainstorm one aspect of render parity to w6` 2026-11-25 (service networking: the private network and WebSockets, at `fe4d53addd`), item 3, filed by `/pmx them to w6`.
- **Evidence:** `privateTCPPorts` (`lego/operator/internal/registry/image_config.go`) returns an error, so the image's metadata read fails and the deploy with it, when an `EXPOSE` declaration:
  - names a reserved port (`exposed TCP port %d is reserved`; `reservedImagePorts` = 18012, 18013, 19099 in `lego/types/v1alpha1/image_network.go`);
  - adds up to more than `MaxImagePorts` (75) TCP ports;
  - uses a protocol other than `tcp` or `udp` (Docker also accepts `sctp`: `invalid exposed port declaration`).
- **Render:** a service can have "up to 75 open ports", and the reserved ports "can't be used for private network communication" (render.com/docs/private-network). That is a routing limit, not a deploy failure, and Render finds ports at run time (render.com/docs/web-services: Render is "usually able to detect" the port). Read 2026-11-25.
- **Do:**
  1. Skip reserved ports and non-TCP declarations instead of failing, and publish only the lowest 75 TCP ports. Which 75 Render keeps above the ceiling is unverified: lowest-first is the proposal's recommendation under ADR008 Render parity first, not a user decision.
  2. Keep refusing an explicitly configured reserved primary port in the API (`apps/service.go`, `settings_check.go`, `core/config.go`), as Render's web-services page says those ports are "reserved by Render and cannot be used".
  3. Unit tests for each case, and amend ADR089's metadata section and the ADR018 Open ports row (7).
  4. On production, deploy an image with `EXPOSE 19099 8000-8100` in `bex-canary` (disposable): it reaches Live, and its open ports are 8000–8074.
- **Acceptance:**
  - [ ] No `EXPOSE` content fails an image's metadata read; the tests cover reserved, more than 75 and SCTP.
  - [ ] The production check passes, and the fixture is deleted.
  - [ ] ADR089 and ADR018 say what is published and why.
- **Estimate:** ~1h. Tenant-visible deploy behavior, so check the Render parity of the result in the same change.
