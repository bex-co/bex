## The blocker: `deploy.yml` is failing on infrastructure, not on code

Every `deploy (bex via Argo)` run on recent commits is red:

| head                     | result                 |
| ------------------------ | ---------------------- |
| `91067653` (w6/m51 ship) | failure                |
| `096d0ddb`               | failure                |
| `8369fc1b`               | failure                |
| `c913fb5e`               | failure                |
| `666fe8ab`               | cancelled (superseded) |

The failing step is the **opensandbox controller image build**, and it is not a compile error:

```
#15 89.40 fatal error: fault
#15 ERROR: process "/bin/sh -c CGO_ENABLED=0 ... go build ... -o server ./cmd/controller"
          did not complete successfully: exit code: 1
```

`fatal error: fault` is a Go **runtime** crash (SIGSEGV/SIGBUS) inside the build container, not a diagnostic from the compiler about the source. The same run also logged

```
Error: Get "http://%2Fvar%2Frun%2Fdocker.sock/v1.55/containers/buildx_buildkit_builder-.../json":
       context deadline exceeded
```

Both point at the **self-hosted runner** (`/home/docker/actions-runner/...`) rather than at anything in the tree: memory pressure, a sick buildkit daemon, or failing storage on that host. Note every _test_ job on the same commits passes — `test-backend`, `test-operator`, `test-dashboard`, `test-opensandbox-controller`, `secret-scan` are all green. Only the image build on the deploy runner dies.

**First step is therefore an infrastructure check on the runner host, not a code change:** free memory/disk, buildkit/docker daemon health, and whether a `docker builder prune` + runner restart clears it. Only if a clean runner still reproduces the fault is this a toolchain/source problem worth bisecting.

**m51 — still not live-verified, new blocker found (not a bug, a fixture problem).** Redeployed the same service to get past the canceled first deploy and reach a real Live baseline before testing the Start-Command-edit `config_change` path. The build failed instead (`build_failed`, `PodFailurePolicy … exit code 90`): Public Git URL's create form defaults an unrecognized/undetected repo to **Node** (`npm install` / `npm start`) with no actual repo-content inspection to confirm the guess — `bex-acc-hello-go` is a Go project, so `npm install` had nothing to install against and the build died before ever reaching a running container.
