## Objective

A Blueprint consumer's `fromService` `port`/`hostport` must carry the target's real serving port, not the `DefaultPort` that the compiler assumes today. That covers both configured-port targets whose port was edited after creation and image-port targets whose port is only known after build.

## Context

- Blueprint services compile with `Port: 0` (`lego/backend/internal/apps/deploy.go:2659`), so `idx.servicePorts[req.Name]` is always `DefaultPort` (`:2125-2129`).
- `port` resolves at parse through `resolveRef(..., idx.servicePorts, ...)` (`:2336`). `host`/`hostport` defer only the **slug** (`:2310-2320`). `hostRef.env` formats `<slug>:<parse-time port>` (`:610`) in `resolveServiceRefs` (`:1078`) and `patchDeferredStackServices` (`:1054`).
- Live bug on `main`: create a Blueprint web→pserv `hostport` pair, then `PATCH /v1/services/{pserv} port=8080` (w4/m121), then resync. The consumer still holds `<slug>:3000`.
- The mechanism is decided in t001. The recommended one emits a typed reference that the operator resolves (t006), instead of a literal.

## Steps

1. Write a failing test first that reproduces the existing `SetPort` + resync defect. Add another for an image-port target on first apply, which must never produce `:3000`.
2. Replace the parse-time literal with t001's mechanism for both `port` and `hostport`, for declared siblings and existing workspace targets (`hostReferenceProblems`). Keep the w8/081 refusal for unaddressable types.
3. Keep validation, preview and plan honest. A plan shows the reference as pending/`<resolved at deploy>` when the target port is not yet known, and never as `3000`.
4. Reject or name reference cycles that would leave both services waiting, per t001.

## Files

- `lego/backend/internal/apps/deploy.go` and its tests (`blueprint_*_test.go`)
- `lego/types/v1alpha1/app_types.go` if the reference becomes a typed env source (with `make` codegen in `lego/operator`)

## Acceptance criteria

- [ ] The `SetPort` + resync regression passes: the consumer resolves to the edited port.
- [ ] A first apply of an image-port target with a `hostport` consumer writes no `:3000` anywhere: not in the App spec, not in the store, not in the preview.
- [ ] Existing `host` references keep the same slug, and a second unchanged sync is a no-op.
- [ ] A cycle is refused (or surfaced) with a located Blueprint error and zero writes.
- [ ] `apps/schema/capabilities.json` `serviceEnvVarProperty` `"port"`/`"hostport"` cite the new real-port fixture and reason; `render.yaml.json` and `schema.sha256` are unchanged.
- [ ] If the reference is a typed CRD env source: `lego/types` and the regenerated CRD/deepcopy (`make` in `lego/operator`, no drift) are in the same change, and the store round-trips it in a real-Postgres test.
