## Objective

Confirm REST, GraphQL, MCP and the dashboard agree on `openPorts`, `port`, `internalAddress` and the Blueprint reference values. Compare them with Render's documented behavior and record the remaining divergence in the ADRs.

## Steps

1. Compare field presence per service type, values during a port-set replacement, pending/empty states, and error wording across REST, GraphQL, MCP and the dashboard.
2. Check against Render:
   - `openPorts` is required on web/pserv details with `{port, protocol}`;
   - private services may bind up to 75 ports, with 18012/18013/19099 reserved;
   - TCP health checks go to an open port;
   - `fromService` `port`/`hostport` semantics.
3. Update `docs/ADR018-render-parity.md`: the Internal address row, a new `openPorts` note, and the `PORT` row unchanged but cross-linked. Also update ADR049 for reference semantics and ADR089's checkpoint (D3/D4 status). Name the remaining divergences: declared-only discovery, no web detection, no prebuilt or native discovery, no UDP, the 3000 vs 10000 default.
4. File any drift as follow-up board items instead of silently diverging.
