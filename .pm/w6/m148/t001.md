## Objective

ADR089 is still **Proposed**. Before writing code, record the decisions this milestone ships, so the later tasks implement one reviewed contract and don't each invent one.

## Context

- `docs/ADR089-render-container-compatibility.md` D3 (image metadata ports), D4 (addresses and references follow the resolved primary), and the 2026-09-30/10-01 implementation checkpoint. The checkpoint lists the pending items: prebuilt discovery, `fromService` port propagation, and CMS.
- `docs/ADR041-service-addresses.md` has the single-port restriction that ADR089 says it would amend. `docs/ADR022-tenant-isolation.md` "Tenant container hardening" drops `NET_BIND_SERVICE`, so no tenant container can bind below 1024.
- One gate currently covers both features: `configureNewImageCompatibility` / `imageCompatibilityAdmits` (`lego/backend/internal/apps/service.go:2434,2451`). The DB columns are already independent (`0135_app_image_compatibility.up.sql`).
- Today's primary-port rule: 3000 if declared, else the lowest declared port (`lego/operator/internal/controller/image_network.go:72`).
- Blueprint port references are frozen at parse time (`lego/backend/internal/apps/deploy.go:2125-2129,2659,610`).

## Steps

1. **Gate split.** Image-derived ports (`portMode image-v1` / `image-configured-v1`) become the creation default for new Git-built Docker private services in **every** workspace. `containerPolicy image-v1` stays behind `BEX_IMAGE_COMPATIBILITY_WORKSPACES`. Existing services never migrate.
2. **Rollback switch.** Choose one for the new port default. A new env var (for example `BEX_PRIVATE_IMAGE_PORTS=off`) must fail closed on malformed values and must never touch existing rows. Record it in `lego/backend/AGENTS.md`'s env table.
3. **Primary-port rule.** Recommended:
   - an explicit port wins;
   - else 3000 if declared;
   - else the lowest declared port ≥ 1024;
   - with nothing usable, fall back to 3000.

   Ports below 1024 stay out of the primary choice. Decide whether they are still published on the Service (they can never be bound under either policy) or dropped with a diagnosis.
4. **Reference mechanism.** Choose how a `fromService` `port`/`hostport` gets the target's real serving port. Recommended: a typed operator-resolved reference in `App.spec.env`, modeled on the existing `fromDatabase` `SecretKeyRef` wait:
   - the operator resolves it from the target App's `ServicePort()` when it builds the pod template;
   - the consumer waits, with a named reason, while the port is unresolved;
   - the consumer re-rolls when the target's serving primary changes.

   The alternative is the backend reconciler rewriting literal env values. Record the cycle rule (consumer ↔ target) either way.
5. **Docs.** Amend ADR089 (D3/D4 status, gate split, primary rule) and ADR041 (private services may publish multiple ports; the primary drives `internalAddress`). Add a short ADR018 note pointing to t008. If the recommended mechanism is rejected, rewrite t005/t006 before starting them.
