## Objective

Prove the milestone's Definition of done on a real stack: first `dev-6`, then production after `/ship` and the platform deploy. Use a purpose-built multi-port fixture in a non-allowlisted workspace, plus the unchanged ClickHouse Blueprint in the `bex` workspace.

## Context

- The fixture repo path follows w4/m142's precedent: `https://github.com/bex-co/bex`, branch `main`, root `examples/<name>`.
- `bash scripts/dev-env.sh 6 up|status` runs w6's isolated stack (pre-approved). `w6/blocked/m146` records the unstable local CAPD API, so expect to recover it with `scripts/mock-cluster.sh` reprovision if needed.
- ClickHouse source: `render-examples/clickhouse@355817b1d95c1a9f2b088474437593234f4027f4`, identical to `lego/backend/internal/apps/testdata/render-clickhouse/`. `yandex/clickhouse-server:21` is amd64-only, which production nodes are.

## Steps

1. Add `examples/multi-port/` and give it its own `go.mod`:
   - a tiny Go program, non-root, that ignores `$PORT`;
   - HTTP on 8123 returning a marker, and a TCP banner on 9000;
   - Dockerfile `EXPOSE 8123 9000`, plus a `render.yaml` with the private service and a web consumer using `fromService` `hostport` and `port`.

   Shipped examples must pass the Blueprint walk (`lego/backend/internal/apps/blueprint_m102_test.go`) and pin base images by digest (`scripts/image-pin-validate.sh`); see `ac348f31f`.
2. On `dev-6`, run DoD 1–4. Then, after deploy, run them on production in a QA workspace that is not on the allowlist. Capture REST/GraphQL/MCP JSON, the dashboard screenshot, and the pod `securityContext` from the running pod, and run the cross-workspace probes.
3. In the `bex` workspace, deploy the byte-for-byte ClickHouse Blueprint (DoD 5): `/ping` on 8123, `SELECT 1` over native 9000, and `openPorts` 8123/9000/9009 from a peer. Record the resolved image digest. A non-port failure is evidence plus a follow-up, and the milestone moves to `blocked/`.
4. Delete every fixture by exact ID (404 on REST, no App CR) and revoke the QA session.
