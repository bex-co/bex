## Objective

Report the ports a service serves in Render's own shape. A Render-compatible client sees the required `openPorts`, and a bex user sees every private port beside the internal address.

## Context

- Render (`lego/backend/internal/api/openapi/render-public-api-1.json`): `openPorts: serverPort[]` is **required** on `webServiceDetails` and `privateServiceDetails`. `serverPort` is `{port: integer, protocol: "TCP"|"UDP"}`, both required. It is absent on background workers.
- bex: `renderServiceDetails` (`lego/backend/internal/apps/render.go:401`, shared by REST and MCP) publishes `port` (`:409`) and `internalAddress`. `addressablePort` → `App.ServicePort()` (`service.go:4557`). `ActiveImageNetwork()` holds the serving set (`lego/types/v1alpha1/image_network.go`). GraphQL `Service.port` is at `graphql.go:324`.
- Dashboard: `dashboard/src/features/services/components/service-port-row.tsx` shows one editable port. Locales are `features/services/locales/{en,zh}.ts`. Generated types are in `dashboard/src/graphql/`.

## Steps

1. Add `openPorts` for web and private services. For configured-port services it is `[{port: <effective port>, protocol: "TCP"}]`. For image-port services it is the serving network's ports, or the first candidate's before anything has served, following the same rule as `ActiveImageNetwork`. Before discovery it is `[]`, never an invented 3000. Leave it off for every other type.
2. Add GraphQL `Service.openPorts: [ServerPort!]` with the same derivation and an MCP `get_service` read, sharing one helper.
3. Dashboard: on a private service, show the open ports (for example `8123 · 9000 · 9009`) beside the internal address, with the primary marked. Update the port-row hint to say an explicit port selects the primary while the image's other TCP ports stay published. Add en and zh copy, and a skeleton matching the ready geometry (repo rule).
4. Regenerate GraphQL types and keep the OpenAPI response conformance tests green.

- [ ] Response validation against the vendored Render schema passes for `webServiceDetails` / `privateServiceDetails`.
