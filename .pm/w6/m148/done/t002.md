## Objective

A new Git-built Docker private service created in any workspace persists `portMode image-v1` (or `image-configured-v1` with an explicit port) while keeping `containerPolicy` strict. This applies to REST/GraphQL/MCP create, dry-run, and Blueprint apply. Only allowlisted workspaces also get `containerPolicy image-v1`.

## Context

- `configureNewImageCompatibility` (`lego/backend/internal/apps/service.go:2434`) is called from both create paths (`:1989`, `:2289`). `imageCompatibilityAdmits` (`:2451`) is the allowlist.
- `SetPort` (`service.go:4527`) already switches an image-port service to `image-configured-v1`. A strict, configured-port service keeps `configured-v1`.
- Config parsing is `lego/backend/cmd/api/config.go:541,655` (`BEX_IMAGE_COMPATIBILITY_WORKSPACES`, fail-closed).
- Existing tests: `container_policy_test.go` (`TestImageCompatibilityCreationPolicy`, `TestImageCompatibilityIsScopedToListedWorkspaces`, `TestPrivateImagePortRejectsReservedCreationWithoutWrites`) and `lego/backend/internal/store/image_compatibility_test.go`.

## Steps

1. Split the helper into two independent decisions: port mode (default on, subject to t001's rollback switch) and container policy (allowlist only).
2. Keep the reserved-port refusal (18012/18013/19099) before any write for explicit ports in both modes.
3. Wire t001's rollback switch through `config.go` with the same fail-closed parsing style, and document it in `lego/backend/AGENTS.md`.
4. Confirm that Blueprint resync of an existing service never passes through the helper (`TestBlueprintSyncPreservesContainerPolicy`), and extend that test to `portMode`.

- [ ] Web services, workers, cron jobs, static sites, native-runtime services and prebuilt `image:` services are unchanged.
