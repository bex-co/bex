## Objective

From one UTC hour, bill an agent session's sandbox on `sandbox_cpu_seconds` and `sandbox_memory_gb_seconds` at the `sandboxUsage` rates, in every workspace, as w22/m314 did for `/v1/sandboxes`.

## Context

- `lego/backend/internal/pricing/pricing.yaml` `sandboxUsage` (`billedFrom: "2026-11-18T00:00:00Z"`, `usdPerCPUSecond`, `usdPerMemoryGBSecond`) and its comment: both are exported on the `sandbox_compute_seconds` Stripe meter as weighted units that cost the same, because the catalog is at Stripe's 20 items.
- [ADR023 § Sandbox CPU billed on use](../../../docs/ADR023-usage-metering.md#sandbox-cpu-billed-on-use-w22m314-adr104-d8).
- Start only when w22/m314's `sandbox-measure.yml -f leg=usage` run has passed.

## Steps

1. Add the agent cutover instant, a UTC hour boundary after the deploy.
2. From it, an agent sandbox's rows are priced and exported on use; before it, weighted. Nothing is re-priced.

## Files

- `lego/backend/internal/pricing/pricing.yaml`, `lego/backend/internal/pricing/`, `lego/backend/internal/sandbox/meter.go`, `lego/backend/internal/usage/`, the Stripe export

## Acceptance criteria

- [ ] A test across the instant: an hour before it bills weighted, an hour after it bills CPU plus memory, and the Stripe quantity equals the priced amount ÷ `sandbox.usdPerWeightedSecond`.
