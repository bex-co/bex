## Objective

Deploy each template t001 listed, unchanged, with `scripts/render-examples-live.sh` on production. Bring every failure to an outcome: a filed item, an existing open item, or evidence that Render fails the same way.

## Context

- Use the newest `chore(deploy): pin platform images to <sha>` on `origin/main` as the pin, and record it.
- [w6/185](../185.md): anonymous GitHub reads are 60 an hour across every workspace, and m644's run hit `503` after about 25 creates in 35 minutes. Start once w6/185 has shipped. If it is parked instead, run at no more than 20 creates an hour and say so on the page.
- m644 met a free-Postgres conflict with another QA session in `bex-canary`. Render also allows one free database per workspace, so wait for the other session's database to go, or run such templates later.
- Known bex-side classes from m644: w6/183 (`dockerCommand` over 4096 bytes), w6/184 (a service starts before its database is available), w6/186 (a non-root image cannot write its disk). Match new failures to them before filing.

## Steps

1. Run each template one after another and record its result line in the table.
2. For each failure, rerun it with `--keep` if you need the logs, then decide:
   - **a bex gap:** file one note per distinct cause with `/pm add w6 …`, naming the template, the stage, the first error line (other tenants' ids hashed) and what Render does;
   - **an existing item:** link it;
   - **Render fails too:** record the evidence (the template's own issues or PRs, its Render guide, a Render changelog entry).
3. Delete every kept resource when triage is done.
