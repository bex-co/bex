## Objective

Adopt Render's REST contract on the write side: `POST /v1/services` accepts the body `ownerId` it currently documents as ignored (`apps/rest.go:62`), stamping the created App into that workspace via t002's membership-checked override. Sweep the other write paths that resolve the caller's tenant implicitly (env-vars, databases, keyvalues creates — wherever `LabelTenant`/ownership is stamped from `Base.Tenant`) and honor `ownerId` there too, matching Render's "every resource carries `ownerId`" model (research finding 10).

## Context

- `lego/backend/internal/apps/rest.go` (create decode, the "ignored fields" comment at :62), `apps/service.go` create path (stamps `core.LabelTenant`).
- Render's OpenAPI: `ownerId` is required on service creation; bex keeps it optional (absent ⇒ t001's deterministic default) — a documented, backward-compatible softening.
- `lego/backend/internal/postgres/`, `keyvalue/`, `secrets/` — same pattern per feature.

## Steps

1. Decode `ownerId` in the REST create bodies; set the t002 context override before invoking the verb.
2. Return 403 (Render-shaped error) when the caller is not a member of the named workspace.
3. Confirm returned objects carry the effective `ownerId` (render.go:43 already has the field).
4. Table-driven handler tests: explicit member `ownerId`, non-member `ownerId`, absent `ownerId`.
