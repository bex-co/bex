## Objective

Give `core.Base` one seam through which an explicit workspace (REST `ownerId`, GraphQL arg, MCP session selection) overrides the implicit `Workspace.Tenant()` resolution — for `Authorize` (base.go:159), `GetApp`'s tenant gate (base.go:244), and `Tenant` (base.go:221). The override is honored **only after verifying the caller is a member of the named workspace**; a non-member naming a workspace gets `ErrForbidden`, never a silent fall-back to their own workspace (no cross-tenant confused-deputy path).

## Context

- `lego/backend/internal/core/base.go` — `Authorize`/`AuthorizeOn`/`Tenant`/`GetApp`; `WorkspaceResolver` at base.go:102.
- Precedent: `core.WorkspaceSelections` (workspaceselection.go) is already the read-side seam MCP list tools use; `apps/mcp.go:595` `resolveOwnerID` shows the precedence order (explicit > session selection > implicit).
- Likely shape: a context-carried workspace hint (set by adapters), so 80+ verb call sites stay untouched — mirroring how `Identity` already travels.

## Steps

1. Add a context-scoped workspace-override carrier in `core` (setter for adapters, reader in `Base`).
2. In `Authorize`/`Tenant`/`GetApp`: if an override is present, verify membership (via the `WorkspaceResolver`/store seam), then use it; non-member ⇒ `ErrForbidden`.
3. Keep the no-override path byte-identical (now deterministic via t001).
4. Unit tests against a fake resolver: override honored for a member, `ErrForbidden` for a non-member, absent ⇒ implicit resolution.
