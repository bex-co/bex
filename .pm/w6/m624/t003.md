## Objective

kube-apiserver and the kubelets of `bex-tenant-0`, `bex-tenant-xl` and `bex-tenant-xxl` run with `ImageVolume=true` on production (Kubernetes v1.34.9), and each node has rolled onto it.

## Context

- `infra/clusterapi/overlays/hetzner-caph/cluster.yaml` sets `feature-gates: UserNamespacesSupport=true` in these places:
  - the KubeadmControlPlane `bex-control-plane`: its API server's `extraArgs`, and the kubelet args of both its init and join configurations;
  - the KubeadmConfigTemplates `bex-tenant-0`, `bex-tenant-build`, `bex-tenant-xl`, `bex-tenant-xxl` and `bex-platform`.
- Only the first, third and fourth templates run Apps.
- `app-cluster.yml` applies the overlay on push to `main`.
  - A KubeadmControlPlane change rolls the control plane by itself.
  - A MachineDeployment does not re-roll on an in-place template edit, so each pool needs its own `rolloutAfter` (the `82d55f40dd` pattern).
- `scripts/wait-capi-rollout.sh` watches a roll. `scripts/gitops-validate.sh` counts the `UserNamespacesSupport` gates.
- With the operator's setting still off, nothing uses an image volume while the gates roll out. So the gate on the API server before the kubelets is harmless.
- Every disk service on a rolled pool moves once (about 33 s, [w6/173](../done/173.md)). If another roll of these pools is due during the milestone, ride it instead of adding one.

## Steps

1. Control plane first. Add `ImageVolume=true` to the API server's `feature-gates`, and to its kubelets' for a uniform node set. Ship it, run `scripts/wait-capi-rollout.sh`, and read `kubernetes_feature_enabled{name="ImageVolume"}` from the API server's `/metrics`.
2. Then each tenant pool in its own commit: add the gate to its KubeadmConfigTemplate and set its `rolloutAfter`. Wait for each roll, then read the gate from each new node's kubelet `/metrics`.
3. Extend `scripts/gitops-validate.sh` so that a template that runs Apps, or the API server, cannot lose the gate.
4. Run `scripts/verify-substrate.sh`, and record each roll's commit and result in this task.

## Acceptance criteria

- [ ] The API server and every node in the three tenant pools report `kubernetes_feature_enabled{name="ImageVolume"} 1`.
- [ ] `scripts/gitops-validate.sh` fails when the gate is removed from any of them.

## Out of scope

- The build, platform and sandbox pools, which run no App.
- The Kubernetes v1.35 upgrade, where the gate is on by default.
