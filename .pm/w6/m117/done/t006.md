## Objective

Cover the case the existing suite structurally cannot see: a CNPG read that fails.

## Context

- `listBackups`' doc comment names the blind spot outright — "Best-effort: an unavailable CNPG CRD (e.g. envtest) yields an empty list." Every existing test runs in exactly that condition, so an empty list is the expected value everywhere and the production failure is invisible.
- The four states to pin: backups readable and present; readable and genuinely empty; unreadable; plan has backups disabled.

## Steps

1. Add a test where the Cluster `Get` fails and assert the response is distinguishable from the healthy-empty one.
2. Same for a failing Backup `List`.
3. Assert `latestRecoveryTime` is absent in the unreadable case and present in the healthy one.
4. Assert `Recover` refuses before any billing gate or resource creation when the window is unsubstantiated.
5. Keep a healthy-empty control that still passes unchanged.
6. Confirm the new tests fail with t002 reverted.
