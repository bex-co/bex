## Objective

`resumeService` returns `200` on an auto-hibernated service, reports `phase: "Hibernated"`, and changes nothing. Make Resume bring back a service that is scaled to zero, whatever scaled it — or refuse honestly.

## Context

Live, on the auto-hibernated private service (`srv-da85ueoueu1c7395is8g`):

```
mutation { resumeService(id:"…"){ id phase suspended } }
=> {"data":{"resumeService":{"phase":"Hibernated","suspended":"not_suspended"}}}
45s later: phase=Hibernated, instances=0
```

- The cause is structural, not a bug in Resume's own logic: auto-hibernation scales to zero **without** setting `spec.suspended` (`parkKubernetes:1862-1866` — "so manual-suspend semantics are preserved"), and Resume clears `spec.suspended`. There is nothing to clear, so it is a correct no-op — and the wrong answer for the user, because Resume is the control someone presses when their service is down.
- The response is what makes it a defect rather than a limitation: it returns success and echoes `Hibernated`, so a caller cannot tell that nothing happened. Compare the product's own standard elsewhere — `errNoPublicIngress` refuses with the type and the reason.
- This is independent of `t001`: even after private-service sleep is settled, a **web_service** can be auto-hibernated, and a user pressing Resume on it deserves the same honesty. Whether Resume currently no-ops there too is listed as unverified and is step 1.

## Steps

1. Reproduce on an auto-hibernated **web_service** as well — the activator would wake it on the next request, which may mask the no-op. Establish whether Resume is a no-op there too before choosing the fix's scope.
2. Decide the target behavior: either Resume clears the auto-hibernation (stamping `last-active` so `shouldAutoHibernate` stops firing, which is the direct analogue of what a wake request does), or it refuses with a message naming why the service is at zero. Do not leave it returning success while doing nothing.
3. If Resume becomes a wake, make sure it cannot fight the idle loop — a resume immediately followed by the TTL re-expiring would flap.
4. Keep explicit-suspend Resume byte-identical.
