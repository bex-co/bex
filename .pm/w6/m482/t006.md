## Objective

Show on production that a deploy restarting the gateway keeps an open SSH session and an open dashboard Shell session.

## Context

- Gate: a production pin whose producer contains this milestone's commit (`git log origin/main --grep "pin platform images"`, then `git merge-base --is-ancestor <commit> <producer>`). The pin with the change rolls the gateway onto it; the deploy after it is the first to drain.
- Production access: `scripts/fetch-app-kubeconfig.sh` with `BEX_SSH_KNOWN_HOSTS_FILE` pointing at a temp file holding `* <key>` from `~/.ssh/bex_cp_host_ed25519.pub` (w3/m472). Signed-in API calls go through `bash scripts/qa-login.sh`.
- SSH needs a paid service: use a Starter fixture in `bex-canary` and delete it by id afterwards.

## Steps

1. Before a deploy that restarts the gateway, open `bex ssh <srv>` running a loop that prints a counter, and a dashboard Shell on the same service doing the same.
2. Across the deploy, record the gateway pods (old ones Terminating, new ones Ready), and that both loops keep printing.
3. Open a new SSH session during the drain and confirm it lands on a new pod (gateway logs).
4. Close both sessions; confirm the old pods exit.
5. Delete the fixture (`GET` answers 404).
