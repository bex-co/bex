## Objective

The native Dockerfile generator gives every native runtime with a root directory `/opt/render/project/src/<rootDir>` as its `WORKDIR`, and every consumer keyed to `nativeWorkdir` follows t001's layout.

## Context

- `lego/operator/internal/build/native.go` `nativeSourceDir`, `nativeGoSourceDir` (segment validation to reuse), `nativePythonVenv`, `nativeBuildDefaults`
- `lego/operator/internal/build/depscache.go` (`nativeDependencyDirs`, the seed and save), `nativestaticdeps.go` (publish check), `lego/operator/internal/publish/publish.go` (extract)
- `lego/operator/cmd/native-init/secretfiles.go` (links into its working directory)
- `lego/operator/internal/build/nativesourcedir_test.go` (m546's tests, including the monorepo case)

## Steps

1. Give every non-Go native runtime `nativeWorkdir + "/" + <rootDir>` when it has a safe root directory, validated as `nativeGoSourceDir` validates its segments; an unsafe one keeps `nativeWorkdir`.
2. Move the virtualenv, Rust's `target`, Elixir's `deps`/`_build` and, if t001 says so, a static site's build directory and publish check. Keep the dependency cache keyed so an existing cache still seeds, or record why it misses once.
3. Confirm native-init's secret-file links and the extract follow the `WORKDIR` with no change, or move them.
4. Unit tests: each runtime with a root directory, with none (byte-identical to before), an unsafe root directory, a static site, and Go unchanged.

## Files

- lego/operator/internal/build/native.go, depscache.go, nativestaticdeps.go and their tests; lego/operator/internal/publish/publish.go if needed

## Acceptance criteria

- [ ] The generated Dockerfiles follow t001's layout; with no root directory, and for Go, they are byte-identical to before
- [ ] `make test` and `make lint` pass

## Out of scope

- The existing-disk mechanism (t003)
- Buildpack and Docker-runtime services

## Record (2026-11-21)

- `nativeSourceDir(o)` (`lego/operator/internal/build/native.go`) gives a static site `nativeRootDir(o.RootDir)`. For a service it calls `NativeSourceDir(runtime, repo, rootDir)`, exported for the operator's disk mounts (t003). Every runtime but Go gets `/opt/render/project/src/<rootDir>`, and Go keeps m546's GOPATH directory. The root directory is cleaned as the build context is (`repoRelative`). None, `.`, `/` or a part outside `nativeSourceSegment` keeps `/opt/render/project/src`. m546's segment check is now `nativeSourceParts`, shared by both directories.
- `nativeSourceLink` links only a directory outside `/opt/render/project/src`, which is Go's. The new directory sits inside, so no other runtime gets a link.
- **Consumers.**
  - The Python virtualenv stays at `nativePythonVenv`, per t001's Render evidence, so its dependency cache key is unchanged.
  - Rust's `target` and Elixir's `deps`/`_build` move to `nativeSourceDependencyDirs` under the working directory (`depscache.go`). Each misses the cache once for a service with a root directory, since the seed discards the old paths.
  - The publish check is `nativePublishCheck(dir)`, built from `nativePublishCheckHead` + dir + `nativePublishCheckTail`. The build-log parser (`buildkitNativeRunStep`, `nativeCommandFailure` through `cutPublishCheck`, `build.go`) reads it from any directory.
  - The publish Job's extract and native-init's secret-file links follow the `WORKDIR` with no change.
- **Byte-identical check.** Every runtime's Dockerfile was generated from `HEAD`'s package (`git archive`) and from the working tree, for root directories `""`, `.`, `/`, `backend`, `apps/api`, `my app` and `a\b`, as a service, a build source and a static site, with and without the dependency cache: 252 files. Only `backend` and `apps/api` differ, for every runtime but Go and for Go static sites. In those, only the `WORKDIR`, the Rust/Elixir dependency paths and the publish check's `cd` change. A Go service, and anything with no or an unsafe root directory, is byte-identical.
- **Tests:** `TestNativeRootDirectoryIsTheWorkdir` and `TestNativeRootDirectoryKeepsItsDependencyDirectories` (`nativesourcedir_test.go`). `TestNativeBuildLogNamesAMissingPublishDirectory` and `TestNativeStaticBuildCommandFailureIsNotAPublishFailure` now also run with a root directory. `go test ./internal/build` passes.
