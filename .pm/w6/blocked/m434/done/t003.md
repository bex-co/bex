## Objective

Prove t001 and t002 against the real Muse host, then ship t001–t003 to the adapter's `main`.

## Context

- `src/tests/async-tasks-live.test.ts` already drives workflow cards on a real host with `src/tests/loopback-provider.ts`, so no paid API is involved.
- A new `*-live.test.ts` must be added to the explicit list in `test:muse-loopback` (`package.json:53`).
- CI runs the loopback suites on Muse 1.1.1-R2514.1, where gated suites may skip, and on 1.4.14-R7309.1, where every gated suite is required.
- Run the suites locally with `MUSE_CODE_ACP_REQUIRE_MUSE=1 MUSE_CODE_ACP_REQUIRE_HOST_FEATURES=all npm run test:muse-loopback`, against a 1.4.14 binary set in `MUSE_CODE_EXECUTABLE`.

## Steps

1. Script the loopback model to call `workflow`, then end its turn. Assert three things: the prompt stays pending; the reporting turn's text arrives as `session/update` before the prompt resolves; and no card reports an unknown outcome.
2. Do the same for a `bash` command that outlasts a short `yield_time_ms`, so Muse sends it to the background.
3. Gate the test on the host's feature detection in `src/muse-host.ts`, so 1.1.1 skips it.
4. Ship t001–t003 with the adapter's `ship` skill. Its required CI must pass.

## Done (2026-11-16)

`src/tests/background-hold-live.test.ts` is in `test:muse-loopback` and gated on the `background-wakes` host feature (`supportsBackgroundWakes`, Muse 1.4.14 and newer). It holds a prompt across a workflow and across a `bash` past its `yield_time_ms`.

- Locally on 1.4.14-R7309.1 (macOS arm64) it passes, and with the hold removed it fails (`expected -1 to be greater than …`).
- The full loopback suite passed locally with `MUSE_CODE_ACP_REQUIRE_HOST_FEATURES=all`: 25 files, 74 tests.
- Adapter CI run 43977123219 on `0e38f27` is green. The 1.4.14 leg ran both tests and the 1.1.1 leg skipped them.
- The same test then failed twice in the v0.12.0 publish run (see t004). The cause is the card-ordering flaw fixed in `8ad6672`. `2ab66a2` widens the fixture ordering test, which under load matched only `tool_call_update`, to accept the completed `tool_call` the client may see first.
