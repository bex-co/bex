## Objective

One Hetzner dedicated server (the planned AX42-1 or the user's chosen replacement) exists in fsn1 and exposes `/dev/kvm`. It is attached to a Robot vSwitch that is coupled to CAPH's `bex` Cloud Network as a vSwitch subnet, and it is registered as a `HetznerBareMetalHost`. This is the only step that spends money ($119–$304 a month plus a one-off setup fee, depending on the server; ADR105 § What can be ordered today, since AX42-1 was out of stock on 2026-11-12), plus the vSwitch, and it needs the account owner.

## Context

- ADR105 § Decision step 1, § Known limits and § What joining the cluster takes.
- Every cluster-internal path rides `bex` (`10.10.0.0/16`, cloud subnet `10.10.0.0/24`). The network is CAPH-owned and treated as immutable (`infra/clusterapi/overlays/hetzner-caph/cluster.yaml`, `HetznerCluster.spec.hcloudNetwork`).
- A vSwitch VLAN interface is limited to MTU 1400 (Hetzner vSwitch docs).
- Robot credentials are not in the repo. `docs/ADR019-infra-credentials.md` owns where they go. The `hetzner` Secret already has `robot-user` and `robot-password` keys reserved for bare metal.
- The AX42-1 was out of stock on 2026-11-12 (`-LTD` only), so the user chose AX42-1 (ADR105 § What can be ordered today).

## Steps

1. The account owner orders one AX42-1 in fsn1, creates Robot webservice credentials, and creates a vSwitch with the server attached.
2. Store the Robot credentials per ADR019, never in git.
3. Add a vSwitch subnet to the `bex` network inside `10.10.0.0/16`, without overlapping `10.10.0.0/24`. Then confirm that CAPH's reconcile leaves it in place across a `HetznerCluster` resync. If CAPH removes it, stop and bring it to the user.
4. Name the server in Robot with the hostname it will join under, so the CCM can match it.
5. On the rescue system, confirm that `/dev/kvm` exists, that the CPU flags include `vmx`, and which NIC name carries the public address and the VLAN.
6. Add the `HetznerBareMetalHost` for the server.

## Acceptance criteria

- [ ] `ls -l /dev/kvm` succeeds on the server.
- [ ] The vSwitch subnet is in the `bex` network and is still there after a CAPH reconcile.
- [ ] From the rescue system, a VLAN address pings a cloud node's private IP.
- [ ] The `HetznerBareMetalHost` reports available in the management cluster.
- [ ] No Robot credential is committed.
