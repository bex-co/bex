## Objective

The AX42-1 is a Ready node whose InternalIP is its vSwitch address. Pods on it reach pods on cloud nodes and the reverse, `kubectl exec` and `logs` work, and from the internet only SSH answers on its public address.

## Context

- ADR105 § What joining the cluster takes.
- `.github/workflows/app-cluster.yml`:
  - the CCM runs without Robot support and with `networking.enabled=true`;
  - Cilium is in tunnel mode with WireGuard, and `devices` and `direct-routing-device` are pinned cluster-wide to `enp7s0`.
- hcloud CCM Robot docs:
  - Robot support needs `robot.enabled=true` and `robot-user` / `robot-password` in the CCM secret.
  - The node is matched by `hrobot://` provider ID or by hostname equal to the Robot name.
  - vSwitch IPs are not reported; the kubelet's `--node-ip` is forwarded as the InternalIP.
  - For private networks, the guide sets `networking.enabled: false` and passes `HCLOUD_NETWORK` directly.
- `infra/terraform/main.tf`, `bex-app-nodes`: cloud nodes expose only SSH and ICMP publicly. Cloud Firewalls do not cover dedicated servers, and VXLAN on `:8472` is unauthenticated.
- In production, CAPH's CSR controller approves kubelet-serving certificates, and the API server verifies them (ADR063, ADR072 #5).

## Steps

1. Enable CCM Robot support in `app-cluster.yml` following the private-networks guide. Confirm that cloud nodes and the edge LB are unchanged.
2. Set the kubelet's `--node-ip` to the vSwitch address and configure the VLAN interface at MTU 1400 in bootstrap.
3. Add a `CiliumNodeConfig` for the node with its VLAN interface as `devices` and `direct-routing-device`.
4. Test the MTU in both directions: a full-size do-not-fragment ping and a 10 MB pod-to-pod transfer between the AX42-1 and a cloud node. If large packets drop, bring the plan to lower Cilium's MTU cluster-wide to the user before applying it.
5. In bootstrap, drop all inbound traffic on the public interface except SSH, ICMP and established flows, using host nftables. Add the Robot firewall as a second layer.
6. Keep the hcloud-csi node plugin off the node.

## Acceptance criteria

- [ ] The node is Ready and has no `node.cloudprovider.kubernetes.io/uninitialized` taint. Its InternalIP is the vSwitch address and its provider ID is `hrobot://…`.
- [ ] The kubelet-serving CSR is approved, and `kubectl exec` and `kubectl logs` work on a Pod on the node.
- [ ] Pod-to-pod traffic works both ways with a 10 MB payload.
- [ ] A scan of the public IP from outside finds only 22/tcp. 8472/udp, 10250/tcp and the NodePorts do not answer.
- [ ] Every DaemonSet on the node is Ready or excluded on purpose, and no crash-loop alert fires.
