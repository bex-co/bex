## Objective

The AX42-1 carries pinned, digest-verified Kata Containers and runsc, installed before kubeadm joins. It has one containerd handler per candidate VMM plus `runsc`, the sandbox labels, and a trial taint that no sandbox template tolerates.

## Context

- `sandbox-pool.yaml` is the model to follow:
  - the runtime is installed at bootstrap, because an in-place containerd restart breaks the Cilium datapath;
  - digests are pinned in the repo (codex-security round 18);
  - the join is gated (w9/074).
- kata-deploy restarts containerd on a live node, so it is not used.
- Kata sizes each VM as `default_memory` (2048 MiB by default) plus the container limit (ADR105 § Inputs). Set `default_memory` small and `sandbox_cgroup_only = true`.
- Candidate VMMs: Cloud Hypervisor and QEMU over virtio-fs. Install Firecracker (devmapper) only if t006 is going to measure it (ADR105 § What the first weeks must also answer).
- runsc on this node uses the same `overlay2 = "none"` as the cloud pool, so pause and resume stay correct (ADR042 D5).

## Steps

1. Install the Kata static release and runsc with digests pinned in the repo. Register the `kata-clh`, `kata-qemu` and `runsc` handlers, and gate the join on all of them.
2. Label the node `bex.co/pool=sandbox`, `bex.co/sandbox=true` and `bex.co/sandbox-runtime=kata`. Taint it `bex.co/sandbox=true:NoSchedule` and with the trial taint `bex.co/metal-trial=true:NoSchedule`.
3. Extend `scripts/capi-sandbox-bootstrap.test.sh` and `scripts/clusterapi-validate.sh` for the Kata gate.
