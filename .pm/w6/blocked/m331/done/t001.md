## Objective

The four ADR105 probes and the routine replay are one script, and they have been run in an idle agent sandbox on today's `cx33` sandbox node. That separates the cost of gVisor as bex configures it from the CPU contention in the original probe. No money is spent, and nothing waits on the account owner.

## Context

- ADR105 § Context: the original probe ran beside three builds on a shared-vCPU node. `overlay2 = "none"` (ADR042 D5) sends every file operation through the gofer.
- The live pool uses `bex-sandbox-cx33` (`infra/clusterapi/overlays/hetzner-caph/sandbox-pool.yaml`). Node CPU and steal time come from node-exporter in Grafana, because gVisor virtualises `/proc/stat` inside the sandbox.
- The replay stands in for `rt-unify-duplicates` as the gate measure (ADR105 § Decision step 3). It runs a fresh clone, then `go build ./...` and `go vet ./...` in `lego/`, one module's `go test`, and the dashboard `tsc`, from a cold module and build cache, with each step timed.

## Steps

1. Write `scripts/sandbox-probe.sh`. It runs the four probes (300 process starts, 3,000 file reads, 2,000 file creates, a 200 MB sequential write) and the replay, and prints one line of timings per step.
2. Run it in an agent sandbox with no other session on the node. Record the node's CPU use and steal time for the run.
3. Record the table in ADR105 § Context beside the original numbers.
