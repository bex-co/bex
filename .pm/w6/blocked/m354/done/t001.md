## Objective

The sandbox pool runs one cpx42 (8 vCPU / 16 GB) in the empty `tenant-large` placement group, with kubelet reservations, replacing the `cx33`.

## Done 2026-11-13

- `infra/clusterapi/overlays/hetzner-caph/sandbox-pool.yaml`: new `HCloudMachineTemplate` `bex-sandbox-cpx42`; the `bex-sandbox` KubeadmConfigTemplate gains `system-reserved` cpu=500m,memory=1Gi, `kube-reserved` cpu=500m,memory=512Mi and `eviction-hard` memory.available<512Mi; the MachineDeployment points at the cpx42 template.
- Applied out of band after `capi-template-drift.sh` reported no drift and the server-side dry run passed; the MachineDeployment's `infrastructureRef` was patched live. CAPI's default rollout added the new machine first and removed the `cx33` once the new node was Ready.
- `bex-sandbox-mzp4j-htm8z`: cpx42, kernel `6.8.0-149-generic`, Ready at 00:02:45 UTC. Capacity 8 CPU / 15.2 GiB, allocatable 7 CPU / 13.2 GiB. A `runtimeClassName: gvisor` pod on it reported `4.19.0-gvisor`.
- The old node ran only system pods when the roll started, so no sandbox ended.
