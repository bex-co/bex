## Objective

A full build of this repository in an agent sandbox outgrew the namespace LimitRange's 10Gi ephemeral storage default and was evicted (t005 run 1).

- Both agent templates set `EphemeralStorage: 30Gi` (under the LimitRange's 32Gi max). bex-api sends it in OpenSandbox's `resourceLimits` map, which the server passes to the container as is, with a quarter (floor 1Gi) as the request. The base template keeps the LimitRange default.
- The gateway's `targetTermination` no longer lets the kubelet's synthetic `ContainerStatusUnknown` exit 137 hide an eviction: a real recorded termination (OOMKilled, an exit) still wins, and otherwise a Failed Pod's `Evicted` is reported, as `EvictedEphemeralStorage` when the kubelet's fixed wording says the Pod exceeded its ephemeral storage limit (node disk pressure stays `Evicted`). A session's failure reason then reads "the sandbox ran out of disk space (it wrote more than its ephemeral storage limit)".

## Done when

A new agent sandbox on production has a 30Gi ephemeral storage limit, and a routine run completes without eviction (t005).
