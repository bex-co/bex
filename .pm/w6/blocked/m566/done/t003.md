## Objective

From one UTC hour, bill an agent session's sandbox on `sandbox_cpu_seconds` and `sandbox_memory_gb_seconds` at the `sandboxUsage` rates, in every workspace, as w22/m314 did for `/v1/sandboxes`.

## Context

- `lego/backend/internal/pricing/pricing.yaml` `sandboxUsage` (`billedFrom: "2026-11-18T00:00:00Z"`, `usdPerCPUSecond`, `usdPerMemoryGBSecond`) and its comment: both are exported on the `sandbox_compute_seconds` Stripe meter as weighted units that cost the same, because the catalog is at Stripe's 20 items.
- [ADR023 § Sandbox CPU billed on use](../../../../docs/ADR023-usage-metering.md#sandbox-cpu-billed-on-use-w22m314-adr104-d8).
- Start only when w22/m314's `sandbox-measure.yml -f leg=usage` run has passed.

## Steps

1. Add the agent cutover instant, a UTC hour boundary after the deploy.
2. From it, an agent sandbox's rows are priced and exported on use; before it, weighted. Nothing is re-priced.

## Files

- `lego/backend/internal/pricing/pricing.yaml`, `lego/backend/internal/pricing/`, `lego/backend/internal/sandbox/meter.go`, `lego/backend/internal/usage/`, the Stripe export

## Acceptance criteria

- [x] A test across the instant: an hour before it bills weighted, an hour after it bills CPU plus memory, and the Stripe quantity equals the priced amount ÷ `sandbox.usdPerWeightedSecond`.

## Done (2026-11-24, `b8510dadf2`)

- **The instant.** `sandboxUsage.agentBilledFrom: "2026-11-26T00:00:00Z"`, a UTC hour boundary about a day after the push, so a deploy lands before it. The sheet refuses one that is not on the hour, not RFC 3339, or before `billedFrom`. `PGStore.AgentSandboxUsageBilledFrom` is set from it in `cmd/api/main.go`.
- **The meter.** `sandboxUsageSwitch` gives each sandbox its switch, `billedFrom` or `agentBilledFrom`. From an agent sandbox's switch the cursor writes no weighted chunk, and its CPU and memory rows are written unmarked (`sandboxUsageUnbilled`). The reads and the export needed no change: an unmarked row after `billedFrom` is priced and exported on use (weighted units on the `sandbox_compute_seconds` Stripe meter).
- **A late deploy.** If production ran the old binary past the instant, that binary kept billing weighted and marking CPU and memory: nothing is double billed, and the switch hour's rows keep the old marks.
- **Tests.**
  - `TestAgentSandboxUsageSwitchPG` covers the rows, the outbox, the month's read and settle's exported totals across the instant.
  - `TestStripeMeterEventMapping` covers an agent sandbox's CPU and memory before the instant (skipped) and from it (563,128.49 and 4,279,776.54 weighted units for 600 CPU-seconds and 8 GiB-hours, the priced amount ÷ the weighted rate).
  - `TestSandboxUsageSwitchInstant` and `TestEstimateSandboxBilledOnUse` cover the instant itself.
