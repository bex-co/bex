## Objective

On the local CAPD cluster, with an operator built from this tree, show the three behaviors: a binary-change roll lets a mid-command client get its reply, an idle client is closed no earlier than the grace period, and enabling internal authentication still closes a held unauthenticated client within seconds.

## Context

- `bash scripts/mock-cluster.sh operator` builds `bex-operator:dev` and deploys it. w6/m469 t003 (`.pm/w6/done/m469/done/t003.md`) forced a binary change locally and held clients through the proxy. Reuse its method.
- The default user cannot run `DEBUG SLEEP` (`-@admin`). Use a blocking command as the mid-command client, for example `BLPOP k 20` with a value pushed from a second client after the roll began, or with the timeout expiring after `SIGTERM`.
- The internal-auth check is the w6/m463 t003 check.

## Steps

1. Create a free store and hold three clients through `<id>:6379`: one blocked in `BLPOP`, one idle, and one unauthenticated idle client on a second store.
2. Deploy a build whose `/kv-internal-proxy` differs. Record the roll's times, the `BLPOP` reply, and when the idle client was closed relative to the old pod's `SIGTERM`.
3. Enable internal authentication on the second store and record how long the held unauthenticated client lasts. A new unauthenticated client must read `-NOAUTH`.
4. Clean up the stores.

## Acceptance criteria

- [x] The `BLPOP` client read its reply after the old pod got `SIGTERM`.
- [x] The idle client closed at the grace period, not before.
- [x] The unauthenticated client closed within seconds of enabling internal authentication, and a new one read `-NOAUTH`.

## Result — 2026-11-19 (local CAPD cluster)

Method as in w6/m469 t003, with each build tagged distinctly through `BEX_OPERATOR_IMG=bex-operator:m512-<x> bash scripts/mock-cluster.sh operator`:

- **Build A** was this tree plus a throwaway `log.Print` in `cmd/kv-internal-proxy`. It was reverted as soon as the image was built and never committed.
- **Build B** is the clean tree, so deploying it is a `/kv-internal-proxy` binary change.
- **The probes** were the free stores `red-m512probea` and `red-m512probeb` (`persistenceMode: "off"`, `app.bex.co/workspace` set to the namespace) in dev-6's tenant namespace `tea-dbtf3l1jg4ra1r0m4ur0`.
- **The clients** were restricted `valkey/valkey:8.1` pods, each holding bash `/dev/tcp` connections through `<id>:6379` and logging every read with millisecond timestamps.

On build A both proxies ran `bex-operator:m512-a` with `BEX_KV_DRAIN_SECONDS=30` and `terminationGracePeriodSeconds: 35`. Pod `m512-client` held three connections from 11:55:57Z:

- a `BLPOP m512 0` on probe a (`CLIENT ID` 17);
- an idle connection on probe a (16);
- an unauthenticated idle connection on probe b (14).

**The binary-change roll (build B, deployed 11:57Z).** Probe a's proxy rolled once, from ReplicaSet `-586b9b455f` to `-57575db9db`, onto `m512-b`:

| time (Z) | event |
| --- | --- |
| 11:57:59 | the old pod `-crzc7` got `SIGTERM` (`Killing`; deletionTimestamp 11:58:34 minus the 35 s grace) |
| 11:58:03.3 | `RPUSH m512 v` through `red-m512probea`, which now selects only the new pod |
| 11:58:03.529 | **the `BLPOP` client read `*2 m512 v` through the old pod**, 4.5 s after its `SIGTERM` |
| 11:58:29.951 | **the idle client read EOF**, 30.9 s after `SIGTERM`, and so did the `BLPOP` connection, which was still open |
| 11:58:30 | the old pod was gone |

Probe b's proxy did the same: `SIGTERM` at 11:58:01, and its unauthenticated idle client read EOF at 11:58:31.842 (+30.8 s).

**Enabling internal authentication (probe b, proxy on the drain-capable `m512-b`).** Pod `m512-client2` held an unauthenticated connection (`CLIENT ID` 110) from 11:58:52.981. Then:

- **11:58:55:** the `spec.internalAuth: true` patch.
- **11:58:56:** the old pod `-6jlll` got `SIGTERM`.
- **11:58:56.956: the held client read EOF**, under 2 s after the patch, rather than at the 30 s deadline.
- The old pod showed `Completed` a second later, because its drain ended with its last stream.

A new unauthenticated client read `-NOAUTH Authentication required.`. Valkey kept StatefulSet generation 1 and revision `-78bc847988`, its 11:55:36Z start and restart counts `0 0`, and the store stayed Ready.

**Cleanup.** Both stores and both client pods were deleted, and no `m512` object is left in the namespace. The shared cluster's operator was left on `bex-operator:m512-b`, this milestone's code, until the next `mock-cluster.sh operator`.

**Seen on the way, not changed here.** Each proxy Deployment write logs the namespace's PodSecurity warning that the `internal-proxy` container does not set `runAsNonRoot`. `execution.RestrictedContainerSecurityContext` has never set it, and the warning predates this milestone.
