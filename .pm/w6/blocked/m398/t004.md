## Objective

On production, start a QA session with a long turn, delete its sandbox Pod mid-turn, and read the transcript on REST and the session page.

## Acceptance criteria

- [ ] The transcript holds the turn's parts up to about 30 s before the kill, and reads truncated with the reason.

## Run 2026-11-16 (production, QA user, workspace tian-personal; deploy `3c6654df6` and later)

- **The mechanism works.** Session `ags-dbtgogbu1inc739f8tug`: its turn-2 sandbox Pod was deleted at 14:03:44Z. Within 8 s the session read `failed` with `sandbox terminated before completion`. The turn kept the 12 items its running harvest stored at 14:03:08Z (steps 2–5), and reads `transcriptTruncated: true` with that reason on REST and GraphQL. The session page shows the prompt, "Some assistant output could not be preserved: sandbox terminated before completion", steps 2–5, then "Session failed".
- **The bound failed: it kept nothing after 14:01:45Z, almost 2 minutes before the kill.** The driver's turn log (`lego/agent-image/driver/src/turn-log.ts`) held parts in a 64 KiB buffer, written only when full or at close. In session `ags-dbtgkukc5bcc73fvh9e0`, parts 0–135 (13:51:59–13:55:11Z) reached `session.jsonl` only at 13:55:11Z, and parts 136–235 only at the turn's end. That run's harvests also showed no duplicates: 24 items while it ran, then 20 more at the finish, 44 in all, each part index once. The one-minute harvest lease (w4/677) adds up to a minute more.
- **Fix (shipped with this record).** The turn log writes each buffered part within 5 s (`flushDelayMs`; tests in `test/hotpath-baseline.test.ts` fail without it), and the running harvest runs every 30 s (`liveTranscriptInterval`). ADR051 records both.
- **Remaining.** After the next production deploy carries the fix (deploy.yml builds the agent image and bex-api), re-run this check. Accept when the last stored item ends within about 30–45 s of the kill.
- Cleanup: both QA sessions deleted (404), their sandboxes gone, both QA Kratos sessions logged out.

## Run 2026-11-17 (production, QA user, workspace tian-personal; pin `fc4fbf28a`)

- **The bound holds.** Session `ags-dbu92gogt2jc73djdvpg` ran one repo-less turn of 40 timed steps (`sleep 6; date -u; echo qa-step-N`). Its sandbox Pod was deleted at 17:42:42Z, when the driver log in the sandbox had reached step 26 (17:42:34Z). The session read `failed` at 17:42:54Z with `sandbox terminated before completion`. Its last stored item is step 23, printed at 17:42:18Z and written at 17:42:19Z: 23 s before the kill. Steps 24–26, the last 23 s, were lost.
- **No duplicates.** The running harvest stored items at 17:40:09, 17:40:39, 17:41:24 … 17:42:24Z, 48 items in all, each turn/partIndex once.
- **REST and GraphQL** return the 48 items with turn 1 `transcriptTruncated: true`, `truncationReason: "sandbox terminated before completion"`. **The session page** shows the prompt, "Some assistant output could not be preserved: sandbox terminated before completion", steps 1–23, then "Session failed".
- **MCP failed.** `get_agent_session_transcript` answered `validating tool output: … /properties/parts/items/properties/part: type: map[…] has type "object", want one of "null, array"`. The SDK inferred the part's `json.RawMessage` as a byte array, so the call failed for every transcript with a part, not just this one. `get_agent_session` read the session as `failed`.
- **Fix (shipped with this record).** `mcputil.AddTool` gives a `json.RawMessage` the schema of any JSON value (`lego/backend/internal/mcputil/mcputil.go`). `TestMCPTranscriptReturnsItsParts` fails with the production error without it. `TestMCPSchemasHaveNoByteArrays` checks every served tool for a byte-array schema, and only this tool's part had one.
- **Remaining.** After a production deploy carries the fix, read `get_agent_session_transcript` for `ags-dbu92gogt2jc73djdvpg` over MCP as the QA user. Accept when it returns the 48 parts and turn 1 truncated with the reason. Then delete that session (kept for this read, its sandbox is gone).
- Cleanup: the QA Kratos session was logged out.
