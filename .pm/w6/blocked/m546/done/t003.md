## Objective

Every way a Go service runs a process starts in the new directory, as on Render.

## Context

- The start command, pre-deploy Job, cron run and initial deploy hook take the image's `WORKDIR` unless the operator sets `workingDir`; Shell and SSH sessions (`lego/backend` ssh-gateway exec) start where the container does.
- Search `lego/` for `/opt/render/project/src` and `workingDir` to find any hard-coded copy.

## Steps

1. Find every place that sets or assumes the working directory for these processes and move it to the per-service directory.
2. Check the Shell and SSH start directory on dev-6 with a Go fixture.

## Files

- lego/operator/internal/controller (pre-deploy, cron), lego/backend ssh-gateway exec, as found

## Acceptance criteria

- [ ] On dev-6, `pwd` in the start command, a pre-deploy command, a cron run, Shell and SSH prints Render's Go path
- [ ] `make test`, `make lint` and `cd lego/backend && go test ./...` pass

## Out of scope

- Non-Go runtimes

## Record (2026-11-21)

- **No code change was needed.** No container in `lego/` sets `workingDir` (`grep -rn 'WorkingDir\|workingDir' lego --include='*.go'` finds none). So the service's Deployment, the pre-deploy Job, cron runs and a build source's linked services all start in the image's `WORKDIR`.
- Shell and SSH run `/bin/sh` or `/bin/sh -lc <command>` through the kubelet exec (`lego/backend/internal/sshgateway/nativessh/session.go:105-129`, `webshell/websocket.go:469`) with no `cd`, so they start in the container's working directory. A login shell's `/etc/profile` does not change directory. `native-init` (`cmd/native-init/secretfiles.go`) links secret files into its working directory, so they follow too.
- **Deviation:** the `pwd` checks moved from dev-6 to production (t005). This machine's Docker daemon had not answered `/_ping` for about two hours, with other sessions' `docker rm` calls hung since then, and the local kind cluster refused connections, so neither a dev-6 stack nor a local image build could run. The old-layout fixture already shows `pwd` from its start command and its pre-deploy command, and t005 adds the Shell, SSH and cron checks.
