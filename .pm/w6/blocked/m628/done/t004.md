## Objective

Write a script that lists bex's Stripe Customers (by `bex_workspace` metadata) whose name is still their `tea-` id and renames each to its workspace's display name. It dry-runs by default and never touches a Customer without that metadata.

## Context

- The Stripe account is shared with other products, so the metadata filter is the boundary.
- The live run writes the shared account; if the agent is refused it, as in [w2/070](../../../../w2/blocked/070.md), park the task on the user's run with the exact command.
- The script reads its own key; never pass a key through the agent's context.

## Files

- scripts/

## Acceptance criteria

- [x] A live-flagged run renamed them, and its count (no names) is in the milestone README; the test-mode dry run is [t009](../t009.md)'s.

## Done (2026-11-25)

- `scripts/stripe-customer-names.py` (tests: `scripts/test_stripe_customer_names.py`, run by `backend-test.yml`) reads the workspaces' names from the control-plane database and the Customers through the `stripe` CLI's own key; it only ever considers a Customer tagged `bex_workspace`, dry-runs by default and prints ids, never names, unless `--show-names`.
- Live run, 2026-11-25, against the production database: 139 Customers on the shared account, 16 of them bex's. 2 were still named by their `tea-` id and `--apply` renamed them; 3 retired ones were skipped, 2 whose workspace's only name is its id were left, and 9 kept their own name (see [w6/180](../../180.md)). A re-run lists none to rename.
- The test-mode dry run moved to [t009](../t009.md), which waits for a test-mode key.
