## Objective

Add meaningful tests for what this milestone shipped. Cover the image-volume projection for every kind of probe that carries the helper (Health Check Path, any open port, drain). Cover the lazy adoption in both directions (setting on, setting off), the pre-pull of the volume's reference and the gate check in `scripts/gitops-validate.sh`.

## Acceptance criteria

- [ ] Each test fails when the behavior it covers is reverted.
- [ ] `make test`, `make lint` and the script's own test pass.

## Done (2026-11-24), ahead of t005

- **Projection, every kind of helper:** `TestHealthProbeImageVolumeReplacesTheInstaller` covers a Health Check Path, the any-open-port check and the drain-only TCP service, each with the setting on (image volume, no init container, the bex-health directory read-only at `/bex-health`, every probe and preStop exec of the mounted helper) and off (the installer), plus a worker and an operator without its own image (no helper).
- **Lazy adoption, both directions:** `TestHealthProbeImageVolumeIsAdoptedOnTheNextRollNotOnUpgrade` turns the setting on and off over web, disk and TCP-drain services, with and without a new operator image, and checks that the next restart adopts the current form and image. Forcing `imageVolumeStale` false, or not keeping `healthProbeImageVolume` in the kept params, fails it.
- **Pre-pull:** `TestDiskPrePullPullsTheHelpersImageVolume`. Dropping image volumes from `podImages` fails it.
- **The API server's view:** the envtest "Health-probe helper from an image volume (w6/m624)" stores the projection on kube-apiserver v1.37, reads it back unchanged and re-applies it without a write.
- **The gate check:** `scripts/clusterapi-validate.test.sh` proves `bex-tenant-0` without the gate, with `ImageVolume=false`, and a serving pool (`bex-tenant-xxl`) without it, red. The control-plane sites' red cases return with the control-plane gate (t003).
- `make test`, `make lint` and the self-test pass.
