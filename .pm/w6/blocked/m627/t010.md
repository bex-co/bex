## Objective

Hold the definition of done's Stripe test-mode bullet against a real test-mode Customer, and bring bex's test-mode portal configuration in line with the live one.

## Context

- Gate: a Stripe test-mode restricted key `rk_test_…` from the user, the same key [w6/m625](../m625/README.md) t004 and [w6/m626](../m626/README.md) t001 and t004 wait for: in `.env` as `BEX_TEST_STRIPE_KEY`, and for a dev-6 bex-api as `BEX_STRIPE_SECRET_KEY` with a test webhook endpoint and `BEX_STRIPE_DUNNING_ENABLED=1`. - The code is on main: `notifications.billingRecipients`, `billing.StripeClient.SetCustomerEmail`, and the store-backed test `TestABillingNoticeReachesTheStoredBillingEmailOnce`.

## Steps

1. With the test-mode CLI context, run `python3 scripts/stripe-billing-setup.py --portal-only --dashboard-url <the dev dashboard's HTTPS origin>`, then `--check-portal`: it must answer `matches`.
2. On a dev-6 bex-api with the test key, make a Pro workspace with an admin and set its billing email to a Mailpit address of its own through the Billing page; check the test-mode Customer's `email` is that address.
3. Fail its invoice with a declining test card so the workspace enters grace, let the notice worker run, and read Mailpit: the grace notice reaches the admin and the billing email, once each. Restart the worker and confirm no second copy.
4. Downgrade it to Hobby and check the Customer's `email` is the owner's account email again.

## Acceptance criteria

- [ ] The test-mode portal configuration answers `matches` to `--check-portal`.
- [ ] The grace notice of a Pro workspace with a billing email of its own reaches that address once, beside its admin, in Stripe test mode.
- [ ] The Customer's email follows the billing email, and returns to the owner's on a downgrade.
