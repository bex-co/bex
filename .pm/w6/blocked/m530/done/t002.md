## Objective

A small binary in the operator image that serves t001's answer for the pods of its own node, deployed as a DaemonSet on every node that runs tenant App pods, with `hostPID` as its only privilege and the operator as its only client.

## Context

- Entry points live in `lego/operator/cmd/` and ship in the one operator image (`lego/Dockerfile`). `cmd/egress-meter` is the nearest shape: a node agent with `/healthz` and `/readyz`.
- Placement: tenant App pods run on the untainted `tenant-0` pool, the serving pools (taint `bex.co/serving-pool`) and the sandbox pool (taint `bex.co/sandbox`). `config/egress-meter/daemonset.yaml` already tolerates exactly that set; copy it, and keep both in step. On production that is 8 nodes today (7 `tenant-0` and 1 sandbox). The platform, control-plane and build-only (`burst`, `lg`) nodes run no tenant App.
- `bex-system` enforces PodSecurity `privileged`, so the per-pod securityContext is the only control: `scripts/lib/platform-pod-hardening-guard.yq` (via `scripts/gitops-validate.sh`) requires pod `runAsNonRoot: true` and seccomp `RuntimeDefault`, and per container `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, `drop: [ALL]`. The reader passes it with `hostPID` added.
- New components are registered in `scripts/image-pin-validate.sh` (the `controller:latest` allowlist row, like egress-meter's) and `config/default/kustomization.yaml`. A DaemonSet on the `controller` image rolls on every platform pin; while a node's reader rolls, t003 must not fall back to a sweep. Consider its own pin held while the binary is unchanged, as w6/m470 gave the SNI proxies (`deploy/gitops/base/bex.yaml`, `scripts/gitops-validate.sh` `operator_pins`), and write the choice here.
- Existing ingress rules in `bex-system` are NetworkPolicies, for example `allow-apiserver-to-operator-webhooks` (selects `control-plane: controller-manager`).

## Steps

1. `cmd/listener-reader` (name it as you see fit): `GET /v1/listeners?pod=<uid>&ip=<ip>` answers `{"ports":[…]}`; 404 when no process of that pod is on this node, 409 when its namespace does not hold that IP, 400 for a malformed UID or IP. Nothing else is served besides health. Bounded request time, `ReadHeaderTimeout`, no request body, a small concurrency cap.
2. `config/listener-reader/`: DaemonSet (`hostPID: true`, no `hostNetwork`, no hostPath, `automountServiceAccountToken: false`, uid 65532, `drop: [ALL]`, read-only root, seccomp `RuntimeDefault`, small requests and limits, `priorityClassName` as egress-meter, its tolerations), its ServiceAccount with no RBAC, and a NetworkPolicy that admits only the operator pod (`control-plane: controller-manager`) on its port. Add it to `config/default`.
3. `scripts/gitops-validate.sh`: pin that the reader has `hostPID` and no other host namespace, no capability, no hostPath, no token, and its NetworkPolicy. Register it in `scripts/image-pin-validate.sh`.
4. Unit-test the handler over a fake procfs (t001's fixtures): each status code, and that the answer carries ports only.

## Record (2026-11-20)

- **Binary:** `cmd/listener-reader` (built into the one image, `lego/Dockerfile`) serves `listeners.Handler("/proc")` on `:9097`: `GET /v1/listeners?pod=<uid>&ip=<ip>` answers `{"ports":[…]}` (an empty list, never null), 400 for a malformed UID, IP, body or repeated parameter, 404 when no process of the pod is on the node, 409 when its namespace lacks the IP, 503 when four reads are in flight past the 5 s read bound, 500 (logged) when the tables are unreadable. Error bodies are the sentinel text only, never a path or PID. `/healthz`; `/readyz` reads `/proc/1/cgroup`. It refuses to start as PID 1 (no `hostPID`). Timeouts: `ReadHeaderTimeout` 5 s, read 10 s, write 15 s, 8 KiB headers.
- **Manifests:** `config/listener-reader/` holds the DaemonSet (`hostPID` only; uid/gid 65532, `runAsNonRoot`, seccomp `RuntimeDefault`, `drop: [ALL]`, read-only root, `allowPrivilegeEscalation: false`, no volume, `automountServiceAccountToken: false`, `enableServiceLinks: false`, egress-meter's two tolerations, `system-node-critical`, 5m/16Mi requests and 100m/64Mi limits, `maxSurge: 1, maxUnavailable: 0`). It also holds a token-less ServiceAccount with no RBAC, and NetworkPolicy `listener-reader`, which admits only `control-plane: controller-manager` on TCP 9097. bex-system's `deny-tenant-ingress` now selects every pod but the reader (`app.bex.co/component NotIn [listener-reader]`), because policies add up and selecting it there would admit all of bex-system, traefik and monitoring. For every existing pod the selection is unchanged.
- **Deviation: not yet in `config/default`.** Argo applies `config/` at the push, but the image moves only with the pin (`lego/operator/AGENTS.md` § Manifest arguments ship after their binary). Listed now, the DaemonSet would run the pinned image, which has no `/listener-reader`, and crash-loop on every tenant node (`PlatformPodCrashLooping`) until a pin carried it. Ship 1 carries the binary, the operator's client, the manifests and every guard. The one line `- ../listener-reader` in `config/default/kustomization.yaml` ships once production's pin carries ship 1 (the milestone's gate). Until then the new operator finds no reader on any node and sweeps exactly as before, counted.
- **Guards:** `scripts/gitops-validate.sh` pins the privilege set whole (hostPID true; no hostNetwork, hostIPC, volume, token, capability, privilege, mount or root, in containers and init containers), the token-less ServiceAccount, no RBAC naming the reader, egress-meter's tolerations with no nodeSelector or affinity, and the hardening guard over the reader's own render (so it holds before `config/default` lists it). The w6/m6 lockdown check accepts one non-empty `deny-tenant-ingress` selector, bex-system's exact reader exclusion, and only while the reader's policy isolates it to the operator on 9097. Each of 14 mutations (hostNetwork, hostIPC, a hostPath, a token, `SYS_PTRACE`, privileged, root in the pod or the container, hostPID off, an init container with `SYS_ADMIN`, a namespace-wide or wrong-port or extra ingress rule, no policyTypes) turned its check red. `scripts/image-pin-validate.sh` has the `controller:latest` row. `scripts/gitops-validate.sh`, `scripts/image-pin-validate.sh`, `make test` and `make lint` pass.
- **Pin choice: the controller pin, no pin of its own.** The reader holds no host state, no tenant traffic and no client connection worth keeping: a roll costs one pod start per node, and the surge keeps a Ready reader on every node throughout, so the operator never falls back during one. Moving with the operator also keeps the reader's one HTTP contract in the same image as its client. The SNI proxies' held pins (w6/m470) exist to keep external streams open, which the reader has none of.
- **Local finding fixed:** `scripts/mock-cluster.sh` re-applied a bare `bex-system` Namespace after `make deploy` (`create --dry-run=client | apply`), and the client-side apply dropped the `pod-security.kubernetes.io/enforce: privileged` label `config/manager/manager.yaml` sets. The cluster's default `baseline` then refused the reader's `hostPID` (and egress-meter's capabilities, whose second pod had been failing the same way). It now creates `bex-system` only when it is missing; `scripts/mock-cluster.test.sh` checks both cases and failed with the old line.
