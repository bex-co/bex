## Objective

Check that `resume` and Open in Zed behave the same on REST, GraphQL, MCP and the dashboard (same fields, semantics, error shapes), and compare with Devin's observable behavior for a sleeping session. File any drift as follow-up work.

## Result (2026-11-22)

REST (`POST /v1/agent-sessions` with `resumeSessionId`), GraphQL `resumeAgentSession` and MCP `resume_agent_session` all call one `Service.Resume`, so they return the same `View` and the same coded errors; capabilities' `sshEnabled` is one struct field on REST and MCP and a GraphQL field (golden and schema updated); the dashboard uses the GraphQL verb. Against Devin: opening a sleeping session's workspace wakes it, and so does Open in Zed here; a message during the wake waits, as a Devin message to a waking session does. Drift filed: w6/168 (`git push` from the editor once the start settles is refused by the live-phase mint allowlist, where a Devin machine pushes) and w6/169 (the CLI's `bex agent ssh`/`bex desktop` do not resume a closed session). Checked in code and tests before the production deploy; t004 is the live check.
