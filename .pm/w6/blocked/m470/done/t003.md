## Objective

The digest write-back pins `controller=` to the new operator digest as today. For each SNI proxy it keeps the current pin when t001's command finds its binary byte-identical in the new image, and pins the new digest otherwise. The PROXY-protocol wait then expects, per DaemonSet, the digest that was pinned for it.

## Context

- "pin image digests in GitOps (write-back)" (`.github/workflows/deploy.yml`): `deploy-superseded.sh`, an inline Python check that each generated field is the only difference, `git rebase origin/main`, one `sed` per pin, a `grep -qF` per pin, then the `[skip ci]` commit. The decision must read the pins after the rebase, which is what Argo will sync.
- The whole workflow is one concurrency group (`bex-production-deploy`), so no other run pins between this run's build and its write-back; only a human commit to `bex.yaml` could.
- "wait for PROXY-compatible datastore proxies" waits for `BEX_EXPECTED_PROXY_IMAGE` (the new operator digest) on both DaemonSets, then `rollout status`. `infra.yml` waits for this workflow before it enables PROXY protocol on the edge. A held image runs a byte-identical binary, so it is as PROXY-capable as the new one.
- `scripts/gitops-validate.sh` greps `deploy.yml` for the wait step's literal lines. `scripts/deploy-superseded.sh` and the inline check each require exactly one generated field per file; `bex.yaml` now has three.
- The deploy job has no Go yet; the build job's `actions/setup-go` step (`go-version-file: lego/go.work`) shows the pinned action.

## Steps

1. In the deploy job, set up Go before the write-back. After `git rebase origin/main`, for each of `kv-sni-proxy` and `pg-sni-proxy`, read its current digest from `bex.yaml`, run t001's command for `linux/amd64` against `${OP_DIGEST}`, and `sed` the pin to its answer. A failed run of the command (compile, network) pins `${OP_DIGEST}`; it never fails the step.
2. Export each pinned digest (`$GITHUB_ENV` or a step output) and log `kept` or `moved` with its reason.
3. Extend the `grep -qF` checks and the `git diff --quiet` / `git add` path list to the new lines (same file).
4. Teach both generated-field checks (`deploy-superseded.sh` and the inline Python) that `bex.yaml` carries three generated digests, each matched exactly once. Add `deploy-superseded.test.sh` cases: an SNI pin moved alone is a digest-only change (exit 1), and a renamed SNI pin is a reshape (exit 0).
5. Make the wait step expect each DaemonSet's own pinned digest, and update the literal lines `gitops-validate.sh` requires.
6. Comment the step: why the SNI pins are held, what any doubt does, and that a held image runs the same bytes.

## Record (2026-11-18)

- `scripts/operator-pins.sh write <bex.yaml> <image> <digest>` pins `controller=` as before. For each SNI pin it runs the built `proxy-pin` for `linux/amd64` and keeps the current digest only when the command answers it; every other answer (no command, a failed or missing one, the candidate, a third digest, garbage) pins the new digest. A missing, repeated, tag-held or renamed pin line fails the step, as a reshape. It logs `kept`/`moved` per proxy (proxy-pin's own reason precedes it) and appends `KV_SNI_PROXY_IMAGE` / `PG_SNI_PROXY_IMAGE` to `$GITHUB_ENV`.
- `deploy.yml`: the deploy job sets up Go from `lego/operator/go.mod` (`cache: false`) and builds `cmd/proxy-pin` from the run's own commit before the write-back, both `continue-on-error`. The write-back calls the script after `git rebase origin/main`, so it reads the pins Argo will sync. `bex.yaml` was already in the `git diff --quiet` / `git add` list.
- `scripts/deploy-superseded.sh` and the write-back's inline check take a tuple of patterns per file; `bex.yaml` has three, each matched exactly once. New `deploy-superseded.test.sh` cases: controller moved with both SNI pins held, and one SNI pin moved alone, are digest-only (exit 1); an SNI pin renamed, removed, repeated or moved to another image is a reshape (exit 0); other `bex.yaml` drift is a manifest change (exit 4). The inline check was run from the workflow text against a scratch repository: an SNI-digest-only change passes, an extra line refuses.
- `scripts/operator-pins.sh wait` (the "wait for PROXY-compatible datastore proxies" step) expects each DaemonSet's own pinned image, then its rollout; an empty pin fails at once. `scripts/gitops-validate.sh` now requires the two script calls in `deploy.yml` and the wait's literals in the script; `scripts.yml` runs `scripts/operator-pins.test.sh`, and `gitops.yml` triggers on the script.
- `scripts/operator-pins.test.sh` (fake proxy-pin and kubectl): kept changes only `controller=`; moved, failing, missing or odd answers change all three; mixed answers hold only the identical proxy; a re-run on pinned digests reads nothing; a bootstrap tag still pins; six reshapes fail; a held DaemonSet's wait returns at once and awaits both rollouts; a moved one returns after Argo syncs; a held one that Argo moved to the new digest, a moved one that never arrives, and a missing DaemonSet each time out naming the DaemonSet.
- `bash scripts/deploy-superseded.test.sh`, `bash scripts/operator-pins.test.sh`, `bash scripts/gitops-validate.sh` and `bash scripts/github-actions-validate.sh` pass.
