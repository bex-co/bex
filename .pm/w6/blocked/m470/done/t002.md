## Objective

`bex-kv-sni-proxy` and `bex-pg-sni-proxy` get their image from their own kustomize pin instead of `controller=`, so `deploy.yml` can move them separately. The commit that introduces the pins renders exactly today's image for both DaemonSets, so Argo's first sync rolls neither.

## Context

- Both DaemonSets use `image: controller:latest` (`lego/operator/config/{kv,pg}-sni-proxy/daemonset.yaml`). Argo deploys `lego/operator/config/prod` with `kustomize.images: [controller=ghcr.io/bex-co/bex-operator@sha256:…]` (`deploy/gitops/base/bex.yaml`); the local overlay inherits that list.
- `config/prod` builds `../default` first, so a placeholder must reach it untouched (README § Findings, kustomize trap). `config/default`'s own `images:` maps only `controller`.
- Local deploys: `make deploy` / `make build-installer` copy `config/deploy/kustomization.yaml` beside `config/default` and run `kustomize edit set image controller=${IMG}` (`lego/operator/Makefile`); `scripts/mock-cluster.sh operator` uses `make deploy IMG=bex-operator:dev`.
- `scripts/image-pin-validate.sh` exempts each placeholder by exact file and reference.

## Steps

1. Give each DaemonSet its own placeholder (`kv-sni-proxy:latest`, `pg-sni-proxy:latest`). Add no `config/default` entry that maps them to `controller`.
2. Add `- kv-sni-proxy=ghcr.io/bex-co/bex-operator@sha256:<D>` and `- pg-sni-proxy=…@sha256:<D>` under `controller=` in `deploy/gitops/base/bex.yaml`, where `<D>` is the `controller=` digest on `origin/main` when this ships. Explain them in the file's header comment.
3. Make `config/deploy/kustomization.yaml` and both Makefile targets set all three images to `${IMG}`, so local deploys behave as before.
4. Replace the two `controller:latest` exemption rows in `scripts/image-pin-validate.sh` with the new placeholders and reasons.
