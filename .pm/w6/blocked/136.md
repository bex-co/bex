# The edge load balancer admits external datastore clients up to the largest plans' limits

Why: after w6/m457 no SNI proxy cap is below a datastore's limit. The edge load balancer still caps every external connection at 10,000, fewer than a Key Value `pro_plus` (10,000), `pro_max` (20,000) or pooled Postgres URL (30,000 under w6/m458) holds on Render.

- **Evidence (2026-11-17):** Hetzner `GET /v1/load_balancer_types` reads `lb11` `max_connections` 10,000, `lb21` 20,000 and `lb31` 40,000. `bex-traefik` is `lb11` with `round_robin` over five listeners: 22, 80, 443, 5432 and 6379. So HTTP, HTTPS and SSH share the 10,000 with every external Postgres and Valkey client. Terraform: `infra/terraform/main.tf` `hcloud_load_balancer.traefik`.
- **What bex does at the cap:** past `max_connections` the load balancer takes no new connection, so a client past it reads a network error, not the datastore's refusal. Hetzner documents the figure, not what the client reads, and it was not measured: filling production's edge would drop every site's new connections too. Each SNI proxy replica admits 4,096 (`BEX_PROXY_MAX_CONNS`, `BEX_KV_PROXY_MAX_CONNS`, memory limit 512 Mi; [ADR009 § External connection admission](../../../docs/ADR009-postgresql-management.md#external-connection-admission-w6m457-2026-11-17)). With three replicas that covers the load balancer's 10,000 but no more, so a larger load balancer also needs larger replica caps and memory limits.
- **Decision needed (user, cost):** move the edge to `lb21` or `lb31`, or sign off the 10,000 ceiling as an ADR018 divergence. ADR009 recorded a larger load balancer at +€14/month when it declined a sixth listener (port 6432, 2026-11-10).
- **Done when:** either a `pro_max` store accepts 20,000 concurrent external TLS clients on production, with the replicas' caps and memory raised to match, or ADR018 records the ceiling with the user's sign-off.

## Parked 2026-11-17 (`/loopx w6`): the user's cost decision

Nothing is left that bex can settle without spending money. The only code change, larger proxy caps and memory limits, does nothing below a larger load balancer, and its size depends on which one is chosen, so it ships with the type change.

**Measured on 2026-11-17** (no money spent):

- **Prices** (Hetzner `GET /v1/load_balancer_types`, `fsn1`, per month, 20 TB traffic included on each): `lb11` €7.89, `lb21` €24.89, `lb31` €49.89. Moving to `lb21` now costs +€17.00 a month, not the +€14 recorded on 2026-11-10. `lb11` also allows only 5 listeners, all in use; `lb21` allows 15 and `lb31` 30.
- **Edge use** (`GET /v1/load_balancers/7115248/metrics?type=open_connections`): over 30 days the median is 49 open connections and the peak 128 at Hetzner's 86-minute averages. The highest point at a finer step is 409 (2026-11-15 13:11Z, 8.6-minute averages over 3 days), 4% of `lb11`. Web traffic shares it directly: of the 31 production Ingress hostnames, 25 resolve straight to the edge's IPv4 and only the 6 Cloudflare-proxied ones reach it through pooled origin connections, so most web clients each hold an edge connection of their own.
- **Production datastores** (`kubectl get databases,keyvalues`): 5 Postgres databases (3 `basic-256mb`, 2 `basic-1gb`), none pooled and none with replicas, and 3 Key Value stores, all `starter`. Their limits add up to 1,250 connections, so nothing a tenant runs today can reach the ceiling.
- **Plans past the ceiling that bex sells:** Key Value `pro_plus` (10,000, $140/month), `pro_max` (20,000, $245/month), and any paid database with pooling (PgBouncer `max_client_conn` 30,000). `pro_ultra` (40,000) and `50g` (50,000) are paused (`INSTANCE_TYPE_UNAVAILABLE`). `50g`'s 50,000 is more than `lb31`, Hetzner's largest type, so serving it would take a second load balancer under any option.
- **Proxy sizing.** The proxies run as DaemonSets on the three `cx33` platform nodes, and 5432 and 6379 are spread over those three, so one node takes at most a third of the edge's connections. At the measured 95 KB per idle connection (ADR009), `lb21` puts up to 6,667 connections on one node, about 635 MB, and `lb31` up to 13,334, about 1.3 GB. Only the limits rise and the requests stay, so no node is added. One platform node (`bex-platform-k9wb4-dpjxh`) already uses 5.5 GB of its 7.8 GB, so promising `lb31`'s worst case on it may also take a `cx43` (€9.99 → €18.49, +€8.50 a month).

**What Render does.** Render sells one connection limit per plan and documents no separate cap on external connections ([compute plans](https://render.com/docs/compute-plans), read 2026-11-17, as cited in ADR009). A `pro_max` store takes 20,000 external clients, and the next one reads Valkey's own refusal. Render's web edge publishes no connection cap either.

The worker's read: only B meets this note's "done when" for every plan bex sells today. A meets it for `pro_plus` and leaves a `pro_max` store a few hundred connections short at today's traffic. With no production store above `starter` and an edge peak of 409, no tenant today is affected by any of the four.
