## Objective

`cmd/kv-sni-proxy` and `cmd/pg-sni-proxy` drain on their first `SIGTERM` or `SIGINT` for a bound read from the environment, then exit as soon as no stream is open. A second signal closes everything at once. With the variable unset or `0`, they close at once, as today. A malformed value refuses to start.

## Context

- Both mains build their context from `ctrl.SetupSignalHandler()`, which cancels on the first signal and exits the process on the second. The manager stops with that context, and the listener is closed from the same goroutine.
- Env names follow each proxy's prefix: `BEX_KV_PROXY_*` for `kv-sni-proxy`, `BEX_PROXY_*` for `pg-sni-proxy` (`lego/operator/AGENTS.md`). For example `BEX_KV_PROXY_DRAIN_SECONDS` and `BEX_PROXY_DRAIN_SECONDS`, whole seconds as `BEX_KV_DRAIN_SECONDS` (w6/m512).
- `sniproxy.EnvDuration` and `EnvInt` log and fall back on a bad value. A drain bound should fail closed instead, as `kv-internal-proxy`'s `drainSeconds` does.
- Keep the metrics listener up while draining, so the old pod's relayed bytes are still scraped.

## Steps

1. Parse the drain bound in each main, failing startup on a negative or non-numeric value.
2. On the first signal, close the listener and start t001's drain. On the second, close everything. Exit when the drain returns.
3. If the manager exits on its own (no signal), keep today's behavior.

## Progress (2026-11-19, implemented and verified locally; in stash `loopx/w6/m515`, not on `main`)

- **Signals.** Each main keeps `ctrl.SetupSignalHandler()` as `stopping`. The manager and the cache sync run on it, so the first `SIGTERM` or `SIGINT` stops the manager, which freezes the routing table, and the same signal starts the drain (`Drain{Start: stopping.Done()}`). controller-runtime exits the process on a second signal, which closes everything at once.
  - Serve's own context is the hard stop. Only a manager that exits on its own, with no signal, or a failed metrics listener cancels it. Both stopped Serve at once before this change too.
  - The metrics listener stays up until `main` returns, so a draining pod is still scraped. The SNI jobs use pod discovery every 15 s, and a terminating pod is still discovered.
- **Env.** `BEX_KV_PROXY_DRAIN_SECONDS` and `BEX_PROXY_DRAIN_SECONDS` (`drainSecondsEnv` in each main) are read by `sniproxy.DrainSeconds`. That takes whole seconds, zero included, and treats unset as zero, which closes at once as before. A negative, fractional, suffixed or overflowing value is an error naming the variable, and the proxy exits 1 (`TestDrainSecondsIsWholeSecondsAndFailsClosed`).
- **Tests.**
  - `cmd/kv-sni-proxy/drain_test.go`: an external TLS client blocked in `BLPOP` through `handleConn` reads the store's reply written after the drain began. A new dial is refused, and Serve returns once the client leaves.
  - `cmd/pg-sni-proxy/drain_test.go`: the same for a libpq-preamble client in a long query.
  - `TestTheDaemonSetGivesTheDrainItsBound`, one per proxy (t003).
- **Deviation.** The real-signal path is proven on the local cluster (t004), not in a unit test. `main` needs a kube API, and `SetupSignalHandler` can only be called once per process. A cancelled context stands in for the signal in the `cmd` tests.
- `make test` and `make lint` pass (README § Park record).
