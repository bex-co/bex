## Objective

A Blueprint that gives a service both a `disk` and `maxShutdownDelaySeconds` fails validation by field path before anything is written.

## Context

- `lego/backend/internal/apps/blueprint_plan.go:81` (`maxShutdownDelaySeconds`, preserved on omission) and `:270` (apply); the Blueprint validator's per-field errors.
- A Blueprint that adds a disk to a service whose live delay is custom, and omits the field: t004's attach rule applies.

## Steps

1. Refuse both fields on one service at validate, with the field path.
2. Make plan and apply refuse the same input (no partial write).
3. Tests for both-present, disk-only on a custom-delay service, and delay-only.

## Record (2026-11-21)

Done. `validateManifestServiceFields` (`deploy.go`) refuses an entry declaring both `disk` and `maxShutdownDelaySeconds`, at any value, as Render's validator does (t001). It runs at parse, so validate, plan and apply refuse the file before any write. `blueprintErrorField` (`blueprint.go`) maps the sentence to `.maxShutdownDelaySeconds`, so validate answers `service "<name>": max shutdown delay is not supported for services with a disk` at `services[i].maxShutdownDelaySeconds`. On an existing service, `probeBlueprintServiceSpec` (`blueprint_plan.go`) refuses a declared delay when the service it leaves has a disk (one attached outside the file), at path `maxShutdownDelaySeconds`. A file that adds a disk and omits the delay is t004's reset.

Tests: `TestBlueprintRefusesADiskWithAShutdownDelay` (30 and 120: the path and sentence, the sync refused, no App written; each half alone is valid), `TestBlueprintSyncKeepsADiskServicesDefaultShutdownDelay`. `TestCreateOwnedSpecFieldParity`'s manual probe, which declares every field beside a disk, no longer declares the delay; its scaling probe still covers the field. The backend suite passes.
