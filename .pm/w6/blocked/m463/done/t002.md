## Objective

A store with `spec.internalAuth` keeps its `<id>-internal` proxy, in t001's plain passthrough mode, and its stable `<id>` Service (ports 6379 and, when public, 6380) routes through it. Enabling internal authentication on a running store switches the proxy's mode in a proxy rollout, which drops the connections that used the unauthenticated URL, and restarts no Valkey pod.

## Context

- `reconcileKeyValueInternalRoute` and `retireKeyValueInternalProxy` (`lego/operator/internal/controller/keyvalue_internal_proxy.go`) delete the proxy Deployment, the `<id>-backend` Service and the two proxy NetworkPolicies (`keyvalue_internal_network.go`) when `spec.internalAuth` is set.
- `reconcileKeyValueService` (`keyvalue_controller.go`) selects the Valkey pods for an internal-auth store (`!kv.Spec.InternalAuth && …`).
- `keyValueInternalProxyReady` returns true at once for an internal-auth store, so readiness never waits on a proxy.
- `keyValueBackupHost` (`keyvalue_backup.go`) dials `<id>` for an internal-auth store; it must dial `<id>-backend` so the snapshot uses the reserve.
- `kvinternalauth.Serve` closes every accepted stream on cancellation, so the old proxy pod's unauthenticated connections close when the rollout terminates it. During the surge (`maxSurge: 1`) the old pod still serves; note how long a new unauthenticated connection could still be accepted there.
- `status.internalAuthOptional` and the connection Secret's credentialed URL (`keyvalue_controller.go`, w5/m268) keep their current behavior.
- A store that enabled internal auth before this change (none on production, m456 t002) has no proxy: `<id>` must switch to the passthrough proxy only once it is ready, as w8/204's cutover does.

## Steps

1. Reconcile the proxy for internal-auth stores in passthrough mode instead of retiring it; drop `retireKeyValueInternalProxy` if nothing else needs it.
2. Route `<id>` through the proxy once it is ready, and keep `<id>` on the proxy through later proxy rollouts.
3. Point the backup snapshot at `<id>-backend` for every proxied store.
4. Make the mode switch the only thing enabling internal auth rolls; assert the Valkey StatefulSet template is unchanged.
5. envtest: an internal-auth store's `<id>` selects the proxy; the proxy Deployment has the passthrough env and no injected-AUTH listener; enabling internal auth on a proxied store leaves the StatefulSet's template and generation unchanged; the backup CronJob dials `<id>-backend`; a pre-change internal-auth store adopts the proxy without a window where `<id>` has no endpoint.

## Result — 2026-11-17

- `reconcileKeyValueInternalRoute` reconciles the proxy for every store, and `retireKeyValueInternalProxy` is gone. The proxy of a store with `spec.internalAuth` carries `BEX_KV_INTERNAL_AUTH=client`. The env var is set only then, so the operator upgrade changes no other proxy's template.
- `reconcileKeyValueService` routes `<id>` through the proxy for every store once the proxy is ready, and keeps it there (the w8/204 cutover). `status.internalAuthOptional` stays false for an internal-auth store.
- `keyValueInternalProxyReady` waits on the proxy for every store, so enabling internal auth reads `config_restart` while the proxy rolls. Render documents a restart for this control ("it will be unavailable for a few seconds", [Key Value](https://render.com/docs/key-value), read 2026-11-17).
- `keyValueBackupHost` dials `<id>-backend` whenever a proxy fronts the store.
- **The surge window.** The old proxy pod keeps serving until the new one is Ready. On the local cluster that was 2.8 s after the patch (t003), and the connections it accepted closed with it.
- Tests, each failing against its reverted change: `TestKeyValueInternalAuthKeepsTheProxyRoute`, `TestKeyValueInternalAuthStoreAdoptsTheProxyOnceReady`, `TestEnablingInternalAuthRollsOnlyTheProxy` (a full reconcile with the fake client: the StatefulSet spec is unchanged, `<id>` stays on the proxy, the backup dials `<id>-backend`), and `TestKeyValueBackupSnapshotBypassesTheTenantBudget`. The envtest suite has no proxy image configured, so these use the fake client, as the existing proxy tests do.
- `make test` and `make lint` (all four modules) pass. Comments in `lego/types` (`KeyValueSpec.InternalAuth`, regenerated into the CRD) and `lego/backend` (`EnableInternalAuth`) now describe the shipped design.
