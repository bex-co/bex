# Run the render-v1 migration and admission dry-runs against production

Why: w6/m149's live acceptance covered everything reachable through the product. Two checks need production cluster access this session does not have.

- **Migration:** `kubectl -n bex-system exec deploy/bex-api -- /api migrate-container-policy <srv-id>` on one existing strict-v1 service: the dry run writes nothing, `--apply` rolls it exactly once onto render-v1, and a rerun is a no-op (unit-tested by `TestMigrateContainerPolicy*`).
- **Admission:** server-side dry-runs as the operator identity: a render-v1 workload adding a capability outside its set, and one using a foreign Localhost profile, are both refused (envtest-tested on a real API server).
- **Gate:** production kubeconfig access.
