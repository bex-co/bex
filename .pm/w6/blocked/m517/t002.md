## Objective

A commit can roll every store's proxy onto the current template on the next pass, for a security fix or for a held template that no longer works. It does so by bumping a constant that is reviewed like any code. A test pins the rendered proxy template, so any commit that changes the rendering fails until its author updates the pin and decides whether to bump the constant.

## Context

- t001's hold, and the inputs record on the Deployment's metadata.
- The hold makes a rendering change reach a store only on its next customer change. An author must know that, and choose the override when it is not acceptable.
- No runtime switch: an env var or flag would be an unreviewed production lever, and the manager restarts on every deploy anyway.

## Steps

1. Add `kvInternalProxyRollRevision` (an int, starting at 1) beside `kvInternalProxyDrainSeconds`. Record it on the Deployment's metadata (e.g. `app.bex.co/kv-internal-proxy-roll-revision`).
2. A Deployment whose recorded revision is lower than the constant takes the rendering, as t001's "inputs changed" path does, and records the constant.
3. Adoption: a Deployment with no revision record is recorded at the current constant without a roll.
4. Add a test that hashes the rendered pod template of a fixture store (one plain and one TLS-forwarding, with and without internal auth) and compares it with a pinned value. Its failure message tells the author three things:
   - the change reaches stores only on their next customer change;
   - bump `kvInternalProxyRollRevision` if that is not acceptable;
   - update the pin either way.

## Acceptance criteria

- [ ] Bumping the constant rolls every proxy Deployment once on the next pass. A second pass changes nothing.
- [ ] Without a bump, no pass rolls a held Deployment.
- [ ] A Deployment with no revision record is recorded without a roll.
- [ ] Adding an env var to the rendering fails the pinned-rendering test with the message above. Reverting the change passes it.
- [ ] `make test` and `make lint` pass.

## Out of scope

- Staggering an override roll across stores. Each store drains for 30 s (w6/m512).
