# Accept Render's larger compute plan IDs (`2c-8g` … `12c-96g`) once bex can run them

Why: Render's pinned OpenAPI `plan` enum offers compute sizes that bex refuses by name (`lego/types/tiers/aliases.go:51-63`). ADR018 row 222 recorded no sign-off for that, so it is an open parity gap, not a divergence (w6/113).

- **Sizes:** `2c-8g`, `2c-16g`, `4c-32g`, `8c-16g`, `8c-64g`, `12c-24g`, `12c-48g`, `12c-96g` (`lego/backend/internal/api/openapi/render-public-api-1.json`).
- **Work once unblocked:**
  - a `tiers.yaml` rung per size, with Render's price for it;
  - Stripe price items;
  - `computeInputAliases` entries plus tests;
  - the dashboard plan picker;
  - serving pools with nodes that fit 12 vCPU and 96 GB.

## BLOCKED — 2026-11-08

- **Gate 1 (Hetzner / account owner): node capacity.** Even Pro Ultra (`8c-32g`) cannot start yet: `w2/blocked/m250` is waiting on cx53 stock in fsn1 and on a dedicated-vCPU limit of at least 32. Advertising sizes that cannot be scheduled would be worse than refusing them.
- **Gate 2 (verify, then user if Render does not publish them): prices.** Find out what Render charges for each size and to which plans it sells them. Its public pricing page lists only Starter through Pro Ultra.
- **Release:** m250 is unblocked and the prices are known. Then promote this note to a milestone.
