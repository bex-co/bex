## Objective

Add `hostedInvoiceUrl` and `invoicePdfUrl` to `billing.Invoice`, taken from Stripe's `hosted_invoice_url` and `invoice_pdf` when an invoice is normalized, and serve them identically on REST (`GET /v1/usage`, the `billing` object), GraphQL (`BillingInvoice`) and MCP (`get_usage`).

## Context

- `lego/backend/internal/billing/read.go`: `Invoice` has only id, status, kind, amounts, currency and period.
- `lego/backend/internal/usage/graphql.go`: `billingInvoiceGQLType`.
- REST and MCP marshal the same struct (ADR006: one core, three adapters).
- Visibility stays w9/m620's `can_view_billing`: members who cannot view billing get no `billing` object today.

## Steps

1. Find where Stripe invoices become `billing.Invoice` and map both URLs; leave a field empty when Stripe gives none.
2. Add both fields to `BillingInvoice`.
3. Confirm the REST and MCP JSON carry them, and update the dashboard's GraphQL documents and types under `dashboard/src/graphql/`.

## Files

- lego/backend/internal/billing/read.go
- the invoice normalizer in lego/backend/internal/billing/
- lego/backend/internal/usage/graphql.go
- dashboard/src/graphql/

## Acceptance criteria

- [x] A Stripe invoice fixture with both URLs yields both fields on REST, GraphQL and MCP, and one without yields neither.
- [x] A caller without `can_view_billing` still gets no invoice and no URL.

## Result (2026-11-25)

Done in `c3bd7a9887`. `billing.Invoice` (`lego/backend/internal/billing/read.go`) carries `HostedInvoiceURL`/`InvoicePDFURL` (`json:"hostedInvoiceUrl,omitempty"`, `json:"invoicePdfUrl,omitempty"`), set in `listInvoices` from Stripe's `hosted_invoice_url` and `invoice_pdf`. GraphQL `BillingInvoice` serves them through `gqlutil.OptionalStrField` (null when empty), REST and MCP marshal the same struct, and the `get_usage` description names both. The schema golden and the dashboard's `usage.graphql`, `definitions.ts` and `schema-types.ts` carry the two fields.

- `TestStripeBillingForCarriesStripesInvoiceLinks`: a Stripe list with an open invoice carrying both links and a void one carrying `null` yields both on the first and neither (absent from the JSON) on the second. Fails with the mapping removed or `omitempty` dropped.
- `TestInvoiceLinksAgreeAcrossSurfaces`: REST, MCP (over an in-memory transport) and GraphQL return the same two links, omitted on REST and MCP and null on GraphQL for the void invoice. Fails with `StrField` in place of `OptionalStrField`.
- `TestInvoiceLinksWithheldFromMembersWhoCannotViewBilling`: a Contributor and a Viewer get 403 on REST, an error on GraphQL and an error from MCP, and no link appears in any of the three outputs.
