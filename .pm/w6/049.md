# Billing page's "Projected total for `<month>`" mismatches between SSR and hydration (React #418)

Why: a live, reliably-reproducing (2/2 fresh loads) console error on the Billing page — a surface about real money — is worth a cheap, well-scoped fix even though it's cosmetic; left alone it will keep getting rediscovered as a "new" #418 by future hunts.

Loading `/billing` fresh (cold `page.goto`) reliably logs `Minified React error #418` (2/2 repro this run). Not a duplicate of `w6/m102` (`formatRelativeAge`/`formatRelativeUntil`, a different file/function) or `w6/m107` (`formatDateTime`/`formatDateLong` reading the runtime's timezone for the same instant) — this is a third, distinct mechanism: a mutable clock read via a default parameter, not a date-formatting function.

**Root cause:** `dashboard/src/features/usage/components/charges-card.tsx:204` — `ChargesCard`'s `now = new Date()` default parameter. Its one caller, `dashboard/src/features/usage/components/usage-page.tsx:131-137`, never passes `now`, so every real render hits the default — evaluated once at SSR-render time and again, independently, at client-hydration time. Two derived values feed directly into rendered text:

- `dashboard/src/features/usage/lib/charges.ts:82` `projectMonthEnd(spentUsd, now)` computes `elapsed = now.getTime() - <start of month>`, a continuously-changing ratio — the "Projected total for August" dollar figure (`charges-card.tsx:237`, formatted via `money()`) will differ by a cent or more between the two clock reads essentially every time, which is a **text-content** mismatch, not merely an attribute — exactly the shape React #418 flags.
- `charges-card.tsx:236,311` also use `now` for `currentPeriod(now)`/`periodLabel(...)`, which is more robust (only flips at a genuine month boundary) but shares the same unguarded mechanism.

**Blast radius:** exhaustive — `grep -rn "new Date()\|Date.now()" dashboard/src/features/usage/components/*.tsx` finds exactly this one call site in the whole `usage` feature; no other billing/usage card reads a live clock.

**Masked in tests:** `dashboard/src/features/usage/components/__tests__/charges-card.test.tsx` has 15 call sites, every one passing an explicit `now={MID_JULY}` — zero test coverage of the real production path (the default parameter), the same "test always injects the fixed value" gap already diagnosed for a sibling class of bug in `w6/m103`.

**Fix shape:** same pattern already used elsewhere in this codebase for the identical class of bug (`env-group-metadata.tsx`'s `w6/030` fix) — either gate the `now`-dependent text behind a mount-only client render (so SSR emits nothing / a stable placeholder for "Projected total" and the real figure appears after hydration), or wrap the two derived spans in `suppressHydrationWarning` if a fleeting stale-then-corrected number is acceptable for an advisory projection. Do not "fix" it by passing a server-supplied `now` down as a prop — the whole point of a live projection is that it reflects the current instant, which the client and server can never agree on exactly; the fix is to stop asserting the same text in both renders, not to make the two clocks agree.

Estimate: ~20-30 min (one component change + a regression test that renders with two different injected `now` values across a simulated SSR/CSR boundary, or a `@testing-library` hydration-mismatch assertion, following whatever test pattern `w6/030`'s fix used).
