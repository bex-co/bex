## Objective

Stamp an agent sandbox's plan metadata with the plan whose size its template has (`2c-4g` for `agent`, `4c-8g` for `agent-4c-8g`), so its charge label and usage tier say what ran.

## Context

- `createAgentSandbox`, `plan := PlanStarter` (`lego/backend/internal/sandbox/service.go:1257`), and the comment there citing w8/247.
- Templates: `lego/backend/cmd/api/main.go:140` (`agent` = `Plan2C4G`, `agent-4c-8g` = `Plan4C8G`); `AgentTemplate` (`service.go`).
- `sandboxChargeLabel` (`lego/backend/internal/sandbox/meter.go`) builds `plan · image`.
- Check that nothing keys on an agent sandbox's tier being `starter` (usage rows, Stripe export, the dashboard) before changing it.

## Files

- `lego/backend/internal/sandbox/service.go`, `lego/backend/internal/sandbox/models.go`

## Acceptance criteria

- [x] A test creates an agent sandbox on each template and reads its stamped plan and charge label.
- [x] The weighted charge for the same sandbox is unchanged.

## Result (2026-11-23)

`createAgentSandbox` stamps `planOfSize(tmpl.limits())` (`lego/backend/internal/sandbox/service.go`, `models.go`): the spec-named plan of exactly the template's CPU and memory, `""` for a size no plan has. `agent` reads `2c-4g · ghcr.io/bex-co/bex-agent-sandbox:…` and `agent-4c-8g` reads `4c-8g · …`, as plan metadata, charge label and meter tier; the weight is the template's, unchanged (2422, 4845). Nothing keys on an agent sandbox's tier being `starter`: `sandbox_compute_seconds` is priced and exported to Stripe by kind alone (`pricing.rateFor`, `billing/stripe.go`), and the dashboard shows the tier as text. `TestAgentSandboxIsLabeledWithItsTemplateSize` covers both templates, an unsized one (starter's size) and an odd size (no plan); it fails with the old `PlanStarter`.
