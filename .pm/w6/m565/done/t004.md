## Objective

Check that the labels read the same on the dashboard's billing page and the REST, GraphQL and MCP usage reads, and compare with how Render's billing page names a sandbox charge. File any drift as follow-up work.

## Result (2026-11-23)

Every usage read funnels through `usage.monthToDateAt`, so REST, GraphQL and MCP share the name, the row tiers and the charge-line tiers: `TestPastAgentSandboxReadsItsRealSizeAcrossAdapters` reads the same five sandboxes identically on all three, and the dashboard's charge tree shows `serviceName` and `charges.tier` as the API sends them (`dashboard/src/features/usage/components/charges-card.tsx`). Render's [Limits & pricing](https://render.com/docs/sandboxes-limits) page (read 2026-11-23) says a sandbox's plan "determines its specs and pricing" and documents no billing-page itemization beyond that, so a charge named by its plan, and by its session where bex knows one, is the parity-sufficient reading. No drift found; nothing filed.
