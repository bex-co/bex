## Objective

Make `SandboxUsageMetadata` also name a sandbox from `agent_session_sandboxes`, which records every sandbox a session ran on.

## Context

- `lego/backend/internal/store/resource_names.go:145` (the `labels` CTE), read by `lego/backend/internal/usage/service.go` (`resolve names`).
- `agent_session_sandboxes (workspace_id, sandbox_id, session_id, turn, compute_milli_seconds)`.

## Files

- `lego/backend/internal/store/resource_names.go`

## Acceptance criteria

- [x] A real-Postgres test: a session's first sandbox, reaped after a second turn moved the session on with no dispatch row, still reads `<repo> (<branch>)`.

## Result (2026-11-23)

The `labels` CTE of `SandboxUsageMetadata` (`lego/backend/internal/store/resource_names.go`) now unions `agent_session_sandboxes` (every sandbox a session ran on since migration 0206, which its trigger and backfill keep a superset of `agent_sessions.sandbox_id`) with the dispatches' `previous_sandbox_id` (sandboxes reaped before 0206), and joins `agent_sessions` once for the label. `TestSandboxUsageMetadataNamesASandboxTheSessionMovedOffPG` moves a session to a second sandbox with no dispatch row, reaps the first, and reads `bex-co/bex (bex-agent/fix)` and `agent session <id>` for it; with the old branch it reads no name.
