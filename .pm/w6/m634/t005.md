## Objective

When a deploy fails because its new instance never passed its health check, append the recorded last result to its failure reason on every surface.

## Context

- Probe-stall templates: `lego/types/v1alpha1/deploy_reasons.go:178-192` (`probeStallHead`, `probeStallHTTP`, `probeStallTCP`, `probeStallOpenPort`) and the table at `:234-251`, including `DeployReasonRolloutDeadline`.
- The deploy's failure reason is read on REST, GraphQL and MCP and in `dashboard/src/features/deploys/components/deploy-failure-reason.tsx`.

## Steps

1. Add a "last result" tail to the probe-stall reasons, filled from the App status line when present.
2. Keep each reason unchanged when nothing was recorded.

## Files

- lego/types/v1alpha1/deploy_reasons.go
- the operator code that renders the probe-stall reason

## Acceptance criteria

- [ ] A stalled HTTP check whose last result was a 503 reads the existing sentence plus `HTTP health check failed with status code 503`.
- [ ] Reasons with no recorded result are byte-identical to today's (existing tests unchanged).

## Out of scope

- Rewording the existing probe-stall sentences.
