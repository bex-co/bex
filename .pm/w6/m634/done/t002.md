## Objective

Make the helper's `check`, `open-port` and `tcp` failures print the message t001 mapped: the status code, the 5-second timeout, `connection refused` or `i/o timeout`. Change nothing about how the helper is installed or mounted.

## Context

- `lego/operator/internal/healthprobe/healthprobe.go:44-72` (`Check`) returns `health check answered %d`. `lego/operator/cmd/health-probe/main.go` prints `health-probe: <err>` to stderr.
- The helper's `--timeout` equals the kubelet's 5 s probe timeout, so a slow answer can reach the kubelet's command timeout first. Leave the helper room to print its own timeout line first.
- w6/m624 (parked) mounts the helper from an image volume. Keep `install` and the binary path unchanged, so both mounts carry the new output and no tenant pod template changes.

## Steps

1. Map each failure of `Check`, the open-port check and the TCP check to its message.
2. Print exactly one line per failure.
3. Unit-test each outcome against a local server: 503, a sleep past the timeout, a closed port.
