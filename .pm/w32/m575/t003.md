## Objective

Give the deploy narration a recorded fact that says whether the release's instance writes `==> Running '<command>'` itself. An image built after t002 does, and an older one does not. A rollback, a reused build, a Blueprint sync that does not rebuild, and a service not rebuilt since all run an older image, and their deploy logs must keep w32/m560's narrated line.

## Context

- w32/m560 records each release's rollout in `status.releaseRollout` (`lego/operator/internal/controller/release_rollout.go`): its start, its app-container starts, its native start command and its `WEB_CONCURRENCY` default. The reconciler copies it onto the deploy row (migration 0327, `lego/backend/internal/store/reconciler.go`), and `DeployProgress` carries it to `rolloutLines`.
- The image is the only thing that knows which native-init it carries. Its config is already read for ports, revision and the native build's base env (`lego/operator/internal/registry/image_config.go`).
- Two options:
  - **A label the native build writes into the image config**, which the operator reads when it projects the release. It survives a rollback to that build.
  - **A fact the build records on the release** when it stages the new native-init. Check that it survives a rollback and a reused build.
- The record must be decided once per release and never move: a resync, a cancel's restore and a revert keep it, as `stampReleaseRollout` keeps its start.

## Steps

1. Pick the option and write down why in the milestone README.
2. Add the field to `ReleaseRolloutStatus` (`lego/types/v1alpha1/app_types.go`), then run `make manifests generate` from `lego/operator/`.
3. Project it onto the deploy row with the rest of the rollout record. A new column needs a migration: take the next free number on `origin/main` at that moment (0332 is the newest at `81bfb51e07`).
4. Carry it in `DeployProgress`.
5. Run `make test` (`-timeout 30m`), `cd lego/backend && go test ./...` against the real-database deps (`scripts/backend-test-deps.sh`), and `make lint`, through Docker.

## Files

- `lego/types/v1alpha1/app_types.go`, the generated deepcopy and CRD
- `lego/operator/internal/build/` (the label), or the build's release record
- `lego/operator/internal/controller/release_rollout.go`
- `lego/backend/internal/store/` (migration, reconciler, store), `lego/backend/internal/logs/progress.go` (`DeployProgress`)

## Acceptance criteria

- [ ] An envtest: a release on an image built with the new native-init records that its instance writes the line, and a release on an older image records that it does not.
- [ ] The record survives a resync, a cancel's restore and a revert.
- [ ] A real-database store test reads it back from the deploy row.
- [ ] A row an older operator wrote reads as "does not write the line".
