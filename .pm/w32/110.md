# `bex services update <image-svc> --branch <name>` emits a bogus `branch_changed` event and marks pending source generation on a prebuilt-image service with no repository

Why: A prebuilt-image service has no Git repository and reads `"branch": null` on every surface, so letting `--branch <name>` mutate hidden `spec.branch`, stamp `AnnotationPendingSourceGeneration`, and append `branch_changed` + `source_changed` events pollutes the activity feed and marks the service as having undeployed changes when its image never changed.

### `bex services update <image-svc> --branch <name>` records `branch_changed` / `source_changed` events and pending source generation on an image service

- **Severity:** minor
- **Versions:** released `bex v0.9.0` (`bex-0.9.0-linux-arm64.tar.gz`, sha256 `714f4e1a…`, pinned Render CLI `v2.36.0`); production pin `f46c44d9ddb1` (`eb52a59622`)
- **Context:** 2026-11-24 UTC, `https://api.bex.co/v1/`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), human device login (`scripts/qa-login.sh --login-challenge`), non-TTY `-o json --confirm`
- **Repro:**

  ```bash
  # On a disposable free prebuilt-image web service (repo: null, branch: null):
  SVC=$(BEX_WORKSPACE=tea-daif693dqjvc73e7as3g bex services create \
    --name qa-20261124-ba2d-imgbr --type web_service --runtime image \
    --image docker.io/library/nginx:1.27-alpine --plan free --confirm -o json | jq -r '.id')

  BEX_WORKSPACE=tea-daif693dqjvc73e7as3g bex services update "$SVC" --branch dev --confirm -o json

  # Inspect events before and after:
  curl -H "Authorization: Bearer <TOKEN>" -H "User-Agent: render-cli/v2.36.0" \
    "https://api.bex.co/v1/services/$SVC/events?limit=20"
  ```

- **Expected / actual:**
  - **Expected:**
    - Every other Git-only flag on a prebuilt-image service is refused with `400` (`--auto-deploy=true` → `prebuilt image services cannot declare autoDeploy`, `--root-directory sub` → `has no repo to build`, `--build-filter-path src/**` → `has no repo to build`), matching `Create`'s `prebuiltImageSourceFields` (`blueprint_compiler.go:438`).
    - At minimum, a prebuilt-image service (`next.repo == ""`) must NEVER emit a `branch_changed` event (`{"from":"main","to":"dev"}`), a `source_changed` event, or stamp `AnnotationPendingSourceGeneration` when it has no repository and its image did not change. Note: `w4/418` (`image_source_patch_test.go:87-96`) intentionally kept `Branch: &"main"` accepted on an image service, while `w32/108` (`b3d3749404`) has since made repo switches without `--branch` resolve the new repo's default branch via `ValidateRepo` rather than reading a pre-staged `spec.Branch`.
  - **Actual:**
    - On disposable prebuilt-image fixtures `srv-dc2h6n9npn2c73ckvfe0` and `srv-dc2h941npn2c73ckvfp0`, `bex services update <id> --branch dev --confirm -o json` exited `0` (`HTTP 200`), returned `"repo": null, "branch": null`, bumped `updatedAt`, and appended BOTH `{"type":"branch_changed","details":{"from":"main","to":"dev"}}` AND `{"type":"source_changed","details":{}}` to `GET /v1/services/<id>/events`.
    - Controls on the same image fixture (`srv-dc2h6n9npn2c73ckvfe0`): `--auto-deploy=true`, `--root-directory sub`, and `--build-filter-path src/**` each exited `1` with `HTTP 400`.
- **Wire evidence:**
  - Pinned CLI (`pkg/service/update.go:33-35`) sends `PATCH /v1/services/{id}` with `{"branch":"dev"}`.
  - Server returned `HTTP 200 OK` with `{"id":"srv-dc2h941npn2c73ckvfp0","repo":null,"branch":null,"imagePath":"docker.io/library/nginx:1.27-alpine","updatedAt":"2026-11-24T04:37:44.663289453Z"}`.
  - `GET /v1/services/srv-dc2h941npn2c73ckvfp0/events?limit=20` before `--branch dev`: zero `branch_changed` events. After `--branch dev`: prepended `{"type":"source_changed","details":{}}` and `{"type":"branch_changed","details":{"from":"main","to":"dev"}}`.
- **Runtime evidence:** Both disposable fixtures (`srv-dc2h6n9npn2c73ckvfe0`, `srv-dc2h941npn2c73ckvfp0`) were created in `bex-canary` and deleted after reproduction (`HTTP 404` confirmed).
- **Attribution:** server
- **Root cause:**
  - `lego/backend/internal/apps/service.go:5612-5632` (`resolveSourcePatch`): mutates `next.branch` from `patch.Branch` even when `next.repo == ""` (prebuilt image service).
  - `lego/backend/internal/apps/service.go:5415,5455,5481-5486` (`SetSourceAndRegistryCredential`, `recordSourceChanged`): when `next.branch != a.Spec.Branch` on a prebuilt-image service, stamps `AnnotationPendingSourceGeneration` (`markSourcePending`), writes `SetAppSource`, and calls `recordSourceChanged(ctx, a, previousBranch, next.branch, updated.UpdatedAt)` which unconditionally emits `branch_changed` whenever `fromBranch != "" && fromBranch != toBranch` plus `source_changed`, without checking whether the service has a Git repository (`next.repo != ""`).
  - Sibling caller `lego/backend/internal/apps/blueprint_setting_events.go:150` (`recordBlueprintSourceChange`) also calls `s.recordSourceChanged(ctx, a, before.Branch, after.Branch, "")` without guarding on repo-backed services (e.g., if `before` or `after` is a prebuilt image).
- **Fix:**
  - In `resolveSourcePatch` (`lego/backend/internal/apps/service.go:5612-5632`) and `checkSourcePatch` (`settings_check.go:686-695`):
    - Decide cleanly relative to `w4/418`'s test (`image_source_patch_test.go:87-96`) and `w32/108` (`b3d3749404`): when `next.repo == ""` (prebuilt image service, neither currently repo-backed nor switching to a repo in this patch), refuse a non-empty `patch.Branch` change (matching `errPrebuiltImageField("branch")`, `"prebuilt image services cannot declare branch; remove it or deploy from repo instead"`, while keeping empty/echo `branch: ""` or unchanged `branch == a.Spec.Branch` as a no-op if any legacy caller echoes it, or refusing any non-empty `patch.Branch` when `next.repo == ""` and updating `image_source_patch_test.go:87-96` whose `"w8/088's two-step switch"` rationale was superseded by `w32/108`).
    - Independently, harden `recordSourceChanged` (`service.go:5481-5486`) and its two callers (`service.go:5455`, `blueprint_setting_events.go:150`) so `branch_changed` is emitted only when both `before` and `after` (or the resulting service) are repo-backed (`a.Spec.Repo != ""` / `next.repo != ""`), so switching Git → image or touching an image service can never emit a spurious `branch_changed` event.
- **Blast radius:**
  - `resolveSourcePatch` → `checkSourcePatch` (3 callers: `ApplyServicePatch`, `SetSourceAndRegistryCredential`, `build_sources.go:637`) across REST `PATCH /v1/services/{id}`, GraphQL `setBranch` (`graphql.go`), and MCP `update_service`.
  - `recordSourceChanged` (2 callers: `service.go:5455`, `blueprint_setting_events.go:150`).
  - Applies to all image-capable service types (`web_service`, `private_service`, `background_worker`, `cron_job`).
