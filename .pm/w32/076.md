# The dashboard's Blueprint page hides a plan still waiting for approval once the Blueprint is no longer `created`

Why: since w32/073, a no-changes re-plan keeps the earlier waiting plan, as Render does. The CLI, REST, GraphQL and MCP can approve that plan, but the dashboard doesn't show it, so a dashboard user can't see or approve it.

- **Severity / estimate:** minor, dashboard parity, ~1h.
- **Seen:** w32/073's worker, 2026-11-21, recorded as a deviation (`.pm/w32/blocked/073.md`, § Shipped, "Deviation").
  - The Blueprint page shows a waiting plan only while the Blueprint is `created`.
  - After a no-changes re-plan, a `created` Blueprint reads `in_sync`, so its waiting first plan disappears from the page.
  - A waiting re-plan of an already approved Blueprint was already hidden the same way.
- **Where:** `dashboard/src/routes/blueprints.$blueprintId.tsx`, which reads `PlannedSync` through GraphQL (`dashboard/src/graphql/definitions.ts`).
- **Fix direction:** show the waiting plan, with its Approve action, whenever GraphQL returns one, whatever the Blueprint's status. Check what Render's dashboard shows for a Blueprint with a pending sync and match it.
- **Related:** w32/075. Render deletes a planned sync not approved within 24 hours; once that ships, the page must stop showing an expired plan.

## Acceptance

- A dashboard test covers an `in_sync` Blueprint with a waiting plan, and shows that plan and its Approve action.
- `yarn lint` and `yarn test` in `dashboard/` pass. The ship gate runs them.
- The page's loading skeleton still matches the loaded layout (dashboard skeleton rule).
