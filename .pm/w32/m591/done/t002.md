## Objective

Persist the release rollout's first exit on the `deploys` table when the reconciler observes `status.releaseRollout.firstExit`, and surface it on `logs.DeployProgress` so every log reader sees it even after the App moves on to a later release.

## Context

- `DeployRollout` and `SetDeployRollout` live in `lego/backend/internal/store/store.go` (around `:3540-3568`), alongside migrations `0327_deploy_rollout` and `0334_deploy_rollout_instance_announces`.
- `deployRolloutFromApp` and `DeployRollout.holds` live in `lego/backend/internal/store/reconciler.go:1270-1315`.
- `app_status_watch.go:216-225` already includes `s.ReleaseRollout` in the watch fingerprint (verify that adding `FirstExit` is automatically covered by the struct/JSON comparison).
- `DeployProgress` lives in `lego/backend/internal/logs/progress.go:95-130`, populated from `store.Deploy` wherever `DeployProgress` is constructed (grep `InstanceAnnounces` across `lego/backend/` to find every wiring site).
- Remember `scripts/migration_order_guard.py`: fetch `origin/main` first and number the new migration strictly above `origin/main`'s highest migration (`0336` as of 2026-11-23).

## Steps

1. Add a new migration pair (`<next>_deploy_rollout_first_exit.{up,down}.sql`) adding `rollout_first_exit_at timestamptz` and `rollout_first_exit_code integer` to `deploys` (NULL means no first exit recorded), with a comment naming `w32/m591`.
2. Add `FirstExitAt *time.Time` and `FirstExitCode *int32` to `store.DeployRollout`.
   - Update `SetDeployRollout` so `rollout_first_exit_at` and `rollout_first_exit_code` are written on an open row (`finished_at IS NULL`) when none is stored yet, or replaced only if a strictly earlier `FirstExitAt` arrives while open; once the row is terminal, writes are ignored. Ensure `rollout_first_exit_code = 0` is preserved (never collapsed to NULL).
   - Update `deployColumns`, `scanDeploy`, and the fake store (`fake_test.go`) to match.
3. Update `deployRolloutFromApp` and `DeployRollout.holds` in `reconciler.go` so the reconciler persists `FirstExit` when it appears (or becomes earlier) on `app.Status.ReleaseRollout`, even if `AppStarts` did not grow in that pass. Also check whether the closing pass that settles `update_failed` copies `FirstExit` before transitioning the deploy to terminal, so a fast crash never misses the write!
4. Add `FirstExitAt time.Time` and `FirstExitCode *int32` to `logs.DeployProgress` and wire them from `store.Deploy.Rollout` at every construction site.
5. Add unit tests (`deploy_rollout_test.go`) and real-Postgres tests (`deploy_rollout_pg_test.go`).
