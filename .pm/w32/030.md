# One tenant's directory transfers can hold a gateway's whole archive-index budget and refuse every other tenant's

Why: since w32/025 every directory copy on an `ssh-gateway` process draws on one 64 MiB index budget with no per-workspace share, so one tenant streaming two worst-case archives slowly can make every other tenant's `bex sandboxes copy` of a directory on that replica answer `503 the sandbox file gateway is at capacity` for up to five minutes at a time. Render documents no transfer concurrency limit, and the budget was meant to engage only under real memory pressure.

- **Found:** w32/025's "Not covered" list, filed at its close on 2026-11-15. Traced from the code, not observed.
- **Mechanism:**
  - `archiveIndexMemory` (`lego/backend/internal/sshgateway/sandboxfiles/sandboxfiles.go`) is one `semaphore.Weighted` for the whole process. A reservation is not tied to the ticket's `Claims.Workspace`.
  - A 256 MiB archive of empty entries indexes about 524k names at 64 B each, about 32 MiB, so two such archives fill the budget.
  - The session limiter allows 5 transfers per identity (`BEX_SSH_MAX_SESSIONS_PER_IDENTITY`), and one transfer may last `files.DefaultTransferTimeout` (five minutes). A refused client retries with a new ticket and is refused again while the budget is held.
  - Single-file copies do not use the index, so only directory copies are refused.
- **Constraint:** a workspace's share must still admit one worst-case archive on an idle gateway (about 40 MiB with its kept symlink targets). Otherwise the budget becomes a routine cap, which w32/025 ruled out. A fixed quarter share, like the sandbox-import budget's (w5/m383), would refuse a lone 524k-entry tree.
- **Fix (one option):** cap what one workspace may hold at 48 MiB inside the 64 MiB total, for example with a per-workspace counter beside the shared semaphore. One workspace then always leaves 16 MiB, about 250k entries, for the others, while a lone worst-case archive still fits.
- **Acceptance:**
  - A gateway test fills one workspace's share with piped archives. A 25,000-entry directory archive from a second workspace is then still copied on the same process, and a further archive from the first workspace gets the 503.
  - A lone worst-case archive (524k entries) still copies on an otherwise idle process.
  - `docs/render-artifacts/ea-sandbox.md` § Bounded file transfers states the share.
- **Not a parity item by itself:** Render documents no such limit, so the share must only ever refuse a workspace that already holds most of the budget.
- Minor (directory copies only, on one replica, while the holder keeps streaming). ~1h.
