## Objective

The change behaves the same on every surface that creates a service, and native runtime start commands that run on Render run on bex.

## Steps

1. Walk every creation path for a native service: REST `POST /v1/services`, GraphQL `createService`, the MCP create tools, the dashboard's new-service wizard, and a Blueprint sync. Each one goes through t001's rule and yields `render-v1` (assert it in tests where a path has its own entry point).
2. Confirm that no read surface (REST, GraphQL, MCP, dashboard) starts exposing the container policy. It is not part of Render's API.
3. Compare with Render's behaviour for common native start commands: `bundle exec passenger start`, `bundle exec puma`, `gunicorn app:app` and `node server.js`. Each starts under `render-v1` (local run of the generated image, as in t002). Record any that does not as a follow-up.

## Acceptance criteria

- [ ] Every creation path yields `render-v1` for a native service, with a test or a recorded check per path.
- [ ] No read surface changed.
- [ ] Every drift found is filed as a follow-up.
