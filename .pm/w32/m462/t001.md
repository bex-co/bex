## Objective

A new native runtime service (web, private, worker or cron, built by bex from a repo with a native runtime, or linked to such a build source) is created with `containerPolicy: render-v1`, exactly as a new Docker or image service is. Static sites stay strict, and native services keep their own port rules.

## Context

- `runsContainerPolicy` (`lego/backend/internal/apps/service.go:2933-2936`) is the one predicate for the widened policy. Today it reads `Image != "" || Runtime == "docker" || Builder == "dockerfile"`, excluding static sites. Creation (`configureNewImageCompatibility`, `:2898`) and the migration (`container_policy_migration.go:136`) share it.
- **Trap.** `configureNewImageCompatibility` returns early on that predicate, then sets the image port modes (`PortModeImageV1`, `PortModeWebImageV1` and their configured variants) whenever `source.Repo != "" || source.Image != ""`. A native service has a `Repo` too. Widening the early return alone would put native private and web services on image port discovery. Split the two rules: the policy rule (every service type but static sites) and the image port rule (Docker and image services only).
- Callers: `create` (`service.go:2312`) and `planStackApp` (`:2762`, Blueprint stacks). A linked service is judged by its build source's runtime through `sourceForImageRules` (`build_sources.go:945`).
- The default still follows `BEX_IMAGE_COMPATIBILITY_WORKSPACES` (`imageCompatibilityAdmits`, `service.go:2938`), which is `*` on production and when unset (w6/090).
- Existing rows never change on update, Blueprint sync or redeploy (ADR089 § Privilege slice decisions item 6). t003 handles existing native services.

## Steps

1. Split the predicate. Keep one function for "this service runs a container policy" (every type except static sites, including native runtimes) and one for "this service follows image port rules" (Docker and image only). Update both doc comments.
2. Gate the port-mode branches on the image rule, so a native web or private service keeps its configured port mode.
3. Check every other caller of `runsContainerPolicy` and choose the right predicate for each.
4. Unit tests: native web, private, worker and cron services get `render-v1`. A native service linked to a native build source gets it, and so does one linked to a Docker source. A static site gets `""`. A native web or private service's `PortMode` is unchanged. A workspace outside `BEX_IMAGE_COMPATIBILITY_WORKSPACES` gets `""`.
