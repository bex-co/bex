## Objective

A download the gateway cannot serve answers once, with its real cause. Today a first attempt reads `409 file ticket already used` (HTTP/2, or HTTP/1.1 on a reused upstream connection) or `503 sandbox file gateway unavailable`. Nobody has used the ticket and the gateway is up.

Links stop failing after t002, but the same path still fails this way for other early errors: an archive over 10,000 entries, a path that became a symlink after the mint, or a sandbox-side `tar` error. Those must name their cause too.

## Context

- `download` (`lego/backend/internal/sshgateway/sandboxfiles/sandboxfiles.go:509-575`) sets its headers, then writes through a `gzip.Writer` that buffers. On any error it panics with `http.ErrAbortHandler` (`:568-574`), even when no byte has reached the client.
- bex-api proxies with `httputil.ReverseProxy` over `s.gatewayClient().Transport` (`lego/backend/internal/sandbox/file_connect.go:266-287`). Go's transport replays a body-less GET when a reused connection closes before any response. The gateway has already consumed the nonce (`sandboxfiles.go:107-109`), so the replay reads `409`. The proxy's `ErrorHandler` (`file_connect.go:281-283`) turns any other transport error into `503`.

## Steps

1. In `download`, track whether any byte has been written to the `ResponseWriter`. If none has, answer `writeError` with the classified error and do not abort. Once bytes are out, keep the abort: the pinned client's gzip-trailer check is the proof of completion.
2. Make bex-api's gateway hop non-replayable. For example, use a transport for file transfers that does not reuse connections, or give the proxied request a body that is not replayable. A dropped hop then surfaces once, and the client mints a new ticket.
3. In `ErrorHandler`, say what happened: "the sandbox file transfer ended before a response" and not "unavailable" when the gateway was reachable. Keep the `503` status.
   - w8/313 (done in `fce731952`) removed the stalled upload refusal that also ended in this `503`. It checks the destination before streaming and drains stdin on a late refusal. It left this `ErrorHandler` and its `503` unchanged and did not take its optional `504` for a header timeout. Only this task changes the handler: tell a hop dropped before any response apart from an unreachable gateway. A header timeout can keep the `503` unless a later item picks up w8/313's `504`.
