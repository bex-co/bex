## Objective

The lines a native build's pod writes carry t001's build forms: the shell form (`\x1b[34m\x1b[1m==>\x1b(B\x1b[m \x1b[1m<text>\x1b(B\x1b[m`) for the cache and build-command lines, and the runtime form (`\x1b[34;1m==>\x1b[0;22m \x1b[1m<text>\x1b[22m`, green for `Build successful 🎉`) for the version, upload and success lines.

## Context

- The BuildKit container's awk filter and the push phase: `lego/operator/internal/build/build.go` (`==> Running build command '…'...`, `==> Reusing the cached result …`, `==> Uploading build...`, `==> Preparing the build failed: …`, `==> Uploading build failed`, the transfer retry line, `==> Uploaded in Ns`, `==> Build successful 🎉`).
- The cache lines: `s3cache.go` (`==> Downloading cache...`, `==> Transferred …`), `xdgcache.go`.
- The version and dependency lines: `nativeversion.go`, `nativeresolve.go`, `nativebundler.go`, `nativestaticdeps.go`, `nativeerlang.go`, `nativecommon.go`. Some are written by Go into the generated Dockerfile or script, some by `echo`/`printf`/awk at build time; each writer needs the bytes its own way (`printf '\033[34m…'` in sh, `"\033[34m"` in awk).
- Readers of these lines that must keep working: `nativePublishMissingLine` (a regexp on `==> Publish directory … does not exist!`), the upload-moment handoff between the BuildKit container and the push phase (w33/m570), the failure classifier and failure reason, which read BuildKit's raw transcript from the termination message, and the operator tests that pin the awk output.
- A Dockerfile build keeps BuildKit's plain output, as Render shows it. Its `==>` lines are the cache lines and the push phase, if any.

## Steps

1. Apply t001's form to every line in the list, with one helper per family so the bytes are written once.
2. Make every reader above match the plain words whether or not the codes are there, and test both.
3. Pin each Render-observed line byte for byte in the operator's tests.
4. Run `make test` from `lego/operator/` and `make lint`.

## Files

- `lego/operator/internal/build/*.go` named above, and their tests

## Acceptance criteria

- [ ] `Downloading cache...`, `Running build command '…'...`, `Uploading build...`, `Uploaded in Ns` and `Build successful 🎉` carry Render's exact forms in the operator's tests.
- [ ] Every other build line carries t001's form.
- [ ] The publish-directory check, the upload moment and the failure reason behave as before, with tests.

## Out of scope

- BuildKit's own step output, and a tenant's build command's output.
- The control plane's `Building from` and `Build failed 😞` lines: t002.
