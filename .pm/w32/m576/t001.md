## Objective

Produce one table, kept in the milestone README, that gives every `==>` line bex writes its exact byte form: Render's own form where a public capture of Render's log API shows that line, otherwise the form of its kind (step, success or failure) in the writer's family, marked as bex's reading.

## Context

- The README's § Render's forms holds the seven forms the triage found and the lines each was seen on, with their sources.
- bex's writers:
  - the control plane's narration: `progressLines`, `preDeployLines`, `rolloutLines`, `portScanLines`, `hookLines`, `closingLines`, `terminalLines`, `primaryURLLines`, `waitLine` and `oidcRefusalLine` in `lego/backend/internal/logs/progress.go`, plus `logsGoneMessage` (`service.go`) and the stream error line (`rest.go`, `"==> " + err.Error()`);
  - the build pod: the awk filter and push phase in `lego/operator/internal/build/build.go`, `s3cache.go`, `xdgcache.go`, `nativeversion.go`, `nativeresolve.go`, `nativebundler.go`, `nativestaticdeps.go`, `nativeerlang.go`, `nativecommon.go`;
  - the instance: `announce` in `lego/operator/cmd/native-init/main.go`, and the narration's copy of it for an image built before w32/m575 (`rolloutLines`, `preDeployLines`).
- Logs quoted in GitHub issues are copied from Render's dashboard and read plain. Only files that hold Render's API, CLI `-o json` or MCP output carry the codes: search GitHub code for `\u001b[0;31m\u001b[1m==>`, `\u001b[34;1m==>`, `u001b` with `onrender`, `render logs -o json` captures, and agent transcripts that read Render logs.

## Steps

1. Search public captures for Render's codes on each line the README lists as unseen. Record each find with repo, path and commit.
2. For each line bex writes, pick the form: Render's exact form when seen; otherwise its writer's family (platform, build shell, build runtime, instance) and its kind (blue step, green success, red failure). A Render line that Render's build writes (`Build failed 😞` at the end of a failed build) takes the build family even though bex writes it from the control plane.
3. Decide two edge cases and write the reason down: the platform failure form colours the whole line, so a multi-line failure reason (`narrated`) colours each line; and the blank URL line keeps its trailing space inside the marker's colour.
4. Write the table into the milestone README under § Render's forms, one row per bex line, with the source or "bex's reading".
