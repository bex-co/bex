## Objective

Prove that each reader returns the codes as Render's do, and that nothing in bex strips or doubles them:

- `bex logs -o json` and `-o yaml` print the message with the codes escaped, as `render logs -o json` does (ivanseibel/tretta's capture);
- `bex logs` on a terminal or a pipe keeps the SGR codes, drops `ESC ( B` and appends a reset (`SanitizeTerminal`), and redirected to a file writes the message untouched;
- MCP `list_logs` returns the message raw, as Render's MCP server does;
- GraphQL `logs`, REST `GET /v1/logs` and `GET /v1/logs/subscribe` return the stored message.

## Context

- The pinned Render CLI's `writeLog` (`cmd/logs.go`) and `SanitizeTerminal` (`pkg/strings/strings.go`) do this already; `lego/cli/internal/branding` leaves log output alone. The CLI's contract tests (`lego/cli/logs_*_contract_test.go`) run the real command against a fake server.
- `lego/backend/internal/logs/mcp.go`, `graphql.go`, `rest.go`.
- bex's `text` filter compares the raw message by default, the only mode Render documents (w4/m189, `lego/backend/internal/logs/display.go`), so a raw search for `==> Deploying` no longer finds the coloured line, as on Render if Render matches raw. `textMode=display` is bex's labeled extension for the visible text.

## Steps

1. Add a CLI contract test: a fake `/v1/logs` returns each of Render's seven forms; `bex logs -o json` prints them byte for byte as the Render CLI would, and `bex logs` to a pipe prints the sanitized form.
2. Add backend tests that read a coloured platform line through REST, the subscribe stream, GraphQL and MCP and get the same bytes.
3. Test the `text` filter on a coloured platform line in both modes, the live tail's filter included.
4. Run `cd lego/cli && go test ./...` and the backend's `internal/logs` tests.
