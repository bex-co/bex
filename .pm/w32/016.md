# A sandbox reads region `frankfurt` while its sandbox group reads `oregon`

Why: Render's CLI help says "Every sandbox belongs to a sandbox group, which scopes it to a region". On bex the same sandbox and its group name two different regions, so any client comparing them (or pinning work to a region) gets a contradiction.

- **Seen:** `/qa-find-bugs-cli` loop sweeps 865a/edb9, 2026-11-12, `bex-canary`, human device login.
  - `bex sandboxes create --wait …` (release v0.5.0) → `"region": "frankfurt", "sandboxGroupId": "sbg-dbpugr7bq3ic73c0acmg"`.
  - `bex sandbox-groups list -o json` (HEAD build, Render CLI v2.36.0 pin) → that group's `"region": "oregon"`.
  - Every sandbox in `sandboxes list --all` reads `frankfurt`.
- **Contract:** the pinned OpenAPI `create-sandbox-group` documents `region` as "Region for the group's sandboxes", and the sandbox's `region` as "Region the sandbox is running in". Both are free strings (no enum), and the Render SDK models type them as `str`. ADR104 D7 says the group sets the region.
- **Cause (traced at `be666f974`):**
  - `lego/backend/internal/store/sandbox_groups.go:41` hard-codes `SandboxGroupRegion = "oregon"`. `sandbox/groups.go:192-200` uses it as "a compatibility value that does not affect placement" (w22/m311).
  - The sandbox's own region comes from `Service.Region` (`sandbox/service.go:140-142`, `BEX_REGION` through `resourcemeta.RenderRegion`). Services read `frankfurt` from the same source.
- **Fix:**
  1. Pick one source and use it for both reads, recording the choice in ADR104 D7.
  2. Recommended: the group carries the platform region (`resourcemeta.RenderRegion`, as services do), keeps accepting `oregon` on create as Render's default, and a sandbox reads its group's region.
  3. Apply it on REST, GraphQL and MCP, and to the dashboard's group dialog (w22/m311 t012 shows "Oregon").
- **Acceptance:** in `bex-canary`, `bex sandboxes create --wait -o json` and `bex sandbox-groups list -o json` show the same region for the sandbox and its group.
- **Unverified:** whether any SDK or CLI path rejects a region other than `oregon` (none seen in the pinned client or SDK models).
- **Dedupe:** no board item covers this. It comes from w22/m311 (blocked on its production walk), and is filed here so m311's walk is not reopened.
