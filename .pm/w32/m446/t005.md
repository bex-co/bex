## Objective

Check that REST, GraphQL and MCP (and the dashboard's Kratos-session requests) all get the same answer for an onboarding fault after this milestone, and that it matches Render, where a signed-in read is not refused because the workspace is busy.

## Context

- All surfaces share the auth middleware (`lego/backend/internal/api/server.go:101`).
- Render's public error schema is `{"id","message"}` (`core.WriteErr`).

## Steps

1. Force an onboarding fault in a test and compare the REST status and body, the GraphQL error, the MCP tool error and the dashboard's handling.
2. File any drift as follow-up work through `/pm`, and record the outcome here.
