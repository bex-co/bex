## Objective

A person whose personal workspace id this replica resolved recently is not refused because one cache-miss read failed. The fault t001 named is fixed at its cause, or absorbed by serving the recently known tenant.

## Context

- `EnsureTenant` caches the tenant for 30 s (`core.PositiveTTL`, `internal/core/http.go:595`) and returns an error on any cache-miss failure (`internal/api/tenancy.go:159-193`).
- The account-deletion tombstone must keep winning over any cache (ADR086). A failure to read it is a separate decision to record, not to silently pass.
- `auth.go`'s comment explains why onboarding fails closed: "a request that can't be tenanted must not be served un-tenanted". A recently resolved tenant is still tenanted.

## Steps

1. Fix the cause t001 found where it lives, for example pool sizing, a missing retry on a transient Postgres error, or OpenFGA load.
2. Keep the last resolved tenant per identity for a bounded window (minutes). On a transient cache-miss fault, serve it and log the fault, instead of answering 503.
3. Decide and record what a failed tombstone read answers. Keep it fail-closed unless ADR086 says otherwise, and log it either way.

## Files

- `lego/backend/internal/api/tenancy.go`
- `lego/backend/internal/api/auth.go`
- `docs/ADR012-auth.md` or `docs/ADR086-*.md` if the fail-closed rule changes

## Acceptance criteria

- [x] With a fake store or OpenFGA that fails one cache-miss call, a returning caller is served, and a first-ever caller still gets 503.
- [x] A tombstoned account is refused even while a stale tenant is held.

## Out of scope

- Client-side retries in the CLI launcher. Upstream semantics stay as they are.

## Result (2026-11-17, `/loopx w32`)

- **Step 1, the cause where it lives:** t001 named two causes. The onboarding one (a reset Check, then a refused duplicate write) is gone with w4/695 and w21/099: 0 onboarding 503s since they deployed. The one still live is `503 auth upstream unavailable`, a token introspection on a dropped keep-alive connection. Introspection is now resent once on a fresh connection (`core.MarkReplayable` in `introspectUpstream`).
- **Step 2:** `tenantService.recent` keeps each person's personal workspace for 10 minutes (`recentTenantTTL`) after onboarding last resolved it. On a cache miss, a failed owner lookup, or a failed admin grant on that same workspace, serves it for one cache window and logs the fault. A creation, a re-read or a revoke after a grant this request wrote still fails, since the workspace may no longer be the person's. `InvalidateTenant` forgets it on that replica. This grants nothing: every verb still authorizes against OpenFGA.
- **Step 3, a failed tombstone read:** it stays fail-closed, as ADR086 requires ("fail closed once it begins"). An unreadable tombstone could be a deletion in progress, so it answers `503 tenant onboarding unavailable: account deletion check failed (workspace store)` and is logged, even with a cached workspace. It is recorded in ADR086 §1 and in the new ADR012 §8f.
- **Tests:** `TestEnsureTenantServesARecentWorkspaceThroughAStoreFault` (a returning caller is served and the next call is a cache hit; a first-ever caller gets the 503), `TestEnsureTenantServesARecentWorkspaceThroughAnOpenFGAFault`, `TestEnsureTenantDoesNotServeARecentWorkspaceThroughEveryFault` (re-read, tombstone read, after `InvalidateTenant`) and `TestEnsureTenantTombstoneWinsOverARecentWorkspace`. With the fallback disabled, the two serve tests fail.
