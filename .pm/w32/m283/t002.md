## Objective

Make the network layer enforce each sandbox's policy: allow-all opens public egress on any protocol above the floor; allow-list admits DNS for and TLS 443 to the listed hostnames (exact SNI, `*.` wildcard) and nothing else; deny-all is unchanged.

## Context

- Existing sandbox egress: Cilium DNS-L7 + `toFQDNs` outside the gVisor guest (ADR042, ADR062 § gVisor blocker); OpenSandbox's egress sidecar cannot be used under gVisor
- Per-tenant `<ws>-sandbox` namespaces (ADR043); bex stamps reserved policy metadata on create (ADR042 D-metadata paragraph)
- App egress floor already exists in `deploy/gitops/base/tenant-node-egress.yaml`

## Steps

1. Choose the mechanism: a per-sandbox CiliumNetworkPolicy selected by a sandbox label, created with the sandbox and garbage-collected with it (owner reference or purger).
2. Allow-all: public egress, floor denies kept.
3. Allow-list: DNS L7 rule limited to the listed names, `toFQDNs` + SNI on 443 only.
4. Make sure the policy object exists before the sandbox can run its first command (no open window).
5. Keep suspend/resume (w2/m278) and the purger consistent with the new object.

## Files

- lego/backend/internal/sandbox/service.go
- lego/backend/internal/sandbox/purger.go
- deploy/gitops/base/ (sandbox egress manifests)
- bex-api RBAC for ciliumnetworkpolicies in `<ws>-sandbox`, if bex-api creates them

## Acceptance criteria

- [ ] An allow-all sandbox reaches a public HTTPS and a non-HTTPS public endpoint
- [ ] An allow-list sandbox reaches only listed hosts, over HTTPS only
- [ ] Under every policy, cluster, metadata and private addresses are denied
- [ ] Deleting or terminating a sandbox removes its policy object

## Out of scope

- Brokered credentials (Render alpha `sandbox-groups credentials`)
