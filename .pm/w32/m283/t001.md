## Objective

Record the parity decision in the ADRs before code changes: a user sandbox created without a policy gets Render's `allow-all`, `allow-list` admits HTTPS to listed hostnames only, and `deny-all` stays. Keep the platform floor that applies under every policy.

## Context

- Render: 'a new sandbox allows outbound network traffic to any destination using any protocol' (render.com/docs/sandboxes-creating); modes `allow-all` (default), `allow-list`, `deny-all`
- Allow-list rules: lowercase hostname, no scheme/port/path, exact host excludes subdomains, `*.example.com` for subdomains, ≤100 rules, non-HTTPS blocked; policy survives suspend/resume and is inherited by snapshot restores
- bex today: `docs/render-artifacts/ea-sandbox.md:48` normalizes an omitted policy to deny-all and refuses `allow-all`/`allow-list` with `SANDBOX_NETWORK_POLICY_UNSUPPORTED`; ADR018 row in § Sandbox create flags records no user sign-off for that
- ADR042 egress table: sandbox → platform FQDN allowlist via Cilium `toFQDNs` + exact SNI; everything else denied
- AGENTS.md: Render parity is the top rule; an unsigned divergence is amended, not preserved

## Steps

1. Amend ADR042's egress section: per-policy rules, plus the floor denied under every policy (cluster/pod/service CIDRs, node and cloud metadata, private and link-local ranges, other tenants, bex platform endpoints, free-plan SMTP ports 25/465/587 as for free services).
2. State that agent-session sandboxes (ADR047/ADR062) are created with an explicit `deny-all` and are unchanged.
3. Decide and record the open allow-list details Render does not state (whether `*.x` matches the apex, port 443 only, IP literals refused) choosing the strictest reading consistent with Render's text.
4. Update `ea-sandbox.md` and the ADR018 row to the target state (marked in progress).
