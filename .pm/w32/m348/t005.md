## Objective

Show on production that the documented copy-then-run workflow and bash syntax work, and keep it checked weekly.

## Context

- Repro from the sweep (`bex-canary`, release `bex` v0.5.0): `copy ./run.sh sbx:run.sh`, then `exec sbx -- sh run.sh` failed with `can't open 'run.sh'`; `exec sbx -- bash -c …` exited 127.
- `scripts/verify-sandbox-isolation.sh` already runs REST exec checks on production (`isolation-matrix.yml`).

## Steps

1. After the deploy that carries t002–t004 (check with `git merge-base --is-ancestor`), run in `bex-canary` with the released CLI:
   - `bex sandboxes create --wait --timeout 900 -o json`
   - `bex sandboxes copy ./run.sh <sbx>:run.sh` (where `run.sh` contains `echo from-script`), then `bex sandboxes exec <sbx> -- sh run.sh` → `from-script`, exit 0
   - `bex sandboxes exec <sbx> -- pwd` → the home directory
   - `bex sandboxes exec <sbx> -- bash -c 'arr=(a b); echo ${arr[1]}; echo {1..3}'` → `b`, `1 2 3`, exit 0
   - `bex sandboxes stop <sbx> --confirm`
2. Add two checks to `verify-sandbox-isolation.sh`: REST exec of `pwd` returns `$HOME`, and REST exec of an array expression is interpreted by bash.
3. Run `isolation-matrix.yml` and record the run id here.
