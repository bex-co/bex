## Objective

Make every caller-facing sandbox exec change to the sandbox user's home directory and interpret the caller's command string with `bash -c`, keeping the command one untouched argument. Fall back to `/bin/sh -c` when the root filesystem has no bash.

## Context

- `lego/backend/internal/sandbox/exec.go:120` (`dialGateway`): `[]string{"/bin/sh", "-c", req.Command}`. Every surface reaches it: REST exec, the connect-token run path (`connect.go:276` → `StreamExec`), GraphQL and MCP `sandbox_exec`.
- Pods/exec has no working-directory field, so the change goes in the argv. A shape that keeps the command one untouched argument: `["/bin/sh", "-c", "cd -- \"$HOME\" 2>/dev/null || cd /; if command -v bash >/dev/null 2>&1; then exec bash -c \"$1\"; else exec /bin/sh -c \"$1\"; fi", "bex-exec", req.Command]`. Verify the exact form, including exit-code propagation, in tests.
- Execution history (w32/m298) must keep recording the caller's command, not the wrapper.
- `exec_test.go:631` `TestExecHandsTheCommandStringToShAsOneUntouchedArgument` pins today's argv.

## Steps

1. Implement the wrapper in `dialGateway` (or the narrowest shared point that only caller-facing execs use).
2. Update the pinned test: the command is still one untouched argument, and a nonzero exit is still data.
3. Add tests: `pwd` prints `$HOME`; bash syntax works when bash exists; `/bin/sh` is used when it does not; a failing `cd` falls back to `/`.

## Files

- lego/backend/internal/sandbox/exec.go

## Acceptance criteria

- [ ] Every caller-facing exec runs in `$HOME` under `bash -c` when bash exists.
- [ ] A rootfs without bash still runs the command under `/bin/sh -c`.
- [ ] The exit code, stdout/stderr split and execution-history `command` field are unchanged for callers.

## Out of scope

- Internal status reads (`service.go:1206`, `:1251`) and the SSH gateway paths (`nativessh`, `webshell`), which pass `/bin/sh` explicitly and are not Render exec.

## Done — 2026-11-12

- `internal/sandbox/exec.go`: `execArgv` → `/bin/sh -c '<wrapper>' bex-exec <command>`; the wrapper `cd -- "${HOME:-/}" 2>/dev/null || cd /`, then `exec bash -c "$1"` when `command -v bash` finds it, else `exec /bin/sh -c "$1"`. `dialGateway` uses it, so REST exec, the connect-token run path and MCP `sandbox_exec` all get it (GraphQL has no exec mutation).
- Tests (`exec_shell_test.go`, run under the host `/bin/sh` and, compiled, inside `bash:5.3` and `alpine:3`): `pwd` is `$HOME`; `sh run.sh` runs a relative upload; arrays/brace expansion under bash (`$0` = `bash`); exit 7 and the stdout/stderr split are the command's own; `$1` does not leak into the command; missing/unset HOME → `/`; no bash → `/bin/sh` in `$HOME`. `exec_test.go`: the signed argv is `execArgv` with the command as one untouched last argument (replaces `TestExecHandsTheCommandStringToShAsOneUntouchedArgument`).
