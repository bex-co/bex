## Objective

Point the `base` sandbox template at the image t001 chose, so that a new sandbox has `bash` and the file gateway, DNS and suspend paths keep working.

## Context

- `lego/backend/cmd/api/config.go:560` sets the default `BEX_SANDBOX_IMAGE` (`alpine:3@sha256:28bd5fe8…`); `cmd/api/main.go:90-105` builds the `base` template (entrypoint `sleep infinity`, plan `1c-2g`).
- The file gateway runs `/bin/sh -c <script>` (`sandboxfiles.go:343`). Its scripts must work under the new image's `sh`.
- ADR104 D3 / w8/m152: allow-list DNS relies on `ndots:1` in the Pod template. A glibc resolver differs from musl, so re-check name resolution under an allow-list.
- The digest-pinning guard from w7/m85 must accept the new reference.

## Steps

1. Change the default (and any deployment override) to the chosen image by digest.
2. Run the file gateway's tests and the sandbox exec/file tests against the new image where they execute real scripts (`shell_test.go` runs the scripts).
3. On a dev stack, create a sandbox and check: `bash --version`, an upload and download (file and directory), an allow-list sandbox resolving a listed name, and an idle suspend and resume.

## Files

- lego/backend/cmd/api/config.go
- lego/backend/cmd/api/main.go (if the entrypoint changes)
- deploy/gitops (only if a deployment sets `BEX_SANDBOX_IMAGE`)

## Acceptance criteria

- [ ] A new sandbox runs `bash --version` with exit 0.
- [ ] The file round trip, allow-list DNS and suspend/resume pass on a dev stack with the new image.
- [ ] The digest-pinning guard passes.

## Out of scope
