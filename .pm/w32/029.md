# The checklist marks `ea objects` verified on production, but the released `bex` (v0.6.0) refuses every `ea objects` command before sending a request; no CLI release carries the pass-through

Why: w21/m415 closed on 2026-11-15, and `docs/cli-compatibility-checklist.md:329-332` now grade `ea objects list|put|get|delete` `[x]` "Verified on production". That walk used a checkout build of `bex` and the unmodified `render` CLI (`.pm/w21/done/m415/done/t010.md:70`). A customer who installs the current release (`bex-cli/v0.6.0`, 2026-11-12) still gets the launcher's old refusal. The server works, the documented CLI does not, and the ledger says it does.

- **Seen:** `/qa-find-bugs-cli` sweep 47 (nonce 92da), 2026-11-15 12:50 UTC, released `bex` v0.6.0 (Render CLI v2.36.0 pin), QA human device login, `bex-canary`. Re-run in sweep 85 (22:20 UTC), after m415 closed, with no session at all: the same line, exit 1 in 0.02 s, so the refusal is client-side and does not depend on the server or on login.

  ```text
  $ bex ea objects list -o json
  Error: bex does not offer Render's early-access object storage yet; --local still stores objects in .render/objects/
  exit 1, 0.01 s, no request sent
  $ bex ea objects list --region frankfurt -o json   → the same line, exit 1, 0.01 s
  ```

- **Cause:** the refusal lives in the launcher. `3c1ef192a` (w21/m415 t008) removed it on `main`, but `git tag -l 'bex-cli/v*'` still ends at `bex-cli/v0.6.0`. `git log bex-cli/v0.6.0..origin/main -- lego/cli` lists 18 unreleased commits (excluding Markdown), including `3c1ef192a`, `83a3f11c9` (`bex agent stop`, w22/013) and the w32/022–024 sandbox copy fixes' `lego/cli` changes. The weekly `cli-release-staleness.yml` reminder exists, but nothing on the board schedules this release.
- **Fix:**
  1. Cut the next CLI release (`/release cli`, presumably `bex-cli/v0.6.1`) from a `main` that carries `3c1ef192a`.
  2. With the released binary, repeat the m415 t010 step-2 round trip: put, list, get and delete a 1 B object in `frankfurt`. Delete it afterwards.
  3. Until the release is out, rows `:329-332` say the pass-through needs a `bex` newer than v0.6.0, and that v0.6.0 refuses client-side.
- **Acceptance:**
  - With the release installed, `bex ea objects list --region frankfurt -o json` sends the request and exits 0.
  - The 1 B put/get round trip matches by sha256, and the object is gone after the delete.

  - The four checklist rows cite the released version that was walked.
- **Unverified:** whether the release workflow needs anything beyond `/release cli` (signing, tap update); its own skill covers that.
