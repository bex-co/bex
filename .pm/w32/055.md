# A static site's rollback clears a saved, undeployed setting from `undeployedChanges`, though the setting still waits for the next deploy

Why: after a rollback, the dashboard and GraphQL say a static site has no undeployed changes. Its saved build command, root directory or publish directory still differs from what is served, and goes live at the next deploy without warning.

- **Severity / estimate:** minor, ~1h.
- **Seen:** w32/049's production walk, 2026-11-20, pin `3e53abbe3bc3`, `bex-canary`. Record: `.pm/w32/done/049.md`, Walk step 4, "Static rollback (w4/m197)".
  - A save of a second build command (writing `PUB2`) read `undeployedChanges: true` / `saved` while the site still served `PUB`.
  - REST `POST /v1/services/S/rollback` went `live` with no build and re-served `PUB`.
  - Afterwards `undeployedChanges` read `false`, although the saved build command was never deployed.
- **Known cause (from w32/049's note, "Known limit, unchanged"):** the rolled-back release's settings are not recorded, so the operator's static settings fingerprint takes the saved settings as served. w32/049 fixed the same gap for Restart (`releaseSettingsFingerprint` kept on restart, `8ab2633c8`). w32/053 added `servedSettingsFingerprint` for failed deploys (`51d66ef96`). Rollback has neither.
- **First check Render:** establish whether Render's dashboard still reports pending changes after a rollback of a static site. Render's rollback redeploys an earlier build and keeps service settings as they are. Cite the source. If Render matches bex today, close this as already met with that evidence.
- **Also check web services:** whether a web service rollback has the same gap (`restartSelectedRelease` / `openSelectedRelease` paths in `lego/backend/internal/rollout/`, w32/049's record), so one fix covers both.

## Acceptance

- After a static rollback with a pending save, GraphQL `undeployedChanges` / `undeployedChangesReason` read `true` / `saved`, and the next deploy clears them.
- An operator or backend test covers rollback with and without a pending save.
- If the fix touches it, ADR018's Rollback row states the behavior.
- The production walk runs once the pin carries the fix and w32/053's `51d66ef96`.
