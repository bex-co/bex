# CLI skill's GitHub Actions example runs the installer on ubuntu-latest, which has no cosign

Why: an agent or user copying the documented CI deploy example gets `install-bex: error: cosign >= 2.4.2 is required …` on the first step, because GitHub-hosted `ubuntu-latest` runners do not ship cosign and the installer refuses unsigned verification.

## Finding (2026-11-04, while closing w32/001)

- `lego/cli/internal/skills/pack/skills/bex-cli/SKILL.md` § "CI/CD Example (GitHub Actions)" (~line 72) downloads `scripts/install-bex.sh` and runs it on `runs-on: ubuntu-latest` with no cosign install step.
- `scripts/install-bex.sh` fails closed without cosign (since w4/m35) and, since w32/001, also below v2.4.2.

## Fix

- Add a `sigstore/cosign-installer` step (SHA-pinned, as `.github/workflows/cli-release.yml:104` pins v4.1.2) before "Install bex CLI" in the example; check other embedded skills for the same pattern (`rg install-bex lego/cli/internal/skills`).
- Regenerate/verify the pack per `lego/cli/internal/skills/packgen` and run `cd lego/cli && go test ./...`.
- Mirror the step in any CI snippet in `docs/bex-cli.md`.
