# A direct static publish that fails before the operator sees it cloning closes `build_failed` with no build on record: the log reads `==> Deploy queued` and there are no `build_started`/`build_ended` events

Why: a deploy that ends `build_failed` should say a build ran. A failed repo build on bex carries `build_started` and `build_ended` (Render's event types for a build), and it reports its recorded window even when its dispatch was not observed (w6/m123). A no-build static site has no such record, so webhooks and the Events timeline miss the build, and the build log opens with the wrong line.

- **Seen:** `/qa-find-bugs w4` round 475, 2026-11-16 03:05–03:06 UTC, pin `a0266464aabd`, `bex-canary` (recorded in [w32/028](done/028.md) § Live replay over REST). A static site with no build command on a branch that does not exist:
  - status `created` → `queued` (03:05:58) → `build_failed` (03:06:16), never `build_in_progress`;
  - build log `==> Deploy queued`, then `==> Build failed: could not fetch "qa-r475-no-such-branch" from this service's repository …`;
  - events `deploy_started` and `deploy_ended` (`build_failed`) only.
- **Not reproduced on pin `f114fdd9f5a6`** (w32/028's closeout walk, 2026-11-16 09:56–10:03 UTC): the same mistake read `build_in_progress` for 11–16 s on three deploys, and the first one's log and events carried the build. The difference is the operator's queue. Before `f114fdd9f` the manager was CPU-throttled and the App queue's p95 wait was 28–58 s (w21/m421 t001). A missing ref fails the publish Job within about 16 s, so the operator's next look found the Job already failed. The case returns whenever a reconcile of that App is late by more than the Job's lifetime (`publish.ObserveInterval` is 3 s).
- **Cause (traced at `a82eaeec8`; the round 475 operator log was not read):**
  - `publishStaticRevision` turns a failed publish with `UserError` into `r.fail(ReasonBuildFailedUserError)` and records no build window (`lego/operator/internal/controller/app_controller.go:4843-4851`). `stampBuildRun` writes `status.buildRun` only for a build Job (`build_failure.go:135`, called at `app_controller.go:1371`).
  - In bex-api, a row that goes from `created` or `queued` straight to a terminal failure reports a build only from `status.buildRun` (`recordedBuildRun`, `lego/backend/internal/store/reconciler.go:2160`; `buildStartedAt` → `evidencedStart`, `:1413-1466`). With none, it emits neither build event and leaves `started_at` null.
  - `progressLines` then prints "Deploy queued", because a finished row with no build fact is not counted as built (`lego/backend/internal/logs/progress.go:252-273`).
- **Fix:** when a direct publish fails on the tenant's source, stamp `status.buildRun` for the release generation from the publish pod's `clone` step (its container start and finish times), in the same status write as the Build verdict, as `stampBuildRun` does for a build Job. A window the pod never reported writes nothing.
- **Acceptance:**
  - Operator test: a direct publish first observed already failed with exit 66 leaves `status.buildRun` with the release's generation and the clone step's window. It fails with the stamp removed.
  - Backend test: a `queued` static-site row that closes `build_failed` with that `buildRun` gets `build_started` and `build_ended` (`failed`) dated from the window and a `started_at`, and its build log reads `==> Build queued`, `==> Building from …`, `==> Build failed: …`.
  - The observed path is unchanged: w32/028's acceptance walk still passes.
- **Unverified:** whether a successful direct publish first seen after its clone needs the same window. By the code it does get a `build_started`, dated at the observation and not at the clone (`reconciler.go:1436-1441`). Not observed on Render: its events for a no-build static site whose branch is missing.
- **Dedupe:** `rg -n -i 'buildRun|Deploy queued' .pm` outside `done/` finds w8/287 (blocked: a built deploy's row reads `queued` through its build), w21/m421 t007 (the wait line of a deploy the operator has not picked up) and w4/m350 (an image deploy's log). None covers the direct path's missing window.
- Minor (status and message are right; events and one log line are missing, and only when the operator is late). ~45m.
