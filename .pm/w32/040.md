# Move the existing Docker and image services still on the strict policy onto `render-v1`

Why: every new Docker, image and native service runs `render-v1`, Render's measured capability set (ADR089 D2, w6/m149, w32/m462), but services created before w6/m149's creation default keep `strict-v1` or `""` until an operator migrates them, so an image that starts on Render can still fail on them (an entrypoint that switches user or chowns its data).

## Evidence

A read-only count of production's App resources on 2026-11-17 (pin `db48cde2bae9`, `kubectl get apps.app.bex.co -A` on the control plane), for w32/m462 t003 step 4:

- Docker services (`runtime: docker` or `builder: dockerfile`) on the strict policy: **2** (one Running, one Hibernated). On `render-v1`: 9.
- Prebuilt image services on the strict policy: **6** (one Running; the rest Failed, Canceled or suspended). On `render-v1`: 1.
- Also strict, and outside both groups: 3 legacy hand-applied Apps with `builder: auto` and no runtime, and one direct App with no control-plane row.

w32/m462's `--all-native` mode selects native runtime services only. The per-service `/api migrate-container-policy <srv-id> [--apply]` already admits Docker and image services.

## Steps

1. Add an `--all` mode to `/api migrate-container-policy` (`lego/backend/cmd/api/migrate_policy.go`), or widen `--all-native`'s selection behind a flag, so one operator run plans and applies every service but a static site (`runsContainerPolicy`), one at a time, with the same per-service JSON lines and summary. Test the selection.
2. After it reaches production, run the plan in the bex-api pod, apply it, and record the counts: migrated, no-op, refused with reasons. Check that each migrated service rolled once as a `settings_change` deploy and kept its status.
3. Record the outcome in ADR089 § Privilege slice decisions item 6.

End state: no Docker, image or native service with a control-plane row runs `strict-v1` or `""` on production, except those the run refused, each with its reason recorded.

Source: w32/m462 t003 step 4, 2026-11-17.
