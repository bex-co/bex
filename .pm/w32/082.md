# A built native web service's deploy log goes silent between `==> Build successful 🎉` and its verdict, where Render writes `==> Deploying...` and `==> Running '<start command>'`

Why: Render parity in the deploy log. During the rollout a bex log shows nothing for up to a minute, where Render's log names the deploy step and the start command it runs. The start command is the first thing a user checks when a deploy fails.

- **Severity / estimate:** minor, likely more than 1h: an operator fact plus backend narration. Promote to a milestone when picked up if it is.
- **Seen:** routine `cli-qa`, 2026-11-22, production pin `89642635b9ce`, released `bex` v0.9.0, `bex-canary`. A free native Node service whose start command is `true`:
  - logged `==> Build successful 🎉` at 09:11:43
  - then nothing for 55 s
  - then `==> Exited with status 0` at 09:12:38
- **Render reference (public issue logs):**
  - DerekSopok/EMS-Kahoot#3 (2026-02-01): `Build successful 🎉`, then `==> Deploying...` 34 s later, then `==> Running 'npm start'`, then `Exited with status 1` and the troubleshooting line.
  - rkendel1/freq#187 (2026-07-14) also shows `==> Deploying...`.
- **Cause (from the routine worker, unverified):** `progressLines` (`lego/backend/internal/logs/progress.go:352-421`) narrates only observed moments. No recorded moment marks a built deploy's rollout start, or the container start of its start command. bex writes neither line anywhere today.
  - `build_ended` in `service_event_facts` is a candidate anchor for `==> Deploying...`.
  - `==> Running '<cmd>'` probably needs a new operator fact for the container start.
- **Scope check:** decide which service types Render prints these lines for:
  - web services: shown above
  - private services and background workers: likely the same
  - static sites: none (no start command)
  - image-backed services: `Deploying...` but no build step

## Acceptance

- `bex logs --type build` on a free native web service shows `==> Deploying...` after `Build successful 🎉`, and `==> Running '<start command>'` before the verdict.
- Each line is anchored on an observed moment, never synthesized from row timestamps.
- Unit tests cover each line's presence and absence by service type and outcome.
- A live check in `bex-canary` with the released `bex` runs once the production pin carries the fix. Delete the fixtures.
