# A static site's deploy log closes with `==> Your service is live 🎉`, where Render's reads `==> Your site is live 🎉`

Why: the last line of a static site's deploy log is how a user (and a script tailing `bex logs --type build`) learns the site went out, and on bex it uses the web service wording instead of Render's static site wording.

- **Severity / estimate:** minor, ~30m. Only the wording differs: the deploy goes `live` and the site serves.
- **Versions:** released `bex` v0.9.0 (Render CLI v2.36.0). Production pin `89642635b9ce`: the `bex-system` pods run `sha256:c103a602e076…`, read on the control plane.
- **Context:** routine `cli-qa`, 2026-11-22 09:04–09:08 UTC, `https://api.bex.co/v1/`, workspace `bex-canary`, human device login, non-TTY text and JSON output. The journey was w8/392's overlap (`e737de697`): two deploys of a no-build static site, the second triggered 3 s after the first read `build_in_progress`. That part held. The first went `live` and was never `canceled`, its `--wait` exited 0, and the second stayed `queued` until then and went `live` after.
- **Repro:**
  - `bex services create --name qa-20261122-f4ce-static --type static_site --repo https://github.com/bex-co/bex --branch main --root-directory examples/static-site --publish-directory . --confirm -o json` exits 0 with `srv-dc1b08r88nrc738n1l0g`.
  - After seven deploys (the create's and six `bex deploys create` triggers), `bex logs -r srv-dc1b08r88nrc738n1l0g --type build --start 2026-11-22T09:04:30Z -o json` has 21 lines. Every deploy reads the same three (oldest first):

    ```text
    2026-11-22T09:06:42.058501Z ==> Build queued
    2026-11-22T09:06:45.585045Z ==> Building from https://github.com/bex-co/bex@24b25a6
    2026-11-22T09:06:59.3608Z   ==> Your service is live 🎉
    ```

  - The fixture was deleted by ID right after: `bex services delete <id> --confirm` exited 0, `bex deploys list <id>` answered `404 Not Found`, the URL answered `404`, and no App CR or pod remained.

- **Render:** deploy logs pasted into GitHub issues end a static site's deploy with `==> Uploading build...` and then `==> Your site is live 🎉`. Examples: muppetbrown/mana_meeples_singles_market#226 (`2025-10-19T21:06:46.47782918Z ==> Your site is live 🎉`, after a Vite build) and notwo/youknowFrontend_graveyard#84 (2023-12-07). A raw Render static site log quoted in 1kz-ma1/HINANEX#373 (2026-11-16) reads `Your site is live` at `01:58:32Z`. A web service's log keeps `==> Your service is live 🎉`.
- **Attribution:** server (bex-api log synthesis). The CLI prints what `GET /v1/logs` returns.
- **Root cause:** `terminalLine` (`lego/backend/internal/logs/progress.go:691`) returns `==> Your service is live 🎉` for `live` and `deactivated` for every type except `cron_job`. `progressContext.serviceType` is the App's `Spec.Type` (`:226`), so `static_site` already reaches it. Nothing matches the text: `rg "is live"` over `lego` and `dashboard/src` finds no consumer outside the tests.
- **Fix:**
  - `terminalLine` returns `==> Your site is live 🎉` for `appv1alpha1.TypeStaticSite`.
  - Every other type keeps its line: web, private and worker keep `Your service is live`, and `cron_job` keeps its scheduled line.
  - REST `/v1/logs`, the subscribe/tail stream, GraphQL `logs`, MCP and the dashboard's deploy log panel share this synthesis, so the one change reaches all of them.
  - Update the terminal `live` row of `docs/render-artifacts/live-deploy-following.md:71` and the ADR018 § Logs, Build logs row.
- **Blast radius:** one function, used by `closingLines` for every deploy row. A static site's native build (with a build command) and a no-build publish both close through it. A `deactivated` deploy keeps its live line by design.
- **Regression checks:**
  - Extend `TestQueryLogsProgressTerminalLineIsTypeAware` (`lego/backend/internal/logs/logs_test.go:881`) with `TypeStaticSite` → `==> Your site is live 🎉`. Keep the `web_service` and `cron_job` cases. Reverting the fix must fail it.
  - Live in `bex-canary`, on a free no-build static site from `bex-co/bex` (`examples/static-site`, publish directory `.`), `bex logs -r <srv> --type build -o text` ends with `==> Your site is live 🎉`. A free web service control still ends with `==> Your service is live 🎉`. Delete the fixtures by ID and confirm the 404s.
- **Unverified:**
  - No Render account was used.
  - Render's full narration of a static site with no build command is not observed here. That includes `==> Empty build command; skipping build` and whether `==> Uploading build...` precedes the verdict; w8/395 records the same gap. This note changes only the verdict.
- **Dedupe:** `rg -i "site is live"` over `.pm`, `docs` and `lego` finds only w32/028's mention of Render's static deploy ("one build step from clone to 'Your site is live'"), which changed statuses and not this line. `git log -S "Your site is live"` finds no fix. Nothing open covers it, and it is not deploy lag.
