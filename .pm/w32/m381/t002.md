## Objective

Implement t001's mechanism so that a sandbox with a command in progress is never idle-suspended, connected or not. Its idle window starts when the command ends.

## Context

- Repro: `--idle-timeout 300`, `timeout 5 bex sandboxes exec <sbx> -- bash -c 'sleep 480; …'`. The sandbox suspended at +330 s and the command was killed (milestone README).
- `idle.go:485` `suspendIfIdle` and the claim/pause path. The pause commits the rootfs and deletes the pod (ADR042 D5).

## Steps

1. Feed the in-progress signal into `suspendIfIdle` before it claims a pause, without waking or resuming anything.
2. Touch activity when the command ends, so the window runs from its end, as on Render.
3. Keep a finished command's background processes out of the signal.
4. Bound the cost: only sandboxes already past their idle window are checked.

## Files

## Acceptance criteria

- [ ] A test with a disconnected, still-running command shows no pause is claimed, and that a pause follows once the command ends and the window passes.
- [ ] A test shows a background process left by a finished command does not hold the sandbox awake.

## Out of scope

- Agent-session sandboxes, which never idle-suspend (t004 records them).
