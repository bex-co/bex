## Objective

Wire `store.Deploy.Repo` and `store.Deploy.Branch` through `logs.DeployProgress` and update `buildProgressLines` so each deploy narrates `==> Build queued`, `==> Building from <repo>@<sha|branch>`, and `==> Deploying...` from its own recorded source instead of the service's current `App.Spec`, while keeping a safe fallback for pre-migration rows.

## Context

- `logs.DeployProgress` (`lego/backend/internal/logs/progress.go:56-126`) carries per-deploy facts adapted from `store.Deploy` in `lego/backend/internal/api/server.go:1017-1050`.
- `buildProgressLines` (`lego/backend/internal/logs/progress.go:421-508`) currently does:
  - line 422: `repo := pc.repo`
  - line 438: `built := repo != ""` (narrowed by `&& d.Built` when `!d.FinishedAt.IsZero()`)
  - line 464: `ref = pc.branch` when `d.Commit == ""`
  - line 492: `rolloutLinesWith(d, repo != "" && d.Built, includeClosing)` — note this ALSO uses `repo != ""`!
- Because `logID` hashes `(instance, timestamp, message)`, preserving the exact message preserves the exact deterministic `id` across reads and live tails.
- All log surfaces (REST `GET /v1/logs`, SSE/WebSocket `/v1/logs/subscribe`, GraphQL `logs`, MCP `list_logs`, CLI `bex logs`, and dashboard `useDeployLogs`) read `buildProgressLines`.

## Steps

1. Add `Repo string` and `Branch string` to `logs.DeployProgress` (documented like `DetectedHTTPPort`: saved on this deploy, never borrowed from the current App when recorded) and wire `Repo: r.Repo, Branch: r.Branch` in `lego/backend/internal/api/server.go:1041`.
2. In `buildProgressLines` (`lego/backend/internal/logs/progress.go:421-493`):
   - Resolve `repo` and `branch` per deploy:
     - When `d.Repo != ""`, use `repo = d.Repo` and `branch = d.Branch` (never borrow `pc.branch` when `d.Repo != ""` and `d.Branch` is set; decide cleanly if `d.Branch == ""` on a row with `d.Repo != ""`).
     - Fall back to `pc.repo` and `pc.branch` ONLY for pre-migration rows where `d.Repo == ""` (and ensure a prebuilt-image deploy with `d.Image != ""` does NOT borrow `pc.repo` if the service later switches from prebuilt image to Git!).
   - Ensure `built` (lines 438-441) and `rolloutLinesWith` (line 492) both use the resolved per-deploy `repo` so:
     - A historical Git deploy (`d.Repo != ""`, `d.Built == true`) still renders `==> Build queued`, `==> Building from <d.Repo>@<sha|d.Branch>`, and `==> Deploying...` even after the service switches to a prebuilt image (`pc.repo == ""`).
     - A historical Git deploy (`d.Repo != ""`) keeps its original `d.Repo` and `d.Branch` — and identical `logID`s — after the service switches `--repo` or `--branch`.
     - A historical prebuilt-image deploy (`d.Repo == ""`, `d.Image != ""`) keeps `==> Deploy queued` and `==> Deploying image <d.Image>` even after the service switches to a Git repo (`pc.repo != ""`).
     - A pre-migration Git deploy (`d.Repo == ""`, `d.Image == ""`) still falls back to `pc.repo` / `pc.branch`.
3. Check `progressFollower` and `synthesizeProgress` for any other reads of `pc.repo` or `pc.branch` (none expected beyond `buildProgressLines`, verify via grep).
4. Add unit tests in `lego/backend/internal/logs/` and adapter/API tests in `lego/backend/internal/api/` covering all cases above, including unchanged `id`s across source switches and REST/GraphQL/MCP/subscribe agreement.

## Acceptance criteria

- [x] Switching `App.Spec.Repo` from repo A to repo B leaves a historical deploy's `==> Building from <repo A>@<sha>` message and `id` unchanged.
- [x] Switching `App.Spec.Branch` from branch A to branch B leaves an unresolved-commit historical deploy's `==> Building from <repo A>@<branch A>` message and `id` unchanged.
- [x] Switching a Git service to a prebuilt image (`App.Spec.Repo = ""`) leaves a historical Git deploy's `==> Build queued`, `==> Building from <repo A>@<sha>`, `==> Deploying...`, and their `id`s unchanged.
- [x] Switching a prebuilt-image service to a Git repo leaves a historical image deploy's `==> Deploy queued` / `==> Deploying image <image>` unchanged.
- [x] Pre-migration fallback (`d.Repo == ""`, `d.Image == ""`) still narrates from `pc.repo` / `pc.branch`.
- [x] `cd lego/backend && go test ./...` and `make lint` pass.

## Done (2026-11-24)

Added `Repo` and `Branch` to `logs.DeployProgress`, wired them in `lego/backend/internal/api/server.go`, and added `deploySource(d, pc)` in `lego/backend/internal/logs/progress.go` so `buildProgressLines` (including `built`, `==> Building from …`, and `rolloutLinesWith`) uses each deploy's recorded source when `d.Repo != ""`, never borrows `pc.repo` when `d.Image != ""`, and falls back to `pc.repo`/`pc.branch` only for pre-migration rows (`d.Repo == "" && d.Image == ""`). Verified across REST, GraphQL, MCP, SSE, and WebSocket subscribe in `progress_source_test.go` and `deploy_source_progress_test.go`.
