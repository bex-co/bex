# `GET /v1/logs/values` (and GraphQL `logLabelValues`, MCP `list_log_label_values`, dashboard filter pickers) never translates public `instance` IDs to pod names, returning `[]` for every public `instance=` filter

Why: `Service.labelValues` (`lego/backend/internal/logs/service.go:1443-1516`) and `Service.datastoreLogLabelValues` (`service.go:1535-1566`) project returned `instance` values from raw Kubernetes pod names to public `srv-…` / `red-…` / `dpg-…` instance IDs via `projectLogLabelValues` (`:1510`, `:1550`), but never call `translateInstanceFilter` on the incoming `q.Instance` filter before querying `s.LabelValues(ctx, namespace, label, part)` (`:1502`, `:1545`). Any caller passing an emitted public instance ID in `instance=` queries Loki with `pod="srv-…"` against streams labelled with raw pod names and gets `200 []` for every label (`level`, `type`, `instance`, etc.); additionally, `datastoreLogLabelValues`'s pod-list fallback (`:1557-1565`) ignores `q.Instance` completely.

- **Severity / estimate:** **major**, ~35m. Every REST `GET /v1/logs/values`, GraphQL `logLabelValues`, MCP `list_log_label_values`, and dashboard Log Explorer / Edit View filter-picker lookup returns `[]` whenever an `instance` filter is set (even to the resource's own active public instance ID returned by `GET /v1/logs/values?label=instance` or `bex logs`).
- **Versions:** verified against `https://api.bex.co/v1/` (production pin `ff5de0a130e6`, `d9dd27d687`) with `User-Agent: render-cli/v2.38.0`; `main` verified through `7acae8c9e7` (`labelValues` and `datastoreLogLabelValues` unchanged).
- **Context:** routine `cli-qa` sweep `590f`, 2026-11-24 11:00–11:26 UTC, `https://api.bex.co/v1/`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), human device login (`bex login`).

## Attribution and root cause

- **Attribution:** server (`lego/backend/internal/logs/service.go`).
- **Root cause:**
  - `Service.QueryLogs` (`service.go:1121`) and `Service.queryDatastoreLogs` (`service.go:1269`) both call `s.translateInstanceFilter(ctx, resource, namespace, &q, candidatesFromPods(pods))` so public instance IDs (`srv-…`, `red-…`, `dpg-…`) are mapped to raw Kubernetes pod/deploy names before querying Loki.
  - `Service.labelValues` (`service.go:1443-1516`) and `Service.datastoreLogLabelValues` (`service.go:1535-1566`) skip `translateInstanceFilter` entirely. They pass `q` directly into `s.LabelValues(ctx, namespace, label, part)` (`:1502`, `:1545`), so `part.Instance` contains the public instance ID while Loki's `pod` label holds the raw Kubernetes pod name. Only the output values are projected (`projectLogLabelValues`, `:1510`, `:1550`).
  - Similarly, `progressInstanceValues` (`service.go:1509`, `progress.go`) checks `q.keepPod(d.ID)`, which also fails for public deploy-progress instance IDs unless `translateInstanceFilter` has already mapped them to `d.ID`.
  - In `datastoreLogLabelValues` (`:1557-1565`), the fallback path when `s.LabelValues == nil` lists live pods and projects every pod name without checking `q.keepPod(pods[i].Name)`, ignoring `q.Instance` completely.

## Fix

- In `Service.labelValues` (`lego/backend/internal/logs/service.go:1443-1516`):
  - Before splitting/querying `s.LabelValues` or calling `progressInstanceValues`, when `len(q.Instance) > 0`, gather best-effort live pod candidates from `s.ownPods(ctx, appNS, app)` (ignoring list errors just like other best-effort paths) and call `s.translateInstanceFilter(ctx, resource, appNS, &q, candidatesFromPods(pods))`.
  - Also verify that if `translateInstanceFilter` collapses an unmatched positive `q.Instance` to `noSuchInstance`, `labelValues` returns `[]` cleanly (including for `progressInstanceValues` and `type=build`).
- In `Service.datastoreLogLabelValues` (`lego/backend/internal/logs/service.go:1535-1566`):
  - When `len(q.Instance) > 0`, list live pods via `target.list(ctx, target.ns, target.name)` (best-effort) and call `s.translateInstanceFilter(ctx, resource, target.ns, &q, candidatesFromPods(pods))` before calling `s.LabelValues`.
  - In the `s.LabelValues == nil` fallback (`:1557-1565`), filter listed pods through `q.keepPod(pods[i].Name)` before projecting and returning them.
- Shares `translateInstanceFilter` with `w32/114`, so once `w32/114` lands, wildcard (`*`) and `/RE2/` regex `instance=` filters work identically on `/v1/logs/values`, `logLabelValues`, and `list_log_label_values` as well.
