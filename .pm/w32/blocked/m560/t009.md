## Objective

Check that every surface that reads a deploy's log shows the same three lines:

- REST `GET /v1/logs?type=build` and `GET /v1/logs/subscribe`;
- the GraphQL logs query;
- MCP `list_logs`;
- the dashboard's deploy page log pane;
- `bex logs`.

They all read one synthesis in `logs.Service`. Compare each with Render's logs in the milestone README.

## Follow-ups to file with `/pm add w32` (each with its evidence)

- **The primary URL block under Render's live line.** Render follows `==> Your service is live 🎉` with `==> `, a `///` rule, `==> Available at your primary URL https://<service>.onrender.com` and another rule (lelewithheart/Pixel-Breach#10 and 20 more logs found by that phrase). bex writes none of it.
- **The new instance's output in the deploy log.** Render's deploy log carries it between `Deploying...` and the verdict, such as rkendel1/freq#187's traceback before `Exited with status 1`. bex's `type=build` carries none of it.
- **Any unknown from the milestone README that is still open:** a worker's, private service's, prebuilt image's or pre-deploy deploy log, or Render's log `type` for these lines.
