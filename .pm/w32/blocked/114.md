# `bex logs --instance` (and REST `/v1/logs`, `/v1/logs/subscribe`, GraphQL `logs`, MCP `list_logs`, project views) silently returns empty for every `*` wildcard and `/RE2/` regex selector

Why: `LogQuery.validateFilterPatterns` (`lego/backend/internal/logs/filterpattern.go:55`) explicitly accepts `*` wildcards and `/RE2/` regular expressions for `q.Instance` (rejecting malformed regexes with `400`), matching Render's log filter syntax, but `translateInstanceFilter` (`lego/backend/internal/logs/service.go:2854`), `followPods` (`service.go:2251`), and `collectPreDeployLogs` (`service.go:3034`) resolve `q.Instance` through `ids.ResolveInstanceSelectors` (`lego/backend/internal/id/instance.go:103-121`), which only performs exact equality (`MatchServiceInstance`) and rejects multi-candidate matches (`instance.go:87-89`). Every `*` or `/RE2/` instance selector therefore fails to resolve, collapses to `noSuchInstance` (`service.go:2855-2860`), and silently returns zero lines on history and `--tail` (and excludes nothing on negated `INSTANCE IS_NOT` project-view filters).

- **Severity / estimate:** **major**, ~45m. Every `*` wildcard and `/RE2/` regex `--instance` filter silently returns exit `0` with `0` lines across services and datastores on both historical reads and `--tail`, even though the API validates regex syntax on `instance` and accepts the exact same wildcard/regex syntax on sibling filters (`--status-code`, `--host`, `--path`).
- **Versions:** isolated checkout `bex` built from `lego/cli` at `a7a5695fd5` (pinned Render CLI `v2.38.0`, upstream `09b7802aa379c92a087884412d88b2b3f8a75a9a`) and installed `/home/tp/.local/bin/bex` `v0.3.3` (Render CLI `v2.27.0`); production running pin `ff5de0a130e6` (`d9dd27d687`); `main` verified through `7acae8c9e7` (`translateInstanceFilter`, `followPods`, and `collectPreDeployLogs` unchanged).
- **Context:** routine `cli-qa` sweep `590f`, 2026-11-24 11:00–11:26 UTC, `https://api.bex.co/v1/`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), human device login (`bex login`), non-TTY `-o json`.

## Attribution and root cause

- **Attribution:** server (`lego/backend/internal/logs/`). The pinned Render CLI (`cmd/logs.go:83`, `pkg/logs/repo.go:26,40`) passes `--instance` verbatim as `instance=` query parameters.
- **Root cause:**
  - `LogQuery.validateFilterPatterns` (`lego/backend/internal/logs/filterpattern.go:49-68`, line `55`) explicitly validates `q.Instance` as a wildcard (`*`) / RE2 (`/regex/`) filter per Render's log filter contract (`docs/ADR010-observability.md`, `w8/176`, `w3/m523`).
  - `translateInstanceFilter` (`lego/backend/internal/logs/service.go:2813-2863`, line `2854`), `followPods` relist (`service.go:2251`), and `collectPreDeployLogs` (`service.go:3034`) pass `q.Instance` to `ids.ResolveInstanceSelectors` (`lego/backend/internal/id/instance.go:103-121`), which loops over `ResolveInstanceSelector` (`instance.go:75-96`) → `MatchServiceInstance` (`instance.go:55-69`).
  - `MatchServiceInstance` checks only exact string equality (`candidate == podName || candidate == ServiceInstanceID(...) || candidate == LegacyServiceInstanceID(...)`), and `ResolveInstanceSelector` also refuses any selector matching more than one candidate (`instance.go:87-89`).
  - Every `*` wildcard or `/RE2/` regex therefore matches zero candidates, `ResolveInstanceSelectors` returns `nil`, and `translateInstanceFilter` (`service.go:2855-2860`) replaces `q.Instance` with `[]string{noSuchInstance}`. On positive filters this silently empties every result; on negated project-view filters (`INSTANCE IS_NOT` with `*` or `/regex/`, `w3/m523`) it collapses to excluding `noSuchInstance`, which excludes nothing instead of excluding matching instances.

## Fix

- Keep `ids.ResolveInstanceSelector` strict/unique for SSH and single-pod callers (`lego/backend/internal/id/instance.go`).
- Add a pattern-aware instance resolver in `lego/backend/internal/logs/` (reusing `filterpattern.go`'s `labelValueAlternative` / RE2 matcher) that evaluates each selector in `q.Instance` against each authorized candidate's public ID (`ids.ServiceInstanceID(resourceID, c.Name)`), legacy UID ID (`ids.LegacyServiceInstanceID(resourceID, c.UID)` when non-empty), and raw `c.Name`, returning **all** matching candidate names (deduplicated, bounded to the authorized resource's candidate set). Exact selectors continue to resolve identically; unmatched selectors still collapse to `noSuchInstance` (and negated `IS_NOT` filters exclude every matched candidate).
- Wire the pattern-aware resolver into all three log sites:
  1. `translateInstanceFilter` (`lego/backend/internal/logs/service.go:2854`) — automatically covers `QueryLogs` (`:1121`), `queryDatastoreLogs` (`:1269`), `followLogs` (`:1667`), `followDatastore` (`:2098`), and (once `w32/115` wires `translateInstanceFilter`) `labelValues` / `datastoreLogLabelValues`.
  2. `followPods` relist (`service.go:2251`) — note that when a live tail runs with a wildcard/regex selector and a new pod rolls in, `followPods` must keep the original pattern selectors (or re-evaluate them against the updated pod list) rather than locking onto the initial resolved pod names at subscribe start, so newly created pods matching the wildcard/regex are followed too.
  3. `collectPreDeployLogs` (`service.go:3034`).
- Update `lego/backend/internal/logs/mcp.go:54` `Instance` jsonschema description so MCP clients know `*` wildcards and `/regex/` patterns are supported alongside exact IDs.

## Blast radius

- Affects every log read surface sharing `internal/logs`: CLI `bex logs` (history & `--tail`), REST `GET /v1/logs` and `GET /v1/logs/subscribe`, GraphQL `logs` (single-resource & project views, `IS` and `IS_NOT`), MCP `list_logs`, across services (app, build, pre-deploy, request), Postgres, and Key Value.
- Double-check `followPods` (`service.go:2240-2265`): `translateInstanceFilter` currently mutates `q.Instance` in place before `followPods` starts, so a live `--tail` with `--instance '*'` or `--instance 'srv-…-abc*'` would miss pods created after subscribe start unless the original pattern selectors are preserved for pod relisting.
- Do not loosen `ids.ResolveInstanceSelector` (used by SSH / single-instance exec where uniqueness is a security and correctness invariant).
