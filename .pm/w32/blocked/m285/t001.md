## Objective

Amend ADR014/ADR042 with the snapshot design: a filesystem snapshot is an OCI image committed from a running sandbox's rootfs (the D5 mechanism w2/m278 uses for suspend), stored per workspace with Render's lifecycle, and `--kind runtime` (Render's default) answers a named refusal recorded as a divergence awaiting the user's sign-off.

## Context

- Render (render.com/docs/sandboxes-snapshots): kinds `runtime` (default; memory+CPU state) and `filesystem`; capture needs a running sandbox and does not terminate it; status `creating`/`available`/`failed`; 30-day default expiry, custom expiry at capture; names 1–64 chars, not starting `snp-`, case-sensitive, latest available wins on reuse; restore creates a new sandbox, inherits plan/policy/timeouts, env not preserved; delete refused while creating; capture rate limit 10/min
- ADR042 D5: rootfs commit to OCI + pod recreate; commit Jobs run in `opensandbox-snapshot` namespace (w3/m42 patch)
- w2/m278 has the related 'what a suspended sandbox keeps' divergence awaiting sign-off (ADR018 § Sandbox create flags)
- IDs: `snp-` minted via `lego/backend/internal/id` (`id.New`)
- Render snapshots are scoped to a sandbox group; groups are a bex non-goal, so scope to the workspace

## Steps

1. Read w2/m278's final mechanism and reuse it.
2. Specify storage (registry repository per workspace), metadata (Postgres table), expiry and purge, quotas/rate limit, and billing (whether stored snapshots are metered; follow Render's pricing page).
3. Record the runtime-kind refusal and the divergence row in ADR018 with sign-off status pending.
4. Remove the `[-]` 'non-goal at this pin' grade rationale in the checklist in favor of the target.
