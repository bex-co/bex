## Objective

Serve Render's snapshot capture: `POST /v1/sandboxes/{id}/snapshots` with `kind` (filesystem; runtime refused by name), `name` and optional expiry; commit the rootfs without terminating the sandbox, track `creating` → `available`/`failed`, and enforce the rate limit and name rules.

## Context

- Pinned OpenAPI snapshot operations (`lego/backend/internal/api/openapi/render-public-api-1.json`)
- Today `/sandboxes/{id}/snapshots` answers a named 404 (`SANDBOX_SNAPSHOTS_UNSUPPORTED`)
- CLI `bex sandboxes snapshots create --kind --name --wait`

## Steps

1. Add the migration and store for snapshots (`snp-` ids).
2. Drive the commit through OpenSandbox / the commit Job without stopping the sandbox.
3. Validate name and expiry; refuse `runtime` and `snp-`-prefixed names by name; apply the 10/min capture limit.
4. Mount REST, GraphQL and MCP through one service path.

## Files

- lego/backend/internal/sandbox/*.go
- lego/backend/internal/store/ (migration)
- lego/backend/internal/api/render_openapi.go

## Acceptance criteria

- [ ] `bex sandboxes snapshots create <id> --kind filesystem --name base --wait` ends `available` and the sandbox keeps running
- [ ] `--kind runtime` and an invalid name answer named 400s
