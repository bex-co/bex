# Mixed-resource and project-scoped log reads (`bex logs -r srv-…,red-…`, `GET /v1/logs?project=…`) fail with `400` or leak datastore lines when a datastore meets `--type`, request, or `build` filters

Why: Render's CLI advertises viewing and filtering logs across multiple services and datastores at once (`bex logs -r srv-…,red-… --type app`), and Render's project-scoped log reads cover services alongside Postgres and Key Value, so rejecting the whole query with `400` whenever a datastore shares the scope breaks core multi-resource and project log debugging.

- **Root cause:**
  1. `lego/backend/internal/logs/project.go:211-225` (`keepLogResourceForTypes`): only excludes datastores for exact singletons `slices.Equal(types, []string{LogTypeRequest})` and `slices.Equal(types, []string{LogTypeBuild})`. It ignores request filters (`q.requestFilters()`), `q.Build`/`q.Deploy`, and multi-type sets without `app` (such as `type=request&type=build`), so `resolveLogScope` keeps datastores in `resolved.IDs`. On `project=…&statusCode=200` (no `type`), `forResource` leaves `StatusCode` set and `datastoreFilters` (`service.go:1321-1330`) returns `400`; on `project=…&type=request&type=build`, `forResource` clears `q.Types = nil` and leaks datastore process logs into a request+build query.
  2. `lego/backend/internal/logs/project.go:241-243,266-272` (`resolveLogScope`, `LogQuery.forResource`): explicit multi-resource queries (`resource=srv-…&resource=red-…`) return early with `q.projectScope = false`, so `forResource` never strips `type=app` for datastores, and `queryLogPage` (`render.go:221`), `logsSubscribe` (`rest.go:263-269` → `checkLiveSubscribable` at `rest.go:344-357`), `logsValues` (`rest.go:141-153`), GraphQL (`graphql.go:213-286`), and MCP (`mcp.go:156-226`) run every datastore through `datastoreFilters` (`service.go:596-598,1292,1321-1330`) and fail the entire mixed request with `400`.
  3. `lego/backend/internal/logs/rest.go:142` and `mcp.go:222`: skip datastores for non-datastore labels only when `resolved.Scoped`, so explicit multi-resource `logs/values` (`resource=srv-…&resource=red-…&label=statusCode`) fails with `400`.
  - Pinned consumer: `github.com/render-oss/cli@v1.1.3-0.20261117005113-11ef59f330de` `cmd/logs.go:77-90`, `pkg/tui/views/logloader.go:148-185`, `pkg/logs/repo.go:26-42`, `pkg/logs/tail.go:214-216` send repeated `resource=` query params alongside `type`, `statusCode`, `method`, `path`, `host` to `/v1/logs` and `/v1/logs/subscribe`.
- **Fix:**
  1. Replace `keepLogResourceForTypes(q.Types)` in `lego/backend/internal/logs/project.go` with query-aware filtering (`keepLogResourceForQuery(q)`): exclude datastores (`KindPostgres`, `KindKeyValue`) whenever `len(q.requestFilters()) > 0`, `len(q.Build) > 0`, `q.Deploy != ""`, or `len(q.Types) > 0 && !slices.Contains(q.Types, LogTypeApp)`.   2. For explicit mixed resource sets (at least one App resource and at least one datastore in `resolved.IDs`):
     - Always authorize every explicitly named resource (preserving `403`/`404` for forbidden, nonexistent, or deleting IDs).
     - Apply the same per-resource eligibility rule as project scope across `queryLogPage` (`render.go`), `logsSubscribe`/`checkLiveSubscribable` (`rest.go`), `logsValues` (`rest.go`), GraphQL `logs`/`logLabelValues` (`graphql.go`), and MCP `list_logs`/`list_log_label_values` (`mcp.go`): skip datastores when the query has request/build/deploy filters, excludes `app`, or asks `/logs/values` for a non-datastore label; strip `q.Types` on the datastore leg when `app` is included so datastores contribute their process logs alongside the App's `type=app` logs.
