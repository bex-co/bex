## Steps

1. After t001–t003 are shipped and production's pin carries the fix commit(s), verify `bex-api` pods are running the pinned image.
2. Sign in with the released `bex` CLI in `bex-canary` (human device login, isolated `BEX_CLI_CONFIG_DIR`).
3. Create a disposable free native Node web service from `https://github.com/bex-co/bex` (`--root-directory examples/hello-node`, `--plan free`, `--auto-deploy=false` or default) and wait for its initial deploy to reach `live`.
4. Read `bex logs -r <id> --type build -o json` and record the initial deploy's `==> Build queued`, `==> Building from https://github.com/bex-co/bex@<sha>`, and `==> Deploying...` lines and their exact `id` values.
5. Switch the service's repository:
   ```bash
   bex services update <id> --repo https://github.com/expressjs/serve-static --confirm -o json
   ```
   Re-read `bex logs -r <id> --type build --text "Building from" -o json` and assert the initial deploy still reports `==> Building from https://github.com/bex-co/bex@<sha>` with the identical `id`.
6. Switch the service to a prebuilt image (`docker.io/library/nginx:1.27-alpine`, `--confirm -o json`), re-read `bex logs -r <id> --type build -o json`, and assert the initial deploy still reports `==> Build queued`, `==> Building from https://github.com/bex-co/bex@<sha>`, and `==> Deploying...` with identical `id`s (and NOT `==> Deploy queued` / `==> Rolling out the current release`).
7. Before deleting the fixture, complete t005's cross-surface check on the same fixture.
8. Delete the fixture by ID (`bex services delete <id> --confirm`), confirm `404` on `GET /v1/services/<id>`, log out (`bex logout` + `scripts/qa-login.sh --logout`), and record the conclusion and reproduction steps in this task (no raw dumps in git).
