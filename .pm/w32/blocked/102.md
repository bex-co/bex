# `bex logs --tail` on a static site with `--type request` (or request filters) and any unhandled post-upgrade WebSocket error enters an infinite reconnect loop

Why: `followLogs` (`lego/backend/internal/logs/service.go:1556,1608-1616`) rejects a static site's request-only/request-filtered tail with `core.ErrBadRequest` after WebSocket upgrade, and `subscribeWebSocket` (`lego/backend/internal/logs/rest.go:735-741`) closes the socket with zero frames (1006 EOF) instead of `CloseTailRefused` (4000) for every post-upgrade error outside three sentinels, so Render CLI v2.29+ retries forever (`Unable to connect to logs. Retrying in Ns.` / `Log connection restored.`).

- **Severity / estimate:** **major**, ~45m. Every `bex logs -r <static-site> --type request --tail` (and `--status-code`, `--method`, `--path`, `--host` `--tail`, plus any multi-resource tail including a static site with request filters, or any post-upgrade `ErrBadRequest`/plan-gate error over WebSocket) loops indefinitely burning reconnects and subscription slots instead of staying open quietly (per `w4/585`) or exiting with a clear error.
- **Versions:** released `bex` v0.9.0 (`bex-0.9.0-linux-arm64.tar.gz`, compatible with Render CLI `v2.36.0`, upstream pin `4fd34231b637`) and checkout build of `lego/cli` at `5576321264` (pinned to Render CLI `v2.37.0`, `11ef59f330dedec290f8d71d89b8f7379bbbed09`); repo HEAD synced to `6069a53140`; production platform pin `9fdf7e0a1171` (`cded300699`). `lego/backend/internal/logs/service.go` and `rest.go` are unchanged through `6069a53140`.
- **Context:** routine `cli-qa` sweep `f4a9`, 2026-11-23 21:03–21:08 UTC, `https://api.bex.co/v1/`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), human device login (`bex login`), non-TTY `-o json`.

## Attribution and root cause

- **Attribution:** server (`lego/backend/internal/logs/`). The pinned Render CLI consumer (`github.com/render-oss/cli@v1.1.3-0.20261117005113-11ef59f330de`, `pkg/logs/tail.go:76-108,260-281`) behaves per its documented v2.29+ contract: non-101 4xx handshake errors and non-retryable WebSocket close codes (such as `4000` `CloseTailRefused`) are terminal, whereas raw EOF / `1006` (`CloseAbnormalClosure`) / `1000` retry with exponential backoff (1s → 2s → 4s → … → 30s) and print `Log connection restored.` on each subsequent `101`.
- **Root cause (two interacting defects in `lego/backend/internal/logs/`):**
  1. **`service.go:1543-1616` (`followLogs`):**
     - `q.liveSubscribable()` (`:1543`, and pre-upgrade in `rest.go:266` `checkLiveSubscribable`) runs before `dropStaticSiteRequests(app, &q)` (`:1556`). For `--type request` or any request filter (`--status-code`/`--method`/`--path`/`--host`, which `:596-607` routes to `q.Types = ["request"]`), `liveSubscribable()` admits the query.
     - `:1556` calls `dropStaticSiteRequests(app, &q)`, setting `q.noRequest = true`.
     - `:1565` checks `if q.onlyRequest() && s.History == nil` without accounting for `q.noRequest`, which would also falsely return `ErrLogStoreUnavailable` on a store-less deployment for a static site that never polls the store.
     - `:1608-1616` checks `if !q.wants(LogTypeApp) && !q.wants(LogTypeRequest)` — because `q.Types == ["request"]`, `q.wants(LogTypeApp)` is `false`, and because `q.noRequest == true`, `q.wants(LogTypeRequest)` (`:523`) is ALSO `false`. The static site falls into the `codex #3` backstop (`:1615`) and returns `core.ErrBadRequest` instead of reaching `followPods` (`:1620`), where `tailPods` (`:2122`) and `pollRequests` (`:2126`) are both `false` so it would stay open cleanly on keepalives as the comment at `:1554-1555` states.
     - `w4/585`'s test (`TestAStaticSiteHasNoRuntimeLogs`, `live_filters_test.go:384-418`) tested `QueryLogs` with `Types: ["request"]` but only tested `FollowLogs` with empty `Types`.
  2. **`rest.go:735-741` (`subscribeWebSocket`):**
     - `subscribeWebSocket` only emits the `==>` refusal Log frame and `CloseTailRefused` (`4000`) close frame when `followErr` matches three hardcoded sentinels: `ErrBuildNotRunning`, `core.ErrLogsUnavailable`, or `core.ErrLogStoreUnavailable`.
     - Any other non-`context.Canceled` error returned by `follow(...)` after `wsUpgrader.Upgrade` — including `core.ErrBadRequest` (e.g. `:1615`, `compileLevelFilter` at `:1557`), Hobby-plan `core.NewPlanFeatureError` (`requireRequestLogsPlan` at `:1546,765` — which `logsSubscribe` does **not** check before upgrading!), `scopeToBuilds` errors (`:1550`), or post-upgrade `ErrNotFound`/`ErrForbidden` (e.g., watchdog revocation, deletion mid-tail, or `followProjectScope`/`followProject` errors) — falls through to `defer conn.Close()` with zero frames (`1006`), triggering an infinite CLI reconnect loop. Compare `subscribeStream` (`rest.go:846-849`), which already handles **every** `err != nil && !errors.Is(err, context.Canceled)`.

## Fix

1. **`lego/backend/internal/logs/service.go` (`followLogs`):**
   - Keep `w4/585`'s contract for static sites across every non-build tail: when `dropStaticSiteRequests(app, &q)` returned `true` (static site) and `q.Types` is request-only (e.g. `type=request` or routed from request filters), do **not** trip `:1565` (`onlyRequest() && s.History == nil`) or `:1608-1616` (`!q.wants(LogTypeApp) && !q.wants(LogTypeRequest)`). Let it proceed to `followPods` (or an explicit keepalive wait) where `tailPods` and `pollRequests` are both `false`, so it stays open quietly on keepalives until the client disconnects or authorization ends, matching unfiltered `bex logs -r <static> --tail` (`:1554-1555`). Keep the `:1608-1616` backstop intact for genuinely non-live types (`type=predeploy`).
2. **`lego/backend/internal/logs/rest.go` (`subscribeWebSocket` and `logsSubscribe`):**
   - In `subscribeWebSocket` (`:735-741`), emit the `==>` refusal Log frame and send `CloseTailRefused` (`4000`) with `closeReason(followErr)` for **every** non-nil `followErr` that is not a normal client disconnect (`!errors.Is(followErr, context.Canceled)` and not a write/socket error from the client having already closed `conn`), rather than whitelisting only three sentinels. (Ensure `followErr` from `conn.WriteMessage` / `conn.WriteControl` when the peer disconnects does not write back onto a dead socket, and keep `CloseTailRefused` text free of internal leakage.)
   - Also audit `logsSubscribe` (`rest.go:256-318`): check whether Hobby-plan `requireRequestLogsPlan` (`service.go:1546`) should also be enforced before `wsUpgrader.Upgrade` (returning HTTP 403 `PLAN_REQUIRED` directly, matching `w8/083`'s pre-upgrade refusal pattern) as well as being safely terminated by `CloseTailRefused` (4000) in `subscribeWebSocket` if reached post-upgrade (e.g. via `projectSubscribe` / `followProjectScope`).
3. **Surfaces (REST/GraphQL/MCP/UI):**
   - REST `GET /v1/logs/subscribe` serves WebSocket (CLI), SSE (dashboard), and NDJSON (`curl`); fixing both `followLogs` and `subscribeWebSocket` repairs all three transports (SSE no longer emits the spurious `type=[request] has no live producer` error on a static site; WebSocket never drops silently on post-upgrade refusals). Historical `GET /v1/logs`, GraphQL `logs`, and MCP `list_logs` are unaffected (already return empty `[]` for static site `type=request`).
