# S3 lifecycle and CORS refusals name the removed Cloudflare R2 fields (`deleteObjectsTransition`, `conditions.prefix`, `allowed.origins`)

Why: since Contract B went on 2026-11-19, the S3 gateway is the only caller of the rule validators, yet every S3 client (`bex s3`, aws-cli, rclone, boto3) is told to fix fields that do not exist in the document it sent, so a user cannot tell what to change.

- Severity: minor. The refusal is right and nothing is stored, but the wording names the wrong document.
- Versions: released `bex` v0.9.0 (`bex-0.9.0-linux-arm64`, sha256 `cecca711…`), upstream pin v2.36.0 `4fd34231b637`. Production gitops pin `cce6c749f6ff`; the live digest was not read (`scripts/fetch-app-kubeconfig.sh` found no reachable control plane from this host, and the host has no `kubectl`). `objectstorage/lifecycle.go`, `objectstorage/cors.go` and `s3gw/handlers_bucket.go` are unchanged from `cce6c749f` to `c9ad6316c`, so production runs this code.
- Context: cli-qa routine run r4ae7, 2026-11-21 13:15Z, `https://api.bex.co`, workspace `bex-canary`, human device login, ephemeral key made by `bex s3` (revoked after), `-o text`, non-TTY.

## Repro

Run these against an owned bucket (`bex s3 mb s3://qa-<nonce>-b2 --region frankfurt`). Each command exits 1 within a second, and nothing is stored (`bex s3 lifecycle get` / `cors get` read the previous rules):

```sh
echo '{"Rules":[{"ID":"d","Status":"Enabled","Filter":{"Prefix":"x/"}}]}' > noaction.json
bex s3 lifecycle set qa-<nonce>-b2 --file noaction.json --region frankfurt
# Error: InvalidRequest: invalid lifecycle rule: lifecycle rule 1: a rule needs deleteObjectsTransition (request …)

# the same rule with "Status":"Disabled": the same message
# an "ID" of 256 characters:
# Error: InvalidRequest: invalid lifecycle rule: lifecycle rule 1: id must be 1 to 255 bytes (request …)
# "Filter":{"Prefix":"x\t/"}:
# Error: InvalidRequest: invalid lifecycle rule: lifecycle rule 1: conditions.prefix is not valid (request …)

echo '{"CORSRules":[{"AllowedOrigins":[],"AllowedMethods":["GET"]}]}' > noorigin.json
bex s3 cors set qa-<nonce>-b2 --file noorigin.json --region frankfurt
# Error: InvalidRequest: invalid CORS rule: CORS rule 1: allowed.origins needs at least one origin (request …)

# "AllowedMethods":[]   -> … CORS rule 1: allowed.methods needs at least one method
# "MaxAgeSeconds":-1    -> … CORS rule 1: maxAgeSeconds must be between 0 and 86400
```

The checks that `lifecycleFromXML` makes itself already speak S3: `Expiration Days must be between 1 and 36500.`, `A lifecycle rule's Status must be Enabled or Disabled.`, `'Date' must be at midnight GMT.` The bucket was removed afterwards (`rb --force`, then `info` answered 404 `BUCKET_NOT_FOUND`).

## Cause

- The stored rule shape is Cloudflare R2's (ADR112 D3): `LifecycleRule{id, enabled, conditions.prefix, deleteObjectsTransition, abortMultipartUploadsTransition}` and `CORSRule{id, allowed.{origins,methods,headers}, exposeHeaders, maxAgeSeconds}`. Contract B (the `/cloudflare/client/v4` routes) sent that shape until 2026-11-19, and `ValidateLifecycle` (`lego/backend/internal/objectstorage/lifecycle.go:105`) and `ValidateCORS` (`objectstorage/cors.go:80`) word their refusals in it: `lifecycle.go:115`, `:122`, `:129`, `:132`, `:139` and `cors.go:92`, `:100`, `:109`, `:113`.
- `lifecycleFromXML` (`lego/backend/internal/s3gw/handlers_bucket.go:336`) converts S3 XML to that shape. It refuses only what it checks itself, and a rule with neither `Expiration` nor `AbortIncompleteMultipartUpload` passes through with a nil `DeleteObjectsTransition`. `serviceError` (`handlers_bucket.go:110-112`) then returns `err.Error()` verbatim as `InvalidRequest`.
- `SetCORS` and `SetLifecycle` (`objectstorage/stream.go:74`, `:86`) are called only from `s3gw/handlers_bucket.go:230`, `:242`, `:309`, `:321`; no REST, GraphQL or MCP route reaches them since the Contract B removal. So the messages can be rewritten in S3's terms with no other consumer.

## Fix

- Word every refusal in the S3 document's element names, with the rule's position or its `ID`:
  - a rule with no action: `At least one action needs to be specified in a rule` (S3's wording; unverified against AWS from here), or bex's own sentence naming `Expiration` and `AbortIncompleteMultipartUpload`. Check it in `lifecycleFromXML` before the service call, as the `Days` and `Status` checks are.
  - `ID` over 255 bytes, an empty or control-character `Filter/Prefix`, and `DaysAfterInitiation`: name `ID`, `Filter.Prefix` (or `Prefix`) and `AbortIncompleteMultipartUpload`.
  - CORS: `AllowedOrigin`, `AllowedMethod`, `AllowedHeader`/`ExposeHeader` and `MaxAgeSeconds`.
- Keep the S3 error codes (`InvalidRequest`, `InvalidArgument`, `MalformedXML`) and the limits as they are.
- Either word the messages in the core validators, which have no other caller, or map them in `s3gw`. Do not keep two wordings of one rule.

## Acceptance

- Unit tests in `lego/backend/internal/s3gw` PUT each document above (lifecycle with no action, enabled and disabled; a 256-byte `ID`; a tab in the prefix; CORS with no origins, no methods, a max age of -1). Each answers its S3 code with a body that names the S3 element, and none contains `deleteObjectsTransition`, `conditions.`, `allowed.`, `abortMultipartUploadsTransition` or `maxAgeSeconds`. A test fails on today's code.
- `objectstorage` tests still pass for the stored-shape checks the sweep relies on.
- Live, on a pin that carries the fix, in `bex-canary`: `bex s3 lifecycle set <owned> --file noaction.json` prints the S3-worded refusal and exits 1; `noorigin.json` likewise for CORS; a valid document still stores (`get -o json` reads it back). Remove the bucket afterwards.
