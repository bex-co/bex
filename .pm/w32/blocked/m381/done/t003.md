## Objective

`GET /v1/sandboxes/{id}/execs` (w32/m298) and its GraphQL and MCP equivalents show a disconnected command with no `stoppedAt` while it runs. When it exits, they show its real `stoppedAt` and `exitCode`.

## Context

- Production, 2026-11-13: the record of the killed `sleep 480` command read `stoppedAt 03:43:01.623Z` (the disconnect) and `exitCode null` (milestone README).
- `exec.go:332-350`: `StreamExec`'s deferred `stopExecution` runs when the copy returns. `executions.go:164` writes `stopped_at = now` and the sniffed exit code.

## Steps

1. Leave the record open when the stream ends without an exit event while the command is still running (t001's signal).
2. Close it with the command's exit time and code once they are known, and as t001 decides when they can no longer be known (the sandbox ended).
3. Keep the connected path unchanged: a stream that sees the exit event closes the record at once.

- [x] A test shows a disconnected command's record has no `stoppedAt` until the command exits, and then has its exit code.

## Done — 2026-11-14

- `StreamExec` and `ExecBuffered` leave the record open when no exit was seen (a disconnect, or output past 2 MiB). A stream that carries the exit closes it at once, as before (`TestAStreamWithoutTheCommandsExitLeavesItsRecordOpen`, `TestABufferedExecRecordsASyncRun`).
- `reconcileCommands` closes a record at the command's own exit with its exit code. The time is held to the present, and the store's `GREATEST(stopped, started)` holds it to the record's start. The sweeper and history reads both use it (`TestAHistoryReadAsksTheRegistryAboutStaleRecords`, `TestASuspendedSandboxsStaleRecordsEndAtTheirLastRefresh`).
