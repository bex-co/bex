## Objective

Run `/simplify` over the code this milestone changed (reuse, simplification, efficiency), keeping behavior unchanged.

## Acceptance criteria

- [x] `/simplify` findings applied or dismissed with a reason in the milestone README.

## Done — 2026-11-14

`/simplify` ran three reviews. Applied:

- The probe has its own per-workspace subject (`sandboxexec.ProbeSubjectPrefix`), which the gateway admits like the Completer's. A tenant reading history can no longer use the Completer's 5 platform-wide slots.
- The wrapper records its own PID too, so a command between its exit and its log line reads as running, not unknown. The reviewer reproduced that race 9 times in 300 runs.
- The probe takes 5 s, well inside the 30 s suspend-claim grace.
- Exit times are held to the present and to the record's start.
- A failed probe touches activity, so it is retried once per idle window, for at most an hour.
- Unknown stale records close on the sweeper path too, and the newest records are probed first.
- The child script is passed as its own argument, so it may hold single quotes. `/proc` is read without `cat`, the exit log is read in one `awk` pass, and its size comes from `stat`.
- `systemExec` is shared with the agent-session reads. `execArgv` and `agentExecArgv` are separate functions. `historyTarget` replaces four return values. `newRecord` is gone.
- Test helpers are shared (`commandExitCode`, `needSh`, `lastActivity`, `lastSeen`).

Skipped:

- A partial index on open records. The existing stale-close query already scans a sandbox's rows, and that predates this change.
- A lock around the exit log's rotation. Two commands ending exactly as the log passes 1 MiB can lose a line, and the record then ends at its last refresh with no exit code.
