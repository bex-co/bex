## Objective

Run `/simplify` over the milestone's changes and apply its fixes. Pay particular attention to keeping one archive-entry rule for both directions instead of two copies.

## Acceptance criteria

- [x] `/simplify` run; fixes applied or each skip explained in the milestone README.

## Done — 2026-11-14

`/simplify` ran three reviews (reuse, quality, efficiency) over the change. Applied:

- `copyArchive` is one plain `switch h.Typeflag` for both directions. Each name records what a later entry sees it as: a hard link counts as what it names, so a link to a FIFO is skipped and a child under any skipped entry is refused. `keptEntry` is gone.
- A hard link to a symlink is now written as a copy of the symlink, not refused. BusyBox writes a second name for a symlink this way (checked in `node:22-alpine`), and the old rule would have failed that download. The BusyBox fixture and the golden now carry `rel-link-2`.
- `startWriter` sets the download's headers at its first write, so the pre-first-byte error path has no header list to keep in step.
- bex-api's empty body applies to GET only. A body-less PUT is never replayed, and an empty body would have sent a `Content-Length: 0` PUT chunked.
- Comments trimmed to the why.

Skipped:

- Answering a download-side archive refusal with something other than 400. The request is fine, but a 5xx would invite retries of a tree that will never transfer.
- Reusing `runtimeUnreachable` (`client.go:266`) or `unreachable(...)`. The first counts a dropped connection as unreachable, which is the case this change tells apart. The second would change the message the CLI shows.
- `strings.Clone` for `seen` keys. The 256 MiB input cap already bounds them, and this predates the change.
