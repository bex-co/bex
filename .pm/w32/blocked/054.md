# After a real `bex login`, `bex agent open --dashboard` and the logout revoke-failure warning link `oauth.bex.co` pages that answer 404

Why: a device login saves `dashboard_url: https://oauth.bex.co`, and the OAuth host redirects only the resource prefixes w8/089 listed. So the agent-session page and the "revoke your token in the Bex dashboard" link both land on Hydra's `404 - Route not found`.

- **Severity / estimate:** minor, ~40m.
- **Attribution:** infrastructure edge routing (`deploy/gitops/charts/cli-dashboard-links/middleware.yaml`). Two consumers read the saved origin: the Bex-native `bex agent open`, and upstream's `logout` warning.
- **Source:** `/qa-find-bugs-cli w32` routine `cli-qa`, 2026-11-20 UTC. Released `bex` v0.7.0 (Render CLI v2.36.0, pin `4fd34231b637`). Production on pin `3e53abbe3bc3`: the deployed bex-api and operator digest `3cfea3ac…` matches that pin commit. Human device login as the QA user, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), non-TTY, isolated `BEX_CLI_CONFIG_DIR`.

## Repro

1. Run a normal `bex login` and approve it. Two fresh logins in this run each saved `dashboard_url: https://oauth.bex.co` in `cli.yaml`. Upstream `pkg/tui/views/login.go:221` stores the origin of the device grant's `verification_uri`, which is Hydra's `https://oauth.bex.co/oauth2/device/verify`.
2. `bex logout`, when the server cannot revoke the token. Seen once live, exit 0:

   ```text
   Warning: something went wrong revoking your CLI token: revoke token failed with status 503. Your local credentials have been cleared, but you'll need to revoke your token in the Bex dashboard: https://oauth.bex.co/settings#cli-tokens
   ```

3. `bex agent open <ags-id> --dashboard` builds `<dashboard_url>/agents/<id>` (`lego/cli/internal/agent/agent.go:1102`). It prints that URL and, on a terminal, opens it. After a login that is `https://oauth.bex.co/agents/<id>`. `EnsureDashboardURL` (`lego/cli/internal/bridge/dashboard.go:24`) covers `agent open`, but it keeps any saved origin, and its test `saved origin kept` pins exactly `https://oauth.bex.co`.

These are anonymous GETs, so the same responses come back for any id:

```text
GET https://oauth.bex.co/settings                       → 404 text/html  <title>404 - Route not found</title>
GET https://oauth.bex.co/agents/ags-dbvt0b1bgjqs73fpzzzz → 404 text/html  <title>404 - Route not found</title>
GET https://dashboard.bex.co/agents/ags-…               → 307 /auth/login?next=%2Fagents%2Fags-…   (route exists)
GET https://dashboard.bex.co/settings                   → 307 /auth/login?next=%2Fsettings         (route exists)
GET https://oauth.bex.co/web/srv-dbkq3hdhhjfs73eiahe0    → 302 https://dashboard.bex.co/web/srv-…  (w8/089 control)
```

- **Mechanism:** the Traefik `RedirectRegex` `auth/cli-dashboard-redirect` matches only `^https://oauth[.]bex[.]co/(web|worker|pserv|static|cron|d|r)/(.+)$`. Upstream's resource links are under those prefixes, so they work. `settings` (upstream `cmd/logout.go`) and `agents` (Bex `agent open`) are not listed, so they fall through to Hydra.
- **Tests miss it:** `lego/cli/runtime_copy_test.go:198` and `internal/agent/agent_test.go:364` both use `dashboard_url: https://dashboard.bex.co`, which a real login never writes.
- **Render:** the same warning links Render's own dashboard settings, where its CLI tokens are listed. Bex lists the CLI grant under Settings → Security → Connected agents (`dashboard/src/features/auth/pages/settings-page/security-compliance-section.tsx`). The settings page has no `cli-tokens` anchor.

## Fix

- In `middleware.yaml`, widen the expression so the OAuth host sends `agents/<…>` and `settings` (with or without a query) to the dashboard, keeping the path and query. For example: `^https://oauth[.]bex[.]co/((web|worker|pserv|static|cron|d|r|agents)/.+|settings([/?].*)?)$` → `https://dashboard.bex.co/${1}`, still non-permanent.
  - Hydra serves nothing under `/agents` or `/settings`, so no OAuth or OIDC route changes.
  - The browser keeps `#cli-tokens` across the redirect.
- Give the Connected agents card `id="cli-tokens"`, so the fragment lands where the bex CLI grant can be revoked. Settings → Security is the place that matches Render's link.
- Do not rewrite the saved origin in the launcher. The edge repairs every existing config, for both upstream and Bex-native links, as w8/089 chose.

## Acceptance

- Against production, `GET https://oauth.bex.co/settings` answers 302 to `https://dashboard.bex.co/settings`. `GET https://oauth.bex.co/agents/<ags-id>?x=1` answers 302 to `https://dashboard.bex.co/agents/<ags-id>?x=1`.
- The w8/089 prefixes still redirect. `/.well-known/openid-configuration`, `/oauth2/device/verify`, `/oauth2/token` and `/oauth2/revoke` still reach Hydra.
- A fresh `bex login` → `bex whoami` → `bex logout` still works. That covers the device login and the revoke.
- With a real login's config, `bex agent open <an existing ags-id> --dashboard -o text` prints a URL whose GET reaches the dashboard. Do not create a session just for this check: agent sandboxes bill.
- The dashboard's `settings#cli-tokens` scrolls to Connected agents, with a dashboard test for the anchor.
- `scripts/gitops-validate.sh` passes.

## Unverified

- `agent open` was not run live, because `bex-canary` has no agent session and creating one bills. The URL it builds comes from reading the code and from this run's saved origin.
- **The 503 itself did not reproduce.**
  - It came after a forced refresh and about 30 minutes of use.
  - Two later login → logout runs revoked cleanly (the old token then answered 401). So did one with a forced refresh first.
  - Hydra's logs (both pods) show no `/oauth2/revoke` at the failed logout (04:53:45Z). Both later revokes show up with Cloudflare `cf-*` headers.
  - So bex-api's `cliauth.postForm` failed before Hydra, on its way out through the public `https://oauth.bex.co` (`BEX_OAUTH_ISSUER`) rather than an in-cluster service.
  - That access token is still live until it expires. Its config was cleared, and nothing holds a copy. If it recurs, it is its own note: send cliauth's Hydra public calls in-cluster, and retry a revoke once.
