# A settings save during an in-flight static-site Restart or Rollback wedges the deploy in `update_in_progress` forever, blocking every later deploy in `queued`

Why: `selectedRelease` (`lego/operator/internal/controller/release_identity.go:563-566`) excludes retained-publication restores (`ref.StaticPrefix != ""`), `staticRestoreSelection` (`app_controller.go:1125-1132`) never stamps `ArtifactFingerprint`, and `resolveDeployImage` (`app_controller.go:1115-1120`) halts built static sites unconditionally on `sourcePending`, so a save-only update (`bex services update`, REST `PATCH /v1/services/{id}`, GraphQL, or MCP) arriving during the ~10 s copy Job strands the static site in `PhaseDeploying` / `update_in_progress` with zero requeue until manually canceled.

- **Severity / estimate:** **major**, ~45m. Every subsequent `bex deploys create` (or auto-deploy) queues indefinitely behind the wedged `update_in_progress` deploy (`bex deploys create --wait` hangs forever), and the site stays in `phase: Deploying` until the operator's deploy is manually canceled via `bex deploys cancel`.
- **Versions:** released `bex` v0.9.0 (`bex-0.9.0-linux-arm64.tar.gz`, compatible with Render CLI `v2.36.0`, upstream pin `4fd34231b637`); repo checkout at `6c11b6b0f6` (`lego/cli` pinned to Render CLI `v2.37.0`, `11ef59f330dedec290f8d71d89b8f7379bbbed09`); production platform pin `9fdf7e0a1171` (`cded300699`). `selectedRelease`, `staticRestoreSelection`, `resolveDeployImage`, and `staticReleaseFinishing` are unchanged on `main` through `6c11b6b0f6`.
- **Context:** routine `cli-qa` sweep `8295`, 2026-11-23 19:45–19:55 UTC, `https://api.bex.co/v1/`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), human device login (`bex login`), non-TTY `-o json`.

## Attribution and root cause

- **Attribution:** operator (`lego/operator/internal/controller/`). The CLI sent valid standard requests (`POST /v1/services/{id}/restart`, `PATCH /v1/services/{id}`), and `bex-api` (`lego/backend/internal/deploys/rollback_config.go:324-334`) validly selected the retained static publication (`ReleaseConfigReference{Generation: 2, Image: target.ResolvedImage, StaticPrefix: prefix}`).
- **Root cause (three interacting defects in `lego/operator/internal/controller/`):**
  1. `selectedRelease` (`release_identity.go:563-566`) explicitly excludes static restores with `ref.StaticPrefix == ""` (comment at `:561-562`: _"A static site's restored publication is a copy with no rollout to hold"_). In reality, `publishStaticRevision` (`app_controller.go:4984-5080`) dispatches an asynchronous Kubernetes copy Job (`publish.Ensure`) while `app.Status.Phase == PhaseDeploying` (~10 s). Because `selectedRelease` returns `false`, `pinnableRelease` (`:553-555`) is `false`:
     - `recordAdoptedRelease` (`app_controller.go:773`) is skipped on adoption (even though `recordAdoptedRelease` at `release_config_snapshot.go:462` only skips `ref.SourceGeneration > 0` and would otherwise record the adopted view cleanly);
     - when a save-only patch sets `AnnotationPendingSourceGeneration` (`sourceUpdatePending` at `release_identity.go:624`), `releaseInFlight(held)` (`:509`, `:631`) returns `false` because `!pinnableRelease(app)` and `!selectedRelease(app)` (while `prepareAppReleaseDecision` at `:691-693` already stamped `SelectedReleaseGeneration = ReleaseGeneration`); so `prepareAppReleaseDecision` falls through to `:638-643` and returns `appReleaseDecision{desired: pinned, sourcePending: true}`.
  2. `resolveDeployImage` (`app_controller.go:1125-1132`) handles `staticRestoreSelection(app)` without stamping `app.Status.ArtifactFingerprint = decision.desired.artifact` and `app.Status.ArtifactImage = ref.Image` (compare `directStaticPublish` right below it at `:1145-1146`). Thus `app.Status.ArtifactFingerprint` stays on the prior release's fingerprint while `app.Status.ReleaseArtifactFingerprint` holds the restore release's fingerprint (`release_identity.go:677`).
  3. On the post-save reconcile pass in `resolveDeployImage`:
     - **No-build static site (`app.Status.Image == ""`):** enters `:1097`, calls `staticReleaseFinishing(app)` (`:8236-8244`), which returns `false` at `:8243` (`app.Status.ArtifactFingerprint == app.Status.ReleaseArtifactFingerprint`), and falls into `holdPendingStaticArtifact(ctx, app, ctrl.Result{})` (`:1103`) — returning `ctrl.Result{}` with zero requeue and never calling `reconcileStaticSite` again to observe the completed publish Job.
     - **Built static site (`app.Status.Image != ""`):** skips `:1097` and hits `:1115-1120` (`if decision.sourcePending && releaseRevision(app) != app.Status.ActiveRevision && (app.Spec.Type == appv1alpha1.TypeStaticSite || ...)`), which unconditionally halts in `holdPendingArtifact(ctx, app, ctrl.Result{})` before reaching `staticRestoreSelection` at `:1125` (also stranding a built static site whose publish Job is in `PhaseDeploying` under `OverlappingDeployPolicyOverride` or whenever `releaseInFlight` is false).

## Fix

- In `lego/operator/internal/controller/release_identity.go`:
  - Include retained static publication restores in `selectedRelease` (`:563-566`: drop `ref.StaticPrefix == ""`), so `pinnableRelease` and `releaseInFlight` hold an in-flight static Restart or Rollback copy Job on its adopted view across concurrent settings saves or newer deploys under Wait overlap policy. Confirm `prepareAppReleaseDecision` / `carryRestoredPublicationSettings` (`static_publication.go:92`) and `ActiveReleaseConfig` (`lego/types/v1alpha1/releasesnapshots.go:335`) preserve `ReleaseSettingsFingerprint` and `undeployedChanges` accurately.
- In `lego/operator/internal/controller/app_controller.go`:
  - Inside `if ref := staticRestoreSelection(app); ref != nil` (`:1125-1132`), stamp `app.Status.ArtifactFingerprint = decision.desired.artifact` and `app.Status.ArtifactImage = ref.Image` before calling `reconcileKubernetes` (mirroring `directStaticPublish` at `:1145-1146`).
  - Handle `staticReleaseFinishing(app)` consistently for **both** no-build (`app.Status.Image == ""`) and built (`app.Status.Image != ""`) static sites when `decision.sourcePending` is true (including under `OverlappingDeployPolicyOverride`, where `releaseInFlight` is false): before `:1115` halts a `TypeStaticSite` in `holdPendingArtifact`, allow a finishing static release (`staticReleaseFinishing(app)`) — including an in-flight `staticRestoreSelection` — to continue into `reconcileKubernetes` with its own artifact image (`ref.Image` or `app.Status.ArtifactImage`) so the publish Job completes and adopts the revision. Keep holding when the static build has not produced its image yet (`ArtifactFingerprint != ReleaseArtifactFingerprint`) or failed (`PhaseFailed` / `terminalBuildFailureRecorded`).

## Blast radius

- Scoped to `lego/operator/internal/controller/` (`release_identity.go`, `app_controller.go`, and tests in `static_first_release_save_test.go`, `static_first_release_save_envtest_test.go`, `release_overlap_pin_test.go`).
- Affects **both** static Restart (`w32/049`) and static Rollback (`w4/m197`), for **both** no-build and built static sites, across every surface that triggers a save-only settings patch during an in-flight restore (CLI `bex services update`, REST `PATCH /v1/services/{id}`, GraphQL settings mutations, MCP `update_service`, Blueprint sync).
- Audit all callers of `selectedRelease` (`release_identity.go:509,554`), `staticReleaseFinishing` (`app_controller.go:1099`), and `recordAdoptedRelease` (`app_controller.go:773`, `release_config_snapshot.go:457`) to confirm:
  - static restores never break `OverlappingDeployPolicyOverride` (where a newer deploy still supersedes the copy Job),
  - a save-only update during a static Restart/Rollback still keeps `undeployedChanges` accurate once the copy finishes, and
  - canceling a static Restart/Rollback (`latestRequestCanceled`) still settles back to the served revision without re-running the copy Job.
