# Concurrent directory transfers can together exhaust the shared SSH gateway's memory

Why: every sandbox file transfer runs in the shared `ssh-gateway` pod (2 replicas, 512Mi limit each, 128Mi of it the exec drain buffer). Each directory archive holds an in-memory index of the names it has passed, so that duplicates, missing parents and hard-link targets can be checked. That index has a per-archive bound but no pod-wide one. One tenant running a few worst-case transfers at once can push a replica out of memory, which ends every SSH session, web shell, exec stream and transfer on it.

- **Found:** the `/simplify` efficiency review of w32/023, 2026-11-14. It is traced from the code, not observed.
- **Per-archive bound (after w32/023):**
  - Every entry costs at least one 512-byte header against `MaxTransferBytes` (256 MiB), so an archive holds at most about 524k entries.
  - `archiveIndex` (`lego/backend/internal/sshgateway/sandboxfiles/sandboxfiles.go`) keys each name by a 128-bit digest. Measured on 2026-11-14, 524,288 entries in `map[[2]uint64]byte` took 29.9 MiB of heap, about 60 B per entry including growth.
  - Kept symlink targets add at most 8 MiB (`maxKeptSymlinkTargets`). The PAX and flate buffers add a few MiB more.
  - The worst case is therefore about 40 MiB per archive. Before w32/023 it was about 80 MB: 10,000 names and 10,000 targets of up to 4096 bytes each.
- **Concurrency:** transfers share the gateway's session limiter, which allows 100 sessions in total and 5 per identity (`sshgateway.NewSessionLimiter` defaults, `sandboxfiles.go:112-118`). About ten worst-case directory transfers on one replica reach its limit.
- **Fix:**
  1. Add a pod-wide budget for archive bookkeeping, for example an atomic byte counter that `archiveIndex` charges as it grows. A transfer that would exceed it fails with a retryable status, which must not consume the ticket: a `503` whose cause names gateway capacity.
  2. Optionally make the index smaller: `map[uint64]uint64` with the entry kind packed into the low byte of the second digest uses 16-byte slots, about a third less than now. A digest collision on the first word must then be refused, never treated as a new name.
  3. Size the budget against the pod limit, leaving the drain buffer and ordinary sessions their share. Record the choice in `docs/render-artifacts/ea-sandbox.md`.
- **Acceptance:**
  - A gateway test runs more concurrent worst-case archives than the budget allows. The ones past the budget get a clean refusal, and the in-flight ones still complete.
  - Heap stays under the budget throughout (`runtime.ReadMemStats` in the test).
  - A normal transfer is unaffected: the w32/023 walk's 25,000-entry tree still copies in both directions.
- **Not a parity item:** Render documents no transfer concurrency limit (render.com/docs/sandboxes-limits lists 1,000 upload or download requests per minute). The budget must only engage under memory pressure, never as a routine cap.
- Major (one tenant can disrupt every gateway session on a replica). ~1h.

## Shipped 2026-11-14 (`/loopx w32`), parked on the production deploy

- **Shipped:** `2d7dcb828`.
  - Every archive index reserves from one process-wide 64 MiB `semaphore.Weighted` (`archiveIndexMemory`) in 64 KiB chunks. It charges 64 B per entry and each kept symlink target plus 96 B; the efficiency review checked both against Go's swiss-map slot sizes.
  - Past the budget, an upload, or a download before its first byte, answers `503 the sandbox file gateway is at capacity; retry the transfer` and counts as `limit_rejected{scope="archive_index_memory"}`. A download already streaming aborts like any mid-stream failure.
  - `copyArchive` reuses one 32 KiB copy buffer. `io.Copy` had allocated one per entry, because tar hides its `WriterTo` and `ReaderFrom`.
  - The gateway Deployment sets `GOMEMLIMIT=450MiB`, so the GC works harder before the 512Mi limit.
- **Differs from the fix above:**
  - A refusal still spends the ticket's nonce, which is consumed before the transfer starts. A retry is a new `copy` with a new ticket, as for every other gateway failure, and bex-api never replays the hop (w32/m380).
  - The heap check became an accounting test instead. `TestArchiveIndexesShareOneBudget` holds the whole budget with one piped archive, then checks three things: a second archive and an HTTP download are refused with the 503, the budget returns whole when the first ends, and a later archive passes. `runtime.ReadMemStats` would have been flaky under the suite.
- **Not covered:**
  - There is no fair share between tenants. Two slow worst-case transfers from one tenant can hold the budget for up to five minutes and refuse other tenants' directory transfers on that pod. That is a refusal, not an out-of-memory kill.
  - Per-transfer gzip and PAX buffers (about 1 MiB each) stay outside the budget.
  - `scripts/dev-env/agent/ssh-gateway.yaml` does not set `GOMEMLIMIT`.
- **Gate:** the acceptance's live half, that a 25,000-entry tree still copies, is w32/023's walk. Once `git merge-base --is-ancestor 2d7dcb828 <pinned sha>` holds, the same worker runs both. No user decision is needed.
