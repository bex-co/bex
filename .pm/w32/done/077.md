# A Blueprint's sync history lists a plan still waiting for approval; Render's leaves `created` syncs out

Why: Render parity is the top product rule. On bex, `GET /v1/blueprints/{id}/syncs` lists a planned sync that is waiting for approval, but Render's list leaves out every sync in the `created` state.

- **Severity / estimate:** minor, parity, ~1h.
- **Contract (pinned `render-oss/cli` `v1.1.3-0.20261106232710-4fd34231b637`, `pkg/client/client_gen.go:233`, `ListBlueprintSyncs`):** "List syncs for the Blueprint with the provided ID. Syncs that are planned but not yet approved (in the `created` state) are not included." `CreateBlueprintSync` says it again: "Syncs in the created state do not appear in the list of the Blueprint's Syncs."
- **bex today (main after w32/075, 2026-11-21):** `store.ListBlueprintSyncs` (`lego/backend/internal/store/blueprints.go`) returns every `blueprint_syncs` row of the Blueprint, and `apps.ListBlueprintSyncs` (`lego/backend/internal/apps/blueprint.go`) filters none. REST `GET /v1/blueprints/{id}/syncs`, GraphQL `blueprintSyncs` and MCP `list_blueprint_syncs` all list a waiting plan in the `created` state. The dashboard's sync history reads `blueprintSyncs`. Since w32/075, a waiting plan is deleted 24 hours after it was planned, so it drops out of the list then.
- **Found by:** w32/075's worker, 2026-11-21, checking what `GET …/syncs` shows before and after a plan expires.
- **Fix direction:** leave `state = 'created'` rows out of the list on every surface, including a cursor that names one. The waiting plan stays readable through GraphQL `blueprintPlannedSync`, which the dashboard's Approve panel uses (w32/076). An approved plan is a run in the list from then on, under the same id.
- **Tests:** a Blueprint with an applied sync and a waiting plan lists only the applied sync over REST, GraphQL and MCP, on the fake store and on real Postgres. Once approved, the plan is listed.

## Acceptance

- `GET /v1/blueprints/{id}/syncs`, GraphQL `blueprintSyncs` and MCP `list_blueprint_syncs` never return a `created` sync.
- ADR049 § Blueprint onboarding says so, replacing its "bex still lists a waiting plan until it expires (w32/077)".

DONE 2026-11-21: the sync history leaves out every `created` sync, as Render's does. Render's wording: "Syncs that are planned but not yet approved (in the `created` state) are not included" (the pinned CLI `v1.1.3-0.20261106232710-4fd34231b637`, `pkg/client/client_gen.go:233` `ListBlueprintSyncs`, and `:243` `CreateBlueprintSync` "Syncs in the created state do not appear in the list of the Blueprint's Syncs"; api-docs.render.com/reference/list-blueprint-syncs says the same, read 2026-11-21). `store.ListBlueprintSyncs` filters `state <> 'created'` in both queries, before the page limit, so a page is never short for it, and a cursor naming a waiting plan still pages from where the plan stands. REST `GET /v1/blueprints/{id}/syncs`, GraphQL `blueprintSyncs` and MCP `list_blueprint_syncs` all read it, and the MCP description says so. No migration: the filter rides the existing `blueprint_syncs_blueprint_id_started` index. The dashboard's Planned sync card reads `blueprintPlannedSync`, not the history (`use-planned-sync.ts`), so w32/076 is unaffected. The pinned CLI calls `ListBlueprintSyncs` from nowhere but its generated client. Tests: `TestBlueprintSyncHistoryLeavesOutWaitingPlansPG` (store, real Postgres: an applied run, a failed plan and a waiting plan list as the run and the failed plan, a page of one skips the waiting plan, cursors, and the approved plan is listed under its id); `TestBlueprintSyncHistoryLeavesOutWaitingPlansOnEverySurfacePG` (apps, real Postgres, REST + GraphQL + MCP agree through a first plan, its approval, a waiting re-plan with a cursor naming it, and the re-plan's approval); `TestBlueprintSyncPublicIDOnEverySurface` (fake store, whose list now mirrors the filter: the replaced create plan, still `created`, is not listed on any surface); `TestAPlanNotApprovedWithin24HoursIsGonePG` now expects no listing before the sweep and checks the deletion in the table. With the SQL filter and the fake's mirror reverted, all four fail. ADR049 § Blueprint onboarding has a **History** bullet in place of "bex still lists a waiting plan until it expires (w32/077)".
