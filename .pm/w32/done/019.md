# A sandbox's home directory is `/root`; Render's is `/home/render`

Why: Render's Python SDK docs say relative remote paths "resolve under `/home/render`" (render.com/docs/sandboxes-sdk-python, read 2026-11-12), so a script written for Render that names `/home/render/...` absolutely (an upload destination, a `cd`, a config path) fails on bex, where the sandbox runs as root with `HOME=/root`. Relative paths and `~` already behave the same on both (w32/m299, w32/m348).

- **Where:** the `base` template (`lego/backend/cmd/api/main.go` `sandboxTemplateRegistry`, entrypoint `baseEntrypoint`) and the sandbox Pod env; the file gateway resolves relative paths under `$HOME` (`lego/backend/internal/sshgateway/sandboxfiles/sandboxfiles.go` `cdParent`), and exec starts in `$HOME` (`lego/backend/internal/sandbox/exec.go` `renderExecScript`).
- **Options:** set `HOME=/home/render` and create it in the entrypoint (still root), or add a `render` user. Check first whether Render's commands run as root (`id` in a Render sandbox, or the SDK/CLI source), and what a sandbox suspended before the change sees on resume (its BatchSandbox keeps the old env).
- **Done when:** on production, `bex sandboxes exec <sbx> -- pwd` prints Render's home path, a relative upload lands there, and ADR104 D2's "Home" bullet and ADR018 record the result.

Est. ~45m. Found while working w32/m348 (ADR104 D2 "How exec runs a command").

## Done — 2026-11-12 (`/loopx w32`)

- **Choice:** set `HOME=/home/render` and keep root. Render's docs give only the path (render.com/docs/sandboxes-sdk-python, read 2026-11-12); neither the SDK 1.8.0 source nor the docs name a user, so changing the user would be a guess.
- `sandbox.Template` gains `Env`, merged under the caller's create env (a caller's `HOME` still wins). The `base` template sets `HOME=/home/render` (`baseHome`, `lego/backend/cmd/api/main.go`), and `baseEntrypoint` runs `mkdir -p -- "${HOME:-/root}"` before sleeping. Exec's `cd "$HOME"` (w32/m348), the file gateway's relative paths and `~` all follow it. A sandbox created earlier keeps its BatchSandbox env, so it stays on `/root` until it is recreated.
- **Verified** in `bash:5.3` with that env and entrypoint: `pwd` and `~` read `/home/render`, the directory exists, the user is root. **Tests:** `TestCreateMergesTheTemplateEnvUnderTheCallers` and the base-template assertions in `TestSandboxTemplateRegistryIncludesPluggableAgentDriver`. The isolation matrix now requires the exec working directory to be `/home/render`.
- ADR104 D2 "Home" and ADR018's exec row record it.
- **Production check:** with the w32/m348 walk: `bex sandboxes exec <sbx> -- pwd` prints `/home/render`.
