# The Docker promtool fallback can't read the rule file

Why: on any machine without a host `promtool`, `scripts/ship-gates.sh` fails its real-DB backend gate, and the error looks like a broken rule.

- `scripts/backend-test-deps.sh:102-110` writes a `promtool` shim that runs `docker run --rm -v "$dir:$dir" … promtool`. The container runs as the image's user, which cannot read the test's 0700 tempdir, so `promtool check rules` fails. Hit during w32/m283's ship on 2026-11-08, worked around by installing promtool on the host.
- Fix: run the shim as the caller (`--user "$(id -u):$(id -g)"`), and add a smoke check that the shim reads a rule file in a 0700 directory.
- ~20m. From `/pm-brainstorm more for w32`, 2026-11-09, item 5.

**Done 2026-11-09 (`/loopx w32`).** The shim now runs `docker run --user "$(id -u):$(id -g)"`, and `up` smoke-checks it against a rule file in a fresh 0700 directory, failing loudly if it cannot read one. Reproduced first: the old shim answered `stat …/r.yml: permission denied` and the new one `SUCCESS: 1 rules found`. With no host promtool on `PATH`, `backend-test-deps.sh up` passed its smoke check, and the three promtool-backed packages (`internal/metrics`, `internal/egressquery`, `internal/usage`) passed under `BEX_TEST_REQUIRE_DEPS=1` through the shim alone.
