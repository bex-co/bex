# A directory copied into a sandbox loses its files' modification times (1970), and uploads arrive owner-only

Why: `bex sandboxes copy ./dir sbx:/path` sends a tar whose headers carry each file's mtime and mode. bex rebuilds the headers without the mtime, so every uploaded file reads as modified on 1970-01-01. Tools that compare or record timestamps (`make`, ZIP writers that refuse pre-1980 times, caches) then misbehave.

- **Seen:** `/qa-find-bugs-cli` loop sweep dc0e, 2026-11-12, `bex-canary`, HEAD build (Render CLI v2.36.0 pin), human device login, sandbox `sbx-dbqnmgiibtfs738vkv5g`.

  | Local file (mode, mtime as epoch seconds) | In the sandbox after the copy |
  | --- | --- |
  | `m` 755, 1794472847 | `/tmp/m` **700**, 1794472848 |
  | `m/x.sh` 755, 1767323045 | `/tmp/m/x.sh` 755, **0** |
  | `m/sub` 750, 1767323045 | `/tmp/m/sub` 750, 1794472848 |
  | `m/sub/y.txt` 644, 1767323045 | `/tmp/m/sub/y.txt` 644, **0** |
  | `single.sh` 755, 1767323045 (single-file copy) | `/tmp/single.sh` **600**, 1794472849; running it gives `sh: /tmp/single.sh: Permission denied` |

  Commands: `bex sandboxes copy ./m <sbx>:/tmp/m`, `bex sandboxes copy ./single.sh <sbx>:/tmp/single.sh`, then `bex sandboxes exec <sbx> -- sh -c 'stat -c "%a %Y %n" …'`.

- **Contract:**
  - The pinned client builds its tar with `tar.FileInfoHeader` (`render-oss/cli` `pkg/sandbox/files.go:173`), so the mtime and mode are on the wire.
  - Its own download path chmods a plain file to "the 0o644 a plain create would produce under a default umask, which is also what the archive path extracts with" (`files.go:103-105`). It extracts directories as `mode&0777|0700` and files as `mode&0777|0600` (`files.go:256,263`).
  - Render's docs (render.com/docs/sandboxes-files, fetched 2026-11-12) say a directory upload "extracts the archive at the specified path". Extracting a tar keeps its mtimes.

- **Cause (traced at `4eb6bac41`):**
  - `lego/backend/internal/sshgateway/sandboxfiles/sandboxfiles.go:641` `copyArchive` re-emits each entry as `&tar.Header{Name, Typeflag, Size, Mode}`, dropping `ModTime`. BusyBox `tar -x` then stamps 0.
  - The archive's `.` root entry is skipped (`:617`), and `stageScript` runs `umask 077; mkdir "$stage/tree"` (`:309-318`), so the published root directory is 0700.
  - The single-file branch writes `cat > "$stage/data"` under the same `umask 077`, so the file is 0600.

- **Fix:**
  1. Carry `ModTime` (seconds, clamped to a sane range) into the clean header.
  2. Give the published root the archive's `.` entry mode (`&0777|0700`), or 0755 when there is none.
  3. Publish a single file as 0644, which is a plain create under the default umask.
  4. Keep the sanitizer's refusals (links, special entries, traversal) unchanged.
  5. Test in `sandboxfiles_test.go` and the `shell_test.go` real-script cases.

- **Acceptance:** after `bex sandboxes copy ./m <sbx>:/tmp/m`, `stat -c '%a %Y'` in the sandbox shows each file's local mtime, and `/tmp/m` is not 700. A single uploaded file is 644.
- **Unverified:**
  - Render's server-side modes for a single-file upload (its docs are silent; 0644 comes from the pinned client's own stated convention).
  - The concrete ZIP failure (Python `zipfile` refuses timestamps before 1980): the sandbox base image has no Python (see w32/m348).
- **Dedupe:** no board item covers upload metadata. The behavior dates from w7/m150 (`c201b1203`); `docs/render-artifacts/ea-sandbox.md` § Bounded file transfers does not mention timestamps or the root mode.
- ~45m.

## Done — 2026-11-12 (`/loopx w32`)

- **Fix as proposed:** `copyArchive` (`lego/backend/internal/sshgateway/sandboxfiles/sandboxfiles.go`) carries each entry's `ModTime` (whole seconds, clamped to the USTAR range BusyBox reads) and returns the archive root's `.` mode (`&0777|0700`, 0755 when absent). `publishScript` takes the published mode as `$5` and `chmod`s the staged tree or file before the `mv`: the root mode for a directory, 0644 for a single file. The sanitizer's refusals are unchanged. Downloads go through the same `copyArchive`, so they keep the sandbox's mtimes too.
- **Tests:** `TestUploadKeepsModTimesAndPublishesPlainModes` runs the real stage and publish scripts (a directory with a `.` root of 755 and entries dated 1767323045 publishes 0755 with those mtimes; a single file publishes 0644) and `TestCopyArchiveDefaultsTheRootModeAndClampsTimes`. Both pass on the host and, compiled, inside `bash:5.3` (BusyBox tar) as root and as a user.
- `docs/render-artifacts/ea-sandbox.md` § Bounded file transfers records the metadata rules.
- **Production check:** with the w32/m348 walk: `bex sandboxes copy ./m <sbx>:/tmp/m` then `stat -c '%a %Y'` shows the local mtimes and `/tmp/m` is not 700; a single uploaded file is 644.
