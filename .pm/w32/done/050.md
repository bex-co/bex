# ADR018 says every resource reads its region back as `frankfurt` on production, but a create reads back the Render region it asked for

Why: since w9/105, ADR018's Create service row describes the region read-back wrongly, so a reader expects `frankfurt` where the API returns `oregon`.

- **Severity / estimate:** minor, docs only, ~20m.
- **Where:** the Create service (web / private) row, `docs/ADR018-render-parity.md:121`. It says every create surface reads a resource back "by its Render name (`frankfurt` on production since w8/218 D7; …)".
- **What ships:** since w9/105, `resourcemeta.StampRegion` / `ResourceRegion` (`lego/backend/internal/resourcemeta/metadata.go:141-175`) read back the Render region the caller asked for, and fall back to `BEX_REGION`'s Render alias only when none was asked for.
- **Evidence:** `/qa-find-bugs-cli w32` run, 2026-11-20, pin `98e053468f52`, released `bex` v0.7.0, `bex-canary`.
  - `bex kv create --plan free` with no `--region` created red-dbvpdth50n7c739ba24g, which has since been deleted.
  - REST, the CLI and the `app.bex.co/region` annotation all read it as `oregon`.
  - An older Key Value reads `frankfurt`.
- **Unverified:** why the create with no `--region` read back `oregon`. The pinned CLI may send a default region, or the backend may fill one in. Confirm which before writing the sentence.

## Acceptance

- ADR018's region text describes the w9/105 read-back: the requested Render region, otherwise `BEX_REGION`'s alias.
- Any other ADR sentence that repeats "`frankfurt` on production" for read-back is corrected the same way.
- `bash scripts/docs-links-validate.sh` passes, and prettier is clean.

**Done 2026-11-19 (w32/050 worker).** Settled the unverified point from the pinned CLI and the backend: `render-oss/cli` v2.36.0 (`4fd34231b637`) `pkg/keyvalue/create.go:41-44` sets `Region` to `oregon` when `kv create` is run without `--region`, before it builds the request, so the body carries `region: oregon` and `resourcemeta.StampRegion` records it. bex-api fills no default (`CheckRequestedRegion` accepts an empty region and `StampRegion` records nothing for it). `pg create` and a `services create` without `--from` send no region, so they read back `frankfurt` on production. Corrected: ADR018's Create service row (both region sentences) and its Postgres/Key Value region-filter paragraph (it still said `fsn1` was not aliased), ADR104's sandbox Region bullet, and the CLI checklist's `--region` row. `lego/backend/AGENTS.md`, ADR006, ADR049 and the Terraform checklist already described the w9/105 read-back.
