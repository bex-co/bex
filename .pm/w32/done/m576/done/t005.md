## Objective

The deploy page's log pane and the service's Logs page draw each coloured `==>` line with the same visible text as before, the marker coloured and the text bold, as Render's viewer does, with no stray `(B` or escape bytes in the text, a copied line or a download.

## Context

- `dashboard/src/features/logs/lib/ansi.ts` parses SGR and swallows `ESC ( B` (the charset selection in the shell and instance forms). It has not been tested on Render's exact forms: `0;34` then `1`, `0` then `1`; `34;1` then `0;22` and a closing `22`; `tput sgr0`'s `ESC ( B ESC [ m`.
- The log row's renderer, the Log Explorer Theme (w3/m531) and any copy or download action read the same messages.
- No dashboard code matches the narration's words (`dashboard/src/features/deploys/lib/deploy-window.ts` only names the live line in a comment).

## Steps

1. Add unit tests in `dashboard/src/features/logs/lib/__tests__/` that feed each of Render's seven forms through `ansi.ts` and check the visible text, the colour and the weight of each segment, and that no style leaks into the next line.
2. Check the deploy page and the Logs page with a coloured fixture line, and fix anything the tests surface.
3. Check what copy and download give: Render's copy reads plain. Match it, or record the difference.
4. Run `yarn lint` and `yarn test` in `dashboard/`.

## Files

- `dashboard/src/features/logs/lib/ansi.ts`, its tests
- the deploy page's and the Logs page's tests, as needed

## Acceptance criteria

- [ ] Each of the seven forms renders its visible text exactly, with the marker's colour and the text bold.
- [ ] `yarn lint` and `yarn test` pass.
