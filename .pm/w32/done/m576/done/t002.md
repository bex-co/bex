## Objective

Every line the control plane writes into a deploy's log carries t001's form, so REST, the subscribe stream, GraphQL and MCP return `\x1b[0;34m\x1b[1m==> \x1b[0m\x1b[1mDeploying...\x1b[0m` where they return `==> Deploying...` today.

## Context

- `lego/backend/internal/logs/progress.go`: every line goes through `progressEntry(deployID, t, msg)`, and the words live in constants (`deployingLine`, `timedOutLine`, `primaryURLRule`, …) and in `terminalLine`, `waitLine`, `oidcRefusalLine` and `narrated`.
- `narrated` and `unmarked` add the marker to each line of a failure reason and drop any marker a reason already carries. The styling must follow the marker, so a reason's lines are styled once.
- Ids come from `logID` (instance, timestamp, message), so a styled line gets a new id. A tail open across the control plane's roll may print one line twice, once plain and once coloured; nothing else depends on the old ids.
- The `text` filter compares the raw message by default and the visible text with `textMode=display` (`display.go`, `textprefilter.go`). The synthesized lines must follow the same rule as a coloured app line.
- Tests that pin these messages: `progress_*_test.go`, `logs_test.go`, `live_filters_test.go` and others in the package, and `lego/backend/internal/api/http_port_progress_test.go`.

## Steps

1. Give each line its kind where it is written, not by matching its words afterwards, and apply the form at one seam. Keep the plain words in the constants, so the docs and the tests can still name them.
2. Apply t001's forms to every line, the URL block's blank line and the multi-line failure reasons included.
3. Keep `displayText(message)` equal to today's plain line for every line, and assert that in a test across every line `progressLines` can write.
4. Update the tests that compare exact messages: compare the styled bytes where the test is about the form, and `displayText` where it is about the words.
5. Run `cd lego/backend && go test ./internal/logs/... ./internal/api/...`, then the full suite through `/land`'s gate.

## Files

## Acceptance criteria

- [ ] A test pins each Render-observed platform line byte for byte against the README's form (`Deploying...`, the `WEB_CONCURRENCY` line, the live line, each URL block line, `Exited with status 1`, the troubleshooting line, `Timed Out`, the port scan's timeout and docs lines, the detected-port line).
- [ ] Every other line carries t001's form, and its visible text is unchanged.
- [ ] A `textMode=display` search for `==> Deploying...` finds the line; a raw search for `Deploying` still does.

## Out of scope

- The build pod's and the instance's lines: t003, t004.
