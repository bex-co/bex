# A Node service with a Bun lockfile writes Render's `==> Using Bun version …` pair at each instance start, before `==> Running '<command>'`

Why: Render parity in a service's application log. On Render a native Node service that uses Bun (a `bun.lock` in the repository) writes `==> Using Bun version 1.3.4 (default)` and `==> Docs on specifying a Bun version: https://render.com/docs/bun-version` at each start of its instance, before `==> Running '<start command>'`. bex writes the Bun line in the build only, so its instance's log starts at the `Running` line.

- **Severity / estimate:** minor, ~1h: native-init must learn the image's Bun choice (an image label or env the native build already resolves, `ResolveNativeBun`, `lego/operator/internal/build/nativeversion.go`) and write the pair before the `Running` line it writes since w32/m575.
- **Seen:** w32/m575 t001's search of public Render logs, 2026-11-22.
- **Render reference:**
  - Pranav7758/AniCircle at `5fac202ebc` (2026-04-19): `runtime: node`, start command `node dist/index.js`, a `bun.lock`. After `==> Deploying...` and the `WEB_CONCURRENCY` line: `==> Using Bun version 1.3.4 (default)`, `==> Docs on specifying a Bun version: https://render.com/docs/bun-version`, then `==> Running 'node dist/index.js'`. `==> Using Node.js version 22.22.0 (default)` is in the build only.
  - harshagavadi/akshay at `dbfd3ed4b1` (2026-04-12): `runtime: node` with a `bun.lock`. The Bun pair before `==> Running 'bun run start'` at 13:39:09, and again at 13:39:25 right after `==> Exited with status 1`, before the second `Running`: it is written at every start.
  - Bubba898/luchadores-web#5 (2026-02-01): the pair before `==> Running 'yarn start'`.
  - Node services with no Bun lockfile (rohitjana573-hash/Rohit.bot-tryAgain, somen2k0/xtoolkit.live, Anmol498/CRM-PRO), Python (martin7-glitch/LetterMusicBox, bitebox420-creator/BiteBox_3) and Ruby (kkraoi/oshi_no_Co_de) write no version line at start. Kitten772/TriviaPaws (2025-05-24, no lockfile) prints the Bun line in its build only.
- **Done when:** a native Node service built with a Bun lockfile, `.bun-version` or `BUN_VERSION` writes the two lines with the resolved version and its source (`(default)` or as the build words it) at every start of its instance, before `==> Running '<command>'`, in `bex logs -r <srv>` with `type=app`. A Node service with no Bun choice, and every other runtime, writes none. native-init's tests cover both.
- **Done (2026-11-23):** `NativeChoice.StartLines` (`lego/operator/internal/build/nativeversion.go`) returns the resolved version line and its docs line without any build-time lookup note (plain until a Render capture shows ANSI codes, w32/m576), and `addNativeBun` (`lego/operator/internal/build/nativeresolve.go`, `nativeInitStartLinesStep` in `nativeinit.go`) writes them to `/opt/bex/native-init-lines` for native Node services starting under `native-init` (including build sources, excluding static sites and non-Node runtimes). `native-init` (`lego/operator/cmd/native-init/main.go`) prints `/opt/bex/native-init-lines` immediately before `==> Running '<command>'` on every announced start (restarts and free spin-ups included; absent on quiet/non-shell launches, zero extra env vars). Verified by `TestNativeInitWritesStartLinesBeforeRunning` (`cmd/native-init`) and `TestNativeNodeBunWritesStartLinesForNativeInit` (`internal/build`), full operator `make test` and `make lint`; updated `docs/render-artifacts/live-deploy-following.md`, `docs/render-artifacts/native-version-narration.md`, and `docs/ADR018-render-parity.md`.
