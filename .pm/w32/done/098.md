# Native build emits no `==> Installing Node.js version <v>...` line after the Node.js version docs line

Why: Render parity in native build logs. When Render resolves an uncached runtime version, it prints `==> Installing Node.js version <v>...` (and Python/Poetry/uv equivalents) after the version docs line in `renderlog.BuildRuntime` blue; bex jumps straight from the docs line to `==> Running build command …`.

- **Severity / estimate:** minor, ~45m: check when bex installs/pulls an uncached runtime version vs reuses a prebuilt base image, emit `==> Installing <Runtime> version <v>...` in `renderlog.BuildRuntime` where appropriate, or record the exact base-image divergence in ADR018 if uncached installs never occur.
- **Seen:** w32/m576 t001 and t008/t009 live walk on production pin `ac882b5f557f` (2026-11-23, `bex-canary` native Node service `srv-dc22ac905vrc73fj7jk0` (disposable), deploy 1 logged `==> Requesting Node.js version >=20`, `==> Using Node.js version 26.13.1 via /opt/render/project/src/examples/hello-node/package.json`, `==> Docs on specifying a Node.js version: https://render.com/docs/node-version`, then `==> Running build command 'npm install'...` with no `Installing` line).
- **Where:** `lego/operator/internal/build/nativeversion.go` and `nativeresolve.go`; `docs/render-artifacts/native-version-narration.md:131` already catalogues Render's `Installing Node.js / Python / Poetry / uv` lines.
- **Render reference:** ivanseibel/tretta `docs/work/reports/assets/T014-public/04b-render-logs.json` at `b0f216c985` (`\x1b[34;1m==>\x1b[0;22m \x1b[1mInstalling Node.js version 22.23.1...\x1b[22m`).
- **Done when:** uncached native runtime installs emit Render's `==> Installing <Runtime> version <v>...` line in `renderlog.BuildRuntime` form with unit tests (or, if bex's prebuilt base-image model only pulls layers without installing, ADR018 § Logs, Build logs records the exact condition and tests pin it).

**DONE 2026-11-23.** Audited bex's native build pipeline (`lego/operator/internal/build/nativebases.go`, `nativeresolve.go`, `nativeversion.go`, `build.go`, `cmd/native-resolve/main.go`) against public Render build logs (`ivanseibel/tretta` `04b-render-logs.json` at `b0f216c985`, `thedimlebowski/soakup#35`, `render-examples/workflow-agents-workshop-ts#1`, `manishgupta2026/TG-Drive#8`, `grimtear/Test-Sheet-Dashboard#1`, `abhi208361-alt/AI-Based-SOC-with-Automated-Firewall-Response-2.0#11`, `alexsandovalball/tombrady420#109`, `peacefulseeker/django-libraryms#4`, `chartbrew/chartbrew#202`, `Higashi-Masafumi/jaXiv#109`). Render omits `Installing` for pre-baked defaults and prints it when its build container downloads and installs a non-prebaked version (even on cached deploys). On bex, `nativeCommonBase` carries no pre-installed primary runtime: `resolve-native-runtime` runs before BuildKit and copies every primary language runtime (Node, Python, Ruby, Elixir, Go, Rust) and Bun from digest-pinned prebuilt OCI images (`COPY --link --from=…`), never running an in-build runtime installer, while Poetry and uv install via BuildKit `RUN … pip install` layers in the subsequent `buildkit` container after every runtime and companion's `Using`/`Docs` lines have already printed. Recorded this exact condition (as a recommendation without user sign-off) in `docs/ADR018-render-parity.md` § Logs, Build logs, `docs/render-artifacts/native-version-narration.md` § Seen but not adopted, and `docs/render-artifacts/live-deploy-following.md` § A native build's own lines, and pinned it with `TestNativeResolveOmitsInstallingLineAndUsesPrebuiltOCIImages` (`narration_test.go`) and `TestNativeBuildLogOmitsInstallingLineForRuntimeLayersAndPythonTools` (`native_log_display_test.go`).
