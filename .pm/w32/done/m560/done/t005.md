## Objective

For a release whose app container launched a start command on a native image (t001's `command`), the deploy log writes `==> Running '<command>'` at each recorded app-container start (`AppStartedAt`) before the verdict.

## Context

- Render quotes the command as configured, with `$PORT` unexpanded (frayel/devagent#62). It prints the line again each time the command starts again: after `Exited with status 1` in DerekSopok/EMS-Kahoot#3, and after `Timed Out` in vincentbellemare90-commits/Mon-bot#1.
- A Dockerfile image prints none, with or without a Docker Command (darthjee/ward#109, HKUDS/nanobot#6607). A prebuilt image, a static site and a cron job's deploy have no native start command.
- The command is the release's own, so a later edit never rewords an earlier deploy's log.
- The verdict lines (`rendersVerdict`, `progress.go:622`) stay at `finished_at`. A start the operator recorded after the close does not belong to this deploy.

## Acceptance criteria

- [ ] Unit tests show one line per recorded start, in order, before `==> Exited with status N` or `==> Your service is live 🎉`.
- [ ] They show the command exactly as recorded, `$PORT` included.
- [ ] They show no line for a Dockerfile service, a prebuilt image, a static site, a cron job or a row with no recorded command.

## Done (2026-11-22)

`==> Running '<command>'` at each recorded start up to the close, quoted as recorded (`$PORT` included). Tests: `TestRolloutLinesQuoteTheCommandAtItsRecordedStarts`, `TestRolloutLinesKeepTheirOrderWithinASecond`, and the table test's Dockerfile, prebuilt, static, cron and no-record rows.
