## Objective

Replace the `SANDBOX_NETWORK_POLICY_UNSUPPORTED` refusal: accept `networkPolicy.type` `allow-all` (and the deprecated `default` alias), `allow-list` with `rules`, and `deny-all`; omit means allow-all. Validate rules with named 400s, report the policy on reads, and keep it across suspend/resume.

## Context

- `lego/backend/internal/sandbox/rest.go` create body; GraphQL `createSandbox`; MCP `spawn_sandbox`
- CLI: `--network-policy`, `--allow-egress-https <domain>` (implies allow-list)
- Agent-session create path `CreateAgentSessionSandbox` must keep passing deny-all explicitly

## Steps

1. Parse and normalize the policy; reject bad hostnames, schemes, ports, paths, uppercase, >100 rules, and rules on non-allow-list policies, each by name.
2. Persist the effective policy in the reserved metadata and echo it on get/list.
3. Make the agent-session path pass deny-all explicitly and assert it in a test.
4. Update the checklist row for `--allow-egress-https` and `--network-policy`.

## Acceptance criteria

- [ ] `bex sandboxes create` with no policy reports `allow-all`
- [ ] `--allow-egress-https api.github.com` reports `allow-list` with that rule
- [ ] Each invalid rule form answers a 400 naming the problem
- [ ] Agent-session sandboxes still report deny-all

## Out of scope
