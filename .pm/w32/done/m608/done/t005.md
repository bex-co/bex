## Objective

Verify that every tenant-facing log surface agrees on immutable historical deploy build lines and IDs after source switches, and that no deploy DTO leaks unrequested fields compared with Render's API.

## Steps

1. Using t004's disposable fixture after both the `--repo` switch and the `--image` switch (before deleting it), read the initial deploy's build logs across:
   - CLI `bex logs -r <id> --type build -o json`;
   - REST `GET /v1/logs?resource=<id>&type=build`;
   - GraphQL `logs` (using the dashboard's `Logs` query shape for the deploy pane);
   - MCP `list_logs`;
   - SSE/WebSocket subscribe stream (verify in code/tests that `progressFollower` uses the same `buildProgressLines` path).
2. Assert every surface returns the identical historical `==> Build queued`, `==> Building from https://github.com/bex-co/bex@<sha>`, and `==> Deploying...` lines and `id`s.
3. Read `GET /v1/services/<id>/deploys` (REST), GraphQL `deploys`, and MCP `list_deploys` and confirm no unexpected `repo` or `branch` field was added to Render's deploy shape.
4. File any unrelated parity drift as a separate inbox note rather than expanding this milestone. Record the results here.
