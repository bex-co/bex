# `bex docs` opens GitHub source markdown, not the public docs site

Why: `render docs` opens Render's public docs site. `bex docs` still lands on a raw repo file on GitHub, even though the public site at `https://bex.co/docs` is live and is where every other Bex surface points (`bex.co/docs/cli`).

- **Severity:** minor (branding/parity polish; nothing breaks)
- **Versions:** bex v0.4.0 (latest release, `~/.local/bin` untouched; the release tarball was verified with `checksums.txt`) and HEAD `ee2441fc6`. Release pin is Render CLI v2.29.0, HEAD pin is v2.35.0. The `docs` override is the same at both. Deployed revision: n/a (client-side only).
- **Context:** 2026-11-05 `/qa-find-bugs-cli` sweep, offline/unauthenticated (QA login unavailable this run). Linux arm64, non-TTY.
- **Repro:** run `bex docs` with a stub `xdg-open` on `PATH` that logs its argument.
- **Expected:** the public Bex docs site opens, the same way the pinned upstream `render docs` opens `render.com/docs` (`docs/cli-compatibility-checklist.md` `docs` row). Target: `https://bex.co/docs` (it 307s to `/docs/intro`) or the CLI page `https://bex.co/docs/cli` ("Command line interface | Documentation | bex.co", HTTP 200).
- **Actual:** exit 0, and the browser is given `https://github.com/bex-co/bex/blob/main/docs/bex-cli.md`, the internal engineering guide (config precedence, pin-bump runbook), not the customer docs.
- **Attribution:** Bex launcher.
- **Root cause:** `lego/cli/internal/branding/branding.go:35-37` sets `DocsURL` to the GitHub file. Its comment says "There is no docs.bex.co host yet", which is no longer true. `overrideDocs` (`branding.go:161-173`) opens it. It is the only `github.com/bex-co/bex/blob` destination in `lego/cli`.
- **Fix:** set `DocsURL = "https://bex.co/docs"`, matching upstream's site-root behavior. (`/docs/cli` would also do; pick one and keep `Long` consistent: "Open the Bex docs in your browser.") Update the stale comment, `docs/bex-cli.md:192`, and the `docs` row at `docs/cli-compatibility-checklist.md:317`. No REST/GraphQL/MCP/UI surface is involved.
- **Blast radius:** one constant and one caller (`overrideDocs`). The skills pack already rewrites render.com docs links to `https://bex.co/docs/cli` (`internal/skills/packgen/packgen.go:111`), so this aligns the two.
- **Regression checks:** a branding test asserts that `bex docs` opens a `https://bex.co/docs` URL (stub opener), and `bex docs --help` still says Bex. Then run `cd lego/cli && go test ./...`.
- **Unverified:** whether the user prefers the site root or `/docs/cli` as the target.
- **Dedupe:** w8/m29 t003 only required "not render.com/docs", and nothing on the board (open or done) covers moving off GitHub. Not in `DO_NOT_DO.md` or the ADR018 divergences.
- **Estimate:** 20m

**Done 2026-11-08 (`/loopx w32`):** `DocsURL` is now `https://bex.co/docs` (site root, matching upstream's `render docs` → `render.com/docs`), the stale "no docs host" comment is gone, `Long` reads "Open the Bex docs in your browser.", and `docs/bex-cli.md` plus the checklist `docs` row say so. `TestApplySetsUseAndHelpChrome` (internal/branding) pins the URL and copy; `cd lego/cli && go test ./...` passes.
