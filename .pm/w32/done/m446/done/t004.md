## Steps

1. Three times: `bex services create --name qa-<date>-<nonce>-lat<n> --type web_service --image docker.io/traefik/whoami:v1.10.3 --plan free --confirm -o json`, then `bex deploys create <id> --image docker.io/traefik/whoami:v1.10.2 --wait --confirm -o json`.
2. Poll `bex deploys list <id> -o json` and `GET /v1/services/{id}/deploys` once a second from the create until 60 s after the second deploy is `live`. Count non-`200` answers and record any body.
3. Delete the fixtures by id and confirm `404`.

- **The one failure on each side got no HTTP answer at all.** Both were the last poll of run 2, started at about 12:18:36. The CLI printed `Error: failed to list deploys: Get "https://api.bex.co/…/deploys?limit=20": net/http: TLS handshake timeout`. curl printed `(28) Connection timed out after 20003 milliseconds`, with status `000`. The body the poller printed beside it is the previous call's. Neither request reached the origin: the Traefik access log has run 2's polls up to 12:18:35.988 and none after. So this was this host's link to Cloudflare, about 20 s with no new connections. It is not an answer from bex and not an onboarding fault. The delete at 12:18:57 and the `404` check at 12:19:01 went through.
- **Server side, 12:07–12:25 UTC:** no `api.bex.co` 503 in the Traefik log for any caller, 0 introspection errors and 0 5xx (`bex_api_http_requests_total`) on the new replicas, and no gate failure line in their logs.
- **Fixtures:** all three were deleted with `bex services delete --confirm`. `GET /v1/services/{id}` answers `404` for each. The CLI was logged out, and both Kratos sessions were signed out (`qa-login.sh --logout`).
