# `bex agent … -o yaml` prints large integers as floats and changes 16-digit ones

Why: `-o yaml` is documented to print the API's own answer. A shared file of a megabyte or more shows `size: 2.097152e+06`, and an integer in the session's own `outcome.result` such as `9007199254740993` comes out as `9.007199254740992e+15`, a different number. A script reading the YAML gets a float where the API sent an integer, and can get the wrong value.

- **Severity:** minor (YAML only; `-o json` is exact)
- **Versions:** bex v0.5.0 (release) and a checkout build of HEAD `57498b14b` (Render CLI pin v2.36.0). Same result on both. Deployed revision: n/a (client-side; `bex agent` is Bex-native code).
- **Context:** 2026-11-11 `/qa-find-bugs-cli w32` loop sweep, offline (the QA sign-in is still refused, see w32/m284). No production request: a loopback stub of the agent-session routes, shaped after `lego/cli/testdata/agent-cli-contract.json`, with a placeholder `BEX_ACCESS_TOKEN` and `BEX_WORKSPACE`. Non-TTY.
- **Repro:** the stub's session has an outcome file of 2097152 bytes and `outcome.result` `{"ok": true, "rows": 1500000, "ratio": 0.5, "issueId": 9007199254740993, "count": 999999}`. Its file list has sizes 2048, 2097152 and 123456789.
  1. `bex agent get <ags-id> -o yaml`
  2. `bex agent files <ags-id> -o yaml`
  3. The same two with `-o json` (control).
- **Expected:** the numbers the API sent: `size: 2097152`, `rows: 1500000`, `issueId: 9007199254740993`. `docs/bex-cli.md:182`: "`-o json` (or `yaml`) prints the API's own answer on stdout".
- **Actual (exit 0):**

  ```text
  $ bex agent get <ags-id> -o yaml          $ bex agent get <ags-id> -o json
  size: 2.097152e+06                        "size": 2097152
  count: 999999                             "count": 999999
  issueId: 9.007199254740992e+15            "issueId": 9007199254740993
  ratio: 0.5                                "ratio": 0.5
  rows: 1.5e+06                             "rows": 1500000

  $ bex agent files <ags-id> -o yaml
  size: 2048
  size: 2.097152e+06
  size: 1.23456789e+08
  ```

  Integers below 1000000 print as integers. From 1000000 up they print in exponent form, and above 2^53 the digits change.

- **Attribution:** Bex launcher (`lego/cli/internal/agent`).
- **Root cause:** `writeRaw` (`lego/cli/internal/agent/render.go:53-65`) turns the API's JSON into YAML by `json.Unmarshal` into `any`, which makes every number a `float64`, then `yaml.Marshal`. yaml.v3 formats a `float64` with `strconv.FormatFloat(…, 'g', -1, 64)`, which switches to exponent form at 1e6. The JSON path indents the raw bytes and never decodes them, so it is exact.
- **Fix:** decode with `json.Decoder.UseNumber()` and convert each `json.Number` before `yaml.Marshal`: an integer literal becomes `int64` (or `uint64`), a literal with `.`, `e` or `E` becomes `float64`, and an integer too large for 64 bits is emitted as a plain `!!int` scalar node carrying its own digits. Nothing else in the output changes. No REST/GraphQL/MCP/UI surface is involved.
- **Blast radius:** `writeRaw` is the only JSON-to-YAML conversion in `lego/cli` and has six callers: `list` (`agent.go:637`), `run`/`send`/`get`/`cancel` through `show` (`agent.go:765`), `wait` and `--wait`/`--follow` through `report` (`agent.go:803,808`), and `files` with and without `--download` (`files.go:79,112`). `logs` refuses YAML. Real fields that reach 1000000: an attachment's `size` (files go up to 25 MiB, `agentsession.MaxShareFileBytes`), `outcome.files[].size`, and any integer in the user's own `outcome.result`. Upstream commands marshal typed structs and are not affected.
- **Regression checks:** beside `TestListCancelAndGet` (`lego/cli/internal/agent/agent_test.go:786`, which already runs `get -o yaml`):
  - a session whose outcome file is 2097152 bytes → `size: 2097152`;
  - `outcome.result` with `1500000`, `9007199254740993`, `0.5` and `1e3` → the first two keep their digits, `0.5` stays a float;
  - `files -o yaml` with a 123456789-byte file → `size: 123456789`;
  - `-o json` output is byte-for-byte what it is today.

  Then `cd lego/cli && go test ./...`.

- **Unverified:** no live session was read; the field list comes from the backend types (`lego/backend/internal/agentsessions/models.go:491`, `attachments.go:65`). YAML output also sorts keys alphabetically where JSON keeps the API's order; that is not part of this note.
- **Dedupe:** nothing in `.pm/` (open or done) covers YAML number output for `bex agent`. w9/m177 shipped the command; its one YAML test checks that the output parses. Not in `DO_NOT_DO.md`.
- **Estimate:** 30m

## Done (2026-11-11, `/loopx w32`)

- **Fixed:** `writeRaw` (`lego/cli/internal/agent/render.go`) decodes the answer with `json.Decoder.UseNumber()` and passes it through `yamlValue` before `yaml.Marshal`. An integer literal is emitted as a plain YAML scalar carrying the API's own digits, so `size: 2097152`, `rows: 1500000` and `issueId: 9007199254740993` print as sent. A number with a fraction or an exponent stays a `float64` and prints as before (`0.5`, `1e3` as `1000`); one outside `float64`'s range keeps its literal.

  This is simpler than the note's plan (`int64`, then `uint64`, then a tagged node): one branch covers every size, and an untagged node is what prints a 30-digit integer plain, where a `!!int` tag would be written out. Data after the JSON value is still refused, as on the JSON branch. `-o json` is unchanged.

- **Tests:** `TestYAMLOutputKeepsIntegersExact` (`lego/cli/internal/agent/agent_test.go`; the fake can now serve a session answer verbatim): `get -o yaml` on a session with a 2 MiB outcome file and a result holding `1500000`, `9007199254740993`, a 30-digit integer, `-42`, `0.5`, `1e3`, `1e400` and a string of digits; the 16-digit id reads back from the YAML as the same number; `get -o json` is byte for byte the API's answer, re-indented; `files -o yaml` prints `size: 123456789`. With `UseNumber` removed it fails. `go test ./...` and golangci-lint v2.15.0 pass for `lego/cli`.
- **Docs:** `docs/bex-cli.md` § `bex agent`, the Output rule.
- **Still unverified:** no live session was read (QA sign-in, w32/m284). Not changed: YAML output sorts keys alphabetically where JSON keeps the API's order. The fix reaches users with the next `bex-cli` release.
