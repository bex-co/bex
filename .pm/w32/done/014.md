# `bex agent … -o json` ends with a blank line

Why: `bex agent` means to end its JSON with one newline: `writeRaw` appends exactly one. Against bex-api the output ends with two, so `get`, `list`, `wait`, `run`, `send`, `cancel` and `files` print an empty last line, and a file written from the output ends with a blank line. The JSON still parses.

- **Severity:** minor (cosmetic; `jq` and `$(…)` are unaffected)
- **Versions:** bex v0.5.0 (release) and a checkout build of HEAD `cdae182b6` (Render CLI pin v2.36.0). Same result on both. Deployed revision: n/a (client-side; the server behavior it meets is in the repo, below).
- **Context:** 2026-11-11 `/qa-find-bugs-cli w32` loop sweep, offline (the QA sign-in is still refused, see w32/m284). No production request: a loopback stub that answers a session read and a session list with a body ending in a newline, as bex-api does, with a placeholder `BEX_ACCESS_TOKEN` and `BEX_WORKSPACE`. Non-TTY.
- **Repro:**
  1. `bex agent get <ags-id> -o json | tail -c 4 | od -c`
  2. `bex agent list -o json | tail -c 4 | od -c`
  3. `bex agent wait <ags-id> -o json | tail -c 4 | od -c`
- **Expected:** the output ends `}\n` (or `]\n`): the one newline `writeRaw` adds on purpose. (Upstream's own commands print the document with no final newline, `pkg/command/wrapper.go:126-132`; `bex agent` is Bex-native and ends it like a text file. Either way, not two.)
- **Actual (exit 0):** all three end with two newlines:

  ```text
  $ bex agent get <ags-id> -o json | tail -c 12 | od -c
  0000000   u   r   n   s   "   :       1  \n   }  \n  \n
  $ bex agent list -o json | tail -c 12 | od -c
  0000000   "   :       1  \n           }  \n   ]  \n  \n
  ```

- **Attribution:** Bex launcher (`lego/cli/internal/agent`).
- **Root cause:** `writeRaw` (`lego/cli/internal/agent/render.go`) prints the API's bytes through `json.Indent` and then appends a newline. `json.Indent` keeps trailing whitespace of its input ("if src ends in a trailing newline, so will dst"), and the client hands it the body untrimmed (`api.do`, `lego/cli/internal/agent/api.go:208`). bex-api ends every JSON body with a newline: `core.WriteJSON` encodes with `json.Encoder.Encode` (`lego/backend/internal/core/http.go:259`), and the agent-session routes answer through it (`lego/backend/internal/agentsessions/rest.go:41,87`). So the output is the indented document, the body's own newline, then `writeRaw`'s.

  An answer for several sessions is joined by `rawArray` and ends `]`, so `bex agent wait a b -o json` prints one newline; only single answers and lists print two.

- **Fix:** trim trailing whitespace from the answer before indenting it (`bytes.TrimSpace(raw)` in `writeRaw`). YAML output re-encodes the value and is not affected. No REST/GraphQL/MCP/UI surface is involved, and the server's newline is correct.
- **Blast radius:** one function with six callers (`list`, `show` for `run`/`send`/`get`/`cancel`, `report` for `wait` and `--wait`/`--follow`, `files` with and without `--download`). `logs -o json` prints rows through `compactJSON` and is not affected.
- **Regression checks:** in `lego/cli/internal/agent/agent_test.go`, whose fake already answers through `json.Encoder.Encode`: `get -o json` and `list -o json` end with exactly one newline; the indented document is otherwise unchanged. Then `cd lego/cli && go test ./...`.
- **Unverified:** production's bytes were not captured (no sign-in). The claim rests on the server's writer in the repo and the stub that mimics it.
- **Dedupe:** nothing in `.pm/` (open or done) covers the end of `bex agent` JSON output. w32/011 changes the YAML branch of the same function and does not touch this. Not in `DO_NOT_DO.md`.
- **Estimate:** 10m

## Done (2026-11-11, `/loopx w32`)

- **Fixed:** `writeRaw` (`lego/cli/internal/agent/render.go`) trims the JSON whitespace that ends the answer before `json.Indent`, so the output ends with the one newline it appends.
- **Correction to this note:** `files -o json` was never affected. Like a wait on several sessions, it joins per-item answers with `rawArray`, which ends `]`. The commands that printed the blank line were `get`, `run`, `send`, `cancel`, a wait on one session, and `list`.
- **Tests:** `TestJSONOutputEndsWithOneNewline` (`lego/cli/internal/agent/agent_test.go`), against the fake that already ends its bodies with a newline: `get`, `list` and `wait` on one session end `}\n` or `]\n` with no blank line (all three fail without the trim); `wait` on two sessions and `files` are the controls. `go test ./...` and golangci-lint v2.15.0 pass for `lego/cli`.
- **Still unverified:** production's bytes (QA sign-in, w32/m284). The fix reaches users with the next `bex-cli` release.
