# 032 — A Blueprint `previewValue` is accepted with a notice when the file enables no previews, as on Render

Why: Render applies `previewValue` only in preview environments, so in a file that enables none it changes nothing there, while bex refuses the whole Blueprint and a Render user's file does not apply.

- **Render (read 2026-11-16):** blueprint-spec § Preview environments: "Use the `previewValue` field to override environment variable values for web and private services in preview environments"; § `previews.generation`: "If you omit this field, preview environments are disabled for any linked Blueprints." preview-environments § Environment variables: "Environment variable overrides are supported for web services, private services, and environment groups." The pinned schema allows `previewValue` on `envVarFromKeyValue`, which both service and `envVarGroups` entries use (`lego/backend/internal/apps/schema/render.yaml.json`).
- **bex today:** `lego/backend/internal/apps/schema/capabilities.json` records `#/definitions/envVarFromKeyValue/properties/previewValue` as `unsupported` ("fail-closed so preview intent is never silently dropped"); `blueprint_compiler.go:746-747` refuses it; `blueprint_compiler_test.go:278-282` asserts the refusal; the corpus guard excuses it (`blueprint_render_examples_corpus_test.go:35`); ADR049:449 lists it as a deliberate divergence, and w8/203 kept it refused. None of these carries a user sign-off; the user decision is the previews non-goal (`DO_NOT_DO.md`, w2/m11), which this note keeps.
- **Fix:** a value-aware acceptance like w8/203's `AcceptPreviewOptOut` (`blueprint_schema.go:87-88`, `:252`). When the file enables no previews (no root `previews.generation` other than `off`, no `previewsEnabled: true`, no service `previews` or `pullRequestPreviewsEnabled` that enables them), accept `previewValue` on service and env-group entries, apply the entry's own `value`, and emit one located `warning` notice per entry on validate, plan and sync, as w8/293 does for `sync: false` in a group (`parsedEnvGroup.ignored`, `lego/backend/internal/apps/deploy.go`). For example: "previewValue has no effect: this Blueprint creates no preview environments". A file that enables previews stays refused as today, so preview intent is never silently dropped.
- **Tests:** the compiler test flips to accept-with-notice; a group entry; a file that also enables previews is still refused; the corpus guard stops excusing `previewValue` on its own. Count how many render-examples files this unblocks with `scripts/render-examples-corpus.sh` while here.
- **Docs:** ADR049 (the divergence list at :449 and § Preview opt-outs), the capability registry reason, and the ADR018 Blueprint row.
- **Decision state:** accepting is this proposal's recommendation, resting on ADR008 Render parity first and the AGENTS.md rule to amend a design that conflicts with parity; it is not a recorded user decision.
- **Out of scope:** `previewPlan` and `previewDiskSizeGB` (same reasoning; a separate note if wanted).
- Source: `/pm-brainstorm` for Render parity of render.com/docs/environment-variables, 2026-11-16, item 4. Sizing: one registry rule, one notice, tests and docs, ~50m, so an inbox note.

## Outcome (2026-11-17)

- **Done.** The capability registry marks `#/definitions/envVarFromKeyValue/properties/previewValue` `acceptWithoutPreviews` (handler `CompileBlueprintSource`, fixture `previews_test.go:TestBlueprintPreviewValueWithoutPreviews`). The compiler's capability walk records whether any preview toggle (root `previews`/`previewsEnabled`, a service's `previews`/`pullRequestPreviewsEnabled`) enables previews. If none does, each `previewValue` is accepted, the entry's own `value` applies (the typed decode drops the field), and validate, plan and sync carry one located `warning`: "previewValue has no effect: this Blueprint creates no preview environments". If one does, each `previewValue` is refused beside the toggle, as before.
- **Tests:** `TestBlueprintPreviewValueWithoutPreviews` (12 cases: no settings and every opt-out accept on a service and an env-group entry; every enabling toggle refuses both), `TestBlueprintPreviewValueAppliesTheEntryValue` (parsed values, validate warnings by path and line, planned create's two notices), and the flipped compiler test. Three mutations were caught: no acceptance, no `enabled` flag, and no warnings.
- **Corpus:** of the 181 render-examples files fetched 2026-11-17, only `preview-environment` uses `previewValue`, and it enables previews, so the count stays 167 valid. The guard comment now says `previewValue` is refused only in a file that enables previews.
- **Docs:** ADR049 (corpus-guard divergence list, § Preview opt-outs), ADR006's capability-registry row, ADR018's Blueprint row.
