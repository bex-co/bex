# Switching a Git service with `rootDir` or `buildFilter` to a prebuilt image leaks those Git-only fields on reads and permanently breaks `bex services create --from`

Why: `view(a)` (`lego/backend/internal/apps/service.go:1255-1298`) hides `Branch` and `AutoDeploy` for prebuilt-image services (`w9/069`, `w4/418`) and `generateServiceEntry` hides `rootDir`/`buildFilter` for Blueprint export (`w4/288`), but `view(a)` still projects `RootDir`, `BuildFilter`, `DockerfilePath`, `DockerContext`, and `Builder` from the retained `App.Spec`, so every REST, GraphQL, and MCP read of a switched image service returns values that `POST /v1/services` refuses and `bex services create --from` can never clone it.

- **Severity / estimate:** **major**, ~45m. Any monorepo (`rootDir`) or build-filtered (`buildFilter`) Git service switched to a prebuilt image becomes permanently un-cloneable via `bex services create --from` (even with `--root-directory ""`), cannot have those fields cleared via `bex services update`, and returns contradictory Git build metadata on REST, GraphQL, and MCP.
- **Versions:** released `bex` v0.9.0 (`bex-0.9.0-linux-arm64.tar.gz`, compatible with Render CLI `v2.36.0`, upstream pin `4fd34231b637`) and checkout build of `lego/cli` at `7c27a28992` (pinned to Render CLI `v2.37.0`, `11ef59f330dedec290f8d71d89b8f7379bbbed09`); repo HEAD synced to `9f914815ea`; production platform pin `9fdf7e0a1171` (`cded300699`). `lego/backend/internal/apps/service.go` and `docker_context.go` are unchanged through `9f914815ea`.
- **Context:** routine `cli-qa` sweep `7b4e`, 2026-11-23 21:48–22:02 UTC, `https://api.bex.co/v1/`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), human device login (`bex login`), non-TTY `-o json`.

## Attribution and root cause

- **Attribution:** server (`lego/backend/internal/apps/`).
- **Pinned CLI consumer (`github.com/render-oss/cli@v1.1.3-0.20261117005113-11ef59f330de`):**
  - `pkg/service/clone.go:98,127-134,211,279-286` copies `source.RootDir` and `source.BuildFilter` verbatim into `ServiceCreateInput` whenever the user does not supply non-empty overrides (`cmd/servicecreate.go:74` binds `--root-directory` with default `""`, so `--root-directory ""` leaves the input pointer nil and `withDefault` still copies `source.RootDir`, and there is no flag to clear `buildFilter`).
  - `pkg/service/create.go:64-67,84-86` serializes `body.RootDir` and `body.BuildFilter` on `POST /v1/services`.
- **Server root cause:**
  - `SetSourceAndRegistryCredential` / `settleSourceSwitch` (`lego/backend/internal/apps/build_strategy.go:179-182`) intentionally keeps `App.Spec.RootDir`, `BuildFilter`, `DockerfilePath`, `DockerContext`, `Builder`, and `Runtime` on the CR so switching back to Git restores them (`w4/m202`, `w4/288`, `w32/056`).
  - `view(a *appv1alpha1.App)` (`lego/backend/internal/apps/service.go:1255-1298`) already hides `Branch` (`imageBackedBranch`, `w9/069`) and `AutoDeploy`/`AutoDeployTrigger` (`imageBackedAutoDeploy`, `w4/418`) when `prebuiltImageSource(a.Spec)` is true, and `generateServiceEntry` (`blueprint_generate.go:631-652`, `w4/288`) already hides `rootDir`, `buildFilter`, `dockerfilePath`, and `dockerContext` for Blueprint export — **but `view(a)` still copies `RootDir` (`:1275`), `BuildFilter` (`:1290`), `DockerfilePath` (`:1276`), `DockerContext` (`:1277` via `viewDockerContext` at `docker_context.go:95-100`, which still emits non-empty stored `spec.DockerContext`), `Builder` (`:1257`), and `BuildCommand` (`:1255`) unconditionally**.
  - On REST, `envSpecificDetails` (`render.go:687-694`) already overrides `dockerfilePath`/`dockerContext` to `""` when `a.Runtime == "image"`, but top-level `rootDir` and `buildFilter` (`render.go:470-471`) pass straight through from `AppView` — and GraphQL (`graphql.go:444-482`) and MCP (`mcp.go:1190`, via `toRenderService`) read the same `AppView`.

## Fix

- In `lego/backend/internal/apps/service.go` (`view(a)` at `:1255-1298`) and `lego/backend/internal/apps/docker_context.go` (`viewDockerContext` at `:95-100`):
  - Gate the Git-only read fields on `!prebuiltImageSource(a.Spec)` (matching `imageBackedBranch` and `imageBackedAutoDeploy`): when `prebuiltImageSource(a.Spec)` is true, project `RootDir: ""`, `BuildFilter: nil`, `DockerfilePath: ""`, `DockerContext: ""`, `Builder: ""`, and `BuildCommand: ""`.
  - Keep `App.Spec.RootDir`, `BuildFilter`, `DockerfilePath`, `DockerContext`, `Builder`, and `Runtime` untouched on the CR so switching back to Git (`w4/m202`, `w4/288`, `w32/056`) continues to restore them immediately on read and on deploy.
  - Ensure `render.go` continues to emit `"rootDir": ""` (required non-omitted string per `w4/421`) and omit `buildFilter` (`omitempty`) for image services, and that GraphQL and MCP automatically agree via `AppView`.

## Blast radius

- Affects `AppView` on every read surface for prebuilt-image services that retain Git fields on `App.Spec`: REST (`GET`/`PATCH`/`DELETE /v1/services*`, `POST /v1/services`), GraphQL (`service`, `services`, and service mutations), and MCP (`get_service`, `list_services`, `update_service`).
- `buildSourceView` (`lego/backend/internal/apps/build_sources.go:577-583`) is unaffected: image build sources take the `if a.Spec.Image != ""` branch and never read `v.RootDir`/`v.BuildFilter`/`v.DockerfilePath`/`v.DockerContext`.
- `generateServiceEntry` (`blueprint_generate.go:631-652`) reads `a.Spec` directly and is unaffected (already tested by `TestGenerateBlueprintAfterGitToImageSourceSwitch`).
- Audit dashboard consumers (`dashboard/src/features/services/`) and existing backend tests (`blueprint_generate_image_source_test.go`, `image_source_patch_test.go`, `cron_docker_command_test.go`, `native_image_switch_test.go`, `terraform_provider_test.go`) to confirm nothing relies on `AppView` exposing stale `rootDir`/`buildFilter`/`dockerfilePath`/`dockerContext`/`builder` while `runtime == "image"`.
