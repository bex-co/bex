# CLI installer fails with old cosign (no minimum version stated)

Why: a user following the documented one-line install with an older `cosign` on PATH gets a cryptic signature error and no bex, at the very first step of the CLI journey.

## Finding (2026-11-04, live install on linux/arm64)

- `curl -fsSL https://raw.githubusercontent.com/bex-co/bex/main/scripts/install-bex.sh | sh` → resolves bex-cli v0.3.3.
- With **cosign v2.4.1** on PATH, `cosign verify-blob --bundle checksums.txt.sigstore.json …` fails:
  `Error: bundle does not contain cert for verification, please provide public key` → installer prints `checksums.txt signature verification failed — refusing to install` and exits 1.
- With **cosign v3.1.4** the same release verifies (`Verified OK`) and installs.
- Likely cause (unverified): `.github/workflows/cli-release.yml:104` signs with `sigstore/cosign-installer` v4.1.2 (cosign v3.x), whose `--bundle` output is the newer Sigstore bundle format that cosign v2.4 cannot read. The exact minimum reader version is not yet established.
- `bex upgrade` is unaffected (in-process sigstore verification, `lego/cli/internal/upgrade/verify.go`).

## Fix

1. Establish the oldest cosign that verifies a current `bex-cli/v*` bundle (bisect v2.4 → v3.x against v0.3.3's `checksums.txt.sigstore.json`).
2. `scripts/install-bex.sh`: before `verify-blob`, check `cosign version` against that minimum and fail with an actionable message (`cosign ≥ X required, found Y — upgrade: <link>`); on verification failure, mention the version requirement as a likely cause.
3. State the minimum version in `docs/bex-cli.md` § Install (and the manual-verification snippet), `lego/cli/README.md`, and the public page https://bex.co/docs/cli (source location not found in this repo — locate it).
4. Test: extend the installer's tests (if any) with a stub `cosign` reporting an old version → actionable error, exit nonzero, nothing installed.

## Acceptance

- Installer with cosign below the minimum exits nonzero with a message naming the required version; nothing written to the install dir.
- Docs and bex.co/docs/cli name the minimum cosign version.

## Outcome (2026-11-04, loopx w32)

**Done in this repo:** bisected against v0.3.3's real `checksums.txt.sigstore.json` on linux/arm64 — cosign v2.3.0 and v2.4.0 cannot verify it at all (v2.4.0: `unsupported tlog public key type: PKIX_ED25519`), v2.4.1 only with `--new-bundle-format`, **v2.4.2+ verifies as-is** (2.4.2, 2.4.3, 2.5.0, 2.5.3, 2.6.1, 3.1.4 all `Verified OK`). Minimum = **2.4.2**. `scripts/install-bex.sh` checks `cosign version` before `verify-blob` (`cosign >= 2.4.2 is required …, found X — upgrade: <link>`), and a verify failure names the requirement; `scripts/install-bex.test.sh` covers 2.4.1 (refused, install dir untouched), 2.4.2 (installs) and a failed verify. Live: with real cosign 2.4.1 the installer now exits with the actionable message; with 2.4.2 it installs v0.3.3. `docs/bex-cli.md` § Install + manual-verification snippet and `lego/cli/README.md` name the minimum.
