# A REST or MCP Key Value create or update with a bad `persistenceMode` lists the CRD spellings (`journal-snapshot`) instead of Render's (`journal_snapshot`)

Why: the 400 tells a Render client to send `journal-snapshot`, a value Render's API does not accept.

- **Severity / estimate:** minor, ~20m.
- **Where:** `lego/backend/internal/keyvalue/service.go`.
  - Create (`:674`) and update (`:1206`) both answer `unknown persistenceMode %q (valid: %v)` with `validPersistenceModes`, which is `journal-snapshot snapshot off` (`:221`), the KeyValue CRD's enum.
  - The accepted input goes through `renderToCRD` (`:248`), so the values a caller must send are Render's: `journal_snapshot | snapshot | off`. That is also how the pinned Render CLI spells them.
- **Reach:** found by reading the code. The pinned CLI checks the value before it sends anything, so only REST and MCP callers see this message.
- **Source:** `/qa-find-bugs-cli w32` run, 2026-11-20, pin `98e053468f52`.

## Acceptance

- A REST create, and a PATCH, with a bad `persistenceMode` answers 400 listing `journal_snapshot | snapshot | off`, with a backend test for each.
- The MCP Key Value create/update tools return the same wording.
- `maxmemoryPolicy` (`validMaxmemoryPolicies`, `:212`) is checked the same way and fixed too if its message also shows CRD spellings.

## Shipped

2026-11-19: a create or update whose `persistenceMode` or `maxmemoryPolicy` neither spelling names answers `400 unknown persistenceMode "aof" (valid: journal_snapshot | snapshot | off)`, and `maxmemoryPolicy`'s refusal lists `noeviction | allkeys_lru | … | volatile_ttl`, on REST, MCP `create_key_value` / `update_key_value` and GraphQL alike (`keyvalue.UnknownPersistenceModeError` / `UnknownMaxmemoryPolicyError`). On the composed REST stack the Render schema gate refused the value first with a bare `invalid request body at /persistenceMode`, naming no value at all; `create-key-value` and `update-key-value` (and the `/v1/redis` aliases) now answer the Service's refusal there (`renderOperationRefusals`), and a value that is not a string keeps the gate's pointer. The MCP argument descriptions now spell the values Render's way too. Tests: `TestUnknownKeyValueSettingsListRenderSpellings` (REST create and PATCH, both MCP tools, both GraphQL mutations) and `TestKeyValueEnumsAcceptBothSeparatorsOverREST` (composed gate, create and PATCH); both fail with the fix reverted.
