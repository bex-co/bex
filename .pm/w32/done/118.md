# 118 — A stale `BEX_WORKSPACE` name still blocks direct-ID recovery on `--group`-scoped `sandbox-groups` commands, `bex ssh <instanceID>`, and URL-addressed `bex agent` commands

Why: `w32/117` (`63caa99ea2`) restricted `workspaceUse`'s `bridge.WorkspaceIfResolvable` bypass to direct-ID commands so stale `BEX_WORKSPACE` names never block recovery, but `workspaceUse` (`lego/cli/main.go:409-414`) gates every entry on `typedResourceID.MatchString(pgtrust.DatabaseArg(rest, arity))` (`^[a-z]{3}-[0-9a-z]{20}$`) against the first positional argument. That breaks four families of direct-ID commands that never read `config.WorkspaceID()`: every real `sandbox-groups credentials` verb with `--group sbg-…` (because credential IDs are user-chosen slugs like `inference-key`, not 24-character typed IDs — making all 6 credential cases in `directResourceIDCommand` dead code for real names — and `credentials list --group` has no positional arg), `sandbox-groups images list|import` and hidden `builds create` with `--group sbg-…`, `bex ssh <instanceID>` (`srv-<20>-<suffix>` has a second hyphen suffix), and all 18 direct-session `bex agent` verbs when passed a dashboard session URL (`https://dashboard.bex.co/agents/ags-…`).

- **Expected / actual:**
  - **Expected:** Any command whose API route directly addresses a typed resource without calling `config.WorkspaceID()` / `ownerId` should classify as `bridge.WorkspaceIfResolvable` so a stale `BEX_WORKSPACE` name never blocks recovery (`docs/bex-cli.md:60`, `w8/064`, `w32/117`):
    1. All `--group sbg-…` `sandbox-groups credentials` (`list`, `create`, `get`, `update`, `delete`, `versions`, `restore`) and `sandbox-groups images`/`builds` (`images list`, `images import`, `images get`, `images delete`, `builds create`, `builds get`) commands when `--group` is a valid typed `sbg-` group ID — regardless of whether the positional argument is a user slug (`inference-key`), an OCI reference (`alpine:3.20`), an `sbb-` ID, or absent (`list`).

    3. - **Wire evidence:** Not separately captured at raw HTTP layer because the failure is purely client-side inside `cobra.OnInitialize` (`lego/cli/main.go:87`) right after `GET /v1/owners?name=stale-nonexistent-ws-e7b5&limit=100` returns `[]`; zero resource requests are sent.
- **Runtime evidence:** Disposable sandbox group `sbg-dc39j8ouqmis73a84ong` (`qa-20261125-e7b5-sbg2`) and its credential `inference-key` were created in `bex-canary` to verify an existing credential slug live and deleted afterwards (`bex-canary` baseline `sandbox-groups` count unchanged: `1` before, `1` after).
- **Attribution:** Bex launcher (`lego/cli/main.go`).
- **Root cause:**
  - In `lego/cli/main.go:329-353` (`directResourceIDCommand`) and `lego/cli/main.go:409-414` (`workspaceUse`):
    1. `workspaceUse` checks `typedResourceID.MatchString(pgtrust.DatabaseArg(rest, arity))` (`^[a-z]{3}-[0-9a-z]{20}$`, line `357`) for every command accepted by `directResourceIDCommand`.
    2. For `sandbox-groups credentials {create,get,update,delete,versions,restore}`, `directResourceIDCommand` checks `strings.TrimSpace(stringFlagValue(target, "group")) != ""`, but the first positional argument is `<credentialId>`, a user-chosen slug (e.g. `inference-key`), not `^[a-z]{3}-[0-9a-z]{20}$` (`TestStaleWorkspaceNameBlocksOnlyConsumers` in `lego/cli/main_test.go:1336,1587` masked this by testing a synthetic 24-character `crd-12345678901234567890`). In addition, `sandbox-groups credentials list`, `sandbox-groups images list`, `sandbox-groups images import`, and hidden `sandbox-groups builds create` all call upstream `s.groups.IDOrDefault(ctx, groupID)` (`pkg/sandboxcredential/service.go:43`, `pkg/sandboximage/service.go:29,64`), never reading `config.WorkspaceID()` when `--group` is supplied, yet were omitted from `directResourceIDCommand` because they lack an `sbb-` positional argument.
    3. For `bex ssh`, upstream `cmd/ssh.go:162-165` accepts `validate.IsServiceInstanceID` (`^srv-[a-z0-9]{20}-[a-z0-9]+$`, `pkg/validate/id.go:65-68`) and extracts the service ID directly without calling `config.WorkspaceID()`, but `typedResourceID` rejects the `-<suffix>` tail.
    4. For the 18 direct-session `bex agent` verbs, `lego/cli/internal/agent/agent.go:242-256` (`sessionRef`) accepts both bare `ags-…` IDs and `http(s)://…/agents/ags-…` URLs without reading the active workspace, but `typedResourceID` rejects URLs.
- **Fix:**

     - **Group-addressed sandbox-groups commands** (`sandbox-groups credentials {list,create,get,update,delete,versions,restore}`, `sandbox-groups images {list,import,get,delete}`, `sandbox-groups builds {create,get}`): return `true` when `strings.TrimSpace(stringFlagValue(target, "group"))` matches a typed sandbox-group ID (`sbg-[0-9a-z]{20}`, or `typedResourceID` with `sbg-` prefix). Note: when `--group` is omitted or empty, keep returning `false` (`WorkspaceRequired`), preserving `w32/117`'s fail-fast guard against leaking a stale workspace name into `GET /v1/sandbox-groups?ownerId=`. Also keep `sandboxes snapshots *` returning `false` because `pkg/sandboxsnapshot/repo.go:21,40,59,111` always sends `?ownerId=<config.WorkspaceID()>` even when `--group` is passed.
     - **`ssh`**: accept both `typedResourceID.MatchString(arg)` (`srv-…`) and `validate.IsServiceInstanceID(arg)` (`srv-<20>-<suffix>`).
     - **Direct-session `agent` verbs** (`agent get|logs|files|send|wait|cancel|stop|archive|unarchive|delete|tags|tree|cost|open|pickup|ssh|update|chat`): accept both `typedResourceID.MatchString(arg)` (`ags-…`) and an agent session URL recognized by an exported helper (e.g. `agent.IsSessionRef(arg)` wrapping `sessionRef`, or matching `/agents/ags-[0-9a-z]{20}`), so URL and bare-ID forms behave identically.
