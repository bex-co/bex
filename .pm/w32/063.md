# `bex s3` sends a key with a `..` or `.` segment or a doubled slash and blames the clock or the secret

Why: bex's own client knows the key rules its gateway enforces (ADR112 D7), but it sends such keys anyway. The refusal it then prints tells the user to check the clock and `BEX_S3_SECRET_ACCESS_KEY`, which has nothing to do with the problem.

- Severity: minor. It misleads, but nothing is stored or lost.
- Versions: released `bex` v0.9.0, production pin `f797f525f5df`. HEAD `06e0187d1` has the same code: `internal/s3/location.go` and `client.go` are unchanged since `bex-cli/v0.9.0`.
- Context: cli-qa routine run r23, 2026-11-21 08:28Z, workspace `bex-canary`, human device login.

## Repro

```sh
bex s3 cp a.txt s3://qa-<nonce>-b1/x/../y
bex s3 cp a.txt s3://qa-<nonce>-b1//dbl
```

Each command exits 1 within a second and prints:

```text
Error: the request signature was refused: check that the clock is right, and that BEX_S3_SECRET_ACCESS_KEY, if set, is the key's own secret (SignatureDoesNotMatch: The request signature we calculated does not match the signature you provided. Check your key and signing method. (request …))
```

The same client refuses a bad bucket name locally, with exit 2 and the naming rule (`bex s3 mb s3://Bad_Name`). The Render-shaped route refuses such a key with a clear 400.

## Cause

- `parseLocation` (`lego/cli/internal/s3/location.go:42-54`) checks the bucket name but passes the key through unchecked.
- Traefik cleans `x/../y` to `y`, and `//dbl` to `/dbl`, before `bex-s3gw` sees the request. So the SigV4 signature over the original path no longer matches. `lego/backend/internal/objectstorage/keys.go:30-47` describes this and refuses such keys on every route.
- `explain` (`internal/s3/client.go:226-227`) then turns `SignatureDoesNotMatch` into the clock and secret advice.

## Fix

- In `parseLocation`, or wherever a command reads a remote key or prefix from its arguments, apply `objectstorage.ValidateKey`'s rules. That means a `.` or `..` segment, `//`, a leading `/`, a backslash or a control character, more than 1024 bytes, or invalid UTF-8. Keep a trailing `/` as a prefix. On a match, refuse with a usage error (exit 2) before a key is made or a request is sent. The message names the rule, for example: `"x/../y" is not a key bex object storage serves: no "." or ".." segment, no doubled or leading slash, no backslash or control character`.
- The CLI cannot import `lego/backend` (the import DAG). Copy the rule next to `bucketName` (`internal/s3/tools.go:37-40`), which already copies ADR112 D1's bucket rule this way. Keep one table of cases in `lego/cli/testdata/` that a backend test also reads, as `lego/backend/internal/agentsessions/cli_contract_test.go` reads the CLI's contract files, so the two rules cannot drift.
- A recursive upload of a local tree cannot produce `.`, `..` or `//` (relative paths never hold them). A local file name with a backslash or a control character can, though: report that file as failed, naming the rule, and go on, as one failing file does today.

## Acceptance

- A unit test covers each of the command-line forms above: `cp`, `mv`, `rm`, `ls`, `sync` and `presign` exit 2 with the rule and send no request (the fake S3 counts zero requests). `s3://b/dir/` and `s3://b/a.b/c` still pass.
- Live in `bex-canary`, `bex s3 cp a.txt s3://<owned>/x/../y` exits 2 with the rule, and `bex s3 cp a.txt s3://<owned>/x/y` still uploads. The bucket is removed afterwards.

Dedupe: no `.pm` item covers client-side key checks. w21/m540 t003 lists `cp`'s forms but none with these keys. Unverified: what the gateway answers for a key with a backslash or a control character, which Traefik does not clean.

Estimate: ~40m.
