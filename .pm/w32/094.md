# The mobile app's log viewer shows a coloured line's escape bytes, where the dashboard draws the line coloured

Why: since w32/m576 bex writes Render's ANSI colour codes on every `==>` line Render's captures show (`==> Deploying...`, `==> Your service is live 🎉`, `==> Running '<command>'`, the build's `==> Build successful 🎉`), as Render's log API does. The mobile app's log viewer prints each message as it comes, so on a phone a deploy log reads `[0;34m[1m==> [0m[1mDeploying...[0m`, and a build tool's coloured app line (Vite, npm) already does.

- **Severity / estimate:** minor, ~1h: draw the shown text, and the colours if the viewer can, as the dashboard does.
- **Seen:** w32/m576, 2026-11-22, reading every reader of the coloured lines.
- **Where:** `mobile/src/features/logs/log-viewer.tsx` renders `{item.message}` in a `Text` with no escape handling; nothing under `mobile/src` reads ANSI. The dashboard interprets SGR, swallows `ESC ( B` and every other escape and applies carriage returns in `dashboard/src/features/logs/lib/ansi.ts`; `lego/backend/internal/logs/testdata/display-text-vectors.json` holds the shared cases, Render's seven forms among them, which the dashboard and bex-api's `textMode=display` search both assert.
- **Render reference:** Render's dashboard draws the codes, which is why logs users copy from it read plain; Render has no mobile app, so the dashboard is the reference.
- **Done when:** a log line carrying any of Render's seven forms, or an app line's SGR codes, shows its words in the mobile log viewer with no escape bytes or parameter tails (`[0;34m`, `(B`), ideally the marker coloured and the text bold; the viewer's text search finds it by those words (`textMode=display`); a mobile unit test runs `display-text-vectors.json` through the viewer's renderer.
