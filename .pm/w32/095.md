# The dashboard's log viewer renders URLs in log lines as plain text, where Render's viewer turns them into clickable links

Why: Render parity in the dashboard log viewer (deploy page and service Logs tab). When a web service's deploy log prints `==> Available at your primary URL https://<service>.onbex.co`, Render turns the URL into a clickable link so the user can open the service straight from the log; bex prints it as plain text.

- **Severity / estimate:** minor, ~45m: linkify safe `http://` / `https://` URLs inside `LogMessage` (`dashboard/src/features/logs/components/log-line-list.tsx:1254-1267`), preserving ANSI spans, copy-line text (`logRowsText`), and keyboard navigation.
- **Seen:** w32/m567 t005, 2026-11-23. `LogMessage` renders `spans` as `<span>` elements or returns raw `text` directly (`dashboard/src/features/logs/components/log-line-list.tsx:1254-1267`), with no URL linkification.
- **Render reference (public issue logs):** logs copied from Render's dashboard viewer show the primary URL as a link whose displayed/copied anchor text gains a trailing slash (`lelewithheart/Pixel-Breach#10`, `bookorbit/bookorbit#31`), while Render's API log message itself carries no trailing slash (`kirara-ai#1498`, `mana_meeples#180`, `z0-auth#12`, `SGSDev#1`). The message bex stores and serves on REST, GraphQL, MCP, and the CLI stays without a trailing slash; linkification is viewer-side only.
- **Done when:** `http://` and `https://` URLs in rendered log messages (including inside ANSI-styled spans such as `==> Available at your primary URL https://<slug>.onbex.co`) render as `<a target="_blank" rel="noopener noreferrer">` links in the dashboard log viewer, while non-`http(s)` schemes (`javascript:`, `data:`) stay plain text, raw API/copy-log text keeps no trailing slash, and unit tests in `dashboard/src/features/logs/` cover plain, ANSI-spanned, and unsafe-scheme messages.
