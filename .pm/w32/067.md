# `bex s3 lifecycle set` stores a different prefix than the file names, prints a raw Go time error for a bare date, and reads "after 1 days"

Why: `lifecycle set` is how a user tells bex which objects to delete, so it must store the rule the file says or refuse it; today one character class is silently replaced, and the other two rough edges make a valid-looking document hard to fix.

- Severity: minor. No object was deleted in the walk, but a stored rule differed from its file without a word.
- Versions: released `bex` v0.9.0 (`bex-0.9.0-linux-arm64`, sha256 `cecca711…`), and a checkout build of `721efc2dd` for the date case (`lego/cli/internal/s3/config.go` changed since `bex-cli/v0.9.0` only in `fd970dce7`, the exit-code guard). Upstream pin v2.36.0 `4fd34231b637`; production gitops pin `cce6c749f6ff`.
- Context: cli-qa routine run r4ae7, 2026-11-21 13:15Z, workspace `bex-canary`, human device login, non-TTY `-o text`.

## Repro

On an owned bucket (`bex s3 mb s3://qa-<nonce>-b2 --region frankfurt`; removed afterwards):

1. A control character other than tab, newline or carriage return in a prefix is replaced by U+FFFD and stored:

   ```sh
   printf '%s' '{"Rules":[{"ID":"c","Status":"Enabled","Filter":{"Prefix":"x\u0007/"},"Expiration":{"Days":1}}]}' > ctl.json
   bex s3 lifecycle set qa-<nonce>-b2 --file ctl.json --region frankfurt   # put_lifecycle: … (1 rules), exit 0
   bex s3 lifecycle get qa-<nonce>-b2 -o json --region frankfurt           # "Prefix": "x�/"
   ```

   A tab in the same place is refused by the gateway (`conditions.prefix is not valid`, w32/066). The stored prefix `x�/` matches real keys (U+FFFD is valid in a key), while `x\u0007/` could match none (ADR112 D7 refuses control characters in keys).

2. A bare date fails with Go's layout string:

   ```sh
   printf '%s' '{"Rules":[{"ID":"d","Status":"Enabled","Filter":{"Prefix":"x/"},"Expiration":{"Date":"2027-01-01"}}]}' > date.json
   bex s3 lifecycle set qa-<nonce>-b2 --file date.json
   # Error: date.json: line 1: parsing time "2027-01-01" as "2006-01-02T15:04:05Z07:00": cannot parse "" as "T"   (exit 1, nothing sent)
   ```

3. `bex s3 lifecycle get` prints `after 1 days` for `"Days": 1` and for `"DaysAfterInitiation": 1`.

## Cause

- 1: `parseLifecycle` (`lego/cli/internal/s3/config.go:371`) passes the prefix to the AWS SDK as written, and the SDK's XML encoder replaces characters XML 1.0 cannot carry with U+FFFD. The CLI checks object keys (`location.go`, w32/063) but not a rule's prefix.
- 2: `lifecycleExpiration.Date` is a `*time.Time` (`config.go:75`), so `encoding/json` accepts RFC 3339 only and its error names Go's reference layout. The server stores a bare `YYYY-MM-DD` as midnight UTC (`objectstorage/lifecycle.go`, `LifecycleDeleteCondition`), and the gateway requires midnight (`'Date' must be at midnight GMT.`).
- 3: `config.go:283` and `:288` format `after %d days` without a singular.

## Fix

- 1: refuse a prefix holding any control character, or invalid UTF-8, with a usage error (exit 2) naming the rule's ID and `Filter.Prefix`, before a key is made or a request is sent. Reuse the character part of `checkKey` (`lego/cli/internal/s3/location.go:107`, w32/063). Apply it to the legacy top-level `Prefix` too.
- 2: accept `YYYY-MM-DD` as midnight UTC as well as RFC 3339. Refuse anything else with a sentence that shows the accepted forms (`"Date" must be a date such as 2027-01-01 or 2027-01-01T00:00:00Z`).
- 3: `after 1 day`.

## Acceptance

- Unit tests (fake S3 rig): `ctl.json` exits 2 with the rule and sends no request; a tab or newline prefix likewise; `date.json` sends `Date` 2027-01-01T00:00:00Z; a malformed date exits non-zero with the accepted forms; `get` prints `after 1 day` and `after 7 days`. Each fails on today's code.
- Live with a release that carries it, in `bex-canary`: `ctl.json` is refused and nothing changes (`get -o json`); `date.json` stores and reads back `"Date": "2027-01-01T00:00:00Z"`. Remove the bucket afterwards.

Dedupe: `rg -i 'ufffd|after 1 days|bare date' .pm` finds nothing, and the object-storage items (w21/m416, w21/m540, w32/062-064) cover none of these. Estimate: ~25m.
