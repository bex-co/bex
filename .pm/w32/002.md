# Blueprint validate: unknown service type also reports a spurious `missing property 'ipAllowList'`

Why: a user who mistypes `type:` in `render.yaml` is told to add an `ipAllowList` their web service never needs, which points them at the wrong fix; the documented contract (`docs/render-artifacts/blueprint-validation-errors.md`) promises only the type-enum error.

## Finding (2026-11-04, live, `bex` v0.3.3 against https://api.bex.co/v1/, workspace bex-canary, human OAuth session)

```yaml
services:
  - type: nonsense
    name: qa-x
```

`bex blueprints validate bp.yaml -o json` → exit 1, two problems:

- `services[0]` 2:5 — `at '/services/0': missing property 'ipAllowList'` ← spurious
- `services[0].type` 2:11 — `at '/services/0/type': value must be one of 'web', 'worker', 'pserv', 'cron', 'keyvalue', 'redis'`

Expected (the capture at `docs/render-artifacts/blueprint-validation-errors.md` line 12): only the type-enum problem.

Attribution: server (CLI just posts the file and prints the problem list; REST/GraphQL/MCP share `ValidateBlueprint`).

## Root cause

`lego/backend/internal/apps/blueprint_compiler.go` `selectBlueprintAnyOfCause` (~line 1477): for an unknown `type`, every `blueprintAnyOfDiscriminatorScore` branch returns -1, so `matched` is empty and the pool falls back to **all** anyOf branches. The fewest-leaves tiebreak then picks `redisServer` (type enum + required `ipAllowList`). `blueprintSchemaLeafMessage` rewrites its enum leaf to the union list, but the branch's other leaf (`required ipAllowList`) is still emitted. `blueprint_m102_test.go:176` ("nonsense type lists cron") only asserts the enum message is _contained_, so it doesn't catch the extra problem.

## Fix

- In `appendBlueprintSchemaProblems` / `selectBlueprintAnyOfCause`: when the services[] anyOf has no discriminator match and the instance's `type` is a string outside `blueprintKnownServiceType`, emit exactly one problem at `/services/N/type` with the union message, discarding the chosen branch's other leaves. A missing or non-string `type` keeps the current behavior.
- Test: extend the m102 case to assert the problem list is exactly the one type problem, for both `nonsense` and a typo like `wbe`, plus one keyvalue-branch control (a real `keyvalue` without `ipAllowList` must still report `missing property 'ipAllowList'`).
- Blast radius: the same problem list feeds REST `POST /v1/blueprints/validate`, GraphQL, MCP, and the dashboard Blueprint validate; the fix in the shared compiler covers all of them.
