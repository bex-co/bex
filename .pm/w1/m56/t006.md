## Objective

Move the control-plane bex-db Cluster, ScheduledBackup, recovery examples, and structural validation from in-tree Barman fields to the plugin.

## Context

- deploy/gitops/charts/bex-postgres/cluster.yaml currently declares spec.backup.barmanObjectStore.
- scripts/gitops-validate.sh and ADR031 intentionally guard the old shape; they must migrate with the manifest rather than being simply removed.

## Steps

1. Point bex-db at its ObjectStore plugin configuration and change its ScheduledBackup method.
2. Update bootstrap recovery manifests/runbook commands to the plugin external-cluster contract.
3. Replace structural guards with plugin-aware checks.

## Files

- deploy/gitops/charts/bex-postgres/
- scripts/gitops-validate.sh
- docs/ADR031-platform-data-backup.md
- docs/runbooks/

## Acceptance criteria

- [ ] Rendered bex-db manifests contain the plugin configuration and no in-tree barmanObjectStore field.
- [ ] Scheduled backups target the existing bex-db prefix and retain the current schedule/retention.
- [ ] Recovery documentation and validation agree with the rendered manifests.

## Out of scope

- Rotating S3 credentials or moving the backup bucket.
