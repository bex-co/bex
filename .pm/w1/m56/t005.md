## Objective

Project tenant database backup, scheduled backup, recovery, and external-cluster configuration through the Barman Cloud plugin instead of spec.backup.barmanObjectStore.

## Context

- lego/operator/internal/controller/database*controller.go currently builds in-tree backup and recovery structures from BEX_DB_BACKUP*\* settings.
- The Database CR contract should remain stable unless the plugin requires a typed contract change; operator mechanism owns the projection.

## Steps

1. Replace Cluster backup and externalClusters projections with plugin references and plugin configuration.
2. Change ScheduledBackup method to the plugin method while preserving plan durability, retention, destination, and credentials.
3. Update envtest coverage for enabled, disabled, malformed, suspend, recovery, and deletion paths.

## Acceptance criteria

- [ ] Newly reconciled backed-up tenant Databases use only plugin-based backup and ScheduledBackup configuration.
- [ ] Recovery targets the same repository and supports the existing PITR API semantics.
- [ ] Backup-disabled plans remain byte-equivalent apart from unavoidable CNPG schema changes.
- [ ] Operator tests cover failure and recovery paths.
