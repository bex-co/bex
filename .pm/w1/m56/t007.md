## Objective

Demonstrate that plugin-based backups are restorable before removing the old implementation.

## Context

- A successful Backup object is not enough; the definition of done requires recovery of known rows through fresh restore targets.
- Drill resources must use separate names and namespaces and must not overwrite production clusters.

## Steps

1. Insert identifiable non-secret test rows into a disposable tenant database and the approved bex-db drill source.
2. Trigger fresh base backups, record WAL progress, and recover new clusters at explicit PITR targets.
3. Verify known pre-target rows exist, post-target rows do not, and tear down only drill resources.

## Acceptance criteria

- [ ] Tenant Database plugin backup and PITR restore recover the expected known data.
- [ ] bex-db plugin backup and PITR restore recover schema and expected control-plane rows.
- [ ] Evidence records timestamps, object prefixes, CNPG/plugin versions, and cleanup without credentials.
- [ ] Production source clusters remain healthy throughout.

## Out of scope

- Destructive restore over a production source cluster.
