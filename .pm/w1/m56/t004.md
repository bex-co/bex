## Objective

Install CNPG's supported Barman Cloud plugin and materialize the ObjectStore resources needed by tenant databases and bex-db without exposing credentials.

## Context

- CNPG 1.30 defers removal of in-tree Barman support to 1.31, making the current release the migration window.
- Official migration guidance requires the plugin, ObjectStore resources, Cluster plugin configuration, external cluster updates, and plugin-method ScheduledBackups.
- Existing S3 credentials remain out of band in Kubernetes Secrets.

## Steps

1. Pin and deploy a plugin version compatible with CNPG and the upgraded Kubernetes cluster.
2. Create tenant and bex-db ObjectStore resources that preserve current destination, retention, endpoint, and credential references.
3. Add GitOps validation for plugin readiness, ObjectStore references, and secret-key names without decoding secret data.

## Acceptance criteria

- [ ] The Barman Cloud plugin is declared through GitOps and reports Ready.
- [ ] Tenant and platform ObjectStore resources resolve their existing destinations and credential references.
- [ ] Validation fails on a missing plugin/ObjectStore or mismatched reference without reading secret values.

## Out of scope

- Deleting in-tree backup fields before successful migration and restore drills.
