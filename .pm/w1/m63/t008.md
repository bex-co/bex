## Objective

Make environment groups, service/database/Key Value references, and mutable/generated env values behave identically whether declared at root, under projects/environments, or under `ungrouped`, including creation-time value collection and authorized references to allowed existing workspace resources.

## Context

- `extractSyncFalseVars` and `resolveBlueprintResources` inspect only root lists.
- `CreateBlueprintRequest.EnvVarValues` exists, but the current create flow does not fully connect collected values to all `sync: false` declarations.
- Current reference handling is largely same-file-only; the official behavior/capability registry must decide which reference kinds may bind existing workspace resources.

## Steps

1. Drive env/group/reference discovery from normalized IR, never re-unmarshal the raw manifest.
2. Support environment-scoped env groups and complete root/nested/ungrouped membership semantics.
3. Wire validation-plan prompts and supplied `EnvVarValues` to seed-once storage for every declaration path; retain generated values across sync.
4. Resolve allowed existing-resource references under workspace auth; reject missing, ambiguous, cyclic, or unsupported references before writes.

## Acceptance criteria

- [ ] The same env group/resource/reference fixture behaves identically in root, environment, and ungrouped locations where the Render schema permits it.
- [ ] Every `sync: false` key is prompted once, seeded once, and never overwritten on later sync; generated values are never exposed or reminted.
- [ ] Unknown/ambiguous/cyclic/cross-workspace references fail before mutation with exact paths.
