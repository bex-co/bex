## Objective

Thread Render Blueprint fields that have an existing or small truthful bex mechanism through the IR, plan, and App/store projection: Docker command/context, `renderSubdomainPolicy`, static `headers`/`routes`, `registryCredential`, and `image.creds`.

## Context

- `AppSpec` already models Docker start-command behavior, subdomain policy, routes/headers, and registry credential intent; Blueprint parsing omits or ignores them.
- Registry credentials must resolve by authorized workspace identity and never expose stored auth material.
- `dockerContext` needs an exact build-context mapping; if the current builder cannot preserve Render semantics, ADR049 requires reclassification to unsupported instead of approximation.

## Steps

1. Add each field to the normalized IR and capability handler with type/runtime placement checks.
2. Resolve credential references to the existing `RegistryCredentialID`/pull-secret path without leaking cross-workspace metadata.
3. Thread static rules and subdomain policy through create/sync presence rules.
4. Implement and test exact Docker context/command behavior; reclassify any untruthful mapping as unsupported with evidence.

## Acceptance criteria

- [ ] Supported fields round-trip to the same App/store state as their REST core equivalents and obey omission semantics.
- [ ] Credential lookup is workspace-scoped and no secret enters validation/plan output.
- [ ] Every listed field is either equivalent with behavioral tests or explicitly unsupported; none is accepted and dropped.

## Out of scope

- General private-registry redesign or a second credential store.
