## Objective

Make service planning/apply obey Render's field-specific create and existing-resource rules instead of wholesale-copying zero/default values, including the intentional `buildFilter` reset exception and autoscaling/manual-scaling transitions.

## Context

- `service.go:2192` copies plan, replicas, env, IP rules, source/build fields, domains, static rules, and more on every stack upsert.
- Render documents new-service defaults separately from existing-service omission behavior; omitted `buildFilter` uniquely clears existing filters.
- `scaling` reaches create today but the existing-update path does not consistently own/preserve autoscaling.

## Steps

1. Encode service field policies in the capability registry/planner, not scattered `if zero` checks.
2. Apply Render defaults only for creates; preserve existing values on omission where documented.
3. Treat explicit empty collections/strings according to the schema; implement the omitted-`buildFilter` clear rule.
4. Correct manual count versus autoscaling ownership and preserve undeclared env vars while reconciling declared Blueprint values.
