## Objective

Make the new compiler/plan authoritative for validate, preview, create, manual/Git sync, deploy-from-chat, adapters, dashboard review, and helper workflows; remove raw-manifest re-parsing and the direct YAML-to-CR shell compiler, then correct the public parity documentation from the registry.

## Context

- `scripts/app-apply.sh` independently parses a root-only subset and writes CRs directly.
- `resolveBlueprintResources` and `extractSyncFalseVars` re-unmarshal raw YAML and miss nested/ungrouped/Key Value entries.
- ADR006 and ADR018 contain stale claims, including ignored fields that are already implemented and sync-delete described as a divergence even though Render documents no-delete sync.

## Steps

1. Route all service methods/adapters through compiler results and make apply consume the exact plan.
2. Build Blueprint `resources[]`, env prompts, sync history, and action summaries from normalized IR/plan rather than raw YAML.
3. Convert `scripts/app-apply.sh` to a thin authenticated API caller or retire it with replacement instructions; delete its parser/direct CR writes.
4. Update ADR006, ADR018, examples/readmes, MCP descriptions, and CLI checklist from the capability registry; remove blanket ✅ claims without fixtures.

## Acceptance criteria

- [ ] A guard test proves every Blueprint entrypoint calls the same compiler/version and no path re-unmarshals for semantics.
- [ ] The helper has no YAML parser or direct App/Database/KeyValue write path.
- [ ] Resource inventory/prompts include root, nested, ungrouped, service, Postgres, Key Value, and env-group entries.
- [ ] Public docs match registry-generated/evidenced state and no longer call accepted-and-ignored behavior parity.

## Out of scope

- Creating or forking a first-party CLI; the existing official Render CLI remains the compatibility client.
