## Objective

Once a release that never served settles failed, the operator scales its Deployment to 0 and keeps it there across reconciles and public requests.

## Context

- `lego/operator/internal/controller/release_plan.go:146-190`: `planRelease` parks only when suspended or auto-hibernating; `nextAct` returns `actRoll` for `!f.servedRuntime`, so a never-served App keeps rolling.
- `lego/operator/internal/controller/app_controller.go:2809-2842` (`desiredReplicas`) returns the configured/autoscaled count unless `plan.autoHibernating`.
- `app_controller.go:3344-3376` (`settleFailedRolloutMessage`): the never-served branch sets `PhaseFailed` + Ready=False and changes no replicas.
- Activator `wakeApp` (`lego/operator/cmd/activator/main.go:181-206`) scales a sleeping free web Deployment to 1 on any request; w1/m172 already keeps an unserved release off a parked Deployment — reuse that guard.
- Siblings that handle a previously served release and must not change: w8/m44, w1/m156, w1/m157, w1/m160, w1/m172.

## Steps

1. Add a release fact for a settled failed verdict with no served release and make the plan park on it.
2. Leave the Deployment and its template in place (logs and diagnosis stay readable); only replicas go to 0.
3. A new release (new generation/deploy), restart or resume clears the park.

## Files

- `lego/operator/internal/controller/release_plan.go`
- `lego/operator/internal/controller/app_controller.go`
- `lego/operator/cmd/activator/main.go` (only if the wake needs the guard)

## Acceptance criteria

- [ ] envtest: after the failed verdict, `spec.replicas` reaches 0 and stays 0 across several reconciles and an activator-style last-active bump.
- [ ] A following deploy rolls normally; a restart and a resume each bring the service back up.
- [ ] Existing served-release tests (m44/m156/m157/m160/m172) pass unchanged.

## Out of scope

- A served release that is unrestorable (the `unrestorable()` path) — unchanged here.
