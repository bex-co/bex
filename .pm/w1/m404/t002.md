## Objective

Give the agent client an auth step that keeps the bearer valid for the whole run, coordinated with other `bex` processes that share the same login file.

## Context

- `config.DefaultAPIConfig()` (upstream, exported) reads the on-disk login; `client.NewDefaultClient()` re-reads it and refreshes (with 15-minute tokens it always refreshes, so call it only when needed).
- The 60 s rotation grace covers two processes refreshing the same token at once; a stale in-memory refresh token used later than that revokes the whole chain.

## Steps

1. Replace the static bearer editor in `lego/cli/internal/agent/api.go` with an auth editor guarded by a mutex.
2. Before a request, if the in-memory access token expires within 2 minutes: re-read the on-disk login; if another process already rotated it and it is valid, adopt it; otherwise rebuild through `client.NewDefaultClient()` (which refreshes and persists).
3. On a `401`, do the same once and retry the request once when it is safely repeatable (GETs and the attach-ticket mint); otherwise return the error.
4. Never write the login file from a stale copy: re-read immediately before any write path we own.

## Files

- `lego/cli/internal/agent/api.go`, a new `lego/cli/internal/agent/auth.go`, tests beside them.

## Acceptance criteria

- [ ] Unit tests with a fake token endpoint and a 2-second token: a loop of requests over 10 seconds never sends an expired bearer.
- [ ] A login file rewritten by "another process" mid-run is adopted without a refresh call.
- [ ] A `401` triggers exactly one refresh and one retry.

## Out of scope

- Upstream `render` commands (not bex-native); fork or vendor nothing.
