## Objective

Give every traffic-serving tenant pod a drain window. When the pod is deleted it keeps serving for a few seconds while its endpoint leaves Traefik, then gets `SIGTERM`, then up to `maxShutdownDelaySeconds` before `SIGKILL`. A rollout under constant traffic then returns no `502` (m154 DoD bullet 1).

## Context

- **Projection.** `lego/operator/internal/controller/deployment_projection.go:252-271` sets the three probes, and `:343` sets `TerminationGracePeriodSeconds` from `app.Spec.MaxShutdownDelaySeconds` (`app_controller.go:2484-2490`; nil means Kubernetes' default of 30). No `Lifecycle` is set today.
- **Precedent.** `dashboard/deploy/deployment.yaml:108-116` (`w1/m52`) uses `preStop: exec sleep 10` after measuring "~3s of 502s on every roll". Tenant images may have no shell, so use `corev1.LifecycleHandler{Sleep: &corev1.SleepAction{Seconds: N}}`, available in `k8s.io/api v0.35.0` (`lego/operator/go.mod:17`), with the cluster on v1.34.9.
- **Grace period.** Kubernetes counts `preStop` time inside `terminationGracePeriodSeconds`.
- **Server defaults.** `applyPodSpecServerDefaults` (`deployment_projection.go:348`) writes server defaults last. Make sure the new lifecycle field matches the stored object, so steady-state reconciles stay no-op (no perpetual roll).
- **Live evidence.** m154 README § Evidence 1–2.

## Steps

1. **Add the drain.** Set `container.Lifecycle.PreStop.Sleep` for non-worker, non-disk (`RollingUpdate`) web and private services. Choose `N`, and record the reason in a code comment: long enough for endpoint propagation (1–2 s measured), short enough not to stretch every rollout and scale-in. The dashboard precedent used 10 s.
2. **Widen the grace period.** Set `terminationGracePeriodSeconds = N + (maxShutdownDelaySeconds or 30)`, so the user's value still means "time after SIGTERM".
3. **Keep reconciles quiet.** Confirm that adding the field to existing Apps rolls each pod once and then stays stable; do not bump it on every reconcile.
4. **Probe live.** Run m154 DoD bullet 1 on a throwaway service and paste the transcript (samples, non-200 count, deploy timeline) into the m154 README.
