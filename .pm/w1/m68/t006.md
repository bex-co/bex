## Objective

## Context

Verified 2026-08-10:

- `scripts/lib/ssh-hostkey.sh:32-38` — with `BEX_SSH_KNOWN_HOSTS_FILE` unset, the helper selects `StrictHostKeyChecking=accept-new` and announces it on stderr. Set ⇒ fails closed; set-but-empty ⇒ hard error. The helper is correct; this task is about its callers and its input.
- `.github/workflows/deploy.yml:477-493` and `.github/workflows/app-cluster.yml:63` materialize the `BEX_SSH_KNOWN_HOSTS` secret to a file and export `BEX_SSH_KNOWN_HOSTS_FILE` when it is non-empty.
- **`.github/workflows/openbao-restore-drill.yml:35-44` does not.** It calls `scripts/fetch-app-kubeconfig.sh` with only `HCLOUD_TOKEN` and `BEX_SSH_PRIVATE_KEY` in scope — and the very next step hands the resulting kubeconfig `BAO_UNSEAL_KEY_1..3`, `BAO_ROOT_TOKEN`, and the four `TF_STATE_*` credentials. Of the three workflows that fetch `admin.conf`, the one that was skipped is the one whose blast radius is unseal material.
- `BEX_SSH_KNOWN_HOSTS` is empty/absent in `.env` and no such GitHub Actions secret is listed, so `deploy.yml` and `app-cluster.yml` also still take the TOFU branch today. The capture procedure is in `docs/ADR019-infra-credentials.md:65`.

## Steps

1. Add the same known-hosts materialization block to `openbao-restore-drill.yml`'s "Fetch production kubeconfig" step, matching `deploy.yml`'s shape exactly (secret funneled through `env:`, not interpolated into the script body — the repo's standing injection-safety convention).
2. Grep for any other caller of `fetch-app-kubeconfig.sh` / `verify-substrate.sh` in workflows or scripts and confirm the set is now complete; the fix is only worth as much as its coverage.
3. Capture the control-plane host keys out of band (`ssh-keyscan`, fingerprint verified against the console/another path — not against the same SSH connection being authenticated), and store them as `BEX_SSH_KNOWN_HOSTS` in `.env` + GitHub Actions via `scripts/gh-secrets.sh`. **Never print the value into the transcript or a log.**
4. Prove activation: a run with the secret present must use `StrictHostKeyChecking=yes`, and a deliberately wrong pin must abort **before** `admin.conf` is read.
5. Record in `docs/ADR019-infra-credentials.md` that all three workflows are now wired and that the pin must be re-captured on control-plane host-key rotation (the immutable-template rotation in ADR053 changes these keys).
