## Objective

Let the dashboard build a Postgres's internal URL without reading its connection string, which is an audited secret view.

## Context

- The internal host is `<id>-rw.<namespace>.svc` (`lego/operator/internal/controller/database_controller.go:1315`). The pool and read replicas have their own hosts (`:2201-2223`).
- The Postgres GraphQL type already carries the non-secret `externalHost` (`lego/backend/internal/postgres/graphql.go:68-87`), and read replicas theirs (`:106`). The dashboard must not copy the operator's naming.
- Key Value needs nothing new: its internal host is its id, and `internalAuth` is already on its type.

## Steps

1. Add non-secret internal host fields for the primary, the pool and each read replica to the Postgres GraphQL type, built from the same code the operator names them with.
2. Test them.

## Files

- `lego/backend/internal/postgres/graphql.go`, the service that builds the hosts, and their tests

## Acceptance criteria

- [ ] A test reads each internal host through GraphQL with a member's read permission and no secret view.
