## Objective

Prove the fix works end to end: force the cluster-autoscaler to mint a brand-new tenant node and confirm a git-built image pulls successfully with zero hand-applied configuration — the actual failure mode the incident exposed.

## Context

- This is the live-verification bar other milestones hold themselves to (e.g. `w1/m19.1`'s prod pivot verification, `w1/m3`'s live-proven elastic behaviors).
- Forcing a fresh node: scale demand up past the current tenant pool's capacity (deploy enough load, or temporarily lower the bin-pack threshold) so the autoscaler provisions a new node from the updated CAPH template.

## Steps

1. Trigger the autoscaler to provision a new tenant node.
2. As soon as it joins, trigger a build-from-git deploy that schedules onto it.
3. Confirm the image pulls without `ImagePullBackOff` and with no manual `/etc/hosts`/containerd intervention.
4. Confirm the Cilium policy (t002) is in effect (check Argo CD sync status shows it, not drifted).

## Files

- none (verification only)

## Acceptance criteria

- [ ] A freshly minted node pulls a git-built image successfully on first attempt.
- [ ] No manual steps were taken on the new node.

## Out of scope

- Load-testing the autoscaler itself — that's covered by `w1/m3`/`w1/m20`.
