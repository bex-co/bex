## Objective

Render counts "WebSocket messages from existing connections" as inbound traffic. A free web service holding a WebSocket that exchanges messages must not hibernate, even when it serves no new HTTP requests.

## Context

- An upgrade request is counted once by Traefik's request counter; later frames are not.
- `deploy/gitops/charts/traefik-plugins/websocketegress/websocketegress.go` keeps an exact per-App counter of server→client frames, exposed on `:9101` (`metricsAddr`) and attached per App by `reconcileWebsocketMeterMiddleware` (`app_controller.go:2835-2850`).
- It was not verified this run whether Prometheus scrapes that endpoint (m151 README § Unverified).

## Steps

1. **Check the scrape.** Confirm whether Prometheus scrapes the plugin's `:9101` counter in production (`deploy/gitops/base/prometheus.yaml`), and add it if not.
2. **Extend the reader.** t001's `ActivityReader` also treats a change in that counter since `last-active` as activity. Record whether client→server frames are counted; if they are not, record the divergence.
3. **Probe live.** Keep a WebSocket open to a throwaway free service (e.g. a small echo app), send a message every 30 s with no new HTTP requests for 20 minutes, and confirm no `service_hibernated`.

## Acceptance criteria

- [ ] The live WebSocket probe transcript is in the m151 README.
- [ ] Any client→server frame gap is recorded as a divergence in t004.
