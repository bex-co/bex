## Findings (2026-09-14, three review passes: reuse, quality, efficiency)

**Applied**

- `useFieldMutation` now goes through `mutationErrorMessage` too, so throttling is handled the same way everywhere. `serverRefusalReason` had no callers left, so it was folded into `mutationErrorMessage` and deleted.
- Stale comments fixed: `useFieldMutation`'s fallback doc, the `isThrottledError` wording ("request", not "read"), `useCreateWebhook`'s "only transport failures toast" comment, and `useDisks`'s `addError` doc.
- `useCreateWebhook` and `useUpdateWebhook` used to set a raw inline error but a stripped toast. Both now compute one `mutationErrorMessage` and use it for the inline error and the toast.
- `cron_schedule_surfaces_test.go` reuses the package helpers `mustSchema` and `serveRESTPatch`. It is now one surface table with a single assertion, so every refusal must carry the same sentence. `TestSetCronJobRejectsInvalidSchedule` loops over the shared table's invalid vectors instead of its own copy of the list.
- The invariant test reads each file once (`readdirSync(..., { recursive: true })`) and its repeated allowlist reasons are now named constants. The 34 imports the codemod appended after type or relative imports were moved next to the other `@/common` imports.
- Two test comments that described history now state the rule.

**Declined**

- `useRenameDatabase` and `useRenameKeyValue` branch on the message text "already exists" and "name must". That predates m145 and keeps localized dedicated copy. Moving it onto `isNameConflictError` first needs the backend rename conflict to carry `CONFLICT`, which is out of scope.
- Skipping generated and locale files in the invariant scan would save a few ms, but a wider scan is the safer invariant.
- Removing the repeated `isValidCron` parse per render costs microseconds on a string under 30 characters, and the fix would couple the callers.
- `use-disks.ts` prettier churn: `HEAD` was not prettier-formatted, and touched files are formatted with the repo's formatter.
- Outside the diff: `use-update-database-version.ts` and `workspaces/hooks/*` set inline (non-toast) errors from `graphQLErrorMessage(err) ?? t(…)`, so a transport failure shows "Failed to fetch". The guard does not cover inline errors. This is a candidate follow-up, not part of m145.
