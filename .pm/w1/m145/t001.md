## Objective

The dashboard's `isValidCron` must accept exactly the set bex-api's `validCronSchedule` accepts. bex-api's answer is the correct one because it is the Kubernetes CronJob parser, and `service.go:3702-3711` records the load-bearing guarantee "if bex accepts it, the CronJob accepts it". Do not widen the server to accept `7`.

## Context

- `dashboard/src/features/services/lib/cron.ts:47`: day-of-week `{ min: 0, max: 7 }`. The comment at `:41-42` ("0 and 7 both Sunday, matching cron") is the wrong premise, since robfig is not Vixie cron.
- `lego/backend/internal/apps/service.go:3712-3718`: 5-field count, then `cron.ParseStandard`.
- `robfig/cron/v3@v3.0.1`: `spec.go:40` sets day-of-week to `{0, 6}`, and `parser.go:262` treats `?` as `*`.
- Tests pinning the drift: `dashboard/src/features/services/lib/__tests__/cron.test.ts:17` (`"0 0 * * 7"` valid) and `:94` (`SUN` == `7`).
- Live evidence: m145 README § Evidence 1 and 3.

## Steps

1. Build one table of schedule vectors (valid and invalid). It must include `0 0 * * 7`, `0 0 * * 0-7`, `0 0 * * 1,7`, `0 0 ? * *`, `0 0 * * ?`, `99 99 * * *`, `@daily`, `*/0 * * * *`, `0 0 * * SUN-SAT` and `0 0 * * sat-sun`. Store it as JSON in one place, and read it from a backend test (asserting `validCronSchedule`) and from `cron.test.ts` (asserting `isValidCron`), so the two sides cannot drift silently again.
2. Set the day-of-week max to 6 and accept `?` wherever robfig does. Make the backend test's results the source of truth, not the list above.
3. Fix `describeCron` for `?` (describe it as `*`) and delete the `SUN == 7` assertion. Correct the header comment.
4. Confirm the create form (`routes/services.new.tsx:81-86`), `create-service-input.ts:135` and `cron-deploy-section.tsx:79` all pick the change up without edits.

## Acceptance criteria

- [ ] Both suites read the same vector file, and flipping one expectation fails both.
- [ ] New Service → Cron Job with `0 0 * * 7` shows the inline error and disables Deploy Service (live, `dev-1` or production).
- [ ] Settings → Edit schedule → `0 0 * * 7` disables Save changes.
- [ ] `0 0 ? * *` is accepted by both sides, or refused by both, matching whatever the backend test proves.

## Out of scope
