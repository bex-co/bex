## Enumeration and classification (2026-09-14)

The enumeration was a string- and comment-aware scan of every `catch` block under `dashboard/src` whose body calls `toast.error`, not the README's `-A3` grep. It found **119 blocks**. The scan is now permanent as `src/common/lib/__tests__/mutation-error-toast-invariant.test.ts`.

- **Migrated to `mutationErrorMessage(err, t(generic))`: 92 toasts.** 79 of them went through a codemod across 64 files: api-keys, blueprints (create/update/sync/disconnect/generate), connected-agents, databases (HA failover, access users/pooler, lifecycle, delete, export, rename, plan, disk autoscaling), deploy cancel/rollback, env groups (8), environments (7), git (3), keyvalue (6), notifications (2), projects (4), registry credentials (3), service environment editor save, and services hooks (auto-deploy, autoscaling ×2, cron run cancel, custom domains ×2, delete, deploy hook, display name, env vars ×2, maintenance, registry credential, scale, secret files ×2, lifecycle, static site ×3, trigger deploy, plan), ssh key delete, team revoke/resend, and webhooks create/update. 13 were edited by hand: `useCreateService`, `useCronJob`, and the 4 `conflictOrGenericMessage` create hooks (the helper is deleted; `mutationErrorMessage` covers the conflict case too). `useChangeRole`, `useRemoveMember` and `useSSHKeys.create` keep their dedicated last-admin or duplicate copy. The webhook delete/resend/toggle hooks keep their `WEBHOOK_*` key mapping, and `useDisks` shares one message with its inline error.
- **Allowlisted with a reason: 19**, in the invariant test's `ALLOWED`. These are Kratos calls (logout, session revoke ×2), the clipboard, reads (env export ×2, secret reveal, cron run history), dedicated-code branch copy (blueprint busy/source-changed ×3, rename conflict/invalid ×4), the invite toast that fires only when no reason exists, billing checkout and portal (an operator-side Stripe gap, logged), and `useDisks`'s derived message.
- **Already relaying the error: the rest.** Agent sessions, env-group toasts with a `description`, `error`-interpolated keys, and the webhook inline refusals.
- **Throttling** (`RATE_LIMITED`/`AUTH_OVERLOADED`) stays generic inside the helper. **An expired session** is a transport `ServerError` 401, so it never reaches the server-reason branch and the auth link's redirect is unchanged.
- **Guard proof:** the test's planted cases fail on `catch { toast.error(t("…")) }`, on a block that reads `err` elsewhere but toasts generic copy, and on a binding named `error`. The fix shape passes. With `cron.ts`, `use-cron-job.ts` and `use-create-service.ts` reverted to `HEAD`, the suite goes red (20 failures across the 4 new or changed test files).
