# Render's env var editor now links a service, database or Key Value: DO_NOT_DO's Link-database line rests on a premise Render no longer holds

Why: `.pm/DO_NOT_DO.md` forbids a "Link database to service" picker because "Render has no such dashboard feature" (verified 2026-07-08), but Render's dashboard bundle now has one, so under the parity-first rule the line needs the user's decision again.

- **Found:** w1/m645's dashboard ledger (2026-11-26), row `servicesForOwnerToLinkSearch` in [dashboard-operations.md](../../docs/render-artifacts/dashboard-operations.md#environment-variables-secret-files-and-environment-groups).
- **Render (bundle, `VariablesActionButtons` chunk, no flag):** the env var editor queries every service, database (replicas included) and Key Value in the workspace with its region and environment, sorts them (same environment first), and offers each as a linked value: "Same region (internal URL)" or "Cross-region (external URL)", with `DATABASE_URL` and `REDIS_URL` as default keys. Not on Render's changelog as of 2026-11-26.
- **The rule it meets:** `.pm/DO_NOT_DO.md` "Do not build a 'Link database to service' picker in the dashboard … Render has no such dashboard feature" (withdrawn from `/pm-brainstorm for w5`, 2026-07-08). Its stated reason no longer holds; the first anti-goal says not to keep a parity gap because an older decision chose otherwise.
- **Needs the user:** lift the DO_NOT_DO line and build Render's picker, or keep the line with a new reason and record a signed-off divergence in ADR018 § Environment & config.
- **Done when:** the decision is recorded (a filed milestone, or the amended DO_NOT_DO line plus an ADR018 divergence), and the ledger row points at it.
