## Objective

When `buildFromSource` halts for a release while a prior release serves, keep that prior release's replicas and public routing following the App: sleep, wake, suspend, resume, manual scale, autoscale and maintenance. This applies to a web or private service with `status.activeRevision` set and its Deployment and Service present. Never write the pending release onto the pod template, and keep both the build's own polling and its durable verdict.

## Context

- **Halt sites.** m157 README § Root cause.
- **Reuse from `w1/m156`.** `convergeServingRuntime`, `ingressRoutes`, `settlePriorRelease`, and the serving-prior checks in `holdUnpassedRelease` (`app_controller.go:4587-4688`).
- **Review constraints.** m157 README § Design constraints.

## Steps

1. Extract the replica prelude that `reconcileKubernetes` runs before its gates (`desiredReplicas`, `holdHibernateForRouting`, `reconcileDiskLifecycle`), so both paths share it.
2. Extract the serving-prior lookup (Deployment, Service, serving port) shared with `holdUnpassedRelease`.
3. From `resolveDeployImage`, hand a build halt that carries no error to the new hold. Hold only web and private services in Kubernetes mode with a prior release, and never when the recorded verdict is a legacy Ready-only marker.
4. **Terminal failure.** Converge, then park (Hibernated) or settle Running from the scale this pass wrote.
5. **Build in flight.** Converge replicas and routing, keep the Building or BuildQueued phase, and requeue at the soonest of the build's own poll, the routing grace and the wake-ready poll.
6. Leave a first release, workers, cron jobs, static sites, and an App without a Deployment or Service on today's path.

## Acceptance criteria

- [ ] Resume, idle sleep, wake and manual scale over a recorded build failure converge the prior release's replicas and route. Its template, `status.image` and Build condition are unchanged, and no build Job is created.
- [ ] A parked service with a build in flight keeps a positive requeue no later than the build's poll, and keeps its Building phase. A wake during the build scales the prior release up.
- [ ] A disk restore in progress is never scaled up by the hold.
- [ ] A legacy Ready-only build-failure marker stays on today's path and is not erased.
- [ ] `make test` (from `lego/operator/`) passes, and `make lint` reports nothing beyond the two findings already on main.
