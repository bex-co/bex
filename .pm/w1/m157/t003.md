## Objective

Run the m157 definition of done on production after the fix deploys, with controls.

## Context

- **Fixtures.** Throwaway free web services from `examples/hello-go` (docker, `dockerContext: examples/hello-go`), named `qa-<yyyymmdd>-…` in the QA workspace.
- **Failing a build.** A PATCH of only `serviceDetails.envSpecificDetails.dockerfilePath` to a missing file opens a `build_failed` deploy while the first release keeps serving.
- **Idle sleep.** Outside scanner requests reach new `*.onbex.co` hosts and reset the idle clock. Prefer suspend and resume for the deterministic check, and record scanner traffic from the request logs when the idle check runs long.

## Steps

1. **Resume over a failed build.** Fail the build, suspend, resume, and sample the URL every second for 180 s.
2. **Idle sleep and wake over a failed build.** Leave a fixture idle until `service_hibernated`, then sample every second.
3. **Wake while a build runs.** With a fixture asleep, trigger a clean deploy and request the URL while the deploy reads building. Record the first `200`, then the deploy reaching `live`.
4. **Controls.** A healthy fixture resumes, and a successful deploy rolls out.
5. **Record and clean up.** Record every transcript in the m157 README, then delete every fixture (`DELETE` → `204`, `GET` → `404`).
