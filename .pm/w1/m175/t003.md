## Objective

On apply, the source's value is generated once and the consumer's env receives the same value in the same apply; when the source already exists, the copy is read from the env store on the server and never returned to the caller.

## Context

- Seed-once semantics for `generateValue`/`sync: false` in the mutable env store (`deploy.go` ~97-178, ~988).
- Secrets live in OpenBao (ADR013); revision-aware env writes (ADR013 w11/m8).

## Steps

1. Order the apply so the source's generated value exists before the consumer's env is seeded; handle consumer-before-source declaration order.
2. Seed the consumer once with the copied value; on a later sync follow t001's recorded semantics.
3. For an existing source, read its stored value server-side for the copy.
4. Make a partial failure leave no consumer holding a value different from its source.

## Files

- `lego/backend/internal/apps/deploy.go`
- env seeding helpers it calls

## Acceptance criteria

- [ ] Real-Postgres/backend test: both services hold identical values after the first apply; a second apply changes neither.
- [ ] No API response, plan or log line contains the value.
- [ ] A failure between the two writes is retried or rolled back without a mismatch (test).

## Out of scope

- Rotating generated values.
