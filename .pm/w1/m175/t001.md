## Objective

Know exactly what Render does before implementing: when the copy happens, what a later sync does, and whether declaration order matters.

## Context

- Render docs (`render.com/docs/blueprint-spec`), the pinned `render.yaml.json` schema, the three render-examples manifests, and any captured behavior under `docs/render-artifacts/`.
- `.pm/w1/README.md` Render decision rule: if unsure, keep parity with Render.

## Steps

1. Collect Render's documented statements on `fromService.envVarKey` and `generateValue` (copy timing, re-sync, rotation).
2. Where docs are silent, record the gap and the parity-preserving default (the copy is taken when the source value is first generated and is not rotated by later syncs, unless evidence says otherwise).
3. Add the result to `docs/ADR049-render-yaml-parity.md`.
