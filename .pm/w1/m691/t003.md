## Objective

The selected instance lives in the path as on Render, so Render's deep links and a copied URL open the same instance.

## Context

- The route today is `dashboard/src/routes/services.$serviceId.shell.tsx`, whose `validateSearch` takes `?instance=` (w3/m528).
- Render's `/web/srv-…/shell/{suffix}` goes through `redirectRenderAlias` (`dashboard/src/common/lib/render-alias.ts`) to `/services/srv-…/shell/{suffix}`, which has no route.
- `serviceInstanceShellHref` (`dashboard/src/features/logs/lib/log-search.ts:186`) builds the Logs and Metrics SSH into instance links (`services.$serviceId.logs.tsx:161`, `application-metrics-card.tsx:211`).

## Steps

1. Add `/services/$serviceId/shell/$instance`. `$instance` is the suffix; resolve it to `${serviceId}-${suffix}`, and accept a complete id too.
2. As the selection changes, replace the URL with `/shell/{suffix}` when more than one instance runs, or with bare `/shell` when one runs.
3. Point `serviceInstanceShellHref` at the path form. Keep `?instance=` working as a redirect, so links already sent still open.
4. Make both the new route and the old one use the Shell's pending frame.

## Files

- `dashboard/src/routes/services.$serviceId.shell*.tsx`
- `dashboard/src/features/logs/lib/log-search.ts`
- `dashboard/src/common/lib/render-alias.ts`, if it needs a test case

## Acceptance criteria

- [ ] `/web/srv-…/shell/{suffix}`, `/services/srv-…/shell/{suffix}` and `?instance=srv-…-{suffix}` all open that instance.
- [ ] The URL follows the picker as described above.
