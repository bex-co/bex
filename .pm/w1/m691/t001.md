## Objective

Write the reference this milestone builds to: how Render's Shell chooses, shows and remembers its instance.

## Context

- Use Render's public dashboard bundle (`bash scripts/render-dashboard-ops.sh list`, or the `crawl()` in `scripts/lib/render_dashboard_ops.py`). The chunks are `ServiceShellStarter`, `server-instances`, `urls` (the suffix helper) and `useSSHAddress`.
- Its rules, read 2026-11-26:
  - The picker lists the instances whose status is running.
  - It selects the URL's instance (`${serviceId}-${suffix}`) when that instance is listed, else the first.
  - With more than one instance, it writes `/shell/{suffix}` with replace. With one, it writes bare `/shell` and shows a read-only picker with the tooltip "This service only has one instance. If it scales up, you can SSH into different instances.".
  - It refetches the list when the picker opens, and again on a 30 s cooldown.
  - It reports an instance as not available when the URL's instance is not running at load, or when `startShell` answers `instance not found`. It then toasts "**{instance} is not available.** Now connected to {instance}." (info, no auto-dismiss).
  - The page's `ssh` command names the URL's instance.

## Steps

1. Re-read the chunks, and record each rule above with its strings in a new `docs/render-artifacts/shell-page.md` (§ Instances). Correct anything that has changed.
2. Link the file from `docs/AGENTS.md`'s artifact list.
