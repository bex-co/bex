## Objective

The Web Shell's picker chooses an instance as Render's does, and never leaves the choice to the gateway.

## Context

- `dashboard/src/features/services/components/web-shell-panel.tsx`:
  - `ANY_INSTANCE` (`:18`), the initial state (`:49`), the fallback when the selection is gone (`:66-71`) and the "Any ready instance" item (`:92-94`).
  - `instanceLabel` (`:153`) already renders Render's "Instance {suffix}".
- `useServiceInstances` lists the instances. Since w1/m661, GraphQL `serviceInstances` also answers each instance's `status`.
- The gateway still accepts a bare service target. Native SSH keeps it: Render's `ssh srv-…@` picks a random instance too ([ADR035](../../../docs/ADR035-ssh.md) step 5).

## Steps

1. Remove "Any ready instance". Select the requested instance when it is running, else the first running instance, in the order `serviceInstances` answers.
2. With one running instance, show the picker read-only with Render's tooltip. With none, keep the terminal waiting as it does now.
3. Refetch the instance list when the picker opens.
4. Add the strings in all eight locales (`dashboard/src/features/services/locales/`).

## Files

- `dashboard/src/features/services/components/web-shell-panel.tsx`
- `dashboard/src/features/services/locales/*.ts`

## Acceptance criteria

- [ ] The Shell never offers "Any ready instance". It opens on the requested running instance or on the first one, and a single instance shows the read-only picker with the tooltip.
