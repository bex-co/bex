# 105 — An autoscaled background worker stops autoscaling after its first scale event

Why: a background worker with autoscaling scales once and then never again. Its scaling transition is recorded as Started but is never marked Ended, so the operator stops reading metrics for it and bex-api never receives the Ended fact.

- **Severity:** moderate. Autoscaling is a paid feature, and every autoscaled worker is affected after its first scale.
- **Found:** `w1/m158` t005 (simplify review), 2026-09-15, traced from the code. Not probed live.

## Where

- **Where a transition ends.** `lego/operator/internal/controller/autoscale.go`: `completeAutoscalingTransition` is the only place a Started transition becomes Ended, once the Deployment reaches `ToReplicas` with that many ready.
- **The gate that freezes.** `applyAutoscaling` returns the recorded `ToReplicas` without reading metrics for as long as a transition is Started.
- **Who calls it.** `completeAutoscalingTransition` has two callers:
  - the web and private rollout path (`reportKubernetesRunning`);
  - the held-release path (`convergeServingRuntime`, `w1/m156`–`w1/m158`).
- **What the worker path does.** `reconcileWorkerStatus` never calls it. A worker's transition therefore ends only while a newer release happens to be held.

## Fix

- **Code.** In `reconcileWorkerStatus`, after it re-reads the Deployment, call `completeAutoscalingTransition(app, dep.Status.Replicas, dep.Status.ReadyReplicas, time.Now())`.
- **Test.** An autoscaled worker whose Deployment reaches the transition's target reads Ended, and the next pass reads metrics again. `app_reconcile_phases_test.go` covers worker autoscaling only with no metrics reader.
