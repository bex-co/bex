# Organization pages: audit log API keys, and each member's login status

Why: Render's organization Settings page mints audit log API keys, and its Members page shows each member's login methods and 2FA; bex's organizations (ADR115) have neither, found by the w1/m645 dashboard ledger.

- **Found:** w1/m645's dashboard ledger (2026-11-26). Rows `organizationAPITokens`, `provisionOrganizationAuditLogToken`, `revokeOrganizationAPIToken` and `orgUserAuthStatus` in [dashboard-operations.md](../../docs/render-artifacts/dashboard-operations.md#workspaces-members-and-organizations).
- **Render (bundle, no flag):**
  - Org Settings → **Audit Logs** ("Render logs material actions taken by members of your organization.") lists the org's API keys with **Create API key** and **Revoke API key**; `provisionOrganizationAuditLogToken(organizationId, label)` returns the token once; too many keys answer "You have created too many keys. Please try again later." render.com/docs/api-keys: "Org Owners can create an audit log API key".
  - Org Members has a **Login & Authentication Status** column from `orgUserAuthStatus(userID, orgID) { loginMethodStatuses { method signedIn } is2FAEnabled }`, with "Not signed in" for a method the member has not used.
- **bex:** the org audit log is served (`GET /v1/organizations/{orgId}/audit-logs`, GraphQL `organizationAuditLogs`, w7/m464) to an Owner's own key; there is no org-scoped key. Org-enforced 2FA and Google login exist (w7/m466) with an impact preview, but the Members page shows no per-member status.
- **Done when:** an Org Owner can create, list and revoke an audit-log-only org key that reads the org log and nothing else, and the org Members page shows each member's login methods and 2FA as Render's does; both on GraphQL (and REST where Render has it), with tests. Or the user signs off a divergence in ADR018. Likely more than an hour: promote to a milestone.
