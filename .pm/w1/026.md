# w1/026 — m33 simplify-pass residuals (four altitude/efficiency follow-ups)

Filed by w1/m33/t009's `/simplify` pass, 2026-07-16. Each was judged real but out
of the milestone's diff scope (touches untouched packages or is a wire-format
decision); none blocks m33.

1. **Dead `core.Base.AuthorizeTarget` + a four-way entry-point family.**
   `AuthorizeTarget` (base.go) has zero production callers since w6/m17 moved
   resource verbs onto `AuthorizeApp`/`AuthorizeDatabase`/`AuthorizeKeyValue`;
   m33 added `AuthorizeOnTarget` as the fourth sibling. Cleaner collapse: delete
   `AuthorizeTarget`, or fold `target` into `AuthorizeOn`'s signature (~20
   mechanical call sites; same frame depth, so `verbFrameSkip` permits it).
2. **Generic `targetName` in REST audit metadata instead of the per-kind
   `email` branch.** `renderMetadata` (internal/audit/rest.go) special-cases
   `kind == "invite"` to surface `TargetName` as `md["email"]`, while
   Postgres/KeyValue events' `TargetName` never reaches REST metadata and
   GraphQL already renders `targetName` generically for every kind. One general
   rule (`md["targetName"] = e.TargetName` for all kinds) is the right
   altitude — a wire-format choice, so decide deliberately, not inline.
3. **Hoist one `IdentityAttrs` + identity-lookup interface into a leaf
   package.** Three per-feature seams now exist (`workspaces.IdentityReader`,
   `members.IdentityLookup`, `notifications.EmailLookup`) with near-copy attr
   structs, laundered across packages by `identityEmailLookup` in
   internal/api/server.go. Rule of three is met: move the contract to `core`
   (or a new leaf `internal/identity`) so `workspaces.KratosIdentities`
   satisfies it directly and the adapter disappears.
4. **Aggregate bound on login-path audit recording.** `tenancy.acceptInvites`
   records one `members.AcceptInvite` row per redeemed invite, each bounded at
   `auditRecordTimeout` (2s) but sequential — K invites × 2s worst case on a
   degraded sink, mirroring the adjacent granter loop's shape. Share one
   deadline context across the loop (and consider the same for the granter
   loop while there).
