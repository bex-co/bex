## Objective

`make lint` completes its dead-code step on every CI run on the existing self-hosted runners.

## Context

- `lego/operator/Makefile:105-114`: one `deadcode -tags=e2e -test` run over `./backend/... ./operator/... ./cli/...` after four golangci passes; `.github/workflows/go-lint.yml`.
- Runners: `[self-hosted, Linux, ARM64]`, all on one Mac (`DO_NOT_DO.md` `#CI-RUNNERS`, `#RUNNER-HOSTS`).

## Steps

1. Measure peak memory of the deadcode step locally.
2. Reduce it without losing whole-program reachability across modules (e.g. `GOMEMLIMIT`/`GOGC`, running golangci passes and deadcode sequentially with memory released, or the job's container memory limit), and keep the `-filter` semantics.
3. Make an OOM kill fail loudly with its cause rather than a bare `Error 137`.

## Files

- `lego/operator/Makefile`
- `.github/workflows/go-lint.yml`

## Acceptance criteria

- [x] Five consecutive CI `go lint` runs finish the dead-code step.
- [x] A seeded dead function is still reported (spot check).

## Out of scope

- Moving to GitHub-hosted or new runner hosts.

## Outcome

Done 2026-10-15. Measured: the single analysis peaks at 8.0 GB RSS. `lego/operator/hack/deadcode.sh` runs backend, operator and cli separately (exact: cli imports no lego module and none imports it; backend and operator never import each other) and keeps only the types findings both backend and operator report, under `GOMEMLIMIT=3GiB`: peak 3.74 GB, 128s. Seeded dead functions (backend, cli root package, unused types, types used only by operator) give output identical to the old single run. A killed analysis now names its signal.
