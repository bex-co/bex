# Re-pin Debian/Ubuntu base images once libbrotli1 fixes land upstream

Why: the native and buildpack runtime images still ship the vulnerable system `libbrotli1` (CVE-2026-111497); Node and Bun bundle their own Brotli, but anything else decompressing through the system library stays exposed.

Filed 2026-10-24.

- Debian fixed bookworm `1.0.9-2+deb12u1` (DLA-4855-1) and trixie `1.1.0-2+deb13u1` (DSA-6582-1), but Docker official images (`node`/`python`/`ruby`/`golang`/`rust`/`elixir` `*-bookworm` in `lego/operator/internal/build/native.go`, `toolchain-freshness.json`) still ship `libbrotli1 1.0.9-2+b6` as of 2026-10-24.
- Ubuntu jammy (Paketo build/run stacks: `deploy/cnb-run/Dockerfile`, `cnb-stack-run`/`cnb-stack-build`) is "needs evaluation" with no USN yet.
- Re-pin when upstream rebuilds, or add an `--only-upgrade libbrotli1` layer as `deploy/opensandbox/server.Dockerfile` does for its CVEs. Then run the platform-rebuild workflow again (w1/135).
