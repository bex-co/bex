## Objective

Make repository Blueprints teach and accept the canonical Render-shaped services root and fields, then delete bex-only parsing aliases.

## Context

- lego/backend/internal/apps/deploy.go and scripts/app-apply.sh accept the legacy apps root, bare image strings, and fields such as tier, replicas, port, imagePath, and publishPath.
- examples/hello-go, hello-node, and hello-python still use apps, so repository-owned inputs must migrate before parser removal.
- Render-compatible fields such as autoDeploy remain in scope as valid contracts even if Render labels a form deprecated.

## Steps

1. Convert all examples, docs, fixtures, and scripts to services and canonical Blueprint fields.
2. Remove legacy decode and normalization branches from the API and app-apply helper.
3. Add rejection tests with actionable validation errors for retired fields.

## Acceptance criteria

- [ ] Every shipped example uses services and canonical fields.
- [ ] Canonical Blueprints still deploy through API and app-apply flows.
- [ ] apps-root and retired bex-only fields fail validation rather than being silently normalized.
- [ ] Render-supported compatibility fields remain accepted and covered.
