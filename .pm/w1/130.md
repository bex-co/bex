# The deploy-hook field can show the previous service's secret URL after an in-place service switch

Why: `useDeployHook` (`dashboard/src/features/services/hooks/use-deploy-hook.ts`) keeps the last good URL in state, keyed by nothing. When the same mounted section moves to another service (a param change on the same route), service A's deploy-hook URL, which is a credential that triggers deploys, stays in the masked field and the copy button until B's read arrives. If B's read fails, A's URL stays indefinitely.

- Found by `w1/m177`'s refactor of this hook (2026-10-15). It is pre-existing behavior; m177 kept it unchanged to stay behavior-preserving.
- Shape: tag the kept URL with the service id it was read for (as m177 did for the database and Key Value connection info), and show it only when the tag matches the current `serviceId`. The rotation path (`regenerate`) sets the URL for the current service, so it keeps working.
- Done when a test switches `serviceId` in place and asserts A's URL is never rendered under B, including when B's read fails.
