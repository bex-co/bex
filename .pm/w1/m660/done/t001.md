## Objective

Each static site release keeps a record of the env vars, secret files and environment groups its build used (names and content hashes, never values), as a Deployment-backed release does, so a later rollback can be compared.

## Context

- Services keep per-release configuration records: [ADR004 § Per-release configuration snapshots](../../../../docs/ADR004-app-deployment.md#per-release-configuration-snapshots-w1m152); `lego/operator/internal/controller/release_config_snapshot.go`, `release_config_selection.go`, `saved_configuration.go`.
- A static release writes only its publication record: `lego/operator/internal/controller/static_publication.go`, `lego/types/v1alpha1/releasesnapshots.go` (`StaticPublicationRecordName`).
- The build's environment is what Render compares for a static site (env vars, secret files, env groups); redirects, rewrites and headers stay current (Render's rollback docs, ADR018 § Deploys: Rollback).

## Steps

1. Record the static build's env var keys, secret file names and linked group ids with content hashes, beside its publication record, retained as long as the publication it describes.
2. Keep values out of the record and out of any log.
3. Leave releases built before this change without a record (no backfill guessed from current values).

## Files

- `lego/operator/internal/controller/static_publication.go` and the release-record helpers
- `lego/types/v1alpha1/releasesnapshots.go`

## Acceptance criteria

- [x] Operator tests: a static build writes the record with names and hashes only; a changed env var changes its hash; the record is reclaimed with its publication.
- [x] `make test` (from `lego/operator/`) and `make lint` pass.

## Outcome (2026-11-26)

**Deviation: the record already existed.** Every static release's adoption (`recordAdoptedRelease`) writes `<app>-podtemplate-r<gen>`, a version 1 record naming its env, secret file and group sources, and keeps a per-source copy of each (`<app>-<source>-r<gen>`). This has held since w8/m120 (2026-10-19) for a built site and since w8/392 (2026-11-21) for a no-build one. That is what a service's release keeps. The copies are App-owned Secrets with values, as a service's are, and the comparison reads only their names out of them. An envtest probe found `site-direct-podtemplate-r1` for a no-build site, and the dev-1 walk found `…-podtemplate-r1`, `-r3` and their copies on the shared operator. No operator code change was needed beyond the shared `appv1alpha1.StaticPrefixGeneration` helper.

- The record is reclaimed with its publication. `gcReleaseConfigSnapshots` sweeps both on the same generation cutoff.
- A static Rollback or Restart builds nothing. Its record names the sources saved when it was requested, and its adopted spec keeps the release selection whose `StaticPrefix` names the publication it copied. bex-api follows that selection (t002).
- Tests: `static_build_environment_test.go` covers sources named and copied, copy-once against a later save, the next release's copy, the record and copies reclaimed with the publication record, and a copy's recorded selection. `make test` and `make lint` pass. Shipped in `303185a725`.
