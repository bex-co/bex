## Objective

Each static site release keeps a record of the env vars, secret files and environment groups its build used (names and content hashes, never values), as a Deployment-backed release does, so a later rollback can be compared.

## Context

- Services keep per-release configuration records: [ADR004 § Per-release configuration snapshots](../../../docs/ADR004-app-deployment.md#per-release-configuration-snapshots-w1m152); `lego/operator/internal/controller/release_config_snapshot.go`, `release_config_selection.go`, `saved_configuration.go`.
- A static release writes only its publication record: `lego/operator/internal/controller/static_publication.go`, `lego/types/v1alpha1/releasesnapshots.go` (`StaticPublicationRecordName`).
- The build's environment is what Render compares for a static site (env vars, secret files, env groups); redirects, rewrites and headers stay current (Render's rollback docs, ADR018 § Deploys: Rollback).

## Steps

1. Record the static build's env var keys, secret file names and linked group ids with content hashes, beside its publication record, retained as long as the publication it describes.
2. Keep values out of the record and out of any log.
3. Leave releases built before this change without a record (no backfill guessed from current values).

## Files

- `lego/operator/internal/controller/static_publication.go` and the release-record helpers
- `lego/types/v1alpha1/releasesnapshots.go`

## Acceptance criteria

- [ ] Operator tests: a static build writes the record with names and hashes only; a changed env var changes its hash; the record is reclaimed with its publication.
- [ ] `make test` (from `lego/operator/`) and `make lint` pass.
