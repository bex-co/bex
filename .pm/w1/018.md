# Dependabot triage — all npm (dashboard); 2 criticals dev-only/unreachable; safe batch applied, residuals noted

**Triage of the Dependabot alerts on `main`** (source: `006`, 2026-07-08 push; re-pulled 2026-07-12). The headline: **every alert is `npm` (the `dashboard/`) — zero Go-module findings.** The live count drifted to **33 open** (2 critical / 15 high / 13 medium / 3 low) from the 36 at task-write — three had already been fixed upstream.

## Criticals reachability (both dev-only, zero prod path)

- **`vitest` < 4.1.0** (alert 249, "Vitest UI server arbitrary file read") — a **devDependency** (the test runner); the Vitest UI server is never exposed in prod. Unreachable in any deployed path. Fixed anyway (see batch).
- **`shell-quote` ≤ 1.8.3** (alert 250, "quote() newline injection") — transitive of **`@graphql-codegen/cli`** (codegen, build-time) and **`launch-editor`** (vite dev-server "open in editor"). Both dev-only; no prod runtime touches it. Unreachable. Fixed anyway.

## Safe batch applied (all within-major, non-breaking) — `dashboard/package.json`

Direct dep bumps (same major):
- `vitest` `^4.0.16` → `^4.1.10` (resolves 4.1.10) — fixes critical 249; `@vitest/coverage-v8` `^4.0.16` → `^4.1.10` to keep the peer aligned.

## Residuals (need a breaking/multi-major bump or have no fix — follow-ups)

- **`lodash` 4.17.23** (high 241 code-injection via `_.template`; medium 240 prototype pollution) — **no upstream fix exists** (4.17.23 is the latest). Build-time transitive (vite toolchain). Already pinned to latest via `resolutions`; monitor for a 4.17.24+ release.
- **`minimatch`** (highs 224/225) — **two majors in the tree** (3.1.2 and 9.0.5); a blanket `resolutions` entry would force one major and break the other's consumers. Needs scoped resolutions (`parent>minimatch`) or a parent upgrade.
- **`picomatch` 2.3.1** (high 234 / medium 236) — the 4.0.5 copy is already patched; only the 2.x copy is vulnerable. Same multi-major trap as minimatch — needs a scoped resolution or parent upgrade.
- **`srvx` < 0.11.13** (medium 237) — 0.x dev-server dep; bump within 0.11.x or via a parent (TanStack Start). Deferred (dev-server, not a prod surface).
- **`@tanstack/start-server-core` < 1.167.30** (medium 246) — a framework-level bump (TanStack Start); deferred to avoid churning the in-flight dashboard work.
- **`vite` 8.x** (breaking major) — all known 7.x vulns are closed at 7.3.6; moving to 8.x is a separate breaking upgrade with its own validation pass.

These five + lodash are the standing security backlog; promote to a milestone if any gets a reachable-in-prod path or an easy fix.
