## Objective

Do what Render's create forms do for a workspace's first resource.

## Context

- Render's `index` hook: when `firstServiceCreationCompleted === false` and the workspace has no projects, the submit first creates project "My project" with environment "Production", then creates the resource in it, reusing the project on a retry; the form hides its Project/Environment fields meanwhile. `NewServiceSourceCode` (web, static, private, worker, cron), `NewDatabase` and `NewRedis` call it; no flag gates it.
- bex's forms: `_serviceCreate.{web,static,pserv,worker,cron}.new.tsx`, `new.database.tsx`, `keyvalue.new.tsx` / `new.redis.tsx`; `new-project-dialog.tsx` already defaults an environment to "Production".

## Steps

1. Add one hook the seven forms share: read the query and the workspace's projects; when it applies, hide the Project field and, on submit, create the project (once per form, reused on retry) before the resource.
2. A failed project create shows its error and creates nothing else.

## Files

- `dashboard/src/features/projects/` (new hook)
- the seven create routes

## Acceptance criteria

- [ ] A fresh workspace's first create lands in My project › Production; the second create shows the Project field and creates no project; a workspace with a project is untouched.
