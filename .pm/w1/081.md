# `dev-env.sh agent-up` silently reuses a stale `bex-lego:dev`

Why: a gateway or bex-api code change never reaches the cluster, so `agent-up` reports success while the pod runs old code — it cost a full verification cycle in w1/m136 and will cost the same for anyone editing `cmd/ssh-gateway` or the packages it imports.

`scripts/dev-env.sh:908` (`agent_build_images`):

```sh
docker image inspect bex-lego:dev >/dev/null 2>&1 ||
  (cd lego && docker build -q -t bex-lego:dev . >/dev/null)
```

The image is built **only when absent**. Once it exists, every later `agent-up`
skips the build, and the "loading images into every node's containerd" loop below
it skips too (it `continue`s when the node already has a tag by that name). The
deployment then rolls out "successfully" onto the identical old image.

Observed in w1/m136: the model-proxy fix was in the working tree, `agent-up`
printed `building the agent-session images` and
`deployment "bex-ssh-gateway" successfully rolled out`, and the session still
reproduced the pre-fix behavior. bex-api (a host process, rebuilt every `up`) had
the new code while the in-cluster gateway did not — the two halves of one change
were split across a version boundary with no signal.

Manual workaround used:

```sh
cd lego && docker build -t bex-lego:dev .
for node in $(kubectl get nodes -o name | cut -d/ -f2); do
  docker exec "$node" ctr -n k8s.io images rm docker.io/library/bex-lego:dev
  docker save bex-lego:dev | docker exec -i "$node" ctr -n k8s.io images import -
done
kubectl -n bex-system rollout restart deploy bex-ssh-gateway
```

Do **not** fix it by always rebuilding — that adds a full multi-module Docker
build to every `agent-up`, including the common case where nothing Go changed.
Options worth weighing:

- an opt-in `AGENT_REBUILD=1` (smallest, explicit, no cost when unset),
- rebuild when any `lego/**/*.go` is newer than the image's created timestamp
  (`docker image inspect -f '{{.Created}}'`) — automatic and usually cheap,
- tag the image with a source hash so a changed tree is a different tag and the
  node-load `continue` misses correctly.

The same `|| build` guard covers `bex-agent-sandbox:dev` (`:906-907`) and the two
opensandbox images, so whatever is chosen should apply to all four.
