# Prod egress usage rows never materialize — the strict billing gate skips every hour

Observed 2026-07-18 while capturing the w1/m50 t006 before-snapshot: the July usage surface has ZERO `egress_bytes` rows for any resource (only instance_seconds/storage rows exist), on a workspace with steadily-serving apps. Cause: the hourly usage rollup's strict egress health gate (`internal/usage/service.go` `queryEgressSources`, correct per ADR023) rejects any hour whose window contains a Traefik router-counter reset, a meter `up` gap, or scrape-density shortfall — and on prod, deploy cadence + meter DS rolls mean nearly every hour fails at least one term for at least one source (the same mechanism that blanked the metrics panel, m50's evidence). Deferred-retry never succeeds because the past hour's samples never improve.

m50 deliberately did NOT touch the billing gate (never invent bytes). But an egress meter that records nothing ever is also wrong — undercounting to zero. Candidate fix (needs its own design pass): per-SOURCE hour gating instead of per-resource all-or-nothing (record the healthy sources' increase, skip only the unhealthy source), and/or relaxing the reset term to `increase()`-tolerant accounting for the http source where resets are deploy-driven and the counter is Traefik-owned (monotone within router generations). Sub-hour to diagnose further, milestone-sized to fix properly; check `usage_hourly` for historical egress rows before assuming it never worked.
