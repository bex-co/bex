## Objective

Render the avatar wherever t001 found that Render shows one: uploaded image, then Gravatar (users only), then monogram.

## Context

- One shared component replaces the initial fallback: `dashboard/src/common/components/user-nav.tsx`, `dashboard/src/common/components/ui/avatar.tsx`.
- Sites to cover:
  - `dashboard/src/features/workspaces/components/workspace-switcher.tsx`;
  - `dashboard/src/common/components/dashboard-layout/sidebar-brand.tsx`;
  - the team members list (`dashboard/src/features/team/`) and `dashboard/src/features/organizations/components/organization-members-card.tsx`;
  - deploy and event "triggered by" rows and cron runs, where Render shows them (`dashboard/src/features/services/components/cron-runs-section.tsx`).
- Gravatar: the trimmed, lower-cased email, hashed with SHA-256, requested with `d=404`; a miss falls back to the monogram and is cached for 5 minutes, as Render's is.

## Acceptance criteria

- [x] Each site renders the three cases in tests; a Gravatar 404 shows the monogram without a broken image.

## Outcome (2026-11-26)

`UserAvatar` and `WorkspaceAvatar` (`features/avatars/components/avatar.tsx`) replace the initial fallback; `ui/avatar.tsx` and `@radix-ui/react-avatar` went with it. The three cases (upload; Gravatar, SHA-256 of the trimmed lower-cased email, `d=404`, a miss remembered 5 minutes; monogram) are tested once in `avatar.test.tsx`, and each site tests the case it adds: the account menu (`user-nav.tsx`, from `user { id avatarDownload { url } }`), the switcher's trigger and rows (round, as Render's; `sidebar-brand.tsx` is bex's logo, not a workspace's, and keeps it), the team members list, the organization's members and workspaces, the events feed's "by" (the event user's own `avatarDownload`) and a cron run's "by" (the member's upload looked up by email, as Render's `avatarsForWorkspaceMembers` does, since a run names only an email). An upload or a reset writes the new URL into Apollo's normalized `User` or `Workspace`, so every site follows without a reload. Render's remaining sites (webhook, registry credential and API key "created by", a deploy's detail page) are follow-up [w1/159](../../159.md).
