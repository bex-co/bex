## Objective

A local cluster can never request a Let's Encrypt certificate, whatever host a local App, platform component or dev-N stack declares.

## Context

- Local Argo syncs `deploy/gitops/charts/cert-manager-issuers` through the `cert-manager-issuers` Application; the local overlay already patches Applications (`bex-operator`).
- Every local host is a production name (operator `BEX_BASE_DOMAIN=onbex.co`, platform `*.bex.co`), so ACME there can only fail and its self-check polls production.

## Steps

1. Patch the `cert-manager-issuers` Application in `deploy/gitops/overlays/local/kustomization.yaml` so both ClusterIssuers keep their names and become `selfSigned: {}` (consumers still get a TLS Secret).
2. Render it the way Argo does and confirm no `spec.acme` remains.
3. Clean the local `hello-go` Certificate that was polling the canary.

## Files

- `deploy/gitops/overlays/local/kustomization.yaml`

## Acceptance criteria

- [x] The local render of both ClusterIssuers is self-signed with no ACME solver; prod is unchanged.
- [x] Production saw no ACME request after the local Certificate was removed (last 10:01:14Z).

## Out of scope

- Giving local clusters a non-production base domain (larger dev-flow change).
