# A deploy a person canceled says who, as Render's "Canceled by you" does

Why: Render's deploy page Notices say who canceled a deploy ("Canceled by you", "Canceled by {email}", "… via API"); bex records no caller for a cancel, so its Notices show nothing for one.

- **Found:** w1/m659 t007 (2026-11-26). Render's public dashboard bundle, `CancelReasonText` chunk: a cancel reason of kind `user` or `api` reads "Canceled by" then "you" (the viewer) or the user's avatar and email, then "via API" for an API key; `useDeployDetails` reads it from the deploy's `DeployEnded` event (`canceledBy`, `canceledWithApiKey`). Recorded in [deploy-detail-page.md § Notices](../../docs/render-artifacts/deploy-detail-page.md#notices), entry 9.
- **bex:** `deploys.Cancel` (`lego/backend/internal/deploys/service.go`) leaves `cancel_reason` empty for a person's cancel (w6/m52) and records no caller; the `deploy_ended` event's reason carries no `canceledBy`. Cron runs already keep theirs (`cron_run_actors.canceled_by`).
- **Do:** record the canceling subject (and whether it was an API key) on the deploy row, serve it on GraphQL `Deploy` and the `deploy_ended` event's reason as Render's `canceledBy` / `canceledWithApiKey`, and show Render's sentence, with the avatar, at entry 9 of the deploy page's Notices, in all eight locales.
- **Done when:** a deploy canceled from the dashboard reads "Canceled by you" to its canceler and "Canceled by {email}" to another member, one canceled with an API key adds "via API", in backend and component tests, and `go test ./...`, `yarn lint` and `yarn test` pass.
