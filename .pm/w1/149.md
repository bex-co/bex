# Cursor Origin as a Git provider: build it, or sign it off beside GitLab and Bitbucket

Why: Render's dashboard now connects "Cursor Origin" as a Git provider, and bex has no disposition for it; GitLab and Bitbucket Git providers are user-rejected non-goals, but that decision does not name this one.

- **Found:** w1/m645's dashboard ledger (2026-11-26), rows `cursorOriginConnect`, `cursorOriginConfirm`, `cursorOriginConfirmUrl`, `cursorOriginDisconnect`, `cursorOriginInstallUrl` and `cursorOriginInstallations` in [dashboard-operations.md](../../docs/render-artifacts/dashboard-operations.md#git-and-registry-credentials).
- **Render (bundle, no flag):** Account Settings' Git providers list has **Connect Cursor Origin**: "Connect to a Cursor workspace where Render is already installed. If it isn't installed yet, a Cursor admin can install it." A callback page says "Connected to Cursor Origin", and the analytics event is "Git Provider Connected" with `git_provider: cursor_origin`. Disconnecting removes each installation.
- **bex:** Git connections are GitHub only, and workspace-owned ([ADR078](../../docs/ADR078-github-workspace-connections.md), `.pm/DO_NOT_DO.md` #GIT-WORKSPACE-OWNED). `.pm/DO_NOT_DO.md` rejects GitLab and Bitbucket Git-provider integration by user decision (2026-07-13).
- **Needs the user:** build Cursor Origin as a Git provider (a workspace-owned connection, as GitHub's), or record it as a non-goal with the GitLab and Bitbucket lines.
- **Done when:** the decision is recorded, as a filed milestone or as a DO_NOT_DO line plus an ADR018 `—` note on the Git connections row, and the six ledger rows point at it.
