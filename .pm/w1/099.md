# 099 — Env var values don't round-trip through the dashboard: Export's JSON escapes come back from Import as literal letters, and a pasted multi-line value is silently flattened

Why: a user who copies their environment out ("Copy env vars") and pastes it back into "Import from .env" should get the same values. A user who pastes a PEM key or JSON blob into a value field should save what they pasted. Today both paths silently change secrets, and nothing warns.

- **Severity:** major (silent value corruption on save; the same values are byte-exact once stored — `w4/done/m92`).
- **Found:** live `/qa-find-bugs`, 2026-09-14 pass 30, journey 4.
  - Workspace `bex` / `tea-d98210cbbpdc73dcrkvg`.
  - Fixture: free web service `qa-20260914-dotenv` (`srv-dak5ad0gsm7s73f64ktg`), `examples/hello-go`.
  - Created 20:12:38Z and deleted 20:18:59Z (`DELETE` → `204`, then `GET` → `404`).

## Root cause

- **The two ends disagree on escapes.**
  - Export serializes each value with `JSON.stringify` (`dashboard/src/features/services/lib/env-export.ts`, `formatEnvExport`). That emits `\uXXXX` for control characters, plus `\b`, `\f`, `\"` and `\\`.
  - The import parser's double-quoted branch understands only `\n`, `\r` and `\t`. Every other escaped character is taken literally (`dashboard/src/features/services/lib/dotenv-import.ts:79-88`), so `\u001b` becomes `u001b`, `\b` becomes `b`, and `\f` becomes `f`.
  - The unit tests cover each side alone (`lib/__tests__/env-export.test.ts`, `lib/__tests__/dotenv-import.test.ts`); nothing feeds `formatEnvExport` output into `parseDotenv`.
- **Value fields are single-line inputs.** Every env value field is a single-line `<Input>`, and the browser flattens a pasted or filled line break:
  - `EnvDraftItem` (`dashboard/src/features/services/components/service-environment-editor.tsx:1159-1181`), shared by the service Environment page (`routes/services.$serviceId.env.tsx:47`) and the env-group detail editor (`features/env-groups/components/env-group-editors.tsx:30`);
  - `NewEnvGroupDialog` (`features/env-groups/components/new-env-group-dialog.tsx:248-251`, used by `routes/env-groups.tsx:119` and `env-groups-panel.tsx:153`);
  - `env-var-row.tsx:114` and `env-vars-panel.tsx:325`, `:337` (consumers not traced).

  The editor also displays an imported multi-line draft flattened (`-----BEGIN KEY-----line-oneline-two-----END KEY-----`), although its state still holds the newlines.

## Fix (~55m)

- **Round-trip identity.** `parseDotenv(formatEnvExport(entries))` must equal `entries` for any string. Accept JSON string escapes inside double quotes (`\" \\ \/ \b \f \n \r \t \uXXXX`, including surrogate pairs), or change Export to emit only escapes Import reads. Pick one, and state it in both files.
  - Adjacent class: a user's own `.env` holding a literal `\u…` is rare, and common dotenv libraries don't expand it. Decide whether import keeps that literal, and document the choice.
- **Multi-line values.** Make env value fields an auto-growing `<Textarea>` (starting at one row) at every site above, so a pasted PEM or JSON keeps its line breaks and an imported multi-line draft displays truthfully. At minimum, refuse or warn on a line break instead of flattening it.
- **Tests.**
  - A property test: arbitrary strings with control characters, U+2028, emoji, quotes, backslashes, `#`, leading and trailing spaces, and empty values round-trip through export then import.
  - A component test: a multi-line paste reaches the `PatchServiceEnvironment` payload with `\n` intact.
- **Live DoD.** Repeat the probe above. `CTRL` and `MULTI` read back byte-identical to what was exported or pasted, and `PEM` stays unchanged.
- **Unverified.**
  - Render's own value field and `.env` escape rules. `render.com/docs/configure-environment-variables` (fetched 2026-09-14) says only "Your file must use valid `.env` syntax".
  - The create-service form's env rows and `env-vars-panel.tsx`'s consumer were not probed.
  - Whether typing into a flattened multi-line draft (as opposed to pasting a new value) drops the stored newlines was not probed.
- **Dedupe.**
