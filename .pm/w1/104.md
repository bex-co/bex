# 104 — A free service parked while its newer release waits for an image (a queued, running or failed build) cannot wake

Why: `w1/m156` stopped a held pre-deploy step from freezing a serving release's replicas and routing. But a release that has no image yet still halts every reconcile in `buildFromSource`, before the runtime dispatch. A free service that is asleep while a push rebuilds it, or whose newest build failed, therefore stays on the activator's `503 service hibernated` until the build succeeds or a new release ships. While awake, its suspend, resume, scale and idle checks wait the same way.

- **Severity:** major for a free service whose newest build failed (unreachable after its next sleep); minor while a build is only queued or running.
- **Found:** `w1/m156` t001–t002, 2026-09-15, traced from the code. The first fix attempt was withdrawn after review. Not probed live: m156 t003 probes it.

## Where

- `lego/operator/internal/controller/app_controller.go`: `resolveDeployImage` returns on `buildFromSource`'s halt, before `dispatchRuntime` → `reconcileKubernetes`. The halts are:
  - a recorded terminal failure (`terminalBuildFailureRecorded`);
  - a queued or running build;
  - a registry-credential wait.

## Constraints from the m156 review

- **Keep the build's requeue.** A parked App with a build in flight must still come back at the build's cadence, because nothing watches build Jobs. Don't overwrite Building or BuildQueued with Hibernated on every poll.
- **Respect the disk lifecycle.** Converge only after `reconcileDiskLifecycle`, which scales a service to 0 for a restore and must win.
- **Don't run the full runtime on every build poll.** Skip routing writes when nothing changed, and when converging, complete autoscaling transitions and persist status.
- **Legacy markers.** `recordedBuildVerdict` falls back to a Ready-only build-failure marker. A status write that replaces Ready must not erase it and cause the failed build to be dispatched again.

## Fix

- Have `resolveDeployImage` report "no image yet over a prior release" (prior `status.image`, active revision) instead of halting. Let `reconcileKubernetes` hold with `convergeServingRuntime` after `reconcileDiskLifecycle`, keeping the build's requeue.
- Tests:
  - waking over a failed build;
  - a parked App with a running build keeps a positive requeue;
  - a disk restore is not scaled up.
