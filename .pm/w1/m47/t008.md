## Objective

Add meaningful test coverage for the merged Events page, ensuring deploy and audit events interleave correctly and the page behaves correctly across edge cases.

## Context

This milestone touches both backend (events service enrichment) and frontend (page merge). Tests should cover:
- Backend: new deploy-detail enrichment in `events.Service.List`
- Frontend: Events page rendering mixed event types, pagination, filtering

## Steps

1. **Backend tests** (in `lego/backend/internal/events/events_test.go`):
   - Add a test that lists events and verifies both deploy events and audit events appear in the result
   - Verify deploy events carry full details (image, commit, trigger)
   - Verify audit events carry expected metadata (actor, target)
   - Test pagination cursor behavior with mixed event types
   - Test filtering by event type (if added in t004)

2. **Frontend tests** (in `dashboard/src/features/events/`):
   - Render the merged Events page with mock data containing both deploy and audit events
   - Verify deploy rows show commit info and action buttons
   - Verify audit rows show actor and what changed
   - Test that clicking a deploy row opens detail view (or navigates if applicable)
   - Test pagination still works

3. **Integration test** (if applicable):
   - Run `scripts/events-verify.sh` (mentioned in ADR006) or equivalent to verify a real sequence of operations produces expected events

## Files

- `lego/backend/internal/events/events_test.go` (add deploy-enrichment tests)
- `dashboard/src/features/events/__tests__/` (create or update component tests)
- `scripts/events-verify.sh` (run the existing verification if it exists, or confirm it works with the new structure)
