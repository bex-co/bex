## Objective

Document Render's Events page design by live observation on render.com. Capture the exact layout, event types shown, how deploys and audit events interleave, filtering options, and any interactive behaviors (pagination, timestamps, details expansion).

## Context

- Render's events page: https://dashboard.render.com/web/srv-cat7akcgqg4clog413b0/events
- Already have bex's API design (ADR006, w3/m7): events are composed from `deploys` + `audit_events` tables
- Backend already emits all required event types; this is purely a UX/interaction audit

## Steps

1. Open https://dashboard.render.com/web/srv-cat7akcgqg4clog413b0/events (or equivalent live service)
2. Screenshot the full page (header, filters, list, pagination)
3. Note the exact event types visible (deploy_started, deploy_ended, config changes, suspensions, etc.)
4. Test pagination behavior — is there a "Load more" or cursor-based pagination?
5. Check filter UI — can you filter by event type? date range?
6. Hover/click on a deploy event — does it expand to show details or link to a deploy page?
7. Note the order (newest-first), timestamp display, and actor/trigger info shown per row
8. Document any visual patterns for deploy success vs failure vs canceled
