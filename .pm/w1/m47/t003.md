## Objective

Modify the `serviceEvents` GraphQL query and `ServiceEvent` type to include full deploy details (commit, image, trigger, duration, preDeployStatus) so the merged Events page can display rich deploy info without a second query.

## Context

Today `serviceEvents` returns:
```
{
  id, type, timestamp, cursor,
  details { deployId, deployStatus, actor, trigger { ... } }
}
```

But the dashboard's Deploys list shows additional deploy fields:
- `image` (the deployed container)
- `commitId`, `commitMessage`, `commitCreatedAt`
- `trigger` (string: "manual", "git-push", "deploy-hook", etc.)
- `preDeployStatus`
- `startedAt`, `finishedAt` (for computing duration)

Render's Events page shows these details inline, so bex must enrich the event's deploy details to avoid a second round-trip.

## Steps

1. Update `ServiceEvent.details` GraphQL type to include deploy-specific fields:
   - `image: string`
   - `commitId: string`
   - `commitMessage: string`
   - `trigger: string` (or existing trigger enum)
   - `preDeployStatus: PreDeployStatus`
   - `startedAt: DateTime`
   - `finishedAt: DateTime`
2. Modify `events.Service.List` (the Core implementation) to fetch full deploy row when the event type is a deploy event
3. Map deploy row fields onto the `ServiceEvent.details` object
4. Test that a deploy_started event carries commit info, image, etc.
5. Run the existing `TestEventSurfaceParity` to ensure GraphQL/REST remain consistent

## Files

- `lego/backend/internal/events/graphql.go` (type definition)
- `lego/backend/internal/events/service.go` (List enrichment logic)
- `lego/backend/internal/events/events_test.go` (test the enrichment)

## Acceptance criteria

- [ ] `ServiceEvent.details` includes image, commitId, commitMessage, trigger, preDeployStatus, startedAt, finishedAt
- [ ] Events with type `deploy_started` or `deploy_ended` carry the full deploy details
- [ ] Non-deploy events (audit events) have those fields set to null/empty as appropriate
- [ ] `TestEventSurfaceParity` passes (GraphQL and REST return identical data)
- [ ] No additional query round-trips (all data fetched in one pass)

## Out of scope

- REST type changes (those remain as-is; this is GraphQL enrichment only)
- Dashboard consumption (next task)
