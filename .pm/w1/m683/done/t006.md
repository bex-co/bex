## Objective

Delete an environment from Render's Delete Environment card, refusing the last one as Render does.

## Context

- Render: "This environment, including its services, will be permanently deleted. This action cannot be undone."; the confirmation `sudo delete environment <name>`; a "Managed by Blueprint" warning; and for a project's only environment, "This environment cannot be deleted as projects require at least one environment. Consider deleting the project instead."
- bex's dashboard, GraphQL and MCP delete contained services, Postgres and Key Value (w4/m264, w6/m290); REST answers 409 for a non-empty environment, as Render's API does (ADR018). Nothing refuses deleting the last environment today.

## Steps

1. Build the card and the sudo modal over the existing delete mutation, with the Blueprint warning when the environment is Blueprint-managed.
2. Refuse the last environment in the dashboard with Render's sentence.
3. If a Render API key is available, probe Render's `DELETE /v1/environments/{id}` on a project's only (empty) environment: if Render refuses, refuse it on REST, GraphQL and MCP with a coded error; if not, or if it cannot be probed, leave the API unchanged and record which in t009.
