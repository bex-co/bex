## Objective

Make the editor's choices depend on the kind of service, as Render's do.

## Context

- `SaveChoice` (`service-environment-editor.tsx:125`) and the menu (`:1192-1253`) are the same for every kind today.
- The routes: `dashboard/src/routes/services.$serviceId.env.tsx` (passes `serviceId`, `suspended` and `dockerBuild`), `static.$serviceId.env.tsx` (reuses `ServiceEnvPage`) and the cron job's.
- Environment groups use the same `EnvironmentEditor` (`dashboard/src/features/env-groups/components/env-group-editors.tsx:35`) and keep all three choices.
- The modes behind the choices already exist: `save_only`, `deploy` and `rebuild` (`use-environment-draft-save.ts`). A static site's deploy already rebuilds it; a cron job's deploy applies on its next run.
- Labels live in `dashboard/src/features/services/locales/en.ts` (`services.environmentSaveOnly`, `environmentSaveDeploy`, `environmentSaveRebuild`).

## Steps

1. Derive the choices from the service's type, `imagePath` and `buildSourceId`. Buildable means not image-backed and not built from a build source.
2. Web services, private services and background workers: "Save, rebuild, and deploy" only when buildable, then "Save and deploy" and "Save only".
3. Static sites: "Save and deploy" (the existing deploy mode) and "Save only".
4. Cron jobs: "Save, rebuild, and apply on next run" only when buildable, then "Save and apply on next run" and "Save only", on the same modes.
5. Add the new labels in English (t006 translates them).

## Files

- `dashboard/src/features/services/components/service-environment-editor.tsx`
- `dashboard/src/routes/services.$serviceId.env.tsx`, the static site and cron job routes
- `dashboard/src/features/services/locales/en.ts`
- `dashboard/src/features/services/components/__tests__/service-environment-editor.test.tsx`

## Acceptance criteria

- [ ] Component tests show Render's choices in Render's order for a repository-built web service, an image-backed one, one built from a build source, a static site, a cron job built from a repository, an image-backed cron job and an environment group.
- [ ] No image-backed service and no service built from a build source offers a rebuild.

## Out of scope
