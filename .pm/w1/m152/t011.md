## Objective

Make the release-config snapshot work in production's namespace layout. Since t001 (`cae30d1e0`, live 2026-09-28 16:47Z), a newly created service's first deploy closes `update_failed` with `snapshot <ns>-<svc>-env for generation 1: unable to get: <ns>/<ns>-<svc>-env-r1 because of unknown namespace for the cache`. This was reproduced twice on production, with a repo build and with an image (`w4/171`). Every later m152 task (t002, t003, t009, t010) builds on the same reads, so none of their live acceptance can pass until this lands.

## Context

- The full evidence and mechanism are in `.pm/w4/171.md`.
- `lego/operator/cmd/manager/main.go:269` → `NamespacedSecretCacheOptions(appsNamespace)` (`internal/controller/secret_cache.go:41`) scopes the Secret informer to one namespace. Tenant Apps live in workspace namespaces (`tea-…`, ADR043).
- `internal/controller/release_config_snapshot.go` reads and writes Secrets in `app.Namespace` through the **cached** client: `r.Get` at ~l.123 (t002's `settleConfigSnapshotTo` probe), ~l.207 (copy-once), ~l.217 (source), and `controllerutil.CreateOrUpdate(ctx, r.Client, …)` at ~l.228. The GC List/Delete are likely cached too.
- The existing uncached path is `AppReconciler.uncachedSecretClient()` (`app_controller.go:1962`).
- Why tests passed: envtest's App lives in the cached namespace.

## Steps

1. Route every Secret Get/List/Create/Update/Delete in `release_config_snapshot.go` (and any other m152 Secret access in `app.Namespace`) through `r.uncachedSecretClient()`.
2. Make sure a cache error is never read as "copy missing" in `settleConfigSnapshotTo`.
3. Explain why an existing App's release (`beancount-cms-v2`, 17:03Z → live 17:50Z) escaped while a new App's failed, and make sure both paths now snapshot.
4. Add an envtest App in a namespace **other** than the cache's `appsNamespace` (the production shape). Its first release must project `-r1` and roll out. Add a regression test that fails on the old code with `unknown namespace for the cache`.

## Acceptance criteria

- [ ] On production, a new free web service from `examples/hello-go` with `MESSAGE=v1` reaches `live` and serves `v1`. Changing `MESSAGE` to `v2` and deploying serves `v2`.
- [ ] The envtest above passes, and fails against `cae30d1e0`.
- [ ] `w4/171` is moved to `w4/done/` with the live result recorded.

## Out of scope

- The m152 cancel and rollback behaviors themselves (t002, t003, t009, t010). This only unblocks their live acceptance.
