## Objective

The cancel rule holds for every kind of change that opens a `config_change` deploy, and the cancel paths that are correct today keep working.

## Context

- **Change sources:**
  - service env vars and secret files (`lego/backend/internal/secrets/service.go`);
  - environment groups, whose shared Secrets are rewritten for all linked services (`lego/backend/internal/envgroups/service.go:653-657`; see also `w1/092`);
  - start command, health check path, pre-deploy command and plan (`releaseIdentityInput`, `lego/operator/internal/controller/release_identity.go`).
- **Controls:** `w6/done/m52` (first-deploy cancel → `Canceled`) and `w6/done/m104` (image-backed cancel restores the image).

## Steps

1. **Change sources.** For each source, live-probe or envtest "change then cancel mid-build", and assert that nothing observable changes. A linked env group must not change for **other** linked services either.
2. **Combined changes.** A code deploy and a config change pending together, then cancel: both are restored.
3. **Controls.** Keep the m52 and m104 cancel paths green, unchanged.

## Acceptance criteria

- [ ] A table of change sources, their cancel result and the test covering each is in the m152 README.
- [ ] The m52 and m104 regression tests pass unmodified.
