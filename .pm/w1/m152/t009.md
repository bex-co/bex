## Objective

A rollback runs the target deploy's image **with the target deploy's environment variables and start command**, as Render documents. Rolling back from the dashboard also turns auto-deploy off, so the next push doesn't silently undo the rollback. An API rollback keeps Render's "does not disable automatic deploys" behavior.

## Steps

1. **Restore the target's config.** Using t001's per-release snapshot, have `Rollback` (REST `POST /v1/services/{id}/rollback`, GraphQL `rollbackService`, MCP `rollback_deploy`) dispatch the target deploy's env/files snapshot and start command alongside its image. Keep the current plan, custom domains and disk, as Render does.
2. **Dashboard rollback turns auto-deploy off.** Do it in the same action (e.g. an input on the dashboard's mutation, or a follow-up `autoDeploy: no` write). Keep REST/MCP rollback leaving auto-deploy alone, and say so in the dialog copy.
3. **Honest copy and ledger.** Dialog copy (`dashboard/src/features/services/locales/en.ts:3860-3864`) says what is restored and that auto-deploy turns off. Correct ADR018 row 100.

## Acceptance criteria
