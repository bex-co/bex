# Rename a sandbox group, as Render's group Settings does (`updateSandboxGroupName`)

Why: Render's dashboard renames a sandbox group from its Settings page; bex's group Settings (w1/m658) shows the name read-only because bex-api serves no rename, and the dashboard ledger marked `updateSandboxGroupName` matched when it is not.

bex-api's group update takes the concurrency limit alone (`UpdateGroup(ctx, id, concurrencyLimit)` in `lego/backend/internal/sandbox/groups.go`, GraphQL `updateSandboxGroup(concurrencyLimit: Int!, id)`, REST `PATCH /v1/sandbox-groups/{id}`). Render's bundle (read 2026-11-26) has `mutation updateSandboxGroupName`, and its public API's group update is worth checking for a `name` field before choosing the surface. Names are unique per workspace (`sandbox_groups_workspace_name_key`).

Done when: a group can be renamed on GraphQL (and REST and MCP where Render's API takes a name), a taken name is refused as create refuses it, the group Settings page (`dashboard/src/features/sandbox-group-pages/components/settings-page.tsx`) edits the name, and the `updateSandboxGroupName` row of `docs/render-artifacts/dashboard-operations.md` reads matched again.
