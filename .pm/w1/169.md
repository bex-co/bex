# An org audit-log key refused on a route it can never call reads "needs: none"

Why: an Org Owner who sends an org audit-log key to the wrong endpoint gets a refusal that names a permission it supposedly lacks ("none"), which reads as a server bug and does not say what the key is for.

- **Found by:** w1/m657 t007, on production pin `410850e80281`, 2026-11-26, with an org audit-log key of a Scale fixture org (disposable).
- **Observed:** the key is refused everywhere but the two audit-log reads, as designed. Where the route needs no catalog permission, the refusal says `this API key is not granted the permission this request needs: none` (`api_key_permission_denied`, `required: ["*"]`): REST `GET /v1/users`, `GET /v1/owners` and `GET /v1/owners/{ownerId}`, GraphQL `workspaces`, and MCP `list_workspaces`. Elsewhere it names a permission no org key can be granted either ("View services and their configuration" on `GET /v1/services`).
- **Cause:** `requireKeyGrant` (`lego/backend/internal/api/scope_matrix.go`) refuses an org key through `core.NewKeyPermissionDeniedError(need)`, built for workspace keys with a grant. An org key's grant holds no catalog action, so `core.KeyActionName(core.KeyAnyGrant)` (`lego/backend/internal/core/keygrant.go`) prints "none".
- **Fix:** when `grant.Organization != ""`, refuse with the same 403 `api_key_permission_denied` code and a message that says what the key can do, for example "this API key reads only audit logs: GET /v1/organizations/{orgId}/audit-logs and GET /v1/owners/{ownerId}/audit-logs". Check what Render's API answers an audit-log key on another route before choosing the words.
- **Done when:** an org key on `GET /v1/users`, GraphQL `workspaces` and MCP `list_workspaces` gets the new message with the same code and status, workspace keys' refusals are unchanged, and a test in `scope_matrix_guard_test.go` or `organization_api_keys_pg_test.go` pins both. ~30m.
