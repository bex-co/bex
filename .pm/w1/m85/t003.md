## Objective

`POST /v1/disks/{diskId}/snapshots/restore {snapshotKey}`: full-disk restore with Render's semantics — service stops, PVC restored to the snapshot, service redeploys; post-snapshot writes lost; irreversible.

## Context

- Flow (ADR082 D5): verb validates the key → operator intent (restore request on the App CR or store) → scale to 0 → restore Job mounts the now-free PVC, wipes, age-decrypts + extracts → clear intent → redeploy. 202-class response like `.../failover`.
- Age private key: restore Jobs need the decrypt half — follow the restore-script custody pattern (`scripts/restore-keyvalue.sh`, ADR050); decide and document whether restore runs operator-side with a mounted key Secret or as a platform-runbook-provisioned Secret.
- Dashboard/API docs carry Render's warning verbatim: do not use disk restore for database recovery.

## Steps

1. Verb on three surfaces + intent field; operator restore-Job state machine; warning copy in tool/route descriptions.

## Files

- `lego/backend/internal/apps/disks.go` (+ fragments)
- `lego/types/v1alpha1/app_types.go` (restore intent) + `lego/operator/internal/controller/`

## Acceptance criteria

- [ ] Mock-cluster round-trip: write file A → snapshot → write file B → restore → A present, B gone, service back up.
- [ ] Expired/forged key → 4xx, no scale-down side effects.

## Out of scope

- Partial-file restore (Render doesn't offer it).
