## Objective

Traefik's HTTP and HTTPS entrypoints read the client address from a PROXY protocol header, but only when the immediate peer is the Hetzner load balancer (`10.10.0.7/32`). This rollout must not change today's traffic: the load balancer is not sending headers yet, so connections without one keep working. That makes t002's listener change safe to apply afterwards.

## Context

- `deploy/gitops/overlays/prod/values/traefik.values.yaml:43-48` defines the `web` (8000, nodePort 31218) and `websecure` (8443, nodePort 31976) ports with no `proxyProtocol`. `:66` sets `externalTrafficPolicy: Local`.
- The chart is `oci://ghcr.io/bex-co/bex-charts/traefik`, pinned by digest (`deploy/gitops/base/traefik.yaml:36-38`).
- Precedent: `w2/done/m57/done/t010.md` (datastore proxies trust only `10.10.0.7/32`, rolled before the listeners changed; `scripts/gitops-validate.sh:1025-1027` pins it).
- m150 README § Root cause and § Unverified (behavior for a trusted peer that sends no header).

## Steps

1. **Resolve the version.** Find the Traefik version the pinned chart digest deploys. Read that version's entrypoint PROXY-protocol listener code and record in the m150 README:
   - how a trusted peer with **no** header is treated (must be accepted unchanged for this order to work);
   - how an untrusted peer's header is treated (must never be believed).
2. **Configure the entrypoints.** Set `proxyProtocol.trustedIPs: [10.10.0.7/32]` on both `web` and `websecure` using the chart's real values key (verify it in the chart's `values.yaml`). Do not set `insecure`, and do not add `forwardedHeaders.insecure`.
3. **Gate it.** Extend `scripts/gitops-validate.sh` so either entrypoint missing the setting, or trusting anything wider than `10.10.0.7/32`, fails.
4. **Roll out and confirm nothing changed.** A throwaway `qa-` web service returns `200`, and its request log `ClientHost` still reads `10.10.0.7`.
