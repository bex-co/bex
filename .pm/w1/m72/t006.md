## Objective

Cover the failure modes that would make the shared harness worse than ten copies — a `down` that reaches beyond its own N, and an identity collision.

## Context

- Convention: `scripts/*.test.sh`, gated by `.github/workflows/scripts.yml`. `scripts/install-bex.test.sh` and `scripts/bao-init.test.sh` are the models.
- The consequential failure is cross-N leakage. Two harnesses sharing the CAPD cluster with the same `BEX_CP_IDENTITY` deleted each other's tenant namespaces once already (`.pm/w3/017.md`); a shared script makes that class of bug shared too.
- The live end-to-end check belongs to the DoD (two workstreams, one of them `w5`), not to this unit-test task.

## Steps

1. Derivation tests: for N in 1..10, namespaces, ports, `BEX_CP_IDENTITY`, and kubeconfig path are distinct and match what each `ports.env` declares today.
2. Assert `down` targets only `dev-N`'s namespaces and PIDs — a dry-run mode asserting the resource list is enough.
3. Assert invalid N (empty, `0`, `11`, non-numeric) fails loudly with no side effect.
4. Assert `up` is idempotent — a second run produces no error and no duplicate resources.
5. Assert `clean` refuses while the environment is up.

## Files

- `scripts/dev-env.test.sh` (new)

## Acceptance criteria

- [ ] Per-N derivations asserted distinct across N=1..10 and matching today's `ports.env` values.
- [ ] `down` scope asserted; cross-N leakage would fail the test.
- [ ] Invalid N and `clean`-while-up both fail safely.
- [ ] `scripts.yml` CI green.

## Out of scope

- Live-cluster end-to-end verification (DoD, t007).
