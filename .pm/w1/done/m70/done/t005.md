## Objective

## Context

- Model to copy: `.github/workflows/render-schema-drift.yml` → `scripts/render-schema-drift.sh`.
- The 21 existing workflows are listed in `.github/workflows/`; this adds one, or extends the existing drift workflow with a second check — prefer extending if the schedule and failure semantics match.
- Drift here means: upstream added a tool, removed a tool, or changed a `Parity1to1` tool's arguments.

## Steps

1. Write `scripts/render-mcp-drift.sh` — re-fetch the upstream inventory, regenerate the snapshot, diff against the pin.
2. Wire it into CI on the same cadence as the REST drift job.
3. Make the failure message actionable: name the added/removed/changed tools, and say to re-run the capture from t001.
4. Confirm the job is green at HEAD before merging (a job that starts red teaches people to ignore it).
