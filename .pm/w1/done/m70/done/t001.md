## Objective

Produce the checked-in, content-hashed snapshot of Render's official MCP tool surface that every later parity claim is checked against — the MCP counterpart of the embedded `render-public-api-1.json` + `renderOpenAPISHA256` pin the REST surface already has.

## Context

- REST precedent to mirror exactly: `lego/backend/internal/api/openapi/render-public-api-1.json` (331 KB, embedded) pinned by `renderOpenAPISHA256` in `lego/backend/internal/api/render_openapi.go:41`, refreshed by `scripts/render-schema-drift.sh`.
- Upstream: `render-oss/render-mcp-server`. Existing comments cite it at several points in time — `v0.3.0` (`internal/webhooks/mcp.go:28`), commit `2a00be1` (`internal/events/mcp.go:27`), and bare dates (`internal/registrycreds/mcp.go:28` "checked live 2026-07-13"). Record ONE version and stick to it.
- Capture the tool **name and argument names** per tool. Argument descriptions drift for editorial reasons and should not be part of the hash.

## Steps

1. Resolve the current `render-oss/render-mcp-server` release (tag + commit) and record both.
2. Extract its registered tool list — name plus argument names — into a stable, sorted JSON document.
3. Write it to `lego/backend/internal/api/openapi/render-mcp-tools.json` (beside the REST spec, same embed pattern).
4. Add its SHA-256 constant next to `renderOpenAPISHA256`, loaded through the same `loadRender…ContractData` shape so a corrupted or hand-edited pin fails loudly.
5. Record capture provenance in the file itself: upstream repo, tag, commit, capture date.

## Files

- `lego/backend/internal/api/openapi/render-mcp-tools.json` (new)
- `lego/backend/internal/api/render_openapi.go` (or a sibling `render_mcp.go`)

## Acceptance criteria

- [ ] The snapshot exists, is sorted and deterministic, and re-generating it from the same upstream commit is byte-identical.
- [ ] A wrong hash fails a test with a clear message, matching the REST pin's failure behaviour.
- [ ] The file states upstream repo + tag + commit + capture date.

## Out of scope

- Classifying bex's own tools (t003).
- Any change to a bex tool.
