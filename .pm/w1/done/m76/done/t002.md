## Objective

Make `useKeyValue`'s refresh start a 3s poll before refetching, mirroring `useDatabase` — whose behavior the keyvalue hook's docstring already claims to mirror. Today a lifecycle mutation can be masked by a stale "available" until the next natural poll.

## Context

- `dashboard/src/features/databases/hooks/use-database.ts:51-58` — the correct pattern: `startPolling(3000)` before `refetch()`.
- `dashboard/src/features/keyvalue/hooks/use-key-value.ts:43` — returns Apollo's raw `refetch`; docstring at :19-21 claims parity with `useDatabase`.

## Steps

1. Port the eager-poll wrapper from `use-database.ts` into `use-key-value.ts`.
2. Add/extend a hook test asserting polling starts before the refetch resolves.

## Files

- `dashboard/src/features/keyvalue/hooks/use-key-value.ts`
- corresponding `__tests__` file

## Acceptance criteria

- [ ] A lifecycle mutation followed by refresh shows the transitional status within one 3s poll tick.
- [ ] Hook test covers the eager-poll ordering.
