## Objective

Make `bex_ssh_gateway_active_sessions` answer the question it exists for — "how close are we to `BEX_SSH_MAX_SESSIONS`?" Six surfaces hold `SessionLimiter` slots but only nativessh and webshell report `SessionStarted`/`SessionEnded`, so the shared limiter can be full while the gauge shows a fraction. Separately, `sandboxsse` counts one exchange twice in `authentications_total` (accepted at admission, revoked mid-stream).

## Context

- Slot holders that never touch the gauge: `sandboxsse/sandboxsse.go:158`, `agentattach/agentattach.go:392`, `agentcred/agentcred.go:161`, `modelproxy/modelproxy.go:112`.
- Reporters: `nativessh/server.go:325,327`, `webshell/websocket.go:232,234`.
- Double count: `sandboxsse.go:177` (`Authentication("accepted")`) + `:220` (`Authentication("revoked")` mid-stream) — other transports report mid-stream revocation via `SessionEnded(result="revoked")`.
- One shared limiter across four transports: `cmd/ssh-gateway/main.go:138-141`.

## Steps

1. Add `SessionStarted`/`SessionEnded` pairs to sandboxsse and agentattach (and agentcred/modelproxy if they share the same limiter instance — verify wiring in main.go first).
2. Drop `sandboxsse.go:220`'s second `Authentication` increment; report the revocation through `SessionEnded(result="revoked")`.
3. Tests asserting gauge symmetry (every acquire path increments, every release path decrements) and single-count semantics.
