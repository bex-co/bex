## Objective

Give bex-api one function that takes an image reference and an optional registry credential and answers deployable or one of Render's five codes, reading the registry the way a deploy will.

## Context

- `lego/backend/internal/sandbox/images.go` already resolves an external image with go-containerregistry. It uses `netutil.SafeDialContext` (`guardedSourceTransport`), `capManifests`, a credential's `authn`, `remote.WithPlatform(linuxAMD64)`, `checkConfigSize`, `imageBytes` and `fromOtherHost`. Reuse or lift these instead of writing a second registry client.
- The operator's platform rule: `BEX_IMAGE_PLATFORM` (`lego/operator/internal/registry/image_config.go` `ParsePlatform`, ADR004 § Which digest). The backend cannot import the operator (`lego/AGENTS.md` import DAG), so bex-api reads the same variable with the same values (unset = `linux/amd64`, or `linux/arm64`; anything else refuses startup). The variable goes in `lego/backend/AGENTS.md`'s inventory. `scripts/mock-cluster.sh` and `scripts/dev-env.sh` set it for arm64 nodes where they set the operator's.
- Registry credentials: `lego/backend/internal/registrycreds/` (`service.go`, `pullsecret.go`; registry kinds `GITHUB`, `GITLAB`, `DOCKER`, `GOOGLE_ARTIFACT`, `AWS_ECR`). The check must authenticate exactly as the deploy's pull secret does, so a "deployable" answer and the deploy agree.
- Syntax: the same OCI reference rules as create (w8/m49), so `invalid_input_url` answers exactly what create would refuse.

## Steps

1. Add the check (for example `lego/backend/internal/registrycreds/imagecheck.go`, or a small package of its own), with the result `{Deployable bool; FailureCode *string; FailureReason *string}`.
2. Classify the answers:
   - a malformed or private-host reference is `invalid_input_url`;
   - manifest unknown, name unknown, or an anonymous 401/403 is `does_not_exist`;
   - a 401/403 with a credential, or the token endpoint refusing it, is `invalid_registry_credential` (t001's table decides the edge cases);
   - an index with no hosting-platform entry, or a single manifest whose config is for another OS or architecture, is `unsupported_platform`;
   - compressed layers over 10 × 10⁹ bytes are `image_too_large`.
   An unreachable registry, a 429 or a 5xx is not one of Render's codes. It answers `deployable: false`, no code, and a `failureReason` that says the registry did not answer, so the client shows it, as Render's fallback does.
3. Guard it. Every dial goes through `SafeDialContext`, redirects and token realms included. A credential's secret goes only to its own host (`fromOtherHost`). Manifest and config bodies are capped. The whole read times out (10 s). A small per-workspace concurrency limit returns a retryable error.
4. Tests against `github.com/google/go-containerregistry/pkg/registry` served in-process, through a test transport the guard allows. Cover each code, a multi-platform index with and without the hosting platform, an image just under and just over 10 GB (fake layer sizes in the manifest, no real bytes), and an anonymous and a credentialed private repository. Also cover a token realm or redirect that points at loopback (refused) and a credential never sent to a second host.

## Out of scope

## Done (2026-11-26)

- `lego/backend/internal/registryread`: `read.go` holds the guarded transport, the manifest cap and the config-size check, lifted from the sandbox image import, which now uses them. `check.go` holds `Checker.Check` with t001's classification and `ParsePlatform`. `Checker.Acquire` bounds a workspace at three concurrent checks per replica. The read has a 10 s timeout and makes one attempt (no retries).
- `lego/types/netutil.ErrBlockedAddress` lets the check tell a guard refusal (`invalid_input_url`) from a network failure.
- `BEX_IMAGE_PLATFORM` is now read by bex-api (`cmd/api/config.go`, `lego/backend/AGENTS.md`). `scripts/dev-env.sh` copies the shared operator's value.
- Tests (`internal/registryread/check_test.go`, against go-containerregistry's in-process registry through a transport the guard allows for `registry.test` only):
  - each code, and an index with and without the hosting platform;
  - an index entry that lies about its config;
  - 10 × 10⁹ bytes deployable, one byte over refused;
  - a private repository anonymous, with the right credential, the wrong one, and one that cannot see the image;
  - 429/5xx with no retries, a timeout, an oversized manifest;
  - a loopback token realm and a loopback redirect refused;
  - a credential never sent to a CDN host the registry redirects a blob to.
