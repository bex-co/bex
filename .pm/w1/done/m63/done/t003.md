## Objective

Introduce one normalized Blueprint IR that preserves omitted versus explicit values, then resolve workspace-authorized current state into a deterministic create/update/no-op/conflict plan that apply consumes without reinterpreting YAML.

## Context

- `applyCreateToSpec`, `applyDatabaseSpec`, and `applyKeyValueSpec` currently receive zero-filled specs and cannot recover field presence.
- `blueprintValidationPlan` counts declarations; it does not compare current state.
- Grouped/root/ungrouped resources must normalize into the same typed entries while retaining membership intent and source paths.

## Steps

1. Define optional/presence-aware IR types for services, Postgres, Key Value, env groups, references, and grouping metadata.
2. Normalize all allowed schema variants and deprecated aliases once, with source paths attached.
3. Resolve existing resources by stable workspace identity/name under the caller's authorization boundary.
4. Produce deterministic actions and an immutable apply input; define structural-only output when no store/client exists.

## Acceptance criteria

- [ ] IR tests distinguish absent, null/empty, zero, false, and set values for every mutable field class.
- [ ] The same normalized manifest/current state yields byte-stable ordered actions.
- [ ] Cross-workspace resources are never resolved or leaked in plans/errors.
