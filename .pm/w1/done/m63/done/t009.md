## Objective

Enforce ADR049's no-ignored-state policy: normalize only official deprecated aliases with correct precedence, reject unavailable Render features at their exact paths, and namespace bex-only build strategy as `x-bex.builder` after auditing stored manifests.

## Context

- `autoDeployTrigger: checksPass` currently maps to `true`, indistinguishable from `commit`.
- Persistent service disks and PR preview environments are hard PM anti-goals; region has no truthful per-resource placement mapping.
- `builder` is a bex-only field currently accepted in the service struct, although the official schema rejects it.

## Steps

1. Add stable unsupported-field errors for `checksPass`, service/database `region`, service `disk`, root/service/database previews, and every registry-classified missing capability.
2. Implement official deprecated alias normalization and precedence (`runtime`/`env`, `autoDeployTrigger`/`autoDeploy`, preview aliases even though their canonical capability is unsupported).
3. Add `x-bex.builder` validation/translation and reject new unnamespaced `builder` with migration guidance.
4. Audit repository/stored Blueprint manifests before enforcement; mechanically migrate only unambiguous stored copies and report Git-owned files.
