## Objective

Make `/v1/blueprints/validate` and its GraphQL/MCP twins expose the compiler's complete, secret-safe errors and honest structural/current-state plans while matching Render's multipart request limit and validation-result behavior.

## Context

- `rest.go` sets `maxBlueprintValidationBodyBytes = 2 << 20`; Render documents 10 MB.
- `blueprintValidationFor` currently wraps the first bad-request error into a one-element slice.
- The current `totalActions` is a declaration count even when no current-state diff was performed.

## Steps

1. Raise only the Blueprint multipart file limit to 10 MB without weakening the general API body cap.
2. Return all independently actionable compiler errors with stable code/path/line/column fields through every adapter.
3. Expose authorized action plans when state is available and explicitly labeled structural summaries otherwise; remove misleading action counts.
4. Pin Render-compatible status/envelope behavior and official CLI decoding with contract tests.

- `lego/backend/internal/apps/rest.go`
- `lego/backend/internal/apps/graphql.go`

## Acceptance criteria

- [ ] Multipart files through 10 MB reach validation; larger files fail predictably without affecting other endpoint limits.
- [ ] REST, GraphQL, and MCP carry the same ordered codes/paths and never leak secret values.
- [ ] A plan's create/update/no-op/conflict counts match current state, or the response plainly says it is structural-only.

## Out of scope

- Changing global `BEX_MAX_BODY_BYTES` defaults.
