## Objective

Change new Blueprint discovery and product language to `render.yaml` while preserving existing explicit paths and a warning-emitting `bex.yml` filename fallback with identical grammar. Refuse ambiguous implicit discovery when both files exist.

## Context

- Defaults are duplicated in `blueprint.go`, `store/blueprints.go`, `dashboard/src/routes/blueprints.new.tsx`, hooks, tests, locales, scripts, and examples.
- `deploy/gitops/base/bex.yaml` is an unrelated platform manifest; ADR049 explicitly declines an application `bex.yaml` name.
- Existing wire args named `bexYaml` remain decode aliases; this is a filename/product-copy migration, not a gratuitous API break.

## Steps

1. Centralize discovery precedence: explicit path, `render.yaml`, legacy `bex.yml`, ambiguity error.
2. Preserve existing Blueprint record paths; add deprecation metadata/warnings for fallback use.
3. Rename repository examples and update dashboard defaults, locale copy, MCP descriptions, comments, and scripts.
4. Add discovery/migration tests for explicit custom paths, each fallback, both-file ambiguity, and old stored records.

## Files

- `lego/backend/internal/apps/blueprint.go`
- `lego/backend/internal/store/blueprints.go`
- `dashboard/src/routes/blueprints.new.tsx`
- `dashboard/src/features/blueprints/**`
- `examples/**/bex.yml` → `examples/**/render.yaml`
- `scripts/**`
- `lego/backend/internal/apps/*blueprint*_test.go`

## Acceptance criteria

- [ ] All new flows default to `render.yaml`; custom paths and existing `bex.yml` records continue to work.
- [ ] `bex.yml` and `render.yaml` pass/fail identically byte-for-byte apart from the deprecation warning.
- [ ] Implicit both-file discovery refuses to guess; no application documentation introduces `bex.yaml`.

## Out of scope

- Removing the `bex.yml` alias; that requires a separate explicit compatibility decision.
