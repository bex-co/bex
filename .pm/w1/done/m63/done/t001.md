## Objective

Vendor the reviewed Render `render.yaml` JSON Schema and introduce a machine-readable bex capability registry that classifies every schema field and enum as equivalent, translated, unsupported, deprecated, or `x-bex` extension. Add deterministic exhaustiveness and upstream-drift checks so a Render schema change cannot become implicit runtime behavior.

## Context

- ADR049 D2–D3 defines the five states and pins the 2026-08-02 research snapshot digest.
- Official source: `https://render.com/schema/render.yaml.json` (JSON Schema 2020-12, unversioned URL).
- Current handwritten shape starts at `lego/backend/internal/apps/deploy.go`'s `bexManifest` and cannot prove completeness.

## Steps

1. Store the schema with retrieval date/source/digest metadata under the backend Blueprint package.
2. Define the registry format with one entry per field/enum and its semantic handler/fixture pointer; classify the complete snapshot, not only supported fields.
3. Add a local-schema overlay for structured `x-bex` objects without weakening unknown-field rejection.
4. Add an offline exhaustiveness test and a scheduled/manual upstream digest + structural-diff workflow; never auto-update the pin.

## Files

- `lego/backend/internal/apps/schema/**` (new pinned schema + capability registry)
- `lego/backend/internal/apps/*schema*_test.go`
- `scripts/render-schema-drift.sh` (new)

## Acceptance criteria

- [ ] The vendored bytes reproduce the recorded digest and runtime tests require no network.
- [ ] Removing a registry entry or adding an unclassified schema enum fails a focused test.
- [ ] The drift job reports upstream differences but cannot modify the vendored contract.

## Out of scope

- Implementing any field handler; later tasks consume the registry states.
