## Objective

Encryption-at-rest parity (ADR082 D3): disk PVCs use a `hcloud-volumes-luks` StorageClass; the operator mints a random per-disk passphrase Secret referenced by the CSI node-publish parameters.

## Context

- hcloud CSI LUKS support: StorageClass `parameters: csi.storage.k8s.io/node-publish-secret-name/-namespace` → Secret key `encryption-passphrase`; resize is LUKS-aware. Nodes need `cryptsetup` (CAPH image prerequisite — verify, and record the finding in the milestone README if it needs an infra follow-up).
- StorageClass manifest belongs with platform GitOps (`deploy/gitops/`), mirrored to `hcloud-csi` install in `.github/workflows/app-cluster.yml:253-262`; local overlay maps to `local-path` (no LUKS) like `deploy/gitops/overlays/local/kustomization.yaml:144-161` does for `hcloud-volumes`.
- Admission volume grammar must not treat the passphrase Secret as a crown-jewel mount (it is CSI-consumed, never pod-mounted).

## Steps

1. Add the `hcloud-volumes-luks` StorageClass (allowVolumeExpansion true, WaitForFirstConsumer, reclaim Delete) + local overlay patch.
2. Operator: mint `disk-luks-<app>` Secret (random 32-byte passphrase) beside the PVC; ownerRef → App CR; wire the class name into t002's PVC.
3. Confirm `cryptsetup` presence on the CAPH node image; file an infra note if absent.
