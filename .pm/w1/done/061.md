# S3 purge-Job envelope: make the three builders' drift visible

From the 2026-08-19 refactor review (§2.7). `publish.PurgeJob` (`publish/publish.go:479`), `dbBackupPurgeJob` (`database_controller.go:1224`), and `keyValueBackupPurgeJob` (`keyvalue_backup.go:373`) share the identical Job envelope (aws-cli image, `s3 rm --recursive`, `BackoffLimit: 3`, deadline, hash-truncated name, `reconcileCleanupJob` driver) but have drifted: publish has Requests-only + `execution.HardenPod`; the DB one has **no resources at all** (BestEffort pod in a tenant namespace) + `tenantSecCtx`; the KV one has guaranteed resources + `AWS_EC2_METADATA_DISABLED=true` + `HOME=/tmp`.

Two steps, deliberately separate: (1) extract the envelope only — name/namespace/labels/deadline/container in, identical `batchv1.Job` scaffold out; command/env/resources/security stay per-caller so **emitted bytes are unchanged** (~60 lines, LOW risk); (2) a follow-up *behavior decision* on closing the drift table (resource bounds + metadata guard + hardening uniformly) — that one changes emitted pods and needs its own review.
