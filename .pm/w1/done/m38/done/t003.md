## Objective

OpenBao is a 3-member raft with Shamir/manual unseal — every member that reschedules comes up sealed, and its PDB (maxUnavailable=1) stalls a roll until it's unsealed. Write the exact drain-time sequence (drain → member reschedules sealed → unseal with the `.env` keys → wait for raft rejoin → next node) into docs/ADR015-openbao-backup-restore.md (or ADR031) and rehearse it once on a single member.

## Context

- Keys custody: `.env` + GH secrets (docs/ADR019-infra-credentials.md; never print them).
- Quorum survives one member down — the sequence must never have two members sealed at once.

## Steps

1. Document the sequence with the exact `bao operator unseal` invocation shape (no key values) and the rejoin check.
2. Rehearse: delete/reschedule one member pod, unseal, verify raft peers = 3.

## Files

- `docs/ADR015-openbao-backup-restore.md` (or ADR031 §runbooks)

## Acceptance criteria

- [x] Runbook merged; one live rehearsal recorded (member rescheduled → unsealed → rejoined, quorum never lost).

## Out of scope

- Auto-unseal (a separate design decision, not this milestone).
