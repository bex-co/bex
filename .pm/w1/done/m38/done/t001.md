## Objective

Make `hydra-db`, `kratos-db`, `openfga-db` (auth) and `bex-db` (control plane) highly available: `instances: 2`+ with pod anti-affinity so each cluster's replica lands on a different platform node, giving CNPG something to switch over to during a drain.

## Context

- `.pm/w1/done/023.md` (renumbered from `022` on promotion) — the pre-flight evidence (all four single-instance, co-located on `bex-platform-b5tch-lv84c`, PDBs `*-primary` minAvailable=1/allowed-disruptions=0).
- Manifests: `deploy/gitops/` (auth DBs from w4/m1; `bex-db` from w2/m27's backup work — grep for the Cluster resources).
- Platform pool is fixed at min/max 3 nodes: one schedulable node per required-anti-affinity OpenBao member, with enough room to keep each database pair separated.

## Steps

1. Set `instances: 2` + `affinity.podAntiAffinityType: required` (CNPG-native) on each of the four Clusters.
2. Push through Argo; verify each cluster reports 2 ready instances on distinct nodes (`kubectl get pods -o wide`).
3. Confirm a real cordon/drain makes CNPG switch the primary and then permits the eviction. CNPG 1.30's generated primary-only PDB correctly remains `minAvailable: 1` / `disruptionsAllowed: 0` at steady state; role handoff, not a permanently positive counter, is the drain-safety mechanism.
