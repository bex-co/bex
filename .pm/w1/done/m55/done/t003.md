## Objective

Remove public REST paths and payload aliases that are not part of Render's current API, leaving one OpenAPI-validated canonical route per operation.

## Context

- Public aliases include /v1/apps, /v1/databases, /v1/registry-credentials, /v1/webhooks/endpoints, webhook eventTypes, and Postgres /exports.
- Canonical paths are /v1/services, /v1/postgres, /v1/registrycredentials, /v1/webhooks with eventFilter, and Postgres /export.
- lego/backend/internal/store/api.go exposes a separate internal control-plane /v1/apps API on port 8091; it must not be removed accidentally.

## Steps

1. Query available request logs for recent alias use and migrate any repository-owned callers.
2. Refactor canonical handlers so none depend on rewriting requests through a legacy alias.
3. Unregister aliases, delete compatibility payload fields, and add negative route tests.

## Acceptance criteria

- [x] Canonical Render routes retain their current successful behavior and strict request validation.
- [x] Removed public aliases return 404 and removed payload aliases are rejected.
- [x] The internal port-8091 control-plane /v1/apps API and repository scripts that intentionally use it remain green.
- [x] No repository-owned dashboard, script, test fixture, or documentation calls a removed public alias.

## Out of scope

- Internal control-plane route renaming.
- Current Render compatibility fields such as autoDeploy and deprecated response-only env.
