## Objective

Update every workspace-scoped MCP tool to match Render's current explicit workspaceId contract, so routing and authorization are determined by each call rather than by transport-session state.

## Context

- Render's official MCP server changed on 2026-07-27 to add workspaceId to resource tools and deprecate implicit session selection.
- Current bex tools resolve a mix of ownerId, selected session workspace, and caller default through lego/backend/internal/core/workspaceselection.go and feature-local resolvers.
- REST and GraphQL ownerId/workspaceId contracts are not being renamed by this task; only MCP schemas and their shared core invocation are in scope.

## Steps

1. Inventory every workspace-scoped MCP tool under lego/backend/internal and record the official current schema.
2. Add workspaceId consistently, enforce membership and operation authorization, and remove feature-local precedence differences.
3. Update MCP schema and cross-workspace positive/negative tests.

## Files

- lego/backend/internal/\*/mcp.go
- lego/backend/internal/core/
- lego/backend/internal/mcp/
- docs/ADR006-bex-api.md
- docs/ADR018-render-parity.md

## Acceptance criteria

- [x] Every workspace-scoped MCP resource tool exposes the official workspaceId field with the documented optionality.
- [x] An authorized explicit workspaceId targets exactly that workspace; a foreign or unknown id fails closed.
- [x] MCP schema tests detect any tool that omits or misspells workspaceId.

## Out of scope

- Removing the deprecated session-selection subsystem, which is t002.
- Renaming Render REST ownerId parameters or GraphQL arguments.
