## Objective

Close Finding 1 (credential-exposure, CWE-441): repository validation permits arbitrary HTTP(S) Git hosts while clone-token minting extracts only the trailing `owner/repo` path and never requires github.com, so a tenant can point `origin` at an attacker server whose path suffix matches a granted repository and have the build credential helper POST a fresh installation token to that server. Bind the minted token to a verified GitHub origin.

## Context

- `lego/backend/internal/github/service.go:317-347` + `:408-416` — repo match splits `CanonicalRepo(raw)` on `/` and takes the last two segments (`parts[len-2]`, `parts[len-1]`) as owner/repo, discarding the host.
- `lego/backend/internal/store/api.go:587-632` — repository persistence / access decision seam.
- `lego/operator/internal/build/build.go:605-631` — the build Job's `git remote add origin "$REPO"` + credential-helper `fetch` sink that hands `$GIT_AUTH_TOKEN` to whatever host `$REPO` names.
- `lego/operator/internal/publish/publish.go:346-386` — the static-site publish path with the same clone sink.
- Report: report.md Finding 1.

## Steps

1. After canonical URL parsing, require an exact allowlisted GitHub host (`github.com`); reject URL userinfo and non-default ports before any token decision.
2. Carry a server-generated structured repository identity (provider, host, owner, repo) from the store rather than re-parsing an arbitrary clone URL at the credential sink; the operator build/publish sink must dial only the verified host.
3. Mint repository-scoped installation tokens where the GitHub API supports it, so a leaked token is not installation-wide.
4. Add regression coverage (see Acceptance criteria) and confirm the existing build/publish paths for legitimate github.com repos are byte-identical.

## Acceptance criteria

- [ ] A non-GitHub host whose path ends in a granted `owner/repo` suffix (e.g. `https://evil.example/org/repo`) never causes token minting or Secret creation — asserted by test.
- [ ] URLs with userinfo or non-default ports are rejected pre-mint.
- [ ] The operator clone/publish sink receives a verified-host repository identity, not a re-interpreted arbitrary URL.
- [ ] Legitimate `github.com` clone + build + publish paths unchanged; backend + operator suites green.
