## Objective

Close two insecure-default authz gaps.

- **F16 (authorization, CWE-862):** with the control-plane DB enabled but `BEX_OPENFGA_URL` unset, `checkAuthz` returns nil for every relation. Explicit-workspace verbs call `AuthorizeOn`/`AuthorizeOnTarget` with an arbitrary workspace object and bypass the membership-resolving `WithWorkspace` path, so cross-tenant isolation does **not** hold in that mode.
- **F13 (authentication, CWE-287):** login-time invite redemption matches pending invites by the session email unless `BEX_REQUIRE_VERIFIED_INVITE_EMAIL == "1"`, and the default is off — an attacker can register a victim's not-yet-registered invited address and claim its workspace role.

## Context

- `lego/backend/cmd/api/main.go:265-280` — optional OpenFGA wiring.
- `lego/backend/internal/core/base.go:441-449`, `:505-525` — `checkAuthz` returns nil when `b.Authz == nil`; `AuthorizeOn` checks caller-vs-object with no membership resolver behind it.
- `lego/backend/internal/members/service.go:516-524` — an explicit-object verb.
- `lego/backend/cmd/api/main.go:424-432` + `lego/backend/internal/api/tenancy.go:181-212` + `lego/backend/internal/store/members.go:245-254` — invite redemption gated only behind the opt-in flag.
- Report: report.md Findings 16 and 13.

## Steps

1. **F16:** fail startup when the DB-backed multi-tenant API is configured without OpenFGA (or, at minimum, enforce membership for every explicit-workspace verb in the fallback so `AuthorizeOn` cannot bypass isolation). Centralize workspace resolution.
2. **F13:** require a Kratos-verified email for all login-time invite redemption (make the secure behavior the default / fail startup if public registration + invite redemption are enabled without verification); preserve the `?invite=<token>` bearer path as the explicit alternative for un-verifiable addresses.
3. Update `docs/ADR012-auth.md` / `docs/ADR024-members.md` + `.env.example` comments to reflect the fail-closed default.
