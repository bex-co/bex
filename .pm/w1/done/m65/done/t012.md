## Objective

Close Finding 15 (SSRF, CWE-918): the outbound-webhook safe dialer rejects loopback, RFC1918, link-local, multicast, and unspecified addresses via `net.IP.IsPrivate` etc., but Go's `IsPrivate` does not cover RFC 6598 shared address space (`100.64.0.0/10`), so a literal address or a hostname resolving there passes and is dialed. Where cluster/metadata/provider services live in `100.64.0.0/10`, this is a signed-POST + status oracle against them.

## Context

- `lego/types/netutil/ssrf.go:27-83` (esp. `:31-34`) — blocked-address predicate omits `100.64.0.0/10`.
- `lego/backend/internal/webhooks/worker.go:186-201`, `:449-470` — URL source + POST sink using the safe dialer.
- Report: report.md Finding 15.

## Steps

1. Express the block policy as an explicit `netip` prefix deny that includes RFC 6598 `100.64.0.0/10` (and any other non-public / deployment-sensitive range), replacing reliance on the broad std-lib classifications alone.
2. Keep dial-time resolution of all answers and redirect refusal.
3. Cover literals, DNS answers, dual-stack, and IPv4-mapped IPv6 in tests.
