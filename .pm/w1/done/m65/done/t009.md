## Objective

Close two shared-API resource-exhaustion findings (both CWE-400).

- **F8:** the `sandbox_exec` MCP tool concatenates every SSE output event into `stdout`/`stderr` with no cumulative byte limit (each line is capped at 1 MiB, but the number of lines is unbounded), so an authorized tenant command can exhaust the API pod — a cross-tenant DoS.
- **F9:** the GraphQL handler executes caller documents with no depth/alias/field/root-operation/resolver-cost limit, and the rate limiter charges one HTTP request, so a near-limit document can invoke an expensive resolver (e.g. GitHub repo listing) many times.

## Context

- `lego/backend/internal/sandbox/mcp.go:99-102`, `internal/sandbox/exec.go:212-247` — `out.Stdout += ev.Data` / `out.Stderr += ev.Data` grow unbounded.
- `lego/backend/internal/api/server.go:1011-1038` — `graphql.Do(...)` executed with no cost gate.
- `lego/backend/cmd/api/main.go:789-832` — GraphQL handler wiring / rate limiting.
- `lego/backend/internal/github/graphql.go:72-80` — an aliasable provider-backed resolver.
- Report: report.md Findings 8 and 9.

## Steps

1. **F8:** enforce a strict cumulative stdout/stderr byte budget; stop and close the upstream stream at the limit; return truncation metadata (prefer streaming/paginated artifacts for large output).
2. **F9:** parse and reject documents exceeding depth, alias, selected-field, root-operation, mutation, and resolver-specific cost budgets before execution; charge rate limits by computed cost and apply an operation deadline.
