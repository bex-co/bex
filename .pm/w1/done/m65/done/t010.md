## Objective

Close Finding 10 (resource-exhaustion, CWE-400): agent parts have no per-part or per-session byte quota. The gateway reads each SSE data line with unbounded `ReadString`, persists every part into an unrestricted text column, and materializes the complete transcript for replay. Tenant-controlled provider output can exceed the gateway's 256 MiB memory limit or grow shared Postgres without bound — a cross-tenant gateway/DB availability hit.

## Context

- `lego/backend/internal/sshgateway/agentattach/agentattach.go:375-395` — `readSSEData` uses `r.ReadString('\n')` (grows until newline).
- `lego/backend/internal/sshgateway/agentattach/agentattach.go:254-325` — `AgentSessionTranscript(ctx, sessionID, -1)` then frames every stored part (no pagination / byte budget on replay).
- `lego/backend/internal/store/agentsessions.go:208-260` — transcript persistence.
- `lego/backend/internal/store/migrations/0067_agent_session_transcripts.up.sql:20` — unrestricted `text` column.
- Report: report.md Finding 10.

## Steps

1. Enforce a maximum serialized-part size with a bounded line reader (replace unbounded `ReadString`); stop the stream when exceeded.
2. Enforce a per-session total bytes/parts quota at driver, gateway, and DB boundaries.
3. Paginate transcript replay and cap in-memory history instead of materializing the whole transcript.
