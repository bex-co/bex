## Objective

Close Finding 11 (resource-exhaustion, CWE-400): several dashboard SSR mutation handlers call `Request.formData()` / `Request.json()` with no streaming byte limit. The consent handler checks only `Content-Length`, so a chunked or HTTP/2 body without that header is treated as length zero and still fully buffered. Any signed-in account can exhaust the single 256 MiB dashboard replica and disrupt auth/consent UI for others.

## Context

- `dashboard/src/common/server-fn/hydra-consent.ts:279-291` — `Number(request.headers.get("content-length") ?? 0)` gate, then `request.formData()` buffers the actual body regardless.
- `dashboard/src/common/server-fn/hydra-device.ts:78-89`
- `dashboard/src/common/server-fn/kratos-sessions.ts:65-78`
- `dashboard/src/common/server-fn/hydra-connected-agents.ts:112-125`
- Report: report.md Finding 11.

## Steps

1. Add one streaming body-reader helper that aborts after a small route-specific byte cap (reading the stream, not trusting `Content-Length`), then parse the bounded buffer.
2. Route every affected `formData()`/`json()` mutation handler through it; keep `Content-Length` only as an early-rejection fast path.
3. Return 413 on overflow before the full body is read.
