## Objective

Close two client-side auth-transition fail-open gaps.

- **F4 (open-redirect, CWE-601):** the login route accepts any string as `next`; the raw value is used as the Ory return target and later passed as a TanStack Router `href` after login (or when an existing session short-circuits flow creation), so external HTTPS destinations receive the browser right after a trusted auth endpoint.
- **F14 (auth race, CWE-362):** the mobile session manager snapshots the session and awaits refresh; logout clears local state but neither cancels nor invalidates `refreshPromise`, so a resuming stale refresh re-saves tokens and republishes `signedIn` after logout.

## Context

- `dashboard/src/routes/auth.login.tsx:5-9` — `next` accepted unvalidated.
- `dashboard/src/features/auth/pages/login-page/index.tsx:16-52` — `navigate({ to: "/", href: search.next })` external-capable navigation.
- `dashboard/src/common/hooks/use-ory-flow.ts:225-237` — retries without `return_to` but still navigates the raw `next`.
- `mobile/src/features/auth/session-manager.ts:138-190` — refresh publishes without a logout-generation check; `mobile/app/(app)/_layout.tsx:111` routes on `signedIn`.
- Report: report.md Findings 4 and 14.

## Steps

1. **F4:** add one same-origin normalizer at the route boundary — resolve `next` against the app origin, require identical origin, keep only pathname+search+hash, fall back to `/`. Use only the normalized relative value for Ory `return_to` and every navigation branch. Reuse across login/registration/recovery/consent.
2. **F14:** add an auth generation/epoch — increment before logout clearing, capture it + session identity at refresh start, and discard refresh results after every `await` unless both still match; ensure stale failures cannot overwrite newer state.
