## Objective

Close Finding 3 (CI/CD privilege escalation, CWE-269): `infra.yml` runs on `pull_request`, checks out PR-controlled Terraform, exposes the production Hetzner token + SSH key + Terraform-state credentials, queries the cloud API, and runs `terraform plan`. Any same-repo branch contributor can modify Terraform to execute code and exfiltrate those credentials before review. Separate untrusted PR validation from credentialed planning.

## Context

- `.github/workflows/infra.yml:13-18` — `pull_request` trigger on `infra/terraform/**`.
- `.github/workflows/infra.yml:28-69` — job-wide + step-scoped secrets (`TF_VAR_hcloud_token`, `TF_STATE_SECRET_KEY`, SSH key) available to `terraform init` (remote backend) and the authenticated Hetzner request.
- `.github/workflows/infra.yml:158-162` — plan/apply steps; push-only guards protect apply/import but not backend init, the Hetzner request, provider execution, or `plan`.
- Report: report.md Finding 3.

## Steps

1. Make the `pull_request` path a **credential-less** job: `terraform fmt -check`, `terraform validate`, policy checks, and sanitized local state — no cloud token, no remote backend credentials.
2. Move `terraform plan`/`apply` + all production secrets behind a GitHub **protected environment** reached only from reviewed `main` (or a manually approved trusted job), with credentials scoped to individual steps rather than job-wide.
3. Use a trusted-ref check so PR-controlled code never runs with production credentials.
