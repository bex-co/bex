## Objective

Close Finding 5 (CSRF, CWE-352): the GitHub connect state carries only `{Version, WorkspaceID, ExpiresAt}` and the callback is anonymous. The two proofs the flow collects — "an authorized bex workspace started this" (HMAC state) and "this browser administers the installation" (user OAuth `code`) — belong to **different principals** and are individually portable, so an attacker can hand its signed install URL to a victim GitHub org admin and bind the victim's installation to the attacker's workspace. The unique installation→workspace binding added in `w1/m65` then also **locks the rightful workspace out**, making this a denial vector as well as a repository-exposure one.

## Context

- `lego/backend/internal/github/state.go:43-122` — `connectState` + mint/verify (HMAC over the App private key; 15-minute TTL, no nonce, no subject).
- `lego/backend/internal/github/rest.go:46-90` — `GET /v1/git/callback`, deliberately outside the auth gate (`server.go`'s "one exact signed-state callback exception").
- `lego/backend/internal/github/service.go:157-217` — `connectFromCallback` → mandatory `VerifyInstallationAdmin(code, installationID)` → `connectWithWorkspace`, whose uniqueness check is the m65 F2 fix.
- `lego/backend/internal/github/service.go:423-473` — the repository-listing/clone-token sinks that a wrong binding exposes.
- The callback is a **top-level GET redirect**, so `SameSite=Lax` session cookies do arrive — requiring the initiating subject at the callback is feasible without weakening cookie policy (and must not turn the dashboard into an OAuth2 client — see `.pm/DO_NOT_DO.md`).
- Precedent for a durable single-use nonce: the agent-session / web-shell ticket nonce store (`docs/ADR047`, `docs/ADR035`) — reuse the DB-backed single-use mechanism rather than inventing a second one.
- Report: report.md Finding 5.

## Steps

1. Persist a server-side connect transaction at `StartConnect`: random nonce, initiating subject (and session id where available), workspace, expiry, unconsumed flag.
2. Carry only the opaque nonce through GitHub; keep the HMAC state as a cheap pre-check but make the durable row authoritative.
3. At the callback, require the authenticated bex subject to match the transaction's initiator, then **atomically consume** the nonce before persisting the installation; refuse replay and cross-workspace substitution with distinct, non-leaky error codes.
4. Handle the no-session case honestly: bounce to login with a return path back to the callback rather than silently binding.
5. Keep the existing installation-admin proof and uniqueness binding — this adds the missing third leg, it does not replace them.

- [ ] The legitimate single-browser flow still completes end to end, including the dashboard redirect.
- [ ] Error codes distinguish expired / already-consumed / wrong-subject without leaking whether a workspace or installation exists.
