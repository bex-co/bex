## Objective

Close Finding 3 (resource-exhaustion, CWE-400): `webhook_deliveries` is both the durable delivery queue and the permanent dashboard history. Terminal rows (delivered or exhausted) are never reclaimed — the only `DELETE FROM webhook_deliveries` in the tree is the one-shot dedup in migration `0055` — so a tenant with ordinary activity grows shared table, index, and backup storage indefinitely.

## Context

- `lego/backend/internal/store/migrations/0025_webhooks.up.sql:38-66` — the table + `webhook_deliveries_endpoint_idx` history index.
- `lego/backend/internal/store/webhooks.go:452-481` — terminal update path (sets `delivered_at`/`failed_at`, reclaims nothing).
- `lego/backend/internal/webhooks/worker.go:337-350` — the insert side.
- Two existing retention patterns to copy rather than reinvent: `audit.DefaultRetentionDays` + its daily sweep (`internal/audit/service.go:200-240`, `BEX_AUDIT_RETENTION_DAYS`) and `SweepPushRetention` (`internal/store/push_deliveries.go:445`, driven from `notifications/push_worker.go:787`).
- Report: report.md Finding 3.

## Steps

1. Define the policy: age-based retention for terminal deliveries (env-tunable, e.g. `BEX_WEBHOOK_RETENTION_DAYS` with a sane default and a minimum), plus a per-endpoint count cap so a burst inside the window cannot evade age alone.
2. Implement a **bounded batch** sweep (delete in chunks, not one giant statement) on the existing worker's daily cadence, following the push/audit sweep shape.
3. Make it tenant-scoped-safe: the sweep must only remove eligible rows and never touch a delivery still eligible for retry.
4. Confirm the dashboard's delivery history pagination behaves sensibly at the retention boundary (no phantom cursors).
5. Mirror the new env var into `.env.example`, the CLAUDE.md env table, and `docs/ADR006-bex-api.md`.
