# Reconcile `VITE_SSR_API_URL` into the other nine `dev-N` READMEs

Why: `dev-1`'s copy and the command `dev-env.sh` prints are fixed, but `dev-2` … `dev-10` still document a dashboard command that silently breaks every SSR GraphQL query — nine workers will each rediscover the same hour-long red herring.

Found while setting up `dev-1` for an agent-session bug hunt, 2026-08-29.

`dashboard/.env` (untracked, written for `yarn local-bex`) pins
`VITE_SSR_API_URL=http://localhost:8099/graphql`, and a `.env` value wins over a
shell variable that is never set. The documented `dev-N` dashboard command sets
`VITE_API_URL` but **not** `VITE_SSR_API_URL`, so only the **SSR** Apollo client
is left pointing at a port nothing serves.

Symptom (measured in `dev-1`, 9/9 SSR operations): every SSR GraphQL query fails
with `TypeError: fetch failed` / `ECONNREFUSED` — visible as
`apollo_ssr <Op>: fetch failed` in the dev-server log — `loadRouteResource`
dehydrates `{state:"error"}`, and every detail page cold-loads titled
**"Something went wrong"** with an empty content region until
`useLoaderErrorRetry` re-runs the loader client-side. It self-heals, so it reads
as a slow flash rather than a broken environment, which is what makes it
expensive to diagnose.

Already fixed:

- `scripts/dev-env.sh` — the printed command now includes `VITE_SSR_API_URL`, with a comment saying why it is not optional
- `.pm/w1/dev-1/README.md` — both dashboard commands, plus the explanation

Remaining (mechanical): the same two-line change in `.pm/wN/dev-N/README.md` for
N = 2 … 10. Each has two `VITE_API_URL` occurrences and zero `VITE_SSR_API_URL`;
verify with:

```sh
for n in $(seq 1 10); do
  printf 'dev-%s: %s\n' "$n" "$(grep -c VITE_SSR_API_URL .pm/w$n/dev-$n/README.md)"
done
```

Too small for a milestone (~20–30m, one mechanical edit repeated nine times).

Worth considering while there: `dashboard/.env` is untracked, so this bites only
developers who have run `yarn local-bex` at some point — which is why it has
survived. A `dev-env.sh` preflight that warns when `dashboard/.env` sets
`VITE_SSR_API_URL` to something other than this environment's bex-api would stop
it recurring, and is the more durable fix than nine README edits.
