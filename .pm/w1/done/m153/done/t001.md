## Objective

On `/project/<id>`, the selected environment's card and its dialogs survive every `Environments` poll or refetch that runs over cached data. `ProjectEnvironmentCardSkeleton` renders only before the first result arrives, so "All settings", "Manage resources", rename, delete and move keep their open state and drafts.

## Context

- **The gate.** `dashboard/src/features/environments/components/environments-panel.tsx:72` calls `useEnvironments(projectId)` (poll defaults to true). `:194-215` renders `loading ? <ProjectEnvironmentCardSkeleton /> : error ? <p>… : <EnvironmentCard key={selectedEnvironment.id} …/>`.
- **The hook.** `features/environments/hooks/use-environments.ts:103-124` uses `cache-and-network` and `pollInterval: RESOURCE_POLL_INTERVAL_MS` (`:114`), and returns `loading: !resolved || loading` (`:123`).
- **What an unmount loses.**
  - Card state lives at `environment-card.tsx:127-135`.
  - The dialogs mount at `:424`, `:440` and `:448`.
  - The settings form's drafts are at `environment-settings-dialog.tsx:57-67`, and the form is keyed on the ACL at `:35-39`.
- **Precedent rule.** `features/env-groups/hooks/use-env-groups.ts:109-112` returns `loading && data === undefined`.
- **Live evidence.** m153 README § Evidence 1–3.

## Steps

1. **Report first load only.** Return `loading: !resolved || (loading && data === undefined)` from `useEnvironments`. If t004's convention has already landed, use it instead.
2. **Keep the card on errors.** When `selectedEnvironment` exists, render the card even while `error` is set (`errorPolicy: "all"` keeps data), with the error shown inline. Render the error body only when there is no data.
3. **Check every consumer.** Grep `useEnvironments(` and confirm each consumer of `loading` still behaves: the URL canonicalization effect at `environments-panel.tsx:106-112`, and the project and environment selectors on the create forms.
4. **Decide the form's ACL key.** Choose whether a poll that returns a changed ACL should still remount the settings form (`environment-settings-dialog.tsx:35-39`), for example when a teammate changed it. Record the choice in a code comment. The dialog itself must stay open either way.
