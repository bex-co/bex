## Objective

The Disk usage chart shows **"No data in range"** for a real, attached 1 GB disk. That is the expected look while kubelet volume-stats warm up — and also exactly what a broken PVC-name match looks like. The two must be told apart with evidence rather than assumed.

## Context

- Observed live 2026-08-24 on `srv-da52hdj8ptnc73bm4un0` (`/var/data`, 1 GB, disk newly attached).
- Suspect path if broken: `lego/backend/internal/metrics/datastore.go`'s `kind="service"` branch, which builds `^<QuoteMeta(DiskPVCName(name))>$`. Both sides derive the name from `appv1alpha1.DiskPVCName`, so a mismatch would be a Prometheus-label or namespace problem rather than a naming drift.
- The series is `kubelet_volume_stats_{used,capacity}_bytes`, already scraped cluster-wide for the PersistentVolumeFillingUp alert.

## Steps

1. Query Prometheus directly for the disk's PVC and confirm whether the series exists at all.
2. If it exists, compare the exact label values (`namespace`, `persistentvolumeclaim`) against the matcher bex-api builds.
3. Fix whichever half is wrong; if the series simply had not been scraped yet, say so and re-check after it has.
