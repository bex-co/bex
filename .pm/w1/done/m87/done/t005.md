## Objective

On production the Snapshots card reads **"Snapshots are unavailable / internal error"**. A 503 that means "this feature has not been configured" must not reach a tenant as "internal error" — it reads as a fault in their service, invites a support ticket, and is simply untrue.

## Context

- Verified live on dashboard.bex.co 2026-08-24 against a real 1 GB disk.
- Source: bex-api answers 503 when `BEX_DISK_SNAPSHOT_*` is unset (`lego/backend/internal/apps/disk_snapshots.go`); the dashboard renders `error.message` verbatim (`dashboard/src/features/services/components/disk-section.tsx`, SnapshotsCard).
- Note this state should become rare once t002 lands, but the message must still be right: a self-hosted operator who has not wired a bucket will see it, and that is the audience it must speak to.

## Steps

1. Give the unconfigured case a distinct, named error code at the API rather than a generic 503 body, so the dashboard can branch on identity instead of on message text.
2. Render a calm not-configured state naming what is missing and who fixes it — the operator, not the tenant.
3. Keep a genuine backend failure visibly distinct from "never configured".
