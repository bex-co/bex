## Objective

No purger stops a deleted workspace's running OpenSandbox sandboxes — the wired list (`cmd/api/main.go:356-361`) is secrets, envgroups, postgres, keyvalue, apps. The `<ws>-sandbox` namespace prune reaps the pods only when `BEX_TENANT_SANDBOX_NAMESPACES` is enabled, and the OpenSandbox control-plane records linger either way. Add a `sandbox.WorkspacePurger` that lists and stops the workspace's sandboxes through the OpenSandbox client, wired only when the sandbox feature is enabled.

## Context

- `lego/backend/internal/sandbox/client.go` — the OpenSandbox lifecycle client (list/stop already exist for the `/v1/sandboxes*` verbs); the per-workspace key comes from `sandboxKeyProvider` (`cmd/api/main.go:101-109`).
- Ordering (from t001): the purger needs the workspace's tenant key to authenticate to OpenSandbox, and `sandbox_tenant_keys` cascades with the row after t002 — so this purger must run in the **pre-cascade** phase.
- `workspaces.WorkspacePurger` contract (`internal/workspaces/service.go:143-149`): idempotent; already-gone sandboxes are a no-op.
- Feature gate: wire only when `BEX_OPENSANDBOX_URL` is set, mirroring how the sandbox feature itself registers.

## Steps

1. Implement `PurgeWorkspace` in `internal/sandbox`: resolve the workspace key, list its sandboxes, stop each; tolerate NotFound/already-stopped; surface transport errors (t001 makes them retryable).
2. Wire into `deps.WorkspacePurgers` in `cmd/api/main.go` behind the sandbox feature gate, in the pre-cascade phase.
3. Unit test with a fake OpenSandbox client: delete stops all sandboxes; NotFound tolerated; a transport error propagates (and the workspace row survives for retry, per t001).
