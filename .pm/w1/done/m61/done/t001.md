## Objective

A purger failure during workspace delete must leave the delete retryable end-to-end. Today `Delete` (`lego/backend/internal/workspaces/service.go:712-760`) reads `GetTenant` (for the `sudo delete workspace <name>` confirmation phrase) _before_ `DeleteTenant`, and the purgers run _after_ — so once the row cascade lands, a retry 404s at `GetTenant` and can never reach the purgers again, despite the doc comment promising re-runnability. A transient OpenBao/k8s failure permanently orphans `Database` CRs (live CNPG cluster + PVCs + S3 backups), `KeyValue` CRs, OpenBao secret paths, and env groups.

## Context

- Current order: authorize → `GetTenant` → confirmation check → revoke OpenFGA tuples → `DeleteTenant` (FK cascade) → `Kick()` (projector prune) → purgers (`s.Purgers`, wired at `cmd/api/main.go:356-361`).
- **Do not naively move the apps purger before `DeleteTenant`**: the rows→App-CR projector re-creates App CRs from still-live `apps` rows. App CRs are the one class with a second net (projector prune after the cascade + `Kick()`); the resurrection-free purgers (secrets, envgroups, postgres, keyvalue) have no such net and can safely run pre-cascade.
- t004 (Stripe) needs the billing lifecycle rows (Stripe customer/subscription ids, migration 0051) read **before** the cascade drops them — a second argument for a purge-before-delete (or pre-read) shape. Design the phase split so t003/t004's new purgers have a correct place to hook (e.g. explicit pre-cascade vs post-cascade purger phases).
- Keep the confirmation semantics and the admin-only `can_manage` guard unchanged.

## Steps

1. Decide the ordering: split purgers into a pre-cascade phase (secrets, envgroups, postgres, keyvalue — idempotent, non-resurrectable) and a post-cascade phase (apps), or an equivalent design (e.g. a `deleting` tombstone) that preserves end-to-end retryability.
2. Implement in `workspaces.Service.Delete`; update the purger wiring in `cmd/api/main.go` if the interface grows a phase.
3. Update the `Delete` doc comment to describe the real retry semantics.
4. Unit test: fail a pre-cascade purger once → `Delete` returns the error and the tenant row still exists → retry the same call → teardown completes, nothing orphaned.
