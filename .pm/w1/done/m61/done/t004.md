## Objective

Nothing in `internal/billing` reacts to workspace delete: the local billing rows cascade with the tenant row (migration 0051), but the metered Subscription stays active at Stripe against a metadata-keyed Customer whose workspace no longer exists. Cancel the active Subscription at delete time; keep the Customer (its invoice history must remain readable — Stripe's guidance is cancel, don't delete).

## Context

- `docs/ADR040-billing-metronome.md` — the Stripe integration shape; env-gated on `BEX_STRIPE_SECRET_KEY` (unset ⇒ no Stripe client, and this teardown must be byte-identical no-op).
- Ordering (from t001): the Stripe customer/subscription ids live in the billing lifecycle rows that the tenant-row cascade drops — this purger must run in the **pre-cascade** phase (or the ids must be read before `DeleteTenant`).
- Cancellation semantics: immediate cancel (`cancel_now`) with a final invoice for any un-invoiced metered usage; already-cancelled/missing subscription is a no-op (idempotent, per the `WorkspacePurger` contract). The emitter's outbox rows (`billing_export_operations`) cascade — verify no in-flight export races the cancel (the sealed-row export horizon `BEX_STRIPE_SEAL_HOURS` means recent usage may never export; note the accepted loss in the ADR or flush before cancel).
- Test via `BEX_STRIPE_API_URL` stub, as the existing billing tests do.

## Steps

1. Implement a billing `WorkspacePurger` (`internal/billing`): look up the workspace's Stripe subscription id from the lifecycle rows, cancel it immediately, tolerate already-cancelled/absent; leave the Customer.
2. Wire into the pre-cascade purger phase in `cmd/api/main.go`, only when Stripe is enabled.
3. Decide + document the in-flight meter-event/final-invoice behavior (flush vs accepted loss) in ADR040.
4. Stub-Stripe test: delete cancels the subscription; retry after transport failure completes; `BEX_STRIPE_SECRET_KEY` unset ⇒ no network, no purger wired.

## Acceptance criteria

- [ ] Workspace delete cancels the workspace's active Stripe Subscription (stub-Stripe test asserts the cancel call).
- [ ] Customer is retained; no Customer-delete call is ever made.
- [ ] Stripe disabled ⇒ byte-identical delete behavior (no wiring, no network).
- [ ] Idempotent: already-cancelled subscription or missing lifecycle row is a no-op.
