# 098 — Seven count strings still break the native-plural rule `w6/done/062` established; the Blueprint review reads "1 resources to sync"

> **Promoted 2026-09-15 → `w1/m159`** by user decision during the w1 triage. The milestone carries the fix, its tests and its live verification.

Why: `062` made `_one`/`_other` the one convention and retired the `(s)` hatch, but its sweep missed these strings. Nothing in the locale tests notices a `{count}` message that has no plural keys, so "1 resources" ships and the next feature copies whichever style it sees first.

- **Severity:** minor (copy).
- **Found:** live `/qa-find-bugs`, 2026-09-14 pass 26, on `/blueprints/new` with `bex-co/bex` `main`:
  - Path `examples/cron-demo/render.yaml` (and `examples/hello-go/render.yaml`): the review reads `Blueprint file parsed successfully — 1 resources to sync.`
  - Control: `examples/stack-demo/render.yaml` reads `3 resources to sync.`

## The seven

A scan of every `dashboard/src/features/*/locales/en.ts` for keys whose message holds `{count}` but that have no `_one`/`_other` suffix found 14 hits. Seven break the rule:

| key (en line) | message | call site |
| --- | --- | --- |
| `blueprints.previewValid` (`blueprints/locales/en.ts:139`) | `Blueprint file parsed successfully — {count} resources to sync.` | `blueprint-plan-summary.tsx:45-47` (**seen live**) |
| `agentSessions.showEarlierMessages` (`agent-sessions/locales/en.ts:644`) | `Show {count} earlier messages` | `session-conversation-impl.tsx:403` |
| `git.repoCount` (`git/locales/en.ts:144`) | `{count} repos` | `git-credentials-menu.tsx:218` |
| `envGroups.serviceCount` (`env-groups/locales/en.ts:160`) | `{count} linked service(s)` | `routes/env-groups.tsx:220-222` |
| `services.scaleSuccess` (`services/locales/en.ts:2961`) | `Scaling to {count} instance(s)…` | `use-scale-service.ts:20` |
| `envGroups.varCount` (`env-groups/locales/en.ts:152`) | `{count} variable(s)` | none (dead key) |
| `envGroups.fileCount` (`env-groups/locales/en.ts:156`) | `{count} secret file(s)` | none (dead key) |

The other seven are correct as they are, because they are label counts with no noun agreement:

- `git.credentialsTrigger` "Credentials ({count})"
- `projects.selectedCount` "Selected: {count}"
- `services.eventsFilterSelected` "Filter events ({count})"
- `services.envGroupsLinkedCount` "Linked ({count})"
- `services.envGroupsAvailableCount` "Available to link ({count})"
- `webhooks.showMore` "Show {count} more"
- `usage.resourceCapsFinishingDeletion` "{count} finishing deletion"

## Why it slipped

- **The sweep missed them.** All seven predate `062`'s resolution (`4375efb29`, 2026-09-04). They landed between 2026-07-12 (`services.scaleSuccess`, `7e928938b`) and 2026-08-29 (`git.repoCount`, `d440a5db7`). `062`'s table came from a search for hard-coded plural nouns, and its `(s)` retirement covered only projects and environments. This is a residual, not a regression.
- **The tests don't look.** `dashboard/src/i18n/__tests__/locale-parity.test.ts:54-90` enforces `_one`↔`_other` pairing and zh's single form. It never checks that a `{count}` noun phrase uses plural keys at all.

## Fix (~40m)

- **Migrate the five live keys** to `key_one` + `key_other` in `en`, and `key_other` only in `zh`, per `dashboard/CLAUDE.md:133` and `src/i18n/__tests__/plurals.test.ts`. Their zh keys are `blueprints.previewValid` (`blueprints/locales/zh.ts:137`), `agentSessions.showEarlierMessages` (`:627`), `git.repoCount` (`:142`), `envGroups.serviceCount` (`:157`) and `services.scaleSuccess` (`:2903`).
- **Delete the two dead keys** `envGroups.varCount` and `envGroups.fileCount` from both `en` and `zh`.
- **Add a guard** to `locale-parity.test.ts` or a sibling test. Any `en` message containing `{count}` must be a `_one`/`_other` key unless it is allowlisted as a label form (the seven above), so the next "1 things" fails CI.
- **Unverified:** only the Blueprint string was observed live. The other four call sites, and whether `repoCount` / `serviceCount` can reach 1 in practice, were read from code.
