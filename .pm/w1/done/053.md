# 053 — Manager defaults `BEX_RUNTIME` to the untested opensandbox path

From the 2026-08-19 architecture survey ([Bex Refactor Ledger](https://claude.ai/code/artifact/5ceae798-6df1-4f3c-94b6-6b1126f640c2) §0). `lego/operator/cmd/manager/main.go:328` defaults an **unset** `BEX_RUNTIME` to `ModeOpenSandbox` — the legacy host runtime (`lego/operator/internal/runtime/opensandbox.go`, 221 lines, **zero test files**) that production never runs: `config/manager/manager.yaml:108` sets `kubernetes`, and all four verification scripts (`scripts/events-verify.sh:155`, `dashboard-env-verify.sh:96`, `name-conflict-e2e.sh:149`, `secrets-verify.sh:111`) force `kubernetes`. With the opensandbox default, `convergeRegistryCredentials` is silently skipped (`internal/controller/app_controller.go:487` early-returns when mode ≠ kubernetes) and deploys route to the untested path — a foot-gun for any operator invocation that forgets the var.

**Fix.** Flip the default to `ModeKubernetes`. Grep for anything relying on the old default (the legacy `scripts/up.sh` / `start-opensandbox*.sh` path is already broken — `up.sh:29` cd's into a directory that no longer exists — so nothing live should depend on it); update the CLAUDE.md env-table row if it implies a default.

**Out of scope here:** deleting the opensandbox runtime entirely (`internal/runtime`, `reconcileOpenSandbox` at `app_controller.go:2895`, the `Mode` branches). That's a larger removal decision — worth its own item if the user confirms the runtime is dead.

**Acceptance:** a test asserting that with `BEX_RUNTIME` unset the manager resolves `ModeKubernetes`; `make test` green from `lego/operator/`.
