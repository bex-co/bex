## L4 — resolved: keep the label-scoped admission posture

The proposal was to widen `lego/operator/config/webhook/manifests.yaml` from
the `app.bex.co/verify-image: enabled` objectSelector to a namespaceSelector
fail-closed posture over the apps namespace, so enforcement would not rest on
tenants lacking pod-create RBAC. Two findings from the 2026-07-20 pass closed
it as **not worth doing**:

1. **The threat-model boundary shows the label design is correct, not a gap.**
   The signature scheme defends ONE thing: the integrity of images **bex
   itself built** (git → build Job → cosign sign → Zot). Its attack is
   registry-content tampering — swap the image behind a tenant's tag, wait for
   a pod reschedule. In that attack the pod is still created by the operator's
   own Deployment/Job templates, so the label **always travels with it** and
   verification always fires; the attacker holds the registry, not the pod
   spec. The only actor who could omit the label is one who can already write
   pod specs in the apps namespace — and that actor can run any arbitrary
   external image, making signature enforcement moot. Flipping to
   namespace-wide enforcement is using the registry-integrity door to guard
   the RBAC door; it adds ~nothing against the failure it targets. The
   invariant that actually carries the load — **tenants have no pod-create
   RBAC in the apps namespace** — is what security sweeps must keep asserting
   (docs/ADR028-security-review.md).
2. **The flip's real cost is a new platform-level single point.** Code-level
   enumeration of every pod kind landing in the apps namespace: tenant-image
   pods (web/worker Deployments, CronJobs, pre-deploy Jobs, publish extract —
   labeled when signing is on) coexist with **unsignable platform-image pods**
   — CNPG Postgres instances (`database_controller.go:499`), Valkey
   StatefulSets (`keyvalue_controller.go:369`), DB-backup and static purge
   Jobs, publish upload containers (`amazon/aws-cli`). With
   `failurePolicy: Fail` scoped namespace-wide, every one of those creations —
   including CNPG failover, the data-availability path — would depend on
   webhook + Zot + registry-credential health (verification is a network
   fetch; the m53 M1 SSRF fix hardened exactly this path). Today that
   dependency binds only labeled tenant pods, which is the right blast
   radius.

Prefix-boundary bypass at the image-name layer stays covered by the m53 M1
fix (`internal/webhook/pod_admit.go` `/`-boundary match). If the RBAC
invariant ever changes (tenants gaining any pod-write path), revisit — the
enumeration table above is the starting point.
