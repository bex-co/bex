## Objective

Wire real ephemeral Postgres and OpenFGA service containers into the backend test workflow so the tests gated behind `BEX_TEST_DB_URI`/`BEX_TEST_OPENFGA_URL` actually run in CI, instead of permanently skipping (as they have on every run to date, in every environment — no workflow has ever set these vars).

## Context

- Found via codebase survey: `internal/deploys/live_acceptance_test.go`, `internal/postgres/query_test.go`, `internal/store/store_pg_test.go` (multiple), `internal/api/workspaces_e2e_test.go` all `t.Skip(...)` without these env vars.
- GitHub Actions `services:` blocks can run a `postgres` container directly (standard pattern); OpenFGA has an official Docker image (`openfga/openfga`) that can run as a service container too, migrated/configured at job start.
- `BEX_TEST_DB_URI` shape and `BEX_TEST_OPENFGA_URL` shape should match whatever the test files themselves expect — read the skip conditions to confirm the exact env var names and connection-string format expected.

## Steps

1. Add a `postgres:16` (or whatever version the CNPG-based prod stack uses) service container to the backend test job, with `BEX_TEST_DB_URI` set to point at it.
2. Add an `openfga/openfga` service container, run its migration step, and set `BEX_TEST_OPENFGA_URL`.
3. Confirm the previously-skipped tests now run and pass (or reveal real, previously-hidden issues — if so, note them, don't silently paper over).
