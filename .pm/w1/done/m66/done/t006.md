## Objective

Close Finding 16 (unverified-code, CWE-494): the etcd and OpenBao backup CronJobs run tag-only images and `apk add --no-cache age` at runtime, in stages that share a volume holding the raw etcd/OpenBao snapshot and mount the S3 credentials. The sharp edge is the runtime package install in the **pre-encryption** stage: a package-repository or tag mutation lands executable code next to the plaintext snapshot before ADR050 encryption happens.

## Context

- `deploy/gitops/charts/etcd-backup/cronjob.yaml:47-100` + `:122-133` — `registry.k8s.io/etcd:3.6.8-0`, `busybox:1.37`, `alpine:3.21`, `amazon/aws-cli:2.22.35`, plus `apk add --no-cache age`.
- `deploy/gitops/charts/openbao-backup/cronjob.yaml:50-98` + `:116-124` — same shape.
- `docs/ADR050-encrypted-platform-backups.md` — the age-encryption design these stages implement (`BEX_BACKUP_AGE_PUBLIC_KEY` / the `bex-backup-age` ConfigMap).
- `docs/ADR031-platform-data-backup.md` — the backup policy and restore runbooks these CronJobs back.
- Report: report.md Finding 16.

## Steps

1. Remove `apk add` from both charts: obtain `age` without a runtime package manager — an image that already ships it, or a release artifact verified against a **repository-pinned** SHA-256 recorded in chart values (a reviewed digest in git, not a same-origin checksum fetched at run time).
2. Digest-pin every backup image (`repo:tag@sha256:…`), keeping the human-readable tag for readability, and resolve the digests against the live registries.
3. Keep the chart's values-level overrides working (`image` / `tag` / `digest`) so an operator can still roll an image without editing templates.
4. Verify the rendered manifests (`helm template`) contain no un-digested image and no runtime package install; keep the existing kustomize/gitops render tests green.
