# A static site's Confirm Rollback page compares the build's environment, as Render's does

Why: since w1/m646 a static site's Confirm Rollback page always says "Unable to load configuration for the current live deploy…", because bex keeps no record of the environment a static build used, while Render lists the env var, secret file and env group changes in its static wording.

- **Render** (`DeployContainer-*.js`, docs/render-artifacts/rollback-comparison.md § The comparison): a static site's snapshot has env vars, secret files and env groups, and its Environment Group row reads "The rollback will not use environment group **X** which was added to the site after this build", "This build used **N** environment groups that have since been deleted. The rollback will use their original values", "The rollback will use the original values for environment groups used for this build."
- **bex today:** `lego/backend/internal/deploys/rollback_comparison.go` returns null snapshots for a `static_site` (its releases write only `StaticPublicationRecordName`, a prefix). `dashboard/src/features/deploys/components/rollback-comparison.tsx` has no static wording.
- **Work:** have the operator record the build's env sources per static release (the same per-source copies or a key/hash record the Deployment path keeps, ADR004 § Per-release configuration snapshots), compare them in `RollbackComparison`, and add Render's static sentences in all 8 locales.
- **Done when:** on a static site whose env var, secret file and linked group changed after a deploy, Rollback on that deploy lists each change in Render's static wording, with no value in the page or the GraphQL response.

- Promoted to [w1/m660](../blocked/m660/README.md) on 2026-11-26 by `/pm` (from `/pm-brainstorm one aspect of render parity to w1`). Verified first: `lego/backend/internal/deploys/rollback_comparison.go:155` still returns before any snapshot for a static site, and Render's `DeployContainer` still carries the static Environment Group sentences ("…which was added to the site after this build"). More than an hour of work across the operator, the comparison and the page, so a milestone.
