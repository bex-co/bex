## Objective

GraphQL `Service.id` returns `AppView.Name` today (`internal/apps/graphql.go:256`) — the last service surface not speaking the minted `srv-` id (REST and MCP already do; the pagination cursor at `graphql.go:706` already keys on `AppView.ID`). Flip the resolver to `a.ID` and audit every GraphQL service verb and nested type for id round-trip consistency.

## Context

- `AppView.ID` = `publicID(a)` (`internal/apps/service.go:755`): the `LabelAppID` srv- id, falling back to the App name for legacy hand-applied CRs — so the flip degrades identically for legacy resources.
- Acceptance is already dual: `core.Base.AuthorizeApp`/`GetApp` resolve an exact `LabelAppID` first, then `LabelServiceName` (`internal/core/base.go:467`), so verbs taking the new id keep working, and old name args too.
- Audit the round trip: every GraphQL field/arg that names a service (`server(id)`, lifecycle mutations, `deploys(serviceId)`, events, cron runs, env/secret-file verbs, logs) must accept what `Service.id` now emits — they all funnel through the same seam, but PIN it (extend the cross-surface tests) rather than assume.
- Out of scope but note: `Domain.id` returns the name (`graphql.go:516`) — `w1/028`.

## Steps

1. `graphql.go:256` → `return a.ID`.
2. Sweep `internal/apps/graphql.go` (+ deploys/events/logs GraphQL fragments) for sibling emitters of service identity; align any that emit `Name` as an id-typed field (leave `name`/display fields alone).
3. Extend the apps GraphQL tests: `server(id: <srv-id>)` round-trips; a mutation on the srv- id mutates the same App the name reaches.
