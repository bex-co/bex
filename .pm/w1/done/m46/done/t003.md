## Objective

Old name-shaped URLs (`/services/whoami/logs`, bookmarks, emails, older CLI captures) and legacy hand-applied Apps without `LabelAppID` must keep resolving — the `AuthorizeApp` srv-first/name-fallback seam already guarantees it; PIN the guarantee with tests so a future resolution change can't silently break it.

## Context

- `core.Base` resolution order (`base.go:467`): exact `LabelAppID` → `LabelServiceName` candidates (workspace-authorized). `publicID` falls back to the App name when `LabelAppID` is absent.
- Cases to pin: (a) GraphQL `server(id: "<name>")` on a store-managed App still resolves; (b) a legacy App with no `LabelAppID` emits its name as `id` and resolves by it; (c) name collision across workspaces still authorizes per the existing collision-fallback tests (don't duplicate those — reference).

## Steps

1. Backend tests for (a) and (b) beside the t001 round-trip tests.
2. Dashboard: one route-level test that `/services/<name>/logs` renders the same service (the shell resolves via `useServer(name)` — server-side fallback carries it).
