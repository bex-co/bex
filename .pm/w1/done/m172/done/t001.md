## Objective

When a rollout settles failed over a release that has served, put the Deployment back on the served release's pod template so a later wake/resume/scale starts working pods instead of the failed ones.

## Context

- `lego/operator/internal/controller/app_controller.go:3026-3036` `settleFailedRolloutMessage` (prior-release branch), `:2229` `applyServingDeployment`, `:2207`/`:5404` `holdUnpassedRelease` (m156, pre-deploy only).
- `lego/operator/internal/controller/release_config_snapshot.go:463-484` `servedPodTemplateForCancel` (w1/m152) — recorded served template in the `ReleaseRecordName` Secret.
- Evidence: `.pm/w8/done/m44/README.md` adjacent observation 1.

## Steps

1. Generalise the cancel-path served-template restore to the failed-rollout settle (and to every later reconcile while the failed generation is current), so `applyServingDeployment` writes the served template.
2. Missing record: scale the prior ReplicaSet or settle Failed — never leave the failed template behind a Running phase.
3. Make sure a later config change or new deploy still rolls the saved config normally (no stuck hold).
