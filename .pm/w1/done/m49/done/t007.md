## Objective

Eliminate the footgun class the webhook modal bug exposed: `max-h-*` on the shadcn `ScrollArea` **root** does not constrain the Radix Viewport (`size-full` inside an auto-height root), so lists render full height with no scrolling and can overlap/intercept elements below. Sweep every dashboard `ScrollArea` usage, fix affected call sites, and make the primitive safe by construction.

## Context

- Mechanism (measured live 2026-07-17 on `dashboard.bex.co/webhooks`): `create-webhook-dialog.tsx:149` — `<ScrollArea className="max-h-56 …">`; the component (`dashboard/src/common/components/ui/scroll-area.tsx:12-22`) puts the caller's classes on `ScrollAreaPrimitive.Root` while the Viewport is `size-full`. With only a max-height on an auto-height root, the viewport's percentage height resolves against auto → content height → no scroll containment. Result: the 17-row events list rendered ~680px tall, overflowed the dialog (rows to y≈1209 vs dialog bottom y≈839), and the `maintenance_mode_enabled` row hit-test-intercepted the Create button at y≈778 — clicking Create toggled a checkbox instead of submitting.
- The offending call site dies with t003 (modal deleted), but the primitive still invites the same misuse anywhere else.
- Fix options (pick one, apply consistently): forward height classes to the Viewport (e.g. accept a `viewportClassName` or route `max-h-*` via `[&>[data-slot=scroll-area-viewport]]:` selectors), or document-and-enforce fixed `h-*` on the root. Prefer making the primitive correct over per-call-site care.

## Steps

1. `grep -rn "ScrollArea" dashboard/src --include="*.tsx"` and classify each usage: fixed height (fine) vs `max-h-*`-on-root (broken containment).
2. Fix the primitive so max-height containment works (viewport-level constraint), or convert affected call sites to a working pattern; keep visual behavior of healthy call sites byte-identical.
3. Add a regression test asserting a tall child inside a constrained ScrollArea produces a scrollable viewport whose height respects the constraint (jsdom-level: assert the class/style lands on the viewport element).
