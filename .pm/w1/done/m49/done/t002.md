## Objective

Build the Render-shaped event picker as a reusable component under `dashboard/src/features/webhooks/`: human-readable labels in collapsible groups, a search box, a tri-state "All events" master checkbox, group-checkbox cascade, and a live "N events selected" counter. Shared by the t003 create page and the t005 Settings tab.

## Context

- The backend vocabulary is 17 raw snake_case keys served by the `webhookEventTypes` GraphQL query (`lego/backend/internal/webhooks/service.go:85-103`); there is **no** label/group metadata on the API — grouping and labels are presentation, so a dashboard-side mapping fits ADR006's thin-adapter rule.
- Mapping (from t001's artifact, Render's grouping applied to bex's 17 keys): Deploy → deploy_started/deploy_ended; Cron Job Run → cron_job_run_started/cron_job_run_ended; Maintenance Mode → maintenance_mode_enabled/maintenance_mode_uri_updated; Postgres → postgres_created/postgres_restarted/postgres_credentials_created/postgres_credentials_deleted/postgres_backup_started; Suspension → service_suspended/service_resumed; ungrouped singles → server_restarted ("Server Restarted"), instance_count_changed, autoscaling_config_changed, plan_changed (bex's analogue of Render's "Instance Type Changed" — label it "Plan Changed").
- Unknown keys the backend may add later must degrade gracefully: render under an "Other" group with the raw key as label — never crash, never hide.
- Current flat list lives in `dashboard/src/features/webhooks/components/create-webhook-dialog.tsx:142-170`; the event types hook is `use-webhook-event-types.ts`.
- Tri-state semantics (observed live on Render): master shows checked/mixed/unchecked; group checkbox cascades to all children (checking "Deploy" selected all 8 child events); counter updates immediately ("8 events selected").
- Dashboard conventions: every string through `useTranslations()` with `webhooks.*` keys in `features/webhooks/locales/{en,zh}.ts`; shadcn primitives (`Checkbox`, `Collapsible`/chevron buttons, `Input`).

## Steps

1. Add `event-catalog.ts` (label + group mapping keyed on raw event type, with the Other-group fallback) and unit-test the fallback.
2. Build `event-picker.tsx`: controlled `Set<string>` value/onChange, search filter (matches label and raw key), groups with expand/collapse, group cascade, tri-state master, selected counter.
3. Contain the list height correctly — a fixed-height scroll viewport, not `max-h-*` on a ScrollArea root (see t007's mechanism note).
4. i18n all strings (group names, "All events", "{n} events selected", "Search for events").

## Acceptance criteria

- [ ] All 17 backend keys render with human labels in their groups; a fabricated unknown key renders under "Other" with its raw key.
- [ ] Group check/uncheck cascades; master reflects none/some/all as unchecked/mixed/checked; counter matches the selection size.
- [ ] Search narrows by label or raw key; clearing restores the full tree.
- [ ] List scrolls inside a genuinely constrained viewport (no footer overlap possible).
