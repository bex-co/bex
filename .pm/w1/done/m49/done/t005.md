## Objective

Wire the dashboard's first webhook **edit** surface: a Settings tab on `/webhook/$id` with a Status toggle, editable Name/Endpoint URL, the t002 event picker with "Save changes", and Render's type-to-confirm delete — all over backend verbs that already exist.

## Context

- The backend update verb has been live since w3/m11 and the dashboard never wired it: GraphQL `updateWebhookEndpoint(id, ownerId, name, url, eventTypes, eventFilter, enabled)` (`lego/backend/internal/webhooks/graphql.go:139-162`) → `service.Update` (service.go:437-476, re-validates URL + normalizes event types) → store `UpdateWebhookEndpoint` (store/webhooks.go:169-181). REST `PATCH /v1/webhooks/{id}` and MCP `update_webhook_endpoint` are the same verb — no backend work in this task.
- Render's Settings shape (t001 artifact): General section — Status toggle ("Webhooks do not send any notifications while disabled."), Name, Endpoint URL, Signing secret (t006 decides bex's treatment); Subscribed Events section with the picker and a "Save changes" button disabled until dirty; Delete Webhook at the bottom with a confirm dialog requiring the literal text `delete webhook <name>`.
- Existing hooks: `use-create-webhook.ts` pattern for the new `use-update-webhook.ts`; `SetWebhookEndpointEnabled` and `DeleteWebhookEndpoint` mutations already exist in `webhooks.graphql` — the Status toggle keeps using `SetWebhookEndpointEnabled` (matches the list row), or folds into update; pick one and note it.
- Delete currently uses a simple confirm `alertdialog` on the list row; the detail Settings gets the type-to-confirm variant. Keep the list-row delete consistent (either navigate to Settings or reuse the same confirm component).

## Steps

1. Add `UpdateWebhookEndpoint` mutation to `webhooks.graphql` + `use-update-webhook.ts`; refresh list/detail caches on success.
2. Build the Settings tab: General fields + Status toggle, event picker prefilled from the endpoint's subscription, Save changes disabled until dirty, toasts on success/failure.
3. Type-to-confirm delete component (`delete webhook <name>` exact match gates the destructive button); on delete navigate to `/webhooks`.
4. i18n everything.

## Acceptance criteria

- [ ] Renaming, changing URL, and changing the event subscription each round-trip: save, reload, values persist (backed by the live `updateWebhookEndpoint`).
- [ ] Invalid URL and empty event selection surface the backend's named errors, not a silent failure.
- [ ] Status toggle disables/enables delivery state identically to the list-row switch.
- [ ] Delete only proceeds after typing `delete webhook <name>` exactly; lands on `/webhooks` with the endpoint gone.
