## Objective

Add the per-webhook detail page at `/webhook/$webhookId` (Render's exact singular path) with the header parity block and an Activity view of deliveries; retire the delivery-history modal.

- Backend reads already exist: GraphQL `webhookEndpoint(id, ownerId)` and `webhookDeliveries(endpointId, ownerId, cursor, limit)` (`lego/backend/internal/webhooks/service.go:90-110`); the dashboard's `webhooks.graphql` already defines `WebhookDeliveries` — only the get-by-id query may need adding to the dashboard's `.graphql` file.
- Render's header (t001 artifact): "Webhook" kicker, name + Enabled badge (badge links to settings), "Webhook ID: whk-…" + copy, endpoint URL link + copy, subscribed-event chips with "Show N more" collapse, "Created by <email> on <date>". Show created-by/date **only if** EndpointView already exposes them — do not grow the API for it (milestone non-goal; record the divergence in the artifact).
- Render's Activity: "Recent deliveries" table, All/Successful/Failed tabs, manual refresh affordance, empty state. bex's delivery rows already carry success/status data (the current modal renders them); filter client-side first — no backend filter param in this milestone.
- Current delivery-history modal lives in the webhooks feature (triggered from the list row, `webhooks-panel.tsx`); it retires here, with the row action becoming a link to the detail page.
- Route naming: `webhook.$webhookId.tsx` (+ child routes or in-page tabs for Activity/Settings — follow `services.$serviceId` shell precedent with a small tab nav; Settings content arrives in t005).
- Detail-page titles: follow the m46 pattern (resolved name in the shell, not a param template).

## Steps

1. Add the get-by-id query to `webhooks.graphql` if missing; regenerate types (`yarn codegen` needs `CODEGEN_SESSION_TOKEN`, or hand-mirror the shape per existing practice).
