## Objective

`TestAuthzGuardsEveryVerb` (and the sibling audit/relation sweeps) reflect over a **hand-maintained**
service inventory that omits 5 of the 22 services actually wired into the live surface. The repo's
stated guarantee — "a new verb can't ship unguarded" — is false for those 5. Close the gap and make
it self-maintaining.

## Context

- `lego/backend/internal/api/server_test.go` — `sweepableServices` lists 17 services.
- `lego/backend/internal/api/server.go:641` — `Server.features()` wires 22. Missing from the sweep:
  **keyvalue, usage, events, notifications, webhooks**. Confirmed `s.KeyValue` (`server.go:661`) and
  `s.Usage` (`:676`) are wired but absent from the sweep.
- All current verbs in those 5 guard correctly today (manually verified in the review), so this is a
  latent regression surface, not a live bypass — but `keyvalue.KeyValueConnectionInfo` reveals the
  Valkey password, so a future ungated verb there would leak a live credential.
- `TestAuditCoversEveryWriteVerbExactlyOnce` and `TestFetchByNameUsesTheVerbsOwnRelation` reuse the
  same incomplete inventory.

## Steps

1. Add the 5 missing services to `sweepableServices` (with the minimal fakes their constructors need,
   as the others do).
2. Add a test that builds a `*Server` with every feature field non-nil, reflects over the struct
   fields, and fails when a wired service is not represented in `sweepableServices` — so the two can
   never drift again.
3. Run the three sweeps; fix any verb the newly-covered services expose without a guard (none
   expected, but the point is CI now proves it).
