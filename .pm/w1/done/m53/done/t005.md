## Objective

Burn down the backend defense-in-depth findings from the review. Each is low-severity; fix or
deliberately-defer-with-rationale.

## Context

- **L1** `lego/backend/internal/core/base.go:427` — with `BEX_CP_DB_URI` set but `BEX_OPENFGA_URL`
  unset, `base.Authz == nil` fails **open** on every relation check: cross-tenant isolation holds
  (membership filtering) but within a workspace a viewer effectively has admin (delete services, read
  secrets). Documented as intentional. Add a startup warning/refusal when `Workspace != nil &&
  Authz == nil` and any workspace has >1 member.
- **L2** `lego/backend/internal/apikeys/service.go:252` — `RevokeAPIKey` falls through to `Delete`
  for a key with no binding row, skipping the cross-workspace ownership check. Treat `!boundOK` as
  forbidden/not-found for store-on callers.
- **L6** `lego/backend/internal/store/members.go:316` — invite tokens stored verbatim
  (`WHERE token = $1`). Store `sha256(token)` and look up by hash. Mitigated today by 128-bit
  entropy + 7-day TTL + single-use + never-returned, so low urgency.
- **L9** `lego/backend/internal/projects/rest.go:86` — `renderProject` calls
  `s.Store.ListEnvironments(...)` directly instead of a gated service verb (thin-adapter violation;
  safe today but REST-only, a parity drift). Route through a service method.
- **L10** `lego/backend/internal/deploys/service.go:436` — deploy-hook `?imgURL=` lets a holder of
  the unguessable hook URL deploy an arbitrary image for an image-backed service. Matches Render;
  token minted behind `RelCanViewSensitive`. Decide: keep-with-doc, or constrain `imgURL` to the
  App's own registry. At minimum document that the hook URL is an arbitrary-image credential.

## Steps

1. L2 + L1: fix the unbound-key path; add the multi-member fail-open startup guard/warning.
2. L6: hash invite tokens at rest (migration + write/lookup change); keep single-use + TTL.
3. L9: add a gated `ListEnvironments`-equivalent service verb and call it from the adapter.
4. L10: decide policy; implement the constraint or document the credential semantics in ADR006/ADR017.
