## Producer, consumer, and concrete fix

- `lego/backend/internal/apps/render.go:494–497`: `envSpecificDetails` returns absent for every `Runtime == "image"`, even a cron with nonempty `AppView.Command`. Its one production caller is `renderServiceDetails` at line 427; that helper's one caller is `toRenderServiceWithMetadata` at line 348. Two wrapper paths feed this common projection: metadata-aware REST rendering and plain rendering used by MCP result/list/stack adapters. Verify every adapter in t002.
- Pinned `pkg/service/clone.go:136–145,320–333`: cron cloning reads only `startCommandFromEnvDetails(details.EnvSpecificDetails)` via `AsNativeEnvironmentDetails().StartCommand`; the Bex-only `command` aliases are ignored.
- Pinned `pkg/types/service/servicecreate.go:68–78,214+`: normalization removes empty optional build fields before validation. `pkg/service/create.go:315–330` encodes cron commands as nested `startCommand` for every runtime.
- `lego/backend/internal/apps/rest.go:477–509` already accepts that nested start command and folds it into the cron command. `lego/operator/internal/controller/app_controller.go:3857–3863` overrides the image command only when a command is present. GraphQL directly exposes `AppView.Command` (`graphql.go:379`).

An offline program importing the **unmodified exact pinned library** decoded the captured source, ran `ServiceFromAPI`, `NormalizeAndValidateCreateInput`, and `BuildCreateRequest`. Actual response produced no cron command. Adding only `envSpecificDetails: {"startCommand": <SOURCE_COMMAND>}` produced the exact source command in the clone POST, with no validation error. The initially nonnil empty build-command pointer was normalized away; the builder's emitted empty `buildCommand` is accepted behavior, not evidence of an upstream validation blocker. No corrected payload was applied live.

Implement a narrow image-cron projection of meaningful `startCommand`, retaining `runtime: image`, imagePath, empty-command semantics, and sibling image behavior. Do not invent repository/build metadata or fork the CLI. Add tests that fail against the current omission and pass through the real pinned consumer; raw-map resend coverage alone misses this defect.
