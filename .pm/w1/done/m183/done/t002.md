## Objective

When a release reaches Running on a cluster-registry image, push the same manifest under `live-<revision>` so retention keeps it.

## Context

- Promotion: `markRunning` in `lego/operator/internal/controller/app_controller.go` (runs on every steady-state reconcile — must be idempotent).
- Registry HTTP + auth already used by repository cleanup (`registryAuthHeader`, `registry.CredentialedBase`).

## Steps

1. Registry helper: GET the manifest by digest (raw body + content type), PUT it as `live-<revision>`.
2. Record the protected digest in App status; skip when it already matches; log and retry next reconcile on failure, never fail the rollout.

## Files

- `lego/operator/internal/registry/`, `lego/operator/internal/controller/app_controller.go`, `lego/types/v1alpha1/app_types.go` (+ codegen)

## Acceptance criteria

- [ ] A promoted release's digest is tagged `live-<revision>` exactly once; external registries are untouched.

## Out of scope

- Pruning old `live-*` tags beyond the retention rule.
