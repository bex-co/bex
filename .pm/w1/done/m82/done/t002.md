## Objective

Close the two minor gaps in the workspace invite dialog found alongside the role
bug: it enables **Send invite** for an obviously-invalid email, and on a server
rejection it shows a generic toast that doesn't say why.

## Context

- `dashboard/src/features/team/hooks/use-invite-member.ts` +
  `dashboard/src/features/team/` invite dialog. Observed 2026-08-19:
  - Typing `not-an-email` (no `@`) enables Send invite; the server then rejects
    it with `bad request: invalid email address`.
  - On a non-`PLAN_LIMIT` failure the hook calls
    `toast.error(t("team.inviteError", { email }))` — a generic "Couldn't invite
    {email}" that doesn't relay the server's specific reason. (It does toast, so
    it is not a silent failure — the ask is to make it specific, matching the
    custom-domain improvement in w1/m81.)
- Mirror the custom-domain pattern (`use-custom-domains.ts` `classifyAddError` +
  inline error) and the webhook form: validate the email client-side and surface
  the server's actual message on rejection.

## Steps

1. Add client-side email-format validation so Send invite stays disabled (and/or
   shows an inline hint) until the email is a plausible address — reuse an
   existing validator/util if one exists rather than a new regex.
2. On invite failure, surface the server's specific reason (strip any generic
   `bad request:` prefix), keeping the `PLAN_LIMIT` inline-alert path and the
   new "already a member" refusal (t001) both rendered helpfully.
3. Keep i18n: new user-visible strings go through `t()` in `en`/`zh` locales.

## Files

- `dashboard/src/features/team/hooks/use-invite-member.ts`
- `dashboard/src/features/team/` invite dialog component + locales

## Acceptance criteria

- [ ] `not-an-email` keeps Send invite disabled (or blocks submit with an inline
      hint); a valid address enables it.
- [ ] A server-rejected invite (invalid email, already-a-member) shows the
      specific reason, not a generic "Couldn't invite {email}".
- [ ] Success and plan-limit paths are unchanged.

## Out of scope

- The backend invite/redeem guard (t001).
