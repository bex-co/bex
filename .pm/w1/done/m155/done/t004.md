## Objective

Each of Render's `GET /metrics/active-connections`, `/metrics/disk-usage` and `/metrics/bandwidth-sources` either answers with Render's shape, or is an explicit divergence in `docs/ADR018-render-parity.md` naming the bex path to use. None may remain an undocumented bare `404`.

## Context

- **Paths.** bex serves the datastore metrics under its own names (`metrics/rest.go:49-56`): `disk`, `disk-capacity`, `db-connections`, `replication-lag`, `kv-memory` and `kv-connections`, with `?resource=&kind=` per ADR018:198. Render's `active-connections` takes `resource` with no `kind`; `disk-usage` takes `resource` and `service`.
- **Bandwidth.** bex already composes HTTP, NAT and WebSocket egress for `monthToDateBandwidth` (ADR018:197, `w8/m15`), which may back a sources breakdown.
- **Ledger.** ADR018:198 marks active-connections and disk ✅ on REST.
- **Live at filing:** all three were bare `404`.

## Steps

1. **`active-connections` and `disk-usage`:** alias them to the existing datastore verbs, inferring the kind from the resource id prefix (`dpg-` for Postgres, `red-` for Key Value) and refusing unknown prefixes with a coded `400`. Or record the divergence with the reason.
2. **`bandwidth-sources`:** implement from the existing egress categories if the shape fits Render's schema; otherwise record it as a divergence.
3. **`disk-capacity` and `replication-lag`:** check them with Render's parameter shape (no `kind`), and fix them or record the result.
4. **Correct ADR018:197-198** to match what production serves.
