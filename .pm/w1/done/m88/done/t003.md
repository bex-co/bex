## Objective

`GET /v1/disks` reads only `q.Get("serviceId")`. Render documents `serviceId` as an **array**, plus `diskId`, `name`, `createdBefore/After`, `updatedBefore/After`, `ownerId`, `cursor`, `limit`. The extra filters pass the OpenAPI gate because they are in the spec, and are then **silently ignored** — a caller filtering by name gets unfiltered results back and no error.

## Context

- `lego/backend/internal/apps/disks.go:363-364`.
- Silent wrong answers are worse than refusals here: the caller cannot tell.
- The Key Value list already implements this same filter family (ADR018 row 146) — follow it rather than inventing a second pattern.
- Repeated `serviceId` currently takes the first value only.

## Steps

1. Read `serviceId` as a repeated param.
2. Implement `diskId`, `name`, and the four time-window filters, matching Key Value's semantics.
3. Cover the ignored-filter case with a test that would have caught the silence.
