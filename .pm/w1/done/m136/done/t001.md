## Objective

Let a caller tell "this workspace has no BYO model key" apart from "this pod is not allowed to mint for this session". Both are `ErrForbidden` today, which is why the proxy cannot treat them differently.

## Context

- `lego/backend/internal/agentsession/model.go:293-299` — after reading OpenBao, an empty `data[ModelKeyField]` returns a bare `ErrForbidden` with a comment explaining it is refusing "rather than forward an unauthenticated request". The refusal is right; only the indistinguishability is wrong.
- The other `ErrForbidden` sites in the same `Mint` are genuine authorization refusals: `AuthorizeSessionPod` mismatch (`model.go:226-232`), session not found (`model.go:275-278`), and `!currentSandboxCaller` (`model.go:281-283`). Those must keep behaving exactly as they do — a stale/compromised sandbox in the ADR054 grace window gets nothing and learns nothing.
- `ErrForbidden` is declared in `lego/backend/internal/agentsession/contract.go:85` alongside the package's other sentinels.
- Keep the new sentinel **wrapping** `ErrForbidden` (`fmt.Errorf("%w: ...", ErrForbidden)` style, as `ValidateBranch` already does at `contract.go:136-143`) so every existing `errors.Is(err, ErrForbidden)` caller — including `http.go:112` — keeps its current behavior unchanged. This task must be behavior-preserving on its own; t002 is what acts on the distinction.

## Steps

1. Declare the sentinel next to `ErrForbidden` in `contract.go`, wrapping it, with a comment saying why it exists (the proxy must report an auth failure for this cause only).
2. Return it from the empty-credential branch in `Mint`.
3. Confirm the mint-denied audit event and the `agent-session model credential mint denied` log line still record the refusal (the `defer` at `model.go:249-263` reads `err`, so it will — verify the message stays useful).
4. Grep every `errors.Is(..., ErrForbidden)` in `lego/backend/` and confirm none changes outcome.

## Acceptance criteria

- [ ] A distinct exported sentinel identifies the "no key provisioned" refusal.
- [ ] `errors.Is(err, ErrForbidden)` is still true for it, so no existing caller changes behavior.
- [ ] The three authorization refusals in `Mint` remain plain `ErrForbidden` and are NOT reclassified.
- [ ] A unit test asserts both `errors.Is` results (new sentinel true, and still `ErrForbidden`) for the empty-credential case, and that an authorization refusal does **not** match the new sentinel.
