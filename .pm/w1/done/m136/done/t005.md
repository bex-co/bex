## Objective

Lock in both halves of the fix: a missing key terminalizes the session with the actionable reason, and an authorization refusal still does not.

## Context

- The second assertion is the one that matters for safety. `reportAuthFailure` is now reachable from a refusal path, so a test must prove a stale/cross sandbox cannot use it to kill a live session — `ModelAuthFailer.Fail`'s `currentSandboxCaller` re-check (`lego/backend/internal/agentsession/model.go:357-362`) is what stops it, and a regression there would be silent.
- Existing homes: `lego/backend/internal/agentsession/model_test.go` (minter/failer, with a fake `SecretKV` keyed by `ModelKeySecretPath`) and `lego/backend/internal/sshgateway/modelproxy/` tests for the proxy branch.
- `lego/backend/internal/agentsession/mint_test.go` has the pattern for asserting an `ErrForbidden` refusal shape.
- Tests must assert observable behavior — the reason string actually written and whether the report fired — not merely that a function was called. No snapshot-everything.

## Steps

1. Minter: empty credential → the t001 sentinel, and `errors.Is(err, ErrForbidden)` still true. An authorization refusal → plain `ErrForbidden`, not the sentinel.
2. Proxy: mint refused with the sentinel → `reportAuthFailure` fires **once**, response is 403, and `mintWithRetry` made exactly one attempt.
3. Proxy: mint refused with plain `ErrForbidden` → 403 and **no** report.
4. Failer: a report from a non-current sandbox is refused and the session's phase is unchanged.
5. End state: a session finalized through this path carries `ModelAuthFailureReason` (or its t003 successor) in `failure_reason`.
