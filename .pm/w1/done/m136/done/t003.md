## Objective

Confirm the one reason string t002 now writes reaches every surface that exposes a session's failure identically, and that the wording still reads correctly for a cause that is "no key was ever provisioned" rather than "the vendor rejected your key".

## Context

- Render ships no coding-agent product, so `docs/ADR018-render-parity.md` has no row to match here — parity for this milestone means bex's own cross-surface discipline (`docs/ADR006-bex-api.md`), the same call `w1/m90` t005 made.
- `failureReason` is already a field on all four surfaces: the REST session view, the GraphQL `AgentSession` type (`failureReason` in `AgentSessionFields`), MCP, and the dashboard's failure card. This task adds no field — it verifies one string arrives everywhere unchanged.
- Wording check: `ModelAuthFailureReason` (`lego/backend/internal/agentsession/model.go:211`) currently says "the model provider rejected this workspace's API key (authentication failed); update the model key and start a new session". For a **missing** key, "rejected this workspace's API key" is arguably wrong — there was no key to reject — while the prescribed next step ("update the model key and start a new session") is exactly right. Decide deliberately: either keep one shared string because the fix is identical, or split into two reasons.
- If it splits, both strings must land on all four surfaces and the dashboard must not special-case one of them into different copy.

## Steps

1. Drive a missing-key session in `dev-1` and read `failureReason` from REST, GraphQL and MCP for the same session id; diff the three.
2. Open the session in the dashboard and confirm the failure card renders that same string (not a truncation, not a generic fallback).
3. Make the wording call and record the reasoning in the milestone README's outcome section.
4. If the string splits, update the shared constant(s) in one place so no surface can drift.

## Files

- `lego/backend/internal/agentsession/model.go` (the reason constant, if it splits)
- whichever cross-surface test already asserts agent-session error parity
- `dashboard/src/features/agent-sessions/` — only if the failure card special-cases reasons

- [ ] The dashboard failure card renders that string verbatim.
- [ ] The wording decision (one reason vs two) is recorded with its rationale.
- [ ] No new field was added to any surface.
