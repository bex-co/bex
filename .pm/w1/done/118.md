# Render's `create_web_service`/`create_cron_job` MCP tools gained Dockerfile args bex lacks

Why: the w1/m165 re-pin (upstream `render-mcp-server` `d9a8abd`) showed upstream `bc94f8d` (#154, "Support Dockerfile-based web service and cron job creation") added `dockerCommand` and `dockerContext` and made `buildCommand`/`startCommand` optional; an agent written against Render passing those args gets them rejected or ignored by bex.

**Source:** `w1/m165` t003 (the refreshed pin) and t004 (the drift headline now names `changed=[create_cron_job create_web_service]` against the old pin). Filed, not built — m165 was scoped to `list_events`.

- Pin diff: both tools' `args` += `dockerCommand`, `dockerContext`, `dockerfilePath`; `required` drops `buildCommand`, `startCommand`. bex already takes `dockerfilePath` and already leaves build/start optional, so the gap is **`dockerCommand` + `dockerContext`** only.
- Both tools were already `Divergent` (no caller-chosen `region`); their `mcpAcceptedDivergences` entries in `lego/backend/internal/api/mcp_parity.go` now name this gap and point here.
- REST already takes both (`lego/backend/internal/apps/rest.go` `DockerCommand`/`DockerContext` on `envSpecificDetails`, and the Blueprint compiler maps them), so this is an MCP argument mapping onto an existing core field, not a new capability — likely well under an hour.
- Done when both args are wired (or deliberately declined with a reason), the two entries' reasons are back to `region` only, and `TestMCPParity*` passes.

**Done 2026-10-02.** Both args wired on `create_web_service`/`create_cron_job` with upstream's names, string types and docker-only semantics (`lego/backend/internal/apps/mcp.go` `resolveMCPDockerArgs`/`checkMCPDockerArgs`): on `runtime: docker`, `dockerCommand` → start command (and a cron's run command, REST's bridge), `dockerContext` → `spec.dockerContext` with REST's core path validation; inert on other runtimes, as upstream and REST. A `dockerCommand` alongside `startCommand`/cron `command` is refused (the Blueprint's "cannot set both" rule). Accepted-divergence reasons are back to `region` only, held by `TestMCPParityGitCreateToolsBreakOnlyOnRegion`; tests in `internal/apps/mcp_docker_args_test.go`. Parity class counts unchanged (both stay `Divergent` on `region`).
