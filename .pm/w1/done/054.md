# 054 — Git-proxy default limiter is a per-call no-op (acquire/release on different instances)

From the 2026-08-19 architecture survey ([Bex Refactor Ledger](https://claude.ai/code/artifact/5ceae798-6df1-4f3c-94b6-6b1126f640c2) §0). `lego/backend/internal/sshgateway/agentcred/agentcred.go:113-118` returns a **fresh** `NewSessionLimiter(0,0)` on every call when `Limits == nil`; the handler then acquires on one instance (`agentcred.go:142`) and releases on a different one (`:147`), so the fallback concurrency cap is silently a no-op. Dormant in production — `cmd/ssh-gateway/main.go:232` wires `Limits` — but the twin handler already fixed the identical shape: `sshgateway/modelproxy/modelproxy.go:212-218` memoizes its default with `limitsOnce` (`sync.Once`). The two copies have diverged once; this closes the gap until the shared credential-proxy skeleton refactor lands.

**Fix.** Memoize the default limiter in `agentcred` exactly like `modelproxy` (`sync.Once` field on the server struct), so acquire and release always hit the same instance.

**Acceptance:** a test with `Limits == nil` asserting the same limiter instance is used across calls (e.g. saturate the default-capped limiter and observe the second request shed, or assert pointer identity across two requests).
