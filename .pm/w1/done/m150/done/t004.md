## Objective

The allowlist's address semantics are true and stated the same way on REST, GraphQL, MCP, the dashboard and Blueprints, and they match Render or diverge on the record.

## Steps

1. **Check every surface.** Confirm REST `serviceDetails.ipAllowList`, GraphQL `setServiceIpAllowList`, MCP `update_service` and the dashboard Networking card need no shape change after t002. Confirm the card copy ("Restrict inbound HTTP traffic to these source CIDRs.") is now true.
2. **Update the ledger.** In `docs/ADR018-render-parity.md` row 125, record:
   - the client address is the public TCP source carried by PROXY protocol from the load balancer, and never a forwarded header;
   - denied requests get `403`, like Render;
   - t003's Cloudflare-fronted-host decision;
   - that production verification needs the Hetzner load balancer in the path (the `w7/m32` mock-cluster check could not catch this).
3. **Compare with Render.** Render's docs (`render.com/docs/inbound-ip-rules`) do not name the evaluated address. Record that gap rather than guessing.

## Acceptance criteria

- [x] ADR018 row 125 is updated.
- [x] Any surface disagreement found is filed as `w1/NNN`.

## Outcome (closed 2026-10-02)

- **No surface needs a shape change.** t002 is edge-only: REST `serviceDetails.ipAllowList`, GraphQL `setServiceIpAllowList`, MCP `update_service` and `PATCH /v1/environments/{id}` keep their shapes. The live probes drove REST for both layers. The Networking card's "Restrict inbound HTTP traffic to these source CIDRs." is now true on DNS-only hosts.
- **ADR018's inbound-IP-allowlist row** now records which address is matched (the TCP source via PROXY protocol, never a forwarded header), the `403`, the Cloudflare-fronted-host decision, that only a probe through the Hetzner load balancer verifies this, and Render's documentation gap.
- **Filed `w1/119`.** Decision 2's refuse-or-warn for allowlists on Cloudflare-proxied custom domains was never built, so on those hosts the card's promise is silently false.
