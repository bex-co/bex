# Remove or lock the composer's `modelEndpoint` field

Why: the field can only ever produce an error — the backend rejects every value except the one the UI already defaults to — so it is a guaranteed dead end that invites users to type something invalid.

`dashboard/src/features/agent-sessions/components/configuration-fields.tsx:67` renders `modelEndpoint` as a free-text URL `<Input>` in the composer's **Advanced** panel, with placeholder `https://api.example.com` and the hint _"Optional custom HTTPS endpoint for the model provider."_

But `agentsession.RegisteredModelEndpoint` (`lego/backend/internal/agentsession/model.go:64`) does:

```go
if requested != "" && requested != expected {
    return "", core.NewBadRequestError("AGENT_SESSION_MODEL_ENDPOINT_INVALID",
        "agentConfig.modelEndpoint must match the selected agent's registered provider", nil)
}
```

`expected` is the selected agent profile's own endpoint. So any value other than the exact default is a 400, and the default is what the UI already sends. The field is either a no-op or an error.

That pin is deliberate — it is what stops a session being aimed at an arbitrary host — so the fix is on the UI side, not the backend's.

Options, cheapest first:

1. Drop the field from Advanced entirely.
2. Render the registered endpoint read-only, so it is visible but not editable — keeps the transparency the hint was reaching for.

Either way delete or reword `agentSessions.modelEndpointHint` / `modelEndpointPlaceholder` in `en.ts` **and** `zh.ts`; the current copy actively invites the invalid input.
