   form.** `requireAuth` now defaults `next` to the requested href (m45), but
   legacy callers still pass static strings that drop query/hash on the login

   env-groups_.$groupId.tsx), so their `next` is a literal `$serviceId`

   `useParams({strict:false})`; database/keyvalue detail pages are the obvious
   next parity targets and would each add a branch, with branch order as a
   silent tiebreak. Route-level ownership (each layout route passes its
   contextual sidebar) is the cleaner mechanism.
3. **Merge `RENDER_ALIAS_TARGETS` + `RENDER_CREATE_LANDINGS` into one
