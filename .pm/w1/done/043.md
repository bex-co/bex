## Resolution — DONE 2026-07-31

Recreated (both kind clusters deleted first) and proven walk-ready: 3 nodes Ready, operator `1/1 Running` with all controllers started, dev-5 raised, and `status.sh`'s verification inventory **ALL GREEN** (default StorageClass · CNPG ready · Loki ready · Loki ingest→query round-trip · bex-api :54050). `w5/028`/`w5/029` pinged with the walk-runnable update.

The recreate surfaced that "walk-ready" had been living on hand-applied state — all of it now **codified** so the next recreate works first-try:

- `scripts/mock-cluster.sh`: installs local-path-provisioner v0.0.30 as the default StorageClass (its namespace PSA-exempted — the cluster's baseline PodSecurity forbids the hostPath helper pods) and cert-manager v1.20.3 (prod's gitops pin; `make deploy`'s webhook Certificate hard-requires it), plus a `calico-kube-controllers` control-plane pin (the ×1903-restart crashloop on the rotted cluster was this — worker-node pods can't reach the apiserver under OrbStack+Calico).
- `.pm/w5/dev-5/up.sh`: `ensure_cnpg` now control-plane-pins the CNPG manager (same apiserver trap — the prior "CNPG webhook crash" diagnosis was actually this) and sets `BEX_CP_INSECURE=1` (dev-1's existing convention; post-w1/m53 bex-api refuses to start CP-enabled without a token, and dev-5 had never run since).
- `.claude/skills/mock-cluster/SKILL.md`: stale `cd operator` → `lego/operator`; documents applying `deploy/gitops/base/operator-apps-rbac.yaml` (Argo-managed in prod, absent from kustomize — without it the manager crashloops on forbidden namespace-scoped Secret/Job watches), the `bex.co/pool=platform` label on the control-plane node, and the `imagePullPolicy: IfNotPresent` override (the manifest's `Always` can never be satisfied by the ctr-imported local image), all re-applied after every `make deploy`.

Known-broken leftovers, deliberately not fixed (not part of the walk substrate; equally broken on the old cluster): in-cluster `bex-api` (ImagePullBackOff — dev-N runs its own on the host), `bex-ssh-gateway` (needs Traefik CRDs + host-key/DB secrets), `bex-static-server` (needs S3 config).
