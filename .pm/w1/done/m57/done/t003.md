## Objective

Close the remaining two hand-applied fixes. First, make the `bex-registry-pull` credential's custody drift-proof: prod's copy was re-minted by hand from the `bex-registry-push` `bex-builder` credential after authenticating as the stale `bex-puller` (no Zot ACL grant under per-App mode) — codify so the correct identity is always minted, not remembered. Second, retire the hand-applied `bex-static-server-apps-reader` ClusterRoleBinding: the durable fix shipped in `bb92f86d` (`config/staticserver` Role→ClusterRole), so once t002 has the shipped manifests applied via Argo, the hand-applied binding is residue to verify-then-drop.

## Context

- `w9/done/014.md` items 1–2; `w9/done/012.md` chain #3/#4 for the original interventions.
- `scripts/registry-secrets.sh` is the existing custodian — it mints the registry secrets (incl. `bex-registry-pull`, the `bex-builder` user with wildcard read; see repo `CLAUDE.md` on `BEX_REGISTRY_BUILD_PULL_SECRET`) from `.env` values. The note's two codify options: re-run it against prod as the documented step, or fold `bex-registry-pull` into the out-of-band bootstrap inventory so it cannot drift ([docs/ADR019-infra-credentials.md](../../../docs/ADR019-infra-credentials.md) is the custody ledger).
- Never print credential values; identity checks only (which htpasswd user).

## Steps

1. Per t001's snapshot: if `bex-registry-pull` still (or again) carries the wrong identity, re-mint via `scripts/registry-secrets.sh` against prod.
2. Codify custody: ensure `scripts/registry-secrets.sh` covers `bex-registry-pull` end-to-end for prod bring-up, and record it in the out-of-band bootstrap inventory (ADR019 / ADR022 § Registry access control) so a rebuilt cluster mints the right identity by procedure, not memory.
3. Verify the shipped `config/staticserver` RBAC (applied through t002's Argo path) grants everything the hand-applied `bex-static-server-apps-reader` CRB granted (same verbs/resources, both static-server SAs → the one remaining SA after consolidation).
4. Delete the hand-applied CRB from prod; confirm the static-server still lists/serves sites (its App-informer keeps working).
5. Update the docs touched (ADR019 inventory, ADR022 registry section) if their described custody changed.
