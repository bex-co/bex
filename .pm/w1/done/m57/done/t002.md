## Objective

Make the static-server Argo-managed from `lego/operator/config/staticserver` so it tracks the current image + config automatically, consolidated to **one** instance placed where the Ingress topology requires it — the operator points static-site Ingresses at a same-namespace Service (`BEX_STATIC_SERVER_SERVICE`), so the serving instance belongs in the App namespace. Add `BEX_BASE_DOMAIN` to the `bex-static-config` ConfigMap (the design already `envFrom`s it; prod's ConfigMap just lacks the key). Remove the unmanaged duplicate.

## Context

- `w9/done/014.md` item 3 names this "the real fix": the Ingress-targeted `default/bex-static-server` ran a stale image and lacked `BEX_BASE_DOMAIN`; a second unmanaged `bex-system/bex-static-server` also exists.
- Follow the existing Argo pattern: `deploy/gitops/overlays/prod/kustomization.yaml` points the `bex-operator` Application at `lego/operator/config/prod`; the static-server needs the equivalent git-tracked path (a base Application or an entry the prod overlay patches), with the image kept current by the same CI image-pin flow the other bex images use (`chore(deploy): pin platform images` commits).
- Static-server env contract (repo `CLAUDE.md`): `BEX_STATIC_ADDR`, `BEX_STATIC_NAMESPACE`, `BEX_STATIC_S3_*`, cache/resync knobs; AWS creds come **only** from the required `bex-system/bex-static-read-s3` read-only Secret and startup fails if its signed origin check is denied — placing the single instance outside `bex-system` must account for where that Secret and `bex-static-config` live (mirror/reference them; do not widen the publisher credential).
- t001's snapshot says which of the two Deployments is live-serving and what the current image is — consolidate onto the Ingress-targeted one, delete the other.

## Steps

1. From t001's snapshot, pick the canonical instance (the one static-site Ingresses target) and namespace.
2. Add the static-server to GitOps: an Argo Application (or kustomize resource) sourcing `lego/operator/config/staticserver`, namespace-targeted per step 1, wired into the prod overlay; keep the local overlay consistent with the mock cluster's shape.
3. Add `BEX_BASE_DOMAIN` (prod: `onbex.co`) to `bex-static-config` in the manifests so `envFrom` picks it up — never a hand-set container env.
4. Ensure the required `bex-static-read-s3` Secret and `bex-static-config` exist in the chosen namespace (adjust `config/staticserver` manifests or the out-of-band bootstrap doc accordingly).
5. Apply via Argo on prod; confirm the app goes Synced/Healthy, the Deployment runs the current CI image, and static sites still serve.
6. Delete the now-redundant second Deployment; confirm nothing (Ingress, Service, probe) referenced it.
