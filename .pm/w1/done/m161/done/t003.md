The server-sending control stayed awake. Root cause: the Prometheus `traefik-websocket-meter` job's `metric_relabel` keep-list named only `bex_websocket_egress_bytes_total`, so the new `bex_websocket_ingress_bytes_total` was dropped at scrape. A local Traefik v3.6 carrying the exact plugin counted the frames (ingress 56 bytes, egress 0), which located the drop. Fixed in `f0b29625c`, with a guard test (`activity_scrape_test.go`) that fails on the old keep-list.

```text

  /stats after the window: clientMessages 35, serverMessages 0, serverPongs 0
server-sending control (/ws?mode=send&every=60s, client listens only): Running for 35 min, no service_hibernated

It could only have *delayed* the sleeps, and cannot explain the subject staying awake while the idle control slept.
