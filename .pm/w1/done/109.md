## Resolved 2026-09-28 (`/loopx w1`) — shipped `be689f2bd`

**Root cause, and it was not the file the note named.** `ff78583c5` ("chore(mobile):
bump to 0.2.0 and align the App Store version record", 2026-09-08) rewrote
`mobile/app.json` with expanded arrays — one element per line — instead of
prettier's collapsed form; its parent was prettier-clean. The next push that
triggered the mobile workflow went red and stayed red for 53 runs.

**The caveat in this note was right, and it mattered twice over.**

1. *Version churn:* checked before fixing — mobile's own prettier (3.9.6, `^3.7.4`)
   and the repo's 3.4.2 markdown pin agree byte-for-byte on the formatted result,
   so the two cannot fight over this file. No config or version reconciliation was
   needed.
2. *Findings behind the gate:* `format:check` is the **first** sub-command of
   `yarn test`, so `typecheck`, `lint`, `test:unit` and `expo:check` had not run in
   19 days — and one of them was also failing. `expo:check`
   (`expo install --check`) reported **14 outdated Expo SDK packages**. That check
   compares installed versions against Expo's *remote* SDK metadata, so it drifts
   red on its own as Expo publishes patches, with no repo change at all. Fixing
   `app.json` alone would **not** have made the job green.

**Both fixed.** `expo install --fix` moved 12 packages onto their expected patch
versions (expo-router 57.0.20 → 57.0.23, expo-notifications 57.0.17 → 57.0.21,
`@expo/metro-runtime`, `@expo/ui`, expo-auth-session, expo-glass-effect,
expo-haptics, expo-localization, expo-secure-store, expo-splash-screen,
expo-symbols, nanoid). Full chain green in 49.70s: `format:check`, `typecheck`,
`lint`, `test:unit` (369 tests), `expo:check`; the separate CI codegen gate
(`yarn codegen:backend && git diff --exit-code -- src/generated-graphql`) clean.

**Ruled out while diagnosing, recorded so nobody re-raises it:** the
`test-renderer` devDependency that `scripts/access-recovery-tests.js` requires is
**not** a typosquat of `react-test-renderer`. It is mdjastrzebski's (a
`@testing-library/react-native` maintainer) legitimate "modern replacement for the
deprecated React Test Renderer", pinned exactly at `1.2.0` and locked with an
integrity hash. The `Cannot find module` seen locally was a stale `node_modules`.

**Standing exposure this leaves.** `expo:check` will drift red again on the next
Expo patch train, exactly like `build-toolchain-freshness` (`w1/108`). Nothing in
the repo pins or reviews that drift on a schedule; `ci-red-streak.yml` will now
catch the redness within a day, which is the mitigation that was missing for 19
days. Not filed as work — recorded so the next occurrence is recognized as drift,
not regression.
