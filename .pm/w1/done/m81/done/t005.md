## Objective

match Render's behavior, flagging any residual drift as follow-up rather than
silently diverging.

## Context

- The findings touch user-facing surfaces: the dashboard UI plus the
  custom-domain and deploy-list reads that also exist on REST/GraphQL/MCP
  (bex-api is Render-compatible, `docs/ADR006-bex-api.md`).
- Parity to check:
  - **Custom domain (t001):** the dashboard now surfaces `addCustomDomain`
    errors; confirm REST/GraphQL/MCP already return the same error shape/message
    for the same rejected inputs (they do — the dialog was the only gap), and
    that no other create/settings dialog swallows `errors[]` the same way (quick
    audit of sibling dialogs).
  - **Deploys list (t003):** whatever resolution t003 chose, confirm REST,
    GraphQL, MCP, and the UI agree on whether an env-triggered rollout appears.
  - **Free-tier validation (t004):** confirm the UI caps match the server's
    enforced limits and match Render's plan semantics where applicable.
