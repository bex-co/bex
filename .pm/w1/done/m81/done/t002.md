## Objective

Eliminate the `Minified React error #418` (hydration text-content mismatch)
logged once on every dashboard page load, or — if it proves to be an
unavoidable, benign third-party effect — reduce it at the source and record why.

## Context

- Observed in the 2026-08-19 QA walk on **every** route (login redirect,
  overview, service detail, billing, metrics, …). Console error, once per page
  load:
  `Minified React error #418; visit https://react.dev/errors/418` — decoded:
  **"Text content does not match server-rendered HTML"** (SSR/CSR hydration
  mismatch). Stack is inside `assets/vendor-react-*.js` (production/minified).
- React recovers by re-rendering client-side, so it is not a hard break, but it
  is a real SSR↔CSR mismatch on the primary product surface and can cause a
  flash of mismatched content on first paint.
- The dashboard is TanStack Start (SSR) + Apollo. Likely culprits: a value that
  differs between server and client render — a locale/`Date`/relative-time
  ("now", "17d", "3:45 PM") formatted with the server's timezone/clock vs the
  browser's, a `typeof window` branch, random ids, or a theme/`prefers-color`
  read. The header renders relative timestamps ("Created: now/1m/17d") which are
  a classic #418 source.

## Steps

1. Reproduce against a **dev/non-minified** build (or point the browser at a
   local `dashboard` dev server) so React prints the full component + the exact
   mismatching text, turning #418 into an actionable stack.
2. Identify the mismatching node (most likely a time/locale/`window`-dependent
   render in a widely-shared component — e.g. the resource header's relative
   "Created" text or a theme read).
3. Fix so server and client produce identical initial HTML: render a stable
   placeholder on the server and hydrate the client-only value in an effect, or
   make the formatter deterministic (fixed timezone/`suppressHydrationWarning`
   only as a last resort for a genuinely client-only leaf).
4. Re-verify: no #418 in the console across overview, a service detail, billing,
   and metrics.

## Files

- `dashboard/src/**` — the shared component(s) responsible for the mismatch
  (identified in step 2); likely a relative-time / date / theme utility.

## Acceptance criteria

- [ ] No `Minified React error #418` is logged on a normal authenticated load of
      the overview, a service detail, billing, and metrics pages.
- [ ] The root cause is named in the task/commit (which value mismatched and
      why), not just suppressed blindly.
- [ ] If any residual hydration warning is intentionally left (e.g. a truly
      client-only third-party widget), it is scoped with
      `suppressHydrationWarning` on the smallest node and justified in a comment.

## Out of scope

- Broader SSR performance/refactor work; only the #418 mismatch.
