# `scripts/mock-cluster.sh` fails on re-run once the local Argo owns kubelet-csr-approver

Why: the script is documented as idempotent ("recovery is re-running this script"), but on 2026-10-15 a re-run after the cluster's load balancer restarted failed at its last step, `helm upgrade --install kubelet-csr-approver`: "conflict occurred while applying object kube-system/kubelet-csr-approver … conflicts with "argocd-controller"" (and with "kubectl-patch" on `.spec.template.spec.nodeSelector`).

- The step's own comment (`scripts/mock-cluster.sh:342-360`) says "Argo CD is not installed on this mock", but the shared local cluster now runs Argo with the `bex-platform-local` app-of-apps, whose base includes `kubelet-csr-approver`. So Helm and Argo both claim the release.
- The earlier steps (storage, CNI, kubeconfig publish) had already run, so the cluster was usable; the script just exits non-zero and never prints its success banner.
- Fix shape: skip the Helm install when an Argo `Application` named `kubelet-csr-approver` exists in the workload cluster (Argo then owns approval), keep it for a bare mock, and keep the one-time backlog approve. Verify by re-running the script twice on the shared cluster.

**Done 2026-10-15 (`/loopx w1`).** The failure was a class, not one step: the next Helm install, `metrics-server`, hit the same Argo field-ownership conflict once the approver was skipped. `scripts/mock-cluster.sh` now has `argo_manages APP` and defers both installs to Argo when its Application exists (Helm still installs them on a bare mock); `scripts/mock-cluster.test.sh` covers both branches for both components. Argo had been carrying the approver's strict prod values while the Deployment ran the script's CAPD values, so the local overlay now owns the two CAPD deviations (`bypassDnsResolution: true`, control-plane placement), and `scripts/gitops-validate.sh` requires local and prod to agree on every other approver check (a seeded `providerRegex: '.*'` fails it). Verified on the shared cluster: two consecutive `bash scripts/mock-cluster.sh` runs exit 0, each printing both deferrals and passing the metrics-server availability wait; the live `kubelet-csr-approver` Application was patched to the overlay's values (Synced, Healthy; the Deployment keeps the bypass and control-plane placement). Full `gitops-validate.sh` passes on yq 4.44.6.
