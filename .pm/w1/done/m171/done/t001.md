## Objective

Give the service and environment features one way to tell which custom domains resolve into Cloudflare's edge, plus one rule for when an allowlist actually restricts traffic.

## Context

- `domainCertificateReason` (`lego/backend/internal/apps/domains.go`, w3/037) relays cert-manager's free-text reason and is empty once a certificate is issued, so it is not a proxied-host signal (see milestone § Decisions 1).
- Cloudflare's ranges were fetched 2026-10-02 from `https://www.cloudflare.com/ips-v4` and `/ips-v6`.

## Steps

1. Add `core.ProxiedHostDetector` with a `HostResolver` seam, concurrent lookups, a 2s bound, a 5-minute cache, and no caching of failures.
2. Add `AllowListRestricts` (non-empty, no `/0` entry), `AppCustomDomains` (`spec.host` + `spec.hosts`, publicly routable types only) and `ProxiedAllowListWarning`.
3. Add `mcputil.WithWarning` (the JSON block plus a warning block; nil when there is no warning).

- `lego/backend/internal/mcputil/mcputil.go`

- [x] Results are in input order, normalized and deduplicated; answers are cached; failures are retried; a nil detector detects nothing.
