# 110 — Honor Postgres suspension-filter arrays

Why: Render clients requesting multiple suspension states must not silently lose all but the first value or receive an invalid-enum refusal.

**Worker:** worker1. **Status:** todo. **Estimate:** 40m. **Source:** approved 2026-09-28 w1 brainstorm item 2, code inspection at f60757162.

## Evidence and work

`lego/backend/internal/postgres/rest.go` `postgresListFilter` reads `q.Get("suspended")` and validates one enum. Repeated values select the first; a comma pair is treated as one invalid value. Existing `filter_rest_test.go` tests cover only individual states. Render documents an array ([list Postgres](https://api-docs.render.com/reference/list-postgres)); `core.QueryList` and the fixed service-list handler already implement multiple values. This is a residual of completed w2/m53, not the completed w4/164 service-list fix.

Use `core.QueryList`, validate every member, OR alternatives and filter before pagination. Add gated behavior tests in `lego/backend/internal/api/` and package tests for comma and repeated forms, both orders, duplicates, invalid members and composed filters. The source-read census alone cannot prove semantics. Update ADR018 Postgres list-filter coverage.

## Acceptance

- Both suspension values return both fixture sets regardless of order or supported serialization.
- A single value still narrows; invalid members fail clearly; owner scoping and pagination remain correct.
- Tests exercise the gated server and fail against the old handler.
- Key Value is not automatically included: verify its applicable contract before expanding scope.

User direction (2026-09-28): where behavior is uncertain, verify the Render contract and keep parity; do not introduce an undocumented divergence. Existing explicit non-goals remain out of scope.

## Resolved 2026-09-28 (`/loopx w1`)

**The Render contract, verified rather than assumed.** The pinned spec declares
`GET /postgres`' `suspended` parameter `type: array, items: {enum: [suspended,
not_suspended]}` (`render-public-api-1.json`, `components.parameters`). So the note's
premise holds: an array is documented.

**Fix.** `postgresListFilter` (`lego/backend/internal/postgres/rest.go:88`) now uses
`core.QueryList(q, "suspended")`, validates **every** member through `core.ParseEnum`,
and ORs them via `slices.Contains` — the same shape `?name=` and `?environmentId=`
already had two lines above, and the same loop `apps/rest.go:689-694` uses for
services (w4/164). `core.QueryList` already handles both supported serializations
(repeated params and comma-joined) with trimming and dedupe, so no new helper was
needed. Filtering still happens before pagination, so `StablePage` keeps its
gap/duplicate-free walk.

**Tests.** `TestRESTListPostgresSuspendedFilterIsAnArray` covers both members in
both serializations and both orders, duplicates, surrounding whitespace, trailing/
leading commas, a single member still narrowing, an invalid member in **either**
position alongside a valid one (400 that names the filter — never a filter that
quietly matches nothing), and composition with `?name=` to prove it ANDs across keys
while ORing within its own. **Proven to fail against the pre-fix handler**: reverting
`rest.go` produces 3 failing assertion groups. The pre-existing
`TestRESTListPostgresSuspendedFilter` is kept unchanged as the single-value control.

**Key Value: verified out of scope, and for a stronger reason than expected.** The
note asked to check its contract before expanding. Render's `GET /key-value`
declares **no `suspended` parameter at all** — its documented filters are `name`,
`region`, `ownerId`, `environmentId`, the four time windows, `cursor` and `limit`.
bex's `?suspended=` on that route is therefore a **bex extension** (added by
`w2/m53`), with no Render array contract to match. Left single-valued; aligning its
arity for internal consistency would be a bex-extension decision, not parity, and is
deliberately not filed.

**Also corrected in passing:** the `w2/m53` backlog row in ADR018 spelled the enum
`"not_supported"` instead of `"not_suspended"`. Fixed in the row being amended.

**Suites.** Full `cd lego/backend && GOWORK=off go test ./...` green (no FAIL lines);
`go build ./...` and `gofmt` clean. ADR018's Postgres list-filter coverage updated.
