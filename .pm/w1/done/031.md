# Prod ops follow-ups from the 2026-07-17 build-log incident (user's call)

Two operational gaps found while debugging `dep-d9d8r3h07a5s73dj32ag` — actions on prod state, not repo code; user decides whether/when:

1. **`agentmarketcap-1` clone token lacks repo access.** Its clone Secret (`tea-d98210cbbpdc73dcrkvg-agentmarketcap-1-clone`, present in `bex-system` and `default`, single 40-byte `token` key, created 2026-07-15) does not grant access to the private repo `github.com/bex-co/agentmarketcap` — every build fails at git clone with `could not read Username for 'https://github.com'`. Remint a token with access to that repo (`beancount-cms-v2`'s sibling token works fine — its gen-143 build succeeded the same hour).
2. **GitHub App is unconfigured in prod.** `BEX_GITHUB_APP_ID` / `BEX_GITHUB_APP_PRIVATE_KEY` / `BEX_GITHUB_APP_SLUG` are unset on prod bex-api ⇒ every git-connect verb 503s and installation-token clone Secrets can't mint (`docs/ADR026-github-integration.md`); hand-minted PATs are the only clone path today. Configure via `scripts/github-app-secret.sh`; keep `.env` / `.env.example` / `.env.template` variable names in sync per repo rule.

> **Resolved 2026-07-17 (superseded — both halves were misdiagnosed):** CLI-driven debugging of the same deploy corrected the record. (1) The GitHub App **is** configured in prod — `BEX_GITHUB_APP_*` arrive via `valueFrom` secretKeyRefs on the `bex-github-app` Secret (the earlier env dump printed only literal `value`s); the workspace is connected (installation 90623475) and `bex-co/agentmarketcap` IS in the repo grant. (2) The clone token needed no manual remint — it's a GitHub App **installation token** (`ghs_…`, one-hour TTL) that bex is SUPPOSED to remint per deploy, and the real bug was that `deploys.Service.Trigger` (manual deploy + deploy hook, `trigger=api`) bumped the generation without reminting, so every manual build of a private repo ran with the previous deploy's expired token → GitHub 401 → git's prompt fallback → `could not read Username`. Webhook-triggered siblings (beancount-cms-v2) remint on their path, which is why they kept building. Fixed in code: `deploys.Service.CloneSecrets` (the reconciler's `store.CloneSecreter` bridge) reminted in `triggerFetched` before the bump, mint failure fails the trigger loudly, declined mint leaves a hand-managed secret alone — pinned by `internal/deploys/clonesecret_test.go`. Post-deploy verification folded into `032`.
