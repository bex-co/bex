## Objective

Close the last known place the protected-mount marker is dropped. The build-namespace copies of an App's registry credential are written with plain `artifactLabels`, so a Secret that was protected in the tenant namespace arrives in the build namespace unmarked — exactly the outcome F7's godoc warns about. Mirror the marker-preserving pattern `copySecret` already uses.

## Context

- `lego/operator/internal/controller/build_registry_secret.go:59-70` (`prepareBuildRegistrySecret` merged credential, labels at `:69`) and `:96-116` (`copyBuildRegistryCredential`, labels at `:112`).
- The pattern to mirror: `lego/operator/internal/controller/app_controller.go:1843-1848` (`dst.Labels[execution.LabelProtectedFromTenantMount] = src.Labels[...]` when set).
- `lego/operator/internal/execution/security.go:63` — `LabelProtectedFromTenantMount`.
- Severity is low (tenant Apps run outside the build namespace), but the guard's godoc claims no legitimate path strips the marker.

## Steps

1. In `copyBuildRegistryCredential`, after `dst.Labels = artifactLabels(...)`, copy the marker from `src` when present (same three lines as `app_controller.go:1845-1848`).
2. In `prepareBuildRegistrySecret`, thread the source Secret(s)' marker through: if any source used to build `externalConfig` carries the marker, set it on the merged Secret.
3. Add an envtest in the controller suite: a protected `<app>-registry-pull` Secret yields a `bld-<app>-registry-auth` Secret carrying the marker; an unprotected source yields none. Update the F7 godoc so it no longer names this path as a residual.
