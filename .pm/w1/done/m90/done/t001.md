## Objective

Give every agent session one canonical display name the whole UI can render, so no surface has to decide for itself what an untitled session is called. Repo-backed sessions keep showing the repo; repo-less sessions fall back to their task text.

## Context

- The session detail header renders `{session.repo}` directly as its `<h1>`; a repo-less session therefore produces an empty heading. Verified in `dev-1`: `<h1 class="truncate text-sm font-semibold"></h1>`.
- Repo-less is a first-class backend mode, not an edge case: `lego/backend/internal/agentsessions/service.go` `validateCreate` clears `repo`/`branch` and the session runs the prompt in an empty sandbox.
- The recents list already shows the task text as its row title, so the two surfaces currently disagree about what a session is called. Prefer the list's behavior.
- `session.agentConfig.task` is the natural fallback; it is user-authored and can be long (validated up to 100k chars), so it must be truncated for display.

## Steps

1. Add the derivation next to the other agent-session view helpers (a pure function, so it is unit-testable without React).
2. Order: non-empty `repo` → truncated `task` → a last-resort localized "Untitled session".
3. Truncate on a word boundary with an ellipsis; keep the untruncated text available for `title`/tooltip use.
4. Expose it wherever the session view model is assembled so t002–t004 all read one value.

## Files

- `dashboard/src/features/agent-sessions/` — a `lib/` helper plus the type/view-model that carries it
- `dashboard/src/features/agent-sessions/locales/en.ts` and `zh.ts` — the fallback string

## Acceptance criteria

- [ ] A pure exported function maps a session to a display name.
- [ ] Repo-backed → the repo. Repo-less with a task → truncated task text. Neither → the localized fallback.
- [ ] Long task text is truncated for display and the full text stays reachable for a tooltip.
- [ ] Unit tests cover all three branches, asserting the returned string.

## Out of scope

- Rendering it — t002/t003/t004 consume this.
- Letting a user rename a session (no such API field; would be its own milestone).
