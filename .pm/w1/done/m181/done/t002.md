## Objective

The App manifest the operator creates asks for `checks: read` and the check-suite/check-run events, and a service cannot select `checksPass` on an installation that has not granted them.

## Context

- ADR026 §2 (`docs/ADR026-github-integration.md:28-40`): self-hosters create their own App via the manifest flow with `contents:write` + `metadata:read` and the `push` event; existing Apps change permissions in GitHub settings and each installation must accept.
- Installation tokens are minted with explicit permission maps (`lego/backend/internal/github/client.go:217,237`, `pulls.go:64`).
- The webhook handler drops every event but `push` (`lego/backend/internal/apps/webhook.go:307-315`).

## Steps

1. Find the manifest helper and add `checks: read` plus `check_suite` (and `check_run` if t001 needs per-run conclusions).
2. Read the installation's granted permissions; when `checks` is missing, refuse `checksPass` with a coded error naming the permission to grant.
3. Document the update step for an existing App in ADR026.

## Files

- `lego/backend/internal/github/`
- `lego/backend/internal/apps/webhook.go`
- `docs/ADR026-github-integration.md`

## Acceptance criteria

- [x] A new manifest carries the permission and events; selecting `checksPass` on an installation without them returns the coded error on every surface.

## Out of scope

- Changing the production GitHub App's settings — that needs the App owner (record it as a user step if t006 needs it).

## Outcome

Done 2026-10-17. `github.Client.MintChecksToken` asks for `checks:read` + `metadata:read` (a 422 means not granted) and `ListCheckRuns` pages `?filter=latest`. The `checksSource` seam's `ChecksPermitted` also requires the installation to receive `check_suite` events (`Installation.Events`). bex has no manifest helper in code, so ADR026 §2 documents the manifest's `checks:read` + `check_suite` and the steps an existing App and its installations need. Refusals are named on the trigger verb, create, and Blueprint sync.
