# 090 — A webhook's Recent deliveries table names each row's service only by its bare `srv-` id, though every delivery already carries `serviceName`

Why: the delivery history is where an owner works out which service's event failed. A column of opaque ids makes them cross-reference the Services list by hand, while the payload in the same row already says which service it was.

**Absorbed 2026-09-15 into [w2/m96](../../w2/m96/README.md)** — tracked there; this note is closed.

- **Severity:** minor (dashboard display).
- **Found:** live `/qa-find-bugs` hunt of `https://dashboard.bex.co`, 2026-09-14 pass 13 (outbound webhooks journey). Fixtures `qa-20260914-hook` (web service `srv-dajvssq6m8ac739r5vdg`) and webhook `whk-dajvu9ogsm7s73f64gcg` were created and deleted inside the run.

## Repro (every step was run)

1. Create a webhook subscribed to Deploy events, then deploy any service.
2. Open `/webhook/<whk-id>` → **Activity** → **Recent deliveries**. Every row reads `Deploy Started · srv-dajvssq6m8ac739r5vdg · Delivered · 1 · HTTP 200 · …`; the Service column holds only the id.
3. The same delivery's `requestBody` (GraphQL `webhookDeliveries { requestBody }`) is `{"type":"service_suspended","timestamp":"2026-09-14T14:09:58Z","data":{"id":"evt-auf3fo2trcujd3gtdtgj","serviceId":"srv-dajvssq6m8ac739r5vdg","serviceName":"qa-20260914-hook"}}`.

## Root cause

- `dashboard/src/features/webhooks/components/webhook-deliveries-card.tsx:288-290` renders `{delivery.serviceId || "—"}` in a truncated mono cell.
- `WebhookDeliveryView` (`dashboard/src/features/webhooks/types.ts:36-56`) has no `serviceName`, although the delivered payload has one (`lego/backend/internal/webhooks/worker.go:346-349`, kept current across renames by `w6/done/m101`).

## Fix (~40m)

- Show the service's name, linked to the service, with the id as secondary text or tooltip.
- Prefer a `serviceName` field on the delivery view from bex-api, taken from the stored payload, over parsing `requestBody` in the browser. That keeps GraphQL and REST agreeing and works for deleted services, whose name no longer resolves live (the bare-id trap `w1/088` found in Billing).
- Keep the id visible for copy.
- Update the deliveries-card test to assert the name renders and that a delivery for a deleted service still shows its recorded name.
- **Unverified:** what Render's own Recent deliveries view shows in this column (Render's `webhookEvent` API object carries no service name).
- **Dedupe:** `w6/done/m101` (payload `serviceName` after rename) and `w6/done/m115` (read-surface `name` agreement) cover the wire value, not this table. Not fixed on `main` as of `fcb1ef507`.
