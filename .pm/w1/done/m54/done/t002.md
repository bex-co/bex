## Objective

A small `lego/backend/internal/email` package where features compose one `Message` (title, paragraphs, optional CTA, footer lines) and get both renderings from it — `Text()` for the plain part and `HTML()` for the branded part — so the two can never say different things.

## Context

- **Already in the working tree (uncommitted):** `layout.html.tmpl` — table-based, fully inlined styles (Gmail/Outlook constraints), `@token@` placeholders for the brand constants, text "bex" wordmark in `BrandPrimary` (no remote logo image → nothing for clients to block), CTA button + "Or open this link" raw-URL fallback, footer over a border-top, "Sent by bex" outside the card.
- Brand placeholders are substituted into the template **text before parsing** (`strings.NewReplacer` at init) so `html/template`'s CSS value filter never sees them; only user data flows through template escaping (paragraphs/title HTML-escaped, CTA URL through the href filter).
- `Text()` layout contract (drives t004/t005 byte-parity): sections = paragraphs, then `CTA.Lead + ":\n" + CTA.URL`, then footer lines; joined with `\n\n`, trailing `\n`.
- Multiline paragraphs (the deploy email's `Commit:\n<msg>`) render as `<br />`-joined lines in HTML — pass paragraphs to the template pre-split into lines.
- Boilerplate header from `lego/operator/hack/boilerplate.go.txt` on new Go files.

## Steps

1. Write `email.go`: `type CTA {Lead, Label, URL string}`, `type Message {Title string; Paragraphs []string; CTA *CTA; Footer []string}`, `Text() string`, `HTML() string` (embed the template via `//go:embed`; a template-exec error — practically impossible with this data shape — degrades to `""`, i.e. text-only send).
2. Write `email_test.go`: exact-text pin for an invite-shaped message; HTML assertions — user data `<script>` escaped, brand hex present, CTA href + label, multiline paragraph → `<br />`, no-CTA/no-footer shapes render.
3. `go build ./... && go test ./internal/email/` from `lego/backend`.
