## Objective

`mailer.SMTP` learns to send `multipart/alternative` — plain text plus HTML — while an empty HTML body keeps today's single-part message byte-identical, so senders that haven't migrated (or a failed HTML render) degrade cleanly.

## Context

- Current `Send(ctx, to, subject, body)` builds a single `text/plain` RFC 5322 message (`lego/backend/internal/mailer/mailer.go:74-95`). The seam is duplicated as narrow per-feature interfaces in `members`, `notifications`, and `webhooks` — all four signatures change together (features in t004–t006; `mailer.SMTP` keeps satisfying all three structurally, so `internal/api/server.go` / `cmd/api/main.go` wiring is untouched).
- MIME boundary must be random (crypto/rand): part content includes tenant-controlled strings (workspace names, commit messages, webhook URLs); a predictable boundary would allow MIME-part injection.
- The HTML part needs `Content-Transfer-Encoding: quoted-printable` (`mime/quotedprintable`) — rendered HTML lines exceed SMTP's 998-byte line limit.
- While in here, close two latent header bugs: subject sanitization strips `\n` but not `\r` (CRLF injection), and non-ASCII subjects (unicode workspace names) go out raw instead of RFC 2047 (`mime.QEncoding` — leaves ASCII untouched, so the existing `Subject: You're invited` test assertion still holds). Sanitize To/From the same way.
- Existing tests: `mailer_test.go` (envelope bare-address, CRLF normalization, PLAIN auth) — update call sites, keep every current assertion passing.

## Steps

1. Change `Send` to `Send(ctx context.Context, to, subject, text, html string) error`; `html == ""` ⇒ exactly today's single-part bytes.
2. Multipart path: `Content-Type: multipart/alternative; boundary="<random>"`; text part as today (CRLF-normalized UTF-8), HTML part QP-encoded; closing boundary.
3. Add `headerSafe` (strip `\r`/`\n`) applied to From/To/Subject and `mime.QEncoding.Encode("utf-8", subject)`.
4. Update tests; add: multipart message parses with `net/mail` + `mime/multipart`, both parts present in order (text first — last part wins in clients), QP round-trip recovers the HTML, boundary differs across sends, and a CRLF-embedded subject cannot inject a header.
