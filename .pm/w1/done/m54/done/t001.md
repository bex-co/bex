## Objective

Make the dashboard palette the single source of truth for email branding: a node script converts the light-theme `:root` tokens in `dashboard/src/style.css` (oklch colors, `--radius`, font stack) into committed Go constants in `lego/backend/internal/email/brand_gen.go`, and the dashboard test suite fails when the two drift.

## Context

- **Already in the working tree (uncommitted):** `dashboard/scripts/generate-email-brand.mjs` (parses `style.css`, Ottosson oklch→sRGB hex conversion, gofmt-clean `renderGo`, `--check` mode) and the generated `lego/backend/internal/email/brand_gen.go` (verified gofmt-clean; `BrandPrimary = "#307d03"`).
- Email clients support neither CSS custom properties nor `oklch()` — hence baked hex, not shared CSS.
- The generated file must be **committed** because `lego/` is a self-contained Docker build context (never sees `dashboard/`); same generate-and-commit pattern as operator codegen.
- ESLint only lints `**/*.{ts,tsx}` — a plain `.mjs` script matches the `scripts/local-bex.mjs` precedent. Vitest's default include picks up `scripts/__tests__/*.test.mjs`; `tsc` does not (scripts/ is outside the app tsconfig), so a `.test.mjs` test avoids typecheck friction.
- Dashboard CI (`.github/workflows/dashboard-test.yml`) runs `yarn test` on every `dashboard/**` change — exactly when `style.css` can change.

## Steps

1. Add `"generate:email-brand": "node scripts/generate-email-brand.mjs"` to `dashboard/package.json` scripts.
2. Write `dashboard/scripts/__tests__/generate-email-brand.test.mjs`: import `generate`/`oklchToHex` from the script; assert `generate(readFileSync(style.css))` equals the committed `brand_gen.go` byte-for-byte (the drift gate), and sanity-check the conversion (e.g. `oklch(0.52 0.16 138.3)` → a green: g channel dominant; `oklch(1 0 0)` → `#ffffff`).
3. Run that test file plus `yarn lint` to confirm nothing new is flagged.
