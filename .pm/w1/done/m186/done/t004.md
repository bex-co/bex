## Objective

Prove the Definition of done on a real CAPI roll: zero failed requests for a single-instance App, the bound releases a stuck replacement, and the admission boundary holds.

## Context

- Local cluster: `bash scripts/mock-cluster.sh` (pre-approved), `kind-bex-mgmt` with CAPI in `default`, workload kubeconfig `infra/local/bex.kubeconfig`.
- drain-guard can run from the host against both clusters (`--capi-kubeconfig`).

## Steps

1. Run a single-replica App-shaped Deployment on the tenant pool. Make sure a second schedulable tenant node exists (`mock-cluster.sh scale`).
2. Run drain-guard, start a request loop against the Service, then delete the tenant Machine that hosts the pod. Record every response, the replacement's Ready time, and the moment CAPI starts draining.
3. Repeat with a replacement that can never become Ready, using a short `--max-hold`. The hook must release at the bound.
4. Apply the admission policy and RBAC. Use `kubectl --as` to show that the identity's three writes pass and other writes are denied, and that `auth can-i get secret -n <capi ns>` prints `no`.
5. Clean up the fixtures.

## Files

- `.pm/w1/m186/t004.md` (evidence)

## Acceptance criteria

- [x] Zero failed responses across the roll. The replacement was Ready before the drain.
- [x] The bound released the hook.
- [x] The admission probes behave as stated. Fixtures are deleted.

## Out of scope

- A production roll. The next routine `bex-tenant-0` roll exercises it, and the runbook says what to watch.

## Evidence (2026-10-26 UTC, local CAPD mock)

**Setup**

- Cluster: `kind-bex-mgmt`, CAPI v1.13.4 + CAPD. Machines are in `default`; the workload cluster runs Kubernetes 1.36.1 with Calico IPIP.
- drain-guard ran from the host: `--machine-namespace=default`, `--machine-selector=topology.cluster.x-k8s.io/deployment-name=tenant-0`, with `--capi-kubeconfig` pointing at mgmt.
- It hooked every tenant Machine and none of the control-plane or platform Machines.
- Fixture `probe`:
  - a single-instance, App-shaped Deployment: `app.bex.co/app: probe`, `traefik/whoami`, readiness on `/`, a preStop sleep;
  - pinned to `bex.co/pool=tenant`, behind a Service.
- Request loop `loop`:
  - runs on the platform worker;
  - fetches the Service every 0.2s with a 2s timeout;
  - logs every failure and a running total.

**Round 1: pool full, so the replacement needs a new node (the 2026-10-24 shape).** A spacer's required anti-affinity kept the replacement off the only other tenant node.
