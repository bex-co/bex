## Objective

Build `drain-guard`, the small controller behind the pre-drain hook. It puts the hook on every guarded Machine. When a guarded Machine is deleted, it moves that Machine's at-risk bex App pods to other nodes, then releases the hook so CAPI's drain finds nothing left to take down.

## Context

- CAPI does not drain a deleting Machine while any `pre-drain.delete.hook.machine.cluster.x-k8s.io/*` annotation remains, and it does not cordon it either (CAPI v1.13, prod clusterctl v1.13.2).
- Production manages itself: Machines (`bex-capi`), Nodes and App Deployments are all in one cluster (`docs/ADR002-architecture.md:45`). The local mock keeps CAPI in `kind-bex-mgmt` (namespace `default`) and the workload in `infra/local/bex.kubeconfig`.
- App Deployments are named after their App and selected by `app.bex.co/app`. With one replica, the default RollingUpdate is maxSurge 1 / maxUnavailable 0 (`docs/ADR004-app-deployment.md:445`). Disk Apps use `Recreate` (`lego/operator/internal/controller/disk.go`).
- The operator keeps pod-template annotations it does not own (`deployment_projection.go:595-629`).

## Steps

1. Add `lego/operator/internal/drainguard` (pure decision code plus a reconciler) and `lego/operator/cmd/drain-guard/main.go`. Flags: `--machine-namespace`, `--machine-selector`, `--capi-kubeconfig` (empty means in-cluster), and `--max-hold` (10m).
2. Hook: on every Machine that matches the selector and is not being deleted, ensure the hook annotation is present.
3. Deleting Machine that still carries the hook:
   - Release at once if there is no `nodeRef`, the Node is missing or not Ready, or `max-hold` has passed since `deletionTimestamp`.
   - Otherwise cordon the Node. Find each bex App Deployment with a Ready pod on that Node and no Ready pod on any other node.
   - For each such Deployment that is rolled out and uses RollingUpdate, set `drain-guard.bex.co/evacuated-from=<node>` on its pod template.
   - Release when no Deployment is at risk. Otherwise requeue.
4. Log each decision with the Machine, Node and Deployments involved.
