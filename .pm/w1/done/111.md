# 111 — Paid-only private services

Why: private services should follow Render plan eligibility consistently across APIs, Blueprints and the dashboard.

**Worker:** worker1. **Status:** todo. **Estimate:** 55m. **Source:** transferred from w4/152; approved 2026-09-28.

## Decision and scope

The user approved the Render-parity option; the historical product-decision blocker below is resolved. Render excludes private services from Free instances ([current guidance](https://render.com/docs/your-first-deploy#explore-other-service-types), checked 2026-09-28). Extend the existing worker policy, without silently converting existing Free private services into paid resources.

1. Extend `normalizeTierForType`, SetPlan/PreviewSetPlan and type-aware Blueprint pricing/payment checks in `lego/backend/internal/apps/`.
2. Update `dashboard/src/features/services/lib/instance-type.ts` and create-form defaults so private services cannot select or carry over Free.
3. Apply the existing worker transition-policy pattern to existing Free private services, recording it in ADR030 section 7 and ADR018.
4. Cover create, downgrade, Blueprint and UI defaults with meaningful regressions.

## Acceptance

- New private services default to the cheapest eligible paid rung; explicit Free creation/downgrade fails consistently through REST, GraphQL, MCP and Blueprint.
- Pickers and payment/pricing previews agree with backend eligibility.
- Existing Free resources have an explicit transition policy and are not silently charged.
- Web-service Free behavior stays supported. User direction (2026-09-28): where behavior is uncertain, verify the Render contract and keep parity; do not introduce an undocumented divergence. Existing explicit non-goals remain out of scope.

## Resolved 2026-09-28 (`/loopx w1`)

**Render contract re-verified before writing code** (the note's standing direction):
Render sells a private service only on paid instances
([explore other service types](https://render.com/docs/your-first-deploy#explore-other-service-types),
checked 2026-09-28). So option (a), Render parity, is what shipped.

**The divergence was one constant.** `normalizeTierForType`
(`lego/backend/internal/apps/service.go`) special-cased `TypeBackgroundWorker`
alone, which is why a plan-less `private_service` came out `free` while a plan-less
`background_worker` came out `starter` — from the same function, in the same QA pass.
Replaced with a **two-type allowlist**, `paidOnlyServiceType`, deliberately *not*
"everything but web": web services and cron jobs keep free because Render sells both
that way, and a static site runs no instance at all.

**Four seams, all of which already funnelled through shared code:**

| seam | function | surfaces covered |
| --- | --- | --- |
| create | `normalizeTierForType` | REST `POST /v1/services`, GraphQL `createService`, MCP `create_web_service`, Blueprint apply/validate (via `specFromCreate`) |
| plan change | `checkPlan` (`settings_check.go`) | REST `PATCH`, GraphQL `updateServicePlan`, MCP `update_service` |
| plan-change dry run | `PreviewSetPlan` | the same, previewed |
| Blueprint probes | `stackHasPaidPlan`, `blueprintEstimatedPricing` (both call `normalizeTierForType`) | ADR046 payment gate + pricing |

**The refusal now names the type the caller asked for.** `errWorkerFreePlan` was
renamed `errFreePlanForType(svcType)` and interpolates the type, because a
private-service author receiving "a background_worker requires a paid plan" is sent
to the wrong docs.

**Dashboard.** `offeredInstanceTypes` now filters a `PAID_ONLY_SERVICE_TYPES` set, so
the create grid, the create default and the instance-type picker all follow from one
place, and a Free selection made under another type still does not survive a switch
into a paid-only one (`use-new-service-form.ts` derives its override from the same
filtered list). Presentation only — the backend refuses regardless.

**Existing free private services: census run, and it is empty where this identity can
see.** ADR030 §7 requires identifying them before rollout. `GET /v1/services?type=private_service`
across all three workspaces this QA identity can reach
(`tea-d98210cbbpdc73dcrkvg`, `tea-da2isimlm39c739m4ofg`, `tea-daif693dqjvc73e7as3g`)
returned **zero private services**, so there is nobody to notify and nothing at risk
of silent charging in those. **This is not a complete census** — the identity sees 3
workspaces and the platform has ~17 — so the authoritative step remains the
control-plane SQL recorded in ADR030 §7, which only the operator can run:

```sql
SELECT id, name, tenant_id, type FROM apps
WHERE type IN ('background_worker', 'private_service') AND (tier = '' OR tier = 'free');
```

Enforcement is new-writes-only either way: an existing free private service keeps
running and is never auto-converted.

**Tests.** New `lego/backend/internal/apps/private_service_plan_test.go`: plan-less
create defaults to `starter`; explicit `free` refused at create and named
`private_service`; `SetPlan` and `PreviewSetPlan` refuse the downgrade without
changing `spec.tier`, while `starter` stays open;
`TestPaidOnlyServiceTypesAreExactlyTwo` pins the allowlist against all five types;
`TestFreeKeepingTypesStillAcceptFree` is the control. Dashboard: a private-service
picker case mirroring the worker one, plus a `cron_job` control proving Free was not
narrowed further.

**Suites.** Full backend `go test ./...` green; full `dashboard/yarn vitest run` green
(451 files / **3757** tests); `yarn typecheck` and `eslint` clean.

**Docs.** ADR030 §7 retitled and extended (decision, the four seams, generalized
refusal, and a transition query covering both types); ADR018's worker row records the
extension and the two guard tests.
