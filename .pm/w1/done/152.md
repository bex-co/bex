# A sandbox group's sandboxes, snapshots, builds and shell in the dashboard

Why: Render's dashboard shows a sandbox group's running sandboxes, their snapshots and builds, and opens a shell into a sandbox; bex serves all of it on REST, GraphQL and MCP but its dashboard has only the group's create dialog, credentials and environment.

- **Found:** w1/m645's dashboard ledger (2026-11-26): the 19 `gap` rows in [dashboard-operations.md](../../../docs/render-artifacts/dashboard-operations.md#sandboxes) (`sandboxesForGroup`, `sandboxDetails`, `sandboxEvents`, `SandboxSnapshots`, `SandboxBuilds`, `CreateSandboxShellSession`, `terminateSandbox`, `DeleteSandboxSnapshot`, `SandboxGroupRunningCount`, their subscriptions and resource redirects).
- **Render (bundle, no flag):** a sandbox group page lists its sandboxes with live updates (`sandboxesForGroupUpdated`), each sandbox's details and events, the group's snapshots and builds, a running count, a shell session (`createSandboxShellSession`, gated by `sandboxGroupShellPermission`), terminate and snapshot delete.
- **bex:** `dashboard/src/features/sandbox-groups/` has the create dialog, the credentials panel and the environment field. The data is served: [ADR104](../../../docs/ADR104-sandbox-render-parity.md), GraphQL `sandboxes`, `sandboxSnapshots`, `sandboxImages`, `terminateSandbox`, `sandboxExecutions`.
- **Done when:** bex's sandbox group page shows its sandboxes (live), each sandbox's details and events, its snapshots and builds, with terminate, snapshot delete and a shell where Render offers them, verified on production; or a recorded divergence. More than an hour: promote to a milestone.
