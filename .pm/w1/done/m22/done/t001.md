## Objective

Provision a replicated (HA) CNPG cluster when the `Database` CR requests high availability: a primary + one or more standbys with replication, spread across nodes. Single-instance DBs must stay single-instance (no behavior change). **First**, capture Render's Postgres OpenAPI as the parity reference so the CR/API shape is verified against evidence, not asserted — the whole milestone's field names hang off this.

## Context

- `docs/ADR009-postgresql-management.md`: `Database` CR → CNPG `Cluster`; today `highAvailabilityEnabled: false` (single instance).
- CNPG natively supports `instances: N` with sync/async replication + anti-affinity; m19's multi-node substrate (platform/tenant pools) is what makes spreading standbys real.
- Plans (m8/m17) — decide which plans allow HA (likely Standard+); gate accordingly.
- **Render parity (verified 2026-07-12 against `api-docs.render.com`):** create body has `enableHighAvailability` (bool, default `false`) **and** `readReplicas` (array of objects) as two independent fields; read model reports `highAvailabilityEnabled`; failover is `POST /v1/postgres/{postgresId}/failover` → `202` (no `promote`). Capture the real spec so t002–t004 match it exactly.

## Steps

0. Capture Render's Postgres OpenAPI (from `api-docs.render.com/openapi/render-public-api-1.json`) into `docs/render-artifacts/` — the Postgres create/read schemas + failover/read-replica endpoints — as the milestone's parity reference.
1. Add `spec.highAvailability` (+ replica count / sync mode) to the `Database` type in `lego/types/`. Keep read replicas as a **separate** field (`spec.readReplicas`, t003), not under the HA toggle — mirroring Render's two independent fields.
2. Map it to CNPG `instances`, replication mode, and pod anti-affinity across nodes.
3. Keep single-instance the default; regenerate deepcopy/CRD.
