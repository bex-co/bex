## Objective

Provide a `failover` operation that triggers a CNPG switchover (promote a standby to primary internally) and reflects the new primary in status. Matches Render's `POST /v1/postgres/{postgresId}/failover` → `202` (async). **Render has no `promote` verb** — failover is the only operation; don't invent one.

## Context

- CNPG exposes switchover/promotion (target primary annotation / plugin action); the operator drives it.
- The primary connection service must keep pointing at the current primary after switchover (CNPG `-rw` service already does this — verify).
- Render's failover returns `202` with no body; reporting the current primary + last-failover time in Database status is a bex superset extension (Render clients ignore it), not part of the failover response shape.

## Steps

1. Add a `failover` action on the Database (verb/annotation) that instructs CNPG to switch primary.
2. Surface the current primary + last-failover time in Database status.
3. Ensure the read-write URL continues to resolve to the new primary post-switchover.

## Files

## Acceptance criteria

- [ ] Triggering failover promotes a standby; status reports the new primary; the `-rw` endpoint follows.
- [ ] No data loss for committed writes under a clean switchover (envtest/integration as feasible).
