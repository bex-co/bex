## Objective

Model read replicas as Render does: a `spec.readReplicas` array of **named** replica entries (`[{name}]`), each yielding its own read-only connection URL, distinct from the primary read-write URL. **Independent of the HA toggle** — a DB may declare read replicas without `enableHighAvailability` (Render's two-field model); do not gate replicas on HA.

## Context

- Render's `readReplicas` is a create-body array of named objects; each replica is an addressable resource with its own name + connection string (not a single shared read-only endpoint). Match that shape.
- CNPG provides a `-ro`/`-r` service that load-balances across standbys, and supports declaring additional read-replica instances; use whichever mechanism lets each **named** replica resolve to a read-only endpoint.
- External hostnames follow the existing `BEX_DB_DOMAIN` Traefik TCP/SNI pattern (`<name>.<domain>`); internal is the in-cluster service DNS.
- Credentials/roles reuse the existing DB access model (m17).

## Steps

1. Add `spec.readReplicas` (array of named entries) to the `Database` type; each entry maps to a read-only CNPG endpoint. Regenerate deepcopy/CRD.
2. Construct internal + external (SNI) read-only URLs **per named replica**; add them to Database status keyed by replica name, alongside the primary URL.
3. Gate external replica hostnames on `BEX_DB_DOMAIN` (internal-only otherwise), mirroring the primary.

## Files

## Acceptance criteria

- [ ] A DB with `readReplicas: [{name: …}]` reports a read-only URL per named replica that connects and serves reads; writes against them are rejected (read-only).
- [ ] Read replicas work with `enableHighAvailability` both on and off (not coupled to HA).
- [ ] External replica hostname present only when `BEX_DB_DOMAIN` is set.
