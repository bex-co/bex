## Objective

Make Render's workspace-scoped URLs land: `/w/settings` → `/workspace/settings` (current workspace, mirroring Render's own id-less canonicalization); `/w/{tea-id}/settings` → workspace settings **with the context switched to that workspace**; `/w/{tea-id}/billing` → `/usage` (bex's deliberate usage-not-billing counterpart, ADR023); `/billing/update-plan` → `/workspace/settings?plan=change` (the plan-change dialog exists; billing itself stays a non-goal).

## Context

- The deep part: bex's workspace pages are **switcher-driven** (`WorkspaceProvider`, `useWorkspace()` — the switcher's selection, not the URL, decides the workspace). A bare redirect would silently show a different workspace whenever the switcher points elsewhere — the confused-deputy shape the backend's `resolveWorkspace` explicitly refuses. So the alias must SET the selection from the URL: extend the workspace context with a `selectWorkspace(id)` the route can call (membership implicitly checked — the switcher's `workspaces` query only returns memberships; an id not in the list ⇒ show the 404/denied state, never fall back to the caller's own).
- Alias mechanics precedent: `src/common/lib/render-alias.ts` + `web.$.tsx` siblings (w5/m39) — but those are pure `beforeLoad` redirects; this one needs the provider, so it likely renders a tiny component that selects-then-navigates rather than throwing `redirect` in `beforeLoad`.
- How the switcher persists selection today: check `src/features/workspaces/context/` (is it state-only or persisted?) and reuse its mechanism.
- Render evidence: t001's artifact section.

## Steps

1. Add `w.$.tsx` parsing `settings | {tea-id} | {tea-id}/settings | {tea-id}/billing` splats.
2. Id-less forms → `/workspace/settings` directly.
3. Named forms: select the workspace via the context; unknown/foreign id → the existing not-found treatment (never silent fallback); then land on `/workspace/settings` (or `/usage` for billing).
4. Add `billing.update-plan` (or a `billing.$` splat) → `/workspace/settings?plan=change`; any other `/billing/*` sub-path → `/usage`.
5. i18n any new user-visible denied/not-found copy.

## Acceptance criteria

- [ ] `/w/settings`, `/w/{own-tea-id}/settings` (context switched), `/w/{own-tea-id}/billing` → `/usage`, `/billing/update-plan` → plan dialog — all land correctly on a dev-N stack with two workspaces.
- [ ] A `tea-id` the caller is not a member of shows the not-found/denied state — the settings page of the caller's own workspace is never shown under a foreign id's URL.
- [ ] Query string + hash survive the redirects (the m39 alias contract).

## Out of scope

- A billing page (non-goal; `/usage` is the landing).
- Making other workspace pages URL-parameterized (only the alias selects; canonical routes stay switcher-driven).
