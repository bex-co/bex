## Objective

On a service page Render replaces the global sidebar with a **resource-scoped** one (live capture, 2026-07-16): a "Dashboard" back link (`/`), then Events, Settings, group **Monitor** — Logs, Metrics; group **Manage** — Environment, Shell, Scaling, Previews, Disk, One-Off Jobs. There is no "Deploys" entry — the service ROOT is the deploy history. bex instead keeps the global sidebar and renders a horizontal `ServiceNav` tab strip (Events/Deploys/Environment/Logs/Metrics/Scaling/Settings + bex-only Plan). Convert the service detail to Render's sidebar-swap pattern.

## Context

- The swap mechanism already exists: `dashboard-sidebar.tsx` returns `<ProjectSidebar/>` when `projectId` is in params — add the service sibling keyed on `serviceId` (a `ServiceSidebar` presenting the existing `service-nav.tsx` items in Render's grouping).
- Item mapping: back link → `/`; Events, Settings top-level; Monitor{Logs, Metrics}; Manage{Environment, Scaling}. **Deploys**: bex's service root already redirects to Deploys (w5/m36) — mirror Render by making the sidebar's service-name/header the root link and keeping a Deploys entry only if dropping it hurts discoverability (decide, note the choice). **Plan** (bex-only, no Render inbound shape) joins Manage. **Shell/Previews/Disk/One-Off Jobs are DO_NOT_DO non-goals** — omit, record.
- Decide the datastore question with the same lens: Render gives Postgres pages tabs (Info/Logs/Metrics/Recovery — dashboard-walk/datastores.md); bex's consolidated `?tab=` detail was ruled "IA-only, not a gap" by the m32 walk. Leave datastores as-is; record that the earlier ruling stands (or file a note if this task's work changes the calculus).
- Mobile/collapse behavior must survive (the sidebar kit's `collapsible="offcanvas"`).

## Steps

1. `ServiceSidebar` in `dashboard-layout/` fed by the `service-nav.tsx` item list (one source of truth — the tab strip's ITEMS move to a shared module; don't fork the list).
