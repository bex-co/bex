## Objective

Add control-plane storage for Projects: a workspace-scoped `projects` table, plus a nullable `project_id` reference on the apps/services row.

## Context

- Control-plane store lives behind `BEX_CP_DB_URI` (`docs/ADR003-control-plane.md`).
- Mint the id through `lego/backend/internal/id` (`id.New(kind)`), register a new `id.Kind` (`docs/ADR020-identifiers.md`).
- A service with `project_id = NULL` stays ungrouped, matching Render's "services list shows both grouped and ungrouped" dashboard shape.

## Steps

1. Design `projects` columns: id, workspace/owner id, name, created_by, created_at, updated_at.
2. Add a nullable `project_id` foreign key column to the apps/services table.
3. Write the migration.

## Files

- `lego/backend/internal/store/migrations/` (new migration)
- `lego/backend/internal/id/` (register the new id.Kind)
- new `lego/backend/internal/projects/` package (model + store access)

## Acceptance criteria

- [ ] Migration applies cleanly against a real Postgres.
- [ ] Project ids follow the `<prefix>-<xid>` convention and are registered in `internal/id`'s guard test.
