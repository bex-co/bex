## Objective

Check whether bex-api's MCP service exposes an events-listing tool. If not, add one so MCP has REST/GraphQL parity for the service-events feed.

## Context

- REST: `GET /v1/services/{id}/events`
- GraphQL: `serviceEvents(serviceId, type, startTime, endTime, cursor, limit)`
- MCP: **need to verify**

bex-api MCP implementation is in `lego/backend/internal/mcp`. Feature package for events is `lego/backend/internal/events`.

## Steps

1. Search `lego/backend/internal/mcp/` for any reference to "events" or "list_service_events" tool
2. Check `lego/backend/internal/events/service.go` for the public `List` method signature
3. If no MCP tool exists, add one following the pattern of other MCP list tools (e.g., `list_services`, `list_postgres_instances`)
4. Match the tool's arguments to REST/GraphQL: `serviceId`, `type?`, `startTime?`, `endTime?`, `cursor?`, `limit?`
5. Return the same event schema as GraphQL (id, timestamp, type, details, cursor)
6. Write a small integration test calling the tool end-to-end

## Files

- `lego/backend/internal/mcp/tools.go` (or equivalent MCP handler)
- `lego/backend/internal/events/mcp.go` (new file if no MCP adapter exists)
- `lego/backend/internal/events/mcp_test.go` (test)

## Acceptance criteria

- [ ] MCP tool `get_service_events` or `list_service_events` exists
- [ ] Tool accepts serviceId, type, startTime, endTime, cursor, limit arguments
- [ ] Tool returns `{events: [{id, timestamp, type, details, cursor}], cursor: string}`
- [ ] Tool result matches REST/GraphQL shape byte-for-byte
- [ ] Integration test passes
