## Objective

Consolidate the separate `DeploysListPage` and `ServiceEventsPage` into one unified Events page that displays both deployment records and audit events in a single newest-first timeline, matching Render's UX.

## Context

Currently:
- `/services/$serviceId/events` shows lightweight events (deploy_started, deploy_ended, config changes, suspensions)
- `/services/$serviceId/deploys` shows detailed deploy records with commit info, filtering, and pagination
- Both are separate React components with separate data fetches

Target:
- Single `/services/$serviceId/events` page that shows everything
- Rich deploy rows (commit, image, duration, status) alongside audit rows (config change, suspension, etc.)
- Filtering/pagination on the unified stream

## Steps

1. Review the existing `ServiceEventsPage` component in `dashboard/src/routes/services.$serviceId.events.tsx`
2. Merge the rich deploy-row layout from `DeploysListPage` into the Events list
   - Use the enriched GraphQL data from t003 to populate deploy rows
   - Keep audit rows lightweight (actor, type, timestamp)
3. Update the Events GraphQL hook to fetch the enriched query
4. Render deploy rows with:
   - Status badge (created, live, failed, canceled, etc.)
   - Image hash or tag
   - Commit (if available) with link to GitHub
   - Duration (startedAt → finishedAt)
   - Trigger label (manual, git-push, deploy-hook)
   - Action buttons (cancel if active, rollback if applicable)
5. Render audit rows with:
   - Event type (config_changed, suspender_added, etc.)
   - Actor (identity/email)
   - Target resource and what changed
   - Timestamp
6. Maintain pagination and cursor behavior from the existing Events page
7. Add optional filtering by event type (if Render supports it; else defer to t006)

## Files

- `dashboard/src/routes/services.$serviceId.events.tsx` (main page merge)
- `dashboard/src/features/events/components/` (create or reuse from deploys)
- `dashboard/src/features/events/hooks/use-service-events.ts` (enrich the query)

## Acceptance criteria

- [ ] Single Events page shows deploy records with commit, image, trigger, duration
- [ ] Audit events (config changes, suspensions) also appear in the same list
- [ ] Newest-first ordering preserved
- [ ] Deploy rows include action buttons (cancel, rollback) where applicable
- [ ] Pagination works across the merged stream (not separate pages)
- [ ] No layout regressions in adjacent pages (Settings, Logs, Metrics, etc.)
- [ ] Page renders on dev-1 without errors

## Out of scope

- Removing the old Deploys page (next task)
- Advanced filtering UI (defer to backlog if Render doesn't have it)
- Analytics/instrumentation (generic task)
