## Objective

Clean up navigation by removing the separate Deploys tab now that Events is the unified view. Optionally keep the detail route (`/services/{id}/deploys/{deployId}`) as an internal link target, or redirect it to the Events page with a deploy-id anchor/filter.

## Context

The service navigation tab strip (in `service-nav.tsx`) currently shows:
1. Events
2. Deploys ← remove this
3. Settings
4. Monitor group (Logs, Metrics)
5. Manage group (Environment, Scaling, Plan)

After t004, Deploys becomes redundant since Events shows the same data.

## Steps

1. Remove the `"Deploys"` tab entry from `dashboard/src/features/services/components/service-nav.tsx`
2. Update any hardcoded links to `/services/$serviceId/deploys` elsewhere in the codebase to point to `/services/$serviceId/events`
3. Decide on the deploy detail route:
   - Option A: Keep `/services/$serviceId/deploys/$deployId` as an internal redirect to `/services/$serviceId/events?deployId=$deployId` (requires Events page to support a `deployId` query param to auto-scroll/highlight)
   - Option B: Delete the route entirely and rely on the detail modal or inline expansion in Events
   - Recommend Option A for backward compatibility
4. Search for any other references to the deploys route (breadcrumbs, action links, etc.) and update
5. Verify no navigation regressions in the live dev-1 instance

## Files

- `dashboard/src/features/services/components/service-nav.tsx`
- `dashboard/src/routes/services.$serviceId.deploys.*.tsx` (delete or repurpose as redirect)
- (search for hardcoded deploy-page links in the entire dashboard)
