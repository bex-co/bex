## Objective

Close the uncollectable-invoice hole (ADR046 §6): the meter-event emitter ships a workspace's sealed rows only once it is payment-bound or comped, so no Stripe Customer/Subscription is auto-provisioned for card-less free workspaces and no invoice can exist that has no card behind it. Sealed rows stay in the durable outbox; binding a card back-bills within the 34-day `BackfillHorizon`, older card-less history falls off the floor by design.

## Context

- Today `Emitter.ensureBillingSetup` (`internal/billing/emitter.go` ~293–302) runs `EnsureCustomer` + `EnsureContract` for **any** workspace whose rows ship; Mode A (`billing_excluded`) is filtered by the store query before that point; Mode B (`billing_comped`) must **keep** shipping (its coupon zeroes the invoice — `CompCustomer` ensures the contract on comping).
- The withhold belongs at row selection (store outbox query joining the t002 marker + `billing_comped`), not as a per-row Stripe-side skip — withheld rows must stay un-stamped (`emitted_at` NULL) so they ship later.
- Existing emitter metrics (`BillingExportStats`) should keep counting withheld rows as pending-not-yet-exportable, not as errors; log the withheld-workspace count once per pass (no-silent-caps convention).
- Sealing/idempotency invariants (ClampSealHours, deterministic event ids) are untouched.

## Steps

1. Extend the outbox selection to `bound OR comped` workspaces only (Mode A exclusion unchanged).
2. Verify `ensureBillingSetup` is now reachable only for workspaces that passed the filter; `CompCustomer` remains the comp path's contract-creation point.
3. Tests: card-less workspace rows never ship and never stamp `emitted_at`; after stamping the marker they ship on the next pass; comped workspaces ship throughout; a row older than `BackfillHorizon` at bind time is floored exactly as an epoch-floored row is today.
4. Update `docs/ADR040-billing-metronome.md` §3/§7 with a one-line cross-ref to ADR046 §6 (export precondition).
