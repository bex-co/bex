## Objective

Define the one seam feature packages consult before allowing paid intent: a small `PaymentGate` abstraction implemented by `internal/billing` (marker read + Mode A/B exemptions), wired at the composition root, enabled only by a new `BEX_REQUIRE_PAYMENT_METHOD` env var that refuses to start without `BEX_STRIPE_SECRET_KEY`. Unset ⇒ nil gate ⇒ byte-identical behavior.

## Context

- Pattern precedent: injected source funcs (`logs.PodLogSource`, `metrics.ResourceMetricsSource`) keep feature services free of cross-feature imports; `apps`/`postgres`/`keyvalue` must consume the gate without importing `internal/billing` (backend/CLAUDE.md dependency rules).
- The gate's answer for a workspace: allow if marker set (t002) OR `billing_excluded` OR `billing_comped`; deny otherwise. One local SELECT, no Stripe call (ADR046 §3).
- Env-gating precedent: every billing feature keys off `BEX_STRIPE_SECRET_KEY`; requiring a card nobody can add would brick creates, hence the startup refusal.
- Repo rule: `.env.example` mirrors `.env` variable names; CLAUDE.md has the env table.

## Steps

1. Define the gate type where features can see it (e.g. `core` or a leaf shared type): `RequirePaymentMethod(ctx, workspaceID) error` returning a typed sentinel (e.g. `core.ErrPaymentRequired`) when unbound.
2. Implement in `internal/billing` over the t002 store read + exemption columns.
3. Wire in `cmd/api` / `internal/api/server.go`: construct only when `BEX_REQUIRE_PAYMENT_METHOD=1`; fail startup if set while `BEX_STRIPE_SECRET_KEY` is unset (or while `BEX_CP_DB_URI` is unset — no store, no marker).
4. Add the env var to `.env.example` (name + comment, no value) and the CLAUDE.md bex-api env table.

- [ ] Gate denies an unstamped workspace, allows stamped / excluded / comped ones (unit test against the store fake).
