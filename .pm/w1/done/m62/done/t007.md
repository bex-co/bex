## Objective

Make the forced step feel like interception, not a wall (ADR046 §5): when a create flow or plan picker hits the 402 (or a precheck shows `PaymentMethodReady: false`), the dashboard opens the existing `BillingOnboardingView` flow in place, polls `workspaceBillingReadiness` until `PaymentMethodReady` flips (the webhook, not the success redirect, is proof), then resumes the interrupted action.

## Context

- Reuse: `dashboard/src/features/usage/components/billing-onboarding.tsx` (`BillingOnboardingView`) + `useBillingOnboarding` (GraphQL `workspaceBillingReadiness`, `createBillingCheckoutSession`); the `/usage` mounting stays.
- Interception points: service create flow + plan tab (`services.$serviceId.plan`), Postgres create/plan, Key Value create/plan — wherever a paid tier can be chosen.
- The GraphQL error arrives as `extensions.code = PAYMENT_REQUIRED` (t004); catching it is the robust path (precheck is an optimization, not the gate).
- Checkout opens in a new tab (Stripe-hosted, `BEX_DASHBOARD_URL` success/cancel); poll readiness with backoff after return focus; webhook latency means the redirect alone proves nothing.
- Every user-visible string through `useTranslations()` with `en`+`zh` locale entries (dashboard/CLAUDE.md).

## Steps

1. A shared hook/component (e.g. `usePaymentRequiredGate`) that wraps a mutation call: catches `PAYMENT_REQUIRED`, opens the onboarding dialog, polls readiness, retries the original mutation on success.
2. Wire it into the paid-capable create/plan flows for services, Postgres, and Key Value.
3. Locale keys (en + zh) for the interception copy.
4. Vitest coverage: 402 → dialog → readiness flip → original mutation retried; cancel path leaves the form intact.

## Files

- `dashboard/src/features/usage/` (shared gate hook/dialog)
- `dashboard/src/features/services/`, `databases`/`keyvalue` feature plan/create components
