## Objective

Map `--every hour|day|week` with `--minute`, `--at`, `--on`, plus `--once`, `--cron`, `--timezone`, `--ends` and `--no-end` onto the trigger body exactly as ADR106's flag table says. `--timezone` defaults to the machine's IANA zone (from `TZ`, else the `/etc/localtime` link) and the CLI prints the zone it used; if no IANA name can be found the command exits 2 asking for `--timezone`. The CLI checks only flag combinations; every semantic rule (minimum interval, past times, cron validity) stays in the API.

## Context

- Design and full CLI spec: `docs/ADR106-cli-cloud-agents-automations.md` (+ `.svg`).
- Shipped group to extend: `lego/cli/internal/agent/` (`agent.go` commands and exit codes, `api.go` REST client, `render.go` text output, `watch.go` polling waits, `types.go` hand-decoded shapes).
- Constraints: the CLI imports no sibling module (thin client, every rule stays in bex-api); never touch the imported Render command tree; `.pm/DO_NOT_DO.md` #APPROVAL-MODE (no permission prompts, no `needs_input`, no agent→user channel).
- `AutomationSchedule` fields and validation: `lego/backend/internal/agentsessions/automation_schedule.go`.

## Acceptance criteria

- [x] Exactly one of `--every`, `--once`, `--cron` on create, else exit 2.

- [x] A machine with `TZ=Europe/Berlin` sends `timezone: Europe/Berlin` and prints it; an unresolvable zone exits 2.
