# A service created without `plan` defaults to free on bex but to `0.5c-512mb` (starter-sized) on Render

Why: Render's current Blueprint spec gives a new service with no `plan` the `0.5c-512mb` compute plan; bex creates it on `free`. A manifest that is portable between the two therefore lands on different (paid vs free) tiers with different sleep behavior, and nothing records the divergence.

**Source:** `w1/m170` (re-pin of `render.yaml.json` to upstream `a0d4e8a3`, 2026-10-02) — the agent noted it and deliberately did not change it, because it is a pricing decision. The default predates the re-pin.

- **Decide (user):** keep bex's free default as a recorded divergence in `docs/ADR018-render-parity.md` / `docs/ADR049-render-yaml-parity.md` (bex's free tier is a product choice, `docs/ADR030-pricing.md`), or follow Render and default to `starter`. Following Render changes the bill for every plan-less manifest and REST/MCP create, so it needs an explicit owner decision.
- **Scope check:** confirm which surfaces share the default (Blueprint compiler, REST `POST /v1/services`, GraphQL, MCP `create_web_service`), and that background workers already default to `starter` (MCP's own description says so).
- **Done when** the decision is recorded and either the divergence row exists or the default moved on every surface with a test.

**Decided 2026-10-15 (user): follow Render.** A service created without a plan defaults to `0.5c-512mb` (bex `starter`) on every surface. Explicit `plan: free` stays allowed where it is today (web, cron); whether cron may be free at all remains `w8/048`'s separate decision. Static sites carry no plan and are unaffected.

**Done 2026-10-15.** `normalizeTierForType` (`lego/backend/internal/apps/service.go`) resolves an omitted plan to the cheapest paid rung, `starter` (Render's `0.5c-512mb`), for every type that runs an instance; a static site keeps the catalog default; an explicit `free` stays valid for web and cron (w8/048's separate question is untouched), and the paid-only types still refuse it. Every surface shares that function: REST `POST /v1/services`, GraphQL `createService`, MCP `create_web_service`/`create_cron_job` (descriptions now say "default starter"), and Blueprint apply, validate, pricing and the payment-method gate. The dashboard is unaffected (its create form always sends a picked plan). Found on the way: Generate Blueprint omitted `plan` for a free service, which would now re-create it on starter; it always writes the plan now. Existing services keep their tier (sync is presence-aware). ADR030 §8, ADR018 and ADR049 record the decision. Tests: per-type defaults, Blueprint pricing and paid-gate, and the free-service export round-trip (fails on the old export code); seven fixtures that meant "free" now say so.
