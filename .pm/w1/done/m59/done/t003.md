## Objective

Pin the supersession-detection logic with an automated check and prove end-to-end that a superseded run concludes neutral and builds nothing.

## Context

- The detection is the `git diff $GITHUB_SHA origin/main` over the production-input path filter (excluding the three generated image files); drift here would either pin stale images or falsely skip builds.

## Steps

1. Add a guard (workflow `lint`/`actionlint` + a small script test of the path-filter/diff logic, or a `scripts/` check wired into `scripts (test)`).
2. Trigger or simulate a superseded run (push a second `lego/` change while one is queued) and confirm it concludes neutral with no image build.

## Files

- `.github/workflows/deploy.yml`
- `scripts/` (guard, if a script test is added)

## Acceptance criteria

- [ ] A guard test pins the supersession path-filter/diff logic.
- [ ] A simulated superseded run concludes neutral and performs no image build/push.

## Out of scope

- The write-back neutralization (t001) and pre-build skip (t002) themselves.

## Completion (2026-07-30)

`scripts/deploy-superseded.sh` factors the path-filter/diff detection into one testable place (exit 0 superseded / 1 current / 2 error). `scripts/deploy-superseded.test.sh` pins it against a throwaway git repo across five cases: current (no drift), superseded-by-lego, superseded-by-deploy.yml, generated-digest-only (a preceding run's pin — NOT superseded), and non-triggering (docs). Registered in `scripts (test)` (scripts.yml). `github-actions-validate.sh` additionally pins the deploy.yml wiring (the job, the `if:`, two script calls, and ≥4 `env.SUPERSEDED` gates) so it can't drift back to `exit 1`. `actionlint` validates the workflow expressions.
