## Objective

At the start of `build-and-deploy`, detect that a newer deploy-triggering commit has landed on `main` and exit before the expensive image build/push/sign/CVE work — so a superseded run wastes no build minutes. Preserve `concurrency.cancel-in-progress: false` for already-running builds.

## Context

- The observed `2fc94bd7` run built + signed three images before failing at write-back; a pre-build check would have skipped all of that.
- GitHub Actions concurrency (`group: bex-production-deploy`, `cancel-in-progress: false`) serializes runs but still runs queued ones to completion — the pre-build check is the cheap way to short-circuit a superseded queued run.
- `cancel-in-progress: false` stays (don't cancel an in-flight build); the check only avoids starting redundant work.

## Steps

1. Add an early step in `build-and-deploy` that, after checkout, checks whether `origin/main` has advanced past `$GITHUB_SHA` over the deploy-triggering path filter.
2. If superseded, exit the job neutral/skipped before any `docker/build-push-action`.
3. Confirm the newest run still builds and rolls normally.

## Files

- `.github/workflows/deploy.yml`

## Acceptance criteria

- [ ] A superseded run performs no image build/push/sign when detected pre-build.
- [ ] An in-progress build is never cancelled (`cancel-in-progress: false` honored).
- [ ] The newest run for a given push builds and deploys normally.

## Out of scope

- Changing the concurrency group or cancelling running builds.

## Completion (2026-07-30)

New `check-supersession` job (checkout + `scripts/deploy-superseded.sh`) outputs `superseded`; `build-and-deploy` gains it in `needs` and `if: needs.check-supersession.outputs.superseded != 'true'`. A run whose supersession is known before the build starts (queued behind a newer deploy-triggering commit) is therefore **skipped** (neutral, no image build/push). `concurrency.cancel-in-progress: false` is untouched — a running build is never cancelled; only a not-yet-started one is skipped. Fail-safe: the pre-check is an optimization; on any script error it reports not-superseded and the build proceeds, backstopped by the write-back guard.
