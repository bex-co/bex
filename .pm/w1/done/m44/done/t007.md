## Objective

Member mutations are the canonical audit-log material — who invited whom, who changed whose role, who removed whom — yet none of the members verbs write `audit_events` rows (the audit system shipped in w4/m10; only `tenant_invites.accepted_at` records anything today). Emit an audit event from each mutating verb: Invite, ResendInvite (t003), ChangeRole, Remove, RevokeInvite, and token/email invite acceptance.

## Context

- `lego/backend/internal/members/service.go` — the six mutation sites.
- Find the existing audit-event writer other features use (the w4/m10 recorder; see how workspace lifecycle or env-var verbs emit) and follow its taxonomy — action naming, actor subject, target workspace, detail payload (role, email, invite id). Do not invent a parallel dialect.
- Acceptance-on-login happens in `internal/api/tenancy.go` — the actor there is the accepting identity, not an admin.
- Retention/pruning is already handled globally (`BEX_AUDIT_RETENTION_DAYS`).

## Steps

1. Inject the audit recorder into `members.Service` (nil-tolerant like Mailer/Granter — store-off mode keeps working).
2. One event per mutation with the standard shape; role changes record old→new; invites record the target email + role (email is PII already present in audit context elsewhere — match existing precedent, don't over-redact unilaterally).
3. Acceptance events from the redemption core (covers both email-match and token paths).

## Files

- `lego/backend/internal/members/service.go`
- `lego/backend/internal/api/tenancy.go`
- the audit recorder package (reads only)

## Acceptance criteria

- [ ] Each of invite/resend/change-role/remove/revoke/accept produces exactly one `audit_events` row with actor, action, workspace, and detail payload.
- [ ] Rows appear in the dashboard audit panel on a dev-N stack.
- [ ] Store-off / recorder-nil mode: verbs still succeed, no panic.

## Out of scope

- Role *history* as a first-class queryable dimension (the audit rows are the history).
- Outbound webhook events for membership changes (separate vocabulary decision, w3 territory).
