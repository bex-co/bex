## Objective

Make the emailed invite link real. `tenant_invites.token` (random 128-bit hex) is minted and embedded in the invite email (`{InviteBaseURL}/auth/sign-up?invite=<token>`, `email.go:48-56`) but never redeemed — acceptance is email-match-only (`AcceptInvitesForEmail` on login), so a recipient who signs up under a different address than the one invited silently never joins. Redeeming by token closes that hole.

## Context

- `lego/backend/internal/store/members.go:210-308` — `AcceptInvitesForEmail` + `planAllowsJoin`; the token path must run the same plan/seat checks and the same FGA grant, sharing the acceptance transaction logic (one redemption core, two lookups — by email, by token).
- `lego/backend/internal/api/tenancy.go:130-192` — `EnsureTenant`/acceptInvites is the login-time hook; the token arrives post-auth from the dashboard instead.
- Dashboard: `?invite=<token>` must survive the Kratos sign-up/login round-trip (return_to) and then be redeemed by an authenticated call — a GraphQL mutation (e.g. `acceptWorkspaceInvite(token)`) is the natural shape; REST + MCP mirror it.
- Security: token is a bearer credential — single-use (mark accepted), expiry enforced, constant-time lookup by token hash is nice-to-have but the token is already high-entropy; never log it.

## Steps

1. Store: `AcceptInviteByToken(token, subject, identityEmail)` sharing the redemption core with the email path (plan check, member upsert, mark accepted, FGA grant).
2. Core verb + three adapters; the caller is whoever is authenticated — no workspace-id argument, the token identifies the invite.
3. Dashboard: preserve `?invite=` through the auth flow (`auth.sign-up.tsx` / login return_to), redeem on first authenticated load, toast the joined workspace, refresh the workspace switcher.
4. Errors: expired/accepted/unknown token → a named, user-visible failure (not a silent no-op).
