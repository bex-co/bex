# An inbound IP allowlist on a Cloudflare-proxied custom domain is neither refused nor warned about

Why: after `w1/m150` the allowlist matches the connection's TCP source, which on an orange-cloud custom domain is a Cloudflare edge, so the Networking card's "Restrict inbound HTTP traffic to these source CIDRs." is silently false there, and m150's Decision 2 promised a refusal or warning that was never built.

**Source:** `w1/m150` t004 (Render-parity check, 2026-10-02). m150 § Decisions 2 chose "(c) with (a) documented": refuse an allowlist on a Cloudflare-proxied host, or warn where refusing would break an existing config, and document that an allowlist matches the real client only on DNS-only hosts. t004 recorded the documented half in `docs/ADR018-render-parity.md`'s inbound-IP-allowlist row. The refuse-or-warn half has no task, and nothing in `lego/backend/internal/apps` or the dashboard implements it (`grep -i cloudflare` finds only the certificate-reason hint in `domains.go`).

- **Scope.** Every `<slug>.onbex.co` host is DNS-only, and m150's live probes confirmed it, so only tenant custom domains are affected.
- **Detection precedent.** `apps/domains.go` `domainCertificateReason` already surfaces the orange-cloud case for certificates (`w3/037`). A warning on the Networking card, or an `ipAllowList` save response that names the proxied hosts, can reuse the same signal, or a resolver check against Cloudflare's published ranges.
- **Decide first.** Choose refuse or warn: refusing breaks any tenant that already saved an allowlist on such a host, which Decision 2 itself flagged. Then cover REST, GraphQL, MCP and the dashboard together.
- **Done when** a tenant who sets an allowlist on a service with a Cloudflare-proxied custom domain is told that the allowlist sees Cloudflare's address on that host, on every surface, with a test.

**Promoted 2026-10-02 (`/loopx w1`) → [m171](../blocked/m171/README.md).** Decision 2 already chose the form: warn, because refusing breaks tenants who already saved such an allowlist. Implemented on REST, GraphQL, MCP and the dashboard; m171 is parked on deploy + live verify.
