# Production deploys starve under steady pushes: nothing pinned for 14+ hours

Why: every deploy run since `cae30d1e0` (pinned 2026-09-28 16:41Z) was superseded before its write-back, so production kept running `cae30d1e0` while urgent fixes (w1/m152 t011, the uncached snapshot Secret I/O that unbreaks every new service with an environment) sat on `main` for 14+ hours.

**Filed and worked 2026-09-29 (`/loopx w1`, pulled ahead of the queue: it blocked a production fix and every live acceptance on the board).**

## Evidence

- `git log origin/main --author=github-actions`: the last `chore(deploy): pin platform images` commit was `8007ec072` → `cae30d1e0be0`, 2026-09-28T16:41:17Z.
- Deploy run `36529568296` (`caef683d2`, 2026-09-29 06:08Z) reported **success**, but its write-back step logged `superseded by newer production inputs on origin/main (ed12210); this run's images will not be built/pinned`, and every rollout step ran with `SUPERSEDED: true`. Runs `36528713197` and `36534288811` were cancelled, and later ones were queued behind newer pushes.
- The consequence was observed live: production GraphQL answered `Cannot query field "undeployedChanges" on type "Service"`, a field shipped in `4e24ad075` days earlier.

## Cause

`scripts/deploy-superseded.sh` treated **any** production-input change after a run's commit as supersession: `lego/`, `dashboard/`, `deploy/gitops`, `deploy/opensandbox` and `deploy.yml`. A run takes about 50 minutes from tests to write-back. Code from several concurrent workstreams lands more often than that, so every run found a newer commit at write-back and pinned nothing. The latest-wins debounce had no progress guarantee.

## Fix

Newer commits are split in two:

- **Manifests**: what Argo CD syncs from `main` (`deploy/gitops`, `deploy/opensandbox`, `lego/operator/config`, including CRDs and RBAC) plus `deploy.yml`. They remain a supersession (exit 0). Images built from an older tree are never pinned onto newer manifests, the part of the w1/m59 invariant that protects correctness.
- **Image source**: everything else under `lego/` and `dashboard/`. The new exit 3 means a newer run is queued. The pre-build check still skips a not-yet-built run on 3. A finished build **pins** on 3: its images onto unchanged manifests are an ordinary deploy of its own commit, and runs are serialized, so the queued run pins newer images right after.

The rollout steps after the write-back rebase onto `main` and read only `deploy/gitops/...` (a manifest), `scripts/` and `deploy/helm-artifacts.lock`. The last two never triggered supersession before either, so no image-source path is applied from the tree.

`scripts/deploy-superseded.test.sh` (run by `scripts.yml`) has 23 cases. The source-only cases (a `lego/` change, a `dashboard/` change, CLI plus backend, renames across the CLI boundary) now exit 3. New cases pin a CRD change under `lego/operator/config`, a gitops manifest change, and manifest-plus-source drift as exit 0.

**This relaxes an explicit w1/m59 invariant** ("never attach images built from this event to newer production source/manifests"). The manifest half is kept exactly; the source half is dropped. One revert of the fixing commit undoes it.
