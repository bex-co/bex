## Objective

Move the control-plane bex-db Cluster, ScheduledBackup, recovery examples, and structural validation from in-tree Barman fields to the plugin.

## Context

- deploy/gitops/charts/bex-postgres/cluster.yaml currently declares spec.backup.barmanObjectStore.
- scripts/gitops-validate.sh and ADR031 intentionally guard the old shape; they must migrate with the manifest rather than being simply removed.

## Steps

1. Point bex-db at its ObjectStore plugin configuration and change its ScheduledBackup method.
2. Update bootstrap recovery manifests/runbook commands to the plugin external-cluster contract.
3. Replace structural guards with plugin-aware checks.

## Files

- deploy/gitops/charts/bex-postgres/
- scripts/gitops-validate.sh
- docs/ADR031-platform-data-backup.md
- docs/runbooks/

## Acceptance criteria

- [x] Rendered bex-db manifests contain the plugin configuration and no in-tree barmanObjectStore field.
- [x] Scheduled backups target the existing bex-db prefix and retain the current schedule/retention.
- [x] Recovery documentation and validation agree with the rendered manifests.

## Completion evidence

- The rendered `bex-system/bex-db` Cluster now has one WAL-archiver plugin (`barman-cloud.cloudnative-pg.io`, ObjectStore/server `bex-db`) and no native backup field. `bex-db-nightly` uses `method: plugin`; the ObjectStore retains `s3://bex-tfstate/bex-db`, compression, credentials, and 7-day retention.
- CNPG uses six-field cron syntax. Production proved the legacy `0 4 * * *` value was running hourly at minute 04; it is corrected to `0 0 4 * * *`, preserving the documented daily 04:00 UTC contract. Structural validation pins the exact Cluster/ScheduledBackup shape, forbids native fields, and orders plugin → ObjectStore → bex-postgres at sync waves 2 → 3 → 4.
- Current ADR031 on-demand Backup and throwaway recovery manifests use plugin configuration and the existing ObjectStore/server identity. Historical native-path drill evidence remains explicitly historical. A local chart overlay removes plugin/schedule when the credential-backed ObjectStore is deliberately absent.
- Production rollout reached two Ready instances with plugin sidecars, a writable primary, healthy replica replay, `ContinuousArchiving=True`, successful plugin uploads of WAL `0000000D0000000C00000036` and `…37`, `api.bex.co/healthz=ok`, and all related Argo Applications Synced/Healthy. The one-time plugin injection restarted the primary without switchover; its 30-minute smart shutdown waited on existing clients, so a PostgreSQL fast stop completed a clean shutdown/restart without forcing the Pod or touching either PVC.
