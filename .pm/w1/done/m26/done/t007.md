## Verification record (2026-07-13, live prod cluster `bex`)

**Result: PASS.** A freshly minted tenant node pulled a git-built image on first
attempt with zero hand-applied config.

- Scaled `bex-tenant-0` MachineDeployment 1→2; CAPI provisioned a brand-new node
  `bex-tenant-0-b5swk-nz9pc` from the updated CAPH template (Ready in ~2 min, never
  hand-patched — the exact failure mode the incident exposed).
- Confirmed the live `bex-tenant-0` KubeadmConfigTemplate bakes the fix into
  `preKubeadmCommands`: containerd `hosts.toml` → `http://127.0.0.1:30500`
  (`skip_verify`) + `config_path = /etc/containerd/certs.d` (t001).
- Scheduled a pod pulling `zot.bex-registry.svc:5000/agentmarketcap:gen-3` onto the
  fresh node (imagePullSecret `bex-registry-pull`). Kubelet events:
  `Pulling image "zot.bex-registry.svc:5000/agentmarketcap:gen-3"` →
  `Successfully pulled image ... in 11.327s` → container Started, ready=true.
  **No `ImagePullBackOff`, no manual `/etc/hosts`/containerd intervention.**
- Confirmed Cilium `allow-node-image-pulls` is Argo-managed (`bex-platform-prod`,
  Synced/Healthy) and VALID — node-identity pull traffic is allowed (t002).
- Scaled back to 1 (removed the fresh node; original workload node untouched).

**Two incident-recovery findings surfaced during verification** (both fixed):

1. Zot was down 21 h (registry unreachable → no pull path at all): the w7/m8
   registry-auth rollout landed without its out-of-band `zot-htpasswd`/push/pull
   Secrets. Minted via `scripts/registry-secrets.sh`.
2. **m26 config bug:** the t003 retention block was under `extensions.retention`,
   which Zot v2.1.18 rejects (`'Extensions' has invalid keys: retention`) — it
   belongs under `storage.retention`, and `repositories: [".*"]` was a broken glob.
   Fixed in `deploy/gitops/base/zot.yaml` (moved to `storage.retention`,
   `repositories: ["**"]`). Durable once shipped.

## Objective

Prove the fix works end to end: force the cluster-autoscaler to mint a brand-new tenant node and confirm a git-built image pulls successfully with zero hand-applied configuration — the actual failure mode the incident exposed.
