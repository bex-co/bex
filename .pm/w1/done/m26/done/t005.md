## Objective

Find and fix whatever kept bumping `eden-cms-v2-git`'s App generation to 51 — a spec-churn loop that (combined with no Zot retention) drove the runaway rebuild that filled the registry volume.

## Context

- Candidate suspects named in the incident note: the operator's reconciler re-writing the App spec on every loop (a no-op-that-isn't-actually-a-no-op bug), or a clone-secret refresh path that touches the spec on a timer.
- The offending app has since been deleted, so this is a code-path investigation (read the reconciler/clone-secret-refresh logic), not a live repro against that specific app — but the bug is presumably still live for any current app on the same code path.

## Steps

1. Read `lego/operator`'s App reconciler and the private-repo clone-secret refresh path (`w2/m9`) for anything that mutates `spec` (bumping `generation`) on a normal, no-change reconcile loop.
2. Reproduce against a test app if a candidate is found (trigger repeated reconciles, watch `metadata.generation`).
3. Fix the root cause (likely: only write `spec` when it actually changes, not unconditionally).

## Files

- `lego/operator/internal/controller/` (or wherever the App reconciler lives)
- clone-secret refresh path (`w2/m9`'s implementation)

## Acceptance criteria

- [ ] A candidate root cause is identified and reproduced (or ruled out with evidence).
- [ ] The fix stops `generation` from incrementing on no-op reconciles for a test app observed over multiple reconcile cycles.

## Out of scope

- Rebuilding the deleted `eden-cms-v2-git` app itself.
