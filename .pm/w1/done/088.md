# 088 — Billing → Charges names a deleted service, and every sandbox, only by a bare id nobody can look up

Why: the Charges tree is where a user asks "what did this cost me?". Once a resource is deleted, or for any sandbox at all, the answer is an opaque id, including a $69.98 line that no other surface can tie to a recognisable resource.

**Absorbed 2026-09-15 into [w2/m96](../../w2/m96/README.md)** — tracked there; this note is closed.

- **Severity:** minor. The totals reconcile and the money is real, but individual lines cannot be attributed.
- **Found:** live `/qa-find-bugs` hunt of `https://dashboard.bex.co`, 2026-09-14 pass 6, journey 16 (does a deleted resource leave the **usage view** honestly). Workspace `bex` / `tea-d98210cbbpdc73dcrkvg`. Read-only: nothing was created, changed or deleted this pass.

3. **The three unnamed service rows are deleted services.** `service(id)` returns `app not found` for `srv-dae9lb988i5c7399e9m0`, `srv-da7o6ovvqdcc73bpn9hg` (a late-August QA fixture, see `w6/done/037.md`) and `srv-dah41v9c7cos73dm39ug`.

The other **13 of 14** charged UUIDs are listed nowhere. None of the 14 matches any of the 71 `agentSessions { id sandboxId }` either (session ids are `ags-…`, and their `sandboxId`s are not these UUIDs). Even the live one can only be recognised by UUID and image, because a sandbox has no name field (`internal/sandbox/graphql.go:45-56`).

## Root cause

- `lego/backend/internal/usage/service.go:286-313` (`resolveServiceNames`) fills `ServiceName` only from **live** rows: `Store.ListApps` for services, and the live Database/KeyValue CRs for datastores. It has **no sandbox branch** at all. The contract at `:161-163` states it outright: "Empty when the resource no longer exists — presenters fall back to ServiceID."
- `nameResourceEstimates` (`:320-332`) copies those names onto the per-resource estimates, so the charge tree inherits the gap.
- Sandbox usage rows store only the sandbox UUID as `service_id` (`lego/backend/internal/store/sandbox_meter.go:238-248`), with no label.
- The dashboard falls back to the id: `dashboard/src/features/usage/components/charges-card.tsx:101` (`resource.serviceName || resource.serviceId`).

## Fix: target behavior

**A charge line keeps the name its resource had while the usage accrued, and says when that resource no longer exists.**

- **Names:** retain the display name alongside the metered id. Either store it on the usage row at rollup time, or keep a tenant-scoped `id → last display name` record that is written on create and rename and survives resource deletion. Resolve names from that record rather than from live resources.
- **Sandboxes:** label by owning context where one exists (the agent session's repo and branch), otherwise by `plan · image`.
- **Dashboard:** render `<name> (deleted)` for a resource that no longer resolves. Fall back to the bare id only when no name was ever recorded, e.g. rows from before the fix.
- **Consumer check:** `charges-card.tsx:101` already prefers `serviceName`, so a non-empty name needs no UI change beyond the "(deleted)" marker. REST `GET /v1/usage`, GraphQL `usage` and MCP share `monthToDateAt`, so all three move together.
- **Adjacent classes:**
  - Workspace deletion (`w1/done/m61` teardown) must still purge any retained names with the workspace.
  - A resource deleted and re-created under the same display name must stay two distinct lines, keyed by id.
  - A renamed resource shows its current name while it exists.
- **Tests:**
  - a usage row for a deleted service or datastore resolves its recorded name, flagged deleted;
  - a sandbox row resolves a label;
  - a live, renamed service shows its current name;
  - workspace purge removes the retained names.
- **Estimate:** ~60–90m. Promote to a milestone at pickup if name retention needs a migration plus a backfill decision for rows already recorded.

## Unverified

- **Deleted Postgres / Key Value rows:** only services and sandboxes were observed nameless. Datastores go through the same live-only lookup, but no deleted datastore row appeared in this month's rated data. The rated data runs only to 2026-09-01 (next bullet), which is also why today's deleted `qa-` resources do not appear yet.
- **Coverage:** `usage.coverage` reads `state: partial, through: 2026-09-01T00:00:00Z, degradedSources: [direct, http, instance, sandbox, websocket]`. Code explains most of it: any sandbox usage marks the month partial (`lego/backend/internal/store/usage.go`, `aggregateUsageCoverage`), and each stream's watermark stops at its first gap (`evaluateStreamCoverage`). Whether those gaps are real meter outages could not be seen from outside, so it is **not** filed here.
- **Render:** Render's billing view for deleted services was not captured.
