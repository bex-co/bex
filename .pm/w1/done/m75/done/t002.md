## Objective

Flip the manager's default runtime from `ModeOpenSandbox` to `ModeKubernetes` so an unset `BEX_RUNTIME` no longer routes deploys to the untested legacy host runtime while silently skipping registry-credential convergence.

## Context

- Default set at `lego/operator/cmd/manager/main.go:328`.
- The opensandbox runtime (`lego/operator/internal/runtime/opensandbox.go`, 221 lines) has zero test files and production never runs it: `config/manager/manager.yaml:108` sets `kubernetes`; `scripts/events-verify.sh:155`, `dashboard-env-verify.sh:96`, `name-conflict-e2e.sh:149`, `secrets-verify.sh:111` all force `kubernetes`.
- With mode ≠ kubernetes, `convergeRegistryCredentials` early-returns (`lego/operator/internal/controller/app_controller.go:487`).
- The legacy scripts that assumed the old default (`scripts/up.sh`, `start-opensandbox*.sh`) are already broken (`up.sh:29` cd's into a path that no longer exists), so nothing live depends on it.

## Steps

1. Change the default at `cmd/manager/main.go:328` to `ModeKubernetes`.
2. Grep for any remaining reliance on the opensandbox default (scripts, docs, CLAUDE.md env-table row) and correct the documented default if stated.
3. Add a test asserting the resolved mode with `BEX_RUNTIME` unset.
