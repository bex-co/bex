## Objective

Fix the git-proxy's nil-`Limits` fallback so acquire and release hit the same limiter instance. Today `agentcred` mints a fresh `NewSessionLimiter(0,0)` on every call, acquires on one instance and releases on another — the fallback concurrency cap is a silent no-op. Dormant in production (main wires `Limits`), but the twin has already diverged once.

- Production wiring: `lego/backend/cmd/ssh-gateway/main.go:232`.

## Steps

1. Add a `sync.Once`-memoized default limiter to the `agentcred` server struct, mirroring `modelproxy`.
2. Add a test with `Limits == nil` asserting one shared instance across calls (saturate the default-capped limiter and observe shedding, or assert pointer identity across two requests).
