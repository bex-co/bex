## Objective

Stop MCP from flattening typed error codes to plain text on most tools. `core.MCPError` reaches only 6 of 24 MCP adapters, so codes REST returns in `params` and GraphQL in `extensions` (`PLAN_LIMIT`, `PAYMENT_REQUIRED`, `AGENT_SESSION_LIVE_LIMIT`, …) vanish for ~130 of 175 tools — the surface agents parse programmatically. Wrap once at the shared tool-registration seam instead of relying on per-handler discipline.

## Context

- Coverage today: envgroups (17 call sites), agentsessions (16), webhooks (8), sandbox (4), apps (3), secrets (1); **zero** in postgres (23 tools), keyvalue (6), members (10), deploys (7), registrycreds, projects, environments, jobs.
- Error mapping is already centralized elsewhere: REST `core/http.go:265`, GraphQL `core/errors.go:209`, MCP shape `core.MCPError`.
- The wrap must be idempotent so the six adapters already calling `core.MCPError` don't double-wrap; their per-handler calls can then be dropped opportunistically (not required here).
- Guards that must stay green: `TestMCPParityInventory` (w1/m70) and the m70/m71 classification/no-regrowth guards — tool count, names, and schemas must not change. This is an error-shape fix, not a surface change.

## Steps

1. Find the shared seam where all 24 adapters register tool handlers and wrap the handler-invocation error return with the coded-error → MCP-error translation.
2. Make the wrapper a no-op for errors already in MCP-error form.
3. Regression test: drive a coded error through a previously-uncovered adapter's tool (e.g. a postgres tool hitting `PAYMENT_REQUIRED` or a quota code) and assert the code survives in the MCP error payload.
4. Assert an already-covered adapter's output is byte-identical before/after.

## Files

- `lego/backend/internal/core/` (error translation helper, if extended)

## Out of scope

- Any change to tool names, count, or schemas.
