## Objective

Align the three KeyValue setters with their Postgres twins' write mechanics. Postgres routes `SetProjectID`/`SetEnvironmentIPAllowList`/`SetEnvironmentID` through `patchDatabase`/`patchDatabaseObj`; KeyValue does a raw fetch → mutate → `resourcemeta.Touch` → `Client.Update`, so the same operation carries different conflict/overwrite semantics depending on the datastore.

## Context

- Postgres (the pattern to match): `lego/backend/internal/postgres/service.go:1076,1094,1113`.
- KeyValue (drifted): `lego/backend/internal/keyvalue/service.go:501,522,540`.
- A full `Update` is last-writer-wins over the whole object; the patch path is a targeted merge.

## Steps

1. Add the `patchKeyValue` equivalent if none exists (mirror the Postgres helper's shape) and route the three setters through it.
2. Add a regression test asserting the setters issue a patch (fake client's recorded action type or equivalent) and that at least one setter's concurrent-modification behavior matches the Postgres twin.
