# 096 — A service env var named `PORT` saves without complaint but is silently ignored; the process still gets the platform port

Why: a user moving from Render sets `PORT=8080`, because Render documents that as how you pick the port, and sees it saved. bex quietly runs the process on 3000 instead, so an app that binds a fixed port never passes its health check, and no surface says why.

**Absorbed 2026-09-15 into [w2/m95](../../w2/m95/README.md)** — tracked there; this note is closed.

- **Severity:** minor (a deliberate bex invariant that's silent on every surface and unrecorded as a Render divergence).
- **Found:** live `/qa-find-bugs` hunt of `https://dashboard.bex.co`, 2026-09-14 pass 23. Workspace `bex` / `tea-d98210cbbpdc73dcrkvg`. Fixture: web service `qa-20260914-port` (`srv-dak30q0gsm7s73f64jf0`), `examples/hello-python` with Docker Command `python -m http.server $PORT --directory /proc/self`, created and deleted inside the run.

## Repro (every step was run)

```text
17:35:39  create form: Add variable PORT = 8080 → no hint, no warning; Deploy Service enabled → createService 200
17:37:24  first deploy live; service phase Running
          GET /v1/services/<srv>/env-vars/PORT → {"key":"PORT","value":"8080",…}
17:38:01  curl https://qa-20260914-port.onbex.co/ → HTTP/2 200, server SimpleHTTP/0.6 Python/3.12.14, "Directory listing for /"
```

`http.server` binds whatever `$PORT` the process receives, and bex routes and health-checks `spec.port` (default `3000`). The deploy reaching live and answering 200 therefore means the process got `PORT=3000`, not the saved `8080`. Reading `/proc/self/environ` through `http.server` returns an empty body, because proc files report size 0.

## Root cause

- **Accepted as ordinary.** The backend accepts `PORT` as a normal key: `ValidEnvKey` checks only the name's shape (`lego/backend/internal/core/config.go:60-72`).
- **Dropped at runtime.** The service env var lands in the service's env Secret (`envFrom`). `appEnv` drops a user `PORT` from `spec.env` and appends the operator-owned `PORT` as a container `Env` entry, which Kubernetes lets win over every `envFrom` key (`lego/operator/internal/controller/app_controller.go:3816-3846`).
- **Deliberate.** ADR004 records this: "the operator-owned `PORT` always appended last so a user variable can never shadow it" (`docs/ADR004-app-deployment.md:152`).
- **Unrecorded.** `docs/ADR018-render-parity.md` has no entry for it, while Render says: "The default value of `PORT` is `10000` for all Render web services. You can override this value by setting the environment variable" (`render.com/docs/web-services`, fetched 2026-09-14).
- **Silent in the UI.** The create form's only port copy is "The container must listen on $PORT (default 3000) and cannot bind ports below 1024." (`dashboard/src/features/services/locales/en.ts:2759`). Nothing appears when a `PORT` key is entered.

## Fix (~40m)

- **Decide and record.** Either (a) keep the invariant and refuse or flag a user `PORT` key, or (b) honor a user `PORT` as the port (update `spec.port`), which is Render's behavior. Record the decision as a divergence row in ADR018, next to ADR004:152.
- **Under (a):**
  - REST/GraphQL/MCP env-var writes (single, bulk, env-group) reject `PORT` with a coded 400 that names the port setting;
  - the dashboard env editors show inline "PORT is set by the platform (3000); change the service port instead";
  - Blueprint `envVars` get the same check.
- **Tests:** backend write-path tests for each surface; a dashboard editor test; the operator's existing `appEnv` shadowing test stays as the control.
- **Adjacent classes:** env-group `PORT` keys (same `envFrom` path), secret files named `PORT` (not an env var, unaffected), and background workers and cron jobs (no port; decide whether `PORT` is reserved there too).
- **Unverified:** the exact value the process received was inferred from routing and health, not read directly. Env-group and Blueprint `PORT` weren't probed.
- **Dedupe:** no board item covers a user-set `PORT`. ADR070:148 mentions "unshadowable `PORT`" only as an inventory item. Not fixed on `main` as of `4399cb71d`.
