## Objective

Add a weekly CI job that fails when Render's bundle and the ledger disagree.

## Context

- Next to the `render-changelog` job in `.github/workflows/render-schema-drift.yml` (w4/m553), same sparse checkout without `.pm/`.
- `scripts/ci_test_inputs.py` checks each workflow's `paths`; `scripts/ci-schedule-drift.sh` lists scheduled jobs.

## Steps

1. The job runs t001's script and compares with the ledger. It fails on four conditions:
   - an operation or flag in the bundle that has no row;
   - a row whose operation or flag is gone;
   - a flag gate that moved to a different chunk family;
   - an entry chunk that cannot be found.
2. A removed flag gate means Render made that feature GA or dropped it. The failure names the ledger row's pointer, for example "reopen w2/066 D2=A" for `postgres-parameter-overrides`.
3. Add `scripts/render-dashboard-ops.test.sh` with fixture mutations for each failure, and run it wherever the other `render-*-drift.test.sh` run.

## Files

- `.github/workflows/render-schema-drift.yml`
- `scripts/render-dashboard-ops.test.sh`, fixtures under `scripts/testdata/` (small, synthetic)
- `scripts/ci_test_inputs.py` / `scripts/ci-schedule-drift.sh` as they require

## Acceptance criteria

- [x] The job passes against the live bundle with the ledger from t002.
- [x] Each fixture mutation fails it with a message naming the operation or flag.

## Out of scope

- Opening board items automatically.

## Outcome

A new or removed operation, a new flag gate, a removed flag gate (naming its row's pointer, e.g. "reopen `w2/066` D2=A") and an entry chunk that is missing or cannot be fetched each fail with the name. Deviation (from the orchestrator's re-verification): a flag whose calls move to another chunk family prints a `::notice` and does not fail, since Rollup re-splits chunks and most calls sit in the entry chunk; the README's DoD does not list that condition. The job's check passed against the live bundle with the committed ledger on 2026-11-26.
