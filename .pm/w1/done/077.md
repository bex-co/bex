# Wire disk snapshots in production — the ADR082 D5 pipeline ships inert

Why: daily snapshots with 7-day retention are a headline parity claim of ADR082 (Render advertises them, ADR018's disk row now says bex has them), but production has **no disk-snapshot configuration at all** — so today a tenant who attaches a disk gets a volume with no backups and no restore path, silently.

Found 2026-08-23 while preparing the post-deploy production walkthrough of the w1/m86 Disk tab.

`grep -rl BEX_DISK_SNAPSHOT deploy/` returns **nothing** — the variables appear only in `lego/**` code and the two CLAUDE.md inventories. Consequences, both by design and both currently active:

- **Operator:** `disk_backup.go` requires endpoint + bucket + S3 secret + age public key to ALL be set before it creates a disk's CronJob. Any unset ⇒ no CronJob, no purge Job. This is deliberate fail-closed behavior (a disk snapshot is a full copy of a tenant filesystem leaving the cluster, so bex takes none rather than an unencrypted one) — it is working as designed, it is just never configured.
- **bex-api:** `BEX_DISK_SNAPSHOT_ENDPOINT`/`_BUCKET`/`_REGION`/`_ACCESS_KEY`/`_SECRET_KEY` unset ⇒ `GET /v1/disks/{diskId}/snapshots` and the restore verb answer 503. The dashboard's Snapshots card renders its unavailable state. Disks themselves are unaffected.

To close it:

1. Create a **dedicated age keypair for disks** — deliberately NOT the ADR050 platform key (`AGE_BACKUP_*`), because restore needs the decrypt half in-cluster and ADR050 keeps the platform key out of the cluster. Public half → `BEX_DISK_SNAPSHOT_AGE_PUBLIC_KEY`; private half → a Secret named by `BEX_DISK_SNAPSHOT_AGE_SECRET` (key `private`).
2. Create/choose an S3 bucket and a scoped credential Secret; set `BEX_DISK_SNAPSHOT_ENDPOINT`/`_BUCKET`/`_PREFIX`/`_REGION`/`_S3_SECRET` on the operator and the read-only `_ACCESS_KEY`/`_SECRET_KEY` pair on bex-api (bex-api only LISTS — it never writes or decrypts a snapshot and never holds the age key).
3. Mirror the names into `.env.example` (repo rule: it must mirror `.env` names) and push via `scripts/gh-secrets.sh`.
4. Verify on a real disk: CronJob created, one object lands, `GET …/snapshots` lists it, restore round-trips. The byte pipeline and the store half are already verified against real MinIO in w1/m85; this is the deployment half only.

Until this lands, ADR082's snapshot claim is true of the code and false of the running system — worth stating that way in ADR082 § Verification if it is not closed soon.

Sizing: likely > 1h once key generation, bucket setup, secret plumbing and a live verification are counted, and it spans operator + bex-api + CI secrets. Promote to a milestone.
