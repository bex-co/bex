## Objective

Apply the same fold to the remaining setter families, or record deliberately why a given one stays standalone.

## Context

- Candidates (confirm against t001's mapping): `set_postgres_ip_allow_list`, `set_postgres_parameter_overrides`, `set_key_value_ip_allow_list`, `set_key_value_maxmemory_policy`, `set_env_var`, `set_secret_file`, `set_env_group_var`, `set_env_group_secret_file`, `set_environment_env_groups`, `set_environment_acl`.
- `internal/secrets/mcp.go` and `internal/envgroups/mcp.go` both declare at the file header that Render's official MCP has no tools in their domain at all — the entire fragments are extensions (10 and 17 tools).
- `postgres` (28 tools) and `keyvalue` (9) are near-parallel implementations of the same managed-datastore shape; keep their MCP grammars symmetric so the later datastore consolidation is not fighting two different tool shapes.
- Replace-semantics tools (allowlists, parameter overrides, `set_environment_*`) replace a whole list rather than patch a field. If folding them into a patch-shaped `update_*` would blur replace-vs-merge, keep them standalone and say so.

## Steps

1. Fold the field-shaped setters into the resource's `update_*` tool.
2. Keep the replace-shaped ones standalone where t001 decided so; make the replace semantics explicit in the tool description.
3. Keep the Postgres and Key Value grammars symmetric.
4. Delete folded registrations and their argument structs.
5. Re-run m70's guard test.
