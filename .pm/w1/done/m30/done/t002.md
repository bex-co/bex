## Objective

Prove t001's fix works and guard against regression: a test that starts the bex-api binary (or its server-lifecycle logic in isolation), sends SIGTERM, and asserts the process/server actually exits within a bounded time instead of continuing to serve.

## Context

- If the full binary is awkward to exercise in a unit test, test the extracted serve-then-shutdown logic directly (e.g. a small function that takes an `*http.Server` and a context, and returns once shutdown completes) — whichever is more natural given how t001 structures the fix.

## Steps

1. Write a test that starts a server via the new goroutine+shutdown pattern, cancels its context, and asserts `Shutdown` completes within a bounded timeout and the server stops accepting new connections.
2. If testing the real binary end-to-end is feasible (e.g. via `os/exec` + signal), prefer that for stronger evidence; otherwise the extracted-logic test is acceptable.

## Files

- `lego/backend/cmd/api/main_test.go` (new, or extend an existing test file for this package)

## Acceptance criteria

- [x] Test fails against the pre-fix code (verify by temporarily reverting t001, confirming the test catches the regression, then re-applying) and passes after the fix.

## Result

`lego/backend/cmd/api/main_test.go` (new). `TestServeUntilShutdownExitsOnCancel` starts a real server via `serveUntilShutdown`, waits until it's reachable, cancels the context (the SIGTERM analogue), and asserts the function returns within 5s and the listener then refuses connections. `TestServeUntilShutdownSurfacesBindError` covers the startup-error branch. Verified the guard is real: against a blocking implementation (both the pre-fix `log.Fatal(ListenAndServe())` shape and a mutated `ctx.Done` branch on the final code) the test fails at the 5s deadline; against the fix it passes in milliseconds.
