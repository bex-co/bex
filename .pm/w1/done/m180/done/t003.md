## Objective

The bex-native GraphQL datastore metrics query and MCP `get_metrics` / `get_datastore_metrics` accept the same pairs with the same semantics and errors as REST.

## Context

- `lego/backend/internal/metrics/graphql.go:71-80` (`datastoreMetricsQueryInputType`); `mcp.go:264` lists only disk, connections, lag and kv metrics.

## Files

- `lego/backend/internal/metrics/graphql.go`
- `lego/backend/internal/metrics/mcp.go`

## Acceptance criteria

- [x] GraphQL and MCP return the same series REST does for the same window; refusals match REST's codes.

## Outcome

Done 2026-10-17. GraphQL `datastoreMetrics` gains `CPU`, `CPU_LIMIT` and `MEMORY_LIMIT`; `MEMORY` is now generic (Postgres container memory, Key Value used memory as before). MCP `get_metrics` already routed `dpg-`/`red-` through the same verb; `get_datastore_metrics` passes the ids through, and its description lists them.
