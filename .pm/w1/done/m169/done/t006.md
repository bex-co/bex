## Objective

Make the regression check durable beyond the publish workflow. `gitops-validate.sh` must fail if the ClusterStack run image reverts to a Paketo image without libatomic. A freshness test fixture must cover the `ghcr.io` upstream parse/resolve path.

## Acceptance criteria

- [x] A tree that pins `paketobuildpacks/run-jammy-base` as the ClusterStack run image fails `scripts/gitops-validate.sh`.
- [x] `scripts/build-toolchain-freshness.test.sh` covers a `ghcr.io/…:tag` upstream.

## Outcome — 2026-10-04 (local; awaits /ship)

- `scripts/gitops-validate.sh` now asserts that the rendered `ClusterStack bex-jammy-base` `.spec.runImage.image` matches `^ghcr\.io/bex-co/bex-cnb-run@sha256:[a-f0-9]{64}$`, and names libatomic in the failure message. Checked by mutation in a throwaway worktree: reverting `platform.yaml` to `paketobuildpacks/run-jammy-base@sha256:33c1e0d7…` exits 1 with the new `FAIL: ClusterStack bex-jammy-base run image is 'paketobuildpacks/run-jammy-base@…'` message, alongside the existing digest-pinned-input failure. The unmodified tree passes.
- `scripts/build-toolchain-freshness.test.sh` adds a ghcr.io case. It loads the real module and checks that `parse_upstream("ghcr.io/bex-co/bex-cnb-run:latest")` returns `("ghcr.io","bex-co/bex-cnb-run","latest")`. It then runs `resolve_upstream` with the HTTP layer stubbed and asserts the exact ghcr.io anonymous-token URL, the Bearer header and the manifest URL. Mutation check: deleting the `ghcr.io` `REGISTRY_AUTH` entry turns the case red. The full self-test passes.
