# Render's Blueprint schema gained `buildSources` — decide it before re-pinning `render.yaml.json`

Why: the repaired `render-schema` drift job (w1/m165) now fails on genuine upstream drift and will stay red until bex decides what its fail-closed Blueprint compiler does with Render's new build-source fields; re-pinning without that decision would silently change what `render.yaml` bex accepts.

**Source:** split out of `w1/m165` by user decision 2026-09-30 ("the `render.yaml.json` `buildSources` Blueprint schema re-pin is NOT in this milestone"). Evidence first recorded in `.pm/w1/done/m165/README.md` § Scope discovery and § t004.

## Evidence

- `scripts/render-schema-drift.sh` (2026-09-30): `::error title=Render Blueprint schema drift::… pinned=665539cb… upstream=57aa0a1ff9c3…`. The webhook-OpenAPI half passes (`Render webhook OpenAPI enum matches pinned 67-value fixture`), so this is the only red.
- The script's new field report (w1/m165 t004) names what moved upstream:
  - **new definitions:** `buildSource`, `buildSourceGit`, `buildSourceRuntime`, `workflowService`, and the plan split `cronPlan`/`keyValuePlan`/`postgresPlan`/`serverPlan` (removed: `plan`).
  - **new properties:** top-level `buildSources` (and under `ungrouped`, and `project.buildSources`) — "Build sources that are not assigned to a project"; a service-level `serverService.buildSource` link by name; `buildSource` = `{name, git | image}` (exactly one), `buildSourceGit` = `{repo, branch, rootDir, baseDir, buildCommand, buildFilter, dockerfilePath, envVars, region, registryCredential, runtime}`.
  - `serverService`'s Git/image fields (`repo`, `branch`, `buildCommand`, `dockerfilePath`, `dockerContext`, `image`, `registryCredential`, `runtime`, previews) moved under a conditional (`allOf[1].then`) — probably "only when no `buildSource` is linked"; check before deciding.
  - `workflowService` is Render Workflows — check `.pm/DO_NOT_DO.md` / ADR018 (workflows are an omitted surface) before treating it as in scope.
- **Render docs, checked 2026-09-30:** `render.com/docs/blueprint-spec` has zero mentions of `buildSource`/`buildSources`, `render.com/docs/build-sources` is 404, and the changelog has none. The field is in the published JSON Schema but not yet documented — re-check the docs before implementing semantics from the schema alone.

## Decide (per ADR049: the compiler is fail-closed on unknown fields)

For `buildSources` / `buildSource` (and each other new definition), one of:

1. **Accept-and-ignore** — schema-valid, recorded `ignored` in `lego/backend/internal/apps/schema/capabilities.json` with a reason. Only honest if ignoring cannot change what gets deployed; a service that takes its repo from a linked build source would deploy nothing, so this is probably wrong for `buildSource`.
2. **Implement** — resolve a service's `buildSource: <name>` into its Git/image source at compile time (bex already has every field `buildSourceGit` carries).
3. **Reject with a named error** — `unsupported` in `capabilities.json` with a coded message naming the field, like `previews`.

Then re-pin: replace `lego/backend/internal/apps/schema/render.yaml.json` with the upstream bytes and move the digest in `scripts/render-schema-drift.sh` (`expected_sha256`), `lego/backend/internal/apps/blueprint_schema.go` (`RenderBlueprintSchemaSHA256`) and `capabilities.json` (`schema.sha256`). Done when `scripts/render-schema-drift.sh` exits 0 and a `workflow_dispatch` run of `Render schema drift` is green on both jobs (the DoD `w1/m165` could not reach).
