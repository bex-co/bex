## Objective

ADR066 #6 was fixed per call site, and one call site (the bulk patch) was missed. Replace "remember every path" with a test that finds every path.

## Context

- Every write to a service's env or file map goes through `updateMapCAS(ctx, envPath|filesPath, …)` or `storeMap(ctx, envPath|filesPath, …)` in `lego/backend/internal/secrets/`.
- Sibling precedents for source-sweep guards: `TestAuthzGuardsEveryVerb` (backend `CLAUDE.md`), and the `forbidigo` rule added in `w1/m75` for MCP registrations.

## Steps

1. Choose the mechanism, and record why in the test's doc comment. One option is a behavioural guard: every exported verb that can grow a map is exercised with an over-quota input and must return `ErrBadRequest` without a store write, using a fake store that records writes. The other is a structural AST sweep over `updateMapCAS`/`storeMap` call sites on `envPath`/`filesPath`, with a reasoned allowlist (restores and compensations shrink maps back and are exempt).
2. Cover the env-group package's own writes too (`envgroups/patch.go`, `service.go`), so the control stays guarded.
3. Prove the guard: temporarily remove the t001 check and watch it fail.

## Acceptance criteria

- [x] The guard fails on the pre-t001 code and passes after it.
- [x] The allowlist (compensation/restore paths) is explicit, and each entry has a one-line reason.

## Result (2026-09-15)

- **Mechanism: behavioural, with a reflection sweep.** The reason is recorded in the tests' doc comments. A structural sweep over `updateMapCAS`/`storeMap` call sites would have to allowlist every compensation and restore path, and those calls shrink a map back and must not be checked. That is the same kind of exemption list that let `batch.go` go unguarded for a month.
- **`lego/backend/internal/secrets/quota_guard_test.go`** drives `SetEnvVars`, `SetEnvVar`, `SeedEnvVars`, `SetSecretFile`, `SeedSecretFiles` and `PatchEnvironment` (env and files) with a 512 KiB + 1 input. Each must return `core.ErrBadRequest` and leave the store empty. The sweep over `*Service`'s exported methods (skipping those promoted from `core.Base`) fails when a verb named `Set…`/`Seed…`/`Patch…`/`Create…`/`Clone…`/`Apply…` (and similar) has no case.
- **`lego/backend/internal/envgroups/quota_guard_test.go`** is the control. It covers `CreateEnvGroup`, `SetEnvGroupVars`, `SetEnvGroupVar`, `SetEnvGroupVarInput`, `SetEnvGroupFile`, `PatchEnvironment` and `ApplyEnvGroup`. The explicit exemptions, each with a reason:
  - `SetEnvironmentID`, `SetGroupEnvironment`, `MoveEnvGroup`: placement only, no map write;
  - `CloneEnvGroup`: copies maps that were quota-checked when written.
- **Proof.** With `batch.go` reverted to `HEAD`, the secrets guard fails on `PatchEnvironment`, along with every new batch-quota test. With the fix, both guards pass.

## Out of scope

- Guarding non-secret maps.
