## Objective

The Environment editor should refuse, before saving, what the server will refuse. That means a draft whose total secret-file bytes (names plus contents) exceed 512 KiB, or more than 500 files, instead of today's 1 MiB per-file check. Any server refusal that still arrives should show the server's sentence.

## Context

- `dashboard/src/features/services/lib/environment-draft.ts:3` (`MAX_SECRET_FILE_BYTES = 1024 * 1024`), `:142-158` (`validateEnvironmentDraft`: names and contents only).
- `dashboard/src/features/services/components/service-environment-editor.tsx:434` (upload size check) and `:497-502` (`commit`: bare `catch` → `services.environmentSaveError`).
- `w1/m145` owns the class-wide generic-toast sweep and lists `:502`. Coordinate: if m145/t003 has already migrated `:502` to `serverRefusalReason`, this task only verifies it. Otherwise it migrates this one site.
- The env-group editor shares `environment-draft.ts`: check that its limits (the same 512 KiB per group, `envgroups/patch.go:186-189`) also hold.

## Steps

1. Replace the per-file constant with the aggregate contract (512 KiB total of name + content bytes, 500 files) in `validateEnvironmentDraft`, and name the limit in the inline error copy (en + zh).
2. The upload path (`:434`) uses the same aggregate check against the current draft.
3. Route the save error through `serverRefusalReason(err) || t("services.environmentSaveError")`, unless m145 already did.
4. Tests: a draft at 512 KiB + 1 byte is invalid; one at exactly 512 KiB is valid; 501 files is invalid; a server refusal shows the server's sentence; a transport failure shows the generic copy.
