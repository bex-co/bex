## Objective

A `type=build` live tail speaks immediately: on subscribe it emits the already-reached phases' lines for the in-flight deploy, then a new line as each status transition lands — filling the minutes-long Pending window `52882f22`'s wait-for-Running fix still leaves silent.

## Context

- `lego/backend/internal/logs/service.go` `followBuildLogs`/`awaitBuildPod` — the tail now waits for a Pending pod; synthesis rides the same wait loop (poll the deploy row alongside the pod list, emit on phase change), using t002's line builder + ids so a client merging history + tail dedupes cleanly.
- Terminal behavior stays honest: after the closing line (`live`/`build_failed`), the existing terminal semantics apply (`ErrBuildNotRunning` for a post-build subscribe is unchanged).

## Steps

1. Emit already-reached phase lines on subscribe (from the deploy row), then watch for transitions while waiting/streaming.
2. Reuse t002's builder — one vocabulary, one id scheme.
3. Test with the fake clock/pod flip pattern from `TestFollowBuildLogsWaitsForPendingPodToStart`.
