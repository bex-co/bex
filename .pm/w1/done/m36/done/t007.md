## Objective

Automate what's automatable: extend the structural validation (`scripts/gitops-validate.sh` pattern / existing CI checks) to assert the worker templates carry `imageName` and no longer carry the images-pull line or the trimmed packages — so a future template edit can't silently reintroduce the downloads. If nothing further is automatable, record why.

## Acceptance criteria

- [x] A structural check fails if the images-pull line or a trimmed package returns.

## Outcome (2026-07-14)

`scripts/clusterapi-validate.sh` (new, follows the `gitops-validate.sh` pattern — `set -euo pipefail`, `fail=0` accumulator, `yq -N 'select(.kind==…)'`, `FAIL:`/`PASS:`) + `.github/workflows/clusterapi-validate.yml` (PR/push on `infra/clusterapi/overlays/hetzner-caph/**`, `infra/packer/**`, the script itself). It asserts, cluster-lessly:

1. every worker `HCloudMachineTemplate` a `MachineDeployment` points at is `imageName: bex-worker` (not `ubuntu-24.04`), and the ref resolves;
2. no worker `preKubeadmCommands` re-adds a runc/containerd/kubelet download, `kubeadm config images pull`, a `pkgs.k8s.io` install, or a trimmed apt package;
3. the packer bake installs no trimmed package;
4. the packer pins match the overlay (drift guard — added via t006's `/simplify`).

Negative-tested: flipping a worker image to `ubuntu-24.04`, sneaking an images-pull / runc-download line into a worker KCT, and bumping the packer k8s pin out of lockstep each fail with a clear message; the pristine tree passes.
