## Objective

Meaningful tests for what m146 shipped.

## Steps

1. Backend: the three t001 scenarios (a Succeeded-only App stays open and a later pod streams; zero pods stay open and a later pod streams; a Running pod is unchanged), for both the SSE and WebSocket transports.
2. Backend: t002's no-producer refusal (no slot taken), revocation ending an idle stream, deletion ending an idle stream, and heartbeat cadence (fake clock).
3. Dashboard: `use-live-logs` keeps `status: "open"` across heartbeat comments and shows no banner. A genuine transport drop still shows the banner, and a terminal `event: error` still closes.

## Acceptance criteria

- [x] Each new backend test is shown failing on the pre-fix `FollowLogs`.
- [x] Backend `go test ./internal/logs/...`, the dashboard logs suite, and lint are green.

## Result (2026-09-15)

1. **t001 scenarios** (`internal/logs/tail_idle_test.go`):
   - a finished run replays once, the stream stays open, and the next run streams;
   - with zero pods the stream stays open, heartbeats, and the first pod streams;
   - a Pending pod is attached once its container starts;
   - a restarted container is re-attached;
   - the instance filter is applied to pods that appear later.

   Transports:
   - SSE/NDJSON keepalive frames: `TestSubscribeWritesAKeepaliveOnAnIdleTail`;
   - WebSocket ping: `TestSubscribeWebSocketPingsAnIdleTail`;
   - a running pod's tail is unchanged, covered by the existing subscribe, resume, and revalidation tests, all green.
2. **t002 cases:**
   - the no-producer refusal: `TestAppTailStillRefusesAQueryWithNoLiveProducer`;
   - revocation and deletion ending an idle SSE tail and releasing its slot: `TestIdleTailStillEndsOnRevocationAndDeletion`;
   - heartbeat cadence runs on real tickers at a 10 ms test interval, not a fake clock. The package has no clock seam, and the tests assert that heartbeats arrive, not their exact spacing.
3. **Dashboard: no new test, declined with reason.**
   - A heartbeat is an SSE comment line. The EventSource spec drops comments before dispatch, so they fire neither `onmessage` nor `onerror`, and a test of "`status` stays open across comments" would only test the spec.
   - The existing `use-live-logs.test.ts` already covers the two behaviors that matter: "surfaces a transport drop as error but leaves the stream to reconnect", and "closes on a terminal error frame".
4. **Red proof:** with `service.go` and `rest.go` reverted to `HEAD` (plus a shim adding only the two new fields and a heartbeat-ignoring `followLogs`), all 8 new tests fail. With the fix they pass.
5. **Green:**
   - `go test ./internal/logs/` passes;
   - backend `go test ./...` passes (after the `internal/api` test above);
   - `golangci-lint ./internal/logs/...` reports 0 issues;
   - the dashboard suite is untouched by m146.
