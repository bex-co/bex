## Objective

`GET /v1/logs/subscribe` behaves like Render's `GET /logs/subscribe` for an idle resource, and the dashboard's Logs page agrees with it.

## Steps

1. Check the pinned Render OpenAPI contract for `/logs/subscribe` (transport, keepalive, close semantics) and the pinned `render-oss/cli` tail decoder: does it tolerate SSE comments / NDJSON keepalives?
2. If a Render account is available, tail an idle Render cron job and record whether its stream stays open and how it keeps alive. Otherwise say so.
3. Confirm there is still no GraphQL or MCP live-tail surface (grep), so nothing else needs to move. Record it in `docs/ADR018-render-parity.md`'s logs row.

## Acceptance criteria

- [x] The Render comparison is recorded (or noted as unobtainable, with the reason), and any drift is filed as a `w1/NNN` note.

## Result (2026-09-15)

1. **Contract.** The pinned `render-public-api-1.json` `GET /logs/subscribe` says: "Open a websocket connection to subscribe to logs matching the provided filters. Logs are streamed in real-time as they are generated." It documents no keepalive and no close semantics, so nothing in the contract implies a stream should end when a resource is idle. The pinned `render-oss/cli` (`v1.1.3-0.20260909214233-a764810a7682`, `pkg/logs/repo.go:45`) tails over gorilla WebSocket. That library's default ping handler answers bex's new pings without surfacing a message, so the SSE comment and the NDJSON blank line never reach it.
2. **Render's own behavior: unobtainable.** This environment has no Render account or API key, so tailing an idle Render cron job isn't possible.
3. **No other live-tail surface.** A grep for `FollowLogs`/`followLogs` outside `internal/logs/{rest,service}.go` finds nothing, and there is no GraphQL or MCP live tail. `docs/ADR018-render-parity.md`'s logs row now records the idle-tail behavior. There is no drift, so no note was filed.
