Run `/simplify` over the code m146 changed (reuse / simplification / efficiency; behavior-preserving). The likely candidate is a shared pod-watch helper for `FollowLogs` and `followBuildLogs`, if the two loops end up parallel.

## Result (2026-09-15)

This was a single-pass review of the m146 diff (`internal/logs/{service,rest}.go`), not the three-agent `/simplify` run. The change is one producer loop and two transport callbacks, so a full run would have added little.

- **Applied:** removed `streamPodLogs`. The new loop calls `streamContainerLogs` directly for its `opened` signal, which left the wrapper with no caller. golangci's `unused` flagged it, and whole-program deadcode would have too.
- **Applied:** both transports keep the heartbeat in the same goroutine as `emit`, so no writer lock is needed. SSE and NDJSON share one `write` closure with the frame path, so the keepalive and a log line flush the same way.
- **Declined:** a shared pod-watch helper for `followAppPods` and `followBuildLogs`. The build tail attaches to the successive init containers of one pod and ends when that pod does. The app tail attaches to a changing set of pods, one container life each, and never ends by itself. The only shared piece is a ticker plus a list, and a helper parameterized over both would be longer than the two loops.
- **Green:** `golangci-lint run ./internal/logs/...` reports 0 issues, and `go test ./...` passes across the backend. `internal/api` needed `TestSSEConnCapRejectsExcess` to disconnect its third subscribe itself, because a tail no longer ends on its own. `make lint-backend`'s only finding is the pre-existing `internal/api/scope_matrix.go:163` (`36457c620`).
