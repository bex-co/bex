## Objective

Add `bex agent automations` (aliases `automation`, `aut`) under the shipped `bex agent` group with the read verbs: `list [--mine] [--limit] [--cursor]`, `get <automation>`, `runs <automation> [--limit] [--cursor]`. An `<automation>` is an `aut-` id or a name (the API resolves either). Text output renders the schedule in words ("every day at 09:00 Europe/Berlin, until 2026-12-31"), next fire, last run and `pausedReason`; `-o json|yaml` prints the API's own answer.

## Context

- Design and full CLI spec: `docs/ADR106-cli-cloud-agents-automations.md` (+ `.svg`).
- Shipped group to extend: `lego/cli/internal/agent/` (`agent.go` commands and exit codes, `api.go` REST client, `render.go` text output, `watch.go` polling waits, `types.go` hand-decoded shapes).
- Constraints: the CLI imports no sibling module (thin client, every rule stays in bex-api); never touch the imported Render command tree; `.pm/DO_NOT_DO.md` #APPROVAL-MODE (no permission prompts, no `needs_input`, no agent→user channel).
- Routes: `lego/backend/internal/agentsessions/automations_rest.go` (`GET /v1/agent-automations[?mine=]`, `GET …/{id}`, `GET …/{id}/runs`).
- Shapes: `AgentAutomation`, `AutomationTrigger`, `AutomationSchedule` (`automation_schedule.go`), `AgentAutomationRun` (`automation_run.go`).
