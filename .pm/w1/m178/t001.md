## Objective

Know exactly what Render passes into a Dockerfile build before implementing: which variables become build args, in what precedence, how secret files are exposed, and whether an env edit rebuilds.

## Context

- render.com/docs/docker-secrets (fetched 2026-10-17): "Render injects your service's environment variables as build args with the same keys and values"; secret files are BuildKit secrets whose id is the filename with every character outside `[A-Za-z0-9_-]` replaced by `_` (`.env` → `_env`, `credentials.json` → `credentials_json`), default path `/run/secrets/<id>`, `required=true` fails the build when absent.
- Unknowns to settle from docs or captured behavior: are linked environment-group variables included, and in what precedence against the service's own; does saving an env var on a Docker service rebuild ("Save, rebuild, and deploy") or only redeploy.
- `.pm/w1/README.md` Render decision rule: if unsure, keep parity with Render; record any inferred default as such.
