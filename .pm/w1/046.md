## Supply-chain hardening pass (F11, F13, F14, F15) — one grouped chunk

One class: version-pinned + HTTPS, but no independent integrity binding. Promote as a single milestone if a plausible upstream-compromise signal ever appears, or fold opportunistically into work that already touches these files.

- **F11 — FIXED 2026-08-17 by `w7/m82` t004.** `lego/operator/internal/build/build.go` passed `--dest-tls-verify=false` unconditionally on the skopeo push: inert on the tracked in-cluster HTTP Zot, wrong the moment `BEX_REGISTRY` names a TLS registry. The flag is now conditional on `registryIsClusterLocal` (Kubernetes service suffixes, `.local`/`.internal`, loopback, or a single-label host), so the shipped default is byte-identical while an external registry gets verification. Pinned by `TestPushTLSVerificationIsConditional`, which asserts both directions. The disposition was "do this next time the build path is touched" — ADR060 D4 was that occasion.
- **F14** `.github/workflows/app-cluster.yml:62-217`, `.github/workflows/deploy.yml:482-515` — clusterctl download, remote Helm chart installs, and `kubectl apply -f https://raw.githubusercontent.com/argoproj/argo-cd/v3.4.6/manifests/install.yaml` all execute/apply with cluster-admin using version names only.
- **F15** `infra/packer/bex-worker.pkr.hcl:135-153`, `infra/clusterapi/overlays/hetzner-caph/sandbox-pool.yaml:220-236` — runc/containerd/runsc/shim binaries verified against checksums fetched from the **same origin** as the artifacts; root install on nodes that run tenant workloads.
- **F13** `infra/terraform/cloud-init.yaml.tftpl:5-11` — `curl -sfL https://get.k3s.io | … sh` as root. Bootstrap is disabled by default (`infra/terraform/main.tf:57-84`), so this only matters during bring-up/DR.

## Small residuals

- **F17** invite-accept OpenFGA projection is best-effort and **not self-healing**: `store/members.go:315-327` commits role + `accepted_at` together, later invite scans filter `accepted_at IS NULL`, and `tenancy.ensureGranted` only covers the caller's own workspace — so a transient OpenFGA failure during a re-invite-to-lower-role strands the prior higher tuple. Narrow (needs the downgrade **and** a coincident failure; an explicit role change repairs it and surfaces errors). Right fix is an outbox/reconciler for cross-datastore authorization projection — build it when the next projection bug appears, not standalone.
- **F18** `logs/service.go:731-814` — `FollowLogs` authorizes once then streams indefinitely; `core.PositiveTTL` is 30s, so a stream opened within 30s of revocation outlives it forever. Cheap partial: cap stream lifetime to the revocation SLO and force reconnect. **Re-owned 2026-08-17 as `w4/034`; use the shipped `AuthorizeAppFresh` seam rather than accepting a cached positive.**
- **F16 residual** — admission-time signature enforcement for platform (not tenant) images, and splitting snapshot access from upload credentials across backup stages. Deferred by `w1/m66/t006`.
- **F7 residual** — independently pinning the Kubernetes CA fingerprint before accepting a fetched `admin.conf` (the host-key pin in `w1/m66/t005` is the load-bearing half).

## Round-5 residuals (2026-08-10, scan `codex-security-bex-UAO3Zb`, revision `deedf4eb`)

The round-5 scan ran against the `m66`+`m67` fix commit and returned 11 findings. Triaged the same day, all verified against source: five went to `w1/m68` (Tier 1 + the two activations), F4 already has its own footing, and these four are accepted, already-recorded, or too small to schedule.

- **R5-F6 — mutable helper-image tags (medium).** Extends the supply-chain chunk above from the gitops charts (which `m66/t006` digest-pinned) to the images the **operator generates into Jobs**: `moby/buildkit:v0.30.0`, `alpine/git:v2.43.0` (both `build/build.go:61-62` and `publish/publish.go:53`), `busybox:1.37.0` (`build/native.go:30`), `gcr.io/projectsigstore/cosign:v2.4.1` (`build/build.go:68`), `amazon/aws-cli:2.22.35` (`publish/publish.go:49`), `alpine:3.21` (`keyvalue_backup.go:51`), plus `valkey/valkey:8-alpine` and `oliver006/redis_exporter:alpine`. Each receives source, Git tokens, registry credentials, a signing key, or object-store credentials. Note the shape: `defaultPushImage` in the **same const block** is already digest-pinned, so the pattern and the guard precedent (`gitops-validate.sh`) both exist — this is mechanical whenever the build path is next touched. Fold in F11 above (unconditional `--dest-tls-verify=false`) while there.
- **R5-F9 — agent-session token is repository-wide `contents:write` (medium).** **Accepted architectural limit, not a defect.** `agentsession/contract.go:98-105` states it outright ("This is a policy check, not a claim that GitHub installation tokens encode a branch scope; tenants must still protect default branches"), and ADR047 D2 documents it. GitHub installation tokens cannot encode a ref scope, so the mint gate validates `bex-agent/*` while `github/client.go:190-204` necessarily hands over repo-wide write. The real remediation — routing pushes through a server-side git proxy that validates the destination ref — is milestone-sized and should be scheduled as a product decision, not as a security patch. Cheaper interim: verify at connect time that the installation's repositories carry a ruleset denying the app writes outside `bex-agent/*`, and document it as an installation prerequisite.
- **R5-F11 — process-global live-log subscription pool (medium).** **The fairness half is already fixed on current main:** `logs.Service.acquireSubscription` enforces `MaxSSEConnsPerSubject` and `MaxSSEConnsPerWorkspace` (wired as `BEX_MAX_SSE_CONNS_PER_SUBJECT`/`_PER_WORKSPACE`) in addition to the global cap and producerless-request rejection. Only F18's fresh authorization lifetime remains; it is now `w4/034`.
- **R5-F4 — `onbex.co` is not a PSL private suffix (medium).** Deliberate, and the code says so: `hostingdomain/suffix.go:29-56` returns a recoverable `ErrUnlistedSharedSuffix`, `cmd/manager/main.go:121-134` warns and proceeds, and `config/manager/manager.yaml:151-157` explains why. Failing closed would take down all shared hosting; the only real fix is submission to `publicsuffix/list`, which then waits on browser releases. **The one action worth taking now is starting that clock** — the lead time is months, so submitting is cheap and everything else waits on it regardless. Until listed, host-only and `__Host-` cookies remain isolated and the platform Kratos cookie is on `bex.co`, a different registrable domain.

### Lineage note

Round 5's most useful signal is not any single finding: it is that **F2 and F7 are the unfixed remainder of a class round 4 partially fixed.** `codex #1` upgraded five executable-selection verbs to `can_create` and left four; nothing failed, because the pinned neighbors in `representativeVerbRelations` now read as evidence the class was handled.
