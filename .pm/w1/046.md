## Supply-chain hardening pass (F11, F13, F14, F15) — one grouped chunk

One class: version-pinned + HTTPS, but no independent integrity binding. Promote as a single milestone if a plausible upstream-compromise signal ever appears, or fold opportunistically into work that already touches these files.

Inert on the tracked in-cluster HTTP Zot, wrong the moment `BEX_REGISTRY` names a TLS registry. **Cheap:** condition the flag on the registry scheme / an allowlisted dev endpoint. Do this next time the build path is touched.

## Small residuals

- **F17** invite-accept OpenFGA projection is best-effort and **not self-healing**: `store/members.go:315-327` commits role + `accepted_at` together, later invite scans filter `accepted_at IS NULL`, and `tenancy.ensureGranted` only covers the caller's own workspace — so a transient OpenFGA failure during a re-invite-to-lower-role strands the prior higher tuple. Narrow (needs the downgrade **and** a coincident failure; an explicit role change repairs it and surfaces errors). Right fix is an outbox/reconciler for cross-datastore authorization projection — build it when the next projection bug appears, not standalone.
- **F18** `logs/service.go:731-814` — `FollowLogs` authorizes once then streams indefinitely; `core.PositiveTTL` is 30s, so a stream opened within 30s of revocation outlives it forever. Cheap partial: cap stream lifetime to the revocation SLO and force reconnect. Do it next time the logs service is touched.
- **F16 residual** — admission-time signature enforcement for platform (not tenant) images, and splitting snapshot access from upload credentials across backup stages. Deferred by `w1/m66/t006`.
- **F7 residual** — independently pinning the Kubernetes CA fingerprint before accepting a fetched `admin.conf` (the host-key pin in `w1/m66/t005` is the load-bearing half).
