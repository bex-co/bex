# A sandbox's Logs: serve Render's `sandbox` logs filter and add the drawer's Logs tab

Why: Render's sandbox details drawer has a Logs tab (Render's log explorer filtered to the sandbox, shown with the group permission `viewSandboxLogs`), and its events' "View in logs" opens it at a command's time; bex's drawer (w1/m658) has no Logs tab because bex-api refuses the filter.

Today `GET /v1/logs` refuses Render's `sandbox` filter by name ("sandbox output is not served by the logs API", `unsupportedLogFilters` in `lego/backend/internal/logs/rest.go`), and a command's output is read only from its run stream. Render's dashboard reads a sandbox's logs through its log explorer with the sandbox as the resource (bundle read 2026-11-26: the drawer's `logs` tab, `viewSandboxLogs`, an execution event's `onViewLogs({startedAt, completedAt})`).

Done when: REST `list-logs` (and GraphQL, MCP) serve the `sandbox` filter for a sandbox of the caller's workspace (another workspace's answers not found), the sandbox drawer (`dashboard/src/features/sandbox-group-pages/components/sandbox-drawer.tsx`) shows a Logs tab with the sandbox's output, an execution event's View in logs opens it at the command's time, and `docs/render-artifacts/dashboard-operations.md` and `sandbox-groups.md` § What bex does say so.
