# Render's Stripe integrations: the Stripe account connection and Stripe's agentic account link

Why: Render's dashboard connects a Stripe account to a workspace, and lets Stripe provision and manage Render resources for a user through an agentic account link; bex has neither and no disposition for them.

- **Found:** w1/m645's dashboard ledger (2026-11-26). Rows in [dashboard-operations.md](../../docs/render-artifacts/dashboard-operations.md): `connectStripeAccountMutation`, `disconnectStripeAccountMutation`, `hasStripeConnection` (Billing and usage) and `confirmAgenticAccountLink`, `agenticTokenSignIn` (Account and sign-in).
- **Render (bundle, no flag):**
  - The Stripe connection: `hasStripeConnection(ownerID)`, `connectStripeAccount(ownerID, token)` and `disconnectStripeAccount(ownerID)`. A connect page says "Your Stripe account is connected!" and "Return to the Stripe dashboard to connect your database."; disconnecting toasts "Stripe disconnected successfully".
  - The agentic link: a page reached from Stripe with a one-time key in the URL fragment, "By proceeding, you agree to let Stripe access your Render account to provision and manage resources. You can revoke this access at any time from your Render account settings.", then `confirmAgenticAccountLink(key)`; expired keys get "This link has expired or has already been used. Please try again from Stripe." `agenticTokenSignIn(token)` signs a user in with a token of the same flow.
- **bex:** Stripe is only bex's own billing processor ([ADR040](../../docs/ADR040-billing-metronome.md)); no partner integration exists.
- **Needs:** Render's docs for both flows (render.com/docs, Stripe's partner pages) read before deciding; then either a milestone per integration or the user's sign-off on a non-goal.
- **Done when:** each integration has a filed milestone or a signed-off non-goal (DO_NOT_DO line or ADR018 `—` row), and the five ledger rows point at it.
