## Objective

A table test drives every path under Render's `/metrics` and each of its documented query parameters through the composed server and the strict validator. It asserts that each is served, refused with a code, or listed as a recorded non-goal or divergence, so an accepted-but-ignored parameter or a bare `404` can't come back unnoticed.

## Context

- **Paths.** Render's pinned spec has 21 `/metrics` paths.
- **Recorded non-goals:** `metrics-stream/{ownerId}` (`.pm/DO_NOT_DO.md:24`) and `task-runs-queued` / `task-runs-completed` (`DO_NOT_DO.md:26`).
- **Precedent.** `w1/089` found that no test walks bex literals against Render templates; this is the metrics-family instance of that gap.
- **Found at filing:** one ignored parameter (`aggregateBy`) and eight bare `404`s (m155 README § Blast radius).

## Steps

1. Generate the path × parameter matrix from `render-public-api-1.json`. Do not hand-list it.
2. For each served parameter, assert it changes the query. For example, `aggregateBy` changes the series count, `instance` narrows, `aggregationMethod` changes the value. A parameter that changes nothing fails, unless it is allowlisted with a reason.
3. Paste the matrix result (served, refused or recorded, per path) into the m155 README.
