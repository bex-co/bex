# Complete the email-verification UX, then require verified email for invites

Filed by w1/m53/t004 (security review V1). Kratos email verification is enabled
(`verification.via: email` in `kratos.values.yaml`) but the dashboard has **no
`/auth/verification` route**, so the emailed verification link dead-ends and no
user can reach a verified state. Because of that, w1/m53 shipped the invite-
redemption gate (`BEX_REQUIRE_VERIFIED_INVITE_EMAIL`, `Identity.EmailVerified`)
**off by default** — turning it on now would block every invited teammate.

Do:

1. Add the dashboard `/auth/verification` route (submit-code + resend), wiring the
   Kratos verification flow (`ui_url: https://dashboard.bex.co/auth/verification`
   is already configured). Confirm a user can complete verification end to end.
2. Flip `BEX_REQUIRE_VERIFIED_INVITE_EMAIL=1` on bex-api so login-time invite
   redemption requires a Kratos-verified email — closing the window where an
   attacker registers with a victim's not-yet-signed-up invited address and
   claims the invite.

Refs: `docs/ADR024-members.md` § Email verification and login-time redemption;
`internal/api/{auth.go,tenancy.go}`; `internal/core/identity.go`.
