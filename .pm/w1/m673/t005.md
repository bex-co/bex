## dev-1 walk (2026-11-26)

bex-api was built from the tree (`bash scripts/dev-env.sh 1 up`). It ran with `BEX_IMAGE_PLATFORM=linux/arm64`, the shared operator's value, because dev-1's nodes are arm64. The walk used a disposable identity and its own workspace, and deleted its disposable web service and two dummy credentials afterwards.

**GraphQL** (session token, real registries):

| Input | Answer |
| --- | --- |
| `docker.io/library/nginx:latest`, and `docker.io/arm64v8/nginx:latest` on the arm64 stack | deployable |
| `nginx:no-such-tag-m673` | `does_not_exist` (manifest unknown) |
| `Not An Image` | `invalid_input_url` |
| `docker.io/amd64/nginx:latest` | `unsupported_platform` ("has no linux/arm64 image") |
| an unknown Docker Hub repository, and `ghcr.io/bex-co/<missing>`, anonymously | `does_not_exist` |
| `127.0.0.1:5000/…`, `169.254.169.254/…` | `invalid_input_url`, no dial |
| `127.0.0.1.nip.io/…`, `169.254.169.254.nip.io/…` | `invalid_input_url` ("resolves to a private or reserved address"), refused by the guard |
| a host that does not resolve | `does_not_exist` |
| a dummy Docker Hub credential, on a private path and on `nginx` | `invalid_registry_credential` (auth.docker.io 401) |
| a dummy GHCR credential on a GHCR path | `invalid_registry_credential` (ghcr.io token 403) |
| the GHCR credential on a Docker Hub image | `invalid_registry_credential`, no request |
| an unknown credential id | `not found`, as `registryCredential(id)` answers |

Every check took 0.2–0.9 s. API keys: a Workspaces Read key got an answer, and a Services Read & write key was refused with `api_key_permission_denied` naming `workspace.registry.view`. Both keys were revoked.
