## Objective

Add a GraphQL read that compares the service's live release with a target deploy's release and returns Render's snapshot shape: keys and names only, never values.

## Context

- Release records and snapshots: `lego/types/v1alpha1/releasesnapshots.go` (`ReleaseRecordName`, `AppReleaseSnapshotName`), `lego/backend/internal/deploys/rollback_config.go` (`targetReleaseConfig`), ADR004 § Per-release configuration snapshots.
- w4/m145's `undeployedChanges` comparison (saved sources against the active record) is the closest existing code; reuse it rather than a second differ.
- GraphQL lives in `lego/backend/internal/deploys/graphql.go` next to `rollbackService`. New operations need rows in `lego/backend/internal/api/scope_matrix_ops.go` and `key_permission_ops.go`.

## Steps

1. Resolve the live and target generations; read both records and their env and file snapshots (uncached client, as the rollback path does).
2. Compute the fields below:
   - start, pre-deploy and docker command, health check path, instances and plan;
   - env var and secret-file key sets: created, deleted and updated (updated compares values server-side, or their hashes);
   - linked and unlinked env groups, and the deleted group count.
3. A missing record on either side (reclaimed, older than records, or a version-0 record) returns a null snapshot for that side: Render shows its one "Unable to load configuration…" sentence then (amended 2026-11-26).
4. Return the plans' CPU and memory so the dialog can show Render's plan warning.

## Files

- `lego/backend/internal/deploys/` (new comparison + GraphQL field), schema test data, scope and permission tables

## Acceptance criteria

- [x] Tests cover a changed key set, an updated secret file, an unlinked group, a missing target record and a missing live record; no response contains a value.

## Out of scope

- REST or MCP surfaces (Render has none).

## Outcome (2026-11-26)

`lego/backend/internal/deploys/rollback_comparison.go`: GraphQL `rollbackComparison(serviceId, deployId)` reads the serving release's and the target's records and their own env and file copies, compares values server-side and returns names only. Env groups come from each record's group refs and the workspace's groups (`EnvGroupIDsByName`); `currentPlanLower` compares the saved tier with the one the target's pod template ran in the compute ladder. It needs `can_view_activity` and the Environment page's key access (`secrets.EnvironmentKeysAccess`: `can_view_sensitive`, Admin in a protected environment). Op rows: `scope_matrix_ops.go` read, `key_permission_ops.go` `deploys.rollback`. Deviation: the tests use the package's fake store and fake cluster client, since the comparison reads cluster Secrets and only deploy rows from Postgres; the real-DB backend suite runs at `/land`.
