## Objective

On every create form that embeds `ServiceSourcePicker`, a `GitConnections` poll never replaces the GitHub tab with its skeleton once the connection is known. The repo search keeps focus mid-typing, the repo list keeps its scroll, and `GitCredentialsMenu` keeps its popover and disconnect confirm open.

## Context

- **The gate.** `dashboard/src/features/services/components/service-source-picker.tsx:159` renders `connectionLoading ? <Skeleton className="h-24 w-full" /> : gitHubDisconnected ? … : …`.
  - `connectionLoading` is `useGitConnection().loading` (`:77-79`).
  - `gitHubDisconnected` is `!connectionLoading && connection?.connected !== true` (`:84-85`).
  - The search state is at `:82`.
- **The hooks.** In `features/git/hooks/use-git-connection.ts`, the query uses `cache-and-network` and polls (`:50-60`, `pollInterval` at `:58`). `useGitConnection` returns raw `loading` (`:82`), and so does `useGitConnections` (`:114-120`).
- **The guarded sibling.** `features/git/components/connect-github-card.tsx:87` uses `loading && connections.length === 0 && !error`.
- **Consumers, per the pass-25 trace (re-verify):** `routes/services.new.tsx:139`, `routes/blueprints.new.tsx:162` and `service-source-card.tsx:204`.
- **Live evidence.** m153 README § Evidence 4.

## Steps

1. **Report first load only.** Return first-load-only `loading` from `useGitConnection` and `useGitConnections`, or apply t004's convention. Keep a separate flag only if a caller truly needs "refreshing".
2. **Check the disconnected state.** Confirm `gitHubDisconnected` cannot flip to the "Connect GitHub" empty state during a poll while the connection is cached.
3. **Probe the menu live.** Open `GitCredentialsMenu`'s popover and its disconnect confirm (without confirming), wait 65 s, and check both stay open. Also check the picker on `/blueprints/new`.
