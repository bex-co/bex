## Objective

Settle one rule and apply it everywhere: once polled or refetched Apollo data exists, it never unmounts stateful UI. Decide whether the rule lives in the Apollo client defaults or in the hooks, apply it to every polled hook that still returns the raw flag, place the partial sites and the `refetchQueries` path, and write the rule down so the next hook doesn't repeat the bug.

## Context

- **Apollo 4.1.3 semantics.**
  - `notifyOnNetworkStatusChange` defaults to `true` (`node_modules/@apollo/client/CHANGELOG.md:709`, `core/QueryManager.js:708`).
  - `loading` is `isNetworkRequestInFlight(networkStatus)` (`core/ObservableQuery.js:1307`), which includes poll = 6.
- **Option A, global.** Set `defaultOptions.watchQuery.notifyOnNetworkStatusChange = false` on the client, restoring Apollo 3 behavior for queries that don't opt in. Four hooks opt in explicitly and must keep working: `use-resource-actions.ts:50`, `use-invite-redemption.ts:25`, `use-service-events.ts:93` and `use-webhook-event-types.ts:23`.
  - Check where the client is built (`dashboard/src/common/apollo/`) and whether any `defaultOptions` already exist.
  - Check which callers show a refresh spinner from `loading` after `refetch()`, since they would lose it.
- **Option B, hook-level.** Every polled hook's `loading` means "no data yet", following the rule `use-env-groups.ts:109-112` documents, with an explicit `refreshing` flag only where a caller needs one.
