## Objective

Export a per-app counter for bytes the client sends on a hijacked WebSocket connection, alongside today's egress counter.

## Context

- `deploy/gitops/charts/traefik-plugins/websocketegress/websocketegress.go` wraps the hijacked connection and counts writes only.
- The existing metric is `bex_websocket_egress_bytes_total{app_id}`.
- The plugin rolls out with Traefik through Argo, so its version bump is an edge change.

## Steps

1. Count reads on the hijacked connection into a second counter, named for ingress and labeled the same way.
2. Keep the egress counter's name and semantics unchanged.
3. Bump the plugin version and its chart reference.

## Files

- `deploy/gitops/charts/traefik-plugins/websocketegress/`

## Acceptance criteria

- [x] Both counters increment on a connection carrying traffic in that direction, and neither counts the other's bytes.
- [x] The plugin's own tests pass.

## Out of scope

- Counting frames rather than bytes, or per-connection cardinality.
