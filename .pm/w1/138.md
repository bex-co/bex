# Keep single-instance services up through node rolls

Why: a node drain evicts a one-instance service's only pod before its replacement is scheduled, so a full pool turns routine maintenance into an outage; Render does not drop service during host maintenance.

Filed 2026-10-24.

- Incident: the w5/174 tenant-pool roll (2026-10-24 ~06:30 UTC) evicted `beancount-cms-v2`'s only pod; the replacement stayed `Pending` (no serving node had room for a standard instance since 2026-10-23 22:00 UTC), so beancount.io answered Traefik's `no available server`. `reverse-proxy-poc` too. Stopgap: `bex-tenant-0` autoscaler max 3 → 5.
- Options: pre-scale/surge (or reserve headroom) so replacements schedule before eviction; PodDisruptionBudget-aware drains with a temporary surge replica; a pre-roll capacity check in `scripts/wait-capi-rollout.sh` that refuses when serving nodes lack room for every evicted pod.
- Honesty gap: the deploys list kept showing the 2026-10-21 deploy as `live` while zero pods ran, and no `server_failed` event fired after the eviction — surface "no running instance".
