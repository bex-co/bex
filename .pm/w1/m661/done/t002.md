## Objective

Each instance bex lists for a service says which deploy it runs and its status, in the values t001 recorded, on GraphQL.

## Context

- `apps.Service.ListInstances` (`lego/backend/internal/apps/service.go:1778`) lists the App's own pods; `ServiceInstanceView`; GraphQL `serviceInstances(id)` and `type ServiceInstance` in `lego/backend/internal/api/testdata/schema.graphql`.
- Pods carry `app.bex.co/revision` (`lego/types/v1alpha1/labels.go:33`); a deploy row carries its release generation (`lego/backend/internal/store/`).
- REST `GET /v1/services/{id}/instances` and MCP keep Render's pinned `serviceInstance` (`id`, `createdAt`).

## Steps

1. Map each pod's revision to the deploy row of that release; answer null when no row matches (never guess).
2. Map the pod's state to Render's instance statuses as t001 recorded them (for example running, succeeded, failed, pending).
3. Add `deployId` and `status` to GraphQL `ServiceInstance` only; regenerate the dashboard types and the schema snapshot.
4. Keep the read authorized as it is (`can_view`).

## Files

- `lego/backend/internal/apps/service.go`, its GraphQL file
- `lego/backend/internal/api/testdata/schema.graphql`
- `dashboard/src/graphql/` (generated)
