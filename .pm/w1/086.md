# 086 — "Move to project" from a resource row joins a project with no environment, so the project page opens on an empty environment while the moved resource sits under "Unassigned"

Why: right after a successful move, the project page says the resource isn't there. It is in the project, but behind a picker option the page doesn't select. The create form meanwhile tells users this state cannot exist.

- **Severity:** minor. Nothing is lost and the resource is one click away, but the page misleads immediately after a success toast.
- **Found:** live `/qa-find-bugs` hunt of `https://dashboard.bex.co`, 2026-09-14 pass 4, journey 1 (placement under change). Workspace `bex` / `tea-d98210cbbpdc73dcrkvg`. Fixtures: project `qa-20260914-p4` (`prj-dajsei0gsm7s73f6472g`) with environment `qa-e4` (`env-dajsei26m8ac739r5m50`), and a free Key Value `qa-20260914-kv4` (`red-dajsei26m8ac739r5m5g`) created ungrouped. All three were deleted inside the run.

   ```text
   → {"data":{"setProjectKeyValues":{"id":"prj-dajsei0gsm7s73f6472g","keyValueIds":["red-dajsei26m8ac739r5m5g"],…}}}
   ```

3. The API:

   ```text

   project { keyValueIds: ["red-dajsei26m8ac739r5m5g"] }
   ```

4. Open `/project/prj-dajsei0gsm7s73f6472g`. The page canonicalizes to `?env=env-dajsei26m8ac739r5m50` and shows **`qa-e4 · 0 resources · All (0) … No resources in this environment yet.`** The store is not mentioned anywhere on the page.
5. The **Selected environment** picker offers `qa-e4` and **Unassigned**. Choosing Unassigned (`?env=unassigned`, also reload-stable) lists `qa-20260914-kv4 · Key Value · Available`.

## Root cause

- **Row menu is project-level only.** `MoveToProjectMenu` → `useMoveToProject` (`dashboard/src/features/projects/hooks/use-move-to-project.ts`) calls `setProject{Services,Databases,KeyValues}`, which sets project membership and never an environment. It is mounted in three row menus: `service-row-actions.tsx:205`, `database-row-actions.tsx:179`, `key-value-row-actions.tsx:103`. The project page's own multi-select Move (w5/m41) is environment-targeted and is not affected.
- **Project page defaults to the first environment even when it is empty and unassigned rows exist.** `dashboard/src/features/environments/components/environments-panel.tsx:100-104`: `selectedId` falls back to `environments[0]?.id` before considering `UNASSIGNED_ENVIRONMENT`, and only uses Unassigned when there are no environments at all. The empty state is `environments.cardEmpty` (`environments-panel.tsx:279`).
- **The create-form hint states an absolute that the row menu breaks.** `dashboard/src/features/environments/locales/en.ts:324-326` (`environments.assignmentHint`, plus `zh.ts`) says "A resource joins a Project only through an Environment." That holds for the create path (w6/m48/t003 confirmed a create with Project but no Environment leaves `projectId` empty), but the row menu produces exactly the project-without-environment state the hint says is impossible.

## Fix — target behavior (≤1h, dashboard only)

1. **Default selection:** when no `?env=` is requested, select the first environment that has rows. If none has rows and `unassignedRows.length > 0`, select **Unassigned**. Otherwise select the first environment, as today. An explicit `?env=<id>` or `?env=unassigned` is always honored unchanged (w5/m41's reload-stable URLs).
2. **Copy:** scope `environments.assignmentHint` to what it describes, i.e. **creating** a resource. Reword it so it no longer claims project-only membership is impossible, e.g. "When creating a resource, it joins a Project through an Environment…". Update en and zh together.
3. **Tests** in `environments-panel`: (a) all environments empty plus an unassigned row → Unassigned selected; (b) a populated second environment → that environment selected; (c) explicit `?env=<empty-env-id>` stays on it; (d) no unassigned rows → the first environment, which is the existing behavior and the control.

**Not this note, a product question instead:** Render places every project resource inside an environment. A row menu offering **Project ▸ Environment** would remove the Unassigned state for this path entirely, but that changes a surface w5/m41 shipped. File it separately if wanted.
