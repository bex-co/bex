## Objective

When the newest release has a terminal failed verdict (the pre-deploy command for this release generation, or a recorded terminal build failure) and a prior release is serving, the reconcile still converges runtime state for that prior release: desired replicas (wake, hibernate, scale), the Deployment's replica count, the Service and the Ingress backend. It never rolls the failed release: no template, image, env or pre-deploy change reaches the pods.

## Context

- **The gate.** `Reconcile` computes `desiredReplicas` at `lego/operator/internal/controller/app_controller.go:2022`. It runs `reconcilePreDeploy` only when `!app.Spec.Suspended && !autoHibernating` (`:2051-2055`) and returns on `halt` before the Deployment `CreateOrUpdate` (`:2057`) and `ingressBackend` (`:2118`).
- **The verdict.** The persisted `PreDeployFailed` branch (`:4395-4400`) calls `failPreDeploy`, which returns `halt=true` on every pass of that release generation (`:4515-4527`). Hibernating works because the gate is skipped while `autoHibernating`. Waking re-enters it and halts, so replicas stay 0 and the Ingress stays on the activator alias.
- **The build analogue.** `buildFromSource` halts on `terminalBuildFailureRecorded` (`:755-756`), and `resolveDeployImage`'s halt returns before `dispatchRuntime` (`:591-594`).
- **Precedents.**
  - `convergeRegistryCredentials` (`:598-628`) converges before the build gate precisely because "a failed newer build deliberately leaves the previous Deployment serving".
  - Operational generations already skip release gates: "reconciles a normalized scale change without source access, build, pre-deploy, or rollout" (`release_identity_envtest_test.go:83`).
- **Routing.** `holdHibernateForRouting` (`:2035`) and `ingressBackend` (`:2328-2359`) keep the route on the activator until a pod is ready.
- **Live evidence.** m156 README § Evidence.

## Steps

1. **Write the failing envtest first.** An App with `status.activeRevision` and a Deployment at the prior pod template, a failed `status.preDeploy` for the current release generation, and a hibernated state: `last-active` past the window, Deployment replicas 0, Ingress on the activator. Stamp a fresh `last-active`, the activator's wake, and reconcile.
   - The Deployment scales to 1 with the prior pod template unchanged.
   - Once the pod is ready, the Ingress backend is the App's own Service.
   - No pre-deploy Job is created, and the verdict is unchanged.
   - Repeat with a recorded terminal build failure in place of the pre-deploy verdict.
2. **Implement the smallest change that keeps "the failed release never rolls".** Candidates:
   - converge replicas and routing on the existing Deployment when a failed verdict halts the release path;
   - dispatch the runtime with the active release's artifact and template.

   Record the choice in a code comment.
3. **Keep the phase honest.** Hibernated while parked, Running only once a pod serves, and the failed deploy row unchanged.
