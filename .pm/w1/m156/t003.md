## Objective

Run the m156 definition of done on production after the fix deploys. Probe the failed-build variant first, and add a DoD bullet for it if it reproduces.

## Context

- **Fixtures.** Throwaway free web services from `examples/hello-go` (docker, `dockerContext: examples/hello-go`, which is repo-root-relative).
- **Timing.** A free service hibernates after 15 minutes without traffic (w1/m151 reads served traffic, so idle means no requests at all), so allow about 20 minutes per sleep.
- **Failed build.** Change `dockerfilePath` to a missing file, or set a start command that makes the image build fail. The build fails while the prior release keeps serving.

## Steps

1. **Failed pre-deploy.**
   1. Set Pre-Deploy Command `echo qa; exit 3`, and wait for `pre_deploy_failed` with the service still serving `200`.
   2. Leave it idle until `service_hibernated`.
   3. Sample the URL every second: expect `503` for the wake, then the prior release's `200` within 60 s.
   4. Record the phase and events throughout.
2. **Failed build.** Repeat with a failed build over the serving release.
3. **Control.** A hibernated service whose latest deploy is live.
4. **Record** every transcript in the m156 README, then delete every fixture (`DELETE` → `204`, `GET` → `404`).
