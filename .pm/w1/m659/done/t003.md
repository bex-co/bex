## Objective

When a service's instance listens on 18012, 18013 or 19099, bex records it and answers it, so the deploy page can show Render's reserved-port warning, instead of dropping the listener and leaving the user with a generic "no open port" hint.

## Context

- `listenerSet` (`lego/operator/internal/controller/private_ports.go:396-404`) drops every reserved port from a scan's answer, so `openPorts` never holds one, and no `DeployReasonHint*` (`lego/types/v1alpha1/deploy_reasons.go:140-165`) names a reserved port.
- The reserved set is Render's three (`ReservedImagePorts`, `lego/types/v1alpha1/image_network.go:64-78`); bex's edge-cache sidecar listens on 19099 (w21/076).
- Render's warning reads the service's `openPorts` entries that are HTTP and in its reserved list, on a free plan (t001 records the exact condition).
- Open ports on every surface: ADR018 § Services & lifecycle: Open ports (`serviceDetails.openPorts`).

## Steps

1. Keep the reserved ports the scan saw (and whether they answered HTTP) apart from the service's routable ports, so nothing starts routing to them.
2. Serve them where t001 settled: on GraphQL (an HTTP mark on `openPorts` entries, as Render's dashboard reads them, or a separate field), keeping REST `openPorts` as Render's pinned contract has it.
3. If a reserved-port listener is all that keeps a deploy from going live, say so in the deploy's reason hint rather than the generic one.

## Files

- `lego/operator/internal/controller/private_ports.go` and the status it writes
- `lego/types/v1alpha1/` (status field or reason hint)
- `lego/backend/internal/apps/` (the GraphQL field), `lego/backend/internal/api/testdata/schema.graphql`

## Acceptance criteria

- [ ] Operator tests: a scan that finds 18012 keeps it out of the routable set and records it; a scan without one records nothing.
- [ ] Backend tests: the GraphQL answer carries the reserved listener, and REST `openPorts` is unchanged.
- [ ] `make test` (from `lego/operator/`), `cd lego/backend && go test ./...` and `make lint` pass.

## Out of scope

- Changing which ports are reserved, or the `PORT` validation (w21/076).

The port stays out of `listenerSet` and `openPorts`; the scan still reads as no open port. GraphQL `Deploy.reservedPort` reads it back (`appv1alpha1.ReservedPortListener`).
