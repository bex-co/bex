## Objective

`ShellTerminal` can reconnect by itself with Render's retry rule, and only the service Shell turns that on.

## Context

- `dashboard/src/common/components/shell-terminal.tsx` takes `mint` (a ticket per attempt) and a copy table.
- `attempt` already re-runs the connect effect (`:87-111`).
- `WebShellTerminal` (`dashboard/src/features/services/components/web-shell-terminal.tsx`) is the service caller. `session-terminal-sheet.tsx` is the agent session's caller, and must not change.

## Steps

1. Add an opt-in policy prop. With it on, a retryable end (t003 defines which those are) schedules the next attempt after min(1 s × 2ⁿ, 30 s), up to 5 attempts.
2. Typed input resets the count.
3. While `document.visibilityState` is `hidden`, wait, and retry on `visibilitychange` to visible.
4. Each attempt calls `mint` again, so it gets a new ticket. Keep the scrollback in the same xterm instance instead of disposing it, as Render's terminal does.
5. Turn it on in `WebShellTerminal`.

## Files

- `dashboard/src/common/components/shell-terminal.tsx`
- `dashboard/src/features/services/components/web-shell-terminal.tsx`

## Acceptance criteria

- [ ] With the policy on, a dropped socket retries on Render's schedule and stops after 5 tries. A hidden tab waits.
- [ ] The agent session's Terminal is unchanged.
