## Objective

The one-shot rebuild: tear down the old app cluster, let the corrected declarations build the new one end-to-end through CI, converge the platform from git, restore stateful data. Downtime accepted by explicit user decision (2026-07-10).

## Context

- Order inside this task: verify t001 backups readable FIRST; then `kubectl delete cluster bex` on the mgmt cluster (CAPH deprovisions machines + kube-api LB); delete the CCM-created `bex-traefik` LB via hcloud API; `terraform apply` (firewall); merge/push the t002-t005 PR -> app-cluster.yml runs: CAPH creates network `bex` + LBs + 3 CP + platform pool; addons (Cilium+WireGuard, CCM, CSI); deploy.yml bootstraps Argo -> platform converges from deploy/gitops/overlays/prod.
- Restore order matters: OpenBao — **no snapshot to restore** (t001 finding: prod was never initialized); instead run `scripts/bao-init.sh` fresh on the new cluster (the m10 prod-activation runbook, finally) + `scripts/bao-k8s-auth.sh`; **re-apply t001's `crs.yaml` FIRST** (Database/KeyValue CRs exist only in etcd - the operator then recreates CNPG clusters + Valkey instances); then `pg_restore` t001's dumps into the recreated clusters (postgres:18 client — servers run PG 18.4) and restore each `dump.rdb` into its Valkey PVC; etcd snapshot itself NOT restored (new cluster; Apps re-project from the store, datastores come from `crs.yaml`).
- The App CRs for tenant apps re-project from the control-plane store (bex-db) once bex-api + projector are up - verify tenant apps return; `crs.yaml` doubles as the App fallback if projection disagrees. Note: CNPG regenerates credential Secrets on recreate - tenant connection strings keep working because bex-api reads live Secrets, but restored roles/ownership need `--no-owner` dumps (t001).
