## Objective

Each row of the org Members table opens Render's member details dialog: the member, their workspaces, and, for a viewer allowed to see it, their login methods and 2FA.

## Context

- `dashboard/src/features/organizations/components/organization-members-card.tsx` is a table with a Remove button per row and no overflow menu; `use-organization-member-actions.ts` holds its actions. Render puts **View details** first in a row overflow menu, beside promote, demote and remove.
- Render's dialog (milestone README § What Render does): header with the avatar (`features/avatars`), the name or email, and "Owner" under it for an Org Owner; a **Workspaces** section; a **Login & Authentication Status** list, one row per method with a "Signed in" success badge or a "Not signed in" warning badge, then "Two-factor Authentication" with "Enabled" or "Not enabled"; a **Close** button. The status section is left out, not shown empty, when the viewer may not see it.
- `OrganizationMember.workspaces` already lists the member's workspaces.

## Steps

1. Give each member row an overflow menu whose first item is **View details**, and move the existing row actions into it if that is what Render's menu holds (Remove, and promote or demote where bex offers a role change).
2. Build the dialog. Query `orgUserAuthStatus` only when it opens and only for a viewer allowed to see it; show a loading state while it runs, and the Workspaces section either way.
3. Add any new strings to every locale file the dashboard keeps.
4. `yarn lint` and `yarn test` in `dashboard/`.

## Files

- `dashboard/src/features/organizations/components/organization-members-card.tsx`, a new `organization-member-details-dialog.tsx`, `organization-route-skeletons.tsx` if the row gains a column
- `dashboard/src/graphql/` operation and generated types, the locale files

## Acceptance criteria

- [ ] An Owner opens View details on any member and sees their workspaces, each method's badge and the 2FA row.
- [ ] A Member opening it sees no status section and sends no `orgUserAuthStatus` query.
- [ ] The dialog fits at 390 with no sideways scroll, the members table's pending frame still matches its ready state, and `yarn lint` and `yarn test` pass.

## Out of scope

- Changing a member's login methods; SAML SSO rows (`.pm/DO_NOT_DO.md`).
