## Objective

Write down what Render does for organization audit-log keys and a member's login status, and decide, with a cited basis, each detail the bundle and the docs leave open, so t002–t006 build one agreed behavior.

## Context

- The milestone README's § What Render does holds the bundle and docs reading of 2026-11-26. Render's bundle is at `https://dashboard.render.com` (public, no sign-in); find the code by `provisionOrganizationAuditLogToken`, `orgUserAuthStatus` and "Login & Authentication Status". Read it with `python3 -I` or grep, never execute it, and cite strings and operation names, never chunk hashes.
- `docs/render-artifacts/organizations.md` is bex's record of Render's organizations; `docs/render-artifacts/login-settings.md` and `audit-logs-api.md` are its neighbours.

## Steps

1. Add an § Audit log API keys and an § A member's login status to `docs/render-artifacts/organizations.md` with the strings, operations, permissions, the `scoped_access_tokens` flag and the docs quotes.
2. Settle and record, each with its basis (Render's behavior where visible, otherwise the nearest bex precedent):
   - **Which login methods a member's status lists, and their wire names.** Render's labels give `pwd` and `saml-sso-…`; the rest are capitalized provider names. Default: every method bex offers (password, Google, GitHub), `signedIn` true when the member's Kratos identity holds that credential (a password set, the oidc provider linked), each method named as Render's wire form. SAML is out (`.pm/DO_NOT_DO.md`). Say whether a method the org's Require Login Method rules out is still listed.
   - **Who holds `viewOrgUserAuthStatus`.** Default: Org Owners (`can_manage` on the org), as `manageOrganization` gates the keys.
   - **An org key's lifecycle:** what happens to it when its creator stops being an Owner or leaves the org (Render shows no creator on the key), when the org requires 2FA or Google login (the `twofactor.Gate` key rules stamp a creator), and when the org is dissolved (revoke). Whether `expiresAt` is ever set (Render's docs state no expiry), and the key quota and the error that answers "You have created too many keys".
   - **Audit rows.** Render's org event list (render.com/docs/audit-logs, `lego/backend/internal/audit/render_inventory_test.go`) has no event for org API keys; record whether bex writes none, as Render, or what it writes.
3. `npx prettier@3.4.2 --write` the file.
