# Decide OD1: port forwarding into agent sandboxes (`bex agent forward`)

Why: both reference products forward ports into the remote environment (Devin ships `devin forward <session> [local:]remote`; Render's CLI documents SSH `-L` pass-through), while bex's SSH gateway refuses all forwarding, so a dev server a Cloud Agent starts cannot be opened from the developer's browser.

- **Source:** [ADR106 § Open decision](../../../docs/ADR106-cli-cloud-agents-automations.md#open-decision) (OD1), D5; approved `/pm-brainstorm ADR106 for w1` item 5 via `/pmx`, 2026-11-11.
- **What blocks it:** a recorded ban, not code. ADR035, `.pm/DO_NOT_DO.md` (SSH carve-outs: "do not expand … into … forwarding"; the agent-sandbox carve-out of ADR054 admits SFTP and multiple channels only) and [ADR018](../../../docs/ADR018-render-parity.md) § "SSH into a running instance" ("TCP/Unix-socket forwarding remain excluded"). It reopens only on an explicit user decision.
- **Recommendation (Devin reference, not a user decision):** allow `direct-tcpip` for `ags-` targets only — destination the sandbox's loopback (`127.0.0.1`/`::1`), ports 1024–65535, at most 8 channels per connection, every open audited; `srv-` App-instance SSH keeps ADR035's full ban. A sandbox is already a workspace-owned, authorized, audited resource reachable over SSH and SFTP, so its own loopback adds no network reach the shell lacks.
- **Needs:** the user's sign-off on the recommendation (or a narrower variant). Nothing is implemented before it.
- **After sign-off (~3h milestone):** gateway `direct-tcpip` handler and audit for agent targets with tests (`lego/backend/internal/sshgateway/`), CLI `bex agent forward <session> [<local>:]<remote>… [--bind 127.0.0.1]` (ADR106 spec; `--bind 0.0.0.0` needs `--confirm`), docs, ADR035/ADR054/ADR018/DO_NOT_DO amendments, live check.
