# Render's Stripe integrations: the Stripe account connection and Stripe's agentic account link

Why: Render's dashboard connects a Stripe account to a workspace, and lets Stripe provision and manage Render resources for a user through an agentic account link; bex has neither and no disposition for them.

- **Found:** w1/m645's dashboard ledger (2026-11-26). Rows in [dashboard-operations.md](../../../docs/render-artifacts/dashboard-operations.md): `connectStripeAccountMutation`, `disconnectStripeAccountMutation`, `hasStripeConnection` (Billing and usage) and `confirmAgenticAccountLink`, `agenticTokenSignIn` (Account and sign-in).
- **Render (bundle, no flag):**
  - The Stripe connection: `hasStripeConnection(ownerID)`, `connectStripeAccount(ownerID, token)` and `disconnectStripeAccount(ownerID)`. A connect page says "Your Stripe account is connected!" and "Return to the Stripe dashboard to connect your database."; disconnecting toasts "Stripe disconnected successfully".
  - The agentic link: a page reached from Stripe with a one-time key in the URL fragment, "By proceeding, you agree to let Stripe access your Render account to provision and manage resources. You can revoke this access at any time from your Render account settings.", then `confirmAgenticAccountLink(key)`; expired keys get "This link has expired or has already been used. Please try again from Stripe." `agenticTokenSignIn(token)` signs a user in with a token of the same flow.
- **bex:** Stripe is only bex's own billing processor ([ADR040](../../../docs/ADR040-billing-metronome.md)); no partner integration exists.
- **Needs:** Render's docs for both flows (render.com/docs, Stripe's partner pages) read before deciding; then either a milestone per integration or the user's sign-off on a non-goal.
- **Done when:** each integration has a filed milestone or a signed-off non-goal (DO_NOT_DO line or ADR018 `—` row), and the five ledger rows point at it.

**Parked 2026-11-26: the Stripe account connection is retired, and the agentic link is Render's Stripe Projects integration, which bex can build only once Stripe accepts it as a provider. Applying is the user's decision.** The note's "no flag" holds. No flag hook guards `/stripe/connect`, `/stripe/new/database`, `/stripe-agentic-link`, `/login-token` or the Settings Stripe section.

The Stripe account connection is Render's **SQL Insights Stripe App**, and Render has retired it. Its three rows are now `n/a` in [dashboard-operations.md](../../../docs/render-artifacts/dashboard-operations.md#billing-and-usage).

- **What it was.** Render's docs page "SQL Insights Stripe App" (render.com/docs/stripe) said: "Render automatically syncs your Stripe data to a secure, encrypted PostgreSQL database". A Stripe user installed the app from the Stripe App Marketplace, clicked "Sign in to Render" and picked a database. The app then kept `stripe_`-prefixed tables up to date "approximately once per hour". Render launched it in public beta on 2022-07-11 (render.com/blog/sql-insights-stripe-app-live).
- **Retired.**
  - render.com/docs/stripe now answers 308 to render.com/docs. The Wayback Machine has it answering 200 through 2025-05-20 and 308 by 2026-01-28, and render.com/docs/llms.txt has no Stripe page.
  - marketplace.stripe.com/apps/sql-insights sends the browser to the Marketplace home page, as an unknown app does.
  - Render's Marketplace listing, marketplace.stripe.com/apps/render ("The intuitive cloud platform for deploying any app or agent"), is now its Stripe Projects app. Its only permission is "Provisioning Account Requests", so it cannot read Stripe data to sync it.
  - The dashboard's two docs links for the feature, "Read the docs." in the Settings Stripe section and "Learn more in docs" on a database's "Connected to Stripe" banner, now point at the docs index.
- **What the bundle still carries, for connections made before:**
  - `/stripe/connect` completes a connection only with a `token` from that app. It lists what "Stripe will be able to access" ("Your email address", "Your name", "Name and status of PostgreSQL databases in your account") and "modify" ("Data in the PostgreSQL database connected to Stripe"). Then it asks to "Pick a team to use with Stripe or use your personal account". Without a token it shows "We weren’t able to complete the connection process. Return to the Stripe dashboard to try again."
  - `/stripe/new/database` is the new database form, titled "Create new database for Stripe".
  - Settings shows the Stripe section ("Sync your Stripe data to a PostgreSQL database to query it alongside your other data.", with **Disconnect from Stripe**) only while a connection exists.
  - A database whose `stripeConnection` is not `NONE` (it is test mode or live mode) shows the "Connected to Stripe" banner, which opens the app in the Stripe dashboard.
- A feature no customer can start any more leaves bex nothing to match, so it needs no sign-off, as w1/148's flagged feature needed none. The ledger's `n/a` definition now names this case.

The agentic link is Render as a **Stripe Projects** provider. Its two rows stay `gap` on this note.

- **The product.** Stripe Projects ([docs.stripe.com/projects](https://docs.stripe.com/projects)) provisions third-party services from the Stripe CLI (`stripe projects link <provider>`, `stripe projects add <provider>/<service>`) and bills each provider through Stripe's Shared Payment Tokens. Its provider table lists "Render | Hosting, database".
  - Render's post "Stripe: An orchestration layer, not a platform" (2026-08-09) says the catalog "surfaces what Render offers on the network: Postgres, a web service, or a static site". It also says "Render remains the actual service provider and the billing relationship".
  - render.com/docs has no page on it (render.com/docs/stripe-projects is a 404, and llms.txt has nothing), and Render's changelog has no entry.
- **The bundle.**
  - `/stripe-agentic-link#key=…` links an existing Render account. It shows "Connect your Render account" and "Stripe wants to connect to your Render account. This will allow Stripe to create and manage services on your behalf." Then it shows the consent text the note quotes, a required "I agree to the Terms of Service" checkbox, and **Accept** and **Decline** buttons.
  - **Accept** calls `confirmAgenticAccountLink(key)` and shows "Account connected" ("Your Render account has been successfully linked to Stripe. You can close this page."). **Decline** shows "Connection declined". A URL without a key shows "Invalid link. The URL is missing a required key."
  - `/login-token#token=…` (base64url) calls `agenticTokenSignIn(token)`. It answers a user, an `idToken`, `expiresAt` and the user's workspaces. The page then signs the browser in and opens the page of the `resourceId` query parameter. If that fails, it goes to `/login`.
  - The API token type enum carries `STRIPE_AGENTIC` beside `CLI`, `REST` and `SCOPED`. Account Settings lists only CLI, REST and scoped keys, though, so this bundle shows nowhere to revoke a link, despite the consent text.
- **Why it is gated outside the code.**
  - Stripe takes providers by application. Its provider intake page ([docs.stripe.com/projects/provider-intake](https://docs.stripe.com/projects/provider-intake)) asks applicants to write to provider-request@stripe.com and says Stripe is "prioritizing SaaS and infrastructure providers that are widely used, developer-loved, and part of the core application stack".
  - Stripe has not published the provider protocol. The intake page looks for providers "who can work closely with us as we develop the product and integration spec", and Render's post says "The protocol itself wasn't published at the time of the talk." No public spec turned up on 2026-11-26.
  - Without the protocol, bex cannot write the provider endpoints, the account link or the token sign-in, and it cannot list itself either.

The gate: the user decides, through `/unblock w1`.

- **Build it:** apply to Stripe as a Stripe Projects provider. Once Stripe accepts bex and shares the protocol, file the milestone: the account link consent page, the token sign-in, provisioning Postgres, web services and static sites through the protocol, billing through Shared Payment Tokens, and a way to revoke a link.
- **Or decline it:** sign it off as a non-goal, with a `.pm/DO_NOT_DO.md` line and an ADR018 `—` row.

Either way, the `confirmAgenticAccountLink` and `agenticTokenSignIn` rows then point at the outcome.
