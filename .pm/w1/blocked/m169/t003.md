## Objective

Point the kpack `ClusterStack bex-jammy-base` at the reviewed `ghcr.io/bex-co/bex-cnb-run@sha256:…` index that `cnb-run-image.yml` published.

## Gate

t002 must be shipped, and its first `cnb-run-image.yml` run on `main` must have succeeded. That run publishes the digest and passes the Node 26 check. Before pinning, confirm that the new GHCR package is **public**: an anonymous `https://ghcr.io/token?scope=repository:bex-co/bex-cnb-run:pull` token must fetch the manifest. kpack pulls the run image with only the Zot credential.

## Steps

1. `deploy/gitops/charts/kpack/platform.yaml`: set `runImage.image` to `ghcr.io/bex-co/bex-cnb-run@sha256:<index digest>`.
2. `toolchain-freshness.json`:
   - Add `cnb-run-image` (kind `stack`, upstream `ghcr.io/bex-co/bex-cnb-run:latest`, files `[deploy/gitops/charts/kpack/platform.yaml]`, `resolved_at` = review time).
   - Drop `platform.yaml` from `cnb-stack-run`'s files, which leaves only `deploy/cnb-run/Dockerfile`.
3. `scripts/gitops-validate.sh`: the digest-pinned kpack-input loop requires `ghcr.io/bex-co/bex-cnb-run` instead of `paketobuildpacks/run-jammy-base`.
4. `deploy/gitops/charts/kpack/README.md`: one paragraph on the run image and why.
5. Run `bash scripts/build-toolchain-freshness.sh validate`, `bash scripts/gitops-validate.sh`, and the operator `make test`, which embeds the inventory.

## Acceptance criteria

- [ ] The rendered kpack chart names the bex run image by digest.
- [ ] Freshness validate passes with the new inventory entry.
