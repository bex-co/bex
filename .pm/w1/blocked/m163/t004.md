## Objective

Prove the DoD on a real cluster with a throwaway cron job on an every-minute schedule: push a failing build, suspend, and confirm no run is recorded after suspend on the fixed operator, while the pre-fix operator keeps firing. Include a healthy control cron that must keep running.

## Context

- `bash scripts/dev-env.sh 1 up` for `dev-1`; production only with explicit approval (see `w1/done/m158` README for the approved pattern and cleanup).
- Cron runs are visible via `GET /v1/services/{id}/jobs`-style run listing (`w2/m36`) and `kubectl get jobs -n <ns>`.

## Steps

1. Pre-fix: create the cron, break the build, suspend, watch two ticks; record the runs that still fire.
2. Post-fix: same sequence; record zero new runs and the control cron's runs.
3. Delete the throwaway resources; record timestamps in the milestone README.
