# Render's env var editor now links a service, database or Key Value: DO_NOT_DO's Link-database line rests on a premise Render no longer holds

Why: `.pm/DO_NOT_DO.md` forbids a "Link database to service" picker because "Render has no such dashboard feature" (verified 2026-07-08), but Render's dashboard bundle now has one, so under the parity-first rule the line needs the user's decision again.

- **Found:** w1/m645's dashboard ledger (2026-11-26), row `servicesForOwnerToLinkSearch` in [dashboard-operations.md](../../../docs/render-artifacts/dashboard-operations.md#environment-variables-secret-files-and-environment-groups).
- **Render (bundle, `VariablesActionButtons` chunk, no flag):** the env var editor queries every service, database (replicas included) and Key Value in the workspace with its region and environment, sorts them (same environment first), and offers each as a linked value: "Same region (internal URL)" or "Cross-region (external URL)", with `DATABASE_URL` and `REDIS_URL` as default keys. Not on Render's changelog as of 2026-11-26.
- **The rule it meets:** `.pm/DO_NOT_DO.md` "Do not build a 'Link database to service' picker in the dashboard … Render has no such dashboard feature" (withdrawn from `/pm-brainstorm for w5`, 2026-07-08). Its stated reason no longer holds; the first anti-goal says not to keep a parity gap because an older decision chose otherwise.
- **Needs the user:** lift the DO_NOT_DO line and build Render's picker, or keep the line with a new reason and record a signed-off divergence in ADR018 § Environment & config.
- **Done when:** the decision is recorded (a filed milestone, or the amended DO_NOT_DO line plus an ADR018 divergence), and the ledger row points at it.

**Parked 2026-11-26: no flag gates the picker, so every Render workspace has it, but Render documents nothing about it. Lifting the DO_NOT_DO line is the user's call, so a worker cannot build it.** Two details above need correcting. Render offers only datastores, not services: the query fetches services too, but the editor asks the picker for its `source` list, which keeps only databases (replicas included) and Key Value instances. And the order is by region first (same region, then cross-region), then by project, environment and name.

What the bundle shows (read 2026-11-26, from the public bundle saved that day):

- **Where:** while you edit a service's Environment Variables, the **Add variable** split button's dropdown holds three items: **Datastore URL**, **Generated secret** and **Import from .env**. Datastore URL shows only when the service has a region, the editor is Environment Variables (not Secret Files) and the service is not a static site. That covers web services, private services, background workers and cron jobs. Environment group editors pass no service, so they never show it.
- **The picker:** "Select a datastore" with a search box ("Datastore search", placeholder "Search"; it matches the name, the environment name and the project name). It shows "Searching datastores..." while loading. Results sit under "Same region (internal URL)" and "Cross-region (external URL)", and each row shows the datastore's icon, its name and its project / environment. With no results it says "No results for “…”" and "Your datastore might be:" Suspended, or In an isolated and/or protected environment, with links to Render's projects docs.
- **Who sees what:** a datastore in an environment is listed only when the user's `manageEnvironmentSecrets` permission there is allowed. From a service in an isolated environment, only datastores in that same environment are listed. Otherwise only datastores outside any environment or in unisolated ones are listed.
- **Choosing one:** the editor reads the datastore's connection (`databasePassword` for Postgres, `redisConnection` for Key Value). It adds a row keyed `DATABASE_URL` (Postgres) or `REDIS_URL` (Key Value), whose value is the internal URL when the datastore shares the service's region and the external URL otherwise. The row is a plain copy saved with the editor's usual Save. No link is kept, unlike the Blueprint `fromDatabase`, so a later credential change does not follow it.
- **Operations:** `servicesForOwnerToLinkSearch` (`servicesForOwner`, `databasesForOwner(includeReplicas: true, emptyEnvironmentOnly: false)`, `redisesForOwner`), then `databasePassword` or `redisConnection`.
- **No flag:** the editor's chunk imports neither flag chunk (`featureflags`, `frontendFlag`), and the service routes' `env` path has no flag loader. The service Environment page calls no flag hook, and nothing on that path mentions a flag or an experiment. The menu item's only conditions are the four above. So the ledger keeps `servicesForOwnerToLinkSearch` as `gap`, not `flagged`.
- **An External URL warning in the same editor, also ungated:** a variable whose value is a Render Postgres or Key Value external URL in the service's own region gets "This variable references an External URL. Those should only be used from services outside of Render.". Its **Use Internal URL** button opens "Review fix", a diff of the old and new values, and **Update** rewrites the value to the internal URL. The DO_NOT_DO line does not cover it, because it inserts nothing, and no GraphQL operation carries it, so the ledger cannot see it. bex has neither the picker nor the warning.

Render's docs and changelog say nothing about either feature (read 2026-11-26):

- [render.com/docs/configure-environment-variables](https://render.com/docs/configure-environment-variables) says "click _Add variable_" and "Select _Import from .env_ from the _Add variable_ dropdown". It mentions neither Datastore URL nor Generated secret, though bex already offers Generated secret.
- [render.com/docs/postgresql-creating-connecting](https://render.com/docs/postgresql-creating-connecting) and [render.com/docs/key-value](https://render.com/docs/key-value) say to copy the URLs from the datastore's Connect menu or Info page.
- The changelog has no entry.

So this is in Render's dashboard for every workspace, undocumented. w1/148's close does not apply here, because it rested on a flag and this has none.

- **bex:** `AddVariableMenu` in `dashboard/src/features/services/components/service-environment-editor.tsx` offers Generated secret and Import from .env, but not Datastore URL. A datastore's page already reveals and copies both URLs.
- **What a build would keep:** reading a connection URL is an audited secret view in bex (`w4/m321`), and in a protected environment it is Admin-only (`w4/m594`). A picker would read the URL through that same path.

The gate: the user decides, through `/unblock w1`. One option is to lift `.pm/DO_NOT_DO.md`'s "Link database to service" line and file a milestone for Render's **Datastore URL** item (and, if wanted, the External URL warning). The other is to keep the line with a new reason and sign the divergence off in ADR018 § Environment & config. Either way, the ledger row `servicesForOwnerToLinkSearch` then points at the outcome.
