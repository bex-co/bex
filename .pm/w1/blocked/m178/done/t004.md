## Objective

An env or secret-file edit on a Dockerfile service has the rebuild behavior t001 records, and the BuildKit registry cache never stores secret-file content.

## Context

- `NativeEnvRevision` (`build.go:358-364`) is the non-secret cache key native builds use; `desiredAppReleaseIdentity` counts `envFromSecret`/`envFromSecrets` for native and buildpack services (w1/121).
- Build args do change layer cache keys (Docker semantics); secret mounts do not and are never persisted.

## Steps

1. Extend the revision to Dockerfile builds per t001.
2. Confirm with `buildctl du`/cache inspection or a unit assertion that secret mounts are not exported.

## Files

- `lego/operator/internal/build/build.go`
- `lego/operator/internal/controller/app_controller.go`

## Acceptance criteria

- [x] An env edit produces the rebuild/redeploy behavior in t001; an unchanged reconcile does not rebuild.
- [x] No secret-file bytes in the exported cache manifest.

## Outcome

Done 2026-10-17 — **amended:** no identity input added. API env/group/file edits already bump `spec.restartedAt`, which is in every builder's artifact identity, and "Save and deploy" reruns the served image (`secrets/batch.go:108-112`) exactly as Render's does. Adding the Secret-name lists would have changed every existing Dockerfile App's release fingerprint and rebuilt the fleet on the operator upgrade. Recorded in `release_identity.go` and ADR004. Secret mounts are never exported to the cache (BuildKit semantics; confirmed by the layer inspection in t003).
