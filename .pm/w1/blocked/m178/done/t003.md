## Objective

`RUN --mount=type=secret,id=_env …` in a tenant Dockerfile finds the service's `.env` secret file, as on Render.

## Context

- The native path already projects the merged secret files into an App-owned Secret (`NativeFilesSecret`, `NativeFiles`, `nativeFileSecretID(i)`; w4/m163, code shipped, its live replay pending in `w4/blocked/m163`). Its ids are index-based; Render's Docker ids are sanitized filenames.
- `build.go:953-955` adds `--secret id=…,src=/native/files/<name>` for native builds only.

## Steps

1. Reuse the m163 projection for Dockerfile builds.
2. Add `--secret id=<render-id>,src=…` per file with Render's sanitization.
3. Two files that sanitize to the same id fail the build with a coded message naming both.

## Files

- `lego/operator/internal/build/build.go`
- `lego/operator/internal/controller/app_controller.go`

## Acceptance criteria

- [x] `RUN --mount=type=secret,id=_env cat /run/secrets/_env` sees the saved file; `id=credentials_json` works for `credentials.json`.
- [x] A colliding pair fails with the coded message; no file content in the Job spec.

## Out of scope

- Changing native builds' index-based ids.

## Outcome

Done 2026-10-17. Secret files are copied from the projection into a private EmptyDir and passed as `--secret id=<render-id>,src=…` (`.env` → `_env`, `credentials.json` → `credentials_json`); a collision fails `EnsureBuild` naming both files before any Job exists. The real BuildKit run read `/run/secrets/_env` (8 bytes) and left no secret path in any layer.
