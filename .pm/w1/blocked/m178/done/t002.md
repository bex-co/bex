## Objective

A Dockerfile build sees every effective service env var as a build arg (`ARG NAME` in the tenant's Dockerfile resolves), using the same sources and precedence the native and buildpack paths already read, without any value appearing in the build Job or Pod spec.

## Context

- `lego/operator/internal/build/build.go:947-960`: only `BuilderNative` gets `--secret id=render-env`; the Dockerfile branch adds just `--local dockerfile=` and `--opt filename=`. No `build-arg` flag exists anywhere under `lego/` (grep 2026-10-17).
- Env sources: `readBuildEnvSources` / `projectNativeBuildEnv` in `lego/operator/internal/controller/app_controller.go` (~:1532-1578) — groups < own Secret < literals, absent group optional, missing own Secret fails, protected operator Secrets refused (w1/121).
- Build pod volumes are wired per builder at `build.go:1024-1030`.

## Steps

1. Project the effective env into the build-scoped Secret for Dockerfile builds too (reuse the native projection, not a second reader).
2. Mount it into the BuildKit container and have the build step turn each `KEY=VALUE` into `--opt build-arg:KEY=VALUE` at exec time (a small wrapper), so values exist only inside the running build container.
3. Keep names that are not valid build-arg keys out, matching t001's contract.

## Files

- `lego/operator/internal/build/build.go`
- `lego/operator/internal/controller/app_controller.go`

## Acceptance criteria

- [x] A Dockerfile with `ARG GREETING` + `RUN test -n "$GREETING"` builds when `GREETING` is set through the env-vars API and its linked group, with precedence per t001.
- [x] `kubectl get job -o yaml` for the build shows no env value.
- [x] Native and buildpack build Jobs are byte-identical to before.

## Out of scope

- Secret files (t003); identity/cache (t004).

## Outcome

Done 2026-10-17. `internal/build/dockerinputs.go`: the merged env Secret (`<app>-native-env`, the same projection native builds use) is mounted read-only at `/bex/build-env`; the BuildKit container's input script appends each key, then each literal (indexed carriers, PORT dropped), as `--opt build-arg:K=V` (buildctl keeps the last per key, so literals win as at runtime). A literal-only Dockerfile build mints no Secret. Verified against `moby/buildkit:v0.30.0` running the generated container: the env value reached `ARG GREETING`, and no Secret-backed value is in the Job (envtest marshals the Job and checks).
