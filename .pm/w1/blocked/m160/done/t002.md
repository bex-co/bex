## Objective

A background worker's autoscaling transition must reach Ended once its Deployment has the scaled replicas ready, so `applyAutoscaling` resumes reading metrics.

## Context

- `autoscale.go`: `completeAutoscalingTransition` is the only Started → Ended path; `applyAutoscaling` returns the recorded `ToReplicas` while a transition is Started.
- Callers today: `reportKubernetesRunning` (web, private) and `convergeServingRuntime` (the held-release path from `w1/m156`–`w1/m158`).
- `reconcileWorkerStatus` never calls it, which is the freeze.

## Steps

1. Call the completion from the worker status path, on the same readiness condition the web path uses.
2. Check the held-release path still ends transitions for workers now that `w1/m158` routes them through `convergeServingRuntime`.
3. Make sure a worker with no autoscaling configured is untouched.

## Files

- `lego/operator/internal/controller/autoscale.go`
- `lego/operator/internal/controller/app_controller.go`

## Acceptance criteria

- [x] An autoscaled worker's transition reaches Ended after its replicas are ready, and a later metric change scales it again.
- [x] Web and private autoscaling behavior is unchanged.
- [x] `make test` passes.

## Out of scope

- Changing the autoscaling algorithm or its thresholds.
