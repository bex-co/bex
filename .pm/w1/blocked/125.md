# Land Dependabot's dashboard group update (PR #83)

Why: #83 (2026-10-06, 66 packages) has been red since it opened, and the dashboard has taken no routine dependency update since. w1/m174 tried to land it and found it is not a lockfile plus an icon: it carries 15 major upgrades, and even its minor and patch half changes behavior the dashboard tests guard. `.github/dependabot.yml` makes a breaking upgrade a person's decision.

**Gate (yours):** which parts to take, and whether the minor half goes first as its own reviewed change. Each group below is independent.

## What m174 found (2026-10-15)

- **Minor and patch updates (50 packages).** Typecheck, ESLint, unused-code and the critical audit pass with them (with `eslint-plugin-react-hooks` held at 7.0.1, see below). `yarn test` had 3 failures of 4891:
  - `network-metrics-card.test.tsx` "applies the free-text Path filter … and clears it": fails every run with the update and passes every run without it. After the × click the first `http_requests` call still carries `/api`: one extra render with the old props before the cleared state lands. The test reads the first call; the end state looks right, so this is probably test fragility, but unconfirmed.
  - `deploys-history-filters.test.tsx` "returns to the filtered history on Back from a deploy" (the w4/284 guard): fails often with the update, but also flaked on `main`'s own dependencies while this machine sat at load ~130. A two-run bisect pointed at `@apollo/client` 4.1.3 → 4.3.3 (what `^4.2.12` resolves to), but holding Apollo back did not clear it, so the attribution is not trustworthy. Re-run on an idle machine before deciding.
  - "opens a copied filtered link filtered": failed with the router family at 1.170.32 and once with it held, likely the same load flake.
- **`eslint-plugin-react-hooks` 7.0 → 7.1 (minor)** turns on 43 React Compiler findings: `set-state-in-effect` 22, `refs` 20, `preserve-manual-memoization` 1. Refactor them, don't suppress.
- **`react-intl` 7.1.13 → 10.1.14: cannot be taken alone.** `@ory/elements-react` pins `react-intl` 7.1.13 as a dependency, so 10.x installs a second copy. `src/common/lib/ory/ory-toast.tsx:64` stops typechecking, and Ory's components would read a different React context than the dashboard's `IntlProvider`. Waits on an `@ory/elements-react` release on react-intl 10.
