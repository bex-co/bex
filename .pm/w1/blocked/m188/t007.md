## Objective

为补丁镜像选择和发布失败路径补充有意义的行为覆盖。

## Context

- 测试应验证实际合同与失败方式，不只匹配 digest、生成文字或实现细节。

## Steps

1. 覆盖同版本选择、精确版本/fallback、补丁缺失或验证失败不切换 pin 等实际行为。
2. 运行受影响 Go/脚本测试和镜像验证，保留必要的补丁前失败、补丁后通过证据及普通健康对照。

## Files

- lego/operator/internal/build/*_test.go
- 平台补丁发布流程的实际行为测试

## Acceptance criteria

- [ ] 相关测试通过；补丁未生效、版本漂移和发布验证失败能被检测。
- [ ] 未修改的模块不靠无关测试数量充数；任何环境造成的验证缺口有明确记录。

## Out of scope

不以实现耦合的快照测试替代实际版本和修复验证。

## 已实现的验收入口

`lego/operator/internal/build/nativebackport_test.go` 使用既有 `BEX_BUILDKIT_INTEGRATION=1`，实际构建和启动已审核的四个旧 Node 镜像；系统和自带 decoder 在 build/start 都验证，语言版本必须保持，HTTP 等待及容器清理复用现有 helper。默认 suite 跳过 Docker 集成，不伪造执行结果。

统一公共底和同版本补丁运行时合格并接入后执行；公共底为空或未固定时会明确失败，不执行 Docker 构建：

```sh
GOWORK=off BEX_BUILDKIT_INTEGRATION=1 go -C lego/operator test ./internal/build -run '^TestNative(Backports|PythonBackport|RubyBackport)BuildAndStart$' -count=1 -timeout=30m -v
```

2026-10-29 的本地临时 overlay 只验证 Node14/20 组件组合，不是上述四版本签名镜像验收；剩余结果仍待实际执行。

Python / Ruby 入口分别为 `nativebackport_python_test.go` 和 `nativebackport_ruby_test.go`，验证真实构建产物、HTTP 启动和 build/start 两阶段 decoder。2026-10-29 本地 arm64 的 Python3.7.17（显式 Poetry1.5.1、无 uv.lock）与 Ruby3.0.7 临时 overlay 验收通过；见 [证据](evidence/local-python-ruby-native-start.json)。正式执行仍需直接使用已采用的签名 pin，不能把 overlay 结果算成正式发布验收。

2026-10-29 后续验收发现 Node20 的 Bookworm 编译破坏了 Bullseye companion 启动，已将 Python/Ruby fixture 改为显式选择 Node20 并独立断言双运行时版本。发布 gate 增加最旧 reviewed 系统的实际执行，并以旧失败候选和 Node14 健康候选做红绿对照；修正后组合与签名镜像仍待实际复验。

修正后的两份真实 native fixture 已对旧候选运行红对照：Python3.7/Ruby3.0 均在 authored build 阶段因 Node20 缺失 GLIBC/GLIBCXX 而失败，证明组合测试会捕捉此回归；见 [实际红对照](evidence/companion-native-red.json)。修复后的绿对照仍待完成。

可移植修复的本地绿对照已完成：两份更新后 Python/Ruby + Node20 真实 build/HTTP fixture 47.459s 通过；Node20 原 Bookworm 主镜像的完整工具与安全检查、真实主运行时 build/HTTP 6.680s 通过。分别见 [组合绿对照](evidence/companion-native-green.json) 和 [主镜像验收](evidence/portable-node20-final-native.json)。正式签名 pin 的直接执行仍待发布接入。

最终实际pin测试也可通过main上的 `.github/workflows/native-backport-acceptance.yml` 在现有bex-ci逐项执行六个fixture；三个入口会记录实际选择的主镜像及Node20 companion引用。新入口的静态Actions/仓库检查与未启用integration时的Go编译通过，见 [准备阶段校验](evidence/native-backport-acceptance-workflow-validation.json)；不以这次跳过检查代替最终真实构建/HTTP验收。
