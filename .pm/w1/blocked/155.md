# A deploy's step timeline: clone, cache, build, upload, pre-deploy, deploy

Why: Render's deploy page shows each step of a deploy with its own live duration, and bex shows one total Duration, so a slow cache restore or upload cannot be told from a slow build command without reading logs.

- **Found:** w1/m645's dashboard ledger (2026-11-26), rows `deployTraces`, `buildTraces` and `cronJobDeployTraces` in [dashboard-operations.md](../../../docs/render-artifacts/dashboard-operations.md#deploys-and-builds).
- **Render (bundle, `LiveDuration` chunk, no flag):** `deployTraces(deployId)`, `buildTraces(buildId)` and `cronJobDeployTraces(cronJobDeployId)` answer `{ group step startedAt endedAt type }`. The page groups steps under Building, Predeploy and Deploying, with labels such as Cloning repo, Checking out repo, Syncing submodules, Initializing build, Downloading cache, Decompressing cache, Installing dependencies, Running build command, Uploading build, Initializing predeploy and Deploying; a step with no end ticks live ("In progress").
- **bex:** the deploy header has one Duration fact (`dashboard/src/features/deploys/components/deploy-header.tsx`, `deployDurationValue`). The build already prints Render's step lines (`==> Downloading cache...`, `==> Running build command '…'...`, `==> Uploading build...`; [live-deploy-following.md](../../../docs/render-artifacts/live-deploy-following.md)), so the step boundaries exist.
- **Done when:** a deploy (and a Build Source build and a cron job's deploy) answers its step timeline on GraphQL, and the deploy page shows Render's groups and steps with live durations, verified on production. Likely more than an hour: promote to a milestone.
