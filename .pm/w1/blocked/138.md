# Keep single-instance services up through node rolls

Why: a node drain evicts a one-instance service's only pod before its replacement is scheduled, so a full pool turns routine maintenance into an outage; Render does not drop service during host maintenance.

Filed 2026-10-24.

- Incident: the w5/174 tenant-pool roll (2026-10-24 ~06:30 UTC) evicted `beancount-cms-v2`'s only pod; the replacement stayed `Pending` (no serving node had room for a standard instance since 2026-10-23 22:00 UTC), so beancount.io answered Traefik's `no available server`. `reverse-proxy-poc` too. Stopgap: `bex-tenant-0` autoscaler max 3 → 5.
- Options: pre-scale/surge (or reserve headroom) so replacements schedule before eviction; PodDisruptionBudget-aware drains with a temporary surge replica; a pre-roll capacity check in `scripts/wait-capi-rollout.sh` that refuses when serving nodes lack room for every evicted pod.
- Honesty gap: the deploys list kept showing the 2026-10-21 deploy as `live` while zero pods ran, and no `server_failed` event fired after the eviction — surface "no running instance".

**BLOCKED 2026-10-25 (decision: may a bex controller write CAPI Machines in `bex-capi`?)** — triaged by `/loopx w1`:

- A zero-disruption PDB on single-instance pods is ruled out: it kept nodes undrainable for 6 days in 2026-08 (ADR060 D8, `lego/operator/internal/controller/database_controller.go:464`). Reacting to a cordon cannot win either: CAPI cordons and evicts in the same reconcile.
- Workable design: a CAPI pre-drain hook (`pre-drain.delete.hook.machine.cluster.x-k8s.io/<name>` on tenant Machines). On Machine deletion the controller surges each single-instance serving Deployment on that node (template restart; 1 replica defaults to maxSurge 1 / maxUnavailable 0), waits for the replacement Ready (bounded, e.g. 10 min, so a stuck surge never pins a node), then removes the hook so the drain proceeds.
- Gate: that controller needs annotate/patch on `machines.cluster.x-k8s.io` in the locked-down `bex-capi` namespace — a security-boundary choice for the user. Alternative: run it as a separate, narrowly-scoped controller instead of the operator.
- Mitigated meanwhile: m183 (live images survive retention, so the reschedule can pull) and the tenant-0 max 3→5 (room to reschedule). Remaining exposure: seconds of downtime per roll for single-instance services.
- The status-honesty half moved to `w1/140`.
