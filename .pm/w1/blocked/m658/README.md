## What Render does

Read 2026-11-26 from Render's public dashboard bundle (the entry chunk, plus the `deploy`, `sandboxGroup` and `ResourceRedirector` chunks; Rollup renames chunk hashes every deploy, so find the code by the operation names and strings below) and from render.com/docs. Not walked signed in.

- **Routes and navigation.** A group lives at `/sandbox-group/<sbg-id>`. Its index and `sandboxes/*` show the Sandboxes list (a sandbox's drawer is a sub-path with a tab), and it has `settings`, `snapshots/*` and `builds/*` pages. Each route's loader sends the browser away unless the frontend flag `sandboxes` is on. The sidebar's **Custom images** entry (the `builds` page) shows only with the frontend flag `sandbox_builds`. The group's delete confirmation lists what goes with it: Sandboxes, Snapshots, Custom images (with `sandbox_builds`) and Brokered credentials.
- **Sandboxes list.** `sandboxesForGroup(input)` answers `cursor`, `hasMore`, `sandboxes`, `sortField` and `sortDirection`; the input carries statuses, a search, and `createdAfter` / `createdBefore` from the time range (All time and shorter ranges). Search reads "Search by name, sandbox ID, or status"; a status word becomes a status filter. A summary over the range shows **Total**, **Errored** ("Share of sandboxes in the time range that ended in an error.", `<0.1%` for a small share) and **Running** ("Creating, running, resuming, or suspending now, whatever the time range. These count against the concurrency limit."), over a chart of ended runs split Succeeded / Errored ("Couldn't load sandbox runs" on error). `SandboxGroupRunningCount` reads `sandboxGroup { runningSandboxCount }`. Rows update live (`sandboxesForGroupUpdated`, `sandboxUpdated`), with **Pause live updates** / **Resume live updates**. Columns can be shown or hidden. Selected sandboxes can be terminated together ("Failed to terminate N sandboxes. Please try again."). Empty states: "Create your first sandbox" with CLI and SDK starter code (Homebrew, direct download, Python 3.10+, Node.js 18+), "No matching sandboxes" ("Try another search, or widen the time range.", Clear filters), and "Couldn't load sandboxes" with Try again.
- **Sandbox fields** (`sandboxListFields`): `id name status createdAt startedAt endedAt errorReason networkPolicy allowedDomains timeoutSeconds timeoutAt idleTimeoutSeconds sourceSnapshotId sourceBuildId sourceBuild { id name } source { … on SandboxEmailSource { email } … on SandboxTemplateSource { templateId } } region { id description } image { name registryUrl } plan { name cpus memoryGb storageGb }`. Statuses Creating, Resuming, Running, Errored, Suspended, Suspending, Terminated.
- **Sandbox details drawer.** Tabs **Events**, **Snapshots**, **Logs** (only with the group permission `viewSandboxLogs`; Render's log explorer filtered to the sandbox) and **Shell** (only with `sandbox_shell`; not built here, see below). Details: Sandbox ID, Group, Plan, Cost, Duration, Timeout, Idle timeout, Network (Policy: Allow all, Deny all, Allow list; Allowed domains), Region, Snapshot or Image it started from ("Imported image" / "Base image", Go to snapshot, Go to image), Trigger (Dashboard, User, API key), Tags, Usage limits (Memory, Storage). The menu has **Terminate sandbox** (`terminateSandbox` answers `id status endedAt`). When the open sandbox stops: "Your selected sandbox stopped. Switched to a running one."
- **Events** (`sandboxEvents(sandboxId, before, beforeId, limit)` answers `hasMore` and events; `sandboxEventsSubscription` streams new ones). Every event has `id timestamp outcome label`. A lifecycle event adds `lifecycleType trigger` (Created, Resumed, …); an execution event `summary executionId executionType operation fullCommand exitCode startedAt completedAt` ("New command or file transfer"; Path, Full command, Exit code, Execution ID, View in logs); a snapshot event its snapshot `id kind status failureCode requestedAt capturedAt sizeBytes` (View snapshot). Strings: "Loading events", "Loading earlier events", "No events yet.", "Couldn't load events. Try again shortly.".
- **Snapshots page.** `SandboxSnapshots(input)` pages `snapshots` (`id sandboxGroupId name kind status sourceSandboxId plan { name cpus memoryGb } sizeBytes failureCode requestedAt capturedAt expiresAt`), with "Search snapshots" and the time range; `SandboxSnapshotsForGroupUpdated` keeps it live. Statuses Capturing, Available, Failed, with failure texts ("An internal error stopped the capture.", "This capture timed out.", "The source sandbox was terminated before the capture finished.", "The source sandbox errored before the capture finished.", then "Create a new snapshot to try again." / "New sandboxes can't start from it."). The drawer ("Snapshot details") has Details (Type, Resource constraint, Source sandbox, Size, Captured, Lifecycle, Expires or Never) and Sandboxes (started from it), starter code to restore it, and **Delete snapshot** ("This permanently deletes …", `DeleteSandboxSnapshot(sandboxGroupId, id)`; "Couldn't delete the snapshot. Try again."). Empty: "Create your first snapshot" ("You need a running sandbox to create a snapshot.").
- **Custom images page** (`sandbox_builds`). `SandboxBuildSources(input)` lists one row per image name: `name source { repository image reference } latestBuild latestSucceededBuild`; `SandboxBuilds(input)` lists one image's versions (`id sandboxGroupId name source sourceDigest status failureReason createdAt finishedAt`); `SandboxBuildsForGroupUpdated` keeps both live. "Search images"; statuses Queued, Importing, Available, Unavailable, with failure texts ("Render couldn't pull the image. Check the registry credentials.", "Render couldn't find the image. Check the image name and tag.", "The import took too long.", …). The drawer's tabs are Versions, Details (Latest available version, Source, Image, Digest, Version ID) and Sandboxes. Empty: "Import your first image" with CLI and SDK starter code ("Import an image (linux/amd64)"). The dashboard imports and deletes nothing: import is CLI and SDK only.
- **Links by id.** `resourceTypeBySandboxId` and `resourceTypeBySandboxSnapshotId` (the `ResourceRedirector` chunk) read a sandbox's or snapshot's `sandboxGroupId` so a bare id resolves to its group's page.
- **Docs and flags.** render.com/docs/sandboxes-creating (read 2026-11-26) names the dashboard for one thing: "You can also create groups from the + New > Sandbox Group menu in the Render Dashboard. In the Dashboard, you can optionally place a group in a project environment." Creating a group lands on its page, whose index is the Sandboxes list, so the `sandboxes` flag is a staged rollout of a documented public beta ("Render Sandboxes is in public beta."), as `artifact_reuse` was for Build Sources. Custom images are documented too (render.com/docs/sandboxes-creating § Providing a custom image) and were announced in Render's changelog on 2026-11-25 ("Use custom base images with Render Sandboxes"), so `sandbox_builds` is the same kind of rollout. Both pages are therefore built here (the w1/149 rule, not w1/148's).

### The shell (not built)

The drawer's **Shell** tab renders only when the frontend flag `sandbox_shell` is on. render.com/docs (the sandbox pages and the CLI reference: `render sandboxes copy, create, exec, list, snapshots, stop`) and the changelog have nothing on an interactive sandbox shell as of 2026-11-26, so it closes as w1/148 closed `oauth_proxy`: the ledger rows `CreateSandboxShellSession` and `sandboxGroupShellPermission` are `flagged` on `sandbox_shell`. Building it would also need the user: `.pm/DO_NOT_DO.md`'s one-off jobs and ephemeral shells line forbids expanding the service shell milestones into "hosted sandboxes". For a later build:

- `mutation CreateSandboxShellSession($sandboxId) { createSandboxShellSession(sandboxId) { url expiresAt } }` returns a URL the terminal connects to; `query sandboxGroupShellPermission($id) { sandboxGroup(id) { permissions { accessShell { permissionLevel message } } } }` gates it.
- Strings: "Start a new shell", "Reconnecting…", "The shell disconnected.", "The shell couldn't start.", "The shell couldn't start. Try again shortly.", "The shell exited.", "A shell isn't available for this sandbox. It may have ended.", "Shell access is limited" with "Protected environment" and "You don't have permission to open a shell." / "You don't have permission to open a shell in this sandbox.". The terminal is xterm.js (WebGL with `shell_webgl_renderer`).
- bex already has the mechanism: an agent session's web Shell reaches its sandbox through the ssh-gateway's `pods/exec` with a TTY ([ADR104 § Terminals in a sandbox](../../../../docs/ADR104-sandbox-render-parity.md#terminals-in-a-sandbox-w4m545-w4m574-w4m598)).

## Definition of done

1. A group's page opens on its Sandboxes list, with Render's navigation (Sandboxes, Snapshots, Custom images, Settings). The list pages, searches by name, id or status, filters by time range, shows Total, Errored and Running over the range, updates while live updates are on and holds still when paused, and terminates one or several selected sandboxes.
2. A sandbox's drawer shows its events newest first with earlier pages on demand, its snapshots, and Render's details (where it started from, who started it, plan, cost, duration, timeouts, network), and Terminate sandbox ends it. A Logs tab shows the sandbox's output, or t001 has filed the `sandbox` logs filter as its own item and the drawer leaves the tab out until it ships.
3. The Snapshots page lists the group's snapshots with Render's statuses and failure texts, its drawer shows a snapshot's details and the sandboxes started from it, and Delete snapshot removes it after confirmation.
4. The Custom images page lists the group's images by name with their latest and latest available versions, and its drawer lists an image's versions and the sandboxes started from it.
5. A link to a sandbox or a snapshot by id lands on its group's page with its drawer open; another workspace's id finds nothing.
6. Every new page and drawer has a pending frame that matches its ready state at 1440 and 390 px, and fits at 390 px with no sideways scroll, in all eight locales.
7. The ledger rows in `dashboard-operations.md`, `docs/render-artifacts/sandbox-groups.md`, ADR104 and ADR018's sandbox rows say what bex does.
8. Walked on dev-1 and, once a production pin carries the milestone, on production as the QA user in a disposable group.
