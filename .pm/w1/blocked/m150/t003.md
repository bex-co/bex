## Objective

PROXY protocol on :80/:443 changes the client address for every HTTP host, not just allowlisted services. Enumerate every consumer, and state its before/after address and whether the change is correct for it. Nothing that behaves correctly today may regress.

## Context

- **bex-api IP-keyed rate limiters:** `BEX_TRUSTED_PROXY_CIDRS=10.244.0.0/16` (`lego/operator/config/api/deployment.yaml:594`). `lego/backend/internal/core/clientip.go:90-117` takes the first untrusted `X-Forwarded-For` entry when the peer is a trusted proxy.
- **Other `X-Forwarded-For` readers:** request logs (`ClientHost`), the activator, static-server, the `bexWebsocketEgress` plugin, and tenant apps.
- **Cloudflare-fronted hosts** (`api.bex.co`, `dashboard.bex.co`, tenant custom domains behind Cloudflare): after t002 Traefik's peer is a Cloudflare edge address.

## Steps

1. **Probe before t002 lands.** Check whether bex-api's anonymous rate-limit key today is `10.10.0.7` for every client, e.g. by comparing limiter keys or metrics for two outside vantage points. If so, record it as its own `w1/NNN` finding with its own evidence; do not fold it into m150.
2. **Build the consumer table.** For each consumer, record the address it sees today and after t002, and whether that is correct. Paste the table into the m150 README.
3. **Decide Cloudflare-fronted hosts.** Either accept the Cloudflare edge address, or configure `forwardedHeaders.trustedIPs` for Cloudflare's published ranges on those entrypoints. Record the decision and reason; never set `insecure`.
4. **Protect what works.** Add regression tests where a consumer relies on today's behavior.
