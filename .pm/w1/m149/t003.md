## Objective

A pre-deploy log record says it is a pre-deploy log, so the dashboard's type filter and API clients can tell it apart from application output.

## Context

- Live evidence: m149 README § Evidence 4. `GET /v1/logs?resource=…&type=predeploy&text=qa-pd-marker` returned the marker line, but the record's `labels` had `type: app`. The same text query without `type` returned 0 lines.
- Log producers and labels: `lego/backend/internal/logs/` (`LabelType`, the predeploy history read) and ADR010.

## Steps

1. Confirm where the record's `type` label is set for predeploy history reads (Loki stream labels vs the response mapping). Fix it to `predeploy`.
2. Decide and record whether an untyped query should include predeploy lines (Render's log explorer behavior). Don't change it silently.

## Acceptance criteria

- [ ] The predeploy-typed query returns records labelled `type: predeploy` (live).
- [ ] A test pins the label, and the decision on untyped queries is recorded.
