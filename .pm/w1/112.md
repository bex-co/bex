## Context

- `lego/backend/internal/usage/service.go:377-396`: when neither a live name nor a retained record exists, a sandbox falls back to `tier + " sandbox"`. That is the only label these rows get.
- `lego/backend/internal/store/resource_names.go:137` `SandboxUsageMetadata` labels only from `agent_sessions` / `agent_session_dispatches` rows with `repo <> ''`. A repo-less session (the `w3/m79` real-model repo-less path) or a sandbox created outside a session never gets one. The same filter applies to migration `0121`'s backfill.
- `sandbox_meter_states` (`store/migrations/0061_sandbox_compute_meter.up.sql:14-23`) records `phase`, `tier` and weight, and **no image**. So the `plan · image` form that t001 step 2 and t002 step 3 asked for cannot be produced from what is stored today. The Decisions section records the SQL-join choice but not this dropped fallback.

## Steps

1. Record the image while the sandbox is alive. Either add `image` to `sandbox_meter_states`, written by the meter where `tier` is written, or write a `plan · image` label into `resource_display_names` at sandbox create. The second shape follows the existing retained-name design and keeps the label after the sandbox is reaped. Pick one and say why in the README's Decisions.
2. In `resolveServiceNames`, fall back to `plan · image` and only then to `<tier> sandbox`. Keep the session repo/branch label first.
3. For a repo-less session, prefer a session-derived label that identifies it (for example the session id or its title, if one exists) over `plan · image`, if that is more useful. Record the choice.
4. Pre-fix sandboxes stay as they are: the image is unrecoverable for already-reaped ones. Note that in the Backfill decision.
5. Tests: a session-less sandbox resolves to `plan · image`; a repo-less session's sandbox resolves to the chosen label; two sandboxes with the same tier and different images get different labels.

## Acceptance criteria

- [ ] On production, a fresh sandbox created without a repo and then terminated shows `plan · image` (or the recorded repo-less label) on `/billing` → Charges and in `usage { estimatedCost { resources { serviceName } } }`. REST and MCP carry the same `serviceName`.
- [ ] Sandbox rows are distinguishable. No two sandboxes with different images share a label.
