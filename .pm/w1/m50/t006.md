## Objective

Prove the DoD on production: the Outbound Bandwidth panel renders real series through the exact two events that used to blank it — an app deploy (router-counter reset) and an egress-meter roll (`up` gap) — and the billing pipeline is untouched.

## Context

- Reference service: `srv-d9bj8s3eg85c7390eb9g` (beancount-cms-v2) — steady traffic, the original report's page. A manual deploy of any repo-backed service provides the in-window router reset; the deploy itself also rolls the meter DS if t005 chose roll-acceptance.
- Month-to-date: `monthToDateBandwidth` was returning zeros + error; after the fix it must return non-zero MB for a service with traffic (compare order-of-magnitude against Prometheus directly: `sum(increase(traefik_router_responses_bytes_total{router=~"<its routers>"}[24h]))`).
- Billing check: the hourly usage rollup for a closed hour before vs after the deploy of this change must be identical (query `usage_hourly`/the usage surface for a past window twice).

## Steps

1. After the milestone's deploy reaches prod, load the reference service's metrics page at 12h and 7d windows — series present; capture screenshots to `.playwright-mcp/`.
2. Trigger a manual deploy of a repo-backed service; confirm the panel still renders across the event (degraded annotation acceptable, blank not).
3. Verify `monthToDateBandwidth` non-zero and sane vs the direct Prometheus sum.
4. Verify a past hour's usage numbers are unchanged by the release.
5. Append the evidence to the t001 ADR section / artifact.
