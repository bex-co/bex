## Objective

End the never-record failure mode (`w1/034`): `usage.queryEgressSources` records the sum of the sources that PASS their health product for the hour, skips (logs) the ones that fail, and defers the hour only on transport errors — because a past hour's samples never improve, so health-based deferral is equivalent to never recording.

## Context

- `lego/backend/internal/usage/service.go:747` today: any source with `health < 1` (or any error) ⇒ `(0, false)` ⇒ the storage window is deferred and retried — forever, on prod, since some term (deploy router-reset, meter roll) fails nearly every hour. July 2026 has ZERO `egress_bytes` rows (evidence in ADR023's w1/m50 section).
- New semantics: per source — transport error (health or increase query fails) ⇒ defer the whole hour (retryable condition); `health < 1` ⇒ skip that source's contribution this hour (undercount, never invent — the flap-reset `increase()` inflation on websecure counters is exactly what the health gate must keep excluding). All-sources-skipped still records a **successful zero** (ADR023's gap-free cursor: the hour is final).
- `TestQueryEgressBytesRejectsPartialSourceHealth` (usage/service_test.go:340) pins the OLD all-or-nothing behavior — rewrite it to pin the new one by name (partial health ⇒ healthy remainder recorded), and add: transport-error ⇒ defer; all-healthy ⇒ unchanged sum; all-unhealthy ⇒ successful zero.
- Update ADR023: the "Successful zeroes and gap-free per-resource meter cursors" § and the w1/m50 section's `w1/034` pointer get the new per-source rule; the strict *per-source* gate remains the never-invent guarantee.

## Steps

1. Rework `queryEgressSources`: per-source health → skip-vs-defer split as above; keep the concurrent fan-out; log skipped sources with resource + source + hour.
2. Rewrite/extend the usage tests per Context.
3. ADR023 prose update.
