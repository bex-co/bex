## Objective

Give the dashboard what Render's Sandboxes list and drawer read: a paged, filtered list of a group's sandboxes, the group's run summary and running count, and the sandbox fields bex's `Sandbox` type lacks.

## Context

- Render: `sandboxesForGroup(input)` (statuses, search by name or id, `createdAfter` / `createdBefore`; answers `cursor`, `hasMore`, `sortField`, `sortDirection`), `sandboxGroup { runningSandboxCount }`, and `sandboxListFields` (README § What Render does).
- bex: `sandboxes(sandboxGroupId, name, status)` and `type Sandbox` in `lego/backend/internal/api/testdata/schema.graphql`; resolvers in `lego/backend/internal/sandbox/graphql.go`; the service in `lego/backend/internal/sandbox/`.

## Steps

1. Add the list's filters and paging to GraphQL (a new field or new arguments, as t001 settles): statuses, a search matching name, id or status, a created-at range, a cursor and limit, newest first. Keep REST `list-sandboxes` as the pinned contract has it.
2. Add the run summary over the same range (total, errored, ended runs per bucket for the chart) and `runningSandboxCount` (creating, running, resuming, suspending, whatever the range) on `SandboxGroup`.
3. Add the drawer's fields to `Sandbox`: started and ended times, error reason, timeout deadline, the snapshot or image it started from (with the image's name), who or what started it, the plan's CPU, memory and storage, and cost if t001 settled it.
4. Authorize every new read as the existing sandbox reads are: another workspace's group or sandbox answers not found.
5. Regenerate the dashboard's GraphQL types (`dashboard/` codegen) and the schema snapshot.

## Files

- `lego/backend/internal/sandbox/graphql.go` and the service files it calls
- `lego/backend/internal/api/testdata/schema.graphql`
- `dashboard/src/graphql/` (generated)
