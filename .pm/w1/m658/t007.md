## Objective

Show a group's imported images as Render's Custom images page does: one row per image name with its latest and latest available versions, and a drawer with the image's versions, details and sandboxes.

## Context

- Render: README § What Render does (Custom images page): `SandboxBuildSources` groups builds by name with `latestBuild` and `latestSucceededBuild`; `SandboxBuilds` lists one name's versions.
- bex: GraphQL `sandboxImages(sandboxGroupId, name, status, …)` and `sandboxImage` ([sandbox-images.md](../../../docs/render-artifacts/sandbox-images.md), [ADR104 § Images](../../../docs/ADR104-sandbox-render-parity.md#images-w2m358)). bex has no grouped-by-name read yet.

## Steps

1. Add the grouped read to GraphQL (one entry per name with its source, latest and latest succeeded version), paged and searchable, with backend tests.
2. The page: rows with Render's statuses (Queued, Importing, Available, Unavailable) and failure texts mapped from bex's `failureCode`, search, the time range and live updates; the drawer with Versions, Details (Latest available version, Source, Image, Digest, Version ID) and Sandboxes started from it; "Import your first image" with Render's CLI and SDK starter code.
3. The group's delete confirmation lists Custom images, as Render's does.
4. Eight locales; a pending frame matching the ready state at 1440 and 390 px.

## Files

- `lego/backend/internal/sandbox/images.go`, `graphql.go`, the schema snapshot
- `dashboard/src/features/sandbox-groups/` (image components, hooks, locales), the images route

## Acceptance criteria

- [ ] Backend tests cover the grouping, latest and latest succeeded, and a cross-workspace read; component tests cover statuses, failure texts and the drawer's tabs.
- [ ] `cd lego/backend && go test ./...`, `make lint`, `yarn lint` and `yarn test` pass.

## Out of scope

- Importing or deleting an image from the dashboard: Render's page does neither.
