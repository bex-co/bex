## Objective

Write down what Render's sandbox group pages show, and decide, each with a cited basis, the details the bundle and the docs leave open, so t002–t008 build one agreed behavior.

## Context

- The milestone README's § What Render does holds the bundle and docs reading of 2026-11-26. Render's bundle is public at `https://dashboard.render.com`; find the code by `sandboxesForGroup`, `sandboxEvents`, `SandboxSnapshots`, `SandboxBuildSources` and the strings quoted there. Read it with `python3 -I` or grep, never execute it, and cite strings and operation names, never chunk hashes.
- `docs/render-artifacts/sandbox-groups.md` § The dashboard is bex's record of Render's group surfaces; `sandbox-images.md` is its neighbour. [ADR104](../../../../docs/ADR104-sandbox-render-parity.md) owns the sandbox contract.

## Steps

1. Extend `docs/render-artifacts/sandbox-groups.md` § The dashboard with Render's group pages: routes, navigation, the Sandboxes list, the drawer, events, Snapshots and Custom images, the flags (`sandboxes`, `sandbox_builds`, `sandbox_shell`) and the docs quotes. Correct its "Listing groups, deleting them, setting the default and images are CLI and API operations" where the bundle says otherwise.
2. Settle and record, each with its basis (Render's behavior where visible, otherwise the nearest bex precedent):
   - **Which sandboxes a group lists:** terminated ones within the time range included, as Render's summary counts ended runs; agent-session sandboxes, if any live in a user's group, in or out.
   - **Events:** which lifecycle transitions bex can report (created, started, suspended, resumed, errored, terminated) and their `trigger`, whether they are already stored (`sandbox_activity`, migration 0208, executions, snapshots) or need a store, and how far back they reach for an existing sandbox.
   - **Cost and Duration:** whether bex can price a sandbox's run from its CPU and memory meters (ADR023 § Sandbox CPU billed on use) or shows Duration only.
   - **Trigger / who started it:** Render's `source` is a user email or a template; what bex records at create (user, API key, agent session).
   - **Logs tab:** whether the drawer's Logs tab can show the sandbox's output from what bex keeps. If it cannot without serving Render's `sandbox` logs filter, file that as its own inbox note with `/pm add w1` (REST `list-logs` `sandbox` filter plus the tab) and record that the drawer leaves the tab out until it ships.
   - **Live updates:** the poll interval for the list, the drawer and the Snapshots and Custom images pages, and what Pause stops.
   - **Paths:** whether bex keeps `/sandbox-groups/<id>` and adds `sandboxes`, `snapshots`, `images` and `settings` sub-paths, or takes Render's `/sandbox-group/<id>` and `builds`; where the current Region, Concurrency limit and credentials cards go (Render's Settings page holds name, concurrency limit and delete).
3. `npx prettier@3.4.2 --write` the file.
