## Objective

Change `successfulReleaseGeneration` so a first release that never served reports 0 (or the value t001 recommends), and make the legacy path (no `activeRevision` because the App predates it) an explicit, commented branch keyed on that condition rather than on `status.image` being non-empty.

## Context

- `lego/operator/internal/controller/release_identity.go` `successfulReleaseGeneration` and `prepareAppReleaseDecision`.
- `w1/done/m160` moved the failure and cancel phases onto `releaseHasServed`; this is the same discriminator.

## Steps

1. Introduce the explicit legacy predicate (e.g. no `activeRevision` and a pre-`rev-` status shape) and keep its result identical to today.
2. Return 0 for the never-served, non-legacy case.
3. Update the store reconciler if t001 found it needs the new value handled.

## Files

- `lego/operator/internal/controller/release_identity.go`
- `lego/backend/internal/store/reconciler.go` (only if t001 requires)

## Acceptance criteria

- [ ] A crash-looping first release followed by a cancel leaves `status.releaseGeneration` at 0.
- [ ] A legacy App reports the same generation it did before the change.

## Out of scope

- Re-deriving release identity for anything but the canceled branch.
