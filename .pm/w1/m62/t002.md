## Objective

Give the platform a local, webhook-stamped record of "this workspace has a payment method on file" so enforcement never calls Stripe on a hot path: a `payment_method_bound_at` column on `billing_provider_mappings`, stamped by the existing `checkout.session.completed` handler at the moment it binds the default payment method, plus a store read used by the gate (t003) and the emitter (t006).

## Context

- `internal/billing/sessions.go` (`completeCheckoutSession`, ~195–267) already re-verifies the SetupIntent and idempotently binds Customer + Subscription `default_payment_method` — the stamp goes exactly there, after a successful bind.
- `billing_provider_mappings` (migration `0051_stripe_billing_lifecycle.up.sql`) keys `workspace_id` → `customer_id`/`subscription_id`; latest migration is `0056` (w1/m61), so this is `0057`.
- Readiness (`workspaceBillingReadiness`) keeps reading Stripe live — the marker is the *enforcement snapshot*, not a replacement for readiness.
- Idempotency: webhook replays must converge (stamp is monotonic — set once, later replays keep the earliest or overwrite harmlessly).

## Steps

1. Migration `0057`: `ALTER TABLE billing_provider_mappings ADD COLUMN payment_method_bound_at TIMESTAMPTZ` (+ down migration).
2. Store: `SetPaymentMethodBound(ctx, workspaceID, at)` and `PaymentMethodBound(ctx, workspaceID) (bool, error)` (one SELECT, also exposing `billing_excluded`/`billing_comped` if a joined read is cheaper for the gate).
3. Stamp in `completeCheckoutSession` after the successful default-payment-method bind; log-only on stamp failure is **not** acceptable — a failed stamp must surface as a webhook processing error so Stripe retries.
4. Real-Postgres store test (existing `BEX_TEST_DB_URI` harness): stamp, read back, replay-idempotent.
