## Objective

The bulk patch has been unguarded since the quota landed (2026-08-17), so production may already hold over-quota maps. Count them before t001 makes them un-editable in surprising ways (a later in-quota edit to an over-quota map will be refused).

## Steps

1. With operator access, measure every service's env and file map (key count and `mapBytes`) through the secrets store or the projected Secrets. **Read only.**
2. Record the counts (not values) in the m147 README Evidence section: how many are over 500 entries or 512 KiB, and whether any projected Secret is near or over 1 MiB.
3. Decide how t001's refusal treats an already-over-quota map. Options: refuse only writes that grow it; allow shrinking writes, which is the recommended shape and matches "deleting frees room" in ADR066 #6; or refuse everything. Implement the chosen rule in t001's tests if it differs from t001's default.

## Acceptance criteria

- [ ] The counts are recorded, or the sweep is recorded as not possible with the reason.
- [ ] The rule for existing over-quota maps is decided and covered by a test (a shrinking write to an over-quota map succeeds, if that rule is chosen).

## Out of scope

- Modifying any tenant's map.
