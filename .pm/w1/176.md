# Resources in a project but in no environment: give each an environment as Render does, or sign the Unassigned section off

Why: Render puts every project resource in an environment, so its project page has no place for a project-only one; bex keeps such resources, and since w1/m682 its project page lists them in an `Unassigned` section after the environments, which Render's page does not have and ADR018 does not sign off.

- **Found:** w1/m682 t010 (Render parity), 2026-11-26.
- **Render:** its project page maps `project.environments` to one section each and has no other list ([project-environments.md](../../docs/render-artifacts/project-environments.md)). render.com/docs/projects: a project's resources belong to its environments.
- **bex:**
  - A service, Postgres or Key Value can join a project without an environment (`internal/projects` membership, ADR032), and REST `DELETE /v1/environments/{id}/resources` ungroups instead (w4/714).
  - `dashboard/src/features/environments/components/environments-panel.tsx` (`UnassignedSection`) lists them so none becomes unreachable; an old `?env=unassigned` link lands there.
- **Decide (the user, `/unblock w1` if it parks):** move each project-only resource into an environment of its project (which one, and what joining a project without one does from then on), or record the divergence with sign-off in ADR018's Projects & environments row ([deployment-sources-iac.md](../../docs/ADR018/deployment-sources-iac.md)).
- **Done when:** either no resource is in a project without an environment on any surface (with a migration for production's existing ones) and the section is gone, or ADR018 records the section with the user's sign-off.
