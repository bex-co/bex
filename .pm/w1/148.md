# Render's per-service Authentication setting: require sign-in through the customer's identity provider

Why: Render's dashboard lets a paid web service require authentication for every request, through an OAuth app the customer registers with their identity provider, and bex has nothing like it; found by the w1/m645 dashboard ledger, with no changelog entry yet.

- **Found:** w1/m645's first full read of Render's public dashboard bundle (2026-11-26). Row: `UpdateServerAuthConfig` in [dashboard-operations.md](../../docs/render-artifacts/dashboard-operations.md#services).
- **Render (bundle, not gated by a flag):** service Settings has an **Authentication** section, "Enforce authentication for requests to this service.", disabled with "Authentication is only available for paid instances." on a free instance.
  - Fields: an enable switch, **Client ID** ("From your identity provider's app credentials."), a client secret shown as Configured / Not configured ("(leave blank to keep current value)"), and a list of routes "that bypass authentication", each a method (or `ALL`) and a path pattern.
  - `mutation UpdateServerAuthConfig($id, $authConfig: AuthConfigInput!)` answers `authConfig { enabled clientId clientSecretSet skipAuthRoutes { method pathPattern } }` and a `deploy { id }`: saving deploys the service. The form asks for confirmation before it saves.
  - Not in Render's public OpenAPI pin or on render.com/docs as of 2026-11-26: read the docs again before building, since the protocol (OIDC discovery, issuer field, cookie scope) is not visible in the bundle.
- **bex:** no service-level authentication at the edge. The nearest is the inbound IP allowlist (ADR018 § Custom domains).
- **Done when:** Render's docs for the feature are captured, and the work is filed as a milestone (edge auth in front of the service, REST/GraphQL/MCP, Settings UI, paid-plan gate), or the user signs off a divergence in ADR018 and the ledger row moves to that.
