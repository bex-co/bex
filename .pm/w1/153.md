# Check an image before creating the service, as Render's create form does

Why: Render's create form tells the user, before the service exists, that an image is private without a credential, built for the wrong platform, too large or malformed; bex only validates the reference's syntax, so the same mistakes surface later as a failed deploy.

- **Found:** w1/m645's dashboard ledger (2026-11-26), row `isDeployableImage` in [dashboard-operations.md](../../docs/render-artifacts/dashboard-operations.md#services).
- **Render (bundle, no flag):** `query isDeployableImage($externalImageReference: ExternalImageReferenceInput!) { isDeployableImage(...) { deployable failureCode failureReason } }`, run as the image URL is typed. Messages: "No public image found. It looks like you may be using a private image - please add a credential or check the image URL for mistakes.", "The provided image URL is invalid.", "The provided registry credential is invalid.", "The provided image URL points to an image with an invalid platform. Images must be built with the platform linux/amd64.", an image-too-large case, and "This is a public image that can be accessed without credentials."
- **bex:** OCI reference syntax is validated on create, source update, Blueprint validation and deploy overrides (w8/m49, ADR018 § Services & lifecycle); nothing reads the registry before create.
- **Done when:** the create form (and image source update) checks the image against its registry with the chosen credential and shows Render's outcome for each failure code above before the service is created, through a GraphQL read with tests; the platform rule follows bex's own node architecture.
