## Done 2026-10-26

`/simplify` ran three reviews (reuse, quality, efficiency). Applied:

- **Correctness.** The "Ready elsewhere" check counted any pod with `app.bex.co/app`. A pre-deploy or disk-backup Job pod on another node therefore released the hook while the App's only instance was still on the deleting node. `serving` now requires a ReplicaSet owner on both sides of the check.
- **Bound.** A workload API error went into controller-runtime's growing per-item backoff, which could push the release minutes past `MaxHold`. `hold` errors are now logged and retried every 5s (`recheck`), and the bound is checked before any workload call.
- **Cache.** Machines are unstructured, which the manager's client reads live by default. Setting `client.CacheOptions{Unstructured: true}` makes the reconcile read the watch cache.
- **Cleanups:**
  - `setHook(on bool)`, with one `guarded != hooked` branch;
  - Node and Deployment patches use `client.MergeFrom`, while the Machine patch stays raw (documented why);
  - `HookAnnotation` is built from `hookOwner`;
  - `run(options)` returns `ctrl.GetConfig()` errors instead of exiting;
  - a CEL comment explains why the lazy variables need no guards;
  - the mid-rollout comment notes that the bound ends that case.
- **Test helpers.** Reads now fail the test on error (the idempotency check could previously pass vacuously). `machine(node, withHook, deleting)` options replace the positional booleans.

Skipped:

- Reusing `execution.LabelApp`. It would add a dependency on the build-execution package for one string. The real fix is a single `LabelApp` in `lego/types`, which is a separate cleanup.
- Trimming the per-App calls. About 2N+2 calls per 5s pass is fine at this scale.
