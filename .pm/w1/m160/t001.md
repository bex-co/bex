## Objective

Make the failed-build and canceled-release paths use the same "has a release ever served" fact the pre-deploy and rollout paths already use, so a never-served first release stops being mistaken for a serving prior release.

## Context

- `app_controller.go`, in `fail`: `if app.Status.Image != "" { r.settleFailureOverPriorRelease(...) }` (around `:4294` at filing).
- `app_controller.go`, the canceled-release path: the same `status.image` check (around `:633`).
- The rule that already holds: `settleFailedRollout` and `failPreDeploy` key on `status.activeRevision`, which `markRunning` sets only once a release has served.

## Steps

1. Switch both checks to `status.activeRevision`.
2. Settle the never-served cases explicitly: a failed or canceled release with no served predecessor reports Failed, with the deploy row unchanged.
3. Keep the served-predecessor behavior exactly as `w6/m124` and `w6/m52` set it.

## Files

- `lego/operator/internal/controller/app_controller.go`

## Acceptance criteria

- [ ] A never-served first release plus a failed build reports Failed; the deploy still reads `build_failed`.
- [ ] A failed build over a served release still reports Running with the prior release serving.
- [ ] `make test` passes.

## Out of scope

- The pre-deploy paths, already converted by `w1/m149`.
