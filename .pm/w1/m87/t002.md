## Objective

`grep -rl BEX_DISK_SNAPSHOT deploy/` currently returns **nothing** — the variables exist only in `lego/**` and the two CLAUDE.md inventories. Set them so the code that already exists starts running.

## Context

- Operator needs `_ENDPOINT`, `_BUCKET`, `_PREFIX`, `_REGION`, `_S3_SECRET`, `_AGE_PUBLIC_KEY`, `_AGE_SECRET` (key `private`).
- bex-api needs `_ENDPOINT`, `_BUCKET`, `_PREFIX`, `_REGION`, `_ACCESS_KEY`, `_SECRET_KEY` — the read-only half.
- Both sets are documented in `lego/operator/CLAUDE.md` and `lego/backend/CLAUDE.md`; follow those names exactly rather than inventing new ones.

## Steps

1. Add the operator variables to its GitOps manifest, and the Secret refs for the S3 credential + age private key.
2. Add the read-only variables to bex-api.
3. Keep the age private key out of any ConfigMap; it belongs in a Secret the operator alone mounts.

## Files

- `deploy/gitops/base/**` (operator + bex-api)

## Acceptance criteria

- [ ] a disk-bearing App gets a backup CronJob created by the operator
- [ ] bex-api stops answering 503 on `GET /v1/disks/{diskId}/snapshots`
- [ ] no age private key appears in any ConfigMap or committed file
