## Objective

Create the object-storage bucket and the encryption keypair the ADR082 D5 snapshot pipeline needs. The keypair is **dedicated to disks** and deliberately not the ADR050 platform key: a restore has to decrypt inside the cluster, and ADR050's whole point is that the platform key never goes there.

## Context

- ADR082 D5 + `lego/operator/CLAUDE.md` § `BEX_DISK_SNAPSHOT_*` (the full variable inventory).
- The operator fails closed: endpoint + bucket + S3 secret + age public key must ALL be set or it creates no CronJob at all. That is intentional — a disk snapshot is a full copy of a tenant filesystem leaving the cluster.
- bex-api only LISTS snapshots. It never writes, never decrypts, and must never hold the age private key.

## Steps

1. `age-keygen` a fresh pair. Public half is safe in clear; private half goes to the secret store only.
2. Create the bucket (or prefix) and a **scoped** credential pair: write+delete for the operator, read-only for bex-api. Do not reuse the ADR050 backup credentials.
3. Record the bucket/prefix/region choices so t002 can reference them.

## Files

- no repo files; infrastructure + secret store only

## Acceptance criteria

- [ ] `age` keypair exists, private half stored out of band, public half recorded for t002
- [ ] bucket reachable with the operator credential (write) and the bex-api credential (read-only), verified with a manual put/get
- [ ] the bex-api credential is provably unable to write (attempt refused)

## Out of scope

- Wiring the variables into manifests (t002).
