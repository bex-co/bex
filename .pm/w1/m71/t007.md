## Objective

Assert that every folded field still works and that the fold did not quietly change semantics.

## Context

- Existing per-field MCP tests for the folded setters are the starting material — they should be rewritten against `update_*`, not deleted.
- Repo rule: tests assert real behaviour and failure modes; no tautological or snapshot-everything tests.
- Highest-risk regressions: an omitted argument clearing a field instead of leaving it unchanged; a build-triggering field no longer triggering a build; replace-semantics tools silently becoming merge.

## Steps

1. Per folded field: setting it through `update_*` reaches the same Service method with the same value.
2. Omitting an argument leaves the field unchanged — assert on a resource with all fields populated.
3. Setting several fields in one call applies all of them.
4. `dockerfilePath` (and any other build-triggering field) still triggers a build.
5. Surviving replace-shaped tools still replace rather than merge.
6. Adapter-parity: the field set reachable over MCP equals REST and GraphQL, in the shape the existing surface-parity tests already use.

## Files

- `lego/backend/internal/apps/*_test.go`
- `lego/backend/internal/{postgres,keyvalue,secrets,envgroups,environments}/*_test.go`

## Acceptance criteria

- [ ] Every folded field has a positive test through its new tool.
- [ ] The omitted-argument case is asserted on a fully-populated resource.
- [ ] Build-triggering and replace-semantics cases asserted.
- [ ] `cd lego/backend && go test ./...` green.

## Out of scope

- New coverage for unfolded tools.
