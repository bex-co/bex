## Objective

让 native 构建使用经过验证的平台补丁镜像，并让原上游来源与平台镜像的后续变化可被跟踪。

## Context

- 保留运行时版本信号、精确版本选择和 registry fallback 的既有语义。
- w1/136 的 19 个更新及 CNB 发布工作保持独立，避免重复实现。

## Steps

1. 按已有版本选择机制接入已发布镜像，保持用户选定的版本语义，更新 image pin 与审阅时间。
2. 同步 freshness inventory、相关校验和来源记录，明确原上游修复到来后的复核/回归条件。
3. 在 ADR060 的构建维护约定中记录本次用户决定、维护责任、发布验证和失败回退方式。

## Acceptance criteria

- [ ] inventory 与所有生效的 source pin 一致，来源和时间可追溯，平台/上游漂移均有明确检查入口。
- [ ] 租户构建直接使用固定镜像，不增加临时补丁下载步骤，也不改变用户应用配置。
- [ ] 补丁接入对所有 workspace 一致；不得留成未排定扩面的内部工作区特例。

## Out of scope

不改变版本支持列表、默认语言大版本或对外 API 字段。
