# With 10 or more variables, the Environment lists scroll in a 490 px box with Show more / Show less, as Render's do

Why: a service with dozens of variables pushes its Secret Files and environment groups far down the page, and Render's list keeps them in view by capping its height.

- **Found:** `/pm-brainstorm one aspect of render parity to w1` (2026-11-26), item 4, verified before filing.
- **Render:** from its public dashboard bundle (entry `index-D5V4ZgbE.js`, chunk `VariablesActionButtons`, list component `yr`). No flag gates it.
  - **The cap:** at 10 or more rows (`gr=10`), the compact state caps the table body at `max-h-[490px] overflow-y-auto`. The column labels stay above it.
  - **The button:** a secondary "Show more" (ExpandVertical) / "Show less" (CollapseVertical) button sits under the list when it is not being edited, and before the Add variable group while it is.
  - **Editing:** editing opens the full list, and the button stays. Leaving editing, by Save or by Cancel, returns to compact. At 10 or more rows it then scrolls the window to the form's top less 200 px (`behavior: "instant"`), and Show less scrolls the same way.
  - **Where:** the same component draws the Environment Variables and the Secret Files, on the service page and the env group page.
- **bex:**
  - `EnvironmentSection` (`dashboard/src/features/services/components/service-environment-editor.tsx:1317-1428`) renders every row. The only height cap is a revealed secret file's `max-h-48` (`:1506`).
  - The page shows the variables, then Secret Files, then environment groups (`dashboard/src/routes/services.$serviceId.env.tsx:33-44`), so 30 variables push the rest about 1,800 px down.
  - The service, environment group and build source tabs share `EnvironmentEditor`, so one change covers all three.

Its `divide-y` and `[&>[data-env-head]+*]` reach direct children only, so wrap the rows in a subgrid scroll box and move those rules onto it. Otherwise the labels scroll away and the dividers break.
