# The Shell's terminal fills the window, and Maximize fills all of it, as Render's do

Why: bex's Shell terminal is a fixed 24rem (384 px) box whatever the window's size, so on a tall screen most of a command's output scrolls away, and nothing gives it the whole window as Render's Maximize does.

- **Found:** `/pm-brainstorm one aspect of render parity to w1` (2026-11-26), item 5, verified before filing.
- **Render:** from its public dashboard bundle (entry `index-D5V4ZgbE.js`, chunks `ShellFrame` and `ServiceShellStarter`).
  - **Height:** the terminal runs from its top to the window's bottom, less the page's padding, and is never shorter than 300 px. It is recomputed on resize (debounced 100 ms) and refit.
  - **Maximize:** a Maximize/Minimize button sits at the top right, and is hidden when the shell failed to start. It puts the terminal `fixed` over the whole viewport with 16 px padding.
  - **URL:** it writes `?mode=maximize` with `replaceState`, and reads it on load, so a reload stays maximized.
  - **Focus:** it refits and focuses the terminal.
  - **Escape:** a document `keydown` listener minimizes on Escape. xterm.js stops the keys it handles, so an Escape typed into the focused terminal still reaches the program (vim).
- **bex:**
  - `dashboard/src/common/components/shell-terminal.tsx:79` uses a fixed 24rem unless `fill`, which only the agent session's sheet passes.
  - The service Shell (`dashboard/src/features/services/components/web-shell-panel.tsx`) has no maximize.
  - The deploy log's `MaximizeButton` (`dashboard/src/features/logs/components/log-explorer.tsx:99`, w9/003) and its copy key can be reused.
