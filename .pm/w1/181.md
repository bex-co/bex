# Render's API refuses deleting a project's last environment: probe it with an API key, and refuse it on bex's REST, GraphQL and MCP if so

Why: since w1/m683 the dashboard refuses deleting a project's only environment with Render's sentence, but bex-api still deletes it on REST, GraphQL and MCP, and Render's own dashboard maps a server refusal for exactly this case.

- **Found:** w1/m683 t006 and t009 (Render parity), 2026-11-27. m683 could not probe Render's API: the run had no Render API key.
- **Render:** the delete-environment form in its public dashboard bundle (entry chunk, read 2026-11-26) maps a server error matching `project contains only this environment` to "Cannot delete the last environment in a project. You can still delete the entire project.", so Render's backend refuses it at least on its dashboard API. Its public REST `DELETE /v1/environments/{id}` is unprobed.
- **bex:** `lego/backend/internal/environments/service.go` `Delete` (GraphQL `deleteEnvironment`, MCP) and `DeleteIfEmpty` (REST, 409 only for a non-empty environment) delete a project's only environment.
- **Work:** with a Render API key, create a project with one empty environment and call `DELETE /v1/environments/{id}`; record the status and body. If Render refuses, refuse it on all three surfaces with one coded error (and Render's status and message on REST), with tests; if Render deletes it, record that in ADR018 and keep the dashboard's refusal.
- **Done when:** ADR018's Projects & environments row ([deployment-sources-iac.md](../../docs/ADR018/deployment-sources-iac.md)) records Render's answer and bex's three surfaces match it.
