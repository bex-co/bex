# Dashboard serves an SSR error page on the first hit right after a roll

Observed twice on 2026-07-18 (immediately after the m50 and m51 deploys): the first navigation to `dashboard.bex.co/services/<srv>/metrics` after the dashboard pod rolls renders the "Something went wrong · bex Dashboard" SSR error page; a reload (or the client-side router taking over) recovers, though the stale error `<title>` can linger on the tab. Likely a brief window where the new pod serves before it can reach api.bex.co (SSR data fetch fails) or an old-asset/new-pod mismatch through the LB. Sub-hour: reproduce against a controlled roll, read the SSR error from the pod logs, and decide between a readiness gate on upstream reachability, an SSR retry, or letting the client boundary recover without the error page (and fix the stale title either way).
