## Objective

Before changing any default, record how many production services each new dated row will move on their next build.

## Context

- A no-signal service's default is resolved at build time from its App `CreationTimestamp`; nothing stores the resolved version per service. The latest build log's `==> Using <Name> version <v> (default)` line shows what a service last built on.
- The board is public: record counts per runtime and band only, never tenant names ([.pm/AGENTS.md](../../AGENTS.md#the-board-is-public)).

## Steps

1. For each runtime (Node, Ruby, Python, uv, Elixir/OTP) count native services whose latest build used a `(default)` version, grouped by the creation bands below.
2. Write the counts into this README under a dated `## Blast radius` heading.
