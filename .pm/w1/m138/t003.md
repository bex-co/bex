The Deploys list can never show a failure reason because its query stops at `preDeployStatus`, while the detail query one file over already selects `failureReason`. Select it and render it in the failed row so a user scanning the list sees why without clicking through.

## Context

- `dashboard/src/features/deploys/api/deploys.graphql:30-44` — list selection; `deploy.graphql:10-21` — detail selection with `failureReason`.
- `dashboard/src/features/deploys/components/deploys-list-page.tsx` — row rendering; `deploy-detail-page.tsx` — existing `failureReason` presentation to reuse.
- Tests: `dashboard/src/features/deploys/components/__tests__/deploys-list-page.test.tsx`.

## Steps

1. Add `failureReason` to the list query; regenerate types.
2. Render it on failed rows (`build_failed`, `pre_deploy_failed`, `update_failed`) with the same treatment as the detail page; keep the row height stable for non-failed rows so the list skeleton still matches.
3. Extend the list test: a failed deploy with a reason shows it; a live deploy shows nothing extra.
