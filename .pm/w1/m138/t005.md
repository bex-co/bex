## Objective

Check that the new event details are consistent across REST, GraphQL, and MCP in `lego/backend/` and the dashboard UI, and that Render's own `deploy_ended` contract is untouched. bex-api is meant to be Render-compatible (`docs/ADR006-bex-api.md`); the new fields are bex extras and must be labeled as such.

## Context

- Render's events API: `deploy_ended.details` = `{deployId, deployStatus}` where `deployStatus ∈ succeeded|failed|canceled`; no failure reason exists on Render's side.
- `docs/ADR018-render-parity.md` events row (L77) already records `preDeployStatus` as a bex extra — add the two new fields the same way.
- `docs/ADR004-app-deployment.md` if it enumerates deploy event fields.

## Steps

1. Diff the REST JSON, GraphQL type, and MCP tool output for one `deploy_ended` event: same field names, same emptiness semantics, same values.
2. Confirm `TestRenderConformance` and the events vocabulary tests still pin Render's `deployStatus` enum.
3. Update ADR018's events row and the REST struct comments to list the extras; flag any remaining drift as a follow-up inbox note rather than silently diverging.

- [ ] The three adapters agree field-for-field on the new details.
