## Objective

A live subscription to an App ends only on client disconnect, authorization loss, App deletion, or a real error. Never merely because every pod present at subscribe time has exited.

## Context

- `lego/backend/internal/logs/service.go:846-884`: a one-shot pod list, a fan-out of `streamPodLogs`, a `close(ch)` after `wg.Wait()`, then `return nil` on the closed channel.
- `lego/backend/internal/core/base.go:1644-1652`: `AppPodsIn` has no phase filter.
- Precedent: `followBuildLogs` (`service.go:917-`), which keeps watching and attaches to build phases as they start (w6/m123).
- `lego/backend/internal/logs/rest.go:353-417` (`subscribeStream`) and `:323-351` (`subscribeWebSocket`) are the two transports.
- Live evidence: m146 README § Evidence.

## Steps

1. Replace the one-shot fan-out with a loop. Keep a set of followed pod names, re-list `AppPodsIn` on a short interval, and start `streamPodLogs` for unseen pods, respecting `q.keepPod` and the instance filter (`translateInstanceFilter` must be re-applied to newly seen pods).
2. Stop treating "all current follows returned" as end of stream. The loop exits on `ctx.Done()` or an emit error only.
3. Add a heartbeat callback to the emit contract (or a separate ticker in each transport): an SSE comment line, a WebSocket ping, and a documented NDJSON keepalive that Render CLI tolerates (verify against the pinned `render-oss/cli` decoder before choosing a format).
4. Make sure a Succeeded pod is replayed once per subscription (as today) and not re-followed on every re-list.
