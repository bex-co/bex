## Objective

Check that the changed GitHub connect surfaces are consistent across REST, GraphQL and the dashboard, and that they match render.com's observable behaviour. Flag any drift as follow-up work.

## Context

- REST `POST /v1/git/claim`, `GET /v1/git/claim/selections/{id}`, `GET /v1/git/callback`; GraphQL `claimGit`, `gitClaimSelection`, `selectGitClaim` (`lego/backend/internal/github/`).
- MCP has no connect or claim verbs by design (ADR078 §5, browser ceremonies).
- On Render, one credentials control reaches every installed account without reinstalling, and each credential is disconnected on its own (ADR078 "What Render actually does", `docs/ADR018-render-parity.md`).

## Steps

1. Compare the chooser-mode option, the candidates' `connected` field and the `install_requested` code across REST and GraphQL: names, semantics and error shapes.
2. Confirm MCP is still absent, and why.
3. Compare the dashboard journey with render.com's credentials control, and update ADR018's Git connections row.
4. File any drift through `/pm` as follow-up work.

## Outcome (2026-11-19)

- **REST ↔ GraphQL agree.** The start option is `chooser` on both (`POST /v1/git/claim?chooser=true`, `claimGit(chooser: Boolean)`), with the same meaning: the callback always lands on the chooser. REST refuses a value that is not a boolean with a 400; GraphQL's type system refuses it. Each candidate's `connected` is on the REST JSON and on `GitClaimCandidate`. `TestClaimSelectionShapesMatchREST` pins the field sets of `ClaimCandidate` and `ClaimSelection` on both surfaces, and `TestGraphQLClaimGitChooserAndConnected` follows GraphQL end to end.
- **`install_requested`** is a callback redirect code. The callback is the browser's REST-only redirect target, so, like every other `git_error` code, it has no GraphQL or MCP counterpart.
- **MCP** still has no connect, claim or selection verbs (ADR078 §5: browser ceremonies). One drift fixed here: `list_repos`' description told agents to fetch "the install URL to give the human" from `list_git_connections`, which has returned no install URL since ADR078 §3. Both descriptions now send the human to "Connect GitHub account" in Account Settings → Integrations.
- **render.com.** One credentials control reaches every account the App is installed on, without reinstalling, as on Render. ADR018's Git connections row now records the single entry and says the observable outcome matches. No further drift, so no follow-up was filed.
