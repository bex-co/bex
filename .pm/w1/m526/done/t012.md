## Objective

In a workspace with no GitHub connection, the agent new-session composer offers the single "Connect GitHub account" action, in a new tab, together with its "GitHub settings" link to `/settings#integrations`. It does so as soon as the person opens the composer's repository list and finds it empty. Chat-only sessions stay free of the GitHub banner until then.

## Context

- t010 walk 1 (2026-11-20), the agent composer row: FAIL.
  - In `bex-canary` with nothing connected, "Add repository or session" → Repositories shows only "No repositories — connect GitHub in workspace settings first.", with no action. Workspace settings has no GitHub card.
  - The callout (`GitHubEmptyCallout`) renders only when `githubMissing && Boolean(repo)` (`dashboard/src/features/agent-sessions/components/new-session-composer.tsx`). A repo can be picked only from the connected installations' repo list, which is empty when nothing is connected. So the callout is unreachable live.
  - Composer tests passed because they mock repos together with `github.connected = false`.
- The repository list is the tiptap `@repos:` suggestion level. It is built in `dashboard/src/features/agent-sessions/components/inline-mention-editor.tsx` (`EditorRuntime`, the suggestion's `items`), and its empty copy lives in `agentSessions.mentionReposEmpty`, in 8 locales.
- Reference (Devin): the repository selector is where a person without connected repos is offered the connection. A chat-only start never needs it. This matches the tested decision "lets chat-only sessions start without a GitHub banner when there are no repos".

## Steps

1. Give `InlineMentionEditor` an `onReposEmpty` callback. It is called when the `@repos:` level opens with no repository rows once loading has finished.
2. In the composer, remember that the person reached for a repository, and show the callout when `githubMissing && (repo || reachedForRepo)`. Keep the flag sticky, so that the callout is still there when focus leaves the editor to click it.
3. Reword `agentSessions.mentionReposEmpty` in all 8 locales so it no longer names workspace settings.
4. Tests:
   - opening Repositories with no repos and no GitHub shows the callout, whose connect action runs in a new tab and whose link goes to `/settings#integrations`, while a chat-only start stays enabled;
   - the callout stays hidden when GitHub is connected.

## Outcome (2026-11-20)

The repository level of the composer's `@` picker reports an empty, loaded list through a new `onReposEmpty` callback on `InlineMentionEditor`. The composer then keeps a sticky `reachedForRepo` flag and shows `GitHubEmptyCallout` when `githubMissing && (repo || reachedForRepo)`. The callout's connect action opens in a new tab, and its "GitHub settings" link goes to `/settings#integrations`. A chat-only start stays enabled and shows no banner until the person reaches for a repository.

`agentSessions.mentionReposEmpty` now reads "No repositories yet. Connect a GitHub account, or give the bex GitHub App access to a repository.", in all 8 locales.

Two tests cover it: an empty repository list without GitHub shows the callout, and an empty list with GitHub connected does not. The first one failed with the fix reverted. `yarn lint` and the composer suite pass. The full `yarn test` run passed all 807 files. Its one unhandled rejection came from `sso-buttons.test.tsx`, which reaches the local `dashboard/.env` Kratos URL on `:8099`; it is unrelated to this change, and main's `test (dashboard)` is green.

The live re-walk is t010's job, once the production pin carries this commit.
