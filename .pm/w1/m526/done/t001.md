## Objective

Amend ADR078 so that the dashboard's connect action starts with GitHub OAuth, the one flow that keeps `state`, and lands on an account chooser. This replaces "Connect another account" and "Claim installed account" as two buttons the user must choose between. Record the parity reasoning in ADR018.

## Context

- `docs/ADR078-github-workspace-connections.md`:
  - §3 is the install flow; §3a is the claim flow, framed as a "recovery affordance"; §5 lists the surfaces.
  - No entry under Alternatives considers a single entry point.
  - The 2026-09-16 revision says already-installed accounts become the common case, but it left the entry point unchanged.
- How Render does it (ADR078, "What Render actually does"): one credentials control, with installed accounts reached through the user's own GitHub OAuth and no reinstall.
- `docs/ADR018-render-parity.md`, the "Git connections (GitHub / GitLab app)" row (about line 277), already records w8/m31's new-tab divergence.
- See the milestone README's Findings 1–3 and 6.

## Steps

1. Add a dated revision to ADR078's status line and to §3, §3a and §5:
   - The one entry, "Connect GitHub account", starts the OAuth claim.
   - Its callback always defers to the chooser. The chooser shows installed accounts the user administers (the connected ones marked) plus "Install on another GitHub account", which uses the stateful install URL from `connectGit`.
   - The three proofs are unchanged.
2. Decide and record two edge cases:
   - A chooser with zero installed accounts shows only the install option.
   - A single unconnected candidate still shows the chooser, because the user may want a new install instead.
3. Record that a redirect carrying `setup_action` is a GitHub setup-URL redirect and never a claim return (§3a step 2), with the `request` handling from t003.
4. Record that pages holding unsaved input open the whole flow in a new tab.
5. Record that "Configure in GitHub" keeps the generic link, and why: Render parity.
6. Update ADR018's Git connections row to cite the amendment and say the observable outcome matches Render.
