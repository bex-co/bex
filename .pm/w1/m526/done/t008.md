## Outcome (2026-11-19)

`/simplify` ran with reuse, quality and efficiency reviews.

**Applied:**

- The install-first and chooser-mode hooks share one `useGitHubFlow` (the new-tab pre-open, the workspace guard and the error toast), with the `newTab` default in one place.
- The composer uses `useRefetchOnFocus`, and the GraphQL resolver uses `gqlutil.Bool`.
- The account chooser takes the selection object and owns both of its flows.
- The source picker's connection watcher reads without a poll timer of its own, since the picker's `useGitConnection` already polls.
- The composer callout reuses the parent's refetches instead of opening new query instances.
- `useRepos` stays cache-first. The Settings card evicts the cached `repos` after a bind or a disconnect (`useForgetCachedRepos`), so a later picker reads the new set without a GitHub fan-out on every mount.
- Comments that repeated the chooser rule now point to `ClaimOptions.Chooser`.

**Skipped:**

- `useRefetchOnChange`: it fires on the first transition after mount, and changing that would alter its `settleKey` caller.
- `buttonVariants` for the connected row: a row that does nothing should not carry a button's hover style.
- A shared `core.QueryBool`: optional, and it would touch other packages.
- Dropping the chooser's local closed state: the router's search update is asynchronous, so dropping it would let the chooser flash.
