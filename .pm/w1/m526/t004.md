## Objective

On Account Settings, the account chooser:

- shows every installed account, with already-connected accounts marked "Connected" and not offered as a new bind;
- offers "Install on another GitHub account";
- after a choice binds, shows a success toast, disappears, and drops `git_claim_selection` from the URL.

## Context

- `dashboard/src/features/git/components/connect-github-card.tsx`: `ClaimAccountPicker` (:335–400). `onSelect` (:127) only refetches, so the chooser stays and a second click reports "expired" (Finding 3).
- `dashboard/src/features/git/hooks/use-claim-selection.ts`, and `dashboard/src/routes/settings.tsx`, which validates the `git_claim_selection` search param.
- `dashboard/src/features/git/components/connect-github-card-skeleton.tsx`: the loading skeleton must match the ready state (repo rule, `dashboard/AGENTS.md`).
- Git locales: 8 files in `dashboard/src/features/git/locales/`.

## Steps

1. Render `connected` candidates (from t002) as non-actionable rows marked Connected. An empty candidate list shows one explanatory line plus the install action.
2. "Install on another GitHub account" calls `useConnectGit()` to get the stateful install URL.
3. After a successful select:
   - navigate with `replace` to the same route without `git_claim_selection`;
   - show a toast naming the account;
   - refetch connections and repos.
4. Update the skeleton so it matches the new ready state at desktop and narrow-mobile widths.
