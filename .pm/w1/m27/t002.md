## Objective

Create the out-of-band `bex-db-backup-s3` Secret (same convention as `etcd-backup-s3`/`openbao-backup-s3` — never in git) and confirm t001's backup configuration actually produces a real backup in object storage, not just a config that looks right.

## Context

- Existing runbook convention: `docs/ADR011-etcd-backup-restore.md`'s "Secret is created out-of-band from `.env`" pattern.
- Credentials should come from the same Hetzner Object Storage account already used for etcd/OpenBao backups.

## Steps

1. Create the `bex-db-backup-s3` Secret in `bex-system` from `.env` credentials (never print or commit the values).
2. Trigger a backup (CNPG `ScheduledBackup` or a manual on-demand `Backup` resource) and confirm it completes.
3. Confirm the backup artifact is visible in the object-storage bucket/prefix.
