# An expired connect state after GitHub installed the App says the account waits in the chooser

Why: a GitHub sudo-mode 2FA that outlasts bex's 15-minute connect state installs the App on GitHub but binds nothing. The alert says only "try again", so a user may install again and meet GitHub's Configure dead end, when one pick in the chooser would finish the connection.

- **Found:** w1/m526 t010, walk 4 (2026-11-21, production pin `f797f525f5df`, workspace `bex-canary`).
  - The flow was "Install on another GitHub account" → `cuckoo-network` → Install & Authorize, which opened GitHub's **Confirm access**.
  - The user completed it at 03:39:15Z. The connect state had expired at 03:24:08Z (`connectStateTTL = 15 * time.Minute`, `lego/backend/internal/github/state.go:36`).
  - GitHub created installation `184232387` anyway. The callback refused the expired state (`lego/backend/internal/github/rest.go:128-134`, `callbackStateErrorCode`) and redirected to `/settings?git_error=expired_state`, with nothing bound. That is correct and stays.
- **What the user saw:** "GitHub connection wasn't completed. This connection request expired. Select Connect GitHub account to try again." (`git.callbackErrorExpired`, `dashboard/src/features/git/locales/en.ts:88`, mapped in `connect-github-card.tsx` `callbackErrorMessage`).
  - The button opened the chooser, which already listed `cuckoo-network`. Choosing it binds the account with no reinstall, so recovery works.
  - The copy does not say that GitHub may already have installed the App, or that the account now waits in the chooser. A user who picks "Install on another GitHub account" again reaches GitHub's Configure page for that org, and GitHub drops the state there (ADR078 §3a).
- **Reference:** on Render, finishing GitHub's install connects the account however long the install page stayed open. Check Render's behaviour after a slow install before choosing copy.
- **Change.**
  - When a callback with an expired state also carries an `installation_id`, redirect with its own bounded code (for example `expired_state_installed`).
  - The dashboard then says that GitHub installed the App, and that choosing the account under "Connect GitHub account" finishes connecting it. The copy goes into all eight locales.
  - The bare `expired_state` keeps today's copy.
  - An expired state still never binds, because it is the workspace's authorization proof. A longer TTL is a separate security trade-off, and this fix does not need one.
- **Done when:**
  - a `rest_test.go` callback with an expired state and an `installation_id` redirects with the new code and binds nothing;
  - one with an expired state and no `installation_id` still redirects with `expired_state`;
  - a dashboard test renders the new copy for the new code.
