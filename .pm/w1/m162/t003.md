## Objective

For the explicit `builder: buildpack` extension, a rootDir inside a workspace monorepo must not become `source.subPath` (which hides the workspace root). Detect a workspace root marker at the repo root (`package.json` with `workspaces`, `pnpm-workspace.yaml`, `go.work`) and, when present, keep the full clone and pass the buildpack's project-path variable instead: `BP_NODE_PROJECT_PATH=<rootDir>` for Node. Other languages and non-workspace repos keep `subPath`.

## Context

- `lego/operator/internal/build/kpack.go:98-116` — the kpack Image `source` block with `subPath`.
- Buildpack env is already forwarded from user env with the `BP_`/`BPE_` prefix filter (`app_controller.go:1508`).
- Paketo Node.js documents `BP_NODE_PROJECT_PATH` for monorepo subprojects.
- The operator's build request carries `Repo`, `Ref`, `RootDir` but does not inspect repo contents; the marker probe needs the clone (a cheap `git ls-tree` of the ref via the existing clone credential path) or a spec hint.

## Steps

1. Decide the detection point: probe the ref for root markers where the operator already resolves `ExpectedCommit` (`app_controller.go:872`), or read it from the build Job's clone stage and record it in status. Prefer the cheapest path that does not add a second clone.
2. When a marker exists and the runtime is Node, omit `subPath` and add `BP_NODE_PROJECT_PATH`; otherwise keep today's `subPath`.
3. Unit-test the kpack Image rendering for both branches.
