## Objective

For `Builder == BuilderNative`, stop narrowing the BuildKit `context=` to rootDir. Keep the full clone as the context and make the generated native Dockerfile `WORKDIR` into rootDir so `buildCommand`/`startCommand` run there while `../packages/shared` stays reachable. `dockerContext` semantics for Dockerfile builds, and the path-escape bound in `boundedSourceDir`, are unchanged.

## Context

- `lego/operator/internal/build/build.go:836-870` — `boundedSourceDir`, `contextDir`, the `--local context=` and `--local dockerfile=/native` args.
- The native Dockerfile generator in `lego/operator/internal/build/` (grep `/native` and `render-env`) — where `WORKDIR`, copy and command lines are emitted.
- `App.spec.rootDir` arrives via `Options.RootDir` (`build.go:314`).

## Steps

1. Thread `RootDir` into the native Dockerfile generation: `COPY` the whole context, then `WORKDIR /app/<rootDir>` (cleaned, bounded) before build and start commands.
2. For the native builder only, pass `context=` as the source mount root; leave Dockerfile builds on the existing `contextDir`/`DockerContext` logic.
3. Keep the escape check: a rootDir that cleans outside the checkout still fails before the Job is created.
4. Unit-test the generated Job args and Dockerfile for rootDir set/unset and for a Dockerfile build with `dockerContext` (unchanged).

## Files

- `lego/operator/internal/build/build.go`
- the native Dockerfile generator in `lego/operator/internal/build/`
- `lego/operator/internal/build/*_test.go`

## Acceptance criteria

- [ ] With `rootDir: apps/api`, the BuildKit context is the repo root and the Dockerfile's `WORKDIR` is `/app/apps/api`.
- [ ] A Dockerfile build with `dockerContext` produces byte-identical Job args to before.
- [ ] A rootDir escaping the checkout is still refused.
