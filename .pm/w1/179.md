# A digest-pinned image reference wraps the deploy page's Image fact to five lines at 390 px, past its frame

Why: a restart of an image-backed service (and any deploy whose `image` carries `@sha256:…`) prints the whole digest-pinned reference in the deploy header's Image fact, which wraps to 120 px at 390 px where the route's frame reserves one 36 px line, so the page grows by 57 px when it replaces its frame, which the skeleton rule (`dashboard/AGENTS.md` § Navigation pending states) forbids.

- **Seen:** production pin `6ba91ca5b72f`, the QA user in `bex-canary`, w1/m661's frame walk (2026-11-27) on `qa-20261127-m661-two` (disposable, Starter, `traefik/whoami`, 2 instances). Its restart deploy's Image fact read `traefik/whoami@sha256:<64 hex>` beside the short digest chip; the first deploy read `traefik/whoami` and the chip. Opened from the Deploys list with the `Deploy` read held, the facts grid went from the frame's 180 px to 284 px at 390 px (264 px in Japanese), and the log toolbar from 392 to 449 px, in all eight locales. At 1440 px the reference fits one line and nothing moved. The hovered open shows no frame, so it did not move either.
- **Source:** `dashboard/src/features/deploys/components/deploy-header.tsx`, `ImageReference` (prints the reference whole and breaks only after a slash) under the Image fact; `DeployHeaderSkeleton`'s full-width Image bar (`deploy-page-skeletons.tsx`, `FACTS`' `w-72` row).
