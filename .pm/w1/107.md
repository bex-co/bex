# 107 — The agent-session stream records Traefik's pod IP as the client address

Why: `ssh_sessions.remote_address` is an audit field — it should say who connected. For agent-session streams it records the reverse proxy instead, so that audit row cannot answer the only question it exists to answer.

- **Severity:** minor. It is one audit column on one endpoint; the web-shell sibling records it correctly.
- **Found:** `w1/m150` t003 blast radius, 2026-09-16. Traced from code, not probed.

## Where

- `lego/backend/internal/sshgateway/agentattach/agentattach.go:413` sets `RemoteAddress: r.RemoteAddr` directly.
- Its sibling in the same package, `webshell/websocket.go:208-212`, resolves the address through `core.TrustedProxies.ClientIP` (`lego/backend/internal/core/clientip.go:89-115`), which trusts the immediate peer only when it is in `BEX_TRUSTED_PROXY_CIDRS` and then reads `X-Forwarded-For`/`X-Real-IP`.
- The route is an HTTP `IngressRoute` (`lego/operator/config/ssh/ingressroute-agent-attach.yaml`), so `r.RemoteAddr` on the backend is always the Traefik pod address.

## Not related to `w1/m150`

m150 changes what Traefik believes the client is on `:80`/`:443`. This field bypasses that derivation entirely, so it is equally wrong before and after that milestone — it is listed in m150's blast radius only so the sweep is complete.

## Fix

Use the same `TrustedProxies.ClientIP` derivation the web-shell handler uses, and pin it with a test that sets `X-Forwarded-For` from a trusted peer and asserts the stored address — including the untrusted-peer case, where the header must be ignored.
