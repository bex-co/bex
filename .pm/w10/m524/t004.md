## Objective

The driver reads t001's variable (`BEX_AGENT_GITHUB_CLI=0`) and, when it is set, configures no `gh` for the turn. The overlay tells the agent that `gh` is turned off for the workspace, so it does not try it.

## Context

- `lego/agent-image/driver/src/github-cli.ts`: `githubCliEnabled` (used by `githubCliEnvironment` and `main.ts` to start the socket) reads only `deliver`, `repoUrl` and `repository`.
- `lego/agent-image/driver/src/config.ts` parses the dispatch env; `overlay.ts` `githubCliLine` has a repo-less variant ("the `gh` CLI is not authenticated") and the repo variant listing what `gh` can do.
- Tests: `lego/agent-image/driver/test/github-cli.test.ts` and the overlay tests.
- If w10/027 (the terminal's `gh`) has shipped by then, the terminal configuration it added obeys the same variable.

## Steps

1. Parse the variable into the driver config; `githubCliEnabled` returns false when it is `0`. Absent means on.
2. Give `githubCliLine` a third variant: there is no GitHub token in the sandbox, `gh` is turned off for this workspace's sessions, pull requests go through the `bex` tools, and code reaches GitHub through pushes to the session branch.
3. Tests for the config parse, the empty `gh` environment, no socket started, and the overlay text.

## Files

- `lego/agent-image/driver/src/config.ts`, `github-cli.ts`, `overlay.ts`, `main.ts` if needed
- `lego/agent-image/driver/test/github-cli.test.ts` and the overlay test

## Acceptance criteria

- [ ] A turn dispatched with the variable `0` has no `GH_*` variables, no `gh` config and no socket, and its overlay says `gh` is off for the workspace.
- [ ] The driver's test suite passes (`lego/agent-image/driver`, its `npm test`), and the image build check still passes.

## Out of scope

- Removing the `gh` binary from the image: without the socket and token it reaches nothing, and the gateway refuses the route anyway.
