## Objective

Store the setting t001 named on the workspace agent environment, default on, and let REST, GraphQL and MCP read it and let workspace admins write it.

## Context

- `lego/backend/internal/store/agent_environments.go`: the struct, the patch, `agentEnvironmentColumns`, `dest` and the upsert's column list. A workspace with no row has the defaults, so the read must report `true` there too.
- `lego/backend/internal/agentsessions/environment.go`: `Environment` (the read), `EnvironmentInput` (the write, with its `jsonschema` descriptions that MCP serves), and the input-to-patch conversion.
- `graphql.go` (the `AgentEnvironment` type and its update input), `mcp.go` (`get_agent_environment` and `update_agent_environment` descriptions), `rest.go` (`GET`/`PATCH /v1/agent-environment`). The scope matrix and key permission tables (`lego/backend/internal/api/scope_matrix_ops.go`, `key_permission_ops.go`) already cover these operations.
- The next free migration number is above `0312`; re-check `lego/backend/internal/store/migrations/` and `origin/main` before naming it.

## Steps

1. Add the migration (up and down) with the column `NOT NULL DEFAULT true`.
2. Add the field to the store struct, the patch (a nil pointer keeps the value) and the upsert.
3. Serve it on the service read and accept it on the input; describe it in the GraphQL field and input descriptions and the MCP tool descriptions, naming what off does and when it applies.
4. Store tests (default row, explicit off, patch keeps it), service and REST, GraphQL and MCP tests (read, admin write, non-admin refused as for the other fields).
5. Regenerate the dashboard's GraphQL schema types if the repo's codegen is how they stay in sync (`dashboard/src/graphql/`).
