## Objective

Verify DoD 5 on production once a deploy carries the milestone.

## Context

- Production runs the milestone once the newest `chore(deploy): pin platform images to <sha>` on `origin/main` contains its commits; park with that pin gate until then.
- The sandbox node is near capacity (w9/m349): at most two short sessions.
- Use the QA user's workspace and a QA repository (`bash scripts/qa-login.sh`; never the `bex` workspace, whose scheduled automations use `gh`, and never a customer's repository). Never revoke the shared QA account's OAuth grants or consent sessions.

## Steps

1. Turn the setting off with `bex agent env set` (or Settings → Agents) and read it back on REST, GraphQL and MCP.
2. Start one short repo session that runs `gh run list` and prints `env | grep ^GH_`: the call is refused with the message naming the setting, there are no `GH_*` variables, and the overlay says `gh` is off. Check the denied mint in the audit log.
3. Turn the setting back on in Settings → Agents, start a second short session that runs `gh run list`, and see it answer.
4. Record both session ids and the outcomes in the milestone README, leave the setting on, and delete the sessions.

## Acceptance criteria

- [ ] DoD 5 holds and is recorded with the session ids.

## Out of scope

- A running session's refusal from its next call (covered by t003's tests; the live check needs no long-lived session).
