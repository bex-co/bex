# 024 — The agent image lacks the runtimes Devin's base image preinstalls: JDK 17, Rust and Cargo, the AWS CLI, nvm and direnv

Why: a session on a Java, Rust or AWS-tooled repository cannot build or test it without a repository environment, and for Rust and nvm not even with one, while Devin's base image has these preinstalled. Found by the w10/m513 Devin comparison (t007). Severity: minor (Devin parity). Surface: `lego/agent-image/Dockerfile`, sessions on both templates.

## Reference

Devin: "JDK 17 is pre-installed on Devin's base image", "Rust (via rustup) and Cargo are pre-installed", "`awscli` is pre-installed", "Use nvm (pre-installed) to switch Node.js versions per repository via `.nvmrc`", and direnv is "pre-hooked into Devin's shell, so `.envrc` variables load automatically" ([Template library](https://docs.devin.ai/onboard-devin/environment/templates), read 2026-11-19).

## Current state (2026-11-19)

- The image has Node 22 (and Node 24 only for DeepSeek Harness), Python 3.11 and 3.12, Go 1.27, `uv`, `gitleaks` and `gh` (w10/m513). No JDK, Rust, AWS CLI, nvm or direnv.
- A setup step cannot `apt-get` (uid 10001). Since w10/m513 it can download GitHub release assets (a Temurin JDK tarball works), but `rustup` needs `static.rust-lang.org` / `sh.rustup.rs` and nvm needs `nodejs.org`, which no registries-tier session reaches.

## End state

- `java -version` (17), `cargo --version`, `aws --version`, `nvm --version` and `direnv version` succeed as uid 10001 in the built image, each pinned and checked by the Dockerfile's build check, and deploy.yml's Trivy CRITICAL gate still passes; or, for any left out, the egress catalog admits its installer host so a setup step can install it, with the choice recorded in ADR047.
