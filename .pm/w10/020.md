# 020 — `bex agent automations apply` refuses `overlapPolicy`, which `list` returns

Why: an automation's overlap policy cannot be kept in the definition files `apply` reads, so the declarative workflow drops a setting. Severity: minor. Surface: `bex agent automations apply` / `export`.

## Evidence (2026-11-15)

A definition with `"overlapPolicy": "skip"` (copied from `bex agent automations list -o json`) → `"overlapPolicy" is not part of a definition (only name, enabled, triggers, template, notifications; export prints that shape)`.

## Direction

Accept `overlapPolicy` in `apply` (and print it in `export`), or document that it is server-only and how to change it.
