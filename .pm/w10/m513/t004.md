## Objective

Implement t003's design in the gateway: a Pod-bound route that forwards the session's read-only GitHub API calls for its own repository to `api.github.com` with a narrowed installation token it mints and injects itself.

## Context

- `lego/backend/internal/sshgateway/agentcred/` authenticates the source Pod for the Git proxy and the `pull-request` verbs, and mints the narrowed token. Reuse that binding and the GitHub client (`lego/backend/internal/github/`).
- The ADR028 security-review lineage applies: the route must not echo the token, follow a redirect off `api.github.com` with it, or reach another repository through a path the parser misses (`/repos/{other}/…`, `/repositories/{id}/…`, GraphQL naming another repository, `..` segments, URL encoding).

## Steps

1. Add the route with t003's method and path allowlist, scoped to the session's repository by the Pod's labels, never by anything the request says.
2. Mint a token with only the read permissions t003 lists, inject it on the upstream hop, and strip it from any response or redirect.
3. Count calls per session against t003's limit, and answer an over-limit call or a refused write with the documented message.
4. Tests in `agentcred`: an allowed read reaches a fake GitHub with the injected token, another repository and every write are refused, the token never appears in a response, and a request from a Pod with the wrong labels is refused.

## Files
