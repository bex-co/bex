## Objective

Ship a pinned `gh` in the agent image, configured by the driver for repo sessions so that `gh run list`, `gh run view --log-failed`, `gh pr checks` and `gh api` GETs reach t004's route, and tell the agent what it can and cannot do with it.

## Context

- t001's build check and pinning pattern; t003's wiring choice.
- The overlay's environment line (`lego/agent-image/driver/src/overlay.ts`) currently says `gh` is not authenticated, and its tests lock the text.
- ADR090 D-overlay names the overlay's contract; the Claude settings disable Claude Code's built-in `gh pr create` instructions, which must stay off.

## Steps

1. Add `gh` (release tarball pinned by SHA-256 per `TARGETARCH`, or GitHub's `gh` apt repository with a pinned version and signing key) and extend t001's build check with `gh --version`.
2. In the driver, set up `gh` for repo sessions only (the placeholder token, the host or socket from t003, `GH_REPO` for the session's repository, `GH_PROMPT_DISABLED=1`, no update check). Sessions without a repository get no `gh` configuration.
3. Rewrite the overlay line: `gh` reads this repository's CI runs, checks and pull requests; pull requests are still opened and answered with the `bex` tools; writes through `gh` are refused.
4. Driver tests: the environment a repo session's agent gets, its absence for a repo-less session, and the overlay text.

## Files

- `lego/agent-image/Dockerfile`, `lego/agent-image/README.md`
- `lego/agent-image/driver/src/` (setup + overlay) and `lego/agent-image/driver/test/`

## Acceptance criteria

- [x] The driver's tests pass (`npm test` in `lego/agent-image/driver`).
- [x] In a locally built image against a fake route, `gh run list` and `gh api repos/{owner}/{repo}` return its answers, and `gh pr create` fails with the route's refusal.

## Out of scope

- `gh` writes.

## Result

Done 2026-11-19: `gh` 2.105.0 ships in the image (t001's stage and check). `lego/agent-image/driver/src/github-cli.ts` serves gh's `http_unix_socket` beside the status file and forwards `api.github.com` calls to `<repo URL>/github-api/…` without the placeholder `Authorization` (any other host is refused); `agentEnvironment` gives repo sessions `GH_CONFIG_DIR`, a placeholder `GH_TOKEN`, `GH_REPO`, `GH_PROMPT_DISABLED=1` and no update checks, and repo-less sessions nothing; `main.ts` starts it in setup and closes it on shutdown. The overlay's environment line now says gh reads the repository's CI runs and logs, checks, pull requests and contents, cannot write, and that pull requests stay with `open_or_update_draft_pr` and `reply_on_pull_request`. Tests: `test/github-cli.test.ts` (environment, socket forwarding, host refusal, overlay); `npm test` 272/269 pass, 3 skipped. In the built image, with the driver's socket and a fake route, `gh run list` and `gh api repos/{owner}/{repo}` returned the route's answers, no `Authorization` reached the route, and `gh pr create` failed with the route's refusal naming the bex tools.
