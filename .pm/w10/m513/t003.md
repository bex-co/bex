## Objective

Choose how `gh` in a repo session reads its repository's GitHub API (Actions runs and logs, check runs, statuses, pull requests and their reviews and comments, contents) while the sandbox still holds no GitHub token. Record it as an amendment to ADR090 (which ruled `gh` out) and ADR047 (credentials), with the reference to Devin.

## Context

- ADR090: "`gh` is not installed, so there is no second PR path to guard"; the overlay's environment section says "There is no GitHub token in the sandbox and the `gh` CLI is not authenticated" (`lego/agent-image/driver/src/overlay.ts`).
- ADR047 and `lego/agent-image/README.md`: the gateway verifies the source Pod against the session's labels, mints a repository-narrowed installation token internally, and injects it only on the upstream hop. The `pull-request` and `pull-request/comment` verbs (`lego/backend/internal/sshgateway/agentcred/`) already call GitHub this way.
- Devin: "Devin's machine can carry a GitHub CLI (`gh`) token that lets Devin use GitHub features directly through the GitHub API"; a security profile removes it ([Security profiles](https://docs.devin.ai/product-guides/security-profiles), read 2026-11-19).
- Constraints on wiring `gh`:
  - `gh` sends every API call with a token, and refuses to run without one (`GH_TOKEN`, `GH_ENTERPRISE_TOKEN` or a login).
  - For a host other than `github.com` it uses `https://<host>/api/v3/` and `/api/graphql`, while the gateway's in-cluster listeners are plain HTTP (`http://bex-ssh-gateway.bex-system.svc.cluster.local:8082`).
  - Candidate wirings: `gh`'s `http_unix_socket` setting pointed at a loopback forwarder the driver runs, a local HTTP forwarder under a `GH_HOST` that `gh` speaks HTTP to, or a TLS listener on the gateway. Each sends a session placeholder as the token, and the gateway swaps in the real one, as the model proxy does (ADR062).
- Scope of the route: GET (and GraphQL queries, if `gh run`/`gh pr checks` need them) for the session's own repository only. Any write is refused and names the `bex` MCP tools. Read permissions of the narrowed token: `actions`, `checks`, `statuses`, `pull_requests`, `contents`, `metadata`. The rate limit is shared with the installation, so the route counts calls per session.

## Steps

1. Verify which endpoints `gh run list`, `gh run view --log-failed`, `gh pr view`, `gh pr checks` and `gh api` call (REST vs GraphQL), with the pinned `gh` version.
2. Pick the wiring that keeps the token out of the sandbox, and write it as ADR090 and ADR047 amendments (dated, with the Devin citation, the refused-write message, and the per-session limit).
3. If no wiring can keep the token out of the sandbox, stop: putting a token in the sandbox reverses a security-review invariant. Park the milestone with that question for the user, after t001 and t002 ship.
