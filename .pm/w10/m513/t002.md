## Objective

GitHub serves release downloads by redirecting `github.com/<owner>/<repo>/releases/download/…` to `release-assets.githubusercontent.com`, a host not in any session's egress. Add it to the GitHub baseline so a repository environment's setup step (ADR109) can install a tool or runtime version the image lacks, as a Devin blueprint's `initialize` does.

## Context

- `githubDomains` (`lego/backend/internal/sessionegress/policy.go`) lists `api.github.com`, `codeload.github.com`, `github.com`, `objects.githubusercontent.com`, `raw.githubusercontent.com` and `uploads.github.com`. Every tier gets them (`domains := append([]string{}, githubDomains...)`), and `BaselineDestination` refuses a workspace allowlist entry that names one.
- The agents' report: "managed-Python downloads … and release-asset hosts are unreachable" (beancount-io #189, #208, #212). `uv python install`, the `gitleaks` and `gh` tarballs, and `actions/setup-python`-style installs all download release assets.
- The host serves only public release assets of GitHub repositories, the same class of content as `objects.githubusercontent.com`, which the baseline already admits.

## Steps

1. Add `release-assets.githubusercontent.com` to `githubDomains`, with a comment saying why.
2. Extend `policy_test.go`: the rendered policy of every tier names the host, and a workspace allowlist entry naming it is refused as a baseline destination.
3. Update ADR047's egress section, where it lists the baseline, and any doc that enumerates the GitHub hosts (`git grep objects.githubusercontent.com`).
