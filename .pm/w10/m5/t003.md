## Objective

The GraphQL `AuditLog` type exposes the stored human-readable target name (migration 0038's `target_name`), so the dashboard — GraphQL's only consumer — can render what a row acted on without decoding kind-prefixed ids. The existing code comment explicitly recorded this omission as "a scope cut, not an oversight… until a consumer exists"; t004 creates the consumer, this task creates the field.

## Context

- `lego/backend/internal/audit/graphql.go` — `auditLogGQLType` exposes `resource` (flat target) only; the scope-cut comment sits on `auditMetadataGQLType` just above.
- `target_name` column: `lego/backend/internal/store/migrations/0038_audit_target_name.up.sql` (`NOT NULL DEFAULT ''`); pre-0038 rows carry `''` — the field should return null/empty consistently so t004 can fall back to the id.
- `core.Base` recorders already populate `ev.TargetName` (e.g. `RecordKeyValueEffect` in `core/audit.go`); verify the audit list read path (`internal/store/audit.go` / `internal/audit`) actually selects the column into the `Event` struct — add it if the read side never loaded it.
- GraphQL is bex's own dialect (Render has no public GraphQL) — naming follows the existing camelCase fields.

## Steps

1. Confirm (or add) `TargetName` on the audit read path from store → `Event`.
2. Add the `targetName` field to `auditLogGQLType`; empty string resolves to null.
3. Update the scope-cut comment to point at this pickup; regenerate/update any GraphQL schema snapshot tests.
