## Objective

An admin changes the workspace's offered models from the CLI with the flag t001 chose. `bex agent env` prints which catalog models are on, and `bex agent models` lists only those, because it reads the capabilities read that t003 narrows.

## Context

- `lego/cli/internal/agent/config.go`: the `env` and `env set` commands, which already use `--default-model`, `--github-cli` and the enabled-agents flags. They build a JSON patch for `PATCH /v1/agent-environment`, and `env` renders a table. The `models` command is there too.
- `lego/cli/internal/agent/lifecycle_test.go` and the config tests hold the existing cases to extend.
- A field missing from an older bex-api must read as "every catalog model on", as `githubCliEnabled` reads a missing field as on.

## Steps

1. Add t001's flag to `env set`. It sends only `enabledModels`, and a bad value is a usage error.
2. Print the list in `bex agent env`, marking the catalog default. When the workspace default is turned off, say that the catalog default runs instead.
3. Check that `bex agent models` lists only offered models against a server that narrows them. Its help should say that admins choose the list.
4. Write tests for the patch body, the usage errors, the table with an older server's response, and the narrowed `models` output.
