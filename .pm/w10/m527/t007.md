## Objective

Check that the list is the same on every surface, compare it with Devin's agent and model allowlists, record the result, and file each remaining gap as its own item.

## Context

- Surfaces:
  - REST `GET`/`PATCH /v1/agent-environment`
  - GraphQL `agentEnvironment`/`updateAgentEnvironment`
  - MCP `get_agent_environment`/`update_agent_environment`
  - the capabilities read on all three
  - `bex agent env`, `bex agent env set` and `bex agent models`
  - Settings → Agents and the three dashboard pickers

  Each should have the same field, the same default, the same admin-only write and the same error shapes.
- Devin:
  - [Your First Session](https://docs.devin.ai/get-started/first-run): admins control which agents are available, and the picker lists only those. A switch applies from the next message.
  - [Devin Desktop admin controls](https://docs.devin.ai/desktop/controls): "Allowlisted models", which can filter by specific models or by provider, held by the Devin Desktop admin permission and hidden from pickers.
  - [Devin CLI Team Settings](https://docs.devin.ai/cli/enterprise/team-settings): a pinned default outside the allowlist falls back to the built-in default.

## Steps

1. Walk the surfaces against each other.
2. Re-read Devin's pages and compare who may change the list, what members see, what happens to the default and to a running session, and how a model added to the catalog later is treated. bex starts it on; Devin's "allowlist specific models" leaves it off.
3. Record the comparison in the milestone README and the ADR018 agent-model row.
4. File each gap users would miss as a `w10` inbox note through `/pm add`, with a testable end state. Candidates are group-level lists, a filter by provider, and new catalog models off by default.

## Acceptance criteria

- [ ] The comparison and the filed ids are recorded in the milestone README.
