## Objective

Every place that now takes the whole platform catalog as the choice takes the workspace's offered models instead. That set is the catalog minus the models the admins turned off, and the catalog default is always in it. The result:

- A turned-off model is refused at create, on a message and in an automation save.
- It is absent from the capabilities read.
- `defaultModel` cannot name it.
- A session or automation already on it runs the workspace default from its next turn.

## Context

- `lego/backend/internal/agentsessions/environment.go`:
  - `sessionModel` serves create through `resolveCreateModel` in `service.go` (also the automation save path), the message check through `steerModel`, and the turn dispatch in `service.go` (`sessionModel(config, workspaceEnv, explicit)`).
  - `agentModels` is the capabilities read. `environmentView` gives `models`/`pinnedModel`. `validateEnvironmentInput` checks `defaultModel`.
- `lego/backend/internal/agentsessions/automation_scheduler.go`: `retiredTemplateModel`. A fire whose template names a model no longer offered runs the workspace's model and records a note.
- `agentsession.PlatformModels` (`lego/backend/internal/agentsession/devroute.go`) stays the catalog. The narrowing is per workspace, so it belongs in `agentsessions` with the environment row, beside `agentEnabled`.
- The mint pins the session's recorded model (`route.pin`, `lego/backend/internal/agentsession/model.go`). The turn in flight keeps its model, and the next dispatch records the fallback as the turn's model.

## Steps

1. Add one helper that returns a workspace's offered models from its environment row, in catalog order with the default first, and whether the workspace is on the route.
2. Use it in `sessionModel`, `agentModels`, `environmentView` (the enabled subset t001 named, beside the whole catalog), `validateEnvironmentInput` and `retiredTemplateModel`. Replace the direct `PlatformModels` reads there; `byoKeyAfter` keeps its own catalog check.
3. Apply t001's rule for a workspace default that is turned off, so `sessionModel`'s fallback and the read agree on which model runs.
4. Write tests:
   - A create, a message, an automation create and an automation update each naming a turned-off model are refused with `AGENT_SESSION_MODEL_NOT_OFFERED`, listing only the offered models.
   - The capabilities `models` omits a turned-off model.
   - A session whose stored model is turned off dispatches its next turn on the workspace default and records it as the turn's model, as does a queued message naming such a model.
   - An automation fire on such a model runs the default with its note.
   - A turned-off workspace default yields the catalog default.
