## Objective

Decide the list's shape before any code and record it in the milestone README, ADR047, ADR090 § Model pin and the ADR018 agent-model row. Cover:

- its name on every surface and how it is stored;
- which reads carry the whole catalog and which carry only the offered models;
- the refusals;
- what happens to a workspace default, a session, a queued message and an automation on a turned-off model;
- when a change applies.

## Context

- The environment row: `lego/backend/internal/store/agent_environments.go` (`AgentEnvironment`, `AgentEnvironmentPatch`). The last migration that added a field to it is `0314_agent_environment_github_cli`.
- The enabled-agents list (w7/m392) is the shape to reuse:
  - The wire field `enabledAgents` replaces the whole list. It is stored as the opt-out `disabled_agents`, so a profile added later starts on.
  - `agentAvailabilityPatch` and `agentEnabled` live in `lego/backend/internal/agentsessions/environment.go`.
  - m524's design record explains why an opt-out column is needed: a workspace with no row is a zero-value `store.AgentEnvironment`.
- The catalog: `agentsession.PlatformModels` (`lego/backend/internal/agentsession/devroute.go`). It is empty on a workspace's own model key, where any model id is free-form.
- Its callers, all in `lego/backend/internal/agentsessions/` (the milestone README lists them with line numbers): `sessionModel`, `agentModels`, `environmentView`, `validateEnvironmentInput` and `retiredTemplateModel`.
- Devin: the README's reference-product paragraph. An allowlist hides models from pickers, a pinned default outside it falls back to the built-in default, and an agent switch takes effect with the next message.

## Steps

1. Pick the names. Keep the following proposal unless the code argues otherwise:
   - The wire field is `enabledModels`, on the REST and MCP read and input and on GraphQL `AgentEnvironment` and `AgentEnvironmentInput`. A write replaces the whole list, as `enabledAgents` does.
   - The column is the opt-out `agent_environments.disabled_models text[] NOT NULL DEFAULT '{}'`. A workspace with no row then offers the whole catalog, and a model added to the catalog later starts on.
   - The environment read keeps `models` as the whole catalog (its GraphQL description already says so), so Settings can list what can be turned on. `enabledModels` is the subset members may choose.
   - The capabilities read's claude `models` becomes the offered subset, since it is "the models a session of this agent may name".
   - CLI flags: `bex agent env set --models ID,ID…`, or `--enable-model`/`--disable-model`. Pick one.
   - Settings → Agents shows "Models members can choose".
2. Decide the refusals:
   - leaving the catalog default off, naming a model outside the catalog, or sending an empty list (a new code such as `AGENT_ENVIRONMENT_MODELS_INVALID`, field `enabledModels`);
   - a create, message or automation naming a turned-off model (`AGENT_SESSION_MODEL_NOT_OFFERED`, unchanged);
   - `defaultModel` naming one (`AGENT_ENVIRONMENT_MODEL_NOT_OFFERED`, unchanged).
3. Decide what turning off the current workspace default does. The proposal follows Devin: it is allowed, the default stops taking effect and the catalog default runs, and the read and Settings say so. The alternative is to refuse the write until the default changes. Record why you chose one.
4. Decide what the list means on a workspace with its own model key. There is no catalog there, so the list has no effect. Decide whether the read still returns it, and whether Settings hides it.
5. Write down when a change applies. New creates, messages and automation saves see it at once. A turn in flight keeps its model, because the mint pins the session's recorded model. The session's next dispatch re-resolves through `sessionModel` and falls back. An automation fire runs the default and records a note.
6. Amend ADR047 (the D7 model paragraph and its "Not built" line naming w10/028), ADR090 § Model pin ("Out of scope … w10/028") and the ADR018 agent-model row ("Not built: an admin allow-list …"), each dated with this milestone's id. Run prettier on them.
