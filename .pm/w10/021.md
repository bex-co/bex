# 021 — The bex CLI session expires within hours and long-running scripts fail with 401

Why: a script that waits on agent sessions (`bex agent wait`, automation runs) breaks mid-run with `401 unauthorized` and needs an interactive `bex login`. Severity: minor. Surface: `bex` CLI auth (token refresh).

## Evidence (2026-11-15..18)

At least three times in three days on one machine:

```
Error: your token is expired; run `bex login` to get a new one
```

Each was followed by `401 unauthorized` from `bex agent get` / `automations list` while a monitoring loop was running.

## Direction

Refresh the access token with the stored refresh token before it expires (or on a 401), and reserve `bex login` for a revoked or expired refresh token.
