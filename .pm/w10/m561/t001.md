## Objective

Settle the contract every other task builds on, choosing in each case what matches Devin's security profiles ([Security profiles](https://docs.devin.ai/product-guides/security-profiles)). Record it in the milestone README's design record and in ADR047 D2's `gh` amendment and ADR090 D4.

## Context

- The workspace switch is `githubCliEnabled`, stored as the opt-out `agent_environments.github_cli_disabled` (migration 0314, w10/m524). A zero-value row reads as on, and the new columns must keep that property.
- A session's `agent_config` and an automation's `template` are JSON. `AgentConfig` is in `lego/backend/internal/agentsessions/models.go:110` and `AutomationAgentConfig` in `automations.go:74`. The automation run copies the template into a session in `automation_scheduler.go:273` and `automations.go:666`. A spawn copies its parent's config in `spawn.go:108`. A session records `AutomationID` and its ADR102 lineage (`lego/backend/internal/store/agentsessions.go:280`).
- The named refusal crosses the internal hop as `X-Bex-Agent-Credential-Refusal: github-cli-off` (`lego/backend/internal/agentsession/contract.go:61`). An unknown value reads as a plain `ErrForbidden` (`agentsession/http.go:200`). The driver reads `BEX_AGENT_GITHUB_CLI` (`lego/agent-image/driver/src/config.ts:489`).
- Devin's model:
  - Each level inherits, pins a profile or opts out. The most specific binding wins unless a mandatory profile higher up is a floor that lower levels "can only tighten, never loosen".
  - Child sessions follow their parent's chain.
  - Selecting needs "Manage security profiles", held by org admins by default. "Members without the permission can't enumerate, select, or change profiles".
  - Changes reach "new sessions immediately, and for existing sessions the next time they resume".

## Steps

1. **Names.** Proposal:
   - `agentConfig.githubCli` (optional boolean) on a session create and an automation template.
   - `automationsGithubCliEnabled` (nullable boolean, null inherits the workspace) and `githubCliMandatory` (boolean, default false) on the agent environment.
   - CLI flags: `--github-cli on|off` on `bex agent run`, `chat` and `handoff` and on `bex agent automations create`/`update`. `bex agent env set` gains `--automations-github-cli on|off|inherit` and `--github-cli-mandatory on|off`.
   - Name the error codes for a refused loosening, e.g. `AGENT_SESSION_GITHUB_CLI_LOCKED` and the automation's equivalent.
2. **Precedence and the mandatory floor.**
   - The chain: session, then automation (for a session an automation started), then the automations default (likewise), then the workspace.
   - Mandatory means the workspace's off is a floor. It has no effect while the workspace is on, because lower levels can always turn `gh` off.
   - Decide whether mandatory also locks the automations default.
   - Decide what a child session inherits: its parent's session binding and its parent's automation link. A spawn cannot loosen it.
3. **Who may set which direction.**
   - Recommended: anyone who may create the session or save the automation may set `false`.
   - `true` against an inherited off needs a workspace admin (`can_manage`, bex's equivalent of "Manage security profiles"), and nobody may set it under a mandatory off.
   - The environment's two new fields are admin-only, like the others.
   - Devin gates every selection behind the permission. If this milestone lets members set `false`, record that it only removes access, and file the stricter variant as its own item.
   - Decide whether a member's save of an automation that already carries an admin's `true` keeps it, which is the recommendation: the check applies when the value changes.
4. **Where it resolves and when a change applies.**
   - Recommended: resolve live in one function on every mint and at every dispatch. It reads the environment row, the session's own `agentConfig.githubCli` and, for an automation's session, the automation's current template. Editing an automation or the environment then applies from a running session's next `gh` call.
   - Record whether an automation's session copies the template's value at fire time instead, and how the level stays nameable if it does.
   - A deleted automation reads as inherit.
5. **The refusal and the driver contract.**
   - Keep `github-cli-off` for the workspace level, so an older gateway is unchanged. Add the level, as a second header or as distinct values the gateway maps (an older gateway then answers a plain 403, never `gh` on).
   - Write the route's message for each level and say how that level turns `gh` back on.
   - Add the driver variable that names the level, e.g. `BEX_AGENT_GITHUB_CLI_LEVEL=session|automation|automations-default|workspace`. When it is absent, the driver shows the workspace text.
6. Amend [ADR047 D2](../../../docs/ADR047-cloud-coding-agent-sessions.md#a-workspace-can-turn-gh-off-amendment-w10m524-2026-11-19) (its "Scope" bullet points at w10/035) and [ADR090 D4](../../../docs/ADR090-agent-owned-delivery.md#d4--agent-facing-tool-the-bex-stdio-mcp-server). Write the design record in the milestone README. Run `npx prettier@3.4.2 --write` on the ADRs.
