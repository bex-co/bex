## Objective

Each binding is set where Devin sets it. A session's is set in the new-session composer's options, like Devin's "options menu in the session start box". An automation's is set in its form, like Devin's "automation's editor". The automations default and the mandatory flag are set in Settings → Agents, beside the existing GitHub CLI switch. Each control shows what is inherited and why it is disabled.

## Context

- Composer: `dashboard/src/features/agent-sessions/components/new-session-composer.tsx`. Its sandbox template option (w10/m519, `:171`) is the pattern to follow.
- Automation form: `dashboard/src/features/agent-automations/components/automation-form.tsx`, `automation-settings-card.tsx` and `lib/form.ts` (the template field at `:50`). Its skeleton is `automation-form-skeleton.tsx`.
- Settings → Agents: `dashboard/src/features/agent-environment/components/github-cli-section.tsx`, `agent-environment-card.tsx` and `agent-environment-card-skeleton.tsx`. The GraphQL operations are in `dashboard/src/features/agent-environment/api/agent-environment.graphql` and the agent-sessions and agent-automations `.graphql` files.
- Rules (`dashboard/AGENTS.md`): a skeleton matches its ready state at every breakpoint, and the strings go through the i18n catalogs (en and zh).
