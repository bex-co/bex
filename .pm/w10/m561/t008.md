## Objective

Hold the Definition of done's item 6 on production once a deploy carries the milestone, with as few and as short sessions as the checks need.

## Context

- Workspace: the QA account's `tian-personal`, whose GitHub connection is the `puncsky` installation. `bex-canary` has no GitHub connection. Sign the dashboard in with `bash scripts/qa-login.sh`, and log out after.
- Production read-only access: `scripts/fetch-app-kubeconfig.sh` to a path outside the repository, or the `hetzner-prod` context. The production sandbox node is near capacity (w9/m349's gate), so use at most three short sessions on the cheapest model, run one at a time.
- Check production's pin carries the milestone's commits: the newest `chore(deploy): pin platform images to <sha>` on `origin/main`, then `git merge-base --is-ancestor <commit> <sha>`. If it does not, park the milestone with ``pin must carry `<sha>` ``.
- w10/m524's t007 is the shape to follow (`.pm/w10/done/m524/README.md`, "Live check").

## Steps

1. Create a private fixture repository with one workflow, push once and wait for its run.
2. **Session level.** With the workspace's `gh` on, run `bex agent run --github-cli off --repo <fixture> --max-spend 1 …` and have the turn run `env | grep '^GH_'`, `gh auth status` and `gh run list`. Expect no `GH_*`, `gh` not configured, and an overlay naming the session. The session's reads show `githubCli: false` on REST, GraphQL and MCP.
3. **Automation level.** Create an automation with `--github-cli off` (a far-future schedule) and `bex agent automations run <it> --wait`. Its session has no `gh` and its overlay names the automation. Delete the automation.
4. **Mandatory floor.** Turn the workspace's `gh` off and mandatory (`bex agent env set`). A REST create naming `agentConfig.githubCli: true` and the composer's "on" are both refused with the named code. The composer shows the control disabled with the reason. Restore the workspace's `gh` on and not mandatory straight away, and leave the automations default on inherit.
5. If a session's binding can change while a turn runs (t001), or an automation is edited mid-turn, check the route's 403 names that level. Otherwise the route's per-level messages rest on t004's tests.
6. Clean up: delete the sessions, the automation and the fixture repository, and read back `bex agent env`.
