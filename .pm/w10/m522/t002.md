## Objective

bex-api mints, for one admitted `gh` write, an installation token narrowed to the session's repository with the write permissions t001 chose and no `contents` write, under the same checks as the read mint, and audits each one.

## Context

- Read mint: `Minter.MintGitHubRead` (`lego/backend/internal/agentsession/mint.go:126`), its verb `InternalGitHubReadMintPath` (`:49`) served by `agentsession/http.go:258`, and `github.Client.MintRepositoryAPIReadToken` (`lego/backend/internal/github/client.go:268`) with its 422 fallback.
- The gateway's client is wired in `lego/backend/cmd/ssh-gateway/main.go:326` (`credentials.GitHubRead`); env inventory in `lego/backend/AGENTS.md` (`BEX_AGENT_GITHUB_READ_API_URL`).

## Steps

1. Add `MintRepositoryAPIWriteToken` to `github.Client` and the `GitHubClient` interface: the read permissions plus t001's write permissions, one repository, with t001's handling of an installation that lacks one.
2. Add `Minter.MintGitHubWrite` with the read mint's session, Pod, phase and branch checks, refusing build principals, and its own audit verb (for example `agentsessions.MintGitHubWriteCredential`).
3. Serve it on its own internal path under the same HMAC, domain-separated by path. Add the gateway's client field, its env var with a cluster default, and the `lego/backend/AGENTS.md` and `.env.example` rows if a new variable is introduced.
4. Unit tests: the requested permission set, the fallback, a refused build principal, a terminal session, another Pod, and the audit record.

- [ ] The write mint never requests `contents`, `workflows`, `statuses`, `checks` or `administration` write (test).
- [ ] It applies every check the read mint does, and each mint is audited allowed or denied.
- [ ] `cd lego/backend && go test ./...` and `make lint` pass.
