# 027 — `gh` works for the agent but not in the session's web shell or SSH terminal

Why: a person who opens a session's terminal (the web Shell, `ssh`, Zed) and runs `gh run list` gets "gh auth login", because only the agent's process environment carries the `GH_*` settings the driver sets (w10/m513), while Devin's `gh` token is on the machine for every shell. Found by the w10/m513 Devin comparison (t007). Severity: minor (Devin parity). Surface: `lego/agent-image/driver/src/github-cli.ts`, the sandbox's login shell.

## Current state (2026-11-19)

The driver writes gh's config to `<status dir>/gh/config.yml` and passes `GH_CONFIG_DIR`, `GH_TOKEN` (a placeholder), `GH_REPO` and `GH_PROMPT_DISABLED` to the agent through `agentEnvironment`. A terminal started through the gateway exec path does not inherit them.

## End state

In a repo session, `gh run list` and `gh api repos/{owner}/{repo}` work from the web Shell and an SSH session without arguments (for example through a profile script or `/etc/gh` defaults the driver writes), and a repo-less session's terminal still has no `gh` configuration.
