## Objective

Settle the shape of the wake before code, and write it into ADR054 D8 (a new paragraph, or D9 if it reads better) and D7, ADR035 § Fail-closed behavior, and ADR018's agent-session rows. Every open choice takes the option that matches Devin ("SSHing into a session whose machine has gone to sleep now wakes the machine and completes the request", [release notes](https://docs.devin.ai/release-notes/2026), 2026-09-25). Record the user-visible choices for the result's `decisions:`.

## Context

- `VerifiedPublicKeyCallback` (`lego/backend/internal/sshgateway/nativessh/server.go:300`) resolves the target under the 10 s `HandshakeTimeout`. Only there can a refusal still be an auth banner (`toldRefusal`, `:899`). After it, the client has a connection and a refusal can only be channel stderr and an exit status.
- `Service.Resume` (`lego/backend/internal/agentsessions/editor.go:54`) returns at once: `resuming` with the start running in the background, or the session unchanged when a turn runs or a sandbox is up. Its refusals: `can_operate` / fresh `can_create` (403), `AGENT_SESSION_NOT_RESUMABLE`, `AGENT_SESSION_ARCHIVED`, and `admitDispatch`'s payment, billing and live-sandbox-cap refusals.
- A `resuming` session has no `sandbox_id` until its start binds, so the sticky target (`server.go:525-529`, `connectionTarget`) cannot name a pod yet. The Completer settles `resuming` back to `completed`/`failed`; a start with no sandbox converges within `editorStartBound` (16 minutes, `editor.go:44`).
- The gateway's other verbs: `agentsession.InternalTwoFactorPath` (`two_factor.go:36`) and `InternalKeyGrantPath`, signed with `BEX_SANDBOX_EXEC_SECRET` (`serveSignedMint` / `postSignedMint`).
- ADR054 D5 shows `sshAddress` only while the phase gate holds, and D8's Connect menu offers **Start the sandbox** on a closed session before it shows the `ssh` command and `zed://` link.

## Steps

1. **Where the wake runs.** The proposal from the note: call the verb in `VerifiedPublicKeyCallback`, after the key re-read, `verifiedOwner` and the login requirements, so a refusal is still a banner, and admit the login with the session id as a target that waits. Check that a client offering several keys, a retried connection and `ssh -O check`-style probes only ever call `Resume` again (idempotent: it returns `resuming` unchanged).
2. **The verb.** Path, request (subject, session id, key fingerprint, nonce) and answer (phase, sandbox, refusal code and message). Whether bex-api re-reads the key by fingerprint and derives the subject itself, and how a key owned by a bex API key is held to its grant (`core.KeySandboxesExec` plus what `resume` needs).
3. **The wait.** Which channels wait (every session channel, `sftp` included, or only the first). How the gateway learns the settle (polling `agent_sessions`, which its role reads, at what interval), the ceiling (the start's own, `editorStartBound`), the progress lines on stderr (Devin's wording and the dashboard's "starting" state), and what a channel prints and exits with when the start ends without a sandbox. Whether a waiting connection holds a session-limiter slot (it does today from `serveConn` on), and how a drain or the revalidator ticks treat it.
4. **Refusals.** What each `Resume` refusal tells the client: the w10/043 banner for authorization, admission's own message for a refused admission, the existing canceled and archived banners. Which metric outcome each counts as (`woke`, `rejected_no_sandbox`, …).
5. **Surfaces.** Whether a closed, unarchived session now shows `sshAddress` (REST, GraphQL, MCP) and the dashboard's `ssh` command and `zed://` link without **Start the sandbox** first, as Devin shows SSH for a sleeping session. Check Zed's connect timeout against a fresh start before letting `zed://` rely on the wake. Record t004's scope from the answer.
6. Amend ADR054 D7 and D8 (its **Limits** paragraph says SSH is refused, w10/049), ADR035 § Fail-closed behavior, and ADR018 if any choice diverges from Devin (only with the user's sign-off; otherwise take Devin's behavior).
