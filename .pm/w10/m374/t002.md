## Objective

Request views appear only where request data can exist (`publiclyRoutable(type)`). For a worker, cron job or private service the Network card shows only Outbound Bandwidth, and Logs offer no Request-logs type or request filters, matching Render: HTTP request volume and latency are "Web services only" ([service-metrics](https://render.com/docs/service-metrics)) and request logs are generated only for requests from the public internet to web services ([logging](https://render.com/docs/logging)).

## Context

- Evidence (worker round 227, private service round 241): [w4/613](../../w4/done/613.md).
- `dashboard/src/routes/services.$serviceId.metrics.tsx:102-111` (already reads the type for the Application card), `:148-152`; `dashboard/src/features/metrics/components/network-metrics-card.tsx:116-146`; `dashboard/src/features/logs/types.ts:66-70`; `dashboard/src/routes/services.$serviceId.logs.tsx:118-125`; `dashboard/src/features/services/lib/service-type.ts:136-142`.
- A static site keeps its Network card (w4/m113's deliberate request metrics); that parity question is separate.

## Steps

1. Pass `requests={publiclyRoutable(service.type)}` (or split the card) so non-routable types render only Outbound Bandwidth and send no request queries.
2. Hold the request sections until the type is known so a worker never flashes them; the pending skeleton matches each type's ready geometry (dashboard AGENTS.md).
3. Drop the Request-logs type and request filters for non-routable types; a stale `?type=request` URL falls back to application logs.
