## Objective

Settle the contract the other tasks build on, picking the option that matches Devin's session security profile. Devin chooses a session's profile at create "or changed later from the session's settings". Changes reach "existing sessions the next time they resume". "Members without the permission can't enumerate, select, or change profiles" ([Security profiles](https://docs.devin.ai/product-guides/security-profiles), re-read 2026-11-23). Write the contract into the milestone README as a design record. Amend ADR047 D2, which says "set at create only" and "A session's own binding is fixed at create", and the ADR018 agent `gh` row ("which bex cannot yet (w10/050)"). Name the new MCP tool in ADR094.

## Context

- Create's guard: `refuseGitHubCLIBinding(ctx, workspaceID, stored, binding, code, field)` (`lego/backend/internal/agentsessions/githubcli.go:80`) already takes a stored binding. It refuses `admin_required` unless the caller holds `can_manage` on the workspace, and refuses `mandatory` for a `true` under a mandatory off. An unchanged binding is never refused. `Create` calls it with `stored` nil (`service.go:699`).
- Storage: `agent_sessions.agent_config` jsonb, key `githubCli`. The store's only later `agent_config` write is the model (`lego/backend/internal/store/agentsessions.go:696`, `jsonb_set` / `- 'model'`), so a binding change needs no migration.
- The existing session-edit verbs to model on: `PUT /v1/agent-sessions/{id}/tags`, GraphQL `setAgentSessionTags`, MCP `set_agent_session_tags`, `bex agent tags` (`ReplaceTags`, `service.go:1410`, needs `can_operate` on the session). Each new verb needs rows in `lego/backend/internal/api/scope_matrix_ops.go` and `key_permission_ops.go`.
- The resolver reads `agent_config` live at every mint and dispatch (`agentsession.ResolveGitHubCLI`, `LoadGitHubCLIChain`), as an automation or environment edit already applies (ADR047 D2 "Where it resolves, and when a change applies").
- A repo-less session has no `gh` (`githubCLIOffLevel` returns "" for it). A spawn from inside a sandbox names no binding.

## Steps

1. **Verb shape.** Proposal:
   - REST `PATCH /v1/agent-sessions/{id}` with `{"agentConfig": {"githubCli": true|false|null}}`, decoded strictly. An explicit `null` returns the session to inherit, and an omitted field keeps the binding. Reject any other `agentConfig` key for now.
   - GraphQL `updateAgentSession(id, input: {githubCli, resetGithubCli})`. GraphQL cannot carry the null, so `resetGithubCli` stands in for it, as `resetAutomationsGithubCli` does.
   - MCP `update_agent_session` with the same fields.
   - CLI: `bex agent update <ags-id> --github-cli on|off|inherit`, or a flag on an existing verb.
   - Weigh a dedicated `githubCli` verb against a general session update that later fields can join, and name the audit verb.
2. **Which sessions take a change.**
   - Decide for each case: a repo-less session (store it, or refuse because it has no `gh` to bind), an archived session (refused as tags are, with `errArchived`?), a finished one (Devin applies a change at next resume, so probably allowed), one still `creating`, and a child session (its own `true` is stored but cannot turn `gh` on).
   - Name each refusal's code and status.
3. **Who.** Only a workspace admin (`can_manage`). Decide whether the admin also needs the session's own `can_operate`. Today an admin holds it on every session in the workspace, so check `ReplaceTags`'s model and state the rule. A bex API key also needs `agents:manage`, as tags do.
4. **When it applies.** The next `gh` mint reads the change at once, as an environment edit already does: an off refuses the next call, sooner than Devin's next resume, which ADR047 already records as the safe direction. The next dispatch's driver env follows it. An on reaches a turn dispatched with `gh` off only from its next turn. Check the web Shell, SSH and Zed `gh` follow the same route. Say whether a running turn needs anything else.
5. **The words.**
   - Rewrite the session level's `gh` refusal (`sshgateway/agentcred/githubapi.go:85-86`) to say how an admin changes the binding (the session's settings, or the CLI verb from step 1). Keep "chosen when it or the session that started it was created" only if it still holds, and cover a child, whose level may come from its root.
   - Rewrite the overlay's session line (`lego/agent-image/driver/src/overlay.ts:185`, "which was started with it off"). That change ships in the agent image: check whether an older driver's wording is still true enough, and say whether the image must be rebuilt and pinned in this milestone.
   - Update the composer's and the field descriptions' "set at create" wording.
6. **The dashboard.**
   - Pick where the session's settings live: a "Settings" item in the session header's menu opening a dialog with `GithubCliPicker`, or a section on the session page.
   - Settle what a member sees. w10/044's composer rule keeps the control open with every choice but the stored one disabled and "Only a workspace admin can change this.". Devin's "anyone can see whether their session is governed by a profile" adds that the member still sees what applies.
   - Say what the picker shows as inherited for a session an automation started, or a child, whose chain is longer than the workspace's setting. Decide whether session reads should gain the resolved level (for example `githubCliResolved`), or whether the dialog only offers the binding.
7. **ADRs.** Write the design record. Amend ADR047 D2's binding bullet, "Who may set a binding" and "Where it resolves". Add the MCP tool to ADR094's tool list, and update the ADR018 row.
