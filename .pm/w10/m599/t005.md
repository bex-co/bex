## Objective

Prove DoD 6 on real systems.

- Once production's pin carries the milestone's commits, a workspace admin in `tian-personal` starts one short repo session with `gh` inherited (on).
- The admin turns its `gh` off from the session's settings. The agent's next `gh` call is refused, naming the session level and the new words.
- The admin turns it back to inherit from the CLI or the API. The next turn has `gh`, and a `gh` call succeeds.
- A member's change is refused `admin_required`. Use `dev-10` if production has no member fixture.

## Context

- Production is read-only apart from this check. Use the `hetzner-prod` context in `~/.kube/config` for reads, and `bash scripts/qa-login.sh` for the signed-in dashboard steps (`.claude/skills/qa-find-bugs/SKILL.md` login and logout).
- The prod sandbox node is near capacity (w9/m349): one short session at a time, in `tian-personal`, deleted afterwards.
- The local kind/CAPD agent-session leg may be held by another workstream's `dev-N`. Don't take it over: run the member refusal on `dev-10`'s bex-api, which needs no sandbox.
- Park with ``pin must carry `<sha>` `` until production runs the commits.

## Steps

1. Confirm the production pin carries the milestone's commits.
2. Run the admin's off and inherit on one session, reading the refusal text the agent sees and the session's `agentConfig.githubCli` on REST, GraphQL and MCP after each change.
3. Run a member's change on `dev-10` (or production with a member fixture) and read the `admin_required` refusal.
4. Check the session's settings at 1280 px and 390 px.
5. Delete the session, log the QA user out, and revoke only the keys the check created.
6. Record the result in the milestone README with the session id, the pin and what each surface returned.

## Acceptance criteria

- [ ] The off refused the next `gh` call naming the session level, inherit restored `gh` at the next turn, and a member's change was refused.
- [ ] No session or key the check created is left behind.
