## Objective

Give a session the settings surface t001 chose, for example a "Settings" item in the session header's menu that opens a dialog. It shows the session's GitHub CLI binding with the composer's picker and saves a change through t002's GraphQL mutation. A workspace admin may choose any value but a mandatory-off `on`. A member sees what applies, with every other choice disabled and "Only a workspace admin can change this.", as w10/044 made the composer.

## Context

- The session header's menu: `dashboard/src/features/agent-sessions/components/session-detail-header.tsx:393-430` (tags, archive, delete) and `EditTagsDialog` (`edit-tags-dialog.tsx`) as a dialog to model on.
- The picker and its lock: `github-cli-picker.tsx` (`GithubCliPicker`), `lib/github-cli.ts` (`githubCliChoice`, `githubCliBinding`, `githubCliMandatoryOff`, `inheritedGithubCli`) and their tests. The composer uses them in `new-session-composer.tsx`.
- Mutations: `hooks/use-agent-session-mutations.ts`. Locales: `features/agent-sessions/locales/*.ts` (eight languages).
- Regenerate the GraphQL clients: the dashboard's generated types and `mobile/src/generated-graphql/index.ts`.
- `dashboard/AGENTS.md`: a skeleton must match the ready state at desktop and narrow mobile widths. A dialog opened from a loaded page has no route skeleton, but any pending state it adds must keep its geometry.

## Steps

1. Add the settings surface and its dialog per t001, with the picker showing the stored binding, or what inherit resolves to as t001 decides.
2. Save through the new mutation. Show the refusal's message on `admin_required`, `mandatory` or a refused state, and refresh the session's view on success.
3. Lock it for members as the composer does, and hide or disable it for sessions t001 rules out.
4. Add locale strings in all eight languages.
5. Regenerate both GraphQL clients.
6. Tests: an admin's change in each direction sends the right input, a member sees the lock, a mandatory off disables `on`, and a refusal is shown.
7. Run `yarn lint` and `yarn test` in `dashboard/`, and check the dialog at 1280 px and 390 px.
