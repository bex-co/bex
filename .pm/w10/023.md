# 023 — The dashboard composer cannot choose the sandbox size, and a workspace cannot set a default one

Why: since w10/017 a session can name its sandbox template (`agentConfig.template`, `bex agent run --template agent-4c-8g`), but only from the CLI and the API; a dashboard user whose session runs out of memory is told about `agent-4c-8g` and has no control to pick it, and every session that names nothing runs on the 2 CPU / 4 GB `agent`. Severity: minor (Devin parity). Surface: `/agents` composer, Settings → Agents, the workspace agent environment.

## Reference

Devin picks the machine per session at start ("Configuration → Virtual environment when starting a session") and lets an admin set an organization default ("Settings → Devin → Default platform"), which a session can still override ([Outposts](https://docs.devin.ai/cloud/outposts/overview), read 2026-11-18).

## Direction

- The composer offers the agent templates (name and size), defaulting to the workspace's default; the session detail shows the one a session ran on.
- The workspace agent environment gains a default template (REST/GraphQL/MCP `agent-environment`, `bex agent env set --default-template`), used when a create names none; the create's refusal and the out-of-memory reason keep naming the registered templates.
- bex-api serves the template list (name, CPU, memory) to clients, for example through the agent-session capabilities read, so neither the dashboard nor the CLI hard-codes it.
