# 033 — `gh workflow run` is refused, so a session cannot dispatch a workflow on its own branch, as Devin's Actions write can

Why: since w10/m522 a session's `gh` re-runs and cancels CI, but a repository whose slow or manual checks (an e2e suite, a benchmark, a preview build) run only on `workflow_dispatch` cannot have them run on the session's branch, while Devin's App holds Actions write and can dispatch. Found by the w10/m522 Devin comparison (t006), 2026-11-19. Severity: minor (Devin parity). Surface: `lego/backend/internal/sshgateway/agentcred/githubapi.go` (`githubAPIWrites`, `restWriteBodyRefusal`), ADR090 D4.

## Reference

Devin's App asks for Actions read and write "to view the actions configured for a repository" and to rerun workflows ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-19), which also covers `POST /repos/{owner}/{repo}/actions/workflows/{id}/dispatches`.

## Why it was refused

w10/m522 refused every dispatch: a dispatch starts a new run on any ref with chosen inputs and the repository's secrets, while a re-run repeats a run that already ran. A dispatch whose `ref` is the session's own branch runs only code the session pushed, which a `pull_request` workflow on its draft PR already runs with the same secrets.

## End state

`gh workflow run <workflow> --ref <the session branch>` (REST `POST …/actions/workflows/{id}/dispatches` with `"ref"` equal to the session's `bex-agent/…` branch, `refs/heads/` form included) is admitted with the w10/m522 write token. Any other `ref`, a missing `ref`, or a repeated key is refused naming the `bex` tools. A gateway test covers each, and ADR090 D4 and the overlay say so.
