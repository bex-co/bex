## Objective

Every settled turn whose repository was set up records whether its checkout was dirty and how many commits were not on the remote session branch, so the save decision and the surfaces read one stored fact.

## Context

- `GitFacts` (`lego/agent-image/driver/src/delivery-check.ts`) has `dirty` and `unpushedCommits`; a succeeded or interrupted status carries them as `git` (`session.ts:488`), a failed one does not (`session.ts:124`, `:513`).
- `statusReport.Git` in `lego/backend/internal/agentsessions/completion.go:58` decodes them; `settleCompleted` only logs them.
- The watchdog failure (`turn-bound.ts:128`, "ACP turn made no progress") and the turn ceiling both reach the failed status write.

## Steps

1. In the driver's failure path, after the agent is stopped and when the repository was set up, read the Git facts (bounded, best effort: a failed read writes none) and include them in the failed status.
2. Add the turn's `dirty` and `unpushed_commits` (nullable: unknown) to `agent_session_turns` with a migration, written in the finalize transactions for completed, interrupted and failed turns.
3. Keep the delivery note as it is.

## Files

- `lego/agent-image/driver/src/session.ts`, `delivery-check.ts`, driver tests
- `lego/backend/internal/agentsessions/completion.go`, `lego/backend/internal/store/` (migration, finalize), tests

## Acceptance criteria

- [ ] A driver test: a turn that fails after editing a file and committing reports `git.dirty: true`, `unpushedCommits: 1`; a setup failure reports none.
- [ ] A real-Postgres test: a failed and a completed turn each record their facts; an older status without them records unknown.
