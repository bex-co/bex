# 026 — A workspace cannot turn off its sessions' `gh` API access, as a Devin security profile can

Why: an admin who wants sessions to reach GitHub only through Git and the `bex` tools has no switch since w10/m513 gave every repo session a read-only `gh`; Devin's security profiles can remove the `gh` token. Found by the w10/m513 Devin comparison (t007). Severity: minor (Devin parity). Surface: the workspace agent environment (REST/GraphQL/MCP `agent-environment`, Settings → Agents), the gateway `github-api` route.

## Reference

A Devin security profile can "remove the GitHub CLI token from the machine"; sessions under it still work with repositories through Devin's git integration but "cannot make direct GitHub API calls" ([Security profiles](https://docs.devin.ai/product-guides/security-profiles), read 2026-11-19).

## End state

The agent environment has a setting (on by default) that, when off, makes the driver configure no `gh` for the workspace's sessions and the gateway refuse the `github-api` route for them with a message naming the setting; REST, GraphQL, MCP, the CLI and the dashboard all read and write it.
