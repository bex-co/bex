# 034 — A session cannot mark its pull request ready for review or merge it when its task asks, as Devin can

Why: a task such as "fix the flaky test and merge once CI is green" ends with a draft pull request a person has to undraft and merge, because the `bex` tools never undraft (ADR090 D3) and w10/m522 refuses `gh pr ready` and `gh pr merge`, while Devin's GitHub integration lets Devin merge once branch protection's required checks pass. Found by the w10/m522 Devin comparison (t006), 2026-11-19. Severity: minor (Devin parity; it needs a decision on what a session may do to its own pull request). Surface: `lego/backend/internal/agentsession/pullrequest.go` (the D3 verb), `lego/agent-image/driver/src/mcp-bex.ts`, ADR090 D3 and D4.

## Reference

Devin's App holds pull requests write ("create new PRs"), and its docs recommend branch protection so that "all required checks pass before Devin can merge changes" ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-19).

## Open question

Whether a session may undraft and merge only the pull request it opened (`prNumber` on the session), and only when its task or a person's message asked for it, or never. Branch protection still decides whether a merge is allowed, and an App's approval stays refused (w10/m522), so a session cannot satisfy required reviews by itself.

## End state

If it is allowed: a `bex` tool (or the D3 verb with a `ready`/`merge` input) marks the session's own recorded pull request ready and merges it with the repository's allowed method, refusing any other pull request and reporting GitHub's own refusal (required checks, reviews) as given. REST, GraphQL and MCP show the merged state, and `gh pr ready`/`gh pr merge` stay refused naming the tool. If it is not allowed: ADR018's agent rows record the divergence with the user's sign-off.
