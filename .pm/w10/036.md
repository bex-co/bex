# A model added to the platform catalog starts on in a workspace whose admins narrowed its model list

Why: an admin who turned `anthropic/claude-opus-5.5` off to keep spend down finds the next expensive model the catalog gains already on for every member, where Devin's curated allowlist leaves a model it does not list off.

- **Found by** w10/m527 t007 (Devin comparison), 2026-11-20. bex stores the list as the opt-out `agent_environments.disabled_models` (ADR047 D7, w10/m527 amendment), so every catalog model the admins did not turn off is offered, including one added to `BEX_AGENT_PLATFORM_MODELS` later. Devin CLI Team Settings offers "allow all models" or "allowlist specific models", a "curated list of approved models" ([Devin CLI Team Settings](https://docs.devin.ai/cli/enterprise/team-settings), read 2026-11-20). The page does not say how a newly released model is treated; a curated list implies it stays off until an admin adds it.
- **Code:** `modelOfferPatch` and `offeredModels` in `lego/backend/internal/agentsessions/environment.go`; migration `0315_agent_environment_models`.
- **End state:** a workspace that has never narrowed its list (no turned-off model) still offers every catalog model, including new ones. Once an admin has turned any model off, a model added to the catalog afterwards is off for that workspace until an admin turns it on, and Settings → Agents and `bex agent env` show it as off ("new in the catalog"). A test adds a catalog model after a narrowing write and checks the capabilities `models` and a create naming it (`AGENT_SESSION_MODEL_NOT_OFFERED`).
- Confirm Devin's behavior for a new model first (a Devin team account, or Devin's support), and record it in ADR018's agent-model row.
