# 047 — A session's surfaces do not show that auto-merge is armed on its pull request, or who armed it, as Devin's merge bar does

Why: after a session arms auto-merge (`merge_pull_request` with `auto: true`, w10/m577), its REST, GraphQL, MCP and dashboard reads say only `prState: open` until GitHub merges it, so a person cannot tell from bex that the pull request will merge itself, while Devin Review's "merge bar shows the current auto-merge status, including who enabled it". Found by the w10/m577 Devin comparison (t006), 2026-11-22. Severity: minor (Devin parity). Surface: `lego/backend/internal/agentsessions` (session read, PR-state poller), the dashboard session view.

## Reference

[Devin Review](https://docs.devin.ai/work-with-devin/devin-review), read 2026-11-22: "Enable or disable GitHub auto-merge from the merge button dropdown." "The merge bar shows the current auto-merge status, including who enabled it."

## Current state (2026-11-22, w10/m577)

The merge verb answers the sandbox `{merged: false, autoMerge: true}` or `{mergeQueue: true}` and records nothing on the session (`lego/backend/internal/agentsession/pullrequest_merge.go`, `Merge`). The PR-state poller (`lego/backend/internal/agentsessions/pr_state.go`) reads only open, closed and merged. GitHub's PullRequest has `autoMergeRequest { enabledAt enabledBy { login } mergeMethod }` and `isInMergeQueue`.

## End state

A session whose pull request has auto-merge armed or is in a merge queue shows it on REST, GraphQL and MCP (for example `prAutoMerge: {enabledBy, enabledAt, method}` or `prMergeQueued: true`) and on the dashboard's session view beside the PR state, kept current by the merge verb's answer and the PR-state poller, and cleared on a disarm or a merge. Tests cover the arm, the disarm, a person arming it on GitHub, and the merge.
