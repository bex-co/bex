## Objective

A deploy built from source has no `image` on REST, GraphQL, MCP, an event's `details.image`, the deploy header or the Events row, as Render's deploy schema says ("Not present for Git-backed deploys", pinned spec checked 2026-11-13). The stored row keeps the ref, because rollback runs that exact image.

## Context

- Evidence: [w4/621](../../w4/done/621.md) (round 248).
- `lego/backend/internal/deploys/service.go:169-175` (view), `lego/backend/internal/events/service.go:1265`, `lego/backend/internal/api/server.go:889`, `lego/backend/internal/store/image.go:103-115` (`PublicImageRef`, w4/m236).
- `dashboard/src/features/deploys/components/deploy-header.tsx:180-182`, `dashboard/src/routes/services.$serviceId.events.tsx:445`.
- Rollback reads the stored ref (`deploys.Rollback`, w4/m236 t002).

## Steps

1. Count the readers of the deploy `image` field first.
2. Omit `image` at the projection seams when the deploy has a commit or the service is repo-backed (a commit-less row of a repo-backed service must not regain it).
3. Keep an image-backed service's deploys byte-identical (the control).
