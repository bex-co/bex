## Objective

A service read (list, retrieve, create and update) carries each key Render's union member for its type requires: `buildPlan: "starter"` on all five types (Render's default build plan; bex has no other) and `healthCheckPath: ""` on `web_service` when unset.

## Context

- Evidence, probes and the per-type table: [w4/626](../../w4/done/626.md) (rounds 259-260, 2026-11-13).
- Pinned spec (`lego/backend/internal/api/openapi/render-public-api-1.json`, checked 2026-11-13): `webServiceDetails` requires `buildPlan` and `healthCheckPath`; `privateServiceDetails`, `backgroundWorkerDetails`, `cronJobDetails` and `staticSiteDetails` require `buildPlan` and not `healthCheckPath`.
- `renderServiceDetails` in `lego/backend/internal/apps/render.go:457` emits `healthCheckPath` only `if field.value != ""` (`:492-494`) and has no `buildPlan`.

## Steps

1. Emit `buildPlan: "starter"` for every type and `healthCheckPath` (empty when unset) for `web_service` only.
2. Remove `buildPlan` and `healthCheckPath` from the four `details(SuiteAPI, …)` entries and lower `allowlistSize`.
3. Leave a private service's `url` as it is (bex's 2026-07-26 capture saw Render omit it; w4/626 asks to note it in ADR018, which t006 does).

## Acceptance criteria

- [ ] An apps unit test: a web service with no health-check path renders `healthCheckPath: ""` and `buildPlan: "starter"`; a worker, cron job and static site render `buildPlan` and no `healthCheckPath`.
- [ ] The rendertest suites pass with the smaller allowlist.
