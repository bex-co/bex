## Objective

The route forwards each write t001 admitted for the session's repository, with its bounded body and a write token minted for that call, and refuses every other write with t001's message before anything reaches GitHub.

## Context

- `lego/backend/internal/sshgateway/agentcred/githubapi.go`: `githubAPIRequestRefusal` refuses every non-`GET`/`HEAD` REST call (`:283`), `graphQLRefusal` every mutation (`:328`). Only a GraphQL body is read and forwarded today (`:126`). Redirects are followed only for reads (`followStorageRedirects`).
- The driver's socket already relays any method and body (`lego/agent-image/driver/src/github-cli.ts`).
- Tests: `githubapi_test.go` (`TestGitHubAPIRouteRefusesWritesNamingTheBexTools`, `TestGitHubAPIRouteScopesGraphQLToTheRepository`).

## Steps

1. Extend the REST policy with t001's method and path patterns on `/repos/<repository>/…`, keeping the path-normalization refusals. Read and forward a write's body under t001's limit.
2. Extend the GraphQL policy: a mutation operation is admitted when every top-level field is an admitted mutation. A document that holds any refused mutation, or mixes in a refused query field, is refused whole.
3. Mint the write token (t002) only for an admitted write. Reads keep the read token. Count writes against the route's budgets, and add a write budget if t001 chose one.
4. Replace `readOnlyRefusal` with t001's message and keep `otherRepositoryRefusal`.
5. Tests: each admitted REST write and mutation reaches the fake upstream with the write token; each DoD 3 write is refused with the message and never reaches it; a mixed document is refused; another repository's write is refused; a read still carries the read token.
