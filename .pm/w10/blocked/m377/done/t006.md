## Objective

Check that the change is consistent across every surface it exposes: REST in `lego/backend/` against Render's pinned contract (default 20, max 100, cursor envelope, error shapes; `docs/ADR006-bex-api.md`), MCP against Render's MCP server, and GraphQL and the `dashboard/` lists unchanged (`dashboard/AGENTS.md`). File any drift as follow-up work rather than silently diverging.

## Acceptance criteria

- [x] Every served Render list pages as Render's does when unpaged; GraphQL and dashboard lists are unaffected; drift is fixed or filed.

## Result (2026-11-14)

REST now matches Render's `limitParam` default on every served list (the guard classifies each). GraphQL and MCP share the service functions but build their own filters, so they are unchanged (`deploys/graphql.go`, `jobs/graphql.go`, the MCP list tools, sandbox `listFiltered`, logs `LogLabelValues`), as the recorded scope says. Log label values are a bare array in Render's contract, so a cut at `limit` has no cursor; bex keeps the first values in sorted order, and Render's order is undocumented (noted in the code). The per-surface scope stays the proposal's recommendation, recorded in ADR006/ADR018 for the user's confirmation.
