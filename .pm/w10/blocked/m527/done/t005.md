## Objective

Settings → Agents lists the platform catalog with a switch per model, in English and Chinese:

- The catalog default is shown on and locked, with a line saying why.
- Admins turn the others on and off. Members see the list read-only.
- The default-model picker offers only the models that are on.
- When the saved default is off, the card says that the catalog default runs instead.

The pickers in the composer, the steering composer and the automation form already read the capabilities read's `models`, so check that they follow the narrowed list.

## Context

- `dashboard/src/features/agent-environment/components/agent-environment-card.tsx` holds the default-model select (`saved.models`). `available-agents-section.tsx` is the precedent for a per-item switch list that saves the whole list.
- `agent-environment-card-skeleton.tsx` must keep matching the card at desktop and narrow-mobile widths (`dashboard/AGENTS.md`, "Dashboard preloading skeletons must match their post-loading contents").
- `hooks/use-agent-environment.ts`, `api/agent-environment.graphql`, and the mocks in `dashboard/src/test/mocks/agent-environment.ts`.
- Pickers: `dashboard/src/features/agent-sessions/components/model-picker.tsx`, `lib/models.ts`, `new-session-composer.tsx`, `steering-composer.tsx`, and `dashboard/src/features/agent-automations/components/automation-form.tsx`.
- Strings: `dashboard/src/i18n/`.

## Steps

1. Query and mutate the field in `agent-environment.graphql`, and regenerate the types.
2. Add the model list to the card beside the default model. It is disabled for members and locked on for the catalog default. It saves the whole list, and an error leaves the switches at the saved state.
3. Limit the default-model select to the enabled models. Keep showing a saved default that is now off, with the note that the catalog default runs.
4. Check that the composer, the steering composer and the automation form offer only the capabilities `models`. An automation whose saved model is now off should show that model with a note saying runs use the default, not a blank select.
5. Update the skeleton, and compare the pending and ready states side by side at desktop and narrow-mobile widths.
6. Write tests: the read, an admin turning a model off (the mutation is sent and the switch reflects the answer), the locked default, a member's read-only state, the error path, the default-model select's options, and the automation form showing a turned-off model.

## Result

Done 2026-11-20. Settings → Agents has "Models members can choose" after the default model, drawn only on the platform catalog: one switch per catalog model in catalog order, the catalog default locked on with the reason, read-only for members. Each toggle saves the whole list and toasts. A refused save puts the switches back and says why (`AGENT_ENVIRONMENT_MODELS_INVALID`, forbidden, or retry). The default-model select offers only the enabled models. A saved default that is off stays the value as "{model} (turned off)" with a note naming the catalog default that runs, and one the catalog dropped gets its own note. The pickers already read the capabilities `models`. `ModelPicker` with one offered model now still offers it when the shown model is turned off, and the automation form shows a saved model that is off with a note that runs use the workspace default. The skeleton draws the section's heading, description and four rows, the first with the locked note, through the same row frame as the ready list. A capabilities-affecting environment save now evicts the cached capabilities read instead of a `refetchQueries` that had no active watcher on Settings, so the next composer or automation form reads the narrowed list. Copy in all 8 locales. `yarn lint` and `yarn test` pass (807 files, 9,755 tests). The side-by-side pending and ready comparison at desktop and narrow-mobile widths was not run live (dev-10 was down and the host loaded). Skeleton parity is held by the shared row frame and the card test "keeps the skeleton's model list in step with the ready card".
