## Objective

Workspace and account deletion first flushes and charges all unbilled usage, refusing deletion with `BILLING_BALANCE_DUE` and a payment link if the charge fails; binding a card whose Stripe fingerprint carries written-off agent-model debt is refused.

## Context

- ADR091 D10.4–D10.7 (amended 2026-11-02); ADR086 account deletion (amendment 2026-10-30).
- Payment method binding: ADR075 D7 `PaymentGate`.

## Steps

1. Deletion path: flush unbilled usage for the workspace bypassing the seal horizon, invoice, charge; on failure return typed `BILLING_BALANCE_DUE` with a payment link and keep identity.
2. At binding: enable Stripe Radar rules and refuse `card.funding = prepaid` with a typed error.
3. Persist written-off debt by card fingerprint; refuse binding a matching card with a typed error.
4. Dashboard: deletion dialog shows the balance-due state and pay link.
5. Update ADR086 body to match what shipped.

## Files

- `lego/backend/internal/billing/`
- account/workspace deletion handlers (ADR086)
- payment-method bind handler
- dashboard deletion dialog
- `docs/ADR086-account-deletion.md`

## Done (2026-11-05)

- **Settle before delete.** `billing.Settler` (`internal/billing/settle.go`) runs first in `workspaces.deleteWorkspace`, before membership revocation and every purger, so the public `deleteWorkspace` and the account worker's teardown both settle. `accounts.Request` also settles each `delete` workspace before the intent commits (25-second deadline, inside the HTTP write timeout). Steps: (1) resolve the live contract; no Customer, a Customer with `bex_deleted_at`, or no live Subscription is a no-op, and the Stripe purger now runs last (`Deps.WorkspaceBillingPurger`, appended after every other pre-cascade purger), so a retry after partial teardown settles nothing. (2) Export the workspace's pending rows (`store.SelectWorkspaceUnemittedUsage`, sharing the outbox read; new partial index `usage_hourly_workspace_pending_idx` in 0198 after EXPLAIN showed the outbox index walking every workspace's backlog). The Customer is provisioned once, not per batch. (3) An open/uncollectible invoice of the Subscription (`Invoices.List` by subscription, capped) is paid as it is. Otherwise wait, with backoff up to 60 s (bounded by the request's own deadline minus a 5 s charge reserve), until Stripe's per-Customer meter event summaries cover bex's exported totals for the period (`store.ExportedUsageTotals`, converted like `stripeMeterEvent`); still short returns the retryable 503 `BILLING_SETTLING` with the Subscription untouched; a shortfall larger than the last hour's exports is logged as a mismatch, not awaited. Then `Invoices.CreatePreview`, and only when `amount_due > 0` reset the anchor with `always_invoice` + `payment_behavior=default_incomplete`; drafts are finalized through the shared `finalizeDraftInvoice` (also behind `FinalizeThresholdInvoice`). (4) Each invoice is paid exactly once off-session; a decline returns 409 `BILLING_BALANCE_DUE` from the listed/returned invoice's amount and hosted link. In the account worker a refusal stores only the code in `last_error`, and the first one emails the hosted link to the account (Kratos email lookup + SMTP mailer); within 5 minutes of the intent the worker reuses the request's settle.
- **Card checks.** `cards.go`: at `checkout.session.completed` and workspace-creation finalize, a prepaid card, or one whose fingerprint matches any `billing_agent_model_writeoffs` row, is detached (one idempotent `detachPaymentMethod`, shared with `retireCustomer`) and never bound. The typed reason (`store.PaymentMethodRejection`) goes to `billing_provider_mappings.payment_method_rejection` (0198; `payment_method_rejected_at` dropped as unused), which `SetPaymentMethodBound` clears. Readiness reads it from `PaymentEligibility` (no new query) and exposes `paymentMethodRejection` (REST/MCP lower-case; GraphQL enum `PaymentMethodRejection`). Workspace creation returns 400 `PAYMENT_METHOD_REJECTED`, detected with `billing.IsPaymentMethodRejected`. The write-off fingerprint is the failed charge's card (invoice payments → PaymentIntent latest charge, else `last_payment_error.payment_method`), falling back to the default card. Radar rules and the key's permissions are in the runbook.
- **Dashboard.** `BalanceDueAlert` (balance via the shared `formatMinorUnits` in the active locale, also behind the charge tree's `money()`; a **Pay invoice** link rendered only for https `*.stripe.com`) in the workspace and account danger zones. `PaymentMethodRejectionAlert` renders with the lifecycle alert in one shared `BillingStatusAlerts` (both payment cards) and on the sign-up wall; the workspace-creation flow localizes `PAYMENT_METHOD_REJECTED`. en + zh.
- **Tests.** `workspaces/settle_pg_test.go` (real DB + Stripe stub): $3 charged with one anchor reset and one charge, then deleted; decline refuses with the workspace, rows and Subscription intact, and the retry after payment neither resets nor charges again; lagging summaries → `BILLING_SETTLING` with no preview/reset/charge, then the caught-up retry charges once; an open invoice is paid without a reset; a $0 preview keeps the billing date; a retry after the Stripe purger ran (and a retired Customer) settles nothing and deletes. `accounts`: refuse before intent; worker decline stores the code and emails the link once; worker reuses a fresh request's settle. `billing/cards_test.go`: prepaid/flagged refused and detached, clean binds, real-DB fingerprint dedupe, fingerprint from the failed charge / last payment error / default fallback. Dashboard: link safety, rejection parsing, creation-flow copy (en/zh), `formatMinorUnits`, alerts.
- **Residuals.** Usage the rollup has not yet written (a Prometheus meter's open hour, the last closed hour before the rollup, a sandbox's open hour) is not settled and falls to the purger's asynchronous `invoice_now` invoice. An unpaid invoice of an already-cancelled Subscription is not charged by a later settle. `default_incomplete` leaves the Subscription `past_due` while the settle invoice is unpaid. A declined settle moves the billing date (documented). A card made default in the Billing Portal is audited but not screened. A workspace-creation attempt whose card was refused must be cancelled and restarted. The anchor reset, `default_incomplete`, and meter summaries with a future-minute `end_time` are verified only against a stub; a test-mode Stripe probe belongs with t007's rollout gates.
