## Objective

Store the workspace's default agent template and make every session that names none run on it: a create, an automation run, a handoff and a child session. The session read reports the template it runs on.

## Context

- `lego/backend/internal/store/migrations/0169_agent_environments.up.sql` (the table), `lego/backend/internal/store/agent_environments.go` (`AgentEnvironment`, `AgentEnvironmentPatch`); the next migration number follows the newest in `internal/store/migrations/`.
- `lego/backend/internal/agentsessions/environment.go`: `EnvironmentInput`, `validateEnvironmentInput`, `environmentView`, `UpdateEnvironment`.
- `lego/backend/internal/agentsessions/service.go`: `validateTemplate` (`:624`), `resolveCreateModel` (create and automation save), the dispatch's sandbox spec.
- `lego/backend/internal/agentsessions/completion.go:254`: the out-of-memory reason (`lostSessionSandboxReason`), which falls back to `sandbox.DefaultAgentTemplate`.
- GraphQL (`internal/graphql` schema + resolvers), REST (`agentsessions/rest.go`), MCP `update_agent_environment` and `get_agent_environment` (`agentsessions/mcp.go`, golden `testdata/mcp_tools.golden.json`).

## Steps

1. Migration: `agent_environments.default_template text NOT NULL DEFAULT ''` with a length check; store read and patch.
2. `defaultTemplate` on `EnvironmentInput` and the environment view (REST, GraphQL `AgentEnvironment`/its input, MCP), validated against the registered agent templates with t001's code; `""` clears it.
3. Create: an empty `agentConfig.template` resolves to the workspace default (or `agent` when unset or no longer registered) and is recorded on the session; automations resolve it when they fire.
4. The out-of-memory reason names the template the session ran on and the next larger one, and says how to choose it in the dashboard as well as with `--template`.
5. Run `cd lego/backend && go test ./...` and `make lint`.

## Files

- `lego/backend/internal/store/{agent_environments.go,migrations/}`, `lego/backend/internal/agentsessions/{environment.go,service.go,completion.go,rest.go,mcp.go}`, `lego/backend/internal/graphql/`, their tests and goldens

## Acceptance criteria

- [ ] A workspace with `defaultTemplate: agent-4c-8g` starts a session naming none on `agent-4c-8g`, and its read reports it; a session naming `agent` still runs on `agent`.
- [ ] An unregistered `defaultTemplate` is refused with the typed 400 listing the templates on REST, GraphQL and MCP.
- [ ] An automation naming no template runs on the default in force when it fires.
- [ ] `cd lego/backend && go test ./...` and `make lint` pass.

## Out of scope

- The template list on the reads (t003); CLI (t004); dashboard (t005).
