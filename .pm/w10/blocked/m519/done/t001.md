## Objective

Decide and record the contract the other tasks build: the `defaultTemplate` field of the agent environment, when a session or automation that names no template resolves it, the template list's shape and where it is served, the refusal codes, and what happens when a stored default stops being registered.

## Context

- Agent templates: `sandbox.AgentSessionLifecycle.AgentTemplates()` (`lego/backend/internal/sandbox/service.go:1113`, session-only templates smallest first); registered in `lego/backend/cmd/api/main.go:140` (`agent` = `Plan2C4G`, `agent-4c-8g` = `Plan4C8G`); `AgentTemplate.Size()` formats "2 CPU, 4 GB".
- The create's refusal: `Service.validateTemplate` (`lego/backend/internal/agentsessions/service.go:624`), `AGENT_SESSION_INPUT_INVALID` with `field` and `templates`.
- The model default this mirrors: `defaultModel` in `agentsessions/environment.go` (`EnvironmentInput`, `validateEnvironmentInput`, `environmentView`), resolved at create by `resolveCreateModel` (`service.go`) and recorded in `agentConfig.model`.
- The capabilities read excludes templates on purpose (`service.go:1129`, `mcp.go:283`): it was written for the mobile composer (w11/m6) when every sandbox template was internal. The agent templates are now a customer choice already named in errors and CLI help; decide whether capabilities lists only the session-selectable ones (and amend that clause) or the environment read alone serves them.
- Devin: the machine is chosen at session start and an admin sets an organization default that applies to new sessions ([Outposts](https://docs.devin.ai/cloud/outposts/overview)).

## Steps

1. Resolution: an empty `agentConfig.template` takes the workspace default at create (recorded on the session, so its read reports it and a later default change leaves it alone); an automation that names none takes the default when it fires, as its model does.
2. A stored default that is no longer registered: the create falls back to `agent` and the environment read says so, never a failed session.
3. List shape: name, CPU, memory (numbers a client can sort and format) and which is the default; which reads carry it (capabilities, environment, or both).
4. Codes: the default's refusal (`AGENT_ENVIRONMENT_TEMPLATE_INVALID` or the environment's existing input code, with `field: defaultTemplate` and `templates`), unchanged create refusal.
5. Amend ADR047 (the agent environment and the capabilities read) and record the decisions in the milestone README's design record.
