## Objective

A message sent to a session whose last turn completed with undelivered work runs in a sandbox booted from that turn's disk, instead of a fresh clone.

## Context

- `Service.Steer` → `runSteerDispatch` (`lego/backend/internal/agentsessions/service.go:2166`) claims a retained image (`Retention.claim`), then tears the previous sandbox down through `CleanupAgentDispatches` and dispatches a fresh one. A queued message reaches the same path.
- The previous sandbox is alive in its idle grace, possibly with an editor connected since the turn ended, which may have changed the checkout.
- `RetainAgentSessionSandbox` (`lego/backend/internal/sandbox/agent_build.go`) is the save; the steer already waits for a save in progress up to `retentionSaveWindow`.

## Steps

1. Before the previous sandbox is torn down, decide whether to save it: the turn's recorded facts, re-read in the live sandbox through the gateway exec path (`sessionExec`, `git status --porcelain` and the count against the remote session branch) when an editor connected after the turn ended or the facts are unknown.
2. If there is undelivered work, begin retention for the settled turn (a `saving` row, cause `replaced`) under the same claim rules as m413, save, then claim the kept image for this dispatch. A full cap, a failed save or an open editor dispatches fresh and records the loss.
3. Keep the accept path fast: the save runs in the background dispatch, and the session reads `redispatching` meanwhile.
