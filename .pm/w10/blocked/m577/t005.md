## Context

- Production runs the milestone once the newest `chore(deploy): pin platform images to <sha>` on `origin/main` contains its commits. Park with that pin gate until then.
- The sandbox node is near capacity (w9/m349). Run one short session, two at most, and restore any setting you change.

## Steps

1. Start a session with the task "make a one-line change, open the PR, and merge it once CI is green". Check these:
   - it marked the PR ready and called `merge_pull_request` with the option while the check was still running, and ended its turn without waiting;
   - the answer said auto-merge was armed, pinned to the recorded head;
   - GitHub merged the pull request as `bex-co[bot]` after the check passed;
   - REST, GraphQL and MCP read `prState: merged` within the poller's five minutes, or sooner by webhook.
2. Turn "Allow auto-merge" off on the repository and have the session, or a second short one, arm a new pull request. Check that it gets t001's typed refusal with its hint.
3. The queue leg: if the QA account can own a repository in an organization with a merge queue on `main`, arm or merge a pull request there and check that the answer says queued and that GitHub merges it. If it cannot, record why, and that the queue rests on t002's and t003's tests.
4. Check the audit records. Record the session ids, pull request numbers and outcomes in the milestone README, then delete the sessions and the repositories.
