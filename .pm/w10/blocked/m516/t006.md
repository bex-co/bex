## Objective

Prove the Definition of done's items 2-6 on production once a deploy carries the milestone.

## Context

- Production pin: the newest `chore(deploy): pin platform images to <sha>` on `origin/main`; read-only cluster access through `bash scripts/fetch-app-kubeconfig.sh` (or the `hetzner-prod` context).
- Run as the `bex` workspace's CLI or the QA user (`bash scripts/qa-login.sh`); delete what the check creates.
- Usage events record the model and its cost (`agent_model_usage_events`, ADR091 D2.3); read them through the billing or usage read the workspace exposes, or read-only on the production database if no API shows them.

## Steps

1. `bex agent models` shows the claude agent's effective model and the catalog.
2. `bex agent run --agent claude --model <a non-default catalog model>` on a small task completes a turn; the session read reports the model; its usage records that model at its own cost.
3. A message with `--model <the default>` switches the next turn back.
4. A non-catalog model is refused with the typed 400.
5. In the dashboard composer, the model control lists the catalog and starts a session on the chosen model.

## Acceptance criteria

- [ ] Each step's result, with session ids, is recorded in the milestone README.

## Out of scope

- Fixing what the check finds, unless it is this milestone's own defect.
