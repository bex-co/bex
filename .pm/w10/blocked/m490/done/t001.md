## Objective

Every service and Blueprint whose repository is on GitHub, and reachable through the workspace's GitHub App installation, stores GitHub's numeric repository id beside its `repo` URL. The id survives renames and transfers, so later tasks can match pushes by it.

## Context

- The push matcher reads App CRs (`repoCandidates`, `lego/backend/internal/apps/webhook.go:948`), so the id must reach the App spec the projector writes (`projectSpec`, `lego/backend/internal/store/reconciler.go`), not only the `apps` row. `AppSpec.Repo` is `lego/types/v1alpha1/app_types.go:616`.
- Blueprints are matched from the store (`ListAutoSyncBlueprints`, then `blueprintAutoSyncTargets`, `webhook.go:875`), so the `blueprints` row needs the id too.
- `github.Repo` already carries `ID` (`lego/backend/internal/github/client.go:160`). `LookupRepo` (`client.go:576`) resolves owner/repo with a token, and GitHub's API follows a renamed repository's redirect, so a lookup of a stale name answers the renamed repository with the same id.
- Services created from a public URL in a workspace with no GitHub connection cannot receive pushes (ADR026 § 8, `w10/blocked/m375`); they get no id and stay URL-only.

## Steps

1. Add the id to the store (`apps` and `blueprints`, a new migration above `origin/main`'s highest) and to the App spec (a `repoId` field in `lego/types`, CRD codegen in `lego/operator`), projected by the reconciler.
2. Set it wherever a service or Blueprint is created or its source changes through a GitHub connection: create, `SetSourceAndRegistryCredential`, Blueprint create and sync.
3. Backfill: for every stored GitHub repo with a workspace installation that can read it, resolve the id once through the installation token. A rename found this way also yields the new URL; leave moving `repo` to t003's rule, but record what the backfill saw.
4. Keep the id off tenant-facing reads unless Render has the field.

## Files

- `lego/backend/internal/store/migrations/`, `lego/backend/internal/store/` (apps and blueprints accessors, `reconciler.go`)
- `lego/types/v1alpha1/app_types.go`, CRD codegen under `lego/operator`
- `lego/backend/internal/apps/` (create and source-change paths), `lego/backend/internal/github/client.go`

## Acceptance criteria

- [x] A service created from a connected GitHub repository stores its repository id, and its App CR carries it.
- [x] The backfill fills the id for an existing service on a renamed repository, using the stale stored name.
- [x] A public-URL service in a workspace with no GitHub connection gets no id and is unchanged.

## Out of scope

- Using the id to match pushes (t002) and moving the stored URL (t003).

## Outcome (2026-11-18)

Done. Migration 0298 adds `apps.github_repo_id` and `blueprints.github_repo_id` (0 = unknown). Create and Update Source record the id their repository check reads (`ValidateRepo` now returns it when the workspace's installation grants the repository); a source change to another repository forgets the old id in the same row write (`SetAppSource`). `apps.RepoIdentityBackfill` (bex-api, every 30 minutes) resolves every remaining github.com service and live Blueprint through the installation (`GrantedRepo`, which GitHub answers for a renamed repository's old name too) and logs a rename it sees without moving the URL. The first App-signed push that matches a row by URL also records the payload's id.

Deviation: the App carries the id as the annotation `app.bex.co/github-repo-id` (`core.AnnotationGitHubRepoID`), stamped by the projector from the row, not as a `repoId` spec field in `lego/types`. A spec write bumps `metadata.generation`, which a deploy row in flight reads as a supersede (w6/m46 t004), and the operator never reads the id, so no CRD change was needed. Services a Blueprint creates get their id from the backfill or their first push, not at create. Tests: `TestCreateStoresTheGrantedRepositoryID`, `TestSourceChangeRecordsTheNewRepositoryID`, `TestRepoIdentityBackfillResolvesAStaleName`, `TestProjectorStampsTheGitHubRepoID`, `TestPGGitHubRepoIdentity`, `TestRepositoryIDComesOnlyFromTheInstallation`.
