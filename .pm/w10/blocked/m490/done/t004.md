## Objective

A transfer to an account where bex's GitHub App is not installed, or a revoked repository grant, stops pushes from reaching bex at all, and an id cannot fix that. The service's Settings → Source then says that the GitHub App cannot read the repository, and what to do, instead of looking connected.

## Context

- Render's GitHub doc says losing repository access "can disrupt deploys for that service" and lists a repository made private as a cause (render.com/docs/github).
- t001's backfill and lookups already learn when an installation token cannot read a stored repository.
- The dashboard's source card is `dashboard/src/features/services/components/service-source-card.tsx` (tests beside it).

## Steps

1. Expose the access state the lookup found on the service's GraphQL read, as a bex extension, with the time it was checked.
2. Show it on the source card with the step to fix it (install the GitHub App on the new owner, or grant the repository), in all eight locales.
3. Refresh the state when the source changes or a lookup succeeds again.

## Files

- `lego/backend/internal/apps/` or `lego/backend/internal/github/` (the lookup), the GraphQL schema for services
- `dashboard/src/features/services/components/service-source-card.tsx` and its locales

## Acceptance criteria

- [x] A service whose installation token gets 404 for its repository shows the warning on Settings → Source; a readable one shows none.
- [x] The warning clears after the repository is granted again.

## Out of scope

- Automatic reinstallation or repository grants.

## Outcome (2026-11-18)

Done. GraphQL `Service.repoAccessLost` (a bex extension, computed by the by-id read only, like `pushDeliveryMethod`): true when the service has a GitHub repository id and the same live grant check reports `manual_webhook` or `unavailable`. Settings → Source shows "bex's GitHub app can't read this repository" with the steps (install the app on the new owner, or grant the repository again), in all eight locales; it clears on the next read after the grant returns. Deviation: no checked-at time, since the state is computed on each read (memoized at most a minute), not stored. Tests: `TestGetReportsLostRepositoryAccess`, the source card's warning test, the status mapper test.
