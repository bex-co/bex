## Objective

While a workspace has the setting off, its sessions' `github-api` calls get no token and the gateway answers each with a 403 in GitHub's error shape whose message names the setting. Its next dispatch also tells the driver to configure no `gh`.

## Context

- `Minter.mint` (`lego/backend/internal/agentsession/mint.go`) serves `MintGitHubRead` and `MintGitHubWrite`. The Minter is wired in `lego/backend/cmd/api/main.go` (`agentsession.Minter{...}`) and has no agent environment store yet.
- The internal hop names refusals with `RefusalHeader` (`contract.go`); the handler sets it (`http.go`) and the gateway's client turns it back into a sentinel (`http.go`, the `RefusalModelKeyMissing` case). An old gateway that does not know the new value still sees a 403 and answers "bex: forbidden", so the wire stays compatible both ways.
- `serveGitHubAPI` (`lego/backend/internal/sshgateway/agentcred/githubapi.go`) maps `agentsession.ErrForbidden` to "bex: forbidden" after `mint.Mint`; the new sentinel must be tested before it, as `modelproxy.go` does for `ErrModelKeyMissing`.
- `driverEnv` (`lego/backend/internal/agentsessions/service.go`) builds each turn's driver env; it already reads the workspace's agent environment for the network tier and the default template.

## Steps

1. Add the sentinel (wrapping `ErrForbidden`) and its `RefusalHeader` value; return it from the read and write mints, after the Pod and lifecycle checks, when the session's workspace has the setting off. The Git mint (`Mint`) and the build mint are unchanged.
2. Map it in the gateway route to 403 with t001's message, in GitHub's error shape, and record it in the route's metrics as its own refusal.
3. Pass t001's driver env (`BEX_AGENT_GITHUB_CLI=0`) from `driverEnv` when the setting is off.
4. Tests: a mint refused with the sentinel and audited as denied; the gateway's 403 body names the setting for a read and for a write; a Git push mint in the same workspace still succeeds; `driverEnv` carries the variable only when the setting is off.

## Result

Done 2026-11-19: `agentsession.ErrGitHubCLIOff` and `RefusalGitHubCLIOff` (`github-cli-off`) are returned by `MintGitHubRead`/`MintGitHubWrite` through `Minter.githubCLIAllowed`. That check reads the row on every call after the Pod, lifecycle and branch checks, and fails closed when the store is unwired or the read fails. bex-api wires `Environments: st`. The gateway route answers 403 with the refusal text and counts `authentications_total{result="github_cli_off"}`. `driverEnv` takes the environment row and sets `BEX_AGENT_GITHUB_CLI=0` for a repo session while the setting is off. `EgressTierStore` became the shared `EnvironmentStore`. Tests: `TestMintGitHubAPICredentialsAreRefusedWhileGitHubCLIIsOff`, `TestGitHubCLIOffRefusalSurvivesTheInternalHop`, `TestGitHubAPIRouteRefusesEveryCallWhileGitHubCLIIsOff` and `TestDispatchTellsTheDriverWhenGitHubCLIIsOff`.
