## Objective

A session whose sandbox the pool cannot place waits and starts when capacity frees, instead of failing its turn after the first 300 s server wait.

## Context

- `dispatch` / `bootSandbox` (`lego/backend/internal/agentsessions/service.go`) create once and settle the turn on any error.
- `dispatchTimeout` (15 min) bounds the goroutine, and dispatch recovery abandons a dispatch whose `next_check_at` passed (`dispatch_recovery.go`, `store/agentdispatch.go`).
- On a timeout the OpenSandbox server deletes the sandbox it created (production log: "Creation failed, cleaning up sandbox"). w3/m405 t002 defines "never two sandboxes for one turn": look the earlier attempt up by the binding labels and the turn.

## Steps

1. In `bootSandbox`, on a start failure whose cause is `pool_full`, end the attempt's sandbox if one survived (`CleanupAgentDispatches` for the turn). Then create again after t001's backoff, until it is placed or t001's bound passes.
2. Keep the dispatch alive while it waits.
   - Advance `next_check_at` on each attempt, so neither recovery nor the legacy repair in `ListAgentDispatchesDue` abandons it.
   - Lift the 15-minute ceiling for a waiting dispatch only.
   - Record the waiting state on the session row, so another replica's read shows it.
3. Stop at once on Cancel, Delete or Archive: check the phase before every attempt, and let the context end the wait in progress.
4. When the bound passes, fail the turn with `SANDBOX_START_FAILED` and the `pool_full` cause, with words that say how long it waited. Every other cause fails at once with its own words.
5. Count each attempt and each wait in the existing provision metrics (`observeProvision`).
