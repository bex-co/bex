## Objective

Move the driver's ACP client SDK to the same major as the new adapter (2.x). Adapt `ClientSideConnection` usage and the typed `session/update` mapping to its API, keeping codex-acp (SDK `^1.3.0`) and gemini `--acp` working.

## Context

- `lego/agent-image/driver/package.json` pins `@agentclientprotocol/sdk@0.14.1` and `ai@6.0.237`. Stay on AI SDK v6 (w5/m66 decision).
- `src/acp.ts` covers initialize, newSession/loadSession, prompt and cancel, plus the `Client` handlers. `src/acp-map.ts` maps ACP updates to typed UI parts.
- The offline fixture `fixtures/acp-agent.mjs` imports the SDK too.

## Steps

1. Read the SDK 1.x/2.x migration notes. Bump the pin and regenerate `package-lock.json`.
2. Fix type and API breakage in `acp.ts`, `acp-map.ts` and the fixture. Map any new update kinds from t001 to typed parts rather than dropping them.
3. Confirm the negotiated `protocolVersion` still works with codex-acp 1.4.0 and gemini-cli 0.55.1 (offline fixture, or a real `initialize` handshake against the installed binaries).

## Outcome (2026-10-22)

- **SDK port:** `@agentclientprotocol/sdk` 0.14.1 → 2.0.0. 2.0 removes `ClientSideConnection` and the `Client` interface. `acp.ts` now uses `client().onNotification(session/update).onRequest(session/request_permission).connect(stream)` and `agent.request(methods.agent.*)`. Cancel is now `agent.notify`, and Codex routing uses `methods.agent.providers.set`.
- **Entrypoint:** imports moved to `@agentclientprotocol/sdk/unstable`. Prompt `usage` and `providers/set` are outside the stable v1 schema, whose parsers would strip them. The wire protocol is still ACP v1.
- **Behavior changes found and fixed:**
  - SDK 2.x rejects with a `RequestError` (an `Error` subclass) instead of the raw `{code,message,data}` object. `describeError` dropped `data`, which broke redaction and the auth-vs-state-loss classification (two tests failed). It now renders an `Error` that carries a numeric `code` as a protocol error.
  - SDK 2.x rejects in-flight requests with "ACP connection closed" as soon as stdout ends, before the child's `exit` event carries the redacted stderr diagnosis (the crash test failed). `raceTerminal` now waits up to 1s for that diagnosis.
  - The new adapter sends a tool's real command and title on a later `tool_call_update`, and its result only as text `content` with no `rawOutput`. Durable tool parts came out as title "Terminal", `input: {}`, `output: {}`; the old adapter stored `output: "mock"`. The mapper now re-publishes refined input for running calls and uses text content as the output or error when `rawOutput` is absent. The placeholder-input gap predates the bump: the old second `tool_call` was ignored too.
- **New update kinds:** no typed mapping needed. They are capability-gated (plan/notices/AIR), which the driver does not advertise. The adapter falls back to `plan` and agent-message text, and `usage_update` uses the existing transient default.
- **Handshakes:** all three adapters were exercised in the built image. Claude got a full offline turn (see t006). Codex and Gemini are covered by the unchanged fixture suite; their real `initialize` was not run separately.
