## Findings (2026-10-22)

Installed `@agentclientprotocol/claude-agent-acp@0.94.0` and `@zed-industries/claude-code-acp@0.16.2` side by side, then compared their `dist/` and the bundled SDKs.

- **Target version:** `@agentclientprotocol/claude-agent-acp@0.94.0`. Bin `claude-agent-acp`, which maps to `/usr/local/bin/claude-agent-acp` after a global install.
- **claude-agent-sdk 0.2.44 → 0.3.303:** Claude Code (2.1.303) now ships as a **native per-platform binary** through optionalDependencies (`@anthropic-ai/claude-agent-sdk-linux-{x64,arm64}[-musl]`, about 270 MB each). The adapter resolves it with `claudeCliPath()` unless `CLAUDE_CODE_EXECUTABLE` is set (`acp-agent.js:662`). Our install uses `npm install --global --ignore-scripts` without `--omit=optional`, so the glibc binary for the image arch installs. Expect a much larger image.
- **`CLAUDE_CODE_EAGER_FLUSH`:** still honored. The 2.1.303 binary awaits the transcript flush when it is set (`Boolean(a.CLAUDE_CODE_EAGER_FLUSH)` → `await Ou()` after `transcript_persist`). Profile env stays **unchanged**.
- **Model proxy (`ANTHROPIC_BASE_URL` / `ANTHROPIC_API_KEY`):** unchanged. Without `providers/set` (`resolveProviderConfig()` null), `createEnvForProvider` returns `{}` and ambient env reaches the CLI. The adapter now also advertises `providers` (like codex-acp), but the env path still works, so `authentication: environment` stays.
- **`sessionState` (`.claude`, `.claude.json`):** unchanged. Resume still reads `$CLAUDE_CONFIG_DIR` or `~/.claude`, under `projects/<dir>/<id>.jsonl` (`paths.js:5`, `resumed-session.js:84-93`).
- **Permissions:** unchanged. `requestPermission` is still the ACP v1 shape, and the driver answers it under `sandbox-auto-approve`. The old `IS_SANDBOX` env read is gone (we run as uid 10001, so it was never used).
- **Protocol version:** the adapter still answers `protocolVersion: 1` (`acp-agent.js:1413`). SDK 2.0.0's root export is still the v1 stable API, and v2 lives only under `experimental/v2`, so the driver bump stays on v1.
- **New `session/update` kinds** (0.16.2 emitted only agent message/thought chunks, `plan`, `tool_call[_update]`, `available_commands_update`, `current_mode_update`): `usage_update`, `session_info_update`, `config_option_update`, `compaction_update`, `compaction_summary_chunk`, `notice`, `plan_update`, `session_message`, `subagent_spawned`, `subagent_update`, `subagent_state_update`, `async_task_spawned`, `async_task_progress`, `async_task_state_update`. Most of the subagent and async-task kinds are behind AIR/experimental client capabilities that the driver does not advertise. The driver's `acp-map.ts` default branch already forwards unknown kinds as `data-acp-<kebab>`, so none are dropped. Typed mapping for the user-visible ones is t003 scope.
- **Removed kinds:** none.
