## Progress (2026-10-22): real-model harness leg done

**Setup.** The real `bex-agent` image (built from this milestone's tree) ran the driver, `claude-agent-acp@0.94.0` and Claude Code against the real model `deepseek/deepseek-v4.1-flash-1017` on OpenRouter (the t016 route, user-authorized `OPENROUTER_API_KEY`). A local harness under `/tmp/m13h` stood in for the gateway, outside the repo:

- a model proxy injecting the Bearer key and dropping the placeholder `x-api-key`;
- a real Git smart-HTTP origin (`git http-backend`) with a seed repo whose `CLAUDE.md` says "only commit or open pull requests when the user explicitly asks" and which has a `.github/pull_request_template.md`;
- a stub of the `pull-request` verb (head pin, `branch_not_pushed`/`not_ahead`, idempotent `<!-- bex-agent-footer -->` footer).

**Turn 1 (slugify).**

- The agent read the template, edited code, tests and README, and ran `npm test`.
- It committed `feat: add slugify string helper` as `bex agent <agent@bex.co>`, pushed `bex-agent/live`, and called `mcp__bex__open_or_update_draft_pr`.
- The PR body filled the template's Summary/Changes/Testing sections and ended with the footer exactly once.
- Status: `git{dirty:false, unpushedCommits:0, prRecorded:true, undelivered:[]}`.
- The transcript shows the agent explicitly reasoning that the overlay's authorization clause outranks the repo's "only commit when asked" rule.

**Steering turns 2 and 4 (truncate, reverse; fresh sandbox, same branch).**

- Each added a commit and updated the same PR #1, with no second PR.
- Two defects surfaced, both fixed and re-verified in this milestone:
  - **Earlier PR unknown to a re-dispatched sandbox.** The fresh sandbox did not know the earlier PR existed, which would also false-nudge a no-code turn. Fix: bex-api `driverEnv` passes `BEX_AGENT_PR_URL`/`BEX_AGENT_PR_NUMBER`, the overlay names the PR, and the delivery check counts it.
  - **Body described only the latest turn.** Fix: the overlay and the tool description say the body replaces the old one and covers every commit since the base. After the fix, the turn-4 PR was titled "feat: add slugify, truncate and reverse string helpers", with a body covering all three commits.

**Turn 3 (question only).** No commit, no PR call, no nudge; the head was unchanged.

**Harness-only artifact.** "Dubious ownership" on the bind-mounted `/workspace` (host uid ≠ container uid). The agent recovered with `safe.directory`. A real sandbox clones as the same uid the agent runs as.
