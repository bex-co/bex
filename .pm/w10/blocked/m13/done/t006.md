## Objective

The turn ends when the agent ends it. The driver only observes Git state, and if work is left undelivered it asks the agent once to finish. It never commits for the agent.

## Context

- `session.ts:311-346`: stop provider → scrub → `deliverBranch` → `extractEvidence` → status `{delivery, evidence, scrubbedFiles}`. Live `POST /turn` turns share `runHeadlessTurn` (`main.ts:59`).
- `delivery.ts`:
  - delete `deliverBranch` 347-489, `commitMessage` 336-342, `scanBranchObjects` 494-552, and `captureDeliveryBaseline` 194-215 if nothing else needs it;
  - keep `ensureRepo`, `restoreWorkspace`, `cloneWithRetry`, `cleanDirectory`, `withGitAuthRetry`.

## Steps

1. Before the provider stops, compute the delivery facts with read-only Git: dirty tree, local commits not on `origin/<branch>`, the remote head (`ls-remote`), and whether a PR was recorded (the MCP tool's last result, written to a driver-owned file outside the repo).
2. If there are uncommitted changes, unpushed commits, or pushed commits with no PR, send **one** follow-up prompt on the same ACP session. Wording: "Your changes are not fully delivered: <facts>. Commit, push and open/update the draft PR, or explain why not." Bound it by the remaining turn budget.
3. Stop the provider; write status `{state, git:{dirty, unpushed, remoteHead, prRecorded}}`. Remove `delivery`/`evidence`/`scrubbedFiles` (consumer changes are t007/t008).
4. Remove the `BEX_AGENT_DELIVER` "deliver" mode switch if setup-clone is now keyed only on `BEX_AGENT_REPO_URL`/`BRANCH`. Update `driverEnv` (`agentsessions/service.go:1331-1335`) to match.
