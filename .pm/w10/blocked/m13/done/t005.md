## Objective

Expose the PR verb to every engine as a first-class tool rather than a curl recipe in the prompt.

## Context

- ACP requires every agent to support stdio MCP servers in `session/new.mcpServers`; HTTP/SSE MCP is optional. The driver sends `mcpServers: []` today (`acp.ts:410-434`).
- Tool shape is modeled on the GitHub MCP server's `create_pull_request` / `update_pull_request` and Open SWE's `open_pull_request`. Owner, repo, head and base are server-filled, so the agent cannot name them.

## Steps

1. Add `driver/src/mcp-bex.ts`, built to `dist/`, using `@modelcontextprotocol/sdk` stdio at an exact pin. It has one tool, `open_or_update_draft_pr({title, body})`. The description says when to use it (after pushing), that it is idempotent, that the footer is added automatically, and to report its errors rather than work around them.
2. The tool calls the t004 gateway endpoint over the Pod network. It needs no secret, because the source IP is the credential. It returns the structured result verbatim.
3. Register it in `session/new` and `session/load` as `{name:"bex", command:"node", args:[".../mcp-bex.js"], env:[...]}`, passing only the gateway URL + bound path.
4. Make `gh` absence explicit: confirm it is not installed in the image, and do not install it. The overlay (t002) already points at the tool. For Claude, add `disallowedTools` for `Bash(gh pr create:*)` if `gh` ever ships.
