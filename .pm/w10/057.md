# 057 — An agent session's page has no Terminal, while Devin's Terminal tab opens on a sleeping session and wakes it

Why: since w10/m597 a closed session wakes when `ssh` or Zed connects, but someone without a local terminal or a registered SSH key has no way to get a shell from the dashboard, where Devin's "opening Files or Terminal wakes Devin" ([release notes](https://docs.devin.ai/release-notes/2026), 2026-10-05, read 2026-11-23). Found by w10/m597 t007's Devin walk, 2026-11-23. Severity: minor (Devin parity). Surface: `dashboard/src/features/agent-sessions/components/session-detail-header.tsx`, the gateway's Web Shell (`lego/backend/cmd/ssh-gateway/main.go`, `webShell.Apps` resolves only `srv-…` services), ADR047 D8 (live attach, phase 2).

## Current state

- A session's header offers Files (its attachments, which need no sandbox and open on a closed session, as Devin's Files tab does) and Connect (`zed://` and the `ssh` command). There is no in-browser terminal: the Web Shell serves services only (w10/027, w10/032 used `ssh` in its place).
- The wake runs in the gateway's SSH handshake (ADR054 D9), so a browser terminal over the same gateway could reuse `Service.Resume` and the held wait.

## End state

A session's page has a Terminal that opens a shell in its sandbox, as a service's Web Shell does. Opening it on a session whose sandbox closed starts the sandbox, says so while it starts, and opens the shell once it is up, as Devin's Terminal tab does. Canceled and archived sessions say why there is none. The decision on where it lives (a tab, a sheet, the Connect menu) follows Devin's session workspace and is recorded in ADR047 or ADR054.
