## Objective

Settle the contract the other tasks build on. Choose the option that matches Devin's two modes, "Allow all models" and "Allowlist specific models" ([Devin CLI Team Settings](https://docs.devin.ai/cli/enterprise/team-settings)), and its stored-UID matching rule ([List Models](https://docs.devin.ai/desktop/accounts/api-reference/list-models)). Record the contract in the milestone README's design record, and amend ADR047 D7's w10/m527 amendment, ADR090 § Model pin ("A workspace narrows the catalog") and the ADR018 agent-model row.

## Context

- Today the list is the opt-out `agent_environments.disabled_models text[] NOT NULL DEFAULT '{}'` (migration 0315). `modelOfferPatch` (`lego/backend/internal/agentsessions/environment.go:585`) writes `catalog − enabledModels`. `leftOn` (`:853`) offers `catalog − disabled`, always keeping `catalog[0]`.
- The catalog is `agentsession.PlatformModels` (`lego/backend/internal/agentsession/devroute.go:356`), read from `BEX_AGENT_PLATFORM_MODEL` + `BEX_AGENT_PLATFORM_MODELS` at startup. It is empty on a workspace's own key, and the list then has no effect.
- To label a model "new in the catalog", the store must tell a model the admins turned off apart from one they never saw. An allowlist alone cannot. An allowlist plus `disabled_models`, or `disabled_models` plus the catalog at the write, can.
- Migrations cannot read the catalog, which is an environment variable. bex-api has one-shot startup backfills (`backfillModelKeyFlags`, `backfillMachineMemberships` in `lego/backend/cmd/api/main.go`).
- The catalog has not changed since `1988962c01` (2026-11-19), before the list shipped. Converting a legacy narrowed row with the catalog bex-api starts with keeps its offer.

## Steps

1. **Storage.**
   - Proposal: a nullable `enabled_models text[]`, the allowlist as Devin stores UIDs. `NULL` allows every model, and a non-null value is the allowlist.
   - Keep `disabled_models` as the models an admin turned off, so `catalog − enabled − disabled` are the new ones. Weigh this against `known_models`, the catalog at the write.
   - Keep the 64-entry cap.
2. **When a workspace allows every model.**
   - The note's floor: a write leaving no model off returns the workspace to "allow all".
   - Decide whether to add an explicit mode, so an admin can keep an allowlist that happens to list every current model, as Devin's "Allowlist specific models" can. Examples: `allModels` on the input, or `bex agent env set --models all`.
   - If you add it, name it on every surface. If not, record why the implicit rule is enough.
3. **The read.**
   - Name the field that lists catalog models off because the list predates them. Proposal: `newModels`, on REST, GraphQL `AgentEnvironment` and MCP.
   - It is always `[]` off the route and in "allow all".
   - `enabledModels` stays the effective offered list.
4. **Legacy rows and the rollout.**
   - A row written under 0315 with a non-empty `disabled_models` and no allowlist converts once, at startup, to `catalog − disabled`.
   - Until it is converted, and for any row a previous-release Pod writes during the rollout, the new code reads it as the opt-out did. Name that rule.
   - Decide whether new writes also keep `disabled_models` exact, so previous-release Pods read them correctly.
5. **Unchanged:**
   - the catalog default always on (`leftOn`'s `i == 0`);
   - `AGENT_ENVIRONMENT_MODELS_INVALID`;
   - the next-turn fallback;
   - `retiredTemplateModel`'s note, which says "turned off in this workspace" for a new model too.
6. Write the design record. Amend the three ADRs: Devin's matching rule replaces "a model added to the catalog later starts on", and the w10/036 divergence is closed.
