# 032 — Maven and Gradle reach nothing on a `full`-tier session, because the JVM ignores `HTTPS_PROXY`

Why: since w10/024 every session has JDK 17, but a `full`-tier session's only route out is the gateway egress proxy, which bex announces only through `HTTPS_PROXY`/`HTTP_PROXY`, and Java reads neither, so `mvn` and `./gradlew` cannot download a dependency or the Gradle wrapper there, while Devin's base image builds Java projects out of the box. Found by w10/024's worker (its "Not done here"), 2026-11-19. Severity: minor (Devin parity). Surface: `lego/backend/internal/agentsessions/service.go` (`withNetworkEnv`), the driver's run env, `lego/agent-image/`.

## Current state (2026-11-19, `aef913d70`)

- A full-tier sandbox resolves only the gateway's name, and its traffic leaves through the egress proxy ([ADR047 § full tier amendment w10/m19](../../docs/ADR047-cloud-coding-agent-sessions.md)). `withNetworkEnv` sets `HTTPS_PROXY`/`HTTP_PROXY` in both spellings and `NO_PROXY` (`service.go:2014`) to `http://<ns>:<session>@bex-ssh-gateway.bex-system.svc.cluster.local:8085`, the userinfo being the base64url session claim sent as `Proxy-Authorization: Basic` (`agentsession/egress.go:58`).
- The JVM takes a proxy only from system properties (`https.proxyHost`, `https.proxyPort`, `http.nonProxyHosts`). Maven reads `<proxies>` in `~/.m2/settings.xml`, and Gradle reads `systemProp.https.proxy*` from `gradle.properties`. The JDK also refuses Basic authentication on a CONNECT tunnel unless `jdk.http.auth.tunneling.disabledSchemes` is cleared, so the session claim must get through as well.
- On `registries` and `custom` the catalog's Maven and Gradle hosts (`repo.maven.apache.org`, `services.gradle.org`, `plugins.gradle.org`, `plugins-artifacts.gradle.org`; `sessionegress/policy.go`) are reached directly, so those tiers are not affected.

## End state

- On a `full`-tier session, `mvn -q dependency:resolve` on a small project with one Maven Central dependency and `./gradlew help` (the wrapper downloads Gradle from `services.gradle.org`) both succeed through the egress proxy with the session claim. A model-provider host is still refused through it, and the gateway and loopback (`NO_PROXY`) stay direct.
- Nothing changes on `registries` or `custom`, and a repository's own `MAVEN_OPTS`, `JAVA_TOOL_OPTIONS`, `settings.xml` or `gradle.properties` still applies (added to, never replaced).
- The overlay's network line and ADR047's full-tier amendment say how Java tools reach the proxy.
