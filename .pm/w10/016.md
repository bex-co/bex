# 016 — A turn is killed after 30 minutes without agent output even while a tool command is still running

Why: a long but healthy check (the beancount-io dashboard `yarn test` takes ~30 min) ends the turn as failed, and with [013](013.md) everything not yet pushed is lost. Severity: major in combination with 013. Surface: agent runtime (ACP turn watchdog).

## Evidence (production, 2026-11-18)

`ags-dbutgej906ns73ff3kb0` (`beancount-rt-flaky-test-fixer`): the agent reproduced the bug, verified a fix 20/20, started the full dashboard suite before committing, and the turn failed with `ACP turn made no progress for 1800000ms`. The fix was lost. Worked around by a prompt rule in the beancount-io automations ("commit and push before any long suite; run it in the background with progress"); the re-run `ags-dbuuuus9rejs73fsjhlg` delivered beancount-io#216.

## Direction

Count a running tool command's output (or a periodic heartbeat from a live child process) as progress, and raise or make configurable the idle limit for automation templates; before failing a turn on the watchdog, snapshot unpushed work (013).
