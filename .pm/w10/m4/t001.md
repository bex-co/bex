## Objective

Tighten `KratosIdentities.Lookup`'s `mfaEnabled` derivation so a webauthn credentials entry counts only when it contains actually-registered keys — Kratos mints a stub (`config.user_handle` only) at password registration because webauthn is an enabled method with `identifier: true`, so today a password-only user reports `mfaEnabled: true`.

## Context

- `lego/backend/internal/workspaces/kratos.go` — derivation is presence-based over the `totp`/`webauthn` credentials map (w6/m10).
- Verified live against dev-4 by w4/m25 (see `.pm/w4/done/020.md`).
- Proposal from the note: webauthn counts only when `config.credentials` is a non-empty list; totp stays presence-based (Kratos only writes it on enrollment).
- Pre-existing behavior, not introduced by m25; scope is one function + tests.

## Steps

1. Inspect the credential's `config.credentials` contents in the lookup; keep totp presence-based.
2. Unit tests per shape: stub-only webauthn ⇒ false, enrolled key ⇒ true, totp ⇒ true, both ⇒ true.
