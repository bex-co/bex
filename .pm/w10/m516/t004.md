## Objective

Make the model that will run visible before a session starts: every offered agent in the capabilities read carries its effective model and the models a person can pick, and `bex agent models` prints them.

## Context

- Capabilities: `AgentProfile` (`lego/backend/internal/agentsessions/models.go:122`) has `id`, `label`, `modelKeyReady`; built in `service.go` (`Capabilities`, around line 1140); GraphQL in `graphql.go:93`; MCP and REST serve the same struct.
- CLI: `modelsCommand` and `writeCapabilities` (`lego/cli/internal/agent/config.go:506`), test in `lifecycle_test.go:420`.
- Fixed-model profiles: `muse` (`muse-spark-1.3-contributor`), `deepseek` (`~deepseek/deepseek-flash-latest`). A workspace on its own key can name any model its provider serves.

## Steps

1. Add `model` (the effective default: the workspace default, else the catalog or profile default) and `models` (the catalog for the claude profile on the platform route, the one fixed model for `muse`/`deepseek`, empty for a workspace's own key, meaning any) to each capabilities agent, on REST, GraphQL and MCP alike.
2. `bex agent models` prints the model column and the choices (text), and `-o json` returns the API's own fields; `--help` says how to pick one (`bex agent run --model`, `bex agent env set --default-model`).
3. Update the CLI README or help text where it lists `bex agent` commands.
