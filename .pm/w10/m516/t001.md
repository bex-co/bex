## Objective

Settle how a person chooses the claude profile's model on the platform route, and record it in the ADRs before code changes: where the catalog comes from, which models start in it, how a session's choice reaches the mint and the sandbox, how a message switches it, and which typed errors refuse a model outside it.

## Context

- Today one model per workspace: `PlatformPinnedModel` (`lego/backend/internal/agentsession/devroute.go:311`), `sessionModel` (`lego/backend/internal/agentsessions/environment.go:649`), the mint's `PinnedModel: route.model` (`agentsession/model.go:402`), `ModelRouteEnv` (`devroute.go:344`). The route model is `BEX_AGENT_PLATFORM_MODEL` (`lego/backend/cmd/api/config.go:935`, default `deepseek/deepseek-v4.1-flash-1017`).
- Pricing is model-agnostic: OpenRouter's reported cost × 1.3, with the `/api/v1/models` price table as the fallback (ADR091 D1-D2), so a catalog model needs no price row.
- The gateway merges `"provider":{"data_collection":"deny"}` into every platform request (`sshgateway/modelproxy/usage.go:43`); a catalog model must still be served under it.
- The reference is Devin's agent selector: chosen at start, switched mid-session from the next message, an organization default, admins limiting the choices ([Your First Session](https://docs.devin.ai/get-started/first-run), [Create Session `devin_mode`](https://docs.devin.ai/api-reference/v3/sessions/post-organizations-sessions)).
- Profiles with one fixed model keep it: `muse` (release-locked, ADR108 D4) and `deepseek` (platform-only, ADR114).

## Steps

1. Decide the catalog's shape and source: an env list next to `BEX_AGENT_PLATFORM_MODEL` (for example `BEX_AGENT_PLATFORM_MODELS`, OpenRouter ids with a display label each), its order (the default first) and whether Anthropic-style ids such as `claude-opus-5-5` resolve to their OpenRouter id as aliases.
2. Pick the initial models (the current default, plus at least one stronger Claude model and one cheaper option if OpenRouter offers it), and probe each live on `https://openrouter.ai/api/v1/messages` with `provider.data_collection: deny` and a tool-use request, with the platform key (never logged). Drop any model that fails.
3. Decide the error vocabulary: the typed 400 for a model outside the catalog (code, params with the offered models) on create, steer, automations and the workspace default; whether `AGENT_SESSION_MODEL_PINNED` stays for the fixed-model profiles.
4. Decide the switch on a message: a `model` on the steer and queued-message inputs, stored on the session before its next turn; how the driver picks it up (a fresh process reads `ANTHROPIC_MODEL`; a reused sandbox needs the ACP model-selection call claude-agent-acp supports, or a restart of the agent process). Check what the pinned claude-agent-acp version supports.
5. Amend ADR090 § Model pin (per-session pin within the catalog; the live probe of step 2), ADR047 (session and automation model choice, the switch), ADR091 (D1 unchanged; a stronger model costs more and the D5 caps bound it), and the env inventory in `lego/backend/AGENTS.md`.
