## Objective

Replace the one-model-per-workspace pin with a per-session pin inside the catalog t001 defined: create, automations and the workspace default accept any catalog model, the session records it, the sandbox env carries it, and the mint pins it so the gateway refuses every other request model.

## Context

- `lego/backend/internal/agentsession/devroute.go`: the route config (`routeModel`, `PlatformPinnedModel`, `ModelRouteEnv`).
- `lego/backend/internal/agentsession/model.go`: `Mint` returns `PinnedModel: route.model` for the platform route; it already decodes the session's stored model (`decodeModelConfig`).
- `lego/backend/internal/agentsessions/environment.go`: `sessionModel`, the `defaultModel` validation (`AGENT_ENVIRONMENT_MODEL_PINNED`), `environmentView` (`modelPinned`, `pinnedModel`).
- `lego/backend/internal/agentsessions/service.go`: `resolveCreateModel` (create and automations), the sandbox env (`ANTHROPIC_MODEL` and `ModelRouteEnv`, around line 1905).
- `lego/backend/cmd/api/config.go`: `BEX_AGENT_PLATFORM_MODEL`; the new catalog setting, mirrored in `.env.example` only if it is a secret-free deploy value the repo already tracks there, and in `deploy/gitops` values if production sets it.
- The gateway (`sshgateway/modelproxy`) pins whatever the mint returns, so it needs no change; its usage report already carries the pinned model.

## Steps

1. Load the catalog at startup (t001's shape), refusing an empty or malformed list loudly; the default model is its first entry.
2. `sessionModel`: on the platform route, an explicit catalog model (or alias) records its OpenRouter id; another is refused with t001's typed 400 listing the offered models; no model takes the workspace default, else the catalog default. A steer keeps the stored model when it is still in the catalog, else falls back to the default (a model removed from the catalog never strands a session).
3. The workspace default (`PATCH /v1/agent-environment` and its GraphQL/MCP twins) accepts a catalog model on a platform-route workspace and refuses others; the environment view reports the effective default and the catalog instead of a single `pinnedModel` (keep the old fields for compatibility, as t001 decides).
4. The mint pins the session's stored model when it is in the catalog, else the default; `ModelRouteEnv` takes the session's model.
5. Automations: create, update and `apply` resolve through the same path; a run whose stored model left the catalog runs the default and says so in its run record.

## Acceptance criteria

- [ ] On a platform-route workspace, a create naming a catalog model records it, its sandbox env carries it in all four `ANTHROPIC_*` names, and its mint returns it as `pinnedModel`.
- [ ] A create, automation or default naming a non-catalog model gets the typed 400 with the offered models.
- [ ] The gateway's end-to-end test still refuses a request model other than the session's.
- [ ] `cd lego/backend && go test ./...` and `make lint` pass.
