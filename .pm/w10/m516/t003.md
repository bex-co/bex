## Objective

Let a person switch a running session's model the way Devin's agent toggle does: a message names a catalog model, the session stores it, and its next turn runs on it. Without a model, a message keeps the session's model.

## Context

- `SteerRequest` (`lego/backend/internal/agentsessions/models.go:228`) has no model today; queued messages are delivered by the dispatcher (`queuedMessageID`).
- REST, GraphQL and MCP each expose the steer/send-message verb; the CLI sends messages with `bex agent send` and `bex agent chat` (`lego/cli/internal/agent/{agent.go,chat.go}`).
- How the driver picks the new model up is t001's decision (a fresh agent process reads `ANTHROPIC_MODEL`; a reused one needs the ACP model call or a restart). The driver lives in `lego/agent-image/driver/src/`.

## Steps

1. Add an optional `model` to the steer and queued-message inputs on every surface; validate it with t002's resolution (catalog on the platform route, any model on the workspace's own key, refused for fixed-model profiles).
2. Store it on the session's `agentConfig.model` when the turn that carries it starts (a queued message switches only when it is delivered), so the session read reports the model of the current turn.
3. Make the next turn run it: the mint pins the new model and the sandbox's agent runs it, by t001's mechanism.
4. `bex agent send --model` and a `bex agent chat` follow-up pass it through.

## Files

- `lego/backend/internal/agentsessions/{models.go,service.go,rest.go,graphql.go,mcp.go}`, `lego/agent-image/driver/src/` if t001 needs it, `lego/cli/internal/agent/`

## Acceptance criteria

- [ ] A message with a different catalog model makes the next turn's mint pin it and its model requests use it; the session read reports it.
- [ ] A message without a model keeps the session's model; a non-catalog model is refused with t002's typed 400.
- [ ] `cd lego/backend && go test ./...`, `cd lego/cli && go test ./...` and the driver's tests pass.
