# w10 · m615 — An agent session's page has a Terminal that opens a shell in its sandbox and wakes a closed one, as Devin's Terminal tab does

**Worker:** worker10 **Goal:** a member who may operate an agent session gets a shell in its sandbox from the session's page, with no local terminal and no registered SSH key, the way a service's Web Shell works. Opening it on a session whose sandbox closed starts the sandbox, says so while it starts, and opens the shell once it is up, as Devin's Terminal tab does ("opening Files or Terminal wakes Devin"). Canceled and archived sessions say why there is no Terminal. **Status:** done (2026-11-24: every task done; t006's live Terminal woke a closed session in `tian-personal` on production at 1280 px and 390 px)

## Design record (t001)

Decided 2026-11-23 against `c620e080ee`; every choice follows Devin's "The session workspace has a new Terminal tab for running commands on Devin's machine." and "opening Files or Terminal wakes Devin" ([release notes](https://docs.devin.ai/release-notes/2026), 2026-10-05, re-read 2026-11-23), with the workspace pane starting closed (2026-11-13). Recorded in [ADR054 D10](../../../../docs/ADR054-open-in-zed.md#d10--the-session-pages-terminal-wakes-a-closed-session-w10m615-2026-11-23), D6 and D7 item 4's amendments, and [ADR035 § A second target](../../../../docs/ADR035-ssh.md#a-second-target-an-agent-sessions-sandbox-w10m615). [ADR018](../../../../docs/ADR018-render-parity.md) is unchanged: no choice diverges from Devin.

1. **Placement: a sheet.** A **Terminal** button beside Files in the session header opens a right-side sheet (768 px on a desktop, the full width on a phone), as Files does (ADR095 D10). Below 640 px the header row has no room for another button beside Files, Connect, Stop and Cancel (a running session's row overflowed by 23 px at 390 px in the scratch check), so the header's "…" menu opens the same sheet there: the session page is one conversation, and the sheet is its side pane. It starts closed on every visit and closing it ends the shell. Remembering per session whether the pane was open belongs to a Devin-style workspace pane, out of scope.
2. **The ticket.** `shellticket.Claims` gains `SessionID` (`ags`), exclusive with `ServiceID`/`InstanceID`; same secret, MAC domain, 90 s lifetime and cross-replica single-use nonce. A key's ticket names `sandboxes.exec`. The gateway routes by the field, not the id's prefix.
3. **The wake: bex-api at the mint**, through `Service.Resume` as the caller (no new gateway verb). The mint answers `sandbox: up` or `starting`; the gateway holds the WebSocket and tells the browser (`starting`, then `ready`).
4. **The wait.** Poll every 2 s with the subject's own resolution and the key's grant; `starting` frames every 30 s; ceiling `agentsessions.SSHWakeTimeout` (16 min); ends with the browser, access, the grant, the 4-hour cap or the drain; holds a session-limiter slot. Endings: `no_sandbox`, `wake_timeout`, `revoked`, `timeout`, `unverified`, or the resolver's message on a cancel or archive. **Reconnect** mints again, which starts it again. An open Terminal keeps the sandbox from the idle close, as an editor's SSH login does.
5. **Surfaces.** REST `POST /v1/agent-sessions/{id}/shell-ticket` and GraphQL `createAgentSessionShellSession`, as the service mint (no MCP). Scope `sensitive`; key permission `sandboxes.exec`, plus `agents.manage` to start a closed sandbox. Capabilities gain `terminalEnabled` on REST, GraphQL and MCP; the session view is unchanged (the Terminal applies where `sshAddress` does).
6. **Refusals.** A closed sandbox the caller may view but not start: D9's banner (`409 AGENT_SESSION_NOT_ATTACHABLE`, `sandbox: closed`). Admission: `Resume`'s own code. Canceled, archived: their banners, and the dashboard's own words without a mint. Not viewable or missing: the same `403`. Unconfigured: `503 SHELL_UNAVAILABLE`.

## Definition of done

1. **A Terminal on the session page.** A session that is neither canceled nor archived offers a Terminal on its page, placed where t001 decided after Devin's session workspace. Opening it on a session whose sandbox is up opens a shell in that sandbox (`/workspace`, the sandbox's user), over the gateway's Web Shell WebSocket with a short-lived ticket, as a service's Web Shell does. The private SSH key never enters the browser, and bex-api never gains `pods/exec`.
2. **A closed session wakes.** Opening it on a `completed` or `failed`, unarchived session whose sandbox closed, by a caller who may operate it and holds a fresh `can_create`, starts the sandbox through `Service.Resume`. The Terminal says the sandbox is starting, keeps saying so while it starts, and opens the shell once the session settles with a sandbox. Opening it on a session already starting waits for that start. Two tabs opening it start one sandbox.
3. **Refusals say why.** A caller who may view but not start the session, a bex API key whose grant does not cover it, and a workspace admission refusal (payment method, billing, the live-sandbox cap) each get a message saying why, as the SSH path's banners do (ADR054 D9). Canceled and archived sessions say why there is no Terminal. A caller who may not view the session gets the same answer as for a missing session. A start that ends without a sandbox says so and offers to try again.
4. **Bounded.** The ticket is single-use and short-lived, the WebSocket re-authorizes on the gateway's revalidation interval, the wait ends at the start's own ceiling (`agentsessions.SSHWakeTimeout`), with the browser or with a drain, and holds a session-limiter slot as an open shell does. The gateway counts the Terminal's wakes and their outcomes with no session, workspace or subject label.
5. **Recorded.** t001's placement and wake design are in ADR047 or ADR054, ADR035 § Browser Web Shell names the second target kind, `lego/backend/AGENTS.md` lists any new env var, and a security review covers the ticket and the held WebSocket as ADR124 covered the SSH wake.
6. **Live.** On production, in `tian-personal`, the Terminal on a session whose sandbox closed starts it and opens a shell, at 1280 px and 390 px, and the session is deleted afterwards.
