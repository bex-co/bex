## Objective

The gateway's Web Shell accepts t002's agent-session ticket, resolves it through the agent-session resolver (re-authorizing itself, never trusting bex-api's decision), and bridges the browser to a shell in the sandbox. When the sandbox is still starting, it holds the WebSocket, tells the browser so on the cadence t001 chose, and opens the shell once the session settles with a sandbox. The `srv-…` path stays byte-identical.

## Context

- `webshell.Server` (`lego/backend/internal/sshgateway/webshell/websocket.go`): `serveWebSocket` (`:236`) verifies the ticket and consumes its nonce, `runWebSocketSession` (`:283`) resolves `claims.Username()` through `Apps`, checks the key grant, takes a limiter slot, writes the audit row and starts the exec with its revalidator (`:358`).
- Wiring: `lego/backend/cmd/ssh-gateway/main.go:297-300` passes `appService`; native SSH gets `sshgateway.CompositeResolver` (`main.go:201`, `lego/backend/internal/sshgateway/composite.go`).
- The SSH wait to reuse or share: `lego/backend/internal/sshgateway/nativessh/wake.go` (poll every 2 s with the login's own resolver, progress every 30 s, ceiling `agentsessions.SSHWakeTimeout`, outcomes `opened`, `no_sandbox`, `timed_out`, `abandoned`).
- Audit: `sshgateway/shellaudit.go` skips sandbox targets for service shell events; the `ssh_sessions` row still records the connection.
- Metrics: `lego/backend/internal/sshgateway/metrics.go`, no identifying labels.

## Steps

1. Resolve an agent-session ticket through the agent-session resolver, keeping `srv-…` tickets on `apps.Service`.
2. A starting session: hold the WebSocket, send t001's progress, poll with the ticket subject's own re-authorization until it settles or the ceiling passes, then bridge as today; a start that ends without a sandbox sends why and closes with t001's code.
3. Limits, revalidation, drain and the metrics for the Terminal's wakes and outcomes; `main.go` wiring and any env var in `lego/backend/AGENTS.md`.
4. Gateway tests over the real resolver: a live sandbox opens, a starting one waits then opens, the ceiling, a start with no sandbox, the browser closing mid-wait, a drain mid-wait, access revoked mid-wait, a replayed ticket, and a `srv-…` ticket unchanged.
