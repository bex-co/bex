## Objective

Settle every open choice before code, each one the option that matches Devin's session workspace, and record it in the milestone README's design record and in the ADRs.

## Context

- Devin: "The session workspace has a new Terminal tab for running commands on Devin's machine." and "opening Files or Terminal wakes Devin" (2026-10-05); the workspace pane starts closed and remembers per session whether it was open (2026-11-13); the Progress and Shell tabs merged into an Activity view (2026-10-26) ([release notes](https://docs.devin.ai/release-notes/2026), read 2026-11-23). Re-read them, and Devin's docs on the session workspace, before choosing.
- bex's session page is one full-page conversation; Files lives in a sheet for that reason ([ADR095 D10](../../../../../docs/ADR095-agent-attachments.md), `session-files-sheet.tsx`). The header holds Files and Connect (`session-detail-header.tsx:352-354`).
- The service Web Shell: ticket minted by `apps.Service.CreateShellSession` (`lego/backend/internal/apps/service.go:1931`) after `can_operate`, verified by `webshell.Server` (`lego/backend/internal/sshgateway/webshell/websocket.go`), which re-runs the resolver itself; [ADR035 § Browser Web Shell](../../../../../docs/ADR035-ssh.md#browser-web-shell).
- The SSH wake: [ADR054 D9](../../../../../docs/ADR054-open-in-zed.md#d9--an-ssh-login-wakes-a-closed-session-w10m597-2026-11-23). Its gateway verb re-reads an SSH key by fingerprint; a browser caller has no key, but bex-api holds the caller's identity when it mints a ticket, so it can call `Service.Resume` itself (`lego/backend/internal/agentsessions/editor.go:54`).
- Who may do what: viewing a sandbox's shell is `can_view_sensitive` on the session (ADR054 D2); starting it is `can_operate` plus a fresh `can_create` (`Service.Resume`); a bex API key needs Agents manage and Sandbox execution (ADR054 D9).

## Steps

1. Placement: a tab, a sheet, a pane, or an entry in the Connect menu, after Devin's Terminal tab and bex's one-conversation layout. Say what the narrow-mobile layout is.
2. The ticket: extend `shellticket.Claims` with an agent-session target or add a flavor; what it binds (subject, session, key action), its lifetime and single use.
3. The wake: bex-api starts a closed session as the caller when it mints the ticket (no new gateway verb), or the dashboard calls `resume` and waits; who polls for the settle and what the browser shows meanwhile (frames on the WebSocket, or the page's own phase).
4. The wait: ceiling, progress cadence, what ends it, what a start that ends without a sandbox says, and how a retry works.
5. Surfaces: whether the mint is on REST, GraphQL and MCP (the service mint is on REST and GraphQL), the scope matrix and key-permission entries, and what the session view tells a client about the Terminal being available.
6. Refusal texts for each case in the definition of done, matching ADR054 D9's banners where the case is the same.
7. Write the record: the milestone README, ADR047 or ADR054 (a new decision), ADR035 § Browser Web Shell, and `docs/ADR018/<section>.md` only if a choice diverges from Devin (none should).
