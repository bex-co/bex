## Objective

Give the blueprint detail page's Sync History table a way to show *why* a sync failed, using the `errorMessage` field t003 exposed.

## Context

- `dashboard/src/routes/blueprints.$blueprintId.tsx` (~line 437) renders each Sync History row's state with `<BlueprintStatusBadge status={run.state} />`; the row currently has no click/expand affordance and no tooltip — confirmed live: clicking an "Error" row does nothing, no message is shown anywhere.
- `dashboard/src/features/blueprints/hooks/use-blueprint-syncs.ts` is the data hook backing this table — it will need to request the new `errorMessage` field from whatever GraphQL query it runs (check `dashboard/src/features/blueprints/api/` for the `.graphql` query document backing this hook, likely needs a new field added and codegen re-run).
- Repro: blueprint `blp-d9nqg95cavls73fp8m10` (discourse_docker) — its existing failed row predates this fix and has no captured message (t002 doesn't backfill), so it will still show nothing; verify against a **freshly induced** failure instead (e.g. trigger a sync against a repo/manifest known to fail).

## Steps

1. Find the GraphQL query document feeding `use-blueprint-syncs.ts` and add `errorMessage` to its selection set; run the dashboard's GraphQL codegen so the generated types pick it up.
2. In the Sync History row (in `blueprints.$blueprintId.tsx`), when `run.state === "error"` and `run.errorMessage` is present, surface it — a `title`/tooltip on the row is the minimal fix; an expandable row or a small inline error line under the row is also acceptable if it fits the existing table layout better. Match whatever pattern this codebase already uses elsewhere for showing an error detail inline (check `dashboard/src/common/components/resource-load-error.tsx` or similar for the house style before inventing a new one).
3. When `run.state === "error"` but `run.errorMessage` is empty/null (pre-fix legacy rows), keep today's plain badge — don't render an empty tooltip or a misleading "no error" message.
4. Add the new locale string(s) needed (e.g. a label like "View error" or the tooltip's aria description) to both `dashboard/src/features/blueprints/locales/en.ts` and `zh.ts`.

## Files

- `dashboard/src/routes/blueprints.$blueprintId.tsx`

- `dashboard/src/features/blueprints/locales/en.ts`, `zh.ts`

- [ ] A freshly induced failed sync's Sync History row exposes its error message (tooltip, expand, or inline line) without navigating away from the blueprint page.
- [ ] A legacy failed row with no captured message (pre-t002) renders exactly as it does today — no empty/broken affordance.
- [ ] `yarn typecheck && yarn lint && yarn test` (dashboard) green, including a test for both the "has errorMessage" and "no errorMessage" row states.
