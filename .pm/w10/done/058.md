# 058 — `.pm/w4/README.md` is 493 KB and grows about 6 KB a day, so the markdown soft limit warns about it within days and will refuse every ship that touches it at 768 KiB

Why: the w4 index is the largest markdown file in the repository. The soft size guard w10/m607 added to `scripts/repo-artifact-guard.sh` warns at 512 KiB, which is about five days away at its pace. It refuses at 768 KiB, and from then on every `/pm` or `/loopx w4` ship that touches the file fails. The file needs trimming, not an exemption. Filed by w10/m607 t005, 2026-11-23.

## Evidence (origin/main, 2026-11-23)

- Size: 447,815 bytes on 2026-11-15 and 493,013 bytes on 2026-11-23. It is the biggest tracked `*.md`. Next come `.pm/w8/README.md` at 330,232 and `.pm/w6/README.md` at 264,267.
- What fills it: 878 `- [x]` lines (done milestones and notes, each with its closing summary) take 467,339 bytes. The 15 open `- [ ]` lines take 13,356 bytes.
- The guard: `bash scripts/repo-artifact-guard.sh` (HEAD tree, as CI runs it) and `bash scripts/repo-artifact-guard.sh origin/main` (a push's range, as `scripts/ship-gates.sh` runs it). Its warning names the file and its size.

## End state

- `.pm/w4/README.md` is well under 512 KiB, with room to grow. For example, the finished `- [x]` history moves into a file of its own that the README links, and the open items stay in the README.
- Every board tool still reads what it reads today: `python3 scripts/pm-board-validate.py`, `python3 scripts/loopx-guard.py board w4` (same open and blocked items), `bash scripts/docs-links-validate.sh`. Every link into a moved line still resolves.
- If the archive shape needs a `/pm` convention, it is written into `.claude/skills/pm/SKILL.md` and `.pm/AGENTS.md`, so `.pm/w8/README.md` and `.pm/w6/README.md` can follow the same shape when they get there.
- The soft limit is not raised, and no file is exempted from it.

## Resolution (2026-11-24)

Done. `scripts/pm-roll-closed.py w4` moved the README's 879 closed lines (878 `- [x]` and one `- [x ]` typo, m347) into [w4/done/closed-1.md](../../w4/done/closed-1.md) (261,864 bytes: Milestones, Historical execution order and the start of Inbox) and [w4/done/closed-2.md](../../w4/done/closed-2.md) (203,167 bytes: the rest of Inbox). Their links are rewritten for `done/`, and the README lists both under a new `## Closed items`. `.pm/w4/README.md` went from 493,013 to 24,619 bytes. Its 15 open lines and their parked lines are byte-identical (`pm_gates.parked_lines` before and after), and `python3 scripts/loopx-guard.py board w4` lists the same 15 parked items. A line-by-line check found every original line in the README or, after undoing the link rewrite, in an archive file. `bash scripts/docs-links-validate.sh` now also checks `wN/done/closed-K.md` and passes. `python3 scripts/pm-board-validate.py` passes.

The convention ("A workstream README holds open work; its closed lines roll into `done/`": roll at 384 KiB, parts under 256 KiB, never appended to) is in `.claude/skills/pm/SKILL.md` and `.pm/AGENTS.md`, so w8 (330 KB) and w6 (267 KB) can run the same command. `scripts/repo-artifact-guard.sh` names the command when it warns about a workstream README. Its limits are unchanged, and no file is exempted. Tests: `scripts/test_pm_roll_closed.py` (in `references.yml`), plus new cases in `scripts/docs-links-validate.test.sh` and `scripts/repo-artifact-guard.test.sh`.
