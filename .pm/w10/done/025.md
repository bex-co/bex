# 025 — `gh` cannot write in a session, while Devin's `gh` token can

Why: Devin's agent can comment, re-run a workflow or edit a pull request with `gh`; a bex session's `gh` only reads (w10/m513), so those actions need the `bex` tools or cannot be done at all (re-running CI, labelling, a review reply). Found by the w10/m513 Devin comparison (t007). Severity: minor (Devin parity). Surface: the gateway `github-api` route (`lego/backend/internal/sshgateway/agentcred/githubapi.go`), ADR090 D4.

## Reference

"Devin's machine can carry a GitHub CLI (`gh`) token that lets Devin use GitHub features directly through the GitHub API", and a profile may keep it only if it "grants Full git access" ([Security profiles](https://docs.devin.ai/product-guides/security-profiles), read 2026-11-19).

## Current state (2026-11-19)

The route refuses every method but `GET`/`HEAD` and every GraphQL mutation, with a message naming `open_or_update_draft_pr` and `reply_on_pull_request` (ADR090 D4 amendment w10/m513). ADR090 keeps one pull-request path on purpose: a `gh pr create` would bypass the draft state, the footer and the session's PR record.

## Open question (for the user, not a gate on parity reads)

Which writes, if any, `gh` may make: for example re-running a failed workflow (`POST …/actions/runs/{id}/rerun-failed-jobs`, needs `actions: write`) and commenting on the session's own pull request, while `gh pr create`/`edit` stay with the `bex` tools so the PR record stays right.

## End state

The decided writes succeed for the session's repository through the route with a narrowed token, every other write is still refused naming the `bex` tools, and ADR090 records the decision.

## Promoted (2026-11-19)

- Promoted to milestone **w10/m522** ([README](../m522/README.md)) by `/loopx w10`. The work needs a write token and its own internal mint verb, a write policy for REST and GraphQL in the gateway route, the overlay, three ADR amendments and a live check. That is more than one sitting.
- Triage on `aef913d70` confirmed the premise. The route refuses every REST method but `GET`/`HEAD` and every GraphQL mutation (`lego/backend/internal/sshgateway/agentcred/githubapi.go:283`, `:328`), and its token is read-only (`lego/backend/internal/github/client.go:270`). `reply_on_pull_request` posts only one conversation comment on the session's own pull request. Production's App `bex-co` and all five of its installations already grant `actions`, `issues`, `pull_requests` and `statuses` write, so there is no App gate.
- The open question was settled under the Devin rule, not parked for the user. Devin's GitHub App holds Actions write "to rerun workflows", issues write and pull requests write ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-19). m522 admits those writes on the session's repository and keeps pull-request create and change with `open_or_update_draft_pr`, as the note suggested. Approvals, workflow dispatch and commit statuses are refused, each with its reason in ADR090, and its t006 files any of them that matters as its own item.
