# 060 — The session page's Files and Terminal sheets start closed on every visit, while Devin's workspace pane remembers per session whether it was open

Why: a person who works in a session's Terminal or Files, leaves the page and comes back finds them closed and opens them again, while Devin reopens the pane where they left it. w10/m615 t001 placed the Terminal in a sheet that starts closed on every visit and left per-session memory out of scope without filing it. Found by w10/m615 t007's Devin walk, 2026-11-24. Severity: minor (Devin consistency).

## Devin

"The workspace pane remembers per session whether it was open, and a session starts with it closed." ([release notes](https://docs.devin.ai/release-notes/2026), 2026-11-13, re-read 2026-11-24). Devin's pane holds Files, Terminal and the other workspace tabs ("opening Files or Terminal wakes Devin", 2026-10-05).

## bex today (pin `19638322178a`)

`SessionFilesButton` and `SessionTerminalSheet` (`dashboard/src/features/agent-sessions/components/`) keep their open state in component state (`terminalOpen` in `session-detail-header.tsx`), so a reload or a return visit starts both closed. Closing the Terminal sheet ends its shell. A session that has never been opened starts closed, as Devin's does.

## Open question to settle first

Reopening a remembered Terminal on a visit would start a closed sandbox just because the page loaded, which is metered compute. Check what Devin does when a remembered pane's active tab is Terminal on a sleeping session: whether it wakes Devin, or waits for a click. Pick the matching behavior and cite it.

## End state

Per session and per browser, the page reopens the Files or Terminal sheet that was open when the person left, and a session never opened before starts with both closed. A remembered Terminal on a closed sandbox behaves as Devin's does, per the check above. A dashboard test covers the reopen, the first-visit default and the closed-sandbox case at 1280 px and 390 px.

## Done (2026-11-24)

**Devin check (the open question).** Devin's release notes (read 2026-11-24) document waking only on an action: "opening Files or Terminal wakes Devin" (2026-10-05), opening a preview URL or SSH traffic (2026-09-25), typing in the composer (2026-09-16). A sleeping Desktop tab shows the last screenshot and offers a one-click "Wake up Devin" (2026-09-09). No note says a restored pane wakes Devin. bex follows that: a remembered Terminal never starts a closed sandbox by itself.

**What changed.** `useSessionPane` (`dashboard/src/features/agent-sessions/hooks/use-session-pane.ts`) keeps which sheet a session had open, Files or Terminal, in local storage (`bex-agent-session-panes`, the 50 sessions left most recently). It reads storage once per session per mount, after hydration, so the server and hydrating renders agree. Another tab's choice never opens or closes this tab's sheet. `session-detail-header.tsx` drives both sheets from it, and `SessionFilesButton` is now controlled. A sheet reopened from memory reaches `SessionTerminalSheet` as `restored`:

- With the sandbox up or already starting, the shell opens at once and holds the sandbox like any open Terminal.
- With the sandbox closed (a completed or failed session with no sandbox), the sheet says so and waits for **Start the sandbox**.

A Terminal opened from the button or the menu starts a closed sandbox at once, as before. ADR054 D10 _Remembered per session_ and ADR095 D10 record it. The new strings are in all eight languages.

**Tests.**

- `use-session-pane.test.ts`: the first visit, the reopen, the close, a move to another session, another tab, the 50-session cap, unreadable storage and refused writes.
- `session-terminal-sheet.test.tsx`: a restored sheet asks on a closed sandbox, opens at once on an up one, and opens once a turn brings the sandbox up. A clicked sheet starts at once.
- `session-detail-header.test.tsx`: at 1280 and 390 px, the first-visit default, the Terminal reopen (from the button at 1280 and the "…" menu at 390), the Files reopen and forget, and the closed-sandbox question. Also: one session's memory is not another's, and the page hydrates with no mismatch before the remembered sheet opens.
- With the restore removed, 7 of the header tests fail. With the closed-sandbox hold removed, 5 header and sheet tests fail.

**Browser check** (Playwright, dev server against a scratch copy of `local-bex` outside the repo that serves a session page and counts Terminal mints):

- At 1280 px on first paint, the header showed `Files@897 Terminal@984 Connect@1096 More actions@1228`, w10/059's places, with no sheet open.
- Opening the Terminal on a closed session minted once. A reload reopened the 768 px sheet with "This session's sandbox has closed. Start it to open a shell." and no mint. **Start the sandbox** minted. Escape and a reload left both sheets closed.
- At 390 px, the Terminal opened from the "…" menu on a session with a live sandbox. A reload reopened it full width (390×844) and minted at once.
- At 390 px, Files reopened after a reload. A remembered Terminal on the closed session asked without minting. No hydration error, and no sideways scroll.
