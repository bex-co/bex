# A workspace admin cannot keep an allowlist that lists every current catalog model

Why: Devin's admins choose "Allowlist specific models" or "Allow all models" as a mode, so an allowlist that happens to list every current model still leaves the next released model off; in bex turning every model on always returns the workspace to "allow all", which turns the next catalog model on.

- **Found by** w10/m568 t001 (design), 2026-11-22 ([Devin CLI Team Settings](https://docs.devin.ai/cli/enterprise/team-settings), read 2026-11-22: "Allow all models" beside "Allowlist specific models"; [List Models](https://docs.devin.ai/desktop/accounts/api-reference/list-models): "A model is allowed when its UID is listed").
- **Today:** w10/m568 ships the mode implicitly. A write leaving any catalog model off is an allowlist (`agent_environments.known_models` set), and a write turning every model on stores `known_models` NULL, "allow all" (`modelOfferPatch`, `lego/backend/internal/agentsessions/environment.go`). That is what m568's definition of done asks ("one whose admins turned every model back on" offers a model added later). An admin who wants every current model but not the next one has no way to say so.
- **Code:** `modelOfferPatch` and `leftOn` in `lego/backend/internal/agentsessions/environment.go`, the Settings → Agents model list in `dashboard/src/features/agent-environment/components/enabled-models-section.tsx`, `bex agent env set --models` in `lego/cli/internal/agent/config.go`.
- **End state:** an explicit mode on the agent environment (for example `allowAllModels: true|false` on REST, GraphQL, MCP, `bex agent env set --models all|ID,…` and an "Allow all models" switch in Settings → Agents). With it off and every model listed, a model added to the catalog later is off and read in `newModels`. With it on, `enabledModels` is the whole catalog. Tests cover both modes, the write that switches between them, and a catalog model added in each.
- Ship only if admins would miss it: re-check whether the catalog grows often enough for "every model but the next" to matter.

## Promoted (2026-11-23)

Promoted to [w10/m592](../m592/README.md) by `/loopx w10`.

- **The premise holds (`23b3c97413`).** `modelOfferPatch` stores `known_models` NULL whenever an `enabledModels` write leaves no catalog model off. `leftOn` reads that, and any row with `disabled_models` empty, as "allow all" (`lego/backend/internal/agentsessions/environment.go:679-682`, `:973`).
- **Devin's modes, confirmed again (read 2026-11-23).** [Devin CLI Team Settings](https://docs.devin.ai/cli/enterprise/team-settings) offers "Allow all models" beside "Allowlist specific models". [List Models](https://docs.devin.ai/desktop/accounts/api-reference/list-models) allows a model "when its UID is listed or it carries a listed tag".
- **Admins would miss it.** Production's catalog has not grown since 2026-11-19, and none of its 3 `agent_environments` rows is narrowed (read-only, pin `ac882b5f557f`), so nobody misses it today. ADR018 records the divergence only as filed, without the user's sign-off, so it ships. It has to land before the catalog's next model.
- **More than one sitting:** three API surfaces, the CLI, Settings → Agents and its skeleton, three ADRs and two live checks.
