## Objective

The sandbox's network posture comes from the workspace tier. The default lets agents install dependencies and run builds and tests for the whole session.

## Context

- `lego/backend/internal/sessionegress/policy.go`:
  - `registryDomains` (npm, PyPI, Go proxy, Maven, crates, RubyGems, Docker Hub…);
  - `TransitionToAgent` removes them today;
  - `modelProviderDomains` stay proxy-only.
- The cluster ValidatingAdmissionPolicy `bex-api-session-egress` is in `deploy/gitops/base/bex-api-namespace-admission.yaml`. It requires exactly 1 FQDN rule + 3 endpoint rules with exact names, and its guard strings are checked by `scripts/gitops-validate.sh`.

## Steps

1. `registries` (default): the agent phase keeps the registry catalog plus any API/custom hosts.
2. `custom`: registries plus the workspace hosts.
3. `full`: decide the mechanism within the admission policy. Exact FQDN rules can't express "any host", so either widen the VAP for a labelled `full` posture (toEntities world on 443/80 with the node/metadata deny kept) or ship `full` later behind a follow-up note. Ship `registries` and `custom` regardless.
4. Update the VAP and the gitops-validate guards consistently. Model-provider hosts are never directly reachable.
