# 019 — The workspace model pin silently runs every agent on one model, and no session or automation can choose another

Why: `bex agent models` lists "claude — Claude Code — ready", but a `claude` session runs whatever model the workspace pins, so users cannot pick a stronger model for hard work (bug hunting) and a cheaper one for routine work. Severity: moderate (product gap; Devin lets a session choose). Surface: agent environment / session create.

## Evidence (production, workspace `bex`, 2026-11-17)

- `bex agent env -o json`: `modelPinned: true`, `pinnedModel: deepseek/deepseek-v4.1-flash-1017`.
- `bex agent run --agent claude --model claude-opus-5-5 …` → `400 AGENT_SESSION_MODEL_PINNED: this workspace runs agents on the platform model; omit agentConfig.model or set it to the pinned model`.
- Without `--model`, a `claude` session's `agentConfig.model` is `deepseek/deepseek-v4.1-flash-1017`; muse sessions run `muse-spark-1.3-contributor`.
- A controlled comparison of routine runs (2026-11-17) found model quality mattered most for bug-hunting routines, which the pin makes impossible to act on.

## Direction

Show the effective model next to each agent in `bex agent models` and the dashboard composer; allow a per-automation (and per-session, when the workspace permits) model choice within the platform catalog.
