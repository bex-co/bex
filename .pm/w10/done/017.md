# 017 — `bex agent run` cannot choose the sandbox size, and its sessions run out of memory where automations do not

Why: an ad-hoc session on a large repository dies at the same work an automation finishes, and the CLI gives no way to ask for the bigger machine. Severity: moderate. Surface: `bex agent run` / session `agentConfig.template`.

## Evidence (production, 2026-11-17/18)

- `ags-dbu0pfuc1l2s739d3n4g`, `ags-dbu0pg6c1l2s739d3n6g`, `ags-dbu2l4kj705s738i859g` (`bex agent run --repo bex-co/beancount-io`, dashboard dedup task): `failed: the sandbox ran out of memory (exit 128)`.
- Their `agentConfig.template` is unset; the automations running the same routine use `template: agent-4c-8g` and completed.
- `bex agent run --help` has `--agent`, `--model`, `--max-spend`, … but no template/size flag.

## Direction

Add `--template` to `bex agent run` (and the REST/GraphQL create), defaulting to the workspace's default template; when a sandbox is OOM-killed, say which template it had and that a larger one exists.

**Done 2026-11-18.** `bex agent run`, `chat`, `handoff` and `automations create|update` take `--template` (`agentConfig.template`; `lego/cli/internal/agent/agent.go` `sessionFlags`), and session and automation details show it as `Sandbox`. REST, GraphQL and MCP already accepted the field; the create (and an automation's save) now refuses a template the platform does not register with `AGENT_SESSION_INPUT_INVALID` on `agentConfig.template` and the list of templates, instead of failing once the sandbox starts (`Service.validateTemplate`, from `sandbox.AgentSessionLifecycle.AgentTemplates`). A sandbox killed for memory names its template and the next larger one: "the sandbox ran out of memory (exit 128) on the agent template (2 CPU, 4 GB); start a new session on a larger one: agent-4c-8g (4 CPU, 8 GB), e.g. bex agent run --template agent-4c-8g" (`Completer.lostSessionSandboxReason`). A session that names none still runs on `agent`: no workspace default template exists yet. Devin also keeps an organization default and offers the choice in its composer, so both are filed as `w10/023`. Tests: `TestCreateTakesARegisteredAgentTemplateAndRefusesAnyOther`, `TestCompleterOutOfMemoryNamesTheSessionsTemplate`, `TestAgentTemplatesListTheSessionOnlyOnesSmallestFirst`, the registry test in `cmd/api`, and the CLI's `TestRunSendsTheCreateContract`, `TestAutomationTemplateFlagSetsTheSandbox` and `TestSessionTextShowsTheSandboxTemplate`; each fails with its fix reverted. Production takes it with the next deploy.
