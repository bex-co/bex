# 048 — Arming auto-merge on a taken-over stacked pull request merges only that pull request into the one below it, where Devin's stacked auto-merge lands the whole stack

Why: a `/bex` takeover session (w9/m348) may be asked to merge a person's pull request that sits in a GitHub stack; `merge_pull_request` with `auto: true` arms it without `includeStack`, so GitHub merges it into the pull request below it, while Devin Review's auto-merge on a stacked PR lands "the PR and every unmerged PR below it". Found by the w10/m577 Devin comparison (t006), 2026-11-22. Severity: minor (Devin parity, takeover sessions only: a session's own pull request targets its base branch and is never stacked). Surface: `lego/backend/internal/github/merge.go` (`EnablePullRequestAutoMerge`), ADR090 D3.

## Reference

[Devin Review](https://docs.devin.ai/work-with-devin/devin-review), read 2026-11-22: "You can enable GitHub auto-merge on a stacked PR." "When the stack is ready, GitHub lands the PR and every unmerged PR below it." GitHub's `EnablePullRequestAutoMergeInput.includeStack`: "Enable auto-merge for this pull request and any eligible pull requests below it in the stack" ([GraphQL pulls](https://docs.github.com/en/graphql/reference/pulls), read 2026-11-22).

## End state

ADR090 D3 decides whether a takeover session's `auto` arms the stack below the taken-over pull request (`includeStack: true`, with `disableAuto` disarming the stack request), and the merge verb does so, with a test of the mutation body and of a non-stacked pull request left unchanged. If the decision is not to, ADR018 records the divergence with the user's sign-off.

## Done (2026-11-23)

ADR090 D3's w10/048 amendment decides it the Devin way. `merge_pull_request({auto: true})` on a pull request in a GitHub stack sends `enablePullRequestAutoMerge` with `includeStack: true`, under the method rule of the stack's base. The pull request's own merge state, measured against the branch below it, never merges it alone. `disableAuto` disarms the stack's request with `includeStack: true`. The answer and the driver's `next` say `stack: true`, and `prAutoMerge` on a stacked pull request is the stack's request covering it.

- **Tests:** `github.TestEnablePullRequestAutoMergePinsTheHeadWithTheMethodRule` (the mutation body with `includeStack`, and the unchanged body without it), `TestDisablePullRequestAutoMergeOrLeaveTheQueue`, `TestPullRequestMergeStateReadsWhatGhReads` and `agentsession.TestPullRequestMergeAutoArmsTheStackOfAStackedPullRequest`. A pull request in no stack keeps its exact options in `TestPullRequestMergeAutoArmsAutoMergeAtTheRecordedHead`. The driver test is `merge_pull_request relays a stack's auto-merge and its undo`.
- **Checks:** the new tests fail with the fix reverted. The extended state query ran read-only against GitHub's live schema: `github/gh-stack#576` (stacked, base `main`) and a pull request in no stack.
- **Not here:** a stack merged now or queued, through `merge-async`, is [w10/053](053.md).
