## Objective

Show DoD 7 holds. On `dev-10`, a catalog that gains a model offers it to an un-narrowed workspace and not to a narrowed one. On production, the deploy leaves every workspace's offer as it was.

## Context

- `bash scripts/dev-env.sh 10 up` runs a local bex-api on `dev-10`'s ports (`.pm/w10/README.md`, Local dev environment).
- The platform catalog is `BEX_AGENT_PLATFORM_MODEL` + `BEX_AGENT_PLATFORM_MODELS`, read at startup. The route is active once `BEX_AGENT_PLATFORM_MODEL_ROUTE=openrouter` and a key are set. The capabilities read and a refused create need no model call.
- Production read-only access is the `hetzner-prod` kubectl context, or `scripts/fetch-app-kubeconfig.sh`.
- Do not change production's catalog to test this. Each catalog model must first pass ADR090 § Model pin's live probe.
- The QA workspace is `tian-personal`. Sign in with `bash scripts/qa-login.sh`.

## Steps

1. **`dev-10`.**
   - Narrow workspace A's list. Leave workspace B whole.
   - Restart bex-api with one more catalog model.
   - Read the capabilities (REST, `bex agent models`) and the environment (`bex agent env`, Settings → Agents) in both workspaces.
   - In A, create a session naming the new model; it must be refused with `AGENT_SESSION_MODEL_NOT_OFFERED`.
   - Turn the new model on in A and read again.
   - Tear the fixtures down.
2. **Production, before the deploy.**
   - Record read-only the count of rows with a narrowed list and each row's offered set, with the workspace ids hashed by `scripts/lib/public_log.py`.
3. **Production, once the pin carries the milestone.**
   - Record the same again. Every set must be unchanged.
   - `tian-personal` still offers the four catalog models and lists no new model.
4. Record both checks in the milestone README.
