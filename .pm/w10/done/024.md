# 024 — The agent image lacks the runtimes Devin's base image preinstalls: JDK 17, Rust and Cargo, the AWS CLI, nvm and direnv

Why: a session on a Java, Rust or AWS-tooled repository cannot build or test it without a repository environment, and for Rust and nvm not even with one, while Devin's base image has these preinstalled. Found by the w10/m513 Devin comparison (t007). Severity: minor (Devin parity). Surface: `lego/agent-image/Dockerfile`, sessions on both templates.

## Reference

Devin: "JDK 17 is pre-installed on Devin's base image", "Rust (via rustup) and Cargo are pre-installed", "`awscli` is pre-installed", "Use nvm (pre-installed) to switch Node.js versions per repository via `.nvmrc`", and direnv is "pre-hooked into Devin's shell, so `.envrc` variables load automatically" ([Template library](https://docs.devin.ai/onboard-devin/environment/templates), read 2026-11-19).

## Current state (2026-11-19)

- The image has Node 22 (and Node 24 only for DeepSeek Harness), Python 3.11 and 3.12, Go 1.27, `uv`, `gitleaks` and `gh` (w10/m513). No JDK, Rust, AWS CLI, nvm or direnv.
- A setup step cannot `apt-get` (uid 10001). Since w10/m513 it can download GitHub release assets (a Temurin JDK tarball works), but `rustup` needs `static.rust-lang.org` / `sh.rustup.rs` and nvm needs `nodejs.org`, which no registries-tier session reaches.

## End state

- `java -version` (17), `cargo --version`, `aws --version`, `nvm --version` and `direnv version` succeed as uid 10001 in the built image, each pinned and checked by the Dockerfile's build check, and deploy.yml's Trivy CRITICAL gate still passes; or, for any left out, the egress catalog admits its installer host so a setup step can install it, with the choice recorded in ADR047.

## Done (2026-11-19)

Every runtime is baked in, pinned and checked, and the catalog admits what they fetch (`lego/agent-image/README.md` § Devin's base-image runtimes, ADR047 D2 and D5):

- **The image.** `lego/agent-image/Dockerfile` adds Temurin JDK `17.0.21` (digest-pinned `eclipse-temurin:17.0.21_9-jdk-noble`, without `jmods`, `JAVA_HOME=/opt/java/openjdk`), rustup `1.29.3` with Rust `1.100.0` plus `clippy`/`rustfmt` (`/usr/local/rustup`, `/usr/local/cargo`, `~/.cargo` and `~/.rustup` linked), the AWS CLI `2.41.2` (installer checked by SHA-256, its PGP signature verified when pinned), nvm `0.41.0` (three files pinned by SHA-256, `NVM_DIR=/usr/local/nvm`) and direnv `2.38.2` (built from its module with Go 1.27.4, as gitleaks is). uid 10001 owns the Rust and nvm homes.
- **The shells.** `lego/agent-image/bex-agent-tools.sh` is `/etc/profile.d/bex-agent-tools.sh`, `BASH_ENV`, and sourced from `/etc/bash.bashrc`: every bash has `nvm` (loaded on first call outside interactive shells, so `bash -c` costs nothing: 4 ms with it, 5 ms without), interactive shells apply `nvm alias default` and the direnv hook, and login shells get the toolchains back on the `PATH` Debian's `/etc/profile` resets (before this, `bash -lc` had no `go`).
- **The catalog.** `index.crates.io` (cargo's default sparse index; the catalog's crates.io entries served no current cargo without it), `static.rust-lang.org`, `nodejs.org`, `services.gradle.org`, `plugins.gradle.org`, `plugins-artifacts.gradle.org` (`sessionegress/policy.go`, `TestToolchainHostsAreInTheDefaultRegistryCatalog`).
- **Verified locally (arm64).** The full image builds, and its final check, run as uid 10001, passes: every pin reported, `javac` + `java` run a class, `cargo run --offline` builds a crate, the homes are writable, `nvm --version` answers in `bash -c`, `bash -lc` and `bash -ic`, and the direnv hook is set. The check fails for each wrong pin, without `BASH_ENV`, and as another uid. `nvm install` from an `.nvmrc` installed Node 20.20.2, and `direnv exec` loaded an allowed `.envrc`. Trivy 0.76.1 (`--severity CRITICAL --ignore-unfixed --skip-dirs /opt/bex-go`, as deploy.yml) found 0. The amd64 `go-tools`, `rust` and `awscli` stages build with their pins. The image grows by about 1.1 GB uncompressed (Rust 552 MB, AWS CLI 288 MB, JDK 204 MB), all in linked layers a node pulls once per pin change.
- **Not done here.** Java does not use `HTTPS_PROXY`, so Maven and Gradle reach nothing on the `full` tier, whose only route out is the authenticated egress proxy. Wiring the JVM to it is follow-up work. The amd64 Trivy gate runs in deploy.yml.
