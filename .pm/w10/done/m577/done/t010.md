## Objective

t005's first production run (2026-11-23) found that the default model (`claude` on `deepseek/deepseek-v4.1-flash-1017`) did not end its turn after arming, though the overlay and the tool description already said to: it armed auto-merge and then ran `gh pr checks 1 --watch` until GitHub merged, and in a second turn it watched the checks and merged without `auto`. Make the instruction reach the agent where it decides: in the armed answer itself, in a merge step that names "CI is green" and "before or after the call", and in the `gh` line that offered `--watch`.

## Context

- Turn 1's reasoning right after the armed answer: "The instruction says end turn, but let me verify it actually merges? … I'll do a quick check to report accurately perhaps." So the answer now says what the final reply reports in place of a merge.
- Turn 2's reasoning after opening the pull request: "Now wait for CI. Check checks." The task said "merge it once CI is green", and the overlay said "once the checks pass" and listed `gh pr checks <number> --watch` as how to wait.

## Steps

1. `lego/agent-image/driver/src/merge-pr.ts`: an armed (`autoMerge`) or queued (`mergeQueue`) answer gains `next`, which tells the agent to end its turn now without waiting for or watching the checks, and that its final reply says auto-merge is armed (or that the pull request is in the merge queue), not that it merged. A merge or an undo carries none. The tool description names "or CI is green", "as soon as the pull request is ready", "without waiting for or watching the checks" and `next`.
2. `overlay.ts`: the merge step says "once the checks pass or CI is green", "as soon as the pull request is ready", "do not wait for or watch the checks, before or after the call" and "not that it merged". The `gh` line says `gh pr checks <number> --watch` is not needed to merge once the checks pass, because `merge_pull_request` with `auto: true` does that.
3. `mcp-bex.ts`: the server instructions say to arm it and end the turn without watching the checks.
4. ADR090 D3 ("Said everywhere") and `lego/agent-image/README.md` describe `next`.

## Acceptance criteria

- [x] `merge-pr.test.ts`: the armed answer's `next` (structured content and text), the queued answer's `next`, none on the undo and on a merge; the description and the server instructions name the new wording. Revert proof: dropping `next` from `mergeAnswer` fails "merge_pull_request with auto arms auto-merge, returns the armed answer and records nothing merged".
- [x] `overlay.test.ts` and `github-cli.test.ts` assert the new merge step (with `gh` on and off) and the `gh` line, with and without a recorded number.
- [x] The driver suite passes (`npm test` in `lego/agent-image/driver`: 304 pass, 4 skipped for `/proc`), and `npm run typecheck` is clean.
