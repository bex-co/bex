## Objective

Let a session create and an automation template carry t001's `agentConfig.githubCli` on REST, GraphQL and MCP, show it on their reads, and refuse a value that would loosen what t001 says it may not, with t001's named codes.

## Context

- Session config: `AgentConfig` (`lego/backend/internal/agentsessions/models.go:110`), stored as JSON in `agent_sessions.agent_config`. GraphQL builds it in `graphql.go:761`, and its read type is `agentConfigGQLType` (`graphql.go:404`). The REST create is `rest.go:14`. MCP is `create_agent_session` (`mcp.go:244`).
- Automation template: `AutomationAgentConfig` (`automations.go:74`), inside `AutomationTemplate`, whose decoder refuses unknown fields (`automations.go` `UnmarshalJSON`). The REST routes are in `automations_rest.go:72` and `:82`. MCP is `create_agent_automation` and `update_agent_automation`.
- An automation run builds the session's config in `automation_scheduler.go:273` and `automations.go:666`, and back from a request in `automations.go:676`. A spawn copies its parent's config in `spawn.go:108`.
- The refusal codes follow the existing `AGENT_SESSION_*` and `AGENT_AUTOMATION_*` shapes, on REST, GraphQL error extensions and MCP tool errors alike.

## Steps

1. Add the field to `AgentConfig` and `AutomationAgentConfig` (a `*bool`, so absent means inherit), with the GraphQL input and type fields and the JSON schema descriptions MCP shows.
2. Validate at session create, at automation create and update, and at the validate/dry-run path `bex agent automations apply --dry-run` uses. Refuse `true` under a mandatory off for everyone, and against an inherited off for a non-admin as t001 decided. Never refuse `false`.
3. Carry the value where t001 said: through the automation run (or its live link) and into spawned children, so a child cannot loosen its parent.
4. Show it on the session and automation reads: REST, GraphQL, MCP, and the automation export that `bex agent automations export` writes.
