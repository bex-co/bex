# 041 — A session can mark ready or merge only its own pull request, while Devin's credentials can merge any pull request in the repository

Why: a person who asks a session "merge #42 once its checks pass" about a pull request the session did not open gets a refusal, where Devin, whose App holds Pull requests and Contents write on the repository, would merge it. Found by the w10/m538 Devin comparison (t006), 2026-11-20. Severity: minor (Devin parity; bex hardening without an ADR018 sign-off). Surface: ADR090 D3 (w10/m538 amendment), `lego/backend/internal/agentsession/pullrequest_merge.go`.

## Reference

Devin's App holds Pull requests write ("Allow Devin to create new PRs") and Contents write ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-20), so its credentials can merge any pull request branch protection lets the App merge. Observed: Devin merges its own pull requests when asked (w10/m538 README).

## Current state (2026-11-20, w10/m538)

`mark_pull_request_ready` and `merge_pull_request` act only on the session's recorded `prNumber` (a takeover session's is the person's pull request it took over), as the Git proxy confines pushes to the session branch. ADR090 D3 records why; ADR018 records no sign-off for the divergence.

## End state

The user decides between the two, and the board records it: either ADR018 records the confinement as a signed-off divergence (with the reason: the session acts only on work it was given), or the tools take a pull request number of the session's repository, merge it at the head GitHub reports when the call is made, and audit which pull request was merged, with tests for another session's and a person's pull request. Use `/unblock w10` for the decision.

## Outcome (2026-11-22)

Devin is the reference, and a divergence stands only with an ADR018 sign-off, which this confinement never had, so the Devin-consistent option shipped instead of waiting on the decision (the `/loopx` worker rule for coding-agent parity). Devin's credentials do merge pull requests it did not open: `devin-ai-integration[bot]` merged Renovate's [syou6162/codex-hook#33](https://github.com/syou6162/codex-hook/pull/33) (opened by `app/renovate` 2026-07-17, merged 2026-11-21) and the `github-actions` release pull request [outfitter-dev/trails#1110](https://github.com/outfitter-dev/trails/pull/1110) (merged 2026-11-18 after Devin "checked exact head"; both read 2026-11-22). The confinement's reason (the session acts only on work it was given) protected nothing a session cannot already do: it can push any change to its own branch and merge its own pull request under the same branch protection.

- **Tools.** `mark_pull_request_ready` and `merge_pull_request` take an optional `number` of a pull request of the session's repository (also beside `disableAuto`); without it, or with the session's own number, nothing changes. The gateway accepts `number` and still refuses an owner, repository or head (`lego/backend/internal/sshgateway/agentcred/pullrequest.go`).
- **Verb.** bex-api reads that pull request with the session's one-repository token and requires the session's repository as its base; any head branch or fork is fine. Its merge, arm or queue is pinned to the head GitHub reported in that read. The answer carries `otherPullRequest: true`, a number with no pull request is `pull_request_not_found` (404), a merge records `prState: merged` at once on every session of the workspace that recorded it (`RecordPullRequestState`), and both hops' audit `TargetName` is `owner/repo#<number>` (`lego/backend/internal/agentsession/pullrequest_merge.go`).
- **Agent side.** The tool schemas and descriptions, the `bex` server's instructions, the overlay's merge step and the `gh pr ready`/`gh pr merge` refusal say to pass the number of another pull request a person names. The driver leaves its own pull request record alone when the answer is another pull request's (`lego/agent-image/driver/src/merge-pr.ts`).
- **Docs.** The ADR090 D3 w10/041 amendment, a new ADR018 row, ADR047 and `lego/backend/AGENTS.md`.
- **Tests.** A person's pull request from a fork and another session's (`TestPullRequestReadyAndMergeOfAnotherPullRequestByNumber`), no pull request of its own, or naming its own number (`TestPullRequestMergeNamingNoneOrItsOwnNumber`), auto and disableAuto (`TestPullRequestMergeAutoAndDisableAutoOfANamedPullRequest`), the refusals and the denied audit (`TestPullRequestReadyAndMergeOfANamedPullRequestRefusals`), the signed hop (`TestPullRequestReadyAndMergeClientsCarryANumber`) in `internal/agentsession`; the gateway route (`TestPullRequestReadyAndMergeRoutesActOnANamedPullRequest`) and the refusal text in `internal/sshgateway/agentcred`; and the driver's number validation and kept record. Ignoring the number, or pinning another pull request to the session's recorded head, fails them.

Done 2026-11-22 in the commit that moves this note. It was not walked on production, since the end state asks for tests.
