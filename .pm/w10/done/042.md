# 042 — The overlay and the `merge_blocked` hint say `gh pr checks --watch`, which fails in a session without the pull request's number

Why: `gh` resolves "the current branch's pull request" through the git remote, and a session's `origin` is the bex Git proxy, which gh cannot map to GitHub, so the command the merge step names fails ("could not resolve remote \"origin\": none of the git remotes configured for this repository point to a known GitHub host") and the agent has to work out `--repo` or the number itself. Found by w10/m538's live check (t005), 2026-11-22. Severity: minor. Surface: `lego/agent-image/driver/src/overlay.ts` (`readyOrMergeStep`), `lego/agent-image/driver/src/merge-pr.ts` (the merge tool's description), `lego/backend/internal/agentsession/pullrequest_merge.go` (`NewPullRequestMergeError`, `merge_blocked` and `head_changed` hints).

## Evidence (production, pin `eaaa61506165`, 2026-11-22)

Session `ags-dc1kmbu0usec73d5it3g` on `puncsky/qa-20261122-m538-merge`: `gh pr merge --squash` and `gh pr checks --watch` with no number both exited 1 with the remote error above; `gh pr checks --watch --repo puncsky/qa-20261122-m538-merge` worked, and so did `gh pr merge 2 --squash` and `gh pr ready 2` with a number (they reached gh's own check and the gateway route). `GH_REPO` names the repository but not the current branch's pull request.

## End state

Every place that tells the agent how to wait for checks names the pull request: `gh pr checks <number> --watch`, with the number the tools return (the overlay's merge step, the merge tool's description and the `merge_blocked` hint), and the overlay's `gh` line says to pass the pull request number to `gh pr` commands. Driver and backend tests assert the new text.

## Outcome

- **Already true on main.** Since w10/m577 (98092bb49e), the overlay's merge step and the merge tool's description say to arm `auto: true` and end the turn. Neither one tells the agent how to wait any more.
- **Backend.** The `merge_blocked` hint says to wait with `gh pr checks <number> --watch`, using the number the agent passed or the `number` that `open_or_update_draft_pr` returned. The `auto_merge_not_allowed` hint, which also says to wait for the checks, names the same command (`lego/backend/internal/agentsession/pullrequest_merge.go`). The `head_changed` hint names no wait command.
- **Overlay.** The `gh` line says to pass the pull request's number to every `gh pr` command: `origin` is the bex Git proxy, so gh cannot find the current branch's pull request by itself. Its examples name the number (`gh pr checks <number> --watch`, `gh pr review <number> --comment`, `gh pr edit <number> --add-label`). Once the session has its pull request, they name that one's number, and otherwise they say `open_or_update_draft_pr` returns it (`lego/agent-image/driver/src/overlay.ts`). With `gh` off, the line still names no `gh` command.
- **Docs.** ADR090 D3, D3's w10/m577 refusals and D4's wiring, plus the agent-image README.
- **Tests.** `TestPullRequestMergeTypedRefusals` and `TestPullRequestMergeAutoTypedRefusals` in `internal/agentsession`, and the driver's `github-cli.test.ts` (both with and without a recorded pull request) and `overlay.test.ts`. Each one fails with the old text.
- **Repro.** Local, gh 2.96.0, with a branch tracking a non-GitHub `origin` and `GH_REPO` set. `gh pr checks --watch` fails with `could not resolve remote "origin"`, and `gh pr checks 12000 --watch` answers. This was not walked on production, since the end state asks for tests.

Done 2026-11-22 in the commit that moves this note.
