# 034 — A session cannot mark its pull request ready for review or merge it when its task asks, as Devin can

Why: a task such as "fix the flaky test and merge once CI is green" ends with a draft pull request a person has to undraft and merge, because the `bex` tools never undraft (ADR090 D3) and w10/m522 refuses `gh pr ready` and `gh pr merge`, while Devin's GitHub integration lets Devin merge once branch protection's required checks pass. Found by the w10/m522 Devin comparison (t006), 2026-11-19. Severity: minor (Devin parity; it needs a decision on what a session may do to its own pull request). Surface: `lego/backend/internal/agentsession/pullrequest.go` (the D3 verb), `lego/agent-image/driver/src/mcp-bex.ts`, ADR090 D3 and D4.

## Reference

Devin's App holds pull requests write ("create new PRs"), and its docs recommend branch protection so that "all required checks pass before Devin can merge changes" ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-19).

## Open question

Whether a session may undraft and merge only the pull request it opened (`prNumber` on the session), and only when its task or a person's message asked for it, or never. Branch protection still decides whether a merge is allowed, and an App's approval stays refused (w10/m522), so a session cannot satisfy required reviews by itself.

## End state

If it is allowed: a `bex` tool (or the D3 verb with a `ready`/`merge` input) marks the session's own recorded pull request ready and merges it with the repository's allowed method, refusing any other pull request and reporting GitHub's own refusal (required checks, reviews) as given. REST, GraphQL and MCP show the merged state, and `gh pr ready`/`gh pr merge` stay refused naming the tool. If it is not allowed: ADR018's agent rows record the divergence with the user's sign-off.

## Promoted (2026-11-20)

- Promoted to milestone **w10/m538** ([README](../m538/README.md)) by `/loopx w10`. The work is more than one sitting: two bex-api verbs and their GitHub calls, two gateway routes, two `bex` MCP tools, the overlay and the `gh` refusal text, ADR090 and ADR047 amendments, and a live check.
- **Premise confirmed on `80b275f87`.**
  - The D3 verb only opens or updates a draft (`lego/backend/internal/github/pulls.go:79`).
  - The overlay tells the agent to leave it as a draft (`lego/agent-image/driver/src/overlay.ts:198`).
  - The `github-api` route refuses `markPullRequestReadyForReview` and `mergePullRequest` (ADR090 D4).
  - `prState` (open, merged, closed) is already on REST, GraphQL, MCP and the dashboard, so the merge only has to record it at once.
- **The open question was settled under the Devin rule, not parked for the user.**
  - **Devin's docs.** Branch protection is recommended "to ensure all required checks pass before Devin can merge changes" ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-20).
  - **Devin merges its own pull requests.** Of the 60 most recently updated merged pull requests authored by `app/devin-ai-integration`, 35 were merged by `devin-ai-integration[bot]` itself.
  - **Devin undrafts and merges.** On [TeddyJubu/cal-scheduling#1](https://github.com/TeddyJubu/cal-scheduling/pull/1) the bot marked its own draft ready and merged it seven seconds later (2026-11-20).
  - **Only when asked.** [Al-does/alex-rl-experiments#149](https://github.com/Al-does/alex-rl-experiments/pull/149), which Devin wrote and merged, says sessions merge "only on explicit request" and otherwise return the link for manual merging.
  - **The verdict** is the note's "allowed" branch: the session's own recorded pull request, only when the task or a person's message asks, which the overlay states, and branch protection decides. No ADR018 divergence is needed.
