# 040 — A session always opens its pull request as a draft, while Devin opens a regular pull request by default

Why: a requester who wants Devin's default gets a draft they must undraft themselves (or ask the session to with `mark_pull_request_ready`), and reviewers whose GitHub notifications skip drafts do not see the pull request until then. Found by the w10/m538 Devin comparison (t006), 2026-11-20. Severity: minor (Devin parity). Surface: ADR090 D3, `lego/backend/internal/github/pulls.go` (`createPull`, `Draft: true`), the overlay's delivery steps.

## Reference

Of the 200 most recent pull requests authored by `app/devin-ai-integration` created since 2026-11-13, 6 were drafts on 2026-11-20 (the w10/m538 README's Devin evidence). Devin's GitHub integration lets Devin "create new PRs" ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-20); nothing in its docs says the pull request starts as a draft.

## Current state (2026-11-20, w10/m538)

ADR090 D3 creates every session pull request as a draft and never undrafts it in the PR verb; since w10/m538 `mark_pull_request_ready` undrafts it when the task or a person asks.

## End state

Decide the default with Devin as the reference: either the D3 verb opens a regular pull request unless the task asks for a draft (for example a `draft` option on `open_or_update_draft_pr`, or a workspace or automation setting), with ADR090 D3 and the overlay amended; or ADR018 records the draft default as a signed-off divergence. A test covers the chosen default and the override.

## Outcome (2026-11-22)

Devin is the reference, and its default is a regular pull request: its docs name no setting that drafts the pull requests it opens (Settings > Devin > Pull requests only picks whose identity opens them; [GitHub integration](https://docs.devin.ai/integrations/gh) and [release notes](https://docs.devin.ai/release-notes/overview), read 2026-11-22), and Port's guide says "Devin usually opens a regular PR (not draft, no WIP)" ([Track AI-driven pull requests](https://docs.port.io/guides/all/track-ai-driven-pull-requests/), read 2026-11-22). So the D3 verb now opens the pull request ready for review, and a `draft` option opens a draft when asked:

- **Verb.** `github.Client.SyncPullRequest` (was `SyncDraftPullRequest`, `lego/backend/internal/github/pulls.go`) sends `draft` from the request, read only when it opens the pull request; an update still sends only the title and body. `PullRequestContent` carries `draft` (omitted when false, so a plain request is the old `{title, body}` on both hops), the answer carries the pull request's `draft`, and a takeover ignores it.
- **A plan without drafts.** GitHub offers drafts in private repositories only on Team and Enterprise Cloud and answers a draft elsewhere with 422 "Draft pull requests are not supported in this repository." That is now `draft_not_supported`, whose hint says to call again without `draft`. The old always-draft verb could not open a pull request on such a repository at all.
- **Agent side.** `open_or_update_draft_pr` keeps its name (tasks and the gateway's hints name it) and gains `draft`. Its description, the overlay's delivery steps, the ready and merge tools' descriptions and the delivery nudge no longer call the pull request a draft, and they say to pass `draft: true` only when the task, a person's message or the repository's instructions ask for one.
- **Surfaces.** The cloud-agents MCP `send_agent_session_message` / `steer_agent_session` descriptions and the dashboard's cancel dialog (all eight locales) say "pull request", not "draft PR". ADR090 D2, D3 and D4 carry the w10/040 amendment, and ADR018, ADR047, `lego/agent-image/README.md` and `lego/backend/AGENTS.md` follow it.
- **Tests.** The default and the override are covered on every hop: `TestSyncPullRequestOpensReadyForReviewThenUpdatesWithoutChangingDraftState`, `TestSyncPullRequestOpensADraftWhenAsked` and `TestSyncPullRequestRefusesADraftTheRepositoryCannotHave` (`internal/github`); `TestPullRequesterOpensADraftOnlyWhenAsked` and `TestPullRequestContentOmitsAnUnsetDraft` (`internal/agentsession`); `TestPullRequestRouteOpensADraftWhenAsked` and the non-boolean `draft` case (`internal/sshgateway/agentcred`); and the driver's `draft: true reaches the gateway and false is not sent at all` plus the overlay assertions. Restoring `Draft: true` in `createPull`, or dropping `req.Draft` in the verb, fails them.

Done 2026-11-22 in the commit that moves this note. It was not walked on production, since the end state asks for tests; the first session pull request after a pin carrying this commit opens ready for review.
