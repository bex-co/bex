# A workspace admin cannot allow the platform catalog's models by provider

Why: Devin Desktop's "Allowlisted models" can "filter by specific models or by provider", so an admin can allow every Anthropic model, current and future, in one step; bex's `enabledModels` names models one by one.

- **Found by** w10/m527 t007 (Devin comparison), 2026-11-20 ([Devin Desktop admin controls](https://docs.devin.ai/desktop/controls), read 2026-11-20: "Filter by specific models or by provider (one filter type at a time)").
- **Today:** the catalog has two providers (`deepseek/…`, `anthropic/…`, `lego/operator/config/api/deployment.yaml`), and `enabledModels` (ADR047 D7, w10/m527 amendment) takes model ids only. With four models a provider filter saves little; it matters once the catalog grows or together with w10/036 (new models start off once a list is narrowed).
- **Code:** `modelOfferPatch` / `offeredModels` in `lego/backend/internal/agentsessions/environment.go`, the Settings → Agents model list in `dashboard/src/features/agent-environment/`, `bex agent env set --models` in `lego/cli/internal/agent/config.go`.
- **End state:** an admin can allow by provider (for example `enabledProviders: ["anthropic"]`, the provider being the id's prefix before `/`), as the one filter type in force, on REST, GraphQL, MCP, the CLI and Settings → Agents. Every model of an allowed provider, including one added to the catalog later, is offered; the catalog default still always is. Tests cover the read, the write's refusals (an unknown provider, both filter types at once) and a new catalog model of an allowed provider being offered.
- Ship only if users would miss it: re-check the catalog's size and whether w10/036 shipped first.

## Promoted 2026-11-22 to [w10/m573](m573/README.md) by `/loopx w10`

No surface takes a provider.
- **The note's conditions are met.** w10/036 shipped first as w10/m568 (`343ae3da8d`), so a narrowed list now leaves every later model off, including a trusted provider's. The catalog still holds four models from two providers (`lego/operator/config/api/deployment.yaml:650-653`). Today a filter allowing `anthropic` offers what "allow all" offers, and the two first differ at the next catalog model.
- **Devin's behavior, re-read 2026-11-22.** [Devin Desktop admin controls](https://docs.devin.ai/desktop/controls): "Filter by specific models or by provider (one filter type at a time)". [List Models](https://docs.devin.ai/desktop/accounts/api-reference/list-models): provider tags such as `provider-anthropic` on the allowlist, and "A model is allowed when its UID is listed or it carries a listed tag".
- **Parity-first applies.** ADR018's agent-model row records the divergence (w10/037) with no user sign-off.
