# 020 — `bex agent automations apply` refuses `overlapPolicy`, which `list` returns

Why: an automation's overlap policy cannot be kept in the definition files `apply` reads, so the declarative workflow drops a setting. Severity: minor. Surface: `bex agent automations apply` / `export`.

## Evidence (2026-11-15)

A definition with `"overlapPolicy": "skip"` (copied from `bex agent automations list -o json`) → `"overlapPolicy" is not part of a definition (only name, enabled, triggers, template, notifications; export prints that shape)`.

## Direction

Accept `overlapPolicy` in `apply` (and print it in `export`), or document that it is server-only and how to change it.

## Outcome (2026-11-19)

Done: the first direction. The API itself refused the field (`AgentAutomationInput` had no `overlapPolicy`, and REST decodes with unknown fields disallowed), so `overlapPolicy` is now writable on REST, GraphQL and MCP create and update (`skip` only, ADR101 D6; any other value is `400 AGENT_AUTOMATION_INVALID` on `overlapPolicy`; omitted keeps the stored value), as Devin's v3 automation API carries its `concurrency` setting in the same body. `apply` accepts it and `export` prints it. The CLI contract fixture gained `definitionKeys`, which the backend twin (`TestShapesMatchCLIAutomationContract`) checks against `AgentAutomationInput`'s writable fields and the CLI checks against `definitionKeys`, so a writable field the CLI misses fails CI on both sides. Tests: `TestApplyAcceptsOverlapPolicy` (it reproduces this note's error when the fix is reverted), `TestAutomationOverlapPolicyAcrossSurfaces`, and the GraphQL input mirror in `TestAutomationGraphQLTypesMirrorTheJSONViews`.
