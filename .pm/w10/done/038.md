# 038 — A JVM HTTP client that installs no `java.net.Authenticator` gets 407 from the egress proxy on a `full`-tier session

Why: since w10/032 every JVM on a `full`-tier session has the egress proxy in `JAVA_TOOL_OPTIONS`, and Maven, Gradle and the Maven/Gradle wrappers authenticate to it, but the JDK sends proxy credentials only through a `java.net.Authenticator`. So a repository's own Java code that calls a public API (an integration test, a `jbang` script, a tool with its own downloader) gets the gateway's 407, while on Devin, whose sandbox has direct internet, it works. Found by w10/032's worker, 2026-11-20. Severity: minor (Devin parity). Surface: `lego/agent-image/` (JVM startup), `lego/backend/internal/sshgateway/egressproxy/egressproxy.go`.

## Current state (2026-11-20, w10/032's `35b3880c9`)

- Against the real egress `Broker` (local Docker, w10/032's setup), with the session's `JAVA_TOOL_OPTIONS`, a plain `HttpURLConnection` GET of `https://repo.maven.apache.org/maven2/` answered 407 (via proxy). The same GET answered 200 once the program installed the proxy `Authenticator` that Gradle's wrapper installs, reading `<protocol>.proxyUser`/`proxyPassword`.
- `java.net.http.HttpClient` uses no default `Authenticator` unless the builder names one, so it gets 407 even with one installed.
- The proxy needs the claim because its Pod resolver looks the source IP up in the claimed namespace (`admit` → `ResolveSessionPod(namespace, sourceIP)`).

## Options

1. A small `-javaagent` baked into the image and added beside the proxy properties, whose `premain` installs a default `Authenticator` that answers only `RequestorType.PROXY` from those properties. A program that sets its own still replaces it. This covers `HttpURLConnection`, not `java.net.http`.
2. The gateway admits a proxy request that carries no claim when its source IP resolves to exactly one live session sandbox Pod, so `-Dhttps.proxyHost` alone suffices for every JVM client. This needs a lookup that is not scoped to a namespace and an ADR047 trust-model amendment.

## End state

On a `full`-tier session, a plain `HttpURLConnection` GET and a `java.net.http.HttpClient.newHttpClient()` GET of `https://repo.maven.apache.org/maven2/` both answer 200 through the proxy. A model-provider host is still refused, the gateway and loopback stay direct, and `registries` and `custom` are unchanged.

## Triage (2026-11-22)

**Work.** The premise held on `aa0c63b659`: nothing in the image installs a `java.net.Authenticator` (`bex-agent-tools.sh` and `credentials.ts` only add the proxy properties), and the egress proxy answers 407 to a request without the claim (`egressproxy.go`, `serve`). Neither option was taken as written:

- Option 1 (a `-javaagent` default `Authenticator`) misses the End state: `java.net.http.HttpClient.newHttpClient()` uses no default `Authenticator`.
- Option 2 (admit a claim-less request by its source IP) needs a Pod lookup across every namespace, which the gateway's per-`<ws>-sandbox` RoleBindings (`bex-tenant-ssh-gateway`, ADR043) do not grant, and it would widen the gateway's reach to every tenant's Pods.
- Taken instead: a loopback relay in the session driver that adds the claim. It covers every JVM client that honours the standard proxy properties, as Devin's direct internet does, with no trust-model or RBAC change, and an older or snapshot image keeps its earlier behavior because the image, not bex-api, decides.

## Work record (2026-11-22)

- **Fix** (`5011472351`).
  - `lego/agent-image/driver/src/java-proxy.ts`: when `BEX_AGENT_JAVA_PROXY_OPTIONS` names the proxy, the driver listens on a `127.0.0.1` port before any tenant process runs, in a session and in a repository environment build. Each CONNECT goes on as the relay's own CONNECT with the session claim, then bytes pass both ways untouched. Each absolute-form plain-HTTP request goes on with the claim, every request of a kept-alive connection included. A client's own proxy credentials are replaced by the session's.
  - The driver points its `BEX_AGENT_JAVA_PROXY_OPTIONS` at the relay (the proxy host and port only), so the agent's `JAVA_TOOL_OPTIONS`, setup steps and `/etc/mavenrc` take it. It writes `java/env.sh` beside its status file, which `bex-agent-tools.sh` reads for terminals; a shell started before the relay gets the gateway's properties in front replaced there. A build removes the file before its image is committed.
