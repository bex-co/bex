# 028 — A workspace admin cannot narrow which platform models its members may choose

Why: Devin lets admins "control which agents are available" ([Your First Session](https://docs.devin.ai/get-started/first-run), read 2026-11-19), and a workspace that wants routine runs kept on the cheap model has no way to stop a member from picking `anthropic/claude-opus-5.5` for every session. Found by the w10/m516 Devin comparison (t007), which filed it apart as the stricter variant. Severity: minor (Devin parity). Surface: `lego/backend/internal/agentsessions/environment.go` (`sessionModel`, the agent environment), Settings → Agents.

## Current state (2026-11-19)

Every workspace on the platform model offers the whole catalog (`BEX_AGENT_PLATFORM_MODELS`, ADR090 § Model pin) to every member for every session, automation and message. The workspace default model only changes what runs when a request names none.

## End state

A workspace admin can turn catalog models off for the workspace (REST `PATCH /v1/agent-environment`, GraphQL, MCP, Settings → Agents, `bex agent env set`), as the enabled-agents list does for agent profiles (w7/m392). A turned-off model is absent from the capabilities `models`, refused at create, on a message and in an automation with `AGENT_SESSION_MODEL_NOT_OFFERED`, and a session or automation already on it runs the workspace default from its next turn. The catalog default can never be turned off.

## Promoted (2026-11-20)

- Promoted to milestone **w10/m527** ([README](../m527/README.md)) by `/loopx w10`. The work needs a migration and a store field, and the list on REST, GraphQL and MCP. It needs one offered-model set behind create, message, automation save and fire, the capabilities read and the default model. It also needs a CLI flag, a Settings → Agents list with the pickers following it, three ADR amendments and a live check. That is more than one sitting.
- Triage on `e9a2a96f3` confirmed the premise. The agent environment row has no model list (`lego/backend/internal/store/agent_environments.go:31`). `agentsession.PlatformModels` (`lego/backend/internal/agentsession/devroute.go:356`) returns the whole catalog with no workspace input, and `sessionModel`, `agentModels`, `environmentView`, `validateEnvironmentInput` and `retiredTemplateModel` all take it as the choice. `sessionModel`'s existing fallback for a model the catalog no longer offers gives the "next turn runs the workspace default" end state once the offered set is narrowed per workspace.
- Devin's reference, read 2026-11-20:
  - In the cloud agent, admins control which agents are available, and the picker lists only those ([Your First Session](https://docs.devin.ai/get-started/first-run)).
  - Devin Desktop and the Devin CLI have an "Allowlisted models" team setting that hides other models from pickers ([admin controls](https://docs.devin.ai/desktop/controls)).
  - A pinned default outside that allowlist falls back to the built-in default ([CLI Team Settings](https://docs.devin.ai/cli/enterprise/team-settings)).
  - m527 ships the workspace-wide list. Its t007 files the group-level and provider-filter variants if users would miss them.
