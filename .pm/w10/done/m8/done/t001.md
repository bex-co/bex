## Objective

Every failure path of the device-verification GET — expired/missing device code, invalid/used code, unconfigured provider, unexpected client — renders inside `AuthPageShell` like the m7 confirm page, instead of the raw `text/plain` body the `error()` helper returns today.

## Context

- `dashboard/src/common/server-fn/hydra-device.ts:21-26` — the `error()` helper returns bare `text/plain`; reached on a top-level browser navigation, so the user sees an unstyled page.
- Failure sites: "missing or expired device code" (:68), "device authorization not configured" (:67), "device code is invalid, expired, or already used" (:169), "device authorization refused an unexpected client" (:192).
- Locale keys `auth.deviceExpiredTitle` / `auth.deviceExpiredSubtitle` already exist (`dashboard/src/features/auth/locales/en.ts:268-276`) but are only wired to the client-side "no live request" branch of `device-confirm-page/index.tsx:46-59`.
- m7 established the pattern: the server-fn hands view data to a React page via deferred loader context (`device-confirm-page/`, route split `auth.device.tsx` + `auth.device.index.tsx`).
- Security invariant: the confirm POST stays same-origin and session-bound (codex-security #9) — error-state rendering must not change the POST semantics.

## Steps

1. Classify each device GET failure site: recoverable user-facing states (expired/invalid code — the common case) vs configuration errors.
2. Extend the device loader context with an error variant (code + message key) instead of returning `text/plain` for document GETs; keep non-navigational/XHR behavior unchanged.
3. Render the error variant in `device-confirm-page` (or a small shared error state component) inside `AuthPageShell`, reusing the existing `deviceExpired*` keys and adding the missing en + zh keys for the other states.
4. Verify each state live in the dev server (expired code, invalid code, unset env) and screenshot to `.playwright-mcp/`.

## Acceptance criteria

- [ ] Navigating to `/auth/device` with an expired, invalid, or missing device code renders an `AuthPageShell` page in both locales — no `text/plain` response on any document GET.
- [ ] The unconfigured/unexpected-client states also render in the shell (or are proven unreachable in production and documented as such).
- [ ] The confirm POST's same-origin session-bound semantics are byte-preserved (existing `hydra-device` tests still pass).
