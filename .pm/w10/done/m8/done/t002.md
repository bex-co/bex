## Objective

The consent document-GET's refusal and error paths render inside `AuthPageShell` instead of bare `text/plain`, using the error-state pattern t001 established for the device flow.

## Context

- `dashboard/src/common/server-fn/hydra-consent.ts` — bare `text/plain` on full-page navigations: `pkceRefusal()` (:184), `scopeRefusal()` (:250), "consent provider not configured" (:342), "consent accept failed" (:364), the cross-user refusal (:380).
- The scope refusal is the round-14 #1 guard (`OAUTH_API_SCOPE`, ADR069) — its refusal semantics (400 `invalid_scope`, fail-up-front so a developer can read the message) must be preserved; only the rendering becomes a themed page for document navigations.
- The consent page itself (`consent-page/`) is already on `AuthPageShell`; only its server-fn failure paths are off-shell.

## Steps

1. Apply t001's error-variant pattern to the consent loader: recoverable refusals (PKCE, scope, cross-user) and configuration errors render as shell error states with en + zh copy.
2. Keep the refusal *semantics* identical — same Hydra reject calls, same status codes on non-document requests; only document-GET rendering changes.
3. Verify the scope-refusal path (the ADR069 developer-facing message) still communicates the exact missing scope.
4. Live-verify the reachable states via the dev server + screenshots.

## Files

- `dashboard/src/common/server-fn/hydra-consent.ts`
- `dashboard/src/features/auth/pages/consent-page/` (error-state rendering)
- `dashboard/src/features/auth/locales/en.ts`, `dashboard/src/features/auth/locales/zh.ts`
- `dashboard/src/routes/auth.consent.tsx` (if plumbing is needed)

## Acceptance criteria

- [ ] Every consent document-GET refusal/error path renders an `AuthPageShell` page in both locales; no `text/plain` document responses remain in `hydra-consent.ts`.
- [ ] The round-14 scope-refusal message still names the missing scope, and existing `hydra-consent` tests (updated as needed) pass.
- [ ] XHR/fetch consumers of these endpoints (if any) are unaffected.

## Out of scope

- Changing which requests are refused (authorization semantics stay exactly as shipped by ADR069/round-14).
