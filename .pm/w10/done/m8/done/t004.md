## Objective

The Hydra OAuth client that the official Render CLI device flow uses is registered as "bex CLI", so the consent hero and Settings → Connected Agents stop showing "Render CLI (bex platform)" — the surviving half of the mis-branding the 2026-08-18 user report named.

## Context

- `scripts/auth-bootstrap-client.sh:170` — `"client_name":"Render CLI (bex platform)"`. The name lives only in this script (no gitops manifest carries it); it flows to the consent hero (`consent-page/index.tsx:75,81` via `consent.clientName`) and Connected Agents (`hydra-connected-agents.ts:77` → `connected-agent-row.tsx:33`).
- Re-running the bootstrap is the documented update path — note the standing warning: `BEX_OAUTH_REQUIRE_AUDIENCE=1` relies on the script's `bex.co/platform-client` marker, so the re-run must preserve the marker and client id (rename in place, never recreate the client).
- Optional tidy: the last internal identifiers carrying the old name — `hydra-device.ts:8` `RENDER_CLI_CLIENT_ID` (re-exported :198), `lego/backend/internal/cliauth/service.go:39` `RenderCLIClientID`, and the script's variable name. Not user-visible; rename only if the diff stays mechanical.

## Steps

1. Change the `client_name` in `scripts/auth-bootstrap-client.sh` to `bex CLI`; confirm the script updates an existing client idempotently (PATCH/PUT, same client id, marker preserved) rather than recreating it.

3. Re-run against production Hydra (same script, prod env); verify live.
4. Optionally rename the internal `RENDER_CLI_CLIENT_ID` / `RenderCLIClientID` identifiers (dashboard + backend) if purely mechanical.
