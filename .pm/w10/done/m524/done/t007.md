## Objective

Verify DoD 5 on production once a deploy carries the milestone.

- Production runs the milestone once the newest `chore(deploy): pin platform images to <sha>` on `origin/main` contains its commits; park with that pin gate until then.
- The sandbox node is near capacity (w9/m349): one short session, three short turns.

## Steps

Refined 2026-11-19 by t001 (see the milestone's design record): a turn dispatched while the setting is off has no `gh` at all (DoD 2), so the route's message naming the setting is checked on a turn that started with `gh` on.

1. With the setting on, start one short repo session whose task runs `gh run list --limit 1`, then `sleep 120`, then `gh run list --limit 1` again and prints both outputs.
2. While it sleeps, turn the setting off with `bex agent env set --github-cli off` and read it back on REST, GraphQL and MCP. The turn's second `gh run list` is refused with the message naming the setting. Check the denied `agentsessions.MintGitHubReadCredential` event in the audit log.
3. Send a second message that prints `env | grep ^GH_` and runs `gh run list --limit 1`, and quotes what the overlay says about `gh`: no `GH_*` variables, `gh` is not configured, and the overlay says `gh` is off for the workspace.
4. Turn the setting back on in Settings → Agents, send a third message that runs `gh run list --limit 1`, and see it answer.
5. Record the session id and the outcomes in the milestone README, leave the setting on, and delete the session.
