# 021 — The bex CLI session expires within hours and long-running scripts fail with 401

Why: a script that waits on agent sessions (`bex agent wait`, automation runs) breaks mid-run with `401 unauthorized` and needs an interactive `bex login`. Severity: minor. Surface: `bex` CLI auth (token refresh).

## Evidence (2026-11-15..18)

At least three times in three days on one machine:

```
Error: your token is expired; run `bex login` to get a new one
```

Each was followed by `401 unauthorized` from `bex agent get` / `automations list` while a monitoring loop was running.

## Direction

Refresh the access token with the stored refresh token before it expires (or on a 401), and reserve `bex login` for a revoked or expired refresh token.

## Closed 2026-11-19: already met (`/loopx w10`)

The login does not expire within hours, and the CLI already refreshes it ahead of expiry. The failures were revocations, and for a revoked grant `bex login` is the right answer.

- **Lifetimes.** Production's Render CLI client issues 7-day access tokens (`device_authorization_grant_access_token_lifespan` and `refresh_token_grant_access_token_lifespan` are `168h0m0s`, read from Hydra on 2026-11-19 and set on every deploy by `scripts/auth-bootstrap-client.sh`). Its refresh tokens last 30 days. This machine's stored login expires 7 days after its `bex login`. The pinned upstream client refreshes with the stored refresh token once a token is within 24 h of expiry (`render-oss/cli` `pkg/client/client.go` `maybeRefreshAPIToken`), so every command starts with at least a day left.
- **Long waits hold.** On 2026-11-17 this machine's `bex agent wait` ran for 2 h 05 m, 58 m and 2 h 30 m without an auth error (CLI telemetry: exit 3 is a failed turn, 124 the wait's own timeout).
- **What failed.** The filing session recorded the error at 04:29, 04:55 and 05:37Z and again at 17:37Z on 2026-11-16. Each followed a production check that revoked every Render CLI grant of the shared QA account, the account this machine's login belongs to:
  - [w21/085](../../w21/done/085.md)'s revoke-path probes, which include the consent-session revoke, ran at 03:09–03:56Z. The login last worked at 02:08Z.
  - [w21/090](../../w21/done/090.md) ran `revoke-oauth-grant … --apply` six times at 12:22:57–12:26:51Z (six `oauth.RevokeGrant` audit rows). No CLI grant of the account older than 12:46Z survives in Hydra.
- **Why refreshing would not have helped.** A revoked grant loses its refresh token too, and Hydra answers `invalid_grant`. A refresh on the 401 could not have recovered it, so `bex login` was the reserved path working as intended.
- **Gap tracked elsewhere.** The upstream client drops the stored refresh token after a transient 429 or 503 refresh failure ([w8/067](../../w8/blocked/067.md), waiting on render-oss/cli#55).
