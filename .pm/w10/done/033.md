# 033 — `gh workflow run` is refused, so a session cannot dispatch a workflow on its own branch, as Devin's Actions write can

Why: since w10/m522 a session's `gh` re-runs and cancels CI, but a repository whose slow or manual checks (an e2e suite, a benchmark, a preview build) run only on `workflow_dispatch` cannot have them run on the session's branch, while Devin's App holds Actions write and can dispatch. Found by the w10/m522 Devin comparison (t006), 2026-11-19. Severity: minor (Devin parity). Surface: `lego/backend/internal/sshgateway/agentcred/githubapi.go` (`githubAPIWrites`, `restWriteBodyRefusal`), ADR090 D4.

## Reference

Devin's App asks for Actions read and write "to view the actions configured for a repository" and to rerun workflows ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-19), which also covers `POST /repos/{owner}/{repo}/actions/workflows/{id}/dispatches`.

## Why it was refused

w10/m522 refused every dispatch: a dispatch starts a new run on any ref with chosen inputs and the repository's secrets, while a re-run repeats a run that already ran. A dispatch whose `ref` is the session's own branch runs only code the session pushed, which a `pull_request` workflow on its draft PR already runs with the same secrets.

## End state

`gh workflow run <workflow> --ref <the session branch>` (REST `POST …/actions/workflows/{id}/dispatches` with `"ref"` equal to the session's `bex-agent/…` branch, `refs/heads/` form included) is admitted with the w10/m522 write token. Any other `ref`, a missing `ref`, or a repeated key is refused naming the `bex` tools. A gateway test covers each, and ADR090 D4 and the overlay say so.

## Done 2026-11-20 (`/loopx w10`)

- **Gateway.** `githubAPIWrites` admits `POST actions/workflows/{id or file}/dispatches`, and `dispatchesOnTheBranch` (`lego/backend/internal/sshgateway/agentcred/githubapi.go`) checks its body after admission against the Pod-bound session branch: one JSON object repeating no key, `ref` equal to the branch or `refs/heads/<branch>`, beside at most an `inputs` object and a boolean `return_run_details`. The w10/m522 write token carries it. Any other ref (tag, another branch, the default branch `gh workflow run` picks without `--ref`), a missing ref, a repeated key (escaped spellings included) or any other field answers `403`: "bex: gh in this session dispatches a workflow only on your session branch, as `gh workflow run <workflow> --ref <branch>`.", then the write refusal naming the `bex` tools, which now also lists the dispatch.
- **Tests.** `TestGitHubAPIRouteDispatchesAWorkflowOnlyOnTheSessionBranch` covers 4 admitted bodies and 24 refused bodies, plus a query string, another repository and other paths. None of the refused requests reached GitHub or minted a token. The pinned gh 2.105.0 was recorded again on 2026-11-20 through a socket that forwarded reads to GitHub and answered writes itself, for `gh workflow run lint.yml --ref bex-agent/task-1`, `… --ref refs/heads/bex-agent/task-1 -f reason=flake` (admitted) and `gh workflow run lint.yml` with no `--ref` (refused). The fixture `testdata/gh-2.105.0-requests.json` gained those three commands, and `TestGitHubAPIRouteReplaysTheRecordedGhCommands` replays them. Five mutants, each killed by the tests: dropping the route, any ref, unknown keys admitted, no repeated-key check, no `refs/heads/` form.
- **Docs and overlay.** ADR090 D4 now has the w10/033 amendment: what is admitted, what is refused and why the session branch is safe (environment deployment-branch rules still apply). The refused list, the refusal and the overlay bullet are updated, as are ADR047 D2 (`gh` writes), ADR026 § 2 and `lego/agent-image/README.md`. The overlay's `githubCliLine` (`lego/agent-image/driver/src/overlay.ts`) says `gh` "runs a workflow on your branch (`gh workflow run <workflow> --ref <branch>`), never on another ref", with the session's branch filled in.
- **Not done together with w10/034.** 034 needs a decision on what a session may do to its own pull request, and touches other code: the D3 verb, the `bex` MCP tool, the session's merged state on REST, GraphQL and MCP. 033 is one route rule. The two share only ADR090 D4's refused list and the overlay sentence, both edited here, so 034 starts from this text.
