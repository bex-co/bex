# A workspace admin cannot change an agent session's `gh` binding after it starts, while Devin's profile is "changed later from the session's settings"

Why: an admin who started a session with `gh` off, or on, has to start a new session to change it, where Devin changes a running session's security profile from its settings.

- **Today.** `agentConfig.githubCli` is set on `POST /v1/agent-sessions`, GraphQL `createAgentSession` and MCP `create_agent_session` only ("set at create only", ADR047 D2's w10/m561 amendment). No update verb takes it, and the session level's `gh` refusal says "start a new session without `--github-cli off` to have gh".
- **Devin** ([Security profiles](https://docs.devin.ai/product-guides/security-profiles), read 2026-11-23). A session's profile is "chosen for an individual session when it's created (via the options menu in the session start box), or changed later from the session's settings". Changes reach "existing sessions the next time they resume". Only "Manage security profiles" may change it, as w10/044 made bex's rule.
- **Done when.** A workspace admin changes a session's binding (inherit, on, off) on REST, GraphQL, MCP, the CLI and the session's settings in the dashboard. A member's change is refused `AGENT_SESSION_GITHUB_CLI_LOCKED` (`admin_required`), and an on under a mandatory off is refused (`mandatory`). The next `gh` mint and the next dispatch follow the change, and a child still only tightens its tree. The session level's refusal text and ADR047 D2 say how to change it, and tests pin each surface.

No REST, GraphQL, MCP or CLI verb and no dashboard surface changes a session's binding. Devin's page, re-read 2026-11-23, still says "changed later from the session's settings". Its API pins a profile to a session only at create.
