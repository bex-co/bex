# 029 — The mobile app's session composer cannot choose the model

Why: since w10/m516 a session's model can be chosen from the platform catalog on REST, GraphQL, MCP, the CLI and the dashboard, but the phone composer still starts every session on the agent's default, so a person on the phone cannot run a bug hunt on a stronger model or see which model will run. Found by the w10/m516 Devin comparison (t007). Severity: minor (parity across bex's own surfaces). Surface: `mobile/src/features/agent-sessions/composer/session-composer-screen.tsx`, `mobile/src/features/agent-sessions/api/agent-sessions.graphql`.

## Current state (2026-11-19)

The mobile composer's capabilities query reads each agent's `id` and `modelKeyReady` only, and its create sends no `agentConfig.model`. The capabilities read already returns each agent's `model` and `models`.

## End state

The phone composer shows the model the chosen agent runs and, where the agent offers a choice, lets the person pick another catalog model; the session starts on it (`agentConfig.model`). A fixed-model agent shows its model without a choice, and a workspace on its own key shows nothing new.

## Done (2026-11-20)

The phone composer's capabilities query reads each agent's `model` and `models`, and a model pill sits beside the agent pill (`mobile/src/features/agent-sessions/composer/session-composer-screen.tsx`, logic in `compose.ts` `modelControl`/`sentModel`). A catalog agent's pill opens a picker of its `models` with the default marked; the create names `agentConfig.model` only for a non-default pick; a fixed-model agent's pill shows its model with no chevron; an agent with no `models` shows no pill; switching agent starts on the new agent's default; a pick an admin has since turned off (w10/m527) falls back to the default and is not sent. The pill row now wraps instead of truncating, so w10/031's sandbox pill can join it. Also: both composer pickers' Done/Cancel are translated, and the scope-policy allowlist admits the two fields.

Checked on production as the QA user in `tian-personal` (no session started): the mobile `MobileAgentSessionCapabilities` document returns `claude` with the four catalog models (default `deepseek/deepseek-v4.1-flash-1017`), `deepseek` with one fixed model and `codex`/`gemini` with none, so all three pill shapes occur; the mobile `MobileCreateAgentSession` document naming `claude-opus-5-5` is refused with `AGENT_SESSION_MODEL_NOT_OFFERED` on `agentConfig.model`, and no session was created. A session starting on a picked catalog model through the same `createAgentSession` input was verified by w10/m516 (`ags-dbvllsp0rfcc73dnr740`). Not exercised on a device; mobile `yarn test`, `bundle:ios` and `bundle:android` pass.
