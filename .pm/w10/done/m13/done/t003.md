## Objective

Make `git commit` and `git push` work for the agent out of the box, with a deliberate author identity.

## Context

- The image has no gitconfig. The driver passes `-c user.name/-c user.email` only on its own commit (`delivery.ts:359-376`). An agent commit falls back to `bex@<podname>` or fails with "unable to auto-detect email address". `scripts/verify-sandbox-isolation.sh:576-577` sets `git config` by hand for exactly this reason.
- `ensureRepo` (`delivery.ts:306-334`) already clones and sets `origin` to the credential-free Pod-bound proxy URL (`agentsession/contract.go:83-98`).
- Defaults: `BEX_AGENT_GIT_NAME` / `BEX_AGENT_GIT_EMAIL` ("bex agent" / "agent@bex.co", `config.ts:260-271`). Producer: `agentsessions/service.go` `driverEnv` 1324-1367.

## Steps

1. In `ensureRepo`, after checkout, write repo-local `user.name` / `user.email` from config, plus `push.default=current` and the branch upstream (`branch.<b>.remote=origin`, `branch.<b>.merge=refs/heads/<b>`), so plain `git push` targets the bound branch.
2. Decide and implement the requester co-author in ADR090 (Copilot pattern: authored by the agent identity, `Co-authored-by` the requesting user when their GitHub noreply email is known). If the requester's email is not available, record the gap in ADR090 and skip.
3. Stop hardening the agent's own Git. Repo hooks now run as they would for a developer; this is intended, and the agent already runs tenant code. The hardened `git()` wrapper stays only for the driver's setup-phase calls.

## Files

## Acceptance criteria

- [ ] Hermetic test: after `ensureRepo`, a plain `git commit -m x && git push` from the worktree lands on the bound branch of the local origin, with the configured author.
- [ ] No credential appears in `.git/config` (proxy URL only).

## Out of scope

- Gateway rejection of non-fast-forward pushes (ADR090 D7 follow-up).
