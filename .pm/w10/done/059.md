# 059 — On a cold load of a session's page, the Terminal button appears only after the capabilities query answers, so the header's action row reflows

Why: from 640 px up the session header first paints Files, Connect and "…", then inserts Terminal between Files and Connect once a separate client query answers, so the row a person is about to click moves under them on every first visit. Found by w10/m615 t007's Devin walk on production, 2026-11-24. Severity: minor (layout shift). Surface: `dashboard/src/features/agent-sessions/components/session-detail-header.tsx` (`useSessionTerminalOffered`, the `terminalOffered ? <SessionTerminalSheet …/> : null` beside `SessionFilesButton`).

## Observed (2026-11-24, pin `19638322178a`)

At 1280 px, an accessibility snapshot taken as `/agents/<id>` finished loading in a fresh browser listed `button "Files"`, `button "Connect"`, `button "More actions"`. The next snapshot on the same page listed `button "Files"`, `button "Terminal"`, `button "Connect"`, `button "More actions"`. The session was a disposable `tian-personal` session, deleted afterwards. The shift's size and duration were not measured.

## Cause

Connect renders from the session's own `sshAddress`, which the page already has (`OpenInZedButton`, `if (!session.sshAddress) return null`). The Terminal renders from `agentSessionCapabilities.terminalEnabled`, a client `useQuery` (`use-agent-session-capabilities.ts`, `cache-first`) that the route loader does not prime. Until it answers, `terminalOffered` is false and the button is absent.

## End state

On a cold load at 1280 px, the header's action row has the same buttons in the same places from first paint to ready. Options include priming the capabilities query in the route loader, or rendering the button from data the page already has and leaving `terminalEnabled: false` to the sheet's own refusal (`agentSessions.terminalUnavailable`). Below 640 px, the "…" menu item follows the same rule. A dashboard test renders the header with the capabilities query pending and finds the Terminal button, or the loader primes the query and a test asserts that.

## Done (2026-11-24)

The `/agents/<id>` route loader (`dashboard/src/routes/agents_.$agentSessionId.tsx`) now warms the capabilities read the header's Terminal renders from, through `warmAgentSessionCapabilities` (`use-agent-session-capabilities.ts`). It uses the same document, variables and `cache-first` policy as the hook. The selected workspace's read starts beside the session's, so the browser sends both in one batch. A session from another workspace warms its owner's read once the session names it. A refused or failed read is swallowed, and the header's own query asks again. The read is in the Apollo cache that SSR renders from and that hydration restores, so the Terminal is in the server's HTML. The gate stays as ADR054 D10 has it: no Terminal where `terminalEnabled` is false.

Browser check (Playwright, dev server against a scratch copy of the `local-bex` stub outside the repo, filling the session fields the page reads and holding the capabilities answer 2.5 s; header buttons sampled every frame from navigation for 10 s):

- Before, at 1280 px: `Files@1010 Connect@1096 More actions@1228`, then at 3.2 s `Files@897 Terminal@984 Connect@1096 More actions@1228`. The repro, with Files moving 113 px.
- After, at 1280 px: `Files@897 Terminal@984 Connect@1096 More actions@1228` from the first sample at 31 ms, unchanged to 10 s, with no hydration error.
- After, at 390 px: `Files@218 Connect@268 More actions@338` throughout, and the "…" menu lists Terminal first.
- Client navigation from `/env-groups` with nothing cached: the route skeleton, then the header with all four buttons in their places at once.

`agent-session-detail-terminal-warm.test.tsx` runs the loader against a real Apollo cache and server-renders the header's Terminal gate from it, for the selected workspace, another owner, no selection, and a refused read. Without the loader change, three of its four tests fail. `route-heads.test.ts` now expects the warm read beside the title read. `yarn lint` and the full dashboard suite pass. Production gets it with the next pin.

Not changed here: the route skeleton's action area is still one 80 px bar, against about 367 px of Files, Terminal, Connect and "…" once ready. That gap was there before m615.
