# Fix operator Secret-watch RBAC crash loop

Production incident observed 2026-07-15 while deploying `beancount-cms-v2`: the
operator repeatedly exits after its controller-runtime cache cannot synchronize.
`KeyValueReconciler.SetupWithManager` owns `corev1.Secret`, which starts a
cluster-wide Secret informer, but `bex-controller-manager` intentionally has no
cluster-wide Secret read permission; only the apps namespace grants Secret
`get/list/watch`. The resulting `secrets is forbidden` error prevents every
controller cache, including `App`, from starting. Deploy
`dep-d9bj8s3eg85c7390eba0` consequently created no build Job and timed out as
`update_failed` after three minutes.

Fix the KeyValue Secret watch without broadening Secret RBAC beyond the existing
namespace-scoped least-privilege boundary. Add regression coverage proving the
manager starts and reconciles Apps while KeyValue Secret events still enqueue the
owning KeyValue in the configured apps namespace. Verify `make test` from
`lego/operator/`, deploy the corrected operator, confirm the controller remains
stable with zero Secret-list denials, then retrigger `beancount-cms-v2` and observe
its deploy reach `live`.

Promoted to `w10/m1` on 2026-07-15.
