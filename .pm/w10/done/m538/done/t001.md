## Steps

1. Pick the tool names and inputs: ready takes no input, and merge takes an optional `method` and optional commit title and message. Pick the gateway path segments and the internal paths and kinds.
2. Verify against GitHub, with a QA repository or the docs:
   - the installation permissions a merge needs, including a PR that changes `.github/workflows/`;
   - the REST `PUT …/pulls/{n}/merge` versus the asynchronous merge API;
   - that `markPullRequestReadyForReview` is the only way to undraft;

3. Map GitHub's answers to typed refusals: 405 not mergeable (checks, reviews, conflicts), 409 head moved, 422 method not allowed or validation, 403. Write each one's hint. Keep `no_pull_request` and `pull_request_closed`.
4. Decide the takeover case and record why.
5. Amend ADR090 D2, D3 and D4 (the refused list and the refusal text name the new tools), ADR047 D2, and `lego/agent-image/README.md`, citing the Devin evidence.
