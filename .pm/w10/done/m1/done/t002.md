## Objective

Implement the namespace-safe Secret event path selected in t001 so the shared
manager cache can synchronize and KeyValue-owned Secret changes still enqueue the
correct resource.

## Context

- The manager watches CRs and workloads cluster-wide but may read tenant Secrets
  only through the apps namespace Role.
- Removing the Secret watch without a replacement would hide credential Secret
  drift from the KeyValue reconciler.
- Adding Secret verbs to `bex-manager-role` would violate the intended security
  boundary and is not an acceptable fix.

## Steps

1. Replace the cluster-wide Secret ownership watch with the namespace-scoped
   mechanism designed in t001.
2. Preserve owner-reference mapping, predicates, and reconciliation behavior for
   KeyValue credential Secrets.
3. Keep generated/deployed RBAC free of cluster-wide Secret read verbs.
4. Run focused controller and RBAC tests while iterating.

## Files

- `lego/operator/internal/controller/keyvalue_controller.go`
- `lego/operator/cmd/manager/main.go`
- `lego/operator/config/rbac/`
- `deploy/gitops/base/operator-apps-rbac.yaml`

## Acceptance criteria

- [ ] The manager no longer requests a cluster-wide Secret informer.
- [ ] A KeyValue-owned Secret event in the apps namespace enqueues its owner.
- [ ] The manager ClusterRole still cannot get, list, or watch Secrets.
- [ ] Focused operator tests pass.

## Out of scope

- Refactoring unrelated controller watches.
- Expanding operator access to Secrets in build, auth, or platform namespaces.
