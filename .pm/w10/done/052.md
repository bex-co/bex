# 052 — After a session's pull request is merged or closed, the next turn's overlay still says "there is never a second one", though `open_or_update_draft_pr` opens a new pull request

Why: the overlay tells the agent something false at the moment it decides how to deliver follow-up work, and the agent spends reasoning reconciling it with the user's "open a new pull request". Found by w10/m577 t005's live run on production, 2026-11-23. Severity: minor. Surface: `lego/agent-image/driver/src/overlay.ts` (`existingPrLine`), `lego/backend/internal/agentsessions/service.go` (the driver env for a steering turn).

## Observed (2026-11-23, pin `ac882b5f557f`)

Session `ags-dc22fn6hv52s73bqmme0` in `tian-personal` merged its pull request #1 in turn 1 (GitHub auto-merge). Turn 2's overlay still read "Earlier turns of this session already opened pull request #1 (…/pull/1). Calling `open_or_update_draft_pr` updates it; there is never a second one." The agent's reasoning stalled on it: "the platform says earlier turns already opened PR #1 … there is never a second one. But the user asks to 'open a new pull request'." It then called `open_or_update_draft_pr`, which answered `created: true` with #2, a new pull request on the same session branch.

## Current state

- `service.go` (around line 1804) sets `BEX_AGENT_PR_URL`/`BEX_AGENT_PR_NUMBER` from the session's recorded pull request whatever its `prState`.
- `existingPrLine` (`overlay.ts:127`) always says the call updates it and that there is never a second one.
- The PR verb opens a new pull request when the recorded one is merged or closed.

## End state

When the recorded pull request is merged or closed, the overlay says so, for example "Earlier turns opened pull request #1, which is merged; calling `open_or_update_draft_pr` after new pushes opens a new pull request". It keeps today's sentence only for an open one. The driver learns the state from bex-api, for example a `BEX_AGENT_PR_STATE` env beside the URL. A driver test covers open, merged and closed, and a backend test covers the env.

## Outcome

- **Backend.** `driverEnv` (`lego/backend/internal/agentsessions/service.go`) passes `BEX_AGENT_PR_STATE` beside `BEX_AGENT_PR_URL` and `BEX_AGENT_PR_NUMBER`: `open`, `merged` or `closed` as bex last read it (the PR-state poller, the `pull_request` webhook, or the merge verb). A state bex has not read yet is left out, and the driver reads an absent or unknown state as open, as an older bex-api meant.
- **Overlay** (`lego/agent-image/driver/src/overlay.ts`). For an open pull request the line stays "Calling `open_or_update_draft_pr` updates it; there is never a second one." For a merged or closed one it reads "Earlier turns of this session opened pull request #1 (…), which is merged. Calling `open_or_update_draft_pr` after you push new commits opens a new pull request for them." The `gh` line then names `<number>` ("`open_or_update_draft_pr` returns your new one as `number`") instead of the merged one's. "Follow-up turns" says the tool updates the pull request while it is open and opens a new one once it is merged or closed. A takeover whose pull request is merged or closed is told the verb answers `pull_request_closed` and its commits stay on the session branch.
- **Delivery check** (`delivery-check.ts`). An earlier turn's merged or closed pull request no longer stands in for commits this turn pushed: they are nudged ("has pushed commits but no pull request was recorded"), while a turn that pushed nothing still counts it.
- **Devin.** One Devin session can open more than one pull request (its metrics "now shows all PRs opened by Devin, even when 2+ PRs were opened in the same session", [release notes, 2025-02-26](https://docs.devin.ai/release-notes/2025)). bex already did this; only what the agent is told changed.
- **Docs.** ADR090 D3 (w10/052 bullet) and the agent-image README's env table.
- **Tests.** Driver: `overlay.test.ts` (open and unread give the same text, merged, closed, takeover merged and closed), `github-cli.test.ts` (merged), `delivery-check.test.ts` (merged and closed, before and after a push) and `driver.test.ts` (parsing). Backend: `TestDriverEnvNamesThePullRequestState` (unread, open, merged, closed). Each fails with the fix reverted.
- **Not walked on production.** The end state asks for tests. The next steering turn after a merge on a pin carrying this commit shows the new line.
