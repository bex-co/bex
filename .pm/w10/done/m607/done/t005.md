## Objective

A markdown file growing toward the 1 MiB blob limit is caught early, with "split it" as the message, instead of by the hard refusal or a red main.

## Context

- `scripts/repo-artifact-guard.sh` refuses any blob of 1 MiB or more (user decision 2026-11-04, w6/100 D10); `scripts/ship-gates.sh` runs it over `base..HEAD`, `.github/workflows/repo-artifact-guard.yml` over HEAD's tree and each push's range. Raising that limit or exempting a file is not the fix.
- w10/053's `d2d63d5cda` reached main with ADR018 over the limit; the incident record is in [w10/054](../../054.md).
- Suggested numbers: warn at 512 KB, refuse at 768 KB, over every tracked `*.md` (docs and `.pm` READMEs alike). That leaves roughly five days at ADR018's November growth between refusal and the hard limit. Record the numbers chosen and why.
- `.pm/w4/README.md` (492,937 bytes on 2026-11-23) is the first file the warning reaches: file a note for splitting or trimming it, do not exempt it.

## Acceptance criteria

- [x] The guard's self-test (beside `repo-artifact-guard.sh`'s, or its own) covers under, warning band and over.
- [x] `bash scripts/ship-gates.sh` and the CI workflow run it; the message names the file, its size and the split remedy.

## Done (2026-11-23)

- `scripts/repo-artifact-guard.sh` refuses a tracked `*.md` of **768 KiB** (786,432 bytes) or more and warns from **512 KiB** (524,288). On a GitHub runner the warning is also a `::warning file=…` annotation. The size counted is the file at HEAD: every `*.md` in the HEAD-tree form, which CI runs; in the range form, which ship-gates and CI's push step run, those a pushed commit adds or changes. The refusal names the file, its size and the remedy (split it into files of its own, leaving a pointer, as `docs/ADR018/` did; a board README moves finished history out instead).
- Why these numbers: ADR018 grew 40–50 KB a day in November. The 256 KiB warning band is about five days of that growth to split, and the refusal leaves 256 KiB for the push that does the split. The 1 MiB hard limit and its decision (w6/100 D10) are unchanged.
- No file is in either band on `origin/main` today. `.pm/w4/README.md` (493,013 bytes, about 6 KB a day) reaches the warning first, so it is filed as [w10/058](../../058.md), not exempted.
- `scripts/repo-artifact-guard.test.sh` covers under the band (silent), the warning band (passes, names the file and size, and annotates on Actions), over (refused with the remedy, in both forms), the range form ignoring a markdown file it does not change, and a file split later in the range passing. Against the old guard the warning case fails. `scripts/ship-gates.sh` and `.github/workflows/repo-artifact-guard.yml` already run the guard in both forms; their header comments now say so.
