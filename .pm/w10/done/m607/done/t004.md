## Objective

No link into the parity ledger dangles after the split, and the docs link gate keeps it that way.

## Context

- On 2026-11-23 the repository uses 13 distinct anchors into ADR018 (`git grep -ohE 'ADR018-render-parity\.md#[A-Za-z0-9_-]+' | sort | uniq -c`): `#deployment-sources--iac` (10), `#render-operation-omissions` (4), `#other-datastores--storage` (3), `#bex-ahead-of-render` (3), `#environment--config`, `#deploys`, `#api-contract` (2 each), `#sandbox-create-flags-w2m263`, `#managed-postgres`, `#list-query-census-w4164-2026-09-27`, `#gap-backlog`, `#allowlisted-response-schema-divergences-w3m272`, and a stale `#L597` (1 each).
- `scripts/docs-links-validate.sh` checks paths only ("#anchors … the heading is not checked"). It has a self-test, `scripts/docs-links-validate.test.sh`.

## Steps

1. For each anchor: keep a heading with that slug in ADR018 (a pointer) or rewrite its links to the new file's anchor. Replace `#L597` with the heading it meant.
2. Extend the link gate to check `#anchor` slugs (GitHub's slug rules) for links into `docs/ADR018-render-parity.md` and `docs/ADR018/` at least, with self-test cases for a good and a dangling anchor.

## Acceptance criteria

- [x] `bash scripts/docs-links-validate.sh` fails on a dangling anchor into the ledger and passes on the tree.
- [x] Every anchor in the list above resolves.

## Done (2026-11-23)

- Every anchor in the list resolves. ADR018 kept every `## ` and `### ` heading as a pointer (t002), so no inbound link needed a rewrite. The stale `#L597` (in `.pm/w5/done/m582/README.md`) meant the `recover-postgres` `environmentId` paragraph. It now links `docs/ADR018/render-operation-omissions.md#render-operation-omissions`. - `scripts/docs-links-validate.sh` checks `#anchors` into `docs/ADR018-render-parity.md` and `docs/ADR018/`, and same-file anchors inside them, against GitHub's slugs of the target file's headings (repeats get `-1`, `-2`; fenced code is skipped) and its `<a id>`/`<a name>`. A miss is reported as `file:line -> target (no such heading in <file>)`. Anchors into other documents are still unchecked, as before. `scripts/docs-links-validate.test.sh` covers a good tree (heading, repeated heading, code-span heading, `<a id>`), an anchor that names no heading, one whose heading lives in another ledger file, a same-file miss, a heading inside a fence, and an anchor into an unchecked document.
