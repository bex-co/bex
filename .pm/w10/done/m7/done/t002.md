## Objective

Every user-visible string in the CLI-authorize flow says "bex CLI", never "Render CLI": document titles, page headings/subtitles, the device-success terminal replica copy, and both locale files. Internal identifiers/comments that name the upstream `render-oss/cli` client (e.g. `RENDER_CLI_CLIENT_ID`, code comments, the hydra-consent trusted-client test) stay accurate and are NOT renamed — the sweep is user-facing copy only.

## Context

- Known "Render CLI" user-visible strings: `dashboard/src/features/auth/locales/en.ts:234-239` (`auth.deviceSuccessTitle` "Render CLI connected", `auth.deviceTitle` "Connect Render CLI") and the zh mirrors at `zh.ts:231-236`.
- `dashboard/src/common/lib/document-head/__tests__/route-heads.test.ts:87-95` asserts those exact titles in en + zh — update expectations in lockstep.
- `dashboard/src/features/auth/pages/device-success-page/index.tsx` — check the animated terminal transcript and hint copy for "render"-branded lines (the CLI binary users run is `bex`, per `docs/bex-cli.md`).
- Branding rule: the launcher wraps the upstream Render CLI unmodified (DO_NOT_DO: no fork), but the product surface is `bex` (`lego/cli/`, ADR058) — user-facing copy follows the product name.
