## Objective

Replace the token quota with a per-workspace monthly USD spend cap checked at mint time, plan defaults Hobby $20 / Pro $200 / Scale $2,000, admin-adjustable up to 10×, with a $10 trust-ramp cap until the first successful agent-model charge.

## Context

- ADR091 D5, D10.1 trust tiers (amended 2026-11-02).
- Webhooks: `lego/backend/internal/billing/lifecycle.go:187` handles `invoice.paid` / `invoice.payment_failed`; `stripe_billing_events` stores no amounts and is purged after 90 days, so tiers need their own durable record.
- Shipped quota path: mint check + `ReportQuotaExceeded` in `lego/backend/internal/agentsession/modelusage.go`, code `AGENT_MODEL_QUOTA_EXCEEDED`, `failureReasonCode` on the session.

## Steps

1. `pricing.yaml`: `agentModel.monthlySpendCapUsd[]` per plan; the trust tier table (`agentModel.trustTiers[]`: reach conditions, charge threshold, cap ceiling, concurrent sessions); remove `monthlyTokenQuota[]`.
2. Migration: `billing_trust` (workspace, lifetime paid cents, paid cycle invoices, tier, lock-until).
3. Feed it from webhooks: `invoice.paid` with `amount_paid > 0` adds to the counters; `invoice.payment_failed` and `charge.dispute.created` (new handler) drop the workspace to T0 and lock it for 30 days after settlement. The tier is a pure function of counters + table.
4. Store a per-workspace cap override (nullable) with admin-only write on REST/GraphQL/MCP, bounded to 10× the plan default.
5. Effective cap = min(override or plan default, tier cap). Concurrent platform-model sessions are limited by the tier (T0: 2).
6. Mint: month-to-date `agent_model_cost_microusd` ≥ effective cap → 429 `AGENT_MODEL_SPEND_CAP_REACHED` (rename the shipped code).
7. Emit a tier-changed signal that t014 uses to update the Stripe item threshold.
8. Ops alert at 80% of the OpenRouter key credit limit (platform-wide spend); document the credit-limit console step for the user.

## Implementation notes (2026-11-05)

- Sheet: `pricing.yaml` `agentModel.monthlySpendCapUsd` (Hobby 20 / Pro 200 / Scale 2000; enterprise and unknown plans take the top cap), `maxCapMultiplier: 10`, `trustTiers` T0..T4; `monthlyTokenQuota` and the token-quota check are gone. `pricing.TrustTier(lifetimePaidCents, paidCycleInvoices, lockedUntil, now)` is the pure tier function.
- Store (migration 0194): `billing_trust` + the per-invoice ledger `billing_trust_invoices` (webhook redelivery never double counts); `agent_environments.agent_model_spend_cap_override_microusd` (micro-USD, the meter's unit). A failed invoice sets `locked_until = 'infinity'` and `failed_invoice_id`; only that invoice's payment (paid at or after the failure) turns it into `paid_at + 30 days`. Another invoice's payment or an older one never unlocks; a failure for an invoice already paid is ignored. A dispute sets `dispute_id`, its own hold, cleared only by `charge.dispute.closed` with status `won` for that dispute (`won_dispute_id` stops a late creation re-locking). A lost dispute keeps T0 until ops runs `UPDATE billing_trust SET dispute_id = NULL WHERE workspace_id = '<ws>'`. Indexes: partial `usage_hourly (workspace_id, kind, window_start) WHERE resource_kind = 'agent_session'` and `agent_sessions (workspace_id) WHERE phase IN (active phases)`.
- Webhooks: `billing.Trust` reduces `invoice.paid` (amount_paid > 0; cycle = `subscription_cycle`), `invoice.payment_failed`, `charge.dispute.created` and `charge.dispute.closed` (Charge re-read from Stripe → customer → `billing_provider_mappings`). Both dispute events are in `HandledStripeEventTypes` and `scripts/stripe-billing-setup.py`; run `scripts/stripe-billing-setup.py --add-missing-webhook-events` (test and live) before relying on dispute intake.
- Mint: `AGENT_MODEL_SPEND_CAP_REACHED` (429, refusal header `model-spend-cap-reached`, failure cause `spend_cap_reached`) replaces `AGENT_MODEL_QUOTA_EXCEEDED`. `store.AgentSpendInputs` reads plan + trust + override + month-to-date in one query; the mint caches the result per workspace for 20s (settings reads are uncached). An override above the plan's 10× bound (plan downgrade) is clamped. The session failure reason names the cause (new-workspace limit, failed/disputed payment, monthly cap). Admission: `AGENT_SESSION_TRUST_LIMIT` (409) for a platform-route claude session beyond the tier's live-session limit; create counts and inserts under a per-workspace advisory lock (`AgentSession.AdmissionLimit`), steer/resume pre-check excluding the session itself. `CountActiveAgentSessions` serves both this and the live-sandbox cap.
- Settings surface: the existing agent environment (REST `PATCH /v1/agent-environment`, GraphQL `updateAgentEnvironment`, MCP `update_agent_environment`) takes `agentModelMonthlySpendCapUsd` (admin-only, 0 < v ≤ 10× plan, `AGENT_ENVIRONMENT_SPEND_CAP_INVALID`); null (REST/MCP) or `resetAgentModelMonthlySpendCap: true` (all surfaces; graphql-go cannot carry an explicit null) clears it. Reads add the effective/plan/override/max cap, month-to-date spend, `trustTier` and `nextChargeThresholdUsd`.
- Tier-change signal: `billing.Trust.OnTierChanged` (bex-api logs the change today; t014 consumes it). A lock expiring changes the tier without a webhook, so t014 must also read the tier when it reconciles.
- Ops: bex-api polls `GET https://openrouter.ai/api/v1/key` every 10 minutes with the platform key, exports `bex_agent_platform_model_credit_{limit,usage}_usd`, and `PlatformModelCreditHigh` warns at ≥ 80% (panel on the bex-api dashboard).
- **User/ops console step (not code):** set the credit limit on the platform OpenRouter key in the OpenRouter console (Settings → API Keys → the key → credit limit). Until a limit is set the gauge reads 0 and the alert cannot fire.
