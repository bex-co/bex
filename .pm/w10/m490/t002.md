## Objective

A GitHub App-signed push reaches every service and Blueprint whose stored repository id equals the payload's `repository.id`, whatever URL they stored. URL matching stays only for rows with no id and for deliveries that carry no installation.

## Context

- `gitRepository` (`lego/backend/internal/apps/webhook.go:221`) decodes `clone_url`, `ssh_url`, `html_url` and `url`, but not `id`.
- `repoCandidates` (`:948`) and `blueprintAutoSyncTargets` (`:875`) both call `repoURLsMatch` (`:1177`).
- Scope: an App-signed delivery is confined to its installation's workspace (`scope`, codex #7, w1/m65 F2). Id matching must keep that confinement.
- A manual push webhook or a Gitea one carries no `installation` (`Installation.ID == 0`) and no GitHub id; it stays URL-only.
- Replay protection and `commit_ignored` are unchanged: the candidate list is the only input that changes.

## Steps

1. Decode `repository.id`.
2. Match by id within the delivery's scope when the delivery is App-signed and the row has an id; otherwise fall back to today's URL match.
3. Apply the same rule to Blueprint auto-sync targets.

## Files

- `lego/backend/internal/apps/webhook.go` and its tests

## Acceptance criteria

- [ ] A push whose payload names `owner/new-name` with the stored id reaches an App that stores `owner/old-name`; the same test fails on today's code.
- [ ] The same push reaches a Blueprint on the old name.
- [ ] An App in another workspace with the same id is not reached by a delivery from this installation.
- [ ] A manual-webhook push still matches by URL only.

## Out of scope

- Changing the stored URL (t003).
