## Objective

Exercise the corrected manager under production-equivalent RBAC in w10's isolated
development stack and prove both the previously blocked App path and the changed
KeyValue Secret-event path reconcile end to end.

## Context

- The production failure in one Secret informer prevented all controller caches,
  so KeyValue-only verification is insufficient.
- `.pm/w10/dev-10/` is the workstream's isolated stack and must be used instead of
  shared default namespaces or ports.
- The failed production deploy never created a build Job or populated App status.

## Steps

1. Start or refresh `.pm/w10/dev-10/` with the corrected operator and
   production-equivalent Secret permissions.
2. Hold the manager stable long enough to pass its cache-sync timeout and confirm
   logs contain no Secret-list denial.
3. Create or update a repo-backed App and confirm status initialization plus build
   Job creation.
4. Mutate/recreate a KeyValue-owned Secret and confirm the owning KeyValue
   reconciles without polling-only behavior.

## Files

- `.pm/w10/dev-10/`
- `lego/operator/internal/controller/`
- `deploy/gitops/base/operator-apps-rbac.yaml`

## Acceptance criteria

- [ ] The manager remains running with zero cache-sync or Secret RBAC errors.
- [ ] A repo-backed App advances far enough to create its build Job.
- [ ] A KeyValue Secret event triggers owner reconciliation in the apps namespace.
- [ ] No shared workstream namespace or standard port is used.

## Out of scope

- Production deployment or mutation.
- Application-specific debugging after a build Job starts.

## Completion evidence

- The restricted service account could list Secrets in `dev-10` but not across
  namespaces; the corrected manager synchronized and became Ready.
- Repo-backed App `w10-secret-cache-app` entered `Building` and created Job
  `bld-w10-secret-cache-app-gen-1` in the configured build namespace.
- KeyValue `w10-secret-cache-kv` reached `Ready`; mutating its owned Secret changed
  the resource version and immediately emitted `keyvalue reconciled` for the owner.
- The transient resources and namespace were removed after verification. The shared
  CAPD cluster had unrelated post-OrbStack CNI/API instability, so durable manager
  startup and zero-restart behavior is additionally asserted by the production-shaped
  envtest in t005.
