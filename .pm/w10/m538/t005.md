## Objective

Verify DoD 6 on production once a deploy carries the milestone.

## Context

- Production runs the milestone once the newest `chore(deploy): pin platform images to <sha>` on `origin/main` contains its commits. Park with that pin gate until then.
- The sandbox node is near capacity (w9/m349), so run one or two short sessions.
- Use a QA repository in `tian-personal`, the QA account's GitHub-connected workspace (not a customer's repository or `bex-co/bex`). Give its default branch a required status check from a small workflow. Never revoke the shared QA account's OAuth grants or consent sessions.

## Steps

1. Start a session with the task "make a one-line change, open the PR, and merge it once CI is green". Check that it opened a draft, waited for the required check, undrafted and merged its own pull request as the App's bot, and that REST, GraphQL and MCP read `prState: merged`.
2. In the same session, or a second one, have the agent try the merge while the check is still pending: GitHub's refusal reaches it under the typed code. Then have it try `gh pr merge`, which is refused naming the tool.
3. Check that the calls were audited. Record the session ids, pull request numbers and outcomes in the milestone README, then delete the sessions and the repository.

## Acceptance criteria

- [ ] DoD 6 holds and is recorded with the ids.

## Out of scope

- Self-hosted Apps without `contents` write (covered by tests).
