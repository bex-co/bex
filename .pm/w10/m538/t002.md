## Objective

Implement t001's two bex-api internal verbs and the GitHub client calls behind them. Each one acts only on the session's recorded pull request, and a merge records the merged state immediately.

## Context

- `lego/backend/internal/agentsession/pullrequest.go` (`PullRequester.sessionTarget`, the live-generation check, audit) and `pullrequest_comment.go` (the kind-tagged verb to copy).
- `lego/backend/internal/github/pulls.go` (`SyncDraftPullRequest`), `client.go` (`mintRepositoryToken`, `grantedPermissions`), and `feedback.go:220` (`GetPullRequest`).
- `store.RecordAgentSessionPRState` (`lego/backend/internal/store/agentsession_pr_state.go:75`) and the poller in `lego/backend/internal/agentsessions/pr_state.go`.
- Handlers mount on `:8091` in `lego/backend/cmd/api/main.go`, beside `InternalPullRequestCommentPath` (`:1385`).

## Steps

1. GitHub client:
   - `MarkPullRequestReady`: GraphQL `markPullRequestReadyForReview` with the PR's node id, through a token narrowed to the repository.
   - `MergePullRequest`: the merge call t001 chose, with `sha` set to the recorded head and the method chosen by t001's rule. It mints its token with t001's permissions and the w10/014-style fallback. It returns GitHub's status and message as typed errors.
2. Add the verbs with their handlers and clients, each of which:
   - checks the identity;
   - runs `sessionTarget`;
   - answers `no_pull_request` when the session has no `prNumber`;
   - re-reads the PR and refuses a closed or merged one;
   - calls GitHub;
   - maps GitHub's refusals to t001's codes;
   - audits as its own verb, allowed or denied, with the repository.
3. On a successful merge, call `RecordAgentSessionPRState(merged)` so REST, GraphQL and MCP read it at once. A failed record is only logged, as the PR verb does.
4. Unit tests with a fake GitHub for every refusal and both successes, plus a real-Postgres test for the merged state.
