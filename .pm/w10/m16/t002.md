## Objective

The durable transcript stores one row per completed item. Live delivery still forwards chunks unchanged.

## Context

- **Gateway tee:** `lego/backend/internal/sshgateway/agentattach/agentattach.go` (`spliceDriverStream`) writes every live part to `agent_session_transcripts`.
- **Completer harvest:** `lego/backend/internal/agentsessions/completion.go` `parseTranscriptLog` + `filterPartsByQuota`.
- **Replay:** gateway replay re-frames stored parts as AI-SDK chunks.
- **Prior art:**
  - Vercel AI SDK persists final `UIMessage` parts.
  - Codex App Server persists `item/completed` items.
  - ACP `session/load` replays chunks, but clients merge them.

## Steps

1. Add a shared coalescer: chunk stream → items.
   - `text-*` → one `text` item; `reasoning-*` → one `reasoning` item.
   - `tool-input-start/available` + `tool-output-available/error` + ACP `data-acp-info` updates for one `toolCallId` → one `tool` item (input, output, status, title, timestamps).
   - `data-acp-usage-update` → last value per turn.
   - transient parts → never stored.
2. The tee writes an item when it completes. An in-flight partial item is buffered and flushed as incomplete on disconnect or turn end.
3. Harvest uses the same coalescer over the driver log, so the two paths agree. Dedup is keyed by turn-local item index.
4. Replay emits each stored item as the minimal AI-SDK chunk sequence (e.g. `text-start` + one `text-delta` + `text-end`). There is no new wire type.
5. Decide whether the driver log should also be item-level, and record the choice in ADR051.
