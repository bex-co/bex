## Objective

A hard reload of a long terminal session renders the whole transcript.

## Context

- **Root cause:** React error #185 (maximum update depth) inside `useChat` during the burst replay. Each chunk is a synchronous store update. `@ai-sdk/react@3.0.243` and `ai@6.0.241` are pinned.
- `dashboard/src/features/agent-sessions/components/session-conversation-impl.tsx:175`: the `useChat` options have no `throttle`. The error renders only while the conversation is empty (around line 333).
- `dashboard/src/features/agent-sessions/lib/conversation-state.ts:40`: a terminal session returns `ended` before the `resuming`/busy check, so "This session ended before a conversation was recorded." shows while the replay loads.

## Steps

1. Add `throttle` (~50ms) to `useChat`. Confirm #185 is gone in a dev (non-minified) build against a recorded fixture of `ags-dbf8nggkbcjs73a5r3u0`'s 5,602-frame replay.
2. When `error` is set and messages are non-empty, show an inline "Conversation only partially loaded — Retry" row instead of silently truncating.
3. A terminal session that is still resuming/busy with no messages returns `connecting`, not `ended`.
