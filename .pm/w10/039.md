# 039 — `merge_pull_request` cannot enable GitHub auto-merge or add the pull request to a merge queue

Why: a session told "merge once CI is green" has to stay in its turn and watch the checks (`gh pr checks --watch`) before it calls `merge_pull_request`, and a repository that requires a merge queue refuses that merge outright; GitHub's own auto-merge and merge queue land the pull request when its checks pass, with no session waiting. Found by the w10/m538 Devin comparison (t006), 2026-11-20. Severity: minor (Devin parity, a variant of the shipped merge). Surface: `lego/backend/internal/github/merge.go`, `lego/backend/internal/agentsession/pullrequest_merge.go`, `lego/agent-image/driver/src/merge-pr.ts`.

## Reference

Devin Review's merge button can "enable or disable GitHub auto-merge", the merge bar "shows the current auto-merge status, including who enabled it", and `m` adds a pull request to the merge queue or enables auto-merge ([Devin Review](https://docs.devin.ai/work-with-devin/devin-review), read 2026-11-20). Devin's own `gh` token can run `gh pr merge --auto`. GitHub recommends `PUT /repos/{owner}/{repo}/pulls/{n}/merge-async` (`merge_action`: `default`, `direct_merge` or `merge_queue`; 202 with a UUID to poll, `enqueued` final for a queue), which the synchronous merge does not support ([Pulls](https://docs.github.com/en/rest/pulls/pulls), read 2026-11-20).

## Current state (2026-11-20, w10/m538)

`merge_pull_request` calls the synchronous `PUT …/pulls/{n}/merge` pinned to the recorded head (ADR090 D3, w10/m538 amendment). A merge-queue repository answers it with GitHub's refusal (`merge_blocked`). `gh pr merge --auto`, `enablePullRequestAutoMerge` and `enqueuePullRequest` are refused in the `github-api` route naming the tool.

## End state

`merge_pull_request` takes an option (for example `whenReady: true`) that enables GitHub auto-merge with the pinned head (`enablePullRequestAutoMerge`, `expectedHeadOid`) or, where the base branch requires a merge queue, enqueues it (`merge-async` with `merge_action: merge_queue`), answering `{enqueued|autoMerge: true}`; the PR-state poller or a `pull_request` webhook then records `prState: merged`. The overlay says to use it when asked to merge once checks pass. Tests cover the auto-merge call, the queue call, a repository that has auto-merge off, and the head pin.
