# 040 — A session always opens its pull request as a draft, while Devin opens a regular pull request by default

Why: a requester who wants Devin's default gets a draft they must undraft themselves (or ask the session to with `mark_pull_request_ready`), and reviewers whose GitHub notifications skip drafts do not see the pull request until then. Found by the w10/m538 Devin comparison (t006), 2026-11-20. Severity: minor (Devin parity). Surface: ADR090 D3, `lego/backend/internal/github/pulls.go` (`createPull`, `Draft: true`), the overlay's delivery steps.

## Reference

Of the 200 most recent pull requests authored by `app/devin-ai-integration` created since 2026-11-13, 6 were drafts on 2026-11-20 (the w10/m538 README's Devin evidence). Devin's GitHub integration lets Devin "create new PRs" ([GitHub integration](https://docs.devin.ai/integrations/gh), read 2026-11-20); nothing in its docs says the pull request starts as a draft.

## Current state (2026-11-20, w10/m538)

ADR090 D3 creates every session pull request as a draft and never undrafts it in the PR verb; since w10/m538 `mark_pull_request_ready` undrafts it when the task or a person asks.

## End state

Decide the default with Devin as the reference: either the D3 verb opens a regular pull request unless the task asks for a draft (for example a `draft` option on `open_or_update_draft_pr`, or a workspace or automation setting), with ADR090 D3 and the overlay amended; or ADR018 records the draft default as a signed-off divergence. A test covers the chosen default and the override.
