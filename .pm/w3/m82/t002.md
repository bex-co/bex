## Objective

Give the reconciler a truthful status source for `postgres_backup_completed` / `postgres_backup_failed`, `postgres_restore_succeeded` / `postgres_restore_failed`, and `postgres_upgrade_started` / `postgres_upgrade_succeeded` / `postgres_upgrade_failed` by projecting CNPG Backup outcomes into `Database.status` in the operator and reading phase edges the CRD already exposes.

## Context

- Backups: the operator owns the CNPG `ScheduledBackup` (`database_controller.go` `scheduledBackupSpec` ~474) and creates on-demand `Backup` objects (`cnpgBackupGVK` ~57; `upsertOwned(... cnpgBackupGVK ...)` ~1122). CNPG `Backup.status.phase` reaches `completed` or `failed` (with `error`). `Database.status` today carries only `BackupsEnabled` / `BackupServerName` / endpoint coordinates (`database_types.go` ~439–453) — no per-backup outcome. `postgres_backup_started` is already audit-derived for on-demand backups (`eventvocab/datastore.go`); leave it.
- Restore: `recover` creates a **new** Database with `SourceBackupServerName` set (`database_types.go` ~284–289; ADR009 recovery). The target reaching `Ready` is the restore success edge; `Failed` is the failure edge.
- Upgrade: `DatabasePhase` has `Upgrading`; the operator writes Ready reasons `MajorVersionUpgrade` (in progress) and `MajorVersionUpgradeFailed` (~1095–1107). Entering `Upgrading` = started; `Upgrading` → `Ready` = succeeded; `MajorVersionUpgradeFailed` = failed.
- Operator CRD changes need `make manifests` + `make generate` in `lego/operator/` (CRD YAML under `config/crd/`), and the types module is the leaf (`lego/types`).

## Steps

1. Operator: after reconciling backups, list owned CNPG `Backup` objects for the Database (label/owner selector), pick the newest terminal one, and project `Status.LastBackup {Name, Phase, StartedAt, CompletedAt, Error, Scheduled bool}` (Error is CNPG's message, never credentials). Keep the projection level-triggered and bounded (newest only).
2. Reconciler: emit `postgres_backup_completed` / `postgres_backup_failed` keyed by `<db-id>:backup:<backup-name>` so each backup projects once regardless of resyncs.
3. Reconciler: on a Database with `SourceBackupServerName` set, emit `postgres_restore_succeeded` on first `Ready` and `postgres_restore_failed` on `Failed`, keyed by the target id (once).
4. Reconciler: emit upgrade started/succeeded/failed on the phase edges above, keyed by `<db-id>:upgrade:<from-version>-<to-version>` (spec version fields).
5. Extend `eventvocab/datastore.go` with the seven constants; extend the t001 fact table if a `details` payload (backup name, versions, error) is needed for `GET /v1/events/{id}` `details`.
