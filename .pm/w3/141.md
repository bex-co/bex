# Find out whether Render's Blueprint Settings plans a sync on an Auto Sync, Branch or Path save, and open it as Render does

Why: Render's dashboard mutations behind Settings' Auto Sync, Branch and Blueprint Path rows each return a sync and open its page when one comes back; bex's `updateBlueprint` returns none, so a bex save stays on Settings, and whether Render plans there was not seen.

Filed by w3/m679 t006 on 2026-11-27.

- **Render:** `setIACAutoSync`, `updateIacSourceBranch` and `updateIacSourcePath` each select `execution { id }`, and the page navigates to `/blueprint/<id>/sync/<executionId>` when it is set (`index-D5V4ZgbE.js`; [blueprint-pages.md § The Settings card](../../docs/render-artifacts/blueprint-pages.md#the-settings-card)). Its REST `PATCH /blueprints/{blueprintId}` says a branch update "does not plan a sync" (`lego/backend/internal/api/openapi/render-public-api-1.json`), and Render's MCP `update_blueprint` plans after a branch or path change.
- **bex:** GraphQL `updateBlueprint` returns the Blueprint and plans nothing; MCP `update_blueprint` plans after a branch or path change, as Render's does (`lego/backend/internal/apps/blueprint_onboarding.go` `updateBlueprintTool`).
- **Done when:** a signed-in read of Render's Settings (one Blueprint, a Branch or Path change on a repository with the file on a second branch) records whether a sync comes back and in what state, in `blueprint-pages.md`. If it does, bex's dashboard save plans the same way and opens the sync's page (a GraphQL field on `updateBlueprint`, or a plan after the save), with a dashboard test; if it does not, the note closes with the finding.
