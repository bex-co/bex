## Objective

Teach the freshness tool to tell whether a newer stable Rust is out and published in the official image on both architectures.

## Context

- Go's equivalent (w4/719, [done note](../../../w4/done/719.md)): `scripts/lib/toolchain-freshness.py` `go-release` / `go-apply`. `image_go_versions` reads only `GOLANG_VERSION=`; `LINE_SOURCES` lists Go and Bun.
- Source of truth: `https://static.rust-lang.org/dist/channel-rust-stable.toml` (`version = "1.100.0 (0ef1bc386 2026-11-09)"` on 2026-11-25). Docker Hub's `rust:1-bookworm` sets `RUST_VERSION` on linux/amd64 and linux/arm64.

## Steps

1. Add `rust-release`: `current`, `wait` (the official index lacks it on either arch) or `bump`.
2. Generalize the image-version reader to a named env var.

## Files

- `scripts/lib/toolchain-freshness.py`

## Acceptance criteria

- [ ] With fixtures it answers `current` for 1.100.0, `wait` for a release missing on one arch, `bump` for 1.100.1 and 1.101.0.

## Done — 2026-11-26

- `rust-release` in `scripts/lib/toolchain-freshness.py` shares Go's planner: `MovingLine` holds what differs (`GO`, `RUST`) and `line_plan` plans both. The image reader is now `platform_versions(upstream, digest, env)`; its test fixture `FRESHNESS_PLATFORM_VERSIONS` replaces `FRESHNESS_GO_VERSIONS`. The newest release is the `[pkg.rust]` version of `channel-rust-stable.toml`, parsed with `tomllib`.
- `scripts/build-toolchain-freshness.test.sh` covers these fixture cases: 1.100.0 and an older 1.99.2 answer `current`; `wait` while `rust:1-bookworm` still carries 1.100.0, while one platform is behind, while a platform is missing, and while the tag is not answered; `bump` for 1.100.1 and for 1.101.0, on the same tag. A beta and a Rust 2 fail the plan.
- Live on 2026-11-26: `rust-release` answers `current` (1.100.0). The tag is at the pinned `75d26c23…`, which carries 1.100.0 on both platforms.
