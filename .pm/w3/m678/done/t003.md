## Objective

Give the dashboard one read for a sync's page and the fields the sync card needs.

## Context

- GraphQL `BlueprintSync`, `blueprintSyncs(id, cursor, limit)`, `blueprintPlannedSync(id)` and `BlueprintPlanAction` in `lego/backend/internal/apps/` (schema snapshot `internal/api/testdata/schema.graphql`).
- REST `GET /v1/blueprints/{id}/syncs` and MCP keep Render's shapes (pinned `render-public-api-1.json`); new fields are GraphQL only, as Render's own dashboard reads them over GraphQL.

## Steps

1. Add `blueprintSync(id, syncId)` returning the sync with `commitMessage`, `actions` (with a per-action state derived from the sync's state and its apply results), errors and `requiredManualEnvVars`.
2. Add `commitMessage` to `BlueprintSync` for the list; regenerate the schema snapshot and the dashboard's `graphql/definitions.ts`.
3. Authorize it as `blueprintSyncs` is (the Blueprint's workspace, the same relation).

## Done (2026-11-27)

GraphQL `blueprintSync(id, syncId, ownerId)` returns `BlueprintSyncDetail`: the sync with `commitMessage`, `actionsRecorded`, `actions` and the parallel `actionStates` (the sync's own state while it waits, runs or has succeeded, none once it failed), `errors` (a failed plan's error notices, else the error message) and `requiredManualEnvVars` while it waits, plus `dashboardUrl`. It authorizes as `blueprintSyncs` does (`blueprintScope`, `can_view`); another Blueprint's sync is not found, and a stranger's read is refused as the history is. `BlueprintSync` gains `commitMessage` (GraphQL only, `json:"-"` on the view so REST and MCP are unchanged), and GraphQL's `blueprintSyncs` lists the waiting plan on its first page by its start, as Render's dashboard lists a `created` sync. Schema golden and `definitions.ts` regenerated. `TestBlueprintSyncReadOnEveryStatePG` covers the reads, the authorization and REST and MCP still leaving the plan out.
