# Render's `/resource/<id>` draws "`<Label>` not found" at its own URL for a dead id; bex opens the type's page

Why: Render resolves the id before it redirects and draws its own not-found or Access denied at `/resource/<id>`; bex redirects by prefix alone (w3/m705), so a dead id lands on the type's page with that page's state (Postgres's "Page not found", a service's "Service not found") and the URL changes.

Filed by w3/m706 t008 on 2026-11-27, from Render's dashboard bundle read the same day (`ResourceRedirector-DwoXTM_f.js`; find the code by these strings).

- **Render:** `ResourceRedirector` runs a `resourceTypeBy…Id` query for the id's prefix (`srv`, `crn`, `dpg`, `red`, `evg`, `sbg`, `sbx`, `snp`, `exs`, `whk`, the workflow kinds); a found resource redirects with the sub-path; a 403 draws Access denied with the join hint; a not-found error or an empty answer draws `ResourceNotFound` with the prefix's label ("Service", "Cron job", "Database", "Key Value instance", "Environment group", "Sandbox group", "Sandbox", "Sandbox snapshot", "Blueprint", "Webhook", …; "Resource" otherwise), `variant: unknown` and Return home only; any other error, an unknown prefix and a malformed id redirect home. [resource-not-found.md § Which page draws which state](../../docs/render-artifacts/resource-not-found.md#which-page-draws-which-state).
- **bex:** `routes/resource.$.tsx` redirects in `beforeLoad` through `resourceAliasPath` (`dashboard/src/common/lib/render-alias.ts`) without reading the id; the type's page then draws its own w3/m706 state.
- **Done when:** `/resource/<id>` with a known prefix keeps its URL while it reads the id; a found id redirects as today (sub-path, query and hash kept); a dead id draws "`<Label>` not found" with Render's label table and Return home alone; a refused one draws Access denied; an unknown prefix and a short id still go home; router tests cover each.
