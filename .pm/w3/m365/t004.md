## Objective

A setting turned off by hand, by an org change or by GitHub's defaults is noticed within a day.

## Context

- Pattern to copy: `scripts/github-environments-drift.sh` + `scripts/github-environments-drift.test.sh` + `.github/workflows/github-environments-drift.yml` (environment policy drift; fixture-driven tests; issue on failure).
- Script tests run in `.github/workflows/scripts.yml`.
- Workflows must keep SHA-pinned actions and declared `permissions:` (`scripts/github-actions-validate.sh`).

## Steps

1. Add `scripts/github-repo-security-drift.sh` (or extend the environments script if it stays readable): read `security_and_analysis` and `rules/branches/main`; report each missing setting or rule; exit 1 on drift, 2 when unusable (no token, API error).
2. Fixtures via an env var (as the environments script does) so the test needs no network.
3. `scripts/github-repo-security-drift.test.sh`: one fixture per disabled setting, a missing ruleset, a ruleset with a bypass actor, and the healthy case.
4. A daily workflow (or a job in the environments workflow) that runs it with a token able to read the settings, opening or updating one issue while drifting and closing it when green.
5. Wire the test into `.github/workflows/scripts.yml`.

## Files

- `scripts/github-repo-security-drift.sh`, `scripts/github-repo-security-drift.test.sh` (new)
- `.github/workflows/github-environments-drift.yml` or a new workflow
- `.github/workflows/scripts.yml`

## Acceptance criteria

- [ ] Each drift fixture exits 1 with a line naming the setting; the healthy fixture exits 0.
- [ ] The live run exits 0, and the scheduled workflow is green on `main`.
- [ ] `bash scripts/github-actions-validate.sh` passes.

## Out of scope

- Dependabot settings drift.
