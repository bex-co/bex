## Result (2026-11-13)

`/simplify` with three reviewers (reuse, quality, efficiency). Applied:

- **No unreadable answer passes.**
  - The secret-scanning alerts read retries, then reports unusable on any answer other than 200, 404 or 401/403. Before, a transient failure became a NOTE with exit 0, which would have closed an open drift issue.
  - Its result is assigned before the `case`, because `case "$(…)"` swallowed the subshell's exit. The new test cases caught this.
  - A `null` bypass list reads as unread, not clean.
  - A ruleset answer that is not JSON is unusable.
  - The OK line says when NOTE lines limited what was read.
- Each ruleset is fetched once, not once per rule. Settings and verdicts are each read in one jq pass.
- The repository defaults to gh's `{owner}/{repo}` placeholder, which needs no network call, instead of `gh repo view`.
- `scripts/lib/gh-retry.sh` gains `GH_RETRY_ATTEMPTS` (default 3, with a test). ship-gates runs the check in the background with one attempt and reads it at the end, so it adds roughly no time to a ship and about 0.1 s when offline.
- `ship-gates.test.sh` pins `GITHUB_REPOSITORY=o/r`. CI sets it to the real repository, which made the new case fail there.
- The workflow treats any exit other than 0 or 1 as a failure, never as drift, and builds the issue body directly.
- The test uses `mktemp -d` fixture directories and one failure helper.

Kept:
- A shared `gh_api_or_404` helper for this script and `github-environments-drift.sh`, and a shared bash test harness. Both would refactor files outside this milestone.
- Parallel API reads inside the script. Running in the background in ship-gates already removes the latency.
