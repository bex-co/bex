## Objective

Enabling secret scanning scans the full history once. Leave no alert open without a decision.

## Context

- List without values: `gh api --paginate 'repos/bex-co/bex/secret-scanning/alerts?state=open&per_page=100' -q '.[] | {number, secret_type, validity, created_at, html_url}'`. Never select `.secret`.
- Close: `gh api -X PATCH repos/bex-co/bex/secret-scanning/alerts/<n> -f state=resolved -f resolution=<revoked|false_positive|used_in_tests|wont_fix> -f resolution_comment=…`.
- Credential custody and rotation paths: `docs/ADR019-infra-credentials.md`, `scripts/gh-secrets.sh`, `scripts/production-secrets.txt`.

## Steps

1. List the open alerts (no values) and group them by type and validity.
2. For each `active` or unknown-validity credential: identify the owner system, rotate it (ADR019 path), update `.env` and the GitHub secret through `scripts/gh-secrets.sh`, then resolve as `revoked`.
3. Where rotation needs a provider console or a person, write the exact steps into a blocked follow-up note and leave the alert open, referenced from it.
4. Test fixtures and sample formats: resolve as `used_in_tests` or `false_positive` with the file path in the comment.
5. Record a table here: alert number, type, disposition, rotation date. No values.

## Files

- this file; any test fixture that should stop matching a provider pattern

## Acceptance criteria

- [ ] No open alert lacks a disposition or a blocked follow-up that names it.
- [ ] No secret value appears in this file, in commit messages or in the session log.

## Out of scope

- Rewriting history to purge an old revoked credential (a revoked credential in history is harmless; a rewrite needs the t003 runbook and a separate decision).
