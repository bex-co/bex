## Objective

Make a force-push or deletion of `main` impossible by accident, without slowing the direct-to-`main` workflow every agent and bot uses.

## Context

- `gh api repos/bex-co/bex/branches/main -q .protected` → `false`; the only ruleset is `bex-cli release tags` (tag target).
- Bots push to `main` by fast-forward (`chore(deploy): pin platform images … [skip ci]`). The ship skill never force-pushes (`.claude/skills/ship/SKILL.md:120,134`).
- `main` was rewritten deliberately twice on 2026-11-04 (AGENTS.md "No build artifacts"). A future rewrite must still be possible on purpose.

## Steps

1. `gh api -X POST repos/bex-co/bex/rulesets` with a branch ruleset named `main history` targeting `refs/heads/main`, enforcement `active`, rules `deletion` and `non_fast_forward`, and an empty `bypass_actors`. Add no pull-request, status-check or signature rule.
2. Confirm an ordinary fast-forward push still lands (the next ship or pin commit), and that `git push --force-with-lease` of a rewritten throwaway commit to `main` is refused. Run the refusal test from a scratch clone that never rewrites real history: push a ref that is not a descendant and expect GH013.
3. Write `docs/runbooks/main-history-rewrite.md`: set the ruleset to `disabled`, rewrite, re-enable, announce the `git fetch && git reset --hard origin/main` instruction (AGENTS.md), and verify the drift check (t004) is green again.

## Files

- `docs/AGENTS.md` (catalog line)

## Acceptance criteria

- [ ] `rules/branches/main` lists `deletion` and `non_fast_forward`.
