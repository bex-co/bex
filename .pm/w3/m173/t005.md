## Objective

Bring the live repository settings to the t002 shape and move every production-class secret from repository scope into its environment, without a window in which a production workflow lacks a secret it needs.

## Context

- Outward-facing, hard-to-reverse GitHub settings changes: **ask the user for explicit authorization before step 2**, and record it here with the date.
- `scripts/gh-secrets.sh` pushes `.env` → GitHub secrets at repository scope today; left unchanged, its next run recreates the repository copies.
- `production-snapshot` is referenced by `snapshot.yml:37` but does not exist.

## Steps

1. Update `scripts/gh-secrets.sh` to push each secret into the environment(s) t002 assigned (`gh secret set --env`), and to refuse pushing a production-class secret at repository scope.
2. With authorization: create `production-snapshot` (and any new environment t002 added); set each environment's main-only deployment-branch policy and reviewers.
3. Push the environment-scope copies via the updated script; dispatch or wait for one run of each affected workflow on `main` (feeds t007).
4. Only after those runs pass, delete the repository-scope copies of production-class secrets and any secret t001 found unused.
