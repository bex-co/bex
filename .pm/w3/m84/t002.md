## Objective

Make agent and dashboard traffic legible below the URL level: one histogram per GraphQL operation (`operation`, `type` query/mutation/subscription, `outcome` ok/error-class) and one per MCP tool (`tool`, `outcome`), with label sets bounded to the schema and the registered tool list.

## Context

- GraphQL: the handler lives with `lego/backend/internal/api/` (`graphql_cost.go` already parses the document for cost limiting — the parsed operation name/type is available there); error class from `extensions.code` of the first error (`graphql_error_redaction_test.go` documents the shape). Unknown/anonymous operation → `operation="other"`; names not in the schema's operation catalogue fold to `other` too (a bounded allowlist derived from the schema at startup).
- MCP: tools are a closed registry (`internal/api/render_mcp.go`, `mcp_parity.go`); label by registered tool name; `outcome` = `ok` / `error` (tool `isError`) / `denied` (authz). Cover both `/mcp` HTTP and the stdio mode only if the stdio registry is shared (metrics are irrelevant for a local stdio process — document the choice).
- Keep the histograms on the same registry and namespace as t001.

## Steps

1. GraphQL: observe around the execution call with the parsed name/type; bounded allowlist from the schema.
2. MCP: observe around tool dispatch with the registered name.
3. Tests: an operation not in the schema yields `other`; an unknown tool never creates a series; error-class labels are the closed set.

## Files

- `lego/backend/internal/api/` GraphQL handler + `graphql_cost.go`, `render_mcp.go` / `mcp_parity.go`, `httpmetrics.go` (shared collectors), tests alongside

## Acceptance criteria

- [ ] Series appear for a known query, a mutation, and an MCP tool call; `other` for an unknown operation; no series for an unknown tool.
- [ ] Backend suite + lint green.

## Out of scope

- Per-workspace labels (unbounded — never).
