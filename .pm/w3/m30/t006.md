## Objective

Close the two verified escapes in the day-old Postgres-logs surface: the GraphQL log-entry type exposes only `timestamp`+`message` while REST/MCP return `labels` (a GraphQL consumer can't tell which CNPG pod — primary vs standby — produced a line, despite the query accepting an `instance` filter), and the MCP tool description + parallel comments still claim Postgres logs don't survive restarts after durability shipped.

## Context

- `lego/backend/internal/postgres/graphql.go:206-214` — `databaseLogGQLType`; its own doc comment promises labels. Sibling pattern: `logs/graphql.go:35-39` derives `instance`/`type`/`level` from labels.
- `lego/backend/internal/postgres/mcp.go:246` — "lines do not survive restarts" is false wherever Loki is wired (`6f1bbaa7`); same stale framing on `postgres/logs.go`'s `QueryDatabaseLogs` header and the GraphQL type comment.

## Steps

1. Add `instance`/`type` resolvers off `e.Labels` to `databaseLogGQLType` (match the app-logs GraphQL naming).
2. Rewrite the MCP description + the two comments to describe the actual durable-with-fallback behavior.
3. Extend the existing postgres logs tests to cover the new fields.

## Files

- `lego/backend/internal/postgres/graphql.go`, `mcp.go`, `logs.go`
