## Objective

Under `BEX_TENANT_NAMESPACES=1` (ADR043) an App CR, its pods, and its Loki streams live in the workspace `<ws>` namespace (e.g. `tea-d98210cbbpdc73dcrkvg`), but the logs feature queries with the hardcoded `s.Namespace` (`BEX_API_NAMESPACE="default"`). The LogQL selector becomes `{namespace="default", app=…}`, which matches nothing → the Logs tab is always empty. Fix the App-log read paths to query the App's actual namespace, mirroring what the metrics feature already does.

## Context

- Root cause + live proof: memory `project_logs_tenant_namespace_bug.md`. Prod: `srv-d9bj8s3eg85c7390eb9g` → App CR `tea-d98210cbbpdc73dcrkvg-beancount-cms-v2` in ns `tea-d98210cbbpdc73dcrkvg`; Loki `{namespace="default",app=X}` → 0 streams, `{namespace="tea-…",app=X}` → 2 streams with real lines.
- The reference fix (already correct): `lego/backend/internal/metrics/service.go:670` uses `app.Namespace` with an explicit ADR043 comment; `:498` uses `s.AppNamespaceByName(ctx, appName)`.
- Resolver already available on the embedded `core.Base`: `s.AppNamespaceByName(ctx, name)` and `s.TenantNamespaces` (`lego/backend/internal/core/base.go:1000-1045`). `AppPods` already resolves the `<ws>` namespace for pod *selection* — but the container-log *reads* below then use `s.Namespace`.
- Affected App-log call sites in `lego/backend/internal/logs/service.go`:
  - `:420` `Logs()` (MCP convenience) — `s.History(ctx, s.Namespace, …)`
  - `:468` `QueryLogs` app-log history — `s.History(ctx, s.Namespace, q)` (the dashboard Logs tab path). The App CR is already in hand here (`app` from `AuthorizeApp` at `:441`) → pass `app.Namespace` directly.
  - `:633/:654/:685` `LabelValues` (filter dropdowns) — `s.LabelValues(ctx, s.Namespace, …)`
  - `:1037` `readPodLogs` (live pod-log fallback) → `readContainerLogs(ctx, s.Namespace, …)`
  - `:1094` `streamPodLogs` (SSE tail) → `streamContainerLogs(ctx, s.Namespace, …)`

## Steps

1. Where the App CR is in hand (`QueryLogs`), pass `app.Namespace` to `s.History`. Elsewhere (`Logs`, `LabelValues`, `readPodLogs`, `streamPodLogs`) resolve via `s.AppNamespaceByName(ctx, appName)` — which returns `b.Namespace` when `TenantNamespaces` is false, so shared-namespace mode is unchanged.
2. Prefer a single small helper (e.g. `appLogNamespace(ctx, app string) string`) so every App-log path resolves identically and the pattern matches metrics.
3. Verify `readPodLogs`/`streamPodLogs` read from the same namespace `appPodNames`/`AppPods` selected the pods in (today they select in `<ws>` but read in `default`).
