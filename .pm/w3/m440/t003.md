## Objective

Prove the data m439's outcome panels read: an agent outcome is stored as an outcome, not as a CLI fault.

## Context

- `bex agent` returns `command.NewExitError(code, …)` (`lego/cli/internal/agent/agent.go:58-69`); upstream classifies an `ExitCoder` as `explicit_exit` (`pkg/command/execution.go`).

## Steps

1. Against a scripted agent-sessions API: `bex agent wait <ags>` on a failed session exits 3, and the stored event has `completion_kind: explicit_exit`, `exit_code: 3`. A canceled session gives 4. `bex agent automations run` with no session started gives 6.
2. If any of these is stored as another kind, record the actual kind in ADR113 and in m439's `cli_fault` definition instead of changing the CLI.

## Acceptance criteria

- [ ] The three cases are pinned by tests.
