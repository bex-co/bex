# A Blueprint sync's page words each action and shows its errors in the file, as Render's does

Why: Render's sync page says what each action does to which resource and shows a failed file's errors on its lines; bex's page names only the resource kind, links nothing and lists the errors by line number.

Filed by w3/m678 t009 on 2026-11-27.

- **Render** (`index-D5V4ZgbE.js`, [blueprint-pages.md § A sync's page](../../docs/render-artifacts/blueprint-pages.md#a-syncs-page-syncs-and-the-sync-card-w3m678)): each action kind has its own sentence (`WR`: "Create web service **api**", "Update … auto-deploy-trigger setting to `commit`", "Associate … with this Blueprint"), an update is split into one row per changed sub-resource, the plan is in parentheses, and a resource that exists links to its page (`qR`). A sync with errors draws the Blueprint file at the sync's commit with each erroring line marked (`rL`, `blueprintContents`). Syncs loads older syncs as the list scrolls.
- **bex:** `dashboard/src/features/blueprints/components/blueprint-sync-actions.tsx` writes "Create Service **api**", "Update Postgres **db**" with the changed field paths, and "Stop managing …" for a resource the file dropped, which Render has no row for; `blueprint-sync-page.tsx` lists the errors with their line and column; `blueprint-syncs-page.tsx` has a Load more button.
- **Done when:** an action names a service's type (web service, private service, background worker, cron job, static site) and links a resource that exists; an update reads Render's per-field sentence; a failed plan's page shows the file's lines around each error (read at the sync's commit through the preview path) with the line marked; and Syncs either scrolls on or records why Load more stays. Tests pin each sentence and the marked lines.
