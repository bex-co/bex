## Objective

Record the design before code: a project's observability views are saved searches (Render's model), the log query takes a project scope plus the view's filter document and resolves the resources server-side, and the caps that bound one query.

## Context

- Capture: `docs/render-artifacts/project-observability.md` (routes, `savedSearches`/`savedSearch`, `SavedSearchType`, filter document `{filters, version: 1}`, the `logs(query: {project, filterDocument, …})` shape, labels `SERVICE`/`DEPLOY`/`INSTANCE`/`LEVEL`/`LOG_TYPE`).
- `docs/ADR010-observability.md` (logs read path, retention floors, time-boxed paging), `docs/ADR032-environments.md` (project/environment membership).
- REST `maxLogResources = 20` (`lego/backend/internal/logs/rest.go:608`); w5/m503 (slow `/v1/logs` reads) is a related load risk.

## Steps

1. Write the saved-search model: id kind `svs` (Render's prefix), project-owned, `type` in `APPLICATION_LOGS | REQUEST_LOGS | METRICS` (`WORKFLOW_RUNS` is a non-goal and refused), `filters` as Render's versioned document, name unique per project (`duplicate_saved_search_name`).
2. Write the scope rule: the project (or the environments the view names) resolves to services, cron jobs, Postgres and Key Value the caller may read; resources it may not read are left out, never named.
3. Decide the per-query bounds (resources, lines per page = 50 as Render, time box) and how a project above them is answered.
4. Note the deliberate omission: no Region picker, since bex hosts one region.
