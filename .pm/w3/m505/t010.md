## Objective

Check that what this milestone shipped is consistent across every surface it exposes and with Render, and flag any drift as follow-up work rather than silently diverging.

## Context

- Surfaces: GraphQL `savedSearches`/`savedSearch`, GraphQL `logs` with a project scope, the live tail, and the dashboard `/project/$projectId/observability/logs/*` pages. Render has no public REST or MCP operation for saved searches or project logs (the pinned `render-public-api-1.json`), so REST and MCP stay as they are; REST `GET /v1/logs` keeps taking explicit `resource` values.
- Reference: [render.com/docs/projects](https://render.com/docs/projects) § Observability and [render.com/docs/logging](https://render.com/docs/logging), fetched 2026-11-18.
- Capture: `docs/render-artifacts/project-observability.md` (2026-11-19).
- Ledger: `docs/ADR018-render-parity.md`.

## Steps

1. Compare the shipped behavior on each surface above (same fields, semantics and error shapes).
2. Compare with Render's captured and documented behavior; mark anything Render does not show or document as unverified, not as matched.
3. File any drift with `/pm add w3 …`, or record it in ADR018 with its date, and write the comparison table into the milestone README.
