## Objective

Serve Render's two read queries with the same fields (`id name type filters`), authorized by the caller's view permission on the project, and validate a filter document against the fields its view type allows.

## Context

- Capture: the query shapes and the fields per type (Application Logs: Environment, Resource, Resource Type, Level, Instance, Text Search, Time Range; Request Logs: those minus Text Search plus Method, Status Code, Host, Path); operators `IS | IS_NOT`.
- OpenFGA project relations as `lego/backend/internal/projects/graphql.go` uses them.

## Steps

1. Add the two queries and a `SavedSearchType` enum.
2. Validate filter documents (version, field per type, operator, values) in one place the later write path (w3/m507) reuses.
3. A saved search of another workspace or an unknown id reads as not found.

## Files

- lego/backend/internal/projects/ or a new `observability` package under lego/backend/internal/
- GraphQL schema registration

## Acceptance criteria

- [x] A member who can view the project reads its views; anyone else gets not found
- [x] An invalid filter document is refused with a named field
