# 079 — The Edit view modal's Instance values are typed; offer the instances the project's resources have run

Why: Render's Edit view picks a filter's values from dropdowns, and its search box already suggests "the instances seen" (`docs/render-artifacts/project-observability.md`); bex's modal (w3/m507) asks for an instance id to be typed, which nobody remembers.

- **Source:** w3/m507 t003 asked for value pickers "fed by the project's environments, resources, levels and instances". The modal shipped with Environment, Resource, Resource Type, Level, Method and Time Range picked from lists, and Instance, Text Search, Status Code, Host and Path typed (`dashboard/src/features/logs/components/edit-view-dialog.tsx`, `TypedValues`), recorded as bex's choice in ADR032 § Project observability views.
- **Gap:** `logLabelValues(resource, label: "instance")` answers one resource at a time (`lego/backend/internal/logs/service.go`, `LogLabelValues`); there is no project-scoped read of the instances a view's resources produced.
- **Done when:** the Instance picker lists the instances the project's resources produced in the log store's window (a project-scoped label-values read, bounded like the project log read, or the per-resource read fanned out over at most 20 resources), each labeled with its resource, and a typed value is still accepted for an instance that has gone. Tests cover the read's scope and authorization and the picker. ~1h.
