## Objective

`scripts/verify-tenant-isolation.sh` left three App CRs behind in production on 2026-09-14. A script whose job is to prove tenant isolation should not itself abandon resources in tenant namespaces. Close the exit path it was missing and remove the leaked objects.

**Corrected diagnosis (2026-09-16):** the first reading of this defect — "the script has no cleanup" — was wrong. `cleanup()` and `trap cleanup EXIT` already existed (`:214`, `:237`), and the trap is registered well before the fixtures are created (`:337`). The actual cause is that the trap covered **EXIT only**: the leaked Apps carried `deletionTimestamp=none`, meaning deletion had never been attempted at all, which is what an interrupted or killed run produces. Compounding it, every delete in `cleanup()` was `&>/dev/null`, so a cleanup that did run and fail would also have been silent.

## Context

- Leaked, confirmed live 2026-09-16:
  - `tea-dak78d26m8ac739r65bg/verify-iso-a`
  - `tea-dak78d26m8ac739r65bg/verify-iso-eg`
  - `tea-dak78da6m8ac739r65c0/verify-iso-b`
- All three carry no `bex.co/tenant` label, so the analytics collector correctly skips them (`lego/backend/internal/store/product_inventory.go:144`) — they are invisible to reporting while still consuming cluster resources. That invisibility is why they survived two days unnoticed.
- Their two tenants are `billing_excluded` fixtures with no tenant rows of substance.
- Sibling scripts in `scripts/` use the same `trap … EXIT` pattern, so they likely share the same signal-path gap — worth a sweep once this lands.

## Steps

1. ~~Extend the trap beyond `EXIT` to `INT`/`TERM`/`HUP` so an interrupted or killed run still cleans up.~~ **Done** — `trap 'exit 130' INT` / `143` TERM / `129` HUP added alongside the existing EXIT trap, so a signal exits the shell and EXIT then runs `cleanup`. Proven: a `TERM`ed shell runs cleanup and preserves rc=143.
2. ~~Stop swallowing cleanup failures.~~ **Done** — added `purge()`, which reports a failed deletion instead of discarding it to `/dev/null`.
3. ~~Delete the three leaked App CRs from production.~~ **Done 2026-09-16** — `verify-iso-a`, `verify-iso-eg`, `verify-iso-b` deleted; their Deployments/Services/ReplicaSets cascaded via ownerRefs; both namespaces are now empty. Cluster App CRs and the `apps` table now agree at 8.
4. **Remaining:** the two disposable fixture workspaces `tea-dak78d26m8ac739r65bg` and `tea-dak78da6m8ac739r65c0` (both `billing_excluded`, zero `apps` rows) still exist along with their namespaces. Remove them through the control-plane delete verb the script's own `delete_disposable_tenants` uses — not by hand and not by raw SQL, which would skip OpenFGA tuple revocation and the Stripe purger. Doing it after `t002` lands also exercises that fix on a real deletion.
5. **Remaining:** re-run the script once and confirm it leaves nothing behind.
