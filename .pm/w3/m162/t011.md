## Objective

Add tests that would have caught each defect this milestone fixes. Every test must assert real behavior and a real failure mode — no tautologies, no snapshot-everything.

## Context

- The whole milestone exists because these failures were invisible: a 503 loop discovered only by reading a metrics counter, a Stripe-side leak discovered only by querying Stripe per customer, an empty analytics dimension discovered only by counting rows. Tests here are the thing that turns each into a loud failure.
- The backend suite runs against real ephemeral Postgres and OpenFGA in CI (`lego/backend/CLAUDE.md`), so foreign-key behavior is exercisable for real — t001's defect is precisely an FK violation and must be tested against a real database, not a mock.

## Steps

1. t001 — delete a workspace against a real Postgres, deliver `customer.subscription.deleted`, assert 204; and assert a store failure for an existing workspace still errors.
2. t002 — assert post-deletion Customer state (no payment methods, no default, anonymized, still present) and purger idempotency.
3. t003 — assert version-mismatch dispatches, signature/livemode mismatch reject, and each rejection logs.
4. t005 — assert the drift check fails on a missing and on an extra event type.
5. t006 — assert a subscription-without-card is reported not-bound by every payment-state reader.
6. t008 — assert a QA-configured workspace without an audience row fails the guard.
7. t009 — assert a failed services list produces a correct count with an honestly-labeled state dimension.
8. Spot-check by mutation: break each fix in turn and confirm the corresponding test fails.

## Files

## Acceptance criteria

- [ ] Each of t001, t002, t003, t005, t006, t008, t009 has at least one test that fails when its fix is reverted.
- [ ] The t001 test runs against a real Postgres and genuinely exercises the FK path.
- [ ] No test asserts only that a function returns without error.
