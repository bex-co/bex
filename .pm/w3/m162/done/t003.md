## Objective

The Stripe webhook receiver rejects three classes of delivery with a bare 400 and no log line: bad signature, unexpected API version, and livemode mismatch. Stripe does not retry 4xx, so any of these silently and permanently discards events — including the `checkout.session.completed` that is the sole writer of `payment_method_bound_at`. Make all three observable, and stop rejecting on API version, which is a self-inflicted failure mode.

## Context

- `lego/backend/internal/billing/webhook.go:60-75` — all three branches call `h.Metrics.Operation(...)` and `http.Error(...)`, with no `log.Printf`. Contrast the two handler-error branches at `:79` and `:93`, which do log.
- The version gate compares against `stripe.APIVersion`, hardcoded to `2026-06-24.dahlia` in `stripe-go/v86@v86.1.1/api_version.go:10`.
- **The version check buys nothing.** `verifiedCheckout` (`billing/sessions.go:250-289`) re-reads every object from Stripe by id and never trusts the event payload's structure, so a payload shaped by a different API version is harmless. The gate's only effect is to turn a version drift into total, unrecoverable, invisible event loss.
- Current production state is correct but unenforced: the endpoint `we_1U50YHEqsEqs2tLVSFK88Ldl` is pinned to `2026-06-24.dahlia`, matching the SDK. Nothing keeps it that way — that is t005.
- Signature and livemode gates must stay as rejections; only their silence is the defect.

## Steps

1. Add a `log.Printf` to each of the three branches, naming the event id where available plus the offending value (received vs expected version, received vs expected livemode). Never log the request body or the signature header.
2. Change the API-version branch from reject-with-400 to log-and-continue: record the metric, log the mismatch, and proceed with dispatch.
3. Leave the signature and livemode branches rejecting — a mismatched signature is untrusted input and a mismatched mode is a misconfiguration that must not write.
4. Keep the existing metric names so t004's alert and any dashboards stay valid.
