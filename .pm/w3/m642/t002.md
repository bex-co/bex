## Objective

Measure, in a real browser, the focus indicator of every control a keyboard reaches on a representative set of pages, in all four themes, and fix whatever still falls under the bar after t001.

## Context

- Measured before t001 (Chromium, the tree's dashboard against `yarn local-bex`, a service's Settings page): the section rail's links 2.05:1 light and 2.95:1 dark; plain links 2.0–2.05:1 and 2.95:1; the sidebar's buttons and the skip link 4.6–4.9:1 and 9.0–9.2:1.
- A ring drawn with `ring-offset-*` paints the offset in a colour of its own (`ring-offset-background` on a dialog whose dark surface is `--popover`): read the ring's shadow, not the offset's, and check the offset matches the surface.
- The measure: the painted colour of the indicator (the ring's or outline's colour blended over the surface behind the control) against that surface, WCAG relative luminance. `dashboard/src/test/__tests__/theme-contrast.test.ts` has the arithmetic.
- `.pm` holds no screenshots or raw run output (root `AGENTS.md`): record the ratios as a table in the milestone README.

## Steps

1. With the dashboard against `yarn local-bex` (or dev-3), in light, dark and each one's high-contrast twin, Tab through: the dashboard home, a service's Settings page, a service's Logs page, the New Web Service page, the Update Source dialog and one confirm dialog, the account menu and one dropdown menu, the sign-in form.
2. For each stop record the control, the indicator (ring or outline, width) and its ratio. A script that reads `getComputedStyle` at each stop is enough.
3. Fix each stop under 3:1 (4.5:1 in a high-contrast twin) where its style lives; a control with no indicator at all is a finding too.
4. Write the table of lowest ratio per page and theme into the milestone README.
