## Objective

Replace ADR022's label-scoped per-App NetworkPolicies with namespace-scoped default-deny + same-workspace + platform-ingress allows, and re-scope ADR022's retained mechanisms (Cilium node/metadata egressDeny, platform-side lockdown, registry ACLs, container hardening) into the per-tenant namespace model (ADR043 D5).

## Context

- ADR022 t003 per-App policy + the platform Cilium `egressDeny` (`deploy/gitops/base/tenant-node-egress.yaml`) + platform lockdown (`network-policies.yaml`) + registry ACLs + `tenantSecCtx()` hardening.
- ⚠️ The node/metadata guard is a **namespaced** `CiliumNetworkPolicy` in `default` today (a namespaced CNP only selects pods in its own namespace — the file's own comment says so). "Keeping it" unchanged would silently drop kubelet `:10250` + `169.254.169.254` protection for every pod that moves to `<ws>` — the exact SSRF paths w7/m4 closed.
- ADR043 D5: only the label-scoped boundary primitive is superseded; the rest is retained, applied per-namespace.

## Steps

1. Drop the operator's per-App label-scoped NetworkPolicy; emit a namespace-scoped default-deny + same-workspace allow + Traefik/DNS/platform-egress allows per `<ws>`.
2. Promote the node/metadata `egressDeny` to a `CiliumClusterwideNetworkPolicy` (or stamp a per-`<ws>` copy from t001's reconciler) so it selects workspace-labeled pods in every tenant namespace; same for `deny-metadata-egress-all-pods`.
3. Verify platform-side lockdown + registry ACLs + hardening still hold with workloads in `<ws>`.

## Files

- `lego/operator/internal/controller/` (NetworkPolicy generation)
- `deploy/gitops/base/network-policies.yaml`, `deploy/gitops/base/tenant-node-egress.yaml`, `deploy/gitops/base/build-boundary.yaml`

## Acceptance criteria

- [ ] `scripts/verify-tenant-isolation.sh` passes with workloads in per-tenant namespaces (reachability matrix re-asserted).
- [ ] A pod in `<ws>` cannot reach kubelet `:10250` or `169.254.169.254` (the promoted egressDeny holds outside `default`).
- [ ] No label-scoped per-App policy remains; ADR022's other mechanisms still enforced.

## Out of scope

- The migration of existing workloads (t006), scale-0 verification (t007).
