## Objective

Workspace create/delete provisions and tears down per-tenant namespaces (`<ws>` for hosting, `<ws>-sandbox` for m32) with base `ResourceQuota`/`LimitRange`/default-deny `NetworkPolicy`, so the namespace boundary's lifecycle matches the workspace (ADR043 D1/D4).

## Context

- Today all tenant workloads share one namespace (`BEX_CP_APPS_NAMESPACE`, default `default`) — ADR022's label-scoped model.
- ADR043 D1: workspace = namespace; D4: namespace lifecycle = workspace lifecycle (not App sleep).
- Namespaces are not nestable, so the tenant layer takes the namespace; environments (ADR032) stay a label inside `<ws>`.

## Steps

1. Add a namespace reconciler on the control-plane projector side (workspace rows live in Postgres) that, on workspace create, creates `<ws>` + `<ws>-sandbox` stamped with `app.bex.co/workspace` + base quota/policy.
2. On workspace delete, a finalizer drains owner-referenced resources and removes both namespaces.

## Files

- `lego/backend/internal/store/` (projector / reconciler)
- `deploy/gitops/base/` (base per-namespace manifest templates)

## Acceptance criteria

- [ ] Creating a workspace creates both namespaces with correct labels + base quota/policy.
- [ ] Deleting a workspace finalizes and removes both.
- [ ] Namespaces carry no always-on pods (so the tenant node pool can still scale to 0).

## Out of scope

- Workload placement into `<ws>` (t002), RBAC authority (t003), per-tenant quota values (t004), NetworkPolicy rules (t005).
