## Objective

Migrate existing tenant workloads from `default` into their per-tenant `<ws>` namespaces without downtime, with the activator/operator handling the cutover.

## Context

- Existing apps live in `default`; their workspace label is already stamped (ADR022 label contract).
- The activator (auto-sleep wake) talks to the API only, never pod IPs directly (ADR022), so wake survives the namespace move.

## Steps

1. One-time migration: for each workspace, create `<ws>` (t001), then move its App/Database/KeyValue CRs (namespace is part of the CR identity — recreate or project into `<ws>`).
2. Verify wake/serve still works post-move; then retire `default` as a tenant namespace.

## Files

- A migration script (e.g. `scripts/migrate-tenant-namespaces.sh`)
- `lego/backend/internal/store/` (projector)

## Acceptance criteria

- [ ] Every existing workspace's workloads run in `<ws>` after migration.
- [ ] No service outage during cutover (activator wake + Ingress host routing still resolve).
- [ ] `default` no longer holds tenant workloads.

## Out of scope

- New-workspace provisioning (t001), ongoing verification (t007).
