## Objective

`dashboard/src/common/apollo/retry-link.ts:33-35` retries queries only; a mutation that fails on the network must never read as "did nothing".

## Steps

1. Audit how mutation network errors reach the UI (Apollo error link, per-form handlers, toasts); find any path where the error is swallowed.
2. Make every mutation network error visible with a retry affordance; do not auto-retry non-idempotent mutations. Record the idempotency-key question as a decision in this file (options + recommendation) for the user.

## Acceptance criteria

- [x] A test simulating a network error on a mutation shows the error UI.
- [x] `yarn typecheck && yarn lint && yarn test` pass.

## Done (2026-10-30, loopx w3)

**Audit** (150 `useMutation` sites in 98 files, 0 `client.mutate`): mutations use the default `errorPolicy: "none"`, so a network failure rejects; there is no global error link/toast/`unhandledrejection` net, so each call site owns its error. 145 sites surface it (mostly via `mutationErrorMessage`, which falls back to the caller's copy for transport errors). Fixed the gaps:

- **Workspace creation Cancel** (`use-workspace-creation-billing.ts` `cancel` had `try/finally` with no catch; the page called `void handleCancel()`): a failed cancel now keeps the attempt, toasts "Couldn't cancel workspace creation. Try again." (en/zh) and stays on the page.
- **Env group "Retry rollout"** (`EnvironmentEditor.retryDeploy` awaited a rethrowing `retryRollout` with no catch): now toasts `services.triggerDeployError` (or the server's reason) and keeps the retry button. The service variant already caught.
- **Web push**: a failed enable/disable left the panel with an error and no control until reload — it now offers the failed action again (`failedAction`); disable unregisters on the server **before** dropping the browser subscription, so a dropped request no longer leaves the server pushing to a dead subscription.
- Tests: env-group network-failed retry (fails without the fix), `/new/workspace` cancel failure + success, hook keeps the attempt on a rejected cancel, web-push hook (server-first unsubscribe, `failedAction`) and panel retry buttons. `yarn lint` 0 errors, `yarn test` 576 files / 5671 tests green.
- Not changed: agent-session ticket minting shows "connecting" for a transport error during provisioning (deliberate, ADR047 transport state); `use-create-workspace.ts` has no consumers (dead-code sweep).

**Decision record — automatic mutation retry / idempotency keys (for the user; not implemented):** a mutation lost after the server ran it cannot be retried blindly. Options: (A) keep today's contract — never auto-retry mutations, always show a retryable error (shipped here); (B) client-generated idempotency keys on create-type mutations with a server-side dedupe table, then auto-retry transport failures once; (C) per-mutation natural idempotency (most updates/deletes already are). **Recommendation: A now;** revisit B only if m244 t001 shows drops are frequent after the edge fix — Render's API has no idempotency-key contract either, so B would be a bex extension.
