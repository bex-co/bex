## Objective

Serve Render's `/resource/<id>[/*]` redirector.

## Context

- Render's `ResourceRedirector` asks eleven `resourceTypeBy*Id` queries and redirects to the resource's page, keeping the rest of the path.
- bex ids carry their kind in the prefix (`lego/backend/internal/id/id.go`); the dashboard's canonical pages: `/services/<srv>`, `/databases/<dpg>`, `/keyvalue/<red>`, `/env-groups/<evg>`, `/blueprints/<exs|blp>`, `/webhook/<whk>`, `/sandbox-groups/<sbg>`, a sandbox (`?sandbox=` on its group), a snapshot, `/project/<prj>`, a build source.
- Workflow and flow-run ids are non-goals (DO_NOT_DO: Workflows & tasks).

## Steps

1. Add `routes/resource.$.tsx` mapping each prefix to its canonical page, keeping the rest of the path and the query and hash. Where the page needs a parent id (a sandbox's group), read it with the resource's existing query.
2. An unknown prefix, or a lookup that finds nothing, goes to the not-found handling (w3/m706 replaces it).
3. Record the mapping in `dashboard-routes.md`.

## Files

- `dashboard/src/routes/resource.$.tsx` (new)
- `docs/render-artifacts/dashboard-routes.md`

## Acceptance criteria

- [x] `/resource/<id>` lands on the right page for every prefix in the mapping; an unknown one reaches the not-found handling.

## Out of scope

- A server-side resolver (a prefix is enough while bex mints the ids).
