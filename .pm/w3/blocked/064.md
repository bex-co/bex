Why: on Render's new Deploys page a service with auto-deploy turned off shows a banner saying so, with a link to change it; bex's Deploys list gives no sign, so a user waits for a push that will never deploy.

- **Source:** `/pm-brainstorm for w3` 2026-11-12, item 5, filed by `/pmx them all to w3`. Render changelog 2026-09-03 (new Deploys page). ~40m, Render parity (dashboard).
- **bex today:** `dashboard/src/features/deploys/components/deploys-list-page.tsx` reads `service.autoDeploy` only to configure `DeployActions` (`:354-356`); nothing on the page says auto-deploy is off. Settings render the control from `dashboard/src/routes/services.$serviceId.settings.tsx:256-257` (`build-deploy-section.tsx`).
- **Fix:**
  1. Capture Render's banner first (wording, placement, link target) from the live dashboard or the changelog's screenshots.
  2. A repo-backed service whose `autoDeploy` is off gets a banner above the list linking to Settings → Auto-Deploy, with en and zh strings.
  3. Image-backed services show no banner (Render deploys them manually by design).
  4. The skeleton keeps the ready state's geometry: reserve the banner's height only when the service read says it will show, or render it after load without shifting the table (dashboard AGENTS.md skeleton rule).
