## Objective

Let a Blueprint follow another branch from Settings, through the `branch` the API already accepts.

## Context

- `use-repo-branches.ts` (GraphQL `repoBranches`) and the picker in `new-blueprint-page.tsx` and `service-source-card.tsx`.
- `UpdateBlueprint` checks the file exists on the new branch at the stored or supplied path and plans no sync.

## Steps

1. Add the Branch row between Auto Sync and Blueprint Path, with the branch picker and Render's not-found sentence for a refusal.
2. After a save, refresh the Blueprint so the header, Syncs and the next plan read the new branch.
3. If the API ever returns a sync for the save (w3/m678), go to its page; otherwise stay.

## Files

- `dashboard/src/features/blueprints/components/` (the settings card)
- `dashboard/src/features/blueprints/hooks/use-update-blueprint.ts`

## Acceptance criteria

- [x] Choosing a branch with the file saves it; one without the file reads Render's sentence and saves nothing.
- [x] A Manual sync after the change plans from the new branch.

## Out of scope

- Planning a sync on a branch change (Render's REST plans none).

## Done (2026-11-27)

The Branch row sits between Auto Sync and Blueprint Path: a combobox over the repository's branches (`useRepoBranches`, read once Branch is edited, as Render's picker reads on edit; `EditableFieldRow` gained `onEdit`), typed or picked, **Required** when empty. GraphQL `UpdateBlueprint` sends `branch`; a branch without the file reads Render's file sentence with the stored path and the new branch, one the repository lacks Render's branch sentence, and nothing is saved. A save refreshes the cached Blueprint (the mutation's answer) and the route loaders, so the header, Syncs and the next Manual sync read the new branch; bex-api plans from the stored branch. `updateBlueprint` returns no sync, so the page stays on Settings (the open question is w3/141).
