## Objective

Build the ADR047 agent sandbox image and make it pullable by sandbox pods on the CAPD `bex` cluster, then point bex-api at it.

## Context

- Image: `lego/agent-image/Dockerfile` (git + Node/Python/Go + pinned Claude Code/Codex/Gemini ACP adapters + the session driver on `:8787`). Build from the `lego/` context: `docker build -f agent-image/Dockerfile -t bex-agent-sandbox:dev .`.
- CAPD nodes are separate Docker containers; `kind load` targets the mgmt cluster, not the CAPD workload cluster. Import into each CAPD node with `ctr -n k8s.io images import` (ADR004 §3 pattern, `docs/ADR004-app-deployment.md:74-81`) or push to the in-cluster Zot.
- bex-api's template registry reads `BEX_AGENT_SESSION_IMAGE` (`cmd/api/main.go:1014`), default `ghcr.io/bex-co/bex-agent-sandbox:latest`.

## Steps

1. Build the agent image from the `lego/` context (tag e.g. `bex-agent-sandbox:dev`).
2. Import the tag into every CAPD node (or push to Zot); ensure the pod template resolves it with `imagePullPolicy: IfNotPresent`.
3. Set `BEX_OPENSANDBOX_URL` consumers' `BEX_AGENT_SESSION_IMAGE` to the imported ref.

## Files

- `scripts/dev-env.sh` (build + import step in the agents path).

## Acceptance criteria

- [ ] The image tag is present on the CAPD node(s) (`ctr -n k8s.io images ls | grep bex-agent-sandbox`).
- [ ] A sandbox pod created from the template pulls/starts without `ImagePullBackOff`.

## Out of scope

- Publishing the image to a public registry; multi-arch builds.
