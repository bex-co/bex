## Objective

Publish operands built with t001. Then adopt the 16, 17 and 18 digests from that one `pg-operand-image.yml` run in `bexOperandImages`, so an upgrade from 16 or 17 starts from an operand whose copied `pg_duckdb` loads.

## Context

- t001's push to `main` touches `deploy/pg-operand/**`, so `pg-operand-image.yml` builds every major in `matrix.json`, two at a time. Each build has taken up to about 20 minutes plus the gates. Watch the run in the foreground or poll it, and never end the turn with it in flight.
- Each digest is gated on arm64 and natively on amd64, and published as `ghcr.io/bex-co/bex-operator:<major>.<minor>-postgres-<commit>@sha256:…`.
- Adoption is a reviewed commit to `bexOperandImages` (`lego/operator/internal/controller/database_operand.go`, ADR060 D7). It restarts every managed cluster of each adopted major once (ADR092 D4). `holdConnectionPreload` keeps the connection preload back until the instance runs the new image, so no pod needs deleting by hand (ADR092 D4 § The connection preload follows the image).
- **16 and 17 must move.** They are upgrade sources that preload `pg_duckdb`.
- **18 moves with them.**
  - The PGDG packages of 16–18 are not version-pinned in `matrix.json`, so a rebuild today can carry newer PostGIS, pg_ivm, pg_partman or pg_repack than the adopted 18 digest. A 16 or 17 source must never run a newer extension library than the 18 it upgrades into. pg_upgrade loads `postgis-3` by soname, and the catalog would then be ahead of the library.
  - 18 is also the source of the next major's upgrades.
  - Compare `dpkg-query -W` for the extension packages across the run's 16/17/18 and the adopted 18 digest. If the run's 16 and 17 packages equal the adopted ones exactly, adopting only 16 and 17 is enough; record which way it went and why.
- **13–15 stay on their digests.** t001 copies nothing into them, so they have no `pg_duckdb` and their old copy has nothing to resolve.

## Steps

1. Wait for the run that t001's push started. Record its id and the per-major digests.
2. Pull the 16 digest. Confirm the relocation holds on the published image: copy the pkglibdir to a scratch path, and `ldd` on the copied `pg_duckdb.so` resolves beside itself.
3. Compare the packages as above, and decide between 16+17+18 and 16+17.
4. Update `bexOperandImages` and its comment (date, run id, why). Run `make test` and `make lint` from `lego/operator/`. Ship.
5. Amend ADR092 D4 with the adoption: which majors restart once, and why.
