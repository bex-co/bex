# Private network for any protocol (UDP included): design the routing

Why: Render says a service "can listen for private network traffic on almost any port and use any protocol" (render.com/docs/private-network); bex routes private traffic through ClusterIP Services whose ports come from TCP-connect discovery (w3/m273), so a UDP listener is unreachable and undiscoverable.

- Options: (a) **recommended** a headless private Service for the service's private hostname, so DNS resolves to pod IPs and any port/protocol reaches the pod with no port list (load-balancing by DNS; check rollout draining and the 10000 alias, which would then need an in-pod or proxy redirect); (b) add UDP discovery by reading the pod's `/proc/net/udp` through an exec probe (needs exec, which the operator does not hold today); (c) declare UDP ports from the image's `EXPOSE …/udp` only.
- This is a networking design decision with rollout risk (every private service's address resolution changes), so it needs an ADR089 amendment before implementation; (a) matches Render's any-protocol behavior without discovery.

**Blocked 2026-11-05 (loopx w3): your decision on the routing design.** Every option changes how every private service's address resolves in production, so it needs an ADR089 amendment you sign off. Recommended: (a) a headless private Service, which matches Render's "any port, any protocol" with no discovery. Choose (a), (b) or (c) via `/unblock w3`; the worker then amends ADR089 and implements it as a milestone.
