## Objective

v2.36 explains that a terminated or errored sandbox "ended, and when". Confirm which fields it reads and that bex populates them, so the explanation shows on bex too.

## Context

- v2.36.0 notes: "Commands on a terminated or errored sandbox now explain that it ended, and when".
- bex sandbox projection: `lego/backend/internal/sandbox/` (REST `GET /v1/sandboxes/{id}`).

## Steps

1. Read the v2.36 code path behind that message; note the fields (status values, timestamps).
2. Compare with bex's response for a terminated sandbox; fill any missing field from data bex holds.

## Files

- `lego/backend/internal/sandbox/`

## Acceptance criteria

- [x] Running a v2.36 command against a terminated bex sandbox prints the ended-and-when explanation

## Out of scope

- Snapshot-related messages (snapshots are w32/m285)

## Result (2026-11-10, loopx w3)

**Gap found, not fillable here:** v2.36 explains an ended sandbox only when a token mint answers 409 and GET returns `status`/`terminatedAt`. On production bex answers both with `404 SANDBOX_NOT_FOUND` after terminate (fixture `sbx-dbpfd5lme2kc73f2l15g`), because bex keeps no record once OpenSandbox deletes the pod. Filed as `w3/062`; ADR018 records the divergence.
