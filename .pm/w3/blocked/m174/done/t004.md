## Objective

Alert when a platform or backed-up tenant CNPG cluster has had no successful base backup for more than 26h, independently of WAL archiving.

## Context

- `PlatformDatabaseBackupStale` (`prometheus.yaml:1761-1762`) reads `cnpg_pg_stat_archiver_last_archived_time` only; `DatabaseNotArchivingWAL` reads a status flag.
- Scrape jobs `cnpg-platform-db` (`:676`) and `cnpg-tenant-db` (`:712`) keep only selected series; no base-backup series is kept.
- Backups use the Barman Cloud plugin (`ScheduledBackup` → `Backup` CRs); `w7/blocked/m156` owns replica WAL metrics, not base backups.

## Steps

1. Choose the signal and record why: a Barman Cloud plugin metric for the last successful backup, if the deployed plugin version exports one, or `Backup`/`ScheduledBackup` status via kube-state-metrics custom-resource-state (last completed time, phase).
2. Wire the scrape/keep rules and add `PostgresBaseBackupStale` (>26h since last completed base backup) for platform clusters (critical) and backed-up tenant clusters (warning), with a never-succeeded arm.
3. Add rule tests with stale, fresh and never-succeeded series.

## Files

- `deploy/gitops/base/prometheus.yaml`
- kube-state-metrics values, if that path is chosen
- the rule-test harness

## Acceptance criteria

- [ ] The rule fires for a cluster whose last completed base backup is >26h old while WAL archiving is healthy, and stays quiet for a fresh one (rule test).
- [ ] The chosen signal and its rationale are recorded in ADR031.

## Out of scope

- Replica WAL metrics (`w7/blocked/m156`); the CNPG upgrade.

## Done (2026-10-20)

Signal chosen: kube-state-metrics custom-resource-state (pinned subchart 5.25.1 supports it) exporting every CNPG `Backup` as `bex_cnpg_backup_stopped_at_seconds{namespace,cnpg_io_cluster,phase}` and every `Cluster` as `bex_cnpg_cluster_info` (RBAC `extraRules` list/watch backups, clusters). The Barman Cloud plugin's own metric names could not be confirmed, so they were not guessed. `PostgresBaseBackupStale` (critical; platform clusters; also fires when no completed Backup is visible, so a broken export pages) and `TenantPostgresBaseBackupStale` (warning; existing clusters only, because CNPG's default `backupOwnerReference: none` leaves Backups behind deleted Clusters). ADR031 §Base-backup age documents both.
