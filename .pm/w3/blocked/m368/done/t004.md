## Objective

The schedule-drift check judges every scheduled workflow on its actual scheduled runs.

## Context

- `runs_for` (`scripts/ci-schedule-drift.sh:161-176`) lists one page of `$LIMIT` (100) runs and keeps the scheduled ones; `event` filters are avoided on purpose (cli/cli#7341). `deploy.yml` runs on every push (~900 a week) and hourly, so 100 runs hold about one scheduled run, and the report says "no scheduled run reached a verdict in the 1 inspected" (`:218-222`).
- Issue #112 (open) carries the false `deploy.yml` finding beside a real deploy-latency lateness.

## Steps

1. Page further for a workflow until its runs cover the lookback window (stop at the first run older than the window, cap the pages), keeping the no-event-filter rule.
2. Add a fixture to `BEX_CI_DRIFT_RUNS_JSON` tests with one scheduled run among 100 pushes and the rest on page 2.
3. Run it live and update or close #112 accordingly.
