## Objective

A public-path outage (load balancer, DNS, edge) that leaves the cluster healthy still reaches a person within minutes.

## Context

- Today only `scripts/alerting-heartbeat.sh` probes `api.bex.co` and `dashboard.bex.co`, at the heartbeat's 5–9 h cadence.
- The tenant edge: pick a long-lived first-party `*.onbex.co` app (the 2026-08-16 outage was a tenant host).

## Steps

1. Configure HTTP checks (≤ 5 min) for the three URLs on the chosen monitor, with expected status codes.
2. Keep the configuration reproducible: an idempotent script using the monitor's API with the key from `.env`, or a documented table in ADR010 if the monitor has no API.
3. Confirm each check is green and alerts on a deliberate failure (a check pointed at a known-404 path, then removed).

## Files

- `scripts/` (if scripted), `docs/ADR010-observability.md`

## Acceptance criteria

- [ ] Three checks run at ≤ 5 min and their alert path is proven once.

## Out of scope

- Per-tenant uptime monitoring as a product feature.
