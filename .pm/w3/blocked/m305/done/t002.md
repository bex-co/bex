## Objective

An admin of a Pro-or-higher workspace picks start and end dates (at most 90 days) and downloads a CSV with Render's columns: timestamp, actor, event, status, metadata.

## Context

- Render: "Select start/end dates, click Export as CSV"; "Each audit log export can span a maximum of 90 days"; "Only workspace admins can export"; Pro plan or higher.
- Backend ready: GraphQL `auditLogs(ownerId, startTime, endTime, direction, cursor, limit)` at `lego/backend/internal/audit/graphql.go:101-114` (limit cap 1000), same `Service.List` as REST `GET /v1/owners/{ownerId}/audit-logs`.
- The hook today sends only `ownerId` and `limit` (`dashboard/src/features/audit/hooks/use-audit-log.ts:94-99`).

## Steps

1. Add a date-range control and an Export as CSV button, shown only to admins on an entitled plan.
2. Page through `auditLogs` for the range and build the CSV client-side; refuse ranges over 90 days in the control.
3. en/zh strings.

## Files

- `dashboard/src/features/audit/`
- `dashboard/src/features/audit/locales/en.ts`
- `dashboard/src/features/audit/locales/zh.ts`

## Acceptance criteria

- [x] The CSV for a range holds exactly the rows REST returns for the same range, in Render's columns
- [x] A non-admin sees no export; a Hobby admin sees the plan notice
- [x] A 91-day range cannot be exported

## Out of scope

- A backend CSV endpoint
- MCP (Render's MCP has no audit tool)

## Result (2026-11-10, loopx w3)

`features/audit/lib/audit-csv.ts` + `components/audit-log-export.tsx`: UTC start/end dates (default the last 30 days), at most 90 days, Render's columns (timestamp, actor, event, status, metadata as JSON), formula-leading cells kept as text, `no-cache` paging of 1000 up to 20 pages (then a named "shorter range" error), aborted on unmount or a workspace switch, downloaded through the shared `downloadTextFile`. Shown only once the plan is known and has audit logs (Hobby keeps the Pro notice).
