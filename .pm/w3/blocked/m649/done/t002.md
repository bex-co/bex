## Objective

On every `/keyvalue/<id>/…` page, replace the workspace sidebar with a Key Value sidebar shaped like Render's, the way a Postgres database's pages already do.

## Context

- `common/components/dashboard-layout/dashboard-sidebar.tsx` swaps in `ProjectSidebar`, `ServiceSidebar` and `DatabaseSidebar` (lazily) by route param. `database-sidebar.tsx` (`ResourceSidebar`, `SidebarNavGroups`) and `features/databases/components/database-nav.tsx` (`databaseNavGroups`, `isDatabaseNavItemActive`, `databasePageLabelKey`, `databasePageRoute`, `filterNavGroups`) are the pattern.
- Render: Info (also active on the bare URL); Monitor: Logs (`viewRedisLogs`), Metrics (`viewRedisMetrics`). bex gates them as it does for Postgres: `useCapabilities().denied("can_view_logs")` drops Logs (Viewer, Billing; w9/145) and `denied("can_view_activity")` drops Metrics (Billing; w9/m621). The group label key `common.navMonitorGroup` already exists.
- Render draws Info alone before the instance loads. bex's database sidebar draws every entry while loading so nothing shifts once it resolves; do the same here (the entries never depend on the instance).

## Steps

1. Add `features/keyvalue/components/key-value-nav.tsx` (`keyValueNavGroups`, the active-page and label helpers, a typed page route), with label keys in all eight locales, reusing the database keys' wording.
2. Add `common/components/dashboard-layout/key-value-sidebar.tsx` and pick it in `DashboardSidebar` on a `keyValueId` param. It reads the instance through `useKeyValue` with the same document and variables the page uses, so Apollo serves it without another request, and an instance the caller cannot see gets no nav.
3. Make sure `/keyvalue/new` (whose route has no `keyValueId`) keeps the workspace sidebar.
