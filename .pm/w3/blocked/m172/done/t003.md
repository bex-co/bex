## Objective

Implement t002's rule so that opening Checkout no longer creates a cardless Subscription (and, under option (a), no Customer), with completion creating exactly what is needed.

## Context

- `CreateCheckoutSession` → `EnsureContract` (`lego/backend/internal/billing/sessions.go:117`, `contracts.go:37`).
- `CompleteCheckoutSession` / `verifiedCheckout` / `bindDefaultPaymentMethod` (`sessions.go:221-353`); idempotency keys `bex-customer-<ws>`, `bex-subscription-<ws>`.
- `Readiness` (`sessions.go:64`) reports `customerReady`/`subscriptionReady` — must keep reading correctly before completion.
- Webhook retries must stay idempotent (m162 lineage).

## Steps

1. Move Subscription creation (and Customer creation under (a)) from `CreateCheckoutSession` into the completion path.
2. Re-derive the ownership proof in `verifiedCheckout` for the new shape.
3. Keep `MarkCheckoutStarted` as intent provenance.
4. Keep `pendingSetupMetadataKey` semantics, or retire it if no cardless Subscription can exist any more (update ADR040).

## Files

- `lego/backend/internal/billing/sessions.go`, `contracts.go`, `stripe.go`
- `lego/backend/internal/billing/*_test.go`

## Acceptance criteria

- [ ] Creating then expiring a Checkout Session leaves no new Subscription (and no Customer under (a)) — Stripe fake test.
- [ ] Completing Checkout twice (webhook retry) yields exactly one Customer + one Subscription and one `payment_method_bound_at` stamp.
- [ ] A forged session (foreign workspace metadata) is still rejected.

## Out of scope

- Emitter / admin / comp paths (intended owners).

## Outcome (2026-10-02)

Done. `CreateCheckoutSession` no longer calls `EnsureContract`; `verifiedCheckout` adopts a session-created, untagged Customer (tag + mapping), deletes a superseded one (two tabs) and acknowledges, refuses a foreign-tagged one, honours the legacy `bex_subscription` claim, then ensures one Subscription. Adoption seeds the Customer address from the card (setup mode leaves it empty); the flag derives from the session so webhook retries stay byte-identical under one idempotency key (a test caught the first version breaking this). `findCustomer` reads the persisted mapping first — authoritative when persistence is wired — so Search lag cannot cause a duplicate and a replica's stale cache cannot point at a reclaimed Customer. Subscription idempotency key now includes the Customer id.
