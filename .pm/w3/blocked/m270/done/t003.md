## Objective

Make Blueprint apply/sync create build sources and link services through the same core w2/m254 uses for REST/GraphQL/MCP, so a repeated sync is a no-op and an edited build source updates in place.

## Context

- m254 core in `lego/backend/internal/` (see `docs/ADR097-build-sources.md`)
- Blueprint sync/plan code under `lego/backend/internal/apps/` (blueprint_*)

## Steps

1. Add plan diff rows for build-source create/update/delete and service link/unlink.
2. Execute them through the m254 service, not a parallel implementation.
3. Make sync idempotent and keyed by build-source name within its scope.

## Files

- lego/backend/internal/apps/blueprint_*.go

## Acceptance criteria

- [ ] Sync of the fixture yields one build source feeding both services (one build, two deploys)
- [ ] A second sync with no change plans nothing
- [ ] Renaming or removing the build source plans the matching update/delete

## Result (2026-11-05)

`applyStackBuildSources` (create via `createBuildSourceCarrier`, update via `updateStackService`, so a change rebuilds), link resolution before any write, probe link/unlink in `probeBlueprintServiceSpec`, `persistBlueprintIntent` writes the link, `build_source` claim kind + migration 0191, resources[] `type: build_source`, plan actions. Tests: `TestBlueprintBuildSourceApply`, `…LinksAnExistingSource`, `…LinksAndUnlinksAnExistingService`, `…Plan`, `…PlanNamesAnOmittedField`, `…Ownership`.
