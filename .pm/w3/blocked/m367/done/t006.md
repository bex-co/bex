## Result (2026-11-13)

`/simplify` with three reviewers. Applied:

- **Defects:**
  - A failed registry delete stays retryable (`SandboxBuildIDs` keeps deleted builds).
  - Delete marks first and restores on 409, which closes the window where a create could start from a build being deleted.
  - Dependents use `endedLive`, so a sandbox with no reported state is live.
  - Other members' dependents are counted, not named.
  - A lazy source-layer failure counts as the source's.
  - The connect body extension is open with `ownerId`.
  - A cron's stale `startCommand` is cleared on link.
- **Reuse:**
  - `core.HandleNoBody` for the DELETE.
  - One `deleteResult` for both sandbox delete tools.
  - `triggerBuildArgs` embeds `buildSourceArgs`.
- **Efficiency:** the newest-first index skips deleted rows.
- **Kept:**
  - A shared optional-body decoder. Six copies predate this milestone.
  - Code parameters for the group and stale sweeps.
  - Backfilling `failure_code` in SQL. The read-time `internal_error` fallback also covers a failure an old replica writes during the rollout.
