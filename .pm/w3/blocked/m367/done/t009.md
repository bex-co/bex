## Objective

Render's live OpenAPI (2026-11-12) gives `trigger-build-source-build` an optional JSON body, `{"clearCache": "clear" | "do_not_clear"}` (default `do_not_clear`). After the re-pin, bex's request gate admits it, so the handler must honor it rather than drop it.

## Context

- Route: `lego/backend/internal/deploys/build_sources.go` (the build-source build trigger). A service deploy's `clearCache` is already implemented in the deploys package, so reuse that path.
- Found by the round-7 live diff (milestone README § Decision 2026-11-13).

## Steps

1. Parse the optional body, defaulting to `do_not_clear`. An unknown value is a 400 in Render's error shape.
2. `clear` triggers the build with the cache cleared, exactly as a service deploy with `clearCache: clear` does.
3. GraphQL and MCP build-source build triggers take the same option.

## Acceptance criteria

- [ ] REST, GraphQL and MCP accept `clearCache`. A `clear` build runs without the cache, and an invalid value is a 400.

## Result (2026-11-13)

- `TriggerBuild(ctx, id, clearCache)` passes `TriggerParams{ClearCache}` to the shared `triggerFetched`. That path validates the enum and stamps the release-scoped cache reset exactly as a service deploy does.
- REST decodes the optional body (an empty body keeps the cache), GraphQL `triggerBuild` takes `clearCache`, and MCP `trigger_build_source_build` takes the boolean or enum, as `trigger_deploy` does.
- `TestTriggerBuildHonorsClearCache`: `clear` sets the deploy's `ClearCache` and the carrier's reset annotation, and `do_not_clear` keeps the cache. An unknown value is a 400, also over REST.
