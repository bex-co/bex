## Objective

`build_ended` and `pre_deploy_ended` carry Render's `buildStatus` / `preDeployStatus` string and the ids Render documents (`buildId`; `deployId`, `deployCommandExecutionId`), and no longer send a string in `status`, which Render types as an integer.

## Context

- `lego/backend/internal/events/rest.go`:92 (`Status string` used for build/pre-deploy/job-run endings), `lego/backend/internal/events/service.go`:1292.
- Render: "Build Ended" `{buildId, buildStatus, reason, status:integer}`; "Pre Deploy Ended" `{deployCommandExecutionId, deployId, preDeployStatus, reason, status:integer}`.
- bex already omits the deprecated integer `status` on `deploy_ended` (ADR018 events row); do the same here.
- Recommendation recorded by the proposal (not a user decision): REST and MCP switch to Render's keys without dual-writing the old ones; GraphQL (dashboard/mobile) is unchanged.

## Steps

1. Emit `buildStatus` (`succeeded|failed|canceled`) on `build_ended`, `preDeployStatus` on `pre_deploy_ended`; drop the string `status` from those REST details.
2. Populate `buildId` / `deployId` / `deployCommandExecutionId` where bex has them (deploy row, pre-deploy Job); omit, never fabricate, when absent.
3. Keep `job_run_ended`'s shape unless a Render member exists for it.

## Acceptance criteria

- [x] The t001 check passes for both types
- [x] A canceled-mid-build deploy's `build_ended` reads `buildStatus: canceled` on REST and MCP
- [x] GraphQL `serviceEvents` output is unchanged

## Out of scope

- Datastore events
- Deploy-ended details

## Result (2026-11-10, loopx w3)

build_ended `buildStatus`, pre_deploy_ended `preDeployStatus` + Render's (empty) `reason`; the string `status` is gone from both. `buildId` and `deployCommandExecutionId` are not recorded by bex and stay omitted (ADR018 events row).
