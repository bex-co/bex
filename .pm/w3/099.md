# A project's observability views size their controls for touch on a phone, as a service's pages do

Why: on a phone, a project's Application Logs view keeps the desktop's 32 px controls (Return to Bottom, Load older, the range picker, Edit view), where the same log panel in a service's Logs tab gives each a 44 px target.

Found by w3/m528 t009's production walk (2026-11-20, pin `820edf28d22d`, Chromium at 390 × 844, project `qa-20261120-m528b`). In `/project/{prj}/observability/logs/application`, these measured 32 px tall: Edit view (103 × 32), Duplicate (107 × 32), Delete view (32 × 32), the Log history range picker (175 × 32), Load older (96 × 32), Return to Bottom (32 × 32) and the New logs in Live Tail button (103 × 32). The Live switch stayed at its drawn 36 × 20 with no larger hit area. Only Maximize and Log options were 44 × 44. In the service Logs tab at the same width, Return to Bottom measured 44 × 44.

Cause: the touch rule in `dashboard/src/style.css` (`@media (width < 64rem), (pointer: coarse)`, the block on `[data-touch-region]`) applies only inside a `data-touch-region`. `service-detail-layout.tsx` sets one on the service pages' scroll container, and `log-filter-bar.tsx` sets one on its phone filter sheet. Nothing in the project layout (`routes/project.$projectId.tsx`) or `project-log-viewer.tsx` sets one, so a project's views keep desktop sizes.

Done when a project's Application Logs, Request Logs and Service Metrics views at 390 give every button, link-button and select a 44 px target and the Live switch a 44 × 44 hit area, as a service's pages do, and a test pins the region on the project layout.
