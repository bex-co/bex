# A dead deploy, build or `/w/<id>` link paints the live page's skeleton before its state, and a dead link's server-rendered title is not the drawn one

Why: on a direct load, a dead service, Postgres or project link paints its not-found page first, but a dead deploy or build paints the deploy or build skeleton, and `/w/<id>` the Workspace Settings skeleton. A dead service's tab reads "Page not found" until the page hydrates, then "Service not found". So the loading frame previews a page that never comes, and the tab's title changes under the reader.

Filed by w3/m706 t007 on 2026-11-28, from the production walk on pin `7d1dce861173` as the QA user in `bex-canary`, at 1440 and 390, reading the server's HTML with the page's scripts blocked:

- **First paint is a skeleton:** `/services/<srv-id>/deploys/dep-d0000000000000000000` under a live service (disposable) paints the deploy detail skeleton (header bars, log panel, status timeline), then "Deploy not found". `/build-sources/<bds-id>/builds/bld-d0000000000000000000` under a live build source (disposable) paints `build-header`, `build-fanout` and `build-logs`, then "Build not found". `/w/<a workspace the user is not in>/settings` paints the Workspace Settings skeleton, then Access denied. A service, Postgres, Key Value, environment group, Blueprint, webhook, project, sandbox group and build source each paint their state first, because their route loaders read the resource on the server.
- **Server title differs from the drawn title:** the server's `<title>` is `stateTitle`'s (`dashboard/src/common/lib/document-head/index.ts`). That gives "Page not found" for a dead service or sandbox group (drawn: "Service not found", "Sandbox group not found") and "Something went wrong" for a failed read (drawn: "An error occurred"). A dead deploy's and build's server title is its service's or build source's ("qa-… ・ Web Service ・ bex Dashboard"). `useStateDocumentTitle` (`common/components/resource-not-found.tsx`) corrects each title once the page hydrates.
- **Fix:** read the deploy (`features/deploys/components/deploy-detail-page.tsx`), the build (`features/build-sources/components/build-detail-page.tsx`) and the `/w/` membership (`routes/w.$.tsx`) in their route loaders, so the server draws the state. Let `routeResourceTitle` take the page's own not-found title (service: "Service not found", sandbox group: "Sandbox group not found"), and use "An error occurred" for an `error` read on the pages that draw `ResourceStateView`.
- **Done when:** with the page's scripts blocked, each of those links' server HTML holds its state and a `<title>` equal to the heading it draws, at 1440 and 390, and a route test asserts the head title for a dead service, sandbox group, deploy and build.
- **Render:** Render's dashboard renders in the client, so it paints its skeleton first and then its state on every page. This item is bex's skeleton rule (`AGENTS.md`), not a parity gap.
