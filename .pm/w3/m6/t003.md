## Objective

The generic "is the platform healthy" pack, kept deliberately small and high-signal: container CrashLoopBackOff / Deployment not-Ready persisting >10m in platform namespaces (`bex-system`, `argocd`, `traefik`, auth/infra namespaces), node NotReady >5m, PVC >85% (etcd/Loki/OpenBao/Prometheus volumes are all single-host disks), cert-manager Certificate not Ready / expiring <14d.

## Context

- Rules as PrometheusRule-equivalent config in the chart's `serverFiles`/rule values (server-only chart — no operator CRDs; follow whatever rule-file mechanism the pinned chart exposes).
- Every alert carries a one-line `description` with the kubectl command to start debugging — alerts nobody can act on are noise.

## Steps

1. Author the rules with `for:` durations and severity labels (page vs warn).
2. `promtool check rules` locally; sync; confirm they load in the Prometheus UI.

## Files

- `deploy/gitops/base/values/` (rule files)

## Acceptance criteria

- [ ] Rules load; a deliberately-broken Deployment in bex-system fires the not-Ready alert and resolves on fix.
