## Objective

Flip `alertmanager: { enabled: false }` to a minimal single-replica Alertmanager in the Prometheus chart values and configure exactly one real notification channel — a Slack-compatible webhook or SMTP email, whichever credential the team can mint fastest — with the secret delivered out-of-band (SealedSecret, the w1/m7 pattern), never in values.

## Context

- `deploy/gitops/base/prometheus.yaml` + `deploy/gitops/base/values/`; the chart bundles alertmanager — enabling is a values change, not a new app.
- Secret pattern: `docs/sealed-secrets.md` (controller + `kubeseal` workflow shipped in w1/m7).
- Route/grouping: keep the default route simple (one receiver, group by alertname); tuning is not this milestone.

## Steps

1. Values: enable alertmanager, wire `alertmanagers` scrape/notify config, receiver referencing the sealed secret.
2. Seal + commit the webhook/SMTP secret; local overlay may point at a dummy receiver.
3. `kustomize build` both overlays; Argo sync; `amtool`/UI check the receiver loads.

## Files

- `deploy/gitops/base/prometheus.yaml`, `deploy/gitops/base/values/`
- sealed secret manifest under `deploy/gitops/`

## Acceptance criteria

- [ ] Alertmanager runs; a hand-fired test alert (amtool) reaches the channel; no plaintext secret in git.

## Out of scope

- Rules (t003/t004); multi-channel routing, on-call schedules, silencing policy.
