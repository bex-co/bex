## Objective

The rules that encode bex's own promises: `etcd-backup` and `openbao-backup` CronJob last-success age > 26h (the nightly jobs' staleness window — this is the "silent backup rot = data loss" alert), OpenBao sealed (its env-vars API 503s tenants; alert when ANY member reports sealed), bex-api down >5m, a Traefik 5xx-rate spike (>5% of requests for 10m — Traefik metrics are already scraped for the request-metrics feature), and stranded node-local images (below). _2026-07-11: the original sealed-detection options don't fit the live deployment — no blackbox exporter exists (adding one fights t002's minimal-exporter stance), `openbao.values.yaml` carries no telemetry stanza, and seal state is PER-MEMBER on the now-initialized multi-member raft: the `openbao` Service round-robins across sealed+unsealed members (`scripts/bao-endpoints.sh`), so a Service-level `/v1/sys/health` probe would flap or miss a sealed follower. Likewise nothing can HTTP-probe bex-api's health endpoint today — use t002's KSM instead._

## Context

- CronJob staleness: `kube_cronjob_status_last_successful_time` from t002's kube-state-metrics (cronjobs collector over `kube-system` + `secrets`).
- OpenBao sealed-on-restart is a documented failure mode (docs/secrets.md); CI unseals on deploy, but a mid-cycle pod restart seals silently. Detection: enable listener telemetry with `unauthenticated_metrics_access = true` in `deploy/gitops/base/values/openbao.values.yaml` + t002's per-POD scrape job; alert when any member reports sealed. Keep the sealed alert's fix path: "run scripts/bao-init.sh unseal path / see docs/secrets.md runbook".
- bex-api down: `kube_deployment_status_replicas_available{namespace="bex-system"} == 0` from t002's KSM — no HTTP probe, no new exporter.
- Traefik metrics labels: reuse what `BEX_PROM_URL` request-metrics queries already select on (`lego/backend/internal/metrics/`).
- Stranded node-local images (new-architecture failure mode): app images are node-local ctr imports (no registry — zot is empty), so tenant-node replacement or autoscaler scale-down strands them and App pods sit in ImagePullBackOff/ErrImageNeverPull. That is a PLATFORM defect (the node-local-image design), not tenant paging — it does not violate t003's no-tenant-alerting scope.
