## Objective

bex-api has no per-account store for the theme. Add one: a row per account subject with Render's `themeSetting` and `logThemeSetting`, read with defaults when absent, and deleted when the account is.

## Context

- Migrations: `lego/backend/internal/store/migrations/` (the newest is `0316_saved_search_render_document`; take the next free number on `origin/main`).
- Per-subject settings today are per (tenant, subject), e.g. `notification_settings` (`internal/notifications/service.go` `GetSettings`). The theme is the account's, not a workspace's: key it by subject alone.
- Account deletion: `PGStore.CleanupAccountSubject` (`internal/store/accounts.go`) deletes personal state by subject; the new table joins its `deletes` list.
- Enums (README § Render's Appearance): `SYSTEM`, `LIGHT`, `DARK`, `SYSTEM_HIGH_CONTRAST`, `LIGHT_HIGH_CONTRAST`, `DARK_HIGH_CONTRAST`; `MATCH_APP`, `ALWAYS_LIGHT`, `ALWAYS_DARK`.

## Steps

1. Add the migration pair: `user_theme_settings (subject text PRIMARY KEY, theme_setting text NOT NULL DEFAULT 'SYSTEM' CHECK (…), log_theme_setting text NOT NULL DEFAULT 'MATCH_APP' CHECK (…), updated_at timestamptz NOT NULL DEFAULT now())`, and its down.
2. Add `GetUserThemeSettings(ctx, subject)` (defaults when no row) and an upsert that sets one of the two columns and keeps the other, in a new `internal/store/user_theme_settings.go`.
3. Add `DELETE FROM user_theme_settings WHERE subject = $1` to `CleanupAccountSubject`.
4. Real-Postgres tests: defaults, each column written alone keeps the other, a value outside the enum is refused by the CHECK, account cleanup removes the row.
