## Objective

A view document with `IS_NOT` on Level, Instance, Method, Status Code, Host or Path is stored and read. Its values reach the negated sets. Environment, Text Search and the time range keep refusing it, as Render's editor offers no negation there.

## Context

- `lego/backend/internal/savedsearch/document.go:180`: the `IS_NOT` refusal. `Document.Values` already reports whether a field is negated.
- `lego/backend/internal/logs/project.go:97`–`:119`: `newProjectView` copies each line field's values into `LogQuery` and refuses a caller filter beside the same field ("the view already filters on …").
- `TestProjectReadRefusals` (`project_test.go`) expects the `LEVEL IS_NOT` refusal. `document_test.go` covers the validator.
- ADR010 § Project views (`docs/ADR010-observability.md`, the filter document bullet) and the ADR018 Projects row both describe the refusal.

## Steps

1. Accept `IS_NOT` on the six fields in `Filter.validate`. Keep the by-name refusal for `ENVIRONMENT`, `TEXT` and `TIME_RANGE`.
2. In `newProjectView`, route a negated field's values into its negated set. Keep the "view already filters" refusal whichever operator the view uses.
3. Update the validator and refusal tests: `IS_NOT` accepted on the six, still refused on the other three.
4. Amend ADR010 § Project views and the ADR018 Projects row: which fields negate, the per-field operators recorded in t001, how a negated read behaves (a line without the label stays, an unresolved instance excludes nothing). Then run prettier.
