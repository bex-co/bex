# attach-ticket mint `url` returns the phase-2 wss origin, not the phase-1 SSE base

The `POST /v1/agent-sessions/{id}/attach-ticket` response `url` field is `BEX_AGENT_SESSION_GATEWAY_URL` = the **phase-2 raw-ACP WebSocket** origin (e.g. `wss://ssh.bex.co/agent-sessions`). It is **not** the phase-1 SSE stream base.

The phase-1 SSE conversation stream is served under the **primary API origin**, edge-routed to the gateway (m43 t006):

```
GET https://api.bex.co/v1/agent-sessions/{id}/stream   (header X-Bex-Agent-Ticket)
```

A client that naively does `mint.url + "/{id}/stream"` builds a `wss://…` URL and fails (this was a real bug in `scripts/agent-session-verify.sh` section 5, since fixed to use the API origin).

**Follow-up for w1/m64 (dashboard):**

- Dashboard/AI-SDK clients must derive the SSE stream URL from the API origin + session id, ignoring `url` for the phase-1 stream (`url` is only for the future WebSocket attach).
- Consider having the mint **also return the explicit phase-1 SSE stream URL** (e.g. `streamUrl`) so clients don't have to hardcode the path — verify the same shape across REST/GraphQL/MCP. Decide in m64.
