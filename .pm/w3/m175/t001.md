## Objective

Establish (and fix where needed) that both components are correct at N>1 replicas: no replica serves before its App index is built, and concurrent work across replicas (wake patches, edge-rule caches) is idempotent.

## Context

- Readiness is a TCP probe on the serving port (`lego/operator/cmd/staticserver/main.go:71`, `lego/operator/cmd/activator/main.go:146`).
- `appwatch.Start` waits for cache sync (`lego/operator/internal/appwatch/appwatch.go:69`); static-server then starts `resolver.Run` in a goroutine (`cmd/staticserver/main.go:168`) and `ListenAndServe` (`:183`); the activator refreshes its host cache via `appwatch.Loop` (`cmd/activator/main.go:107-136`).
- A cold replica answering "no static site for host" or a 404 for a known host during a roll would be a regression a second replica introduces.
- The activator's wake writes `app.bex.co/last-active` and uses `singleflight` per process; two replicas may both wake the same App.

## Steps

1. Read both startup paths; confirm the first index/resolver build completes before the port listens. If not, build once synchronously before `ListenAndServe`.
2. Check every in-memory structure (host index, edge rules, custom-page cache, wake debounce) for per-replica assumptions.
3. Confirm a duplicated wake from two replicas is a harmless idempotent patch (or make it so).
4. Add a unit test per fix (e.g. a request before the first build is not answered as "unknown host").

- `lego/operator/cmd/activator/main.go`
