## Objective

Make each component's health observable on its own: Prometheus metrics from both binaries, scrape jobs, per-component availability alerts and dashboard panels.

## Context

- Neither `cmd/staticserver` nor `cmd/activator` registers `promhttp`; neither is in `deploy/gitops/base/prometheus.yaml`'s scrape jobs. The serving ports are tenant paths with no reserved routes (w4/m162), so metrics need a separate listener (as `cmd/ssh-gateway/main.go:309` does).
- `TraefikHigh5xxRate` is fleet-wide; Traefik per-service series (`traefik_service_requests_total`) are already scraped.

## Steps

1. Add a separate metrics listener to both binaries: requests by outcome (served, unknown host, origin error, wake, first-deploy, suspended, maintenance), index size, last index build time, origin fetch errors.
2. Add scrape jobs and NetworkPolicy allowances for the metrics port.
3. Add `StaticServerUnavailable` / `ActivatorUnavailable` (no ready replica, or per-service 5xx ratio high) and an index-staleness rule.
4. Panels on the ADR088 platform-availability dashboard; `scripts/obs-coverage-check.sh` passes.

## Files

- `lego/operator/cmd/staticserver/main.go`, `lego/operator/cmd/activator/main.go`
- `lego/operator/config/staticserver/`, `lego/operator/config/activator/` (metrics port)
- `deploy/gitops/base/prometheus.yaml` and dashboard JSON

## Acceptance criteria

- [ ] `/metrics` answers on the metrics port only, never on the tenant serving port (test).
- [ ] Rule tests: each alert fires with zero ready replicas and stays quiet during a one-replica roll.
- [ ] `obs-coverage-check.sh` passes.

## Out of scope

- Per-tenant static-site metrics surfaced to tenants.
