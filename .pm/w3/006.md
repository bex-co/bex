# FollowLogs: combined `app+build` silently drops build lines — interleave or reject

Since `5a0c62dc` (live-build-following hardening), `lego/backend/internal/logs/service.go:534`
dispatches to `followBuildLogs` only when `Types == [build]` exactly; a
subscriber requesting `type=app,build` silently gets app lines only (the old
code interleaved both). No live caller regresses — the dashboard's
`use-deploy-logs.ts` requests `build` alone — but silent drop is the failure
mode the log surface has repeatedly paid to remove (cf. the store-only-filter
503s in CLAUDE.md's `BEX_LOKI_URL` row: "never silently ignored").

Sub-hour, either direction: restore app+build interleaving in the follow path,
or explicitly reject multi-type follow requests that include `build` with a
clear error. Pick whichever matches Render's SSE behavior if evidence exists;
otherwise reject-with-error is the honest default.
