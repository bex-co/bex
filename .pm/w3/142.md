# A Blueprint's Build Sources table shows each build source's latest build, as Render's does

Why: Render's Build Sources table on a Blueprint's Resources page has a Latest build column (the build's state and id, which opens it) and dates each row by that build; bex's table, drawn since w3/m680, shows neither, so a reader cannot see whether a Blueprint's build sources built.

Filed by w3/m680 t007 on 2026-11-27.

- **Render:** the table's columns are Build Source Name, **Latest build** (the latest artifact's build status icon and its id, a button that opens the build's drawer), Source and **Updated**, the latest artifact's `createdAt`; its project rows collapse (`expandedRowIds`). `index-D5V4ZgbE.js` (`Cxe`, `KI`) and `artifact-sources-table-utils-B6M4NPij.js` ([blueprint-pages.md § Resources](../../docs/render-artifacts/blueprint-pages.md#resources-w3m680)).
- **bex:** `dashboard/src/features/blueprints/components/blueprint-build-sources-table.tsx` draws Build Source Name, Source and Updated (the build source's own `updatedAt`), with fixed project rows. GraphQL `BuildSource` has no latest build, and a build source's builds are a read of their own (`BuildSourceBuilds`).
- **Done when:** the table has Render's Latest build column (the state's icon and the build's id, linking the build's page at `/build-sources/<id>/builds/<buildId>`, bex's equivalent of the drawer) and Updated reads that build's time, from one read for the table (for example a `latestBuild` field on GraphQL `BuildSource`, REST and MCP unchanged unless Render's API has it); the pending frame keeps its rows' height; a dashboard test pins the column; `blueprint-pages.md` § Still apart loses the line.
