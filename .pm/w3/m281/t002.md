## Objective

Add `create` to the protected restricted verbs and make `ResolveEnvironmentForCreate` (or its callers) refuse a non-Admin with 403 when the target environment is `protectedStatus=protected`, on Service, Postgres, Key Value, recovery and env-group create.

## Context

- `core.RequireEnvironmentAdmin` / `ProtectedVerbRestricted` in `internal/core/confirmation.go`
- `authorizeACLBearingMutation` uses `AuthorizeFreshOn(ctx, core.RelCanManage, core.WorkspaceObject(...))` (`internal/environments/service.go:1346`)
- Render's 403 shape for an insufficient role is the existing protected-verb refusal

## Steps

1. Add `create` to `ProtectedVerbRestricted` and update its comment.
2. Apply the check at the single resolution point so every create caller inherits it.
3. Keep non-protected environments and the default (no environment) path unchanged.

## Files

- lego/backend/internal/core/confirmation.go
- lego/backend/internal/core/ (ResolveEnvironmentForCreate)
- lego/backend/internal/apps/service.go
- lego/backend/internal/postgres/service.go
- lego/backend/internal/keyvalue/service.go

## Acceptance criteria

- [ ] A Member creating a service, Postgres or Key Value with a protected `environmentId` gets 403 on REST, GraphQL and MCP
- [ ] An Admin succeeds
- [ ] Creating in an unprotected environment is unchanged for a Member
