## Objective

Make device-flow tokens authorize as the signed-in human and replace the API-key-specific logout behavior with revocation of that user's CLI token/consent chain while preserving the shared public client.

## Context

Hydra introspection must expose the Kratos identity as `sub`, so existing membership/OpenFGA checks work. Ensure the device approval path performs the same first-login tenant provisioning needed by the dashboard. Current `/v1/oauth/revoke` calls `RevokeAPIKey` and deletes the caller's Hydra client; that is invalid for a shared CLI client and must be split by credential type.

- `lego/backend/internal/api/auth.go`

- Hydra admin client and integration tests

## Acceptance criteria

- [ ] CLI tokens resolve to the human subject and the correct real workspace; first-time signed-in users receive the normal tenant membership without an API-key identity fallback.
- [ ] `render logout` revokes the caller's access + refresh chain/consent and never deletes or mutates the fixed public client.
- [ ] One user's logout cannot revoke another user's CLI session; API-key self-revocation retains its existing semantics.

## Out of scope

- Global "sign out every device" or connected-agent UI changes.
