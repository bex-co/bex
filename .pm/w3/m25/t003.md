## Objective

Provide the verification URL opened by `render login`, requiring the existing Kratos session/aal rules and accepting or denying Hydra's device authorization request through the supported admin API.

## Context

Configure Hydra's device verification/success URLs and reuse the login/consent bridges already shipped in m9, m16, and m17. The page should show enough device/client context for an informed decision and handle signed-out, signed-in, approve, deny, expired, and replayed codes without inventing a second login or consent provider.

## Files

- `deploy/gitops/base/values/hydra.values.yaml`
- a focused route under `dashboard/src/routes/auth.*`
- a focused server function alongside `dashboard/src/common/server-fn/hydra-consent.ts`
- dashboard page/unit tests

## Acceptance criteria

- [ ] The CLI's verification URL reaches bex, sends signed-out users through Kratos, and returns them to a working approve/deny page.
- [ ] Approval binds the Hydra device request to the logged-in Kratos identity; denial reaches the CLI as `access_denied`.
- [ ] Expired/replayed/foreign requests fail safely, and CSP/redirect handling works in a real browser.

## Out of scope

- A bespoke username/password UI or replacement consent system.
