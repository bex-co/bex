# A resource page's sidebar goes blank for a frame as it hydrates, and before the loading frame on a first client navigation

Why: the server-rendered sidebar (back link, name and nav) disappears for one frame and comes back, and a first navigation into a resource clears the sidebar before the page's loading frame paints, so the one part of the frame that should hold still flickers on every full load.

Filed by w3/m706 t007 on 2026-11-28, from the production walk on pin `7d1dce861173` as the QA user in `bex-canary`, headless Chromium at 1440, sampling `[data-slot="sidebar-content"]` every animation frame:

- **Full load, live Postgres** (`/databases/<dpg-id>`, created for the walk (disposable)): 430 ms "Dashboard qa-…-pg Info Monitor Logs Metrics …", 559 ms empty, 589 ms the nav again. A dead service (`/services/srv-d0000000000000000000/deploys`) does the same: 520 ms "Dashboard srv-…", 624 ms empty, 658 ms back. It does not depend on the read: holding GraphQL for 2.5 s changes nothing.
- **First client navigation** from `/` into a service: 540 ms after the click the sidebar is empty and the outgoing page is still drawn, then the service's nav and the loading frame appear together.
- **Cause:** `DashboardSidebar` (`dashboard/src/common/components/dashboard-layout/dashboard-sidebar.tsx`) loads every contextual rail (`ServiceSidebar`, `DatabaseSidebar`, `KeyValueSidebar`, `ProjectSidebar`, `BlueprintSidebar`, `SandboxGroupSidebar`) through `lazy()`, inside `<Suspense fallback={<SidebarShell />}>`, and `SidebarShell` draws an empty `SidebarContent`. The server renders the rail, the client has not loaded its chunk at hydration, and the fallback replaces the server's markup until it has.
- **Fix:** have the rail's chunk ready before it renders. Either preload it from the route that shows it (each detail route's `loader` or `beforeLoad` can start `import("./service-sidebar")`, so hydration and a client navigation find it resolved), or make `SidebarShell` draw the rail's own frame (the back link and the name from the params) instead of nothing. Keep the rails out of the entry chunk (the comment above the `lazy()` calls).
- **Done when:** sampling the sidebar on a full load of a service, a Postgres and a project at 1440 never shows it empty, a first client navigation into a service keeps the outgoing sidebar or shows the service's frame (never an empty rail), and a test keeps the server-rendered rail through hydration.
