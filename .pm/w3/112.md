Why: the header's loading frame should end on the line the ready header does (dashboard/AGENTS.md, shape parity); at 640 a web service's frame draws a line the ready one does not, so the page shifts up when the header loads.

- **Measured** on 2026-11-25 (w3/m555 t007's local check, the dashboard on `vite dev` against `local-bex`'s web service `eden-cms-v2`, with the `Server` read held on a click from the project page): the frame is 239 px and the ready header 217 px at 640, equal at 390, 768, 1024 and 1440. It is the same before and after `a43d36790f`, which changed the frame's first row.
