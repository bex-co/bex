## Objective

Add the control-plane storage for outbound webhook registrations and their delivery history: a `webhook_endpoints` table (per-workspace destination URL, signing secret, subscribed event types, enabled flag) and a `webhook_deliveries` table (per-attempt status/response for the delivery worker and dashboard history view).

## Context

- Control-plane store lives behind `BEX_CP_DB_URI` (docs/ADR003-control-plane.md); migrations live alongside the existing usage/audit tables in `lego/backend/internal/store` (or wherever prior migrations for `tenant_members`/`audit_events`/`owner_ids` were added — follow that convention).
- Mint the endpoint id through `lego/backend/internal/id` (`id.New(kind)`), never by hand (docs/ADR020-identifiers.md); register a new `id.Kind` for the webhook-endpoint resource.
- Signing secret is generated server-side once at creation and shown only at creation time (never re-displayed in full) — mirrors the API-key mint-once pattern (`w4/m3`).

## Steps

1. Design `webhook_endpoints` columns: id, owner/workspace id, url, secret (encrypted or at least not returned on read), event_types (array/jsonb), enabled, created_by, created_at, updated_at.
2. Design `webhook_deliveries` columns: id, endpoint_id, event_type, event_id, attempt_count, last_status_code, last_attempted_at, delivered_at (nullable), disabled_at (nullable reason).
3. Write the migration, following the existing migration numbering convention.
4. Add minimal Go types + a thin store-access layer (no HTTP surface yet — that's t004-t006).

## Files

- `lego/backend/internal/store/migrations/` (new migration)
- `lego/backend/internal/id/` (register the new id.Kind)
- new `lego/backend/internal/webhooks/` package (model + store access)

## Acceptance criteria

- [ ] Migration applies cleanly against a real Postgres in tests.
- [ ] Endpoint ids are minted via `id.New`, follow the `<prefix>-<xid>` convention, and are registered in `internal/id`'s guard test.
- [ ] Secret is never returned by a read/list query (only at creation).
