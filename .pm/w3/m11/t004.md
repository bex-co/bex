## Objective

Expose `webhook_endpoints` CRUD and `webhook_deliveries` history reads over bex-api's REST surface, following the existing resource-package conventions (`apikeys/rest.go`, `secrets/rest.go`, etc.).

## Context

- Render's own public docs don't fully specify REST endpoints for webhook management (checked live 2026-07-12 — the docs page says only "see the API reference" without detailing them); this is bex filling a gap in its own API-first style, matching the precedent set by API-key management (`docs/ADR018-render-parity.md` § bex ahead of Render).
- Follow the REST envelope/error-shape conventions in `docs/ADR006-bex-api.md`.

## Steps

1. `GET/POST /v1/webhooks/endpoints`, `GET/DELETE /v1/webhooks/endpoints/{id}` (secret returned only on POST/create response).
2. `GET /v1/webhooks/endpoints/{id}/deliveries` (paged, newest-first, matching the deploys/audit-log cursor pattern).
3. Wire into the existing OpenFGA authz check (workspace-scoped, `can_manage` or equivalent tier).

## Files

- new `lego/backend/internal/webhooks/rest.go`
- `lego/backend/internal/api/server.go` (route registration)

## Acceptance criteria

- [ ] Create returns the secret once; subsequent reads never include it.
- [ ] List/get/delete are workspace-scoped (cross-workspace access denied).
- [ ] Error shapes match the existing REST convention (`{"id":"...","message":"..."}`).
