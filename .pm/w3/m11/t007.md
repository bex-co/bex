## Objective

Give workspace admins a dashboard UI to register webhook destinations, pick event subscriptions, see the one-time signing secret, and review delivery history — modeled directly on Render's own Integrations → Webhooks page (create form: name, destination URL, event-type checkboxes; secret shown once on the Settings page after creation).

## Context

- Follow `dashboard/CLAUDE.md` conventions (TanStack Start + Apollo + shadcn).
- Precedent for "reveal-once" secrets: the API-key mint flow (`w4/m8`) and env-var "Show secret" pattern.
- Precedent for delivery-history-style paged tables: the Audit Log card (`w4/m14`) and deploy history list.

## Steps

1. New Settings → Integrations → Webhooks section: list of registered endpoints (URL, subscribed events, enabled state, last-delivery status).
2. Create form: destination URL + event-type multi-select; on submit, show the signing secret once in a copy-to-clipboard dialog (never re-shown).
3. Delivery-history view per endpoint: status/timestamp/response-code table, newest-first.
4. Enable/disable toggle + delete action (type-to-confirm not required — lower blast radius than service delete).

## Files

- `dashboard/src/features/` (new `webhooks` feature directory, following the existing feature-per-package convention)
- `dashboard/src/routes/` (new settings sub-route)

## Acceptance criteria

- [ ] Creating an endpoint shows the secret exactly once.
- [ ] Delivery history renders and updates after a live event fires.
- [ ] `yarn test`/`yarn lint` green.

## Out of scope

- Update/edit of an existing endpoint's URL or events (delete + recreate is fine for v1).
