## Objective

Prove the whole path works end to end against a real (or realistically mocked) receiver, not just unit tests: register an endpoint, trigger a real deploy, and confirm a correctly signed payload arrives; then simulate a failing endpoint and confirm the retry/backoff/auto-disable path.

## Context

- Mirrors the verification bar other milestones hold themselves to (e.g. `w4/m11`'s `auth-mfa-e2e.sh`, `w2/m9`'s live acceptance run).
- A local mock HTTP receiver (e.g. a small throwaway server, or `scripts/` helper) is sufficient — no need for a public tunnel.

## Steps

1. Stand up a local mock receiver that logs headers + body and can be told to return a failing status code.
2. Register it as a webhook endpoint (via REST or dashboard) against a real or mock-cluster app.
3. Trigger a deploy; confirm the receiver got `webhook-id`/`webhook-timestamp`/`webhook-signature` headers and the payload's HMAC checks out against the endpoint's secret.
4. Point the receiver at a failing status; confirm retries follow the documented backoff and the endpoint disables after exhausting attempts, with the failure-notice email attempted (or logged, if SMTP unset).

## Files

- `scripts/` (a small verification helper script, if useful for future re-runs)

## Acceptance criteria

- [ ] A real deploy event is received with a valid signature.
- [ ] A simulated failing endpoint retries and eventually auto-disables.

## Out of scope

- Testing every one of Render's documented event types — cover the subset t002 actually wired up.
