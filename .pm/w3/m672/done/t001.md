## Objective

`deploy/native-base/node-brotli/patch.sh` rebuilds exactly Node 24.14.1 and 24.21.0 with Node's own 24-line decoder fix, keeping every other version the same, and refuses any other 24.x.

## Context

- The EOL cases swap `deps/brotli/c` for Google's 1.0.10 or 1.1.1 archive and assert that `process.versions.brotli` equals that release. The 24 line bundles 1.2.0. Node fixed it in-tree with `49dff6f57aa7` (decode.c, decode.h) and kept `1.2.0` as the reported version on 24.22.1.
- Official source checksums (nodejs.org `SHASUMS256.txt`, read 2026-11-26):
  - `node-v24.14.1.tar.xz`: `7822507713f202cf2a551899d250259643f477b671706db421a6fb55c4aa0991`
  - `node-v24.21.0.tar.xz`: `a6f54defb6fd7c84f41dba13d61e78e9b4e0961712cf61f29715c05f5ced94fc`
- Node 24 needs GCC 12.2 or newer, so it compiles in the `--common-bookworm` mode (Bookworm's GCC 12), not in the Bullseye EOL stage of `deploy/native-base/Dockerfile`. Final tenant images are Bookworm (the common foundation), so a Bookworm-built binary runs wherever these releases run.
- The node_zlib.cc constant edit is already in the script.

## Steps

1. Vendor `49dff6f57aa7`'s `deps/brotli` diff as a patch file beside the script, with its sha256 checked before it is applied. A GitHub-generated `.diff` is not a stable checksum input, so check in the file.
2. Add 24.14.1 and 24.21.0 cases with their source checksums. Apply the vendored patch to `deps/brotli` instead of replacing `c/`. Expect `process.versions.brotli` to stay `1.2.0`. Make every other 24.x exit as unreviewed.
3. Keep the post-build comparison of node, modules, napi, v8, uv, openssl, zlib and icu, plus the npm check, and record the patch's sha256 in `sources.txt`.
4. Build one of the two releases locally on Bookworm (this host is arm64) and run `check.js` on the result and on the original binary.
5. Add the sources and the 24-line recipe to `node-brotli/README.md`.

## Files

## Acceptance criteria

- [x] The rebuilt 24.14.1 or 24.21.0 passes `check.js`, and the original official binary fails it.
- [x] The version comparison and the npm check pass, and `process.versions.brotli` is `1.2.0`.
- [x] A 24.x other than the two exits non-zero as unreviewed, and a changed patch file fails its checksum.

## Result (2026-11-26)

- `patch.sh` has `24.14.1` and `24.21.0` cases with their official source checksums. They apply the vendored `node-24-brotli-49dff6f57aa7.patch` (Node's `deps/brotli` diff, SHA-256 `1e9ee182…331876`, checked before it applies) and then check that `decode.c` and `decode.h` are byte-for-byte Node 24.22.1's. With them `deps/brotli/c` equals 24.22.1's tree; only the unused GN file `unofficial.gni` differs. Brotli stays `1.2.0`. Any other 24.x below 24.22.1 exits 1 (`Unreviewed Node 24 source without the Brotli fix`). 24.22.1 and later exit 0 untouched, so a `node-24-bookworm` line publication still works. The `--common-bookworm` tenant-build mode refuses Node 24.
- **Deviation:** the milestone expected `--common-bookworm` mode. That mode is the tenant-build compile fallback, which t003 keeps for the EOL lines only. So `deploy/native-base/Dockerfile` instead gains a `node-backport-bookworm` stage on the pinned `node:24-bookworm` builder (GCC 12.2, system Python 3.11) that runs the script for a Node 24 primary.
- **Local build (arm64, Docker Desktop):** `docker build --build-arg BASE_IMAGE=node:24.14.1-bookworm@sha256:80fc9349… deploy/native-base`. The script was unchanged except `make -j20` instead of `-j2`, to finish in 23 minutes. Results:
  - The candidate's `process.versions` (every key) and `npm --version` (11.11.0) are identical to the official binary's.
  - `node /usr/share/bex-security/node-check.js` passes.
  - The official `node:24.14.1-bookworm` fails `check.js` (constant undefined). On the malformed stream it decodes past the invalid block switch and fails late with `ERR__ERROR_FORMAT_BLOCK_LENGTH_1` (-9). The candidate rejects it with `ERR__ERROR_FORMAT_BLOCK_SWITCH` (-17).
  - `sources.txt` reads `Node 24.14.1; source sha256:7822507…0991; Brotli 1.2.0; patch nodejs/node@49dff6f57aa7 sha256:1e9ee18…1876` / `Compiler baseline: Debian bookworm; glibc 2.36`.
- The publication gates (`deploy/native-base/check.Dockerfile`: real utility transformations, `check-brotli.py` against the system and the repaired bundled decoders, the wormhole round trip, network off) pass on that arm64 candidate. CI publishes for linux/amd64, production's architecture under D3 (t002).
- Tests: `.github/scripts/test_native_oci_workflow.py` `NodeBackportInputControls` covers each release's source and patch checksum, the patch's pre- and post-image blobs, the refusals of 24.0.0, 24.10.0, 24.14.0, 24.21.1 and 24.22.0, the untouched 24.22.1, 24.22.2, 24.23.0 and 24.100.0, and the common-mode refusal.
