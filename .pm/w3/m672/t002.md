## Objective

Publish a reviewed runtime donor image for `node:24.14.1-bookworm` and one for `node:24.21.0-bookworm` through the existing publication gates, each verified on both architectures.

## Context

- The Node 14/16/18/20 donors came through `native-base-image.yml` (a singleton `runtime` dispatch; its matrix comes from `deploy/native-base/matrix.py`) and were qualified by `native-common-image.yml`'s `node-donors` and `families` profiles (the "2026-11-04 donor route" in `nativebases.go`).
- Official index digests read 2026-11-26: `node:24.14.1-bookworm@sha256:80fc934952c8f1b2b4d39907af7211f8a9fff1a4c2cf673fb49099292c251cec` and `node:24.21.0-bookworm@sha256:3d27e5c11e5786e309ec3e03f93ae536eb36e6e5eb3714d5eb3300a36157add0`. Confirm they are what the build's exact resolver pins for these defaults. The donor map key must equal that identity.
- Publication requires the malformed-input rejection and a healthy round trip on amd64 and arm64, SBOMs, vulnerability reports and signatures (ADR060 D7 addendum).

## Steps

1. Add the two exact identities to the publication matrix and route major 24 to the Bookworm compiler path (t001).
2. Dispatch one run per identity. Compiling Node 24 takes long, so run them in the foreground with a long timeout or poll them; never end the turn with a run in flight.
3. Record each run id, the published digest and its passing probe on both architectures in this task.

## Files

- `deploy/native-base/matrix.py` (+ its test), `deploy/native-base/Dockerfile`, `.github/workflows/native-base-image.yml` only if the routing needs it
