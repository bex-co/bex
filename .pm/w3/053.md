# Response-shape divergences found by the m272 schema check

Why: w3/m272's whole-suite schema validation surfaced three places where bex's response still differs from Render's pinned spec without a parity decision; each is a small fix toward Render, not a divergence to sign off.

- **`serviceDetails.disk.id` is missing.** The disk id lives in the control-plane `disks` row, not the App CR, so the service projection cannot fill it; read it from the store where the projection already reads disk fields (`lego/backend/internal/apps`).
- **`POST /v1/services?dryRun=true` answers 200, Render's create answers 201.** Decide from Render's API docs whether a dry run shares the create's status; match it.
- **MCP `list_logs` still returns a `container` label.** w3/m272 dropped it from REST because Render's label enum is closed (`lego/backend/internal/logs/render.go`); the MCP projection should match REST.

Each fix removes its entry from the shrink-only allowlist in `lego/backend/internal/rendertest/allowlist.go` and its ADR018 row.
