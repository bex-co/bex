## Objective

Write what the triage read from Render's dashboard bundle into the capture, and record the one mapping decision the build needs. Render makes Live tail one of its time ranges, while bex has a Live switch beside the range.

## Context

- The milestone README § Render's explorer lists the bundle findings and the chunks they came from (`Logs-*.js`, `UserSettings-*.js`, 2026-11-20). To re-read them, start at `https://dashboard.render.com/`, follow `./*.js` imports, and look for the strings `LogLineOverflowMenu`, `LogViewerReturnButton`, `BufferedLogsButton`, `NewLogsAvailableButton` and `Theme Settings`. Keep downloads in their own empty directory and read them with `grep` or `python3 -I`.
- `docs/render-artifacts/project-observability.md` § The view page has one line on Live tail and the row menu.
- bex's live model: each explorer keeps a `live` boolean (`log-viewer.tsx`, `datastore-log-viewer.tsx` default off, `project-log-viewer.tsx` default on). With Live off the history window is frozen (w4/399, `useLiveRange(..., { paused: !live })`). A deploy's log has no Live switch of its own.

## Steps

1. Re-read the five components from the live bundle, so the record is current.
2. Replace the capture's Live tail line with the row menu's items, each with its condition. Add the Return button, the held-lines button and the New logs in Live Tail button, each with its wording and trigger. Add Options' Theme Settings target and Render's Appearance section. Note the chunk names and the date.
3. Record the mapping in this milestone's README:
   - Render's relative range corresponds to bex's Live off. Render's Live tail range corresponds to Live on.
   - Which explorers get the held-lines button: those with a live tail of runtime lines (service, Postgres, Key Value, project views), not a deploy's build log.
   - How a paused explorer learns that a new line arrived. Prefer one tail subscription opened while paused that closes at its first line, so the frozen window is untouched. Record what it costs the API and why it is acceptable.
4. Run prettier on the capture.
