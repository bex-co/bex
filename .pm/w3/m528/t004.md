## Objective

With Live off, an explorer finds out when a new line matching its filters arrives. It then shows Render's centred `NewLogsAvailableButton` ("New logs in Live Tail", tooltip "Switch to Live Tail", Dismiss ×). Clicking it turns Live on.

## Context

- Render: on a relative range the page keeps a `logAdded` subscription open, and its first line sets `hasNewLogsAvailable`. The button switches the range to `live`. The flag resets on every range change. (Milestone README § Render's explorer.)
- t001's README record says how a paused bex explorer detects a new line (proposed: one tail subscription opened while paused that closes at its first line).
- bex: `useLiveLogs` (`dashboard/src/features/logs/hooks/use-live-logs.ts`) opens the SSE tail when `enabled`. With Live off the history window is frozen (w4/399), and `useLiveLogs` is disabled.
- Explorers with a Live switch: `log-viewer.tsx` (service), `datastore-log-viewer.tsx` (Postgres, Key Value; Live off by default) and `project-log-viewer.tsx`.
- A Hobby request view refuses the tail (`planRefused`), and some explorers have no tail at all (`liveSupported` false, or a closed custom window). These must not watch.

## Steps

1. Build the watch as t001 recorded it. It carries the same resource, type, text and structured filters as the live tail would, and starts at the frozen window's end, so only lines newer than the snapshot count. It never changes the lines shown.
2. When a line arrives, show the button centred at the newest edge, with a refresh icon, "New logs in Live Tail", the tooltip "Switch to Live Tail", and a × button named "Dismiss". Use new `logs.*` keys in all eight languages.
3. Clicking the button turns Live on, as the explorer's own switch does, and the button goes away. Dismiss hides it and closes the watch until Live, the range or a filter changes.
4. Wire it into the three explorers. Skip it where the tail is unsupported or refused.
5. Write tests with the injected `EventSourceFactory`. Cover: no button before a line arrives; the button after one; the paused list's rows unchanged; click turns Live on; Dismiss hides it until a filter change; and no watch on a refused or unsupported tail.

## Acceptance criteria

- [ ] A paused service, Postgres or project explorer shows "New logs in Live Tail" within seconds of a new matching line, and only then
- [ ] Its button turns Live on, and Dismiss hides it until Live, the range or a filter changes
- [ ] The paused list's lines and scroll position do not change while it watches
- [ ] The tests fail with the watch removed

## Out of scope
