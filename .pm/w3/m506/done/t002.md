## Objective

Drop each instance's application lines beyond Render's limit before they reach Loki, and count them.

## Context

- `sandbox_logs` already has `stage.limit { rate = 20, burst = 400, by_label_name = "pod", drop = true }` (`log-shipper.yaml:1134`), the precedent.
- Render does not document its window; a token bucket at 100 lines/s with a 6,000 burst is the recommendation, and ADR010 records the edge where it differs from a per-minute window.
- Request lines and datastore logs are platform-generated, not "application-generated", and stay uncapped.

## Steps

1. Add `stage.limit` to `app_logs` keyed by pod (rate 100, burst 6000, drop).
2. Add a `scripts/gitops-validate.sh` guard that fails if the limit leaves the pipeline.

## Files

- deploy/gitops/base/log-shipper.yaml
- scripts/gitops-validate.sh

## Acceptance criteria

- [x] The rendered config carries the limit and the guard fails without it
