## Objective

Check that what this milestone shipped is consistent across every surface it exposes and with Render, and flag any drift as follow-up work rather than silently diverging.

## Context

- Surfaces: REST `GET /v1/logs` and `/v1/logs/subscribe`, GraphQL `logs`, MCP `list_logs`, the dashboard explorers; all read the same capped history, and the live tail applies the same cap.
- Reference: [render.com/docs/logging](https://render.com/docs/logging) ("Render processes a maximum of 6,000 application-generated log lines per minute for each running instance. Excess lines are dropped and do not appear in the explorer or log streams.").
- Capture: `docs/render-artifacts/project-observability.md` (2026-11-19).
- Ledger: `docs/ADR018-render-parity.md`.

## Steps

1. Compare the shipped behavior on each surface above (same fields, semantics and error shapes).
2. Compare with Render's captured and documented behavior; mark anything Render does not show or document as unverified, not as matched.
3. File any drift with `/pm add w3 …`, or record it in ADR018 with its date, and write the comparison table into the milestone README.

## Files

- the milestone README (parity table)
- docs/ADR018-render-parity.md (only if a cell or note changes)

## Acceptance criteria

- [ ] Every surface above is compared with Render and with each other
- [ ] Each drift is filed or recorded with its date
