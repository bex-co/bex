# `TestShippedExampleBlueprintsValidate` walks gitignored directories

Why: it fails on a developer machine because of a file that is not part of the repo, which trains people to ignore a red suite.

`lego/backend/internal/apps/blueprint_m102_test.go:34-60` walks `repoRoot(t)` looking for every `render.yaml` / `bex.yml`, skipping only `.git`, `node_modules`, `.output`, and `vendor`. It does not consult `.gitignore`.

Observed 2026-09-16: a gitignored sibling checkout at `bex-desktop/` (a different project, present only locally) contributed `bex-desktop/eden-cms-v2/bex.yml`, and the test failed with `additional properties 'apps' not allowed`. Nothing in bex is wrong — the file belongs to another product and was never meant to satisfy bex's blueprint schema.

CI never sees this (clean checkout), so it only ever fires locally, which is the worst place for a false failure: it makes `go test ./...` unreliable on exactly the machines that run it most.

Fix options, cheapest first:

- scope the walk to the directories that actually ship examples (`examples/`, and wherever else shipped blueprints live), which is what the test name already claims; or
- skip anything `git check-ignore` matches.

Prefer the first — the test's purpose is "the blueprints **we ship** validate", and a whole-repo walk is a broader promise than that.
