## Objective

A cron job can be built from a shared build source in a Blueprint, exactly as Render's schema allows.

## Context

- w3/m270 (done) implemented `buildSources` and server `buildSource`: capability kinds at `lego/backend/internal/apps/blueprint_compiler.go:179-180,531`; `buildSources` handling at `:274,498-504`.
- Field mapping table with `rootDir` → `rootDirectory`: `blueprint_compiler.go:385`.
- Render's new `cronService` `allOf`: without `buildSource`, `runtime` is required; with it, `runtime, repo, branch, image, registryCredential, buildCommand, buildFilter, dockerContext, dockerfilePath, rootDir` are forbidden. `serverService` adds `rootDir` to its forbidden list.

## Steps

1. Compile a cron service's `buildSource` the way m270 compiles a server's: link the App to the build source's image and schedule it.
2. Plan and sync: a cron job linked to a build source is created and updated by sync; its runs use the latest build.
3. Export: the cron job exports `buildSource:` and no runtime or repo fields.
4. Refusals follow the schema's `allOf` with the schema path in the message, for cron and server alike.
5. Golden tests for validate, plan, sync and export; a dev-3 sync of a sample Blueprint.

## Files

- `lego/backend/internal/apps/blueprint_compiler.go`, the Blueprint plan/sync/export code and their tests

## Acceptance criteria

- [ ] A cron job with `buildSource` validates, plans, syncs, runs and round-trips on dev-3.
- [ ] Each forbidden field beside `buildSource` is refused for cron and server.

## Out of scope

- `buildSource` on static sites (not in Render's schema).
