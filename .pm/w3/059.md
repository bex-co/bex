# Protected placement follow-ups from w3/m281

Why: m281 shipped Admin-only create and move for protected environments; three loose ends remain.

- **Blueprint auto-sync into a protected environment.** The auto-sync worker has no user identity, so an auto-sync that creates in, or moves into or out of, a protected environment is now refused until an Admin syncs manually (the exit guard already refused its moves out). Render does not document this case. Check what Render does when a Blueprint auto-sync adds a resource to a protected environment, then match it; if Render applies it, attribute the sync to the Blueprint's connecting Admin or exempt identity-less syncs, and record the decision in ADR032.
- **ADR018 row 225 stale sentences.** "Render's own protected environments gate deletion and suspension only" and the "typed retry" note predate w8/187; rewrite them against ADR032 § Protected environments follow Render's role rule.
- **Preselected protected environment.** A create URL that preselects a protected environment keeps it selected (shown disabled) for a non-Admin, and the refusal only appears on submit. Clear the preselection, or show the reason beside the picker on load. About 1 hour in total.
- **Blueprint placement cost (from m281's `/simplify`).** An Admin's Blueprint sync runs one fresh `can_manage` check in the whole-manifest pre-check and another per protected create (`ResolveEnvironmentForCreate` → `RequirePlacement`); validation and apply each list environments twice, one query per project (`blueprint_protected_placement.go` and `blueprint_plan_limits.go`, `applyBlueprintGroupingsWith`). Reuse `store.ListWorkspaceEnvironments` for one query, and carry the passed pre-check in the request context.
