## Objective

Find what actually closes the connection the browser reports as `ERR_CONNECTION_CLOSED`.

## Steps

1. Run the dashboard in Chromium with `--log-net-log=<file> --net-log-capture-mode=Everything` (Playwright `launchOptions.args`), signed in as the QA user (`scripts/qa-login.sh`), polling a service page for ≥2h with periodic mutations on a disposable fixture.
2. For every failed request: extract the socket/session events (H2 `GOAWAY`, RST, `ERR_CONNECTION_CLOSED` origin, idle age of the reused session) and the timestamp; correlate with edge codes / bex-api + Traefik rollouts (Prometheus) the same way `w3/044` did.
3. Record excerpts (no cookies/tokens) in this file.

## Acceptance criteria

- [x] At least one failure captured and explained, or ≥2h captured with none (documented).

## Done (2026-10-30, loopx w3) — root cause found

**Capture:** headless Chrome (playwright-core 1.64.1, channel `chrome`) signed in as the QA user via `scripts/qa-login.sh`, on `dashboard.bex.co` for 2 h (02:26–04:26Z) with 1–8 min idle gaps between reloads, `--log-net-log`. Session revoked afterwards.

**Result:** 13 `net::ERR_CONNECTION_CLOSED` on `POST https://api.bex.co/graphql` (≈1 in 9 polls). Every one is the same mechanism:

| request | transport | session idle when the request started | close |
| --- | --- | --- | --- |
| all 13 | **QUIC (HTTP/3) to Cloudflare** `[2606:4700:3033::ac43:9497]:443` | **27.2–29.0 s** | 0.02–1.8 s later, `QUIC_SESSION_CLOSED` "No recent network activity after 29.00 s. Timeout:29s", `quic_error 25` (network idle timeout), **`from_peer: false`** (Chrome itself) |

`api.bex.co` is proxied by Cloudflare, so the browser leg is HTTP/3, which none of the TCP probes in t002 exercised. Chrome's QUIC idle timeout is ~29 s; the dashboard's baseline poll (`RESOURCE_POLL_INTERVAL_MS = 30_000`) sent each poll onto a session at ~28.9 s idle, racing Chrome's own idle close, and Chrome does not replay the POST. This explains why the origin and Traefik never saw these requests, and why reads (retried by the retry link) looked fine while a mutation that happened to land in the window was lost.

**Fix → t003:** the baseline cadence is 25 s (and every other 30 s poll moved onto it), so an open page's session never idles out; a guard test fails on any recurring poll interval in the 26–32 s band.
