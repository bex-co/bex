## Objective

`t002` fixed the list half of DoD item 2 — a deleting App is dropped from the resource list immediately. The detail half was assumed, not built: DoD item 2 reads "no lingering `Unknown` row **once the URL + detail already 404**", and live verification shows the detail never 404s, so that precondition never arrives and the `Unknown` page persists indefinitely at the by-id URL.

## Live evidence (2026-08-27, 31st `/qa-find-bugs` run)

A `qa-` static site was created, configured, verified, and deleted through the dashboard. `deleteService` returned `true` and the row left the list at once (t002 works). **26+ minutes later**, with the serving side fully torn down:

```
# serving side: GONE (correct)
$ echo | openssl s_client -connect qa-20260827-static.onbex.co:443 \
    -servername qa-20260827-static.onbex.co | openssl x509 -noout -subject
subject=CN=TRAEFIK DEFAULT CERT            ← managed cert withdrawn, no route

# record side: ALL still 200
GET  /v1/services/srv-da7tf87krsvc73c3mcng          → 200  {"phase":"Deleting", ...}
GET  /v1/services/srv-da7tf87krsvc73c3mcng/routes   → 200  [{"type":"redirect","source":"/qa-old","destination":"/main.go"}]
GET  /v1/services/srv-da7tf87krsvc73c3mcng/deploys  → 200
query { service(id:"srv-da7tf87krsvc73c3mcng") { phase url } }
  → { "phase": "Deleting", "url": "https://qa-20260827-static.onbex.co" }   ← advertises a dead URL

# dashboard
https://dashboard.bex.co/static/srv-da7tf87krsvc73c3mcng
  → renders "STATIC SITE / qa-20260827-static / Service **Unknown**", with the dead URL
```

`Service: Unknown` is the exact string DoD item 2 names. The list is consistent; the detail is not.

## Why the current design does not deliver item 2

`lego/backend/internal/apps/service.go:1120-1131` (t002's change) states the trade-off it relies on:

> "…matching Render (a deleted service leaves the list at once) and **the by-id Get, which already 404s once the store row is gone**. … Trade-off: a delete stuck on a failing finalizer becomes invisible here (the operator's own alerts/audit surface it, not the tenant list); **the detail view is already 404 in that state, so hiding the list row keeps the two consistent**."

That invariant is conditional on *"once the store row is gone"*, which happens at the **end** of teardown. In the stuck-finalizer case the comment itself calls out, the store row is still present, so the by-id Get returns 200 and the two are **not** consistent — the comment's own justification for hiding the list row does not hold in the one case it was written to excuse.

The same comment budgets "a static site's S3-prefix cleanup Job can run for **tens of seconds**". This one is unbounded — 26+ minutes and counting at the time of writing.

`phase: "Deleting"` itself is deliberate and tested (`service.go:840-841`; `w6/m52/t005`'s `TestDeletingPhaseStillWinsOverCanceled`) — the defect is not the phase value, it is that every by-id surface keeps serving a resource the product has told the user is gone.

## Steps

1. Decide and record the target behavior for a by-id read of a deleting App. The two coherent options: **404 as soon as deletion is requested** (matches the list, matches the comment's stated invariant, matches Render — a deleted service is gone), or **keep 200 with `Deleting` but bound it** and surface a real terminal state when teardown fails. Pick one; do not leave the list and the detail disagreeing.
2. Apply it consistently across every by-id surface, not just the service read: REST `GET /v1/services/{id}`, `/routes`, `/deploys`, `/headers`, GraphQL `service(id:)`, and MCP. All four REST paths above returned 200 in the capture.
3. Whichever option wins, stop advertising `url` for a service whose route and cert are withdrawn.
4. Decide what bounds the finalizer. The comment budgets tens of seconds; there is currently no timeout, no tenant-visible error, and the tenant is deliberately not told. If a stuck teardown is meant to be invisible to the tenant, the by-id surfaces must not contradict that by serving the record.
5. Re-run the live E2E that `t008` is waiting on, including this case: create a static site, delete it, and confirm the list, the by-id detail, and the dashboard page all agree within a stated window.
