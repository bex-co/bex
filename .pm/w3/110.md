# Update Source keeps its Runtime field under the fold on a desktop, and says "No changes to save." beside Deploy

Why: since w4/m593 added Runtime (and, for a native runtime, Build Command and Start Command) to Update Source, every desktop viewport opens the dialog with those fields scrolled out of sight and nothing saying the body scrolls, so a user can press Deploy without seeing the runtime it reconfirms.

- **Measured** 2026-11-23 on main `33d658b497`, the tree's dashboard (`vite dev`) against `yarn local-bex`, the stub's Docker web service, the dialog as it opens (GitHub tab), in Chromium:

  | viewport | dialog | body shows / holds | body scrolls | Runtime |
  | --- | --- | --- | --- | --- |
  | 768×1024, 1024×768, 1280×800, 1440×900, 1920×1080 | 704 px (its cap) | 526 / 612 px | 86 px | wholly below the fold |
  | 1440×900 after choosing Node | 704 px | 526 / 760 px | 234 px | below the fold, with Build Command and Start Command |
  | 390×844 | 812 px | 574 / 574 px | 0 | visible (the list gives way to 160 px) |
  | 360×800 | 768 px | 530 / 542 px | 12 px | visible (the list is at its 128 px minimum) |

  Production on pin `9fdf7e0a1171` measured the same at 1440×900 for a Docker web service in bex's own workspace, as the QA user: dialog 704 px, body scrolls 86 px, the Runtime label below the body's lower edge. Nothing was submitted.

- **The footer.** With nothing changed, the footer's line is `services.sourceNoChanges`, "No changes to save.", beside a primary button that reads "Deploy" (Git and Build source) or "Connect" (image). The key's description still says "why Update source is disabled". The line was written for the button's old label; m593 renamed the button.
- **Where.** `dashboard/src/features/services/components/service-source-card.tsx`: `DialogContent` is capped at `sm:max-h-[min(calc(100dvh-2rem),44rem)]`, sized for the body before m593 (696 px on the GitHub tab). From `sm` the repository list is a fixed `sm:h-[17rem]` (`REPO_LIST_CLASS` in `repo-list-skeleton.tsx`). Below `sm` the list already gives way: `REPO_LIST_FILL_CLASS` in `service-source-picker.tsx` is `max-sm:` only, as is `max-sm:has-[[data-repo-list]]:h-[calc(100dvh-2rem)]` on the dialog, which is why the phone rows above hold.
- **A way in.** Let the list give way from `sm` as well, through the same `fillHeight` path, so Branch and Runtime stay above the footer and the list is what shrinks. A native runtime on a short viewport can still overflow once the list is at its minimum: there the body needs a cue that it scrolls. Change the idle line to match the action ("No changes to deploy.") in all eight locales and correct the key descriptions.
- **Done when**, in a real browser at 360, 390, 768, 1024, 1280, 1440 and 1920 wide: the dialog as opened for a Docker service shows Branch and Runtime without scrolling its body; with a native runtime chosen at 1440×900 the two command fields are in view too, or the body shows that it scrolls; the dialog's top edge still does not move between tabs; the footer's idle line names the primary action in every locale; and `service-source-card.test.tsx` covers the line. The create pages share the picker: their list height and pending frame (`SourcePickerSkeleton` in `route-skeletons.tsx`) must not change.
