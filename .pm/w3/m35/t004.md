## Objective

Eliminate the accepted-but-ignored sandbox `networkPolicy` contract: normalize supported Render values into the effective Cilium posture and reject every unsupported value with a named client error.

## Context

- REST accepts `networkPolicy`, `Service.Create` echoes it, and `Client.createRequest` does not send or otherwise enforce it.
- `models.go` explicitly says the field is reflected while the namespace policy is effective.
- Under gVisor, forwarding it blindly to OpenSandbox would fail because the sidecar is incompatible.

## Steps

1. Define supported `networkPolicy` values and defaults from the t001 contract.
2. Enforce or reject at the core service before any OpenSandbox call; never silently reflect an unenforced request.
3. Ensure list/get return the effective policy or omit it honestly when unavailable.

## Acceptance criteria

- [ ] Supported policies affect the generated/enforced posture and round-trip consistently.
- [ ] Unsupported policies return the same named 4xx semantics on REST, GraphQL, MCP, and CLI paths.
- [ ] No code comment or response claims an unenforced policy.

## Out of scope

- Arbitrary tenant-authored Cilium policy expressions.
