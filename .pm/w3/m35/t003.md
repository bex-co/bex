## Objective

Enforce sandbox outbound policy outside the gVisor guest with Cilium L7 DNS plus `toFQDNs`, blocking raw DNS exfiltration and direct-IP bypass while permitting only platform-approved destinations.

## Context

- OpenSandbox's egress sidecar needs the iptables `nat` table, which gVisor does not implement.
- The current sandbox namespace permits unrestricted UDP/TCP 53 to CoreDNS, allowing data to leave in attacker-controlled query names.
- `deploy/gitops/base/tenant-node-egress.yaml` denies node/metadata but has no sandbox FQDN or DNS-query policy.

## Steps

1. Select sandbox endpoints reliably and apply Cilium DNS L7 policy to CoreDNS.
2. Deny unapproved query names, public-IP traffic without approved TLS SNI, private/rebound targets, cluster CIDRs, host/remote-node, API server, and metadata.
3. Add an explicit platform-managed FQDN/port allowlist and document how it is extended without exposing cluster CIDRs to tenants.

## Files

- `deploy/gitops/base/tenant-node-egress.yaml`
- `deploy/gitops/base/` sandbox policy manifest(s)
- `lego/backend/internal/store/namespaces.go`
- `scripts/gitops-validate.sh`

## Acceptance criteria

- [ ] A unique `*.attacker.test` DNS-exfiltration query is denied and observable in Cilium/Hubble.
- [ ] Approved FQDN+port+SNI traffic works; no/wrong-SNI IP traffic, private/rebound targets, and every unapproved FQDN fail. An approved SNI to its learned public IP is explicitly equivalent because that is the identity visible to Cilium.
- [ ] Enforcement is demonstrated on a gVisor sandbox, with no OpenSandbox egress sidecar dependency.

## Out of scope

- Credential Vault/MITM proxying; this milestone controls reachability, not outbound secret injection or request content. An approved writable HTTPS service remains a possible exfiltration channel to an attacker-controlled account and is documented as residual risk rather than presented as DLP.
