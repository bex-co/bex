## Objective

Make `<ws>-sandbox` fail closed between pods: remove the hosting-oriented same-namespace allow from the sandbox regime and admit only the exact authenticated control/data-plane paths needed by OpenSandbox and bex-api.

## Context

- `allowNetworkPolicies` currently installs `allow-same-namespace` for both hosting and sandbox regimes.
- The same policy allows unrestricted ingress and egress between every sandbox Pod in a workspace.
- Sidecars within one sandbox share a Pod network namespace and do not need a Kubernetes NetworkPolicy exception to talk to each other.

## Steps

1. Split hosting and sandbox policy generation so only hosting receives `allow-same-namespace`.
2. Add narrowly selected ingress/egress rules for the lifecycle/exec route chosen in t001, including explicit ports and pod identities.
3. Preserve default deny for Pod/Service CIDRs, hosting namespaces, other tenants, and platform namespaces.

## Acceptance criteria

- [ ] Generated sandbox namespaces have no unrestricted same-namespace allow.
- [ ] Sandbox A cannot reach Sandbox B in the same workspace while the authenticated gateway path remains usable.
- [ ] Hosting namespace behavior is unchanged.
