## Objective

Check that the logs `limit` behavior is consistent across bex's surfaces and with Render, and flag any drift as follow-up work.

## Steps

1. Compare REST (`GET /v1/logs`), GraphQL (the dashboard's logs query) and MCP (`list_logs`, "max 100" as in `render-mcp-server`). Accepted range, served page size, `hasMore` and cursor semantics, and error shape for out-of-range values.
2. Compare with render.com: its API docs (`limit` max 100), its CLI (sends 1000 on scroll) and, if reachable, its actual response size for `limit=1000`.
3. File any drift as an inbox note through `/pm add`. In particular, file Render's served size if it is found to exceed 100.

## Acceptance criteria

- [ ] A short parity table is written into the milestone README, with every difference either fixed, filed, or recorded in ADR018.
