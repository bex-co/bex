# Render's downgrade confirmation lists what the downgrade changes; bex lists only the organization's removal

Why: Render's Confirm downgrade starts with "To initiate the changes to your plan, including:" and a list of what the new plan takes away (team members, projects, autoscaling, PITR retention, preview environments, webhooks, IP allow lists, …); bex's confirmation (w3/m708) lists only an org primary's removal of its organization, so a Pro to Hobby downgrade shows no effects at all.

Filed by w3/m708 t007 on 2026-11-27, from Render's dashboard bundle read the same day (`billing-confirm-plan-utils-DuDK6s98.js`, its warning builder `F`; `BillingUpdatePlanConfirmation-DZzLF7e6.js`).

- **Render:** each item is a bold lead and a sentence, built from the workspace's usage and `tierUpdateWarnings` (services with autoscaling, Blueprints with previews, webhooks to delete, dedicated static IPs, metric streams, IP allow lists). [workspace-plan-change.md § Confirmation](../../docs/render-artifacts/workspace-plan-change.md#confirmation-billingupdateplanconfirmation).
- **bex:** `dashboard/src/features/workspaces/components/update-plan-confirm-page.tsx` draws the list only when `removesOrganization`. What a bex downgrade really does lives in bex-api: the PITR window (`core.PITRVisibleFromAfterPlanChange`), the log and metrics window (`core.LogsVisibleFromAfterPlanChange`), the builds kept for rollback (`core.KeptBuilds`), autoscaling, webhooks and request logs gated below Pro (`core` plan gates).
- **Done when:** the confirmation lists, in Render's words where Render has them, each effect bex applies to this workspace on this downgrade (read from bex-api, not guessed in the dashboard), and a test pins the list for a Pro to Hobby and a Scale to Pro downgrade.
