## Objective

Let the live tail follow a running build: `GET /v1/logs/subscribe?type=build` streams the current `bld-<name>-gen-<N>` Job pod's logs from `BEX_BUILD_NAMESPACE` (the `PodLogStream` seam, like `type=predeploy`'s query path reads Job pods), instead of today's behavior where build logs are store-query-only. Keep the m8 honesty rules: a type the tail can't serve is refused with a named error event, never silently widened; no running build ⇒ an honest terminal event, not a hang.
