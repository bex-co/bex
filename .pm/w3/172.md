# A dead project's sidebar still offers Overview, Observability, New View and Settings

Why: `/project/<dead id>` draws "Page not found", but the sidebar beside it lists the project's pages and its + New View menu as if the project existed. Every other resource's sidebar drops its nav for a dead id, because "a sidebar of dead links would contradict" the not-found state (`database-sidebar.tsx`).

Filed by w3/m706 t007 on 2026-11-28, from the production walk on pin `7d1dce861173` as the QA user in `bex-canary`, at 1440: `/project/prj-d0000000000000000000` draws Page not found, and its server-rendered and hydrated sidebar both read "Dashboard prj-d0000000000000000000 Overview Observability New View Manage Settings". For a dead id, `/services/…`, `/databases/…`, `/keyvalue/…`, `/blueprints/…` and `/sandbox-groups/…` show the back link and the id alone.

- **Cause:** `ProjectSidebar` (`dashboard/src/common/components/dashboard-layout/project-sidebar.tsx`) takes the project's name from the workspace's project list (`useProjects`) and draws its nav unconditionally. The other rails read the resource and set `showNav = loading || resource !== null`.
- **Fix:** give `ProjectSidebar` the same gate: read the project (the route loader's `ProjectDocument` is in the cache) and leave the nav and + New View out once the read settles on nothing, keeping them while it loads.
- **Done when:** `/project/<dead id>` and a project the caller cannot see show the back link and the id with no nav, a live project's nav never flashes empty while it loads, and a sidebar test covers both.
