## Objective

`POST …/stream` submits a prompt turn to a **live** session: the driver gains a turn-submission endpoint feeding its persistent ACP session (`persistSession`), the gateway forwards the POST body verbatim, and the `steer` verb narrows accordingly.

## Context

- Driver today (`lego/agent-image/driver/src/server.mjs`) serves only the broadcast `GET /stream`; turns run headless from env. A live turn = `streamText` over the existing provider on the persistent session (m42 shipped resume-mode; `acp.mjs` owns the provider lifecycle). One turn at a time — concurrent POSTs get a 409-equivalent part/error.
- Wire shape: accept the AI SDK `sendMessages` request body (id, messages/trigger) — the driver extracts the new user prompt; response is the turn's SSE stream (same hub, so `GET` watchers see it too).
- Steer narrowing (ADR047 § D9): live-session `steer` → documented 409 pointing at the stream POST (or transparent server-side absorption — decide and record in the ADR); idle/terminal redispatch unchanged; MCP `steer_agent_session` remains a one-shot alias.

## Steps

1. Driver: `POST /turn` (or POST on `/stream`) → validate single-flight, run the turn via the persistent provider, publish parts to the hub, update the status file per turn.
2. Gateway: forward POST (ticket-authenticated, same claims) to the driver; response is the SSE turn stream; tee as in t002.
3. bex-api: `Steer` gains the live-path narrowing + error copy; keep redispatch for idle; update `turns` accounting from transcript turn boundaries (t001).
4. Record the absorption decision (409 vs absorb) in ADR047 § D9.

## Acceptance criteria

- [ ] A live POST turn executes in the sandbox on the same branch; its parts stream back on the POST response **and** to concurrently attached GET clients; transcript gains the turn.
- [ ] Concurrent POST during an in-flight turn fails closed with a named error; single-flight proven by test.
- [ ] Live-session `steer` behaves per the recorded decision; idle redispatch unchanged (existing tests stay green).
