## Objective

Make `GET …/stream` the universal history API: on attach, replay the stored transcript from the store, then splice the live tail without gap or duplication; for terminal sessions, replay everything and close with `[DONE]` — this replay mode **is** the transcript-read API (ADR047 § D9 target shape).

## Context

- `useChat` consumes this directly (`messages` seeding becomes unnecessary; `resumeStream`/`reconnectToStream` hit this GET). AI SDK reconnect semantics: a dead stream must end cleanly, not hang.
- Splice correctness: the tee assigns monotonic sequence numbers (t001); replay reads to sequence S, live fan-out delivers > S — the boundary must be exact under concurrent writes.
- A session with a live sandbox but no active turn should hold the connection open (heartbeat comments per SSE convention) rather than closing.

## Steps

1. On attach: snapshot the session's max sequence, stream stored parts ≤ S, subscribe to live fan-out > S, then bridge.
2. Terminal phases (`completed`/`failed`/`canceled`): replay all parts, emit `[DONE]`, close.
3. Optional `Last-Event-ID`/cursor query param to resume replay mid-transcript (cheap, helps huge transcripts).
4. Extend `scripts/agent-session-verify.sh`: attach mid-run → assert replay+live continuity; reattach after disconnect → no duplicates; attach after completion → full replay + `[DONE]`.

## Files

- `lego/backend/internal/sshgateway/agent_attach.go` (replay path)
- `scripts/agent-session-verify.sh` (live E2E legs)

## Acceptance criteria

- [ ] Attach during a turn yields every part exactly once (replay∪live, no gap/dup) — asserted by test on sequence numbers.
- [ ] Terminal-session attach replays fully and terminates with `[DONE]`; `useChat` (or a protocol-equivalent test client) parses it cleanly.
- [ ] Gateway restart between turns does not lose replay (store-backed).
