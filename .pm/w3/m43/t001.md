## Objective

Durable per-session transcript storage in the control-plane Postgres: every UI-message stream part the gateway tees is persisted in replayable order, keyed by session and turn, surviving gateway restarts and sandbox teardown.

## Context

- ADR047 gaps 1+5 and § D9 target shape: replay serves reattach **and** terminal-session history; the store — not gateway memory — is the source of truth.
- Parts are the AI SDK UI-message stream events (JSON lines incl. `data-acp` parts) exactly as emitted by the driver (`lego/agent-image/driver/src/session.mjs` → `server.mjs`); store verbatim JSON, no re-encoding (verbatim-forward guarantee extends to storage).
- Existing store conventions: `lego/backend/internal/store/` (migrations numbered; `agent_sessions` is 0060/0066). Retention should follow an env-tunable window (audit precedent `BEX_AUDIT_RETENTION_DAYS`).

## Steps

1. Migration: `agent_session_transcripts` (session id FK, turn number, monotonic sequence, part JSON, timestamps); index for ordered replay; ON DELETE CASCADE from `agent_sessions`.
2. Store methods: append (batched), ordered scan by session (optionally from a sequence cursor), turn boundaries; prune hook wired to the existing retention sweep pattern.
3. Record per-turn prompt text at turn start (closes the "turns is a bare counter" gap — the prompt is the first part of each turn).

- [ ] Append + ordered replay round-trips byte-identical part JSON on a real Postgres (integration test).
- [ ] Cascade delete with the session row; retention prune covered by test.
- [ ] Per-turn prompt recoverable from the transcript alone.
