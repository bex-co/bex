## Objective

Wire each new-user-path empty state's primary action to its create flow, gated by the same permission the page's existing create button uses.

## Context

- Create flows: new service (`routes/services.new.tsx`; Overview already has a "New" dropdown in `routes/index.tsx`), `routes/blueprints.new.tsx`, `features/env-groups/components/new-env-group-dialog.tsx`.
- Locales: `features/*/locales` en + zh.

## Steps

1. Overview empty: "Create a service" (primary) → the new-service flow; "New project" secondary if the page offers it today.
2. Blueprints empty: "New Blueprint" → `blueprints.new`.
3. Env groups empty: "New environment group" → opens the existing dialog.
4. Hide or disable each action exactly when the page's existing create control is hidden/disabled for the caller.
5. en + zh strings.

## Files

- `dashboard/src/routes/index.tsx`, `routes/blueprints.tsx`, `routes/env-groups.tsx`
- the three features' `locales/`

## Acceptance criteria

- [ ] Each action opens its create flow (component test per page).
- [ ] A caller without create permission sees no enabled action (test).
- [ ] zh strings present for every new key.

## Out of scope

- Empty states outside the new-user path.
