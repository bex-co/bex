## Objective

Wire the session completion path (ADR047 D4): when the driver's headless turn finishes, the sandbox pushes the session's `bex-agent/*` branch (m38 helper token), the driver signals completion, and bex-api opens a **draft PR** via the GitHub App — recording branch + PR URL on the `agent_sessions` row and transitioning the session to `completed`.

## Context

- GitHub App client: `lego/backend/internal/github/client.go`; PR creation needs the installation token (`pulls:write` — check/extend the app permission set; a permission change requires tenant re-acceptance on the installation, flag if so).
- Completion signal: driver exit status + a completion callback contract (driver → gateway → bex-api, or the session poller reading sandbox state) — pick the simplest honest mechanism and document it.
- One branch + one PR per session (Copilot model); re-runs push to the same branch and update the same PR.

## Steps

1. Driver completion hook: push branch, emit completion (status + head SHA).
2. bex-api: on completion, open the draft PR (title/body from the task prompt + session id), store branch/PR URL, set phase.
3. Failure path: push or PR-open failure → session `failed` with a named reason.

## Files

- `lego/agent-image/driver/`, `lego/backend/internal/agentsession/`, `lego/backend/internal/github/client.go`

## Acceptance criteria

- [ ] Completed session yields a draft PR on the target repo from the `bex-agent/*` branch
- [ ] Branch/PR URL on the session record across all three surfaces
- [ ] Push/PR failures produce `failed` sessions with reasons, never hangs
