# 048 — A new account's workspace is named after its raw id instead of "<Name>'s Workspace"

Why: Render names the workspace it creates at signup after the person ("Tian Pan's Workspace" in the operator's own Render account, seen 2026-10-29), but bex's signup path inserts the tenant with `name = id` (`lego/backend/internal/store/store.go` `CreateTenantWithMember`: `VALUES ($1, $1, …)`), so the dashboard's workspace switcher, settings and every workspace picker show `tea-dbi22f1jg4r76k3u33gg` (dev-3 first-run walk, `w3/m176` t005, 2026-10-30). Render parity gap on the first screen every user sees.

- `EnsureTenant` (`internal/api/tenancy.go`) already has the identity; pass its name (fallback: the email local part) and create the tenant as `"<name>'s Workspace"` (Render's shape; check Render's exact casing/possessive for names ending in "s").
- Do not rename existing workspaces silently; consider a one-off migration only for rows whose `name = id`, and record the decision.
- Tests: store/real-DB test that a new member tenant gets the derived name; dashboard shows it in the switcher. Render parity note in ADR018.
