## Objective

Deploy the ssh-gateway **in-cluster** on the CAPD `bex` cluster (it cannot run host-side — see the runbook placement table), with everything its four transports need.

## Context

- The gateway is the shared image's `ssh-gateway` entrypoint; prod manifests in `lego/operator/config/ssh/{deployment,service,serviceaccount,networkpolicy}.yaml`. It is the only workload with `pods/exec`.
- Hard requirements at startup: `BEX_CP_DB_URI` (+ `dbrole.CheckRequiredPrivileges`), `BEX_OPENFGA_URL`, `BEX_SSH_HOST_KEY_PATH` (Ed25519) (`cmd/ssh-gateway/main.go:66-68`).
- Transports gate on `BEX_SANDBOX_EXEC_SECRET` (exec/git/model) and `BEX_SHELL_TICKET_SECRET` (attach); both must **byte-match** host bex-api. Attach dials `podIP:8787`; git/model are pod→gateway over cluster DNS.
- Reach bex-db via in-cluster DNS (`bex-db-rw.<ns>.svc:5432`), not the host port-forward. Reuse `bex-db` creds or the `bex_ssh_gateway` role (`scripts/ssh-gateway-db-role.sh`).

## Steps

1. Build the shared image's `ssh-gateway` entrypoint; import into CAPD nodes (as t004) with `IfNotPresent`.
2. Generate an Ed25519 host-key Secret; apply the `bex_ssh_gateway` DB role (or reuse `bex-db-app`).
3. Deploy Deployment + ServiceAccount + RBAC (`pods` get, `pods/exec`) + Service (2222/8080-8084/9090), pinned to a schedulable node, with `BEX_OPENFGA_URL`, in-cluster `BEX_CP_DB_URI`, and the two shared secrets matching host bex-api. Omit the restrictive ingress NetworkPolicy locally (or label the sandbox ns `app.bex.co/regime=sandbox`).

## Files

- `scripts/dev-env.sh` / `scripts/dev-env/` (local gateway manifest set, host-key/DB-role helpers).

## Acceptance criteria

- [ ] Gateway pod Ready; `/healthz` OK on the aux listeners; DB privilege preflight passes.
- [ ] Its `BEX_SHELL_TICKET_SECRET` / `BEX_SANDBOX_EXEC_SECRET` equal host bex-api's.

## Out of scope

- The reverse-hop mint URLs + port-forwards (t006); prod NetworkPolicy/Cilium enforcement.
