## Objective

Install the sandbox substrate into the CAPD `bex` cluster: the `CiliumNetworkPolicy` CRD (so session-egress `Create` succeeds under Calico), and the OpenSandbox controller + `BatchSandbox` CRD, plus a relaxed local pod template that schedules on a plain CAPD node.

## Context

- `sessionegress.Manager` creates `CiliumNetworkPolicy` (cilium.io/v2) before sandbox creation (`internal/sessionegress/policy.go:55,309`); CAPD runs Calico, so only the CRD is needed — the policy is inert (acceptable for dev).
- Controller + CRDs ship in the vendored chart `deploy/gitops/charts/opensandbox-controller/` (CRD at `templates/crds/batchsandboxes.yaml`), image `ghcr.io/bex-co/opensandbox-controller:v0.2.0-bex-snapjobns-terminalpod` (`deploy/gitops/base/values/opensandbox-controller.values.yaml`). Runs in `opensandbox-system`.
- `deploy/opensandbox/batchsandbox-template.yaml` requires `runtimeClassName: gvisor` + `nodeSelector bex.co/pool=sandbox` + toleration — none present on CAPD. The template is pluggable via `[kubernetes] batchsandbox_template_file` (used in t003).
- CAPD workers can't reach the apiserver (OrbStack+Calico) — pin the controller manager to the control-plane node like CNPG does (`scripts/dev-env.sh:257`).

## Steps

1. `kubectl apply` the Cilium v2 `CiliumNetworkPolicy` CRD to the CAPD cluster (CRD only, not full Cilium).
2. `helm upgrade --install opensandbox-controller deploy/gitops/charts/opensandbox-controller -n opensandbox-system --create-namespace -f deploy/gitops/base/values/opensandbox-controller.values.yaml`; patch the manager onto the control-plane node; wait for rollout.
3. Generate a relaxed BatchSandbox template (drop `runtimeClassName`/`nodeSelector`; keep `automountServiceAccountToken:false`, `restartPolicy:Never`) as a rendered file — do not edit the tracked template.

## Files

- `scripts/dev-env.sh` / `scripts/dev-env/` (Cilium CRD manifest or fetch, controller install, rendered relaxed template).

## Acceptance criteria

- [ ] `kubectl get crd ciliumnetworkpolicies.cilium.io` and `batchsandboxes.sandbox.opensandbox.io` both present.
- [ ] `opensandbox-controller-manager` reaches Ready in `opensandbox-system`.
- [ ] Relaxed template file rendered; the tracked template is untouched.

## Out of scope

- gVisor RuntimeClass / sandbox node pool (FUTURE-MAYBE #27); real Cilium.

## Completion note

Live CAPD verification refined the relaxed template: it still drops gVisor and the hosted sandbox-pool selector, but replaces them with a control-plane selector/toleration. The in-cluster gateway is pinned there too because OrbStack + Calico cross-node pod routing is unreliable.
