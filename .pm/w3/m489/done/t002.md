## Objective

The operator projects the cache tier for every caching web service and routes the Ingress through it only while it is Ready, so no rollout or failure empties the endpoints.

## Context

- `lego/operator/internal/controller/edge_cache.go`, `deployment_projection.go` (today's sidecar), the Ingress projection, and the tenant NetworkPolicies (`docs/ADR043-tenant-namespace-isolation.md`).
- `w6/m484`'s guard: a new operator image must not change a long-lived tenant template; the tier's template is one.

## Steps

1. Project the Deployment, Service and NetworkPolicy from t001's design.
2. Switch the Ingress backend only when the tier is Ready; switch back when caching turns off.
3. envtest coverage for create, Ready gating, off, and the operator-image guard.

## Files

- lego/operator/internal/controller/ (edge_cache.go, ingress projection, new tier projection), tests

## Record (2026-11-19)

Done. `reconcileEdgeCacheTier` (`lego/operator/internal/controller/edge_cache.go`) projects the tier's Deployment and headless Service on every pass, ahead of any build or gate. A tier failure is logged and never returned, so a broken tier costs the cache but never a deploy. `ingressBackend` routes to the tier (`bex-edge-cache-<app>:80`) only while one of its pods is Ready (`edgeCacheTierServing`), and back to the App's Service when none is. Turning caching off hands the proxies `no-cache`, moves the route, and removes the tier on the pass after (`retireEdgeCacheTier`). No NetworkPolicy is added (ADR004). The tier's template holds its environment labels and its image while nothing else changes, so no operator release changes it, which is w6/m484's rule (m484 has not landed; its guard is not on main). Envtest (`edge_cache_test.go`) covers create, Ready gating, the loss of every tier pod, caching off, and the projection matching what the API server stores. `container_policy_admission_test.go` admits the tier Deployment under the production workload policy. `make test` and `make lint` pass.
