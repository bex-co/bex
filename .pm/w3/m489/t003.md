## Objective

The cache process keeps entries on its tier's bounded disk with the capacity and object cap t001 chose, so it survives the app's restarts and holds objects far above today's 6 MiB.

## Context

- `lego/operator/internal/edgecache/edgecache.go` (in-memory LRU, `MaxBytes`, `MaxObjectBytes`), `lego/operator/cmd/edge-cache/main.go`.

## Steps

1. Add a disk-backed store behind the existing lookup/store interface, bounded by bytes and by the `emptyDir` `sizeLimit`.
2. Keep the in-memory index bounded; evict from the cold end as today.
3. Unit tests for eviction, the object cap and a restart of the cache process.
