## Objective

When no pin is configured, derive one from the stable control-plane host key the maintainer already holds. Then a local `fetch-app-kubeconfig.sh` or `verify-substrate.sh` authenticates the server instead of trusting `~/.ssh/known_hosts` on first use.

## Context

- `scripts/lib/ssh-hostkey.sh` `bex_ssh_hostkey_args`:
  - `BEX_SSH_KNOWN_HOSTS_FILE` set → pinned, `StrictHostKeyChecking=yes`.
  - Unset with `BEX_SSH_REQUIRE_KNOWN_HOSTS` truthy → refuse.
  - Unset otherwise → `accept-new` against the global known-hosts, with a notice.
- `.env.example:49-55`: `BEX_CP_SSH_HOST_KEY_FILE` is the path of the PRIVATE ed25519 key every control-plane node serves (w6/m153 t008). "The pin then carries one wildcard line: `* ssh-ed25519 <its public key>`."
- `fetch-app-kubeconfig.sh:41-57` `bex_fetch_env_inputs` reads `HCLOUD_TOKEN`, `BEX_SSH_PRIVATE_KEY_FILE` and `BEX_SSH_KNOWN_HOSTS_FILE` from the repository `.env`, each only when unset, assigned and not exported. `verify-substrate.sh:34-41` loads `.env` through `bex_load_env`.
- Workaround in use by other sessions: `.pm/w6/blocked/m469/t005.md` points `BEX_SSH_KNOWN_HOSTS_FILE` at a temp file holding `* <key>` from `~/.ssh/bex_cp_host_ed25519.pub`.

## Steps

1. In `bex_ssh_hostkey_args`, add a tier between "pin file set" and the `accept-new` fallback, in this precedence:
   1. `BEX_SSH_KNOWN_HOSTS_FILE`.
   2. `BEX_SSH_KNOWN_HOSTS` content, materialized to a 0600 temp file, as the workflows do.
   3. `BEX_CP_SSH_HOST_KEY_FILE`: take its `.pub` sibling, or `ssh-keygen -y -f` it, and write `* <type> <key>` to a 0600 temp file.
   4. `accept-new`.

   Tiers 1–3 pin fail-closed with the global known-hosts ignored. Clean the temp file up through the caller's existing trap, or return its path for the caller to remove.
2. Add `BEX_SSH_KNOWN_HOSTS` and `BEX_CP_SSH_HOST_KEY_FILE` to `fetch-app-kubeconfig.sh`'s `.env` input list, with the same assigned-not-exported handling. `verify-substrate.sh` gets the same inputs.
3. Say on stderr which tier was used (a path or "derived from BEX_CP_SSH_HOST_KEY_FILE"), never key material.
4. CI keeps `BEX_SSH_REQUIRE_KNOWN_HOSTS=1` plus an explicit pin and is unchanged. A derived pin also satisfies the requirement, because it is authenticated.

## Acceptance criteria

- [ ] With only `BEX_CP_SSH_HOST_KEY_FILE` set, the generated ssh options are `UserKnownHostsFile=<temp>`, `GlobalKnownHostsFile=/dev/null` and `StrictHostKeyChecking=yes`, and the temp file holds exactly one `* ssh-ed25519 …` line (test).
- [ ] A key file whose public half does not match the server fails closed. A test drives ssh against a local `sshd` or a stub that checks the options.
- [ ] With an explicit `BEX_SSH_KNOWN_HOSTS_FILE`, the stable key is ignored (test).
- [ ] No temp pin file survives the script's exit (test).

## Out of scope

- Rotating the stable host key, or changing how CI provisions `BEX_SSH_KNOWN_HOSTS`.
- Editing `~/.ssh/known_hosts`. The scripts stop depending on it; cleaning it is the maintainer's choice.
