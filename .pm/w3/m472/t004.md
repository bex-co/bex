## Objective

A new script cannot put a production credential back on a `curl` command line without a gate failing.

## Context

- `scripts/production-secrets.txt` lists the production-class secret names. `scripts/gh-secrets.sh` and `scripts/github-actions-validate.sh` check 9 already read it.
- `HCLOUD_TOKEN` is consumed locally and by CI and must be covered whether or not it is listed there.
- `scripts/ship-gates.sh` runs the repository validators before push. CI wiring lives in the workflow whose `paths` cover `scripts/` (`scripts/ci_test_inputs.py` checks inputs).

## Steps

1. Write `scripts/secret-argv-validate.sh`. Over tracked `scripts/**/*.sh` and `.github/workflows/*.yml` `run:` blocks, fail on a `curl` invocation whose arguments expand a listed name, or `HCLOUD_TOKEN`, inside `-H`/`--header`/`-u`/`--user`/`--oauth2-bearer`. Allow the `scripts/lib/curl-auth.sh` helper.
2. In workflows on ephemeral hosted runners, argv exposure is lower risk. Keep them in scope anyway, so one rule holds everywhere, and fix any hits the same way. Alternatively exclude workflows explicitly, with the reason in the script header.
3. Add `scripts/secret-argv-validate.test.sh` with a planted violation and a clean helper call.
4. Wire it into `scripts/ship-gates.sh` and the CI workflow that runs the other script validators.

## Files

- `scripts/secret-argv-validate.sh`, `scripts/secret-argv-validate.test.sh` (new)
- `scripts/ship-gates.sh`, the validator workflow under `.github/workflows/`

## Acceptance criteria

- [ ] The validator fails on the old `fetch-app-kubeconfig.sh:77` form and passes on the tree after t003.
- [ ] Its test runs in CI.

## Out of scope

- Secrets passed as environment variables to child processes, which `ps` does not show by default.
