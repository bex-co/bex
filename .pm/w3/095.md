# GraphQL `MetricSeries.parameters` is a list; Render's is one `MetricResultParameters` object

Why: Render's dashboard names a latency line from `series.parameters.quantile`, and on bex's list that reads `undefined`, so a Render-shaped client draws a percentile overlay with no names.

Found by w3/087 (2026-11-20) in Render's public dashboard bundle ([metrics-page.md § GraphQL label names](../../docs/render-artifacts/metrics-page.md#graphql-label-names-w3087-2026-11-20)). `ServiceMetrics-*.js` names a Response Times line `` `p${(e.parameters.quantile?.toFixed(2) ?? "").slice(2)}` `` and colors it by `e.parameters.quantile`, and its mock series is `parameters: {quantile: null, __typename: "MetricResultParameters"}`. bex's `MetricSeries.parameters` is `[MetricSeriesParameter]` (`metricSeriesGQLType`, `lego/backend/internal/metrics/graphql.go`): `[]` without a percentile and `[{quantile}]` with one. The input side, `MetricsQueryInput.parameters: [{quantile}]`, is a list on Render too and stays.

Consumers that select `parameters { quantile }`: `dashboard/src/features/metrics/api/metrics.graphql` (`Metrics` and `ProjectMetrics`; the dashboard reads the `quantile` label instead, so check nothing reads the field before changing it), and any installed mobile build's documents (`mobile/src/**/*.graphql`; check whether one selects it, and keep it working).

Done when GraphQL `metrics` and `projectMetrics` answer `parameters` as one object, `{quantile}` with `quantile` null when the series has none, as Render's `MetricResultParameters`; the dashboard and every shipped mobile document still validate and read their percentiles; ADR010 § Series label names and the capture say so; and a test pins the shape against a Render-shaped `series.parameters.quantile` read.
