# The dashboard sets `<meta name="theme-color">` from its theme, as Render's provider does

Why: a phone's browser bar and the installed app's title bar take the page's colour from `theme-color`; bex sets none, so on a dark (or high-contrast) dashboard the bar stays the browser's default.

Read from Render's dashboard bundle by w3/m531 (2026-11-20, [account-appearance.md](../../docs/render-artifacts/account-appearance.md) § The browser copy and other tabs; `Button-C53p1QQg.js`): the theme provider renders `<meta name="theme-color" content={tokens.getTokenValue(currentTheme, "page-primary")}>`, the current theme's page colour.

bex today: no `theme-color` anywhere in `dashboard/src` or `dashboard/server`; the theme is applied as `light`/`dark` and `high-contrast` classes on `<html>` by `ThemeProvider` (`common/providers/theme-provider/index.tsx`) and the pre-paint script (`common/components/document/theme-script.js.txt`).

Done when the document carries one `<meta name="theme-color">` whose colour is the applied theme's `--background`, set before the first paint for a stored theme and updated when the theme changes (System following the preference included), and a test pins the colour for light, dark and their high-contrast twins.
