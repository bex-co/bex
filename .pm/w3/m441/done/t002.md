## Objective

Each create records one `created` product activity row with its surface, as services and datastores already do.

## Context

- Recorder: `core.Base.ObserveProductActivity` (`lego/backend/internal/core/product_activity.go:43`), best-effort and bounded; surface from `core.ProductSurface(ctx)` (REST with `User-Agent: render-cli/…` → `cli`, MCP → `mcp`, GraphQL with a session → `dashboard`).
- Creates: `agentsessions.Service.Create` (`lego/backend/internal/agentsessions/service.go:639`), `agentsessions.Service.CreateAgentAutomation` (`agentsessions/automations.go:294`), `sandbox.Service.Create` (`lego/backend/internal/sandbox/service.go:790`). Both services embed `*core.Base`.

## Steps

1. After each create's durable success, call `ObserveProductActivity` with the workspace, the resource id (`ags-`, `aut-`, the sandbox id) and the new resource type.
2. An idempotent replay of a create must not add a second row (the store's `source_key` upsert already dedupes `created:<id>`).

## Acceptance criteria

- [x] Tests: a create over REST with a `render-cli/` user agent records `cli`; over MCP records `mcp`; a recorder error does not fail the create.

## Result (2026-11-17)

`ObserveProductActivity` after each durable success: `agentsessions.Service.Create` once the row and its OpenFGA parent tuple exist (past every compensating delete; an idempotent replay returns before it), `CreateAgentAutomation` once the row is stored, `sandbox.Service.Create` after OpenSandbox accepted it (agent-session sandboxes take their own dispatch path and are not counted). Tests in `agentsessions/product_activity_test.go` and `sandbox/product_activity_test.go`: REST with a `render-cli/` user agent records `cli`, GraphQL with a session records `dashboard`, MCP records `mcp`, a replay and a refused create record nothing, a recorder error does not fail any of the three creates. Removing each call makes its tests fail.
