## Objective

Restrict Alloy's `discovery.kubernetes "pods"` block so each node's replica only discovers pods scheduled on that node, eliminating the N× duplication.

## Context

- `deploy/gitops/base/log-shipper.yaml` — `discovery.kubernetes "pods"` currently has no node scoping, so every node discovers every pod cluster-wide, including the high-volume Traefik access-log stream `w3/m8` added.
- Two viable approaches: `discovery.kubernetes`'s `selectors { field = "spec.nodeName=<NODE_NAME>" }` (server-side field selector, most efficient — filters at the apiserver) or a `discovery.relabel` `keep` action on `__meta_kubernetes_pod_node_name`.
- **Failure mode of getting this wrong: the shipper matches nothing and the platform silently loses all logs** — this is why the fix wasn't done inline during `w3/m8` and needs live verification (t003).

## Steps

1. Implement node-scoped discovery using the field-selector approach (preferred — avoids fetching irrelevant pod objects at all) referencing the `NODE_NAME` env var from t001.
2. Test against the local mock cluster (`scripts/mock-cluster.sh`) first for basic sanity (discovery still finds local pods) before the live multi-node verification in t003.
