## Objective

Prove on a real multi-node cluster that node-scoped discovery ships every log line exactly once, with zero loss.

## Context

- This is the step the original `w3/004.md` note explicitly withheld an inline fix for — a bad node-scope match silently loses all logs, so it needs a live Loki-synced cluster, not a blind config edit.
- Pair with the existing `w3/m5/t005` and `w3/m8/t005` live-run tasks, which need the same cluster — batch them together if the cluster is available.

## Steps

1. Deploy the node-scoped config to a real multi-node cluster.
2. Generate known log volume from multiple nodes (app pods + Traefik access logs).
3. Query Loki and confirm: every expected log line is present exactly once (no loss, no duplication).
4. Confirm shipper CPU/push-bandwidth drops roughly in proportion to node count vs. the old cluster-wide behavior.
