# 045 — The Prometheus Argo Application is out of room: move the rule pack out of inline Helm values

Why: after w3/m174 and w3/m175 the local overlay's Prometheus Application models at 1,310,650 of its 1,310,720-byte budget (`scripts/test_platform_metrics.py` `verify_application_size`; prod 1,282,525), so the next alert or scrape job anyone adds fails `gitops (render)` — and trimming comments to fit is already how m174 got in.

- **Cause:** `deploy/gitops/base/prometheus.yaml` carries the whole rule pack, scrape config and Alertmanager config as inline `spec.source.helm.values`; Argo retains that text in history, `comparedTo`, `operation` and `syncResult`, so every byte counts roughly 8× (`(revisionHistoryLimit + 3) × source + 2 × application`).
- **Options:** (a) move `serverFiles.alerting_rules.yml` into a kustomize-generated ConfigMap mounted through the chart's `server.extraConfigmapMounts` / `rule_files` (rules stay reviewed in git; promtool extraction in `scripts/gitops-validate.sh` and `scripts/obs-coverage-check.sh` reads the new file); (b) lower `revisionHistoryLimit` on this Application (cheap, but loses rollback history); (c) a multi-source Application with a values file from the repo. (a) is the durable fix; (b) is a stopgap.
- **Done when:** the size check passes with ≥ 64 KiB headroom in both overlays, promtool tests and obs coverage still read the same rules, and the rendered rule set is byte-identical before/after.
- **Size:** may exceed 1h once the extraction scripts are repointed — promote if so.
