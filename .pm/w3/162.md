# A service's Instance failed event has Render's Debug menu: Logs, Metrics and SSH for that instance

Why: on Render an Instance failed event offers a Debug menu that opens the instance's logs and metrics around the failure and an SSH shell on it; bex's Events row shows the failure with no way to the instance, though bex reads every link the menu builds since w3/m707.

Filed by w3/m707 t007 on 2026-11-27, from Render's dashboard bundle read the same day (`FailureReasonFragment-*.js`, the `ServerFailed` event's `rightElems`; find it by `metricsUrl`).

- **Render:** for an instance (not the whole service) the menu links Logs `…/logs?l=[["INSTANCE","<instance id>"]]&r=<an hour before>~<a minute after>`, Metrics `…/metrics?i=<slug>-<suffix>&t=<an hour before>,<15 minutes after>` (ms) and SSH `…/shell/<suffix>`, SSH disabled with "You can only SSH into running instances. This one is not available." when the instance is gone.
- **bex:** `routes/services.$serviceId.events.tsx` renders `server_failed` with its label only; `serviceInstanceLogsHref` and `serviceInstanceShellHref` (`dashboard/src/features/logs/lib/log-search.ts`) already build the bex links.
- **Done when:** an Instance failed row naming an instance has the Debug menu with the three links over Render's windows, SSH disabled for an instance no longer running, every locale carries the strings, and a route test covers it.
