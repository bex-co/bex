## Objective

Give the isolated ssh-gateway an internal-only endpoint the in-sandbox credential helper calls to obtain a fresh session token: the gateway authenticates the calling sandbox (pod identity / session binding), proxies an authorized re-mint to bex-api's t001 verb, and returns the token — the sandbox never holds a standing credential and bex-api never talks to the sandbox network (ADR047 trust design).

## Context

- Pattern precedent: the sandbox-exec internal listener (`BEX_SANDBOX_EXEC_ADDR` `:8081`, `internal/sshgateway/sandbox_exec.go`, w3/m33) — internal-only, never edge-reachable.
- The sandbox NetworkPolicy must allow egress from the sandbox to this gateway endpoint (coordinate with w3/m40's allowlist — GitHub + model endpoint + this gateway hop).
- Caller authn: bind to the sandbox pod (source identity via Cilium/pod IP + session claim), not a bearer the guest could exfiltrate; design within the existing HMAC-ticket toolbox.

## Steps

1. New gateway listener/route (e.g. `/session-credential`) with sandbox-identity verification.
2. Proxy the re-mint to bex-api (existing internal-call pattern + shared-secret/HMAC), stream the token back; never log token material.
3. Audit-log issue events (gateway side) alongside bex-api's mint log.
