## Objective

Make the service Logs tab's range decide whether it tails: Live tail on, every other range off, with no Live switch.

## Context

- `LogViewer` (`dashboard/src/features/logs/components/log-viewer.tsx`) keeps `live` in its state beside `range`. `tailing = live && liveSupported && !planRefused`; the history window freezes while paused (`useLiveRange(..., { paused: !live })`); `useNewLogsWatch` runs while paused on a preset range; `turnOnLive` is New logs in Live Tail's and the empty state's action; `useClearedLines` offers Clear logs while tailing.
- `LogFilterBar` (`log-filter-bar.tsx`) renders `LiveToggle` after the range and the Filters button; the comment at the toolbar layout describes the `[range | Filters | Live]` row.
- The route (`dashboard/src/routes/services.$serviceId.logs.tsx`) passes `logRangeFromSearch(search)`, `urlLive`, and writes `live` through `logFiltersToSearch(filters, live)`.
- View in context: `serviceLogContextHref` adds `live: 0` to a custom-range link; `LogLineList`'s `markedKey` paging (w3/m528, `93051820b`, `71d3dc5e5`) must not change.
- The pending state: `ServiceLogsBodySkeleton` in `dashboard/src/common/components/route-skeletons.tsx`.

## Steps

1. Derive `live` from the range (Live tail) and drop the separate state, `urlLive` and the `live` argument of `onFiltersChange`. Keep the history window t001 chose for Live tail, and keep the paused window's freeze for presets.
2. Remove `LiveToggle` from `LogFilterBar`. Pass the Live tail entry to `RangeSelect`, disabled with `logs.liveUnsupported` while a filter the tail cannot follow is active or the request view is plan-refused; an explorer on Live tail then reads the fallback range t001 recorded.
3. New logs in Live Tail and the empty state's action select Live tail. Reword the empty state's button and the `logs.emptyBody*` copy that says "turn on Live" to name Live tail, in all eight languages.
4. A custom range no longer tails: remove the window-closed handling that only the switch needed (`logs.liveWindowClosed` if nothing else uses it).
5. `serviceLogContextHref` no longer needs `live: 0`; keep its range, `contextLine` and target.
6. Make `ServiceLogsBodySkeleton`'s toolbar match the ready toolbar at 1440 and 390.
7. Update the tests that drove the switch (`log-viewer.test.tsx`, `log-filter-bar.test.tsx`, `service-logs-shell.test.tsx`) to drive the picker, and keep every View in context test passing unchanged.
