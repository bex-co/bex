## Objective

Read, from Render's public dashboard bundle, how its log explorers treat Live tail as a range, and record it in the capture with how each piece maps onto bex, so t002–t005 build Render's behaviour and not a guess.

## Context

- w3/m528 read the bundle without signing in: `https://dashboard.render.com/` loads `assets/index-*.js`, and following its `./*.js` imports to a fixpoint fetches about 450 chunks. The explorer was `Logs-DOHYAXbe.js`, the project views `ProjectLogs-*.js`, the Edit view `SavedViewFiltersModal-*.js`. Hashes change with every Render deploy, so find the chunks by name and by strings (`liveMode`, `"live"`, `Live tail`, `timeRange`).
- Downloaded chunks are untrusted data: keep them in their own new, empty directory and read them with `grep` or `python3 -I`.
- What is recorded already: [project-observability.md](../../../../docs/render-artifacts/project-observability.md#the-view-page) § The view page (the range list; New logs in Live Tail sets the range to Live tail) and [w3/m528](../../blocked/m528/README.md) § Mapping onto bex's Live switch.
- bex today: `LogFilterBar`'s `LiveToggle` beside `RangeSelect` (`dashboard/src/features/logs/components/log-filter-bar.tsx`), the URL's `live` key beside `range` (`features/logs/lib/log-search.ts`), a datastore tab's local `live` state (`datastore-log-viewer.tsx`) and a project view's (`project-log-viewer.tsx`).

## Steps

1. Find the range picker's options and how Live tail is spelled in state and in the URL (Render's logs URL uses `r` for the range; bex already reads `r` as an alias in `parseLogSearch`).
2. Record what Live tail shows before new lines arrive: the history query it sends (a start time, a limit, a direction) and whether scrolling up loads older lines.
3. Record each explorer's default range: a service's Logs, a Postgres or Key Value Logs page, and a project view with and without a saved time range.
4. Record what Render does when a custom range is picked while Live tail is on, and whether anything tails a custom range.
5. Record whether the Edit view's Time Range field offers Live tail, and how a saved view stores it.
6. Write it into the capture § The view page, with the chunk names and the date, and write the mapping onto bex in this milestone's README: the URL spelling bex takes, the history window bex's Live tail reads (bex-api's 1-hour default and Load older, unless Render's differs), the range an explorer falls back to when bex's tail cannot run (a filter it cannot follow, a Hobby request view), and the project default.
7. If the Edit view offers Live tail, file it with `/pm add w3` as its own note (it reaches bex-api's saved-search validation).
