## Objective

Check that an upgrade from every supported major to the latest succeeds the same way on every surface that starts or reports one, as Render's does.

## Steps

1. Using t004's runs: REST `PATCH /v1/postgres/{id}`, GraphQL `upgradeDatabaseVersion`, MCP `update_postgres` and the dashboard's guided page (w3/m676) start the same upgrade. `lastUpgradeRun` and `GET /v1/postgres/{id}` (`version`) report the same result.
2. Compare with [render.com/docs/postgresql-upgrading](https://render.com/docs/postgresql-upgrading): an in-place upgrade from any supported version to the latest, with downtime. The extra restart after an upgrade from 13–15 falls within that downtime or right after it. Say which in ADR009 § Major-version upgrades.
3. Find the upgrade row in `docs/ADR018/` and correct anything it says about upgrades failing or about this restart. File any drift found as a follow-up note.

## Acceptance criteria

- [x] Every surface reports the same succeeded run, and ADR018's row and ADR009 describe upgrades as they now run.

## Record (2026-11-27)

- **Surfaces:** REST `PATCH /v1/postgres/{id}` and MCP `update_postgres` both reach `UpdatePostgres` with `PostgresPatch.Version` (`lego/backend/internal/postgres/mcp.go`, `update_postgres`), and GraphQL `updateDatabaseVersion` and Render's `upgradeDatabase` reach `SetVersion` (`graphql.go`), which the dashboard's guided page calls (`dashboard/src/features/databases/api/databases.graphql`, `updateDatabaseVersion`). Each writes `Database.spec.version`, and this milestone changed nothing above the operator, so every surface starts the same upgrade. On dev-3 t004's REST runs and one 15 → 18 through GraphQL `updateDatabaseVersion` (`pgu-dc4n9t9jg4r62fancpl0`, 12:17:57 → 12:19:40, row kept) each read `SUCCEEDED` in `lastUpgradeRun` while `GET /v1/postgres/{id}` answered `version` `18`, `status` `available`. The guided page offers a paid database only and the local cluster has no backups to satisfy its guard, so production's walk (t005, then w3/m676) covers it.
- **Render:** an in-place upgrade from any supported version to the latest, with downtime ([render.com/docs/postgresql-upgrading](https://render.com/docs/postgresql-upgrading)). bex now does that from 13–17 to 18, and there is no extra restart after an upgrade from 13–15 (t003 § Record), so ADR009 § Major-version upgrades says the downtime is the only interruption.
- **ADR018:** the "Postgres major-version upgrade" row in `docs/ADR018/managed-postgres.md` said nothing about upgrades failing; it now records that every source upgrades, how, and that production's repeat is t005. No new drift found, so no follow-up note.
