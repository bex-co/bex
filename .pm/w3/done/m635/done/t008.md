## Done — 2026-11-26 (shipped in `9874e5ea21`)

- **A version field its image does not carry is drift.** `toolchain-freshness.py resolve` reads every reviewed line's `version` (`native.go`, and `Version` in `lego/types/toolchains/python.go`), reads the patch the committed image records in its linux/amd64 config (`RUBY_VERSION`, `NODE_VERSION`, `PYTHON_VERSION`, `ELIXIR_VERSION` without its `v`, `RUST_VERSION`, Bun's `org.opencontainers.image.version`), and marks a disagreeing line `version_mismatch`, which the issue names. It runs in `resolve`, not `validate`, because only `resolve` reads registries; tag lookups moved to `HEAD`, which Docker Hub does not count, so the config reads fit the anonymous limit (a real run spent 30 pulls). `build-toolchain-freshness.test.sh` covers a stale field, a current one, Elixir's `v` prefix, the issue line and the registry path's Env and label reads. Mutations: dropping the drift flag fails two checks; dropping the `v` strip fails two.
- **The Bun BuildKit gate builds each reviewed line's own patch.** With the 1.4 line's field set back to 1.4.4, `TestNativeImageRunsAnOptedInBun/node/1.4.4` fails because the image runs 1.4.5.
- **The Bun and Ruby resolution tests read the reviewed patch from the table** (t002). With the table set to 1.4.6 and 3.4.14, every Bun and Ruby test passes unedited; before, the real refresh failed six of them.
