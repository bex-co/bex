# A project view's filter document is stored in Render's spellings and shape: `TEXT_SEARCH` with `CONTAINS`, `timeRange.relative`, and `display`

Why: a view document written on Render (or by a client that copies Render's) is refused by bex, and one bex stores is not one Render reads, because bex's document differs from Render's in three places the dashboard bundle shows.

Found by w3/m523 t001 (2026-11-19) in Render's public dashboard bundle (`https://dashboard.render.com/`, following its `./*.js` imports; the hashes change with each Render deploy, so find the chunks by name). The record is in [project-observability.md § Edit view](../../../docs/render-artifacts/project-observability.md#edit-view):

- **Text Search.** Render's field is `TEXT_SEARCH` with the operator `CONTAINS` (`ProjectLogs-*.js`: `operators:[CONTAINS]`, `values:{pick:"text"}`). bex stores `TEXT` with `IS` (`lego/backend/internal/savedsearch/document.go` `FieldText`, `dashboard/src/features/logs/lib/view-filters.ts`).
- **Time range.** Render keeps it out of `filters`, as `{"timeRange": {"relative": "<preset>"}}` at the top of the document (`SavedViewFiltersModal-*.js` builds `{version, filters, timeRange:{relative}, display}`). bex stores a `TIME_RANGE` filter row (`FieldTimeRange`, read by `dashboard/src/features/logs/lib/project-log-search.ts` as the view's default range).
- **Display.** Render's document has a `display` object holding a metrics view's `aggregationMethod`, `requestGroupBy`, `groupBy` and `rootTasksOnly`. bex's has none, and `Parse` refuses unknown keys (`DisallowUnknownFields`), so a Render document carrying `display` or `timeRange` is refused.
- Render's saved-search field enum otherwise matches bex's names: `ENVIRONMENT, HOST, INSTANCE, LEVEL, METHOD, PATH, RESOURCE, RESOURCE_TYPE, RUN_ID, STATUS, STATUS_CODE, TASK, TASK_TYPE, TEXT_SEARCH, VERSION` (`git-*.js`). `RUN_ID`, `STATUS`, `TASK`, `TASK_TYPE` and `VERSION` belong to Workflow Runs, a non-goal.

Done when bex stores and reads Render's spellings and shape (`TEXT_SEARCH` with `CONTAINS`, `timeRange.relative`, `display` kept as written), every stored view is migrated to it, a document in bex's old shape still reads, the Edit view modal labels Text Search's operator `contains` as Render's does, and the validator, the project log read, `projectMetrics` and the dashboard have a test each for both shapes. Record the change in ADR010 § Project views and the ADR018 Projects row.

**Done 2026-11-20.** `internal/savedsearch` stores and answers Render's document: `TEXT_SEARCH` with `CONTAINS`, the top-level `timeRange.relative`, and `display` kept as written (any JSON object of valid text, at most 4 KiB). It still reads bex's earlier spellings, a `TEXT` row as `TEXT_SEARCH` with `CONTAINS` and a `TIME_RANGE` row as `timeRange`. Migration 0316 rewrote every stored view (its down restores the earlier shape and drops `display`), and a view an older replica writes during the rollout is served in Render's shape. The Edit view labels Text Search's operator `contains` and keeps a view's `display` when it saves. Tests cover both shapes in the validator (`document_test.go`), the views service (`savedsearches_test.go`), the project log read (`logs/project_test.go`), `projectMetrics` (`metrics/project_test.go`), the migration (`saved_search_document_migration_test.go`) and the dashboard (`view-filters.test.ts`, `project-log-search.test.ts`, `edit-view-dialog.test.tsx`). Recorded in ADR010 § Project views and the ADR018 Projects row.
