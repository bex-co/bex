## Objective

Probe production the way a tenant sees it: a permanent first-party canary service is requested over its public host, then bex-api is asked — with a scoped API key — whether that request shows up in logs, whether the service has CPU/memory metrics, and whether its events feed advanced; any empty answer opens an issue. This is the only form that catches bex-api-side query bugs (the `w6/m110` class: series existed, the query named them wrong).

## Context

- Fixture: a `bex-canary` workspace (first-party, `billing_excluded` per ADR040 §7) with one free web service from `examples/hello-go`. Free-tier hibernation is fine — the probe's request wakes it, which also exercises the activator path; the events feed then shows `service_woken`.
- Credential: a workspace API key (`/v1/api-keys`, w4/m8/m13) stored as `BEX_CANARY_API_KEY` — add to `.env.example` (name only), `scripts/gh-secrets.sh`, and the ADR019 credential inventory (scope: canary workspace only; rotation: on demand). Never print it; `scripts/github-actions-validate.sh` check 6 requires the job on `bex-production`.
- Probe `scripts/tenant-view-liveness.sh`: (1) `GET https://<canary>.onbex.co/` → 200 within the wake budget; (2) poll `GET /v1/logs?resource=<srv>&type=request` (and `type=app`) until the probe's own request line (unique query param) appears, bounded ~3 min; (3) `GET /v1/metrics/cpu` + `/memory` for the last hour non-empty (after wake there is at least one sample); (4) `GET /v1/services/{id}/events` newest event within the window. Exit codes per stage; output redacts nothing secret because nothing secret is printed.
- Workflow: a `tenant-view-liveness` job in `.github/workflows/ssh-edge-liveness.yml` (or rename the file to `production-liveness.yml` and update the m131/m132 pointers), 6h cron, label `tenant-view-down`, issue open/close like the existing jobs.

## Steps

1. Create the canary workspace + service on prod (authorized operator step; record ids, not keys); mint the key; push the secret.
2. Write the probe; dry-run it locally with the key from `.env`.
3. Add the job; dispatch once; confirm green.
4. Document the fixture in ADR088 §6 + ADR019.
