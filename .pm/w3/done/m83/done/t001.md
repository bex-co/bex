## Objective

Turn "every alert gets a panel" into "every tenant-facing surface gets a falsifiable signal": one table in ADR088 §6 that classifies each surface as covered by an alert rule, covered by a scheduled probe, or uncovered — and, for each uncovered row, records which form this milestone adds (or a reasoned waiver).

## Context

- Alert inventory (43 rules, `deploy/gitops/base/prometheus.yaml`): covers platform health, builds, billing, backups, certs, datastore provisioning, egress meter, registry, WAL archiving, webhook admission — not app-log ingestion, tenant metrics, the events feed, deploy-from-git, static serving/teardown, push delivery, agent-session provisioning, or isolation invariants.
- Scheduled probes (`.github/workflows/ssh-edge-liveness.yml`, 6h): SSH KEXINIT, `*.onbex.co` fallback TLS, Web Shell WS refusal-shape, request-log tenant streams. Weekly: `render-schema-drift.yml`, `cli-release-staleness.yml`, `build-toolchain-freshness.yml`; daily: infra drift plan.
- Candidate surfaces to classify: app logs, request logs, build logs, datastore logs, resource metrics, request metrics, usage metering, events feed, outbound webhooks, push, deploy email, deploy-from-git → Ready → URL, static-site serving + teardown, custom domains/TLS, SSH edge, Web Shell, agent sessions (provision + turn), sandboxes, tenant/sandbox isolation invariants, datastore provisioning, datastore backups, billing.
- Alert-vs-probe rule of thumb: a Prometheus rule when the failure is visible in a series bex already emits; a scheduled probe when the failure is only visible from the tenant's side (a query that returns empty, a URL that 404s) or needs a fixture.

## Steps

1. Build the table from the inventory above (verify each "covered" claim by naming the rule or job).

3. Add the rule text to ADR088 §6 and a pointer from ADR010; note the `obs-coverage-check.sh` waiver list stays for alerts only.
