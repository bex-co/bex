# Crash-path stranding: an uncaught ACP-provider spawn error strands the session in `running`

**Absorbed 2026-08-17 into [`w5/m72`](../../w5/m72/README.md)** at user direction. The same failure class reproduced on production session `ags-da1prbt040bc73aj5230`, where a credential-cleanup exception killed the driver, its Pod became Failed while BatchSandbox stayed Pending, and the Completer retried against the dead container forever. `w5/m72` carries both the driver caught-failure path and the independent substrate/control-plane terminal fallback, plus the conversation-role grant outage uncovered in the same investigation.

Found live in the w3/m43 verify run (`scripts/agent-session-verify.sh` section 4 — the synthetic non-existent-adapter crash leg). Section 4 currently **warns** (does not hard-fail) on this; the conversation-API legs are unaffected.

**Symptom:** a fire-and-forget turn whose ACP adapter cannot run never reaches `failed` — the session lingers in `running` until manually canceled.

**Root cause (confirmed on prod):**

- The driver's ACP provider spawns its agent child during the turn. An **uncaught** child-process error/exit (e.g. `ENOENT` on a bad command, an async `'error'` event the provider doesn't wire into the turn promise) kills the driver's container **without** the caught-error path running — so no `status:failed` is written and the driver's stay-alive fix (shipped this session) never engages.
- OpenSandbox keeps reporting the sandbox as **pending/creating** (BatchSandbox `Progressing`), not terminal, even though the pod's container has exited. The Completer's `ReadSessionStatus` therefore exec's into a dead container forever (`exec failed to start in this sandbox`, logged every tick) and never finalizes. The terminal-state fail-closed check added this session (`StatusTerminated`/`StatusErrored`) does not fire because OpenSandbox never reports terminal here.

**Fix directions (both carried by w5/m72):**

- **Driver:** wire fatal child/cleanup errors into the turn failure contract so `runHeadlessTurn` writes `status:failed` and remains observable until the Completer acknowledges it.
- **Substrate + control plane:** project a failed child Pod into BatchSandbox/OpenSandbox terminal status and independently let the gateway report a dead/terminated Pod so the Completer cannot strand a session if upstream status is stale.

This is fire-and-forget robustness (m41 lineage), now tracked together with the exact production recovery. Related: `scripts/agent-session-verify.sh`.
