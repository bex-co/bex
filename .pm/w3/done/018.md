# Driver-only: adopt Vercel AI SDK harness layer for ACP (simplify ai-sdk↔acp chain)

**Type:** proposal / spike (driver-only). **Touches:** ADR047 D3/D9 (agent-session conversation plane). **Blast radius:** small — the in-sandbox driver + client parts classifier only; gateway, bex-api, transcript, Completer unchanged.

## Problem

The in-sandbox agent-session driver (`lego/agent-image/driver/`) bridges the ACP agent (`claude-code-acp`) to the browser through a lossy round-trip:

1. `acp.ts` — `createACPProvider(@mcpc-tech/acp-ai-provider)` wraps the ACP agent as a `LanguageModelV3`.
2. `session.ts:182` — `streamText(model).toUIMessageStream()` — **drops** the ACP `session/update` raw parts (plans, diffs, terminals).
3. `session.ts:195` — separately drains `.fullStream` raw chunks, re-wraps them as `data-acp` (`rawUIMessagePart`) to recover the lost structure.
4. Browser `dashboard` `acp-parts.ts` — `classifyAcpData(...)` re-classifies `data-acp` back into plan/diff/terminal shapes.

Net: **ACP → LanguageModel → UI stream (lossy) → data-acp re-wrap → browser re-classify** — structure is torn apart and reassembled, with reassembly code on both the driver and the client. Also depends on a third-party 0.2.x package (`@mcpc-tech/acp-ai-provider`).

## Proposal

Replace the provider + hand-rolled `streamText`/`toUIMessageStream`/raw-drain with Vercel's first-party **AI SDK harness layer**: `HarnessAgent` + `@ai-sdk/harness-acp` (uniform ACP path first). The harness layer projects agent built-ins (diffs, tool calls, `fileChange`, terminal) as **typed UI-message parts** natively (`tool-*`, `dynamic-tool`, `part.state`), so:

- driver drops the `.fullStream` raw-drain + `data-acp` re-wrap (`session.ts`);
- client `acp-parts.ts` `classifyAcpData` shrinks or disappears — render built-ins like normal AI-SDK tool parts;
- swaps a third-party provider for a Vercel-maintained package on the same `ai` SDK already shipped.

**Follow-up (optional):** route claude/codex through the *direct* adapters `@ai-sdk/harness-claude-code` / `@ai-sdk/harness-codex` (Vercel recommends direct over ACP where available — tighter integration), keep `@ai-sdk/harness-acp` for gemini. Keeps the uniform-path migration low-risk first.

## Guardrails / non-goals

- **Byte-transparency stays intact.** Driver still emits `x-vercel-ai-ui-message-stream: v1`; gateway (`agentattach.go`) + bex-api untouched.
- **Do NOT adopt the harness layer's session/resume or sandbox lifecycle.** It's built around `createVercelSandbox` + an opaque resume-state store; we run OpenSandbox on our own k8s with the ADR051 Completer log-harvest + Postgres transcript. Take only the *adapter + HarnessAgent stream*, not its persistence/sandbox model.
- New 0.x packages; ACP may under-expose some harness internals (per Vercel's own caveat). **Spike + verify typed parts arrive before committing.**

## First step

Driver-only spike in `lego/agent-image/driver/`: swap the provider for `HarnessAgent` + `@ai-sdk/harness-acp`, confirm plans/diffs/terminals arrive as typed UI parts, then delete the `data-acp` re-wrap and simplify `acp-parts.ts`. If clean, promote to a milestone (driver swap + client simplification + parity check across the conversation surface + tests).
