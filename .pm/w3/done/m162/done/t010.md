## Outcome

Reviewed the milestone's diff for the specific duplication risks this task named, and
found none worth changing:

- `store.ErrWorkspaceGone` has exactly one producer (`verifyBillingProviderMapping`)
  and one consumer (`Lifecycle.HandleStripeEvent`).
- The 23503 branch in `billing_lifecycle.go` is deliberately narrower than the generic
  `classify()` helper — it matches by constraint name so an unrelated FK violation
  still surfaces as a real error — so the two are not a duplicated concern.
- The two new Stripe metadata constants sit with the existing ones in `stripe.go`.
- `Customers.Update` now appears in three places (workspace creation, payment binding,
  retirement); each carries different semantics and different idempotency keys, so
  folding them would obscure rather than simplify.

The event whitelist was consolidated during t005 into a single `lifecycleEventTypes`
slice that `isLifecycleEvent`, `HandledStripeEventTypes`, and the drift script all
derive from — that was the one real duplication the milestone would otherwise have
introduced.
