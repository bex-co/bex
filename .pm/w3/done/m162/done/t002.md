## Objective

Deleting a bex account cancels the Stripe subscription and stops there. The Stripe Customer survives with the card still attached, still set as `default_payment_method`, and with the user's `email` and `name` intact — while every trace of the tenant is gone from bex. Extend the deletion purger to detach the payment instruments and anonymize the Customer, without deleting the Customer object itself.

## Context

- `lego/backend/internal/billing/contracts.go:127-150` — `CancelContract` cancels the subscription and returns; nothing touches payment methods or customer PII.
- Reproduced twice in production:
  - `tea-dadkqjrr12dc73ba2hg0` deleted 2026-09-05 00:38:10 → `cus_VCV5qtrtlYh0N0` still has 1 attached PM and `default_payment_method` set.
  - `tea-dalhl0rrvmrc739ndahg` deleted 2026-09-16 ~23:27 → `cus_VGzT7XpXc4z57t` still has 1 attached PM, `default_payment_method`, and `email`/`name` present.
- The purger framework already exists: `lego/backend/internal/workspaces/service.go:1199` (`PreCascadePurgers`), wired in `lego/backend/cmd/api/main.go:741`.
- Purgers must be idempotent/retryable — `service.go:1193-1198` documents that re-issuing an identical Delete re-runs the whole sweep. Detach and anonymize are naturally idempotent.
- **Do not delete the Stripe Customer.** Invoice retention requires it; deleting the Customer would orphan already-issued invoices.

## Steps

1. Extend `CancelContract` (or add a sibling called from the same purger) so that after cancelling the subscription it: lists the Customer's payment methods, detaches each one, clears `invoice_settings.default_payment_method`, then updates the Customer with empty `email`/`name` and metadata `bex_deleted_at=<RFC3339>`.
2. Keep it retryable: a Customer already anonymized must be a no-op, not an error. A missing Customer is already handled (`findCustomer` → `!found` → `nil`).
3. Use deterministic idempotency keys for the write calls, matching the existing convention (`bex-payment-customer-…` in `billing/sessions.go:323`).
4. Remediate the two known orphans manually after the code lands, using the same operations.
