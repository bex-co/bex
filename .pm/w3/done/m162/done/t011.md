## Objective

Add tests that would have caught each defect this milestone fixes. Every test must assert real behavior and a real failure mode — no tautologies, no snapshot-everything.

## Context

- The whole milestone exists because these failures were invisible: a 503 loop discovered only by reading a metrics counter, a Stripe-side leak discovered only by querying Stripe per customer, an empty analytics dimension discovered only by counting rows. Tests here are the thing that turns each into a loud failure.
- The backend suite runs against real ephemeral Postgres and OpenFGA in CI (`lego/backend/CLAUDE.md`), so foreign-key behavior is exercisable for real — t001's defect is precisely an FK violation and must be tested against a real database, not a mock.

## Steps

1. t001 — delete a workspace against a real Postgres, deliver `customer.subscription.deleted`, assert 204; and assert a store failure for an existing workspace still errors.
2. t002 — assert post-deletion Customer state (no payment methods, no default, anonymized, still present) and purger idempotency.
3. t003 — assert version-mismatch dispatches, signature/livemode mismatch reject, and each rejection logs.
4. t005 — assert the drift check fails on a missing and on an extra event type.
5. t006 — assert a subscription-without-card is reported not-bound by every payment-state reader.
6. t008 — assert a QA-configured workspace without an audience row fails the guard.
7. t009 — assert a failed services list produces a correct count with an honestly-labeled state dimension.
8. Spot-check by mutation: break each fix in turn and confirm the corresponding test fails.

## Files

- `lego/backend/internal/billing/*_test.go`
- `lego/backend/internal/store/*_test.go`
- `scripts/` test harnesses for the script-level changes

## Acceptance criteria

- [x] Each of t001, t002, t003, t005, t006, t008, t009 has at least one test that fails when its fix is reverted.
- [x] The t001 test runs against a real Postgres and genuinely exercises the FK path.
- [x] No test asserts only that a function returns without error.

## Out of scope

- Coverage targets or metrics.

## Outcome

Coverage was written alongside each fix rather than as a trailing pass, and every test
was checked to fail when its fix is reverted:

- t001 — `TestPGStoreStripeBillingEventForDeletedWorkspaceReportsWorkspaceGone` and
  `TestPGStoreStripeBillingEventConflictOnLiveWorkspaceStillFails` against a real
  Postgres (the defect is an FK violation, so a mock would not have exercised it), plus
  `TestLifecycleAcknowledgesEventsForDeletedWorkspaces` /
  `TestLifecyclePropagatesOtherStoreFailures`. Mutation-checked: reverting the handler
  ignore fails the first; pointing the constraint match at a wrong name fails the store
  test with the exact production error text.
- t002 — `TestCancelContractRetiresPaymentInstrumentsAndPersonalData` (every method
  detached, invoice default cleared, email/name emptied, `bex_deleted_at` set, Customer
  kept) and `TestCancelContractNoLiveSubscriptionStillRetiresTheCustomer`.
- t003 — `TestStripeWebhookDispatchesDespiteApiVersionMismatch` and
  `TestStripeWebhookRejectsIncompatibleMode`.
- t004 — promtool unit tests for both new rules, including that a version mismatch does
  NOT page and that a never-delivered replica does not read as silence.
- t005 — the drift script's own failure paths exercised against production Stripe
  (absent endpoint → 2, bad key → 2, real endpoint → 0).
- t006 — `TestPGStoreCheckoutStartIsRecordedSeparatelyFromBinding`.
- t008 — `TestPGStoreNewWorkspacesAreClassifiedForAnalytics`.
- t009 — `TestProductInventoryMarksStatesUnobservedWhenTheListFails`.

All four CI suites green. One CI-only failure surfaced after the first push (the
product-analytics suite builds its schema from a curated migration list that did not
include 0124) and was fixed in `2f2a057db`.
