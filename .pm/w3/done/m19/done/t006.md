## Objective

Add a typed operator-status handoff for autoscaler-driven replica transitions so the backend can record `autoscaling_started` and `autoscaling_ended` without giving the operator a database path.

## Context

- The custom autoscaler writes its effective replica count through an App annotation and reconciles a Deployment, but App status exposes no typed from/to scaling edge.
- Manual scale is already `instance_count_changed`; autoscaling activity must not reuse or duplicate that event.
- Render's start/end details require from/to instance counts; current/target CPU or memory is optional.

## Steps

1. Add a compact `AppStatus.Autoscaling` observation with stable transition identity, from/to replicas, state, and timestamps.
2. Have the operator update it only when autoscaling—not manual scale—begins changing the desired count and when readiness reaches the target.
3. Have the backend reconciler persist start/end facts idempotently from that status.
4. Preserve existing config-change and manual-count events and verify the three types cannot be confused.

## Acceptance criteria

- [ ] One autoscaler change from N→M emits one started event and one ended event after M is ready.
- [ ] A manual scale emits only `instance_count_changed`.
- [ ] Reconcile retries, readiness flaps before completion, and process restart do not duplicate a transition.
- [ ] The operator remains mechanism-only and DB-free.

## Out of scope

- Billing, predictive autoscaling, or a new HPA implementation.
