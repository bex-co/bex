## Objective

Turn the current 20-row card into a useful activity timeline: grouped multi-select filters, rich event-specific summaries, and explicit older-history loading across retained windows.

## Context

- The captured Render page has a `Filter events` control with grouped human labels, paired intent/observed status entries, deploy links/actions, and cursor loading through weeks of history.
- bex currently has no event filter on the Events route and maps unknown types to the generic “Service changed.”
- `dashboard/src/features/webhooks/event-catalog.ts` already proves the grouped/searchable served-vocabulary presentation pattern, but service-event labels and semantics differ from outbound webhooks.

## Steps

1. Add a service-event presentation catalog matching the supplied Deploy / Service Status / Scaling / Maintenance / Maintenance Mode / Edge Cache taxonomy, displaying only truthful supported types and documenting omissions rather than offering dead filters.
2. Add a searchable grouped multi-select filter with an all-events state and selected count; filter the accumulated feed without issuing one request per checkbox.
3. Render failure/recovery, observed suspension/resumption, branch/commit, autoscaling, and image-pull details with accessible icons, timestamps, and deploy links where present.
4. Add automatic or explicit older-history loading, a terminal retained-history state, and separate no-events-in-filter vs no-history states.

## Acceptance criteria

- [ ] A quiet service with old events does not show the initial empty state.
- [ ] Filters expose supported labels in the requested groups and never imply unsupported mechanisms exist.
- [ ] Loading older history preserves order, scroll context, and event-id deduplication.
- [ ] Narrow and desktop layouts remain usable and every visible string is localized.

## Out of scope

- UI for preview environments, workflows, platform maintenance runs, pipeline billing, or edge-cache controls.
