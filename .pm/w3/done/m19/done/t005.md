## Objective

Make source-control decisions visible: a typed branch change from a service update and a commit-ignored fact when a valid signed push targets the service but intentionally does not deploy it.

## Context

- `apps.SetSource` currently maps every repo/image/branch edit to the coarse `source_changed` event.
- `GitWebhook.redeployMatching` silently drops repo+branch matches rejected by Root Directory or Build Filters.
- Render exposes Commit Ignored; the supplied dashboard filter also exposes Branch Changed, while the public API currently names only `branch_deleted`, so bex must not lie about deletion.

## Steps

1. Record typed previous/current branch columns for an actual branch change and expose an honest `branch_changed` bex extension unless the fresh Render capture proves an exact public type.
2. Extend the signed push payload slice with non-secret commit id/URL/message fields needed to apply Render skip phrases and explain a filter decision.
3. Persist one `commit_ignored` fact when a repo+branch-matching push is rejected by a skip phrase, Root Directory, or Build Filters; do not emit for unrelated repos/branches or Auto-Deploy-off services.
4. Keep the webhook response idempotent under Git-host delivery retries.

## Acceptance criteria

- [ ] A real tracked-branch edit produces one event with typed from/to values.
- [ ] A matching filtered/skip-phrase push produces one `commit_ignored` and no deploy row.
- [ ] Retrying the same signed delivery produces no duplicate event.
- [ ] Unrelated and Auto-Deploy-disabled services receive no commit event.

- GitLab/Bitbucket integrations or PR previews.
