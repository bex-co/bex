## Objective

Add the smallest append-only control-plane source needed for events that are neither a deploy row's opening/closing timestamp nor an authorized API write, while keeping the operator DB-free and making duplicate resyncs harmless.

## Context

- `internal/events` currently UNIONs only `deploys` and `audit_events`; observed service health and intermediate deploy/scaling edges have no durable source.
- `store.Reconciler` already observes App status and persists deploy state from bex-api, so it is the correct DB-writing side of the operator→App status→control-plane boundary.
- Existing event redaction is structural: no generic details JSON or arbitrary verb arguments may reopen a secret path.

## Steps

1. Define a typed event-fact/checkpoint schema with stable source keys, App/workspace identity, a closed event kind, transition time, and only the scalar detail columns required by accepted event types.
2. Add idempotent store methods that insert a fact and advance its observed-state checkpoint atomically; the same reconciler observation must be a no-op.
3. Add a third projection arm to the service-events query and the workspace-wide webhook query, retaining total ordering, keyset cursors, retention behavior, tenant isolation, and derived `evt-` ids.
4. Document why bex-api persists the fact after observing typed App status and why the operator receives no database client.

## Acceptance criteria

- [ ] Replaying one observation/resync inserts exactly one event fact.
- [ ] Facts page correctly when interleaved with deploy and audit rows.
- [ ] No generic JSON/details or arbitrary message/value column can contain env/secret input.
- [ ] The operator module still does not import backend/store code or receive control-plane credentials.
