## Objective

Lock the milestone's real failure modes: repeated observations, interleaved three-source paging, transition discrimination, filtered Git pushes, explicit time windows, and accessible empty/filter states.

## Context

- A page that returns zero rows after LIMIT or loses a cursor boundary looks exactly like end-of-history.
- Level-triggered reconciliation makes duplicate events the primary ingestion risk.
- Event details are security-sensitive because a future generic value field would undo the feed's structural redaction guarantee.

## Steps

1. Add migration/store tests for idempotent source keys, checkpoints, retention, tenant isolation, and interleaved cursor pages.
2. Add table-driven service tests for every new event mapping, required details, unknown filters, and retry/no-op behavior.
3. Add operator/types tests for autoscaling and availability status edges without manual-scale confusion.
4. Add dashboard tests for explicit ranges, fetch-more accumulation, filter catalogs, rich rows, and distinct empty/error/end-of-history states.
5. Keep a planted secret sentinel in cross-surface serialization tests.

## Acceptance criteria

- [ ] Tests fail on duplicate resync facts, missing cursor rows, over-wide windows, or cross-tenant facts.
- [ ] Every new event type has positive and wrong-source/negative coverage.
- [ ] The secret sentinel cannot appear in REST, GraphQL, MCP, dashboard fixtures, or webhook payloads.
- [ ] Backend, operator/types, and dashboard suites pass.
