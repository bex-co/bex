## Objective

Rewrite only the Rust line's `version` and digest, and refuse anything else.

## Context

- `lego/operator/internal/build/native.go:225-231`: `{line: "1", version: "1.100.0", image: "rust:1-bookworm@sha256:ade39…"}`; `line` and `defaultLine` stay `"1"`. The `version` field is what the build log names (w8/327).
- The official image runs `rustup-init --default-toolchain $RUST_VERSION`, so a default build uses exactly the pinned release; bex sets no `RUSTUP_TOOLCHAIN`.
- A wrong `version` is caught today only by the opt-in `BEX_NATIVE_TEST_GORUST_PROFILE`, which the bump job does not run.

## Steps

1. Add `rust-apply` for `native.go` and the `native-rust` inventory entry.
2. Cross-check `version` against the image's `RUST_VERSION`.
3. Add a `TestNativeRustLineIsItsImageTag`-style guard of the entry shape.

- `scripts/lib/toolchain-freshness.py`
- `lego/operator/internal/build/native.go`
- `lego/operator/internal/build/toolchain-freshness.json`

## Acceptance criteria

- [ ] A simulated bump rewrites exactly two values and passes `scripts/image-pin-validate.sh`, the inventory validation and `go test ./internal/build/...`; any other diff is refused.

## Done — 2026-11-26

- `rust-apply` (`line_apply` with `RUST`) rewrites only the Rust entry's `version` and digest, plus the `native-rust` inventory's `committed`, `resolved_at` and `source`. It refuses a plan that is not a bump, a Go plan, an image that is not `rust:1-bookworm`, a partial release, and an entry not in the one-line shape.
- Cross-check: the `version` it writes is the release `rust-release` read from `RUST_VERSION` on both platform configs of the candidate digest. The smoke then checks that `rustc --version` reports it on both architectures.
- The guard is `TestNativeRustLineIsItsImageTag`, in `nativeversion_test.go` beside Go's twin rather than in `native_test.go`.
- A simulated 1.100.0 → 1.101.0 bump of the real tree changed exactly those two values in `native.go` and the `native-rust` entry. It passed the inventory validation, `scripts/image-pin-validate.sh` (205 references) and `go test ./internal/build/...`.
- The simulation found that the apply re-encoded every other entry's non-ASCII (`…`, `—`) as `\u` escapes. Go's `go-apply` had the same latent bug. The inventory is now written with `ensure_ascii=False`, and both test fixtures carry non-ASCII text with a byte-level check.
