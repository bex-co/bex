## Objective

Prove a candidate image builds a crate that needs its release, offline, on both architectures.

## Context

- `scripts/go-line-smoke.sh` mounts the source read-only; cargo writes `Cargo.lock` into the source directory, so copy the crate to a writable directory (or ship a lockfile).

## Steps

1. `scripts/rust-line-smoke.sh <image> <release>`: network off, check `rustc --version`, `rustup show active-toolchain`, `cargo build --offline` of a crate with `rust-version = "<release>"`.
2. A `rust-version` newer than the image must fail.

## Files

- `scripts/rust-line-smoke.sh`
- `scripts/rust-line-smoke.test.sh`

## Acceptance criteria

- [ ] The smoke passes on the pinned image for 1.100.0 and fails for 1.100.9.

## Done — 2026-11-26

- `scripts/rust-line-smoke.sh` checks three things with the network off: `rustc --version` is the release, `rustup show active-toolchain` is `<release>-<triple> (default)`, and `cargo build --offline` of a crate declaring `rust-version = "<release>"` succeeds. The source is mounted read-only and copied inside the container, because cargo writes `Cargo.lock` and `target/` beside the manifest.
- On the pinned image (linux/arm64, local Docker) the smoke passes for 1.100.0. It fails for 1.100.9 with cargo's `rustc 1.100.0 is not supported by the following package: smoke@0.1.0 requires rustc 1.100.9`. The linux/amd64 image reports `1.100.0-x86_64-unknown-linux-gnu (default)`.
- `scripts/rust-line-smoke.test.sh` (fake docker) covers: a pass, the run being offline on the host platform with the source read-only, a newer crate, another release, a toolchain that is not rustup's default, another architecture's triple, a regex-wildcard release, a failed pull, and the refused arguments.
