# Account Settings ▸ Appearance: Render's Log Explorer Theme and High Contrast Mode, and a theme kept on the account

Why: Render lets a reader give the log explorer its own theme and turn on high contrast, and its theme follows the account to every browser; bex's Appearance (w3/m528) has Dashboard Theme only, kept in one browser.

Read from Render's dashboard bundle by w3/m528 (2026-11-20, `UserSettings-3jrn6Tc2.js`): Appearance holds **Dashboard Theme** (System, Light, Dark, the default marked `(Default)`; saved with `updateUserThemeSetting`), **Log Explorer Theme** (`Match Dashboard (Default)`, `Light`, `Dark`; `updateUserLogThemeSetting`, read by the explorer as `effectiveLogViewerTheme`) and **High Contrast Mode** (_"Increase the visibility of interactive elements."_, a switch that swaps the theme for its high-contrast twin, disabled where the theme has none).

bex today: `AppearanceCard` (`dashboard/src/features/auth/pages/settings-page/appearance-card.tsx`) drives the browser-local `useTheme` state the account menu drives (`common/providers/theme-provider`, `localStorage`). There is no user settings store for the theme in bex-api, and the stylesheet has no high-contrast token set.

Done when the theme is stored on the account (REST, GraphQL and the dashboard; a new browser opens in it), Appearance offers Log Explorer Theme and every log explorer follows it, and High Contrast Mode switches to high-contrast tokens that pass `theme-contrast.test.ts` at a stricter ratio; or, for any of the three Render keeps and bex does not build, ADR018 records the divergence with the user's sign-off. Likely more than an hour: promote it when it is picked up.
