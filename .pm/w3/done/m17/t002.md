## Objective

Flip the gate on real status: the `DatastoreMetrics` verb requests `replication_lag` from the source when the target Database's `status.highAvailabilityEnabled` is true, and omits the metric (as today — not a fabricated zero) when HA is off. A source outage maps to `core.ErrMetricsUnavailable`, consistent with the other datastore metrics.

## Context

- `lego/backend/internal/metrics/datastore.go` — the `MetricReplicationLag` branch that currently never calls the source; the status field is `Database.status.highAvailabilityEnabled`.
- Preserve the honest-omission contract (m10's design): non-HA ⇒ the metric simply isn't in the response.
