## Objective

Build the async delivery worker that takes internal domain events, looks up subscribed `webhook_endpoints`, and POSTs a signed, thin JSON payload to each — with retries on failure and auto-disable after repeated failure, matching Render's documented delivery semantics.

## Context

- Verified live from render.com/docs/webhooks (2026-07-12): payload `{type, timestamp, data: {id, serviceId, serviceName, status?}}`; headers `webhook-id` (= `data.id`), `webhook-timestamp` (unix epoch seconds), `webhook-signature` (HMAC-SHA256 over `id.timestamp.body.secret`); endpoints must respond 2xx within 15s; up to 8 retries with exponential backoff (final ~33h later); after 3 consecutive failures, notify by email; after all retries fail, disable the endpoint until manually re-enabled.
- bex has no billing/plan system (`w6` non-goal) — do not gate delivery or endpoint-count on a plan tier the way Render does (Pro=1 destination, Scale=100); allow multiple endpoints per workspace unconditionally. Note this as a deliberate divergence.
- Reuse the existing SMTP courier (`w4/m7`, `BEX_SMTP_ADDR`/`BEX_SMTP_FROM`) for the failure-notice email — same relay pattern as workspace-invite email.

## Steps

1. Implement a delivery queue (in-process worker pool is sufficient — no new message-broker dependency needed at this scale).
2. Implement HMAC-SHA256 signing per the Standard Webhooks scheme above.
3. Implement the HTTP POST with 15s timeout, 2xx-required success.
4. Implement bounded exponential backoff across up to 8 attempts, recording each attempt in `webhook_deliveries`.
5. On the 3rd consecutive failure, send the SMTP failure-notice email; on final failed retry, set `enabled=false` on the endpoint with a disabled reason.

## Files

- `lego/backend/internal/webhooks/` (delivery worker, signing)

## Acceptance criteria

- [ ] A successful delivery is recorded with status code + timestamp.
- [ ] A failing endpoint retries per the documented backoff schedule and each attempt is recorded.
- [ ] After exhausting retries the endpoint is disabled and an email is sent (skip email delivery gracefully — not an error — when SMTP env vars are unset, matching `w4/m7`'s pattern).
- [ ] Signature can be independently verified: `HMAC-SHA256(id + "." + timestamp + "." + body, secret)` matches `webhook-signature`.

## Out of scope

- Distributed delivery-worker scaling across replicas (single-replica caveat noted, like `w7/m3`'s rate limiter) — a follow-up if it matters.
