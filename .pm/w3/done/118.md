# Leaving an edited settings row asks Render's Discard unsaved changes? first

Why: Render asks before a navigation throws away an unsaved edit; bex drops it without a word, so a theme picked but not saved, or a half-typed service setting, is simply gone.

Read from Render's dashboard bundle on 2026-11-25 by w3/097 ([account-appearance.md](../../docs/render-artifacts/account-appearance.md) § Appearance, in order; `RowInput-vO6wbvrA.js`, `useUnsavedChangesWarning-DVhBkOwh.js`, whose provider `index-BPMVVQol.js` mounts at the app's root): every `RowInput` registers itself while it is open with a change not yet saved and not saving. While one is registered, a client navigation to another path is held by a small modal **Discard unsaved changes?**, reading _"You've edited **the {label} field** but haven't saved your changes. If you leave now, your changes will be lost."_ (two rows: "the A and B fields"; more: "the A, B, and C fields"), with **Keep editing** (closes it and focuses the first edited field) and a critical **Discard** (goes on). A reload or a closed tab gets the browser's own `beforeunload` prompt. A navigation that keeps the path is not held.

bex today: Appearance's theme rows (`dashboard/src/features/auth/pages/settings-page/appearance-card.tsx`, w3/097) put the saved theme back when the page is left mid-edit, without asking; `EditableFieldRow` (`dashboard/src/features/services/components/editable-field-row.tsx`) drops its draft the same way on every service, static site, Postgres and Key Value settings page.

Done when an open row with a changed, unsaved value on those pages holds a navigation to another path with the modal in Render's words (all eight languages, the field list joined as Render joins it), Keep editing returns to the field, Discard leaves (Appearance then puts the saved theme back), a reload asks through `beforeunload`, a saving row does not ask, and a test pins each.
