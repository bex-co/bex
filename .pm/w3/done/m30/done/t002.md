## Objective

Extend the log-shipper so tenant Valkey (KeyValue) pods' logs land in Loki under immutable keyvalue-identity labels, mirroring the operator-marked CNPG stream pattern m28 shipped for Postgres.

## Context

- `deploy/gitops/base/log-shipper.yaml` — m28 added the CNPG `postgres` stream selection under immutable database labels; the Valkey StatefulSet pods (docs/ADR021-keyvalue-management.md) need the analogous selection.
- The operator stamps identity labels on Valkey workloads (`lego/operator/internal/controller/keyvalue_controller.go`); reuse whatever marker exists, or add one the same way m28's operator-marked CNPG selection works.
- `scripts/gitops-validate.sh` gained log-shipper regression guards in w3/m13/m28 — extend, don't bypass.

## Steps

1. Identify the stable label set on tenant Valkey pods; add an operator-stamped marker if none is immutable.
2. Add the Alloy discovery/relabel stage for keyvalue streams, scoped like the CNPG one (node-scoped, no duplication).
3. Extend `scripts/gitops-validate.sh` with the same class of guard m28 added.

## Files

- `deploy/gitops/base/log-shipper.yaml`
- `lego/operator/internal/controller/keyvalue_controller.go` (only if a marker label is needed)

- [ ] A Valkey pod's stdout lines appear in Loki labeled with the store's stable identity (not the pod name alone).
