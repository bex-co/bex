## Objective

Implement the second half: the endpoint the token from t002 unlocks, which verifies the token, re-resolves the sandbox (workspace-key scoped), and bridges stdout/stderr from `Client.Exec` (t001) to the client as the CLI's `ExecSandboxStream` expects (SSE / chunked).

## Context

- The CLI opens the `{method, uri}` from t002 carrying `token`, and reads a stream. Match its framing exactly (inspect `pkg/sandbox/repo.go ExecSandboxStream` in `render-oss/cli`).
- Verify the HMAC token (t002): expiry, single-use (nonce store, cf. `shell_ticket_nonces` migration 0049), sandbox+workspace binding — re-run authorization, do not trust the token alone for targeting.
- Reuse the gateway-style transport if it fits (the ssh-gateway Web Shell WebSocket is the closest precedent); a plain-HTTP listener Traefik terminates TLS onto mirrors `BEX_SHELL_WS_ADDR`.

## Steps

1. Add the stream handler (its own listener or a bex-api route, per the t002 `uri` decision); verify token + re-authorize.
2. Call `Client.Exec` and copy execd stdout/stderr onto the response stream; propagate exit status.
3. Bound the session (timeout, max concurrent) like the shell gateway.

## Files

- `lego/backend/internal/sandbox/*` (+ possibly a small stream handler in `internal/api` or the ssh-gateway if the transport is shared)

## Acceptance criteria

- [ ] With a valid token, the endpoint streams a command's stdout/stderr and closes with its exit status.
- [ ] Expired/replayed/mis-bound token → rejected; targeting is re-authorized, never token-only.

## Out of scope

- MCP exec (t004).

## Done

Gateway internal SSE endpoint (`/sandbox-exec`, :8081): verify the signed ticket → run the argv via one `pods/exec` → emit the CLI's exact SSE (`event: output {stream,data}` / `event: exit {exitCode}`), single-use nonce + session caps. bex-api `StreamExec` authorizes can_operate, mints the ticket, and reverse-proxies the SSE. Validated on prod.
