## Objective

Add a background reclaimer, symmetric to `WorkspaceCreationCleaner`, that cancels the cardless Subscription and deletes the Customer for workspaces whose checkout was started but never bound, past a horizon.

## Context

- Candidate rows: `billing_provider_mappings` with `payment_method_bound_at IS NULL`, `checkout_started_at < now() - horizon`, `tenants.billing_comped = false`.
- Must never touch: bound, comped, any Customer with a non-zero invoice, or deleted-workspace retained Customers (`deletedAtMetadataKey`).
- Pattern: `ExpireWorkspaceCreationAttempts` claim + `FinishWorkspaceCreationCleanup` (`lego/backend/internal/store/workspace_creation.go:262-330`), 15-minute interval, bounded batch, `SKIP LOCKED`.
- The `StripeClient` process cache (`lookupCustomer`) and the mapping row must be dropped so a later Checkout re-mints cleanly.

## Steps

1. Store: claim query + finish method + migration if a claim column is needed.
2. Billing: `CleanupAbandonedCheckout` (cancel sub → delete Customer → drop mapping + cache).
3. Wire in `lego/backend/cmd/api/main.go` next to the workspace-create cleaner; metric `abandoned_checkout_cleanup`.

## Files

- `lego/backend/internal/store/billing.go`, new migration under `lego/backend/internal/store/migrations/`
- `lego/backend/internal/billing/` (new cleaner)
- `lego/backend/cmd/api/main.go`

## Acceptance criteria

- [ ] Real-Postgres test: only eligible rows are claimed; bound/comped rows are never selected.
- [ ] Re-opening Checkout after reclaim works and binds.
- [ ] A Stripe error leaves the row retryable, not lost.

## Out of scope

- Historical backfill (t006).
