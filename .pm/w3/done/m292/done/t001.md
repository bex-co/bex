## Objective

Make a Blueprint auto-sync (no user identity) apply a render.yaml change that creates in, or moves into or out of, a protected environment, as Render does, instead of refusing it until an Admin syncs manually.

## Context

- Render (render.com/docs/projects, checked 2026-11-08): "If your protected environment includes resources that are managed via Blueprints, non-Admin workspace members _can_ still modify those resources by publishing an update to the corresponding `render.yaml` file." Render runs the push-triggered sync as the Blueprint, with no per-member role check.
- Today: `blueprintProtectedPlacementProblems` / `requireBlueprintPlacement` (`lego/backend/internal/apps/blueprint_protected_placement.go`) and `loadExitGuard` (`internal/environments/service.go`) refuse an identity-less auto-sync (w3/m281, ADR032 § Creating and moving resources).
- A manual sync by a Member through REST/GraphQL/MCP stays gated (it is a direct member action, m281).

## Steps

1. Identify how the auto-sync worker's context is distinguished from a member's call (it carries no identity) and treat a Blueprint-initiated sync as the Blueprint's own action for placement and exit checks.
2. Keep manual member syncs and every non-Blueprint placement path gated.
3. Record the decision in ADR032 with the Render quote.

## Files

- lego/backend/internal/apps/blueprint_protected_placement.go
- lego/backend/internal/apps/deploy.go (auto-sync path)
- lego/backend/internal/environments/service.go (loadExitGuard)
- docs/ADR032-environments.md

## Acceptance criteria

- [x] An auto-sync whose render.yaml adds a service to a protected environment creates it, and one that moves a resource out applies
- [x] A Member's manual sync with the same manifest still gets 403 `PROTECTED_ENVIRONMENT_ADMIN_REQUIRED`
- [x] ADR032 records the rule with Render's wording

## Out of scope

- Re-deciding the m281 Admin-only rules for manual (identity-bearing) API, GraphQL, MCP and dashboard placement

## Result (2026-11-08, loopx w3)

`core.WithBlueprintSync` marks the auto-sync worker's and the push webhook's sync contexts (both built from the stored Blueprint row's tenant); `core.BlueprintSync` counts it only without an Identity. The Blueprint whole-manifest check, `createResolver.RequirePlacement` and `loadExitGuard`'s protected branch admit it, so a pushed render.yaml that creates in, or moves into or out of, a protected environment applies, as Render documents. A member's manual sync stays gated. Tests: `TestABlueprintSyncPlacesInAProtectedEnvironment` (marked sync admitted at create and exit; a member's marked call refused) and the member-marked leg of `TestBlueprintPlacementIntoAProtectedEnvironmentNeedsAnAdminPG`. ADR032 records the rule with Render's quote. Non-protected isolated/allow-listed exits keep their guard for every caller.
