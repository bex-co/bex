# Buttons, links and tabs draw their focus indicator off the control's edge, as Render's do

Why: bex's 2 px focus ring sits flush against the control, so on a filled primary or destructive button it touches a fill of its own colour and reads as the button growing 2 px; Render leaves a gap of the page between the control and its outline.

- **Render** (2026-11-25, w3/m642 t003): every indicator on `dashboard.render.com/login-next` is a 2 px solid outline in `--outline-focus-action` (`#0088e5` light, `#8ad6ff` dark) at full strength. Text fields draw it flush (`outline-offset: 0`, outside the 1 px border); the Sign in button, the provider buttons and the links draw it 2 px off the control (`outline-offset: 2px`); the show-password icon button draws it inset (`-2px`). The `Tabs` chunk (`Tabs-BccqB0tj.js`) uses `outline-2 outline-offset-2` and `outline-offset-1`; list rows use `-outline-offset-2`.
- **bex** (after w3/m642): the shared controls draw `focus-visible:ring-2 focus-visible:ring-ring` (a box-shadow, flush), the bordered ones with the border swapped to the ring colour. `bg-primary` and `--ring` are the same green in both themes, so the default button's ring and fill meet with no edge between them (`dashboard/src/common/components/ui/button.tsx`, `badge.tsx`; the Update Source dialog's Deploy button, `service-source-card.tsx`, did the same before w3/m642).
- **A way in.** Draw the buttons', links' and tabs' indicator as an outline with a 2 px offset (`focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring`) instead of the ring; keep the fields' flush ring and the rows' inset ring. An offset outline reaches 4 px past the control, so check it is not clipped where a control sits at the edge of an `overflow` container (the dialog bodies, the repository list, card headers).
- **Done when**: in a real browser, in light, dark and both high-contrast twins, a focused default, destructive, outline and ghost button, a link and a tab show a gap of the surface between the control and its indicator, the indicator still measures 3:1 (4.5:1 in the twins) against that surface, and none is clipped on the pages w3/m642 swept; `theme-contrast.test.ts` keeps reading the indicator's strength (it reads `outline-ring` already).
- **Done 2026-11-25.** The shared Button (every variant), a Badge that is a link, and the stylesheet's rule for every other link and button draw a solid 2 px outline in `--ring` 2 px off the control (`focus-visible:outline-2 focus-visible:outline-offset-2`); the destructive button, badge and confirm draw it in `--destructive`. The shared tabs and the resource detail pages' tabs (`DetailTabNav`) draw it 1 px off, as Render's `Tabs` chunk does, which keeps a pill tab's outline inside its list's 3 px padding; the tab panel, a tab stop that drew nothing (`outline-none`), draws it 2 px off. The sign-in pages' Sign in, provider and "More options" buttons and their links draw the same in an unlayered rule (Ory's sheet sits in a later layer), and the show-password button draws it inset (`-2px`), as Render's does. The span that takes focus for a disabled button (`PermissionTooltip`) draws the button's outline. Fields keep their flush ring and list rows their inset ring. Links and buttons get `scroll-margin: 0.5rem`, so Tab no longer scrolls a control to its scroll container's edge with the outline cut off on that side (at 390 wide on Settings, two Edit buttons lost 4 px at the bottom without it).
- **Measured** in headless Chromium 1440×900, the tree's dashboard (`vite dev`) against `yarn local-bex` (web service `eden-cms-v2`, Key Value `sessions-cache`), the sign-in form served a Kratos login flow through intercepted requests, transitions off, by Tab through the w3/m642 pages plus Automations (pill tabs) and a Key Value page (detail tabs), in all four themes.
