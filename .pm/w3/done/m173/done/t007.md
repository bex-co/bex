## Objective

Prove on the live repository that the gates hold in both directions: a non-main branch cannot read a production credential, and every production workflow on `main` still works.

## Context

- Pushing a throwaway branch with a probe workflow is outward-facing; it is covered by t005's recorded authorization (confirm it is).
- The probe prints only a boolean, never a value.

## Steps

1. Push a throwaway branch carrying a `workflow_dispatch` probe that runs under `production-deploy` (and one under no environment) and prints `${{ secrets.BAO_ROOT_TOKEN != '' }}` for a few production-class secrets; dispatch both.
2. Expect: the environment job is refused by the branch policy; the no-environment job prints `false`. Record run ids; delete the branch.
3. On `main`, record green run ids for `deploy.yml`, `deploy-canary.yml`, `ssh-edge-liveness.yml`, `isolation-matrix.yml` and one restore drill after the move.
4. Run the t004 drift workflow once; confirm no tracking issue opens.
