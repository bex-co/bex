## Objective

Write what Render's cron header and its two actions do into the capture, marking which facts the walk saw and which only the bundle shows.

## Context

- Evidence: a signed-in, read-only walk of four cron jobs in a Render workspace on 2026-11-21 (nothing that acts was clicked), plus Render's public dashboard bundle read the same day without sign-in (`CronJob-D3WeWa8V.js` sha256 `23d3ad7d7c97…`, `index-BR2q8yex.js` `f19b12ced9c1…`, `urls-B5ihPFNO.js` `3ab9b8053a93…`, `helpers-C_tFPHBn.js` `302444d539f3…`; the hashes change with every Render deploy, so find the chunks by name, as `metrics-page.md` § Status-code label describes).
- Seen on the walk: a running cron job's header has one action, **Trigger Run**, and no Connect or Manual Deploy menu. A suspended one's header has no action; a "Manually suspended · You are not billed for suspended services. · Resume service" notice sits under the facts. The facts line reads "Runs `<command>` at 09:00 AM UTC" (or "every minute") and then "Last successful run <date>". The Deploys page has **Manual Build** beside a "Search deploys and commits" field.
- Bundle only (`CronJob-*.js` `ja`, `Ma`; `index-*.js` `Ohe`): Trigger Run calls `runCronJob` at once, with no confirm, then opens `logs?r=live` (or Events when no run came back). It is disabled while the cron job is suspended ("Resume this cron job to trigger a run.", seen on the walk), when a repo-backed cron job has no successful build ("No successful build detected. View Deploys.") and without permission. Failures toast "You don't have permission to run this cron job." or "Couldn't trigger a run. Try again in a moment." and stay until dismissed. Manual Build is hidden for an image-backed cron job, disabled without permission or when pipeline minutes are exhausted, and opens the new build on success.
- Render's docs say a manual trigger during an active run cancels it first; they show no confirm.
