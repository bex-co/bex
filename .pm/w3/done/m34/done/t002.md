## Objective

Remove the `BEX_TENANT_NAMESPACES` and `BEX_TENANT_SANDBOX_NAMESPACES` env gates and delete every shared-namespace code branch they guard, so per-tenant `<ws>` namespaces become the unconditional model (App CRs, pods, pod-mounted Secrets, cron Jobs, billing enforcement all resolve into `<ws>`).

## Context

- The gate is read in `cmd/api/main.go` (base wiring ~`:149`; projector/namespace-reconciler ~`:617-627`).
- Shared-namespace fallbacks added by the w3/m32 hotfix (commit `e2d6fbb4`) collapse to no-ops once the flag is always on:
  - `core.Base`: the `TenantNamespaces` field + `AppNamespace(tenantID)`, `AppListScope()`, `AppNamespaceByName()` shared-mode branches (`internal/core/base.go`) — `AppNamespace` becomes just the workspace id; `AppListScope` becomes always cluster-wide.
  - `store.Reconciler.TenantNamespaces` shared-ns projection path (`internal/store/reconciler.go:173-176,233-234`).
  - `NamespaceReconciler` — always constructed/run.
  - `billing.KubernetesEnforcer.TenantNamespaces` field + `appNamespace()` (`internal/billing/enforcement.go`).
  - `jobs`/`secrets`/`envgroups`/`metrics`/`usage`/`deploys`/`apps` call sites that go through `AppNamespace`/`AppListScope` simplify but keep behavior.
- Keep `BEX_API_NAMESPACE`/`BEX_CP_APPS_NAMESPACE` — still meaningful as the platform/base namespace and for Databases/KeyValues (which stay there).

## Steps

1. Delete the env reads and the `TenantNamespaces` fields; make the per-tenant-namespace path unconditional.
2. Simplify `core.Base` helpers: `AppNamespace(tenantID)` → return the workspace namespace; `AppListScope()` → always cluster-wide; keep `AppNamespaceByName` (still used, now always resolving).
3. Confirm Databases/KeyValues/Secrets that legitimately stay in `BEX_API_NAMESPACE` are untouched.
4. `go build ./... && go test ./...`; `make lint` from `lego/operator`.
