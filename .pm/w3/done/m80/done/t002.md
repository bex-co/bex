## Objective

No auth failure may ever render as a network/outage error again. Every load-error surface must distinguish "your session expired" (recoverable via sign-in) from "bex-api is unreachable/5xx" (recoverable via retry). Where the t001 redirect doesn't fire (SSR loaders, edge cases), show an explicit "Your session has expired" card with a **Sign in** button carrying `next=` — never "The request to bex-api failed" with a dead-end "Try again".

## Context

- Service detail card + the comment that lumps auth with outages: `dashboard/src/features/services/components/service-detail-layout.tsx:56-87`; strings `services.detailErrorTitle`/`detailErrorBody` at `dashboard/src/features/services/locales/en.ts:339-344`, list variants at `:331-337`.
- Generic surface: `dashboard/src/common/components/resource-load-error.tsx` (`common.errorTitle`/`common.resourceErrorBody`).
- The deciding predicate never inspects status: `dashboard/src/common/hooks/use-not-found-redirect.ts:35-41` (`resourceFailed` = "error present AND not not-found").
- SSR loaders collapse everything to `{state:"error"}`: `dashboard/src/common/lib/document-head/index.ts:106-121` (`loadRouteResource`); `dashboard/src/common/hooks/use-loader-error-retry.ts:37-60` re-runs the loader once, which cannot heal a 401.
- t001 provides the 401 classification on both clients.

## Steps

1. Thread the t001 auth classification into `resourceFailed` / `loadRouteResource` so consumers get a three-way state: ok / not-found / error{auth|network}.
2. Add a session-expired variant to the error surfaces (detail layout, list, `ResourceLoadError`): title "Your session has expired", body inviting sign-in, primary action **Sign in** → login URL with `next=` (reuse t001's builder). Add locale strings; remove none of the existing network copy.
3. `useLoaderErrorRetry` must not blind-retry an auth-shaped error — surface the sign-in card instead.
4. Verify the pending-skeleton rule: the expired-session card must keep the same outer geometry as the existing error card at desktop and narrow-mobile widths (repo rule: skeletons/states match ready-state geometry).
