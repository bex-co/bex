## Objective

Make the unavoidable re-auth round-trip lossless (WCAG 2.2.5 / W3C G105): unsaved work must survive redirect → sign-in → return. Highest-stakes surface: the service Environment editor — losing a half-edited env group to a login redirect is exactly the documented F12 anti-pattern. Persist a local draft keyed by route, restore it after the user returns via `next=`, and clear it on successful save or explicit discard.

## Context

- t001/t002 establish the redirect-with-`next` flow this task rides; the user always returns to the same URL.
- Environment editor lives under `dashboard/src/features/services/` (Environment tab); identify the concrete form component(s) during implementation and record them in the PR.
- Drafts belong in `sessionStorage` (per-tab, auto-cleared on tab close, never sent to the server) keyed by `pathname` + resource id — no server-side draft store, no new API surface.
- Repo rule: never store tokens in browser storage — drafts are user-typed form values only; env-var **values** the user typed are theirs to keep locally for the round-trip, but do not persist values fetched from the API.

## Steps

1. Build a small `useReauthDraft(key)` helper (save-on-change debounced, restore-on-mount if a draft exists and is younger than a short TTL, clear on successful mutation).
2. Wire it into the env-var editor: dirty state snapshots to the draft; on return from sign-in the editor rehydrates and marks itself dirty; a restored draft is visibly indicated (e.g. "Restored unsaved changes") with a discard affordance.
3. Snapshot eagerly enough that the t001 redirect (which the editor cannot intercept) never races the save — persist on change, not on unload.
4. Sweep for other high-loss forms (service create, scaling, notification settings) and apply the helper only where a redirect genuinely destroys meaningful input; list what was considered and skipped in the PR description.

## Files

- `dashboard/src/common/hooks/` (new `useReauthDraft`)
- `dashboard/src/features/services/` (Environment tab editor components)
- locale files for the restored-draft notice

## Acceptance criteria

- [ ] Type unsaved env-var edits → expire the session server-side → trigger any request → sign in → land back on the Environment tab with the edits restored and marked unsaved.
- [ ] Saving or discarding clears the draft; a fresh visit shows no stale restore.
- [ ] No fetched-from-API secret values are written to storage — only user-typed dirty fields.

## Out of scope

- In-context re-auth modal (redirect flow is acceptable once expiry is rare); server-side draft persistence; autosave-as-you-type to the real API.
