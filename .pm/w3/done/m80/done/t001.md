## Objective

Give the dashboard one central place that reacts to an HTTP 401 from bex-api on an already-mounted page. Today neither Apollo client has an error link (`retryLink → HttpLink` only), the retry link deliberately skips 401, and the only redirect-to-login path lives in route `beforeLoad` — so mid-session expiry surfaces as a generic load error. On 401: invalidate the client session memo, re-check the session, and if it is gone redirect to `/auth/login` with `next=` the current href (carrying `aal=aal2` when a step-up is owed), reusing the exact redirect shape `requireAuth` already builds.

## Context

- Client link chain: `dashboard/src/common/apollo/factory.client.ts:14-28` — no `onError`/error link anywhere.
- SSR link chain: `dashboard/src/common/apollo/factory.server.ts:77-94` — classify only, never redirect from the link (route loaders own SSR redirects).
- Retry link intentionally excludes 401 (only 5xx/429 reads): `dashboard/src/common/apollo/retry-link.ts:21-34` — keep that behavior; a 401 is not retryable without re-auth.
- Existing redirect builder with `next` + `aal2`: `dashboard/src/common/lib/auth/auth.ts:40-59` (`requireAuth`).
- Session memo to invalidate: `SESSION_CACHE_TTL_MS = 60_000` + `invalidateSessionCache` in `dashboard/src/common/server-fn/session.ts:45-91`.
- bex-api expiry signal is a plain HTTP 401 (`{"error":"unauthorized"}`, `WWW-Authenticate: Bearer`) from the auth gate — there is no GraphQL `UNAUTHENTICATED` extension (`lego/backend/internal/api/auth.go:363-366`, `core/http.go:318-320`).

## Steps

1. Add an error link (new file under `dashboard/src/common/apollo/`) that detects `networkError` with HTTP status 401.
2. On 401 (client only): call `invalidateSessionCache()`, re-run `fetchSession()`; if the session is genuinely gone, navigate to the login redirect built the same way `requireAuth` does (`next=` current `pathname+search`, `aal=aal2` when owed).
3. Loop guards: never redirect when already under `/auth/*`; do not re-enter if a redirect is already in flight; a 503 ("auth upstream unavailable") is NOT a 401 — leave it to the network-error path.
4. Wire the link into `factory.client.ts`; in `factory.server.ts` only tag the error as auth-shaped (t002 consumes the classification in loaders).

## Acceptance criteria

- [ ] With a mounted service page and the session revoked server-side, the next Apollo operation redirects to `/auth/login?next=<that page>` instead of rendering an error card.
- [ ] After sign-in the user lands back on the original URL.
- [ ] A bex-api 5xx/network failure still renders the existing retry card (no redirect).
- [ ] No redirect loop when the login page itself performs Apollo operations.
