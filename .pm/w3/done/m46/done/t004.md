## Objective

bex's static-server serves the site root `index.html` for any extension-less miss by default (`spaFallback`), so every static site behaves as an SPA and unmatched paths return `200`. Render defaults to `404` for unmatched paths unless a rewrite / `404.html` is configured. This divergence is currently undocumented. Make it a deliberate, recorded decision: keep-by-design, match Render's default-404, or make it configurable.

## Context

- Verified live 2026-08-21: with **no** routes configured, `GET /nope` returned the exact `index.html` (`200`, byte-identical), not a 404.
- The behavior is intentional in code: `lego/operator/internal/staticserver/staticserver.go:264` — "`spaFallback` fetches the site's root index.html for extension-less misses so a …"; applied around `staticserver.go:196` (`obj, servedPath = fallback, "/index.html"`).
- Render parity ledger: `docs/ADR018-render-parity.md`; static-site behavior doc: `docs/ADR029-static-sites.md`.

## Steps

1. Decide the disposition (record it): (a) keep the SPA-by-default fallback as a deliberate bex divergence, (b) match Render's default-404 for extension-less misses when no route matches, or (c) gate it (e.g. honor a `404.html` / opt-in flag).
2. If a behavior change is chosen, implement it in `staticserver.go` (and any needed CRD/API field); otherwise leave serving unchanged.
3. Document the decision + observed behavior in `docs/ADR029-static-sites.md` and the ADR018 ledger so it is no longer undocumented drift.
