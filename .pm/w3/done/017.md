# dev-N control planes mutually prune each other's tenant namespaces on the shared cluster

Found by w3/m78's live leg (2026-08-08). ADR043's `NamespaceReconciler` (any bex-api with `BEX_CP_DB_URI`) deletes every managed `tea-*` namespace whose workspace is absent from **its own** database (`pruneOrphans`). Two dev-N harnesses (each with its own bex-db) sharing the CAPD mock cluster therefore delete each other's tenant namespaces within one 60s resync — observed live: the dev-5 session's bex-api pruned this session's freshly provisioned `tea-…` namespace (Terminating within 60s of creation), and symmetrically. The `.pm/wN/dev-N` isolation design predates the ADR043 pruner and is silently broken by it.

Candidate fixes (choose one):

- Stamp managed namespaces with a **control-plane instance identity label** (e.g. `bex.co/control-plane: dev-3`, from a new env var defaulting to `production`) and prune only namespaces carrying one's own identity.
- Or scope the dev-N harness: a `BEX_CP_NAMESPACE_PRUNE=0` dev knob that disables pruning (provisioning stays on), documented in the dev-N READMEs.

Until fixed, at most **one** dev-N control plane may run against the shared cluster at a time; note this in `.pm/*/dev-*/README.md` when touched next.
