# Disk, maintenance-mode and auto-deploy events carry the details Render requires

Why: Render requires `diskId`/`sizeGB` on disk events, `enabled` on maintenance mode, and a `reason` on auto-deploy disable, but bex's audit rows never record them, so those events answer without them (w3/m302).

- **Evidence:** `TestRenderEventDetailsMatchTheirMember` (`lego/backend/internal/events/render_member_test.go`) pins these as missing. `apps.AddDisk`/`UpdateDisk`/`DeleteDisk` audit through `RecordAppConfigChanged` with no disk id or size (`lego/backend/internal/apps/disks.go:136`). `apps.SetMaintenanceMode` records no on/off. `RecordAutoDeployChanged(…, false)` is written the same way for a settings change and a dashboard rollback (`internal/apps/service.go:5162`, `internal/deploys/service.go:1207`), so the reason (`setting_change` / `rollback`) cannot be told apart.
- **Render:** pinned `/events/{eventId}` members "Disk Created" `{diskId, sizeGB}`, "Disk Updated" `{diskId, fromSizeGB, toSizeGB}`, "Disk Deleted" `{diskId}`, "Maintenance Mode Enabled" `{enabled}`, "Maintenance Mode URI Updated" `{fromURI, toURI}`, "Auto Deploy Disabled" `{reason}`.
- **Fix:** record the values on the audit row at write time (`core.AuditEvent` already has `DiskID` and `DiskSizeGB`; a disk resize also needs the from-size, maintenance the boolean and URIs, auto-deploy the disable reason), project them in `events.view` / `toRenderEvent`, and drop the matching `missing` entries and `rendertest.Allowlist` lines (lower `allowlistSize`). Rows written before stay as they are; omit, never invent.
- **Size:** likely more than an hour once the migration for the new audit columns is counted; promote to a milestone if so.
- Source: w3/m302 (2026-11-10), found while matching every event type to its Render member.
