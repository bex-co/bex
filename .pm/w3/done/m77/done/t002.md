## Objective

Make the bex-api background Completer trigger the gateway record endpoint (t001) for a finished session **immediately before it tears the sandbox down**, so the transcript is persisted while the driver's hub is still alive. Best-effort and logged — a record failure must never strand a session in `running`.

## Context

- The Completer already reads the driver status file over the gateway sandbox-exec boundary and owns teardown: `lego/backend/internal/agentsessions/completion.go` — `complete()` (teardown at ~181/220), `fail()` (teardown at ~229), `teardown()` → `SandboxLifecycle.CancelAgentSessionSandbox`. It runs under the trusted system subject `system:agent-session-completer` with no tenant authz.
- The boundary seam it uses: `SandboxLifecycle` interface in `internal/agentsessions/service.go` (`ReadSessionStatus`), implemented by `internal/sandbox/service.go` `AgentSessionLifecycle` via `mintAndDial` (`internal/sandbox/exec.go`). Add a sibling `RecordTranscript(ctx, workspaceID, sessionID, sandboxID)` that mints the record HMAC and dials the t001 endpoint — bex-api still never holds `pods/exec`.

## Steps

1. Add `RecordTranscript(...)` to the `SandboxLifecycle` interface (`service.go`) and implement it on `AgentSessionLifecycle` (`internal/sandbox/service.go` + `exec.go`): resolve/verify the session sandbox, mint the record ticket (HMAC over `BEX_SANDBOX_EXEC_SECRET`, binding pod/ns/session), and POST the gateway record endpoint.
2. In `completion.go` `complete()` and `fail()`, call `RecordTranscript` **before** `c.teardown(record)`; on error, log and proceed to teardown/finalize anyway (honest degradation — empty transcript, never a hang).
3. Skip when the sandbox is already lost (`ErrNotFound` path) — no reachable driver; the empty transcript is the documented limitation.
4. Update the fake in `internal/agentsessions/service_test.go` (`fakeLifecycle`).

## Acceptance criteria

- [ ] `complete()` and `fail()` invoke `RecordTranscript` before `teardown`.
- [ ] A `RecordTranscript` error is logged and does not prevent finalize/teardown (session never stranded in `running`).
- [ ] bex-api uses the HMAC seam only — no new `pods/exec` grant.
