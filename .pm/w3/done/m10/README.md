## What shipped

- **Two verbs, not one bent out of shape.** `cpu_target`/`memory_target` reuse the existing App-scoped `Metrics` verb (same shape as `cpu_limit`/`memory_limit`). Disk/connections/replication-lag target a Database or KeyValue CR instead of an App, so they ride a new sibling verb, `DatastoreMetrics` (`internal/metrics/datastore.go`) — REST/GraphQL/MCP each got the small adapter fragment that verb needs, without fragmenting the shared roots.
- **Omit, never fake.** Every new series follows the existing rule (`docs/ADR010-observability.md`'s cpu/mem-percentage precedent): no autoscaling config → `cpu_target`/`memory_target` absent; no PVC limit → nothing invented; and — the one that mattered most — replication-lag stays gated on `Database.status.highAvailabilityEnabled` rather than on Prometheus availability, because CNPG's own lag query returns a real `0` from a lone primary pre-HA, which would have been a textbook fake-zero if surfaced.
- **`core.Base` gained `GetDatabase`/`GetKeyValue`**, promoting a fetch-by-name-plus-cross-workspace-gate pattern that `internal/postgres` and `internal/keyvalue` each already had privately once a third copy (`internal/metrics`) needed it — a `/simplify`-driven cleanup, not a day-one design, but landed before this shipped.
- **One new Prometheus scrape job** (`cnpg-tenant-db`, `deploy/gitops/base/prometheus.yaml`) widens CNPG-exporter coverage from bex's own `bex-db` to every tenant Postgres instance; disk usage needed no new scrape config (kubelet's volume-stats series were already cluster-wide).
