# 078 — A Viewer's project log view says it reads nothing, instead of why it shows no lines

Why: a workspace Viewer has no log access (`can_view_logs` is Contributor and up, `deploy/gitops/authz/model.fga`), so every project Observability view reads an empty scope for them, and the page tells them the project has no services when it has several.

- **Source:** w3/m507's dev-3 walkthrough, 2026-11-19. A Viewer of a Scale workspace opened `Production errors` (`ENVIRONMENT IS production`), whose scope held the web service `storefront` for a Developer. The page read "Nothing to read in this view yet. This view reads the project's services, cron jobs, Postgres databases and Key Value instances, and there are none in it yet." GraphQL `logs(project, filterDocument)` answered `resources: []` for the Viewer and `[storefront]` for the Developer.
- **Cause:** by design the project read probes the workspace's log access quietly and answers an empty page with no audit noise (`resolveProjectView`, `lego/backend/internal/logs/project.go`; ADR010 § Project views), and the dashboard's empty-scope state (`ProjectLogViewer`, `dashboard/src/features/logs/components/project-log-viewer.tsx`) cannot tell that from a project with nothing in it.
- **Done when:** a caller without log access gets a distinct, localized state that names the role limit (as a service's Logs tab does for a refused read), and a project with no readable resource keeps today's copy. Check what Render shows a Viewer on a project view first (render.com/docs/team-members role table) and match it. A test covers both states. ~45m.

**DONE 2026-11-20.** Render's role table (render.com/docs/team-members, re-read 2026-11-20) gives "View service logs" to Admin, Developer and Contributor only, and documents no screen for a Viewer. `ProjectLogViewer` therefore shows a role-limit state ("You can't view logs", "Logs in this workspace need the Contributor role or higher…", in all 8 languages) when the page reads no resource and the project workspace's capability check confirms `can_view_logs` is denied. The project route adopts the project's workspace before its pages render, so that check asks about the same workspace as bex-api's quiet probe. The backend probe is unchanged, and ADR010 § Project views records the rule. An empty scope for a Contributor, or for an unconfirmed role answer, keeps today's copy. `project-log-viewer.test.tsx` covers the Viewer state, both kept-copy cases and a Viewer page that does read lines. The Viewer test fails with the branch disabled.
