# A cron job's Metrics page charts Outbound Bandwidth only, as Render's does

Why: Render's cron job Metrics page has one section, Network Metrics → Outbound Bandwidth; bex's also draws CPU, Memory and the event timeline, charts Render never shows for a cron job.

- **Render** (signed-in walk 2026-11-21; bundle `CronJobMetrics-BCPRz1m0.js` sha256 `4d7387578c2c…`): a range picker, then "Network Metrics" with "Outbound Bandwidth" (month to date included), and the "Want to stream your metrics to another observability tool?" notice and footer. bex shows neither: metric streams are a `DO_NOT_DO.md` non-goal. No CPU, Memory or event timeline. Render's [service metrics doc](https://render.com/docs/service-metrics) says CPU and memory for "all services except static sites", but the dashboard does not draw them for a cron job.
- **bex:** `dashboard/src/routes/services.$serviceId.metrics.tsx` renders `ApplicationMetricsCard` for every non-static type (`showApplicationCard`, around line 112) and `EventTimeline` while it is shown. `NetworkMetricsCard` already offers only bandwidth to a type with no public requests (w4/613).
- **Done when** a cron job's Metrics page shows the range picker and Outbound Bandwidth only (no Application Metrics card, no event timeline or its toggle), other types are unchanged, the route skeleton matches the ready page at 1440 and 390, REST, GraphQL and MCP metrics reads are unchanged, `docs/render-artifacts/metrics-page.md` records the walk, and a test pins the cron page's cards.
