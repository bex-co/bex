# The Edit view modal's Level, Method, Status Code, Host and Path values: offer the values the project's logs hold, as Render's does

Why: Render's Edit view lists each line field's values from the project's own logs, so `Status Code is not one of 2xx` or `Path is not one of /healthz` is picked, not typed; bex's modal asks for Status Code, Host and Path to be typed and lists fixed Level and Method values.

Found by w3/m523 t007 (2026-11-19) in Render's dashboard bundle (`ProjectLogs-*.js`, [project-observability.md § Edit view](../../../docs/render-artifacts/project-observability.md#edit-view)): Level, Instance, Method, Status Code, Host and Path each render a many-value picker fed by `logValues(input: {label, logQuery: {filters: [], ownerId, pageSize: 50, project, region}})`, a project-scoped label-values read.

- **bex today:** `dashboard/src/features/logs/lib/view-filters.ts` `viewValueKind` types Instance, Status Code, Host and Path (`TypedValues` in `components/edit-view-dialog.tsx`) and lists Level and Method from the fixed `LOG_LEVELS` and `LOG_METHODS`.
- **The gap is one read:** `logLabelValues(resource, label)` answers one resource at a time (`LogLabelValues`, `lego/backend/internal/logs/service.go`). [w3/079](079.md) asks for a project-scoped read for Instance; this note is the same read for the other five labels, so whichever ships first builds it and the other reuses it.

Done when the modal's Level, Method, Status Code, Host and Path pickers list the values the view's resources' logs hold in the store's window (one project-scoped label-values read, bounded and authorized like the project log read), a typed value is still accepted for one not in the list, and tests cover the read's scope and the pickers.

**DONE 2026-11-20.** The Edit view's Level, Method, Status Code, Host and Path rows are the same `DiscoveredValues` picker Instance got in [w3/079](079.md) (`viewValueKind` in `dashboard/src/features/logs/lib/view-filters.ts`; only Text Search is typed now): each lists what the project-scoped GraphQL `logLabelValues(project, label, type)` answers for the view's type over the last seven days, narrows as you type, and adds a typed value the list lacks (a status class such as `4xx`, a path not yet requested). Path, a line field rather than a stream label, is the one label a project read takes beyond Render's six (`projectDiscoverableLabels`, `lego/backend/internal/logs/service.go`; REST, MCP and the one-resource GraphQL read still refuse it): Loki answers it from each web service's newest 1,000 request lines in the window, projected to the path with the query's own path and host filters, and lists the 100 seen most often (`lokiPathValues`, `lego/backend/internal/logs/loki.go`); an app view's read asks the store nothing.
