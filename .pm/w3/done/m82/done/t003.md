## Objective

Project the datastore configuration changes bex already audits into Render's event names — `postgres_ha_status_changed`, `postgres_read_replicas_changed`, `postgres_connection_pool_enabled_changed`, `postgres_disk_size_changed`, and (verify-first) `key_value_config_restart` — following the `auto_deploy_enabled` / `auto_deploy_disabled` precedent: one intent verb, the recorded resulting value, no invented verbs.

## Context

- `lego/backend/internal/eventvocab/datastore.go` `DatastoreAuditTypes()` is the closed audit-verb → event-name map (today: created, restarted, credentials created/deleted, backup started, plan changed). Adding a name here is what lets the webhook projector, `GET /v1/events/{id}` hydration (w8/m24), and the picker agree.
- Verbs that exist: HA enable/disable + read replicas (`w1/m22`, `internal/postgres/service.go`), pooler toggle (`resolvePooler`, `w2/024`), storage increase (grow-only, `w2/m60`), Key Value `maxmemoryPolicy` / `persistenceMode` updates (`w6/m127`, `internal/keyvalue/service.go`). Confirm each writes an audit row with the resulting value in `details` (`core.AuditVerb*` constants in `lego/backend/internal/core/`); add the detail where missing.
- `key_value_config_restart` on Render means "a config change restarted the instance". Verify whether bex's Valkey reconciler actually restarts on the policy change; if it does not, do **not** advertise the type — record the divergence in t004's ledger update instead.
- Precedent for one-verb/two-outcomes: `w2/m70` t002 (`auto_deploy_*`), `docs/render-artifacts/webhooks-api.md` table row "Implement now from an existing discriminated audit row".

## Steps

1. Inventory the five verbs' audit rows (verb constant, details keys); add a resulting-value detail where absent (HA on/off, replica count, pooler on/off, new size GB).
2. Extend `DatastoreAuditTypes()` and, where one verb maps to one Render name with the outcome in the payload, keep it a single mapping; where Render splits by outcome, branch on the detail like `auto_deploy_*` does.
3. Ensure the webhook projector's `data.id` and the event index's `details` carry the resulting value (Render's payload shape per the pinned artifact).
4. Decide `key_value_config_restart` from the reconciler's real behaviour; document either way.
