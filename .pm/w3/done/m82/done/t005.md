## Objective

Let a member opt in to being paged when their datastore goes down (`postgres_unavailable`, `key_value_unhealthy` — Critical, like `server_failed`) and told when it recovers or when a backup, restore, or upgrade fails (Important), through the existing push worker and policy editor, with the default policy unchanged.

## Context

- Policy + worker: `lego/backend/internal/notifications/delivery_policy.go` (`DeliveryEvent` constants — today `deploy_*`, `server_failed`, `server_available`, `service_suspended`, `service_resumed`, `cron_failed`, `agent_*`), `push_worker.go` (tails the feed via `push_watermark`; deliberately excludes routine `service_hibernated`/`service_woken` — datastore events are not routine and must not be excluded), `destination_policy.go` (ADR087 eligibility: the recipient must currently be able to view the datastore — use the datastore `can_view` relation, not the App's).
- The m78 precedent: additive opt-in, default set unchanged, and a **DB CHECK** on the persisted policy that migration `0070_push_lifecycle_events` widened — a new migration must widen it again or the integration test that caught it in m78 fails.
- Dashboard push-policy editor: the component that lists `server_available` (`dashboard/src/features/notifications/` — locate via the m78 diff); both locales. Mobile: verify whether the notification catalog enumerates event types (search `mobile/src` for `server_available`); add strings only if it does.
- The feed the worker tails must include the datastore facts (t001's table) — extend `feedtail.go` / the watermark source accordingly, keeping the `(source, id)` cursor monotonic.

## Steps

1. Add the delivery events + severities; widen the CHECK via `0109_push_datastore_events.{up,down}.sql` (t003 took `0108_datastore_audit_details` for the typed audit-detail columns); keep the default policy set byte-identical.
2. Extend the tailed feed with datastore facts; route eligibility through the datastore relation.
3. Editor + locales (+ mobile catalog if applicable); message copy names the datastore display name and id.
4. Real-PG test: an opted-in member receives exactly one inbox row + one `push_deliveries` row per unavailable/available pair; a non-opted-in member receives none; a member without datastore access receives none.
