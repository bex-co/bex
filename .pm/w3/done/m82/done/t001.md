## Objective

Extend the control-plane store reconciler's observed-state path from Apps to managed datastores so that a Database or KeyValue CR whose Ready condition flips produces exactly one durable `postgres_unavailable` / `postgres_available` (or `key_value_unhealthy` / `key_value_available`) fact per real transition — with the same stale-transition rejection and single-tick debounce the App path already has — and a suspended datastore produces nothing.

## Context

- App precedent: `lego/backend/internal/store/reconciler.go` — `ReconcileOnce` lists `appv1alpha1.AppList` (managed-by selector, ~line 491); `recordObservations` (~401) runs `observedServiceStateFor` → `rejectStaleUnhealthy` (~304, compares the Ready condition's `LastTransitionTime` against the checkpoint's `healthy_transition_at`) → `debounceUnhealthy` (`unhealthyOnce` map) → `Store.RecordObservedServiceState` (`store/event_facts.go` ~260, `observedStateFacts` ~407). Interface in `store/store.go` ~553.
- Datastore status: `lego/types/v1alpha1/database_types.go` (`DatabasePhase` Pending/Provisioning/Upgrading/Ready/Failed; `Status.Conditions`) and `keyvalue_types.go` (`KeyValuePhase` Pending/Provisioning/Ready/Failed; `Conditions`). The operator writes `ConditionReady` with reasons `Provisioned` (True), `Provisioning`, `Suspended`, `MajorVersionUpgrade`, `MajorVersionUpgradeFailed` (`lego/operator/internal/controller/database_controller.go` ~901, 1095–1144) and the KeyValue equivalents (`keyvalue_controller.go` ~392, 800, 831).
- Datastore CRs are created directly by `internal/postgres` / `internal/keyvalue` (not projected by the reconciler), so the reconciler must **list** them: verify which label the datastore CRs carry (the App `LabelManagedBy` selector or the datastore's own) before choosing the selector.
- Facts today are keyed by App (`service_event_facts.app_id`). Datastore facts need a `dpg-…` / `red-…` subject plus workspace scoping so the w8/m24 owner-scoped index can serve them. Recommended shape: a sibling `datastore_event_facts` table (stable `source_key` PK, `workspace_id`, `datastore_id`, `kind`, `type`, `occurred_at`, `details`) plus a `datastore_observed_checkpoints` table carrying `availability`, `phase`, `suspended`, `healthy_transition_at`. Record the decision in the task's commit message and ADR052.
- Suspension is intentional downtime: `Ready=False/Suspended` must map to the "observed empty" state (the hibernated-App precedent: `AvailabilityObserved=false`), never to an unavailable fact. Provisioning before first Ready is not an outage either — the first healthy checkpoint arms the edge.
- Webhook vocabulary lives in `lego/backend/internal/eventvocab/datastore.go`; add the four availability constants there so the projector, the index, and the picker share one name.

## Steps

1. Add the datastore listing to `ReconcileOnce` (Database + KeyValue, one selector decision, cached client like Apps) and an `observedDatastoreStateFor` sibling of `observedServiceStateFor` that maps phase + Ready reason to `healthy` / `unhealthy` / observed-empty.
2. Add the migration `lego/backend/internal/store/migrations/0107_datastore_observed_checkpoints.{up,down}.sql` (checkpoints + facts tables, indexes for the owner-scoped index lookups).
3. Implement `RecordObservedDatastoreState` on `PGStore` reusing the App path's checkpoint CAS + `healthy_transition_at` ordering; reuse `rejectStaleUnhealthy` / `debounceUnhealthy` (parameterise by subject id rather than duplicating).
4. Emit `postgres_unavailable`/`postgres_available` and `key_value_unhealthy`/`key_value_available` with stable source keys (`<id>:<availability>:<transition-time>`), so resyncs and restarts replay idempotently.
5. Fail open like the App path on unknowns (no row, pre-migration NULL, timestamp-less condition); bump `bex_controlplane_observed_state_rejections_total` with a `subject="datastore"` label (`store/reconciler_metrics.go`).

## Acceptance criteria

- [ ] A real-Postgres test drives a Database CR Ready True → False → True through the reconciler and observes exactly one unavailable and one available fact, across repeated resyncs.
- [ ] `Ready=False/Suspended` and initial `Provisioning` produce no unavailable fact; the first `Provisioned` arms the edge.
- [ ] A Ready=False conclusion whose `LastTransitionTime` predates the last healthy checkpoint is rejected and counted, never recorded (the w6/m41 class, for datastores).
- [ ] KeyValue takes the same path with `key_value_*` names.
- [ ] `go test ./...` and `make lint-backend` green from `lego/backend`.
