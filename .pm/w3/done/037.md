# Show the ACME challenge reason on a tenant's pending custom-domain row

Why: `blockeden.xyz` sat in "Pending" for 25 days because the apex is Cloudflare-proxied and the HTTP-01 challenge answers 404 — the reason was in the `Challenge` object (`Waiting for HTTP-01 challenge propagation: wrong status code '404'`) and in the `TenantCustomDomainCertNotReady` annotation, but the tenant sees only a clock icon and cannot self-diagnose.

- Read `challenge.status.reason` (and `order.status.state`) for the App's `<app>-tls-<host>` Certificate in `lego/backend/internal/apps/domains.go` next to `domainCertificateReady`, and expose it as a nullable `certificateReason` on `DomainView` across REST / GraphQL / MCP (Render parity: additive, no Render field to mirror).
- Dashboard: `custom-domains-section.tsx` `CertificateStatusBadge` gets a tooltip/hint with the reason, plus the ADR005 fix-it text (DNS-only, ALIAS/CNAME to `<name>.onbex.co`).
- Likely > 1h across backend + three surfaces + dashboard: promote to a milestone rather than doing it as a note.
