# 075 — A HEAD for an edge-cached path reads its stored GET, not `MISS`, when the client sends no `Accept-Encoding`

Why: the edge cache means to answer a HEAD from the page a GET stored (`writeEntry`'s HEAD branch), but on production a bare `curl -I` of a cached path never hits. Each such HEAD goes to the app, which is load Render's CDN would absorb, and uptime monitors and link checkers send exactly these requests.

- **Source:** `w3/m488` t004's production check, 2026-11-19, pin `7af50a28168d` (per-pod sidecar). Fixture `m488-t004-cache` in `bex-canary`, nginx serving a 17-byte `/m488.css`, profile `origin-controlled`. The fixture is deleted. The record is in [`done/m488/README.md`](m488/README.md#production-record-t004-2026-11-19).
- **Observed:** after GETs had stored the path (`HIT`, `Age` counting), `curl -sI` twice read `200 MISS`, `200 MISS`, and `curl -sI -H 'If-None-Match: <etag>'` read `304 MISS` (nginx's own 304, with `Last-Modified`, no `Age`). With `-H 'Accept-Encoding: gzip'` the same HEADs read `200 HIT` and `304 HIT` with `Age`.
- **Cause:** Traefik forwards a GET that carries no `Accept-Encoding` with `Accept-Encoding: gzip` added (Go's transport does that for every method except HEAD), and a HEAD as it came. `cacheKey` (`lego/operator/internal/edgecache/edgecache.go`) includes `acceptsGzip`, so a bare client's GET fills the gzip key while its HEAD looks up the identity key, which no public GET fills. On the pod's port 19099 directly, a bare GET then a bare HEAD read `MISS`, then `HIT` with `Age: 0`. The tier (`w3/m489`, `a6b1658fb`) keys the same way behind the same Traefik, so the gap outlives the sidecar.
- **Constraint:** a HEAD must not be answered from a gzip-encoded stored page with `Content-Encoding: gzip` the client never asked for. Traefik decompresses only the GETs it added gzip to. So either serve a HEAD from the gzip key only when that page has no `Content-Encoding`, or fill a HEAD miss with a GET (RFC 9110 §9.3.2: a HEAD gets the GET's header fields).
- **Done when:** a unit test sends the edge's shape, a GET with `Accept-Encoding: gzip` and then a bare HEAD, and the HEAD reads `HIT` with `Age` (and `304 HIT` with a matching `If-None-Match`) without stating an encoding the client did not accept. On production, `curl -sI` twice and once with `If-None-Match` on a cached static path read `HIT` on the second and `304 HIT` on the third. ~1h.

## Work record (2026-11-19)

- **Reference.** Cloudflare, Render's CDN, sends a HEAD miss for a cacheable resource to the origin as a GET, caches the full response and returns only the headers ([cache-behavior](https://developers.cloudflare.com/cache/concepts/cache-behavior)). So both halves of the note's "either" ship, not one.
- **Fix** (`lego/operator/internal/edgecache/edgecache.go`, `peers.go`):
  - A HEAD whose own key has no page reads the page the same URL stored under the other encoding preference, when that page names no `Content-Encoding` beyond `identity` (`unencodedVariant`). A gzip page never answers a bare HEAD.
  - A HEAD miss is filled with a GET carrying the HEAD's own encoding preference. The leader gets the GET's header fields alone (`MISS`, or `304 MISS` for a matching validator), and the page is stored. A page the cache does not keep is answered with its header fields, and its body is not read (`decide`).
  - The tier routes a request to its owner by host and target (`resourceKey`), not by key, so both of a URL's pages live on one replica. Keyed alone, the edge's gzip GET and a bare HEAD could have different owners.
- **Tests** (`edgecache_head_test.go`):
  - `TestABareHeadReadsThePageTheEdgesGzipGetStored`: a GET with `Accept-Encoding: gzip`, then a bare HEAD, reads `HIT` with `Age: 7`, then `304 HIT` with `If-None-Match`, and the origin is hit once. The stored page is tried both without `Content-Encoding` and with `Content-Encoding: identity`.
  - `TestABareHeadNeverReadsAGzipPage`: on the wire, an app that gzips reads `MISS`, then `HIT`, with no `Content-Encoding` and the identity `Content-Length`. The app sees `GET gzip`, then `GET identity`, and no HEAD.
  - `TestAHeadMissIsFilledWithAGet`: a fill with `MISS`, a `304 MISS` and a `BYPASS` each answer with header fields only.
  - `TestAHeadReadsNoBodyTheCacheDoesNotKeep`: a 64 MiB file is not downloaded for a HEAD.
  - `TestABareHeadReadsTheEdgesGzipGetThroughEitherReplica`: on a two-replica tier, 16 paths are filled once each, and a bare HEAD reads `HIT` at either replica.
- **Proof the tests are real.** Each part of the fix was reverted in turn, and each revert failed at least one of these tests. Reverting the GET fill also fails the existing `TestAHeadMissNeverPoisonsGet`. `make test` and `make lint` pass.
- **Docs.** [ADR004](../../../docs/ADR004-app-deployment.md) § Edge caching has a new paragraph on HEAD, and the [ADR018](../../../docs/ADR018-render-parity.md) "Edge caching" row has one sentence.
