## Objective

Add meaningful tests that assert the logs read path queries the App's (and datastore's) `<ws>` namespace when `TenantNamespaces=true` — tests that fail against the pre-fix `s.Namespace` behavior, so this regression cannot silently return.

## Context

- Existing logs tests run in shared-namespace mode (`TenantNamespaces=false`), which is exactly why CI stayed green while prod was broken.
- Assert the namespace actually handed to the Loki history source / pod-log reader, not just that a call happened. A fake `LogHistorySource`/`PodLogs` capturing the `namespace` argument is the cleanest seam (`s.History`/`s.PodLogs` are injectable deps — see `cmd/api/main.go:180-182`).
- Cover: App history (`QueryLogs`), `Logs`, `LabelValues`, live pod-log fallback, and the datastore paths (Postgres/Key Value). Include a shared-namespace case that still passes `b.Namespace` (byte-identical guard).

## Steps

1. Build a `Service` with `TenantNamespaces=true`, an App CR (via fake client) in a `<ws>` namespace, and a capturing fake `History`/`PodLogs`.
2. Assert the captured namespace == the App's `<ws>` namespace across every App-log path; add the datastore equivalents.
3. Add the negative: with `TenantNamespaces=false`, the captured namespace == `b.Namespace`.
