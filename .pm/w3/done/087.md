# GraphQL metric labels use REST's spelling (`resource`, `instance`); Render's GraphQL names them by its `MetricQueryFilter` enum

Why: a Render-shaped GraphQL client finds a series' resource and instance by `labels.find(l => l.field === "RESOURCE")`, and bex's GraphQL answers `resource`, so that client finds nothing.

Found by w3/080 (2026-11-20), which moved the status-code label to `STATUS_CODE` and left the rest. Render's public dashboard bundle (`docs/render-artifacts/metrics-page.md` § Status-code label) types `MetricResultLabel.field` as the `MetricQueryFilter` enum and keys a project series by its `RESOURCE` and `INSTANCE` labels (`ProjectMetrics-*.js`, `n(S.RESOURCE)`, `n(S.INSTANCE)`). bex's GraphQL `MetricSeries.labels` reuses REST's mapper (`toRenderMetricSeries`, `lego/backend/internal/metrics/render.go`), so its fields are `resource`, `instance`, `host`, `method`, `quantile`, `aggregate`, `direction` and `degraded_sources`.

Consumers that read those labels by name: `dashboard/src/features/metrics/components/{application-metrics-card,datastore-metrics-panel,network-metrics-card}.tsx`, `dashboard/src/features/metrics/lib/project-metrics.ts`, `dashboard/src/features/metrics/hooks/use-metrics.ts` (`degraded_sources`), and `mobile/src/features/metrics/series.ts`. A shipped mobile build reads `degraded_sources` itself.

Done when every GraphQL metric label with a `MetricQueryFilter` value (`RESOURCE`, `INSTANCE`, `HOST`, `METHOD`) uses it on `metrics`, `datastoreMetrics` and `projectMetrics`, REST and MCP keep their labels, and the dashboard and mobile read the new names. Bex-only labels (`quantile`, which Render returns in `parameters`, `aggregate`, `direction`, `degraded_sources`) are either given a value Render's enum has or recorded in ADR010 as Bex extensions, with an installed mobile build kept working. A test pins the GraphQL label set. Check Render's `HOST` breakdown label in the bundle before choosing: w3/080 found `HOST` read only as a filter value there.

**DONE 2026-11-20.** Checked Render's `HOST` label first, as asked: in Render's public dashboard bundle the service page's Total Requests breakdown sends `aggregateBy: [HOST]` and charts with `seriesKey: HOST`, so a host breakdown's label is `HOST`; `INSTANCE` keys the CPU, Memory and Disk charts, and `RESOURCE` the database and project charts ([metrics-page.md § GraphQL label names](../../../docs/render-artifacts/metrics-page.md#graphql-label-names-w3087-2026-11-20)). GraphQL `metrics`, `datastoreMetrics` and `projectMetrics` now name `resource`, `instance`, `host` and `method` `RESOURCE`, `INSTANCE`, `HOST` and `METHOD`, beside w3/080's `STATUS_CODE`, through one rename at the GraphQL `labels` field (`graphqlLabelFields`, `lego/backend/internal/metrics/render.go`); REST and MCP keep the lowercase names. `quantile`, `aggregate`, `direction` and `degraded_sources` are recorded as Bex extensions in [ADR010 § Series label names](../../../docs/ADR010-observability.md#series-label-names-w3080-w3087-2026-11-20): Render's GraphQL carries a percentile in `parameters`, its read and write graphs split by `CUSTOM` on a query bex serves as its own `datastoreMetrics`, and shipped mobile builds read `degraded_sources` (mobile reads no other label, so it needed no change). The dashboard's Application, Network, datastore and project charts read the new names. `TestGraphQLMetricLabelNames` pins the label set on GraphQL (eleven reads across the three queries), REST and MCP, and fails on every GraphQL read with the rename disabled; the dashboard tests of the four consumers fail with the old reads. The bundle showed two more gaps, filed as [095](095.md) (GraphQL `parameters` is a list where Render's is one object) and [096](096.md) (MCP refuses a host breakdown beside CPU).
