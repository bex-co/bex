## Objective

Make the page work against the real `api.bex.co` with a browser session, handle the failure modes honestly, and verify end-to-end with live `beancount-cms` data (the App's resource/CR name — `beancount-cms-v2` is only its `.onbex.co` hostname, confirmed in t001).

## Context

- Cross-origin: the dashboard origin differs from `api.bex.co`; bex-api's CORS is a single exact origin via `BEX_API_CORS_ORIGIN` (`operator/config/api/deployment.yaml`). **`Access-Control-Allow-Credentials` is already fixed** (t001 prerequisite, `operator/internal/api/auth.go`'s `withCORS`) — this task only needs to set the actual origin value and verify it works live.
- Failure modes to surface (from `docs/observability.md`): **503** `metrics source not configured` (e.g. `BEX_PROM_URL` unset) → explicit callout, not an empty chart; empty series (Prometheus warming / no traffic) → "no data in range" state; 401 → redirect to login (existing `requireAuth`).
- Live verification target: `beancount-cms` (Running in prod; request metrics need some traffic to have shape — a brief curl loop against `https://beancount-cms-v2.onbex.co`, its hostname, is fine).

## Steps

1. Set `BEX_API_CORS_ORIGIN` in `operator/config/api/deployment.yaml` to the dashboard's prod origin (and document the localhost dev origin override).
2. Add the three UI states (unavailable / empty / unauthenticated) to the metric chart block.
3. Run the dashboard against prod api, log in, open the beancount-cms metrics page; drive light traffic so request charts have points.
4. Screenshot the populated page to `.playwright-mcp/` (bare filename) as the PoC artifact.
