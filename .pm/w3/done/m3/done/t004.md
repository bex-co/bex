Ran 4 parallel review agents (reuse / simplification / efficiency / altitude) over the milestone's full diff (t001–t003's commits + the t005 test additions). Applied:

- **Efficiency + altitude (same finding, two angles):** `NetworkMetricsCard`'s three `useMetrics` calls now pass `pollIntervalMs: 0` — `useLiveRange`'s 15s tick already forces a refetch every cycle by changing `startTime`/`endTime`; Apollo's own 30s poll timer on top was a second, out-of-phase, fully redundant refetch (~30-50% more requests than necessary).
- **Simplification:** `useLiveRange`'s tick cadence now derives from `preset.resolutionSeconds` instead of a flat `TICK_MS = 15_000` — the 12h preset (300s buckets) was ticking 20× more often than its own resolution could show anything new. Also hoisted the `WIDTH`/`HEIGHT`/`PAD` constants duplicated across `svg-line-chart.tsx`/`svg-bar-chart.tsx` into a shared `chart-layout.ts`, and swapped `MetricSection`'s `ReturnType<typeof useMetrics>` for the already-exported `UseMetricsResult` type.
- **Altitude:** `routes/index.tsx`'s Services sample table now only links the one real App (`beancount-cms`) to the Metrics page — the other three rows are fake ids with no backing App; linking them routed to a live "app not found" GraphQL error that (per the altitude review) every component silently swallows as an empty state. Gated via an explicit `hasLiveMetrics` field rather than hardcoding the id string.
- **Reuse:** one finding (`use-live-range.ts`'s mount effect duplicates `common/hooks/use-on-mounted.tsx`'s documented setInterval pattern) turned out to be **incompatible** with the simplification fix above — `useOnMounted` is deliberately mount-once/no-deps, but tying the tick to `preset.resolutionSeconds` requires the effect to re-run when the preset changes. Kept the plain `useEffect` with a real dependency array; noted the conflict rather than applying both.
- **Also fixed while investigating:** a genuine bug the t005 tests surfaced — an all-zero-value series collapsed the Y-axis gridline ticks to the same value in both chart components, and they were keyed by value (React duplicate-key warning); now keyed by index.

**Explicitly skipped** (documented, not applied — out of `/simplify`'s "quality only, behavior-preserving" scope):
- Altitude finding: `useMetrics` distinguishes `ErrMetricsUnavailable` from a real error by exact string-matching bex-api's Go error message (`"metrics source not configured"`), with no test pinning that contract on either side, and the `.error` field is currently dead (no component renders a distinct error state for e.g. `ErrNotFound`). The fix (`ErrMetricsUnavailable` implementing a GraphQL `Extensions()` code, matched by `extensions.code` instead of a message string) is real and worth doing, but it's a cross-language change to bex-api's error contract plus a live redeploy — bigger than a simplify pass over already-shipped code. Recommend a follow-up task if this page grows past PoC.
- Altitude finding: `ApplicationMetricsCard`'s single-replica `latestValue(series[0])` assumption. Already honestly documented in a code comment tied to the milestone's actual verification target (`beancount-cms`, single replica); the review's own judgment was this is "acceptable... not mandatory" to fix further for a stated PoC.
- Reuse (soft): `MetricUnavailable` could reuse `common/components/ui/alert.tsx`'s `Alert` primitive. `Alert` is unused anywhere else in the dashboard and its default layout (left-aligned icon+title+description) doesn't match the PoC's centered dashed-border treatment — not a clear net improvement, skipped.
