## Objective

Prove the whole chain on the real cluster — cAdvisor → Prometheus → bex-api → REST/GraphQL — over a range of at least an hour, then update `docs/observability.md` so the docs describe reality.

## Context

- Verify recipe pattern already in `docs/observability.md` ("Verify (mock cluster)" section) — extend it with a ranged query.
- The "Render compatibility" deviations list currently leads with "snapshot resolution — resource metrics return a single current point"; that entry must be rewritten (Prometheus path stepped, metrics-server fallback still snapshot).
- The w3/m3 dashboard metrics page is the downstream consumer — a quick look there confirms charts draw lines, not dots.

## Steps

1. Deploy/sync t001's Prometheus config; wait for cAdvisor targets to be up.
2. `curl` `/v1/metrics/cpu|memory|instance-count` with `startTime`/`endTime` spanning ≥1h and a `resolutionSeconds`; confirm multiple points per series and sane `percentage=true` values. Repeat via GraphQL `metrics(...)`.
3. Update `docs/observability.md`: metrics flow diagram/source description, the snapshot deviation entry, and the verify recipe. Run `npx prettier@3.4.2 --write "**/*.md"`.
