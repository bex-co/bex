# An image-backed service's header is one line shorter than its skeleton at 640–1279 px, because the skeleton reserves a Git repository slot

Why: the dashboard's pending frames must hold the ready page's geometry (root `AGENTS.md`, dashboard skeleton rule); every tab under an image-backed service's header still moves up 34 px (24 px at 768) when the service read lands at these widths.

Found by w3/085 (2026-11-20, on the tree against `scripts/local-bex.mjs`, the `Server` read held and the answer rewritten to `repo: null`, `runtime: image`). With w3/085's fix, every slot of `ServiceDetailHeaderSkeleton` (`dashboard/src/features/services/components/service-detail-header.tsx`) is as tall as the element it stands for, and a Git service matches at 1440, 1024, 768 and 390. The second row is a wrapping flex row, though, and whether it wraps depends on the service. At 1024 (720 px of content) a Git service's Service ID, repository and URL take two lines (66 px). An image service has no repository item, so its Service ID and URL fit on one line (32 px), while the skeleton always draws the repository slot and wraps like the Git service. Header: pending 48–227, ready 48–193 at 1024; pending 48–255, ready 48–231 at 768. At 1440 and 390 both runtimes match.

The pending frame knows nothing about the service. `useCachedServiceType` (`dashboard/src/features/services/hooks/use-cached-service-type.ts`, w4/m196) already shapes skeletons from Apollo's cache. The `Services` list (`dashboard/src/features/services/api/services.graphql`) does not select `repo`, so the header cannot do the same today. One way: select `repo` (and `registryCredentialId`) in the list, read them beside the type, and let `ServiceDetailLayout` pass the skeleton whether to draw the repository slot. A cold navigation with nothing cached keeps today's Git-shaped frame.

Done when, with the `Server` read held and the workspace's services list cached, an image-backed web service's header border and its tab's first control sit at the same y pending and ready at 1024 and 768, a Git service's still do at 1440, 1024, 768 and 390, and a test covers the cached-repository decision.

**Done 2026-11-20.** The `Services` list now selects `repo` and `registryCredentialId`. `useCachedServiceSource` (`dashboard/src/features/services/hooks/use-cached-service-type.ts`) reads them from the cached `Service`, from its own `server(id)` read or else the workspace list. `ServiceDetailLayout`'s pending frame passes that answer to `ServiceDetailHeaderSkeleton`. The skeleton then draws the repository slot only for a service with a repository, and a registry-credential slot when one is bound. A cold navigation with nothing cached keeps the Git-shaped frame. The skeleton's "Details" slot also sits in the first row on a phone, as the ready toggle does (`row-start-1`, at its touch height). Without that, an image with a registry credential drew its URL beside the credential and ended 28 px short at 390.
