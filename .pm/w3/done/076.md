# Project log views: `IS_NOT` on the line filters (Level, Instance, Text Search, Method, Status Code, Host, Path)

Why: Render's filter operators are `IS` and `IS_NOT`, but bex's log query has no negation, so w3/m505 refuses a view whose document puts `IS_NOT` on a line filter. Once w3/m507's Edit view modal can write one, a view such as "everything but info" must read, not fail.

- Today: `lego/backend/internal/savedsearch/document.go` (`Filter.validate`) refuses `IS_NOT` on every field but `RESOURCE` and `RESOURCE_TYPE`, by name (`filter field "LEVEL" does not support operator IS_NOT`); scope fields already negate in `Document.Scope`.
- Needed: negated value sets on `LogQuery` (`Level`, `Instance`, `Search`, `Method`, `StatusCode`, `Host`, `Path`) honored by the Loki selector (`loki.go`, `!~` label matchers and negated line filters), the pod-log path (`LogQuery.keep`) and the live tail, then the validator accepts `IS_NOT` there.
- Render's exact operator set per field is not captured (docs/render-artifacts/project-observability.md lists `IS | IS_NOT` for the bundle as a whole); capture it from the Edit view modal before shipping, and record any field Render keeps `IS`-only.
- Done when: a project view with `LEVEL IS_NOT [info]` reads every non-info line of the project on GraphQL `logs(project, filterDocument)` and on the `/v1/logs/subscribe?project=` tail, with a test per surface, and ADR010 § Project views no longer lists the refusal.

## Promoted (2026-11-19)

- Promoted to milestone **w3/m523** ([README](m523/README.md)) by `/loopx w3`. The negation reaches six read paths (the Loki selector and pipeline, the pod-line level matcher, pod selection and instance resolution, the datastore reads and the live-tail routing), plus the validator, the Edit view modal, ADR010 and a live check. That is more than one sitting.
- Triage on `a767dc133` confirmed the premise: `Filter.validate` refuses `IS_NOT` on every line field (`lego/backend/internal/savedsearch/document.go:180`), and `LogQuery`'s structured filters only select.
- The note's open question is settled from Render's public dashboard bundle, read 2026-11-19 (`ProjectLogs-*.js`, `SavedViewFiltersModal-*.js`). Render offers `IS` / `IS_NOT` on Level, Instance, Method, Status Code, Host and Path, `contains` only on Text Search, and `is` only on Environment and the time range. So m523 negates six fields, not seven. The bundle also shows bex's document spellings (`TEXT`, a `TIME_RANGE` row) differ from Render's (`TEXT_SEARCH` with `CONTAINS`, top-level `timeRange.relative`). m523 t001 files that as its own item.
