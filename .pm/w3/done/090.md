# Log explorer Copy logs writes Render's line format: `timestamp [resource] METHOD STATUS host+path text`

Why: a reader pasting copied logs into a ticket or a script gets Render's machine-readable ISO timestamps from Render, and bex's localized clock, `[instance]` tags and date rows instead.

Read from Render's dashboard bundle by w3/m528 (2026-11-20, `Logs-DOHYAXbe.js`, function `Dn`): Options ▸ Copy logs (`⌘⇧C`) writes each line as `${log.timestamp} ${En(log, {labelValue})}`, the record's own ISO timestamp, then `[resource name]` in a project view, the request's METHOD, STATUS and host+path, then the text with ANSI stripped. There is no instance tag and no date separator line. The toast reads `Copied logs` / `Couldn't copy logs`.

bex today: `logRowsText` (`dashboard/src/features/logs/lib/log-rows.ts`) writes each row as it reads: a date row per day, the dashboard-language clock (or none when timestamps are hidden), `[resource]`, `[instance]`, then the request parts and message. The row menu's Copy log line (w3/m528) already writes Render's `En` part (`logLineText`), so the two can share it.

Done when Copy logs writes Render's format, one line per record in the order shown, with no date rows; the ADR018 Logs row's copied-text note says so; and `log-rows.test.ts` pins the format for an app line, a request line and a project view line.

**Done (2026-11-20).** `logRowsText` (`dashboard/src/features/logs/lib/log-rows.ts`) now writes Render's `Dn` for every explorer (service, Postgres, Key Value, project views, a deploy's log): one line per record in the order shown, the record's own RFC 3339 timestamp (as the API sent it, whether or not the list shows its clock), then Copy log line's `logLineText` (`[resource]` in a project view, a request's METHOD STATUS host+path, the text with ANSI stripped); no date rows and no instance tag. The toast now reads Render's _Copied logs_ / _Couldn't copy logs_ (en; the other catalogs already said the same). Tests: `log-rows.test.ts` § logRowsText (w3/090) pins an app line, a request line, a project view line (named, and by id when unnamed), the order with no date rows, and a line without a time; each failed with the date row, the instance tag or the timestamp put back. The explorer and list tests copy the new format and toast. ADR018's Logs row says so. Not walked in a browser: the change is the clipboard text only, covered through the list handle and the Options menu in jsdom.
