## Objective

Expose the reason on all three API surfaces at once, so the three cannot drift.

## Context

- The wire type is `renderCustomDomain` (`domains.go`), the GraphQL type is `customDomainGQLType` (`graphql.go:646`), and MCP projects the same view — the existing `dnsRecord`/`ownershipDnsRecord` additions are the precedent for a bex extension that Render has no field for.
- `omitempty` on the JSON field keeps a healthy domain's response byte-identical to today's.

## Steps

1. Add `CertificateReason string \`json:"certificateReason,omitempty"\`` to `renderCustomDomain` and map it in `toRenderCustomDomain`.
2. Add a nullable `certificateReason` field to `customDomainGQLType`, resolving to `nil` when empty (the `redirectForName` pattern).
3. Confirm the MCP projection carries it (it shares the REST wire shape) and assert it in the cross-surface test.
4. Extend the existing three-surface test so REST, GraphQL, and MCP are asserted to report the same reason for one pending domain.
