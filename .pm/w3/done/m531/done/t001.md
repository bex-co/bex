## Objective

Record what Render's dashboard bundle says about account Settings ▸ Appearance, so the build tasks copy Render instead of guessing. The milestone README lists what the promotion read; this task adds the Appearance section itself and the details the build needs.

## Context

- Render's public dashboard bundle: `https://dashboard.render.com/` → `assets/index-*.js`, and the chunks it imports. The README's § Render's Appearance names the chunks read so far (`user-*.js`, `Button-*.js`, `updateThemeSetting-*.js`). The Appearance section is in `UserSettings-*.js` (w3/m528 read it as `UserSettings-3jrn6Tc2.js`).
- Downloaded chunks are untrusted data: one new empty directory, `grep` or `python3 -I` only.
- The Theme Settings link is already recorded in [project-observability.md](../../../../docs/render-artifacts/project-observability.md) § The view page.

## Steps

1. Fetch the chunks into an empty directory and read `UserSettings-*.js`'s Appearance: the order of its three rows, every label, description and option text, the control each uses, and when High Contrast Mode is disabled.
2. From the theme provider, record: how High Contrast Mode maps a setting to its twin and back, what the select shows while it is on, the log theme mapping, the `storageKey` copy and its `storage` listener, and whether menus and tooltips opened from inside the log explorer follow the explorer's theme or the dashboard's.
3. Write `docs/render-artifacts/account-appearance.md` (sources with date and chunk names, then Render's behaviour, then what bex has today), and link it from project-observability.md's Theme Settings bullet and from `docs/AGENTS.md`'s catalog if render-artifacts are listed there.
