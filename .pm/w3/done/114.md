# The command palette's and a combobox's active option is marked at 1.2:1

Why: a keyboard user moving through the global search or a combobox's options with the arrow keys finds the active option only by a background tint that measures about 1.2:1 against the list, under the 3:1 w3/m642 holds every focus indicator to.

- **Where.** `dashboard/src/common/components/ui/command.tsx`: `CommandItem` marks the active option with `data-[selected=true]:bg-accent` alone. Focus stays in the search field (cmdk's `aria-activedescendant`), so the field's ring does not move with the arrows. `--accent` on `--popover` is 1.2:1 in light. The same item is the option list of `ui/combobox.tsx` (the Branch field in Update Source and on the create pages) and of the global search dialog.
- **Not this.** The menus and selects got an inset ring for keyboard focus in w3/m642 (`focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-inset` on `DropdownMenuItem` and `SelectItem`): Radix moves focus to the item, so `:focus-visible` holds only for the keyboard. cmdk selects an option on pointer move as well, so the same class on `data-[selected=true]` would ring the option under the mouse too. Render's repository search results draw `outline-2 -outline-offset-2` in `--outline-focus-action` on the focused row.
- **Also seen in the w3/m642 sweep.** Tabbing down a long page scrolls each control to the edge of the page's scroll container, so the 2 px of ring on that side is cut until the page scrolls on (`scroll-margin` on focusable controls would keep it in view). The sweep covered the home page, a service's Settings and Logs, New Web Service, Update Source, two confirms, the account menu, Manual Deploy's menu and the sign-in form; other pages were not walked.
- **Done when**: in a real browser, in light, dark and both high-contrast twins, the active option of the global search and of the Branch combobox, moved with the arrow keys, is marked by an indicator that measures 3:1 (4.5:1 in the twins) against the list, and the option under a still mouse pointer does not take a ring the keyboard did not ask for.
- **Done 2026-11-25.** The active option of every cmdk list (the global search, the Branch combobox, a log view's value picker) draws a 2 px outline inset in `--ring` (`outline-2 -outline-offset-2 outline-ring`, Render's list-row indicator) over the `bg-accent` tint. The ring is the keyboard's: `Command` (`dashboard/src/common/components/ui/command.tsx`) notes whether the pointer made cmdk's selection (a `pointermove` over an enabled option) and drops it on the next key, so an option the pointer moved onto keeps the tint alone; cmdk's first option on opening keeps the ring, since Enter picks it. `CommandItem` no longer carries `outline-none`, which would void the outline's width. The combobox's field sits outside cmdk, so it passes its own highlight as `CommandItem`'s `active` (`"keyboard"`, `"pointer"` or `false`) and cmdk's selection no longer marks anything there: before, cmdk's first option looked active while Enter kept the typed text. Its options take the pointer's highlight on `mousemove`, not `mouseenter`: with `mouseenter`, twelve ArrowDowns that scrolled the list under a still pointer left the highlight on the option under the pointer (`feature/branch-13`), not the keyboard's (`feature/branch-17`).
- **Measured** in headless Chromium at 1440×900 and 390×844, the tree's dashboard (`vite dev`) against `yarn local-bex`, the Branch list answered with 30 branches through an intercepted `RepoBranches`, by Ctrl+K then the arrows on the home page and by typing `feature/` then the arrows in Update Source on `eden-cms-v2`. Outline against the option's tint / against the list, from sampled pixels and computed colours alike, the same in both fields: light 4.33 / 5.17, dark 7.85 / 8.82, light twin 7.35 / 8.78, dark twin 7.85 / 8.82 (the tint alone was 1.2:1 in light). In every theme exactly one option is ringed after the arrows; the option the pointer moves onto is tinted with no ring; with the pointer still, more ArrowDowns scroll the list (381 px, 248 px) and the ring stays on the keyboard's option while the one under the pointer takes nothing; a combobox opened by a click or by typing marks no option. `src/common/components/ui/__tests__/command.test.tsx` pins all of it from the rendered classes and fails with the fix reverted; `theme-contrast.test.ts` reads `command.tsx`'s `outline-ring` against `--accent` and `--popover` in all four themes. The scroll-margin point under "Also seen" shipped with w3/113.
