## Objective

Return the stored `secret` on `GET /v1/webhooks`, `GET /v1/webhooks/{id}` and `PATCH /v1/webhooks/{id}`, as Render's webhook object requires, and validate the responses with the m272 pinned-schema harness.

## Context

- Render's webhook object requires `id`, `name`, `url`, `secret`, `enabled`, `eventFilter` and returns `secret` on create, list, get and patch (`docs/render-artifacts/webhooks-api.md:18`)
- bex omits it after create (`webhooks-api.md:20`; `lego/backend/internal/webhooks/rest.go:32-41`); reads never select the column (`internal/store/webhooks.go:74`); it is stored in plain text for signing (`:201`)
- No user sign-off records this divergence in ADR018; `.pm/DO_NOT_DO.md` line 7 says amend the ADR instead of keeping the gap

## Steps

1. Add `secret` to the store's read column lists.
2. Return it in the REST webhook view on list, get and patch.
3. Remove any schema-allowlist exemption for `secret` in the m272 validator.

## Files

- lego/backend/internal/store/webhooks.go
- lego/backend/internal/webhooks/rest.go
- lego/backend/internal/webhooks/service.go

## Acceptance criteria

- [x] `GET /v1/webhooks/{id}` returns the same `whsec_…` the create returned
- [x] List and patch include `secret`
- [x] The pinned Render schema validates every webhook response with no `secret` exemption

## Out of scope

- Rotating secrets

## Result (2026-11-08, loopx w3)

`webhookEndpointColumns` and the scan targets select `secret` (`store/webhooks.go`); `toView` returns it to managers. `TestRenderRESTCreateReadPatchDeleteReturnTheSecret` runs create/get/list/patch through `rendertest.Wrap` (pinned schema, no `secret` exemption — none existed in `rendertest/allowlist.go`); a mutation dropping the secret fails it with `/secret: property "secret" is missing`. `TestPGWebhookReadsReturnTheSecret` (real Postgres) covers get, list, update and set-enabled.
