## Objective

The rule packs need object-state series (`kube_pod_container_status_waiting_reason`, `kube_node_status_condition`, `kube_job_status_succeeded`, `kube_cronjob_status_last_successful_time`, PVC usage) that the server-only Prometheus doesn't collect. Enable kube-state-metrics in the chart — and only it; keep the no-pushgateway/no-node-exporter stance. _2026-07-11: "PVC usage comes from kubelet, already scraped" was wrong — `prometheus.yaml` wholesale-replaces the chart's default scrape config with exactly two jobs (traefik + cadvisor via the apiserver proxy), so neither kubelet `/metrics` (`kubelet_volume_stats_*`) nor a newly-enabled KSM gets scraped; no annotation-based discovery survives the override. Explicit scrape jobs are part of this task (estimate bumped 25m → 40m)._
