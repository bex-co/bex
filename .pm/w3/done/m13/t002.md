## Objective

Restrict Alloy's `discovery.kubernetes "pods"` block so each node's replica only discovers pods scheduled on that node, eliminating the N× duplication.

## Context

- `deploy/gitops/base/log-shipper.yaml` — `discovery.kubernetes "pods"` currently has no node scoping, so every node discovers every pod cluster-wide, including the high-volume Traefik access-log stream `w3/m8` added.
- Two viable approaches: `discovery.kubernetes`'s `selectors { field = "spec.nodeName=<NODE_NAME>" }` (server-side field selector, most efficient — filters at the apiserver) or a `discovery.relabel` `keep` action on `__meta_kubernetes_pod_node_name`.
- **Failure mode of getting this wrong: the shipper matches nothing and the platform silently loses all logs** — this is why the fix wasn't done inline during `w3/m8` and needs live verification (t003).

## Steps

1. Implement node-scoped discovery using the field-selector approach (preferred — avoids fetching irrelevant pod objects at all) referencing the `NODE_NAME` env var from t001.
2. Test against the local mock cluster (`scripts/mock-cluster.sh`) first for basic sanity (discovery still finds local pods) before the live multi-node verification in t003.

## Files

- `deploy/gitops/base/log-shipper.yaml`

## Acceptance criteria

- [ ] In the local mock cluster, each Alloy pod's discovered target set is limited to its own node.

## Out of scope

- Live multi-node verification (t003).

## Resolution

Added `selectors { role = "pod"; field = "spec.nodeName=" + sys.env("K8S_NODE_NAME") }` to the single shared `discovery.kubernetes "pods"` block in `deploy/gitops/base/log-shipper.yaml` — the field-selector approach, server-side at the apiserver (not a client-side relabel `keep`), so it also cuts List/Watch bandwidth, not just processing. Because `app_pods`/`build_pods`/`traefik` `discovery.relabel` blocks all read `discovery.kubernetes.pods.targets`, scoping this one block fixes duplication for all three log pipelines at once.

Deviated from the acceptance criterion's literal "local mock cluster" step: the session's sandbox denied access to the mock cluster's kubeconfig (`infra/local/bex.kubeconfig`), so basic sanity was proven offline instead — `kubectl kustomize` render clean, and the real `grafana/alloy` binary's own `validate`/`fmt` subcommands (run via `docker run grafana/alloy:latest`) against the extracted River config, both clean — before t003 went further and proved it live on real prod pods, which is strictly stronger evidence than the mock cluster would have given.
