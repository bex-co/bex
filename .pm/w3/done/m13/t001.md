## Objective

Make the local node's name available to the Alloy DaemonSet's config as an environment variable, via the Kubernetes downward API.

## Context

- `deploy/gitops/base/log-shipper.yaml` runs Alloy as a DaemonSet.
- Standard pattern: `env: [{name: NODE_NAME, valueFrom: {fieldRef: {fieldPath: spec.nodeName}}}]`, exposed to the Alloy config via `controller.extraEnv` or equivalent.

## Steps

1. Add the `NODE_NAME` downward-API env var to the DaemonSet pod spec.
2. Confirm it's readable from within the Alloy config (e.g. via `env("NODE_NAME")` in River config, or however Alloy exposes env vars to its config language).

## Files

- `deploy/gitops/base/log-shipper.yaml`

## Acceptance criteria

- [ ] Each Alloy pod has `NODE_NAME` set to its own node's name.

## Out of scope

- Using the value to scope discovery (t002).

## Resolution

Deviated from the literal task: discovered the Alloy Helm chart (grafana/alloy, pinned 1.10.1) already injects a `K8S_NODE_NAME` downward-API env var (fieldRef `spec.nodeName`) into every DaemonSet replica unconditionally by default (chart's `containers/_agent.yaml`, "Default used by some Alloy components"). Reused it instead of adding a redundant custom `NODE_NAME` extraEnv — confirmed via a `helm template` diff against the live DaemonSet that the pod env spec is completely unchanged from what's already deployed. Zero new env vars added; acceptance criterion is satisfied by the chart's existing default.
