## Objective

Return the display name where Render returns `name`; keep the slug reachable.

## Steps

1. REST owners, GraphQL `Workspace`, MCP workspace tools.
2. Rename verb edits the display name; slug change (if kept) is a separate bex extension.
3. Parity tests on all three surfaces.

## Done (2026-10-30, loopx w3)

- `WorkspaceView.Name` = display name (else slug) + new `Slug`; REST `owner.name` (top-level and nested `owner` on services/Postgres/Key Value/projects via `ResolveResourceOwners`), GraphQL `Workspace.name` (+ `slug`), MCP `list_workspaces` (+ `slug`) all show it.
- `GET /v1/owners?name=` matches exactly, as Render's filter: an exact **slug** match wins outright (slugs are unique, so renaming another workspace to someone's slug cannot redirect a typed key), else every display-name match (ambiguity stays visible). `X-Bex-Workspace` applies the same precedence; the CLI's `BEX_WORKSPACE` trusts that filter (0 = unknown, 1 = it, more = ambiguous).
- Rename (`renameWorkspace`) sets the display name with the shared label rule (`core.TrimmedLabel`, ≤ 100 code points, no control characters) and refuses blank with the existing `core.NameRequiredError()`; slug and id unchanged; store `RenameTenant` → `SetTenantDisplayName`.
- Delete confirmation phrase uses the display name (Render); invite preview/accept, invite email and account-deletion details show it.
- Dashboard schema types regenerated (`slug`); mobile codegen unchanged. ADR018 Workspace lifecycle row + `render-artifacts/workspace-lifecycle.md` record the closed drift.
- Tests: rename freeform/required/control-char/length, owners filter by either name (exact), delete phrase after a rename, `X-Bex-Workspace` by display name, CLI slug selection; backend `go test` + `make lint` green.
