# 065 — A sandbox run connect token can be minted without a command, as Render's round-7 contract allows

Why: Render's 2026-11-13 OpenAPI dropped `connect-sandbox-run`'s `{command}` body, so a client written to it mints the token with no body. bex still binds the token to a command and refuses a mint without one, so that client gets a 400. Today's pinned CLI v2.36 still sends the command, so nothing breaks yet.

- **Source:** w3/m367 (round 7) simplify review, 2026-11-13. `renderRequestBodyExtensions` keeps the old body declared for the pinned CLI (`lego/backend/internal/api/render_openapi.go`). `lego/backend/internal/sandbox/exec.go` (the mint path, ~:198) requires `command`, and `connect.go` `verifyConnectToken` binds the token to it.
- **Decide (security):** Render's new flow sends the command only to the returned `uri`. Matching it means a token minted without a command either authorizes one run of whatever command the stream request carries, or is refused at redeem without one. The audit trail (`sandbox_executions` command text) then comes from the stream request. Keep the single-use and expiry bounds either way.
- **Done when:** a mint with no body answers 201 on REST, GraphQL and MCP. The stream request's command runs once and is audited. A token minted with a command still refuses a different command. The pinned CLI's `sandboxes exec` still works. Then drop the body extension once the CLI pin stops sending it. ~45m.

## Done (2026-11-13, `/loopx w3`)

- **Chosen (worker's call under ADR008 Render parity first):** Render's behavior.
  - A token minted with no command is `Unbound` (`connectClaims.ub`). Its single redeem runs the command the stream request names, under the minter's identity, with the full exec gate re-run (can_create, ownership, the agent-session `can_view_sensitive`), the same nonce and the same lifetime.
  - A redeem with no command is a 400 that does not spend the token.
  - A token minted with a command keeps the exact-match rule. An old token, with no `ub`, decodes as bound.
- The execution history records the command at redeem (`SetSandboxExecutionCommand`, once, only into an empty command).
- The command check stays inside `authorizeExecTarget`, after authorization, so a refused caller is still refused and audited before any input is judged (`TestAuthzGuardsEveryVerb`). Only the mint passes `needCommand` false.
- The mint route is REST only (GraphQL and MCP have no connect mint). The gate test covers a bodiless mint. The pinned CLI keeps sending `{command}`, which still binds.
- **Tests:**
  - `TestConnectRunWithoutACommandBindsTheRedeemsCommand`: a 201 mint, then the no-command 400 without spending, then the redeemed command executed and recorded, then a 409 replay.
  - `TestConnectRedeemRechecksPermission`: revocation after the mint gives 403 with no exec, for bound and unbound tokens.
  - `TestSetSandboxExecutionCommandPG`.
- ADR104 records the round-7 connect behavior.
