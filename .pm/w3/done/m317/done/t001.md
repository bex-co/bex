## Objective

`audit_events` gains typed columns for what Render's members require and bex does not keep yet, and the events store reads them back onto the page without widening the feed's UNION.

## Context

- `audit_events` already has `disk_id` (0186), `disk_size_gb` (0108) and `maintenance_mode_to`; the feed reads only `disk_id` and `disk_size_gb` (`lego/backend/internal/store/events.go` `serviceEventsQuery`, `getServiceEventQuery`)
- `attachDeployEnds` / `attachDiskUsage` fill a page's rows in one extra read so the UNION projection stays as it is

## Steps

1. Migration `NNNN_audit_event_change_details`: `disk_size_from_gb integer`, `maintenance_uri_from text`, `maintenance_uri_to text`, `auto_deploy_reason text`, `auto_deploy_trigger text`; all NULL for every other verb and older rows
2. `core.AuditEvent` + `store.Record` write them
3. `store.ServiceEventRow` gains the fields plus `MaintenanceModeTo`; an `attachAuditDetails` reads them for the page's audit rows in one query, called by `ListServiceEvents` and `GetServiceEvent`

## Files

- `lego/backend/internal/store/migrations/`, `store/audit.go`, `store/events.go`, `core/audit.go`

## Acceptance criteria

- [ ] A store test records an audit row with each field and reads it back through both `ListServiceEvents` and `GetServiceEvent`
- [ ] A row without them reads back nil

## Out of scope

- Backfilling old rows
