## Objective

Every write that produces one of the six events records the facts on its audit row.

## Context

- `apps.AddDisk`/`UpdateDisk`/`DeleteDisk` audit through `RecordAppConfigChanged` with no disk (`lego/backend/internal/apps/disks.go`)
- `RecordMaintenanceModeEffects` (`core/audit.go`) records the toggle's `to` but not the URIs (`apps/service.go` `setMaintenanceMode`)
- `RecordAutoDeployChanged(…, false)` is written the same way by a settings change (`apps/service.go` `setAutoDeployFetched`) and a dashboard rollback (`deploys/service.go` Rollback)

## Steps

1. A disk recorder: id and size on create, id and from/to size on update, id on delete
2. Maintenance: the from/to URI on a URI change
3. Auto-deploy: the reason (`setting_change` / `rollback`) and the trigger before a disable or after an enable

## Files

- `lego/backend/internal/core/audit.go`, `apps/disks.go`, `apps/service.go`, `deploys/service.go`

- [ ] Unit tests with a recording audit sink pin each verb's fields

## Out of scope

- `manual_deploy`: bex has no path that disables auto-deploy on a manual deploy
