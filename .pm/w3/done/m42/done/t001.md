## Objective

Fix the ADR042 D5 blocker: OpenSandbox's snapshot-commit Job mounts `hostPath`, forbidden under the tenant-namespace PSS baseline — move the Job outside the tenant namespace (a privileged platform namespace, mirroring bex's own `BEX_BUILD_NAMESPACE` pattern) or otherwise eliminate the `hostPath` requirement, and land the change upstream (PR) or as a documented carried patch.

## Context

- Substrate: OpenSandbox server + BatchSandbox controller deployed via `deploy/gitops/` (opensandbox controller); tenant sandboxes live in `<ws>-sandbox` under baseline PSS (w3/m31).
- Precedent for the shape: bex runs build Jobs in a separate privileged-enough `bex-build` namespace rather than weakening tenant namespaces.
- Upstream-scope uncertainty is why this task is 120m — timebox the upstream conversation; a carried patch in gitops is the acceptable fallback (documented, pinned).

## Steps

1. Read the upstream snapshot-commit Job code; design the out-of-namespace (or hostPath-free) variant.
2. Implement + test on the local/dev substrate.
3. Open the upstream PR; if stalled, pin a carried patch in `deploy/gitops/` with provenance notes.

## Files

- upstream OpenSandbox (PR), `deploy/gitops/` (opensandbox manifests/patch)

## Acceptance criteria

- [ ] Snapshot commit succeeds with tenant namespaces at PSS baseline (no privileged/hostPath pod in `<ws>-sandbox`)
- [ ] Change upstreamed or carried-patch pinned with provenance
