## Objective

With the commit Job fixed, re-enable the pause/resume path end to end: suspend snapshots the rootfs and tears down the pod; resume restores from the snapshot and the workload continues — verified live on the production gVisor substrate with evidence (the w3/m32 deferred capability, now real).

## Context

- Lifecycle client: `lego/backend/internal/sandbox/client.go` (suspend/resume verbs shipped in w3/m32 but broken in prod per ADR047 "Known substrate defect").
- Verify against `render ea sandbox` stop/resume semantics where they map (cli-compat checklist).
- **t001 groundwork (2026-08-01)** — read before executing:
  - Patched controller image + `opensandbox-snapshot` namespace deploy automatically on `/ship` (base values + chart + deploy.yml write-back); the transport stays off until this task flips prod values.
  - Push side is solved: `bash scripts/snapshot-registry-secrets.sh` (out-of-band) creates `opensandbox-snapshot/bex-snapshot-push`; bex-builder already holds Zot's adminPolicy, so `snapshots/**` needs no ACL change.
  - **The open design piece is resume-pull scoping**: the controller injects `resumePullSecret` into the recreated pod template's `imagePullSecrets` (`batchsandbox_pause_resume.go:562`), a namespace-local reference — it must exist in every `<ws>-sandbox` namespace. A shared read credential there lets any tenant pull other tenants' snapshot rootfs (may embed secrets) — per-workspace scoping is required. The upstream contract is ready: in dedicated-job-namespace mode the carried patch nests snapshot repos under the source namespace (`snapshots/<ws>-sandbox/<sandbox>-<container>`), so the bex-side work is a per-ws Zot user with a `snapshots/<ws>-sandbox/**` read ACL + a `reg-pull`-style Secret minted at `<ws>-sandbox` provisioning (NamespaceReconciler or operator registry machinery — decide custody at execution). Do NOT enable push-only: pause would succeed while resume fails (worse than failing fast).
  - Prod flip values are pre-written in `deploy/gitops/overlays/prod/values/opensandbox-controller.values.yaml`'s comment (registry `zot.bex-registry.svc:5000/snapshots`, `registryInsecure: true` — in-cluster Zot is HTTP, w7/008); `containerdSocketPath` is already set for k3s.

## Steps

1. Design + implement resume-pull scoping (per-`<ws>-sandbox` secret minting; security review per the context note).
2. Run `scripts/snapshot-registry-secrets.sh` on prod; flip the prod snapshot values; `/ship` + Argo rollout.
3. Live verification: `BEX_LIVE_VERIFY=1 … bash scripts/verify-sandbox-pause-resume-live.sh` (pre-written; asserts the marker round-trip AND that the commit Job ran in the dedicated namespace, with named failures for the D5 hang / missing resume credentials).
4. Record evidence in the milestone log; update ADR042 D5 notes to verified-resolved.
