## Objective

Give the agent client an auth step that keeps the bearer valid for the whole run, coordinated with other `bex` processes that share the same login file.

## Context

- `config.DefaultAPIConfig()` (upstream, exported) reads the on-disk login; `client.NewDefaultClient()` re-reads it and refreshes (with 15-minute tokens it always refreshes, so call it only when needed).
- The 60 s rotation grace covers two processes refreshing the same token at once; a stale in-memory refresh token used later than that revokes the whole chain.

## Steps

1. Replace the static bearer editor in `lego/cli/internal/agent/api.go` with an auth editor guarded by a mutex.
2. Before a request, if the in-memory access token expires within 2 minutes: re-read the on-disk login; if another process already rotated it and it is valid, adopt it; otherwise rebuild through `client.NewDefaultClient()` (which refreshes and persists).
3. On a `401`, do the same once and retry the request once when it is safely repeatable (GETs and the attach-ticket mint); otherwise return the error.
4. Never write the login file from a stale copy: re-read immediately before any write path we own.

## Files

- `lego/cli/internal/agent/api.go`, a new `lego/cli/internal/agent/auth.go`, tests beside them.

## Acceptance criteria

- [x] Unit tests with a fake token endpoint and a 2-second token: a loop of requests over 10 seconds never sends an expired bearer.
- [x] A login file rewritten by "another process" mid-run is adopted without a refresh call.
- [x] A `401` triggers exactly one refresh and one retry.

## Out of scope

- Upstream `render` commands (not bex-native); fork or vendor nothing.

## Result (2026-11-26)

`lego/cli/internal/agent/auth.go` (`login`) replaces the static bearer editor. Before every request it re-reads the login on file and adopts a newer, unexpired one for the same API. It refreshes only within `renewBefore` (2 min) of expiry or once after a `401`, from the refresh token on file unless this run already spent it, through upstream's public `oauth.NewClient(...).RefreshToken`. It writes back only while the file still holds the login it refreshed from. A refused refresh writes nothing, keeps a still-valid token with a 30 s pause, and otherwise answers `renew the bex login: <error>` followed by the advice to run `bex login`, then the command again. After a `401`, `api.do` repeats GETs and the attach-ticket mint once; any other request reports the `401`, and the next one carries the renewed bearer. An API key (`ExpiresAt` 0) is never refreshed. Tests in `auth_test.go` run against a fake token endpoint with two-second tokens. They cover ten seconds of polling with no dead bearer, adopting another process's rotation without a refresh, a `401` causing one refresh and one repeat (none for a steer), and a refresh written over neither a newer login nor a concurrent one. Each test fails with the static bearer restored.
