## Objective

Every new alert has a panel (ADR088 §6), and the board answers "quiet or broken?" (ADR113 G6).

## Context

- Board `bex-cli-usage` in `deploy/gitops/base/values/grafana.values.yaml` (from ~:8239). Its collection-health row has "Telemetry ingest rate", "Ingest rejection share" and "Ingest latency p95".

## Steps

1. Add "Telemetry coverage": stored events ÷ CLI API requests, by client, as a trend.
2. Add "Stored events by completion kind" from the relabelled counter.
3. Add "Backoff-causing answers": `429` and `503` answers on the ingest route.
4. Link each panel to the alert it backs in its description.

## Acceptance criteria

- [ ] `bash scripts/gitops-validate.sh` passes, including the alert-to-panel coverage check.

## Result (2026-11-16)

Panels 26 to 28 on `bex-cli-usage` (row y=82): **Telemetry coverage** (stored events per CLI request over an hour by client, with the requests as bars on the right axis), **Stored events by completion kind** (events per hour by kind; the 30-minute execution_error share and the dashed alert line on the right axis, from the rules the alert reads) and **Backoff-causing answers** (429 and 503 per hour on the ingest route). Each description names the alert it backs; `obs-coverage-check.sh` maps all three alerts to the board. The panels read the recorded rules rather than every replica's raw counters, so a 7-day board refresh stays cheap.
