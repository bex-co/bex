## Objective

Verify the new push events are consistent across every surface they touch, and keep the deliberate bex-extension divergences explicit rather than drifting.

## Context

- Push is a documented bex extension — Render has no push channel (`docs/ADR018-render-parity.md`, native-push row; `docs/ADR048-mobile.md` D2). "Parity" here = one `Service` core behind thin adapters (docs/ADR006-bex-api.md): identical event names, enum vocabulary, field shapes, and error dialects across REST `GET`/`PATCH /v1/notification-settings/push`, GraphQL, the dashboard editor, and the mobile client.
- Deliberate divergences to re-assert, not "fix": MCP has **no** push-policy or device-token tools (ADR048 D2); the mobile envelope vocabulary is closed; email notification policy (`notificationsToSend`) is untouched by this milestone.
- ADR052's gap register items 1–2 and its CLAUDE.md index line must be updated to reflect the shipped state.

## Steps

1. Diff the event vocabulary across REST validation, GraphQL enum, `push-policy.ts`, and the mobile vocabulary — byte-identical names.
2. Confirm MCP surface unchanged (no push tools appeared) and REST error shapes for unknown events match the pre-existing dialect.
3. Update `docs/ADR052-notifications.md` (gap items 1–2 → resolved, pointer to w3/m78), `docs/ADR018-render-parity.md` push row if its wording changes, and the ADR052 line in `CLAUDE.md`'s docs index. Run `npx prettier@3.4.2 --write "**/*.md"`.
