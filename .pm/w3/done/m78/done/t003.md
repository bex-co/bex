## Objective

Prove ADR052 gap-register item 2: a post-`Running` crash emits **exactly one** `server_failed` fact and its recovery **exactly one** `server_available`, across multiple 30s resync ticks (the `service_event_checkpoints` edge dedup), with the corresponding push rows enqueued — closing the "correct by unit tests only" hole in the reconciler's derived-availability edge.

## Context

- The edge is synthesized, not operator-native: a post-Running crash routes the App back through `PhaseDeploying`/`RolloutProgressing` (`lego/operator/internal/controller/app_controller.go` ~1177–1200, `stuckPodMessage` ~2576), and `observedServiceStateFor` (`lego/backend/internal/store/reconciler.go:726`) derives `unhealthy` from `Ready=False` + `ActiveRevision != ""` with the `hasOpenDeploy` guard (~751) limiting rollout-time failures to CrashLoop/ImagePull reasons.
- `RecordObservedServiceState` (`store/event_facts.go:191`) diffs against the checkpoint inside a transaction — re-observing an unchanged state must emit zero facts.
- Existing harness patterns: real-Postgres-gated integration tests (`BEX_TEST_DB_URI`) in `lego/backend/internal/store/event_facts_test.go`, and the `scripts/*-verify.sh` live-leg convention (e.g. `scripts/webhooks-verify.sh`).

## Steps

1. Store-level integration test (real-PG gated): feed a synthetic App status sequence — Running/healthy → Ready=False CrashLoopBackOff (repeated over ≥3 observations) → Ready=True Running (repeated) — through `observedServiceStateFor` + `RecordObservedServiceState`; assert exactly one `server_failed` (reason `readiness_failed`) and one `server_available`, and that push dispatch enqueues rows for a policy-enabled member.

The live leg is instead specified as the operator runbook block in the milestone README (break a store-managed service's image → assert the events-feed pair + inbox rows), gating t007 — the m77 closeout pattern.
3. Record the run evidence in the milestone README on completion.
