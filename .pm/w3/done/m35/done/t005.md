## Objective

Turn sandbox ownership from a create-response decoration into a durable authorization boundary used by list/get/lifecycle and the future exec surface.

## Context

- `Service.Create` adds `Owner` only after OpenSandbox returns and sends no owner/workspace metadata upstream.
- `List` returns every sandbox in the workspace; get/pause/resume/terminate authorize the workspace relation but never verify the sandbox owner.
- ADR014 D7 requires owner→sandbox reconnection keyed on resolved caller identity.

## Steps

1. Stamp reserved owner/workspace metadata on OpenSandbox create and parse it on list/get.
2. Centralize resource authorization: owner access plus a documented explicit workspace-admin override.
3. Apply the same check before lifecycle and future exec operations; reject legacy ownerless objects and any object missing its sandbox-regime or enforced-policy stamp fail closed.

## Acceptance criteria

- [ ] Two non-admin members of one workspace cannot list, inspect, terminate, or exec each other's sandboxes.
- [ ] The owner and explicit workspace administrator can perform the documented operations.
- [ ] Owner/workspace metadata survives list/get and cannot be overridden by caller-supplied metadata.
- [ ] A foreign, legacy, or incompletely hardened metadata record is hidden behind the same named not-found response.

## Out of scope

- A general sandbox-sharing/invitation feature.
