## Objective

Amend the sandbox ADRs with the exact security domains and permitted flows that implementation and verification must enforce: every sandbox is mutually untrusted, including two sandboxes in one workspace; gVisor is the runtime boundary; Cilium is the network enforcement layer; bex-api/OpenSandbox are the only control/data-plane gateways.

## Context

- OpenSandbox's Kubernetes guidance treats direct sandbox Pod-IP access as an authorization bypass.
- `lego/backend/internal/store/namespaces.go` currently treats the entire `<ws>-sandbox` namespace as one trust domain through `allow-same-namespace`.
- ADR042 currently calls the per-tenant namespace the isolation boundary but does not state the same-workspace sandbox-to-sandbox deny invariant.

## Steps

1. Document actors, assets, trust boundaries, allowed flows, and fail-closed behavior in ADR042/ADR043.
2. Record the gVisor/OpenSandbox-sidecar incompatibility and the Cilium enforcement decision.
3. Define ownership semantics for ordinary members versus explicit workspace administrators.
