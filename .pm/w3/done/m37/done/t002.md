## Objective

Implement the in-sandbox session driver (ADR047 D3): a small Node process built on the Vercel AI SDK with the pinned `@mcpc-tech/acp-ai-provider` community provider, which spawns the ACP agent as a stdio child via `createACPProvider({command, args, persistSession, existingSessionId})` and runs a headless one-`streamText`-turn task (phase 1 fire-and-forget, D8).

## Context

- Provider is stdio-spawn only — that is why the driver lives inside the sandbox (ADR047 "Alternatives considered").
- Provider is v0.2.x on AI SDK v6: pin exact versions; `acpTools()` is experimental — avoid or isolate it.
- ACP permission requests get no client callback: run the agent auto-approve (the sandbox + egress policy is the safety boundary, exemplar posture).
- The driver receives the task prompt + agent config at start (env/config file injected by the session create path, w3/m39).

## Steps

1. Scaffold the driver package inside the agent image context (TypeScript or plain JS, pinned deps).
2. Wire `createACPProvider` → `streamText` for a single headless turn; capture the full stream (including raw chunks) to a local session log for evidence (w3/m41 consumes it).
3. Handle agent exit/failure: nonzero exit surfaces a failed-session status the lifecycle layer can read.
4. Run it end-to-end in a sandbox on the dev-3 or prod substrate against a real cloned repo; confirm commits appear.
