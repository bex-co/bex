## Closeout note (2026-08-02)

Found genuinely incomplete when auditing this milestone: the driver-side consumption + scrub half (`lego/agent-image/driver/src/credentials.mjs`, `bex-pre-snapshot`, `credential-scrub-test.sh`) was already shipped and tested by an earlier session, but the upstream OpenBao-sourcing half did not exist anywhere in `lego/backend` — `sandbox/service.go`'s agent-session create path passed a literal `nil` env, so no code path could ever get a tenant's model key into a real sandbox pod. Closed the gap:

- `internal/agentsessions/service.go`: added `Service.ModelKeys core.SecretKV` + `modelAPIKey(ctx, workspaceID)`, fetched at `Create()` time from a workspace-scoped OpenBao path (`modelKeySecretPath`). Following `envgroups`' own precedent (a different package sharing the same `core.SecretKV` store, which bakes its own opaque `envg-<xid>` id into the path rather than using `secrets` package's private `withTenant` context mechanism), the path bakes the workspace id (`tea-<xid>`, equally opaque/unguessable) directly in: `agent-sessions/<workspaceID>/model-key`.
- `internal/sandbox/service.go`: added `sandbox.ModelAPIKeyEnvVar` (= `BEX_AGENT_MODEL_API_KEY`, matching the driver's own env var name exactly, no translation needed), threaded a new `modelAPIKey` parameter through `CreateAgentSessionSandbox` → `createResolved` → the real `env` map → `Client.Create` (previously hardcoded `nil`).
- `internal/api/server.go`: wired `ModelKeys: d.Secrets` (the existing OpenBao store, already used by the env-vars feature) into the `agentsessions.Service`.
- A missing key is not an error (`core.SecretKV.Get`'s documented not-found behavior returns `""`, common case until a workspace provisions one); a genuine OpenBao failure fails the create closed (`core.ErrSecretsUnavailable`) rather than silently starting a session the agent can never authenticate from.
- Resume needs no separate re-injection path: OpenSandbox resumes the same pod, whose k8s-level env (set once at create) persists independent of the rootfs snapshot the pre-snapshot hook scrubs — confirmed by reading `AgentSessionLifecycle.ResumeAgentSessionSandbox`, which calls `Client.Resume(ctx, key, sandboxID)` with no env parameter at all.
- v1 provisioning of the key itself is operator/manual (`bao kv put`) — no REST/GraphQL/MCP surface was added, consistent with this milestone's explicit no-API-surface scope (that's `w3/m39`'s and later milestones' territory if a self-serve UI is ever wanted).
- Tests: `internal/agentsessions/service_test.go` (`TestCreateInjectsWorkspaceScopedModelKey` — proves per-workspace isolation, not just presence; `TestCreateWithNoProvisionedModelKeyStartsAnyway`; `TestCreateFailsClosedOnModelKeyStoreError`) and `internal/sandbox/agent_session_test.go` (extended `TestAgentSessionLifecyclePreservesReservedMetadata` to assert the key lands in pod env and never in metadata; added `TestAgentSessionLifecycleSendsNoEnvWithoutAModelKey`). Full backend suite green.

## Objective

Wire ADR047 D7's v1 credential model: the tenant's model API key is stored in OpenBao (ADR013 pattern), injected into the sandbox at session start as the agent's provider credential, and scrubbed before any rootfs snapshot so a resumed/hibernated sandbox never carries it at rest (D2 snapshot hygiene).

## Context

- OpenBao tenant secret store: `BEX_OPENBAO_URL`, k8s-auth scoped to `tenants/*` (docs/ADR013-secrets.md); env-vars verbs in `lego/backend/internal/` show the read pattern.
- w3/008 (inbox) flags injecting reusable tenant credentials into sandboxes — the accepted mitigations are exactly this task's scrub + w3/m40's model-endpoint-only egress; note the residual in the session docs.
- Injection shape: env var (e.g. `ANTHROPIC_API_KEY`) or agent config file, per chosen agent binary.

## Steps

1. Define the OpenBao path convention for per-workspace agent model keys + a bex-api read at session create (coordinate with w3/m39's create path — a stub env injection is fine until m39 lands).
2. Driver/entrypoint: place the key for the agent process only (env of the spawned child, not a file).
3. Scrub hook: before hibernate/snapshot, remove the key from any persisted location; on resume, re-inject via the same path.
4. Verify a committed snapshot image contains no key material (grep the exported rootfs layer).
