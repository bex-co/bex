## Objective

The cache process keeps entries on its tier's bounded disk with the capacity and object cap t001 chose, so it survives the app's restarts and holds objects far above today's 6 MiB.

## Context

- `lego/operator/internal/edgecache/edgecache.go` (in-memory LRU, `MaxBytes`, `MaxObjectBytes`), `lego/operator/cmd/edge-cache/main.go`.

## Steps

1. Add a disk-backed store behind the existing lookup/store interface, bounded by bytes and by the `emptyDir` `sizeLimit`.
2. Keep the in-memory index bounded; evict from the cold end as today.
3. Unit tests for eviction, the object cap and a restart of the cache process.

- lego/operator/internal/edgecache/, lego/operator/cmd/edge-cache/main.go

## Record (2026-11-19)

Done. `internal/edgecache` keeps bodies as files under `Config.Dir` when set. Fills stream to temp files up to `MaxObjectBytes`. `MaxBytes` bounds the stored bodies, charged in 4 KiB blocks; `MaxIndexBytes` bounds the in-memory metadata (default `MaxBytes/32`). Eviction runs from the cold end and removes the file. A hit opens its file under the lock, so an eviction cannot unlink it first. `New` empties the directory, so a restarted process starts empty. `cmd/edge-cache` reads `BEX_EDGE_CACHE_DIR`, `_MAX_OBJECT_BYTES` and `_MAX_INDEX_BYTES`. The tier runs 1 GiB and 128 MiB. Tests (`edgecache_disk_test.go`): round trip, eviction by disk bytes and by index bytes, an over-cap body served but never stored, a purge removing every file, a fill across a purge leaving none, a restart starting empty, a body that will not open becoming a miss, a hit evicted while it streams, and 304s from disk. The peer fill is in `peers.go` (`TestATierFillsEachKeyOnceThroughEitherReplica`, the fallback and hop-trust tests). `go test -race` passes.
