## Objective

Add one Postgres-scoped core query that authorizes and fetches the Database
through the shared seam, then reads attributed log history from Loki or a
documented live-pod fallback without making the domain clientset-dependent.

## Acceptance criteria

- [x] Range/search/limit validation is shared and honest; tenant/database
      attribution and configured-store degradation have focused tests.

## Completion

`QueryLogs` now dispatches typed Postgres resources through
`AuthorizeDatabase(can_view_logs)` before building an exact
`{namespace,database}` Loki selector or `cnpg.io/cluster` pod selector. The
fallback reads only the `postgres` container; range/text/direction/limit/instance
share the existing query machinery, while service-only filters are named 400s.
