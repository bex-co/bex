## Objective

A session an automation starts is counted as `automation`, not `unknown`, so the surface panels do not under-count agent-driven work.

## Context

- The ADR101 scheduler calls `Service.Create` with no HTTP request, so `ProductSurface` returns `unknown` today.
- Precedent: `core.WithBlueprintApply` (`product_surface.go`) makes a Blueprint apply win over its trigger.

## Steps

1. Add `core.WithAutomationFire(ctx)` and give it precedence right after the Blueprint rule in `ProductSurface`.
2. Mark the scheduler's create context with it. A child session an agent starts through MCP stays `mcp`.

## Acceptance criteria

- [x] A test fires an automation and the session's row has surface `automation`.

## Result (2026-11-17)

`core.WithAutomationFire` ranks right after the Blueprint rule in `ProductSurface`. `decideAutomationRun` marks the context for the scheduler's fire and a member's run-now alike. Deviation: an in-sandbox child (`spawn_session` on the sandbox's `bex` MCP server, relayed by the gateway to bex-api's internal listener, which records no request origin) read `unknown`; `SpawnSession` now marks it `mcp`, so "a child an agent starts through MCP stays `mcp`" holds. `TestAutomationFiredSessionsAreAttributedToTheAutomation` (scheduled fire and run-now over MCP), `TestSpawnedChildIsAgentWorkOverMCP` and `TestAutomationFireOutranksItsTrigger` fail without the change.
