## Objective

Implement the captured neutral model for a failure-only workspace default plus an inheritable per-service notification policy. Reconcile the pending `0032_notification_failure_only` migration and preserve intentional existing customizations while moving untouched all-enabled defaults to failure-only.

## Context

- Current member defaults live in `internal/notifications.defaultSettings` and `internal/store.ListNotifyRecipients`.
- Current per-service failure behavior lives in `App.spec.notifyOnFail`; it cannot independently represent all lifecycle choices.
- The operator must remain mechanism-only; notification policy belongs to bex-api/types and the control-plane projection.

## Steps

1. Add the captured policy type and persistence/projection fields.
2. Make failure-only the effective default for unconfigured workspaces/services.
3. Migrate legacy defaults and map existing explicit overrides according to t001.

## Files

- `lego/types/v1alpha1/app_types.go`
- `lego/backend/internal/store/`
- `lego/backend/internal/notifications/`
- `lego/backend/internal/store/migrations/`
- `lego/operator/config/crd/`

## Acceptance criteria

- [ ] A service with no explicit override resolves to failure-only.
- [ ] Every explicit policy round-trips through storage/projection.
- [ ] Legacy customized settings retain the t001-defined meaning after migration.

## Out of scope

- Notification channels other than email.
