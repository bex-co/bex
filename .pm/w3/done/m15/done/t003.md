## Objective

Apply one effective-policy decision to every deploy notification seam so `all`, `failure`, `none`, and inherited failure-only behavior match their labels. Default services must never emit start/success email and must still emit actionable failure email.

## Context

- Start mail is emitted from request-time API/deploy-hook and signed git-webhook paths.
- Success/failure mail is emitted by `store.Reconciler.DeployNotifier` when a deploy row closes.
- Policy resolution must not add blocking identity/SMTP work to request or reconciliation hot paths.

## Steps

1. Centralize effective-policy resolution.
2. Thread policy context through both start and close notification seams.
3. Preserve best-effort asynchronous fan-out and per-service compatibility behavior.

## Files

- `lego/backend/internal/notifications/service.go`
- `lego/backend/internal/apps/`
- `lego/backend/internal/deploys/`
- `lego/backend/internal/store/reconciler.go`

## Acceptance criteria

- [ ] A decision-table test proves every policy against started, succeeded, and failed events.
- [ ] The inherited failure-only case sends exactly one failure email and zero routine emails.
- [ ] Repeated reconciles do not duplicate terminal notifications.

## Out of scope

- Diagnosing or suppressing the deploy trigger itself.
