## Objective

Mint an HMAC session ticket at session create/attach on the web-shell design (ADR047 D3): HMAC-SHA256 with a secret shared only with the isolated gateway, DB-backed single-use nonce (long-lived stream), short expiry, claims binding subject + sandbox pod + workspace — returned with the gateway origin so wave-2 attach needs no bex-api change.

## Context

- Precedents: `BEX_SHELL_TICKET_SECRET` (w2/m55, ADR035 § Browser Web Shell — DB-backed nonces) and `BEX_SANDBOX_EXEC_SECRET` (w3/m33, signed argv tickets) in `lego/backend/internal/sandboxexec/ticket.go` + sshgateway counterparts.
- New env pair (e.g. `BEX_AGENT_SESSION_TICKET_SECRET` + gateway twin) following the either-unset ⇒ 503-verb convention; mirror in `.env.example` + CLAUDE.md env table.
- bex-api mints; only the gateway verifies — bex-api never gains `pods/exec` or sandbox network access.

## Steps

1. Ticket type + mint (claims, nonce row, expiry) reusing the sandbox-exec ticket toolbox where it fits.
2. Return `{ticket, gatewayOrigin}` from create/attach verbs (attach verb may be a thin re-mint).
3. Env plumbing + docs table rows.

## Files

- `lego/backend/internal/agentsession/`, `lego/backend/internal/sandboxexec/` (shared ticket helpers), `.env.example`, `CLAUDE.md`

## Acceptance criteria

- [ ] Ticket claims bind subject+pod+workspace; nonce is single-use; expiry enforced in tests
- [ ] Secret-unset path returns 503 on the ticket verb only
