## Objective

Model agent sessions first-class in OpenFGA (ADR047 gap 6): a session type related to its workspace so `can_operate`-class checks flow from workspace membership/roles, replacing the code-level-only authz pattern the sandbox feature used.

## Context

- FGA model + authz plumbing: docs/ADR012-auth.md, `lego/backend/internal/` authz packages; members/roles model from ADR024.
- Sandbox authz today is code-level (ADR047 gap 6 names this); sessions set the corrected precedent.
- Unset `BEX_OPENFGA_URL` ⇒ allow-all (existing dev behavior) — keep that consistent.

## Steps

1. Extend the FGA authorization model with the session type + relations (viewer/operator derived from workspace roles).
2. Write tuples on session create; delete on session delete/workspace prune.
3. Wire `AuthorizeAgentSession`-style helper used by t003's verbs.

## Files

- FGA model definition + `lego/backend/internal/` authz package, session service

## Acceptance criteria

- [ ] Cross-workspace get/cancel denied by tuple check (test with two workspaces)
- [ ] Allow-all fallback preserved when FGA unset
