# 079 — The Edit view modal's Instance values are typed; offer the instances the project's resources have run

Why: Render's Edit view picks a filter's values from dropdowns, and its search box already suggests "the instances seen" (`docs/render-artifacts/project-observability.md`); bex's modal (w3/m507) asks for an instance id to be typed, which nobody remembers.

- **Source:** w3/m507 t003 asked for value pickers "fed by the project's environments, resources, levels and instances". The modal shipped with Environment, Resource, Resource Type, Level, Method and Time Range picked from lists, and Instance, Text Search, Status Code, Host and Path typed (`dashboard/src/features/logs/components/edit-view-dialog.tsx`, `TypedValues`), recorded as bex's choice in ADR032 § Project observability views.
- **Gap:** `logLabelValues(resource, label: "instance")` answers one resource at a time (`lego/backend/internal/logs/service.go`, `LogLabelValues`); there is no project-scoped read of the instances a view's resources produced.
- **Done when:** the Instance picker lists the instances the project's resources produced in the log store's window (a project-scoped label-values read, bounded like the project log read, or the per-resource read fanned out over at most 20 resources), each labeled with its resource, and a typed value is still accepted for an instance that has gone. Tests cover the read's scope and authorization and the picker. ~1h.

**DONE 2026-11-20.** GraphQL `logLabelValues` takes `project`, `filterDocument` and `type` instead of `resource`, as `logs` does and as Render's `logValues(input: {label, logQuery: {project, …}})` reads: `queryProjectLabelValues` (`lego/backend/internal/logs/project.go`) resolves and authorizes the view's scope as a page read does (at most 20 resources, none the caller may not read named) and fans the per-resource `LogLabelValues` out over it eight at a time, so each instance id keeps its resource's id as its prefix. It answers every discoverable label, a datastore adding nothing to one its lines lack, so [w3/084](084.md) only wires its pickers to it (Path still needs its own discovery). The Edit view's Instance row is a picker (`DiscoveredValues`, `dashboard/src/features/logs/components/edit-view-dialog.tsx`) that lists the project's instances for the view's type over the last seven days, each named `<resource> · <short id>`, narrows them as you type, and adds a typed id for an instance that has gone; it says when the logs cannot be read or hold none. `project_values_test.go` covers the scope (every resource, a document's narrowing, Request Logs' web services), authorization (no log access reads nothing and asks the store nothing, a gone resource drops, a refused project), the refusals, every label and the store being off; the datastore skip fails its test when disabled. `edit-view-dialog.test.tsx`, `view-filters.test.ts` and `use-log-label-values.test.tsx` cover the picker. ADR010 § Project views, ADR018's Projects row and ADR032 record it. Not walked live: dev-3's fixture workloads were gone and the host was at load ~60; the per-resource read it fans out is the one production's Logs tab already serves.
