ADR047 phase 2's live-attach spine — deliberately **not** materialized until the phase-1 integration milestone (w3/m41) is done, so the stream/ticket contracts are fixed by working code first (user decision, `/pm-brainstorm` 2026-08-01).

Scope when promoted (~4h, a real milestone):

- Control-plane transcript tables + the gateway tee (ADR047 gaps 1+5): every session stream teed durably; required for `loadSession`-absent resume, multi-client attach, evidence, audit.
- Gateway third listener (web-shell pattern): verify the m39 HMAC ticket, claim the DB nonce, reverse-proxy **both** driver streams (SSE UI-message + raw-ACP WebSocket) — same shape as the sandbox-exec SSE path, no protocol bridging. **Bound by ADR047 D3's verbatim-forward guarantee (added 2026-08-02):** byte-transparent, `x-vercel-ai-ui-message-stream: v1` preserved + CORS-exposed to the dashboard origin, additions limited to auth/tee/replay-splice — the Vercel-AI-SDK-compatible stream the driver already serves must reach `useChat` unmodified.
- Reattach: transcript replay then live; multi-client fan-in semantics are bex-defined (ACP leaves them open).
- Native ACP IDE attach (phase 2+) folds in here — the raw-ACP listener proxied through the same ticket path.
- **D9-exposed API gaps (added 2026-08-02, ADR047 § D9 + Consequences #8)** — the dashboard design pass surfaced three backend gaps this milestone must also close: a **ticket-only attach verb** for running sessions (today only create/resume/steer mint, so a page reload on a running session cannot reattach), **per-turn history** (`turns` is a bare integer counter — steering prompts and prior-turn evidence are not stored), and optional **+/− diff stats in evidence** for the PR card.
- **Target API shape (decided 2026-08-02, ADR047 § D9 "Target API shape")** — binds this milestone's deliverable:
  - **Public origin**: the stream endpoint publishes as `api.bex.co/v1/agent-sessions/{id}/stream`, with the platform edge routing that path to the **gateway process** (deliberate, documented exception to "everything on the API origin is served by bex-api"; the gateway ignores cookies on this path — ticket is the only credential).
  - **One conversation endpoint, two modes**: `POST` = prompt turn on a live session (verbatim-forward to the driver); `GET` = transcript replay + live tail, and for **terminal** sessions replay-only then `[DONE]` — this replay mode **is** the transcript-read API (an optional JSON transcript read for MCP/REST parity may be added).
  - **Steer absorption**: live steering becomes the chat `POST`; the `steer` verb narrows to idle-session redispatch and is slated for deprecation into `resume` + chat POST (MCP `steer_agent_session` survives as a one-shot alias).
  - When transcript replay lands, delete the phase-1 interim client-side prompt persistence in the dashboard (`w1/m64` t002).
