# Reduce the shared sandbox control-plane TCB blast radius to one workspace

Why: A compromise of a shared sandbox control-plane identity currently reaches every provisioned workspace sandbox namespace, so Kubernetes does not provide post-compromise tenant containment at that layer.

**Type:** security residual / architecture follow-up. **Not an m35 closeout gate** because m35's frozen contract explicitly treats the shared lifecycle server/controller/exec gateway as trusted components and promises platform/cluster containment, not per-workspace containment after their compromise.

The m35 RBAC design binds the same `opensandbox-server`, `opensandbox-controller-manager`, and `bex-ssh-gateway` ServiceAccounts into every provisioned `<ws>-sandbox`. Kubernetes correctly limits each RoleBinding to its namespace, but permissions aggregate for the shared identity. A compromise can therefore operate across all provisioned sandbox namespaces within that identity's verbs; the server can exec/read logs, the controller can create gVisor Pods/Jobs and mount namespace-local PVCs, and the gateway can `pods/exec` after bypassing its own ticket verifier. Cilium identity policy, short-lived signed tickets, egress confinement, and the Pod admission boundary limit normal access and cluster escape, but do not restore cross-tenant confidentiality after a shared trusted component itself is compromised.

Investigate before promoting:

1. Upstream support for per-request Kubernetes impersonation or a namespace-scoped credential/provider hook.
2. A narrow broker that exchanges the already-authenticated workspace key for a short-lived, audience-bound ServiceAccount token scoped to one namespace.
3. Per-workspace lifecycle/controller identities without one always-on deployment per tenant; quantify informer and controller scale costs.
4. Whether the shared ssh-gateway can exchange each signed command ticket for a short-lived, namespace-bound Kubernetes credential instead of aggregating permanent RoleBindings.

Promote when the sandbox service moves beyond early access, a compliance tenant-containment requirement lands, or upstream adds a usable identity hook. Evidence for completion must exploit a test server/controller identity for workspace A and prove Kubernetes itself denies access to workspace B—not merely that normal application code chooses A.

Source: m35 attacker-perspective review, 2026-07-28; documented in ADR042 D4.
