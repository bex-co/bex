## Objective

Let tenants widen a session's agent-phase egress with an explicit allowlist at session create (Codex opt-in pattern, ADR047 D5): an API field (coordinated with w3/m39's create surface) whose FQDN entries render into the sandbox's policy on top of the baseline; invalid entries are a named 400, never silently ignored.

## Context

- Nothing-accepted-is-ignored is a house rule (w3/m8 precedent: store-only filters 503, unknown values 400).
- Validate entries (FQDN shape, no wildcards beyond what Cilium `matchPattern` supports, deny-listed internal/metadata ranges stay non-overridable — m31/m35 cluster-wide egressDeny is a floor the tenant cannot lift).

## Steps

1. Field schema + validation in the session create path (m39 contract).
2. Render extra FQDN entries into the agent-phase profile.
3. Guard: platform deny floors (node/metadata CIDRs) remain enforced regardless of tenant entries.

## Files

- `lego/backend/internal/agentsession/` (field), `lego/backend/internal/sandbox/` (rendering)

## Acceptance criteria

- [ ] Widened destination reachable only in sessions that requested it; invalid entry → named 400
- [ ] Metadata/node deny floor unaffected by any tenant entry

## Out of scope

- Content-aware egress / DLP (`.pm/w3/008.md` residual)
