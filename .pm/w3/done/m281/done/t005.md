## Objective

In the dashboard, show create and move actions that target a protected environment as disabled with a localized, keyboard-reachable reason for non-Admins, using the same effective relations as the API.

## Context

- Role-aware controls pattern from w9/m84 and w6/m143 (ADR018 line 55)
- `dashboard/AGENTS.md` skeleton and i18n rules (en/zh)
- **Result (2026-11-07):** a new `useProtectedPlacement` hook (`features/environments/hooks/`) restricts placements for a confirmed non-Admin only (`loaded && !canManage`). Gated controls:
  - `ProjectEnvironmentSelector`, used by the service, Postgres and Key Value create flows: a protected option shows "(admins only)" and is disabled, and the reason is the trigger's `aria-describedby`.
  - `ScopeSelect`, for env-group create, Move and same-workspace Clone.
  - An env group's Move menu item, when its current environment is protected (`PermissionMenuItem`: focusable, with a tooltip reason).
  - An environment card's Manage resources and bulk Move, when the environment is protected, plus protected destinations in the card's move picker.
  - Move to project, when the resource is in a protected environment.
  A raced 403 renders the same localized reason through `placementErrorMessage`, used by the create, move, env-group, environment-membership, project-move and recovery hooks. New en/zh keys: `environments.protectedPlacementAdminOnly`, `environments.protectedOptionAdminOnly`. There is no route skeleton change. The only new element is a reason line that appears after the data loads. Not visually verified in a browser.

## Steps

1. Find the create wizards' environment pickers and the move/assign dialogs.
2. Disable protected targets for non-Admins with a reason string (en/zh).
3. Handle a 403 from the API with the same message.
