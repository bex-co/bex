## Objective

Make Blueprint validate/plan/sync and Postgres recovery refuse a non-Admin placing resources into a protected environment, with the refusal shown in the plan rather than failing halfway through a sync.

## Context

- Blueprint create path: `internal/apps/deploy.go:3747`
- Recovery: `internal/postgres/recovery.go:369`
- **Result (2026-11-07):** `apps.blueprintProtectedPlacementProblems` (new `blueprint_protected_placement.go`) checks every declared service, Postgres, Key Value and env group against the workspace's environments. It flags any that the sync would create in, or move into or out of, a protected environment, including one the manifest itself declares protected. When there is at least one, it checks the caller's fresh `can_manage`. Validation (`blueprintValidationFor`, which feeds the plan and pre-sync preview) returns them as located entries coded `PROTECTED_ENVIRONMENT_ADMIN_REQUIRED`. `deployParsedStack` refuses with the first one before `applyBlueprintGroupings`, so nothing is written. A resource the sync leaves in place passes: the re-apply uses `core.ResolveEnvironmentMembership`, and `MoveEnvGroup` skips the check for a group that stays, per Render's Blueprint exception. Env-group placements are read through `envgroups.GroupPlacements`, a wired function so the verb sweeps do not count it. Recovery: `postgres.sourceEnvironment` goes through the gated resolver. Decision: the auto-sync worker has no identity, so its sync that creates in a protected environment is refused, as the exit guard already refused its moves out. An Admin's manual sync applies it. Tests: `TestBlueprintPlacementIntoAProtectedEnvironmentNeedsAnAdminPG`, `TestBlueprintProtectedPlacementTruthTable`, `TestRecoveringIntoAProtectedEnvironmentNeedsAnAdmin`.

## Steps

1. Surface the refusal at plan time for a non-Admin.
2. Make sync refuse before any write.
3. Cover recovery into a protected environment.
