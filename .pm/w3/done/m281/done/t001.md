## Objective

List every way a Service, Postgres, Key Value or environment group lands in, or leaves, an environment, and record which check guards each today, so t002–t004 cover all of them and nothing else.

## Context

- Render (https://render.com/docs/projects) restricts creating, moving and deleting a protected environment's resources to workspace Admins; `docs/ADR032-environments.md:81` cites it
- `core.ProtectedVerbRestricted` covers only delete, suspend, resume, take offline, shell (`lego/backend/internal/core/confirmation.go:92`)
- Create paths call `core.ResolveEnvironmentForCreate` with no protected check: `internal/apps/service.go:2129`, `:2471`; `internal/apps/deploy.go:3747` (Blueprint); `internal/postgres/service.go:875`; `internal/postgres/recovery.go:369`; `internal/keyvalue/service.go:610`
- Environment `Set*` verbs go through `setResourceMembers` (`internal/environments/service.go:1209`), which runs `authorizeACLBearingMutation` only on the target environment; `SetEnvironmentID` on postgres/keyvalue/envgroups checks only `RelCanCreate`
- ADR018 row 225 records 'moving _into_ one stays `can_create` (Render: admin only)' with no user sign-off

Leaving a protected environment was already Admin-only on every writer through `loadExitGuard` (w4/m232), refused with a plain `FORBIDDEN`. The gaps were every **create** (resolver callers + env-group create/clone), **`MoveEnvGroup`'s target**, and the **Blueprint** datastore/env-group paths, which have no resolver. The per-resource `SetEnvironmentID` writers are reached only through the environments feature, which already gates the target.
