## Objective

Add `create` to the protected restricted verbs and make `ResolveEnvironmentForCreate` (or its callers) refuse a non-Admin with 403 when the target environment is `protectedStatus=protected`, on Service, Postgres, Key Value, recovery and env-group create.

## Context

- `core.RequireEnvironmentAdmin` / `ProtectedVerbRestricted` in `internal/core/confirmation.go`
- `authorizeACLBearingMutation` uses `AuthorizeFreshOn(ctx, core.RelCanManage, core.WorkspaceObject(...))` (`internal/environments/service.go:1346`)
- Render's 403 shape for an insufficient role is the existing protected-verb refusal
- **Result (2026-11-07):** `core.ProtectedVerbRestricted` now lists `create` and `move`. `core.ResolveEnvironmentForCreate` runs the resolver's optional `core.EnvironmentPlacementGuard` after its lookup. `environments.NewCreateResolver` implements it as a fresh workspace `can_manage` check on a protected environment, refused with the coded 403 `PROTECTED_ENVIRONMENT_ADMIN_REQUIRED` (`core.ProtectedPlacementRefusal`, `core.PlacementRefusal`). Every create inherits it: service create and dry run, Postgres, Key Value, recovery, and env-group create and clone (`envgroups.validateEnvironment` now resolves through the same resolver, wired in `api/server.go`). An unprotected environment, no environment and an authz outage are unchanged. Tests: `TestCreatingInAProtectedEnvironmentNeedsAnAdmin`, `TestAnAuthzOutageOnAProtectedCreateIsNotARoleRefusal`, `TestProtectedEnvironmentPlacementNeedsAnAdminOnEverySurfacePG` (REST, GraphQL and MCP for all four kinds).

## Steps

1. Add `create` to `ProtectedVerbRestricted` and update its comment.
2. Apply the check at the single resolution point so every create caller inherits it.
3. Keep non-protected environments and the default (no environment) path unchanged.
