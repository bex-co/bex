## Objective

Implement the git credential helper that lives in the agent template image: on each git credential request it fetches a fresh token from the gateway's t002 endpoint and emits it to git over stdout — the token exists only in process memory for the duration of the git operation, never in `.git-credentials`, gitconfig, or any file (ADR047 D2).

## Context

- Install path + `credential.helper` wiring contract was reserved in w3/m37/t001 — land the real binary/script there.
- git credential-helper protocol: `get`/`store`/`erase` on stdin/stdout; implement `get`, make `store`/`erase` no-ops.
- Failure mode: gateway unreachable → helper fails loudly (git error), never falls back to cached material.

## Steps

1. Write the helper (small static Go binary or script) speaking the credential protocol against the gateway endpoint.
2. Wire it into the template image gitconfig (`credential.helper` + `credential.useHttpPath`).
3. Verify clone + push in a live sandbox; verify no token lands on the filesystem (fs scan post-op).

## Files

- new helper under `lego/agent-image/` (or `lego/backend/cmd/` if a Go binary shared with the image build)
- `lego/agent-image/Dockerfile` (install + gitconfig)

## Acceptance criteria

- [x] Clone/fetch/push work end-to-end via the helper in a live agent-image container
- [x] Filesystem scan after operations finds no token material

## Verification

`lego/agent-image/credential-e2e-test.sh` runs the built agent image against a hermetic GitHub-compatible smart-HTTP origin. On 2026-08-01 it cloned, pushed, and fetched through the installed helper, with a post-operation scan of `/home/bex`, `/workspace`, and `/tmp` proving the fixture token prefix absent.
