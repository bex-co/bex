## Objective

Verify the new events are consistent everywhere they surface (webhook payloads, and whether the events feed / audit log should mirror any of them the way Render does); compare payload fields against Render's documented shapes; file follow-ups for drift.

## Acceptance criteria

- [x] Payload-shape comparison recorded; drift filed, not silently accepted.

## Completion

The contract capture records Render's thin `{type,timestamp,data:{id,serviceId,serviceName,status?}}` shape. Datastore events carry no `status`; bex uses immutable datastore ids and captures the display name at transition time. Availability/health/completion events remain an explicit source gap because the operator has no control-plane event channel. Generic datastore `plan_changed` is identified as an inference from Render's shared instance-type semantics, not misrepresented as datastore-specific prose.
