## Objective

Register the t001 event types in the webhook service and emit them from the datastore lifecycle paths: create (and reaching available), suspend/resume, delete, and plan change where Render has a type for it — for both managed Postgres (`internal/postgres`) and Key Value (`internal/keyvalue`).

## Context

- Emission pattern: how the service/deploy families publish events through `internal/webhooks` today (see w3/m11's wiring).
- Lifecycle write points live in the postgres/keyvalue core services; status transitions (e.g. available) may come from the projector/status sync.

## Steps

1. Add the types to the registry (`webhooks/service.go`).
2. Publish at each lifecycle write/transition with Render-shaped payloads (t001 fields).
3. Walk one full lifecycle with `scripts/webhooks-verify.sh` (or a local sink) and capture the deliveries.
4. `cd lego/backend && go build ./... && go test ./...`.

## Files

- `lego/backend/internal/webhooks/service.go`
- `lego/backend/internal/postgres/`
- `lego/backend/internal/keyvalue/`

## Acceptance criteria

- [x] Each sourceable lifecycle verb produces exactly one post-success effect of the Render-named type with the documented payload.
- [x] No emissions for internal-only transitions Render doesn't publish.

## Out of scope

- New delivery/retry machinery (m11's is reused untouched).

## Completion

Shipped fixed audit effects for `postgres_created`, `postgres_restarted`, `postgres_credentials_created`, `postgres_credentials_deleted`, `postgres_backup_started`, and generic `plan_changed` for services/Postgres/Key Value. The worker continues to consume its existing durable `deploys` + `audit_events` feed; no parallel publisher or retry path was added. Failed validations/writes and unrelated datastore PATCHes do not map to webhook deliveries.
