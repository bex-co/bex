# Blueprint build sources: buildSources-only projects and non-literal build-time env vars

Why: w3/m270 brought Blueprint `buildSources` to Render parity except two edges, recorded in ADR018 row "Blueprint Build Sources" and ADR097 § Blueprints, which still diverge from Render's schema.

- **A project holding only `buildSources`** (no `environments`, which Render's 2026-10 schema allows) is still refused with `BLUEPRINT_PROJECT_ENVIRONMENTS_REQUIRED` (`lego/backend/internal/apps/blueprint_compiler.go` `blueprintProjectEnvironmentsProblems`). bex materializes a project from its environments (`applyBlueprintGroupings`), so the carrier's project scope has no project to land in. Fix: let the grouping apply create an environment-less project when it scopes build sources, then drop the refusal for that case.
- **Build-time env vars take literal values only** (`blueprintBuildSourceEnvError` in `blueprint_build_sources.go`): `fromDatabase`/`fromService`/`fromGroup`/`generateValue`/`sync: false` are refused by name on a build source. Check how Render treats them in a build source's `envVars` (the pinned schema admits every `envVar` form) before choosing: `generateValue`/`sync: false` likely seed the carrier's env store once, as for a service.
