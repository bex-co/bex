## Objective

Stand up a disposable k3s node (real containerd-CRI + Kata) and validate the BatchSandbox lifecycle + snapshot round-trip there — the gate the OrbStack mock can never close (ADR042 D6).

## Status: BLOCKED (partial — 2026-07-29)

Validated **directly on prod** (real containerd-CRI Hetzner node under gVisor, better than the k3s dev gate): `create` / `list` / `stop` round-trip cleanly in the per-tenant `<ws>-sandbox` namespace (see t006 evidence). **`pause`/`resume` is blocked**, and by a real architectural tension, not a config miss: the controller's snapshot **commit Job mounts the node `containerd.sock` via `hostPath`**, but `<ws>-sandbox` enforces PodSecurity **`baseline`** (no hostPath) → `FailedCreate … violates PodSecurity "baseline": hostPath volumes`, sandbox stuck `Pausing`. Documented in [ADR042 §D5](../../../docs/ADR042-sandbox-cluster-substrate.md). Unblocking needs the commit Job to run in a **dedicated privileged platform namespace** (an upstream OpenSandbox change) — relaxing the tenant PSS is rejected (it would dissolve the isolation floor for every untrusted sandbox pod). Also gated on t003 (snapshot registry push/pull secrets). Net: rootfs pause/resume is not available under the secure per-tenant topology in v1 — consistent with ADR042 marking snapshots a watch item.

## Context

- `scripts/mock-cluster.sh` is CAPD under OrbStack (cri-dockerd) — the k8s snapshot path is blocked there (ADR014 D5).
- DoD loop adapted from ADR014 §Verification.

## Steps

1. `scripts/k3s-sandbox-node.sh`: bring up k3s with containerd-CRI + kata-runtime.
2. Deploy the substrate (t002–t006) there; run the DoD loop: create → exec (stdout) → pause (snapshot) → resume (rootfs restored) → stop/delete, under Kata + the Cilium boundary.
3. Confirm rootfs-only semantics (memory does not survive pause in v1).
