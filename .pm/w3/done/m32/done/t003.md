## Objective

Switch the OpenSandbox snapshot registry from `127.0.0.1:5050` insecure to the in-cluster Zot + push/pull secrets, and stand up a warm `Pool` + in-cluster `execd` (ADR042 D1).

## Context

- Current values pin `snapshot.registry: 127.0.0.1:5050/snapshots`, `registryInsecure: true`; the chart's `snapshot.*` knobs are complete (no chart change needed).
- Push/pull secret pattern: `scripts/registry-secrets.sh` (`bex-registry-push` / `bex-registry-pull`); needs replicating into `opensandbox-system`.

## Steps

1. Set `snapshot.registry=zot.bex-registry.svc:5000/snapshots`, `registryInsecure=false`, `snapshotPushSecret`/`resumePullSecret` (replicate the dockerconfigjson secrets into `opensandbox-system`).
2. `imageCommitterImage` → Zot-hosted; `execd` image resolvable in-cluster.
3. Apply a warm `Pool` CR in `opensandbox-system`. ⚠️ Known limitation (ADR042 Consequences watch item): under per-tenant `<ws>-sandbox` scoping (t006), a tenant's create cannot draw from a pool in another namespace — this pool warms the dev/validation path only; a per-tenant (or claim-time-move) warm strategy is out of scope for v1.

## Files

- `deploy/gitops/base/values/opensandbox-controller.values.yaml`
- `scripts/registry-secrets.sh` (extend to mint `opensandbox-system` secrets)

## Acceptance criteria

- [ ] Snapshot push (pause) + resume pull round-trip through in-cluster Zot with auth.
- [ ] Warm `Pool` reconciles; `execd` reachable.

## Out of scope

- Kata (t004), the full lifecycle validation (t007).

## Deferred (descoped by the per-tenant architecture, 2026-07-29)

Both halves are blocked/mooted by the secure v1 topology, consistent with the m32 DoD amendment:
- **Snapshot registry** — moot: rootfs pause/resume is blocked by the baseline-PSS-vs-hostPath commit tension ([t007](t007.md), [ADR042 §D5](../../../docs/ADR042-sandbox-cluster-substrate.md)), so there is no snapshot push/pull to authenticate in v1.
- **Warm Pool** — no tenant-facing value: a `Pool` lives in one namespace, but per-tenant `<ws>-sandbox` scoping (t006) means a tenant create cannot draw from a pool in another namespace (the task's own ⚠️ note). A dev-only pool isn't worth the operational surface.
Both return when the snapshot/pool story is re-opened (future milestone). execd image is already wired in the cluster TOML.
