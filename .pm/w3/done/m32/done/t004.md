## Objective

Ship a `kata` `RuntimeClass`, bake `kata-containerd` into the worker image (CAPH), and add a dedicated tainted sandbox node pool — hypervisor-grade isolation for untrusted agent code (ADR042 D3; ADR043 D2).

## Context

- No `RuntimeClass` exists today; microVM tier deferred in `.pm/FUTURE-MAYBE.md` (trigger GA) — this milestone pulls it forward for sandboxes.
- Node pools declared in `infra/clusterapi/overlays/hetzner-caph/cluster.yaml` (platform / tenant / burst).

## Steps

1. `RuntimeClass` manifest (`deploy/gitops/base/`).
2. Bake `kata-containerd` into the worker image; add a `bex-sandbox` MachineDeployment (tainted `bex.co/sandbox=true:NoSchedule`, Kata-capable).
3. BatchSandbox template sets `runtimeClassName: kata` + `nodeSelector: bex.co/pool: sandbox` + `hostUsers: false` — this task **owns** the template edits (t005 only verifies them; the in-cluster mounted-ConfigMap form of the template ships via t002, and t007 validates the assembled result end-to-end).

## Files

- `deploy/gitops/base/` (RuntimeClass), `infra/clusterapi/overlays/hetzner-caph/cluster.yaml`
- `deploy/opensandbox/batchsandbox-template.yaml`

## Acceptance criteria

- [ ] A `kata`-scheduled pod runs inside a microVM on a sandbox-pool node.
- [ ] Sandbox pool is tainted (no platform/tenant pods co-locate).

## Out of scope

- The per-tenant `<ws>-sandbox` boundary policy (t005), the bex-api surface (t009).
