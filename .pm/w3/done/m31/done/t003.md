## Objective

Give the operator, bex-api, and ssh-gateway service accounts the authority to manage/reach workloads across every tenant namespace, replacing the single-namespace bindings in `default`.

## Context

- Today: `deploy/gitops/base/operator-apps-rbac.yaml` binds the operator SA in one namespace (`bex-operator-apps` RoleBinding), and `deploy/gitops/base/bex-ssh-apps-rbac.yaml` binds the ssh-gateway's discover/exec Role in `default` only (its `BEX_API_NAMESPACE` is "the one tenant App namespace" — SSH and the browser Web Shell break after migration if untouched).
- **Kubernetes RBAC has no namespace-label selector** (that's NetworkPolicy vocabulary): the choice is a cluster-wide ClusterRoleBinding vs per-namespace RoleBindings. A cluster-wide Secrets grant would reverse the deliberate least-privilege decision in `operator-apps-rbac.yaml` (the manager ClusterRole omits Secrets so a compromised operator can't read Kratos/Hydra/OpenBao/CNPG/GitHub-App credentials in platform namespaces). So: **per-namespace RoleBindings, stamped automatically by t001's namespace reconciler** — Secret access exists only inside tenant namespaces, and there is no manual churn because the reconciler owns them.
- `scripts/gitops-validate.sh` hard-asserts the old shape ("SSH gateway tenant Role must remain default-only") — its assertions move with this task, not silently after it.

## Steps

1. Define tenant-scope Roles (operator + bex-api: App/Database/KeyValue + pod/service/secret verbs; ssh-gateway: its discover/exec verbs) and have t001's namespace reconciler stamp the RoleBinding (+Role or ClusterRole ref) into each `<ws>`/`<ws>-sandbox` at namespace create.
2. Remove the single-namespace `bex-operator-apps` and `bex-ssh-gateway-apps` bindings in `default`; multi-namespace the ssh-gateway's `BEX_API_NAMESPACE` discovery.
3. Update `scripts/gitops-validate.sh`'s RBAC assertions to the new shape (per-tenant-namespace bindings; still **no** cluster-wide Secrets grant).

## Acceptance criteria

- [ ] Operator and bex-api can reconcile tenant workloads in any `<ws>` namespace; ssh-gateway can discover/exec there.
- [ ] RoleBindings are created/removed by the namespace lifecycle automatically (no manual per-workspace churn).
- [ ] The manager/bex-api ClusterRoles still carry **no** cluster-wide Secrets grant; `scripts/gitops-validate.sh` passes with the updated assertions.
