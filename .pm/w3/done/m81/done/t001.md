## Objective

Choose and document one coherent contract for tenant reads while an App deletion is finalizing, including the expected finalizer window and what tenants observe when teardown exceeds it.

## Context

- `apps.Service.List` hides Apps with a `DeletionTimestamp`, while `Get` still projects them as `Deleting` until the Kubernetes object disappears.
- The static-site S3-prefix cleanup can outlive route/certificate teardown, leaving by-id reads and the dashboard advertising a dead URL.
- Coherent options include immediate tenant-facing 404 after delete acceptance, or a visible bounded `Deleting` state with a terminal failure outcome. The decision must cover every tenant surface, not just the list.

## Steps

1. Compare Render's observed delete behavior and bex's current App finalizer sequence.
2. Select the tenant read contract and state its timeout/terminal semantics.
3. Record how list, by-id children, dashboard, URL projection, audit/operator alerts, and quota accounting relate during finalization.
4. Update the relevant ADRs before implementation so t002/t003 share one target.
