# GraphQL `metrics` names a status-code series `code`; REST, MCP and `projectMetrics` say `statusCode`

Why: one breakdown should read the same on every surface, and Render's own vocabulary for it is `statusCode` (its REST `aggregateBy` value and `filters/http` field).

Found by w3/m508's parity check (2026-11-19). A per-status breakdown of `http_requests` carries its code under `statusCode` on REST `GET /v1/metrics/http-requests?aggregateBy=statusCode` and MCP `get_metrics` (`renderStatusCodeLabel`, `lego/backend/internal/metrics/render.go`), and on GraphQL `projectMetrics(groupBy: STATUS_CODE)` (`lego/backend/internal/metrics/project.go`), but GraphQL `metrics(aggregateBy: ["STATUS_CODE"])` still answers the source's `code` label (`graphql.go` never renames it). The service Network card reads `labels["code"]` (`dashboard/src/features/metrics/components/network-metrics-card.tsx`, `groupLabel`).

Done when GraphQL `metrics` labels the breakdown `statusCode` like the other surfaces (or ADR010 records why it keeps `code`), the Network card reads the new label, and a test pins the label on all four surfaces. Render's own GraphQL label was not captured; check the capture before choosing.

**DONE 2026-11-20.** Checked the capture first, as asked: Render's GraphQL had not been captured, so w3/080 read Render's public dashboard bundle ([metrics-page.md § Status-code label](../../../docs/render-artifacts/metrics-page.md#status-code-label-w3080-2026-11-20)). Render's GraphQL `MetricResultLabel.field` is its `MetricQueryFilter` enum, and its service Metrics page finds a status line's code with `labels.find(l => l.field === "STATUS_CODE")`. So each surface now spells the code as Render's same surface does, rather than all four saying `statusCode`. REST and MCP keep `statusCode`. GraphQL `metrics(aggregateBy: ["STATUS_CODE"])` renames the sources' `code` to `STATUS_CODE`, and `projectMetrics(groupBy: "STATUS_CODE")` moves from `statusCode` to `STATUS_CODE` (`nameStatusCodeLabel`, `lego/backend/internal/metrics/render.go`). The Network card and the project Service Metrics page read `STATUS_CODE`. `TestStatusCodeBreakdownLabelOnEverySurface` pins all four surfaces and fails on GraphQL `metrics` and `projectMetrics` with the fix reverted. The dashboard tests for both legends fail with the old label reads. ADR010 and ADR018 record the choice. The rest of the GraphQL label vocabulary (`resource`, `instance`, …) still uses REST's spelling: filed as [w3/087](../087.md).
