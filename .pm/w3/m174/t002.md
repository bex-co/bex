## Objective

Detect a dead alert path or a whole-cluster outage from outside the cluster, through GitHub's own notifications rather than SendGrid: a scheduled check that confirms `Watchdog` is firing, recent notifications are succeeding and the public API/dashboard answer, and opens one tracking issue when any of that fails.

## Context

- Pattern to copy: `ssh-edge-liveness.yml` (cron `:52`, open/update/close tracking issue `:101-128`) and `isolation-matrix.yml:53-85` (SSH key + known-hosts + kubectl from the self-hosted runner).
- ADR088:23,:220 name an "external uptime check" that does not exist; this task is it.
- Runners live on the operator's Mac (`#RUNNER-HOSTS`): an independent failure domain from the cluster, not from the operator.

## Steps

1. Write `scripts/alerting-heartbeat.sh`: via the same SSH/kubectl access as `isolation-matrix.yml`, query Alertmanager `/api/v2/alerts?filter=alertname="Watchdog"` and Prometheus for `increase(alertmanager_notifications_failed_total[1h])`; probe `https://api.bex.co` and `https://dashboard.bex.co` health; exit non-zero with a named reason per failure.
2. Add `alerting-heartbeat.yml` (self-hosted, environment per `w3/m173` if it has landed), hourly; open/update one tracking issue on failure and close it on recovery.
3. Register its window in `scripts/ci-schedule-drift.sh`.
4. Update ADR088 §1 to name this check.
