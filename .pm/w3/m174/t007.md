## Objective

Prove each new signal fires for its real failure on a running cluster, not only in rule tests.

## Context

- Use `dev-3` / the local CAPD mock cluster (pre-approved, `AGENTS.md`); never production for injection.
- The out-of-cluster check (t002) can point at the mock cluster's Alertmanager for this drill.

## Steps

1. Scale Alertmanager to 0 ⇒ the heartbeat check reports Watchdog absent (and opens the tracking issue, if run against a test repository/label); restore ⇒ it closes.
2. Suspend a `dskbak-*` CronJob (or shorten the threshold for the drill) ⇒ `BackupCronJobStale` fires.
3. Make a ScheduledBackup fail (bad ObjectStore reference on a scratch cluster) ⇒ the base-backup alert fires.
4. Create an unschedulable tenant pod (impossible request) ⇒ `TenantPodUnschedulable` fires after 10m.
5. Record timings and outcomes in `docs/drills/`; deploy the rules to production and record that `Watchdog` is firing there and the heartbeat workflow's first run is green.

## Files

- `docs/drills/<date>-silent-failure-alerts.md` (new)

## Acceptance criteria

- [ ] Each of the four injections recorded with the observed alert/issue and its latency.
- [ ] Production: `Watchdog` firing and the first scheduled heartbeat run green (run id recorded).

## Out of scope
