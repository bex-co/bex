## Objective

Make the conformance harness check every REST event's `details` against the oneOf member its `type` selects, instead of the union as a whole, so a renamed or mistyped key fails CI. It is expected to fail at first; t002–t004 make it pass.

## Context

- Pinned schema: `lego/backend/internal/api/openapi/render-public-api-1.json` (`/events/{eventId}` 200 → `details` oneOf, 47 members); member titles such as "Build Ended", "Instance Count Changed", "Server Failed".
- `lego/backend/internal/rendertest/rendertest.go` validates responses; `allowlist.go` excuses `list-events` and `retrieve-event` with `event/details: does not match the documented union` (row "Service event types and details").
- bex-named event types (w8/060 decision) have no Render member and stay excused by the `event/type` entry.

## Steps

1. Map each Render event type to its details member in the pinned schema (derive it from the schema, not a hand list).
2. In the validator, for an event whose type has a member, validate `details` against that member, with additional properties still allowed for bex extras.
3. Run `go test ./internal/api/... ./internal/apps/...` and record the failing types as the t002–t004 worklist.

## Files

- `lego/backend/internal/rendertest/rendertest.go`
- `lego/backend/internal/rendertest/rendertest_test.go`

## Acceptance criteria

- [ ] A `build_ended` details with string `status` fails the check
- [ ] An `instance_count_changed` details with `from`/`to` and no `fromInstances` fails the check
- [ ] bex-named types are not checked against a member

## Out of scope

- Changing any projection (t002–t004)
