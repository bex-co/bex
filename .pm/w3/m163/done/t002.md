## Objective

Turn the payment wall's self-host exit into a two-step flow: the wall's button opens a confirmation dialog, and only the dialog's confirm — gated on typing the account email — deletes the account and forwards to the self-hosting guide.

## Context

- `dashboard/src/features/onboarding/pages/payment-setup-page/index.tsx:53` documents the current exits ("self-hosting (the free path) and sign out"); the self-host exit is a plain link today.
- Existing test asserting the old behavior: `dashboard/src/features/onboarding/pages/payment-setup-page/__tests__/payment-setup-page.test.tsx:145,166` — expects a link named "Self-host bex instead". It must be updated, not deleted.
- The wall's skeleton must keep matching its ready state (repo rule; `dashboard/CLAUDE.md` § navigation pending states). `dashboard/src/common/components/route-skeletons.tsx:1141` explicitly models the self-host/sign-out footer — if the footer's height or structure changes, update the skeleton in the same change.
- Account deletion already exists server-side and is asynchronous (`account_deletions`, observed state `done`); reuse it rather than adding a path.

## Steps

1. Replace the link with a button that opens a confirmation dialog, using the repo's existing dialog primitives.
2. Gate the destructive confirm on the typed account email; keep it disabled until the input matches.
3. On confirm: call the existing account-deletion verb, then forward to the self-hosting guide. Surface a real error state if deletion fails — never forward as if it succeeded.
4. On dismiss: change nothing.
5. Update the skeleton if the footer's geometry changed, and verify pending and ready side by side at desktop and narrow-mobile widths.
6. Update the existing test to the new flow.

- [x] The wall cannot delete an account in one click — the dialog is always interposed.
- [x] The confirm control stays disabled until the typed email matches exactly.
- [x] Dismissing leaves the account intact and returns to the wall.
- [x] A failed deletion shows an error and does not navigate away.
- [x] Skeleton and ready state match at desktop and narrow-mobile widths.
