## Objective

Implement the Codex-style phase split (ADR047 D5): the session sandbox's egress policy differs by phase — setup (clone + dependency install) may reach package registries; the agent phase gets the narrow baseline. The phase transition is driven by the session lifecycle (setup completes → policy swaps), fail-closed.

## Context

- Policy machinery: w3/m35's per-sandbox `default-deny` + fail-closed Cilium DNS/FQDN/SNI CiliumNetworkPolicies (rendered by the backend/reconciler for `<ws>-sandbox`); see `lego/backend/internal/sandbox/` policy rendering + `deploy/gitops/` for the platform pieces.
- Phase state lives on the m39 `agent_sessions` store; until m39 lands, drive the swap from a sandbox label/annotation contract agreed with m39.
- Registry set for setup: npm/PyPI/Go proxy/crates + GitHub — a curated FQDN list, config-driven.

## Steps

1. Define the two policy profiles (setup, agent) as rendered CNP variants keyed by a sandbox phase label.
2. Swap mechanism: label update → policy re-render; verify the swap is race-safe (deny during transition, never allow-all).
3. Config knob for the setup registry list.

## Files

- `lego/backend/internal/sandbox/` (policy rendering), `deploy/gitops/` if platform-side pieces move

## Acceptance criteria

- [ ] Setup-phase sandbox reaches a registry; same sandbox post-transition is denied
- [ ] Transition window never widens policy
