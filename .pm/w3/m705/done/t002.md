## Objective

Map Render's sandbox group URLs onto bex's sandbox group pages and drawers.

## Context

- Render: `/sandbox-group/${e}`, `/sandbox-group/${e}/sandboxes`, `/sandbox-group/${e}/*`, `/sandbox-group/new`. Read the sandbox-group layout's `hrefPatterns` for the remaining sub-paths (snapshots, builds, settings, a sandbox's or a snapshot's own path).
- bex: `routes/sandbox-groups_.$sandboxGroupId.{index,images,settings,snapshots}.tsx`; drawers by `?sandbox=` / `?tab=` (`docs/render-artifacts/sandbox-groups.md` § The dashboard, w1/m658 kept bex's paths with drawers as search params); `NewSandboxGroupDialog` on `sandbox-groups.tsx`.

## Steps

1. Record Render's sub-paths from the bundle in `sandbox-groups.md`.
2. Add `routes/sandbox-group.$.tsx`: the bare id and `sandboxes` to the index, `sandboxes/<sbx-id>` to the index with `?sandbox=`, `snapshots[/<snp-id>]` to snapshots (with its drawer param if one exists), `builds` to `images`, `settings` to settings, `new` to the list with the create dialog open from a search param.
3. Keep query and hash; an unknown sub-path lands on the group's index.

## Files

- `dashboard/src/routes/sandbox-group.$.tsx` (new), `sandbox-groups.tsx`
- `docs/render-artifacts/sandbox-groups.md`

## Acceptance criteria

- [x] Each Render sandbox-group path recorded in step 1 opens the matching page or drawer.

## Out of scope

- Changing bex's own sandbox group paths.
