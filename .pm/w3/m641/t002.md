## Objective

On every `/databases/<id>/…` page, replace the workspace sidebar with a Postgres sidebar shaped like Render's, the way a service's pages already do.

## Context

- `common/components/dashboard-layout/dashboard-sidebar.tsx` swaps in `ProjectSidebar` for a `projectId` and `ServiceSidebar` for a `serviceId`. `service-sidebar.tsx` (the back link, the resource name, `SidebarNavGroups`) and `features/services/components/service-nav.tsx` (`serviceNavGroups`, `filterNavGroups`, the label keys) are the pattern to follow.
- Render: Info (also active on the bare URL); Monitor: Logs, Metrics; Manage: Plan (also active on `high-availability-upgrade`), Apps, Recovery. bex has no replica pages (its read replicas belong to the primary), so the primary's sidebar is the only one.
- Neither a Viewer nor a Billing member views logs (w9/145, `useCapabilities().denied("can_view_logs")`). Check whether a bex role is denied database metrics; if none is, Metrics is always drawn.

## Steps

1. Add `databaseNavGroups` beside the database feature (one source of truth, as `service-nav.tsx` is), with label keys in all eight locales.
2. Add `DatabaseSidebar` and pick it in `DashboardSidebar` on a `databaseId` param. It reads the database through the same document and variables the page uses, so Apollo serves it without another request, and a database the caller cannot see gets no nav, as for a service.
3. While the database loads, draw the entries that never change (Info, Logs, Metrics, then Manage), so nothing shifts once it resolves.
