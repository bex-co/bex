# Quota-denied sandbox creation surfaces as an opaque 502, not a quota error

**Type:** correctness / UX gap, found live during the w3/m40 t004 verification (2026-08-03).

When a workspace's `<ws>-sandbox` ResourceQuota cannot admit another sandbox pod (hobby tier: limits 4 CPU / 8 Gi = exactly two sandboxes at the default 2 CPU / 4 Gi template limits), the failure chain is: the BatchSandbox controller's pod create is rejected by the API server (`exceeded quota: tenant-quota …` — visible only in controller logs), the CR sits in "pending allocation", the OpenSandbox server polls its 60-second pod-ready wait, and bex-api's OpenSandbox client (`internal/sandbox/client.go`, `http.Client{Timeout: 30s}`) gives up first — so the tenant sees a generic **502 after 30 seconds** with zero indication they hit their plan's sandbox capacity. Diagnosing this live took a full descent through Traefik → bex-api → server → controller logs.

Two composable fixes, either promotable:

1. **Surface the quota denial as a typed 4xx** — the controller records the scale failure on the BatchSandbox (status/events); the server could map "pending allocation" + a quota-exceeded condition to an immediate 409/429-class response, and bex-api map it to Render's error dialect (the `BEX_MAX_*` retirement, w3/m34, moved cap enforcement to ResourceQuota — this is that decision's missing error-shape half, the exact risk w3/m34's t004 parity task flagged for Services).
2. **Fix the timeout inversion** — bex-api's 30s client timeout under the server's 60s synchronous pod-ready wait guarantees the client never sees the server's own richer 504 (`KUBERNETES::POD_READY_TIMEOUT`); either raise the client timeout above the server's wait or make the server respond immediately with a pending state.

Also worth noting for capacity planning: two sandboxes per hobby workspace is a *very* low ceiling once agent sessions (one sandbox each, ADR047) ship to real tenants.

Source: w3/m40 t004 live run (five failed attempts diagnosed to this root cause; fixture-side fix = pro-tier verify workspace, recorded in `scripts/verify-sandbox-isolation-live.sh`).
