## Objective

Teach the logs feature to read history from Loki: a `BEX_LOKI_URL` env var (like `BEX_PROM_URL`) selects a Loki-backed `QueryLogs` source that translates the existing `LogQuery` filter set (service, instance, level/type, text, limit, time range) into LogQL; when unset, the current pod-log path runs byte-identical. No REST/GraphQL/MCP shape changes — same envelope, same Render-matched limit semantics (default 20, cap 100).

## Context

- `lego/backend/internal/logs/service.go` — `PodLogSource` seam + `LogQuery.normalized()`; add a sibling Loki source behind the same domain interface rather than forking the service.
- Precedent for optional-backend wiring: `BEX_PROM_URL` (request metrics 503 when unset; here the fallback is pod logs, not 503).
- Time-range params exist in the query shape but are only best-effort over live logs today — Loki makes them real.

## Steps

1. Loki HTTP client (query_range) + `LogQuery` → LogQL mapping (label selectors from service/instance; line filters from text/level).
2. Source selection in the feature constructor from `BEX_LOKI_URL`; env-var row in CLAUDE.md table + `.env.example`/`.env.template` name mirrors if a var is added beyond the URL.
3. docs/bex-api.md logs paragraph: note the backend swap, shapes unchanged.
