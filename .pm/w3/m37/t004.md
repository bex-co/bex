## Objective

Wire ADR047 D7's v1 credential model: the tenant's model API key is stored in OpenBao (ADR013 pattern), injected into the sandbox at session start as the agent's provider credential, and scrubbed before any rootfs snapshot so a resumed/hibernated sandbox never carries it at rest (D2 snapshot hygiene).

## Context

- OpenBao tenant secret store: `BEX_OPENBAO_URL`, k8s-auth scoped to `tenants/*` (docs/ADR013-secrets.md); env-vars verbs in `lego/backend/internal/` show the read pattern.
- w3/008 (inbox) flags injecting reusable tenant credentials into sandboxes — the accepted mitigations are exactly this task's scrub + w3/m40's model-endpoint-only egress; note the residual in the session docs.
- Injection shape: env var (e.g. `ANTHROPIC_API_KEY`) or agent config file, per chosen agent binary.

## Steps

1. Define the OpenBao path convention for per-workspace agent model keys + a bex-api read at session create (coordinate with w3/m39's create path — a stub env injection is fine until m39 lands).
2. Driver/entrypoint: place the key for the agent process only (env of the spawned child, not a file).
3. Scrub hook: before hibernate/snapshot, remove the key from any persisted location; on resume, re-inject via the same path.
4. Verify a committed snapshot image contains no key material (grep the exported rootfs layer).

## Acceptance criteria

- [ ] Agent authenticates to its model API with the tenant key in a live sandbox run
- [ ] Rootfs snapshot provably contains no key material
- [ ] Residual risk cross-referenced to `.pm/w3/008.md`

## Files

- `lego/agent-image/driver/` (entrypoint/injection)
- `lego/backend/internal/sandbox/` or session-create stub (key fetch)

## Out of scope

- Bundled-token billing / metering proxy (wave 2, D6); GitHub tokens (w3/m38)
