## Objective

Add the two ADR047 D3 listeners to the driver: (1) an SSE endpoint emitting the AI SDK UI-message stream (`streamText` → `toUIMessageStreamResponse`-style, `includeRawChunks: true`) for the dashboard's `useChat`, and (2) a raw ACP JSON-RPC WebSocket pass-through to the agent's stdio for native ACP clients (phase 2+).

## Context

- Only the isolated ssh-gateway may reach these listeners: the `<ws>-sandbox` NetworkPolicy admits ingress from the gateway alone (w3/m35 machinery already scopes sandbox ingress; verify the gateway identity is admitted).
- The wire format on listener 1 is the standard AI SDK UI-message stream — the contract w5's dashboard UI and the wave-2 gateway proxy build against; document it.
- Listener 2 is newline-delimited JSON-RPC 2.0 over WebSocket (ACP custom-transport MAY, ADR047 "ACP as the interface").

## Steps

1. Add an HTTP server to the driver: `GET /stream` (SSE, UI-message stream of the active turn) and `GET /acp` (WebSocket ⇄ agent stdio).
2. Ensure headless mode still works with no client attached (listeners are optional consumers, never blockers).
3. Verify pod-network reachability from the gateway pod and non-reachability from another sandbox/namespace (reuse `scripts/verify-sandbox-isolation-live.sh` spot checks).

## Files

- `lego/agent-image/driver/` (server module)
- `deploy/gitops/` sandbox NetworkPolicy manifests if the gateway-ingress rule needs the new port

## Acceptance criteria

- [ ] `curl` from the gateway pod streams UI messages during a turn; a second sandbox cannot connect
- [ ] Raw-ACP WebSocket round-trips an `initialize` request to the agent
- [ ] Headless run unaffected when nothing attaches

## Out of scope

- Gateway-side proxying/ticket verification (wave-2 milestone); dashboard consumption (w5)
