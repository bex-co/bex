## Objective

Build the agent template image ADR047 D1 describes: a sandbox base image containing git, common language toolchains, and at least one ACP agent binary, with agent selection reduced to `command`/`args` configuration (D7 pluggability) — the image the OpenSandbox lifecycle client will instantiate per session.

## Context

- Sandbox templates today default to `opensandbox/base:latest` (`BEX_SANDBOX_IMAGE`, w3/m32); the lifecycle client is `lego/backend/internal/sandbox/client.go`.
- Candidate agent binaries (ADR047 D7): `claude-code-acp`, `gemini --experimental-acp`, `codex-acp`; pick one primary for v1 (BYO-API-key).
- The image must also carry Node (for the t002 driver) and a mount/install point for the m38 git credential helper (coordinate the path contract with w3/m38/t003 — agree the interface, build in parallel).

## Steps

1. Author a Dockerfile (new `lego/agent-image/` or sibling context) layering git, Node LTS, base toolchains (go/python/node), and the chosen ACP agent binary.
2. Make agent selection config-driven (`command`/`args` via env or a session config file), not baked-in.
3. Reserve the credential-helper install path + gitconfig `credential.helper` wiring (stub until m38 lands).
4. Build + push to the platform registry; wire an image reference the sandbox create path can select (new env or template metadata).

## Files

- new `lego/agent-image/Dockerfile` (or agreed sibling context)
- `lego/backend/internal/sandbox/client.go` (template/image selection)
- `.env.example` + `CLAUDE.md` env table if a new `BEX_AGENT_SANDBOX_IMAGE`-style var is added

## Acceptance criteria

- [ ] A sandbox created from the image has `git`, Node, and the agent binary on PATH
- [ ] Switching agents is a config change only (no rebuild for `command`/`args`)
- [ ] Credential-helper path contract documented for m38

## Out of scope

- The driver itself (t002); credential helper implementation (w3/m38)
