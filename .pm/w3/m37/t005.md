## Objective

De-risk the young `@mcpc-tech/acp-ai-provider` (v0.2.x) with vendor tests that lock the behaviors ADR047 D3 depends on: `persistSession`/`existingSessionId` → ACP `session/load` used **only** when the agent advertises `loadSession` in `initialize`; raw-chunk passthrough (`includeRawChunks: true`) delivering plans/diffs/terminal output; and zero-token-usage reporting (documented, so nobody later assumes metering can come from this path).

## Context

- ACP `session/load` is an optional agent capability — clients MUST check `loadSession` and MUST NOT call it if absent (ADR047 "ACP as the interface").
- A stub ACP agent (small script speaking JSON-RPC over stdio) makes these tests hermetic — no real model calls in CI.
- Escape hatch if the provider stalls: the raw-ACP listener (t003) — these tests are the early-warning signal.

## Steps

1. Write a stub ACP agent fixture (advertises/omits `loadSession`, echoes prompts, emits tool-call chunks).
2. Tests: resume with `loadSession` advertised → `session/load` called; absent → not called; raw chunks surface through `streamText`; usage is empty (assert + comment pointing at D6).
3. Pin exact provider + `ai` versions; note the pin rationale in the driver package.json.
