# A Blueprint's name reads "Name already in use" as it is typed in Settings, as Render's does

Why: Render checks a Blueprint name against the workspace's other Blueprints as it is typed, so the field says **Name already in use** before Save; bex-api has no such check, so bex's Settings says it only after Save is refused.

Filed by w3/m679 t006 on 2026-11-27.

- **Render:** the Blueprint Name row's schema is `name: required("Required").test("unique", "Name already in use", …)`, and the test runs the `blueprintNameExists(name, ownerId)` query with no cache (`index-D5V4ZgbE.js`; [blueprint-pages.md § The Settings card](../../docs/render-artifacts/blueprint-pages.md#the-settings-card)). A refused save sets the same message.
- **bex:** GraphQL has no name check; `updateBlueprint` refuses a taken name with `BLUEPRINT_NAME_TAKEN` (`lego/backend/internal/apps/blueprint.go` `UpdateBlueprint`, `blueprintNameTaken`), which `BlueprintSettingsCard` (`dashboard/src/features/blueprints/components/blueprint-settings-card.tsx`) words as **Name already in use** under the row after Save.
- **Done when:** GraphQL `blueprintNameExists(name, ownerId)` answers whether another approved Blueprint of the workspace has the name (case-insensitive, the rule `blueprintNameTaken` applies, a Blueprint's own name excepted), and the Settings row reads **Name already in use** while the typed name is taken, with Save held; a backend test covers a taken, a free and the Blueprint's own name, and a dashboard test types a taken name and reads the message without saving.
