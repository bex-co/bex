# Render's repository picker and its project-scoped and restore create URLs open bex's create forms

Why: Render starts a create at `/select-repo`, offers creates scoped to a project without an environment, and restores a Postgres into a new database at `/d/<id>/recovery/new/database`; bex answers all of them with its not-found page or Info, and no board item owns them.

Filed by w3/m704 t002 on 2026-11-27, from the URL inventory in [dashboard-routes.md § Render's URL inventory](../../docs/render-artifacts/dashboard-routes.md#renders-url-inventory). w1/m684 owns the environment-scoped creates (`/project/<id>/environment/<env>/new…`) and w3/m705 `/new` and `/new/<slug>`.

- **Render:** the create app table routes `/select-repo` (the urls chunk also builds `/select-repo?type=blueprint`) and `/project/:projectId/environment/:environmentId/select-repo`, `/project/:projectId/:serviceTypeSlug/new`, `/project/:projectId/new/database`, `/project/:projectId/new/redis`, `/project/:projectId/sandbox-group/new`, and `/d/:id/recovery/new/database`, which draws the new-database form as a restore.
- **bex:** none of these routes exists; `/d/<id>/recovery/new/database` reaches `databases.$databaseId.$.tsx`, which lands on Info. bex's repository choice lives on each create form, and point-in-time restore on the Recovery page.
- **Done when:** each URL opens the matching bex form with the project, the repository type or the restore source chosen (or, where bex has no such step, the nearest form with the query kept), dashboard tests pin each, and the inventory's rows read `matched` or name what remains.
