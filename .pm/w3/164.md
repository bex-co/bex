# A typed `/billing/update-plan-preview` URL draws Render's Choose custom domains; bex goes on to the confirmation

Why: Render's preview page draws for any plan that caps custom domains, so a hand-typed `/billing/update-plan-preview?plan=hobby` opens Review new limits and Choose custom domains there; bex's goes on to the confirmation, because its plan page never opens the preview and `changeWorkspacePlan` has nothing to receive the chosen domains.

Filed by w3/m708 t007 on 2026-11-27, from Render's dashboard bundle read the same day (`BillingUpdatePlanPreview-b8G1f0fw.js`, `billing-confirm-plan-utils-DuDK6s98.js`).

- **Render:** the preview draws when the target plan's `customDomains.isUnlimited` is false, which every new plan's soft limit is (2, 15, 25 included), and sends `tierChangeOptions.customDomains` with the plan. Its own plan page opens the preview only for a hard limit (the legacy Hobby plan's two), so the flow never reaches it for a workspace on the new plans. [workspace-plan-change.md § Preview](../../docs/render-artifacts/workspace-plan-change.md#preview-billingupdateplanpreview-and-choose-custom-domains).
- **bex:** `dashboard/src/routes/billing_.update-plan-preview.tsx` redirects to `/billing/update-plan-confirm` with the same search. bex meters custom domains above the included count (ADR030 §16); it never deactivates one on a plan change.
- **Done when:** either the preview draws Render's sections for a typed URL, with the chosen domains carried to a `changeWorkspacePlan` that acts on them, or ADR018's Workspace lifecycle row records the redirect as a difference the user signed off.
