# Render's Metrics URL keys beyond its window open the same chart state

Why: Render keeps a Metrics page's instance filter, unit, aggregations and request filters in its URL, and its Instance failed card links Metrics filtered to the failed instance (`?i=<slug>-<suffix>&t=<startMs>,<endMs>`); bex reads only the window (`t`, w3/m707) and keeps the rest in component state, so such a link opens unfiltered.

Filed by w3/m707 t007 on 2026-11-27, from Render's dashboard bundle read the same day (the metrics filter enum in `src-*.js`: `timeRange` `t`, `unit` `u`, `appAggregationMethod` `a`, `instances` `i`, `requestAggregationMethod` `r`, `responseAggregationMethod` `l`, `statusCodes` `s`, `hosts` `h`, `paths` `p`, `appResolution` `ares`, `requestResolution` `rres`, `selectedMetrics` `m`).

- **Render:** `nH` reads each key from `window.location.search` and `bSe` writes every non-default value back; `i` holds comma-separated `<service slug>-<instance suffix>` values. [dashboard-routes.md § Render's deep-link queries](../../docs/render-artifacts/dashboard-routes.md#renders-deep-link-queries).
- **bex:** `parseMetricsRangeSearch` (`dashboard/src/features/metrics/lib/range.ts`) reads `t` only; `application-metrics-card.tsx` holds `selectedInstances` and the aggregation in `useState`, and the request card its own filters.
- **Done when:** `i` (mapped onto bex's instance ids), `u`, `a`, `s`, `h` and `p` open the cards in that state, bex writes them back as Render does, values bex cannot honour are ignored, and tests cover each key.
