# A Postgres past 1 TB used cannot start an export, with Render's reason

Why: Render's Recovery page disables Create export once a database has used more than 1 TB and says why; bex offers the button and lets an export of that size start.

- **Render** (bundle `index-D5V4ZgbE.js`, read 2026-11-25 for w3/m656, [postgres-dashboard.md § Almost-full warning](../../docs/render-artifacts/postgres-dashboard.md#almost-full-warning-w3m656)): the Export card disables Create export on the Free and Starter plans and when `Number(storageUsed) > 1099511627776`. Above 1 TiB the Create export button is disabled with the tooltip "Exports are disabled for databases exceeding 1TB disk used."
- **bex**: `dashboard/src/features/databases/components/recovery-panel.tsx` disables Create export only while one is running; nothing reads usage. GraphQL `Database.storageUsed` (w3/m656) now carries the fullest instance volume's used bytes, null when unknown.
- **Done when**: a database whose `storageUsed` is past 1099511627776 bytes shows Create export disabled with Render's sentence in all eight locales, a null or smaller `storageUsed` leaves it enabled, and a test pins both. Check whether Render's REST `POST /postgres/{id}/export` also refuses (its OpenAPI says nothing); if it does not, the dashboard rule is the whole parity.
