# A Blueprint on GitLab, Bitbucket or an unsupported host is refused in wording that names GitHub, and the dashboard drops the host refusal

Why: since w8/344 (`ce33010c1`) bex reads Blueprints from gitlab.com and bitbucket.org and refuses every other host by name. But the refusal copy still blames "bex's GitHub app", so a user with a GitLab typo or a codeberg URL is sent to check a GitHub installation that has nothing to do with their repository.

- **Source:** follow-up from the w8/344 worker, 2026-11-20. These were the note's "Known gaps", which were never filed. Found by code reading, plus the live refusal text seen while closing w8/344.
- **Evidence:**
  - Server, `lego/backend/internal/apps/blueprint.go`. `classifyBlueprintFetchError` (`:350–352`) answers `Repository not found, or bex's GitHub app cannot access it.` for any `ErrRepoNotFoundOrNoAccess`, including a missing GitLab or Bitbucket repository. The 401/403 case (`:379`), the 429 case (`:382`) and the default `unavailable` case (`:386`) also name GitHub. `blueprintBranchRefusal` (`:2715`, `:2717`) answers with the same GitHub wording when the no-branch default lookup fails on another host, for example `example.com/a/b`.
  - Dashboard, `dashboard/src/routes/blueprints.new.tsx:278–330`. The page picks fixed copy per `reason` and never renders `preview.error` (`:265–268`). For `repo_not_found_or_no_access` it shows `blueprints.previewRepoNotFoundBody` (`src/features/blueprints/locales/en.ts:158–161`): "This repository does not exist, or bex's GitHub app cannot access it." So a codeberg preview, which the API refuses live with `bex reads a Blueprint from a public repository on github.com, gitlab.com or bitbucket.org, as Render does; codeberg.org is not one of them`, reaches the user as the GitHub-app message. The `access_denied` (`en.ts:167–169`) and `unavailable` (`en.ts:194–196`) bodies name GitHub too.
- **Fix direction:**
  - Server: pick the wording from the repository's host. github.com keeps today's text. gitlab.com and bitbucket.org say the public repository or branch was not found or could not be reached on that host. Keep the `reason` codes unchanged.
  - Dashboard: give the host refusal its own copy, or render the server's message for it. Two ways to tell it apart: a distinct `reason`, or a host check on the repo URL the page already holds. Make the other bodies host-neutral or host-aware in all 8 locales.
- **Done when:**
  - A unit test shows a missing GitLab repository, a GitLab outage and a failed default-branch lookup on `example.com` answer messages that do not name GitHub, while the github.com wording is unchanged.
  - A dashboard test shows a codeberg preview names `codeberg.org`, and a GitLab `repo_not_found_or_no_access` does not mention a GitHub app.
- **Estimate:** ~1h.
