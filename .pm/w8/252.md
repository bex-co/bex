# A Blueprint route or `fromService` with an invalid `type` is told to use a service type

Why: `routes[].type` takes `redirect` or `rewrite`, but `bex blueprints validate` answers a wrong value with the list of **service** types, so the message sends the author to values that are also invalid there. The same wrong list is printed for `envVars[].fromService.type`.

**Severity:** minor (misleading validation message; the error's line, column and path are right). **Attribution:** server. **Estimate:** ~20m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `f940`, 2026-11-11 UTC, released `bex v0.5.0` (Render CLI v2.35.0), `https://api.bex.co/v1/`, workspace `bex-canary`, QA human device login. Validation only; no resource was created.

## Evidence

```yaml
services:
  - type: web
    name: st
    runtime: static
    repo: https://github.com/mdn/beginner-html-site-styled
    staticPublishPath: .
    routes:
      - type: bogus
        source: /a
        destination: /b
```

```text
$ bex blueprints validate render.yaml -o json        → exit 1
{ "errors": [ { "line": 8, "column": 15, "path": "services[0].routes[0].type",
    "error": "at '/services/0/routes/0/type': value must be one of 'web', 'worker', 'pserv', 'cron', 'keyvalue', 'redis'" } ], "valid": false }
```

The same answer comes back for the route inside `projects[0].environments[0].services[0]`, and for:

```yaml
envVars:
  - key: REF
    fromService:
      type: bogus # → "…/fromService/type': value must be one of 'web', 'worker', 'pserv', 'cron', 'keyvalue', 'redis'"
      name: api
      property: host
```

## Expected

The enum of the field that failed, as the vendored Render schema states it (`lego/backend/internal/apps/schema/render.yaml.json`): `route.type` is `'redirect', 'rewrite'`; `fromService.type` is the `serviceType` definition (`web`, `cron`, `worker`, `pserv`, `workflow`, `static`, `dpg`, `job`, `redis`, `keyvalue`, less whatever bex marks unsupported).

## Root cause

`blueprintSchemaLeafMessage` (`lego/backend/internal/apps/blueprint_compiler.go:1463-1475`) replaces an enum error with `blueprintServiceTypeValues` whenever `blueprintServiceTypeLocation` is true. That predicate is `blueprintServiceFieldLocation(location, "type")` (`:1477-1497`), whose comment says "location is services/<n>/field" but whose loop returns true for **any** location that ends in `type` and has `services/<n>` anywhere before it. So `services/0/routes/0/type` and `services/0/envVars/0/fromService/type` are treated as the service discriminator. The loop exists so that services nested under `projects/<n>/environments/<n>/` match; it only needs to check that `services` and its index are the two tokens directly before the field.

## Fix

Make `blueprintServiceFieldLocation` require `location[len-3] == "services"` and a numeric `location[len-2]`. Then the schema's own enum message is used for nested `type` fields. `blueprintServicePlanLocation` (`:1481`, used at `:1415` to drop the free-cron schema error) shares the helper and gets the same tightening; check that a free cron inside a project environment is still handled by the service stage.

## Acceptance

- The YAML above answers `value must be one of 'redirect', 'rewrite'` at `services[0].routes[0].type`, at the root and inside a project environment.
- `fromService.type: bogus` lists the reference types, not the six service discriminators.
- `services[0].type: webb` still lists the six service types (existing `blueprint_m102_test.go` cases pass), also for a service inside a project environment.
- A unit test covers the three locations.
