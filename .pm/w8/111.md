## Producer, consumer and correction

- lego/operator/internal/build/native.go:243–284 generates the actual native image. Authored build RUN is emitted at268. Static images return at271–275. The serving-image tail at278–284 supplies only PORT, cleared ENTRYPOINT and exact CMD; NODE_ENV is absent.

The unchanged real generator/resolver exports for Node22/24/26 web all lack the default; Node24 static correctly has no runtime CMD. Four observations plus three maintained command/PATH/entrypoint tests yield14 named pass events,0 fail/skip. These observations are not a fixed regression or Docker execution.
- Runtime consumes image configuration plus appEnv/envFromSources. deployment_projection.go:260–261, cronPodSpec at app_controller.go:4676–4677 and pre-deploy container at5754–5755 share that environment assembly. appEnv at4831–4859 supplies user literals and PORT; envFromSources at4862 onward supplies existing group/service snapshots. No producer supplies NODE_ENV automatically. Exact primary Node24 runtime absence is live-proven; other lines/types are source-only.
- The pinned framework's lib/application.js:90–97 consumes process.env.NODE_ENV or development;138–140 enables view cache only in production. The observed view state follows that code exactly. The native CLI creates/updates valid configuration; no launcher/upstream fork belongs in this correction.

Add ENV NODE_ENV=production to the generated **primary Node serving-image tail after the build RUN and static return**. Keep it as a low-precedence image default so configured literals, linked groups and service envFrom values—including explicit empty—still override it. Do not put it before RUN, add it to the build bundle, append a higher-precedence container Env that overrides user secrets, or use a shell fallback that replaces explicit empty values. Preserve authored build/start bytes, PATH, entrypoint clearing, version selection, pnpm/Bun and cache keys. The change should reach a service through its next ordinary deployment; do not reconcile/restart the existing fleet just to add the default.

Primary Node web/private/worker and existing supported cron builds share the generator. No cron was created; current paid-only cron policy stays. Static-only artifacts, Dockerfile/image workloads, and Node companions in primary Python/Ruby must retain their existing behavior. Other runtimes' documented environment defaults are not certified here and are outside this bounded Node fix. REST/GraphQL/MCP/Blueprint/dashboard carry unchanged runtime/env input; no new field or CLI flag. Six exact REST/GraphQL/MCP source/runtime/command readbacks pass; no browser acceptance is claimed.
