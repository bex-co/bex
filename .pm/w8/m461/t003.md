## Objective

The source-aware read (t001) and the command rule (t002) hold for every way a service reaches an image source, for every service type that can have one, and for services already switched before the fix.

## Context

- Callers that switch a source: REST `PATCH /v1/services/{id}` (`image`, `repo`), GraphQL `updateService` (dashboard Settings → Source → Existing Image), MCP `update_service` (`image`/`repo`, `apps/mcp.go:93-94`), and a Blueprint sync that changes `runtime`/`image` (w8/m70 fixed which source a sync deploys; check it sets runtime explicitly).
- Build-source links (`buildSourceId`, w2/m254) clear `spec.BuildSource` in the same `applyTo`.
- Service types with an image source: web, private service, background worker, cron job. A static site refuses an image (`resolveSourcePatch`).

## Steps

1. Walk each caller above through t001 and t002's rules in unit tests. Note any caller that writes the source outside `sourceFields`.
2. Cover native → image for each type, Dockerfile → image, and image → native (w8/088 must still hold).
3. Read the dashboard's Settings → Source save. Does it send a Docker Command, and what does its Docker Command field show after a switch?
4. Count production Apps whose saved source is image-only with a native runtime and a non-empty `startCommand` they did not set as a Docker Command, if a read-only query can (store or `kubectl get apps -A`). Record the number in the milestone README. If any exist, decide whether they get a one-off fix or a note.

## Files

- `lego/backend/internal/apps/*_test.go`, plus whichever caller the review shows writes the source on its own
- `dashboard/` Settings source form, if step 3 shows it prefills the native command

## Acceptance criteria

- [ ] Every caller and service type above is listed in the milestone README with its result.
- [ ] The production count is recorded, or the reason it could not be read.
