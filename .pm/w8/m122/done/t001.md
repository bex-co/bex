## Objective

When a release converges Ready, record on App status the image digest its `app` container is running, attributed to that release generation, so bex-api can report Render's `image.sha` truthfully.

## Context

- External prebuilt images run `app.Spec.Image` verbatim (`lego/operator/internal/controller/release_identity.go:642–643`). `pinBuiltImage` (`app_controller.go:1463–1482`) pins only platform-registry builds, and `pullPolicyFor` (`:1509–1514`) makes a mutable tag `PullAlways`.
- The kubelet reports the running bytes in `pod.status.containerStatuses[].imageID`. `stuckPodMessage` (`app_controller.go:5298–5330`) already lists the Deployment's pods from the informer cache.
- App status types: `lego/types/v1alpha1/app_types.go` (`Image`, `ArtifactImage` around `:1508–1521`).

## Steps

1. Add a status field (for example `imageDigest`) plus the generation it belongs to, or attach both to the existing per-release record if that is the cleaner home.
2. On Ready convergence of the active revision, read a Ready pod of that revision's `app` container `imageID`, and keep only the `sha256:<hex>` part. If `status.image` already contains `@sha256:`, use that.
3. Leave the field empty when no Ready pod of that revision reports a digest. Never copy the previous release's value.
4. Observe on dev-8 (kind) whether `imageID` is the platform manifest or the index digest for a multi-arch tag, and document it in ADR004.

## Files

- `lego/types/v1alpha1/app_types.go` (+ regenerated CRD/deepcopy)
- `lego/operator/internal/controller/app_controller.go` (or the release-identity helpers)
- `docs/ADR004-app-deployment.md`

## Acceptance criteria

- [ ] An envtest-driven Ready pod with `imageID: docker.io/x/y@sha256:<d>` yields the status digest `sha256:<d>` for that generation.
- [ ] A failed rollout leaves the digest of the new generation empty, and the prior generation's value is not reattributed.
- [ ] A digest-pinned built image reports its own digest without a pod read.

## Out of scope

- Running `ref@digest` instead of the tag (a separate product decision; record it in ADR004 as open).
