## Objective

Apply the m81 read gate to the Postgres family: every by-id read verb in `internal/postgres/` calls `core.NotFoundIfDeleting` immediately after `AuthorizeApp`, so a `Database` App carrying a `DeletionTimestamp` answers `not found` on get, connection-info, and every sibling by-id read — across REST, GraphQL, and MCP (which share the service core).

## Context

- The gate: `core.NotFoundIfDeleting` (`lego/backend/internal/core/base.go:1016-1027`); the call-site pattern: `apps/service.go:1279` and `deploys/service.go` (m81's work).
- Inventory the family's by-id reads first — get, connection info, and any sub-reads (backups/recovery/exports listings keyed by the datastore id) so none is missed; List already omits deleting rows and stays untouched.
- Write verbs already refuse on deleting Apps via their own guards — do not touch them here.

## Steps

1. `grep -n 'AuthorizeApp' lego/backend/internal/postgres/*.go` to enumerate by-id verbs; classify read vs write.
2. Insert the gate after authorization on each by-id read; keep error shape identical to an absent id (the m81 safe-404 contract).
3. Extend the family's unit tests: a fixture with `DeletionTimestamp` set reads not-found on every gated verb.
