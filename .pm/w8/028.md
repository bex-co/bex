# 028 — A failing cron run executes the tenant's command 7 times over ~11 minutes, and every scheduled run in between is silently skipped

Why: one failed run of `* * * * *` re-ran its command seven times (Kubernetes' default Job `backoffLimit: 6`) and blocked the schedule for 11 minutes. A non-idempotent cron (send a digest, charge, post a webhook) repeats its side effect up to 7× on any non-zero exit, and ten scheduled runs never happened with no event saying so. A Render cron run executes once and reports failure; the next tick runs on time.

Live, 2026-09-27, production `726042a28`, `bex v0.2.1` (pin v2.27.0), human device login, workspace `bex-canary`. Found by the `/qa-find-bugs-cli` sweep 40. Fixture: free busybox cron `srv-das6jegd0qnc73d7a330` (deleted), `--cron-schedule "* * * * *" --cron-command "sh -c 'echo qa40-run; exit 3'"`.

```text
$ bex logs -r <cron> --type app --start 2026-09-27T00:56:00Z --direction forward
00:57:03 qa40-run   00:57:16 qa40-run   00:57:40 qa40-run   00:58:23 qa40-run
00:59:46 qa40-run   01:02:30 qa40-run   01:07:54 qa40-run          ← one scheduled run, 7 executions (10s→20s→40s→80s→160s→320s backoff)
01:08:00 qa40-run   01:08:13 qa40-run   01:08:36 qa40-run          ← the next run, already retrying the same way

GET /v1/services/<cron>/events
00:57:00 cron_job_run_started
01:07:57 cron_job_run_ended {"status":"failed"}                     ← terminal only after the 7th attempt
01:07:57 cron_job_run_started                                       ← ticks 00:58 … 01:07 never ran (ForbidConcurrent skips them)
```

## Mechanism

- `lego/operator/internal/controller/app_controller.go:3571-3583` (`reconcileCronJob`) sets `ConcurrencyPolicy: ForbidConcurrent` and the pod template (`RestartPolicyNever`, `cronPodSpec` `:3856`) but **no `JobTemplate.Spec.BackoffLimit`**, so Kubernetes applies 6 (7 pods). The manual-run Job has the same gap (`ensureManualRun` `:3743-3755`).
- While the retrying Job is active, `ForbidConcurrent` suppresses every tick, and with no `startingDeadlineSeconds` the skipped ticks are just gone.
- The same repo already uses `BackoffLimit: 0` for run-once Jobs (`disk_backup.go:553`, and predeploy per `predeploy.go:243`).

## Fix

Set `BackoffLimit: 0` on the CronJob `JobTemplate` and on the manual `RunAt` Job, so one run is one execution. A non-zero exit then ends the run `failed` within seconds, and the next tick runs on schedule. Leave `ForbidConcurrent` as is (Render runs at most one execution at a time).
