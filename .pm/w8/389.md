# The port-scan narration prints Render's docs line only once and its timeout line only at the 15-minute failure, where Render prints the docs line after every scan line and the timeout line about five minutes in

Why: w8/385 (`445a266883`, parked) added Render's port-scan lines to the deploy log, but ADR018's "Divergences" for that row has two departures. It attributes the first to "the no-flood rule the user set in w8/385". That attribution is wrong. The one-line-a-minute cap came from the orchestrator's worker brief, not from the user. The user's rule bounds QA fixtures' log output (no floods over 6,000 lines a minute), and it says nothing about product narration. Neither departure has the user's sign-off, so under AGENTS.md neither stands.

- Severity: minor. The wording is right; only the cadence and the timing differ.
- Evidence on record (`.pm/w8/blocked/385.md` "Render"): every `==> No open ports detected, continuing to scan...` is followed by `==> Docs on specifying a port: https://render.com/docs/web-services#port-binding`. There are five scan lines about a minute apart, then `==> Port scan timeout reached, no open ports detected. …` and its docs line. The deploy itself fails later, with `==> Timed Out` at about 15 minutes (wifihaven/wifihaven#1194: first scan line 00:33:48, timeout line 00:37:56, `Timed Out` 00:47:46).
- Dedupe: w8/385 is the narration itself, and w8/388 covers the localhost and non-HTTP variants. This item is only the cadence, the timing and the ADR018 wording.

## Fix

- Write the docs line after every scan line, which is two lines a minute at most, and five pairs at most.
- Write the timeout line and its docs line after the fifth scan line, about five minutes into the scan. Keep the deploy running to bex's 15-minute budget, and close it with Render's `==> Timed Out` equivalent, or bex's existing failure line if that is what Render's `Timed Out` maps to. Check what bex does with a port that opens after the timeout line, and record it.
- Rewrite ADR018's "Divergences" sentence for this row. Drop the attribution to the user, and drop any divergence this item removes.
- Update `TestPortScanLinesKeepRendersCadence` and its siblings to pin the new cadence.

## Acceptance

- Unit tests pin it: scan line plus docs line each minute, five pairs, then the timeout pair, and nothing more until the deploy ends.
- Live in `bex-canary`, on a free `busybox:1.36` web service listening only on `127.0.0.1`: `bex logs --type build` shows the pairs and, at about 5 minutes, the timeout pair. Delete the fixture by ID before the 15-minute budget, and confirm the 404.
