## Objective

Enforce `BEX_MAX_SSE_CONNS`, `BEX_MAX_SSE_CONNS_PER_SUBJECT`, and `BEX_MAX_SSE_CONNS_PER_WORKSPACE` across all `bex-api` replicas using the Postgres lease store from t001, with a heartbeat renewal loop so open tails hold their slots and crashed replicas' slots expire automatically.

## Context

- `lego/backend/internal/logs/rest.go:450` (`acquireSlot`) currently tracks `s.sseConns` (`atomic.Int64`), `s.sseBySubject`, and `s.sseByWorkspace` in process memory.
- ADR006 lines 750–758 document the defaults: global 100 (`BEX_MAX_SSE_CONNS`), per-subject 5 (`BEX_MAX_SSE_CONNS_PER_SUBJECT`), per-workspace 20 (`BEX_MAX_SSE_CONNS_PER_WORKSPACE`). Because production runs 2 replicas, a single subject could open up to 10 concurrent tails instead of 5.
- `acquireSlot` is shared by SSE (`GET /v1/logs/subscribe`), WebSocket, and NDJSON log tail paths.
- Idle tails stay open indefinitely (w1/m146), so a lease must be renewed periodically while the stream is active and released immediately when the returned `release()` closure runs.

## Steps

1. Define a minimal `SubscriptionSlotStore` interface on `logs.Service` (implemented by `*store.PGStore` from t001) and optional tunable `SubscriptionLeaseTTL` / `SubscriptionRenewInterval` (defaults e.g. 60 s TTL, 20 s renew interval).
2. Update `acquireSlot` in `lego/backend/internal/logs/rest.go`:
   - Keep the fast pre-auth global check or run the store-backed `AcquireLogSubscriptionSlot` with a unique slot ID (minted via `id.New` or crypto-random token) once workspace + subject are known, honoring `MaxSSEConns`, `MaxSSEConnsPerSubject`, and `MaxSSEConnsPerWorkspace`.
   - Start a lightweight heartbeat goroutine that renews the lease every `SubscriptionRenewInterval` until the returned `release()` is called or `ctx` cancels.
   - On `release()` (idempotent via `sync.Once`), stop the heartbeat goroutine and delete the lease with a short background context (so a canceled request context still frees its slot immediately).
   - On a store error (DB outage), log a warning and fall back to the existing in-process counters (fail-open, matching t002) so a transient DB blip never breaks live logs.
3. Wire `srv.Logs.SubscriptionStore = st` (when `st != nil`) in `lego/backend/cmd/api/main.go`.
4. Add unit and Postgres-backed tests in `lego/backend/internal/logs/` verifying cross-instance global, per-subject, and per-workspace caps, immediate release on close, lease renewal across >1 TTL, expired lease reclamation, and fail-open fallback on store error.

## Acceptance criteria

- [ ] Two `logs.Service` instances sharing one `PGStore` refuse the 6th concurrent tail for the same subject (when `MaxSSEConnsPerSubject=5`), the 21st for the same workspace, and the 101st globally across both instances with `429 too many active log subscriptions`.
- [ ] Closing a stream immediately frees its slot on the other instance; an abandoned lease expires after TTL without leaking.
- [ ] Store errors fall back to the in-process counters cleanly without returning 500s.
- [ ] `cd lego/backend && go test ./internal/logs/...` passes (including `-race`).

## Out of scope

- Changing log tail authz watchdog cadence or idle-tail retention semantics.
