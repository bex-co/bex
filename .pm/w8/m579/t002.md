## Objective

Back `bex-api`'s rate limiters (general API, Render REST/MCP rows, deploy hooks, and sandbox rate classes) with the shared control-plane Postgres token-bucket store from t001 so all replicas enforce one budget per caller/service/workspace, falling back cleanly to the in-process limiter on store outage or when no DB is wired.

## Context

- `lego/backend/internal/core/ratelimit.go` owns `KeyedRateLimiter`, `SetRateLimitHeaders`, `ReserveEach`, `ChargeRateLimit`, `SetRateLimitRefusal`, and `RateLimitScope`.
- `lego/backend/internal/api/ratelimit.go`, `render_ratelimit.go`, `lego/backend/internal/sandbox/ratelimit.go`, and `lego/backend/internal/deploys/deployhook.go` all build on `core.KeyedRateLimiter` and `core.ReserveEach` / `core.ChargeRateLimit`.
- `lego/backend/cmd/api/main.go` (`configureRateLimiters`, `:2119`) wires all limiters; `st` (`*store.PGStore`) is already constructed earlier in `main.go` and may be `nil` in DB-free tests/dev.
- Internal `:8091` listener, `/healthz`, `/readyz`, and in-process reconcilers have no limiter and must stay unthrottled. `BEX_RATE_LIMIT=0` disables general, Render, and sandbox rate limiting.
- Note that `RateLimit-Limit`, `RateLimit-Remaining`, and `RateLimit-Reset` must report the tightest bucket's post-take state (and `Remaining: 0` on 429) identically to today's single-replica headers.

## Steps

1. Define a shared bucket-store interface in `lego/backend/internal/core/ratelimit.go` (e.g. `RateLimitStore` with `Take`, `Refund`, `Peek`, and `BucketSpec` carrying `Key`, `RPS`, `Burst`, `Idle`) and a small bucket-state representation so `SetRateLimitHeaders`, `ReserveEach`, `ChargeRateLimit`, and `RateLimitScope.Refund` work seamlessly against either the shared store or local `golang.org/x/time/rate` buckets.
2. Add namespaced bucket support to `core.KeyedRateLimiter` (or a thin shared-store hook) so distinct limiters never collide on keys (e.g. `general:caller:<k>`, `general:workspace:<k>`, `render:<row>:<k>`, `render:workspace:<k>`, `sandbox:<class>:<k>`, `sandbox:workspace:<k>`, `deployhook:token:<hex>`).
3. Implement explicit **fail-open fallback to the in-process bucket**: if a shared-store call fails (DB unavailable/timeout), log a rate-limited warning and serve the request through the replica's local `KeyedRateLimiter` bucket rather than returning 500 or leaving traffic completely unthrottled. Keep `ctx` timeouts bounded on store calls so a stalled DB cannot hang every HTTP request.
4. Wire `*store.PGStore` into `configureRateLimiters` in `lego/backend/cmd/api/main.go` (when `st != nil`), including `RateLimiter`, `RenderRateLimits` (plus `Deploys.ServiceDeployRate` and `DeployHookLimiter`), and `Sandbox.RateLimits`, and start a periodic background pruner calling `PruneRateLimitBuckets` tied to `ctx`.
5. Keep `RefusedCredentialMiddleware` (`SandboxConnectRateLimiter`) and GraphQL batch `admit` working cleanly with the shared store.
6. Keep internal `:8091`, `/healthz`, `/readyz`, and `BEX_RATE_LIMIT=0` behavior unchanged.

## Acceptance criteria

- [ ] Two `api.RateLimiter` + `RenderRateLimits` instances sharing one `PGStore` share all Render rows, workspace bounds, deploy-hook buckets, general buckets, and sandbox classes, producing consistent `RateLimit-Limit` / `RateLimit-Remaining` / `RateLimit-Reset` headers across instances.
- [ ] On a simulated store error, requests fall back to the local in-process limiter (fail-open, no 500s).
- [ ] `BEX_RATE_LIMIT=0` still disables general, Render, and sandbox rate limiting; internal `:8091` remains unthrottled.
- [ ] Existing rate-limit unit tests in `internal/core`, `internal/api`, `internal/sandbox`, and `internal/deploys` pass.
