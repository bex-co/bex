# 068 — Upstream `logs -o yaml` merges multiple entries into an invalid mapping and silently loses earlier entries in permissive parsers

Why: exporting two log entries as YAML exits successfully but produces duplicate mapping keys. A strict parser rejects the export, while a permissive parser keeps only the last entry, misleading automation that expects the complete query result.

Severity: major (corrupted log export and silent loss in a downstream parser; server-side logs are not deleted). Attribution: upstream Render formatter, reproduced through Bex. Estimate: ~45m upstream patch preparation and separate shared-consumer verification; upstream acceptance, pin update, distribution and live confirmation are separate follow-ups. No product fix or external upstream issue has been submitted.

## Cause, contract and concrete fix

At the exact upstream pin, `cmd/logs.go:109–125` marshals each log independently with `yaml.Marshal` and writes the bytes directly. `nonInteractiveLogs` calls that formatter once per history entry (`:136`) and once per tail frame (`:148`), without any YAML document boundary. The repo-wide symbol search finds exactly these two production callers and the declaration. `pkg/tui/views/logloader.go:36–54` feeds the history result or tail channel into these branches.

[Render's CLI reference](https://render.com/docs/cli-reference#logs) exposes YAML as a global output format and logs as a multiple-entry query/stream. Its current generated reference names v2.28.0, so the local v2.27.0 source and control binary are the version-specific oracle here. [YAML 1.2.2](https://yaml.org/spec/1.2.2/#3211-nodes) requires unique mapping keys; [its document-stream rules](https://yaml.org/spec/1.2.2/#91-documents) provide document boundaries. The duplicate-key output is therefore malformed, regardless of a permissive parser accepting it.

Prepare an upstream change that preserves streaming and emits a YAML document boundary between log records. A reusable `yaml.Encoder` scoped to one command can do this; do not instantiate a fresh encoder for every record, which repeats the defect. Preserve an empty stream for zero entries and the existing field values/order for a single record. Keep JSON's existing stream contract and text output unchanged. The formatter is upstream-owned: do not fork/vend it or alter Bex's server response to compensate. Until a fixed pin is adopted, JSON or text is the supported workaround for exporting multiple entries.
