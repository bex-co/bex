# A web service's own `Server` header reaches clients verbatim (`server: nginx/1.27.5`), where Render moves it to `x-render-origin-server` and sends `x-render-origin-server: Render` when the app sets none

Why: Render's edge never hands a web service's `Server` header to clients. It renames it to `x-render-origin-server`, keeping the value, and when the app sends no `Server` it adds `x-render-origin-server: Render`. On bex the app's `Server` header passes straight through, version included, and no `x-render-origin-server` is ever set. So bex exposes the origin's software and version, and a client or monitor that reads Render's header gets nothing. bex already mirrors Render's other edge headers (`Rndr-Id` w8/m125, `X-Request-Start` w8/196, `x-render-routing`), and this one is missing.

**Severity:** minor. **Attribution:** infrastructure (Traefik edge plugin). **Estimate:** ~45m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `66c6`, 2026-11-14 00:52 UTC, released `bex v0.6.0`, `https://api.bex.co/v1/`, workspace `bex-canary`, production pin `ac206b76841b`.

## Render's behavior (captured 2026-11-14 ~00:50 UTC)

Public Render web services, each response with Render's `rndr-id`:

```
https://litellm-l9il.onrender.com/health/liveliness   (uvicorn app)
  HTTP/2 200
  server: cloudflare
  x-render-origin-server: uvicorn
https://express-typescript.onrender.com/              (Express, no Server header)
  HTTP/2 200
  server: cloudflare
  x-powered-by: Express
  x-render-origin-server: Render
```

`elysiajs-hello-world-xy2f`, `rails` and `read-it-for-me` (all `.onrender.com`) also answer `x-render-origin-server: Render`. Other app headers, such as `x-powered-by`, pass through untouched; only `Server` is moved. `server: cloudflare` is Render's CDN, which bex does not have. Render static sites carry no `x-render-origin-server` (`sveltekit-static.onrender.com`). Render's own wake page carries `X-Render-Origin-Server: Render` ([wake-interstitial capture](../../docs/render-artifacts/wake-interstitial.md)).

## Root cause

- The tenant edge plugin `deploy/gitops/charts/traefik-plugins/clientipheaders/clientipheaders.go` (`ServeHTTP`, `:92-124`) rewrites request headers and sets `Rndr-Id` on the response. It then calls `next.ServeHTTP(w, r)` with the client's own `ResponseWriter`, so the app's response headers reach the client unchanged.
- The plugin is attached at the `web` and `websecure` entrypoints (`deploy/gitops/base/values/traefik.values.yaml:75`, `:82`). It therefore also sits in front of static sites, the activator and the platform's own hosts, which Render treats differently: no `x-render-origin-server` on static sites.

## Fix (target behavior)

- For a **web service** response only, as the app sent it:
  - an app `Server` header → removed and sent as `X-Render-Origin-Server` with the same value (several values joined as Go's `Header` holds them);
  - no `Server` header → `X-Render-Origin-Server: Render`;
  - no `Server` header is sent to the client, since bex has no CDN of its own to name.
- Static sites, the platform's own hosts (`api.bex.co`, `dashboard.bex.co`) and other entrypoint traffic are unchanged.
- **Placement options:**
  - a response-wrapping writer in the plugin, enabled by a plugin config field on a second middleware instance that the operator puts in web services' App Ingress chain (`app_controller.go:4342-4362` already composes that chain);
  - or keying on a request marker the App route sets.

  Either way, rename on `WriteHeader`, and on the first `Write` when the app never calls `WriteHeader`. Keep `http.Flusher`, `http.Hijacker` (WebSockets) and streaming working.
- Optionally the activator's wake and first-deploy answers also send `X-Render-Origin-Server: Render`, as Render's wake page does.
- Record it in ADR018 next to the `Rndr-Id`/`X-Request-Start` rows, citing the captures above.

## Blast radius

- **Covered:** every public web service, on both entrypoints (`:80` before the redirect and `:443`).
- **Must stay untouched:** static sites, the activator's own responses (unless deliberately covered), and platform hosts. A test should prove they are unchanged.
- **Wrapper risks:** streaming (SSE), `Hijack` for WebSockets, and `Flush`. The plugin's tests (`clientipheaders_test.go`) cover request-side behavior only today.

## Acceptance

- Plugin tests:
  - an app answering `Server: nginx/1.27.5` → the client sees `X-Render-Origin-Server: nginx/1.27.5` and no `Server`;
  - an app with no `Server` → `X-Render-Origin-Server: Render`;
  - a hijacked WebSocket and a flushed SSE stream still work;
  - static-site and platform routes are untouched.
- Live, after the roll: the same nginx image service answers `x-render-origin-server: nginx/1.27.5` with no `server: nginx…`; a static site shows no `x-render-origin-server`; `https://api.bex.co/v1/` headers are unchanged. Delete the fixture.
