# Full-SPDX publication through Rekor v2 — 2026-10-30 UTC

Node 14 recovery and Python 3.7 publication each passed both runtime architectures and both vulnerability scans, then failed on the first amd64 SPDX attestation POST to Rekor. The retained Node 14 recovery log reports two attempts without an underlying HTTP status. This does not prove a precise server limit or timeout. The installer action defaults to Cosign 3.0.6; its reviewed source is archived here.

Verified official Syft 1.55.0 independently regenerated the exact Node 14 candidate's amd64 SPDX: 25,143,815 bytes, 1,147 packages, 29,999 files and 34,068 relationships. The full gzip and raw hashes are retained, and the unchanged strict SPDX binding validates the real registry child/config identities. CI used Syft 1.51.1, so this independent report demonstrates scale rather than exact CI byte identity.

[Cosign 3.1.1 release notes](https://github.com/sigstore/cosign/releases/tag/v3.1.1) document the large-SBOM Rekor v2 hashed-PAE fix; [the upstream discussion](https://github.com/sigstore/cosign/issues/3599) describes the earlier full-payload upload boundary. The patch pins the existing installer to verified Cosign 3.1.4, creates its official TUF-derived `--with-default-rekor-v2` signing configuration and explicitly passes that configuration to every image-sign, SPDX-attest and Trivy-attest command. It preserves the complete predicates, GitHub OIDC source, identity/issuer/source-SHA verification, transparency logging, both architectures, both scans and all runtime probes. Discovery tags still move only after every signing command succeeds.

A verified 3.1.4 local protocol experiment supplied the unchanged genuine 23,418,941-byte exact-Python SPDX predicate and captured a 415-byte `/api/v2/log/entries` hashed request. The local server intentionally returned 500, public HTTPS was blocked, and no public transparency entry or signature acceptance occurred. A separate local OCI round trip retained the complete predicate and existing envelope parser shape; it is not a GitHub identity or transparency-verification result. No private test key is archived.

Independent review of exact 3.1.4 and sigstore-go code confirms explicit GitHub OIDC selection is compatible with the signing configuration and the highest supported valid Rekor API is chosen before the `ANY` selector. The config therefore selects v2, while the full report stays in its signed OCI bundle. [New-bundle verification](https://github.com/sigstore/cosign/blob/v3.1.4/pkg/cosign/verify_bundle.go) automatically selects signed timestamps for pure v2 entries; certificate identity/extensions and transparency thresholds remain enforced. The existing strict review tool already uses the verified 3.1.4 binary.

Workflow validation and actionlint pass. Actual CI replay must still establish successful public signing/attestation and per-candidate strict review. The evidence supports the payload/API diagnosis and a supported full-report fix; it does not approve any native candidate, populate the production catalog, establish adoption or close hosted acceptance.
