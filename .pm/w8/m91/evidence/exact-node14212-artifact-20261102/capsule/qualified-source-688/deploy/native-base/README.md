# Shared native base images

The 2026-10-29 user decision selects one [common Bookworm foundation](../native-common/README.md), with selected runtimes installed above it. Automatic per-language publication is retired. `native-base-image.yml` retains explicit singleton manual publication to finish existing requests and supplies the shared gates for the common publisher. `matrix.py` still reads the reviewed official runtime pins directly, including historical lines. Publication does not change the operator's runtime image pins.

The package recipe installs PostgreSQL 18 clients, Pandoc, SQLite, libvips, gettext, Ghostscript, jq, rsync, SWIG, pigz, zip, and Debian's Python development and packaging tools with their normal library/resource closures. It selects PGDG's signed archive for Bullseye and the live signed repository for Bookworm/Trixie. The signing key is pinned by SHA-256. System packages are resolved during image publication; adopting the result requires reviewing the immutable image digest, SBOM, package inventory and tests.

TypeScript and Webpack use an integrity-locked npm dependency graph under `/opt/bex/native-node-tools`. Their wrappers use a private reviewed Node 24 executable, preserving the tenant's chosen Node version and working on historical Node lines too. Replacing an exact primary's `/usr/local` tree therefore retains the system and JavaScript utilities.

Primary Python packaging is supplied separately from Debian's system Python. `python-tools.json` records the public PyPI wheel URLs, SHA-256 identities, Python requirements, review date and freshness sources. Python 3.7 uses setuptools 68.0.0 and wheel 0.42.0; Python 3.8 uses setuptools 75.3.4 and wheel 0.45.1; Python 3.9–3.14 uses setuptools 80.9.0, wheel 0.48.0 and packaging 25.0. All selected setuptools payloads retain `pkg_resources` and vendored `distutils`. The historical bundles use their last compatible release lines; their old `wheel convert`/`wheel unpack` security limitations are not repaired by the packaging checks. Modern Python uses wheel 0.48.0, which includes those fixes.

The publisher verifies complete wheel bytes and embedded metadata before retaining them under `/opt/bex/python-tools`. `/usr/bin/bex-native-python-tools` then installs the selected bundle offline into the absolute primary `/usr/local/bin/python3`, and can run again after an exact primary transplant. It leaves Debian's interpreter and the tenant's interpreter version, PATH, PYTHONPATH and project import precedence intact. The default publisher and exact-primary assembly both invoke it with networking disabled. Primary pip and development headers remain those of the pinned official primary image.

The workflow signs and attests candidates only after a real PG18 archive converts to the exact three expected rows, without network, on both amd64 and arm64. `check-tools.py` additionally runs real document conversion, SQL queries, image processing, message catalog compilation, PostScript rendering, manifest/asset copying, strict TypeScript compilation, a SWIG C extension import, Webpack bundling, compression, archive extraction, and a Python metadata/wheel build and install. These checks run without network. An invalid archive must fail. The fixture was generated by official PostgreSQL 18 (`archive.sql`), not fabricated archive bytes.

For images with a primary Python, `check-primary-python.py` separately exercises real metadata generation, `pkg_resources`/`distutils`, matching-header C compilation/import, a local-only wheel build and target installation, independent arithmetic/Unicode values, compiler/corrupt-wheel errors, helper idempotence and project-local import precedence. It also runs with networking disabled.

For a local candidate:

```sh
docker build --build-arg BASE_IMAGE='<reviewed official image@sha256:digest>' \
  -t bex-native-check deploy/native-base
docker build --build-arg NATIVE_BASE=bex-native-check \
  -f deploy/native-base/check.Dockerfile deploy/native-base
```

Candidates use `ghcr.io/bex-co/bex-cnb-run:native-<upstream-tag>-<commit>` and are published for `linux/amd64,linux/arm64`. The existing public package provides anonymous pulls; native tags never move the CNB `latest` tag. Review the workflow's per-line digest and SBOM before a separate pin commit under ADR060 D7. Never substitute a mutable tag into tenant builds. A successful candidate build alone does not establish native-generator, exact-patch, companion, hosted-service or other-tool acceptance; w8/m91 and the individual tool milestones retain those checks.

## Security maintenance for frozen runtimes

User decision D1=A (2026-10-29, w1/m188) permits platform-maintained security backports while retaining the selected language version. Bookworm and Trixie use signed Debian security packages. Frozen Bullseye images rebuild the checksum-locked Debian `1.0.9-2+deb12u1` source on Bullseye, with the transparent package suffix `+bex11u1`, replacing shared **and static** libraries. The Debian source record remains under `/usr/share/bex-security/`. This avoids linking newer-distribution binaries against an older libc.

The four reviewed EOL Node releases separately rebuild their original Node source with the matching Google Brotli security release; see [node-brotli](node-brotli/README.md). Their compiler uses the pinned Bullseye baseline so the repaired executable remains usable as a companion on Python 3.7 and Ruby 3.0; compiling on Bookworm can raise libc/libstdc++ requirements even when Node and ABI versions stay identical. The final primary image retains its original distribution. The publisher also executes every patched Node binary with the canonical decoder probe against Bullseye libraries on both architectures. Updating Debian alone cannot repair a statically bundled decoder. No patch download or compilation is added to tenant builds.

Before a discovery tag moves, both architectures must pass real utility transformations and network-free malformed-stream and healthy-round-trip probes against system and bundled decoders. The published index has build provenance, per-architecture SBOM and vulnerability-report attestations, and a keyless signature from this workflow. Trivy reports include unfixed vulnerabilities; these backports address this Brotli defect, not every vulnerability in EOL runtimes. Version-only scanner findings on backported Node require source and runtime evidence, never blanket CVE ignores.

The stable discovery tag `ghcr.io/bex-co/bex-cnb-run:native-<upstream-tag>` moves only after these gates. Builds and failures never edit the operator's committed pins. The build-plane maintainer reviews both official upstream drift (the existing freshness inventory) and the latest verified platform candidate, then adopts only an immutable, verified digest in a separate commit. A failed build, scan, signature or behavioral probe keeps the previous discovery tag and adopted pin. A new upstream fix is a review request: verify equivalent library/runtime behavior on both architectures before returning to the official image. These recipes support the eleven reviewed legacy line images; arbitrary dynamically resolved exact patches and tenant-installed dependencies need their own evidence.

Running candidates finish instead of losing completed work; newer explicit requests replace only pending work for that runtime. Source changes no longer automatically publish a per-language matrix. Historical publication and failed requests remain evidence, without authorizing C adoption. Review includes the source revision as well as the immutable digest. The expensive interpreter compilation layer is separate from probe and documentation changes. Inline exports do not reliably restore that intermediate stage: importing the first Node14 candidate succeeded, but the compiler still missed cache. Do not assume that a registry import avoids compilation.

The former automatic matrix ordered the eleven frozen Brotli backport lines first. Existing requests retain their original source and the same checks; this historical order does not create new publication requests.

## Recovering a completed build

Full utility images contain compiler-sized ELF files; each architecture gets a bounded 20-minute Trivy analysis budget. Scanning, findings, both architecture checks and signing remain mandatory. Registry login retries transport failures at most three times, with a 60-second bound per attempt, and always removes the job credential afterward.

The publisher pins cosign 3.1.4 and creates its Rekor v2/Fulcio/TSA signing configuration from Sigstore's TUF defaults. Modern Rekor records the signed DSSE content's digest while the complete signed SBOM/report stays in its OCI bundle, avoiding legacy full-envelope request limits for these large utility images. Verification requires cosign 3.1 or newer and still checks transparency, workflow identity and the complete predicates. Configuration creation and each signing call get three attempts, a five-minute timeout with ten-second forced-termination grace, and 5/10-second backoff. Exhausted retries stop publication before discovery tags move. See the [Rekor v2 large-SBOM protocol change](https://github.com/sigstore/rekor-tiles/releases/tag/v2.3.0).

Syft reads `registry:$REF` for each architecture. Automatic source selection can use a Docker-save image with a synthetic manifest digest; the registry source keeps the signed SPDX root tied to the reviewed platform manifest. Reviewers check that identity and each signed scan's config digest alongside the common index subject.

A reviewer may authorize an already-built immutable index in `.github/native-base-recovery.json`, recording its original producer SHA, reviewed base, source job and evidence. This main-branch file is the authorization boundary; there is no arbitrary-image dispatch input. Recovery requires the same package, base and unchanged non-Markdown recipe (rename-aware comparisons are disabled). It reruns both architecture checks, scans, SBOM generation and signing against that exact index. OCI revision/provenance retain the original producer; the recovery workflow SHA identifies fresh verification/signing. Failed recovery never moves the verified discovery tag.

Remove each recovery authorization once its verified discovery tag is published. Cleanup does not start another full build. A required `workflow_dispatch` `runtime` selects exactly one name from the authoritative matrix, for example `gh workflow run native-base-image.yml -f runtime=node-14-bullseye`; unknown or empty names fail before a production job starts. The common foundation is built from source and does not use per-language recovery authorizations.

Publication retries interrupted Python-tool transfers at most three times with 1/2-second backoff and a 60-second socket timeout. Partial responses are discarded; checksum, size, wheel metadata, permanent HTTP and certificate-validation failures remain final. The independently checksum-pinned PGDG signing key gets bounded curl transport retries with 30-second connection and 180-second per-attempt limits. These retries run only while publishing the base image.
