## Objective

Pin `nativeCommonBase` to the digest a green `-f profile=families` run published, and fill `nativeRuntimeArtifacts` with the five reviewed Node donor trees (the map in `commonNodeQualificationArtifacts`). Production native builds then start from the common Bookworm image, which carries the PostgreSQL 18 clients and the rest of Render's tool table. No feature that production serves today on the official language images may be lost.

## Context

A dry run on 2026-11-16 pinned the 2026-11-16 push-run image (`sha256:28a42dc4…`) plus the donor map and ran the build package. 39 tests failed, in three groups:

1. **Fakes that are not registry-faithful.** Common mode reads every selected primary's image environment (`pinCommonNativePrimary`, `nativecommon_erlang.go:29`). `fakeExact` returned no version env, Debian history or OTP checksum.
2. **Unit tests on the live registry.** `resolveNativeBuild` (`nativeresolve_helpers_test.go`) used `NewDockerHubResolver()`. In common mode every resolution reads image metadata, so those tests hit Docker Hub and got HTTP 429.
3. **Features that existed only on the official-image path** (`nativeCommonBase == ""`): w8/309 (a Node release older than bookworm, exact or by range, copied from its bullseye/buster image) and the empty-mode-only Dockerfile shapes the tests pinned.

## Checkpoint — 2026-11-16 (loopx session)

Shipped with production behavior unchanged (the pins stay empty, and every production change is behind `nativeCommonBase != ""`). The whole build package now passes in both modes: empty, and with the dry-run digest plus the donor map pinned.

- **Offline unit tests.** `resolveNativeBuild` uses `fakeExact`, and `fakeExact` answers metadata the way Docker Hub does when a test sets none (`officialImageMetadata`). The build package runs in about 2.5 s with no registry call, where it took about 5 minutes against Docker Hub.
- **w8/309 on the common base.** An exact or range Node release with no bookworm image becomes the exact primary itself. Its bullseye or buster tree is copied onto the common image. The source guard admits exactly that older suite, and recipes for existing selections stay byte-identical.
- **Common-mode expectations.** Tests that pinned empty-mode Dockerfile text now check the common equivalent: the copied tree, and the generated lines unchanged after it (`commonResolutionKeeps`). Supplied-mode tests and the source-fallback controls run with the pin cleared (`withoutCommonBase`), because those modes exist only without it.
- **Families run 43858983878** (the first `profile=families` dispatch; 43857294349 stuck queued with no jobs and cannot be cancelled): its utility cohort passed. Two Python fixtures predate w8/274 (`448b121c3`), which put every native Python build in Render's project venv (`VIRTUAL_ENV=/opt/render/project/src/.venv`):
  - Both Python 3.13 + Node 16 addon legs required `sys.prefix == /usr/local` for PATH `python3`. `native-node-addon-qualification/check.py` now checks `sys.base_prefix`.
  - The modern-python legs refused any `VIRTUAL_ENV`. `native-legacy-python/check.py`, which modern and legacy share, now admits exactly Render's venv path.

  The full leg results are recorded in the milestone README.

## Remaining steps

1. Dispatch `-f profile=families -f case=all` on the fixed source and fix any case it fails, until one run is green on every case.
2. Pin that run's digest and the donor map in `nativebases.go`. Make `commonNodeQualificationArtifacts` and production read one map, so the donor set the families run qualifies is the one production uses. Add `toolchain-freshness.json` entries for the common image (`ghcr.io/bex-co/bex-cnb-run:native-common-bookworm-<sha>`) and each donor (`native-node-14-bullseye-bfdeb622…`, `native-node-16-bookworm-bfdeb622…`, `native-node-18-bookworm-dbc493ba…`, `native-node-20-bookworm-6fd4f455…`, `native-node-14.21.2-bullseye-6883953e…`).
3. `make test`, `make lint` and `scripts/build-toolchain-freshness.sh validate` pass. Then ship. Production picks up the pin on its next ordinary roll; no `deploy.yml` dispatch.

Known common-mode behavior to keep in view (both reviewed choices, not regressions):

- When a selected image's environment cannot be read, the build fails with `read selected native primary environment: …` (`nativebases.go` `pinNativePrimary`). Empty mode fell back to the reviewed patch, and only `TestSuppliedResolverEnvironmentLookupFailureKeepsVersionFallbackRules` covers that fallback now.
- Removing the per-language supplied-base mode, which no production pin uses once the common base is set, belongs to t004 (Simplify).
