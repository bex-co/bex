## Objective

Cut production over to the store with no customer data lost, and verify the milestone's read and integrity targets live before pruning.

## Context

- This writes to production OpenBao and Postgres. It requires the user's explicit authorization for a stated window — the same rule as `docs/runbooks/env-group-path-migration.md` — plus a fresh OpenBao snapshot ([ADR031](../../../docs/ADR031-platform-data-backup.md)).
- The deploy path is `deploy.yml` / GitOps image pins; t001 fixed how the new revision refuses env groups until `apply` completes.

## Steps

1. Run `dry-run` against production. Share the per-workspace counts and every duplicate or unresolvable item with the user, and get the window approved.
2. In the window: snapshot OpenBao, run `apply`, roll out the new revision, then verify the milestone DoD's read and integrity bullets live (QA session, read-only checks plus an owned throwaway group for create/rename/delete).
3. Run `prune`, then verify the DoD's OpenBao end state by listing the env-group paths (counts only).
4. Record sanitized evidence here: counts and timings only — no values, names of other tenants' groups, or credentials.
