## Objective

Add t001's tables and a store API that covers every metadata operation env groups need, with the constraints doing the work the KV workarounds did.

## Context

- Migrations: `lego/backend/internal/store/migrations/` — take the next free number at implementation time (other workers add migrations concurrently), with up and down files.
- The list filter contract to serve in SQL is `EnvGroupListFilter` (names, owners, environment ids, created/updated windows; `lego/backend/internal/envgroups/service.go`).
- Postgres test convention: `*_pg_test.go` beside the store file.

## Steps

1. Write the migration.
2. Add store methods: create (unique violation → typed name conflict), get, list by tenant with the filter, list membership by environment for a tenant, rename, set environment, touch, delete, link/unlink, links per group and per app, and t001's generation and operation-state operations.
3. Add Postgres tests for each, including the unique-name race and every FK cascade.

## Files

- `lego/backend/internal/store/migrations/<next>_env_groups.{up,down}.sql`
- `lego/backend/internal/store/envgroups.go`, `envgroups_pg_test.go`

## Acceptance criteria

- [ ] The migration applies and reverts cleanly
- [ ] Two concurrent creates of one name → one row and one typed conflict
- [ ] Deleting an app, an environment or a tenant cascades exactly as t001 specifies
