## Objective

Fix, before any code, the Postgres schema, the surviving OpenBao layout, the cutover sequence, the data-migration rules and the deliberate breaks. Rewrite ADR013's env-group sections and ADR006's name-uniqueness paragraph to describe the new design rather than the KV history.

## Context

- Every non-secret path and workaround to replace is listed in the milestone README ("What goes away"). Inventory them again with `grep -n '"env-group' lego/backend/internal/envgroups/*.go`.
- ADR013 env-group text: `docs/ADR013-secrets.md:41-45`; projection ordering (keep): `:98`. ADR006 name uniqueness: `docs/ADR006-bex-api.md:632`.
- Revision tokens are opaque `egr1_<version>` (`lego/backend/internal/envgroups/revision.go`), today the KV version of the revision record.
- FK targets: `tenants(id)`, `environments(id)`, `apps(id)` (all `text` primary keys).

## Steps

1. **Schema.** An `env_groups` table (id PK, `tenant_id` → `tenants` ON DELETE CASCADE, name, `environment_id` → `environments` ON DELETE SET NULL, `created_at`, `updated_at`, `UNIQUE (tenant_id, name)`) and an `env_group_links` table (`group_id` → `env_groups` CASCADE, `app_id` → `apps` CASCADE, both as the primary key). Decide what replaces the revision record and the op record — a generation column with row-lock or CAS updates, lease columns or an operations table — and the new revision-token prefix.
2. **OpenBao layout.** Only `env` and `files` under the group's workspace tenant, plus `op/<opID>/{old,new}-{env,files}` while a save is in flight. Confirm that no non-secret value stays in OpenBao.
3. **Cutover.** Default plan: snapshot OpenBao; take the API (or the env-group routes) down; `apply` copies metadata into Postgres and copies values to their workspace-tenant paths without deleting anything; the new revision starts; verify; `prune` then deletes every other path. Before prune, rollback is redeploying the previous image. Decide how the new revision refuses to serve env groups before `apply` has run, for example a cutover-marker row. Any such gate is deleted in t008.
4. **Migration rules.** Ownerless groups go to `core.DefaultTenant` (today's lazy rule). Links stored as names resolve to ids by today's `migrateLinks` rules; unresolvable ones are dropped and reported. Fenced or stale ids are not migrated. Duplicate names inside a workspace stop `apply` with a report — never a silent choice.
5. Record the deliberate breaks (milestone README) in ADR013.
