## Objective

A single migrator, the only code that still knows the old OpenBao layout, moves production from KV metadata to the store under t001's rules. It is idempotent, reports every decision, and is deleted in t008 once production has been pruned.

## Context

- Old layouts it must read: legacy-tenant full groups, legacy locators and tombstones, workspace-tenant meta (including `{"tombstoned":"1"}` fences), name claims, links stored as names, ownerless groups. The old helpers live in `tenant.go`, `migrate.go`, `nameclaims.go`, `links.go` and `meta.go`; move what the migrator needs into its own file rather than keeping it on the serving path.
- Precedent for an opt-in startup mode: `lego/backend/cmd/api/main.go:381-400`. Prefer a one-shot command that does not serve traffic.

## Steps

1. `dry-run`: classify every id across both tenants (live / fenced / stale / locator / duplicate name / unresolvable link) and report counts per workspace. No writes.
2. `apply`: upsert rows and links; copy legacy-resident values to workspace-tenant `env` / `files`; delete nothing; stop on duplicate names. Re-runs are no-ops.
3. `prune`: delete every non-value env-group path, every legacy copy and every fenced or stale id's residue.
4. Rehearse on dev-8 (`bash scripts/dev-env.sh 8 up`): seed each old shape with the current release, then dry-run → apply → start the new code → verify → prune. Record the reports here.

## Files

- `lego/backend/internal/envgroups/cutover.go` (new), its test file
- `lego/backend/cmd/api/main.go` (or a dedicated command)

## Acceptance criteria

- [ ] On the dev-8 rehearsal, every seeded live group reads back identically through REST after `apply`
- [ ] After `prune`, OpenBao holds only value maps
- [ ] `apply` is idempotent and refuses duplicate names with a report
