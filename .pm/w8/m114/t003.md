## Objective

Every env-group read and write of non-secret state goes through the store. OpenBao is touched only for the env and files value maps at the group's workspace tenant. The serving code has no legacy-tenant fallback, no locator, no name claim, no fence and no store-off branch.

## Context

- Replace: `meta.go` (`encodeMeta`, `mutateMetaCAS`, `clearMetaCAS`, `writeMeta*`); `listScopedMeta` / `scanGroups` / `readMeta` (`service.go:451`, `:483`, `:2085`); `listGroupIDs` and locators (`tenant.go:122`, `:181`); name claims (`service.go:1741`, `:1768`); `plantDeletedMetaFence` (`service.go:995`); links held in meta (`links.go`).
- Verbs to cover: create, get, list (filtered), rename, delete, link/unlink, clone (`clone.go`), initial links at service create (`initial_links.go`), set environment.
- Wiring: `lego/backend/internal/api/server.go` (envgroups service construction).

## Steps

1. Route each verb's metadata through the store. Create and delete run their row change and value writes in an order t001 fixed: the row is the commit point, and value writes are idempotent before it and cleaned up after it.
2. Read and write values only at the workspace-tenant `env` / `files` paths.
3. Require the store: no `s.Store == nil` / `Workspace == nil` behavior for env groups.
4. Bump the revision-token prefix per t001.
5. Leave the old metadata code reachable only from the migrator package t006 creates — not from serving code.
