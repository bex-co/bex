## Objective

Pin the properties the end state relies on, so neither a metadata read nor a KV workaround can come back. Assert call counts and constraint outcomes, not wall-clock time.

## Steps

1. Postgres tests: the concurrent same-name create and rename race (one success, one `ENV_GROUP_NAME_EXISTS`); FK cascades on app, environment and tenant delete; a deleted id cannot be re-created by a delayed writer.
2. With a counting `core.SecretKV`: env-group list, environment membership and Blueprint name resolution make zero OpenBao calls; get reads only value maps; no write targets a `meta`, `revision`, `op` record, name-claim or legacy path.
3. Content saves on the new store: a stale `expectedRevision` conflict; interrupted-save recovery for each phase; `op/` value maps gone after every terminal path.
4. Confirm each test fails against the pre-migration code for the stated reason. The migrator's own tests left with it in t008.
