# Backward log pages without a startTime hand out inverted cursors past the first hour

Why: following `nextStartTime`/`nextEndTime` is Render's documented way to page logs, and the official CLI's scroll-to-load path. When a query omits `startTime`, a backward page whose oldest line is more than an hour old returns cursors whose start is after their end, and following them returns a 400.

Found by the w8/123 code review on 2026-10-19 with a probe test; reproduced in a unit test, not live. Two defaults disagree about the window when `startTime` is omitted:

- **The read.** `lokiRange` (`lego/backend/internal/logs/loki.go`) looks back `lokiLookback`, which is seven days.
- **The cursors.** `resolveCursorWindow` (`render.go`) defaults the cursor start to `earlier(end, now) − 1h`.

A backward page returns `nextStartTime` = that one-hour start and `nextEndTime` = one nanosecond before the page's oldest line. When that line is older than an hour, the start is after the end.

Fix direction:

1. Decide the omitted-start default against Render's logs API reference.
2. Use the same default in both places, either the seven-day read for the cursors or a one-hour read.
3. Add a backward-paging test with lines older than an hour and no `startTime` that follows the cursors to the end. It must not hit a 400 or repeat a line.

Record the default in ADR010's logs section.
