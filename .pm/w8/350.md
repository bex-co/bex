# A native cron job's own command and the pre-deploy command miss a secret file the image was not built with, until the next build

Why: Render puts every secret file in a native service's root directory "at runtime", with no condition (render.com/docs/configure-environment-variables). Since w8/348, `native-init` links the mounted files at every start, but these two workloads start without it, so after a deploy that does not build they still see only the names the image was built with.

- Severity: minor. It affects a cron job with its own command, and a paid service's pre-deploy command, after an environment-group link, a file added to a linked group or a "Save and deploy" that adds a file. The file is at `/etc/secrets/<name>` throughout, and the next build puts it in the root.
- Found by: the w8/348 worker, 2026-11-20, from the code. Not reproduced on production.

## Where

- The cron container replaces the image's entrypoint when the cron has a command: `container.Command = shellCommand(command)` in `cronPodSpec` (`lego/operator/internal/controller/app_controller.go`, the `default:` branch). Only a cron linked to a native build source passes the command as `Args` to the entrypoint (`launchNativeArgs`, w2/m262).
- The pre-deploy Job runs `preDeployArgv`, which for a native image is `/bin/sh -c <command>` as the container's `Command` (`app_controller.go`, `preDeployArgv`, w8/172).
- Both use the release's image and mount `/etc/secrets`, so they get the image's build-time links (`nativeSecretFileLinks`, `lego/operator/internal/build/native.go`) and nothing else.

## Options

- Run both through the image's entrypoint (`Args` instead of `Command`), as `launchNativeArgs` does. A native image's entrypoint is `native-init` or `[]` since w8/m61. Check images from before w8/m61, whose toolchain entrypoint would then receive the arguments, and whether rewriting the CronJob template on the operator upgrade is safe.
- Or give the `/bin/sh -c` script the same link step as a prefix, for native images only.

## Acceptance

- A native cron job with its own command, linked to a group with a secret file after its last build, reads `./<name>` on its next triggered run with no build in between. After an unlink the name is gone from the root.
- The same for a paid service's pre-deploy command on the link deploy.
- Regression tests in the operator suite. Docker and image services keep `/etc/secrets` only.
