# Allow command updates on image-runtime cron jobs in the upstream CLI

Why: CLI-created image cron jobs execute their configured work, but the same CLI cannot replace or clear that command, blocking ordinary terminal maintenance.

**Major, upstream CLI builder; estimate 50m** for an upstream correction/regression proposal and Bex compatibility documentation. Upstream acceptance and a published pin refresh are external dependencies; this finding authorizes no Bex fork. Filed through /pm from w8 live CLI QA sweep 30, 2026-10-09 UTC. Product source was not edited or shipped by this hunt.

## Producer, consumer and concrete correction

- `cmd/serviceupdate.go:115–153` resolves the ID, reads the service, validates the flags for its type, calls `BuildUpdateRequest`, and only then submits PATCH. One production caller uses this builder; name/ID selectors share it.
- `pkg/service/update.go:285–311,337–353` dispatches a cron to its runtime helper. `:403–411` rejects any present CronCommand together with BuildCommand in the image helper and returns no body. A private exact-pin probe reproduces both replacement and explicit-empty clearing failures. Schedule-only, image-build refusal and native/Docker command controls pass. [Probe source](evidence/072/probe.go.txt), [exact module](evidence/072/go.mod.txt), [expected failing result](evidence/072/probe-result.txt). This probes the actual imported builder; it does not model a replacement implementation.
- The producer already accepts commands on create through `pkg/service/create.go:315–329` for image crons. Docker updates use `dockerEnvSpecificDetailsFromInput` at `update.go:427–448`; native updates use startCommand. The affected branch is image-runtime cron command updates, including empty values. Native/Docker cron updates, ordinary image web-service start/build refusal, and unrelated datastores are separate controls.
- Bex REST folds either command spelling in `lego/backend/internal/apps/rest.go:883–885,982–1018`; `settings.go:378–398` and `service.go:4042` pass a cron command to the shared domain. The API-only controls below prove the server accepts and executes the update.

Proposed upstream correction: separate the BuildCommand refusal from CronCommand in `buildImageUpdateEnvSpecificDetailsForCronJob`. Retain the registry-credential pairing guard, omission semantics and image build-command refusal; serialize a present CronCommand, including empty string, through the existing Docker-command PATCH helper. Target wire body is `{"serviceDetails":{"envSpecificDetails":{"dockerCommand":"<requested command>"}}}`. Keep the image runtime truthful. [Official pinned source](https://github.com/render-oss/cli/blob/a764810a768202704e7206eb7b87a47211fcd98e/pkg/service/update.go#L403) and [Render cron documentation](https://render.com/docs/cronjobs) support image command overrides. The fetched [upstream main source](https://raw.githubusercontent.com/render-oss/cli/main/pkg/service/update.go) also retains the image guard; external issue/PR state and Render-production behavior were not exhaustively checked.
