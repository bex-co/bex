## Outcome (2026-10-09)

The fix sits at the one prune boundary every App passes through. Every producer — REST, GraphQL `graphql.go`, the three MCP creates and Blueprint `createFromStack` — calls the shared `apps.Service.Create` → `writeInitialApp`/`writeNewApp`. Their only CR delete path is this loop (`grep Client.Delete internal/store/*.go`: only reconciler.go and namespaces.go). So all five store-managed types (web, private, worker, cron, static) and every CR-only field (native build/start, health, predeploy, env and secret-file references) are covered without per-type code. A pending grouped row is returned by `GetApp` regardless of `creation_pending`, so it now also blocks deletion. Datastores use a separate observation pass and are untouched. Namespace pruning (`namespaces.go` `pruneOrphans`) has the same stale-snapshot shape and is reachable because bex-api's `EnsureWorkspaceNamespace` creates namespaces synchronously. It is kept out of this fix per scope and filed as w8/071.
