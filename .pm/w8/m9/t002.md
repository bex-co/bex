## Objective

Extend the metering collector to query actual volume usage for CNPG (Postgres) and Valkey (KeyValue) instances and roll it into the hourly `storage_gb_seconds` meter.

## Context

- `w8/m1`'s collector already runs on an hourly cadence for compute instance-seconds; `w8/m5` extended it to meter Postgres/KeyValue compute.
- Volume usage is available via k8s PVC status (`status.capacity`) or CNPG/Valkey-specific metrics if already scraped (check `w1/m17`/`w1/m25` Postgres observability for an existing volume-usage source before adding a new one).

## Steps

1. Reuse `w1/m25`'s Postgres observability metrics for actual volume bytes used, if available; otherwise query PVC status directly.
2. Compute GB-hours for the metering interval and add to the `storage_gb_seconds` column.
3. Mirror for KeyValue/Valkey.

- `lego/backend/internal/usage/` (collector)

## Acceptance criteria

- [ ] Hourly rollup includes accurate storage-GB-seconds for both resource types.
- [ ] No double-counting or missed intervals across collector runs.
