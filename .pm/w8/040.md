# 040 — Restart is accepted for cron jobs; Render refuses it

Why: Render's restart contract is "Restart the service with the provided ID. **Not supported for cron jobs.**" bex answers 200 "restarted successfully" and opens a `live` deploy row for a cron job that has no running instance. The CLI user is told something happened when it did not, and the REST surface diverges from the contract it claims.

Severity: minor. Attribution: server (`lego/backend/internal/deploys`), with a dashboard affordance.

## Repro (2026-10-03, `/qa-find-bugs-cli` w8 loop sweep 2)

Production (images pinned `8f6a69e9e`), `bex v0.2.1` (pin v2.27.0), human device login, workspace `bex-canary`. Fixture: free cron `srv-db0bc609ohsc73e5r1vg` (`busybox:1.36`, schedule `0 0 1 1 *`), deleted afterwards (`GET` 404).

```text
$ bex restart srv-db0bc609ohsc73e5r1vg --confirm -o text   → exit 0  "srv-… restarted successfully"
$ bex deploys list srv-… -o json                             → dep-db0bcb7fq78s73et1dj0 live api / dep-…200 deactivated create
POST /v1/services/srv-…/restart                              → HTTP 200
```

No cron run was triggered, so nothing observable restarted.

## Mechanism

`lego/backend/internal/deploys/service.go:532` `Restart` has no service-type guard. `restartSelectedRelease` (`rollback_config.go:93`) opens a selected release for any non-static type, and the static path falls through to a commit-pinned rebuild. REST `POST /v1/services/{id}/restart`, GraphQL `restartServer`, MCP `restart_service` and the dashboard Restart action all route through this verb. `dashboard/src/features/services/components/service-row-actions.tsx` offers Restart without an `isCron` check, unlike the specific-commit deploy (`manual-deploy-button.tsx:87-88`, which already cites the same Render sentence).

## Fix

- In `Restart`, refuse `TypeCronJob` before any mutation with a named 400 (`core.ErrBadRequest`, for example `restart is not supported for cron jobs; trigger a run instead`). REST, GraphQL and MCP inherit it.
- Hide or disable Restart for cron jobs in the dashboard row actions and the detail header, with the same reason.
- Leave static sites unchanged. Render does not exclude them, and bex's rebuild-at-live-commit is the documented behavior.

## Acceptance

- [ ] `bex restart <cron>` exits 1 with the named 400; no deploy row is opened (`deploys list` unchanged).
- [ ] The same refusal comes from GraphQL `restartServer` and MCP `restart_service`. The dashboard offers no Restart on a cron job.
- [ ] Controls: restart of a web service and of a static site still succeeds.

`rg -i 'not supported for cron' .pm docs` finds only the specific-commit deploy (`w1/done/m145`, `w1/done/m148`), which is already refused. Nothing covers restart.
