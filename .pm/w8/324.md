# A static-site redirect rule drops the request's query string (`/old/x?v=1` → `Location: …/x`), stamps the site's custom headers on the 301, and is skipped for `POST`, where Render forwards the query, sends a bare 301 and redirects every method

Why: a `type: redirect` rule is how a Render static site moves old URLs or sends heavy assets to a CDN. On Render the redirect carries the visitor's query string, so links keep cache-busters, tracking and OAuth parameters such as `?v=…`, `?ref=…` and `?code=…`. bex drops it, so the redirect target loses data the visitor sent. bex also adds the site's custom headers to the 301, which Render does not. And a `POST` to a redirected path is refused with 405 today (and answered an empty 200 once w8/319 rolls) instead of getting Render's 301. Two earlier items left this unanswered:

- w4/m154: "Incoming-query forwarding on redirects is **not** asserted as a defect: this sweep did not establish that policy".
- w8/319: "Whether Render applies a local redirect rule (301) to a non-`GET` request".

These captures answer both.

**Severity:** major (query data is lost on every redirected request). **Attribution:** server (static-server). **Estimate:** ~45m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `1b01`, 2026-11-14 03:25 UTC, released `bex v0.6.0`, `https://api.bex.co/v1/`, workspace `bex-canary`, production pin `ac206b76841b`.

## Render's behavior (captured 2026-11-14 ~03:20 UTC)

`wc3v.onrender.com`'s `render.yaml` (`jblanchette/wc3v`) has redirect rules such as `/assets/wc3icons/* → https://cdn.wc3v.com/assets/wc3icons/*` and `/maps/* → https://cdn.wc3v.com/maps/*`, and a `/*` `X-Frame-Options: SAMEORIGIN` header rule. Each response carries Render's `rndr-id`.

```
GET  /assets/wc3icons/foo.jpg?v=1&x=2  → 301  location: https://cdn.wc3v.com/assets/wc3icons/foo.jpg?v=1&x=2
GET  /assets/wc3icons/a%20b.jpg        → 301  location: https://cdn.wc3v.com/assets/wc3icons/a%20b.jpg
GET  /assets/wc3icons/sub/dir/x.png    → 301  location: https://cdn.wc3v.com/assets/wc3icons/sub/dir/x.png
HEAD /maps/X/map.jpg                   → 301  location: https://cdn.wc3v.com/maps/X/map.jpg
POST /maps/X/map.jpg                   → 301  location: https://cdn.wc3v.com/maps/X/map.jpg
```

Every 301 carries only `content-type: text/html; charset=utf-8` and `location`. There is no `x-frame-options` (the site's `/*` rule), no `strict-transport-security` and no `cache-control`, although the same site's `GET /` and its 404 page carry all three.

## bex (fixture `qa-20261114-1b01-rd`, `srv-dbrt7hhrr8ts738m9pdg`)

Repro: a static site from `octocat/Spoon-Knife`. `PUT /v1/services/<id>/routes` sets:

- `/ext/* → https://cdn.example.com/ext/*`
- `/loc/* → /target/*`

`PUT …/headers` sets `/* X-Frame-Options: SAMEORIGIN`. Then:

```
GET  /ext/foo.jpg?v=1&x=2  → 301  location: https://cdn.example.com/ext/foo.jpg      (query dropped)
                                  x-frame-options: SAMEORIGIN                         (rule stamped on the 301)
GET  /loc/x.txt?q=1        → 301  location: /target/x.txt                             (query dropped)
GET  /ext/a%20b.jpg        → 301  location: https://cdn.example.com/ext/a%20b.jpg     (matches Render)
HEAD /ext/x                → 301  location: https://cdn.example.com/ext/x              (matches Render)
POST /ext/x                → 405                                                       (Render: 301)
POST /loc/x.txt            → 405
```

The fixture was deleted afterwards and reads 404.

## Root cause

- **Query:** the redirect branch of `Handler.ServeHTTP` (`lego/operator/internal/staticserver/staticserver.go:320-327`) writes `Location: target.String()`. `target` is the rule's expanded destination (`matchRoutes` → `expandDestCaptures`, `:764-781`), so the request's `r.URL.RawQuery` never reaches it. w4/m154 kept "configured query/fragment values literal" and left incoming queries undecided.
- **Headers:** the same branch calls `applyHeaders(w.Header(), site.Headers, requestPath)` before `http.Redirect`. w4/m101's "every resolved-site response class carries matching custom headers" covers the 301.
- **Methods:** `serveOtherMethod` (`:386-395`, the w8/319 fix d11a1bc33, not yet on production) proxies only an external rewrite and answers every other matched rule with an empty 200. A redirect rule is therefore never applied to `POST`, `PUT`, `DELETE`, `PATCH` or `OPTIONS`. Production still answers 405.

## Fix (target behavior)

- **Query:** a matched redirect appends the request's raw query to the expanded destination.
  - When the configured destination has no query of its own: `Location = destination + "?" + RawQuery`.
  - When it has one, either join them with `&` or keep the configured one. Render's choice is uncaptured, so pick one, test it and record it.
  - An empty request query adds nothing, so there is no trailing `?`.
  - The w4/384 directory redirect already keeps the query and is unchanged.
- **Headers:** send the 301 without custom rules, HSTS or the default cache policy: only `Content-Type`, the `Location` and `http.Redirect`'s body. The 400 "invalid redirect target" refusal keeps w4/m101's behavior, since it is uncaptured.
- **Methods:**
  - In `serveOtherMethod`, a path whose first matching rule is a redirect answers the same 301 and `Location`, query included, as `GET`.
  - An external rewrite still proxies (w8/184).
  - Anything else keeps w8/319's empty 200.
  - A local rewrite on a non-`GET` request stays an empty 200, as captured on `wrappedforlinkedin.onrender.com`'s `/* → /index.html` site.
- Amend ADR029 (§ Destination URLs, the w4/m101 sentence at :136, and w8/319's paragraph) and the ADR018 static-site row, citing the captures above.

## Blast radius

- Every static site with a redirect rule, which all share the static-server.
- `matchRoutes` is shared with rewrites, which must not gain the query: a rewrite serves a file, and the query never reaches it.
- `serveOtherMethod` is reached only for non-`GET`/`HEAD` methods.
- Tests that pin the dropped query or the stamped header need updating, such as w4/m154's literal-query cases and w4/m101's `301 carries the rule`.

## Acceptance

- Handler tests:
  - a redirect with `?v=1&x=2` → `Location` ends `?v=1&x=2`;
  - a redirect with no query → no `?`;
  - a configured destination query combined as chosen;
  - the 301 carries no custom rule;
  - `POST`, `PUT`, `DELETE`, `PATCH` and `OPTIONS` on a redirected path → 301 with the same `Location`;
  - `POST` on a local-rewrite path → empty 200;
  - an external rewrite still proxies `POST`.
- Live, after the static-server rolls: the fixture matrix above matches Render's capture line for line. Delete the fixture.
