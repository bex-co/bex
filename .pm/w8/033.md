# 033 — `deploys create` image/commit input gaps: `--commit` on an image service silently re-rolls the last image, invalid OCI refs are accepted, and every registry refusal blames "whitespace or shell metacharacters"

Why: `bex deploys create <image-srv> --commit <sha>` answers 201 and redeploys whatever image the row last requested, which in our run was a broken one, instead of refusing like `--image` on a repo service does. Malformed references (uppercase repo, truncated digest) are queued and then sit open with no diagnosis. A caller refused for using `localhost`, a private IP or an untrusted registry is told the ref has whitespace or shell metacharacters, which it does not.

Live, 2026-09-27, production `4a0422577`, `bex v0.2.1` (pin v2.27.0), human device login, workspace `bex-canary`. Found by the `/qa-find-bugs-cli` sweep 54. Fixture: free image web service `srv-dasihua1pbgc73a24jsg` (`mendhak/http-https-echo`, deleted).

```text
# control: digest pinning works
--image docker.io/mendhak/http-https-echo@sha256:b9b4…8532 --wait   → live in 32 s, imagePath records the digest, site 200

# accepted though invalid (OCI: repository must be lowercase; sha256 digest is 64 hex)
--image docker.io/mendhak/HTTP-https-echo:35          → 201 dep-dasiihjncejs739qit7g
--image docker.io/mendhak/http-https-echo@sha256:deadbeef → 201, then update_in_progress with NO stallReason after 2+ min

# --commit on an image-backed service: accepted, commit ignored, last row image re-rolled
--commit abc1234   → 201 dep-dasiii21pbgc73a24jvg  image.ref = …@sha256:deadbeef, commit = null   (twice)

# refused with a misleading reason
--image localhost:5000/qa54/img:1                      → 400 "imageUrl must be an OCI reference (no whitespace or shell metacharacters)"
--image http://docker.io/mendhak/http-https-echo:35    → same text
```

## Mechanism

- `lego/backend/internal/deploys/service.go:580-640` `validateTrigger` refuses `imageUrl` on repo services (`:606-609`) and `commitId` on cron jobs (`:630-632`), but has **no refusal for `commitId` on an image-backed service**. `triggerFetched` then proceeds with the row's current image.
- `lego/backend/internal/store/api.go:718-741` `ValidImage` folds three different refusals into one boolean: grammar (`imageRE`), loopback/private host (codex r7 F6), and "not in the trusted registry set". The caller (`deploys/service.go:613-614`, and `apps/service.go:2552,3755`, `store/api.go:413`) prints the same whitespace/metacharacter sentence for all of them. `imageRE` accepts uppercase repository paths and digests of any length.
- A pull of an invalid reference (`InvalidImageName`) is not classified by the w8/m44 stuck-pod diagnosis, so the row shows no `stallReason`.

## Fix

1. `validateTrigger`: `commitId` on a service with `Spec.Image != ""` and no repo → 400 `commitId is not supported for image-backed services — deploy an image tag or digest with imageUrl`, mirroring the repo-service `imageUrl` refusal. Keep the restart exemption.
2. Split `ValidImage` into a reason-returning check with three named refusals: malformed reference (with the OCI rule broken: uppercase repository, bad digest), "registry host `<h>` is not allowed (loopback/private address)", and "registry `<h>` is not in this installation's trusted registries". Tighten `imageRE` to the distribution reference grammar: lowercase path components, `algo:hex` digest with the right length for sha256/sha512.
3. Add `InvalidImageName` to the w8/m44 image-pull stall/failure diagnosis.
