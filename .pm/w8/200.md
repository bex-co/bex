# Blocker: every prebuilt-image web service create fails with `spec.portMode: Unsupported value: "web-image-v1"`: w4/m243 added the port mode without adding it to the App CRD enum

Why: since platform pin `8383024017b8` (2026-10-25 20:11 UTC), `bex services create --type web_service --image …` (with or without `PORT`) answers 400 and creates nothing, on every surface that creates an image web service (CLI/REST, and so GraphQL/MCP/dashboard and Blueprints through the same path). Native repo builds still work. Render-compatible image deploys, the most common bex onboarding path, are down for every workspace.

Severity: **blocker**. Source: `/qa-find-bugs-cli` loop sweep k2m4, 2026-10-25 21:01 UTC, bex v0.3.3, pin Render CLI v2.27.0 `a764810a7682`, platform pin `8383024017b8`, `https://api.bex.co/v1/`, `bex-canary`, human device login.

## Evidence

```text
$ bex services create --type web_service --name qa-20261025-k2m4-port --plan free --image docker.io/library/nginx:1.27-alpine --env-var PORT=80 --confirm -o json
Error: received response code 400: bad request: spec.portMode: Unsupported value: "web-image-v1": supported values: "configured-v1", "image-v1", "image-configured-v1"
$ bex services create --type web_service --name qa-20261025-k2m4-noport --plan free --image docker.io/traefik/whoami:v1.10.3 --confirm -o json
Error: … spec.portMode: Unsupported value: "web-image-v1" …          (same)
$ bex services create --type web_service --name qa-20261025-k2m4-native --plan free --repo https://github.com/render-examples/express-hello-world --branch main --runtime node --build-command yarn --start-command "node app.js" --confirm -o json
exit 0 → srv-dbf6sfjiigcs738vnm8g (control; deleted)
```

The same image create succeeded on the previous pin `bd6423e5e46f` (sweeps 2026-10-25 b2c4/k2m4 earlier: `traefik/whoami` with `PORT=80` → live).

## Root cause

- w4/m243 (`3f9140d3d` "Docker web services serve on their image's exposed port", `5e591855c` "allow web image port modes in the store check") added `PortModeWebImageV1 = "web-image-v1"` (and `web-image-configured-v1`) in `lego/types/v1alpha1/image_network.go:32` and the store CHECK (`lego/backend/internal/store/migrations/0163_web_image_port_mode.up.sql:5`).
- The App CRD enum was not updated. `lego/types/v1alpha1/app_types.go:626` is still `// +kubebuilder:validation:Enum=configured-v1;image-v1;image-configured-v1`, and the generated `lego/operator/config/crd/bases/app.bex.co_apps.yaml:705-708` lists only those three. The Kubernetes API server rejects every App bex-api now writes for an image web service.

## Fix

Add `web-image-v1;web-image-configured-v1` to the kubebuilder enum at `app_types.go:626`, regenerate the CRD (`make manifests` in `lego/operator/`), ship and roll the CRD through GitOps. Add a test that fails when a `PortMode*` constant is missing from the CRD enum (the drift guard that would have caught this). Until it deploys, consider reverting the backend's use of the new mode (`3f9140d3d`) to restore image creates immediately.

## Acceptance

- `bex services create --type web_service --plan free --image docker.io/traefik/whoami:v1.10.3 [--env-var PORT=80] --confirm -o json` → exit 0, `live`, 200. Same for `nginx:1.27-alpine` without `PORT` (m243's intent: serves on the image's exposed port 80).
- CI test: every `PortMode*` constant appears in the generated CRD enum.

## Dedupe

New regression from w4/m243 (2026-10-25). Not filed elsewhere (searched `.pm` for `web-image-v1`, `portMode` enum).
