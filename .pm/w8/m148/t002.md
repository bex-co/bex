## Objective

When a BuildKit step in a platform-owned stage (`bex-hugo-*`, `bex-pnpm-*`, other `bex-` helper stages) fails, `deploy_ended.failureReason` says bex could not download that toolchain (with the HTTP status or error when known) and that retrying is the remedy. The raw BuildKit line stays in the build log.

## Context

- `failureReason` construction for "build failed in the docker build step" (grep the operator/build packages).
- Observed raw reason: `build failed in the docker build step:\nerror: failed to solve: digest mismatch sha256:bef140a1…: sha256:b382aacb…`.

## Steps

1. Classify BuildKit errors by the failing step's stage name. A `digest mismatch` or HTTP error on a platform `ADD` becomes a platform-download failure.
2. Keep user build-command failures unchanged.

## Acceptance criteria

- [ ] Test: a fake BuildKit error on `bex-hugo-amd64` yields the named message. A failure in the user's build command keeps its existing reason.
