```sql
WITH series AS (
  SELECT workspace_id,
         service_id,
         kind,
         MIN(window_start) AS first_window,
         MAX(window_start) AS last_window,
         COUNT(*) AS recorded_windows,
         1 + EXTRACT(EPOCH FROM (MAX(window_start) - MIN(window_start))) / 3600
           AS expected_windows,
         SUM(quantity) AS total
  FROM usage_hourly
  WHERE resource_kind = 'service'
    AND (
      (kind = 'build_seconds' AND window_start >= TIMESTAMPTZ '2026-07-14T23:00:00Z')
      OR
      (kind = 'egress_bytes' AND window_start >= TIMESTAMPTZ '2026-07-16T09:00:00Z')
    )
  GROUP BY workspace_id, service_id, kind
)
SELECT *, expected_windows - recorded_windows AS missing_windows
FROM series
ORDER BY workspace_id, service_id, kind;
```

After `m11`, zero rows are collector-success anchors: `recorded_windows = expected_windows` therefore proves there are no internal hourly holes between a service/meter series' first and last row. ## Pickup inputs and constraints

- Re-verify the Render anchor from first-party docs at pickup. As of 2026-07-14, current Hobby includes [**5 GB outbound bandwidth**](https://render.com/docs/outbound-bandwidth) and [**500 Starter pipeline minutes**](https://render.com/docs/build-pipeline) per calendar month. Render's [free-instance documentation](https://render.com/docs/free) says it emails when usage is approaching the limit and again after it is exceeded; its public docs do not state the approaching-limit percentage.
- Enforcement is meter-specific, not one `warn-only`/`suspend` toggle. With no payment method, Render spins down workspace services after bandwidth exhaustion, but build-minute exhaustion stops new pipeline tasks while already-running services stay active. bex has no payment/overage path, so these are the relevant comparison semantics.
- The `w8/m15` production implementation composes exact-router HTTP responses, metered WebSocket downstream connections, direct-to-public App traffic, and public Postgres/Key Value response traffic. It passed the focused production-equivalent Cilium matrix and the first full production evidence hour. Keep its `2026-07-16T09:00:00Z` bandwidth origin separate from the retained July 14 build-minute origin when evaluating the two caps.
- A quota suspension must be durable and distinct from the user-controlled `App.spec.suspended` flag, or a user can accidentally clear enforcement with Resume (and the system cannot distinguish manual suspension from quota suspension at the next month boundary).
- Evaluate calendar-month totals in UTC and persist one threshold-delivery record per `(workspace, meter, period, threshold)` so retries/restarts cannot duplicate approaching/exceeded email. Reset enforcement automatically at the next month boundary.
- Reuse bex-api's shared SMTP mailer and identity-email lookup. Decide recipients explicitly (workspace owner/admin/billing roles versus all members); deploy-notification opt-outs do not implicitly apply to quota/security mail.
