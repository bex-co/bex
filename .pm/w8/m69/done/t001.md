## Objective

Fix native CLI create routing so its startCommand is baked into the native artifact without being synthesized into an opaque image override. Use the runtime/build-specific existing helpers while retaining Docker/image alias acceptance and explicit Bex command behavior. Qualify native CLI updates through setStartCommand/SetCommands and legacy duplicates; preserve explicit clear/omit semantics. No global shellBinary change or CLI workaround.

## Done 2026-10-15

REST create (`rest.go` `toCreateRequest`) now aliases a cron's `envSpecificDetails.startCommand` to its run command only when the build is not native. A native runtime keeps it as `StartCommand`, which its build bakes into the generated `/bin/bash -c` CMD, and leaves `Command` empty. Docker, image and buildpack crons keep the w9/m165 alias; MCP create already aliased for images only. `setStartCommand` (`build_strategy.go`) routes a native cron's start command update to `StartCommand` and drops any `Command` override, so a legacy duplicate (`Command == StartCommand`, created before this fix) moves to the native role on its next update. A blank write drops only the override, since the native build needs its start command. REST PATCH, MCP `update_service`, GraphQL `setStartCommand` and the settings preflight all reach this setter. Bex's explicit `command` (`SetCronJob`/`updateCronJob`, REST `command`) stays the documented override. The global `shellBinary`, CLI and wire spelling are unchanged. Existing native duplicates are not bulk-migrated: they keep running `/bin/sh` until their command is next written.
