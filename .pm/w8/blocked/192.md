# Retire the implicit static-site SPA fallback for sites created before 2026-10-23

Why: w8/183 gave sites created on or after 2026-10-23 Render's miss handling (404 with the site's `404.html`, client-side routing by an explicit `/* → /index.html` rewrite). Sites created earlier keep the implicit root-`index.html` fallback (`staticserver.SPAFallbackCutoff`) so no running single-page app loses its deep links on an operator upgrade. That residual is a recorded transitional divergence ([ADR029 § Miss handling](../../docs/ADR029-static-sites.md), ADR018's static-site row). Under ADR008 § Render parity first it needs a dated widen-to-every-site step.

**Severity:** minor. **Attribution:** platform runtime (static-server) plus a one-time data migration. **Estimate:** 45m. **Source:** w8/183 (2026-10-22). **Due:** 2026-11-22.

## Fix

1. List the static sites created before the cutoff whose published `index.html` is a single-page app (no rule in `routes`, no `404.html`): the production App list filtered by `spec.type=static_site`.
2. Add `{type: rewrite, source: /*, destination: /index.html}` to each through the normal routes API, so its deep links keep working under Render's rules.
3. Remove `SPAFallbackCutoff` and `Site.NoSPAFallback` (and the `spaFallback` path), so every site gets Render's miss handling. Update ADR029 § Miss handling and ADR018's static-site row.

## Acceptance

- Unit: a site created before the former cutoff answers a miss with 404 and its `404.html`; the SPA rewrite serves the index with 200.
- Live: a pre-cutoff site with the rewrite still serves a deep link; one without it answers 404.
