## Done 2026-10-15

- **Readback** (`render.go`): a native cron's `envSpecificDetails.startCommand` is its override when one is set, otherwise its baked `StartCommand`. A correct native-role cron no longer reads back empty, and the CLI clone re-sends the real command; explicit overrides still win.
- **Blueprint** (`blueprint_plan.go` `applyBlueprintCommand`): a genuine edit of a native cron's command goes through `setStartCommand`. The w4/174 unchanged guard is kept, and a legacy override already equal to the declared command is left alone, so the fix opens no deploy by itself.
- **GraphQL:** keeps distinct `command`/`startCommand` roles (`TestNativeCronStartCommandIsNotACommandOverride` passes).
- **Blueprint generate:** already emits `StartCommand`, replaced by a set override.
- **Dashboard** (`cron-deploy-section.tsx`): a native cron's Command row shows the override when one is set, otherwise its `startCommand`, and saves through a new `useCronJob().setStartCommand`, which shares the stale-save guard, protected-environment retry and `publish` re-read with `updateCronJob`. The row is required for native crons (a blank draft is blocked), and re-saving an unchanged override moves it into the start command (a repair path for legacy duplicates). Container crons are unchanged. The Schedule row still replays only the explicit override, never `startCommand`. `SetStartCommand` now also returns `command`, so the dropped override leaves the Apollo cache. This also fixes a pre-existing bug where a failed `updateCronJob` left `busy` set. The skeleton was measured in a browser at 1280px and 375px against a scratch copy of the local stub: the native ready card is 2px shorter (no Optional badge) and the hint wraps the same, so the skeleton is unchanged. Against the original component, 9 native tests fail across the four component/route files, and `cron-late-read-rollback` now has a native case. `yarn typecheck`/`lint`/prettier pass; full `yarn test` passes except the known load-flaky `deploys-history-filters`.
- **Operator:** the native/image/buildpack launch and carrying-release logic is unchanged. Its existing test already covers a native cron with an empty override launching the image's own CMD.
- **Expectations updated** from the old override role to the native role: `TestNativeCronCommandUnchanged`, the go/node cases of `TestBlueprintCronCommandClearingAndUpdateReapply` and `TestBlueprintCronFirstReapplyPreservesCommand`, and the REST cron/native rule in `TestCreateWireFieldsReachTheRequest`.
