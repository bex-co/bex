## Objective

Make `SetAppImage` + `CreateDeploy` (+ the release-generation stamp) one serialized unit per app, for example `SELECT … FOR UPDATE` on the app row or a per-app advisory lock in `store`, so two triggers cannot interleave their row and deploy writes. Keep parameter-free triggers, restarts, rollbacks and the deploy hook on the same path.

## Acceptance criteria

- [ ] The t001 test's row/deploy-row mismatch no longer occurs.

## Outcome (2026-09-27) — done

`deploys.openRelease` is the one critical section for `triggerFetched` (API, deploy hook, restart) and `Rollback`: the row image write, the CR patch and the deploy-row open all run under `withTriggerLock`. That's `store.PGStore.WithAppAdvisoryLock` (`pg_advisory_xact_lock(hashtextextended('deploy-trigger:'||appID))`, one domain per app, across replicas; `var _ AppLocker = (*store.PGStore)(nil)` pins it), or an in-process per-app mutex for stores without it. `store/advisory_pg_test.go` `TestWithAppAdvisoryLockSerializesOneApp` mirrors the tenant-lock test. It runs in CI against real Postgres; it wasn't run locally because Docker Desktop's VM is out of disk (`initdb: No space left on device`).
