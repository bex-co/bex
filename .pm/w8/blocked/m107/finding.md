# Native ZIP creation fails because the documented zip tool is absent

Why: ordinary native asset builds and download handlers cannot create ZIP archives with the supplied toolchain.

**Severity:** major. **Attribution:** shared operator native image assembly. Ordinary functional CLI sweep434, 2026-10-17, noninteractive JSON, api.bex.co/v1, isolated human QA bex-canary/tea-daif693dqjvc73e7as3g. Published Bex 0.3.2/a6350da0 and unmodified Render 2.27.0/a764810a7682. Source HEAD is captured; actual serving SHA/OCI is unknown. [Complete evidence](evidence/cli-sweep434/README.md).

## Reproduce and isolate

Both unchanged clients use supported `services create --type web_service --plan free --runtime node --auto-deploy=false --confirm -o json`, fresh names and public git-fixtures/basic/master at commit `6ecf0ef2c2dffb796033e5a02219af86ec6584e5`. The bounded authored source pack checks the original LICENSE/CHANGELOG, then runs a Node build that invokes the real `zip -X -9 -q` on six harmless owned files. Start is `node qa434-app.cjs serve`. Exact original/control commands, actual wire responses and native outputs are retained.

Both original creates return unchanged POST 201/native exit 0. Their first builds fail `spawnSync zip ENOENT` after proving original source bytes, Node 24 and an existing UnZip extractor; the unpublished URL returns 404. Adding only `apt-get update -qq && apt-get install -y --no-install-recommends zip` to each authored build makes both supported native updates exit 0 and their single replacements become Live. Source, archive flags, file data, start command, runtime, Free plan and explicit environment are unchanged.

Each successful build creates an actual ZIP; each HTTP request creates another archive at runtime. Four JSON responses and two raw ZIP downloads contain exact source files plus empty, binary, space-named and Unicode-text files. Python's independent ZIP/zlib decoder verifies all six ordered unique members, complete bytes, lengths, CRC32, stored/deflated methods and a real deflated member; JSON archive size/SHA and build/runtime source identity also agree. Native UnZip tests succeed. Six exact marker/boot/nonce/archive-SHA log events, twelve shared REST/GraphQL/MCP command/source/Free reads and four explicit-env reads agree. Original runtime was never entered because its build failed; runtime ZIP production is proved by install-only controls, not by an unmodified original service.

[Render's native tool contract](https://render.com/docs/native-runtimes#tools-and-utilities) includes ZIP creation and extraction at build and runtime for all native runtimes. Existing `unzip`/`zipinfo` are extractors and do not supply `zip`. This authored project tests that documented utility, not a feature of the public source carrier. Render-hosted comparative execution and an exact Render ZIP version are unverified.
