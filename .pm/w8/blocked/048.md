# 048 — Cron jobs are sold on `free`, but Render's API types every cron plan as `paidPlan` (decided: match Render)

Why: ADR030 §7 and w1/111 keep free cron jobs on the stated premise that "Render sells both that way". Render's own API contract and docs say otherwise, so the recorded reason for the divergence is false.

Severity: major for pricing parity (a plan the Render contract cannot express is accepted on create, update and Blueprint). **Decision needed before implementation:** match Render (cron paid-only), or keep free cron as a deliberate bex differentiator and correct the record.

## What Render says

- Pinned Render public API (`lego/backend/internal/api/openapi/render-public-api-1.json`): `cronJobDetailsPOST.plan` and `cronJobDetailsPATCH.plan` → `#/components/schemas/paidPlan` (`starter|standard|pro|pro_plus|pro_max|pro_ultra|0.5c-512mb…`, **no `free`**). They match `backgroundWorkerDetails{POST,PATCH}` and `privateServiceDetails{POST,PATCH}`. Only `webServiceDetails{POST,PATCH}` use `plan`, which includes `free`.
- render.com/docs/free: free instances exist for web services, Postgres, Key Value (and static sites); "Other service types don't support Free instances."
- render.com/docs/cronjobs: "There is a minimum monthly charge of $1 per cron job service."

## Mechanism

`lego/backend/internal/apps/service.go:3153-3168` `paidOnlyServiceType` is a two-type allowlist (worker, private service). Its comment says "Web services and cron jobs keep free — Render sells both that way". The same premise appears in `docs/ADR030-pricing.md` §7 ("Extended to Private Services 2026-09-28") and `.pm/w1/done/111.md:55`, with no source cited.

## Fix (if the decision is Render parity)

- Add `appv1alpha1.TypeCronJob` to `paidOnlyServiceType`. The create (`normalizeTierForType`, `:3136`), plan-change (`:3548`), settings-check (`settings_check.go:216`) and Blueprint probes (`stackHasPaidPlan`, `blueprintEstimatedPricing`) then follow automatically: a plan-less cron defaults to `starter`, and an explicit `free` gets a named 400.
- Dashboard: `dashboard/src/features/services/lib/instance-type.ts` paid-only filter (`:21-48`) gains `cron_job`.
- ADR030 §7: correct the premise, and apply the "existing free resources: transition, no silent conversion" paragraph to cron jobs. Production query: `SELECT id, name, tenant_id FROM apps WHERE type='cron_job' AND (tier='' OR tier='free')`. Known hits include QA fixtures and `examples/cron-demo` sweeps (w9/m44); notify owners.
- Pricing: confirm the cron minimum-charge story in ADR030 (Render: $1/month minimum, per-second billing).

If the decision is to keep free cron, only correct the comment, ADR030 §7 and the ADR018 parity row to name it a deliberate differentiator. That takes ~15m.

## Decision and implementation — 2026-10-15

**User decision (2026-10-15): match Render.** Cron jobs are paid-only, like background workers and private services.

- **Backend:** `paidOnlyServiceType` now includes `cron_job`. Create (REST, GraphQL, MCP `create_cron_job`), plan change (`SetPlan`/`SetPlanDryRun`), the settings check and the Blueprint probes all route through it. An explicit `free` gets `a cron_job requires a paid plan; plan must be one of starter|…`, and a plan-less cron already lands on `starter` (w1/122).
- **Blueprint:** the bex overlay that admitted `free` in Render's `cronPlan` (`admitBexFreeCronPlan`) is removed, so the pinned upstream enum refuses it at `#/services/n/plan`, worded like every other paid-only type. Generate Blueprint refuses a legacy free cron with a coded 400 (`BLUEPRINT_GENERATE_PAID_PLAN_REQUIRED`) naming the service and the remedy, instead of failing its self-check as a "bex bug".
- **Dashboard:** `PAID_ONLY_SERVICE_TYPES` includes `cron_job`, so the create form and plan picker never offer Free for a cron.
- **Repo:** `examples/cron-demo` declares `starter`, and `scripts/samples-lifecycle.sh` creates its cron and worker on `PAID_PLAN` (default `starter`).
- **Docs:** ADR030 §7/§8, ADR049 and ADR018 record the decision. MCP plan descriptions no longer advertise free for crons.
- **Tests:** `TestCronJobIsPaidOnly`, `TestPaidOnlyServiceTypes`, `TestBlueprintCronPlanFreeIsRefused`, `TestGenerateBlueprintRefusesALegacyFreeCron`, and the picker/skeleton grouping tests. Fixtures that created free crons now use `starter`. Backend `go test ./...`, `make lint-backend` and the full dashboard `yarn test`/`typecheck`/`lint` pass.
- **Existing free crons:** they keep running, and suspend, resume, schedule, command and env edits never re-check the tier. A Blueprint that still declares `plan: free` on a cron fails validation at that entry until it names a paid plan. A `SetPlan(free)` is refused, as for workers.

**Remaining before close:**

1. After deploy, run the hosted acceptance with `bex` against production: a free cron create exits 1 with the named refusal, a plan-less create returns `plan: starter`, `update --plan free` is refused, `blueprints validate` flags a free cron entry, and a free web service still creates. Clean up afterwards.
2. Run the ADR030 §7 inventory query against the production control-plane store (`… type IN ('background_worker','private_service','cron_job') AND (tier='' OR tier='free')`) and notify the owners of any free crons, especially Blueprint-managed ones, before their next sync.
