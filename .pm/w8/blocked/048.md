# 048 — Cron jobs are sold on `free`, but Render's API types every cron plan as `paidPlan` (needs a product decision)

Why: ADR030 §7 and w1/111 keep free cron jobs on the stated premise that "Render sells both that way". Render's own API contract and docs say otherwise, so the recorded reason for the divergence is false.

Severity: major for pricing parity (a plan the Render contract cannot express is accepted on create, update and Blueprint). **Decision needed before implementation:** match Render (cron paid-only), or keep free cron as a deliberate bex differentiator and correct the record.

## Evidence (2026-10-04, `/qa-find-bugs-cli` w8 loop, sweep 2)

Production, `bex v0.2.1` (pin Render CLI v2.27.0), workspace `bex-canary`, human device login.

```text
$ bex services create --type cron_job --name qa-20261004-3d35c5-cron --image docker.io/library/busybox:1.37 \
    --cron-schedule "*/5 * * * *" --cron-command "echo qa-cron-3d35c5" --plan free --confirm -o json
exit 0 → {"id":"srv-db1eau8a8tcs73b1a0l0","type":"cron_job","plan":"free",…}     # ran at 23:50 UTC, logged its marker; deleted
$ bex services create --type cron_job --name qa-20261004-3d35c5-cron2 … (no --plan) --confirm -o json
exit 0 → {"id":"srv-db1eaunhb1uc73ebifsg","plan":"free",…}                        # deleted
```

Blueprint, same session. `bex blueprints validate render.yaml -o json` on one `worker`, one `pserv` and one `cron`, all `plan: free`, flags only the first two:

```json
{"valid":false,"errors":[

 {"path":"services[1].plan","error":"service \"qa-bp-pserv\": a private_service requires a paid plan; …"}]}
```

## What Render says

- Pinned Render public API (`lego/backend/internal/api/openapi/render-public-api-1.json`): `cronJobDetailsPOST.plan` and `cronJobDetailsPATCH.plan` → `#/components/schemas/paidPlan` (`starter|standard|pro|pro_plus|pro_max|pro_ultra|0.5c-512mb…`, **no `free`**). They match `backgroundWorkerDetails{POST,PATCH}` and `privateServiceDetails{POST,PATCH}`. Only `webServiceDetails{POST,PATCH}` use `plan`, which includes `free`.
- render.com/docs/free: free instances exist for web services, Postgres, Key Value (and static sites); "Other service types don't support Free instances."
- render.com/docs/cronjobs: "There is a minimum monthly charge of $1 per cron job service."

## Mechanism

`lego/backend/internal/apps/service.go:3153-3168` `paidOnlyServiceType` is a two-type allowlist (worker, private service). Its comment says "Web services and cron jobs keep free — Render sells both that way". The same premise appears in `docs/ADR030-pricing.md` §7 ("Extended to Private Services 2026-09-28") and `.pm/w1/done/111.md:55`, with no source cited.

## Fix (if the decision is Render parity)

- Add `appv1alpha1.TypeCronJob` to `paidOnlyServiceType`. The create (`normalizeTierForType`, `:3136`), plan-change (`:3548`), settings-check (`settings_check.go:216`) and Blueprint probes (`stackHasPaidPlan`, `blueprintEstimatedPricing`) then follow automatically: a plan-less cron defaults to `starter`, and an explicit `free` gets a named 400.
- Dashboard: `dashboard/src/features/services/lib/instance-type.ts` paid-only filter (`:21-48`) gains `cron_job`.
- ADR030 §7: correct the premise, and apply the "existing free resources: transition, no silent conversion" paragraph to cron jobs. Production query: `SELECT id, name, tenant_id FROM apps WHERE type='cron_job' AND (tier='' OR tier='free')`. Known hits include QA fixtures and `examples/cron-demo` sweeps (w9/m44); notify owners.
- Pricing: confirm the cron minimum-charge story in ADR030 (Render: $1/month minimum, per-second billing).

If the decision is to keep free cron, only correct the comment, ADR030 §7 and the ADR018 parity row to name it a deliberate differentiator. That takes ~15m.

## Acceptance (parity branch)

- [ ] `bex services create --type cron_job … --plan free` exits 1 with `400 … a cron_job requires a paid plan; plan must be one of starter|…`. The plan-less create returns `plan: starter`.
- [ ] `bex services update <free-cron> --plan free` is refused. `blueprints validate` flags a `type: cron` + `plan: free` entry at `services[n].plan`.
- [ ] Controls: free `web_service` create still succeeds. Existing free cron jobs keep running unchanged.

`rg -i 'cron.{0,40}(paid|free plan)|paidPlan' .pm` (open items) found nothing. w6/025 (workers) and w1/111 (private services) are the precedent decisions. This note questions the cron exclusion they recorded.
