# Native PostgreSQL clients are missing from an otherwise valid build

**Severity: major. Attribution: operator native image assembly.** Both published Bex0.3.2 and unchanged same-pin Render2.27.0 create valid Free Node24 services, but their first builds fail because pg_restore is absent. Exact source and backup hashes pass before the failure; independent version probes report psql, pg_dump and pg_restore ENOENT. The authored command emits SQL from a real PG15 custom archive containing three QA rows. No hosted database or connection credentials are involved. [Complete evidence](evidence/cli-sweep402/README.md), [results](evidence/cli-sweep402/results.json).

Six fresh HTTPS200s perform real runtime pg_restore archive-to-SQL conversion and return the exact original source/backup hashes, three Unicode/quote/comma INSERT rows and canonical row hash. Six unique request paths correlate in native app logs. Twelve shared source/command and four explicit-env reads agree before/after. Only the working controls reach runtime; initial runtime behavior was not observed because their builds failed.

[Render's native tools contract](https://render.com/docs/native-runtimes#tools-and-utilities) includes PostgreSQL clients at build and runtime. [PostgreSQL documents](https://www.postgresql.org/docs/15/app-pgrestore.html) pg_restore's file/stdout mode without a database connection. The selected pinned Node base plus original command independently exits127 locally; the exact one-line install control decodes the same archive successfully with PostgreSQL15.19. These are functional backup-inspection results, not database restore/connection or managed-export coverage.
