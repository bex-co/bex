## Objective

When a static site's first release has started building and a save changes its publish directory or root directory, that release publishes and goes live as it started. The App reaches `Running` and the deploy row closes `live`. The saved value is served from the next deploy, as Render documents ("Changes will not be deployed automatically"). A save made before the build starts keeps w21/051's rule: the first release reads it.

## Context

- t001's named branch.
- w21/051 (`firstReleaseReadsSavedSource`) and ADR060 §D1a (the pending slot) are the rules to keep.
- `undeployedChanges` read `false` during the hang, though `publishPath` differed from what was published. Once the deploy settles, the saved value is an undeployed change and should read as one.

## Steps

1. Fix the branch t001 names so a first static release that published reaches `convergeStaticRouting` and `PhaseRunning`.
2. Make `undeployedChanges` (and its reason) report the saved-but-unpublished publish input after the first release settles.
3. Make sure a coalesced newer generation that only settings saves produced is not left owed forever; it waits for a deploy request.

## Files

- `lego/operator/internal/controller/app_controller.go`, `release_identity.go`
- `lego/backend/internal/apps` if the undeployed-changes read needs it

## Acceptance criteria

- [ ] t001's test passes: the App is `Running` on `rev-1`, and the deploy row would close `live`.
- [ ] A following deploy publishes the saved directory.
- [ ] A save before the build starts is still read by the first release (w21/051's test passes).
