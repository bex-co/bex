# Every REST 404 on a Render operation carries bex's own `code: "NOT_FOUND"` in the field Render reserves for its errorCode vocabulary, so the pinned CLI prints `received response code 404 (NOT_FOUND): …` where Render's prints `received response code 404: …`

Why: ADR006 keeps bex's upper-case refusal codes on REST because "Render's error body has no `code`, so these are extensions a Render client ignores". That premise is now stale: the pinned spec's `error` schema has a `code` field, and the pinned CLI prints whatever it holds in every error line.

**Severity:** minor (wording of every CLI not-found and coded refusal; statuses and messages are right). **Attribution:** server (bex-api REST error writer on the Render-contract routes). **Estimate:** ~1h. **Source:** routine `cli-qa` sweep r33, 2026-11-22 21:50–22:10 UTC, released `bex v0.9.0` (Render CLI pin `4fd34231b637`), `https://api.bex.co/v1/`, workspace `bex-canary`, QA human device login. Read-only.

## Evidence

- **REST.** 15 of 15 unknown-id reads answer `404 {"code":"NOT_FOUND","error":"<resource> not found","id":"not_found","message":"<resource> not found","params":null}`. These were services, deploys, env vars, secret files, env groups, custom domains, Blueprints, registry credentials, projects, environments, Postgres, Key Value, owners, logs and metrics. The same holds for malformed ids, except a Blueprint's, which answers a codeless 400 `invalid path parameter "blueprintId"` from the pinned pattern.
- **CLI** (`-o json`, stdin closed). Each exits 1 with nothing on stdout:
  - `bex environments prj-d00000000000000000a0` → `Error: received response code 404 (NOT_FOUND): project not found`
  - `bex restart srv-d00000000000000000a0 --confirm` → `Error: failed to restart resource: received response code 404 (NOT_FOUND): not found`
  - `bex deploys create srv-d00000000000000000a0 --confirm` → `Error: received response code 404 (NOT_FOUND): not found`
  - `bex logs -r srv-d00000000000000000a0` → `Error: error listing logs: received response code 404 (NOT_FOUND): not found`
  - The same holds for every other bex-coded refusal, for example w8/354's `(NOT_FOUND): registry credential … not found`.
- **Render's contract at the pin.**
  - `components.schemas.error` is `{id, message, code}`. `code` is "present on specific errors that clients can handle specially. Each endpoint documents the codes it can return. The errorCode schema lists the full vocabulary of codes."
  - `errorCode` has 33 lower-case values (`invalid_cursor`, `insufficient_token_scope`, `build_not_found`, …), with no generic not-found value.
  - The pinned CLI's fake Render API writes a 404 with `message` only (`internal/fakes/renderapi/sandboxsnapshots.go:89-95`, `writeAPIError(w, 404, "sandbox group not found", "")`).
  - Its decoder prints the code in parentheses whenever it is non-empty (`pkg/client/client.go:120-131`). A Render 404 therefore reads `received response code 404: <message>`.

## Root cause

`core.ErrNotFound` and `core.NotFound` carry `NotFoundCode = "NOT_FOUND"` on every surface (`lego/backend/internal/core/errors.go:47-50`, `:466`, w5/m130), and `core.WriteErr` serializes it as `code` with `params`. `docs/ADR006-bex-api.md:168-175` records the choice on the premise quoted above. The dashboard and mobile read codes from GraphQL, not REST. bex's own CLI reads REST codes only on bex-native routes (`lego/cli/internal/s3/tools.go:548`, `BUCKET_NOT_FOUND`; agent sessions).

## Fix

- On the Render-contract REST operations (the intersection `renderRequestValidator` enforces, `lego/backend/internal/api/render_openapi.go`), write `code` only when its value is in the embedded spec's `errorCode` enum. Read the enum from the spec, so a re-pin updates it.
- Drop `params` when it is null.
- Keep bex's codes on GraphQL, MCP and bex-native REST routes.
- Amend ADR006:168-175 to say so, and record any code bex keeps on a Render route in ADR018.

## Blast radius

- Every `core.CodedError` that reaches `core.WriteErr` on a Render route: NOT_FOUND, FORBIDDEN, CONFLICT, `ENV_VAR_MANIFEST_MANAGED`, `PROTECTED_ENVIRONMENT_CONFIRMATION_REQUIRED`, `WORKSPACE_RESOURCE_LIMIT` and others.
- `api/refusal_codes_test.go` pins codes per surface and needs its REST cases split into Render-route and bex-native-route cases.
- Audit `scripts/` and `lego/cli/` for REST `code` reads on Render routes before removing anything. The protected-environment retry phrase must stay reachable; it lives in `params.confirm`.

## Regression checks

- `bex environments prj-d00000000000000000a0 -o json` prints `Error: received response code 404: project not found`.
- A REST 404 on `/v1/services/<unknown>` has `id` and `message` and no `code`.
- `GET /v1/sandbox-groups?limit=0` still answers `invalid_limit`, and a scope refusal still answers `insufficient_token_scope`.
- GraphQL `service(id: <unknown>)` still carries `NOT_FOUND`, and `bex s3` still reads `BUCKET_NOT_FOUND`.

## Unverified

Render's live 404 body was not observed (no Render account, w10/002). The expectation comes from the pinned schema, the vocabulary and Render's own CLI fake.

## Dedupe

No item covers REST `code` values outside Render's vocabulary. w8/312 (done) and w22/004 and w22/016 (done) replaced bex codes where Render has a specific one. w8/084 and w8/354 quote the `(NOT_FOUND)` line without questioning it. Searched `.pm/` and `docs/` for `(NOT_FOUND)`, "vocabulary" and "errorCode".
