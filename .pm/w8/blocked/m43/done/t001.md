## Objective

Refuse `enableHighAvailability: true` unless the resolved plan's catalog CPU is at least 1. Refuse a plan change to an unsupported plan while HA is on. Do this once, in `lego/backend/internal/postgres/service.go`, so REST, GraphQL and MCP inherit it.

## Context

- Create: `service.go:638`. PATCH: `:1029-1031`. Plan resolution: `:599`, `:874-875`.
- CPU data: `lego/types/tiers/tiers.yaml` `postgres:`. Add a `SupportsHighAvailability()` (or similar) on the tier type rather than hard-coding plan names.
- The message names the requirement ("high availability requires a plan with at least 1 CPU") and, for a downgrade, the remedy ("disable high availability first").

## Acceptance criteria

- [ ] Free/`basic-256mb`/`basic-1gb`/spec-named sub-1-CPU plans refuse HA on create and PATCH (400). `standard`/`1c-2g` and above accept it.
- [ ] A downgrade under HA is refused. Disabling HA is always allowed.
- [ ] `ha_test.go` fixtures move to a supported plan.

## Outcome (2026-09-26) — done

- `tiers.PostgresTier.SupportsHighAvailability()` (`lego/types/tiers/tiers.go`) — per-instance CPU ≥ 1, from the catalog, no plan names hard-coded.
- `postgres.CheckHighAvailabilityPlan` + `checkHighAvailabilityPatch` (`lego/backend/internal/postgres/tiers.go`) run in `CreatePostgres` (dry run included), `UpdatePostgres`/`PreviewUpdatePostgres`, and `SetPlan`/`PreviewSetPlan`. So REST, GraphQL (`createDatabase`, `updateDatabase`, `updatePostgresPlan`) and MCP inherit one 400: `POSTGRES_HA_PLAN_UNSUPPORTED`, "high availability requires a Postgres plan with at least 1 CPU; plan "free" has 100m CPU".
- Plan change while HA stays on → "…; disable high availability first". Disabling HA (alone or together with the downgrade) is always allowed. A database already running HA on an unsupported plan keeps it through unrelated edits and an idempotent re-enable, so nothing is converted silently.
- **Catalog finding:** no shipped bex Postgres plan reaches 1 CPU (`free` 100m, `basic-256mb` 100m, `basic-1gb` 500m), so today HA is refused on every plan. `ha_test.go` fixtures could not "move to a supported plan". Enable-path tests use `allowHighAvailabilityOnEveryPlan` (swaps `postgres.PlanSupportsHighAvailability`) instead.
