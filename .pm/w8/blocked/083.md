## Root cause and shared scope

- `lego/backend/internal/logs/rest.go:133–198` validates syntax, live producer types and resource admission, then upgrades. `LogQuery.liveSubscribable` does not reject managed resource families here.
- `service.go:905–914` authorizes the owned datastore inside `followLogs`, then returns `core.ErrBadRequest` with the exact guidance: `managed Key Value live log subscription is not supported; use the historical logs query` (Postgres has the corresponding branch).
- By then `subscribeWebSocket` at `rest.go:358–396` has already sent 101. Its final refusal branch handles only `ErrBuildNotRunning`, `ErrLogsUnavailable` and `ErrLogStoreUnavailable`; this BadRequest falls through to socket close without any Log frame.
- Pinned `pkg/logs/repo.go:39–95` treats non-101 handshake errors as errors, but closes its output channel on any WebSocket read error. `cmd/logs.go:142–150` ends normally on the closed channel. This explains both clients' observed silent exit 0.

Move resource-family live compatibility into shared **preflight after the existing resource checks and before transport success headers**. Use the same named refusal for WebSocket, SSE and NDJSON; retain the direct `FollowLogs` guard as appropriate. Audit both managed families, single/multiple resources and the supported App/build controls. A mixed supported/unsupported resource request must fail coherently before any successful transport. Source proves Postgres shares this late-refusal mechanism, but its native live tail was not reproduced in this sweep. SSE/NDJSON behavior and mixed-resource transport acceptance are also unverified.

The API already defines this feature as unsupported; this note fixes its refusal, not its feature scope. w8/done/020 fixed build/unavailable terminal frames and does not handle this known BadRequest before upgrade. w2/done/m167's implementation says unsupported datastore tails retain named refusals, but its recorded live acceptance does not establish this WebSocket family boundary. Its OR-term behavior is not reopened here. w8/m58 owns Unicode history matching and now proves both datastores' raw-history failures; this unrelated early stream close must not be counted as Unicode live-delivery failure. Open/blocked/done board searches for the exact managed refusal, datastore upgrades and silent tail completion found no existing filing; current source/history has no preflight repair waiting for deployment.
