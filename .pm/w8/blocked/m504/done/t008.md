## Objective

t007's production replay (2026-11-19) found the definition of done's log line missing. A native web service switched to `nginx:1.27-alpine` went live on 80, but its deploy log read only `==> Deploy queued`, `==> Deploying image …` and `==> Your service is live 🎉`. An image-created nginx service's deploy log also reads `==> Detected HTTP on port 80; serving it`. Make the switched service's deploy name its detected port the same way.

## Context

- The deploy log's line comes from the deploy row's `detected_http_port` (`lego/backend/internal/logs/progress.go`). The row records it at its live close through `releaseDetectedHTTPPort` (`lego/backend/internal/store/reconciler.go`).
- That function accepted only an image-port web service's HTTP discovery (`web-image-v1`, `status.servingNetwork`/`imageNetwork`). A configured-port service's bound-port detection (`status.detectedPort`, w8/177) was never recorded, so no configured-port deploy named its port: not a switched one, and not a native one that binds another port.

## Steps

1. `releaseDetectedHTTPPort`: for a configured-port web service, return `status.detectedPort` when the row's release is the one the operator serves (`servesGeneration`) and the running release names no port of its own (`App.ServingPortDetected`, new in `lego/types/v1alpha1/image_network.go`, the running-release twin of `SavedPortDetected`).
2. Tests in `lego/backend/internal/store/deploy_http_port_test.go`.
3. ADR089 § Port slice decisions item 7.

## Acceptance criteria

- [x] `TestReleaseDetectedHTTPPortNamesABoundPortDetection`: the served release with a detected port names it. An older release, a release not served yet, nothing detected, an explicit port, a `PORT` variable, a private service (no HTTP check) and a row that ran nothing name none.
- [x] `TestSwitchedServicesDeployNamesItsDetectedPort`: the native deploy names no port; the switched deploy, served on the detected 80, names 80; the native row keeps none.
- [x] With the new branch disabled, both tests fail.

## Out of scope

- A private service's deploy log. Its listener answers no HTTP check, so the HTTP line does not fit it, and Render's wording for a private service is not captured.
