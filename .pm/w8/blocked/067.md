# 067 — Upstream token refresh deletes the saved refresh credential on a temporary 503 or 429

Why: a temporary refresh failure removes the local refresh token, so the next command cannot recover when the endpoint becomes healthy. With an access token still valid for 12 hours, the command even succeeds while silently removing its future refresh capability. Preserve credentials on transient failures and require a new login only for a definitive invalid grant.

Severity: major (persistent loss of local credential state). Attribution: upstream Render client, reproduced through Bex. Estimate: ~50m upstream patch preparation and shared-client verification; upstream acceptance, a later pin update and distribution are separate follow-ups. Source: `/qa-find-bugs-cli` w8 loop, 2026-10-07 local date; fixture matrix at 2026-10-08 04:20Z and independent header confirmation at 04:26Z. Goal: ADR008's dependable hosting client and ADR012's normal human device-login/refresh journey. No product fix or external upstream issue has been submitted.

| First refresh outcome | First command / saved state | Next command with refresh healthy |
| --- | --- | --- |

## Mechanism, ownership and concrete fix

- Pinned [`pkg/client/client.go:57-80`](https://github.com/render-oss/cli/blob/a764810a768202704e7206eb7b87a47211fcd98e/pkg/client/client.go#L57) proactively refreshes within 24 hours of stored expiry. Every error except `context.DeadlineExceeded` sets `RefreshToken` to empty and calls `config.SetAPIConfig`; `pkg/config/config.go:240` persists that change. A later process has no credential with which to retry.
- Pinned [`pkg/client/oauth/oauth.go:161-177`](https://github.com/render-oss/cli/blob/a764810a768202704e7206eb7b87a47211fcd98e/pkg/client/oauth/oauth.go#L161) converts non-200 OAuth responses into plain errors and drops status/Retry-After. `temporarily_unavailable`, `slow_down`, transport errors and definitive `invalid_grant` all reach the same destructive branch. The deadline control proves preservation/recovery is already an upstream policy for one transient class.
- Fix upstream error classification: retain HTTP status and OAuth code in a typed error; preserve stored tokens on temporary network/read failures, 429 and 5xx. Keep bounded refresh and current-access fallback, and clear the refresh credential only on a definitive terminal-grant refusal. Preserve device-grant `authorization_pending` handling and existing login/revoke contracts when changing the shared OAuth helper. Do not create an unbounded retry or replay resource mutations.
- No Bex server workaround is proposed. Keep honest 503/429 statuses, rate limiting, replica refresh idempotency, scope checks and OAuth wire dialect. REST/GraphQL/MCP/dashboard resource adapters need no change; mobile uses its own auth manager. Do not fork/vendor the CLI, fabricate a successful token response, or widen token lifetime to hide this branch.
- Shared source audit finds **39 production references** to upstream `NewDefaultClient` excluding tests/declaration, covering identity/workspaces, services/deploys, Postgres/Key Value, projects/environments, logs/session loaders and workflows. Bex has three additional production references: `internal/bridge/workspace.go:80`, `internal/pgtrust/fetch.go:29`, and the factory assignment in `internal/telemetry/telemetry.go:44`. The fresh-process evidence covers `whoami` only; the counts are source evidence, not separate runtime coverage for every caller.

## Upstream patch prepared (2026-10-08, w8 /loopx)

- **Error type.** `pkg/client/oauth` returns a typed `*ResponseError` carrying status, OAuth code and Retry-After. Its `Error()` strings are unchanged, so the device-grant `authorization_pending` check still works.
- **Refresh behaviour.** `maybeRefreshAPIToken` clears the stored refresh token only on `IsInvalidGrant` (`invalid_grant` with 400/401). Transport/read errors, deadline, 429, 5xx, `temporarily_unavailable`, `slow_down` and malformed 200s keep it. There is still exactly one bounded attempt.
- **Tests:**

  - `pkg/tui/views/login_test.go`: device polling continues through `authorization_pending`.
