# Applying the CLI log filter silently removes fractional timestamp bounds

Why: a hosting log that is visible with an exact time range disappears after applying unchanged filters, undermining the reliable log inspection promised by ADR008 and ADR010.

**Status:** todo. **Worker:** worker8. **Severity:** minor. **Attribution:** upstream Render CLI. **Estimate:** 55m; one bug, with a separate shared-caller verification step. No Bex fork or server workaround.

## Reproduction and observed behavior

Functional CLI QA on 2026-10-11 UTC, production `https://api.bex.co/v1/`, isolated human OAuth grant, workspace `bex-canary` / `tea-daif693dqjvc73e7as3g`. Released Bex v0.3.2 and an unmodified standalone Render v2.27.0 at `a764810a768202704e7206eb7b87a47211fcd98e` both reproduce. Bex source HEAD was `014810e45037ee446612fa752481c7eddf579fd8`; deployed backend/operator revision was not observed.

The fresh Free Node fixture `srv-db5dpgel97ls73au609g` reached Live and served its exact harmless HTTP marker. Its startup log `QA86_FORM_b2102d` has timestamp `2026-10-11T00:50:00.857576125Z`. Creation command, log ID, readiness and cleanup observations are in [fixture-cleanup.json](../evidence/082/fixture-cleanup.json). The fixture is now deleted. To repeat, create a fresh owned equivalent using that command with a fresh name/nonce, obtain its marker timestamp with native JSON logs, and substitute its ID/marker/time below.

```sh
bex logs --resources srv-db5dpgel97ls73au609g --type app \
  --text QA86_FORM_b2102d \
  --start 2026-10-11T00:50:00.857576125Z \
  --end 2026-10-11T00:50:00.857576125Z \
  --limit 10 --confirm -o interactive
```

Wait for the marker, press `/`, then Enter without editing any field. Repeat with the actual same-pin `render` binary against Bex using a separate private config and the same human grant/workspace. These are read-only commands on the same owned fixture.

**Expected:** unchanged filters preserve both instants and return the same row. **Actual:** each client initially sends both bounds with `.857576125Z`, gets HTTP 200 with the one exact marker, then sends both bounds as `2026-10-11T00:50:00Z` and gets HTTP 200 with `logs: []`. Other query parameters are unchanged. The marker disappears because the client narrows the point window to an earlier instant.

[native-ui.json](../evidence/082/native-ui.json) contains exact methods, raw paths, decoded queries, safe headers and complete log response bodies for both requests from each client. Capture used a GET-only loopback forwarder to the fixed production origin, changing authority only; it did not repair paths, queries, payloads or responses. Private copied config authority was also replaced because stored API host overrides the environment-only host. Authorization was never journaled. The first environment-only capture attempt recorded zero requests and was discarded as wire evidence.

The bounded successful capture observations lasted 10.223s for Bex and 7.097s for Render. Both submitted the filter before the observation deadline. The harness subsequently forced process termination/reaping (Bex exit -9; Render -15); these exits do **not** establish product interruption behavior. Interactive stdout/stderr share the PTY. Native noninteractive controls below have independently recorded streams and normal exits.

[Four direct native controls](../evidence/082/native-controls.json), using `-o json`, all exit zero with empty stderr: fractional point returns the exact same one log in Bex (0.470s) and Render (0.432s); rounded point prints empty stdout in Bex (0.297s) and Render (0.339s). JSON log output is a stream of row objects, not a `logs` envelope; empty stdout is the valid zero-row result.

## Root cause and ownership

The actual imported pin, not latest documentation, gives this chain:

- [`pkg/command/time.go:36–40`](https://github.com/render-oss/cli/blob/a764810a768202704e7206eb7b87a47211fcd98e/pkg/command/time.go#L36): absolute `TimeOrRelative.String()` uses `time.RFC3339`, dropping fractional seconds. Relative strings are returned unchanged.
- `pkg/command/form.go:72–75`: `FormValuesFromStruct` initializes time fields from that lossy string. `:171–184` reparses every time field in `StructFromFormValues`.
- [`pkg/tui/views/logview.go:175–183`](https://github.com/render-oss/cli/blob/a764810a768202704e7206eb7b87a47211fcd98e/pkg/tui/views/logview.go#L175): the filter callback reconstructs the entire `LogInput`; `:246–249` invokes it on Enter. An unrelated text edit therefore also changes the times.
- `pkg/tui/views/logloader.go:142–147` passes the resulting `time.Time` values to the generated `NewListLogsRequest` (`pkg/client/client_gen.go:12552`, start/end serialization at `:12590–12613`). The pinned oapi-codegen/runtime v1.2.0 `styleparam.go:221` preserves available precision with RFC3339Nano; it cannot recover precision already lost in the form.
- `pkg/command/inputs.go:37` reads the original CobraTime value for noninteractive flags. Bex's backend `lego/backend/internal/logs/rest.go:525` and `internal/core/http.go:497–509` preserve the parsed bounds. The production controls prove the server distinguishes the fractional and rounded requests correctly.

The [actual-pin offline probe](../evidence/082/form-probe.go.txt), [module](../evidence/082/form-probe-go.mod.txt), [checksums](../evidence/082/form-probe-go.sum.txt) and [six results](../evidence/082/form-probe-results.json) exercise the public form round trip, an unrelated text edit, and the real `NewLogsView` Enter callback without network calls. UTC nanoseconds, offset nanoseconds and milliseconds fail; whole-second UTC, whole-second offset and relative `5m` controls preserve their intended representation. This is imported-package evidence, distinct from the native live wire reproduction.

## Proposed work and acceptance

1. **Upstream correction (15m):** make absolute `TimeOrRelative.String()` preserve nanoseconds, e.g. RFC3339Nano, while preserving relative strings and existing whole-second spelling. Prepare the upstream patch locally. External submission, adoption of a new pin and release are separate actions; no external issue/PR/message was sent by this hunt.
2. **Regression checks (20m):** unchanged form apply and unrelated text edits must retain both original absolute instants at millisecond/nanosecond precision, including a non-UTC offset. Preserve whole-second, relative and unset-time neighbors. Repeat the native one-row point journey after adoption; changing only a text filter must not change either time bound.
3. **Shared-caller verification (15m):** four production `HuhFormFields` callers exist: logs, job creation, workflow creation and task-run creation. Only `LogInput` declares time fields (two). The one `NewLogsView` constructor has two production call sites in `pkg/tui/flows/log.go`; deploy, job and workflow viewers reuse that flow and may seed fractional absolute times. Verify those inherited viewers with equivalent inputs; keep service, Postgres, Key Value and workflow resource-filter semantics unchanged. `CobraTime.String()` also delegates to this formatter, so inspect flag/help display and relative defaults. Live job/workflow/datastore form paths were not exercised.
4. **Closeout evidence (5m):** retain the failing and control probes, note upstream acceptance/pin/release dependencies, and update the compatibility ledger when the shipped behavior actually changes. REST/GraphQL/MCP/dashboard do not need a time-range rewrite for this client defect.

No deployment-lag fix was identified in the Bex history. The anti-goals and deliberate CLI non-goals were checked.
