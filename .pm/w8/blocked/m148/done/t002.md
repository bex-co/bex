## Objective

When a BuildKit step in a platform-owned stage (`bex-hugo-*`, `bex-pnpm-*`, other `bex-` helper stages) fails, `deploy_ended.failureReason` says bex could not download that toolchain (with the HTTP status or error when known) and that retrying is the remedy. The raw BuildKit line stays in the build log.

## Context

- `failureReason` construction for "build failed in the docker build step" (grep the operator/build packages).
- Observed raw reason: `build failed in the docker build step:\nerror: failed to solve: digest mismatch sha256:bef140a1…: sha256:b382aacb…`.

## Steps

1. Classify BuildKit errors by the failing step's stage name. A `digest mismatch` or HTTP error on a platform `ADD` becomes a platform-download failure.
2. Keep user build-command failures unchanged.

## Acceptance criteria

- [x] Test: a fake BuildKit error on `bex-hugo-amd64` yields the named message. A failure in the user's build command keeps its existing reason.

## Done — 2026-11-10

`platformFetchFailure` (`lego/operator/internal/build/platformfetch.go`) reads a native build's captured BuildKit transcript: when the failed step (`#N ERROR`, or the closing ` > [stage …]` header when the progress header scrolled off) is a `bex-<tool>` helper stage, a checksum-pinned `ADD`, an image's `load metadata`, or a `COPY --from=<image>`, it is bex's fetch, because a native build's Dockerfile is generated whole. `failureDetail` returns the sentence for the buildkit container of native builds only, so a tenant's own Dockerfile stage named `bex-…` is never reclassified. `EnsureBuild` then marks the failure `FaultInfra`, so the correlated-failure alert counts it, and `buildFailureMessage` returns the sentence, e.g. `bex could not download its Hugo toolchain (github.com served a file that did not match its pinned checksum); this is a platform problem, not a problem with your code — trigger a new deploy to retry, and contact support if it keeps happening`. It names the HTTP status when BuildKit's HTTP source (`invalid response status 504`) or a registry (`: 503 Service Unavailable`) reports one. The raw lines stay in the build log. Tests: `TestPlatformFetchFailureNamesTheDownload` (the 2026-11-08 transcript, HTTP status, registry pull, scrolled-off header, main-stage pnpm `ADD`, FFmpeg `COPY --from`, base image), `TestPlatformFetchFailureLeavesTenantStepsAlone` (a failing `curl … github.com` build command keeps its reason), `TestBuildFailureMessageNamesAPlatformFetch`.
