## Objective

Establish completed hook state at the deployment lifecycle boundary so an ordinary later native Trigger does not require Blueprint re-sync to select the regular command. Trace and correct backend/operator ownership of that transition and the common predeploy job selector. Preserve pending/failed retries and ordinary regular predeploy jobs. Review later config/release sources, saved/history selection and source snapshots; do not rerun completed hooks or drop regular commands through a text-equality shortcut.

Files: lego/backend/internal/apps/deploy.go, lego/backend/internal/deploys/service.go, lego/operator/internal/controller/{app_controller.go,release_identity.go}, and shared types if needed.

Acceptance: recorded native no-resync cases now select regular/empty intent; actual current operator creates no initial job for a completed hook. Re-sync controls and failure/retry neighbors stay correct. Preserve old/new generation association and command roles across repeated releases.

## Done 2026-10-13

The operator owns completion: `preDeployStepCommand` (`lego/operator/internal/controller/app_controller.go`) runs the hook as a release's pre-deploy step until `status.initialDeployHookCompleted`, which the hook Job's success sets (also for a canceled release left to finish); later releases — any trigger, no re-sync needed — run the regular command, none when it is empty, with roles kept apart even for identical text. A failed or pending hook retries on the next release. `InitialDeployHook` joins the release fingerprint (omitempty, so no existing app re-rolls). Legacy services with the injected hook migrate on their next Blueprint sync (`initialDeployHookState`): a hook that already succeeded is never reintroduced and the regular command returns; the plan resolver applies the same reconciliation so a migrated service plans as unchanged.
