## Objective

`allowLongResume` (`lego/backend/internal/sandbox/idle.go`) pushes the connection's write deadline to now + 210 s so a wake-on-exec can wait out a resume. `StreamExec` (`exec.go`) never lifts it, so every exec dies at 210 s. Clear it once the gateway accepts and output starts (`stream.start()`), as the log tail does (`internal/logs/rest.go`).

## Acceptance criteria

- [x] A test proves the deadline is cleared after the gateway accepts and not before.

## Done — 2026-11-10

`StreamExec` (`lego/backend/internal/sandbox/exec.go`) clears the connection's write deadline once the gateway accepts and the stream starts (`http.NewResponseController(w).SetWriteDeadline(time.Time{})`), as the log tail does. `allowLongResume`'s 210 s deadline still bounds a resume wait. A refused dial keeps it, and the error is an ordinary HTTP answer. File-connect routes already reset theirs after the transfer. `TestStreamExecLiftsTheResumeWriteDeadlineOnceTheGatewayAccepts` covers the resume deadline being lifted after the header, and kept on a refused dial.
