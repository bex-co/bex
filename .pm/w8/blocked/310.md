# An exact Python or Ruby release older than its line's bookworm images (`PYTHON_VERSION=3.11.2`, Ruby 3.1.2) builds on the line's reviewed patch, where Render installs the release

Why: w8/175 builds an exact `PYTHON_VERSION` / `RUBY_VERSION` (or version file) on that release's official image of the line's Debian variant, `python:<release>-bookworm` / `ruby:<release>-bookworm`. Many releases from before mid-2023 have no bookworm image:

| Release | Variants on Docker Hub (2026-11-13) |
| --- | --- |
| Python 3.11.2, 3.10.4, 3.9.7 | bullseye, buster, slim, alpine |
| Ruby 3.2.0, 3.1.2, 3.0.4 | bullseye, buster, slim, alpine |

Such a pin falls back to the line's reviewed patch, and the log says so (`No official image python:3.11.2-bookworm; using the reviewed Python 3.11 image`). Render installs the release it was asked for.

**Severity:** minor. The substitution is logged, and the Render templates pin recent releases: the `render.yaml` `PYTHON_VERSION`s are 3.11.14, 3.12, 3.13 and 3.14.3, all on bookworm. **Attribution:** platform build (native version selection). **Source:** w8/309's open note, checked 2026-11-13 against Docker Hub.

## Why the Node fix does not carry over

w8/309 copies an old Node release's binary onto the bookworm line image, which works because the nodejs.org binary needs only an old glibc. CPython and Ruby link Debian's shared libraries, so a bullseye-built interpreter would not load its `_ssl`, `openssl` or `ffi` extensions on bookworm:

- bullseye has libssl 1.1, bookworm libssl 3;
- bullseye has libffi 7, bookworm libffi 8.

## Decision needed (user)

1. **Build on the release's bullseye image.** This is Render-exact, but it runs those builds on Debian 11, whose LTS ended on 2026-08-31, with no further security updates.
2. **Compile the release from source on bookworm,** as pyenv/ruby-build do. This is exact and current, but it adds minutes to the first build of each release and needs a cache. Python releases before 3.10 also want OpenSSL 1.1.
3. **Keep the logged fallback,** and record it in ADR018 as a divergence with sign-off.

The parity rule favors 1 or 2; 1 trades security for parity, and 2 trades build time. **BLOCKED** on that choice.
