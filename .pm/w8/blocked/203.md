# A Blueprint or service that turns previews **off** is refused as if it asked for them: `previews.generation: off` fails 25 of 87 official Render templates, and `bex services create --previews off` returns 400

Why: Render's Blueprint spec says `generation` defaults to `off` and that omitting the field disables preview environments. Render's API schema (`previews.generation`, enum `off|manual|automatic`, `"default": "off"`) agrees. So `off` is the same request as omitting the field, which bex accepts. Render's current templates write the opt-out explicitly. bex refuses on the field's _presence_, so a file or request that only says "no previews" fails with "preview environments are not available on bex". Building previews stays a non-goal (`.pm/DO_NOT_DO.md`, ADR018 row "PR preview environments"); declining them is not preview intent, so the fail-closed reason in `capabilities.json` does not cover it.

Severity: **major** (blocks the Blueprint journey for ~29% of current official templates; an explicit opt-out cannot be expressed on create or update). Attribution: server (Blueprint compiler and REST adapter). Estimate: ~45m. Source: `/qa-find-bugs-cli` loop sweep fcaa, 2026-10-26. Context: HEAD-built bex at `1dcc46614` with pinned Render CLI v2.27.0 `a764810a7682`; platform pin `2331a3dad`; `https://api.bex.co/v1/`; workspace `bex-canary`; human device login.

## Evidence

The minimal file: a free web service on `render-examples/express-hello-world` (build `yarn`, start `node app.js`), with a different preview setting in each variant.

```text
$ bex blueprints validate min-none.yaml -o json      # no previews key
{"plan":{"services":["qa-prev-off"],"totalActions":1},"valid":true}                   exit 0
$ bex blueprints validate min-off.yaml -o json       # previews: {generation: off}
{"errors":[{"column":3,"error":"preview environments are not available on bex","line":2,"path":"previews"}],"valid":false}   exit 1
$ bex blueprints validate min-auto.yaml -o json      # previews: {generation: automatic}  (correct refusal)
{"errors":[{"column":3,"error":"preview environments are not available on bex","line":2,"path":"previews"}],"valid":false}   exit 1
$ bex blueprints validate min-prfalse.yaml -o json   # services[0].pullRequestPreviewsEnabled: false
{"errors":[{"column":33,"error":"preview environments are not available on bex","line":9,"path":"services[0].pullRequestPreviewsEnabled"}],"valid":false}   exit 1

$ bex services create --type static_site --name qa-20261026-fcaa-prevoff \
    --repo https://github.com/render-examples/vue-hello-world --build-command 'yarn; yarn build' \
    --publish-directory dist --previews off -o json --confirm
Error: received response code 400: bad request: services previews is not supported by this platform    exit 1 (nothing created)
```

Corpus: I ran `bex blueprints validate` on the `render.yaml` of every non-archived `render-examples` repo that has one (87 files, fetched 2026-10-26). 29 fail on a preview field:

- 25 have root `previews: {generation: off}`;
- 1 has a service-level `previews: {generation: off}` (`flowise-render-template`);
- 3 really ask for previews (`generation: automatic`, or `previewPlan`/`previewValue`); those refusals are correct.

The 26 opt-out files all also carry `region: oregon`, which [w8/152](blocked/152.md) blocks (a separate decision). Both fixes are needed before these templates validate.

## Root cause

- REST: `unsupportedPreviewsField` (`lego/backend/internal/apps/rest.go:372`) returns `"previews"` / `"pullRequestPreviewsEnabled"` whenever the raw JSON is non-empty. Create and PATCH both call it (`:351`, `:358`).
- Blueprint: `capabilities.json` marks these properties as wholly `unsupported`, and `blueprintUnsupportedCapabilityMessage` refuses them (`blueprint_compiler.go:701`). The properties are root `previews`, `previewsEnabled` and `previewsExpireAfterDays`, plus service `previews` and `pullRequestPreviewsEnabled`. Values are never inspected.

## Fix

- Accept these spellings as a no-op: they mean the service has no previews, which is all bex offers. Read-back stays unchanged (bex omits `previews`; the field is optional in Render's read schema).
  - `previews: {generation: "off"}`, root or service-level, including when `expireAfterDays` is also set (inert when off);
  - root `previewsEnabled: false`;
  - Blueprint service `pullRequestPreviewsEnabled: false` (the Blueprint schema types it as a deprecated boolean);
  - REST create/PATCH `serviceDetails.previews.generation: "off"` and `serviceDetails.pullRequestPreviewsEnabled: "no"` (Render's OpenAPI: a deprecated string enum `yes|no` with `"default": "no"`).
- Keep the existing refusal and message for `manual`/`automatic`, `previewsEnabled: true`, `pullRequestPreviewsEnabled: true` (Blueprint) / `"yes"` (REST), and any `previewPlan`/`previewValue`/`previewDiskSizeGB`.
  - Open choice: these are also inert on Render when generation is off. Keeping them refused is conservative; accepting them only when the file's effective generation is off would be fuller parity. Ship the conservative version and note the other as a follow-up if the corpus shows it.
- Express it as a value-aware capability entry, so validate/plan/sync/apply share one rule (ADR049 D4). Don't special-case `validate`.
- Update `capabilities.json` reasons, ADR049's previews line, ADR018 row 105 ("opt-out values accepted"), and `docs/cli-compatibility-checklist.md` lines 70/196/225: `--previews off` is accepted and other values are refused.

## Blast radius

- Blueprint validate/plan/apply/sync over REST, GraphQL and MCP (one compiler).
- REST `POST /v1/services` and `PATCH /v1/services/{id}`.
- GraphQL/MCP service mutations expose no previews input, so nothing changes there.
- The dashboard Blueprint import uses the same compiler, so it also stops refusing these files.

## Regression checks

- Unit tests over the matrix above: off/false/no accepted with no stored effect; automatic/manual/true/yes and `previewPlan` still refused with the unchanged message and location.
- REST create/PATCH tests: `previews.generation` `"off"` and `pullRequestPreviewsEnabled` `"no"` succeed (2xx, service unchanged); `"automatic"` and `"yes"` keep the 400.
- Live: the four `min-*.yaml` validations above give valid, valid, refused, valid. `bex services create … --previews off` creates the service (delete by ID, 404 proof). `bex services update <id> --previews automatic` is still refused.

- Whether any of the 25 templates fail on something else once both `previews` and `region` are fixed. In this run, `previews` and `region` were their only errors.
