# An unknown `registryCredentialId` on a service create or update answers "validating registry pull secret for <image>: not found", which reads as a missing image and never names the credential

Why: the pinned Render CLI passes `--registry-credential` through as the id with no lookup, so a user who types the credential's name (or a stale id) gets an error naming the image and Kubernetes "pull secret", not the credential they got wrong.

- Severity: minor. The request is refused correctly with 404 and nothing is saved; only the message misleads.
- Versions: production `https://api.bex.co/v1/` on 2026-11-20 15:16 UTC; bex CLI v0.7.0 (Render CLI pin `4fd34231b637`, `pkg/service/update.go:41-42` and `create.go:77-78` copy the flag value into `image.registryCredentialId` unchanged).
- Context: routine `cli-qa` run `r14-f377`, QA human device-flow token, workspace `bex-canary`, run-owned fixtures (deleted afterwards).

## Repro

```text
bex services update <srv> --image docker.io/qafakeorg-f377/private-none:v1 --registry-credential qa-20261120-f377-rc --confirm -o json
  → rc 1, stderr: Error: received response code 404 (NOT_FOUND): validating registry pull secret for docker.io/qafakeorg-f377/private-none:v1: not found
bex services update <srv> … --registry-credential rgc-aaaaaaaaaaaaaaaaaaaa …   → the same text
POST /v1/services?dryRun=true {… "image":{"ownerId":"<tea>","imagePath":"docker.io/library/nginx:1.27-alpine","registryCredentialId":"qa-20261120-f377-rc"} …}
  → 404 {"code":"NOT_FOUND","error":"validating registry pull secret for docker.io/library/nginx:1.27-alpine: not found","id":"not_found",…}
The same command with the real rgc- id → rc 0.
```

## Cause

`resolvePullCredential` returns a bare `core.ErrNotFound` for an unknown explicit id (`lego/backend/internal/registrycreds/pullsecret.go:108-111`), while its neighbors name the id (`:92` forbidden, `:95` host mismatch). `validateExternalRegistryCredential` then wraps every error as `validating registry pull secret for <image>: …` (`lego/backend/internal/apps/pullsecret.go:72`).

## Fix

Return `fmt.Errorf("%w: registry credential %q not found", core.ErrNotFound, id)` there, and drop the "validating registry pull secret for <image>" wrapper from customer-facing text (keep the image only where the error is about the image, as the host-mismatch message already does). Keep 404 and the `NOT_FOUND` code; a credential in another workspace stays the 403 it is now, so no existence leak changes. Check the other callers of the wrapper and of `resolvePullCredential` (create, update, deploy trigger at `deploys/service.go:944`, Blueprint `fromRegistryCreds`, GraphQL and MCP `registryCredentialId`) read the same.

## Acceptance

`bex services update <srv> --image docker.io/library/nginx:1.27-alpine --registry-credential rgc-aaaaaaaaaaaaaaaaaaaa --confirm` exits 1 with a message that names `rgc-aaaaaaaaaaaaaaaaaaaa` as an unknown registry credential and does not say "pull secret"; the same through `POST /v1/services?dryRun=true`. A unit test in `registrycreds` pins the message.

- Unverified: Render's exact status and text for an unknown `registryCredentialId` (no Render account to probe); 404 matches the spec's listed responses for service update.
- Dedupe: `rg -i 'pull secret' .pm` and `rg -i 'registry ?cred' .pm` find w4/599 (a delete naming the Kubernetes object, fixed) and w4/577/504/491/490 (other credential validation), none on this message.
- Estimate: ~20m.
