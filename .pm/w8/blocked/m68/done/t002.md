## Done 2026-10-15

`commandText` (`lego/backend/internal/apps/build_strategy.go`) keeps nonblank command text byte for byte and stores whitespace-only as empty. It replaces `strings.TrimSpace` in `setBuildCommand`, `setCronCommand` and `setStartCommand`, `SetPreDeployCommand`, the settings pre-deploy preflight, and create's pre-deploy, cron command and initial deploy hook. It also applies to create's build and start commands (previously stored raw), so a whitespace-only command at create is no command rather than a blank override the operator would run. The Blueprint initial-deploy-hook copy (`deploy.go`) goes through it too. REST and MCP reach these through `ApplyServicePatch`; GraphQL through `SetCommands`/`SetPreDeployCommand`/`SetCronJob`. Static build clearing (w8/m59) and the cron fallback clear (w4/m194) are unchanged, since a whitespace-only write is still `""`. Two existing expectations changed deliberately: `TestSetPreDeployCommandSetsAndClears` now expects padded `"  npm run migrate  "` to be kept, and `TestDirectCronCreatePreservesCommandFields` expects a padded cron command kept and a whitespace-only one empty. The original failing-policy receipt stays in `evidence/cli-sweep284/backend-original-policy-test.json`. The Blueprint docker-whitespace reapply case now expects the whitespace-only dockerCommand stored as empty, and the reapply is still a no-op. Services saved before this change keep their trimmed commands; a manifest whose command has surrounding whitespace (e.g. a YAML block scalar's final newline) plans one update on its first sync after rollout, then is a no-op.
