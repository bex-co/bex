## Done 2026-10-15

`commandText` (`dashboard/src/features/services/lib/command-text.ts`) is the dashboard's copy of the backend rule. `EditableFieldRow` now takes one `normalize` prop, which defaults to trimming (the old `trim={false}` caller, `health-check-path-row.tsx`, passes an identity function). The build, pre-deploy, start/Docker and cron Command rows pass `normalize={commandText}`. A nonblank draft is saved byte for byte, a stored command with a trailing escaped space opens clean, and a whitespace-only draft clears exactly as `""` did. A schedule-only cron save replays the stored command unchanged instead of `command!.trim()`. `buildCreateServiceInput` sends static build, native build/start, image Docker and cron commands through `commandText`/`optionalCommand`. A blank optional command is still omitted, and a whitespace-only required native command still counts as missing. Name, root directory, publish path, schedule, Dockerfile path and every other editor keep their trimming. The five command mutation hooks, the `services.new` wizard fields and Blueprint flows already forwarded strings unchanged, and the dashboard has no clone flow that sends commands. Mutation-boundary tests render the real sections and record the variables each mutation receives. Against the original source, 21 cases fail: 12 escaped-space UI cases (6 rows: sends verbatim, opens clean), 7 create-input cases, the cron replay and the pre-deploy padding expectation. `yarn typecheck`, `yarn lint` and prettier pass. Of the full `yarn test` run, 4931 pass; the 2 failures are in `src/routes/__tests__/deploys-history-filters.test.tsx` (w4/284), which fails identically on a clean HEAD worktree at load average ~170 and passed in the last green CI. No browser session was run; hosted dashboard acceptance is part of t004.
