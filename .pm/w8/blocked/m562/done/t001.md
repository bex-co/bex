## Objective

Give each store's `kv-internal-proxy` a third listener that only refuses. It ends TLS with the store's own certificate, answers every RESP command with `-Client IP address is not in the allowlist.\r\n`, and closes. It never dials an upstream and never uses the store's budget.

## Context

- `kvinternalauth.refuse` (`lego/operator/internal/kvinternalauth/proxy.go:447`) already ends TLS with `TLSCertFile`/`TLSKeyFile`, read at each refusal so a renewed certificate applies at once, and answers Valkey's maxclients line. `maxRefusing` (16) bounds concurrent refusals per listener.
- `cmd/kv-internal-proxy/main.go:101` opens the TLS listener when `BEX_KV_TLS_ADDR` is set. `run` waits for `count` listener results and drains them on SIGTERM.
- Why every command: `valkey-cli` keeps the connection after a failed `AUTH` and sends its command on it (README triage). Clients send RESP multibulk (`*N\r\n$len\r\n…`); `valkey-cli` interactive and telnet users may send inline commands (a line ending in `\n`).

## Steps

1. Add the refusal to `kvinternalauth`, either as a `Mode` that `Serve` handles without an upstream or as its own `ServeRefusals(ctx, listener, Config)`. Each connection:
   - gets one deadline for its whole life (the config's handshake timeout, or a named bound of about 10 s);
   - completes `tls.Server` with the store's certificate, and is closed if the files are missing or unreadable;
   - reads commands with a bounded parser (multibulk with bounded counts and lengths, or an inline line of bounded length) and writes the refusal after each one;
   - closes on EOF, at the deadline, on a malformed or oversized command, or after a bounded number of commands.
2. Bound concurrent refusals as `maxRefusing` does; past the bound, close the connection.
3. Never dial, never `admit` into the `Budget`, and follow `Drain` and `ctx` like the other listeners.
4. `cmd/kv-internal-proxy`: open the listener when a new env var (for example `BEX_KV_ALLOWLIST_REFUSAL_ADDR`) is set. It requires `BEX_KV_TLS_CERT_FILE`/`BEX_KV_TLS_KEY_FILE`, and joins the `count` loop and the drain.
5. Tests in `proxy_test.go` and `cmd/kv-internal-proxy/main_test.go`, using a test certificate:
   - a TLS client's `AUTH` and `PING` each read the refusal, pipelined too;
   - an inline command reads it;
   - a listener whose upstream address points at a test listener records no accepted connection on it;
   - a missing certificate closes the connection;
   - the deadline closes an idle refused client;
   - a flood past the bound is closed.

## Record (2026-11-22)

- `kvinternalauth.AllowListRefusal` is a fourth listener mode. `Serve` sends every client of such a listener to `refuse`, outside the budget, bounded by `maxRefusing` (16) like the budget refusals. `refuse` ends TLS with the store's certificate (read at each refusal) and `answerAllowListRefusals` answers each command with `-Client IP address is not in the allowlist.\r\n`.
- The listener cannot dial: `normalized` refuses an `AllowListRefusal` configuration that names an upstream or a password, or lacks the certificate. Commands are read within Valkey's unauthenticated bounds (10 arguments of at most 16 KiB, an inline line of 16 KiB) and at most 64 per connection; an AUTH's password is read past, never checked. Each connection lives `HandshakeTimeout` (5 s).
- `cmd/kv-internal-proxy` opens it on `BEX_KV_ALLOWLIST_REFUSAL_ADDR`, requires `BEX_KV_TLS_CERT_FILE`/`BEX_KV_TLS_KEY_FILE` with it, and drains it with the other listeners.
- Tests: `internal/kvinternalauth/refusal_test.go` (every command inside TLS, pipelined and inline, empty commands unanswered, a full budget untouched; the command bounds; malformed and oversized commands closed; the 64-command bound; the deadline; a missing certificate; the 16-refusal bound; a configuration with an upstream or password refused while a counting upstream sees nothing) and `cmd/kv-internal-proxy/refusal_test.go` (AUTH and PING read the refusal through `run`, the upstream reads nothing). `TestRunDrainsUntilTheDeadline` closes the refusal listener on drain.
