## Objective

List every REST/GraphQL/MCP verb that accepts a service (and datastore) name where Render requires an id: deploys list/create/cancel, restart, instances, jobs list/create, logs resources, and so on. Prove each follows the new rule, using **fixtures only**, including one mutation (for example `restart <name>`) on a two-workspace fixture pair.

## Acceptance criteria

- [ ] A table of verb → behavior is in this task, and each has a test.

## Outcome (2026-09-26) — done

Every service by-path verb resolves through the two seams the guard sits in. `grep` shows no feature doing its own `LabelServiceName` lookup:

| Surface / verb | Seam | Behavior on an ambiguous name |
| --- | --- | --- |
| deploys list/get/create/cancel/rollback, restart, deploy hook (`deploys/service.go`) | `AuthorizeApp` / `GetApp` | 409 (deploy hook has no identity → by-id/URL-token only, unchanged) |
| services get/update/delete/suspend/resume/scale, instances, env vars, secret files, domains, disks, outbound IPs, headers/routes (`apps/*`) | `AuthorizeApp` / `GetApp` | 409 |
| jobs list/create/get/cancel (`jobs/service.go`) | `AuthorizeApp` | 409 |
| logs / metrics resources, events (`logs/`, `metrics/`, `events/`) | `GetApp` | 409 |
| env groups links, environments membership (`envgroups/`, `environments/`) | `AuthorizeApp` | 409 |
| SSH / web shell tickets (`shellticket/`, `sshgateway/webshell`) | `AuthorizeApp` | 409 |
| GraphQL / MCP counterparts | same service methods | 409 (GraphQL error extension `code: SERVICE_NAME_AMBIGUOUS`) |
| Postgres / Key Value by name | `AuthorizeDatabase`/`AuthorizeKeyValue` | unchanged: sweep 17 found these already scoped (the CLI resolves datastore names client-side) |

Tests at the seam (`core/ambiguous_name_test.go`): the mutation relation (`can_operate`, which restart/deploy/cancel authorize) and the read relation, on the direct and the sweep path. Fixtures only; nothing live was mutated.
