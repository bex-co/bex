## Objective

Carry the active workspace from the launcher in a native header so a service name resolves only in selected workspace A, while immutable service IDs remain global addresses.

## Acceptance criteria

- [x] The sweep-16 reproduction (same name in `bex-canary` and `tian-personal`, `bex-canary` selected) returns the `bex-canary` service.

## Historical blocker (2026-09-26; resolved 2026-10-02)

Needs the user's sign-off on t001's option (a), a bex-native launcher header carrying the selected workspace that the server honors for name resolution only. Until then, the sweep-16 pair returns `409 SERVICE_NAME_AMBIGUOUS` with both ids instead of the selected workspace's service. That's safe (no wrong target), but it doesn't meet DoD bullet 1.

## Decision and implementation (2026-10-02)

The user's accepted sequence authorizes the native `X-Bex-Workspace` header. The launcher resolves the same saved/environment workspace as upstream; it sends the header only to configured control-plane service paths, without altering upstream commands or User-Agent. The API applies the hint only to service names, resolves workspace names within membership, validates access, and refuses cross-workspace fallback. Immutable service IDs retain their resource's authorization scope.

Full-router tests use same-named services in two member workspaces, a foreign workspace, and nested deploys/instances with an unselected positive control. CLI tests cover saved selection, environment ID/name precedence and third-party isolation. Removing the middleware through a Go overlay fails the regression test. API deployment, CLI release and live two-workspace verification remain in t008.
