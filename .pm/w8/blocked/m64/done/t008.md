## Objective

An immutable Blueprint literal, including empty, remains the known effective source when a mutable sync:false seed uses the same key. Accepted sibling copies agree in first apply and reapply.

## Context

- [Eight actual feature states and sixteen fresh native wire captures](evidence/literal-seed-sweep222/README.md).
- Two accepted first applies copy the seed while the persisted source uses its explicit literal. Four existing-source validations falsely refuse that fixed literal as unknown.
- classifyServiceEnv conflates literal and seed values in se.known; knownServiceEnv assigns seed provenance by key membership; classifyRefs adds stateCopies and currentStateCopyProblems rejects it.
- Explicit spec.Env wins over own envFrom; generated/literal controls and the seed-only unknown-value refusal remain correct.

## Steps

1. Distinguish immutable literals from seed hints in the index. Preserve literal priority in either entry order and use seed provenance only for the effective seed source.
2. Keep refs appended after literals masking the key, seed-once writes/edits, groups, generated controls and t007's names-only eligibility guard. Do not globally reject valid repeated keys or read arbitrary dynamic values.
3. Verify the shared parser/current-state consumers, metadata-backed/public IDs, nested and consumer-first manifests, and zero writes on real unknown-value refusals.
4. Add behavioral regressions that fail on these two wrong copies/four false refusals, then complete the milestone's shared/native acceptance.

## Done 2026-10-13

`serviceEnv.literals` now holds only plain manifest literals; seeds and answered prompts stay in `seedLiterals`. `knownServiceEnv` layers runtime precedence: linked groups, then the service's own store (seed provenance), then manifest literals (container env, which win), then reference masks. A literal and a same-key `sync:false` seed therefore resolve to the literal in either entry order, with literal provenance, so first apply copies it and reapply no longer falsely refuses it. Tests: fixed and empty literals in both seed orders copy the literal on two consecutive applies (all four fail on the previous code); the seed-only refusal, reference masks, group order and generated controls are unchanged.
