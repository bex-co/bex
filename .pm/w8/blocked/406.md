# A private service's Health Check Path gets an HTTP probe, where Render gives private services only its default TCP check

Why: Render says "Private services only support default TCP checks", and its Blueprint spec scopes `healthCheckPath` to "Web services only". bex probes the path over HTTP on a private service, so a Render private service with a path that answers 4xx or 5xx (or that does not speak HTTP) goes live on Render but never goes live on bex. ADR018's health-check row lists the private-service support without a user sign-off.

- Severity: minor. It affects paid private services that carry a path, which Render's schema accepts in a Blueprint (`serverService.healthCheckPath`) and its API never offers.
- Seen: routine `cli-qa`, 2026-11-22 18:30 UTC, bex CLI v0.9.0, `https://api.bex.co/v1/`, QA human login, `bex-canary`, validate only. A private service is paid, so this was not applied. `bex blueprints validate` accepts a `type: pserv` (`plan: starter`) with `healthCheckPath: /healthz` (exit 0), and refuses the same field on a worker ("health check path is not applicable to a background_worker", w8/056).
- Render:
  - [render.com/docs/health-checks](https://render.com/docs/health-checks) (read 2026-11-22): "Health checks only apply to web services and private services." and "Private services only support default TCP checks."
  - [render.com/docs/blueprint-spec](https://render.com/docs/blueprint-spec) § `healthCheckPath`: "Web services only. The path of the service's health check endpoint."
  - Render's pinned OpenAPI (`lego/backend/internal/api/openapi/render-public-api-1.json`) has `healthCheckPath` only on `webServiceDetails`, `webServiceDetailsPOST` and `webServiceDetailsPATCH`. There is none on the private-service schemas.
- bex:
  - `healthCheckPathApplies` (`lego/backend/internal/apps/settings_check.go:51`) excludes only cron jobs and workers, so REST, GraphQL, MCP and Blueprint create and update all store a path for `private_service`.
  - The operator projects the no-redirect HTTP exec probe for every non-worker App with a path (`lego/operator/internal/controller/deployment_projection.go:244-246`, `:473-489`).
  - The dashboard offers the row for private services (`dashboard/src/features/services/components/health-check-path-row.tsx`, "web_service + private_service only" in ADR018's health-check row).

## Fix

- The operator gives a private service the TCP check whatever its stored path is. This rolls each existing private service that has a path once, so list them first and note the count.
- A Blueprint `pserv` with `healthCheckPath` still validates, because Render's schema accepts it, and the path has no effect. Decide how REST, GraphQL and MCP treat a private-service path (refuse as they do for a worker, or accept and ignore) from Render's REST answer to `POST /v1/services` with `serviceDetails.healthCheckPath` on a `private_service`. If it cannot be measured, accept and ignore, the way the Blueprint does. Stop reading the path back on a private service, since Render's private-service schema has no such field.
- Remove the dashboard row for private services, and update ADR018's health-check row and ADR004.

## Acceptance

- [x] An operator unit test shows that a private service with `HealthCheckPath: /missing` gets the TCP probe, with no HTTP exec handler. Control: a web service keeps the HTTP probe.
- [x] A backend test covers a Blueprint `pserv` with `healthCheckPath`: it validates, and the App has no effective HTTP check.
- [x] A dashboard test shows the private-service settings page has no Health Check Path row, and the web service page keeps it.

Estimate: ~1h. Promote it if the surface decision splits it.

- **Render, re-read 2026-11-22.** [health-checks](https://render.com/docs/health-checks): "Health checks only apply to web services and private services.", "By default, health checks are TCP socket probes to one of your service's open ports." and "Private services only support default TCP checks.", with the path setup under "HTTP health checks (web services only)". [blueprint-spec](https://render.com/docs/blueprint-spec) § `healthCheckPath`: "Web services only." Render's pinned CLI (`render-oss/cli` `4fd34231b637`, `pkg/types/service/servicecreate.go` `validateFlagsForType` and `serviceupdate.go` `ValidateForServiceType`) refuses `--health-check-path` for every type but `web_service` on create and update. Its Blueprint schema (`lego/backend/internal/apps/schema/render.yaml.json`) has `healthCheckPath` on `serverService` (web, worker, pserv) and not on `cronService` or `staticService`, both `additionalProperties: false`. One contrary line: Render's generated agent reference `render-examples/render-ops-agent-ts/.agents/skills/render-private-services/references/patterns.md` shows a `pserv` with `healthCheckPath`. The docs page answers this exact question and outranks it, and the same reference gets the default wrong ("Default: `/`").
- **Decision, by surface.**
  - Operator: a private service gets the TCP check whatever it stores (`AppSpec.HTTPHealthCheckPath`, `lego/types`). Workers and cron jobs were never probed.
  - REST, GraphQL and MCP create and update refuse a non-empty path on every type but `web_service`, with the worker's reason: `health check path is not applicable to a private_service; only a web_service has an HTTP health check`. That now covers a static site too, which create used to store and nothing probed. Clearing stays allowed on any type. Render's REST answer could not be measured (no Render API key). Refusing, not accepting and ignoring, follows Render's CLI and its schemas, keeps private services and workers on one rule, and follows bex's REST rule that a declared field it cannot honor is refused (`docs/render-artifacts/openapi-request-validation.md`). Reads report no path on a non-web service.
  - Blueprint: Render's schema accepts the field on a `pserv` and a `worker`, so validate, plan, sync and apply take it there and the parse drops it. A sync leaves a stored path alone, so a re-plan reads `no_changes`. This reverses w8/056's worker refusal, which had no user sign-off. A `cron` entry is still refused by the schema.
  - Dashboard: the Health Checks section is web-only (`settings-sections.ts`).
- **The roll.** The production count of private services with a stored path could not be read: `scripts/fetch-app-kubeconfig.sh` stops at `HCLOUD_TOKEN is required`, because this checkout's `.env` has no token. The change is therefore adopted lazily, as w8/m133's probe was: a template that still probes the stored path keeps that probe until it changes for another reason (a deploy, a restart, a saved change), so the operator upgrade rolls no service. The count no longer decides anything.
- **Tests.** Operator: `TestPrivateServiceHealthPathGetsTheTCPCheck` (a private service with `/missing` gets the TCP check on all three probes, with and without the helper image, and a web service keeps its HTTP check of `/missing`) and `TestPrivateServiceTCPCheckIsAdoptedOnTheNextRollNotOnUpgrade`. Backend: `TestPrivateServiceHealthCheckPathIsRefusedOnEveryDirectSurface` (REST create, dry run and PATCH, GraphQL `createService` and `setHealthCheckPath`, MCP `create_web_service` and `update_service`), `TestPrivateServiceStoredHealthCheckPathIsNotReadBackAndClears` and `TestBlueprintPrivateServiceAndWorkerHealthCheckPathHasNoEffect` (validates, the Apps store no path, a re-plan over a stored path is a no-op, and a cron is refused). The create matrix in `create_type_applicability_test.go` now refuses the path on a private service and a static site. Dashboard: `offers no Health Check Path to a private service, and keeps it for a web service`. With the fix reverted, the operator, backend and dashboard tests fail.
- **Docs.** ADR004 § A private service has only the TCP check, the ADR018 Health checks and Blueprint rows, and ADR049.
