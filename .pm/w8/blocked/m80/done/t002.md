## Outcome (2026-10-16)

Truth table (all through the shared Core path; REST/GraphQL/MCP/dashboard unchanged):

- New service, independent repo, branch omitted → repo default (lookup); explicit branch → as written (no lookup); own/omitted repo → Blueprint's branch (no lookup).
- Existing image service switched to Git (declared or inherited repo) → the entry's branch, resolved as for a create.
- Existing Git service, another repo, branch omitted → new repo's default (previously kept the old repo's ref).
- Existing Git service, same repo however spelled, branch omitted → keeps its current branch, no lookup, identical reapply no deploy; rollback image override kept.
- Lookup failure / inaccessible / unbuildable default → service refused before any write, in apply and in the preview's plan; no opinion (GitHub off, non-github.com) → legacy `main`.
- Manual source setter (settings_check.go) untouched. Callers: Blueprint create, provided/fetched/stored/auto sync and validate/preview share `planStackApp`/`updateStackService`/`blueprintActionResolver`; lookups are memoized per validation and per create/update, so a switch reads twice per sync (plan + apply) and a no-op re-sync reads nothing. Hosting kinds share the source structures; live paid/cron untested by design.
