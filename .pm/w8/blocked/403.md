# A web service's text responses under 1 KiB go out uncompressed to a gzip client, where Render's edge gzips them from 48 bytes

Why: Render's edge compresses a web service's small JSON and HTML responses, which are most API answers, but bex's Traefik `compress` keeps its default 1 KiB floor, so an API moved from Render sends those bodies at full size. w8/359 already moved static sites to Render's 48-byte gzip floor, and web services still differ.

Severity: **minor** (bytes on the wire; content is exact). Attribution: platform edge (the per-App Traefik `compress` Middleware). Estimate: ~30m. Source: `/qa-find-bugs-cli` cli-qa routine sweep 251abe, 2026-11-22 14:19–14:21 UTC. Context: `https://api.bex.co/v1/`, workspace `bex-canary`, human device login, bex v0.9.0, deployed revision not observed.

## Evidence

The bex fixture was a free image web service `qa-20261122-251abe-echo` (`srv-dc1finj88nrc738n1q20`, `docker.io/ealen/echo-server:0.9.2`), deleted by ID after the sweep. `?echo_body=<n chars>` makes it answer a JSON string of that size. The Render oracle is the public Render web service `httpbin.onrender.com` (`x-render-origin-server: uvicorn`). Each row is one `curl -s -H 'Accept-Encoding: <offer>'` with wire bytes counted.

```text
host    path                      offer     wire B   content-encoding  vary
render  /html (209 B identity)     gzip      148      gzip              Accept-Encoding
render  /uuid (464 B identity)     gzip      279      gzip              Accept-Encoding
render  /json (938 B identity)     gzip      476      gzip              Accept-Encoding
render  /robots.txt (31 B)         gzip       31      -                 Accept-Encoding
render  any of the above           identity  full     -                 Accept-Encoding
bex     /s?echo_body=<500 chars>   gzip      502      -                 Accept-Encoding
bex     /s?echo_body=<1200 chars>  gzip       43      gzip              Accept-Encoding
bex     /s?echo_body=<500 chars>   identity  502      -                 (none)
```

Render gzips 209-, 464- and 938-byte bodies and leaves a 31-byte one alone. That fits the 48-byte gzip floor w8/359 measured on Render's static sites, which sit behind the same Cloudflare edge. bex compresses nothing under 1 KiB.

Controls that agree with ADR018 § Edge compression for web services (no new finding):

- `br` alone gets identity on bex and `br` on Render. That is signed-off difference (3), tracked by w8/227.
- `text/event-stream` is never encoded.
- On a second free fixture, `qa-20261122-251abe-sink` (`srv-dc1fl2388nrc738n1q40`, a native Python web service from `render-examples/flask-hello-world` running a stdlib server, deleted by ID): a chunked `text/plain` or `application/json` stream, written as one short line every 2 s, reached a gzip client line by line (gzip-encoded, one 32–47-byte frame at 0.5 s, 2.5 s, 4.5 s and so on), so nothing is buffered. Server-Sent Events arrived the same way, unencoded.
- On the same fixture, 10 MB and 100 MB `application/octet-stream` uploads of zero bytes reached the app whole over HTTP/2 (`received=100000000`, 25 s). The edge has no body limit, and Render documents none.

## Root cause

`lego/operator/internal/controller/edge_compression.go:49–53` (`edgeCompressionMiddlewares`) writes `{"compress": {"encodings": ["gzip"], "includedContentTypes": …}}` with no `minResponseBodyBytes`. Traefik's default for that is 1024, which is the floor its doc comment on line 41 describes. ADR018 records the 1 KiB floor as the design but not as a signed-off difference.

## Fix

- Set `minResponseBodyBytes: 48` in `edgeCompressionMiddlewares`, matching the static server's `minGzipBytes` (w8/359).
- Update the doc comment and ADR018's "gzip, for responses of at least 1 KiB" sentence.
- Add rows to `TestEdgeCompressionOnTheDeployedTraefik` (`edge_compression_traefik_test.go`): a 48-byte listed-type body is gzip, a 47-byte one is identity, and the small and large `206` Range rows stay untouched.

## Acceptance

- `BEX_TRAEFIK_INTEGRATION=1 go test ./internal/controller -run TestEdgeCompression` passes with the new rows. `make test` and `make lint` pass in `lego/operator`.
- Live, on a fresh free `ealen/echo-server:0.9.2` web service in `bex-canary` (deleted by ID, with a 404 proof): `curl -H 'Accept-Encoding: gzip' '<url>/s?echo_body=<500 chars>'` answers `content-encoding: gzip` and decodes to the same bytes. A 40-character body stays identity.

## Unverified

- Render sends `Vary: Accept-Encoding` to an identity client too. bex sends it only when the request offered an encoding. The oracle app may set `Vary` itself, so this was not judged for web services. w8/359 saw Render's static edge send it to every client.
- Render's exact floor on web services was bracketed (31 B identity, 209 B gzip), not pinned at 48.

## Dedupe

w8/359 (done, static sites only, `820edf28d`), w8/m83 (the shipped web-service compression and its three signed-off differences), w8/227 (blocked: Brotli, `no-transform`, strong ETag). `rg -i 'minResponseBodyBytes'` over `.pm` and `lego/` finds nothing. `git log -S minResponseBodyBytes` finds no commit.

## Shipped 2026-11-22 (`1856c628c5`), live check owed

- **Render recheck, 17:35–17:50 UTC, `httpbin.onrender.com`.** Its `/user-agent` and `/get/args` JSON answers were sized byte by byte, with each identity size measured separately. With English text, 45 B stayed identity and 46 B was gzip. With random hex, 48 B stayed identity and 49 B was gzip. A body of one repeated character stayed identity at every size up to 1,015 B. So Render's edge has no single floor (the rule behind it is uncaptured). 48 sits inside its 46–49 B range and matches the static server's `minGzipBytes`. This settles the second Unverified bullet.
- **Fix.** `edgeCompressionMiddlewares` sets `minResponseBodyBytes: 48` (`edgeMinGzipBytes`). The content types, gzip-only encoding and `206` passthrough are unchanged. Static sites are untouched.
- **Tests.** `TestEdgeCompressionOnTheDeployedTraefik` (Traefik v3.7.17) now checks that a 48 B JSON body is gzip and a 47 B one is identity. The 100 B and 200 KB `Range` rows stay `206` identity. A stream of 31-byte NDJSON events (under the floor) still arrives gzip, one event at a time. `TestOriginServerOnTheDeployedTraefik` still passes its event-stream and gzip-stream checks. With the floor reverted, the 48 B row and the projection test's `minResponseBodyBytes` check fail. `make test` and `make lint` pass in `lego/operator`.
- **ADR018** (§ Edge compression for web services, "Small responses") records the floor and Render's range.
