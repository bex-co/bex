# A failed deploy's startup-crash reason says the instance "is restarting repeatedly" after it has stopped, and tells an exit-0 crash to check its port bind

Why: cli-qa routine run 30 (sweep r29, 2026-11-21 ~21:20–21:40 UTC, production pin `7e481dece7ac`, bex v0.9.0) ran free `busybox:1.36` web services that exit right after start (fixtures c4e0 and c4e1). The deploy's `failureReason` read "container exited shortly after start and is restarting repeatedly (last exit code N)". But since w4/m351 the instance is already stopped when the deploy fails: `/instances` answered `[]`, and no new start came within a minute. For exit code 0, the reason also says "If the crash is a port bind: the process must listen on $PORT".

- Severity: minor. The deploy's status is right; the reason a user reads describes a state that is over, and gives the wrong advice for a clean exit.
- Attribution: operator. The crash-settle text is in `lego/types/v1alpha1/deploy_reasons.go`, set from `lego/operator/internal/controller`.
- Dedupe: w8/383 is the `deploy_ended` event's empty `reason: {}` for an exit-0 crash. This item is the deploy's `failureReason` text. Fix them together if the same code sets both, but keep the verdicts separate.

## Render

Render's troubleshooting guide, re-read 2026-11-21 ([render.com/docs/troubleshooting-deploys#exit-code-0](https://render.com/docs/troubleshooting-deploys#exit-code-0)), under **Exit codes → Exit code 0**:

> Your app exited "successfully" but early. Web services, private services, and background workers all run continuously and should never exit unless they receive a `SIGTERM` signal. For workloads that exit after their task is complete, use a workflow or cron job instead of a continuously running service type.

Under **Startup failures**, a non-zero exit is "`Exited with status <N>`: Your application exited or crashed during startup. See the exit code to identify the cause."

## Fix

- The terminal `failureReason` for a startup crash says the instance has stopped, not that it is restarting.
- Exit code 0 gets the early-exit guidance: a web service's process must keep running and serve on `$PORT` until SIGTERM. A non-zero exit keeps the port-bind hint where it applies.
- Update every dashboard locale that renders this reason.

## Acceptance

- Unit tests cover the exit-0 and exit-1 reasons after settle.
