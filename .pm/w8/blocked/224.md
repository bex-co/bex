# `bex login` tells the user to complete login in the "Render Dashboard"

Why: the device-login prompt is the first thing a new CLI user reads, and it names the wrong product. `bex login` on the released `bex-cli/v0.3.3` prints `Complete login in the Render Dashboard with code: <code>` and then opens `https://oauth.bex.co/oauth2/device/verify?user_code=…`. The help text for the same command already reads "Log in to Bex using the Bex dashboard", so the command contradicts itself.

**Status:** blocked — explicit-login fix and local checks complete; awaiting user-authorized CLI release and published replay.

Severity: minor (branding; the flow itself works). Estimate: ~45m. Source: loopx w4 replay of w4/m116, 2026-10-29 UTC (`bex-canary`, released `bex-0.3.3-darwin-arm64`, `bex login --confirm -o text` with an empty `HOME`).

## Evidence

```
Complete login in the Render Dashboard with code: <redacted expired device code>

Opening your browser to:

	https://oauth.bex.co/oauth2/device/verify?user_code=<redacted expired device code>

Waiting for login...
```

## Cause

- Upstream `render-oss/cli` `pkg/tui/views/login.go` hard-codes the string in two places. Line 65 (non-interactive, `command.Println(cmd, "Complete login in the Render Dashboard with code: %s…")`) and line 178 (the TUI `LoadingMsgTmpl`, "Complete login in the Render Dashboard. Opening your browser to: …"); line numbers are from the cached upstream module.
- `lego/cli/internal/branding.RewriteText` already maps `Render Dashboard` → `Bex dashboard`, but it is applied only to cobra `Short`/`Long`/`Example`/flag usage (`branding.go:127-155`), not to runtime output.
- w8/m29 t002 explicitly left "hard-coded `fmt`/TUI strings inside upstream packages (`Complete login in the Render Dashboard`, `run \`render login\``, logout success copy)" out of scope, so this is the known remainder, not a regression.

## Direction

- No fork (DO_NOT_DO). The non-interactive line goes through the command's output writer, so the launcher can wrap the `login` (and `logout`) command's `cmd.OutOrStdout()` / `ErrOrStderr()` with a writer that applies `branding.RewriteText` line by line, keeping the URL and code byte-exact.
- The TUI path (`LoadingMsgTmpl`) renders through bubbletea and may not be reachable this way. Either rewrite at the same writer seam if the TUI output passes through it, or propose the wording upstream ("Complete login in the dashboard") and adopt it through the pin workflow.
- Tests: `bex login -o text` output contains "Bex dashboard" and the unchanged verify URL and code. Help text is unchanged.

## Unverified

- The interactive TUI rendering was not captured (the run used `-o text`).
- `bex logout` and other upstream runtime strings named in m29 t002 were not re-probed.

## Implementation outcome (2026-10-29) — explicit login fixed; release acceptance remains

- **Verified fix:** `lego/cli/internal/branding/branding.go` wraps only the explicit `login` command's output while retaining its upstream `RunE`. `loginOutput.Write` replaces only the complete fixed `Complete login in the Render Dashboard` prefix with `Complete login in the Bex dashboard`; everything after that prefix, including the user code and verification URL, is forwarded byte-for-byte. The original writer is restored when the runner returns. No upstream code is copied or forked, no request/config/credential flow changes, and stderr/other command output is untouched.
- **Regression evidence:** extending `TestBexLoginReportsBexReleaseNotRenderCLI` first reproduced the old prompt with a real subprocess against an isolated HTTP device-grant/token server. It passes after the fix for default, explicit text and explicit interactive output selections, asserting the Bex prompt, exact synthetic code/URL, successful OAuth completion and existing Bex update hint. `TestLoginOutputPreservesDeviceData` verifies that branding phrases inside the code/URL payload or a non-prompt write survive unchanged. `cd lego/cli && go test ./...`, `bash scripts/bex-cli-validate.sh` and scoped `git diff --check` pass. Root owns the required final Markdown/lint/ship checks.
- **Interactive boundary:** the actual explicit `login` runner is `views.NonInteractiveLogin` for both text and interactive output selections (`cmd/login.go:22` at current pin). The distinct automatic `LoginView` is installed inside *other* interactive commands by `cmd/root.go:69`; `cmd/fullscreen.go:13` constructs Bubble Tea without an exported output option, so Cobra stdout does not brand that separate path. The original filing explicitly left its rendering unverified. It remains an accurately documented upstream runtime-copy residual; this item does not claim to repair it or require an upstream fork.
- **Remaining gate / owner / release condition:** the user must explicitly authorize `/release cli` (as for existing w8/m67 and m143). After the released binary contains this change, replay `bex login -o text` and the default/interactive selection against Bex in isolated configs, verifying Bex copy with the exact actual device URL/code, successful login and scoped logout. A code push is not a CLI release, and current v0.3.3 is known to retain the old prompt. No external issue or PR was posted.
- **Disposition:** **blocked** on that published delivery/acceptance gate, with the implementable launcher fix and local tests complete. Recovered original provenance remains above; quota w8/223 stays independent.
