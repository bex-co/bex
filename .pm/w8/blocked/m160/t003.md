## Objective

Fix 2 of the note. t001 closes the window once the operator has recorded the new revision; the Deployment can switch traffic seconds before that, and a cancel landing in that gap is still accepted, after which the settle rolls a third instance back. Pick one:

1. Extend w4/m320's revision pin to every web and private rollout, so a candidate takes traffic only when the operator promotes it and a stamped release is never promoted (Render's sequence exactly); or
2. Keep the plain Deployment switch, and make the operator keep a canceled release it finds already serving and report it, so bex-api corrects the row to `live`.

## Carried here from the t001 review (2026-11-12)

- **The suspend path.** `recordDeploy`'s suspend cancel still calls the unguarded `store.CancelRelease` on a possibly stale observation; if the release turns active between that read and the stamp, the suspend stamps a serving release and a resume rolls back to the one before. Guarding it alone would leave the row open until the gate timeout, so it belongs with the decider.
- **One definition of live.** The guard refuses a cancel once `status.activeRevision` names the release; the reconciler closes the row live only for `RolloutSettling` or `Running`. A stall diagnosis that rewrites the reason on the same status write would leave a refused row `update_in_progress`, and a later failure could close it `update_failed`. Consider reading `ReleaseGeneration == G && servesGeneration` as live in `observedDeployStatus`'s `PhaseDeploying` arm whatever the reason (the operator records the revision only once every pod is Ready, w4/405's reading).

## Gate

Needs a cluster: the decision rests on when the Deployment controller moves traffic relative to the operator's status write, which envtest (no Deployment controller, no kubelet) cannot show. The local CAPD mock cluster is down until the host's inotify limits are raised (`sudo sysctl -w fs.inotify.max_user_instances=512 fs.inotify.max_user_watches=524288`), the same gate as w8/m156, w8/264, w8/282 and w8/283.
