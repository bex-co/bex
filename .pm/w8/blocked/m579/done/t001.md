## Objective

Add the control-plane Postgres tables and atomic `store.PGStore` operations that let multiple `bex-api` replicas share token-bucket rate limits and active log-subscription leases without race conditions, deadlocks, or unbounded table growth.

## Context

- Control-plane Postgres (`deploy/gitops/base/bex-postgres.yaml`) is the shared store `bex-api` already uses for cross-replica coordination (e.g. `shell_ticket_nonces` in `lego/backend/internal/store/migrations/0049_shell_ticket_nonces.up.sql` and `sshsessions.go:92`).
- Check the highest migration number on `origin/main` before creating the new migration (`scripts/migration_order_guard.py` enforces strictly higher numbering than `origin/main`).
- Multi-bucket requests (`core.ReserveEach`) check caller/row and workspace buckets together and must be all-or-nothing: if the second bucket refuses, the first must not lose a token.
- Classified GraphQL/MCP requests refund their general token (`core.RateLimitScope.Refund`), and `RefusedCredentialMiddleware` checks available tokens before serving and consumes 1 only on a credential refusal.
- Log subscriptions (`internal/logs/rest.go:450`) are long-lived streams bounded by global, per-subject, and per-workspace caps; leases need a TTL so a crashed replica cannot leak slots permanently.

## Steps

1. Create a new migration pair (`0NNN_shared_rate_limits.up.sql` / `.down.sql`, numbered above `origin/main`'s highest) adding:
   - `rate_limit_buckets (bucket_key TEXT PRIMARY KEY, tokens DOUBLE PRECISION NOT NULL, updated_at TIMESTAMPTZ NOT NULL, expires_at TIMESTAMPTZ NOT NULL)` plus an index on `expires_at` for pruning.
   - `log_subscription_slots (slot_id TEXT PRIMARY KEY, subject TEXT NOT NULL, workspace TEXT NOT NULL, expires_at TIMESTAMPTZ NOT NULL)` plus indexes on `expires_at`, `subject`, and `workspace`.
2. Implement atomic token-bucket methods on `*store.PGStore` in `lego/backend/internal/store/ratelimit.go`:
   - `TakeRateLimitBuckets(ctx, now, n, specs)` — sorts `specs` by `Key` (preventing deadlocks), locks/upserts each row in one transaction applying continuous token-bucket refill `min(burst, tokens + max(0, elapsed) * rps)`, checks whether every bucket has `>= min(n, burst)` tokens, commits the deductions only when all pass, otherwise rolls back and computes the wait duration until the tightest failing bucket can serve `min(n, burst)` tokens. Returns per-bucket post-state (`tokens`, `burst`, `rps`) and `wait`.
   - `RefundRateLimitBuckets(ctx, now, n, specs)` — atomically adds `n` tokens back (capped at `burst`) for each bucket in sorted key order.
   - `PeekRateLimitBucket(ctx, now, spec)` — returns current refilled tokens without deducting (for `RefusedCredentialMiddleware` pre-check).
   - `PruneRateLimitBuckets(ctx, now)` — deletes rows with `expires_at < now`.
3. Implement atomic log-subscription lease methods on `*store.PGStore` in `lego/backend/internal/store/log_subscriptions.go` (or alongside `ratelimit.go`):
   - `AcquireLogSubscriptionSlot(ctx, now, slotID, subject, workspace, ttl, maxGlobal, maxSubject, maxWorkspace)` — under a transaction-scoped advisory lock (`pg_advisory_xact_lock`), deletes rows where `expires_at <= now`, verifies the global, per-subject (when `subject != ""`), and per-workspace counts against the positive caps, and inserts the lease row with `expires_at = now + ttl` (returning `ErrLogSubscriptionLimit` if any cap is full).
   - `RenewLogSubscriptionSlot(ctx, slotID, expiresAt)` — updates `expires_at` while the stream stays alive.
   - `ReleaseLogSubscriptionSlot(ctx, slotID)` — deletes the lease row on close.
4. Add real-Postgres tests in `lego/backend/internal/store/ratelimit_pg_test.go` covering:
   - token deduction, refill over time, burst clamping, and `PruneRateLimitBuckets`;
   - multi-bucket all-or-nothing refusal (bucket 1 untouched when bucket 2 rejects) and concurrent multi-goroutine takes (no deadlocks, exact count admitted);
   - refund capping at burst;
   - subscription slot global/subject/workspace caps, release, renewal, and expired-lease cleanup.
