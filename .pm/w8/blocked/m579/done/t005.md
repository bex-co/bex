## Objective

Verify that the shared cross-replica rate limiter and log-subscription caps behave consistently across every tenant-facing surface (REST, GraphQL, MCP, deploy hooks, and log subscriptions) and match Render's documented rate-limiting contract.

## Context

- Reference: [api-docs.render.com/reference/rate-limiting](https://api-docs.render.com/reference/rate-limiting), [docs/ADR006-bex-api.md](../../../../../docs/ADR006-bex-api.md), [docs/ADR018-render-parity.md](../../../../../docs/ADR018-render-parity.md).
- Standing closing task per `.claude/skills/pm/SKILL.md`.

## Steps

1. Walk every surface wired to the shared limiter:
   - **REST (Render contract):** verify `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`, and 429 + `Retry-After` (`{"id":"rate_limited","message":"…"}`, `RateLimit-Remaining: 0`) across GET/HEAD (400/m), writes (30/m), log reads (30/m), service create (20/h), custom domain (50/h), jobs (100/m), and per-service deploy (10/m).
   - **MCP:** verify Render MCP tools spend their mapped REST row, refund the general token in the shared store, and refuse with tool error `rate_limited`; verify sandbox MCP tools spend their sandbox class in the shared store.
   - **GraphQL:** verify GraphQL queries/mutations keep `BEX_RATE_LIMIT`, batch admission charges `len(bodies)-1` extra tokens atomically across replicas, and sandbox fields refund the general token cleanly.
   - **Deploy hooks & dashboard sessions:** verify deploy hooks share the service's deploy row across replicas; verify dashboard Kratos sessions on REST still use `BEX_RATE_LIMIT` rather than Render's public API rows.
   - **Log subscriptions:** verify SSE, WebSocket, and NDJSON tails share the global/subject/workspace lease caps and answer `429 too many active log subscriptions` past the cap.
   - **Internal callers:** verify `:8091`, `/healthz`, `/readyz`, and in-process reconcilers remain unthrottled.
2. Flag any uncovered Render drift as a follow-up note rather than silently diverging, and record the parity check outcome in the milestone README.
