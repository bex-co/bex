# A service's inbound rules admit no IPv6 source under a lone `0.0.0.0/0`; decide the IPv6 side before service hosts publish AAAA records

Why: since w8/284 a web service or static site stores an allow-all list as written. `0.0.0.0/0` with any description other than Render's `everywhere`, or a list beside other all-ranges, projects a Traefik middleware whose `sourceRange` is `0.0.0.0/0` alone, which refuses every IPv6 source. Nothing reaches a service over IPv6 today (no service host publishes an AAAA record), so nothing breaks yet; the day the edge gets an AAAA record, every such service refuses its IPv6 clients while the dashboard calls it open.

**Severity:** minor (latent; no reachable path today). **Attribution:** operator (service `-ip-allow` middleware) and server (`core.RestrictsServiceInbound`). **Estimate:** ~45m. **Source:** review of the w8/284 fix, `/loopx w8`, 2026-11-12.

## Evidence

- `core.ServiceAllowListToSpec` (`lego/backend/internal/core/cidr.go`) saves no rule only for Render's default (`0.0.0.0/0` "everywhere") and the pre-w8/284 pair; any other non-restricting list is stored and `reconcileIPAllowListMiddleware` (`lego/operator/internal/controller/app_controller.go`) projects it.
- `core.RestrictsServiceInbound` treats a list without `0.0.0.0/0` as a restriction because the service edge is IPv4-only; that reasoning ends with an AAAA record.
- Inconsistent with datastores: the Postgres/Key Value SNI front door already admits IPv6 under a lone `0.0.0.0/0` (w8/140, `lego/operator/internal/sniproxy/allowlist.go` `anyIPv4`/`anyIPv6`).

## Fix

Before any service host gets an AAAA record: decide whether a stored `0.0.0.0/0` admits IPv6 (as the datastore front door does) or not, and either make the operator project `::/0` beside it (or no middleware for a list of only all-ranges), or migrate the stored rows. Revisit `RestrictsServiceInbound` and the dashboard's `isAllowAllRule` in the same change.

## Unverified

- What Render does for IPv6 under `0.0.0.0/0` (Render's services are IPv4-only as far as its docs say).

## Dedupe

w8/284 (done) created the stored lists; w8/140 (done) is the datastore side; ADR032 made the same IPv4-only choice for the environment HTTP layer.

## Parked 2026-11-12 (`/loopx w8`)

Nothing to change while no service host publishes an AAAA record: today's behaviour (a stored lone `0.0.0.0/0` admits every IPv4 source) is the parity-sufficient one, and no item plans IPv6 ingress. **Gate:** a decision or item to publish AAAA records for service hosts; this note's fix then lands before it.
