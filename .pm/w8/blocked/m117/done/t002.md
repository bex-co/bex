Done 2026-10-18 (loopx w8):
- `deploys.Cancel` → `cancelSurvivor`. Canceling the overlap-pending deploy of a repo-backed service names the deploy ahead of it, provided that deploy is a source build with no selected image, and the pending deploy only brought a source (api, deploy_hook or new_commit trigger).
- `store.CancelRelease(…, survivor, …)` stamps `app.bex.co/surviving-release-generation`. It also restores `spec.buildCommit` to the survivor row's commit (w5/138), but only while the canceled release is still the newest requested, so a racing deploy keeps its own commit.
- Every later cancel restates the survivor. A cancel of the survivor's own generation (a suspend, or Cancel of A) removes it.
- Operator: `survivorInFlight` pins A's identity (`pinnedReleaseDecision`, shared with the D1a pin) through its build and rollout. It requires the stamp to be latest, A to be the in-flight generation and unserved, and `pinnableSourceRelease` (repo-backed, not suspended, no selected release config, not a direct static publish). The cancel settles on A once A serves.
- A canceled decision now stops the build of a release in flight that it settled below (`stopAbandonedBuild`).
- Reconciler: `endedWithNewerCancel` closes an older row the cancel settled below. The row closes immediately with "Canceled along with dep-…".
- The other `CancelRelease` caller (the suspend-ended rollout) passes no survivor, so its behavior is unchanged.
