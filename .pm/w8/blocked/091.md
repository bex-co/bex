# SSH project filters start connection preparation before choosing a service

Why: choosing a project should narrow the SSH service chooser; the current CLI abandons that chooser and fails a lookup for an empty service name.

**Status:** blocked. **Worker:** worker8. **Severity:** minor. **Attribution:** upstream Render CLI routing. **Estimate:** 55m. Source: functional CLI QA sweep138, ADR008 hosting usability and the supported running-service SSH journey. Prepare an upstream correction and record the pin-adoption prerequisite; implementation, external submission and shipping require separate authorization.

## Boundary and scoped correction

- Pinned [`cmd/ssh.go:119–125`](https://github.com/render-oss/cli/blob/a764810a768202704e7206eb7b87a47211fcd98e/cmd/ssh.go#L119) builds a fresh SSHInput with the selected Project and EnvironmentIDs, leaving ServiceIDOrName empty. It calls uppercase **InteractiveSSHView**, the direct execution-view constructor at42–44.
- The correct chooser dispatcher, lowercase **interactiveSSHView**, has the empty-selector branch at53–76. That branch creates NewServiceList and uses `getServiceListInput:98–112`, retaining this project's nonempty environment scope and supported web/private/worker type restriction.
- `pkg/tui/views/ssh.go:33–38` always constructs an ExecModel. Its `loadDataSSH:140–149` resolves ServiceIDOrName through `getServiceFromIDOrName:107–137`; the latter sets `Name: &client.NameParam{idOrName}` at119–121 and does not consume Project/EnvironmentIDs. Here that is a one-element empty-name selector.
- `pkg/service/repo.go:27–36` adds the selected workspace, and the actual generated `pkg/client/client_gen.go:20410–20447` serializes the empty selector as `name=`. The [actual-pin builder probe](../evidence/091/builder-probe.go.txt), [module](../evidence/091/go.mod.txt), [checksums](../evidence/091/go.sum.txt), and [three outputs](../evidence/091/builder.json) preserve empty, nonempty and omitted name inputs without sending HTTP.
- [Separate API diagnosis](../evidence/091/diagnostic-wire.json) sends that generated empty-name shape: `GET /v1/services?name=&ownerId=tea-daif693dqjvc73e7as3g&limit=100` returns400 and complete `{error,id,message}` naming `name`. A nonempty absent-name control returns200 `[]`. These are diagnostic replays, not captured native requests. Regardless of how a server treats an empty name, the project action should return a chooser and should not attempt connection preparation.

Change **only this project callback's dispatch** to the existing lowercase chooser dispatcher. Preserve selected Project/EnvironmentIDs for the scoped list, and nil clearing for the unfiltered list. Keep direct service/instance arguments and the services palette's intentional direct-service SSH action on their existing paths. No server filter relaxation, request rewriting, launcher fork, new SSH transport or dashboard/GraphQL/MCP field is needed.

The [production caller census](../evidence/091/callers.json) has17 occurrences: six project-filter call sites plus its definition, eight direct SSH-view calls, and the chooser dispatcher definition plus its existing root-command call. **One** direct-view call is wrong here. The generic project filter (`pkg/tui/flows/options.go:58–68`) passes its handler to NewProjectFilterView; `projectfilter.go:27–32` uses that same handler for Save as default, and35–41 for Clear. Saving a default was source-affected but not natively tested in the initial sweep; the follow-up below now confirms it. Services, logs, psql, pgcli and kv-cli callbacks remain separately owned; do not rewrite the generic flow.

[Upstream main review](../evidence/091/upstream-status.json), SHA `c4d106cfdaf8eec6d23475155e43f4baeeed2013`, finds cmd/ssh.go byte-identical to the pin.
