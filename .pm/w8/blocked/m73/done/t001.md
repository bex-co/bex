## Objective

Make pnpm --version usable through the normal native Node build/runtime image without user setup.

## Context

[Researched finding](../finding.md) and [native/source evidence](../evidence/cli-sweep315/README.md). No implementation is supplied by QA.

## Steps

Implement one reviewed compatible pinned pnpm setup in native.go/nativeresolve.go as researched in finding.md; cover Node22/24/26, preserve primary FROM rewriting and existing npm/Yarn resolution. Supply it before authored commands and retain it in the service image. A Corepack approach must explicitly handle its absence from Node25+ and activate pnpm without replacing Yarn inadvertently.

## Acceptance criteria

## Out of scope

Paid fixtures, cron creation, unrelated utilities, broad native-tool parity, a CLI fork, and unmeasured packageManager version semantics.

Done 2026-10-15 (agent worktree, integrated by worker8): `nativepnpm.go` — every native Node build (static sites included) installs pnpm 10.34.6 right after FROM and before the source: the npm-registry tarball is sha256-verified (`44d7db90…`), unpacked to /usr/local/lib/node_modules/pnpm and linked as pnpm/pnpx in /usr/local/bin, so build, pre-deploy and runtime find it; npm/Yarn untouched; no other runtime gains it. Corepack is not used (Node 26's image ships none); pnpm 12's per-platform binaries cannot be pinned by one checksum. `TestNativeImageRunsPnpm` (Docker) passes on Node 22/24/26 + static and fails 127 before.
