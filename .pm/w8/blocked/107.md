# 107 — A valid output flag cannot override an invalid output default

Why: a script supplying an explicit output format should not fail because an unused environment default contains a typo.

**Severity:** minor. **Attribution:** upstream command initialization at the current Render2.27/a764810a7682 pin; also reproduced on the released2.29 tag build. **Estimate:** 35m. **Status:** blocked. Source: functional `$qa-find-bugs-cli` w8/sweep279; ADR008 usable hosting automation, ADR018 pinned CLI behavior. [Complete evidence and proposed upstream patch](../evidence/107/README.md).

In an isolated synthetic loopback fixture, installed Bex0.2.1 and published0.3.2 run `BEX_OUTPUT=qa-invalid-output bex workspaces --confirm -o json`. Each exits1 before HTTP, stdout empty, stderr `invalid RENDER_OUTPUT value: qa-invalid-output`. The unmodified exact-pin Render client with RENDER_OUTPUT does the same. An unmodified2.29 tag build also fails. All four subjects otherwise pass eight format/precedence/refusal/help controls each. No QA credential, real owner or production fault is used.

Expected: the explicit valid flag wins over the default, returning0/JSON containing the fixture owner; invalid defaults still error when selected, and invalid explicit flags remain errors. Bex docs describe BEX_OUTPUT as the default; upstream ResolveAutoOutput also puts an explicit flag ahead of ForcedOutput. Actual: rootPersistentPreRun calls DetectRuntimeSignals at `cmd/root.go:264` before ResolveAutoOutput at268. `pkg/command/outputresolver.go:49–53` parses/validates RENDER_OUTPUT unconditionally and returns early, so the explicit-flag branch at76 is never reached. The bridge's mapping at `lego/cli/internal/bridge/bridge.go:73–86` is correct; no server request is made and no Bex backend fix is proposed.

Research: a private exact-pin overlay moves environment/auto detection under the flag-absent path, after the normal StringToOutput flag validation. All12 native diagnostic cases pass, including explicit JSON/YAML/text over the invalid default and strict invalid-selected-default/invalid-flag controls. Existing root/output/runtime/context tests pass43 named cases in two packages. One initial overlay with a noncanonical symlink path failed to apply and is retained separately; it is excluded from fixed evidence. No repository Go file is changed.
