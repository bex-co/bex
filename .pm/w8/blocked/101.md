Why: an author fixing a static route or header is directed to the service header or its unrelated name, although validation knows the exact array item and field.

## Boundary and mechanism

Four actual unchanged multipart POST `/v1/blueprints/validate` captures return HTTP200. Two contain the wrong API path/line and two are positive controls. Native decoded validity/errors match the server, establishing server ownership. Credentials are omitted. [Wire receipts](../evidence/101/native-wire.json).

- `service.go:4975–4984` already names routes[i].source/destination in refusal messages; `:5033–5041` names headers[i].path/name. The same validators also serve ordinary create and the dedicated setters (two production call sites each).
- `deploy.go:1330–1343` wraps the failure in the service resource context, and `:1347–1350` retains the refusal text from specFromCreate. It reaches shared Blueprint validation's per-resource mapper.
- `blueprint.go:763` appends `blueprintErrorField(msg)` to the resource path. The keyword classifier at `:1957–1960` has no routes/headers indexing grammar: source/destination/path fall back to the declaration, while name chooses the unrelated top-level service name.
- The env-entry, domain-entry and coded-field overrides at `:764–769` cover other contexts, but no override consumes the already-known static rule index/field. `blueprintLocatedError:864–881` then emits the wrong path and ancestor location even though the correct leaf exists in source.Locations.
- Pinned `cmd/blueprintvalidate.go:125–173` decodes and prints the API result; `:176–187` consumes its path/line/column for interactive diagnostics. Both modes are affected by the server data; JSON is live-tested here, interactive display is source-traced.

They use a private virtual overlay and assert the existing bug, not a fixed regression. Four existing neighboring aggregation/domain/env-location tests also pass. No full suite is claimed. ## Scoped fix and acceptance

Add an indexed static-rule field locator before the keyword fallback in the per-resource mapper. Consume only the known routes[i].type/source/destination and headers[i].path/name/value refusal forms, verify the declared array index/field exists, then build the nested JSON pointer from the caller resource. Preserve honest array/declaration fallback for collection-wide limits and out-of-range or unrecognized messages. A field-existence check alone cannot fix the header-name case because the unrelated service name exists. Preserve validation decisions, static rules and all message meaning; no launcher or HTTP envelope change is needed.

- The eight root/nested invalid fixtures retain exit1/valid:false and now report the exact second-rule field path/line/column above through both native clients.
- Add meaningful current-service regression cases for routes and headers at both placements, including headers[i].name, and an invalid first-item case. They fail before the location fix and pass after it.
- Combined valid rules, splat redirects, empty header values and empty lists stay valid. Existing env-reference, domains, coded-field and multiple-resource diagnostics keep their locations.
- Review all four callers of the per-resource mapper and its nearby fallback paths. Shared validation/preview exposes results through REST (rest.go:1346), GraphQL errorDetails (graphql.go:1044/1259) and MCP (mcp.go:1024); dashboard views.ts:111–118 carries the same details. Verify those surfaces with the same harmless invalid fixture. Only native REST validation is live-tested by this hunt; other consumers and apply behavior are source-traced.
- Run the relevant backend checks and review the small change. No changes to rule admission, pricing, operator runtime or pinned CLI semantics.

## Outcome (2026-10-13) — fix shipped, blocked on hosted acceptance

- **Fix:** `blueprintStaticRulePointer` (`lego/backend/internal/apps/blueprint.go`) reads the `routes[i].field` / `headers[i].field` the static validators already name, checks the resource declares that index, and points at the authored field (or the rule entry when the field is absent) before the keyword fallback. Out-of-range or unrecognized messages keep the previous fallback; decisions, messages, env/domain/coded-field overrides and the four mapper callers are unchanged.
- **Tests:** `TestBlueprintStaticRuleErrorsLocateTheRule` (`blueprint_static_rule_location_test.go`) covers second-rule route source/destination and header path/name plus a first-route case, root and project-environment: one refusal each, exact field path and that field's own line. All 10 fail on the original locator; combined rules, a splat redirect and an empty header value stay valid; backend apps tests pass.
- **Blocked:** the native replay (both clients, root/nested) and GraphQL/MCP/dashboard detail checks need the fix deployed to production.
