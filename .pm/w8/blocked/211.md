# Service URLs offer no HTTP/3: Render serves every `onrender.com` and custom domain over HTTP/3 (`alt-svc: h3=":443"`), while bex's edge is TCP-only

Why: Render's edge enables HTTP/3 by default on every service. Render staff say: "HTTP/2/3 is enabled by default on all services so you shouldn't need to do anything" ([community.render.com/t/http-2-and-http-3/4826](https://community.render.com/t/http-2-and-http-3/4826)). Every live `onrender.com` response advertises it. bex service URLs answer only HTTP/1.1 and HTTP/2 and advertise no `alt-svc`, so browsers and clients never upgrade to QUIC. Mobile and lossy-network users lose the latency and head-of-line benefits they get on Render, and anything that negotiates h3 (for example, WebTransport experiments) has no path. The app itself needs no change on either platform, because TLS and QUIC terminate at the edge.

Severity: **minor** (performance/transport parity; every request still works over HTTP/2). Attribution: infra (tenant edge: Hetzner Load Balancer + Traefik). Estimate: ~2h plus a design decision. Source: `/qa-find-bugs-cli` loop sweep 3093, 2026-10-28 10:20 UTC. Context: platform pin `838feec85fdd`; `https://api.bex.co/v1/`; workspace `bex-canary`.

## Evidence

```text
# Render (four public hosts, 2026-10-28)
$ curl -sI https://express-hello-world.onrender.com/   → HTTP/2 503 · server: cloudflare · alt-svc: h3=":443"; ma=86400
$ curl -sI https://render-examples-express-hello-world.onrender.com/ → HTTP/2 404 · alt-svc: h3=":443"; ma=86400
$ curl -sI https://flask-hello-world.onrender.com/     → HTTP/2 404 · alt-svc: h3=":443"; ma=86400
$ curl -sI https://docs.render.com/                    → HTTP/2 301 · rndr-id: … · alt-svc: h3=":443"; ma=86400

# bex (owned Free fixture qa-20261028-3093-sink, srv-dbgsj0lgf0kc739tgk8g)
$ curl -sI https://qa-20261028-3093-sink.onbex.co/
HTTP/2 501 · rndr-id: 596212d0-… · server: BaseHTTP/0.6 Python/3.14.8 · (no alt-svc)
```

Even a 404 or a suspended (503) Render host carries `alt-svc: h3`, so the advertisement is edge-wide, not per app.

bex's own hosts already have it. `dashboard.bex.co` (HTTP/2 307) and `api.bex.co` (HTTP/2 401) are Cloudflare-proxied (`server: cloudflare`, `cf-ray`) and both carry `alt-svc: h3=":443"`. Only tenant URLs lack it: `qa-20261028-3093-sink.onbex.co` resolves straight to the Hetzner LB `49.12.20.236`. ADR022's client-identity table (line 174) records every `*.onbex.co` host as a non-Cloudflare peer by design.

## Root cause

- `deploy/gitops/base/values/traefik.values.yaml` defines the `websecure` entrypoint without `http3: {enabled: true}`, so Traefik neither listens on UDP 443 nor sets `alt-svc`.
- Even with that flag, production traffic cannot reach it. `infra/terraform/main.tf` (`hcloud_load_balancer_service.https`) fronts the edge with a Hetzner Load Balancer, `protocol = "tcp"`, 443 → NodePort 31976 with PROXY protocol. Hetzner Load Balancers forward only TCP/HTTP/HTTPS, never UDP. The node firewall (`hcloud_firewall.app_nodes`) opens no public UDP either.

## Proposed fix (needs a decision)

QUIC needs a UDP path to the edge. Options:

1. Publish UDP 443 directly on edge nodes, using a Hetzner Floating/Primary IP per edge node (or DNS A records for the edge nodes). Add a firewall rule for `udp 443`, enable `http3` on `websecure` (with `advertisedPort: 443`), and keep TCP on the LB. Clients that cannot reach UDP fall back to h2 automatically, because `alt-svc` is only a hint. Trade-off: the real client IP for QUIC comes from the UDP source instead of PROXY protocol. Check that the w8/m123 client-identity sanitizer and the IP allowlist (ADR018 row 155) still see the true client IP.
2. Proxy `*.onbex.co` through Cloudflare, as `bex.co` already is. This matches Render's Cloudflare edge most closely, but ADR022's client-identity model (it trusts `CF-Connecting-IP` only from Cloudflare peers), wildcard edge certificates, WebSocket and long-upload limits (w8/207's 6000 s versus Cloudflare's 100 s proxy read timeout), and DNS-only custom domains would all need rework. That is a much larger change.
3. Sign off on an ADR018 divergence ("HTTP/3 not offered") if neither is worth it now.

Option 1 is the parity-sufficient choice. Option 2 is a separate follow-up if it is ever wanted.

## Triage (2026-10-28)

**BLOCKED on a user decision.** The premise holds at HEAD `bab5e727c`. `websecure` has no `http3` in `deploy/gitops/base/values/traefik.values.yaml`. The LB service is `protocol = "tcp"` (`infra/terraform/main.tf:219`), and the node firewall opens no UDP.

This is not an optional-variant decision that parity work can step past. Every option changes the production tenant edge, and option 1 also adds recurring spend:

- A push to `infra/terraform/**` runs a credentialed `terraform apply` on production (`.github/workflows/infra.yml`).
- Edge nodes are Cluster API machines that come and go. Option 1's per-node Floating/Primary IPs are billed, and need an always-on reassignment mechanism plus a public UDP firewall rule.
- Every `*.onbex.co` and custom-domain A/CNAME would also move off the LB, unless the alt-authority variant below is used.

Shipping the Traefik `http3` flag alone, before a UDP path exists, is worse than today. Clients would try QUIC to the TCP-only LB IP, fail, and mark the alternative broken.

**Design input for the decision (bex5 triage):** RFC 7838 lets `alt-svc` name a different host, e.g. `alt-svc: h3="h3.onbex.co:443"`. The alternative server only has to present a certificate valid for the origin, and Traefik already selects that by SNI. Tenant and custom-domain DNS can then stay on the TCP LB, and only one new name (`h3.onbex.co` → the edge nodes' UDP-reachable IPs) is added. Traefik's `http3.advertisedPort` cannot set a host, so the header would come from a headers middleware on `websecure`. The client-IP caveat from option 1 (no PROXY protocol on UDP; w8/m123 sanitizer, IP allowlist) still applies.

**Needed from the user:** choose option 1 (paid per-node IPs, optionally via the alt-authority variant above), option 2 (Cloudflare-proxied `*.onbex.co`), or option 3 (sign off an ADR018 "HTTP/3 not offered" divergence). The implementation follows once that choice is made.
