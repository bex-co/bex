# A static site's `404.html` miss carries no `ETag`, where Render sends the page's own tag on the 404

Why: Render's static sites send the `404.html` page's `ETag` on a miss, but bex sends none, so a site moved from Render loses that header on every 404 page it serves.

- Severity: minor. Every client still gets the right status and body. Only the `ETag` header differs.
- Source: found by the w8/359 `/loopx w8` worker on 2026-11-20, while it probed Render's encoding of 404s.

## Repro

```text
# Render, 2026-11-20
mentorship-guide.onrender.com /qa-nope-z  Accept-Encoding: gzip, br               404  2,511 B br        etag: "a39a83ad03f1bb20e08819b6da093059"
mentorship-guide.onrender.com /qa-nope-z  no Accept-Encoding                      404  7,873 B identity  etag: W/"a39a83ad03f1bb20e08819b6da093059"
mentorship-guide.onrender.com /qa-nope-z  gzip, br + If-None-Match: "a39a83ad…"   404  2,511 B br again (no 304)
sveltekit-static.onrender.com /qa-nope-y  (bare 404, no 404.html)                  404  no etag
```

bex sends the page with no `ETag` (`serveNotFound` passes `""` to `setFileHeaders`, `lego/operator/internal/staticserver/staticserver.go`). w8/322 chose that so that a conditional request could not read the error body as a cache hit. Render never answers a 404 with a 304 either, but it still sends the tag.

## Fix sketch

Send the page's generated `ETag` on the `404.html` miss: weak on the br body and strong on identity (w4/341), retyped as `serveObject` does when a `Content-Type` rule changes the type. Keep answering 404 with the page whatever `If-None-Match` or `If-Match` says, never 304 or 412. The bare 404 keeps sending no tag. Amend ADR029 § Miss handling, which says the page has no `ETag`, and the ADR018 static-site row.

## Acceptance

- On a free static site with a `404.html`, a miss sends the page's `ETag`, and a request whose `If-None-Match` matches it still gets the 404 with the page.
- A bare 404 sends no `ETag`.

## Outcome

- 2026-11-20 triage: the premise held at main `41df490fc`. `serveNotFound` passed `""` to `setFileHeaders`, so the `404.html` miss had no `ETag`.
- Render measured on 2026-11-20 (about 30 read-only requests to `mentorship-guide`, `buzz-docs`, `breadcrumbs-wiki`, `wc3v`, `black-widow-site` and `whatseasonisitinhorizon`):
  - Each of the four sites with a `404.html` sent, on a miss, the same `ETag` that its `/404.html` sends in the same coding: strong on br, weak (`W/`) on identity, and identity to a gzip-only client.
  - `If-None-Match` with the br tag or the identity tag, `If-None-Match: *`, a foreign `If-Match` and `Range: bytes=0-9` each got the full 404 page, never a 304, 412 or 206. The 404 has no `Accept-Ranges`.
  - The two sites with no `404.html` sent the bare `Not Found` with no `ETag`.
- Fixed in `67a1aa91f`:
  - The `404.html` miss sends the page's generated tag: the tag a fetch of `/404.html` gets in the same coding, weak on br and strong on identity (bex's w4/341 direction), and retyped by a `Content-Type` rule as a file's is. The retype now lives in `setFileHeaders`, shared by `serveObject` and the miss.
  - The miss still never goes through `http.ServeContent`, so every precondition and `Range` still gets the full 404. The bare 404 still sends no tag.
  - Tests: `TestThe404PageSendsItsOwnETagAndStaysA404`, plus tag checks in `TestMissServes404HTMLWithStatus404` and `TestThe404PageTakesTheSitesRulesAsAFileDoes`. All three fail with `""` put back.
  - Checks: `make test` and `make lint` pass. ADR029 § Miss handling and the ADR018 static-site row record the rule.
- Render's tag direction (strong on br, weak on identity) is the opposite of bex's on every file. ADR029 already records it. It is out of this note's scope.
- Parked: production's pin `7474e1c6a` (images `820edf28d22d`) predates the fix. Once the pin carries `67a1aa91f`, sign in as the QA user and, in `bex-canary`, create a free static site whose build writes `index.html` and `404.html`. Then check:
  - A miss with `gzip, br` sends the weak tag that `/404.html` sends with `gzip, br`, and a miss with no `Accept-Encoding` sends `/404.html`'s strong tag.
  - A miss with `If-None-Match` set to either tag still gets the 404 with the page.
  - Change the build command so it writes no `404.html`, deploy, and check that a miss gets the bare `Not Found` with no `ETag`.
  - Delete the fixture and close.
