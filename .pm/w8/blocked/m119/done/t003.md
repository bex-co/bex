## Objective

Make the deploy reconciler close an executing row `live` (then `deactivated`) whenever the operator records its release served, and keep the "missed-observation" canceled fallback only for rows whose release never served. Confirm Restart selects the truly serving release during the window.

## Context

- `lego/backend/internal/store/reconciler.go:1529` (`supersededDeployStatus` `:1500`, comment `:1520-1528`), `observedDeployStatus`.
- `lego/backend/internal/deploys/rollback_config.go:202` `servingDeploy` resolves `status.activeRevision` (w4/m201).
- Existing tests: `store/deploys_test.go:146` `TestLiveTransitionDeactivatesPriorLiveDeploy`, `:177` `TestCreateDeployKeepsActiveAndQueuesLatestOverlap`, `reconciler_test.go:1206` `TestObservedDeployStatusCancelsSupersededRow`.

## Steps

1. When `releaseGeneration` has passed the open row but the operator's served evidence names the row's generation, close it `live` (deactivating the prior live row), not `canceled`.
2. Keep the canceled fallback for rows whose release never served, and keep `build_failed` precedence (w6/m100).
3. Verify `servingDeploy` resolves the served row during the window; add a case where the served row is still projecting.
4. Add a reconciler test that replays the real operator CR sequence from the finding's repro 3 timeline.

## Outcome (2026-10-19)

In `supersededDeployStatus`, before the canceled fallback for a release generation past the row:

- a row whose release served (`activeRevision == rev-<gen>`) closes **live**, which deactivates the prior live row;
- a row with a durable pre-deploy failure closes **pre_deploy_failed**;
- a row with a durable rollout failure closes **update_failed**, with its diagnosis.

Only a release that never settled closes canceled. The live close records `status.image` as the row's resolved image while the newer release still builds (`servedBehindBuildingRelease`), so Restart and Rollback have the artifact. `servingDeploy` already resolves the served row by `activeRevision`. While that row is still projecting and the newer release is current, it refuses retryably and never restarts an older release.

Tests, which fail before and pass after:

- `TestReconcileOverlapRecordsServedReleaseAfterTheNextIsAdopted` replays repro 3's sequence. The backend first looks after adoption; gen 2 goes live then deactivated, the prior row deactivated, and the resolved image is gen 2's.
- `TestReconcileOverlapKeepsTheFailedRolloutVerdictAfterTheNextIsAdopted` covers a failed rollout.
