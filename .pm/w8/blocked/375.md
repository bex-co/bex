# No public free-plan `render.yaml` exercises Blueprint references end to end, so cli-qa can only validate them

Why: cli-qa routine run 25 (sweep r25-9f91, 2026-11-21 12:38–13:05 UTC, production pin `cce6c749f6ff`, bex v0.9.0) wanted to test Blueprint references at runtime. No public repo has a free-only `render.yaml` that combines `envVarGroups`/`fromGroup`, `generateValue`, `sync: false`, `rootDir`, `buildFilter` and `fromService` (`envVarKey`, or a static site's `host`). The run proved them with 47 `blueprints validate` cases, plus one runtime case (`generateValue` in `render-examples/mcp-server-typescript`), but cannot show the other resolved values reaching a process.

- Severity: minor. This is test coverage, not a product bug.
- Free targets limit the shape:
  - `host`/`port`/`hostport` pointing at a free web service are refused by design (w8/m130);
  - workers, private services and cron jobs are paid on both bex and Render (ADR030 §7).

  So the fixture can use only free web services and static sites, linked with `fromService` `envVarKey` and a static site's `host`.
- Dedupe: no `.pm` item matches. `examples/` has single-service probes (`default-env-probe`, `build-probe`, `cron-demo`), but nothing with Blueprint references.

## Fix

Add `examples/blueprint-refs/render.yaml` with free web services and a static site only, plus a small app. Its `GET /` reports a harmless marker for every resolved reference: the `fromGroup` value, the `fromService` `envVarKey` value, the static site's `host`, and whether the `sync: false` key is present and empty. For `generateValue`, it reports only the length and the base64 shape of the value, **never the value itself**. Put the app under a `rootDir`, and give it a `buildFilter` so a change outside that directory does not redeploy it.

## Acceptance

- `bex blueprints validate examples/blueprint-refs/render.yaml` exits 0.
- In `bex-canary`, `bex ea blueprints create --repo https://github.com/bex-co/bex --path examples/blueprint-refs/render.yaml` followed by approve deploys it, and `GET /` serves the report with every marker as expected. A re-plan reads `no_changes`.
- Every created resource, including the env group and the Blueprint instance, is deleted by ID with its 404 confirmed.

Estimate: ~1h.
