Why: a Node app with an ordinary npm start command and a correct SIGTERM handler loses its in-flight response before its configured shutdown delay can help it.

## Exact fix and blast radius

Give the **primary Node serving launch** a static absolute startup helper that starts the exact existing /bin/bash -c command in its own child process group, forwards termination to that group, and remains alive while terminating descendants finish/reap. Preserve the launched command's normal exit/error status, signal behavior, stdin/stdout/stderr, cwd, exact argv, PATH and environment. During termination, an npm ancestor exiting must not end the container while its app child is draining. Exercise launch/exit/signal races and bounded uncooperative children with real processes.

Package the helper alongside native-resolve through lego/Dockerfile's existing CGO_ENABLED=0/TARGETARCH build and copy paths. The operator already supplies its own image as Options.NativeResolverImage (build.go:371–374; app_controller.go:1048); reuse this delivery seam for the serving helper. Specify and test behavior for an empty/legacy helper-image option, unavailable artifact and supported target architectures. Copy/install only into the primary Node serving tail after the build RUN/static return; use an absolute entrypoint so w8/m61's custom/empty PATH contract remains valid, while the existing CMD bytes remain exact. Build phase and Node's runtime-only NODE_ENV default keep their current meaning. A future implementation must validate this wiring against the real generator/resolver, not only this local model.

Give those consumers explicit source/test dispositions without claiming unrun paid hosting acceptance.
