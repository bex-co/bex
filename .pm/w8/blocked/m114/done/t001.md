## Objective

Fix, before any code, the Postgres schema, the surviving OpenBao layout, the cutover sequence, the data-migration rules and the deliberate breaks. Rewrite ADR013's env-group sections and ADR006's name-uniqueness paragraph to describe the new design rather than the KV history.

## Context

- Every non-secret path and workaround to replace is listed in the milestone README ("What goes away"). Inventory them again with `grep -n '"env-group' lego/backend/internal/envgroups/*.go`.
- ADR013 env-group text: `docs/ADR013-secrets.md:41-45`; projection ordering (keep): `:98`. ADR006 name uniqueness: `docs/ADR006-bex-api.md:632`.
- Revision tokens are opaque `egr1_<version>` (`lego/backend/internal/envgroups/revision.go`), today the KV version of the revision record.
- FK targets: `tenants(id)`, `environments(id)`, `apps(id)` (all `text` primary keys).

## Steps

1. **Schema.** An `env_groups` table (id PK, `tenant_id` → `tenants` ON DELETE CASCADE, name, `environment_id` → `environments` ON DELETE SET NULL, `created_at`, `updated_at`, `UNIQUE (tenant_id, name)`) and an `env_group_links` table (`group_id` → `env_groups` CASCADE, `app_id` → `apps` CASCADE, both as the primary key). Decide what replaces the revision record and the op record — a generation column with row-lock or CAS updates, lease columns or an operations table — and the new revision-token prefix.
2. **OpenBao layout.** Only `env` and `files` under the group's workspace tenant, plus `op/<opID>/{old,new}-{env,files}` while a save is in flight. Confirm that no non-secret value stays in OpenBao.
3. **Cutover.** Default plan: snapshot OpenBao; take the API (or the env-group routes) down; `apply` copies metadata into Postgres and copies values to their workspace-tenant paths without deleting anything; the new revision starts; verify; `prune` then deletes every other path. Before prune, rollback is redeploying the previous image. Decide how the new revision refuses to serve env groups before `apply` has run, for example a cutover-marker row. Any such gate is deleted in t008.
4. **Migration rules.** Ownerless groups go to `core.DefaultTenant` (today's lazy rule). Links stored as names resolve to ids by today's `migrateLinks` rules; unresolvable ones are dropped and reported. Fenced or stale ids are not migrated. Duplicate names inside a workspace stop `apply` with a report — never a silent choice.
5. Record the deliberate breaks (milestone README) in ADR013.

## Decisions (2026-10-18)

**Schema** — one table, `env_groups`, plus a transitional `env_group_cutover` marker table:

| column | replaces |
| --- | --- |
| `id` PK, `tenant_id` → `tenants` ON DELETE CASCADE, `name`, `UNIQUE (tenant_id, name)` | meta `name`/`workspace`, the name-claim index (`env-group-name-claims/*`), the legacy locator, `ENV_GROUP_NAME_RESERVED`, `ENV_GROUP_NAME_AMBIGUOUS` |
| `environment_id` → `environments` ON DELETE SET NULL | meta `environment` |
| `service_links text[]` (ordered, no FK) | meta `links` / `linksByID` |
| `env_keys text[]`, `file_names text[]` | the two OpenBao map reads every list/get hydration made — key and file names are non-secret and already shown without the sensitive scope |
| `created_at`, `updated_at`, `meta_version` (optimistic CAS) | meta timestamps and the meta path's KV version (`mutateMetaCAS`) |
| `content_state` (`idle`/`busy`/`repair_required`), `content_generation`, `content_version` (CAS token) | the `revision` record and its KV version |
| `op_id`, `op_kind`, `op_phase`, `op_lease_until`, `op_env_changed`, `op_files_changed` | the `op` record; the claim now writes `busy` and the op in one statement, so "busy without recovery evidence" can no longer exist |

- **No `env_group_links` table and no FK to `apps`:** initial links are composed before a new service's App (and its `apps` row) exists (`initial_links.go`). Deleting a service keeps removing its links through `WorkspacePurger.UnlinkApp`, now one CAS per mounted group.
- **No resurrection fence:** a delete removes the row (`DELETE … RETURNING`); every later meta or content write is a CAS that matches no row and reports not found, and ids are freshly minted, so nothing can re-create a deleted id. `plantDeletedMetaFence` and `clearMetaCAS` go.
- **Revision tokens keep `egr1_`:** they already encode the generation, not a KV version, and the migrator copies each group's generation, so tokens issued before the cutover stay valid. (This removes the "tokens rejected" break listed in the milestone README.)
- **Create:** a name pre-check fails fast before any side effect; the row insert stays the last write (the commit point, as the meta write was). A lost race hits the unique index and compensates exactly like any other failed create. A crash before the insert leaves only unreferenced value paths, invisible to every read.
- **Rename:** one meta CAS; a unique violation answers `ENV_GROUP_NAME_EXISTS`.

**OpenBao layout after cutover** — under the group's workspace tenant only: `env-groups/<gid>/env`, `env-groups/<gid>/files`, and while a save is in flight `env-groups/<gid>/op/<opID>/{old,new}-{env,files}`. Delete removes all of them, every op map included (today's `clearOpArtifacts(…, "")` left them behind).

**Store-off mode goes:** `Service.Groups` (the store seam) is required; nil answers `core.ErrSecretsUnavailable` like a missing OpenBao.

**Cutover** (all on production pods, nothing from a laptop):

1. Ship the code with a gate: until a row exists in `env_group_cutover`, every env-group verb answers 503 `ENV_GROUPS_CUTOVER_PENDING`, and environment membership treats groups as absent. Old pods keep serving the KV layout until the rollout replaces them.
2. After the rollout: snapshot OpenBao (`kubectl -n secrets create job --from=cronjob/openbao-backup …`).
3. `kubectl exec` into a bex-api pod: `/api env-group-cutover dry-run` (no writes), then `apply`: insert rows, copy legacy-resident values to workspace-tenant paths, write the marker. Nothing in OpenBao is deleted. Re-running `apply` is a no-op.
4. Verify live, then `prune`: delete every non-value env-group path in every workspace tenant, everything under the legacy tenant's `env-groups/`, every name claim, and every stale or fenced id's residue.
5. Rollback before prune: redeploy the previous image (OpenBao is untouched); after prune: restore the snapshot.
6. t008 deletes the subcommand, the migrator, the gate and the marker table (a drop migration).

**Migration rules:** canonical meta is the workspace-tenant copy when editable, else the legacy full copy; locators, tombstones and empty fences are not groups. Ownerless → `core.DefaultTenant`. Links not stored by id resolve through today's `migrateLinks` rules; unresolvable ones are dropped and reported. An environment that no longer exists becomes NULL (reported). `apply` refuses, with a report and no writes, on duplicate names within a workspace, a group whose tenant has no `tenants` row, or a group not idle (busy or repair_required).

ADR013 is rewritten with the code (t003), so the document never describes a layout that is not shipped.
