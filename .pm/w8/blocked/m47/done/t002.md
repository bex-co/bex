## Objective

In `core/base.go` `AuthorizeApp` (`:1054-1080`) and `GetApp` (`:1505-1530`), resolve a non-id argument against the **displayed** name (display name when set, else creation name) within the workspace, and refuse ambiguity (coordinate with w8/m45 t002). Consider mirroring the display name into a label, so the lookup stays a label selector.

## Acceptance criteria

- [ ] The sweep-19 swap reproduction: `deploys list …-a` returns B (the service listed as `…-a`).

## Outcome (2026-09-27) — done

`core.Base.appByDisplayedName` runs in `AuthorizeApp` and `GetApp` after the typed-id lookup and before the creation-name lookups. It matches the name each service in the acting workspace is **shown** as (`spec.displayName`, else the creation name). One match resolves (then m45's cross-workspace guard applies), none falls through to the creation-name path (an old name keeps working until another service shows it), and several return `409 SERVICE_NAME_AMBIGUOUS` with the ids. A label mirror was rejected because display names are free text (spaces etc.), so this is a workspace-scoped list plus an in-memory match, paid only on by-name requests. Tests: `core.TestByNameResolvesTheDisplayedName` (the sweep-19 swap → B, new name, old name, never renamed) and `TestByNameRefusesDuplicateDisplayedNames`.

## Additional fix (2026-10-02)

The live recheck exposed the default-workspace-only limit: a renamed service in `bex-canary` returned 404 when the account default was `bex`. The resolver now checks current displayed names across member-workspace labels when unselected, with per-resource authorization and visible ambiguity detection. Explicit selections stay within that workspace, including the legacy alias fallback. The new full-router and core tests pass; disabling the cross-workspace displayed-name search makes the regression fail. Production recheck remains in t007 after ship.
