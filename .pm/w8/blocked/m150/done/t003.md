## Objective

When the repo is read anonymously (no installation token) and the API read still fails with a 5xx, transport error or timeout, `resolveBlueprintCommit` resolves the branch with git smart-HTTP `ls-remote` (`github/public_git.go`, w8/209), and `fetchBlueprintFileAtCommit` reads `https://raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>` with the same size limit. A 404 from the fallback keeps the existing not-found reasons; when both paths fail, the existing "Could not reach GitHub" reason stands. Log each fallback with the API error it replaced.

## Acceptance criteria

- [x] Tests: an API 502 or timeout on a public repo is answered by the fallback; an API 404 never reaches the fallback; a private repo (token) never uses it; both failing keeps the 503.

## Done — 2026-11-10

For an anonymously read (public) repo, when the API still fails with a 5xx, timeout or transport error:
- `resolveBlueprintCommit` resolves the branch through `resolvePublicGitCommit`, the smart-HTTP advertisement from w8/209.
- `fetchBlueprintFileAtCommit` reads `raw.githubusercontent.com/<owner>/<repo>/<commit>/<path>` through the anonymous SSRF-guarded client, with `maxBlueprintFileBytes`. A raw 404 answers as the contents API's not-found does.

Each fallback is logged with the API error it replaced. When both paths fail, the original error and its "Could not reach GitHub" reason stand. A 404 never reaches the fallback, and a connected repo (installation token) never uses it.

Tests:
- `TestBlueprintPublicRepoFallsBackWhenTheAPIFails`: a 502, a reset and a timeout each resolve and read through the fallback, and a raw 404 is still a not-found.
- `TestBlueprintFallbackKeepsTheRepositorysAnswers`: an API 404 keeps `ErrBranchNotFound`, and a connected repo stays on the API.

The shared test Service now refuses network by default.
