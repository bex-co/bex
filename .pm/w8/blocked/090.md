# Fresh CLI configs open dashboard resources as filesystem paths

Why: a supported environment credential can load hosting resources without device login, so their Dashboard action needs a Bex origin before any login has populated local configuration.

**Severity:** minor. **Estimate:** 55m. **Status:** todo. **Source:** functional CLI QA sweep127, 2026-10-11; ADR008 hosting usability and the documented Bex configuration boundary.

**Versions/context:** actual Bex release v0.3.2 and unmodified pinned Render CLI v2.27.0, dependency `v1.1.3-0.20260909214233-a764810a7682` / commit `a764810a7682`; source HEAD `d6ebd8d5ae3908da9064f9b61c2b55671e5ab59b`. API `https://api.bex.co/v1/`, human device-issued bearer privately supplied through the documented environment credential, selected `bex-canary` / `tea-daif693dqjvc73e7as3g`, native interactive output. Deployed server revision unobserved.

## Native reproduction and control

Use an isolated config containing only `version: 1`, with no `dashboard_url`; privately supply an already-issued bearer through `BEX_ACCESS_TOKEN`, set the production host and selected workspace, and run `bex services --confirm -o interactive`. Enter the first service row, then select its Dashboard action. The actual native process loads the list successfully but invokes the OS opener with **`/cron/srv-dap3v694dm7c7390q930`**, a path without a URL origin. It cannot identify the Bex dashboard. The selected baseline cron resource is read-only metadata throughout.

The same-pin Render binary against Bex, using the equivalent isolated config and `RENDER_API_KEY` credential, produces the same argument. Two fresh controls add **only** `dashboard_url: https://dashboard.bex.co` to their local configs: both open **`https://dashboard.bex.co/cron/srv-dap3v694dm7c7390q930`**.

## Cause and scoped fix

**Missing-file replay (sweep130):** at source `7308b037080e55be0b0bc3569611b5248623ef40`, two additional actual native launches begin with **no config file at all**. Bex (1.566s) and Render against Bex both load metadata and pass the same relative cron path to the opener. Both exit0 after normal dismissal, without timeout/panic; neither creates a config file or persists the supplied environment credential. [Complete native captures](../evidence/090/native-missing.json), [driver](../evidence/090/native-missing-driver.py.txt). The original two explicit-origin controls above remain the passing comparison. No fresh login, actual browser or hosting mutation is added.

**Attribution:** Bex launcher/configuration default, with a shared upstream empty-value defect; no server request-builder change.

- Pinned `pkg/config/config.go:253–278` returns a successful config with empty DashboardURL for a missing file or the valid version-only file. `DashboardURL:70–75` returns that empty field; its Render default applies only to a Load error.
- Pinned `pkg/dashboard/dashboard.go:28–48` appends resource/deploy paths to that empty origin and starts the OS opener. Bex `lego/cli/internal/bridge/bridge.go:63–109` supplies API/config/workspace/output/credential defaults but no dashboard origin.
- The exported `config.SetDashboardURL:78–93` can persist this non-secret platform metadata without constructing API requests or copying the environment bearer into the stored API key.

Add a small Bex configuration helper in `lego/cli/internal/bridge/`, invoked from the existing `cobra.OnInitialize` callback in `lego/cli/main.go:59–65` for dashboard-consuming hosting commands. With the effective API origin equal to the production Bex default and the loaded dashboard field empty, initialize it to `https://dashboard.bex.co` through the exported config seam. Preserve nonempty origins, explicit upstream overrides, custom/local API configurations and unrelated config fields. Resolve the actual command through Cobra, including the `service` alias; skip help/version and non-consuming commands. Preserve malformed-config errors rather than treating them as fresh files. Keep environment credentials out of persistence. Do not fork upstream navigation or derive dashboard hosts by string replacement.

**Blast radius:** two hosting command callers: `cmd/service.go:208` OpenResource and `cmd/deploylist.go:97` OpenDeploy. The shared constructor covers seven resource kinds (web, worker, private, static, cron, Postgres, Key Value) and five service deploy kinds. An actual imported-pin local probe records **12/12 relative paths**: [results](../evidence/090/client-probe.json), [source](../evidence/090/client-probe.go.txt), [module](../evidence/090/client-probe-go.mod.txt), [checksums](../evidence/090/client-probe-go.sum.txt). Synthetic IDs are local only; twelve live navigation failures are not claimed. Unsupported workflow navigation is excluded. REST/GraphQL/MCP resource metadata and dashboard aliases need no change.

## Acceptance, dedupe and cleanup

Replay both native cases and controls. Bex fresh-config Dashboard must pass an absolute Bex URL to the opener; preserve the pinned Render comparison as evidence of the upstream neighbor. Add behavioral checks for missing and version-only configs, both hosting callers and the service alias, preserved explicit dashboard origin/custom API/upstream overrides, malformed config, unchanged help/version state, retained unrelated fields and absent persisted environment bearer. Verify the shared twelve link shapes; run appropriate CLI checks and simplify the bounded configuration change. Real authenticated browser arrival and deploy-menu navigation remain future acceptance, not coverage claimed here.

Open/blocked/done searches for dashboard_url, DashboardURL, empty origins and relative dashboard paths found no matching fix. w5/m39 provides path aliases; w9/m41 populates separate API metadata. **089** addresses a nonempty OAuth origin via an edge redirect: a hostless path cannot reach that edge, so this empty-default cause needs separate work. Targeted launcher history retains the missing initialization. Current later upstream behavior is unverified; the exact tested pin is authoritative here.

No hosting resources were created, changed, executed or deleted. All four temporary config directories were removed and native PTYs reaped; token-free local probe config was removed. Existing baseline metadata was only read. The isolated human grant remains active for the ongoing authorized QA loop. Filing is uncommitted; no implementation or deployment is claimed.

## Outcome (2026-10-12) — fix shipped, blocked on CLI release

- **Fix (launcher):** `bridge.EnsureDashboardURL` (`lego/cli/internal/bridge/dashboard.go`), called from the existing `cobra.OnInitialize` hook in `lego/cli/main.go`, saves `dashboard_url: https://dashboard.bex.co` through the pinned config seam when the invoked command has a Dashboard action (`services`/`service`, `deploys list`, resolved by cobra in `opensDashboard`), the API is the production default (`RENDER_HOST` and any stored host), and the loaded config has no origin. A saved origin, custom/local hosts, malformed configs (left untouched) and help/version are unaffected; only the non-secret origin is written, never an environment bearer. Best-effort: an unwritable config keeps upstream's behavior. No upstream fork; the shared constructor then builds absolute URLs for all twelve link shapes.
- **Tests:** `TestEnsureDashboardURL` (missing file, version-only, unrelated fields kept, saved origin kept, custom env/stored host, malformed, non-dashboard command, bearer never persisted) and `TestOpensDashboard` (services, alias, deploys list, non-consumers). `cd lego/cli && go test ./...` and `make lint` pass. README documents the default.
- **Blocked:** the fix reaches users only in a new Bex CLI release (`/release cli`, separately authorized), then the fresh-config native replay must open the absolute Bex URL. The pinned Render comparison stays upstream's empty-origin behavior.
