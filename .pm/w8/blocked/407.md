# A Blueprint project with `environments: []` validates when the file has other resources, and the project is silently dropped, where Render requires at least one environment

Why: Render's spec makes `environments` required ("Each project must have at least one environment"). bex refuses a project with no `environments` key, but an empty list counts as "declared". So the file validates, the plan leaves the project out, and the apply never creates it. That is the silent no-op that `blueprintProjectEnvironmentsProblems` was written to prevent.

- Severity: minor.
- Seen: routine `cli-qa`, 2026-11-22 18:45 UTC, bex CLI v0.9.0, `https://api.bex.co/v1/`, QA human login, `bex-canary`, validate only.
- Repro: `bex blueprints validate render.yaml -o json` with:

  ```yaml
  projects:
    - name: qa-20261122-r31-p
      environments: []
  services:
    - type: web
      name: qa-20261122-r31-w
      runtime: image
      plan: free
      image:
        url: docker.io/library/nginx:1.27
  ```

  The answer is exit 0, `{"plan":{"services":["qa-20261122-r31-w"],"totalActions":1},"valid":true}`. It has no project and no error. With the `environments` key left out, the same project is refused at `projects[0]` with "a project must define at least one environment". With `environments: []` and nothing else in the file, it is refused with the unrelated "render.yaml must define at least one service, database, env group, build source, or project environment resource".

- Render, from [render.com/docs/blueprint-spec](https://render.com/docs/blueprint-spec) § Project fields (read 2026-11-22): "`environments` | *Required.* A list of the project's environments. Each project must have at least one environment."
- bex: `blueprintProjectEnvironmentsProblems` (`lego/backend/internal/apps/blueprint_compiler.go:315`) returns early on `if _, declared := object["environments"]; declared`, so `[]` passes the check.

## Fix

- Treat an empty `environments` list like a missing one, unless the project has `buildSources`, the exception the function already makes. Then `[]` gets `BLUEPRINT_PROJECT_ENVIRONMENTS_REQUIRED` at `projects[0].environments` with the same message, whether or not the file declares other resources.

## Acceptance

- [ ] The repro file is refused with exit 1 and "a project must define at least one environment", located at the project.
- [ ] `environments: []` alone gets the same error, not the "at least one service, database…" message.
- [ ] Controls: a project with one environment (even an empty one beside other resources), and a project with only `buildSources`, still validate.

Estimate: ~20m.

Each project must have at least one environment." The target is therefore a validation error naming the field, not an empty project. The pinned schema (`lego/backend/internal/apps/schema/render.yaml.json` `#/definitions/project`) has no `minItems` on `environments` and requires only `name`, so the rule lives in bex's compiler, as the missing-key case already did.
- **Fix.** `blueprintProjectEnvironmentsProblems` (`lego/backend/internal/apps/blueprint_compiler.go`) treats `environments: []` like a missing key unless the project has `buildSources`. The refusal is `BLUEPRINT_PROJECT_ENVIRONMENTS_REQUIRED`, "a project must define at least one environment", located at `projects[N].environments` when the key is present and at `projects[N]` when it is absent. A null or non-list value is still the schema's one refusal.
- **Surfaces.** CLI and REST validate, GraphQL and MCP validate (`blueprintValidationWithSuffix`), and plan, sync and apply (`compileStack`) all compile through `CompileBlueprintSource`, so the one check covers every surface. With `environments: []` alone the compile refusal now comes before the parse's "must define at least one service…" message.
- **Tests.** `TestBlueprintProjectWithoutEnvironmentsIsRefused` (`blueprint_repin_test.go`): the missing key, `[]` alone and `[]` beside a service each give exactly one located refusal; `ValidateBlueprint` gives one error at `projects[0].environments` with a line; `DeployStack` refuses. Controls: one empty environment beside a service, and `[]` beside `buildSources`, compile clean. With the fix reverted the test fails. w8/405's and w8/406's Blueprint tests stay green (`./internal/apps`, `./internal/api`, and the ship gates' real-DB suite).
