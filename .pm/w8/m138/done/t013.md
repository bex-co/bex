## Objective

Three of this milestone's four plan gates refuse with an **uncoded** 400, so a client (the dashboard, the CLI, an agent over MCP) can only branch on wording. The webhook gate already answers `code: WEBHOOK_PLAN_LIMIT` with `params.plan`. Make the other three coded on every surface, without changing any message text.

**Source:** live `/qa-find-bugs w4` loop run 5804, 2026-10-26 UTC (`muse.env`, `bex-canary` **Hobby**, pin `b4726243e74f`), REST and GraphQL through the run's session jar. Filed here, not in w4, because this milestone owns the gates and is still open. Owned project `prj-dbfuhldn83uc738utvr0` was deleted (`GET` → 404).

## Context

Live answers on Hobby:

| Probe | Answer |
| --- | --- |
| `POST /v1/webhooks {ownerId, name, url, …}` | `400 {"code":"WEBHOOK_PLAN_LIMIT", "params":{"plan":"hobby"}, "message":"webhooks require the Pro plan or higher; this workspace is on Hobby"}` — the coded control |
| `POST /v1/projects` with 3 environments | `400 {"id":"bad_request","message":"invalid request body at /environments: bad request: environments: a Hobby workspace is limited to 2 environments per project; …"}` — **no `code`** |
| `POST /v1/environments {name, projectId}` (third) | `400` same text, **no `code`**; GraphQL `createEnvironment` → `errors[0]` with **no `extensions.code`** |
| `PATCH /v1/environments/{id} {"networkIsolationEnabled":true}` | `400 "bad request: networkIsolationEnabled: network-isolated environments require the Pro plan or higher; …"`, **no `code`** |
| `GET /v1/logs?…&type=request` | `400 "bad request: type: HTTP request logs require the Pro plan or higher; …"`, **no `code`** (run d678) |

Root cause: `lego/backend/internal/core/plan_gate.go` `RequireNetworkIsolation` (`:178-189`) and `RequireEnvironmentCapacity` (`:194-204`), plus `logs/service.go:473` `requireRequestLogsPlan`, return `fmt.Errorf("%w: <field>: …", ErrBadRequest, …)`. A coded constructor already exists: `core.NewPlanLimitError` (`core/errors.go:320-330`, `code: PLAN_LIMIT`, `params: {plan, limit}`). `RequirePlanFeature` (`:167-173`) has the same shape but no production caller today.

Blast radius: `RequireNetworkIsolation` has 5 production callers (`environments/service.go:659,825,1356`; `projects/service.go:448`; `apps/deploy.go:1810` Blueprint apply), `RequireEnvironmentCapacity` 3 (`environments/service.go:740`; `projects/service.go:428`; `apps/deploy.go:1781`). The Blueprint callers surface through the validate/apply error lists, which already carry a `code` field.

## Steps

1. Return coded errors from all three gates: `PLAN_LIMIT` for the environment cap (`params: {plan, limit: 2, field: "environments"}`), and a feature code for the two feature gates, e.g. `PLAN_FEATURE_REQUIRED` with `params: {plan, feature: "networkIsolation" | "requestLogs", requiredPlan: "pro"}`. Or reuse one code family consistently, and decide whether `WEBHOOK_PLAN_LIMIT` joins it.
2. Keep every message byte-for-byte, including the `type:` / `networkIsolationEnabled:` / `environments:` field prefixes the DoD pins to Render's CLI shape.
3. Check the REST request-body wrapper for `POST /v1/projects` ("invalid request body at /environments: bad request: …"): it must pass the code through.
4. The dashboard's plan notices (t011) can then branch on the code instead of message text.
