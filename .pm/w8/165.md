# A root directory written with a trailing slash (`rootDir: ./`, `server/`) is refused as "a relative path with no '..' components"

Why: Render's own Blueprint export writes `rootDir: ./`, and authors commonly write directories with a trailing slash (`server/`). Bex refuses both, with a message that names the rule the path does not break (there is no `..`). At the same time it accepts a leading-slash `/server`. A Render-exported Blueprint therefore fails on import for a cosmetic spelling.

**Severity:** minor (blocks a Render export; workaround is deleting the slash). **Attribution:** server (root directory validation). **Estimate:** 25m. **Source:** `/qa-find-bugs-cli` sweep 1283, 2026-10-21 ([evidence](evidence/cli-sweep1283/README.md)).

## Reproduction

Production `https://api.bex.co/v1/`, pin `a3f66521f93d`, bex-canary, HEAD-built pinned CLI. `bex blueprints validate` on a free static site whose only variable is `rootDir`:

| `rootDir` | Result |
| --- | --- |
| `.` | valid |
| `./server` | valid |
| `/server` | valid |
| `./` | `rootDirectory must be a relative path with no '..' components` |
| `server/` | same |
| `server//x` | same |

REST `POST /v1/services` with `rootDir: "./"` → the same 400. `Davender-1565/VisualSort`'s render.yaml, which carries Render's export header and `rootDir: ./`, fails with the same message at `POST /v1/blueprints`. Across the sweep 1267 and 1270 corpora, 15 files use `rootDir: ./` or `.`, and 3 use `server/`.

## Expected

The trailing-slash and `./` spellings mean the same directory as the bare form, and Render's exporter emits them. Normalize before validating, so that `./` → repo root and `server/` → `server`. Keep refusing `..`, backslashes and control characters. Decide one rule for a leading `/`: it is accepted today after compiler normalization and refused by `ValidRootDir`. When a spelling is refused, name the actual problem ("empty path segment").

## Root cause

`lego/backend/internal/store/api.go:690–706` (`ValidRootDir`) splits on `/` and refuses any empty segment, so a trailing `/` and `./` (which yields `[".", ""]`) fail. The message at `apps/service.go:3027` and `apps/settings_check.go:132` only mentions `..`. The Blueprint compiler strips a leading `/` before this check but not a trailing one.

## Fix

Add `normalizeRootDir` (trim, strip a leading `./` and `/`, `path.Clean`, map `.` to `""`), apply it on every write path (REST create/PATCH, GraphQL, MCP, Blueprint compile), and then validate. Store the normalized value so a read returns `server`, not `server/`. Update both messages to name the failing rule.

## Acceptance

- Unit table: `./` → `""`, `server/` → `server`, `./server/` → `server`, `/server` → `server`; `../x`, `a/../b`, `a\b` refused; `a//b` → `a/b`.
- Live after deploy: the table above validates for every spelling except the refused ones. `Davender-1565/VisualSort` (static, free) connects and serves. Delete fixtures by ID with 404 proofs.
