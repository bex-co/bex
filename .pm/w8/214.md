# `bex skills install` has no interactive picker: in a terminal it installs every skill to every detected tool, where Render's TUI lets the user pick scope, tools and skills

Why: w8/m143 replaced upstream's `skills` tree, which drives a bubbletea picker (scope, tools, skills) when run in a terminal with no flags. bex's commands are flag-driven only. A terminal run with no `--output` prints text and installs the whole pack at user scope to every detected tool. The flags (`--scope`, `--tool`, `--skill`) reach every choice, and nothing is lost in agent or CI use, but an interactive user does not get Render's guided selection.

Severity: **minor** (UX parity; every choice is reachable by flags). Estimate: ~2h. Source: w8/m143 t002 design choice, 2026-10-28 (bex5 `/loopx w8`).

## Fix

- Reuse upstream's multi-select TUI components (`pkg/tui`), if they can be driven with the embedded pack's skill list, or build a small picker for scope → tools → skills in `lego/cli/internal/skills`, run only when stdout is a TTY and no selection flags or `--output` are given.
- `list`/`update`/`remove` in a TTY: match Render's views where practical. `remove` with no flags currently errors with "specify --skill or --all".

## Acceptance

- In a TTY, `bex skills install` with no flags shows the scope, tools and skills picker; flags skip the matching step, as on Render.
- Non-interactive behavior is unchanged (`TestLifecycleLeavesRenderSkillsAlone`, `TestCommandSurfaceMatchesUpstream`).
