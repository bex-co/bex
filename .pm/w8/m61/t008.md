## Objective

An accepted empty or narrow application PATH must not prevent the platform from starting the shell for an absolute authored pre-deploy command. Preserve the application's exact PATH and the pre-deploy lifecycle.

## Context

- [Two native failures, same-commit PATH-only recoveries and controls](evidence/live-node-predeploy-sweep228/README.md). Both clients build successfully, then end pre_deploy_failed with original program output absent; both causal controls reach Live/HTTP200 and print one marker.
- `lego/operator/internal/predeploy/predeploy.go:145` uses relative sh and copies Env/EnvFrom unchanged. The sole production Ensure caller at `controller/app_controller.go:5658` supplies the app's env. Its own platform-shell policy at231–235 already declares /bin/sh.
- The generated native service uses an absolute shell and its empty-PATH startup now passes. Current TestJobShape asserts the relative command and misses this runtime boundary.
- The exact deployed OCI startup error and artifact config are unavailable; source tracing and PATH-only recovery identify the lookup without claiming direct image inspection. All five fixtures/seven deploy records are deleted; deployed SHA unknown.

## Steps

1. Make predeploy.Job use the absolute POSIX shell consistent with the existing operator command policy; preserve -c and the authored command, env/envFrom, mounts and image. Do not normalize application PATH or introduce a CLI/API workaround.
2. Audit the one shared controller caller and both regular/initial-hook command selection. Preserve per-release no-retry/TTL/generation bookkeeping, saved-image/override behavior and opaque Docker/buildpack shell contracts. Do not sweep unrelated helper commands from this finding.
3. Add a real container execution regression for the Job command with empty/narrow PATH and an absolute harmless Node command: the original relative lookup fails, the corrected shell runs and reports the exact original PATH. Retain normal/omitted controls, environment/file bytes and existing lifecycle tests.
4. After deployment, repeat fresh Free fixtures through published/current Bex and the unmodified Render pin. Pre-deploy marker, Live/HTTP200, exact build/runtime configuration and owned cleanup must pass without broadening PATH. Keep unexercised surfaces explicit.
