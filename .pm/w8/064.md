# 064 — A stale `BEX_WORKSPACE` name blocks help, version and the workspace recovery commands before they run

Why: the workspace-name support added by w8/038 resolves before command dispatch. A renamed or deleted workspace now prevents a user from running the suggested `bex workspaces` recovery command, printing help/version, identifying their account, explicitly selecting a different workspace, or reading Postgres by an explicit ID. Fix this before the next CLI release while preserving name resolution for commands that consume the active workspace.

Severity: minor. Attribution: Bex launcher. Estimate: ~50m. Source: `/qa-find-bugs-cli` w8 loop, 2026-10-07, offline sweep 1. Goal: ADR008's usable hosting client and the imported Render command contract in `docs/bex-cli.md` / `lego/cli/UPSTREAM_RENDER_CLI.md`. No dependencies and no product fix implemented by this filing.

## Reproduction and complete refusal

With the checkout binary, an authenticated fixture API that returns an empty owner page for `no-such-qa-ws`, and isolated Bex configuration:

```text
BEX_WORKSPACE=no-such-qa-ws bex --help
BEX_WORKSPACE=no-such-qa-ws bex --version
BEX_WORKSPACE=no-such-qa-ws bex workspaces -o json
BEX_WORKSPACE=no-such-qa-ws bex whoami -o json
BEX_WORKSPACE=no-such-qa-ws bex workspace set tea-12345678901234567890 -o json
BEX_WORKSPACE=no-such-qa-ws bex completion bash
```

All six exit 1, stdout is empty, and complete product stderr is:

```text
bex: BEX_WORKSPACE: no workspace named "no-such-qa-ws"; run `bex workspaces` to list yours
```

Durations were 0.041–0.048s on the warmed build (the first `--help` run was 1.013s); `--help` and the other recovery cases reproduced in a second fresh-process matrix. There is exactly one instrumented API request before this refusal:

```http
GET /v1/owners?name=no-such-qa-ws&limit=100
Authorization: Bearer <fixture-only dummy credential>

HTTP/1.1 200 fixture
Content-Type: application/json

[]
```

This is the complete response from the in-memory fixture, not a live capture. Instrumentation printed `QA FIXTURE REQUEST ...` separately on stderr; that line is not Bex's product output. No resource request or runtime activity follows it.

Offline sweep 4 also reproduced root `-h`, root `-v`, nested `services --help`, and `help services`: each sent that same owner-name request and exited 1 with the same complete product stderr and empty stdout. The explicit precedence control (`BEX_WORKSPACE=no-such-qa-ws RENDER_WORKSPACE=tea-12345678901234567890 bex services -o json`) exited 0 and used the typed ID on collection requests, with no preliminary owner-name request.

## Explicit Blueprint workspace override (offline sweep 7)

```http

Content-Type: application/json

```

This fixture asserts dispatch and explicit selection only; it does not claim the manifest was validated by production. ## Mechanism, scope and fix

- `lego/cli/main.go:44` calls `bridge.ResolveWorkspaceName` before adding commands/branding, the root-version branch (`:63`), Postgres trust provisioning and `cmd.Execute` (`:91`). An error calls `os.Exit(1)`, so upstream never dispatches the intended command.
- `lego/cli/internal/bridge/workspace.go:53-65` lists owners for a non-ID value, then returns the correct unknown-name refusal when none matches. The error itself is correct for a workspace-consuming command; its unconditional placement is the defect. Duplicate-name refusal (`:72`) also has the dispatch reproduction and scoped refusal control above.
- Consumer: pinned `cmd/workspaces.go:26-35` lists the caller's owners without consulting the active workspace; `pkg/user/repo.go:19-29` reads the caller independently; `cmd/workspaceset.go:29-34,57-64` resolves its **explicit** positional selector. Cobra help/completion and the root-version path likewise need no active workspace.
- Exhaustive symbol search finds **one production call site** of exported `ResolveWorkspaceName`, in `main.go`, plus its definition and unit test. The startup boundary reaches the whole imported tree. No REST/GraphQL/MCP/dashboard adapter change is needed and no upstream request workaround or fork is proposed.
- Restrict name resolution to invocations that actually consume the active workspace. Help (including nested help), root version, static completion generation, `workspaces`, `whoami`, and explicit `workspace set` must reach their own handlers without resolving the stale selection. Preserve the ordering needed by workspace-consuming Postgres trust preparation. Keep explicit `RENDER_WORKSPACE` precedence and zero extra request for an ID.
- Include argument-dependent reads: unfiltered `pg get <typed ID>` reaches its direct-ID handler without a default-workspace name lookup. Preserve the active-workspace mapping for name selectors, optional scopes and any ID-404 fallback that consumes it; do not exempt the entire command group.
- Classify login and API-backed dynamic resource completion explicitly in the fix; those variants remain **unverified**. Logout and metadata/file completion now have the fixture evidence above. Preserve their own auth/revocation and resource-resolution semantics. `workspace set` writes isolated stored selection; it does not unset an inherited `BEX_WORKSPACE` environment override.
- Neighbors: unknown/ambiguous active workspace remains a named exit-1 error on workspace-consuming commands; unauthenticated, forbidden and unavailable responses remain the dispatched command's existing contract. Do not turn an API failure into an empty owner list or disclose inaccessible workspaces. No change to existing resource-existence policy.
