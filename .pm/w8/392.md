# A no-build static site's publish in flight is replaced by the next deploy, even once the operator has adopted it, where Render's default Wait lets it finish

Why: w8/390 checked the operator side it named as unverified. `releaseInFlight` (`lego/operator/internal/controller/release_identity.go`) holds a release only while `pinnableRelease` is true, and `pinnableSourceRelease` returns false for `directStaticPublish`, a repo-backed static site with no build command, Dockerfile, runtime or builder. Its publish Job clones the repo and uploads the publish directory (`reconcileStaticSite`, `app_controller.go`). So while it publishes, a newer release from any writer (a trigger, a git push, a configuration save, a Blueprint sync) is adopted at once, and the publish in flight closes "Superseded by …". The exclusion dates from ADR060 §D1a (w2/m72, "no build Job to protect"). w4/635 later pinned prebuilt images through their rollout, and w4/661 pinned selected releases, but static publishes were never pinned.

- Severity: minor. A no-build publish is short (a clone and an upload), so two deploys within its window are needed to hit it.
- Parity: Render's Wait, "Allow the in-progress deploy to finish, then proceed directly to the most recently triggered deploy" ([render.com/docs/deploys](https://render.com/docs/deploys)). ADR018's "List / get deploy objects" row names this as still open (w8/390).
- Not yet seen live: the premise holds from the code above. Check it first on a free no-build static site in `bex-canary`. Trigger a deploy, wait about 5 s for the operator to adopt it, and trigger a second. The first should still reach `live`.

## Fix

Pin a direct static publish once the operator has adopted it, as `pinnableSourceRelease` pins a source build. The publish Job must render from the release's adopted view (`heldReleaseView`), with its commit, publish path and routes, not from the newer saved spec. The newer release then waits in the pending slot until the publish serves or fails. Keep Override's cancel-and-start, and keep w8/m460's hold, which keeps a static site's IP allow-list following the App while a publish runs.

## Acceptance

- Envtest: a direct static publish adopted and in flight, then a newer release written to the App. The first publishes and serves its own commit, and the newer one publishes after it.
- Live in `bex-canary`: two deploys of a free no-build static site, the second about 5 s after the first, both reach `live` in order. Delete the fixture by ID and confirm the 404.
- ADR018: drop the "Still open" sentence from the w8/390 paragraph.
