# Blueprint services use main when their own repo defaults to master

**Severity: major. Attribution: backend Blueprint source planning/defaulting.** Two healthy native-created Free image services fail their first Git deployment after accepted Blueprint syncs omit the independent service repo's branch. Both clients validate the exact manifest. The server chooses main; the actual repo default is master. Adding only branch: master makes both deployments Live with exact artifacts. [Full retained evidence](evidence/cli-sweep344/README.md).

Both first syncs200; stored YAML omits branch; six API reads show main; first builds fail cloning that nonexistent ref. Independent anonymous HEAD resolves master. ## Concrete correction and shared scope

Resolve an independently sourced Git service's omitted branch from its repository metadata before shared planning, canonical writes and first commit/build selection. Carry the resolved source coherently into new creation and source-kind-changing updates. Reuse the direct-create resolver/validation behavior where appropriate, preserving its outage, unusable-ref and metadata-unavailable rules. Do not globally rewrite main to master, silently repair after side effects, change the authored YAML, or add CLI flags as a server workaround.

Audit source presence and existing-service semantics explicitly: an old image's fallback branch is not meaningful Git intent; deliberate preserved existing-Git branches, explicit choices, same-repo inheritance, same-repo rollback images, direct manual source setters and no-op behavior need a truth table and independent controls. settings_check.go's manual source edit deliberately ignores the metadata default; this finding does not authorize changing that contract. Do not bind a containing Blueprint commit to an independent repo.

Compiler/source callers include Blueprint create (blueprint.go:1109–1110), provided sync preparation:1300–1301, fetched/stored sync fallback:1484, preview/validation/generation and automatic sync/webhook adapters. Exported ApplyBlueprintServiceSpec has2 production call sites in blueprint_state_plan.go:182/191 plus the private wrapper in deploy.go:3643; the wrapper's production update caller is deploy.go:3231. Preview/planning/application must agree. Root/nested declarations and web/static/private/worker/cron share source structures; live proof is Free web only and no paid/cron fixture is requested. REST apps/rest.go, GraphQL apps/graphql.go, MCP apps/mcp.go and dashboard consumers share the domain behavior; retain coherent errors/readbacks without reimplementing source selection in clients.
