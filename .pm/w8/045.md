# Service create dry-run skips every check the real create runs after the spec resolves

Why: `dryRun: true` answers "this would succeed" for creates the real call refuses (reserved `dashboard.bex.co`, a taken name, `PORT`, a domain another service owns), so agents, MCP clients and CI cannot trust a preview as a validation step.

Found by live QA 2026-10-03: a dry-run service create with custom domain `dashboard.bex.co` returned a preview; the same request without dry-run is refused `400 "dashboard.bex.co" is a reserved platform hostname`.

- `lego/backend/internal/apps/service.go:1925-1936` returns the preview before `RequirePlanBilling` (`:1936`), `nameTaken` (`:1945-1954`), `checkReservedSpecEnv` (`:1959`), `GitHub.ValidateRepo` (`:1980-1984`) and `ensureHostsClaimable` (reached via `materializeNewApp` at `:2304`: per-service domain cap `domains.go:1007`, workspace quota `:1012`, reserved host `:1026-1027` via `reservedHost` `:796-807`, claimed by another service `:1040`, ownership `:1044`).
- Fix: move the dry-run return to just before `materializeNewApp`, so every read-only check runs first; for hosts, call `ensureHostsClaimable` on the preview App (same name, tenant label, environment — `ownPlatformHost` needs the slug) and confirm it writes nothing. Decide explicitly whether dry-run also returns the billing 402 (Render's dry-run semantics unverified; real-create parity is the safer default).
- Tests (`apps`): a table where each refusal (reserved host, dashboard host, duplicate name, `PORT`, claimed domain) gives the same error with and without `DryRun`, while w2/m29's zero-writes assertions still pass; one REST `?dryRun=true` case.
- Check the Postgres/Key Value dry-run paths (`lego/backend/internal/postgres/service.go:663`, keyvalue) for the same early return; cover here or file a sibling note.
