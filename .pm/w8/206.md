# `$$` in a build or start command reaches bash as `$`: Kubernetes rewrites `$$` and `$(NAME)` in the generated Dockerfile env value and in container commands, which bex never escapes

Why: Render runs a service's build and start commands through bash unchanged, so `$$` is the shell's PID and `a$$b` stays `a<pid>b`. bex hands those commands to Kubernetes in fields that Kubernetes itself rewrites: `env[].value`, `command` and `args`. There, `$$` is Kubernetes' escape for a literal `$`, and `$(NAME)` is replaced by an env var of the same container. So a command containing `$$` runs differently from what the user saved, silently. Env var _values_ are not affected (they travel through Secrets).

Severity: **minor** (silent command rewrite; `$$` and `$(NAME)` matching a container env var are uncommon in commands, but the outcome is wrong without any error). Attribution: platform runtime (operator build and deployment projection). Estimate: ~45m. Source: `/qa-find-bugs-cli` loop sweep 6646, 2026-10-26 (11:19–11:28 UTC). Context: HEAD-built bex `b4726243e` with pinned Render CLI v2.27.0 `a764810a7682`; `https://api.bex.co/v1/`; workspace `bex-canary`; human device login.

## Root cause

- Native builds:
  - `nativeBuildPreparer` passes the generated Dockerfile as `corev1.EnvVar{Name: "BEX_NATIVE_DOCKERFILE", Value: nativeDockerfile(o)}` (`lego/operator/internal/build/native.go:438`).
  - The Dockerfile embeds the build command (`RUN … shellJSON(…)`, `:320`) and the start command (`CMD shellJSON(o.StartCommand)`, `:338`).
  - The kubelet applies `$(VAR)` expansion and `$$` → `$` to `env[].value` before the container sees it.
- Docker/image services: `container.Command = shellCommand(app.Spec.StartCommand)` (`lego/operator/internal/controller/deployment_projection.go:298`, also `app_controller.go:5026` and `:6415` for the pre-deploy/one-off paths). Kubernetes applies the same rewrite to `command`/`args`, and `$(PORT)`/`$(RENDER_…)` are substituted from the container's own `env[]` (verified live, below).
- Nothing escapes `$` (`git grep` finds no `$` → `$$` escaping in `lego/operator`).

## Fix

- Add one helper, `k8sLiteral(s) = strings.ReplaceAll(s, "$", "$$")`. Apply it wherever user-authored text enters a Kubernetes-expanded field:
  - the `BEX_NATIVE_DOCKERFILE` value (or deliver the Dockerfile through the existing Secret/volume path instead of an env value);
  - every element of `shellCommand(...)` output put into `container.Command` (start, pre-deploy, cron and job paths);
  - `BEX_NATIVE_FILES` and any other env value derived from user input in the preparer.
- Compare like with like: `release_config_selection.go:413` compares `c.Command` to `shellCommand(rec.spec.StartCommand)`. Escape both sides or compare unescaped, so a fix does not make every existing release look changed.
- Existing Deployments carrying an unescaped `$$` command will roll once when the projection changes. Note it in the ship message (Render semantics are the intended result).

## Blast radius

- Native build and start commands (all native runtimes).
- Docker/prebuilt-image start commands.
- Pre-deploy commands.
- Cron commands, if projected through `shellCommand` (check the cron Job builder).
- Static-site build commands (same native Dockerfile path).
- The REST/GraphQL/MCP stored values are already verbatim, so there's no API change.
