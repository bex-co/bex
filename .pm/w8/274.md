# A native Python service has no virtualenv at Render's path, so `VENV_ROOT` is not set

Why: Render installs a Python service's dependencies into a virtualenv at `/opt/render/project/src/.venv` and sets `VENV_ROOT` to it. bex installs into the toolchain image's own Python and sets nothing. A build or start script that reads `VENV_ROOT`, or calls `.venv/bin/<tool>`, works on Render and not on bex.

**Severity:** minor (no failing journey was reproduced). **Attribution:** infrastructure/runtime (native Python image). **Estimate:** ~2h. **Source:** `/qa-find-bugs-cli` sweep `965c` via w8/256, 2026-11-11.

## Why it was not set with the others (w8/256)

`VENV_ROOT` names a directory. Setting it without the virtualenv would point scripts at a path that does not exist.

## Fix

1. Create the virtualenv at `/opt/render/project/src/.venv` before the build command and put its `bin` first on `PATH`, so `pip install`, Poetry and uv install into it and the start command resolves from it. Decide what happens to a `.venv` the repository commits.
2. Set `VENV_ROOT` to that path, build and runtime (`nativeBuildDefaults`, `lego/operator/internal/build/native.go`).
3. Check each reviewed Python line, Poetry and uv, and a static site built with Python.

## Acceptance

- `python -c "import sys; print(sys.prefix)"` in the build and at runtime prints `/opt/render/project/src/.venv`, and `VENV_ROOT` equals it.
- Existing Python services build and start unchanged from their users' point of view (`pip install -r requirements.txt` then `gunicorn app:app`).
