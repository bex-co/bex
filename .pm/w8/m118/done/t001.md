## Objective

Every tenant web host's plain-HTTP router answers a permanent redirect to the same `https://` URL, path and query preserved, while HTTPS serving is unchanged.

## Context

- Traefik v3 makes two routers from each App Ingress rule: the base router `<ns>-<ingress>-<host>-<path>@kubernetes`, which serves plain HTTP, and its TLS sibling `websecure-<same>@kubernetes` (w1/m51, `lego/backend/internal/core/traefik.go:124`). The `traefik.ingress.kubernetes.io/router.middlewares` annotation applies to both. Traefik's `redirectScheme` only redirects a request whose scheme differs, so on the TLS sibling it passes through.
- `reconcileIngress` (`lego/operator/internal/controller/app_controller.go`) is the one writer for the web, static-site and activator Ingresses. The per-App ipAllowList and WebSocket-meter middlewares already use `upsertOwned`/`deleteOwned` with `traefikHTTPMiddlewareGVK`.
- cert-manager's HTTP-01 solver creates its own Ingress for `/.well-known/acme-challenge/<token>`. Traefik's longer rule wins, and that Ingress carries none of the App's middlewares.
- `ClusterIssuer` is empty when no certificates are issued. Redirecting there would point at a host with no certificate.

## Steps

1. In `reconcileIngress`, when the App has hosts and `r.ClusterIssuer != ""`, upsert an owned Middleware `<app>-https` with `redirectScheme: {scheme: https, permanent: true}`. Prepend its ref to the router middlewares so a cleartext request is redirected before any other layer. Otherwise delete it.
2. Keep the host-redirect Ingress as it is: its `redirectRegex` already targets `https://`.
3. Decide HSTS. Recommendation: do not ship HSTS in this milestone. Record the decision in ADR005 with its reason; preloading or `includeSubDomains` on a shared suffix is out of scope.

## Files

- `lego/operator/internal/controller/app_controller.go`
- `docs/ADR005-custom-domain.md` (or the ADR that owns the App Ingress)

## Acceptance criteria

- [x] The App Ingress carries the `<app>-https` middleware ref first whenever it has hosts and an issuer is configured, for web services, static sites and the activator route.
- [x] The middleware is owned by the App and removed when the App has no hosts or no issuer.

## Out of scope

- HSTS headers and preload.
- Redirecting the platform's own hosts (dashboard and API), which have their own ingress.

Done 2026-10-18 (loopx w8):
- `reconcileIngress`, the writer for the web, static-site and activator Ingresses, now upserts an owned `<app>-https` Middleware (`httpsRedirectSpec`: `redirectScheme` https, permanent) and puts it first in the router middleware chain whenever the App has hosts.
- When the App has no hosts, or `BEX_HTTPS_REDIRECT=false`, the middleware is deleted, but only after the Ingress stops naming it. Traefik disables a router whose middleware is missing.
- The off switch is `BEX_HTTPS_REDIRECT=false` (`AppReconciler.HTTPSRedirect`, `lego/operator/AGENTS.md`). The first cut gated on an empty `BEX_CLUSTER_ISSUER`, which can't happen, because `envOr` falls back to letsencrypt-staging.
- The host-redirect Ingress is unchanged: its `redirectRegex` already targets `https://`.
- HSTS is not sent. The reason is recorded in ADR005.
