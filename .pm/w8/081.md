# 081 — Blueprint validation accepts port links to services with no network address

Why: a Blueprint can pass validation while wiring a caller to port `0` or `<slug>:0` on a worker, cron job or static site, which has no private-network address.

Severity: **minor**. Attribution: **server compatibility**, shared Blueprint parser in `lego/backend/internal/apps`. Estimate: **55m** for the common addressability guard and meaningful regression cases. Source: functional `$qa-find-bugs-cli` loop in w8, 2026-10-09 UTC. Goal: reliable pre-deployment configuration checks (ADR008 / ADR018 / ADR041 / ADR049). Filing only; no product fix or shipping.

Bex **v0.3.2**, unmodified Render **v2.27.0**, pin **a764810a768202704e7206eb7b87a47211fcd98e**, module `v1.1.3-0.20260909214233-a764810a7682`. Checkout **c5e413f38324fdff0a36f4c3edc0063e889ce639**; deployed revision unobserved. Validation only: **no resources created**, including the worker/private declarations with a paid plan.

From the repo root:

```sh
bex blueprints validate .pm/w8/evidence/081/cron-hostport.yaml --confirm -o json
bex blueprints validate .pm/w8/evidence/081/worker-port.yaml --confirm -o json
bex blueprints validate .pm/w8/evidence/081/static-hostport.yaml --confirm -o json
```

Repeat through the unmodified pinned Render binary configured privately for the same Bex API, QA grant and workspace. Each file declares its target in the same file and references it from a free web caller. The caller appears before the target, exercising forward references. These artifacts contain JSON, which is valid YAML; contents are preserved from the native checks.

Expected: exit **1**, `valid:false`, and a diagnostic that the referenced service has no network address. Actual in both clients: exit **0**, empty stderr, and complete stdout:

```json
{
  "errors": null,
  "valid": true
}
```

The [24-case native matrix](evidence/081/live-matrix.json) contains complete commands, manifests, stdout/stderr, exits and durations. **All 12 port/hostport checks against worker, cron and static targets incorrectly pass**. The six matching `host` checks correctly fail. The six web address checks pass; a further [six private-service checks](evidence/081/private-controls.json) also pass. [Six plain envVarKey-copy controls](evidence/081/envkey-controls.json) from worker/cron/static targets pass and must remain supported.

[Render's official Blueprint specification](https://render.com/docs/blueprint-spec#referencing-service-properties) defines `host`, `port` and `hostport` for web/private services. Bex's own `AppSpec.InternallyAddressable()` and ADR041 make the same distinction. This is an invalid-reference acceptance, not a request to give workers, crons or static sites a private address.

## Wire, producer and consumer

Native HTTP traffic was **not intercepted**. The pinned command constructs multipart `ownerId` + `file`, posts validation, requires a decoded HTTP 200 result and uses its `valid` value for exit status (`cmd/blueprintvalidate.go:95–136,142–161`). Both binaries consume the server's false success correctly.

[Four API-only multipart checks](evidence/081/multipart-api.json) preserve exact method/path, non-secret multipart bytes, User-Agent, workspace header, status, relevant response headers and complete response; Authorization is redacted. Worker/port and cron/hostport return **HTTP 200 with `valid:true`**. Web/port returns 200/true; cron/host returns 200/false with the existing addressability message. These diagnostic requests match the pinned multipart field shape and remain distinct from native wire evidence. REST `apps/rest.go:1331–1351` calls `ValidateBlueprint` and serializes its result; changing the launcher or response decoder would not fix the underlying decision.

## Root cause and fix

- `deploy.go:1912–1918` populates `stackIndex.servicePorts` only for web/private services. The missing entry for worker/cron/static is correct.
- `stackIndex.classifyRefs` (`:2030–2070`) checks target existence for all service forms. Its addressability branch handles host/hostport, but `:2056` refuses a missing port entry **only when the property is `host`**. Hostport therefore keeps a zero port in its deferred `hostRef`.
- Port references bypass that branch and call `resolveRef`; `deploy.go:2730–2734` reads `ports[ref.Name]` without checking map membership and converts the missing entry to `"0"`.
- `hostRef.env` (`deploy.go:571–576`) formats the retained zero as `<slug>:0`. Its two application sites are `:994` and `:1030`. `types/v1alpha1/app_types.go:862–864` identifies the supported addressable types, and the operator's `reconcileSlugService` (`app_controller.go:3087–3104`) removes aliases for other types rather than creating an address for them.

An [actual current-checkout parser probe](evidence/081/parser-probe.go.txt), run in a private `git archive` copy with no cluster or apply, confirms all twelve original cases. [Values](evidence/081/parser-values.json) and [output](evidence/081/parser-probe.txt) show each invalid port becomes `"0"`, and each invalid hostport projects to the sample `qa73-probe-slug:0`. Web controls resolve port 3000 and the matching sample hostport. [Source hashes and reproduction command](evidence/081/source-check.json) distinguish this execution from inference; the sample slug is a projection input, not a deployed hostname.

**Fix:** before resolving any declared sibling's `host`, `port` or `hostport`, require that the target is in the addressable-port map. Apply this one rule to all three properties and fail before resource writes. Preserve the existing out-of-file **host-only** lookup, forward/backward web/private refs, database/Key Value branches and envVarKey copies. Include the caller's env key in the structured refusal so validation can locate the offending entry; `blueprintResourceValidationErrors` / `blueprintEnvVarIndex` (`blueprint.go:757–780,819–833`) already support `envVars["KEY"]` diagnostics. Keep correct address production and the pinned CLI unchanged.

One production caller each of `classifyRefs` and `resolveRef`; two callers of `hostRef.env`. There are **four direct call sites** of `parseCompiledStack`: shared compilation, validation, generated-manifest checking and disconnect grouping reclamation. `compileStack` feeds direct deploy, Blueprint creation and manual/automatic sync; `parseStack` is its test wrapper. REST, GraphQL and MCP validation/deploy entry points share these functions, and dashboard validation consumes GraphQL. Those sibling surfaces and historical manifests are source-traced, not live-certified here. Preserve disconnect's existing behavior when an old stored manifest no longer parses.

## Acceptance, dedupe and limits

- Both native clients reject all three address properties for worker/cron/static targets: exit 1, `valid:false`, diagnostic at the caller's `envVars` entry naming the target/property, no port `0` or `<slug>:0` accepted.
- Both clients continue accepting web/private references and plain envVarKey copies from all three non-addressable types. Missing-target, forward/backward/self-reference, database and Key Value controls preserve their semantics.
- Shared validate/preview/apply/create/sync paths agree. An isolated apply regression proves each invalid reference fails before any service, datastore or group write. Preserve generated-manifest and disconnect callers; run relevant backend checks and lint after the fix.
