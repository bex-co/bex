## Objective

Make the first allowlist enable on a private store restart-free without issuing a certificate at birth: mount the Secret `optional: true`, then enable TLS at runtime via `CONFIG SET` once the Secret exists.

## Context

- ADR021:187 (platform ACL user)
- w8/181 DoD
- pinned Valkey 7 and 8 images

## Steps

1. Check runtime `tls-port` on both majors.
2. Implement the optional mount and runtime enable; keep `status.tlsListener` truthful.
3. Fallback if unsupported: birth certificates plus a quota analysis.

## Files

- operator keyvalue files, ADR021

## Acceptance criteria

- [x] Persistence Off store: first enable → no `KEY_VALUE_RESTART_CONFIRMATION_REQUIRED`, uptime keeps increasing, the key survives.

## Out of scope

- —

**Done (2026-10-29, per user decision D3):** new stores mount `<id>-kv-tls` with `optional: true` and start Valkey through a `sh` wrapper that adds `--tls-port 6380` and the certificate flags only when `/tls/tls.crt` and `/tls/tls.key` exist. On an enable the operator waits for the Secret, then runs `CONFIG SET tls-cert-file/tls-key-file/tls-ca-cert-file/tls-auth-clients` and `CONFIG SET tls-port 6380` as the platform user. A disable runs `tls-port 0`. Neither touches the pod template. `status.tlsRuntimeSwitch` marks such stores, and bex-api's `externalAccessRestarts` is false for them, so the first enable needs no restart phrase. Older stores are untouched by the upgrade; an older private store's first enable restarts once and adopts the switch. The real switch is verified on the pinned Valkey 7.2 and 8.1 images by `TestValkeyRuntimeTLSSwitch` (`BEX_TEST_VALKEY=1`): same `run_id`, Persistence Off key kept, port closed by `tls-port 0`, and a restart with the files mounted comes back listening. Fake-client tests show the StatefulSet's resourceVersion is unchanged across enable, disable and re-enable. The live DoD remains t007.
