# 055 — `blueprints validate` passes `domains: [dashboard.bex.co]`, `api.bex.co` and `*.onbex.co` that apply refuses, and points hostname errors at `services[n].name`

Why: validate (and the dashboard's create review and pre-sync preview, which share it) promises a file is applicable. For platform-reserved hosts it says `valid: true` and the apply then fails. That is the validate/apply split w8/045 closed for service-create dry-runs. The hostname errors validate does report also land on the wrong field.

Severity: minor (apply still refuses, so no hijack). Attribution: server (`lego/backend/internal/apps`).

## Mechanism

- Apply enforces: `lego/backend/internal/apps/deploy.go:2891` → `ensureHostsClaimable` → `checkHostsClaimable(…, preview=false)` (`domains.go:1031-1051`), which runs `reservedHost`/`platformHostReserved`, the per-service cap and the cross-App collision check.
- Validate does not: `previewHostsClaimable` (`domains.go:1047`), the read-only twin w8/045 added for service-create dry-runs, has no caller in the Blueprint validate/preview path (`rg 'previewHostsClaimable|ensureHostsClaimable' internal/apps/blueprint*.go` → none). Validate runs only `canonicalHosts` (`service.go:2986`), the format check that catches IPs, single labels and wildcards.
- Wrong path: `lego/backend/internal/apps/blueprint.go:1894-1906` `blueprintErrorField` guesses the field by substring. `"invalid hostname"` contains `name`, which matches before `domains` is considered, so the error maps to `services[n].name` (the service's `name:` line) instead of `services[n].domains[i]`.

## Fix

- In Blueprint validate/preview, run `previewHostsClaimable` (preview semantics: exempt nothing under the base domain while the store mints slugs, skip the DNS-TXT proof) on each declared service's canonical host set. Report each refusal as a located entry. Keep the cross-tenant collision wording non-revealing, as w4/190 requires.
- Locate hostname errors precisely: carry the offending index from `canonicalHosts`/the claim check, or at minimum map `hostname`/`wildcard` messages to `.domains` ahead of `name` in `blueprintErrorField`.
