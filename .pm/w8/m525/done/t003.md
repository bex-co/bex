## Objective

Publish `ghcr.io/bex-co/bex-alloy` with t001's patch, set the new argument in the `app_logs` `stage.limit` only, and pin the image. Then prove on the real image that the shipper keeps the same lines the Go cap keeps.

## Context

- `.github/workflows/log-shipper-image.yml` builds and verifies the image from `deploy/log-shipper/`. The digest pin in `deploy/gitops/base/log-shipper.yaml` is a reviewed commit made after that build.
- `scripts/test_log_shipper.py` already floods `app_logs` in the pinned Alloy image beside a quiet neighbor. `scripts/gitops-validate.sh` pins the stage's values and the tail's constants.

## Steps

1. Build and publish the image (CI), then pin its digest and add the argument to `app_logs` (`deploy/gitops/base/log-shipper.yaml` and the dev-N copy).
2. Extend `scripts/test_log_shipper.py`: write a numbered flood in 20-line bursts, read back what reached the fake Loki, and assert the admitted numbers equal what `lineCap` admits on the same stamped lines (the shared table or a generated equivalent). Add one case where Alloy reads the burst in a single batch late, which the wall-clock limiter fails.
3. `scripts/gitops-validate.sh` pins the new argument on `app_logs` and its absence on `sandbox_pods`.

## Acceptance criteria

- [x] The harness passes on the new image and fails on the previous digest.
- [x] `bash scripts/gitops-validate.sh` passes. The log-shipper DaemonSet rolls on the next production deploy.
