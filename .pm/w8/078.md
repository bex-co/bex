# Empty workspace flags bypass current-workspace name resolution

Why: scripts that pass `--workspace="$OPTIONAL_WORKSPACE_ID"` lose the documented current-workspace fallback when the optional value is empty and `BEX_WORKSPACE` contains a valid name.

**Status:** todo. **Worker:** worker8. **Severity:** minor. **Attribution:** Bex launcher. **Estimate:** 55m (30m dispatch correction, 25m shared-command regression verification). Functional CLI QA sweep 64, 2026-10-09; filing only. Goal: dependable hosting automation under ADR008 / ADR018 and the pinned Render command contract.

## Root cause and fix

- Launcher [`main.go`](../../lego/cli/main.go) at lines 249–286 classifies any raw `--workspace`, `--workspace=…`, or `-w…` token as `WorkspaceUnused`, without checking its final value. Its initializer at lines 59–65 then calls the bridge; `internal/bridge/workspace.go:39–41` skips name resolution for that classification.
- Pinned `cmd/blueprintvalidate.go:85–107` reads the parsed string and falls back to `config.WorkspaceID()` when it is empty. `pkg/config/config.go:121–125` returns the mapped, still unresolved `RENDER_WORKSPACE` name. The multipart writer sends that name as `ownerId`.
- Server `lego/backend/internal/apps/rest.go:1331–1344,1611–1614` decodes the owner field; `apps/blueprint.go:621–627,633–640` scopes validation to that owner. The resolved-ID controls pass. The correction belongs in launcher dispatch; accepting names in this server ID field would conceal the wrong request.
- Read the **final parsed workspace value** when classifying the command: only a nonempty explicit selection bypasses active-name resolution. Cobra v1.10.2 `command.go:919–921,959,1047–1050` parses flags before invoking initializers, so the command's existing flag value is available. Preserve one upstream parse, last-value semantics, terminators and normal flag errors; do not reparse into live flag sets or rewrite requests.

The shared detector has one production caller, `workspaceUse`, invoked by the startup initializer. The pin declares three string workspace flags: Blueprint validation (`cmd/blueprintvalidate.go:49`, shorthand `-w`), Postgres create (`cmd/pgcreate.go:53`), and Key Value create (`cmd/kvcreate.go:51`). These expose five command paths when `pg`/`postgres` and `kv`/`keyvalues` aliases are counted. All three request builders were exercised offline; only Blueprint validation was exercised live. Preserve commands without this flag, typed-resource recovery, help/completion/auth dispatch, explicit `RENDER_WORKSPACE` precedence and the existing PG trust ordering. REST/GraphQL/MCP/dashboard contracts need no change.

## Implementation (2026-10-09) — live control pending

Fixed in the launcher. `workspaceUse` (`lego/cli/main.go`) now classifies a command on the `--workspace` flag's **final parsed value**. Cobra parses flags before initializers run, so the existing single upstream parse is reused. Only a nonempty value skips active-name resolution. The raw-token `selectsWorkspace` scan has been removed. Typed-ID, help/inventory/auth and PG trust ordering are unchanged.

`TestStaleWorkspaceNameBlocksOnlyConsumers` (binary against a fixture API) now also checks the `ownerId` each request carries:

- Blueprint validate with the flag omitted, `--workspace=`, `--workspace ""`, `-w ""`, or an ID followed by an empty repeat sends the resolved ID after exactly one name lookup.
- An empty value followed by an ID sends the ID with no lookup.
- `pg create` and `kv create` (both refused by the fixture, so no side effects) send the resolved ID both when the flag is omitted and when it is `--workspace=`.

The old detector fails 10 of these assertions. The w8/064 stale and ambiguous-name matrix passes unchanged. `lego/cli` `go test ./...` and `make lint` pass.

Remaining: a live production Blueprint validate with `BEX_WORKSPACE=<name>` and `--workspace=` from a checkout build, in a separate process. The note closes once that check passes. Users get the fix in the next `bex` CLI release.
