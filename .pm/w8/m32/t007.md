## Objective

Add meaningful tests that assert the real behavior this milestone ships: a static site cannot be sourced from an image at any layer, and the four image-valid service types still can.

## Context

- Layers: dashboard submit gate/payload (`create-service-input.ts`), dashboard picker gating (create + source card), bex-api create validation (`service.go`), CRD schema (`app_types.go` XValidation via envtest).
- The four image-valid types (web/private/worker/cron) are regression subjects — the allowlist must not over-reach.

## Steps

1. Dashboard unit tests: `isSubmittable`/`buildCreateServiceInput` reject static+image and never emit `runtime:"image"`+`publishPath` for static; the four types still submit an image source.
2. Dashboard component/render test: `/services/new?type=static_site` renders two source tabs; other types render three. Same for the Update Source card.
3. Backend test: create with `type: static_site` + image returns 4xx (assert status + message shape) across the shared path; the four types succeed.
4. envtest/CRD test: applying a `static_site` App with a non-empty `image` is rejected by the API server; a Git-sourced static site is accepted.

## Files

- `dashboard/src/features/services/**/*.test.*`, `lego/backend/internal/apps/*_test.go`, operator envtest.

## Acceptance criteria

- [ ] Tests fail if any single layer's guard is removed (mutation spot-check: delete a guard → a test goes red).
- [ ] Regression tests cover all four image-valid types.
- [ ] `dashboard/yarn test`, `cd lego/backend && go test ./...`, and operator `make test` pass.

## Out of scope

- Tests for behavior outside the static-vs-image rule.
