## Objective

Confirm the static-vs-image rule is consistent across every surface it exposes — REST, GraphQL, and MCP in `lego/backend/` (same fields, semantics, and error shapes) and the `dashboard/` UI — and matches render.com behavior (static sites are Git-repo-only). Flag any residual drift as follow-up rather than silently diverging.

## Context

- bex-api is meant to be Render-compatible ([docs/ADR006-bex-api.md](../../../docs/ADR006-bex-api.md)); the create path is shared across REST/GraphQL/MCP.
- Render's static sites deploy only from a Git repo — no prebuilt-image option.
- Governing ADRs: ADR029 (static sites), ADR018 (parity ledger), ADR049 (render.yaml parity).

## Steps

1. Verify `type: static_site` + image is rejected identically via REST, GraphQL, and MCP (same 4xx error shape/message).
2. Verify the dashboard create wizard (t001/t002) and the Update Source card (t004) both refuse the image source for a static site and are unchanged for the four image-valid types.
3. Verify the render.yaml/blueprint compile path (ADR049) refuses the same combination (or file the gap if t003 deferred it).
4. Update the ADR018 parity ledger row for static sites / service source if it records this behavior; note any deliberate divergence.

## Files

- `lego/backend/internal/apps/` (REST/GraphQL/MCP), `dashboard/src/features/services/`, `docs/ADR018-render-parity.md`

## Acceptance criteria

- [ ] All three API surfaces reject static+image with the same error shape.
- [ ] UI (create + edit) and API agree that static = Git-only.
- [ ] Any remaining drift (e.g. blueprint path) is filed or fixed, not left silent.

## Out of scope

- New behavior beyond enforcing static = Git-only.
