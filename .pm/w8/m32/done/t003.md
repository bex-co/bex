## Objective

Reject a `static_site` service created with an image source (and no repo) at the bex-api create path — which is shared by REST, GraphQL, and MCP (ADR006) — with a clear 4xx validation error, and add a CRD `XValidation` so the API server refuses it even if the app layer is bypassed.

## Context

- bex-api create path (shared by all three surfaces):
  - `validateTypeSpecificCreate` static branch `lego/backend/internal/apps/service.go:2395-2403` requires only `publishPath`, never rejects `image`.
  - `resolveBuildStrategy` `case "image"` `service.go:2459-2463` has no static exclusion.
  - `validateCreateSource` `service.go:2337-2367` only requires one of repo/image.
  - `specFromCreate` `service.go:2292-2293` copies both repo and image.
- CRD: `lego/types/v1alpha1/app_types.go` — `Image` `:356-363`, `Type` enum `:292`, `PublishPath` `:321-328`, doc `:346-347`; spec `XValidation` rules `:268-273` do NOT exclude image for static.
- Blueprint compile path (ADR049): `lego/backend/internal/apps/blueprint_compiler.go:279-288` — the "prebuilt image can't declare build-from-git fields" list does not include `publishPath`, so an image + publishPath static passes there too. Check and, if needed, add the same rejection.

## Steps

1. In `validateTypeSpecificCreate` (`service.go:2395`), when `type == static_site` and an image source is set (no repo), return a 4xx validation error whose message states that static sites build from a Git repo. Use the existing validation-error shape so REST/GraphQL/MCP all surface it consistently.
2. Add an `XValidation` rule to the App spec in `app_types.go` (near `:268-273`) rejecting `type == "static_site"` with a non-empty `image`; regenerate CRDs (`make manifests`/`make generate` from `lego/operator/`).
3. Check the blueprint compiler (`blueprint_compiler.go:279-288`); if it accepts a `static_site` + image, add the same rejection there (ADR049) or note in t005 that it already refuses.
4. Confirm the error is a 4xx (bad request / validation), distinct from 404 (no such resource), 403 (forbidden), and 401 (unauthenticated).

- [x] `kubectl apply` of an App with `type: static_site` and a non-empty `image` is rejected by the CRD schema (envtest proves it).
- [x] The four image-valid types still create through all three surfaces.
