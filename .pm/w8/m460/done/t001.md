## Objective

An operator envtest (or a reconcile unit test) that drives a static site's first release through build → publish while a release-identity input (`publishPath`, `rootDir`) changes between dispatch and publish, and fails today the way production does: the App stays `Deploying` on `rev-1` after publishing it. Name the exact early return in the milestone README.

## Context

- `lego/operator/internal/controller/app_controller.go:4942-5045` (`reconcileStaticSite`): first-publish handover at `:5020-5027`, `PhaseRunning` at `:5033`.
- `lego/operator/internal/controller/release_identity.go:743-806`: `sourceUpdatePending`, `firstReleaseReadsSavedSource`, `pendingReleaseOwed`, `requestedReleaseGeneration`, `releaseRevision`.
- Production evidence is in the milestone README (sweep `0bbe`). `pp` and `rd` reproduce it with one save each. A set-and-clear of `rootDir` also reproduces it, so it is the generation bump, not the value.

## Steps

1. Write the test with the smallest change set (`rootDir` set and cleared mid-build).
2. Trace each reconcile pass and record the returning branch, plus the `status.releaseGeneration`, `pendingReleaseGeneration` and `activeRevision` values, in the README's Cause section. Remove "unverified" there.
3. Run the same sequence for a web service and confirm it settles, so the cause stays static-specific.
