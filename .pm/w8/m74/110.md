## Cause and complete small fix

- `lego/backend/internal/apps/deploy.go:2520` already carries the authored ordinal in envRef.index (w8/100). `classifyRef:2278` drops it when storing hostRef; hostRef at595 carries only key/target/port/hostport.
- `blueprint_ownership.go:652` unknownServiceReferences emits strings containing both the consumer name and missing target. At637 validation passes each string to blueprintReferencePointer:716, which scans every non-KV fromService name for any quoted match in the message and chooses the first. Consumer-name matches and repeated targets therefore lose origin. A key-only lookup would also mislocate repeated keys.
- Preserve exact authored consumer + env ordinal/source pointer into deferred host references and structured unknown-reference results; locate directly under that consumer's IR SourcePath. Reuse the existing envRef.index and located-error machinery. Emit one error per actual missing reference in document order, without matching display text or deduplicating by target/key. Keep existing messages, validity and runtime values.
- Census: unknownServiceReferences has two production callers: validation637 and apply `deployParsedStack` at781. Update both; apply must preserve the pre-write400/deterministic first refusal and create nothing. Preserve forward/existing-service resolution and addressability/type refusals. Host/hostport properties share storage; port is resolved separately. Supported source placements include root/project environments; service namespace excludes databases/KV (w1/126).
- blueprintReferencePointer also handles the default workspace resolver refusal at619; `resolveUndeclaredDatabases:1183` labels a pooler-required refusal as Service. Preserve/audit that separate path rather than deleting its fallback accidentally. Typed missing DB/KV mapping uses blueprintReferencePointers and must retain every origin.
- Shared consumers: REST `apps/rest.go:1351` returns HTTP200 BlueprintValidation; GraphQL `apps/graphql.go:1044,1259` exposes errorDetails alongside legacy string errors; MCP `apps/mcp.go:1024` validate_bex_yml and preview_blueprint share the core. Dashboard `features/blueprints/components/blueprint-error-list.tsx:13` prints returned coordinates/path in Validate/New/Sync. Pinned Render cmd/blueprintvalidate.go:104–153 and generated ValidationError fields preserve server paths/line/column and exit1. Fix the server; no CLI fork/rewriting.
