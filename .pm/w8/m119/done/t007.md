## Objective

Run `/simplify` over the operator and backend code this milestone changed (behavior-preserving).

## Acceptance criteria

- [x] `/simplify` applied; tests still pass.

## Outcome (2026-10-19)

Three independent reviews (reuse, quality, efficiency) ran over the m119 diff. Fixed:

- **Rollback/Restart pin regression.** A selected release that was still rolling out, whose `spec.releaseConfig` a newer deploy then cleared, would have been pinned and rolled with the saved configuration. It is now recorded on adoption (`status.selectedReleaseGeneration`, a new CRD field) and never pinned.
- **Served image.** The served row's image now comes from its own release record (`ReleaseRecordName` pod template, app container `ReleaseRecordAppContainer`). The old fallback was `status.image`, which a newer configuration-only release can already have taken over. `status.image` is still used while the newer release builds.
- **Pre-deploy verdict.** The pre-deploy failure check now uses the same status test as `observedDeployStatus` (`preDeployStatusAt`).
- **Restart wording.** It is now true for rollback rows as well: "…which kept the running release: what this deploy was applying was not deployed".
- **Cleanups:**
  - one `servesGeneration` helper on `RevisionGeneration` replaces three `rev-%d` comparisons;
  - removed `prepareDeployCreate`'s unused `id` parameter;
  - the cheap fingerprint comparison now runs before `releaseInFlight`;
  - the Postgres test uses the lifecycle helpers with a unique app name;
  - comments trimmed or corrected.

Not changed:

- `sourceUpdatePending` is still decided before the pin. That ordering predates this milestone; it is filed as w8/124.
- A crash-looping in-flight release now holds a pushed fix until its 900s progress deadline or a Cancel. This is Render's Wait behavior, and ADR060 records it.
