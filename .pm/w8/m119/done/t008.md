## Objective

Lock in the shipped behavior with tests that drive the real operator status sequence into the backend, not a hand-made Ready state.

## Steps

1. Operator envtest: gen-1 building, gen-3 pending; drive gen-1's Deployment available; assert the served record, then gen-3's adoption and live.
2. Backend reconciler test: replay the finding's repro 3 sequence; assert live/deactivated for every row and no canceled served row.
3. Restart-in-window test: assert the serving release is restarted and the t004 decision for the in-flight deploy.
4. Controls: queued-row replacement (w2/018), executing-row build failure (w6/m100), user cancel (m117).

- `TestPendingReleaseWaitsUntilTheReleaseInFlightServes` covers ten states: building, rolling out over a served or first release, served, failed over the prior release, failed first release, asleep, own deploy canceled, deselected rollback, and prebuilt image.
