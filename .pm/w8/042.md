# 042 — `imageUrl` / deploy-hook `imgURL` deploy an image from any repository; Render requires the configured repository

Why: Render's deploy contract says the image's "host, repository, and image name all must match the currently configured image for the service". bex accepts any syntactically valid, allowlisted image, on the authenticated API **and on the unauthenticated deploy hook**. A leaked hook URL can therefore run any public image with the service's environment and secret files mounted, not just a new tag of the user's own image.

Severity: major (Render contract unmet; widens the deploy-hook credential beyond Render's). Attribution: server (`lego/backend/internal/deploys`).

## Repro (2026-10-03, `/qa-find-bugs-cli` w8 loop sweep 6)

Production (images pinned `8f6a69e9e`), `bex v0.2.1` (pin v2.27.0), human device login, workspace `bex-canary`. Fixture: free image web service `srv-db0dqrg9ohsc73e5r2eg` configured as `docker.io/traefik/whoami:v1.10`, deleted afterwards (`GET` 404).

```text
$ bex deploys create <srv> --image docker.io/library/nginx:1.27 --confirm -o json   → exit 0, deploy opened (different repository)
$ bex deploys create <srv> --image ghcr.io/traefik/whoami:v1.10 --confirm -o json   → exit 0, deploy went **live** (different host)
POST <deploy-hook URL>&imgURL=docker.io/library/nginx:1.27   (no auth; hook URL kept private)
  → 200 {"deploy":{"id":"dep-db0drqo9ohsc73e5r2gg"}}, trigger deploy_hook, image docker.io/library/nginx:1.27
app logs (same service): "/docker-entrypoint.sh: Configuration complete; ready for start up"   ← the foreign image ran
control: --commit on the image service → 400 "commitId is not supported for image-backed services …" (fine)
```

The foreign container starts, with the service's env and secret files, before any health gate. Whether it ever becomes `live` does not matter for exposure.

## Mechanism

- `lego/backend/internal/deploys/service.go:625-627`: `Trigger` checks `p.ImageURL` only with `store.ValidateImage` (OCI syntax plus registry allowlist, w8/m49). There is no comparison with the service's configured `imagePath` (registry host + repository + image name). The deploy hook forwards `imgURL` through the same path (`deployhook.go`).
- `w2/done/m44` DoD promised "gated by one written origin-safety rule, with unsafe origins rejected by a Render-shaped 400 that names the rule". Its design task `w2/done/m44/t001.md` still reads `status: todo`, and no rule exists in ADR004/ADR006. `docs/ADR006-bex-api.md:243` still says `imgURL` is rejected, which is stale.
- `docs/ADR028-security-review.md:153` rated "deploy-hook `imgURL` = arbitrary-image deploy credential" LOW, **fixed** by `ValidImage` plus documenting the hook as a credential. `ADR072` (2026-08-15) gated hook reveal/rotation by credential class. Neither disposition compared bex against Render's narrower documented contract. This note asks for that comparison and a decision, not a re-triage of the earlier review.

## Fix

- In `Trigger`, when `ImageURL` is set, require its registry host, repository and image name to equal the saved `imagePath`'s (normalize `docker.io/library/x` ⇔ `x`, ignore tag/digest). Otherwise return a named 400, for example `imageUrl must use the service's configured image <host/repo>; change the image in settings to switch repositories`. The rule applies to REST, GraphQL, MCP and the hook alike, because Render's contract makes no hook/API distinction.
- Switching repositories stays possible through the saved-settings path (`services update --image`, Render's `PATCH image.imagePath`), which is authenticated and audited.
- Docs: record the rule in ADR006 (replacing the stale l.243 sentence) and the ADR018 deploy rows. Update ADR028's row to reference the parity rule.

## Acceptance

- [ ] `bex deploys create <srv> --image <other repo>` and `--image <other registry>/<same name>` → exit 1 with the named 400, and no deploy row is opened. The same refusal comes from GraphQL `triggerDeploy`, MCP `trigger_deploy` and the hook `?imgURL=`.
- [ ] Same-repository tag and digest deploys still succeed (`--image docker.io/traefik/whoami:v1.11.0`, `@sha256:…`). The `docker.io/library/` normalization is covered by tests.
- [ ] Controls: `services update --image <other repo>` still switches the saved image. w8/m44's per-deploy override semantics are unchanged.
