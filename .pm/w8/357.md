# A plain-HTTP `HEAD` to a service answers `308`, and every other non-GET method a permanent `308`, where Render answers `HEAD` with `301` and the others with a temporary `307`

Why: Render's HTTP→HTTPS redirect is `301` for `GET` and `HEAD` and `307 Temporary Redirect` for every other method, but bex answers `HEAD` and every non-GET method with `308 Permanent Redirect`, which browsers cache forever, so a client sees different status codes for the same request on bex and on Render.

- Severity: minor. Path, query and method are kept in both cases, and `GET` matches. But `HEAD` gets a different code, and a `POST`/`PUT`/`DELETE`/`OPTIONS` redirect is permanent and cacheable on bex where Render's is temporary.
- Versions: production `https://*.onbex.co` on 2026-11-20 20:10–20:18 UTC. The operator code is unchanged at main `3d2522f0d`. bex CLI v0.7.0 (Render CLI v2.36.0) created the fixtures.
- Context: routine `cli-qa` run `r17-0f97`, QA human device-flow token, workspace `bex-canary`. Run-owned free fixtures: image web service `qa-20261120-0f97-hb` (`srv-dc0ahk5i534c73chvgjg`, `mccutchen/go-httpbin:2.26.0`) and static site `qa-20261120-0f97-st` (`srv-dc0ahnli534c73chvglg`), both deleted afterwards.

## Repro

```text
# bex (web service; the static site answers the same)
curl -s -o /dev/null -D - http://qa-20261120-0f97-hb.onbex.co/anything/a%20b/c?x=1&y=two%2Fthree
  → 301 Moved Permanently, Location: https://…/anything/a%20b/c?x=1&y=two%2Fthree
curl -sI http://…/get?q=1                        → 308 Permanent Redirect, Location: https://…/get?q=1
curl -s -X POST|PUT|OPTIONS|DELETE http://…/anything?b=1  → 308 Permanent Redirect, Location kept
ws:// upgrade (Connection: Upgrade, Upgrade: websocket)   → 301

# Render (sveltekit-static.onrender.com and express-typescript.onrender.com, the same on both)
GET  http://…/x/a%20b?q=1&r=%2F    → 301 Moved Permanently, Location: https://…/x/a%20b?q=1&r=%2F
HEAD http://…/x/a%20b?q=1&r=%2F    → 301 Moved Permanently
POST, PUT, OPTIONS                 → 307 Temporary Redirect, Content-Length: 0, Location kept
```

Render's WebSocket docs (`render.com/docs/websocket`) say a `ws://` handshake gets a 301, which bex matches.

## Cause

`httpsRedirectSpec` (`lego/operator/internal/controller/app_controller.go:4787`) is Traefik's `redirectScheme` with `permanent: true`, and so is the platform-host fallback (`lego/operator/config/activator/platform-host-fallback-https.yaml:16`). In the pinned Traefik v3.7.17, `moveHandler.ServeHTTP` (`pkg/middlewares/redirect/redirect.go:95-106`) sends `301` only for `GET` and `308` for every other method, `HEAD` included. The middleware has no per-method status option (`statusCode` is internal to the ingress-nginx provider). w8/m118 accepted the 308s without comparing them with Render.

## Fix

Send Render's codes from the tenant redirect: `301` for `GET` and `HEAD`, `307` for every other method, with `Location` keeping the path and the raw query exactly as now. The edge already loads three local Yaegi plugins (`deploy/gitops/base/values/traefik.values.yaml:35-52`), so the smallest change is a fourth, `bexHTTPSRedirect`. It answers a plain-HTTP request with that status and `Location: https://<host><RequestURI>`, and passes an HTTPS request on. Point `httpsRedirectSpec` and the fallback manifest at it, keeping the `BEX_HTTPS_REDIRECT` switch and the ACME HTTP-01 exclusion as they are.

Blast radius: every tenant host's Ingress (web services, static sites, verified custom domains, the auto-hibernate activator route) plus the unknown-host fallback (w8/320). No REST, GraphQL, MCP or dashboard field changes.

## Acceptance

- `curl -sI http://<slug>.onbex.co/x?y=1` answers `301` to `https://<slug>.onbex.co/x?y=1`; `GET` still answers `301`.
- `POST`, `PUT`, `PATCH`, `DELETE` and `OPTIONS` on `http://` answer `307` with the same `Location`.
- A `ws://` upgrade still answers `301`, an HTTPS request is never redirected, and HTTP-01 issuance still passes.
- The unknown-host fallback (`http://qa-nohost-x.onbex.co/`) follows the same codes.
- A real-Traefik test (as in `edge_compression_traefik_test.go`) covers each method's code and `Location`.

## Not verified

Render's code for `PATCH` and `DELETE` (only `POST`, `PUT` and `OPTIONS` were probed; all answered 307). Custom-domain redirects on bex (no domain this run controls). The body: Cloudflare sends a 94-byte HTML body with the 301 and none with the 307, while Traefik sends the status text.

Dedupe: `rg -i "308|307" .pm` finds only w8/m118's own acceptance table (`done/m118`, which recorded the 308s as expected) and unrelated dashboard 307s. ADR018 has no row for the redirect codes, and `.pm/DO_NOT_DO.md` has nothing on them.
