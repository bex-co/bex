## Objective

`--tail --level <l>` (type-less or `type=app`) on an App streams the app lines whose level, parsed exactly as the Alloy shipper parses it, matches. Request lines, which carry no level, are excluded.

## Context

- Shipper rule: `deploy/gitops/base/log-shipper.yaml:288-320` (JSON or logfmt `level`/`severity` field, honest `unknown`).
- Datastore precedent: `compileLevelFilter` (`service.go:858`) and the per-line parse in `followDatastore`.
- Pod follow: `followPods` / `streamContainerLogs` in `service.go`.

## Steps

1. Port the shipper's app-level parse into Go (`appLineLevel(line) string`).
2. Add a drift test that reads `log-shipper.yaml` and fails if the field names or normalization change, following `TestShipperRegex*`.
3. Allow `level` in `liveSubscribable` for App tails and apply it per line on the pod producer. A level filter disables the request producer, unless request filters are also present (then each producer gets only its own filters).

## Files

- `lego/backend/internal/logs/service.go` (+ a small `applevel.go`), tests.

## Acceptance criteria

- [ ] JSON `{"level":"error"}`, logfmt `level=warn`, and an unstructured line (`unknown`) are classified as history classifies them.
- [ ] `level=error` tail emits only error app lines; `level=unknown` emits unstructured lines.
- [ ] Drift test fails when the shipper's level field list is edited.

## Out of scope

- Build-log levels.
