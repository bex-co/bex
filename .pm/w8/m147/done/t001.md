## Objective

`GET /v1/logs/subscribe?resource=<srv>&path=/x` (also `statusCode`, `method`, `host`, alone or combined, with no `type` or with `type=request`) follows the request producer with those filters instead of answering 400.

## Context

- `lego/backend/internal/logs/service.go:445` `liveSubscribable`, `:430` `onlyRequest`, `:1043` `FollowLogs`; `rest.go:185` pre-slot validation and the `onlyRequest() && s.History == nil` 503 that follows it.
- History semantics: these labels exist only on request streams, so a type-less history query with them returns request lines only.

## Steps

1. Add a narrowing step (e.g. `q.narrowRequestOnlyFilters()`): with no `Level`, Types empty and any of StatusCode/Method/Host/Path set, set Types to `[request]`. Apply it before `liveSubscribable` in both callers.
2. Keep 400 for an explicit `type=app` (or `build`) together with a request-only filter, naming the filter.
3. The store-absent case answers the same 503 as a request-only subscription today.

## Files

- `lego/backend/internal/logs/service.go`, `rest.go`, tests beside them.

## Acceptance criteria

- [x] Type-less `path`/`statusCode`/`method`/`host` subscriptions stream matching request lines only.
- [x] `type=app&statusCode=500` is still 400 with a message naming `statusCode`.
- [x] No store wired → 503 `ErrLogStoreUnavailable`, before any slot or upgrade.

## Out of scope

## Done — 2026-11-10

`LogQuery.narrowLiveTypes` (`lego/backend/internal/logs/service.go`) runs in `liveSubscribable` (REST pre-slot, per resource) and in `followLogs` before the plan rule: request filters with no type (or with `request` among the types) narrow the tail to `[request]`, so the store poll follows them alone. An explicit type without `request` is a 400 naming the filters (`statusCode filters request logs, which type=[app] does not include …`). The REST handler answers the store-absent 503 after every resource's own 400. Tests: `TestNarrowLiveTypesRoutesFiltersToTheirProducers`, `TestTypelessRequestFiltersTailRequestLinesAlone`, `TestSubscribeRoutesStructuredFiltersBeforeStreaming` (SSE, NDJSON, WebSocket), `TestFallbackRefusesStoreOnlyFilters` (503 without a store).
