## Concrete scheduled correction

For native Node static builds, add the automatic project-dependency phase before the exact authored build, using the selected application root and effective build environment. At minimum, recognize an unambiguous package.json plus npm lock/shrinkwrap and install the required locked dependencies, including ordinary build devDependencies; handle the manifest-without-lock npm path. Explicit SKIP_INSTALL_DEPS=true suppresses it, while omitted/false retains normal detection. With no supported manifest, preserve the authored command and direct raw publication policy. Do not require users to insert npm ci or change the pinned CLI.

Use one shared install path and preserve command bytes, literal env/PATH (including empty/narrow), source-root boundaries, version/companion selection, secret files, cancellation, tenant-classified install failure and existing env/file/cache revision semantics. Resolve npm/Yarn/pnpm/Bun/competing-lock and packageManager interactions from their supported contract before expanding selection; do not blindly run npm over a different manager's project. The confirmed defect/DoD is the unambiguous locked npm static case. Audit other managers through the shared path and record unverified gaps/follow-ups rather than claiming broad acceptance. Do not add new tool suppliers, arbitrary image downloads, dependency behavior to Dockerfile/image or compute runtimes, or a new product toggle.

Source-established sibling callers: native static builds from direct REST, GraphQL, MCP, Blueprint and dashboard, omitted-runtime default and explicit primary Node. Dockerfile/image and buildless raw publication take other branches. Scope the fix to static; primary Node compute and Ruby/Python's Node companion keep their behavior. Other supported Node lines, nested roots, true/false skip and other managers are regression/acceptance work, not hosted coverage here.
