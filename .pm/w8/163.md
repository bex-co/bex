# Render's "Deploy to Render" button has no bex counterpart: `/deploy?repo=` is a 404 and the Blueprint wizard ignores `?repo=`

Why: Render's one-click deploy is a README badge linking to `https://render.com/deploy?repo=<repo URL>`. The click opens Blueprint creation for that repository, shows the services, and asks for approval. 103 READMEs in Render's own `render-examples` org carry it, and template authors use it to say "deploy this". Bex has the Blueprint machinery but no entry URL. `https://dashboard.bex.co/deploy?repo=…` renders "Page not found", and `/blueprints/new?repo=…` keeps the query only through login and then shows an empty wizard. So a template author cannot offer a "Deploy to bex" button, and a user who swaps the host in a Render button lands on a 404.

**Severity:** minor (adoption/migration gap; no data risk). **Attribution:** dashboard (route and prefill). **Estimate:** 90m. **Source:** `/qa-find-bugs-cli` sweep 1280, 2026-10-21 ([evidence](evidence/cli-sweep1280/README.md)).

## Reproduction

Production dashboard, 2026-10-21:

- `curl -s 'https://dashboard.bex.co/deploy?repo=https://github.com/render-examples/express-hello-world'` → 200 HTML `<title>Page not found ・ bex Dashboard</title>`.
- `curl -sI 'https://dashboard.bex.co/blueprints/new?repo=https://github.com/render-examples/express-hello-world'` → 307 to `/auth/login?next=%2Fblueprints%2Fnew%3Frepo%3D…`. The query survives login, but `dashboard/src/routes/blueprints.new.tsx` reads no search params; the repo comes only from the GitHub picker or a typed URL (`selectedRepo`/manual state, `:58–99`).
- `gh api 'search/code?q=render.com/deploy+in:file+filename:README.md+user:render-examples'` → `total_count: 103`.

## Expected

[Render's Deploy to Render Button](https://render.com/docs/deploy-to-render):

- `https://render.com/deploy?repo=<full https:// repo URL>`.
- The branch is the default unless `repo` ends with `/tree/<branch>`.
- Without `repo`, the Referer is used, though Render "strongly recommends" `repo`.
- The user "can check which services will be deployed … and approve".
- Public repos work as is; private GitHub repos need the GitHub App.

Target for bex:

- `https://dashboard.bex.co/deploy?repo=<url>[/tree/<branch>]` redirects (after login if needed) to `/blueprints/new` with the repo and branch prefilled and the preview loaded. `render.yaml` is the default path, and an optional `path=` covers the custom filenames bex already accepts.
- The user still reviews and approves. Nothing is created on click.
- A missing or unreadable repo shows the existing preview error, not a 404.
- Publish a badge asset (for example `https://dashboard.bex.co/images/deploy-to-bex-button.svg`) and document the Markdown snippet in `docs/`.

## Root cause

There is no `/deploy` route in `dashboard/src/routes`, and `blueprints.new.tsx` has no `validateSearch` for `repo`/`branch`/`path`.

## Fix

1. Add `routes/deploy.tsx`. It parses `repo` (split a trailing `/tree/<branch>`), falls back to `document.referrer` only when `repo` is absent, and redirects to `/blueprints/new?repo=…&branch=…`.
2. In `blueprints.new.tsx`, add `validateSearch` for `repo`, `branch` and `path`, seed the public-URL tab from them, and trigger the existing preview.
3. Add the badge SVG and a short `docs/` section. The skeleton must match the prefilled ready state (AGENTS.md rule).
4. Record the row in ADR018.

## Acceptance

- Route tests: `/deploy?repo=https://github.com/a/b/tree/dev` yields `repo=https://github.com/a/b`, `branch=dev`. A missing `repo` with no referrer shows the empty wizard with a hint.
- Live after deploy: the express-hello-world link above opens the prefilled Blueprint preview after login. Approving creates nothing until Apply is clicked; then delete by ID with a 404 proof. Check desktop and narrow-mobile pending and ready states.

## Dedupe

`rg -i 'deploy to render|deploy-to-render|/deploy\?repo' .pm docs dashboard/src`: no item or route (w4/m159's "button" matches are confirmation dialogs). DO_NOT_DO has no related anti-goal.
