# Resuming a service suspended by the Free-hours budget names it by its internal App name (`"tea-<workspace>-<slug>"`), not the service the caller asked for

Why: the m139 budget refusal tells the user to `upgrade "tea-daif693dqjvc73e7as3g-qa-20261030-3093-py" to a paid plan`. That string is the internal App CR name, an identifier no API surface ever issued, so the user cannot act on it (no `bex services update tea-…`). This is the same leak class w8/128 fixed for Restart/Rollback, where its review swept other `a.Name` uses onto `core.AppPublicName(a)`. The new message in m139 reintroduces it.

Severity: **minor** (wrong identifier in an error message; the refusal itself is correct). Attribution: server (`lego/backend/internal/apps/free_hours.go:81`). Estimate: ~10m. Source: `/qa-find-bugs-cli` loop sweep 3093, 2026-10-30 09:3x UTC. Context: platform pin `dc80c29bf2bc`; `https://api.bex.co/v1/`; workspace `bex-canary` (Hobby).

## Evidence

`bex-canary` has used its October budget: `GET /v1/usage?ownerId=tea-daif693dqjvc73e7as3g` → `"freeInstanceHours": {"used": 750.58, "included": 750}`. A Free web service created now (`qa-20261030-3093-py`, `srv-dbi62p09vnuc73fiqq5g`) builds and deploys, but is `suspended` with `suspenders: ["billing"]`, and its URL answers `503 x-render-routing: suspend` "This service is suspended."

```text
POST /v1/services/srv-dbi62p09vnuc73fiqq5g/resume  →  400
{"code":"FREE_INSTANCE_HOURS_EXHAUSTED",
 "error":"this workspace has used its monthly Free instance hours; Free web services resume at the start of next month,
          or upgrade \"tea-daif693dqjvc73e7as3g-qa-20261030-3093-py\" to a paid plan to run it now", …}
```

Expected: `… or upgrade "qa-20261030-3093-py" to a paid plan …`, the service's name as every read returns it (or its `srv-…` id). The fixture was deleted by ID (`GET` 404).

## Root cause and fix

`requireFreeHoursAvailable` (`lego/backend/internal/apps/free_hours.go` ~`:80`) formats `a.Name`. Use `core.AppPublicName(a)`, the helper w8/128's review adopted. Add a test asserting that the refusal names the public service name and contains no `tea-` prefix. A quick grep of `free_hours.go` for other `a.Name` in user-facing strings (for example the exhaustion email or the suspension reason) would cover the same leak elsewhere in m139.

## Note for QA

While `freeInstanceHours.used ≥ included`, every Free web service in `bex-canary`, including new fixtures, is suspended until 2026-11-01 00:00 UTC. Free-web-service live checks need either a different workspace or the month reset. Static sites, datastores and paid services are unaffected.
