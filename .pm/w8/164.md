# Bex runs every Docker Command through its own `/bin/sh -c`: Render's documented `/bin/sh -c <commands>` form silently drops the first command's arguments, and shell-less images cannot start

Why: Render's Docker docs tell users to wrap commands themselves when they need a shell ("To run multiple commands, provide them to `/bin/sh -c`"), which implies a plain Docker Command is executed directly. Real Blueprints follow that (`dockerCommand: sh -c 'export …'`), and a minimal image such as `traefik/whoami` (`FROM scratch`) or any distroless Go image can take arguments without a shell. Bex wraps every Docker Command in `/bin/sh -c`, so on those images the container never starts. The stall message says so, but the Render-valid configuration has no bex equivalent short of rebuilding the image with a shell.

**Severity:** major (Render's documented Docker Command form, e.g. its Django example `/bin/sh -c python manage.py migrate && gunicorn …`, runs on bex with the migration silently skipped; shell-less images cannot start). **Attribution:** platform runtime (operator container projection). **Estimate:** 60m. **Source:** `/qa-find-bugs-cli` sweep 1281, 2026-10-21 ([evidence](evidence/cli-sweep1281/README.md)).

## Reproduction

Production `https://api.bex.co/v1/` (deploy started on pin `9cace6b6e25d`), bex-canary. `POST /v1/services`: free web service, `image.imagePath: docker.io/traefik/whoami:v1.10.3` (`FROM scratch`, `ENTRYPOINT ["/whoami"]`), bex `port: 8080`, `envSpecificDetails.dockerCommand: "/whoami --port 8080 --name qa1281"` (`srv-dbc9hn9v5vjs73b9he30`). After 424 s the deploy was still `update_in_progress` with `stallReason`: `container could not start: the startup program "/bin/sh" does not exist in this image. … A Docker Command runs through /bin/sh -c, so clear the Docker Command to use the ima[ge's own command]`. The fixture was deleted (204 → 404).

## Expected

[Render Docker docs](https://render.com/docs/docker): Docker Command lets you "run a custom command to start your service instead of using the `CMD` instruction", and "To run multiple commands, provide them to `/bin/sh -c`" (`/bin/bash -c` if the image has Bash). Target: split a Docker Command shell-style into argv and exec it directly, with no `/bin/sh`, matching exec-form. Commands that need shell features keep working when written as `/bin/sh -c '…'`, which is how Render users already write them.

**Unverified:** whether Render keeps the image ENTRYPOINT and replaces only CMD, or replaces both. Bex's current `container.Command` replaces both. Settle this against a Render capture before changing ENTRYPOINT behavior. The no-shell part is independent of it.

## Root cause

`lego/operator/internal/controller/deployment_projection.go:216–218` (`shellCommand` → `[]string{shellBinary, "-c", command}`) and `:266–267` set `container.Command` for every Docker Command. Pre-deploy (ADR004:281) and cron (`cronPodSpec`, ADR038:21) use the same wrapper.

## Fix

Parse the saved command with POSIX shell-word rules (quotes and escapes, no expansion) into argv. Exec it directly when it contains no shell operators. Keep `/bin/sh -c` only when it does contain them (`&&`, `|`, `;`, `$VAR`, redirections), or require an explicit wrap and say so in the refusal. Option A (direct exec, refuse shell syntax with a hint) matches Render most closely. Option B (auto-detect) keeps every existing bex service working; it needs a migration note for services relying on `$PORT` expansion without a shell. Apply the same rule to pre-deploy and cron, and update ADR004/ADR038/ADR018.

## Acceptance

- Projection tests: `/whoami --port 8080` → `Command: ["/whoami","--port","8080"]`; `sh -c 'a && b'` → `["sh","-c","a && b"]`; quoting edge cases round-trip.
- Live after deploy: the fixture above goes `live` and `GET /` shows `Name: qa1281`. An existing service whose command uses `&&` keeps working under the chosen option. Delete by ID with 404 proofs.

## Addendum — Render's documented form misparses on bex (sweep 1283, 2026-10-21)

Render's [Docker docs](https://render.com/docs/docker) give the multi-command form **without quotes**: `/bin/sh -c python manage.py migrate && gunicorn myapp.wsgi:application --bind 0.0.0.0:10000`. Render's own `render-examples/minio` uses `dockerCommand: /bin/sh -c mkdir -p /data && exec minio server --address $HOST:$PORT …`. For that to work, Render must pass everything after `-c` as **one** argument. Community reports show that without the wrapper Render does not use a shell: [`&&` reached `manage.py` as a literal argument](https://community.render.com/t/dockercommand-with-multiple-commands-fails-why/21171), and [how to chain commands](https://community.render.com/t/how-to-chain-commands-for-docker-deploys/3008).

Bex wraps the whole string again: `sh -c '/bin/sh -c python manage.py migrate && gunicorn …'`. The outer shell runs `/bin/sh -c python manage.py migrate`, where the inner shell's script is just `python` (with `$0=manage.py`), so it starts a bare interpreter on empty stdin and exits 0. Then `&& gunicorn` starts the app. **The migration never runs and nothing fails.**

Live proof on pin `a3f66521f93d`: a free `python:3.12-alpine` web service with `dockerCommand: /bin/sh -c echo marker-qa1283-first && python -m http.server $PORT` (`srv-dbcagfu03oos73cqir60`) went `live` in 42 s. Its app log shows an empty line where `marker-qa1283-first` should be printed (the inner shell's script was just `echo`). The fixture was deleted (204 → 404).

Revised target rule: if the command starts with a shell (`sh`/`bash`, bare or absolute path) followed by `-c`, exec `[shell, "-c", <rest of the string verbatim>]`. Otherwise split it into argv with POSIX word rules and exec directly, without expansion. Both Render forms then behave as on Render, and shell-less images work. Existing bex services that rely on implicit shell expansion (`$PORT`, `&&` without a wrapper) need a migration note or a one-time rewrite to an explicit `sh -c` form. ENTRYPOINT semantics stay **unverified**: Render's older dashboard help says the Docker Command "will also override the ENTRYPOINT"; its [PocketBase article](https://render.com/articles/host-pocketbase-on-render) says it overrides CMD only.
