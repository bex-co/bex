## Objective

Backward log pages currently present their (correctly selected) newest lines oldest-first. Present backward pages most-recent-first, per Render's List logs contract, without disturbing page selection, cursors, or same-timestamp grouping.

## Context

- Live repro (sweep465): planted app lines `first@06:02:30.455Z`, `second@06:02:33.177Z` on an owned free web service. REST `direction=backward&limit=2` → `[first, second]`; `forward&limit=2` → `[first, second]`; CLI `-o json`/`text` agree with the wire. But `backward&limit=1` → `second`, and cursor follow → `first`, then empty with `hasMore:false` — selection and cursors are right; only within-page order is flipped.
- Mechanism: [render.go](../../../lego/backend/internal/logs/render.go) `queryLogPage` sorts merged entries unconditionally ascending (`sort.SliceStable(..., core.TimestampLess)`, ~line 170) after the per-resource fetches, then `capToLimit` ([service.go](../../../lego/backend/internal/logs/service.go):418, direction-aware — backward keeps the newest tail) and `pageCursors`. The ascending sort is load-bearing for cursor math and for the multi-resource merge; reverse the **presented** slice for backward after capping/cursor computation, or make the sort direction-aware and audit every consumer of `all[0]`/`all[len-1]` in the cursor code — whichever keeps one ordering rule in one place.
- Sibling ascending sorts exist at the fetch layers (loki.go:286/661, service.go:616, progress.go:406) — those feed selection/coverage math and are not themselves the presentation order; do not flip them blindly.
- Secondary wart in the same envelope: a full backward page reports `hasMore:true` and the cursor-follow returns an empty page (observed: page2 `hasMore:true`, page3 `[]`). If the fix touches `pageCursors`, take the +1-probe or exact-count route so `hasMore` never precedes an empty page for these fixtures; if that needs a store round-trip the current design avoids, record the decision rather than silently keeping it.

## Steps

1. Write the fail-first page-verb test: two+ lines, both directions, asserting wire order and cursor walk.
2. Apply the ordering change at `queryLogPage`; keep `capToLimit` grouping and cursor values byte-identical for the same inputs.
3. Address or explicitly disposition the `hasMore`-then-empty wart.
