## Exact cause and repair

- operator/internal/build/native.go:262–270 creates the native image and authored build RUN;279–284 adds only PORT/entrypoint/CMD. No primary Ruby RAILS_ENV default exists. ResolveNativeBuild at nativeresolve.go:50–102 selects the image/JS companion without supplying it. One generator caller at native.go:330, preparer at build.go:1126–1128 and BuildKit941–946 consume this artifact.
- appEnv/envFromSources, used at deployment_projection.go:260–261 and app_controller.go:4676–4677/5754–5755, retain user variables and platform port but supply no Ruby production environment. See app_controller.go:4831–4886. Readiness/startup probes at deployment_projection.go:299–315 connect to the pod address; healthCheckHandler:340–351 puts the service hostname in the HTTP header, not the socket destination. A loopback-only listener cannot satisfy them. Preserve this correct probe/port behavior.
- Actual [Rails8.0.4 environment selection](https://github.com/rails/rails/blob/v8.0.4/railties/lib/rails.rb#L69) falls back to development. Its [server command](https://github.com/rails/rails/blob/v8.0.4/railties/lib/rails/commands/server/server_command.rb) chooses localhost for development and0.0.0.0 for other environments when binding is not explicitly supplied, while honoring PORT. This is the runtime consumer, not a request-construction error in either launcher.

Add a low-precedence **primary Ruby image ENV RAILS_ENV=production before the authored build RUN**, retained for runtime/predeploy. Let the existing build loader and runtime literal/group/service/Secret values override it, including an explicit empty value; preserve Rails' own RACK_ENV fallback/explicit CLI option semantics under those user overrides. Do not force a binding flag, modify the app, change platform ports/probes, add a higher-precedence container Env, use a shell fallback that erases empty values, or inject it only at runtime. Preserve command/PATH/env/files/cache revisions, Ruby/Node/Bun selection and other primary runtimes; no new API flag or fleet restart.

Cached exact Ruby3.4 image execution proves the same actual app is healthy over loopback but unreachable through its published port in default development. An explicit-binding-only development control returns200, and a production-only control without a binding override also returns200. All three local boots and containers are cleaned. Six real generator/resolver exports cover the supported Ruby3.3/3.4/4.0 lines, custom/empty env and a static Ruby artifact; all lack the default. Three maintained neighbors plus the observation give10 named passes,0fail/skip across4 top tests. These are source observations and exact-base app executions, not fixed regressions or executed generated Dockerfiles. Only Ruby3.4 is hosted.
