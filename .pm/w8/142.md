# Blueprint `ipAllowList` refuses a bare IP address, so Render's own example `render.yaml` fails validation

Why: Render's Blueprint schema defines `ipAllowList[].source` as “The IP address or CIDR block to allow access from”, and every allow-list example in Render's Blueprint reference includes `source: 198.51.100.1`. A user who imports that file, or any render.yaml that lists a single office or home IP, gets `… is not a valid CIDR` and cannot validate, sync or deploy until they hand-edit `/32` onto every entry.

**Severity:** minor (clear error, trivial workaround, but a documented Render form is refused). **Attribution:** server (Blueprint compiler). **Estimate:** 30m. **Source:** `/qa-find-bugs-cli` sweep 1240, 2026-10-20 ([evidence](evidence/cli-sweep1240/README.md)).

## Reproduction

HEAD checkout CLI at `94533d795` against pinned Render CLI v2.27.0, production `https://api.bex.co/v1/`, workspace `bex-canary`. Validation only; nothing was created.

```yaml
# kv.yaml — Render's “Key Value instance that defines all available fields” allow list, verbatim
services:
  - type: keyvalue
    name: thunder
    ipAllowList:
      - source: 203.0.113.4/30
        description: office
      - source: 198.51.100.1
        description: home
```

- `bex blueprints validate kv.yaml -o json` → exit 1: `{"errors":[{"column":7,"error":"key-value \"thunder\" ipAllowList: \"198.51.100.1\" is not a valid CIDR","line":6,"path":"services[0].ipAllowList"}],"valid":false}`.
- Only `198.51.100.1` changed to `198.51.100.1/32` → `{"plan":{"keyValue":["thunder"],"totalActions":1},"valid":true}`.
- The same refusal hits a web service (`service "qa-web" ipAllowList: "198.51.100.1" …`), the static site and the `elephant` database in Render's full example Blueprint (three errors from that file alone). A bare IPv6 host (`2001:db8::1`) fails the same `ParsePrefix` check; only the first failing entry is reported, so this was inferred from the code, not observed.
- Not part of this item: the pinned CLI's own `--ip-allow-list cidr=198.51.100.1` flag refuses client-side (`invalid CIDR address`), as upstream does, and REST's field is named `cidrBlock`.

## Root cause

`lego/backend/internal/apps/deploy.go:2044–2056` (`manifestAllowEntries`) copies `source` verbatim into `CIDRBlock` and calls `core.ValidateAllowList` → `core.ValidateCIDRs` (`lego/backend/internal/core/cidr.go:39–49`), which accepts only `netip.ParsePrefix`. It has two callers: services and static sites (`deploy.go:2659`), and databases and Key Value via `parseBlueprintIPAllowList` (`deploy.go:3030–3035`). The vendored Render schema (`lego/backend/internal/apps/schema/render.yaml.json`, `definitions/ipAllowList/items/properties/source`) types `source` as a free string described as “The IP address or CIDR block”.

## Fix

In `manifestAllowEntries` only, before validation: when `source` parses as `netip.ParseAddr`, rewrite it as a single-host prefix (`<addr>/32` for IPv4, `/128` for IPv6, after `Unmap`). Everything downstream (store rows, CR specs, the SNI proxies' `ParsePrefix`, Traefik `sourceRange`, Blueprint export at `blueprint_generate.go:717`) then sees canonical CIDRs, and the parsers keep agreeing as `cidr.go:31–38` requires. Leave `ValidateCIDRs` and the REST/GraphQL/MCP `cidrBlock` contract unchanged.

## Acceptance

- `apps` tests: a bare IPv4 address and a bare IPv6 address in a service, a static site, a database and a Key Value allow list validate and compile to `/32` and `/128`. `not-an-ip`, `203.0.113.0/99` and an empty `source` still fail with the existing messages.
- Live after deploy: `bex blueprints validate` on Render's full example Blueprint no longer reports any `is not a valid CIDR` errors; the remaining errors are the documented refusals (PORT, region, previews, workflows, database names with spaces).
- Sync/apply round trip on a free fixture: a Key Value created from `source: 198.51.100.1` reads back `cidrBlock: 198.51.100.1/32`.

## Dedupe

`w4/done/116.md` recorded “`203.0.113.7` (bare IP, no mask) → same named refusal” on GraphQL `setServiceIpAllowList` as correct behavior, without checking Render's Blueprint contract. That REST/GraphQL `cidrBlock` behavior stays as it is; this note covers only the Blueprint `source` field. `rg -i 'bare ip|not a valid CIDR'` across `.pm` and `docs` found no other item.
