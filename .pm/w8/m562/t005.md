## Objective

## Context

## Steps

1. `bex kv create --plan free --ip-allow-list "cidr=10.0.0.0/8,description=private" --confirm -o json </dev/null` in `bex-canary`, saving the output to a 0600 file. Wait until the store is available and its connection info reads `externalCertificate: publiclyTrusted`.
2. From this host, which is outside `10.0.0.0/8`:
   - `bex kv-cli <id> -- PING` in a PTY prints `AUTH failed: Client IP address is not in the allowlist.`;
   - `valkey-cli --tls --sni <id>.kv.bex.co -h <id>.kv.bex.co -p 6379 PING`, with no password, prints `(error) Client IP address is not in the allowlist.`
3. Controls:
   - `valkey-cli --tls --sni nope.kv.bex.co -h <id>.kv.bex.co -p 6379 PING` still reads an EOF before any handshake.
   - `bex kv update <id> --clear-ip-allow-list --confirm </dev/null` leaves an empty `externalConnectionString`.
4. The admitted control (`NOAUTH` without the password, `PONG` with it) rests on t003's tests, or a dev-8 stack when one is up. Do not widen the production store's list to reach it.
5. Delete the store by ID and confirm 404 on REST, GraphQL and the CLI.
