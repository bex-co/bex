## Objective

Where `kvRouter.resolve` refuses a source for a store it knows, forward the ClientHello to that store's refusal port instead of closing, so the client completes TLS and reads Render's refusal. An unknown name is still dropped.

## Context

- `kvRouter.resolve` (`lego/operator/cmd/kv-sni-proxy/main.go:152`) returns `false` both for an unknown name and for a refused source (`main.go:163`). `handleConn` closes on either (`main.go:351`).
- `handleConn` already holds the per-source slot (`AcquireSource`) and the per-network handshake slot (`AcquireHandshake`), and releases the handshake slot once the SNI is read (`main.go:349`). The route capacity is `AcquireRoute` (`main.go:358`). Rejections are `meter.Reject(<reason>)` (`internal/sniproxy/meter.go:76`).
- `kvRoute.Backend` is `<id>.<ns>.svc.cluster.local:6380` (`main.go:118`).

## Steps

1. Give `kvRoute` the refusal address (the stable Service and t002's port), and make `resolve` say which of three cases it found: admitted, refused for a known store, or unknown.
2. For a refused source:
   - keep the handshake slot and the source slot until the connection ends;
   - set one deadline on both sides at accept plus `handshakeTimeout`;
   - skip `AcquireRoute`;
   - call `meter.Reject` with a new reason (for example `allowlist`) and log it at the level of today's `no allowed route`;
   - dial the refusal address with `dialTimeout`, write the ClientHello, and copy both ways without metering the bytes as the store's egress, or say in the task record why they should be metered.
   - If the dial fails, close as today.
3. Tests, in `route_admission_test.go` or a new file, using a fake refusal listener:
   - a refused source on a known name reaches the refusal address and never the store's backend address;
   - an unknown name and a name without the domain are closed without a dial;
   - an admitted source is routed to the backend unchanged;
   - a refused connection counts toward the per-network handshake cap for its whole life, not toward the route's capacity;
   - the rejection metric counts it;
   - a refusal address that refuses the dial closes the client.

## Record (2026-11-22)

- `kvRouter.resolve` returns an `admission`: `unrouted`, `admitted` or `refused`, and a refused route carries `Refusal` (`<id>.<ns>.svc.cluster.local:6381`).
- `handleConn` releases the handshake slot only on the admitted path. A refused connection keeps it and its source slot until it ends, takes no route slot, is counted as `meter.Reject("allowlist")`, and is logged at Info (`connection refused by the allow list`). `refuseAllowList` dials the refusal address with the accept-plus-`handshakeTimeout` deadline, writes the ClientHello and relays both ways under that one deadline, with half-close.
- **Not metered.** A refusal is no use of the store, and an attacker's probes would otherwise bill the customer, so its bytes are not counted as the store's egress.
- **The shedding alert leaves it out.** `DatastoreProxyShedding` summed every reason, so a customer's client retrying from a refused address would have paged as shedding. Its Key Value arm now reads `{reason!="allowlist"}`, and `datastore_proxy_shedding_alerts_test.yml` holds sustained allow-list refusals silent (it fails without the filter). The Grafana panel shows the new reason as its own series.
- Tests (`cmd/kv-sni-proxy/allowlist_refusal_test.go`, with a real `kvinternalauth` refusal listener): `TestARefusedSourceReadsRendersRefusalUnderTheStoresCertificate` (the store's certificate, AUTH and PING read the refusal, the backend sees nothing, one `allowlist` rejection and no other, no egress, and the admitted control reaches the backend and not the refusal port), `TestAnUnknownNameIsStillDroppedBeforeTheHandshake`, `TestARefusedConnectionHoldsItsHandshakeSlotAndNoRouteSlot`, `TestARefusalPortThatRefusesTheDialClosesTheClient` and `TestTheRefusalRelayEndsAtItsDeadline`. Reverting `resolve` to drop refused sources fails the first and the third; releasing the handshake slot before the switch fails the third.
