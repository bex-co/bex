## Objective

A core service function that takes a set of workspace resource ids (services, Postgres, Key Value, env groups) and produces a render.yaml manifest string: one entry per resource with the fields bex round-trips (type/runtime/plan/branch/build/start/health/scaling/domains/routes/headers/schedule/…), env vars with **names only for secret-backed values** (`sync: false`), literal values kept for plain vars, and `fromDatabase`/`fromService`/`fromGroup` references where the live wiring is derivable. Never emit a field outside the registry's `translated`/`equivalent` set.

## Context

- Serialization source: App CRs + datastore rows already projected by the Render-compatible read paths (`lego/backend/internal/apps/render.go`, postgres/keyvalue equivalents).
- Secret detection: env vars resolved from OpenBao/secret-backed storage ⇒ `sync: false`; the ADR018 note "write-only secret-backed env-group plan is structural" is the relevant precedent.
- Link derivation: an env var whose value equals another selected resource's connection string/internal address ⇒ emit the reference form instead of the literal (best-effort; keep literal when ambiguous — never guess wrong).
- Validate output through the existing compiler (`CompileBlueprintSource`) before returning — a generated manifest that fails own-validate is a bug.

## Steps

1. Define `GenerateBlueprint(ctx, rel, resourceIDs) (string, error)` in the blueprint service; authz `RelCanViewSensitive` (it reads env wiring, though never secret values).
2. Serialize per resource kind against the registry allowlist; implement secret/link classification.
3. Self-check: compile the output; fail loudly on any validation error.
4. Unit tests with fixture resources incl. secret vars and cross-links.

## Files

## Acceptance criteria

- [ ] Generated manifest passes bex validate with zero errors for a mixed fixture.
- [ ] No secret value bytes in the output (test asserts absence).
- [ ] Derivable links emit reference form; ambiguous ones stay literal.
