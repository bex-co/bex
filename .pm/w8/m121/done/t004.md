## Outcome (2026-10-19)

`held_release_source_envtest_test.go` has four specs, and each fails with `heldReleaseView` stubbed to nil:

1. **Update Source over a queued build.** The build waits at the cluster ceiling. Generation 2 stays off `rev-2` until its own build, builds `REF=main`, serves its own image, and the saved `next` waits for a deploy. Old code rolled generation 1's image as `rev-2`.
2. **Prebuilt-image switch mid-build.** Generation 2 rolls its own built image, not the prebuilt one or generation 1's. Old code rolled generation 1's image as `rev-2`.
3. **Newer deploy while queued.** Generation 2 builds `EXPECTED_COMMIT=X`, serves, and then the waiting deploy builds Y. Old code built Y as generation 2.
4. **Pre-deploy after a newer save.** A's pre-deploy runs `migrate A` and reads A's adoption snapshot `K=a`. Old code ran `migrate B`.

Specs 1 and 2 also assert the stored spec is untouched by the held passes. Unit tests in `release_view_test.go` cover the field split, the disk-remount identity check, `keepReleaseView` scoping, and the selected-release guard.
