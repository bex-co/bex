## Objective

A held release whose build has not started yet builds from its captured inputs. A held repo-backed release keeps its build path after a switch to a prebuilt image. The `sourcePending` branch never rolls `status.image` as a newer generation.

## Context

- `prepareAppReleaseDecision` `sourcePending` branch: the w8/124 `releaseSourceFixed` guard becomes unnecessary once the build reads N's own inputs.
- `pinnableSourceRelease`, `reusableArtifactImage`, `buildFromSource`, `effectiveDeployRef`

## Steps

1. Make pinnability, the build ref and the build inputs read the held release's captured inputs.
2. Make image selection prefer the held release's own artifact over `spec.image` and `status.image`.
3. Keep the legacy, uncaptured path on the prior behavior or t001's chosen fallback.

## Outcome (2026-10-19)

`release_view.go` holds the mechanism:

- **The view.** `releaseView(saved, adopted)` copies every field `AppSpecIdentityClasses` does not class operational from `adopted`, and keeps `Disk` and the operational fields from `saved`.
- **Loading.** `heldReleaseView` loads the view only on in-flight passes (Building or Deploying) whose saved spec moved on. It requires the view's release identity to equal `status.releaseFingerprint`. It yields when the saved spec selects a release, so a Rollback or Restart still overrides.
- **The decision.** `prepareAppReleaseDecision(app, view)` judges `releaseInFlight` and `survivorInFlight` on the view, and a viewed release counts as source-fixed in the `sourcePending` branch. A pinned decision carries the view.
- **The swap.** `withViewedRelease` makes `app.Spec` the view for the rest of the pass, in memory only. Status writes decode the stored spec back into the App, so `keepReleaseView` re-applies the view after each one: `updateStatusIfChanged`, the new `writeAppStatus` (the three direct writes) and `updateStatusRetrying`'s re-read.
- **Snapshots.** `inFlightRelease(ctx, app)` points a viewed release's build and pre-deploy steps at its adoption snapshots.

This also closes m120's known gap, since a held release now runs its own pre-deploy command.

The m120 restart spec caught one regression during the work: the view first held a release behind a saved Restart. The selected-release guard fixed it.
