# A service deployed from a public non-GitHub repository (GitLab, Codeberg, …) gets deploys with no commit: commit resolution is GitHub-only

Why: Render deploys any public Git repository by URL and shows each deploy's commit (SHA and message). bex accepts a public GitLab URL and builds and serves it, but the deploy has no `commit`. bex-api resolves commits only through the GitHub API. Without a commit, the deploy history can't say what is running, a deploy can't be pinned to the SHA that was checked, and rollback targets are unnamed. This is not the GitLab _integration_ that `.pm/DO_NOT_DO.md` rejects (connect, repo listing, private deploy, push-to-deploy). Public repo URLs need no provider connection.

Severity: **minor** (the service works; deploy metadata is missing and the build is unpinned). Attribution: server (bex-api commit resolver). Estimate: ~45m. Source: `/qa-find-bugs-cli` loop sweep 6a81, 2026-10-27 02:41–02:44 UTC. Context: HEAD-built bex `34bcceed6` with pinned Render CLI v2.27.0 `a764810a7682`; platform pin `b4726243e74f`; `https://api.bex.co/v1/`; workspace `bex-canary`; human device login.

  # no "commit" (a GitHub-backed deploy carries {"commit":{"id":<sha>,"message":…}}), and no "startedAt"

The fixture was deleted by ID (`GET` 404).

## Root cause

- `apps.resolveDeployCommit` (`lego/backend/internal/apps/commit.go:52`) and `deploys.resolveCommit` (`lego/backend/internal/deploys/service.go:881`) call `Commits.ResolveCommit`, which is GitHub's `commitSource` (`lego/backend/internal/github/service.go:1308`).
- `resolveCommit` returns "no commit" unless `core.CanonicalRepo(repoURL)` starts with `github.com/` (`service.go` ~`:1346`). Public repos resolve only through GitHub's REST `GetCommit` (`resolvePublicCommit`, `:1384`). So every other host deploys without commit metadata ("omitted, not faked", w9/001).

## Fix

- Add a host-agnostic fallback for public HTTPS repos: resolve `ref` to a SHA with the Git smart-HTTP protocol, as `git ls-remote <repo> refs/heads/<ref>` does (anonymous, bounded timeout, the same miss/TTL cache and no-existence-oracle rule as `resolvePublicCommit`).
- That gives the SHA. For the message, either leave it empty (Render shows it, so prefer filling it) or have the operator report the checked-out commit's subject from the clone step into the deploy row.
- Pin the build to the resolved SHA exactly as for GitHub public repos.
- Keep GitHub on its current API path (it also supplies the message and author time).

## Blast radius

- Every service whose repo URL is on a non-GitHub host: GitLab, Codeberg, self-hosted Gitea/GitLab, Bitbucket public repos.
- The deploy list and detail (REST/GraphQL/MCP, CLI `deploys list`, dashboard), `RENDER_GIT_COMMIT` if it reads the same record, rollback/deploy-by-commit selection, and auto-deploy comparisons. Auto-deploy on push for those hosts remains out of scope (DO_NOT_DO).

## Regression checks

- Unit: a `gitlab.com` public URL resolves `main` to the `ls-remote` SHA; an unknown ref or a private repo is a miss (no existence oracle); the GitHub path is unchanged.
- Live: recreate the fixture above. The first deploy carries `commit.id = 87e8c32b8918…` (or the then-current HEAD), and `RENDER_GIT_COMMIT` matches on a web service. Delete by ID with a 404 proof.
