## Definition of done

On a live environment, the GitHub tab of the new-service source picker (`/services/new`) shows a **"Credentials (N)"** control. Opening it lists every connected GitHub account/org with its repo count, an "Open in GitHub" link, a "Configure in GitHub" (grants) link, and a per-account Disconnect; it also offers "Connect another account" (which opens GitHub's install in a **new tab** and, on return/focus, shows the new account's repos in place) and the ADR075 claim fallback for the already-installed case. Disconnecting an account removes its repo group in place. The half-filled create form is never lost to the connect flow. The same control appears in create-Blueprint and the Settings→Update Source dialog (shared `ServiceSourcePicker`). REST/GraphQL/MCP are unchanged; dashboard typecheck + lint + tests green.

## Constraints

- **No backend verbs** — `gitConnections`, `connectGit`, `disconnectGit(installationId)`, `claimGit`, and `repos` (with `accountLogin`/`installationId`) already exist; this milestone composes them in the UI only.
- **Preserve the create form** — the connect action opens the GitHub install in a **new tab** (`window.open`) and refetches on focus, rather than the Settings card's full-navigation `window.location.href` (`use-connect-git.ts`), so a half-filled `/services/new` form survives. Do not change the backend callback's `/settings` redirect target (a same-tab `return_to` is a separate, security-sensitive change — deferred, not in scope).
- Reuse the existing hooks (`use-git-connection(s)`, `use-connect-git`, `use-disconnect-git`, `use-claim-git`) rather than adding new GraphQL.
