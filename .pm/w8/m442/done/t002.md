## Objective

Render's `envGroup` schema no longer requires `envVars` and `secretFiles`. Each is "Omitted if the caller doesn't have the permission to read the environment group's secret values." bex refuses the whole REST read to such a caller instead. Serve the group's metadata and omit both fields.

## Context

- `lego/backend/internal/envgroups/render.go:130-150` (`revealGroups`): every REST read is authorized for `core.RelCanViewSensitive` and re-asserted fresh, and "a caller without it is refused the whole read rather than served a masked body". A read of values records `ViewEnvVarValuesEvent` (w4/m321).
- `GetEnvGroup` (`service.go:380`) already authorizes metadata at `RelCanView`.

## Steps

1. On a REST read, a caller with `can_view` but not `can_view_sensitive` gets 200 with the `envGroupMeta` fields and no `envVars` or `secretFiles` keys.
2. Record no reveal event on that path, and keep the fresh re-assertion for callers who do get values.
3. A caller without `can_view` is still refused, by the same answer as today.
4. Write responses (create, update) keep their current shape for the writer.

- `lego/backend/internal/envgroups/render.go`, `rest.go`

- [x] A test identity with view-only access reads a group: 200, both keys absent, no reveal event.
