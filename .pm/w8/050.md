# 050 — Platform internals ship as tenant log lines: the kubelet's "failed to try resolving symlinks in path /var/log/pods/…" (app and Postgres logs) and CNPG's Go `http: TLS handshake error from 10.244.…` (Postgres logs)

Why: `bex logs` shows platform internals (node log path, pod/namespace/UID) as `type: app` lines from the tenant's service, in bursts, after a pod goes away. This is the sibling of w8/025's `unable to retrieve container logs` placeholder, which m48 fixed in the shipper by exact match only.

Severity: minor. Attribution: infrastructure/runtime (`deploy/gitops/base/log-shipper.yaml`, plus the pod-log read path in `lego/backend/internal/logs`).

## Mechanism

- `deploy/gitops/base/log-shipper.yaml:212-221` `loki.process "app_logs"` has one `stage.drop`, anchored to the exact `^unable to retrieve container logs for containerd://[0-9a-f]{64}…$` body. When the pod's log directory is already gone, the kubelet answers with this other untimestamped body instead, and it passes through as an app line.
- `deploy/gitops/base/log-shipper.yaml:486-560` `loki.process "database_logs"` drops CNPG lines by `logger != postgres` (`:522`), by `logger == "" && logging_pod` (`:527`, w8/032) and non-record `logger=postgres` lines (`:532`). The Go `http:` line has neither `logger` nor `logging_pod`, so none of them match. The kubelet body is not JSON at all, so it passes through untouched as well.
- `lego/backend/internal/logs/service.go:1599` (`kubeletLogsGonePrefix`, the pod-log read and follow path) recognizes only the same `unable to retrieve container logs for ` prefix. Check whether the direct pod path surfaces the symlink body too.

## Fix

- Shipper: add a second exact `stage.drop` (own `drop_counter_reason`, for example `kubelet_pod_log_dir_gone`) anchored to the full kubelet shape `^failed to try resolving symlinks in path "/var/log/pods/[^"]+/[^/"]+/[0-9]+\.log": lstat /var/log/pods/\S+: no such file or directory\r?\n?$`. Keep it exact, like m48's, so tenant text that merely mentions the phrase survives.
- API pod path: treat the same untimestamped body like `kubeletLogsGonePrefix` (one platform line, `==> logs for this instance are no longer available …`).
- Shipper, `database_logs`: drop the same kubelet body (shared exact regex). Also drop CNPG instance-manager JSON that has no `logger` key, i.e. `{level, ts, msg}` only with no `record`. That generalizes `:527` beyond `logging_pod`; a `drop_counter_reason` of `cnpg_instance_manager` is fine. Do not drop PostgreSQL's own non-JSON lines.
- Extend `scripts/test_log_shipper.py` with the replayed body (dropped) and a tenant line quoting it (kept).
