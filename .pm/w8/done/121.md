# Platform-subdomain services answer plain HTTP instead of redirecting to HTTPS

Why: Render redirects all HTTP requests to HTTPS; bex serves tenant apps in cleartext on `:80`, so credentials/cookies sent to an `http://…onbex.co` link travel unencrypted and apps see `x-forwarded-proto: http` where Render apps only ever see `https`.

Found by `/qa-find-bugs-cli` sweep 114, 2026-10-18, live fixture `qa-20261018-38b5ed-echo` (echo-server image, bex-canary): `curl http://<slug>.onbex.co/plain` → `HTTP/1.1 200` with the app body and `x-forwarded-proto: http` at the app; no `Location`, no HSTS observed. HTTP/1.0, 1.1 and 2 over TLS all work normally. Render's contract: "Render automatically redirects all HTTP requests to HTTPS" / external requests are HTTPS-only (Render community/docs statements by Render staff, checked 2026-10-18).

Why it happens: the Traefik entrypoints deliberately keep `web` (:80) unredirected so cert-manager HTTP-01 succeeds (`deploy/gitops/base/values/traefik.values.yaml:171`), but no per-Ingress/per-router scheme redirect replaces it for tenant routes (no `RedirectScheme` middleware in `lego/operator/internal/controller`; `host_redirect` is host→host only). Dedupe: open+done `.pm`, `docs/ADR018`, and the ADR028→ security-review lineage have no verdict on scheme redirection for platform subdomains (w1/m51 treats the `web` router's bytes as "80→443 redirect" traffic, i.e. a redirect was assumed).

Fix sketch: attach a `RedirectScheme https` (permanent) middleware to tenant `web`-entrypoint routers in the operator's Ingress builder — platform subdomains and verified custom domains — while excluding cert-manager challenge paths (`/.well-known/acme-challenge/*`) and any internal plain-HTTP entrypoints (activator/health). Decide the status code (Render uses a permanent redirect) and whether HSTS ships with it. Acceptance: `curl -sI http://<slug>.onbex.co/x` returns a 3xx to the `https://` URL with path/query preserved; HTTPS behavior, ACME HTTP-01 issuance, and bandwidth/router attribution (`websecure-` sibling, w1/m51) unchanged.

Promoted to `w8/m118` on 2026-10-18.
