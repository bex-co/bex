# A Docker service with no `dockerfilePath` reads back `""`, where Render reports its default `./Dockerfile`

Why: w8/m128 made an unset `dockerContext` read back as Render's `.`. The sibling field still reads back empty, so the same service object reports one Docker default Render's way and the other bex's way. Anything that copies the object (a Blueprint export, `services create --from`, an agent writing render.yaml from `GET /services/{id}`) carries `dockerfilePath: ""` instead of the path the build actually used.

**Severity:** minor. **Attribution:** server (REST/GraphQL/MCP read projection). **Estimate:** 20m. **Source:** `/qa-find-bugs-cli` sweep 1269, 2026-10-21 ([evidence](evidence/cli-sweep1268/README.md#sweep-1269)).

## Reproduction

Production `https://api.bex.co/v1/`, deployed pin `9cace6b6e25d`, workspace `bex-canary`. Read-only `GET /v1/services/srv-daif6dsmg29s73d1umvg` (the pre-existing `hello-go`, a `runtime: docker` service built from `examples/hello-go/Dockerfile`, inspected only) → `serviceDetails.envSpecificDetails: {"dockerCommand": "", "dockerContext": "examples/hello-go", "dockerfilePath": ""}`.

On HEAD after w8/m128, `lego/backend/internal/apps/render.go:582–586` emits `"dockerContext": cmp.Or(a.DockerContext, ".")` but `"dockerfilePath": a.DockerfilePath`, so `""` persists after that release.

## Expected

The pinned Render schema states `dockerDetailsPOST.dockerfilePath` "Defaults to \"./Dockerfile\"". The pinned CLI's own fake Render API (`internal/fakes/renderapi/services.go:430–451`, `dockerEnvDetails`) reports an unset path as `./Dockerfile` and an unset context as `.`. Reads should report `./Dockerfile` for a Dockerfile-built service with no stored path. The build resolves the same file either way (`build.go`: an empty `DockerfilePath` means `Dockerfile` under `rootDir`), so only the reported value changes.

## Fix

`render.go`: `"dockerfilePath": cmp.Or(a.DockerfilePath, "./Dockerfile")`, beside the m128 context default. GraphQL and MCP service reads use the same projection, so they need checking too. Leave the Blueprint export (`blueprint_generate.go`) omitting the default, as it does now. Writes are unchanged: a PATCH of `""` still clears the stored path.

## Acceptance

- Projection test: a Dockerfile-built App with no path reads `./Dockerfile`, and one with `docker/Dockerfile.ci` reads that value. Native, image and static services have no `dockerfilePath` key, as now.
- `services create --from <docker service>` still sends no explicit path, or an equivalent one, and the clone builds the same file.
- Live after deploy: a fresh free Docker web service created without `dockerfilePath` reads back `./Dockerfile` on REST and MCP. Delete it by ID with a 404 proof.

## Dedupe

w8/m128 (context default `.`, in `blocked/` for its live check) does not mention `dockerfilePath`'s read default. Sweep 877 checked the PATCH round trip of an explicit path only. No other item.

**Done 2026-10-21:** REST/MCP service reads report an unset `dockerfilePath` as `./Dockerfile` (`render.go` docker details; `TestRenderServiceDetailsDefaultsDockerfilePath`). Blueprint export and writes unchanged. Live acceptance runs after deploy.
