## Objective

Add one core Resend verb that queues an immediate new attempt for an existing notification and expose it consistently to humans and agents.

## Context

- Render exposes Resend in the dashboard but not its documented public REST family.
- Bex's REST/GraphQL/MCP forms must be labeled as compatible extension where no official route exists.

## Steps

1. Define authorization, enabled/terminal constraints, idempotency, and coded errors.
2. Queue an immediate attempt without changing source event ID or payload bytes.
3. Add REST, GraphQL, and MCP thin adapters over the same verb.

## Files

- `lego/backend/internal/webhooks/service.go`
- `lego/backend/internal/webhooks/rest.go`
- `lego/backend/internal/webhooks/graphql.go`
- `lego/backend/internal/webhooks/mcp.go`

## Acceptance criteria

- [ ] Resend creates exactly one new attempt for an authorized request.
- [ ] Event ID/body remain stable while timestamp/signature are fresh.
- [ ] Disabled, deleted, foreign, or unknown targets fail with stable safe codes.
- [ ] Every adapter returns the same resulting attempt identity/state.

## Out of scope

- Bulk resend and automatic service/deploy triggers.
