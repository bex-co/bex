## Objective

Make status filters describe individual attempts truthfully, including a failed exchange whose parent notification still has a retry scheduled.

## Context

- `lego/backend/internal/store/webhooks.go` currently filters Failed on terminal `failed_at`.
- The dashboard currently derives Pending from the mutable parent row.

## Steps

1. Define attempt success/failure and parent pending/exhausted states separately.
2. Apply filters and counts to immutable attempt outcome.
3. Preserve parent diagnostics for GraphQL/MCP without relabeling failed sends Pending.

## Files

- `lego/backend/internal/store/webhooks.go`
- `lego/backend/internal/webhooks/service.go`
- `dashboard/src/features/webhooks/types.ts`

## Acceptance criteria

- [ ] A 500/timeout attempt appears under Failed immediately.
- [ ] A scheduled retry remains visible as parent state without erasing the failed attempt.
- [ ] Successful/failed/all filters page only matching immutable attempts.

## Out of scope

- Changing retry budgets.
