## Objective

Prove the collector contract with meaningful tests that would fail under the old sparse-write, single-cursor implementation.

## Context

- Existing usage tests cover positive quantities and storage retry behavior but not zero App rows or independent App meter cursors.
- Failure tests must distinguish source unavailability from a legitimate empty result.

## Steps

1. Test successful zero persistence for each App meter.
2. Test Prometheus/Kubernetes/store failures leave retryable gaps.
3. Test independent oldest-first retry and idempotent reruns.
4. Run the backend suite.

## Files

- `lego/backend/internal/usage/service_test.go`
- `lego/backend/internal/usage/service_acceptance_test.go` if database-backed proof adds value

## Acceptance criteria

- [ ] Tests fail against the pre-m11 behavior and pass with the fix.
- [ ] Healthy-meter independence and failed-meter ordering are asserted.
- [ ] `cd lego/backend && go test ./...` passes.

## Out of scope

- Synthetic tests that only assert implementation details without observable row/cursor behavior.
