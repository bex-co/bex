## Objective

Refactor all three App meter queries to report whether collection succeeded, then persist successful quantities including zero while leaving failed windows absent for retry.

## Context

- Prometheus empty-vector results and a Kubernetes Job list with no completed builds are successful zeroes.
- Missing `BEX_PROM_URL`, a failed Prometheus request, a nil Kubernetes client, or a failed Job list are unavailable sources, not measured zeroes.
- Store upserts are idempotent on the existing per-meter/window key.

## Steps

1. Return `(quantity, ok)` or an equivalent result from each App meter collection path.
2. Upsert each successful result even when zero.
3. Treat store-write failure as cursor failure.

## Files

- `lego/backend/internal/usage/service.go`
- `lego/backend/internal/usage/service_test.go`

## Acceptance criteria

- [ ] Successful zero instance, egress, and build windows each create a row.
- [ ] Source failure and store failure advance no meter cursor.
- [ ] Positive-quantity and idempotent-upsert behavior is unchanged.

## Out of scope

- Historical backfill beyond the existing 48-hour limit.
