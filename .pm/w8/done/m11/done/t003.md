## Objective

Replace the App-wide `instance_seconds` catch-up cursor with one contiguous cursor per meter so transient source failures are retried without blocking unrelated healthy meters.

## Context

- `store.LatestUsageWindow(resourceKind, serviceID, kind)` already accepts a meter kind.
- Datastore storage collection already demonstrates stop-on-failure cursor behavior.
- Both startup catch-up and each hourly pass must retry gaps; restart cannot be the only retry trigger.

## Steps

1. Add a per-App/per-meter catch-up helper bounded to 48 hours.
2. Process windows oldest-first and stop that meter on query or write failure.
3. Invoke the helper at startup and for each newly closed hourly window.

## Files

- `lego/backend/internal/usage/service.go`
- `lego/backend/internal/usage/service_test.go`

## Acceptance criteria

- [ ] Egress and build cursors no longer follow `instance_seconds`.
- [ ] A failed window is retried before that meter writes a newer window.
- [ ] Other meters continue through the same hour when one source fails.
- [ ] Reprocessing remains idempotent.

## Out of scope

- A catch-up horizon longer than 48 hours.
