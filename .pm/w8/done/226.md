# Native Node 14/16 builds carry a pnpm that refuses to run on them

Why: Render documents pnpm at build and runtime in every native Node environment, but bex installs pnpm 10.34.7's pure-JS entrypoint on every Node line (`lego/operator/internal/build/nativepnpm.go:28-57`), and that entrypoint exits 1 below Node 18.12 — so a native service selecting Node 14 or 16 has a `pnpm` on PATH that cannot run.

Severity: **minor** (legacy Node lines only; npm and Yarn work). Attribution: platform build (native Node tools layer, pre-existing since w8/m73 — not a regression from the w8/m91 common Bookworm base). Estimate: likely >1h (standalone artifact, launcher, node-gyp fallback, offline regression on both architectures) — promote on pickup. Filed 2026-10-31 from the w8/m91 t007 modern-Python/native-init source review.

## Evidence

- Read-only research and proposal: [m91 pnpm proposal](../blocked/m91/evidence/modern-python-init-source-20261031/pnpm/research/proposal.json) (official sources retained under `research/sources/`), plus a size preflight under `pnpm/size-preflight/`. No image reproduction was run.

## Proposed fix (from the proposal, not yet reviewed)

1. For app Node 14/16 only, install the official `@pnpm/exe` 10.34.7 Linux standalone (x64/arm64) under a private `/opt` prefix, checksum-verified and inventoried in `toolchain-freshness.json`; Node 18+ keeps the current JS package. Keep the default pnpm version — no silent downgrade to pnpm 7/8.
2. A legacy-only launcher sets `NODE` to the PATH node only when `NODE` is absent, then execs the unmodified standalone; no private node beside it.
3. Legacy native-addon fallback through the selected app npm's bundled node-gyp, preserving the Node 14 private Python 3.9 finder (`310558be3`).
4. Same helper on the primary and JS-companion paths.

## Acceptance

- A native Node 14 and a Node 16 service (primary) and one legacy Node companion each run `pnpm install` + a lifecycle native-addon build on amd64 and arm64; `pnpm --version` prints `10.34.7`; Node 18+ output is unchanged.

## Dedupe

- w8/m73 (pnpm supply), w8/m91 t007 (common base; does not fix this).

## Closure — 2026-10-31

**DONE.** Node 14/16 selections — primary (`rewriteNativePrimaryBase`) and JS companion (`nativeJSToolLines(image, line)`), in both the per-line and common-Bookworm paths — now get pnpm's official standalone 10.34.7 (`@pnpm/linux-x64|arm64`, sha256-checked per `dpkg --print-architecture`, no build ARG) under `/opt/bex/pnpm`, fronted by `/usr/local/bin/pnpm`/`pnpx` launchers. The launcher sets `NODE` to the app's node when unset (otherwise lifecycle `NODE`/`npm_node_execpath` named the pnpm binary) and prepends a `node-gyp` shim that runs the app npm's bundled node-gyp (the standalone's own copy is inside the executable). Node 18+ is byte-identical. Freshness inventory carries both tarballs; its validators accept npm scopes. ADR060 updated.

Verification: `TestNativePnpmFollowsTheSelectedNodeLine` (Node and Python runtimes × lines 14–24), full `GOWORK=off make test`, `make lint`. Real BuildKit builds of the generated lines on `node:14-bullseye` and `node:16-bookworm`, linux/arm64 and linux/amd64 (emulated): `pnpm --version` 10.34.7, lifecycle `NODE=/usr/local/bin/node`, a gypfile N-API addon builds and loads, `pnpx` reaches `pnpm dlx`. Python 3.13 + Node 16 companion: lifecycle `NODE` correct; a gypfile addon there fails in npm 8's own node-gyp 9.1 (`No module named 'distutils'` on Python ≥ 3.12) — the same failure `npm install` hits, not pnpm-specific, left as is. The m91 opt-in Node qualification harness (`check.js`/`check.py`) now accepts the standalone instead of expecting the old failure; it has not been executed against a common image (none is published yet).

**Follow-up 2026-11-01:** the standalone is now fetched like Hugo — per-architecture `ADD --checksum` stages (`nativeLegacyPnpmStages`, prepended before the final base for the primary and carried with a companion's `primaryStage`), unpacked by the pinned busybox and copied in — instead of a `curl` inside a `RUN`, so it needs no network inside the build (the m91 qualification builds run with `--network none`). Resolver-generated Dockerfiles rebuilt for real: Node 14 primary on arm64 and amd64 (pnpm 10.34.7, gypfile addon builds); Python 3.13 + Node 16 companion on arm64 (lifecycle `NODE` is the app node).
