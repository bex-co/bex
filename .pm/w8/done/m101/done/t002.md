## Closed — 2026-11-19 (loopx session)

Audited on main. The chain is the one w8/m94, m95 and m97 to m100 traced, and no commit since production's pin `dff52c596d13` touches `deploy/native-base`, `deploy/native-common`, `native.go`, `nativeresolve.go` or `nativebases.go`.

- **One recipe chain.** `nativeDockerfile` (`native.go`) has one caller, the native build Job's preparer. `cmd/native-resolve` ends with `applyNativeCommonBase` (`nativeresolve.go` → `nativebases.go`). So every native web service, private service, worker, cron job and static-site build starts from the common image, whatever the primary (Node, Python, Ruby, Elixir, Go, Rust) and its companions.
- **Phases.** Build, pre-deploy and runtime run one image: the pre-deploy Job runs the image the build produced. A static site's image is only its publish Job's extract source, so it gets `webpack` at build only, which is where a static site bundles.
- **Resolution.** `applyNativeCommonBase` re-copies only `/usr/local` from the selected primary, then sets the primary's environment, `PATH` included. The wrapper is `/usr/bin/webpack` and the packages live in `/opt/bex/native-node-tools`. No primary image ships `webpack` (sweep 422's Node 24 primary had none), so nothing shadows it.
- **Node.** The private Node is not the primary's. An app's `NODE_VERSION` still selects its own Node and npm, and webpack runs the same under every Node line (22, 24, 26) and under a primary with no Node (Python, Ruby and the others): the cohort bundles with no `node` on `PATH` (t005).
- **Precedence kept.** An npm script runs a project's own `node_modules/.bin/webpack` first (t005). On the Node primary's `PATH`, `/usr/local/bin` comes before `/usr/bin`, so a tenant's `npm install -g webpack webpack-cli` (the sweep 422 control) also wins. That order is read from the primary's environment and was not separately exercised.
- **Cache and writes.** The base is digest-pinned, and tenant source and environment changes do not touch its layers. `/opt/bex/native-node-tools` is root-owned and webpack never writes there: `--cache-type filesystem` keeps its cache in the project's `node_modules/.cache/webpack`, and the checks passed as uid 1000 on the replica (t005).
- **Exclusions.** Dockerfile, prebuilt-image and buildpack services never enter this recipe. A static site with no build command builds no native image.
- **Neighbors kept.** TypeScript shares the private Node and the lock and is unchanged. FFmpeg, Pandoc, SQLite, libvips, Ghostscript, jq, rsync, SWIG, the PostgreSQL clients, native-init and the companion and package-manager steps are unchanged. m101 changes no product code.
- **Exercised versus source-only.**
  - Production (t006): build and runtime, Node 24.22.3, both CLIs, on `4b809600…`.
  - Maintained cohort: the frozen m101 program on the Node primary at build and on a network-off runtime (`node-compute`, through `original-cases.py`); the Webpack checks at the Node compute build, its network-off runtime and the static build; and the `missing-webpack` omission on the Node primary (t005).
  - Families runs on the same digest: the other primaries, companions, native-init and static.
  - Not executed: a hosted pre-deploy run (Free refuses `preDeployCommand`, as Render does) and ARM64 (D3).
