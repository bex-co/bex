## Closed — 2026-11-19 (loopx session)

Every `native-common-image.yml` utility cohort (`TestNativeUtilityGeneratedImages`) runs these real-image checks on the image it publishes:

- **The original program** (already maintained). `node-compute` runs the frozen m101 build on the Node 24 primary through `original-cases.py`: the before proof, the original `webpack ./qa-webpack-entry.mjs --mode production --target node --output-path ./dist --output-filename bundle.cjs --json`, and the emitted bundle's `build` step, which the frozen `valid_after` checks. Three HTTP requests on a `--network none` runtime then run the bundle again, call `webpack` and pass the frozen oracle.
- **New Webpack checks** in `utility-check.py`, at the `node-compute` build and network-off runtime and at the `node-static` build. They replace the older two-line bundle and unresolved-import check, which they cover.
  - m101's own sources through the original argv, outside the original program. The bundle must be the exact bytes production emitted (`8fd8eb19…`): one strict IIFE that requires `node:http`, with no `import` and no module path left. The statistics must report `5.112.2`, no errors or warnings and the one asset. The bundle's own `build` step must report the input rows and a result equal to labels, total and sorted quantities computed independently in Python, and the same compiler statistics and bundle identity.
  - Exit statuses: 1 for an unresolved import, whose one error names `./does-not-exist.mjs` and whose output directory is never created; 2 for an unknown option, named on stderr.
  - A bare `webpack` reads `webpack.config.mjs`, whose exported function receives `--env name=from-env` and names the output it writes; Node runs it and prints Unicode and a space intact.
  - Code splitting: a dynamic `import()` becomes a second chunk beside `main.cjs`, the bundled JSON module carries the Unicode rows, and Node's result equals the independent one. In a project with a `package.json`, `--cache-type filesystem` writes `node_modules/.cache/webpack`, and the second build reports every module cached.
  - `--devtool source-map` writes a map whose `sources` name both authored modules, and the bundle links it.
  - The private Node: with `PATH=/usr/bin:/bin`, where no `node` exists, `webpack` still bundles and reports 5.112.2. A project's stub `node_modules/.bin/webpack` wins inside `npm run`, while a bare `webpack` is still `/usr/bin/webpack`.
  - No dev server: `webpack serve` with stdin closed names `webpack-dev-server` as missing and returns, leaving the project's `package.json` and `node_modules` unchanged.
- **New omission control.** `missing-webpack` removes only `/usr/bin/webpack`. It proves `command -v webpack` fails while the private Node still runs the package's own `bin/webpack.js` and `webpack-cli` remains. The original m101 build must then fail with `webpack: command not found` after its ready line, the sweep 422 failure.
- **How this was checked before shipping.** The host is arm64 and the adopted image is amd64-only, so the generated-image gate cannot run here. A local replica built the image's `node-tools` stage from the same lock on the same pinned `node:24-bookworm` digest (webpack 5.112.2, webpack-cli 7.2.3, Node 24.22.3):
  - the new block passed offline as uid 1000 and as root, and emitted the same `8fd8eb19…` bytes production did on amd64;
  - each of 14 source mutations failed the assertion it targets: `--target web`, `--mode development`, reversed sort, a wrong total, an import that resolves, a known option, a renamed `--env` value, a static import instead of the dynamic one, `--cache-type memory`, no `package.json` (the cache moves to `.cache/webpack`), no `--devtool`, `node` on the bare `PATH`, an npm script calling `/usr/bin/webpack`, and a `webpack-dev-server` directory already present;
  - two image mutations failed too: a wrapper that runs `node` from `PATH` failed the bare-`PATH` check, and deleting `webpack-cli` failed the first bundle. On stock `node:24-bookworm` the block fails at its first `webpack`;
  - the original m101 build and its three network-off runtime requests passed through `original-cases.py`, and on stock `node:24-bookworm` the build failed with `webpack: command not found`;
  - after the exact `missing-webpack` command, the original build printed `QA_WEBPACK_BEFORE` with `ENOENT` and failed with `webpack: command not found`. A variant that also deleted `webpack-cli` stopped in the removal layer before its ready line, at the CLI's install question.
  - The push of this change re-runs the amd64 utility cohort through `native-common-image.yml`; that run is the amd64 proof.
- **Unit and package checks.** `gofmt`, `go test ./internal/build/` (`TestNativeUtilityOmissionsHaveRemovalLayers`, `TestNativeOriginalReplayHTTPOracles`, `TestNativeUtilityOmissionEvidenceRequiresActualReadyStdout`), `golangci-lint` over `internal/build` and the operator's `make test`.
