## Closed — 2026-11-19 (loopx session)

The adopted common base (w8/m91 t007/t008) is the supplier. The `node-tools` stage of `deploy/native-common/Dockerfile` runs `npm ci --ignore-scripts` on `deploy/native-base/package.json` and `package-lock.json`, an integrity-locked graph, into `/opt/bex/native-node-tools`, and copies that stage's Node there. `/usr/bin/webpack` is a two-line wrapper that execs the package's `bin/webpack.js` on that Node. The SPDX attestation of `sha256:4b809600…` (production's `nativeCommonBase` at pin `dff52c596d13`), fetched again from the registry at 16:02Z, lists `webpack` `5.112.2`, `webpack-cli` `7.2.3` with its own `commander` `14.0.3`, and the private `node` `24.22.3`. All 102 packages the lock installs on linux/amd64 are in it at their locked versions.

- **The reviewed release.** `webpack` 5.112.2 (published 2026-10-23) is npm's `latest` on 2026-11-19. `webpack-cli` 7.2.3 was `latest` when the lock was cut on 2026-10-29; 7.3.0 and 7.3.1 followed on 2026-10-30. The lock's `sha512` integrity of both equals the registry's. The CLI's peer range `webpack ^5.101.0` holds, and its `node >=20.9.0` engine holds on the private Node. The sweep 422 control's core 5.112.0 was not adopted: the reviewed core is 5.112.2. The CLI's optional peers (`webpack-dev-server`, `webpack-bundle-analyzer`, `json5`, `toml`, `js-yaml`) are not installed.
- **What travels together.** The wrapper, the private Node, `webpack`, `webpack-cli` and the whole dependency closure, including the minimizer (`minimizer-webpack-plugin` 5.13.1 with `terser` 5.51.2), `enhanced-resolve`, `watchpack`, the `@webassemblyjs` packages and the `browserslist` data. `--ignore-scripts` runs no install script, nothing is downloaded at build or run time, and no donor root filesystem is copied. Copying only `webpack/bin/webpack.js` would not do: without `webpack-cli` it asks to install it (t005's image mutation).
- **Phases.** `/usr/bin` and `/opt/bex` are outside the primary's `/usr/local` copy, so `webpack` is present before source and authored commands at build, pre-deploy and runtime (t002). Both production builds found it before compiling, and every runtime request ran `webpack --version` with status 0 (t006).
- **Environment.** bex sets no webpack variable. The wrapper runs its own Node, so the app's `NODE_VERSION`, `node` and `npm` are untouched, and a project's own webpack still runs first from an npm script (t005).
- **Identity.** A changed lock or Node is a new image digest, which a families run re-qualifies. The image's SPDX attestation lists every package and the ADR060 D7 table records the versions; `toolchain-freshness.json` tracks the image digest, not the npm lock. Every `native-common-image.yml` run's utility cohort bundles with Webpack and rejects an unresolved import on the image it publishes (t005).
