# Free Postgres never expires and never reports `expiresAt`, although ADR009 specifies a 30-day TTL

Why: ADR009's MVP plan table says the free Postgres plan has a “30-day TTL (a control-plane sweeper — else ‘free forever’ eats the cluster, which is why Render expires them)”. Render's API exposes the expiry as `expiresAt` (“The time at which the database will expire. Applies to free tier databases only.”). Bex has neither the sweeper nor the field, so either the documented capacity guard is missing or the ADR is stale. A user cannot tell which.

**Severity:** minor (documentation/implementation drift; no user data at risk today). **Attribution:** server and docs. **Estimate:** 20m if the ADR is corrected; a milestone if expiry is implemented. **Source:** `/qa-find-bugs-cli` sweep 1247, 2026-10-20 ([evidence](evidence/cli-sweep1247/README.md)). **Decision needed (user):** implement Render's expiry, or record “free Postgres does not expire on Bex (bounded by the 1-database free workspace limit)” as a deliberate divergence.

## Observed

- `GET /v1/postgres/dpg-db9r654flioc739mcpbg` (free, created 2026-10-17, read-only baseline) → `plan: free`, `status: available`, **no `expiresAt`**. The same holds for a free database created 2026-10-07 in another accessible workspace, and for the free PG18 fixture `dpg-dbbg9e19a20c7385raa0` created by `bex pg create --plan free` in sweep 1230.
- `rg -i 'expiresAt|free.*(ttl|expir|sweep)'` over `lego/backend/internal/postgres`, `lego/backend/internal/store` and `lego/operator` finds only logical-export expiry (`Database.spec.exports`) and the App idle TTL. No free-database TTL, sweeper or `expiresAt` serializer exists.
- Render's schema carries the field: pinned `pkg/client/types_gen.go:2624–2625` and `2674–2675` (`ExpiresAt *time.Time json:"expiresAt,omitempty"` on the Postgres and PostgresDetail objects). The pinned CLI does not display it.
- The free workspace already caps Postgres at one database (`400 WORKSPACE_RESOURCE_LIMIT: workspace is limited to 1 Postgres database …`, sweep 1230). That bounds the “free forever eats the cluster” risk ADR009 cites.

## Options

1. **Record the divergence (recommended):** correct ADR009:148 and add an ADR018 Postgres-row note that free databases do not expire on Bex, bounded by the per-workspace free limit. Keep `expiresAt` omitted, which is honest because nothing expires.
2. **Implement Render's lifecycle:** a control-plane sweeper (30-day expiry with a deletion grace period and owner notifications, as Render does), plus `expiresAt` on REST, GraphQL, MCP and the dashboard. This deletes user data automatically, so it needs an explicit product decision and its own milestone.

## Dedupe

`rg -i 'free postgres.*(expir|30)|expiresAt'` across `.pm` (excluding evidence) matches only registry-credential and export `expiresAt` fields. No item tracks the free-database TTL.

## Status — BLOCKED (2026-10-20)

Needs the user to decide: implement Render's free-database expiry (a sweeper plus `expiresAt` on REST/GraphQL/MCP/dashboard; a milestone), or record "free Postgres does not expire on Bex (bounded by the one-database free workspace limit)" as a deliberate divergence in ADR009/ADR018 (about 20 minutes). Both are plausible. The note found no sweeper and no `expiresAt` in the code (`rg` over `lego/backend/internal/postgres`, `store`, `lego/operator`), so the premise holds.
