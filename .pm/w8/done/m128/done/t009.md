## Fix — 2026-10-29

A production check on 2026-10-29 found REST, MCP and both CLIs read `dockerContext` back correctly, and a REST PATCH changed it in place. Two gaps remained:

1. GraphQL `Service` had no `dockerContext` field (`Cannot query field "dockerContext" on type "Service"`); only `setDockerContext` existed. `createService` took no `dockerContext` argument either.
2. The dashboard service Settings → Build card had no Docker Build Context Directory field, which Render's settings page has.

Fixed:

- **GraphQL** (`lego/backend/internal/apps/graphql.go`): `Service.dockerContext` reads `AppView.DockerContext`, the value REST reports (`"."` when unset on a Dockerfile build, empty for other builds). `createService(dockerContext:)` maps onto `CreateRequest.DockerContext`, so it shares REST/MCP's translation and validation: `../../etc` is refused with REST's `dockerContext must be a relative path with no '..' components`.
- **Dashboard**: the Build card shows an editable Docker Build Context Directory row for Dockerfile builds, beside Dockerfile Path. It uses the same Edit/confirm/Save pattern, is wired to `setDockerContext` (`use-docker-context.ts`) and reads `dockerContext` from the `server` query. The copy is in en and zh. `definitions.ts` was hand-spliced, and offline codegen (`TestDumpGraphQLSchema` + `SCHEMA_JSON`) produced exactly the spliced hunks. The Build-card skeleton for a Dockerfile build reserves the new row: 8 rows, `h-[930px] sm:h-[778px]`. The row's height was measured in Chromium against `yarn dev:local` at 390/640/1024/1440 and matches Dockerfile Path's at every width. The `local-bex` stub serves the field and the mutation.
- **Tests**: `TestGraphQLDockerContextMatchesREST` (create with `.`/unset/`ctx` under `rootDir: example-pserv`, then GraphQL `service { dockerContext }` equals REST `envSpecificDetails.dockerContext`; GraphQL and REST both refuse `../../etc`), plus `gqlCreateRules.dockerContext` in the create-transport guard. Dashboard: hook, Build card, Settings route, `toServiceView` mapping and skeleton tests.

**Hosted re-check pending deploy:** after the release pipeline deploys bex-api and the dashboard, query GraphQL `service(id) { dockerContext }` on a fresh Docker fixture, check that the Settings field reads and edits it, and delete the fixture by ID with a 404 proof.
