# Prebuilt images from common public registries (cgr.dev, registry.gitlab.com, nvcr.io, docker.elastic.co, lscr.io, *.azurecr.io) are refused as "not trusted"

Why: Render deploys an image from any registry, public or with credentials. Bex accepts only a fixed list of hosts (Docker Hub, GHCR, Quay, GCR/Artifact Registry, registry.k8s.io, public ECR, MCR). Render's own `render-examples/minio` uses `cgr.dev/chainguard/minio` and fails validation on bex. Every GitLab-hosted project's image, Elastic's official images, NVIDIA's images and linuxserver.io images are refused the same way, with no path to allow them (no per-workspace or per-credential exception). The guard exists for a real reason: kubelet pulls run on the node network, so private and reserved addresses must stay blocked. An allowlist of names is a coarse proxy for that.

**Severity:** minor (decision needed; blocks common public images). **Attribution:** server policy (`store.ValidateImage`). **Estimate:** 60–120m depending on the option. **Source:** `/qa-find-bugs-cli` sweep 1284, 2026-10-21 ([evidence](../evidence/cli-sweep1284/README.md)).

## Reproduction

Production `https://api.bex.co/v1/`, pin `a3f66521f93d`, HEAD-built pinned CLI. `bex blueprints validate` on a free image web service with `image.url`:

| Image | Result |
| --- | --- |
| `cgr.dev/chainguard/nginx:latest` | `image registry host "cgr.dev" is not trusted` |
| `registry.gitlab.com/gitlab-org/gitlab-runner:latest` | `… "registry.gitlab.com" is not trusted` |
| `nvcr.io/nvidia/cuda:12.4.1-base-ubuntu22.04` | `… "nvcr.io" is not trusted` |
| `docker.elastic.co/elasticsearch/elasticsearch:8.15.0` | `… "docker.elastic.co" is not trusted` |
| `myregistry.azurecr.io/app:1` | `… "myregistry.azurecr.io" is not trusted` |
| `lscr.io/linuxserver/nginx:latest` | `… "lscr.io" is not trusted` |

`render-examples/minio/render.yaml` (`image.url: cgr.dev/chainguard/minio`) → the same refusal (sweep 1284 corpus re-run).

## Expected

Render: "You can deploy public images from any registry Render can reach", and private images "from the following registries: Docker Hub, GitHub Container Registry, GitLab Container Registry, Google Artifact Registry, AWS Elastic Container Registry (ECR)" ([deploying an image](https://render.com/docs/deploying-an-image)). Target: at minimum, add the widely used public registries above (and, with a registry credential, Render's private set: GitLab `registry.gitlab.com` and AWS ECR `*.dkr.ecr.*.amazonaws.com`; Azure is not on Render's private list). Better: replace the name allowlist with the property it stands for. Refuse literal private/reserved IPs as now, and enforce "no private destinations" at pull time (for example, kubelet/containerd pulls via an egress proxy or a node-level policy that blocks private ranges), which also closes the DNS-rebinding gap the comment in `image.go` notes.

## Root cause

`lego/backend/internal/store/image.go:127–136` (`trustedImageRegistry`) is a fixed `switch` of hostnames plus `*.pkg.dev`. ADR018:69 says only that "the existing registry allowlist is preserved". Neither the host list nor the trade-off is recorded as a Render divergence.

## Fix (decision first)

1. **Expand the list.** Add `cgr.dev`, `registry.gitlab.com`, `nvcr.io`, `docker.elastic.co` and `lscr.io`, plus the `*.azurecr.io` and ECR private patterns when a registry credential is attached. Small and safe; it keeps the model.
2. **Policy by destination.** Accept any public hostname and block private destinations at pull time. A larger change that removes the list.

Either way, record the divergence and the current list in ADR018's image row, and make the refusal name the escape hatch, if one exists.

## Acceptance

- `ValidateImage` table tests for the hosts above under the chosen option. Private IPs and `localhost` stay refused.
- Live after deploy: `render-examples/minio/render.yaml` passes the registry check (its paid plan and disk rules aside), and a free image web service from `cgr.dev/chainguard/nginx` deploys. Delete by ID with a 404 proof.
