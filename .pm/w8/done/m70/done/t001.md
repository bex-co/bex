## Done 2026-10-15

`ApplyBlueprintServiceSpec` (`lego/backend/internal/apps/blueprint_plan.go`) now applies source intent as one coupled transition, using the source setter (`applySourceChange`/`resolveSourcePatch`) as the reference.

- **Declared new repo** (`applyBlueprintRepo`, compared with `core.CanonicalRepo` so a respelling is the same repo): clears a former prebuilt image or rollback override, the old origin's clone token and an image-only registry credential, and fills an untracked branch from the declared default. It runs before the branch and `registryCredential` appliers, so their declared values still win. The same repo keeps a rollback's image override.
- **Repo inherited from the Blueprint:** on an image-backed service, it switches the same way.
- **Declared image:** clears the repo, so the old repo does not build again on the next push. Branch, rootDir and commands stay for a switch back.
- **Native or buildpack → image, no command declared:** the native start command baked into the old image is dropped, rather than run as the image's `/bin/sh` override. A Dockerfile build's command already is that override and stays (w4/m202).
- **Strategy:** on a source-kind switch, the declared runtime/builder is applied even when the stale spelling resolves to the same build. The declared kind decides, so per-field plan probes agree.

Validation is not relaxed, and Repo+Image is not banned globally (rollback overrides still use it).
