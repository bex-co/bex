## Closed — 2026-11-19 (loopx session)

Every `native-common-image.yml` utility cohort (`TestNativeUtilityGeneratedImages`) runs these real-image checks on the image it publishes:

- **The original program** (already maintained). `node-compute` runs the frozen m99 build on the Node 24 primary through `original-cases.py`: the before proof, the original `tsc --strict --noEmitOnError --module NodeNext --target ES2022 --outDir dist qa-ts-app.cts`, and the emitted `build` step, which the frozen `valid_after` checks. Three HTTP requests on a `--network none` runtime then call `tsc` again and pass the frozen oracle.
- **New TypeScript checks** in `utility-check.py`, at the `node-compute` build and network-off runtime and at the `node-static` build. They replace the older three-line strict compile and type-error check, which they cover.
  - m99's own source through its original argv, outside the original program. The emit must be the exact bytes production compiled (`af1acfde…`): `"use strict"`, the enum lowered, no interface left. The emitted program's result must equal labels, total and tones computed independently in Python, and it must report `Version 7.0.2`.
  - Exit statuses: 1 with `TS2322` and no output directory under `--noEmitOnError`; 2 with the `.cjs` emitted when that flag is absent; 1 with `TS5023` for an unknown option.
  - The packaged standard library: `Array.prototype.at` checks under `--target ES2022` and fails with `TS2550` naming `es2022` under `--lib es2020`.
  - Project and build modes: a bare `tsc` compiles from `tsconfig.json` and the output prints Unicode and a space intact; `--build` writes `tsconfig.tsbuildinfo`, and a second `--build --verbose` reports the project up to date.
  - ES modules: `.mts` sources compile to `.mjs` with `.d.mts` declarations and a source map whose `sources` names the input, and Node runs the result.
  - The private Node: with `PATH=/usr/bin:/bin`, where no `node` exists, `tsc --version` still answers. A project's stub `node_modules/.bin/tsc` wins inside `npm run`, while a bare `tsc` in the same directory is still the platform's 7.0.2.
- **New omission control.** `missing-typescript` removes only `/usr/bin/tsc`. It proves `command -v tsc` fails while the private Node runs the package's own `bin/tsc` and the platform package's `lib.es2022.d.ts` remains. The original m99 build must then fail with `tsc: command not found` after its ready line, the sweep 420 failure.
- **How this was checked before shipping.** The host is arm64 and the adopted image is amd64-only, so the generated-image gate cannot run here. A local replica built the image's `node-tools` stage from the same lock on the same pinned `node:24-bookworm` digest (TypeScript 7.0.2, `@typescript/typescript-linux-arm64`, Node 24.22.3):
  - the new block passed offline as uid 1000 and as root, and compiled the same `af1acfde…` bytes production did on amd64;
  - each of 13 source mutations failed the assertion it targets: ES2015 target, swapped tones, a wrong total, `--noEmitOnError` dropped or added, a known option, `--lib es2022`, a different `outDir`, no first `--build`, no `--declaration`, no `--sourceMap`, `node` on the bare `PATH`, and the npm script calling `/usr/bin/tsc`;
  - two image mutations failed too: a wrapper that runs `node` from `PATH` failed the bare-`PATH` check, and deleting the ES2022 declarations failed the first compile. On stock `node:24-bookworm` the block fails at its first `tsc`;
  - the original m99 build and its three network-off runtime requests passed through `original-cases.py`, and on stock `node:24-bookworm` the build failed with `tsc: command not found`;
  - after the exact `missing-typescript` command, the original build printed `QA_TS_BEFORE` with `ENOENT` and failed with `tsc: command not found`. A variant that also deleted the private Node stopped in the removal layer before its ready line.
  - The push of this change re-runs the amd64 utility cohort through `native-common-image.yml`; that run is the amd64 proof.
- **Unit and package checks.** `gofmt`, `go test ./internal/build/` (`TestNativeUtilityOmissionsHaveRemovalLayers`, `TestNativeOriginalReplayHTTPOracles`, `TestNativeUtilityOmissionEvidenceRequiresActualReadyStdout`) and the operator's `make test`.
- **Bounds.** ARM64 is out of scope (D3). Pre-deploy runs the same image, and there was no hosted pre-deploy run (Free refuses it). Other primaries rely on the families runs. No language server, watch mode or JavaScript compiler API is checked.
