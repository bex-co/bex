## Closed — 2026-11-19 (loopx session)

Audited on main. The chain is the one w8/m94, m95, m97 and m98 traced, and no commit since production's pin `dff52c596d13` touches `deploy/native-base`, `deploy/native-common`, `native.go` or `nativebases.go`.

- **One recipe chain.** `nativeDockerfile` (`native.go`) has one caller, the native build Job's preparer. `cmd/native-resolve` ends with `applyNativeCommonBase` (`nativeresolve.go` → `nativebases.go`). So every native web service, private service, worker, cron job and static-site build starts from the common image, whatever the primary (Node, Python, Ruby, Elixir, Go, Rust) and its companions.
- **Phases.** Build, pre-deploy and runtime run one image: the pre-deploy Job runs the image the build produced. A static site's image is only its publish Job's extract source, so it gets `tsc` at build only, which is all a static site has.
- **Resolution.** `applyNativeCommonBase` re-copies only `/usr/local` from the selected primary, then sets the primary's environment, `PATH` included. The wrapper is `/usr/bin/tsc` and the compiler lives in `/opt/bex/native-node-tools`. No primary image ships `tsc` (the sweep 420 failure showed the Node 24 primary had none), so nothing shadows it.
- **Node.** The private Node is not the primary's. An app's `NODE_VERSION` still selects its own Node and npm, and the compiler runs the same under every Node line and under a primary with no Node (Python, Ruby and the others).
- **Precedence kept.** An npm script runs a project's own `node_modules/.bin/tsc` first (t005). On the Node primary's `PATH`, `/usr/local/bin` comes before `/usr/bin`, so a tenant's `npm install -g typescript@<version>` (the sweep 420 control) also wins. That order is read from the primary's environment and was not separately exercised.
- **Cache.** The base is digest-pinned, and tenant source and environment changes do not touch its layers. `tsc --build` and `--incremental` write `.tsbuildinfo` inside the project. The compiler keeps nothing under `$XDG_CACHE_HOME`.
- **Exclusions.** Dockerfile, prebuilt-image and buildpack services never enter this recipe. A static site with no build command builds no native image.
- **Neighbors kept.** Webpack shares the private Node and is unchanged. FFmpeg, Pandoc, SQLite, libvips, Ghostscript, jq, rsync, the PostgreSQL clients, native-init and the companion and package-manager steps are unchanged. m99 changes no product code.
- **Exercised versus source-only.**
  - Production (t006): build and runtime, Node 24.22.3, both CLIs, on `4b809600…`.
  - Maintained cohort: the frozen m99 program on the Node primary at build and on a network-off runtime (`node-compute`, through `original-cases.py`); the TypeScript checks at the Node compute build, its network-off runtime and the static build; and the `missing-typescript` omission on the Node primary (t005).
  - Families runs on the same digest: the other primaries, companions, native-init and static.
  - Not executed: a hosted pre-deploy run (Free refuses `preDeployCommand`, as Render does) and ARM64 (D3).
