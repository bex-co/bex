# `bex logs` panics (exit 2) when the CLI has no usable credential — upstream defect, grade it in the checklist

Why: a Bex user whose session expires gets a raw Go stack trace from `bex logs` instead of "run `bex login`", and the compatibility checklist currently grades every `logs` row `[x]` with no record of this crash — so the ledger overstates the surface and the next pin bump has nothing to re-test against.

Source: live CLI QA sweep 2026-09-15 (`/qa-find-bugs-cli`), `bex` v0.2.1 / upstream pin v2.27.0 (`a764810a768202704e7206eb7b87a47211fcd98e`) against `https://api.bex.co/v1/`.

## Finding

Attribution: **upstream CLI, not bex.** Same class as the already-recorded `skills list` / `skills update` non-TTY panic. No bex request is ever sent — the crash is entirely client-side, before any HTTP call.

`bex logs` panics with a Go stack trace and exits **2** whenever the CLI has no usable stored credential. Every sibling command returns a clean error and exits 1.

Repro (isolated config, no auth):

```sh
BEX_CLI_CONFIG_PATH=$TMP/fresh.yaml BEX_HOST=https://api.bex.co/v1/ \
  BEX_NO_UPDATE_NOTIFIER=1 bex logs -r srv-abc123 -o json
# stderr line 1: panic: run `render login` to authenticate
# exit 2
```

Identical for `-o json`, `-o yaml`, `-o text`, and for a corrupt (unparseable) `cli.yaml`.

Controls in the same config dir, all clean `Error: …` + exit 1: `bex services`, `bex deploys list`, `bex restart`, `bex whoami`, `bex workspaces`, `bex projects`.

## Root cause (pinned upstream v2.27.0)

- `cmd/logs.go:46` calls `deps.LogLoader()` inside `RunE`, before auth is established.
- `pkg/dependencies/dependencies.go:294` (`LogLoader`) → `APIConfig()` at `dependencies.go:281`, which does `cfg, err := config.DefaultAPIConfig(); if err != nil { panic(err) }`.
- `DefaultAPIConfig` (`pkg/config/config.go:49-68`) returns `ErrLogin` when there is no API key and no loadable stored config.

So any absent, expired-beyond-refresh, or corrupt `cli.yaml` turns `bex logs` into a crash.
