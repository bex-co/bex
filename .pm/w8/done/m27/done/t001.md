## Objective

Replace the one-bit `bex.api` contract with one authoritative, fail-closed capability model for third-party human OAuth tokens while naming the exact compatibility boundary for platform clients.

## Context

- `lego/backend/internal/api/auth.go` defines `DefaultAPIScope` and currently treats `bex.api` as all control-plane access.
- `lego/backend/internal/core/base.go` defines the complete `RelCan…` vocabulary consumed by feature services.
- `docs/ADR012-auth.md` and `docs/ADR069-security-review-round14.md` explicitly defer operation-level scopes after the round-14 coarse backstop.
- Kratos sessions and machine `client_credentials` API keys do not derive authority from human OAuth consent and must not be retrofitted into this capability class.

## Steps

1. Define fixed `bex.read`, `bex.write`, and `bex.sensitive` constants and one relation-to-required-capability registry in the shared authorization layer.
2. Classify every `RelCan…` relation, including `Can` response-shaping probes, and add a completeness guard so a new or unknown relation cannot silently inherit broad OAuth authority.
3. Encode the rollout rule: granular scopes are mandatory for non-platform human OAuth clients; legacy `bex.api` is compatibility-only for Hydra clients carrying the existing `bex.co/platform-client` marker; sessions and machine keys remain scope-exempt by credential class.
4. Update the auth ADRs and configuration comments so consent, introspection, and authorization use the same exact vocabulary and no arbitrary deployment override can create a second semantic matrix.

## Acceptance criteria

- [ ] Every current `RelCan…` constant maps explicitly to exactly one of the three capabilities.
- [ ] Unknown relations and near-match scope strings fail closed for a third-party human token.
- [ ] `bex.api` cannot grant a non-platform client umbrella authority.
- [ ] Session and machine-key authorization remains byte-for-byte equivalent at the scope gate.
- [ ] The compatibility policy names a removal condition and does not rely on a first-party-dashboard OAuth conversion.

## Out of scope

- Per-resource or per-service-instance OAuth grants.
- Changes to Render's workspace roles or the OpenFGA model.
- A general-purpose custom scope registry.
