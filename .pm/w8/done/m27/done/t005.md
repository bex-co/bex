## Objective

Make clients request, humans understand, and operators inspect the same granular capability vocabulary that the API enforces, while preserving the current official CLI and mobile rollout path.

## Context

- `dashboard/src/common/server-fn/hydra-consent.ts` intersects requested scopes with a recognized vocabulary and controls both headless and human consent decisions.
- `dashboard/src/features/auth/pages/consent-page/` renders requested scopes; `dashboard/src/features/connected-agents/` lists remembered grants.
- `lego/backend/internal/api/server.go` publishes RFC 9728 protected-resource metadata.
- `scripts/auth-bootstrap-client.sh` provisions platform-marked Render CLI and mobile clients; `scripts/auth-oauth21-e2e.sh` exercises the real consent/introspection flow.

## Steps

1. Advertise all three granular scopes in deterministic RFC 9728 metadata and update consent's closed recognized vocabulary.
2. Refuse a non-platform API-audience human grant that lacks an applicable granular capability, drop unknown scopes, and keep trusted/skip consent handling subject to the same API backstop.
3. Add plain-language, localized descriptions and risk distinctions for read, write, and sensitive access on consent and Connected Agents while preserving exact raw scope values for technical inspection.
4. Update platform-client bootstrap and OAuth E2E fixtures so clients that support granular requests use them; retain and document the platform-marker compatibility path for the unmodified official Render CLI launcher and current mobile release until their request vocabulary can migrate.
5. Update deployment examples and ADR rollout notes so dashboard and bex-api configuration cannot advertise different scope sets.

## Acceptance criteria

- [ ] Discovery advertises `bex.read`, `bex.write`, and `bex.sensitive` in one stable order.
- [ ] Consent never grants an unknown scope or a third-party `bex.api` umbrella grant.
- [ ] The human can distinguish ordinary read, mutation, and sensitive-value access before approving and later in Connected Agents.
- [ ] Revocation semantics remain unchanged and no token enters browser-readable storage.
- [ ] The unmodified official Render CLI and existing platform-marked mobile client retain their current effective behavior during rollout.
- [ ] The executable OAuth flow proves granular approval, insufficient-scope refusal, legacy third-party refusal, and platform compatibility.

## Out of scope

- Making the first-party dashboard an OAuth client.
- A custom Hydra login provider or OAuth-client administration console.
- Forking or patching the upstream Render CLI.
