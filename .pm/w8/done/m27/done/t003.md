## Objective

Require both the caller's OAuth capability and their existing OpenFGA relation in the one `core.Base` path shared by REST, GraphQL, MCP, and response-shaping probes.

## Context

- `core.Base.Authorize`, `AuthorizeOn`, typed resource helpers, and fresh-check variants converge on the authorization helpers in `lego/backend/internal/core/base.go`.
- `core.Base.Can` is a non-audited response-shaping probe used to omit sensitive fields and must apply the same scope matrix.
- `lego/backend/internal/core/errors.go`, `http.go`, and the GraphQL/MCP adapters already carry coded domain errors across transports.
- Existing OpenFGA authorization remains necessary: OAuth scopes narrow a user's authority; they never grant a relation the user lacks.

## Steps

1. Add the capability check before OpenFGA at the shared authorization seam and make every standard, typed-resource, `Can`, and fresh authorization path consume it.
2. Return one stable insufficient-scope domain error carrying the required capability, with consistent safe mappings for REST, GraphQL, and MCP and without revealing whether an inaccessible target exists.
3. Feed a capability denial through the existing denial-audit path exactly once; do not call OpenFGA after the scope has already failed.
4. Preserve the compatibility/exemption rules from t001 and keep `AuthorizeMintClass`'s platform-client proof as an additional credential-mint restriction rather than treating a scope as proof of client trust.

## Acceptance criteria

- [ ] `bex.read` permits ordinary reads but cannot pass a mutation or sensitive-read gate.
- [ ] `bex.write` permits mapped mutations but does not reveal a field guarded by `RelCanViewSensitive`.
- [ ] `bex.sensitive` is required for every `RelCanViewSensitive` gate, with OpenFGA still authoritative afterward.
- [ ] `Can` and every `Authorize*`/fresh variant enforce the same registry, and a completeness test catches a new unmapped relation.
- [ ] REST, GraphQL, and MCP report the same machine-readable insufficient-scope code and required capability.
- [ ] A capability denial produces one denied audit decision and no downstream OpenFGA check or side effect.

## Out of scope

- OAuth scopes that grant more authority than OpenFGA.
- Adapter-specific authorization branches.
- Changing which workspace role owns a relation.
