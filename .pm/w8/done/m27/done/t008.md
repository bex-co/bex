## Objective

Lock the granular OAuth matrix, compatibility boundary, audit provenance, consent/discovery contract, and cross-surface error behavior with meaningful positive and negative tests.

## Context

- A scope regression can either over-grant a third-party client or silently break the official CLI/mobile platform path; both are release-blocking.
- The database projection needs real Postgres coverage because array/null/migration behavior is not proven by a mock store.
- Existing guard sweeps and OAuth E2E scripts provide stronger evidence than adapter snapshots.

## Steps

1. Add exhaustive table tests covering every `RelCan…` relation for granular, missing, near-match, legacy third-party, platform legacy, session, and machine identities; assert OpenFGA is still required and is not called after scope denial.
2. Cover introspection normalization/cache equivalence, accepted-audience binding, coded REST/GraphQL/MCP errors, and `Can`-based sensitive-field omission.
3. Add real-Postgres migration/store tests for new/old/null audit rows, bounds, pagination, and retention, plus REST/GraphQL/dashboard projection tests.
4. Cover consent, discovery, localization, Connected Agents, and executable OAuth flows, then run backend, dashboard, CLI, and Markdown CI-equivalent checks affected by the milestone.
