# A Key Value or Postgres live tail goes silent after the store restarts

Why: `bex logs --tail` on a datastore stops showing anything once its pod is replaced (a persistence change, a plan change, a crash). The stream stays open and looks healthy while the restarted store's logs never arrive. That is exactly when a customer is watching.

**Severity:** major (a silent, misleading dead stream). **Attribution:** server (bex-api logs service). **Estimate:** ~45m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `18cb`, 2026-11-08.

## Root cause

`lego/backend/internal/logs/service.go:1155-1170` (`followPods` → `attach`) keys follow state by `pod.Name` and re-attaches an ended follow only when `containerRestarts` grew (`restarted := f.opened && restarts > f.restarts`) or kubelet refused it. A Valkey store's StatefulSet replaces its pod under the **same name** with a new container whose restart count is 0. The old follow ended (`active=false`, `opened=true`, `restarts=0`), so `restarted` is false and `refused` is false, and the new pod is skipped on every relist (`datastoreTarget` relists every `5 × DefaultTailRelistInterval` = 10 s, `service.go:806`). CNPG Postgres instance pods also keep stable names (`<cluster>-1`), and the Postgres case was reproduced live (below).

## Fix

Key `follows` by pod UID (or store the UID in `podFollow` and treat a UID change as a new pod), keeping the restart-count rule for in-place container restarts and the once-per-life replay rule for finished cron pods. Apply it in the shared `followPods`, so App, build, datastore and multi-resource tails all use it.

## Acceptance

- Unit: a fake pod list that replaces `kv-0` (same name, new UID, restarts 0) after the first follow ends → the tail attaches to the new pod and emits its lines. A finished cron pod is still replayed only once.
- Live: free Key Value, `--tail`, trigger `--persistence-mode` change, then the tail shows the new pod's `Ready to accept connections` within 15 s of it appearing in history. The same check for a free Postgres `suspend`/`resume` (reproduced above).
- Render: Render's `GET /v1/logs/subscribe` follows a resource, not a process ([API reference](https://api-docs.render.com/reference/subscribe-logs)). Render's restart-time behavior was not observed directly.

## Done — 2026-11-10

`followPods` (`lego/backend/internal/logs/service.go`) keys each follow by pod incarnation, its name and UID (`podFollowKey`). A StatefulSet's same-named replacement (Key Value `red-…-0`, CNPG `<cluster>-1`) is a new key and is attached at the next relist. The restart-count rule (in-place container restarts) and the once-per-life replay of a finished pod are unchanged per incarnation. The shared producer covers App, build, datastore and multi-resource tails. `TestTailAttachesAPodReplacedUnderTheSameName` covers the old pod's last line, then the replacement's first line. It fails with name-only keys (mutation-checked); the existing restart and cron-replay tests pass.
