## Objective

Native static builds take Hugo 0.111.3 extended from a bex-controlled, digest-pinned source (platform registry image), not from `github.com/gohugoio/hugo/releases` at build time.

## Context

- `lego/operator/internal/build/nativehugo.go` (`nativeHugo`, `nativeStaticTools`).
- `lego/operator/internal/build/toolchain-freshness.json:188` inventory.
- Existing pattern: how other pinned helper images (`nativePreparerImage`, ffmpeg) are referenced by digest.

## Steps

1. Add a CI-built `FROM scratch` image (per arch) containing `/hugo`, built from the GitHub tarballs verified against the existing sha256s, and pushed to the platform registry.
2. Replace the two `ADD --checksum` stages with `COPY --link --from=<image>@sha256:<digest> /hugo /hugo`, keeping the same layer shape.
3. Record the image digest and source tarball checksums in `toolchain-freshness.json`.

## Files

- `lego/operator/internal/build/nativehugo.go`, its tests, the image build workflow/Dockerfile, `toolchain-freshness.json`.

## Acceptance criteria

- [x] A generated static Dockerfile contains no `github.com` URL.
- [x] `hugo version` in the built image reports `0.111.3`, extended.
- [x] Hugo quickstart (`hugo --gc --minify`) still builds.

## Out of scope

- Upgrading Hugo.
