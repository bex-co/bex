# 071 — Namespace prune shares m52's stale-snapshot shape

Why: `NamespaceReconciler.pruneOrphans` deletes a workspace namespace on stale absence, the same way the App prune did before w8/m52. If this race ever fires, it deletes every App, Secret and datastore in the namespace, not just one service's settings.

**Worker:** worker8. **Severity:** minor (low reachability, catastrophic impact). **Estimate:** 30m.

## Mechanism

- `lego/backend/internal/store/namespaces.go`: `ReconcileOnce` takes `Store.ListTenants` first. `pruneOrphans` lists managed namespaces afterwards and deletes any owned one whose workspace is not in that earlier snapshot, without re-reading the workspace row.
- bex-api creates a workspace's hosting namespace synchronously (`core.Base.EnsureWorkspaceNamespace`, called from `apps/service.go:2418`, `postgres/service.go:760` and `keyvalue/service.go:518`). So a namespace can appear for a workspace that was absent from the snapshot.
- Reaching it needs the workspace row created **and** its namespace ensured between the two reads, a sub-second window. Signup and the first create are normally seconds apart, so it has not been observed live.

## Fix (same shape as m52)

Before deleting, re-read the workspace with a fresh query and delete only on a definitive `ErrNotFound`. Any other error keeps the namespace and reports a retryable error. Delete with `Preconditions{UID, ResourceVersion}`. Add a probe that creates the tenant and namespace inside a hooked `ListTenants`, plus a failed-read control and a true-orphan control.

Filed 2026-10-09 while triaging w8/m52 t002 (kept out of m52's fix per its scope).

## Outcome (2026-10-09)

Fixed. `NamespaceReconciler.pruneOrphans` (`lego/backend/internal/store/namespaces.go`) now re-reads the workspace with `Store.GetTenant(ns.Labels[LabelWorkspace])` and deletes only on a definitive `ErrNotFound`. Any other read error keeps the namespace and reports `confirm namespace … is orphaned`. The delete carries `Preconditions{UID}`, so a recreated namespace answers Conflict and is skipped. The label carries the tenant id for both hosting and sandbox namespaces. A legacy label that isn't a tenant id still reads as not-found and is pruned. Deletion is a hard delete, so `ListTenants` and `GetTenant` never disagree on a deleted workspace.

Tests (`namespace_prune_race_test.go`, sharing `snapshotRaceStore` with m52's tests): a workspace and namespace created between the two reads survive and converge on the next pass, and an inconclusive read keeps the namespace until a later pass reclaims the true orphan. Both fail on the old code. The existing identity and legacy prune tests pass, as do the full store suite and `make lint`. `/simplify` ran: a shared prune helper was judged not worth it (two sites, different post-delete handling), the two test stores were merged, and a Conflict comment was added.
