# CLI compatibility checklist grades four `ea sandbox …` rows under a command name that does not exist at the pin

Why: `docs/cli-compatibility-checklist.md` is the oracle for "what the CLI supports", and four of its `[x]` rows name `ea sandbox <verb>` — a command the pinned CLI rejects with `unknown command "sandbox" for "bex ea"`. Anyone following the ledger (a QA sweep, a support answer, a pin-bump re-baseline) runs a command that cannot work, and three consecutive pin re-baselines did not catch the rename.

Source: live CLI QA sweep 2026-09-15 (`/qa-find-bugs-cli`, sweep 2), upstream pin v2.27.0 (`a764810a768202704e7206eb7b87a47211fcd98e`), verified against both the installed `bex` v0.2.1 and a `go build` of `lego/cli` at HEAD `f6604b5e1`.

## Finding

The pinned CLI defines the group as **plural** with no singular alias:

- `cmd/sandbox.go:9` — `Use: "sandboxes"`
- `cmd/sandboxgroups.go:9` — `Use: "sandbox-groups"`
- the only alias anywhere in that tree is `cmd/sandboxcopy.go:60` — `Aliases: []string{"cp"}`

Observed:

```sh
bex ea sandbox exec
# Error: unknown command "sandbox" for "bex ea"
# exit 1

bex ea --help
#   objects              Manage object storage in early access
#   sandbox-groups       Manage sandbox groups
#   sandboxes            Manage sandboxes

bex ea sandboxes --help
#   copy  create  exec  list  snapshots  stop
```

The checklist mixes both spellings: the four older rows use the singular `ea sandbox create` / `ea sandbox exec` / `ea sandbox list` / `ea sandbox stop`, while the rows added in the v2.27.0 re-baseline use the correct plural (`ea sandboxes copy`, `ea sandboxes snapshots …`). The **capability** grades are right — w7/m147's 2026-09-15 exec verification clearly drove the real command — only the command strings in the ledger are wrong.

Attribution: bex documentation. No product defect; nothing to fix in `lego/` or `lego/backend/`.

## Release lag observed in the same sweep (no filing needed)

The installed customer binary `bex` v0.2.1 (tag `bex-cli/v0.2.1`, 2026-09-09) leaks upstream branding that **is already fixed on main**:

- flag usage on `postgres create` / `keyvalues create`: `Defaults to the active workspace (set via 'render workspace set')`
- `Long` text on `postgres`/`keyvalues` `get|update|delete|suspend|resume` (10 commands): `switch workspaces with 'render workspace set <name|ID>' and try again`
- `ea objects --help`: `Manage object storage for your Render services.`

The fix is commit `232fb116f` "fix(cli): correct nested help configuration and command references" (2026-09-11), which added the `{"'render workspace set", "'bex workspace set"}` rule at `lego/cli/internal/branding/branding.go:172`. `git merge-base --is-ancestor 232fb116f bex-cli/v0.2.1` is false — the fix postdates the tag. A `go build` of `lego/cli` at HEAD shows zero leakage across the whole help tree.

That commit is the implementation of `.pm/w4/done/063.md` (a 2026-09-11 `qa-find-bugs-cli` filing covering these exact twelve help forms).

So this is **release lag, not a defect**: the next `bex-cli/v*` release ships it. Flagging only so a future sweep does not re-file it against the installed binary.
