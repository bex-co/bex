## Closed — 2026-11-19 (loopx session)

Every `native-common-image.yml` utility cohort (`TestNativeUtilityGeneratedImages`) runs these real-image checks on the image it publishes:

- **The original PDF app** (already maintained). `python313-original` runs the frozen m97 program on the Python 3.13 primary. At build, the original `gs … -sDEVICE=png16m -r72 -dFirstPage=1 -dLastPage=1` argv renders the 471-byte PDF to a 2×1 PNG with exact red/blue pixels. Three HTTP requests on a `--network none` runtime render it again, and the frozen oracle decodes each PNG independently.
- **Already maintained in `utility-check.py`:** a Base14 Helvetica text and color PDF rendered to exact pixels, and an unreadable PDF that must fail.
- **New Ghostscript checks** in `utility-check.py`, at the `node-compute` build and network-off runtime and at the `node-static` build:
  - m97's own PDF through its original argv, outside the Python primary, to the exact pixels in `original-cases.json`;
  - `ps2pdf -dPDFSETTINGS=/prepress` turns a two-page PostScript program into a PDF that embeds a Helvetica subset (`/FontFile3`), which only the packaged URW Base35 fonts can supply;
  - `txtwrite` extracts `Hi` from its first page;
  - all pages render to two PNGs, and `-dFirstPage=2 -dLastPage=2` renders only the all-green second page, decoded independently by `png-decoder.py`;
  - an authored `GS_LIB` directory is searched by `runlibfile`, and without it the same program fails with `/undefinedfilename`;
  - the default `-dSAFER` refuses to open `/etc/passwd` (`/invalidfileaccess`), and an undefined operator exits 1 with `/undefined`.
- **New `missing-ghostscript` omission control.** On the Python 3.13 primary, a test-only layer removes only `/usr/bin/gs`. It checks that `libgs.so.10`, `Resource/Init/gs_init.ps` and the URW Helvetica font remain. The original m97 build must then fail with `gs: command not found` after the layer's ready line.
- **New unit test** `TestNativeUtilityOmissionsHaveRemovalLayers`: every omission in the cohort table has a removal layer, so a table typo fails `go test` instead of panicking on CI's image. Renaming the new entry to `gs` made it fail.
- **How this was checked before shipping.** The host is arm64 and the adopted image is amd64-only, so the generated-image gate cannot run here. On `python:3.13-bookworm` arm64 with the identical `ghostscript`, `libgs10`, `libgs10-common` and `libgs-common` `10.0.0~dfsg-11+deb12u8` from snapshot.debian.org (`fonts-urw-base35` and `poppler-data` match too):
  - the new block passed as uid 1000 and as root, with no network;
  - each assertion failed under its mutation: `-r144` on the original PDF, no page selection, `-dNOSAFER`, a `GS_LIB` without the file, `ps2pdf` without `/prepress` (no embedded font), and a succeeding program in place of the failing one;
  - with every `fonts-urw-base35` file removed, `ps2pdf` failed with `/invalidfont in findfont`;
  - the original m97 build and its three network-off runtime requests passed through `original-cases.py`;
  - after the exact omission command, the original build printed `QA_GS_BEFORE` with `gs_path` null, which matches the historical failure (`valid_before`), and failed with `gs: command not found`.
  - The push of this change re-runs the amd64 utility cohort through `native-common-image.yml`; that run is the amd64 proof.
- **Unit and package checks.** `go vet`, `gofmt` and `go test ./internal/build/` (including `TestNativeOriginalReplayHTTPOracles` and the omission tests), and the operator's `make test`.
- **Bounds.** ARM64 is out of scope (D3). Pre-deploy runs the same image, and there was no hosted pre-deploy run (Free refuses it). Other Python lines rely on the families runs. Other output devices, CJK fonts and multi-file document workflows are not exercised.
