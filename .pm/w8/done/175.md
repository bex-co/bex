# `PYTHON_VERSION=3.11.9` builds on Python 3.11.17: bex substitutes its pinned patch where Render installs the exact version requested

Why: Render requires a fully qualified `PYTHON_VERSION` and installs that exact release. `NODE_VERSION=18.18.0` likewise gets 18.18.0. Bex maps a requested version onto its reviewed line's pinned patch, so the app runs a different patch than the one its owner pinned, and nothing in the API reports the substitution. Patch differences are usually harmless, but users pin exact patches to reproduce a known-good build, and a security or regression fix between patches can change behavior either way. ADR060 D7 addendum calls this "a recorded divergence from Render", and ADR018 row 84 lists it without a user sign-off. This is the stricter follow-up to w8/173 (which adds missing lines); it is filed separately so that w8/173 is not blocked on it.

**Severity:** minor. **Attribution:** platform build (native version selection). **Estimate:** 4h (design-heavy). **Source:** `/qa-find-bugs-cli` sweep 1307, 2026-10-22 ([evidence](evidence/cli-sweep1300/README.md#sweep-1307--runtime-versions)).

## Reproduction

Production `https://api.bex.co/v1/`, pin `efdd8e2ff06b`, `bex-canary`. The same free `render-examples/fastapi` fixture as w8/174, with `--env-var PYTHON_VERSION=3.11.9` (`srv-dbcoah7t87js73873adg`). It went live in 171 s and logged `QAVER Python 3.11.17`. It was deleted (204 → 404).

## Expected

[render.com/docs/python-version](https://render.com/docs/python-version): `PYTHON_VERSION` "must be fully qualified (e.g. `3.13.5`)" and any version from 3.7.3 onward is supported, so 3.11.9 runs 3.11.9. A `.python-version` with only `3.11` gets "the latest matching patch", which matches bex's line behavior. [render.com/docs/node-version](https://render.com/docs/node-version): a semantic version such as `18.18.0` is honored. The same applies to `RUBY_VERSION`/`.ruby-version` and `ELIXIR_VERSION`.

## Root cause

`lego/operator/internal/build/nativeversion.go:74` `ResolveNativeVersion` keys plain versions by major.minor (Python, Ruby, Elixir) or major (Node) and returns the line's single pinned image (`native.go:87–131`). ADR060 D7 addendum: "A plain version maps onto its line … This is a recorded divergence … Reproducing arbitrary patches would mean pulling unreviewed images at build time, which D7 exists to forbid."

## Fix

There are two parity-sufficient designs; pick one in ADR060 and record it in ADR018:

1. **Exact official image by tag.** Resolve `python:3.11.9-bookworm` (and `node:18.18.0-bookworm`, …) to a digest at build time from the official repositories, under the same provenance checks applied to the reviewed lines (official namespace, signature/attestation where published, digest recorded in the build log and the release). Fall back to the line's pinned patch, with a log line, when the exact tag does not exist.
2. **Toolchain install on the line's base.** Install the exact interpreter with the ecosystem's own installer (`uv python install 3.11.9`, a pinned `node` tarball with its published SHASUMS256 verified, `ruby-build`), cached per version.

Either way, narrate `==> Using Python 3.11.9 (from PYTHON_VERSION=3.11.9)`. Today the narration names the line, while the process runs the line's patch.

## Blast radius

Native builds with a fully qualified version signal, on every surface. Services without an exact pin are unaffected. A service that pins a patch older than its line's pin would move to its requested (older) patch on its next build.

## Acceptance

- Unit: `PYTHON_VERSION=3.11.9` selects 3.11.9; `.python-version` `3.11` still selects the line's latest; `NODE_VERSION=24.22.1` selects 24.22.1.
- Live after deploy: the fixture above logs `Python 3.11.9`. Delete by ID with a 404 proof.

## Dedupe

No open item. ADR060 records the mapping as intended; w8/173 covers versions with no line at all.

Done 2026-10-22: design 1 (exact official image by tag). `build.DockerHubResolver` + `pinExactVersion` in the resolve phase; fallbacks log and never fail the build. Unit tests: `nativeexact_test.go`.
