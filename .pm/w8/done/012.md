# Datastore finalizer bound: DeletionStalled-equivalent for Postgres/Key Value

Why: w8/m35 folded Postgres/Key Value by-id reads onto consistent-absence (matching services / Render 404), but App-style `DeletionStalled` (w3/m81) does not yet exist on Database/KeyValue — a stuck CNPG/Barman or Valkey RDB purge can leave an invisible terminating quota slot with no operator condition.

## Gap

- Apps stamp `DeletionStalled` when finalization overruns its bound ([ADR029](../../docs/ADR029-static-sites.md)).
- Database (`app.bex.co/db-finalizer`) and Key Value (`app.bex.co/kv-finalizer`) are fail-closed on purge failure and keep the CR until cleanup succeeds, but they do not stamp an equivalent condition or deadline backoff.
- Tenant reads correctly 404 during the window (w8/m35); operators still need an observable bound for hung datastore deletions.

## Suggested shape

Mirror App's `DeletionStalled` on Database/KeyValue status (or a shared finalizer-bound helper), with envtest coverage for overrun vs healthy in-progress purge. Do not reopen the tenant read contract.
