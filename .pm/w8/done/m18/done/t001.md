## Objective

Add a forward-looking estimator to `lego/backend/internal/pricing` that maps **declared** resources (plan/tier ids, instance counts, provisioned storage GB, HA, read replicas) to an always-on monthly USD estimate — the projection Render's blueprint panel shows. Today `Sheet.Estimate` only accepts metered `store.UsageSummaryRow`s (post-hoc usage); the rates themselves all exist in `pricing.yaml`.

## Context

- `lego/backend/internal/pricing/pricing.go` — `Sheet`, `rateFor` (unknown tier ⇒ $0 per ADR030 §5), `Estimate`. Month = 730h = 2,628,000s (the yaml's own derivation constant).
- `lego/backend/internal/pricing/pricing.yaml` — per-second rates: compute/postgres/valkey tiers + `storage.usdPerGBSecond` ($0.21/GB-mo).
- `lego/types/tiers/tiers.yaml` — per-tier `StorageGB` floors (Postgres basic-256mb ⇒ 1 GB, basic-1gb ⇒ 5 GB; Valkey likewise) used when the blueprint omits `diskSizeGB` — mirrors Render's tier-default-disk behavior.
- Render semantics to mirror (from the decoded dashboard bundle): free plans contribute nothing; a database line = instance + provisioned storage; HA standby doubles the line (ratio 1.0); each read replica prices like the primary; fixed `numInstances > 1` and autoscaling are "variable" (excluded from the total); cron jobs listed but $0 toward the total.

## Steps

1. Define an input struct (kind: service/postgres/keyvalue/cron, tier id, numInstances, storageGB, ha, readReplicas) and an output: line items `{name, kind, tier, monthlyUsd, breakdown{instanceUsd, storageUsd}}`, `variable[]` entries with a reason enum, `totalUsd`.
2. Implement `Sheet.MonthlyEstimate(...)`: `rate × 2,628,000 × instances` + `storageGB × storageRate × 2,628,000`; free/unknown tiers filtered out of lines (consistent with `rateFor`'s $0 policy).
3. USD formatting consistent with `EstimatedCost` (string dollars, 2dp).
4. Unit tests: each tier family, storage floor fallback, HA doubling, replica rows, free-only ⇒ empty lines + zero total.
