## Objective

REST create and PATCH, GraphQL `setServiceIpAllowList`, MCP create and `update_service`, and Blueprint apply all save through the one conversion. A request that omits the field changes nothing; `[]` blocks. `requireServiceInboundRules` counts an empty list as a restriction, so below Scale it is refused unless the service is already blocked, and the allow-all rule is always accepted.

## Files

- `lego/backend/internal/apps/rest.go`, `service.go`, `settings.go`, `settings_check.go`, `graphql*.go`, `mcp.go`
- `lego/backend/internal/apps/blueprint*.go`

## Acceptance criteria

- [x] REST: `[]` on create and on PATCH stores the deny-all entry; an omitted field leaves a blocked service blocked.
- [x] GraphQL and MCP: the same two cases.
- [x] Blueprint: `ipAllowList: []` blocks; the field removed keeps the rules.
- [x] Below Scale: `[]` on an open service is refused with the Scale sentence; `0.0.0.0/0` is accepted and clears a legacy rule.
