## Outcome (2026-10-17)

Done.

Signals modelled: `npm-shrinkwrap.json`/`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `bun.lock`/`bun.lockb`, and `packageManager` naming npm, yarn, pnpm or bun with a version. The step installs only when they name exactly one manager:
- npm, or no signal at all, installs with npm as before.
- Yarn Classic installs with Yarn.
- pnpm, Bun, Yarn 2+ (the installed Yarn 1 refuses `packageManager: yarn@4`; checked in `node:24-bookworm`) and more than one manager are each skipped, with a build-log line naming the signals.

Other behaviour:
- `SKIP_INSTALL_DEPS` set to true (any case) skips; false or empty installs.
- Caller `NODE_ENV` is untouched; `--production=false` keeps devDependencies.
- The checks are bash builtins, so a narrow or empty PATH cannot skew them, and only the step's own process appends `/usr/local/bin`.
- Env, secret files and the cache key are unchanged, because the step stays in the same RUN, keyed by the env revision.

Callers: one chain, `nativeStaticInstall` → `nativeDockerfile` → the native preparer, reached only by Node static builds that do not publish their root. Compute services, other runtimes, Dockerfile/image sources, buildless sites and root-published sites are unchanged.

Limits:
- A workspace member whose lockfile sits above its root directory is outside the build context, so npm runs on it, as before.
- `packageManager` is matched at its first occurrence in `package.json` (pre-existing).
