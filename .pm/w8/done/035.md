# 035 — Free Postgres escapes its tier through sibling flags: read replicas, arbitrary disk size, disk autoscaling (to 16 TB) and a pgbouncer pooler are all accepted on `plan: free`; only HA is gated (w8/m43)

Why: w8/m43 stopped a free database from becoming a replicated cluster via `--high-availability`. `--read-replica <name>` on the same free plan is accepted and provisioned, so the same extra instance comes back through a sibling flag, running free and uncapped per replica name.

Live, 2026-09-27, production `4a0422577`, `bex v0.2.1` (pin v2.27.0), human device login, workspace `bex-canary`. Found by the `/qa-find-bugs-cli` sweep 58. Fixture: free Postgres `dpg-daskh63ncejs739qittg` (deleted).

```text
$ bex postgres create --name … --plan free --read-replica qa58-r1 --confirm -o json   → exit 0
  (create response: readReplicas [] — status not yet populated)
$ bex postgres get <dpg> -o json   (after ~80 s)
  status: available, plan: free,
  readReplicas: [{"id": "dpg-daskh63ncejs739qittg-ro-qa58-r1", "name": "qa58-r1"}]
control: bex postgres update <free-dpg> --high-availability → 400 POSTGRES_HA_PLAN_UNSUPPORTED (m43, holds)
```

## Mechanism

`lego/backend/internal/postgres/service.go:619-631`: `Create` runs `CheckHighAvailabilityPlan(req.Plan)` only when `EnableHighAvailability` is set, then copies every `req.ReadReplicas` entry into `DatabaseSpec.ReadReplicas` with no plan check. The operator provisions them (`Status.ReadReplicaStatuses` populated → view at `:395-420`). Replica count is also unbounded.

## Fix

- Gate `readReplicas` by plan with the same rule and error family as HA (`POSTGRES_READ_REPLICA_PLAN_UNSUPPORTED`: at least 1 CPU, or whatever the Render-parity check confirms), on every write path: REST create, GraphQL `createDatabase`, MCP `create_postgres`, Blueprint `readReplicas`, plus any plan downgrade that would strand replicas (refuse the downgrade or require removing replicas first, mirroring m43's HA handling).
- Cap replicas per database (Render's documented maximum, or a named bex limit).

## Acceptance

- [ ] `bex postgres create --plan free --read-replica r1` → exit 1 with the named refusal, nothing created. The same on GraphQL/MCP and in a Blueprint.
- [ ] A ≥1-CPU plan still creates the replica (blocked on the same plan decision as m43 § Blocked; a unit test covers it until then).
- [ ] Plan downgrade of a database with replicas to an unsupported plan is refused with the reason.

## Unverified

- Render's exact plan floor for read replicas (the pinned CLI documents none; `render-artifacts/postgres-ha.md` shows them on `basic-1gb`). The parity check must confirm before the refusal ships.
- Whether the replica pod actually ran on the free plan's resources, or was scheduled at a larger size (only the status entry was observed).

## Sweep 59 addendum: disk, autoscaling and pooler on free

Same production, fixture `dpg-dasl1c21pbgc73a24kng` (deleted):

```text
$ bex postgres create --plan free --disk-size-gb 15 --disk-autoscaling --connection-pool pgbouncer --confirm   → exit 0
$ bex postgres get <dpg>   → status available, plan free, diskSizeGB 15, diskAutoscalingEnabled true, connectionPool pgbouncer
```

- `tiers.yaml` gives `free` `storageGB: 1` as a **floor** ("spec.storageGB can grow past it, never below"), and `diskAutoscalingCapGB: 16384` applies to every plan. The server checks only `DiskSizeGB > 0` (`postgres/service.go:973`), with no per-plan ceiling on create or update and no plan gate on autoscaling or the pooler.
- So a free database can be created at any disk size and set to autoscale toward 16 TB. `w1/done/m81/t004` capped the dashboard form on the assumption of "existing server enforcement", which does not exist.
- Extend the fix: a per-plan disk ceiling (free = 1 GB, matching Render's fixed free storage), refuse `--disk-autoscaling` and (if Render agrees) the pooler on free, on create **and** `postgres update`, with named errors in the HA family.
- Unverified: whether the metering/price sheet bills free-plan storage (if it bills, the risk is cost to the tenant, not to the platform), and Render's pooler availability on free.

Estimate: ~70m. Coordinate with `w8/blocked/m43` (same plan gate).

> Contrast (sweep 60): web services already enforce the free tier. `services create --plan free --num-instances 3` → `400 the free plan is limited to 1 instance(s) and cannot scale to 3`. The Postgres create/update paths should get the same kind of plan check.
