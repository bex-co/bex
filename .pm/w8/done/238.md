# A misspelled Blueprint `runtime` also reports a false `buildCommand` error

Why: `bex blueprints validate` on `runtime: nodee` reports two errors, and the extra one tells the user their service is a "Dockerfile or prebuilt-image service", which it is not. The only real problem is the typo.

**Severity:** minor (misleading copy, exit status correct). **Attribution:** server (Blueprint compiler). **Estimate:** ~30m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `a6b6`, 2026-11-08.

## Evidence

Checkout build `bex vqa-460c283a6`, Render CLI v2.35.0 `24ac2d60fdb2`, `https://api.bex.co/v1/`, workspace `bex-canary`, non-TTY.

```yaml
# rt.yaml
services:
  - type: web
    name: qa-bp-rt
    runtime: nodee
    plan: free
    buildCommand: npm i
    startCommand: node x
```

```text
$ bex blueprints validate rt.yaml -o json      → exit 1
{
  "errors": [
    { "column": 19, "line": 6, "path": "services[0].buildCommand",
      "error": "buildCommand requires a native runtime (elixir, go, node, python, ruby, or rust); bex does not run it for Dockerfile or prebuilt-image services" },
    { "column": 14, "line": 4, "path": "services[0].runtime",
      "error": "at '/services/0/runtime': value must be one of 'docker', 'elixir', 'go', 'image', 'node', 'python', 'ruby', 'rust', 'static'" }
  ],
  "valid": false
}
```

Controls (same run): the same file with `runtime: node` → `{"plan":{"services":["qa-bp-rt"],"totalActions":1},"valid":true}`, exit 0. `runtime: docker` + `buildCommand: npm i` → the single `buildCommand` error above, which is correct there. A file whose only problems are unknown `fromDatabase`/`fromService` references reports exactly those two errors.

## Root cause

`lego/backend/internal/apps/blueprint_compiler.go:292-313` `blueprintServiceRuntimeProblems` evaluates `!hasImage && !blueprintNativeRuntime(runtime)` for any runtime string, including one the schema already refused. An unknown value is treated as non-native, so the Dockerfile/image message fires. The `dockerCommand` and `dockerfilePath` rules in the same loop have the same shape.

## Fix

Return no runtime-dependent field problems when `runtime` is set to a value outside the schema enum. The schema error at `services[N].runtime` stands alone. Keep the rules unchanged for valid runtimes and for an absent runtime.

## Acceptance

- `rt.yaml` above → exactly one error, at `services[0].runtime`, exit 1.
- `runtime: docker` + `buildCommand` still reports the `buildCommand` error. `runtime: image` + `dockerfilePath` still reports its error.
- Same result through REST `POST /v1/blueprints/validate`, GraphQL and MCP validate, which share the compiler.

## Done — 2026-11-10

`blueprintServiceRuntimeProblems` (`lego/backend/internal/apps/blueprint_compiler.go`) skips the runtime-dependent field rules when `runtime` is outside the schema enum, so `runtime: nodee` reports only the schema error at `services[0].runtime`. Valid runtimes, and an absent one, keep every rule. `TestBlueprintRuntimeTypoReportsOnlyTheRuntime` covers the typo, `docker` + `buildCommand`, `image` + `dockerfilePath`, and `node` + `buildCommand` (no problem). REST, GraphQL and MCP validate share the compiler.
