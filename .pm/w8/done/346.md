# A Blueprint on GitLab, Bitbucket or an unsupported host is refused in wording that names GitHub, and the dashboard drops the host refusal

Why: since w8/344 (`ce33010c1`) bex reads Blueprints from gitlab.com and bitbucket.org and refuses every other host by name. But the refusal copy still blames "bex's GitHub app", so a user with a GitLab typo or a codeberg URL is sent to check a GitHub installation that has nothing to do with their repository.

- **Source:** follow-up from the w8/344 worker, 2026-11-20. These were the note's "Known gaps", which were never filed. Found by code reading, plus the live refusal text seen while closing w8/344.
- **Evidence:**
  - Server, `lego/backend/internal/apps/blueprint.go`. `classifyBlueprintFetchError` (`:350–352`) answers `Repository not found, or bex's GitHub app cannot access it.` for any `ErrRepoNotFoundOrNoAccess`, including a missing GitLab or Bitbucket repository. The 401/403 case (`:379`), the 429 case (`:382`) and the default `unavailable` case (`:386`) also name GitHub. `blueprintBranchRefusal` (`:2715`, `:2717`) answers with the same GitHub wording when the no-branch default lookup fails on another host, for example `example.com/a/b`.
  - Dashboard, `dashboard/src/routes/blueprints.new.tsx:278–330`. The page picks fixed copy per `reason` and never renders `preview.error` (`:265–268`). For `repo_not_found_or_no_access` it shows `blueprints.previewRepoNotFoundBody` (`src/features/blueprints/locales/en.ts:158–161`): "This repository does not exist, or bex's GitHub app cannot access it." So a codeberg preview, which the API refuses live with `bex reads a Blueprint from a public repository on github.com, gitlab.com or bitbucket.org, as Render does; codeberg.org is not one of them`, reaches the user as the GitHub-app message. The `access_denied` (`en.ts:167–169`) and `unavailable` (`en.ts:194–196`) bodies name GitHub too.
- **Fix direction:**
  - Server: pick the wording from the repository's host. github.com keeps today's text. gitlab.com and bitbucket.org say the public repository or branch was not found or could not be reached on that host. Keep the `reason` codes unchanged.
  - Dashboard: give the host refusal its own copy, or render the server's message for it. Two ways to tell it apart: a distinct `reason`, or a host check on the repo URL the page already holds. Make the other bodies host-neutral or host-aware in all 8 locales.
- **Done when:**
  - A unit test shows a missing GitLab repository, a GitLab outage and a failed default-branch lookup on `example.com` answer messages that do not name GitHub, while the github.com wording is unchanged.
  - A dashboard test shows a codeberg preview names `codeberg.org`, and a GitLab `repo_not_found_or_no_access` does not mention a GitHub app.
- **Estimate:** ~1h.

## Fixed 2026-11-20 (`/loopx w8`)

- Server (`lego/backend/internal/apps/blueprint.go`): `classifyBlueprintFetchError`, `blueprintFetchFailure`, `blueprintCreateFetchError` and `blueprintBranchRefusal` take the repository and pick their wording from its host (`blueprintWordingFor`, host from the new `github.BlueprintHost`). github.com keeps its sentences word for word. A gitlab.com or bitbucket.org repository answers `Repository not found on <host>, or it is not public. …`, `<host> did not let bex read this repository. …`, `<host> is rate-limiting bex …` and `Could not reach <host> to read the Blueprint file. …`. The `reason` codes are unchanged, and sync history records the same sentences.
- With no branch, `blueprintBranch` now asks `github.RefuseBlueprintHost` first. A host bex reads no Blueprint from is refused by name before any default-branch lookup, as a preview (`repo_not_found_or_no_access`) and as a create's 400 with the same code a read with a branch gives. `https://example.com/a/b` is no longer probed, and no longer reads "bex's GitHub app cannot access it" or `repo and branch are required`.
- Dashboard (`dashboard/src/routes/blueprints.new.tsx`, `src/features/blueprints/lib/repo-host.ts`): the review reads the host from the repo URL it holds. On a host bex does not read, `repo_not_found_or_no_access` shows its own panel ("Git host not supported", naming the host). On gitlab.com or bitbucket.org, the repo-not-found and access-denied bodies name the host and no app. The rate-limited and unavailable copy takes `{host}`, which is "GitHub" for GitHub, so GitHub's text is unchanged. These strings are in all 8 locales. A failed review with no branch typed now shows its panel instead of "Select a repository and branch", so a pasted codeberg URL is refused at once.
- Tests: `apps/blueprint_host_wording_test.go` covers a missing GitLab repository, a GitLab outage and raw failure, Bitbucket not-public, 403 and 429 cases, github.com controls compared exactly, a GitLab sync's history line, and `example.com` with no branch (preview and create, with no lookup made). `github/public_blueprint_test.go` `TestRefuseBlueprintHostNeedsNoRead` is the other new backend test. On the dashboard, `blueprints-new.test.tsx` has the codeberg (no branch), GitLab and Bitbucket panels, none containing "GitHub", and `repo-host.test.ts` is new. With the host wording forced back to GitHub's and the early refusal removed, all 8 backend cases fail. On the original page, all 5 dashboard cases fail.
- Not changed: a gitlab.com or bitbucket.org preview with no branch whose host does not answer still answers `repo and branch are required`, because `publicGitDefaultBranch` reports no opinion. A malformed gitlab.com or bitbucket.org URL (not owner/repo) still classifies as `invalid_path`.
