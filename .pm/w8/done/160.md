# A Blueprint database on Render's `pro-4gb` plan is refused as "not a supported Render Postgres plan", although it is one

Why: `pro-4gb` is a current Render Postgres plan, and Render's own `multi-environments-blueprint` example uses it. Bex does not sell it, which is a legitimate limit, but the refusal tells the author their Render plan name is wrong. The REST create for the same case says the neutral thing ("plan must be one of free|basic-256mb|basic-1gb"). w8/054 fixed this exact class of message ("blames the author's Render syntax") for `postgresMajorVersion`; the Postgres plan message was missed.

**Severity:** minor. **Attribution:** server (Blueprint message). **Estimate:** 15m. **Source:** `/qa-find-bugs-cli` sweep 1276, 2026-10-21 ([evidence](evidence/cli-sweep1276/README.md)).

## Reproduction

Production `https://api.bex.co/v1/`, pin `9cace6b6e25d`, HEAD-built pinned CLI. `bex blueprints validate multi-environments-blueprint.yaml -o json` on `render-examples/multi-environments-blueprint/render.yaml`, which passes Render's pinned Blueprint schema with 0 errors and declares `databases: [{name: portal-db-env-demo, plan: pro-4gb, …}]`:

```
database "portal-db-env-demo" plan "pro-4gb" is not a supported Render Postgres plan (one of free|basic-256mb|basic-1gb)
```

Control: `POST /v1/postgres` with `plan: pro_4gb` → 400 `POSTGRES_PLAN_UNSUPPORTED`, `plan must be one of free|basic-256mb|basic-1gb`, and nothing is created.

## Expected

Name bex's limit, not a Render syntax error: `database "portal-db-env-demo" plan "pro-4gb" is not available on bex; choose one of free|basic-256mb|basic-1gb`. A plan name Render itself does not recognize (for example `pro-5gb`) keeps a "not a Render Postgres plan" wording.

## Root cause

`lego/backend/internal/apps/deploy.go:2946–2948` uses one message for "unknown to Render" and "known to Render, not offered by bex", because it only consults `tiers.Postgres`.

## Fix

Check the name against Render's Postgres plan enum (the pinned Blueprint schema's database `plan` enum, or `tiers` metadata). Use the "not available on bex" wording when Render knows the plan, and keep the current wording otherwise. Check the Key Value and service plan refusals for the same split.

## Acceptance

- Compiler tests: `pro-4gb`, `basic-4gb` and `accelerated-16gb` get the "not available on bex" message. `pro-5gb` gets the "not a Render plan" message. `free`, `basic-256mb` and `basic-1gb` validate.
- Live after deploy: the example file above shows the new wording.
