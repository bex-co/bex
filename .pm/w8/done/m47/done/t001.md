## Objective

In `SetDisplayName` (`lego/backend/internal/apps/service.go:4203-4232`), refuse a trimmed display name equal to any other App's displayed name **or** creation name in the same workspace, with the create path's `CONFLICT` error ("name … is already in use"). Make it race-safe: the uniqueness check and write happen under the same serialization create uses, or behind a unique index on the store's `(tenant, displayed_name)`.

## Acceptance criteria

- [ ] Sequential and concurrent (two parallel) renames to one name: exactly one succeeds, the other gets 409.
- [ ] Renaming to one's own current or creation name stays allowed.

## Outcome (2026-09-27) — done

`store.PGStore.SetAppDisplayName` now runs in one transaction. A non-empty name other than the service's own creation name takes the per-workspace `service-names:<tenant>` advisory lock and refuses (`ErrConflict`) any other service in the workspace created as, or displayed as, that name. `CreateApp` takes the same lock and also refuses a name another service is displayed as. `apps.SetDisplayName` answers exactly like create: `409 CONFLICT "name "…" is already in use"`, unprefixed (`writeThroughStoreFetched` passes coded refusals through), and the CR keeps its old name. Name-availability suggestions now count displayed names too. Clearing, re-setting, and renaming to your own creation name stay allowed.

Tests: `store.TestServiceNamesStayUniqueAcrossCreateAndRename` (creation-name, displayed-name and create-as-displayed conflicts, own-name/clear allowed, 5 concurrent rounds → exactly one lands), run against real Postgres 16 locally (tmpfs container; the Docker Desktop VM is out of disk). `apps.TestSetDisplayNameTakenNameIsCreatesConflict`.
