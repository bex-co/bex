# `bex ssh --ephemeral` on a paid service ends with "failed to create ephemeral shell: not found": bex has no `ephemeral-shell` route, so the deliberate non-goal reads as a missing service

Why: ephemeral shells are off-roadmap together with one-off jobs. `.pm/DO_NOT_DO.md` lists "One-off jobs (`/services/{id}/jobs`) and ephemeral shell instances", and ADR035 does not authorize "ephemeral shell instances, `--ephemeral`".

- **Jobs refuse by name:** `POST /v1/services/{id}/jobs` answers 410 `ONE_OFF_JOBS_UNSUPPORTED`, "one-off jobs are not supported on bex; run the command in the service itself (`bex ssh <service>`), as a pre-deploy command, or as a cron job" (w4/m116 t003).
- **Ephemeral shells do not:** `POST /v1/services/{id}/ephemeral-shell`, the route the pinned CLI's `ssh --ephemeral` calls, does not exist, and answers the router's generic 404 `{"error":"not found","message":"not found"}`. The CLI prints that message after its own prefix, so a user who added `--ephemeral` on a paid service is told `failed to create ephemeral shell: not found`. That reads as a missing service, and there is no hint that plain `bex ssh <service>` works.

**Severity:** minor (a non-goal's error message; nothing else is affected). **Attribution:** server (bex-api routes). **Estimate:** ~30m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `551a`, 2026-11-13 UTC, released `bex v0.5.0` (Render CLI v2.35.0), `https://api.bex.co/v1/`, workspace `bex-canary`, QA human device login, production pin `4c3c68e6b05b`.

## Evidence

**Fixture:** a free Node web service `qa-20261113-551a-node` (`srv-dbrb70gv8soc73b22m50`), created with `bex services create … --plan free -o json --confirm`. It went live at 06:55:33 UTC and was deleted afterwards.

**Jobs, for comparison:** `bex jobs create <srv> --start-command 'echo hi' -o json --confirm` exited 1 in 0.4 s with `Error: received response code 410 (ONE_OFF_JOBS_UNSUPPORTED): one-off jobs are not supported on bex; …`. `bex jobs list <srv> -o json` printed `[]`, so nothing was written. That matches the checklist's `jobs create` row, which said "Not yet re-probed".

**The raw route:** `POST /v1/services/srv-dbrb70gv8soc73b22m50/ephemeral-shell` with `{}` answered `404 {"error":"not found","id":"not_found","message":"not found"}`.

**The CLI on this free service:** `bex ssh <srv> --ephemeral --output text -- …`, with and without `--plan 1c-2g`, exited 1 with `Error: service does not support ssh`. The pinned client refuses before calling the route, because a Free service has no `sshAddress`. That is the correct Render behavior for Free.

**On a paid service** (not run here; paid fixtures are off-limits), the client reaches the route:

- `pkg/tui/views/ssh.go:188-190`: it checks `sshAddress`.
- `:212`: it then calls `createEphemeralShell`.
- `:89-97`: that turns a non-2xx response into `failed to create ephemeral shell: <body.message>`.

With bex's 404, the message is `not found`.

## Root cause

`lego/backend` registers no `ephemeral-shell` route. A search for `ephemeral-shell`, `ephemeralShell` and `EphemeralShell` in `lego/backend` finds nothing outside tests. The request falls through to the router's not-found answer. The jobs gate is a dedicated route that refuses by name (`lego/backend/internal/jobs/rest.go:30`, `CodeOneOffJobsUnsupported` in `jobs/service.go:173`).

## Fix

- **Mount the route as a gated refusal:** `POST /v1/services/{id}/ephemeral-shell` answers 410 with a stable code, for example `EPHEMERAL_SHELLS_UNSUPPORTED`, and a message the CLI shows verbatim.
  - Suggested message: "ephemeral shells are not supported on bex; connect to the running service with `bex ssh <service>` (without `--ephemeral`)".
  - Authorize it like the jobs gate: resolve the service in the caller's workspace first, so an unknown or foreign service still answers 404 and no existence leaks.
- **Docs:** add the refusal to ADR035's non-goals and to the checklist's `--ephemeral` row, which today says only "(flag parses)".
- **The jobs message:** while there, its advice names `bex ssh <service>`, which a Free service cannot use. Consider naming SSH as a paid-instance feature, or putting the pre-deploy and cron options first.

## Blast radius

- **Who sees it:** paid web services, private services and background workers, the services that have an `sshAddress`, reached through the pinned CLI's `ssh --ephemeral` / `--plan`. Free services stop client-side, as above.
- **Not affected:** the dashboard (it offers no ephemeral shell) and MCP. No data path changes.

## Regression checks

- **Go test:** `POST /v1/services/{id}/ephemeral-shell` answers 410 with the code for a service in the caller's workspace, 404 for an unknown or foreign service, and writes nothing.
- **Production:** the raw `POST` on an owned Free service answers 410 with the message. A paid-service CLI check prints `failed to create ephemeral shell: ephemeral shells are not supported on bex; …`; that needs a paid fixture, so record it only if one is authorized.

## Dedupe

- w4/m116 t003 (done) gated jobs only.
- The checklist marks `--ephemeral` as a non-goal with no refusal behavior.
- No `.pm` item covers the ephemeral-shell route.

## Resolution

**DONE 2026-11-13.** `POST /v1/services/{id}/ephemeral-shell` is mounted beside the jobs gate (`lego/backend/internal/jobs/rest.go`). `CreateEphemeralShell` (`jobs/service.go`) authorizes the caller with `can_create`, the same gate and deferred audit as `jobs create`, then answers 410 `EPHEMERAL_SHELLS_UNSUPPORTED`: "ephemeral shells are not supported on bex; connect to the running service with `bex ssh <service>` (without --ephemeral)". An unknown or foreign service still answers 404, and a role below developer gets the authz refusal. `TestEphemeralShellIsRefusedWithNamedGone` covers all three and fails if the refusal comes before authorization.

The scope matrix classes the route `Write`, as `jobs create` is. The verb sweep counts 430, and the role ladder pins `can_create`. The jobs message now lists the options that work on every plan first, since a Free service cannot use `bex ssh`: "run the command as a pre-deploy command or a cron job, or in the running service with `bex ssh <service>` on a paid instance". ADR035 and the checklist's `--ephemeral` row record the refusal. Production check after the next roll: the raw `POST` on an owned Free service answers 410 with the code. A paid-service CLI check needs a paid fixture.
