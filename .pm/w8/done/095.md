## Cause and bounded correction

[Numbered producer/consumer excerpts](../evidence/095/source.txt):

- `apps/deploy.go:2136–2170` keeps plain group literals, including empty values, in `parsedEnvGroup.literals`. Its sole forwarding call, `applyStackEnvGroups:842`, passes that map directly to `ApplyEnvGroup`.
- `envgroups/service.go:1563` compares `env[key] != literals[key]`. Go's one-value lookup returns `""` for an absent string key, so an absent key with desired `""` compares equal and produces no write. When there are no other writes, the method returns nil at `1576–1577`.
- The new-group path at `1536–1544` correctly sends `ValueSet:true` for every literal to `prepareCreateEnv:560–584`, explaining the creation control.
- The existing-group write already sets `ValueSet:true` at `1564`. `envgroups/patch.go:187,202` applies the sparse patch and compares complete maps; `core/environmentpatch.go:75–99` honors the explicit-empty flag. Neither downstream consumer needs new empty-value handling.

Use the two-result lookup in the existing-group literal diff: emit the current sparse literal write when the key is **absent or its value differs**. Preserve the present-empty no-op, generated-value preservation, omitted-key retention, validation, revisions and the current rollout policy. Do not change parser presence semantics, conservative group plan operations or the ordinary editor/API write protocol.

[Exact production caller census](../evidence/095/callers.json): one `ApplyEnvGroup` call, one `applyStackEnvGroups` call, and three `deployParsedStack` calls. The latter cover direct stack deployment and Blueprint create/sync application. Direct `DeployStack` has REST and MCP callers; Blueprint lifecycle methods also expose the shared path. Group declarations in all three locations converge on this same writer. Review those consumers without broadening the fix to service literals, datastore settings or every string-map comparison.

## Outcome (2026-10-12) — fix shipped, blocked on hosted acceptance

- **Fix:** `ApplyEnvGroup`'s existing-group literal diff (`lego/backend/internal/envgroups/service.go`) uses the two-result lookup, so a declared key that is absent is written even when its value is `""`; a present equal value (including empty) is still a no-op. Parser presence, generated-value preservation, omitted-key retention, validation, revisions and rollout policy are unchanged; the sole caller is `applyStackEnvGroups`.
