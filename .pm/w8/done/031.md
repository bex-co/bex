# 031 — `bex logs --level warning` (and `notice`/`critical`/`alert`/`emergency`) never matches: the pinned CLI only accepts Render's level names, and bex stores `warn`

Why: `bex logs --level warning` is the only way the CLI can ask for warnings, and it always returns nothing, even when warnings exist. `--level warn` is refused client-side. So on bex a user cannot filter warnings from the CLI at all, and `notice`/`critical`/`alert`/`emergency` fail the same way. The response labels also carry values (`warn`, `unknown`) outside Render's enum.

Live, 2026-09-27, production `726042a28`, `bex v0.2.1` (pin v2.27.0), human device login, workspace `bex-canary`. Found by the `/qa-find-bugs-cli` sweep 45. Fixture: free busybox cron `srv-das9l7od0qnc73d7a420` (deleted) printing one line per style:

```text
# labels the pipeline assigned (bex logs -o json)
{"level":"error","msg":"qa45 json-error"}           → level=error
level=error msg=qa45-logfmt                         → level=error
{"severity":"WARNING","message":"qa45 json-sev"}    → level=warn
ERROR qa45 prefixed-error / [WARN] … / plain stdout / plain stderr → level=unknown

$ bex logs -r <cron> --type app --level error    → 2 lines ✔
$ bex logs -r <cron> --type app --level warning  → (nothing) ✘
$ bex logs -r <cron> --type app --level warn     → Error: invalid argument "warn" for "--level" flag: must be one of "debug", "info", "notice", "warning", "error", "critical", "alert", "emergency"
GET /v1/logs?…&level=warn → 2 lines;  &level=warning → 0
```

## Mechanism

- The pinned client's enum is `debug|info|notice|warning|error|critical|alert|emergency` (`render-oss/cli` `cmd/logs.go:64`), sent verbatim as `level=`.
- The shipper normalizes into its own buckets `error|warn|info|debug|unknown` (`deploy/gitops/base/log-shipper.yaml:236,329`: `warning→warn`, `notice→info`, `critical/crit/fatal/panic→error`).
- The server passes `level` straight to an exact Loki label matcher (`lego/backend/internal/logs/loki.go:213`, `labelMatcher(lokiLabelFor(LabelLevel), q.Level)`), so any Render name that the shipper renamed never matches.

## Fix

1. **Query side (backward-compatible, covers existing streams):** in `logs` query building, map each requested Render level to the shipper bucket(s) before `labelMatcher`: `warning→warn|warning`, `notice→info`, `critical|alert|emergency→error`, `debug`/`info`/`error` unchanged. Apply the same mapping in the datastore fallback filter and in GraphQL/MCP `level` args.
2. **Emit side:** change the shipper bucket from `warn` to Render's `warning` so response labels are in-enum. Keep the query mapping so older `warn` streams still match within retention.
3. Optional, separate decision: whether `unknown` should stay as the label for unclassified lines (Render has no such value). Record the decision.

## Acceptance

- [ ] The repro above: `bex logs --level warning` returns the `severity: WARNING` line. `--level critical` returns a line logged as `{"level":"fatal"}`, and `--level notice` returns one logged as `notice`.
- [ ] Newly shipped warning lines carry `level=warning`. A query within retention still finds older `warn`-labelled lines.
- [ ] Unit test for the level mapping in the Loki matcher, which fails on the old code for `warning`.

## Outcome (2026-09-27) — done

1. **Query side:** `logs.storedLevels` maps Render's level names onto the stored buckets before the Loki label matcher (`loki.go`): `warning`/`warn` → `warning|warn`, `notice` → `info|notice`, `critical`/`alert`/`emergency`/`fatal` → `error|<name>`; `debug`/`info`/`error` unchanged. REST, GraphQL, MCP and the dashboard share this query path. The dashboard's level picker already falls back to `warning`, which was broken the same way and now works. The pod-log fallback applies no level filter, so it's unaffected. Test: `TestLokiQueryFor` cases for `warning` and `notice/critical/emergency` (fails on the old exact matcher).
2. **Emit side:** the shipper's app and platform pipelines, and w8/030's Postgres pipeline, emit `warning` instead of `warn` (Render's enum). `datastorelogs` emits the same. Streams stored as `warn` within retention still match via (1).
3. **`unknown`:** kept for unclassified lines (Render has no such value, but a guessed severity would be worse). Recorded in ADR010.
