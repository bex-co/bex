## Objective

Today one Secret per App, `<app>-registry-pull`, holds whichever credential the last trigger materialized. The serving release's pods name that Secret, so a trigger for credential B rewrites what a release that went live with A pulls with. Give each (App, credential) pair its own Secret, so materializing B never touches A's. Rotating A's token still refreshes A's Secret at its next materialization, so the same credential keeps working, as on Render.

## Context

- `materializePullSecret` (`lego/backend/internal/registrycreds/pullsecret.go:132`) upserts `appv1alpha1.ExternalRegistryPullSecretName(app.Name)` (`lego/types/v1alpha1/secretnames.go:48`).
- The deterministic name is also derived in:
  - the projector, `projectSpec` and `applyOwnedSpec` (`lego/backend/internal/store/reconciler.go:2986`, `:3039`);
  - `writeInitialApp`'s operational capture (`lego/backend/internal/apps/service.go:3229`);
  - `deleteExternalRegistryPullSecret` (`lego/backend/internal/apps/pullsecret.go:142`);
  - the operator's own-Secret recognition: `rejectProtectedSecretRefs` (`app_controller.go:2535`), `ownBuildPlaneSecret` (`:2739`) and the build-namespace relocation (`build_registry_secret.go`).
- `appBoundToCredential` (`registrycreds/pullsecret.go`) refuses to delete a credential that an App's spec still binds. Once per-credential copies exist, a credential the spec no longer binds can still have a copy, so its delete has to reap them.
- The Secret carries no owner reference, on purpose (an App created in the same call has no UID yet). App delete removes it by name.

## Steps

1. In `lego/types`, derive a per-credential name, for example `<app>-registry-pull-<rgc-id>`, plus a predicate that recognizes an App's own pull Secrets: the per-credential form and the legacy `<app>-registry-pull`. Label each Secret with its App and credential so reaping can select them.
2. Backend: materialize under the per-credential name. The projector derives the same name from the row's binding. The capture in `writeInitialApp` follows. App delete removes every pull Secret of the App, the legacy name included. Credential delete removes that credential's copies in the workspace namespace once no App binds it.
3. Operator: accept the per-credential form wherever the App's own pull Secret is recognized. Keep refusing another App's Secret and every other protected Secret.
4. Tests: materializing B leaves A's Secret unchanged. Materializing A after a rotation refreshes A. App delete and credential delete reap what they own. The operator accepts its own per-credential name and still refuses another App's.
