# `bex services create --type static_site` without `--publish-directory` is refused, although Render's API defaults the publish path to `public`

Why: the pinned CLI makes `--publish-directory` optional for a static site and omits `publishPath` when it is not given. Render's create contract fills in `public`. Bex answers 400 `publishPath is required for a static_site`, so a command that works against Render fails against bex. Scripts and agents that copy Render's minimal static-site create, which covers most Jekyll, Hugo and plain-HTML sites that publish `public/`, stop at the first step.

**Severity:** minor. **Attribution:** server (REST create default). **Estimate:** 30m. **Source:** `/qa-find-bugs-cli` sweep 1268, 2026-10-21 ([evidence](evidence/cli-sweep1268/README.md)).

## Reproduction

Production `https://api.bex.co/v1/`, deployed pin `9cace6b6e25d`, workspace `bex-canary`, human device-login grant, HEAD-built pinned CLI (Render CLI v2.27.0, `a764810a7682`).

```text
$ bex services create --name qa-20261021-<nonce>-pubdef --type static_site \
    --repo https://github.com/mdn/beginner-html-site --branch main -o json --confirm
Error: received response code 400: bad request: publishPath is required for a static_site
exit 1 (7.1 s)
```

A by-name list afterwards returned `[]`, so nothing was created.

## Expected

The pinned Render schema (`lego/backend/internal/api/openapi/render-public-api-1.json`, `staticSiteDetailsPOST.publishPath`) says "Defaults to \"public\"". The pinned client carries the same comment (`pkg/client/types_gen.go:3459`). It sends `PublishPath: cliInput.PublishDirectory` (`pkg/service/create.go:241–245`), which is nil, and so omitted, when the flag is absent. The create should succeed with `publishPath: "public"` and read it back. If the repository has no `public/` directory, the deploy should fail with the existing nonexistent-publish-directory attribution (w6/038), not at create.

The Blueprint field is different. Render documents `staticPublishPath` as "**Required.**", so bex's Blueprint requirement (w4/m102) stays as it is.

## Root cause

`lego/backend/internal/apps/service.go:3080–3082` refuses an empty `PublishPath` for every create adapter. The REST adapter (`rest.go:456`) passes the omitted field through as `""` and applies no Render default. The operator (`app_controller.go:4019–4021`) and the CRD comment (`types/v1alpha1/app_types.go:400–406`) also treat the field as required, so the default belongs at the Render-shaped boundary, not in the operator.

## Fix

In the REST create adapter only, when `type: static_site` and `serviceDetails.publishPath` is absent or blank, use `public` before the shared validation runs. Keep the shared requirement for bex's own surfaces where it was a choice: the Blueprint (Render requires it there), GraphQL `createService` and the dashboard form (w4/332). Upstream MCP `create_static_site` also lists `publishPath` as optional. Either apply the same default there and drop the "genuine divergence" note at `mcp.go:523–526`, or record why MCP keeps the requirement. Note the default in ADR029 and ADR018.

## Acceptance

- REST handler test: a static-site create without `publishPath` stores and reads back `public`. An explicit `dist` is unchanged. A blank string defaults the same as omission. A web service with `publishPath` keeps its 400.
- The Blueprint without `staticPublishPath` still fails with the existing message (w4/m102 control).
- Live after deploy: the command above returns a service with `serviceDetails.publishPath: "public"`. With `--repo https://github.com/mdn/beginner-html-site` its first deploy fails on the missing `public/` with the w6/038 message, and a repository that has `public/` goes live. Delete both by ID with 404 proofs.

## Blast radius

One REST create default. It touches MCP `create_static_site` if that tool aligns with upstream. GraphQL, the dashboard and the Blueprint are unchanged by choice. w4/332 (dashboard: require a publish directory before Deploy) stays valid for the form, but it could prefill `public` instead of an empty field.

## Dedupe

`rg -i 'publishPath is required|publish directory' .pm docs`: w4/m102 (Blueprint `staticPublishPath`; done), w4/332 (dashboard form validation; blocked; it says "preserve the existing bex API requirement" without considering Render's API default), w2/m91/t004 (MCP divergence recorded as accepted without a Render comparison), w6/038 (nonexistent publish directory attribution). No item covers the REST/CLI default.
