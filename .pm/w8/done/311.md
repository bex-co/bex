# Turning on connection pooling or disk autoscaling on a free Postgres is refused with "disable … before selecting the free plan", though the request selected no plan

Why: the refusal's code and first clause are right, since only paid plans support these features. Its remedy is written for a different request: moving a pooled or autoscaling database to the free plan. A user who runs `bex postgres update <free-db> --connection-pool pgbouncer` is told to disable pooling, which is already off, "before selecting the free plan", which they did not select. The fix they need is the opposite: choose a paid plan. w8/246 already made the read-replica refusal's remedy fit what the request did (`plan_refusal_wording_test.go`). These two sibling refusals were left with one fixed remedy.

**Severity:** minor (the wording of a correct refusal). **Attribution:** server (bex-api Postgres admission). **Estimate:** ~30m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `2edc`, 2026-11-13 UTC, released `bex v0.5.0` (Render CLI v2.35.0), `https://api.bex.co/v1/`, workspace `bex-canary`, QA human device login, production pin `5de3d5bcce8e`.

## Evidence

**Fixture:** free Postgres 16 `qa-20261113-2edc-pg2` (`dpg-dbrijmhens8c73fghqf0`), created with `bex postgres create --plan free --version 16 …`, status `available`, `connectionPool: none`, disk autoscaling off. It was deleted afterwards.

- `bex postgres update dpg-dbrijmhens8c73fghqf0 --connection-pool pgbouncer --confirm -o json` exited 1 with:
  `Error: received response code 400 (POSTGRES_CONNECTION_POOL_PLAN_UNSUPPORTED): connection pooling requires a paid Postgres plan; disable connection pooling before selecting the free plan`
- `bex postgres update dpg-dbrijmhens8c73fghqf0 --disk-autoscaling --confirm -o json` exited 1 with:
  `Error: received response code 400 (POSTGRES_DISK_AUTOSCALING_PLAN_UNSUPPORTED): disk autoscaling requires a paid Postgres plan; disable disk autoscaling before selecting the free plan`
- The raw REST request answers the same message. `PATCH /v1/postgres/dpg-dbrijmhens8c73fghqf0` with `{"connectionPool":"pgbouncer"}` answered `400 {"code":"POSTGRES_CONNECTION_POOL_PLAN_UNSUPPORTED","error":"connection pooling requires a paid Postgres plan; disable connection pooling before selecting the free plan","id":"bad_request",…,"params":{"field":"connectionPool","plan":"free"}}`.

Neither request changed the plan, and nothing was written: a later read showed `connectionPool: none`.

## Root cause

`CheckDatabaseAdmission` (`lego/backend/internal/postgres/admission.go:43-44`) runs each check in two cases:

- **The request turns the feature on:** `current == nil` or `!current.Spec.Pooler` (`!current.Spec.DiskAutoscaling` for autoscaling).
- **The request changes the plan:** `planChanged`.

Both cases share one fixed message (`:112`, `:116`), and its remedy only fits a plan change on a database that already has the feature. The read-replica refusal just above (`:88-98`, w8/246) picks its remedy from the same facts.

## Fix

Pick the remedy from what the request did, as the read-replica branch does. Keep the codes, `params` and the first clause.

- **Feature turned on, no plan change** (an update where `!current.Spec.Pooler`/`!current.Spec.DiskAutoscaling` and `!planChanged`): "connection pooling requires a paid Postgres plan; choose a paid plan (for example basic-256mb) to enable connection pooling". The same shape applies to disk autoscaling.
- **Create** (`current == nil`): the same remedy, or "choose a paid plan or leave connection pooling off".
- **Plan change onto free while the feature is on:** keep today's "disable connection pooling before selecting the free plan".

## Resolution

**DONE 2026-11-13.** `paidFeatureRemedy` (`lego/backend/internal/postgres/admission.go`) fits both refusals' remedy to what the request did, as the read-replica refusal does.

- **Moving a database that has the feature onto the free plan** keeps "disable connection pooling / disk autoscaling before selecting the free plan".
- **Asking for it on a free plan** (a create, or an enable on a free database) now reads "choose a paid plan (for example 0.1c-256mb) to enable connection pooling / disk autoscaling".
- **Unchanged:** the codes, `params` and the first clause.
- **Tests:** `TestPlanRefusalsNameThePlanAsTyped` gains the six cases, and the four create and enable cases fail without the change.
- **Production check after the next roll:** the 2edc CLI commands on a free fixture print the "choose a paid plan" remedy.
