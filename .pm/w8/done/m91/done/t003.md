## Closed — 2026-11-16 (loopx session)

- **No surface change.** The tools arrive through the image every native build already uses. REST, GraphQL, MCP, Blueprint and the dashboard keep their schemas, fields and error shapes; nothing gains a toggle. ADR060 D7 records the tool table and versions. Render's [native tools table](https://render.com/docs/native-runtimes#tools-and-utilities) lists `postgresql-client` at build and runtime on Debian 12, and bex now matches it. Render names no client version; bex ships `postgresql-client-18` 18.7, which is at least the default managed server's major, 18.
- **Two-client replay on production** (pin `7aaa8700befa`, 2026-11-16):
  - Fixtures were created in bex-canary on Free: published bex v0.7.0 and the unmodified Render CLI at the same pin (`render-oss/cli` `4fd34231b637`, built from the module cache) each created one.
  - Each create used the frozen original backup-processing build and start commands from `testdata/native-utilities/original-cases.json`, with no installer prefix. They are byte-identical except the per-client marker (`QA402_6456de_bex` / `_render`).
  - Each kept the public source `git-fixtures/basic@6ecf0ef`, `NODE_VERSION=24` and the base64 archive as a secret file.
  - Both CLIs read back both services the same way: repository, branch, Free plan, `node` runtime, and the exact build and start commands. REST read back `NODE_VERSION=24` and the secret file's SHA-256 (`8697ff56…`). Results are in t006.
- **Other tools.** Bounded follow-ups already exist as m93–m103 and m107, gated on this adoption. No blanket tool claim follows from this milestone.
