## Objective

Make completion respect current Blueprint settings and expose consistent busy/interrupted/not-found outcomes through the existing product surfaces.

## Context

- Parent milestone: [w8/m37 — Blueprint lifecycle consistency](../README.md), user-approved on 2026-09-08.
- prepareSyncManifest copies name/path/autoSync from a previously read Blueprint into UpsertBlueprint; completion also uses the old AutoSync value.
- The dashboard already has status badges, sync history, protected confirmation, settings controls, and resource-not-found handling.

## Steps

1. Patch only the fields owned by a sync; retain current name/path/autoSync settings rather than copying a stale whole row.
2. Define the status projection when Auto Sync is disabled during a run, so successful completion does not accidentally re-enable automation.
3. Map busy, interrupted, and disconnected results consistently in REST/GraphQL/MCP and existing dashboard controls/history.
4. Verify API-driven activity and two-tab interactions refresh to a consistent state. Preserve pending/ready geometry if rendering changes.

## Acceptance criteria

- [ ] A completing sync cannot undo a name/path/autoSync change or overwrite disconnected status.
- [ ] Auto Sync disabled remains disabled and its displayed status follows the documented projection.
- [ ] Busy/interrupted outcomes are actionable across adapters and dashboard; stale dead-ID pages use normal absence handling.
- [ ] Protected confirmation remains required where applicable, and hidden controls never replace backend authorization.

## Out of scope

- Redesigning the Blueprint detail page or adding new lifecycle products.
- m38's webhook discovery and durable delivery changes.
