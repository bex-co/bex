# `RENDER_CLI_CONFIG_DIR` is silently ignored and `bex` writes the real `$HOME/.bex/cli.yaml` instead

Why: a user or harness that isolates CLI state with `RENDER_CLI_CONFIG_DIR` — the form upstream v2.26.0 **recommends** — gets no isolation and no warning: `bex` reads and writes the operator's actual credential file. This sweep hit it for real and overwrote the active workspace in `~/.bex/cli.yaml`.

Source: live CLI QA sweep 2026-09-15 (`/qa-find-bugs-cli`, sweep 3), upstream pin v2.27.0 (`a764810a768202704e7206eb7b87a47211fcd98e`), `go build` of `lego/cli` at HEAD `7502e7217`.

Directly continues `.pm/w4/done/063.md`, which fixed the *help text* for this area and recorded at its Finding 1: _"no behavior of a supplied `RENDER_CLI_CONFIG_DIR` override is claimed from this probe."_ This note closes that unverified residual. Not a duplicate.

## Severity: major

Silent write to the real credential store when the user explicitly asked for isolation. Not a blocker (no core journey is broken), but it destroys state without any signal.

## Repro

Against a local capture sink, with **no** `BEX_CLI_CONFIG_*` set:

```sh
RENDER_CLI_CONFIG_DIR=$TMP/rdir bex workspace set tea-x1
# stdout: Workspace set to: QA Sink WS (tea-x1)
# exit 0
# $TMP/rdir/        -> empty, nothing written
# ~/.bex/cli.yaml   -> REWRITTEN (workspace + workspace_name replaced)
```

Control cases in the same run, all correct and matching the documented contract:

| # | env | config written | verdict |
| --- | --- | --- | --- |
| 1 | `BEX_CLI_CONFIG_DIR` | `<dir>/cli.yaml` | ✅ |
| 2 | `BEX_CLI_CONFIG_DIR` + `BEX_CLI_CONFIG_PATH` | the exact PATH | ✅ PATH wins |
| 3 | both + `RENDER_CLI_CONFIG_PATH` | the RENDER path | ✅ RENDER wins |
| 4 | `BEX_CLI_CONFIG_PATH` + empty `RENDER_CLI_CONFIG_PATH` | the BEX path | ✅ empty = unset |
| 5 | `BEX_CLI_CONFIG_DIR` + `RENDER_CLI_CONFIG_DIR` | the BEX dir | ⚠️ RENDER dir ignored |
| 6 | **`RENDER_CLI_CONFIG_DIR` alone** | **`$HOME/.bex/cli.yaml`** | ❌ **the finding** |
| 7 | `BEX_CLI_CONFIG_DIR` + empty `BEX_CLI_CONFIG_PATH` | the BEX dir | ✅ |

## Root cause

`lego/cli/internal/bridge/bridge.go:57-73` — when `RENDER_CLI_CONFIG_PATH` is unset, `apply()` **unconditionally sets** it to the Bex exact path, else the Bex dir, else `$HOME/.bex/cli.yaml`.

Upstream `pkg/config/config.go:98-108` (`getConfigPath`) checks `RENDER_CLI_CONFIG_PATH` **first** and only consults `ConfigDir()` — the sole reader of `RENDER_CLI_CONFIG_DIR` — when that is empty.

Because the bridge always populates `RENDER_CLI_CONFIG_PATH`, upstream's `RENDER_CLI_CONFIG_DIR` branch is **unreachable in `bex`**. The variable is not rejected, not warned about, and not honored; the write silently lands on the default Bex path.

## Fix (needs a decision)

Two defensible options — pick one before implementing:

- **A (recommended): honor it.** In `apply()`, skip setting `RENDER_CLI_CONFIG_PATH` when *either* `RENDER_CLI_CONFIG_PATH` **or** `RENDER_CLI_CONFIG_DIR` is explicitly set and non-empty, letting upstream's own PATH > DIR > default precedence run. Consistent with the existing "explicit `RENDER_*` inputs win" rule and with the skill's model of inherited upstream overrides. Note the upstream default under this path is `$HOME/.render`, not `$HOME/.bex` — only reachable if the user sets the variable themselves.
- **B: fail loudly.** Exit non-zero when `RENDER_CLI_CONFIG_DIR` is set, telling the user to use `BEX_CLI_CONFIG_DIR`. Safe, but diverges from the inherit-`RENDER_*` model and breaks anyone currently setting it harmlessly.

Whichever is chosen, also correct the `workspace set` help override (`lego/cli/internal/branding/branding.go:93-99`), which states the precedence and mentions only `RENDER_CLI_CONFIG_PATH`.

## Blast radius

- `bridge.apply()` is the single resolution point; `isSet` (`bridge.go:113`) already has the non-empty semantics needed.
- `bridge/transport.go` `controlPlaneHosts` resolves the config file to build the header allow-list — it must follow the same resolution, or `X-Bex-CLI-Version` stamping drifts from the config actually in use.
- `lego/cli/main_test.go:805` currently asserts `RENDER_CLI_CONFIG_DIR` is **absent** from `workspace set` help. If option A is taken, that assertion has to change; if option B, it should assert the new error instead.

Closed 2026-09-15 (option A): `apply()` leaves `RENDER_CLI_CONFIG_PATH` unset when `RENDER_CLI_CONFIG_DIR` is non-empty so upstream PATH > DIR > default runs; `workspace set` help documents DIR; hermetic tests cover DIR-alone never writing `$HOME/.bex/cli.yaml`. Explicit `RENDER_*` still wins over Bex directory inputs (including DIR + `BEX_CLI_CONFIG_DIR`).

## Incident note from this sweep

The case-6 probe rewrote `~/.bex/cli.yaml` at 21:52:45 PDT: `workspace` became `tea-x1` and `workspace_name` became `QA Sink WS`. `api.key`, `api.refreshtoken`, `api.expires_at` and `api.host` (`https://api.bex.co/v1/`) were **preserved** — the login is intact and the host was never contaminated. The original workspace id was not recorded anywhere before the overwrite and could not be recovered. Recovery is one command: `bex workspaces` then `bex workspace set <id>`. No further edits were made to that file.
