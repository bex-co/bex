## Closed — 2026-11-16 (loopx session)

- **Render's contract.** [render.com/docs/native-runtimes](https://render.com/docs/native-runtimes) lists `pandoc` under "Tools and utilities" with 🟢, "Available both during builds and at runtime" (read 2026-11-16). It says every native runtime runs on Debian 12 "bookworm" and names no Pandoc version. bex supplies Debian 12's `pandoc` 2.17.1.1, so the version is the one that base carries, and its formats and filters follow the package. bex installs no PDF engine (`pdflatex` and others), and Render's list names none.
- **No surface change.** The tool arrives through the image every native build already uses. REST, GraphQL, MCP, Blueprint and the dashboard keep their schemas, fields and error shapes, and nothing gains a toggle or a launcher change.
- **Two-client replay on production** (pin `7aaa8700befa`, 2026-11-16, details in t006):
  - Published bex v0.7.0 and the unmodified Render CLI at the same pin (`render-oss/cli` `4fd34231b637`, rebuilt from the module cache) each created one Free service in bex-canary.
  - Each create used the frozen original build and start commands from `testdata/native-utilities/original-cases.json`, with no installer line. They are byte-identical except the per-client marker (`QA407_12b88f_bex` / `_render`).
  - Each kept the public source `git-fixtures/basic@6ecf0ef`, `NODE_VERSION=24` and `--auto-deploy=false`.
  - Both CLIs listed both services identically: repository, branch, Free plan, `node` runtime, auto-deploy off and the exact build and start commands. REST read back `NODE_VERSION=24` on both.
