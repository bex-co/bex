## Objective

Rewrite ADR049 § "One blueprint per repo+branch" against Render's Replicating documentation (quoted in the milestone README) and record the rules the code will follow.

## Steps

1. State that a workspace may hold several Blueprints for one repo+branch+path, each identified by its id.
2. Decide and record: what a second create in `adopt` mode does when the first Blueprint manages the same-named resources (keep `BLUEPRINT_RESOURCE_CONFLICT` and its takeover phrase; never a silent move); what the legacy one-step create/sync does for a repeated source; whether "re-connect the same path" (the retry after a failed apply) is kept and how it is told apart from a deliberate second Blueprint.
3. Update the ADR018 Blueprint row. If any difference from Render remains, it needs the user's sign-off there.

## Acceptance criteria
