## Objective

A Blueprint row is created by insert and changed by id. Remove the uniqueness constraint (`migrations/0016_blueprints.up.sql:14`) with a new migration and replace the `ON CONFLICT (tenant_id, repo, branch)` arms (`store/blueprints.go:129`, `store/blueprint_lifecycle.go:261`, `store/blueprint_plans.go:98`).

## Acceptance criteria

- [x] Two live rows for one repo+branch can exist; updates and deletes address one row by id. (`TestPGCreateIsANewBlueprintExceptARetry`, `TestPlannedBlueprintSyncsPG`.)
- [x] A create after a delete mints a new id instead of reviving the deleted row (or ADR049 records why reuse is kept). (New id on both creates; the deleted row stays disconnected. The one reuse, the retry of a failed one-step create, is recorded in ADR049.)
- [x] Migration applies on a populated database (real-Postgres store tests). (`0229_blueprints_per_source`; `TestPGBlueprintsPerSourceMigration`; the full backend suite, 77 packages, passes on real Postgres.)
