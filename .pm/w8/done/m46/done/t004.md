## Objective

When a trigger is accepted while another deploy is open, close the older one `canceled` (superseded) **by intent**, not as a side effect of generation churn, so the newest always proceeds. Cover the deploy hook, restart and rollback.

## Acceptance criteria

- [ ] With A then B concurrently, B is `live` and A is `canceled`, 10/10 in the t001 harness.

## Outcome (2026-09-27) — done

With triggers serialized, every accepted trigger's release generation is strictly greater than the previous one and the CR's release annotation names the newest. The existing reconciler supersede (`supersededDeployStatus` → `canceled`, reason naming the newer deploy) then closes every earlier open row by that ordering, so it happens by intent, not generation churn. `CreateDeploy`'s overlap slot already cancels an older queued row. The test asserts older < newer == CR release, CR/row image = the newest row's, and the newest row never opens canceled. The deploy hook and restart go through `triggerFetched` and rollback through `openRelease`, so all share the path.
