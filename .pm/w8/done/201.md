# Blocker: every new prebuilt-image web service fails its first deploy with `image metadata request returned status 307`: the operator refuses the registry's blob redirect

Why: since w4/m243 (Docker web services serve on their image's exposed port), every new image web service, with or without `PORT`, reads the image config through `registry.ReadImageConfig`. Docker Hub (and GHCR, ECR, GCR) serve config blobs through a redirect to CDN/presigned storage, and the reader refuses every redirect. So every new Docker Hub image web service deploys `update_failed` and never serves, which is the most common Render onboarding path.

Severity: **blocker**. Source: `/qa-find-bugs-cli` loop sweep v9p3, 2026-10-25 23:55 UTC, bex v0.3.3, pin Render CLI v2.27.0 `a764810a7682`, platform pin `2331a3dadbc1` (after the w8/200 CRD fix), `https://api.bex.co/v1/`, `bex-canary`, human device login.

## Root cause

`lego/operator/internal/registry/image_config.go` `readImageConfigDocument` sets `CheckRedirect` to return `http.ErrUseLastResponse` for every request. That includes `blobs/<config digest>`, so the 307 becomes `image metadata request returned status 307`. m243's tests used an in-memory registry that serves blobs directly. bex's own zot registry (native builds, `ReadImageRevision`) doesn't redirect, which is why native services kept working.

## Fix (shipped with this note)

Manifest reads still refuse redirects, so the credential and the trust anchor stay on the registry. Config blob reads follow at most 3 redirects, only to `https` URLs. The registry `Authorization` header is dropped on every hop (presigned URLs carry their own authorization, and S3 rejects a second one). The blob is content-addressed and its sha256 is verified against the manifest, so a redirect cannot substitute content. The dialer still refuses metadata IPs. New test `TestReadImageConfigFollowsBlobStorageRedirect` covers credentialed and anonymous storage redirects (pass, no credential at storage) and plaintext, redirect-loop and tampered-content redirects (fail closed). It fails on the old code. Blast radius: only `ReadImageConfig`/`ReadImageRevision` go through this path; `livetag.go` reads manifests only.
