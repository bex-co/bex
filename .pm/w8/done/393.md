# A failed build or a start command that exits closes its log with bex's `==> Build failed: …` or `==> Deploy failed: …`, where Render's closes with `==> Build failed 😞` or `==> Exited with status N`, then its troubleshooting line

Why: w8/391 matched Render's closing for a deploy that runs out its rollout budget. Every other failed deploy still closes with bex's own line and without Render's troubleshooting line, and no user sign-off lets that stand.

- Severity: minor. Only the wording differs; the deploy fails the same way.
- Render, from deploy logs users quoted in GitHub issues (`gh search issues "Common ways to troubleshoot your deploy"`, read 2026-11-21): every failed deploy's log ends with `==> Common ways to troubleshoot your deploy: https://render.com/docs/troubleshooting-deploys`. The line before it is:
  - `==> Build failed 😞` for a failed build: thephm/the-beans#417 (2026-09-30), EthanM32122/cloaket#1 (2026-09-22), thedimlebowski/soakup#35 (2026-06-12), MeganHarrison/ai-agent-mastery#33 (2025-09-19).
  - `==> Exited with status N` for a start command that exits: darthjee/ward#109 (2026-11-14), eoinoconn/intervals-mcp-server#51 (2026-11-01), rkendel1/freq#187 (2026-07-14).
  - `==> Timed Out` for the rollout budget, which w8/391 shipped.
- bex: `terminalLines` (`lego/backend/internal/logs/progress.go`) writes `==> Build failed: <failureReason>`, `==> Pre-deploy failed: <failureReason>` and `==> Deploy failed: <failureReason>` (w5/064), with no troubleshooting line.
- Not yet observed: Render's lines for a failed pre-deploy command, an image pull failure and an out-of-memory kill, and whether any carries the cause. Confirm each from a 2026 log before changing it.
- Dedupe: w8/391 is only the rollout-budget close. w8/291 (done) left `Build failed 😞` unconfirmed. w4/m324 t009 (done) is the wording of the build command's failure reason, and w8/386 the early exit's. None covers the closing lines.

## Fix

For each failure Render's logs confirm, write Render's closing line and the troubleshooting line, as `terminalLines` does for the rollout budget since w8/391. Decide from the evidence where bex's failure reason goes: Render's log carries it only in Render's own lines, and the deploy page's header shows it. Amend ADR018 § Logs, Build logs, and `docs/render-artifacts/live-deploy-following.md`.

## Acceptance

- Unit tests: each confirmed failure closes with Render's lines, and an unconfirmed one keeps bex's.
- Live in `bex-canary`, on a free web service whose build command is `exit 1`: `bex logs --type build` ends with `==> Build failed 😞` and the troubleshooting line. Delete the fixture by ID and confirm the 404.

Estimate: ~1h.
