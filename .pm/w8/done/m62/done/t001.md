Reject actual NUL bytes in newly supplied application environment values through a small shared core guard and Blueprint semantic preflight.

3. Use existing validation errors with source paths; keep the pinned client unchanged.

## Done 2026-10-12

`core.ValidEnvValue`/`CheckEnvValue`/`EnvValueSentence` (`lego/backend/internal/core/config.go`) are the one rule; Blueprint `parseEnvGroup` and `classifyServiceEnv` (`apps/deploy.go`) refuse NUL in group literals, service literals, `sync:false` seeds and prompt answers with the entry location, so `ValidateBlueprint` returns `valid:false` for all three finding documents while the newline controls stay valid (`TestBlueprintValidationRefusesANULEnvValue`). Errors name the key, never the value. The native exit1 receipt needs the deployed API (t003).
