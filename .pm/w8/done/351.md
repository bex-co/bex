# A metrics read with a decimal `resolutionSeconds` (`60.0`, `90.5`, `1e2`) answers 400 with a raw `strconv.Atoi` error, though Render's spec types it as a number

Why: the pinned Render client sends `resolutionSeconds` as a `float32` and Render's OpenAPI types it `number` (minimum 30), so a value like `60.0` from a JSON-number-minded client is valid on Render, while bex refuses it with a Go parser message no customer should see.

- Severity: minor. Integer values work, and the refusal is a 400, not a wrong answer. But the message leaks an internal error string, and a spec-valid request fails.
- Versions: production `https://api.bex.co/v1/` on 2026-11-20 13:18 UTC; Render CLI pin `4fd34231b637` (`pkg/client/metrics/metrics_gen.go:269`: `type ResolutionParam = float32`); bex CLI v0.7.0 has no metrics command, so this is REST only.
- Context: routine `cli-qa` run `rt13-5f51`, QA human device-flow token, workspace `bex-canary`, free image web service `srv-dc04eu4d1ruc73b8cng0` (run-owned, deleted afterwards).

## Repro

```text
GET /v1/metrics/memory?resource=<srv>&resolutionSeconds=120   → 200, 3 series
GET /v1/metrics/memory?resource=<srv>&resolutionSeconds=60.0  → 400 {"error":"resolutionSeconds: strconv.Atoi: parsing \"60.0\": invalid syntax","id":"bad_request","message":"resolutionSeconds: strconv.Atoi: parsing \"60.0\": invalid syntax"}
GET /v1/metrics/memory?resource=<srv>&resolutionSeconds=1e2   → 400 (same, parsing "1e2")
GET /v1/metrics/cpu?resource=<srv>&resolutionSeconds=90.5     → 400 (same, parsing "90.5")
GET /v1/metrics/cpu?resource=<srv>&resolutionSeconds=29       → 400 invalid query parameter "resolutionSeconds"   (the spec's minimum; fine)
```

## Cause

The OpenAPI request validator (`lego/backend/internal/api/render_openapi.go`) accepts any `number` ≥ 30, as the spec says. The handler's `parseTimeWindow` (`lego/backend/internal/metrics/rest.go:346-351`) then parses it with `strconv.Atoi` and returns the wrapped Go error as the 400 message. `quantile`, the other numeric query parameter in the same file, already uses `strconv.ParseFloat` (`rest.go:437`).

## Fix

In `parseTimeWindow`, parse `resolutionSeconds` with `strconv.ParseFloat` and accept any finite value ≥ 30 the spec's `number` admits (`60.0`, `1e2`, `90.5`). Use it as the step, rounded to whole milliseconds (Prometheus takes fractional steps) or to whole seconds; either is fine, but say which in a comment. A non-number, NaN or infinity gets a clean 400 such as `resolutionSeconds must be a number of at least 30`, never a `strconv` string.

Blast radius: `parseTimeWindow` serves every App metrics path and every datastore metrics path (`rest.go:373`, `rest.go:423`). The pinned spec declares `resolutionSeconds` on 18 metrics operations (`cpu`, `cpu-limit`, `cpu-target`, `memory`, `memory-limit`, `memory-target`, `http-requests`, `http-latency`, `disk-usage`, `disk-capacity`, `instance-count`, `active-connections`, `replication-lag`, `filters/application`, `filters/http`, `filters/path`, `task-runs-queued`, `task-runs-completed`). GraphQL and MCP take integer resolutions of their own and are unaffected.

## Acceptance

- `GET /v1/metrics/cpu?resource=<free srv>&resolutionSeconds=60.0` answers 200 with the same series as `resolutionSeconds=60`.
- `resolutionSeconds=1e2` answers 200; `resolutionSeconds=90.5` answers 200.
- `resolutionSeconds=abc` and `resolutionSeconds=29` still answer 400, and no 400 on any metrics path contains `strconv`.
- A unit test in `lego/backend/internal/metrics` covers the integer, decimal, exponent and invalid cases.

## Not verified

Render's live answer to a fractional value (whether it rounds or refuses). The conclusion rests on the spec's `number` type and the pinned client's `float32`.

Dedupe: `rg resolutionSeconds .pm` finds only coverage records of integer values (w4/345, w4/m175, w6/065, w3/m487); no item covers a decimal value or the `strconv` message.

Estimate: ~20m.

## Parked 2026-11-20

A non-number, NaN, infinity or a value below 30 is one 400, `resolutionSeconds must be a number of at least 30`, on Render's paths and on bex's own ungated datastore paths (`disk`, `db-connections`, `kv-memory`, …). A value past 1e9 s is bounded so `time.Duration` cannot overflow.
