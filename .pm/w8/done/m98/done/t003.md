## Closed — 2026-11-19 (loopx session)

Audited on main; the chain is the one w8/m94, w8/m95 and w8/m97 t002 traced, and nothing since touches the base, the tools or their paths.

- **One recipe chain.** `nativeDockerfile` (`native.go`) has one caller, the native build Job's preparer environment. `cmd/native-resolve` ends with `applyNativeCommonBase` (`nativeresolve.go` → `nativebases.go`), so every native web service, private service, worker, cron job and static-site build starts from the common image, whatever the primary (Node, Python, Ruby, Elixir, Go, Rust) and its companions.
- **Phases.** Build, pre-deploy and runtime run one image: the pre-deploy Job runs the image the build produced. A static site's image is only its publish Job's extract source, so it gets jq and rsync at build only, which is all a static site has.
- **Resolution.** `applyNativeCommonBase` re-copies only `/usr/local` from the selected primary, then runs `ldconfig`. jq and rsync are `/usr/bin/jq` and `/usr/bin/rsync`, their libraries are under `/usr/lib/<triplet>`, and no primary image ships either program, so nothing shadows them; the historical failure itself showed the Node 24 primary had neither. No `LD_LIBRARY_PATH` or tool variable is set, so an authored `PATH` keeps its meaning.
- **Cache.** The base is digest-pinned. Tenant source and environment changes do not touch its layers; a package change is a new digest that misses the cache. Neither tool keeps a cache under `$XDG_CACHE_HOME`.
- **Exclusions.** Dockerfile, prebuilt-image and buildpack services never enter this recipe. A static site with no build command builds no native image.
- **Neighbors kept.** FFmpeg, Pandoc, SQLite, libvips, Ghostscript, the PostgreSQL clients, native-init and the companion and package-manager steps are unchanged; m98 changes no product code.
- **Exercised versus source-only.**
  - Production (t007): build and runtime, Node 24.22.3, both CLIs, on `4b809600…`.
  - Maintained cohort: the frozen m98 program on the Node primary at build and on a network-off runtime (`node-compute`, through `original-cases.py`); the jq and rsync checks at the Node compute build, its network-off runtime and the static build; and the `missing-jq` and `missing-rsync` omissions on the Node primary (t006).
  - Families runs on the same digest: the other primaries, companions, native-init and static.
  - Not executed: a hosted pre-deploy run (Free refuses `preDeployCommand`, as Render does) and ARM64 (D3).
