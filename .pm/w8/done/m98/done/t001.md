## Closed — 2026-11-19 (loopx session)

The adopted common base (w8/m91 t007/t008) is the supplier. `deploy/native-base/install.sh` installs Debian's `jq` with `--no-install-recommends`, which pulls its normal closure. The SPDX attestation of `sha256:4b809600…` (production's `nativeCommonBase` at pin `dff52c596d13`), fetched again from the registry on 2026-11-19, lists `jq` and `libjq1` `1.6-2.1+deb12u3` and `libonig5` `6.9.8-1`. That is Debian 12's package, the base Render names for its native runtimes.

- **What travels together.** `/usr/bin/jq` (`jq-1.6`), `libjq.so.1` and Oniguruma's `libonig.so.5`, which jq's regular-expression builtins need. Nothing is copied by hand: no bare executable or donor root filesystem.
- **Phases.** `/usr/bin` and `/usr/lib` are outside the primary's `/usr/local` copy, so jq is present before source and authored commands at build, pre-deploy and runtime (t003). Both production builds and their runtime requests report `jq-1.6` (t007).
- **Environment.** bex sets no jq variable, so authored values and `PATH` keep their meaning.
- **Identity.** A changed package is a new image digest, so a reviewed pin change is re-qualified by a families run. The common image's `toolchain-freshness.json` entry and the ADR060 D7 table inventory it. `check-tools.py` filters JSON with `jq` at every publication.
- **Not chosen.** Trixie or upstream jq 1.7: the user's 2026-10-29 decision put every utility on the one Bookworm image as distribution packages. Render names no jq version, so the version is not asserted to match Render's. One 1.6 trait authors may notice: malformed input exits 4, where jq 1.7 exits 2; both are nonzero, so a build step stops either way.
