# Platform-generated responses carry no `x-render-routing` header: an unknown host, a suspended service and a waking Free service look like the app's own 404/503

Why: when Render's edge answers in place of the service, it tags the response with `x-render-routing`. Values seen live:

- `no-server`: 404 for a host with no running service;
- `suspend`: 503 "Service Suspended";
- `hibernate-pending-wake`: the Free-tier wake page, captured in `docs/render-artifacts/wake-interstitial.md`.

The header is undocumented, but developers and their agents use it to tell "the platform has no server for this" from "my app returned 404/503". Public debugging threads cite `x-render-routing: no-server` to diagnose a wrong hostname, a crashed service or a static root with no rewrite ([1](https://github.com/Martiherenu1/ProyectoVanFull/issues/125), [2](https://github.com/daniel2004-lsd/Movil-EcoRuteando/pull/24), [3](https://github.com/victordeoliveira255-eng/Synara/pull/5)). bex already mirrors Render's edge `rndr-id` on these same responses, but sends no routing tag. A script or agent written against Render's signal (`curl -sI … | grep x-render-routing`) cannot tell an edge 404/503 from an app 404/503 on bex.

Severity: **minor** (diagnostic signal; status codes and bodies are correct). Attribution: operator (`lego/operator/cmd/activator`). Estimate: ~30m. Source: `/qa-find-bugs-cli` loop sweep 3093, 2026-10-28 11:30–12:01 UTC. Context: platform pin `838feec85fdd`; `https://api.bex.co/v1/`; workspace `bex-canary`.

## Root cause

The activator's response writers set only `Cache-Control`, `Retry-After` and `Content-Type`. They are `writeWakeResponse`, `writeSuspendedResponse` → `writeNotServing`, the unknown-host `writeNegotiated(…, http.StatusNotFound, …)` (`main.go:356`) and the first-deploy/maintenance pages. No routing tag is set anywhere (`rg -i 'render-routing' lego` finds nothing).

## Proposed fix

In the activator, set `X-Render-Routing` on every response the platform generates instead of the app:

- `no-server` on the unknown-host 404;
- `suspend` on the suspended 503;
- `hibernate-pending-wake` on the wake 503 (HTML and JSON variants).

For states without a captured Render value (first deploy in progress, maintenance mode, a bex "no running instance"), pick from evidence. Capture Render's value for maintenance mode first; if a value can't be captured, use `no-server` for "nothing to route to". Record each choice in ADR007. App-served responses must never carry the header, and a saved static-site header rule must not be able to forge one on a platform response. A test pins the header for each activator state.

## Outcome (2026-10-28)

Fixed in the activator (`lego/operator/cmd/activator`). Every answer it gives in place of the service now carries `X-Render-Routing`:

- `no-server`: unknown host; an awake App failing its health check; a proxy 502; a failed or canceled first release; a first deploy in progress; maintenance.
- `suspend`: a suspended service.
- `hibernate-pending-wake`: the wake page or JSON of a hibernated App, and a held request's 504 wake timeout.

The tag is set only on platform answers, never on a request proxied to the woken App. The `/robots.txt` of a spun-down service stays untagged. The value table and the reasons for the uncaptured states are in ADR007 § Platform routing tag.

Tests:

- `TestPlatformResponsesCarryRenderRouting` pins each state in HTML, JSON and plain text.
- The hold tests assert that the App's own proxied response is untagged, the 504 is tagged, and the awake-unready answer is `no-server`.
- A mutation check (dropping the `suspend` tag) fails the table test.
- Operator `make test` and golangci-lint pass.
