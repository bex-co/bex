# Updating a build source stores `git.dockerContext` and `git.dockerfilePath` unchecked: `../x` is accepted, and `./` is kept as typed rather than relative to the Root Directory

Why: every other surface that writes a Docker build's context or Dockerfile path judges it with the repository path rule (`store.RootDirProblem`: no `..`, not absolute, no backslash or control character) and stores the context relative to the Root Directory through `storedDockerContext` (w8/m128, w8/292). A build source's update (ADR097, `PATCH /v1/build-sources/{id}` and its GraphQL/MCP twins) does neither, so a value create would refuse is stored, and the stored context does not mean what the same value means on a service.

**Severity:** minor until the reach of a stored `../x` is checked (see Unverified). **Attribution:** server (bex-api build sources). **Estimate:** ~45m. **Source:** the `/simplify` review of w8/292, 2026-11-12 (`/loopx w8`), traced in code; not reproduced on production.

## Evidence (code)

- `lego/backend/internal/apps/build_sources.go:657-689`: `buildSettings.apply` sets `a.Spec.DockerfilePath` and `a.Spec.DockerContext` from the patch as sent (`set(&a.Spec.DockerContext, b.dockerContext)`); only `rootDir` is normalized (`store.NormalizeRootDir`), and only the runtime pairing of `dockerContext` is checked (`:686`).
- `build_sources.go:726-727`: the patch carries `g.DockerfilePath` and `g.DockerContext` straight into `buildSettings`; no `checkDockerContextPath` or `RootDirProblem` call on this path.
- `build_sources.go:694`: `equalBuildSettings` compares the raw strings, so `./` and the stored default `""` differ and a no-op update reads as a change.
- Create of a build source (`build_sources.go:218-222`) goes through `CreateRequest`, whose validation (`apps/service.go:3432-3438`) does apply the rules, so only the update path is open.

## Fix

- In the build source patch (or `buildSettings.apply`), judge `git.dockerfilePath` with `store.RootDirProblem` and `git.dockerContext` with `checkDockerContextPath`, naming the field (`git.dockerContext …`) as create does.
- Store the context with `storedDockerContext(a.Spec.RootDir, v)` after the Root Directory is applied, and compare through `wireDockerContext` (or the stored form) in `equalBuildSettings`.
- Rebase a stored context when only `rootDir` changes, as `SetRootDir` does for services (`rebaseDockerContext`).

## Regression checks

- An update with `git.dockerContext: ../x`, `/abs` or `a\b` answers 400 naming the field; `git.dockerfilePath: ../Dockerfile` likewise.
- An update with `git.dockerContext: ./` on a build source with `rootDir: backend` stores `""` and reads back `.`; `ctx/` stores `backend/ctx`.
- The same update twice is a no-op the second time.

## Unverified

- What a stored `../x` reaches in the build: whether BuildKit's context then leaves the checkout inside the build pod, and what is there. Not exercised.

## Dedupe

w8/292 (done): the same rule for services and Blueprints. w8/m128 (done): `dockerContext` relative to `rootDir`. No `.pm` item covers build-source updates.

## Shipped 2026-11-12 (`/loopx w8`)

- **Fix:** `buildSettings.apply` (`lego/backend/internal/apps/build_sources.go`) now judges a build source update's paths as create does. It refuses `git.rootDir`, `git.dockerfilePath` and `git.dockerContext` outside the repository with a 400 that names the field. It stores the context relative to the Root Directory (`storedDockerContext`, so `./` stores `""` and `ctx/` stores `<root>/ctx`), and rebases it when only the Root Directory moves (`rebaseDockerContext`). `git.rootDir` was not checked either, and the rebase would have carried a `../x` into the context.
- **Shared rule:** `checkRepoPath(field, path)` and `checkDockerContextPath(field, wire)` now name their field. Service create and update, and the build source, share them instead of three inline copies.
- **Test:** `TestBuildSourceUpdateJudgesAndStoresDockerPaths` covers the three refusals, `./` and `ctx/`, a Root Directory move (rebased), and a patch setting both at once. Its steps run in order.
- **Review** (`/simplify`, three reviewers):
  - Not changed: `opt("")` reads an empty value as "not sent", so a context is cleared with `.` or `./`.
  - Not changed: `dockerfilePath: "."` is accepted as before.
  - Not changed: a context stored outside the Root Directory before w8/m128 reads back as `../…`, and sending that back is now refused.
