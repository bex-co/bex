# `GET /v1/metrics/bandwidth-sources` answers 501 for every resource; Render serves hourly bandwidth broken down by traffic source

Why: Render's pinned OpenAPI serves `GET /metrics/bandwidth-sources`: "Get bandwidth usage for one or more resources broken down by traffic source (HTTP, WebSocket, NAT, PrivateLink). Returns hourly data points…", with `labels.trafficSource` ∈ `total|http|websocket|nat|privatelink`. Bex answers a coded 501 that points the caller at two other surfaces. A Render API client, dashboard integration or agent that charts egress by source gets an error. The data exists: bex meters per-source egress as Prometheus counters and only its query layer reduces them to month-to-date totals. ADR018's metrics row lists the 501 as a divergence without a user sign-off.

**Severity:** minor. **Attribution:** server (metrics REST adapter and query). **Estimate:** 1h30m. **Source:** `/qa-find-bugs-cli` sweep 1325, 2026-10-22 ([evidence](evidence/cli-sweep1300/README.md#sweep-1325--bandwidth-sources)).

## Reproduction

Production `https://api.bex.co/v1/`, pin `21652364739c`, `bex-canary`, read-only metadata on the pre-existing `hello-go`:

- `GET /v1/metrics/bandwidth-sources?resource=srv-daif6dsmg29s73d1umvg` → **501** `{"error":"bandwidth-sources is not served: bex keeps its per-source bandwidth (http, nat, websocket) as month-to-date totals, not time series — read /v1/metrics/bandwidth for the all-sources series, or GraphQL monthToDateBandwidth for the per-source totals","id":"internal_error",…}`.
- `GET /v1/metrics/bandwidth?resource=…` → 200 with a per-minute all-sources series.

## Expected

200 with Render's response shape: `{data: [{labels: {resource, trafficSource}, values: [{timestamp, value}]}]}` (check the exact envelope against the pinned schema), one series per traffic source plus `total`, at hourly resolution, honoring `startTime`, `endTime` and `resource` (multi-resource) as the spec defines. Sources bex does not have (`privatelink`) are omitted or zero, as the spec allows. Requests before the earliest retained data follow the spec's 400 rule. The error id should not be `internal_error` in any case: an unserved route is not an internal error.

## Root cause

`lego/backend/internal/metrics/rest.go:87–89` registers the route as a fixed 501. Per-source counters exist in Prometheus (`lego/backend/internal/egressquery/query.go:59–84`: `bex_websocket_egress_bytes_total` (websocket), `bex_app_direct_egress_bytes_total` (nat/direct), the HTTP edge counters, and the pg/kv proxy counters). `metrics/service.go:1243` `MonthToDateBandwidth` sums them per month for GraphQL.

## Fix

Add a range query per source, using `sum by (source) (increase(<counter>{matchers}[1h]))` at a 1-hour step over the requested window, through the same egress-meter health gates `/v1/metrics/bandwidth` uses (`egressquery` health metric). Map bex's sources onto Render's enum (`http`, `websocket`, `nat` for direct egress; datastore proxy egress counts under its own resource) and add `total`. Serve the result in the pinned shape, add the route to `api/render_metrics_contract_test.go`'s served set, and update ADR018's metrics row.

## Blast radius

One REST route. GraphQL `monthToDateBandwidth` and `/v1/metrics/bandwidth` are unchanged.

## Acceptance

- Live after deploy: the read above returns hourly per-source series for `hello-go` (zeros allowed). Its `total` agrees with `/v1/metrics/bandwidth` summed per hour.
