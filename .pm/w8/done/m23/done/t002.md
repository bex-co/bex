## Objective

Before any write, blueprint create/sync checks each planned adopt/update target's ownership marker: owned by another blueprint ⇒ refuse the whole apply with one coded conflict error (e.g. `BLUEPRINT_RESOURCE_CONFLICT`, 409-class; names the resource + owning blueprint id) — unless the request carries the explicit takeover confirmation, which transfers ownership and proceeds. Unowned resources adopt freely as today.

## Context

- Confirmation-flow precedent: the existing protected-resource `confirmation_required` handshake already used by blueprint create/sync and the dashboard's `ProtectedConfirmationDialog` — extend that shape rather than inventing a second one.
- Coded-error precedent: `BLUEPRINT_GROUPING_LIMIT` (m20) / `AGENT_SESSION_LIVE_LIMIT` — identical body across REST/GraphQL/MCP.
- Check runs in the plan phase (`blueprint_state_plan.go`) so `PreviewBlueprint` also reports the conflict before anyone syncs.

## Steps

1. Add the ownership check to the planner; thread the takeover flag through create/sync requests on all three surfaces.
2. Dashboard: conflict rendered in the m21 pre-sync review + create review, reusing the confirmation dialog.
3. Auto-sync path (`triggerBlueprintSync`): a conflict marks the sync run `error` with the coded message — never silent takeover from a webhook.
