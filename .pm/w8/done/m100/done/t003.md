## Closed — 2026-11-19 (loopx session)

- **Render's contract.** [render.com/docs/native-runtimes](https://render.com/docs/native-runtimes) marks `swig` as available both during builds and at runtime, on Debian 12 "bookworm", and names no version (read 2026-11-19). bex supplies Debian 12's SWIG 4.1.0 (t001). Which version Render ships is unverified, and no Render-hosted comparison was run.
- **SWIG's contract.** [SWIG's Python guide](https://www.swig.org/Doc4.1/Python.html) describes the pipeline exercised: `swig -python` writes the C wrapper and the proxy module, the wrapper compiles into `_<module>` against the interpreter's headers, and the proxy imports it. The library files exercised (`typemaps.i`, `exception.i`, `carrays.i`, `std_string.i`) and the `-c++`, `-I`, `-o` and `-outdir` options are the documented ones. The maintained checks run each (t005).
- **ADR060.** The D7 m100 row records the packages, the library path, the compilers and headers it builds with, the behaviors accepted and the limits: target languages other than Python, `ccache-swig` and wider C++ library wrapping are not separately accepted.
- **No surface change.** SWIG arrives through the image every native build already uses. REST, GraphQL, MCP, Blueprint and the dashboard keep their schemas, fields and error shapes, and no selector, toggle or launcher change was added.
