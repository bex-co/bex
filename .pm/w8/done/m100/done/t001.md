## Closed — 2026-11-19 (loopx session)

The adopted common base (w8/m91 t007/t008) is the supplier. `deploy/native-base/install.sh` installs Debian's `swig` in the common image's package layer, beside `python3-dev` and the compilers. The SPDX attestation of `sha256:4b809600…` (production's `nativeCommonBase` at pin `dff52c596d13`), fetched again from the registry on 2026-11-19, lists `swig` (`arch=all`) and `swig4.0` (`arch=amd64`) `4.1.0-0.2` from Debian 12. `swig4.0` owns 776 files, among them `/usr/bin/swig4.0` and the library under `/usr/share/swig4.0`.

- **The reviewed release.** `4.1.0-0.2` is Debian 12's only SWIG: bookworm's archive offers no other candidate (`apt-cache policy`, 2026-11-19). The sweep 421 control installed the same Debian package, but this one was checked on its own terms: it is the distribution build that matches the image's `gcc-12` and `python3.11-dev`, and Render names no SWIG version (t003).
- **What travels together.** `/usr/bin/swig` is the `swig` package's link to `swig4.0`. The program, its library (`swig.swg`, `swigrun.swg`, `typemaps/`, the `python/` language files and `std_string.i`) and `ccache-swig` are one package, so a binary-only copy cannot happen. The compilers (`gcc-12`, `g++-12` `12.2.0-14+deb12u1`) and Debian's Python 3.11 headers come from the same image, and a Python primary's own headers arrive with its `/usr/local`. Nothing is downloaded at build or run time, and no donor root filesystem is copied.
- **Phases.** `/usr/bin` and `/usr/share` are outside the primary's `/usr/local` copy, so `swig` is present before source and authored commands at build, pre-deploy and runtime (t002). Both production builds and every runtime request reported `SWIG Version 4.1.0` at `/usr/bin/swig` (t006).
- **Environment.** bex sets no `SWIG_LIB` or `SWIG_FEATURES`. `swig -swiglib` answers `/usr/share/swig4.0`, and an authored `SWIG_LIB` replaces it (t005).
- **Identity.** A changed package is a new image digest, which a families run re-qualifies. The image's SPDX attestation lists both packages and the ADR060 D7 table records them; `toolchain-freshness.json` tracks the image digest. Every `native-common-image.yml` run's utility cohort generates, compiles and imports SWIG wrappers on the image it publishes (t005).
