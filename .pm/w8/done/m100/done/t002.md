## Closed — 2026-11-19 (loopx session)

Audited on main. The chain is the one w8/m94, m95, m97, m98 and m99 traced, and no commit since production's pin `dff52c596d13` touches `deploy/native-base`, `deploy/native-common`, `native.go`, `nativebases.go` or `nativecommon.go`.

- **One recipe chain.** `nativeDockerfile` (`native.go`) has one caller, the native build Job's preparer. `cmd/native-resolve` ends with `applyNativeCommonBase` (`nativeresolve.go` → `nativebases.go`). So every native web service, private service, worker, cron job and static-site build starts from the common image, whatever the primary (Node, Python, Ruby, Elixir, Go, Rust) and its companions.
- **Phases.** Build, pre-deploy and runtime run one image: the pre-deploy Job runs the image the build produced. A static site's image is only its publish Job's extract source, so it gets `swig` at build only, which is all a static site has.
- **Resolution.** `applyNativeCommonBase` re-copies only `/usr/local` from the selected primary, then sets the primary's environment, `PATH` included. `swig`, `swig4.0` and `/usr/share/swig4.0` live outside `/usr/local`, and no primary image ships `swig` (the sweep 421 failure showed the Python 3.13 primary had none), so nothing shadows it.
- **Headers and compilers.** On a Python primary, `python3-config` is the primary's own (`/usr/local/bin`), so an extension builds against the selected Python's headers and suffix: production built `_qa_swig.cpython-313-x86_64-linux-gnu.so` (t006). Elsewhere `python3-config` is Debian's 3.11 from `python3-dev` in the common image, which the maintained checks use on the Node primary (t005). `gcc`/`g++` are the common image's `12.2.0`.
- **Precedence kept.** On the primaries' `PATH`, `/usr/local/bin` comes before `/usr/bin`, so a tenant's own SWIG (for example `pip install swig` on the Python primary, or a project directory put first on `PATH`) still wins. That order is read from the primary's environment and was not separately exercised.
- **Cache.** The base is digest-pinned, and tenant source and environment changes do not touch its layers. SWIG keeps nothing between runs: it writes only the wrapper and proxy where it is told, and `ccache-swig` is not used unless a build calls it.
- **Exclusions.** Dockerfile, prebuilt-image and buildpack services never enter this recipe. A static site with no build command builds no native image.
- **Neighbors kept.** The Python packaging tools and headers (w8/m103), FFmpeg, Pandoc, SQLite, libvips, Ghostscript, jq, rsync, TypeScript, Webpack, the PostgreSQL clients, native-init and the companion and package-manager steps are unchanged. m100 changes no product code.
- **Exercised versus source-only.**
  - Production (t006): build and runtime, Python 3.13.18, both CLIs, on `4b809600…`.
  - Maintained cohort: the frozen m100 program on the Python 3.13 primary at build and on a network-off runtime (`python313-original`, through `original-cases.py`); the new SWIG checks at the Node compute build, its network-off runtime and the static build; and the `missing-swig` omission on the Python primary (t005).
  - Families runs on the same digest: the other primaries, companions, native-init and static.
  - Not executed: a hosted pre-deploy run (Free refuses `preDeployCommand`, as Render does), and ARM64 (D3). Trixie is not a native base: every native build ends on the Bookworm common image (the 2026-10-29 decision).
