# A static site's 404 headers differ from Render's: its `404.html` page lacks the HSTS and cache policy every file carries, and a bare 404 carries the site's custom headers where Render's carries only `nosniff`

Why: Render handles a miss in one of two ways. It serves the site's `404.html` like any published file: the custom `headers` rules, `strict-transport-security`, its default `cache-control` and `nosniff`. A site with no `404.html` gets a bare `text/plain` `Not Found` with **only** `x-content-type-options: nosniff`, and none of the site's rules. bex differs both ways:

- its `404.html` answer drops HSTS and the cache policy;
- its bare 404 adds every matching custom rule.

w4/m101 t003 chose "every resolved-site response class carries matching custom headers" (ADR029:136) without a Render capture, and ADR018 records no sign-off for it. Parity first.

**Severity:** minor. **Attribution:** server (static-server). **Estimate:** ~30m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `cc60`, 2026-11-14 02:25 UTC, released `bex v0.6.0`, `https://api.bex.co/v1/`, workspace `bex-canary`, production pin `ac206b76841b`.

## Render's behavior (captured 2026-11-14 ~02:20 UTC)

Four public Render static sites whose `render.yaml` sets `/*` header rules, each response with Render's `rndr-id`. Two have a `404.html`, two don't:

| Site | `404.html` | `GET /missing-…` and `GET /missing-….css` |
| --- | --- | --- |
| `buzz-docs.onrender.com` (`X-Frame-Options: DENY`, `nosniff`) | 200, 11388 B | 404 `text/html`, the 11388-byte page; `cache-control: public, max-age=0, s-maxage=300`, `strict-transport-security: max-age=315360000; includeSubdomains; preload`, `x-content-type-options: nosniff`, `x-frame-options: DENY` |
| `wc3v.onrender.com` (`X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`) | 200, 4169 B | 404 `text/html`, the page; `cache-control`, HSTS, `nosniff`, `referrer-policy`, `x-frame-options: SAMEORIGIN` |
| `whatseasonisitinhorizon.onrender.com` (`X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, a custom HSTS) | 404 | 404 `text/plain`, `Not Found` (10 B); `x-content-type-options: nosniff` **only** |
| `black-widow-site.onrender.com` (`X-Frame-Options`, `Referrer-Policy`) | 404 | 404 `text/plain`, `Not Found`; `nosniff` **only** |

`GET /`, `HEAD /` and a `304` on all four carry the rules, HSTS and `cache-control`. `POST` and `OPTIONS` are a bare 200 with no headers at all, which confirms w8/319's headerless target.

## bex (fixtures `qa-20261114-cc60-ha` with `404.html`, `qa-20261114-cc60-hb` without)

Both are static sites from `octocat/Spoon-Knife`, with `PUT /v1/services/<id>/headers` rules `/* X-Frame-Options: DENY` and `/* Referrer-Policy: strict-origin-when-cross-origin`:

```
ha  GET /missing-x       404  content-type: text/html  referrer-policy  x-content-type-options: nosniff  x-frame-options: DENY
                              (no strict-transport-security, no cache-control)
ha  GET /404.html        200  cache-control: public, max-age=0, must-revalidate  HSTS  nosniff  referrer-policy  x-frame-options
hb  GET /missing-x       404  content-type: text/plain; charset=utf-8  referrer-policy  nosniff  x-frame-options: DENY
hb  GET /missing-x.css   404  (same)
both GET / and 304       carry HSTS, cache-control, nosniff and both rules (match Render)
```

Both fixtures were deleted and read 404.

## Root cause

- **`404.html` answer:** `serveNotFound` (`lego/operator/internal/staticserver/staticserver.go:429-456`) writes the page with `applyErrorHeaders`, `Content-Type` and `nosniff` only. `serveObject` (`:472-478`) gives every file `Cache-Control: defaultCacheControl` and `Strict-Transport-Security: defaultStrictTransportSecurity` before the rules, but the 404 page skips both.
- **Bare 404:** `serveSiteError` (`:1027-1030`) calls `applyErrorHeaders` for every error class, so a bare miss carries the rules. This is the w4/m101 t003 decision.

## Fix (target behavior)

- **A miss served with `/404.html`:** status 404 with the page's bytes, and the same header set `serveObject` gives a file:
  - `Cache-Control` (`defaultCacheControl`) and `Strict-Transport-Security` (`defaultStrictTransportSecurity`), each replaceable by a matching rule, as on a file;
  - `nosniff`;
  - matching custom rules.

  Keep it free of ETag, ranges and conditionals, as ADR029 § Miss handling already requires.
- **A miss with no `/404.html`:** 404 `Not found` with `X-Content-Type-Options: nosniff` and **no** custom rules.
  - The body text is `not found` today; Render's is `Not Found`, which can change in the same edit.
  - Only the 404 class was captured. Leave 400 (invalid redirect target), 413, 502 and the 503 shed and unavailable classes as w4/m101 made them, and record that they are uncaptured.
- Amend ADR029 (§ Miss handling and the w4/m101 sentence at :136) and the ADR018 static-site row, citing the captures above.

## Blast radius

Every static site, which all share the static-server. Only `serveNotFound` changes; the paths that reach it are the miss after rules and SPA fallback, an overlong key and a `.git` path. Other error classes keep `serveSiteError`, so add a separate bare-404 writer rather than changing `serveSiteError` for everyone.

**DONE 2026-11-14.**

- **Code:** `serveNotFound` (`lego/operator/internal/staticserver/staticserver.go`) now answers a miss in one of two ways:
  - On a site with a `404.html`, it sends the page with `setFileHeaders`, the header block `serveObject` uses: the default `Cache-Control`, `Strict-Transport-Security`, `nosniff`, then the site's rules matched against the request path. It sends no ETag, ranges or conditionals. A rule can replace the cache policy, HSTS or type, as on a file. The page's length is always its own, because `Content-Length` is reserved and set after the rules.
  - Without a `404.html`, it calls `serveBareNotFound`: `text/plain` `Not Found\n` with `nosniff` only and none of the site's rules.
- **Same handling elsewhere:** overlong and `.git` paths follow the same rule. A pre-cutoff site's misses that its SPA fallback does not serve get the bare answer.
- **Unchanged:** the 400, 413, 502 and 503 classes keep the w4/m101 rules. Render's answers for them were not captured. Render's behavior for a `Content-Type` rule on its 404 page was not captured either.
- **Tests:** `TestMissServes404HTMLWithStatus404` (the file headers), `TestThe404PageTakesTheSitesRulesAsAFileDoes`, `TestMissWithoutA404PageIsAPlain404`, `assertBareNotFound` in `TestErrorResponsesCarryCustomHeaders` and the security-headers test, `TestHeaderPatternsResolvedErrors` (a bare 404 carries no rule), and `TestHeaderPatternsServedResponses` (misses now go through a `404.html`, body checked).
