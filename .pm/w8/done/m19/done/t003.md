## Objective

Accept `#/definitions/staticService/properties/buildCommand` and make it drive the static-site build, so the near-universal Render static-site pattern (`runtime: static` + `buildCommand: npm run build` + `staticPublishPath: dist`) validates and deploys instead of failing closed. This is the single biggest real-world compat blocker found by the 2026-08-15 parity review.

## Context

- Current registry state: `unsupported`, reason "static builds don't run Render's buildCommand".
- bex static sites (docs/ADR029-static-sites.md): build → publish Job extracts the built image → object-store origin. The build path already runs `buildCommand` for server services — determine how the static build derives its output today and wire the declared `buildCommand` into that pipeline.
- Compiler entry points: `parseService`/`parseCompiledStack` in `lego/backend/internal/apps/` (blueprint_compiler.go / deploy.go); contract fields in `lego/types/`; operator build dispatch in `lego/operator/`.

## Steps

1. Trace how a `static_site` App's build currently produces `staticPublishPath` content; decide the translation (most likely: pass `buildCommand` through the App CR build spec like server services).
2. Flip the registry entry to `translated` with handler + fixture evidence (the validator requires both).
3. Add a golden render.yaml fixture using static `buildCommand`; assert compile + plan output.
4. Verify end to end on the dev stack: a static blueprint with `buildCommand` reaches `deployed` and serves the built output.

## Files

- `lego/backend/internal/apps/schema/capabilities.json`
- `lego/backend/internal/apps/blueprint_compiler.go` + parse path in `deploy.go`
- `lego/types/` (if the CR contract needs a field passthrough)
- `lego/operator/` static build/publish path (per ADR029)

## Acceptance criteria

- [ ] Static blueprint with `buildCommand` validates (no fail-closed error) and the command demonstrably runs in the build.
- [ ] Registry validator passes with the entry `translated` + evidence.
- [ ] Fixture test covers compile → plan → App spec.

## Out of scope

- Static `preDeployCommand` (stays unsupported — no pre-deploy phase; t002 records the reason).
