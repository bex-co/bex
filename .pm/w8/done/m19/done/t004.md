## Objective

Accept `dockerContext` on server and cron services and thread it into the BuildKit build Job as the Docker build context directory, unblocking monorepo blueprints where the context is not the repo root (`dockerContext: ./apps/api` + `dockerfilePath: ./apps/api/Dockerfile`).

## Context

- Currently fail-closed: `#/definitions/serverService/properties/dockerContext`, `#/definitions/cronService/properties/dockerContext`.
- `dockerfilePath` and `rootDir` are already `translated` — the context knob is the missing third leg. Render semantics: `dockerContext` defaults to repo root, resolved independently of `rootDir`.
- Build mechanics: operator-dispatched BuildKit Jobs (ADR034/ADR060); the buildctl invocation's local context is where this lands.

## Steps

1. Add the field through the compiler → App CR build spec (`lego/types/`) → operator BuildKit Job args.
2. Pin Render's exact resolution semantics (relative-to-repo-root; interaction with `rootDir` and `buildFilter`) and match them; reject path escapes (`..`) like the existing path validations do.
3. Flip the registry entry to `translated` with handler + fixture evidence for both service shapes.
4. Fixture + operator unit test asserting the Job's context argument.
