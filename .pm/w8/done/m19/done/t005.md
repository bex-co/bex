## Objective

Accept the private-image credential fields — `registryCredential` (server + cron), `image.creds`, `fromRegistryCreds` — so a blueprint can deploy a prebuilt image from a private external registry. Translation target: a per-App Kubernetes `imagePullSecret` (and build-time pull auth where the image is a build base), riding the credential machinery bex already owns (ADR022 § registry access control, w7/m36 per-App pull credentials; OpenBao for the secret value per ADR013).

## Context

- Currently fail-closed: `#/definitions/registryCredential/properties/{name,fromRegistryCreds}`, `#/definitions/image/properties/creds`, `#/definitions/serverService/properties/registryCredential`, `#/definitions/cronService/properties/registryCredential`.
- Render's model: registry credentials are workspace-level named objects referenced by services. bex has no credential-object CRUD yet — decide the minimal shape: either (a) a named credential resource (new small surface) or (b) accept inline/env-referenced creds bound at compile. Prefer whichever meets Render's observable blueprint semantics without a lossy approximation (ADR049 D7 rule); if only a subset is truthful, translate that subset and keep the rest unsupported with the reason updated.
- Secret custody: value goes to OpenBao / a namespaced k8s Secret, never into the stored manifest, audit log, or `can_view` reads (see w1/049 #11 precedent on manifest sensitivity).

## Steps

1. Decide the credential-object shape (spike ~15m against Render's `registrycredentials` API docs); record the decision in the task on completion.
2. Wire compile → App spec → operator: Deployment/CronJob `imagePullSecrets` referencing a minted per-App Secret.
3. Flip the truthfully-supported registry entries to `translated` with evidence; leave any untruthful remainder `unsupported` with an honest reason.
4. Fixture: blueprint with `image: {url, creds}` deploys; secret value absent from manifest reads and audit events.
