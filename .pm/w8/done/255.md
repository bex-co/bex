# `bex psql` without `--command` answers with `Usage: render psql …`

Why: in a script or any non-TTY shell, `bex psql <db>` without `--command` prints a usage line that names the `render` executable. A user who copies it runs a command that does not exist on their machine. `docs/bex-cli.md` lists this string as rewritten; it is not.

**Severity:** minor (wrong executable name in one error; the first line of the error is correct). **Attribution:** Bex launcher (branding). **Estimate:** ~20m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `833c`, 2026-11-11 UTC, released `bex v0.5.0` (Render CLI v2.35.0), `https://api.bex.co/v1/`, workspace `bex-canary`, QA human device login, non-TTY.

## Evidence

```text
$ bex psql qa-20261110-833c-pg -o text -- -At -c "select 1"        → exit 1
Error: --command flag is required in non-interactive mode
Usage: render psql <postgresID> --command "SELECT ..." -o json

$ bex psql qa-20261110-833c-pg -o json                              → exit 1, same two lines
```

With `--command` the same database answers (`bex psql qa-20261110-833c-pg --command "select 1" -o json` → exit 0), so only the hint is wrong.

## Expected

`Usage: bex psql <postgresID> --command "SELECT ..." -o json`. `docs/bex-cli.md` § run-time copy, "Usage / follow-up hints", records it as "`cmd/psql.go:96` — `Usage: render psql <postgresID> --command "SELECT ..." -o json` (a returned error, rewritten)".

## Root cause

Upstream returns one error with an embedded newline (`cmd/psql.go:96`, same text at the v2.35.0 and v2.36.0 pins): `"--command flag is required in non-interactive mode\nUsage: render psql <postgresID> …"`. The launcher's `brandError` runs `RewriteCommandRefs` over it (`lego/cli/internal/branding/runtime.go`), which rewrites `render <command>` only where `refBoundary` holds: at a line start after indentation, or right after a backtick, a quote, a newline or `"| "`. Here `render` follows `Usage: ` on its line, so the boundary fails and the word stays. No test covers this string (`runtime_test.go` and `runtime_copy_test.go` do not mention `psql`).

A scan of the pinned client for `render <known command>` after a letter, colon, comma, period or parenthesis finds this one string in the commands bex serves (the other two hits are in upstream's `skills` views, which bex replaces).

## Fix

Let `refBoundary` also accept `Usage: ` directly before the word, the way it accepts `"| "`. Add the string to the reference-rule table in `runtime_test.go`, and a binary case to `runtime_copy_test.go`: `psql <id> -o json` against the stub API prints `Usage: bex psql`.

## Acceptance

- The two commands above print `Usage: bex psql <postgresID> --command "SELECT ..." -o json` and still exit 1.
- `render.yaml`, `render.com`, `RENDER_*` and prose such as "Usage: render the page" (no known command after the word) are unchanged.
- The `docs/bex-cli.md` line is true as written.
