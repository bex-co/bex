## Objective

Use Traefik router response counters as the HTTP edge-source component so a response is attributed to the App's Ingress even when its backend is shared, as with `static_site`.

## Context

- Before this task, `lego/backend/internal/usage/service.go` and `internal/metrics/source.go` queried service-level response counters by an App-name substring.
- Traefik exports `traefik_router_responses_bytes_total` with router and service labels when router labels are enabled.
- The operator names each App Ingress after the projected CR, but static sites share the static-server Service and therefore cannot be attributed reliably by backend Service. A router-prefix regex is also unsafe: display names and host labels can contain hyphens, so one App's prefix can overlap another App's exact router name.
- Traefik's capture wrapper increments response size through `ResponseWriter.Write`, while `Hijack` returns the underlying connection. WebSocket frames therefore need `t014`'s connection-level edge source and are not claimed by this HTTP counter.

## Steps

1. Resolve the App's actual Ingress rules and derive the exact router identities emitted by the pinned Traefik version; fail the meter, rather than broad-match, when attribution cannot be resolved.
2. Switch bandwidth-only query paths to the router response counter without changing request-count/latency semantics.
3. Cover ordinary, custom-domain, static-site, overlapping-name, empty-vector, pinned-version naming, and counter-reset behavior.
