# A Rust build that sets its toolchain logs `==> Using Rust 1 (default)` while rustup builds on the toolchain it named, and the default line names no version

Why: Render's documented Rust selection works on bex:

- **Selection:** `RUSTUP_TOOLCHAIN`, or a `rust-toolchain` file at the repo root, with the variable overriding the file. bex's pinned `rust:1-bookworm` image lets rustup apply both (ADR060 § "Rust exception").
- **Narration:** bex's own version line ignores both. A service that sets `RUSTUP_TOOLCHAIN=1.75.0` builds and runs on 1.75.0, while its build log opens with `==> Using Rust 1 (default)`.

Every other native runtime names the version it picked and where the choice came from, for example `==> Using Bun 1.3.0 (from BUN_VERSION=1.3.0)` and `==> Using Python 3.12 (from .python-version)`.

- **Pinned toolchain:** a user reading a failed build sees "default" and assumes the platform toolchain was used, not the one they pinned.
- **No pin:** the default line says only "Rust 1", not which stable toolchain built the service. That is `1.99.1` on today's pin. Render documents its default as "latest stable".

**Severity:** minor. The build is correct; the bex-owned log line misstates it. **Attribution:** operator (native build narration). **Estimate:** ~30m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `c687`, 2026-11-14 UTC, released `bex v0.6.0`, `https://api.bex.co/v1/`, workspace `bex-canary`, production pin `706a389d5924`.

## Render's documented behavior

From [render.com/docs/language-support](https://render.com/docs/language-support), § "Set your language version" (Rust row):

- the default is "Latest stable";
- to change it: "Set the `RUSTUP_TOOLCHAIN` environment variable", or "add a `rust-toolchain` file to your project root containing only the toolchain version".

From [render.com/docs/rust-toolchain](https://render.com/docs/rust-toolchain), § "Specifying a Rust Toolchain":

- "By default, Render uses the latest stable Rust toolchain";
- "The environment variables overrides the version in toolchain files."

Neither page shows Render's build-log wording, so this item fixes what bex's own line asserts, not its phrasing.

## Root cause

- **Resolution:** `resolveNativeLine` (`lego/operator/internal/build/nativeversion.go:215-228`) has a case for Python, Node, Ruby and Elixir. Rust falls to `default: return r.choice(t.defaultLine, "")`: line `"1"` with no source.
- **Narration:** `NativeChoice.Narration` (`:84-100`) therefore prints `==> Using Rust 1 (default)` for every Rust build, whatever `RUSTUP_TOOLCHAIN` or `rust-toolchain` asks for.
- **The table:** the `rust` entry (`native.go:137`) carries only `line: "1"`, no `version`, so even the default names no release. The doc comment (`nativeversion.go:118`, "go, rust default … rustup applies Rust's") records the gap as intended. It predates the per-runtime narration that every other runtime gained since.

## Fix (target behavior)

- **Rust resolution:** give Rust its own case in `resolveNativeLine`, keeping line `"1"` (the one image) and recording the request and its source for the narration, in Render's precedence:
  1. `RUSTUP_TOOLCHAIN` → `==> Using Rust 1.75.0 (from RUSTUP_TOOLCHAIN=1.75.0)`;
  2. a `rust-toolchain` file at the service root, one line → `(from rust-toolchain)`;
  3. `rust-toolchain.toml` `[toolchain] channel`, which rustup also reads → `(from rust-toolchain.toml)`;
  4. otherwise `==> Using Rust 1.99.1 (default)`, naming the pinned image's `RUST_VERSION`.
- **Requests narrated verbatim:** a channel (`stable`, `nightly`, `nightly-2026-01-01`) or a partial version (`1.75`) is narrated as written. rustup resolves it, and bex does not pin or validate it. A malformed value still reaches rustup, which fails the build with its own message, as on Render.
- **The pinned version:** record `1.99.1` as the `rust` line's `version` in `native.go`, and keep it in step with the digest when the toolchain pins are refreshed. Make sure `exactRequest` treats the Rust line the same as before; Rust has no exact-image swap.
- **Docs:** update ADR060's runtime table row and its § "Rust exception" to name the narration.

## Blast radius

- **Rust:** only native Rust builds (web, private, worker, cron) narrate through this path. No image or toolchain choice changes; the narration does, and `NativeChoice` gains a display version.
- **Go, unverified:** it shares the `default:` branch and narrates `==> Using Go 1.27 (default)`. Go's own `toolchain`/`go` directives in `go.mod` can make the `go` command download another toolchain (`GOTOOLCHAIN=auto`). Whether Render documents a Go selection, and whether bex's narration misstates it, was not checked here. Check it while in this code, and file it separately if it differs.

## Dedupe

- **Searched:** `.pm`, ADR060 and ADR018 for `Using Rust`, `RUSTUP_TOOLCHAIN` and `rust-toolchain`.
- **Hits:**
  - `w8/m51` (done), the per-runtime version selection that left Rust to rustup;
  - `w4/321` and `w4/m213` (done), JavaScript tools in Rust builds;
  - `w8/286` (done), which quotes the same `Using Rust 1 (default)` line in passing.

  ADR060 § "Rust exception" documents that rustup honors both signals, but not that bex's narration contradicts them. No open item covers it.

**DONE 2026-11-14.** `resolveNativeLine` gives Rust its own case, `rustToolchain` (`lego/operator/internal/build/nativeversion.go`). It keeps the one line and image (no exact swap) and names the toolchain rustup applies, in a display-only `NativeChoice.narratedVersion` that `Narration` prints:

- `RUSTUP_TOOLCHAIN` → `==> Using Rust 1.75.0 (from RUSTUP_TOOLCHAIN=1.75.0)`;
- else the first root toolchain file rustup reads, `rust-toolchain` then `rust-toolchain.toml`, one-line or TOML `channel` → `(from rust-toolchain)`;
- else the pinned release → `==> Using Rust 1.99.1 (default)`.

The `rust` line records `version: "1.99.1"` (`native.go`).
