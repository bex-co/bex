# A Docker build whose Dockerfile is missing logs bex's `the Dockerfile "…" does not exist in the repository at "<sha>"`, where Render's log shows BuildKit's `error: failed to solve: failed to read dockerfile: open Dockerfile: no such file or directory`

Why: w8/053 (2026-10-04) replaced BuildKit's line with bex's own sentence, before the parity rule of 2026-10-17. Render's 2026 build logs still print BuildKit's line, and no ADR018 sign-off keeps bex's wording.

- Severity: minor. The deploy fails the same way (`build_failed`) and the live release keeps serving. Only the log line differs, and it is the line users paste into a search.
- Seen: routine `cli-qa`, 2026-11-22 17:53 UTC, bex CLI v0.9.0 (Render CLI pin per `lego/cli/UPSTREAM_RENDER_CLI.md`), `https://api.bex.co/v1/`, QA human device-flow login, workspace `bex-canary`. The fixture was a free Docker web service `qa-20261122-327c-ctx` (`srv-dc1in23r121s73eu0df0`, deleted, 404 confirmed) on `bex-co/bex` at `main`, `rootDir` `examples`. It went live first with `dockerContext` `./docker-build-env` and `dockerfilePath` `./build-probe/Dockerfile`. Then `PATCH /v1/services/{id}` set `envSpecificDetails.dockerfilePath` to `./nope/Dockerfile`, and `bex deploys create … --confirm` started deploy `dep-dc1io4u0usec73d5irtg`. `bex logs --resources <srv> --type build --direction forward` printed:

  ```text

  ==> Building from https://github.com/bex-co/bex@4407ea6
  the Dockerfile "examples/nope/Dockerfile" does not exist in the repository at "4407ea61a2f8dabadcd133c5faee75e83afda948"
  ==> Build failed 😞
  ==> Common ways to troubleshoot your deploy: https://render.com/docs/troubleshooting-deploys
  ```

- Render, from build logs users quoted on GitHub (`gh api 'search/issues?q=%22failed+to+read+dockerfile%22+render'`, read 2026-11-22):
  - frayel/devagent#6 (2026-09-26), with Render's timestamps: `==> Cloning from https://github.com/…`, `==> Checking out commit … in branch main`, `#1 [internal] load build definition from Dockerfile`, `#1 transferring dockerfile: 2B done`, `error: failed to solve: failed to read dockerfile: open Dockerfile: no such file or directory`.
  - dittofeed/dittofeed#1396 (2025-04-08) has the same four lines after the clone lines. Pongpitakzaa/PROCUREMENT-#4 (2026-10-13) and Bjorn1010/memecoin.github.io#4 (2026-09-09) quote the same `error:` line.
  - Numbu-bit/TroSky#13 (2026-10-11) quotes `failed to read dockerfile: open Dockerfile: no such file or directory` for a configured `dockerfilePath: ./Dockerfile`. So Render names the file as `Dockerfile`, not `./Dockerfile`.
- bex: the clone step's `bex_require -f "$BEX_DOCKERFILE_PATH" "Dockerfile" …` (`lego/operator/internal/build/build.go`, the clone script around line 1922; `sourcePathChecks` around line 1826) exits 66 with bex's sentence, so BuildKit never runs. Without that check, BuildKit would print `open ./nope/Dockerfile`, because `buildctlRecipeArgs` passes the whole configured path as `--opt filename=` (w1/m156 recorded `open ./Dockerfile.qa-missing`). The same configured path shows up in `#1 [internal] load build definition from ./build-probe/Dockerfile`.

## Fix

- For a missing Dockerfile, write Render's lines instead of bex's sentence: `#1 [internal] load build definition from <name>`, `#1 transferring dockerfile: 2B done`, then `error: failed to solve: failed to read dockerfile: open <name>: no such file or directory`. Keep the tenant-error classification (exit 66) and the `build_failed` status, and keep Render's two closing lines from w8/393. Writing the lines from the clone step keeps the check in front of BuildKit. Removing the Dockerfile check and passing BuildKit the Dockerfile's directory plus its base name as `filename` would also produce them.
- `<name>` is `Dockerfile` for the default path and for `./Dockerfile` (TroSky#13). For a nested `dockerfilePath` such as `nope/Dockerfile`, Render's form is not yet seen: find a public 2026 Render log with a nested path before choosing between the base name and the cleaned path, and cite it here.
- Leave alone: the missing root directory and missing `dockerContext` sentences, since no Render log for them has been found (w8/395 made the same call). The `.dockerignore` and context checks stay as they are.
- ADR018's build-log row: record the change with the citations above.
