# Eleven of Render's documented runtime defaults are unset or different on native Python, Go, Rust, Elixir and Node

Why: Render documents a set of default environment variables per native runtime. bex sets most of them (w8/111–117, w5/162) but not these eleven, so a build script, a framework or a clustering setup that reads one behaves differently on bex, and nothing records the difference.

**Severity:** minor (no failing journey was reproduced; each variable is one Render documents as set by default). **Attribution:** infrastructure/runtime (native build image). **Estimate:** ~60m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `965c`, 2026-11-11 UTC, released `bex v0.5.0` (Render CLI v2.35.0), `https://api.bex.co/v1/`, production pin `7ca0227aa477`, workspace `bex-canary`, QA human device login.

## Evidence

One free web service per runtime from `https://github.com/bex-co/bex` (`--root-directory examples/runtime-version/python`, so the build context is three small files), whose build command and start command print the environment:

```text
$ bex services create --name qa-20261111-965c-env-<rt> --type web_service --repo https://github.com/bex-co/bex --branch main \
    --runtime <rt> --root-directory examples/runtime-version/python --plan free \
    --build-command 'env | sort | grep -E "^(CI|FORWARDED|GUNICORN|PIPENV|VENV|GO111|GOPATH|MIX_|RELEASE_|BUNDLE_|GEM_|MALLOC|PASSENGER|PIDFILE|RAILS_|CARGO|ROCKET|RUSTUP|NODE_|PORT|WEB_CONC|RENDER_WEB)" | sed "s/^/BENV /"' \
    --start-command "sh -c '<the same pipeline with RENV>; sleep 900'" --auto-deploy=false -o json --confirm
$ bex logs -r <srv> --type build --text BENV -o text ;  bex logs -r <srv> --type app --text RENV -o text
```

Matching Render in the same runs: Python `FORWARDED_ALLOW_IPS=*`; Elixir `MIX_ENV=prod`; Node `NODE_ENV=production` at runtime only; Ruby's `RAILS_*`, `BUNDLE_*`, `MALLOC_ARENA_MAX`, `PASSENGER_ENGINE`, `PASSENGER_ENVIRONMENT`, `PIDFILE`; `PORT=10000`, `WEB_CONCURRENCY` and `RENDER_WEB_CONCURRENCY` at runtime on every runtime; and on Node the all-runtime set: all fifteen variables at runtime, and in the build all but `RENDER_INSTANCE_ID` and the two runtime-only concurrency variables.

Already decided, not part of this note: Python's `GUNICORN_CMD_ARGS` without `--bind=0.0.0.0:10000` (w8/113), and Ruby without `GEM_PATH` and `PASSENGER_PORT` (w5/162). Those reasons live in the code comment only.

## Expected

Each variable has Render's value, or ADR018 records why bex leaves it out. The ones most likely to change behavior:

- `RELEASE_DISTRIBUTION=name` — an Elixir release starts with long names on Render, which is what clustering over `RENDER_DISCOVERY_SERVICE` needs. Without it a release uses short names.
- `ROCKET_PORT=10000` and `ROCKET_ENV=prod` — a Rocket app listens on Render's port with no configuration. On bex it listens on Rocket's own default; whether port detection then serves it was not tested.
- `CI=true` in a Python build — tools that switch to non-interactive or stricter behavior under CI.

## Root cause

`nativeBuildDefaults` (`lego/operator/internal/build/native.go:407-431`) has cases for Elixir (`MIX_ENV`), Python (two variables) and Ruby, and none for Go or Rust. `nativeRuntimeDefaults` (`:439-444`) has Node's `NODE_ENV` only. The Go and Rust values that are set come from the upstream base images. ADR018's default-environment row covers the all-runtime set; nothing in `.pm` or `docs` mentions these eleven names.

## Fix

Add the missing values to the two functions (build and runtime, or the phase Render names). For each one that cannot be Render's value on bex, say why in ADR018's default-environment row, and move the two existing omissions there too:

- `GOPATH`, `CARGO_HOME`, `RUSTUP_HOME`, `VENV_ROOT`: Render's paths only make sense if the toolchain really lives there. Either relocate or record the divergence.
- `NODE_MODULES_CACHE`: set it only if `NODE_MODULES_CACHE=false` also turns the dependency cache off, as on Render; otherwise record it.
- `ROCKET_PORT`: follow the service's `PORT`.

## Acceptance

- The five services above print Render's value for every row, or the row is listed in ADR018 with its reason.
- A service's own value for any of these names still wins, at build and at runtime (as for `NODE_ENV`, w8/111).
- `TestNative*` cases cover each added variable and the build-only / runtime-only split.

## Shipped 2026-11-11 (w8 drain): seven set, four filed; the live check waits for the next production deploy

Render's page was read again (render.com/docs/environment-variables, 2026-11-11): the eleven names and values are as the table above says.

| Variable | Outcome |
| --- | --- |
| Python `CI=true` (build only) | Set, as a build `ARG`: the build command sees it and the image does not keep it. |
| Python `PIPENV_YES=true` | Set, build and runtime. |
| Go `GO111MODULE=on` | Set, build and runtime. |
| Go `GOPATH=/opt/render/project/go` | Set, with its `bin` first on `PATH`. Checked in a container on the pinned image line: `go build` and `go install` work and the installed binary resolves. |
| Rust `ROCKET_ENV=prod` | Set, build and runtime. |
| Rust `CARGO_HOME`, `RUSTUP_HOME` | Set to Render's paths, which are links to the toolchain image's own directories. Checked in a container: `cargo build --release` works and `rustup` reports the active toolchain. |
| Elixir `RELEASE_DISTRIBUTION=name` | **Not set; filed w8/272.** With a pod's hostname an Elixir node given a long name dies at boot with `nodistribution` (reproduced in a container). Setting it would stop every Elixir release from starting. |
| Rust `ROCKET_PORT` | **Not set; filed w8/273.** It must follow the port the service is routed on and yield to the service's own value. |
| Python `VENV_ROOT` | **Not set; filed w8/274.** No virtualenv exists at Render's path. |
| Node `NODE_MODULES_CACHE` | **Not set; filed w8/275.** There is no dependency cache for it to switch. |

- Code: `nativeBuildDefaults` (`lego/operator/internal/build/native.go`); test `TestNativeRuntimeDefaultsFromRendersTable` pins each added line, that no other runtime gains it, and that the four left out stay out.
- A service's own value still wins: build defaults are image `ENV` (or `ARG`) before the build command, and the build loads the service's variables after them.
- ADR018's default-environment row now lists the per-runtime defaults and the six that differ (these four, and the two earlier ones that lived only in a code comment), marked as not signed off.
