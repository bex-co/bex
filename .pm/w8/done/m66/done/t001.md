## Done 2026-10-14

`patchChangedStackService` now calls `persistBlueprintIntent` (`lego/backend/internal/apps/deploy.go`) before opening the Blueprint deploy row and patching the CR. It writes each projector-owned field the update changes onto the managed App row, in the same row-first order as `writeThroughStoreFetched`: source (`SetAppSource`, after the shared `markSourcePending` marker, as Update Source does), plan (`SetAppTier`), instance count (`SetAppReplicas`) and disk (`CreateDisk`/`UpdateDisk`). The deploy branch also materializes the pull Secret for an explicit registry binding, as a redeploy does, because the projector now carries that binding from the row. A failed row write returns before any deploy row or CR change. Unmanaged/storeless Apps, no-op re-applies and maintenance-only changes write no row.
