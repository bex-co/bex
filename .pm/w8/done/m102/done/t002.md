## Closed — 2026-11-19 (loopx session)

Audited on main. The chain is the one w8/m94, m95 and m97 to m101 traced, and no commit since production's pin `dff52c596d13` touches `deploy/native-base`, `deploy/native-common`, `native.go`, `nativeresolve.go` or `nativebases.go`.

- **One recipe chain.** `nativeDockerfile` (`native.go`) has one caller, the native build Job's preparer. `cmd/native-resolve` ends with `applyNativeCommonBase` (`nativeresolve.go` → `nativebases.go`). So every native web service, private service, worker, cron job and static-site build starts from the common image, whatever the primary (Node, Python, Ruby, Elixir, Go, Rust) and its companions.
- **Phases.** Build, pre-deploy and runtime run one image: the pre-deploy Job runs the image the build produced. So `pigz` is present at runtime too, beyond Render's build-only contract, but nothing at runtime needs it (t005 serves the built bytes with no pigz on `PATH`). A static site's image is only its publish Job's extract source, so it gets `pigz` at build only, which matches Render, and it publishes the `.gz` files its build wrote.
- **Resolution.** `applyNativeCommonBase` re-copies only `/usr/local` from the selected primary, then sets the primary's environment, `PATH` included. pigz is `/usr/bin/pigz`, and no official primary image ships one (sweep 423's Python 3.13 primary had none), so nothing shadows it. A tenant's own `pigz` earlier on `PATH` still wins.
- **Cache and writes.** The base is digest-pinned, and tenant source and environment changes do not touch its layers. pigz writes only where it is told (beside its input, or to stdout); the checks passed as uid 1000 and as root on the replica (t005).
- **Exclusions.** Dockerfile, prebuilt-image and buildpack services never enter this recipe. A static site with no build command builds no native image.
- **Neighbors kept.** `gzip`, zlib, the ZIP tools and every other utility of the common image are unchanged, as are native-init and the companion and package-manager steps. m102 changes no product code.
- **Exercised versus source-only.**
  - Production (t006): build and runtime, Python 3.13.18, both CLIs, on `4b809600…`.
  - Maintained cohort: the frozen m102 program on the Python 3.13 primary at build and on a network-off runtime (`python313-original`, through `original-cases.py`); the pigz checks at the Node compute build and network-off runtime and at the static build; and the `missing-pigz` omission on the Python primary (t005).
  - Families runs on the same digest: the other primaries, companions, native-init and static.
  - Not executed: a hosted pre-deploy run (Free refuses `preDeployCommand`, as Render does), ARM64 on production (D3) and trixie (the common image is bookworm only, as Render's runtimes are).
