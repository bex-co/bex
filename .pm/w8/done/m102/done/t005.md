## Closed — 2026-11-19 (loopx session)

Every `native-common-image.yml` utility cohort (`TestNativeUtilityGeneratedImages`) runs these real-image checks on the image it publishes:

- **The original program** (already maintained). `python313-original` runs the frozen m102 build on the Python 3.13 primary through `original-cases.py`: the before proof, the original `pigz -n -p 2 -c qa-pigz-input.txt > qa-pigz-output.gz`, and the program's `build` step, which the frozen `valid_after` checks (header, CRC32, ISIZE, inflated bytes). Three HTTP requests on a `--network none` runtime then pass the frozen oracle, the raw `/asset.gz` inflated independently.
- **New pigz checks** in `utility-check.py`. pigz runs at the `node-compute` and `node-static` builds; the network-off runtime only reads. They replace the older pigz lines, whose empty, binary and Unicode artifacts and invalid-input error they keep.
  - m102's own program through its original argv, outside the original build. The output must be the exact bytes production emitted (`8aecad5d…`, 130 bytes, header `1f8b0800000000000003`), and the program's own build proof must report `pigz 2.6` and the expected gzip proof (CRC32, ISIZE, inflated hash).
  - Every phase reads the retained `public/*.gz` artifacts (empty, binary, Unicode and the original) with Python's zlib alone: exact header, CRC32, ISIZE and inflated bytes. The static build publishes them.
  - In place, `two words 雪.txt` (mode 0640, a fixed time) becomes its `.gz` with the same mode and time, and its header carries `FLG.FNAME` with the UTF-8 name and the `MTIME`. Renamed, `-d -N` restores the name, time, mode and bytes.
  - A 14-block input (`-b 32`) gives the same bytes on 1, 2, 4 and 8 threads, and `-i` writes a different stream that still inflates.
  - `-z` writes zlib with an Adler-32 trailer, `-K` a ZIP with one deflated member and its CRC, `-11` a smaller zopfli stream; two concatenated members decompress as one, `unpigz` decompresses, and options in `PIGZ` apply.
  - Exit statuses, with pigz's own messages: 1 for an invalid stream, a truncated one (`-t`), a missing input and an existing output (kept until `-f`); 22 (`EINVAL`) for an unknown option.
  - At the runtime, m102's own server, started with `PATH=/nonexistent`, serves the original `.gz` bytes and a proof equal to the build's.
- **New omission control.** `missing-pigz` removes only `/usr/bin/pigz`. It proves `command -v pigz` fails while the `unpigz` hard link still inflates `gzip` output and `libz.so.1` remains. The original m102 build must then fail with `pigz: command not found` after its ready line, the sweep 423 failure.
- **How this was checked before shipping.** The host is arm64 and the adopted image is amd64-only, so the generated-image gate cannot run here. Local replicas installed Debian's `pigz=2.6-1` on the pinned `python:3.13-bookworm` and `node:24-bookworm` (the same `pigz`, `zlib1g`, `libc6` and `gzip` versions as the image's SPDX, Debian 12.15, Python 3.13.18):
  - the new block passed build and network-off runtime as uid 1000 and as root, with `/usr/bin/python3` and `/usr/local/bin/python3`, and emitted the same `8aecad5d…` bytes production did on amd64;
  - with `/usr/bin/pigz` and `unpigz` deleted between build and runtime, the runtime still passed;
  - each of 16 source mutations failed the assertion it targets: a changed frozen hash, no `-n`, mode 0644, `-d` without `-N`, a block size varying with the thread count, `-9` for `-z`, a stored ZIP member, `-6` for `-11`, `PIGZ` without `-n`, exit 1 for an unknown option, no `-f`, a concatenation without its space, gzip's error wording, another XFL byte in the retained header, the JSON page served as the asset, and another compressor version at runtime;
  - two image mutations failed the build: stock `python:3.13-bookworm` at the first pigz proof, and a deleted `unpigz` at its check;
  - the original m102 build and its three network-off runtime requests passed through `original-cases.py`;
  - after the exact `missing-pigz` command, the original build printed `QA_PIGZ_BEFORE` with `"pigz_path": null` and failed with `pigz: command not found`.
  - The push of this change re-runs the amd64 utility cohort through `native-common-image.yml`; that run is the amd64 proof.
- **Unit and package checks.** `gofmt`, `go test ./internal/build/` (`TestNativeUtilityOmissionsHaveRemovalLayers`, `TestNativeOriginalReplayHTTPOracles`, `TestNativeUtilityOmissionEvidenceRequiresActualReadyStdout`), `original-cases_test.py` and the operator's `make test`.
- **Bounds.** ARM64 is out of scope (D3). Pre-deploy runs the same image, and there was no hosted pre-deploy run (Free refuses it). Other primaries rely on the families runs. Archive modes beyond those listed, compression speed and parallel scaling are not checked.
