## Objective

Bump the unmodified upstream `render-oss/cli` pin from v2.24.0 to v2.26.0 following the documented procedure, re-verify the launcher overlay seams, and re-run the graded compatibility walk so the checklist reflects the new pin.

## Context

- The full pin-bump procedure (module pseudo-version, `RootCmd`/branding-overlay seams, `isRootVersionRequest` re-diff, validation scripts) is `lego/cli/UPSTREAM_RENDER_CLI.md` § "Updating the pin" — follow it step by step.
- Pin-conditional checklist bullets to re-check on any pin move: the `skills list`/`skills update` upstream non-TTY panic rows, and the service-disks bullet ("a future `render disks` command would make this a real row") in `docs/cli-compatibility-checklist.md`.
- DO_NOT_DO: never fork or vendor the CLI — this is a pin bump on the sanctioned launcher train; `/release` mints `bex-cli/v*` versions separately.

## Steps

1. Read the v2.25.0 and v2.26.0 upstream release notes; note new commands/flags and any collision with Bex-native command names.
2. `go get github.com/render-oss/cli@<v2.26.0 commit>` from `lego/cli/`; update the three pin values in `UPSTREAM_RENDER_CLI.md` and the version strings in `README.md`.
3. Walk the overlay checks: `RootCmd` attach, `isRootVersionRequest` re-diff, branding template/`docs` retarget, `bex --help` / `bex postgres --help` / `bex blueprints --help` spot-checks.
4. Run `bash scripts/bex-cli-validate.sh` and `cd lego/cli && go test ./...`; run `scripts/cli-compat.sh verify` and regenerate the command tree.
5. Re-check the pin-conditional checklist bullets (skills panic — possibly fixed upstream; disks command — possibly grown).
