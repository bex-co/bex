# 047 — Every tenant's request log carries Traefik's platform-wide request counter, pod IPs and internal router names

Why: `bex logs --type request` hands each tenant a live counter of _all_ edge traffic plus cluster-internal addressing that nothing in bex reads. Dropping the fields costs one config block.

Severity: minor (information disclosure). Attribution: infrastructure (`deploy/gitops/base/values/traefik.values.yaml`).

## Evidence (2026-10-04, `/qa-find-bugs-cli` w8 loop, sweep 2)

Production, `bex v0.2.1` (upstream pin Render CLI v2.27.0 `a764810a7682`), workspace `bex-canary`, human device login. Fixture: free web service `qa-20261004-3d35c5-web` (`srv-db1e4vnhb1uc73ebifi0`, image `docker.io/mendhak/http-https-echo:35`, deleted).

`RequestCount` across the three lines: `7647968` → `7671778` → `7647990`, so there are two Traefik replicas. On one replica the counter advanced by 22 between this service's 1st and 3rd request (~1.07 s), and this service received only those 3. The counter is process-wide: any tenant can sample it to measure total platform edge traffic. `ServiceAddr`/`ServiceURL` expose pod IPs, and `RouterName` exposes the edge's internal routing names.

## Mechanism

- `deploy/gitops/base/values/traefik.values.yaml:92-103` sets `accessLog.fields.defaultMode: keep` (headers and query parameters already dropped), so every Traefik field reaches the shipper.
- `deploy/gitops/base/log-shipper.yaml:758-900` (`loki.process "request_logs"`) only extracts fields for labels. The line itself ships unchanged, and bex-api returns it verbatim as the tenant's `message`.
- The raw-JSON message itself is a recorded divergence (ADR010 "Request logs", ADR018 row "Request / HTTP logs") and stays. The problem is these specific platform-internal fields.

## Fix

In `traefik.values.yaml`, under `accessLog.fields`, add `names:` with `RequestCount: drop`, `ServiceAddr: drop`, `ServiceURL: drop` and `RouterName: drop`. Keep `ServiceName` and `KubernetesIngressName`: the shipper attributes lines with them (`log-shipper.yaml:774-775`). Keep `RequestHost`/`RequestPath`/`Duration`/`DownstreamStatus`/`RequestMethod`, which the logs filters and Loki metrics read (`lego/backend/internal/logs/loki.go:432`, `lego/backend/internal/metrics/lokisource.go:132-134`). `rg 'RequestCount|ServiceAddr|ServiceURL|RouterName'` over `lego`/`deploy`/`dashboard/src`/`scripts` finds no reader of the four dropped access-log fields. (`TraefikRouterNames` in `lego/backend/internal/core/traefik.go` reads Prometheus labels, not the access line.) Update the ADR010 request-log paragraph to name the dropped fields.

Render reference: Render's request logs show method, status, URL, and a `requestID` (render.com/docs/logging), with no edge-internal addressing.
