## Objective

Identify production databases with `spec.highAvailability: true` on a sub-1-CPU plan (a read-only query or `kubectl` listing of Database CRs). Record the count and the chosen handling in this task. Also check whether `readReplicas` has the same plan gap and note it for follow-up.

## Acceptance criteria

- [ ] The query and its result are recorded, and the handling is decided by the user (not silently applied).

## Outcome (2026-09-26) — done

Read-only query against production (`kubectl --context hetzner-prod get databases.app.bex.co -A -o json`, filtering on `spec.highAvailability`, `status.highAvailabilityEnabled` and `spec.readReplicas`): **3 Database CRs, 0 with HA (spec or observed), 0 with read replicas.** The gate strands nothing, so there is no handling for the user to decide. The grandfathering path (keep HA through unrelated edits, refuse only plan changes) stays for any database enabled before deploy.
