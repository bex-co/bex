# A Blueprint naming the paused Pro Ultra plan points its error at `type` (line 2), not `plan`

Why: since `bd33b3012` (w2/m250) a Blueprint that selects `plan: pro ultra` is correctly refused with "`"Pro Ultra" is temporarily unavailable; choose Pro Max or a smaller instance type.`" But the error's `path`/`line`/`column` point at the service's `type: web` line rather than its `plan:` line. An editor or CI annotation therefore highlights the wrong line, and the fix the message asks for (change the plan) is not where the marker is. Render's Blueprint validation locates an instance-type error on `plan`.

Severity: **minor** (message is right, location wrong). Attribution: backend Blueprint error mapping (`lego/backend/internal/apps/blueprint.go:2186` `blueprintErrorField`). Estimate: ~15m. Source: `/qa-find-bugs-cli` loop sweep 3093, 2026-11-03 13:1x UTC, pin `549af492873d` (contains `bd33b3012`), workspace `bex-canary`.

## Evidence

```yaml
services:
  - type: web            # line 2
    name: qa-bpu
    runtime: node
    plan: pro ultra      # line 5
    repo: https://github.com/render-examples/express-hello-world
    buildCommand: yarn
    startCommand: node app.js
```

```text
bex blueprints validate bpu.yaml -o json
→ {"errors":[{"column":11,"line":2,"path":"services[0].type",
              "error":"service \"qa-bpu\": \"Pro Ultra\" is temporarily unavailable; choose Pro Max or a smaller instance type."}],"valid":false}
plan: pro max → {"valid":true}
Control (same file shape, worker with plan: free) → path services[0].plan, line 5
```

## Cause and fix

`blueprintErrorField` picks the first field name that appears in the message. The pause message contains "instance **type**" and no "plan", so it maps to `.type`. This is the same trap w4/416 fixed for "paid instance type". Map "temporarily unavailable" (or the `INSTANCE_TYPE_UNAVAILABLE` cause, preferably via the typed error rather than text) to `.plan`, and add a `blueprint_validate` regression that asserts `path services[0].plan` and the plan's line.
