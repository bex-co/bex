# 059 — Every Render-route 400 for an unknown query parameter says "request contains an unsupported query parameter" without naming it

Why: a typo (`limt=5`) or a parameter Render doesn't define (`resolutionSeconds` on bandwidth, `groupBy` on metrics) gets the same anonymous 400 on every Render-shaped route. The caller has to guess which of their parameters is wrong. The neighbouring validator messages already name the parameter (`invalid query parameter "…"`, constraint messages).

Severity: minor (diagnosability). Attribution: server (`lego/backend/internal/api/render_openapi.go`).

## Evidence (2026-10-05, `/qa-find-bugs-cli` w8 loop, sweep 21)

Production pin `8f58b933d`, workspace `bex-canary`, human device login, read-only GETs with the CLI's token (read privately) and User-Agent `render-cli/2.27.0`.

```text
GET /v1/services?ownerId=tea-…&bogusParam=1                        → 400 {"error":"request contains an unsupported query parameter",…}
GET /v1/postgres?ownerId=tea-…&limt=5                              → 400 same
GET /v1/services/srv-daif6dsmg29s73d1umvg/deploys?limt=5           → 400 same
GET /v1/logs?ownerId=tea-…&resource=srv-…&limt=5                   → 400 same
GET /v1/metrics/bandwidth?resource=srv-…&startTime=…&endTime=…&resolutionSeconds=300 → 400 same
    (the same request without resolutionSeconds → 200)
```

## Mechanism

`lego/backend/internal/api/render_openapi.go:630-638` `hasUnknownRenderQuery` loops over the request's query names and returns `true` on the first one absent from `allowedQuery[route.Operation]`, throwing the name away. `:543-545` then writes the fixed string. `safeRenderValidationMessage` (`:640-…`) names parameters for every other request-error kind.

## Fix

Return the offending names (sorted, quoted and length-capped, since they are caller-supplied) and write `unsupported query parameter "limt" for <operationId>` (or a list for several). Keep the message distinct from the constraint-violation messages, as `w5/060` intended.

## Acceptance

- [ ] `GET /v1/postgres?ownerId=…&limt=5` → 400 naming `"limt"`. Two unknown names → both named, in deterministic order.
- [ ] An over-long or control-character name is truncated or escaped safely in the message.
- [ ] Controls: known parameters still pass. Constraint errors keep their existing wording. `TestRenderRequestValidator*` updated.
