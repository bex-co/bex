## Objective

A service whose saved source is a prebuilt image with no repository reads `runtime: image` and `env: image` on REST, `runtime: image` on GraphQL and MCP, and gets the image `envSpecificDetails` projection, even while `spec.runtime` keeps a native runtime (or `docker`) for a later switch back. This mirrors w8/088's `staleImageRuntime` in the other direction.

## Context

- `lego/backend/internal/core/source_runtime.go:45-62` `EffectiveRuntime` returns an explicit `spec.Runtime` first. Only a retained `image` with a repo is treated as stale.
- `lego/backend/internal/apps/service.go:1196` (`view`) and `render.go:618-654` (`envSpecificDetails`) consume it. GraphQL's `runtime`/`builder` read the same view.
- `lego/backend/internal/apps/build_strategy.go:101-111` `prebuiltImageSource` and `staleImageRuntime`. The build already treats an image-only source as an image (`buildStrategy` line 55).
- The pinned client chooses its update body builder from this field (`render-oss/cli` `pkg/service/update.go:74-93`).

## Steps

1. Make `EffectiveRuntime` source-aware: an image with no repo reads `image` whatever runtime is retained. A retained runtime is reported again once a repo is the source (switch back, as today).
2. Check every caller of `EffectiveRuntime` and of `AppView.Runtime`. Decide whether each needs the reported runtime or the retained one, including Blueprint export and generation and the dashboard Settings form, which may need the retained value to prefill a switch back.
3. Leave `spec.runtime`, `builder` and `rootDir` retained, as ADR004 w4/m202 records.

## Files

- `lego/backend/internal/core/source_runtime.go`
- `lego/backend/internal/apps/service.go`, `render.go`, `graphql.go`, `mcp.go` as the caller review requires

## Acceptance criteria

- [x] After `PATCH {"image":{"imagePath":…}}` on a native Node service, `GET /v1/services/<id>` reads `serviceDetails.runtime: image` and `env: image`, with no `buildCommand`/`startCommand` keys in `envSpecificDetails`.
- [x] A switch back to the repo reads the retained `runtime: node` again.
- [x] An image-created service and a Git-created native service read exactly as before.

## Out of scope

- What the deploy runs (t002).

## Result (2026-11-17)

`core.EffectiveRuntime` (`lego/backend/internal/core/source_runtime.go`) now decides from the source first: an image with no repo reads `image` whatever runtime it keeps, and a stale `image` runtime on a Git source still reads its build (w8/088). Callers checked: the REST/GraphQL/MCP view (`apps/service.go` `view`), REST `envSpecificDetails` (`render.go`), the REST list's `env` filter (`rest.go`), Blueprint generation (`blueprint_generate.go`, which already exported an image entry), and build-source build reads (`deploys/build_sources.go`, repo carriers only). None needs the retained runtime: the dashboard's Runtime and Build sections show only for a repo-backed service. `spec.runtime`, `builder` and `rootDir` stay. Tests: `TestNativeToImageSwitchReadsAsAnImageService`, `TestSourceSwitchToImageAcrossCallersTypesAndSources`; three fixtures that were image-only Apps labelled `docker`/`node` gained a repo (`cron_docker_command_test.go`, `api/service_list_filters_test.go`).
