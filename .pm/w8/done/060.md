# 060 — Service events answer `service_hibernated` / `service_woken` on the Render REST feed, outside Render's closed event-type enum, unseen by conformance

Why: this is the event-feed half of the drift w8/058 fixed for deploy triggers. A strictly generated Render client (OpenAPI SDK, Terraform provider) reading `/v1/services/{id}/events` for any free service gets type values that are not in Render's enum. Free services sleep and wake many times a day, so these are often the bulk of the feed. `TestRenderConformance` allowlists only event `details`, and its fixture seeds a single deploy event, so these values go unseen.

Severity: minor. Attribution: server (`lego/backend/internal/events`, `lego/backend/internal/api` conformance).

## Evidence (2026-10-05, `/qa-find-bugs-cli` w8 loop, sweeps 20 and 22)

Production pin `f837cec46` (w8/058's fix `bexTrigger` is merged but not yet deployed and does not touch events), workspace `bex-canary`, human device login, read-only GETs with the CLI's token (read privately), User-Agent `render-cli/2.27.0`.

```text
GET /v1/services/srv-daif6dsmg29s73d1umvg/events?limit=100&startTime=2026-10-01T00:00:00Z     (hello-go, free web)
→ 43 events: service_hibernated ×20, service_woken ×19, deploy_ended, build_ended, build_started, deploy_started
jsonschema 4.23 vs serviceEventWithCursor (pinned render-public-api-1.json):
  $[*].event.type  value "service_hibernated" not in enum
  $[*].event.type  value "service_woken" not in enum
```

Render's event-type enum (`components.parameters.eventTypeParam` → 43 values) has no sleep/wake member. Render's free-tier spin-down produces no event. (Control: `GET …/events?limit=100` with no `startTime` returns `[]` when the newest event is more than an hour old. That matches Render's documented `now() - 1 hour` default, `events/service.go:527-531`. Not a bug.)

## Mechanism

- `lego/backend/internal/events/service.go:178-179` (`TypeServiceHibernated`, `TypeServiceWoken`) emits both types into the shared feed served by REST, GraphQL, MCP, webhooks and notifications.
- `lego/backend/internal/api/conformance_allowlist_test.go:119-126` allowlists only `event/details` for `list-events`/`retrieve-event`. The conformance fixture's `conformEventStore` seeds one deploy `started` row, so no sleep/wake type is ever validated.

## Fix

Mirror w8/058's approach on the Render REST/MCP event shape. Either map sleep/wake onto an honest Render value (there is no close one; `server_restarted`/`service_resumed` would claim a different cause) and keep bex's value in an extension field (for example `bexType`, as `bexTrigger` does for deploys), or omit these two types from the Render-shaped REST feed and keep them on GraphQL/dashboard/webhooks. Record the choice in ADR018. Make the conformance fixture seed one event per emitted `events.Type*` value, so a new type fails until it is mapped or allowlisted.

## Acceptance

- [ ] `GET /v1/services/<free-svc>/events?startTime=<1d ago>` validates against `serviceEventWithCursor`: no `type` outside Render's enum, or the documented extension field carries bex's value.
- [ ] `TestRenderConformance` fails for an unmapped `events.Type*` value emitted on REST.
- [ ] Controls: dashboard Events tab, webhooks and notifications still show "hibernated"/"woken" exactly as today. Render-enum types are unchanged.

## Dedupe

Split out of w8/058, whose fix (done 2026-10-05) covered deploy `trigger` only. `rg -i 'service_hibernated|service_woken' docs .pm` finds feature notes (w1/m151, w8/m44) but no conformance or enum discussion.

Estimate: ~40m.

**DONE 2026-10-05 (kept as declared extensions, not remapped):** ADR018's Service events row already records bex-named types on REST as deliberate ◐ drift (~30 config/domain/job/env-group types share the shape), so remapping only this pair would be inconsistent and there is no honest Render value for it. `lego/backend/internal/events/rest_vocab_test.go` `TestRESTEventTypesAreRenderOrDeclaredExtensions` enumerates every REST-emitted type (deploy phases, audit verbs incl. auto-deploy sub-types, service facts, datastore types) against the pinned `eventTypeParam` enum and fails on any type outside it that is not declared with a reason (proved by dropping `service_woken`). ADR018 names the sleep/wake pair. Acceptance #1 is met through the documented-extension branch; if strict-enum parity is ever wanted, the gate's map is the worklist.
