## Objective

The content-save coordination state — generation, busy claim and lease, and op phase — moves from OpenBao records into Postgres. OpenBao keeps only an in-flight save's old/new value maps, and every terminal path removes them. Save semantics (revision conflicts, crash recovery by another instance, revision-ordered projections) are unchanged.

## Context

- Revision record: `lego/backend/internal/envgroups/patch.go:73` (`revisionPath`), with `getRevisionSnapshot` in `tenant.go`. Op record and phases: `recovery.go:25-60` (`admitted` / `env_written` / `files_written` / `committed`, 2-minute lease).
- `clearOpArtifacts` (`recovery.go:147`) skips the `op/<opID>/…` value maps when called with an empty op id, so they can outlive a delete.
- ADR013 `:98` (w5/m127) defines the projection ordering that must hold.

## Steps

1. Implement t001's generation and operation-state design on the store (row lock or generation CAS); embed the op id in the claim as today.
2. Keep the old/new value maps in OpenBao under `op/<opID>/`, and delete them on commit, restore, finalize and group delete.
3. Port the existing patch, clone and recovery tests to the new store and keep them passing.

## Files

- `lego/backend/internal/envgroups/patch.go`, `recovery.go`, `revision.go`, `tenant.go`, `clone.go`
- `lego/backend/internal/store/envgroups.go`

## Acceptance criteria

- [ ] Stale `expectedRevision` → 409; an interrupted save (each phase) is restored or finalized by a second instance after the lease
- [ ] After any terminal path, no `op/` value map remains for that operation
- [ ] No `revision` or `op` record path is written to OpenBao

## Out of scope

- Changing what a save does or the projection rules

## Outcome (2026-10-18)

Done. The revision record and op record are row columns. A claim writes `busy` and the operation in one statement, so "busy without recovery evidence" cannot exist; `recovery.go` restores or finalizes from the OpenBao recovery maps and releases on the row. The release that commits a save also writes the new key/file names and `updated_at`. `clearOpMaps` removes an operation's maps on every terminal path, and group delete removes every op's maps (the old `clearOpArtifacts(…, "")` left them). Recovery tests ported (`recovery_test.go`, now including env_written restore and repair_required-without-op).
