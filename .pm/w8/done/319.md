# A static site answers `POST`, `PUT`, `DELETE`, `PATCH` and `OPTIONS` with `405 method not allowed`, where Render answers `200` with an empty body

Why: a request to a static site with a method other than `GET` or `HEAD` gets 405 on bex. Examples:

- an HTML form that posts to a page;
- a webhook or uptime monitor pointed at the site;
- a CORS preflight `OPTIONS`.

Render answers the same requests with a bare `200` and `content-length: 0` on every path, whether the file exists or not. Senders that treat 4xx as failure therefore retry or alert on bex, and a posted form shows "method not allowed" instead of Render's blank 200. Render parity first.

**Severity:** minor. No content is lost, but the status a client branches on differs from Render's. **Attribution:** server (static-server). **Estimate:** ~20m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `bc16`, 2026-11-13 UTC, released `bex v0.6.0`, `https://api.bex.co/v1/`, workspace `bex-canary`, production pin `3e30e291e`.

## Render's behavior (black-box captures, 2026-11-13 ~23:25 UTC)

Four unrelated Render static sites, each response carrying Render's `rndr-id`:

- Render's own `sveltekit-static.onrender.com`;
- `wrappedforlinkedin.onrender.com`, whose `render.yaml` has a `/* → /index.html` rewrite;
- two Docusaurus sites, `mentorship-guide.onrender.com` and `breadcrumbs-wiki.onrender.com`.

Each was probed with `POST` and `OPTIONS` (with `Origin` and `Access-Control-Request-Method` headers) on `/`, an existing file and a missing path. All 24 answers were the same:

```
HTTP/2 200
content-length: 0
rndr-id: …
cf-cache-status: DYNAMIC
server: cloudflare
```

`PUT`, `DELETE` and `PATCH` on `sveltekit-static.onrender.com/` answer the same way. The answer has no body and no `content-type`. It also lacks the `strict-transport-security` and `x-content-type-options` headers that the same site's `GET` carries, and no `access-control-*` headers appear. A `POST` with a form body to an existing page (`/docs/about`) is also an empty 200, not the page.

## bex (fixture `qa-20261113-bc16-st`, `srv-dbrpnpu9k6ds73eb4ro0`)

Static site from `octocat/Spoon-Knife`, publish path `.`. For each of `POST`, `PUT`, `DELETE`, `OPTIONS` and `PATCH`, on `/`, `/index.html` and `/missing-bc16`:

```
HTTP/2 405
allow: GET, HEAD
content-type: text/plain; charset=utf-8
content-length: 19
method not allowed
```

A control `curl https://qa-nohost-x.onbex.co/` stayed a clean 404.

## Root cause

`Handler.ServeHTTP` (`lego/operator/internal/staticserver/staticserver.go:250-254`) sends every method other than `GET`/`HEAD` to `serveOtherMethod` (`:402-408`). That function proxies a matching external rewrite (`serveExternalRewriteForMethod`, `:1137`, w8/184) and otherwise answers `405` with `Allow: GET, HEAD`. The 405 dates from the first static-site implementation (`918c97b9b`, 2026-07-12) and was never compared with Render.

## Fix (target behavior)

- In `serveOtherMethod`, a resolved site whose request no external rewrite claims answers **200** with `Content-Length: 0` and no body.
  - Keep it headerless, as Render's answer is and as `TestUnresolvedHostAndMethodStayHeaderless` already requires for the 405.
  - Read and discard no more of the request body than `net/http` already does.
- Keep these unchanged:
  - an external rewrite still proxies any method (w8/184);
  - `GET`/`HEAD` handling;
  - a suspended site's answer;
  - an unknown host's `404 no static site for host` (resolve the host first, so an unknown host does not start answering 200).
- Update `TestMethodNotAllowed` (`staticserver_test.go:314`), `TestUnresolvedHostAndMethodStayHeaderless` (`:747`), `host_case_test.go:88` and `proxy_test.go:94` ("a method no rule claims") to the new answer, renamed to say what they check.
- Record the behavior in ADR029 and the ADR018 static-site row, citing the captures above.

## Blast radius

The change is confined to the static-server's method gate, shared by every static site. Web services are untouched, because their requests reach the app. No REST, GraphQL or dashboard surface serves static bytes.

## Acceptance

- Handler tests:
  - `POST`, `PUT`, `DELETE`, `PATCH` and `OPTIONS` on an existing file, a missing path and `/` → 200, `Content-Length: 0`, empty body, no custom headers;
  - an external rewrite still proxies `POST`;
  - an unknown host still answers 404.
- Live, after the static-server rolls: the same `curl -X POST|OPTIONS` matrix against a fresh static fixture answers 200 with `content-length: 0`. Delete the fixture.

## Unverified

- Whether Render adds a site's custom `headers` rules to this answer. None of the captured sites sets one on these paths. The bare answers suggest Render's edge does not.
- Whether Render applies a local redirect rule (301) to a non-`GET` request.

## Dedupe

- Searched `.pm` open and done and ADR029 for `405`, "method not allowed", `OPTIONS` and non-`GET`.
  - Only w8/137 (REST rule endpoints, unrelated), w8/184 (external rewrites for other methods, kept) and w4/309 (host case, which kept the 405 incidentally) mention it.
- Neighbors filed this loop: w8/317 (`<path>.html`) and w8/318 (directory index). The same fixture reproduces both: `/page` with `page.html` → 404, `/about` with `about/index.html` → 301.

**DONE 2026-11-13.**

- **Code:** `ServeHTTP` (`lego/operator/internal/staticserver/staticserver.go`) now resolves the host first for every method, so an unknown host keeps its `404 no static site for host`. A suspended site then answers every method with its 503 (`serveSiteUnavailable`), as it does for `GET`, rather than a 200 that reads as live. Render's answer for a suspended site was not captured. Any other method on a live site goes to `serveOtherMethod`. If an external rewrite claims the path, it proxies (w8/184; the root path is never rewritten, and both branches share `isExternalRewrite`). Otherwise the request gets Render's bare 200: `Content-Length: 0`, no body, no content type and none of the site's headers. `serveExternalRewriteForMethod` and the 405 with `Allow: GET, HEAD` are gone. The request body is read no further than `net/http` already drains it.
- **Tests:**
  - `TestOtherMethodsGetABareOK` sends `POST`, `PUT`, `DELETE`, `PATCH` and `OPTIONS` to `/`, a file, a miss, a redirect source, a local-rewrite path and a rule whose target fails to expand. Each answers 200 with no body and no headers.
  - `TestASuspendedSiteRefusesOtherMethodsToo` checks the suspended 503.
  - `TestUnresolvedHostStaysHeaderless` now also sends a `POST` to an unknown host and expects 404.
  - `TestHostLookupIgnoresLetterCase`, `TestExternalRewriteProxiesAnyMethodAtTheOriginalPath` and `cmd/staticserver` `TestHealthPathErrorsKeepTheSiteContract` were updated.
  - Five of the changed tests fail on the previous handler. The full operator suite passes.
- **Docs:** ADR029 has a new section, "Other methods", and its external-rewrite and headerless lines are amended. The ADR018 static-site row is updated.
- **Production check after the static-server rolls:** on a fresh static fixture, `curl -X POST|PUT|DELETE|PATCH|OPTIONS` on `/`, a file and a missing path should each answer 200 with `content-length: 0`. Delete the fixture afterwards.
