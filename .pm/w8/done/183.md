# A static site never serves its `404.html`, and every extension-less miss returns the home page with 200: Render answers a miss with 404 and the site's own `404.html`

Why: on Render, a request for a static-site path that matches no file and no redirect or rewrite rule gets **404**. The body is the site's root `404.html` when it has one ([Render staff on community.render.com](https://community.render.com/t/custom-404-page/26172); [redirects-rewrites docs](https://render.com/docs/redirects-rewrites): rules apply only where no resource exists; client-side routing needs an explicit `/* → /index.html` rewrite).

Bex differs in three ways:

- It serves the root `index.html` with **200** for every extension-less miss, even without a rewrite rule.
- It ignores `404.html` entirely, even when the site publishes one.
- It answers asset-like misses with a plain-text `not found`.

So every broken link on a Hugo, Jekyll, Docusaurus, Astro or plain HTML site shows the home page as a successful page (a soft 404 that search engines index and link checkers pass), and the custom error page the generator built never appears. ADR029's "Default SPA fallback" calls this a deliberate divergence ("the decision (w3/m46)"), and ADR018's static row says "accepted"; neither records a user sign-off. ADR029 does not mention `404.html` at all.

**Severity:** major (affects every static site with a broken or mistyped URL; generator sites ship a `404.html` by default). **Attribution:** platform runtime (static-server miss handling). **Estimate:** 1h30m plus a migration decision for existing SPAs. **Source:** `/qa-find-bugs-cli` sweep 1315, 2026-10-22 ([evidence](evidence/cli-sweep1300/README.md#sweep-1315--static-site-misses)).

## Expected

When no file exists at the request path and no redirect or rewrite rule matches:

- if the site's publish root has `404.html`, serve it with status **404** (custom headers apply as for other error responses);
- otherwise, return 404 with a plain body.

A site that wants client-side routing adds Render's `/* → /index.html` rewrite. It then gets the existing behavior through the rule, not by default.

## Root cause

`lego/operator/internal/staticserver/staticserver.go:356–365`: after rule handling, `h.spaFallback` (`:544–556`) serves `/index.html` for any extension-less miss when a root `index.html` exists. The remaining misses go to `serveSiteError(…, 404, "not found")` (`:783–786`, `http.Error`), which never looks up `/404.html`. ADR029:142–146 documents the fallback as intended.

## Fix

1. Replace the unconditional `spaFallback` with Render's order: an existing file; then redirect and rewrite rules (already first); then the root `/404.html` served with status 404 (through `serveObject` with an overridden status, keeping ETag and caching rules sensible for an error body); then a plain 404.
2. Migration: existing sites created before the change with no routes may rely on the implicit fallback. Decide in ADR029 and ADR018 (user sign-off if anything is kept) between:
   - adding an explicit `/* → /index.html` rewrite once to sites whose deploys show SPA-like traffic, or that have no `404.html` and a single `index.html`;
   - applying the new behavior only to sites created after a cutoff, like w5/m147's WEB_CONCURRENCY cutoff.

   Either way, new sites behave as on Render.
3. Update ADR029 § Default SPA fallback and ADR018's static-site row.

## Blast radius

Every static site's miss path, on all hosts (platform subdomain and custom domains), including resumed and suspended handling (unchanged). Sites with explicit rewrite rules are unaffected. Blueprints with `routes` are unaffected.

## Acceptance

- Unit: with `404.html`, an extension-less and an asset-like miss each return 404 with its body; without it, a plain 404. With a `/* → /index.html` rewrite, deep links return the index with 200.
- Live after deploy: repeat the table. The `404.html` site returns 404 "qa1315 custom 404" for both misses, and the plain site returns 404. Delete by ID with 404 proofs.
