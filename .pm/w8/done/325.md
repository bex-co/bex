# A static-site rule `/x/*` also matches the bare path `/x`, for both routes and headers, where Render matches only `/x/` and the paths below it

Why: on Render a source or header path ending in `/*` covers the directory and its contents (`/x/`, `/x/a`), not the bare `/x`. On bex, `/x/*` also claims `/x`. So a redirect such as `/assets/* → https://cdn…/assets/*` turns `/assets` into a 301 to `https://cdn…/assets/` where Render answers 404 (or serves a real `/assets` page). A header rule such as `/data/* Access-Control-Allow-Origin: *` also lands on `/data`, which Render leaves alone. Render parity first.

**Severity:** minor. **Attribution:** server (static-server matcher). **Estimate:** ~30m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `1b01`, 2026-11-14 03:25 UTC, released `bex v0.6.0`, `https://api.bex.co/v1/`, workspace `bex-canary`, production pin `ac206b76841b`.

## Root cause

`matchPattern` (`lego/operator/internal/staticserver/staticserver.go:789-803`) documents `"/foo/*" matches "/foo" and "/foo/..."` and returns a match for `reqPath == prefix`. Both paths use it:

- `matchRoutePattern` (`:822`, routes);
- `matchHeaderPattern` (`:980-992`, headers, through its fallback at `:990`).

## Fix (target behavior)

- `/x/*` matches `/x/` (splat empty) and `/x/<anything>`, never `/x`.
- `/*` still matches every path including `/`.
- Exact patterns, `:name` segments and the header grammar's `/**/*.ext` and `/dir/*.ext` forms are unchanged.
- Apply it to routes and headers alike, since Render behaves the same way for both.
- The w4/384 directory redirect (`/x` with `x/index.html` → 301 `/x/`; in-place 200 once w8/318 rolls) runs before rules and is unaffected.
- Record it in ADR029 (§ route grammar at :130 and the header grammar) and the ADR018 static-site row, citing the captures above.

## Blast radius

- **Sites:** every static site using a `/x/*` rule.
- **Callers:** `matchPattern` has three: route matching, header matching, and `serveExternalRewriteForMethod` through `matchRoutes`.
- **Rewrites:** `/app/* → /index.html` stops claiming `/app`, which then falls to the next rule, the file lookup or the miss. That is Render's behavior. Sites that relied on bare `/app` add an exact `/app` rule, so call it out in ADR029.
- **Tests:** existing ones that assert `/foo/*` matches `/foo` need updating.

## Acceptance

- Matcher tests:
  - `/x/*` vs `/x` → no match;
  - `/x/*` vs `/x/` → match with an empty splat;
  - `/x/*` vs `/x/a/b` → match `a/b`;
  - `/*` vs `/` → match.
- Handler tests:
  - a redirect `/ext/*` leaves `/ext` to the miss path (404);
  - a header `/data/*` does not reach `/data`.
- Live, after the static-server rolls: `GET /ext` on a fixture with `/ext/* → …` answers 404, and `/ext/` still 301s. Delete the fixture.

## Unverified

- Render's treatment of `/x/*` against `/x` when `x/index.html` exists. Directory resolution (w8/318) runs first on bex.
- `:name` patterns with a trailing `/*` against the bare prefix.
