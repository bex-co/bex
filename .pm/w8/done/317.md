# A static site answers 404 for `/about` when it publishes `about.html`, where Render serves the page, so every prerendered SvelteKit, Next.js-export or Astro page but `/` breaks on reload

Why: Render's own SvelteKit guide deploys `render-examples/sveltekit-static`. That template prerenders `index.html` and `about.html` (adapter-static), and its header links to `/about`. On Render a direct visit or reload of `/about` serves `about.html` (200). On bex the same template's `/about` and `/about/` answer 404, so any page except `/` dies as soon as a visitor reloads it or follows a shared link. The same applies to every generator that writes `<page>.html`: Next.js `output: 'export'` (`out/about.html`), Astro `build.format: 'file'`, Docusaurus `trailingSlash: false`, Hugo `uglyURLs`.

**Severity:** major (a core static-site journey: Render's official template is broken for every page but the root). **Attribution:** server (static-server, `lego/operator/internal/staticserver`). **Estimate:** ~45m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `617f`, 2026-11-13 UTC, released `bex v0.6.0` (Render CLI v2.36.0), `https://api.bex.co/v1/`, workspace `bex-canary`, human device login, production pin `1c4d721bc8dc`.

## Root cause

`Handler.ServeHTTP` (`lego/operator/internal/staticserver/staticserver.go:250`) handles a request in this order:

1. It looks up the exact object through `fetch` → `lookupPath` (`:610-629`). `lookupPath` adds `index.html` only for `/` or a path ending in `/`.
2. On a miss, it runs the route-expansion check (`:316`).
3. Next comes the directory-index redirect (`redirectToDirectory`, `:329`, `<path>/index.html` only; see w8/318).
4. Then the ordered rules run (`:332-384`), then the pre-cutoff SPA fallback (`:390`), then `serveNotFound` (`:396`).

No step tries `<path>.html`, so a site created on or after `SPAFallbackCutoff` answers 404. A site created before the cutoff is worse off: `spaFallback` (`:647`) serves the root `index.html` with 200 for `/about`. That shows the wrong page wherever pages differ, as in a Next.js export.

## Fix (target behavior)

Add the resolution at the same point as the directory resolution (after a genuine miss and the route-expansion check, before the ordered rules and the SPA fallback). It applies only when the request path is extensionless (`path.Ext` empty after stripping one trailing `/`) and is not `/`:

- If `<path without trailing slash>.html` is published, serve it with **200 in place**, as an ordinary object:
  - the content type, ETag, ranges and conditional handling of `<path>.html`;
  - custom headers matched against the **request** path, ADR029's request-path contract.
- `/index` and `/index/` then serve the root `index.html`.
- Leave alone: anything with an extension (`/favicon`, `/about.htm`, `/about.html/` stay misses), case (`/ABOUT` stays a miss), over-long keys (`overlongKey`), `.git` paths (`hasGitSegment`), and the origin error classes (only `ErrNotFound` continues to the next step).
- Order relative to w8/318's `<path>/index.html`: when both are published, Render's choice was not captured (see Unverified). Pick one, test it, and record it as uncaptured.
- Record the rule in ADR029 (§ Directories without a trailing slash becomes "Extensionless paths") and in the ADR018 static-site row, citing the captures above.

## Blast radius

- **Sites:** every static site, which all share the static-server, on both sides of the cutoff. Pre-cutoff sites stop serving the root `index.html` for `/about` when `about.html` exists, which is a fix, not a regression.
- **Code path:** only `ServeHTTP`'s miss path changes. `fetch`/`lookupPath` also serve rewrite targets (`:367`): a rewrite to `/about` should resolve `about.html` the same way. Decide that explicitly and test it.
- **No other surfaces:** the dashboard, REST and GraphQL serve no static bytes.

**DONE 2026-11-13.** Shipped together with w8/318 as one change to the static-server's miss path.

- **Code:** `fetchPage` (`lego/operator/internal/staticserver/staticserver.go`) resolves a visitor's path as Render does: the object at it, then on a miss `resolvePage`. That tries `<path>.html` for an extensionless path, with or without one trailing slash, then `<path>/index.html` for a slashless one. The page is served in place with 200 as an ordinary object: `about.html`'s type, ETag, ranges and conditional handling, with custom headers matched against the request path. Both the request and a rewrite target resolve through it. A page now wins over every rule, even one whose expansion is refused (the 400 a miss would get), as a direct object hit already did. An origin failure on a candidate answers its own class instead of falling into a rule or the root page.

Under fetch-gate overload a page probe answers 503 where the old directory probe fell through to the root `index.html`.
