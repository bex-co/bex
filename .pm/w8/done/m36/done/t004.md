## Objective

Make source and validation failures visible through existing sync history, and prevent applying a stack when its run could not be recorded.

## Context

- Parent milestone: [w8/m36 — Blueprint Git source integrity](../README.md), user-approved on 2026-09-08.
- CreateBlueprint and runSync currently ignore InsertBlueprintSync errors; source/preflight failures can also return before any run is recorded.
- w6/m50 already added BlueprintSync.errorMessage across REST, GraphQL, MCP, and the dashboard. Reuse that channel.

## Steps

1. For an existing Blueprint, record an attempt before source/preflight work so failures can terminate in history. Initial creation failures before a Blueprint identity exists return normal errors without fabricating a resource; after identity exists, persist the initial run before application.
2. Require successful run insertion before workload side effects; when the store is unavailable, return an error without promising a history row.
3. Propagate completion-write failures rather than returning success with misleading persisted state; retain enough run identity for m37's recovery work.
4. Verify the existing adapters and Sync History display consume the same result; change projection code only where necessary.

## Acceptance criteria

- [ ] With a working store, an existing Blueprint's failed fetch/validation attempt has an error run and a useful sanitized reason; pre-identity create failure does not invent a Blueprint.
- [ ] A failed run insertion causes no App, datastore, grouping, environment, or ownership mutations.
- [ ] Initial-create and manual/webhook sync use consistent source-failure semantics.
- [ ] REST, GraphQL, MCP, and the dashboard expose the failure without leaking source secrets.
- [ ] A failed completion write is not reported as verified success.

## Out of scope

- Multi-replica execution admission, atomic lifecycle transitions, and abandoned-run recovery; m37 owns these.
- Adding a parallel error-history store.
