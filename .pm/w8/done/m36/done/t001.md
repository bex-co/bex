## Objective

Make the GitHub Blueprint reader return either a complete bounded manifest or an error, so a valid-looking YAML prefix can never be applied as the whole file.

## Context

- Parent milestone: [w8/m36 — Blueprint Git source integrity](../README.md), user-approved on 2026-09-08.
- Source review on 2026-09-08 found GetFileContents using io.LimitReader at 1 MiB and discarding io.ReadAll errors; an oversized or interrupted response can therefore look successful.
- The same GitHub client serves public and installation-authenticated repositories. Preserve both authentication paths and existing path containment.

## Steps

1. Reproduce an interrupted 200 response and an oversized response whose first 1 MiB is valid YAML.
2. Read through the existing limit plus one byte; propagate transport/read failures and explicitly reject an over-limit body.
3. Classify missing-file, upstream-auth/rate-limit, and transient transport failures without exposing upstream bodies or credentials. Apply the same complete-response discipline to commit resolution where needed.

## Acceptance criteria

- [ ] Exactly-at-limit complete content is accepted; limit-plus-one content is refused.
- [ ] A reader error after a valid YAML prefix remains an error.
- [ ] 404, denied access, rate limits, and interrupted responses do not become successful empty or partial content.
- [ ] Error output contains neither installation tokens nor raw upstream response bodies.

## Out of scope

- Raising the accepted Blueprint size limit.
- GitLab/Bitbucket integration or a new HTTP client abstraction.
