# The bex skills pack tells agents to require "bex CLI v2.7.0+", a version that does not exist

Why: the skills that `bex skills install` writes (w8/m143, released in `bex-cli/v0.4.0`) still carry the Render CLI's version floor, renamed to bex. The current bex CLI is **v0.4.0**. An agent that reads "requires bex CLI v2.7.0+" will conclude the installed CLI is too old. It may then refuse to run `bex blueprints validate`, or tell the user to upgrade to a release that will never exist. `bex --version` itself prints `bex v0.4.0 / compatible with Render CLI v2.29.0`. The 2.x number belongs to the pinned Render CLI, not to bex.

Severity: **minor** (agent guidance; the commands themselves work). Attribution: `lego/cli/internal/skills/pack/skills/**`. Estimate: ~20m. Source: `/qa-find-bugs-cli` loop sweep 3093, 2026-11-04 12:1x UTC, released `bex-cli/v0.4.0` skills pack in a sandboxed `HOME`.

## Evidence

```text
lego/cli/internal/skills/pack/skills/bex-cli/SKILL.md:12                       compatibility: bex CLI v2.7.0+ (Homebrew, Linux/macOS, direct download)
lego/cli/internal/skills/pack/skills/bex-blueprints/SKILL.md:14                v2.7.0+ recommended for `bex blueprints validate`.
lego/cli/internal/skills/pack/skills/bex-blueprints/references/common-mistakes.md:105   `bex blueprints validate` (CLI v2.7.0+).
lego/cli/internal/skills/pack/skills/bex-{blueprints,deploy,migrate-from-heroku}/references/blueprints.md:20
                                                                                When bex CLI v2.7.0 or later is available, validate the finished file:
```

The installed copies under `~/.agents/skills/bex-*` match: the same text is in the released pack.

## Fix

Drop the Render version floor from the pack. Either state no minimum, or state the bex release that first shipped the command: `bex blueprints validate` exists in every released bex CLI, so "any bex CLI" is accurate. If a floor is wanted, generate it from the pack's own release train (`bex-cli/v*`) rather than hard-coding it. Add a pack lint that rejects `v2\.\d+\.\d+` next to "bex CLI".

## Acceptance

`grep -rn 'v2\.[0-9]' lego/cli/internal/skills/pack/skills` finds no bex-CLI version claim, and a freshly installed pack from the next release says nothing an agent could read as "your bex v0.x is too old".

Dedupe: m143 (done) replaced Render references and URLs but kept these version strings; no other `.pm` item mentions them. The `brew install bex-co/tap/bex` instruction is correct: the tap exists and carries 0.4.0 since w9/073 (done) republished it.

**DONE 2026-11-04** (`/loopx w8`): all six Render version floors are gone from the pack; the text now states no minimum, because every released bex CLI has `bex blueprints validate`. `TestPackOperatesBexOnly` now rejects any `v2.x.y` line in the pack (`renderVersionFloor`), and it reported all six on the old text. `grep -rn 'v2\.[0-9]' lego/cli/internal/skills/pack/skills` finds nothing. The pack is embedded, so the fix reaches users with the next `bex-cli/v*` release; it is not published by this change.
