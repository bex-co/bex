# Service create dry-run skips every check the real create runs after the spec resolves

Why: `dryRun: true` answers "this would succeed" for creates the real call refuses (reserved `dashboard.bex.co`, a taken name, `PORT`, a domain another service owns), so agents, MCP clients and CI cannot trust a preview as a validation step.

Found by live QA 2026-10-03: a dry-run service create with custom domain `dashboard.bex.co` returned a preview; the same request without dry-run is refused `400 "dashboard.bex.co" is a reserved platform hostname`.

- `lego/backend/internal/apps/service.go:1925-1936` returns the preview before `RequirePlanBilling` (`:1936`), `nameTaken` (`:1945-1954`), `checkReservedSpecEnv` (`:1959`), `GitHub.ValidateRepo` (`:1980-1984`) and `ensureHostsClaimable` (reached via `materializeNewApp` at `:2304`: per-service domain cap `domains.go:1007`, workspace quota `:1012`, reserved host `:1026-1027` via `reservedHost` `:796-807`, claimed by another service `:1040`, ownership `:1044`).
- Fix: move the dry-run return to just before `materializeNewApp`, so every read-only check runs first; for hosts, call `ensureHostsClaimable` on the preview App (same name, tenant label, environment — `ownPlatformHost` needs the slug) and confirm it writes nothing. Decide explicitly whether dry-run also returns the billing 402 (Render's dry-run semantics unverified; real-create parity is the safer default).
- Tests (`apps`): a table where each refusal (reserved host, dashboard host, duplicate name, `PORT`, claimed domain) gives the same error with and without `DryRun`, while w2/m29's zero-writes assertions still pass; one REST `?dryRun=true` case.
- Check the Postgres/Key Value dry-run paths (`lego/backend/internal/postgres/service.go:663`, keyvalue) for the same early return; cover here or file a sibling note.

## Resolution (2026-10-03)

- `apps.Service.create` (`lego/backend/internal/apps/service.go`): the dry-run return now comes after every read-only check: `RequirePlanBilling`, `nameTaken`, `checkReservedSpecEnv`, `GitHub.ValidateRepo`. It then runs the two read-only gates the real create runs inside `materializeNewApp`, in the same order, on the preview App: the new `previewHostsClaimable` and the existing write-free `validateExternalRegistryCredential`. The preview keeps the bare request name, so its id is unchanged.
- `previewHostsClaimable` (`domains.go`) shares `checkHostsClaimable` with `ensureHostsClaimable`: the per-service and per-workspace domain caps, reserved/dashboard/base-apex hosts, and hosts another service owns. It only reads. Two inputs exist only after the create writes, so they are handled conservatively. With the store on, the real slug is random (`store.CreateApp`), so the preview exempts no `*.<base>` host. The DNS-TXT ownership proof is keyed by the minted id, so it is not evaluated. The store-mode real create never runs that proof either, because managed claims start pending.
- Billing decision: a dry run returns the same 402 as the real create (real-create parity). The gate is read-only (`PaymentGate.PaymentEligibility`, `CheckBillingMutationAllowed` SELECT). Render does not document dry-run semantics for service create, so parity is the safer default.
- Postgres and Key Value (`postgres/service.go`, `keyvalue/service.go`): name, version, plan, allow-list and admission checks already ran before their dry-run return. `RequirePlanBilling` now runs before the return too.
- Tests: `apps/dryrun_parity_test.go` has a table (reserved dashboard host, reserved platform subdomain, base apex, claimed domain, per-service cap, duplicate name, `PORT`, inaccessible repo, registry credential without support). Each case checks that dry-run returns the real create's exact error and writes nothing. It also covers an admissible preview, the billing 402, the store-mode `*.<base>` refusal, and REST `?dryRun=true` with `dashboard.bex.co` returning 400. `postgres`/`keyvalue` `payment_gate_test.go` cover the dry-run 402. The w2/m29 zero-write tests still pass. All backend packages pass (`go test ./...` on HEAD plus this change), and `make lint` is clean.
- Not covered: plan object-count caps (Hobby 25 services / 1 Postgres / 1 Key Value) are enforced only by namespace ResourceQuota admission on the real CR create, so a dry run still previews a create past the cap. Filed as [046](../046.md).
