## Closed — 2026-11-17 (loopx session)

Every `native-common-image.yml` utility cohort (`TestNativeUtilityGeneratedImages`) runs these real-image checks on the image it publishes:

- **The original PyVips app** (already maintained). `python313-original` runs the frozen m95 program on the Python 3.13 primary. At build it installs `pyvips==3.2.0` from the prepared wheel and transforms the 107-byte PPM to exact 2×1 red/blue pixels and a PNG. Three HTTP requests on a `--network none` runtime repeat the transform, and the frozen oracle decodes the PNG independently.
- **Headers** (already maintained). `utility-check.py` compiles and links a C program through `pkg-config --cflags --libs vips`, checks its output pixels, and requires `vipsheader` to refuse an invalid PPM.
- **New, vips tools** in `utility-check.py`, at the `node-compute` build and network-off runtime and at the `node-static` build:
  - `vips resize … --kernel nearest` on the m95 image gives exactly PyVips' pixels, decoded by `png-decoder.py`;
  - `vipsthumbnail` writes a 4×2 JPEG through `jpegload`, red on the left and blue on the right;
  - a lossless WebP round trip returns the PPM's 96 pixel bytes exactly;
  - a hand-written 2×2 BMP loads only through the packaged `vips-magick` module, with exact pixels.
- **New, `missing-libvips` omission control.** On the Python 3.13 primary, a test-only layer removes only `libvips.so.42*` and refreshes the loader cache. It checks that `find_library('vips')` finds nothing while the headers and `vips.pc` remain. The original m95 build must then fail with `cannot load library 'libvips.so.42'` after the layer's ready line.
- **How this was checked before shipping.** The host is arm64 and the adopted image is amd64-only, so the generated-image gate cannot run here. On `python:3.13-bookworm` arm64 with the identical `libvips-dev`/`libvips-tools` 8.14.1-3+deb12u3:
  - the libvips block passed;
  - each new assertion failed under its mutation: resize without `--kernel nearest`, lossy WebP, `vips-magick.so` removed ("not a known file format") and `vipsthumbnail` removed;
  - the original m95 build and its three network-off runtime requests passed through `original-cases.py`;
  - after the exact omission command, pip installed `pyvips` 3.2.0 and the original build failed. The API-mode import failed with an `ImportError` and the ABI fallback with `OSError: cannot load library 'libvips.so.42'`. Its before-probe matched the historical failure (`valid_before`, `shared_library` null).
  - The push of this change re-runs the amd64 utility cohort through `native-common-image.yml`; that run is the amd64 proof.
- **Unit and package checks.** `go test ./internal/build/` (including `TestNativeOriginalReplayHTTPOracles` and the omission-evidence tests), `go vet`, `gofmt` and `golangci-lint` on the package (0 issues).
- **Bounds.** ARM64 is out of scope (D3). Pre-deploy runs the same image, and there was no hosted pre-deploy run (Free refuses it). Other Python lines rely on the families runs. HEIF/JXL encoding, OpenSlide, PDF loading and every optional codec are not exercised.
