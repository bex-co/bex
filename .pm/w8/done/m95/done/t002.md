## Closed — 2026-11-17 (loopx session)

Audited on main; the chain is the one w8/m94 t002 traced, unchanged since.

- **One recipe chain.** `nativeDockerfile` has one caller, `nativeBuildPreparer`, which every `BuilderNative` build Job runs. `cmd/native-resolve` ends with `applyNativeCommonBase` (`nativebases.go`), so every native web service, private service, worker, cron job and static-site build starts from the common image, whatever the primary (Node, Python, Ruby, Elixir, Go, Rust) and its companions.
- **Phases.** Build, pre-deploy and runtime run one image: the pre-deploy Job runs the image the build produced. A static site's image is only its publish Job's extract source, so it gets the library and tools at build only, which is all a static site has.
- **Library resolution.** `applyNativeCommonBase` re-copies only `/usr/local` from the selected primary, then runs `ldconfig`. `libvips.so.42`, its `vips-modules-8.14` loaders and the codec libraries live under `/usr/lib/<triplet>`, so `ctypes.util.find_library('vips')` returned `libvips.so.42` at build and runtime on production (t006). No `LD_LIBRARY_PATH`, `VIPS_*` variable or loader override is set, so an authored `PATH` or library path keeps its meaning.
- **Cache.** The base is digest-pinned. Tenant source and environment changes do not touch its layers. A package change is a new digest that misses the cache.
- **Exclusions.** Dockerfile, prebuilt-image and buildpack services never enter this recipe. A static site with no build command builds no native image.
- **Neighbors kept.** FFmpeg, Pandoc, SQLite, the PostgreSQL clients, native-init and the companion and package-manager steps are unchanged; m95 changes no product code.
- **Exercised versus source-only.**
  - Production (t006): build and runtime, Python 3.13, both CLIs, on the re-pin `4b809600…`. A first pair on the earlier `5d6b8139…` also built and went live.
  - Maintained cohort: the frozen m95 program on the Python 3.13 primary at build and on a network-off runtime (`python313-original`), and the header compile/link and vips-tool checks at the Node compute build, its network-off runtime and the static build (t005).
  - Families runs on the same digests: the other primaries, companions, native-init and static.
  - Not executed: a hosted pre-deploy run (Free refuses `preDeployCommand`, as Render does) and ARM64 (D3).
