## Closed — 2026-11-17 (loopx session)

The adopted common base (w8/m91 t007/t008) is the supplier. `deploy/native-base/install.sh` installs Debian's `libvips-dev` and `libvips-tools`, which pull `libvips42` and its normal closure. The SPDX attestations of `sha256:5d6b8139…` and of the re-pin `sha256:4b809600…` (now on production), both fetched again from the registry on 2026-11-16, list the identical 864 packages. Among them are `libvips42`, `libvips-dev`, `libvips-tools` and `gir1.2-vips-8.0` `8.14.1-3+deb12u3`, with `/usr/lib/x86_64-linux-gnu/libvips.so.42.16.1`, `pkgconfig/vips.pc`, `/usr/include/vips/vips.h`, the five tools `vips`, `vipsthumbnail`, `vipsheader`, `vipsedit` and `vipsprofile`, and the loader modules in `vips-modules-8.14` (`heif`, `jxl`, `magick`, `openslide`, `poppler`). The codec libraries come with them as distribution packages: JPEG, PNG, WebP, TIFF, GIF, HEIF, JXL, EXR, FITS, Matio, librsvg, Poppler and ImageMagick 6. That is Debian 12's package, the base Render names for its native runtimes.

- **Phases.** `/usr/lib` and `/usr/bin` are outside the primary's `/usr/local` copy, so the library, its modules and the tools are present before source and authored commands at build, pre-deploy and runtime (t002).
- **Identity.** A changed package is a new image digest, so a reviewed pin change re-qualified by a families run. The common image's `toolchain-freshness.json` entry and ADR060 D7 inventory it.
- **Binding.** No tenant Python binding is supplied. With the headers present, the original `pip install pyvips==3.2.0` built its API-mode wheel (`pyvips-3.2.0-cp313-cp313-linux_x86_64.whl`) against this library on production; without the headers it would load the same `libvips.so.42` in ABI mode. Neither path needs `pyvips[binary]`.
- **Not copied.** No donor root filesystem or bare `.so` symlink: the user's 2026-10-29 decision put every utility on the one Bookworm image as distribution packages, which also settles bookworm versus trixie. Render names no libvips version, so the version is not asserted to match Render's.
