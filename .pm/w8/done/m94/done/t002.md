## Closed — 2026-11-16 (loopx session)

Audited on main at `638bd4914`; production pin `7aaa8700befa` (common image `sha256:5d6b8139…`).

- **One recipe chain.** `nativeDockerfile` (`native.go:320`) has one caller, `nativeBuildPreparer` (`native.go:531`), which `build.go:1487` adds to every `BuilderNative` build Job. `cmd/native-resolve` calls `ResolveNativeBuildExact` (`nativeresolve.go:65`), which ends with `applyNativeCommonBase` (`nativeresolve.go:166`, `nativebases.go:113`). Every native web service, private service, worker, cron job and static-site build ends on the common image, whatever the primary: Node, Python, Ruby, Elixir, Go and Rust, plus their companions.
- **Phases.**
  - Build, pre-deploy and runtime run one image. The pre-deploy Job (`app_controller.go:2887` → `reconcilePreDeploy`, `app_controller.go:7361`) runs the image the build produced, so `sqlite3` and `libsqlite3` are there in all three.
  - A static site's image is only the publish Job's extract source (`native.go:211`), so the CLI exists at its build only. Render lists `sqlite3` as available at build and runtime, which a static site has no runtime to use.
- **The Python library.** `applyNativeCommonBase` removes and re-copies only `/usr/local` from the selected primary, then runs `ldconfig`. The CLI, `libsqlite3.so.0`, `libreadline8` and `zlib1g` are distribution packages under `/usr`, outside that copy. The official Python primary's `_sqlite3` module links the distribution `libsqlite3.so.0` (checked on `python:3.13-bookworm`), so the module and the CLI load one library: on production both reported SQLite 3.40.1 at build and runtime (t006). No `LD_LIBRARY_PATH` or other loader override exists and no SQLite environment variable is set, so an authored `PATH` keeps its meaning and nothing shadows the module.
- **Cache.** The base is digest-pinned. Tenant source and environment changes do not touch its layers, and a package change is a new digest that misses the cache. A database file the build writes into the source tree is part of the app's own layer, as on Render.
- **Exclusions.** Dockerfile, prebuilt-image and buildpack services never enter this recipe (builder selection, `app_controller.go`). A static site with no build command never builds a native image.
- **Neighbors kept.** FFmpeg, Pandoc, the PostgreSQL clients and the companion and package-manager steps are unchanged; m94 changes no product code.
- **Exercised versus source-only.**
  - Production (t006): build and runtime, Python 3.13, both CLIs.
  - Maintained cohort on `5d6b8139`/`4b809600`: the original program on the Python 3.13 primary at build and on a network-off runtime (`python313-original`), and the CLI-and-library check (Debian's Python 3.11) at the Node compute build, its network-off runtime and the static build. The new import, seed-failure and readonly checks and the omission control run from this milestone's commit on (t005).
  - Families runs on the same digests: the other primaries, companions, native-init and static.
  - Not executed: a hosted pre-deploy run (Free refuses `preDeployCommand`, Render's rule, `settings_check.go:67`) and ARM64 (D3).
