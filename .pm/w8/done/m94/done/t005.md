## Closed — 2026-11-16 (loopx session)

Maintained real-image checks, run by every `native-common-image.yml` utility cohort (`TestNativeUtilityGeneratedImages`) on the image it publishes:

- **Original seed and exports** (already maintained). `python313-original` runs the frozen m94 program on the Python 3.13 primary: `sqlite3 -bail` seeds the exact SQL at build, and three HTTP requests on a `--network none` runtime each export the three rows with `sqlite3 -readonly -json` and compare them with the Python library's read of the same file. The exact source, SQL, program, three rows and database identity pass through the frozen validators.
- **New, in `utility-check.py`** (runs at the `node-compute` build and network-off runtime and at the `node-static` build, beside the existing readonly CLI JSON and library comparison of Unicode, quote, comma and numeric values):
  - a CLI-only `.import --csv --skip 1` of a quoted, comma-bearing Unicode label and numeric values, read back identically by the CLI's JSON export and the Python library;
  - a `-bail` seed on stdin whose third statement breaks a primary key: it exits non-zero, names `UNIQUE constraint failed: seeded.id`, and leaves only the statements before it applied;
  - a write to a `-readonly` database is refused (`readonly database`) and leaves the file's bytes unchanged.
- **New, `missing-sqlite3` omission control.** A test-only layer removes only `/usr/bin/sqlite3`, checks that no other `sqlite3` is on `PATH` and that the distribution `libsqlite3` still answers SQL through Python, then runs the original m94 build on the Python 3.13 primary, which must fail with `sqlite3: command not found` after the layer's ready line. Omissions now name the primary their original case runs on, so this is the cohort's first Python-primary omission.
- **How this was checked before shipping.** The host is arm64 and the adopted image is amd64-only, so the generated-image gate cannot run here. On `python:3.13-bookworm` arm64 with the identical `sqlite3` 3.40.1-2+deb12u2:
  - the new block passed, and failed without the CLI (`FileNotFoundError`);
  - each new assertion failed under its mutation: the seed without `-bail` applied the later row, the write without `-readonly` succeeded, and the import without `--skip 1` imported the header;
  - the original m94 build and its three network-off runtime exports passed through `original-cases.py`;
  - after the exact omission layer (run by `dash`), the original build printed the ready line, then `sqlite3: command not found`, and its before-probe matched the historical failure (`valid_before`: library rows exact, CLI `ENOENT`).
  - The push of this change re-runs the amd64 utility cohort through `native-common-image.yml`, which publishes and qualifies a fresh image; that run is the amd64 proof.
- **Unit and package checks.** `go test ./internal/build/` (including `TestNativeOriginalReplayHTTPOracles` and the omission-evidence tests), `go vet`, `gofmt` and `golangci-lint` on the package.
- **Bounds.**
  - ARM64 is out of scope (D3).
