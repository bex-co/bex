The adopted common base (w8/m91 t007/t008) is the supplier. `deploy/native-base/install.sh` installs Debian's `sqlite3` with its normal closure. The SPDX attestation of the production image `sha256:5d6b8139…`, fetched again from the registry for this check, lists `sqlite3`, `libsqlite3-0` and `libsqlite3-dev` `3.40.1-2+deb12u2`, with `/usr/bin/sqlite3` and `/usr/lib/x86_64-linux-gnu/libsqlite3.so.0.8.6`; the re-pin `4b809600…` has the identical 864-package set. That is Debian 12's package, the base Render names for its native runtimes. The CLI links `libsqlite3.so.0`, `libreadline.so.8` and `libz.so.1`, all distribution packages under `/usr`, and `/usr/bin` is on the default `PATH` before source and authored commands at build, pre-deploy and runtime. The common image's `toolchain-freshness.json` entry and ADR060 D7 inventory it. A changed package is a new image digest, so a reviewed pin change, re-qualified by a families run.

- **The Python library is kept, not replaced.** The selected primary is copied into `/usr/local` only, and its `_sqlite3` module links the distribution `libsqlite3.so.0` (checked on `python:3.13-bookworm`), the library the CLI uses. On production both reported SQLite 3.40.1 at build and runtime (t006). Nothing wraps or substitutes the module.
- **Review of the finding's candidates.** The finding's working counterfactual was this same Debian package, and it is what the image carries. No self-contained distribution was adopted: the user's 2026-10-29 decision put every utility on the one Bookworm image as distribution packages. Render names Debian 12 as its base but no SQLite version, so the version is not asserted to match Render's.
- **Observable behavior.** At build, the frozen original command `sqlite3 -bail qa409.db < qa409.sql` seeds the exact SQL, and the program exports the three rows with `sqlite3 -readonly -json` and compares them with the Python library's read of the same file. At runtime it exports them again on three requests with the network off. Both run in the `python313-original` case of the maintained utility cohort, which passed on `5d6b8139` (families run 43883107194) and `4b809600` (families run 43900534897). Both native clients reproduced it on production (t006).
