# `POST /blueprints/generate` answers malformed JSON with a bare 500

Why: a client (or agent) that sends a broken body to blueprint-generate gets `{"error":"internal error"}` with no hint that its JSON is at fault, while every sibling route names the problem as a 400 — a wrong status class that sends debugging in the wrong direction and trips 5xx alerting for caller error.

Seen in the `/qa-find-bugs-cli` loop sweep 571, 2026-10-19, production, `bex-canary`:

- `POST /v1/blueprints/generate` with body ``, `{`, `"x"`, `[]`, or `{"serviceIds":"x"}` → each `500 {"error":"internal error","id":"internal_error"}`. (`null` decodes cleanly and correctly reaches the named `400 select at least one resource…`.)
- Controls on the same afternoon: `POST /v1/blueprints/preview` with an empty body → `400 bad request`; `POST /v1/blueprints/validate` with empty/`{`/`[]` → boundary `400 request body does not match the Render API schema`.

Root cause: the generate handler is the only `DecodeJSON` caller in `lego/backend/internal/apps/rest.go` that returns the decode error raw —

```go
// rest.go:1381 (POST /v1/blueprints/generate)
if err := core.DecodeJSON(r, &body); err != nil {
    return nil, err
}
```

Every sibling wraps it (`return nil, core.ErrBadRequest` — create/update blueprint at :1293/:1315, preview at :1403, deploy at :1366, notification overrides at :1531 with a named message). `core.DecodeJSON` (non-strict context) returns bare `encoding/json` errors, which `HandleJSON` maps to the generic 500. The route is bex-native (Render has no generate API), so no OpenAPI boundary catches the body first — which is exactly why validate, a gated Render op, 400s correctly while generate does not.

Fix (~10m): wrap the one return like its siblings — `return nil, core.ErrBadRequest` (or `fmt.Errorf("%w: invalid blueprint generate body", core.ErrBadRequest)` if a named body reads better) — and pin it with a handler test posting an empty and a malformed body expecting 400, next to the existing generate tests. No other handler in `rest.go` needs the change (audited all 12 `DecodeJSON` call sites 2026-10-19: :1428 deliberately ignores the error for an optional sync body; the rest wrap).

Acceptance:

- Empty, truncated, wrong-typed, and non-object JSON bodies to `POST /v1/blueprints/generate` → `400` in the standard error dialect; valid bodies (including `null` → the existing select-at-least-one 400, and real selections → 200) unchanged.
- The new test fails on the old code (500) and passes after.

Severity: minor (caller-error ergonomics + alert noise; no state touched — decode precedes any work). Estimate: ~15m.

**Done (2026-10-19, `f31004f7c`, live after pin `ca30db3a3646`):** live on production: `POST /blueprints/generate` with a malformed body and with a wrong-typed `serviceIds` → `400 invalid blueprint generate body`; with `{}` → `400 select at least one resource to generate a Blueprint from`. No bare 500 remains on the probed set.
