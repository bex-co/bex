## Objective

Materialize the one-way-derived public `evt-…` identity in a durable owner-scoped index so lookup across deploys, audit events, and typed service-event facts is direct and cannot leak foreign-workspace facts.

## Context

- `lego/backend/internal/store/events.go`
- `lego/backend/internal/events/service.go`
- `lego/backend/internal/id/id.go` derives event IDs with a one-way hash; lookup must not scan and hash an unbounded workspace history.

## Steps

1. Add the next numbered migration for a unique `(workspace,event_id)` source-key index and deterministic backfill of all three source families.
2. Keep the index current when a deploy transition, allowed audit event, or typed fact becomes publicly observable.
3. Add the owner-scoped store seam and reuse existing translators so list and get cannot disagree.
4. Normalize missing and unauthorized records to the same safe result.

- `lego/backend/internal/events/service.go`

## Acceptance criteria

- [ ] Every event returned by `ListServiceEvents` is retrievable by its unchanged ID.
- [ ] Lookup uses an indexed owner/event key and never scans an unbounded event feed.
- [ ] Backfill preserves IDs for existing deploy, audit, and fact rows.
- [ ] Cross-workspace lookup reveals neither existence nor details.
- [ ] No generic secret-bearing event payload is introduced.

## Out of scope

- HTTP, GraphQL, MCP adapters and new event types.
