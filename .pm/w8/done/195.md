# Pino/bunyan JSON logs (`"level":30`, `"level":50`) are labelled `unknown`, so no `bex logs --level` value ever returns them

Why: Node's two most common structured loggers, pino (Fastify's default, also NestJS via nestjs-pino) and bunyan, write the level as a number. bex's shipper only recognizes level names. Every such line lands in `unknown`, a bucket the pinned CLI cannot select, so `bex logs --level error` silently misses every error those apps log. ADR010 promises "`level` on app logs is parsed" from JSON.

Severity: minor (log filtering silently incomplete). Source: `/qa-find-bugs-cli` loop sweep 5e2a, 2026-10-23 UTC, bex v0.3.3, pin Render CLI v2.27.0 `a764810a7682`, `https://api.bex.co/v1/`, `bex-canary`, human device login.

## Evidence

Owned fixture `srv-dbddm07sf6rc738q75g0` (`qa-20261022-5e2a-logs`, free web, `docker.io/ealen/echo-server:0.9.2`, `PORT=80`; deleted by ID afterwards). echo-server logs every request as pino-style JSON (`{"name":"echo-server",…,"level":30,…}`).

```text
$ bex logs -r srv-dbddm07sf6rc738q75g0 --type app --limit 50 -o json        → 50 entries; label level="unknown", message .level=30 for all 50
$ bex logs -r srv-dbddm07sf6rc738q75g0 --type app --level info --limit 50 -o json                  → 0 entries
$ bex logs -r srv-dbddm07sf6rc738q75g0 --type app --level debug,info,warning,error --limit 50 -o json → 0 entries
$ bex logs -r srv-dbddm07sf6rc738q75g0 --type app --level unknown -o json
Error: invalid argument "unknown" for "--level" flag: must be one of "debug", "info", "notice", "warning", "error", "cri…
```

Controls in the same sweep: request-log filters `--status-code 404`, `--status-code 500,503`, `--method PUT`, `--path /st-5e2a`, `--path /st-*`, `--host …` and combinations all returned exactly the planted entries.

## Root cause

`deploy/gitops/base/log-shipper.yaml:312-342` (`loki.process "app_logs"`): `stage.json` extracts `level`/`severity`, and the normalizing `stage.template` maps only the strings `error|err|fatal|panic|critical|crit|alert|emergency`, `warn|warning`, `info|notice`, `debug|trace`. The number `30` falls to `unknown`. The comment "bunyan via "level", pino numeric aside" is wrong about bunyan, which is numeric too.

## Fix

Extend the template with the pino/bunyan numeric scale (identical in both libraries): `10`/`20` → `debug` (trace, debug), `30` → `info`, `40` → `warning`, `50`/`60` → `error` (error, fatal). Match the exact numeric strings, so the label still has five values and the cardinality budget holds. Add cases to `scripts/test_log_shipper.py` (numeric 10…60, `"level":"30"` as a string, an out-of-range `35` → `unknown`). Update ADR010 § level parsing. Lines already stored stay `unknown` until retention expires (no backfill).

## Blast radius

Every App log stream in every workspace (one shared pipeline). Request, build and datastore pipelines are untouched. Dashboard and MCP level filters read the same label and benefit. Render's own handling of numeric levels is not documented and not captured (no Render account). The target is bex's ADR010 contract, not a Render measurement.
