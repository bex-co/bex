## Objective

Before `cmd.Execute()`, mutate the exported upstream `cmd.RootCmd` so the help surface presents as `bex` — command path, examples, version chrome, and the ungrouped-commands help header — without copying any upstream command implementation.

## Context

- Upstream `cmd/root.go`: `Use: "render"`, Short/Long Render-branded, examples use `render …`.
- Help: `cmd/helptemplate.go` `cliVersion()` prints `Render CLI v` + `cfg.Version`; `CustomHelpTemplate` special-cases `CommandPath == "render"` for the "Additional Commands" group (where `docs`, `skills`, and Bex-native `code`/`upgrade` land).
- Bex already attaches native commands to `cmd.RootCmd` in `lego/cli/main.go` and intercepts `-v`.
- `cobra.AddTemplateFunc("cliVersion", …)` registered later wins over upstream's `init`.
- DO_NOT_DO: do not fork/vendor `render-oss/cli`.

## Steps

1. Add a small branding package or function in `lego/cli/` (e.g. `internal/branding`) called from `main` after `bridge.Apply()` and after Bex-native commands are registered, before version intercept / `cmd.Execute()`.
2. Set `cmd.RootCmd.Use = "bex"`.
3. Walk the cobra tree; rewrite example lines with word-boundary `render ` → `bex ` (and backtick forms `` `render `` → `` `bex `` where present in Example fields). Do not touch Short/Long in this task.
4. Re-register `cliVersion` to print a Bex label (use `main.bexVersion` / injected release identity for the product line; may still mention upstream compatibility sparingly if needed for help DETAILS — prefer not leading with "Render CLI").
5. `SetHelpTemplate` from `cmd.CustomHelpTemplate` with the `CommandPath == "render"` check changed to `"bex"` so ungrouped commands keep their section.
6. Record in code comments that every pin bump must re-diff these seams (`UPSTREAM_RENDER_CLI.md` updated in t004).
