# Internal Key Value connections require a password, so Render's own webdis guide (`REDIS_HOST`/`REDIS_PORT`) gets `NOAUTH` on every command; Render leaves internal connections unauthenticated by default

Why: Render's Key Value docs say: "Connections using the internal URL are unauthenticated by default … This is why the default internal connection URL doesn't include a username or password". The default internal URL is `redis://red-abc123:6379`; internal authentication is an opt-in ("Enable Internal Authentication"), and external connections always require it. bex mints a password into every store and every internal URL. ADR018's Key Value row calls this a "conscious divergence … a safe superset", but it is not a superset. A client configured the way Render documents (host and port, no password) fails with `NOAUTH`. The row records no user sign-off, which the parity rule requires (AGENTS.md: "A divergence stands only when ADR018 records it with the user's sign-off").

Severity: **major** (an official Render deploy guide and the Dify template's `fromService … property: host/port` wiring cannot talk to their store). Attribution: platform runtime (operator Valkey auth) plus the API's internal URL. Estimate: **> 1h, needs a design choice** (see Fix). Promote to a milestone once the option is approved. Source: `/qa-find-bugs-cli` loop sweep 9098, 2026-10-26 (10:04–10:12 UTC). Context: HEAD-built bex `b4726243e` with pinned Render CLI v2.27.0 `a764810a7682`; `https://api.bex.co/v1/`; workspace `bex-canary`; human device login.

The bare ID resolved and the TCP connection reached Valkey, so only authentication fails. Both fixtures were deleted by ID (service then store), and `GET` returns 404 for each.

Corpus: of the 87 current `render-examples` Blueprints, Key Value `fromService` wiring is mostly `property: connectionString` (12 uses, which work because the URL carries the password). `dify-render-template` wires `property: host` + `port` (4 uses), which fails the same way. Apps that read `REDIS_HOST`/`REDIS_PORT` (webdis, many Celery/Sidekiq/RQ setups) are the affected class.

## Root cause

- `valkeyArgs` (`lego/operator/internal/controller/keyvalue_controller.go:232`) starts every store with `--user default on >$(VALKEY_PASSWORD) …` (`valkeyDefaultUserRule`, `:265`), so every listener (internal plain and external TLS) requires AUTH.
- The connection Secret's `uri` is `redis://default:<password>@<internal host>:6379` (`:312`), surfaced as `internalConnectionString` (`lego/backend/internal/keyvalue/service.go:155`).
- ADR018 row "Key Value" ("Divergences (conscious): the internal URL always mints a password … a safe superset") and ADR021's internal-URL table describe this as intended, without sign-off.

## Fix (needs the design choice below)

Target behavior, matching Render:

- New and existing stores accept **unauthenticated** connections from the workspace's private network on the internal address (`<id>:6379`, and the `.svc` FQDN).
- A client that sends `AUTH default <password>` keeps working, so existing apps and the current `connectionString` values don't break.
- External (`rediss://…kv.bex.co`) connections still require the password.
- The REST/GraphQL/MCP `internalConnectionString` becomes `redis://<id>:6379` (no credentials), as on Render. The dashboard copy follows.
- Cross-workspace isolation is unchanged (ADR043 NetworkPolicy/Cilium). Render's private network is per-workspace too.

Valkey cannot require AUTH on one listener but not another, and the external path is TLS passthrough (`bex-kv-sni-proxy`) into Valkey's own TLS port. Options:

1. **Recommended: an auth-injecting internal front.** The internal `<id>` Service targets a small in-pod sidecar on 6379. It opens each upstream connection to Valkey (moved to a loopback/plain port) already authenticated as `default`, and passes a client's own `AUTH` through (a correct password is a no-op; a wrong one is refused, as Render does once internal auth is on). Valkey keeps `requirepass`, so the external TLS path is untouched.
2. **`default` user `nopass` plus a TLS-terminating, AUTH-enforcing front on the external path.** This rewrites the metered SNI proxy's passthrough model (ADR021 "External URL" row), so it is larger and riskier.
3. **Opt-out only:** add Render's "require internal auth" toggle as the existing behavior and make it off by default via option 1. The toggle is the same work as 1 plus an API/UI field; it can be a follow-up.

## Blast radius

- Every Key Value store in every workspace.
- `fromService` Key Value `host`/`port`/`connectionString` resolution (Blueprint compiler).

- ADR018 row and ADR021 internal-URL table.
