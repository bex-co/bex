# A Blueprint `worker`/`pserv` on `plan: free` is told to use `pro_plus|pro_max`, which a Blueprint cannot spell

Why: following the error's advice should produce a valid file. A Blueprint author who writes `plan: pro_plus` as told gets a second, schema-level error, because a Blueprint spells it `pro plus`. w6/093 fixed this for cron jobs; its own fix description also covered "the service enum", but that part was never changed.

**Severity:** minor (misleading copy, exit status correct). **Attribution:** server (Blueprint validation). **Estimate:** ~30m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `4844`, 2026-11-08. Incomplete fix of w6/093.

## Evidence

Checkout build `bex vqa-460c283a6`, Render CLI v2.35.0 `24ac2d60fdb2`, `https://api.bex.co/v1/`, workspace `bex-canary`, non-TTY. Production pin `19dfc2982`.

```text
$ cat worker.yaml
services:
  - type: worker
    name: qa-worker
    runtime: image
    image:
      url: docker.io/library/busybox:1.37
    plan: free
$ bex blueprints validate worker.yaml -o json     → exit 1
  services[0].plan (line 7, col 11): service "qa-worker": a background_worker requires a paid plan; plan must be one of starter|standard|pro|pro_plus|pro_max
(pserv: the same text with "a private_service")

# following the advice
plan: pro_plus  → valid=false: at '/services/0/plan': value must be one of 'free', 'starter', 'standard', 'pro', 'pro plus', 'pro max', 'pro ultra', …
plan: pro_max   → valid=false (same schema error)
plan: "pro plus" → valid=true
plan: "pro max"  → valid=true

# control: cron (fixed by w6/093)
services[0].plan: a cron_job requires a paid plan; plan must be one of starter|standard|pro|pro plus
```

Secondary, same run: a file with a free `cron`, a free `worker` and a free `pserv` reported **only** the cron error. Each of the other two is refused when validated alone. The cron rule runs in the compiler stage (`blueprint_compiler.go:1446`), and a compiler problem stops the per-service checks (`deploy.go:1575-1586`, which aggregate across services). So a user fixes one plan, re-validates, and then meets the next one.

## Root cause

`lego/backend/internal/apps/deploy.go:1698-1701` `validateBlueprintService` → `blueprintReadSpec` → `resolveTierForType` (`service.go:3760-3769`) → `errFreePlanForType` → `freePlanForTypeMessage` (`service.go:3821-3822`). That joins `paidRenderPlans()`, the API's underscore ladder. w6/093 added `blueprintCronFreePlanMessage` (`blueprint_compiler.go:1413-1419`) for cron only.

## Fix

In Blueprint context, word the paid-only refusal for `worker`/`pserv` from the pinned schema's `serverPlan` enum without `free` and the size ids (`starter|standard|pro|pro plus|pro max`, plus `pro ultra` only while it is selectable; it is paused per ADR018, w2/m250). Keep the API message unchanged. Then either move the worker/pserv free-plan rule into the compiler stage beside cron, or let compiler-stage plan problems fall through to the aggregate, so every free paid-only service in a file is reported in one run.

## Acceptance

- Each value listed in the worker/pserv Blueprint message validates when written back into the file (test, as w6/093 added for cron).
- The three-service file above reports all three plan errors in one response, each at its own `services[N].plan` location.
- REST/GraphQL/MCP Blueprint validate share the change. `bex services create --type background_worker --plan free` keeps the API spelling.

## Dedupe

w6/093 (done 2026-10-21, cron only), w8/048 (done: paid-only types refuse free; its evidence quotes this exact worker/pserv text). No open item.

## Done — 2026-11-10

- **Blueprint spelling.** A free worker or private service is refused in the service stage, as before, but a Blueprint now words it in its own spelling: `a background_worker requires a paid plan; plan must be one of starter|standard|pro|pro plus|pro max`. That is the selectable paid ladder as `serverPlan` writes it, from `blueprintFreePlanMessage`. The refusal is a typed `freePlanForTypeError` that `validateBlueprintService` rewords, and the create API keeps `pro_plus`.
- **Every service in one run.** A free cron moved from the schema stage to the same service stage, keeping its cronPlan hint (`starter|standard|pro|pro plus`). A file with a free cron, worker and pserv therefore reports all three at their own `services[N].plan`, in one response that still aggregates with parse-stage errors.
- **Test.** `TestBlueprintPaidOnlyTypesRefuseFreeInBlueprintSpelling` checks each type's refusal and path, that no hinted plan carries an underscore, that every hinted plan validates when written back, and that the three-service file reports three errors. REST, GraphQL and MCP validate share `ValidateBlueprint`.
