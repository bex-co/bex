## Objective

Decide and implement how a namespace-migration delete avoids running the KeyValue purge finalizer against a prefix a recreated instance still owns — the defect that destroyed every pre-cutover recovery point on 2026-08-21/22.

## Context

- The purge Job runs `aws s3 rm --recursive` on `keyvalue/<id>/` (`lego/operator/internal/controller/keyvalue_backup.go`, purge builder). The id — and therefore the prefix — is preserved across a cutover, so deleting the old CR wipes the new instance's backups too.
- Candidate shapes: (a) an operator-recognized annotation on the old CR (e.g. skip-purge for migration deletes) that suppresses the purge Job; (b) a hard runbook gate in `docs/runbooks/datastore-namespace-cutover.md` (verify prefix custody before delete); (c) the ADR050 follow-up — Object Lock/WORM on backup prefixes so even a purge cannot destroy retained objects. (a)+(b) are in scope here; (c) stays an ADR050 follow-up pointer unless trivially adjacent.
- Whatever is chosen must not weaken the normal delete path: a real tenant delete must still purge (privacy commitment in ADR021/ADR031 drill records).

## Steps

1. Pick the mechanism (annotation guard is the likely minimal shape) and record the decision in the runbook.
2. Implement + unit-test the guard in the operator (skip-purge path leaves the prefix; normal delete still purges).
3. Update `docs/runbooks/datastore-namespace-cutover.md` with the mandatory pre-delete step.

- [ ] A normal delete still purges (existing behavior covered by test)
