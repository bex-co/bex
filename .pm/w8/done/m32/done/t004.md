## Objective

Close the sibling entrypoint: the service Settings → "Update Source" card must not let an existing `static_site` be switched to an "Existing Image" (Docker) source, mirroring the create-wizard fix in t001.

## Context

- `dashboard/src/features/services/components/service-source-card.tsx:202-209` passes `image` to `ServiceSourcePicker` unconditionally — the same gap as the create wizard, on the edit surface.
- This was found by code citation this hunt, not exercised live (the QA workspace had no static site to edit), so this task must verify the behavior live in dev-8.

## Steps

1. In `service-source-card.tsx`, omit the `image` prop when the service being edited is a `static_site` (use the service's type from its loaded data), mirroring t001.
2. Verify the card degrades to the two-tab (GitHub / Public Git URL) layout for a static site and is unchanged for the four image-valid types.
3. Verify live in dev-8: open an existing static site's Settings → Update Source and confirm no "Existing Image" option; confirm a web service still shows it.

## Files

- `dashboard/src/features/services/components/service-source-card.tsx`

## Acceptance criteria

- [x] Editing a `static_site`'s source offers only GitHub + Public Git URL — no "Existing Image".
- [x] Editing a web/private/worker/cron service's source still offers "Existing Image".
- [ ] Live-verified in dev-8 on an actual static site (record the click path). _Deferred to t008's live pass alongside the other DoD probes._

## Out of scope

- Create-wizard gating (t001) and backend/CRD validation (t003).

## Outcome (2026-09-06)

The citation was real but the card is unreachable for a static site: the shared
settings page mounts `ServiceSourceCard` only when `!staticSite`
(`dashboard/src/routes/services.$serviceId.settings.tsx` — static sites edit
their source through the Git-only `LegacySourceFields` in
`BuildDeploySection`). No UI change was needed; the mount-site gate already
expresses the rule where the service type is known. The reachable sibling gap
was the **API** behind this card — GraphQL `setImage`, REST PATCH `image`, MCP
update — which happily repointed a static site at an image. That is now
refused in the shared source verb (`resolveSourcePatch`,
`lego/backend/internal/apps/service.go`), pinned by
`TestGraphQLSetImageRejectedForStaticSite`.
