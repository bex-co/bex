## Objective

Make the create-service submit gate and payload builder refuse the `static_site` + image combination in depth, so that even if a `static_site` form somehow carries an image source (deep-link, stale state, future regression of t001), Deploy stays disabled and no `runtime:"image"` + `publishPath` payload is emitted.

## Context

- `dashboard/src/features/services/lib/create-service-input.ts`:
  - `:114` — `isSubmittable` accepts `(shape.isImageSource && form.image.trim().length > 0)` with no service-type check.
  - `:130` — static bypasses the plan requirement (`shape.isStaticType || form.plan !== ""`).
  - `buildCreateServiceInput` `:149-157` sets `source = { image }`; `:168` sets `runtime:"image"`; `:192` still attaches `publishPath` because `shape.isStaticType`.
  - `buildShape` `:67-90` computes `isStaticType`/`isImageSource` independently — no conflict guard.

## Steps

1. In `buildShape` (or a derived predicate), treat `static_site` + image as invalid; expose it so `isSubmittable` returns false for that combination.
2. In `isSubmittable`, require a Git source (github/git) when `isStaticType`; never accept an image source for a static site.
3. In `buildCreateServiceInput`, guard so a static site never serializes `runtime:"image"` or an `{ image }` source; keep `publishPath` only on the Git-repo static path.
4. Keep behavior identical for the four image-valid types.

## Acceptance criteria

- [x] A unit test: `isSubmittable` is false for `{ serviceType: "static_site", tab: "image", image: "nginx" }` even with a name set.
- [x] A unit test: `buildCreateServiceInput` for a static site never returns `runtime:"image"` or a `source.image`.
- [x] Web/private/worker/cron with an image source still submit and still serialize `runtime:"image"`.
