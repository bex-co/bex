# A Node release with no image in its line's Debian variant (Node 16.13, 18.0–18.15 on bookworm) keeps the line's patch; copy the release's Node onto the line's image instead

Why: since w8/175, w8/307 and w8/308, an exact Node version or range builds on the release's official image of the line's Debian variant: `node:<release>-bookworm` for Node 16, 18 and 20. Docker Hub has bookworm images only for Node 16.20.x and 18.16+. So `NODE_VERSION=16.13.2`, `~16.13.0` (`render-examples/strapiconf2022-workshop-strapi`) or `18.10.0` keeps the line's patch, and the build log says so. Render installs those releases.

**Severity:** minor (the substitution is logged). **Attribution:** platform build (native version selection). **Estimate:** ~3h. **Source:** the /simplify review of w8/308, 2026-11-13.

## Design

The `node` binary in every official image is the same nodejs.org build, on a glibc 2.17/2.28 baseline, and `node_modules` is plain JavaScript. So:

- **Keep the line's bookworm image as the base.** Copy `/usr/local/bin/node` and `/usr/local/lib/node_modules` from the release's official image in whatever Debian variant has it (`node:16.13.2-bullseye`), with the npm/npx links. Companions already work this way (`nativeJSToolLines`). The base OS stays Debian 12, current with Render; Debian 11 LTS ended on 2026-08-31.
- **pnpm by release, not by major.** `nativeLegacyPnpmLine` keys on the major (14/16), but pnpm 10 needs Node 18.12 or newer. Key it on the pinned release, and give Node 18.0–18.11 the legacy pnpm.
- **node-gyp patch.** `prepare-node14-tools.py` patches npm's `find-python.js` by anchor text. Verify it against the npm that early 16.x and 18.x releases bundle, or skip it with a log line when the anchor is absent, rather than failing the build.
- **Python and Ruby** releases older than their line's variant likely have the same gap. Check them, and give them the same treatment if so.

## Regression checks

- **Unit:** `16.13.2` and `~16.13.0` build on the bookworm line image with node copied from `node:16.13.2-bullseye`, and the log names it. `18.10.0` with pnpm gets the legacy pnpm. An absent node-gyp anchor logs instead of failing.
- **Production:** the strapi template's API logs `Using Node 16.13.2` and goes live.

## Dedupe

- w8/308 (done) withdrew the bullseye-base fallback for these reasons.
- w8/175 and w8/307 (done) cover images of the line's variant.

## Resolution

**DONE 2026-11-13, for Node.** A release whose bookworm image does not exist, asked for exactly or through a range, keeps the line's bookworm image and takes its Node from the release's official older-variant image.

- **The lookup:** `olderNodeDonor` (`lego/operator/internal/build/nativeresolve.go`) tries `-bullseye`, then `-buster`, and `pinRangeRelease` looks for a range's release in those variants too.
- **The copy:** `rewriteNativePrimaryBase` copies `/usr/local/bin/node`, `/usr/local/lib/node_modules` and `/usr/local/include/node` with the npm links, relinks Corepack only where the release ships it (16.9+), and sets `ENV NODE_VERSION`. The copy is inserted ahead of the legacy node-gyp patch so the patch edits the release's own npm. A companion copies from the same donor. The log names it: `node:16.13.2-bookworm does not exist; copying Node 16.13.2 from node:16.13.2-bullseye onto the Node 16 image`.
- **pnpm:** it follows the release (`nativeLegacyPnpmRelease`), so Node 18 before 18.12 gets the legacy standalone.
- **Python patch:** it stays keyed by the 14/16 lines.
- **Evidence:**
  - **node-gyp anchors:** the patch's anchors and markers match node-gyp 5.1.0, 7.1.2, 8.2.0, 8.4.1, 9.0.0 and 9.1.0, the releases the old npm versions bundle.
  - **Real image:** the opt-in test `TestOlderNodeReleaseRunsOnTheLineImage` resolved `NODE_VERSION=16.13.2` against Docker Hub. Built with BuildKit, the image ran `node=v16.13.2 npm=8.1.2 npx=8.1.2 pnpm=10.34.7 corepack=0.10.0`, with `NODE_VERSION=16.13.2` in its env.
  - **Unit, buster:** `TestNodeReleaseFallsBackToBuster` covers a buster-only release (16.8.0, which has no Corepack).
- **Common base:** with a common base configured, no donor is offered, since that path reads the runtime from the selected image.
  - **Unit tests:** `TestNodeReleaseOlderThanBookwormIsCopiedOntoTheLine` (exact and range; the copy precedes the patch), `TestNodeReleaseBefore1812GetsTheLegacyPnpm` and `TestNodeCompanionCopiesAnOlderVariantRelease`. Each fails with its change removed.
- **Docs:** ADR060 D7 records it.
- **Not done:** Python and Ruby releases older than their line's variant were not checked; that is left for a sweep to find.
- **Production check after the next roll:** re-import `strapiconf2022-workshop-strapi`; the API's build log reads `Using Node 16.13.2` and names the copy, and the service goes live.
