# Restart/Rollback refusals name the internal App name instead of the service the caller asked for

Why: a user who restarts a suspended service gets `service "tea-<workspace>-<slug>" is suspended` — the internal App CR name, an identifier no API surface ever issued to them — while the same refusal via deploy correctly names the `srv-…` ID they sent. Internal tenant-prefixed names must not leak into public error text, and the two verbs must refuse identically.

Seen in the `/qa-find-bugs-cli` loop sweep 503, 2026-10-19, production `https://api.bex.co/v1/`, workspace `bex-canary`, human device-login QA identity, HEAD-build `bex` (`97a170c1b`, Render pin v2.27.0) and raw REST with the same credential:

- `bex deploys create srv-… --confirm` on a suspended owned fixture → exit 1, `409: conflict: service "srv-dbatn7vbcrps73dmoa80" is suspended` (correct).
- `bex restart srv-… --confirm` on the same fixture → exit 1, `409: conflict: service "tea-daif693dqjvc73e7as3g-qa-20261019-5b6da0-susp503" is suspended` (internal name).
- Raw `POST /v1/services/srv-…/restart` returns the same internal-name body, so the substitution is server-side, not CLI rendering.

Root cause: both refusals come from `validateTrigger(service, …)` at `lego/backend/internal/deploys/service.go:626-631`, which formats the `service` label its caller passes. The deploy path threads the caller's selector (`triggerFetched`, `service.go:732`). The selected-release path at `lego/backend/internal/deploys/rollback_config.go:152` calls `s.validateTrigger(a.Name, a, …)` — `a.Name` is the tenant-prefixed CR name. Two sibling sites in the same file format `a.Name` into user-visible conflicts directly: `rollback_config.go:163` ("changed its running release during the restart") and `:243` ("is serving %s but …").

Blast radius: `restartSelectedRelease`/`openSelectedRelease` are shared by Restart and Rollback, and `deploys.Service.Restart` is reached from REST (`apps.Service.Restart` → `RestartDeploy`, `lego/backend/internal/api/server.go:899-902`), GraphQL `restartServer` (`deploys/graphql.go:242`), and MCP — so every surface's Restart/Rollback refusals that pass through these three sites carry the internal name. Every `validateTrigger` refusal is affected when reached this way (suspended; not-store-managed), not only the suspended one observed. (`deployhook.go:248,255` also format `a.Name`, but into backfill-index errors; whether those reach a user response is unverified — check while fixing, don't assume.)

Fix: thread the caller's `service` selector into `restartSelectedRelease` (and the `openSelectedRelease` closure errors at 163/243 — they receive only `*App` today, so pass the selector or the public service ID alongside) and format that, exactly as the deploy path does. Do not invent a new label format.

Acceptance:

- On a suspended owned free web service: `bex restart <srv-id> --confirm` and `POST /v1/services/<srv-id>/restart` refuse `409` naming the `srv-…` ID (or the name selector the caller sent), never `tea-…`. Same for a Rollback refusal reached through `openSelectedRelease`.
- `bex deploys create <srv-id> --confirm` refusal text is unchanged.
- A test in `lego/backend/internal/deploys` drives Restart on a suspended app by public ID and asserts the error names that ID and contains no tenant-prefixed CR name; it fails before the fix.
- REST/GraphQL/MCP restart refusals agree (same shared verb).

Severity: minor (correct status/semantics; misleading internal identifier in error text, caller's own workspace only). Estimate: ~30m.

**Done (2026-10-19, `8e57d4eaa`):** the snapshot Restart path validates with, and formats, the caller's `service` selector instead of `a.Name`. `restartSelectedRelease`, `servingDeploy` and `restartSelection` take it. That covers:

- the suspended and not-store-managed refusals;
- the serving-release-not-established conflicts;
- the in-lock "changed its running release" conflict;
- the restart's deploy-started email.

The review sweep found two more `a.Name` leaks and fixed them with `core.AppPublicName(a)`: `rollout.PatchAppLocked`'s "too many concurrent updates" conflict (reached by Restart and Rollback), and the git-push redeploy's started email. `deployhook.go`'s two `a.Name` errors come only from the startup backfill (`cmd/api/main.go:468`) and never reach a response.

- `TestRestartStartedNotificationNamesTheCallersService`.

Live on production after deploy, 2026-10-19, against a suspended owned Free web service (`srv-dbav017mnaes738pfoj0`, deleted by ID, 404):

- **CLI:** `bex restart <srv-id> --confirm` → `409: conflict: service "srv-dbav017mnaes738pfoj0" is suspended`.
- **REST:** `POST /v1/services/<srv-id>/restart` → `409 {"error":"conflict: service \"srv-dbav017mnaes738pfoj0\" is suspended",…}`.
- **GraphQL and MCP:** `restartServer` and `restart_service` return the same text.
- **Control:** `bex deploys create <srv-id>` is unchanged and names the same ID.

No surface names a `tea-…` App name. The live harness's REST check misread the JSON-escaped quotes, so it reported a false FAIL, but the recorded body above shows the correct text.
