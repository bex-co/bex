# An unknown or deleted service's `*.onbex.co` host answers a bex-styled negotiated 404 page and skips the HTTPS redirect, where Render answers a plain-text `404 Not Found` after redirecting to HTTPS

Why: a platform host that no service owns gets a different answer on bex than on Render. That covers a typo, a deleted service (w4/516 routes those here) and a private service's would-be host.

- **bex:** the response depends on `Accept`:
  - browsers get a dark HTML page reading "There is no service at this address.";
  - JSON clients get `{"error":"not found"}`;
  - everyone else gets that sentence as text.

  bex sends `cache-control: no-store` and no `x-content-type-options`, and answers over plain HTTP without upgrading.
- **Render:** every client gets the same `text/plain` `Not Found`, with `x-content-type-options: nosniff` and `x-render-routing: no-server`, after a 301 to HTTPS.

Uptime monitors and scripts that check a removed service's body or scheme see different answers. w4/m235 t008 introduced the page as "a bex-branded 404" instead of Traefik's raw text; it never compared it with Render.

**Severity:** minor. **Attribution:** server (activator) plus platform manifest (fallback Ingress). **Estimate:** ~30m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `83e1`, 2026-11-13 23:55 UTC, production pin `ac206b76841b`.

## Render's behavior (captured 2026-11-13 23:52 UTC)

`qa-nohost-bc16x.onrender.com` is a nonexistent Render host. Each response carries Render's `rndr-id`:

```
GET http://qa-nohost-bc16x.onrender.com/a?b=1
  → HTTP/1.1 301 Moved Permanently
    Location: https://qa-nohost-bc16x.onrender.com/a?b=1
GET https://qa-nohost-bc16x.onrender.com/  (Accept: text/html,… | application/json | none)
  → HTTP/2 404
    content-type: text/plain; charset=utf-8
    content-length: 10
    x-content-type-options: nosniff
    x-render-routing: no-server

    Not Found
```

The body and headers are identical for all three `Accept` values.

## bex (no fixture needed)

`qa-nohost-x.onbex.co` is a nonexistent bex host:

```
GET http://qa-nohost-x.onbex.co/a?b=1
  → HTTP/1.1 404 Not Found   (no redirect)
    Content-Type: text/plain; charset=utf-8
    X-Render-Routing: no-server

    There is no service at this address.
GET https://qa-nohost-x.onbex.co/   Accept: text/html,…
  → 404  cache-control: no-store
         content-type: text/html; charset=utf-8
         x-render-routing: no-server
         content-length: 581
         <!DOCTYPE html>… <title>Not found</title> … <h1>There is no service at this address.</h1><p>Check the URL for a typo.</p>
GET https://qa-nohost-x.onbex.co/   Accept: application/json
  → 404  content-type: application/json  {"error":"not found"}
```

A served host does redirect: `http://hello-go.onbex.co/a?b=1` → `301 https://hello-go.onbex.co/a?b=1`, through the App's own middleware, w8/m118.

## Root cause

- **Body:** `newHoldingHandler` (`lego/operator/cmd/activator/main.go:166-179`) answers a host no public App owns with `writeUnknownHostResponse` (`:411`). That function calls `writeNegotiated` (`:390-400`), which:
  - sets `Cache-Control: no-store`;
  - picks `unknownHostPage` (`:912`), `unknownHostJSON` or `unknownHostText` (`:416-417`) by `Accept`;
  - never sets `X-Content-Type-Options`.
- **Scheme:** the `platform-host-fallback` Ingress (`lego/operator/config/activator/platform-host-fallback-ingress.yaml`, router priority 1) attaches no middleware. Every App Ingress leads with its own HTTPS-redirect middleware (`app_controller.go:4342-4362`), but an unclaimed host is served on `:80` as is.
  - The same gap applies to a just-created service's first-deploy answer during the seconds before its own route exists.

## Fix (target behavior)

- `writeUnknownHostResponse` answers every `Accept` with Render's response:
  - `404`, `Content-Type: text/plain; charset=utf-8`;
  - `X-Content-Type-Options: nosniff` and `X-Render-Routing: no-server`, which is kept;
  - body `Not Found\n`, with no HTML page and no JSON variant.
- Delete `unknownHostPage` and `unknownHostJSON`, which become unused, so `make lint`'s dead-code pass stays green.
- Leave the first-deploy, suspended and maintenance answers unchanged; they are separate captures.
- Give the fallback Ingress an HTTPS redirect, matching the App routes. A `bex-system` `Middleware` (`redirectScheme: https`, permanent) referenced through `traefik.ingress.kubernetes.io/router.middlewares`, honoring the same `BEX_HTTPS_REDIRECT` switch if practical. Then `http://<unknown>.onbex.co/a?b=1` → `301 https://<unknown>.onbex.co/a?b=1`.
- Record the unknown-host answer in ADR018 (routing rows) with the captures above, and amend the w4/m235 t008 wording in ADR004 if it names the branded page.

## Blast radius

- **One caller:** `writeUnknownHostResponse` is called only at `main.go:177`.
- **Hosts that see the new answer:**
  - unknown hosts;
  - deleting or deleted Apps (w4/516);
  - non-public Apps' platform hosts.
- **Tests:** `main_test.go:968`, `:1292` and `:1304` assert `unknownHostText` or the sentence, and need the new body.
- **Manifest:** the fallback Ingress change is platform-wide, at the lowest router priority. App routes keep their own redirect, so served hosts are unchanged.

## Acceptance

- Activator tests: an unknown host with `Accept: text/html`, `application/json` and none → `404`, `text/plain; charset=utf-8`, `nosniff`, `x-render-routing: no-server`, body `Not Found\n`.
- After the roll:
  - `curl -s -D - https://qa-nohost-x.onbex.co/`, with and without a browser `Accept`, matches Render's capture;
  - `curl -s -D - 'http://qa-nohost-x.onbex.co/a?b=1'` → `301 Location: https://qa-nohost-x.onbex.co/a?b=1`;
  - `http://hello-go.onbex.co/` still 301s.

**DONE 2026-11-13.**

- **Body:** `writeUnknownHostResponse` (`lego/operator/cmd/activator/main.go`) now answers every `Accept` with Render's capture: `404`, `Content-Type: text/plain; charset=utf-8`, `Content-Length: 10`, `X-Content-Type-Options: nosniff`, the existing `X-Render-Routing: no-server`, and the body `Not Found\n`, with no cache directive. HEAD gets the same headers and no body. `unknownHostPage` and `unknownHostJSON` are deleted. The first-deploy, suspended and maintenance answers are unchanged.
- **Scheme:** a new `Middleware` (`lego/operator/config/activator/platform-host-fallback-https.yaml`) carries `httpsRedirectSpec`'s `redirectScheme: https`, permanent. It syncs at wave -1, because Traefik disables a router whose middleware is missing. The `platform-host-fallback` Ingress names it as `bex-system-bex-platform-host-fallback-https@kubernetescrd`, since `config/default`'s `namePrefix` does not reach annotation values. The prod and default renders were checked with kustomize v5.8.1. As a static manifest, the route is not governed by `BEX_HTTPS_REDIRECT`; this is noted in `lego/operator/AGENTS.md` and ADR005. cert-manager's HTTP-01 solvers keep their own longer-rule routes, so the redirect never reaches them.
- **Tests:**
  - `TestAnUnknownHostAnswersRendersPlainNotFound`: three `Accept` values × GET and HEAD.
  - `TestPlatformHostFallbackRouteIsTheLowestPriorityCatchAll` now derives the expected Middleware reference from `config/default/kustomization.yaml` through `traefikMiddlewareRef`, and checks that the spec equals `httpsRedirectSpec` at sync wave -1. It fails on an unprefixed reference.
  - The full operator suite passes.
- **Docs:** ADR007 § Platform routing tag, ADR018 (Unknown platform hosts), ADR093, ADR005 and `lego/operator/AGENTS.md`.
- **Not done here:** the static-server still answers a host its resolver has dropped with `404 no static site for host`, for example in the seconds after a static site is deleted (the w4/636 window). That is outside this item's scope.
- **Production check after the operator and activator roll:**
  - `curl -s -D - https://qa-nohost-x.onbex.co/`, with a browser `Accept`, with `application/json` and with none, should give `404 text/plain` `Not Found` with `nosniff` and `x-render-routing: no-server`.
  - `curl -s -D - 'http://qa-nohost-x.onbex.co/a?b=1'` should give `301 Location: https://qa-nohost-x.onbex.co/a?b=1`.
  - `http://hello-go.onbex.co/` should still 301.
