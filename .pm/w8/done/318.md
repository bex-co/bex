# A static site answers `/docs/about` with a 301 to `/docs/about/` when it publishes `docs/about/index.html`, where Render serves the page in place with 200

Why: w4/384 fixed `/blog` serving the homepage by redirecting it to `/blog/`. It chose the 301 as "bex's directory semantics" and listed "Render's actual response for `/blog` when `blog/index.html` exists" as unverified (`.pm/w4/done/377.md`, § Unverified). That response is now captured: Render serves the directory's `index.html` at the slashless path with **200** and no redirect. The extra hop changes the address bar and canonical URL of every slashless link that Docusaurus, Astro, Hugo or VuePress sites emit. Parity first: amend the w4/384 decision.

**Severity:** minor (the visitor still lands on the right page, one redirect later and at another URL). **Attribution:** server (static-server). **Estimate:** ~30m (same function as w8/317; ship them together). **Source:** `/qa-find-bugs-cli` w8 loop sweep `617f`, 2026-11-13 UTC, released `bex v0.6.0`, `https://api.bex.co/v1/`, workspace `bex-canary`, production pin `1c4d721bc8dc`.

## Render's behavior (black-box captures, 2026-11-13 ~22:30 UTC)

`https://mentorship-guide.onrender.com` is a Docusaurus site with the default `trailingSlash`, which publishes `docs/about/index.html`. Each response carries Render's `rndr-id` header:

```
/docs/about              200  etag W/"36f49511…"  20354 bytes   (no Location)
/docs/about/             200  etag W/"36f49511…"  20354 bytes
/docs/about/index.html   200  etag W/"36f49511…"  20354 bytes
/docs/about.html         404  (the site's 404 page)
/docs                    404  (no docs/index.html)
```

A second, unrelated Render Docusaurus site behaves the same way: `/blog/bun` and `/blog/bun/` → 200 with the same ETag as `/blog/bun/index.html`, and `/blog/bun.html` → 404. Render's static-site and redirect docs are silent on this, as w4/377 found.

## bex (fixture `sveltekit-static-blkj`, `srv-dbrorbld9ioc73ds1o5g`)

The build command appended `mkdir -p build/dirq && echo DIRQ-INDEX > build/dirq/index.html`. Then:

```
GET /dirq            301  Location: /dirq/        body: <a href="/dirq/">Moved Permanently</a>
GET /dirq?x=1        301  Location: /dirq/?x=1
GET /dirq/           200  text/html  "DIRQ-INDEX"
```

The sweep-ceeb `vuepress` walk showed the same: `/abc` → 301 `/abc/`.

## Root cause

`redirectToDirectory` (`lego/operator/internal/staticserver/staticserver.go:410-423`) runs after a genuine miss (`ServeHTTP` `:329`). When `hasDirectoryIndex` (`:631-645`) finds `<path>/index.html`, it answers `http.Redirect(…, 301)` with the query kept. That is the w4/384 decision, recorded in ADR029 § Directories without a trailing slash (`docs/ADR029-static-sites.md:18`) and the ADR018 static-site row as "bex's directory semantics, not a captured Render behavior".

## Fix (target behavior)

- At the same point, serve `<path>/index.html` with **200 in place** as an ordinary object:
  - the index's content type, ETag, ranges and conditional handling;
  - custom headers matched against the **request** path;
  - no `Location`.
- Keep everything else w4/384 established:
  - the step runs ahead of the ordered rules and the SPA fallback, so the catch-all `/* → /index.html` rewrite still does not claim a directory;
  - a rewrite to a directory serves its index (`:377`);
  - `/docs` without `docs/index.html` stays a miss;
  - extension-bearing misses stay 404.
- Choose the order against w8/317's `<path>.html` together with that note.
- Amend ADR029 line 18 and the ADR018 static-site row: replace the 301 with Render's captured in-place 200 and cite the captures above. Update `TestDirectoryWithoutSlashRedirectsToTheSlashForm` (`directory_index_test.go:34`) to the new expectation, under a new name.

## Blast radius

Every static site, which all share the static-server, on both sides of `SPAFallbackCutoff`. Relative links inside a directory index served at the slashless path resolve against the parent directory, exactly as on Render. That is the trade w4/384's 301 was avoiding, and parity decides it. Only `ServeHTTP`'s miss path changes. `hasDirectoryIndex` keeps its other caller, the rewrite branch at `:377`.

## Acceptance

- Handler tests:
  - `GET` and `HEAD` `/blog` with `blog/index.html` → 200 with its bytes and no `Location`, query ignored for lookup;
  - a `/blog/*` header applies;
  - `/blog/` is unchanged;
  - the catch-all SPA rewrite still does not claim `/blog`;
  - `/docs` without an index is unchanged.
- Live, after the static-server rolls: a fixture static site publishing `dirq/index.html` answers `/dirq` and `/dirq?x=1` with 200 `DIRQ-INDEX` and no redirect. Delete the fixture.

## Unverified

- Render's choice when both `<path>.html` and `<path>/index.html` exist (see w8/317).
- Whether a matching redirect rule for `/blog` wins over the directory index on Render.
