## Done 2026-10-15

When Bun is selected, the resolve phase (`ResolveNativeBuild`) inserts `COPY --link --from=<pinned oven/bun> /usr/local/bin/bun` plus `RUN ln -sf bun /usr/local/bin/bunx` right after the verified `FROM`, before the source copy and the authored build. The build, the pre-deploy step and the started image therefore all have Bun on the image PATH. A Dockerfile without the expected base is refused, and a refused request leaves the file untouched. `cmd/native-resolve` narrates `==> Using Bun 1.3 (from BUN_VERSION=1.3.4)` after the primary line. m61's PATH/command/env semantics are unchanged: Bun sits beside node in `/usr/local/bin`.
