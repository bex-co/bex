## Objective

Audit the one preparer and resolver wiring across six primary runtimes plus static Node defaulting and applicable App types. Verify changed/unchanged version inputs, exact PATH/commands/env/files and distinct Dockerfile/image/buildpack/direct-static controls.

## Context

[Researched finding and caller trace](../finding.md) · [actual two-client evidence](../evidence/cli-sweep306/README.md).

## Acceptance criteria

- [x] The stated behavior is verified with actual execution or appropriately scoped source checks, with remaining live limits explicit.
- [x] Existing shared contracts and truthful error/version reporting are preserved.

## Done 2026-10-15

- **Callers:** the one `nativeDockerfile` caller, the one `ResolveNativeBuild` caller (`cmd/native-resolve`) and the one `ResolveNativeVersion` caller all follow the new path.
- **Applicability:** static builds default to node, so they opt in the same way. Every primary base is Debian glibc (bookworm, plus trixie for Elixir 1.18/1.19); the copied binary needs only glibc 2.17, and both digests carry amd64 and arm64.
- **Rebuilds:** a `BUN_VERSION` change rebuilds through the native artifact identity (`release_identity.go` `BuildEnv`) and the w4/m93 env revision. A `.bun-version` or lockfile change rebuilds through the commit. The pinned digest separates BuildKit's layer cache.
- **Unchanged:** Dockerfile, prebuilt-image, buildpack and direct static paths. A symlinked or directory lockfile is ignored, like the other version files.
- **Root directory:** lockfiles are read from the service's root directory only, so a Bun workspace whose lockfile sits at the repo root needs `BUN_VERSION`. This is recorded in ADR060.
