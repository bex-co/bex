## Outcome (2026-10-17)

Done. One chain serves every static source: generator → resolve phase → BuildKit.

- **Cache:** the Ruby layer is a `--link` copy keyed by the pinned Ruby digest, so it stays cached across builds. Gems are installed per build, as npm packages are.
- **Root directory:** the check reads the service root, as the build does.
- **Unchanged:** static sites without a `Gemfile`, sites publishing their root (no install step, so no Ruby), explicit-runtime static builds, compute Node services, Dockerfile/image sources and buildless sites.
- **Gem location:** gems land in `/opt/render/project/.gems`, outside the published source.

Limits: a `Gemfile` outside the root directory is not seen. A symlinked `Gemfile` is ignored, as `readVersionFile` ignores links.
