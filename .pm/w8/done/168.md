# A web service with no port set expects port 3000 on bex but 10000 on Render, so commands copied from Render's docs (`--port 10000`, `--bind 0.0.0.0:10000`) never pass the health check

Why: Render documents `PORT` as `10000` by default, and its own guides and real templates hardcode that number. Render's Docker docs use `gunicorn myapp.wsgi:application --bind 0.0.0.0:10000`, and many public templates use `--port 10000`. Bex injects `PORT=3000` and health-checks 3000 when no port is set. A service that binds 10000 literally (as Render's docs tell it to) therefore runs but never becomes healthy, and its first deploy fails at the 15-minute rollout budget. The pinned CLI cannot set a port at all, because Render detects ports, so a CLI user has no remedy short of rewriting the start command.

**Severity:** major (Render-documented start commands fail on import; affects 25 of the sampled real Blueprints). **Attribution:** platform default (`DefaultPort`). **Decision note:** ADR018:103 records "the fallback port is bex's 3000, not Render's 10000" as a divergence but gives no reason to keep it. **Estimate:** 45m plus a migration note. **Source:** `/qa-find-bugs-cli` sweep 1285, 2026-10-21 ([evidence](evidence/cli-sweep1285/README.md)).

## Reproduction

- `lego/types/v1alpha1/app_types.go:881–900`: `const DefaultPort = 3000`, applied whenever `spec.port` is unset. Every create path without a port reads back `serviceDetails.port: 3000` (seen live this sweep: `nginx:1.27-alpine` from `bex services create --image …` gets port 3000 and a health check stalled on "a TCP connect to port 3000").
- Corpus (sweeps 1267/1270/1276): **25 files** hardcode 10000 in a start or Docker command, for example `uvicorn main:app --host 0.0.0.0 --port 10000` (several) and `gunicorn -w 4 -b 0.0.0.0:10000 app:app`. Comments in those files say "Render routes public HTTP to $PORT (default 10000)". A further 61 set `PORT: 10000` as an env var, which is a separate path (ADR018:137).
- A live run of `python -m http.server 10000` was attempted (`srv-dbcauf9akels738t2l10`) but could not schedule ("no node currently has room…", recorded in the evidence). It was deleted (204 → 404). The failure mechanism is the same port-3000 health check shown by the nginx run.

## Expected

[Render web services](https://render.com/docs/web-services): "The default value of `PORT` is `10000` for all Render web services." Target: new web services with no explicit port get `PORT=10000` and are health-checked on 10000. Existing services keep their stored port: the default applies only when `spec.port` is unset at create, so persist `3000` on existing Apps before flipping the constant. The pinned CLI's `services create` then produces a service that a Render-documented command can serve.

## Root cause

`DefaultPort = 3000` (`app_types.go:885`), consumed by `apps/service.go:3140` and the operator's `appEnv` (`app_controller.go:5056–5076`). ADR018:103 and :137 describe the mismatch without a rationale.

## Fix (decision first)

1. **Adopt Render's 10000 (recommended).** First, backfill `spec.port: 3000` on every existing App with an unset port, so no running service changes. Then set `DefaultPort = 10000` and update the dashboard placeholder, ADR018:103/137 and the CLI checklist. A private service keeps its image-declared ports (ADR089).
2. **Keep 3000** and warn: the Blueprint plan flags a start command containing a literal `10000` that differs from the service port, and the docs say so. This is cheaper, but Render's docs and templates keep failing.

## Acceptance

- Unit: create without a port → `port: 10000`, `PORT=10000`, probe on 10000. The backfill leaves existing Apps at 3000 (envtest).
- Live after deploy: `python -m http.server 10000` (free image web service, created via REST with no port) goes `live`; an existing pre-change service is unaffected. Delete by ID with 404 proofs.

## Dedupe

ADR018:103 (fallback-port divergence, recorded) and :137 (`PORT` reserved, w2/m95). ADR089 covers image ports for private services. No item proposes changing the default or measures its cost.
