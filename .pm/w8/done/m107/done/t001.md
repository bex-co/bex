- **The reviewed release.** Debian 12's `zip` 3.0-13+deb12u1 (`This is Zip 3.0 (July 5th 2008), by Info-ZIP.`) is the bookworm package; Render names no version. The sweep 434 diagnostic `apt-get install zip` chose the same package, but it is now part of the reviewed image rather than a tenant installer line.
- **What travels together.** `/usr/bin/zip` with the package's `zipcloak`, `zipnote` and `zipsplit`, and its runtime closure: `libbz2.so.1.0` and glibc (`ldd /usr/bin/zip` on the replica). Info-ZIP zip carries its own deflate, so zlib is not part of it. Nothing is downloaded at build or run time, and no donor root filesystem is copied. `unzip` and `zipinfo` stay as they were.
- **Phases.** `/usr/bin` is outside the primary's `/usr/local` copy, so `zip` is present before source and authored commands at build, pre-deploy and runtime (t002). Both production builds and both runtimes ran it (t006).
- **Environment.** bex sets no `ZIPOPT` or `ZIP` variable, so a tenant's own options apply.
- **Identity.** A changed package is a new image digest, which a families run re-qualifies. The image's SPDX attestation lists every package and the ADR060 D7 table records the versions. Every `native-common-image.yml` run's utility cohort creates archives with zip on the image it publishes (t005).
