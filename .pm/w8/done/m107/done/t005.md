## Closed — 2026-11-19 (loopx session)

Every `native-common-image.yml` utility cohort (`TestNativeUtilityGeneratedImages`) runs these real-image checks on the image it publishes:

- **The original program** (already maintained). `node-compute` runs the frozen m107 build on the Node primary through `original-cases.py`: the before proof, the original archive (`zip -X -9 -q`) checked by `unzip -t`, and the frozen `valid_after`. Three HTTP requests on a `--network none` runtime then pass the frozen `cases/m107/http.py` oracle, every build and runtime archive decoded independently.
- **New ZIP checks** in `utility-check.py`, at the `node-compute` build and network-off runtime and at the `node-static` build. Every archive is read back with Python's `zipfile` alone: exact ordered names, bytes, sizes, CRC32 and methods. They replace the older ZIP lines, whose archives and missing-input error they keep.
  - m107's own program through its original argv, outside the original build. Its build archive must be the frozen bytes (`317e333e…`, 1,645 bytes, for the frozen marker), with the program's six members stored or deflated as zip chose, and every phase reads the retained archive back. At the runtime, m107's own server creates a fresh archive for a request, served as `application/zip` and inside its JSON proof, with the frozen bytes (`67642885…`).
  - `-0` stores all four members; `-9` deflates three with the maximum-compression flag while the empty member stays stored. The name `雪 two.txt` is stored as its UTF-8 bytes without the UTF-8 flag (zipfile reads it as code page 437), and `unzip` restores that name and every byte.
  - `-X` drops the `UT` and `ux` extra fields the default adds; `-Z bzip2` writes method 12 through libbz2; `-y` stores a symlink as a link, without it the target's bytes.
  - `-r` with directory entries, `-D` without them, `-j` junked paths, `-x '*.bin'`, and `-@` names from stdin in their given order.
  - Stdin becomes the deflated member `-`, and an archive written to a pipe uses data descriptors (flag bit 3).
  - `-u` replaces only the newer member (`updating: old.txt (stored 0%)`), `-d` deletes one, `-z` writes the comment `note 雪` from stdin and `-T` reports `test of u.zip OK`.
  - Exit statuses, with zip's own messages: 12 `Nothing to do!` for an unmatched input (no archive written) and for deleting an absent member (the archive unchanged); 18 under `-MM` for an unreadable input, writing nothing; 16 for an unknown option; 3 `Zip file structure invalid` for a damaged archive, which stays as it was.
- **New omission control.** `missing-zip` removes only `/usr/bin/zip`. It proves `command -v zip` fails while `unzip` 6.00, `zipinfo`, `zipnote`, `zipcloak`, `zipsplit` and `libbz2.so.1.0` remain. The original m107 build must then fail with `Error: spawnSync zip ENOENT` after its ready line, the sweep 434 failure.
- **How this was checked before shipping.** The host is arm64 and the adopted image is amd64-only, so the generated-image gate cannot run here. A local replica installed Debian's `zip=3.0-13+deb12u1` and `unzip=6.0-28+deb12u1` on the pinned `node:24-bookworm` (the same `zip`, `unzip`, `libbz2-1.0` and `libc6` versions as the image's SPDX, Debian 12.15, Python 3.11.2):
  - the new block passed build and network-off runtime as uid 1000, as root and with `LANG=C.UTF-8`;
  - the replica wrote the same build archive bytes for production's markers as production did on amd64 (`9a580705…` and `d9459dc6…`, t006), so the frozen values hold on both architectures;
  - each of 25 source mutations failed the assertion it targets: either frozen hash, the program's member methods, unzip's version, the runtime label, the maximum-compression flag, a deflated empty member, the default extra fields, a UTF-8-flagged name, unzip's restored bytes, `-X` keeping a field, the bzip2 method, a followed symlink under `-y`, `-D` keeping directories, `-x` keeping `.bin`, the `-@` order, a stored stdin member, a pipe without data descriptors, the update wording, a comment keeping its newline, each of the four exit statuses, and a delete that changes the archive;
  - four image mutations failed: stock `node:24-bookworm` at the program's first archive (`spawnSync zip ENOENT`), a deleted `libbz2.so.1.0` (zip and unzip no longer load), a deleted `unzip` at the program's before proof, and zip deleted between build and runtime, where m107's server cannot start;
  - the original m107 build and its three network-off runtime requests passed through `original-cases.py`;
  - after the exact `missing-zip` command, the original build printed `QA434_BEFORE` and failed with `Error: spawnSync zip ENOENT`.
  - The push of this change re-runs the amd64 utility cohort through `native-common-image.yml`; that run is the amd64 proof.
