## Closed — 2026-11-19 (loopx session)

Audited on main. The chain is the one w8/m94, m95 and m97 to m103 traced, and no commit since production's pin `c624a4f217ff` touches `deploy/native-base`, `deploy/native-common`, `native.go`, `nativeresolve.go` or `nativebases.go`.

- **One recipe chain.** `nativeDockerfile` (`native.go`) has one caller, the native build Job's preparer. `cmd/native-resolve` ends with `applyNativeCommonBase` (`nativeresolve.go` → `nativebases.go`). So every native web service, private service, worker, cron job and static-site build starts from the common image, whatever the primary (Node, Python, Ruby, Elixir, Go, Rust) and its companions.
- **Phases.** Build, pre-deploy and runtime run one image: the pre-deploy Job runs the image the build produced. So `zip` is there at build and at runtime, as Render lists it, and production's runtimes created a fresh archive on every request (t006). A static site's image is only its publish Job's extract source, so it gets `zip` at build, where the maintained static build creates and publishes archives (t005); a static site has no runtime to promise it at.
- **Resolution.** `applyNativeCommonBase` re-copies only `/usr/local` from the selected primary, then sets the primary's environment, `PATH` included. zip is `/usr/bin/zip`, and the official Node primary ships none (sweep 434's first builds failed with `spawnSync zip ENOENT`), so nothing shadows it. A tenant's own `zip` earlier on `PATH` still wins.
- **Cache and writes.** The base is digest-pinned, and tenant source and environment changes do not touch its layers. zip writes only the archive it is told to (or stdout); the checks passed as uid 1000 and as root on the replica (t005).
- **Exclusions.** Dockerfile, prebuilt-image and buildpack services never enter this recipe. A static site with no build command builds no native image.
- **Neighbors kept.** `unzip`, `zipinfo`, `libbz2`, `pigz`, `gzip` and every other utility of the common image are unchanged, as are native-init and the companion and package-manager steps. m107 changes no product code.
- **Exercised versus source-only.**
  - Production (t006): build and runtime, Node 24.22.1 (Render's default for a new service), both CLIs, on `4b809600…`.
  - Maintained cohort: the frozen m107 program on the Node primary at build and on a network-off runtime (`node-compute`, through `original-cases.py`); the ZIP checks at the Node compute build and network-off runtime and at the static build; and the `missing-zip` omission on the Node primary (t005).
  - Families runs on the same digest: the other primaries, companions, native-init and static.
  - Not executed: a hosted pre-deploy run (Free refuses `preDeployCommand`, as Render does), ARM64 on production (D3) and trixie (the common image is bookworm only, as Render's runtimes are).
