# A logical export and Insights cover only a Postgres instance's primary database; decide whether they should cover every database

Why: since w8/m155 a user can create more databases in an instance. A logical export still dumps the primary database only, and what Insights reports for another database is unchecked. w8/258 made the export surfaces say which database an export contains; what an export and Insights should cover is still open.

**Severity:** minor (an export is incomplete for an instance with more than one database, and says so). **Attribution:** operator (export Job) and server (Insights). **Estimate:** ~2h once decided. **Source:** split from w8/258, 2026-11-11.

## Open

1. **Export.** Should an export hold every database in the instance (one dump per database in the artifact, or a `pg_dumpall`-style dump)? Check first what Render's export contains for an instance with two databases; that needs a Render account. Until then the export is the primary database, named as such.
2. **Insights.** Read what `top-queries` and the size views report for a second database on a cluster, then either cover it or say they read the primary one.

## Acceptance

- An export of an instance with two databases either contains both, or the surfaces keep saying it contains the primary one, matching what Render does.
- Insights' coverage of a second database is stated in ADR009.

## Dedupe

w8/258 (done: the surfaces name the exported database). w8/m155 (done: `CREATE DATABASE` for the default users).

## Decided and closed 2026-11-12 (`/loopx w8`)

- **Export: the primary database, as on Render.** Render's dashboard export is a `.dir.tar.gz` ([Recovery and Backups](https://render.com/docs/postgresql-backups), "Trigger a backup"): PostgreSQL's directory format, which `pg_dump` writes for one database (`pg_dumpall` writes plain SQL only). The same page's "Exporting with `pg_dump`" section tells a user with several databases to "repeat the steps above for each database. Alternatively, you can use `pg_dumpall`". So a Render export holds one database, and bex's export of the primary database, named as such since w8/258, matches. No code change.
- **Insights: stated in ADR009.** Insights connects to the primary database. Processes (`pg_stat_activity`) and Top queries (`pg_stat_statements`) are instance-wide views, so they already list every database's backends and statements; Storage, Table sizes and Table scans read the primary database only (`current_database()`, `pg_tables`, `pg_stat_user_tables`; `lego/backend/internal/postgres/insights.go`). Render's Top Queries tab sits on the database's Metrics page and documents nothing for a second database, so there is nothing to match beyond saying what each view covers.
- **Not verified:** a Render instance with two databases was not exported (no Render account); the directory-format inference rests on the documented file name.
