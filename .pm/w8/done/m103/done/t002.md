The same common image supplies Debian's `python3-pip` and `python3-pip-whl` `23.0.1+dfsg-1` with `python3-wheel` `0.38.4-2` (SPDX of `sha256:4b809600…`, fetched at 18:04Z). `python3 -m pip --version` reports `pip 23.0.1 from /usr/lib/python3/dist-packages/pip (python 3.11)`.

- **Local-only target installation.** The original `pip install --no-index --no-deps --target qsite qa_local_data-1.0-py3-none-any.whl` installs the program's own wheel with no index, and the installed module hashes to the frozen `b63a48ce…` on both production services and on the replica (t008, t007). Nothing is written to the interpreter's site-packages.
- **Beyond the original.** `pip wheel --no-build-isolation` builds a `cp311` platform wheel through `wheel` 0.38.4, `--find-links` resolves a dependency offline into a target, and the console script, `PYTHONPATH`, `importlib.metadata` and `pkg_resources` see the installed distributions (t007).
- **Debian's PEP 668 marker stays.** `/usr/lib/python3.11/EXTERNALLY-MANAGED` is in the image's SPDX file list, so pip refuses a system or `--user` install with `externally-managed-environment` and exit 1, as on Debian 12. A `--target`, `python3 -m venv` (Debian's `python3-venv` bootstraps pip 23.0.1 and setuptools 66.1.1 offline from `/usr/share/python-wheels`) or `--break-system-packages` avoid it. Render's page names the packages but says nothing about this marker; bex keeps the distribution's behavior and promises nothing more.
- **Environment.** bex sets no `PIP_*` or `PYTHONPATH` variable for tenant commands; an authored one applies (t007 sets `PYTHONPATH`).
