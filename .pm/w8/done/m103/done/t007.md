Every `native-common-image.yml` utility cohort (`TestNativeUtilityGeneratedImages`) runs these real-image checks on the image it publishes:

- **The original program** (already maintained). `node-compute` runs the frozen m103 build on the Node 24 primary through `original-cases.py`: metadata, the local-only target wheel install and `build_ext`, checked by the frozen `valid_after`. Three HTTP requests on a `--network none` runtime then pass the frozen oracle, with the extension and wheel identities equal at build and runtime.
- **New packaging checks** in `utility-check.py`, on Debian's `/usr/bin/python3` at the `node-compute` and `node-static` builds; the network-off runtime repeats the last group.
  - m103's own `qa_native_ext.c` and wheel, read from `original-cases.json` (the wheel's frozen hash checked), become a second project, `qa-meta` 2.5, with a requirement on the wheel, a console script and package data. setuptools 66.1.1, `pkg_resources`, setuptools' `distutils` and wheel 0.38.4 import from `/usr/lib/python3/dist-packages`.
  - `setup.py egg_info` writes the exact name, version, `requires.txt`, `entry_points.txt` and `SOURCES.txt`; `setup.py sdist` writes a tarball whose C source equals the input.
  - `pip wheel --no-build-isolation` (pip 23.0.1) builds `qa_meta-2.5-cp311-cp311-linux_<machine>.whl` with the right `Tag` and `Requires-Dist`, and every `RECORD` hash and size is recomputed independently.
  - `pip install --no-index --find-links` resolves the dependency offline into a target: the own module hashes to the frozen `b63a48ce…`, the extension equals the wheel's member, and an import through `PYTHONPATH` and the installed console script (`#!/usr/bin/python3`) print the expected sums, Unicode text and package data. `importlib.metadata` and `pkg_resources` see both distributions and the requirement.
  - pip refuses a system or `--user` install with `externally-managed-environment` (PEP 668). `python3 -m venv` bootstraps pip 23.0.1 and setuptools 66.1.1 offline and installs the wheel with its dependency; the system interpreter still cannot import it.
  - Exit statuses, with pip's own messages: 1 for an unsatisfiable requirement and an invalid wheel, neither creating its target; 2 for an unknown option.
  - `python3-config` reports `-I/usr/include/python3.11` and the interpreter's extension suffix, and `patchlevel.h` says `3.11.2`. An embedded interpreter fails to link without `--embed` and links `libpython3.11.so.1.0` with it; its `PY_VERSION_HEX` equals the library's `Py_Version`. A C error names the undeclared identifier, `build_ext` exits 1 and writes no extension.
  - At every phase, including the network-off runtime, the built wheel reinstalls offline into a fresh target with identical extension bytes, both targets give the expected output, and the embedded interpreter prints the expected JSON and sum.
