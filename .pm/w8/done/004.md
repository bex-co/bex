# KeyValue `maxmemoryPolicy` rejects Render's real wire values (underscore vs. hyphen)

`w9/m2`'s Render CLI walk found `POST /v1/key-value` only accepts hyphenated `maxmemoryPolicy` values (`allkeys-lru`); Render's real API — and every value the CLI's generated client can send (`allkeys_lru`, underscore, `cli/pkg/client/types_gen.go`) — uses underscores. bex-api 400s: `unknown maxmemoryPolicy "allkeys_lru" (valid: [noeviction allkeys-lru allkeys-lfu volatile-lru volatile-lfu allkeys-random volatile-random volatile-ttl])`. This is a hard block on `render keyvalues create` end to end — no CLI flag combination can produce a hyphenated value. Sub-hour fix: accept (or normalize) underscore-separated values in the KeyValue create/update handler, matching Render's wire format; check `persistenceMode` for the same underscore/hyphen drift while in there.

Evidence + full repro harness: `docs/cli-compatibility-checklist.md` (root cause RC4).

Source: `w9/m2` (Render CLI compatibility), 2026-07-15.
