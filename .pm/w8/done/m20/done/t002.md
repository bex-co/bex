## Objective

Cap the projects/environments a workspace may hold, checked before any grouping write during blueprint create/sync, refusing with one coded error (409-class, shape precedent: `AGENT_SESSION_LIVE_LIMIT`) identical across REST, GraphQL, and MCP.

## Context

- Round-7 triage: walk budgets cap a single request at ~10–12.5k groupings but nothing bounds the durable per-tenant total.
- Fix-shape precedent: `w7/done/m72/t004` (exports maxItems + active cap); same bucket as `w1/048`'s deferred webhook quota.
- Pick a generous default (groupings are cheap rows; the cap is an abuse bound, not a plan tier) and make it an env knob following the `BEX_*` table convention in `CLAUDE.md` — mirror the name into `.env.example`.

## Steps
