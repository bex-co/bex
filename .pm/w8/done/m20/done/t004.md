## Objective

On disconnect, delete the project/environment grouping rows and their ACL tuples that this blueprint minted **and that no surviving resource still references** — while preserving Render's disconnect contract exactly: deployed services/datastores are never touched.

## Context

- Round-7 triage: "`DisconnectBlueprint` never reclaims orphans" — dead grouping rows + ACL tuples accumulate per disconnect.
- Careful edge: a grouping may also contain manually-assigned resources (the projects/environments feature exists outside blueprints, ADR032) — reclaim only empty, blueprint-minted groupings; skip any with surviving members and leave a debug log line.

## Steps

1. Track/derive which groupings a blueprint minted (existing rows should reference the blueprint; verify, else derive from the stored manifest).
2. In `DisconnectBlueprint`, sweep empty minted groupings: delete rows + tuples in the t001 transactional shape.
3. Tests: disconnect after sync ⇒ empty groupings gone, populated ones survive; deployed Apps untouched.

## Acceptance criteria

- [ ] Disconnect removes empty minted groupings + tuples; resources and member-bearing groupings untouched.
- [ ] Behavior documented in the disconnect verb's REST/GraphQL/MCP descriptions if they state semantics.

## Out of scope

- Any resource deletion (Render semantics: disconnect never deletes resources).
