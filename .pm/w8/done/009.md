# 009 — Blueprint wire-shape divergence notes for ADR018 (created status, redis alias)

Two documentation-only divergences from the 2026-08-16 lifecycle verification —
record them in `docs/ADR018-render-parity.md`'s Blueprint row notes rather than
changing behavior:

1. **`created` status unreachable.** Render blueprints can rest in `created`
   (registered, never synced); bex syncs on create, so status goes
   `syncing → in_sync|error` immediately (`blueprint.go` create path; the
   `BlueprintStatusCreated` constant exists but is never written). Arguably
   better UX — document, don't change.
2. **`redis` alias never emitted.** bex `resources[]` emits canonical
   `key_value` only, never Render's deprecated `redis` type string. Check
   whether the official Render CLI or any Render client chokes on this during
   the next `w8/007` live re-grade; if not, document as intentional.

Sub-hour doc chore; fold into whichever session next touches ADR018.

## Implemented — 2026-08-16

`docs/ADR018-render-parity.md` now records both deliberate divergences next to the current Blueprint contract: immediate sync makes stored `created` unreachable, and `resources[]` emits canonical `key_value` rather than deprecated `redis`. The deprecated spelling remains read-compatible but is intentionally never emitted.
