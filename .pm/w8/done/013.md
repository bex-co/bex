# Registry digest client sends Basic credentials over plaintext HTTP for any non-cluster-local host

Why: `lego/operator/internal/build/build.go` already decides plain-HTTP-vs-TLS correctly with `registryIsClusterLocal`, but `lego/operator/internal/registry/digest.go` does not share that guard — it defaults **every** schemeless `BEX_REGISTRY` to `http://` and then attaches `SetBasicAuth`, so the day someone points `BEX_REGISTRY` at a real off-cluster registry host the operator silently leaks the Zot/registry password on the wire while the build plane, reading the same variable, correctly requires TLS. Two halves of the operator disagreeing about the same config value is the bug.

Source: `~/.local/state/bex-security-integration/20260915T200437Z/scan/report.md` finding 3 (CWE-319), re-triaged against the tree.

## What's actually there

`registry.NormalizeBase` (`lego/operator/internal/registry/digest.go:51-56`) is unconditional:

```go
func NormalizeBase(registryHost string) string {
	if strings.HasPrefix(registryHost, "http://") || strings.HasPrefix(registryHost, "https://") {
		return registryHost
	}
	return "http://" + registryHost
}
```

Credentials ride that base in `ResolveDigest` (`digest.go:70-79`) and `ListTags` (`digest.go:105`), and `NormalizeBase` is also used directly for repo teardown at `lego/operator/internal/controller/app_controller.go:5580`.

Meanwhile `lego/operator/internal/build/build.go:1350-1375` already has the correct predicate — loopback, `.svc`/`.cluster.local`/`.local`/`.internal` suffix, or single-label host ⇒ cluster-local plain HTTP is fine; anything else ⇒ verify TLS — consumed at `build.go:1174` and `build.go:1192`.

## Not urgent, but not theoretical

Today's configured values are all cluster-local, so nothing leaks in production right now: `BEX_REGISTRY` defaults to `127.0.0.1:5050` (`lego/operator/cmd/manager/main.go:317,354,434`) and `zot.bex-registry.svc:5000` (`lego/operator/cmd/registry-migrate/main.go:59`), and no `deploy/`/`infra/` manifest overrides it. The exposure is latent: it arms itself on the first off-cluster registry host, with no error and no log line.

## Shape of the fix

- Export the cluster-local predicate (move `registryIsClusterLocal` into `internal/registry`, have `build.go` call it) so one function answers "is plain HTTP legitimate for this host" for the whole operator.
- `NormalizeBase` defaults to `https://` for non-cluster-local hosts, keeps `http://` for cluster-local ones, and still honors an explicit scheme.
- Fail closed rather than silently downgrade: if credentials are present and the effective URL is `http://` on a non-cluster-local host, return an error naming `BEX_REGISTRY`.
- Tests: bare cluster-local host → `http://`; bare public host → `https://`; bare public host + credentials over forced `http://` → refused; explicit scheme passes through unchanged.

## Not this note

Node-level image-pull registry config (`infra/clusterapi/overlays/hetzner-caph/cluster.yaml`) — those plain-HTTP endpoints are loopback NodePorts and were correctly dispositioned as not-a-finding by the same scan.
