## Objective

Create bex's price sheet as a new data structure, deliberately **outside** `lego/types/tiers/` — that file's own header comment states "No pricing here... runtime behavior (mechanism) must never depend on money, and this catalog is imported by the operator" — so pricing must live in a bex-api-only location.

## Context

- Discount policy: 30% off every Render $ figure captured in t001 (compute tiers, Postgres tiers, Key Value tiers, build-minute overage), 90% off the bandwidth $/GB rate.
- `lego/backend/internal/store/api.go`'s `normalizeTier` comment ("Prices are Metronome's, not this validity gate's concern") already anticipated pricing living outside the tier-validity code — this task's new package is the near-term, non-Metronome home for it.
- Precedent for a bex-api-only internal package: `lego/backend/internal/usage/` (the metering pipeline this milestone extends).

## Steps

1. Create `lego/backend/internal/pricing/` with a versioned price-sheet data structure: tier id → bex $/month (compute, postgres, valkey families), a single bandwidth $/GB rate, a build-minute overage rate.
2. Compute every bex figure as Render's captured figure × 0.7 (compute/Postgres/KV/build-minutes) or × 0.1 (bandwidth) — round to a sensible $ precision (e.g. nearest cent or nearest dollar, pick one convention and apply it uniformly).
3. Add a lookup function (tier id → price) mirroring `tiers.Compute.ByID`'s shape, for t004-t006 to consume.

## Files

- new `lego/backend/internal/pricing/`

## Acceptance criteria

- [ ] Every tier id from `lego/types/tiers/tiers.yaml` has a corresponding bex price.
- [ ] Compute is a pure function of the t001 snapshot + the stated discount percentages (no hand-picked one-off numbers).
- [ ] The operator module does not import this package (money stays out of mechanism code).

## Out of scope

- Documenting the policy in prose — that's t003.
- Wiring it into the usage API — that's t004-t006.
