## Objective

Extend the existing `GET /v1/usage` REST endpoint (`docs/ADR023-usage-metering.md`) with an `estimatedCost` field — per-meter $ amounts plus a total — computed by multiplying each returned `instance_seconds`/`egress_bytes`/`build_seconds` row by the t002 price sheet.

## Context

- Current response shape (from `docs/ADR023-usage-metering.md`): `{ "kind": "instance_seconds", "tier": "starter", "total": 14400 }`, `{ "kind": "egress_bytes", "total": 2048 }`, `{ "kind": "build_seconds", "total": 120 }`.
- `instance_seconds` is tier-scoped (needs the per-tier compute price ÷ seconds-per-month); `egress_bytes` needs bytes→GB conversion at the bandwidth rate; `build_seconds` needs seconds→minutes at the build-minute rate.
- Label the field clearly as an estimate (e.g. `estimatedCostUsd`, not `cost` or `charge`) to avoid implying an invoice.

## Steps

1. Add the computation in `lego/backend/internal/usage/` (or wherever `GET /v1/usage`'s handler lives), calling into `lego/backend/internal/pricing/` from t002.
2. Add `estimatedCost` (per-meter + total, in USD) to the REST response envelope.
3. Handle the free tier / unpriced-usage case gracefully (zero cost, not an error).

## Files

- `lego/backend/internal/usage/rest.go` (or equivalent)

## Acceptance criteria

- [ ] Response includes a per-meter estimated cost and a total, computed correctly against the price sheet.
- [ ] Zero usage or free-tier usage returns `0`, not an error.

## Out of scope

- GraphQL (t005) and MCP (t006) — same computation, different adapters, per ADR006's "one Core, three adapters."
