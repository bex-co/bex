# A no-build static site whose publish directory is missing closes its log with bex's `==> Build failed: the publish directory "…" does not exist in the repository at "<sha>"`, where Render's logs `==> Publish directory <dir> does not exist!` and then `==> Build failed 😞`

Why: w8/393 matched Render's `==> Build failed 😞` close for a build whose own work failed. A static site with no build command fails in bex's publish Job instead, so its log still closes with bex's line and its cause, and never prints the line Render prints there.

- Severity: minor. The deploy fails the same way and keeps the live release serving; only the log's last lines differ.
- Render, from EthanM32122/cloaket#1 (2026-09-22, `gh issue view -R EthanM32122/cloaket 1`): `==> Cloning from …`, `==> Checking out commit … in branch main`, `==> Empty build command; skipping build`, `==> Publish directory 1.0 does not exist!`, `==> Build failed 😞`, `==> Common ways to troubleshoot your deploy: https://render.com/docs/troubleshooting-deploys`.
- bex: the no-build publish Job's clone check (`failUserSource`, `lego/operator/internal/publish/publish.go:736`) fails with `the publish directory "<rootDir>/<dir>" does not exist in the repository at "<full sha>"`. The operator records it as the Build condition's message (`app_controller.go` `publish.PhaseFailed`, `ReasonBuildFailedUserError`), which is not a `FormatBuildFailed` reason, so `rendersVerdict` (`lego/backend/internal/logs/progress.go`) keeps bex's `==> Build failed: …` line. w8/291's probe of round 216 recorded the same residual and filed nothing.
- A native static build with a build command already prints Render's `==> Publish directory <dir> does not exist!` (w8/291) and, since w8/393, closes with Render's two lines.
- Not yet observed: whether Render prints `==> Empty build command; skipping build` for a static site with no build command on every deploy, and its line for a branch or commit the clone cannot fetch.

## Fix

Make the no-build publish's missing directory read as Render's does: the build log carries `==> Publish directory <dir> does not exist!` (the publish path as configured, not root-joined), and the deploy closes `build_failed` with a reason `appv1alpha1.IsBuildFailed` reads, so the log closes with `==> Build failed 😞` and the troubleshooting line. Keep the cause on the deploy's `failureReason`. Leave the clone's other failures as they are unless a Render log shows their lines.

## Acceptance

- Unit tests: the publish Job's missing-directory failure reads back through `IsBuildFailed`, and its log carries Render's line.
- Live in `bex-canary`, on a free static site with no build command and Publish Directory `nope`: `bex logs --type build` ends with `==> Publish directory nope does not exist!`, `==> Build failed 😞` and the troubleshooting line. Delete the fixture by ID and confirm the 404.
