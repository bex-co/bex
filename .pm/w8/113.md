## Outcome (2026-10-16)

Implemented: the generated primary-Python image carries `ENV GUNICORN_CMD_ARGS="--preload --access-logfile -"` before the build RUN (`nativeBuildDefaults`, lego/operator/internal/build/native.go), so build and runtime have Render's Gunicorn flags while the service's own value (incl. explicit empty) wins in each phase; Render's `--bind` is left out because Gunicorn binds the platform PORT (a `gunicorn.conf.py` bind still wins, recorded). Explicit Python static builds get it for their build; other runtimes none. `nativeruntimeenv_test.go`: shared placement test (every Python and Elixir line, static, exclusions) and an opt-in BuildKit gate serving a request through real Gunicorn 23.0.0 at port 10000 — access line in the container log by default with the flags visible in both phases, none when explicitly empty. Fail-before on a clean HEAD worktree: flags absent (`build= runtime=None`), no access line. Python image gates (Poetry/uv/JS/FFmpeg) and lint pass; ADR060 D7 note covers the preload rollout caveat and duplicate request logging, as on Render. Not covered locally: other Python lines' execution, group/Secret-sourced overrides, CLI-flag precedence and pre-deploy — hosted replay gate.
