# An Elixir release cannot start with long node names in a bex pod, so `RELEASE_DISTRIBUTION=name` is not set

Why: Render sets `RELEASE_DISTRIBUTION=name` on every Elixir service, which is what clustering over `RENDER_DISCOVERY_SERVICE` needs. bex leaves it unset, so a release uses short names and cannot join a cluster the way Render's guide describes. Setting the variable alone is worse: the node fails to boot.

**Severity:** minor (clustering parity; single-node releases work). **Attribution:** infrastructure/runtime (pod hostname) and the native Elixir image. **Estimate:** ~2h. **Source:** found while working w8/256, 2026-11-11.

## Evidence

A pod's hostname is its pod name, with no domain. Reproduced with the same shape in a container (`elixir:1.18-slim`, hostname `web-7d9f5c`, resolver search list `bex-ws.svc.cluster.local svc.cluster.local cluster.local`):

```text
$ elixir --name foo -e "IO.inspect(node())"
Kernel pid terminated (application_controller) ("{application_start_failure,kernel,{{shutdown,{failed_to_start_child,net_sup,
  {shutdown,{failed_to_start_child,net_kernel,{'EXIT',nodistribution}}}}},{kernel,start,[normal,[]]}}}")
$ elixir --sname foo -e "IO.inspect(node())"
:"foo@web-7d9f5c"
```

A release started with `RELEASE_DISTRIBUTION=name` and the default `RELEASE_NODE` runs `--name <release>`, the first command. The search list does not help: Erlang takes the domain from the host's own name.

## Fix

1. Give the node a name it can use. Either the pod gets a fully qualified hostname (a pod `subdomain` puts `<pod>.<subdomain>.<ns>.svc.<cluster>` in `/etc/hosts`), or the Elixir image defaults `RELEASE_NODE` to `<release>@<pod IP>`; an address is a valid long-name host.
2. Then default `RELEASE_DISTRIBUTION=name` in `nativeBuildDefaults` (`lego/operator/internal/build/native.go`), build and runtime, and drop the name from the left-out list in its comment and in `TestNativeRuntimeDefaultsFromRendersTable`.
3. Check Render's Elixir clustering guide for what `RELEASE_NODE` is there, and whether two instances of one bex service can reach each other's distribution port.

## Acceptance

- A Phoenix release with no clustering configuration boots on bex with `RELEASE_DISTRIBUTION=name` in its environment, and `node()` is a long name.
- A service that sets `RELEASE_DISTRIBUTION=sname` itself still starts with a short name.

## Unverified

- Not run in a bex pod; the container above has a pod's hostname and resolver shape.
- What hostname a Render instance has, and why the default works there.

## Dedupe

w8/256 set the other per-runtime defaults and left this one out. w8/112 (done) is `MIX_ENV`.
