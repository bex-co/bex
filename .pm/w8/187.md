# Protected environments demand a bex-only typed phrase (`confirm="sudo …"`) from every caller, admins included, so `bex services delete`, `bex deploys create --image` and a Render-shaped rollback all fail; Render restricts a fixed list of actions to Admins and never asks for a phrase

Why: [Render's projects docs](https://render.com/docs/projects) say that in a protected environment only **Admin** workspace members may:

- create, move or delete the environment's resources, or delete the environment;
- suspend or resume services, and toggle maintenance mode;
- use shell access;
- view or modify environment variables and secret files.

Blueprint-managed resources stay editable through `render.yaml`. Rollbacks, deploys of a specific commit or image, and ordinary settings changes are not on that list, and no confirmation parameter exists. Bex instead gates many verbs behind a typed phrase that only bex knows (`?confirm=` on REST, `confirm` on GraphQL and MCP). The gate applies to every caller, including the workspace owner, and the pinned CLI has no way to send the phrase. A Render admin's normal CLI and API workflow therefore fails on bex, and actions Render leaves open (rollback, image or commit deploys, settings changes) are gated too. ADR018's rollback row and ADR032 call it "ADR032's recorded divergence" without a user sign-off.

**Severity:** major (every protected environment; admins cannot delete, roll back or redeploy a specific image from the CLI or a Render API client). **Attribution:** server (`apps`, `deploys`, `postgres` and `keyvalue` protection gates). **Estimate:** 3h. **Source:** `/qa-find-bugs-cli` sweep 1321, 2026-10-22 ([evidence](evidence/cli-sweep1300/README.md#sweep-1321--protected-environments)).

## Reproduction

Production `https://api.bex.co/v1/`, pin `efdd8e2ff06b`, `bex-canary`, human device-login grant as the workspace **owner**. All fixtures were deleted afterwards (the service needed bex's phrase; then the service, project and environment → 404).

1. `POST /v1/projects {"name":"qa-20261022-c4033a-prot","ownerId":"tea-daif693dqjvc73e7as3g","environments":[{"name":"production","protectedStatus":"protected"}]}` → 201 (`prj-dbcsfobpgbls73dcpa7g`). The environment reads `protectedStatus: protected`.
2. `bex services create --type web_service --image docker.io/traefik/whoami:v1.10.3 --plan free --env-var PORT=80 --environment-id <env>` → `srv-dbcsfojpgbls73dcpa9g`, live (`dep-dbcsfojpgbls73dcpaa0`).
3. `bex deploys create <srv> --image docker.io/traefik/whoami:v1.10.3` → **exit 1**: `400 (PROTECTED_ENVIRONMENT_CONFIRMATION_REQUIRED): "qa-20261022-c4033a-pweb" is a member of a protected environment; retry with confirm="sudo repoint service qa-20261022-c4033a-pweb" to repoint it`. A plain `bex deploys create <srv>` works.
4. `POST /v1/services/<srv>/rollback {"deployId":"dep-dbcsfojpgbls73dcpaa0"}` (Render's body) → the same 400.
5. `DELETE /v1/services/<srv>` and `bex services delete <srv> --confirm` → **400** `… retry with confirm="sudo delete service qa-20261022-c4033a-pweb" to delete it`. Only `DELETE …?confirm=sudo%20delete%20service%20<name>` succeeded.

## Expected

- Bex enforces Render's rule: the restricted actions above (create, move, delete, suspend/resume, maintenance mode, shell, env-var and secret-file read and write, environment deletion) require the caller to be a workspace **Admin**. A non-admin gets 403. There is no phrase and no extra parameter, so a Render client or the pinned CLI used by an admin succeeds unchanged.
- Rollback, deploys of a specific commit or image, and other settings changes are allowed for anyone who may deploy, as on Render.
- The Blueprint exception holds: a non-admin's Blueprint sync may modify the environment's Blueprint-managed resources.

## Root cause

`lego/backend/internal/apps/protection.go:138–151` (`requireUnprotected`) and `core/confirmation.go:98–107` (`RequireProtectedConfirmation`) turn "member of a protected environment" into "needs the typed phrase", regardless of role. Call sites:

- **apps:** deploy/repoint `apps/deploy.go:3445`; `deploys/service.go:488–500` (override trigger and rollback); delete `apps/service.go:2859`; suspend `apps/service.go:4996`; "redefine" settings changes `apps/settings_check.go:125,154,193,205,264`; "take offline" `apps/settings_check.go:334`.
- **postgres:** delete `postgres/service.go:855`, suspend `postgres/lifecycle.go:55`, fail over `:104`, write queries `postgres/query.go:171`.
- **keyvalue:** delete `keyvalue/service.go:585`, suspend `:625`.

## Fix

1. Replace the phrase check with a role check. In a protected environment, the verbs in Render's list require the workspace Admin (or Owner) role, through the OpenFGA relation the members model already has (ADR024); others get `403` naming the restriction. Remove the gate from verbs Render does not restrict: rollback, repoint deploys, "redefine" settings, Postgres write queries and failover (check failover against Render's list; it is not on it).
2. Add the missing Render restrictions that bex does not enforce today, if any: env-var and secret-file reads for non-admins, and shell access.
3. Keep the Blueprint exception: a sync by a non-admin may change Blueprint-managed resources in the environment.
4. The dashboard may keep a confirm dialog as UX, but the API must not require a phrase. Update ADR032, ADR018's rollback and projects rows, and the MCP tool descriptions that mention `confirm`.

## Blast radius

Every resource in a protected environment (services, Postgres, Key Value, env groups), on REST, GraphQL, MCP, CLI and dashboard. Unprotected environments are unaffected. Non-admin members lose today's phrase escape hatch for Render's restricted actions and gain the unrestricted ones, as on Render.

## Acceptance

- Authorization tests: an Admin performs every restricted verb with no phrase. A non-admin Developer gets 403 on each restricted verb and succeeds on rollback, image deploy and a settings change. A non-admin's Blueprint sync still updates its resources.
- Live after deploy: repeat steps 1–5 as owner. Steps 3–5 succeed without a phrase. Delete fixtures by ID with 404 proofs.

`git grep -i 'PROTECTED_ENVIRONMENT_CONFIRMATION|protected environment' .pm`: w4/m176 (done) introduced the phrase gate. No open item replaces it with Render's role rule.
