# A new Python service with no version signal now runs Python 3.14.10; Render's default for services created since 2026-10-12 is exactly 3.14.8 (regressed w8/174's acceptance)

Why: Render's [Python version](https://render.com/docs/python-version) page fixes the default for new services at **3.14.8** ("services created on or after 2026-10-12"). w8/174 matched that: its acceptance was "a new `render-examples/fastapi` service logs `Python 3.14.8`", and that was true only because bex's 3.14-line pin happened to be 3.14.8. `63fd10231` ("refresh native and CNB base images for Brotli fixes") moved the 3.14 line to 3.14.10 (`lego/operator/internal/build/native.go:121`), so the no-signal default moved with it. Ruby avoids this: since w8/198 its default is an explicit exact patch (`rubyDefaultVersion = "3.4.4"`, `nativeversion.go:114`), separate from the line's latest patch.

Severity: **minor** (patch-level drift; an app that relies on 3.14.8 behavior or pins wheels to it differs from Render). Attribution: platform build (native default resolution). Estimate: ~30m plus a decision on the security trade-off. Source: `/qa-find-bugs-cli` loop sweep 3093, 2026-10-29 04:11–04:30 UTC. Context: platform pin `c9ccd73df050` (carries `63fd10231`); `https://api.bex.co/v1/`; workspace `bex-canary`.

All three fixtures were deleted by ID (`GET` 404). (The Ruby probe's `ruby -run -e httpd` crash-loops because Ruby 3.4 no longer bundles webrick; that is the fixture's fault, not a finding.)

## Decision needed

`63fd10231` bumped 3.14.8 → 3.14.10 to pick up upstream Brotli fixes. Matching Render exactly means the default stays on 3.14.8, which lacks them.

1. **Exact default, like Ruby:** add `pythonDefaultVersion = "3.14.8"` for services created on or after the 2026-10-23 cutoff, pinned by digest, and keep `3.14` → 3.14.10 for explicit line requests (`PYTHON_VERSION=3.14`). This is Render-identical, but new no-signal services run an interpreter without the Brotli fixes (whether Render's own 3.14.8 runtime image carries a patched Brotli is unverified). Note it in ADR018.
2. **Keep 3.14.10**, record the divergence in ADR018 with the security reason and user sign-off, and amend w8/174's acceptance text.

Option 1 is the parity-first default (AGENTS.md). The security rationale for option 2 is real, so the user should choose.

## Acceptance (option 1)

- New `render-examples/fastapi` (or flask) service with no version signal → `Python 3.14.8`. `PYTHON_VERSION=3.14` → 3.14.10. A service created before the cutoff keeps 3.13. Unit test alongside `rubyDefaultVersion`'s. Delete fixtures by ID with 404 proofs.

## Dedupe

- `rg -i '3\.14\.8|default Python' .pm`: w8/174 (done; it asserted 3.14.8 when the pin coincided) and w8/198 (the Ruby exact-default precedent). No open item; `63fd10231` and w1/136 do not mention the default-version effect.
