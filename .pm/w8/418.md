# `PATCH /v1/blueprints/{id}` (and `bex ea blueprints update --path`) persists a nonexistent Blueprint file path instead of refusing it (`404` when branch is unchanged)

Why: Render's `update-blueprint` contract refuses a path change whose file does not exist on the Blueprint's branch (`404`), preserving the working Blueprint; bex skips repository file discovery whenever `branch` is unchanged, so a typo in `--path` overwrites the Blueprint's path and breaks every subsequent `plan` and `update --branch` until manually reverted.

- Severity: **major** (a typo in `bex ea blueprints update <id> --path <missing>` mutates and corrupts a working Blueprint's configured path with `200 OK`, then fails planning and leaves the Blueprint broken on the nonexistent path).
- Versions: checkout build of `lego/cli` at `ac882b5f55` (compatible with Render CLI `v2.37.0`, upstream pin `11ef59f330dedec290f8d71d89b8f7379bbbed09`); production platform pin `1a5a8e872398` (`e6c65f5c62`); `blueprint.go` unchanged through `f68b234111`.
- Context: 2026-11-23 10:47 UTC, `https://api.bex.co/v1/`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), QA human device login, non-TTY `-o json`.
- Source: routine `cli-qa` sweep `c8a2`.

## Render's contract

- Pinned Render OpenAPI (`lego/backend/internal/api/openapi/render-public-api-1.json`, `PATCH /blueprints/{blueprintId}`, `operationId: update-blueprint`):
  - `branch`: _"The branch must contain a Blueprint file at the configured path. Updating this field does not plan a sync."_
  - `400`: _"The request contains invalid values (such as an empty branch or path), branch updates are not available for the workspace, or the Blueprint file could not be read and validated after changing the branch."_
  - `404`: _"The Blueprint was not found, or the Blueprint file could not be found at the requested path when the branch is unchanged."_
- Pinned upstream CLI (`github.com/render-oss/cli@v1.1.3-0.20261117005113-11ef59f330de`):
  - `pkg/blueprint/service.go:140-164` (`Service.Update`): sends `PATCH /v1/blueprints/{id}` first (`s.repo.Update`). If `PATCH` returns an error (400/404), the CLI returns immediately without changing the Blueprint or calling `Plan`. Only after `PATCH` returns `200` does it call `POST /v1/blueprints/{id}/syncs` (`s.repo.Plan`).
  - `bex ea blueprints update --help`: _"The branch must contain a Blueprint file at the configured path."_

## Attribution and root cause

- Attribution: **server** (`lego/backend/internal/apps/blueprint.go:2127-2138`).
- `Service.UpdateBlueprint` (`lego/backend/internal/apps/blueprint.go:2073-2159`) runs `discoverBlueprintFile` **only** inside `if req.Branch != nil && *req.Branch != b.Branch` (`:2127-2138`).
- When `req.Path != nil && *req.Path != b.Path` while `branch` is unchanged, `UpdateBlueprint` validates only the syntactic allowlist `approvedBlueprintPath(*req.Path)` (`:2103-2109`), skips `discoverBlueprintFile`, and persists the nonexistent path via `s.Blueprints.UpdateBlueprint` (`:2154`).
- `blueprintCreateFetchError` (`lego/backend/internal/apps/blueprint.go:449-463`) maps every non-retryable fetch error (including `BlueprintFetchFileNotFound`) to `400`, whereas Render's OpenAPI specifies **`404`** when the Blueprint file cannot be found at the requested path with the branch unchanged and **`400`** when the branch changed.

## Fix

- In `Service.UpdateBlueprint` (`lego/backend/internal/apps/blueprint.go:2127-2138`):
  - Run `discoverBlueprintFile(ctx, s.GitFetcher, tenantID, b.Repo, targetBranch, targetPath)` whenever **either** `branchChanged` (`req.Branch != nil && *req.Branch != b.Branch`) **or** `pathChanged` (`req.Path != nil && *req.Path != b.Path`).
  - When `branchChanged` is true, keep `blueprintCreateFetchError` (`400` for non-retryable fetch errors, `503` for retryable ones).
  - When `pathChanged` is true and `branchChanged` is false: if `classifyBlueprintFetchError` classifies the error as `BlueprintFetchFileNotFound`, return a `404` (`fmt.Errorf("%w: %s", core.ErrNotFound, message)` — no non-Render `code` field, preserving w8/411's REST 404 rule); for retryable fetch errors return `503` (`core.NewUnavailableError`), and for other non-retryable errors (e.g. repo access) return `400` (`blueprintFetchRefusal`).
  - Leave unchanged: no-op `PATCH` where `req.Path` equals `b.Path` (or is omitted) and `branch` is unchanged; forbidden/unauthenticated (`403`/`401` before fetch) and missing Blueprint (`404` before fetch) neighbors stay unchanged.
- Update the existing tests that relied on `UpdateBlueprint{Path: new("nope.yaml")}` / `"other.yaml"` as a shortcut to force a failed plan (`blueprint_approve_no_changes_test.go:130,197`, `blueprint_approve_waiting_plan_test.go:180,342,407,477`, `blueprint_test.go:4017,4026`): swap `svc.GitFetcher` (as `TestAPlanAfterANoChangesPlanIsTheNewest` at `blueprint_approve_no_changes_test.go:161` already does) or serve the requested path on the fake fetcher instead of relying on `UpdateBlueprint` saving a missing file.
- Update `docs/ADR049-render-yaml-parity.md` / `docs/ADR018-render-parity.md` if needed to record path-existence verification on `PATCH /v1/blueprints/{id}`.

## Regression checks and acceptance

- Unit/API tests covering REST, GraphQL, and MCP `UpdateBlueprint`:
  - Changing `path` to a nonexistent file with branch unchanged → `404` (no non-Render `code` on REST), stored `path` stays `"render.yaml"`, no sync created.
  - Changing `path` to an existing `.yaml` file with branch unchanged → `200`, stored `path` updates.
  - Changing `branch` to a branch missing the file → `400`, stored `branch` unchanged (existing `TestUpdateBlueprintBranch` control).
  - Changing both `branch` and `path` together where the new `(branch, path)` exists → `200`; where it does not → `400`, neither field mutated.
  - Unchanged `path` (e.g. name/autoSync-only update) makes no `GitFetcher` call.
- Live acceptance in `bex-canary` after deploy:
  - Create a plan-only Blueprint from `https://github.com/render-examples/express-hello-world` (`main`, `render.yaml`).
  - `bex ea blueprints update <id> --path no-such-file.yaml -o json` exits 1 with `received response code 404: …`, and `GET /v1/blueprints/<id>` still reports `"path": "render.yaml"`.
  - Delete the Blueprint by ID (`DELETE /v1/blueprints/<id>`) and confirm `GET` 404.

## Unverified

- Render's exact 404 JSON `message` wording for a missing path on `PATCH /blueprints/{id}` was not live-captured against render.com; the status code (`404` when branch is unchanged vs `400` when branch changes) and refusal semantics come directly from Render's pinned OpenAPI spec (`render-public-api-1.json`).
- Whether Render also parses/validates YAML contents on a `path`-only change (as the `400` description mentions for `branch` changes) was not verified live; validating file existence via `discoverBlueprintFile` closes the observed corruption bug cleanly.
