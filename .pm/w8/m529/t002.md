## Objective

The release record keeps the image, commands, environment and runtime settings a release went live with, but not its registry credential. Record the binding, meaning the credential id and its pull Secret, or "none". Have Restart and rollback carry it in the selection they open, the same way `Runtime` travels today.

## Context

- `ReleaseRecordSpec` and `ReleaseConfigReference` live in `lego/types/v1alpha1/releasesnapshots.go`. Pointer fields tell an explicitly empty value apart from a legacy record.
- The operator writes the record in `releaseRecordSpec` (`lego/operator/internal/controller/release_config_selection.go:552`). The binding to record is the spec's `RegistryCredentialID` and `ExternalRegistryPullSecret` as the release dispatches.
- Records since w8/m121 (`190c12865`, 2026-10-19) already hold the whole adopted `AppSpec` under `releaseRecordAdoptedSpecKey` (`release_view.go:31`, written by `recordAdoptedRelease`), binding included. A selection copies its source's adopted spec (`ensureSelectedReleaseConfig`). The key is operator-internal today. If the binding can be read from it, that covers every release recorded since October, not only new ones. Prefer that over a new field if it holds, and say which you chose.
- `targetReleaseConfig` (`lego/backend/internal/deploys/rollback_config.go:46`) copies the record's `Runtime` into the selection for Restart (`restart=true`) and rollback (`restart=false`).
- Render's rollback pulls the target's tag or digest (`render.com/docs/rollbacks` § Registry-hosted Docker images). Read what it documents about the credential for that pull. Default to the target's own binding, the one that pulled it before, unless Render says otherwise.

## Steps

1. Make the binding readable from a release record: from the adopted spec (see Context), or as a new `ReleaseRecordSpec` field that the operator writes. A record without it is legacy. Carry it in `ReleaseConfigReference` (nil means legacy), then regenerate the CRD (`make manifests` from `lego/operator/`).
2. Check that a Restart of a Restart keeps the original binding: the selection's own record copies its source's.
3. `targetReleaseConfig` copies the record's binding into the selection for both Restart and rollback.
4. If the binding names a credential that still exists, Restart and rollback refresh that credential's per-App Secret from the stored token before opening the release, so a rotated token is used, as a new pull on Render would. A credential that was deleted selects no Secret.
5. Backend tests (`lego/backend/internal/deploys`) cover a served release with none, with A while the spec binds B, a legacy record, and a rollback to a deploy with another credential.

## Files

## Acceptance criteria

- [ ] The Restart selection carries the serving release's binding, whatever the saved one is.
- [ ] The rollback selection carries the target's binding.
- [ ] A legacy record selects nothing, and the release keeps today's saved binding.
- [ ] Reverting step 3 fails the backend test.
