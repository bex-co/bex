## Objective

The operator attaches `spec.externalRegistryPullSecret` to every pod it builds, whichever release the pod runs. When the active selection (Restart, rollback) carries a recorded binding, build that release's pods and read its image with the binding instead. A legacy selection with no binding keeps the spec's.

## Context

- `imagePullSecrets` (`lego/operator/internal/controller/app_controller.go:2436`) feeds:
  - the Deployment (`:3009`, through `withLinkedSourcePullSecret`);
  - the pre-deploy step Job (`:7631`);
  - cron pods (`:6179`);
  - `backfillWorkloadPullSecrets` (`:2614`), which patches a running Deployment's references when its image is registry-hosted.
- `externalImageAuthHeader` (`image_network.go:124`) reads the spec's Secret for image metadata. `imageRefusalError`'s credential flag (`app_controller.go:835`) uses the same field.
- `App.RuntimeSpec()` (`lego/types/v1alpha1/releasesnapshots.go`) is the existing pattern: the active selection's recorded settings over the saved spec, skipped when `canceledOverServed` restores a template verbatim.
- `ExternalRegistryPullSecret` is part of the release identity (`release_identity.go:164`, `:215`) and is dropped from the settings fingerprint (`:247`). Keep both meanings.

## Steps

1. Add one accessor for the external pull Secret the current release runs with: the active selection's binding when recorded, else the spec's. Use it in every caller above. `backfillWorkloadPullSecrets` must not repoint a serving release at the saved binding.
2. Envtest, built on the production repro:
   - A served image release with no credential. The spec now binds a fake credential, and a failed image switch has run. A Restart's Deployment names no external pull Secret.
   - A served release with A while the spec binds B. The restart names A's Secret, whose content is still A.
   - A rollback to a deploy with another binding names that binding's Secret.
   - The pre-deploy step Job matches the Deployment.
   - A legacy selection keeps the spec's binding.
3. Check cron jobs. A run builds its pod from the saved spec and the image of the serving release (`:6179`). After a failed image switch, the next scheduled run may pull the old image with the new credential. If it does, have the run use the serving release's recorded binding and cover that in the envtest. If that needs more than this task holds, file it as its own item.
4. Revert step 1 and watch the envtest fail.
