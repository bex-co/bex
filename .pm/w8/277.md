# A logical export of a Free Postgres database is refused with "has no backup store", which does not name the Free plan

Why: Render says "Free Render Postgres databases don't support any form of backups", and bex refuses an export of a Free database, which is right. But the refusal reads `"dpg-…" has no backup store; exports are unavailable`. That is the platform's storage wiring, not a reason a user can act on, and it has no error code. The other Free limits on the same database answer with a named code and the plan: `POSTGRES_CONNECTION_POOL_PLAN_UNSUPPORTED`, "connection pooling requires a paid Postgres plan".

**Severity:** minor (the refusal is correct; only its wording and code are off). **Attribution:** server (backend postgres). **Estimate:** ~20m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `05f7`, 2026-11-11 UTC, released `bex v0.5.0` (Render CLI v2.35.0), `https://api.bex.co/v1/`, production pin `8330744bd643`, workspace `bex-canary`, QA human device login. The pinned CLI has no export command; the request is REST with the CLI's token.

## Evidence

On a free PostgreSQL 18 database (`qa-20261111-05f7-pg`):

```text
POST /v1/postgres/<dpg>/export
→ 400 {"error":"bad request: \"dpg-…\" has no backup store; exports are unavailable","id":"bad_request",
       "message":"bad request: \"dpg-…\" has no backup store; exports are unavailable"}

$ bex pg update <dpg> --connection-pool pgbouncer
Error: received response code 400 (POSTGRES_CONNECTION_POOL_PLAN_UNSUPPORTED): connection pooling requires a paid Postgres plan; …
$ bex pg update <dpg> --disk-size-gb 5
Error: received response code 400 (POSTGRES_STORAGE_PLAN_UNSUPPORTED): free Postgres storage is fixed at 1 GB; upgrade to a paid plan for 5 GB of storage
```

`GET /v1/postgres/<dpg>/recovery` answers `{"recoveryStatus":"NOT_AVAILABLE"}`, and `GET …/export` answers `[]`.

## Expected

Render, [Free instances](https://render.com/docs/free): "Free Render Postgres databases don't support any form of backups."

The export refusal for a Free database says so in product terms and carries a code like its siblings, for example `POSTGRES_EXPORT_PLAN_UNSUPPORTED`: "logical exports require a paid Postgres plan; Free databases have no backups".

## Root cause

`CreateExport` refuses on `!d.Status.BackupsEnabled` with one sentence for every cause (`lego/backend/internal/postgres/recovery.go:528-530`). It does not look at the plan, so a Free database and a cluster whose backup store is not configured read the same.

## Fix

1. In `CreateExport`, when the database's plan has no backups, return the coded plan refusal. Keep the current sentence for a paid database whose store is missing, which is an operator fault.
2. Use the same sentence wherever else a Free database is refused a backup action (manual backup, restore), if those paths share the check.

## Acceptance

- `POST /v1/postgres/<free>/export` answers 400 with the new code and a message that names the Free plan and contains no "backup store".
- A paid database with backups enabled still exports.
- A test covers both causes.
