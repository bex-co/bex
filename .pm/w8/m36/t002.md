## Objective

Bind each fetched manifest to one real Git commit before reading its bytes, so branch movement cannot falsify sync provenance.

## Context

- Parent milestone: [w8/m36 — Blueprint Git source integrity](README.md), user-approved on 2026-09-08.
- fetchBlueprintFile currently fetches contents at the branch and then calls GetRepoCommitSHA; the branch can move between calls.
- Its fallback assigns a file/blob SHA to the commit field. GitHub's contents endpoint accepts a commit as the ref parameter.

## Steps

1. Resolve and validate the selected branch's commit before fetching manifest content; use that exact commit as the content ref.
2. Carry the resolved commit with the returned bytes through the existing BlueprintFetcher seam; remove blob-SHA-as-commit fallback.
3. Ensure implicit canonical/legacy filename discovery examines a consistent revision rather than independently moving branch tips.

## Acceptance criteria

- [ ] A branch advancing between requests cannot change the manifest read at the reported commit.
- [ ] Commit lookup failure or an empty/malformed commit ID is an actionable error, never fabricated provenance.
- [ ] Canonical/legacy filename discovery retains its explicit-path and ambiguity rules at one revision.
- [ ] Private and public repository fetches use the same revision contract.

## Out of scope

- Pinning every service build in a multi-repository Blueprint to the manifest repository's commit.
- Adding a preview approval token or changing Blueprint ownership.
