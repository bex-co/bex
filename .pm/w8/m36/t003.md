## Objective

Remove the stored-manifest fallback from Git-backed syncs, preserving deliberate supplied-manifest behavior and legacy non-Git behavior only where the existing contract actually supports it.

## Context

- Parent milestone: [w8/m36 — Blueprint Git source integrity](README.md), user-approved on 2026-09-08.
- runSync in lego/backend/internal/apps/blueprint.go swallows a Git fetch error and falls through to b.Manifest.
- w2/m62/t004 required a failed fetch to leave the stored manifest untouched and the run in error; invalid fetched YAML already has a preflight refusal path.

## Steps

1. Trace manual sync, initial create, and webhook-triggered sync through their common source-selection rules.
2. Return a sanitized failure when a Git-backed source cannot be fetched or its fetcher is unavailable; do not deploy the stored manifest as an implicit substitute.
3. Preserve explicit supplied YAML as the documented bex extension, with no invented commit ID, and retain approved legacy filename behavior.
4. Keep compilation, payment, authorization, and ownership checks ahead of workload mutations.

## Acceptance criteria

- [ ] Missing file, revoked access, timeout, and disabled fetcher on a Git-backed sync cause zero workload mutations.
- [ ] The last stored valid manifest is not replaced by an unavailable or invalid source.
- [ ] Explicit supplied-manifest sync remains usable and never claims a Git commit it did not consume.
- [ ] Existing protected-environment, billing, and ownership refusals still apply.

## Out of scope

- Automatic replay after partial application; m37 defines interruption handling.
- Changing supported Blueprint fields or creating new deployment products.
