# Deploy-hook 400s name REST body fields the caller never sent (`commitId`, `imageUrl`) instead of the hook's `ref`/`imgURL`

Why: a deploy hook is called from CI scripts with Render's `ref` and `imgURL` query parameters. When one is wrong, Bex answers with the authenticated trigger's field names. The person debugging a pipeline is told “commitId is not supported” about a parameter they spelled `ref`.

**Severity:** minor. **Attribution:** server. **Estimate:** 25m. **Source:** `/qa-find-bugs-cli` sweep 1239, 2026-10-20 ([evidence](evidence/cli-sweep1239/README.md)).

## Reproduction

Production `https://api.bex.co/v1/`, deployed pin `94533d795067`, workspace `bex-canary`. A free image-backed web service (`gcr.io/google-samples/hello-app:1.0`) was created with `bex services create`. Its secret hook URL came from `GET /v1/services/{id}/deploy-hook` (shape `https://api.bex.co/v1/deploy-hooks?key=<secret>`; the key is never recorded). The service was deleted afterwards (GET 404).

| Call (hook URL plus) | Actual | Expected (Render's [deploy-hook contract](https://render.com/docs/deploy-hooks)) |
| --- | --- | --- |
| `&ref=0123…4567` on an image service | 400 `bad request: commitId is not supported for image-backed services — deploy an image tag or digest with imageUrl` | 400 naming `ref` (“Invalid … `ref` parameter”) and pointing at `imgURL` |
| `&imgURL=docker.io/library/nginx:1.27` | 400 `… imageUrl must use the service's configured image gcr.io/google-samples/hello-app (got docker.io/library/nginx) …` | the same rule, naming `imgURL` |
| `&imgURL=gcr.io/google-samples/hello-app:not a tag` | 400 `bad request: imageUrl: image reference is malformed: invalid reference format` | the same, naming `imgURL` |

Controls on the same hook all matched the documented contract or recorded drift: GET and POST → 200 `{"deploy":{"id":"dep-…"}}`; PUT and DELETE → 405 with `Allow: GET, POST`; a same-repository `imgURL` tag deploys that tag while the saved image stays unchanged; a suspended service → 409; a wrong or missing key → 404 (ADR018's recorded uniform-404 drift); a burst → 429 with `Retry-After` (the documented 6/min, burst 2).

## Root cause

`lego/backend/internal/deploys/deployhook.go:374–377` maps the hook's `ref`/`imgURL` onto `TriggerParams{CommitID, ImageURL}` and writes `triggerFetched`'s error verbatim (`:378–380`). Those validation errors are phrased for the authenticated REST/GraphQL/MCP body: `service.go:652` (`commitId is not supported for image-backed services … with imageUrl`), `:680` (cron `commitId`), `:714` (`imageUrl must use the service's configured image …`), and the shared OCI-reference errors prefixed `imageUrl:` (malformed, uppercase repository, digest length, private/reserved address, untrusted registry; see `input_validation_test.go:40–46`).

## Fix

Keep one validation path, but let the caller's vocabulary name the field. Either thread the field names through `TriggerParams` (the hook passes `ref`/`imgURL`; REST, GraphQL and MCP keep `commitId`/`imageUrl`), or have the hook handler rewrite only those two field tokens in a `core.ErrBadRequest` message before writing it. Status codes, rule text, and the REST/GraphQL/MCP messages stay byte-identical.

## Acceptance

- A handler test drives the hook with `ref` on an image service and on a cron job, plus `imgURL` for a different repository, a malformed reference, an untrusted registry and a short digest. Every 400 names `ref`/`imgURL` and never `commitId`/`imageUrl`.
- `input_validation_test.go` keeps its REST/GraphQL/MCP expectations unchanged.
- Live after deploy: the three table rows above answer with the hook's parameter names.

## Dedupe

`rg -i 'deploy.hook' .pm` with `imgURL`/`ref`: the matches are w2/m33 (the hook itself) and ADR018's “Secret deploy hook” row, which records the 404, path and management drift but not the error vocabulary. No open item.
