# A static site's default `Cache-Control` is `public, max-age=0, must-revalidate`, where Render's static sites send `public, max-age=0, s-maxage=300` on pages, hashed assets and the `404.html` miss alike

Why: Render's static sites with no `Cache-Control` rule send `public, max-age=0, s-maxage=300`, but bex sends `public, max-age=0, must-revalidate` on the same files. w4/m160 picked its value without a Render probe, and no ADR018 sign-off records the difference, so a site moved from Render changes its caching headers.

- Severity: minor. Browsers revalidate on every use under both values. What differs is what shared caches and offline clients may do: Render lets a shared cache (a proxy, or the owner's own CDN in front of a custom domain) keep a response 300 s, and `must-revalidate` forbids serving a stale copy.
- Versions: production `https://*.onbex.co` on 2026-11-20 20:15–20:20 UTC. `lego/operator/internal/staticserver/staticserver.go:1232` is unchanged at main `3d2522f0d`. bex CLI v0.7.0 (Render CLI v2.36.0) created the fixture.
- Context: routine `cli-qa` run `r17-0f97`, QA human device-flow token, workspace `bex-canary`. Run-owned free static site `qa-20261120-0f97-st` (`srv-dc0ahnli534c73chvglg`, from `octocat/Spoon-Knife` with a build command writing `out/404.html`, `out/docs/index.html`, `out/assets/app.4f9c2b1e.js` and `out/assets/main-B7xQ9kLp.css`), deleted afterwards.

`wc3v.onrender.com` sends `public, max-age=0, must-revalidate`, but only because its `render.yaml` sets that value as a header rule (its comment says Render's default "caused stale-content reports after deploys"). The same `s-maxage=300` value was seen on six Render demos in w4/341 (2026-10-19), on `create-react-app.onrender.com` in w8/194 (2026-10-23) and on `buzz-docs` in w8/322. Each time it was recorded as a Render control and never compared with bex's default.

## Cause

`defaultCacheControl` (`lego/operator/internal/staticserver/staticserver.go:1232`) is `public, max-age=0, must-revalidate`. `setFileHeaders` (`:489`) sets it on every published file, directory index, rewrite target, SPA fallback and the `404.html` miss page before the site's own rules. w4/m160's finding says outright that "no authenticated Render site or exact default header policy was probed". It chose revalidation to fix the old one-year `immutable` default, and Render's `max-age=0` already gives that.

## Fix

Set `defaultCacheControl` to `public, max-age=0, s-maxage=300`. Keep everything else: the ETag and 304 revalidation (w4/341), a site's `Cache-Control` rule replacing the default, and no default on bare 404s, redirects or errors. m160's guarantee still holds, because `max-age=0` makes a browser revalidate before reuse and the ETag changes with the bytes. bex puts no shared cache in front of static sites (the edge cache, `internal/controller/edge_cache.go`, is for web services only), so nothing on bex holds a site for 300 s. Update ADR029's "Browser freshness across deployments" paragraph and its tests: `revalidation_test.go:30`, `not_found_page_test.go:51`, and every assertion of the old string.

Blast radius: one static-server binary serves every static site. REST, GraphQL, MCP and the dashboard expose no default header. The `bex-deploy` skill asset's explicit `no-cache, no-store, must-revalidate` rule is a customer rule and stays.

## Acceptance

- On a free static site with no header rules, `/`, a hashed asset, a directory index, an SPA fallback and the `404.html` miss each send `cache-control: public, max-age=0, s-maxage=300`.
- `If-None-Match: <etag>` still answers 304, and a republish still serves new bytes to the next normal fetch.
- A `/assets/*` → `Cache-Control: public, max-age=31536000, immutable` rule still replaces the default.
- A bare 404 (no `404.html`) still sends no `cache-control`, as on Render.

## Not verified

Whether Render's own CDN honors `s-maxage=300` between deploys. Its docs say deploys invalidate the CDN at once, and bex has no CDN tier to match. Render also Brotli-encodes static bodies under 1 KiB (a 14-byte 404, a 62-byte `robots.txt`), where bex starts at `minBrotliBytes = 1024` (`staticserver/encoding.go:46`). That is a separate, smaller difference and is not filed here.

Dedupe: `rg -i s-maxage .pm docs` finds it only as a Render control value in w4/341, w8/194 and w8/322, and in w5/m151's web-service edge-cache rules. No item or ADR018 row covers the static default. `.pm/DO_NOT_DO.md` excludes only a static CDN purge API.
