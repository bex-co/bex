# Blueprint parser loses explicit empty env-value presence

Why: Retaining whether a manifest supplies an empty value restores valid seeded copies and makes conflicting value-generation declarations fail consistently.

**Current status:** todo — 25m remaining acceptance review. Production native validation now passes; hosted apply and remaining surface checks are still required.

**Status:** todo. **Worker:** worker8. **Severity:** minor. **Attribution:** Bex server Blueprint parser. **Estimate:** 55m. Preserve literal-value presence in the existing decoder, seed classification and generation-conflict checks; no CLI fork or upstream change.

## Reproduction and versions

Functional CLI sweep143, 2026-10-11, production `https://api.bex.co/v1/`, isolated human OAuth in `bex-canary` / `tea-daif693dqjvc73e7as3g`. Actual released Bex v0.3.2 (`a6350da0d6e451e063143432e06c548ba7b5851b`) and unmodified Render v2.27.0 at `a764810a768202704e7206eb7b87a47211fcd98e` both target Bex. Diagnosis HEAD `ab2a07ad26f3076d621816da7f1eebf6db08f69f`; deployed revision unobserved. No Render-production validation or hosting-resource apply was performed.

The [exact readable reproduction](evidence/092/repro.yaml.txt) declares two fresh-named Free image services. The caller precedes its target:

```yaml
services:
  - name: qa143-544da4-caller
    type: web
    runtime: image
    plan: free
    image:
      url: docker.io/mendhak/http-https-echo@sha256:440ca6b810bc04606aac700e461caca5543eaa882c4e0af96a33424d05a23592
    envVars:
      - key: COPY_VALUE
        fromService:
          name: qa143-544da4-target
          type: web
          envVarKey: SOURCE_VALUE
  - name: qa143-544da4-target
    type: web
    runtime: image
    plan: free
    image:
      url: docker.io/mendhak/http-https-echo@sha256:440ca6b810bc04606aac700e461caca5543eaa882c4e0af96a33424d05a23592
    envVars:
      - key: SOURCE_VALUE
        value: ""
        sync: false
```

```sh
bex blueprints validate repro.yaml --confirm -o json
render blueprints validate repro.yaml --confirm -o json
```

Expected under [Bex's presence-aware manifest contract](../../docs/ADR049-render-yaml-parity.md#d5--sync-is-presence-aware-and-field-specific): the explicitly declared empty string is a known seed value, and the sibling copy is empty. The existing [seed-once objective](../w1/done/m35/done/t003.md) and [copy objective](../w1/done/m35/done/t004.md) also apply to literal values. The [Render reference](https://render.com/docs/blueprint-spec#setting-environment-variables) documents these reference and sync forms; whether Render production accepts this exact combination was not tested. The pinned-schema compiler and Bex provider-only control both accept the explicit-empty declaration.

Actual: both native commands exit1, return `valid:false`, and report:

```text
fromService.envVarKey references env "SOURCE_VALUE" on service
"qa143-544da4-target", which has no such plainly-defined variable
```

The key and value are present. Removing `sync: false`, replacing `""` with one space or a nonempty string, or removing the caller's reference makes validation succeed. Reversing declaration order does not repair the empty-seed failure. Root, `ungrouped.services`, and project/environment-nested declarations all reproduce.

[Thirty actual native cases](evidence/092/native.json), [matrix driver](evidence/092/native-driver.py.txt), [readable-YAML driver](evidence/092/yaml-driver.py.txt): ten explicit-empty seeded-copy cases fail across two clients and three containers, including reversed root order and ordinary YAML. Eighteen positive controls pass; two genuinely omitted-value prompt-copy controls correctly fail. All processes complete normally, with empty native stderr. The first 24 manifests use JSON syntax accepted as YAML; the final six use ordinary YAML. An initial PyYAML batch accidentally emitted aliases for a reused image object, which the product correctly refused; all six initial cases are retained separately and excluded. Corrected ordinary YAML has independent image objects and no aliases.

## Producer, consumers and scoped correction

- `lego/backend/internal/apps/deploy.go:448–455` stores `bexEnvVar.Value` as a string. Its existing numeric-compatible `UnmarshalJSON:464–481` reads `json.RawMessage`, but retains no distinction between an omitted value and a literal empty string. The strict compiler's IR still preserves that distinction.
- `parseService:2409–2417` classifies `sync:false` using **`e.Value != ""`**. An explicit blank goes into `promptKeys`, stays absent from `seedLiterals` and `known`, and receives a known value only if a separate `envVarValues` entry is supplied. Plain empty literals take the separate default branch and are correctly present in `known`.
- `parseCompiledStack:1895–1910` has the sole production `parseService` call and records this map in the shared index. `resolveRef:2715–2733` correctly distinguishes a missing map entry from a present empty value, but receives the wrong map and rejects the sibling copy. The copy lookup should retain this distinction.
- The same classification supplies seed-once apply at `deploy.go:967–975` and prompt-value admission at `1700–1718`. These are source-traced consumers; no production apply or runtime seeding failure is claimed.
- [Caller census](evidence/092/callers.json): four direct `parseCompiledStack` call sites (validation, compileStack, generated-manifest verification, disconnect grouping reclamation), five `compileStack` calls, one `parseService` call. REST `rest.go:1346`, GraphQL `graphql.go:1259` and MCP `mcp.go:1024` share `ValidateBlueprint`; preview/create/manual and automatic sync also reach the shared preparation. GraphQL/MCP/dashboard and post-change hosted apply remain unexercised in this sweep.

The [actual compiler/parser probe](evidence/092/parser-probe.json), [virtual test source](evidence/092/parser-probe_test.go.txt), [overlay](evidence/092/probe-overlay.json), [complete output](evidence/092/parser-probe.log.txt) run existing code under Go1.27.0. All six documents pass the compiler. Explicit-empty and omitted unreferenced seeds both become a prompt with no seed entry, despite different IR presence. A plain empty copy and one-space seed copy work. Supplying an explicitly empty `envVarValues` override makes the failing copy work and creates an empty seed entry. This is an isolated diagnostic probe of current behavior, not a fix, full suite or committed regression test.

Record valid literal-value presence in the **existing** `bexEnvVar.UnmarshalJSON` and use it in the seed branch instead of nonempty-string testing. A declared valid `""` must enter both `seedLiterals` and `known`; genuinely omitted values remain prompts. Preserve numeric conversion, explicit prompt overrides, seed-once retention, generated values and reference classification. Keep the canonical schema and all client request shapes. Do not change the copy lookup to silently accept genuinely missing values. Review preview prompt metadata as a neighbor; this finding does not assert that its current all-sync:false key list is itself repaired by the parser change.
