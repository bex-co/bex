## Pin and rollout (added 2026-10-31 from t008)

t008 publishes the per-major bex operands; this task adopts them, which is the rollout ADR092 D4 approved:

- Review each published digest: gate log for both platforms, signature, SBOM. Then pin it in `bexOperandImages` (`lego/operator/internal/controller/database_operand.go`) in one reviewed commit per batch.
- Before the restart, list every production database's `datcollate`/`datctype`/`datlocprovider` (the bullseye → bookworm base moves glibc). Anything other than `C`/`C.UTF-8` gets a reindex plan first.
- Run it off-peak, with per-cluster health checks before and after, and record the previous digests as the rollback.

**Pre-rollout inventory — 2026-10-31 (read-only, production):**

- Five tenant clusters. Four are unversioned Databases (`spec.version` empty, `status.currentVersion` 18) on CNPG's default `18.4-system-trixie`; one is pinned PG14.
- Every database in all five, the `postgres` DBs included, is `C/C`, with no user collations and no columns using a libc collation. So the trixie/bullseye → bookworm glibc move needs no reindex.
- Unversioned Databases now join their running major's bex operand only when it is adopted, through `unversionedOperandImage`. Without that they would have been left without extensions.
- The pin deploys through `deploy.yml`, which is red until the onbex.co fallback certificate is renewed (w10/010, w4/441). Production adoption waits on that.
