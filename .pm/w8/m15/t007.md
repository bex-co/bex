## Objective

Replace the unmetered Traefik TCP route for public Key Value connections with a TLS/SNI pass-through proxy that preserves allowlist behavior and exports backend-to-client bytes by KeyValue resource.

## Context

- Traefik's documented Prometheus byte metrics are HTTP-only; its TCP routes do not expose per-service response bytes.
- Public Valkey currently uses an `IngressRouteTCP` on the `valkey` entrypoint.
- The new front door must preserve end-to-end TLS, SNI routing, source-IP allowlists, and existing connection coordinates.

## Steps

1. Add a KeyValue watcher/router and bounded TLS ClientHello/SNI parsing using the proven proxy scaffolding.
2. Preserve IP allowlists and route public traffic through the proxy in base/prod configurations.
3. Export backend-to-client bytes and internal health metrics per KeyValue.

## Acceptance criteria

- [ ] Existing TLS clients connect through the same public hostname and credentials.
- [ ] Allowlisted and denied source behavior is unchanged.
- [ ] Only backend-to-client bytes attribute to the owning KeyValue.

## Out of scope

- Protocol termination, plaintext inspection, or new public API fields.
