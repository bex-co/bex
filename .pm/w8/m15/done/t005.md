## Objective

Deploy one node meter per tenant-capable node, grant only the host mounts/capabilities and Kubernetes reads it needs, scrape it in Prometheus, and alert when accounting is incomplete.

## Context

- The meter is privileged infrastructure and must not inherit the manager's broad controller permissions.
- Production schedules tenant workloads on worker pools; control-plane-only deployment would miss traffic.
- Missing scrape targets, map pressure, or attachment failures must block the affected meter window.

## Steps

1. Add dedicated ServiceAccount/RBAC, DaemonSet, Service, PSS exception, scheduling, and resource bounds.
2. Add Prometheus discovery/relabeling and retain only required metric families.
3. Add tested alerts for missing targets and loss/reset health signals.

## Acceptance criteria

- [x] Every tenant-capable node has one Ready meter pod.
- [x] The container has no unnecessary Kubernetes verbs, host mounts, or capabilities.
- [x] Prometheus and alert-rule tests fail on a missing or unhealthy meter.

## Out of scope

- Hourly collector composition and cap enforcement.
