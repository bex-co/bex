## Objective

Count bytes written from an App-backed WebSocket connection to the public client after HTTP upgrade, attributed to the exact App router, without counting the private App→edge hop or client→App frames.

## Context

- Traefik labels WebSocket handshakes with `protocol="websocket"`, but its response-size capture wraps `ResponseWriter.Write`; after `Hijack` it returns the raw `net.Conn`, so downstream frames bypass `traefik_router_responses_bytes_total`.
- The node meter on the App pod sees only the App→Traefik private hop and must exclude it to avoid charging private traffic.
- Attribution must survive long-lived connections, disconnects, edge restarts, and multiple App routers sharing the same Traefik process.

## Steps

1. Select and prove a bounded edge wrapper that intercepts writes on hijacked connections while preserving WebSocket behavior and exact router identity.
2. Export monotonic downstream-byte and source-health counters with bounded labels.
3. Add the counter to Prometheus scraping and validate downstream-only direction, close/error handling, and resets.

## Acceptance criteria

- [ ] WebSocket server→client frames increase exactly one App's downstream counter.
- [ ] Client→server frames, handshake HTTP bytes, and the private backend hop are not double counted.
- [ ] Upgrade failure, normal close, abrupt disconnect, and edge restart expose deterministic delta/reset behavior.

## Out of scope

- General TCP proxying, direct service egress, or datastore protocols.
