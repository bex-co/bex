## Objective

Instrument the existing Postgres SNI proxy's backend-to-client copy path with a monotonic counter attributed to the resolved Database and expose it for Prometheus.

## Context

- `lego/operator/cmd/pg-sni-proxy` already resolves every public connection to a Database and owns the public `:5432` path.
- Only bytes copied from backend to client are outbound; client requests must not be counted.
- Read-only and pooler hostnames must roll up to the parent Database resource.

## Steps

1. Return structured Database identity from routing and count the backend-to-client copy result.
2. Expose health and response-byte counters on an internal metrics listener.
3. Scrape/relabel the proxy without exposing its metrics publicly.

## Files

- `lego/operator/cmd/pg-sni-proxy/main.go`
- `lego/operator/cmd/pg-sni-proxy/main_test.go`
- `lego/operator/config/pg-sni-proxy/`
- `deploy/gitops/base/prometheus.yaml`

## Acceptance criteria

- [ ] RW, pooler, and replica response bytes attribute to one Database.
- [ ] Request bytes and failed/unrouted handshakes contribute zero.
- [ ] Concurrent connections update race-free monotonic counters.

## Out of scope

- Valkey and App direct egress.
