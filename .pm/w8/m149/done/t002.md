## Objective

`GET /v1/projects` with no `ownerId` (and `?name=` with no `ownerId`) returns matching projects from every workspace the caller belongs to, in one stable cursor order. The pinned CLI's `ResolveProject` and `ListAllAccessibleProjects` then find a project or environment in the active non-default workspace, and refuse an environment name present in two workspaces as ambiguous. See finding F2 in the milestone README.

## Context

- `lego/backend/internal/projects/rest.go:120-128` → `listBare(ctx, "")` → `WorkspaceOrDefault`.
- Pinned consumer (Render CLI v2.35.0, `go list -m -f '{{.Dir}}' github.com/render-oss/cli` from `lego/cli`): `pkg/resolve/resolve.go` `ResolveScope`/`ResolveProject`/`candidateProjectsForEnvironmentLookup`, and `pkg/project/repo.go` `ListProjectsByName`/`ListAllAccessibleProjects`.
- Reusable pattern: `apps/rest.go:1815-1828` `listOverrideApps` (`MemberWorkspaceIDs` + `core.ListOwners`), w8/191.
- Paging: `core.StablePage` must page the merged list by project id, so a cursor continues across workspaces.

## Steps

1. When `ownerId` is absent and the caller is identified, list projects over `MemberWorkspaceIDs`. Keep `ownerId` as an exact filter.
2. Check `GET /v1/environments` (requires `projectId`, so no change) and any project-scoped resolver the CLI calls next.
3. Record the change in ADR006 alongside w4/475's note.

## Done — 2026-11-10
