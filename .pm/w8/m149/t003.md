## Objective

Apply t002's rule to every REST list whose pinned spec makes `ownerId` optional. With no `ownerId`, return the union of the caller's member workspaces in stable cursor order. With `ownerId`, return exactly the named workspaces. Retire the "omitted `ownerId` = default workspace" wording for lists.

## Context

- Pinned list routes that take `ownerId` (from `lego/backend/internal/api/openapi/render-public-api-1.json`): `/services`, `/postgres`, `/key-value`, `/redis`, `/projects` (t002), `/env-groups`, `/blueprints`, `/disks` (t001 adds the filter), `/registrycredentials`, `/webhooks`, `/notification-settings/overrides` (already spans, w8/191). `/logs*`, `/sandboxes` and `/dedicated-ips` require `ownerId` and are unaffected.
- Shared helpers: `core.ListOwners`, `core.EnvironmentOwners` (`internal/core/pagination.go:84-137`), `listOverrideApps` (`apps/rest.go:1815`).
- Internal REST callers that omit `ownerId` and may rely on the default: the mobile app's REST reads (ADR018 notifications row, w6/m140 keeps omission = default for **its** notification routes, not Render lists), `scripts/*`, and the CLI launcher. The dashboard uses GraphQL. Audit them before the change.
- AGENTS.md (`lego/backend/AGENTS.md`, "Workspace from request context") says "Empty → the default workspace for `List`". Update it.

## Steps

1. Introduce one helper (for example `core.ListMemberOwners`) that resolves owners: explicit `ownerId` → those; otherwise the caller's member workspaces; no identity/membership source → the default (today's behavior).
2. Route each list above through it.
3. Amend ADR006 (lists section and w4/475's note), ADR018 (rows that mention default-workspace list scope), and `lego/backend/AGENTS.md`.
