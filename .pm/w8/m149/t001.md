## Objective

`GET /v1/disks?ownerId=…` lists only the named workspaces' disks, as Render's `list-disks` does. A workspace the caller is not a member of answers 403, as `GET /v1/services` does. See finding F1 in the milestone README.

## Context

- `lego/backend/internal/apps/disks.go:376-450`: the list handler never reads `ownerId`. Its no-`serviceId` branch calls `ListDisks(ctx, "")` (`:142-168`), which lists `s.WorkspaceOrDefault(ctx)`.
- Pattern: `apps/rest.go:845-846` (`core.EnvironmentOwners` + `core.ListOwners(ctx, owners, s.List)`) and `keyvalue/rest.go:306`.
- With `serviceId` and `ownerId` together, keep the per-service authorization and drop disks whose service is outside the named owners (intersection, as services' `ownerId`+`environmentId` do).
- GraphQL `disks` (`disks.go:544-552`) has no `ownerId` argument. Add Render-style optional `ownerId` (`gqlutil` owned-list pattern) so GraphQL can express the same filter. MCP `list_disks` already scopes by the session `workspaceId`.

## Steps

1. Read `core.QueryList(q, "ownerId")` in the handler and list through `core.ListOwners` with a closure over `ListDisks(ctx, "")` under `core.WithWorkspace`, or give `ListDisks` an owner argument.
2. Intersect with `serviceId`, `diskId`, `name` and the time windows as today.
3. Add the GraphQL `ownerId` argument.
