# `bex keyvalues create --confirm -o text` (and `bex kv create`) prints `Created Render Key Value` instead of `Created Bex Key Value`

Why: user decision D2=A (2026-11-11, `w2/073`, `w2/082`) establishes that upstream product-name prose on stdout reads Bex in exact phrases; `keyvalues create` was missed from `branding.runtimeStdout` and `branding.runtimeProse`, so text and interactive creation output still announces `Created Render Key Value`.

- Severity: **minor** (product-name branding leak on stdout; JSON/YAML output and server behavior are unaffected).
- Versions: checkout build of `lego/cli` at `ac882b5f55` (compatible with Render CLI `v2.37.0`, upstream pin `11ef59f330dedec290f8d71d89b8f7379bbbed09`); unchanged through `f68b234111`.
- Context: 2026-11-23 10:49 UTC, `https://api.bex.co/v1/`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), QA human device login, non-TTY `-o text`.
- Source: routine `cli-qa` sweep `c8a2`.

## Attribution and root cause

- Attribution: **Bex launcher** (`lego/cli/internal/branding/runtime.go`).
- Upstream consumer (`github.com/render-oss/cli@v1.1.3-0.20261117005113-11ef59f330de/cmd/kvcreate.go:140-145`): `kvCreateSuccessMessage` returns `"Created Render Key Value\n\n%s\n"` for all three non-JSON/YAML paths (`-o text` at `:102`, `--confirm` at `:136`, and interactive wizard completion at `:123`).
- In `lego/cli/internal/branding/runtime.go`:
  - `runtimeProse` (`:58-64`) contains the exact phrases from `cmd/logout.go` and `pkg/blueprint/output.go`, but not `"Created Render Key Value"`.
  - `runtimeStdout` (`:139-147`) wraps `ea blueprints create|plan|approve|update`, `logout`, and `postgres create`, but does not include `"keyvalues create"` (Cobra's `CommandPath()` is `"bex keyvalues create"` for both `keyvalues` and its `kv` alias).

## Fix

- In `lego/cli/internal/branding/runtime.go`:
  - Add `"keyvalues create"` to `runtimeStdout` using a mode (or dedicated prefix/prose mode) that rewrites only the exact leading heading `"Created Render Key Value\n\n"` → `"Created Bex Key Value\n\n"` on text/interactive output while keeping `keepTerminal` for the interactive wizard (`views.RunKeyValueCreate` at `cmd/kvcreate.go:114`) and leaving `-o json` / `-o yaml` and all API data fields (including a Key Value named `render-…` or containing `"Created Render Key Value"`) byte-exact.
  - Note: do **not** apply `plainOutput` wholesale to `keyvalues create -o text`, because the body prints API data (instance/workspace/project/environment names). Scoping the rewrite to the exact heading prefix `"Created Render Key Value\n\n"` (or text/interactive only) preserves API data untouched.
- Update `docs/bex-cli.md` § Compatibility and branding limits (`runtimeStdout` list and `runtimeProse` exact-phrase list) and `lego/cli/UPSTREAM_RENDER_CLI.md` run-time copy re-diff checklist to include `cmd/kvcreate.go:142`.
- Keep all upstream non-served/residual strings documented in `docs/bex-cli.md` untouched (workflows, automatic `LoginView`, User-Agent).
