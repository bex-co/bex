# A static site whose root directory is set and then cleared reads "saved changes aren't live yet", though nothing it serves differs

Why: after a root-directory save that nets out to the published settings, a static site keeps `undeployedChanges: true` (reason `saved`) indefinitely. The dashboard banner then tells the owner to deploy changes that do not exist. A web service given the same save reads `false`.

- **Found by:** w8/m460 t008's production replay, 2026-11-19, pin `4b2cebd0bd03`, bex CLI v0.7.0, `bex-canary`.
- **Evidence (production):**
  - Static site `qa-20261119-d623-rd` (`srv-dbvc9ufh83kc738vm1fg`, deleted) ran `bex services update --root-directory sub`, then `--root-directory ''`, during its first build. The deploy went `live` with one deploy row and no rebuild. GraphQL then read `{"phase":"Running","publishPath":"out","rootDir":"","revision":"rev-1","undeployedChanges":true,"undeployedChangesReason":"saved"}` at settle and still 80 s later.
  - The same save during a non-first deploy (`qa-20261119-d623-none`, `rev-2`) gave the same answer.
  - Control: native web service `qa-20261119-d623-web` with the identical mid-build save read `undeployedChanges: false` after going live.
- **Cause (code):**
  - `PATCH /v1/services` with `rootDir` runs `SetRootDir`, which also bumps `spec.restartedAt` (`lego/backend/internal/apps/service.go:5034`). `SetPublishPath` does the same (`:6621`).
  - w8/m460's `staticSaveWaits` (`lego/operator/internal/controller/saved_configuration.go:131-134`) compares `desiredAppReleaseIdentity(app.Spec).release` with `status.releaseFingerprint`. Both the artifact and release identities include `RestartedAt` (`release_identity.go:169`, `:229`), so a set-and-clear never matches again until a deploy.
  - The web path compares saved settings through `releaseSettingsFingerprint`, which drops the restart stamp and commit (`settingsIdentitySpec`, `release_identity.go:246`). Static publications keep no release record to compare against (the comment in `reconcileSavedConfigurationStatus`).
  - m460's envtest `save` helper (`static_first_release_save_envtest_test.go:95`) stamps `pending-source-generation` but not `restartedAt`, so the "root directory set, then cleared" case passed in envtest.
- **Inferred, not run:** a publish-directory save that is reverted (`out` → `out2` → `out`) reads the same way, since `SetPublishPath` bumps the same stamp.
- **Fix direction:** record the settings fingerprint of the release a static site dispatches (a status field or an annotation next to `releaseFingerprint`). `staticSaveWaits` then compares `releaseSettingsFingerprint(spec)` with it, and falls back to today's comparison when it is empty. Make the envtest `save` helper bump `restartedAt` as bex-api does for root-directory and publish-directory saves.
- **End state:** on production, a static site's root-directory set-and-clear during its first build, and during a later build, settles `Running` with `undeployedChanges: false`. A real publish-directory save still reads `saved` until a deploy publishes it (m460's site A: `out2`, cleared by the next deploy).
