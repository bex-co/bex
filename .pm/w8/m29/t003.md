## Objective

Stop `bex docs` from opening render.com, and make `bex -v` lead as a Bex release rather than a Render-compatible binary first.

## Context

- Upstream `cmd/docs.go` opens `https://render.com/docs` client-side (graded in `docs/cli-compatibility-checklist.md`).
- Bex has no `docs.bex.co` yet; sensible destinations: GitHub repo docs (`https://github.com/bex-co/bex` or a deep link to `docs/bex-cli.md` on `main`) or `https://dashboard.bex.co`. Prefer a stable public URL — document the choice.
- `lego/cli/main.go` `printVersion` currently: `bex v%s (Render CLI v%s compatible)`. Compatibility remains true; move or soften the Render clause so the product line is bex-first (e.g. lead with `bex vX.Y.Z` only, or put compatibility on a second line / help DETAILS).

## Steps

1. Locate the `docs` command on `RootCmd` by name; override `Short`/`Long`/`Example`/`RunE` to open the chosen Bex URL (reuse upstream `dashboard.Open` if exported, or `browser`/OS open consistent with existing patterns — do not vendor docs.go).
2. Soften `printVersion` copy; keep `cfg.Version` available for compatibility mention if retained.
3. Update any test that asserts the old version string (`lego/cli/main_test.go`).

## Files

- `lego/cli/main.go`
