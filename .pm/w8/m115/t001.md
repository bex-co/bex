## Objective

Traefik access lines for requests its IPAllowList middleware refuses (HTTP 403 before routing) never reach the owning service's `type=request` history. Make the log-shipper attribute those lines to the App they targeted, so the refusal is queryable like any other request line — without weakening tenant isolation or the label cardinality budget.

## Context

- Live reproduction (sweep458): own free web service with `--ip-allow-list cidr=203.0.113.7/32`; two curls at 03:59:00Z answer 403; 90 s later `logs --type request --status-code 403`, `--path /qa458blocked`, and unfiltered history contain only subsequent 200s; `/v1/logs/values?label=statusCode` offers only `["200"]`.
- Root-cause locus: [the request_logs pipeline](../../../deploy/gitops/base/log-shipper.yaml) (~lines 873–1048). Two conjunctive gates can drop a middleware-rejected line: `stage.match` drops any line without `ServiceName` (`not_an_access_line`), and attribution requires the `ServiceName` tenant regex (`^(tea-[a-z0-9]{20}|default)-(.+)-\d+@kubernetes$`, `KubernetesIngressName` preferred only when the regex already matched), else `should_drop` (`not_a_tenant_app`). A middleware short-circuit may emit no/empty `ServiceName`, or a selected-service name while `OriginStatus` is 0 — determine the actual emitted shape first (Traefik pod stdout or the Alloy `loki_process_dropped_entries_total` counters by reason) and fix the gate that actually drops it.
- Attribution inputs already on the line: `KubernetesIngressName` (the App CR name — the operator names each App's Ingress after it), `KubernetesIngressNamespace`, `RequestHost`. Any new attribution path must remain a closed, App-derived vocabulary: the namespace regex stays anchored; never attribute by bare `RequestHost` alone (an attacker-controlled header value would let one tenant's noise land in another's history — the pipeline's existing "a wrong label only hides a line" property must be preserved, so the safe key is ingress name+namespace from Traefik's own routing record, not client input).
- Contrast receipt (sweep462): an app-generated 404 (static site `/missing462`) DOES reach `type=request` and matches `--status-code 404` — the gap is specific to lines Traefik itself answers before routing to a service, not to non-200 statuses generally.
- Query side needs no change in expectation: `lego/backend/internal/logs` reads `{type="request", namespace, app, status, method}` from Loki ([ADR010](../../../docs/ADR010-observability.md)); a correctly labeled line surfaces on REST/GraphQL/MCP and the dashboard unchanged. Confirm the rejected line's `DownstreamStatus` maps to the `status` label (403), and that `OriginStatus` 0/absent does not break the JSON stage.

## Steps

1. Capture the raw Traefik JSON line(s) for an IPAllowList refusal in a local/dev stack (or read the production Alloy drop counters by reason) and record which gate drops it.
2. Extend the pipeline so a refused line with trustworthy ingress attribution is labeled `namespace`/`app` of its target App and forwarded; keep every existing drop for genuinely non-App, non-platform lines.
3. Re-run the shipper's maintained config tests/helpers; keep label set identical (`namespace`, `app`, `service`, `method`, `status`, `type`) — no new labels.

## Out of scope

- Cloudflare/edge rejections that never reach Traefik.
