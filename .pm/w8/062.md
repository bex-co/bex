# 062 — Static `routes`/`headers` REST answers bare `{type,source,destination}` / `{path,name,value}`: no `{route|header, cursor}` envelope and no `id`/`priority`, unlike Render's contract

Why: Render's `list-routes`/`list-headers` return `routeWithCursor`/`headerWithCursor` (`{route: {id, type, source, destination, priority}, cursor}`), and `put-routes`/`update-headers` return `route`/`header` objects carrying `id` (and `priority` for routes). bex answers flat items with none of those keys. A generated Render client reading `.route.source` gets an empty value for every item, and no client can identify a rule (`id`) or read its order (`priority`), which also blocks any future per-rule verbs (ADR018:414). The behavior itself is right: redirects, rewrites and headers serve correctly.

Severity: minor. Attribution: server (`lego/backend/internal/apps`).

## Evidence (2026-10-06, `/qa-find-bugs-cli` w8 loop, sweep 43)

Production (pin containing `0903a31b6`), workspace `bex-canary`, human device login, REST with the CLI's token (read privately), User-Agent `render-cli/2.27.0`. Fixture: free static site `qa-20261006-5a87a7-st` (`srv-db25bv7pn68c73ec586g`, `examples/static-site`, deleted).

```text
PUT /v1/services/{id}/routes [{redirect /qa-old → /}, {redirect /blog/* → /posts/:splat}, {rewrite /app/* → /index.html}]
→ 200, items keys ['destination','source','type']                    # Render `route`: id, type, source, destination, priority (all required)
GET /v1/services/{id}/routes  → items keys ['destination','source','type'] (no 'route'/'cursor' envelope)   # Render: routeWithCursor
GET /v1/services/{id}/headers → items keys ['name','path','value']                                          # Render: headerWithCursor {header:{id,…},cursor}
jsonschema 4.23 vs pinned `route`/`header`: $[*] required (missing id, priority / id)

Served behavior (control, correct):
/qa-old → 301 Location https://…/            /blog/hello → 301 …/posts/hello
/app/deep/link → 200 (rewrite)               /missing.html → 404        every path carries X-QA-Mark: qa43
```

Validation (control, correct): `source: "no-slash"` → 400 `routes[0].source must be a path starting with /`. An external destination → 400. Header name `Bad Header` → 400 `not a valid HTTP header name`. Unknown `type` → 400.

Also observed, not part of this note's claim: a self-redirect `{redirect /loop → /loop}` is accepted (200). Whether Render refuses redirect loops was not verified, so it is recorded only as a candidate check for whoever picks this up.

## Mechanism

- `lego/backend/internal/apps/rest.go:1252-1255` mounts `GET`/`PUT` for `/{id}/routes` and `/{id}/headers`. `apps/render.go:720-732` (`toRenderRoutes`/`toRenderHeaders`) only nil-coalesces `[]StaticRouteView`/`[]StaticHeaderView`. There is no envelope and no id/priority.
- Routes and headers live on the App CR spec as plain lists (`service.go:4902-4960`), so they have no stable identity today.
- `internal/api/conformance_allowlist_test.go` has no entry for `list-routes`/`put-routes`/`list-headers`/`update-headers`, and `TestRenderConformance` does not seed a static site with rules, so the drift is unseen.

## Fix

- Give each rule a stable id (for example a `rte-`/`hdr-` id minted via `lego/backend/internal/id` and stored on the CR entry, or a deterministic derivation from (index, content) if a stored id is undesirable). Expose `priority` as the list index.
- REST `GET`: wrap items as `{route|header: {...}, cursor}`. REST `PUT`: return `route`/`header` objects with `id` (+`priority`). GraphQL/MCP may keep their shapes, as documented in ADR018.
- Add conformance coverage: seed a static site with one route and one header, and validate all four operations.

## Acceptance

- [ ] `GET /v1/services/<static>/routes` validates against `[routeWithCursor]`, and `GET …/headers` against `[headerWithCursor]`. `PUT` responses validate against `[route]`/`[header]`, with ids stable across a no-op re-PUT of the same list.
- [ ] Served behavior is unchanged: 301 redirect with `:splat`, 200 rewrite, header on every matching path, existing objects win over rules (ADR029).
- [ ] Controls: GraphQL `setStaticRoutes`/`setStaticHeaders` and the MCP tools are unchanged. Dashboard Redirects/Headers editors still round-trip.

## Dedupe

ADR018:414 records only the missing per-rule verbs (add/patch/delete route, add/delete header), not the list/PUT response shape. `rg -i 'routeWithCursor|headerWithCursor' .pm docs` found nothing. w4/204 (`Content-Length` header rule takes the site down) is a different behavior bug.

Estimate: ~50m.
