# Native runtimes lack `prince` (PrinceXML), which Render's native tools table lists as available at build and runtime in every native runtime

Why: an app that renders HTML to PDF with Prince (`prince in.html -o out.pdf`, or a library that shells out to it) builds and runs on Render's native runtimes with no setup, but on bex the build or request fails with `prince: command not found`. It is the one entry in Render's tools table that w8/m91's tool milestones never mapped.

**Severity:** minor (a niche tool, but a hard failure for the apps that use it, and the only workaround is moving the service to Docker). **Attribution:** build (the native common image). **Source:** `/qa-find-bugs-cli` sweep `d40a`, 2026-11-16, production pin `7aaa8700befa`, bex CLI v0.7.0, workspace bex-canary.

## Render

[render.com/docs/native-runtimes](https://render.com/docs/native-runtimes) (read 2026-11-16), § Tools and utilities: "All Render native runtimes run on Debian 12.x, 'bookworm'" and "Additionally, all native runtimes include the tools listed below." `princexml` is in the 38-row table, marked 🟢 "Available both during builds and at runtime". The table gives no version.

## bex (production, 2026-11-16 19:51–19:55 UTC)

The probe is a free native Node web service (`render-examples/express-hello-world@039c347`). Its build command and start command each run `command -v` on the binaries for Render's table, plus `python3 -c "import setuptools"` and `ls /usr/lib/postgresql`:

```text
QA_BUILD_TOOLS … bun:N magick:N prince:N pgdirs:18,
QA_RUN_TOOLS   … bun:N magick:N prince:N pgdirs:18,
```

Every other tool in the table was found at both build and runtime: curl, ffmpeg, g++, gcc, gettext, gs, git, gpg, convert, jq, vips, make, nano, node, npm, pandoc, pigz (build), pnpm, psql, python3-config, pip3, setuptools, rsync, sqlite3, swig, tsc, unzip, vim, webpack, wget, yarn and zip. The other three misses are not bugs:

- **`bun`** is installed only on a Bun signal (`BUN_VERSION`, `.bun-version`, `bun.lock`), which is what Render's own [bun-version](https://render.com/docs/bun-version) page says (w8/m86). The two Render pages disagree.
- **`magick`** is an ImageMagick 7 name. Debian 12's `imagemagick` is 6 and provides `convert`, which is present.
- **The PostgreSQL clients:** only the 18 client is installed (`/usr/lib/postgresql/18`), where Render lists `postgresql-client-12`, `-13` and `-14`. That is ADR060 D7's recorded scope ("not every older versioned client executable", w8/m91).

## Cause

- `w8/done/m91/design.md` maps Render's table to milestones m91 and m93–m103 plus m107: postgresql-client, pandoc, sqlite3, libvips, gettext, ghostscript, jq and rsync, typescript, swig, webpack, pigz, the python3 tools, and zip. `princexml` has no milestone and no recorded exclusion.
- `rg -i prince` over `.pm`, `docs`, `deploy`, `lego/operator/internal/build` and `.github` finds nothing.

## Fix

- **Decision first (the user's):** Prince is commercial software from YesLogic. Shipping it in a shared platform image needs a licence choice. Unverified: whether a redistribution or server licence is required, whether the free non-commercial edition (which watermarks its output) may be preinstalled for tenants, and which edition Render ships.
- **Then:** add the chosen Prince build to the common native image (`deploy/native-base`) for amd64 and arm64, digest- or checksum-pinned and inventoried in `toolchain-freshness.json` like the other utilities (Prince publishes Debian 12 packages; arm64 availability is unverified). Add a utility gate that renders a fixture HTML file to a non-empty PDF at build and runtime, and record the version and its limits in ADR060 D7's table.
- **If the licence is refused:** record the divergence in ADR018 with the user's sign-off and name Docker as the route, as Render does for anything not in its table.

## Regression checks

- **Production:** the probe above reports `prince:Y` at build and runtime, and `prince --version` prints the pinned version. `prince fixture.html -o out.pdf` in a build command produces a PDF (`%PDF` header).
- **Unit and gate:** the common-image utility gate (`TestNativeUtilityGeneratedImages`, w8/m91) gains a `prince` case.

## Dedupe

- No board item, ADR line or commit mentions Prince (`git log -S prince` is empty).
- `w8/m91` and its tool milestones cover the rest of the table.

**Estimate:** ~1h once the licence is decided (the image change, gate and docs). The decision itself is not estimated.
