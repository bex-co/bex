## Objective

Run `/simplify` over the code this milestone changed (reuse / simplification / efficiency; behavior-preserving).

## Acceptance criteria

- [x] `/simplify` pass complete; tests still green

## Outcome (2026-10-19)

`/simplify` ran with three reviewers covering reuse, quality and efficiency. Behavior is unchanged.

- **One held-record read per pass.** `recordReleasePodTemplate` reads the held record once and projects from it. It used to read it again after `selectedRuntimeApp` had already done so.
- **Shared record selection.** `runtimeRecord` picks the record for both `selectedRuntimeApp` and `selectedRuntime`, the held or the selected one, so the two duplicated branches are gone.
- **Simpler signatures:**
  - `heldReleaseRecord` returns `(*runtimeConfigRecord, error)`.
  - `projectRuntimeApp` takes a generation instead of a throwaway `ReleaseConfigReference`.
- **Stamps on the record.** They travel on the record instead of in extra parameters: `writeRuntimeConfigRecord` stamps from the saved spec, and `persistRuntimeConfigRecord` writes the record as given.
- **Shared snapshot copy.** `snapshotReleaseConfig` is the copy loop shared by the adoption and deploy-stage snapshots.
- **Envtest helpers.** The envtest uses `findContainer`, `readRuntimeConfigRecord` and `deleteOwner`.

Not taken:

- Threading the selected runtime through `afterServingDeployment` to drop the remaining per-pass record reads while a release is held. Those reads are bounded to the hold, and the selected-release path already has the same pattern.
- Swapping `copyConfigSecret`'s `CreateOrUpdate` for `Create` + `AlreadyExists`. That is pre-existing code.

`make test` and `make lint` both pass.
