## Objective

When a release is adopted, record its own runtime settings and snapshot its configuration Secrets, so a later save cannot change what that release runs.

## Acceptance criteria

- [x] A save that lands after adoption leaves the adopted release's record and snapshot unchanged (unit and envtest).
- [x] A single deploy is unchanged.

## Out of scope

- Rendering from the record (t003)

## Outcome (2026-10-19)

`recordAdoptedRelease` (`release_config_snapshot.go`) runs on the pass that adopts a pinnable source release (`releaseChanged`). It copies the release's configuration Secrets to their generation snapshots, copy-once, and writes its release record from the adopted spec, with no template yet. `status.configSnapshotGeneration` is not flipped there, so a prior release that is still serving keeps projecting its own snapshots. The deploy-stage `ensureSavedReleaseConfigSnapshot` finds the copies, keeps them, and flips the generation as before. The m120 envtest saves `K=b` while A is held; A's pods still read A's `K=a` snapshot.
