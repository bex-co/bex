## Objective

Pick the mechanism and record it in this milestone and in the ADR that owns workspace targeting (ADR043/ADR006):
- (a) the launcher sends the selected workspace as an explicit bex header that the server honors only for name resolution (a bex-native, documented addition, like `X-Bex-CLI-Version` in `lego/cli/internal/bridge/transport.go`), or
- (b) server-only: names resolve only when unambiguous across the caller's workspaces, otherwise 409, or
- both.

Weigh upstream-contract purity (the skill forbids teaching the launcher workarounds for server gaps) against correctness for single-name-many-workspace users.

## Acceptance criteria

- [ ] The decision is recorded with its trade-offs, and the user signs off if it adds a launcher header.
