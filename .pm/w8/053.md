# 053 — A root directory missing from the repo fails the build with BuildKit's `invalid local: resolve : lstat /source/…`

Why: a mistyped Root Directory is a common setup mistake, and it should say so. Static sites already get a plain sentence (`the publish directory "…" does not exist in the repository at "<sha>"`), but a web service build reports a BuildKit internal error naming bex's `/source` mount.

Severity: minor. Attribution: operator (`lego/operator/internal/build/build.go`).

## Evidence (2026-10-04, `/qa-find-bugs-cli` w8 loop, sweep 8)

Production (`41e6f34b0` on main; deployed revision not observed), `bex v0.2.1` (pin Render CLI v2.27.0), workspace `bex-canary`, human device login. Fixture: free native-Python web service `qa-20261004-a33450-py` (`srv-db1h3gt0e7fs7390d4ag`, deleted). Public repo `https://github.com/bex-co/bex`, root `examples/hello-python`. It first went live in 155 s.

Contrast, sweep 3: a static site with a missing publish directory → `==> Deploy failed: clone: the publish directory "examples/static-site/dist-missing" does not exist in the repository at "e88c7e33…" (exit 2)`.

Sibling, sweep 9 (`6d7095e91`): a Docker-runtime service (`qa-20261004-bbd228-dock`, `srv-db1hfct0e7fs7390d5d0`, deleted) pointed at an existing directory with no Dockerfile (`--root-directory examples/static-site`) fails with `error: failed to solve: failed to read dockerfile: open Dockerfile: no such file or directory`. That is readable but still BuildKit's wording, and it doesn't name the configured path. The same clone-step check should cover it.

## Mechanism

- `lego/operator/internal/build/build.go:850-870` `BuildJob` passes `boundedSourceDir(o.RootDir)` straight to `buildctl … --local context=/source/<rootDir>` (and `--local dockerfile=` for Dockerfile builds). Nothing checks that the directory exists, so BuildKit's `lstat` failure becomes the tenant-facing tail.
- The clone container script (`build.go:1333-1346`) fetches and checks out but never looks at `RootDir`/`DockerContext`, even though it is the step that classifies tenant input (`classifyPrelude`/`bex_run`).
- The static publish path does this check: `lego/operator/internal/publish/publish.go:504` (`cd "/work/$SRC_DIR" || fail … "the publish directory … does not exist in the repository at …"`).

## Fix

After `git checkout`, have the clone container verify, with the bounded paths passed as env vars (never spliced into script text): the root directory, the Docker context (when set), and, for Dockerfile builds, the Dockerfile path. Fail through the tenant classifier with sentences such as `the root directory "examples/no-such-dir" does not exist in the repository at "<sha>"`. That message then flows through `buildFailureMessage` unchanged. Render's equivalent is a plain "root directory is missing" line, not a BuildKit error.

## Acceptance

- [ ] `--root-directory examples/no-such-dir` then `deploys create --wait` → `build_failed`, and the summary reads `the root directory "examples/no-such-dir" does not exist in the repository at "<sha>"`, with no `/source`, `invalid local` or `lstat`.
- [ ] The same holds for a missing `dockerContext` and a missing Dockerfile path (via Blueprint or REST `serviceDetails.envSpecificDetails`, since the pinned CLI has no flags for them).
- [ ] Controls: valid root directories build unchanged (native and Dockerfile). Traversal input (`../..`) stays contained by `boundedSourceDir`. Static sites keep their publish-directory message.
