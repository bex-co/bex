## Objective

Schedule automatic apply when the linked manifest changes, without depending on complete changed-path arrays in every webhook.

## Context

- Parent milestone: [w8/m38 — Resource-independent Blueprint auto-sync](README.md), user-approved on 2026-09-08.
- Render documents automatic Blueprint sync for pushes changing the configured file; custom YAML paths and legacy discovery already ship.
- The push payload's changed-path inventory can be absent or incomplete. m36 provides complete content fetched at an immutable revision.

## Steps

1. Compare complete changed-path evidence with the Blueprint's configured path and skip known unrelated changes.
2. When path evidence is incomplete, perform a bounded revision/content comparison through m36's fetcher rather than treating absence as proof of no change.
3. Carry the selected source revision/fingerprint into the accepted intent so worker execution cannot silently fetch different content.
4. Handle removed files, force-push/older deliveries, and rapid successive pushes explicitly; stale delivery must not roll applied configuration backward.

## Acceptance criteria

- [ ] A changed custom-path manifest triggers work; complete evidence of only unrelated changes does not.
- [ ] Missing/incomplete path arrays cannot silently suppress a real manifest update.
- [ ] File removal/source failure becomes a diagnosable outcome through the existing sync contract.
- [ ] The source revision applied matches the accepted revision; older redelivery cannot overwrite a later accepted source.

## Out of scope

- Scanning every repository file or adding recursive provider inventory.
- Changing service build filters or expanding implicit filename rules.
