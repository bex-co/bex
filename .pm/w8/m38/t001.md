## Objective

Discover Blueprint targets from their own authorized connection records instead of inferring them from Apps that happen to reference the pushed repository.

## Context

- Parent milestone: [w8/m38 — Resource-independent Blueprint auto-sync](README.md), user-approved on 2026-09-08.
- GitWebhook.ServeHTTP currently returns when repoCandidates finds no App; the subsequent Blueprint tenant set is collected only from matching Apps.
- Database-only, environment-group-only, image-backed, and cross-repository service Blueprints are valid supported compositions with no matching App.spec.repo.
- w1/m69 established server-derived acting-tenant binding; retain that boundary while expanding discovery.

## Steps

1. Add a bounded store query for active connected Blueprints matching the canonical repository, branch, and installation-authorized workspace.
2. Combine independent App and Blueprint target discovery before the no-target return/replay decision; normalize supported GitHub URL forms consistently.
3. Exclude disconnected/paused-auto-sync records and bind execution to the Blueprint row's authorized workspace.
4. Keep unrelated valid deliveries out of durable replay/queue storage.

## Acceptance criteria

- [ ] Database-only, environment-group-only, image-backed, and services-from-another-repo fixtures select the correct Blueprint without a matching App.
- [ ] HTTPS, .git, and SSH repository forms match canonically without crossing workspace boundaries.
- [ ] Wrong branch, unbound/foreign installation, disconnected Blueprint, and Auto Sync disabled select no Blueprint.
- [ ] An unrelated valid delivery allocates no durable work.

## Out of scope

- Changing App autoDeploy/build-filter behavior or using user-supplied tenant IDs as authority.
- GitLab/Bitbucket integration and new Blueprint composition features.
