## Objective

Finish integration so automatic work actually runs in configured environments and users can observe its accepted, active, and terminal states.

## Context

- Parent milestone: [w8/m38 — Resource-independent Blueprint auto-sync](README.md), user-approved on 2026-09-08.
- Current triggerBlueprintSync uses context.Background in a detached goroutine; the process has no durable ownership of that task.
- REST/GraphQL/MCP Blueprint history and dashboard status already exist. Reuse the supported vocabulary and confirm rendering for any newly reachable queued state.

## Steps

1. Register/start/stop the durable processor through the normal bex-api lifecycle and remove the replaced goroutine dispatch.
2. Expose accepted/running/error/success outcomes and commit provenance through existing Blueprint/history views, adding a supported pending/created projection only if needed.
3. Verify store-disabled behavior is explicit and configured workers are demonstrably started.
4. Run the dev-8 signed-push and restart scenario, recording fixture cleanup and the exact evidence boundary.
