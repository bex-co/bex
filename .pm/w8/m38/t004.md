## Objective

Replace the detached goroutine with recoverable bounded processing that consumes m37's execution ownership and m36's source guarantees.

## Context

- Parent milestone: [w8/m38 — Resource-independent Blueprint auto-sync](README.md), user-approved on 2026-09-08.
- m37 provides persisted admission, generation checks, coherent terminal writes, and interrupted-run handling.
- Automatic attempts must still enforce the existing tenant, billing, quota, protected-environment, and Blueprint ownership rules; webhook execution never supplies takeover confirmation.

## Steps

1. Claim pending intents in bounded batches with per-workspace fairness/admission bounds and per-Blueprint execution coordination.
2. Recheck active generation, Auto Sync, installation/workspace binding, and current policy before starting apply.
3. Resume pending work after restart; handle transient failures before any side effect with bounded retry, and route ambiguous partial application to m37's explicit error/retry outcome.
4. Preserve source order or safely coalesce queued changes with recorded disposition, so a busy Blueprint eventually sees later eligible changes.
5. Mark terminal intent/run outcomes durably and retain failures for the existing history surface.

## Acceptance criteria

- [ ] Pending acknowledged work runs after restart and converges to success or an actionable failure.
- [ ] Two replicas cannot execute the same logical intent or overlap one Blueprint's apply.
- [ ] Work per tick, retries, and per-workspace backlog are bounded without starving other workspaces.
- [ ] Disconnect, Auto Sync off, lost connection, billing enforcement, and ownership conflict prevent unauthorized late apply.
- [ ] Partially applied interrupted work is not blindly replayed.

## Out of scope

- A generic orchestration framework, auto-takeover, or automatic replay of ambiguous partial effects.
- Changes to sandbox dispatch, operator mechanisms, or unrelated event delivery.
