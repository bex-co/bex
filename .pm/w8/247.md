# A sandbox created without `--plan` gets the deprecated `starter` plan, not Render's default `1c-2g`

Why: on Render a sandbox with no plan is `1c-2g` (1 CPU / 2 GB). On bex it is created, reported and metered as `starter` (0.5 CPU / 512 MiB), a deprecated name the CLI's own help no longer lists, so the default sandbox is a different size and a different billing weight than Render's.

**Severity:** minor (parity; the default is smaller and cheaper than Render's, and the name is not in the documented set). **Attribution:** server. **Estimate:** ~40m. **Source:** `/qa-find-bugs-cli` w8 loop sweep `2a35`, 2026-11-11 UTC, released `bex v0.5.0` (Render CLI v2.35.0, `24ac2d60fdb2`), production `https://api.bex.co/v1/`, workspace `bex-canary`, QA human device login.

## Evidence

```text
$ bex sandboxes create --timeout 900 -o json            # no --plan; five creates in this sweep, all the same
{ "id": "sbx-dbpukgvbq3ic73c0adpg", "plan": "starter", "status": "running", "timeoutSeconds": 900, … }     exit 0

$ bex sandboxes create --plan 1c-2g --timeout 1800 --wait -o json
{ "id": "sbx-dbpugr7bq3ic73c0acm0", "plan": "1c-2g", … }

$ bex sandboxes list -o text
ID                          STATUS     PLAN       …
sbx-dbpugr7bq3ic73c0acm0    running    1c-2g
sbx-dbpukgvbq3ic73c0adpg    running    starter

$ bex sandboxes create --help
      --plan <string>   Compute plan: 1c-2g, 2c-4g, 4c-8g, 8c-16g
```

All sandboxes were stopped (`terminated`) in the same sweep.

## Expected

Render: plans are `1c-2g` (default), `2c-4g`, `4c-8g`, `8c-16g` (ADR104 § Groups, plans and limits, line 151; the pinned CLI lists only those four and marks `starter`/`standard`/`pro` deprecated in `cmd/sandboxcreate.go:127-137`). A create with no plan should answer `"plan": "1c-2g"` and be sized and metered as 1 CPU / 2 GiB.

## Root cause

- `lego/backend/cmd/api/main.go:1303` sets `deps.SandboxDefaultPlan = sandbox.PlanStarter`.
- `lego/backend/internal/sandbox/service.go:782-785` applies it when `req.Plan` is empty; `models.go:67-75` sizes `starter` at 500m / 512Mi, and the compute meter weight follows the plan size.
- The default predates the spec-named plans (w2/m263); ADR018's `plan` row keeps `starter` only as a deprecated alias and says nothing about the default.

## Fix

1. Default Render sandbox creates (REST `POST /v1/sandboxes`, GraphQL, MCP `create_sandbox`) to `sandbox.Plan1C2G`. The response and lists then show `1c-2g`.
2. **Blast radius — check before changing the shared field:** `service.go:1034` uses the same `DefaultPlan` for agent-session sandboxes. Their size and price are a separate decision (ADR047/ADR091), so either keep `starter` there with its own field or confirm the change is intended. Tests that pin the default: `agent_session_test.go:41,106`, `payment_gate_test.go:55`, `cli_flags_test.go:117`.
3. Existing sandboxes keep the plan they were created with.
4. Record the default in ADR018's sandbox `plan` row and ADR104.

## Acceptance

- `bex sandboxes create --timeout 900 -o json` answers `"plan": "1c-2g"`; `bex sandboxes list` shows `1c-2g`; GraphQL and MCP creates agree.
- `--plan starter` still works and still reports `starter`.
- An agent session's sandbox plan is unchanged unless step 2 decided otherwise.
- A unit test fails on the old default.

## Unverified

- Render's default was taken from ADR104 and the pinned CLI help, not from a live Render account.
- Actual in-guest resources do not follow the plan below `2c-4g` today (w8/244, blocked), so this changes the reported plan and the meter weight, not the measured CPU/memory, until w8/244 is fixed.

## Dedupe

No `.pm` item covers the default plan. w8/244 (plan sizes not enforced) and w2/m263 (spec-named plans accepted) are related, not duplicates.
