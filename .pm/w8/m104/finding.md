# A fresh managed PostgreSQL database cannot install pg_partman

**Severity: major. Attribution: database-server extension supply.** Published Bex0.3.2 and unchanged pinned Render2.27.0 each exit1 on the original ordinary application migration `CREATE EXTENSION IF NOT EXISTS pg_partman SCHEMA <own-schema>`. PostgreSQL18.6 reports the extension is unavailable and must first be installed on the server. Four matching catalogs omit pg_partman while vector0.8.6, pg_stat_statements1.12 and plpgsql are installed. [Results](evidence/cli-sweep428/results.json), [complete native results](evidence/cli-sweep428/complete-native-SQL-failures-controls-and-cleanup.json).

[Render's extension contract](https://render.com/docs/postgresql-extensions) supports pg_partman on PostgreSQL14+ for databases created after2026-02-05, with the background worker disabled. This fixture is freshly created2026-10-17. It fails before partition management can start. Both same-database controls create/query hstore and real declarative range partitions: three rows retain exact Unicode/space labels and route to the expected two children. All transactions roll back, and all four catalogs show no own schema or retained hstore. Connection, encoding, ordinary extension and built-in partitioning behavior are healthy.
