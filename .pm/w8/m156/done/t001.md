## Objective

Render the `^live-.*` keepTags entry first and the catch-all second, in the canonical Zot config and in the storage block carried onto existing configs, so the live rule sees its tags.

## Context

- Zot gives a tag to the first `keepTags` entry whose pattern matches and counts inside that entry's group (`getTagPolicy`, `pkg/retention/retention.go`, v2.1.22).
- `lego/operator/internal/registry/zotconfig.go`: `buildBaseZotConfig` renders the entries; `setZotStorage` replaces a differing storage block at reconcile.

## Files

- `lego/operator/internal/registry/zotconfig.go`
- `lego/operator/internal/registry/creds_test.go`

## Acceptance criteria

- [x] The rendered `keepTags` lists `^live-.*` (10) first and `.*` (retention count) second; a config in the old order is migrated once and then left alone. (2026-11-11: `zotKeepTags`.)
- [x] An operator test pins the order and the migration. (`TestZotLiveTagRuleComesBeforeTheCatchAll`.)
- [x] The change reaches the running registry. (Added after review, 2026-11-11: Zot reads its config only at start and a storage-only change restarted nothing. `ensureStorageActive` restarts Zot once per storage block and records it on the config Secret; `TestAStorageChangeRestartsZotOnce`.)

## Out of scope

- Images already removed from production's registry cannot be brought back by the rule; see the README's note on running services.
