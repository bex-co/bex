# Static-site redirects cannot point at another site (`destination: https://…`), although Render allows it and a redirect proxies nothing

Why: Render's redirect rules take a path or a full URL ("**Destination** can be either a path or a full, publicly accessible URL", with the example `/web-host` → `https://render.com`; [redirects-rewrites](https://render.com/docs/redirects-rewrites)), and real Blueprints use it to send old asset paths to a CDN or a moved page to a new domain. Bex refuses every non-path destination with `routes[N].destination must be a path starting with /`, so the whole Blueprint fails validation. The recorded reason for local-only targets is that tenants "cannot choose an upstream server" (ADR029:50). That is a property of **rewrites**, which bex would have to fetch. A redirect only emits a `Location` header, as any web service may. Keeping rewrites local and allowing redirects to fixed external hosts loses no security property.

**Severity:** minor. **Attribution:** server policy (route validation; static-server sink check). **Decision note:** ADR018:211 and w4/m154 record "local-only targets" as a deliberate divergence covering both rule types; this note asks to split them. **Estimate:** 60m. **Source:** `/qa-find-bugs-cli` sweep 1278, 2026-10-21 ([evidence](evidence/cli-sweep1278/README.md)).

## Reproduction

Production `https://api.bex.co/v1/`, pin `9cace6b6e25d`, HEAD-built pinned CLI. `bex blueprints validate redir.yaml -o json`, for a static site with:

```yaml
routes:
  - { type: redirect, source: /maps/*, destination: https://cdn.example.com/maps/* }
  - { type: redirect, source: /old,    destination: https://example.org/new }
```

→ exit 1, `services[0].routes[0].destination` line 12: `routes[0].destination must be a path starting with /`. REST `PUT /v1/services/{id}/routes` shares `validateRoutes` and refuses the same.

Corpus (sweep 1270, 601 real `render.yaml` files): 92 route rules, 19 of them with absolute destinations. Examples: 6 redirects in `jblanchette/wc3v` (`/assets/textures/*` → `https://cdn.wc3v.com/assets/textures/*`, …) and 13 rewrites, mostly `/api/*` → `https://<backend>.onrender.com/api/*`. The rewrites stay out of scope here.

## Expected

A `redirect` with an absolute `https://` (or `http://`) destination whose scheme and host are literal (no `*`/`:splat` before the path) validates, and the static server answers `301 Location: <expanded URL>`. A capture may expand only in the path and query, as for local targets. `rewrite` destinations stay local-only (ADR029), and network-path forms (`//host`, `/\host`, control bytes; ADR056 #11) stay refused for both types.

## Root cause

`lego/backend/internal/apps/service.go:5177–5180` (`validateRoutes`) requires a leading `/` for every destination. `lego/operator/internal/staticserver/staticserver.go:429–436` (`safeRedirectTarget`) enforces the same at the output sink. ADR056 #11 hardened the local-path rule against protocol-relative bypasses. It also raised the setters to `can_create`, so only developers configure redirects. An owner-chosen absolute redirect is then equivalent to app code calling `http.Redirect`.

## Fix

In `validateRoutes`, accept for `type: redirect` only a destination that parses as an absolute URL with scheme `http`/`https`, a non-empty literal host (no wildcard or `:` placeholder in scheme, userinfo or host), no userinfo, and a length within `maxStaticPathLen`. In the static server, expand captures only in the parsed path/query of that URL and allow it at the sink when its scheme and host equal the configured ones. Keep every current refusal for rewrites and network-path forms. Update ADR029 § threat model, ADR018:211 and the dashboard Redirects editor hint.

## Acceptance

- Validation tests: absolute `https://cdn.example.com/maps/*` redirect accepted; `https://*.example.com/x`, `https://:splat/x`, `https://user@host/x` and `//host/x` refused; an absolute **rewrite** still refused with the current message.
- Static-server tests: `/maps/a/b.png` → `301 Location: https://cdn.example.com/maps/a/b.png`. A capture containing `@`, `//` or `\` cannot change the host.
- Live after deploy: `redir.yaml` validates. On an owned free static site, `curl -sI https://<site>.onbex.co/old` returns `301 Location: https://example.org/new`. Delete it by ID with a 404 proof.

## Dedupe

ADR018:211 / ADR029 / w4/m154 (the local-only divergence; this note keeps it for rewrites), ADR056 #11 (protocol-relative bypass hardening, kept). No item separates redirects from rewrites.
