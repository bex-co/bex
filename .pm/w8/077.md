## Diagnosis and proposed work

Pinned Render `pkg/command/inputs.go:79–107` retrieves StringArray flags with `flags.GetStringArray(tag)` at 94. The standalone Render build uses pflag v1.0.9; the released Bex binary and checkout use v1.0.10. Both store the literal string, but their byte-identical `string_array.go:52–68` getter serializes it to CSV and parses it again through `string_slice.go:22–28`. Go's CSV reader removes carriage returns preceding newlines, including inside quoted fields. This is documented [CSV behavior](https://pkg.go.dev/encoding/csv#Reader), applied to a literal flag where a second CSV parse is unnecessary.

The probe invokes actual pflag storage/getter, Render `command.ParseCommand`, create normalization/validation and `service.BuildCreateRequest`. CRLF is exact in storage, changed by the getter and parser, and already LF in the generated environment body. Feeding the stored slice directly into the same validator/builder preserves CRLF. LF, lone CR, empty value and Unicode/punctuation controls stay exact. `pkg/types/envvar.go:14–25` trims outer whitespace but leaves this interior CRLF intact; `pkg/service/create.go:107–130` consumes the already changed flags.

Prepare an **upstream Render** correction to the StringArray branch: defensively obtain its `pflag.SliceValue` and use `GetSlice()` directly. In this dependency that method at `string_array.go:40–45` returns a copy, including a non-nil empty slice. Preserve type errors, default/empty behavior, repeated argument order, Enum handling and StringSlice CSV semantics. Audit explicit empty-element behavior before changing shared consumers. Do not fork/vendor the CLI or reconstruct lost bytes in Bex transport/storage.
