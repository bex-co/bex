## Objective

`FOR ALL TABLES` needs a superuser, which Render's support team supplies. On bex, the operator creates it as a CNPG declarative `Publication` while `allTables` is set, and removes it when it is cleared.

## Context

- CNPG v1.30.1 `docs/src/logical_replication.md`: `Publication` with `spec.cluster.name`, `spec.dbname`, `spec.name`, `spec.target.allTables: true`, `publicationReclaimPolicy: retain|delete`; `status.applied` and `status.message`.
- The operator already drives CNPG's declarative `Database` (`lego/operator/internal/controller/database_extensions.go`); follow that pattern.
- RBAC markers: `database_controller.go:876` (generated into `lego/operator/config/rbac/role.yaml:200`).

## Steps

1. Add `publications` to the CNPG RBAC marker; regenerate.
2. Converge one owned `Publication` per enabled database with `allTables`, reclaim policy `delete`, named so a user's own publications cannot collide.
3. Surface `applied: false` and its message on the Database status, so the verb can report it.

## Files

- `lego/operator/internal/controller/database_controller.go` (or a new `database_publication.go`)
- `lego/operator/config/rbac/role.yaml` (generated)

## Acceptance criteria

- [ ] On dev-N, `SELECT puballtables FROM pg_publication` shows the publication while `allTables` is set and nothing after it is cleared.
- [ ] A failed apply is visible on the Database status.
- [ ] `make test` passes.

## Out of scope

- Publications the user creates with `FOR TABLE`: they stay the user's, untouched.
