## Objective

Confirm on a dev stack what a subscriber gets from a bex Postgres today, then write the contract the rest of the milestone implements: Render's rules, bex's mapping of them, and the ADR018 row.

## Context

- Render's contract and bex's current state are in the milestone README (§ Source + Goal linkage).
- Expected today: `SHOW wal_level` reads `logical`; `CREATE PUBLICATION p FOR TABLE t` succeeds as the default user, who owns the tables; an external `CREATE SUBSCRIPTION … CONNECTION '<external URL>' PUBLICATION p` fails with `must be superuser or replication role to start walsender`. Confirm each, do not assume.
- Logical replication connections name a database, so `pg_hba` matches them on the ordinary database rules, not the `replication` keyword (PostgreSQL docs, pg_hba.conf).
- PgBouncer cannot carry a replication connection, so the pooler URL is never the one a subscriber uses.

- `SHOW wal_level` reads `logical`; `max_slot_wal_keep_size` reads `-1`.
- The default user's `CREATE PUBLICATION mine FOR TABLE public.orders` succeeds; its `CREATE PUBLICATION … FOR ALL TABLES` answers `must be superuser to create FOR ALL TABLES publication`.
- The external subscriber's `CREATE SUBSCRIPTION … PUBLICATION mine` as the default user is refused: `permission denied to start WAL sender` (DETAIL `Only roles with the REPLICATION attribute may start a WAL sender process.`).
