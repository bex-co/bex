## Objective

bex's operators play Render's support team: one verb, reachable only on bex-api's cluster-internal listener, takes Render's request inputs (database id, publisher role, schemas, all tables or not), checks Render's prerequisites, writes `spec.logicalReplication`, grants the role read access to the named schemas, and records an audit event. A second form disables.

## Context

- The internal mux: `opsrole.Register(internalRoot, …)` in `lego/backend/cmd/api/main.go:1487`; the ADR088 §4 pattern (static bearer, never the public `:8090` mux).
- Plan gate: add a `FeatureLogicalReplication` with `minimum: planPro` beside `FeatureNetworkIsolation` (`lego/backend/internal/core/plan_gate.go:82`).
- Storage: the database's effective storage is at least 10 GB (`Database.spec.storageGB`, else the plan's default).
- The role must be one of the database's credentials (the owner or a `spec.users` entry), per t003's decision.
- Schema grants (`GRANT USAGE ON SCHEMA …`, `GRANT SELECT ON ALL TABLES IN SCHEMA …`, `ALTER DEFAULT PRIVILEGES … GRANT SELECT`) run as the owner through bex-api's direct query path (`lego/backend/internal/postgres/query.go`). Render's form asks for the schemas, which implies it grants them; if t001 decides otherwise, the runbook tells the user to grant.

## Steps

1. Add the verb and its refusals: `LOGICAL_REPLICATION_PLAN_REQUIRED` (below Pro), `LOGICAL_REPLICATION_STORAGE_TOO_SMALL` (under 10 GB), `LOGICAL_REPLICATION_ROLE_UNKNOWN`, a free plan, a suspended or deleting database. Each refuses before any write.
2. Write the spec field, run the grants, wait for the operator's convergence (role attribute, publication), and answer with the outcome.
3. Record an audit event for enable and disable.
4. Write `docs/runbooks/postgres-logical-replication.md`: the request inputs, the call, how to check the result, how to disable.

## Done (2026-11-21)

- `/api postgres-logical-replication enable --database dpg-… --role … --schema … [--all-tables]` / `disable --database dpg-…`, a thin client of `POST /internal/postgres-logical-replication` on `:8091` behind `BEX_CP_TOKEN` (`lego/backend/internal/postgres/logical_replication.go`, `cmd/api/logical_replication.go`). Never on `:8090`; excused from the authz sweep like `PlatformRebuild`.
- Refusals before any write: `LOGICAL_REPLICATION_PLAN_REQUIRED` (below Pro or the plan unreadable, `core.FeatureLogicalReplication`), `…_FREE_PLAN`, `…_STORAGE_TOO_SMALL` (`tiers.PostgresLogicalReplicationMinStorageGB`), `…_ROLE_UNKNOWN`, `…_SCHEMA_UNKNOWN`, `…_DATABASE_UNAVAILABLE` (suspended, deleting, not available), `…_PUBLICATION_NAME_IN_USE` (a user's `bex_all_tables`), `…_INVALID_REQUEST`.
- Enable grants USAGE, SELECT and default privileges (for every owner-privileged role the default user belongs to) as the default user, writes the spec, waits up to 2 minutes for PostgreSQL itself to report `rolreplication` and the publication, and records `postgres.EnableLogicalReplication` (caller `bex-operations`); a repeated request writes and records nothing. Disable drops the database's logical slots as the publisher (terminate, wait for release, drop, retry: a subscriber's apply worker reconnects in about a second), clears the spec, waits, ends the walsenders left, records `postgres.DisableLogicalReplication`, and lists dropped and remaining slots.
- `docs/runbooks/postgres-logical-replication.md`. Tests: `logical_replication_test.go` (every refusal writes nothing; the bearer), `logical_replication_pg_test.go` (real PostgreSQL 17 in CI and 18 locally, with a real subscription), `cmd/api/logical_replication_test.go`. CI's test PostgreSQL now runs `wal_level=logical`, as CloudNativePG does (`backend-test.yml`, `scripts/backend-test-deps.sh`).
