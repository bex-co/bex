## Done (2026-11-21)

Walked render.com/docs/postgresql-logical-replication (read 2026-11-20) rule by rule:

| Render's rule | bex |
| --- | --- |
| Off by default | Same: no role holds `REPLICATION`, no all-tables publication, `max_slot_wal_keep_size` `-1` |
| A Pro workspace or higher | `LOGICAL_REPLICATION_PLAN_REQUIRED` below Pro, and when the plan cannot be read |
| At least 10 GB of storage | `LOGICAL_REPLICATION_STORAGE_TOO_SMALL` on effective storage; a free database `…_FREE_PLAN` |
| Ask support, naming the databases, the subscriber role, the schemas, all tables or not | The operators' `/api postgres-logical-replication` takes the same four inputs; the dashboard note and the agent skill say to contact support. **Difference:** bex has no support channel yet, owned by [w34/002](../../002.md) |
| A dedicated read-only user is recommended | Any live credential may publish; `POST …/users` makes a dedicated one, and the verb grants it the schemas |
| `FOR ALL TABLES` by support | `--all-tables` declares `bex_all_tables`, created by CloudNativePG as the superuser |
| `FOR TABLE` by the user | Works for the default user (PostgreSQL 18, 2026-11-21) |
| Subscribers need not be Render-managed | An external PostgreSQL 18 subscribed over TLS (local pair); production in t008 |

REST `GET /v1/postgres/{id}`, GraphQL and MCP `get_postgres` are unchanged: `PostgresView`, `graphql.go` and `mcp.go` are untouched, and no tenant route serves the verb (`TestLogicalReplicationIsNoRESTRoute`). Remaining differences, each in the ADR018 row with its owner: the request channel (w34/002); Render's undocumented role attributes, retained-WAL bound, majors and HA behavior (w34/001); bex as a subscriber (w34/m542); lifecycle (w34/m543); the production replay (t008, t012).
