## Objective

Extend `MetricsFiltersQuery` and `Service.MetricsFilters` to support `[Start, End]` time windows (clamped to plan retention), multiple resources (with per-resource authorization and `checkFanOut`), optional `Hosts`/`StatusCodes` narrowing filters, and datastore (`dpg-`/`red-`) instance resolution.

## Context

- `lego/backend/internal/metrics/service.go:1362-1455`: `MetricsFiltersQuery` currently holds only a single `App string` and `OutputFilters []string`, with no `Start`/`End`, `Hosts`, or `StatusCodes`.
- `lego/backend/internal/metrics/retention.go`: `withinRetention` enforces the workspace plan's metrics retention floor.

## Steps

1. Extend `MetricsFiltersQuery` with `Resources []string` (preserving backward compatibility when a single `App` is set), `Start`/`End time.Time`, `Hosts []string`, and `StatusCodes []string`.
2. Enforce `checkWindow`, `ValidateQueryRange`, `checkFanOut`, per-resource authorization (`AuthorizeApp` for services; `AuthorizeDatabase`/`AuthorizeKeyValue` + `core.NotFoundIfDeleting` for `dpg-`/`red-` when requesting `INSTANCE` or `RESOURCE`), and `withinRetention` clamping (clamping `Start` to the resource's retention floor and `AppNotBefore`).
3. Validate `StatusCodes` up front before calling any backend source.

## Files

- `lego/backend/internal/metrics/service.go`

## Acceptance criteria

- [ ] Multi-resource `MetricsFilters` authorizes every resource and fails closed if any is unauthorized or unknown.
- [ ] Ranges exceeding `MaxQueryHours` or inverted ranges return `400`; ranges wholly before plan retention return empty values cleanly.
- [ ] Single-resource callers without `Start`/`End` continue to default to `[now-1h, now]` (clamped to plan retention).

## Out of scope

- Prometheus historical-instance discovery (t002) and Loki host/cross-filter discovery (t003).
