# Attribute API keys via `KeyCreator` in `changeWorkspacePlan`

Why: `changeWorkspacePlan` is permitted for API keys (`KeyWorkspaceSettingsManage`), but passing the raw Hydra client UUID (`id.Subject`) instead of `s.KeyCreator(ctx)` bypasses the 5-Hobby-workspace-per-user cap, breaks entitlement/downgrade checks, and promotes every admin on `upgradeToOrganization`.

- **Source:** follow-up from `routine:mcp-qa` (`cc9a07fd30`), 2026-11-26 (GraphQL-only, out of `/qa-find-bugs-mcp` scope).
- **Finding:** GraphQL `changeWorkspacePlan` (`lego/backend/internal/workspaces/service.go:1561,1630-1634` and `lego/backend/internal/workspaces/organizations.go:565,669`, permitted for API keys via `KeyWorkspaceSettingsManage` in `lego/backend/internal/api/key_permission_ops.go:81`) passes raw API-key `id.Subject` (Hydra client UUID) instead of `s.KeyCreator(ctx)` to `requirePlanEntitlement`, `guardPerUserWorkspaceCap` (bypassing the 5-Hobby-workspace-per-user cap), `downgradePreconditions` (`unseated`), and `upgradeToOrganization` (`owners`, matching zero `kind='user'` rows and promoting every admin).
- **Fix:** Resolve attributed API keys via `s.KeyCreator(ctx)` across those `changeWorkspacePlan` paths and add unit/e2e tests proving parity with human sessions.
