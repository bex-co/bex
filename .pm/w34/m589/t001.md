## Objective

Remove the `400` refusal on `instance` and `percentage` for datastore `cpu`, `memory`, `cpu-limit`, and `memory-limit` queries so callers can filter primary/HA-standby/read-replica instances and read percentage utilization against the datastore's own limit history.

## Context

- `lego/backend/internal/metrics/rest.go:167-186` (`datastoreAppMetric`) rejects `q.Percentage || len(q.Instances) > 0` with `400` before calling `DatastoreMetrics`.
- `lego/backend/internal/metrics/datastore.go:505-515` already fetches per-pod cAdvisor series (`cpu`, `memory`) and kube-state-metrics limits (`cpu_limit`, `memory_limit`) via `s.DatastoreResource`, then projects pod names with `projectInstanceLabels`.
- `lego/backend/internal/metrics/service.go:920-938` (`normalizeUsageToPercentage`, `buildLimitTimelines`, `steppedLimitAt`) and `select.go` (`applyInstanceSelection`) already implement percentage normalization and instance filtering for services.

## Steps

1. In `lego/backend/internal/metrics/rest.go` (`datastoreAppMetric`) and `datastore.go`, support `q.Percentage` for `MetricCPU` and `MetricMemory` on Postgres and Key Value by reading the matching `MetricCPULimit`/`MetricMemoryLimit` series from `s.DatastoreResource` over the same window and normalizing via `normalizeUsageToPercentage` (using raw pod labels before `projectInstanceLabels`, with unit `percentage` — note Key Value `memory` maps to `MetricKVMemory`, whose limit is `MetricMemoryLimit`).
2. Allow `q.Instances` on `MetricCPU`, `MetricMemory`, `MetricCPULimit`, and `MetricMemoryLimit` for datastores, reusing `validateInstanceSelection` and `applyInstanceSelection` (returning empty series on unresolved instance IDs, never silently broadening — `w5/m91`).
3. Keep refusing `percentage` and `instance` on unsupported metrics (`http_*`, `bandwidth`, `instance_count`, etc.) with clear `400` errors.

## Files

- `lego/backend/internal/metrics/rest.go`
- `lego/backend/internal/metrics/datastore.go`
- `lego/backend/internal/metrics/select.go`

## Acceptance criteria

- [ ] `GET /v1/metrics/cpu?resource=dpg-…&instance=dpg-…-2` returns only the selected replica's series (and empty `[]` for an unknown instance ID, never broadening).
- [ ] `GET /v1/metrics/cpu?resource=dpg-…&percentage=true` and `memory` (Postgres and Key Value) normalize each sample against the datastore's limit series with unit `percentage`.
- [ ] `ReplicaAggregate` (`aggregateAllMethod`) works over selected datastore instances consistently with services.

## Out of scope

- Multi-resource datastore endpoints (`t002`) and MCP/GraphQL adapter alignment (`t003`).
