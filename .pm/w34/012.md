# Classify `validate_bex_yml` and `POST /v1/blueprints/validate` as `core.OpClassRead`

Why: Blueprint validation is a read-only operation (`validate_bex_yml` advertises `readOnlyHint: true`, `GQL Query.validateBlueprint` is `core.OpClassRead`, and all three surfaces require only `core.KeyBlueprintsView`), so classifying MCP/REST as `core.OpClassWrite` wrongly blocks `bex.read` OAuth tokens.

- **Source:** follow-up from `routine:mcp-qa` (`11608b2206`), 2026-11-25.
- **Finding:** `MCP validate_bex_yml` and `REST POST /v1/blueprints/validate` are classified `core.OpClassWrite` in `lego/backend/internal/api/scope_matrix_ops.go:748,1045`, while `GQL Query.validateBlueprint` is `core.OpClassRead` (`:435`), `validate_bex_yml` advertises `readOnlyHint: true`, and all three require only `core.KeyBlueprintsView` (`key_permission_ops.go`).
- **Fix:** Add both operations to `scopeClassOverrides` in `lego/backend/internal/api/scope_matrix_overrides.go`, regenerate `lego/backend/internal/api/scope_matrix_ops.go`, and add a test asserting a `bex.read` OAuth token succeeds on all three surfaces (REST, GraphQL, MCP).
