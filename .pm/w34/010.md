# Multi-value `statusCode` / `STATUS_CODE` filtering across HTTP metrics and filters

Why: Render's GraphQL `MetricsFilterInput.values` is a list and Render's REST filter endpoints OR repeated `statusCode` query params, whereas bex silently drops extra REST `statusCode` values (`rest.go:428`) and returns `400 STATUS_CODE accepts one value` in GraphQL (`graphql.go:507`).

## Evidence

- `lego/backend/internal/metrics/service.go:157`: `MetricQuery.StatusCode` (and `RequestMetricsRequest.StatusCode`) is a single `string`.
- `lego/backend/internal/metrics/source.go:578-607`: `codeMatcher(statusCode string)` compiles only one status code or class (`5..` or `500`).
- `lego/backend/internal/metrics/rest.go:428`: `parseMetricParams` uses `v.Get("statusCode")`, silently ignoring any second repeated `statusCode` param (e.g. `?statusCode=4xx&statusCode=5xx`). Note: Render's pinned OpenAPI (`render-public-api-1.json`) declares repeatable `statusCode` on `/metrics/filters/http` and `/metrics/filters/path`, not on `/metrics/http-requests` or `/metrics/http-latency` (where REST `statusCode` is a bex extension; do not invent an unpinned OpenAPI claim).
- `lego/backend/internal/metrics/graphql.go:507-510`: rejects `len(codes) > 1` with `STATUS_CODE accepts one value, got N`.

## Fix

1. Replace scalar `StatusCode string` on `MetricQuery` and `RequestMetricsRequest` with `StatusCodes []string` (preserving behavior for empty and single-element inputs).
2. Add shared `normalizeStatusCodeFilters([]string)` and `codesMatcher([]string)` in `lego/backend/internal/metrics/source.go` (deduplicating, validating every token before touching a backend, bounding list size, and compiling ORed regexes such as `^(4..|500|502)$` for PromQL `code=~` and LogQL `status=~`).
3. Update `parseMetricParams` (`rest.go`) to read `nonEmptyValues(v["statusCode"])` and `metricsQueryInputFromArgs` (`graphql.go`) to pass all `STATUS_CODE` filter values instead of 400ing on `len > 1`.
4. Add regression tests in `metrics_test.go`, `lokisource_test.go`, and `render_contract_test.go` covering multi-value exact + class combinations (`["4xx", "5xx"]`, `["500", "502"]`), invalid-member 400s, and unchanged single-value queries.

## Acceptance criteria

- [ ] GraphQL `metrics(query: {filters: [{field: "RESOURCE", values: ["srv-…"]}, {field: "STATUS_CODE", values: ["4xx", "5xx"]}]})` returns the ORed union across both Loki and Prometheus paths.
- [ ] REST `parseMetricParams` passes all repeated `statusCode` values (never silently dropping past the first) and refuses any invalid token in the list with `400`.
- [ ] Single-value queries remain byte-identical, and `go test ./internal/metrics ./internal/api` passes.
