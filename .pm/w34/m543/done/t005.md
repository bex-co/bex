## Objective

Recovery creates a new database with a new `dpg-` id. Render enables logical replication per database id, so the recovered copy starts not enabled, without the role attribute, the all-tables publication or the WAL bound, however its source was configured.

## Context

- `Recover` (`lego/backend/internal/postgres/recovery.go:341`) copies the source's configuration into the new Database; check whether it would copy `spec.logicalReplication`.
- Restored data still contains the user's own `FOR TABLE` publications (they are catalog rows); without an enabled role no subscriber can stream from them.

## Steps

1. Make recovery leave `spec.logicalReplication` out of the new Database.
2. State it in ADR009 and the runbook (enable the copy through the verb if it should publish).

- `lego/backend/internal/postgres/recovery.go`

## Acceptance criteria

## Out of scope

- Read replicas: logical decoding from a standby is not offered.

## Done (2026-11-21)

- **Already true:** `Recover` builds the copy's spec afresh and never carried `spec.logicalReplication`.
- **Found and fixed:** the backup restores the publisher role's `REPLICATION`, the subscriber role's `pg_create_subscription` and the source's subscriptions. The copy now retires the source's publisher and subscriber credentials when they are not its owner (`recoveredRetirements`), and CNPG strips both from the owner, which it manages. The operator runs a copy with `max_logical_replication_workers = 0` from its Cluster's creation until it is enabled as a subscriber (`holdsRecoveredSubscriptions`), so the restored subscriptions cannot connect to the source's publisher and take its slot; a copy recovered before the rule is not restarted for it. The verb refuses the copy's first subscriber enable while `pg_subscription` holds any, naming each (`LOGICAL_REPLICATION_SUBSCRIPTIONS_EXIST`). The source's managed settings no longer reach the copy in any spelling: `tenantParameters` used to drop only the canonical name, so `Hot_Standby_Feedback` (or `Archive_Mode`) survived.
- **Tests:** `TestRecoveredCopyIsNotEnabled`, `TestRecoveredCopyHoldsItsLogicalWorkers`, and on real PostgreSQL `TestRecoveredCopyRefusesASubscriberWhileHoldingItsSourcesSubscriptions`.
