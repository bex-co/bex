## Objective

An upgrade must not fail halfway or drop a subscriber's position silently because of logical slots. Before accepting an upgrade, bex reads the database's logical slots and refuses while any has not consumed all WAL. For a 13–16 source it accepts but tells the caller the slots will not survive.

## Context

- The shared verb: `validateVersionUpgrade` and `SetVersion` (`lego/backend/internal/postgres/service.go:1968`, `:2026`), reached from REST `PATCH /v1/postgres/{id}` (`version`), GraphQL `updateDatabaseVersion` and MCP `update_postgres(version:)`.
- PostgreSQL docs, pg_upgrade § Prepare for publisher upgrades: logical slots migrate only from a 17+ old cluster, every slot must be usable, and its `confirmed_flush_lsn` must equal the latest checkpoint. Confirm on dev-N what CNPG 1.30's in-place upgrade does when that check fails before writing the refusal.
- Slot state is readable through bex-api's direct query path (`lego/backend/internal/postgres/query.go`): `pg_replication_slots` (`slot_type = 'logical'`, `wal_status`, `confirmed_flush_lsn`).

## Steps

## Done (2026-11-21)

- **What pg_upgrade does** (checked locally on 2026-11-21 with PostgreSQL 16.15, 17.11 and 18.7 binaries and a real external subscriber, in place of dev-N): from 17 with a paused subscriber 50 rows behind it fails, `The slot "s" has not consumed the WAL yet`; from 17 with only a checkpoint behind it passes; from 17 with the subscriber streaming until shutdown it restores the slot and the subscriber resumed with every row exactly once; from 16 it passes and the slot is gone. CNPG 1.30.1 builds the new data directory's configuration from the Cluster (`wal_level = logical`), and a failed `pg_upgrade` leaves the Job failed until bex reverts `spec.version` (w4/m215).
- **Shared verb:** a publisher's upgrade reads every logical slot of the instance last (`logical_slots.go`). From 17+ it refuses with 409 `POSTGRES_UPGRADE_LOGICAL_SLOTS_BEHIND` naming each slot invalidated or not yet at the WAL position read when the check began, waiting up to 10 s for a streaming one; from 13–16 it accepts and answers `upgradeNotice` naming the slots it drops; an unreadable slot list refuses with 503 `POSTGRES_UPGRADE_LOGICAL_SLOTS_UNREADABLE`. A database that does not publish is not read. **Deviation:** the code is `POSTGRES_UPGRADE_LOGICAL_SLOTS_BEHIND`, not the task's `VERSION_UPGRADE_LOGICAL_SLOTS_BEHIND`, to match the verb's other `POSTGRES_UPGRADE_*` codes.
- **Dashboard:** the upgrade dialog shows the refusal inline (the server's message, naming the slots), and an accepted upgrade with a notice raises a warning toast that stays until dismissed.
- **Left:** a 17→18 upgrade on a real cluster keeping its slot: t006, on production.
