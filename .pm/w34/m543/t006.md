## Objective

Walk definition-of-done items 1, 3, 4 and 5 on a dev stack, with a counted write stream so lost or duplicated rows are visible.

## Context

- `scripts/dev-env.sh <N> up`, the operator from the tree, a Pro workspace, an HA PostgreSQL 18 database enabled through m541's verb, and an external `postgres:18` subscriber created with `failover = true`.
- A write stream with a monotonically increasing key makes gaps and duplicates countable.

## Steps

1. Start the stream; delete the primary's pod (forced failover); later run a switchover; compare keys on the subscriber.
2. Suspend and resume, change the plan, resize storage; compare again.
3. On a 17 database: request an upgrade while the subscriber is paused (refused), resume it until caught up, upgrade to 18, confirm the slot and streaming survive.
4. Recover a point in time from the enabled database; confirm the copy reads not enabled.
5. Record the conclusions in the milestone README; tear down.
