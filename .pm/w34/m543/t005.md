## Objective

Recovery creates a new database with a new `dpg-` id. Render enables logical replication per database id, so the recovered copy starts not enabled, without the role attribute, the all-tables publication or the WAL bound, however its source was configured.

## Context

- `Recover` (`lego/backend/internal/postgres/recovery.go:341`) copies the source's configuration into the new Database; check whether it would copy `spec.logicalReplication`.
- Restored data still contains the user's own `FOR TABLE` publications (they are catalog rows); without an enabled role no subscriber can stream from them.

## Steps

1. Make recovery leave `spec.logicalReplication` out of the new Database.
2. State it in ADR009 and the runbook (enable the copy through the verb if it should publish).

## Out of scope

- Read replicas: logical decoding from a standby is not offered.
