## Objective

Return real observed `host` values from `MetricsFilters` and honor `host`/`statusCode` cross-filtering over `[Start, End]`, matching Render's `GET /metrics/filters/http` contract.

## Context

- `lego/backend/internal/metrics/service.go:1427` falls into `default: []string{}` for `filterFieldHost`, so `/v1/metrics/filters/http` always returns `{"filter":"host","values":[]}`.
- `lego/backend/internal/metrics/rest.go:248-252` explicitly returns `400` whenever `statusCode` or `host` is passed to `/v1/metrics/filters/http`.
- `lego/backend/internal/metrics/source.go:854-896` (`NewPrometheusFilterValuesSource`) only passed `start` (`req.Since`) and never `end`.

## Steps

1. Add `[Start, End]` (`start` and `end` Unix timestamps) to `MetricsFilterValuesRequest` / `NewPrometheusFilterValuesSource` so unfiltered Prometheus `code` label discovery respects the requested window.
2. Add a Loki-backed HTTP filter-values source (`NewLokiHTTPFilterValuesSource`, wired when `BEX_LOKI_URL` is configured) that scans bounded Traefik request logs for `{namespace=..., app=..., type="request"}` over `[Start, End]` with optional `host` and `statusCode` filters to discover distinct observed `RequestHost` and `status` values (and cross-filter one dimension by the other).
3. In `MetricsFilters`:
   - When `HOST` is requested or when `Hosts`/`StatusCodes` cross-filters are supplied, use the Loki HTTP filter-values source (returning `core.ErrLogStoreUnavailable` when cross-filtering is requested with Loki unwired, or honest `[]` for `HOST` when unfiltered and Loki is unwired so Prometheus-only status-code discovery does not regress).
   - Deduplicate and sort values deterministically across multiple resources.
4. Wire `NewLokiHTTPFilterValuesSource` in `lego/backend/internal/api/server.go`.

## Acceptance criteria

- [x] `GET /v1/metrics/filters/http` returns real observed `host` values alongside `statusCode` values over `[startTime, endTime]`.
- [x] Passing `?host=api.example.com` narrows returned `statusCode` values to codes observed on that host, and passing `?statusCode=5xx` narrows returned `host` values to hosts that served 5xx responses.
- [x] Unfiltered status-code discovery on a Prometheus-only (no Loki) server still succeeds using `[start, end]` bounded Prometheus label discovery.
