## Objective

CNPG keeps logical slots through a failover on 13–16 only with the `pg_failover_slots` extension, which is not in the image bex runs today. Until it is, say so where an operator and a user will see it, instead of losing a subscriber's position silently.

## Context

- ADR092's operand image is blocked ([w8/m92](../../../../w8/m92/README.md)); [w8/276](../../../../w8/done/276.md) is the extension supply item beside it.

## Steps

1. Record the gap in the ADR018 logical-replication row with w8/m92 as owner.
2. Make m541's verb answer an enable on an HA 13–16 database with a warning that a failover makes subscribers resync from a new copy, and put the same sentence in the runbook.
3. Add a note to w8/m92 (through `/pm`) that `pg_failover_slots` is a requirement for this.

## Done (2026-11-21)

- **Gap recorded:** the ADR018 row "Logical replication (lifecycle)" names the HA 13–16 loss with w8/m92 as its owner; ADR092 § Consequences records `pg_failover_slots` as a requirement of the operand image. The note goes to ADR092 rather than w8/m92's board files, which this worker may not edit (worker.md § Scope).
- **Verb:** an enable of an HA publisher answers `warnings`: on 13–16, that a failover loses every slot and subscribers must be re-created (naming w8/m92); on 17+, that a subscription keeps its place only `WITH (failover = true)` (`failoverWarnings`, from the server's own major). The runbook says the same. Covered by `TestFailoverWarnings` and the real-PostgreSQL `TestHAPublisherEnableWarnsAboutFailover`.
