## Objective

Allow `GET /v1/metrics/disk-usage`, `GET /v1/metrics/disk-capacity`, `GET /v1/metrics/active-connections`, and `GET /v1/metrics/replication-lag` (plus bex datastore metric routes) to accept multiple `resource` query parameters, matching Render's pinned OpenAPI contract.

## Context

- `lego/backend/internal/metrics/rest.go:374-395` (`parseDatastoreMetricParams`) enforces `len(resources) != 1` (`"exactly one resource is required"`).
- `lego/backend/internal/api/openapi/render-public-api-1.json` documents `resource` on all four endpoints as _"When multiple resource query params are provided, they are ORed together"_, with `disk-usage` and `disk-capacity` accepting mixed `srv-`, `dpg-`, and `red-` IDs, `active-connections` accepting `dpg-` and `red-`, and `replication-lag` accepting `dpg-`.
- `lego/backend/internal/metrics/service.go:448-454` (`checkFanOut`) bounds multi-resource fan-out.

## Steps

1. Update `parseDatastoreMetricParams` (and callers `datastoreMetricQuery` and `activeConnectionsQuery` in `lego/backend/internal/metrics/rest.go`) to return `[]string` of requested resources (requiring ≥1), enforce `checkFanOut(len(resources), 1, 1)`, and resolve `kind` per resource (using explicit `kind` when provided, else `datastoreKindFor(res)` per ID so mixed `srv-`/`dpg-`/`red-` requests work on `disk-usage` and `disk-capacity`, and mixed `dpg-`/`red-` work on `active-connections`).
2. Loop over each resource, calling `s.DatastoreMetrics` (authorizing each independently and failing closed on any unauthorized/unknown/invalid-kind resource), and merge all returned series into one Render-shaped JSON array (non-nil `[]` when empty).
3. Ensure every returned series carries its canonical `resource` label so callers can distinguish each resource's points.

## Files

- `lego/backend/internal/metrics/rest.go`
- `lego/backend/internal/metrics/datastore.go`

## Acceptance criteria

- [x] `GET /v1/metrics/disk-usage?resource=dpg-a&resource=srv-b` and `/disk-capacity`, `/active-connections?resource=dpg-a&resource=red-b`, and `/replication-lag?resource=dpg-a&resource=dpg-b` return merged, resource-labeled series in one `200` response.
- [x] Over-budget resource lists fail with `400` (`checkFanOut`), and any unauthorized or unknown resource in the list fails closed (`403`/`404`).
- [x] Single-resource requests remain byte-identical.

## Out of scope

- Changing GraphQL `datastoreMetrics` single-resource input signature (keep backward-compatible).
