## Objective

Enable `*` wildcard path patterns (such as `/user/*` or `/api/*/items`) in HTTP request-count and HTTP latency metric queries across REST, GraphQL, and MCP while keeping exact matching for literal paths without `*`.

## Context

- `lego/backend/internal/metrics/lokisource.go:173-195`: `lokiOrFilter("request_path", req.Paths)` emits `request_path="..."` for every path, so Render's wildcard example `/user/*` only matches the literal string `/user/*`.
- REST (`GET /v1/metrics/http-requests`, `/http-latency`), GraphQL (`metrics`), and MCP (`get_metrics(httpPath:)`) all funnel through `MetricQuery.Paths` → `lokiRequestPipeline`.

## Steps

1. Add a helper `lokiPathFilter(field string, paths []string) string` in `lego/backend/internal/metrics/lokisource.go`:
   - If a path contains no `*`, keep exact equality `request_path="..."`.
   - If a path contains `*`, escape all literal segments with `regexp.QuoteMeta`, replace `*` with `.*`, anchor with `^...$`, and emit `request_path=~"..."` (using `%q` escaping so no LogQL injection is possible).
   - OR multiple path predicates together, deduplicating empty/repeated inputs.
2. Enforce reasonable bounds on wildcard count / pattern length in `metrics.Service` so pathological patterns are refused with `400` rather than stressing Loki's RE2 engine.
3. Verify the same helper is shared by `PathFilterSuggestions` (`t001`/`t002`) when filtering candidate paths by `?path=`.

## Files

- `lego/backend/internal/metrics/lokisource.go`
- `lego/backend/internal/metrics/service.go`

## Acceptance criteria

- [ ] `path=/api/*` matches `/api/v1/users` and `/api/health` and does not match `/v2/api/health`; regex metacharacters like `.`, `+`, `?`, `(`, `)` in a wildcard path are treated literally.
- [ ] Paths without `*` emit the exact same `request_path="..."` LogQL filter as before.
- [ ] REST, GraphQL, and MCP all honor wildcard path filters identically through the shared service.

## Out of scope

- Full arbitrary regex syntax `/.../` beyond `*` glob wildcards.
