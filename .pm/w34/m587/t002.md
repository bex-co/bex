## Objective

Connect REST `GET /v1/metrics/filters/path` and GraphQL `metricsPathFilterSuggestions` to `Service.PathFilterSuggestions` so both surfaces accept multi-resource and filter inputs and enforce authorization.

## Context

- `lego/backend/internal/metrics/rest.go:263-272` (`pathFilters`) currently authorizes only one `resource`, ignores `startTime`/`endTime`/`host`/`statusCode`/`path`, and always returns `[]string{}`.
- `lego/backend/internal/metrics/graphql.go:476-484` (`metricsPathFilterSuggestions`) currently returns `metricsPathFilterSuggestionsResult{Paths: []string{}}, nil` without reading `query` or authorizing `serviceIDs`.

## Steps

1. Update `pathFilters` in `lego/backend/internal/metrics/rest.go` to parse repeatable `resource`/`service` (required, ≥1), `startTime`/`endTime`, repeatable `host`, repeatable `statusCode`, and repeatable `path`, call `s.PathFilterSuggestions`, and serialize a non-nil JSON `[]string` (`[]` when empty).
2. Update `metricsPathFilterSuggestions` in `lego/backend/internal/metrics/graphql.go` to parse `serviceIDs` (required, ≥1) and optional `paths` (and optional `start`/`end`/`hosts`/`statusCodes` if present on the input type without breaking existing clients), call `s.PathFilterSuggestions`, and return `{paths}` (failing on unauthorized or unknown `serviceIDs`).
3. Verify the REST handler passes `rendertest` OpenAPI validation (`list-path-filter-values`).

## Files

- `lego/backend/internal/metrics/rest.go`
- `lego/backend/internal/metrics/graphql.go`

## Acceptance criteria

- [ ] `GET /v1/metrics/filters/path` accepts multiple `resource`, `host`, `statusCode`, `path`, `startTime`, and `endTime` params and returns real suggestions from `PathFilterSuggestions`.
- [ ] GraphQL `metricsPathFilterSuggestions` rejects unauthorized or unknown `serviceIDs` and returns the same suggestions as REST.
- [ ] Empty results serialize as `[]` (never `null`).

## Out of scope

- Dashboard UI autocomplete redesign (existing GraphQL query shape stays backward-compatible).
