## Objective

Decide and write what enabling a bex database as a subscriber grants, per PostgreSQL major, so the user can run `CREATE SUBSCRIPTION` themselves as Render's docs describe.

## Context

- PostgreSQL 16+: a member of `pg_create_subscription` with `CREATE` on the database can create subscriptions. A non-superuser subscription owner must authenticate to the publisher with a password (`password_required`), which every bex and Render connection string carries.
- PostgreSQL 13–15: `CREATE SUBSCRIPTION` needs a superuser. Options: an ops-run CNPG `Subscription` from the verb's inputs (publisher connection, publication name), which is what Render's support team can do; or a named refusal, which is a divergence needing the user's sign-off.
- bex accepts majors 13–18 (`docs/ADR009-postgresql-management.md` § version; default `18`, `lego/types/v1alpha1/database_types.go:110`).

## Steps

1. Write ADR009 § Logical replication › Subscribers: the grant per major, the 13–15 choice (recommended: the CNPG `Subscription`), the egress rule from t003, and what the user does (create tables first, `CREATE SUBSCRIPTION`, sequences by hand).
2. Add the subscriber half to the ADR018 row m541/t001 wrote.
