## Objective

A subscriber's apply worker runs in the database's own CNPG instance pod, so that pod must reach the publisher on TCP 5432: another workspace's bex database through its external URL, a same-workspace one through its internal host, or a host outside bex. Open only what an enabled subscriber needs.

## Context

- [ADR043 D8.3](../../../docs/ADR043-tenant-namespace-isolation.md) lists today's datastore allows; the apiserver egress lives in GitOps (`deploy/gitops/base/datastore-control-egress.yaml`), and bex-api may not create Cilium policies in a hosting namespace (ADR043 D6).
- From inside the cluster, `<id>.db.bex.co` resolves to the public load balancer; whether that hairpins back to `pg-sni-proxy` is unverified.

## Steps

1. On dev-N, from an instance pod, try TCP 5432 to: a same-workspace database's `-rw` Service, another workspace's external URL, and an outside host. Record each result.
2. For each that fails and is needed, add the narrowest allow selecting only enabled subscribers (a label the operator sets while `subscriberRole` is set), in the layer ADR043 assigns (GitOps for cluster-wide Cilium, the namespace reconciler for k8s NetworkPolicy).
3. Add the policy to `scripts/gitops-validate.sh`'s guards if it is GitOps.

## Files

- `deploy/gitops/base/` (a new or extended policy) or `lego/backend/internal/tenancy/`
- `lego/operator/internal/controller/database_controller.go` (the label)
- `docs/ADR043-tenant-namespace-isolation.md` (D8.3 table)

## Acceptance criteria

- [ ] An enabled subscriber reaches its publisher on all three paths.
- [ ] A database that is not enabled gains no egress (checked on dev-N).

## Out of scope

- Any egress port other than 5432.
