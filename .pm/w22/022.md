# Sandbox API calls: the user signs off on, raises or removes the 10,000-a-minute workspace bound

Why: Render documents sandbox rate limits per user only, and bex also refuses a workspace whose members together send more than 10,000 sandbox operations a minute, a divergence ADR018 lists as awaiting the user's sign-off.

From w22/m443 (2026-11-20). The milestone shipped the bound as an ADR104 D11 abuse control in place of the general 500-a-minute workspace bucket sandbox calls spent before, so it is looser than what it replaced.

- **Where.** `sandboxWorkspaceRatePerMinute` in `lego/backend/internal/sandbox/ratelimit.go`; the row "Workspace bound on sandbox API calls" in `docs/ADR018-render-parity.md`.
- **When it differs from Render.** One user spending every class in full sends 3,610 a minute, so only when three or more members run every class near its limit at once.
- **The choices.** Keep 10,000 (sign the divergence), raise it, or remove it (the parity-sufficient variant: set the constant aside and charge only the user's class bucket).
- **Done when:** the ADR018 row carries the user's decision and its date, and the code matches it.
