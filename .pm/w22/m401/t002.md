## Objective

Alert on the symptom a tenant sees when Zot, its network path or a garbage-collected tag fails: a tenant container stuck pulling an image that the platform registry should serve. Distinguish it from a tenant's own bad image reference, which is not a platform defect.

## Context

- The only pull-failure rule today is `StrandedNodeLocalImages` (`deploy/gitops/base/rules/alerting_rules.yml`, ~line 1640): `kube_pod_container_status_waiting_reason{reason=~"ImagePullBackOff|ErrImageNeverPull", namespace="default"}` for 10 minutes. It is scoped to `namespace="default"` and was written for node-local `ctr` imports; a tenant namespace is the workspace id (`tea-…`), which it cannot see. It also omits `ErrImagePull`, the first state before backoff.
- `kube_pod_container_info` carries the `image` label, so it joins to the waiting-reason series on `(namespace, pod, container)`.
- How tenant pods name the registry: the operator's `Registry` setting is `zot.bex-registry.svc:5000` (`lego/operator/internal/controller/app_controller.go`, ~line 348), while kubelet on tenant nodes pulls through `127.0.0.1:30500` (`deploy/gitops/base/zot.yaml` comment, containerd `hosts.toml`). Read how the Deployment's container `image` is written for a Git-built service (`lego/operator/internal/controller/deployment_projection.go` and the `registry` handling near `app_controller.go:2354`) and match what really appears in `kube_pod_container_info`, not a guess.

## Steps

1. Confirm `kube_pod_container_info` and `kube_pod_container_status_waiting_reason` are both scraped (`grep -rn "kube_pod_container_info\|kube-state-metrics" deploy/gitops`). If a metric allowlist drops `image`, extend it in the same change.
2. Establish the real `image` prefix of a Git-built tenant service (read it from the mock cluster's pod spec, or from the operator's projection code) and write the matcher from it. Record the prefix in a comment.
3. Add `TenantRegistryImagePullFailing`: waiting reason `ImagePullBackOff|ErrImagePull`, `image` matching the platform registry prefix, namespace not in the platform-namespace list the pack already uses (reuse the regex from `PlatformDeploymentNotReady`, inverted, or a `tea-.*` matcher if that is how tenant namespaces are named; state which and why), `for: 10m` to match `StrandedNodeLocalImages` unless step 1 of t001 suggests a different registry-restart window. Severity warning; the description names `kubectl -n bex-registry get pods` and `kubectl describe pod` as the first checks, and says that one affected pod with the others healthy points at a garbage-collected tag rather than a Zot outage.
4. Leave `StrandedNodeLocalImages` as it is, except for the stale comment (t003).
5. Add `deploy/gitops/base/rules/registry_pull_alerts_test.yml`: a platform-registry image in `ImagePullBackOff` for 10m fires; the same with `ErrImagePull` fires; one minute short does not; an image on `docker.io` does not; a pod in a platform namespace does not; a healthy pod does not.
