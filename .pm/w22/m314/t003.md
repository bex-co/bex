## Objective

Add the used-CPU meter: per running interval, CPU-seconds from cAdvisor, written to `usage_hourly`, deferred and marked partial when Prometheus is unreachable, never billed as zero.

## Context

- `lego/backend/internal/metrics/source.go` already queries `container_cpu_usage_seconds_total` and `container_memory_working_set_bytes` for App metrics through the `kubernetes-cadvisor` job; reuse its query client, not a new one.
- `increase()` handles a counter reset when a pod is recreated.
- ADR023 describes the independent, gapless-cursor meter pattern; storage precedent in w22/m313.

## Steps

1. Add the usage kind `sandbox_cpu_seconds` (CPU-seconds).
2. For each closed or ongoing interval from t002, query `increase(container_cpu_usage_seconds_total{pod=...,namespace=...})` over exactly that interval and accrue it hour by hour.
3. If Prometheus is unreachable or returns no series for a running interval, defer the window and mark it `partial`; never write zero.
4. Test with a fake Prometheus: normal window, counter reset, missing series, outage then recovery.

## Files

- `lego/backend/internal/sandbox/meter.go` (or a sibling `cpu_meter.go`)
- `lego/backend/internal/store/usage.go`, `sandbox_meter.go`
- `lego/backend/internal/metrics/source.go`

## Acceptance criteria

- [ ] One CPU-minute of busy time yields about 60 CPU-seconds in the usage row
- [ ] A Prometheus outage defers, then catches up, without double counting or a zero
- [ ] An idle running sandbox accrues close to zero

## Out of scope

- Billing it (t004)
