# Sandbox group list and paging: the places bex's answers differ from Render's error vocabulary

Why: w22/m311 t008 (Render parity) found small differences in `GET /v1/sandbox-groups` and the group routes that are outside the milestone's scope but must not go unrecorded; the pinned OpenAPI `errorCode` vocabulary is the reference, and live Render behavior was not checked.

Found 2026-11-10, none fixed:

1. `GET /v1/sandbox-groups` without `ownerId` answers a codeless 400, and a repeated `ownerId` passes with the first value winning. Render's vocabulary has `invalid_owner_id`, though the pin does not tie it to this operation.
2. A `limit` outside 1..100 gives REST a codeless 400 (Render's vocabulary: `invalid_limit`), while GraphQL and MCP clamp. The three surfaces differ; this is repo-wide pagination policy, not groups only.
3. An unknown or malformed `cursor` returns an empty page; the vocabulary says `invalid_cursor` (400). Also repo-wide.
4. GraphQL and MCP group lists carry no cursor field, and the MCP description does not say the cursor is the last group's id. Harmless while a workspace has at most 10 groups and the default page is 20.
5. With the group cap turned off, `store.maxSandboxGroupsListed = 1000` truncates the list silently.
6. A non-member's `ownerId` answers 403 (the repo convention) where the pin lists 404 for create and list; the pin also lists a 409 on update that bex never returns.

Also open, to be settled by the production walk (w22/m311 t007): after a terminate the binding is released at once, so a sandbox OpenSandbox still lists as Running for a moment is counted under the default group.

Size: a few small fixes plus a decision on whether pagination errors should follow Render's vocabulary everywhere; promote it with `/pm promote w22/004` when its turn comes, and read Render's live API first.

## Blocked

Blocked 2026-11-10 (`/loopx w22`). Items 1 to 3 and 6 change shared pagination and authorization behavior across every list endpoint, and the pinned OpenAPI does not tie the codes to these operations, so changing them on the pin's say-so could introduce a drift instead of closing one. Item 4 is harmless at ten groups, and item 5 needs the group cap turned off. The production walk (w22/m311 t007) also has to settle the terminate-release question.

## 解阻记录 2026-11-14（/unblock w22）

- **来源：** 用户决定（D2，2026-11-14）。
- **决定：** `GET /v1/sandbox-groups` 的 REST 分页和参数错误按 Render OpenAPI pin 的 `errorCode` 词汇改：缺 `ownerId`（或重复）返回 400 `invalid_owner_id`，`limit` 越界返回 400 `invalid_limit`，未知或格式错误的 cursor 返回 400 `invalid_cursor`（现在返回空页）。GraphQL 和 MCP 保持现有的 clamp，因为 Render 没有这两个面。
- **用户接受的取舍：** 没有真实 Render 账号做对照，只有 pin 做依据；pin 没有把这些码绑定到具体操作，日后可能要微调。要验证真实行为，需要 w10/002 里记录的 `RENDER_API_KEY`（用户有 Render 账号后才有）。
- **对标依据：** render.com 的 API 契约（pin 的 `errorCode` 词汇）；客户可见的变化：原来的无码 400 带上错误码，传了坏 cursor 会得到 400 而不是空页。
- **worker 的下一步：** (1) 先看分页校验是否在共享 helper 里；若是，按 Render 对标让所有 REST 列表同一套词汇，并在 ADR018 记录；若改动大于一小时，只改 sandbox-groups 这一个列表，并把"其余列表"另开一条 inbox 笔记。(2) 第 4 项（GraphQL/MCP 的 cursor 字段和 MCP 描述）顺手补；第 5 项只在组数上限关闭时才需要；第 6 项（非成员 `ownerId` 返回 403 而 pin 写 404）不在本次决定内，按"安全约定"保留并记入 ADR018 作为偏离，除非发现更强的对标证据。(3) 每个新错误码都有 REST 测试，GraphQL 和 MCP 的 clamp 行为不变并有测试钉住。
- **验收：** 上述三个错误在 REST 上返回 Render 词汇里的错误码；`bash scripts/docs-links-validate.sh` 通过；ADR018 的 sandbox 组那一行更新。


## Outcome (2026-11-14)

- **Done.** The REST `GET /v1/sandbox-groups` answers `invalid_owner_id` (missing, empty or repeated `ownerId`), `invalid_limit` (outside 1 to 100, or not a number) and `invalid_cursor` (not an `sbg-` id), from the pinned errorCode vocabulary: `sandbox.ValidateGroupListQuery` and a `list-sandbox-groups` refusal in the gate (`lego/backend/internal/api/render_openapi.go`). Test: `TestSandboxGroupListAnswersRendersErrorCodes` (12 cases; eight fail without the gate change).
- **One reading of the decision, stated plainly.** The user's D2 said a bad cursor answers 400 `invalid_cursor`. The pin's text is "the cursor is malformed", and the repository documents that a cursor naming no item is an empty page (Render's end of list), so only a cursor that is not an `sbg-` id is refused; a well-formed cursor naming no group stays an empty page.
- **Items of the note.** (1) to (3) done as above. (4) and (5) not done: with at most 10 groups a workspace and a default page of 20 a cursor is never needed, and (5) needs the cap off. (6) stays the repository's 403, recorded in ADR018 as an open drift. The "terminate releases the binding at once" question was settled by the production walk (w22/m311 t007).
- **Follow-up.** The build list's codes are w22/016.
