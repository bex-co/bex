## Objective

Get a node that can run `runsc` pods where changing runtime flags cannot affect any customer, and record exactly what it runs.

## Context

- The production pool is labelled `bex.co/pool=sandbox` and tainted `bex.co/sandbox=true`; RuntimeClass `gvisor` has handler `runsc` (`deploy/opensandbox/gvisor-runtimeclass.yaml`).
- `--net-raw` and `--allow-packet-socket-write` are node-level containerd `runsc` settings that apply to every pod on the node (gVisor Docker-in-gVisor tutorial, cited in ADR104 D6). They must never be applied to the production pool.
- Unverified: whether the local CAPD/kind cluster (`scripts/mock-cluster.sh`) can run `runsc`, and whether `infra/` can add a throwaway Hetzner pool.

## Steps

1. Check whether a non-production node with gVisor already exists; otherwise **try a local throwaway node first (user decision D4, 2026-11-16)**: a separate, disposable colima VM profile running a single-node Kubernetes with Cilium and runsc, never the production pool and never at the same time as the dev-N stack's VM. A one-node billable pool through `infra/` was **not** approved: if the local node cannot run runsc or reproduce Cilium's FQDN policy, park the milestone again with that as the gate.
2. Record runsc version, kernel and node image; these are the ADR104 D6 "unverified on bex's nodes" facts.
3. State the teardown step and owner before provisioning anything billable.

## Files

- `infra/` (only if a throwaway pool is provisioned)
- `docs/ADR104-sandbox-render-parity.md` D6 (facts recorded in t007)

## Acceptance criteria

- [x] A node exists where `kubectl run` with the gVisor RuntimeClass works and no tenant workload is scheduled
- [x] runsc version, kernel and node image are written down

## Out of scope

- Any change to the production pool or its containerd configuration

Done on a free local node (user decision D4). A throwaway colima VM (profile `gvisor-spike`, Apple VZ aarch64, Ubuntu 24.04.4, kernel `6.8.0-117-generic`) ran single-node k3s `v1.34.13+k3s1` (containerd `2.2.10-k3s1`) with Cilium 1.19.5 and runsc `release-20260622.0` (production's pin) and `release-20261102.0`. `kubectl run` on the `gvisor` RuntimeClass reported kernel `4.19.0-gvisor`; the node ran no tenant workload. The default colima profile was stopped while it ran and restarted afterwards. Nothing billable was provisioned. Facts are in ADR104 D6 (isolation results, 2026-11-16).
