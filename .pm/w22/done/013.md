# `bex agent stop`, and `send --wait` for a queued message

Why: the server queue and Stop turn shipped with `bex agent chat /stop`, but a script or CI job that sends to a running session cannot stop the turn from the CLI, and `send --wait` against a running session returns at once instead of waiting for its own message's turn.

- **Evidence.** w22/m403 t006: `lego/cli/internal/agent/agent.go` `bex agent send` prints `Queued (position N): it runs when the session's running turn ends.` and, with `--wait` or `--follow`, returns at once with "Not waiting: a queued message runs as its own turn." (waiting would otherwise report the running turn's outcome, not the queued message's). Chat has `/stop` (`chat.go`, `POST /v1/agent-sessions/{id}/interrupt`), and `bex agent` has no `stop` subcommand. ADR106 lists the command tree; Devin's CLI is the reference.
- **Steps.** (1) `bex agent stop <session>`: calls the interrupt verb, prints the same text as `/stop`, exit codes like `cancel` (0 on 202, a named non-zero on `AGENT_SESSION_NO_TURN_RUNNING` and `AGENT_SESSION_TURN_STARTING`), `--json` passes the API bytes through; (2) make `send --wait` on a queued send wait for the turn that message starts: poll `GET .../queued-messages` until the message is no longer pending, then follow the session as `send --wait` does for a direct send; `--follow` the same; (3) update ADR106, `docs/bex-cli.md`, `lego/cli/README.md` and the CLI contract fixture if a shape changes; (4) `cd lego/cli && go test ./...` with a fake server per case.
- **Done when:** `bex agent stop` ends a running turn from a script, and `send --wait` against a running session returns the outcome of the message it queued.

## Done 2026-11-14 (/loopx w22)

- `bex agent stop <session>` calls the interrupt verb with no confirmation (the session stays open). Success prints `Stopping the current turn. The session stays open and any queued messages run next; `bex agent cancel` ends it.` (chat's `/stop` says `/cancel`) and exits 0; `-o json`/`-o yaml` print the API bytes. `AGENT_SESSION_NO_TURN_RUNNING` exits 7 (`stop: no turn is running, so there is nothing to stop`), `AGENT_SESSION_TURN_STARTING` exits 8 (`stop: the turn is still starting; try again once the agent is working`), any other refusal exits 1. The codes 7 and 8 are a choice of the implementation (the note said "a named non-zero"); they are in the root help, `docs/bex-cli.md` and ADR106.
- `send --wait` and `--follow` on a queued 202 print `Queued (position N): … Waiting for it.`, poll the queue by message id (2 s rising to 15 s, chat's between-turn poll), then wait for or stream the turn that message starts and exit by that turn's state; stdout is the settled session. If no new turn started when the message left the queue (the server dropped it), it prints `the queued message was not started; see the session` and exits 1. One `--timeout` covers the queue wait and the turn; a deadline in the queue wait exits 124 and says the message is still queued, Ctrl-C exits 130 and leaves it queued. An older server's 409 `AGENT_SESSION_TURN_IN_FLIGHT` is still exit 1 with no polling.
