# Pre-deploy commands get Render's 30 minutes, not 10

Why: Render's deploy step table gives the pre-deploy command 30 minutes, bex kills it at 10, so a long migration that finishes on Render fails on bex; ADR018 marks Pre-Deploy ✅ and records no divergence.

- **Render.** [render.com/docs/deploys](https://render.com/docs/deploys), read 2026-11-14: step limits are Build 120 minutes, Pre-deploy 30 minutes, Start 15 minutes. bex already matches Build (`lego/operator/internal/build/build.go`, `BuildTimeout = 120 * time.Minute`, raised 2026-10-24 for beancount-cms-v2) and has no sign-off for a shorter pre-deploy.
- **bex.** `lego/operator/internal/predeploy/predeploy.go`: `const predeployTimeout = 10 * time.Minute` (the Job's `activeDeadlineSeconds`, ~line 77; the failure text takes its `{minutes}` from it at ~line 281). `lego/backend/internal/store/reconciler.go`: `defaultPreDeployGateTimeout = 12 * time.Minute` (~line 97), the control-plane fallback, which must stay longer than the Job (w7/m80 t002's rule: a gate that observes a mechanism is strictly longer than it; the build gate is 125 minutes for a 120-minute Job). The dashboard words the failure from the `{minutes}` parameter (`dashboard/src/features/deploys/locales/en.ts` and `zh.ts`), so it needs no change.
- **Docs saying 10.** `docs/ADR018-render-parity.md` line ~108 ("did not finish within its 10-minute window"), `docs/ADR004-app-deployment.md` ~line 288 ("the 10-minute deadline") and ~line 437 ("pre-deploy commands receive 12 minutes (longer than their 10-minute Job deadline)"; the same sentence still gives the build numbers as 35 and 30 minutes, which are stale: 125 and 120).

Steps:

1. `predeployTimeout` to `30 * time.Minute`; fix its comment and `FailureMessage` still reads the minutes from it.
2. `defaultPreDeployGateTimeout` to `35 * time.Minute` (30 + the 5 minutes the build gate adds), with its comment updated; `lego/backend/internal/store/reconciler_test.go` (~lines 2174 and 2187) builds its cases from the constant and needs no new numbers.
3. Tests: in `lego/operator/internal/predeploy/predeploy_test.go` pin the Job's `activeDeadlineSeconds` at 1800 and, in `failure_message_test.go`, that the deadline-exceeded message carries "30"; in the backend add a test that `defaultPreDeployGateTimeout` is longer than 30 minutes (the operator constant is not importable from backend, so the cross-check is a number in each test and a comment in each constant pointing at the other).
4. Docs: ADR018 row, ADR004 lines above (and correct the stale build numbers in the same sentence), citing Render's page and the date.
5. Optional and cheap: on the local cluster (`bash scripts/mock-cluster.sh operator`), a pre-deploy `sleep 700` completes, where the old 10-minute limit would have killed it. Record the result in this note.
6. `cd lego/operator && make test`, `cd lego/backend && go test ./internal/store/...`, `make lint`.

Done when: a pre-deploy command is allowed 30 minutes, the failure text says "30-minute window", the control-plane gate stays longer than the Job, and ADR004 and ADR018 say 30.

Out of scope: the free-plan restriction (w8/m131), `.pm/w4/blocked/m336`'s reason-text work (it takes the minutes from the same parameter), Render's 15-minute Start budget.
