## Objective

v2.38.0's once-a-day "a newer release is available" notice never tells a `bex` user to install a Render CLI release.

## Context

- This is a third update-check call site. The two known ones: the root `--version` path intercepted in `main.go`, and the login banner suppressed in `lego/cli/internal/bridge/transport.go` (upstream's `cfg.RepoURL + "/releases/latest"` answered with a local 404, `TestUpstreamReleaseCheckNeverAdvertisesRenderCLI`).
- The new code may use another HTTP client, another URL or a cache file under the state directory, so the existing seam may or may not cover it.

## Steps

1. Read the new notice's code upstream: what it fetches, with which client, where it caches, and when it prints.
2. Make it print nothing about Render releases (extend the transport seam if it covers the request; otherwise disable it at its own seam), and decide whether `bex` prints its own release hint there, as it does after login.
3. A test that drives a command with a stale cache and a reachable "latest" answer and fails if stderr names a Render CLI release.
4. Document the third call site in `UPSTREAM_RENDER_CLI.md` step 3.

## Files

- lego/cli/internal/bridge/transport.go (or the new seam)
- lego/cli/UPSTREAM_RENDER_CLI.md

## Acceptance criteria

- [x] The new test fails with the seam removed and passes with it.
