## Objective

Let a sandbox group record the project environment it was placed in.

## Context

- `sandbox_groups` (migration 0221) has no environment column; `store.SandboxGroup` (`lego/backend/internal/store/sandbox_groups.go`) has no field for it, and `Group.EnvironmentID` is always null (`lego/backend/internal/sandbox/groups.go`).
- The precedent is `env_groups.environment_id text REFERENCES environments (id) ON DELETE SET NULL` with a partial index (migration 0149_env_groups.up.sql) and `envgroups.go` reading it with `COALESCE(environment_id, '')`.
- Migrations are numbered `NNNN_name.{up,down}.sql`: other workers take numbers, so re-scan `git ls-tree --name-only origin/main lego/backend/internal/store/migrations/` before writing (0269 was the highest on 2026-11-14).

## Steps

1. Write failing real-Postgres tests first: a group created with an environment reads it back; deleting the environment sets it to null and keeps the group; a group in no environment reads empty.
2. Add the migration (nullable column, `ON DELETE SET NULL`, a partial index on the non-null values) and its down file.
3. Add `EnvironmentID string` to `store.SandboxGroup`, write it in the create path, select it in every read path (`SandboxGroups`, get by id, default group).
4. Document the column in ADR042 § Sandbox groups in one sentence.
