## Objective

Accept an optional `environmentId` when a group is created on REST, GraphQL and MCP, place it through the same environment resolver every other resource kind uses, and echo it on reads.

## Context

- Render: "In the Dashboard, you can optionally place a group in a project environment" (render.com/docs/sandboxes-creating, read 2026-11-14); the page says nothing about scope or visibility, and the pinned OpenAPI's `create-sandbox-group` body has only `ownerId`, `name` and `region` while the response carries a nullable `environmentId`. So the meaning here is membership only: a group belongs to an environment, and who can see it stays the workspace's (decided in the 2026-11-14 record of w22/003).
- bex's precedent for a resource placed in an environment is `lego/backend/internal/envgroups/service.go`: `Service.Environments core.EnvironmentResolver` (`environments.NewCreateResolver`, wired in `lego/backend/cmd/api/main.go`) validates the association, refuses another workspace's environment as not found, and requires an Admin to place into a protected environment (w3/m281).
- The REST gate validates the body against the pinned schema (`lego/backend/internal/api/render_openapi.go`, `applyRenderSchemaCompatibility` widens it for bex extensions, e.g. `widenWebhookEventFilter`); an `environmentId` the pin lacks is refused today. Official clients never send it, so widening changes nothing for them.
- GraphQL and MCP: `lego/backend/internal/sandbox/groups_surfaces.go` and `graphql.go`; the MCP tool list is pinned in `lego/backend/internal/agentsessions`-style golden JSON for the sandbox tools (grep `create_sandbox_group` in `testdata`), and `lego/backend/internal/sandbox/groups_surfaces_test.go` drives the three surfaces with one outcome type.

## Steps

1. Write failing tests first (service and `groups_surfaces_test.go`, one outcome for REST, GraphQL and MCP): create with an environment of this workspace returns it as `environmentId`; another workspace's environment id answers the not-found of an id that does not exist; a protected environment refuses a non-admin; an omitted or null `environmentId` stays null; list and get echo it.
2. `CreateGroupRequest` gets `EnvironmentID`; `Service` gets the `Environments` resolver field, wired in `cmd/api/main.go` the way envgroups' is; the service resolves it before the store write and stores it; `groupView` returns it.
3. REST: widen `create-sandbox-group`'s body schema for an optional string `environmentId` in `applyRenderSchemaCompatibility`, with a gate test (`render_openapi_sandbox_groups_test.go` style).
4. GraphQL: an optional `environmentId` argument on the create mutation and the field on the type; MCP: the optional parameter on the create tool with its description; regenerate `testdata/mcp_tools.golden.json`, the GraphQL schema dump and the dashboard's generated types (`SCHEMA_DUMP_PATH` method in `lego/AGENTS.md`/`dashboard/AGENTS.md`; never run prettier on `dashboard/src/graphql/*.ts`).
5. Update `render-artifacts/sandbox-groups.md` and ADR042 § Sandbox groups.
