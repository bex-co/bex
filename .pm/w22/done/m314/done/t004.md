## Objective

Switch sandbox billing to Render's model in one step for every workspace, billing the measured CPU. (The older wording said: or, if t001 failed, record the fallback as a divergence for the user to sign; that branch is not taken, see step 2.)

## Context

- Rates (ADR104 D8; render.com/articles/render-sandboxes-vs-vercel-sandboxes, 2026-11-06): Render $0.12 per active CPU-hour and about $0.019 per GB-hour; bex × 0.70 gives $0.084 and $0.0133 (`pricing.yaml` convention). Keep them in `pricing.yaml`, not code.
- `outcome.cost` for agent sessions keeps `sandbox_compute_seconds` (w9/m178, `AgentSessionComputeMilliSeconds`); do not change its basis.
- Parity rule: no allowlist or canary for a customer-facing change; one dated effective timestamp for every workspace. No retroactive re-pricing.

## Steps

0. **Before switching (added 2026-11-16):** read a sandbox pod's CPU limit against its plan (`1c-2g` is 1 CPU, 2 GiB; `lego/backend/internal/sandbox/models.go`, `client.go`) and record in ADR104 D8 whether the limit caps the used-CPU charge at the plan's allocated shape. If it does not, say so in the usage notes; the cutover still bills the measured CPU.
1. Bill the measured CPU (**the branch taken, per the README's "解阻记录 2026-11-16"**). Pass branch: price `sandbox_cpu_seconds` and `sandbox_memory_gb_seconds`; from the effective timestamp stop billing `sandbox_compute_seconds` for new usage (keep writing it for history and agent cost); add the Stripe lines; show both kinds on REST, GraphQL, MCP and the dashboard.
2. Fail branch (t001 verdict = fail): **not taken** (2026-11-16: the fallback is a divergence that needs the user's sign-off, and the measured CPU is the parity-sufficient choice). Kept for history: keep an allocated-shape CPU charge as a **time-boxed divergence**: add the kind, record the divergence in ADR018 for the user's sign-off, and file the dated removal task; bill memory as in the pass branch.
3. Escalate branch: not applicable; the question was answered by the existing rules (README, "解阻记录 2026-11-16").
4. Document the effective timestamp in ADR030 and in the usage response notes.

## Outcome (2026-11-17)

- **Step 0, read on production 2026-11-17: the pod's CPU limit does not cap the charge at the plan's shape.** The init container `execd-installer` takes the namespace LimitRange default of 2 CPU, a pod's effective limit is the larger of its containers' sum and its largest init container, and under gVisor the sentry and the workload share the pod cgroup. The charge is capped at max(plan CPU, 2) cores. Recorded in ADR104 D8 and ADR030 §17; the fix is filed as w22/020. The cutover bills the measured CPU all the same.
- **The switch is 2026-11-18T00:00:00Z** (`pricing.yaml` `sandboxUsage.billedFrom`), one instant for every workspace. From it a sandbox created through the sandbox API writes `sandbox_cpu_seconds` and `sandbox_memory_gb_seconds`, both billed ($0.084 per CPU-hour, $0.0133 per GiB-hour), and no `sandbox_compute_seconds`. Usage before it is not re-priced; CPU and memory recorded before it are `unbilled` rows and lines at a rate of 0.
- **Agent sessions keep `sandbox_compute_seconds`**, so `outcome.cost` and the bill stay on one basis (`TestAgentSessionComputeAttributionPG` runs an interval across the switch).
- **Stripe: no new line.** The catalog is at Stripe's 20 items per Subscription, so billed CPU and memory are exported on the `sandbox_compute_seconds` meter as the weighted units that cost the same (`Sheet.SandboxUsageWeightedUnits`). This departs from the step's "add the Stripe lines": the usage API and the dashboard show the kinds apart, the invoice shows one sandbox compute line. No Stripe credential or setup run is needed.
- **Surfaces.** REST and MCP `rows[].unbilled`, `estimatedCost.resources[].charges[].unbilled` and `estimatedCost.sandboxUsageBilledFrom`; the same three on GraphQL; the dashboard labels billed and unbilled lines apart and prints the instant under the charge tree, in eight locales.
- **Fixture (`TestEstimateSandboxBilledOnUse`):** 3,600 s with 2 GiB and 600 CPU-seconds previews CPU $0.014 and memory $0.0266, and nothing on the weighted meter.
- `sandboxUsage` is withheld from `GET /pricing` until bex.co quotes it.
