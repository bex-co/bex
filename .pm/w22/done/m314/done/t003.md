## Objective

Add the used-CPU meter: per running interval, CPU-seconds from cAdvisor, written to `usage_hourly`, deferred and marked partial when Prometheus is unreachable, never billed as zero.

## Context

- `lego/backend/internal/metrics/source.go` already queries `container_cpu_usage_seconds_total` and `container_memory_working_set_bytes` for App metrics through the `kubernetes-cadvisor` job; reuse its query client, not a new one.
- `increase()` handles a counter reset when a pod is recreated.
- ADR023 describes the independent, gapless-cursor meter pattern; storage precedent in w22/m313.

## Steps

0. **Keep the pod-level CPU series for sandbox namespaces (added 2026-11-16, found by t001).** Under gVisor the workload container's own cgroup has no CPU series and the pod-level series is `container=""`, which the `kubernetes-cadvisor` job's `metric_relabel_configs` drops (`deploy/gitops/base/prometheus.yaml:468` onward, written to stop sum-by-pod queries double-counting). Keep those series for the `*-sandbox` namespaces only, in a form the existing sum-by-pod queries and rules cannot double-count (a rename through `__name__`, or a separate job), then confirm on production that the series exists for a running sandbox before step 1. Prove the existing App metrics queries are unchanged.
1. Add the usage kind `sandbox_cpu_seconds` (CPU-seconds).
2. For each closed or ongoing interval from t002, query `increase(container_cpu_usage_seconds_total{pod=...,namespace=...})` over exactly that interval and accrue it hour by hour.
3. If Prometheus is unreachable or returns no series for a running interval, defer the window and mark it `partial`; never write zero.
4. Test with a fake Prometheus: normal window, counter reset, missing series, outage then recovery.

## Acceptance criteria

- [x] The pod-level CPU series exists in Prometheus for a running sandbox, and no existing App or alert query changes its result
- [x] One CPU-minute of busy time yields about 60 CPU-seconds in the usage row (the pod-level reading is higher than the load's own count by gVisor's overhead, +9.8% measured in t001: record the ratio you see)
- [x] A Prometheus outage defers, then catches up, without double counting or a zero
- [x] An idle running sandbox accrues close to zero
