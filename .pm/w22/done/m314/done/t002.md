## Objective

Make each running interval attributable to the pod that ran it, because a resume recreates the pod and cAdvisor series carry only the pod name.

## Context

- ADR104 D8: do not add pod labels to kube-state-metrics (its allowlist is nodes-only, `deploy/gitops/base/prometheus.yaml`); attribute by interval instead.
- `sandbox/meter.go` already tracks running intervals through `ObserveSandboxMeter` (`store/sandbox_meter.go`); the pod name must come from OpenSandbox or the Kubernetes API in the same poll.

## Steps

1. Find where the pod name is available at poll time and read it with the status.
2. Store it on the interval, starting a new interval when the pod name changes.
3. Add tests: a resume that recreates the pod yields two intervals with two names and no gap or overlap.

## Files

- `lego/backend/internal/sandbox/meter.go`
- `lego/backend/internal/store/sandbox_meter.go` and a migration if the cursor needs a column

## Acceptance criteria

- [ ] Every accrued interval has the pod name that ran it
- [ ] A pod recreated by resume produces a new interval

## Out of scope

- Reading Prometheus (t003)

## Outcome (2026-11-17)

- The OpenSandbox list response carries no pod name, so the pod is derived: `<substrate sandbox id>-0` (`sandboxPodName`, `lego/backend/internal/sandbox/cpu_meter.go`). Read on production 2026-11-17: four of four running sandbox pods are named `<batchsandbox name>-0`. A resume that creates a new substrate sandbox changes the name; one that recreates the pod under the same name is told apart by its interval.
- `sandbox_running_intervals` (migration 0281) holds one row per stretch a sandbox ran on one pod. The phase cursor opens it at the first `running` sample and closes it at the first other sample, at a terminate, or when the pod name changes (`syncSandboxInterval`, `lego/backend/internal/store/sandbox_cpu.go`).
- `TestSandboxRunningIntervalsPG`: a resume and a pod replaced while running give three intervals with three names, the replaced pod's interval ending at the instant the next starts; a terminate closes the last one once. Mutation-checked.
