## Objective

Make the session's next turn start from the retained image when one exists and is current, so the interrupted turn's uncommitted and unpushed work is still in the checkout.

## Context

- Decision (user, 2026-11-14, w22/012): option A. The interrupted turn's work survives into the next message by retaining the sandbox's disk instead of replacing it, with a retention shorter than Devin's 14 days; the retained image is absorbed (w22/005: Devin does not bill a sleeping session). Devin: a sleeping session's machine is kept, and can be resumed for 14 days (docs.devin.ai/release-notes/2026, 2026-10-09, 2026-09-25, 2026-10-05).
- Mechanism chosen by the worker (the lifecycle map of 2026-11-14 shows why a literal OpenSandbox resume is unsafe): `Client.Resume` posts no body, so a resumed pod keeps its create-time env, which holds the old prompt, turn number, secrets, model route and egress choices (`lego/backend/internal/agentsessions/service.go` `driverEnv`; `lego/agent-image/driver/src/main.ts`, `config.ts`), and stale `status.json`, sentinel and `result.json` would make the Completer read the old verdict. Instead the interrupted turn's rootfs is pause-committed to an image (the machinery `CommitAgentBuildSandbox` in `lego/backend/internal/sandbox/agent_build.go` already uses for repo-environment images) and the next turn boots a fresh sandbox from it, which gets fresh env, secrets and egress for free, while the driver keeps the checkout (`ensureRepo` in `lego/agent-image/driver/src/git-setup.ts` keeps commits and working-tree edits when `/workspace` is already a git repo and runs `checkout -B <branch>`).
- The fresh-sandbox path is `Steer` to `runSteerDispatch` to `dispatch` (`service.go` ~1859-2056, 811-922) and `CreateAgentSessionSandbox` (`sandbox/service.go` ~1061-1089); ADR111's `AgentImage` / `agentImageRef` path (`sandbox/agent_build.go` ~72) already starts an agent sandbox from a stored image, with fresh env, `PrepareSetup` and `TransitionToAgent`.
- `adoptPersistedSession` adopts the agent's own session id only when the previous status was `succeeded` (`driver/src/session.ts` ~141-160); an `interrupted` status carries `sessionId` and `resume`. The conversation context reaches the new turn through the continuity env that `runSteerDispatch` builds, as it does for every turn today.

## Steps

1. Failing tests first: a Steer on a session with a current retained image starts its sandbox from that image (the create carries the image reference), clears the record only after the sandbox is up, and the new turn's checkout still holds a file that was uncommitted at the interrupt (a driver test with a git fixture: dirty tree plus an unpushed commit survive `ensureRepo`'s checkout of the session branch); an expired, deleted or missing image falls back to the fresh path with no error; a queued message and a direct send behave the same.
2. Implement the image-backed start in the dispatch path, with the stale-file removal and CAS from t002; the egress and secrets are re-resolved exactly as for a fresh sandbox.
3. If the retained image cannot be pulled or the sandbox fails to start from it, retry once from a fresh sandbox and say so in the turn's delivery note (never fail the turn because of the optimization).
4. Record in ADR047 D12 'As built'; ADR018's row for w22/m403 loses its second divergence (an interrupt keeps only what was pushed) and keeps one line of history.

## Outcome (2026-11-15)

- **Done.** The next Steer, direct or queued, waits for a save in progress (up to its 6-minute window), claims the kept image with a compare-and-set, and boots a fresh sandbox from it (fresh env, secrets and egress; the retained disk keeps the checkout, which the driver's `ensureRepo` leaves alone); a missing, expired, older-agent-image or unpullable image falls back to a fresh sandbox once with a note at the top of the delivery note, and a capacity error is not retried. The driver test proves an unpushed commit, a dirty tracked file and an untracked file survive `ensureRepo`, including with the repo moved on and the checkout left on another branch (`lego/agent-image/driver/test/git-setup.test.ts`; `src/git-setup.ts` is unchanged). The retained disk sets no prebuilt marker, so a repository environment's setup steps run again (a follow-up).
