## Objective

The dashboard and MCP clients can move and clear a group with the same semantics, refusals and codes as REST, through the same service call.

## Context

- GraphQL: environment writes in `lego/backend/internal/environments/graphql.go` (`updateEnvironment`, `setEnvironment*` full-list setters); group writes in `lego/backend/internal/sandbox/groups_surfaces.go` (`createSandboxGroup`, `updateSandboxGroup`, `setDefaultSandboxGroup`).
- MCP: `update_environment` takes the four member lists (`lego/backend/internal/environments/mcp.go:51`); the group tools `list_sandbox_groups`, `get_sandbox_group`, `create_sandbox_group` (`groups_surfaces.go:142-152`), whose description says placement is membership only.

## Steps

1. Pick the shape that matches the existing patterns and the SDK's verb: a group-side `setSandboxGroupEnvironment(id, environmentId)` on GraphQL and `set_sandbox_group_environment` on MCP (`null` clears) is the closest to `setGroupEnvironment`; record the choice in the README.
2. Both call the core verb t002 and t003 built; no second implementation.
3. Update the MCP tool descriptions (`create_sandbox_group`, the new tool) to say a group can move.
4. Tests on each surface: move, clear, 403, 404.
