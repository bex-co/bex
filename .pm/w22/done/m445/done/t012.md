## Objective

Two v1.10.0 changes that touch bex: the Python SDK's cleanup of a sandbox whose create was canceled must leave nothing running on bex, and bex's own SDK scenario uses the supported import path.

## Context

- Python v1.10.0 release notes (Fixed): "`sandboxes.create(wait=True)` terminates the new sandbox if the call is canceled while it waits for the sandbox to become ready. Before, the sandbox kept running and its ID was lost." Python only; the TypeScript notes do not mention it.
- The sandbox is in `creating` (or the substrate's equivalent) when the terminate arrives. bex's terminate route and states: `lego/backend/internal/sandbox/`.
- Deprecated: `render.experimental.sandbox` ("The old path still works"). The only such import in the repository is `scripts/render-sdk-compat/scenario.py`.

## Steps

1. Read the Python source for the request it sends on cancel (path and method) and when.
2. Replay it against bex on a sandbox still being created: it is accepted, and the sandbox ends and is not billed past the terminate.
3. Change `scripts/render-sdk-compat/scenario.py` to import from `render.sandbox` (keep the old path only if the scenario must still run v1.9.0, and say so).

## Files

- lego/backend/internal/sandbox/ (test, and a fix if terminate refuses a `creating` sandbox)
- scripts/render-sdk-compat/scenario.py
