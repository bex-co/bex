## Objective

Turn SDK v1.10.0's sandbox contract into files in the repository that tests can read, so the contract no longer lives in a model's reading of a release page.

## Context

- Upstream: `render-oss/sdk` on GitHub, the Python and TypeScript v1.10.0 tags (`python/v1.10.0`, `typescript/v1.10.0`, 2026-11-20). The release notes are readable with `gh api repos/render-oss/sdk/releases/tags/<tag>`; the code-to-class table still comes from the source. Note any difference from v1.9.0's table (the milestone was filed against v1.9.0).
- ADR104 gap 15 asks for the SDK and OpenAPI shapes frozen "as contract fixtures like `lego/cli/testdata`".
- `lego/backend/internal/sandbox/sdk_compat_test.go` is the existing SDK compatibility test; `lego/backend/internal/validationcorpus` and `lego/backend/internal/rendertest` hold other Render-derived fixtures.

## Steps

1. Clone the SDK at the v1.10.0 tags into the scratch directory (not the repository). Record both commits.
2. From each SDK's sandbox error module, extract the table: API `code` string, error class, and the HTTP status if the SDK checks it. Note where the two SDKs differ.
3. Extract how `SandboxEndedError` is detected (which code or status, which field carries the end time) and what `SandboxImage.failureCode` reads.
4. Extract the requests of `images.list()`, `images.delete()`, `snapshots.create()` with TTL, and TypeScript's `copyTo()` and `copyFrom()`: method, path, query and body fields, and the response fields read.
5. Write a small JSON fixture (well under the repository's size limits; it is test data, not run output) under the sandbox package's `testdata`, with the SDK version and commits in it, and a short README line saying how to regenerate it.
6. Update ADR104 D9 to name v1.10.0 and point at the fixture.
