## Objective

Code written against SDK v1.10.0 that creates a group in an environment, moves it, or takes it out works pointed at bex.

## Context

- TypeScript (`typescript/src/sandboxes/index.ts` at `typescript/v1.10.0`): `createGroup` (~line 1188) sends `{name, region, ownerId, environmentId}` in `POST /sandbox-groups`; `setGroupEnvironment` (lines 1266–1316) sends `POST /environments/{environmentId}/resources` with `{resourceIds: [sandboxGroupId]}`, or for `null` reads the group and sends `DELETE /environments/{environmentId}/resources?resourceIds=<sandboxGroupId>`, then reads the group. An empty string throws before any request.
- Python: `create_group(environment_id=…)`, `set_group_environment()` in `python/render/sandbox/client.py` at `python/v1.10.0`; the release notes say they match TypeScript, which this task checks in the source.
- bex: create with `environmentId` is served since w22/m412; the move is w22/m603, which must ship first. w22/m603 t001 freezes these requests too; reuse its fixture instead of a second one.

## Steps

1. Read the Python client's two calls and record any difference from TypeScript.
2. In `sdk_compat_test.go`, replay create-in-environment, set, move, and clear, and assert the group reads after each, the 201 and 204 statuses the client accepts, and the protected-environment 403 a non-Admin gets.
3. Replay the clear of a group already in no environment (the SDK reads `environmentId == null` and sends nothing).
