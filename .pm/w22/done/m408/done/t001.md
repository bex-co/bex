## Objective

Make `Idempotency-Key` (REST header, `idempotencyKey` on GraphQL and MCP) work for a send that starts a turn directly, not only for one that queues, so a retry after a lost reply returns the earlier outcome instead of queueing a duplicate that runs as a second turn.

## Context

- Today `EnqueueAgentSessionMessage` (`lego/backend/internal/store/agentsession_queue.go`) looks the key up inside its transaction and a direct start records no key (ADR047 D12 "As built"); `Service.Steer` (`lego/backend/internal/agentsessions/service.go`) decides queue-or-start before any key lookup, and `BeginAgentSessionTurn` (`store/agentsessions.go`) inserts the turn row.
- The failure: the first attempt starts the turn and its 200 is lost; the retry finds the session in flight and queues a duplicate, which later runs as a second turn. The same after a queued message was dispatched and the queue drained.
- The CLI no longer retries `steer` (w22/m403), but REST, GraphQL and MCP clients still can.
- Migrations are numbered `NNNN_name.{up,down}.sql` in `lego/backend/internal/store/migrations/`; other workers take numbers, so re-scan `git ls-tree --name-only origin/main lego/backend/internal/store/migrations/` immediately before committing.

## Steps

1. Write failing real-Postgres tests first: the same key sent twice while the first started a turn (the second returns the first outcome, one turn row); the same key after its queued message was dispatched and the queue drained (returns the delivered message, no new turn); the same key with a different prompt is `AGENT_SESSION_IDEMPOTENCY_KEY_REUSED`; keys are per session; a keyless send behaves as before.
2. Record the key and its request hash on the turn a direct send starts (a nullable `idempotency_key` and `request_hash` on `agent_session_turns`, unique per session where not null), written in the same transaction as the turn row.
3. In `Service.Steer`, look the key up before the queue-or-start decision: in `agent_session_turns`, then in `agent_session_queued_messages` (pending or delivered), and return the earlier outcome (the turn started, or the queued message with its place).
4. Update ADR047 D12 "As built" (the key is honored for every keyed send) and delete the limitation from the CLI notes in ADR106 and `docs/bex-cli.md`.
