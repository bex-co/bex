## Objective

Add an availability alert for the Zot StatefulSet, the way `KratosCourierNotReady` covers the Kratos courier, so a registry that is Pending, NotReady or failing its volume mount alerts within minutes.

## Context

- `PlatformDeploymentNotReady` (`deploy/gitops/base/rules/alerting_rules.yml`, ~line 83) uses `kube_deployment_spec_replicas` and `kube_deployment_status_replicas_available`. Its namespace regex includes `bex-registry`, but Zot is a StatefulSet (the chart's workload is `statefulset/zot`; `deploy/gitops/base/zot.yaml` has an `ignoreDifferences` entry for it), so the rule never matches.
- `KratosCourierNotReady` (`alerting_rules.yml`, ~line 106) is the template: `kube_statefulset_replicas{...} - on (namespace, statefulset) kube_statefulset_status_replicas_ready{...} > 0`. Its unit test is in `deploy/gitops/base/rules/alerts_test.yml` (~line 1097).
- `scripts/gitops-validate.sh` (~line 1398) copies every `deploy/gitops/base/rules/*_test.yml` and runs `promtool check rules` and `promtool test rules *_test.yml`, so a new test file is picked up without wiring.
- Planned Zot restarts exist today: ADR022 § Credential activation restarts the registry per new service credential until `w4/m347` removes it. The `for` window must be longer than a normal restart-to-ready, or every credential activation fires the alert.

## Steps

1. Find how long a planned Zot restart takes to become ready: read `kube_statefulset_status_replicas_ready{namespace="bex-registry",statefulset="zot"}` history for the last 30 days from the production Prometheus **read-only** (a loopback port-forward, as `docs/drills/2026-09-09-build-cache-enablement.md` did). If there is no access, keep `for: 5m`, say so in the alert's comment, and record the assumption in the milestone README.
2. Add `ZotRegistryNotReady` beside the other Zot alerts in `alerting_rules.yml`: the Kratos-courier expression scoped to `namespace="bex-registry", statefulset="zot"`, `for` from step 1 (default 5m), a severity chosen by the same rule the pack already uses for a dependency whose loss blocks all new Git-built starts (state the choice in a comment). The description must name `kubectl -n bex-registry get pods,pvc` and the credential-activation restart as the benign cause to rule out first.
3. Put a comment on the `PlatformDeploymentNotReady` namespace regex saying Zot is a StatefulSet covered by the new alert. Remove `bex-registry` from the regex only if no existing test depends on it.
4. Add `deploy/gitops/base/rules/registry_availability_alerts_test.yml` with promtool cases: ready 0 of 1 for the full window fires; the same one minute short does not; 1 of 1 does not; recovery resolves; a StatefulSet named `zot` in another namespace, or another name in `bex-registry`, does not match.
5. Run `promtool check rules` and `promtool test rules` over the pack as `scripts/gitops-validate.sh` does.
