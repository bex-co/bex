## Objective

Make sure the promtool tests assert real failure modes, not only the happy path: mutate each rule and confirm a test fails.

## Context

- The tests live in `deploy/gitops/base/rules/registry_availability_alerts_test.yml` and `registry_pull_alerts_test.yml`, run by `scripts/gitops-validate.sh`.
- A promtool test that still passes after its rule is broken is worthless; coverage here means each rule has a case that fails when the rule is wrong.

## Steps

1. For each alert, apply three mutations in turn and run `promtool test rules`: halve the `for`; loosen or tighten the namespace/name/image matcher; invert the comparison. Record which case failed for each mutation.
2. Add a case for any mutation no existing case catches (for example a pod in two states at once, or a Zot at 2 desired and 1 ready).
3. Revert every mutation. Confirm `git diff` shows only added tests.

## Files

- deploy/gitops/base/rules/registry_availability_alerts_test.yml
- deploy/gitops/base/rules/registry_pull_alerts_test.yml

## Acceptance criteria

- [ ] Each of the six mutations (three per alert) is caught by at least one promtool case, recorded in the task.
- [ ] No rule change remains from the mutation runs.

## Out of scope

- Tests for existing alerts.
