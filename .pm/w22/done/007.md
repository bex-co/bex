# Unparameterized lists return the full set where Render returns 20: record the divergence in ADR018 with the user's sign-off

Why: pinning the sandbox list `limit` (w22/001, 2026-11-10) showed `GET /v1/sandboxes` with neither `cursor` nor `limit` returns every sandbox, where Render's pinned OpenAPI defaults it to 20; found while writing the test.

- **Finding.** `core.StablePage` returns the whole list unless `cursor` or `limit` is present, for every list endpoint, "preserving pre-pagination clients" ([ADR006](../../../docs/ADR006-bex-api.md), § Deliberate divergences from Render). Once either is present the page is Render's: default 20, maximum 100. The sandbox list follows it (`lego/backend/internal/sandbox/rest.go`, `TestListLimitIsClampedToOneHundredAndAnUnpagedListIsComplete`).
- **Why it matters.** ADR018 holds that a divergence stands only when it records it with the user's sign-off, and ADR018 has no row for this one: ADR006 records it as deliberate, with no sign-off. It is platform-wide, so the decision is not specific to sandboxes.
- **Decision for the user.** Keep the full-set default (a documented compatibility choice; the dashboard and agents may depend on it), or switch every list to Render's 20 with a migration for the clients that never page. The parity-sufficient variant is Render's 20. Until then it stands as ADR006 recorded it.
- **Sizing.** Recording it is minutes; switching is a cross-feature change that needs its own milestone.

## Blocked

Blocked 2026-11-10 (`/loopx w22`). A recorded divergence needs the user's sign-off; ADR006 records this one without it. Until then the behavior stands as ADR006 describes and is pinned by a sandbox test.

## Decision 2026-11-13

- **Affected:** w22/007; the work is filed as [w10/m377](../../w10/blocked/m377/README.md).
- **Source:** explicit user decision, 2026-11-13, in the `/pm-brainstorm for w10` follow-up: "w22/007 -> Render 返回 20 条" (switch to Render's 20), given together with `/pmx them all to w10`.
- **Chosen behavior:** an unpaged Render-shaped REST list (no `cursor`, no `limit`) returns Render's first page of 20 with a cursor to continue, as Render's pinned `limitParam` ("Defaults to 20", 1-100) specifies. The full-set default ADR006 recorded is retired for REST.
- **Scope (the proposal's recommendation, not part of the user's decision):** GraphQL, bex's own API with no Render counterpart (the dashboard and the mobile app read it), keeps whole lists; MCP follows what Render's MCP server returns, read from its source in w10/m377 t005. The user's confirmation of this per-surface scope is still open and is named in w10/m377's README.
- **Rationale:** ADR008 Render parity first; root AGENTS.md: a divergence stands only with the user's sign-off in ADR018, which this decision withholds.
- **Remaining gates:** none for the work. The switch is a cross-feature change larger than an hour (this note's sizing), so it is a milestone, placed in w10 because w10 is draining now.
- **Next steps and acceptance:** w10/m377 (inventory, ADR006/ADR018, the switch, a spec-driven guard, in-repo clients, MCP), with its definition of done.
