# Harden the message queue and Stop turn: keyed direct sends, a forged `interrupted` status, Move around a leased head, and blocked-head retry cadence

Why: four risks the w22/m403 review found by reading are real but change semantics or need a schema change, so they were left out of that milestone: a retried send can run a message twice, an untrusted agent can fake the interrupted status, a reorder can trade places with a message the dispatcher is already starting, and a blocked message retries every 5 seconds forever.

- **1. A retried send can run twice.** `Idempotency-Key` is honored for queued sends only (`EnqueueAgentSessionMessage` looks the key up inside its transaction); a send that starts a turn directly records no key. If the first attempt starts the turn and its `200` is lost, a client retry finds the session in flight and queues a duplicate, which later runs as a second turn; the same after a queued message was dispatched and the queue drained. The CLI's `steer` no longer retries (w22/m403), but any REST, GraphQL or MCP client can still hit it. Fix: look the key up before the in-flight or idle decision in `Service.Steer` (`lego/backend/internal/agentsessions/service.go`) and return the earlier outcome for any keyed send, recording the key for direct starts too (a column on `agent_session_turns`, or enqueue-then-dispatch for keyed sends); update ADR047 D12 "As built".
- **2. The `interrupted` status can be forged.** `Completer.interrupted` (`completion.go`) finalizes a turn as completed when the sandbox's status file says `interrupted`, and bex-api records no stop request, so an untrusted agent that can write the status file can end its turn "interrupted" to skip the missing-structured-result failure `complete()` would raise. Fix: `Interrupt` stamps a request on the turn (a nullable `interrupt_requested_at`), and the Completer honors `interrupted` only for a stamped turn.
- **3. Move and edit around a leased head.** In `MoveQueuedAgentMessage` (`lego/backend/internal/store/agentsession_queue.go`) the target must be unleased but the leased head still takes part in the position trade, so "send now" can show message M first while the leased message H starts first; and an edit after a lapsed 2-minute lease is lost, because `BeginQueuedAgentSessionTurn` uses the claim-time prompt and author. Fix: exclude a leased head from reordering (a coded 409 `AGENT_QUEUED_MESSAGE_DISPATCHED`), and re-read the row at begin-turn.
- **4. Retry cadence of a blocked head.** A message blocked by the spend ceiling or the live-sandbox cap is released with `claimed_until` null and claimed again on every 5 s pass, each pass running a full `Steer` for up to 20 sessions; `last_attempt_at` only orders claims. Fix: a backoff clause in the claim, for example `AND (head.blocked_reason = '' OR head.last_attempt_at < $1 - interval '30 seconds')` with `blocked_reason` in the DISTINCT ON subquery.
- **Steps.** Test first for each (real Postgres for 1, 3, 4; a Completer test for 2), then the change, then ADR047 D12 "As built". `cd lego/backend && go test ./internal/agentsessions/... ./internal/store/...`, then the full real-dependency suite.
- **Done when:** a retried keyed send never starts two turns, a turn is finalized `interrupted` only if bex-api recorded a stop request for it, a reorder never trades places with the message being started, and a blocked message does not run `Steer` more than about twice a minute.
