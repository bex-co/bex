## Objective

A sandbox created with no image starts from the image t002 chose.

## Context

- `lego/backend/cmd/api/config.go` (~line 607): `BEX_SANDBOX_IMAGE` default, pinned by digest. `lego/backend/AGENTS.md` lists the variable; the gitops manifests may set it for production.
- The `base` template's entrypoint links `/bin/bash` and runs `sleep infinity` (ADR104 § D2 "Image", w32/m348). Exec falls back to `/bin/sh -c` when bash is missing (`lego/backend/internal/sandbox/exec.go`, `exec_shell_test.go`).
- Sandbox Pods run under gVisor with a 40Gi ephemeral-storage limit (w22/008) and without root-only assumptions in the file gateway's scripts.

## Steps

1. If the image is built by bex: add its Dockerfile and wire it into the existing image build and publish path; pin the pushed digest. Otherwise pin the upstream digest.
2. Update the default in `config.go`, the production value in gitops if one is set, the inventory in `lego/backend/AGENTS.md` and `.env.example` if it names the variable.
3. Keep or drop the `/bin/bash` link step according to the new image, and keep `sleep infinity`.
4. Record the compressed image size and a cold-start pull time for the old and the new image on a local cluster (`scripts/mock-cluster.sh` is pre-approved) in the milestone README.
5. Local check: create a sandbox, `bash -c 'curl --version && wget --version | head -1 && echo $HOME'`.
