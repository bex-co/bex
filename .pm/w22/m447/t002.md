## Objective

Decide the image from t001's table and write the decision where the old one lives, before changing anything.

## Context

- ADR104 § D2 "Image" records w32/m348's choice of `bash:5.3` and the rejection of Debian ("drops `wget` and busybox"); open question 5 asks what Render's image ships.
- AGENTS.md Rules: when an earlier decision conflicts with parity, amend it; never park parity work on an optional decision; ship the parity-sufficient choice.
- The image is pulled from a registry on every node that starts a sandbox; check how the platform mirrors or pre-pulls it (`deploy/gitops/`, ADR042) so the new one is reachable the same way.

## Steps

1. Choose: the Alpine image plus `curl` if t001 showed that is enough, otherwise a glibc Debian-family slim base with `bash`, `curl`, `wget`, `ca-certificates`, `tar`, `git` and busybox. Record it as this milestone's recommendation under the parity rule, not as a user decision.
2. Decide where the image is built and published if it is no longer a stock upstream image (a Dockerfile in the repository, built and pushed by an existing image workflow, pinned by digest). No image artifact goes into git.
3. Amend ADR104 § D2 "Image" and answer open question 5: the evidence (three templates, commits, date), the contents list, and that Render's own image is unverified.
4. State the user, `$HOME` and working directory the image keeps, so exec's "new shell in the home directory" contract is unchanged.
