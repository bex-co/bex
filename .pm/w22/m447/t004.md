## Objective

Everything that was verified against Alpine and busybox is verified again on the new image, and fixed where it relied on them.

## Context

- **Resolver.** ADR104 D3 and ADR042 § Sandbox network policies (w8/m152): sandbox Pods use `ndots:1` because Alpine's musl resolver gave up on search-list candidates the DNS filter refuses. glibc's resolver walks the search list differently; `curl https://<listed host>` must still work by name under an allow-list, and an unlisted host must still fail.
- **File gateway.** Its in-sandbox scripts ran on busybox `tar` and shell (`lego/backend/internal/sandboxfiles`, `lego/backend/internal/sandbox/file_roundtrip_test.go`); w22/011 fixed a bsdtar difference, so tar dialect matters.
- **Isolation matrix.** Its in-sandbox probes use busybox `wget`, `httpd` and `nc` (the weekly production workflow w22/m311 and w22/m414 extended).

## Steps

1. On a local cluster with the allow-list policy: resolve and fetch a listed host with `curl` and `wget`, fail on an unlisted one, and check a wildcard rule. Adjust the Pod DNS config only if a probe fails, and record why in ADR042.
2. Run the file upload and download round trips (file, directory, a directory over 10,000 entries if the suite has it) against the new image; fix any tar or shell dialect difference in the gateway's scripts.
3. Run the isolation matrix's probes locally or list each applet they need and confirm the image has it (busybox is installed for this reason).
4. Run the backend suite's sandbox packages.
