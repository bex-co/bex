## Objective

Changing the default breaks no existing sandbox, and the documents say which sandboxes have which image.

## Context

- ADR104 § D2 "Older sandboxes": a sandbox created before w32/m348 keeps its Alpine image across suspend and resume. A suspended sandbox resumes from its own committed image (w22/m313), not from the default.
- Agent-session sandboxes use their own image and are not affected; confirm, do not assume (`lego/backend/internal/sandbox/agent_build.go`).

## Steps

1. Confirm in code that resume and the retained-image path never re-read `BEX_SANDBOX_IMAGE`, and that agent sessions do not use it.
2. Add a test: a sandbox created under the old default, then the default changes, then suspend and resume; its image is unchanged and exec still works through the shell fallback.
3. Extend ADR104's "Older sandboxes" paragraph with this change and its date.

## Files

- lego/backend/internal/sandbox/ (a test beside `agent_suspend_test.go` or `resume_connect_test.go`)
- docs/ADR104-sandbox-render-parity.md

## Acceptance criteria

- [x] The test passes and fails if resume is made to use the current default.
- [x] ADR104 states which sandboxes keep the old image and until when.

## Out of scope

- Migrating existing sandboxes to the new image.
