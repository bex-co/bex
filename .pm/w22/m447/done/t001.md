## Objective

Replace the inference in the milestone README with measurements: what exactly each template needs from the default image, and where each fails on bex's current one.

## Context

- Templates: `github.com/render-examples/cursor-cloud-agent-sandbox` (`scripts/install-executor.sh`, `src/launch-policy.ts`); the Claude Managed Agents and OpenAI Agents API templates are linked from their Render docs pages (`src/policy.ts` holds `RUNTIME_DESTINATIONS` and `INSTALL_DESTINATIONS` in the Claude one).
- Today's image: `docker.io/library/bash:5.3` by digest, `BEX_SANDBOX_IMAGE` in `lego/backend/cmd/api/config.go` (~line 607).
- The install scripts download public release archives and need no account. Do not run the templates' agent loop; it needs provider keys this milestone does not use.

## Steps

1. Clone the three templates into the scratch directory, never the repository. Record each commit.
2. For each install script: the shebang, every tool it calls, the architecture and libc of what it downloads (run `file` and `ldd` or read the ELF interpreter on the downloaded binary), the directories and user it assumes, and whether it needs root.
3. For each launch policy: the allow-list hosts for install and for runtime, the env vars and the sandbox plan and timeouts it sets.
4. Run each script in a container of today's image locally (`docker run` the pinned digest) and record the first failure and, after working around it by hand, the next one, until the executor starts or cannot.
5. Write a table into the milestone README under "Template requirements": requirement, which templates need it, present in today's image or not.
