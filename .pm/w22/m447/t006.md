## Objective

Show on production that Render's three templates find what they need in bex's default sandbox.

## Context

- Needs the production deploy that carries t003. Deploys are batched; if it has not happened, park the milestone with that as the gate and do not close on local evidence.
- Use the QA user in a disposable workspace, as earlier w22 production checks did. The scripts download public archives; no provider key is used.
- Each sandbox gets the template's own install allow-list as its network policy (from t001's table), so the check also proves the hosts resolve and connect under an allow-list.

## Steps

1. For each template: create a default sandbox with its allow-list, upload the install script unchanged, run it, then run the executor's version command. Record exit codes and the version strings. First, in one default sandbox, run t003's check command (`bash -c 'curl --version && wget --version | head -1 && echo $HOME'`) and read the sandbox's `image` field: it must be the pinned `ghcr.io/bex-co/bex-operator:sandbox-base-ddcfca92d9b8…@sha256:014b703a…` digest, the same on REST, GraphQL and MCP creates (t007). In the Claude sandbox, record whether `/dev/pts` is mounted (its script mounts it otherwise, which needs `CAP_SYS_ADMIN`).
2. Confirm `/workspace/output` can be created and a file in it downloaded, since every template collects from there.
3. Run the weekly isolation matrix once on the new image and record the run id.
4. Terminate everything created. Record all of it in the milestone README under "Production check".
