## Objective

Split the memory part out of the folded weighted meter into its own usage kind, recorded from the same phase cursor, while leaving billing and the agent-session cost unchanged until w22/m314 cuts over.

## Context

- `lego/backend/internal/store/usage.go:37-40` defines `UsageKindSandboxComputeSeconds` (milli-vCPU-equivalent seconds); `sandbox/meter.go` polls every `MeterInterval = 30 * time.Second` and accrues only while `running`; `store/sandbox_meter.go` (`ObserveSandboxMeter`, `accrueSandboxInterval`) holds the cursor and remainder carry.
- `outcome.cost` for agent sessions uses `AgentSessionComputeMilliSeconds` (`store/sandbox_meter.go`) and must keep its basis (ADR104 D8).
- Billing cannot split the existing weighted charge into CPU and memory, so the new kind is recorded in shadow until the CPU meter (w22/m314) lets billing switch in one step.

## Steps

1. Add the usage kind constant and migration if the rollup needs a new row shape.
2. Emit allocated GiB × running seconds from `accrueSandboxInterval` beside the existing weighted accrual, with the same chunking and remainder behavior.
3. Confirm `pricing.go` and billing skip a kind that has no rate rather than failing or charging zero silently; add a test that names the behavior.
4. Keep `sandbox_compute_seconds` writes and every reader of it unchanged.
