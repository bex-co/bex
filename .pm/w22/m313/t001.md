## Objective

Settle the two open design questions of ADR104 D8 for storage (the byte source and the meter's shape) before building, and record them in ADR023.

## Context

- ADR104 D8: `sandbox_snapshot_gb_seconds` = compressed image bytes × retention seconds for a suspended sandbox's rootfs image and for each snapshot; event-driven; starts when the commit succeeds, ends when the image is deleted (terminate, 30-day expiry, snapshot delete or expiry).
- Neither `lego/backend/internal/sandbox` nor `deploy/opensandbox` carries a size field (2026-11-10 grep). Images are committed to per-tenant Zot repositories nested as `<registry>/<namespace>/<sandbox>-<container>` (`deploy/opensandbox/patches/controller-snapshot-job-namespace.patch`).
- Layers shared between successive commits of one sandbox will be counted more than once unless the size source dedupes; ADR104 says charge the sum and say so.
- Render: snapshot storage $0.08 per GB-month; a suspended sandbox pays snapshot storage only (render.com/articles/render-sandboxes-vs-vercel-sandboxes, 2026-11-06).

## Steps

1. Read what Zot exposes for a repository's size (its search/GraphQL extension or manifest and layer sizes) and what the OpenSandbox SandboxSnapshot status reports; pick one source and test it against a real suspended sandbox on a dev environment.
2. Define the event contract: idempotent `start(object, bytes, at)` and `end(object, at)` keyed by (workspace, object id), replay-safe like the durable phase cursor in `sandbox/meter.go`.
3. Decide whether a running sandbox that still holds its old rootfs image keeps accruing; follow whatever D11's garbage-collection rule retains.
4. Write the decisions into ADR023 and update ADR104 D8 "Not settled".
