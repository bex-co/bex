## Objective

Store the setting, let an admin change it, and audit the change, with no enforcement yet.

## Context

- The workspace record and its mutations live in `lego/backend/internal/workspaces/` (`service.go`, `graphql.go`; `createWorkspace`/`renameWorkspace`/`deleteWorkspace` and `changeWorkspacePlan` are GraphQL-only because Render has no REST workspace-mutation API, ADR018's "Workspace lifecycle" row). Follow the rename path for authorization (the admin relation) and for the audit verb.
- Audit verbs are `<pkg>.<Method>` names mapped to Render's vocabulary in `lego/backend/internal/audit/service.go` (`renderEvents`, ~line 145); `lego/backend/internal/audit/vocabulary_test.go` fails if a mapped verb stops naming a real service method. Render's event type for this change is `ChangeTeam2FAEnforcementEvent` (pinned OpenAPI audit-log enum; the `Org` variant is for Render organizations).
- Migrations are in `lego/backend/internal/store/migrations/` as paired `NNNN_name.up.sql`/`.down.sql`; the last one when this was filed is `0256`. Re-scan for the next free number.
- Backend AGENTS rules: mint ids only through `internal/id`; the real-Postgres suite runs in CI.

## Steps

1. Migration adding `require_two_factor boolean not null default false` to the workspace table, with a down migration.
2. `Service.SetRequireTwoFactor(ctx, workspaceID, enabled)`: admin-only; a no-op change writes no audit row; enabling is refused with the coded 409 from t001 unless the acting admin has 2FA (the lookup t003 will share: build it as a small function here and reuse it there).
3. Map the verb to `ChangeTeam2FAEnforcementEvent` in `renderEvents`; the event's data carries the new value.
4. GraphQL: `setWorkspaceRequireTwoFactor(workspaceId:, enabled:)` and a `requireTwoFactor` field on the workspace type, readable by any member (a blocked member must be able to read why).
5. Tests: a real-Postgres test for the migration and the read; service tests for admin vs non-admin vs viewer, the no-op, the lock-out guard and the audit row; the audit vocabulary test passes with the new mapping.

## Acceptance criteria

- [ ] An admin toggles the setting through GraphQL; a non-admin is refused; the read field reflects the change.
- [ ] An audit-log read returns `ChangeTeam2FAEnforcementEvent` for a change and nothing for a no-op.
- [ ] Enabling as an admin without 2FA is refused with the coded error, and succeeds once they have it (test double for the identity lookup).
- [ ] `cd lego/backend && go test ./...` and `make lint` pass.
