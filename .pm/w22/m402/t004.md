## Objective

Close the non-HTTP doors: Render says members with SSH or API keys cannot use them until they enable 2FA. Refuse at ticket mint, and at the gateway for native SSH, and cut a live session when the member stops being compliant.

## Context

- `lego/backend/internal/sshgateway/` holds the gateway: `resolver.go` (maps a connection to a target and identity), `revalidate.go` (rechecks a live session), `nativessh`, `terminal.go`, `agentattach`, `sandboxfiles`, `sandboxsse`. Tickets are minted by bex-api: `lego/backend/internal/shellticket`, `agentsessionticket`, `snapshotticket`, `sandboxexec`. User public keys are `lego/backend/internal/sshkeys`.
- A mint that goes through the t003 check is refused already if it passes the shared point; verify each mint does, rather than assuming.
- Native SSH to a `srv-…` instance authenticates the user's public key at the gateway, which never touches bex-api's HTTP middleware: this is the path most likely to be missed.
- The gateway has its own metrics (`sshgateway/metrics.go`) and a nonce/limiter; keep the check off the hot path with the t001 cache.

## Steps

1. Write failing tests first: an unenrolled member's ticket mint (shell, agent attach, sandbox connect) is refused with the coded error; a native SSH authentication by an unenrolled member's key is refused with a clear message the SSH client prints; an enrolled member is unaffected.
2. Wire the check into the gateway resolver for native SSH (identity from the key's owner) and into each ticket mint that does not already pass the t003 point.
3. In `revalidate.go`, re-run the check on its existing interval so a session opened before the setting was enabled, or by a member who later removed their last second factor, is closed at the next revalidation. Record the interval as the bound.
4. Count refusals in the gateway's metrics without workspace-id labels.

- [ ] `cd lego/backend && go test ./...` and `make lint` pass.
