## Objective

Give admins the Render control ("Enforce two-factor authentication (2FA)" in Workspace Settings), and give a blocked member a page that says why and takes them to enroll, instead of a wall of failing requests.

## Context

- Workspace Settings: `dashboard/src/routes/workspace.settings.tsx`, `dashboard/src/features/workspaces/components/` (`workspace-details-card.tsx`, `workspace-settings-navigation.tsx`, `delete-workspace-card.tsx`), locales in `dashboard/src/features/workspaces/locales/`.
- The member list: `dashboard/src/features/team/components/member-row.tsx` (~line 83 shows the `mfaEnabled` badge), `team-panel.tsx`, locales in `features/team/locales/`.
- Enrollment is Kratos's own settings flow (ADR012 §9; `use-ory-flow.ts` mints the aal2 step-up flow). The dashboard links there; it does not re-implement enrollment.
- Dashboard rules (`dashboard/AGENTS.md`, AGENTS.md): every preloading skeleton matches its ready state's geometry at desktop and narrow widths; every string goes through the locale files (en and zh); the dashboard is a client of the GraphQL API and reimplements nothing.
- The API refuses with the coded 403 `WORKSPACE_2FA_REQUIRED` (t003). Find the Apollo error handling (`grep -rn "errorLink\|onError" dashboard/src`) to intercept it in one place.

## Steps

1. GraphQL documents and generated types for `requireTwoFactor` and `setWorkspaceRequireTwoFactor`; run the repo's codegen.
2. A "Two-factor authentication" card in Workspace Settings: a switch with an explanation, visible to admins and read-only for others; the lock-out refusal from t002 shows its message. Skeleton matches the card.
3. The blocked state: when a workspace-scoped query fails with `WORKSPACE_2FA_REQUIRED`, show one page (not a toast per query) with the workspace name, why, a link to account security to enroll, and a way to switch workspace or leave it. The page must not be reachable as a loop: leaving or switching works, because the exempt routes allow it.
4. Member row: when enforcement is on, a member without 2FA shows "2FA required, not enabled" in place of the empty state; keep the existing "2FA enabled" badge.
5. Tests: the card for admin and non-admin and the refused-enable message; the blocked page appears on the coded error and not on other 403s; the member row states; skeleton/ready geometry. Verify pending and ready side by side at desktop and narrow-mobile widths (Playwright MCP, bare filenames; no images committed).
6. `cd dashboard && yarn lint && yarn test`.
