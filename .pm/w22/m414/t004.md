## Objective

Prove on production that the meter counts a sandbox's real egress, so the alert's number means something.

## Context

- The user authorized short production probes through `sandbox-measure.yml` on 2026-11-14 (D1 of `/unblock w22`): one disposable, billing-excluded workspace, bounded load. The base sandbox image is `bash:5.3` (busybox `wget`, `dd`, `df` available; no curl or python3). `scripts/lib/sandbox-measure.sh` has the REST, exec, pod and Prometheus helpers; `scripts/measure-sandbox-kubelet.sh` is the model for a leg. The new operator image must be deployed before this runs.

## Steps

1. Add an `egress` leg (`scripts/measure-sandbox-egress.sh`, and its option in `.github/workflows/sandbox-measure.yml`): create an allow-all sandbox, read the series `bex_app_direct_egress_bytes_total{namespace="<ws>-sandbox"}` through a Prometheus port-forward, download a known size (for example 50 MB from a public HTTP host with `wget -O /dev/null`), wait two scrapes, read again; the delta must be within about 10% of the bytes moved (headers and retransmits make it slightly larger).
2. Dispatch it (`gh workflow run sandbox-measure.yml -f leg=egress`), record the run id and the two numbers in this task.
3. If the meter does not see gVisor traffic, say what it sees and open a follow-up.
