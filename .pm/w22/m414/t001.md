## Objective

Make the egress meter count the public-internet bytes of `/v1/sandboxes` sandbox pods, per workspace.

## Context

- ADR104 D11 requires "egress metering on `allow-all` sandboxes (the egress-meter exists), and an alert on a workspace whose sandboxes egress far above its plan". Today no sandbox egress is metered: the operator's egress meter (`lego/operator/internal/egressmeter/meter.go`, an eBPF netfilter counter keyed by Pod IP) lists pods by the label `app.bex.co/app` and attributes bytes by `bex.co/app-id` (`reconcilePods`, `desiredPodResources`), and a sandbox pod in `<ws>-sandbox` carries neither.
- Measured on production 2026-11-14/15 (sandbox-measure runs 43688904321 and 43689373598): a sandbox pod's network counters exist on the node (kubelet stats summary `pods[].network`; raw cAdvisor on the pause container with `container=""`), and Prometheus carries none of them because its `kubernetes-cadvisor` job drops `container=""` series. So the cAdvisor route is closed without a scrape change; the eBPF meter is the existing, workspace-attributed source.
- Sandbox pods carry the public id in the label `bex.co/sandbox-id` (`lego/backend/internal/sandbox/service.go` ~45-70) and live in the namespace `<workspace>-sandbox` (`lego/backend/internal/store/namespaces.go` ~62, 89). An agent-session sandbox carries `bex.co/agent-session` and not `bex.co/sandbox-id`, so it stays out (its egress goes through the session egress policy and the model proxy, ADR047 D5).
- Key per workspace, not per sandbox: a `ResourceKey` is (namespace, app id), 64-byte labels (`types.go`), and the exported series is `bex_app_direct_egress_bytes_total{namespace, app_id}`; a constant app id (for example `sandboxes`) in the sandbox namespace keeps the series count bounded by workspaces instead of by short-lived sandboxes.

## Steps

1. Failing unit tests first (`types_test.go` style; `desiredPodResources`): a pod with `bex.co/sandbox-id` in a `-sandbox` namespace maps its IPs to (namespace, the sandbox app id); an App pod still maps as before; a pod with neither label is skipped; an agent-session pod is skipped; a terminal pod is skipped; one IP for two UIDs still stops accounting.
2. `reconcilePods` lists the node's sandbox pods as well (a second label selector; a list per selector or one list filtered in code, whichever keeps the API load flat), merges them, and counts them in `expected` so `bex_egress_meter_expected_pods` and `bex_egress_meter_attributed_pod_ips` stay honest.
3. Check the bounded BPF maps (`PodV4Resources`, `ResourceBytes`) against the largest sandbox count a node can hold (the workspace cap `BEX_SANDBOX_MAX_ACTIVE_PER_WORKSPACE` times workspaces on a node), and raise or document the bound; `bex_egress_meter_resource_map_pressure_ratio` is the gauge.
4. Check RBAC: the operator already lists pods cluster-wide by node; confirm no new rule is needed.
