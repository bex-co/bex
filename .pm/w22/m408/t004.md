## Objective

Back off the dispatcher's retry of a message that is blocked by the spend ceiling or the live-sandbox cap, so up to 20 blocked sessions do not run a full `Steer` every 5 seconds.

## Context

- `ReleaseQueuedAgentMessage` leaves `claimed_until` null and `ClaimQueuedAgentMessages` claims it again on every 5 s pass; `last_attempt_at` only orders claims (`lego/backend/internal/store/agentsession_queue.go`, `lego/backend/internal/agentsessions/message_queue.go`).

## Steps

1. Write a failing test first: a message released with a `blocked_reason` is not claimed again within the backoff, and is claimed after it; a message with no blocked reason is unaffected.
2. Add a clause to the claim, for example `AND (head.blocked_reason = '' OR head.last_attempt_at < $1 - interval '30 seconds')`, with `blocked_reason` in the DISTINCT ON subquery; make the interval a constant beside the poll and lease constants.
3. Update ADR047 D12 "As built" and the dispatcher metrics help text if it mentions cadence.
