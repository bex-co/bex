## Objective

Get a node that can run `runsc` pods where changing runtime flags cannot affect any customer, and record exactly what it runs.

## Context

- The production pool is labelled `bex.co/pool=sandbox` and tainted `bex.co/sandbox=true`; RuntimeClass `gvisor` has handler `runsc` (`deploy/opensandbox/gvisor-runtimeclass.yaml`).
- `--net-raw` and `--allow-packet-socket-write` are node-level containerd `runsc` settings that apply to every pod on the node (gVisor Docker-in-gVisor tutorial, cited in ADR104 D6). They must never be applied to the production pool.
- Unverified: whether the local CAPD/kind cluster (`scripts/mock-cluster.sh`) can run `runsc`, and whether `infra/` can add a throwaway Hetzner pool.

## Steps

1. Check whether a non-production node with gVisor already exists; otherwise decide between the local cluster and a one-node throwaway pool through `infra/`.
2. Record runsc version, kernel and node image; these are the ADR104 D6 "unverified on bex's nodes" facts.
3. State the teardown step and owner before provisioning anything billable.

## Files

- `infra/` (only if a throwaway pool is provisioned)
- `docs/ADR104-sandbox-render-parity.md` D6 (facts recorded in t007)

## Acceptance criteria

- [ ] A node exists where `kubectl run` with the gVisor RuntimeClass works and no tenant workload is scheduled
- [ ] runsc version, kernel and node image are written down

## Out of scope

- Any change to the production pool or its containerd configuration
