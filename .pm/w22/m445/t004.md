## Objective

The two v1.9.0 additions (carried in v1.10.0) that read response fields, not only a code, find those fields in bex's answers.

## Context

- `SandboxEndedError`: "raised by exec and file operations on a terminated or errored sandbox. It reports when the sandbox ended." w3/m318 made ended sandboxes readable (GET 200 `terminated`, the token mint 409, the v2.36 CLI's "was terminated at"). Check whether the field the SDK reads for the time is the one m318 serves, on both the run and the file connect paths (`lego/backend/internal/sandbox/connect.go`, `file_connect.go`).
- `SandboxImage.failureCode` (TypeScript): a failed import's reason. bex's image model is `Build` in `lego/backend/internal/sandbox/images.go`; check what a failed import records today and under which field name.

## Steps

1. From the fixture, take the exact detection rule and field for the ended case; make the exec and file refusals on a terminated and on an errored sandbox carry them.
2. Add `failureCode` to the image's REST shape (and GraphQL and MCP), with values from Render's vocabulary where bex's failure maps to one, and omitted otherwise. Record the mapping in ADR104 § Images.
3. Tests for both, through the router.
