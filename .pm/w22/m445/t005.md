## Objective

The fixture drives the tests: adding a code to the fixture without a bex answer, or changing a bex code, fails the suite.

## Context

- `lego/backend/internal/sandbox/sdk_compat_test.go` (v1.8.0 cases) and the fixture from t001.
- The image list is served at `lego/backend/internal/sandbox/images_surfaces.go` (~line 53: `name`, `status`, cursor, limit).

## Steps

1. A table test that loads the fixture and requires, for every code, either a registered scenario or an entry in the "cannot occur" list with a reason. An unregistered code fails.
2. Each scenario drives the router into the situation and asserts status and `code`.
3. Replay `images.list()` (no filter, name, status, paging; assert newest first) and `images.delete()` (success, in use with named dependents, missing).
4. Assert the `snapshots.create()` TTL request still gets the named snapshot refusal, so w32/m285 finds a pinned starting point.
