## Objective

`sandbox-groups create|list` and `retrieve`/`update` work on Render's paths, and `sandboxGroupId` is honored on sandbox create and list.

## Context

- `lego/backend/internal/sandbox/notoffered.go` lists the four group routes to remove (keep the builds and snapshots entries); `rest.go`, `service.go` and `models.go` own the sandbox REST.
- Isolation rule already in force for sandbox reads: a foreign or ownerless id answers the same not-found as a missing one.
- A `sandboxGroupId` that is not `sbg-` shaped already fails the Render request gate's pattern check with a 400 naming the field (ADR018).

## Steps

1. Implement create, list (cursor paging as the pinned schema defines), retrieve and PATCH `concurrencyLimit` returning the effective limit.
2. Accept `sandboxGroupId` on create (default group when absent) and as a list filter; remove the `SANDBOX_GROUPS_UNSUPPORTED` refusal for them.
3. Reject a region other than `oregon` the way Render does (t001 records which error).
4. Run the response through the OpenAPI contract check used by the sandbox tests.

## Files

- `lego/backend/internal/sandbox/rest.go`, `service.go`, `models.go`, `notoffered.go`
- `lego/backend/internal/sandbox/cli_flags_test.go`, `sdk_compat_test.go`
- `lego/cli/testdata/` if a contract fixture changes

## Acceptance criteria

- [ ] The pinned v2.35 CLI's `sandbox-groups create` and `list` succeed against the test server
- [ ] A group response validates against the pinned OpenAPI schema
- [ ] A sandbox created with `--group` lists under that group and not under another
