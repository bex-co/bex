## Objective

Persist groups and bind every sandbox to one, with every workspace having exactly one default group and every existing sandbox resolving to it.

## Context

- Latest migration is `0219_registry_credential_explicit_binding` on 2026-11-10; take the next free number when writing.
- `lego/backend/internal/store/sandbox_names.go` and `sandbox_names_pg_test.go` are the pattern for a per-sandbox attribute; `0056_sandbox_tenant_keys_fk` shows the tenant-row cascade a deleted workspace relies on.
- `lego/backend/internal/sandbox/purger.go` stops a deleted workspace's sandboxes; groups must cascade with the workspace.

## Steps

1. Add the migration (up and down): `sandbox_groups` (id, workspace, name, region, concurrency_limit, is_default, created_at, updated_at), unique name per workspace, a partial unique index for one default per workspace, workspace cascade.
2. Backfill: create each existing workspace's default group and bind existing sandboxes.
3. Add store methods: create, list, get, update limit, count active sandboxes in a group, ensure default; mint ids with `id.New`.
4. Add Postgres tests for uniqueness, one default per workspace, backfill, cascade.

## Acceptance criteria

- [x] Two defaults in one workspace are rejected by the database
- [x] A workspace that had sandboxes before the migration has them in its default group after it
- [x] Deleting a workspace removes its groups
