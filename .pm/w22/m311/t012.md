## Objective

A signed-in workspace member can create a sandbox group from the dashboard's "+ New" menu, as Render's dashboard allows, using the REST/GraphQL group operations this milestone ships.

## Context

- Render docs (render.com/docs/sandboxes-creating, read 2026-11-10): "You can also create a group from the Dashboard's + New > Sandbox Group menu", with an optional project environment; "Group names must be unique within your workspace"; listing returns up to 20 groups per call.
- The dashboard has no sandbox UI today except usage charges (`dashboard/src/features/usage/`). Dialog patterns to follow: `dashboard/src/features/projects/components/new-project-dialog.tsx`, `dashboard/src/features/environments/components/new-environment-dialog.tsx`; the dashboard home route is `dashboard/src/routes/index.tsx`.
- `dashboard/AGENTS.md`: GraphQL offline codegen, i18n (en and zh), destructive-confirmation rules, and the rule that preloading skeletons must match their post-loading contents.
- t001 decides `environmentId` (null in bex for now). If the dashboard offers an environment picker Render has and bex's API cannot honor, record it as a drift note instead of faking it.

## Steps

1. Find the "+ New" menu and add a "Sandbox Group" entry that opens a dialog (name; region fixed to Oregon and shown as such).
2. Call the group-create GraphQL mutation from t005 through Apollo with the dashboard's existing error handling; show the unique-name conflict and the 10-group limit as inline errors.
3. After creation, show the group (id, name, default marker, concurrency limit) where the user lands; if no list page is added, keep the scope to a confirmation that links nowhere false.
4. Add en and zh strings; run offline codegen; add component tests and update the route tests that enumerate the "+ New" items.
