# Run `scripts/render-sdk-compat.sh` at SDK v1.10.0 on production

Why: the harness still installs Render's SDK v1.8.0, so the unmodified current SDK (v1.10.0, 2026-11-20) has never run against bex; w22/m445 covered its contract with router replays only, and w32/m284 handed this run to it when m284 closed.

- **What changes in the harness:** pin `python_sdk_version` and `typescript_sdk_version` to `1.10.0`. Since v1.9.0 an ended sandbox raises `SandboxEndedError` with the message `exec failed: sandbox <id> was terminated at <time>`, so `ended()` in `scenario.py` (which asserts `status 409` and `sandbox_not_running` in the message) and the `ended` helper in `scenario.mjs` must accept the class. `scenario.py` already imports from `render.sandbox` (w22/m445). Add the calls v1.9.0 and v1.10.0 added: `images.list` (filters, paging), `images.delete` (success, `ImageInUseError`, `ImageNotFoundError`), `snapshots.create(ttl_seconds=…)`, TypeScript `copyTo`/`copyFrom` and `SandboxImage.failureCode`, `createGroup({environmentId})`/`setGroupEnvironment()` in a disposable environment, and a typed refusal per class that can occur on bex (the list is `codes` in `lego/backend/internal/sandbox/testdata/sdk-v1.10.0-contract.json`).
- **How to run it:** as w32/m284 and w2/m536 did, as the QA user in `bex-canary` with a token from a headless device login (`.claude/skills/qa-find-bugs/SKILL.md` § Approving a CLI device login without a browser), with a Python 3.11 or newer (`render-sdk` 1.10.0 requires it). Every sandbox, group, image and environment it creates is removed at the end, and the token and sessions are revoked.
- **Overlap:** w22/m603 t010 walks `setGroupEnvironment()` with the same SDK on production; one run can serve both.
- **End state:** both SDKs pass every step on production, the PASS counts and pin are recorded in `docs/cli-compatibility-checklist.md` § Render SDK, and its header names v1.10.0.
