## Objective

When a turn settles as interrupted, keep its sandbox's disk (the checkout and everything the agent installed) as a retained image for a bounded time, so the next message can continue from it.

## Context

- Decision (user, 2026-11-14, w22/012): option A. The interrupted turn's work survives into the next message by retaining the sandbox's disk instead of replacing it, with a retention shorter than Devin's 14 days; the retained image is absorbed (w22/005: Devin does not bill a sleeping session). Devin: a sleeping session's machine is kept, and can be resumed for 14 days (docs.devin.ai/release-notes/2026, 2026-10-09, 2026-09-25, 2026-10-05).
- Mechanism chosen by the worker (the lifecycle map of 2026-11-14 shows why a literal OpenSandbox resume is unsafe): `Client.Resume` posts no body, so a resumed pod keeps its create-time env, which holds the old prompt, turn number, secrets, model route and egress choices (`lego/backend/internal/agentsessions/service.go` `driverEnv`; `lego/agent-image/driver/src/main.ts`, `config.ts`), and stale `status.json`, sentinel and `result.json` would make the Completer read the old verdict. Instead the interrupted turn's rootfs is pause-committed to an image (the machinery `CommitAgentBuildSandbox` in `lego/backend/internal/sandbox/agent_build.go` already uses for repo-environment images) and the next turn boots a fresh sandbox from it, which gets fresh env, secrets and egress for free, while the driver keeps the checkout (`ensureRepo` in `lego/agent-image/driver/src/git-setup.ts` keeps commits and working-tree edits when `/workspace` is already a git repo and runs `checkout -B <branch>`).
- Today an interrupted turn's sandbox stays running, driver alive, until the 2 h idle grace (`BEX_AGENT_SANDBOX_IDLE_TTL`), then `teardown` terminates it (`completion.go` ~846-917); a Steer before that terminates it too (`service.go` ~2042-2054, `CleanupAgentDispatches`). There is no suspend verb for agent sessions (`SandboxLifecycle` in `service.go` ~149-164).
- The storage cap counts only `/v1/sandboxes` objects, imports and repo-environment builds (`store/sandbox_storage.go` ~392-411); agent sandboxes open no storage object (`sandbox/meter.go` ~227-232), and nothing deletes an agent snapshot image on terminate (`snapshot_size.go` `RegistryReaper.DeleteImages` runs only for storage objects and builders). Zot's volume is 100 Gi shared. ADR047 D6 was corrected on 2026-11-14 to say so.
- Transcript harvest needs a running pod, so it must come before the pause (`completion.go` ~850-855). `CommitAgentBuildSandbox` removes `status.json` before pausing for exactly the stale-verdict reason (`agent_build.go` ~125-150); do the same for the sentinel and `result.json`.

## Steps

1. Failing tests first (real Postgres plus the fake sandbox lifecycle): an interrupted settle harvests the transcript, removes the stale status, sentinel and result files, pause-commits the sandbox and records the retained image (reference, bytes, `retained_until`) on the session; a completed or failed turn retains nothing; the retained bytes count against `BEX_SANDBOX_MAX_STORAGE_GB_PER_WORKSPACE`, and a full cap means no retention (the sandbox is terminated and the loss is recorded, never an error to the user); a retention deadline (a named setting, default 24 h, always shorter than Devin's 14 days) expires it.
2. Add a nullable retained-image record to the session (migration; re-scan `git ls-tree --name-only origin/main lego/backend/internal/store/migrations/` first; unique, indexed on `retained_until`), a sandbox-package seam for harvest-then-pause-commit (reuse `CommitAgentBuildSandbox`), and count the bytes in `SandboxStorageBytes`.
3. Delete the image (all `snap-gen` tags through `RegistryReaper`) and the record on: retention expiry (a sweeper beside `reapIdleSandboxes`), Cancel, Delete, archive, workspace purge and a successful continuation (t003). CAS every deletion and every continuation on (session, retained record) so a Steer racing an expiry never boots from a deleted image or deletes one in use.
4. Order the settle so a Steer cannot begin before the retention step finishes (`FinalizeAgentSession` currently makes the session steerable before `teardown`, `completion.go` ~687-699); a Steer that arrives first simply takes the fresh path.
5. Record the design in ADR047 D12 'As built' and correct D6's bound.

## Outcome (2026-11-15)

- **Done.** A turn that settles as interrupted saves its sandbox's disk as a retained image: one transaction settles the turn and inserts a `saving` row (migration 0271, at most one live row per session), then the save reads the transcript, removes `status.json`, the interrupt sentinel and `result.json`, pauses the sandbox, reserves the bytes against the storage cap (retained bytes count in `SandboxStorageBytes`), copies the image to `snapshots/<ws>-sandbox/images/ari-<id>:image` (new id kind `ari`), ends the paused sandbox and records the image as `kept` until now plus `BEX_AGENT_INTERRUPT_RETENTION` (default 24h, 0 keeps nothing, capped at 7 days). The image is deleted on expiry (a sweep on each Completer tick, bounded to 10 s and 5 images), cancel, archive, delete, workspace purge and after a successful continuation; a full cap, a failed pause, a failed transcript read or an open editor over SSH (which keeps the live sandbox, as `teardown` does) degrade to today's behavior with the loss recorded on the turn. Review findings fixed: a save outliving its deadline no longer touches the next turn's sandbox id or egress policy; an early dispatch failure no longer strands the claim; the purge is bounded.
- **Tests:** real-Postgres store tests (the state machine, the claim racing an expiry, the cap), sandbox tests with an in-process registry, agent-session tests for every end and race, 19 mutations caught (see ADR047 D12 'As built'). Follow-ups the review named are listed in D12 'Not done'.
