# The org audit log hides rows written just after the org was created when the database clock runs ahead of bex-api's

Why: an org's audit history starts at the org row's `created_at`, which Postgres stamps, while each audit row's `at` is stamped by bex-api, so a database clock a few tens of milliseconds ahead hides the first events; on a Mac it fails `scripts/ship-gates.sh` for every backend push.

Found shipping w22/m443, 2026-11-20. Not caused by that change: the same tests fail on its parent `ed1452f75`, and CI, where both clocks are one machine's, is green.

- **Symptom.** `TestOrganizationInviteLinkE2E`, `TestOrganizationsE2E` and `TestOrganizationLoginRequirementsE2E` (`lego/backend/internal/api/`) fail against `scripts/backend-test-deps.sh` on colima with rows missing from `GET /v1/organizations/{orgId}/audit-logs` (for example "org log has 1 AcceptOrgInviteEvent rows, want 2"); which rows are missing changes from run to run.
- **Cause.** `audit.Service.ListOrganization` (`lego/backend/internal/audit/organizations.go`) passes the org's `AuditVisibleFrom` as the list's lower bound. Measured here, the colima VM's clock was 50 to 80 ms ahead of the host's, so rows the test wrote within that window after creating the org have `at` earlier than the bound. lima's guest agent sets the VM clock again within a minute of a manual step, so it cannot be held back for a whole suite.
- **Check.** With the VM clock stepped one second behind the host (`colima ssh -- sudo date -u -s @<epoch>`) and the tests started at once, all three pass.
- **Fix to try.** Stamp the bound and the rows with one clock: have the org's creation write `audit_visible_from` from the same `time.Now()` its first audit row uses, or stamp `at` in SQL. A workspace's `AuditVisibleFrom` after a plan change (`store/workspaces.go`) may have the same shape and should be checked.
- **Done when:** a test that creates an org with the database clock ahead of the caller's (an injected clock, no real skew) still lists the org's first events, and the three tests pass on colima without touching the VM clock.
