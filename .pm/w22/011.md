# The sandbox file-gateway refusal test fails on macOS, which stops `ship-gates.sh` there

Why: `TestFileGatewayRefusalBeforeTheFirstByteReachesTheClient` (w32/m380) fails on every developer Mac that lacks GNU tar, so the real-dependency backend suite in `scripts/ship-gates.sh` fails there for every ship, although Linux CI is green.

- **Evidence (2026-11-14).** `cd lego/backend && go test ./internal/sandbox -run TestFileGatewayRefusalBeforeTheFirstByteReachesTheClient` fails 3 of 3 on a clean checkout of `origin/main` (`13dc1b1d7`) with `file_connect_hop_test.go:124: refused download = 503 "the sandbox file transfer ended before a response"`, where the test expects `400 "invalid or unsupported sandbox archive: unsafe entry"`. The machine has `/usr/bin/tar` = bsdtar 3.5.3 (libarchive) and `/bin/bash` 3.2.57, and no `gtar`. CI (Linux) passed this commit. With the test skipped (`-skip`), the whole suite is green: 78 packages, exit 0, against real Postgres, OpenFGA, OpenBao and Loki.
- **Where it comes from.** The test runs the gateway's real scripts through `newLocalFileExecutor` (`internal/sandbox/file_roundtrip_test.go`); the script archives with `tar -cf - -C "$name" .` (`internal/sshgateway/sandboxfiles/sandboxfiles.go`, ~line 499) and the Go side rejects an entry whose name holds a control character (`unsafe entry`, ~line 743). The refused directory holds a file named `a\nb`. Which tar or shell difference turns that into a stream that ends before a response was not established.
- **Steps.** (1) Find the cause on a Mac: run the script by hand against a directory holding `a\nb`, with bsdtar and with a GNU tar (`brew install gnu-tar` provides `gtar`). (2) Make the test pass or skip on the cause, not on the OS: for example skip with a message when `tar --version` is not GNU tar, or make the script portable if bsdtar's output is valid. (3) `cd lego/backend && go test ./internal/sandbox` passes on macOS and still runs on Linux.
- **Done when:** the sandbox package passes on a Mac without GNU tar, or skips with a message naming the missing tool, and the test still runs and passes in Linux CI.
