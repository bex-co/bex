## Objective

Build the limiter the surfaces will call: one token bucket per (user, class) at the class's rate, and a way for a classified request to skip the general per-subject budget.

## Context

- `lego/backend/internal/core/ratelimit.go`: `KeyedRateLimiter[K]`, the shared token-bucket implementation with idle sweep and a bounded map.
- `lego/backend/internal/api/ratelimit.go`: the general limiter and its middleware, including the workspace aggregate bucket and the 429 writer.
- `lego/backend/cmd/api/main.go` (~line 1882) wires it; `BEX_RATE_LIMIT=0` disables it.

## Steps

1. Define the classes and their rates as constants beside the sandbox package's other Render limits (`lego/backend/internal/sandbox/service.go` holds the env-var limits), each with a comment citing Render's page and date.
2. Add a class-keyed limiter built from `core.KeyedRateLimiter` with a key of user plus class. Reuse the existing sweep and map bound; do not hand-roll a second limiter.
3. Let the general middleware recognize a classified sandbox request and not charge the per-subject bucket for it. Keep the workspace aggregate bucket in force, sized as t001 recorded.
4. Keep the disable switch: with `BEX_RATE_LIMIT=0` the class limiter is off too, as the tests and local stacks expect.
5. Unit tests: each class refuses at its rate plus one, two keys of one user share a bucket, two users do not, classes do not spend each other's tokens.

## Files

- lego/backend/internal/core/ratelimit.go

## Acceptance criteria

- [ ] A class bucket refuses the first request over its per-minute rate and accepts again after refill.
- [ ] A classified request does not reduce the caller's general budget, and an unclassified request does not reduce any class bucket.
- [ ] `make lint` passes for the backend module.

## Out of scope

- Mounting on routes (t003, t004).
- New environment variables for the rates: they are Render's numbers, not operator settings.
