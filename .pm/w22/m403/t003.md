## Objective

Deliver queued messages: when a session's turn settles, claim the next pending message and run it as an ordinary steer turn, exactly once, in order.

## Context

- Model on the D11 worker in `lego/backend/internal/agentsessions/pr_feedback.go`: `feedbackPollInterval = 10s`, `feedbackLease = 2m`, a claim with `claimed_until`, delivery recorded as `delivered_turn`/`delivered_at`, and the idle-session condition for starting the steer. The store tests are `lego/backend/internal/store/agentsession_feedback_pg_test.go`.
- The existing steer path is `Service.Steer` (`service.go`); a dispatched message must go through it so `admitDispatch` (the live-sandbox limit and the spend ceiling, `spend.go`, `spendceiling.go`, `limits.go`), the branch-in-use rule and the prompt quota apply.
- Turn completion and the "turn keeps its first completion time" repair are in `completion.go` (migration `0256`): the dispatcher must key off the settled turn, not a timestamp that can be re-harvested.
- Ordering with PR feedback: t001's decision (recommended: user messages first). The two loops must not both start a turn on the same idle session: one claim point per session.

## Steps

1. Write failing tests first (real Postgres): a settled turn with two queued messages starts the first and not the second; after that turn settles, the second runs; messages run in queue order; a restart between settle and dispatch loses nothing and dispatches once; two replicas racing on one session start one turn; a lease that expires after a crash is reclaimed.
2. A blocked dispatch (spend cap reached, live-sandbox limit) leaves the message pending with a `blocked_reason` the session view exposes, and retries on the poll.
3. A message whose session was canceled, archived or deleted is never dispatched (re-check at claim time, not only at the clearing transaction).
4. Coordinate with the D11 worker: a single "next turn" claim per session, user messages before PR feedback, and an existing feedback batch is not starved when no user message is pending.
5. Metrics beside `completion_metrics.go`: pending depth, dispatch latency from settle, dispatches blocked by reason.

## Acceptance criteria

- [ ] Queue order, exactly-once dispatch across restart and across replicas, and lease recovery are proven by real-Postgres tests.
- [ ] A blocked dispatch keeps the message and shows the reason; a cancelled session's messages never run.
- [ ] D11 feedback delivery still passes its existing tests and is not starved.
- [ ] `cd lego/backend && go test ./...` and `make lint` pass.

## Out of scope

- Batching several queued messages into one turn (t001 chose one per turn).
