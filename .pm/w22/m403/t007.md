## Objective

Check that the queue and the interrupt are consistent across every surface they expose, and compare them with Devin's observable behavior (the reference for cloud coding-agent surfaces); record drift as follow-up work rather than diverging silently.

## Context

- Surfaces: REST (`/v1/agent-sessions/{id}/steer`, the queued-messages and interrupt routes), GraphQL (`steerAgentSession`, `queuedMessages`, the edit, delete, move and interrupt mutations), MCP (the steer tool and the new tools), the dashboard session page, and `bex agent chat`. Same fields, semantics and error shapes on each.
- Devin entries to compare against ([docs.devin.ai/release-notes/2026](https://docs.devin.ai/release-notes/2026)): queueing as a preference while working (2026-07-17); stop while working (2026-08-21); Cmd/Ctrl+Enter sends a queued message immediately (2026-08-26); queued messages survive idle and resume (2026-09-09); interrupt keeps the reply already seen (2026-10-14); queued messages can be sent, edited, removed, reordered after Devin stops or sleeps (2026-10-16); Side Chats "send to interrupt it or queue to run after it finishes" (2026-11-06). Re-read them: the notes change.

## Steps

1. For each surface, send while a turn runs, list, edit, delete, reorder and interrupt, and confirm the same codes and fields (`AGENT_SESSION_QUEUE_FULL`, the interrupt conflict code).
2. Compare with the Devin entries above, one by one: default (queue versus a preference), send now, survival across idle/resume (bex: durable queue), reorder, partial reply kept, Stop versus Stop session. Record each match and each drift.
3. Update the ADR018 Devin-reference row from t001 and ADR047 with what shipped; file every drift (for example a CLI interrupt command, the queue-as-preference setting) as an inbox note with `/pm add`, never leave it implicit.
