## Objective

Let the terminal client use the server-side queue instead of holding one message locally, so the same messages show in the dashboard and survive a disconnect.

## Context

- This changes an existing extension of the Render CLI launcher (`lego/cli/internal/agent/chat.go`, ADR106 D2); it is not a new CLI (DO_NOT_DO's first-party CLI rule is unaffected). `chatState.sendNext` (~line 259) and the `pending` slot hold one queued message; the prompt shows "queued — sends when this turn ends" (ADR106 D2, lines ~109–110).
- `lego/cli` imports none of the other modules (the import DAG): it talks to the REST API only. The queued-steer response comes from t002.
- `lego/cli/dashboard_test.go` and the `*_contract_test.go` files pin the CLI's contract tests.

## Steps

1. Write failing tests first: a message typed while a turn runs is sent to the server and printed as queued with its position; typing again adds another instead of replacing; the queued messages are listed on reattach; Ctrl-C leaves the queue on the server.
2. Replace the single `pending` slot with the server queue; keep the idempotency key per typed line.
3. Update ADR106 D2's sentence ("queued in the client in one slot") to describe the server queue.
4. `cd lego/cli && go test ./...`.
