## Objective

Decide the queue's rules and the interrupt's semantics in ADR047 before code, and find out by reading and a short experiment whether "end only the current turn, keep the session" is possible with the driver and each engine, because t004's shape depends on the answer.

## Context

- Today's refusal: `lego/backend/internal/agentsessions/service.go` (~lines 1818–1820 and ~2126), code `AGENT_SESSION_TURN_IN_FLIGHT`. Phase 1 steering runs a follow-up prompt turn on an existing session; the comment above `Steer` (~line 1773) explains why a new prompt cannot ride the original sandbox in phase 1.
- ADR047 § D9 (table stakes, `AGENT_SESSION_LIVE_TURN_UNAVAILABLE`), § D11 (PR feedback: durable per-session queue, delivered once idle) and ADR106 D2 (the CLI's client-side one-slot queue, lines ~109–110).
- Driver: `lego/agent-image/driver/src/session.ts` (`stopProvider`, `provider.cancel()` at ~line 195; per-turn `turnAbort` and `options.abortSignal`, ~lines 211–226), `main.ts`, `gateway.ts`, `acp.ts`. The ACP protocol has a `session/cancel` notification that an engine may honor.
- Devin: queueing is a preference (2026-07-17); a queued message can be sent immediately (2026-08-26) and edited, removed, reordered (2026-10-16); interrupting keeps the reply already seen (2026-10-14); Side Chats offer "send to interrupt it or queue to run after it finishes" (2026-11-06). Re-read these entries at [docs.devin.ai/release-notes/2026](https://docs.devin.ai/release-notes/2026) before writing the ADR section: Devin's behavior is the reference, and the claim that Stop keeps the session was not verified when this was filed, so verify it or leave it out.
- `#APPROVAL-MODE` (DO_NOT_DO.md): nothing in this design may pause a turn for a person or add an agent-to-user question channel.

## Steps

1. Read how Cancel reaches the driver today (`agentsessions` cancel path, the gateway, `driver/src/gateway.ts`/`main.ts`) and who sets `abortSignal`. Answer: can an external signal end only the running turn? What state is the sandbox and the session in afterwards (phase, the branch, the transcript's last turn)? Does each supported engine honor `session/cancel` and leave its conversation resumable?
2. Run a short experiment on `dev-N` (`scripts/dev-env.sh <N> up`) or the driver's own tests: start a long turn, abort only the turn, then send a follow-up steer. Record the outcome per engine.
3. Pick t004's shape from the result and record it: (a) the driver ends the turn and the session goes idle in the same sandbox (preferred); (b) the turn is cancelled and the sandbox torn down, the session resumes from continuity on the next message (ADR059); (c) an engine that supports neither refuses the verb with a coded error and the dashboard hides the button, recorded as drift against Devin.
4. Decide and record, each with its basis: the cap on pending messages per session (recommend 10); FIFO, one message per turn; the idempotency key (reuse `agentsessions/idempotency.go`); that queued messages are cleared on cancel, archive and delete and are never silently dropped by age (unlike D11's 24 h feedback drop: say why a person's message differs); what happens when dispatch is blocked (spend cap, live-sandbox limit): the message stays queued with a visible reason; whether to extend `agent_session_feedback` (its `kind` check allows only PR kinds, its key is `(session_id, source_key)`) or add a table (recommend a new table with the same claim/lease and delivered-turn columns, because edit and reorder need an ordering column the feedback table lacks); the order between a user message and PR feedback when both are pending (recommend user messages first); "send now" as interrupt then move to the front; queue-by-default versus Devin's preference model and the divergence label.
5. Name the API: REST paths under `/v1/agent-sessions/{id}/` (the existing verbs are `steer` and `cancel`), GraphQL and MCP names, and the 202 body for a queued steer.
6. Write the section in `docs/ADR047-cloud-coding-agent-sessions.md` after D11, update the D9 and `AGENT_SESSION_LIVE_TURN_UNAVAILABLE` text it supersedes, add a Devin-reference row to `docs/ADR018-render-parity.md` (or the agent-session section it keeps), and update ADR106 D2's "queued in the client" text to say it is replaced (t006 does the CLI).
