## Objective

Make each running interval attributable to the pod that ran it, because a resume recreates the pod and cAdvisor series carry only the pod name.

## Context

- ADR104 D8: do not add pod labels to kube-state-metrics (its allowlist is nodes-only, `deploy/gitops/base/prometheus.yaml`); attribute by interval instead.
- `sandbox/meter.go` already tracks running intervals through `ObserveSandboxMeter` (`store/sandbox_meter.go`); the pod name must come from OpenSandbox or the Kubernetes API in the same poll.

## Steps

1. Find where the pod name is available at poll time and read it with the status.
2. Store it on the interval, starting a new interval when the pod name changes.
3. Add tests: a resume that recreates the pod yields two intervals with two names and no gap or overlap.

## Files

- `lego/backend/internal/sandbox/meter.go`
- `lego/backend/internal/store/sandbox_meter.go` and a migration if the cursor needs a column

## Acceptance criteria

- [ ] Every accrued interval has the pod name that ran it
- [ ] A pod recreated by resume produces a new interval

- Reading Prometheus (t003)
