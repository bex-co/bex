## Objective

Call the ensure function from the operator and give it the permissions t001 chose.

## Context

- `SandboxNamespaceRegistryReconciler` (`lego/operator/internal/controller/sandbox_namespace_registry_controller.go`) already runs for sandbox namespaces; a dedicated one-shot runnable is the alternative t001 may prefer.
- The registry ACL change takes effect after a Zot restart (`tryBounce`, shared rate limit).

## Steps

1. Call `EnsureSandboxMeterCreds` where t001 decided, gated on an env var naming the target namespace so an operator without it behaves exactly as before.
2. Add the RBAC marker and regenerate `config/rbac/role.yaml`; add the env var to `config/manager/manager.yaml`.
3. An envtest or controller test that the Secret appears and a sandbox namespace reconcile still works.

## Files

- `lego/operator/internal/controller/`, `lego/operator/config/rbac/`, `lego/operator/config/manager/manager.yaml`, `lego/operator/cmd/`

## Acceptance criteria

- [ ] `make test` (operator) passes, with the generated RBAC committed
- [ ] With the env var unset nothing changes

## Out of scope

- bex-api (t004)

## Result — 2026-11-10

`SandboxMeterCredsRunnable` (ensure at start, retry in 30 s on failure, resync every 10 minutes), registered in the manager behind `BEX_SANDBOX_METER_CREDS=1` (set in `config/manager/manager.yaml`); a runnable rather than a reconciler hook because these users are platform-wide and nothing triggers a reconcile for them. **No operator RBAC or cache change**, which was the point of t001. The new Role is bex-api's, `deploy/gitops/base/bex-api-sandbox-registry-rbac.yaml`, with a guard in `scripts/gitops-validate.sh` that it grants exactly `get` on exactly that Secret (the base renders with `kubectl kustomize`; the rest of `gitops-validate.sh` could not be run here: its `helm-artifact` self-test fails on macOS bash 3.2 and a network 504). Minting changes Zot's ACL and bounces Zot once.
