## Objective

Make the throwaway node run `dockerd` inside a gVisor pod as gVisor documents, on a separate RuntimeClass so the default one stays tight.

## Context

- gVisor documents `--net-raw` for every Docker version and, for Docker v28 and later, `--allow-packet-socket-write` (which "allows sandboxed code to craft arbitrary network packets").
- Docker v29 needs a `tmpfs` at `/var/lib/docker` (or `--feature containerd-snapshotter=false`); `dockerd` runs with `--iptables=false --ip6tables=false`.

## Steps

1. Add a second RuntimeClass (for example `gvisor-docker`) on the throwaway node with the flags above.
2. Start a pod on it with the capabilities the tutorial uses (`sys_admin`, `net_admin`, `net_raw`, `setuid`) and confirm `dockerd` starts.
3. Keep these manifests out of the Argo CD base so they cannot reach production by accident.

- Spike manifests under a clearly marked non-GitOps path (or the run notes only)

## Acceptance criteria

- [ ] `docker info` answers inside the pod
- [ ] The default `gvisor` RuntimeClass on the same node is unchanged
