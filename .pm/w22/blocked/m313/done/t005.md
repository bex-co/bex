## Objective

Price snapshot storage at Render × 0.70 and show the new kinds wherever usage is shown, so a suspended sandbox is billed storage only.

## Context

- Render rates (render.com/articles/render-sandboxes-vs-vercel-sandboxes, published 2026-11-06): snapshot storage $0.08 per GB-month. `pricing.yaml` convention is Render × 0.70 (header comment at line 28), giving $0.056 per GB-month.
- `lego/backend/internal/pricing/pricing.yaml` keeps rates in per-second units (`storage.usdPerGBSecond`, `disk.usdPerGBSecond`); `pricing.go` maps kinds to rates and estimates cost; Stripe lines are ADR040 (`lego/backend/internal/billing/`).
- Surfaces: `GET /v1/usage`, GraphQL `usage(period:)`, MCP `get_usage`; dashboard `dashboard/src/features/usage/components/charges-card.tsx` and `usage.graphql`.

## Steps

1. Add the snapshot-storage rate to `pricing.yaml` and `pricing.go`; the memory kind stays unpriced (w22/m314 prices it).
2. Expose both new kinds on REST, GraphQL and MCP together; label them in the dashboard charges card.
3. Add the Stripe line item for storage following ADR040; confirm a unit test for a workspace with only suspended sandboxes produces storage and no compute charge.
4. Update the ADR030 price sheet and the advisory `estimatedCost`.

## Files

- `lego/backend/internal/pricing/pricing.yaml`, `pricing.go`
- `lego/backend/internal/billing/`
- `lego/backend/internal/store/usage.go` and the usage handlers

## Acceptance criteria

- [ ] A fixture workspace with one suspended 10 GB sandbox for a month previews $0.56 of storage and no compute
- [ ] The three usage surfaces list the same kinds
- [ ] The dashboard usage page renders them

## Out of scope

## Result — 2026-11-10

`pricing.yaml` `sandboxSnapshot.usdPerGBSecond` = $0.056 / 2,628,000 (Render's $0.08 × 0.70; the article is dated 2026-11-06 and is the only source). A suspended 10 GB sandbox for a 730 h month previews $0.56 and no compute (`TestEstimateSuspendedSandboxPaysSnapshotStorageOnly`); the memory kind reads at a rate of $0 and never changes the bill (`TestMemoryShadowMeterIsShownAndNeverBilled`). REST, GraphQL and MCP carry the same kinds (`TestResourceKindSurfacesAcrossAdapters`); the dashboard labels both. **Stripe:** `sandbox_snapshot_gb_hours` in `scripts/stripe-billing-setup.py`, and the meter ships **held** behind `BEX_STRIPE_SANDBOX_STORAGE_METER=1`, like the agent model cost meter, so nothing bills against a Price that does not exist. Production still needs the setup script run on the test and live Stripe accounts before the flag is set; that is part of t006's gate.
