## Objective

Every REST sandbox operation spends one unit of the class t001 assigned it, and answers the limiter's 429 when the class is exhausted.

## Context

- Routes: `lego/backend/internal/sandbox/rest.go` (sandboxes), `groups_surfaces.go` (groups), `images_surfaces.go` (images and builds), `connect.go` and `file_connect.go` (run and file connect tokens), `executions.go` (exec history).
- The group concurrency 429 (w22/m311) is a different refusal with its own code; a rate-limit 429 must stay distinguishable from it.

## Steps

1. Classify each route at registration so a new sandbox route cannot be mounted without a class. A test walks the mounted sandbox routes and fails on an unclassified one.
2. Charge the bucket before the handler does work, after authentication (the key is the user).
3. Charge exec and file transfer where t001 found them countable, once per customer operation.
4. Real-database tests through the router: the 101st create in a minute is 429, reads refuse at 401, a group write refuses at 101, and a terminate is still accepted after 500 other sandbox calls.
