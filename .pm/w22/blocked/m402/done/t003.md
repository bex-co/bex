## Objective

When a workspace requires 2FA, refuse every workspace-scoped call from a human principal who has not enrolled a second factor, on all three API surfaces through one shared point, including calls made with an API key that principal created.

## Context

- The seam is the one t001 chose; candidates are the workspace-resolving check in `lego/backend/internal/authz/authz.go` and the admission decision in `lego/backend/internal/api/authadmission.go`. `lego/backend/internal/core/identity.go` carries the resolved identity; an API key's creator is on the key (`lego/backend/internal/apikeys`).
- The enrollment fact comes from the Kratos identity (`lego/backend/internal/workspaces/kratos.go` ~191–199, `MFAEnabled`); `BEX_KRATOS_ADMIN_URL` unset means the lookup is unavailable (`members/service.go` ~133 says "honest omission"): decide fail-open versus fail-closed in t001 and keep it consistent; recommended: fail closed only when the setting is on, since a workspace that asked for enforcement should not silently lose it to a misconfigured lookup.
- Exempt routes and the cache TTL are from t001. Error: coded 403 `WORKSPACE_2FA_REQUIRED` with `{workspaceId}`.

## Steps

1. Write failing tests first at the shared point: setting off, any member passes; setting on and an enrolled member passes; setting on and an unenrolled member gets the coded 403; a platform principal passes; an exempt route passes for the unenrolled member.
2. Implement the check with the t001 cache (TTL, keyed by identity), reusing the lookup function from t002.
3. API keys: a key whose creator lacks 2FA is refused for that workspace's resources; a key created by an enrolled member keeps working; revoking is not blocked.
4. Prove REST, GraphQL and MCP each reach the shared point: one test per surface calling a representative workspace-scoped operation as the unenrolled member (REST `GET /v1/services`, a GraphQL query, an MCP tool) and asserting the same code.
5. Verify the member's other workspaces (setting off) are unaffected in the same test.
6. Metrics: a counter for refusals by workspace-less reason (do not label by workspace id; cardinality), if the package already exports request metrics (`internal/api/httpmetrics.go`).

## Acceptance criteria

- [ ] An unenrolled member gets `WORKSPACE_2FA_REQUIRED` on REST, GraphQL and MCP; an enrolled member and every member of a workspace with the setting off are unaffected.
- [ ] An API key created by an unenrolled member is refused for that workspace and works again after enrollment (within the cache TTL).
- [ ] The exempt routes work for a blocked member.
- [ ] The real-DB backend suite and `make lint` pass.
