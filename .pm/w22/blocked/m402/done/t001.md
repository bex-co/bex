## Objective

Settle the five design questions before code, in the ADRs, so t002 to t005 implement one agreed behavior. The answers below are this milestone's recommendations; record them as recommendations with their basis, not as user decisions.

## Context

- Render's behavior (render.com/docs/login-settings, 2026-11-14): admin-only toggle in Workspace Settings; a member without 2FA cannot reach the workspace's resources or settings; their SSH and API keys are blocked too; no plan requirement.
- `lego/backend/internal/workspaces/kratos.go` (~191–199) already derives `MFAEnabled` from the Kratos identity: `totp` is presence-based ("Kratos only writes the entry on enrollment") and `webauthn` is read with the credential include. `highest_available` (ADR012 §9) makes Kratos demand the second factor at login for any enrolled user, so an enrolled member's sessions are AAL2 anyway.
- Identity and admission seams: `lego/backend/internal/core/identity.go` (`IdentityFrom`), `lego/backend/internal/api/auth.go`, `lego/backend/internal/api/authadmission.go`, `lego/backend/internal/authz/authz.go` (OpenFGA checks, where a request's workspace is known). API keys carry their creator (`apikeys` `CreatedBy`). SSH and ticket paths: `lego/backend/internal/sshgateway/` (`resolver.go`, `revalidate.go`, `nativessh`), `shellticket`, `agentsessionticket`, `sandboxexec`.
- Machine principals exist (`members/machine_binding_test.go`, `members/mint_class_test.go`).

## Steps

1. **Storage.** Recommend a boolean on the workspace record (`require_two_factor`, default false), read with the workspace. Confirm which table and read path `workspaces/service.go` uses.
2. **What "has 2FA" means.** Recommend: the member's Kratos identity has an enrolled `totp` or `webauthn` credential (the existing `MFAEnabled`), not "this session is AAL2". State why (Kratos forces AAL2 at login for enrolled users, and a session minted before enrollment should not be locked out by a stricter test than Render's page states).
3. **Who is checked.** Recommend: every human principal acting in the workspace, including an API key (the key's creator), an SSH key (the key's owner) and an agent-session or sandbox ticket (the user who minted it); non-human platform principals that cannot enroll (bex-system components, HMAC webhooks) are exempt. Read `members/machine_binding_test.go` to classify machine bindings before writing this down.
4. **Exempt routes.** The routes a blocked member needs to understand and fix their state: reading their own identity, listing their workspaces, reading the workspace's name and the setting itself, and leaving the workspace. Everything else in the workspace is refused. Record the list.
5. **Lock-out guard.** Recommend: enabling is refused with a coded 409 unless the acting admin has 2FA. Say plainly that Render's page does not describe this, and that it exists so the setting cannot lock out its only actor.
6. **Cache.** The check needs a Kratos admin lookup per human per workspace. Recommend a per-identity cache of the enrollment fact with a short TTL (60s) and invalidation on the enrollment path where cheap; the TTL is the documented bound on "access returns after enrolling" and "blocked again after removal".
7. **Error shape.** A coded 403 `WORKSPACE_2FA_REQUIRED` with `{workspaceId}` in details, built with the repo's coded-error helpers (`lego/backend/internal/core/coded_error_test.go` shows the shape). Render documents no error code for this, so it is a bex-owned vocabulary entry: say so.
8. **Pick the enforcement seam** for t003 (candidate: the workspace-resolving authorization check in `authz`, so REST, GraphQL and MCP share one point, with `authadmission.go` as the precedent for an admission decision) after reading both files, and record why.
9. **Write it down:** a new section in `docs/ADR012-auth.md` ("Workspace-enforced 2FA"), a note in `docs/ADR024-members.md` next to the `mfaEnabled` paragraph, and `docs/ADR018-render-parity.md`: a new row (or an extension of the MFA row) citing the Render page, the pinned-OpenAPI event names and this milestone.
