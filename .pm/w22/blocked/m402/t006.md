## Objective

Prove the milestone's observable end state on a running stack, with real Kratos TOTP, not only against test doubles.

## Context

- `scripts/dev-env.sh <N> {up,down,status,clean,env}` brings up a `dev-N` environment and is pre-approved (AGENTS.md, 2026-09-09); respect the harness's isolation boundaries (own namespaces and ports).
- `scripts/auth-mfa-e2e.sh` registers a user and enrolls TOTP plus `lookup_secret` recovery codes through Kratos's settings flow: reuse its approach to enroll in this check.
- Record outcomes as text in this task and the milestone README. No screenshots, HAR files or raw logs in git (`#NO-ARTIFACTS-IN-GIT`).

## Steps

1. Bring up `dev-N`. Create a workspace with an admin (A) and two more members: one who will enroll TOTP (B) and one who will not (C). Create an API key and an SSH public key as C, and an API key as B.
2. A tries to turn the setting on without 2FA: expect the coded 409. A enrolls TOTP, turns it on: expect success and one `ChangeTeam2FAEnforcementEvent` in the audit log.
3. C: a dashboard session shows the blocked page; REST and GraphQL with the session cookie return `WORKSPACE_2FA_REQUIRED`; C's API key returns the same; a shell or SSH ticket mint and a native SSH login are refused; C's other workspace still works.
4. B: all of the above succeed, including B's API key.
5. C enrolls through the page's link; within the t001 TTL, C's session, API key and SSH work again.
6. C removes their TOTP (or an admin-simulated removal through Kratos admin): within the TTL C is blocked again, and an open shell session is closed at the next revalidation.
7. A turns the setting off: C works without 2FA; a second audit event is recorded.
8. Write the observed codes, timings and the TTL/revalidation bounds into the milestone README under "Live check". Tear the environment down.
