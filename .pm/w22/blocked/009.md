# Widen the dashboard's `/agents` gate to every workspace, the day the platform model route widens

Why: `dashboard-agents` is forced on only for workspace `tea-d98210cbbpdc73dcrkvg`, and no board item widens it, so once `w10/m14` t007 opens the backend route to everyone the dashboard would still hide `/agents`; ADR008 § Render parity first and DO_NOT_DO #2 require a dated widen step for every rollout gate.

- **Evidence.** `dashboard/src/config/growthbook.ts`: `AGENTS_DASHBOARD_BETA_WORKSPACE_ID = "tea-d98210cbbpdc73dcrkvg"`, and `"dashboard-agents": { defaultValue: false, rules: [{ condition: { workspaceId: AGENTS_DASHBOARD_BETA_WORKSPACE_ID }, force: true }] }`. Consumers: `use-growthbook.ts`, `dashboard-nav.ts`, `global-search-dialog.tsx`, the sidebar section, and the route guard `dashboard/src/common/lib/growthbook/require-agents-feature.ts`. `grep -rn "dashboard-agents\|AGENTS_DASHBOARD_BETA" .pm` finds nothing, so no task owns this widen.
- **What `w10/m14` t007 covers.** Only the backend allowlist `BEX_AGENT_PLATFORM_MODEL_WORKSPACES` in `lego/operator/config/api/deployment.yaml` (the only allowlist env in that file). t007 was due 2026-11-13 and, as of 2026-11-12, waited only on an OpenRouter top-up (`.pm/w10/blocked/m14/t007.md`).
- **Due:** the same day t007 lands. The BYO model-key path (t012) already exists, so this is not strictly blocked by t007, but widening the UI first would send workspaces without a key to a "model API key is missing" dead end that t007 exists to remove.

Steps:
