## Objective

Make a steer sent during a running turn durable and visible instead of a 409, and let a user manage the pending messages.

## Context

- `Steer` is in `lego/backend/internal/agentsessions/service.go` (~lines 1775–1830): the phase switch at ~1818 and the store-race mapping at ~2126 both return `AGENT_SESSION_TURN_IN_FLIGHT`. Routes: `lego/backend/internal/agentsessions/rest.go` (`POST /v1/agent-sessions/{id}/steer` at ~225, `/cancel` at ~143), `graphql.go` (`steerAgentSession`, ~847), `mcp.go` (`steerArgs`, ~135). Authorization for operating a session is the existing steer relation (`can_operate`, `service.go` ~584).
- The D11 queue to model on: `lego/backend/internal/store/migrations/0237_agent_session_feedback.up.sql` and `lego/backend/internal/agentsessions/pr_feedback.go`. Names and shapes come from t001's ADR section.
- Migrations: paired `NNNN_name.up.sql`/`.down.sql` in `lego/backend/internal/store/migrations/` (the last one when this was filed is `0256`; re-scan). Mint ids only through `internal/id`.
- The prompt-history quota (`AGENT_SESSION_PROMPT_QUOTA`) and `Steer`'s 100,000-byte prompt bound still apply to a queued message's body.

## Steps

1. Write failing tests first: a steer while a turn runs returns the queued view; a second returns it behind the first; the cap answers `AGENT_SESSION_QUEUE_FULL`; the same idempotency key does not enqueue twice; list/edit/delete/move respect `can_operate`; a canceled or archived session still refuses; editing or deleting a message already dispatched answers a coded 409.
2. Migration and store functions for the queue table per t001 (pending, dispatched, with the claim/lease and delivered-turn columns and an ordering column), with a down migration.
3. In `Steer`, replace the in-flight refusal with an enqueue; keep the existing validation (prompt size, skills, secrets, attachments) at enqueue time where it does not depend on dispatch state, and defer spend-cap and live-sandbox checks to dispatch (t003).
4. Expose list, edit, delete and move on REST (paths from t001), GraphQL (a `queuedMessages` field on the session type and mutations) and MCP; include the pending count on the session view so the list page can show it.
5. Clear the queue when the session is canceled, archived or deleted (store transaction with that transition).
6. Real-Postgres store tests (the `agentsession_feedback_pg_test.go` pattern).
