## Objective

Add "Stop turn": end the running turn without ending the session, as Devin's interrupt does ("the part of the reply you already saw stays in the chat"), implemented in the shape t001's spike found possible.

## Context

- t001 names the shape: (a) the driver ends the turn and the session goes idle in the same sandbox, (b) the turn is cancelled and the sandbox torn down with the session resuming on the next message, or (c) an engine that supports neither refuses with a coded error. Implement what t001 recorded; if (c) applies to every engine, stop and report back to the milestone README instead of building a verb that always refuses.
- Cancel today: `POST /v1/agent-sessions/{id}/cancel` (`lego/backend/internal/agentsessions/rest.go` ~143), GraphQL `cancelAgentSession` (`graphql.go` ~953), MCP `cancel_agent_session` (`mcp.go` ~31); it is terminal and must stay so.
- Driver: `lego/agent-image/driver/src/session.ts` (turn runner with `abortSignal` and `turnAbort`, ~lines 211–226; `stopProvider`, ~195), `acp.ts`, `gateway.ts`, `main.ts`. The gateway-to-driver control path and its envelope are under `lego/backend/internal/agentsession/` (`spawn.go` shows how a Pod-verified verb is forwarded).
- What a stopped turn leaves: commits already pushed stay on the `bex-agent/*` branch; assistant output already streamed is already in the durable transcript (ADR051); the turn row must read as interrupted, not failed, and must not trigger the failure callout or a spend or PR-state side effect that assumes a normal finish.

## Steps

1. Write failing tests first: interrupt on a running turn returns the session to a steerable idle state; the transcript keeps the partial reply; an interrupt on an idle session answers a coded 409 (`AGENT_SESSION_NO_TURN_RUNNING`, or the name t001 chose); a viewer is refused; a canceled session still answers its existing code; Cancel behaves as before.
2. Driver side: expose the turn-level abort through the gateway control path with the Pod-verified envelope; the turn settles as `interrupted`.
3. Service side: `Interrupt(ctx, id)` with the `can_operate` check, an audit verb, the settle bookkeeping that `completion.go` does for a normal turn (so the dispatcher in t003 sees a settled turn), and queued messages kept.
4. Expose it on REST (`POST /v1/agent-sessions/{id}/interrupt`, or t001's path), GraphQL and MCP.
5. Driver unit tests (`lego/agent-image/driver`), service tests, and an on-cluster check on `dev-N`: start a long turn, interrupt, send a follow-up, see it run with the earlier reply intact.
