## Objective

Decide and record, before any code, how bex stores groups, binds a sandbox to one, creates the default group, and counts toward the concurrency limit, so the REST, GraphQL and MCP work in later tasks implements one agreed contract.

## Context

- Render contract (ADR104 D7): up to 10 groups per workspace; each has a `concurrencyLimit` (default 1,000, lowerable); suspended sandboxes do not count; create and resume answer **429** at the limit; region is `oregon` only and the group sets it; snapshots belong to the source sandbox's group.
- Pinned OpenAPI (`lego/backend/internal/api/openapi/render-public-api-1.json`): `create-sandbox-group` body `ownerId`, `name` (unique in the workspace), `region` (default `oregon`); `update-sandbox-group` is a PATCH of `concurrencyLimit` (integer ≥ 1; "lowering the limit does not stop existing sandboxes"); a group has `id`, `ownerId`, `name`, `region`, `isDefault`, nullable `environmentId`, `concurrencyLimit` (the effective limit), `createdAt`, `updatedAt`. Responses list 201/200, 400, 401, 403, 404, 409, 429, 500, 503.
- Today `lego/backend/internal/sandbox/notoffered.go` (`NotOfferedRoutes`) answers `SANDBOX_GROUPS_UNSUPPORTED` for GET/POST `/v1/sandbox-groups` and GET/PATCH `/v1/sandbox-groups/{id}`, and a `sandboxGroupId` on create or list answers 400 (ADR018 § Sandbox create flags).
- Precedent for a per-sandbox attribute stored beside OpenSandbox: `lego/backend/internal/store/sandbox_names.go` (w5/m287). Ids are minted only through `lego/backend/internal/id` (`id.New(kind)`, hyphen, e.g. `sbg-`); there is no group kind there yet.
- w3/m303 t003 keeps `sandbox-groups delete`, `default set` and `credentials` as named refusals; this milestone must not conflict with it.

## Steps

1. Re-read render.com `/docs/sandboxes-limits` and `/docs/sandboxes-creating` and the OpenAPI operations above; note the date.
2. Decide: id kind and table; default group created at workspace creation plus a backfill, or lazily on first use; how a sandbox is bound to a group (a column beside the sandbox name, or an OpenSandbox metadata stamp); which statuses count toward the limit (suspended do not); what answers the over-10-groups case if Render documents none (record it as a guess).
3. Decide `environmentId` (ADR032 environments are out of scope here: return null) and `region` (only `oregon`, ignored for placement as D7 says).
4. Write the section `§ Sandbox groups (w22/m311)` in `docs/ADR042-sandbox-cluster-substrate.md` (precedent: the w32/m283 and m297 sections) and update ADR104 D7 and gap 2.
