# bex's own release hint follows Render CLI v2.38.0's notice rules: agents get one line, JSON and YAML output get none

Why: since v2.38.0 Render's CLI tells its user about a newer release under rules bex's own hint does not follow, so a `bex` user meets a different notice than a `render` user does (found by w22/m604, 2026-11-24, which turned Render's notice off in `bex` because it names Render CLI releases).

- **Render v2.38.0** (`internal/updatenotice` at `09b7802aa379`, CHANGELOG "A notice after a command when a newer release is available, at most once a day. It goes to stderr and doesn't show in scripts, CI or structured output"): it shows to a person at a terminal (every stream a TTY, `TERM` not `dumb`, not CI) and to an AI agent in one plain line whether or not it runs in a terminal (the agent markers of `pkg/analytics/agentsignals.go`, not CI); it never shows after `-o json` or `-o yaml`, even when stdout and stderr share a terminal; `RENDER_CLI_DISABLE_UPDATE_NOTIFIER` turns it off; a Homebrew install waits 6 hours after a release; it links the release notes.
- **bex today** (`lego/cli/main.go` `startUpdateCheck`, `internal/update` `Allowed`): shown only when stderr is a TTY and `CI` is unset, also after `-o json`; an agent outside a terminal gets nothing; only `BEX_NO_UPDATE_NOTIFIER` turns it off. `bridge.Apply` sets `RENDER_CLI_DISABLE_UPDATE_NOTIFIER=1` for upstream's notice, so honoring a user's own setting of it needs `apply` to record that value first.
- **End state:** the bex hint follows Render's rules for bex releases (agents, structured output, a user-set `RENDER_CLI_DISABLE_UPDATE_NOTIFIER` beside `BEX_NO_UPDATE_NOTIFIER`, the Homebrew wait for `brew upgrade bex`), with tests driving the binary as an agent and with `-o json` in a pseudo-terminal, and `docs/bex-cli.md` § `BEX_NO_UPDATE_NOTIFIER` says so.
