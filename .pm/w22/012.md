# Stop turn keeps only what the agent had pushed: save the checkout's work before the sandbox is replaced, and settle in seconds

Why: Devin's Stop keeps the machine, so an interrupted agent's work survives, but every bex turn runs in a fresh sandbox and the driver never commits or pushes (ADR090), so work the agent had not pushed when it was stopped is lost when the next turn replaces the sandbox.

- **Evidence.** [ADR047 D12](../../docs/ADR047-cloud-coding-agent-sessions.md) "As built": after an interrupt the driver records the checkout's Git facts in the status file, the delivery note names unpushed or uncommitted work, and "anything it had not [pushed] is named in the delivery note and lost when the next turn's sandbox replaces it". `lego/agent-image/driver/src/interrupt.ts` and `session.ts` (the status `git` facts) hold the driver side. ADR090 forbids the driver to commit or push, because the agent owns its Git credentials and history. Settling is by the Completer's 15 s tick (`lego/backend/internal/agentsessions/completion.go`), so Stop takes up to 15 s to show.
- **Devin.** Its interrupt keeps the partial reply and the session's machine; [release notes](https://docs.devin.ai/release-notes/2026), 2026-10-14 and 2026-10-16. Re-read them: whether Devin's Stop keeps the machine was not established, so verify it before choosing.
- **Options to weigh (each is a choice for the ADR, not decided here).** (1) Keep the interrupted turn's sandbox until the next message and let that turn start in it (it breaks "every turn is a fresh sandbox", so it needs the idle-reuse design); (2) before the sandbox is reaped, run a platform-side save of the working tree to a `bex-agent/wip/…` ref with a narrowly scoped credential, outside the agent's history; (3) leave it and surface the loss in the dashboard when an interrupted turn had unpushed work (the status already carries the facts). For the 15 s latency: have the Completer react to the status file sooner for an interrupted turn, or make the interrupt wait for the status for a few seconds and answer with the settled state.
- **Steps.** Pick the option with the user (it touches ADR090 or D12); implement it; test with a real-Postgres store test plus a driver test (an interrupted turn with uncommitted changes keeps them by the chosen mechanism, and the next turn sees them); record the live check for the next `dev-N` session.
- **Done when:** an interrupted turn's unpushed work survives into the next turn (or the loss is shown before the user sends the next message), and Stop shows within a few seconds.

## Triage 2026-11-14 (/loopx w22): blocked on a decision that changes ADR090

- **Premise holds.** The driver never commits or pushes ([ADR090](../../docs/ADR090-agent-owned-delivery.md) and ADR047 D12 "As built"), every turn runs in a fresh sandbox, and an interrupt settles on the Completer's 15 s tick, so an interrupted turn's unpushed work is lost when the next turn replaces the sandbox. `lego/agent-image/driver/src/interrupt.ts`, `session.ts` and `lego/backend/internal/agentsessions/completion.go` are as the note says.
- **Why it is not the worker's to pick.** Every option that keeps the work either moves custody of the agent's Git history (a platform-side save to a `bex-agent/wip/…` ref needs a credential and a commit the agent did not make, which is exactly what ADR090 forbids the driver) or changes "every turn is a fresh sandbox" (reusing the interrupted turn's sandbox). Both are security and architecture decisions for the user, not a parity detail Devin's behavior settles: whether Devin's Stop keeps the machine was not established (the release notes of 2026-10-14 and 2026-10-16 say only that the seen reply stays and that queued messages can be edited).
- **Recommendation (a recommendation, not a decision):** first surface the loss, which needs no custody change: the dashboard names the unpushed and uncommitted files from the status `git` facts next to an interrupted turn, before the user sends the next message. Then, if the user wants Devin's persistence, amend ADR090 to let bex-api, not the driver, push a work-in-progress commit of the working tree to a `bex-agent/wip/<session>` ref with the installation token it already holds for PR delivery, and keep the agent's own branch untouched. The 15 s latency can be fixed independently: the Completer reads the status file of a session with a recorded stop request on a 2 s tick.
- **Next action when the user decides:** `/pm unblock w22/012` with the chosen option, then promote it (`/pm promote w22/012`): it is more than an hour.

## 解阻记录 2026-11-14（/unblock w22）

- **来源：** 用户决定（D3，2026-11-14）选择 **A**。
- **决定：** 被 Stop 的 turn 的 sandbox 不销毁，暂停保留；该 session 的下一条消息恢复它，而不是新建 sandbox，所以没推送的改动会留到下一个 turn。保留期设得比 Devin 的 14 天短（具体值由 worker 提出并写进 ADR047 D12）。保留下来的镜像成本吸收（见 w22/005 的结论，Devin 的睡眠 session 不计费），受每 workspace 存储上限约束。
- **用户接受的取舍：** 这改变 ADR047 D12 的"每个 turn 一个新 sandbox"，但**不碰** ADR090 的 Git 托管规则（driver 仍不 commit/push）。B（bex-api 推 WIP 分支）和 C（只提示会丢）没有选。
- **对标依据：** Devin 的休眠 session 机器保留（release notes 2026-09-25、2026-10-05、2026-10-09：休眠的机器被预览或 SSH 唤醒、打开 Files/Terminal 唤醒、14 天内可恢复）。Devin 的 Stop 本身是否保留机器文档没写，这一点没有核实，所以不把它写成 Devin 的承诺。
- **worker 的下一步：**
  1. 先做、不需要等设计：Stop 要 15 秒才显示的问题。Completer 对有 Stop 请求记录的 session 用 2 秒 tick 读 status 文件，或让 interrupt 等几秒再回结算后的状态。这件事可以单独发布。
  2. 其余部分超过一小时：先 `/pm promote w22/012` 成里程碑。设计要点：中断后暂停而不是销毁该 sandbox；下一条消息恢复它并重新签发短期凭据和模型 key（恢复的 sandbox 不能沿用旧的）；保留期到了或 workspace 达到存储上限时回收，并在 dashboard 的该 turn 旁明确写出"未推送的改动已随 sandbox 回收而丢失"；D12 的"As built"和 ADR018 里把"被中断的 turn 只保留已推送的内容"那条偏离改写成已关闭（并保留一行历史）。
