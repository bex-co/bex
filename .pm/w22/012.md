# Stop turn keeps only what the agent had pushed: save the checkout's work before the sandbox is replaced, and settle in seconds

Why: Devin's Stop keeps the machine, so an interrupted agent's work survives, but every bex turn runs in a fresh sandbox and the driver never commits or pushes (ADR090), so work the agent had not pushed when it was stopped is lost when the next turn replaces the sandbox.

- **Evidence.** [ADR047 D12](../../docs/ADR047-cloud-coding-agent-sessions.md) "As built": after an interrupt the driver records the checkout's Git facts in the status file, the delivery note names unpushed or uncommitted work, and "anything it had not [pushed] is named in the delivery note and lost when the next turn's sandbox replaces it". `lego/agent-image/driver/src/interrupt.ts` and `session.ts` (the status `git` facts) hold the driver side. ADR090 forbids the driver to commit or push, because the agent owns its Git credentials and history. Settling is by the Completer's 15 s tick (`lego/backend/internal/agentsessions/completion.go`), so Stop takes up to 15 s to show.
- **Devin.** Its interrupt keeps the partial reply and the session's machine; [release notes](https://docs.devin.ai/release-notes/2026), 2026-10-14 and 2026-10-16. Re-read them: whether Devin's Stop keeps the machine was not established, so verify it before choosing.
- **Options to weigh (each is a choice for the ADR, not decided here).** (1) Keep the interrupted turn's sandbox until the next message and let that turn start in it (it breaks "every turn is a fresh sandbox", so it needs the idle-reuse design); (2) before the sandbox is reaped, run a platform-side save of the working tree to a `bex-agent/wip/…` ref with a narrowly scoped credential, outside the agent's history; (3) leave it and surface the loss in the dashboard when an interrupted turn had unpushed work (the status already carries the facts). For the 15 s latency: have the Completer react to the status file sooner for an interrupted turn, or make the interrupt wait for the status for a few seconds and answer with the settled state.
- **Steps.** Pick the option with the user (it touches ADR090 or D12); implement it; test with a real-Postgres store test plus a driver test (an interrupted turn with uncommitted changes keeps them by the chosen mechanism, and the next turn sees them); record the live check for the next `dev-N` session.
- **Done when:** an interrupted turn's unpushed work survives into the next turn (or the loss is shown before the user sends the next message), and Stop shows within a few seconds.
