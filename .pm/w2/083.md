# 083 — main's `test (bex CLI)` is red since `059874a26`: the handoff snapshot tests fail with no git identity on GitHub-hosted runners

Why: every push that touches `lego/cli` turns main red, and the repository rule is to fix a red main first, shipped alone as `fix(ci): …`.

- **Source:** `/pm-brainstorm for w2` 2026-11-12, item 1. Nothing else on the board tracks it.
- **Evidence:**
  - `test (bex CLI)` has failed 9 runs in a row since `059874a26` (w1/m341), most recently run 43311635243 (2026-11-12 21:34 UTC).
  - Failing tests: `TestSnapshotLeavesTheCheckoutAlone`, `TestHandoffPushesTheWorktreeAndStartsTheSessionOnIt` and `TestHandoffDeletesItsBranchWhenTheCreateIsRefused`, each with `git commit-tree: Author identity unknown`.
  - `lego/cli/internal/agent/gitsnap.go:166` runs `commit-tree` with no identity. The fixture `gitIn` (`handoff_test.go:37`) passes `-c user.name/-c user.email` only to its own git calls.
  - GitHub-hosted runners have no global git identity. A developer machine has one, so the local ship gate passes and the red never shows there.
- **Fix:**
  1. The fixture writes a repository-local identity (`git config user.name/user.email` in `newGitFixture`), as a real checkout has.
  2. The tests run with `GIT_CONFIG_GLOBAL=/dev/null` (and `GIT_CONFIG_NOSYSTEM=1`), so a local run fails the same way CI does.
  3. When `commit-tree` fails for a missing identity on a user's machine, `bex agent handoff` names it in one line with the command to fix it (`git config user.email …`), instead of git's raw multi-line text.
- **Acceptance:**
  - The three tests pass locally with the global config isolated, and fail without step 1.
  - `test (bex CLI)` on main is green after the push.
  - A handoff test with no identity asserts the one-line hint.
- **Files:** `lego/cli/internal/agent/handoff_test.go`, `lego/cli/internal/agent/gitsnap.go`.
- Render parity: not applicable (test fixture and CLI copy).
