## Objective

Give the database page a connection-pool switch that behaves like Render's.

## Context

- Render ([docs](https://render.com/docs/postgresql-connection-pooling)):
  - The switch lives on the database's Info page, under General > Connection Pool.
  - Turning it on opens a confirmation modal that warns the database restarts (a few minutes of downtime), or fails over when HA is on. The confirm button is **Enable connection pool**.
  - Pooled URLs on port 6432 then appear.
  - Free databases cannot pool.
- bex: `dashboard/src/features/databases/components/access-control-panel.tsx:197` `PoolerSection` (`supportsPooling` is already passed in at `:55`). `databases.accessPoolerDisabled` (`locales/en.ts:983`) currently says only the API can enable it.
- The confirm dialogs live in `database-confirm-dialogs.tsx`. Use `ha-panel.tsx` as the pattern for an HA-aware warning.

## Steps

1. Add `UpdateDatabaseConnectionPool` to `dashboard/src/features/databases/api/databases.graphql` and regenerate the types.
2. Put the switch where Render puts it, relative to bex's page layout: the database page's general information, or `PoolerSection` if that is where bex shows General details. Record the choice in the task notes.
3. Confirm before enabling and before disabling. The copy names the restart, or the failover when HA is on.
4. On free plans, disable the switch and use Render's reason. Replace `databases.accessPoolerDisabled` in en and zh.
5. Keep a loading skeleton that matches the ready state (AGENTS.md skeleton rule).
