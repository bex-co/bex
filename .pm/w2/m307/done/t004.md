## Objective

Let a dashboard user increase a database's storage, as Render's Plan page Storage section → **Edit** does.

## Context

- Render: "From your database's **Plan** page … scroll down to the **Storage** section and click **Edit**" ([docs](https://render.com/docs/postgresql-creating-connecting)).
- bex: `dashboard/src/features/databases/components/database-plan-section.tsx` (plan picker; reads `diskSizeGB` and `maxStorageGB` at `:59-66`). `database-metadata-card.tsx:87-88` only displays storage. `database-disk-autoscaling-control.tsx` is the sibling control.

## Steps

1. Read Render's storage rules in its docs (minimum step, maximum per plan, grow-only) and match them in the input's validation and helper copy. Record what Render documents.
2. Add `UpdateDatabaseDiskSize` to `databases.graphql`, and add a Storage **Edit** control in `database-plan-section.tsx` that refuses smaller values client-side and shows the server's named 400 as is.
3. After a grow, show the new size, plus a converging note while the live volume catches up, as the API reports it.
4. Free plans: the control is unavailable, with Render's reason (storage is fixed at 1 GB).
5. Keep a loading skeleton that matches the ready state.

## Acceptance criteria

- [ ] On dev-2, growing storage from the dashboard updates the size, and the CNPG volume grows.
- [ ] A smaller value is refused with the same named error as REST.
- [ ] `yarn lint` and `yarn test` pass.

## Result (2026-11-10)

- A Storage row ends the plan card: the current size and **Edit** (a plain Dialog).
- Accepted sizes: a whole multiple of 5 GB above the current size, up to the plan maximum. This is Render's rule, quoted in the dialog.
- The server's refusal shows in the dialog, which stays open.
- Edit is disabled on a fixed-storage plan (Free) and until the catalog names the plan.
- The rules live in `features/databases/lib/storage.ts`, which the create dialog and the read-replica check now share.
- The pending Postgres plan preview has the same Storage row. Reserved heights were re-measured (416px desktop, 764px at 390px wide) and match ready.
