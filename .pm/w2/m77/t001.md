## Objective

A dedicated, SSE-enabled S3-compatible bucket for agent-session snapshots exists, with a durable credential scoped to that bucket only, and the values are custodied through the standard `.env` → `scripts/gh-secrets.sh` flow.

## Context

ADR059 D3 requires object storage (never an OCI registry) with per-workspace prefixes (`agent-snapshots/<ws>/…`); ADR050 requires the bucket to have **default server-side encryption enabled** — the sandbox streams to presigned URLs, so at-rest encryption is provider-side, not client-side. The bucket must be **dedicated** — NEVER `bex-tfstate` (the ADR029 static-sites rule applies here too). `.env.example` already lists all the variable names (`BEX_AGENT_SNAPSHOT_S3_ENDPOINT/_BUCKET/_REGION/_PREFIX/_ACCESS_KEY/_SECRET_KEY`, lines 141–146), so only values are missing.

**Flag:** if console access for bucket/credential creation is user-held (likely — Hetzner/S3 provider console), record the exact steps needed (bucket name, region, SSE toggle, scoped-key policy) in this task file and hand off to the user rather than guessing or creating with an over-broad root credential.

## Steps

1. Identify the S3 provider + endpoint used by the existing backup contracts (`BEX_DB_BACKUP_ENDPOINT` custody in `.env`) to co-locate the snapshot bucket.
2. Create (or hand off creation of) the dedicated bucket with default SSE enabled; verify SSE with a `HeadObject`/bucket-encryption read after a test PUT.
3. Create a credential scoped to this bucket alone (no `bex-tfstate` reach); verify it can PUT/GET/DELETE under `agent-snapshots/` and is denied elsewhere.
4. Fill the six `BEX_AGENT_SNAPSHOT_S3_*` values in `.env` (never print them); run `bash scripts/gh-secrets.sh` to sync GitHub Actions secrets.
5. Confirm `.env.example` names still mirror `.env` exactly (no new names expected; mirror any addition, name + comment only).

## Files

- `.env` (values; never committed/printed) · `.env.example` (names only, already present)
- `scripts/gh-secrets.sh` (sync flow, run not edited)

## Acceptance criteria

- Bucket exists, is not `bex-tfstate`, and reports default SSE enabled (evidence captured for t005).
- Scoped credential verified: allowed on the snapshot bucket, denied on others.
- `.env` filled + gh-secrets synced; `.env.example` in sync.
- If handed off: the exact user-side steps are recorded here and the task blocks on their completion, not on guesses.

## Out of scope

Prod manifest/secret wiring (t002); ADR050 per-store credential rotation (standing deferral); client-side `age` encryption (presigned-URL path is provider-SSE by design).
