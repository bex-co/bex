## Objective

Define the web-push server-side contract: `BEX_WEBPUSH_VAPID_PUBLIC_KEY`, `BEX_WEBPUSH_VAPID_PRIVATE_KEY`, and `BEX_WEBPUSH_SUBSCRIBER` (the `mailto:`/URL VAPID `sub` claim), a one-shot keypair generation/rotation script following the `scripts/push-secret.sh` pattern, and a fail-closed gate: any required var unset ⇒ no web-push transport is constructed, no network calls, the dashboard reports "not configured", and existing behavior is byte-identical (the exact posture `BEX_PUSH_PROVIDER` blank already gives Expo).

## Context

- Expo transport config precedent: `lego/backend/internal/notifications/push/transport.go` — `push.Config{Provider, AccessToken, Endpoint, Timeout}`; empty provider returns a nil `Transport` and constructs no HTTP client. Wired in `lego/backend/cmd/api/main.go` (~line 249) from `BEX_PUSH_PROVIDER` / `BEX_EXPO_PUSH_ACCESS_TOKEN` / `BEX_EXPO_PUSH_URL`.
- `.env.example` has a "Native mobile push: Expo Push Service" section (~lines 347–366) documenting the optional-secret pattern (`bex-system/bex-push` Secret, `optional:true` secretKeyRefs); CLAUDE.md rule: `.env.example` must mirror every new env var (name + comment, never a value).
- Secret install pattern: `scripts/push-secret.sh` (Expo); the VAPID private key is the same class of out-of-band server credential.
- `pushMetrics.SetEnabled(mobilePush != nil)` in `main.go` shows the honest-availability pattern to extend.

## Steps

1. Add a `WebPushConfig` (public key, private key, subscriber, optional TTL/timeout) beside `push.Config` in `lego/backend/internal/notifications/push/`; validate at construction (base64url P-256 keys, `mailto:`/`https:` subscriber); all-unset ⇒ nil transport; partially set ⇒ startup error (mirror the unsupported-`BEX_PUSH_PROVIDER` fail-fast).
2. Write `scripts/webpush-secret.sh`: generate a VAPID P-256 keypair, install/rotate the `bex-system/bex-webpush` Secret, print the public key for the dashboard env; model on `scripts/push-secret.sh`.
3. Wire the three vars in `lego/backend/cmd/api/main.go` next to the Expo block; extend the availability reporting so `GET /v1/notification-settings/push/availability` (in `lego/backend/internal/notifications/rest.go`) can report web-push configured/unconfigured distinctly.
4. Mirror all three vars into `.env.example` under a new "Browser web push (VAPID)" section, comment-only, following the Expo section's tone.
