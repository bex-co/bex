## Objective

Add a control-plane-backed SSH-key feature that safely parses and fingerprints public keys, associates each key with the authenticated identity, and supports list/create/delete plus gateway lookup without storing private material.

## Context

- The gateway must map an SSH public-key fingerprint to the same caller subject OpenFGA authorizes.
- Keys are user-scoped rather than workspace-scoped: one identity can use the same key in every workspace where it has sufficient permission.
- New stored resource ids must be minted through `internal/id`; add a registered SSH-key kind rather than hand-building ids.

## Steps

1. Add the next reversible store migration for SSH key id, subject, display name, canonical authorized-key text, SHA-256 fingerprint, timestamps, and uniqueness constraints.
2. Create `internal/sshkeys` with strict public-key parsing, accepted algorithm policy, canonical serialization, duplicate detection, ownership checks, and constant-shape not-found behavior.
3. Add `id.SSHKey` to the closed registry and mint every row with `id.New(id.SSHKey)`.
4. Expose a read-only fingerprint-to-subject lookup seam for the gateway; never return another user's key through public verbs.

## Acceptance criteria

- [ ] Only valid supported public keys are stored; private-key text and malformed/trailing payloads are rejected.
- [ ] Duplicate key material cannot create two identities or ambiguous gateway authentication.
- [ ] List/delete are identity-scoped, and gateway lookup returns only the subject and non-secret key metadata.

## Out of scope

- SSH sessions, host keys, or Kubernetes access.
