## Objective

Translate authorized SSH session channels into a correctly attached Kubernetes `pods/exec` stream with stdin/stdout/stderr, TTY allocation, resize events, exit status, cancellation, and bounded lifetime.

## Context

- The app container—not an injected sshd—must receive the shell/exec session and its existing runtime environment.
- Kubernetes remotecommand requires `create` on `pods/exec`; pod get/list alone is insufficient.
- Redeploy/restart deletes the target pod and must naturally terminate the attached session.

## Steps

1. Support SSH `pty-req`, `window-change`, `shell`, and single `exec` requests; reject additional/unsupported channel types explicitly.
2. Select an available shell using the ADR's deterministic contract and return a useful unsupported-image error when none exists.
3. Bridge SSH streams to Kubernetes remotecommand, propagate terminal resizes and exit status, and cancel promptly on client disconnect, pod deletion, timeout, or server shutdown.
4. Enforce per-identity/global session caps and handshake/session deadlines from the threat model.

## Acceptance criteria

- [ ] Interactive commands see the app environment and terminal resize works.
- [ ] Non-zero remote exits reach the SSH client; disconnect/redeploy leaves no orphan exec stream.
- [ ] Unsupported forwarding, subsystem, and extra-session requests fail without reaching Kubernetes.

## Out of scope

- SFTP/SCP, agent forwarding, X11, and TCP/Unix-socket forwarding.
