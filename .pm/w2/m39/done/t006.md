## Objective

Implement a separately deployable backend SSH gateway that accepts only registered public keys, resolves the requested service/instance, and authorizes that identity against the target service before opening any session channel.

## Context

- The gateway belongs in `lego/backend` but should run as a separate process/Deployment so the HTTP API does not inherit `pods/exec`.
- SSH username encodes the service plus optional instance target; the presented key resolves the caller subject.
- Authorization must use the service's workspace through the `AuthorizeApp` seam and `can_operate`, never the caller's default workspace.

## Steps

1. Add `cmd/ssh-gateway` plus an `internal/sshgateway` server with bounded handshakes, modern algorithm policy, public-key-only auth, and stable host-key loading.
2. Resolve the public-key fingerprint to a subject, parse the requested target, and call the same resource-scoped OpenFGA authorization model as bex-api.
3. Permit only eligible current-revision Ready targets and collapse unknown key/service/instance/forbidden cases without cross-tenant disclosure.
4. Emit session-start/session-end audit facts with subject, service target, instance id, timing, and outcome—but never commands, environment, or terminal bytes.

## Acceptance criteria

- [ ] An unregistered/deleted key and a caller lacking `can_operate` cannot open a channel or distinguish a foreign service.
- [ ] The HTTP API process retains no `pods/exec` permission.
- [ ] Session audit records contain no command arguments, terminal data, or environment values.

## Out of scope

- Kubernetes exec streaming and public network exposure.
