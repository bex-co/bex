## Objective

Supply the exact service and instance data the official Render CLI needs to choose an SSH target: an honest `serviceDetails.sshAddress` and Render-shaped running-instance list backed by Ready app pods.

## Context

- The current Render CLI reads `sshAddress` only for web/private/background-worker details and calls `GET /v1/services/{id}/instances` for instance selection.
- `core.AppPods` and the App ownership labels are the existing safe pod-discovery seam; build/pre-deploy/static/cron pods must never leak into the list.
- The configured public host should be explicit (`BEX_SSH_HOST`), with SSH availability omitted when the gateway is not configured.

## Steps

1. Project `sshAddress` into eligible service details only when the SSH host is configured and the service plan/type supports it.
2. Add an authorized `ListInstances` core verb and `GET /v1/services/{id}/instances`, returning stable session target ids and pod creation times for Running+Ready current-revision pods.
3. Define any-instance and specific-instance username parsing so the gateway and REST projection share one implementation.
4. Reject suspended, free, unsupported, stale-revision, terminating, and non-Ready targets without exposing pod internals.

## Acceptance criteria

- [ ] Eligible service responses contain a CLI-usable SSH address; ineligible/unconfigured services omit it.
- [ ] The instances endpoint lists only Ready pods belonging to the requested service and current revision.
- [ ] Instance ids resolve deterministically back to exactly one pod without exposing raw Kubernetes credentials.

## Out of scope

- Creating ephemeral instances or waking suspended/free services.
