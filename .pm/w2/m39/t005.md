## Objective

Give humans a safe way to manage their public keys and discover the exact SSH command for an eligible service without embedding a browser terminal.

## Context

- Render places SSH public keys in user/account settings and shows a copy-ready command in a service Connect menu.
- The dashboard consumes GraphQL and must preserve its Kratos cookie-session architecture.
- Key material is public but deletion is security-sensitive; fingerprint and name should be the primary display.

## Steps

1. Add an SSH Public Keys panel with create, list, fingerprint display, and confirmed delete states.
2. Validate and explain accepted public-key input before submitting while leaving server validation authoritative.
3. Add an eligible service Connect → SSH affordance that copies `ssh <sshAddress>` and explains unavailable states.
4. Add localized copy and focused component/hook tests following the API-keys feature patterns.

## Files

- `dashboard/src/features/ssh-keys/`
- `dashboard/src/routes/settings.tsx`
- `dashboard/src/routes/services.$serviceId.*.tsx`
- `dashboard/src/locales/`

## Acceptance criteria

- [ ] A signed-in user can add/list/delete their keys and copy an eligible service's SSH command.
- [ ] Invalid/duplicate key and unavailable-service errors are actionable and do not expose internal details.
- [ ] No OAuth tokens, private keys, or terminal contents enter browser storage.

## Out of scope

- A browser terminal or client-side SSH implementation.
