## Outcome (2026-11-03)

- **Source card:** Settings → Source names the linked build source and what it builds from, read with `buildSource(id)`, with a skeleton while the name loads.
- **Update Source dialog:** gains a **Build source** tab. It lists the workspace's sources, asks for a start command only for a native-runtime source (the same allowlist as the backend, pre-filled with the runtime's default), and saves with `linkBuildSource` without deploying, like every source change. A failed list says so instead of claiming there are none.
- **Unlinking:** the Git and Image tabs unlink, since setting the service's own source clears the link. `setRepo`/`setImage` now return `buildSourceId`, so the card updates.
- **Backend:** `buildSourceId` on the GraphQL Service type; `linkBuildSource` mutation and `link_service_to_build_source` MCP tool over `LinkBuildSource`, which now runs the same protected-environment `repoint` check as a source change.
- **Follow-ups:**
  - GraphQL/MCP linking has no `dryRun` (REST does).
  - The picker lists the first 100 sources.
  - A linked service's Settings shows the image Deploy card even for a native source.
