## Objective

Bill a build source's builds as Render bills Build Source build minutes. Carrier builds currently go unmetered because the usage rollups enumerate `ListApps`, which excludes carriers.

## Context

- `lego/backend/internal/usage/service.go` `rollup`/`catchUp` → `catchUpAppThrough` meters instance, egress and build seconds per service row; `queryBuildSeconds` sums build Jobs labelled `app.bex.co/build=<CR name>`.
- A carrier has build Jobs only: no instances, no egress.
- Usage rows, invoice lines and the dashboard usage view key on the service id; a carrier's id is `bds-…`.

## Steps

1. Enumerate carriers alongside services for the build meter only (`build_seconds`), keeping instance/egress off for them.
2. Make sure billing (Stripe/Metronome lines) and the usage surfaces attribute `bds-` rows to the build source by name.
3. Declare the enumeration in `TestEveryAppEnumerationDeclaresBuildSources`.

## Files

- lego/backend/internal/usage/
- lego/backend/internal/store/usage.go

## Acceptance criteria

- [x] A carrier build's Job duration appears as `build_seconds` for the build source, and is billed like a service build.
- [x] A carrier never records instance or egress usage.

## Out of scope

- Build retention.

## Outcome (2026-11-03)

- **Metering:** the hourly usage rollup and catch-up meter every build source carrier (`store.ListBuildSourceCarriers`, part of the `UsageStore` interface) for `build_seconds` alone, under its `bds-` id. Build Jobs are found by the carrier's CR name in the build namespace, as for a service, and the platform-rebuild exemption applies.
- **After deletion:** a deleted carrier still meters its last builds, and builds only (no instance usage).
- **Display:** usage rows name the build source (its display name), not a deleted service, and its coverage streams stay open while it exists.
- **Billing:** Stripe/Metronome bill `build_seconds` by kind, so no billing change was needed.
- **Rollout note:** on first deploy each carrier's cursor starts within the 48-hour catch-up window, so recent carrier builds are billed retroactively, as for services.
