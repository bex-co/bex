## Objective

Serve the deploy half of Build Sources found by the round-5 drift (w2/m251): Render's deploy objects carry `buildId`, and `POST /services/{id}/deploys` accepts `buildId` to deploy a specific build of the service's build source.

## Context

- Pinned OpenAPI 2026-11-02: `deploy.buildId` on `list-deploys`, `retrieve-deploy`, `create-deploy` (201), `cancel-deploy`, `rollback-deploy`; `create-deploy` request gains `buildId`.
- New error codes `build_not_found`, `build_not_succeeded` in Render's `errorCode` enum.
- Deploys: `lego/backend/internal/deploys/rest.go`.

## Steps

1. Record the build id on deploys produced from a build source; return it on every deploy response (omit when none).
2. Accept `buildId` on create-deploy for build-source services; refuse with `build_not_found` / `build_not_succeeded` as Render does, and by name on services without a build source.
3. Mirror on GraphQL `triggerDeploy` and MCP `trigger_deploy`.

## Files

- lego/backend/internal/deploys/
- lego/backend/internal/apps/

## Acceptance criteria

- [x] A deploy from a build source lists its `buildId`; deploying an older succeeded build by `buildId` runs that image.
- [x] Unknown and failed builds return Render's error codes.

## Out of scope

- Build retention policy.

## Outcome (2026-11-03)

- **Storage:** `deploys.build_id` (migration 0190) is written in the deploy's own insert (`CommitInfo.BuildID`), and a rollback or restart copies its target's build.
- **Which build:** a deploy of a linked service records the build it ships. A fan-out takes the carrier deploy that went live; a manual deploy takes the carrier row serving its current build (`servingDeploy`).
- **Deploy by build:** `buildId` on create-deploy (REST, GraphQL `triggerDeploy`, MCP `trigger_deploy`) deploys a succeeded build. Refusals: `build_not_found` (404), `build_not_succeeded` (409), 400 combined with `commitId`/`imageUrl`/`deployMode`, and 400 on an unlinked service. It authorizes as create-like, like `commitId`.
- **Surfaces:** `buildId` appears on every REST/GraphQL/MCP deploy view.
- **Follow-ups:** a rollback restores the target's image through the release config but leaves the link's selected build (`spec.buildSource.image`) on the newer build, and a restart through the legacy fallback path carries no `buildId`.
