## Objective

Prevent any plan update from reducing the effective CNPG PVC request while preserving legitimate storage growth.

## Context

- The current helper compares requested storage only with the new plan floor.
- A `basic-1gb -> basic-256mb` update can render `5Gi -> 1Gi`, which CNPG rejects.
- Render plan changes and explicit storage settings need one stable effective-capacity rule.

## Steps

1. Derive effective storage from current allocated/requested capacity, explicit request, and new plan floor using a monotonic maximum.
2. Reject an explicit shrink with a named user-facing error instead of relying on CNPG admission failure.
3. Preserve the last effective size through projector/resync and plan changes.
4. Add downgrade, upgrade, explicit-grow, and explicit-shrink tests.

## Acceptance criteria

- [ ] A plan downgrade never emits a smaller CNPG storage request.
- [ ] An explicit grow emits the new request and reaches an observable resize condition.
- [ ] An explicit shrink is rejected consistently before CNPG admission.

## Out of scope

- Changing the storage sizes assigned to existing plan catalog entries.
