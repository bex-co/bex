## Objective

Rate-limit the deploy-hook trigger endpoint independently of the existing per-caller token bucket (`BEX_RATE_LIMIT`), since this endpoint is unauthenticated by design and has no caller identity to key on.

## Context

- root `CLAUDE.md`'s `BEX_RATE_LIMIT`/`BEX_RATE_BURST` are per-caller (keyed on authenticated identity) — this endpoint has no such identity, so it needs its own limiter, likely keyed per-token or per-App.

## Steps

1. Add a per-token (or per-App) rate limiter for the deploy-hook endpoint, independent of the main caller-token bucket.
2. Document the limit (reuse `BEX_RATE_LIMIT`'s default philosophy or pick a sensible fixed default).

## Files

- `lego/backend/internal/apps/rest.go` (or `deployhooks` package)

## Acceptance criteria

- [ ] Repeated triggers beyond the limit are rejected (429), not queued indefinitely or ignored.

## Out of scope

- Configurable per-workspace limits (fixed default is sufficient for v1).
