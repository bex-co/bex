## Objective

Add an unauthenticated-but-token-gated `POST`/`GET /v1/deploy-hooks/{token}` endpoint that validates the token and triggers a deploy on the matching App.

## Context

- This route needs to bypass the standard session/Bearer auth gate (`lego/backend/internal/api/auth.go`), similar in spirit to `w2/m34`'s callback exception — the token itself is the credential. Coordinate/sequence with `w2/m34` if both land close together, since both add narrow, explicit exceptions to the same blanket-gate file.
- Reuse the existing deploy-trigger internals from `internal/deploys` (`w2/m5`) — this endpoint should call the same `Trigger` verb, not reimplement it.

## Steps

1. Add the route, exempted from the standard auth gate (explicit, narrow, well-commented — same pattern as `w2/m34/t002`).
2. Look up the App by token; 404 on unknown/invalid token (don't leak whether a token format is "close" to valid).
3. Call the existing `deploys.Trigger` verb for that App.

## Files

- `lego/backend/internal/apps/rest.go` (or a new `deployhooks` package)
- `lego/backend/internal/api/auth.go` (route exception)

## Acceptance criteria

- [ ] `POST /v1/deploy-hooks/{validToken}` triggers a deploy.
- [ ] Invalid/unknown token returns 404, not a distinguishing error.

## Out of scope

- Rotation (t003), rate limiting (t005).
