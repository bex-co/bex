## Objective

Mint an opaque, unguessable deploy-hook token per App, stored so it can be looked up on trigger and rotated.

## Context

- `lego/backend/internal/id` (`id.New(kind)`) mints all resource ids per `docs/ADR020-identifiers.md` — reuse this convention for the token, or a dedicated high-entropy secret generator if id.New's ids aren't secret-strength (check before reusing).
- Store alongside App state (control-plane Postgres or a CR field/annotation — decide based on whether other App secrets like this already have a precedent).

## Steps

1. Decide storage: control-plane Postgres row (if `BEX_CP_DB_URI` is set) vs. a CR-level secret reference — follow the pattern of the least new machinery, consistent with existing App secret storage.
2. Mint a token on first request (lazy) or at App creation — decide and document.
3. Index for lookup: given a token, resolve the App.

## Files

- `lego/backend/internal/apps/service.go` (or a new `deployhooks` package if warranted)
- `lego/backend/internal/store/migrations/` (if a new column/table)

## Acceptance criteria

- [ ] Each App has (or can mint) a deploy-hook token.
- [ ] Token is high-entropy, not derivable from the App name/id.

## Out of scope

- The trigger endpoint itself (t002).
