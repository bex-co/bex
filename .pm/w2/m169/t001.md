## Objective

Produce the authoritative list of forum uploads that are referenced but not served, and which of them the recovered files on `nvme4tbfish` can restore. The private SHA-1 manifest that `w7/042` produced no longer exists, so the list is rebuilt from the databases themselves.

## Context

- `w7/done/042.md` (2026-09-06): 29 referenced `/forum/uploads/...` URLs, 15 unique SHA-1 objects (~1.7 MiB) missing; its manifest path `/Users/tianpan/.local/share/bex/backups/forum-retirement-20260906/uploads-manifest.json` is **gone** (directory absent, checked 2026-10-19).
- Recovered bytes: `/Volumes/nvme4tbfish/discourse_docker/data/{beancount,block-eden,tianpan}-forum/uploads/default/original/1X/<sha1>.<ext>` (14 / 16 / 11 files; several SHA-1s appear in more than one site).
- Uploads made **after** the 2026-09-06 count are also lost on each restart (current pod started 2026-10-19T00:56Z), so the inventory must include every `uploads` row, not just the 2026-09-06 set.
- Databases (`discourse_docker/_infra/bex/README.md`): beancount `dpg-d9nqg95cavls73fp8m20` (default site), tianpan `dpg-d9rrkoc4h4mc73edurp0`, blockeden `dpg-d9rs3ee0ccis738kc7c0`; workspace `tea-d98210cbbpdc73dcrkvg`.
- Discourse's `uploads` table carries `id`, `sha1`, `url`, `filesize`, `created_at`; `optimized_images` are derivatives and regenerate on rebake — only originals need bytes.

## Steps

1. Read-only query each database for every `uploads` row (`id, sha1, url, filesize, created_at`) and every post reference to `/uploads/` (to separate referenced from orphaned rows).
2. For each referenced upload, GET its URL with the site's `Host` header and record served vs missing.
3. `shasum -a 1` every recovered file; match missing uploads by SHA-1 (not by filename alone).
4. Write the private inventory to a restricted directory (e.g. `~/.local/share/bex/backups/forum-uploads-restore-2026-10/`, mode 0700): per upload — site, URL, SHA-1, served/missing, recoverable/unrecoverable.
5. Record counts only in this milestone's README (`## Evidence`).
