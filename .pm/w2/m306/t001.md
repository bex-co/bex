## Context

- CI pins ShellCheck 0.10.0 (`.github/workflows/scripts.yml:198`). Run 42787673233 flags SC2218 ("This function is only defined later") at `scripts/mock-cluster.test.sh` lines 166, 191, 197, 390, 552, 560, 563, 590, 595, 598 and 884. The test sources `scripts/mock-cluster.sh` with `# shellcheck source=/dev/null` and then redefines those functions as stubs. ShellCheck sees only the later stub.
- Verified with `koalaman/shellcheck:v0.10.0`: `# shellcheck disable=SC2218` as line 2 gives rc=0 on 0.10.0 and 0.11.0.
- `scripts/dev-env.test.sh:15-20`: `assert() { if eval "$2"; then … }` runs under `set -euo pipefail`. Conditions like `sed -n '/^start_api()/,/^}/p' scripts/dev-env.sh | grep -q …` print 6–9 KB. `grep -q` exits after the first chunk, sed's next write fails (`sed: couldn't flush stdout: Broken pipe`, runs 42744186783 and 42529060683), and `pipefail` fails a true assertion. About 35 `| grep -q` uses go through `assert()`.

## Steps

1. Add `# shellcheck disable=SC2218` as line 2 of `scripts/mock-cluster.test.sh`, with a one-line reason: the sourced script's functions are deliberately redefined as stubs.
2. In `dev-env.test.sh`'s `assert()`, evaluate the condition with `pipefail` off (e.g. `set +o pipefail; eval "$2"; rc=$?; set -o pipefail`), so an early-exiting `grep -q` cannot fail a true condition.
