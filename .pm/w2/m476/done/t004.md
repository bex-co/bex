## Objective

Serve `GET /{tea-…}/.well-known/openid-configuration` and `GET /{tea-…}/.well-known/jwks.json` on the issuer host, answering exactly Render's five discovery fields.

## Context

- Live probe 2026-11-17: `GET https://oidc.render.com/tea-c0000000000000000000/.well-known/openid-configuration` → 200 `{"issuer":"https://oidc.render.com/tea-c0000000000000000000","jwks_uri":"https://oidc.render.com/tea-c0000000000000000000/.well-known/jwks.json","response_types_supported":["id_token"],"subject_types_supported":["public"],"id_token_signing_alg_values_supported":["ES256"]}`. Any well-formed `tea-` id answers (format check, no existence check); `tea-abc` and `tea-d0000000000000000001` answer `404 page not found` (text/plain), and so does the host root. The JWKS holds one EC P-256 ES256 key (`use: sig`) whose `kid` (`_VSjJvQvo0AvEDG68QvXH01Ps2ZPj4Wl_ZIQZNo6PvU`, a 43-character base64url value, consistent with an RFC 7638 SHA-256 thumbprint) is the same for every workspace probed.

## Steps

1. Route on the issuer host only (host-based mux in bex-api); no authentication; the shared rate limiter applies.
2. Validate the `tea-` id format the way `internal/id` does and answer 404 otherwise; do not check existence (Render does not).
3. Set cache headers so providers can cache the JWKS but pick up a rotation within the overlap window.

## Files

- `lego/backend/internal/oidcissuer/http.go` (new)
- `lego/backend/internal/api/server.go` (mount)

## Acceptance criteria

- [x] A test asserts the discovery JSON has exactly Render's keys and values for a sample id, the JWKS lists every published key, a malformed id answers 404, and the root path answers 404.

## Done (2026-11-18)

`internal/oidcissuer/http.go` serves both documents with Render's bytes (`Cache-Control: public, max-age=300`, discovery with a trailing newline, the JWKS members in Render's order without one), Go's `404 page not found` for any other path or a malformed id, and a bodyless `405 Allow: GET` for another method on a document's path. bex-api mounts it on the root mux under a host pattern (`internal/api/server.go`), so only the issuer answers on its host and it answers nowhere else, behind the shared limiter keyed on the client address; it is in the always-public census (`alwayspublic_guard_test.go`) and `internal/api/AGENTS.md`. Tests: `TestDocumentsAnswerAsRendersDo`, `TestOIDCIssuerOwnsItsHost` (through every wrapper; a port in `Host` still routes). The JWKS answers 503 until the replica's first load.

## Out of scope

- Any REST/GraphQL/MCP surface: Render has none for OIDC.
