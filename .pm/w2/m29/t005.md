## Objective

Prove, for every resource kind (service, Postgres, Key Value) and every surface (REST, GraphQL, MCP), that a `dryRun`/`dry_run` call produces zero Kubernetes CRs and zero control-plane store rows.

## Context

- Real Postgres + a k8s test environment (envtest or the mock cluster) needed to assert "no CR created" convincingly, not just "no error."
- Precedent for this shape of assertion: `w2/m15`'s blueprint validate tests (no-apply assertions).

## Steps

1. For each of the 9 combinations (3 resource kinds × 3 surfaces), issue a dry-run create, then assert: no new App/Database/KeyValue CR exists, no new control-plane store row exists, and the returned preview matches what a real create would have produced (name, resolved plan, etc.).
2. Assert dry-run update calls (plan changes) leave the existing resource's spec untouched.

## Files

- `lego/backend/internal/apps/dryrun_test.go` (or integrated into existing `*_test.go` files per package)
- `lego/backend/internal/postgres/dryrun_test.go`
- `lego/backend/internal/keyvalue/dryrun_test.go`

## Acceptance criteria

- [ ] All 9 combinations pass with an explicit "zero side effects" assertion (not just "no error returned").
- [ ] A regression that accidentally applies a dry-run write fails at least one of these tests.

## Out of scope

- Dashboard/UI testing (no UI surface for this feature).
