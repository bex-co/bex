## Objective

Expose the t001 dry-run mechanism on the REST create/update endpoints for services, managed Postgres, and Key Value, returning a preview envelope instead of the usual 201/200 create response.

## Context

- `lego/backend/internal/apps/rest.go` `POST /v1/services`, `PATCH /v1/services/{id}` (plan update).
- `lego/backend/internal/postgres/rest.go` `POST /v1/postgres`, `PATCH /v1/postgres/{id}`.
- `lego/backend/internal/keyvalue/rest.go` `POST /v1/key-value`, `PATCH /v1/key-value/{id}`.

## Steps

1. Add a `dryRun` query param (bool) to each create/update endpoint above.
2. When set, call the service layer with `core.WithDryRun(ctx)` (t001) and return the resolved spec in a preview envelope (e.g. `{"dryRun": true, "preview": {...}}`) instead of the normal create response — distinct enough that a caller can't mistake it for a real create.
3. Document the param in whatever REST reference comments/docs exist alongside the other query params.

## Files

- `lego/backend/internal/apps/rest.go`
- `lego/backend/internal/postgres/rest.go`
- `lego/backend/internal/keyvalue/rest.go`

## Acceptance criteria

- [ ] `POST /v1/services?dryRun=true` (or body field, whichever fits the existing param convention) returns a preview envelope, and `GET /v1/services` afterward shows no new service.
- [ ] Omitting `dryRun` preserves today's behavior byte-identically.

## Out of scope

- GraphQL (t003), MCP (t004).
