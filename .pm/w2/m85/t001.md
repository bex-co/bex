## Objective

Supply the production wildcard certificate and private key without putting either in Git or coupling bex to a DNS provider.

## Steps

1. Define local certificate/key file paths in `.env.example` and upload their contents as environment-scoped GitHub Secrets through `scripts/gh-secrets.sh`.
2. In the protected deploy job, validate the certificate/key pair, wildcard SAN, and remaining lifetime before any cluster mutation.
3. Create/update `traefik/onbex-default-wildcard-tls` as `kubernetes.io/tls` over stdin after kubeconfig is available; never echo either value.
4. Make absent, mismatched, malformed, or near-expiry material fail before Argo applies the TLSStore and document rotation.

## Acceptance criteria

- [ ] Certificate private-key material is absent from Git, command arguments, and logs.
- [ ] `.env.example`, `.env`, secret uploader, and workflow names stay in sync.
- [ ] The Secret is limited to the trusted `traefik` namespace and has type `kubernetes.io/tls`.
- [ ] Missing/invalid material fails with an actionable message before rollout.

## Out of scope

- Issuing or renewing the externally owned wildcard certificate.
