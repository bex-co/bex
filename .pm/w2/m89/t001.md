## Objective

Restructure `.github/workflows/deploy.yml` so building and deploying are separate jobs with separate credential scopes: the build job checks out, tests-as-needed, builds and pushes images using only the registry-push credential (the minimum it cannot avoid), while the deploy job — gated on the existing protected `environment` — holds the kubeconfig/infra/gitops credentials and only applies manifests referencing already-built images.

## Context

- Current `deploy.yml` gates on the three platform suites + `dashboard/yarn test` before building (root `CLAUDE.md` §Commands); platform images are pinned by commit (`chore(deploy): pin platform images…` commits).
- ADR080 finding 2's point: the build stage executes repo-controlled code (Dockerfiles, `go generate`, yarn scripts), so any secret in its scope is exfiltratable by a supply-chain-poisoned dependency.
- The registry-push credential the build keeps must be write-scoped to the build's target repos only — check what the current push uses and narrow if it is broader.
- ADR080's env-gate + main-ref guards (round-19 fixes) must survive the restructure unchanged.

## Steps

1. Map every secret/credential `deploy.yml` currently exposes and to which steps.
2. Split into `build` (secretless except registry push) and `deploy` (`environment:`-gated, `needs: build`) jobs; move credential mounts accordingly.
3. Keep the pinning/commit flow (`[skip ci]` pin commits) working.
4. Dry-run via a branch `workflow_dispatch` if the workflow supports it; otherwise rely on t004's live verification.

## Acceptance criteria

- [ ] Reading the workflow shows the build job's secret scope is exactly the registry-push credential; deploy credentials appear only in the environment-gated job; existing round-19 guards intact.
