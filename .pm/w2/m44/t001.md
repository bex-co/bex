## Objective

Decide what image origins a deploy trigger may name — e.g. the same repository as the service's configured image, the registry of the service's bound w2/m14 registry credential, never arbitrary origins — and whether the secret-URL hook gets the same rule as the authenticated API or a stricter subset (e.g. tag-only changes on the configured repo).

## Context

- `.pm/w2/012.md`'s framing: "design what makes an image origin *safe* to accept from a secret-URL trigger … then promote if it survives."
- Render's contract: `CreateDeployJSONBody.imageUrl` on `POST /services/{id}/deploys`; deploy hooks accept `imgURL` (render.com docs).
- Rejection sites today: `lego/backend/internal/deploys/deployhook.go:256,292`; m30's deliberate omission `.pm/w2/done/m30/t005.md`.
- Compare how Render scopes it (docs say the image must match the service's configured image path? verify) — mirror if resolvable, be stricter if not.

## Steps

1. Verify Render's documented `imageUrl`/`imgURL` constraints.
2. Write the rule (allowed-origin predicate, hook-vs-API difference, error message shape) into `docs/ADR004-deployment.md` (or ADR006) as a decision section.
3. Close the design portion of `w2/012` by pointing it at the written decision (the note moves to done with this milestone's materialization; the decision text is the deliverable).
