## Objective

Make REST's `WriteErr` and the GraphQL error formatter both surface a `CodedError`'s code+params consistently, mirroring the `RATE_LIMITED` envelope shape already proven in production.

## Context

- `lego/backend/internal/api/` — `WriteErr` (REST) and the GraphQL error-formatting middleware.
- `lego/backend/internal/api/ratelimit.go:151` — the exact shape to mirror for the GraphQL side (`extensions.code`).

## Steps

1. `WriteErr`: when the error is (or wraps) a `CodedError`, include `code` (and params, where sensible) in the REST JSON error body.
2. GraphQL formatter: when the error is (or wraps) a `CodedError`, implement `gqlerrors.ExtendedError` so `code`/params land in the response's `extensions` field, matching `RATE_LIMITED`'s shape.

## Files

- `lego/backend/internal/api/` (REST error writer, GraphQL error formatter)

## Acceptance criteria

- [ ] A `CodedError` surfaces its code+params identically in shape to the existing `RATE_LIMITED` precedent, on both REST and GraphQL.

## Out of scope

- MCP surfacing — MCP tool errors follow a different convention (tool-call error content); not in this milestone's DoD, which is scoped to the dashboard's consumption path (REST/GraphQL).
