## Objective

Add an opt-in Go acceptance probe that launches the pinned, unmodified `render` binary with a real pseudo-terminal, forces `--output interactive`, and safely drives one-shot `kv-cli` commands without a human terminal. The probe must be reusable by the live fixture orchestration in t002 and must keep all credential-bearing terminal bytes private.

## Context

- Official CLI v2.21.0 (`c398207`) resolves automatic output from stdin/stdout/stderr TTY state, but an explicitly set `--output interactive` wins; `ParseCommandInteractiveOnly` then allows `kv-cli` to build its API client.
- `cmd/kvcli.go` passes arguments after `--` to `pkg/tui/views/rediscli.go`; that view fetches connection-info and uses `tea.ExecProcess` to launch `redis-cli`/`valkey-cli`.
- A successful one-shot child command produces `DoneMsg`, pops the only TUI view, and quits. This makes `PING`/`SET`/`GET` automatable even though the command is intentionally interactive-only.
- `scripts/ssh-verify.sh` already uses an opt-in Go acceptance test for PTY behavior and deliberately keeps terminal bytes in memory. Follow that redaction and gating pattern.
- Any new Go file needs the repository Apache-2.0 header. All Go stays under `lego/`; do not add a Go helper under `scripts/`.

## Steps

1. Add a gated acceptance test/helper under `lego/backend/internal/keyvalue/` that opens a PTY, sets a bounded terminal size, and starts the caller-supplied official CLI binary with inherited `RENDER_HOST`, `RENDER_API_KEY`, `RENDER_WORKSPACE`, and an isolated `RENDER_CLI_CONFIG_PATH`.
2. Construct the command as `render kv-cli --output interactive <target> -- <redis args...>`; never copy or parse bex's connection URI in the probe.
3. Read the PTY until the expected one-shot result and clean process exit, with a short configurable timeout; on timeout or mismatch, terminate only the spawned process tree and return a sanitized diagnostic.
4. Keep raw TUI/child transcripts in memory, clear them after the assertion, and redact URI user-info, bearer material, and control sequences from any failure message.
5. Skip the acceptance probe unless every required `BEX_TEST_KV_CLI_*` input is present, so normal `go test ./...` remains deterministic and network-free.

## Acceptance criteria

- [ ] From a non-TTY parent, the probe gives the child real PTY-backed stdin/stdout/stderr and reaches the CLI's API-loading state instead of the interactive-only guard.
- [ ] The helper accepts an opaque id or display name plus arbitrary one-shot Redis arguments and distinguishes expected output, nonzero exit, timeout, and premature EOF.
- [ ] Success emits no terminal transcript; failure output cannot contain a bearer token, password-bearing URI, raw connection-info body, or control-sequence dump.
- [ ] Missing opt-in inputs skip cleanly; `cd lego/backend && go test ./internal/keyvalue` stays green without a cluster.

## Out of scope

- Provisioning a public Key Value or running against a real external edge (t002/t004); modifying or rebuilding the official CLI; adding a general-purpose terminal automation framework.
