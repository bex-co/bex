## Objective

Confirm that repairing raw datastore wildcard DNS changes only deployed reachability and preserves the existing Render-compatible Key Value contract across REST, GraphQL, MCP, the dashboard, and the unmodified official CLI.

## Context

- t008 is an infrastructure repair for behavior ADR021 already promises; it must not introduce a second connection-info shape or a bex-specific CLI path.
- The official CLI must continue resolving by opaque id or display name through bex-api and consuming the returned `cliCommand`; it must not receive a copied URI from the verifier.
- PostgreSQL shares the same raw-edge DNS rule, so the audit must ensure the generalized reconciliation does not alter Postgres API/dashboard semantics or the proxied HTTP zone.

## Steps

1. Recheck Key Value connection-info and public-host behavior across REST, GraphQL, MCP, and the dashboard for any adapter-specific workaround added during t008/t004.
2. Confirm the official CLI remains unmodified and both id/name legs use its own list/item/connection-info requests.
3. Confirm the DNS reconciler targets only datastore wildcard A/AAAA records and leaves application/API/custom-domain Cloudflare proxying unchanged.
4. Record any drift as a follow-up task rather than weakening the m57 acceptance criteria.

## Acceptance criteria

- [ ] REST, GraphQL, MCP, and dashboard connection semantics remain consistent and require no DNS-specific adapter branch.
- [ ] The official v2.21.0 CLI is still byte-for-byte unmodified and uses bex's Render-compatible API path by both id and name.
- [ ] Raw datastore wildcard reconciliation is isolated from proxied HTTP application/API/custom-domain DNS.

## Out of scope

- Closing adjacent Key Value update, `pgcli`, or `psql` checklist gaps; adding new API or dashboard behavior.
