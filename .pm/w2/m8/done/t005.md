## Objective

Mirror the REST surface on the other two adapters over the same t003 verbs: GraphQL queries `gitConnection` + `repos` and mutations `connectGit` (returns install URL) / `disconnectGit`; MCP tools `list_repos` and `get_git_connection` (connection status + install URL so an agent can tell the human what to click).

## Context

- One core, thin adapters ([docs/bex-api.md](../../../docs/bex-api.md)); follow the `envgroups`/`keyvalue` graphql.go + mcp.go layout in `internal/github`.
- Both are **bex extensions** (Render's dashboard GraphQL for repos is uncaptured; Render's MCP has no repo tools) — flag in-code like `createService` does, and name tools in Render's MCP style (`list_*`/`get_*`).
- MCP `list_repos` is the agent-facing payoff: "which repos can I deploy?"

3. Adapter tests: resolver + tool round-trips against a fake core; identical field sets across REST/GraphQL/MCP asserted.
