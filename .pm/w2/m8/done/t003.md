## Objective

Persist the GitHub connection in the control-plane Postgres and expose service verbs on the core: record a connection (installation id + account login, keyed by workspace), read it, delete it. Writes are admin-only via OpenFGA; unset `BEX_CP_DB_URI` or missing GitHub env ⇒ 503.

## Context

- Store pattern: `lego/backend/internal/store` owns migrations + queries ([docs/control-plane.md](../../../docs/control-plane.md)).
- One connection per workspace for now (bex is effectively single-workspace; w6 owns multi-workspace).
- Every exported service verb must start with `Authorize` — `TestAuthzGuardsEveryVerb` reflection sweep enforces it.
- On record, validate the installation is real by minting a token for it (t002 client) before persisting.

## Steps

1. Migration: `git_connections(workspace_id, installation_id, account_login, created_at, …)` with a uniqueness constraint per workspace.
2. Store queries: upsert / get / delete.
3. Service verbs in `internal/github`: `Connect` (record installation after validating via token mint), `GetConnection`, `Disconnect` — OpenFGA-gated (admin scope for writes, member read).
4. Unit tests: verbs 503 when store or GitHub config absent; authz denial paths; record→get→delete round-trip against the store test harness.
