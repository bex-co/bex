## Objective

Extend `scripts/render-sdk-compat.sh` to exercise Render's unmodified Python SDK `*_sandbox_group_credential*` methods against bex-api, and add an automated credential-brokering isolation leg to `.github/workflows/isolation-matrix.yml` verifying cross-group and `networkPolicy` confinement.

## Context

- `scripts/render-sdk-compat.sh` already drives the pinned unmodified Python and TypeScript Render SDKs against `api.bex.co` and cleans up all fixtures on exit (`docs/cli-compatibility-checklist.md#render-sdk-sandboxes`).
- `.github/workflows/isolation-matrix.yml` runs live tenant/sandbox isolation checks; adding a broker leg proves group A's credentials never inject into group B's sandbox and `deny-all` / non-listed `allow-list` sandboxes stay blocked.

## Steps

1. Update `scripts/render-sdk-compat.sh` to create, list, retrieve, update, list versions, restore, and delete a sandbox group credential through the unmodified Python SDK (replacing any expectation of `404 SANDBOX_CREDENTIALS_UNSUPPORTED`) and assert no secret value appears in any response.
2. Add a credential-brokering isolation check to `.github/workflows/isolation-matrix.yml` (and any companion script validated by `scripts.yml` / ShellCheck) covering cross-group non-injection, `deny-all` broker refusal, and `allow-list` intersection.
3. Run offline shell/workflow validators (`bash scripts/github-actions-validate.sh`, `shellcheck`).
