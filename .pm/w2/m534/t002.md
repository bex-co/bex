## Objective

Implement the Sandbox Broker CA loader and an in-memory bounded-LRU leaf certificate signer that mints short-lived ECDSA P-256 TLS server certificates on demand for exact credentialed DNS hostnames.

## Context

- The Sandbox Broker CA private key lives exclusively in `bex-ssh-gateway` (mounted from a `bex-system` Secret provisioned in `w2/m535`); neither `bex-api` nor any tenant sandbox Pod ever holds the private key.
- Leaf certificates are minted only for exact validated public DNS hostnames that have an enabled credential (never wildcards, never IP literals), with short lifetimes (e.g. 1 hour) and a bounded in-memory cache so memory cannot grow unbounded.

## Steps

1. Implement CA cert/key loading from configured PEM paths (failing closed / disabling broker listener when unconfigured).
2. Implement an in-memory concurrency-safe bounded leaf cert cache keyed by exact lowercase hostname, minting ECDSA P-256 leaf certs with `DNSNames: [host]`, `ExtKeyUsageServerAuth`, short `NotAfter` (e.g. 1 h, refreshing before half-life), and unique serials.
3. Add unit tests proving leaf certs verify against the Broker CA for the exact hostname, fail for other hostnames, never issue wildcards or IP SANs, and evict cleanly at cache capacity.

## Files

- `lego/backend/internal/sshgateway/sandboxbroker/ca.go`
- `lego/backend/internal/sshgateway/sandboxbroker/ca_test.go`

## Acceptance criteria

- [ ] Loaded Broker CA mints valid short-lived exact-hostname leaf certs verifiable by Go/OpenSSL roots containing only the public CA cert.
- [ ] Leaf cache is concurrency-safe, memory-bounded, and refuses wildcards or IP literals.

## Out of scope
