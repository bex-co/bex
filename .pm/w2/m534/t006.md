## Objective

Prove the full `sandboxbroker` + `bex-api` internal lookup path end to end over real loopback TLS connections with realistic HTTP clients before any tenant Pod is routed through it.

## Context

- Tests should run hermetically under `cd lego/backend && go test ./...` using an in-process Broker CA, a loopback upstream TLS echo server (plus a second upstream host to test cross-host 302 redirects), and a fake DNS resolver.

## Steps

1. Add loopback end-to-end tests driving a real `http.Client` configured with `HTTPS_PROXY` and the Broker CA root against `sandboxbroker` + `bex-api` broker lookup:
   - `header`, `basic`, `cookie`, and `query` injection with `${SECRET}` templates (1–5 occurrences) and replacement of caller-supplied credentials;
   - non-matching method and non-matching path send zero injected secret;
   - uncredentialed host completes TLS pass-through with the upstream's own leaf cert (not Broker CA);
   - cross-host 302 redirect returns 302 to client and subsequent request to redirect target carries no secret;
   - `Host`/SNI mismatch is refused;
   - `deny-all` refuses every request; `allow-list` refuses a credentialed domain absent from the allow-list;
   - DNS resolving to `127.0.0.1`, `169.254.169.254`, `10.0.0.1`, or `fc00::1` is refused before dialing;
   - disabling, deleting, updating, or restoring a credential cuts off or swaps the injected secret on new requests within the cache TTL;
   - captured logs, error responses, and Prometheus metric text contain zero secret bytes.

## Files

- `lego/backend/internal/sshgateway/sandboxbroker/e2e_test.go`

## Acceptance criteria

- [ ] Every scenario above passes deterministically under `go test -race ./internal/sshgateway/sandboxbroker/...` and fails if any security check is weakened.

## Out of scope
