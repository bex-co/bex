## Objective

Implement the Pod-bound HTTP `CONNECT` broker in `lego/backend/internal/sshgateway/sandboxbroker/` that authenticates `/v1/sandboxes` Pods by source IP, enforces `networkPolicy` and the SSRF floor, relays uncredentialed hosts as raw pass-through TLS, and terminates TLS + injects secrets only for credentialed hosts on port 443.

## Context

- Reuse `sshgateway.SessionPodResolver` / `RemoteIP` (`lego/backend/internal/sshgateway/sessionpod.go`) and the resolve-once SSRF guard pattern from `lego/backend/internal/sshgateway/egressproxy/egressproxy.go` (resolve DNS once, check every returned IP against private/loopback/link-local/CGNAT/cluster/metadata deny prefixes, dial the checked IP directly).
- Security invariants:
  - Never trust any `Proxy-Authorization` or in-sandbox credential as identity; resolve the Pod solely from `RemoteIP` in `<ws>-sandbox` namespaces and require `app.bex.co/regime=sandbox`, `bex.co/sandbox-id`, `bex.co/sandbox-group`, non-terminating, and `bex.co/agent-session` absent.
  - Enforce the sandbox's own `networkPolicy`: `deny-all` rejects all CONNECTs; `allow-list` admits only destinations matching the sandbox's exact/wildcard allow-list rules (even if the group has a credential for another domain); `allow-all` admits any public DNS host.
  - Never inject into plain HTTP or non-443 ports; only `CONNECT <host>:443` where the group has an enabled credential for `<host>` enters selective TLS termination; all other allowed `CONNECT` destinations pass through raw TCP/TLS untouched (original upstream server cert preserved).
  - Inside a terminated TLS connection, validate that every HTTP request's `Host` matches the negotiated CONNECT/SNI hostname (rejecting `Host`/SNI smuggling with 421/400), forward upstream over verified public-root TLS (`ServerName: host`), and configure the upstream client with `CheckRedirect` returning `http.ErrUseLastResponse` so 3xx redirects return to the sandbox unfollowed (preventing cross-host secret leakage).

## Steps

1. Implement Pod resolution across sandbox namespaces (or namespace-indexed informer/resolver) and strict `/v1/sandboxes`-only label checks.
2. Implement `CONNECT` handling: parse `host:port`, reject literal IPs for credentialed hosts and private/cluster/metadata targets (resolve-once public IP check), check `networkPolicy`, branch between raw pass-through tunnel (no enabled credential for `host` on `:443`) and selective MITM HTTP/1.1 reverse-proxy loop (enabled credential for `host` on `:443`).
3. Enforce `Host` == CONNECT/SNI hostname, reject ambiguous framing, inject via `t003` engine, dial verified public IP over system-root TLS, pass 3xx responses back unfollowed, and scrub any error bodies so secrets never leak.

## Acceptance criteria

- [ ] Uncredentialed hosts pass through raw TLS with the upstream server's real certificate untouched.
- [ ] Credentialed hosts on `:443` receive injected secrets matching `domain`/`methods`/`paths`, reject `Host`/SNI mismatch, never follow 3xx redirects upstream, and never inject on plain HTTP or non-443 ports.
- [ ] `deny-all`, `allow-list` violations, private/metadata/cluster IPs (including DNS rebinding), agent-session pods, and unknown source IPs are all refused before dialing.
