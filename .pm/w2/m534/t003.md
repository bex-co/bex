## Objective

Implement the pure request-matching and secret-injection engine implementing Render's exact credential rules across `domain`, `methods`, `paths`, `${SECRET}` templating, all four injection types, and non-combination on overlap.

## Context

- Exact Render OpenAPI matching & injection semantics (`lego/backend/internal/api/openapi/render-public-api-1.json`):
  - Only HTTPS requests on port 443 match.
  - `domain`: exact lowercase hostname match.
  - `methods`: normalized uppercase match; empty list matches any method.
  - `paths`: each pattern matches the entire absolute path (ignoring query string); `*` matches exactly one nonempty path segment; `**` matches one or more nonempty path segments; e.g., `/a/*` matches `/a/b`, `/a/**` matches `/a/b` and `/a/b/c`, neither matches `/a`. Empty list matches any path.
  - Multiple matching credentials are **not combined**; pick one deterministically (lexicographically smallest `id` among matching enabled credentials) and report `overlap=true` for metrics.
  - `template`: replace 1–5 `${SECRET}` occurrences with the raw secret (omitted template = raw secret).
  - `header`: set header `name` (replacing any caller-supplied value); reject forbidden routing/connection headers at injection time as defense in depth.
  - `basic`: Base64-encode rendered `username:password` and set `Authorization: Basic <b64>` (replacing any caller-supplied `Authorization`).
  - `cookie`: set/replace cookie `name=<rendered>` on the `Cookie` header while preserving unrelated cookies.
  - `query`: set/replace query parameter `name=<rendered>` on the upstream request URL without corrupting other query parameters or logging the mutated URL.

## Steps

1. Implement whole-segment `*`/`**` path matching (handling cleaned/raw paths safely against traversal tricks like `/a/../b`).
2. Implement rule selection (enabled + domain + method + path, deterministic single-match non-combination + overlap flag).
3. Implement `${SECRET}` rendering and all four injectors (`header`, `basic`, `cookie`, `query`) with defense-in-depth header validation and unit tests covering every edge case.
