## Objective

Standing closing task: add guard checks so the fix cannot silently regress — the insecure flag must never reappear in a production-reachable render, the approver Application must stay present, and the machine templates must keep serving-cert rotation.

## Context

- `scripts/gitops-validate.sh` is the pattern to follow: pure client-side, `rg`/`grep`/`yq` assertions with `FAIL:` messages and `fail=1`, plus kustomize render checks; CI runs it via `.github/workflows/gitops.yml`. It already greps the base for forbidden source patterns — mirror that style.
- `scripts/clusterapi-validate.sh` (331 lines) guards the machine templates (e.g. the baked-image imageName invariant) and is the home for template assertions.
- Assert against the **rendered prod output** (kustomize build of base/prod overlay), not just the base file, so an overlay patch reintroducing `--kubelet-insecure-tls` also fails. The local overlay is exempt only if t003 deliberately kept its bypass.

## Steps

1. In `scripts/gitops-validate.sh`: fail if the base/prod render contains `--kubelet-insecure-tls`; fail if the metrics-server args lack `--kubelet-certificate-authority`; fail if the kubelet-csr-approver Application is missing from the base kustomization.
2. In `scripts/clusterapi-validate.sh`: fail if any `kubeletExtraArgs` block in the CAPH or CAPD cluster templates lacks `rotate-server-certificates: "true"` (match the existing guard style).
3. Prove each guard by temporarily reintroducing the violation and watching the script fail, then restore.
4. Run both scripts clean.
