## Objective

Point metrics-server at the cluster CA (`--kubelet-certificate-authority=/etc/kubernetes/pki/ca.crt` via the chart's CA mount, or the kubelet-ca ConfigMap approach) so kubelet scrapes are TLS-verified, and retire the CAPD-only `--kubelet-insecure-tls` overlay patch now that mock-cluster kubelets serve approved certs.

## Context

- **The insecure flag is already gone from the shared base**: commit 815e003b removed it from `deploy/gitops/base/metrics-server.yaml`; prod/staging overlays add no metrics-server patch, so the production render has been flag-free since 2026-08-16. But the base also lacks `--kubelet-certificate-authority`, so verification currently relies on default trust that cannot validate kubelet certs — the finding is only half-closed.
- The flag's sole remaining home is `deploy/gitops/overlays/local/kustomization.yaml` lines 12–24 (a Helm-parameter patch replacing the args). After t002 the mock cluster can verify too; ADR072's plan allows local CAPD to keep the bypass, but prefer dropping it so local mirrors prod.
- Mock-cluster quirk (memory note): worker-pod → apiserver/kubelet networking is flaky, so infra pods are pinned to the control-plane and metrics-server needs `hostNetwork: true` with port 10251. Respect/retain that local arrangement when testing; do not push hostNetwork into the base.

## Steps

1. Add the CA wiring to the base Application values (chart digest bump via `scripts/helm-artifact.sh mirror` if a newer chart is needed for the CA mount).
2. Drop (or, if CAPD certs prove unverifiable, explicitly keep with a dated comment) the local overlay's `--kubelet-insecure-tls` parameter patch.
3. `bash scripts/gitops-validate.sh`; sync to the mock cluster.
4. Verify: `kubectl top nodes` + `kubectl top pods -A` return data; bex-api resource metrics (metrics-server snapshot fallback, `NewResourceMetricsSource`) serve without `ErrMetricsUnavailable`; metrics-server logs show no `x509` scrape errors.
