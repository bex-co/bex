## Objective

Make sure no SSH path admits an unverified human. That covers public-key SSH to `srv-…` instances and agent-session sandboxes, the browser web shell, and exec/shell/snapshot tickets.

## Context

- `lego/backend/internal/sshgateway/`, `shellticket/`, `sandboxexec/`, `snapshotticket/`, `sshkeys/`. Ticket mints that go through the bex-api middleware are already covered by t002. The public-key auth path resolves an identity from a stored key and may never touch Kratos.
- `sshkeys` registration also goes through bex-api, so an unverified user can't add a key after t002. Keys added before then can still exist (legacy unverified accounts).

## Steps

1. Trace each SSH entry point to its identity resolution and list which ones bypass the middleware.
2. For those that bypass it, check verification per connection (a Kratos admin lookup by subject, with a short cache) or refuse at the ticket mint. Choose the smallest path that holds per connection.
3. Tests for the refusal.

## Files

- `lego/backend/internal/sshgateway/**`, related ticket packages

## Acceptance criteria

- [ ] An unverified identity holding a pre-existing SSH key is refused with a clear message, as shown by a test.

## Out of scope

- Changing SSH auth architecture (ADR035/ADR054).
