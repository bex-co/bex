## Objective

Record the 2026-10-06 user decision in ADR075. Option B's per-request gate becomes the operative verification gate. The `require_verified_address` login hook stays as defense in depth. Pin down every policy choice the implementation tasks need, so they don't re-decide anything.

## Context

- `docs/ADR075-user-onboarding.md` has three places that encode the old decision: the D8 bullet, the Option B paragraph ("remains deferred, not built") and the Non-goals ("No bex-api gate, no `BEX_REQUIRE_VERIFIED_EMAIL` env, no `EMAIL_VERIFICATION_REQUIRED` error code").
- The D8 sentence "an unverified identity cannot outlive its registration session" is false: `deploy/gitops/base/values/kratos.values.yaml:213-214` slides the session (`lifespan: 168h`, `earliest_possible_extend: 24h`).
- `core.Identity.EmailVerified` is computed at `lego/backend/internal/api/auth.go:~661` from the Kratos `verifiable_addresses` match.

## Steps

1. Rewrite D8 as a hard gate. Unverified humans are refused on every bex-api surface, at OAuth consent, and on SSH. Decide the HTTP status (403 recommended) and the error code `EMAIL_VERIFICATION_REQUIRED`.
2. Exemptions: machine callers (no human `sub`). List the allowlisted human routes and justify each one. Candidates: account deletion (the D5 exit) and anything the verification wall itself needs. Prefer an empty list if the wall can work from the Kratos session alone.
3. Env switch: decide whether it's default-on, or opt-in via `BEX_REQUIRE_VERIFIED_EMAIL` (as dev-env's Mailpit stack may need). If an env var is added, mirror it in `.env.example` and the AGENTS.md env tables.
4. Legacy accounts: no grandfathering. The 41 unverified identities get the wall and can verify via resend.
5. Update the Status line, Option B paragraph and Non-goals. Add a dated revision note.
