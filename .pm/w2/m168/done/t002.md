## Objective

Add one choke point in the auth middleware. When a human identity has `EmailVerified=false`, return the coded refusal before `EnsureTenant` mints a workspace, on REST, GraphQL and MCP alike.

## Context

- `lego/backend/internal/api/auth.go:~336-345`: the `default:` branch calls `a.onboard.EnsureTenant(... id.EmailVerified)` for `id.Human`. Insert the gate before that call.
- Coded errors: `lego/backend/internal/core/errors.go`, following the `CodeAccountDeletionPending` / `NewAccountDeletionPendingError` pattern. GraphQL and MCP must surface the code the same way `PAYMENT_REQUIRED` and `ACCOUNT_DELETION_PENDING` do.
- Fresh-bearer revalidation (`WithFreshBearerValidator`) must not let a token minted while verified bypass a later state. Confirm which state wins and test it.
- `EnsureTenant` invite redemption (`tenancy.go:~104`, `BEX_REQUIRE_VERIFIED_INVITE_EMAIL`) becomes unreachable for unverified callers. Keep it as defense in depth.

## Steps

1. Add `CodeEmailVerificationRequired` and a constructor.
2. Gate in the middleware, applying t001's exemptions and allowlist.
3. Wire the env decision from t001 into `cmd/api` config, if one was made.
4. Unit tests: unverified human refused, with no `EnsureTenant` call; verified human passes; machine caller passes; each allowlisted route passes.
