Found 2026-10-29 during w2/035's post-change health check. It predates that change and is unrelated: the Pod `…-beancount-forum-d6cb4546-2jxks` had run 17h with no restart, and Phase 4 only touched registry grants and legacy repos.

## Evidence

- `curl https://forum.tianpan.co/`, `/latest.json` and `/srv/status` all return 404. So does `forum.blockeden.xyz`. `beancount-forum.onbex.co` returns 404 with `x-cascade: pass`, `content-length: 12` (Rack). `forum.bex.co` returns 302 (BlockEden edge).

- The Pod logs show the Key Value `red-d9p49kdrtmes73c34ovg` refusing connections repeatedly on 2026-10-29 (09:07, 10:28 and 14:48 UTC, `Connection refused … 10.100.204.0:6379`), with Discourse sites `[default]` and `[tianpan]` both affected. The multisite host mapping may not have recovered after a Redis outage. That is unverified.
