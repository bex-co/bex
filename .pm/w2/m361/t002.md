## Objective

A create under a name held only by an App that is being deleted succeeds, under a distinct object name.

## Context

- `lego/backend/internal/apps/service.go`: the free-form name to slug mapping (`serviceNameLabel`, `blueprintResourceSlug`, ~2157-2166), `nameTaken`, `planNewApp` (~2385), `writeNewApp`, `SERVICE_NAME_STILL_DELETING` (~2363-2369), `errServiceNameInUse`.
- w4/m19's slug suffix for public hosts; w8/m47's creation vs shown name and the per-workspace advisory lock shared by create and rename.

## Steps

1. Under the existing per-workspace lock: if the slug's holder has a DeletionTimestamp and no live service is created as or shown as the name, allocate `<slug>-<suffix>` (the same short random suffix shape as m19) as the object name.
2. Store the requested name as the service's creation name and shown name, so reads, the list and by-name addressing show the name the user typed.
3. A raw `AlreadyExists "object is being deleted"` from the API server retries with a fresh suffix instead of failing.
4. Dry runs answer exactly what the real create would.

- [ ] Tests: with a terminating holder, create returns 201 with the requested name and a suffixed object name; with a live holder, the 409 "already in use" stands; dry run matches.

## Out of scope
