## Objective

Everything that looks a service up by name finds the live one, and a Blueprint re-sync creates the new service instead of matching the dying one.

## Context

- By-name resolution: `core.Base.AuthorizeApp` / `GetApp` (ADR018 "Address a service by name", w8/m45, w8/m47).
- Blueprints: `lego/backend/internal/apps/blueprint_plan.go` resource matching (w2/m256 t015 handled a terminating App's name in the plan path).
- Datastores: Postgres and Key Value create in `lego/backend/internal/postgres/` and `lego/backend/internal/keyvalue/`.

## Steps

1. Exclude Apps with a DeletionTimestamp from by-name resolution and from Blueprint resource matching.
2. Check whether a Postgres or Key Value create under a just-deleted name waits too. If it does, apply the same rule; if not, record why.

## Files

- `lego/backend/internal/core/`, `lego/backend/internal/apps/blueprint_plan.go`, `lego/backend/internal/postgres/`, `lego/backend/internal/keyvalue/`

## Acceptance criteria

- [ ] Tests: `GET /v1/services/<name>` returns the live service while the old one terminates; a Blueprint sync plans a create for the new service; the datastore outcome is tested or recorded.

## Out of scope

- Blueprint adoption of unrelated resources.
