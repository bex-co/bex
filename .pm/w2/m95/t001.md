## Objective

Make the dashboard's env Export and Import inverses of each other. Today Export serializes every value with `JSON.stringify`, which emits `\uXXXX`, `\b`, `\f`, `\"` and `\\`, while the Import parser's double-quoted branch understands only `\n`, `\r` and `\t` and takes every other escape literally. So the JSON escape for U+001B comes back as the letters `u001b`. Pick one contract, implement it on both sides, and prove it with a property test.

## Context

- Export: `dashboard/src/features/services/lib/env-export.ts` (`formatEnvExport`) uses `JSON.stringify` per value.
- Import: `dashboard/src/features/services/lib/dotenv-import.ts:79-88` handles only `\n`, `\r`, `\t` inside double quotes.
- Existing tests cover each side alone: `dashboard/src/features/services/lib/__tests__/env-export.test.ts` and `__tests__/dotenv-import.test.ts`. Nothing composes them.
- Live evidence (w1/done/099): a `CTRL` value holding a real ESC byte exported as its `\uXXXX` escape and imported back as `escu001bend`; a `PEM` value with `\n` escapes round-tripped correctly (control).
- The rest of the import journey is correct and must stay so: `export` prefix stripped, `#` inside quotes kept, trailing comments stripped on unquoted values, last duplicate wins, `EMPTY=` → `""`.

## Steps

1. Choose the contract: accept the full JSON string escape set inside double quotes (`\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`, `\uXXXX` including surrogate pairs) in `parseDotenv`. This keeps Export unchanged and makes Import a superset of common dotenv parsers. State the contract in a header comment in both files.
2. Decide what a literal `\uXXXX` in a user's own `.env` means. Common dotenv libraries do not expand it; with the contract above, bex does, inside double quotes only. Document that in the same comment and in the Import dialog's help text if one exists.
3. Implement the escape decoding in `dotenv-import.ts` for the double-quoted branch only; single-quoted and unquoted values stay verbatim.
4. Add a property test (use fast-check if it is already a dev dependency, otherwise add it) in a new `__tests__/env-round-trip.test.ts`: for arbitrary strings including control characters, U+2028/U+2029, emoji and astral characters, `"`, `\`, `#`, `=`, leading/trailing spaces, and the empty string, `parseDotenv(formatEnvExport(entries))` deep-equals `entries` for arbitrary valid keys.
5. Keep the existing per-side tests green; add explicit cases for `\b`, `\f`, `\/`, the U+001B escape, and a surrogate pair.
