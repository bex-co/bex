Why: every new bex-api pod CrashLoops at boot (`BEX_REQUIRE_PAYMENT_METHOD=all: BEX_STRIPE_PUBLISHABLE_KEY is required for Stripe Payment Element`), so no bex-api deploy has actually rolled since the billing-gate change landed — the two old pods keep serving (maxUnavailable 0, no outage), but every ship's bex-api changes silently never reach production, and Argo has been Degraded on it.

- Observed 2026-09-02 during w2/m86's operator restart (`bex-api-864f668558-btdzt` CrashLoopBackOff, 38h-old pods serving).
- Fix: add the Stripe **publishable** key (safe-to-expose `pk_…` value, but custody still rides the normal chain) to the prod env path — `.env` → `scripts/gh-secrets.sh` → deploy — or wherever bex-api's Stripe env is injected; then confirm one green rollout. The value is user-held (Stripe dashboard).
- Alternatively decide the validation is too eager (require the publishable key only when the Payment Element surface is actually served) — but the env fix is the fast path.
