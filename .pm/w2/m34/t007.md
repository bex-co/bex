- Source-level parity and automated coverage are green: the full-handler regression test exercises authenticated `StartConnect` → anonymous signed callback → connection persisted, while auth middleware tests preserve the credentialed callback path and confine the bypass to the exact uncredentialed `GET /v1/git/callback` route.
- The public dashboard and API are reachable, but a credential-free `GET https://api.bex.co/v1/git/callback` currently returns `401` with the OAuth protected-resource challenge. That is the pre-fix behavior and proves this working tree—including the newly explicit production `BEX_DASHBOARD_URL` redirect setting—has not reached production.
- A short-lived `bex-bootstrap` client-credentials token successfully exercised production `POST /v1/git/connect` without changing the connection: the Bearer caller was authorized, the existing connection was visible, and an install URL was returned. The URL had no `state`, which is additional evidence that production is still pre-fix. The existing installation callback was not replayed because its upsert deliberately resets `created_at`.
- The local CAPD app cluster was recovered far enough to inspect, but it contains no bex API or dashboard deployment and no public route; it cannot exercise the GitHub App's production Setup URL.
- Repository policy forbids committing or pushing this working tree without an explicit `$ship`, so the live browser and Bearer-path checks remain deliberately open rather than being inferred from tests.
