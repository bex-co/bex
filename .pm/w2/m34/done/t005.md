## Objective

On a failed callback (invalid/expired state, GitHub-side error), get the user back to a styled dashboard page with a visible error, instead of a bare API JSON error page.

## Context

- `dashboard/src/features/git/components/connect-github-card.tsx` — the Connect GitHub card, currently has no handling for a failed connect attempt (a successful connect is detected via focus-refetch, but a failure leaves the user on the bare API error page mid-flow with no way back).
- The backend callback, on failure, should redirect the browser to a dashboard URL (e.g. `/settings?git_error=<reason>`) rather than rendering raw JSON, so there's something for the dashboard to catch.

## Steps

1. Backend: on callback failure, redirect (302) to a dashboard settings URL with an error query param, instead of writing a JSON error body directly.
2. Dashboard: `ConnectGithubCard` (or the settings route) reads the error param and shows a toast/inline error.

## Files

- `lego/backend/internal/github/rest.go`
- `dashboard/src/features/git/components/connect-github-card.tsx`

## Acceptance criteria

- [ ] A failed connect attempt lands the user back on `/settings` with a visible, understandable error, not a bare JSON page.

## Out of scope

- Retry/auto-resume flows.
