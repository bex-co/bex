## Objective

Ensure the credential presented to KeyValue clients always matches the password loaded by the running Valkey Pods.

## Context

- The controller accepts an existing/mutated password Secret.
- The StatefulSet consumes it through an environment reference but has no Secret-content hash.
- A Secret mutation changes client-visible credentials without restarting Valkey.

## Steps

1. Choose and document controller-owned immutable credentials or an explicit safe rotation mechanism.
2. If rotation is supported, hash the effective Secret content into the Pod template and gate status on rollout convergence.
3. Reject unsupported direct mutation or recover it deterministically.
4. Add old/new client authentication controls around rotation.

## Acceptance criteria

- [ ] At no observed Ready point do clients receive a password the running Valkey process rejects.
- [ ] Rotation or mutation behavior is deterministic across operator/Pod restart.
- [ ] Credential values never appear in status, Events, logs, or tests.

## Out of scope

- User-selectable KeyValue passwords unless separately approved as a product feature.
