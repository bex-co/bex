## Objective

Keep finalizers until registry, static-object, backup-purge, and TLS cleanup has succeeded or a persisted cleanup Job has reached a proven terminal result.

## Context

- App cleanup logs several errors and removes its finalizer anyway.
- Static and Database backup purge Jobs are fire-and-forget.
- TLS cleanup considers only currently effective hosts, so removed hosts can leave private keys.

## Steps

1. Convert required cleanup steps to synchronous, context-bounded operations or persisted Jobs with terminal status observation.
2. Aggregate failures without acknowledging incomplete deletion.
3. Track historical/custom-host TLS identities so removed hosts are reclaimable.
4. Make manager restart adopt and continue in-flight cleanup.

- `lego/operator/internal/controller/app_controller.go`

## Acceptance criteria

- [ ] Finalizers remain present while any required cleanup is failed or nonterminal.
- [ ] Manager restart resumes cleanup without duplicate destructive work.
- [ ] Delete and removed-host tests leave no registry manifest, object prefix, backup-purge Job, Certificate, or TLS Secret/private key.

## Out of scope

- An operator-wide generic workflow engine.
