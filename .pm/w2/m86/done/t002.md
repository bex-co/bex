## Objective

Verify the hcloud-csi node ServiceAccount can read the per-App LUKS passphrase Secrets the operator mints in tenant namespaces, and add the missing RBAC (gitops-managed) if it cannot. This is the second unverified prereq w1/m83 recorded.

## Context

- The operator mints a per-App passphrase Secret in the App's namespace (`diskLUKSSecretName` — `lego/operator/internal/controller/app_controller.go:1634`, `disk_test.go:147`).
- `deploy/gitops/base/disk-storageclass.yaml` wires the class's `csi.storage.k8s.io/node-*-secret-name/namespace` parameters to that Secret.
- hcloud-csi is installed by the cluster bring-up (`.github/workflows/app-cluster.yml`); its node plugin's SA needs `get` on Secrets in tenant namespaces for LUKS staging.
- Tenant namespaces carry restricted RBAC (ADR043); check `deploy/gitops/base/tenant-namespace-clusterroles.yaml` and siblings.

## Steps

1. Read `disk-storageclass.yaml`'s secret-parameter wiring and the hcloud-csi install in `app-cluster.yml`; identify the node SA.
2. `kubectl auth can-i get secrets --as=system:serviceaccount:<csi-ns>:<node-sa> -n <tenant-ns>` against the shared/local cluster.
3. If denied: add a narrowly-scoped (ClusterRole limited to `secrets` `get`, ideally by resourceNames pattern or a documented accepted width) binding in `deploy/gitops/base/`, and run `scripts/gitops-validate.sh`.
4. Record the decision and evidence.
