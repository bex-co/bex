# Honor instance filters for pre-deploy log reads

Why: A pre-deploy log query with an instance selector currently returns lines from every migration pod, so a successful filtered response can include the wrong deployment's output.

Found by the w2/m167 consumer audit on 2026-10-02. `lego/backend/internal/logs/service.go` resolves `Instance` against App pods before dispatching `type=predeploy` to `collectPreDeployLogs`; that collector lists the authorized App's pre-deploy pods but never checks `q.keepPod`. Thus even an unmatched selector becomes `noSuchInstance` and is then ignored. App/namespace authorization still holds; this is incorrect filtering within an authorized resource, not evidence of cross-tenant access. This is source-audit evidence, not a production reproduction.

Resolve public and legacy raw-name selectors against the actual authorized pre-deploy pod candidates, and apply the resolved filter before reading their logs. Keep existing App/build history behavior, timestamp/text/limit semantics, and the explicit refusal of a pre-deploy subscription. Add behavioral cases with two pre-deploy pods plus App/foreign-resource controls: omitted filter returns both; each public/raw selector returns only its own records; unknown/foreign selectors return none; text/time remain AND filters. Verify REST, scalar GraphQL and MCP share the correction, and document the source limitation closure.

Expected scope: one focused shared collector fix and regression cases, under an hour. Dedupe searched predeploy/instance and `collectPreDeployLogs` across the board. w1/m33 introduces this source; w1/m149 fixes its type label; w5/m100 preserves migration logs in stored build history; w5/m87 fixes public App-instance identity. None addresses the live pre-deploy collector's ignored filter. Keep this separate from m167's text-array repair.

Local diagnostic confirmed 2026-10-02: with two owned fake pre-deploy pods emitting separate A/B markers, `QueryLogs(type=predeploy, text:[A,B], instance:[does-not-exist])` returned both matching entries instead of none. The diagnostic used a private Go overlay, leaving the repository tests unchanged. This independently reproduces the source-audited defect without a production probe.
