## Objective

`lego/backend/internal/deploys/rest.go`'s `POST .../deploys` handler currently calls `s.Trigger(r.Context(), r.PathValue("id"))` and never reads the request body at all — the existing comment ("the body may carry clearCache — accepted and ignored") is aspirational, not real: nothing is decoded, let alone honored. Decode the real Render-shaped body and thread it to `Trigger`.

## Context

- `lego/backend/internal/deploys/rest.go` — `POST .../deploys` handler.
- `lego/backend/internal/deploys/graphql.go` — `triggerDeploy(serviceId)` mutation, needs `commitId`/`clearCache`/`deployMode` as new optional args.
- Render's real body (`CreateDeployJSONBody`): `commitId *string`, `clearCache *"clear"|"do_not_clear"`, `deployMode *"deploy_only"|"build_and_deploy"`, `imageUrl *string` (imageUrl — overriding the image URL for an image-backed deploy — is explicitly OUT of scope for this milestone; note it as a follow-up, don't half-implement it).
- MCP: no change — Render's own official MCP server has no create/trigger-deploy tool at all (`list_deploys`/`get_deploy` only, confirmed against `pkg/deploy/tools.go`), so there's no MCP surface to extend here.

## Steps

1. REST: `json.NewDecoder(r.Body).Decode(&body)` for `commitId`/`clearCache`/`deployMode` (empty body still valid — every field optional, matches Render).
2. Validate `clearCache` against the two-value enum (400 on anything else) — implement per t001's finding (real cache-bust, or documented no-op).
3. GraphQL: add `commitId: String`, `clearCache: String`, `deployMode: String` args to `triggerDeploy`, same validation.
4. Both adapters delegate to the same `Trigger` — no logic duplicated between REST and GraphQL (matches the package's existing "one Service, adapters can't drift" discipline).

## Files

- `lego/backend/internal/deploys/rest.go`
- `lego/backend/internal/deploys/graphql.go`

## Acceptance criteria

- [ ] `POST .../deploys` with a `commitId`/`deployMode` body actually affects the resulting deploy (proven by t002/t003's behavior, exercised through this handler).
- [ ] An empty body still triggers a default deploy, byte-identical to today's behavior.
- [ ] `triggerDeploy` GraphQL mutation accepts the same three optional args with the same validation as REST.

## Out of scope

- `imageUrl` (image-backed deploy targeting a different image) — not part of this milestone, file separately if wanted.
- MCP — no tool exists to extend (see Context).
