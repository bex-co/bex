## Objective

`dashboard/src/features/services/components/manual-deploy-button.tsx` (shipped this session) currently wires "Restart service" to the separate `onRun("restart", service)` lifecycle action, not `deploys.Trigger`. Now that t004 consolidates restart into `deploys.Trigger(deployMode: deploy_only)`, fix the dashboard to match — both menu items go through `useTriggerDeploy`.

## Context

- `dashboard/src/features/services/components/manual-deploy-button.tsx` — the dropdown: "Deploy latest commit"/"Deploy latest image" + divider + "Restart service".
- `dashboard/src/features/services/hooks/use-trigger-deploy.ts` — currently takes only `serviceId`; needs to accept `deployMode`/`commitId` and pass them through the `TriggerDeploy` GraphQL mutation (regenerate `dashboard/src/graphql/definitions.ts`'s hand-maintained `TriggerDeployDocument` per `dashboard/CLAUDE.md`'s GraphQL section).
- `dashboard/src/features/services/components/service-detail-header.tsx` — passes `pending`/`onRun` to `ManualDeployButton`; once restart goes through `useTriggerDeploy` instead, confirm whether `pending`/`onRun` are still needed there at all (the header's `ServiceRowActions` still needs them for Suspend).
- `dashboard/src/features/services/components/__tests__/service-detail-header.test.tsx` — the "restarts through the Manual Deploy dropdown" test currently asserts `onRun` was called with `"restart"`; update to assert the `TriggerDeploy` mutation was called with `deployMode: "deploy_only"` instead.
- `dashboard/scripts/local-bex.mjs` — the dev stub's `TriggerDeploy` GraphQL case needs to accept and honor the new args (at minimum, echo them back so the dev stub stays truthful, not silently drop them).

## Steps

1. Extend `useTriggerDeploy`'s `trigger()` signature to accept `{ deployMode?, commitId? }`.
2. `manual-deploy-button.tsx`: "Deploy latest commit"/"Deploy latest image" call `trigger(service.id, {})` (default mode); "Restart service" calls `trigger(service.id, { deployMode: "deploy_only" })`.
3. Update the confirm-dialog copy if needed — the existing restart confirm text ("The service's pods roll with no downtime...") should still read true for the image-backed case; for a repo-backed service restart (which per t004 still rebuilds), consider whether the copy needs to say so honestly rather than implying a fast no-rebuild bounce that t003 established bex can't deliver for that case.
4. Update `service-detail-header.test.tsx`'s restart test to assert the new mutation call shape.
5. Update `local-bex.mjs`'s stub.
