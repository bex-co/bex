## Objective

Implement Active → Hibernated per the t001 verdict: at the m67 reap seam, instead of Terminate, capture the workspace's mutable state (working tree + `~/.zed_server` + tool caches), persist it durably, record the snapshot ref on the row, and only then reclaim the pod.

## Context

- Path A: completion path switches `Terminate` → `Suspend` + whatever retention hook the spike found; the snapshot ref is OpenSandbox's.
- Path B (Gitpod/Cloudflare pattern): pre-hibernate exec tars the mutable mount, streams to object storage (new bucket/prefix contract like the KV-backup envs: destination + endpoint + secret; ADR050 age-encryption via `BEX_BACKUP_AGE_PUBLIC_KEY`'s lineage), then Terminate. Reuse the gateway/sandbox exec boundary the Completer already uses for status/transcript reads; run `bex-pre-snapshot` first (credential scrub).
- Hard invariants either way: per-workspace object prefix + scoped credentials, encrypted at rest, checksum recorded, `bex-pre-snapshot` before capture, snapshot-size bound (quota) enforced at capture with a named failure that falls back to plain reap.
- Fires from the m67 reaper (idle > grace) — hibernate replaces reap for non-canceled sessions; explicit Cancel still deletes outright.

## Steps

2. Env/contract plumbing (`CLAUDE.md` + `.env.example` rows for the storage contract if path B).
