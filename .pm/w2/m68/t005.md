## Objective

Implement Hibernated → Deleted per ADR059 D5: a daily sweep deletes hibernated snapshots idle past retention (default **7d**, `BEX_AGENT_SNAPSHOT_RETENTION`), extends the window when the snapshot's git tree was dirty at capture, **never touches pinned rows**, and an object-storage lifecycle rule backstops orphans.

## Context

- Ride the existing daily retention sweep lineage (`BEX_AUDIT_RETENTION_DAYS` worker) — a new sweep step, not a new daemon.
- "Dirty at capture" is recorded by t003 (a boolean from `git status --porcelain` during the pre-hibernate step) — extension e.g. 2× retention, mirroring Gitpod's 14→28.
- Delete = object(s) removed + row transitioned to Deleted/terminal-with-no-snapshot; idempotent; failures retried next sweep. Explicit tenant delete (t006) shares the same deletion helper.
- Backstop: document (and where possible provision) a bucket lifecycle rule at retention + slack so a lost row can't leak storage forever.

## Steps

1. Sweep step + store list query (unpinned, hibernated, idle > retention, dirty-aware).
2. Deletion helper shared with the explicit-delete verb; env plumbing + docs rows.
3. Lifecycle-rule note in the ops docs / ADR059.
