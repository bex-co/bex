## Objective

Ship ADR059 D5's pinned primitive and D6's visibility/control: pin/unpin verbs (quota'd per plan), hibernated-snapshot storage metered as its own usage dimension, and a tenant-visible list of workspaces with state + storage + cost plus stop/delete/unpin — consistently on REST, GraphQL, MCP, and the dashboard.

## Context

- Verbs on the agent-session feature (`can_operate`): pin, unpin, delete-hibernated (explicit). Pin refused past the per-plan quota (`BEX_AGENT_MAX_PINNED_PER_WORKSPACE` default e.g. `3`; `0` disables pinning) with a named code.
- Metering: hibernated snapshot bytes enter the ADR023 usage pipeline as a new dimension (byte-hours like the disk lineage), distinct from compute-seconds — so ADR040's Stripe export picks it up without special-casing; pinned simply keeps accruing.
- Read surface: extend the session View/list with `state` (active/hibernated), `pinned`, `snapshotSize`, `hibernatedAt` — same shape on all three surfaces (models.go View + graphql.go + MCP inherit); dashboard session header/list gains the state chip + pin toggle + storage note, and the unavailable/hibernated state explains "resume to reconnect".
- ADR059 D6 is a hard gate: days-scale retention must not ship ahead of this task.
