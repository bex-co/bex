## Objective

Implement Hibernated → Active: `Resume`, a new turn (`Steer`), and an SSH connect against a hibernated workspace provision a fresh sandbox, restore the snapshot into the mutable mount before the driver/agent starts, and flip the row back to a live phase — instrumented so the ADR059 Performance SLOs (p50<~5s / p95<~15s) are measurable, not aspirational.

## Context

- Entry points: `agentsessions.Service.Resume` (today refuses when `sandbox_id == ''` — must instead detect Hibernated and rehydrate), `Steer` (today re-clones a fresh sandbox — must restore the snapshot instead, preserving uncommitted work per D4), and the gateway's `SSHResolver` (an `ags-…` connect against a hibernated workspace should trigger rehydrate-then-connect, or at minimum a clear "resuming, retry shortly" refusal in v1 — decide and document).
- Path B restore: initContainer (or pre-driver step over the exec boundary) downloads + decrypts + untars into the mount; checksum verified; uid 10001 ownership preserved; corrupt snapshot ⇒ explicit fallback to clean re-clone with the failure recorded on the row (never a silent half-restore). Path A: `Client.Resume`-from-snapshot per the spike.
- Instrumentation: a resume-duration histogram (bounded labels: path=a|b, outcome) on the bex-api metrics registry, phase-stamped (schedule / download / extract / boot) if cheap — this is the evidence for t010's acceptance.

## Steps

1. Rehydrate flow behind `SandboxLifecycle` (new method or extended Create), wired from Resume/Steer; decide + implement the SSH-connect behavior.
2. Restore-integrity handling (checksum, ownership, disk-quota, corrupt-fallback).
3. Metrics + a log line with the measured phases.
