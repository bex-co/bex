# 082 — `bex logout` sends users to Render's dashboard when token revocation fails

Why: after a normal `bex login`, a `bex logout` whose token revocation fails prints "you'll need to revoke your token in the Render dashboard: https://dashboard.render.com/settings#cli-tokens". It names the wrong product and links a dashboard where the bex token does not exist, so the user cannot do what it asks.

- **Seen in:** `TestLogoutNamesBex` (w2/073), when its fake `/oauth/revoke` answered 404 instead of 204. Upstream: `cmd/logout.go:71` (pinned render-oss/cli), using `config.DashboardURL()`, whose default is Render's.
- **Why the URL is Render's:** bex sets the Bex dashboard origin only for the commands `opensDashboard` lists (`services`, `deploys list`, `agent open`; `lego/cli/main.go:305`), and `bridge.EnsureDashboardURL` writes it only then. A config that `bex login` wrote has no dashboard origin, so `logout` falls back to `https://dashboard.render.com`.
  - Unverified: whether a real `bex login` stores a dashboard origin. Check with a fresh login before fixing.
- **Fix shape:**
  1. Make the dashboard origin Bex's for `logout` too: add it to `opensDashboard`, or have `bex login` store `https://dashboard.bex.co` for the default host.
  2. Add the warning's "the Render dashboard" and the API-key branch's "your Render Dashboard" (`logout.go:36`) to `runtimeProse` (w2/073's exact-phrase table).
  3. Test: a failed revoke prints the Bex dashboard and names Bex.
- **Size:** sub-hour.
