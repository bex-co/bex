## Objective

Eliminate the condition in which a malicious Dockerfile process can potentially ptrace a BuildKit process that has registry or signing credentials.

## Context

- The current worker uses `--oci-worker-no-process-sandbox` and unconfined seccomp.
- Upstream BuildKit warns that this mode permits killing and potentially ptracing BuildKit-container processes.
- Registry push material is mounted in the BuildKit/cosign process boundary.

## Steps

1. Prove whether the supported cluster runtime can restore BuildKit's process sandbox.
2. If it cannot, redesign push/sign handoff so tenant build processes never share a reachable process boundary with long-lived credentials.
3. Remove obsolete unconfined settings and document the chosen trust boundary.
4. Add an adversarial Dockerfile that attempts filesystem, process, `/proc`, ptrace, environment, and declared-secret extraction.

## Acceptance criteria

- [ ] Production no longer depends on an unmitigated `--oci-worker-no-process-sandbox` process/credential boundary.
- [ ] The adversarial build cannot read or infer push, private-base-image, clone, or signing credentials.
- [ ] A normal private-source/private-base build still pushes and signs successfully.

## Out of scope

- Replacing the whole build pipeline with OpenChoreo, Korifi, or a shared BuildKit daemon.
