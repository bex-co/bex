## Objective

Ensure build, kpack, static-publish, and pre-deploy Pods receive no ambient Kubernetes API credential and only the minimum explicit identity required by their mechanism.

## Context

- Build and static publish currently omit `automountServiceAccountToken: false`.
- Pre-deploy already disables the token and is the desired default.
- kpack ServiceAccounts and copied registry credentials need an explicit inventory.

## Steps

1. Set `automountServiceAccountToken: false` on every untrusted Pod template and generated ServiceAccount.
2. Remove or narrow RBAC that is unnecessary after the namespace split.
3. Add generated-object assertions for every builder/publish/pre-deploy variant.

## Files

- `lego/operator/internal/build/`
- `lego/operator/internal/predeploy/`
- `lego/operator/internal/publish/`
- `lego/operator/config/rbac/`
- `deploy/gitops/base/`

## Acceptance criteria

- [ ] No untrusted Pod variant mounts a projected ServiceAccount token.
- [ ] The build namespace's workload identities cannot read Secrets or list unrelated workloads through the Kubernetes API.
- [ ] Unit/rendered-manifest tests cover BuildKit, signed BuildKit, kpack, publish, and pre-deploy variants.

## Out of scope

- Operator-manager RBAC unrelated to untrusted execution.
