## Objective

Apply default-deny ingress/egress and untrusted node placement to the dedicated execution namespace, then allow only the dependencies proven necessary by t001.

## Context

- `bex-system` currently has ingress-only policy.
- Builds must never become eligible for tainted platform nodes merely to gain capacity.
- DNS, source hosts, Zot, and explicitly required datastore endpoints need intentional policy.

## Steps

1. Add namespace-wide default-deny ingress and egress.
2. Add narrow DNS, source, registry, and required-service allowances with workspace scoping where possible.
3. Pin build placement to the untrusted tenant/build pool and exclude platform nodes.
4. Extend GitOps validation and live reachability tests.

## Files

- `deploy/gitops/base/network-policies.yaml`
- `deploy/gitops/base/tenant-node-egress.yaml`
- `deploy/gitops/base/`
- `scripts/gitops-validate.sh`
- `scripts/verify-tenant-isolation.sh`

## Acceptance criteria

- [ ] Metadata, kubelet, Kubernetes API, platform services, and cross-tenant probes are blocked from execution Pods.
- [ ] Valid Git/build/registry flows pass their positive controls.
- [ ] Scheduler evidence proves execution Pods cannot land on the platform pool.

## Out of scope

- Introducing a new physical build node pool unless existing placement cannot meet the contract.
