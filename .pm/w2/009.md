# `POST /v1/blueprints/validate` 400s on a plain bex App CR manifest

`w9/m2`'s Render CLI walk ran `render blueprints validate examples/whoami-app.yaml` (a valid bex App CR spec, not wrapped in a `render.yaml`-shaped `services:` document) and got `validation request failed with status 400: {"error":"bad request"}`. ADR018 marks blueprint validate as shipped/✅ (`w2/m15`, done) with no known issue recorded, so this is either a real regression or the CLI's evidence run simply fed it the wrong input shape (an App CR instead of a `render.yaml`/Blueprint manifest) — the error message gives no way to tell which from the CLI side (see `docs/cli-compatibility-checklist.md` root cause RC1, the generic-error-envelope bug, which also swallows this one's real reason). Retest with a real `render.yaml` and, separately, fix bex-api's error body so a bad-request reason is legible to any Render-spec client, not just this one.

Evidence + full repro harness: `docs/cli-compatibility-checklist.md` (`blueprints validate` row).

Source: `w9/m2` (Render CLI compatibility), 2026-07-15.
