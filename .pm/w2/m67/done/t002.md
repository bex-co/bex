## Objective

Bound the Active tier's cost: a workspace may hold at most N concurrent **live** agent-session sandboxes (ADR059 D6's live-compute bound); create/steer/resume beyond the cap gets a named, actionable refusal.

## Context

- Longer idle grace (t001) multiplies live pods; without a cap one workspace can exhaust the `bex-sandbox` pool — the exact failure mode ADR059 D6 names.
- Count = sessions in live phases (`creating/running/resuming/redispatching`) with `sandbox_id <> ''` for the workspace — a store count query at dispatch time in `agentsessions/service.go` (`Create`/`Steer`/`Resume` dispatch paths), checked before sandbox provisioning.
- Env: `BEX_AGENT_MAX_LIVE_SANDBOXES_PER_WORKSPACE` (default e.g. `5`; `0` disables). Named error code (e.g. `AGENT_SESSION_LIVE_LIMIT`) through the standard coded-error envelope so all three surfaces render it identically; the message should tell the user to stop/cancel an idle session.
- Race tolerance: a best-effort pre-check is acceptable (the dispatch CAS + Completer reconcile bound any overshoot); do not build a distributed lock.

## Steps

1. Store count query + dispatch-time guard in the three verbs' dispatch path.
2. Env plumbing + `CLAUDE.md`/`.env.example` rows.
3. Confirm the refusal shape on REST/GraphQL/MCP via the existing coded-error tests' pattern.
