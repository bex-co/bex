## Objective

Remove the 90-day manual reseal by having Grafana's two analytics readers keep TLS encryption but stop verifying `bex-db`'s CNPG-generated CA, which rotates about every 90 days.

## Context

- User decision 2026-10-20: changing `bex-db`'s TLS for an internal, read-only dashboard is not worth it. The readers only `SELECT` from `product_analytics.events` / `cli_analytics.events` with database-side connection and query caps; cross-node traffic is WireGuard-encrypted (w1/m19); every other in-cluster `bex-db` client already connects without CA verification (only Grafana used `verify-full`, t002).
- `deploy/gitops/base/values/grafana.values.yaml`: datasources `product-analytics` / `cli-analytics` (`sslmode: verify-full`, `tlsConfigurationMethod: file-path`, `sslRootCertFile`) and the `extraSecretMounts` for `ca.crt`.
- `scripts/lib/analytics-bootstrap.sh` writes `password` + `ca.crt` and fails closed on CA drift (w7/m153 contract); `scripts/analytics-bootstrap.test.sh` pins that.
- Probe: `deploy/gitops/overlays/prod/analytics-datasource-probe.yaml` (`PGSSLMODE=verify-full`, `PGSSLROOTCERT`).

## Steps

1. Grafana values: `sslmode: require`; drop `sslRootCertFile`, `tlsConfigurationMethod` and both CA `extraSecretMounts`.
2. Bootstrap: password-only Secret; remove the CA read and the CA-drift branch; update the test (sealed Secret never rewritten, password follows it, no CA anywhere).
3. Reseal both `grafana-*-analytics.sealedsecret.yaml` with the unchanged password only (read the live password; never print it).
4. Probe: `PGSSLMODE=require`, drop `PGSSLROOTCERT` and the `ca.crt` dependency.
5. Validator: fail if a sealed manifest or Grafana value in `monitoring` reintroduces a `bex-db` CA / `verify-full` for these readers.
6. ADR088 § Analytics datasource custody: record the decision and its reasoning; drop the reseal runbook.

- [ ] Reader passwords stay sealed and unchanged.

## Out of scope

**Done 2026-10-20:** Grafana datasources `sslmode: require` with no `sslRootCertFile` or CA mounts; reader SealedSecrets resealed with the unchanged password only; `analytics-bootstrap.sh` neither reads nor writes `bex-db-ca` (test asserts it, all 19 checks pass); probe `PGSSLMODE=require`; `gitops-validate.sh` requires `require` + no `sslRootCertFile` for both datasources and fails if a reader SealedSecret seals anything but `password` (red-checked with the previous CA-bearing manifest); ADR088 § Analytics datasource custody records the decision.
