## Objective

Send the unhealthy-service email Render sends, digesting flaps so a crash loop does not flood inboxes.

## Context

- Event source: `server_failed` / `server_available` facts (see `store/event_facts.go`, push worker `notifications/push_worker.go`).
- Render documents no digest; digest only limits mail frequency, never drops an alert.
- Render: service-becomes-healthy is Email ✗ — do not email recovery unless Render's doc says so at the time of implementation.

## Steps

1. Add an email projection for `server_failed` reusing the push worker's durable event cursor/claim pattern (exactly-once per member).
2. Digest: first failure mails immediately; subsequent failures for the same service within a window are batched into one digest mail.
3. Email content: service name, time, last instance exit reason if known, link to service events/logs.

- [ ] One email per first failure; N flaps in a window → one digest listing them.
