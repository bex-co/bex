## Objective

Re-pin `lego/cli`'s imported `render-oss/cli` to the current upstream release and prove the launcher still builds and passes its suite, recording any upstream flag/behavior changes for t004's checklist run.

## Context

- Current pin (checked 2026-08-18): Render release **v2.22.0**, commit `d8fd7c2bb09d56beaca5df15ac2aefcb5ae5f427`, Go module pseudo-version `v1.1.3-0.20260721145337-d8fd7c2bb09d` (pinned 2026-07-21) — recorded in `lego/cli/UPSTREAM_RENDER_CLI.md`, which CI compares against `go.mod`. If no upstream release newer than v2.22.0 exists, this task verifies + records that (dated note in the pin record's update trail via the PR/notes for t005) instead of moving the pin.
- The module needs Go 1.26 (`lego/cli/go.mod`: `go 1.26.0`); workspace builds use the 1.26 toolchain.
- Upstream v2 tags are not valid Go major-version tags (no `/v2` module path), so the pin is always `go get github.com/render-oss/cli@<commit>` yielding a pseudo-version.

## Steps

1. Check upstream `render-oss/cli` releases for the newest tag; identify its commit.
2. Follow `lego/cli/UPSTREAM_RENDER_CLI.md`'s update procedure: `go get` the exact commit from `lego/cli/`, update the record's three values, confirm `cmd.RootCmd` is still exported and no new upstream command collides with the Bex-native names (`code`, `glm`, `muse`, `kimi`, `deepseek`), and re-diff upstream's unexported `isRootVersionRequest` against the `main.go` intercept.
3. `bash scripts/bex-cli-validate.sh` and `cd lego/cli && go test ./...` (go 1.26 toolchain).
4. Diff upstream command/flag surface between the old and new pin; write down every added/removed/changed command or flag and behavior change for t004.
