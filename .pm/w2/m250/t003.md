## Live observation — 2026-11-03 03:53 UTC (from the `/qa-find-bugs w4` loop, read-only `kubectl get`)

- The xxl pool's first scale-up fails at Hetzner: the `HCloudMachine` `bex-tenant-xxl-rf84l-642td` reports `ServerCreateFailedReason` with the message `failed to create HCloud server "bex-tenant-xxl-rf84l-642td" in "fsn1" (type "ccx43"): dedicated core li…`, cut off in the condition. This is the account's dedicated-vCPU limit. An earlier xxl Machine (`bex-tenant-xxl-rf84l-ckgqh`) was in the same state, so CAPI keeps recreating it.
- So a `pro_ultra` service cannot reach `live` until the Hetzner dedicated-core limit is raised for the project (a support request, which needs the account owner), or the xxl pool uses a type that fits the current limit. Check `kubectl -n <capi ns> get hcloudmachine -o yaml` for the full message before choosing.
- The xl pool (cx53) did not show a failing machine at that time.
