# 079 — Pooled Postgres connection strings use port 5432; Render's use 6432

Why: Render's pooled URLs differ from the direct ones only by PgBouncer's port 6432. Its docs tell users to swap the port. A bex user following Render's guidance, or comparing the two URLs, finds the same port on both, and a Render-shaped client config that pins 6432 for pooled traffic cannot connect.

- Render ([docs](https://render.com/docs/postgresql-connection-pooling)): "The pooled URLs are almost identical to your direct connection URLs, except they use PgBouncer's port 6432 instead of the standard PostgreSQL port 5432."
- bex: the pooled URI is built with `:5432` in two places, `lego/backend/internal/postgres/service.go:1114` (connection info) and `lego/operator/internal/controller/database_controller.go:1381` (the operator's pooler Secret `uri`). The CNPG `Pooler` Service listens on 5432 by default.
- Fix shape: serve the pooler on 6432, both the CNPG Pooler Service port and the external SNI path through `pg-sni-proxy` if pooled external URLs ride it. Emit 6432 in both URI builders, and keep existing clients working: check whether any `fromDatabase` `connectionPoolString` consumer or tenant env holds the old URI, and plan a dual-port window if so. Covers REST/GraphQL/MCP `connection-info` and Blueprint `connectionPoolString`.
