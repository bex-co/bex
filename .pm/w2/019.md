Deploy should idempotently apply the ssh-gateway DB role grants (dbrole.sql)

Found live during w2/m65 acceptance (2026-08-11): the gateway role missed
`SELECT ON agent_sessions` in prod because `dbrole.sql` (the single source of the
gateway's DB privilege surface) is applied out-of-band by
`scripts/ssh-gateway-db-role.sh`, which the deploy pipeline never runs. Any future
gateway grant will silently be absent until someone re-runs the script by hand —
so a shipped feature that needs a new grant is broken in prod with no signal.

Fix idea: a deploy step (or a small Argo Job / init) that idempotently applies
`internal/sshgateway/dbrole/dbrole.sql` against the CP DB on each deploy, so the
tested boundary and the live boundary can't drift. Keep it least-privilege (GRANT
only; the role/password creation stays where it is). Sub-hour once the apply
mechanism is chosen; possibly folded into w2/m68's ops scope (it also adds an
object-storage contract). Record which it lands in.
