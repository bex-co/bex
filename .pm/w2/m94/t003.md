## Objective

The service read exposes each linked group's position in `spec.envFromSecrets` (for example an ordered `linkedEnvGroups` list or a `linkOrder` per group) identically on REST, GraphQL and MCP. The Linked Environment Groups panel renders groups in precedence order (last linked first) and marks a key or secret file as shadowed when a later-linked group defines the same name, with a tooltip naming the winning group. The existing service-overrides-group marker stays as the control.

## Context

- Runtime: linking appends the group's Secret to `spec.envFromSecrets` (`addString`, `lego/backend/internal/envgroups/service.go:1083`, `:1896-1901`). The operator emits groups in that order, then the service's own Secret (`envFromSources`, `lego/operator/internal/controller/app_controller.go:3847-3878`). Kubernetes lets the last `envFrom` source win, so the most recently linked group beats earlier ones. Files follow the same list-order rule after t002.
- Display: `EnvGroupItem` marks a group key as overridden only when the **service** defines it (`dashboard/src/features/services/components/env-groups-panel.tsx:185-190`, `w6/done/067`). It never compares linked groups with each other. `linked` is the workspace group list filtered by link (`:68-70`), so it carries no link order. Secret file names are rendered without any check (`:236`).
- Live evidence (w1/091, 2026-09-14): with B linked then A, both defining `MESSAGE`, the service served A's value; the panel listed A above B with no marker (0 `s`/`del`/`.line-through` nodes).
- Render: "Render does not guarantee its precedence behavior when multiple linked environment groups define the same environment variable. Currently, Render uses the value from the most recently created environment group." bex keeps last-linked-wins (changing it would silently flip running services); t005 records the divergence.

## Steps

1. Add the ordered link information to the service view in `lego/backend/internal/apps` (whatever `AppView` field the three adapters share), derived from `spec.envFromSecrets` order. Confirm REST, GraphQL and MCP read the same field.
2. In `env-groups-panel.tsx`, sort linked groups by precedence and compute, per key and per file name, whether a later-linked group defines it. Reuse the existing strike-through affordance and add a tooltip such as "Overridden by `<group>`, linked later". Add `en` and `zh` strings.
3. Mark a linked group's secret file as overridden when the service defines the same name (the t002 rule), reusing the `services.envGroupKeyOverridden` copy shape.
4. Panel tests: two groups sharing a key (the earlier-linked one is marked), two groups sharing a file name, the service-override case as the control, and the ordering assertion.
