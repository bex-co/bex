## Objective

A Render-shaped environment-group write (a variable, a secret file, a link, an unlink, a delete, or create-with-services) updates the group's Secret for every linked service, but opens a deploy only on linked services whose `autoDeploy` is `yes`. Services with auto-deploy off keep running their current release and pick the new values up on their next deploy. The write result names the services left untouched, and the group page copy says so. The explicit `saveMode` paths (REST `PATCH /v1/env-groups/{id}/contents`, GraphQL `saveMode`, MCP `saveMode`, the dashboard editor) stay a caller's deliberate choice and are unchanged.

## Context

- Every Render-shaped group write hard-codes `SaveMode: SaveModeDeploy`: `SetEnvGroupVars` (`lego/backend/internal/envgroups/service.go:884`), `SetEnvGroupVarInput` (`:936-939`), `DeleteEnvGroupVar` (`:960-962`), `SetEnvGroupFile` (`:979-981`), `DeleteEnvGroupFile` (`:1003`), `ApplyEnvGroup` (`:1372`).
- `patchEnvironmentAuthorized` rolls **every** linked service (`lego/backend/internal/envgroups/patch.go:282-306` → `rollOne` → `rollLinkedService`, `service.go:1114-1119`).
- Link (`linkFetched`, `service.go:1082-1086`), unlink (`detachFetched`, `:1176-1180`) and create-with-services (`persistCreate`, `:659-665`) roll the service directly.
- `grep -rni autodeploy lego/backend/internal/envgroups` (non-test) returns 0 hits.
- Explicit-mode callers: REST `/contents`, GraphQL `graphql.go:298`, MCP `mcp.go:204`, dashboard `env-group-editors.tsx:51`.
- Live evidence (w1/092, 2026-09-14): `PATCH /v1/services/<srv> {"autoDeploy":"no"}` → 200, then `PUT /v1/env-groups/<evg>/env-vars/MESSAGE` → 200 and a `config_change` deploy opened one second later and went live.
- Render: "If you make changes to an environment group (including deleting it), Render kicks off a new deploy for every linked service that has autodeploys enabled." (`render.com/docs/configure-environment-variables`, fetched 2026-09-14).
- The group page states unconditionally: "Linking or unlinking redeploys the affected service."

## Steps

1. Add one gate in the roll path (`rollLinkedService` or its caller) that reads the linked App's `autoDeploy` and skips the deploy when it is off, while still writing the group Secret. Return the skipped service ids to the caller.
2. Route the six hard-coded call sites, plus link, unlink, create-with-services and group delete, through that gate. Keep the explicit `saveMode` paths untouched.
3. Decide `ApplyEnvGroup` (Blueprint sync) separately: check Render's Blueprint semantics for env-group changes during a sync and record the decision in the m94 README under a `## Decisions` heading, with the source.
4. Surface the untouched services on the write result on REST, GraphQL and MCP together (for example `pendingServiceIDs`), and change the group page copy to "Linking or unlinking redeploys linked services that have auto-deploy on." in `en` and `zh`.
5. Per-verb tests: one auto-deploy-on service (a deploy row opens) and one auto-deploy-off service (no deploy row, Secret updated). Keep the existing explicit-`saveMode` tests as the control.
