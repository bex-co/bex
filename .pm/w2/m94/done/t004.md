## Objective

`PatchEnvironment` on an environment group applies the same quota rule the service batch patch got in `w1/m147`: a map already over the secret-map quota accepts a patch that leaves it with no more entries and no more bytes than before, and refuses one that grows it. The refusal sentence stays unchanged so the `w1/m147` adapter table still holds.

## Context

- `lego/backend/internal/envgroups/patch.go:186-189` runs `secrets.ValidateEnvMapQuota(env)` / `secrets.ValidateFilesMapQuota(files)` on the patched copies with no comparison against the pre-patch maps.
- The rule to reuse is `patchWithinQuota(before, after, within)` in `lego/backend/internal/secrets/batch.go:619`, unexported.
- A group can only be over quota if it was filled before the round-11 fix (`cacde0622`, 2026-08-17) or through a path outside `envgroups`. The per-key `DeleteEnvGroupVar` / `DeleteEnvGroupFile` are unaffected.
- From `w1/100` (code triage during `w1/m147` t006, 2026-09-15; not probed live).

## Steps

1. Export the helper from `secrets` (for example `ValidatePatchQuota(before, after, within)`), keeping `patchWithinQuota` as a thin alias or replacing its call sites.
2. Call it at `envgroups/patch.go:186-189` with `oldEnv`/`env` and `oldFiles`/`files`.
3. Extend `envgroups/quota_guard_test.go` with a pair of tests on a group seeded over quota: a delete-only patch succeeds, an add is refused with the existing sentence.
