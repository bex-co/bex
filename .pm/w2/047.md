# 047 — `basic-256mb` and `basic-1gb` Postgres are priced above bex's own Render × 0.70 rule

Why: ADR030 prices Postgres at Render × 0.70, but `pricing.yaml` records Render's small tiers at $7 and $20 while Render lists $6 and $19, so every paid small database is billed $0.70/month more than the rule allows.

**Found by:** `w2/m171` t001 research, 2026-10-19 (render.com/pricing page data: `0.1c-256mb` "$6/month", `0.5c-1g` "$19/month"; legacy table "Basic-256mb $6/month", "Basic-1gb $19/month").

## Evidence

- `lego/backend/internal/pricing/pricing.yaml`: `basic-256mb` `0.000001864535768645 # $4.90/mo (Render $7.00 × 0.70)`; `basic-1gb` `0.000005327245053272 # $14.00/mo (Render $20.00 × 0.70)`.
- At the rule, they would be **$4.20** and **$13.30** per instance-month.
- `scripts/stripe-billing-setup.py` derives each Stripe meter price from `pricing.yaml` and refuses when an existing Stripe price differs ("deactivate or repair it before enabling billing"), so the code change alone is not enough: the live Stripe catalog must be repaired too.

## Do

1. Confirm Render's current prices (they may have changed after bex's numbers were recorded; record the fetch date).
2. Update both rates and comments in `pricing.yaml` (`usdPerSecond = monthly / 2,628,000`) and any ADR030 table that quotes them; keep the pricing tests green.
3. **Needs the Stripe admin:** create the corrected Stripe prices and retire the old ones (the setup script's repair path), choosing whether existing subscriptions move at the next period.
