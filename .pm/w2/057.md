# 057 — Datastore backup and export Jobs are charged to the services' compute quota, so a full Hobby workspace can lose its backups

Why: after w2/m247 t001 and w2/056, datastore instance Pods carry PriorityClass `bex-datastore` and are exempt from `tenant-compute-quota`, but the Job Pods that datastores need are not: Postgres exports, Key Value backup CronJob Pods, and CNPG initdb/join Pods. A Hobby workspace whose services already use all 3 CPU (or 50 Pods) can have a scheduled Key Value backup or a requested Postgres export refused with `exceeded quota: tenant-compute-quota`. On Render, backups are not competing with your services for a quota.

## Do

1. Find every datastore-owned Job/Pod template the operator creates (Postgres export/expiry/purge Jobs, the Key Value backup CronJob, CNPG bootstrap Pods through `spec.priorityClassName`, which CNPG propagates).
2. Give them `priorityClassName: bex-datastore`, and extend the operator workload admission rule (w2/m247 t001) so only datastore-owned Jobs may carry it.
3. Test: with the services' CPU at the Hobby budget, a Key Value backup Job and a Postgres export still start.

## Acceptance

- [ ] Datastore backup/export Jobs run in a Hobby workspace whose services use its whole compute quota.
