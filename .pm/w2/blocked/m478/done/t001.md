## Objective

Extend the provider table: Anthropic (`aud` `api.anthropic.com`, `ANTHROPIC_IDENTITY_TOKEN_FILE`) and OpenAI (`aud` `api.openai.com`, `OPENAI_IDENTITY_TOKEN_FILE`), and give a service with several providers one token per audience.

## Context

- Provider triggers on Render (set as ordinary service env vars, then redeploy): AWS `AWS_ROLE_ARN` → `AWS_WEB_IDENTITY_TOKEN_FILE` (aud `sts.amazonaws.com`); GCP `GCP_WORKLOAD_IDENTITY_PROVIDER` (+ optional `GCP_SERVICE_ACCOUNT_EMAIL`) → `GOOGLE_APPLICATION_CREDENTIALS` (a generated credential configuration; aud = the provider's default audience); Anthropic `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID`, `ANTHROPIC_SERVICE_ACCOUNT_ID`, `ANTHROPIC_WORKSPACE_ID` → `ANTHROPIC_IDENTITY_TOKEN_FILE` (aud `api.anthropic.com`); OpenAI `OPENAI_IDENTITY_PROVIDER_ID`, `OPENAI_SERVICE_ACCOUNT_ID` → `OPENAI_IDENTITY_TOKEN_FILE` (aud `api.openai.com`). Render says not to set the `*_FILE`/credentials variables by hand. No REST/CLI/MCP/Blueprint field exists. Build time: native runtimes get the token, Dockerfile builds do not. OIDC does not authenticate ECR image pulls.

## Steps

1. Add the variable names to `lego/types/renderenv`.
2. Mint and mount one token per configured audience; never reuse a token across audiences.

## Files

- `lego/types/renderenv/`
- the w2/m477 provider table and minter
- `lego/operator/internal/` mount code

## Acceptance criteria

- [x] Tests: a service with AWS and Anthropic variables gets two files with different `aud`; removing one provider removes only its file.

## Out of scope

- GCP (w2/m479).

## Done (2026-11-18)

Deviation: the provider table lives in `lego/types/v1alpha1/managed_oidc.go` (`ManagedOIDCProviders`, where w2/m477 put it), not in `lego/types/renderenv`, which holds Render's platform default variables only.

- `ManagedOIDCProviders` adds `anthropic` (`ANTHROPIC_FEDERATION_RULE_ID` → `ANTHROPIC_IDENTITY_TOKEN_FILE`, file `anthropic-token`, `aud` `api.anthropic.com`) and `openai` (`OPENAI_IDENTITY_PROVIDER_ID` → `OPENAI_IDENTITY_TOKEN_FILE`, file `openai-token`, `aud` `api.openai.com`). The w2/m477 mechanism needed no other change. The operator decides and mounts every provider the release sets, and the minter mints one token per provider, each for its own audience.
- Below Pro, the deploy log names every trigger the release set (`AWS_ROLE_ARN, ANTHROPIC_FEDERATION_RULE_ID and OPENAI_IDENTITY_PROVIDER_ID are set, …`).
- Tests:
  - `TestManagedOIDCProvidersAreRendersVariables` and `TestManagedOIDCProvidersNeverShareATokenOrAFile` (types).
  - `TestAServiceWithSeveralProvidersGetsOneTokenPerAudience` (minter): each token verifies through discovery for its own audience only, a provider added at a deploy is minted at once, and a provider dropped at a deploy loses only its key.
  - The envtest "mounts one token file per provider when a release sets several triggers, and a later release drops only the one it no longer sets".
  - The logs refusal test for two and three triggers.
- Mutation-checked: a wrong Anthropic trigger fails the envtest, and a shared audience fails the minter test.
