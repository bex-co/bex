## Objective

Extend the opt-in real-BuildKit test gate: an authored build command reads and verifies the token; a Dockerfile build of the same source sees neither variable nor file; no layer of the built image contains the token.

## Done (2026-11-18)

`TestNativeManagedOIDCPinnedBuildKit` (`lego/operator/internal/build/nativeoidc_test.go`, `BEX_BUILDKIT_INTEGRATION=1`) runs the real preparer and the Job's exact buildctl arguments through the pinned `moby/buildkit:v0.30.0` on the local Docker daemon (arm64; the node toolchain is multi-arch):

- **Native**: the service set `AWS_WEB_IDENTITY_TOKEN_FILE=/tmp/mine` itself; the build command checks both variables name the platform paths, checks the SHA-256 of the AWS token, the GCP token and the credential configuration, and writes a verdict the test reads back from the RUN layer.
- **Dockerfile**: the same Options as a Dockerfile build; its RUN asserts neither variable is set and `/var/lib/render/oidc` does not exist.
- **Layers**: no blob of the archive (config, manifests, every layer, decompressed) contains either token, no `var/lib/render/oidc/` entry is committed, the build log carries no token, and the image's `Config.Env` names no token variable.

Passed 2026-11-18 (67 s cold, about 35 s warm). Mutations, each reverted: the loader copying the token into the workdir failed it (a decompressed layer carried the token); the token passed as `--opt build-arg:` with an `ARG` before the RUN failed it (the config's history carried it).
