## Objective

At build start, mint the service's provider tokens (and GCP configuration) and pass them beside the existing env secret, so the authored build command sees the same `*_FILE` variables a running instance does.

## Context

- Native builds read service env through `readBuildEnvSources` into a BuildKit secret (`lego/operator/internal/build/native.go`).

## Steps

1. Mint through the w2/m477 minter (or a build-scoped call it exposes); mount as a BuildKit secret, never as a build arg or a file copied into the context.
2. Dockerfile and buildpack paths stay unchanged.

## Files

- `lego/operator/internal/build/native.go`
- `lego/operator/internal/build/build.go`
- the minter's build-scoped entry point

## Acceptance criteria

- [x] Unit tests: native builds with a trigger get the secret mount and variables; Dockerfile and buildpack builds do not.

## Out of scope

- Refreshing a token inside a running build.

## Done (2026-11-18)

- **Decision** (`lego/operator/internal/controller/build_managed_oidc.go`): at a native build's dispatch the operator decides with the runtime's rules (`decideManagedOIDC`, factored out of `managedOIDC`) from `inFlightRelease`, records `status.buildManagedOIDC` (generation = the release being built) before the Job exists, and keeps it for the build. Dockerfile and buildpack builds never decide (`prepareSourceBuildEnv` calls it for `builder == native` only).
- **Minting** (`lego/backend/internal/managedoidc/minter.go`): the minter's targets are the running release's `<app>-oidc` and, while `AppStatus.BuildingManagedOIDC()` (phase `building` and a decision that mounts a provider), `<app>-oidc-build`, stamped `app.bex.co/oidc-generation` so a newer build never reuses an earlier build's tokens. The status watch wakes the minter when a build starts needing tokens.
- **Delivery**: the operator copies the minted files next to the Job as `bld-<app>-oidc` only when they carry the build's generation, rewrites it every pass while the build waits, and removes an earlier build's copy. `build.Options.ManagedOIDCSecret`/`ManagedOIDC`: a required Secret volume only the preparer mounts; the preparer snapshots the files into `/native/oidc`; buildctl `--secret id=bex-oidc-<file>`; the authored RUN mounts each at `/var/lib/render/oidc/<file>` (`required=true`); the env loader exports each file variable after the service's values. Never a build arg, ENV, COPY or context file. `endBuildManagedOIDC` clears the decision and deletes both Secrets at the build's terminal observation; the copy is in the finalizer's inventory.
- **Unit tests**: `TestNativeBuildMountsManagedOIDCFilesForTheBuildCommandOnly`, `TestOnlyNativeBuildsReadManagedOIDC` (Dockerfile, `auto` and buildpack Jobs/Images unchanged by a decision, and a native build without one byte-identical), `TestNativeManagedOIDCValidation`, `TestNativePreparerSnapshotsTheManagedOIDCFiles`; envtest `Managed OIDC at build time (w2/m480)`; `TestEndBuildManagedOIDCEndsTheBuildsTokensOnlyOnceItIsOver`; `TestANativeBuildGetsItsOwnTokensWhileItBuilds`; `TestStatusWatchWakesTheMinterWhenANativeBuildNeedsTokens`; `TestBuildingManagedOIDCIsTheBuildsDecisionWhileItBuilds`.
