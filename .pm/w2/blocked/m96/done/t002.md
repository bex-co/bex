## Objective

Make `resolveServiceNames` read from the retained-name record (t001) rather than from live resources, add a `deleted` signal to the per-resource estimate, and label sandbox rows. Because REST `GET /v1/usage`, GraphQL `usage` and MCP all funnel through `monthToDateAt`, one change moves all three surfaces. Record the backfill decision for pre-fix rows in the milestone README.

## Context

- `resolveServiceNames` (`lego/backend/internal/usage/service.go:286-313`) and `nameResourceEstimates` (`:320-332`) are the two places names enter the cost tree.
- At filing (2026-09-14) `usage(ownerId)` returned 27 resources, 17 with `serviceName: ""` (3 deleted services, 14 sandboxes). 13 of the 14 sandbox UUIDs are listed by no `sandboxes` or `agentSessions { sandboxId }` query.
- The dashboard already prefers `serviceName` (`charges-card.tsx:101`), so a non-empty name needs no UI change beyond the deleted marker (t003).

## Steps

1. Replace the live-only lookup with the t001 batch accessor; keep a live-resource fallback for rows with no retained name (pre-fix rows) so nothing regresses.
2. Add a per-resource `deleted` (or `resolved`) boolean to the estimate view: true when the id no longer resolves live but a retained name exists.
3. Sandbox rows: resolve the label via the retained record; if absent, try the live sandbox (`plan · image`) before falling back to the UUID.
4. Confirm REST, GraphQL and MCP each expose the name and the deleted flag with identical values for the same tenant/period.
5. Decide backfill for rows recorded before t001 (options: one-time backfill from live resources + audit-event names; or leave bare ids for historical rows) and write the decision under `## Backfill decision` in `.pm/w2/m96/README.md`.
