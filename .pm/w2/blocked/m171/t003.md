## Objective

Ship the approved tiers through the single catalog so every surface (REST, GraphQL, MCP, Blueprint, CLI, dashboard metadata) and every consumer (operator, pricing, billing) sees them.

## Context

- Catalog: `lego/types/tiers/tiers.yaml` (`postgres.tiers`: `id`, `cpu`, `memory`, `storageGB`, `instances`, `backup`; `renderPlan` when the bex id differs from Render's).
- Pricing: `lego/backend/internal/pricing/pricing.yaml` (`postgres:` list); Stripe: `scripts/stripe-billing-setup.py`.
- Schemas: `lego/backend/internal/apps/schema/capabilities.json`, `render.yaml.json`; HA gate `lego/backend/internal/postgres/tiers.go:115-140` (drop the "no ≥1-CPU plan" test-only rationale once a real plan exists).
- Admission: ADR009 "Capacity admission (w8/m50)" — one helper for creates, merged updates, dry runs, plan changes and Blueprint sync.

## Steps

1. Add the tiers (and `renderPlan` mappings) to `tiers.yaml`; regenerate anything derived.
2. Add prices (Render × 0.70) and Stripe catalog entries.
3. Implement the t001-recorded Render rule for plan changes that would leave HA on an ineligible plan, in the shared admission helper (so REST, GraphQL, MCP and Blueprint agree).
4. Flatten `PlanSupportsHighAvailability`'s test-only indirection if tests can now use a real plan.
5. Raise `bex-tenant-0`'s autoscaler max-size 5 → 8 (user decision 2026-10-29, milestone README `## Unblock 2026-10-29`) in `infra/clusterapi/overlays/hetzner-caph/cluster.yaml`, keeping `scripts/clusterapi-validate.sh` and ADR060 consistent as `2faa86f18` did. After the `app-cluster.yml` roll, confirm the live MachineDeployment annotation reads 8.
