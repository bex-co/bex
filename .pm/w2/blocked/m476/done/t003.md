## Objective

Make the key set durable and rotatable: bootstrap a key when none exists, publish the next key before it signs, retire the previous one only after its tokens have expired.

## Context

- Key custody per the ADR (D5 recommends a `bex-system` Secret).
- bex-api runs two replicas: bootstrap must not race (one writer).

## Steps

1. Implement bootstrap and the rotation states (next → current → previous → removed).
2. Add a rotation command or script plus a runbook under `docs/runbooks/`.
3. Exercise one rotation on dev-2.

## Files

- `lego/backend/internal/oidcissuer/`
- `docs/runbooks/oidc-key-rotation.md` (new)
- `lego/backend/AGENTS.md` (any new env var)

## Acceptance criteria

- [x] On dev-2, a token signed before a rotation still verifies until it expires, and new tokens carry the new `kid`.
- [x] Two replicas starting together create exactly one key.

## Done (2026-11-18)

Bootstrap: `KeySet.Load` inserts the first key when `oidc_signing_keys` is empty through `store.BootstrapOIDCSigningKey`, which holds a transaction advisory lock, so replicas starting together insert one key (`TestOIDCBootstrapInsertsExactlyOneKey`, 16 concurrent callers on real Postgres, and the deterministic `TestOIDCBootstrapWaitsForAWriterHoldingTheKeySet`, which fails every time without the lock). States are a pure function of the rows and the clock (`Classify`: next, current, previous, removed; ADR116 D6), so replicas need no coordinator; each reloads every minute, deletes removed rows, and refuses to sign after an hour without a reload. Rotation: `/api oidc-rotate-key [--emergency] [--apply]` (`oidcissuer.Rotate`, `store.RotateOIDCSigningKey`), runbook `docs/runbooks/oidc-key-rotation.md`. No new environment variable beyond `BEX_OIDC_ISSUER_URL` (t005).
