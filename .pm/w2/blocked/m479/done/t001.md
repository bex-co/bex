## Objective

Turn `GCP_WORKLOAD_IDENTITY_PROVIDER` (a resource name or its full URL) into the provider's default audience, mint the token for it, and generate an `external_account` configuration whose `credential_source.file` is the token file (with `service_account_impersonation_url` when `GCP_SERVICE_ACCOUNT_EMAIL` is set), named by `GOOGLE_APPLICATION_CREDENTIALS`.

## Context

- Provider triggers on Render (set as ordinary service env vars, then redeploy): AWS `AWS_ROLE_ARN` → `AWS_WEB_IDENTITY_TOKEN_FILE` (aud `sts.amazonaws.com`); GCP `GCP_WORKLOAD_IDENTITY_PROVIDER` (+ optional `GCP_SERVICE_ACCOUNT_EMAIL`) → `GOOGLE_APPLICATION_CREDENTIALS` (a generated credential configuration; aud = the provider's default audience); Anthropic `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID`, `ANTHROPIC_SERVICE_ACCOUNT_ID`, `ANTHROPIC_WORKSPACE_ID` → `ANTHROPIC_IDENTITY_TOKEN_FILE` (aud `api.anthropic.com`); OpenAI `OPENAI_IDENTITY_PROVIDER_ID`, `OPENAI_SERVICE_ACCOUNT_ID` → `OPENAI_IDENTITY_TOKEN_FILE` (aud `api.openai.com`). Render says not to set the `*_FILE`/credentials variables by hand. No REST/CLI/MCP/Blueprint field exists. Build time: native runtimes get the token, Dockerfile builds do not. OIDC does not authenticate ECR image pulls.
- Render's troubleshooting: the provider must use the project **number**, not the project id; the audience must be the default audience; libraries must request the `cloud-platform` scope.

## Steps

1. Parse both spellings; a project id where the number is required fails with a named deploy-log line.
2. Generate the configuration beside the token in the same Secret and mount it read-only.

## Done (2026-11-18)

Shipped as [ADR116 D11](../../../../../docs/ADR116-managed-oidc.md#d11--google-cloud-w2m479).

- **Parse** (`lego/types/v1alpha1/managed_oidc_gcp.go`, not `renderenv`, which holds Render's `RENDER_*` defaults): `NewManagedOIDCGCP` takes `projects/…`, `https://iam.googleapis.com/projects/…` and `//iam.googleapis.com/projects/…` to one resource name. A project id is refused by name, and so is any other value that is not a provider's resource name, or a `GCP_SERVICE_ACCOUNT_EMAIL` that could not name an account in the impersonation URL.
- **Decide** (operator): the release records `status.managedOIDC.gcp` (resource name and email, or `refused`), and `gcp` joins `providers` only when usable. GCP sits second in `ManagedOIDCProviders`, Render's order.
- **Mount**: `gcp-token` and `gcp-credentials.json` in the same read-only Secret volume, `GOOGLE_APPLICATION_CREDENTIALS=/var/lib/render/oidc/gcp-credentials.json`, the service's own value giving way. A template that mounts GCP carries its inputs in `app.bex.co/managed-oidc-gcp`, so a cancel that restores a served template restores its inputs (`recordManagedOIDCOf`), and the status watch wakes the minter for that change.
- **Mint** (bex-api): the token for `https://iam.googleapis.com/<resource name>`, with the configuration written beside it and both rewritten when the provider or the account changes.
- **Deploy log**: `==> GCP_WORKLOAD_IDENTITY_PROVIDER names project "my-project" by its ID: …, so no Google Cloud credential configuration is mounted`. The deploy itself proceeds, with its other providers: Render's page documents only Google's run-time "invalid audience" for this mistake, so failing the deploy would be stricter than Render.
- `scripts/oidc-audience-verify.sh` now checks GCP too. It reads the configuration, requires it to name the token file, and takes the audience from it. Its self-test covers AWS beside GCP, and a configuration that names another token file.
