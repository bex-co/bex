## Done (2026-11-18)

- Golden files `lego/backend/internal/managedoidc/testdata/gcloud-direct.json` and `gcloud-impersonate.json`. They were written by gcloud 593.0.0 (core 2026.11.06) with `gcloud iam workload-identity-pools create-cred-config projects/123456789012/locations/global/workloadIdentityPools/bex-pool/providers/bex-provider [--service-account=svc@my-project.iam.gserviceaccount.com] --credential-source-file=/var/lib/render/oidc/gcp-token --credential-source-type=text --output-file=…`. The command is recorded in the test.
- `TestGCPCredentialConfigurationIsWhatGcloudWrites` compares byte for byte, for each spelling, with and without the account. Any field, order or whitespace drift fails it. The token path is the mounted one, so no path differs.
- `TestGoogleAuthExchangesTheMountedTokenForCloudPlatform` uses `golang.org/x/oauth2/google` (already in the module graph, now a direct backend dependency, adding `cloud.google.com/go/compute/metadata` to `go.mod`). `google.CredentialsFromJSONWithType(…, ExternalAccount, cloud-platform)` builds credentials from the file. With the endpoints pointed at a stand-in, it sends the file's token to STS with the provider's `//iam.googleapis.com/` audience and the `cloud-platform` scope, rereads the file at the next exchange, and calls `generateAccessToken` for the account when one is named. gcloud itself loaded the dev-2 file and reached Google's STS (t001).
