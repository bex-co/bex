## Objective

Extend the Managed OIDC ADR with the delivery design and its residuals.

## Context

- IDs: `lego/backend/internal/id/id.go` (`Workspace` = `tea`, `Service` = `srv`, `Environment` = `evm`). Pod labels `app.bex.co/workspace` and `app.bex.co/environment-id` (`lego/types/v1alpha1/labels.go`).
- Plan gate pattern: `requireAutoscalingPlan` → `RequirePlanFeatureAt(ctx, tenantID, field, core.FeatureAutoscaling)` (`lego/backend/internal/apps/settings_check.go:423`, w7/m429).
- Short-lived credential precedent: bex-api mints a 1 h GitHub installation token into the per-App `<app>-clone` Secret named by `spec.cloneSecret` (`lego/types/v1alpha1/app_types.go:687`).
- Uniform pod hook: the mutating webhook `lego/operator/internal/webhook/instance_id.go` sees every tenant pod carrying `RENDER_SERVICE_ID` (web, cron and pre-deploy pods); Render env names live in `lego/types/renderenv`.
- Native builds read service env through `readBuildEnvSources` into a BuildKit secret (`lego/operator/internal/build/native.go`, w1/121); kpack refuses `secretKeyRef` build env (`.pm/w1/done/121.md`).
- No OIDC issuer, discovery or JWKS code exists in `lego/` today; no etcd `EncryptionConfiguration` was found under `infra/` or `deploy/`.
- Provider triggers on Render (set as ordinary service env vars, then redeploy): AWS `AWS_ROLE_ARN` → `AWS_WEB_IDENTITY_TOKEN_FILE` (aud `sts.amazonaws.com`); GCP `GCP_WORKLOAD_IDENTITY_PROVIDER` (+ optional `GCP_SERVICE_ACCOUNT_EMAIL`) → `GOOGLE_APPLICATION_CREDENTIALS` (a generated credential configuration; aud = the provider's default audience); Anthropic `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID`, `ANTHROPIC_SERVICE_ACCOUNT_ID`, `ANTHROPIC_WORKSPACE_ID` → `ANTHROPIC_IDENTITY_TOKEN_FILE` (aud `api.anthropic.com`); OpenAI `OPENAI_IDENTITY_PROVIDER_ID`, `OPENAI_SERVICE_ACCOUNT_ID` → `OPENAI_IDENTITY_TOKEN_FILE` (aud `api.openai.com`). Render says not to set the `*_FILE`/credentials variables by hand. No REST/CLI/MCP/Blueprint field exists. Build time: native runtimes get the token, Dockerfile builds do not. OIDC does not authenticate ECR image pulls.
- **Brainstorm recommendations, not user decisions** (record the chosen answer and its basis in the ADR): D2 issuer host `oidc.<root domain>` (`oidc.bex.co` in production, configurable for self-hosters); D3 deliver the token through a per-App Secret that bex-api refreshes and the pod mounts read-only (kubelet keeps Secret volumes in tmpfs; residual: a ≤60-minute token sits in etcd), with memory-only CSI delivery filed to FUTURE-MAYBE as the stricter variant; D4 below Pro the trigger variable is accepted and kept, no token is mounted, and the deploy log says why (Render's Hobby behavior is **unverified**); D5 one shared ES256 P-256 key set in a `bex-system` Secret, not OpenBao transit, so token refresh does not depend on OpenBao's manual unseal.
