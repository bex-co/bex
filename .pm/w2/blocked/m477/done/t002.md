## Objective

Decide per service whether Managed OIDC applies: a trigger variable (`AWS_ROLE_ARN` here) present in the service's own env, a linked env group or its Blueprint, and a Pro-or-higher workspace.

## Context

- Plan gate pattern: `RequirePlanFeatureAt` with a new `core.FeatureManagedOIDC` (`lego/backend/internal/apps/settings_check.go`).
- Env values can live in the service Secret, linked group Secrets or OpenBao; read keys the way the rest of bex-api does.

## Steps

1. Add `core.FeatureManagedOIDC` and a provider table keyed by trigger variable (AWS only in this milestone).
2. Project the result into the App spec field the ADR names (set only when it applies, so other Apps' specs stay byte-identical).
3. Below Pro: keep the variable, project nothing, and emit the deploy-log line the ADR specifies.

## Files

- `lego/backend/internal/core/` (feature)
- `lego/backend/internal/apps/` (projection)
- `lego/types/v1alpha1/app_types.go` (spec field, CRD regen in `lego/operator`)
- `lego/types/renderenv/` (variable names)

## Acceptance criteria

- [x] Tests: a Pro service with `AWS_ROLE_ARN` from each env source projects AWS; a Hobby one projects nothing and logs why; a service without the variable has an unchanged spec.

## Out of scope

- Refusing the env var write: it stays an ordinary variable on every surface.

## Done (2026-11-18)

- `core.FeatureManagedOIDC` (Pro and higher) and `core.PlanIncludes` (an unknown plan includes nothing); the provider table is `appv1alpha1.ManagedOIDCProviders` (AWS only), in `lego/types/v1alpha1/managed_oidc.go`, shared by both planes.
- **Deviation from step 2, recorded in ADR116 D9:** no App spec field. The plan is a label bex-api projects (`app.bex.co/managed-oidc: enabled`, `store.ManagedOIDCLabel`, on the projector's update path and the create path), and the operator reads `AWS_ROLE_ARN` from the release's own environment (literal, own Secret, linked groups, or their per-release snapshots), as it reads `PORT`. Every surface that writes a variable already reaches those sources, so none needs a projection of its own, and the decision follows the release's snapshot rather than a spec write every env writer would owe. Other Apps' specs and pod templates are untouched.
- Below Pro: the variable stays, `status.managedOIDC.planAllowed` is false, and the deploy log narrates it (`logs.oidcRefusalLine`).
- Tests: `store.TestReconcileLabelsManagedOIDCByWorkspacePlan` (every plan, no issuer, a downgrade, an unknown plan), the operator envtests for each env source and Hobby, `logs.TestManagedOIDCRefusalIsALineInTheDeployThatAskedForIt`.
