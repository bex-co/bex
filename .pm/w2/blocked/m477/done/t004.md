## Objective

Make the operator (or the pod webhook) mount the App's token Secret read-only and set `AWS_WEB_IDENTITY_TOKEN_FILE` in instances, cron runs and the pre-deploy Job.

## Context

- Pod hook: `lego/operator/internal/webhook/instance_id.go` sees every pod carrying `RENDER_SERVICE_ID`; pod projections live in `lego/operator/internal/controller/`.

## Steps

1. Add the mount and the variable where the ADR says, only for Apps whose spec asks for it.
2. envtest: a web App, a cron run and a pre-deploy Job carry the mount; an App without the field has a byte-identical pod spec.

## Files

- `lego/operator/internal/controller/`
- `lego/operator/internal/webhook/`

## Acceptance criteria

- [x] `make test` (operator) passes with the new envtests.
- [x] An SSH session into an opted-in instance can `cat "$AWS_WEB_IDENTITY_TOKEN_FILE"`.

## Out of scope

- Private image pulls from ECR: Render's OIDC does not cover them either.

## Done (2026-11-18)

`lego/operator/internal/controller/managed_oidc.go`: `managedOIDC` decides once per release, writes `status.managedOIDC` before the release's pods exist and keeps it; the Deployment template, every cron run's template and the pre-deploy Job mount the Secret volume (required, listing `aws-token`) read-only and set `AWS_WEB_IDENTITY_TOKEN_FILE`; the initial deploy hook copies the instance's template. Envtests (`managed_oidc_envtest_test.go`): own env, linked group and literal on a web service; Hobby keeps the variable and mounts nothing; a service without the trigger has the template an unlabeled one has; the plan decision is kept until the next deploy; a release that served before Managed OIDC is not rolled; a cron's template carries the mount and does not churn; the pre-deploy step carries it and the decision is on the App before its pod can start. `make test` passes.

The shell check ran on dev-2 through `kubectl exec` into the instance, the path the SSH gateway and the dashboard shell use (`pods/exec`): `AWS_WEB_IDENTITY_TOKEN_FILE=/var/lib/render/oidc/aws-token`, the directory a read-only tmpfs, the token readable. dev-2's in-cluster ssh-gateway was not running, so no `bex ssh` session ran; production's is t006's.
