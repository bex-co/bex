## Objective

Prove the end-to-end exchange without external accounts: an STS-compatible service configured to trust `https://oidc.bex.co/<tea>` (for example MinIO's `AssumeRoleWithWebIdentity`) issues credentials for the token a dev-2 or production QA service holds, before and after a refresh.

## Context

- The relying party fetches discovery from the public issuer, the same path AWS uses.

## Steps

1. Add `scripts/oidc-aws-verify.sh` that deploys or reuses the relying party and a QA service with `AWS_ROLE_ARN`, exchanges the token, waits past one refresh, and exchanges again.
2. Record the run in this milestone's README.

## Files

- `scripts/oidc-aws-verify.sh` (new)
- `examples/` fixture if needed

## Acceptance criteria

- [x] The script exits 0, and the token file's `iat` advanced between the two exchanges.

## Out of scope

- Real AWS (t006).

## Done (2026-11-18, dev-2)

`scripts/oidc-aws-verify.sh` (self-test `scripts/oidc-aws-verify.test.sh`, in `scripts.yml`) starts a MinIO STS in docker (the image the local cluster pins) trusting `<issuer>/<tea>` for `sts.amazonaws.com`, exchanges the instance's token with `AssumeRoleWithWebIdentity`, requires a second STS for another audience to refuse it, waits for a refreshed token and exchanges that too.
