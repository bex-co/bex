## Objective

Find a route that checkpoints a running sandbox pod's memory and processes and restores it into a recreated pod, on the production substrate:
- gVisor RuntimeClass under containerd, with the OpenSandbox BatchSandbox controller and its carried patches (`deploy/opensandbox/patches/`);
- candidates: `runsc checkpoint`/`restore` through containerd's checkpoint API, Kubernetes `ContainerCheckpoint` (kubelet checkpoint, then restore from the archive), or a controller-side `runsc` call in the confined `opensandbox-snapshot` Job.
Measure checkpoint size and time for a small sandbox. Write the evidence and the chosen route (or why none works) into ADR042 D5.

## Acceptance criteria

- [ ] A dev or staging sandbox running a background process is checkpointed and restored into a new pod with the process alive, or the evidence shows no carriable route.
- [ ] Size and time are measured and recorded.

## Result (2026-11-11)

- **Answer:** no upstream route. The only carriable route is a bex-maintained patched `containerd-shim-runsc-v1` on the sandbox node image. Evidence is in ADR042 D5 (feasibility paragraph).
- **Production substrate:** `gvisor`/`runsc`, containerd 2.3.3 (`bex-sandbox-*`).
- **What works:**
  - `runsc checkpoint`/`restore` from the CLI;
  - whole-pod `--no-root-container`, since gvisor#15551 (merged 2026-10-16).
- **What is missing:**
  - The runsc shim's Checkpoint RPC is `ErrNotImplemented`, and containerd's CRI `CheckpointContainer` for runsc is unimplemented (containerd#12280, open).
  - The kubelet checkpoint API is CRIU-only.
  - Shim support is gvisor#14760, open since 2026-09-15; gvisor#13326 was closed unmerged.
- **Not done:** no hands-on checkpoint was run. Proving the patched-shim route needs a disposable gVisor cluster, and it is only worth doing once that route is chosen.
