## Objective

Expose the selector and the new refusal identically on every surface that should carry them, and keep the two that should not carry them absent for a stated reason.

## Context

- One core, thin adapters ([ADR006](../../../../../docs/ADR006-bex-api.md)) — the same verb must not be re-implemented per surface.
- Connect and claim are **deliberately absent from MCP** because they are browser ceremonies an agent cannot complete ([ADR026 §5](../../../../../docs/ADR026-github-integration.md)). The selection verbs are halves of the same ceremony and inherit that absence.
- Env inventories live with the code and cascade: `lego/backend/CLAUDE.md` for bex-api.

## Steps

1. REST: `claimGit` body/query gains optional `installationId`; add `GET /v1/git/claim/selections/{id}` and `POST /v1/git/claim/selections/{id}`.
2. GraphQL: `claimGit(ownerId, installationId)`, `gitClaimSelection(id)`, `selectGitClaim(selectionId, installationId)`.
3. MCP: **no new tools** — add the same in-code note connect/claim already carry, so a future reader sees the absence is deliberate.
4. `GIT_INSTALLATION_WORKSPACE_LIMIT` returns the same code, HTTP 409, and details shape on all three surfaces, next to the existing `GIT_CONNECTION_LIMIT`.
5. Add `BEX_MAX_WORKSPACES_PER_GIT_INSTALLATION` to the bex-api env inventory in `lego/backend/CLAUDE.md`, and to `.env.example` if the existing connection cap is there (`.env.example` mirrors `.env` names — repo rule).

## Files
