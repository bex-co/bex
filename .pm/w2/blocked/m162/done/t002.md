## Objective

Make the claim flow and the bind path accept an installation another workspace already holds, on the claiming workspace's own three-proof sequence — the single change that unblocks the reported "永远无法绑定".

## Context

- `internal/github/service.go:347-377` (`claimFromCallback`) filters candidates to installations the OAuth user administers **and** that are unbound; the bound-elsewhere case falls through the `switch`'s implicit default and is silently discarded, producing `errNoClaimableInstallation` whose user-facing copy says "install the App first" — the misleading dead end from the report.
- `connectWithWorkspace` (`service.go:~385-415`) maps `store.ErrConflict` to "already connected to another workspace".
- The proofs that make this safe are unchanged: signed nonce-only state, single-use transaction, initiator match, fresh `can_manage`, `VerifyInstallationAdmin` against the exact installation. See [ADR078 §2 "Why the original rejection does not survive"](../../../../../docs/ADR078-github-workspace-connections.md).

## Steps

1. Delete the "not bound to any workspace" filter. Keep the same-workspace case as an idempotent candidate.
2. Remove the cross-workspace `ErrConflict` mapping from the bind path; keep conflict semantics only for a duplicate `(workspace_id, installation_id)`, which stays idempotent rather than an error.
3. Add the coded refusal for the new per-installation cap — `GIT_INSTALLATION_WORKSPACE_LIMIT`, 409, same shape as `GIT_CONNECTION_LIMIT` (count + limit in the details map).
4. Accept an optional `installationId` on `StartClaim`, recorded on the `github_connect_transactions` row, and use it at step 3 of the callback to **narrow** the server-proved candidate set. An id the OAuth user does not administer must not become a candidate.
5. Leave `no_claimable_installation` and `ambiguous_installation` as bounded codes; their meanings narrow rather than disappear.

## Acceptance criteria

- [x] An installation bound to workspace A binds to workspace B given B's own complete proof sequence; both rows exist.
- [x] A caller without `can_manage` on the target workspace is still refused, and a callback whose OAuth user does not administer the installation still binds nothing.
- [x] Re-claiming into a workspace that already holds the installation is idempotent (one row, no error).
- [x] A supplied `installationId` outside the proved set narrows to zero candidates rather than binding it.
- [x] The per-installation cap refuses with `GIT_INSTALLATION_WORKSPACE_LIMIT`.
