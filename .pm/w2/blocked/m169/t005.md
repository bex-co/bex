## Objective

Show that the original failure — uploads vanishing when the pod is replaced — is gone, using both replacement paths that previously lost data.

## Context

- Before this milestone the pod had no volumes, so every restart and every redeploy emptied the upload directory.
- Use a site admin account (Discourse API key or the admin UI) on one forum; keep the test post unlisted or delete it afterwards.

## Steps

1. Upload a small test image; GET its URL → 200.
2. Delete the pod; after it is Ready, GET → 200.
3. Trigger a bex manual deploy of `beancount-forum`; after it is live, GET → 200.
4. Delete the test post and upload; record the evidence (timestamps, pod names, deploy id).

## Acceptance criteria

- [ ] The test upload survives both a pod deletion and a redeploy.
- [ ] The test artifacts are removed.

## Out of scope

- Off-cluster backups of the forum disk (ADR082 snapshot policy applies as for any disk).
