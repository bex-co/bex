## Objective

Give the activator a suspended responder: a `503` with `Retry-After` and a bex body in the format the client asked for. It must mirror the maintenance branch's no-side-effect behavior, so a request to a suspended host never scales the App or advances its activity marker.

## Context

- The activator's content-negotiated 503 interstitial for sleeping services lives at `lego/operator/cmd/activator/main.go:198-210`.
- The maintenance branch (`main.go:151-156`) already answers without waking; copy that shape.
- `wakeApp` (`main.go:136-165,171-182`) is the sole writer of `app.bex.co/last-active` on the web path; the suspended branch must never reach it.
- Observed today (`w1/094`): `HTTP/2 503`, `content-type: text/plain`, body `no available server` for HTML, JSON and no-`Accept` requests alike.

## Steps

1. In the activator's request path, check the suspended marker t001 exposes before the sleep/wake branch.
2. Respond `503` with `Retry-After` and: HTML for `Accept: text/html`, `{"error":"service suspended"}` for `application/json` or API clients, plain text otherwise. Reuse the existing negotiation helper.
3. Return before any replica patch or `last-active` write.
4. Keep the wake interstitial and maintenance branches byte-identical for their cases.

## Files

- `lego/operator/cmd/activator/*_test.go`

## Acceptance criteria

- [ ] For a suspended App, HTML, JSON and no-`Accept` requests each get a `503` with a bex body in the matching content type and a `Retry-After` header.
- [ ] No replica patch and no `app.bex.co/last-active` write happens for a suspended App.
- [ ] The sleeping-service interstitial and the maintenance response are unchanged.

- Localising the page beyond what the existing interstitial does.
