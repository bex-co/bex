## Objective

Enforce the t002 matrix at the auth gate: a token's normalized scopes resolve to a set of allowed operation classes, and an operation outside that set is refused with one consistent Render-dialect 403 on REST, GraphQL, and MCP.

## Context

Round 14's check lives in `lego/backend/internal/api/auth.go`: introspection decodes `scope` and requires the single capability scope (`BEX_OAUTH_API_SCOPE`, default `bex.api`; see auth.go ~lines 76/231 and `server.go` `OAuthAPIScope` ~line 148) on API-audience human tokens, with exemptions for `client_credentials` API keys and `bex.co/platform-client`-marked clients (`platformClientMarker`, auth.go ~line 226; `IsPlatformClient` resolver ~line 248). Regression tests are in `lego/backend/internal/api/r14_scope_test.go`. This task extends that boolean into a class set carried on the request identity, checked per-operation against the t002 table — the refusal is authorization-shaped (403), distinct from round 14's introspection-inactive 401.

## Steps

1. Extend the introspection path in `auth.go` to normalize scopes into a class set on the caller identity: `bex.api` ⇒ all classes; granular scopes ⇒ their classes; ADR069's exempt shapes (API keys, platform-marked clients, audience-less device flow) ⇒ all classes, byte-identically as today.
2. Check the class set at each surface's dispatch seam against the t002 matrix: REST (route lookup pre-handler), GraphQL (per top-level field), MCP (per tool call). Prefer one shared checker consumed by three thin adapters (ADR006's one-core rule).
3. Refuse with a single coded 403 (e.g. `INSUFFICIENT_SCOPE`) rendered in the Render REST error dialect, the GraphQL error convention, and the MCP tool-error convention — same code and message shape everywhere (verified in t006/t008).
4. Preserve round 14 exactly: tokens lacking the capability scope still introspect inactive (401) before any class logic; `r14_scope_test.go` must pass unmodified.
5. Run `cd lego/backend && go test ./internal/api/...` and `make lint-backend` (from `lego/operator/`).

## Acceptance criteria

- A read-only-scoped token performs reads on all three surfaces and receives the coded 403 on any write/mint operation.
- `bex.api` tokens, API keys, platform-marked clients, and audience-less device-flow tokens behave byte-identically to before.
- Existing round-14 tests pass without edits.
