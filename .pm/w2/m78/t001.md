## Objective

Decide and document the operation-level scope vocabulary before any code changes: the scope names, the operation classes they map to, how `bex.api` remains the implies-all umbrella, and exactly which caller shapes stay exempt.

## Context

ADR069 finding 1 (round 14) shipped the coarse `bex.api` capability scope — one scope, all-or-nothing. Its recorded follow-up (`docs/ADR069-security-review-round14.md` line 114) defers "per-capability scopes across REST/GraphQL/MCP, plus authorization-decision audit carrying client id, subject, audience, and normalized scopes" to the board. ADR012 §7 ("Scope discipline", ~line 141) documents the current single-scope rule and its three enforcement points (introspection, consent, discovery). The round-7 credential-class gate (`AuthorizeMintClass`, `lego/backend/internal/core/identity.go` + `base.go`, used by `apikeys`/`sshkeys`/`deploys` mint verbs) already partitions credential-mint operations from ordinary writes — the mint scope class should ride that existing boundary, not invent a parallel one.

## Steps

1. Read ADR012 §7's round-14 scope-discipline block and `lego/backend/internal/api/auth.go` (scope check ~line 76, vocabulary ~line 231) plus `server.go`'s `OAuthAPIScope` wiring to fix the existing invariants.
2. Draft the vocabulary (suggested shape: `bex.api` = all; `bex.api.read`; `bex.api.write`; `bex.api.mint` aligned with the `AuthorizeMintClass` class) and the implies-all lattice.
3. Specify unchanged exemptions: `client_credentials` API keys, `bex.co/platform-client`-marked clients, and the audience-less device flow (the w1/m67 F1 rule) — enumerate them explicitly in the amendment.
4. Specify the refusal contract: 403 in Render dialect, one shape across REST/GraphQL/MCP; and that `BEX_OAUTH_API_SCOPE` / dashboard `OAUTH_API_SCOPE` defaults are NOT re-armed or renamed.
5. Amend ADR012 §7 (or an addendum section) with the vocabulary, lattice, exemptions, and the audit-record fields (client id, subject, audience, normalized scopes).
