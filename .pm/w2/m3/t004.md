## Objective

Let an agent spawn and use a sandbox natively over MCP, and prove the full spawn → run → hibernate → resume loop.

## Context

- The MCP adapter exists from w2/m1/t001; the sandbox service + idle-hibernate from t001/t003.
- Goal: agents get an execution environment as one MCP action.

## Steps

1. Register an MCP `sandbox` tool (spawn + exec/connect) over the sandbox service.
2. Acceptance: agent spawns a sandbox, runs a command, lets it idle to hibernation, then resumes on the next call.

## Files

- `lego/backend/internal/<sandbox feature>/mcp.go` — `spawn_sandbox` / `sandbox_exec` tool fragments on the existing bex-api MCP server (per-feature adapter pattern, docs/sandboxes.md D3)

## Acceptance criteria

- [ ] Via MCP, an agent spawns a sandbox, executes in it, sees it auto-hibernate when idle, and resumes it on next use.

## Out of scope

- Multi-sandbox orchestration; persistent sandbox volumes.
