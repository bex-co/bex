## Objective

Replace the pass-through of internal error text in `PreviewBlueprint` with a classifier that maps each failure to one of eight coded reasons, exposed as a `reason` field on `BlueprintPreview` across REST, GraphQL and MCP `preview_blueprint`. The `error` field stays for API clients but carries a human-readable sentence: no `github:` prefix, no `unexpected status NNN`, and no commit SHA.

## Context

- `PreviewBlueprint` turns any `discoverBlueprintFile` error into `BlueprintPreview{Error: err.Error()}`, stripping only a `bad request: ` prefix (`lego/backend/internal/apps/blueprint.go:557-562`).
- Missing file: `GetFileContents` formats `github: file %q not found at ref %q: %w` (`lego/backend/internal/github/client.go:860`); the ref is the commit SHA `discoverBlueprintFile` pinned up front (`blueprint.go:272`).
- Wrong branch or missing repo: `resolveBlueprintCommit` returns the commit lookup's error unwrapped (`github/service.go:1053-1065`); `GetCommit` returns a bare `&APIError{Status}` for any non-200 (`client.go:589-590`); `APIError.Error()` is `github: unexpected status %d`, deliberately body-free per `w6/005` (`client.go:189-195`).
- Path rules: the `approvedBlueprintPath` refusals (`blueprint.go:304-317`) land in the same `Error`, as do implicit discovery with neither file (`:293-294`) and `ErrBlueprintFilenameAmbiguous` (`:288`).
- Reasons to emit: `file_not_found` (with path and branch), `branch_not_found`, `repo_not_found_or_no_access`, `access_denied` (401/403), `rate_limited` (429, retryable), `invalid_path`, `ambiguous_filename`, `unavailable` (other upstream status or transport failure, retryable).
- GitHub answers 404 for a private repo the installation cannot see, so a missing repo and a no-access repo are indistinguishable; they stay one reason.

## Steps

1. Add a `BlueprintPreviewReason` string type with the eight constants, and a `Reason` field (`json:"reason,omitempty"`) on `BlueprintPreview`.
2. Write `classifyBlueprintFetchError(err error, path, branch string) (reason, message)` in `lego/backend/internal/apps/blueprint.go`: `errors.As(*github.APIError)` on status 404 after the commit lookup → `branch_not_found` when the repo resolved but the ref did not, else `repo_not_found_or_no_access`; 401/403 → `access_denied`; 429 → `rate_limited`; a wrapped file-not-found from `GetFileContents` → `file_not_found`; the `approvedBlueprintPath` sentinels → `invalid_path`; `ErrBlueprintFilenameAmbiguous` → `ambiguous_filename`; anything else → `unavailable`. Distinguishing branch-vs-repo 404 may need `resolveBlueprintCommit` to wrap its error with which lookup failed; do that rather than guessing from the message.
3. Have `PreviewBlueprint` call the classifier and set both `Reason` and a human-readable `Error` (for example `Blueprint file "render.yaml" not found on branch "main".`). Never include the pinned SHA.
4. Expose `reason` on GraphQL `BlueprintPreview` and confirm the MCP `preview_blueprint` tool returns the same struct so it inherits the field.

## Acceptance criteria

- [ ] Every failing preview returns a non-empty `reason` from the eight-value set on REST, GraphQL and MCP.
- [ ] No `error` string contains `github:`, `unexpected status`, or a 40-character hex SHA.
- [ ] A 404 on a missing repository and a 404 on a private repository both classify as `repo_not_found_or_no_access`.
- [ ] `found: true` previews are unchanged.
- [ ] `cd lego/backend && go test ./internal/apps/...` is green.
