## Objective

Meaningful tests for what m97 shipped. Every reason must be produced by a concrete upstream failure, and the dashboard must render each reason's own copy.

## Steps

1. **Backend table test** in `lego/backend/internal/apps/` with a fake GitHub fetcher: one row per reason (`file_not_found`, `branch_not_found`, `repo_not_found_or_no_access` for both a missing and a private repo, `access_denied` for 401 and 403, `rate_limited`, `invalid_path` for the extension and the `../` case, `ambiguous_filename`, `unavailable` for a 500 and a transport error). Assert `reason`, assert `error` matches neither `github:` nor a 40-hex SHA, and assert `found` is false.
2. **Sync-path test:** a fetch failure inside `runSync` and inside the auto-sync worker records the classified message, not the raw one.
3. **Dashboard tests** (vitest): one case per reason asserting the rendered title and body, that `invalid_path` renders beside the path field, that Retry appears only for the two retryable reasons, and that a preview with no `reason` falls back to the generic panel.
4. **Control:** the `found: true` and "Blueprint file has errors" paths are unchanged.

## Acceptance criteria

- [ ] Each new backend test is shown failing on the pre-fix code (raw text or missing `reason`).
- [ ] `cd lego/backend && go test ./...` and `yarn typecheck && yarn lint && yarn test` in `dashboard/` are green.
