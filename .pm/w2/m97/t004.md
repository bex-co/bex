## Objective

Confirm the new `reason` field and the human-readable `error` are identical on REST `POST /v1/blueprints/preview`, GraphQL `blueprintPreview`, and MCP `preview_blueprint`, that the dashboard copy matches, and record what Render's own Blueprint review step shows for the same failures. Flag drift instead of silently diverging.

## Steps

1. **Three adapters agree.** Drive the same wrong-branch, missing-repo and bad-path inputs through REST, GraphQL and an in-process MCP client. Assert byte-identical `reason` and `error` for each.
2. **Compare with Render.** On Render's dashboard, start a new Blueprint with a wrong branch, a missing repository, and a non-YAML path. Note the copy Render shows and the date checked. Render's public API has no preview endpoint, so the comparison is dashboard-only.
3. **Record.** Update the Blueprint / `render.yaml` IaC row (~170) of `docs/ADR018-render-parity.md` with the coded-reason preview contract and the combined missing-or-no-access reason and why. File any copy drift as an inbox note rather than changing the reason set.

## Acceptance criteria

- [ ] An adapter-parity test asserts identical `reason` and `error` across REST, GraphQL and MCP for at least three reasons.
- [ ] The Render comparison, with its date, is noted in the m97 README and the ADR018 row is updated.
