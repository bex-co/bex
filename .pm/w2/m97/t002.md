## Objective

Make `/blueprints/new` render a title and body chosen from `reason`, so a wrong branch reads "Branch not found", a missing repo reads "Repository not found, or bex's GitHub app can't access it", an invalid path is shown as a field error rather than "not found", and Retry appears only for `rate_limited` and `unavailable`.

## Context

- `dashboard/src/routes/blueprints.new.tsx:243-253` renders every `!preview.found` under `blueprints.previewNotFoundTitle` ("Blueprint file not found", `features/blueprints/locales/en.ts:121-124`). The body is `preview.error ||` the friendly `previewNotFoundBody` (`:125-129`), a fallback that can never render because the backend always sets `error`.
- The `BlueprintPreview` GraphQL query lives under `dashboard/src/features/blueprints/`; add `reason` to its selection and regenerate types per `dashboard/CLAUDE.md`.
- "Deploy Blueprint" is already correctly `disabled` in every failure case; keep that.

## Steps

1. Add `reason` to the preview query and generated types.
2. Add locale keys (en + zh) for each reason's title and body: `file_not_found` (interpolating path and branch), `branch_not_found`, `repo_not_found_or_no_access`, `access_denied`, `rate_limited`, `invalid_path` (two bodies: extension, clean-relative-path), `ambiguous_filename`, `unavailable`. Remove the dead `previewNotFoundBody` fallback path or wire it as the `file_not_found` body.
3. In `blueprints.new.tsx`, switch on `preview.reason`. Render `invalid_path` as an inline error beside the path field, not in the "not found" panel. Render a Retry button only for `rate_limited` and `unavailable`. Fall back to the generic "not found" panel when `reason` is absent (an older bex-api during a rolling deploy).
4. Never render `preview.error` verbatim in the UI.
