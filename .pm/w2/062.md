# 062 — Hobby workspaces cap service disks at 120 GiB / 8 PVCs; check Render

Why: after w2/061 matched Render on compute, Hobby still has its own disk budget for services (`quotaForPlan`: `requests.storage` 120Gi and 8 PVCs before datastore room), so a Hobby customer who attaches a ninth persistent disk, or a large one, is refused where Render may allow it.

- **Found:** w2/061, 2026-11-01. `lego/backend/internal/store/namespaces.go` (`quotaForPlan`, Hobby case: `storage, pvcs = "120Gi", "8"`); paid is 5Ti / 200.
- **First step:** verify Render's behavior for persistent disks on a Hobby workspace (docs; the user's Render CLI is logged in, and `w2/059` used it for a live check). If Render has no Hobby disk cap, align with the paid budget the same way 061 did for compute (keep the per-GB billing; the CNPG disk-autoscaler ceiling stays separate). If Render has one, record the match in ADR018 and close.
- **Done when:** the Hobby disk budget matches Render's documented or observed behavior, ADR043/ADR018 say so, and a test pins it.

## Progress 2026-11-01 — Render checked; shipped; production check after the deploy

- **Render (docs, 2026-11-01):** "You can attach a persistent disk to a paid Render web service, private service, or background worker"; the page states no per-workspace limit on disk count or total size. "Paid" means a paid instance type, which Hobby workspaces can run (and since `w2/061`, without a compute cap). So Render has no Hobby disk cap.
- **Decision (by the parity rule, consistent with the user's 2026-11-01 choice in 061 to match Render on Hobby limits):** Hobby's disk budget equals paid: `requests.storage` 5Ti + datastore room (6995Gi), PVCs 200 + room (400). Per-GB billing and the 25-service cap bound it.
- **Shipped:** `quotaForPlan` change, tests (`TestHobbyComputeMatchesPaid` now covers storage and PVCs; the room and namespace tables updated), ADR082 D10, ADR043 and ADR018 amended.
- **Next:** after the deploy, check `tenant-quota` in an existing Hobby namespace (`tea-da2isimlm39c739m4ofg`) shows `requests.storage: 6995Gi` and `persistentvolumeclaims: 400`; close together with 061's check.
