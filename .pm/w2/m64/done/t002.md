## Objective

Stop minting the attach ticket inside `Create`/`Steer`'s response path. The ticket binds the exact sandbox pod (ADR047 D9), which no longer exists when the fast create returns — clients must mint it lazily via the existing `AttachTicket` verb once the session is `running`.

## Context

- `withTicket` (`lego/backend/internal/agentsessions/service.go`) currently decorates the `Create`/`Resume`/`Steer` responses; per CLAUDE.md the agent-session ticket's claims bind subject + session + exact sandbox pod + workspace, so a pre-dispatch create cannot carry a valid one.
- `AttachTicket` (`service.go:563`) already exists exactly for "mint a fresh ticket for an already-started session" — make it the single ticket source.
- Check the REST (`rest.go`), GraphQL (`graphql.go`), and MCP (`mcp.go`) adapters for how the ticket/stream URL is projected on create/steer responses; the field should become absent/empty for a not-yet-running session rather than a fabricated value.
- Check how the dashboard consumes the create-time ticket today (`dashboard/src/features/agent-sessions/`) so t004 knows what to switch to `AttachTicket`/`createShellSession`-style lazy minting.

## Steps

1. Remove/conditionalize the `withTicket` call on the fast create path (and on steer once t003 lands); keep it for `AttachTicket` itself.
2. Adjust the three adapter fragments so the ticket field is cleanly optional; verify error shape when attaching to a session whose sandbox isn't up yet (should be a named conflict/retryable, not a 500).
3. Update tests asserting create responses carry a ticket.
