## Objective

Make `agentsessions.Create` return as soon as the session is durably accepted (validation + store row + OpenFGA tuple, `phase: pending`/`creating`), moving the slow `dispatch` chain (`CreateAgentSessionSandbox` → `EnterAgentSessionPhase` → `RecordAgentSessionDispatch`) into a background goroutine so sandbox pod scheduling/image pull no longer sits on the HTTP request path.

## Context

- `lego/backend/internal/agentsessions/service.go:198` — `Create` today: authz → `validateCreate` → `createEgress` → model-key read → `CreateAgentSession` row → `GrantAgentSessionWorkspace` tuple → **`dispatch` (blocking, tens of seconds)** → `withTicket`.
- `dispatch` (`service.go:261`) already owns the rollback semantics: failure → `SetAgentSessionLifecycle(…, PhaseFailed, reason)`; store failure after sandbox-up → best-effort cancel. Keep those semantics intact in the background path.
- All cheap validation (branch/egress/template/prompt, `createEgress`) must stay synchronous — the composer anchors these to form fields (`ERROR_FIELDS` in `new-session-composer.tsx`) and the user must not be navigated away before seeing them.
- The background goroutine must not inherit the HTTP request context's cancellation (`context.WithoutCancel` or equivalent) but must preserve identity/workspace values needed for audit and the store/authz calls.
- Race: `Cancel` (`service.go:415`) can run while dispatch is in flight. The background dispatch must not resurrect a canceled session — re-check/CAS the phase before `RecordAgentSessionDispatch`, and tear the sandbox down if the session was canceled meanwhile.
- Consider whether the model-key OpenBao read stays sync (cheap) or moves async; keep template validation (`unknown agent sandbox template`) sync — it is a named 400 today.

## Steps

1. Extract the synchronous accept path; set an explicit pre-dispatch phase (`pending` or reuse `creating`) on the row at accept time.
2. Move `dispatch` into a supervised goroutine with a detached context; keep its existing failure/rollback semantics.
3. Add the cancel-vs-dispatch phase re-check before recording the dispatch; tear down the sandbox when losing the race.
4. Ensure a bex-api restart mid-dispatch leaves the session in a terminal or recoverable state (at minimum: a stuck `creating` session must be cancelable — verify `Cancel` handles `SandboxID == ""`).
5. Update `service_test.go` fakes to exercise the async path deterministically (injectable dispatch runner or synchronization hook).
