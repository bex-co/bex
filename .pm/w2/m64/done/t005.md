## Objective

Make sending a follow-up message feel instant: the user's steer prompt appears in the conversation immediately, the phase chip reflects `redispatching`, and the background re-dispatch progression (or failure) renders through the same phase treatment t004 built — no frozen composer while the fresh sandbox provisions.

## Context

- `dashboard/src/features/agent-sessions/components/steering-composer.tsx` — today it awaits the full steer round trip.
- Backend after t003 returns fast with `phase: redispatching`; conflicts (`AGENT_SESSION_TURN_IN_FLIGHT`, `AGENT_SESSION_NOT_STEERABLE`) still come back synchronously — on those, the optimistic message must be rolled back/marked failed-to-send, not silently kept.
- The optimistic entry should reconcile with the durable transcript once the new turn's stream attaches (avoid a duplicate user bubble).
- Strings through `useTranslations()` (`agentSessions.*`).

## Steps

1. Optimistically append the steer prompt to the conversation on submit; clear the input immediately.
2. On sync rejection, remove/mark the optimistic entry and surface the coded error (existing i18n error mapping).
3. Show `redispatching` via the t004 provisioning treatment; on `failed`, the reason + retry surface applies.
4. Deduplicate the optimistic entry against the replayed transcript/live stream.
5. Component tests for optimistic append, sync-rejection rollback, and dedup.
