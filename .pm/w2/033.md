# Disk-snapshot Secrets don't reach new tenant namespaces (no projection) nor the bootstrap apps namespace

Why: `scripts/disk-snapshot-secret.sh install` copies `bex-disk-snapshot` + `bex-disk-snapshot-age` into namespaces matching `tea-*` **at run time** — a workspace namespace created afterwards gets neither, so its first disk-bearing App's backup Job dies in `CreateContainerConfigError` and restore is impossible until an operator re-runs the script; the bootstrap apps namespace (`default`, where hand-applied Apps land) is never covered at all (w2/m86 hand-copied them there).

- The KeyValue pipeline solved this with `BackupSourceNamespace` projection; disks deliberately have none (recorded in the script's comments). Options: operator-side projection of the two Secrets into workspace namespaces at namespace-provision time (the ADR043 `quotaForPlan` seam already touches every new namespace), or fold the copy into bex-api's workspace-namespace creation.
- Until fixed, the runbook should at least say "re-run install after new workspaces appear".
