## Objective

Prove the whole milestone on the local CAPD mock cluster: two Apps with the same name in different workspaces coexist end to end (build → push → pull → serve for a web service; publish → serve for a static site) on disjoint workspace-scoped Zot repos and S3 prefixes; a pre-existing legacy bare-name App keeps working untouched through dual-read; then the t004 migration tool moves the legacy App and it keeps working on the new scheme.

## Context

- Cluster: `bash scripts/mock-cluster.sh` (kubeconfig `infra/local/bex.kubeconfig` — never commit/print); build-from-git prerequisites per memory note "Mock-cluster build-from-git" (Zot NodePort, `bex-builds` privileged PSA, node containerd certs.d insecure-registry config).
- App tooling: `scripts/app-apply.sh <bex.yml>` (`DRY_RUN=1` to preview), `scripts/deploy-sample.sh`, `examples/hello-go/` (build-from-git), `examples/whoami-app.yaml`; status via `kubectl get apps.app.bex.co`.
- Workspace identity is the `app.bex.co/workspace` label (`lego/operator/internal/controller/app_controller.go:137`) — hand-label the two same-named App CRs with distinct `tea-…` ids (mint-style per docs/ADR020-identifiers.md); the legacy App carries no label.
- Registry secrets bootstrap: `scripts/registry-secrets.sh` (BEX_REGISTRY_NS/`zot-htpasswd`/`zot-config`); static env: `BEX_STATIC_S3_*`, `BEX_STATIC_SERVER_SERVICE` (docs/ADR029-static-sites.md).
- This is dev-2's shared-cluster world — see `.pm/w2/README.md` Local dev environment (never the shared default ports/namespaces).

## Steps

1. Bring up/refresh the mock cluster with the m75 operator image (`make docker-build` + `make deploy` from `lego/operator/`, or `make install && BEX_RUNTIME=kubernetes make run`).
2. Create the legacy App FIRST on the pre-m75 scheme (or with the label absent), verify it serves.
3. Apply two same-named Apps labeled with different workspace ids; verify: distinct Zot repos + `reg-pull-*` Secrets + htpasswd users (inspect `zot-config`/`zot-htpasswd` in `BEX_REGISTRY_NS`), both reach Ready and serve; repeat for two same-named `static_site` Apps (distinct S3 prefixes, both serve).
4. Verify the legacy App still serves (dual-read) after the operator upgrade.
5. Run the t004 tool against the legacy App (dry-run, then real); verify digests/objects, tombstone, and continued serving on the new scheme.
6. Record the evidence (commands + observed names) in this task file.
