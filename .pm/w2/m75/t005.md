## Objective

Make every registry-side lifecycle mechanism scheme-aware: the Zot per-repo retention policy matches workspace-scoped repos, the App finalizer's tag purge and `RevokeCreds` target whichever repo/user the App actually used, the `checkOwnedArtifact` ownership gates cover the new-scheme mirror/Secret names, and the repo-naming helper exposes the derivation w7/m86 will use so its `-cache` repos are born workspace-scoped.

## Context

- Retention: `defaultRetentionCount = 5` / `BEX_ZOT_RETENTION_COUNT` writes `mostRecentlyPushedCount` per-repo policies into the `zot-config` Secret — `lego/operator/internal/registry/zotconfig.go` (policy plumbing at `setZotRepoPolicy`, line 162; repo maps `zotRepos`/`zotReposFor`, lines 103-110); repo-name patterns must match the new `<tea-id>/<app>`-style paths (Zot retention policies glob on repository paths).
- Purge/revoke: `RevokeCreds` (`lego/operator/internal/registry/creds.go:154`) and `removeZotConfigEntry` (line 410) are name-keyed — ADR067 explicitly notes "`RevokeCreds(app.Name)` and the Zot repo purge stay name-keyed inside the F3 deferral" (docs/ADR067-security-review-round12.md:44). Deletion-side tests: `lego/operator/internal/controller/registry_cleanup_test.go`, `app_deletion_test.go`.
- Ownership gates: `checkOwnedArtifact` (`lego/operator/internal/controller/build_registry_secret.go:129`) guards `bld-<name>-registry-auth` + the `reg-pull-<name>` build-ns mirror (ADR067 finding 1's four fixed gaps; `m71_build_secret_ownership_test.go`) — extend coverage to the new-scheme names.
- w7/m86 (ADR060 D3) will mint `-cache` repos exempt from image retention; the naming helper from t002 must expose a documented `CacheRepo(...)`-style derivation (or equivalent) so m86 consumes it instead of bare names.

## Steps

1. Route retention-policy writes, `RevokeCreds`, and the finalizer's repo purge through the t002 scheme helper, resolving legacy vs new per App (dual-read parity with the credential path).
2. Extend `checkOwnedArtifact`-guarded call sites and tests to the new-scheme Secret/mirror names.
3. Add the cache-repo naming derivation + a unit test pinning its format; note it in the t001 design section.
4. `make test` + `make lint` from `lego/operator/`.

- [ ] Cache-repo naming helper exists with a pinned-format test
