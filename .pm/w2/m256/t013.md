## Objective

Three residuals on a planned Blueprint's dashboard page, seen live after t012 shipped (2026-11-03 15:43 UTC, pin `4bde8fa7577f`). The first is a regression of `w4/120` on the new create path.

## Context

Probe: `POST /v1/blueprints` (Render body) for `https://github.com/render-examples/express-hello-world@main` in QA workspace `tea-daif693dqjvc73e7as3g`. The same repo+branch had been connected and deleted earlier the same day (12:44 UTC).

1. **Revived row without the reconnection note (regression of `w4/120`).**
   - The create returned the **same id** as the Blueprint deleted at 12:44, `blp-dbd9mq1ml1cs73dkbfb0`.
   - Its Sync History showed the earlier connection's rows as if they were this Blueprint's: `039c3477 Error 2h … superseded: the Blueprint was reconnected`, `039c3477 Error 3h …`, and `039c3477 Success 11d 11d —`.
   - The new row (`Queued 1m — —`) carried no note.
   - Cause:
     - `store.CreatePlannedBlueprint` (`lego/backend/internal/store/blueprint_plans.go:54`, `ON CONFLICT (tenant_id, repo, branch) DO UPDATE … WHERE blueprints.status = 'disconnected'`) revives the disconnected row with its history.
     - Its caller `apps.CreatePlannedBlueprint` (`lego/backend/internal/apps/blueprint_onboarding.go:209`) never writes the boundary note.
     - The legacy create writes that note at `lego/backend/internal/apps/blueprint.go:1213-1224`: "re-established a previously disconnected connection to <repo>@<branch>; earlier sync history below belongs to that connection".
   - Target: the planned path reports whether it revived a row, as `AdmitBlueprintCreate` does (`blueprint.go:1192`), and sets the same note on the planned sync. The dashboard then shows it in that row's Details, as for the legacy path.
2. **Status chip says `Queued`.**
   - The header chip and the newest Sync History row read `Queued` while the API reports the sync `state:"created"` and the page says it awaits approval.
   - Label source: `dashboard/src/features/blueprints/locales/en.ts:856` (`message: "Queued"`).
   - Target: a planned, unapproved sync reads "Awaiting approval" or similar, distinct from a queued run. Check what Render's dashboard labels it.
3. **Empty-state copy points at the refused action.**
   - Managed Resources says "No resources yet — sync the Blueprint to apply your render.yaml." (`locales/en.ts:580`), but syncing is now refused (`BLUEPRINT_AWAITING_APPROVAL`).
   - Target: when the Blueprint is `created`, the copy says to approve the planned sync.
