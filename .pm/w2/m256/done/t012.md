## Objective

A Blueprint created through Render's plan-then-approve flow (`status: created`, a planned sync waiting) must be approvable from the dashboard page that the API's `dashboardUrl` links to. Today that page offers only the legacy **Sync** button. The backend's manual sync path does not refuse `created`, so that button would apply the Blueprint at once: no plan review, and the plan's `requiredManualEnvVars` are skipped.

## Context

Live probe, `/qa-find-bugs w4` loop, 2026-11-03 12:44 UTC, pin `549af492873d`, QA workspace `tea-daif693dqjvc73e7as3g`. Blueprint `blp-dbd9mq1ml1cs73dkbfb0` was deleted afterwards (`GET` 404). Nothing was applied.

- **Create (works):**
  - `POST /v1/blueprints` with `{"name":"qa-20261103-bp","ownerId":…,"source":{"repo":"https://github.com/render-examples/express-hello-world","branch":"main"},"autoSync":false}` returned 201 in 1.6 s.
  - The response had `status:"created"`, `planningOutcome:"planned"`, `notices:[]` and sync `bsr-dbkte87v44os73fk000g` with `state:"created"`.
  - `rawPlan` was `{"actions":[{"operation":"create","kind":"service","name":"express-hello-world","sourcePath":"#/services/0"}]}`, `requiredManualEnvVars:[]`, and `dashboardUrl:"https://dashboard.bex.co/blueprints/blp-dbd9mq1ml1cs73dkbfb0"`.
  - 20 s later, `GET /v1/services?name=express-hello-world` returned 0 services, so nothing was applied. `GET /v1/blueprints/{id}` returned `status:"created"`, `lastSync:null`.
- **Re-plan (works):** `POST /v1/blueprints/{id}/syncs` returned 201 with a new planned sync `bsr-dbktegcs5ghs73bphs30` at the same commit and the same plan.
- **Dashboard page (the gap):** `GET https://dashboard.bex.co/blueprints/blp-dbd9mq1ml1cs73dkbfb0` returned 200 (184 KB SSR).
  - It renders the Blueprint name and `express-hello-world`, plus `Created`, `Last synced`, `Sync History` and `Sync`.
  - The word "Approve" does not appear anywhere in the page.
  - `grep -rln approveBlueprint dashboard/src` matches only `dashboard/src/graphql/schema-types.ts` (generated types). No component calls `approveBlueprint` or `planBlueprintSync`.
- **Backend:**
  - The dashboard Sync button calls GraphQL `syncBlueprint` → `apps.(*Service).SyncBlueprint` (`lego/backend/internal/apps/blueprint.go:1340`) → `runSync`.
  - Nothing on that path refuses `store.BlueprintStatusCreated`. The only `created` guard is the auto-sync path (`lego/backend/internal/store/blueprint_lifecycle.go:171`).
  - `confirm` only gates takeovers and destructive changes (`blueprint.go:229-237`), so a plain create applies without it.
  - **Unverified live:** I did not click Sync, because it would have created an un-prefixed `express-hello-world` service. The apply-at-once claim comes from the code path above.
  - Aliases of the same manual path: REST `POST /v1/blueprints/{id}/sync`, GraphQL `syncBlueprint`, and the MCP sync tool.

## Steps

1. Blueprint detail page (`dashboard/src/features/blueprints/`): when `status === "created"`, show the newest planned sync's `rawPlan` actions, a field per `requiredManualEnvVars` entry, and an **Approve** button that calls `approveBlueprint` with `manualEnvVars`. Keep the plan visible until it is approved.
2. Hide or disable the legacy **Sync** button while the Blueprint is `created`, or point it at `planBlueprintSync` (re-plan). It must never apply.
3. Backend: make the manual sync path (`SyncBlueprint`, and through it REST `/sync`, GraphQL `syncBlueprint` and the MCP sync tool) refuse a `created` Blueprint by name, for example `BLUEPRINT_AWAITING_APPROVAL`, pointing at approve. This way no client can skip the plan and its required manual env vars.
4. Check render.com's dashboard for a Blueprint created through `render ea blueprints create`, and record whether it shows the plan and an approve control. Note any divergence in ADR018.
5. Skeleton rule: the pending state of the new plan panel must match its ready geometry (repo rule).
