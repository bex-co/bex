## Objective

Implement ADR054 D1+D2: an SSH username of the form `ags-<xid>` resolves — at handshake time, under the SSH-key identity — to the session's sandbox pod, gated on `can_view_sensitive`.

## Context

- Seam: `sshgateway.TargetResolver` (`lego/backend/internal/sshgateway/resolver.go`) — single method, wired in `cmd/ssh-gateway/main.go` as `apps.Service` today; called from `VerifiedPublicKeyCallback` (`nativessh/server.go`).
- New branch: dispatch on `ids.KindOf` of the first two hyphen segments — `srv-…` → existing `apps.Service.ResolveSSHSession` unchanged; `ags-…` → new agent-session resolver; else `ErrBadRequest` after the authorize attempt (403-before-400/404).
- Agent-session resolver: `AuthorizeOn(core.RelCanViewSensitive, "agent_session:"+id)` under the ssh identity → `GetAgentSession` → require phase ∈ {creating, running, resuming, redispatching} and `sandbox_id != ''` → `SSHInstanceTarget{Namespace: <workspaceID>-sandbox, PodName: <sandboxID>-0, Container: "sandbox"}` — the identical derivation `agentsessions/service.go` `withTicket` uses. Instance suffixes (`ags-…-x`) rejected.
- Gateway already has DB store + OpenFGA checker + k8s client wired (`cmd/ssh-gateway/main.go`).

## Steps

1. Add the composite dispatcher (new type in `internal/sshgateway` or `cmd/ssh-gateway`) and the agent-session resolver (in `internal/agentsessions`, mirroring `apps.ResolveSSHSession`'s shape: authorize → fetch → gate → derive).
2. Wire it in `cmd/ssh-gateway/main.go`; `srv-…` path byte-identical.
3. Audit rows: the existing `ssn-…` write carries the `ags-…` id in the service-id column — confirm, don't extend the schema.
4. Unit tests: contributor denied; developer allowed; each dead phase refused; empty `sandbox_id` refused; instance suffix refused; malformed id gets 403-before-400 ordering.
