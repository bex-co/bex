## Objective

Implement ADR054 D6: a finished agent turn must not kill a live editor — before tearing down a finalized session's sandbox, the Completer defers while an open `ssh_sessions` row targets that `ags-…` id.

## Context

- `lego/backend/internal/agentsessions/completion.go`: 15s loop; on driver `succeeded`/`failed` it finalizes then `teardown` → transcript capture (ADR051) → `CancelAgentSessionSandbox`.
- Deferral affects **teardown only**: the session still finalizes, transcript still captured, delivery still happens; `sandbox_id` cleared when teardown eventually runs.
- Guards: rows with `started_at` older than `BEX_SSH_SESSION_TIMEOUT` (4h) are ignored (crashed-gateway stale rows can't pin a sandbox); explicit `Cancel` overrides deferral and reclaims immediately.
- The gateway writes/closes `ssn-…` rows in `store/sshsessions.go`; bex-api's store needs a query for "open rows whose service-id column equals this ags id and started_at within the window".

## Steps

1. Add the store query (open `ssh_sessions` rows by target id + freshness window).
2. In the Completer's teardown path: finalize as today; skip `CancelAgentSessionSandbox` while a fresh open row exists; re-check each tick; Cancel path bypasses.
3. Tests: open row defers teardown while finalizing status/transcript normally; closed row → immediate teardown; stale open row (older than timeout) → teardown proceeds; Cancel tears down despite an open row.

## Files

- `lego/backend/internal/store/sshsessions.go`

## Acceptance criteria

- [ ] All four test scenarios pass; metering keeps accruing during deferral (no metering change — assert nothing stops).

## Out of scope

- Any keep-alive channel or sandbox TTL product; the 4h cap is the ceiling.
