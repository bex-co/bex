## Objective

Create the `/build-sources/$buildSourceId` layout route with a consistent detail header, tab navigation (`Builds`, `Services`, `Environment` [git only], `Settings`), not-found redirect to `/build-sources`, and breakpoint-matched pending skeletons at `1440px` and `390px`.

## Context

- Follow existing detail-layout patterns (`dashboard/src/routes/services.$serviceId.tsx` and `sandbox-groups.$sandboxGroupId.tsx`).
- Build Source data comes from `useBuildSource(buildSourceId)` created in `w2/m613/t001`.
- Image-backed Build Sources have no build-time environment and cannot trigger builds (`POST …/builds` is git-only on Render).
- Update `/build-sources` list row links and `/build-sources/new` post-create navigation from `w2/m613` to point directly to `/build-sources/$buildSourceId`.

## Steps

1. Create `dashboard/src/routes/build-sources.$buildSourceId.tsx` layout route with:
   - Breadcrumb back to `/build-sources`, Build Source name, kind badge (`Git` / `Docker image`), region badge, repo+branch / image subtitle, and primary **Trigger Build** button (visible for git sources, role-gated on `can_create`).
   - Tab navigation: `Builds` (index), `Services`, `Environment` (git sources only), `Settings`.
   - `useNotFoundRedirect` to `/build-sources` on unknown ID and `ResourceLoadError` on auth/network error.
2. Create breakpoint-matched pending skeletons (`1440px` and `390px`) registered in the dashboard's route-skeleton manifest.
3. Wire list row links on `/build-sources`, `⌘K` search navigation, Project Overview links, and `/build-sources/new` redirect to `/build-sources/$buildSourceId`.
