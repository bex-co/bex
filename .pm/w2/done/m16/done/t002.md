## Objective

Wire t001's `SetPlan` verb onto all three API surfaces for managed Postgres.

## Context

- `lego/backend/internal/postgres/rest.go` — no `PATCH` route exists today; add one alongside the existing `GET`/`POST`/`DELETE`/lifecycle routes.
- `lego/backend/internal/postgres/graphql.go`, `mcp.go` — mirror the REST verb.
- Follow the App `PATCH /v1/services/{id}` `serviceDetails.plan` body shape for REST field naming consistency.

## Steps

1. REST: `PATCH /v1/postgres/{id}` accepting `{"plan": "..."}`, calling `Service.SetPlan`, returning the updated instance view.
2. GraphQL: `updateDatabasePlan(id: ID!, plan: String!): Database` mutation.
3. MCP: `update_postgres_plan` tool (`id`, `plan` args).
4. Confirm all three return the same error shape on an unknown plan (`ErrBadRequest` → REST 400 / GraphQL error / MCP error).

## Files

- `lego/backend/internal/postgres/rest.go`
- `lego/backend/internal/postgres/graphql.go`
- `lego/backend/internal/postgres/mcp.go`

## Acceptance criteria

- [ ] `PATCH /v1/postgres/{id}` with `{"plan":"standard"}` returns 200 and the updated plan.
- [ ] GraphQL `updateDatabasePlan` and MCP `update_postgres_plan` both call the same `SetPlan` verb and return consistent results.
- [ ] An unknown plan is a 400/GraphQL-error/MCP-error on all three, not a 500.
