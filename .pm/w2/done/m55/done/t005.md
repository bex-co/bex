## Objective

Add Render's "Select an instance" picker above the terminal, wired to the existing instances surface. Selecting an instance targets that specific replica for the exec session; the default (no explicit pick) targets a random Ready replica, matching Render and m39.

## Context

- Render's Web Shell has a "Select an instance" dropdown (captured live: `Instance xc8cn`). The list comes from `GET /v1/services/{id}/instances`, which already exists and returns Render's `{id, createdAt}` array (m39 t004 + the broader instances surface). Public instance ids are `srv-…-<opaque-suffix>`.
- Gateway targeting (t003 / m39 `ResolveSSHSession`): a bare service id picks a random Ready replica; a specific `srv-…-<pod-uid>` id selects exactly that pod (still gated Ready/current-image/current-revision/non-terminating).
- The exec ticket (t002) is service-scoped; the specific instance id is passed to the gateway WS as the target, re-validated server-side.

## Steps

1. Fetch the instances list for the service (reuse any existing dashboard query for instances, or add one over `GET /v1/services/{id}/instances`).
2. Render a picker above the terminal; default selection = "any Ready instance" (bare target). Show instance id + created-at like Render.
3. On selection, (re)open the exec session against the chosen instance id (new ticket if the design makes tickets single-use/instance-bound; otherwise pass the instance id on WS connect). Server re-checks the target.
4. Handle the single-instance case (picker disabled/auto-selected, as Render does) and the empty/no-Ready case (clear message, no terminal).

## Files

- `dashboard/src/features/services/components/service-shell-page.tsx` / `web-shell-terminal.tsx`
- dashboard instances hook/query (new or reused)

## Acceptance criteria

- [ ] The picker lists the service's current instances (Render `{id, createdAt}` shape) and reflects the selected one.
- [ ] Selecting an instance attaches the terminal to that specific replica; the default attaches to a random Ready replica.
- [ ] Single-instance and no-Ready-instance cases are handled without a broken terminal.
- [ ] The selected instance id is re-validated server-side (no client-trusted targeting).

## Out of scope

- Reconnect-on-close and cap messaging (t006).
