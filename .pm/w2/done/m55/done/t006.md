## Objective

Make the browser session behave like Render's under every close and limit condition: surface redeploy/restart/timeout closures clearly, respect the gateway's global/per-identity session caps with a useful "too many sessions" message, and offer a clean reconnect that re-mints a ticket rather than silently reusing a dead stream.

## Context

- Gateway bounds (m39): `MaxSessions` (default 100) and `MaxSessionsPerIdentity` (default 5); handshake and 4h session timeouts. Browser sessions must count against these (t003).
- Close causes (m39 exec bridge): client disconnect, gateway shutdown, session timeout, redeploy, restart, pod deletion — each cancels the stream.
- Ticket lifecycle (t002): short TTL + single-use ⇒ a reconnect needs a fresh ticket.
- The terminal component (t004) already renders a "closed" state; this task makes the reasons specific and the reconnect real.

## Steps

1. Map gateway close codes/reasons to specific dashboard messages: "session closed by redeploy/restart", "session timed out", "instance no longer available", "session limit reached (N per user)".
2. Add a "Reconnect" affordance that re-mints a ticket (t002) and reopens the WS (t003) against the same or re-picked instance; guard against duplicate/leaked sockets.
3. When the per-identity cap is hit, show the limit and how to free a session (close other shells) rather than a generic error.
4. Ensure navigation away, tab close, and unmount reliably close the WS so caps aren't exhausted by zombie sessions.

## Files

- `dashboard/src/features/services/components/web-shell-terminal.tsx` / `service-shell-page.tsx`
- dashboard ticket/WS hook (close-reason handling, reconnect)

## Acceptance criteria

- [ ] Redeploy, restart, timeout, and pod-deletion closures each show a specific, correct message.
- [ ] Hitting the per-identity cap shows a clear limit message; reconnect works after freeing a session.
- [ ] Reconnect re-mints a ticket and reopens cleanly with no leaked/duplicate sockets.
- [ ] Leaving the page reliably releases the gateway session.

## Out of scope

- Changing the gateway cap defaults (they carry over from m39).
