## Objective

Add an authenticated **WebSocket exec endpoint** to the isolated ssh-gateway. It validates the exec ticket (t002), resolves the target instance, and bridges the browser terminal stream to `KubeExecutor.Execute` — reusing every m39 guard (targeting, session caps, content-free audit). The powerful `pods/exec` permission stays confined to the gateway ServiceAccount.

## Context

- The gateway already has the exec mechanism: `lego/backend/internal/sshgateway/exec.go` (`KubeExecutor.Execute` → client-go SPDY `remotecommand`), `apps.ResolveSSHSession(username)` for Render-compatible targeting + `AuthorizeApp(can_operate)`, session caps (`MaxSessions`/`MaxPerIdentity`), and `ssh_sessions` audit (start/end, content-free). Reuse all of it.
- Today the gateway listens only for SSH on `:2222` (`cmd/ssh-gateway/main.go`) plus an internal metrics/health HTTP listener on `:9090`. There is **no** WebSocket path. The new WS listener is a distinct, browser-facing surface — decide its address/entrypoint and Traefik exposure per t001 (it needs a TLS HTTP entrypoint, unlike raw TCP/22).
- The dashboard is same-origin behind Traefik; the WS must be reachable from the browser and CORS/Origin-checked.
- Precedent for WS in the codebase: the logs live-tail (`lego/backend/internal/logs/rest.go`) already uses a WebSocket — reuse its library/patterns for consistency.

## Steps

1. Add a WS handler to the gateway (new listener or an added route on a browser-facing HTTP server). On upgrade: read the ticket (query param or subprotocol), validate it with the t002 verify helper (integrity, TTL, single-use, subject/service/workspace scope), and reject closed on any failure.
2. Resolve the target via `ResolveSSHSession` using the ticket's service id (bare = random Ready replica) or a client-supplied instance id (specific `srv-…-<pod-uid>`), re-checking `can_operate`. Keep the m39 fail-closed matrix (non-Ready/stale-image/stale-revision/terminating denied).
3. Enforce session caps (global + per-identity) counting browser sessions alongside SSH sessions. Open one exec stream per WS; reject multiplexing.
4. Bridge stdin/stdout/stderr and terminal resize between the WS (xterm.js protocol: data frames + a resize control message) and `KubeExecutor.Execute` (TTY + `TerminalSizeQueue`). Propagate exec exit; close the stream on client disconnect, redeploy/restart, pod deletion, or session timeout.
5. Write the `ssh_sessions` audit row (start/end/result) exactly as SSH sessions do — **no** command/stream/terminal-content field.
6. Confirm the gateway ServiceAccount RBAC is unchanged (namespaced App/pod read + `pods/exec` create only); WS ingress restricted appropriately; metrics stay bounded (no subjects/ids/content).

## Acceptance criteria

- [ ] A valid ticket opens a WS exec stream to a Ready instance; an invalid/expired/reused/foreign ticket is rejected with no exec.
- [ ] Targeting matches m39 (bare = random Ready replica; specific instance id honored; non-Ready/stale/terminating fail closed).
- [ ] Session caps count browser sessions; one exec stream per WS; resize + exit + disconnect/redeploy/restart/timeout all handled.
- [ ] `ssh_sessions` audit row written with no terminal-content field; gateway RBAC and metrics unchanged in scope; bex-api still has no `pods/exec`.
