## Objective

Verify `logSvc.DeployProgress` in `lego/backend/internal/api/server.go:1017` and `logs/progress.go` narration so Build Source carrier builds narrate clean build-only phases (cloning/building/pushing/succeeded/failed) without emitting runtime rollout, live-URL, or port-scan lines.

## Context

- `lego/backend/internal/api/server.go:1017-1050` queries `ds.ListDeploys(ctx, resource, ...)` and `BuiltDeployIDs(ctx, resource, ...)`, which read `deploys` rows by `app_id` (`bds-…`).
- A Build Source carrier never creates a Deployment, Service, Ingress, or HTTP port scan (`ADR097 §Decision 1`), so its terminal success is a built image (`live` carrier row), not a live serving URL.

## Steps

1. Inspect `logs/progress.go` narration rules for `DeployProgress` rows when the target is a Build Source carrier (`bds-…`).
2. Ensure carrier narration emits accurate build-lifecycle lines (`type=build`, `build=bld-…`) and suppresses runtime-only phrasing (e.g., "Your service is live", port detection, rollout announcements).
3. Verify `server.go:1017` `DeployProgress` and `BuiltDeployIDs` work end-to-end when `resource` is a `bds-…` ID.

## Files

- `lego/backend/internal/logs/progress.go`
- `lego/backend/internal/api/server.go`

## Acceptance criteria

- [x] Build Source carrier progress narration accurately reports build start, completion, and failure with `type=build` and `build=bld-…`.
- [x] No runtime rollout, port-scan, or live-URL narration lines are emitted for Build Source carriers.

## Out of scope

- Runtime deploy logs of linked services (they already run through normal `srv-…` deploy logging).
