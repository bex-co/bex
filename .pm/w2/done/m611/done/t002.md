## Objective

Translate Build Source carrier deploy IDs (`dep-…`) to public build IDs (`bld-…`) when indexing build Jobs, filtering by `build=bld-…`, emitting `LabelBuild` on build pod and narration lines, and returning `label=build` values.

## Context

- `lego/backend/internal/logs/build_filter.go:47-61` (`newBuildIndex`) stores `index[job] = d.ID` (`dep-…`).
- `lego/backend/internal/logs/progress.go:395` stamps `LabelBuild: d.ID` (`dep-…`) on platform narration entries.
- Per `docs/ADR097-build-sources.md`, a Build Source carrier's public build ID is `id.Rekind(ids.Build, d.ID)` (`bld-…`), reversible back to `dep-…` via `id.Rekind(ids.Deploy, buildID)`.

## Steps

1. Update `newBuildIndex` (and its callers in `logs/service.go`) to know whether the target App is a Build Source (`core.IsBuildSource(app)` or `ids.KindOf(resource) == ids.BuildSource`).
2. For Build Source carriers, key `buildIndex` values and `progressEntry` `LabelBuild` on `id.Rekind(ids.Build, d.ID)` (`bld-…`) instead of `dep-…`.
3. Update `build` query filtering (`narrowToBuilds` / `jobsOf` / live-tail filter / `label=build` values) so `build=bld-…` matches both build Job pod lines and carrier platform narration lines.
4. Keep ordinary service build logs (`srv-…`) unchanged (`dep-…`) so existing service build filter behavior does not regress.

- `lego/backend/internal/logs/build_filter.go`
