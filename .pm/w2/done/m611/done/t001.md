## Objective

Update `lego/backend/internal/logs/service.go` so callers naming an explicit Build Source ID (`bds-…`) are authorized via `core.WithBuildSources(ctx)` under `core.RelCanViewLogs` across log history, label values, and SSE/WebSocket live tail, while unscoped workspace/project enumerations keep carriers excluded.

## Context

- `lego/backend/internal/logs/service.go` calls `s.AuthorizeApp(ctx, core.RelCanViewLogs, requested)` at lines ~760, 982, 1025, 1386, 1548 and `AuthorizeAppFresh` at ~2380 without `core.WithBuildSources(ctx)`.
- `lego/backend/internal/core/build_source.go:79` rejects `IsBuildSource(app)` as `ErrNotFound` unless `core.WithBuildSources(ctx)` is set.
- `TestEveryAppEnumerationDeclaresBuildSources` guards any `AppList` reads in `logs/`.

## Steps

1. Inspect every resource resolution and authorization call in `lego/backend/internal/logs/service.go` (history, label values, live tail, fresh auth checks).
2. Add a small helper (e.g. `logResourceCtx(ctx, id)`) that applies `core.WithBuildSources(ctx)` when `ids.KindOf(id)` is `ids.BuildSource` (or when an explicit `bds-…` resource is requested), preserving `core.ServiceApps` exclusion for unscoped list-all workspace/project log queries.
3. Ensure `bds-…` log reads respect workspace boundaries, `core.RelCanViewLogs`, scoped API keys, and fresh-auth checks identically to `srv-…`.
