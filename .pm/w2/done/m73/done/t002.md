## Objective

Make Environment Group display names unique inside a workspace on create and rename, including concurrent requests across API replicas, while keeping identical names valid in different workspaces. Stop Blueprint and Environment name resolution from selecting an arbitrary legacy duplicate.

## Context

- `envgroups.Service.CreateEnvGroup` currently performs no uniqueness check.
- `findGroupByName` explicitly sorts ids and returns the first match when names collide; that makes `fromGroup` and Environment assignment potentially resolve the wrong secret set.
- A preflight list check alone is insufficient because bex-api is multi-replica and the metadata cache converges on a TTL.
- Existing `core.SecretKV` versioned snapshots/`PutCAS` provide the cross-replica primitive; no secret contents belong in a name index.

## Steps

1. Add a workspace/name claim seam backed by a CAS-safe, non-secret index; document normalization (trimmed exact name), rename-to-self, create/rename/delete compensation, and cross-workspace behavior.
2. Claim before create persistence, move the claim safely on rename, and release only after successful delete. Roll back owned claims on later failures without clobbering a concurrent winner.
3. Return one stable coded conflict mapped to HTTP 409 and equivalent GraphQL/MCP error metadata; make dashboard create/rename show the server reason.
4. Change every name resolver to collect matches and return a coded ambiguity error when legacy duplicates exist—never first-id-wins.
5. Add an idempotent audit/backfill command or startup-safe administrative path that creates missing claims, reports duplicate ids/workspace/name without values, and refuses destructive automatic merging.

## Acceptance criteria

- [ ] Same-workspace duplicate create and rename return the named conflict/409; rename-to-self succeeds and same-name groups in two workspaces succeed.
- [ ] A concurrent two-replica create test has exactly one winner and leaves no orphan metadata, projection Secret, or name claim.
- [ ] Delete/failed-create/failed-rename compensation cannot release another operation's claim.
- [ ] Legacy duplicate name resolution fails with a non-secret ambiguity error that includes enough ids/workspace context for an operator to repair it.
- [ ] The audit/backfill path is dry-run capable and idempotent; it never chooses, merges, or deletes a duplicate automatically.
- [ ] Blueprint `fromGroup` and Environment assignment tests prove they cannot bind arbitrarily.

## Out of scope

- Case-insensitive uniqueness unless a fresh Render check proves it.
- Automatic rename or content merge for legacy duplicates.
