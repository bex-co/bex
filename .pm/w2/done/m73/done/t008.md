## Objective

Bring the safe import/export conveniences observed on Render to Environment Groups by reusing the service Environment parser/export boundaries: dotenv paste/file import into the draft, per-value copy, and all-or-nothing copy/download export.

## Context

- Render create/edit exposes Add/Import from `.env`; detail Export offers Copy env vars and Download `.env`, and rows expose per-value copy.
- Bex already ships tested dotenv parsing, Web Crypto generation, escaping, and fail-closed export for service-local values (`w5/m44`).
- `ExportEnvButton` is currently gated on `serviceId`, so group pages cannot use it.

## Steps

1. Generalize the existing dotenv paste/file importer to target the group draft, including duplicate/invalid-key previews and no writes before Save.
2. Make per-value copy call only the named fresh-authorized reveal and clear transient plaintext according to the existing UI policy.
3. Add Copy env vars and Download `.env` for groups; reveal every requested value only after authorization and emit nothing on any missing/denied/failed value.
4. Reuse one escaping/order implementation; never log, cache persistently, toast, or include values in filenames/errors.
5. Place import affordances in create and edit where the live parity pass confirms them.

## Acceptance criteria

- [ ] Paste and file import parse the same valid syntax/order as the service editor, show invalid/duplicate outcomes, and only modify the draft.
- [ ] Per-value copy reveals exactly one value under fresh authorization.
- [ ] Copy/download includes every env var with correct dotenv escaping and stable order, or produces no clipboard/file output if any reveal fails.
- [ ] Group export works without a `serviceId`; service export remains unchanged.
- [ ] Tests prove no values enter Apollo normalized cache, URLs, logs, error strings, or snapshots.

## Out of scope

- Importing secret files from dotenv.
- Exporting secret-file contents.
