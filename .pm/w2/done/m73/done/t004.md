## Objective

Expose each group's optional Environment membership on list/detail and stop the dashboard from offering service links the backend must reject because they are outside that scope.

## Context

- `EnvGroupView` and the backend GraphQL type already carry `environmentId`, but the dashboard list/detail documents omit it.
- The detail route loads all services in the workspace and presents them as candidates; same-Environment enforcement happens only after submit.
- Render's populated list has an Environment column and its detail page names the current scope.
- Standalone workspace-scoped groups remain valid; their compatible link set is all workspace services that are not bound incompatibly by the established Environment rules.

## Steps

1. Query and type `environmentId` on list/detail; load the workspace Project/Environment index once and map ids to stable display labels.
2. Add scope metadata to list/detail with explicit Workspace/no-Environment fallback and resilient unknown-id rendering.
3. Derive compatible service-link candidates from the same membership rules as Core, excluding invalid choices before interaction without replacing server authorization/validation.
4. Keep currently linked services visible even if legacy drift exists, marking incompatibility and offering safe unlink rather than hiding it.
5. Cover workspace switching, deleted Environment fallback, scoped/standalone candidates, and legacy drift.

## Acceptance criteria

- [ ] Populated list and detail display the group Environment name, not only an opaque id; standalone and missing-target states are explicit.
- [ ] A group scoped to Environment A offers only compatible A services; an invalid cross-Environment service cannot be submitted from the UI and remains rejected by Core if called directly.
- [ ] Legacy incompatible links remain discoverable and unlinkable.
- [ ] Workspace switching cannot reuse scope/service data from the prior workspace.
- [ ] Dashboard queries include `environmentId` with generated types and focused tests.

## Out of scope

- Moving the group (t005).
- Changing Project/Environment membership semantics globally.
