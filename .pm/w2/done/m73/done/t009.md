## Objective

Add Render's Clone Environment Group workflow with an atomic Core operation that copies vars/files to a new group in an authorized target workspace and optional Environment without exposing source values to the dashboard or copying service links accidentally.

## Context

- Render's clone dialog selects destination workspace/Environment and copies variables/files.
- Client-side reveal-then-create would unnecessarily place all source secrets in browser state and can leave partial copies.
- Bex create already validates target workspace, Environment, initial vars/files, and compensation; t002 supplies unique target naming and t006 supplies revision-safe content primitives.

## Steps

1. Define `CloneEnvGroup(sourceId, name, ownerId, environmentId)` with fresh sensitive authorization on the source and create authorization on the target.
2. Read source contents server-side, validate target scope/name/quota, create atomically with compensation, and copy no `serviceLinks`.
3. Expose one consistent REST/GraphQL/MCP verb/result and a detail Manage → Clone dialog using authorized workspace/Environment selectors.
4. Navigate to the returned new id and reconcile both source/target workspace lists without ever returning copied values.
5. Cover cross-workspace allow/deny, target conflict, environment mismatch, source mutation race, and failure cleanup.

## Acceptance criteria

- [ ] Clone copies env vars and secret files exactly, returns only names/metadata, and leaves source contents unchanged.
- [ ] Destination name/workspace/Environment are validated with t002/t004 semantics; unauthorized cross-workspace targets fail without revealing their existence beyond established policy.
- [ ] New group starts with zero linked services and causes zero deployments.
- [ ] Any late failure removes target metadata, content, projections, and name claim without touching the source.
- [ ] Dashboard reaches the new group by returned id and does not reveal source values into client cache/state.

## Out of scope

- Copying links or triggering deployments.
- Synchronizing future edits between source and clone.
