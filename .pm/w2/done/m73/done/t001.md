## Objective

Fix the reproduced data-loss path where the dashboard requests a generated Environment Group value but the group hook/API sends and stores an empty literal. Give single-key and bulk group writes the same literal-or-generated contract already shipped for create-time group vars and service env vars.

## Context

- `EnvVarsEditor` calls `setVar(key, "", true)` when Generate is selected.
- `useEnvGroupVarMutations.setVar` currently accepts only `(key, value)` and `SetEnvGroupVar` exposes only `$value`, so the third argument disappears.
- `CreateEnvVarInput` and `prepareCreateEnv` already define the correct mutually exclusive `value | generateValue` rule.
- A normal mutation response must remain names-only; the generated value is visible only through the existing fresh-authorized reveal verb.

## Steps

1. Introduce one reusable env-group write input with `key`, optional `value`, and `generateValue`; reject both-set and neither-intended invalid shapes consistently.
2. Resolve generation with `core.GenerateValue` inside Core before persistence, never in an adapter.
3. Thread the flag through per-key and replace/patch REST, GraphQL, and MCP inputs while preserving literal compatibility.
4. Update the dashboard document, generated types, hook signature, and shared editor adapter so Generate sends intent instead of an empty string.
5. Keep success/rollout copy dependent on the actual mutation outcome and link count.

## Acceptance criteria

- [ ] Dashboard Add variable → Generate → Save sends `generateValue: true`, not `value: ""`.
- [ ] Core stores a non-empty cryptographically generated value; an explicit sensitive reveal proves it while list/get/mutation payloads stay masked.
- [ ] REST, GraphQL, and MCP accept identical literal-or-generate semantics and return the same coded 400 for conflicting input.
- [ ] Create-time generation continues to work through the shared validator/generator rather than a second implementation.
- [ ] Focused regressions cover the exact dropped-third-argument bug and all adapter shapes.
