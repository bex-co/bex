## Objective

Add a reusable `DryRun` mechanism to `internal/core` that lets a write verb (Create/Update) resolve its full effective spec — validation, defaulting, plan/tier resolution, ownerId/workspace resolution — without applying it to Kubernetes or writing to the control-plane store, mirroring the short-circuit-before-apply pattern `internal/blueprints`' `Validate` already established for `bex.yml`.

## Context

- Precedent: `internal/blueprints` `Validate` (dry-run for the `bex.yml` path, `w2/m15`) — read its short-circuit shape before designing this one; reuse rather than reinvent.
- `internal/core/base.go` — `Base.Authorize*` methods still run in dry-run mode (auth checks are not skipped, only the write).
- The mechanism must apply identically across services (`internal/apps`), Postgres (`internal/postgres`), and Key Value (`internal/keyvalue`).

## Steps

1. Define a `DryRun` context key/helper in `internal/core` (e.g. `core.WithDryRun(ctx)` / `core.IsDryRun(ctx)`).
2. In each of `apps.Create`/`apps.Update`(-equivalent), `postgres.Create`, `keyvalue.Create`, and their plan-update verbs: when dry-run is set, run every validation/resolution step (name conflicts, plan/tier validity, ownerId membership) but skip the actual Kubernetes apply and control-plane store write, returning the resolved spec.
3. Ensure authz checks (`Base.Authorize*`) still run — a dry-run is not a way to probe access without a check.

## Files

- `lego/backend/internal/core/dryrun.go` (new)

## Acceptance criteria

- [ ] A dry-run create call runs full validation (bad plan, name conflict, unauthorized ownerId all still error the same way) but performs zero Kubernetes/store writes.
- [ ] The resolved spec returned by a dry-run call matches what a real create would have produced.
