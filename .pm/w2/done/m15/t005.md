## Objective

Prove the full chain works live: validating a bad `bex.yml` catches per-entry errors with no apply; validating then deploying a valid one via two MCP calls works with no surprise; `sync` is idempotent.

## Steps

1. Validate a deliberately-broken `bex.yml` (e.g. an invalid `fromDatabase` reference) — confirm per-entry errors, nothing created.
2. Validate a good `bex.yml`, then deploy it via the existing `deploy` MCP tool — confirm no surprises between the two calls.
3. Sync an already-applied blueprint with no changes — confirm it's a no-op.
