## Objective

Implement ADR054 D3: connections resolved to an agent-session sandbox may open multiple concurrent `session` channels (Zed's ControlMaster model), each bridged to its own `pods/exec` stream; `srv-…` connections keep the single-channel contract byte-identically.

## Context

- `nativessh/server.go` `serveConn`: today accepts the first `session` channel, spawns `rejectAdditionalChannels`, returns. `serveSession`/`runExec` are already self-contained per channel (own SPDY stream via stateless `KubeExecutor`); channels share only the immutable target.
- Zed opens an initial master with **zero** channels (`ssh -N -o ControlMaster=yes`) — the connection must idle validly until channels arrive or timeout.
- New env `BEX_SSH_MAX_CHANNELS_PER_CONN` (default 16; `0` disables the exception → single-channel everywhere). The existing `SessionLimiter` keeps counting connections — do NOT switch it to per-channel (would break Zed against the 5-per-identity cap); the channel bound is a separate per-connection semaphore.
- 4h `BEX_SSH_SESSION_TIMEOUT` stays connection-scoped; forwarding/env/X11 bans unchanged on every path.

## Steps

1. Branch `serveConn` on a target flag (sandbox vs app): sandbox → per-channel `go serveSession(...)` under the per-connection semaphore, loop until the channel chan closes; app → existing behavior verbatim.
2. Add the env knob in `cmd/ssh-gateway/main.go` + a `bex_ssh_gateway` channel-count metric (bounded labels only, per the metrics rule).
3. Mirror the new env var in `CLAUDE.md`'s env table and `.env.example` (name + comment only).
4. Tests with an in-process ssh client: N concurrent channels each get independent exec streams and exit statuses; channel N+1 past the cap is rejected; a zero-channel connection times out cleanly; `srv-…` still rejects a second channel.
