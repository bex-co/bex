## Objective

Implement the `/build-sources/new` create wizard supporting both Git-backed and Docker-image-backed Build Sources matching Render's `POST /v1/build-sources` contract, with optional project scoping, initial service linking, build-time environment setup (git only), role gating, and a breakpoint-matched skeleton.

## Context

- `createBuildSource` in `lego/backend/internal/apps/build_sources_graphql.go` accepts: `ownerId`, `name`, `projectId`, `git` (`repoUrl`, `branch`, `runtime`, `buildCommand`, `rootDir`, `dockerfilePath`, `dockerContext`, `buildFilter`, `registryCredentialId`, `region`) OR `image` (`imageUrl`, `registryCredentialId`), plus (git only) `envVars`, `secretFiles`, `envGroupIds`, and `serviceIds`.
- Valid git runtimes per Render OpenAPI: `docker`, `elixir`, `go`, `node`, `python`, `ruby`, `rust` (no `static`).
- `dockerContext` is only valid when `runtime === "docker"`; `envVars`/`secretFiles`/`envGroupIds` are only valid for git sources.

## Steps

1. Create `/build-sources/new` route with `can_create` role guard and a breakpoint-matched pending skeleton (`1440px` and `390px`, registered in the route-skeleton manifest).
2. Build `CreateBuildSourcePage` with:
   - Source type selector (**Git repository** vs **Docker image**).
   - Shared fields: Name (with inline duplicate-name `BUILD_SOURCE_NAME_TAKEN` error handling), optional Project scope selector.
   - Git fields: existing GitHub repository picker / manual public repo URL input, Branch, Runtime (`docker`, `elixir`, `go`, `node`, `python`, `ruby`, `rust`), Region selector, Build Command (native) or Dockerfile Path + Docker Context (docker), Root Directory, Build Filter (`paths` / `ignoredPaths`), optional Registry Credential selector, and collapsible Build-time Environment section (env vars, secret files, workspace env groups).
   - Image fields: Image URL and optional Registry Credential selector (build-time environment hidden for image sources).
   - Optional "Link existing services" multi-select (filtered to linkable service types: `web_service`, `private_service`, `background_worker`, `cron_job` — excluding `static_site`).
3. On success, navigate to the created Build Source (or `/build-sources` with confirmation toast if detail route isn't mounted yet, ready for `w2/m614`).
