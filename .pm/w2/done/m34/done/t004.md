## Objective

Add a `Connect` path in `github/service.go` that takes an already-resolved `workspaceID` (from the verified state, t003) instead of deriving it from `s.Tenant(ctx)`/caller identity, since there is no caller identity at the callback.

## Context

- The existing `Connect` (`service.go:118-141`) assumes normal caller-identity-based authorization (`s.Authorize(ctx, core.RelCanManage)`), which has nothing to check at the callback — the state token itself is the credential, analogous to how `installation_id` is already independently validated against GitHub before persisting.

## Steps

1. Add a `ConnectWithWorkspace(ctx, workspaceID, installationID string) error` (or similar) that performs the same installation validation as the existing `Connect` but skips caller-identity authorization, trusting the pre-verified `workspaceID`.
2. Wire the callback handler (t003) to call this new entry point.

- `lego/backend/internal/github/service.go`
- `lego/backend/internal/github/rest.go`

## Acceptance criteria

- [ ] A valid state-verified callback records the GitHub connection against the correct workspace.
- [ ] The existing Bearer-token `Connect` path is unchanged (no regression).
