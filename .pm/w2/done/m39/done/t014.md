## Objective

Add Render's left-nav Shell destination to bex service pages while mapping it honestly onto the already-shipped running-instance SSH contract instead of implementing a browser-hosted terminal.

## Context

- Render's `/shell` page embeds an interactive browser terminal, supports paid web/private/background services, and offers an instance selector for scaled services.
- bex ADR035 deliberately supports standard OpenSSH into an existing Ready instance and excludes browser terminals, ephemeral shells, cron shells, and new client-side exec authority.
- User request, 2026-07-17, after comparing `dashboard.render.com/.../shell` with `dashboard.bex.co/services/eden-cms-v2/deploys`.

## Steps

1. Add Manage → Shell to the service-scoped sidebar and a typed `/services/$serviceId/shell` route.
2. Present the service's advertised `sshAddress` as a copy-ready command with lifecycle guidance and an honest unavailable state.
3. Deep-link to account SSH public-key settings without handling private keys or terminal streams in the browser.
4. Update the Render dashboard route record and ADR035, then add focused route/sidebar tests and run the dashboard validation suite.

## Acceptance criteria

- [x] A service page shows Manage → Shell and the link resolves under the shared service-detail chrome.
- [x] An eligible service shows a copy-ready `ssh <sshAddress>` command; an ineligible or unconfigured service invents no address and explains the gate.
- [x] The page links directly to SSH public-key settings and stores no browser-readable private credential or terminal stream.
- [x] Dashboard typecheck, lint, focused tests, and the full test suite pass.

## Out of scope

- Render's browser terminal, instance-picker UI, ephemeral/cron shells, SFTP/SCP, forwarding, or any new Kubernetes exec permission.
