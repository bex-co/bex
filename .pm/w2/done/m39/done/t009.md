## Objective

Prove the shipped path end to end against a real cluster, a real registered key, raw OpenSSH, and the current unmodified official Render CLI, including denial and session-termination cases.

## Context

- Unit tests cannot prove TCP/22 routing, SSH host-key behavior, OpenFGA identity mapping, or SPDY exec through a real kube-apiserver.
- The CLI additionally requires list-by-name, a live deploy, `sshAddress`, and the instances endpoint to compose correctly.
- Verification artifacts must never print private keys, kubeconfigs, environment values, or terminal secrets.

## Steps

1. Add a redacting verification script that registers a disposable public key and deploys a shell-capable test service with at least two replicas.
2. Verify raw `ssh`, `render ssh <service-name>`, any-instance selection, specific-instance selection, resize, exit status, and session closure on restart/redeploy.
3. Verify deleted/unknown key, viewer/foreign workspace, suspended/free/static/cron, non-Ready instance, and shell-less image failures.
4. Delete the disposable key/service and record only sanitized commands, fingerprints, ids, statuses, and pass/fail evidence.

## Files

- `scripts/ssh-verify.sh`
- `.pm/w2/done/m39/evidence/`
- `docs/cli-compatibility-checklist.md`

## Acceptance criteria

- [x] Raw OpenSSH and the current official Render CLI both reach the intended app container through the public endpoint.
- [x] Every denial case fails before `pods/exec`, and restart/redeploy closes the session.
- [x] Evidence contains no private key, kubeconfig, token, secret value, or captured environment.

## Out of scope

- Ephemeral CLI mode and non-SSH execution commands.
