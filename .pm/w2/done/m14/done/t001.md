## Objective

Add control-plane storage for external registry credentials: a `registry_credentials` table scoped to a workspace, storing the registry host, username, an opaque secret, and an optional expiry.

## Context

- Control-plane store lives behind `BEX_CP_DB_URI` (`docs/ADR003-control-plane.md`); migrations live alongside the existing tables (follow the convention used for `webhook_endpoints`, `tenant_members`, etc.).
- Mint the id through `lego/backend/internal/id` (`id.New(kind)`), never by hand (`docs/ADR020-identifiers.md`); register a new `id.Kind` for the registry-credential resource.
- Render's docs explicitly flag ECR credentials as short-lived (12h rotation) — the schema must carry an optional `expiresAt` from the start, not bolt it on later.
- Secret is generated/supplied at creation and never returned in full on subsequent reads (mirrors the webhook-endpoint secret pattern from `w3/m11`).

## Steps

1. Design `registry_credentials` columns: id, workspace/owner id, registry host, username, secret (not returned on read), expires_at (nullable), created_by, created_at, updated_at.
2. Write the migration, following the existing migration numbering convention.
3. Add minimal Go types + a thin store-access layer (no HTTP surface yet — that's t003-t005).

## Files

- `lego/backend/internal/store/migrations/` (new migration)
- `lego/backend/internal/id/` (register the new id.Kind)
- new `lego/backend/internal/registrycreds/` package (model + store access)

## Acceptance criteria

- [ ] Migration applies cleanly against a real Postgres in tests.
- [ ] Credential ids are minted via `id.New`, follow the `<prefix>-<xid>` convention, and are registered in `internal/id`'s guard test.
- [ ] Secret is never returned by a read/list query (only at creation).

## Out of scope

- HTTP surfaces (REST/GraphQL/MCP) — t003-t005.
- Operator wiring — t002.
