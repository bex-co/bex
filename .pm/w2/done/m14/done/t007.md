## Objective

Make a near/past-expiry registry credential visible on REST/GraphQL/MCP/dashboard rather than silently letting pulls start failing — Render's own docs specifically call out ECR's 12h rotation as a real operational concern for this feature.

## Context

- bex does not auto-rotate credentials — that requires the tenant's own registry-side action (e.g. regenerating an ECR token). This task is about **visibility**, not automation.

## Steps

1. Add a computed `status` (e.g. `active`/`expiring_soon`/`expired`) to the credential read shape wherever `expiresAt` is set, based on the current time vs. a reasonable "expiring soon" threshold (e.g. within 1h for ECR-style short-lived tokens).
2. Surface this status field in REST/GraphQL/MCP responses and the dashboard list (t006).

## Files

- `lego/backend/internal/registrycreds/` (shared status-computation logic, consumed by all three adapters)

## Acceptance criteria

- [ ] A credential with a past `expiresAt` reports `expired` consistently across all surfaces.

## Out of scope

- Any automated re-fetch/rotation of the underlying registry token.
