## Definition of done

A workspace stores credentials for a private external registry (host + username + secret, with optional expiry), and a service whose `image` references that host pulls successfully using a materialized `dockerconfigjson` Secret — verified against a real private registry, not just a unit test. Stale/expired credentials are surfaced, not silently hidden.

## Live acceptance evidence (2026-07-13, local CAPD mock cluster)

Rebuilt `bex-operator:dev` (manager + bex-api, one image) from this milestone's code and redeployed it into the running mock cluster; the new `0014_registry_credentials` migration applied automatically on bex-api startup.

1. **Real, auth-enabled registry**: a `registry:2` server (`test-private-registry`) with `REGISTRY_AUTH=htpasswd` — confirmed genuinely access-controlled (anonymous `GET /v2/` → 401; `docker push` without `docker login` failed with "no basic auth credentials"; correct credentials → 200/success).
2. **End-to-end pull**: created a registry credential via `POST /v1/registry-credentials`, deployed an App whose `image` pointed at the private registry — `kubectl get events` showed `Successfully pulled image "…/priv-nginx:v1"`, the pod reached `1/1 Running`. The decoded `<app>-registry-pull` Secret's `.dockerconfigjson` had the correct host/username/password; `App.spec.externalRegistryPullSecret` was set and present in the Deployment's `imagePullSecrets`.
3. **Negative (no-leak) check**: a second App pulling public `nginx:alpine` had no `externalRegistryPullSecret` and no pull-secret Secret was ever materialized for it — a credential never reaches an unrelated pull.
4. **Real bug found and fixed, not worked around**: the Secret materialization originally ran before the App's own `Create` call (no UID yet), so its owner-reference write failed on a first-time create of an image-backed App whose image already matched a stored credential. Fixed by dropping the owner reference (mirroring `apps`' clone-secret Secret, which has the identical constraint) and adding an explicit delete in `apps.Service.Delete`; covered by new regression tests (`TestMaterializeFailureSurfacesAsCreateError`, `TestDeleteRemovesExternalRegistryPullSecret`, `TestDeleteWithNoRegistryPullSecretIsANoOp`).

**Pre-existing issues found during verification, unrelated to this milestone (documented, not fixed here)**: the mock cluster's live CRD hadn't been re-applied after this session's `AppSpec` field addition (a required-but-undocumented deploy step, not a code bug); `bex-db`'s `deploys` table was missing a `generation` column despite `schema_migrations` claiming it applied (repaired manually for the verification run); the store-backed redeploy path doesn't write a redeployed image back to the `apps` control-plane row, so the projector can revert it on its next resync pass; `DELETE /v1/services/{id}` 500s on a Secrets-delete RBAC gap. Worth their own follow-up tasks.
