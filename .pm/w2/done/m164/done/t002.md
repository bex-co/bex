## Objective

Build the second census — the one that would have caught `git_connections` and `sandbox_tenant_keys` years earlier: every table carrying a workspace id must declare how its rows die when the workspace does.

## Context

- `store.DeleteTenant` (`lego/backend/internal/store/workspaces.go:133`) is one `DELETE FROM tenants`. Everything else is either an FK cascade or one of the eight purgers registered in the composition root (`apps`, `postgres`, `keyvalue`, `sandbox`, `secrets`, `envgroups`, `registrycreds`, `billing` — each a `workspaces.WorkspacePurger`, `workspaces/service.go:227`).
- The three legitimate answers are: **cascade** (FK to `tenants` with `ON DELETE CASCADE`), **purger** (a registered `PurgeWorkspace` that covers the table), **retention** (deliberately kept, with a sweep or a written reason — `audit_events`, `ssh_sessions`, `cli_telemetry_events` are this class today, each with a retention purge).
- Detection must survive the real-world pattern where the FK arrives in a **later** migration than the `CREATE TABLE` (0094 added `git_connections`' cascade, 0117-era added `sandbox_tenant_keys`'). So query the live schema through `information_schema`/`pg_constraint` after migrating, never by parsing migration text.
- Known unclassified tables to expect on the first run: `jobs`, `agent_session_dispatches`, `datastore_event_facts`, `datastore_observed_checkpoints`, `service_event_index`, `workspace_creation_attempts`.

## Steps

1. Add a real-Postgres test that migrates, then enumerates every table with a `tenant_id`/`workspace_id`/`owner_id` column.
2. For each, resolve whether a cascading FK chain to `tenants` exists (directly or transitively — `push_deliveries` cascades through `push_notifications`).
3. Compare against a declared inventory mapping each remaining table to `purger:<name>` or `retention:<reason>`; fail on anything undeclared.
4. Prove the guard with a seeded table that declares nothing.

## Evidence — 2026-09-21

The migrated schema contains 48 workspace-keyed columns: 43 validated cascading paths and five explicit retention declarations. Later-added and transitive FKs are discovered. Mutation tests reject an undeclared workspace/owner key, a cascade on the wrong sibling column, and a nullable composite MATCH SIMPLE bypass; NOT NULL and MATCH FULL controls delete correctly. Retention records distinguish actual sweeps from indefinite agent-dispatch safety retention.
