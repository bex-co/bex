# Brand late-added command descriptions before shell completion

Why: Shell suggestions are part of the documented Bex CLI identity; PostgreSQL and Key Value suggestions currently advertise Render even though help for the same commands is correctly branded.

- **Severity / attribution:** minor / Bex launcher. Suggestions still execute correctly; no hosting failure demonstrated.
- **Estimate:** 35m; no dependencies. Source: live CLI QA loop, 2026-10-03 UTC. Goal: ADR008 hosting CLI usability within the branding boundary in `docs/bex-cli.md`.
- **Versions:** installed `/opt/homebrew/bin/bex` v0.2.1 and checkout build `f296747d9`; Render CLI v2.27.0, commit `a764810a768202704e7206eb7b87a47211fcd98e`; Cobra v1.10.2. Launcher branding/main code remains unchanged at `ebe65b324`. Deployed API revision unknown and immaterial to the local metadata symptom.
- **Context:** macOS, non-TTY, isolated human QA login, `https://api.bex.co/v1/`, workspace `tea-daif693dqjvc73e7as3g`. No hosting resources created or modified by this probe.

## Reproduction and durable evidence

With the normal isolated Bex configuration, run each in a fresh process:

```sh
bex __complete postgres ""
bex __complete keyvalues ""
bex __complete pg ""
bex __complete kv ""
```

Both canonical selectors reproduce on the installed release and checkout; both aliases reproduce on checkout. All exit 0. The release Key Value repeat took 0.85s. Exact checkout stdout follows (the gap between value and description is a tab); aliases produce identical corresponding output.

```text
create	Create a new Render Postgres database
delete	Delete a Render Postgres database
get	Get details of a Render Postgres database
list	List Render Postgres databases
resume	Resume a suspended Render Postgres database
suspend	Suspend a Render Postgres database
update	Update a Render Postgres database
:4
```

```text
create	Create a new Render Key Value instance
delete	Delete a Render Key Value instance
get	Get details of a Render Key Value instance
list	List Render Key Value instances
resume	Resume a suspended Render Key Value instance
suspend	Suspend a Render Key Value instance
update	Update a Render Key Value instance
:4
```

All four return stderr:

```text
Completion ended with directive: ShellCompDirectiveNoFileComp
```

Expected: identical values, order, tabs, directive `:4`, exit and stderr, with `Bex Postgres` / `Bex Key Value` in descriptions. Installed Bash and Zsh completion scripts invoke `__complete`; both generated scripts parse successfully (`bash -n`, `zsh -n`) and register `bex`. This is metadata returned by completion, not incorrect shell registration.

Controls: checkout `postgres --help` and `keyvalues --help` exit 0 with Bex descriptions and empty stderr. `__completeNoDesc postgres ""` returns `create`, `delete`, `get`, `list`, `resume`, `suspend`, `update`, and `:4`, one per line, exit 0. Services completion has no corresponding Render description leak. No shell configuration was installed or changed.

Wire evidence: not captured; the observed failing boundary is local Cobra command metadata. This does not assert the upstream bootstrap makes no network requests. Actual interactive shell menu rendering, Fish and PowerShell were not exercised.

## Cause and proposed fix

`lego/cli/main.go:50` calls `branding.Apply` before upstream `cmd.Execute` at line 74. Pinned `cmd/root.go:404` then calls `setupCommands`, registering PostgreSQL/Key Value children after the initial branding walk. `lego/cli/internal/branding/branding.go:41–78` refreshes late commands only from HelpFunc and UsageFunc. Successful completion uses neither. Cobra `completions.go:520` directly serializes `subCmd.Short`; `brandTree` already owns rewriting that field at `branding.go:115`.

Refresh the existing branding tree once after upstream registration and before completion executes, retaining help/usage fallbacks. One candidate is a once-registered launcher initialization hook using Cobra's public `OnInitialize` (`cobra.go:99`, invoked by `command.go:1048`); verify ordering with the real launcher. This hook is a proposal, not a tested fix. Avoid accumulating global initializers across test roots, calling upstream SetupCommands twice, or wrapping PersistentPreRunE before upstream overwrites it at `cmd/root.go:219`. Do not fork upstream or regex-filter stdout.

Blast radius: 14 late-added child descriptions across PostgreSQL and Key Value, reachable via four parent selectors (`postgres`, `pg`, `keyvalues`, `kv`). The shared metadata walk also handles other children and flag Usage strings; audit those consumers when changing its timing. No REST, GraphQL, MCP, dashboard, or server response changes are needed. Keep command values, upstream handlers, directives, `render.yaml`/`bex.yml`, User-Agent compatibility version, and intentionally retained upstream runtime copy unchanged.

## Acceptance and exclusions

- The four fresh-process reproductions return Bex descriptions with the same seven values and completion protocol; `__completeNoDesc` remains unchanged.
- Help and usage-error branding remain correct for late-added children; generated Bash/Zsh scripts still parse and register Bex. Preserve native commands and flag completions.
- Exercise initialization ordering through a real launcher subprocess so a preconstructed Cobra tree cannot mask the failure.
- Dedupe searched open/done `.pm` for `__complete`, completion descriptions, and completion/branding combinations: no matching item. Existing `w7/045` and commits `68a7e73fc` / `34484344f` repair help/usage, not this successful-completion path; current tests cover those two wrappers only.
- `docs/bex-cli.md` explicitly includes Short/Long metadata in branding. This finding does not reopen the documented runtime-copy residual, installation, update, or upstream skills-management work. `.pm/DO_NOT_DO.md` and the compatibility ledger were checked.

**Closed 2026-10-06 (w2 /loopx):** fixed. `branding.Refresh` is registered once as a cobra initializer in `lego/cli/main.go`, so the late-added Postgres/Key Value children are branded before `__complete` reads `Short`. `TestBexCompletionBranding` checks all four selectors plus `__completeNoDesc` through a real launcher subprocess.
