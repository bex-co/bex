## Objective

Make the dashboard sidebar collapse to a slim icon rail instead of sliding fully off-screen: switch the three `Sidebar` consumers from `collapsible="offcanvas"` to `collapsible="icon"` and make every nav item render correctly in the collapsed rail (icon visible, label hidden, tooltip on hover).

## Context

- The shadcn primitive already supports it: `Sidebar` accepts `"offcanvas" | "icon" | "none"` and all `group-data-[collapsible=icon]:` CSS exists (`dashboard/src/common/components/ui/sidebar.tsx:173,243,256,494`; `SIDEBAR_WIDTH_ICON = "3rem"`).
- Consumers to flip: `dashboard/src/common/components/dashboard-layout/dashboard-sidebar.tsx:82`, `project-sidebar.tsx:44`, `service-sidebar.tsx:46`.
- `SidebarMenuButton` has a `tooltip` prop that only shows when collapsed — audit `sidebar-nav-groups.tsx`, `sidebar-brand.tsx`, and the project/service nav item lists so every item has an icon + tooltip. Items without icons must get one or degrade gracefully.
- Devin reference: collapsed rail is 52px, same DOM stays mounted, labels hidden via `group-data-[state=collapsed]` variants, 36px icon buttons.
- Mobile must keep the existing Sheet/offcanvas behavior (the primitive already branches on `isMobile`).
- The header toggle (`dashboard-header.tsx:24-31`) currently renders only when collapsed/mobile — verify it shows correctly in both states or relocate per the Devin pattern (in-sidebar toggle when expanded, content-header toggle when collapsed).

## Steps

1. Flip `collapsible="offcanvas"` → `"icon"` in the three sidebar components.
2. Audit every `SidebarMenuButton`/nav item for an icon + `tooltip`; add missing ones.
3. Check `SidebarHeader`/`SidebarFooter` content (brand, workspace switcher) renders sanely at rail width — hide or shrink text via the existing `group-data-[collapsible=icon]` variants.
4. Verify Cmd/Ctrl+B, header trigger, and `SidebarRail` click all toggle to the rail (not off-screen) on desktop, and mobile still gets the Sheet.
