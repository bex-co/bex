## Objective

Make sidebar state + width survive reloads with no flash: persist one cookie encoding a signed width (Devin's scheme — `320` = expanded at 320px, `-320` = collapsed remembering 320px), read it during SSR, and hydrate `SidebarProvider` from it.

## Context

- Today the primitive writes `sidebar_state=<bool>` on toggle (`dashboard/src/common/components/ui/sidebar.tsx:83-86`) but **nothing ever reads it back** — `SidebarProvider` always starts `defaultOpen = true` (`sidebar.tsx:54,72`; `dashboard-layout/index.tsx:29` passes no prop), so the cookie is dead weight today.
- Devin persists `webapp_sidebar_state` as a signed width in a cookie (not localStorage) precisely so SSR can render the right state/width first paint — verified live: resize to 360 ⇒ `360`, collapse ⇒ `-360`, survives reload.
- TanStack Start SSR: read the cookie in a server fn / root loader (the repo already reads Kratos session cookies in `src/common/server-fn/` — follow that pattern) and thread it to every `DashboardLayout` (or hoist; see below).
- `DashboardLayout` is instantiated per page (~25 call sites), not in `__root.tsx` — hoisting `SidebarProvider` to the root layout would also make the state survive client-side navigations without re-mount; do it if it's a contained change, otherwise thread `defaultOpen`/`defaultWidth` into the existing per-page layout and note the hoist as follow-up.
- The wrapper already carries `suppressHydrationWarning` (`sidebar.tsx:142`).

## Steps

1. Replace the boolean cookie write with the signed-width encoding (keep the `sidebar_state` cookie name or migrate — handle the legacy `true`/`false` values gracefully).
2. Write the cookie on toggle **and** on drag-commit (t002's `pointerup`).
3. Add a server-side read (server fn or root loader) exposing the parsed `{open, width}`.
4. Pass `defaultOpen` + initial `--sidebar-width` into `SidebarProvider`; verify SSR HTML already has the right width/state (view-source or disable JS).
5. Reload in both states/widths — no flash, no hydration warning in console.

## Files

- `dashboard/src/common/components/ui/sidebar.tsx`

- `dashboard/src/routes/__root.tsx` (if hoisting) or the server-fn module under `dashboard/src/common/server-fn/`

## Acceptance criteria

- [ ] Collapse, reload ⇒ page renders collapsed from first paint (no expanded→collapsed flash).
- [ ] Resize to a custom width, reload ⇒ same width from first paint.
- [ ] Collapse then re-expand (any trigger) ⇒ returns to the remembered width, matching the signed-cookie semantics.
- [ ] Legacy `sidebar_state=true/false` cookie values don't crash parsing.

## Out of scope

- Cross-device sync of the preference (cookie is per-browser; fine).
