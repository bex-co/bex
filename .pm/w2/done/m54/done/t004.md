## Objective

Complete w5/m42's service-title work by making the human name and translated service type available in the initial SSR title while preserving one invariant title across every service tab and deploy detail.

## Context

- w5/m42 correctly settled the browser title on `<name> · <type> · bex dashboard` after Apollo data loaded and proved that tab names do not belong in it.
- Its documented compromise is an id-only SSR/first-paint fallback plus a client `document.title` effect.
- Current Render code uses `<name> ・ <user-facing type> ・ Render Dashboard` for Web Service, Background Worker, Cron Job, Private Service, and Static Site layouts.

## Steps

1. Expose the authenticated service name/type to the parent route head through an SSR-safe loader/cache seam.
2. Use the shared formatter and the existing canonical service-type label mapping; remove the direct title effect.
3. Ensure Overview, Logs, Metrics, Deploys, deploy detail, Events, Environment, Shell, Scaling, Plan, and Settings inherit the exact parent title with no tab segment.
4. Define deterministic loading/not-found/error titles and confirm service rename/type changes refresh the title.

## Acceptance criteria

- [ ] Authenticated SSR HTML contains `<service name> ・ <translated service type> ・ bex Dashboard`.
- [ ] Every service child route and deploy detail keeps that exact title after direct load and client navigation.
- [ ] The opaque service id appears only in explicit loading/not-found diagnostics, never the settled title.
- [ ] No duplicate GraphQL request is introduced solely for the title, and w5/m42's type/tab tests remain green after migration.

## Out of scope

- Changing service tabs, service-type vocabulary, or the deploy-detail UI.
