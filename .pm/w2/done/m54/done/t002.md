## Objective

Move every non-resource content page onto the shared title contract so its SSR title, client-navigation title, visible heading vocabulary, and selected language agree.

## Context

- Current routes mix `— bex`, `· bex dashboard`, hard-coded English, and an inherited generic root title.
- The scope includes Overview, Settings, Workspace Settings, Notifications, Usage, Webhooks, Blueprints, Environment Groups, create flows, and Ory/OAuth/device auth pages.
- Render's shared page containers follow `<page> ・ Render Dashboard`; bex's equivalent is localized `<page> ・ bex Dashboard`.

## Steps

1. Inventory the audit matrix's static/auth/list/create/settings content routes and give each an explicit shared-helper title.
2. Add or reuse i18n messages for every page prefix; ensure SSR language detection and head evaluation use the same locale.
3. Align create labels to `New <resource>` and keep auth/device titles purpose-specific without the old em-dash suffix.
4. Remove redundant hard-coded title strings and verify client navigation cannot leave the previous route title behind.

## Files

- `dashboard/src/routes/*.tsx`
- `dashboard/src/features/*/locales/{en,zh}.ts`
- `dashboard/src/common/lib/`

## Acceptance criteria

- [ ] Every rendered static/auth/list/create/settings route has a localized initial SSR title using the shared suffix.
- [ ] English and Chinese navigation updates both the page copy and document title without a hard-coded-English flash.
- [ ] Equivalent aliases redirect to their canonical route rather than owning a second title.
- [ ] No title string in this route family manually spells the separator or brand suffix.

## Out of scope

- Dynamic resource names (t003–t005) and visible page-layout redesign.
