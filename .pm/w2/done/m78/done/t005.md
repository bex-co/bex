## Objective

Record every scope-authorization decision (allow and refuse) in the audit stream with exactly the four fields ADR069's follow-up names — client id, subject, audience, normalized scopes — plus the operation and outcome, bounded, and never carrying token material.

## Context

`docs/ADR069-security-review-round14.md` line 114 asks for "authorization-decision audit carrying client id, subject, audience, and normalized scopes" alongside the scope matrix. The audit machinery exists: `lego/backend/internal/audit/` (`service.go` + `vocabulary_test.go`'s event-vocabulary discipline, REST/GraphQL read surface, retention via `BEX_AUDIT_RETENTION_DAYS`). The record must be derived from introspection results only — the bearer token, ticket, or introspection response body must never be stored (custody rule; cf. ADR072 finding 4's raw-edge-log custody note).

## Steps

1. Add an audit event type for scope decisions to the audit vocabulary (satisfying `vocabulary_test.go`'s conventions), with fields: client id, subject, audience, normalized scope list, operation (surface + name from the t002 matrix), decision (allowed/refused), and refusal code.
2. Emit it from t003's shared checker seam so all three surfaces produce identical records; normalize scopes (sorted, deduped) before writing.
3. Bound the write: cap the scopes list and field lengths at the write seam (the ADR069 finding-4 `SanitizeDeliveryError` pattern — sanitize/bound where data is written, not read); decide and document the volume policy (at minimum every refusal is recorded; if allows prove too hot, record refusals + a sampled/aggregated allow signal, and say so in the ADR012 amendment).
4. Confirm retention: rows ride the existing `BEX_AUDIT_RETENTION_DAYS` sweep with no new knob.
5. Add unit tests: record shape, normalization, bounds, and absence of token material; run `cd lego/backend && go test ./internal/audit/... ./internal/api/...`.

## Files

- `lego/backend/internal/audit/service.go` (+ vocabulary)
- `lego/backend/internal/audit/vocabulary_test.go`
- `lego/backend/internal/api/auth.go` / t003's checker seam (emit)

## Acceptance criteria

- A refused write with a read-scoped token produces an audit row carrying client id, subject, audience, normalized scopes, operation, and refusal code — on each of the three surfaces.
- No token, ticket, or introspection body material appears in any audit field; all fields are length-bounded.
- Rows are purged by the existing retention sweep.

## Out of scope

- A new audit read surface or dashboard UI; metrics/alerting on refusals; auditing non-scope authorization (OpenFGA) decisions.
