## Objective

Make the granular scopes requestable end to end: bex-api's RFC 9728 metadata advertises them, and the dashboard consent screen recognizes them — intersecting grants against the extended vocabulary and refusing audience-without-capability consistently on both GET and POST decision paths.

## Context

Round 14 wired one vocabulary at three points (ADR012 §7 ~line 141): introspection (t003 extends it), discovery (`scopes_supported: ["bex.api"]` emitted from `lego/backend/internal/api/server.go`; tests in `oauth_discovery_test.go`), and the dashboard's Hydra consent bridge (`dashboard/src/common/server-fn/hydra-consent.ts`, tests in `dashboard/src/common/server-fn/__tests__/hydra-consent.test.ts`), whose recognized-scope intersection currently spans `openid offline_access profile email` + `OAUTH_API_SCOPE`. The dashboard `OAUTH_API_SCOPE` must keep resolving to the same base value as bex-api's `BEX_OAUTH_API_SCOPE`; the granular names should derive from that base so the lockstep rule stays a single knob.

## Steps

1. Extend `scopes_supported` in the RFC 9728 metadata to the full vocabulary (umbrella + granular), so discovery-driven MCP clients can request a subset; update `oauth_discovery_test.go` expectations.
2. Extend the consent vocabulary in `hydra-consent.ts`: granular scopes are recognized (not dropped by the intersection) and displayed distinguishably on the consent screen; a request pairing the API audience with only identity scopes is still refused `400 invalid_scope` — but any one API scope (umbrella or granular) now satisfies that check.
3. Apply identically on GET and POST decision paths (the round-14 fix covered both; keep them symmetric), leaving trusted/skip and platform-client exemptions untouched.
4. Verify lockstep: granular names derived from the shared base scope in both codebases; document the derivation next to `OAUTH_API_SCOPE` handling.
5. Run `cd dashboard && yarn test` (hydra-consent suite) and backend discovery tests.

## Acceptance criteria

- Discovery metadata lists the granular scopes; a client requesting only `bex.api.read` + identity scopes walks consent successfully and the grant survives the intersection.
- Audience-with-identity-only-scopes is still refused `400 invalid_scope` on GET and POST.
- `OAUTH_API_SCOPE`/`BEX_OAUTH_API_SCOPE` remain a single shared base value; no rename, no default change.

## Out of scope
