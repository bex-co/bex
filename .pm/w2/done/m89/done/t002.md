## Objective

Make the deploy job consume the exact artifact the build job produced: the build job outputs each image's immutable digest (`repo@sha256:…`), and the deploy job pins manifests to those digests — no window where a mutable tag could be re-pushed between build and deploy.

## Context

- Job outputs (`outputs:` + `needs.build.outputs.*`) are the GitHub-native channel; digests are not secrets.
- The existing pin flow pins by commit-derived tag (`4a92feb91f64`-style); moving the pin to digest form (or tag+digest) strengthens it — keep the human-readable tag alongside for operability if the manifests/tooling expect it.
- Check how `deploy/gitops` and the pin-commit script consume image references today before choosing tag@digest vs digest-only.

## Steps

1. Emit digests from the build/push steps as job outputs.
2. Thread them into the deploy job's manifest render/pin step.
3. Verify the rendered manifests reference the digest; confirm the cluster pulls by digest.

## Files

- `.github/workflows/deploy.yml`
- pin/render scripting it invokes (locate in `scripts/` / `deploy/`)

## Acceptance criteria

- [x] A deploy's applied manifests reference the digest the same run's build job emitted; re-pushing the tag between jobs cannot change what deploys.

The existing `^sha256:[0-9a-f]{64}$` validation and tag@digest manifest form are unchanged (the pin flow was already digest-based; the handoff now crosses the job boundary as outputs). `scripts/gitops-validate.sh`'s literal guards updated to the `needs.build.outputs.*` forms.
