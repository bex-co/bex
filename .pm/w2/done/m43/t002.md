## Objective

GraphQL `Service.id` returns the App *name* (`apps/graphql.go:254`, comment "id is the App name") while REST/MCP return the minted `srv-…` public id — a client joining surfaces by id fails, and ADR020's Known deviations don't list it. Audit every dashboard consumer of `Service.id` (routing params, cache keys, mutations), then either align GraphQL to the `srv-…` id (resolvers already accept both forms, `core/base.go:446-476`) or — if the blast radius is real — record it as a documented ADR020 known deviation. Independently, add `updatedAt` to the GraphQL `Service` type (REST/MCP expose it, `apps/render.go:46`).

## Context

- Dashboard is the only first-party GraphQL client (`dashboard/CLAUDE.md`); grep `dashboard/src` for service id usage in routes/queries.
- Changing `id` changes Apollo cache identity — check `dataIdFromObject`/typePolicies if configured.

## Steps

1. Inventory dashboard `Service.id` consumers; classify safe/breaking.
2. Decide align-vs-document; implement (code or docs/ADR020-identifiers.md §Known deviations).
3. Add `updatedAt` to `serviceGQLType`.
4. `go build ./... && go test ./...`; dashboard `yarn test` if queries changed.
