## Objective

GitHub #109 keeps listing `.github/workflows/native-base-image.yml` (4–5 failures, "never passed") even though the workflow is healthy. Make the detector stop counting a streak that can never clear, without hiding real ones.

## Context

- The counted runs (41020368108 and siblings, 2026-10-30) failed because the workflow file did not parse. Such runs have no jobs and GitHub names them after the file path, not the workflow's `name:`.
- The workflow is now `workflow_dispatch`/`workflow_call` only, and its dispatches pass (41360577241, 2026-11-01).
- `scripts/ci-red-streak.sh:69` lists `name,conclusion,status,event,…` per workflow id but groups by `.name` (`:88`) and counts only push/schedule events. The path-named group gets no further push/schedule runs, so it stays red forever.

## Steps

1. Add `workflowDatabaseId` (or the workflow id the loop already iterates at `:65`) to the listed fields and group by it. Report the workflow's current name.
2. A successful run of the same workflow from any event, newer than a streak of jobless parse failures, ends that streak. A push/schedule streak of real failures is still ended only by a push/schedule success.
3. Add red and green fixtures to `scripts/ci-red-streak.test.sh`: parse failures followed by a dispatch success (green); real push failures followed by a dispatch success (still red).

## Files

- [ ] The next `ci-red-streak` run's #109 no longer lists `native-base-image.yml`.

## Result (2026-11-10)

- `scripts/ci-red-streak.sh` groups by `workflowDatabaseId`, falling back to `.name` for id-less fixtures, and reports the workflow's own name.
- A push or schedule run named after its `.github/` path is one GitHub could not parse. Every bex workflow declares `name:`, which was checked. Such a run no longer counts once a success of the same workflow from any event is newer than it. Real push and schedule failures are unaffected.
- New fixtures (k)–(o): later dispatch success clears parse failures; dispatch success keeps a real push streak; parse failures with no later success stay red; parse failures after the last success count; same name, different workflows. Fixtures (k), (m) and (o) fail against the previous script.
- Live read-only run: `native-base-image.yml` is no longer listed. It surfaced a new red, `docs (prettier)`, which was fixed in `64ba8a85f`.
