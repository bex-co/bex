# Account-deletion isolated-stack evidence — 2026-08-29

Environment: the `w2`-owned `dev-2` stack, with real Kratos, Hydra,
PostgreSQL, OpenFGA, bex-api, the operator, Kubernetes, and dashboard. All
subjects, workspace ids, credentials, cookies, email addresses, and database
passwords are intentionally omitted.

## Workspace disposition and authorization

- The initial preview classified one sole-member workspace as `delete`, one
  shared workspace with another administrator as `leave`, and one shared
  workspace with no other administrator as `blocked`.
- `DELETE /v1/users` returned `409` with
  `ACCOUNT_DELETION_BLOCKED`; the response named only the blocking workspace,
  and no deletion-intent row was written.
- An API-key bearer attempting the same operation received `403`; only the
  direct Kratos-session request was accepted.
- After promoting the second member, the preview reported one `delete`, two
  `leave`, and zero `blocked` workspaces. The request returned `202` and wrote
  one durable `pending` intent.
- A second live browser session immediately received
  `ACCOUNT_DELETION_PENDING`, proving that onboarding could not recreate the
  personal workspace while cleanup was incomplete.

## Failure injection and convergence

- The Kratos admin endpoint was stopped after acceptance. The worker completed
  credential, OAuth, workspace, and subject cleanup, then remained in the
  `identity` state with a retry recorded; it did not report false completion.
- While Kratos was unavailable, PostgreSQL showed the sole-member workspace
  gone, both shared workspaces present, the deleting subject's memberships and
  SSH keys gone, and its API-key membership gone. The API-key bearer returned
  `401`, and its Hydra client was absent.
- Re-enabling Kratos allowed the worker to resume from `identity` and converge
  to `done`. A repeated worker pass was harmless.
- The Kratos identity lookup returned `404`; both pre-existing browser sessions
  and the old API-key bearer returned `401`.

## Kubernetes and survivor checks

- The sole-member workspace contained a private running App. Normal App
  finalization removed the App CR, tenant-local resources, registry state, and
  tenant namespace. No finalizer was manually removed.
- Both shared workspaces remained queryable by the other administrator. Their
  membership list no longer contained the deleted subject, and the remaining
  administrator retained management access.
- A public App fixture failed before deletion because the isolated cluster did
  not install Traefik's `Middleware` CRD; this did not affect deletion
  convergence or the successfully running private-App proof.

## Fresh identity proof

- Registration with the same synthetic email succeeded after completion and
  produced a different Kratos identity.
- The new browser session received a clean personal workspace and authenticated
  successfully. PostgreSQL showed one owner binding and one membership for the
  new identity, with no owner binding, membership, SSH key, notification
  preference, or pending invite for the deleted identity.

## Connected-agent OAuth cleanup

- The shared `dev-N` Kratos harness initially rejected Hydra's authorization
  return URL. The harness now allowlists the per-stack Hydra public origin, and
  `scripts/dev-env.test.sh` guards that interpolation.
- A disposable third-party public client completed a real authorization-code
  flow using PKCE S256 with `openid`, `profile`, `offline_access`, and
  `bex.read`. Hydra reported exactly one remembered consent grant for the
  synthetic subject before deletion.
- The account was deleted from the live `/settings#danger-zone` surface using
  the exact confirmation phrase. The browser reached the terminal
  `/auth/account-deleted` route; after worker convergence Hydra reported zero
  remembered grants and Kratos returned `404` for the identity.
- The unrelated third-party client itself still existed after subject cleanup,
  proving that deletion removed the subject grant rather than another party's
  client registration.

## Verification and fixture cleanup

- Backend, CLI, operator, and dashboard test suites passed. The dashboard ran
  2,832 tests across 385 files; typecheck, lint, production build, Go lint, and
  skill-layout validation also passed.
- The disposable OAuth client was deleted after verification. The `dev-2` and
  `dev-2-auth` namespaces plus every tenant namespace labelled for the `dev-2`
  control plane were deleted, the local dashboard and stale port-forward were
  stopped, and generated local credentials/runtime artifacts were removed from
  the workspace. No synthetic account, resource, credential, or connected-agent
