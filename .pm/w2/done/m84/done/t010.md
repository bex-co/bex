## Objective

Lock the real safety properties and failure modes of account deletion with meaningful automated coverage.

## Context

- Happy-path component tests are insufficient: the regressions to prevent are remint-after-delete, last-admin orphaning, live residual credentials, skipped subject columns, and cleanup continuing after an upstream failure in the wrong order.
- The store's real-Postgres tests and existing OpenFGA fakes can assert concurrency and ordering more honestly than snapshots.

## Steps

1. Add service table tests for direct-session authorization, exact confirmation, delete/leave/block matrices, stable errors, and idempotent repeated processing.
2. Add real-Postgres concurrency tests for begin intent, membership/admin races, onboarding suppression, claims/retries, cascades, anonymization, and the migration inventory guard.
3. Add strict Ory transport tests proving Hydra/credential cleanup precedes Kratos, `204`/`404` finalization, and retry on other responses/timeouts.
4. Add dashboard interaction/accessibility tests for preview consequences, blockers, exact confirmation, double-submit prevention, errors, terminal redirect, localization, and five-section skeleton parity.
5. Run backend `go test ./...` plus dashboard `yarn test`, `yarn typecheck`, `yarn lint`, and `yarn build`; run repository lint gates covering the touched modules.

## Acceptance criteria

- [ ] Tests fail if onboarding can remint after intent, if Kratos runs before cleanup, or if a last-admin workspace can be orphaned.
- [ ] Tests fail if any credential remains usable or a future subject column is unclassified.
- [ ] Concurrency/restart/idempotency and all external failure branches are asserted as behavior.
- [ ] Dashboard tests cover blockers, exact confirmation, accessibility, localization, terminal navigation, and skeleton structure.
- [ ] All relevant backend/dashboard/lint/build gates pass without weakening unrelated tests.

## Out of scope

- Coverage-number gaming or snapshot-everything tests.
