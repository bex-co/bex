## Objective

Prove the destructive workflow against real Kratos, Hydra, Postgres, OpenFGA, Kubernetes, and dashboard behavior rather than only mocks.

## Context

- `w2` owns isolated `.pm/w2/dev-2/`; never use shared namespaces/ports.
- The high-risk failures are cross-system: a workspace purger or Hydra call can fail after earlier steps, and a retry must neither remint a tenant nor skip the remaining cleanup.
- The DoD requires both deletion and preservation: sole-member resources disappear, while a shared workspace and its other admin remain.

## Steps

1. In `dev-2`, create a deletable user with a running resource, API key, SSH key, OAuth-connected agent, notification/push state, and two Kratos sessions; add it to one shared workspace with another admin.
2. Create a second workspace with other members but no other admin and verify preview/mutation block with actionable details and no intent written.
3. Resolve that blocker, request deletion in the real dashboard at desktop and narrow-mobile, and capture the disposition/terminal states with bare screenshot filenames.
4. Inject one mid-workflow dependency failure, restart/re-enable it, and prove the worker resumes without creating a replacement personal workspace or repeating harmful work.
5. Verify every deleted artifact/credential/session and the surviving shared workspace, then register the same email again and prove a new identity/clean personal workspace is created.
