## Objective

Turn the research into one explicit lifecycle contract before any destructive code lands.

## Context

- The current `/settings` page renders Kratos profile/password plus integrations, access, and security cards; it has no account-delete surface.
- Ory's admin API says `DELETE /admin/identities/{id}` permanently deletes the identity and returns `204` or `404`; deleting the IdP row alone would leave bex memberships, credentials, and subject-keyed records.
- `tenant_members.subject`, `tenants.owner_identity_id`, `owner_ids.subject`, `notification_settings.subject`, `ssh_keys.subject`, `ssh_sessions.subject`, `oauth_revocations.subject`, `github_connect_transactions.subject`, and creator/audit columns all need an explicit delete/cascade/anonymize/retain disposition. Hydra API keys and consent sessions are external subject-owned state. Stripe invoice retention is external/legal history, not a row to pretend can be erased with the Kratos identity.
- `.pm/FUTURE-MAYBE.md`'s generic ownership-transfer idea is broader than deletion. For this milestone, the contract is narrower: delete sole-member workspaces; leave a shared workspace only when another admin remains; block otherwise; clear a surviving workspace's deleted `owner_identity_id` binding without inventing general transfer.

## Steps

1. Add `docs/ADR086-account-deletion.md` recording the state machine, workspace disposition matrix, confirmation rule, caller-class restriction, retention/anonymization table, failure ordering, and operator recovery path.
2. Specify a preview and request contract with stable typed errors (`ACCOUNT_DELETION_BLOCKED`, `ACCOUNT_DELETION_PENDING`, and dependency-unavailable cases) and no raw identity ids in user-facing blocker copy.
3. Inventory every current Postgres subject/provenance column and every external identity/credential store; classify each as hard-delete, FK cascade, revoke, anonymize, or retained record with rationale.
4. Record why Kratos deletion is last and why the deletion-intent tombstone must suppress onboarding before any personal workspace is removed.
5. Define which API surfaces exist: authenticated self-delete over REST + GraphQL for a direct Kratos session; no MCP tool and no API-key/delegated-OAuth authorization for this irreversible account boundary.
