## Objective

Remove every credential and personal subject record while preserving only the workspace/audit history t001 explicitly classifies for retention.

## Context

- bex-minted Hydra clients carry `metadata["bex.co/created-by"]`; deleting memberships alone does not revoke them or already-minted tokens.
- Connected-agent consent lives in Hydra; SSH keys, notification preferences, OAuth revocation markers, connect transactions, and some session/audit history live in Postgres.
- Workspace-owned webhooks/registry credentials and audit rows must not disappear merely because their creator leaves a surviving workspace; their creator fields need the t001 anonymized tombstone shape.

## Steps

1. Add idempotent account-purger interfaces and implementations for Hydra API keys/bindings, Hydra consent sessions/tokens, SSH keys, push/web-push/device state, notification preferences, OAuth revocation/connect state, and every other hard-delete item in the inventory.
2. Revoke authorization/bindings before deleting credentials, preserving the existing fail-closed API-key order and invalidating bex-api positive caches across replicas.
3. Rewrite retained audit/provenance/session history to the ADR's opaque deleted-user marker before deleting the active subject→`own-` mapping; never retain email/name or a usable Ory id merely for display.
4. Make absent external records success and surface real dependency errors so the worker retries instead of reporting a false completion.
5. Add an inventory guard test that fails when a future migration adds a subject/provenance column without an account-deletion disposition.

## Acceptance criteria

- [ ] Every t001 hard-delete/revoke row and external object is absent after cleanup.
- [ ] Every retained row uses the documented opaque deleted-user marker and contains no email/name/raw active identity id.
- [ ] All bex-minted API keys and delegated OAuth grants for the subject immediately stop authorizing.
- [ ] Credential/binding cleanup is fail-closed and idempotent under 404/already-absent responses.
- [ ] The migration inventory guard detects an unclassified future subject/provenance column.

## Out of scope

- Deleting another member's credentials.
- Erasing legally retained Stripe invoice/payment records.
