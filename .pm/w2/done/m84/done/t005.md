## Objective

Expose one self-delete Core workflow and make the identity-provider delete the final irreversible, retry-safe step.

## Context

- The existing `workspaces.KratosIdentities` client is read-only and intentionally hides lookup errors; deletion needs a strict admin client that distinguishes success/already-gone from retryable failure.
- Ory's current admin API documents identity delete as permanent, returning `204` when deleted and `404` when already absent. It also exposes explicit all-session deletion; no cleanup should depend on a session after identity finalization.
- A dashboard SSR route that calls Kratos directly would bypass workspace, FGA, Hydra, credential, and store cleanup, making the dashboard a second control plane.

## Steps

1. Add an `accounts.Service` composition-root feature with preview/request verbs and narrow injected purgers; reject any caller whose `core.Identity.Method` is not a direct Kratos session.
2. Register authenticated `GET /v1/users/deletion-preview`, `DELETE /v1/users` and matching GraphQL preview/mutation fields; use `202 Accepted`/an explicit accepted view for durable work and stable typed blocker/pending errors.
3. Run workspace offboarding and subject cleanup to convergence, delete/invalidate all Kratos identity sessions, then call strict `DELETE /admin/identities/{escaped-id}` as the last external action.
4. Treat Kratos `204` and `404` as terminal success; never run a post-Kratos step that needs the caller or identity.
5. Wire worker startup, auth/scope/route inventories, dependency health behavior, audit event, and bounded structured metrics.

## Acceptance criteria

- [ ] Only the session subject can request its own deletion; API-key, machine, and delegated-human OAuth callers are refused.
- [ ] Preview is read-only; request requires the exact t001 confirmation and recomputes blockers server-side.
- [ ] Accepted deletion survives request cancellation and process restart.
- [ ] Kratos delete is provably last, `204`/`404` converge, and a nonterminal response is retried.
- [ ] Completion leaves no authenticated session or bearer chain for the deleted identity.
- [ ] Route/scope/authz inventories recognize the new operations and their intentional MCP absence.

## Out of scope

- Administrator-initiated deletion of another user's account.
