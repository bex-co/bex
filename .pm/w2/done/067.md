# 067 — The audit log records a workspace payment-method change, as Render's does

Why: Render's 2026-11-02 audit-log enum adds `UpdateWorkspacePaymentMethodEvent` (and `UpdateOrgPaymentMethodEvent`) (round-5 drift, w2/m251); bex changes a workspace's payment method through Stripe setup sessions but writes no audit entry, so `GET /v1/owners/{ownerId}/audit-logs` never shows who changed billing.

- **Render:** `auditLog.event` enum (pinned OpenAPI 2026-11-02) gains `UpdateWorkspacePaymentMethodEvent`, `UpdateOrgPaymentMethodEvent`, five Build Source events (w2/m254) and drops `CreateArtifactSourceEvent`.
- **bex:** audit vocabulary `lego/backend/internal/audit/service.go` (verb → Render event map); payment-method change completes in `internal/billing/sessions.go` (`verifiedSetupPaymentMethod`, the setup checkout completion). `UpdateOrgPaymentMethodEvent` does not apply (bex has no organization scope, ADR018 § Render audit-log paths).
- **Do:** record `UpdateWorkspacePaymentMethodEvent` (actor = the member who completed the setup session, workspace = owner) when the default payment method changes; serve it on REST/GraphQL/MCP audit reads and the dashboard audit view label (en/zh).
- **Acceptance:** completing a payment-method setup on dev-2 (Stripe test mode) adds exactly one `UpdateWorkspacePaymentMethodEvent` with the actor; no card details appear in the entry.

**Done 2026-11-03.** `billing.UpdatePaymentMethod` (`core.AuditVerbUpdatePaymentMethod`) → `UpdateWorkspacePaymentMethodEvent` (`internal/audit/service.go`). `CreateCheckoutSession` stamps the opener (`bex_actor`, `bex_actor_method`) on the session metadata; `CompleteCheckoutSession` writes the row through the ordinary audit sink with an id derived from the session (`core.AuditEvent.ID`; `PGStore.Record` now inserts `ON CONFLICT (id) DO NOTHING`), so redeliveries insert nothing (`TestPGAuditRecordWithDerivedIDRecordsOnce`); a failed write fails the webhook for a Stripe retry. The dashboard audit view renders the event name as it does for every event (no per-event labels exist), so no en/zh copy was needed. Portal-side changes → w2/070. The live Stripe test-mode walk on dev-2 waits on the mock cluster.
