# 066 — Render removed Postgres `parameterOverrides`; keep bex's or retire it?

Why: Render's 2026-11-02 OpenAPI drops `parameterOverrides` from Postgres create, update and detail (and the `postgresParameterOverrides` schema) while bex still accepts and returns it and the dashboard's Insights panel edits it (round-5 drift, w2/m251).

- **Render:** the field and schema are gone from `render-public-api-1.json` (pinned 2026-11-02); render.com docs search finds no Postgres parameter-override page.
- **bex:** `lego/backend/internal/postgres/{rest,service,mcp,graphql,insights}.go`; dashboard `features/databases/components/parameter-overrides-editor.tsx`.
- **Decision needed (user):** (A, recommended) keep it as a documented bex extension — Render clients never send it, so nothing breaks for them — and record it in ADR018 as a superset with sign-off; (B) retire it on every surface to match Render exactly, migrating existing overrides away first.
- **Acceptance:** ADR018's Postgres row records the chosen option with the user's sign-off; under (B) the field is refused by name on REST/GraphQL/MCP and the editor is gone.

**Blocked 2026-11-03 (`/loopx w2`).** The parity-sufficient option is (B), retiring the field. But retiring it would drop the parameter overrides customers have already applied to running Postgres instances, which is hard to reverse. Keeping it (A) is a divergence that needs the user's sign-off in ADR018. Either way the call is the user's. Release condition: the user picks (A) with sign-off, or picks (B) together with a disposition for existing overrides (migrate, keep applied but read-only, or drop).

## 解阻复核（2026-11-04，复核证据，待用户决定）

- **Render：** Postgres 文档没有任何客户可修改服务器参数的入口（render.com/docs/postgresql 及其子页，2026-11-04 查阅），API 也已删除该字段。客户能用的是标准的 `ALTER DATABASE … SET` / `ALTER ROLE … SET` 设置会话级参数。
- **bex：** 覆盖值存在 Database CR 的 `Parameters` 里，由 CNPG 应用（`lego/backend/internal/postgres/service.go` 的 `declaredParameters`/`normalizeParameterOverrides`）。只下线 API 和 dashboard 入口时，CR 里已有的值不动，数据库照常运行。

## 解阻决定（2026-11-04，来源：用户决定 D2=A）

- **决定：** 与 Render 一致，下线 `parameterOverrides` 的所有入口。
  - REST、GraphQL、MCP 的 Postgres create/update 收到该字段时，按名拒绝（400），错误信息指向标准 SQL `ALTER DATABASE … SET` / `ALTER ROLE … SET`。
  - 详情和读取接口不再返回该字段。
  - dashboard 去掉 Insights 面板的覆盖编辑器（`parameter-overrides-editor.tsx`）。
- **保留已生效值：** Database CR 里已有的 `Parameters` 不动，客户数据库继续按这些值运行，零中断；只是之后不能再自助修改。
- **对标依据：** Render 2026-11-02 的 OpenAPI 已删除该字段及 `postgresParameterOverrides` schema；render.com/docs/postgresql 及子页没有客户修改服务器参数的入口（2026-11-04 查阅）。
- **worker 下一步：** 按上述范围实现；ADR018 的 Postgres 行记录“对齐 Render，已下线”。
- **验收：** 三个接口都按名拒绝该字段；读取接口不再返回它；dashboard 没有编辑器；已有覆盖值的数据库 CR 不变；`parameter-overrides`（观测到的 `pg_settings` 只读视图）若属另一功能则保持不变。

## Done (2026-11-04, `/loopx w2`)

Implemented as decided (D2=A):

- **Refused by name:** REST create, REST PATCH and MCP `update_postgres` refuse `parameterOverrides` with 400 `POSTGRES_PARAMETER_OVERRIDES_UNSUPPORTED`. The message points at `ALTER DATABASE … SET` / `ALTER ROLE … SET`. The refusal also applies to dry runs and to `{}`.
- **Removed:** the bex-only write endpoints (REST `PUT …/parameter-overrides` and GraphQL `setDatabaseParameterOverrides`), the field on every detail read, and the dashboard editor.
- **Kept, read-only:** the declared set and the observed `pg_settings` view. Existing CR `spec.parameters` keep applying.
- **Docs:** ADR018, ADR009, ADR006 and ADR048 are updated.
- **Tests:** `w2_066_parameter_overrides_retired_test.go` and `update_relation_test.go`. The real-DB postgres/api/events suite, `make lint`, and the dashboard `yarn test` all pass.
- **GraphQL:** never had a create or update field for this. Its one mutation is removed, so it answers a schema error rather than the SQL guidance.
