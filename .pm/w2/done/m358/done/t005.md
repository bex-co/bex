## Objective

`sandboxes create --image <id|name>` starts the sandbox from the imported image instead of the base template.

## Context

- `lego/backend/internal/sandbox/service.go:399-414` (`refuseImage`, `SANDBOX_IMAGES_UNSUPPORTED`), `client.go:305` (`Client.Create(..., image, entrypoint, ...)`), `idle.go` (w2/m278 suspend/resume), `exec.go` (bash with a `/bin/sh` fallback).
- The base template sets `HOME=/home/render` and links `/bin/bash` in its entrypoint (ADR104 D2). An imported image keeps its own entrypoint semantics: bex's keep-alive entrypoint must still run.

## Steps

1. Resolve `buildId` (an `sbb-` id in the sandbox's group) or `buildName` (the group's newest succeeded image of that name). An unknown, failed, running or other-group image is a named 400/404 with Render's wording.
2. Start the sandbox with the image's registry reference and bex's keep-alive entrypoint; create `$HOME` if the image lacks it; exec falls back to `/bin/sh` when the image has no bash.
3. Keep `--image` mutually exclusive with `--from`/`--snapshot-id`, as the CLI does.
4. Delete `refuseImage` and `SANDBOX_IMAGES_UNSUPPORTED`.

## Files

- `lego/backend/internal/sandbox/{service.go,client.go,exec.go,idle.go}`

## Acceptance criteria

- [ ] Tests: create by id and by name start from the image's digest; a name picks the newest succeeded image; a failed or other-group image is refused.
- [ ] A sandbox from an image without bash still runs `exec`.
- [ ] Suspend and resume of an imported-image sandbox keep its files (unit/fake-client test; production in t007).

## Out of scope

- Memory/process survival across suspend (w2/m322).

## Result (2026-11-12)

- `buildId`/`buildName` on REST create, GraphQL `createSandbox` and MCP `spawn_sandbox`; resolution runs in the sandbox's group before admission, so a refused image takes no slot. Name = the group's newest succeeded build.
- Refusals: unknown or other-group build 404 `build_not_found`; not succeeded 400 `SANDBOX_IMAGE_NOT_READY`; both named 400; no registry 503 `SANDBOX_IMAGES_UNAVAILABLE`. The raw `image` key now fails decoding (not a Render field). `refuseImage` and `SANDBOX_IMAGES_UNSUPPORTED` are gone.
- The sandbox keeps the template's entrypoint, environment and size; the image is `<registry>/snapshots/<ns>/images/<sbb>@<digest>`, pulled with the template's `bex-snapshot-pull` Secret.
- Found and fixed in passing: the sandbox's bex-only `image` field and its charge label would have shown the internal registry address; both now show the build's `sbb-` id (`displayImage`).
