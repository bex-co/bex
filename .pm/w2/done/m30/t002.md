## Objective

Render's `POST /services/{id}/deploys` accepts `commitId`, the SHA of a specific git commit to deploy (default: latest commit on the connected branch); it does not disable autodeploy and is rejected for cron jobs. Add the narrow version of this: thread an optional commit ref through to the build Job's git checkout step, without building full commit-object tracking in deploy history (that's a documented follow-up, not this task).

## Context

- `lego/backend/internal/deploys/service.go` `Trigger(ctx, service string)` — signature needs a second param (or an options struct — pick whichever keeps `Rollback`'s call site clean, since it must not gain a spurious `commitId`).
- `lego/operator/internal/build/build.go` — the git-clone/checkout step the build Job runs; today it always checks out `App.spec.branch`'s HEAD. Needs a way to accept a specific ref instead (an App-level field the operator reads, or a Job env var the Trigger call sets directly — decide based on how `RestartedAt`-style verb-as-field plumbing already works in `app_types.go`).
- Cron jobs: `deploys.Trigger` already checks `a.Spec.Suspended`; add the same-shaped rejection for `commitId` on a cron job (`core.ErrBadRequest`, matches Render's documented restriction).

## Steps

1. Add `CommitID string` (or equivalent) to whatever request shape `Trigger` takes.
2. Reject non-empty `commitId` for `Type: cron_job` with a named error.
3. Thread the ref through to the build Job's checkout (new `App.spec` field, verb-as-field pattern like `RestartedAt`/`RunAt`, or a one-shot Job param — whichever avoids polluting the CR's steady-state spec with a value that should only apply to one deploy).
4. Confirm the deploy row records which `commitId` (if any) it targeted, for `get_deploy`/`list_deploys` to report it back later (even before full `Deploy.Commit` object work — see the milestone's deferred follow-up).

## Files

## Acceptance criteria

- [ ] Triggering a deploy with a `commitId` builds from that exact commit, not branch HEAD.
- [ ] Omitting `commitId` behaves exactly as today (branch HEAD).
- [ ] A `commitId` on a cron job is rejected with a clear error, never silently ignored.
