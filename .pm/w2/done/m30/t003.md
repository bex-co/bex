## Objective

Render's `deployMode` is `"deploy_only"` (redeploy the last successful build without rebuilding) or `"build_and_deploy"` (default, full rebuild). bex has no concept of a cached build artifact distinct from "rebuild from source" — confirmed: any `App` generation bump unconditionally triggers a rebuild for a repo-backed service (`lego/operator/internal/controller/app_controller.go`, no distinction between "redeploy the same build" and "rebuild"). Implement `deployMode` honestly rather than silently treating `deploy_only` as a no-op success it can't actually deliver.

## Context

- `lego/backend/internal/deploys/service.go` `Trigger` — needs a `DeployMode` field alongside `t002`'s `CommitID`.
- Repo-backed service + `deployMode: "deploy_only"`: reject with a typed, clear error ("bex has no build cache — every redeploy rebuilds from source"; use whichever error-code convention `w2/m28`'s typed-error envelope established, if it's landed by the time this runs — check `.pm/w2/done/m28/` for the pattern).
- Image-backed service + `deployMode: "deploy_only"`: accept and behave identically to `build_and_deploy` — there's nothing to build either way, so the two modes genuinely coincide for this service type. Don't reject a mode that happens to be a no-op distinction, only reject the one that would otherwise lie about rebuilding.
- `deployMode: "build_and_deploy"` (or omitted): today's existing behavior, unchanged.
- Cross-check against Render's own documented constraint: `deploy_only` cannot be combined with `commitId`/`imageUrl`/`clearCache` (those are build-related fields) — reject the combination with a clear error rather than silently ignoring one of them.

## Steps

1. Add `DeployMode` (string enum: `deploy_only` | `build_and_deploy`, default `build_and_deploy`) to `Trigger`'s request shape.
2. Repo-backed + `deploy_only` → typed rejection, no partial/fake success.
3. Image-backed + `deploy_only` → proceeds exactly like `build_and_deploy` (restart with current image).
4. `deploy_only` combined with `commitId`/`clearCache` → rejected (mirrors Render's own documented constraint).

## Acceptance criteria

- [ ] `deployMode: deploy_only` on a repo-backed service returns a clear, typed error — never a 2xx that silently rebuilds anyway.

- [ ] `deploy_only` + `commitId` (or `clearCache`) together is rejected, not silently resolved by picking one.
