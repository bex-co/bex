## Objective

One rule, every exit. A membership can end three ways — an admin removes you, you leave, or your account is deleted — and all three must dispose of your machine credentials identically.

## Context

- Account deletion already does it (`accounts.Service.process` → `APIKeys.CleanupSubject`, `internal/accounts/service.go:197`), but **globally by subject**, not per workspace, which is correct for that path and must stay that way.
- `w5/m102` adds `members.LeaveWorkspace`; it must call the same workspace-scoped disposition t002 adds. If m102 has not landed yet, leave a failing-by-default guard or a test that will fail when it does, rather than a silent gap.
- `members.AccountOffboarder.Remove` (`internal/members/service.go:1014`) is the trusted background adapter used by the account worker — it must **not** double-dispose (the worker already cleaned the keys globally in an earlier state).

## Steps

1. Apply the disposition to the leave path.
2. Confirm `AccountOffboarder.Remove` does not re-run it, and assert that with a test (double-disposal must be a no-op, not an error).
3. Add a single enumeration test over the three exit paths asserting each ends with the same key state.

- `lego/backend/internal/accounts/service.go` (only if ordering needs a note)

## Acceptance criteria

- [x] All three exit paths end with the same key disposition.
- [x] The account-deletion path is not double-running the cleanup.
- [x] An enumeration test covers all three and would fail if a fourth exit path shipped without the rule.
