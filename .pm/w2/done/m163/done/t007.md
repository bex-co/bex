## Objective

Prove the property that matters — after the membership ends, the credential cannot act — rather than only asserting that a cleanup function was called.

## Context

- Real Postgres and OpenFGA run in backend CI (`BEX_TEST_DB_URI`, `BEX_TEST_OPENFGA_URL`); the Hydra side is faked in `apikeys` tests today (`apikeys/apikeys_test.go`), so the end-to-end assertion is: binding row gone, tuple gone, and the auth gate refuses a request carrying that client id.
- Mock-echoing is the failure mode to avoid here: a test that asserts `CleanupSubject` was invoked proves nothing about access.
- Useless-test rules apply.

## Steps

1. Scenario test: member with keys in two workspaces is removed from one — the key bound to that workspace reaches the decided state, the other is untouched.
2. Access test: a request bearing the disposed key is refused by the gate (or, under the retention decision, is *allowed* and the badge is asserted — pin whichever the decision was).
3. Cover the three exit paths (remove / leave / account deletion) converging on the same state.
4. Failure-path test: key disposition fails → removal surfaces the error and leaves a retryable state.
