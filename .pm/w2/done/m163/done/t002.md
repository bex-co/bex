## Objective

Apply t001's decision inside `members.Remove`, reusing the account-deletion path's existing machinery rather than writing a second implementation of key teardown.

## Context

- The seam already exists and is trusted: `apikeys.AccountTeardown.CleanupSubject` (`lego/backend/internal/apikeys/service.go:114`) lists keys, matches `CreatedBy`, unbinds (`Binding.UnbindKey`) then deletes the Hydra client — in that order, so a partial failure leaves an unbound-but-live client rather than a bound orphan.
- Injection: the members service would need the apikeys teardown adapter wired from the composition root (`internal/api/server.go`), the same way `accounts.Service` receives it.
- Ordering inside `Remove`: the member's own tuple is revoked before the row is deleted (`members/service.go:981-994`). Key disposition should sit inside that same fail-closed window and surface its error rather than swallowing it.
- Scope check: `CreatedBy` alone is not enough — a subject may have created keys in several workspaces. Only keys **bound to the workspace being left** may be touched (`Binding.TenantForKey`).

## Steps

1. Wire the apikeys teardown seam into `members.Service` from the composition root.
2. Apply the decided disposition, scoped to keys bound to *this* workspace and created by *this* subject.
3. Keep the error surfaced (a failed key revocation must not report a clean removal).
4. Verify the degraded configuration: with the store or Hydra unavailable, the behavior is explicit, not a silent skip.

## Files

- `lego/backend/internal/members/service.go`
- `lego/backend/internal/apikeys/service.go` (seam only, if it needs a workspace-scoped variant)
- `lego/backend/internal/api/server.go` (wiring)

## Acceptance criteria

- [x] Removal applies the decided disposition only to keys created by the removed subject **and** bound to that workspace.
- [x] Keys the same subject created in other workspaces are untouched.
- [x] A failure in key disposition is surfaced, not swallowed.
- [x] No second implementation of key teardown exists.
