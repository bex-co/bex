## Objective

Emit `:6432` in `internalConnectionPoolString` and `externalConnectionPoolString` (`lego/backend/internal/postgres/service.go`) and in the operator's `<db>-pooler-app` Secret `uri` (`reconcilePoolerConnectionSecret`). Blueprint `fromDatabase: connectionPoolString` resolves that Secret through `secretKeyRef` (`apps/deploy.go`), so linked services get 6432 on their next deploy, while running pods keep a 5432 URI that still works. Name the port once per module (a `pgPoolerPort` constant) rather than as a literal.

## Acceptance criteria

- [ ] Connection-info tests on REST/GraphQL/MCP assert `:6432` for both pooled strings, and `:5432` for the direct ones.
- [ ] The operator envtest asserts the pooler Secret `uri` names 6432.

## Result (2026-11-10)

- One exported constant, `appv1alpha1.PoolerPort = 6432` in the CRD contract (documented on `Status.PoolerHost`), is used by:
  - bex-api's `internalConnectionPoolString` (the external string went back to 5432 in `3bc94d538`: the edge cannot listen on 6432 yet, see t003);
  - the operator's `<db>-pooler-app` Secret `uri`.
- The direct strings keep 5432.
- Tests: `advanced_test.go` pins internal 6432, external 6432 and direct 5432; `public_certificate_test.go` the external form; `database_test.go` the Secret `uri`.
