## Objective

`poolerSpec` (`lego/operator/internal/controller/database_controller.go`) adds `serviceTemplate.spec.ports: [{name: pgbouncer-6432, port: 6432, protocol: TCP, targetPort: pgbouncer}]`. Because neither the name nor the port is CNPG's default, CNPG still adds its `pgbouncer`/5432 port, so the `<db>-pooler` Service serves both. Existing Poolers pick it up on their next reconcile. Unit-test the spec, and check against the CNPG version deployed (`deploy/helm-artifacts.lock`) that the default port is kept.

## Acceptance criteria

- [ ] The `poolerSpec` unit test pins the 6432 port and its `targetPort: pgbouncer`.
- [ ] On dev-2 the `<db>-pooler` Service lists ports 5432 and 6432 (t004).

## Result (2026-11-10)

`poolerSpec` adds `serviceTemplate.spec.ports: [{name: pgbouncer-pooled, port: appv1alpha1.PoolerPort (6432), targetPort: pgbouncer}]`. CNPG keeps its default only when no template port is named `pgbouncer`. On dev-2 (CNPG from `deploy/helm-artifacts.lock`) the `<db>-pooler` Service listed `pgbouncer=5432->pgbouncer` and `pgbouncer-pooled=6432->pgbouncer`. `TestPoolerSpec` pins the port exactly.
