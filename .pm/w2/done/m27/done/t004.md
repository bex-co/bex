## Objective

Add a Prometheus/Alertmanager rule that pages if `bex-db`'s scheduled backup hasn't succeeded recently, so a silently failing control-plane backup is caught before it's needed — the same class of gap `w1/m26/t004` closed for Zot's volume usage.

## Context

- `w3/m6` (Platform alerting) shipped the Alertmanager rule pack this extends.
- CNPG exposes backup-related metrics (e.g. `cnpg_pg_stat_archiver_*`, or `Backup`/`ScheduledBackup` resource status) that can back a staleness rule — check what CNPG's Prometheus exporter actually surfaces.

## Steps

1. Add a rule alerting if no successful `bex-db` backup has completed within the expected window (e.g. 25 hours for a nightly schedule).
2. Verify the rule passes `promtool check rules` (or equivalent) if the repo uses that pattern.
