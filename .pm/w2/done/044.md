# Remove the nonexistent service-get command from Bex CLI guidance

Why: the checkout’s Bex-owned job-plan hint directs users to a command this pinned CLI does not provide; correct it before the next launcher release.

- **Severity / ownership:** minor / Bex launcher documentation. No hosting failure demonstrated.
- **Estimate:** 20m, no dependencies. Source: continuing CLI QA, 2026-10-03 UTC; ADR008 usable hosting CLI and the existing metadata-branding scope in `docs/bex-cli.md`.
- **Versions:** checkout build `f296747d9`; branding and launcher code unchanged through research HEAD `4ab2566f4`. Pinned Render CLI v2.27.0, commit `a764810a768202704e7206eb7b87a47211fcd98e`. Installed `/opt/homebrew/bin/bex` v0.2.1 is a control, not a reproduction: it still has the older Render docs link already addressed by w7/045. No deployed-server revision is needed for this local help defect.

## Reproduction

```sh
bex jobs create --help
bex services --help
```

On the checkout, the first command exits 0 with empty stderr and includes:

```text
# Create a job with a specific plan
# Plan IDs match the service plans listed by `bex services get`
bex jobs create srv-abc123 --start-command "npm run worker" --plan-id plan-srv-006
```

The actual `services` child commands are **create, delete, instances, update**; there is no `get`. The parent is the list command, not a service-detail selector. Two fresh checkout processes reproduce the bad hint; release help retains the old upstream URL. All tested help calls exit 0 with empty stderr. Complete stdout/stderr/exit/duration captures, including the full command tree and release control, are in [044-evidence.json](044-evidence.json).

Expected: Bex-owned help should not recommend a nonexistent command. This does not require adding a new CLI verb or changing upstream argument validation.

## Cause and bounded fix

`lego/cli/internal/branding/branding.go:110` explicitly injects the false hint when replacing the Render jobs-plan URL. The consumer is the normal HelpFunc → brandTree → Cobra Example rendering path. Pinned `cmd/service.go:30–49,260–293` defines the listing parent and `cmd/servicecreate.go`, `serviceupdate.go`, `servicedelete.go` plus instance setup supply the supported children. The server's REST by-ID read is not a CLI `get` command.

Remove this replacement comment, as the original w7/045 proposal explicitly allowed, or use guidance verified against the actual command tree. Do not substitute another unsupported plan-selection claim: `jobs/service.go` currently persists the supplied plan ID and separately submits the Job; the independent jobs scope/RBAC decision remains w4/m116. Preserve the upstream example commands and flags and the narrow hostname-rewrite boundary.

The same inaccurate CLI wording appears in `docs/cli-compatibility-checklist.md:40`: distinguish the REST by-ID `GET` from the actual `bex services -o json` list when describing deletion readback. These are the **two** occurrences found in the CLI source and its primary guide/checklist. This is a small copy correction, not a backend/read-contract change; REST, GraphQL, MCP and dashboard behavior stay outside this item.

## Acceptance and dedupe

- Fresh checkout `jobs create --help` no longer suggests `services get` and does not restore the removed Render-specific jobs-plan link. Existing jobs example commands/flags and nested Bex branding remain intact.
- The compatibility checklist accurately distinguishes REST detail reads from CLI listing. Verify every newly suggested command against this pin's help tree; run the existing focused `TestBexNestedHelp` check.
- `git log -S 'Plan IDs match the service plans'` identifies `68a7e73fc` (w7/045) as the producer. That completed item removed the wrong vendor link but introduced this invalid command; its real-binary test (`lego/cli/main_test.go:922`) checks branding/link absence, not command existence.
- Searched open/done `.pm`, CLI sources and primary CLI docs for the exact hint, `services get`, unsupported/nonexistent-command combinations: no existing item addresses it. w2/043 is separate late-command completion timing; w4/m116 is the one-off-job scope/RBAC decision. This note does not reopen that excluded execution surface, change plan handling, or authorize job creation.
- No wire trace or runtime probe is needed for the reproduced help mismatch. Help bootstrap network behavior was not audited. No hosting resources, shell configuration, or personal CLI state were changed.

## Resolution (2026-10-02)

**DONE.** `lego/cli/internal/branding/branding.go` now drops the render.com job-plan comment instead of replacing it with the invalid `bex services get` hint; the upstream example commands and `--plan-id` flag are unchanged and still rewritten to `bex`. `TestBexNestedHelp/jobs_create` now also asserts `services get` is absent (mutation-checked: fails against the previous branding code). `docs/cli-compatibility-checklist.md` w3/m81 bullet now names the REST by-id `GET /v1/services/{id}` and the CLI's `services -o json` list. Gates: `cd lego/cli && go test ./...` and `make lint` (all four modules, 0 issues) green.
