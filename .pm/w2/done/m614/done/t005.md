## Objective

Implement the **Linked Services** tab (`/build-sources/$buildSourceId/services`) for inspecting/linking/unlinking services and the **Build-time Environment** tab (`/build-sources/$buildSourceId/environment`, git sources only) reusing the dashboard's env-var, secret-file, and workspace env-group editors in save-only mode.

## Context

- `buildSource.serviceLinks` lists linked services; GraphQL `linkBuildSource` links an existing service (requiring `startCommand` for native sources and forbidding it for Docker/image sources; enforcing git-source region match).
- Backend GraphQL `secrets` (`envVars`, `secretFiles`, `patchServiceEnvironment`, `setEnvVars`, etc.) already scopes `bds-…` through `envScope` (`secrets/staged.go:102-108`) with `WithStagedWrite(ctx)` (save-only, never deploys).
- Backend GraphQL `envgroups` (`linkEnvGroup`, `unlinkEnvGroup`) already resolves `bds-…` via `core.WithBuildSources(ctx)` (`envgroups/service.go:1455, 1544`) and saves without deploying.
- Render forbids build-time environment on image-backed Build Sources (`build_sources.go:222`).

## Steps

1. Create `dashboard/src/routes/build-sources.$buildSourceId.services.tsx` and `BuildSourceServicesTab`:
   - List all linked services with clickable link to the service, type badge, region, and auto-deploy indicator.
   - Provide **Link existing service** dialog (`can_create`-gated) picking an eligible workspace service (excluding `static_site` and already-linked services, prompting for `startCommand` when the Build Source is native-runtime) calling `linkBuildSource`.
   - Provide clear navigation to unlink/change source (or inline link-to-another-source guidance consistent with Render's PATCH source rules).
2. Create `dashboard/src/routes/build-sources.$buildSourceId.environment.tsx` and `BuildSourceEnvironmentTab`:
   - Redirect image-backed Build Sources to `/build-sources/$buildSourceId` (or render an explicit unsupported notice).
   - Reuse the dashboard's shared environment-variable, secret-file, and workspace env-group editors wired against `serviceId: buildSourceId` with **Save changes** only (no "Save and deploy" CTA, clearly explaining changes apply on the next build).
   - Respect `can_create` (writes) and `can_view_sensitive` (reveal/export) gates.
3. Add breakpoint-matched skeletons for both routes (`1440px` and `390px`).
