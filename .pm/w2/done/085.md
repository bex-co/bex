# The isolation matrix's agent-session phase step relabels a running sandbox Pod, which `bex-sandbox-pods` now refuses (issue #196)

Why: the weekly `isolation-matrix.yml` has stayed red since the label-immutability rule shipped. A red run that only means "the probe is out of date" hides a real regression the next time one happens.

- **Where:**
  - `scripts/verify-sandbox-isolation.sh:1042`: the probe step "verify agent-session setup/agent egress phases" runs `kubectl label pod "$pod_a" "bex.co/agent-session=…" --overwrite` on a sandbox Pod that already exists.
  - `deploy/gitops/base/sandbox-pod-admission.yaml:46`: since `48b78ea2c` (w2/m536, 2026-11-21) the policy keeps `bex.co/agent-session` and the other identity and egress labels strictly immutable on UPDATE.
- **Seen:** `isolation-matrix.yml` run 45004293073 on `main`, 2026-11-22.
  - The ADR043 tenant leg passed 17/17 and the ADR122 broker leg passed.
  - The ADR042 leg passed every check up to that step, then failed at it: `ValidatingAdmissionPolicy 'bex-sandbox-pods' … denied request: sandbox Pod identity and egress labels … must be valid at CREATE … and remain strictly immutable on UPDATE`.
  - The run updated issue #196. That issue was opened on 2026-11-19 by an earlier, different failure: a missing `bex-tenant-sandbox-api` RoleBinding.
- **Production is not affected.** Production sets the session label when the Pod is created (`lego/backend/internal/agentsession/contract.go:204`), so the rule refuses only the probe's relabel.

## Fix

- Make the probe's agent-session fixture a Pod that carries `bex.co/agent-session` from CREATE, the way production creates session Pods.
- Add a negative check that relabelling an existing sandbox Pod is refused.
- Done when a dispatched `isolation-matrix.yml` on `main` is green and #196 closes on recovery.
