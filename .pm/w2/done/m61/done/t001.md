## Objective

Create one testable inventory and identity scheme for every object an App generates outside owner-reference reach.

## Context

- Cross-namespace clone/env/file/registry Secrets and kpack ServiceAccounts can outlive an App.
- Some copied Secrets use the source Secret name rather than App identity in `app.bex.co/app`.
- Finalizers cannot delete what they cannot reliably list.

## Steps

1. Enumerate generated names, namespaces, kinds, labels, and retention requirements for build, kpack, publish, pre-deploy, registry, static, and TLS artifacts.
2. Standardize App UID/name/workspace labels on every generated object and Pod template.
3. Add inventory assertions that fail when a new generated kind lacks ownership/cleanup metadata.

## Files

- `lego/operator/internal/build/`
- `lego/operator/internal/controller/app_controller.go`
- `lego/operator/internal/predeploy/`
- `lego/operator/internal/publish/`
- `lego/operator/internal/registry/`
- `docs/ADR039-operator-audit-and-platform-reuse.md`

## Acceptance criteria

- [x] Every cross-namespace or external artifact has a deterministic App identity and documented cleanup owner.
- [x] Recreated Apps with the same name can distinguish old UID-scoped residue safely.
- [x] A test requires inventory updates when a new generated artifact class is added.

## Out of scope

- Deleting the artifacts; t002/t003 implement reclamation.
