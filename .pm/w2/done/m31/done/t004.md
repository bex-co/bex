## Objective

bex's `list_deploys` MCP tool currently takes only `serviceId` — Render's own official MCP server's `list_deploys` tool (`pkg/deploy/tools.go`) takes `serviceId`, `limit` (default 10, min 1, max 100), and `cursor`. Match it — this is a gap against Render's MCP surface itself, not just the REST API.

## Context

- `lego/backend/internal/deploys/mcp.go` — `listDeploysArgs` struct + the `list_deploys` tool registration.
- Render's tool description: "List deploys matching the provided filters. If no filters are provided, all deploys for the service are returned." — bex's tool description should be updated to stop implying (or should now honestly state) pagination support.
- Render's response shape returns the deploys JSON plus a trailing `cursor: "<value or empty string>"` marker in the text result — match this exact response convention if straightforward, since it's what a Render-trained agent already expects to parse.

## Steps

1. Add `Limit *int` (default 10, clamp 1–100) and `Cursor *string` to `listDeploysArgs`.
2. Pass through to `Service.List`.
3. Match Render's response-text convention (deploys JSON + trailing cursor marker) if it doesn't conflict with bex's existing `listDeploysResult` JSON-object convention (MCP tool outputs must be JSON objects per the existing code comment) — if the two conventions conflict, keep bex's existing JSON-object shape and simply add a `cursor` field to it, documented as the bex-shaped equivalent.

## Files

- `lego/backend/internal/deploys/mcp.go`

## Acceptance criteria

- [ ] `list_deploys` accepts `limit`/`cursor` and behaves identically to REST/GraphQL's equivalent query.
- [ ] Default behavior (no `limit`/`cursor`) is unchanged... or, if a default `limit` of 10 is now applied (matching Render's own default), this is called out explicitly as an intentional behavior change from bex's previous "always return everything" default — not a silent regression for existing callers expecting the full list.

## Out of scope

- A dedicated `trigger_deploy`/`create_deploy` MCP tool — Render's own MCP server has none, confirmed in `w2/m30`'s audit.
