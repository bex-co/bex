## Objective

Make every node request a CA-signed kubelet serving certificate: add `rotate-server-certificates: "true"` to the CAPD machine templates (the CAPH templates already have it), then verify on the mock cluster that a new node's `kubernetes.io/kubelet-serving` CSR is approved by the t001 approver and the kubelet serves the signed cert.

## Context

- CAPH is **already done**: `infra/clusterapi/overlays/hetzner-caph/cluster.yaml` sets `rotate-server-certificates: "true"` at lines 114, 287, 831, 851, 1231 and `sandbox-pool.yaml` at line 204 — all via `kubeletExtraArgs` (the flag form, not `KubeletConfiguration.serverTLSBootstrap`; keep that style for consistency).
- CAPD is **missing it**: `infra/clusterapi/overlays/local-capd/cluster.yaml` has `kubeletExtraArgs` blocks at ~lines 386, 391, 445, 476 (control-plane init/join + worker KubeadmConfigTemplates) with no rotation flag — which is why the local overlay still needs `--kubelet-insecure-tls`.
- Without an approver the flag alone leaves kubelets on a self-signed fallback cert while the CSR sits Pending — hence the t001 dependency.

## Steps

1. Add `rotate-server-certificates: "true"` to each CAPD `kubeletExtraArgs` block (control-plane and worker templates).
2. Recreate or scale the mock cluster (`bash scripts/mock-cluster.sh` / `scale N`) so a node boots with the flag.
3. Verify: `kubectl get csr` shows `kubernetes.io/kubelet-serving` CSRs Approved,Issued by the approver (check its logs); `openssl s_client` against the node's :10250 returns the CA-signed cert with node IP/DNS SANs.
4. Confirm existing CAPH prod templates need no edit; note in the task log that already-running prod nodes only pick the flag up on the next ADR053 template rotation.
