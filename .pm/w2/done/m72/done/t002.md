## Objective

Move the build state the synchronous wait loop currently holds in-process into the App CR's status so a watch-driven reconciler can resume it from any manager: current build phase (admitted/building/pushing), the generation being built, elapsed-budget bookkeeping (queued-vs-building split), and the new **pending-generation slot**. This is the data-model half of ADR060 D1; per D1 it also fixes the restart wart where an adopted build got a fresh 30-minute operator-side clock.

## Context

- lego/types/ owns the CRD contract (`app.bex.co/v1alpha1`); status additions need deepcopy/codegen (`make manifests generate` from lego/operator/).
- lego/operator/internal/build/build.go + native.go hold today's in-process wait state; lego/operator/internal/controller/app_controller.go dispatches it.
- The pre-deploy observer (lego/operator/internal/predeploy) is the existing non-blocking shape to mirror.
- Deterministic Job names `bld-<name>-gen-<generation>` already give idempotent adopt-on-restart.

## Steps

1. Design the status fields: active build (generation, phase, start/scheduled timestamps for the queued/building split) + `pendingGeneration` (the slot — a single value, overwritten by newer).
2. Add them to lego/types with markers; run `make manifests generate` and commit the regenerated deepcopy/CRD.
3. Thread reads/writes through the build package without changing dispatch semantics yet (behavior-preserving refactor; the poll loop persists its state instead of holding it).
4. `make test` green.

## Files

## Acceptance criteria

- [ ] App status round-trips active-build phase + pending generation; a manager restart mid-build reconstructs identical budget state from status + Job observation (envtest).
- [ ] No behavior change yet: existing build/cancel tests still pass unmodified.
- [ ] `make test` green (codegen/fmt/vet run as part of it).

## Out of scope

- Removing the synchronous wait loop (t003) or changing supersede semantics (t004).
