## Objective

Record the semantic decision before code moves: newest-wins is redefined to act on the **pending slot only** — a running build Job always runs to completion; a newer generation overwrites the App's single pending slot; once the image is pushed the generation's rollout proceeds and newer work waits. The explicit user Cancel verb (w2/m10) remains the only human-initiated preemption of a running build; failure/timeout releases the slot. Amend ADR060 (build-worker reliability) with this as a new decision under D1, and correct ADR034's "a newer revision cancels the older active build" line to point at the amendment.

## Context

- docs/ADR034-scalable-build-pipeline.md:33 states the current cancel-active semantics.
- docs/ADR060-build-worker-reliability-and-performance.md D1 (§"Non-blocking build state machine") is where the state machine that hosts the pending slot is specified.
- Reference behavior: Render/Vercel supersede queued deploys, never in-flight ones.
- Motivation: production livelock — push cadence < build duration ⇒ zero completed deploys.

## Steps

1. Add the supersede-semantics decision to ADR060 (guarantee statement: ≥1 completed deploy per build-duration window; eventual convergence to latest commit; exceptions: explicit Cancel, `activeDeadlineSeconds`).
2. Amend ADR034's newest-wins line with a pointer to the ADR060 decision (do not silently rewrite history — mark it superseded-by).
3. Note the deliberate divergence-then-alignment with Render in the decision text (bex was more aggressive; new behavior matches Render's queued-supersede).
