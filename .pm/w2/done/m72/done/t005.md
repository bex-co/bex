## Objective

Make the new semantics observable (the ADR060 D5 subset this milestone needs): outcome-labeled build counters that distinguish `superseded` (pending slot overwritten — expected, cheap) from `canceled` (user verb — human intent) from `failed`/`succeeded`/`timeout`, plus the `bex_build_queue_seconds` vs run-seconds split from the t002 timestamps. If running-cancel counts ever grow post-ship outside the Cancel verb, a supersede path was missed — that's the tripwire this exists for.

## Context

- The operator's only Prometheus collector today is the egress meter (ADR060 §"Zero build-plane metrics"); follow its registration pattern.
- t002 status timestamps already carry admitted/scheduled/terminal times — the histograms read them, no new bookkeeping.
- `BEX_PROM_URL` scraping and dashboards are out of scope; this task only emits.

## Steps

1. Add outcome-labeled counter(s) (`superseded|canceled|failed|succeeded|timeout`) incremented at the single terminal-observation point from t004.
2. Add `bex_build_queue_seconds` / run-seconds histograms from status timestamps.
3. Unit-test label correctness for each terminal path (supersede vs Cancel verb especially).
