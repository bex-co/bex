## Objective

Repair the production datastore DNS contract exposed by the first m57 live run: reconcile `*.db.bex.co` and `*.kv.bex.co` as DNS-only A/AAAA records pointing directly at the Hetzner edge load balancer, never ordinary Cloudflare-proxied records, and add a read-only drift gate.

## Context

- The 2026-07-18 m57 run created an available, source-restricted public Key Value and resolved an external `rediss://` hostname, but both the official CLI and a bounded TCP preflight could not connect to port 6379.
- Hetzner's public API reported the `bex-traefik` 6379 service and multiple worker targets healthy. The generated Key Value hostname resolved to Cloudflare's HTTP proxy address set instead of the load balancer; `*.kv.bex.co` and `api.bex.co` currently resolve to the same A/AAAA sets.
- ADR009 and ADR021 already require gray-cloud/DNS-only wildcard records because ordinary Cloudflare proxying cannot transport raw PostgreSQL or Valkey TCP. `scripts/ssh-dns-cloudflare.sh` implements the same exact-address, no-proxy, duplicate-removal safety model for `ssh.bex.co`.
- Cloudflare credentials stay ephemeral and out of `.env`; applying the repair requires a zone-scoped DNS/Edit token. Tests and `--check` must run without a live credential.

## Steps

1. Generalize the existing Cloudflare raw-edge reconciler so it can safely target a validated wildcard hostname while retaining the SSH entrypoint's current interface and output.
2. Add one datastore wrapper that reconciles both `*.$BEX_DB_DOMAIN` and `*.$BEX_KV_DOMAIN` to the Terraform-owned `bex-traefik` public addresses with `proxied:false`, deleting stale and duplicate A/AAAA records only at those exact names.
3. Add deterministic Cloudflare/Hetzner fakes for wildcard validation, check-mode non-mutation, proxied-record repair, and exact-host targeting; wire them into the GitOps validation gate.
4. Document the production reconcile/check commands and the reason raw datastore wildcards differ from the proxied HTTP application/API zone.
5. With an ephemeral zone token, reconcile production and require the read-only check plus public TCP/6379 preflight to pass before t004 reruns the official CLI.

## Acceptance criteria

- [x] Check mode fails on proxied, missing, stale, duplicate, or load-balancer-mismatched datastore wildcard records and performs no mutation.
- [x] Apply mode changes only exact `*.db.bex.co` / `*.kv.bex.co` A/AAAA records to the load balancer addresses with `proxied:false`; CNAME/NS collisions fail closed.
- [x] The SSH DNS workflow remains behaviorally unchanged, and local fake-backed tests plus `scripts/gitops-validate.sh` pass without Cloudflare credentials.
- [x] Production `*.kv.bex.co` resolves directly to the load balancer, accepts TCP/6379, and the ephemeral Cloudflare token is never printed or persisted.
- [x] Production `*.db.bex.co` has the load balancer's DNS-only A **and** AAAA records, so the two-wildcard objective and read-only production check pass together.

## Result

Cloudflare's authoritative nameserver now returns exactly `49.12.20.236` and `2a01:4f8:c01e:3d1f::1` for probes beneath both `*.db.bex.co` and `*.kv.bex.co`. Those are the Terraform-owned Hetzner edge addresses rather than Cloudflare proxy addresses. The Key Value TCP/6379 preflight and full official-CLI acceptance passed, and the fake-backed exact-host/check-mode gates remain green.
