## Objective

Make the live `kv-cli` proof discoverable and reproducible from the existing official-CLI compatibility entrypoint without forcing a public-edge mutation into the normal dev-9 regression suite.

## Context

- `scripts/cli-compat.sh verify` is deliberately runnable in dev-9 and currently creates/deletes Key Values without public connectivity. It must remain safe and deterministic there.
- The live verifier is an opt-in extension like `registry-credential-verify`, not an unconditional leg of `verify`.
- The checklist currently says the interactive guard fires before any bex call. Research proved that default non-TTY output causes the guard and that explicit interactive output plus a PTY reaches bex; the docs should explain the rerun seam even before t004 earns `[x]`.

## Steps

1. Add a `kv-cli-verify` dispatch to `scripts/cli-compat.sh` after it establishes the pinned CLI binary, refreshed bearer, workspace, and isolated config.
2. Document the required full-edge inputs, source-CIDR requirement, mutation/cleanup behavior, timeout controls, and the distinction from the dev-9 `verify` suite in the script usage block and checklist reproduction section.
3. Pin and report the official CLI version/commit used without dumping the environment or generated config.
4. Keep the checklist row open until t004 completes the real external run; record only that the headless method is now available.
