## Objective

Run the opt-in verifier against production or an equivalent complete public Key Value edge, capture sanitized evidence, and change the compatibility checklist's `kv-cli [id|name]` row to verified only after every Definition-of-Done assertion passes.

## Context

- The required path is API resolution → sensitive connection-info authorization → external `rediss://` URI → public DNS/LB `:6379` → source-preserving SNI proxy → Valkey TLS/authentication. A direct internal port-forward or direct `redis-cli -u ...` does not prove the CLI row.
- Both arguments matter: id goes directly to connection-info; name performs list filtering, uniqueness checking, and then connection-info by resolved id.
- The evidence must be useful without retaining resource identifiers, tokens, passwords, connection strings, terminal transcripts, or kubeconfig contents.

## Steps

1. Run `scripts/cli-compat.sh kv-cli-verify` with a pinned v2.21.0 (`c398207`) official binary, a disposable workspace fixture created by `render keyvalues create --ip-allow-list`, and the verifier host's explicit allowlisted CIDR.
2. Require PASS results for public readiness, by-id `PING`, by-id unique-key `SET`, by-name exact-value `GET`, key cleanup, and resource deletion; confirm the run needed no human input or attached terminal.
3. Record a dated sanitized evidence note under `.pm/w2/m57/evidence/` with target class, CLI version/commit, invocation shape, pass/fail assertions, cleanup result, and any non-secret operational caveat.
4. Update `docs/cli-compatibility-checklist.md` to `[x]`, replace the obsolete "not verifiable headlessly" explanation with the PTY/live evidence, and add the verifier to the reproduction method. Update ADR021's verification paragraph if needed so the official-CLI proof is discoverable from the Key Value contract.
5. If any bex behavior fails, keep the row open and use `$pm add-task w2/m57 ...` for the concrete defect before closeout; do not weaken the proof or relabel an environment failure as success.
