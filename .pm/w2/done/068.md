# 068 — Scope refusals: Render now names `insufficient_token_scope`; bex answers `INSUFFICIENT_SCOPE`

Why: Render's 2026-11-02 `errorCode` vocabulary adds `insufficient_token_scope` (round-5 drift, w2/m251); bex's granular-scope refusal uses its own `INSUFFICIENT_SCOPE`, so a Render client switching on the code would not recognize bex's refusal.

- **Render:** `components.schemas.errorCode` enum (pinned OpenAPI 2026-11-02) — plain-string `code`, "new codes are not breaking changes".
- **bex:** `lego/backend/internal/core/errors.go:576-582` (`InsufficientScopeCode = "INSUFFICIENT_SCOPE"`), raised from `core/base.go:1032` and mapped in `core/decision.go:67` across REST/GraphQL/MCP.
- **Do:** find where Render returns `insufficient_token_scope` (render.com docs search: API key / token scopes) and confirm it is the same situation (a token lacking a scope). If so, answer Render's code on REST (keep the HTTP status and message), and keep GraphQL/MCP consistent; update the error-shape tests. If Render's situation differs, record why in ADR018 and close.
- **Acceptance:** a REST call with a token lacking the scope returns `code: insufficient_token_scope` (or ADR018 records why not).

**Done 2026-11-03.** Render's pinned `errorCode` describes `insufficient_token_scope` as "The scoped API token does not satisfy the endpoint's minimum scope requirements." — the same situation as bex's granular-scope refusal. `core.InsufficientScopeCode` is now `insufficient_token_scope`: still 403 with `params.required`, and the message now names the required scope as Render's does, on REST `code`, GraphQL `extensions.code` and the MCP error prefix (one constant, so the three cannot drift). `scripts/auth-oauth21-e2e.sh`, ADR006/ADR012/ADR018 updated. No dashboard or CLI code switched on the old spelling.
