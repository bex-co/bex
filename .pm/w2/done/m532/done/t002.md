## Objective

Create the control-plane Postgres migration and store methods for sandbox group credentials and their version history, enforcing group-scoped uniqueness, monotonic version IDs, group-salted SHA-256 fingerprints, current + 3 most recently active distinct prior configuration retention, and exact 25-credential / 200 KiB / 1 MiB storage caps.

## Context

- Latest migration on `main` is `0304_object_multipart`; check `lego/backend/internal/store/migrations/` and number strictly above `origin/main`'s highest migration (`scripts/migration_order_guard.py`).
- Every tenant-scoped table must declare its cascade/disposal contract (`w2/m164` disposition census — check `lego/backend/internal/store/` disposition tests so CI passes).
- Render OpenAPI rules: `id` is case-sensitive and unique within a `sandbox_group_id`; `version.id` is monotonic `int64 >= 1` (each create, update, or restore mints a higher ID); `fingerprint` is 64-hex SHA-256 over routing + injection + secret value, salted per sandbox group so fingerprints match identical configs in the same group and cannot be compared across groups; retaining current + 3 distinct prior configs prunes all version rows pointing to any evicted config.

## Steps

1. Add migration `<next>_sandbox_group_credentials.{up,down}.sql` with `sandbox_group_credentials` (current config metadata, group salt or per-group fingerprint key, current version pointer, serialized byte sizes, `ON DELETE CASCADE` to `sandbox_groups`/`tenants`) and `sandbox_group_credential_versions` (monotonic version ID, `updated_at`, `updated_by`, `fingerprint`, `restored_from_version_id`, OpenBao secret reference key, config snapshot JSON excluding secret value).
2. Implement store methods in `lego/backend/internal/store/sandbox_credentials.go`: list (sorted lexicographically by `id`), get, create (serializing group writes via row lock on `sandbox_groups` to enforce 25-cred and 200 KiB / 1 MiB caps atomically and surface temporary contention cleanly), update, delete (idempotent, returning OpenBao refs to purge), list versions (newest `id` first), and restore (returning evicted config OpenBao refs to purge).
3. Update the tenant/identity disposal census tests if applicable so workspace deletion and user anonymization (`updated_by`) stay compliant.

## Acceptance criteria

- [x] Migration applies and rolls back cleanly against real Postgres and passes `scripts/migration_order_guard.py` and the disposition census tests.

- [x] Postgres never stores raw secret values.
