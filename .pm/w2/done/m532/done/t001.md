## Context

- Pinned Render OpenAPI (`lego/backend/internal/api/openapi/render-public-api-1.json`) defines all 7 `/sandbox-groups/{sandboxGroupId}/credentials*` operations (`list`, `create`, `retrieve`, `update`, `delete`, `versions`, `restore`) plus `429SandboxCredentialRateLimitOrConflict`.
- `lego/backend/internal/api/key_permission_ops.go` already maps all 7 REST paths to `core.KeySandboxesHistory` (GET) and `core.KeySandboxesCredentials` (POST/PATCH/DELETE).
- `docs/ADR104-sandbox-render-parity.md` § Out of scope currently defers credential brokering as early access while noting CLI commands already exist; `docs/ADR018-render-parity.md` § Render operation omissions lists the 7 routes as omissions.
- Brainstorm recommendations (not user decisions — record basis and open sign-offs honestly): OpenBao write-only secret custody; lexicographical `credentialId` tie-breaker on overlapping rules; `HTTPS_PROXY` + Sandbox Broker CA data plane (with non-proxy/pinned-cert bypass recorded as an open divergence vs Render's Firecracker transparent TCP-443 interception).
