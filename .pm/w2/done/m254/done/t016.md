## Objective

On production, a git build source with a native runtime (`node` here) fails every build within seconds. The operator refuses to dispatch the build because the carrier has no start command. By design (ADR097, t003) a carrier has none: each linked service supplies its own. Make a native carrier build succeed, and make the linked services start with their own start commands.

## Steps

1. Exempt build-source carriers from the start-command requirement in the native build path: a `BuildOnly`/`BuildSource` option set from `app.Spec.Type == TypeBuildSource`, or extend the static-site waiver. Decide what the image's default command is, if any.
2. Make sure a service linked to the carrier runs its own `startCommand` against the carrier's image (fan-out, `controller/build_source.go`). Check that a native-built image without a baked start command still starts under the service's command.
3. Either require `git.buildCommand` for native runtimes at `POST`/`PATCH /v1/build-sources`, with a named 400, or default it as Render does. Do not accept it and then fail every build.
4. Tests: an operator test that a native `build_source` carrier dispatches without a start command, and an e2e or dev-cluster run of create → build → linked service live.

## Implementation (2026-11-03) — awaiting production verification

- **Operator:** `build.Options.BuildOnly`, set for `type: build_source`. A native carrier build needs no start command and bakes no `CMD`; it keeps the runtime's env, `PORT` and entrypoint. `TestNativeBuildSourceDispatchesWithoutAStartCommand` fails without it, with the probe's exact error. `TestBuildOnlyNativeBuildNeedsNoStartCommand` pins the Dockerfile.
- **Backend:** a native git build source without `buildCommand` is refused at create, and at a PATCH that switches to a native runtime, with a 400 naming `buildCommand`. A PATCH cannot clear it.
- **Linked services:** they run their own start command over the carrier image through the shell override (`shellRunsStartCommand`). The gap that path leaves for native sources (no `native-init`, `sh` not bash) is t017.
- **Still open:** the acceptance criteria above are production checks: a build reaches `succeeded`, and a linked Free service goes Live. They need this commit deployed.
