## Objective

Run the hook command through the existing pre-deploy Job mechanism (`w1/m33`, `docs/ADR004-deployment.md` § Pre-deploy command) exactly once: gated on the App's first successful deploy, with the ran-once marker set atomically with success so failures retry on the next deploy and success never re-runs.

## Context

- Pre-deploy Jobs: `predeploy-<name>-gen-<generation>` in `BEX_BUILD_NAMESPACE`; the operator owns dispatch, the logs feature reads them (`type=predeploy`).
- Semantics from t001 decide the failed-first-deploy behavior (Render: hook on first *successful* deploy — so a failed deploy must leave the marker unset).

## Steps

1. Thread the hook into the operator's pre-deploy dispatch when the marker is unset (compose with an existing `preDeployCommand` if both are set — order per t001's captured semantics).
2. Set the marker only on hook + deploy success; leave unset on failure.

## Files

- `lego/operator/internal/` pre-deploy Job dispatch, `lego/types/` if the marker is CR-side

## Acceptance criteria

- [ ] envtest/unit: first successful deploy runs the hook; second deploy does not; failed first deploy retries.
- [ ] Hook Job logs readable via the existing `type=predeploy` log path.

## Out of scope

- New Job mechanism — this rides `w1/m33`'s.
