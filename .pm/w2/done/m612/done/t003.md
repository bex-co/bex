## Objective

Enable the `buildSource` source tab in Dashboard `/services/new` for `web`, `pserv`, `worker`, and `cron` service creation so users can select an existing workspace Build Source directly during service creation.

## Context

- `dashboard/src/features/services/components/service-source-picker.tsx` already implements the `buildSource` tab (currently used only in Update Source).
- Service creation routes live in `dashboard/src/routes/_serviceCreate.{web,pserv,worker,cron}.new.tsx` (static sites do NOT support Build Sources).
- GraphQL `createService` now accepts `buildSourceId` from `t001`; regenerate dashboard GraphQL types via codegen.

## Steps

1. Update the dashboard `CreateService` GraphQL mutation document to pass optional `$buildSourceId: String` (and `$dockerCommand: String` if needed) and run GraphQL codegen.
2. Enable the `buildSource` option on `ServiceSourcePicker` for `web`, `pserv`, `worker`, and `cron` create forms (keep disabled on `static`).
3. When a Build Source is selected in `/services/new`:
   - Hide source-owned fields (`repo`, `branch`, `runtime`, `buildCommand`, `rootDir`, `dockerfilePath`, `dockerContext`, `buildFilter`, `image`, `registryCredential`).
   - For git-backed Build Sources, default/constrain region to the Build Source's region (or clearly indicate region match requirement).
   - For native-runtime git Build Sources, require `startCommand` (or cron `command`); for Docker/image Build Sources, hide `startCommand` and allow optional `dockerCommand`.
4. Submit `buildSourceId` cleanly via `createService` and handle error states gracefully.

## Files

- `dashboard/src/features/services/api/*.graphql`
- `dashboard/src/features/services/components/service-source-picker.tsx`
- `dashboard/src/routes/_serviceCreate*.tsx` (and shared create form components)

## Acceptance criteria

- [x] Users can create `web`, `pserv`, `worker`, and `cron` services from an existing Build Source in `/services/new`; static site creation does not offer Build Source.
- [x] Form fields and client validation adapt cleanly to native vs Docker/image Build Sources and git-source region match.

## Out of scope

- Creating a brand-new Build Source (`/build-sources/new` belongs to `w2/m613`).
