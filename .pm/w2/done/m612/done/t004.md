## Objective

Wire `buildId` through the dashboard's `TriggerDeploy` mutation and `useTriggerDeploy` hook, and update `ManualDeployButton` so Build-Source-linked services show accurate copy (**"Deploy latest build"** instead of **"Deploy latest image"**) and offer **"Deploy a specific build…"** to roll out or roll back to any succeeded `bld-…` from the linked Build Source.

## Context

- Backend GraphQL `triggerDeploy` (`lego/backend/internal/deploys/graphql.go:239`) already accepts `buildId: String`.
- `dashboard/src/features/services/api/events.graphql:203` and `dashboard/src/features/services/hooks/use-trigger-deploy.ts:21-44` currently omit `buildId`.
- `dashboard/src/features/services/components/manual-deploy-button.tsx:85-95` derives `const repoBacked = !!service.repo;` which evaluates `false` for Build-Source-linked services (`service.buildSourceId != null`), displaying **"Deploy latest image"**.
- Backend GraphQL `builds(buildSourceId, cursor, limit)` (`lego/backend/internal/deploys/build_sources.go:777`) already lists builds for a Build Source.

## Steps

1. Add `$buildId: String` to `TriggerDeploy` in `dashboard/src/features/services/api/events.graphql`, add a `Builds` query document (or reuse a shared one) for listing a Build Source's builds, and run GraphQL codegen.
2. Add `buildId?: string` to `TriggerOptions` in `dashboard/src/features/services/hooks/use-trigger-deploy.ts` and forward it through `withProtectedRetry`.
3. Update `ManualDeployButton` (`manual-deploy-button.tsx`):
   - Detect `buildSourceBacked = !!service.buildSourceId`.
   - Show **"Deploy latest build"** for Build-Source-linked services (and hide inapplicable git-only "Clear build cache & deploy" / "Deploy a specific commit" actions).
   - Add **"Deploy a specific build…"** menu item opening a picker dialog listing `builds(buildSourceId)` with build ID (`bld-…`), status badge (only succeeded builds selectable, or clearly showing non-succeeded state), commit SHA / image ref, and relative timestamp.
   - Respect RBAC (`can_create` / `deploy` gate) and protected-environment confirmation via `useTriggerDeploy`, navigating to the newly created deploy on success.

## Files

- `dashboard/src/features/services/api/events.graphql`

## Acceptance criteria

- [x] On a Build-Source-linked service, the Manual Deploy dropdown displays **"Deploy latest build"** and **"Deploy a specific build…"** (never "Deploy latest image").
- [x] Selecting a succeeded build in the dialog calls `triggerDeploy(serviceId, buildId)` (with protected-environment confirmation when required) and navigates to the new deploy.
- [x] Non-linked git and image services preserve their exact existing menus.

## Out of scope

- Triggering a new build of the Build Source itself (`w2/m614`).
