## Objective

Expose `buildSourceId` on GraphQL `createService` (`lego/backend/internal/apps/graphql.go`) delegating directly to `apps.Service.Create`, so GraphQL matches REST `POST /v1/services` for creating services backed by a Build Source.

## Context

- `lego/backend/internal/apps/graphql.go:441` already exposes `buildSourceId` on `serviceGQLType` reads, but `createService` (`lines 1537-1585`) has no `buildSourceId` argument.
- `apps.CreateRequest` already supports `BuildSourceID` and enforces Render's mutual exclusion, region match (`build_source_region_mismatch`), and native `startCommand` / Docker `dockerCommand` rules.

## Steps

1. Add optional `buildSourceId: String` (and `dockerCommand` if missing on `createService` for Docker/image Build Sources) to `createService` in `lego/backend/internal/apps/graphql.go`.
2. Map it onto `CreateRequest.BuildSourceID` and return the created `AppView` (including `buildSourceId`, derived `runtime`, and `envSpecificDetails`).
3. Add GraphQL tests in `lego/backend/internal/apps/build_sources_graphql_test.go` covering git native, git Docker, image Build Source creates, and Render refusal codes (mutual exclusion with `repo`/`image`, region mismatch, missing/forbidden `startCommand`, static site refusal).

## Files

- `lego/backend/internal/apps/graphql.go`
- `lego/backend/internal/apps/build_sources_graphql_test.go`

- [x] GraphQL `createService(buildSourceId: "bds-…", ...)` creates linked `web_service`, `private_service`, `background_worker`, and `cron_job` services with identical validation and error codes as REST `POST /v1/services`.
