## Objective

Add optional `buildSourceId` support to MCP `create_web_service` and `create_cron_job` in `lego/backend/internal/apps/mcp.go` so coding agents can create services backed by a Build Source directly, keeping `TestMCPParity*` green.

## Context

- `lego/backend/internal/apps/mcp.go:194-410` defines `createWebServiceArgs` and `createCronJobArgs` and their `createRequest` helpers.
- `lego/backend/internal/api/mcp_parity_test.go:261-263` already classifies both `create_web_service` and `create_cron_job` as `mcpParitySuperset`, so an optional extra argument preserves parity counts without introducing divergence.

## Steps

1. Add `BuildSourceID string` (`json:"buildSourceId,omitempty"`) with clear JSON schema description to `createWebServiceArgs` and `createCronJobArgs` in `lego/backend/internal/apps/mcp.go`.
2. Update `createRequest` for both tools so setting `buildSourceId` maps cleanly onto `CreateRequest.BuildSourceID` without spuriously requiring `repo`/`image`/`runtime` when `buildSourceId` is supplied, and passes `startCommand` / `dockerCommand` cleanly.
3. Add MCP tests covering valid creates (git native, git Docker, image, cron) and refusals (mutual exclusion, region mismatch, start-command rules), and run `TestMCPParity*` in `lego/backend/internal/api/`.
