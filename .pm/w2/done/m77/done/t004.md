## Objective

The t003 hibernated session rehydrates on Steer/Resume into a fresh sandbox with `/workspace` state intact (including uncommitted edits), and the measured resume latency is recorded against ADR059 D4's p50<~5s / p95<~15s budget.

## Context

m68's rehydrate path (Resume/Steer → fresh sandbox + presigned restore URL → driver `restoreWorkspace` curl→tar) already instruments latency: `lego/backend/internal/agentsessions/service.go` ~line 1009 logs `agent-session rehydrate: session=<id> resumed in <duration> (SLO p50<5s/p95<15s)`. That log line is the measurement source — there is no Prometheus histogram, so p50/p95 come from repeated walks, not a query. On corrupt-snapshot restore the driver falls back to a clean re-clone with an explicit failure note — that outcome fails this walk.

## Steps

1. Before hibernation is exercised (or on a second session), leave a distinctive uncommitted edit in `/workspace` so restoration is provable.
2. Steer (or Resume) the hibernated session; confirm phase leaves `hibernated`, a fresh sandbox pod appears, and the turn proceeds.
3. Verify restored state: the uncommitted edit is present, git tree status matches pre-hibernate, uid 10001 preserved (no permission breakage on subsequent writes).
4. Capture the rehydrate log line's duration. Repeat the hibernate→rehydrate cycle at least 3–5 times (canary TTL makes this cheap) to get a defensible latency sample; record min/median/max against p50<~5s / p95<~15s.
5. If latency busts the budget or restore falls back to re-clone, capture full logs — regression input for t007 and an ADR059 Performance-section note for t005.

## Files

- No repo files expected; raw captures staged for `.pm/w2/m77/evidence/` (t005).

## Acceptance criteria

- Rehydrated session carries the pre-hibernate working tree, uncommitted edit included; no clean-re-clone fallback occurred.
- Resume latency sample (≥3 cycles) recorded with the log-line evidence, compared against the SLOs.
- Any SLO miss or restore failure is documented with logs, not discarded.

## Out of scope

Building a Prometheus histogram for resume latency (record as a follow-up candidate if the log line proves insufficient); memory-snapshot resume (ADR059 explicitly cold-process).
