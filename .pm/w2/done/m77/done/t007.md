## Objective

The env contract is guarded: a partially set `BEX_AGENT_SNAPSHOT_S3_*` group can no longer silently disable the tier without a trace, and any gap the t003/t004 live walks surfaced has a regression test. Standing closing task.

## Context

Today `agentsessions.NewS3SnapshotStore` returns nil when any of bucket/endpoint/access/secret is empty (`snapshotstore.go` line ~87) and `main.go` simply skips wiring — a typo'd Secret key in prod would quietly revert reclaim to Terminate with only the *absence* of the "hibernation enabled" log line as a clue. Precedent for loud partial-config handling: `BEX_STRIPE_EPOCH` malformed-while-enabled fails startup. Choose the proportionate guard: a loud startup warning (or fail-closed, matching the Stripe precedent) on a partial set, plus a unit test over the config→enabled/disabled/partial matrix. If the deployment manifest wiring is assertable, add a `scripts/gitops-validate.sh`-style check that the api manifest carries all six env entries or none.

## Steps

1. Add the partial-config guard in `lego/backend/cmd/api/main.go` (or a small validate helper in `agentsessions`): all-set ⇒ enabled, none-set ⇒ off, partial ⇒ loud warning or startup failure (pick one, document why).
2. Unit-test the matrix in `lego/backend/internal/agentsessions` (table test over `S3SnapshotConfig` combinations).
3. If t003/t004 surfaced a hibernate/rehydrate bug, add its regression test next to the existing m68 suites.
4. If a manifest assertion is cheap, extend `scripts/gitops-validate.sh` (or the existing config guard tests) to hold the six-entries-together invariant.
5. `cd lego/backend && go test ./...` green; `make lint` from `lego/operator/` if Go changed.
