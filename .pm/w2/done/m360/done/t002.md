## Objective

Move the cron runs list into its own page, as Render's Runs page, and show each run's logs there.

## Context

- `dashboard/src/features/services/components/cron-runs-section.tsx` (paged runs, Trigger Run, per-run detail, confirmed cancel), `dashboard/src/features/services/hooks/use-cron-runs.ts`.
- `dashboard/src/routes/services.$serviceId.events.tsx:410-412` renders it under Events today.
- Logs: `dashboard/src/features/logs/` (a run's logs are the Job's lines between its start and end).

## Steps

1. Add `dashboard/src/routes/services.$serviceId.runs.tsx` rendering the runs list, with Trigger Run in the page header (Render's placement from t001).
2. Opening a run shows its logs, bounded to the run (its Job/instance and its time window).
3. Remove the runs section from the Events page.
4. A non-cron service at `/runs` gets the same explanation page pattern Scaling uses for cron.

## Files

- `dashboard/src/routes/services.$serviceId.runs.tsx` (new), `dashboard/src/routes/services.$serviceId.events.tsx`, `dashboard/src/features/services/components/cron-runs-section.tsx`, `dashboard/src/features/logs/**`

## Acceptance criteria

- [ ] Component tests: the list pages, Trigger Run and cancel keep their confirmations and permission gating, and a run opens its own logs.
- [ ] The Events page of a cron job shows no runs section.

## Out of scope

- Changing run semantics or the API.

## Result (2026-11-13)

`/services/$serviceId/runs` renders `CronRunsSection` (title "Runs", Trigger Run in the card header, run list with status, start, duration and cancel, cursor paging). The section left the Events page. A run's detail links **View logs**: the Logs tab over the run's window padded 5 s each side (`makeCustomRange`/`rangeToSearch`), or the live view for a run still going. A non-cron service's `/runs` lands on its primary tab.
