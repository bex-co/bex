## Objective

Document web push for operators/self-hosters: generate a VAPID keypair with `scripts/webpush-secret.sh`, set the three `BEX_WEBPUSH_*` vars, verify delivery — with zero Apple/Google developer accounts, app-store artifacts, or push-provider signups (the push service is the user's own browser vendor's, spoken to directly via VAPID). Record verified browser-support caveats, especially iOS Safari's installed-PWA requirement.

## Context

- Runbook precedent: `docs/runbooks/mobile-push.md` (Expo channel, referenced from `.env.example`'s push section and ADR052 §c) — the web-push runbook is its sibling.
- ADR052 must be amended: `docs/ADR052-notifications.md` line ~78 states "Transport is **Expo only** … there is no web push/VAPID (D6)" and the gap register line ~93 lists "Web push / VAPID / service worker — not built anywhere" — both become stale when t003/t005 land and must be updated to describe the second transport.
- `docs/ADR048-mobile.md` line ~98 records web push as "valid complementary work, especially for self-hosters" — add a pointer to this milestone's implementation.
- `.env.example` gains the annotated `BEX_WEBPUSH_*` section in t001; the runbook links it.
- CLAUDE.md: markdown is CI-checked with prettier — but this milestone's instructions say the milestone closeout handles formatting; keep doc edits prettier-clean by hand.

## Steps
