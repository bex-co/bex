# 077 — Dashboard `long-replay.test.tsx` times out under host load and turns ship gates red

Why: `src/features/agent-sessions/components/__tests__/long-replay.test.tsx` ("replays every block through the real useChat without React #185") failed the full dashboard run twice: 2026-11-05 (5820/5821, a w2/m269 agent run) and 2026-11-08 (the w2/m288 ship gate, 128 s at host load ~59). It passes 5/5 alone, so any workstream's gate can go red on it and need a manual flake call.

- **Do:** find what makes it slow (block volume, real timers, rendering the full replay), then make it deterministic.
  - Options: fake timers, a smaller fixture that still proves the React #185 guard, or a timeout sized to the work with the reason stated.
  - Keep the assertion it exists for.
- **Acceptance:** the full dashboard suite passes reliably on a loaded host, and the test still fails if the #185 regression it guards returns.

## Done (2026-11-09, `/loopx w2`)

- **Root cause:** a feedback loop. `useChat`'s `experimental_throttle` uses wall-clock time, so a slower host renders the growing transcript more often, and each render is bigger. `waitFor` re-queried the whole DOM, and pretty-printed it, on every commit. CPU time went from 13 s alone to 102 s under load, and the baseline failed after 430 s.
- **Fix:** `makeClockedFixtureFetch` feeds one chunk per pull and advances a mocked `Date.now()` 1 ms per chunk, so the render count depends only on the stream. The test waits for the chat to settle through `onChat`, then asserts. All the original assertions stay on the full 5,602-chunk fixture. The timeout is 180 s, with a comment explaining it.
- **Timing:** about 4.8 s alone. Under 48 `yes` processes (load 59–135) it passed in 19.6 s and 25.9 s, where it used to fail at 430 s.
- **Still catches the regression:** with the pre-fix hook and the throttle removed, it fails in 102 ms with "Maximum update depth exceeded" (it used to take 60 s and fail on a missing text). As before, it fails only when both guards are gone.
- **Checks:** dashboard `yarn lint` passes, and the full `yarn test` passes (6183 tests).
- **Not covered:** at extreme load (four concurrent full suites, load about 176), 13–17 tests in other files hit the default 10 s timeout. That is a different scale from the gate failures seen, and was not filed.
