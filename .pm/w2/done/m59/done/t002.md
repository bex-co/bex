## Objective

Create and wire a dedicated namespace boundary for BuildKit, kpack, static publish, and pre-deploy workloads instead of executing tenant-controlled code in the platform namespace.

## Context

- Build/publish/pre-deploy identities and copied Secrets currently follow `BEX_BUILD_NAMESPACE`.
- The backend Cancel and log paths must use the same namespace as the operator.
- Cross-namespace artifacts require explicit cleanup because owner references cannot cross namespaces.

## Steps

1. Add the dedicated namespace and its production configuration to GitOps.
2. Point operator and bex-api build-namespace settings at the new boundary.
3. Propagate App/workspace identity onto every Job and Pod template.
4. Preserve build cancel, build/pre-deploy logs, kpack, and static publishing behavior.

## Files

- `deploy/gitops/base/`
- `lego/operator/config/manager/manager.yaml`
- `lego/operator/internal/build/`
- `lego/operator/internal/predeploy/`
- `lego/operator/internal/publish/`
- `lego/backend/`

## Acceptance criteria

- [x] Rendered production manifests contain a dedicated untrusted execution namespace with no platform PSS label inheritance.
- [x] Every untrusted Job's Pod template carries the App/workspace identity.
- [x] Build cancellation and log discovery still resolve the same workload from bex-api.

## Out of scope

- A per-tenant namespace-per-build design or OpenChoreo/Korifi migration.
