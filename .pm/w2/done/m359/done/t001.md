## Objective

Write down exactly what the pinned CLI sends and expects for the two operations, since neither is in Render's public OpenAPI.

## Context

- CLI module dir: `go list -m -f '{{.Dir}}' github.com/render-oss/cli` from `lego/cli`. Files: `cmd/sandboxgroupsdelete.go`, `cmd/sandboxgroupsdefaultset.go`, `pkg/sandboxgroup/repo.go` (409 `default_sandbox_group_not_deletable`, 409 `sandbox_group_suspended`; set-default returns the group with 200), and the generated sandboxes client (`DeleteSandboxGroupWithResponse`, `SetDefaultSandboxGroupWithResponse`) for the success status and body.
- bex: `lego/backend/internal/sandbox/notoffered.go` (both routes refused today).

## Steps

1. Read the generated client for the delete success status (and whether a body is expected) and the set-default request body.
2. Read how the CLI's preview (no `--confirm`) gets the group it shows (a GET, not the DELETE).
3. Record the contract and the fact that bex has no suspended groups (so `sandbox_group_suspended` is never produced) in `docs/render-artifacts/sandbox-groups.md` and ADR104 D7.

## Files

- `docs/render-artifacts/sandbox-groups.md`, `docs/ADR104-sandbox-render-parity.md`

## Acceptance criteria

- [ ] The artifact names method, path, success status, bodies and each 409 code, with the CLI file each came from.

## Out of scope

- Group credentials (`sandbox-groups credentials`, early access).

## Result (2026-11-12)

`docs/render-artifacts/sandbox-groups.md`: `DELETE /v1/sandbox-groups/{id}` → `204` (no body), `POST …/set-default` (no body) → `200` with the group, from the CLI's generated client; the 409 codes `default_sandbox_group_not_deletable` and `sandbox_group_suspended` from `pkg/sandboxgroup/repo.go`; the CLI reads the group first and refuses a default itself; without `--confirm` it stops after the read. ADR104 D7 records that bex has no suspended groups, so `sandbox_group_suspended` is never produced.
