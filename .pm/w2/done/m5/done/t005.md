## Objective

Prove the agent poll-loop end-to-end on the mock cluster: creating a service records deploy #1; `POST …/deploys` triggers deploy #2 which an agent polls to `live` via `get_deploy`; a service with a broken image yields a deploy that truthfully reads `failed`.

## Context

- Mock cluster (`bash scripts/mock-cluster.sh`) with `BEX_CP_DB_URI` pointing at a local Postgres (CNPG `bex-db` or a dev container).
- Health gating semantics from docs/deployment.md decide `live` vs `failed`.

## Steps

1. Create (w2/m4) → assert one deploy row → `live`.
2. Trigger → poll `get_deploy` until `live`; assert two entries, newest-first.
3. Deploy a nonexistent image tag → deploy ends `failed` within the gating window.

- Feature test files; a script or test notes under the milestone if the live check is manual.
