## Objective

Extend the outbound projector to deliver lifecycle facts bex already persists and the existing auto-deploy audit transitions, including Render's terminal `data.status`, without adding a second emitter or changing the DB-free operator boundary.

## Context

- `internal/store/event_facts.go` already stores branch deletion, build start/end, pre-deploy start/end, and job-run end; ended facts carry a checked status.
- `internal/webhooks/service.go`'s `factEvents` omits all six, while `worker.go` only copies status for `deploy_ended`.
- `apps.SetAutoDeploy` audit rows already carry `auto_deploy_enabled`; the webhook feed must preserve that discriminator to select Render's enabled/disabled event name.

## Steps

1. Add the eight Render event constants to the subscribable vocabulary and dashboard catalog source.
2. Thread fact status and the auto-deploy discriminator through `WebhookEventRow` and the composed feed.
3. Project each source to the correct type and include status only on Render terminal events.
4. Preserve stable `evt-…` ids, occurrence timestamps, fan-out dedupe, and multi-replica claims.

## Acceptance criteria

- [x] All eight event types are subscribable and produce signed thin payloads from their existing durable rows.
- [x] `build_ended`, `pre_deploy_ended`, and `job_run_ended` carry `succeeded|failed|canceled`; started/nonterminal events omit status.
- [x] One source row yields at most one delivery per endpoint across two worker replicas and restart replay.

## Out of scope

- Creating a new one-off-job product or inventing provider events without a source.
