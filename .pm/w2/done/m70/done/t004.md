## Objective

Make endpoint creation and update honor Render's request semantics while preserving thin-adapter consistency across REST, GraphQL, MCP, and the dashboard.

## Context

- Render create requires `ownerId`, `name`, `url`, `enabled`, and `eventFilter`; an empty filter means all current and future events.
- Bex ignores create `enabled`, allows a blank name that becomes the URL, stores duplicate workspace names, rejects an empty filter, and accepts plain HTTP destinations.
- Update must distinguish omitted `eventFilter` from an explicitly empty all-events filter.

## Steps

1. Represent omitted versus explicit-empty subscriptions in adapter inputs and the core/store contract; make empty persisted filter mean all events during fan-out.
2. Decode/apply create `enabled`, require a trimmed name, and enforce workspace-scoped name uniqueness transactionally on create and rename.
3. Require HTTPS destinations per Render, with any test-only transport seam kept outside production validation.
4. Mirror the semantics and coded conflicts across GraphQL/MCP and surface them cleanly in the dashboard.

## Acceptance criteria

- [ ] Render's create body can create disabled; missing/blank/duplicate name and non-HTTPS URL fail before mutation with stable cross-surface errors.
- [ ] `eventFilter: []` subscribes to a newly introduced event without updating the endpoint; omitted PATCH filter preserves current selection.
- [ ] REST, GraphQL, MCP, and dashboard perform the same core validation and retain mint-once secret behavior.

## Out of scope

- Render plan-tier pricing/gating; the existing bounded bex endpoint quota remains.
