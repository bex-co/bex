## Objective

Repair the remaining Render REST wire incompatibilities: stable paginated webhook lists, Render-shaped reads, and `/events` history with timestamp filters and bounded delivery response evidence, while keeping richer bex retry diagnostics available to GraphQL/MCP/dashboard consumers.

## Context

- Render lists `[{webhook,cursor}]`, accepts `ownerId[]`, `cursor`, and `limit`, and returns `[{webhookEvent,cursor}]` from history with `sentBefore`/`sentAfter`.
- Bex list ignores pagination and returns bare endpoints; `/events` returns `{delivery,cursor}` with different field names and no response body.
- Signing secrets remain create-only by prior user decision even though Render read schemas expose them.

## Steps

1. Add stable keyset pagination and multi-owner filtering to endpoint list with Render's default/bounds.
2. Render exact supported non-secret webhook fields from list/get/update.
3. Add history time filters and the `webhookEvent` envelope (`id`, `eventId`, `eventType`, `sentAt`, `statusCode`, bounded `responseBody`, `error`).
4. Store only a safe bounded response prefix with explicit truncation behavior; retain bex retry state on its GraphQL/MCP/dashboard contract or a clearly named extension path.

## Acceptance criteria

- [ ] A pinned Render fixture pages endpoint and event lists without duplicates/skips and honors all documented owner/time filters.
- [ ] `/v1/webhooks/{id}/events` uses Render's envelope and fields; response evidence is byte-bounded and never logs or reflects request secrets.
- [ ] List/get continue to omit the signing secret, and the contract artifact/tests identify that one deliberate security divergence.
