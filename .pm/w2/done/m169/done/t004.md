## Objective

Replace the hand-built Traefik Middleware `…-forum-bex-co-root` with a redirect the forum application itself serves, so the hostname needs nothing but a bex custom domain.

## Context

- Render web services have no platform path-redirect feature; a tenant does this in the app.
- `DISCOURSE_RELATIVE_URL_ROOT=/forum`; multisite config is assembled by `discourse_docker/_infra/docker/start.rb`.

## Steps

1. Add a `/` → `/forum` 301 in the forum image (rack middleware or the image's front server), scoped to the hosts that need it.
2. Deploy it through the normal bex path (push / Blueprint sync).
3. Verify `forum.bex.co/` and the App's own onbex host both answer 301 → `/forum`.

## Files

- `discourse_docker` image/startup files (as found in t003)

## Acceptance criteria

- [x] The application answers `/` with 301 → `/forum` without any platform Middleware.

## Out of scope

- Removing the Middleware (t005).

## Result

Done 2026-10-29, at the tenant's edge instead of in the image: `forum.bex.co` cannot be a bex custom domain (bex reserves the `bex.co` zone, as Render does `onrender.com`), so the BlockEden edge fronts it anyway and answers `/` (and any non-`/forum` path) with 302 → `https://forum.bex.co/forum` (`block-eden-mono` `40da94bb6c`). No platform Middleware is involved; the other hosts never redirected `/`, so nothing in the image is needed.
