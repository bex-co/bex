## Objective

Prove the whole chain works end-to-end: a `healthCheckPath` change made on any surface reaches the operator and changes readiness-gating behavior for real.

## Context

- The operator reconciles `spec.healthCheckPath` into a `ReadinessProbe` (`w1/m23/t001`).
- A running mock cluster or prod App is needed to observe pod readiness react to a probe-path change.

## Steps

1. On a running App, change `healthCheckPath` via REST, then GraphQL, then MCP — confirm each write is visible via `GET`/query/tool-read.
2. Point `healthCheckPath` at a path that 404s on the running app; confirm the pod goes NotReady (or fails to route traffic) as expected.
3. Revert to a working path; confirm it recovers.

## Files

- none (live verification against a running cluster)

## Acceptance criteria

- [ ] A change via any of REST/GraphQL/MCP is visible on the other two and on the dashboard.
- [ ] A bad `healthCheckPath` value causes observable readiness-gating failure; a good one recovers it.

## Out of scope

- Automating this as a permanent regression script — a manual/scripted one-time proof is this task's bar; t008 (Test coverage) covers the automated regression tests.
