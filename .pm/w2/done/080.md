# 080 — Manual Postgres storage increases: Render requires 5 GB steps and waits 6 hours between them; bex's API checks neither

Why: Render's contract for growing storage is "any multiple of 5 GB greater than the current storage capacity", and "after you increase a database's storage, you can't increase it again for 6 hours". bex's REST, GraphQL and MCP writes accept any larger integer, as often as the caller likes. Odd sizes then drift from what the dashboard can show, and repeated volume expansions hit the cloud volume API back to back.

- Render: [creating & connecting § storage](https://render.com/docs/postgresql-creating-connecting). The 6-hour rule may come from the underlying volume provider; check whether Render enforces it on the API too (`PATCH /postgres/{id}` `diskSizeGB`) before mirroring it.
- bex: `validateDatabaseStorageResize` (`lego/backend/internal/postgres/service.go`) checks only grow-only. The w2/m307 dashboard Storage edit already accepts only a multiple of 5 GB above the current size, client-side.
- Fix shape: refuse a non-multiple-of-5 manual `diskSizeGB` with a named 400 on every surface, the plan-included size excepted. If Render enforces the cooldown on its API, record the last manual increase on the Database status and refuse a second within 6 hours, with the time remaining. The disk-autoscaling path keeps its own 12-hour cooldown.
