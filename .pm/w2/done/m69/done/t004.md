## Objective

Teach the in-sandbox driver to point each agent binary at the proxy via its native base-URL mechanism and hand it the placeholder credential, keeping the existing scrub machinery as defense in depth. An agent adapter with no base-URL override cannot join the proxy path and must fail closed at profile level, never silently fall back to a direct vendor connection.

## Context

- Driver credential plumbing: `lego/agent-image/driver/src/config.ts` (shape-routing to `CLAUDE_CODE_OAUTH_TOKEN`/`ANTHROPIC_API_KEY`, `BEX_AGENT_MODEL_API_KEY_ENV` pin) and `credentials.ts` (env delete + scrub manager) — both retained; only the carried value changes to the placeholder.
- Base-URL envs per adapter: `ANTHROPIC_BASE_URL` (claude-code-acp, covers both API-key and `sk-ant-oat` paths), `OPENAI_BASE_URL` (codex-acp), the Gemini CLI equivalent (verify the exact variable against the pinned CLI version in the agent image).
- The proxy base URL arrives via driver env from t003; the tenant egress policy only admits the proxy, so a misconfigured adapter surfaces as a connection refusal, not a silent leak.

## Steps

1. Extend driver config: accept the proxy base URL, set the per-adapter base-URL env alongside the credential env in `agentEnvironment()`.
2. Fail closed: if proxy mode is on and the selected adapter has no known base-URL mechanism, refuse to start the agent with a clear driver error (surfaces in the session transcript).
3. Verify the scrub manager still scrubs the placeholder (cheap, keeps the machinery exercised) and that `BEX_AGENT_ENV_JSON` still cannot smuggle credential vars.
4. Rebuild/pin the agent image; note the change in the image changelog if one exists.
