## Objective

Give the SSH gateway a way to obtain, per verified agent session, the workspace's BYO model key plus the session's registered model endpoint — without the gateway ever gaining OpenBao access. Mirror the agentcred pattern: the gateway calls a cluster-internal bex-api route (the `BEX_AGENT_CREDENTIAL_API_URL` trust model, ADR047 D2), bex-api re-authorizes and answers from `agent-sessions/<ws>/model-key`.

## Context

- Key custody today: `lego/backend/internal/agentsessions/service.go` `modelKeySecretPath` → `core.SecretKV` (OpenBao); fetched only at dispatch and pushed into pod env.
- The existing gateway→bex-api mint seam for Git tokens is the template (`internal/sshgateway/agentcred` calls `BEX_AGENT_CREDENTIAL_API_URL`); reuse its authentication of the calling gateway and its internal-only routing.
- Deny-set discipline: refuse non-live/canceling sessions, mirroring ADR056 F13 (live-phase gate on turn tickets) and F10 (`canceling` in the credential-mint deny-set).
- Response must carry the key **and** the session's pinned `ModelEndpointHost`-validated endpoint so the proxy can never be steered elsewhere by the sandbox.

## Steps

1. Add an internal route (beside the existing agent-credential mint) that takes a session id, verifies the caller is the gateway, re-runs fresh (uncached) authorization on the session and its live phase, and returns `{credential, endpointHost}` from OpenBao + the session record.
2. Return a coded refusal (no oracle drift) for unknown/foreign/non-live sessions; never log the credential.
3. Unit-test: happy path, no-key-provisioned (empty credential, not an error), OpenBao failure fail-closed, non-live phase refused.

## Files

- `lego/backend/internal/agentsessions/` (resolve handler + service seam)
- `lego/backend/cmd/api/` (route wiring, internal listener)

## Acceptance criteria

- [ ] Gateway-scoped route returns key + pinned endpoint for a live session; refuses canceling/completed/foreign sessions with a coded error.
- [ ] OpenBao unreachable ⇒ fail-closed error, never an empty-success.
- [ ] The credential appears in no log line, audit event, or error message (test asserts).

## Out of scope

- The proxy itself (t002); any change to how the key is stored or provisioned.
