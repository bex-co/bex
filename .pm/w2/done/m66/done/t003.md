## Objective

Wrap the agent-session Connect control in `RequiresSshKey`: with zero keys, the dropdown's contents (the `zed://` Open-in-Zed link + copyable `ssh` command) are replaced by the add-key CTA carrying `returnTo=/agents/<id>`; with a key, it renders exactly as today.

## Context

- Control: `OpenInZedButton` in `dashboard/src/features/agent-sessions/components/session-detail-header.tsx` (w2/m65). Keep the trigger visible for discovery — swap only the menu *payload* (swap-payload-not-hide).
- Agent sessions have no in-dashboard browser terminal yet (ADR047 D8 ACP attach is phase 2), so the agent-session fallback is the single add-key door — the second "browser terminal" door applies on services (t004), not here. Note this asymmetry in the CTA so it isn't mistaken for a missing feature.
- The gate is additive to the existing `session.sshAddress` phase-gating: address absent → no control at all (unchanged); address present + zero keys → CTA; address present + key → live affordance.

## Steps

1. Wrap the menu content in `RequiresSshKey`, fallback = `AddSshKeyCta` with `returnTo` = the session route.
2. Keep the trigger button + its icon/label untouched (discovery preserved).
3. Component test: no-key session shows the CTA (not the `zed://` link); has-key shows the link; loading/error shows the link (fail-open).
