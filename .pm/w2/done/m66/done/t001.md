## Objective

Build the reusable gate: a `RequiresSshKey` component that renders its children (the real SSH affordance) when the caller has ≥1 registered key, and a `fallback` CTA when they have zero — plus a single app-cached `hasSSHKey` selector so every SSH surface shares one query, not one per button.

## Context

- Existing hook: `dashboard/src/features/ssh-keys/hooks/use-ssh-keys.ts` (list/create/delete over the `sshKeys` GraphQL query). Reuse it; do NOT add a new backend field (keeps the milestone API-surface-free — see README parity omission).
- Gate must **fail open**: while the query is loading OR on error, render `children` (the real affordance), never the fallback. A guard bug must never hide a working feature.
- The selector is per-identity, changes rarely → one cached read app-wide (Apollo cache-first; the gate reads the cache, doesn't refetch per mount).
- API surface of the primitive: `<RequiresSshKey fallback={<AddKeyCta …/>}>{realAffordance}</RequiresSshKey>` — render-prop or children+fallback. Keep it presentation-only; no SSH knowledge leaks in.

## Steps

1. Add `useHasSSHKey()` (or extend `use-ssh-keys.ts`) returning `{ hasKey, loading, error }` off the shared cached query.
2. Add `RequiresSshKey` in `features/ssh-keys/components/` — renders `children` when `hasKey || loading || error`, else `fallback`.
3. Add a shared `AddSshKeyCta` component (label, description, deep-link — the link target lands in t002) the fallbacks reuse.
4. Unit-test the three states: has-key → children; no-key → fallback; loading/error → children (fail-open).
