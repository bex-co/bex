# Align default Postgres create allowlist readback with external access

Why: A default public Postgres returns an empty list, so the pinned Render CLI says external access is blocked and refuses psql even though the public network path is enabled.

Discovered during w2/m166 Render-parity review (2026-10-02), separately from its explicit-clear fix. The REST create adapter defaults omitted `public` to true while leaving omitted `ipAllowList` empty; `TestRESTPostgresPublicDefaultIsAdapterSpecific` in `lego/backend/internal/postgres/postgres_test.go` pins that default. `pgView` returns those empty entries. Pinned Render CLI `pkg/text/ipallowlist.go` describes an empty list as blocked, and `pkg/tui/views/psql.go` rejects it before launching the client.

[Render Postgres documentation](https://render.com/docs/postgresql-creating-connecting#restricting-external-access), checked 2026-10-02, declares the public default rule as `0.0.0.0/0`. Compare the pinned create builder and live/local CLI path, then align REST create omission versus explicit empty intent/readback without migrating existing resources or changing Bex-native GraphQL/MCP private defaults and explicit public overrides. Preserve the m166 update contract. Add meaningful create and CLI-contract regression coverage, update the state-matrix documentation, and record exact validation limits.

Expected scope: one focused REST create-default fix plus tests/documentation, under an hour; promote if tracing reveals broader work. Dedupe: w7/m46 records the psql empty-list guard, w6/m109 fixes required-array serialization, w4/blocked/m116 handles private-to-public update and CA trust, and w9/blocked/066 is a launcher release gap. None repairs the default public create readback. This is source/contract evidence, not a new production network repro.


Closed 2026-10-02 in `c95a70d4d`: REST create distinguishes omitted from explicit empty lists, persists explicit unrestricted IPv4/IPv6 rules for the public default, and honors explicit public overrides. The composed API rejects `ipAllowList:null` and `public:null` with HTTP 400 before reaching the adapter; direct-fragment decoder tests separately cover null-as-omission. Shared native defaults and existing resources are unchanged. Regression coverage checks create/GET/persisted intent, dry-run non-persistence, required arrays and native adapters. Restoring the old REST file through a Go overlay fails the default/empty cases.

These use the real REST fragment and in-memory Kubernetes fixtures; they do not exercise OAuth, managed provisioning or a psql network connection.
