## Objective

Make every sync a recorded run with Render's state machine, and make manual sync pull the latest manifest from the repo. Wrap `SyncBlueprint` so a run inserts a `blueprint_syncs` row (`created` → `running` → `success|error`, commit id from the fetch, started/completed timestamps), stamps `last_sync_at`, and drives blueprint status (`syncing` while running, `in_sync`/`error` after; `paused` when `autoSync=false` — set by t006). When the sync request carries no explicit `bexYaml` body, fetch from `(repo, branch, path)` via t002 and persist the fetched manifest on success; an explicit `bexYaml` body keeps today's behavior (bex extension, still recorded).

## Context

- Core: `SyncBlueprint(ctx, id, ownerID, bexYAML, confirm)` in `lego/backend/internal/apps/blueprint.go` (re-applies stored manifest today).
- Render sync object: `id (exe-…) · commit.id · startedAt · completedAt · state ∈ {created, pending, running, error, success}`; read via `GET /v1/blueprints/{id}/syncs` with cursor/limit.
- Sync **never deletes** resources removed from the manifest — preserve existing behavior; that is parity.
- Reads: REST `GET /v1/blueprints/{id}/syncs`, GraphQL `blueprintSyncs(id, cursor?, limit?)`, MCP `list_blueprint_syncs` — one core verb, thin adapters (ADR006).

## Steps

1. Refactor sync into a run-recording wrapper (shared by manual sync, create's initial apply, and t005's webhook trigger).
2. Implement fetch-when-no-body + stored-manifest update on success; failure leaves the stored manifest untouched and the run `error` with the message captured.
3. Add the three read adapters with Render's cursor/limit envelope.
4. Tests: success + failure transitions, no-body pull-from-repo, explicit-body bypass, protected-env confirm still honored, syncs pagination.
