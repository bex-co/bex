## Objective

Give the blueprint feature a way to read the blueprint file **from the repository** — the inversion that makes the repo the source of truth. A helper fetches the file contents at `(repo, branch, path)`: via the GitHub App installation token for connected/private repos (ADR026 machinery), or anonymously for public GitHub URLs. Returns contents + the resolved head commit id (needed by sync history).

## Context

- GitHub App integration: `docs/ADR026-github-integration.md`; installation-token minting already exists for clone Secrets (w2/m8–m9) — find it under `lego/backend/internal/github/` and reuse, don't duplicate.
- GitHub contents API (`GET /repos/{owner}/{repo}/contents/{path}?ref={branch}`) or raw fetch both work; pick whichever the existing `github` package idiom supports; capture the branch head SHA alongside.
- Git provider stays **GitHub-only + public URLs** (`.pm/DO_NOT_DO.md`: no GitLab/Bitbucket).
- Bounded HTTP (deadline + response-size cap) per the w2/m61 idiom.

## Steps

1. Add a `FetchBlueprintFile(ctx, repo, branch, path)` seam (interface on `apps.Service` so tests can stub it) returning `{contents, commitID}`.
2. Implement GitHub-App-token fetch for repos with an installation; anonymous fetch for public `https://github.com/...` URLs; named errors for not-found file, unreachable repo, and no-installation-private cases.
3. Unit tests with a stub HTTP server: token path, public path, missing file, oversized file.

## Files

- `lego/backend/internal/github/` (reuse token minting)
- `lego/backend/internal/apps/blueprint.go` (seam + wiring)
- `lego/backend/internal/apps/blueprint_test.go`

## Acceptance criteria

- [ ] Private connected repo fetch authenticates with an installation token; public repo fetch needs no credential.
- [ ] Returned commit id matches the branch head the contents came from.
- [ ] Errors are named and secret-free (no token in error text).

## Out of scope

- Calling the fetch from create/sync flows (t003/t004); webhook triggering (t005).
