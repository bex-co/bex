## Objective

The two missing Render verbs. `PATCH /v1/blueprints/{id}` updates `name`, `autoSync`, and `path` (partial body, Render's exact field names; unknown fields rejected per the existing REST idiom). `DELETE /v1/blueprints/{id}` **disconnects**: the blueprint stops syncing and disappears from the workspace's list, while every resource it created remains untouched — Render's documented semantics ("stops automatic resource syncing"). GraphQL `updateBlueprint`/`disconnectBlueprint` mutations and MCP `update_blueprint`/`disconnect_blueprint` tools ride the same core verbs.

## Context

- Routes today: `lego/backend/internal/apps/rest.go:1340-1387` registers only GET list/by-id, validate, sync — no PATCH/DELETE.
- `autoSync=false` sets status `paused` (Render vocabulary); re-enabling returns it to `in_sync`/`error` per the last run.
- Disconnect: soft-delete or row delete — pick one, but the `(tenant_id, repo, branch)` unique key must allow reconnecting the same repo+branch later, and sync history handling must be deliberate (dropping runs with the row is acceptable if documented).
- Cross-workspace deny guards: the w7/m55 negative-authorization matrix enumerates every verb — add these two on all three surfaces there.
- Audit/activity events for update + disconnect, consistent with the existing event vocabulary.
