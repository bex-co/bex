## Objective

Extend the blueprint data model to Render's object shape: add `path` (blueprint file location in the repo, default `bex.yml`), `auto_sync` (boolean, default true), and `last_sync_at` columns to `blueprints`; adopt Render's status vocabulary `created | paused | in_sync | syncing | error` (map the legacy constant `'active'` → `in_sync` on read so existing rows stay valid); and add a `blueprint_syncs` table (sync id, blueprint id FK, commit id, state `created|pending|running|error|success`, started_at, completed_at) with a new `id.Kind` for sync ids.

## Context

- Current table: `lego/backend/internal/store/migrations/0016_blueprints.{up,down}.sql` — `id, tenant_id, name, repo, branch, manifest, status ('active'), created_at, updated_at`, unique `(tenant_id, repo, branch)`.
- Store methods: `lego/backend/internal/store/blueprints.go` (`UpsertBlueprint`, `GetBlueprint`, `ListBlueprints`).
- Render blueprint ids are `exs-…`, sync ids `exe-…`; bex mints every id via `lego/backend/internal/id` (`id.New(kind)`, hyphen separator) and registers new kinds there (`docs/ADR020-identifiers.md`).
- Next free migration number: `0059`.

## Steps

1. Write migration `0059_blueprint_git_connection.{up,down}.sql`: `ALTER TABLE blueprints ADD COLUMN path text NOT NULL DEFAULT 'bex.yml', ADD COLUMN auto_sync boolean NOT NULL DEFAULT true, ADD COLUMN last_sync_at timestamptz;` plus `CREATE TABLE blueprint_syncs (…)` with an index on `(blueprint_id, started_at DESC)`.
2. Add the sync `id.Kind` to `internal/id` (registry + guard test).
3. Extend `store.Blueprint` + store methods; add `InsertBlueprintSync`/`UpdateBlueprintSync`/`ListBlueprintSyncs` (cursor + clamped 1–100 limit, newest first, Render's exclusive-cursor idiom as in projects w1/m42).
4. Extend `BlueprintView` (`internal/apps/blueprint.go`) with `path`, `autoSync`, `lastSync`, mapped status; keep list/get output stable for existing fields.
