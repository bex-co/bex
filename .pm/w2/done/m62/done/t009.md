## Objective

Bring `/blueprints/{id}` up to Render's detail page: a **sync history** list (state chip, commit id, started/completed, relative time; paged), a **managed resources** card (name, Render type label, link to `/services/{id}` / `/databases/{id}` / key-value page), a **status badge** speaking the Render lifecycle (`in_sync`/`syncing`/`error`/`paused`/`created` — replacing the current always-`active` badge), **Manual Sync** that pulls the latest manifest from the repo (no-body sync), and a **settings card**: rename, auto-sync toggle, blueprint path editor, and Disconnect with a confirm dialog stating resources are kept.

## Context

- Route: `dashboard/src/routes/blueprints.$blueprintId.tsx`; components `dashboard/src/features/blueprints/components/` (`blueprint-status-badge.tsx` currently maps only `active`).
- New GraphQL operations in `operations.ts`: `blueprintSyncs`, `updateBlueprint`, `disconnectBlueprint`, plus `resources`/`path`/`autoSync`/`lastSync` fields on the existing queries; hooks per file convention (`use-blueprint-syncs.ts` etc.).
- List page (`blueprints.tsx`) gains the `lastSync` + real status columns in the same move (Render's list shows them).
- Keep the existing manifest viewer + Validate panel; Manual Sync keeps the protected-env confirm retry (server-issued phrase, w5/m31).
- Disconnect navigates back to `/blueprints` on success; en/zh strings.
