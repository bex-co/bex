## Objective

Render's headline behavior: a push to the linked branch that **modifies the blueprint file** triggers an automatic sync. Extend the existing `/v1/webhooks/git` intake (both HMAC keys: `BEX_WEBHOOK_SECRET` and the GitHub App's `BEX_GITHUB_WEBHOOK_SECRET`) so that after the existing per-service push-to-deploy handling, pushes are matched against Git-connected blueprints on `(repo, branch)`; when the push's changed files include the blueprint's `path` and `autoSync=true`, run a recorded sync (t004). `autoSync=false` blueprints are skipped (status `paused`).

## Context

- Intake: `lego/backend/internal/webhooks/rest.go` (`POST /v1/webhooks/git`); GitHub push payloads carry `commits[].added/modified/removed` for changed-path matching; the plain-HMAC bex payload may not — define the honest fallback (no file list ⇒ sync on any push to the linked branch) and document it.
- Rate limiting/intake hardening (w7/m60) already meters this route — no new limiter.
- Webhook handling must stay fast: dispatch the sync async (the run row's `created`→`running` states make this observable), mirroring how push-to-deploy dispatches builds.
- Loop safety: a sync applying the manifest must not re-trigger itself.

## Steps

1. Blueprint lookup by `(repo normalized, branch)` on push events; path-match against changed files.
2. Async recorded-sync dispatch; audit/activity event for `blueprint_sync` start/finish consistent with the existing event vocabulary (w7/m66 idiom).
3. Tests: matching push triggers exactly one run; non-blueprint-file push does not; `autoSync=false` does not; both HMAC keys accepted; tampered signature still 401.

## Files

- `lego/backend/internal/webhooks/rest.go` (+ its wiring to `apps.Service`)
- `lego/backend/internal/apps/blueprint.go`
- tests alongside both packages

## Acceptance criteria

- [ ] Push modifying `path` on the linked branch → recorded sync with the push's head commit id.
- [ ] Push touching other files, other branches, or a paused blueprint → no run.
- [ ] Webhook response returns before the sync completes (async), and the run is observable via the syncs read surface.

## Out of scope

- Dashboard surfacing (t009); outbound event webhooks for sync results beyond the existing event vocabulary.
