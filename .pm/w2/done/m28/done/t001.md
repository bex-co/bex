## Objective

Design a general `core` error envelope carrying a machine-readable code and structured params, reusable across every REST/GraphQL surface — mirroring the one existing precedent (`ratelimit.go`'s hardcoded `"extensions": {"code": "RATE_LIMITED"}`) but as a shared mechanism rather than a one-off.

## Context

- `lego/backend/internal/core/errors.go` — the existing plain-sentinel error system (`ErrBadRequest`, `ErrForbidden`, `ErrConflict`, etc.), all mapped to status codes by `WriteErr` with no machine-readable code today.
- `lego/backend/internal/api/ratelimit.go:151` — the one working precedent: `"extensions": map[string]string{"code": "RATE_LIMITED"}` in the GraphQL envelope, hardcoded directly in middleware, outside the shared error system. graphql-go honors `gqlerrors.ExtendedError`, which is the seam this design should generalize.
- `.pm/w6/done/014.md` (or `w6/014.md` if not yet moved) — the source note's exact design sketch: `core.ErrPlanLimit` wrapping `ErrBadRequest`, carrying `{code: "PLAN_LIMIT", plan, limit}`.

## Steps

1. Design a `core.CodedError` (or similar) type: wraps an existing sentinel, carries `code string` + `params map[string]any`.
2. Decide how REST's `WriteErr` surfaces it (a `code` field in the JSON error body) and how the GraphQL error formatter surfaces it (via `gqlerrors.ExtendedError`'s `Extensions()`), matching the `RATE_LIMITED` shape already proven in production.
3. Document the pattern so future features can adopt it without re-deriving the design.
