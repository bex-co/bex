## Objective

Add a per-field GraphQL mutation that grows a database's storage, through the same grow-only guard REST and MCP use.

## Context

- REST/MCP: `PostgresPatch.DiskSizeGB` (`lego/backend/internal/postgres/service.go:1287`; MCP `mcp.go:331`, "grow-only, and fixed at 1 GB on free").
- w2/m60 (ADR018:177): the operator keeps a status/live-CNPG high-water mark (`DatabaseStorageHighWater`, `service.go:590`). A smaller explicit request returns a named 400 before mutation. An accepted grow is visible at once through `PostgresView.DiskSizeGB` while CNPG converges.
- `database-plan-section.tsx:59-66` already reads `diskSizeGB` against a plan's `maxStorageGB`.

## Steps

1. Add `updateDatabaseDiskSize(id: String!, diskSizeGB: Int!)`, returning the database, next to `updateDatabaseDiskAutoscaling`.
2. Route it through `PostgresPatch` with only `DiskSizeGB` set, so the shrink refusal, the free-plan rule and the plan maximum are the existing ones.

## Files

- `lego/backend/internal/postgres/graphql.go` and its tests

## Acceptance criteria

- [ ] A grow, a shrink (named 400), a free-plan change and a value above the plan maximum give the same outcome through GraphQL and REST.

## Result (2026-11-10)

- `updateDatabaseDiskSize` is a `gqlutil.PatchMutation`, which now accepts Int arguments (GraphQL Int is 32-bit, so the `int32` patch field cannot overflow). It goes through `PostgresPatch.DiskSizeGB`, so the grow-only guard, the free-plan rule and the plan maximum are the existing ones.
- REST/GraphQL/MCP parity is tested for grow, shrink (the same message on REST and GraphQL) and the free plan (`POSTGRES_STORAGE_PLAN_UNSUPPORTED`), and dry-run writes nothing. Scope class: Write.
