## Objective

Add a per-field GraphQL mutation that sets a database's connection pool to `pgbouncer` or `none`. It goes through the same service path as REST `PATCH /postgres/{id}` `connectionPool`, so admission, errors and side effects are identical.

## Context

- REST: `lego/backend/internal/postgres/rest.go:478` maps Render's `connectionPool` enum, alongside bex's native `pooler` bool.
- MCP: `mcp.go:329` (`connectionPool`; omission leaves it unchanged) and `resolvePooler` at `mcp.go:387`.
- Admission: `admission.go:104-106` refuses plans without `SupportsConnectionPooling()`, with `{"field":"connectionPool","plan":…}`.
- GraphQL: `graphql.go:556` accepts `connectionPool` only at create. Sibling per-field mutations (`updateDatabasePlan`, `updateDatabaseVersion`, `updateDatabaseDiskAutoscaling`) are in `graphql.go:594-707`.
- Render: enabling restarts the database, or fails over when HA is on; free databases cannot pool.

## Steps

1. Add `updateDatabaseConnectionPool(id: String!, connectionPool: String!)`, returning the database, next to the siblings and with their authorization (the same relation the REST PATCH needs).
2. Route it through the existing `PostgresPatch` service call with only `ConnectionPool` set.
3. Map errors exactly as the siblings do: a free plan gets the named admission error; an unknown value gets a bad request.

## Files

- `lego/backend/internal/postgres/graphql.go`
- tests beside the siblings' GraphQL tests (e.g. `lego/backend/internal/postgres/disk_autoscaling_test.go` exercises `updateDatabaseDiskAutoscaling`)

## Acceptance criteria

- [ ] The same inputs give the same stored state and the same error code/field through GraphQL, REST and MCP (free plan refused; `pgbouncer`/`none` applied).
- [ ] A caller without write permission is refused, as for `updateDatabasePlan`.

## Out of scope

- PgBouncer configuration knobs. Render does not expose them ("Not directly").

## Result (2026-11-10)

- `updateDatabaseConnectionPool` is a `gqlutil.PatchMutationE` (new: a lift that can refuse with the feature's coded error) over `connectionPoolPatch`. The dry-run and confirm branch stays in one place.
- `pool_disk_setters_test.go` runs each case through REST PATCH, the GraphQL setter and MCP `update_postgres` on triplet databases, and requires the same stored spec and code: enable, disable, free plan refused (`POSTGRES_CONNECTION_POOL_PLAN_UNSUPPORTED`), unknown value refused (`POSTGRES_CONNECTION_POOL_UNKNOWN`). An empty value is refused by name on GraphQL.
- Scope matrix: classified as `OpClassWrite`, like REST PATCH and MCP `update_postgres`.
