## Objective

Move `app.bex.co/disk-autoscale-at` into `lego/types/v1alpha1` as an exported constant (the operator keeps using it). Add `app.bex.co/storage-increased-at`, which bex-api's update path stamps (RFC 3339, UTC) when it applies an increase; a dry run does not stamp. `CheckStorageIncrease` refuses an increase within 6 hours of the later of the two stamps with a 409 `POSTGRES_STORAGE_INCREASE_TOO_SOON`, whose params carry `nextIncreaseAt` and whose message names the time.

## Acceptance criteria

- [ ] Tests with a fixed clock: 5h59m after either stamp is refused with the right `nextIncreaseAt`; 6h later is accepted.
- [ ] A dry run does not stamp.

## Result (2026-11-10)

- **Shared annotations:** `appv1alpha1.AnnotationDiskAutoscaleAt` and `AnnotationStorageIncreasedAt`; the operator now uses the shared constant.
- **The wait:** `CheckStorageIncreaseWait` refuses an increase within 6 hours of the later stamp with 409 `POSTGRES_STORAGE_INCREASE_TOO_SOON`, params `lastIncreaseAt`/`nextIncreaseAt`.
- **The stamp:** `updatePostgres` stamps an applied increase. A dry run does not, because a server-side dry run never persists.
- **Tests:** fixed-clock cases for both stamps (5h59m refused, 6h accepted) and the dry run.
