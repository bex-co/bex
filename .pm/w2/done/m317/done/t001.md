## Objective

In `lego/backend/internal/postgres`, add an exported `CheckStorageIncrease(d, requested, now)` used by `validateDatabaseStorageResize`:
- a requested size above the current high-water mark that is not a multiple of 5 is a 400 `POSTGRES_STORAGE_STEP_INVALID`;
- the existing grow-only refusal is kept;
- an unchanged size is a no-op.
At create (`CreatePostgresRequest` validation), an explicit `diskSizeGB` other than 1 or a multiple of 5 is the same 400. The recovery path, which sets the source's high-water size itself, is exempt.

## Acceptance criteria

- [ ] REST, GraphQL and MCP give the same code for an off-step create and an off-step increase.
- [ ] An unchanged odd legacy size is accepted.
- [ ] A restore of a 7 GB source is still admitted.

## Result (2026-11-10)

- `postgres.CheckNewDatabase` (create, REST/GraphQL/MCP and the three Blueprint create sites) refuses an explicit `diskSizeGB` other than 1 or a multiple of 5 with 400 `POSTGRES_STORAGE_STEP_INVALID`.
- `validateDatabaseStorageResize` applies the step to increases only. Recovery keeps plain `CheckDatabaseAdmission`, so a 7 GB source restores.
- `storage_rules_test.go` runs every case through REST, GraphQL and MCP.
