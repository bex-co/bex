## Objective

A signed-in unverified session on any app route lands on `/auth/verification`, keeping the guarded `next`. After verifying, the user continues to `/setup/payment` (D7) and then to `next`. The wall replaces today's "Verify your email" checklist nudge as the enforcement point.

## Context

- Pattern to mirror: `dashboard/src/features/onboarding/components/payment-setup-gate.tsx` (wraps routed content in `RootComponent`; bare routes are never gated). This gate runs before the payment gate.
- The source of truth can be the Kratos session's `identity.verifiable_addresses` (no API call), or `EMAIL_VERIFICATION_REQUIRED` from any API call routed to the wall. Use both: session check first, API code as the backstop.
- `dashboard/src/features/auth/pages/verification-page/index.tsx` is the destination. It needs the resend affordance, sign-out, and the D5 delete/self-host exit, if t001 allowlisted deletion.
- Repo rule: the pending skeleton must match the verification page geometry at desktop and narrow-mobile widths (`dashboard/AGENTS.md` §navigation pending states).

## Steps

1. Add `EmailVerificationGate`, ordered before `PaymentSetupGate`, so the bare routes stay ungated.
2. Map `EMAIL_VERIFICATION_REQUIRED` in the Apollo/REST error handling to the wall.
3. Verification success goes to `/setup/payment?next=…`. This already exists per D7; confirm it.
4. Add tests next to the payment gate tests. Compare the pending and ready states side by side with Playwright.

## Files

- `dashboard/src/features/onboarding/components/*`, `dashboard/src/routes/__root.tsx` (or wherever `PaymentSetupGate` mounts), error link, verification page, locales (en/zh), `dashboard/AGENTS.md`

## Acceptance criteria

- [ ] An unverified session can't render any app route. Verifying continues seamlessly with no re-login.
- [ ] `yarn test` is green, and skeleton parity has been checked at both widths.
