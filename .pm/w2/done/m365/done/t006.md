## Gate

The production deploy. `deploy.yml` deploys at most every 6 hours, and the 07:31Z push run on 2026-11-13 skipped: the pin was 2.0 h old. The next push or hourly cron after about 11:31Z deploys m361 and m365 together. The worker then runs the steps below; this is already authorized by `/pmx them all for w2`.

## Steps

1. In the QA workspace, with the pinned CLI and REST: create an image web service, wait for Live, delete it, and within 5 s create the same name. Record the 201, its `object_name` and slug, the old App still terminating, and the new service reaching Live on its own host.
2. Repeat with a static site: publish it, delete it, re-create it while its object purge still runs, and check that the new site serves its own content.
3. Blueprint: delete a service a Blueprint declares, then sync the Blueprint. It re-creates the service at once (w2/m361's DoD).
4. While both exist:
   - `GET` by name and the services list return the new service, and so does the dashboard.
   - A repeated `DELETE` of the old `srv-` id answers 204, and the new service's env vars survive.
   - A second live service with the name is refused with 409.
   - The new service's logs, metrics, events and deploys hold nothing of the old one.
5. Delete every fixture.
