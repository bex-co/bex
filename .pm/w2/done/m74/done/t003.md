## Objective

Apply the same relation-accurate behavior to Key Value plan, lifecycle, and delete controls without treating all datastore changes as developer-only.

## Context

- `DeleteKeyValue` requires `can_create`; `SetPlan`, suspend, and resume require `can_operate`.
- The Key Value plan cards and danger row currently allow every loaded user to begin these flows.

## Steps

1. Gate plan selection/save and suspend/resume on definitive `canOperate` denial with the localized operation reason.
2. Gate delete on definitive `canCreate` denial with the localized create reason.
3. Preserve loading/unknown permissiveness and compose capability denial with busy, billing, and protected-resource state.

## Files

- `dashboard/src/features/keyvalue/components/key-value-plan-section.tsx`
- `dashboard/src/features/keyvalue/components/key-value-danger-actions.tsx`
- `dashboard/src/features/capabilities/**`

## Acceptance criteria

- [x] A contributor retains plan and suspend/resume access but cannot begin delete; a viewer missing `can_operate` cannot begin operational flows.
- [x] Definitively denied controls explain the exact relation and invoke no dialog or mutation callback.

## Out of scope

- Backend relation changes, billing/plan eligibility, backup controls, and connection-info sensitivity.
