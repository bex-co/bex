## Objective

`POST .../runs/{runId}/cancel`: for a Running run, delete the underlying k8s Job (foreground/propagating) so the pod dies, and the run settles to the captured canceled status via the operator's status write-back; a terminal run's cancel is 4xx per t001 — never a silent no-op (the deploy-cancel CAS precedent, w2/m10).

## Context

- Operator owns `status.runs` (`app_controller.go` cron reconcile) — decide the division: backend deletes the Job directly (it has the RBAC for build-job cancel already — check) vs a spec field the operator acts on. Follow the deploy-cancel precedent; record the choice.
