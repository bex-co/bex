## Objective

Decision taken (option a, 2026-09-15): bex keeps the operator-owned `PORT` invariant from ADR004:152 and does **not** honor a user `PORT` as the service port, because an env-group `PORT` would otherwise silently change routing and health checks for every linked service. Today a user `PORT` is accepted by every write path, stored, and then dropped by the operator at runtime, with no surface saying so. Make the refusal explicit: every write path rejects the key with a coded 400 that names the service port setting, both dashboard editors show the same hint inline, and ADR018 records the divergence.

## Context

- Accepted today: `ValidEnvKey` checks only the key's shape (`lego/backend/internal/core/config.go:60-72`).
- Dropped at runtime: `appEnv` removes a user `PORT` from `spec.env` and appends the operator-owned `PORT` as a container `Env` entry, which wins over every `envFrom` key (`lego/operator/internal/controller/app_controller.go:3816-3846`). ADR004:152 records this as deliberate. Keep that operator behavior unchanged; it is the control.
- Write paths to guard (all share `core`/`secrets`/`envgroups` validation): REST single `PUT /v1/services/{id}/env-vars/{key}`, REST bulk `PUT …/env-vars` and `PATCH …/environment`, env-group single/bulk (`envgroups/service.go`, `envgroups/patch.go`), GraphQL `patchServiceEnvironment`/`patchEnvGroupEnvironment`, MCP `patch_service_environment`/`patch_env_group_environment`, the create-service request, and Blueprint `envVars` (`lego/backend/internal/apps/blueprint.go`, validation plan). The `w1/m147` batch-quota work shows where the shared validation hook sits (`lego/backend/internal/secrets/batch.go`).
- Render: "The default value of `PORT` is `10000` for all Render web services. You can override this value by setting the environment variable" (`render.com/docs/web-services`, fetched 2026-09-14). This is a recorded divergence, not parity.
- Dashboard copy today: only "The container must listen on $PORT (default 3000) and cannot bind ports below 1024." (`dashboard/src/features/services/locales/en.ts:2759`).
- Error-shape convention: coded refusals are `core.ErrBadRequest`-wrapped with a stable sentence that REST, GraphQL and MCP all carry (see the `w1/m147` adapter table).

## Steps

1. Add one reserved-key check in the shared key validator (next to `ValidEnvKey`) that rejects `PORT` (case-sensitive, exact) with a wrapped `core.ErrBadRequest` such as `env var "PORT" is reserved: bex sets PORT from the service port; change the service port instead`. Decide and record whether the rule applies to background workers and cron jobs too. Recommended: reserved everywhere, one rule, because the operator injects `PORT` on every App type today; confirm in `appEnv` before writing that down.
2. Make sure every write path in Context passes through that validator: single, bulk, env-group single and bulk, create-service, Blueprint `envVars` (validate + sync, with a source location in the validation response).
3. Dashboard: in the create form and the Environment editor (service and env-group), show an inline field hint the moment the key `PORT` is typed, reusing the server sentence as locale copy in `en` and `zh`, and surface the server's refusal on Save without dropping the draft.
4. Record the divergence: a `PORT` row in `docs/ADR018-render-parity.md` beside the env-vars row (~line 112) citing ADR004:152 and the worker/cron decision. Add one line to `docs/ADR004-app-deployment.md` near :152 that the API now refuses the key.
5. Tests: one refusal test per write path (REST/GraphQL/MCP through the real adapters like `TestPatchEnvironmentQuotaRefusalIsIdenticalAcrossAdapters`), a Blueprint validation test with `PORT` in `envVars`, a dashboard editor test for the hint, and the operator's existing `appEnv` shadowing test kept green as the control.
