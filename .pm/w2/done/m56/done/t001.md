## Objective

Define an explicit, persisted identity for build artifacts and deploy releases so the operator no longer equates every `App.metadata.generation` change with a source build.

## Context

- `lego/operator/internal/controller/app_controller.go` currently reuses `status.image` only when `status.observedGeneration == metadata.generation` (or the App is suspended), so a replicas-only update is classified as a source deploy.
- `AppSpec` mixes source/build inputs, release-time inputs, and operational controls. The classification must be exhaustive so a future field cannot silently inherit unsafe behavior.
- Fingerprints may describe references and intent but must never embed Secret contents. Credential rotation already has explicit restart/deploy paths and must remain outside artifact identity.

## Steps

1. Inventory every `AppSpec` field and assign it centrally to artifact, release, or operational identity; document the semantics and ambiguous cases.
2. Add operator-owned status fields needed to persist the active artifact/release identity, then regenerate deepcopy and CRD artifacts.
3. Add a reflection-based or equally exhaustive guard test that fails when a new `AppSpec` field has not been classified deliberately.
4. Update the deployment and GitHub-integration ADRs to distinguish deploy triggers from ordinary reconciliation and explain why scale does not refresh or consume a clone credential.

## Acceptance criteria

- [ ] Every current `AppSpec` field has one explicit classification, enforced by a guard test.
- [ ] `Replicas` is excluded from artifact and release identity; source, build, commit, and image-origin inputs are included where appropriate.
- [ ] Persisted identities are deterministic, versionable, and contain no credential or Secret value.
- [ ] The documented model distinguishes Kubernetes object generation, artifact identity, active release, and reconciliation progress.

## Out of scope

- Redesigning the public App API or teaching the operator to mint GitHub credentials.
