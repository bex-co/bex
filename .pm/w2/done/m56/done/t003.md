## Objective

Introduce the new identity model without rebuilding legacy Apps, replacing healthy pods, or recording operational generations as deploys.

## Context

- Every deployed App initially lacks the new status identity fields, so a naive comparison would classify the upgrade itself as a deploy.
- The incident App is already in a split state: spec generation 2 requests two replicas; status image and active revision are from generation 1; `observedGeneration` is 1; and the generation-2 build condition is failed.
- Deploy-history projection must continue to represent actual release attempts. A replicas-only generation must not manufacture a deploy row merely because Kubernetes assigned a new generation.

## Steps

1. Derive and persist initial identities from legacy App status and the active workload without requiring source access or changing the pod template.
2. Make the exact incident state self-heal on reconciliation: reuse the active generation-1 artifact, clear superseded build failure state appropriately, and converge the replica target.
3. Keep deploy rows and transition timestamps tied to true deploy attempts while allowing `observedGeneration` to acknowledge operational changes.
4. Document upgrade and rollback expectations, including how operators can inspect a backfilled App without exposing credentials.

## Acceptance criteria

- [ ] An existing App with no identity fields is backfilled without a build, pre-deploy Job, ReplicaSet replacement, or deploy-history row.
- [ ] The production incident shape converges from one to two replicas using the existing image/revision and exits the stale `BuildFailed` state without an App recreation or manual deploy.
- [ ] Genuine deploy attempts still have correct generation/provenance, transitions, failure semantics, and rollback targets.
- [ ] Upgrade and rollback behavior is documented and covered by focused tests.

## Out of scope

- Mutating the production service before the fixed operator is deployed or redesigning the deploy-history schema beyond identity correctness.
