## Objective

Use the explicit artifact/release identity in the App controller so replicas-only and other classified operational changes update workload state without building, running pre-deploy, or rolling the active release.

## Context

- The production scale mutation correctly changed only `spec.replicas`, but the generation gate sent reconciliation into the source-build path.
- Pre-deploy Jobs are currently named and gated by generic App generation. Running them for scale can repeat migrations or other non-idempotent release work.
- The existing image and revision are valid inputs for operational reconciliation even when `observedGeneration` trails the newest spec generation.

## Steps

1. Replace the generation-equality image-reuse decision with the artifact/release identity comparison from t001.
2. Retain the active image and revision for operational changes, applying replicas and other desired workload resources in place.
3. Gate source builds, image-origin changes, revision advancement, and pre-deploy Jobs on genuine release intent rather than generic generation churn.
4. Preserve the existing failure guarantee: a genuine failed build leaves the previous healthy release serving and records the failed attempt honestly.
5. Apply the classification consistently to continuous services, Cron Jobs, workers, and static sites while keeping resource-type-specific behavior explicit.

## Acceptance criteria

- [ ] Scaling a source-backed web service changes the Deployment replica target without creating a build or pre-deploy Job.
- [ ] The scale path preserves the active image, revision label, pod-template hash, and existing ReplicaSet.
- [ ] A true source/build/image-origin change still creates exactly one intended build and advances the release only after success.
- [ ] A failed true deploy keeps the previous release serving and exposes the failed deploy state without poisoning later operational reconciliation.

## Out of scope

- Replacing the build system, refreshing clone tokens inside the operator, or changing Kubernetes rollout strategy.
