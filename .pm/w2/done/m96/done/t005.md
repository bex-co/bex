## Objective

Confirm the new `serviceName`/`deleted` fields on usage rows agree across REST `GET /v1/usage`, GraphQL `usage` and MCP, and that the webhook delivery `serviceName` agrees across REST and GraphQL. Compare with Render and record drift instead of silently diverging.

## Steps

1. **Three-adapter check.** For one tenant/period, read the usage estimate over REST, GraphQL and MCP and diff the per-resource `serviceName`/`deleted` values; they must be identical.
2. **Webhook read check.** Read one delivery over REST and GraphQL; `serviceName` must match.
3. **Compare with Render.** Capture what Render's billing/usage view shows for a deleted service, and what its Recent deliveries column shows (Render's `webhookEvent` object carries no service name). Note findings and date in the m96 README.
4. **Record drift.** Update the usage and outbound-webhooks rows of `docs/ADR018-render-parity.md` if bex now exposes fields Render does not; file any divergence as a `w2/NNN` note.

## Acceptance criteria

- [ ] Adapter diffs are empty on both surfaces sets.
- [ ] The Render comparison, with its date, is noted in the m96 README and ADR018 rows are updated or confirmed unchanged.
