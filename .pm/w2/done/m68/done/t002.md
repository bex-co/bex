## Objective

Give ADR059 D2's state machine a durable shape: the session/workspace row learns a `hibernated` state (distinct from live phases and from terminal-with-nothing), a `pinned` flag, a snapshot reference (object key + size + checksum), and the timestamps the idle/retention clocks read.

## Context

- Today `agent_sessions` has live phases + terminal phases and a `sandbox_id` that m65 clears on teardown; "hibernated" must be representable so `Resume`/connect can find the snapshot after the pod is gone (the exact thing that's impossible today).
- Choose deliberately (and record in the migration comment): extend `agent_sessions` (state + `pinned` + `snapshot_key/size/checksum` + `hibernated_at`/`last_interaction_at`) vs a new `agent_workspaces` table with sessions pointing at it (ADR059 D1's workspace-as-unit realized in schema). Prefer whichever keeps m67's reaper and the existing verbs' queries simple; D1 can be realized logically first (one workspace per session row) without blocking on a full workspace table.
- Migration via the store's numbered-migration convention; update the m67 cap/reaper queries if the state name set changes; keep the live-sandbox partial unique index correct.

## Steps

1. Schema migration + store scan/columns + state constants.
2. Store verbs the later tasks need: mark-hibernated (with snapshot ref), find-hibernated-by-id, list-for-retention, set/unset pinned.
3. Adjust existing phase-driven code (Completer active/terminal sets, m67 counts, `sshAddress` gating) for the new state.
