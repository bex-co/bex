## Objective

Walk the full migration end to end on the dev stack: seed legacy-layout groups, run dry-run then apply, and verify every read/write verb and the quota behave identically before and after.

## Context

The milestone's DoD requires the migration proven against a real OpenBao, not only fakes. The dev stack is the local harness (`BEX_CP_IDENTITY=dev-N`, mock cluster + OpenBao per docs/ADR013-secrets.md); the backend integration-test envs (`BEX_TEST_DB_URI`/`BEX_TEST_OPENFGA_URL`) cover the store seams in CI, but this task exercises the operator-facing invocation path (`BEX_ENV_GROUP_PATH_MIGRATION` or whatever t002 named it) exactly as the prod runbook (t005) will describe it.

## Steps

1. On the dev stack, create env-groups in at least two workspaces **before** t001's build (or seed legacy paths directly via the OpenBao CLI under `tenants/data/default/env-groups/…`) so genuine legacy-layout data exists.
2. Deploy the t001–t003 build; confirm legacy groups still list/get/reveal via dual-read, and new writes land workspace-prefixed (inspect paths via `bao kv` against the `tenants` mount).
3. Run the migration in dry-run; check the report matches the seeded set. Run apply; verify tombstoned legacy paths and workspace-prefixed copies.
4. Post-migration sweep across REST + GraphQL + MCP: list, get by name, env-var reveal, secret-file reveal, link/unlink to a service, patch, delete; confirm cross-workspace lists stay disjoint.
5. Verify quota: create up to `BEX_MAX_ENV_GROUPS_PER_WORKSPACE` and confirm the `ENV_GROUP_LIMIT` refusal fires identically across the three surfaces.
6. Record the walk (commands + observed paths) in the milestone notes for t005's runbook to lift.

## Files

- No product code expected; findings feed back into `lego/backend/internal/envgroups/` fixes if the walk surfaces bugs.

## Acceptance criteria

- Seeded legacy groups are fully readable pre-migration, workspace-prefixed post-migration, with no verb regressions on any surface.
- Dry-run/apply reports match reality; re-running apply is a no-op.
- Quota refusal (`ENV_GROUP_LIMIT`) unchanged.

## Out of scope

- Prod execution (t005); performance benchmarking beyond eyeballing read fan-out.
