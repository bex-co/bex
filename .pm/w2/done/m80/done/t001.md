## Objective

Introduce a workspace-prefixed OpenBao path scheme for env-groups so every write lands on the owning workspace's prefix, while reads fall back to the legacy shared index until t002's migration completes.

## Context

ADR066 finding 3 (docs/ADR066-security-review-round11.md:33): env-group metadata lives in one shared index — `env-groups/<gid>/meta|env|files` (`lego/backend/internal/envgroups/service.go:202-204`), `env-groups/<gid>/revision` (`patch.go:65`) — under the legacy `default` tenant root, because env-groups never adopted w7/m70's tenant keying (`lego/backend/internal/secrets/store.go`: `withTenant`/`tenantFromCtx` are unexported; env-groups deliberately never sets a ctx tenant, per m70's ship record). The group's owning workspace is already durable in its stored meta (`workspace` key, w6/m24), so the target prefix is derivable per group.

## Steps

1. Decide the seam: either export the secrets store's tenant-ctx annotation for env-groups (mirroring m70 exactly: paths become `tenants/data/<ws>/env-groups/…`) or thread the workspace into the path helpers directly. Prefer the ctx-tenant seam — it reuses m70's tested prefixing, and the OpenBao `bex-api` role already grants `tenants/*` (m70 t003 was a no-op).
2. Make `metaPath`/`envPath`/`filesPath`/`revisionPath` (and the name-claim prefix) workspace-aware; every write (create, patch, revision CAS, link updates, delete) goes to the new prefix only.
3. Reads resolve new-prefix first, then legacy fallback (m70's `readMap` shape); do NOT lazily migrate-and-delete yet — t002 owns the explicit migration, so dual-read stays side-effect-free this task.
4. Keep the purger (`purger.go`) and clone paths cleaning both prefixes.
5. `cd lego/backend && go test ./...` green.

## Files

- `lego/backend/internal/envgroups/service.go`, `patch.go`, `nameclaims.go`, `purger.go`, `clone.go`, `revision.go`
- `lego/backend/internal/secrets/store.go` (only if exporting the tenant seam)

## Acceptance criteria

- New groups' meta/env/files/revision live under the workspace prefix; a unit test asserts the exact paths.
- A pre-existing legacy-path group still reads correctly (get, reveal, membership) via fallback.
- No REST/GraphQL/MCP wire change; existing envgroups tests green.

## Out of scope

- Migration/tombstoning of legacy data (t002); prefix-scoped list sweeps (t003); services' m70 layout.
