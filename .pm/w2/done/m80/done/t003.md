## Objective

Make every env-group read fan out over only the caller's workspace prefix, and retire (or narrow to per-workspace) the round-11 global-sweep snapshot cache that exists solely to bound the shared-index scan.

## Context

Today every list/name-resolution/membership read calls `s.Store.List(ctx, "env-groups")` (`lego/backend/internal/envgroups/service.go:386` in `sweepMeta`, plus `:1163`, `:1311`, `:1425`) and filters by workspace afterward; the 15s snapshot (`envGroupMetaCacheTTL`, `service.go:61`; `metaCache`/`sweepMeta`/`invalidateMetaCache`) plus the create quota were ADR066 #3's stopgap. With t001's workspace prefixes, the sweep can list one prefix. Content hydration (2 reads per matched group) then also touches only caller-prefix paths.

## Steps

1. Point `sweepMeta`/`listScopedMeta` at the caller's workspace prefix; keep the legacy-index union only while unmigrated legacy groups may exist (dual-read window), behind a check that is cheap when the legacy index is empty.
2. Convert the other three global `List` sites (`:1163`, `:1311`, `:1425` — membership/claim sweeps) to the same prefix-scoped walk.
3. Cache decision: prefer retiring `metaCache` outright — a per-workspace list is already bounded by `BEX_MAX_ENV_GROUPS_PER_WORKSPACE` (default 100) — but if hydration-heavy paths still benefit, narrow the snapshot key to workspace id and keep write-through invalidation. Record the choice in the code comment where `envGroupMetaCacheTTL` lives.
4. `claimGroupName`'s fresh legacy-metadata sweep (`service.go:1369`) must stay correct across the dual-read window (a legacy unmigrated group with the same name must still block a claim).
5. `cd lego/backend && go test ./...` green.

## Acceptance criteria

- With groups seeded in two workspaces, a list/name-resolution for workspace A performs zero store reads under workspace B's prefix (test-asserted via a recording fake `core.SecretKV`).
- Legacy-index union still surfaces an unmigrated group during the dual-read window.
- `ENV_GROUP_LIMIT` quota behavior unchanged.

## Out of scope

- The migration itself (t002); changing quota defaults; content-hydration read-count reduction beyond prefix scoping.
