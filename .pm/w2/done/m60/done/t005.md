## Objective

Make App and KeyValue status respond to status-only Deployment/StatefulSet/Pod changes and distinguish current-rollout readiness from stale available replicas.

## Context

- App applies its generation/deletion event filter to owned resources too.
- Deployment status changes normally do not increment generation.
- KeyValue checks only `availableReplicas` and filters StatefulSet status-only updates.

## Steps

1. Separate primary-resource predicates from owned-child predicates.
2. Watch the child status/Pod events needed for crash and rollout convergence without reconcile storms.
3. Require observed generation and current/update revision convergence before Ready.
4. Retain a bounded safety requeue for missed external events.

## Files

- `lego/operator/internal/controller/app_controller.go`
- `lego/operator/internal/controller/keyvalue_controller.go`
- `lego/operator/internal/controller/*_test.go`

## Acceptance criteria

- [x] A previously Ready App leaves Ready after its running Pods crash without an App spec update.
- [x] A failed StatefulSet rollout cannot report Ready from old replicas.
- [x] Successful rollout/status propagation is prompt and does not create an update loop.

## Out of scope

- Replacing bex health evaluation with Knative or OpenChoreo.
