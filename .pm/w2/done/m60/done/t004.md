## Objective

Prevent type changes from leaving an old Deployment/Service/Ingress/CronJob alive alongside the new workload kind.

## Context

- `App.spec.type` is mutable in the CRD.
- Blueprint updates can rewrite it through `applyCreateToSpec`.
- Type-specific reconcile branches do not prune all resources produced by previous types.

## Steps

1. Add CRD validation that makes `spec.type` immutable after creation.
2. Reject Blueprint/API attempts with the same named validation semantics before persisting divergent state.
3. Add tests for every source/target type pair and direct Kubernetes admission.
4. Document delete-and-recreate as the supported type-change path if that matches Render behavior.

## Acceptance criteria

- [x] Every attempted type transition fails before child resources change.
- [x] Existing same-type updates and Blueprint sync remain functional.
- [x] No old workload kind can continue running as a consequence of an accepted type update.

## Out of scope

- A migration engine that transforms a live service between workload kinds.
