# CAPD/dev-N: EnsureTenant does not provision `tea-*` namespaces before create

From **w2/m79** `cli-compat.sh verify` on **dev-2** with CLI v2.24.0. Auth/list/env passed; `services`/`postgres`/`keyvalues` create returned `500: namespaces "tea-…" not found`. No matching `tea-*` Namespace appeared in the cluster. Prior production baselines worked — this is a local control-plane / NamespaceReconciler (or stuck finalizer) harness failure, not a CLI wire bug. Reproduce on a fresh `dev-env.sh N up`, check NamespaceReconciler logs + RBAC, clear long-Terminating namespaces if they block.

**DONE 2026-08-23** — root cause was an async-provisioning race, not RBAC/finalizers/admission: `EnsureTenant` only writes the `tenants` row; namespace provisioning rides the NamespaceReconciler's 60s resync and `Kick()` was wired only to workspace delete. A create landing before the tick got `namespaces "tea-…" not found` (reproduced deterministically on dev-2: immediate POST → 500, namespace appeared 53s later). Fix: synchronous `NamespaceReconciler.EnsureWorkspace` + `core.Base.EnsureWorkspaceNamespace` (GET fast-path; nil/default-tenant no-op) called at the top of the apps/postgres/keyvalue create paths (8 files, incl. `cmd/api/main.go` wiring). Verified end to end on dev-2 with three fresh tenants: `POST /v1/postgres`, `/v1/services` (with env-var secret projection), `/v1/key-value` all 201 with `tea-*` namespaces provisioned synchronously; fixtures cleaned up. New tests in `store/namespaces_test.go` + `core/base_test.go`; package suites green.
