## Objective

`setPhase` and `setNotReadyCondition` discard the `Status().Update` error (`_ = …`). The Failed-branch design treats the Ready condition as "the durable marker … already persisted in status, so it survives a manager restart" — but a write conflict (the bex-api control-plane projector rewrites App CRs on resync, racing the operator's cache read) silently loses the marker, and every gate built on it (`buildOutcomeAlreadyRecorded`, t002/t006) misses.

## Context

- Live prod evidence 2026-08-20: after the first `r.fail` for `market-size` at 22:31:31Z, the recorded-marker gate should have halted every subsequent reconcile — instead 8 consecutive `Reconciler error` retries followed a perfect exponential backoff through 22:42:22Z (22 ERRORs/25m across two Apps). Persistent non-engagement of the gate is consistent with the status write silently failing each pass.
- `lego/operator/internal/controller/app_controller.go:3313` (`setPhase`) and `:3326` (`setNotReadyCondition`) both `_ = sw.Update(ctx, obj)`.

## Steps

1. On conflict, retry with a fresh `Get` + re-apply of phase/condition (`retry.RetryOnConflict` or the controller-runtime idiom already used elsewhere in this file); on other errors, log at ERROR with the app name so a lost marker is visible.
2. Audit the other `_ = r.Status().Update` sites in the App reconciler for the same swallow; fix the ones guarding durable markers, leave true best-effort progress updates logged at V(1).
3. Keep `r.fail`'s contract: ObservedGeneration stays unstamped on failure.
