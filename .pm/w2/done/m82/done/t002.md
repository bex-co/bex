## Objective

Once an App's Ready condition already records this generation's terminal build failure reason, return success from the Failed branch — do not call `r.fail` again (controller-runtime ERROR + exponential requeue).

## Context

- Live ERROR: `controller=app` … `build failed: PodFailurePolicy: … exit code 90` repeating for Apps already `phase=Failed` with `BuildFailedUserError`.
- Metering was gated by `buildOutcomeAlreadyRecorded`; `r.fail` still returned an error every pass (~20×/h until Job TTL).
- `r.fail` must still run **once** so phase/Ready are written; ObservedGeneration must stay unstamped on failure (successfulReleaseGeneration).
- Draft already in tree: `lego/operator/internal/controller/app_controller.go` `build.PhaseFailed` branch.

## Steps

1. If `buildOutcomeAlreadyRecorded(app, view.reason)` → `return halt(ctrl.Result{}, nil)`.
2. Else meter + `return halt(r.fail(...))` exactly once.
3. Confirm Failed Apps stay Failed until generation bumps; Job delete / Owns(Job) still wakes Observe correctly.

## Files

- `lego/operator/internal/controller/app_controller.go`

## Acceptance criteria

- [x] First Failed observation still sets phase Failed + Ready reason/message
- [x] Subsequent reconciles for the same generation produce no `Reconciler error`
- [x] ObservedGeneration is not advanced on failure

## Out of scope

- Changing exit-90 tenant-vs-infra classification
- Deleting or auto-retrying tenant Failed Apps
