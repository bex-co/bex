## Objective

Build the migration tool that moves one legacy App's artifacts to the workspace-scoped scheme: enumerate its bare-name Zot repository tags and static S3 prefix objects, copy them to the new locations (registry copy preserving digests — Skopeo-style, as the post-build push path already uses; S3 server-side copy), verify (image digest equality per tag; object count + ETag/size per key), flip the App to the new scheme, and tombstone the legacy location per t001 so dual-read stops consulting it. Idempotent and resumable; dry-run by default.

## Context

- Legacy locations: Zot repo `<app.Name>` with tags `gen-N` (`lego/operator/internal/build/build.go:394-399`), htpasswd user `app-<name>` + ACL (`lego/operator/internal/registry/creds.go:101-104`, `lego/operator/internal/registry/zotconfig.go`), S3 prefix `<appID>/<revision>/` (`lego/operator/internal/publish/publish.go:144`).
- Credentials: Zot admin-side edits go through the `zot-htpasswd`/`zot-config` Secrets in `BEX_REGISTRY_NS` (operator-managed; see `scripts/registry-secrets.sh` for the out-of-band bootstrap and the `bex-builder` wildcard-read user usable for enumeration); S3 uses the publish Secret (`BEX_STATIC_PUBLISH_S3_SECRET`, production `bex-static-publish-s3` in `BEX_BUILD_NAMESPACE`).
- Deployment image refs bake the old repo (`ADR055` F3's outage risk, docs/ADR055-security-review-round4.md:44): the tool must NOT delete legacy image blobs while any Deployment still references them — tombstone means "no new writes + dual-read marker", deletion is a separate runbook step (t007).
- Precedent for operator-adjacent tooling: `lego/operator/cmd/` (manager, staticserver, sni proxies) — add a small `cmd/` binary or a `scripts/` Go-run tool; artifact inventory helpers exist in `lego/operator/internal/build/artifacts.go` (`ReclaimAppArtifacts`).

## Steps

1. Decide packaging (suggest `lego/operator/cmd/registry-migrate` reusing `internal/registry` + `internal/publish` scheme helpers from t002/t003).
2. Implement per-App migration: enumerate → copy → verify → update App labels/status to the new scheme → write tombstone + mint new creds / retire legacy user per t001.
3. Make it idempotent (re-run skips verified-complete work) with `--dry-run` default and explicit `--app`/`--all` selection.
4. Unit-test verification logic against fakes (digest mismatch fails the App's migration and leaves the legacy location authoritative).
