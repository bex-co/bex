## Objective

Make the group page tell the truth about the auto-deploy gate that t001 shipped. t001 step 4 required the copy "Linking or unlinking redeploys linked services that have auto-deploy on." in `en` and `zh`, and the DoD's second bullet checks for it. The live re-probe on 2026-09-27 (`/qa-find-bugs` pass 225, recorded in the milestone README) found the old copy still on the page: `/env-groups/<evg>` → Linked Services reads **"Linking or unlinking redeploys every affected service."** Linking the group to a service with auto-deploy off opened no deploy row on that service, so the copy is wrong exactly in the case the gate exists for.

## Context

- `dashboard/src/features/env-groups/locales/en.ts:392-394` `envGroups.servicesDescription` still reads "Linking or unlinking redeploys every affected service." The `zh` twin is presumably the same.
- Same inaccuracy, same card family: `en.ts:~384-386`, the delete-env-group-secret-file warning "Every linked service will redeploy without this file." A secret-file delete is a group write and follows the same gate (ADR013 rule 3).
- The shipped gate, observed live in pass 225: a PUT to the group's `MESSAGE` opened a `config_change` deploy on the auto-deploy-on service and none on the auto-deploy-off one. The batch `PATCH …/contents` response listed the latter under `pendingServiceIds`.

## Steps

1. Change `envGroups.servicesDescription` to "Linking or unlinking redeploys linked services that have auto-deploy on." in `en` and the matching `zh` string.
2. Correct every other env-group copy string that promises an unconditional redeploy (at least the delete-secret-file warning; grep the env-groups locale for "redeploy").
3. Update any component test that pins the old string.

## Acceptance criteria

- [ ] `/env-groups/<evg>` shows the gate-aware sentence in both locales.
- [ ] No env-group copy promises that every linked service redeploys.

## Out of scope

- Listing the specific services that will not redeploy in the UI. `pendingServiceIds` on the batch response already carries that for API callers.
