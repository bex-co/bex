# 076 — A deleted static site never finishes deleting on dev-N (missing static publish credential)

Why: in the w2/m256 t015 dev-2 walk (2026-11-08), a deleted static site stayed Terminating. The operator logged `static publish credential Secret bex-build/bex-static-publish-s3 is unavailable`, and its finalizer had to be removed by hand. Any dev-N walk that deletes a static site, or reuses its name, hangs.

- **Do:** have `dev-env.sh` (or `mock-cluster.sh`) provide a dev publish credential and bucket stand-in, or make the operator's static-content purge tolerate an absent credential on clusters that never published. Production behavior must not change.
- **Acceptance:** on dev-2, creating then deleting a static site completes without manual finalizer edits.

## Done for its scope (2026-11-08, `/loopx w2`); remaining acceptance moved to w2/m293

- **Fix (b), in the operator:**
  - `publishStaticRevision` stamps `app.bex.co/static-publish-dispatched=<UID>` before the first publish Job is dispatched.
  - On delete, `latchStaticPublishEvidence` latches that marker if an older operator left traces: an App-controlled publication record or a publish Job.
  - With the store unconfigured or the credential missing, the purge lets the finalizer go only when there is no publish evidence (marker, `activeRevision`, `staticPrefix`). Otherwise it fails closed as before.
- **Production:** behavior is unchanged when the credential is present. An earlier-published site with the credential missing still blocks.
- **Docs:** ADR029 § Deletion.
- **Checks:** `static_purge_decision_test.go` and the envtest cases pass, as do `GOWORK=off make test` and `make lint`.
- **On dev-2:** the static purge now logs `static site never published; no object-store content to purge`. Deletion still hangs on a separate blocker: the mock has no Zot, but `BEX_REGISTRY` names it. That is filed as **w2/m293**, which carries this note's acceptance check.
