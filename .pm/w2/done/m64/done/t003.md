## Objective

Apply the accept-fast/provision-async split to `Steer` and `Resume`: the synchronous half keeps the guards and the phase transition (`redispatching`/`resuming`), while the old-sandbox teardown + fresh dispatch (Steer) or sandbox resume (Resume) run in the background using t001's supervised-dispatch machinery.

## Context

- `Steer` (`lego/backend/internal/agentsessions/service.go:507`): after guards it synchronously sets `PhaseRedispatching`, cancels the old sandbox, and calls `dispatch` — the same tens-of-seconds block as create.
- `Resume` (`service.go:380`): sets `PhaseResuming`, then blocks on `ResumeAgentSessionSandbox`.
- The conflict guards must stay synchronous and unchanged: `AGENT_SESSION_TURN_IN_FLIGHT` (phase `creating|running|resuming|redispatching`), `AGENT_SESSION_NOT_STEERABLE`, `AGENT_SESSION_NOT_RESUMABLE` — setting the transitional phase synchronously before returning is what makes double-steer impossible.
- Steer's prompt validation (empty / >100k) stays sync.
- Failure paths keep today's semantics, just recorded async: teardown failure → `failed`/"steer teardown failed"; dispatch failure → `failed`; resume failure → `failed`/"sandbox resume failed".
- Cancel-vs-background-work race: same phase re-check discipline as t001.

## Steps

1. Split `Steer`: sync guards + `PhaseRedispatching` + return the view; background = teardown → `dispatch` (with t001's runner).
2. Split `Resume` the same way around `PhaseResuming` → `ResumeAgentSessionSandbox` → `PhaseRunning`.
3. Verify `Create`'s `ResumeSessionID` delegation path composes with the async `Resume`.
4. Extend fakes/tests for both async paths, including the double-steer rejection while a background re-dispatch is in flight.
