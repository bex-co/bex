## Objective

Verify the changed create/steer/resume/attach-ticket semantics are consistent across every surface they expose: REST, GraphQL, and MCP return the same phases, same optional-ticket shape, and same named error codes; the dashboard renders honestly against them. Agent sessions are a bex extension with no Render equivalent, so this pass is cross-surface consistency (per `docs/ADR006-bex-api.md`'s one-core/thin-adapters rule), not a render.com comparison.

## Context

- `lego/backend/internal/agentsessions/{rest,graphql,mcp}.go` — the three adapter fragments over the one service.
- New/changed observable behavior: fast-return phases (`pending`/`creating`, `redispatching`, `resuming`), optional attach ticket, the attach-not-ready named error, unchanged sync validation 400s and conflict 409s.
- `docs/ADR047-cloud-coding-agent-sessions.md` — update the lifecycle description if it states create blocks until the sandbox is up; ADR051/ADR018 likely untouched but scan for stale claims.

## Steps

1. Exercise create/steer/resume/attach on all three surfaces (tests or dev stack) and diff fields, phases, and error codes.
2. Fix any drift in the thin adapters (never fork the core).
3. Update ADR047 (and any other doc stating the synchronous behavior); run prettier over touched markdown.
