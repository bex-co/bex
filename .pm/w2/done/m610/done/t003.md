## Objective

Ensure push-triggered carrier builds create a properly shaped carrier deploy row (`bld-…`) with commit metadata and default auto-deploy fan-out scope, so `deploys.BuildSucceeded` deploys every linked non-suspended service with `autoDeploy: true` once the carrier build completes.

## Context

- `redeployCandidates` calls `h.Svc.redeployFetched(ctx, a, ev.commitInfo())` (`webhook.go:1125`).
- `deploys.BuildSucceeded` (`lego/backend/internal/deploys/build_sources.go`) reads the carrier deploy's `build_deploy_scope` (empty/`autodeploy_only` fans out to linked services with `autoDeploy: true` and skips suspended services) and records `buildId` on every fan-out deploy.
- Verify whether `redeployFetched` on a carrier needs `core.WithBuildSources(ctx)` or special trigger/commit handling so the resulting `BuildView` (`GET /v1/build-sources/{id}/builds`) shows `commitId`, `commitUrl`, and status accurately.

## Steps

1. Trace `redeployFetched` → `DeployRecorder` / `OpenDeploy` → operator build Job → `BuildFanout` → `deploys.BuildSucceeded` for a `TypeBuildSource` App triggered by webhook push.
2. Fix any carrier-specific guard or trigger/commit plumbing so the carrier build row opens cleanly with `Trigger: new_commit`, `CommitID`/`CommitURL`, and empty/`autodeploy_only` deploy scope, and returns cleanly in `GET /v1/build-sources/{id}/builds`.
3. Verify linked services with `autoDeploy: false` or suspended are not deployed on push fan-out, while linked services with `autoDeploy: true` (or waiting for first build) receive exactly one deploy pinned to the new `bld-…`.

- `lego/backend/internal/apps/webhook.go`

## Acceptance criteria

- [x] A push-triggered carrier build opens a `bld-…` row with `commitId`/`commitUrl` and bumps the carrier App so the operator builds the pushed commit.
- [x] Completing the carrier build fans out via `deploys.BuildSucceeded` to linked `autoDeploy: true` non-suspended services and skips `autoDeploy: false` and suspended services.
