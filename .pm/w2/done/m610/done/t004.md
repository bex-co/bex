## Objective

Keep Build Source carriers faithful to ADR097 §Consequences during webhook handling: never emit service-only `commit_ignored` or `branch_deleted` service events onto carrier feeds, never enlist carriers in `checksPass` awaiting-checks state, and handle `serveDelete` / branch deletion cleanly.

## Context

- `docs/ADR097-build-sources.md` §Consequences: a carrier is not a service — service event feeds and deploy webhook events exclude carriers.
- `lego/backend/internal/apps/webhook.go`: `prepareCheckedPush` (line 1068), `recordBranchDeletedCandidates` (line 1003), `recordCommitIgnored` (line 1167), and `serveDelete` (line 665) all receive `candidates` from `repoCandidates`.
- `lego/backend/internal/apps/checks_pass.go` handles `check_suite` events.

## Steps

1. Guard `prepareCheckedPush` and `redeployCandidates`'s `checksPassTrigger` branch so `core.IsBuildSource(a)` carriers never enter `checksPass` pending state.
2. Guard `recordCommitIgnored` so skipped carrier pushes do not write service-event facts for `bds-…` (or verify whether `EventFacts` already ignores/excludes them and make exclusion explicit).
3. Decide and enforce `branch_deleted` behavior on carriers in `servePush` (`branchDeleted`) and `serveDelete`: do not disable `AutoDeploy` on a carrier in a way that permanently bricks a git Build Source (which has no user-facing `autoDeploy` toggle on Render), and do not emit service-only `branch_deleted` facts for carriers; document this behavior in `ADR097`.

## Files

- `lego/backend/internal/apps/webhook.go`
- `lego/backend/internal/apps/checks_pass.go`
- `docs/ADR097-build-sources.md`

## Acceptance criteria

- [x] A skipped commit or deleted branch on a git-backed Build Source's repo never writes bogus service event facts for `bds-…` and never permanently breaks future pushes after branch recreation.
- [x] `prepareCheckedPush` and `serveCheckSuite` never enqueue or mutate Build Source carriers.

## Out of scope

- Outbound webhook events for Build Source builds (Render defines none).
