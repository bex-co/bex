## Objective

Add `Create` and `Delete` to the apps feature `Service` — the single implementation every adapter delegates to. `Create` validates the request (name, plan against the tiers catalog, image or repo, optional env vars) and writes the `App` CR; `Delete` removes it. When the control-plane store is enabled (`BEX_CP_DB_URI`), both write through the apps row (single-writer-of-intent, per w1/m2) so the projector never reverts them.

## Context

- Feature-package layout: verbs live in `lego/backend/internal/apps/service.go`, adapters are thin fragments beside it (`docs/bex-api.md` "one core, three adapters").
- Plan validation reads the tiers catalog from `lego/types/tiers` (w1/m8).
- w1/m2's rule: when the store runs, the row owns projection-owned spec fields — lifecycle verbs write the row, the projector reconciles the CR. Store-less mode writes the CR directly (same as suspend/resume today).
- A `repo`-backed body is accepted and validated but the built-from-git path only converges once w1/m5 lands — document, don't fake.

## Steps

1. Add `Create(ctx, req)` — validate name (`RFC 1123` label), plan (tiers catalog), exactly one of image/repo, env var names; construct the `App` CR spec; write row-then-projection when the store is enabled, else create the CR.
2. Add `Delete(ctx, id)` — remove the row (store mode) / delete the CR; `ErrNotFound` for unknown ids.
3. Return the same `service` object shape the existing verbs return.

## Files

- `lego/backend/internal/apps/service.go`
- `lego/backend/internal/store/` (create/delete row helpers, if store mode needs them)

## Acceptance criteria

- [ ] `Create` with a valid image-backed request yields an `App` CR the operator converges; invalid name/plan/body → typed validation error.
- [ ] `Delete` removes the CR (and row in store mode); unknown id → `ErrNotFound`.
- [ ] With `BEX_CP_DB_URI` set, create/delete survive a projector resync (no revert).

## Out of scope

- Adapter fragments (t002/t003); building from `repo` (w1/m5); deploy history records (w2/m5).
