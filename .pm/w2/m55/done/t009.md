## Objective

Add meaningful tests for the behavior this milestone shipped: exec-ticket authz/TTL/single-use, gateway WebSocket exec (validation + bridge + fail-closed matrix + content-free audit), and the dashboard terminal/picker/reconnect. Tests must assert real behavior and failure modes — no tautological or snapshot-everything coverage.

## Context

- Backend patterns to mirror: m39's `sshgateway` tests (in-process handshake, PTY resize, exit status, deleted-key/forbidden-target denial, session caps, content-free audit) and the real-store integration tests (fingerprint lookup, session start/end/retention). The WS path should get analogous coverage.
- The opt-in real-cluster exec test (`TestGatewayRealKubernetesExec`) is the precedent for exercising the actual `pods/exec` bridge without mutating a cluster during ordinary `go test`.
- Dashboard patterns: existing hook/component tests (e.g. the SSH-keys hook tests, log-viewer tests) show how WS/stream UIs are tested here.

## Steps

1. Ticket tests (t002): authorized mint vs. free/suspended/foreign/unauthorized denial; TTL expiry; single-use reuse rejected; bex-api-has-no-`pods/exec` guard.
2. Gateway WS tests (t003): valid ticket opens stream; invalid/expired/reused/foreign ticket rejected with no exec; targeting matches m39 (bare random-Ready, specific instance, non-Ready/stale/terminating fail closed); session caps counted; resize + exit propagated; disconnect/redeploy/restart/timeout close the stream; `ssh_sessions` row written with no terminal-content field.
3. Dashboard tests (t004–t006): terminal mounts and streams against a mock WS; instance picker selects/targets; unavailable/free states render; close-reason messages + reconnect (re-mint) behave; teardown closes the socket.
4. Run `cd lego/backend && go test ./...`, dashboard `yarn test` + `yarn lint`.
