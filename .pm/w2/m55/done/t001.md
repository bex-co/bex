## Objective

Design the browser-hosted Web Shell and lift the anti-goal that currently forbids it. Produce a settled architecture (transport, auth model, re-drawn security boundary) recorded in `docs/ADR035-ssh.md`, and amend `.pm/DO_NOT_DO.md` to record the user's explicit reopening — the same way the 2026-07-14 SSH reopening amended it for `w2/m39`. No silent conflict may remain.

## Context

- Today the browser terminal is a documented non-goal in **two** places: `docs/ADR035-ssh.md` (§Explicit non-goals lists "browser terminals"; §Public contract says the Shell page is "a copy-ready running-instance SSH guide, not Render's browser-hosted terminal … keeping private keys and terminal streams out of the browser") and `.pm/DO_NOT_DO.md` (the "browser-hosted Shell terminal" entry ~line 22 and the render-parity `—` non-goals bullet).
- The security rationale in ADR035 is real: `pods/exec` is confined to the isolated ssh-gateway ServiceAccount; **bex-api must not inherit `pods/exec`**. The browser transport must not break that split.
- User decision 2026-07-17 (this session): reopen the browser terminal, transport "consistent with render.com" (browser WebSocket → backend → exec). Render shows both a live terminal and the copy-ready `ssh` command.
- Precedent for the reopening edit: `w2/m39` moved interactive SSH out of `DO_NOT_DO.md` per an explicit user decision; mirror that citation style.

## Steps

1. Decide the transport: **gateway WebSocket** (browser → WS on the isolated ssh-gateway → `pods/exec`) as the default, because it keeps `pods/exec` isolated in the gateway. Record the rejected alternative (bex-api WS bridge → gateway over SSH) and why (terminal streams would traverse the main API surface; weaker isolation).
2. Decide the browser auth model: no SSH private key in the browser. The dashboard's Kratos session authorizes a short-lived, workspace+service-scoped **exec ticket** (minted by bex-api after `AuthorizeApp(can_operate)`) that the gateway validates before opening the exec stream. Specify ticket contents, TTL, signing/validation, and single-use semantics at the design level (implementation is t002/t003).
3. Add a "Browser Web Shell" section to `docs/ADR035-ssh.md`: connection path, the re-drawn boundary ("terminal streams reach the browser over an authenticated gateway WebSocket, but only after a `can_operate` ticket; bex-api still has no `pods/exec`; audit still records no terminal content"), and the preserved fail-closed cases. Update §Explicit non-goals so "browser terminals" is no longer listed as forbidden (SFTP/SCP, forwarding, ephemeral shells stay).
4. Amend `.pm/DO_NOT_DO.md`: update the "browser-hosted Shell terminal" entry and the render-parity non-goals bullet to record that the browser Web Shell was explicitly reopened 2026-07-17 and is tracked as `w2/m55` (leave one-off jobs / ephemeral shells / sandboxes excluded).
5. Run `npx prettier@3.4.2 --write "**/*.md"`.
