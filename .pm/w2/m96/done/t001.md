## Objective

Add a durable, tenant-scoped record mapping each metered resource id (service, Postgres, Key Value, sandbox) to the last display name bex knew for it. It is written on create and on rename, is never deleted when the resource is deleted, and is purged only with its workspace. Later tasks read names from this record instead of from live resources.

## Context

- `lego/backend/internal/usage/service.go:161-163` states the current contract: `ServiceName` is "Empty when the resource no longer exists — presenters fall back to ServiceID."
- `resolveServiceNames` (`usage/service.go:286-313`) fills names only from `Store.ListApps` and the live Database/KeyValue CRs; it has no sandbox branch.
- Sandbox usage rows store only the sandbox UUID as `service_id` (`lego/backend/internal/store/sandbox_meter.go:238-248`) with no label. A sandbox has no name field (`internal/sandbox/graphql.go:45-56`).
- Workspace deletion teardown lives in the `w1/done/m61` path; the new table must be included in its purge.
- Migrations live under `lego/backend/internal/store/migrations/` (next free number — scan first).

## Steps

1. Add a migration for a table shaped like `(tenant_id, resource_kind, resource_id) → display_name, updated_at`, keyed by id so a deleted-then-recreated resource with the same name stays two rows.
2. Write the record from the create and rename paths of services, Postgres, Key Value and sandboxes (sandbox label: owning agent session repo + branch when one exists, else `plan · image`; write it at sandbox create and when the session binds).
3. Add a store accessor that resolves a batch of `(kind, id)` to names for one tenant.
4. Hook the workspace teardown so the tenant's rows are purged with everything else.
5. Real-Postgres store tests: write on create, overwrite on rename, survive resource deletion, same-name re-create yields two rows, workspace purge removes all rows.
