## Objective

Expose `serviceName` on the webhook delivery read (REST and GraphQL) taken from the delivery's stored request payload, and render it in the Recent deliveries table as a link to the service with the id as secondary text. A delivery for a since-deleted service keeps its recorded name.

## Context

- `dashboard/src/features/webhooks/components/webhook-deliveries-card.tsx:288-290` renders `{delivery.serviceId || "—"}` in a truncated mono cell.
- `WebhookDeliveryView` (`dashboard/src/features/webhooks/types.ts:36-56`) has no `serviceName`.
- The delivered payload already carries `data.serviceName` (`lego/backend/internal/webhooks/worker.go:346-349`, kept current across renames by `w6/done/m101`).
- Prefer a server-side field over parsing `requestBody` in the browser so REST and GraphQL agree and deleted services still resolve.

## Steps

1. In the delivery read path, extract `data.serviceName` from the stored payload into a `serviceName` field on the delivery view; expose it on the REST delivery/history envelope and the GraphQL `WebhookDelivery` type.
2. Update the dashboard delivery fragment + codegen; render the name as a link to `/services/<id>` (unlinked with a deleted marker when the service no longer resolves), with the id in secondary text/tooltip and still copyable.
3. Update the deliveries-card test: name renders; a delivery for a deleted service still shows its recorded name.

## Files

- `lego/backend/internal/webhooks/` (delivery view, REST + GraphQL adapters)
- `dashboard/src/features/webhooks/types.ts`, `api/webhooks.graphql`, `components/webhook-deliveries-card.tsx` + test

## Acceptance criteria

- [ ] Backend and dashboard test suites green.
