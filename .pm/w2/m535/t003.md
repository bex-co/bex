## Objective

Configure `/v1/sandboxes` Pods (for `allow-all` and `allow-list` policies when the broker is configured) with `HTTPS_PROXY`/`https_proxy`/`NO_PROXY` pointing at `bex-ssh-gateway`'s broker port and with the public Sandbox Broker CA trusted across standard TLS stacks (`SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS`, and system CA bundle) without requiring user code changes and without exposing any credential secrets.

## Context

- Base sandbox template runs `bash:5.3` (Alpine + bash, `HOME=/home/render`), and users may also start sandboxes from imported custom images (`python:3.13`, `node:*`, Debian/Ubuntu/Alpine images via `w2/m358`) or snapshots (`w32/m285`).
- Injected env vars must sit below user-provided `env` or handle `NO_PROXY=localhost,127.0.0.1,::1` cleanly while refusing caller attempts to inject reserved `BEX_` vars (existing `env` validation in `sandbox`).
- `deny-all` sandboxes must NOT receive broker proxy access (they have zero egress).
- Only the **public** Broker CA cert (never a secret) is placed in the Pod; when a user adds a credential to the group later, already-running sandboxes already point at the broker and pick it up live with no restart.

## Steps

1. Wire `bex-api` sandbox create/resume/restore to inject the broker proxy URL (`HTTPS_PROXY`, `https_proxy`, `NO_PROXY`) and materialize the combined public system + Sandbox Broker CA bundle (or public CA file + `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS`, `CURL_CA_BUNDLE`) for `allow-all` and `allow-list` `/v1/sandboxes` Pods (never for `deny-all`, never for agent-session pods).
2. Ensure imported custom images (Alpine, Debian/Ubuntu, Python, Node, Go) trust both normal public CAs (for pass-through TLS) and the Sandbox Broker CA (for selectively intercepted credentialed hosts).
3. Add unit tests verifying the exact env/CA projection across `allow-all`, `allow-list`, `deny-all`, imported images, and `BEX_SANDBOX_BROKER_URL` unset (graceful no-op).

## Acceptance criteria

- [ ] `allow-all` and `allow-list` sandboxes (default base image and imported Python/Node images) trust both public CAs and the Sandbox Broker CA and send HTTPS through `bex-ssh-gateway`'s broker automatically.
- [ ] `deny-all` sandboxes receive no proxy/broker wiring; zero secret values exist anywhere in the Pod env or filesystem.
