# 075 — Creating a service under a name whose App is still being deleted may answer 500

Why: the w2/m256 t015 fix (2026-11-08) handles a still-terminating App's name in the Blueprint plan path. A plain `POST /v1/services` (and GraphQL/MCP create) with that name likely meets the same AlreadyExists ("object is being deleted") inside `planNewApp`/`writeNewApp` and returns 500. This is unverified.

- **Reproduce:** on dev-2, delete a service, then immediately create one with the same name.
- **Render:** check whether Render lets a just-deleted name be reused. Then answer the same way, or with a named 409 ("the earlier service with this name is still being deleted; retry shortly"), never a 500.
- **Acceptance:** a REST/GraphQL/MCP test with a terminating holder. The dev-2 walk returns no 500.
