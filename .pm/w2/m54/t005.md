## Objective

Replace settled opaque-id titles on Postgres, Key Value, environment-group, and Blueprint details with Render-shaped human-name/resource-type titles available during authenticated SSR.

## Context

- The four current route heads template URL params, so an id remains in the browser tab after page data renders.
- Render emits `<name> ・ Database`, `<name> ・ Key Value`, `<name> ・ Blueprint`, and the equivalent named Environment Group prefix before its brand suffix.
- Database/Key Value log tabs are search-param views of the same resource and must keep the parent resource title.

## Steps

1. Add cache-sharing loader/head data for Database, Key Value, environment-group, and Blueprint name/type resolution.
2. Format each title through the shared helper and translated resource-type label.
3. Keep datastore overview/log views title-identical and make rename/refetch update the title.
4. Define loading/not-found/error fallbacks without treating query/schema/auth failure as resource absence.

## Files

- `dashboard/src/routes/databases.$databaseId.tsx`
- `dashboard/src/routes/keyvalue.$keyValueId.tsx`
- `dashboard/src/routes/env-groups_.$groupId.tsx`
- `dashboard/src/routes/blueprints.$blueprintId.tsx`
- `dashboard/src/features/{databases,keyvalue,env-groups,blueprints}/`

## Acceptance criteria

- [ ] Authenticated SSR and settled client titles lead with the human resource name, never the opaque id.
- [ ] The resource type matches Render's current taxonomy and is translated with the active bex locale.
- [ ] Database/Key Value log tabs do not add `Logs` or mint a competing title.
- [ ] Head and page share fetched data; title support does not double each resource query.

## Out of scope

- Resource-detail layout changes or new API fields.
