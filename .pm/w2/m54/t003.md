## Objective

Give project overview/settings and workspace-scoped pages Render's name-first title hierarchy from authenticated SSR data, replacing the two client-only `document.title` effects.

## Context

- Project overview currently SSRs `Project · bex dashboard`, then changes after `useProjects()` resolves.
- Project Settings currently SSRs a generic title and settles on `Settings · <project> · ...`; Render emits `<project> / Settings ・ Render Dashboard` (and includes environment between them when present).
- Workspace-global pages should remain page-named; they must not accidentally use a stale project title after navigation.

## Steps

1. Add a loader/cache seam that resolves the current project name once and is available to both route head and page data without duplicate GraphQL traffic.
2. Render `<project name> ・ bex Dashboard` for overview and `<project name> / Settings ・ bex Dashboard` for settings.
3. Remove direct `document.title` writes and define loading/not-found/error fallback titles.
4. Verify rename invalidates/refetches the title and leaving a project restores the destination's own title.

## Files

- `dashboard/src/routes/project.$projectId.tsx`
- `dashboard/src/routes/project.$projectId.index.tsx`
- `dashboard/src/routes/project.$projectId.settings.tsx`
- `dashboard/src/features/projects/`

## Acceptance criteria

- [ ] Authenticated SSR HTML contains the project name for overview and settings, not the opaque id or a generic `Project` placeholder.
- [ ] Settings uses Render's name-first slash hierarchy.
- [ ] Renaming a project updates the title; project-to-global navigation cannot retain the prior project name.
- [ ] The route head and page consume one cached project result; no second request exists solely for title generation.

## Out of scope

- Adding an Environment detail page or changing project membership behavior.
