## Objective

Add regression coverage that proves the head contract on initial SSR, hydration, client navigation, resource-data changes, locale changes, private metadata boundaries, and every route category.

## Context

- Component-only assertions of `document.title` do not prove SSR output or metadata ordering.
- The highest-value regressions are stale titles after navigation, ids that never resolve to names, duplicate head tags, private names in OG/Twitter, self-hosted pages pointing at the hosted SaaS, and a new unclassified route.
- The existing w5/m42 service tests are useful inputs but cover only post-load client effects.

## Steps

1. Test the title formatter and global metadata fields, deduplication, privacy boundary, and configured/request-origin behavior.
2. Add SSR/direct-load tests for static, auth, project, each service type, deploy detail, Database, Key Value, env group, Blueprint, error, and not-found representatives.
3. Add client-navigation/rename/locale tests proving titles update and never retain prior-route private state.
4. Enforce the complete route classification and run `yarn typecheck`, `yarn lint`, `yarn test`, and `yarn build`.

## Files

- `dashboard/src/common/lib/__tests__/`
- `dashboard/src/routes/__tests__/`
- `dashboard/src/features/**/__tests__/`

## Acceptance criteria

- [ ] Tests inspect rendered SSR head output, not only JSDOM's final `document.title`.
- [ ] Dynamic resource names/types, tab inheritance, rename, errors, not-found, and en/zh navigation are covered.
- [ ] A test fails if any private resource value enters description/OG/Twitter metadata or if a self-hosted origin points at `dashboard.bex.co`.
- [ ] A newly generated unclassified route fails with an actionable message.
- [ ] `yarn typecheck && yarn lint && yarn test && yarn build` pass.

## Out of scope

- Snapshotting whole HTML documents or testing TanStack Router internals.
