## Objective

Make the route inventory exhaustive and enforce which routes own, inherit, redirect, or omit a document head so future route additions cannot silently fall back to stale metadata.

## Context

- The current 58-route inventory includes rendered content, parent layouts, service children, Render-shaped aliases, legacy auth/create aliases, two non-HTML server APIs, and catch-all/error states.
- Adding independent heads to aliases or service tabs would break canonical inheritance; leaving a new content route unclassified would recreate today's drift.
- Error/loading/not-found navigation must not show the title from the previous successful page.

## Steps

1. Check in a route-family manifest or equivalent test fixture classifying every route as content, inherited-layout, redirect-only, non-HTML, or fallback.
2. Centralize explicit error, not-found, and loading title behavior with localized prefixes and generic social metadata.
3. Assert aliases redirect before rendering, API handlers emit no HTML head, and service/project child routes inherit only their intended parent title.
4. Add a failure message that tells future contributors how to classify a newly generated route.

## Files

- `dashboard/src/routes/`
- `dashboard/src/routes/__tests__/`
- `dashboard/src/common/root-route/`
- `dashboard/src/common/lib/`

## Acceptance criteria

- [ ] All 58 current routes are classified; adding an unclassified route fails a focused test.
- [ ] Redirect-only and non-HTML routes do not own competing metadata.
- [ ] Error/not-found/loading states use deterministic localized titles and never retain private names from the previous route.
- [ ] Inherited titles remain explicit for service tabs/deploy detail and project layouts.

## Out of scope

- Changing redirect destinations or API-handler behavior.
