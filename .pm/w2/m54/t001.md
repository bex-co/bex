## Objective

Create one typed, SSR-safe dashboard head contract and use it from the root route to emit bex-branded global metadata matching Render's generic-shell behavior.

## Context

- The audit records Render's `prefix ・ Render Dashboard` formatter and its static description/Open Graph/Twitter shell.
- Route-specific names belong only in `<title>`; putting tenant names into OG/Twitter tags would leak private state into link previews.
- bex is self-hostable, so absolute image/origin metadata cannot silently hard-code `dashboard.bex.co`.
- Use existing mission language and branded assets; do not copy Render's text or images.

## Steps

1. Add one small head/title module owning the brand suffix, separator, generic metadata, and safe origin/image URL construction.
2. Extend `__root.tsx` with description, Open Graph, Twitter, locale/site-name, viewport, favicon, and any required social-card asset.
3. Keep social metadata static and generic while allowing route matches to override only `<title>`.
4. Define behavior when the configured/request origin is unavailable; never emit a misleading SaaS URL for a self-hosted install.

## Files

- `dashboard/src/common/lib/`
- `dashboard/src/routes/__root.tsx`
- `dashboard/public/`
- `dashboard/src/**/locales/`

## Acceptance criteria

- [ ] One formatter produces `prefix ・ bex Dashboard`; route code does not concatenate brand/separator copies.
- [ ] The initial SSR head includes accurate bex description, OG, and Twitter metadata with a self-host-safe absolute image URL.
- [ ] Global social tags contain no tenant name, resource name/id, deploy id, email, or other private route data.
- [ ] Metadata copy is i18n-aware where appropriate and makes no product claim beyond the current ADR008 mission.
- [ ] No unsupported canonical/robots behavior is added under the name of parity.

## Out of scope

- Marketing-site SEO, analytics, sitemap generation, and route-specific social cards.
