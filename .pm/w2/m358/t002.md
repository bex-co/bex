## Objective

Persist imported images so imports dedupe, list in order and survive bex-api restarts.

## Context

- Migrations live in `lego/backend/internal/store/migrations/` (latest `0240_sandbox_record_expiry`). Group storage: `lego/backend/internal/store/sandbox_groups.go`.
- Ids are minted only with `lego/backend/internal/id` (`id.New(kind)`), hyphenated (`sbb-…`).

## Steps

1. Add the next migration: `sandbox_builds (id, workspace_id, sandbox_group_id, name, source_image, digest, status, failure_reason, size_bytes, created_at, updated_at, started_at, finished_at)`. Add a unique index on `(sandbox_group_id, name, digest)` for non-failed rows, and an index for "newest succeeded by name".
2. Store functions: create-or-return-existing, get (scoped to group), list (cursor paging, newest first), newest succeeded by name, status transitions, count pending per group.
3. Register the new `sbb` id kind.

## Files

- `lego/backend/internal/store/migrations/<next>_sandbox_builds.{up,down}.sql`, `lego/backend/internal/store/sandbox_builds.go` (new), `lego/backend/internal/id/`

## Acceptance criteria

- [ ] A real-Postgres test shows a second create for the same group, name and digest returns the first row.
- [ ] "Newest succeeded by name" skips running and failed rows.
- [ ] A build in another group is not returned by a group-scoped get.
