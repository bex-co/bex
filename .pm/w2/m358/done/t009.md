## Result (2026-11-12)

`/simplify` (reuse, quality and efficiency reviews). Applied:

- **Two real bugs:** a queued import (waiting for one of the two worker slots) got no heartbeat, so the sweeper failed it as interrupted after 5 minutes, and its 30-minute timeout started before the slot. The heartbeat now runs from the start, touches pending and running builds, and stops the import once the build has settled; the slot wait watches it; the timeout starts after the slot. The image-size sum had no guard against negative or overflowing manifest sizes (a hostile manifest could slip under the cap); it now uses `manifestBytes`.
- **Index:** `sandbox_builds_stored (workspace_id) INCLUDE (size_bytes) WHERE succeeded`, so the storage-cap read on every suspend stays index-only.
- **Reuse:** `RegistryConfig.namespacePath` and `.credentials` shared with the meter's registry code; `labelOK` shared by group and image names; `storageFull` shared by the suspend and import caps (the import refusal now counts in `bex_sandbox_refusals`); `storedGroup`; `lockSandboxBuilds`; `classify` handles a group deleted mid-import.
- **Cleanups:** the sweeper uses the database clock (`make_interval`), the `Now` field is gone, the worker pool initialises lazily, the defaults are unexported, the `/images/` segment is one constant.

Skipped: resolving the group once for create and admission (one indexed read, only when an image is named); keyset paging for the build list (the group list pages the same way); a shared SSRF transport in `lego/types/netutil` (cross-module, three callers).
