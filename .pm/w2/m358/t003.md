## Objective

Turn a create request into a stored image: resolve `sourceImage` to a digest, copy it into the group's repository in the platform registry, and settle the build `succeeded` or `failed` with a reason.

## Context

- Registry: the sandbox snapshot registry (`SandboxSnapshotRegistryURL`, `SandboxSnapshotRegistrySecret` in `lego/backend/cmd/api/config.go`), already used for suspended-sandbox rootfs images.
- Render: the credential is "used for this build only and never stored"; dedupe is by name and digest, so a moved tag imports again.

## Steps

1. Resolve the tag to a digest (anonymous, or with the request's credential) before writing the row, so dedupe works on the digest.
2. Copy the image (manifest + layers) into `<registry>/<workspace>/<group>/<name>@<digest>`. Use a library copy in a bounded background worker; never write the credential to the database, a Kubernetes object or a log line.
3. Refuse at settle time, with a failure reason naming the cause: an image with no `linux/amd64` manifest, an image over the size cap, an unreachable registry, an authentication failure.
4. Enforce the per-group pending limit at create (429 with Render's wording) and the per-group image cap from t001.
5. A bex-api restart marks builds left `running` as failed ("interrupted; import again").

## Files

- `lego/backend/internal/sandbox/images.go` (new), `lego/backend/cmd/api/main.go` (worker wiring), `lego/backend/cmd/api/config.go`

## Acceptance criteria

- [ ] Tests with a local registry: a public image succeeds; a private image succeeds with a credential and fails without one; an arm64-only image fails naming the platform; an oversized image fails naming the cap.
- [ ] A test asserts the credential appears in no stored row and no log output.
- [ ] The pending limit answers 429.

## Out of scope

- Garbage-collecting images when their group is deleted (w2/m359).
