## Objective

Serve Render's three builds operations on REST, with matching GraphQL and MCP verbs, so the pinned CLI's `images import|get` work.

## Context

- `lego/backend/internal/sandbox/notoffered.go` (the builds entries of `NotOfferedRoutes`), `groups.go` (`registerGroupREST`, `scopeGroup`, `loadGroup`), `groups_surfaces.go`, `graphql.go`, `mcp.go`.
- Wire shapes from t001's artifact.

## Steps

1. Mount `POST/GET /v1/sandbox-groups/{sandboxGroupId}/builds` and `GET …/builds/{buildId}` with the group's authorization (the same check as the group routes). Remove them from `NotOfferedRoutes`.
2. Add GraphQL `sandboxImages(groupId)`, `sandboxImage(id)` and `importSandboxImage` (credential as an input never echoed), and MCP `list_sandbox_images`, `get_sandbox_image`, `import_sandbox_image`.
3. Errors: malformed group id is 400 `invalid_sandbox_group_id`, another group's image is 404, the pending limit is 429.

## Files

- `lego/backend/internal/sandbox/{notoffered.go,groups.go,groups_surfaces.go,graphql.go,mcp.go,images.go}`

## Acceptance criteria

- [ ] The pinned CLI's client decodes create, list and get responses (contract test against the CLI's types, as `groups_contract_test.go` does for groups).
- [ ] REST, GraphQL and MCP return the same fields and the same refusals.
- [ ] No response or GraphQL field ever returns the credential.
