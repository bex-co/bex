## Objective

bex's three trigger values are `create` (a service's first deploy), `api` (matches Render's real `DeployTriggerApi`), `rollback` (matches Render's real `DeployTriggerRollback`). `create` has no Render equivalent — Render's real enum has `new_commit`/`manual`/`deployed_by_render`/etc. but nothing named "create" for a first deploy. Decide and document.

## Context

- `lego/backend/internal/store/store.go:93-96` — the three `Trigger*` constants and their doc comments.
- Render's real `DeployTrigger` values: `api`, `blueprint_sync`, `deploy_hook`, `deployed_by_render`, `manual`, `new_commit`, `other`, `rollback`, `service_resumed`, `service_updated`.
- A first deploy created via `CreateApp` is arguably closest to Render's `new_commit` (a repo-backed service's first build) or `manual`/`other` (an image-backed service's first deploy has no commit) — there's no single perfect match, which is fine: bex's `create` value can stay as a documented **bex extra**, same treatment `cancel_deploy`/`rollback_deploy` already get for having no Render MCP equivalent.

## Steps

1. Decide: keep `TriggerCreate = "create"` as-is but strengthen its doc comment to explicitly say "bex extra, no Render equivalent — Render doesn't distinguish a first deploy's trigger from any other" (the low-risk option), OR remap it to `"other"` (Render's genuine catch-all value) for closer wire compatibility with a Render-trained client that switches on known trigger strings.
2. Whichever is chosen, update the doc comment and any dashboard/MCP description text that lists trigger values.

## Out of scope
