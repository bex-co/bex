## Objective

Render's `Deploy` object has `updatedAt` alongside `createdAt`/`startedAt`/`finishedAt`; bex's doesn't. Add it, written every time a deploy row's status changes (including the new `build_in_progress`→`update_in_progress` transition from t001).

## Context

- `lego/backend/internal/store/store.go` — the `Deploy` row model.
- `lego/backend/internal/store/reconciler.go` and `deploys.Service.Cancel`/`Rollback` — every write path that mutates a deploy row's status needs to also bump `updated_at`.
- `lego/backend/internal/deploys/service.go` `DeployView` + `rest.go`'s `renderDeploy`/`toRenderDeploy` — the read-side projection.

## Steps

1. Migration: add `updated_at` column, default to `created_at` for existing rows (never null).
2. Every status-transition write path sets `updated_at = now()`.
3. Thread through `DeployView.UpdatedAt` → REST `renderDeploy.UpdatedAt` → GraphQL `deployGQLType`'s `updatedAt` field.

## Acceptance criteria

- [ ] A fresh deploy's `updatedAt` equals `createdAt`.
- [ ] Every status transition (including t001's new build-phase ones) bumps `updatedAt`.
- [ ] `updatedAt` is present in REST/GraphQL responses.

## Out of scope

- MCP's `renderDeploy` shares the same struct as REST (`toRenderDeploy`) — no separate work needed there, just confirm it picks up the field automatically.
