## Objective

Prove the whole path end to end on a real cluster: change a running Postgres instance's plan and a running Key Value instance's plan, confirm pod resources actually resize and no data is lost.

## Context

- `scripts/mock-cluster.sh` for the local cluster; `scripts/app-apply.sh` or the dashboard for driving the change.

## Steps

1. Deploy a Postgres instance and a Key Value instance to the mock cluster.
2. Write a small amount of data to each (a table row / a key).
3. Change each instance's plan via REST (or the dashboard).
4. Confirm `kubectl get` shows the CNPG `Cluster`/Valkey `StatefulSet` pod resource requests updated to the new plan's values.
5. Confirm the data written in step 2 is still present after the resize.

## Files

- none (live verification only)

## Acceptance criteria

- [ ] A real plan change on a Postgres instance resizes its pod and preserves data.
- [ ] A real plan change on a Key Value instance resizes its pod and preserves data.

## Out of scope

- Prod verification — the mock cluster is sufficient for this milestone's DoD.
