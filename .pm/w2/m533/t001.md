## Objective

Expose all 7 sandbox group credential operations on bex-api's GraphQL schema over `sandbox.Service`, wired into scoped API key permissions and OAuth scope classification.

## Context

- Existing sandbox GraphQL definitions live in `lego/backend/internal/sandbox/graphql.go`, `groups_surfaces.go`, and `snapshots_surfaces.go`.
- Scoped API key op classification lives in `lego/backend/internal/api/key_permission_ops.go` (`KeySandboxesHistory` for reads, `KeySandboxesCredentials` for writes); OAuth scope classification (`bex.read` / `bex.write`) must also cover every new query/mutation so `internal/api` classification guards stay green.

## Steps

1. Define GraphQL types (`SandboxGroupCredential`, `SandboxGroupCredentialVersion`, `SandboxGroupCredentialInjection`, `SandboxGroupCredentialInjectionInput`, create/update/restore inputs) mirroring the REST fields exactly without ever exposing a secret value field.
2. Add queries (`sandboxGroupCredentials`, `sandboxGroupCredential`, `sandboxGroupCredentialVersions`) and mutations (`createSandboxGroupCredential`, `updateSandboxGroupCredential`, `deleteSandboxGroupCredential`, `restoreSandboxGroupCredential`) calling `sandbox.Service` with optional `ownerId`.
3. Register all 7 GraphQL operations in `lego/backend/internal/api/key_permission_ops.go` and OAuth scope maps.

## Files

- `lego/backend/internal/sandbox/credentials_surfaces.go`
- `lego/backend/internal/sandbox/graphql.go`
- `lego/backend/internal/api/key_permission_ops.go`
- `lego/backend/internal/api/scope_matrix.go` (or equivalent scope classifier)

## Acceptance criteria

- [ ] All 7 GraphQL operations execute over `sandbox.Service`, respect optional `ownerId`, enforce split Admin/Developer RBAC and scoped API key permissions, and never expose secret values.
- [ ] All `lego/backend/internal/api` scope-classification and key-permission coverage tests pass.
