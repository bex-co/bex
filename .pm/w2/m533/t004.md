## Objective

Build a role-aware Sandbox Group Credentials management panel in `dashboard/src/features/sandbox-groups/` backed by the new GraphQL queries and mutations so workspace members can inspect and manage group credentials cleanly.

## Context

- Existing sandbox-groups dashboard feature lives in `dashboard/src/features/sandbox-groups/` (`api/sandbox-groups.graphql`, `components/`, `hooks/`, `locales/`).
- Follow `dashboard/AGENTS.md` conventions: Apollo hooks, shadcn components, accessible forms/dialogs, capability/role-aware controls (Admins: create, edit all fields including `domain` and replacement `value`, toggle `enabled`, inspect version history, restore prior version, delete; Developers: edit `injection`/`methods`/`paths`/`enabled` only; Viewers: read-only metadata). Secret values are write-only password inputs that clear after submit and are never displayed back.

## Steps

1. Add GraphQL operations to `dashboard/src/features/sandbox-groups/api/sandbox-groups.graphql` and regenerate/update hooks in `hooks/`.
2. Build credentials list, create/edit dialog (supporting `header`, `basic`, `cookie`, `query` injection forms, methods multi-select, paths list, optional `${SECRET}` template, write-only secret input), inline enabled toggle, delete confirmation dialog, and version history drawer/modal with Admin-only Restore action.
3. Wire the panel cleanly into the Sandbox Groups view/route so users can reach it directly from their workspace's sandbox groups.

## Files

- `dashboard/src/features/sandbox-groups/api/sandbox-groups.graphql`
- `dashboard/src/features/sandbox-groups/hooks/*`
- `dashboard/src/features/sandbox-groups/components/*`
- `dashboard/src/routes/*` (as needed to mount the group credentials panel)

## Acceptance criteria

- [ ] Admins can create, edit (`domain`, `value`, routing, injection, `enabled`), view version history, restore a retained version, and delete a credential; Developers see only their editable fields (`injection`, `methods`, `paths`, `enabled`) and cannot trigger Admin-only mutations; Viewers see read-only metadata.
- [ ] Secret inputs are masked/write-only and never retained in Apollo cache or displayed after save.

## Out of scope

- Preloading skeletons, locales, and Vitest coverage (`t005`).
