## Objective

A suspended web service keeps its Ingress and certificate but today points at its own endpoint-less Service, so Traefik answers with its built-in `503 no available server`. Route it to the activator alias instead, so a bex responder answers, and restore the App's own backend on resume.

## Context

- `parkKubernetes` (`lego/operator/internal/controller/app_controller.go:2153-2181`) scales a suspended compute service to 0 while keeping Ingress and certificate.
- `ingressBackend` (`app_controller.go:2328`) picks the maintenance alias only in maintenance mode, and the activator only when auto-hibernating or when the App is sleep-eligible. `autoSleepEligible` (`:1935-1938`) requires `!Spec.Suspended`, so a suspended App falls through to its own Service.
- Suspended static sites already route to the static-server 404 (`app_controller.go:3140-3150`, `w3/m46`). Sleeping free services already route to the activator (`w6/m94`).
- `grep -rn "no available server" lego/ deploy/ infra/` finds nothing; the text is Traefik's.

## Steps

1. Add a suspended branch to `ingressBackend` for web services: when `Spec.Suspended` and not in maintenance mode, return the activator alias backend. Final precedence: maintenance → suspended → sleep → own Service.
2. Make sure the activator can tell "suspended" from "sleeping" for the App (an annotation or label on the Ingress/App it already reads is enough); t002 consumes it.
3. On resume, `ingressBackend` must fall back to the own Service once `Spec.Suspended` clears, with no extra reconcile step.
4. Leave private services, background workers and cron jobs untouched (no public host). Static sites keep the `w3/m46` path.
