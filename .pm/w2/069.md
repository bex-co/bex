# 069 — Blueprint create with `existingResources: create_new`

Why: Render's Blueprint onboarding offers `create_new` beside the default `adopt` — "creates a separate set of resources, leaving existing resources unchanged … via a random suffix that is assigned to this Blueprint and appended to the name of all resources this Blueprint manages" (Render CLI v2.35 `CreateBlueprintRequest`); w2/m256 shipped `adopt` and refuses `create_new` by name (`BLUEPRINT_EXISTING_RESOURCES_UNSUPPORTED`).

- **bex:** `blueprints.existing_resources` / `resource_suffix` columns exist (migration 0185); `apps/blueprint_onboarding.go` refuses the mode.
- **Do:** mint a short random suffix at create for `create_new`, store it, and append it to every managed resource name when compiling the Blueprint (services, databases, Key Value, env groups) and to every reference between them (`fromService`, `fromDatabase`, `fromGroup`), on every later plan and sync of that Blueprint; `requiredManualEnvVars` name the suffixed services.
- **Acceptance:** creating a `create_new` Blueprint in a workspace that already has `api` from another Blueprint plans `api-<suffix>` as a create and leaves `api` untouched; approving creates it; a later push syncs the suffixed set; ADR049's onboarding section drops the divergence.
