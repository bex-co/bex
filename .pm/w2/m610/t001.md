## Objective

Verify every field a git-backed Build Source carrier carries at create and update time (`AutoDeploy`, `GitHubRepoID`, `Branch`, `RootDir`, `BuildFilter`, `Repo`) and document exact git-push webhook behavior in `docs/ADR097-build-sources.md`.

## Context

- `lego/backend/internal/apps/build_sources.go:231-248, 399-416` creates git carriers via `s.create(ctx, create)` (`service.go:3971` defaults `AutoDeploy` to `true` for repo-backed creates) and `UpdateBuildSource` stamps `recordGitHubRepoID` at line 660.
- `lego/backend/internal/apps/webhook.go:972-991` currently filters `core.ServiceApps(list.Items)` with comment `// A push does not reach build sources yet (w2/m254 t006 decides).`

## Steps

1. Verify whether `createBuildSourceCarrier` stamps `GitHubRepoID` on create (matching normal git service creates) and preserves `AutoDeploy: true` across create, update, and Blueprint sync.
2. Check how `followRepository`, `prepareCheckedPush`, `recordBranchDeletedCandidates`, and `recordCommitIgnored` behave when a candidate is a Build Source carrier (`core.IsBuildSource(a)`).
3. Update `docs/ADR097-build-sources.md` with a concise section specifying git-push auto-build, `buildFilter`, skip-phrase, `branch_deleted`, and `autoDeploy` fan-out semantics for Build Source carriers.
