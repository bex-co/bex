## Objective

Let one app-signed push delivery reach every workspace that proved a binding for the delivering installation, while preserving — in substance — the fail-closed property [ADR057](../../../docs/ADR057-security-review-round6.md) round-6 #9 and codex #7 established. This changes a security invariant, so it lands as its own reviewable commit with its own tests.

## Context

- `internal/apps/webhook.go:139` `scopeFor(ctx, key, installationID) (scope string, proceed bool)` is the only reverse-lookup call site in the repo. Callers: `:315` and `:390`, plus `replayScope` at `:334`/`:357`/`:413`.
- The invariant is **not** "the lookup is a function" — that is a Go signature. It is: an app-signed delivery reaches only proved workspaces, and an unresolvable one acts on **nothing** rather than falling back to the manual key's deliberately global scope. See [ADR078 §4a](../../../docs/ADR078-github-workspace-connections.md).
- `replayClaim` (`:466`) already includes the scope in its claim key, so N scopes take N independent claims for free.
- Direction matters: every other consumer resolves `workspace → connections` (the clone-token mint reads the App CR's `bex.co/tenant` label first, [ADR026 §6](../../../docs/ADR026-github-integration.md)), so this is the whole blast radius.

## Steps

1. `scopeFor` → `scopesFor(...) (scopes []string, proceed bool)`, backed by `GitConnectionsByInstallation`.
2. Update both push and delete call sites to iterate scopes: `repoCandidates`, `blueprintAutoSyncTargets`, `redeployMatching`, `recordBranchDeleted`, and one `claimReplay` per scope.
3. Preserve every existing fail-closed branch verbatim in meaning: unwired resolver, missing installation id, lookup error, unknown/unbound installation ⇒ empty set ⇒ act on nothing in multitenant operation. An empty slice must never be treated as the manual key's global scope — assert this explicitly rather than relying on `len(scopes) == 0` falling through.
4. Keep the manual `BEX_WEBHOOK_SECRET` key's global behaviour and its multitenant rejection at verify time unchanged.
5. Bound the loop by `BEX_MAX_WORKSPACES_PER_GIT_INSTALLATION` and log the fan-out width once per delivery.

## Acceptance criteria

- [x] One push to a repo tracked in two bound workspaces produces one deploy in each, with independent replay claims; a redelivery is refused in both.
- [x] Disconnecting one workspace leaves the other deploying and the disconnected one receiving nothing.
- [x] Empty scope set ⇒ nothing is matched or mutated, in multitenant operation, for: unbound installation, absent installation id, unwired resolver, lookup error. Each has a test.
- [x] The manual-key path's behaviour is byte-identical to before.
- [x] Fan-out never exceeds the configured cap.
