## Objective

Close the last two dead ends where the user actually experiences them: render the account picker, and stop the Settings card from sending people down a path GitHub will silently swallow.

## Context

- `dashboard/src/features/git/components/connect-github-card.tsx:31-56` maps the bounded callback codes; `claimRecovers()` decides which errors offer the claim CTA.
- Copy lives in `dashboard/src/features/git/locales/{en,zh}.ts`. `git.callbackErrorNoClaimable` currently reads "未找到你管理的、尚未连接的 GitHub 账户。请先在该账户上安装 bex GitHub App…" — actively misleading once N:N lands, since the App *is* installed.
- `git.callbackErrorAmbiguous` currently tells the user to uninstall the extras; after t004 the remedy is to pick one.
- Every git hook already threads `ownerId: currentWorkspaceId` ([ADR078 §6](../../../docs/ADR078-github-workspace-connections.md)) — keep it that way for the new ones.
- Repo rule: a preloading skeleton must structurally match its ready state at the same breakpoint (`dashboard/CLAUDE.md`).

## Steps

1. Render the account picker from the selection id on the `/settings` return, in both en and zh.
2. Rewrite `callbackErrorNoClaimable` and `callbackErrorAmbiguous` for the post-N:N meanings; drop "uninstall the extras" entirely.
3. Install-URL dead end: when the Settings card is about to send the user to an install URL for an account that already has the App, route to the claim flow instead. GitHub strips `state` there and never calls back, so the current behaviour is a silent stop.
4. Thread `ownerId: currentWorkspaceId` through the new hooks; defer rather than issue an unscoped query while the workspace id is still resolving.
5. Give the picker a skeleton matching its ready geometry; verify pending and ready side by side at desktop and narrow-mobile widths.
