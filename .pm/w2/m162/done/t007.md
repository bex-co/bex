## Objective

Check that this milestone's change is consistent across every surface it exposes, and that the comparison against render.com is made on the right axis: **observable behaviour**, not mechanism.

## Context

- bex-api is meant to be Render-compatible ([ADR006](../../../docs/ADR006-bex-api.md)); the ledger is [ADR018](../../../docs/ADR018-render-parity.md), already updated for this change.
- The git connection surface is a **bex extension** (Render lists repos only through its private dashboard API), so the parity target here is bex's own cross-surface consistency plus the one Render behaviour being matched: a GitHub account usable from more than one workspace.
- The ownership model stays divergent on purpose ([ADR078 §1](../../../docs/ADR078-github-workspace-connections.md)) — do not "fix" it toward per-user credentials.

## Steps

1. Diff fields, semantics and error shapes for claim, selection, connections list and disconnect across REST, GraphQL, MCP and the dashboard.
2. Confirm both quota refusals are identical on all three API surfaces.
3. Confirm the MCP absences (connect/claim/select) are deliberate and documented, not oversights.
4. Re-read ADR018's git rows and ADR078 §2/§3a/§4a against what shipped; correct the docs if the code diverged.
5. File any genuine drift as follow-up board work rather than silently diverging.
