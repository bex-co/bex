## Objective

Re-key `git_connections` from `PRIMARY KEY (installation_id)` to the composite `(workspace_id, installation_id)`, turn the reverse lookup plural, and add the mirror quota that bounds how many workspaces one installation may serve. The new key only **relaxes** the old one, so every existing row already satisfies it — no dedup, no backfill, no row rewrite.

## Context

- Current key was set by `lego/backend/internal/store/migrations/0091_git_connections_multi.up.sql` (`ADD PRIMARY KEY (installation_id)`); `0094_git_connections_tenant_fk.up.sql` added the workspace FK.
- `store.GitConnectionByInstallation` (`internal/store/github.go:156`) is a single-row query with exactly two non-test callers: `internal/github/service.go:360` (claim candidate filter, deleted in t002) and `:772` (`WorkspaceForInstallation`, made plural in t003).
- `BindGitConnection` already admits the existing per-workspace quota inside the insert transaction — a standalone count lets two concurrent callbacks at limit−1 both pass. The new cap must ride the same transaction.
- Decision: [ADR078 §2](../../../docs/ADR078-github-workspace-connections.md), including the rollback subsection.

## Steps

1. New migration pair. Up: drop the `installation_id` primary key, add `PRIMARY KEY (workspace_id, installation_id)`, keep the `workspace_id` index, add a **non-unique** `installation_id` index for the webhook's reverse lookup.
2. Down: mirror `0091_git_connections_multi.down.sql`'s guard — `RAISE EXCEPTION` while any `installation_id` maps to more than one `workspace_id`, naming the offenders so the operator can disconnect the extras first. Only then restore the single-column key.
3. Replace `GitConnectionByInstallation` with `GitConnectionsByInstallation` returning `[]GitConnection` (stable order); drop the singular.
4. Add `MaxWorkspacesPerInstallation` to the bind path, admitted in the same transaction as the insert and the existing per-workspace cap, surfaced as a typed error alongside `GitConnectionLimitError`.
5. Wire `BEX_MAX_WORKSPACES_PER_GIT_INSTALLATION` (default `10`, `0` disables) the way `BEX_MAX_GIT_CONNECTIONS_PER_WORKSPACE` is wired.

## Acceptance criteria

- [x] Up migration applies against a database holding the current production shape with no data change; re-binding an existing row is still idempotent.
- [x] Two rows with the same `installation_id` and different `workspace_id` insert successfully; two rows with the same pair are rejected by the key.
- [x] Down migration succeeds when every installation serves one workspace and raises a named exception once any serves two.
- [x] `GitConnectionsByInstallation` returns both rows; no singular caller remains.
- [x] The new cap refuses inside the insert transaction, not via a preceding count.
