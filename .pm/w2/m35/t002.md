## Objective

A k8s Job runs `pg_dump` (format per t001's capture) against the tenant Database using its existing credentials Secret and uploads the artifact to the backup object store under a per-export prefix.

## Context

- CNPG cluster credentials Secret + internal Service DNS (docs/ADR009-postgresql-management.md); the S3 credential pattern is `BEX_DB_BACKUP_*` (w2/m27).
- Run in the Database's namespace; resource-limit the Job; the dump must never transit through bex-api memory.
- Image choice: the CNPG postgres image already carries pg_dump at the right major version — prefer it over a new image dependency.

## Files

- `lego/operator/internal/` (export Job mechanism — decide operator-owned vs bex-api-created Job deliberately; the build-Job precedent is operator-owned via CR fields)

## Acceptance criteria

- [ ] An export of a seeded tenant DB lands a valid dump in the store; `pg_restore --list` reads it.

## Out of scope

- Status lifecycle (t003), download (t004).
