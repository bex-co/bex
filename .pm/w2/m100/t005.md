## Objective

Meaningful tests for what m100 shipped. A bex-native literal route must reach its handler through the strict validator, real Render intersections must stay validated, the reverse inventory must catch the next shadowed route, and the overrides list must be workspace-scoped in Render's envelope.

## Steps

1. **Composed-server tests through the strict validator** (the real mux plus `renderRequestValidator`, not the synthetic mux of `TestRenderRequestValidatorPassThroughBoundaries`):
   1. `GET /v1/webhooks/event-types` → `200` with `EventTypes`; the same with `?ownerId=`.
   2. `GET /v1/webhooks/whk-<20 chars>` for an unknown id → still validated, still the canonical `404 {"id":"not_found"}`.
   3. `GET /v1/webhooks/not-an-id` → still the validator's `400 invalid path parameter "webhookId"`.
   4. `GET /v1/notification-settings/overrides`: a service with `notificationsToSend: failure` appears with `failure`; a `default` service appears or is omitted per the t002 decision; `?serviceId=` narrows; `?limit=1` plus the returned `cursor` walks all rows without repeats; a service in a second workspace never appears, with or without `?ownerId=` naming it.
2. **Reverse inventory guard.** Assert it enumerates every registered route (its count matches the forward test's route list) and, with a synthetic extra route such as `GET /v1/services/literal-name` injected, fails naming that route.
3. **Regression controls.** `TestRenderRouteIntersectionInventory` unchanged; the per-service override `GET`/`PATCH` tests unchanged; `crossworkspace_rest_test.go` still passes with the event-types route now reachable.

## Acceptance criteria

- [ ] Each new test is shown failing on the pre-fix code (event-types `400`, overrides `404`, reverse inventory naming the shadowed route).
