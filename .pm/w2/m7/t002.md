## Objective

Build `lego/backend/internal/keyvalue/` mirroring `internal/postgres/` (`service.go` + `tiers.go`): a core service that lists/gets/creates/deletes `KeyValue` CRs (`lego/types/v1alpha1`) in the watched namespace and derives connection info from the credentials Secret — internal `redis://` URI always, external `rediss://` only when `spec.public` and `status.externalHost` are set, plus the `cliCommand`. Register the KV id kind (`red-` prefix, matching Render) in `lego/backend/internal/id`.

## Context

- Mechanism contract (w1/m14, live in prod): CR spec `plan`/`version`/`storageGB`/`public`; status `phase`/`host`/`port`/`secretName`/`externalHost`; Secret keys `host`/`port`/`username`/`password`/`uri`. Plans come from `lego/types/tiers` (`Valkey` catalog: `free`/`starter`/`standard`).
- Follow `internal/postgres/service.go` for the Core-method + k8s-client shape and `tiers.go` for the plan mapping; docs/bex-api.md one-core/thin-adapters rule.
- `id.New(kind)` only — never hand-concatenate (docs/identifiers.md); adding the Kind updates the package registry, and its guard test enforces it.
- Render object shape per the t001 capture (id/name/plan/status enum/…); fields the CR lacks (`maxmemoryPolicy`, `persistenceMode`, `ipAllowList`) are omitted or fixed-default for now — record the divergence for t007.

## Steps

1. Add the `KeyValue` Kind (`red-`) to `internal/id` + guard-test entry.
2. `internal/keyvalue/service.go`: List/Get/Create/Delete + ConnectionInfo (Secret read; never surface the password anywhere else).
3. `internal/keyvalue/tiers.go`: plan id ↔ tiers.Valkey mapping, Render-shaped plan validation errors.
4. Unit tests against a fake client (deferred bulk to t009; smoke-level here).
