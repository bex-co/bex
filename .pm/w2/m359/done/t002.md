## Objective

`POST /v1/sandbox-groups/{id}/set-default` makes the group the workspace's default and returns it.

## Context

- `lego/backend/internal/store/sandbox_groups.go` (`is_default`, the lazy default creation; a pg test already proves two defaults are refused by the schema).
- `lego/backend/internal/sandbox/groups.go` (`registerGroupREST`, `scopeGroup`, `loadGroup`), `groups_surfaces.go` (MCP tools), `graphql.go`.

## Steps

1. Store: in one transaction, clear the current default and set the new one (the unique-default constraint must hold at every instant).
2. Serve REST; add GraphQL `setDefaultSandboxGroup` and MCP `set_default_sandbox_group`; remove the route from `NotOfferedRoutes`.
3. Setting the group that is already default is a no-op that returns it.

## Files

- `lego/backend/internal/store/sandbox_groups.go`, `lego/backend/internal/sandbox/{groups.go,groups_surfaces.go,graphql.go,notoffered.go}`

## Acceptance criteria

- [ ] A real-Postgres test with two concurrent set-default calls ends with exactly one default.
- [ ] A create without a group lands in the new default.
- [ ] Another workspace's group answers 404 on every surface.

## Out of scope

- Renaming the default group.

## Result (2026-11-12)

`store.SetDefaultSandboxGroup` swaps the default in one transaction under the workspace's group lock (`lockedSandboxGroup`); REST `POST /v1/sandbox-groups/{id}/set-default`, GraphQL `setDefaultSandboxGroup`, MCP `set_default_sandbox_group`. Setting the current default returns it. A group being deleted is not found. `TestSandboxGroupDefaultSwapAndDeletePG` races 8 swaps and finds exactly one default; `TestSetDefaultGroupMovesTheDefault` shows a create without a group lands in the new default.
