# Stateful MCP sessions lose affinity across bex-api replicas

Production verification on 2026-07-17 initialized a streamable-HTTP MCP session successfully, then intermittently received `404 session not found` when follow-up `notifications/initialized`, `select_workspace`, and list-tool requests reached another bex-api replica. Retrying reached the owning replica and completed the calls, proving the tools themselves work but the public multi-replica transport is not reliably session-affine.

Make stateful MCP sessions survive normal production load balancing, either through an appropriate shared session mechanism or explicit routing affinity, and add a multi-replica regression check. This is independent of `w5/m41`'s Project dashboard parity result.
