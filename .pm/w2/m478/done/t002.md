## Done (2026-11-18)

Recorded in [ADR116 D10](../../../../docs/ADR116-managed-oidc.md#d10--anthropic-and-openai-w2m478), from render.com/docs/oidc and the SDK sources (read 2026-11-18):

- **Triggers.** Render says it "detects" `ANTHROPIC_FEDERATION_RULE_ID` and `OPENAI_IDENTITY_PROVIDER_ID`. Those are the triggers, as t001 had them, so no change was needed. The companions are read by the SDK, not the platform.
- **Anthropic SDKs.** The zero-argument client federates when `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID` and `ANTHROPIC_IDENTITY_TOKEN_FILE` are set, sends the service account and workspace ids when they are, and rereads the file at every exchange. First releases: Python `anthropic` 0.98.0, TypeScript 0.93.0, Go v1.39.0 (2026-05-04). Workspace targeting arrived in 0.99.0, 0.94.0 and v1.40.0. An API key, auth token or profile outranks federation.
- **OpenAI SDKs.** They read no variable. The code passes `workload_identity` with a `get_token` the SDK calls at each exchange. First releases: Python 2.31.0 and Node 6.34.0. Render's examples omit the client id, which needs 2.37.0 or 6.38.0.
- **Render's Python example** binds `get_token` to the string read when the client is built (`Path(…).read_text().strip`), so it fails after the token's hour. `examples/oidc-ai` reads the file at each call.
