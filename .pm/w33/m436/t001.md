## Objective

A Blueprint Key Value entry without `plan` creates a `starter` instance (Render's `256mb`). A sync of an existing instance whose entry omits `plan` keeps the plan it has.

## Context

- Render: "Render uses `256mb` for a new Key Value instance." (blueprint-spec § `plan`, read 2026-11-16). `256mb` is bex's `starter` (`tiers.Valkey`, ADR049 § Schema re-pin 2026-10-02).
- The Key Value parse canonicalizes the plan and leaves an empty one empty (`lego/backend/internal/apps/deploy.go:3560`); the CRD then defaults it to `free` (`lego/types/v1alpha1/keyvalue_types.go:53`).
- The database parse is the model: a create default in the parse, with the presence-aware sync leaving an existing plan unchanged when `plan` is omitted (`deploy.go:3489`).
- Both `type: keyvalue` and the legacy `type: redis` reach this parse.

## Steps

1. Default an omitted Key Value plan to `starter` in the parse, as a create default.
2. Confirm the presence bit still says "omitted", so a sync of an existing instance plans no plan change (`lego/backend/internal/apps/blueprint_plan.go`), including for an instance on `free`.
3. Confirm an explicit `plan: free` is untouched.
4. Confirm a `create_new` (suffixed) copy takes the same default.

- [ ] A plan-less `keyvalue` and a plan-less `redis` entry both create on `starter`.
