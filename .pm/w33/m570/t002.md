## Objective

`nativePushNarration` drops its own `==> Uploading build...` when the stamp exists, and computes `==> Uploaded in Ns` from the stamp instead of from its own start. A buildkit phase that fails after the command step (an export, cache or disk failure) leaves the log reading `==> Uploading build failed`, never a bare silence.

## Context

- `nativePushNarration` (`lego/operator/internal/build/build.go:310-314`) prints `Uploading`, runs `bex_skopeo`, then prints `Uploaded in` and `Build successful`.
- The push container mounts `output` read-only (`build.go:1524`), which is enough to read the stamp.
- A failure in the buildkit phase after the command step is classified by `failureDetail` (`build.go:912`) and the termination message. The display filter prints `==> Preparing the build failed: …` for an error outside the command step (`build.go:254`).

## Steps

1. In `nativePushNarration`, read the stamp. If it is present, skip the `Uploading` line and use it as `bex_started`. If it is absent (an older buildkit phase, or a Dockerfile build), keep today's behavior.
2. Make an error after the command step in the buildkit phase print `==> Uploading build failed` once the `Uploading` line has been printed.
