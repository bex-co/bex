## Objective

`nativeLogDisplay` prints `==> Uploading build...` once, at the moment BuildKit finishes the build command's step and starts exporting the image. The buildkit phase also writes that moment, in epoch seconds, to a file on the `output` volume for the push phase.

## Context

- `nativeLogDisplay` (`lego/operator/internal/build/build.go:202-275`) is an awk filter over BuildKit's plain transcript. It already knows the build command's step number (`step`) and prints Render's narration.
- After the command, BuildKit runs the image's remaining steps, exports the OCI archive (`--output type=oci,dest=/output/image.tar`, `:1335`) and the layer cache (`--export-cache`, `:1353-1356`). Then `xdgBuildctl` (`xdgcache.go:307-345`) runs the XDG export solve, whose output never reaches the log.
- The trigger can be the step's `#N DONE` line, or the first `exporting to` line. Pick the one that also holds for a `CACHED` command step and for a build without the cache.

## Steps

1. Print `==> Uploading build...` once at the chosen trigger, only after a command step that succeeded.
2. Write `date +%s` to `/output/bex-upload-started` (or a name of your choice) at the same moment, from the shell side rather than inside awk if that is simpler.
3. Keep the Dockerfile path (`dockerfilePush`) unchanged.
