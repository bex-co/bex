## Objective

Propagate the operator's structured build OOM fact through the control-plane reconciler into `build_ended` events so REST, GraphQL and MCP populate `reason.failure.oomKilled.memoryLimit` per Render's OpenAPI schema.

## Context

- Render's pinned OpenAPI (`lego/backend/internal/api/openapi/render-public-api-1.json`, `"Build Ended"`) defines `details.reason.failure.oomKilled.memoryLimit` using the same `failureReason` object `deploy_ended` uses (`w4/630`).
- Today `buildEndReason` (`lego/backend/internal/events/service.go:789-799`) only populates `NewBuild` (for canceled/superseded builds) and returns `&EndReason{}` for every failed build.
- `lego/backend/internal/store/reconciler.go:1444-1464` emits `EventFactBuildEnded` without carrying structured build-failure fields.

## Steps

1. Persist the operator's structured build failure (`OOMKilled` + `MemoryLimit`, or reuse `DeployEnd` / fact columns — check existing migration `0176_deploy_end_reason.up.sql` and `event_facts.go` to see whether `service_event_facts` or `deploys` already holds `oom_killed` / end-reason columns). Add a migration only if needed (numbered strictly above `origin/main`'s highest migration).
2. Update `reconciler.go` so a `build_failed` transition carries `App.Status`'s build-OOM fact onto the deploy / `build_ended` event fact.
3. Update `buildEndReason` (and `withMemoryLimit` if needed) in `lego/backend/internal/events/service.go` so a failed `build_ended` event with OOM populates `Reason.Failure.OOMKilled = &OOMKilledInfo{MemoryLimit: "8GB"}` (or the recorded build limit) with `Evicted: false` across REST, GraphQL and MCP.
4. Check how `dashboard/` renders `build_ended` events in the Events feed (`dashboard/src/features/events/` or `services/`) so it displays the OOM reason cleanly without regression.
