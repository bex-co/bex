## Objective

Surface a clear, actionable out-of-memory failure message in the deploy failure reason and closing build log line instead of `"build failed for an infrastructure reason"`, and ensure `build_seconds` meters OOM builds as failed tenant builds.

## Context

- `lego/operator/internal/controller/build_failure.go:81-102` (`buildFailureMessage`) composes the tenant-facing sentence; today OOM hits `case build.FaultInfra` and prints `"build failed for an infrastructure reason and was retried — this was not caused by a change in your code; trigger a new deploy to retry…"`.
- `lego/backend/internal/usage/build_seconds.go:118-120` bills `0` seconds when `AnnotationBuildFault` or `BuildJobFault(failureReason)` is `BuildFaultInfra`. Because `StampMetering` writes `app.bex.co/build-fault=tenant` and `PodFailurePolicy` maps to `BuildFaultTenant`, verifying both paths ensures OOM builds count toward `build_seconds` per `docs/ADR030-pricing.md §13`.
- Check how `bex-api` closes the build log on failure (`appv1alpha1.IsBuildFailed` in `lego/types/v1alpha1/build_failure.go`) so the new OOM message stays recognized as a build failure everywhere.

## Steps

1. Update `buildFailureMessage` in `lego/operator/internal/controller/build_failure.go` (and `lego/types/v1alpha1/build_failure.go` if needed for `IsBuildFailed`) so a build with `obs.OOMKilled` produces a clear tenant message naming the 8 GB build memory limit and actionable advice (reduce build memory usage or lower heap limits such as `NODE_OPTIONS=--max-old-space-size`), without leaking Kubernetes internals.
2. Verify `recordBuildOutcome` / `recordBuildInfraFailure` in `lego/operator/internal/controller/app_controller.go` records `user_failed` (not `infra_failed`) and never fires `recordBuildInfraFailure` for build OOM.
3. Verify `lego/backend/internal/usage/build_seconds.go` bills a build Job whose `PodFailurePolicy` failed on OOM (`BuildFaultTenant`) and add a unit test pinning that behavior.

## Acceptance criteria

- [ ] A build killed by OOM displays a memory-limit failure message (never `"infrastructure reason"`), passes `appv1alpha1.IsBuildFailed`, records `user_failed` (never `infra_failed`), and bills `build_seconds`.
- [ ] Both container-level `OOMKilled` and a BuildKit `RUN` child killed with exit 137 produce the memory-limit message.
