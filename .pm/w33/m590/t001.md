## Objective

Make build Jobs fail immediately on `OOMKilled` (exit 137) without spending `backoffLimit` retries, classify OOM as `FaultTenant` instead of `FaultInfra`, and expose structured build-OOM state (`OOMKilled` + memory limit) so the controller and backend can report it without parsing prose.

## Context

- `docs/ADR060-build-worker-reliability-and-performance.md:105` already decided: *"OOM (exit 137) is deterministic at this size. No retry; the failure message states the build exceeded its memory tier."*
- `lego/operator/internal/build/build.go:2151-2187` (`buildPodFailurePolicy`) currently omits exit `137` from `FailJob`, so OOM falls through to `backoffLimit: 2` (3 attempts) and produces Job reason `BackoffLimitExceeded`.
- `lego/types/v1alpha1/jobnames.go:125-136` (`BuildJobFault`) maps `BackoffLimitExceeded → BuildFaultInfra` unconditionally.
- `lego/operator/internal/build/signals.go:492-493` (`retryReason`) already detects `term.Reason == "OOMKilled"` (`RetryOOM`).
- Note: `DisruptionTarget: Ignore` is the first rule in `buildPodFailurePolicy`, so node drain / preemption / eviction is absorbed before exit-code rules are evaluated. Keep `cache-save` OOM governed by its existing `failedOnCacheSave` rule (never blaming the tenant when `cache-save` fails).

## Steps

1. In `buildPodFailurePolicy` (`lego/operator/internal/build/build.go`), add a `FailJob` rule for exit code `137` on tenant-executing phases (`buildkit` and `clone`, or `OnExitCodes` after `DisruptionTarget: Ignore`, keeping `push`/`sign`/`cache-save` infra-owned so a platform push/cache OOM is never misattributed to the tenant).
2. In `EnsureBuild` / `failureDetail` (`lego/operator/internal/build/build.go`), inspect terminated container statuses for `OOMKilled` (and BuildKit child `exit code: 137` in tenant `RUN` steps) and populate structured OOM fields on `build.Observation` (e.g., `OOMKilled bool`, `MemoryLimit string` = `buildMemoryLimit`).
3. Ensure `EnsureBuild` sets `Fault = FaultTenant` when a tenant-executing phase (`buildkit`, `clone`) failed from OOM (even if a Job somehow hit `BackoffLimitExceeded`), while keeping platform phases (`push`, `sign`, `cache-save`) as `FaultInfra`.
4. Add structured build-failure status (e.g. `BuildFailure` / `OOMKilled` + `MemoryLimit`) on `App.Status` (`lego/types/v1alpha1/app_types.go`), run CRD codegen (`make manifests generate` from `lego/operator/`), and stamp it in `app_controller.go` alongside `stampBuildRun` when a build fails (and clear it when a newer build starts or succeeds).

- [ ] `EnsureBuild` reports `Fault: FaultTenant` and structured `OOMKilled: true` with the build memory limit for both container `OOMKilled` and a BuildKit `RUN` step killed with exit 137, and stamps it onto `App.Status`.
- [ ] `make test` and `make lint` pass in `lego/operator/`.
