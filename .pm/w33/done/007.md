# 007 — A static-site route whose `destination` is neither a path nor a URL is accepted, as Render's `redwoodjs` template needs

Why: Render's own `render-examples/redwoodjs` Deploy-to-Render template ships the rewrite `destination: replace_with_api_url/*` under the comment "replace destination api url after first deploy to Render", so Render accepts it, but bex refuses the whole Blueprint. On 2026-11-16 it was the only corpus refusal outside the guard's deliberate list (w33/001).

Facts, 2026-11-16:

- The refusal is `routes[0].destination must be a path starting with /`, the `!strings.HasPrefix(dest, "/")` branch of `validateRoutes` in `lego/backend/internal/apps/service.go`, after the http(s) case. The same function guards every routes surface: Blueprint validate, plan and apply (through the create validation), REST create service, `PUT /v1/services/{id}/routes` (`SetRoutes`) and add-route (`AddRoute`, `static_rules.go`), and so GraphQL and MCP too.
- Render documents no rule. render.com/docs/redirects-rewrites says only "Destination can be either a path or a full, publicly accessible URL". The pinned Blueprint schema (`lego/backend/internal/apps/schema/render.yaml.json`) and the OpenAPI `routePost.destination` (`lego/backend/internal/api/openapi/render-public-api-1.json`) are a plain `string`.
- What such a rule serves on Render is uncaptured, because no Render workspace is at hand. bex's static server already refuses to expand it (`expandDestCaptures` → `safeRedirectTarget`, `lego/operator/internal/staticserver/staticserver.go`), so if the rule were stored, a request it matches would get 400 `invalid rewrite target` (or `invalid redirect target`). In `redwoodjs` the next rule, `/* → /index.html`, would serve the SPA if the placeholder rule were skipped instead.

Do:

1. Accept a destination that is neither rooted nor http(s) on every surface. Render's template deploys with one, which makes this the parity-sufficient choice. Keep every other refusal: another scheme (`javascript:`), a network-path reference, a backslash or control byte (round-5 finding 11), the length budget, and an undeclared `:name` placeholder.
2. Decide what a matching request gets: the static server's current 400, a 404, or skipping the rule so a later one matches. Capture Render's answer if a Render workspace is available. Otherwise record the choice as uncaptured in ADR029 and ADR018's static-site row.
3. Add regression tests in `lego/backend/internal/apps`: validate and apply of the `redwoodjs` shape, plus REST set-routes and add-route. If the answer to a matching request changes, add tests in `lego/operator/internal/staticserver` too.
4. Remove the `destination must be a path starting with /` entry from `knownBlueprintGaps` in `lego/backend/internal/apps/blueprint_render_examples_corpus_test.go`, and the gap line in ADR049 § Render template spellings.

End state: the `redwoodjs` file validates `valid: true`, and `TestRenderExamplesCorpus` passes on a freshly fetched corpus with `knownBlueprintGaps` empty.

Source: w33/001, the corpus guard's triage of the `redwoodjs` class, 2026-11-16. ~1h.

**Done 2026-11-16 (w33 `/loopx`).**

1. `validateRoutes` (`lego/backend/internal/apps/service.go`) now accepts any destination that is an RFC 3986 relative reference, so it reaches every writer: Blueprint validate, plan and apply, REST create, set-routes and add-route, GraphQL and MCP. The dashboard's rule row (`static-rule-validation.ts`) accepts the same destinations. A colon in the first segment, before any query or fragment, reads as a scheme, so `javascript:`, `mailto:`, `ftp:`, `http:/x` and `:splat` are refused, with the new message "must be a path or an http(s) URL" (the dashboard key is `services.staticRuleDestinationPathOrUrl`, in all eight languages). Every other refusal is unchanged: a network-path reference, a backslash or control byte, a malformed escape, the 2,048-byte budget and an undeclared `:name`. An empty destination now says "is required".
2. The answer to a matching request is unchanged and recorded as uncaptured, because no Render workspace was at hand. The static server never serves an unrooted destination. A `GET` or `HEAD` such a rule matches gets 400 `invalid rewrite target` (`invalid redirect target`), with no fetch and no `Location`. A `POST` gets a rewrite's bare 200 or a redirect's 400, and the later rules still serve every other path. The 400 was chosen over a 404 and over skipping the rule: skipping would hand an API client the SPA's HTML with a 200, and the 400 names the rule its author must replace. This is recorded in ADR029 § API surface ("Unrooted destinations") and in ADR018's static-site row, and pinned by `TestUnrootedDestinationIsNeverServed` (`lego/operator/internal/staticserver`).
3. These tests are in `lego/backend/internal/apps/static_route_unrooted_destination_test.go`: accepted and refused forms, a validate plus `SyncBlueprint` of the redwoodjs shape, and REST set-routes plus add-route. The cross-adapter persistence test now carries the placeholder through REST, GraphQL, MCP, create and the Blueprint. A new validation-corpus family, `lego/backend/testdata/validation/route-destination.json` (32 cases), is asserted against bex-api and the dashboard row alike. Run against the pre-fix validator, the new Go tests and the corpus's dashboard case all fail. `TestBlueprintStaticRuleErrorsLocateTheRule` now uses `javascript:x` as its refused destination.
4. `knownBlueprintGaps` is empty, and ADR049 § Render template spellings records the fix. `TestRenderExamplesCorpus` on the 181 files freshly fetched on 2026-11-16 passes with 167 valid: `redwoodjs` is one of them.
