## Objective

The time t001 records reaches every surface that reports a build's end: `App.status.buildRun.finishedAt`, the `build_ended` service event, and the deploy row's move from `build_in_progress` to `update_in_progress`.

## Context

- `stampBuildRun(app, obs.StartedAt, obs.FinishedAt)` (`lego/operator/internal/controller/build_failure.go:131-139`) writes `BuildRunStatus`.
- The backend derives the deploy status from the App's phase (`lego/backend/internal/store/reconciler.go` around `:1945-1967`). `update_in_progress` needs `PhaseDeploying`, which the operator stamps when it dispatches the release.
- `build_ended` is `EventFactBuildEnded` (`lego/backend/internal/store/event_facts.go:64`). w8/blocked/287.md requires that `build_ended` carries the time the build ended, not the time it was observed.

## Steps

1. Check that the `build_ended` event timestamp is the App's `buildRun.finishedAt`, and not the time the backend loop saw the change. Fix that if it isn't.
2. Add a backend test: an App whose `buildRun.finishedAt` precedes the Job's completion projects `build_ended` at `finishedAt`, and the deploy row reads `update_in_progress` once the phase is `Deploying`.

## Files

- `lego/backend/internal/store/event_facts.go`, `lego/backend/internal/store/reconciler.go` (only if the timestamp source needs changing)
- `lego/backend/internal/store/*_test.go`
