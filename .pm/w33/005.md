# 005 — `scripts/mock-cluster.sh` says so when the host's inotify limit cannot hold the cluster, instead of cycling workers forever

Why: on a host with the kernel default `fs.inotify.max_user_instances=128` the CAPD worker and tenant nodes never join, the bring-up reports nothing, and the shared local cluster stays a control plane with no CNI for days; every workstream's local walk is blocked on a cause the script could name in one line.

Found by w33/m435 t007 on 2026-11-16 (Linux arm64, Docker 29.6.2, cgroup v2). The local `bex` cluster had been in this state for 3 days 16 hours: control plane `NotReady`, `coredns` Pending, both MachineDeployments replacing their one Machine every few minutes.

- Each new node container's containerd logs `failed to load plugin io.containerd.grpc.v1.cri: failed to create CRI service: failed to create cni conf monitor for default: failed to create fsnotify watcher: too many open files`, so `crictl ps` answers `unknown service runtime.v1.RuntimeService`, CAPD reports `CGroupsReady: failed to run crictl ps: context deadline exceeded`, the Machine never gets a provider id, and the MachineHealthCheck replaces it.
- The limit is per user, and Docker's node containers all run as the host's root: the mgmt node held 63 inotify instances, the workload control plane 36, each stuck worker 3, and the host's own daemons the rest of the 128. One more node cannot start its CRI plugin.
- Raising it needs root on the host (`sudo sysctl -w fs.inotify.max_user_instances=1024 fs.inotify.max_user_watches=1048576`, kind's documented known issue "Pod errors due to too many open files"); `sudo` asks for a password in an agent session.

Change: before creating or scaling node containers, `mock-cluster.sh` reads the two sysctls and, below what the topology needs, stops with the cause and the exact command instead of starting a bring-up that cannot finish; the same check runs when a Machine has not joined after its startup window, reading the node container's containerd journal for the fsnotify line. `infra/local/README.md` and the root `AGENTS.md` local-cluster section name the requirement.

End state: on a host at 128 the script exits non-zero within seconds naming `fs.inotify.max_user_instances` and the command to run; on a host at 1024 the bring-up is unchanged. `scripts/mock-cluster.test.sh` (or the script's existing test) covers both by faking the sysctl read. ~1h.

Source: w33/m435 t007, 2026-11-16.
