# 011 — `docs/bex-cli.md`: a non-interactive `bex logs` prints one page of at most 100 entries; show how to read a whole build log

Why: watching `eden-dash-v3`'s deploy on 2026-11-22, `bex logs -r srv-d9ndt8hmcglc739fkp50 --type build --limit 1000 -o text` printed the 2026-11-14 build log up to yarn's `Direct dependencies` and stopped, with no hint that over 1,000 more lines followed. A user diagnosing a build reads one page as the whole log.

- **Source:** `/pm-brainstorm for w33` (the fixes found watching deploy `dep-dc1mrpt3vdpc73b0i0l0` with the bex CLI, 2026-11-22), item 4; filed by `/pmx the fix to w33`. ~20m, docs only.
- **Why it happens (both halves are deliberate):**
  - The pinned CLI's `nonInteractiveLogs` makes one `ListLogs` call, prints `result.Logs` and ignores `hasMore` (`render-oss/cli@v1.1.3-0.20261106232710-4fd34231b637`, `cmd/logs.go:153-169`). Only the interactive viewer pages.
  - bex serves at most 100 entries a page, with `hasMore` and cursors, for any `limit` from 101 to 1000 (w3/m475's recorded recommendation; `lego/backend/internal/logs/service.go:134-148`). Whether Render's server fills a 1000 page is still unverified (ADR018 "Application logs").
- **Do:** in `docs/bex-cli.md`, near the logs and CI sections, say that a non-interactive `bex logs` prints one page of at most 100 entries, whatever `--limit` says. Show how to read a whole build log:
  - run `--direction forward --start <first>` and repeat with `--start` set to the last entry's `timestamp` from `-o json`, deduplicating by `id`;
  - or follow a running build with `--tail`;
  - or use the interactive viewer, which pages.
  Add one line to the `logs` row of `docs/cli-compatibility-checklist.md` pointing at it.
- **Not this note:** raising the page past 100 (it reopens w3/m475's recommendation and needs Render's behavior first), and patching the upstream CLI.
- **Done when:** both documents say it, `npx prettier@3.4.2 --write "**/*.md"` and `bash scripts/docs-links-validate.sh` pass, and the recipe, run against `srv-d9ndt8hmcglc739fkp50`'s 2026-11-14 build window, returns every entry from `==> Build queued` (08:58:43) to `==> Your service is live 🎉` (09:22:40), not 90 lines.
