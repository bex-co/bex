## Objective

A Blueprint that spells the hook `afterFirstDeployCommand` validates, plans and applies as if it said `initialDeployHook`, as Render documents.

## Context

- Render (blueprint-spec, read 2026-11-16): `afterFirstDeployCommand` is "a deprecated alias for this field."
- The pinned schema (`lego/backend/internal/apps/schema/render.yaml.json`) has no such property and the compiler is fail-closed, so the key is refused as unknown today. It appears nowhere in `lego/`.
- Precedents: `env` → `runtime` in the registry's `aliases` (`lego/backend/internal/apps/schema/capabilities.json`, `lego/backend/internal/apps/blueprint_aliases.go`), and the inputs Render accepts though its schema forbids them (ADR049 § Render template spellings, w5/m143).
- `initialDeployHook` is registered only on `serverService`; cron jobs and static sites refuse it.

## Steps

1. Before schema validation, rename `afterFirstDeployCommand` to `initialDeployHook` on web, private and worker services, with a deprecation notice in the plan located at the key.
2. Refuse a service that declares both spellings, at the field's path.
3. Keep cron jobs and static sites refusing either spelling.
4. Generate Blueprint keeps writing `initialDeployHook` only.
5. Add the alias to ADR049 § Render template spellings.

## Files

- `lego/backend/internal/apps/schema/capabilities.json`

## Acceptance criteria

- [ ] A file using `afterFirstDeployCommand` answers `valid: true` on REST, GraphQL and MCP validate, and its plan carries the hook.
- [ ] Both spellings on one service are refused with a located error.
- [ ] The registry guard tests (`blueprint_schema_test.go`, `blueprint_repin_test.go`) pass.

## Out of scope

- Other deprecated spellings Render may still accept.

## Outcome (2026-11-16)

- `afterFirstDeployCommand` is the capability registry's fourth alias (lego/backend/internal/apps/schema/capabilities.json), registered on `serverService` only, so a cron job or a static site still refuses either spelling. `reviewedBlueprintAliases` (blueprint_aliases.go) is the reviewed set the registry must match.
- Both spellings on one service are refused with `BLUEPRINT_ALIAS_CONFLICT` at the alias's path, whether or not the values agree. A valid file earns one plan `warning` notice at the key: "afterFirstDeployCommand is deprecated; use initialDeployHook".
- Tests: `TestBlueprintAfterFirstDeployCommandAlias`, `…ValidatesWithADeprecationWarning`, `…WithInitialDeployHookIsRefused`, `…StaysRefusedWhereTheHookIs`, `TestBlueprintAliasRegistryMatchesTheReviewedSet`. The registry guards pass.
- REST, GraphQL and MCP validate share `ValidateBlueprint`, so the three answer alike; that was checked through the service, not over the wire.
- Step 4's premise was off: Generate Blueprint has never written the hook under either spelling, so nothing changed there. Whether it should is part of w33/004.
