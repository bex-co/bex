## Objective

Prove the mechanism end to end on the local cluster before the parity, simplify and test tasks, so the production replay in the closeout is a confirmation and not a first run.

## Context

- `bash scripts/mock-cluster.sh` and `bash scripts/mock-cluster.sh operator` are pre-approved (AGENTS.md, local dev environments); `scripts/app-apply.sh <render.yaml>` applies a Blueprint through bex-api.
- The fixture needs a paid web service with a disk, a `preDeployCommand` and an `initialDeployHook`, each leaving a distinct harmless marker; the hook's marker is a file under the disk's mount path.

## Steps

1. Deploy the operator built from the tree and apply the fixture Blueprint.
2. Record the order of the first release: pre-deploy Job, rollout, live, hook Job; and the marker file as the service sees it.
3. Trigger a second deploy and a Blueprint re-sync; record that only the pre-deploy command ran.
4. Apply a second fixture whose hook exits non-zero; record that the deploy stays live, then fix the hook and deploy again.
5. Apply a fixture spelled `afterFirstDeployCommand`.
6. Write the results into the milestone README (conclusions only; raw output stays out of git) and delete the fixtures.

## Blocked (2026-11-16)

Not run. The local CAPD cluster cannot start its worker nodes on this host: `fs.inotify.max_user_instances` is 128, the mgmt node and the workload control plane already hold about 100 of root's instances, and each new node's containerd fails to load its CRI plugin ("failed to create fsnotify watcher: too many open files"). The evidence and what stands in for the walk are in the README under § Local-cluster walk.

Needed from the machine's owner: `sudo sysctl -w fs.inotify.max_user_instances=1024 fs.inotify.max_user_watches=1048576` (and the same two lines in `/etc/sysctl.d/` to survive a reboot), then `bash scripts/mock-cluster.sh reprovision`. Check: `kubectl --kubeconfig infra/local/bex.kubeconfig get nodes` lists the control plane, a worker and a tenant node, all `Ready`. w33 has no `dev-N` stack (`scripts/dev-env.sh` takes N 1–10), so the walk also needs a local bex-api for step 1's `scripts/app-apply.sh`, or it applies App CRs directly and leaves item 4 to the backend tests.

The production replay (t011) covers the same items. Without this walk it is the first run on a kubelet.
