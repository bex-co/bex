# 008 — A deploy-scoped build-log read shows other deploys' pre-deploy output

Why: the w33/m435 t011 production replay found that one deploy's log can carry another deploy's migration output. The cluster files pre-deploy pods under `type=build`, but a deploy-scoped `build` read leaves out only the other deploys' build pods.

Evidence (production, pin `58ef086ab21d`, 2026-11-17):

- An image-backed web service with a `preDeployCommand` that echoes a per-run marker had three deploys, at 05:27, 05:29 and 05:31Z. GraphQL `logs(resource: <srv>, deployId: <first deploy>, type: "build", startTime: "05:27:00Z")` returned the first deploy's lines and also the pre-deploy markers of deploys 2 and 3. The hook pods were left out correctly (w33/m435).
- `scopeToDeploy` (`lego/backend/internal/logs/service.go:730`) adds the other deploys' `appv1alpha1.BuildJobName` Jobs to `excludeJobs` for a `build` read, and their `PreDeployJobName` Jobs only when the read asks for `predeploy`. The shipper files every pre-deploy-plane pod (`app.bex.co/component=predeploy`) as `type=build` (ADR004 § Initial deploy hook, Tenant surfaces), so the durable `build` read carries every deploy's `predeploy-<app>-gen-N` pods. `TestDeployScopeExcludesOtherDeploysBuildPods` (`deploy_scope_test.go`) covers only the `bld-` Jobs.
- The dashboard deploy page (`dashboard/src/features/deploys/hooks/use-deploy-logs.ts`) sends `deployId` on its `build` leg inside the deploy's own window. The leak appears there only when two deploys' windows overlap, which is the case w21/m324 scoped for: a superseded deploy, or a deploy whose window is held open by a running hook while the next deploy's pre-deploy step starts.
- Render's deploy log shows only that deploy's lines.

Fix: for a deploy-scoped read, exclude both Job families of every other deploy, `bld-` and `predeploy-`, whatever types the read asks for. Their names do not collide (`lego/types/v1alpha1/jobnames.go`).

Done when: a deploy-scoped `build` read and a deploy-scoped `predeploy` read both drop the other deploys' pre-deploy pods and keep the deploy's own pod. A test in `deploy_scope_test.go` fails on today's code. The production repro above returns only the first deploy's own pre-deploy marker.
