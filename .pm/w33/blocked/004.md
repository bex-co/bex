# 004 — Capture what Render does with an `initialDeployHook` that fails, that is added late, and that outruns a timeout

Why: w33/m435 made the hook run once after the first successful deploy, as Render documents, but three of its rules are bex's choices because Render's spec is silent and no Render workspace was at hand; ADR018 may only keep a divergence the user signed off, so each needs a capture or a decision.

Render's Blueprint spec (render.com/docs/blueprint-spec#initialdeployhook, read 2026-11-16) says the hook runs "after a service's _first_ successful deploy" and "only once per service instance". It says nothing about failure, a timeout, or a hook added to a service that already deployed. bex today (docs/ADR004-app-deployment.md § Initial deploy hook):

1. **Failure.** A hook that exits non-zero leaves the deploy `live`, writes `==> Initial deploy hook failed: …` into the deploy's log, and runs again after the next deploy goes live.
2. **Added late.** A hook added by a Blueprint sync to a service that has already deployed runs once after its next deploy goes live. Render's sentence reads as "never".
3. **Bound.** The hook's Job has the pre-deploy command's 30-minute deadline and one attempt.

Capture, in a Render workspace, with a paid web service created from a Blueprint (a `render-examples` template with a hook and a disk, e.g. `dify-render-template`, is enough):

- a hook that exits 1: the deploy's status and events, the log lines Render prints, and whether the next deploy runs it again;
- a hook added in a later sync to the live service: whether it ever runs;
- a hook that sleeps past 30 minutes: when and how Render ends it;
- `afterFirstDeployCommand` declared beside `initialDeployHook`: which Render runs, or how it refuses (bex refuses both, `BLUEPRINT_ALIAS_CONFLICT`);
- Generate Blueprint for a service that has a hook: whether Render writes `initialDeployHook` into the generated file (bex writes neither spelling: `lego/backend/internal/apps/blueprint_generate.go` exports `preDeployCommand` only);
- the deploy page: whether Render shows the hook's outcome outside the log (bex's dashboard does not).

Write the capture to `docs/render-artifacts/initial-deploy-hook.md`. For each behavior that differs from bex's, either change bex (a milestone) or record the divergence in ADR018 with the user's sign-off; for each that matches, replace "bex's choice" in ADR004 and the ADR018 Blueprint row with the capture's citation.

End state: the artifact exists and no sentence in ADR004 § Initial deploy hook or ADR018 still calls rule 1, 2 or 3 an uncaptured choice. Needs Render workspace credentials (none are in `.env.example`), so it starts in `blocked/` if none exist. ~1h with a workspace.
