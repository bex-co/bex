## Objective

Make `CompleteBillingLifecycleWork` finish a lifecycle row for a workspace that has no `billing_provider_mappings` row, instead of failing with a bare `pgx.ErrNoRows` that rolls the transaction back and leaves the row `enforcing` forever.

## Context

- `CompleteBillingLifecycleWork` (`lego/backend/internal/store/billing_lifecycle.go:631-690`) runs `SELECT livemode FROM billing_provider_mappings WHERE workspace_id=$1` unconditionally after its UPDATE (`:669`). With no mapping the scan returns `pgx.ErrNoRows`, the transaction rolls back, and the worker's `Enforce` call has already succeeded, so nothing is recorded on the row: `last_error` stays empty and `attempt_count` grows by one per lease expiry (about 21,000 on the 11 stuck rows).
- A lifecycle row can exist without a mapping: `applyBillingExceptionTransition` (`:906`) and `EnsureBillingLifecycle` (`:279`) seed one for any workspace, and `DeleteUnboundBillingProviderMapping` (`:261`) removes the mapping of a reclaimed card-less workspace and leaves the lifecycle row.
- `SetBillingException` already tolerates the missing mapping (`:975`, `_ = tx.QueryRow(...).Scan(&livemode)`); the Complete path is the inconsistent one.
- The `livemode` read feeds only `insertBillingNotification` (`:313`), reached when `notifyBillingStatus(current.Status, status)` is true (enforcing to enforced is).
- This root cause is code-traced, not yet reproduced: the first step is the failing test.

## Steps

1. Write the failing test first, on a real Postgres in `lego/backend/internal/store/billing_pg_test.go` (or a new `billing_lifecycle_complete_pg_test.go` beside it): seed a workspace, its lifecycle row in `enforcing` with a claimed lease, and no mapping; call `CompleteBillingLifecycleWork(..., BillingEnforced, ...)`. It must fail today with `no rows in result set`.
2. Read `livemode` only when a notification will be inserted. Decide what a missing mapping means for the notice and record the decision in this task's Acceptance section: the notice names a Stripe customer's mode, and a workspace with no mapping has no customer, so the recommendation is to skip the notification row (the audit row still writes). Check `BillingNotifier.NotifyBilling` (`lego/backend/internal/billing/worker.go:55`) to confirm nothing downstream requires the row.
3. Keep every other `Complete` rule unchanged (version check, status guards, audit row).
4. Add the sibling case for `BillingRecovering` to `BillingHealthy` with no mapping, since `notifyBillingStatus(recovering, healthy)` is also true.
