## Objective

Add `mcputil.Toolset(...)` as a registration tag and mount a second streamable-HTTP endpoint `/mcp/cloud-agents` serving only the `cloud-agents` toolset (nine tools, ADR094 D2) plus `list_workspaces` and `list_repos`, sharing auth, rate limiter, workspace binding and error mapping. Advertise RFC 9728 metadata with that resource URL. Add the stdio flag.

## Context

- `lego/backend/internal/api/server.go` builds the one MCP server; `lego/backend/internal/api/mcp_workspace.go` binds `workspaceId`.
- Toolsets are a tag, not packages, so `/mcp` and `/mcp/cloud-agents` cannot drift.

## Steps

1. Add the tag option to `mcputil.AddTool`.
2. Tag the nine tools; build a filtered server for the new mount.
3. Serve protected-resource metadata for the new resource URL; add `--toolset` to `mcp-stdio`.

## Files

- lego/backend/internal/mcputil/mcputil.go
- lego/backend/internal/api/server.go
- lego/backend/internal/api/mcp_workspace.go
- `lego/backend` mcp-stdio command

## Acceptance criteria

- [ ] `tools/list` on `/mcp/cloud-agents` returns exactly the nine tools + `list_workspaces` + `list_repos`; `/mcp` is unchanged.
- [ ] A tool outside the toolset is not callable on the new mount.
- [ ] Metadata endpoint names the new resource URL.

## Out of scope

- Other toolsets (`deploys`, `data`).
