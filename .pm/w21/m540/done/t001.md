## Objective

`bex s3` builds an S3 client from the cached ephemeral key and talks to the endpoint with no other program involved.

## Context

- ADR112 D3 (The command: `bex s3`, a native client). The key mint, the 12-hour cache and its file lock, the endpoint resolution and the bucket and key routes already exist in `lego/cli/internal/s3` (`session.go`, `api.go`, `output.go`) and stay.
- Dependencies: `github.com/aws/aws-sdk-go-v2` with `service/s3` and the GA `feature/s3/manager` (Uploader and Downloader: multipart, concurrency, part size). Not `feature/s3/transfermanager`: it is a v0.x module without a compatibility guarantee; move to it only once it is GA (a later task, not this one). `lego/cli/go.mod` has no AWS SDK today (the backend does: `lego/backend/go.mod`).
- Build the `aws.Config` by hand (region, static credentials from the cached key, the endpoint as the base endpoint, `UsePathStyle`), never with `config.LoadDefaultConfig`: nothing may read a credential or configuration file or an `AWS_*` variable of the environment. The gateway takes `UNSIGNED-PAYLOAD`, an explicit SHA-256 and the `STREAMING-UNSIGNED-PAYLOAD-TRAILER` mode (ADR112 D3 payload modes), and its Go SDK v2 suite passed in w21/m498 t015; keep the SDK's default checksum unless a call fails, and record which.
- Map S3 error codes to bex's messages: an expired or revoked key (403 `InvalidAccessKeyId` or `ExpiredToken`) says the key is gone and that a very long transfer needs a persistent key (`bex s3 keys create`); `QuotaExceeded` prints the server's message (it names the cap); `SlowDown` and `ServiceUnavailable` are retried by the SDK; `NotImplemented` says bex does not serve that operation.

## Steps

1. Add the dependencies and record the binary-size change of `bex` (before and after, from `go build`) in this task's notes and in ADR112 § Not verified.
2. Replace the `deps` seam that launched another program with a client factory (`newClient(ctx, session) (*s3.Client, error)`), keep `session()` as it is.
3. Add the error mapping and the progress and output helpers every verb will use (`-o json` through `resolveFormat`, progress to stderr and only on a terminal).

## Result

Shipped 2026-11-20. `lego/cli` now depends on the AWS SDK for Go v2: `service/s3` v1.116.0 and `feature/s3/manager` v1.23.28 (`aws-sdk-go-v2` v1.48.0). `client.go` builds the `aws.Config` by hand (region, static credentials from the cached key, `BaseEndpoint`, path style, five attempts with the retry quota off); nothing reads `~/.aws` or an `AWS_*` variable. The `deps` seam that started another program is gone: `deps` carries `httpClient`, `stdin` and `isTerminal` instead, `session(ctx, region)` is unchanged in what it does for a signed-in person and also takes a persistent key from `BEX_S3_ACCESS_KEY_ID` and `BEX_S3_SECRET_ACCESS_KEY` (needed by CI and by t007's harness, which has no bex-api), and `run` (in `s3.go`) is each command's key, client, format and reporter.

- **Concurrency:** `--concurrency` is enforced by the HTTP transport (`limitedClient`): every request holds one of N slots from send to the end of its response body, so files in flight times parts per file can never pass the flag. Tested at the fake S3 (peak in flight) and on the transport itself.
- **Error mapping:** `explain` turns `InvalidAccessKeyId` and `ExpiredToken` (and a bodiless HEAD 403) into "the key expired or was revoked ... run again ... a transfer over twelve hours needs `bex s3 keys create`" and forgets the cached key; `QuotaExceeded` prints the server's message, `NotImplemented` says bex does not serve the operation, `SlowDown` is retried by the SDK and then says to lower `--concurrency`, `SignatureDoesNotMatch` and `RequestTimeTooSkewed` get their own words. Every message carries the request id.
- **Checksums:** the SDK's default request checksum (CRC32, trailer over HTTPS) is kept; against the fake it works for single and multipart uploads. The gateway's Go SDK suite (w21/m498 t015) is the earlier evidence; the real-gateway check is t007's harness and t009's walk, and this note is extended there if a call needs a change.
- **Binary size** (darwin/arm64, `go build` of `lego/cli`): 53,133,026 bytes before, 61,058,274 after (+7.9 MB, +14.9%); recorded in ADR112 § Not verified.
- **Finding:** `feature/s3/manager` is deprecated in its `go.mod` and on its functions in favor of `feature/s3/transfermanager` (still v0.5.x). Kept, as decided; confined to `multipart.go` with a named lint exception; ADR112 records it.
- Tests: `client_test.go` (poisoned `~/.aws` and `AWS_*` change nothing; every request path-style, signed with the cached key, sent to the endpoint only; expired key prints the hint and is forgotten; persistent key from the environment mints nothing; the in-flight bound; part-size rule; error mapping; SlowDown retried).
