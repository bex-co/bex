## Objective

A customer reads and writes a bucket's CORS rules and lifecycle rules, and inspects an object, with bex's own verbs.

## Context

- ADR112 D3 (Bucket configuration, and the command's own names). The server stores CORS (at most 100 rules and 64 KiB) and lifecycle (`Filter.Prefix`, `Status`, `Expiration` of `Days` 1 to 36,500 or a `Date`, `AbortIncompleteMultipartUpload`; at most 1,000 rules); transitions and the tag and size filters answer 501; a bucket with no rules answers `NoSuchCORSConfiguration` or `NoSuchLifecycleConfiguration`.
- `cors get|set|delete <bucket>` and `lifecycle get|set|delete <bucket>`: `set --file rules.json` reads a JSON document of the S3 API's rule shape (`CORSRules`, or lifecycle `Rules`) and calls `PutBucketCors` or `PutBucketLifecycleConfiguration`; `get` prints what the server stored (`-o json` as JSON, otherwise a table), and prints `no CORS rules` for the not-found code, with exit status 0; `delete` calls the delete operations.
- `info <bucket>` exists (bex's bucket route: region, public host, objects and bytes as of the last hourly count) and now accepts `s3://bucket` too; `info s3://bucket/key` calls `HeadObject` and prints size, ETag, modification time, content type and user metadata.

## Steps

1. Add the commands, the JSON decoding into the SDK's types with unknown fields rejected, and the printing.
2. Tests with the fake S3: a rule set round-trips, a 501 prints the server's message, a bad file names the line.

## Acceptance criteria

- [x] A CORS rule set and a lifecycle rule set written with `set` read back identical with `get`; `info s3://b/k` prints the object's metadata with lowercase names.

## Out of scope

## Result

Shipped 2026-11-20 with `config.go` and `tools.go`. `cors get|set|delete` and `lifecycle get|set|delete` read and write the S3 API's JSON documents (`CORSRules`, `Rules`) through bex's own structs with unknown fields refused: an error names the file and line (`rules.json: line 3: json: unknown field "AllowedOrigin"`), and a document is checked before a key is made. `get` prints a table, `-o json` a document `set` accepts, and `no CORS rules` / `no lifecycle rules` (exit 0) for the not-found codes. A server 501 prints the server's words. `info <bucket>` is unchanged and now accepts `s3://bucket`; `info s3://bucket/key` is a HeadObject printing size, ETag, time, content type and lowercase metadata. `env` prints the endpoint and key for another S3 client and no longer carries a config-file path.
- Tests: both rule sets round trip through `set`, `get -o json`, `set` of that output and standard input; the bad-file cases; a 501; `info` of an object as text and data.
