## Objective

`bex s3 sync ./site s3://photos/site` copies what is missing or changed and nothing else, in both directions and between prefixes.

## Context

- ADR112 D3 (the verbs). This is the one piece of real logic the SDK does not supply: it has no listing diff and no delete.
- Both sides are listed in key order and merged in one pass with memory bounded by a page (a tree of a million keys must not be held in memory). For each key: only on the source, or different in size, or older on the destination (by modification time), means copy; only on the destination means delete when `--delete` is given. `--size-only` compares sizes alone. `--include` and `--exclude` filter both sides the same way. `--dryrun` prints what would happen and makes no change.
- A downloaded file gets the object's `LastModified` as its modification time, so a second sync of the same tree copies nothing. Regular files only: a symlink, a device or a socket is skipped with one warning line each.
- Directions: local to prefix, prefix to local, prefix to prefix (through `CopyObject`, one workspace and region). Output: one line per action in the `cp` format, and with `--delete` a `delete:` line.

## Steps

1. Add the merge, the comparison and the three directions on top of t003's transfer.
2. A decision table test (missing, same, size differs, source newer, destination newer, destination only with and without `--delete`) and a property-style test that sync of a tree twice makes zero requests the second time.
