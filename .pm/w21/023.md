# API key names take no label rule: a 5000-character name and a name with a newline and BEL are accepted, and the revoke confirmation for a long name is a 3230px dialog whose Cancel and Revoke sit off-screen for a pointer

Why: an API key is a full-authority credential its owner must be able to revoke, and a long name makes the revoke confirmation unusable with a mouse; the missing rule is the one [w4/491](../w4/done/491.md) listed as "not probed".

**Severity:** minor (input hygiene plus a layout trap; no data lost, keyboard still works). **Estimate:** 40m (one shared-service check, a `maxLength`, tests; the scoped dialog cap is optional and about 15m). **Source:** live `/qa-find-bugs` pass 17, 2026-11-10, production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction. **Status:** inbox.

## Reproduction (own keys `qa-20261110-*`, each revoked in the same visit; the list returned to the 3 original keys, `w32`, `m43-verify-temp`, `tp-ms-fish`)

1. **Length is unbounded.** GraphQL `createApiKey(name:)` with `qa-20261110-` plus 288 `x` (300 characters) answers "API key created"; with `qa-20261110-` plus 4988 `y` (5000 characters) also answers "API key created", and the list row's name cell holds all 5000 characters. The dashboard's Create dialog has no `maxlength` attribute (`#Name` input, `getAttribute('maxlength')` is `null`).
2. **Control characters are kept.** `mutation($name:String!){ createApiKey(name:$name){ id name } }` with `qa-20261110-a\nb\u0007c` returns the name as `"qa-20261110-a\nb\u0007c"`; `revokeApiKey(id:)` on the returned id answers `true`.
3. **The revoke confirmation becomes unreachable.** With the 5000-character key present, Settings, API Keys, Revoke opens an `alertdialog` 512×3230 at `top: -1165` on a 1280×900 viewport (`overflow-y: visible`, `max-height: none`). Cancel and Revoke are at y 2004 to 2040. Playwright's click on Revoke times out with "element is outside of the viewport", so a pointer can neither confirm nor cancel (Escape still closes it). Keyboard works: focus starts on Cancel, Tab moves to Revoke, Enter revokes, but the focused button is at y 2004 with `scrollY` 0, so focus lands off-screen. At 300 characters the dialog fit (the click worked), so the threshold lies between 300 and 5000 characters and was not measured.
4. Revoke through the keyboard, then the list shows the 3 original keys again.

**Evidence:** the request and response shapes above and the measured geometry are the durable probes; no screenshot is needed.

## Root cause

- **Finding 1:** `lego/backend/internal/apikeys/service.go:252` checks only `strings.TrimSpace(name) == ""` (`:253` refuses blank). `core.TrimmedLabel` / `core.CheckLabel` (`lego/backend/internal/core/errors.go:381-405`: no control characters or line separators, at most 100 code points, named 400s `DISPLAY_NAME_CONTROL_CHARACTER` and `DISPLAY_NAME_TOO_LONG`) is applied by environment groups, projects, environments, workspaces and webhooks ([w4/419](../w4/done/419.md), w4/491), but not here. Sibling credential writers have their own bounds: SSH keys `maxKeyNameBytes = 120` (`lego/backend/internal/sshkeys/service.go:37`), registry credentials 253 (`lego/backend/internal/registrycreds/service.go:74`). The dashboard dialog gates only on `name.trim()` (`dashboard/src/features/api-keys/components/create-api-key-dialog.tsx:46`).
- **Entry points (aliases):** all three mint through `CreateAPIKey`: GraphQL `createApiKey` (`graphql.go:68`), REST `POST /v1/api-keys` (`rest.go:38`) and MCP `create_api_key` (`mcp.go:53`). One check covers the three transports.
- **Finding 2:** `dashboard/src/common/components/ui/alert-dialog.tsx:51` (`AlertDialogContent`) has no `max-h` or `overflow-y`, while the sibling `dashboard/src/common/components/ui/dialog.tsx:128` (`DialogContent`) has `max-h-[90vh] … overflow-y-auto`. The revoke dialog's title embeds the key name (`dashboard/src/features/api-keys/components/api-key-row.tsx:54-55`, `confirmTitle={t("apiKeys.revokeConfirmTitle", { name })}`).
- **Precedent:** [w4/219](../w4/done/219.md) (done 2026-10-09) found the same primitive gap for long Docker commands and deliberately fixed only its 6 `EditableFieldRow` sites through `ConfirmDialog`'s existing `contentClassName` prop, writing "do not modify the global alert-dialog primitive". `contentClassName` users today are `features/services/components/editable-field-row.tsx:376` and `routes/blueprints.$blueprintId.tsx:646`; the API key revoke dialog is not one.

## Fix (target behavior)

1. **Server (all transports):** `CreateAPIKey` applies `core.TrimmedLabel` to the name and answers the same named 400s as the sibling writers (`DISPLAY_NAME_CONTROL_CHARACTER`, `DISPLAY_NAME_TOO_LONG`), before any credential is minted, so a refused name creates no OAuth client. The dashboard Create dialog gets a matching `maxLength` (100) so the limit is visible before submit.
2. **Dialog, scoped:** the revoke confirmation opts into `contentClassName="max-h-[85dvh] overflow-y-auto [overflow-wrap:anywhere]"`, as w4/219 did, so a key that already has a long name (created before the rule) keeps Cancel and Revoke inside the viewport and reachable by scrolling. Changing the global `AlertDialogContent` is a separate decision that w4/219 declined (it would touch 48 files that import `ConfirmDialog`; only 2 opt in today) and this note does not reopen it.
3. No migration of existing names: this account's 3 keys have short names and none over 100 characters was seen.

## Blast radius (counted by grep on the working tree)

- `CreateAPIKey` has 3 non-test callers (GraphQL, REST, MCP). Existing tests only pin the blank-name refusal (`apikeys_test.go:607-609`, `:658`), so regression tests belong on the 100/101-code-point boundary and a control character, for each transport.
- The key name is shown in the list row, the Copy client ID and Revoke aria-labels, the confirm title and the toast (all observed with the long names); whether it also appears in the audit log was not checked.
- `ConfirmDialog` is imported in 48 production files; the primitive-level gap applies to each whose text embeds unbounded user text, which was traced only for API keys.

## Adjacent classes

- A refused name answers a named 400 for a caller who can manage keys; unauthenticated and forbidden answers are decided earlier (`Authorize(ctx, core.RelCanManageKeys)`, `service.go:239`), so the new check discloses nothing new.
- A name of exactly 100 code points still creates; a blank name keeps today's refusal.
- Not an authorization boundary: the key's authority ("full authority in this workspace, including connection strings", as the Create result says) is unchanged.
