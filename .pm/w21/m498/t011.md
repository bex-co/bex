## Objective

Record S3 operations in the audit log without flooding it, with the key as the actor.

## Context

- ADR112 D6 (verbs, targets, the download row). Verbs: `PutObject`, `GetObject`, `DeleteObject`, `DeleteObjects`, `CopyObject`, `ListObjects`, bucket verbs, `CreateMultipartUpload`, `CompleteMultipartUpload`, `AbortMultipartUpload`, `ListMultipartUploads`, `NotOffered` (the 501s); `UploadPart` and `ListParts` write none.
- A get writes a row at most once per access key, bucket and key in 15 minutes on a replica (an in-memory window; `aws s3 cp` reads in 8 MB ranges, ten at a time); a denied row at most once per key, verb and bucket per window; `CopyObject` records its source bucket and key as well as its destination; `DeleteObjects` one row with the bucket, the count and the first key.
- `core.auditedViews` stays the closed set (`secrets.ViewEnvVarValues`, `datastores.ViewConnectionInfo`, `objectstorage.GetObject`); the actor is the key id; the target is built from the path alone (escaped, 256 bytes) and never carries a query string, header, URL or credential.

## Steps

1. Add the verbs and the dedupe windows.
2. Extend `audit_verbs_test.go`, `audit_verbs_pg_test.go` and `audit_object_targets_test.go` to the S3 surface.

## Acceptance criteria

- [ ] Ten ranged gets of one object by one key write one row; a leaked `read` key's denied puts write one row per window.
- [ ] A copy's row names the source; no row carries a signed query.
