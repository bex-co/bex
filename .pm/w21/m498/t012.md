## Objective

Page a bucket correctly with and without a delimiter, statelessly and without leaving the bucket's prefix.

## Context

- ADR112 D3 (Listing). Wasabi `ListObjectsV2` under `<tea-id>/<obk-id>/` plus the client's prefix; the prefix is stripped from returned keys; `delimiter` (one ASCII byte in v1, else 501), `max-keys` ≤ 1000, `encoding-type=url`, `start-after`; `fetch-owner` ignored.
- V2 `continuation-token` is the base64url, without padding, of the last client key returned, fed to Wasabi as `StartAfter` after the server adds the prefix back; V1 `marker` and `NextMarker` are raw client keys. With a delimiter, a page that ends in a common prefix `p` continues from `p` with its last byte incremented (`/` becomes `0`); a `marker` ending in the delimiter is treated the same way. Contract A's list already uses `StartAfter` with a base64 cursor (`lego/backend/internal/objectstorage/objects.go`).
- Wasabi counts what a listing reads as egress (w21/095): add the estimated response bytes (`listResponseBytes`, `sweepbudget.go`) to the workspace's `object_storage_egress_bytes`; cap listings at 5 a second per workspace per replica (t010).

## Steps

1. Write the handlers, the token codec and the successor rule.
2. Test a page that ends on a prefix, a key equal to a prefix, a prefix with a multi-byte character before the delimiter, a forged token, and a prefix that tries to leave the bucket.

## Files

- lego/backend/internal/objectstorage/objects.go
- lego/backend/internal/api/ or the `bex-s3` package

## Acceptance criteria

- [ ] A listing of a tree pages without repeats or gaps with every delimiter case above.
- [ ] The egress meter grows by the estimated listing bytes.

## Out of scope

- Delimiters other than one ASCII byte.
