## Objective

Authenticate every S3 request with SigV4 and route it so that no unimplemented subresource or header can reach an object or bucket handler.

## Context

- ADR112 D3 (Verification) and the context table. Header form (`Authorization: AWS4-HMAC-SHA256`) and presigned query form (at most 7 days); service `s3`; the region is taken from the credential scope and compared with nothing; clock skew 15 minutes; constant-time comparison.
- Every `x-amz-*` header and `host` must be in `SignedHeaders`; the router matches subresource query parameters first (`?tagging`, `?acl`, `?retention`, `?versioning`, `?policy`, `?uploads`…): an unrecognised one and a `POST /<bucket>` form upload answer 501 before any handler; a header bex does not implement (`If-None-Match` and `If-Match` on a put, `x-amz-tagging`, `x-amz-copy-source-if-*`, a non-`STANDARD` storage class, `x-amz-server-side-encryption*`, a non-private ACL) answers 501.
- Errors are S3's XML with `x-amz-request-id`: `AccessDenied`, `InvalidAccessKeyId`, `SignatureDoesNotMatch`, `RequestTimeTooSkewed`, `NotImplemented`, `ServiceUnavailable`, `SlowDown`, `AuthorizationHeaderMalformed`, `AuthorizationQueryParametersError`. An OpenBao error is 503, never 403.
- Authorization is `core.Base` as the key's creator on exactly `workspace:<key.workspace_id>`, capped by the key's permission (D3); the audit actor is the key id.

## Steps

1. Write the canonical-request builder and verifier for both forms, with the signed-header rule.
2. Write the router, the subresource and unsupported-header refusals, and the XML error writer.
3. Resolve the key (caches of t002), authorize, and put the resolved workspace on the request context.
4. Write the known-answer tests from the worked examples in the S3 API reference (a header-signed GET and PUT and a presigned URL, with the documented example credentials and dates).
