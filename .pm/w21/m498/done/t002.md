## Objective

Create, list and revoke workspace-scoped S3 access keys whose secrets live in OpenBao, with the caches and caps of ADR112 D3.

## Context

- ADR112 D3 (Access keys, the secret store) and D9. Typed id `s3k-<xid>` through `lego/backend/internal/id` ([ADR020](../../../docs/ADR020-identifiers.md)); the migration must number above `origin/main`'s highest (`scripts/migration_order_guard.py`).
- Precedent: `lego/backend/internal/registrycreds/service.go` keeps a metadata row in Postgres and the secret in OpenBao through `core.SecretKV` (`lego/backend/internal/core/secretstore.go`), with fail-closed deletion.
- The OpenBao store prepends the context's tenant and falls back to `default` (`lego/backend/internal/secrets/store.go`, `WithTenant`): read and write the secret at `object-storage/keys/<id>` under `secrets.WithTenant(ctx, row.workspace_id)`.
- Row: `object_access_keys(id, workspace_id, created_by, name, permission, created_at, expires_at, last_used_at, revoked_at)`; `permission` is `read` or `readwrite`; persistent or ephemeral (at most 12 h). Caps: 100 live persistent per workspace, 20 live ephemeral per creator.
- Caches per replica: key rows 30 s (misses too, bounded), secrets 15 min. A 40-character secret is shown once at creation.

## Steps

1. Write the migration (`.up.sql` and `.down.sql`), the `s3k` id kind and the store methods.
2. Write the core service: create (OpenBao first, rolled back if the row fails), list, revoke (row first, secret after), a row whose secret is missing is revoked and listed as broken.
3. Implement the two caches with bounds and a test clock; a key id is checked against the `s3k-<xid>` shape before any lookup.
4. An OpenBao error is a typed `ErrSecretStoreUnavailable` the S3 layer maps to 503, never to an authentication failure.

## Acceptance criteria

- [x] Create, list and revoke work against real Postgres and a fake `SecretKV`; the secret is returned once.
- [x] A failed row insert leaves no OpenBao secret; a revoke leaves no usable key; a missing secret revokes the row.
- [x] The cap, expiry and cache behaviors each have a test that fails without them.

## Out of scope

- The REST, GraphQL and disposal wiring (next task) and the S3 verification (later tasks).

## Result

Done 2026-11-19. Migration `0301_object_access_keys` (a row per key; the secret is not a column), the `s3k` id kind (the id registry's prefix rule now reads a letter then letters or digits, ADR020 amended), `store.PGStore` methods with the cap enforced under a per-workspace advisory lock, and `objectstorage.AccessKeys`: Create (OpenBao first, rolled back when the row fails), List, Revoke (row first, secret after), Authenticate (key-id shape check before any lookup, row cache 30 s with misses cached, secret cache 15 min, an OpenBao error is `ErrSecretStoreUnavailable` and never an authentication failure, a missing secret revokes the key and lists it as broken), Dispose, PurgeWorkspace and SweepEnded. The service reads its clock through `Now`, so the cache and expiry tests cross windows without sleeping. Tests run on real Postgres against a fake `SecretKV`. Deviation: the sweep's call to `SweepEnded` is wired with the other sweep additions in t013.
