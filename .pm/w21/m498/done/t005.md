## Objective

Authenticate every S3 request with SigV4 and route it so that no unimplemented subresource or header can reach an object or bucket handler.

## Context

- ADR112 D3 (Verification) and the context table. Header form (`Authorization: AWS4-HMAC-SHA256`) and presigned query form (at most 7 days); service `s3`; the region is taken from the credential scope and compared with nothing; clock skew 15 minutes; constant-time comparison.
- Every `x-amz-*` header and `host` must be in `SignedHeaders`; the router matches subresource query parameters first (`?tagging`, `?acl`, `?retention`, `?versioning`, `?policy`, `?uploads`…): an unrecognised one and a `POST /<bucket>` form upload answer 501 before any handler; a header bex does not implement (`If-None-Match` and `If-Match` on a put, `x-amz-tagging`, `x-amz-copy-source-if-*`, a non-`STANDARD` storage class, `x-amz-server-side-encryption*`, a non-private ACL) answers 501.
- Errors are S3's XML with `x-amz-request-id`: `AccessDenied`, `InvalidAccessKeyId`, `SignatureDoesNotMatch`, `RequestTimeTooSkewed`, `NotImplemented`, `ServiceUnavailable`, `SlowDown`, `AuthorizationHeaderMalformed`, `AuthorizationQueryParametersError`. An OpenBao error is 503, never 403.
- Authorization is `core.Base` as the key's creator on exactly `workspace:<key.workspace_id>`, capped by the key's permission (D3); the audit actor is the key id.

## Steps

1. Write the canonical-request builder and verifier for both forms, with the signed-header rule.
2. Write the router, the subresource and unsupported-header refusals, and the XML error writer.
3. Resolve the key (caches of t002), authorize, and put the resolved workspace on the request context.
4. Write the known-answer tests from the worked examples in the S3 API reference (a header-signed GET and PUT and a presigned URL, with the documented example credentials and dates).

## Acceptance criteria

- [x] The reference examples verify; each refusal in the context has a test that fails without it.
- [x] `PUT /b/k?tagging` and `DELETE /b/k?tagging` never overwrite or delete an object; an unsigned `x-amz-copy-source` is refused.

## Result

Done 2026-11-19. `internal/s3gw`: SigV4 in the header and presigned forms (`sigv4.go`) with the 15-minute skew, a presigned URL's expiry bounded to a week, the scope's service and terminator checked, the region compared with nothing, constant-time comparison, SigV2 and mixed mechanisms refused with 501 and 400, host and every x-amz-* header required in SignedHeaders; and the router (`router.go`, `headers.go`) that matches a subresource before anything else, answers 501 for any subresource, query parameter or write header bex does not implement (If-Match and If-None-Match on a put, x-amz-tagging, copy-source conditions, storage classes other than STANDARD, server-side encryption, non-private ACLs, grants, object lock), a POST form upload and a version id, and takes the SDKs' x-id parameter. A request acts as the key's creator on exactly the key's workspace (`core.WithWorkspace` of the key's row), under the key's permission as a ceiling checked before OpenFGA is asked (so no key can reach can_manage), with the key id as the audit actor; an unreachable OpenFGA or OpenBao is a 503. The known-answer tests verify signatures botocore produced for eight requests, the first three being the S3 API reference's own worked examples (documented signatures f0e8bdb8..., 98ad7217... and aeeed9bb... match), against clock skew, expiry, tampering of every part, unsigned headers and malformed fields; gateway tests cover each failure's S3 code, the creator losing the role, the read key's ceiling, `PUT` and `DELETE` of `?tagging` never reaching a handler and every route's relation pinned to ADR112 D6. Seven mutations of the verifier, the ceiling and the router each fail a test.
