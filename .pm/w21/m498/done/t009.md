## Objective

Serve the object calls over the existing streaming and quota code, with the S3 semantics ADR112 D3 fixes.

## Context

- ADR112 D3 (Objects stream, Concurrency, CopyObject and UploadPartCopy). Put streams to a server-signed presigned PUT that signs `content-length` and the request's `x-amz-meta-*`; `Content-Type`, `Cache-Control`, `Content-Disposition`, `Content-Encoding`, `Content-Language`, `Expires` and `x-amz-meta-*` are stored as sent and returned by Get and Head (rclone keeps `x-amz-meta-mtime`).
- Get opens the object once, passes `Range`, `If-Match`, `If-None-Match`, `If-Modified-Since`, `If-Unmodified-Since`, serves `Content-Disposition: attachment` unless stored, `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`, and is exempt from compression. A `Range` past the end is 416 `InvalidRange` (Wasabi answered a presigned one with the whole object and a 200).
- Delete of a missing key succeeds; `DeleteObjects` takes up to 1,000 keys. `CopyObject` is server-side between two bex buckets of one workspace and region, up to 5 GiB, directive `COPY` or `REPLACE`; `GetObjectTagging` answers 200 with an empty `TagSet`; a non-empty `PutObjectTagging` answers 501.
- bex rebuilds every XML answer and forwards no Wasabi body (the physical `<tea-id>/<obk-id>/` key never leaves); `CopyObject` can answer 200 with an `<Error>` body, which bex turns into the error. Put, copy and multipart start/complete confirm the bucket row `FOR SHARE` (D1). 5 GiB per object (`EntityTooLarge`); 30-minute deadlines.

## Steps

1. Write the handlers on the existing stream helpers and deadline extension.
2. Write the Range and conditional handling, the metadata round trip and the rebuilt XML answers.
3. Write the copy path (HEAD for the size, the quota gate, the Wasabi copy) and the tagging stub.
4. Test against the fake S3 and, for `Range`, against the Wasabi behavior recorded in ADR112.

## Acceptance criteria

## Result

Done 2026-11-19. `handlers_object.go` and `objectstorage/objects_s3.go`: PutObject (streamed, metadata and entity headers kept), GetObject (Range, 416 even where Wasabi answers 200 past the end, the four conditionals), HeadObject, DeleteObject, DeleteObjects (up to 1,000 keys), CopyObject inside one workspace and region (HEAD for the size, the quota gate, the Wasabi copy; the source needs can_view_sensitive, the destination can_create) and the empty tagging answer. Tests: `handlers_object_test.go`. Stock aws-cli: cp both ways, get-object --range, head-object, s3 sync both ways, rm --recursive, byte-identical.
