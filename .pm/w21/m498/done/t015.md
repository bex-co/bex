## Objective

Pin the whole S3 surface with tests written against a real client library, and prove tenant isolation.

## Context

- ADR112 D11 (S3 layers 1 and 2; isolation tests). The AWS SDK for Go v2 is already a dependency through `lego/backend/internal/s3client`; style: `lego/cli/sandbox_contract_test.go`.
- Cases: put and get with `Range`, a multipart upload, a copy and `UploadPartCopy`, a listing with continuation, a batch delete, a round trip of each bucket configuration.
- Isolation: `..`, `%2e%2e`, doubled slashes, 1024 bytes, Unicode, another workspace's bucket and `obk-` id, a presigned URL signed for another key and one past its expiry, a multipart upload id of another workspace, a forged continuation token, a listing prefix that tries to leave the bucket, a bucket name reused after delete, a key whose creator was removed.
- Run the cases through Traefik as well as directly where the test environment allows (Traefik cleans paths and times out `100-continue`); fuzz the canonical-request and chunk parsers.

## Steps

1. Write the suite on a fake S3 (`httptest`) and the isolation tests on real Postgres.
2. Add the fuzz targets for the parsers.
3. Make the suite part of the backend CI job (no new workflow).

## Files

- lego/backend/internal/objectstorage/
- lego/backend/internal/api/ or the `bex-s3` package
- lego/backend/internal/s3client/

## Acceptance criteria

- [x] Every behavior in the milestone's definition of done is covered by a test that fails without it.
- [x] Every isolation case is refused and none reads or writes another workspace's data.

## Out of scope

- The pinned aws-cli, rclone and boto3 script (m499).

## Result

Done 2026-11-19. `s3gw/sdk_test.go`: the AWS SDK for Go v2 with its defaults untouched (default request checksums included) against the real handlers over a socket, on real Postgres and a fake Wasabi. Put and get with metadata, `Range` and 416, a wrong SHA-256 that stores nothing, each of the five checksum algorithms; a multipart upload, `ListParts` paging, `CopyObject`, `UploadPartCopy` of ranges and an abort; `ListObjectsV2` paginators with and without a delimiter, `ListObjects` by marker, `DeleteObjects`; every bucket call and the CORS and lifecycle round trips, the 501s; presigned GET and PUT, one signed for another key, one with its expiry changed, one past its expiry and one whose creator lost access. **It found a real incompatibility the CLI had hidden: `GetBucketLifecycleConfiguration` answered `<Date></Date>` and the SDK could not parse it** (fixed: the element is omitted). Isolation, with a mutation that kills it: another workspace's bucket name, its `obk-` id, this workspace's own `obk-` id and the workspace id as bucket names (NoSuchBucket for every call), another workspace's upload id on UploadPart, Complete and Abort (NoSuchUpload, its upload untouched), a forged and a malformed continuation token, a listing prefix with `..`, the key shapes D7 refuses and Unicode, `+`, `%` and 1,024-byte keys that round trip, a bucket name reused after delete (an orphan under the old prefix is invisible), and a key whose creator left (AccessDenied on every operation, and the same key works when the creator returns). `fuzz_test.go`: the canonical query, the Authorization fields and the aws-chunked framing (a round trip of arbitrary data) as native fuzz targets that run over their seeds in the backend job, 15 seconds each explored with nothing found beyond a loose property of my own. The suite is part of `go test ./...` of the backend job. **Not done: running the cases through Traefik** (path cleaning, `100-continue`): there is no Traefik in the test environment, so those two behaviors stay on the production walk of m500, where ADR112 § Not verified already lists them.
