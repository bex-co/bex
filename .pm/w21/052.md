# The Public Git URL field in the shared source picker shows a red "Enter an https:// URL, or a GitHub SSH URL…" for `github.com/bex-co/bex` or `http://…` but never marks the input: no `aria-invalid`, no `aria-describedby`, and the message has no id and no `role="alert"`, while the image field in the same component does all three

Why: a screen-reader user who pastes a repository URL the way it sits in the address bar, without `https://`, hears nothing: the field is not invalid, nothing describes it, the message is not announced, and Deploy Service or Deploy Blueprint just stays disabled.

**Severity:** minor (accessibility and consistency; the message is visible and correct). **Estimate:** 15m (one field, three callers). **Kind:** sibling of [w21/015](done/015.md), whose Fix records the convention "`aria-invalid` + `aria-describedby`, as the other row errors do". **Source:** live `/qa-find-bugs` pass 63, 2026-11-11 05:1x UTC (2026-11-10 local), production `https://dashboard.bex.co`, workspace `bex`, pin `a0d5802594e9`, filed to w21 per user direction; method: a read-only form probe on New Blueprint and New Service; nothing was created. **Status:** inbox.

## Reproduction (signed in; nothing created)

On New Blueprint (`/blueprints/new`, Public Git URL tab) and on New Service (`/services/new`, Public Git URL tab), type `github.com/bex-co/bex` and then `http://github.com/bex-co/bex` into the Repository URL textbox.

- **Both forms:** the textbox reads `aria-invalid` null and `aria-describedby` null. The only change is a `<p class="text-sm text-destructive">Enter an https:// URL, or a GitHub SSH URL (git@github.com:owner/repo.git).</p>` with `id=""` and `role` null. `getByRole('alert')` returns nothing.
- **New Blueprint:** the review region stays on "Select a repository and branch to review its Blueprint file before deploying." and Deploy Blueprint is disabled.
- **New Service:** Deploy Service is disabled.
- **Control in the same component:** the New Service Existing Image tab, typing `not an image!!`, reads `aria-invalid="true"`, `aria-describedby="svc-image-error"` and an alert "Use a Docker image reference, e.g. docker.io/library/nginx:latest — …".
- **Valid inputs for contrast:** `https://github.com/bex-co/bex`, the same with `.git` and with a trailing slash, and `git@github.com:bex-co/bex.git` are accepted. The Blueprint review then parses `examples/hello-node/render.yaml`: "Blueprint file parsed successfully — 1 resource will change. Create hello-node Service".

## Root cause

- `dashboard/src/features/services/components/service-source-picker.tsx:300-312`: the Git URL `<Input id={`${idPrefix}-git-url`}>` sets no `aria-invalid` or `aria-describedby`, and the message `<p className="text-sm text-destructive">` has no `id` or `role`. It shows when `gitUrl && !isValidGitUrl(gitUrl)`.
- `isValidGitUrl` (`dashboard/src/common/lib/utils/git-url.ts:9`) is the right rule: its comment says it matches bex-api's `store.RepoRule`.
- The image field a few lines below (`service-source-picker.tsx:326-345`) does it right: `aria-invalid`, `aria-describedby={`${idPrefix}-image-error`}`, and `<p id=… role="alert">`.

## Fix (target behavior)

The Git URL field follows the image field's pattern: `aria-invalid` is true while `gitUrl && !isValidGitUrl(gitUrl)`, `aria-describedby` points at the message's id, and the message carries that id and `role="alert"`. The en and zh text stay unchanged. One change in one component covers every caller.
