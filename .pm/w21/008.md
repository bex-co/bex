# 008 — Approval rules: edit them rule by rule in the dashboard

Why: ADR100 ships approval mode with a fixed, versioned risky-action table, and customers who find one rule too noisy or too lax can only switch the whole mode; Devin lets members set allow and ask rules, so per-rule editing closes that gap.

- **Source.** User request 2026-11-07 (`/pm-brainstorm w21`, then `/pm them all to w21`); the "per-rule editing in the dashboard" follow-up in [ADR100](../../docs/ADR100-agent-approval-mode.md) ("Follow-ups, not gates"). Devin reference: its CLI and Desktop permissions let a member allow once or for the session and set allow/ask/deny rules, and org rules override a member's own.
- **Sequence.** Take this only after w9/m176 (approval mode) is done and live; the rule table, `approvalMode` and the decision record do not exist before then.
- **What.** In the dashboard's agent settings (`dashboard/src/features/agent-environment/`), list the driver's risky-action rules and let a workspace admin turn each rule on or off for the workspace, stored with the existing `approvalMode` setting and served through the same REST, GraphQL and MCP environment endpoints.
- **Done when.** An admin disables one rule, a session then runs the matching command without a prompt, re-enabling it makes the next session ask again, and the change is in the audit log.
- **Not in this note.** Smart auto-approval by a fast model, org-level deny rules (`security_profile`) and any change to the safety boundary; each of those needs its own decision.
