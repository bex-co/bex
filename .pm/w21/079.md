# 079 — Run the tightened admission policies on the local cluster: the sample App deploys and wakes, a node drains, and no policy denial reaches the logs

Why: w21/m409 tightened `bex-operator-workloads`, `bex-operator-daytoday-workloads`, `bex-build-job-shape` and `bex-drain-guard-writes` and added `bex-activator-writes`. Each identity's real code passes its policy against a real API server in the tests, but nothing ran the flows through a whole cluster: the operator reconciling an App, the activator waking a hibernated one, drain-guard handing an App over during a node roll. Those are the paths a policy that is right in a unit and wrong in the running system would break first.

- **Source:** w21/m409 t005, 2026-11-14. The local CAPD cluster could not be brought up on the machine that ran m409: `kind` and `clusterctl` are not installed there and the helm artifact downloads that `scripts/mock-cluster.sh` and `scripts/gitops-validate.sh` depend on answered `504 Gateway Timeout`. Local environments are pre-approved by the root `AGENTS.md`; installing their tools was not part of that approval, so this waits for a machine that has them.
- **Size:** about 45m once the cluster is up, plus the bring-up.

## Steps

1. `bash scripts/mock-cluster.sh`, then `bash scripts/mock-cluster.sh operator` to build and deploy the operator from this tree; apply `deploy/gitops/base/activator-admission.yaml`, `drain-guard-admission.yaml` and `operator-workload-admission.yaml` to the app cluster (kustomize the base, or apply the three files).
2. Deploy `examples/whoami-app.yaml`, wait for it Ready, then let it hibernate (or suspend and resume it), send a request through the activator and watch it wake; the App's `app.bex.co/last-active` and `app.bex.co/wake-started` annotations and its Deployment's replicas change.
3. Scale the worker pool (`bash scripts/mock-cluster.sh scale 3`, then back) or cordon a node to run drain-guard's evacuation of the App's Deployment, if the cluster has the CAPI hook wired.
4. Read the operator, activator and drain-guard logs and `kubectl get events -A` for `ValidatingAdmissionPolicy` denials; record counts and statuses here.

## Files

- scripts/mock-cluster.sh, examples/whoami-app.yaml (run, not edited)
- deploy/gitops/base/activator-admission.yaml, drain-guard-admission.yaml, operator-workload-admission.yaml (read)

## Acceptance

- The sample App deploys and wakes, a drain evacuates it, and the logs show no policy denial; what could not be exercised on the cluster is named.
