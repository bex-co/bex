# The ⌘K palette's Navigation group is a hand-copied list that never gained Agents, Automations or Router: typing `agents` or `automations` (en) or `智能体` / `自动化` (zh) answers "No matching pages or resources" for two destinations that sit in the sidebar

Why: the palette is the primary resource navigator and its Navigation group is meant to name the pages the sidebar does; on production a user who types the name of a sidebar page they can see gets a definitive "no matches".

**Severity:** minor (a missing search shortcut, not data loss). **Estimate:** 30m (derive the palette's pages from the sidebar's nav list with the same gating, plus a drift-guard test). **Kind:** drift between two hand-written lists. **Source:** live `/qa-find-bugs` pass 28, 2026-11-10, production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction. **Status:** inbox.

## Reproduction (read-only: only ⌘K was opened and queries typed; nothing created)

Signed in to workspace `bex` (Agents enabled), en and zh.

1. The sidebar's links are Projects `/`, Blueprints `/blueprints`, Agents `/agents`, Automations `/automations`, Environment Groups `/env-groups`, Webhooks `/webhooks`, Notifications `/notifications`, Billing `/billing`, Settings `/workspace/settings` (zh shows 智能体 and 自动化 for the two).
2. ⌘K with an empty query: **Navigation** lists exactly 8 entries: Projects, Blueprints, Environment Groups, Webhooks, Notifications, Billing, Workspace Settings, Account Settings. No Agents, no Automations.
3. Type, wait 400 ms, read the dialog:

| query | result |
| --- | --- |
| `agents` | `role=status` "No matching pages or resources." |
| `automations`, `automation` | the same |
| `agent` | 1 result, the unrelated service `agentmarketcap-1` (matched by its name) |
| `智能体`, `自动化` (zh) | "没有匹配的页面或资源。" |
| `webhooks` (control) | 1: Webhooks |
| `settings` (control) | 2: Workspace Settings, Account Settings |
| `database` (control) | the 4 databases |

4. `GET /agents` and `GET /automations` from the page both answer 200, so the pages exist and are reachable; only the palette does not know them.

## Root cause (code-traced)

- `dashboard/src/common/components/dashboard-layout/global-search-dialog.tsx:145-186`: `const pages = [...]` is a hand-written list of 8 destinations. It is filtered at `:196` (`matchesQuery(page.label, query)`) and rendered as the Navigation group; that filter is its only consumer.
- `dashboard/src/common/components/dashboard-layout/dashboard-sidebar.tsx:64-96`: `NAV_GROUPS` is the sidebar's list. Besides the eight it carries Router `/router` (`common.navRouter`), Agents `/agents` (`common.navAgents`) and Automations `/automations` (`common.navAutomations`), and `:105-115` filters them: `/agents` and `/automations` only when `useAgentsFeatureEnabled()` (`config/use-growthbook.ts:8`, `isAgentsDashboardEnabled(currentWorkspaceId)`), `/router` only when `useRouterFeatureEnabled()`.
- History: the sidebar gained Agents on 2026-08-04 (`f3bc965fe`, w1/m64), Router on 2026-09-15 (`640b53d27`) and Automations on 2026-11-08 (`933631c39`, w21/m278). `git log -S"common.navAgents"` (and `navAutomations`, `navRouter`) on `global-search-dialog.tsx` returns nothing: the palette never referenced any of the three. `git show origin/main:` of the palette file has none of the keys either.
- Why it escaped: no test ties the two lists together. `__tests__/global-search.test.tsx` `expectUnfiltered` asserts only Webhooks and Environment Groups.

## Fix (target behavior)

The palette's Navigation entries are derived from the sidebar's nav list (export the destinations from one module that both consume), so a destination added to the sidebar is searchable without a second edit. The palette applies the **same feature gating** as the sidebar, so a workspace whose sidebar hides Agents, Automations or Router does not see them in ⌘K either (no new entitlement leak). The palette keeps its two deliberate extra entries, `common.topbarWorkspaceSettings` "Workspace Settings" and `common.userMenuSettings` "Account Settings" (the sidebar words the one page "Settings"), and the Billing label as the sidebar words it (`common.navUsage`).

Add a drift-guard test: every enabled sidebar destination has a Navigation option; `agents` finds the Agents option in en and `智能体` in zh; with the flag off neither appears.
