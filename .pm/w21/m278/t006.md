## Objective

Expose automations on all three API surfaces as one core with thin adapters, and filter sessions by automation.

## Context

- Spec: ADR101 D8 operation table; the pattern is ADR099 D3. Read tools sit in the `bex.cloud_agents` scope; write tools need the scope `create_agent_session` needs.
- MCP annotations are set per tool: list/get/list_runs read-only, delete destructive, run not idempotent.
- Lists use the cursor/limit envelope with `StablePage`.

## Steps

1. Add REST routes under `/v1/agent-automations` (list, get, create, update, delete, pause, resume, run, take-over, runs).
2. Add the GraphQL fields and the nine MCP tools named in ADR101 D8.
3. Add the `automationId` filter to the session list on REST, GraphQL and MCP and expose `automationId` on the session view.
4. Golden tests for the MCP tool list and error-code tests for each refusal.

- [ ] The same operation returns the same fields and error codes on REST, GraphQL and MCP.
- [ ] `run` is idempotent per call key and obeys authorization, overlap and spend rules.
- [ ] Sessions list filters by `automationId`.
