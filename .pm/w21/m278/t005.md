## Objective

Implement the loop that fires due automations safely across replicas, and wire it into bex-api next to the webhook worker.

## Context

- Spec: ADR101 D3, D4, D6, D7. Pattern: `internal/webhooks/worker.go` (`FOR UPDATE SKIP LOCKED`).
- Order per fire: claim, then in one transaction insert the run row and advance `next_fire_at`; then outside it re-authorize as the creator (`core.WithIdentity`), check overlap, call `agentsessions.Service.Create` with `idempotencyKey = aut:<id>:<fire_at unix>`; then settle the run.
- A recovery pass claims stale `claimed` runs with `SKIP LOCKED` and a one-minute lease.
- Only the latest missed tick fires after an outage; the run records `missedTicks`. Three consecutive `failed_create`/`denied` outcomes pause the automation.

## Steps

1. Write the loop (15 s tick), the fire path, overlap skip, auto-pause and the recovery pass under `lego/backend/internal/agentautomations/`.
2. Start it in `lego/backend/cmd/api/main.go` beside `webhooks.Worker`, behind the same enablement conventions.
3. Concurrency test on real Postgres: N loops claim the same due set for a thousand rounds; each fire yields one run row and one session.
4. Crash test: stop after the record step; recovery starts exactly one session, also when two recovery passes race.
5. Authorization test: the creator leaves the workspace; the next fire is `denied` and the automation pauses with `creator_lost_access`.

## Acceptance criteria

- [ ] N concurrent loops never produce a second session for the same fire.
- [ ] A crash between record and create still yields exactly one session after recovery.
- [ ] An outage that missed 60 ticks yields one session and `missedTicks = 59`.
- [ ] A still-active previous session produces `skipped_overlap` and no new session.

## Out of scope

- Webhook events for runs; queue/allow overlap policies.
