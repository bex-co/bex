## Objective

Add the Postgres tables and store layer for automations and their runs, plus the `aut` id kind.

## Context

- Spec: ADR101 D1–D3 and D7. Tables `agent_automations` and `agent_automation_runs` (primary key `(automation_id, fire_at)`, `claimed_until` lease), nullable `agent_sessions.automation_id`.
- A partial index on `next_fire_at WHERE enabled` serves the claim query.
- Ids mint only through `lego/backend/internal/id` (`id.New(kind)`, hyphen).

## Steps

1. Add `id.AutomationKind` (`aut`) to `internal/id/id.go`.
2. Write the next free migration pair in `internal/store/migrations/` (up and down).
3. Write `internal/store/agentautomations.go`: create, get, list (cursor/limit, `mine`), update, delete, claim-due, insert-run, settle-run, claim-stale-runs.
4. Real-Postgres tests for every store method, including the unique violation on a repeated `(automation_id, fire_at)`.

## Files

- lego/backend/internal/id/id.go
- lego/backend/internal/store/migrations/ (next free number)
- lego/backend/internal/store/agentautomations.go
- lego/backend/internal/store/agentautomations_pg_test.go

## Acceptance criteria

- [x] The migration applies and reverses cleanly.
- [x] A second insert of the same `(automation_id, fire_at)` is rejected by the database.
- [x] The claim query skips a row another transaction holds and sees `next_fire_at` already advanced after that transaction commits.

## Out of scope

- The scheduler loop and any HTTP surface.
