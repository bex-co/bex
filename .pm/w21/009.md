# Check the Deploy-to-bex link survives sign-up and the payment gate for a new account

Why: the whole point of the button is a first-time visitor, and the only path verified so far is a logged-in or already-registered user (w8/163 live check, and the 307 above); a new account must also pass sign-up and, on hosted bex, the payment-readiness gate before it can create anything.

- Reproduce as a brand-new visitor: open `https://dashboard.bex.co/deploy?repo=https://github.com/bex-co/beancount-io/tree/bex-deploy&path=bex.yaml` logged out, sign up (and sign in with GitHub), bind a card if asked, and note where the browser lands. Pass means the Blueprint wizard opens with repo, branch and path still filled; fail means the query is dropped at sign-up, at email verification, or after the card step.
- Check `next` handling on `/auth/sign-up` and the OAuth return, not only `/auth/login`; `blueprints.new.tsx` keeps the query through `requireAuth()` login (QA sweep 1280) but sign-up is a separate route.
- Check the wizard with a 15-variable `sync:false` form (the beancount.io Blueprint prompts for 15): layout, scroll, and that nothing in the URL or router state carries the values.
- Also record what the preview says on a clean workspace: the beancount.io Blueprint previews valid with a monthly estimate of about 32.97 USD (4 Starter services, 1 Postgres, 1 Key Value, a 10 GB disk) and a plan with no errors.
- If the link is lost at any step, file it as a bug with the step; do not fix inside this note.
