## Objective

Make `bex-operator-workloads` (and its day-to-day sibling, which has the same volume and toleration clauses) refuse a `projected` volume that sources a crown Secret, a toleration of `bex.co/platform`, and a container `hostPort`, each as a denial case first.

## Context

- `deploy/gitops/base/operator-workload-admission.yaml`: the volume rule (about line 203) forbids `hostPath` and a `secret` volume of a crown Secret (`bex-kubeconfig`, `bex-ca`, `bex-etcd`, `bex-proxy`, `bex-sa`) but not a `projected` volume's `sources[].secret`; the toleration grammar (about line 215) needs a non-empty key and refuses control-plane keys but not `bex.co/platform`, the taint platform pods tolerate (for example `deploy/gitops/charts/bex-postgres/cluster.yaml:31`); no clause looks at a container port's `hostPort`.
- The same volume and toleration clauses repeat in the day-to-day policy (about lines 529 to 541), and the build Job policy allows only `emptyDir` and non-crown `secret` volumes, so a `projected` volume is already refused there.
- Harness: `lego/operator/internal/controller/container_policy_admission_test.go`, one Ginkgo spec that starts its own API server, applies the deployed policy and binding, and writes real workload projections (`admissionApplicationWorkloads`, `admissionTierWorkloads`, `admissionEdgeCacheWorkloads`, `admissionPlatformWorkloads`) as the operator identity. Run it with `make test` from `lego/operator`.

## Steps

1. Add the denial cases: a pod template with a `projected` volume sourcing `bex-kubeconfig`, one tolerating `bex.co/platform` (Equal and Exists), and one with a container `hostPort`, on a workload kind the operator authors; and the allowed controls: a `projected` volume of a non-crown Secret or a service-account token, and a container port without `hostPort`. Watch the denials pass through the current policy.
2. Add to the volume rule `projected` sources that name a crown Secret, to the toleration grammar the `bex.co/platform` key, and a rule that no container, init container or ephemeral container sets a non-zero `hostPort`; mirror the first two in the day-to-day policy.
3. Run the spec: every workload the operator really projects is still admitted.
