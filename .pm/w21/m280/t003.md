## Objective

Expose the history on every API surface. Restoring is a read of the old version followed by an ordinary update with `ifVersion`.

## Context

- Pattern: ADR099 D3 table (`/v1/agent-skills`, `list_agent_skills`, …). New operations: list versions, get a version's content, get the diff against the previous version.
- Authorization matches reading a skill (`can_create`); the MCP tools sit in the `bex.cloud_agents` scope and are read-only.

## Steps

1. Add REST routes under `/v1/agent-skills/{id}/versions`, GraphQL fields and MCP tools `list_agent_skill_versions` and `get_agent_skill_version`.
2. Golden test for the MCP schemas; tests for unknown skill and unknown version errors.

## Files

- lego/backend/internal/agentskills/rest.go, graphql.go, mcp.go (package created by w9/m175)

## Acceptance criteria

- [ ] The same version list and content come back on REST, GraphQL and MCP.
- [ ] A restore through update with the old content creates a new version and leaves the history intact.

## Out of scope

- A dedicated restore endpoint (the restore flow is read plus update).
