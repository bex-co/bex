## Objective

Implement the selection ADR005 records, and tell the user what to change when neither CA may issue.

## Context

- `lego/operator/internal/controller/app_controller.go:606-626` (issuer annotation), `:4823` (wildcard issuer); the per-host TLS Secret (`TLSSecretNameFor`).
- `lego/backend/internal/apps/domains.go:647` (`domainCertificateReason`), `:717` (`certificateReadyReason`).

## Steps

1. Read the host's Certificate/Order failure, decide the issuer per ADR005, and write it on the Ingress for that host only.
2. Add the CAA lookup at add time if ADR005 keeps it.
3. Phrase a CAA refusal as a reason naming CAA and the values `letsencrypt.org` and `pki.goog`, identically on REST, GraphQL and MCP.
4. With no second issuer configured, behave exactly as today.

## Files

- `lego/operator/internal/controller/app_controller.go`
- `lego/backend/internal/apps/domains.go`
- their tests

## Acceptance criteria

- [x] Envtest: a CAA-refused host moves to the second issuer; an unconfigured second issuer changes nothing.
- [x] The reason text is the same on the three surfaces.

## Out of scope

- Moving platform `*.onbex.co` certificates.

## Result

Done 2026-11-24.

- **Operator** (`lego/operator/internal/controller/certificate_issuer.go`): after each App Ingress write, an Ingress that ingress-shim issues for from `BEX_CLUSTER_ISSUER` has each Secret-naming TLS entry's Certificate read; when its latest attempt failed (Issuing=False/Failed for the current generation) and `issuerMoveDue` says so, one update makes the Certificate the App's (controller reference) and names the other ClusterIssuer. ingress-shim leaves a Certificate it does not control alone (cert-manager v1.20.3 `certificate-shim/sync.go`, read 2026-11-24), and a changed issuer makes cert-manager retry at once (`shouldBackoffReissuingOnFailure`). The refusal reads the Certificate's message and the current issuer's Challenges, since a CAA refusal at validation reaches only the Challenge (`order is in "invalid" state:` on the Certificate). A dropped entry's taken-over Certificate is deleted (`deleteDroppedCertificate`); one whose host changed goes back to ingress-shim. `BEX_SECOND_CLUSTER_ISSUER` unset: nothing extra is read or written. RBAC adds `acme.cert-manager.io` challenges get/list/watch.
- **Shared predicate** `v1alpha1.CertificateRefusedOnCAA` (`lego/types/v1alpha1/certificate_refusal.go`): the ACME `caa` problem, or "CAA" as a word, except a DNS failure looking the records up.
- **bex-api** (`lego/backend/internal/apps/domains.go`): a CAA refusal reads _The domain's CAA records do not allow bex's certificate authorities to issue its certificate. Add CAA "issue" records for letsencrypt.org and pki.goog (and "issuewild" records for a wildcard domain), or remove the CAA records._ The Challenge and Order are read for the issuer the Certificate names now, so an earlier CA's refusal is not shown while the other CA works.
- **Step 2:** no CAA lookup at add time (t001).
- **Tests:** `certificate_issuer_envtest_test.go` (a CAA-refused host's Certificate becomes the App's and names `google-trust-services`, keeps its Secret name, is not moved again by the old generation's failure and is deleted when the host is dropped; with no second issuer its resourceVersion is unchanged; it fails with the move disabled), `certificate_issuer_test.go` (the move table, cert-manager's backoff, the failure read), `TestCertificateRefusedOnCAA`, and in bex-api `TestCertificateReasonNamesTheCAAValues` (REST, GraphQL and MCP, refused at validation and at finalize) and `TestCertificateReasonSkipsAnEarlierIssuer`, each failing with its part of the change reverted.
