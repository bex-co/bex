# `bex s3`: ask for confirmation before a bulk delete in a terminal, as `bex ea objects delete` does

Why: `bex ea objects delete` asks "are you sure?" in a terminal unless `--yes` or `--confirm` is given, while `bex s3 rm --recursive`, `rb --force` and `sync --delete` delete without asking (they follow the S3 command-line tools, which only offer `--dryrun`), and `bex s3` accepts the root `--confirm` flag and does nothing with it. Render parity is the top principle; ADR018 records the divergence (2026-11-20, awaiting the user's sign-off) and this is the parity-sufficient follow-up.

- **Change.** When stdin and stderr are terminals and neither `--yes` nor `--confirm` is given, `rm --recursive`, `rb --force` and `sync --delete` (not `--dryrun`) print what is about to go (the count, or the prefix) and ask; a pipe, a script or CI never prompts. `--yes` is the short alias `ea objects delete` has.
- **Where.** `lego/cli/internal/s3` (`rm.go`, `buckets.go`, `sync.go`; the terminal check is `deps.isTerminal`, already injectable), `docs/bex-cli.md`, the ADR018 divergence line.
- **Done when.** A test per verb proves a terminal run waits for an answer, `--confirm` and `--yes` skip it, and a non-terminal run never prompts; the divergence line in ADR018 is removed.
