# `/loopx` reports the decisions a worker made for the user, so none stays inside an ADR or a note

Why: twice in one run a choice the user would have made themselves reached them only in use. `bex s3` launched the user's own `aws` (the choice sat in a list of decisions made for them, and was described as available at release), and the `render-<region>` buckets that `bex s3 ls` shows were a worker's choice that ADR112 lists under "decisions the user can still change" and the user was never asked. A worker's `LOOPX-RESULT` has no place for such a choice, so it is lost in the notes of a commit.

- **Change.** The `LOOPX-RESULT` block (`.claude/skills/loopx/worker.md:189-195`, and the CI-fix variant) gets a `decisions:` line: each choice the worker made that the user will meet in their own account or output (a name, a default, a flag, a command's shape, a limit, an entry that shows up in a listing), with the alternative it did not take, or `-`. `worker.md` defines "user-visible" with the two cases above and says a decision an ADR calls changeable is still reported, not left in the ADR. The orchestrator (`.claude/skills/loopx/SKILL.md`: the run-local list of step 3, the drained report at `:157` and the Exit report at `:179`) keeps them and prints a **Decisions made for you** section ahead of the shipped list, one line each with the alternative and where it is changed. `/pmx`'s Report (`.claude/skills/pmx/SKILL.md`) carries them under the same heading.
- **Where.** `.claude/skills/loopx/worker.md`, `.claude/skills/loopx/SKILL.md`, `.claude/skills/pmx/SKILL.md`.
- **Done when.** A worker result with a `decisions:` line appears word for word in the drained report under that heading, and a result with `-` prints nothing; `bash scripts/skill-layout-validate.sh` passes.
