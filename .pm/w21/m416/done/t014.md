## Objective

Check the Cloudflare-shaped surface against Cloudflare's published API and wrangler, and check both contracts see the same data. Render has no equivalent of this surface.

## Context

- Surface: REST under `/cloudflare/client/v4`. Reference: Cloudflare's R2 API, error-code table and wrangler 4.162.0 (ADR112 § Sources). GraphQL, MCP and the dashboard have no object surface.
- Render parity still applies to the shared store: `render ea objects` and wrangler must read and write the same `render-<region>` data.

## Steps

1. Compare each route's result shape and error codes with Cloudflare's published API and wrangler's source.
2. Confirm the Render CLI and wrangler agree on the same objects.
3. Record each difference in ADR018's Extension row.

## Result

Dependency changed from t013 to t012 on 2026-11-15: the check reads Cloudflare's published API and wrangler 4.162.0's source and runs the real wrangler against the handlers, and none of that needs production (t013 does, and stays open as the gate). Compared on 2026-11-15 with Cloudflare's published API reference for create, list, CORS and lifecycle (Cloudflare publishes no reference for the object routes, which are wrangler's own `fetchR2Objects`; those are pinned by running the real tool) and with the R2 error-code table. Differences the comparison found and this task fixed: a bucket list took no query, where Cloudflare documents `name_contains`, `order`, `direction`, `start_after`, `per_page` (1 to 1000), `cursor` and a `result_info` block (now served, ordered by name, with `per_page` defaulting to 1000 because wrangler needs every bucket in one call and Cloudflare's own default is not published); a bucket's `location` is spelled in lower case in the schema (`wnam`), not upper; a CORS `maxAgeSeconds` tops out at 86400; and `rules` is optional on a CORS and a lifecycle set, so a body with none clears the set (any other field is refused). Differences that remain, each dated, unsigned and written into ADR018's extension entry with its reason: two regions and one storage class (bex's own), the caps, `7400` and the use of `10042` for an exceeded quota, `jurisdiction` always reported `default`, an unset CORS or lifecycle configuration listed as an empty array (Cloudflare's answer was not checked), the hardened object get, delete of a missing key succeeding, no range reads or checksum headers. Interoperation of the two contracts is shown at the service and handler level, not with the two real CLIs together: the real wrangler puts into `render-oregon` and Render's list shows the object (`TestWranglerEndToEnd`), the Render side mints a PUT URL and wrangler's route reads the bytes back (`TestCloudflareTheSystemBucketIsSharedWithTheRenderRoutes`), and the pinned Render CLI's own contract test (w21/m415 t008) runs against a stand-in. Running the real Render CLI and the real wrangler on the same production data is part of t013.
