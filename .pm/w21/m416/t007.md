## Objective

Make the only early warning for a wrangler release real: stock wrangler 4.162.0 against bex's own handlers.

## Context

- `docs/ADR112-object-storage.md` D11: `CLOUDFLARE_API_BASE_URL`, `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` are all stock wrangler needs; it calls no `/memberships` or token-verify route. Object commands default to local, so `--remote` is required.
- Measured with 4.162.0 earlier: bucket list, create, info, delete, object put, get and delete with `--remote`, `dev-url get|enable`, `cors list`, `lifecycle list`, `domain list`. Not run: `dev-url disable`, `cors set`, `lifecycle add|set|remove`, `domain add|update|remove`, `bulk put`, `create` with `--location`, `--jurisdiction` and `--storage-class`. Run those for real here.
- CI rules: `scripts/github-actions-validate.sh` allows only `ubuntu-24.04-arm` or `ubuntu-latest` runners (DO_NOT_DO #CI-RUNNERS, re-opened 2026-11-09); a workflow's `paths` must list every file outside its tree its tests read (`scripts/ci_test_inputs.py`).

## Steps

1. Capture wrangler 4.162.0's requests for every command above and write them as fixtures the Go test replays.
2. Write `scripts/wrangler-r2-contract.sh`: install the pinned wrangler into a temp directory, start bex-api with the fake S3, and run the commands end to end.
3. Add `.github/workflows/wrangler-r2-contract.yml` (weekly and on pushes touching the handlers) and any `ci_test_inputs.py` entries.
