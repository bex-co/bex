## Objective

Serve `wrangler r2 object put --remote`, whose bytes travel in the REST call, without the 30 s server timeouts cutting a large upload.

## Context

- `docs/ADR112-object-storage.md` D3: require `Content-Length` (`10033`), refuse above 300 MiB (`100100`), extend the per-request deadlines with `http.NewResponseController` (precedent `internal/deploys/platform_rebuild.go:192`; the server's 30 s timeouts are in `cmd/api/main.go` `newHTTPServer`), run the quota gate, stream to Wasabi on a server-signed presigned PUT (no payload hash, no spooling), store `Content-Type`, `Cache-Control`, `Content-Disposition`, `Content-Encoding`, `Content-Language` and `Expires` as sent, overwrite on put.
- Concurrent streams: 8 per workspace and the per-replica cap, `429` code `10058`. Traefik's `readTimeout` is 6000 s (`deploy/gitops/base/values/traefik.values.yaml:72`).
- Unverified: whether Wasabi accepts a streamed presigned PUT with a signed `Content-Length` (the production walk, t013, settles it). If it does not, fall back to a single `PutObject` with the known length and record why.

## Steps

1. Add `Client.PutStream(key, size, body, headers)` to the package and the put handler.
2. Test: no length gives `10033`; 300 MiB + 1 gives `100100`; a body slower than 30 s still completes; the ninth stream gets `429`; a quota breach gives `10042` with a message that names the cap.
3. Check wrangler's measured request shape (headers and chunking) against the handler.
