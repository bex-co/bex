## Objective

Close the two request-validation gaps the audit named in the dashboard's server functions, each with a test that fails first.

## Context

- `isSameOrigin` (`src/common/server-fn/same-origin.ts`) compares the Origin host with the request URL's host or with `X-Forwarded-Host`, which a client can send; whether the dashboard's own ingress needs it (the code says behind an ingress the server sees http while the browser sends https, but it compares hosts, which are the same) has to be checked before it goes.
- The JSON routes `api.sessions` and `api.connected-agents` do not require `Content-Type: application/json`, so a cross-site form POST (`text/plain`) reaches them; the browser blocks a `fetch` with that type only through CORS.

## Steps

1. Find what sets `Host` and `X-Forwarded-Host` in each deployment (Traefik in production, Vite locally) and decide whether the Origin host can be compared with the request host alone; if not, trust the header only from the platform's own proxy.
2. Add the failing cases, then the smallest change; add the content-type requirement to both routes with a 415 answer.
3. Run the dashboard tests.

## Files

- dashboard/src/common/server-fn/same-origin.ts
- dashboard/src/routes/api.sessions.ts (and api.connected-agents)
- their tests

## Acceptance criteria

- [ ] A request that forges `X-Forwarded-Host` is refused, a same-origin request through the real proxy shape still passes, and a non-JSON POST to either route answers 415.
