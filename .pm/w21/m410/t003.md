## Objective

Tighten the Content-Security-Policy where it can be done without nonces, and keep the platform's response headers on error responses.

## Context

- `dashboard/server/security-headers.ts`: `script-src 'unsafe-inline'`, `connect-src https: wss:`, no `base-uri` or `form-action`. Removing `unsafe-inline` needs per-request nonces through TanStack Start's SSR and is a design change, so it is recorded, not done here.
- Non-2xx responses lose the route-rule headers (h3's `prepareResponse`); the dashboard already works around the Nitro v3 quirks in `server/plugins/html-never-public.ts` and `server/middleware/assets-miss.ts` (w21/m394).

## Steps

1. Add the policy test first: `base-uri 'self'`, `form-action 'self'` (check the OAuth and Kratos forms post to the same origin), and `connect-src` limited to `self` plus the API and websocket origins the app really uses.
2. Reproduce the lost headers on a 404 and a 500 in a test against the built handler, then restore them.
3. Record `unsafe-inline` as accepted in `dashboard/AGENTS.md` with what removing it takes.
