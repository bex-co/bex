## Objective

Make `safeNext` and the service worker's notification click hold their own contract: the result is a same-origin path that starts with a single `/`, never a protocol-relative `//host`.

## Context

- `safeNext("/.//evil.com")` returns `//evil.com` (also `/a/..//evil.com`, `/%2e//evil.com`, `/..//evil.com`): the leading-character guard runs before `new URL` collapses the dot segment, and the result is rebuilt from `pathname`. The login route feeds it to Kratos' `return_to` and to a router `href`; the router neutralises it today.
- `dashboard/public/push-sw.js` has the same shape: a notification payload whose `route` is `/.//evil.com` reaches `client.navigate("//evil.com")` and `openWindow("//evil.com")`.
- Tests: `src/common/lib/__tests__/safe-next.test.ts`; the service worker has none, and is plain JavaScript run in a worker scope, so a test loads the file and calls its `notificationclick` handler with a stubbed `self`.

## Steps

1. Add the failing cases to `safe-next.test.ts` and a new test for the service worker (stubbed `self.clients`), covering the four payloads above and the ordinary routes that must still work.
2. Reject a result that starts with `//` or `/\` in both places, after the URL resolves.
3. Run the dashboard tests.
