## Objective

Make the access rules of D6 real for the four routes: workspace relations and OAuth scope classes, including the get row that moves to sensitive.

## Context

- `docs/ADR112-object-storage.md` D6: list is `can_view`; get is `can_view_sensitive`; put and delete are `can_create`. Machine API keys carry no scope and hold the `developer` role.
- `lego/backend/internal/api/scope_matrix_ops.go:799-800` classes the list and get rows as `OpClassRead`; `:682` and `:1033` class delete and put as `OpClassWrite`. The get row changes to `OpClassSensitive` (beside the Postgres export row), or a developer's `bex.read`-only token could mint a presigned GET for the bytes.
- Regenerate the matrix with `GENERATE_SCOPE_MATRIX=1 go test ./internal/api -run TestGenerateScopeMatrix`; scope classes live in `lego/backend/internal/core/scope.go:217-232`.

## Steps

1. Pass the right relation to `AuthorizeWorkspace` in each handler.
2. Change the get row to `OpClassSensitive` and regenerate the matrix.
3. Write the tests: a viewer lists but cannot get, put or delete; a developer does all four; a `bex.read`-only OAuth token cannot mint a GET URL; a `bex.write` token cannot either; a machine key is unaffected; another workspace's `ownerId` is refused with the shape the other Render routes use.
