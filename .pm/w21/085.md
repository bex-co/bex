# 085 — A token revoked at Hydra is still accepted by bex-api for more than 90 seconds

Why: revocation is a security control, so how long a revoked token keeps working must be known, bounded and written down.

- **Source:** the post-deploy check of w21/m417's fixes on production, 2026-11-15. A token revoked directly at Hydra was still accepted by bex-api for more than 90 s, until `/v1/oauth/revoke` on bex-api was called enough times to reach both replicas. The cache TTL was not found. Revocation through bex-api's own `/v1/oauth/revoke` is not covered by this note.

## Steps

1. Find where bex-api caches token introspection (the OAuth middleware in `lego/backend/internal/api`) and read the TTL and the cache key.
2. Decide the bound (Render's tokens are API keys with no cache; for OAuth access tokens a short bound such as 30 s, or invalidating on `/v1/oauth/revoke` across both replicas) and write it in ADR012 as the revocation latency.
3. Implement it with a test that revokes at Hydra and asserts the token is refused within the bound.

## Done when

- [ ] The revocation latency is a documented number and a test pins it.
