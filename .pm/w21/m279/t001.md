## Objective

Write the design for session lineage, including the limits and the inheritance rules that keep a spawning agent from escaping its owner's controls.

## Context

- `docs/ADR094-coding-agent-mcp.md` line 254 defers this: "bex agents cannot yet spawn agents; an in-sandbox tool for that, with lineage on the session record, is a separate decision."
- Reference (Devin, verified live in the Devin dashboard on 2026-11-06): the parent chat shows a "Created a Devin session" card for each child; an Agents panel groups children by status with a View session link; the sidebar nests children under the parent. Devin's automation form also has an "Allow auto-start of child sessions" switch (default on); bex has no approval mode (`.pm/DO_NOT_DO.md` #APPROVAL-MODE), so children always start unattended. Devin's docs add that a parent can launch children with their own prompt, playbook, tags and spend limit and message running children.
- Decisions to settle with the user: does a child's spend count against the parent's ceiling (recommended: yes), and does a child inherit the parent's secrets (recommended: inherit, never add).

## Steps

1. Write the ADR: lineage columns, depth and fan-out limits, spend roll-up, secrets inheritance, cancel cascade, the spawn path through ssh-gateway, API, MCP and dashboard.
2. Get the user's answers to the three decisions and record them with dates.
3. Add the row to `docs/AGENTS.md`.
