# 104 — "Billing recovered: Payment recovered and resources changed by billing enforcement were restored" is sent to a workspace that never paid and never had a resource enforced

Why: the recovery notice states two things that are false when the recovery corrects bex's own mistake for a workspace that never bound a card, and the owner has by then already received two wrong mails about it.

Found 2026-11-16 while recovering the 11 workspaces of [w21/m336](m336/README.md) (the user accepted the mail for them, so this is polish, not a gate).

- **Source:** `billingEmail` in `lego/backend/internal/notifications/service.go` (the `store.BillingHealthy` case, near line 297) has one wording for every transition into `healthy`, whatever the previous status, the reason and the workspace's enforcement rows.
- **Also wrong in the same mail:** its footer and subject say "Stripe Test Mode" because a workspace with no provider mapping reads as test mode (the w21/m336 t001 rule), while production's Stripe account is live mode (all 13 mappings that hold a card read `livemode=true`). The 11 workspaces got "[bex Test Mode]" on all three mails for that reason; a workspace that never had a mapping cannot say which mode it was in, so the label should be dropped or taken from the platform's configured mode, not guessed.
- **Care:** the operator `recover` override (`ForceBillingRecovery`) and a real payment recovery both end in `healthy` with the notice queued by `CompleteBillingLifecycleWork`; only the first can name a workspace that never paid. A change must keep the real recovery's text and the "no payment details" footer.

## Steps

1. Decide the minimal truthful behaviour for a recovery of a workspace with no `payment_method_bound_at` and no `billing_enforcements` row: no mail, or a mail that says billing is in good standing and nothing was suspended.
2. Carry that fact to the notice (the notification row already has `reason`; a recovery from an operator correction can say so) and test both wordings against the store and `billingEmail`.

## Done when

- [ ] Recovering a never-paid workspace sends nothing false, and a real payment recovery's notice is unchanged; both are tests.
