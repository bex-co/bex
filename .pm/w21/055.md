# Refuse a webhook Destination URL whose literal host is loopback, private or cluster-internal when it is saved (REST, GraphQL, MCP and the form), a stricter-than-Render variant of w21/046

Why: [w21/046](done/046.md) shipped the parity-sufficient half (an inline notice and a "Destination not allowed" delivery label) because Render accepts any webhook URL and reports a failed delivery in its list; refusing at save is stricter than Render, so it needs the user's sign-off in ADR018 before it ships.

**Severity:** minor. **Estimate:** 35m once decided. **Kind:** follow-up variant split from w21/046. **Status:** inbox; needs a user decision.

## What 046 left as it was

- `webhooks.Service.parseDestination` (`lego/backend/internal/webhooks/service.go`, create and update) checks the scheme, a host, no userinfo and the byte cap only. `https://localhost/x`, `https://127.0.0.1/x`, `https://169.254.169.254/x`, `https://[::1]/x` and `https://x.svc.cluster.local/x` still save (201) and every delivery fails at dial time (`netutil.SafeDialContext`), because Render accepts any URL and bex matched that.

## The variant

- `parseDestination` refuses a destination whose literal host is unsafe, with the rule `validatePublicRewriteHost` already applies to static-site rewrites (`netutil.UnsafeOriginIP`, a single-label host, a `.localhost`, `.local`, `.internal`, `.lan`, `.svc`, `.cluster.local` or `.home.arpa` name) and a message that names the reason. REST create and update, GraphQL and MCP share it.
- The form's notice becomes an inline error that holds Create (`isUnreachableWebhookDestination` in `dashboard/src/features/webhooks/lib/unreachable-destination.ts` is the mirror).
- A hostname that merely resolves to a private address stays a dial-time failure. Webhooks already stored with such a host are not migrated.

## The decision

- Whether bex may refuse at save an input Render accepts. `AGENTS.md` lets a divergence stand only when [ADR018](../../docs/ADR018-render-parity.md) records it with the user's sign-off, so a "yes" is recorded there in the same change; a "no" closes this note.
