## Objective

Show where bex places a multi-instance service today, and record the rule that matches Render.

## Context

- `bash scripts/mock-cluster.sh` and `bash scripts/mock-cluster.sh scale N` (pre-approved, AGENTS.md); the local overlay also uses `MostAllocated` (`infra/clusterapi/overlays/local-capd/cluster.yaml:376-387`).
- `projectDeployment` in `lego/operator/internal/controller/deployment_projection.go:935`; manual scale creates no rollout (ADR018 Manual scale row, w2/m56).

## Steps

1. Bring up the mock cluster with at least three tenant workers; deploy the sample App and scale it to 2 and 3.
2. Record the nodes each instance lands on, over several runs.
3. Write an ADR004 section: the constraint, which services carry it (paid, non-`Recreate`, instance count or autoscaling maximum above 1), how it reaches existing Deployments without rolling them, and how a 1 → 2 scale of a template without it behaves.

## Result

Done 2026-11-24. The measurement and the rule are in [ADR004 § Multiple instances run on different nodes](../../../../../docs/ADR004-app-deployment.md#multiple-instances-run-on-different-nodes-w21m617).

- Mock cluster (CAPD, Kubernetes v1.36.1, `MostAllocated`, three tenant workers plus the untainted platform worker, 8 CPUs a node), the operator from before this milestone: a new Starter service at two and three instances, three runs each, landed one instance per node, also with one tenant node packed to 75% CPU. The built-in spread score and image locality outweigh `MostAllocated` on near-empty 8-CPU nodes.
- The gap: with room for a second instance only on the node holding the first, the scale to two put it beside the first (Running 15 s later).
- Rule recorded: every web, private and worker service that can run more than one instance (no disk, not Free) carries the spread, **at one instance too**. Deviation from this task's "instance count or autoscaling maximum above 1": a scale makes no rollout (ADR018 Manual scale), so that rule would either roll the running instance at the scale or miss the instance the scale adds.
- Rollout policy recorded: adopted on the service's next deploy, restart or settings change, never on the upgrade or a scale; a 1 → 2 scale of a template without it places the new instance by the default score until that roll.
