# Live completion webhook and spend ceiling on a dev stack (m260 definition of done)

Why: m260's definition of done asks for a live run; it was verified by backend (real Postgres + OpenFGA), gateway and webhook tests only. `scripts/dev-env.sh` takes N 1-10, so there is no `dev-21` harness. This note keeps `w21/m260/t007` (closeout) open.

- On a dev stack with the agent leg up and a platform model route for the workspace, subscribe a webhook endpoint (for example a request catcher) to `agent_session_turn_succeeded` and `agent_session_turn_failed`, run one session that succeeds and one that fails, and confirm one signed delivery each with `data: {id, state, outcome}` (no `summary`), `id` = the session id, and nothing for a workspace without a subscription.
- Create a session with a tiny `maxSpendUSD` (for example `0.01`) on the platform model, let it run past the ceiling, and confirm the next model request gets the Anthropic-shaped 429 with `code: AGENT_MODEL_SPEND_CAP_REACHED` and `scope: "session"`, the turn ends `failed` with that `failureReasonCode`, and `outcome.cost.modelUSD` equals the `agent_model_usage_events` sum. Also confirm a session on the workspace's own model key is refused `400 AGENT_SESSION_SPEND_LIMIT_UNAVAILABLE`.
- Confirm migrations 0201/0202 applied on the rolled-out bex-api and that the webhook worker's `ListWebhookEvents` plan stays cheap with the new `agent` arm (the arm is filtered by `workspace_id = ANY($5)` and read by `(recorded_at, session_id, turn)`).
