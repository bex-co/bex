## Objective

Add meaningful tests for the behavior this milestone shipped: real behavior and failure modes, never tautological or snapshot-everything tests.

## Context

- Changed code: lego/backend/internal/objectstorage/, lego/backend/internal/api/objects_render.go, lego/cli/objects_contract_test.go
- Read each earlier task's acceptance criteria and check a test fails if the behavior is removed.

## Steps

1. List the behaviors and failure modes shipped by the milestone's tasks.
2. For each, find the test that fails when the behavior is removed (mutate it locally to confirm); add the missing ones.
3. Run the backend suite with the real Postgres the repo's CI uses.

## Files

- lego/backend/internal/objectstorage/, lego/backend/internal/api/objects_render.go, lego/cli/objects_contract_test.go

## Acceptance criteria

- [ ] Every behavior and failure mode in the milestone has a test that fails without it.

## Out of scope

- Raising coverage numbers with trivial tests.

## Result

Mutation-checked every behavior the milestone shipped: 15 mutants (quota bytes and objects boundaries, the emptiness verdict on delete, the HEAD before a get mint, the unsigned Content-Length, the missing attachment pin, a `..` segment, a leading slash, an ignored cursor, a get that needs only can_view, a put authorized as a view, an unlimited mint rate, the scope row back to read, an ignored bucket cap) were each killed by a test, except removing the lock-free fast path of `EnsureSystemObjectBucket`, which is a behavior-preserving optimization. The review turned up two gaps and both are closed: the per-workspace advisory lock (the cap and the single system bucket under concurrency) had no test, so `TestObjectBucketCreationIsSerializedPerWorkspace` races 12 creates under a cap of 3 (exactly 3 succeed) and 16 `EnsureSystemObjectBucket` calls (one row), and removing the lock from either path now fails it; and the first mutation run showed two mutants that did not compile, re-run with compile-safe forms and caught. Earlier in the milestone, real failures found by running the wider suite became fixes: the tenant-scope census (every workspace_id table needs a delete disposition) and the sensitive-override heuristic table. The full backend suite runs in the ship gate (`scripts/ship-gates.sh`, real Postgres, OpenFGA, OpenBao).
