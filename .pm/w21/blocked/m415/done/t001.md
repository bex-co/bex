## Objective

Add the two tables ADR112 D1 and D8 name, the typed `obk-` id kind and the store methods every later task reads and writes.

## Context

- `docs/ADR112-object-storage.md` D1: `object_buckets(id, workspace_id, name, region, system, public, cors, lifecycle, created_at)` with `(workspace_id, name)` unique; D8: `object_storage_usage(workspace, bucket, region, bytes, objects, observed_at)`.
- Latest migration when this was filed: `lego/backend/internal/store/migrations/0271_agent_session_retained_images`. Take the next free number at write time (`git ls-tree -r --name-only origin/main -- lego/backend/internal/store/migrations`); follow `0184_agent_session_attachments.up.sql` for the workspace foreign key and delete behavior.
- Ids: `lego/backend/internal/id/id.go:149` (`AgentAttachment = Kind{prefix: "att", …}`) and the `kinds` list at `:175`. Mint only through `id.New`.
- `docs/ADR020-identifiers.md` lists every prefix.

## Steps

1. Write the `up` and `down` migration for both tables.
2. Add `ObjectBucket = Kind{prefix: "obk", desc: "object storage bucket"}` to `id.go`, append it to `kinds`, and update the id package's tests.
3. Add the `obk` row to `docs/ADR020-identifiers.md`.
4. Write `internal/store/object_buckets.go`: create (a duplicate `(workspace_id, name)` returns a typed conflict error), get by name, get by id, list by workspace, delete, set public, set cors, set lifecycle, count non-system buckets, upsert usage, read usage by workspace and region.
5. Write store tests in the style of the neighbouring store tests (real Postgres, skipped without the CI dependencies).

## Acceptance criteria

- [ ] The migration applies and reverts on the CI Postgres.
- [ ] A second bucket with the same `(workspace_id, name)` returns the typed conflict error; a deleted and recreated name gets a new `obk-` id.
- [ ] `id.New(id.ObjectBucket)` returns an `obk-` id and the id tests cover it.

## Out of scope

- Routes, Wasabi calls, and cleanup on workspace delete (w21/m416).

## Result

Migration 0273_object_storage (both tables, a partial unique index so a retired row does not hold a name, no workspace foreign key as in 0184), the `obk` id kind, and `internal/store/objectbuckets.go` with its tests and a migration round-trip test. Beyond the task text: `location_hint` (so `bucket info` can report the hint), `deleted_at` and `purge_attempted_at` (the retire-then-purge state w21/m416 t010 uses), and a capped create under a per-workspace advisory lock. docs/ADR020-identifiers.md lists only Render-spelled prefixes (`att-` and `bds-` are absent too), so no row was added; the registry in id.go is the source.
