## Objective

Build the core service every route calls: bucket rules, the Render namespace as a system bucket, the write-time quota gate and the concurrency limits.

## Context

- `docs/ADR112-object-storage.md` D1 (system bucket, 1,000-bucket cap, `render-` reserved, a bucket must be empty to be deleted), D8 (gate, caps, per-workspace mint rate limit that bounds Contract A's overshoot).
- The gate reads the last observed usage from `object_storage_usage` (t001); until the sweep (w21/m416) writes any, usage reads as zero and the per-object cap and rate limit still apply.
- The ADR gives no per-replica stream cap or mint rate; choose constants here and record them with the other caps (ADR018, dated, unverified).

## Steps

1. Add `service.go`: `CreateBucket` (name rule, reserved prefix, 1,000 cap excluding system buckets, conflict error), `EnsureSystemBucket(workspace, region)` (idempotent), `ListBuckets`, `GetBucket`, `DeleteBucket` (empty check with a one-key `List`; ADR112 is silent on deleting a system bucket, so it follows the same rule).
2. Add `quota.go`: `Gate(workspace, region, addBytes, addObjects)` against the 100 GB and 1,000,000-object caps with typed errors the adapters map (429 on Contract A, 403 `10042` on Contract B).
3. Add `limiter.go`: 8 concurrent streams per workspace plus a per-replica cap, and a per-workspace mint rate limit.
4. Test every rule with the fake S3 and the store.

## Files

- lego/backend/internal/objectstorage/{service,quota,limiter}.go and tests

## Acceptance criteria

- [ ] A name that starts with `render-` is refused for a user bucket and accepted for the system bucket.
- [ ] The 1,001st user bucket is refused and a system bucket does not count.
- [ ] A put that would pass a cap is refused before any URL is minted; a ninth concurrent stream is refused.
- [ ] A bucket with one object cannot be deleted.

## Out of scope

- Routes (t006), the sweep that fills usage (w21/m416).

## Result

`objectstorage.Service` over a small `Repository` interface (`*store.PGStore` satisfies it): create (name rule, reserved `render-`, region needs a store, cap and conflict mapped), the idempotent system bucket, get, list, and delete with a one-key emptiness check that treats an unreachable Wasabi as an error rather than as empty; `Gate` (bytes and objects against the last sweep, a failed usage read refuses the write); `CheckObjectSize`; `StreamLimiter` (per workspace and per replica, idempotent release, forgets idle workspaces); a per-workspace token bucket for mints. Tests: stub-repository tests for every mapping and cap edge, Postgres plus fake-S3 tests (system bucket once, duplicate name, non-empty delete, Wasabi down, a recreated name never sees the old objects), a race-detector run and concurrency test. Two constants beyond the ADR, recorded as bex's own: 64 concurrent streams per replica and a mint burst of 30 refilling at 5 a second.
