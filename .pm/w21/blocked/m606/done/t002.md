## Objective

A workflow in this repository builds CloudNativePG's operator image from the tag in `deploy/cnpg-operator/UPSTREAM` plus every patch in `deploy/cnpg-operator/patches/`, and publishes it to GHCR as a multi-arch manifest (linux/arm64, linux/amd64) whose digest the workflow prints. No fork repository is needed to build it.

## Context

- `.github/workflows/pg-operand-image.yml` is the precedent for building from an upstream base and publishing to `ghcr.io/bex-co/bex-operator` by digest. Runners are `ubuntu-24.04-arm` by default and `ubuntu-latest` only for amd64 work (`DO_NOT_DO.md` #CI-RUNNERS, as amended 2026-11-09).
- Upstream builds with goreleaser (`.goreleaser.yml`): `CGO_ENABLED=0`, `main: cmd/manager/main.go`, `binary: manager/manager_{{ .Arch }}`, and `-X github.com/cloudnative-pg/cloudnative-pg/pkg/versions.build{Version,Commit,Date}`. Its `Dockerfile` copies `dist/manager/*` and links `manager` to `operator/manager_${TARGETARCH}`. The same binary is the instance manager that the operator copies into every Postgres pod.
- A CI workflow's `paths` must list every file outside its tree that its tests read (`scripts/ci_test_inputs.py`).

## Steps

1. Add `.github/workflows/cnpg-operator-image.yml`. It runs on `workflow_dispatch` and on pushes to `main` touching `deploy/cnpg-operator/**`.
   1. Check out `cloudnative-pg/cloudnative-pg` at `UPSTREAM`'s commit, verify the tag points at it, and `git apply` the patches.
   2. Run t001's package tests.
   3. Build `manager_arm64` and `manager_amd64` with upstream's ldflags, keeping `buildVersion` `1.30.1` and putting the bex suffix in the image tag.
   4. Build and push with upstream's Dockerfile, then print the digest.
2. Name the tag after the upstream version and a bex revision (for example `cnpg-1.30.1-bex.1-<bex commit>`). Follow `pg-operand-image.yml`'s naming.
3. Run it, and record the run id, the digest and each architecture's manifest.
