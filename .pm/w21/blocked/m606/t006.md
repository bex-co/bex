## Objective

## Context

- The production pin must carry t004's commit, and w21/m585's `979d68fdc1`, which admits `pgaudit`. If either is missing, park with ``pin must carry `<sha>` ``.
- `bash scripts/fetch-app-kubeconfig.sh <path outside the repo>` gives the app cluster's kubeconfig. Use the QA workspace `bex-canary`, and delete each database at the end (404).
- Render's command is `CREATE EXTENSION pgaudit;` (<https://render.com/docs/postgresql-extensions>).

## Steps

1. Confirm `cnpg-system`'s Deployment runs t004's digest. Confirm every managed cluster's instance manager reports the new version, and that its postmaster start time is unchanged from before the pin (no PostgreSQL restart). Confirm `bex-postgres` and the auth databases are healthy.
2. Create a new Free database (disposable) on a bex-operand major. As the default user over the external URL, run `CREATE EXTENSION pgaudit;`, then `\dx`.
3. Delete its primary pod (or use Render's restart verb), wait for `available`, and check that `pgaudit` is still in `pg_extension`. Then `DROP EXTENSION pgaudit;` succeeds.
4. On a second new database (disposable), `CREATE EXTENSION pgaudit;` succeeds without "already exists".
5. Record the result in this milestone's README, ADR092 and ADR018. Delete both databases.
