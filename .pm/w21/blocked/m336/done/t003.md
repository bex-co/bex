## Objective

Let the push worker's delivery stages run when the projection stage fails: a failing `dispatch` or `dispatchAgentSessions` must not stop `send`, `checkReceipts` and `sweep`, and must not lose or skip the feed page that failed.

## Context

- `PushWorker.RunOnce` (`lego/backend/internal/notifications/push_worker.go:200-236`) returns at `:216` and `:219` when projection fails, so already-queued deliveries are never sent, receipts are never checked and retention never runs that tick.
- A feed page whose projection fails (`fanOutPage` returns the error, for example when `levels.admits` fails on a policy or owner lookup, `:626-640`) keeps its cursor, so it retries every poll interval (2 seconds). A permanently failing row therefore starves the rest forever, and the error is only logged.
- Whether a feed row can fail permanently is not verified; a transient database error already shows the same starvation for its duration. The change must hold in both cases.
- The comment on `RunOnce` states the ordering rule to keep: projection is committed before any provider call, so a send never precedes the logical notification and the cursor commit.

## Steps

1. Write the failing test first in `lego/backend/internal/notifications/push_worker_test.go`: a store with a queued delivery and a feed page whose `levels.admits` returns an error; `RunOnce` must still call the sender for the queued delivery. It fails today.
2. In `RunOnce`, collect the projection errors (`errors.Join` of `dispatch` and `dispatchAgentSessions`), run the send, receipts and sweep stages regardless, and return the joined error of all stages.
3. Keep the cursor rule: the failed page's cursor must not advance, so its events are retried (assert that in the test).
4. Decide whether the failing page should back off instead of retrying every 2 seconds, and record the decision in the Acceptance section; if it is a small change inside this file, include it, otherwise file a note. **Decided 2026-11-11: no backoff.** `TailFeed` is the shared pager for webhooks, alert email and push, and its `Park` option only moves a quiet cursor forward; a per-page backoff is a change to that shared contract, and with the stages decoupled a failing page no longer starves anything. The retry and its log line stay at the poll cadence.
