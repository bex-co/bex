## Objective

Everything Render lists that needs the image or a restart is in the digest m584 adopts, so later admissions are reloads.

## Context

- Render lists `pg_repack` for "PostgreSQL 16 or later" and `wal2json` and `pgaudit` for 13+ ([postgresql-extensions](https://render.com/docs/postgresql-extensions), read 2026-11-23).
- PGDG bookworm carries `postgresql-{13..18}-repack` 1.5.3, `postgresql-{13..18}-wal2json` and `postgresql-{13..18}-pgaudit` (Packages index read 2026-11-23). CNPG's system image already carries pgaudit, pgvector and pg-failover-slots only (`cloudnative-pg/postgres-containers` `docker-bake.hcl:43-45`); `matrix.json` and the Dockerfile install no `wal2json`.
- pg_repack 1.5.2 "Allow to run pg_repack by non-superusers"; the C functions require table ownership (`must_be_owner`, `lib/repack.c:120`), and its `regress/sql/nosuper.sql` grants the non-superuser `USAGE` on schema `repack` and its tables. Under pgextwlist the `repack` schema belongs to the bootstrap superuser, so the owner needs a custom script in `deploy/pg-operand/extwlist/pg_repack/` (the pattern of `extwlist/pg_partman`).
- pgaudit refuses to load outside `shared_preload_libraries` (`pgaudit.c:2292-2295`, "pgaudit must be loaded via shared_preload_libraries"). Add it to `pgExtensionPreloadLibraries` (`database_operand.go:69`). Do not use CloudNativePG's pgaudit management through `pgaudit.*` parameters; confirm it would also create the extension in every database, which ADR092 D2 rules out.
- `wal2json` is an output plugin, used through `pg_create_logical_replication_slot(…, 'wal2json')` by a role with `REPLICATION` (w34/m541's enable verb); `wal_level` is already `logical` (ADR009 § Logical replication).

## Steps

1. Add the three packages per major in `matrix.json` (`pg_repack` 16–18 only) and to the Dockerfile's install.
2. Add `pg_repack` to `extensions` on 16–18 and write its after-create grant script.
3. Add `pgaudit` to the projected preload list; add a gate check that `SHOW shared_preload_libraries` lists it.
4. Gate checks: `CREATE EXTENSION pg_repack` as the owner on 16+; a superuser creates and drops a `wal2json` slot and reads one change through it.

## Done (2026-11-23)

- `matrix.json`: `wal2json` on 13–18, `repack` on 16–18, `pg_repack` carried and admitted on 16–18. pgaudit comes from CNPG's system base (already `postgresql-<major>-pgaudit`), so the Dockerfile asserts `pgaudit.so` and `wal2json.so` instead of installing pgaudit again.
- `extwlist/pg_repack/after-create.sql` grants `USAGE, CREATE` on `repack` and `SELECT` on its views, and hands `repack.repack_trigger()` (`SECURITY DEFINER`) to the database owner, so it never runs the owner's triggers on its own log table as superuser. The gate runs `pg_repack --no-superuser-check` as the table's owner and checks the trigger's owner.
- `pgaudit` joins `pgExtensionPreloadLibraries` and `config.sh` on every major. CNPG's `pgaudit.*` management would `CREATE EXTENSION pgaudit` in every database, and drops an installed one when no `pgaudit.*` parameter is set (v1.30.1 `reconcileExtensions`): recorded in ADR092 D1 for w21/m585.
- **Found:** the bases' minor releases add `output_plugin_libraries` (postgres/postgres `4e1252ee56`, 14+), which refused `wal2json` even for a superuser. The operator projects `pgoutput,test_decoding,wal2json` on 14–18 (13 has no such setting), keeps tenants from overriding it, and `config.sh` matches.
- Gate: a superuser reads an insert through a `wal2json` slot; `SHOW shared_preload_libraries` lists `pgaudit`. Local PG15 and PG18 builds pass.
