## Objective

Delete the objects a bucket's lifecycle rules say to delete, bounded so the sweep stays inside its hour.

## Context

- `docs/ADR112-object-storage.md` D5: delete objects matching a rule's prefix whose `LastModified` is older than `maxAge` (or past `date`), at most 10,000 per rule per sweep. Whether `LastModified` suits `maxAge` on Wasabi is unverified.
- Wasabi bills a 90-day minimum storage duration; whether it bills the remainder for a deleted object is unverified, so the user docs must say a short rule saves nothing on storage.

## Steps

1. Add rule evaluation to the sweeper and the 10,000 bound.
2. Test `maxAge`, `date`, prefix match, the bound and a rule that matches nothing.

## Files

- lego/backend/internal/objectstorage/sweeper.go and tests

## Acceptance criteria

- [ ] Only matching, expired objects are deleted and no more than 10,000 per rule per sweep.

## Out of scope

- Storage-class transitions (answered `10042`).

## Result

`objectstorage/lifecycle.go` (`LifecycleRule`, `ParseLifecycle`, `Validate`) and the sweep: each enabled rule that deletes (`Age` by `LastModified` older than `maxAge` seconds, or `Date` once the date has passed, as S3 and R2 do) deletes the objects under its prefix, after each listed page, in one batch request, at most 10,000 per rule per sweep (an object several rules match is deleted once and charged to the first with room). The simplify review found a real bug here: a `maxAge` of 10,000,000,000 (a "never expire" idiom) overflowed `time.Duration`, which made every object look expired and deleted up to 10,000 per rule per hour. `maxAge` is now compared in seconds and capped at 100 years (`MaxLifecycleAgeSeconds`), by `Validate`, so the route refuses it and the sweep skips it. A rule that does not parse or validate is logged and skipped and never aborts the sweep; a missing `maxAge` deletes nothing (it is a pointer, so it cannot read as 0). A failed delete stops deletion for that region until the next sweep. `LastModified` as the age of an object on Wasabi, and whether Wasabi bills the rest of its 90-day minimum for a deleted one, remain unverified; the user docs say a short rule saves nothing on storage. Tests: `maxAge`, `date`, prefix match, disabled, the bound, shared cap, a rule that matches nothing, a bad rule beside a good one; mutation-checked.
