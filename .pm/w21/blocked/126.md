# 126 — Give Render's DDoS protection an ADR018 row: what bex's tenant edge does today, and the user's sign-off or the Cloudflare decision

Why: Render promises every app automatic DDoS protection, and bex's ledger calls it "same on every plan" without saying what bex's edge does, so the claim has never been checked.

**Source:** `/pm-brainstorm one aspect of render parity to w21` (2026-11-23), item 4, filed by `/pmx them all to w21`. Render's [ddos-protection](https://render.com/docs/ddos-protection) page was cited nowhere in the repository.

- **Render** (read 2026-11-23): "free distributed denial-of-service protection" for every application and website, on Cloudflare's infrastructure, with no setup.
- **bex:** every `*.onbex.co` host and every DNS-only custom domain reaches the Hetzner load balancer directly, not through Cloudflare ([ADR022](../../../docs/ADR022-tenant-isolation.md), the forwarded-headers table). What protects it is Hetzner's network-level filtering and bex's own per-source caps (w21/070, w21/074). [ADR030 §9](../../../docs/ADR030-pricing.md#9-workspace-plans-gate-renders-plan-features-w8m137-w8m138) lists "Automatic DDoS mitigation" under "Same on every plan", which is true of its plan scope only. ADR018 has no row.

**Do (~45m):**

1. Add an ADR018 row (Platform events & integrations or Custom domains) stating bex's mechanism with pointers, marked ◐ pending the user's decision.
2. Verify Cloudflare's current proxy limits on each plan (response timeout, upload size) and record them in the row.
3. Ask the user to choose: sign the difference off in ADR018, or file a milestone to front tenant hosts with Cloudflare. **The proposal's recommendation, not a user decision:** on Cloudflare plans below Enterprise the proxy ends a response at 100 s and an upload at 100 MB (to be confirmed in step 2), which would break bex's 100-minute request parity ([ADR018 Request duration row](../../../docs/ADR018/services-lifecycle.md), w8/207); so matching Render needs Cloudflare Enterprise or Cloudflare for SaaS, a cost only the user can approve.

**Done when:** ADR018 has the row with evidence, and the decision is either recorded or parked as this note's gate.

## Worked (2026-11-24, `/loopx w21`)

- **Step 1, the row:** [ADR018 Custom domains § Automatic DDoS protection for every tenant host](../../../docs/ADR018/custom-domains.md), ◐ on every column. It records Render's claim and how its hosts sit behind Cloudflare (`hello-world.onrender.com` → `…cdn.cloudflare.net` → Render's `RS-1125` range, `server: cloudflare`), and bex's edge as it is: `*.onbex.co` and DNS-only custom domains resolve straight to the Hetzner load balancer (only `bex.co`, `api.bex.co` and `dashboard.bex.co` go through Cloudflare); Hetzner's free network filtering (reflection, UDP and SYN floods, invalid packets; no application-layer filtering named); one `lb11` in `fsn1`, which the Hetzner API caps at 10,000 connections across its five TCP listeners; Traefik's tenant entrypoints with a 6000 s read and no rate or concurrency limit (ADR022's w8/207 choice); and the per-source caps that sit behind the edge only (static server R25-05, w21/070, w21/074). The divergence is the missing application-layer mitigation in front of tenant hosts.
- **Step 2, Cloudflare's limits (read 2026-11-24), with one correction to this note:** the response timeout is now **125 s**, not 100 s, on Free, Pro and Business; Enterprise raises the Proxy Read Timeout to at most 6000 s, which is exactly Render's 100 minutes. Uploads: 100 MB on Free and Pro, 200 MB on Business, Enterprise 500 MB by default and up to 5 GB self-serve since 2026-09-04. Cloudflare for SaaS is on every plan (100 hostnames included, then $0.10 each a month), but wildcard custom hostnames are Enterprise-only and apex proxying is an Enterprise paid add-on, so a plan below Enterprise would also leave bex's wildcard custom domains (w4/m326) and apex `A` records outside it. The recommendation stands: Render's behavior with bex's 100-minute request parity needs Cloudflare Enterprise (or an Enterprise Cloudflare for SaaS contract).
- **Not changed:** ADR030 §9 (true of plan scope) and the `bex-static-sites` CLI skill's "DDoS protection included" (true of Hetzner's network filtering); the row says how far each holds.

## Parked 2026-11-24 (`/loopx w21`)

- **Gate (the user):** choose one. (a) Sign the divergence off: say so, and a worker records the sign-off, its date and the user's words in the ADR018 row and closes this note. (b) Approve a Cloudflare Enterprise plan, or an Enterprise Cloudflare for SaaS contract, for `onbex.co` and tenant custom hostnames (a sales-quoted cost), and a worker files a milestone that fronts tenant hosts with it: Proxy Read Timeout 6000 s, upload limit at least today's, wildcard hostnames and apex proxying, the client-identity plugin's Cloudflare branch for every host, and the SSH, Postgres and Key Value listeners kept off the proxy.
- **Not a parity-sufficient option without the spend:** proxying `*.onbex.co` on a Cloudflare plan below Enterprise protects HTTP but cuts responses at 125 s and uploads at 100 MB (200 MB on Business), which breaks the Request duration row; that trades one parity row for another.
- **Variants the user may want filed whichever way (a) or (b) goes, none of them parity:** a per-source concurrency cap on Traefik's tenant entrypoints (ADR022 declined one in w8/207 for shared-NAT clients), or a larger load balancer type (`lb21` 20,000 connections, `lb31` 40,000).
