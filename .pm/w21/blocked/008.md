# Document the "Deploy to bex" button in the public docs

Why: the button shipped in w8/163 (2026-10-21) and works live, but the public docs and the agent docs dump never mention it, so a template author cannot discover the URL, the badge asset, or the `path` and `/tree/<branch>` options.

- Verified 2026-11-07: `https://dashboard.bex.co/deploy?repo=<repo>/tree/<branch>&path=<file>` answers 307 to `/blueprints/new` with `repo`, `branch` and `path` prefilled, and `https://dashboard.bex.co/images/deploy-to-bex-button.svg` serves `image/svg+xml`. `rg -i 'deploy-to-bex|deploy to bex'` over the repo finds only `docs/ADR018-render-parity.md`, `docs/ADR049-render-yaml-parity.md`, the dashboard route and asset, and the CLI skill pack's `bex-deploy`/`bex-cli` skills. `https://bex.co/llms-full.txt` has no section for it.
- Add a short section to the public Blueprints guide (`/docs/platform/blueprints`; its source is not in this checkout, so locate it first): the Markdown snippet `[![Deploy to bex](https://dashboard.bex.co/images/deploy-to-bex-button.svg)](https://dashboard.bex.co/deploy?repo=https://github.com/OWNER/REPO)`, the branch rule (default branch unless `repo` ends in `/tree/<branch>`), `path=` for a manifest not named `render.yaml`, that nothing is created until the user approves the preview, and that a private repository needs the GitHub App.
- Mirror one line into the `bex-deploy` skill reference if it is missing there.
- Found while checking whether a self-hosted application (beancount.io's `bex.yaml`) can offer one-click deploy.
