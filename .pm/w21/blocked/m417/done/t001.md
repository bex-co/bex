## Objective

Let a workspace admin publish a bucket and let the gateway ask which bucket a host belongs to.

## Context

- `docs/ADR112-object-storage.md` D4: `PUT …/{b}/domains/managed {enabled}` sets `public` and answers `{bucketId, domain: "pub-<obk-xid>.<BEX_BASE_DOMAIN>", enabled}`; `GET` reads it; `dev-url enable|disable` needs `can_manage`, get needs `can_view`. `BEX_BASE_DOMAIN` already exists.
- The `pub-` prefix is reserved in service-slug validation so a service cannot take a bucket's host. Where slugs are validated (bex-api and the operator) is unverified: search `lego/backend/internal` and `lego/operator` and cover every place.
- objectgw resolves `Host` to a bucket by asking bex-api, so it holds no database credential. ADR112 does not say how objectgw authenticates to bex-api. Reuse an existing service-to-service mechanism (for example the ssh-gateway's shared-key ticket) and add any new credential to the `bex-system/bex-object-storage-read` Secret and `.env.example`; then amend ADR112 D4 and D9 in the same change.
- Scope classes: the public toggle is `write` (ADR112 D6).

## Steps

1. Add the two `dev-url` handlers, the `classifiedOps` entries and the relations.
2. Add the reservation to slug validation and tests for a slug `pub-…`.
3. Add the internal lookup route (host to `{bucket id, region, public, cors}`), authenticated as decided above, with tests that a private or deleted bucket answers not found.
4. Amend ADR112 D4 and D9 with the chosen mechanism.

## Result

`dev-url` is served: `cloudflare_r2_domains.go` answers `PUT|GET …/buckets/{b}/domains/managed` with `{bucketId, domain, enabled}` in Cloudflare's envelope (PUT needs `can_manage`, GET `can_view`; the scope matrix has PUT as write and GET as read, pinned by a test), `10042` where the deployment has no hosting domain, and turning it off never needs one. `internal/objectstorage/publichost` (a leaf) is the one place that knows a bucket's host, `pub-<xid>` for `obk-<xid>`; the real wrangler 4.162.0 runs `dev-url get|enable|disable` in `TestWranglerEndToEnd` and the fixtures were re-recorded. **Decision (objectgw to bex-api):** a static bearer, `BEX_OBJECT_STORAGE_GATEWAY_TOKEN`, on two verbs of bex-api's cluster-internal `:8091` listener (`internal/objectgw/verbs.go`, the shape of the ops-role and identity-claims verbs; never on the public mux, which a test pins). It is not the SSH gateway's `BEX_SANDBOX_EXEC_SECRET`: that secret also signs the agent credential mints, so an internet-facing server must not hold it, and a lookup of public data needs no replay guard (the HMAC verbs spend a database write per request on one). The lookup answers `{bucketId, workspaceId, region, cors}` for a public, live bucket of a served region and the same `404` for everything else, so a private bucket cannot be told from one that never existed. The token is at least 32 characters, mounted only when set; `provision` mints it once and `install` puts it in both Secrets (script test extended), `.env.example`, `lego/backend/AGENTS.md`, ADR019 and ADR112 D4 and D9 amended. **Deviation from the task text, for parity:** the acceptance line "a service slug starting `pub-` is refused" is not what shipped. Render refuses no service name for its host, so refusing every `pub-` name would be a parity divergence (and AGENTS.md says to amend the design then). The slug is minted only in `store.CreateApp` (the operator and the CRD never validate one), where exactly the shape of a bucket host (`pub-` and a 20-character xid) now gets a `-xxxx` suffix, as a taken subdomain does; `pub-site` keeps its slug. Pinned by a Postgres test, and by unit tests of the shape. Real Postgres run: `TestPGAServiceCannotTakeAPublicBucketsHost`.
