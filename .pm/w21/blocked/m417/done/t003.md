## Objective

Apply the bucket's CORS rules and the safety headers, and count every byte out.

## Context

- `docs/ADR112-object-storage.md` D4: `X-Content-Type-Options: nosniff`; the bucket's CORS rules applied by objectgw, including preflight (Wasabi's CORS stays off); a cache; every byte counted (the shadow meter `object_storage_egress_bytes`).
- Public content shares a registrable domain with tenant apps and static sites, so the risk class is the same as ADR103's; objectgw claims no stronger isolation.
- How the counts reach bex: decide here (periodic report to the lookup route's service, or a metrics endpoint bex-api scrapes), record it in ADR112 D4, and keep the credential rule (no config in environment variables).

## Steps

1. Add CORS matching (origin, method, headers, max age, expose headers) and `OPTIONS` preflight.
2. Add `nosniff`, a bounded in-memory cache and the byte counter, and the chosen reporting path.
3. Test allowed, denied and preflight cases and the counter.

## Files

- lego/backend/internal/objectgw/ and tests

## Acceptance criteria

- [ ] An allowed origin gets the CORS headers and a denied one does not.
- [ ] Every response carries `nosniff`.
- [ ] The bytes out of a request are counted exactly.

## Out of scope

- Rate and bandwidth caps (t004).

## Result

`cors.go` applies the first matching rule (`*`, an exact origin or `https://*.example.com`; method; headers), answers a preflight `204` or `403` with no CORS header, sends `Vary: Origin` on every answer of a bucket with rules and never `Access-Control-Allow-Credentials`; every answer carries `X-Content-Type-Options: nosniff`. The cache holds whole objects up to 1 MiB, 64 MiB and 8192 entries per replica for 60 s, filled by a plain GET (at most 32 fills at once), evaluated by `http.ServeContent`, so a hit costs no Wasabi request. **Decision (how counts reach bex):** objectgw counts the object bytes each response sends per workspace, exports `bex_objectgw_response_bytes_total{origin}` and `bex_objectgw_requests_total{result}` on its internal `:9090`, and posts the per-workspace sums every minute (and once after it drains) to the egress verb on `:8091` with the same bearer, which adds them to `object_storage_egress_bytes`; bytes of an error's text are not counted, a failed report is kept for the next, a lost answer can count twice (a shadow meter). Recorded in ADR112 D4 and ADR023. Tests: allowed, denied, wildcard, subdomain-pattern and first-match CORS cases, preflights (allowed, wildcard header rule, denied origin, method and header, a non-preflight OPTIONS, no rules, never reads the object), `nosniff` on 13 kinds of answer, cache hit, expiry, bounds and eviction, and exact byte counts for a miss, a hit, ranges, a stream, a 304, a HEAD, a 404, a 405 and a 416.
