## Objective

Build the read-only gateway binary that serves public bucket objects straight from Wasabi.

## Context

- `docs/ADR112-object-storage.md` D4: GET and HEAD only; `Range` and conditional requests passed to Wasabi; no listing (the root answers 404); a read-only Wasabi identity (`BEX_OBJECT_STORAGE_READ_ACCESS_KEY` and `_SECRET_KEY`); host lookup cached 30 s, misses cached too; a private, deleted or unknown host answers 404.
- Precedent: the static-server (`lego/operator/cmd/staticserver/main.go`, `docs/ADR029-static-sites.md`, `docs/ADR103-security-review-static-rewrite-proxy.md`).
- Keys use the same validation as D7 (reject `..` and its encodings).

## Steps

1. Create `lego/backend/cmd/objectgw/main.go` and `internal/objectgw`: lookup client and cache, handler, Wasabi read with the read-only credential.
2. Return the stored `Content-Type` and `Cache-Control`; answer 405 for other methods; 404 for the root, a private, deleted or unknown host.
3. Test with the fake S3: hit, miss, `Range` 206, conditional 304, HEAD.

## Files

- lego/backend/cmd/objectgw/main.go
- lego/backend/internal/objectgw/ and tests

## Acceptance criteria

- [ ] A public object is served byte-identical, including a `Range` and a conditional request.
- [ ] Private, deleted, unknown, root and `..` keys answer 404; POST answers 405.

## Out of scope

- CORS and caps (t003, t004), deployment (t005).

## Result

`cmd/objectgw` and `internal/objectgw`: the host is checked for the shape of a bucket's before anything is asked, resolved by bex-api (cached 30 s, misses too, concurrent lookups of a host share one call, guessed hosts and renewals of served buckets under separate rate limits, a failed lookup is `503` and never a cached `404`), and the object is read from Wasabi with the read-only identity by signing a one-minute GET or HEAD URL and sending the visitor's `Range` and conditional headers with `net/http` (compression off), so `206`, `304` and `412` are Wasabi's and the bytes are those stored; Wasabi's `412` and `416` XML bodies become a plain line. `If-Range` is not an S3 header, so a request with it gets the whole object. The query is ignored, the root and any key that fails D7 (`.` or `..` after decoding, a leading `/`, a backslash, a control character) is `404`, and POST and the rest are `405` only for a real bucket (an unknown host is `404` whatever the method). With none of the three credentials it stays Ready and answers `503`. Tests with the fake S3 (made to evaluate conditional headers and to type an untyped object as S3 does): byte-identical objects of 0 B to 3 MiB, ranges on both paths, conditionals, HEAD, stored gzip not decoded, no `x-amz` header relayed, private, deleted, unknown, malformed and look-alike hosts, 18 hostile paths that never reach Wasabi, another bucket's prefix, and an origin failure. A mutation run found the cache path's header filter redundant, and it was removed.
