## Objective

Remove `http://localhost:5173` from the production Kratos configuration while keeping it for local development.

## Context

- It sits in production `allowed_return_urls` (the Kratos config under `deploy/gitops/`); a return URL on localhost sends a signed-in browser to whatever listens on the user's own port 5173.

## Steps

1. Find the production and local values (base against the prod overlay) and the test that pins them (`scripts/gitops-validate.sh`).
2. Move localhost to the local overlay only; add a check that fails if production lists it.

## Files

- deploy/gitops/ (Kratos values, base and overlays)
- scripts/gitops-validate.sh

## Acceptance criteria

- [ ] Production lists no localhost return URL, local development still works, and the validation script fails if it returns.

## Out of scope

- Other Kratos settings.

## Blocked (2026-11-14)

**Needs the user's decision:** does the documented "Local dev against prod" workflow (`dashboard/README.md`, the Vite `/kratos` proxy against `auth.bex.co`) stay?

- `deploy/gitops/base/values/kratos.values.yaml` lists `http://localhost:5173` in `allowed_return_urls` for every overlay, with a comment that a redirect to a user's own localhost is harmless; the README says that entry must exist for that workflow to work. The audit's concern is that whatever listens on 5173 receives the browser after a flow.
- **Keep:** record it as accepted (the redirect carries no credential: the session cookie belongs to the auth host), and the task closes with a test that pins the entry as deliberate.
- **Remove:** move the entry to a local-only overlay (`deploy/gitops/overlays/local`) and have `scripts/gitops-validate.sh` fail if the prod or staging render lists a localhost URL. The README's "Local dev against prod" section then has to say to run against a local Kratos, which is a change to how contributors work and is the owner's call.
- Either is about 20 minutes once decided. The other six tasks of this milestone are done and shipped.
