# 124 — A database owner's `pg_restore --exit-on-error` of a bex export into a bex database stops at `COMMENT ON EXTENSION pg_stat_statements`

Why: `TestApplicationDatabaseExtensionsOnCNPG`'s owner export and restore phase (ADR092 D3, property 5 on a real CloudNativePG) has never passed, so the full test cannot be CloudNativePG's CI gate, and an owner restoring their own data meets an error that is not about their data.

**Found by** w21/m606 t003, the first time the test ran on a real CloudNativePG in CI (2026-11-23): `cnpg-operator-qualify.yml` runs [45292792887](https://github.com/bex-co/bex/actions/runs/45292792887) (bex's operator build) and [45292801383](https://github.com/bex-co/bex/actions/runs/45292801383) (the 1.30.1 release), PG18 operand `18.7-postgres-6c11b6b0f6…`, on arm64 and amd64 alike:

```
ordinary-owner complete restore phase0 remains unqualified: exit status 1
pg_restore: error: could not execute query: ERROR:  must be owner of extension pg_stat_statements
```

**Cause (read, not yet reproduced by hand):**

- bex sets `pg_stat_statements.track`, so CloudNativePG creates `pg_stat_statements`, owned by the superuser, in every database that allows connections, `template1` included (`reconcileExtensions` over `datallowconn` databases), and bex's bootstrap `postInitSQL` creates it in the application database. Every database created afterwards copies it from `template1`.
- `bex-postgres-export` (`deploy/pg-operand/dump-snapshot.sh`) dumps with `--no-owner --no-privileges`, which still writes `COMMENT ON EXTENSION pg_stat_statements`. Restored by the database owner into any of those databases, the comment needs ownership of an extension the superuser owns, and `--exit-on-error` (or `bex-postgres-restore`'s single transaction with `ON_ERROR_STOP`) stops there.
- The 2026-08-21 namespace cutover drill saw the same class: "The four `pg_restore` errors were all `COMMENT ON EXTENSION`" ([drill](../../docs/drills/2026-08-21-datastore-namespace-cutover-prep.md)).

**Open question first:** what Render does. Read [Render's backup and restore docs](https://render.com/docs/postgresql-backups) for the owner's restore command and whether a new Render database has `pg_stat_statements` (ADR018's extensions row already lists that as unverified), and choose the fix from that, not from bex's current shape.

**Done when:**

- An owner's export of a database that uses only the owner's own extensions restores into a new bex database with `pg_restore --no-owner --no-privileges --exit-on-error` (or the command Render documents), and through `bex-postgres-restore`.
- `TestApplicationDatabaseExtensionsOnCNPG` passes on kind (`BEX_CNPG_QUALIFY_TEST=TestApplicationDatabaseExtensionsOnCNPG bash scripts/cnpg-operator-qualify.sh`), and `cnpg-operator-qualify.yml` runs it instead of `TestOwnerPgauditAcrossRestartOnCNPG` alone.

## Worked (2026-11-24, `/loopx w21`)

**What Render does.** [postgresql-extensions](https://render.com/docs/postgresql-extensions) (read 2026-11-24) lists `pg_stat_statements` on 13+ with no note; only `plpgsql` is "enabled by default". Render's restore commands ([postgresql-backups](https://render.com/docs/postgresql-backups)) are `pg_restore --clean --if-exists --no-owner --no-privileges` for a dashboard export and `pg_restore --no-owner --no-privileges --jobs=4` for a directory `pg_dump`, without `--exit-on-error`. Render's Top Queries tab ([service-metrics](https://render.com/docs/service-metrics)) and `GET /postgres/{id}/query/top-queries` read `pg_stat_statements` with no step the user takes, and the one report of a Render database's catalog, community thread 12294 (2023-05-23, read through the Internet Archive), answered `extension "pg_stat_statements" already exists`. Whether a new Render database on 13+ has it stays unverified (no Render account here).

**Choice: keep CloudNativePG's preinstall, admit `pg_stat_statements` to the allowlist on every major 13–18.** pgextwlist runs `COMMENT ON EXTENSION` (and `CREATE`, `ALTER … UPDATE`, `DROP`) for an admitted extension as the bootstrap superuser (`pgextwlist.c` v1.20, `T_CommentStmt`), so the dump's comment restores; `CREATE EXTENSION IF NOT EXISTS` stays a no-op. The owner can also drop it and run Render's `CREATE EXTENSION pg_stat_statements;`, which was refused before in a database that lacked it. On-demand (as w21/m586 did for `vector`) was not taken: it would leave Top Queries unavailable on every new database, which Render's does not document. The admission is a reload of `extwlist.extensions`, no restart.

**Changes:** `untrustedContribExtensions` and `matrix.json` (`extensions`, `admitted`) list it; `TestAllowlistIsRendersUntrustedListPerMajor` states it. The gate (`check.sh`) creates it in `template1` as the superuser before any database, as CloudNativePG does, checks Render's command (`already exists`), the owner's read through `pg_monitor`, the refused `pg_stat_statements_reset()`, the owner's drop and create, and judges its owner restore; every extension's owner export is now also restored through `bex-postgres-restore`. `TestApplicationDatabaseExtensionsOnCNPG` runs Render's command after the owner drops CloudNativePG's, and restores the owner's export through `bex-postgres-restore` into a second new database; `cnpg-operator-qualify.yml` (via `scripts/cnpg-operator-qualify.sh`) now runs it. ADR092 D1 § pg_stat_statements, D2, ADR009 § Legacy query-insights convergence, ADR018's extensions row and the operand README record it.

**Evidence (local, arm64 builds of the pinned recipe, 256 MiB, no network):** the gate passed on every major 13–18 with `owner_restore_pg_stat_statements=PASS`, every other extension `PASS` through both restores, and TimescaleDB its only `FAIL` (`permission denied to set parameter "timescaledb.restoring"`, unchanged). With `pg_stat_statements` held out of the list on PG18, all 32 owner restores failed with `must be owner of extension pg_stat_statements`, the production error, and the gate failed. The kind run of `TestApplicationDatabaseExtensionsOnCNPG` is CI's: this machine's container VM reaches neither ghcr.io nor the host, and has 1.7 GB free.
