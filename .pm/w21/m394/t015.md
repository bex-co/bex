## Objective

Make the edge-cache sidecar's memory accounting honest so unique cacheable 404s cannot OOM it, and make it pass Traefik's `X-Forwarded-For` and `X-Forwarded-Proto` through as ADR004 says.

## Context

- Finding R25-06 (Low). `lego/operator/internal/edgecache/edgecache.go:422-437` `store` charges only `len(e.body)` (`:428`): the key, the cloned headers and the structure are free, there is no entry-count bound, and expired entries are removed only in `lookup` (`:256`) when the same key is looked up again; a 404 is cached 3 minutes with no directive (`defaultTTL` `:86`; `requestEligible` `:209-225`). 100K unique `.css` 404s accounted 1.81 MiB and used 72 MiB (756 B/entry); the real binary reached 250 MiB at 250K requests against the 160Mi limit (`lego/operator/internal/controller/edge_cache.go:64-83`: `GOMEMLIMIT` 120MiB, budget 48 MiB). Opt-in (paid web service with `cacheProfile`). ADR004 (`docs/ADR004-app-deployment.md:402`) says the memory is bounded.
- Finding R25-07 (Low). `edgecache.go:171-174`: `Rewrite` strips the inbound `Forwarded`/`X-Forwarded-*` (Go semantics, verified on the pinned toolchain) and `SetXForwarded` sets `X-Forwarded-For` to the Traefik peer and `X-Forwarded-Proto` to `http`; `True-Client-IP` and `X-Real-Ip` survive. Apps that read XFF or the proto header see one client address and `http`. ADR004 says 'identical forwarding headers either way'; the activator's proxy (`hold.go:117-134`) already copies them from the trusted ingress. Safe because Traefik sanitises XFF and only Traefik, same-workspace pods and the activator reach the sidecar (`namespaces.go:725-800`); treat copying `Forwarded` as optional (Traefik's sanitising of it is unverified).
- `TestTheCacheStaysWithinItsByteBound` (`edgecache_test.go:183`) asserts body-only accounting and must be re-based.

## Steps

1. Write the failing tests first in `lego/operator/internal/edgecache/edgecache_test.go`: 5,000 unique tiny-body 404s with `MaxBytes` 1 MiB keep `len(h.entries)` and `h.size` within bounds; empty-body 301s with 7 KB keys have non-zero `h.size`; after the clock passes the TTL a new `store` drops expired entries; `TestForwardedHeadersSurviveTheCache` with a Traefik-shaped request (peer 10.10.0.5, client 198.51.100.77, https): the upstream must see `X-Forwarded-For: 198.51.100.77, 10.10.0.5` and `X-Forwarded-Proto: https`.
2. Charge `len(body)+len(key)+header bytes+a fixed per-entry overhead`; add a `MaxEntries` cap with LRU eviction; reap expired entries from the LRU tail on `store`; re-base `TestTheCacheStaysWithinItsByteBound`.
3. Copy the inbound `X-Forwarded-For` and `X-Forwarded-Proto` into `pr.Out.Header` before `SetXForwarded` (append the peer to XFF).
4. Run the edgecache package tests and `make lint`; run the real binary once with the production settings against a 404 app and record the RSS after 250K requests.
