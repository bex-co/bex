## Objective

Fix each confirmed finding at its root, test first: a regression test that fails on the pre-fix code and passes after.

## Context

- The finding count is unknown at filing, so t003 adds one task per extra confirmed finding ahead of this one; this task carries the first (or records that none was confirmed).
- Gates: `make test` and `make lint` from `lego/operator/`, `cd lego/backend && go test ./...`, and `cd dashboard && yarn lint && yarn test`. A fix that touches a tenant-facing behavior (a response, a header, a status) needs the Render parity check, which `/pm` adds as a task for that case.

## Steps

1. Write the failing test first and watch it fail on the unfixed code.
2. Fix the cause, not the symptom, and re-run the test.
3. Run the affected module's gates.

## Files

- the code and test files each finding names (lego/operator/**, dashboard/**)

## Acceptance criteria

- [ ] Each confirmed finding has a regression test that fails when its fix is reverted.
- [ ] The operator, backend and dashboard gates pass.

## Out of scope

- Findings that need live deployment testing: they stay listed in the ADR.
- Hardening of accepted residuals.
