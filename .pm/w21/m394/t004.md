## Objective

Stop the dashboard from serving its server-rendered page, with the signed-in visitor's Kratos session JSON, under `/assets/**` with `Cache-Control: public, max-age=31536000, immutable`, so a shared cache cannot store one user's page under an attacker-chosen URL.

## Context

- Finding R25-08 (Medium). `dashboard/server/security-headers.ts:84-89` gives `/assets/**` `public, max-age=31536000, immutable`; a path with no built file falls through Nitro's fallthrough public-asset handler to the SSR renderer (`200 text/html`), which embeds the Kratos session (`dashboard/src/routes/__root.tsx:22,72`, `src/common/server-fn/session.ts:127`): email, name, identity id, session id, device IP, user agent, location. Reproduced on a real production bundle with a session cookie; neither response sets a cookie. Whether production's Cloudflare stores a cookie-bearing response is unverified (deployment testing).
- `dashboard/server/plugins/mobile-association-content-type.ts` is the precedent for a Nitro response hook in this directory; `dashboard/server/__tests__/security-headers.test.ts:59-61` asserts the `/assets/**` rule.
- Overlap: w4/m348 t001 (`.pm/w4/m348/t001.md`, open when this was filed) plans the same 404-with-`no-store`. Check its state first: if it has landed, keep only the backstop and the authenticated test here; if not, ship it here and record in m348's README that t001 shipped with w21/m394 t004. m348 t002/t003 (rollout overlap, URL move) stay w4's.

## Steps

1. Write the failing tests first: (a) a response under `/assets/` with `Content-Type: text/html` is replaced by `404` with `Cache-Control: no-store` and carries no page body; (b) any `text/html` response whose `Cache-Control` contains `public` is rewritten to `private, no-store`; (c) a real built file under `/assets/` still answers `public, max-age=31536000, immutable`.
2. Implement both as a Nitro response hook beside `mobile-association-content-type.ts` (or a non-fallthrough `/assets` asset base in `dashboard/vite.config.ts` if that gives the 404 directly), keeping the route rule for real files.
3. Update `dashboard/server/__tests__/security-headers.test.ts` for the rule and add the three tests above.
4. Run the built bundle once as the image runs it (`NODE_ENV=production node .output/server/index.mjs` with a mock Kratos) and record in this task that `/assets/<missing>.css` with a session cookie answers 404 `no-store` with no session fields.
5. Record in the notes for t005 the operator actions this fix does not cover: a Cloudflare bypass-on-cookie rule for the dashboard zone and a one-time purge of `/assets/*` (the deploy token is DNS-only).
