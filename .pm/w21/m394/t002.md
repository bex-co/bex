## Objective

Run the `security-audit` skill over the dashboard's server-side routes, the one tenant-reachable surface the first review of the dashboard's own server code has not named.

## Context

- Server routes: `dashboard/src/routes/{auth.consent,auth.device.index,api.sessions,api.connected-agents,healthz}.tsx`; server code `dashboard/server/security-headers.ts` and `dashboard/server/plugins/mobile-association-content-type.ts`; related helpers `dashboard/src/common/lib/{safe-next,external-url,invite-token,fetch-policy}.ts`.
- None of the 24 review ADRs names `consent`, `api.sessions` or `auth.device` (searched at filing).
- The dashboard authenticates with its Kratos session cookie and is never a Hydra client; consent is at most a headless acceptor (`.pm/DO_NOT_DO.md`: do not OAuth2-ize the dashboard, do not hand-build a Hydra login/consent provider). A finding that would require either is reported as a finding, not fixed by adding one.
- Likely questions, to be confirmed against the code: how `login_challenge`/`consent_challenge`/`next` values are validated before a redirect, whether state-changing server routes check origin or a token, what the SSR fetch to `VITE_SSR_API_URL` can be pointed at, what cookies the session proxy forwards, and what the CSP and framing headers leave open.

## Steps

1. List each server route and handler: method, who can call it (anonymous, a session), what it reads and writes, and what it forwards upstream.
2. Run the skill with target `dashboard/` scoped to those routes and the server directory, output outside the repo.
3. Carry the raw findings into t003; keep the route table for the ADR (t005).

## Files

- (none in the repo; the audit output lives outside it)
- the route table is carried into docs/ADR<next>-security-review-round25.md by t005

## Acceptance criteria

- [ ] Every file under `dashboard/server/` and every `routes/` file that exports a server handler is in the route table with its caller and what it forwards.
- [ ] The run produced a `findings.json` (possibly empty) that validates against the skill's `report-schema.json`.

## Out of scope

- Fixes (t004).
