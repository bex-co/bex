## Objective

Make a host the owner removed from a hibernated or suspended App stop being routed to it, and make a host claimed by two Apps resolve deterministically in favour of the spec.

## Context

- Finding R25-01 (Low). `lego/operator/internal/controller/app_controller.go:3488-3500` `hibernated()` sets only `Status.URL` (and only when hosts is non-empty); `Status.URLs` is written only by `setStatusURLs` (`:3423` Running, `:4826/:4841` static site) and the nil-ing branches (`:3426`, `:3736`, `:5113`); a spec edit while parked reconciles the Ingress (`:2855`) but not status. `lego/operator/cmd/activator/main.go:761-782` `appHosts` indexes `Spec.Host`, `Spec.Hosts`, `Status.URL`, `Status.URLs`; `refreshOnce` (`:829-831`) is last-listed-wins in informer-cache (map) order. A later claimant's non-HTML requests can be woken, held and proxied (Host, Cookie, Authorization, body) to the former holder's app until its first Running pass.
- The claimed bypass of per-App Ingress middlewares for a dropped custom host is REJECTED: a host with no Ingress gets Traefik's 404 (`config/activator/platform-host-fallback-ingress.yaml:30-31` matches `*.onbex.co` only).
- Other readers of `Status.URL(s)` (backend `service.go:1124`, logs `service.go:1143`, `domains.go:509`) only gain correct data from the refresh. Prototype from the validator: refresh in `hibernated()` plus spec-first claims in `refreshOnce` removed all stale hosts and all 200 misroutes; the activator package passed.

## Steps

1. Write the failing tests first: operator: a parked reconcile that drops a host leaves `Status.URLs` without it (use the existing lifecycle fixture; cases: hibernated with host dropped, suspended with host dropped, subdomain policy disabled); activator: a two-App `mapReader` test over 200 index rebuilds asserting the App whose spec claims the host always wins.
2. In `hibernated()` refresh status from `hosts`: `setStatusURLs` when hosts is non-empty, otherwise `URL = internalURL` for addressable types and `""` otherwise, `URLs = nil`.
3. In `refreshOnce` let spec-derived claims beat status-only ones and make duplicate resolution deterministic (stable order).
4. Run `make test` for the operator and `make lint`.

## Result (2026-11-14)

- **Operator.** `app_controller.go`: a new `setServingURLs(app, hosts)` (public hosts through `setStatusURLs`; with none, `internalURL` for an addressable type and `""` otherwise; `URLs = nil`) replaces the if/else in `reportKubernetesRunning` and is what `hibernated()` now calls, so a suspended, auto-hibernated or suspended static-site pass rewrites `Status.URL(s)` from the spec's current hosts instead of only setting `URL` when a host remained. A held background worker, which parks through the same function with no hosts, keeps its empty URL.
- **Activator.** `cmd/activator/main.go`: `appHosts` is split into `specHosts` (spec hosts, plus `EffectiveHosts` when the base domain is known) and `statusHosts`; `refreshOnce` builds its map with the new `hostIndex(items, baseDomain)`: every spec claim is taken first, then status-only hosts fill what is left, and within each tier the oldest App wins, then the lowest namespace/name, so two Apps claiming one host resolve the same way on every rebuild. `appHosts` (the maintenance-page recursion guard) still returns the union.
- **Tests.**
  - `internal/controller/parked_status_urls_test.go`, through the lifecycle fixture: a suspended App with a custom host dropped, with the platform host dropped by `subdomainPolicy: disabled`, with every public host dropped (internal URL, no `URLs`), and an auto-hibernated App after `serveReleaseOne` and `parkIdle`. Before the change all four leave `gone.example.com` (or the platform host) in `Status.URLs`.
  - `cmd/activator/host_index_test.go`: 200 random orderings of a stale-status holder and a spec claimant (the claimant always wins; before the change the answer followed the order, failing at once); a host only status records stays routed; two spec claimants resolve to the oldest, then the lowest name, over 200 shuffles; a deleted App's hosts are not indexed and a platform host is named from the spec.
  - Mutation checks: restoring the old `hibernated()` write fails all four controller cases; the old loop (extracted unchanged as `hostIndex`) failed the claimant and duplicate tests before the fix.
- **Suites.** `make lint` exit 0; `GOWORK=off make test` exit 0, including the full controller envtest suite (328 s) and the activator package.
- **For t005's ADR109.** The rejected half stands: a host with no Ingress gets Traefik's 404, and the platform-host fallback Ingress matches `*.onbex.co` only. The ValidatingAdmissionPolicy for the activator ServiceAccount stays a hardening note.
