## Objective

Inventory every tenant-facing daemon under `lego/operator/cmd/` (who can reach it, what input it parses, what credential it holds) and run the `security-audit` skill over them, keeping the raw output outside the repository.

## Context

- ADR107 § Residuals (Coverage): "a second run should weight the areas this one covered least: the operator and the dashboard's server-side routes" (`docs/ADR107-security-review-round24.md`).
- Across the 24 review ADRs (ADR028 … ADR107) `kv-internal-proxy` and `egress-meter` are named in none; `activator` last appears in ADR028 and ADR066 (round 11); the SNI proxies in ADR028, ADR056, ADR066 and ADR067 (rounds 5, 11 and 12). The static-server rewrite proxy has ADR103.
- Binaries: `lego/operator/cmd/{activator,pg-sni-proxy,kv-sni-proxy,kv-internal-proxy,staticserver,egress-meter,edge-cache,health-probe,drain-guard,native-init,native-resolve,disk-snapshot,backup-encrypt,registry-migrate,manager}`; packages under `lego/operator/internal/` (`sniproxy`, `kvinternalauth`, `staticserver`, `egressmeter`, `edgecache`, `healthprobe`, `drainguard`, `portscan`, `publish`, `httpport`, `imagecheck`, …).
- The skill is `.claude/skills/security-audit/SKILL.md`; its output directory defaults to `~/security-audit-skill/<repo-name>/run-<N>` (ADR107's run was `bex-w5/run-1`), outside the repository, and `findings.json` validates against the skill's `report-schema.json`.
- Accepted residuals, not findings: `.pm/DO_NOT_DO.md` #PSL, #CI-RUNNERS, #RUNNER-HOSTS, #ENV-REVIEWERS, #APPROVAL-MODE.

## Steps

1. For each `lego/operator/cmd/*` binary write one inventory row: listener and port, reachability (a tenant, the internet, in-cluster only), the input it parses, the credentials and RBAC it holds. Mark any binary out of scope with the reason (a one-shot job with no listener, for example).
2. Run the skill with target `lego/operator`, weighting the tenant-facing rows, and an output directory outside the repo.
3. Carry the raw findings list into t003; keep the inventory for the ADR (t005).
