## Objective

Land three one-to-five-line fixes with regression tests: an unbounded read in the pg SNI proxy, a server error on a malformed `lang` query, and per-source connection counting that a single IPv6 /64 can sidestep.

## Context

- R25-13 (hardening). `lego/operator/cmd/pg-sni-proxy/main.go:500` `io.ReadFull(back, resp[:])` has no deadline after the client deadline was cleared (`:471`); a backend that accepts TCP but never answers pins the global, source and route slots even after the client leaves (20 slots still pinned 22.5 s later). Only an infrastructure hang triggers it (a tenant cannot freeze the postmaster); kv has no equivalent window (`kv-sni-proxy/main.go:329-335`). Fix: `back.SetReadDeadline(time.Now().Add(dialTimeout))` before the read; the validator's prototype passed its test.
- R25-15 (informational bug). `dashboard/src/common/lib/search-params/server.ts:6` calls `decodeURIComponent` on a value `URLSearchParams.get` already decoded, so `?lang=%25`, `?lang=%` and `?locale=%25zz` throw `URIError` and the built server answers 500 on any route (not cached; no other effect). Fix: drop the redundant decode.
- R25-12 mitigation 1 (the residual itself is ADR066's and is recorded by t005). `lego/operator/internal/sniproxy/limiter.go:106` keys the per-source cap on the exact `addr.Unmap()`, so 1024 addresses of one IPv6 /64 all pass the per-source cap of 128. Fix: key IPv6 sources on their /64 in `AcquireSource` (about 5 lines).

## Steps

1. Write the failing tests first: pg-sni-proxy: a backend that accepts and never answers the SSLRequest releases its slots within the dial timeout after the client disconnects (port the validator's M1/M2 pair into `cmd/pg-sni-proxy/main_test.go`); dashboard: mock `getRequest` with `?lang=%25` and assert `getSearchParamOnServer("lang")` returns `"%"` instead of throwing; limiter: `TestLimiterPerSourceKeysIPv6OnSlash64` (1024 addresses of one /64 admit 128, today 1024).
2. Apply the three fixes.
3. Run `make test` and `make lint` for the operator and `cd dashboard && yarn lint && yarn test`.

## Result (2026-11-14)

- **R25-13.** `cmd/pg-sni-proxy/main.go`: `handleConn` sets a read deadline of `backendSSLReplyTimeout` (a variable defaulting to `dialTimeout`, 10 s, so a test can shorten it) before reading the backend's one-byte answer to the proxy's SSLRequest, and clears it again once the answer is in, so it cannot cut the spliced session that follows. `TestStalledBackendSSLReplyReleasesTheSlots` (a backend that accepts and never answers; the client sends the SSLRequest and a ClientHello with the route's SNI and then leaves; limiter of 2) fails before the change, with the connection still holding its slots 3 s after the client left, and passes after: `handleConn` returns within the 300 ms test timeout and both global slots are free.
- **R25-15.** `dashboard/src/common/lib/search-params/server.ts` returns `searchParams.get(key)` without a second `decodeURIComponent`. `search-params/__tests__/server.test.ts` (new): `?lang=%25`, `?lang=%`, `?locale=%25zz` and `?lang=%2541` threw `URIError: URI malformed` before and now return `%`, `%`, `%zz` and `%41`; an ordinary value, a UTF-8 value and a missing key are unchanged.
- **R25-12 mitigation.** The /64 collapse is one function for both users: `netutil.SourceKey` (`lego/types/netutil/sourcekey.go`, with its test) returns an IPv4 or IPv4-mapped address as itself and an IPv6 address as its /64 with the zone dropped. `sniproxy.Limiter.AcquireSource` keys on it (`TestLimiterPerSourceKeysIPv6OnSlash64`: 1,024 addresses of one /64 admit 128, as the per-source cap says; before, 1,024; another /64 and an IPv4 source are separate), and the static server's client key from t009 now calls it instead of keeping its own copy (its key for an IPv6 client is the masked address, `2001:db8:1:2::`, in place of the `/64` string; `TestClientKey` follows). The residual itself (a global cap with no source cap before SNI resolution) stays ADR066's, recorded by t005.
- **Suites.** `make lint` and `GOWORK=off make test` (operator), `cd lego/types && go test ./netutil/`, and `cd dashboard && yarn lint` all pass; the ship gate runs the backend suite (types changed) and the dashboard's `yarn lint` and `yarn test`.
