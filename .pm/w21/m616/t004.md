## Objective

Keep egress working when the gateway node goes away, as Render keeps its ranges working, and reset the connections that lose their path, as Render documents.

## Context

- Cilium OSS egress gateway has no built-in failover: one node per policy.
- Hetzner Floating IPs are reassigned through the Hetzner Cloud API; drain-guard (`lego/operator/cmd/drain-guard`, `internal/drainguard`) is the existing pattern for a narrowly granted platform controller.
- Render: "proactively resets affected TCP connections to public destinations" ([outbound-connection-resets](https://render.com/docs/outbound-connection-resets)).

## Steps

1. Implement the reassignment the ADR chose: when the gateway node is NotReady past a bound, deleted, or tainted for deletion, assign its Floating IP to the standby and move the policy's gateway selection.
2. Reset connections that were routed through the lost gateway so clients reconnect at once.
3. Give it its own ServiceAccount and the narrowest Hetzner token scope available; document it in a runbook.

## Files

- the controller (new, beside `lego/operator/cmd/drain-guard`)
- `deploy/gitops/base/` (its Deployment and RBAC)
- `docs/runbooks/` (new runbook)

## Acceptance criteria

- [ ] Deleting the gateway node's pod network or the node itself restores egress from the same address within the ADR's bound, with no person.
- [ ] A long-lived connection through the lost gateway is reset, not left hanging.

## Out of scope

- Multi-gateway load sharing.
