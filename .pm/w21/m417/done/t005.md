## Objective

Ship the gateway like the static-server: same image, its own Deployment, and a documented way to turn it off.

## Context

- `lego/Dockerfile:44-59` builds each binary (the backend module's binaries are built elsewhere in the file; add objectgw the same way). Model the manifests on `lego/operator/config/staticserver/{deployment,service,pdb}.yaml` and `lego/operator/config/prod/kustomization.yaml`.
- `docs/ADR112-object-storage.md` D4: the kill switch is scaling objectgw to zero replicas in GitOps; a stopped host then gets Traefik's no-backend answer, expected 503 and unverified. D9: the read pair comes from `bex-system/bex-object-storage-read`.

## Steps

1. Add the build line and the objectgw manifests (Deployment, Service, PodDisruptionBudget, NetworkPolicy) with the Secret references.
2. Write `docs/runbooks/objectgw-kill-switch.md`: how to scale to zero, what a visitor sees, how to restore.
3. Measure the real answer for a `pub-` host with no replicas once routed (t006) and replace the expectation in ADR112.

## Result

Done by a sub-agent of this run, reviewed here. `lego/Dockerfile` builds `/objectgw`; `lego/operator/config/objectgw/` has the Deployment (two replicas, same image as the manager, hardened like the static-server, no API access, `envFrom` the optional `bex-object-storage-read` Secret so a cluster without it stays Ready and answers 503, readiness on `GET :9090/healthz`), Service, ServiceAccount and PodDisruptionBudget, wired into `config/default`; bex-api gets the optional token variable. No NetworkPolicy was added: the namespace-wide `deny-tenant-ingress` already admits traefik, monitoring and bex-system pods (so objectgw reaches `:8091`), and nothing restricts egress from bex-system. `scripts/gitops-validate.sh` pins the contract in both renders (credentials only, no `BEX_BASE_DOMAIN`, no role binding, the routes, the scrape job). **The kill switch** is one reviewed change: the `bex-objectgw` replicas patch in `lego/operator/config/prod/kustomization.yaml` (Argo CD's self-heal reverts a `kubectl scale`); `docs/runbooks/objectgw-kill-switch.md` names the change, when to use it, what is unaffected (Contract A and B routes), how to restore, and says plainly that the visitor-visible answer at zero replicas (expected `503` from Traefik) is not measured. **Not done, needs production:** the measurement, which stays in t008 and which will replace the expectation in ADR112 and the runbook.
