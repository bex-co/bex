# Billing shows the credit balance as `$1000551.64` (no thousands separators, in en and zh) because four billing-summary amounts bypass the locale-aware `money()` helper the rest of the page uses

Why: a seven-digit money amount with no grouping is hard to read, and the credit balance is the first number a credited workspace checks on the Billing page.

**Severity:** minor (formatting; the amounts themselves are correct). **Estimate:** 25m (four call sites, two message strings in en and zh, one test). **Source:** live `/qa-find-bugs` pass 18, 2026-11-10, production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction. **Status:** inbox.

## Reproduction (read-only)

1. Open `https://dashboard.bex.co/billing?lang=en`, then `?lang=zh`. Collect the dollar amounts in `main` in reading order (`innerText.matchAll(/\$[0-9][0-9.,]*/g)`): `$42.27`, `$8.16`, `$2.79`, `$2.43`, `$0.22`, `$143.61`, `$55.87`, `$0.00`, `$173.45`, `$0.19`, **`$1000551.64`**, `$143.61`, `$0.00`, `$0.00`. The list is identical in both languages.
2. The `$1000551.64` is the Credits remaining card: `TOTAL BALANCE $1000551.64`, followed by "Credits applied −$143.61 → amount due $0.00".
3. Expected shape, from the browser's own formatter in the same session: `new Intl.NumberFormat(l, { style: "currency", currency: "USD", currencyDisplay: "narrowSymbol" }).format(1000551.64)` returns `$1,000,551.64` for `l = "en"` and for `l = "zh"`.
4. Control: the amounts are right and only their formatting differs. The Charges card lines add up (42.27 + 8.16 + 2.79 + 2.43 + 0.22 = 55.87, which is the "Breakdown above: November to date" value), and the totals and projection go through the shared helper.

**Evidence:** the amount list and the `Intl` output above are the durable probes; nothing was created.

## Root cause

`dashboard/src/features/usage/components/billing-summary-cards.tsx` builds four amounts by hand instead of calling `money()` (`dashboard/src/features/usage/lib/charges.ts:42`, which calls `formatMinorUnits`, `dashboard/src/common/lib/format/format-minor-units.ts`: `Intl` currency with `narrowSymbol`):

- `:70` `${credits.availableUsd}`: the backend's raw string (`"1000551.64"`) behind a literal `$`. This is the one observed live with a large value.
- `:75-76` `usd(current.creditsAppliedUsd).toFixed(2)` and `usd(current.amountDueUsd).toFixed(2)`, interpolated into `usage.creditsAppliedLine` ("Credits applied −${applied} → amount due ${due}", `dashboard/src/features/usage/locales/en.ts:476`, zh `:468`).
- `:83` `amount: expiring.remainingUsd` into `usage.creditsExpiryNote` ("${amount} of it expires {date}", `en.ts:103`, zh `:101`).
- `:152` `${usd(inv.amountDueUsd).toFixed(2)}` for each Invoice history row.

`toFixed(2)` never groups, so an amount due or an invoice of $1,234.50 prints as `1234.50`. That gap is traced in code only: this account's due amount and invoices are `$0.00`, and `:83` is not rendered (the grant has no expiry).

## Fix (target behavior)

Every dollar amount on the Billing page is rendered by `money(usd(x), i18n.language)`, so a value of 1,000 or more is grouped (`$1,000,551.64`, `$1,234.50`) in en and zh, and a small value looks as it does today (`$143.61`). The literal `$` is dropped from the two message strings (`creditsAppliedLine`, `creditsExpiryNote`) in en and zh, otherwise the output reads `$$1,000.00`. The "−" sign handling and the trailing `USD` style that the totals use stay as they are. UI only; the API keeps returning plain decimal strings.

## Blast radius (counted by grep on the working tree)

- `money()` has 13 non-test callers already; the four sites above are the only places in `features/usage` that build a total by hand. `charges-card.tsx:92` formats a per-unit rate (`$0.0001/min`), not a total, and is left alone.
- **Look-alikes, same hand-built `$` pattern, cause unverified and not part of this fix** (each is a separate claim because their values rarely reach four digits): the plan price strings `common.pricePerMonth` ("${price}/month", `dashboard/src/common/locales/en.ts:90`) and the "new plan costs ${price}/month" strings (`databases`, `keyvalue`, `services` locales), whose `price` comes from the tier catalog; `dashboard/src/features/agent-automations/components/automation-settings-card.tsx:84` (`$${tpl.maxSpendUSD}`, a user-set spend ceiling that can exceed $1,000); and the Blueprint cost strings in `dashboard/src/features/blueprints/locales/en.ts:381-415`. The agent session spend limit already uses `Intl` (`features/agent-sessions/lib/spend-limit.ts:33`).
- Tests: `usage/components/__tests__` for these cards must keep passing; add the large-value case (below).

## Adjacent classes

Not an authorization matter. A negative or zero amount keeps its current sign handling; a non-USD currency is not served (the backend reports USD strings), so currency choice is unchanged.
