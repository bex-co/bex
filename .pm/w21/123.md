**Issue text (draft):**

> **The instance manager drops an extension the user created when its library is preloaded through `shared_preload_libraries`**
>
> `reconcileExtensions` runs `DROP EXTENSION` for every managed extension (`pgaudit`, `pg_stat_statements`) that is installed while no parameter of its namespace is set. It runs in every database that allows connections, on the first reconciliation after the instance manager starts on the primary.
>
> Reproduce: a Cluster with `spec.postgresql.shared_preload_libraries: [pgaudit]` and no `pgaudit.*` parameter. As a user allowed to create it, run `CREATE EXTENSION pgaudit;` in the application database. Delete the primary pod. When it is back, `SELECT extname FROM pg_extension WHERE extname = 'pgaudit'` returns nothing. The same happens at a failover and at an in-place instance manager upgrade, so with `ENABLE_INSTANCE_MANAGER_INPLACE_UPDATES` an operator upgrade removes it from every cluster.
>
> Setting a `pgaudit.*` parameter avoids the drop but makes the operator create the extension in every database, so a user's `CREATE EXTENSION pgaudit;` then fails with "already exists".
>
> The drop is there because an installed `pgaudit` whose library is no longer preloaded breaks every DDL statement (its event triggers load a library that refuses to load outside `shared_preload_libraries`). A library the cluster lists in `shared_preload_libraries` itself does not have that problem. Proposal: do not drop an unused managed extension when one of its `SharedPreloadLibraries` is in `spec.postgresql.shared_preload_libraries`, and include that in the status that triggers the check, so removing the library from the list still drops the extension. Creation is unchanged. Seen on 1.30.1; `main` and 1.30.2 have the same code.

**Pull request description (draft):**

> Fixes #<issue>.
>
> `reconcileExtensions` no longer drops an unused managed extension whose library the cluster lists in its own `shared_preload_libraries`, so an extension a user created survives a pod restart, a failover and an in-place instance manager upgrade. An extension whose library is no longer preloaded is still dropped, as before.
>
> The status that triggers the check (`extensionStatus`) now records, per extension, whether a parameter uses it and whether the cluster preloads its library (`getExtensionStatus`, compared with `maps.Equal`), so a change to `shared_preload_libraries` runs the check again. The create branch is unchanged.
>
> Tests (Ginkgo with sqlmock): an unused, installed, preloaded extension is not dropped; an unused, installed, not preloaded one is dropped; a used, missing one is created with or without the preload; removing the library from the list changes the status. The first and last fail without the change.
>
> We build 1.30.1 with this change for our own clusters and test it on kind with a pod restart (bex-co/bex, w21/m606).
