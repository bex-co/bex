# 122 — An owner's `CREATE EXTENSION pgaudit` is dropped again by CloudNativePG at the instance manager's next start

Why: on Render an extension stays once its owner creates it. On bex, w21/m585 admits `pgaudit`, but CloudNativePG drops it from every database whenever the instance manager starts on a primary with no `pgaudit.*` parameter set, so it lasts only until the next restart, failover or in-place manager upgrade.

**Source:** w21/m585 t001 (2026-11-23), read from CloudNativePG v1.30.1 and `main` the same day: [ADR092](../../docs/ADR092-postgres-extension-supply.md) D1 § Render's untrusted contrib modules, `pgaudit` row.

## What happens

- `internal/management/controller/instance_controller.go` `reconcileDatabases`: on the first reconcile after the manager starts, `r.extensionStatus` is empty, so `extensionStatusChanged` is true and `reconcileExtensions` runs in every database that allows connections, on the primary only.
- `reconcileExtensions`: for each of `postgres.ManagedExtensions` (`pkg/postgres/configuration.go`: `pgaudit`, `pg_stat_statements`, `auto_explain`, `pg_failover_slots`), `else if !extensionIsUsed && extensionIsInstalled { DROP EXTENSION … }`. "Used" means a key with the `pgaudit.` prefix in `spec.postgresql.parameters`.
- bex sets no `pgaudit.*` parameter: the operator preloads `pgaudit` through `shared_preload_libraries` (`pgExtensionPreloadLibraries`, `database_operand.go`), because any `pgaudit.*` parameter makes the same reconciler run `CREATE EXTENSION pgaudit` in every database, which ADR092 D2 rules out and which would make Render's literal `CREATE EXTENSION pgaudit;` fail with "already exists".
- What is lost is the extension's two event triggers. The owner cannot set `pgaudit.log` (superuser-only), so no audit output is lost, but `pg_extension` no longer lists it and a later `DROP EXTENSION pgaudit` fails.

## Options

1. Upstream: CloudNativePG drops only an extension it created (or offers a per-extension opt-out). An issue or PR to `cloudnative-pg/cloudnative-pg`, then adoption.
2. bex: re-create `pgaudit` after a manager start in each database whose owner had created it. Needs a record of which databases had it, and races the reconciler.
3. Accept the preinstall: project a no-op `pgaudit.*` parameter. Conflicts with ADR092 D2 and Render's `CREATE EXTENSION pgaudit;`.

## Done when

On a real CloudNativePG running a bex operand, an owner creates `pgaudit`, the instance pod restarts, and `pgaudit` is still listed in that database, while a new database still answers Render's `CREATE EXTENSION pgaudit;` without "already exists". `TestApplicationDatabaseExtensionsOnCNPG` covers the restart.
