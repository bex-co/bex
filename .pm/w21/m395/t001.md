## Objective

Add static accessibility rules for JSX to `yarn lint`, choosing a linter that actually runs on this tree's ESLint version, and bring the existing violations to zero or to a documented exception each.

## Context

- `dashboard/eslint.config.js` has only `eslint-plugin-react-hooks` and `eslint-plugin-react-refresh`; no accessibility rule runs today. ESLint is `^10.7.0` (`dashboard/package.json`).
- At filing (2026-11-14): `eslint-plugin-jsx-a11y` 6.10.2, last published 2024-10, lists peer `eslint` only up to `^9`; `eslint-plugin-jsx-a11y-x` 0.2.0 lists `^9.0.0 || ^10.0.0`; `oxlint` 1.93.0 (published 2026-11) ships jsx-a11y rules. None of them was run against this tree.
- The board holds about 47 notes on missing or wrong accessible names, 26 on `aria-invalid`, 16 on contrast (w21/017, 018, 019, 025, 027, 052; w4/466, 607, 612), each fixed one file at a time.

## Steps

1. Spike the candidates on the tree: violation count by rule, false positives, and whether each runs on ESLint 10 without a peer override.
2. Pick one. Prefer an ESLint flat-config plugin that runs unmodified; otherwise run oxlint limited to the jsx-a11y rules from `yarn lint`.
3. Fix each violation, or disable it on its line with a one-line reason; make a new violation fail `yarn lint`.
4. Record the choice and the spike numbers in `dashboard/AGENTS.md`. If no maintained linter runs here, record that evidence instead and let t002 and t003 carry the milestone.

- [ ] `yarn lint` passes on the tree, and each per-line exception carries a reason.
