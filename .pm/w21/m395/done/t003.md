## Objective

Add a test that computes the WCAG contrast ratio of the text and background colour pairs the dashboard actually uses, in the light and the dark theme, and fails below the AA threshold.

## Context

- Tokens are `oklch(...)` custom properties in `dashboard/src/style.css`: the light set under `:root` (about line 21: `--background`, `--foreground`, `--card`, `--primary`, `--primary-foreground`, `--muted-foreground`, `--accent`, `--destructive`, `--border`) and the dark set (about line 315).
- w21/019 found log instance ids, the 404 chip, the project health line, the Partial data label and the success badge under 4.5:1 in the light theme; no guard exists, so any new colour can reintroduce it.
- Thresholds: 4.5:1 for normal text, 3:1 for large text and UI component boundaries (WCAG 2.1 AA).

## Steps

1. Write an oklch → sRGB → relative-luminance converter in the test and self-test it on known values (black on white is 21:1).
2. Declare the pairs explicitly: foreground on background, card-foreground on card, muted-foreground on background and on card, primary-foreground on primary, accent-foreground on accent, destructive text on background, and the status colours the w21/019 components use (read their classes to find the tokens).
3. Assert each pair in both themes; a pair that names a token the stylesheet no longer defines fails the test.
4. List the pairs that fail today for t004.

## Files

- dashboard/src/test/**tests**/theme-contrast.test.ts
- dashboard/src/style.css (read only unless t004 changes a token)

## Acceptance criteria

- [x] The converter's self-test passes on known values.
- [x] Lowering a token's lightness below the threshold fails the test in the matching theme.
- [x] Pairs that fail today are listed in the milestone README.

## Out of scope

- Redesigning the palette (t004 changes a token only to reach the threshold).
- Non-token colours inside charts.

## Result (2026-11-14)

- **Test:** `dashboard/src/test/__tests__/theme-contrast.test.ts`. It parses the `:root` and `.dark` token blocks of `src/style.css` (the dark theme is the light tokens overridden by `.dark`) and Tailwind's palette from `node_modules/tailwindcss/theme.css`, converts `oklch()` to sRGB (out of gamut clipped), blends a translucent colour over its page in sRGB as CSS does, and computes WCAG relative luminance and contrast.
- **Pairs (19 token pairs, per theme):** `foreground` on `background` and `card`; `card-foreground` on `card`; `popover-foreground`, `secondary-foreground`, `accent-foreground`, `primary-foreground`, `sidebar-*` on their backgrounds; `muted-foreground` on `background`, `card` and `muted`; `destructive` and `primary` as text on `background` and `card` (4.5:1); `ring` on `background` and `card` (3:1, the focus indicator, WCAG 1.4.11); plus the log line's timestamp and instance id on the log viewport (`bg-muted/30`). **Status colours (8):** the log 2xx, 3xx, 4xx and 5xx chips (a `-500` tint at 15% over the viewport, light and dark text), the project card health line, the billing Partial data label, the success badge, and the notifications "bex extension" chip (`text-primary` on `bg-primary/10`, the at-the-limit case in w21/019 note 6). For each status entry the test also checks that the component source still contains the classes the table assumes, so a colour change there comes back to this table.
- **Self-tests:** known values (black on white 21:1, sRGB red on white 4.0:1, a mid grey in the 4.4 to 4.9 band; a half-transparent black over white blends to 0.5); lowering `--muted-foreground` in the light theme adds failures only in the light theme and names that token, and dimming it in the dark theme adds failures only in the dark theme; a pair naming a token the stylesheet no longer defines throws.
- **First run, before any change: one pair fails.** Light theme, the **log 2xx chip** (`text-green-700` on `bg-green-500/15` over the log viewport): **3.98:1**, needs 4.5:1 (4.32:1 even on a white page; checked independently with a second implementation). w21/019 recorded the 2xx chip as passing; its other fixes (404 chip, health line, Partial data, success badge, instance id) hold. Every token pair passes in both themes, and so does the "bex extension" chip.
- **Fixed in t004:** `text-green-800` for the light 2xx chip (`log-line-list.tsx`); the dark text and every other pair are unchanged. Not covered, and not claimed: the ANSI colour palette in `features/logs/lib/ansi.ts` (e.g. `text-green-700` on the viewport has the same ratio as the chip had) and the palette-class colours outside the eight entries; a new colour there is not caught until it is added to the table.
