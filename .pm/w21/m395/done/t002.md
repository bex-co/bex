## Objective

Add an `axe-core` pass to the page-level test sweep, so a dialog with no name, a control with no label or an accessible name that drops the visible text fails the test that rendered it.

## Context

- `dashboard/src/test/route-hydration-sweep.ts` (w21/m337) is registered in `dashboard/vitest.config.ts` `setupFiles` and runs after each page-level test's assertions on the first tree it rendered, with an `EXEMPT` table of fixtures that give a reason, and `PAIRS` that vary language (English and Chinese). The a11y pass can follow the same shape.
- `axe-core` is 4.14.0 and is not a dependency yet. `vitest-axe` is 0.1.0 and old; call `axe-core` directly.
- jsdom has no layout or computed colour, so `color-contrast` is switched off here (t003 covers it) as is any rule that needs layout. axe's experimental `label-content-name-mismatch` rule (WCAG 2.5.3, the w4/612 shape) is disabled by default: enable it if it runs under jsdom.
- Shapes to reproduce in self-tests: w4/607 (a Radix popover with `role="dialog"` and no name) and w4/612 (a link whose `aria-label` replaces its visible text).

## Steps

1. Add `axe-core` as a dev dependency and a helper `src/test/axe.ts` that runs it on a container with the rules above and formats violations as readable test failures.
2. Call it from the sweep (or a sibling setup file) on the same first tree, after the assertions pass, in both languages.
3. Self-tests in `src/test/__tests__/`: an unnamed dialog and a mismatched link name fail; the named forms pass.
4. Run the sweep over the suite; list what it finds (feeds t004) and put any fixture the pass cannot judge on an exempt table with a reason.

## Result (2026-11-14)

- **What shipped.** `axe-core` 4.14.0 (devDependency); `dashboard/src/test/axe.ts` (`a11yViolations`: 35 axe rules by name, plus a label-in-name check); the pass in `src/test/route-hydration-sweep.ts`, which already renders the first tree of every route test, `*page*` test and `automation-form` test; `src/test/__tests__/axe.test.tsx` (self-tests). `hydrateAcrossEnvironments` takes an optional `inspect(container)`.
- **How it runs.** Each swept test's tree is hydrated in the browser environment of its hydration pair (English or Chinese, by test name, as before) and in the other pair (the other language), and `document.body.innerHTML` is copied while mounted, so a dialog in a Radix portal is included. After both trees are gone the copies are checked with axe, in both languages, and any violation fails the test that rendered the page with the rule, its help text, the selector and the markup. The check runs on the copy, not on the mounted tree: the first version ran axe inside the mounted tree, and its yielding to the event loop under an open Radix modal left that modal's `pointer-events: none` on the page, which failed the next test in `routes/__tests__/index.test.tsx` (found by running the suite; bisected to the `inspect` call).
- **Rules.** Structural: every `aria-*` name rule (dialog, command, input, meter, progressbar, toggle, tooltip, treeitem), `button-name`, `link-name`, `image-alt`, `input-button-name`, `input-image-alt`, `label`, `select-name`, `svg-img-alt`, `role-img-alt`, `frame-title`, `summary-name`, `empty-heading`, `form-field-multiple-labels`, `aria-allowed-attr`, `aria-allowed-role`, `aria-roles`, `aria-required-*`, `aria-valid-attr`, `aria-valid-attr-value`, `aria-hidden-focus`, `duplicate-id-aria`, `list`, `listitem`, `nested-interactive`, `tabindex`. Not run: `color-contrast` (jsdom has no computed colour; t003), the page-level landmark and heading rules (fixtures are fragments), and axe's experimental `label-content-name-mismatch`, which ends `incomplete` without layout. WCAG 2.5.3 is `labelInNameViolations`: a link, button, tab, menu item, checkbox, radio or switch whose `aria-label` omits the text it shows (text with no letter or digit, an icon glyph, names nothing; `aria-hidden` text is skipped; comboboxes and listboxes are skipped, since they show a value and the label names the field). The one axe finding dropped by design is `aria-hidden-focus` on Radix's `data-aria-hidden` wrappers, which hide the page behind an open modal while trapping focus.
- **Self-tests** (`axe.test.tsx`, 6): an unnamed `role="dialog"` fails (w4/607) and passes once named; a link whose `aria-label` replaces its visible text fails (w4/612) and passes when the label contains it, as does an icon-only `×` button; an unnamed button, an image with no `alt` and an unlabelled field fail; Chinese text is compared the same way. End to end: a temporary page-level test with an unnamed dialog and a mismatched link failed in both languages with the readable report above, then was deleted.
- **First sweep, before the fixes: 322 failing tests in 16 files, 53 distinct violations** (`label-in-name` 188 hits, `link-name` 16, `aria-valid-attr-value` 6, `aria-hidden-focus` 4, `empty-heading` 4). They sorted into four causes, none of them a pass that proves nothing:
  1. **Two false positives in my own check** (fixed in `axe.ts`): Radix `Select` triggers (`role="combobox"` with the field's name and the value shown) and the modal `aria-hidden` wrappers.
  2. **Two test fixtures** (`automations-page.test.tsx`, `detail-and-form-pages.test.tsx`) mocked `Link` without passing `aria-label` through, so the real "back" link looked unnamed; the mocks now pass every prop, as the real `Link` does.
  3. **Real: the top bar's Search button** shows "Search" and a `Ctrl K` hint but is named "Search" (WCAG 2.5.3), on every page with the layout: the hint is `aria-hidden` and the button has `aria-keyshortcuts` (`Meta+K` or `Control+K`), in `global-search.tsx`.
  4. **Real: the automations pages**: the scope tabs (list page and its skeleton) carried an `aria-controls` to a panel that is not a Tabs panel, which is invalid ARIA (removed, with a comment); and the detail skeleton's `<h1>` held only a skeleton bar, an empty heading, so it now carries a screen-reader-only `common.loading` beside the bar (no visible change, same geometry).
- **After the fixes: no violations; every swept fixture passes in both languages and the exempt table (`A11Y_EXEMPT`) is empty.** `yarn test` 693 files, 7,374 tests pass, `yarn lint` exit 0.
- **`yarn test` time:** 109.7 s wall (tests 412 s, setup 289 s summed over workers) against 90.3 s (tests 294 s, setup 239 s) for the suite without the pass, measured on this machine on the same day; the w21/m337 baseline was about 80 s. About +20 s wall.
