## Objective

Add an `axe-core` pass to the page-level test sweep, so a dialog with no name, a control with no label or an accessible name that drops the visible text fails the test that rendered it.

## Context

- `dashboard/src/test/route-hydration-sweep.ts` (w21/m337) is registered in `dashboard/vitest.config.ts` `setupFiles` and runs after each page-level test's assertions on the first tree it rendered, with an `EXEMPT` table of fixtures that give a reason, and `PAIRS` that vary language (English and Chinese). The a11y pass can follow the same shape.
- `axe-core` is 4.14.0 and is not a dependency yet. `vitest-axe` is 0.1.0 and old; call `axe-core` directly.
- jsdom has no layout or computed colour, so `color-contrast` is switched off here (t003 covers it) as is any rule that needs layout. axe's experimental `label-content-name-mismatch` rule (WCAG 2.5.3, the w4/612 shape) is disabled by default: enable it if it runs under jsdom.
- Shapes to reproduce in self-tests: w4/607 (a Radix popover with `role="dialog"` and no name) and w4/612 (a link whose `aria-label` replaces its visible text).

## Steps

1. Add `axe-core` as a dev dependency and a helper `src/test/axe.ts` that runs it on a container with the rules above and formats violations as readable test failures.
2. Call it from the sweep (or a sibling setup file) on the same first tree, after the assertions pass, in both languages.
3. Self-tests in `src/test/__tests__/`: an unnamed dialog and a mismatched link name fail; the named forms pass.
4. Run the sweep over the suite; list what it finds (feeds t004) and put any fixture the pass cannot judge on an exempt table with a reason.
