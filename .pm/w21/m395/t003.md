## Objective

Add a test that computes the WCAG contrast ratio of the text and background colour pairs the dashboard actually uses, in the light and the dark theme, and fails below the AA threshold.

## Context

- Tokens are `oklch(...)` custom properties in `dashboard/src/style.css`: the light set under `:root` (about line 21: `--background`, `--foreground`, `--card`, `--primary`, `--primary-foreground`, `--muted-foreground`, `--accent`, `--destructive`, `--border`) and the dark set (about line 315).
- w21/019 found log instance ids, the 404 chip, the project health line, the Partial data label and the success badge under 4.5:1 in the light theme; no guard exists, so any new colour can reintroduce it.
- Thresholds: 4.5:1 for normal text, 3:1 for large text and UI component boundaries (WCAG 2.1 AA).

## Steps

1. Write an oklch → sRGB → relative-luminance converter in the test and self-test it on known values (black on white is 21:1).
2. Declare the pairs explicitly: foreground on background, card-foreground on card, muted-foreground on background and on card, primary-foreground on primary, accent-foreground on accent, destructive text on background, and the status colours the w21/019 components use (read their classes to find the tokens).
3. Assert each pair in both themes; a pair that names a token the stylesheet no longer defines fails the test.
4. List the pairs that fail today for t004.

## Files

## Acceptance criteria

- [ ] The converter's self-test passes on known values.
- [ ] Lowering a token's lightness below the threshold fails the test in the matching theme.
- [ ] Pairs that fail today are listed in the milestone README.

## Out of scope

- Redesigning the palette (t004 changes a token only to reach the threshold).
- Non-token colours inside charts.
