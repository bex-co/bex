# The global + New menu words its webhook entry "Create a new webhook" / "创建新 Webhook" while every other entry reads "New …" / "新建…", because it reuses the create page's heading key

Why: the + New menu is on every page and its six entries read as one list, so a different verb for the last entry looks like a different kind of action.

**Severity:** minor (copy consistency). **Estimate:** 10m (one new menu label key in en and zh, one line in the menu, one test). **Source:** live `/qa-find-bugs` pass 24, 2026-11-10, production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction. **Status:** inbox.

## Reproduction (read-only)

1. Open any page and click "New" in the top bar. `page.getByRole('menuitem').allInnerTexts()` returns, in `?lang=en`: `["New Service", "New Postgres", "New Key Value", "New Blueprint Instance", "New Project", "Create a new webhook"]`.
2. In `?lang=zh`: `["新建服务", "新建 Postgres 数据库", "新建键值存储", "新建蓝图实例", "新建项目", "创建新 Webhook"]`. Five entries use 新建, the last uses 创建新.

**Evidence:** the two arrays above are the durable probe; nothing was created.

## Root cause

`dashboard/src/common/components/dashboard-layout/new-resource-menu.tsx:48` renders `t("webhooks.newTitle")`. That message is the create page's heading ("Create a new webhook", `dashboard/src/features/webhooks/locales/en.ts:778-779`, whose description reads "Create page heading (Render: 'Create a new Webhook')"; zh `locales/zh.ts:766` "创建新 Webhook"). The other five entries use their feature's `createTitle` key, each already a "New …" label: `services.createTitle` "New Service", `databases.createTitle` "New Postgres", `keyvalue.createTitle` "New Key Value", `blueprints.createTitle` "New Blueprint Instance", `projects.createTitle` "New Project".

`webhooks.newTitle` has 4 other users that are correct as a page heading and must keep it: the page `<h1>` (`dashboard/src/routes/webhooks_.new.tsx:119`), the document title (`:40`), the breadcrumb label (`dashboard/src/common/components/dashboard-layout/dashboard-breadcrumbs.tsx:513`) and the document-head test (`dashboard/src/common/lib/document-head/__tests__/route-heads.test.ts:195-196`).

## Fix (target behavior)

Add a menu label for the entry, "New Webhook" in en and "新建 Webhook" in zh (the other entries' wording), and use it at `new-resource-menu.tsx:48` only. The page heading, document title and breadcrumb keep "Create a new webhook" ("Create a new Webhook" is Render's page heading, per the key's own description). UI only.
