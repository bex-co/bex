## Objective

Give the edge-cache sidecar the server limits it can have without cutting a legitimate stream: an idle timeout and a header-size bound, and record why a write timeout and a whole-request read timeout are not set.

## Context

- `lego/operator/cmd/edge-cache/main.go` builds `http.Server{ReadHeaderTimeout: 10s}` and nothing else, so an idle keep-alive connection is held forever and a client may trickle a body without limit.
- A `WriteTimeout` ends a response that streams past it (server-sent events, long-poll), and a `ReadTimeout` ends a slow but legitimate upload to the origin; `cmd/staticserver/main.go` sets both because it serves files only.

## Steps

1. Read what the sidecar proxies and caches (`internal/edgecache`) to confirm which responses stream.
2. Add `IdleTimeout` (the value `staticserver` uses is the reference) and `MaxHeaderBytes` through a `newServer` function like `cmd/staticserver/main.go` has, with a test on the returned fields.
3. If a body-read bound is wanted, set it per request with `http.ResponseController` only when the request is not an upgrade or a stream; otherwise record it as accepted.
