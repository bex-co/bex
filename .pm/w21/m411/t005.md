## Objective

Run both with production defaults: info level, JSON, stack traces only on error, sampling on, and no `DPanic` panic.

## Context

- `cmd/manager/main.go:161` sets `zap.Options{Development: true}` (the kubebuilder scaffold default) and `cmd/staticserver/main.go:82` calls `zap.UseDevMode(true)`: debug level, console encoder, stack traces at warn, no sampling, and a `DPanic` call panics.
- The activator and the SNI proxies already use `zap.New()`; the flags `--zap-devel`, `--zap-log-level` still override for a developer.
- Check nothing parses the console format (log-based alerts, runbooks, tests) before changing the encoder.

## Steps

1. Search alert rules, runbooks and tests for strings that assume the dev-mode line shape.
2. Move the options into a small function in each `main` package and test that `Development` is false by default and a flag still turns it on.
3. Note the log format change in `lego/operator/AGENTS.md`.
