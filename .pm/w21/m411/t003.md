## Objective

Stop the singleflight leader's cancellation (its client went away) from answering every waiter 502.

## Context

- `internal/staticserver/staticserver.go` `get` runs the origin fetch inside `h.group.Do` with the leader's own `ctx`; when that client disconnects, `origin.Get` returns `context.Canceled` and every coalesced waiter gets it as a 502 "origin error" (line 503).
- The fetch needs a bound of its own once it no longer follows its leader: nothing but the request context limits `S3Origin.Get` today.

## Steps

1. Red-first test in `concurrency_test.go`: two requests for one missing key, cancel the first while the origin blocks, release it, and the second must get 200 (and the origin is asked once).
2. Run the shared fetch on `context.WithoutCancel(ctx)` with a timeout, and wait per caller with `DoChan` and a `select` on the caller's own `ctx.Done()`, so a cancelled caller leaves and the fetch continues for the others.
3. Keep the admission slot and the per-client count tied to the fetch, released when it ends.
