# 078 — Repair the broken links in the other workstreams' README.md files and have the link gate read them

Why: `scripts/docs-links-validate.sh` (w21/m397) does not read `.pm/wN/README.md`, because 130 of their links are already dead and repairing another workstream's index was outside that milestone. These READMEs are the board's own index, so a `/pm` move breaks them first, and the `/pm` skill already says to rewrite links there. Until the gate reads them that rule is only a convention.

- **Source:** w21/m397 t005 simplify review (the gate's scope claimed more than it checked), 2026-11-14. Measured the same day with the final parser, widened to `.pm/w*/README.md`: 134 broken relative links in 8 files, 4 of them in `.pm/w21/README.md` (repaired in the m397 commit), leaving 130:

  - By cause: about 94 point into `evidence/` directories purged on 2026-11-04, about 29 point at items that moved to `done/` or `blocked/`, and 7 at something else.
- **Size:** about 75m.

## Steps

1. Re-measure: copy `scripts/docs-links-validate.sh`, widen `in_scope` to also accept `.pm/wN/README.md`, and list the failures by file.
2. Repair by cause, as m397 t002 did for `docs/`: a moved item gets its new relative path (`done/` or `blocked/`), a purged evidence file becomes plain text that says `evidence, purged 2026-11-04` and keeps the conclusion the line already states, and a link with no successor keeps its id as plain text.
3. Other workers edit these READMEs while they run, so re-read each file immediately before writing it, change only the links, and commit the repair on its own (`docs(pm): …`).
4. Widen the gate: accept `.pm/wN/README.md` in `in_scope`, add a fixture case to `scripts/docs-links-validate.test.sh` (a broken link in a workstream README is red, one in a milestone README under `wN/` is still not read), and drop the sentences saying the gate does not read them from `.pm/AGENTS.md` and the `/pm` skill.
