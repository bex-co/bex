## Objective

`bex s3 sync ./site s3://photos/site` copies what is missing or changed and nothing else, in both directions and between prefixes.

## Context

- ADR112 D3 (the verbs). This is the one piece of real logic the SDK does not supply: it has no listing diff and no delete.
- Both sides are listed in key order and merged in one pass with memory bounded by a page (a tree of a million keys must not be held in memory). For each key: only on the source, or different in size, or older on the destination (by modification time), means copy; only on the destination means delete when `--delete` is given. `--size-only` compares sizes alone. `--include` and `--exclude` filter both sides the same way. `--dryrun` prints what would happen and makes no change.
- A downloaded file gets the object's `LastModified` as its modification time, so a second sync of the same tree copies nothing. Regular files only: a symlink, a device or a socket is skipped with one warning line each.
- Directions: local to prefix, prefix to local, prefix to prefix (through `CopyObject`, one workspace and region). Output: one line per action in the `cp` format, and with `--delete` a `delete:` line.

## Steps

1. Add the merge, the comparison and the three directions on top of t003's transfer.
2. A decision table test (missing, same, size differs, source newer, destination newer, destination only with and without `--delete`) and a property-style test that sync of a tree twice makes zero requests the second time.

## Files

## Acceptance criteria

- [x] Syncing a tree up, then again, copies zero objects the second time; `--delete` removes exactly the extra keys; `--dryrun` makes no write.
- [x] The merge holds at most two listing pages of each side in memory (asserted with a counting fake).

## Out of scope

- Watching a directory for changes.

## Result

Shipped 2026-11-20 with `sync.go`. Both sides are read in key order and merged in one pass (`merge`): a local walk that sorts a directory as its name and a slash (`walkLocal`, asserted equal to key order) against a paginated listing (`listSource`: one page of at most 1,000 entries, the next fetched only when the last is used up, asserted exactly by a counting fake) or two listings. The rule is the one of the task: copy when missing, different in size, or (unless `--size-only`) newer in the source by whole seconds; `--delete` removes what only the destination has (remote deletes in batches of 1,000); `--include`/`--exclude` filter both sides alike so an excluded path is never deleted; `--dryrun` prints the plan and writes nothing; downloaded files get the object's time. Non-regular files are skipped with one warning each; a directory that cannot be read stops the sync before any delete.

- Tests: the decision table (missing, same, size differs, source newer, destination newer, same second, destination only with and without `--delete`, `--size-only`), the merge reads one entry ahead per side, the listing holds one page, a tree synced up, down and prefix to prefix copies nothing the second time (zero writes at the fake), `--delete` removes exactly the extras, an unreadable directory deletes nothing.
