## Objective

A customer copies a file or a tree to and from a bucket, and between buckets, with multipart, concurrency and progress.

## Context

- ADR112 D3 (the verbs) and the server's limits (D3's concurrency bullet): 16 streams per workspace on each replica, 5 GiB per object, 5 GiB for `CopyObject`, parts of at least 5 MiB. The earlier launcher's stock client ran 10 requests at a time and the production walk did 16 streams of 256 MiB; this client defaults to 8 (`--concurrency`, at most 10) so a second command in the same workspace is not refused with `SlowDown`.
- Upload and download use `feature/s3/manager` (`Uploader` and `Downloader`): 8 MiB parts, the part size grown so an object fits in 10,000 parts, concurrency from the flag. Wasabi's own part limits were not read (ADR112 § Not verified): keep the 10,000-part bound and record what the walk shows.
- `cp <local> s3://b/k`, `cp s3://b/k <local>`, `cp s3://b/k s3://b2/k2` through `CopyObject` (one workspace and one region; the server refuses others and the message passes through; an object over 5 GiB is refused before any request with the cap in the message). `-` is stdin or stdout (`cp - s3://b/k` is a multipart upload from a stream of unknown size). `--recursive`, `--include`, `--exclude`, `--content-type`, `--metadata k=v`, `--dryrun`, `--no-progress`. A download writes a temporary file beside the target and renames it, so a failed transfer leaves no half file. `mv` is `cp` and then a delete, and the delete runs only after the copy succeeded.
- Metadata names are lowercase on the wire since w21/113; a test pins that `--metadata Mtime=1` reads back as `mtime`.
- Output lines: `upload: ./a to s3://b/a`, `download: s3://b/a to ./a`, `copy: s3://b/a to s3://b2/a`, `move:` for `mv`; the progress line goes to stderr and is on only for a terminal.

## Steps

1. Implement the three directions and the recursive walk with a bounded worker pool (`--concurrency` bounds files in flight times parts per file so the total stays within the flag).
2. Tests: a 20 MiB upload is multipart with the right part count, a download with a failing middle part leaves no file, stdin upload, `--dryrun` makes no request, a `mv` whose copy fails deletes nothing.

## Acceptance criteria

- [x] Round trips of 0 B, 1 B and 20 MiB are byte-identical by sha256 against the fake S3; the number of in-flight requests never exceeds `--concurrency`.
- [x] No command leaves a partial local file after a failure, and `mv` never deletes a source whose copy failed.

## Out of scope

- `sync` (t004); `cors`, `lifecycle` (t005).

## Result

Shipped 2026-11-20 with `cp.go`, `transfer.go` and `multipart.go`. `cp` and `mv` (one implementation, `mv` deletes each source only after its own copy succeeded, per file) cover a file or tree to a prefix, an object or prefix to a path, and object to object by `CopyObject` (a percent-encoded copy source; a copy that sets headers uses `REPLACE` and keeps the old type), `-` for standard input and output, `--recursive`, `--include`, `--exclude`, `--content-type`, `--metadata k=v`, `--dryrun`, `--no-progress`, `--concurrency`. Uploads and downloads go through the SDK managers in 8 MiB parts (`partSizeFor` grows the part in whole MiB to stay under 10,000); a download goes to `.name.bex-<random>` beside its target and is renamed when whole, gets the object's time as its modification time, and is removed on any error or interrupt (the command's context is cancelled by Ctrl-C). A file over 5 GiB is refused before any request. Names that would leave the destination directory (`..`) are skipped with a warning; folder-marker keys make a directory.

- Acceptance at the fake S3 (TLS, path style, checksum trailer decoded): 0 B, 1 B and 20 MiB round trips are byte-identical by sha256, the 20 MiB object is a multipart upload of three parts, the peak of requests in flight never exceeds `--concurrency` (1, 3, 10 and a download at 2), a download whose middle part fails leaves no file and keeps the older one, a `mv` whose copy fails (bucket to bucket, local to bucket, bucket to local) removes nothing, `--metadata Mtime=1` is stored and read back as `mtime`, and `--dryrun` sends no write.
