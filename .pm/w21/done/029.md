# Postgres recover: the backend accepts a `targetTime` before the earliest restore point or in the future (second layer of w21/020)

Why: w21/020 fixed the dashboard picker (local-time conversion + `min`/`max`), but REST, GraphQL and MCP callers can still send any RFC3339 instant and provision a paid restore database that cannot bootstrap.

**Severity:** minor (API/MCP callers only; the dashboard now refuses it). **Estimate:** 45m, backend only. **Source:** split out of w21/020 item 3 on 2026-11-10 (parity-sufficient dashboard part shipped first). **Status:** inbox.

## Change

`lego/backend/internal/postgres/recovery.go` `Service.Recover`: after `window.established()` (≈ line 268) and before any billing gate, refuse a non-empty `targetTime` that is before `window.earliest` or after now with a named `core.ErrBadRequest` (400). The upper bound is now, not the latest base backup: PITR is WAL-based (ADR009 `:206`). All callers share it: REST `POST …/recover` and `POST …/recovery`, GraphQL `recoverDatabase`, MCP `recover_postgres`.

## Check before landing

Existing tests pass `TargetTime: "2026-07-09T10:00:00Z"` (`advanced_test.go:298,985,1051,1071,1088`, `m68_recovery_gates_test.go:138`) against fixture windows: move each fixture's window around the target (or the target inside the window). The malformed-string 400 (`advanced_test.go:347`) is unchanged.

## Definition of done

- A `targetTime` before the earliest restore point and one in the future each answer a named 400 and create no Database; an in-window target still answers 201; GraphQL and MCP return the same refusal.
- `cd lego/backend && go test ./...` (real Postgres + OpenFGA) passes.
