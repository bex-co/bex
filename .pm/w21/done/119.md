# The CLI test helpers drop the runner's `CI` and terminal environment in one place

Why: `withoutRenderEnv` strips only `RENDER_*` and the bex keys, so `bexAgainst` ran `ea objects delete` with the runner's `CI=true`, the root command saw no terminal, and a pseudo-terminal test failed only in CI (w21/115, fixed in `0b97bf731` for that one call site); three other helpers already delete `CI` on their own, so the next test built on `bexAgainst` fails the same way.

- **Evidence.** `lego/cli/main_test.go:463` (`withoutRenderEnv`), `:822-826` (`telemetryEnv` deletes `CI=` itself), `:474-486` (`updateTestEnv` deletes `CI` itself), `lego/cli/s3_confirm_test.go:222` (the fix, which deletes `CI=` for one run), `lego/cli/edit_contract_test.go:77` (sets `CI=`), `lego/cli/sandbox_id_contract_test.go:101` (`bexAgainst`, used by `object_storage_test.go`, `runtime_copy_test.go`, `sandbox_credentials_contract_test.go`, `sandbox_groups_contract_test.go` and others). The root command treats a run as a terminal only when all three streams are terminals, `CI` is not set, `TERM` is not `dumb` and neither `-o` nor `RENDER_OUTPUT` chose a format (`lego/cli/internal/s3/confirm.go:40`).
- **Change.** `withoutRenderEnv` also drops `CI` and `TERM`, plus any other variable the root reads for an output decision (check `NO_COLOR`), so every helper built on it behaves alike on a laptop, in a pseudo-terminal and on a runner. Delete the per-helper deletions that become redundant. A test that wants `CI` or a `TERM` passes it explicitly. Sweep the other `os.Environ()` sites (`main_test.go` has 9, then `agent_contract_test.go`, `disclosure_test.go`, `edit_contract_test.go`, `psql_trust_test.go`, `runtime_copy_test.go`, `sandbox_id_contract_test.go`) for a test whose result depends on them.
- **Where.** `lego/cli/main_test.go` and the test files above.
- **Done when.** `cd lego/cli && go test ./...` passes with `CI=true`, with `CI` unset, and with `TERM=dumb` and with `TERM=xterm-256color`. A small test fails when `withoutRenderEnv` lets `CI` through.

**Done 2026-11-23.** `withoutRenderEnv` (`lego/cli/main_test.go`) now also drops `CI`, `TERM`, `COLORTERM`, `NO_COLOR`, `CLICOLOR` and `CLICOLOR_FORCE`, by name in one list (`droppedEnv`). Those are the output decisions the pinned root command and the color library under it read: `CI` and `TERM` in `pkg/command/outputresolver.go` and `pkg/cfg` (the interactive decision), and the other four in termenv (whether the output carries color escapes). `RENDER_OUTPUT` was already gone with every `RENDER_*`. `telemetryEnv`, `updateTestEnv` and `s3_confirm_test.go` lost their own `CI` deletions, and `TestBexBinaryEditShorthand` now builds on `withoutRenderEnv` instead of `os.Environ()` plus a blank `CI=`. A test that wants one of them passes it after the helper (`TERM=xterm` in the pseudo-terminal runs, `CI=true` in `TestCIBypassesTheDisclosureGate`).

- **Sweep.** Every `exec.Command` in the CLI tests now takes its environment from `withoutRenderEnv` (directly or through `bexAgainst`, `telemetryEnv`, `s3Env`, `updateTestEnv`), except the `go build` in `TestMain`, the `git` helper in `internal/agent`, and the formula script in `TestFormulaCaveatsAreTheBexNotice`, none of which reads those names. The in-process tests under `internal/` inject their lookup or clear what they read (`internal/disclosure`'s `cleanEnv`).
- **A second leak found.** Before the change the suite already failed with `CLICOLOR_FORCE=1` in the environment (`TestNoHelpLinksRenderDocs`, `TestBlueprintNextStepsNameBex/text`, four cases of `TestBexNativeGroupsWithoutAWordAreUnchanged`), because the child printed color escapes into a pipe; it now passes.
- **Matrix, `cd lego/cli && go test -count=1 ./...`, all 14 packages `ok` each time.** `CI=true`; `CI` unset; `TERM=dumb`; `TERM=xterm-256color`. Also, for the root package: `CLICOLOR_FORCE=1`; `NO_COLOR=1 CLICOLOR=0`; `CI=true TERM=dumb NO_COLOR=1 CLICOLOR_FORCE=1 GITHUB_ACTIONS=true`; `TERM` and `COLORTERM` unset. The baseline before the change passed the first four and `NO_COLOR` and no-`TERM`, and failed only `CLICOLOR_FORCE=1`.
- **The new test.** `TestChildEnvironmentsIgnoreTheRunnersOutputSettings` exports every one of those names (plus `RENDER_OUTPUT` and `BEX_API_KEY`) with `t.Setenv` and fails when any of `withoutRenderEnv`, `bexAgainst`, `telemetryEnv`, `s3QuietEnv` or `updateTestEnv` hands one to a child, or drops `PATH`. Proven by mutation in a scratch run (the file backed up, edited and restored by one script, then compared with the backup): taking `CI` out of `droppedEnv` fails it with `… hands a child CI=true` for all five helpers, and the same for `TERM` and for `CLICOLOR_FORCE`. With that `CI` mutation and `CI=true` in the runner's environment, `TestBexS3DeletesAskOnATerminalLikeEaObjectsDelete` also fails (the reference and the four delete verbs), which is the w21/115 failure.
- **Done when.** The four runs above pass and the test fails when `withoutRenderEnv` lets `CI` through; `golangci-lint run` over `lego/cli` reports 0 issues.
