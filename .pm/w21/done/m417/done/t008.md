## Result (2026-11-16): public reads walked on production, steps 1 to 5 done, two defects fixed

Production ran the images pinned to digest `sha256:7e70d397bbb2d6b98cd6aed0f76515f5c54055361923e5e4c0621fce6171693f` (both Secrets installed, bex-api and bex-objectgw 2/2 Ready); the tenant was the QA user's workspace `bex-canary`; the client was stock **wrangler 4.162.0** against `objects.onbex.co`. A token came from a headless device approval (`scripts/qa-login.sh --login-challenge`, no password typed). The full record, with the numbers, is in [ADR112 § Not verified](../../../../../docs/ADR112-object-storage.md#not-verified) ("bex, settled 2026-11-16 on production"); this is the summary.

- **Steps 1 and 2 (reads, CORS, disable).** `dev-url enable` on a bucket with an 18 B, a 300,000 B and a 20 MiB object: plain GET, HEAD, `Range` (prefix, open-ended, suffix, mid-object; the 20 MiB object's bytes and sha256 equal the source), `If-None-Match` and `If-Modified-Since` (304), `If-Match` (200 and 412), `If-Range` (whole object, by design), `PUT|DELETE|POST` 405, root, listing query, missing key and a `..` path 404. Private before enable: 404. A real Chromium page on `https://example.com` fetched with CORS (plain, `Range`, a preflighted `If-None-Match`) and was blocked for an `X-Secret` header and a `PUT`; the preflight answers `204`/`403` as designed. Disable: last `200` 23.5 s and first all-`404` 24.5 s after the call (bound: 30 s).
- **Wildcard certificate.** `*.onbex.co` (Let's Encrypt, to 2027-01-29) verifies for a `pub-` host; the host is DNS-only like `objects.onbex.co`.
- **Wasabi.** On a presigned GET it honors `Range` (206), `If-None-Match`/`If-Modified-Since` (304) and `If-Match`/`If-Unmodified-Since` (412) and **ignores `If-Range`** (a stale validator still gets 206), which is why the gateway drops `Range` when `If-Range` is present. A `Range` past the end answers 200 with the whole object. HEAD is signed by objectgw; conditionals and `Range` work on it too.
- **Step 3 (kill switch).** With objectgw at zero replicas a visitor gets Traefik's `503 Service Unavailable`, `text/plain; charset=utf-8`, body `no available server`, for an existing bucket's host and any other `pub-` host alike, from 0.5 s after the scale; `502 Bad Gateway` for the first seconds while the pods terminate; `http://` still `301`s to `https://`; other hosts stay `200`. Done with `kubectl scale`, which Argo CD reverts in 4 to 11 s (`selfHeal`), so the window was short and the GitOps commit path (Argo's apply time) was not run. The expectation in ADR112 D4 and `docs/runbooks/objectgw-kill-switch.md` is replaced by the measurement. Replicas were restored by Argo (2/2 Ready) every time.
- **Step 4 (egress).** Five 20 MiB downloads (104,857,600 bytes) raised the workspace's `object_storage_egress_bytes` by exactly that, and the alert's gauge carried the same total. The three panels are in the live dashboard and return data; both alerts are loaded, healthy and inactive.
- **Throughput and resets.** In-cluster through the Service: Oregon 8.3 MiB/s a stream, 68 MiB/s with 8; Frankfurt 56 MiB/s a stream, 216 MiB/s with 24 over two replicas at about 2 ms of CPU per MiB (a replica's 0.5 core is worth about 240 MiB/s); the request caps admitted exactly 2 x (burst + rate x s), a refusal costs about 80 microseconds. The shared Wasabi account holds 67.4 GB of active storage (12 buckets) and Wasabi's rule is egress at or below it, so the first caps spent the allowance in 27 minutes. Reset: bandwidth 2 MiB/s per bucket and 4 MiB/s per workspace per replica, bursts 64 and 128 MiB, request caps kept (`limits.go`, `TestTheBandwidthCapsLeaveTheAllowanceAnHourOfWarning`); alerts 30 GB and 50 GB after five minutes (`alerting_rules.yml`, `object_storage_egress_alerts_test.yml`, panel thresholds). Node egress is not a constraint (22 TB per server included, 24 GB used by all 15).
- **Defects found and fixed.** (1) `If-Match` or `If-Unmodified-Since` that fails on a small cached object reset the visitor's HTTP/2 stream (the cache kept Wasabi's `Content-Length`; `http.ServeContent` answers 412 with no body); it is now the plain 412 of the uncached path, counted as `precondition_failed`; regression test over a real connection (`TestAFailedPreconditionOnACachedObjectIsACompleteAnswer`, fails without the fix: `unexpected EOF`). (2) Prometheus scraped `bex-objectgw` through its ClusterIP and held one replica's counters only (the panels showed about half of the traffic): the job now discovers pods; `scripts/gitops-validate.sh` pins it (five mutations of the job each fail it, as does the old static target).
- **Matching slugs (QA note of 2026-11-15).** None of the 38 Ingress hosts or 27 App resources on production is a `pub-<xid>` host or slug.
- **Cleaned up.** Both test buckets (disabled, emptied, deleted), the Contract A object and the `render-oregon` system bucket it created (Wasabi lists nothing under the workspace's prefix in either region), the load-generator pod, the OAuth token and the Kratos sessions, the kubeconfig and every scratch file. Left: `usage_hourly` rows.
- **Not run.** The GitOps commit path of the kill switch; several workspaces loading the gateway at once; whether Wasabi measures the ratio per account or per bucket. The two fixes reach production with the next deploy.
