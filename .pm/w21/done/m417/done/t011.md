## Objective

Add meaningful tests for the behavior this milestone shipped: real behavior and failure modes, never tautological or snapshot-everything tests.

## Steps

1. List the behaviors and failure modes shipped by the milestone's tasks.

3. Run the backend suite with the real Postgres the repo's CI uses.

## Acceptance criteria

## Out of scope

- Raising coverage numbers with trivial tests.

## Result

Mutation-checked every behavior the milestone shipped: 52 one-line mutants of the gateway (handler, origin, CORS, limits, resolver, meter, verbs, cache), the public service and `publichost`, the `dev-url` route, the token check, the slug reservation and the egress query, each run against the package suites. Three survived and each was a real finding: the cache path's header filter and a dot check in `BucketIDOfHost` were redundant (removed), and a charge clamped at the burst on one side only was masked by the other side (the test now isolates each side and also asserts the bucket is in debt at once, which found that a relayed stream's charge needed its own test: `TestAStreamedObjectIsChargedWhenItStarts`). Gaps the run exposed and closed: the untyped-object download (the fake S3 now types it as S3 does, and a stub origin drives the no-Content-Type case), the rolling write deadline, the connection pool, the 412 label, disabling with no hosting domain, the open-response caps, the zero-cap panic, and the renewal limiter. The Postgres tests ran against a real Postgres 17 (egress sum, its index and its down migration, the slug reservation); the full suite runs in `/land`'s gate on a fresh database (the local test database had a retired webhook replay epoch from an earlier run, which fails four unrelated `GitWebhookReplay` tests until `backend-test-deps.sh up` recreates it). `make lint` and `deadcode -test` are clean, and the script and promtool tests pass.
