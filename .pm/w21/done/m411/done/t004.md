## Objective

Stop passing the registry password to `skopeo` as `--src-creds user:pass` on the command line.

## Context

- `cmd/registry-migrate/main.go` builds `skopeoCopyArgs` with `--src-creds` and `--dest-creds` (line 206) and `--src-tls-verify=false`; an argv is readable by every process in the container through `/proc/<pid>/cmdline` and lands in process listings and crash reports.

## Steps

1. Red-first test on `skopeoCopyArgs`: the password appears nowhere in the arguments.
2. Write a 0600 auth file in a private temp directory (`{"auths":{host:{"auth":base64(user:pass)}}}`), pass `--src-authfile` and `--dest-authfile`, and remove it when the copy ends.
3. Leave `--src-tls-verify=false` and record why (the source is the in-cluster Zot on a private address), or scope it to that host.

## Files

- lego/operator/cmd/registry-migrate/main.go
- lego/operator/cmd/registry-migrate/main_test.go

## Acceptance criteria

- [x] No argument of the skopeo command carries the password, the auth file is private and removed, and the tests pass.

## Out of scope

- Anything else the round-25 audit listed.

## Result (2026-11-14)

`registry-migrate` writes the registry credentials to a private auth file (`0600` in a `0700` temp directory, removed when the run ends) and passes `--src-authfile`/`--dest-authfile`; no argument carries the password (`TestSkopeoCopyArgsPointAtTheAuthFileAndCarryNoPassword`, `TestSkopeoAuthFileHoldsTheCredentialsPrivatelyAndIsRemoved`). `--src-tls-verify=false` stays: the source and destination are the in-cluster Zot at its Service name, and the reason is now in the code. The tool's own `--registry-password` flag still defaults from `BEX_REGISTRY_BUILDER_PASSWORD`; giving it on the command line is the operator's choice and is what the environment variable avoids.
