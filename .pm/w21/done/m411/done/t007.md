## Objective

Run the `pwd -P` containment check that `dockerContextFilesScript` has before BuildKit reads the build context and Dockerfile directories, whether or not the build has secret files.

## Context

- `internal/build/dockerinputs.go` `dockerContextFilesScript` refuses a context that is a link leaving the source mount, but that step exists only when `copiesContextFiles` (a Dockerfile build with secret files). Without secret files, `build.go` hands `context=<dir>` and `dockerfile=<dir>` to `buildctl` unchecked, and a repository whose context directory is a link to `/` would give BuildKit the builder container's own filesystem.
- The clone step's root directory is the other place a tenant-chosen path is entered; check whether it resolves a link the same way.

## Steps

1. Red-first test: the BuildKit script of a Docker build without secret files contains the containment check for the context and the Dockerfile directory, and a script run against a fixture tree with an escaping link exits `ExitTenantError`.
2. Share one containment snippet between the two steps rather than copying it.
3. Do the same for the native build's root directory if the clone step does not.

## Result (2026-11-14)

The clone step, which runs for every build (Dockerfile or native, with or without secret files), now refuses a root directory, Docker build context or Dockerfile directory that resolves out of the checkout (`pwd -P` against `BEX_SOURCE_ROOT`), as the tenant's error (`ExitTenantError`, "the root directory \"x\" is a link that leaves the repository"); links that stay inside the checkout are accepted. This covers the Docker context step's gap (its own check, which stays, ran only when there were secret files) and the native build's root directory. Test: `TestCloneRefusesALinkThatLeavesTheRepository` (relative, absolute and nested links, in and out).
