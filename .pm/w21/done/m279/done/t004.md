## Objective

Give a running agent a controlled way to start a child session without handing the sandbox an API credential.

## Context

- Spec: ADR102. The sandbox already reaches bex through the ssh-gateway model proxy and the `/agent-results/...` path (`BEX_AGENT_RESULT_API_URL`); the spawn path follows the same operation-scoped pattern.
- A tool in the driver (`lego/backend/internal/agentsession`, the `submit_result` tool from ADR094 phase 3 is the closest precedent) calls the gateway, which creates the child as the parent's owner.

## Steps

1. Add the spawn route in the gateway, scoped to the calling session's id and operation token.
2. Add the driver tool and register it with the engine's tool list.
3. Refuse when the depth or fan-out limit is hit, with a message the agent can read.
4. Tests for token scoping: a session cannot spawn on behalf of another.

## Files

- lego/backend/internal/agentsession/ (driver tool)
- lego/backend/cmd/ssh-gateway/ (spawn route)
- lego/backend/internal/agentsessionticket/ (scope)

## Acceptance criteria

- [x] A session spawns a child through the tool and the child records its parent.
- [x] A session cannot spawn using another session's token.
- [x] No bex API credential appears in the sandbox environment.

## Out of scope

- Messaging a running child.
