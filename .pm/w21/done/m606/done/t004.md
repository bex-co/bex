## Objective

Production, the mock cluster and the dev environments run the patched operator by digest, the validators pin it, and the ADRs say what runs and when it is removed.

## Context

- `deploy/gitops/base/cnpg-operator.yaml`: `image.tag: 1.30.1@sha256:923c…` and `ENABLE_INSTANCE_MANAGER_INPLACE_UPDATES: "true"`. The in-place setting means the adoption replaces each instance manager without restarting PostgreSQL.
- `scripts/gitops-validate.sh:1216` asserts the rendered Deployment image equals upstream's `1.30.1` digest.
- `lego/operator/internal/controller/database_operand_cnpg_test.go:37` `qualificationCNPGImage`.
- `scripts/mock-cluster.sh` `install_cnpg` and `scripts/dev-env.sh` `ensure_cnpg` install the pinned chart.
- ADR092 D1 `pgaudit` row (says CloudNativePG drops it, owner w21/m606). ADR018 § Managed Postgres "Postgres extensions" row and gap-backlog line.

## Steps

1. Set `image.repository` and `image.tag` (`<tag>@sha256:<digest>` from t002) in `cnpg-operator.yaml`, and make the rendered image the one `gitops-validate.sh` asserts.
2. Point the qualification pin, mock-cluster and dev-env at the same image. A CloudNativePG bump that drops the bex build must fail one of these checks.
3. ADR092:
   1. Rewrite the `pgaudit` row: the owner's extension survives restarts through the bex build.
   2. Add a short "CloudNativePG build" paragraph: what the patch does, where it lives, how the image is built, and that it is removed once an upstream release carries an equivalent fix (t005's link).
   3. ADR018: update the row and the gap line to match.
4. Prettier the markdown and run `bash scripts/docs-links-validate.sh`.
