# The Chinese UI keeps two English accessible names: the toast landmark on every page, and the Metrics chart's event markers

Why: with the language set to Chinese a screen-reader user still hears "Notifications alt+T" on every page and a lowercase machine name ("commit ignored") on chart events, while everything around them is translated.

**Severity:** minor (accessible names and one hover label, no functional loss). **Estimate:** 40m, dashboard only (two independent root causes, each with its own test). **Source:** live `/qa-find-bugs` pass 8 (i18n sweep), 2026-11-10, production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction. **Status:** inbox.

## Method (reproducible)

For 20 read-only pages (Overview, Blueprints, Agents, Automations, Env Groups, Webhooks, Webhooks/new, Notifications, Billing, Workspace Settings, New Web Service, and the Deploys, Events, Logs, Metrics, Environment, Scaling, Plan and Settings tabs of one existing service plus one private service's Deploys), load each page with `?lang=en` and with `?lang=zh`, collect every text node and every `aria-label`/`placeholder`/`title`/`alt`, and keep the strings that are identical in both languages and look like English prose. After removing data (commit messages, log lines, agent prompts, resource names), plan names, the typed confirmation phrase `sudo delete workspace <name>` and server-authored sentences, two UI-owned strings remain.

## 1. The toast region's accessible name is never translated (all 20 probed pages)

- **Repro:** open `https://dashboard.bex.co/?lang=zh` (`html lang=zh`, the h1 reads 概览). `[...document.querySelectorAll('[aria-label]')].find(e => /^Notifications/.test(e.getAttribute('aria-label')))` returns `<section aria-label="Notifications alt+T">` in both zh and en. The same string appeared on all 20 probed routes.
- **Root cause:** `dashboard/src/common/components/ui/sonner.tsx` renders `<Sonner … {...props}/>` with no `containerAriaLabel`, and `dashboard/src/common/providers/ory-toaster.tsx:43` mounts it as a bare `<Toaster />`. The pinned sonner 2.0.8 (`dashboard/node_modules/sonner/dist/index.mjs`) builds the landmark name as `${containerAriaLabel} ${hotkeyLabel}` with `containerAriaLabel = 'Notifications'` and `hotkeyLabel = 'alt+T'`.
- **Fix:** pass `containerAriaLabel` from the translation catalog in `OryToaster` (it already reads `useTranslations()`). Reuse the existing `common.navNotifications` ("通知", `dashboard/src/common/locales/zh.ts:239`) or add a dedicated key `common.notificationsRegion` in `en.ts` and `zh.ts`. The hotkey suffix stays `alt+T`.
- **Blast radius:** 1 mount point (`root-provider.tsx:51` lazy-loads `OryToaster`), and no other `<Toaster` caller in `dashboard/src` (grep). The existing tests `dashboard/src/common/providers/__tests__/ory-toaster.test.tsx` and `root-provider.test.tsx` must keep passing; add one asserting the landmark name per language.
- **Adjacent:** the toast bodies are already translated at their call sites ("Environment saved and deployment started" and so on); only the container label is the library default.

## 2. Chart event markers fall back to the raw event-type name (Metrics tab)

- **Repro:** open `/services/srv-d9ndt8hmcglc739fkp50/metrics?lang=zh` (an existing service of the workspace, read-only). The chart's marker links have accessible names `最新部署: 已上线` (translated), `2 个事件` (translated) and `commit ignored` (English, lowercase, underscore replaced by a space). `?lang=en` shows the same lowercase `commit ignored` next to capitalized markers such as "Latest deploy: Live".
- **Root cause:** `dashboard/src/features/metrics/lib/chart-events.ts:157-163`: the `default:` branch of the event-type switch returns `labelKey: "metrics.eventsChanged"` ("Service changed") **and** `fallbackLabel: type.replaceAll("_", " ")`. `dashboard/src/features/metrics/components/chart-event-markers.tsx:192` (`markerLabel`) prefers `fallbackLabel` over the translated key, and uses it for both the link `aria-label` (lines 107 and 120) and the hover popup text (line 138). Only 14 event types have a `case`; the Events tab catalog (`dashboard/src/features/events/service-event-catalog.ts`) lists more than 40, and the Events tab already translates them (`commit_ignored` maps to `services.eventsTypeCommitIgnored`, line 151). Every catalog type outside the 14 renders as its machine name on the chart.
- **Fix (target behavior):** a marker for a type the catalog knows shows that type's translated Events-tab label (reuse the `services.eventsType*` keys through the catalog's type-to-key map instead of a second vocabulary). A type absent from the catalog keeps the raw-name fallback, which the unit test at `dashboard/src/features/metrics/lib/__tests__/chart-events.test.ts:114` (`fallbackLabel` is "image updated") pins as intended for truly unknown types. UI only; REST, GraphQL and MCP are untouched.
- **Blast radius:** `markerLabel` has 3 call sites, all in `chart-event-markers.tsx` (lines 107, 120, 138). The markers are used by the 6 service Metrics charts through `SvgLineChart` and `SvgBarChart`. The 14 explicit cases must keep their current labels (regression tests on them), and the cluster label `metrics.eventMarkerCluster` is unaffected.
- **Adjacent:** whether chart markers should show every catalog type at all, or only Render's captured taxonomy (w5/m43 t002 wrote the 14-case mapping from Render's captured markers), is a product question this note does not decide; the fix only changes how an already-shown marker is named.

## Dedupe / precedent

`grep` of `.pm` (open and done): "Notifications alt+T" appears only inside unrelated captured snapshots (w4/227, 216, 264, m183) and nobody filed it. `fallbackLabel` / `eventsChanged` / `chart-events` appear only in w5/m43 (which built the mapping) and w4/297 (Chinese Metrics chart descriptions and "No data in range", done, which observed the marker group label `服务事件` translated but not the per-marker names). `git grep` on `origin/main`: `containerAriaLabel` has no match in `dashboard/src`, and `chart-events.ts` still has the `replaceAll("_", " ")` fallback, so neither is fixed upstream. Not in `DO_NOT_DO.md`.

- `/services/srv-d9ndt8hmcglc739fkp50/metrics?lang=zh`: the marker for a commit-ignored event has a Chinese accessible name and hover text; in `?lang=en` it reads the capitalized Events-tab wording, not `commit ignored`.
