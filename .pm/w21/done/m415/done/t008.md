## Objective

Prove the unchanged Render CLI works against bex-api for all four commands, and keep the compatibility checklist true.

## Context

- Models: `lego/cli/agent_contract_test.go`, `lego/cli/edit_contract_test.go` (how the pinned `render-oss/cli` is run against a bex-api).
- `docs/cli-compatibility-checklist.md` has four `ea objects` rows that say not offered; `lego/cli/README.md` documents the launcher; `docs/bex-cli.md:3` says what `bex` is.
- `docs/ADR112-object-storage.md` D11: the launcher passes `ea objects` through; no bex command is added.

## Steps

1. Add `lego/cli/objects_contract_test.go`: the pinned CLI runs `ea objects put`, `get`, `list` and `delete` against an in-process bex-api and the fake S3; check 0 B, 1 B and 5 MiB round trips byte for byte, `list --limit 200`, and "object not found" on a missing key.
2. Confirm the launcher forwards `ea objects` unchanged; add a pass-through test if none exists.
3. Update the four checklist rows from not offered to supported, with the bex-specific limits.

## Result

`lego/cli/object_storage_test.go` rewritten as the pinned-CLI contract test: a stand-in for bex-api answering in the shapes of `objects_render.go` plus a stand-in for Wasabi behind the presigned URLs. The real pinned CLI puts, gets, lists and deletes through them: 0 B, 1 B and 5 MiB round trips are byte for byte, every upload matches what the mint declared with a real Content-Length and no chunked encoding (the CLI special-cases a zero length), `--limit 200` prints 200 keys and sends limit=200, a missing key prints `object not found` on get and delete, every route call carries the CLI's bearer, and `--local` still never calls the API. The launcher override that refused cloud `ea objects` (`notOfferObjectStorage` in `lego/cli/main.go`) is deleted: the CLI passes through unchanged and no bex command is added. The CLI module's whole suite passes (44 s). `docs/cli-compatibility-checklist.md`: the four rows are `[~]` (served, contract-tested, production walk pending) with the bex limits, and the `ea` row and the non-goals sentence no longer list objects; they flip to `[x]` when t010 verifies them live. The stand-in server is the test's own, so it proves the pinned client's wire handling, not bex-api's handlers; those are covered by the backend route tests written against the same generated client types.
