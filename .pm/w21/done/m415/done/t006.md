## Objective

Serve Render's four `/v1/objects/{ownerId}/{region}` routes as the pinned CLI and SDKs call them, with presigned URLs so the bytes never pass bex-api.

## Context

- `lego/backend/internal/api/server.go:1749-1797`: `notOfferedRefusals` lists the four patterns, `mountNotOffered` answers them, `objectStorageNotOffered` is the message. Remove the four entries and the constant, and update the comment above the map.
- `docs/ADR112-object-storage.md` D2: list reads Wasabi under `<tea-id>/<obk-id of render-region>/` (limit default 20, up to 1000, cursor is the base64 of the last key fed to `StartAfter`); put mints a presigned PUT signing `Content-Length = sizeBytes` and returns `{url, expiresAt, maxSizeBytes}` with `maxSizeBytes = sizeBytes` (413 above the 5 GiB cap); get and delete `HEAD` first and answer 404 for a missing key; the GET URL pins `response-content-disposition: attachment`.
- Presigned lifetime 15 minutes (the architecture diagram's bound).
- Authorize through `Base.AuthorizeWorkspace` (`lego/backend/internal/core/base.go:1231`) on `ownerId`; t007 sets the relations.
- How the pinned-spec request gate treats a route: `internal/api/render_openapi.go:796` and the `render_openapi_*_test.go` files. The four routes must not stay in any not-offered set.

## Steps

1. Add `internal/api/objects_render.go` with the four handlers as a thin adapter over `objectstorage.Service`; mount them in `server.go`.
2. With no service configured the handlers answer today's named 404 so nothing changes before the credential exists.
3. Region path value: `oregon` or `frankfurt`, anything else is 400 `REGION_NOT_OFFERED`.
4. Resolve the workspace's system bucket with `EnsureSystemBucket` on first use.
5. Write handler tests against the fake S3: each route, each error, and the unconfigured 404.

## Files

- lego/backend/internal/api/objects_render.go and tests
- lego/backend/internal/api/server.go

## Acceptance criteria

- [ ] The four routes no longer appear in `notOfferedRefusals` and the unconfigured answer is unchanged.
- [ ] put returns `maxSizeBytes` equal to `sizeBytes` and signs `Content-Length`; a size over 5 GiB is 413.
- [ ] A missing key answers 404 on get and on delete.
- [ ] list honors `limit` 200 and pages with the cursor.

## Out of scope

- Authorization relations and scope classes (t007); the pinned-CLI test (t008).

## Result

Core: `MintPut`, `MintGet`, `DeleteObject`, `ListObjects` on `objectstorage.Service` (the Render namespace is the workspace's render-<region> system bucket, created on first use; a refused mint creates nothing; get and delete HEAD first so a missing key is a 404; the cursor is the base64 of the last key). Adapter: `internal/api/objects_render.go` with the wire shapes read from the pinned render-oss/cli (`pkg/client/storage/storage_gen.go`: `items[{cursor, object{key,sizeBytes,lastModified}}]`, `hasNext`, `nextCursor`, `{url, expiresAt, maxSizeBytes}`, `{url, expiresAt}`, 204 on delete), Render's error shape with codes (REGION_NOT_OFFERED 400, OBJECT_KEY_INVALID 400, SIZE_BYTES_REQUIRED 400, OBJECT_TOO_LARGE 413, OBJECT_STORAGE_QUOTA and OBJECT_REQUESTS_LIMITED 429 with Retry-After, OBJECT_NOT_FOUND 404). The four patterns and the constant left `notOfferedRefusals`; with no credential the handlers still answer the named 404. `cmd/api/main.go` builds the service from the store and `NewStores(cfg.ObjectStorage)`. The relations were set here as D6 says (list can_view, get can_view_sensitive, put and delete can_create); t007 adds the matrix row and the tests. Tests: core tests against Postgres and the fake S3 (round trip with real presigned URLs, isolation between workspaces and between the system and user buckets, quota, rate, 200-item limit, cursor refusal), route tests through the mux, the two guards that assumed the routes were not offered (emptylist_test, the not-offered test), and the by-id guard now classifies `obk-`. A `..` key cannot reach a handler through the mux (ServeMux redirects the cleaned path), so the key-validation route tests use a backslash, a control character and an over-long key; the `..` cases are unit-tested in `ValidateKey`.
