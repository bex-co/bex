# 010 — Automations: count a workspace's automations in the database, and read the previous run's phase with one query

Why: `CreateAgentAutomation` loads up to 50 full rows just to count them, and every fire's overlap check makes two queries (`LatestStartedSession`, then `GetAgentSession`); both are cheap to remove and the second sits on the scheduler's hot path.

- **Source.** The w21/m278 t010 simplify review (2026-11-08); the review left these two alone because each adds store-interface surface.
- **What.** Add a `CountAgentAutomations(ctx, workspaceID)` store method and use it for the 50-per-workspace limit; add one store query that returns the latest started session's phase for an automation and use it in the overlap check.
- **Done when.** The limit and the overlap check give the same answers as today (existing tests pass), the create path no longer lists rows to count them, and the overlap check makes one round trip.

Done 2026-11-08: `CountAgentAutomations` counts in the database and `LatestStartedSessionPhase` reads the previous run's phase in one query (the overlap check is one round trip); behavior and tests unchanged.
