# Billing → switching to a past month shows the loading state as a real total: the Charges card draws three skeleton bars and, under them, "Total for the period $0.00 USD" until the month's data arrives ($180.24 for October)

Why: the Charges card already takes care not to assert a claim before its figure arrives ([w10/m11/t001](../w10/done/m11/done/t001.md) made the description neutral while `loading`, and the rows show skeletons), but the total line was left rendering `$0.00 USD` from an empty tree, so a cold month reads as "you spent nothing".

**Severity:** minor (transient, but it states a wrong money figure on the billing page; screen readers read it as data). **Estimate:** 15m (render a skeleton or a dash in place of the total while it loads, one test). **Kind:** gap in the guarantee of w10/m11/t001. **Source:** live `/qa-find-bugs` pass 37, 2026-11-10, production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction. Read-only: only the month selector and in-page GraphQL reads; the slow response is simulated by holding the page's own `Usage` request in the browser with `page.route`, so nothing reaches the server differently. **Status:** inbox.

## Reproduction (`/billing`, en)

1. The month selector offers Current month, October 2026, September 2026, August 2026, July 2026 and June 2026.
2. **Control, the data exists.** In-page GraphQL `usage(period: "2026-10", ownerId)` returns `estimatedCost.totalUsd: "180.25"` over 140 resources and `freeInstanceHours.used: 19.3`. After load the UI reads Services $124.87, Postgres $23.86, Key Value $21.31, Sandboxes $10.20, Agent sessions $0.00 and "Total for the period $180.24 USD".
3. **The bug, with the October `Usage` request held.** Load `/billing` (current month shown: five category buttons, "Total this billing period (Oct 16 – Nov 16) $145.02 USD", the "Partial data" caveat, Credits remaining $1000551.64). Then choose October 2026 in the selector while `page.route('**/graphql')` delays the `query Usage` body that contains `2026-10` (the delay is a `page.waitForTimeout` inside the route handler before `route.continue()`).
   - At 1.5 s and again at 4 s the accessibility tree reads `term: Total for the period` / `definition: $0.00 USD`, with zero breakdown buttons, no "Partial data" note, the Credits remaining section replaced by skeleton blocks, and `.animate-pulse` skeletons on the page.
   - A screenshot at that moment (local, gitignored: `.playwright-mcp/qa-billing-2.png`) shows the three grey skeleton bars inside the Charges card and below them, in bold monospace, "Total for the period  $0.00 USD".
   - At 7.5 s it reads "$180.24 USD" with five category rows.
   - Without any route delay the same flash happens on a cold month: choosing June then October, the total read "$0.00 USD" at 1.8 s (the server needed longer than that for October).
4. A first load of `/billing` is not affected: the Usage data is fetched server-side and arrives with the HTML, so only a month switch (a client fetch) shows the flash.

## Root cause (code-traced)

- `dashboard/src/features/usage/components/charges-card.tsx:347-348`: `const treeTotal = categories.reduce((sum, c) => sum + c.totalUsd, 0); const total = rated ?? treeTotal;` is 0 while `categories` is empty. `:461-463` renders `<dd className="font-mono text-lg font-semibold tabular-nums">{money(total, i18n.language)} USD</dd>` unconditionally.
- The card has the `loading` prop (`:289`, `:310`) and already uses it for the skeleton rows (`:412-418`) and the description (`:399-404`, w10/m11/t001: "Say nothing rather than the wrong thing"), but not for the total. So the `<dt>` "Total for the period" (`:449-460`) and the `<dd>` render as a finished $0.00 total beside the skeletons.

## Fix (target behavior)

While `loading && categories.length === 0` the total line shows a skeleton of the same size as the amount (or a dash) and exposes no number to assistive technology, the way the rest of the card does. Once the month resolves it renders the real total, including a true `$0.00` for a month with no usage (June 2026: 0 resources, `estTotal "0.00"`), which must still show `$0.00 USD` and the "no charges" empty state. No backend change.

- The page also swaps its Agent model and Credits sections to skeletons during the same wait, and those render correctly.

Not in `DO_NOT_DO.md`. `charges-card.tsx` is unchanged on `origin/main`.
