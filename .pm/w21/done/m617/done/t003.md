## Objective

Check the two interactions that can go wrong: the autoscaler and drain-guard.

## Context

- Cluster Autoscaler values: `infra/clusterapi/autoscaler-values.yaml`; drain-guard sets `drain-guard.bex.co/evacuated-from` on an at-risk App's template ([runbooks/drain-guard.md](../../../../../docs/runbooks/drain-guard.md)).

## Steps

1. Fill one node so only it has room, scale a service to 2, and confirm the second instance waits for a new node rather than landing beside the first.
2. Delete a Machine holding one instance of a 2-instance service and confirm the replacement lands on another node and the service keeps serving.
3. Record both runs.

## Files

- this task's `## Result`

## Acceptance criteria

- [x] Both runs behave as stated, with the commands and timings recorded.

## Out of scope

- Production capacity planning.

## Result

Done 2026-11-24 on the mock cluster with the operator built from this change (binaries layered over `bex-operator:dev`; the host has no buildx).

1. **A full node.** Every usable node except one tenant node filled to 300m free with `pause` pods; that node kept 1600m. A Starter service at one instance landed on it; `kubectl patch app scarce --type merge -p '{"spec":{"replicas":2}}'`. The second instance stayed Pending (`0/5 nodes are available: 1 node(s) didn't match pod topology spread constraints, 1 node(s) had untolerated taint(s), 3 Insufficient cpu`), the Cluster Autoscaler grew `bex-tenant-0` and the node count went 5 → 6 within 46 s, the instance was scheduled on the new node at 61 s and Running at 76 s. The same run on the operator before the change put it beside the first instance, Running at 15 s. (The mock imports bex's own image onto a new node by a loop; production pulls it.)
2. **A Machine deleted.** A two-instance Starter service on a tenant node and the platform worker; one request a second to its Service from the control-plane node; `kubectl --context kind-bex-mgmt delete machine <the tenant node's Machine>`. The replacement started at once on another tenant node, not beside its sibling, the old instance left after its 60 s drain, the Machine was gone after 92 s, and 111 of 111 requests answered. The mock runs no drain-guard (its hook needs the CAPI objects in the workload cluster); it would have released at once, since the service had a Ready instance elsewhere. Its evacuation of a one-instance service is guarded by `TestDrainGuardsEvacuationKeepsItsTemplate`: the operator's next pass keeps drain-guard's template as written, spread or not, so the evacuation rolls once.
