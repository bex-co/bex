## Objective

Implement the rule ADR004 records.

## Context

- `lego/operator/internal/controller/deployment_projection.go` (`projectDeployment`, the `Recreate` branch for disk services).
- Free services are capped at one instance (ADR030 §6); disk-attached services roll with `Recreate`.

## Steps

1. Add the `topologySpreadConstraints` entry to the pod template for the services ADR004 names.
2. Make sure an operator upgrade does not change the template of any running Deployment that is not otherwise rolling.
3. Envtest: the constraint is present for a multi-instance service, absent for single, free and disk services, and the upgrade leaves an existing template unchanged.

## Files

- `lego/operator/internal/controller/deployment_projection.go`
- its tests

## Acceptance criteria

- [x] `make test` passes from `lego/operator/` with the new envtest cases.

## Out of scope

- Changing the scheduler's scoring.

## Result

Done 2026-11-24. `lego/operator/internal/controller/instance_spread.go` (`spreadsAcrossNodes`, `instanceSpread`, `applyInstanceSpread`, `storedSpread`); `applyDeploymentSpec` keeps a stored template's spread or its absence while nothing else changes (the lazy block moved into `keepStoredTemplate` to keep `applyDeploymentSpec` under gocyclo's 30). Unit tests `instance_spread_test.go`, envtest `instance_spread_envtest_test.go` ("Instance spread (w21/m617)": the API server stores the spread unchanged; the upgrade writes none of the multi, single, Free or disk Deployments; through the reconciler a legacy template survives the upgrade unwritten, a scale to three changes only replicas, a restart adopts it). Reverting either the lazy keep or the projection fails both suites. `make test` and `make lint` pass.
