## Objective

Add a dashboard test that loads the corpus and asserts each client validator reaches the server's verdict on every entry; a client may be more lenient only on `serverOnly` entries.

## Context

- Read the files the way `dashboard/src/test/go-source.ts` does (paths relative to the repo root from `process.cwd()/..`).
- Client validators return different shapes (a boolean, an i18n message key, a parsed value); the test needs a small adapter per family that reduces each to accept or refuse.
- Both directions are defects: refusing a valid input blocks the user (w21/048), accepting an invalid one sends a doomed request that comes back as a toast (w21/038).

## Steps

1. Add `dashboard/src/common/lib/__tests__/validation-corpus.test.ts` with a family → adapter table and one assertion per entry.
2. Treat `serverOnly` entries as: the client may accept, must not refuse an input the server accepts.
3. Self-test the harness: a deliberately stricter and a deliberately looser adapter each fail.
4. Run it; list every divergence for t004.

## Files

- dashboard/src/common/lib/__tests__/validation-corpus.test.ts
