# 066 — Dashboard GraphQL documents are validated against the backend's own schema in `yarn test`

Why: `dashboard/src/graphql/definitions.ts` is partly hand-maintained and `dashboard/AGENTS.md` calls the hand-splice "the common case", yet no CI step checks that the dashboard's operations are valid against bex-api's schema, so a query for a field or argument the server lacks would only fail in production (as w1/116's `Cannot query field "undeployedChanges"` did once, from a deploy skew).

- **Source:** `/pm-brainstorm for w21` (2026-11-14), filed by `/pmx them all to w21`. At filing, graphql-js `validate` over the 67 `.graphql` files (322 definitions) against a fresh `TestDumpGraphQLSchema` dump reported 0 errors, so the gate starts green. Neither `dashboard-test.yml` nor `backend-test.yml` runs a schema step.
- **Size:** about 1h (a golden file, one test, two `paths` lines). If it grows past that, `/pm promote` it.
- **Do not commit the introspection JSON.** `SCHEMA_DUMP_PATH` writes 1,169,802 bytes, over the repository's 1 MiB blob limit (`AGENTS.md`). Commit the schema as SDL instead.

## Steps

1. In `lego/backend/internal/api/schema_dump_test.go`'s package, add a test that prints the served schema as SDL and compares it to a committed golden file (for example `lego/backend/internal/api/testdata/schema.graphql`), with an update flag; check the file stays well under 1 MiB.
2. Add a dashboard test that parses the golden SDL, loads every `dashboard/src/**/*.graphql` document (fragments across files merged), runs `validate` and fails with the messages. Read the file the way `dashboard/src/test/go-source.ts` reads Go.
3. Add the golden file to `dashboard-test.yml` `paths`; run `python3 scripts/ci_test_inputs.py`.

## Done when

- A dashboard operation naming a field the golden schema lacks fails `yarn test`, and a backend schema change without a golden update fails the Go test.
- `python3 scripts/ci_test_inputs.py`, `yarn lint`, `yarn test` and `cd lego/backend && go test ./...` pass.

## Out of scope

- Comparing the generated types in `definitions.ts` with a regeneration (it is partly hand-maintained, per `dashboard/AGENTS.md`).

## Done (2026-11-14)

- **Go:** `lego/backend/internal/api/schema_golden_test.go` prints the served schema as SDL (types, fields, argument and field types, required-ness and defaults; names and arguments sorted, because graphql-go hands arguments back in map order, which changed between runs; no descriptions) and `TestGraphQLSchemaMatchesTheGolden` compares it to `lego/backend/internal/api/testdata/schema.graphql` (75 KB, not the 1.17 MB introspection JSON). `UPDATE_SCHEMA_GOLDEN=1 go test ./internal/api -run TestGraphQLSchemaMatchesTheGolden` regenerates it. The dump test shares the `servedSchema` helper.
- **Dashboard:** `dashboard/src/graphql/__tests__/schema-validity.test.ts` builds the schema from the golden, merges the 68 `src/**/*.graphql` files codegen reads, and validates them with graphql-js, reporting `file:line: message`. It started green (0 errors), as the note predicted, and five self-tests show it refuses an unknown field, an unknown argument, a missing required argument and an unknown fragment type.
- **Mutation checks:** dropping `Query.accountDeletionPreview` from the golden fails the dashboard test with `features/auth/api/account-deletion.graphql:2: Cannot query field "accountDeletionPreview" on type "Query"` and fails the Go test at the first differing line.
- **CI:** the golden is in `dashboard-test.yml`'s push and pull_request `paths`; with it removed `scripts/ci_test_inputs.py` fails naming the file and the test that reads it. `dashboard/AGENTS.md` records the regeneration step.
