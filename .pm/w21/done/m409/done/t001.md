## Objective

Make `bex-drain-guard-writes` refuse a Deployment write that touches pod-template `finalizers`, `ownerReferences`, `generateName`, `name` or `namespace`, and one on a Deployment that is not an App's, with each denial a case in the existing envtest table first.

## Context

- `deploy/gitops/base/drain-guard-admission.yaml`, variable `deploymentWrite`: it compares the template spec, labels and annotations, but not the rest of `object.spec.template.metadata`, and it applies to any Deployment the identity can patch (cluster-wide).
- The controller only evacuates a Deployment whose selector carries `app.bex.co/app` equal to the Deployment's name (`lego/operator/internal/drainguard/drainguard.go:313`), so the policy can require the same shape.
- Harness: `lego/operator/internal/drainguard/admission_test.go` runs the production policy in a real API server (envtest) with the identity impersonated and `cluster-admin` granted, so each denial is the policy's; the cases are one table. Run with `go test ./internal/drainguard -run TestAdmissionPolicyConfinesDrainGuard`.

## Steps

1. Add the failing cases to the table: a template `finalizers` add, an `ownerReferences` add, a `generateName`, `name` and `namespace` set, each on the App Deployment `web`; and the evacuation annotation on a Deployment whose selector is not `app.bex.co/app=<its name>`. Watch them fail (allowed) against the current policy.
2. Tighten `deploymentWrite`: the five template-metadata fields equal the old object's, and the selector's `app.bex.co/app` label equals `object.metadata.name`.
3. Re-run the whole table: the existing allowed cases (evacuation annotation on the App Deployment) still pass.
