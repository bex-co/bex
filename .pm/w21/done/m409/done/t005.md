## Objective

Show the three identities' real writes are not refused by the policies as tightened, by running their own code against an API server that has the production policies, and file the live-cluster check separately.

## Context

- The first plan was the local CAPD cluster (`scripts/mock-cluster.sh`, then `operator`, deploy the sample App, let it hibernate and wake it, roll a node). On 2026-11-14 it could not be brought up on this machine: `kind` and `clusterctl` are not installed, and the helm artifact downloads the script depends on answered 504 (`scripts/gitops-validate.sh` died at "mirror of an already-published chart" for the same reason). Installing them is a change to the machine the milestone was not asked to make, and the downloads would have failed anyway, so the live run is filed as w21/079.
- What replaces it is stronger on the risk this task exists for, a legitimate write refused: each identity's own code runs against a real API server holding the production policy, and the result is read back (the activator's `wakeApp` logs a refused write instead of returning it).

## Steps

1. Operator: the spec in `container_policy_admission_test.go` submits what the operator's real producers project (`admissionApplicationWorkloads`, the tier, edge-cache and platform workloads and a real `build.BuildJob`) through the three policies; it passes with every clause in.
2. Activator: `TestTheActivatorsWakePassesItsPolicy` calls the real `wakeApp` as the activator identity for a hibernated and an awake App and reads back both annotations and the Deployment's replicas.
3. drain-guard: the table in `TestAdmissionPolicyConfinesDrainGuard` ends by running the real `evacuate` as the identity and reading back the template annotation.
4. Show each test fails against a policy stricter than the real write (the wake test fails with a policy that refuses replicas 1 or the timestamp format).
