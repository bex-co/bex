# The static-site Redirects/Rewrites editor marks none of the rules bex-api refuses on length and `:name` placeholders (a 2049-character source, a repeated `:x`, a destination naming an undeclared `:slg`), and the Headers path limit counts UTF-16 units while the server counts bytes

Why: [w4/145](../w4/done/145.md) promised that an invalid edge rule is marked in its own row with Save held, but its `routeErrors` mirrors only the leading `/` and the network-path guard, so the other row-checkable route rules reach the user as a few-second toast with no field marked, while the sibling Headers editor marks its path length inline.

**Severity:** minor (a refused save that costs a toast the user must map back to a row; no data lost). **Estimate:** 35m (one shared UTF-8 byte-length helper, three more rules in `routeErrors`, the headers path switched to the helper, tests, en+zh wording). **Kind:** gap in the guarantee of w4/145 (per-row validation of the rules a row can check) and [w4/402](../w4/done/402.md) (which mirrored the header limits but not the route ones). **Source:** live `/qa-find-bugs` pass 41, 2026-11-10, production `https://dashboard.bex.co`, workspace `bex`, journey 9, filed to w21 per user direction. **Status:** inbox.

## Reproduction (own Free static site `qa-20261110-static`, `srv-dbppi4vbq3ic73c0a4g0`, deleted in the same visit)

The site came from the Static Site form with Public Git URL `https://github.com/bex-co/bex`, root `examples/static-site`, publish directory `.`, auto-deploy off. Created 22:22:11; the deploy was `live` at 22:23:14 (63 s) and served `https://qa-20261110-static.onbex.co`.

1. **Controls that work.**
   - `curl -sSI` answers 200 with `strict-transport-security: max-age=315360000; includeSubdomains; preload`, `x-content-type-options: nosniff`, `rndr-id`, `etag` and `cache-control: public, max-age=0, must-revalidate`. `Accept-Encoding: br` gets `content-encoding: br`; `If-None-Match` gets 304; POST, PUT, DELETE, OPTIONS and PATCH answer 405 with `allow: GET, HEAD`; `http://` answers 301 to https and keeps the query.
   - Saved rules take effect on the served responses within seconds. Header `/*` `X-QA-Test: all` appears on `/`, `/index.html` and rewritten paths. Header `/index.html` `Cache-Control: public, max-age=60` replaces the default. Rewrite `/spa/*` to `/index.html` serves the page at `/spa/anything/deep`. Redirect `/old/:id` to `/new/:id` answers `301 location: /new/42` (the incoming query is not forwarded; ADR029 w4/m154 records that).
   - REST `GET /v1/services/{id}/routes` and `/headers` agree with what was saved. Events show `routes_changed` and `headers_changed` once per successful save and nothing for refused saves.
2. **The bug.** On `/static/<id>/redirects`, Add rule, type Redirect, on row 3. For each input below Save routes stays enabled and no field has `aria-invalid`; Save then answers only a toast, and the saved list stays at the 2 earlier rules (REST count 2).
   - source `/` plus 2048 `a`, destination `/index.html`: "Row 3: source must not exceed 2048 characters".
   - source `/ok`, destination `/` plus 2048 `b`: "Row 3: destination must not exceed 2048 characters".
   - source `/a/:x/:x`, destination `/b/:x`: "Row 3: source repeats :x".
   - source `/blog/:slug`, destination `/posts/:slg`: "Row 3: destination references :slg, which the rule's source does not declare".
3. **Control, the Headers editor.** On `/static/<id>/headers`, Add header with path `/` plus 2048 `a`, name `X-Long`, value `1`: the Path field gets `aria-invalid`, the inline message reads "At most 2048 characters" and Save headers is disabled.
4. **Unit mismatch.** A path of `/` plus 700 `中` is 701 characters and 2101 UTF-8 bytes.
   - In the Headers editor, which does check the limit, it is not marked and Save is enabled; the server answers the toast "Row 3: path must not exceed 2048 characters".
   - In the Routes editor a source of the same text gives "Row 3: source must not exceed 2048 characters".
   - The server counts bytes but its message says characters, so the user with 701 characters in the field is told 2048 is the limit.

## Root cause (code-traced; `origin/main` is unchanged for these files)

- Dashboard `features/services/lib/static-rule-validation.ts:63-84` `routeErrors` checks only the leading `/`, the external-URL grammar and the network-path guard. It has no length check and no placeholder check. `headerErrors` at `:129-130` checks the path against `MAX_STATIC_PATH_LEN = 2048` with `String.length` (UTF-16 units). The editors apply them at `features/services/components/static-site-section.tsx:212` (routes) and `:359` (headers). The i18n key `services.staticRulePathTooLong` already exists.
- Server `lego/backend/internal/apps/service.go:5774-5832` `validateRoutes`:
  - `len(source) > maxStaticPathLen` at `:5785`;
  - `validateRoutePlaceholders` at `:5789`, defined `:5731-5772`: a repeated `:name` in the source, or a destination `:name` token other than `:splat` that the source did not declare;
  - `len(dest) > maxStaticPathLen` at `:5812`, and inside `validateExternalRedirect` at `:5653`.
- `validateHeaders` `:5862` uses `len(strings.TrimSpace(h.Path))`. `maxStaticPathLen = 2048` is at `:5635`. Every one of these is `len` on a Go string, so bytes.
- The static-server expands `:name` tokens anywhere in a destination path (`lego/operator/internal/staticserver/staticserver.go:822-880` `substituteCaptures`), and the grammar `[A-Za-z_][A-Za-z0-9_]*` is the same in `routePlaceholderName` (service.go) and `placeholderName` (`staticserver.go:755`). The client can mirror it exactly; the server's own comment says the two sides pin the same vectors in their tests.

## Fix (target behavior)

- The row checks, before Save and in the row, the same four rules the server applies:
  - source and destination at most 2048 UTF-8 bytes after trim;
  - no repeated `:name` in the source;
  - no destination `:name` (other than `:splat`) that the source does not declare.
- Each is marked with `aria-invalid` and an inline message, and Save is held by the existing "Fix the marked rows to save." note.
- The headers path limit and the new route limits all count UTF-8 bytes through one shared helper (for example `new TextEncoder().encode(s).length`).
- The wording says bytes, not characters, in the dashboard (en and zh) and in the server messages (`service.go:5653,5786,5813,5863`), because the server contract is bytes.
- No API, REST, GraphQL or MCP behavior change: only the message wording (Blueprint `routes:` shares the validator).

## Blast radius (counted by grep)

- `routeErrors` has 1 production caller (`static-site-section.tsx:212`) and `headerErrors` has 1 (`:359`).
- The server validators `validateRoutes` and `validateHeaders` are shared by REST PUT, GraphQL, MCP and Blueprint apply.
- Tests to extend: `features/services/lib/__tests__/static-rule-validation.test.ts` and the editor cases beside it, plus the Go cases that assert the "characters" wording.

## Adjacent classes

- The list-level caps (100 routes, 100 headers) stay server-only, as w4/402 decided.
- The external-rewrite public-host rule is deliberately server-only (the `static-rule-validation.ts` comment says so).
- A destination with a literal `:word`, such as `/v1/items:batchGet`, is refused as an undeclared placeholder by design ([w4/479](../w4/done/479.md) reviewed that message). It is not part of this finding.
- The header value and name limits cannot hit the byte/unit gap: names are ASCII tokens, and the row already rejects code points above 0xFF in a value.
