# `scripts/ship-gates.sh` fails the backend gate on a Mac whose Docker VM shares only `$HOME`, unless the caller sets `TMPDIR` by hand

Why: every local `/ship` of a change under `lego/backend/**` or `lego/types/**` fails at the dependency probe until the person or agent running it knows to export a `TMPDIR` under `$HOME`; the requirement is written in a script comment and nowhere a ship reads.

**Estimate:** ~20m. **Source:** `/pm-brainstorm for w21`, 2026-11-11 (hit while shipping w21/041–053 on this Mac, then written down only in a private memory note). **Status:** inbox.

## Evidence

- `scripts/backend-test-deps.sh:116-119` says "a Docker VM that shares only $HOME, such as colima, needs TMPDIR under $HOME" and then creates its probe directory with `mktemp -d "${TMPDIR:-/tmp}/promtool-probe.XXXXXX"`; the shim directory is `"${TMPDIR:-/tmp}/$prefix/bin"` (`:29`). Nothing sets `TMPDIR`: `grep -n TMPDIR scripts/ship-gates.sh scripts/backend-test-deps.sh` finds only those reads.
- On macOS the default `TMPDIR` is under `/var/folders/…`, which the Docker VM does not mount, so the probe fails with `backend-test-deps: the Docker promtool shim cannot read a rule file in a 0700 directory` and the ship stops. Dashboard-only pushes are unaffected.
- `.claude/skills/ship/SKILL.md` and `AGENTS.md` do not mention `TMPDIR`; the working command is `mkdir -p ~/.cache/bex-tmp && TMPDIR="$HOME/.cache/bex-tmp/" bash scripts/ship-gates.sh origin/main`.

## Fix

In `scripts/backend-test-deps.sh` (the only consumer of the path), when the Docker host is a VM that shares only `$HOME` (macOS, or `TMPDIR` is not under `$HOME`), default `TMPDIR` to `$HOME/.cache/bex-tmp` and `mkdir -p` it before the shim and the probe are created. Keep an explicit caller `TMPDIR` that is already under `$HOME`. Linux hosts keep `/tmp`.

## Definition of done

- On this Mac, `bash scripts/ship-gates.sh origin/main` with the default `TMPDIR` and a diff under `lego/backend/**` passes the dependency probe (record the run).
- With `TMPDIR` set to a directory under `$HOME`, that directory is used; on a Linux runner the script still uses `/tmp` (read the code path, no run needed).
- The probe error message names the `TMPDIR` rule if it still fails.

**Done 2026-11-11:** `scripts/backend-test-deps.sh` now picks the temporary directory itself on macOS: unless the caller's `TMPDIR` is already under `$HOME`, it uses `$HOME/.cache/bex-tmp` (created if missing), and its `env` output exports that `TMPDIR`, so the `go test` that `ship-gates.sh` (and the documented `eval "$(… env)"` flow) runs next writes its rule-file tempdirs where the Docker VM can mount them. Linux keeps its `TMPDIR`. It had to be `env`, not only the probe: the shim mounts the suite's own tempdirs too, so fixing the probe alone would still have failed the first test that checks a rule file. Reproduced first: with this Mac's default `TMPDIR` (`/var/folders/…`) `bash scripts/backend-test-deps.sh up` failed with "the Docker promtool shim cannot read a rule file in a 0700 directory". After the change, with the same default `TMPDIR`, `up` passed the probe, `env` printed `export TMPDIR='/Users/…/.cache/bex-tmp'`, and the three suites that use promtool (`internal/egressquery`, `internal/metrics`, `internal/usage`) passed against it; a `TMPDIR` under `$HOME` set by the caller was kept as it was. Not run: a full `ship-gates.sh` with a backend diff under the default `TMPDIR` (this change touches only scripts, so the gate would not start the dependencies), and a Linux host (read, not run: the new block is Darwin-only). The probe's own error text was left as it was; with the default now handled, the case it describes is a Docker VM that shares less than `$HOME`.
