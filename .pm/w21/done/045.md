# Service Settings → Root Directory, Dockerfile Path, Docker Build Context, Build Filters and Health Check Path validate nothing in the editor: Save stays enabled, three of them ask "The service rebuilds and redeploys" before the server refuses, and the refusal arrives as a toast naming the wire field ("RootDirectory must be a relative path with no '..' components")

Why: a typo in a build setting is common (a Windows path `src\app`, a leading `../`, an unclosed `[`), and today the user confirms a rebuild that can never run, then reads a raw server toast with the wire field name in camel-case and English only.

**Severity:** minor (a refused save that first asks the user to confirm a rebuild; nothing is saved or built). **Estimate:** 45m (one shared relative-directory check plus a glob and a health-path check in the rows, hold the rebuild confirmation until the value is valid, tests, en+zh wording; and a corrected server message). **Kind:** sibling of [w21/038](done/038.md) (CIDR forms), [w4/145](../w4/done/145.md) and [w4/402](../w4/done/402.md) (static edge rules) and [w21/043](043.md) (static route rules): the server owns a rule and the editor mirrors none of it. **Source:** live `/qa-find-bugs` pass 52, 2026-11-11 01:2x UTC (2026-11-10 local), production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction; method: a client-versus-server validation differential on service Settings. **Status:** inbox.

## Root cause (code-traced; `origin/main` has no code change since the last pin)

- The dashboard has no validator for these editors. `grep -rni rootdir dashboard/src/features/services/{lib,components,hooks}` finds no validation, and the rows set no `aria-invalid`. The Port editor does mirror the server (`features/services/lib/port.ts` `parsePort`, 1-65535), and the static rules do ([w4/145](../w4/done/145.md), `static-rule-validation.ts`).
- Server rules:
  - `lego/backend/internal/store/api.go:691-707` `ValidRootDir`: empty is valid; at most 512 bytes; no NUL, CR, LF, TAB or backslash; no leading `/`; no `..` and no empty segment. It runs after `NormalizeRootDir` (`api.go:716-732`), which first drops `.` and empty segments, so `./`, `server/` and `a//b` are valid.
  - It guards rootDir at `apps/settings_check.go:172` and `apps/service.go:3373`, dockerfilePath at `settings_check.go:183` and `service.go:3376`, and the build context at `apps/docker_context.go:119`.
  - `normalizeHealthCheckPath` (`settings_check.go:148-155`) trims, then requires empty or a leading `/`.
  - `ValidGlob` (`api.go:740`) is non-empty, at most 512 bytes, no control character or backslash, no leading `/`, no `..` segment, and compilable by doublestar.
- The toast's capitalized wire names: `dashboard/src/common/lib/graphql-error.ts:34` capitalizes the first letter of the server sentence, whose field is written `rootDirectory`, `dockerfilePath`, `dockerContext`, `buildFilter.paths`.

## Fix (target behavior)

- Each of the five rows checks, before Save and in the row, the rules the server applies after the same normalization:
  - Root Directory, Dockerfile Path and Build Context accept `./`, `server/` and `a//b` and refuse an absolute path, a `..` segment, a backslash, a control character and more than 512 bytes.
  - Build Filter patterns refuse a leading `/`, `..`, a backslash, a control character, more than 512 bytes and an unclosed `[` (the doublestar compile stays server-side).
  - Health Check Path refuses a non-empty value without a leading `/` after trim.
- Each is marked with `aria-invalid` and an inline message, Save is held, and the "service rebuilds and redeploys" confirmation opens only for a valid value.
- The server's messages for the three directory fields name the rule that failed (too long, backslash, control character, absolute, `..`) instead of always saying `..` (`settings_check.go:173,183`, `service.go:3374,3377`, `github/service.go:946`). REST, GraphQL, MCP and Blueprint share these validators, so only the wording changes there.
