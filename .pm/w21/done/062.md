# A quiet Postgres's Top queries now reads "pg_stat_statements may not be enabled on this cluster", which is false: the empty list means the extension answered and nothing the customer ran is in it

Why: after w21/058 a quiet database finally shows Top queries' empty state, and that state tells the owner their cluster may be misconfigured when the backend has just proved the extension is enabled; a failed read already has its own "unavailable" line.

**Severity:** minor (a wrong hint on an empty state; no data is wrong). **Estimate:** ~20m (one string in en and zh, one test). **Kind:** consequence of [w21/058](done/058.md): the empty state it makes reachable carries copy written when the list was never empty. **Source:** live `/qa-find-bugs` pass 162, 2026-11-12 06:4x UTC, production `https://dashboard.bex.co`, workspace `bex`, deploy pin `84c4489a3` ("pin platform images to 10acf5314735", 2026-11-12T06:33:48Z, which contains the w21/058 fix `70f101a5a`; the deploy run finished 06:46Z), filed to w21 per user direction. **Status:** inbox.

## Reproduction (own Free Postgres `qa-20261112-pg2`, `dpg-dbqm1p0rcnqs73dmcum0`, no application, no console use; deleted at the end of the visit)

1. `POST /v1/postgres` `{"name":"qa-20261112-pg2","ownerId":"tea-d98210cbbpdc73dcrkvg","plan":"free","version":"16","region":"frankfurt"}` answers 201; wait for `available` (about 2 min).
2. Open `/databases/dpg-dbqm1p0rcnqs73dmcum0`, scroll to Insights (the sections load lazily), reload, scroll again. Top queries reads, both times:

```text
Top queries
No query stats yet — pg_stat_statements may not be enabled on this cluster.
```

3. `GET /v1/postgres/dpg-dbqm1p0rcnqs73dmcum0/query/top-queries` answers `200 {"topQueries":[]}`. The w21/058 DoD bullet 1 passes (no `begin read only` or `rollback` row).
4. The extension is enabled: the same panel's "Non-default parameters" lists `shared_preload_libraries = pg_stat_statements` (seen on the database from [w21/058](done/058.md)'s run), and the SQL console can read `pg_stat_statements` on it.

## Root cause (code-traced; `origin/main` at `00192f348` and later)

- The empty branch renders `databases.insightsNoTopQueries` (`dashboard/src/features/databases/components/insights-panel.tsx:207-210`), whose English text is "No query stats yet — pg_stat_statements may not be enabled on this cluster." (`dashboard/src/features/databases/locales/en.ts:1527-1531`; the zh text is `zh.ts:1481`).
- The panel already has a separate branch for a failed read (`insights.topQueriesError`, `:200-204`, "unavailable"), and the backend maps every failed read, including a missing extension, to `ErrUnavailable` with "the database must be reachable with pg_stat_statements enabled" (`lego/backend/internal/postgres/insights.go`, `TopQueries`, the `runAuthorizedInsight` error return). So an empty list that arrives with a 200 always means the extension answered and has no row for the customer.
- Until w21/058 the list was never empty on a running database (the panel's own envelope statements filled it), so the empty-state text was unreachable in practice and nobody saw it was wrong.

## Fix (target behavior)

- The empty state says what is true: no queries from the owner's workload have run yet (for example "No queries yet. Statements your application and the SQL console run will appear here."), and says nothing about the extension. The "extension missing" message stays only on the existing unavailable branch, if that branch needs a clearer line.
- en and zh change together; the key can keep its name or be renamed, but its description must say "the list is empty because nothing has run".
- Dashboard only. REST, GraphQL and MCP already answer `[]` for this state and an error for the other.

## Blast radius (counted by grep)

`databases.insightsNoTopQueries` has 1 render site (`insights-panel.tsx:209`) and 2 locale entries (`en.ts`, `zh.ts`). The Active processes and Table scans empty states have their own keys and are not touched.

## Adjacent classes

- A database whose extension really is missing answers an error, so it lands on the "unavailable" line, not on this text.
- A suspended or still-creating database is refused before the read (`requireQueryable`) and never reaches the empty state.
- A masked list (`insightsMaskedNote`) is a different branch.
