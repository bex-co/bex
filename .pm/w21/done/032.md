# Settings → Active sessions labels the sign-in time "Last active": the column and every Sign-out button name show Kratos `authenticated_at`, so the session in use right now reads "18m" and a browser used daily reads "6d"

Why: the card exists so a user can tell their live sessions from stale ones ([w4/006](../w4/done/006.md), [w4/m18](../w4/done/m18/README.md)), and "Last active" tells them the opposite of the truth for a session that is open right now.

**Severity:** minor (a mislabel; it can mislead which session to sign out). **Estimate:** 25m (relabel en and zh to what the value is, sort the rows by it, update 3 tests). **Kind:** label drifted from the data. **Source:** live `/qa-find-bugs` pass 29, 2026-11-10, production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction. **Status:** inbox.

## Reproduction (read-only: only Settings was read and one in-page `fetch`)

The QA session was created at about 10:49 PST by `scripts/qa-login.sh`, so its user agent is `curl/8.7.1`.

1. Open `/settings` → Security & Compliance → **Active sessions**: the current row `curl/8.7.1` `[This device]` `US` shows **Last active 17m**.
2. In the page, `fetch('/api/sessions', {credentials: 'include'})` at `2026-11-10T19:08:12Z` returns for the current session `authenticatedAt: "2026-11-10T18:49:47.523Z"` (18 minutes earlier) and the keys exactly `id,current,ipAddress,location,userAgent,authenticatedAt`. There is no activity field at all. This session had been loading dashboard pages and GraphQL continuously for those 18 minutes, so a real "last active" would read under a minute.
3. The other rows have the same shape. Their `authenticatedAt` ages are 59 min, 6493 min (4.5 d), 8526 min (5.9 d), 9189 min (6.4 d), 9196 min (6.4 d) and 7734 min (5.4 d), all rendered as "Last active …" and as the accessible name `Sign out <UA>, US, last active <age>`.

## Root cause (code-traced)

- `dashboard/src/common/server-fn/kratos-sessions.ts:42` maps Kratos `session.authenticated_at` to `authenticatedAt`, and nothing else about time.
- `dashboard/src/features/sessions/components/session-row.tsx:25-31,47,55` renders `session.authenticatedAt` as `lastActive`.
- The header is `activeSessions.colLastActive` ("Last active" / "最近活动", `features/sessions/locales/en.ts:41`, `zh.ts:40`, used at `active-sessions-panel.tsx:94`). The Sign-out aria-label is `activeSessions.revokeNamed` ("…, last active {lastActive}" / "…，最近活动 {lastActive}", `en.ts:74`, `zh.ts:73`).
- The label, not the data, drifted: the entry's own description reads "Active Sessions table column: last authenticated", and the original spec ([w4/m18/t003](../w4/done/m18/t003.md), executing inbox 006) says "authenticated-at".
- Kratos cannot supply activity. The pinned `@ory/client-fetch` 1.22.66 `Session` model carries only `authenticated_at`, `issued_at` and `expires_at` (`node_modules/@ory/client-fetch/dist/models/Session.d.ts:36,62,82`), and `SessionDevice` only `id`, `ip_address`, `location`, `user_agent`.

## Fix (target behavior)

The card says what it shows: column **"Signed in"** / **"登录时间"**, and the Sign-out aria-label **"Sign out {device}, {location}, signed in {age}"** / **"退出登录 {device}，{location}，登录于 {age}"**. It keeps the existing relative-age rendering and the w4/084 per-row names. No data plumbing and no new Kratos dependency.

Tracking real last-activity would need a bex-side tracker and is a different, larger decision: not proposed here.

## Adjacent, traced separately: the rows are not sorted

`kratos-sessions.ts:57-60` spreads `others` in Kratos's order and `active-sessions-panel.tsx:99` maps them as given. Live, the list after "This device" reads 59 min, 4.5 d, 5.9 d, 6.4 d, 6.4 d, 5.4 d. Target: the other rows sort by `authenticatedAt` descending, with the current session staying first.
