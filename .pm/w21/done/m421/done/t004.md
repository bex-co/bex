## Objective

`DELETE /services/{id}/env-vars/{key}` answered 409 `ENV_VAR_MANIFEST_MANAGED` for a variable removed from the manifest and after redeclaring it `sync: false`; `GET …/env-vars` returns 20 rows unless `limit` is passed. Verify Render's documented behavior for both, reproduce on the QA workspace, and fix what differs.

## Context

- `lego/backend/internal/secrets/service.go` `manifestEnv`: derived from the App's `spec.env` literals; a leftover key means no sync rewrote the App.
- Render's list endpoints default to `limit` 20 (check the API reference before changing anything).

## Steps

1. Read Render's env-var API and Blueprint pages and cite them in § Findings.
2. Reproduce with a Blueprint whose manifest drops a variable, on the QA workspace; decide whether the leftover is a sync gap or a derivation gap and fix the cause.
3. Tests on real Postgres; delete every fixture.

## Files

- `lego/backend/internal/secrets/`, `lego/backend/internal/apps/`

## Acceptance criteria

- [x] The leftover key can be deleted after the sync that removed it from the manifest, and a `sync: false` redeclaration frees it.
- [x] The list default matches Render's documented default, or ADR018 records the difference unsigned.

## Out of scope

- Variables a manifest still declares with a literal value (still manifest-managed, as on Render).

## Result

Shipped `a30c71abd` (deployed 10:17 UTC) and verified on production 2026-11-16: after a sync whose manifest drops `MESSAGE`, `DELETE` of it answers 204 and `PUT` answers 200 (409 `ENV_VAR_MANIFEST_MANAGED` before); `KEEPME`, still declared, stays 409. `GET …/env-vars` paging at 20 is Render's documented default.
