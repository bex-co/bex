# Backend, types and cli have no Go formatting gate, and six backend files are already unformatted

Why: in a tree several sessions share, whoever next runs `go fmt` sweeps unrelated files into their own diff, and a gate that never checks formatting lets the drift grow.

**Estimate:** ~40m. **Source:** `/pm-brainstorm for w21`, 2026-11-11 (a finding while shipping w21/041–053: `gofmt -l` named files nobody in the session had touched). **Status:** inbox.

## Evidence

- `gofmt -l` in `lego/backend` lists six files: `internal/agentsession/sessionceiling_test.go`, `internal/apps/config_rollout_test.go`, `internal/logs/service.go`, `internal/registrycreds/pullsecret.go`, `internal/secrets/batch_quota_test.go` and `internal/webhooks/agent_events_test.go`. `lego/types`, `lego/operator` and `lego/cli` list none.
- `lego/operator/.golangci.yml:68-70` enables the `gofmt` and `goimports` formatters, and the operator's `make test` runs `go fmt ./...` (`lego/operator/Makefile`, `fmt` target). `lego/backend/.golangci.yml` has no `formatters:` section; `lego/types` and `lego/cli` have no golangci config. So only the operator is held to formatting.
- `internal/logs/service.go` has `"maps"` after `"io"`: it arrived with commit `2290efebb` (w4/584, w4/585), which passed every gate.
- `make lint` (`lego/operator/Makefile`, `lint` target) runs `golangci-lint run` in each of the four modules and `hack/deadcode.sh`; none of that checks `gofmt` output for the three unconfigured modules.

## Fix

1. `gofmt -w` the six files (check each with `git log -1 -- <file>` that no other session has it uncommitted; they are formatting-only changes).
2. Add a formatting check to `make lint` that covers all four modules and does not depend on how golangci-lint treats formatters: for each module run `gofmt -l .` and fail with the file list if it prints anything. Optionally also add the `formatters:` section to `lego/backend/.golangci.yml` as the operator has.
3. Run `bash scripts/ship-gates.sh origin/main` once to be sure the gate still passes on a Go-only change.

## Definition of done

- `gofmt -l .` prints nothing in `lego/types`, `lego/operator`, `lego/backend` and `lego/cli`.
- A deliberately misordered import in a backend file makes `make lint` fail with that file's name, and the check passes again after reverting it (record both runs).
- The fix does not touch any file besides the six and the lint wiring.

## Not verified

- Whether `golangci-lint run` itself fails on the operator's formatters (golangci-lint v2 may only apply them through `golangci-lint fmt`); the `gofmt -l` check above makes the answer irrelevant.

**Done 2026-11-11:** the six files are `gofmt -w`'d (formatting only: three import or blank-line fixes, one struct-literal layout, two comment alignments), and two checks now fail on drift:

- `make fmt-check` (`lego/operator/Makefile`) runs `gofmt -l` over the operator, backend, types and cli, and `make lint` (the `go-lint.yml` CI job) runs it first. It does not depend on how golangci-lint treats formatters, which the note left unverified. The backend's own golangci config was left as it was.
- `scripts/ship-gates.sh` runs `gofmt -l` on the Go files the push changes (`lego/**/*.go`, changed since the base), so a local ship stops before CI does, in about a second and without blocking a push on someone else's drift.

Checked: with `"maps"` and `"io"` swapped in `lego/backend/internal/logs/service.go`, `make fmt-check` failed naming `../backend/internal/logs/service.go` and the gate snippet exited 1 with the same name; after restoring the file both passed, and `gofmt -l` is empty in all four modules. `make lint` as a whole was not run (it builds the pinned custom golangci-lint); `make -n lint` shows `fmt-check` as its first step.
