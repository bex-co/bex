## Objective

Add the read tool `wait_agent_sessions {ids(1–20), until:any|all, timeoutSeconds(1–25,default 25)}` returning `{sessions, settled, timedOut}`. Handler reads once, then waits on `LISTEN agent_session_state` (NOTIFY added to phase/turn writes) with a 2 s re-read fallback; emits `notifications/progress` when the client sent a `progressToken` (ADR094 D6).

## Context

- Settled = `state != working`. Cap 25 s because bex-api `HTTPWriteTimeout` is 30 s (`api/graphql_cost.go`).
- Each pod shares one LISTEN connection; counts once against the read rate limit.
- Transport stays stateless (ADR025).

## Steps

1. Add NOTIFY on phase/turn writes in the store.
2. Implement a shared per-pod listener fan-out.
3. Implement the tool, annotations (read-only), progress notifications, golden entry.

## Acceptance criteria

- [ ] A waiter on a working session returns within ~1 s of the state change; `timedOut:true` at 25 s otherwise.
- [ ] `until:any` vs `all` semantics tested; works when the change happens on another replica.
- [ ] Lost NOTIFY is recovered by the fallback re-read.
