## Objective

Pin the launcher's behavior and keep ADR113's coverage contract for extended commands.

## Context

- [ADR113](../../../docs/ADR113-cli-usage-telemetry.md) D7: a command that replaces the process must call `telemetry.EmitLaunch` just before; `lego/cli/telemetry_coverage_test.go` keeps the reviewed list `processReplacers` of the module's process-replacing call sites. `docs/bex-cli.md` lines on extended-command telemetry and `docs/runbooks/cli-analytics.md` describe it.

## Steps

1. Add the `bex s3` call sites to `processReplacers` and make the commands call `EmitLaunch`.
2. Extend the disclosure and coverage tests.
3. Add a contract test that runs the launcher binary against a fake `aws` on PATH and a fake bex-api.

## Files

- lego/cli/telemetry_coverage_test.go
- lego/cli/ (the S3 launcher package)
- docs/runbooks/cli-analytics.md

## Acceptance criteria

- [x] `go test ./...` in `lego/cli` passes and fails if a `bex s3` call site is not in `processReplacers`.
- [x] The launch event is emitted before the process is replaced.

## Out of scope

- Server-side coverage counters beyond ADR113.

## Result

Done 2026-11-19. `telemetry_coverage_test.go` lists `internal/s3/launch.go execAWS` in `processReplacers` with `TestBexS3LaunchEmitsExactlyOneEvent` (deleting the entry fails `TestEveryProcessReplacingCallSiteIsReviewed`, and dropping the `EmitLaunch` hook fails the launch test; both were mutation-checked). `s3_contract_test.go` runs the built binary against a fake `aws` on PATH and a fake bex-api: one stored event for `bex s3` and one for `bex s3api`, named by the commands alone (no bucket, key or secret in any body); the exact command line and environment the AWS CLI received, with a person's own `AWS_PROFILE`, session token, keys, config file and endpoint set and none of them reaching it; nothing created under `~/.aws`, the cached key mode 0600; `bex s3` with no `aws` is one `execution_error` from upstream's hook and mints no key; `env`, `keys list` and `info` report once each through the hook; and the disclosure gate's opt-out does not reach the AWS CLI. `disclosure_test.go`'s headless-run test now includes `bex s3 ls`. `scripts/cli-analytics.sql` maps `s3` and `s3api` to the `data` command family (with `test_command_family_mapping` and the runbook's table; the view on production is re-applied with `scripts/cli-analytics-bootstrap.sh`, until then the two read as `other`), and `docs/runbooks/cli-analytics.md` and the `internal/telemetry` package comment name the new launches.
