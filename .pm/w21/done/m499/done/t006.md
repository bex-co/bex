## Objective

Check the `bex s3` command family against the Render CLI conventions it extends and flag drift as follow-up work; Render has no S3 command.

## Context

- Surface: `bex s3`, `s3api`, `env`, `keys`, `public`, `info` in the `bex` launcher (`docs/bex-cli.md`); the launcher's other bex-native commands (`bex code`, `bex edit`, `bex agent`, `bex upgrade`) are the convention for flags, `--output` and exit codes.

## Steps

1. Compare flags, output formats and exit codes with the other bex-native commands.
2. Confirm `bex ea objects` and the Render CLI contract are unchanged.
3. Record any difference in the `bex-cli.md` section or as a follow-up note.

## Files

- docs/bex-cli.md

## Acceptance criteria

- [x] Every difference from the launcher's conventions is fixed or written down with its reason.

## Out of scope

- Fixing drift found here beyond one-line corrections; file it instead.

## Result

Done 2026-11-19. Render has no S3 command, so the comparison is with the launcher's own bex-native commands (`bex agent`, `bex code`, `bex edit`, `bex upgrade`). **Same:** `env`, `keys`, `public` and `info` take the root `-o json|yaml|text` (json and yaml print the API's own answer), use the active workspace (`bex workspace set` or `BEX_WORKSPACE`), exit 2 on a usage error (a malformed bucket or key id, an unknown action, `--expires-in` over 12 hours) and 1 on any other failure, and each reports once through ADR113 D7. **Different, and written down with its reason in the `bex-cli.md` section:** `bex s3` and `bex s3api` parse no bex flag (they are pass-throughs like `bex glm`, so `--output`, `--region` and `--profile` are the AWS CLI's) and their exit status is the AWS CLI's; there is no per-command `--workspace` (as `bex agent`). `bex ea objects` and the pinned Render CLI contract are unchanged: no file of `object_storage_test.go`, `internal/branding` or the bridge changed, and `go test ./...` in `lego/cli` passes, including the pinned-CLI contract tests. No drift needed filing.
