## Objective

Bound the static server's origin fetches per client as well as per site, so a flood of unique missing paths on four sites cannot make every other tenant's cold objects answer 503 on a replica.

## Context

- Finding R25-05 (Low; likelihood high, impact low). `lego/operator/internal/staticserver/fetchgate.go:35-36,80-96`: 4 slots per site (`site.AppID`), 16 per replica, non-blocking, 503 `server busy` when full; `staticserver.go:707-747` takes a slot for a full S3 GET per unique missing path and only then stores a negative entry under the exact path, so singleflight and the negative cache never help; `cache.go:80-138` evicts at random within a site's 32 MiB budget so negative entries evict real objects. Reproduced with the real handler: 0 to 3 attacker sites leave a victim at 300x200, 4 or 8 sites give 300x503.
- A workspace-keyed gate or reserved global slots are NOT enough (the attacker floods other tenants' sites). Recommended by the validator: a per-client in-flight cap of about 2, the client taken from the sanitised `True-Client-IP` (set by the Traefik plugin, `clientipheaders.go:128`; only Traefik reaches the static server), IPv6 collapsed to /64; about 40 lines.
- The rewrite proxy gate has the same shape and is ADR103's; do not change it here.

## Steps

1. Write the failing test first in `lego/operator/internal/staticserver/concurrency_test.go`: with a blocking origin, one client takes 4 slots on each of 4 sites; a second client's cold miss on a fifth site must return 200 (today 503); add the same-site variant.
2. Add the per-client cap to `fetchGate.acquire` and pass the client key through the request context from `ServeHTTP` to `get`; fall back to the peer address when the header is absent.
3. Keep negative entries in a separate small per-site budget in `cache.go`; test that 150K unique 404s no longer evict a site's cached real objects.
4. Run `make test` for the operator (staticserver package at least) and `make lint`.

## Result (2026-11-14)

- **Per-client cap.** `lego/operator/internal/staticserver/clientkey.go` adds `clientLimiter` (non-blocking, in-flight count per client, entry deleted at zero so the map is bounded by the replica's 16 slots) and `clientKey(r)`: the `True-Client-IP` the Traefik `clientipheaders` plugin sets (`deploy/gitops/charts/traefik-plugins/clientipheaders/clientipheaders.go:128`: Cloudflare's `CF-Connecting-IP` when the peer is a Cloudflare range, else the peer), else the connection's peer host; IPv4-mapped addresses unmapped, zones dropped, IPv6 collapsed to its /64. `ServeHTTP` stores the key in the request context; `get` takes a client slot in the singleflight leader before the site/replica gate and sheds `ErrOverloaded` (503 + Retry-After, the existing overload answer). A request with no usable address (key `""`) is not client-limited, so a missing header can never put every visitor in one bucket.
- **The cap is 3** (`defaultMaxClientFetches`, reason in the code): a single visitor's cold page still fetches its HTML, stylesheet and script at once, and 13 of the replica's 16 slots and one of any site's 4 stay with other visitors. The validator's "about 2" would have shed more of a legitimate cold page; the existing per-site cap of 4 already bounded a one-site visitor, so 3 costs it one slot. Many visitors behind one NAT address share the cap, which only matters while cold fetches are in flight.
- **Negative entries** (`cache.go`): a confirmed miss (and encoding.go's "incompressible" marker, which shares the `negative` flag) has its own per-site budget (`min(perSiteBudget/8, 1 MiB)`, about 3000 entries), makes room only by evicting this site's other negative entries, and is not cached rather than displacing a real object under the site or global byte budget. A real object may still evict negative entries to fit. A review pass dropped the first draft's global negative-only eviction: with few negatives in a full cache it scanned the whole entries map under `cache.mu` per put.
- **Tests** (`client_gate_test.go`, all with the real `Handler` and a holding origin, run with `-race`):
  - `TestOneClientCannotStarveOtherTenantsSites`: one client floods 4 sites x 4 held paths; another client's cold miss on a fifth site answers 200 (before: every slot held, 503).
  - `TestOneClientCannotPinAWholeSite` (same-site variant), `TestClientKeepsEnoughSlotsForAColdPage`, `TestClientSlotsAreReturned`, `TestRequestWithoutAClientAddressIsNotClientLimited`, `TestClientKey` (10 cases incl. /64 collapse, mapped IPv4, zone, fallback).
  - `TestNegativeEntriesCannotEvictRealObjects` (150,000 unique 404s; 8 real objects survive; negative use stays within its budget), `...FromManySitesCannotEvictRealObjectsGlobally` (40 sites under an 8 MiB budget), `TestRealObjectDisplacesNegativeEntries`.
  - Mutation checks: with `acquire` always admitting, the two starvation tests fail; with negatives on the real-object path, both budget tests fail; with the empty-client exemption removed, its test times out. The existing per-site cap test still passes.
- **Suites.** `make lint` exit 0; `GOWORK=off make test` exit 0 (plain `make test` fails in controller-gen under the workspace, as `lego/AGENTS.md` says platform suites run `GOWORK=off`).
- **For t005's ADR109.** The cap raises the price of the attack from one address to a set of /64s: an attacker with 6 or more distinct sources (3 slots each) can still fill the 16 replica slots, which is ADR066's accepted "edge/LB rate limiting" residual, not a new gap. `True-Client-IP` is trusted because only Traefik reaches the static server and the plugin overwrites any client-sent value (`alwaysStripped`). The rewrite proxy gate (`proxy.go`, ADR103) is unchanged. t017 can reuse `canonicalClient` for the pg-sni-proxy /64 key.
