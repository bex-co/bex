## Objective

Stop a tenant's never-answering app from pinning the activator's shared hold slots, and stop one tenant's slow maintenance URLs from delaying other tenants' maintenance pages.

## Context

- Finding R25-02 (Low). `lego/operator/cmd/activator/hold.go:274-298` `serve` takes a global (256) and per-App (64) slot, clears the server read and write deadlines (`:282-283`) and keeps the slot through `ReverseProxy.ServeHTTP` (`:296`); the transport (`:127-170`) has no `ResponseHeaderTimeout`; Traefik has none either. Only non-HTML requests to an App that is waking (hibernated or within the 120 s wake window) are held (`main.go:263`). Four hibernated attacker apps x 64 requests, accepting and never answering, pin 256 slots per replica; a victim's request is shed in 1 ms with `503 service not ready` (the wake still happens). ADR103 F2 fixed the same class on the static rewrite proxy with caps plus a 30 s `ResponseHeaderTimeout` (`staticserver/proxy.go:87`).
- Hardening R25-11. `main.go:573-578`: a caller waiting on the 16-slot custom maintenance fetch semaphore blocks until a slot frees or its request ends, with no stale fallback while waiting (stale only after an error, `:597-605`); 16 slow paid-service URLs delay a victim's page 4 s. Fix: non-blocking acquire falling back to the stale snapshot or the default page.
- Validator prototype for R25-02: release the slot once `wait` returns true, before `proxy.ServeHTTP`, plus a `ResponseHeaderTimeout` of about 100 s; the full activator package passed, including `TestHeldRequestLimitShedsToTheImmediateAnswer` (`hold_test.go:188`, only calls `admit`); WebSocket upgrades keep working because httputil handles 101 itself (ADR007:70).

## Steps

1. Write the failing tests first: hold: swap in a hung in-process `RoundTripper`, fill the global slots with proxied exchanges, assert a victim's cold-start request is still served (today slots in use 256, victim 503); maintenance: with 16 busy slots and a snapshot past TTL but inside the stale window, the fetch answers from the snapshot at once (today it waits 4 s).
2. Release the slot after `wait` returns true and before proxying; add `ResponseHeaderTimeout` about 100 s to the transport.
3. Make the maintenance fetch acquire non-blocking with the stale or default fallback.
4. Run the activator package tests and `make lint`.

## Result (2026-11-14)

- **R25-02.** `cmd/activator/hold.go`: `serve` now returns its hold slot (global and per-App) as soon as the wake wait succeeds, before `ReverseProxy.ServeHTTP` (`release` is a `sync.OnceFunc`, so the deferred call is a no-op on that path and still frees the slot on a timed-out wait or a client that left). The slot covers the wait only; a hung app, a long upgrade or a stream no longer holds one. The proxy transport gets `ResponseHeaderTimeout: proxyResponseHeaderTimeout` (100 s, Render's HTTP request timeout, held in a `holder.responseHeaderTimeout` field so a test can shorten it); a woken app that accepts and never answers ends as the existing `502 bad gateway`.
- **R25-11.** `cmd/activator/main.go`: the custom maintenance fetch acquires its slot without waiting and returns `errCustomPageFetchBusy` when all 16 are taken, so the fetcher's existing `staleSnapshot` fallback answers at once; with no snapshot `serveMaintenanceWithFetcher` writes the default maintenance page (`503`) for that error only. Any other fetch error is still `502 custom maintenance page unavailable`.
- **Tests** (`hold_slot_test.go`, `maintenance_busy_test.go`; `-race`):
  - `TestHungAppDoesNotPinHoldSlots`: two slots, two `/hang` exchanges in flight, `len(h.total) == 0`, and a third request is served (before: 2 slots held, 503).
  - `TestUnansweringAppEndsAtTheResponseHeaderTimeout` (the transport carries the 100 s constant; a 200 ms override ends an unanswered exchange as 502).
  - `TestUpgradeThroughTheHoldPathStillWorks`: a real server, a hijacked `101` upstream, an open upgrade holds no slot and echoes `ping` (the acceptance criterion for WebSocket).
  - `TestBusyMaintenanceFetchServesTheStaleSnapshotAtOnce` (16 busy slots, a snapshot past the TTL inside the stale window: served in well under 500 ms; before: 3.0 s, the test's context), `TestBusyMaintenanceFetchWithNoSnapshotAnswersTheDefaultPage` (before: 502 after 3 s), `TestFailedMaintenanceFetchStillAnswersBadGateway`.
  - Before the change the first five fail on behavior; the existing `TestHeldRequestLimitShedsToTheImmediateAnswer` and the rest of the package pass.
- **One existing test changed.** `TestCustomPageCacheBoundsConcurrentOriginFetches` (64 distinct slow URIs at once) asserted that every caller eventually succeeds, which is the queueing R25-11 removes; it still asserts at most 16 reach the origin at once, and now accepts `errCustomPageFetchBusy` for the callers that found every slot taken.
- **Suites.** `make lint` exit 0; `GOWORK=off make test` exit 0 (the activator package also re-run with `-race` after the last line wraps). While landing this, main's `go lint` was red from w4/636 (three activator lines over 120 characters; green at `70e8c1650`, red from `902bddbec`), so that was fixed and shipped first, alone, as `67f7ca378` `fix(ci)`.
- **Not done** (out of scope, per the finding): a separate cap on proxied exchanges, a per-namespace slot share, a per-owner cap on the maintenance fetch. For t005's ADR109: with the slot released after the wake, the remaining pin is the exchange's own goroutine and socket, bounded by the 100 s header timeout for a silent app and unbounded for a streaming one (as Render's).
- **Correction (2026-11-14, found by w8's QA loop, fixed as w8/329 in `b2b4bee9d`).** The 100 s header timeout above was wrong: it came from the finding's "about 100 s" and was not checked against Render, whose documented limit is 100 **minutes** (render.com/docs/render-vs-vercel-comparison § Long-running requests). It is now `100 * time.Minute`. The slot release, the 502 for a silent app and the maintenance fallback stand. For t005's ADR109: a silent exchange is bounded at 100 minutes, not 100 seconds.
