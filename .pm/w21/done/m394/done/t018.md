## Objective

Check that the fixes that change tenant-visible behavior agree with Render on every surface they touch: the dashboard (`/assets` and link rendering), the REST, GraphQL and MCP custom-domain add and Blueprint domain paths in `lego/backend/` (same refusal semantics and error shapes, `docs/ADR006-bex-api.md`), and tenant-visible request and response behavior of the static server, activator and edge cache. Compare against render.com's observable behavior and flag any drift as follow-up work rather than silently diverging.

- Fixes that change what a tenant or visitor observes: t013 (custom-domain claims: when an add or a Blueprint `domains:` entry is refused as in use, and when a stale pending claim is reclaimed; Render's custom-domains page and its 'domain already exists on another site' behavior), t015 (X-Forwarded-\* passed through, as Render's Cloudflare-fronted cache does), t009 (503 under overload), t011 (a dropped host stops answering), t004 and t016 (dashboard behavior).

## Result (2026-11-14)

The comparison is recorded in ADR110 § Render parity; no fix creates a divergence, so ADR018 needed no sign-off and was not amended. Render sources read on 2026-11-14: render.com/docs/custom-domains, render.com/docs/web-service-caching, render.com/docs/static-sites, render.com/docs/render-vs-vercel-comparison, Render's DDoS article and community threads for the forwarded headers.

- **t013, custom-domain claims.** Render's custom-domains page documents no "already in use" error text, no reservation period and no rule for an unverified domain, so the 48-hour reclaim is bex's choice where Render is silent (already in ADR005 before this round). REST, GraphQL, MCP, the dashboard (through those) and Blueprint all call `Service.AddDomain` (`lego/backend/internal/apps/domains.go:1640`, `mcp.go:958`) or `ReplaceDomainClaims` (service create, `service.go:2975`; Blueprint, `blueprint_setting_events.go:87`), which map the store's `ErrConflict` once to `core.ErrConflict` (409, "already exists on another site"). t013 changed only when a stale claim stops conflicting, in the store beneath them, so the surfaces cannot disagree.
- **t015, forwarded headers.** `X-Forwarded-For: client, peer`, `X-Forwarded-Proto: https` and `True-Client-IP` match what an app on Render sees (the docs page names none of these headers; the evidence is Render's DDoS article, community threads and ADR018's w8/m118 row for the scheme).
- **t011, a dropped host.** Render's page does not describe a removed domain's routing; there is nothing to diverge from.
- **t012.** Render allows HTTP responses up to 100 minutes; my first value (100 s) was wrong and w8's QA loop corrected it (w8/329, `b2b4bee9d`). See t012's correction and the memory note on checking Render numbers.
- **t009, overload: drift risk, filed as w21/067.** Render's static-sites page says the site is served over a global CDN and documents no per-visitor limit and no 503. bex's static server shed a 5th concurrent cold fetch of one site before; it now sheds a visitor's 4th. A fix would let an over-cap request wait briefly for a slot; the note has the measurement step.
- **t004, t016, t010, t014, t017.** No Render counterpart (dashboard internals, the operator's registry client and reconcile queue, proxy limits).
