## Objective

Parse the bearer realm as a URL instead of testing string prefixes, so a tenant's registry can no longer direct the operator's plaintext request at an in-cluster host.

## Context

- Finding R25-03 (Low). `lego/operator/internal/registry/image_config.go:264` accepts the realm by `HasPrefix` of `https://`, `http://127.0.0.1` or `http://localhost` (comment at `:247-248`: loopback for local registries in tests; ADR089:236: the realm is https); `service` and `scope` are appended unescaped (`:273-277`) and the raw string goes to `http.NewRequestWithContext` (`:279`). `http://127.0.0.1@zot.bex-registry.svc:5000/v1/sys/internal/x?probe=1`, `127.0.0.1.attacker.example`, `localhost.attacker.example`, `127.0.0.100` are accepted; the production transport dials them (the dial guard blocks only link-local, multicast and unspecified addresses, `lego/types/netutil/ssrf.go`).
- Reachable by any tenant that can create an image web service on a registry it controls (`lego/backend/internal/store/image.go:42` accepts any public dotted host). No platform credential is attached; no in-cluster token-returning endpoint was found. Not the ADR061 #12 / ADR063 #10 / ADR064 #18 residual.
- `bearer_test.go:38` and `image_config_test.go:203` use `http://127.0.0.1:port` httptest realms; they must keep passing.

## Steps

1. Write the failing table test in `lego/operator/internal/registry/image_config_test.go`: each of the realms above (and uppercase `HTTP://`, a userinfo form, a fragment) must return an error without invoking the client's `RoundTripper`; positive rows `http://127.0.0.1:PORT/token`, `http://localhost:PORT/token` and `https://auth.docker.io/token` must pass.
2. `url.Parse` the realm; reject userinfo and fragment; allow `https`, or `http` only where `Hostname()` is exactly `127.0.0.1`, `localhost` or `::1`; build `service` and `scope` with `url.Values`.
3. Run the registry package tests and `make lint`.

## Result (2026-11-14)

- `lego/operator/internal/registry/image_config.go`: `bearerToken` now calls `parseBearerRealm`, which `url.Parse`s the realm and refuses an empty host (covers `//host`, `https:token`, `https:///x`), userinfo and a fragment, and allows `https`, or `http` only where `Hostname()` is exactly `127.0.0.1`, `localhost` or `::1`. `service` and `scope` are set through `url.Values` (the realm's own query is kept), so an `&` inside either is a value, not a new parameter. `fetchOnce`'s `url` parameter became `target` because it shadowed the new `net/url` import (revive).
- Test: `bearer_realm_test.go`. 16 rejected realms (the four from the finding, `127.0.0.1.:5000`, `[::2]`, userinfo on http and https, `HTTP://` on a non-loopback host, a fragment, `ftp://`, `//host`, `https:///token`, `https:token`, a bare path) must error without the client's `RoundTripper` running; 5 accepted (`http://127.0.0.1:5001`, `localhost`, `[::1]`, `https://auth.docker.io/token`, an https realm with its own query) must fetch with `service` intact; one test injects `service="a&scope=repository:admin:*"` and asserts a single `scope` parameter equal to the challenge's. Against the old prefix check 10 of the rejected/accepted rows and the escaping test fail (the exploit realms were all requested); the existing `bearer_test.go` and `image_config_test.go` loopback httptest cases pass unchanged.
- `make lint` exit 0; `GOWORK=off make test` exit 0.
- Not changed (out of scope, per the finding): a public-only dial guard for realms, and an https realm whose DNS name resolves to a private address (the accepted residual).
