## Objective

Make the edge-cache sidecar's memory accounting honest so unique cacheable 404s cannot OOM it, and make it pass Traefik's `X-Forwarded-For` and `X-Forwarded-Proto` through as ADR004 says.

## Context

- Finding R25-06 (Low). `lego/operator/internal/edgecache/edgecache.go:422-437` `store` charges only `len(e.body)` (`:428`): the key, the cloned headers and the structure are free, there is no entry-count bound, and expired entries are removed only in `lookup` (`:256`) when the same key is looked up again; a 404 is cached 3 minutes with no directive (`defaultTTL` `:86`; `requestEligible` `:209-225`). 100K unique `.css` 404s accounted 1.81 MiB and used 72 MiB (756 B/entry); the real binary reached 250 MiB at 250K requests against the 160Mi limit (`lego/operator/internal/controller/edge_cache.go:64-83`: `GOMEMLIMIT` 120MiB, budget 48 MiB). Opt-in (paid web service with `cacheProfile`). ADR004 (`docs/ADR004-app-deployment.md:402`) says the memory is bounded.
- Finding R25-07 (Low). `edgecache.go:171-174`: `Rewrite` strips the inbound `Forwarded`/`X-Forwarded-*` (Go semantics, verified on the pinned toolchain) and `SetXForwarded` sets `X-Forwarded-For` to the Traefik peer and `X-Forwarded-Proto` to `http`; `True-Client-IP` and `X-Real-Ip` survive. Apps that read XFF or the proto header see one client address and `http`. ADR004 says 'identical forwarding headers either way'; the activator's proxy (`hold.go:117-134`) already copies them from the trusted ingress. Safe because Traefik sanitises XFF and only Traefik, same-workspace pods and the activator reach the sidecar (`namespaces.go:725-800`); treat copying `Forwarded` as optional (Traefik's sanitising of it is unverified).
- `TestTheCacheStaysWithinItsByteBound` (`edgecache_test.go:183`) asserts body-only accounting and must be re-based.

## Steps

1. Write the failing tests first in `lego/operator/internal/edgecache/edgecache_test.go`: 5,000 unique tiny-body 404s with `MaxBytes` 1 MiB keep `len(h.entries)` and `h.size` within bounds; empty-body 301s with 7 KB keys have non-zero `h.size`; after the clock passes the TTL a new `store` drops expired entries; `TestForwardedHeadersSurviveTheCache` with a Traefik-shaped request (peer 10.10.0.5, client 198.51.100.77, https): the upstream must see `X-Forwarded-For: 198.51.100.77, 10.10.0.5` and `X-Forwarded-Proto: https`.
2. Charge `len(body)+len(key)+header bytes+a fixed per-entry overhead`; add a `MaxEntries` cap with LRU eviction; reap expired entries from the LRU tail on `store`; re-base `TestTheCacheStaysWithinItsByteBound`.
3. Copy the inbound `X-Forwarded-For` and `X-Forwarded-Proto` into `pr.Out.Header` before `SetXForwarded` (append the peer to XFF).
4. Run the edgecache package tests and `make lint`; run the real binary once with the production settings against a 404 app and record the RSS after 250K requests.

## Result (2026-11-14)

- **R25-06, accounting.** `internal/edgecache/edgecache.go`: `entryCost` charges `len(body) + len(key) + every header name and value + entryOverhead` (1 KiB, rounded up from the measured 756 B of structure), and `store` and `removeLocked` share it, so an entry is released for exactly what it was charged. Because every entry costs at least the overhead, the byte budget also bounds how many entries the cache holds; a separate `MaxEntries` cap would only restate that, so none was added (the step's optional item). `store` also drops expired entries from the cold end of the LRU before evicting live ones, so a 404's 3-minute entry no longer stays until its key is asked for again.
- **R25-07, forwarding.** `Rewrite` copies the inbound `X-Forwarded-For` before `SetXForwarded` (which appends the Traefik peer) and passes an inbound `X-Forwarded-Proto` of `http` or `https` through; any other value keeps `SetXForwarded`'s `http`. A Traefik-shaped request (peer 10.10.0.5, client 198.51.100.77, https) reaches the app with `X-Forwarded-For: 198.51.100.77, 10.10.0.5` and `X-Forwarded-Proto: https`; `True-Client-IP` still survives. `Forwarded` is not copied (the finding's optional item: Traefik's sanitising of it is unverified).
- **Tests** (`edgecache_accounting_test.go`; the byte-bound test in `edgecache_test.go` re-based to size the cache from one entry's real charge): 5,000 unique 404s under a 1 MiB bound keep at most `1 MiB / 756` entries (before: 5,000); an empty-bodied 301 with a 7 KB key and a 500-byte header is charged over 7,500 (before: 0); 1,000 expired 404s are gone after the next store and `h.size` equals the live entries' cost (before: 1,001 entries); the forwarded headers above; an odd `X-Forwarded-Proto` is not passed on. All but the last fail on the old accounting and forwarding.
- **Real binary, production settings** (`BEX_EDGE_CACHE_MAX_BYTES=50331648`, `GOMEMLIMIT=120MiB`, profile `origin-controlled`, an upstream answering 404 `not found` to every path, 250,000 sequential unique `/assets/missing-N-xxxxxxxxxxxxxxxxxxxx.css` requests with `Host: victim.onbex.co`, all answered 404): **old 247 MiB RSS, new 84 MiB**, against the sidecar's 160Mi limit. The old figure reproduces the finding's 250 MiB. Measured on macOS arm64 with `ps -o rss` (a Go heap's resident size is the same order on Linux). A first run at 64 concurrent requests exhausted the Mac's ephemeral ports through the sidecar's default upstream transport (`MaxIdleConnsPerHost` 2) and answered 502 for about 60% of requests, so the numbers above are from 2 concurrent requests; that transport setting is outside this task.
- **Suites.** `make lint` exit 0; the edgecache package passes with `-race`; the controller's edge-cache tests pass; the full operator suite runs unchanged code paths elsewhere (`GOWORK=off make test` last ran in full on the commit before this one).
- **For t005's ADR109.** `docs/ADR004-app-deployment.md:402` says the cache memory is bounded; it now is by the charge above, and its "identical forwarding headers either way" now holds for `X-Forwarded-For` and `X-Forwarded-Proto`. Still open and out of scope: slow-leader blocking and the missing server timeouts on the sidecar; an upstream transport with more idle connections per host.
