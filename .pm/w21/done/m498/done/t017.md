## Result

Done 2026-11-19. /simplify ran over every commit of the milestone (t006 to t012 before the first, t013 to t015 before this one), each as reuse, quality and efficiency reviews, and the findings were applied behavior-identically with the suites green. **Applied:** the S3 error constructors (`errMalformedXML`, `errInvalidRequest`, `errSlowDown`) in place of repeated literals; `confirmOrDiscard` for the put, copy and multipart-complete tail; `GetObject` delegating to `GetObjectWith`; one `validateName` for keys and listing prefixes; the client address key from `netutil.SourceKeyString` instead of a copy of it; `denialDedupe.repeat`; `etagEqual` and `ConditionStatus` shared by the copy conditions and the reads; `CompletedPart` instead of a duplicate type; `classify` for the multipart store errors; a single-statement part upsert; workspace-scoped queries that use their index; CRC-64/NVME computed with a table built once (the standard library's rebuilds one per 2 KiB write, which is the AWS CLI v2 default checksum); the pacing buckets kept as long as the longest stream (a swept bucket handed the next stream a full burst); per-workspace gate locks instead of one for the replica; zero entries of the in-flight map deleted; the listing limit checked before the bucket row is read. **A bug the review found and a test now pins:** a suffix range on `UploadPartCopy` (`bytes=-5`) counted one byte too many against the quota, and S3 only defines `bytes=first-last`, so the copy range is now parsed strictly (400 InvalidArgument). **Not applied, with reasons:** a `size_bytes` column on the upload row to avoid summing parts on every part (worst case 100 uploads of 10,000 parts, and the sum is indexed through the primary key; file it if a workspace gets near it); folding the preamble of the multipart service methods into one helper and the three abort paths into one (the paths differ in whether they keep the row on failure, and merging them hides that); a typed error from `putSigned` in place of matching `NoSuchUpload` in Wasabi's answer (the probe of 2026-11-19 shows the code is stable); merging the response-header block with Contract B's `writeObjectHeaders` (Contract B is removed in m500); the conditional-read evaluation in the fake S3, which is a fake. The migration comment that cites t013 is left as written because the migration is applied.
