## Objective

A table's owner repacks it as Render's guide describes.

## Context

- Render's guide: install the client matching the extension version, run `pg_repack --no-superuser-check --dbname=<EXTERNAL_DATABASE_URL> --table=<TABLE_NAME>`, never through the connection-pool URL; the table needs a primary key or a non-null unique index; free storage of twice the table ([postgresql-pg-repack](https://render.com/docs/postgresql-pg-repack)).
- The image carries pg_repack 1.5.3 on 16+ with the `repack` schema grants (w21/m584 t003). pg_repack's C functions require ownership of the table (`lib/repack.c:120`).

## Steps

1. Gate: as the owner, create a table with a primary key, update it to make dead tuples, run `pg_repack -k --table` with the image's client against the local instance, compare row counts and `pg_relation_size` before and after.
2. Production: same on a disposable 16+ database over its external URL with a 1.5.3 client.
3. Add a sentence to ADR009 (or ADR092) on the client version and the direct URL.

## Production (2026-11-24)

This ran on t003's disposable Free databases on 16.16, 17.12 and 18.7, as the owner, over the external URL. The client was pg_repack 1.5.3, built from upstream's `ver_1.5.3` tag (tarball sha256 `9439892c0b7c…`) against libpq 18.6. The image's own client could not reach production from this machine.

- Render's command ran as written: `pg_repack --no-superuser-check --dbname=<external URL> --table=public.repacked`. The owner's `CREATE EXTENSION pg_repack` gives 1.5.3. The table had a primary key and 100,000 rows, and its even ids were deleted. On each major the command exits 0 with `INFO: repacking table "public.repacked"`. The rows are unchanged (50,000 rows, the same md5 over every row), the filenode is new, and `pg_relation_size` goes from 6,832,128 to 3,416,064 bytes.
- A table owned by a second user (`POST /v1/postgres/{id}/users`, then `GRANT CREATE ON SCHEMA public` to it): the same command prints `WARNING: lock_exclusive() failed for public.others` and `ERROR: permission denied for table others`, exits 0, and leaves the filenode unchanged.
- The external URL carries `sslmode=verify-full`. On these new databases the publicly trusted certificate was still pending (`externalCertificate: failed`, "The certificate authority's issuance rate limit was reached"), so the client needed the connection info's `serverCaCertificate` as `PGSSLROOTCERT`.
