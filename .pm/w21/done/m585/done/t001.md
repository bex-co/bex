## Objective

ADR092 lists every untrusted extension on Render's list with the majors it is admitted on and why it is safe to admit.

## Context

- Render's table ([postgresql-extensions](https://render.com/docs/postgresql-extensions)): `old_snapshot` and `pg_surgery` are "PostgreSQL 14 or later"; `pg_repack` "PostgreSQL 16 or later". PostgreSQL 17 removed `adminpack` and `old_snapshot`, so they exist on 13–16 and 14–16.
- w8/276's evidence table names the 22 refused on 18 and a sample on 16.
- The review facts in the milestone README (egress, `dblink`'s password rule, `file_fdw` and `CREATEROLE`).
- Default grants: most inspection modules revoke their functions from `PUBLIC` in their install scripts. Under pgextwlist those scripts run as the bootstrap superuser, so the revocations hold for the owner.

## Steps

1. Add a D1 table row group (or a D5 section) with each extension, its majors, and its disposition: admitted with default grants.
2. For each, note what the owner can call after `CREATE EXTENSION` (read from the extension's SQL script), and flag any module whose default leaves the owner a path beyond its own objects.
3. Write down `dblink`'s and `file_fdw`'s review and the `CREATEROLE` reopen condition.
4. If any module needs an after-create grant script, say so before w21/m584 t004 publishes.

## Done (2026-11-23)

- ADR092 D1 § Render's untrusted contrib modules: one row per extension with its majors and what the owner can call after `CREATE EXTENSION`, read from the pinned 13, 16, 17 and 18 operands as the owner (`has_function_privilege`, then each call). Every module keeps PostgreSQL's own grants; none needs an `extwlist/` script, so the image does not change.
- Flagged: `pg_prewarm`'s `autoprewarm_dump_now` and `autoprewarm_start_worker` are `PUBLIC` by PostgreSQL's default (a fixed file in the cluster's own data directory, one background worker of its own cluster; bounded). The owner already holds `pg_monitor` (`insightsMonitorRole`), so the modules that grant to `pg_monitor` or `pg_stat_scan_tables` are readable; each database is its own cluster.
- Review notes with sources: `dblink` (ADR043 D8.3 egress, PostgreSQL's password rule for non-superusers), `file_fdw` (no `USAGE` on the wrapper, `pg_read_server_files`, and the `CREATEROLE` reopen condition), the residual install-script risk of D3 property 2, and the untrusted extensions Render does not list (`postgres_fdw` and others), which stay refused.
- **`pgaudit`:** CloudNativePG's instance manager runs `DROP EXTENSION pgaudit` in every database whenever it starts on a primary with no `pgaudit.*` parameter set (v1.30.1 `reconcileDatabases`/`reconcileExtensions`, unchanged on CNPG `main`), and a `pgaudit.*` parameter would preinstall it everywhere instead (D2). Admitted anyway so Render's `CREATE EXTENSION pgaudit` succeeds; keeping it across restarts is filed as w21/122. Recorded as the plan's recommendation, not a user decision.
