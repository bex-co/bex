# The Registry Credentials Add and Edit dialogs never mark the Registry host, Username or token: a host with a path or space, a 300-character host or username and a control character in the username all leave Add credential enabled and come back from the server as an English toast

Why: a person who pastes `ghcr.io/owner/image` (the way a pull command shows it) into Registry host gets no hint until after the click, and a zh-locale user then reads the server's English sentence; the dialogs already mark the Name field, so the three fields beside it look checked and are not.

**Severity:** minor (every refusal is a plain, specific sentence and the dialog keeps its input; nothing is lost or created). **Estimate:** 30m (two dialogs, one shared rule module). **Kind:** sibling of [w21/045](045.md) and [w21/047](047.md) (editors and forms that mirror none of the server's rules; this is a surface neither names) and of [w21/036](done/036.md), which marked only the Name field of these same dialogs. **Source:** live `/qa-find-bugs` pass 70, 2026-11-11 06:4x UTC (2026-11-10 local), production `https://dashboard.bex.co`, workspace `bex`, pin `2f1c62c93f49`, filed to w21 per user direction; method: a client-versus-server validation differential on Workspace Settings → Registry Credentials. **Status:** inbox.

## Reproduction (signed in; `/workspace/settings#registry-credentials` → Add credential)

One credential, `qa-20261110-rc`, was created and deleted in the same visit. Every refused value created nothing.

**1. Add dialog.** Registry host `ghcr.io/qa-owner/qa-image`, `my registry.io`, and `a`×300 + `.io`; Username `qa\tuser` (a tab) and `u`×300; token `dummy-token-1`; Name `qa-20261110-rc`.

- In every case the three fields read `aria-invalid` null, no `role=alert` exists and Add credential is enabled. The inputs `rc-host`, `rc-username` and `rc-auth-token` have no `maxLength`; only `rc-name` has 100.
- After the click the dialog stays open with every input kept, and one toast per refusal:
  - `Host must be a registry host such as ghcr.io or registry.example.com:5000, without a path (got "ghcr.io/qa-owner/qa-image")` (also for `my registry.io`)
  - `Host must be at most 253 bytes`
  - `Username must not contain control characters`
  - `Username must be at most 253 bytes`

**2. Edit dialog** (`rc-edit-username`). Username `u`×300 leaves `aria-invalid` null and Save enabled. The toast is `Username must be at most 253 bytes`.

**3. Control (the server side works).** `https://GHCR.IO/` with username `qa-user` is accepted ("Added a credential for ghcr.io"). The row shows host `ghcr.io`, and REST `GET /v1/registrycredentials` lists it. Delete (no typed phrase; the dialog says only an unused credential can be deleted) answers "Deleted qa-20261110-rc", and REST then lists `[]`. So the server's canonicalisation (scheme, trailing slash, case, Docker Hub aliases) is real; only the refusals are unmarked.

**4. zh locale** (verified in pass 71, 2026-11-11 07:1x UTC). With `?lang=zh` the Add credential dialog is Chinese (buttons 取消 / 添加), but the refusals are still the server's English sentences as toasts, for example `Host must be a registry host such as ghcr.io or registry.example.com:5000, without a path (got "ghcr.io/qa-owner/qa-image")` and `Username must be at most 253 bytes`. REST `GET /v1/registrycredentials` stayed `[]`, so nothing was created.

## Root cause

- `dashboard/src/features/registry-credentials/components/create-registry-credential-dialog.tsx:46-47` gates only on `host.trim() && username.trim() && authToken.trim() && !isInvalidLabel(name)`. The three Inputs (`:96-132`) set no `aria-invalid`, `aria-describedby` or `maxLength`.
- `edit-registry-credential-dialog.tsx:116` gates on `isValidLabel(name) && username.trim()`; its username Input (`:150-157`) is the same.
- Server rules to mirror:
  - `lego/backend/internal/registrycreds/host.go:30,56-71`: `registryHostPattern` `^(localhost|dns-labels)(:port)?$`, applied after dropping `https://`/`http://` and trailing `/`, lowercasing and folding Docker Hub aliases.
  - `lego/backend/internal/registrycreds/service.go:73-74,412-422`: host and username at most 253 bytes, token at most 64 KiB, `hasControlCharacter` on the username.
- The dashboard already has a control-character rule in `common/lib/utils/resource-label.ts:10` (`CONTROL_RE`) it can reuse.

## Fix (target behavior)

- Add and Edit mark each field inline in en and zh before any request, hold the submit button while a rule fails, and use the server's wording as the English source:
  - host: a bare registry host such as ghcr.io or registry.example.com:5000 (an `https://` prefix and a trailing slash stay accepted, because the server drops them), at most 253 bytes (UTF-8 bytes, not characters);
  - username: no control characters, at most 253 bytes;
  - token: at most 64 KiB.
- Host and username get `aria-invalid` + `aria-describedby` and a `role="alert"` message, like the Name field beside them.
- The inline en and zh messages are what removes the English toast in zh: the client check makes the server's English refusal unreachable from these dialogs, as w21/036 did for the Name field.
- One shared validator in the feature (for example `lib/credential-fields.ts`) serves both dialogs, with a test that pins it against the server's accepted and refused host samples so a rule change on one side fails the other.

## Adjacent classes

- The client's `authToken.trim()` (create `:61`, edit `:125`) strips surrounding whitespace the server would keep, so the dashboard can never store a token with a leading or trailing space that REST can. Harmless for a pasted token; not a finding.
- A blank Name stays allowed (it defaults to the host).
- The host is immutable after creation, so the Edit dialog's host field is read-only and needs no rule.
- The pass-71 zh sweep of 15 pages (`/`, `/blueprints`, `/agents`, `/automations`, `/env-groups`, `/webhooks`, `/notifications`, `/billing`, `/workspace/settings`, `/settings`, `/services/new`, `/databases/new`, `/keyvalue/new`, `/blueprints/new`, `/env-groups/new`) found no new English UI copy: the paused-plan tooltips on New Web Service and New Key Value are the already-filed [w4/552](../w4/552.md), the `sudo delete workspace bex` and `delete my account` phrases are the deliberate English confirmation phrases of `dashboard/AGENTS.md`, and the one English sentence on `/agents` is another session's own prompt text.
