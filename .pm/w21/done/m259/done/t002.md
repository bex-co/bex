## Objective

Add the gateway verb that stores a turn's result, authorized the same way as the ADR090 `pull-request` verb; last valid submission wins; non-final submissions stay readable while the turn runs.

## Context

- ADR090 gateway `pull-request` verb is the pattern; result ≤256 KiB; re-validate server-side against the stored schema.

## Steps

1. Implement the verb and auth.
2. Persist partial vs final results.
3. Reject results exceeding limits or not matching the schema.

## Files

- lego/backend ssh-gateway/agent gateway package for verbs
- lego/backend/internal/agentsessions/service.go

## Acceptance criteria

- [x] Only the session's own sandbox grant can post a result.
- [x] Invalid-against-schema results are rejected; last valid wins.

## Out of scope

- Driver tool (t003).

## Completion note (2026-11-05)

- Gateway: `POST /agent-results/<b64 ns>/<b64 session>` on the agent listener (`agentcred/result.go`), admitted like the share route (session-label Pod rule, so repo-less sessions submit). bex-api: `/v1/agent-session-results` (`agentsession/result.go`), kind-tagged `submit-result` envelope with its own MAC domain, single-use nonce, 256 KiB cap; `Service.SubmitResult` re-applies the current-sandbox rule and validates against the schema stored on the turn.
- Last valid submission wins; a non-final submission is accepted but never replaces a final one (`RecordAgentSessionResult`). Refusals: `forbidden`, `not_expected`, `schema_mismatch`, `too_large`, `invalid_request`, `rate_limited`, `unavailable`.
