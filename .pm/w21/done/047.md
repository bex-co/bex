# The service and env-group Environment editors mark nothing for the three value rules the server owns (a `PORT` that is not a usable port, a KEY=value entry over 131071 bytes, a NUL byte): Save is accepted, the server refuses it, and the refusal is a toast with the row unmarked — the dashboard inline message that w8/170 listed as "Not done" was never filed

Why: the editor already marks bad keys, duplicate keys and the 500-entry and 512 KiB map limits in the row, so a person who types `PORT=abc` or pastes a 200 KB certificate as a variable reasonably expects the same, instead of finding out only after Save.

**Severity:** minor (the refusals are readable full sentences, the draft is kept and nothing is saved; the row just is not marked). **Estimate:** 30m (three more rules in `validateEnvironmentDraft`, inline messages en+zh, tests). **Kind:** sibling of [w21/038](done/038.md), [w21/043](043.md) and [w21/045](045.md); closes the leftover recorded in [w8/170](../w8/done/170.md) ("Not done: dashboard inline message (the API error shows as the save error)") and the dashboard side of [w4/422](../w4/done/422.md). **Source:** live `/qa-find-bugs` pass 54, 2026-11-11 01:4x UTC, production `https://dashboard.bex.co`, workspace `bex`, filed to w21 per user direction; method: a client-versus-server validation differential on environment variable values. **Status:** inbox.

## Reproduction (own Free Docker web service `qa-20261110-envv`, `srv-dbpsdkfbq3ic73c0a930`, deleted in the same visit)

The service came from the public repo `https://github.com/bex-co/bex`, root `examples/hello-node`, auto-deploy off. It was suspended right after creation, so no save rebuilt it.

On `/services/srv-dbpsdkfbq3ic73c0a930/env`: Edit → Add variable → Save only. Each time the draft stayed in the editor and REST `GET /v1/services/{id}/env-vars` stayed empty.

1. **Key `PORT`, value `abc`.** The value textbox has `aria-invalid` null and Save only is enabled. After Save the toast reads "PORT must be an integer from 1 to 65535 (not 18012, 18013, 18014 or 19099, which the platform reserves); the operator would otherwise ignore it and serve the service's own port", and an alert reads "Couldn't save the environment. Your draft is still here."
2. **`PORT` `18012`.** Same toast.
3. **Key `QA_BIG`, a 140000-character value.** `aria-invalid` null, Save enabled, toast "Environment variable "QA_BIG" is too large: a process cannot start with a KEY=value entry over 131071 bytes; use a secret file for large payloads".

## Root cause (code-traced; `origin/main` has no code change since the last pin)

- `dashboard/src/features/services/lib/environment-draft.ts:275-293` `validateEnvironmentDraft` checks only the key shape (`VALID_ENV_KEY`, `:7`), the secret-file name, duplicates and the whole-map limits (`flagOverLimit` `:250-273`, `MAX_ENVIRONMENT_ENTRIES` 500 and `MAX_ENVIRONMENT_MAP_BYTES` 512 KiB). It has no per-entry size check, no `PORT` value check and no NUL check.
- The server rules are in `lego/backend/internal/core/config.go`:
  - `ValidEnvValue` (`:159`): no NUL byte;
  - `MaxEnvEntryBytes = 131072` (`:172`) and the `len(k)+1+len(value)+1` check in `CheckEnvValue` (`:176-190`);
  - `ValidPortValue` (`:202`): an integer 1-65535 that is not a platform-reserved port.
- `CheckEnvValue` has 6 production call sites (`core/environmentpatch.go:92`, `secrets/service.go:588`, `envgroups/service.go:504`, `apps/deploy.go:2742` and `:3158`, `apps/service.go:2427`), so REST, GraphQL, MCP, create and Blueprint all refuse the same way.
- The group editor reuses the same component (`features/env-groups/components/env-group-editors.tsx:30` renders `EnvironmentEditor`), so it has the same gap.

## Fix (target behavior)

`validateEnvironmentDraft` also flags, per row and before Save, each with an inline message and Save held, en and zh:

- a `PORT` whose value is not an integer 1-65535 or is one of the platform-reserved ports (the reserved list is the server's `IsReservedImagePort`; mirror it in one place and pin it with a test, as `static-rule-validation.ts` does for header names);
- a KEY=value entry whose UTF-8 length plus the separator and terminator exceeds 131072 bytes, with the message pointing to a secret file as the server's does;
- a value containing a NUL.

No API change.
