## Objective

Add static accessibility rules for JSX to `yarn lint`, choosing a linter that actually runs on this tree's ESLint version, and bring the existing violations to zero or to a documented exception each.

## Context

- `dashboard/eslint.config.js` has only `eslint-plugin-react-hooks` and `eslint-plugin-react-refresh`; no accessibility rule runs today. ESLint is `^10.7.0` (`dashboard/package.json`).
- At filing (2026-11-14): `eslint-plugin-jsx-a11y` 6.10.2, last published 2024-10, lists peer `eslint` only up to `^9`; `eslint-plugin-jsx-a11y-x` 0.2.0 lists `^9.0.0 || ^10.0.0`; `oxlint` 1.93.0 (published 2026-11) ships jsx-a11y rules. None of them was run against this tree.
- The board holds about 47 notes on missing or wrong accessible names, 26 on `aria-invalid`, 16 on contrast (w21/017, 018, 019, 025, 027, 052; w4/466, 607, 612), each fixed one file at a time.

## Steps

1. Spike the candidates on the tree: violation count by rule, false positives, and whether each runs on ESLint 10 without a peer override.
2. Pick one. Prefer an ESLint flat-config plugin that runs unmodified; otherwise run oxlint limited to the jsx-a11y rules from `yarn lint`.
3. Fix each violation, or disable it on its line with a one-line reason; make a new violation fail `yarn lint`.
4. Record the choice and the spike numbers in `dashboard/AGENTS.md`. If no maintained linter runs here, record that evidence instead and let t002 and t003 carry the milestone.

- [x] `yarn lint` passes on the tree, and each per-line exception carries a reason.

## Result (2026-11-14)

- **Choice: `eslint-plugin-jsx-a11y-x` 0.2.0** (`dashboard/package.json` devDependency, `dashboard/eslint.config.js`). Spike: `eslint-plugin-jsx-a11y` 6.10.2 declares ESLint `^9` at most and, in an isolated directory with ESLint 10.7, ran only with `--legacy-peer-deps`; `jsx-a11y-x` declares `^9.0.0 || ^10.0.0`, ships the same rule set (34 rules in `recommended`, 36 in all; `strict` adds none) and ran unmodified in about 2.5 s over `src/**/*.tsx`. oxlint was not tried, because an ESLint flat-config plugin ran unmodified (the step's preference).
- **Baseline:** 30 violations in 26 files, 23 of them (21 files) outside the tests: `no-autofocus` 16 (14 outside tests), `no-noninteractive-tabindex` 5, `anchor-is-valid` 3 (all tests), `no-static-element-interactions` 3, `click-events-have-key-events` 2, `no-noninteractive-element-interactions` 1.
- **Scope and options:** the rules run on `src/**/*.tsx` outside the tests' fixtures (the rendered pages are t002's job). `no-autofocus` checks only raw DOM elements (`ignoreNonDOM`): the 13 component `autoFocus` props are a dialog's or inline editor's first field, which is focus management, not a page stealing focus. That left 10 violations, each a deliberate pattern with a one-line `eslint-disable-next-line … -- reason`: four tooltip triggers that must be focusable so a keyboard user can reach the tooltip (`instant-tooltip.tsx`, `session-detail-header.tsx`, `permission-tooltip.tsx`, `service-detail-header.tsx`), the sidebar's focusable `separator` (the WAI-ARIA window splitter; two exceptions), the OTP input's `autoFocus` (`auth-form-overrides.tsx`), the delegated link click on the Kratos card (`auth-page-shell/index.tsx`; two rules), and the log viewport's input listeners (`log-line-list.tsx`). No component needed a fix, so t004 has nothing from this lint.
- **Acceptance:** a planted `<img src>` and a clickable `<div onClick>` make `eslint` fail with `alt-text`, `click-events-have-key-events` and `no-static-element-interactions`; `yarn lint` (typecheck, ESLint, knip) exits 0 on the tree (the one existing `use-live-logs.ts` warning is unchanged).
- **Recorded** in `dashboard/AGENTS.md` § Code standards, with the spike numbers.
