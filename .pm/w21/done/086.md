# 086 — The dashboard's charges card has no labels for the three object-storage usage kinds

Why: `object_storage_gb_seconds`, `object_storage_ingress_bytes` and `object_storage_egress_bytes` now appear in `GET /v1/usage` at $0, and a customer who looks at the card sees raw names or nothing.

- **Source:** the w21/m416 worker's report, 2026-11-15; the meters were confirmed in `GET /v1/usage` on production in w21/m416 t013.

## Steps

1. Find the charges card and its usage-kind label table in `dashboard/` and add readable labels and units for the three kinds (units that match the card's other metered kinds).
2. Add the strings to every language the dashboard ships (the eight-language set; `dashboard/AGENTS.md`), and a test that every usage kind the API can return has a label.
3. Check the card at desktop and narrow-mobile widths with a workspace that has the usage.

## Done when

- [x] A workspace with object storage usage shows labelled lines for all three kinds, in every shipped language.

## Result

DONE 2026-11-15 in `027e4009e`. The card had two gaps, not one: the resource kind `object_storage` had no category label either, so the category header read `object_storage` as well. Units and quantities were already right, because bex-api's `pricing.unitFor` returns `GB-mo` and `GB` for the three kinds.

- **Labels.** The category reads "Object storage", and its lines "Storage", "Inbound bandwidth" and "Outbound bandwidth" (the mobile app already says "Outbound bandwidth" for `egress_bytes`), in en, zh, ko, ja, es, pt, ru and de. The tables moved to `dashboard/src/features/usage/lib/charge-labels.ts`; `object_storage` joined `CATEGORY_ORDER` after Key Value.
- **Guard.** `charge-labels.test.ts` reads every `UsageKind…` and `ResourceKind…` string constant from `lego/backend/internal/store` (the backend has no list of kinds, only these constants), so a kind added there without a label in every language fails the suite, and so does a table row for a kind the backend no longer declares. Mutation runs: removing the egress label, the category label, one German or Russian string, or the `CATEGORY_ORDER` entry each fails it. The two declaring files are in `dashboard-test.yml`'s trigger paths (`scripts/ci_test_inputs.py` checks that); a third file declaring a kind fails the test until it is listed.
- **Production, after the `deploy.yml` run 43802337671 (dispatched, success).** The workspace `bex-canary` has the meters (quantities 3.42 GB out, 0.00187 GB-mo stored, 1.33 GB in). Before the deploy its card showed `object_storage` with `object_storage_egress_bytes`, `object_storage_gb_seconds` and `object_storage_ingress_bytes`; after it, at 1280 px and at 390 px (no horizontal overflow), the category and the three lines read as above, and with `?lang=` set to each of zh, ko, ja, es, pt, ru and de every line was in that language.
- **Not changed.** The resource row under the category is named by bex-api (`usage/service.go`, "Object storage"), so it stays English in every language: filed as w21/092.
