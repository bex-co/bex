# 011 — Skill versions saved before migration 0210 read with SQL-style YAML quoting, so their next diff shows one spurious description line

Why: the 0210 backfill rendered each existing skill's content in SQL, which quotes some descriptions differently from the Go renderer (`Deploy: staging` is double-quoted by the SQL and single-quoted by Go), so after the next save that skill's diff can show a description-line change although the text means the same.

- **Source.** The w21/m280 t006 simplify review (2026-11-08). The migration may already be applied, so it must not be edited.
- **What.** A new migration (next free number) that re-renders the content of every `agent_skill_versions` row whose `message` is the backfill's and whose version is the one that was current at backfill time, using the same quoting as the Go renderer; or recompute the first diff from parsed frontmatter instead of text.
- **Done when.** A skill backfilled from a description that needs YAML quoting shows no description-line change in the diff of its next save, with a test that pins it for the cases the migration test already lists.

Done 2026-11-08: a one-off startup step `BackfillSkillVersionContent` (not a migration: SQL could not be proved identical to Go's YAML quoting) re-renders only backfilled rows whose content is byte-for-byte the 0210 SQL output and differs from the Go renderer, recomputing `short_id`; idempotent, covered by six description cases.
