## Objective

Make the dashboard tests deterministic about time zone: every test runs in one pinned zone regardless of the machine, and the hydration probe switches zones explicitly.

## Context

- `dashboard/vitest.config.ts` pins no time zone, so tests run in the machine's zone (CI is UTC, a developer's Mac may not be); a test that depends on the zone can pass in one place and fail in the other.
- The server-side render of the real app runs in the container's zone (UTC); the browser's zone is the viewer's.

## Steps

1. Pin `process.env.TZ` to `UTC` for the whole run (vitest `globalSetup` or `test.env`), and fix any test that only passed in the machine's zone (run `yarn test` once under `TZ=Asia/Shanghai` first and list the failures).
2. Let t001's harness switch zones inside a test; document in `dashboard/AGENTS.md`'s testing section that a test needing another zone says so through the harness.

## Files

- dashboard/vitest.config.ts (or a new `src/test/global-setup.ts`)
- dashboard/AGENTS.md (one line)

## Acceptance criteria

- [x] `yarn test` passes under `TZ=UTC` and under `TZ=Asia/Shanghai` set in the shell (the pin makes both identical).
- [x] The zone a test sees is `UTC` unless the harness changes it.

## Out of scope

- Running the suite twice in CI.
