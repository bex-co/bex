## Objective

Render each route that already has a test fixture through the cross-environment probe and assert zero recoverable hydration errors, so a mismatch anywhere on a page fails a test.

## Context

- `dashboard/src/routes/__tests__/` holds about 44 test files with mocked Apollo data, covering services, databases, billing, webhooks, env groups, blueprints, agents and settings.
- The pairs to run: (UTC, English, server clock) to (Asia/Shanghai, Chinese, clock one minute later), and the w21/054 case: the `i18nextLng` cookie missing while localStorage says `zh`.
- A jsdom probe of 054's inferred mechanism (`src/i18n/__tests__/hydration-language-sync.test.tsx`) hydrates cleanly, so a clean result for 054 is possible; record it either way.

## Steps

1. **Done as a setup file, not a per-route helper** (2026-11-11): the route tests each build their own mocks and routers, so `src/test/route-hydration-sweep.ts` wraps `render` from Testing Library, records the first element each swept test renders, and probes it in `afterEach` after the test's assertions passed, with the test's own fixtures as data. Swept: every file under `src/routes/__tests__/`, every `*page*.test.tsx` and `automation-form.test.tsx`.
2. One pair per test, chosen by test name: a probe mounts the tree again and a stateful fixture (a feed) answers its second mount differently (`services.$serviceId.events-live` failed with both pairs, passes with either alone). A page whose server pass errors (`<!--$!-->`, a mock that is not SSR-safe or reset by the test's own `afterEach`) is inconclusive and skipped; only React's mismatch reports fail a test.
3. List every route that fails; do not fix them here (t004).
