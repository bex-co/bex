# 089 — Runbooks name the production SSH key `~/.ssh/id_bex`, and the QA login helper's challenge needs decoding

Why: the wrong key name stopped real work for hours (the key is `~/.ssh/bex`, which `scripts/fetch-app-kubeconfig.sh` uses by default and `.env.example` names as `BEX_SSH_PRIVATE_KEY_FILE`), and a double-encoded login challenge makes a documented step fail.

- **Source:** the ADR112 production walks, 2026-11-15. Stale key name in `.claude/skills/deploy-app-from-local/SKILL.md` (lines 27, 28 and 64), `.claude/skills/rt-fix-prod-crashes/SKILL.md` (line 38) and `docs/ADR036-ca-rotation-runbook.md` (the `ssh -i` lines), and in the parked notes of w21/m336 and w21/012. The QA login: `scripts/qa-login.sh --login-challenge` needs the challenge percent-decoded; the raw value from the redirect is double-encoded and Kratos answers 400.

## Steps

1. Replace `~/.ssh/id_bex` with `~/.ssh/bex` (or the `BEX_SSH_PRIVATE_KEY_FILE` variable) in the files above, and drop the `BEX_SSH_KEY_PATH` override from the examples where the default is right.
2. Make `scripts/qa-login.sh --login-challenge` decode the challenge itself, or document the decode step in `.claude/skills/qa-find-bugs/SKILL.md`, with a test or dry run.
3. Run `bash scripts/skill-layout-validate.sh` and `bash scripts/docs-links-validate.sh`.

## Done when

- [x] `grep -rn id_bex` finds nothing outside this note's own history, and the login-challenge step works as documented.
