## Objective

Make the only early warning for a wrangler release real: stock wrangler 4.162.0 against bex's own handlers.

## Context

- `docs/ADR112-object-storage.md` D11: `CLOUDFLARE_API_BASE_URL`, `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` are all stock wrangler needs; it calls no `/memberships` or token-verify route. Object commands default to local, so `--remote` is required.
- Measured with 4.162.0 earlier: bucket list, create, info, delete, object put, get and delete with `--remote`, `dev-url get|enable`, `cors list`, `lifecycle list`, `domain list`. Not run: `dev-url disable`, `cors set`, `lifecycle add|set|remove`, `domain add|update|remove`, `bulk put`, `create` with `--location`, `--jurisdiction` and `--storage-class`. Run those for real here.
- CI rules: `scripts/github-actions-validate.sh` allows only `ubuntu-24.04-arm` or `ubuntu-latest` runners (DO_NOT_DO #CI-RUNNERS, re-opened 2026-11-09); a workflow's `paths` must list every file outside its tree its tests read (`scripts/ci_test_inputs.py`).

## Steps

1. Capture wrangler 4.162.0's requests for every command above and write them as fixtures the Go test replays.
2. Write `scripts/wrangler-r2-contract.sh`: install the pinned wrangler into a temp directory, start bex-api with the fake S3, and run the commands end to end.
3. Add `.github/workflows/wrangler-r2-contract.yml` (weekly and on pushes touching the handlers) and any `ci_test_inputs.py` entries.

## Files

- lego/backend/internal/api/testdata/ (fixtures)

## Acceptance criteria

- [ ] Every command in the list runs against bex's handlers and passes, including the ones never run before.
- [ ] The weekly workflow passes `scripts/github-actions-validate.sh`.

## Out of scope

- Other wrangler versions.

## Result

`TestWranglerEndToEnd` starts the handlers (the real chain minus the OAuth gate, over the fake S3) on a socket and runs the real wrangler 4.162.0 through 44 steps, among them every command the first measurement did not run: `bucket create` with `--location`, `--jurisdiction` and `--storage-class`, `cors set`, `lifecycle add|set|remove`, `domain add|update|remove`, `dev-url get|enable|disable` (all `10042` until w21/m417), `lock`, `sippy` and `notification`; it also reads back the bytes put, and checks that an object put with wrangler into `render-oregon` is in Render's listing. `TestWranglerFixturesReplay` replays the 50 requests that run recorded (`testdata/wrangler-4.162.0/requests.json`, rewritten with `BEX_WRANGLER_RECORD=1 scripts/wrangler-r2-contract.sh`) on every build with no node, checks each status and the envelope, that an object put always carries its Content-Length, and that the fixture covers every step so one cannot silently stop being tested. `scripts/wrangler-r2-contract.sh` installs the pinned version into a temp directory with `--ignore-scripts` and runs both. `.github/workflows/wrangler-r2-contract.yml` runs it weekly, on dispatch and on pushes touching the handlers; the weekly window is declared in `ci-schedule-drift.sh`; `github-actions-validate.sh`, `ci_test_inputs.py` and `ci-schedule-drift.sh validate` pass. Finding: wrangler 4.162.0 has no `object bulk put` (only `get|put|delete`); ADR112's mention came from reading another version's source. The recorded run also shows wrangler treats a 404 on an object get as a missing key and sends the entity headers it was given.
