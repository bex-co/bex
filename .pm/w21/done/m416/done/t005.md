## Result

`cloudflare_r2_config.go`: `cors list|set|delete` and `lifecycle list|set` (wrangler's `lifecycle add|remove` are a get and a put of the whole set), storing the rules on the bucket row through `SetCORS` and `SetLifecycle` (the `Repository` interface grew `SetObjectBucketCORS`, `SetObjectBucketLifecycle` and `ListObjectStorageUsage`). The service validates before it stores (`Service.SetCORS` and `SetLifecycle` take typed rules and call `ValidateCORS` and `ValidateLifecycle`, so no caller can store a set the sweep or the public host would mishandle). CORS rules are checked by `objectstorage.ValidateCORS` (shared `CORSRule` type for objectgw: at most 100 rules and 64 KiB, an origin of `*` or a scheme and host, methods from Cloudflare's five, header names without spaces, `maxAgeSeconds` 0 to 86400 as Cloudflare's schema shows); lifecycle rules by `ValidateLifecycle`, which runs the sweep's own `LifecycleRule.Validate` plus a unique id, a clean prefix, an expiry or an abort, at most 1000 rules, and refuses `storageClassTransitions`, so a rule the route stores is a rule the sweep runs (a test parses the stored row with the sweep's parser). Cloudflare documents `rules` as optional, so a body with none clears the set, but any other top-level field is refused so a body in another tool's shape (S3's `CORSRules`) cannot clear what is stored. Over a cap or a storage-class transition is 403 `10042` naming the limit; a malformed rule is 400 `7400`. An unset configuration lists as an empty array. Real wrangler ran `cors list|set|delete` and `lifecycle list|add|remove|set` (expiry in days, expiry by date, abort multipart).
