## Objective

Tell customers how to point wrangler at bex and record the Cloudflare-shaped API in the parity ledger.

## Context

- `docs/ADR018-render-parity.md` uses an `Extension` category for bex-only APIs; ADR112 adds the Cloudflare-shaped API as one. Record dated, unsigned divergences: regions, caps, the Cloudflare error-code subset, the key rule, `cf-r2-jurisdiction` ignored in lookups.
- The user docs must say: three environment variables and `--remote`; 300 MiB per object; no object listing for named buckets until the S3 API follow-up (ADR112 D10) and what the Render CLI lists instead; a short lifecycle rule saves nothing on storage (Wasabi's 90 days).
- `lego/backend/AGENTS.md` holds the route and environment inventories.

## Steps

1. Add a wrangler section to `docs/bex-cli.md` with the three variables and an example.
2. Add the Extension row and the divergences to ADR018.
3. Update the `lego/backend/AGENTS.md` route inventory and the `docs/AGENTS.md` catalog line.
4. Run prettier and the link check.
