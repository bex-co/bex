# `bex s3 rm` of one object asks for confirmation in a terminal, as `bex ea objects delete <key>` does

Why: `bex ea objects delete a/b` asks "Are you sure you want to delete object 'a/b'? This cannot be undone. [y/N]:" in a terminal unless `--yes`, and `bex s3 rm s3://b/a/b` deletes one object without asking; w21/115 added the question to the bulk deletes only, and ADR018 names the difference. Render parity is the top principle, so this is the stricter variant 115 did not take, filed on its own.

- **Change.** `bex s3 rm s3://bucket/key` (no `--recursive`, not `--dryrun`) asks in a terminal with `ea objects delete`'s single-key words, `Are you sure you want to delete object '<key>'? This cannot be undone. [y/N]: `, through `deps.confirmBulkDelete` (`lego/cli/internal/s3/confirm.go`, rename it for the wider use); `--yes` (`-y`) and `--confirm` skip it and a pipe, a script or CI never asks. `mv` keeps its source delete without a question, since the bytes survive at the destination.
- **Where.** `lego/cli/internal/s3/rm.go`, `confirm_test.go`, `lego/cli/s3_confirm_test.go`, the `bex s3 --help` text, `docs/bex-cli.md` ("Asking before a bulk delete") and the ADR018 sentence that names this difference.
- **Done when.** A terminal run of a single-object `rm` waits for an answer and a `--yes`, `-y`, `--confirm`, `-o json`, CI or piped run does not; the pseudo-terminal test pins the wording against `ea objects delete a/b`'s own prompt; ADR018 and `docs/bex-cli.md` no longer say a single-object `rm` does not ask.

**Done 2026-11-20.** `bex s3 rm s3://bucket/key` (not `--dryrun`) asks `Are you sure you want to delete object 's3://bucket/key'? This cannot be undone. [y/N]: ` in a terminal, through the same `confirmDelete` (renamed from `confirmBulkDelete`, `lego/cli/internal/s3/confirm.go`) and so with the same rules as the bulk deletes: `--yes`, `-y` and `--confirm` skip it, and a pipe, a script, CI, `TERM=dumb` or `-o` never asks; `mv` keeps its source delete without a question. The words are `ea objects delete`'s, checked against the pinned `cmd/objectdelete.go` and run on a pseudo-terminal (`s3_confirm_test.go` builds the single-object question from the same `objectQuestion` frame that its reference subtest pins to `ea objects delete a/b`'s own output). One choice the note did not make: `ea objects delete` has no buckets and quotes the key, so `rm` quotes the object's `s3://bucket/key`, as the three bulk prompts already quote theirs; two buckets can hold the same key. Unit tests (`confirm_test.go`) add `rm` to every case of the bulk deletes plus `mv`; with the single-object ask removed, both the unit and the pseudo-terminal test of `rm` fail. ADR018's sentence that a single-object `rm` does not ask is gone, and `docs/bex-cli.md` ("Asking before a delete") and the `bex s3 --help` and `rm --help` text say it. The change rides in the next CLI release.
