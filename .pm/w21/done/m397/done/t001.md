## Objective

Add `scripts/docs-links-validate.sh` that fails on any relative Markdown link whose target does not exist, with a test script in the shape of the ADR registry check.

## Context

- Measured at filing (2026-11-14, `cc671cbfd`): across `docs/**/*.md`, every `AGENTS.md`, `README.md`, `lego/**/README.md`, 1900 relative links, 71 broken: 22 into `.pm/**/evidence/` (purged 2026-11-04), 16 into `.pm` items that are gone or renamed, 12 into `.pm` items since moved to `done/` or `blocked/`, 18 into renamed docs (`docs/ADR027-sso.md` links `auth.md`, `render-parity.md`, `sandboxes.md`).
- Precedent: `scripts/adr-registry-validate.sh` and `scripts/adr-registry-validate.test.sh`; `docs/AGENTS.md` and `.pm/AGENTS.md` are cascading docs.
- Heading anchors (`#section`) are out of scope: they need GitHub's slug rules and would widen the repair.

## Steps

1. Write the script: collect Markdown files (the set above plus `.pm/*.md` at the top level, not the `wN` history), strip fenced code and inline code, skip `http(s):`, `mailto:` and absolute paths, resolve each relative target and report `file:line -> target`; exit 1 on any miss.
2. Write `scripts/docs-links-validate.test.sh` with a fixture tree holding one good and several bad links (a missing file, a link inside a code fence that must be ignored).
3. Run it on the tree and record the count (the input of t002).

## Files

- scripts/docs-links-validate.test.sh

## Acceptance criteria

- [x] The test script passes: it fails on a missing target and ignores fenced code.
- [x] The script on the tree reports the broken links with file:line and exits 1.
