# 087 — The audit log names the object routes' verb `api.route.func1`

Why: an audit event whose verb reads `api.route.func1` tells nobody what happened; object puts, gets, deletes and bucket changes need a verb a reader can search for.

- **Source:** the w21/m416 worker's report, 2026-11-15. The cause (read 2026-11-16, see Result) is the one suspected here: that the audit middleware takes the verb from the handler's function name and the object and Cloudflare-shaped routes (`lego/backend/internal/api/objects_render.go` and the Cloudflare handlers) register closures.

## Steps

1. Read how the audit middleware derives the verb and what the other routes pass.
2. Give every object and Cloudflare-shaped route an explicit verb (for example `object.put`, `object.get`, `bucket.create`) the way the neighbouring routes do, and add a test over all registered routes that no verb contains `func`.
3. Confirm an audit-log entry for a put and a bucket create on a local stack.

## Done when

- [x] No registered route's audit verb is derived from a closure name, and a test fails if one is.

## Result

DONE 2026-11-16 in `ae5cd494c` and `14af7282d` (deploy.yml run 43808103686, dispatched, success; pin `a518fa61f`).

- **Cause.** `core.callerVerb` names a verb after the stack frame that called `Authorize…` and walks past an unexported method, but never past a closure or a function value. The object routes authorize in their HTTP adapters (`objects_render.go` `serve`, `cloudflare_r2.go` `route`), so the closure's name was the verb. The sweeps that would have caught it (`TestAuthzGuardsEveryVerb`, `TestAuditCoversEveryWriteVerbExactlyOnce`) walk the types that embed `core.Base`, which the two object adapters do not.
- **Production before the fix.** 591 rows in `audit_events` carried a closure verb: `api.route.func1` on a local build, and on production `api.registerObjects.route.func4`, `api.registerBuckets.route.func9`, `api.RegisterREST.func2` and so on (Go names an inlined closure after its caller, so the number moves with every build); 214 rows of `api.composedMuxes.ConnectFileHandler.func9` (sandbox file transfers), `usage.RegisterREST.func1`, `projects.RegisterREST.func1(.1)`, `usage.GraphQLQuery.func1`, `apps.registerOnboardingMCP.func5`.
- **Fix.** `core.Base` gained `AuthorizeAs`, `AuthorizeTargetAs` and `AuthorizeWorkspaceAs`, which take the verb. Every object and Cloudflare-shaped route names one (`objectstorage/audit.go`: `PutObject`, `GetObject`, `DeleteObject`, `ListObjects`, `CreateBucket`, `GetBucket`, `ListBuckets`, `UpdateBucket`, `DeleteBucket`, `GetBucketUsage`, `Get/Set/DeleteBucketCORS`, `Get/SetBucketLifecycle`, `Get/SetBucketPublic`, `ListCustomDomains`, `NotOffered`); both contracts share a verb for the same action. The sweep found five more routes: `sandbox.TransferFile` (the file-transfer redemption), `usage.MonthToDate`, `projects.List`, `apps.PreviewBlueprint` and `apps.ValidateBlueprint`, and MCP's `update_blueprint` now records `apps.UpdateBlueprint`. The naming is `<feature>.<Action>`, as every other verb; Render's audit-log enum has no object or bucket event, so there was nothing to map to, and REST reports the verb as bex's own value (`audit-logs-api.md`). ADR006 and ADR112 D6 record it.
- **Tests.** `audit_verbs_test.go` drives every route of the REST and Cloudflare muxes (412), every MCP tool (245) and every GraphQL field (355), refused and allowed, and fails any verb that is not `<feature>.<Action>` (a verb containing `func`, a method value, an unexported helper, `unknown`); each object route must record its own listed verb, and a route not listed must be a refusal. Reverting any one of the five fixes fails it, and each fails with the verb production recorded. `audit_verbs_pg_test.go` is the real-Postgres check: a bucket create and two puts (wrangler's and Render's) read back through `GET /v1/owners/{id}/audit-logs` as `objectstorage.CreateBucket` and `objectstorage.PutObject`, and with the old code it reads `api.route.func1`. A sandbox test covers the file transfer.
- **Production, after the deploy.** In `bex-canary` as the QA user: a bucket create, a wrangler put, Render's put mint, an object delete and a bucket delete (all 200, nothing left behind) wrote five rows, `objectstorage.CreateBucket`, `objectstorage.PutObject` twice, `objectstorage.DeleteObject` and `objectstorage.DeleteBucket`, all `success`; no row since the new pods started carries `func`.
- **Old rows.** No read-side mapping is needed and none is filed: a closure's name is not stable (the number changes with every build, and every Cloudflare action shared one name), so a mapping would be a guess, and 278 of the 591 rows are one workspace's own walk of the feature (the rest are first-party test and probe workspaces). The 90-day audit retention removes them by 2027-02-13. History rows were not rewritten.
- **Left.** One GraphQL field (`envVars`) and two background paths (the automation scheduler's fire, 48 rows; the placement clears, 26 rows) still record a closure: w21/093, with the sweep's backlog entry that fails when it is fixed. An object row names no bucket or key, and a successful get records nothing: w21/094, a product decision.
