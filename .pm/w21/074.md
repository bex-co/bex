# 074 — The backend's per-source connection and admission caps key an IPv6 client on its exact address, so one /64 holds 2^64 "sources"

Why: w21/m394 t017 made the operator's SNI proxies and static server count an IPv6 client under its /64 (`netutil.SourceKey`), but the same per-source pattern in `lego/backend` still keys on the exact address, so a client that rotates through its own /64 never meets the cap (the R25-12 mechanism, on the SSH gateway and the auth admission path).

- **Source:** w21/m394 t006 reuse review, 2026-11-14. Not reproduced here: the three sites below were read, not run.
- **Evidence:**
  - `lego/backend/internal/sshgateway/nativessh/server.go:343-345` keys `preAuthSources` on `addr.String()`, where `addr` is already a `netip.Addr`.
  - `lego/backend/cmd/ssh-gateway/main.go:646-652` `connectionSource` (used at the call near `:600`) returns the raw host string.
  - `lego/backend/internal/api/authadmission.go:170` builds its fingerprint from `"source:" + a.TrustedProxies.ClientIP(r)`.
- **Size:** about 45m: three one-line changes and a test each.

## Steps

1. Write a test per site first: 1,024 addresses of one /64 must meet the per-source cap (the SSH pre-auth pool's `BEX_SSH_MAX_PREAUTH_CONNS_PER_SOURCE` default of 32, and the auth admission limit), today each address is its own source.
2. Key each on `netutil.SourceKey(addr)` (`lego/types/netutil/sourcekey.go`); `connectionSource` and `authadmission` parse the string first and fall back to the raw value when it is not an address. The backend module already depends on `types`.
3. Keep metrics labels and log lines readable: log the real address, count by the key.
