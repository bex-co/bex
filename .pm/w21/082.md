# 082 — `make test` cannot run its codegen step on a machine with Go 1.27.3: controller-gen answers "directory prefix . does not contain modules listed in go.work"

Why: from `lego/operator/`, `make manifests` (the first codegen step of `make test`) fails with `-: pattern ./...: directory prefix . does not contain modules listed in go.work or their selected dependencies` and `Error: not all generators ran successfully`. The same controller-gen run over `paths="./..."` alone succeeds, so the failure is in the pair of patterns the Makefile passes (`paths="./..." paths="../types/..."`, [`lego/operator/Makefile`](../../lego/operator/Makefile) line 48) under the workspace's `go 1.27.3`. `make test` therefore stops before it tests anything; w21/m411 ran the `go test` line the target runs, directly, and it passed.

- **Source:** w21/m411 t008, 2026-11-14, local `go version go1.27.3 darwin/arm64`, controller-gen v0.20.1.
- **Size:** about 30m, most of it finding whether CI (`operator-test.yml`) uses a different Go and where the pattern resolves differently.

## Steps

1. Reproduce with `cd lego/operator && make manifests`, then with `bin/controller-gen rbac:roleName=manager-role crd paths="./..." paths="../types/..."` and each pattern alone, to see which pair breaks.
2. Check which Go `operator-test.yml` installs; if CI is on 1.26 and passes, the fix is to run the codegen from the module directory it names (two invocations, or `paths` from `lego/` with the module-qualified pattern), keeping the output identical (`git diff --exit-code` after `make manifests generate`).
3. Make `make test` work on the workspace's own toolchain, and say in `lego/AGENTS.md` which Go the codegen needs if it must differ.
