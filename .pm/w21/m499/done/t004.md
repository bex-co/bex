## Objective

Run the clients exactly as customers do, with their own defaults and no tuning, against a bex-api over a fake S3, and register the job like the other drift jobs.

## Context

- ADR112 D11 (S3 layer 3). Style: the old `scripts/wrangler-r2-contract.sh` (removed in m500): install the pinned tools into a temporary directory, start a bex-api over the fake S3, run the commands.
- Commands: `aws s3 ls|cp|mv|rm|sync|mb|rb|presign`, `aws s3api` for each configuration call, an rclone copy, sync and listing, and a boto3 `upload_file` of 20 MiB and a presigned-URL upload. Terraform's AWS provider is untested and documented as such.
- Registration: a workflow with `paths`, `scripts/ci-schedule-drift.sh` and `scripts/ci_test_inputs.py` rules; it runs weekly and on any pin change, not on every PR.

## Steps

1. Write the script and its workflow.
2. Register it in `scripts/ci-schedule-drift.sh` and check `scripts/ci_test_inputs.py`.
3. Run it once and record the defaults each client actually sent (addressing style, checksum framing) in ADR112 § Not verified.

## Result

Done 2026-11-19. `scripts/s3-contract.sh` installs the pinned aws-cli 2.39.5 (the official zip on Linux, the `.pkg` expanded on macOS), rclone v1.75.2 and boto3 1.43.125 (botocore the same) into a temporary directory, each artifact checked against a sha256 pinned in the script (`scripts/ci-fetch-verified.sh`), starts the real gateway over TLS (`lego/backend/internal/s3gw/contract_server_test.go`, `TestS3ContractServer`, skipped unless `BEX_S3_CONTRACT_DIR` is set) on a throwaway Postgres (the digest `backend-test.yml` pins) and a fake Wasabi, and runs each client with its own defaults: aws-cli (`s3 mb|cp|mv|rm|sync|ls|presign|rb` and `s3api` for CORS, lifecycle, paged listing, tagging, an explicit multipart upload and a batch delete, with the config `bex s3` writes), rclone (mkdir, copy, copyto, sync, check, lsf, cat, moveto, delete, purge, with the variables `bex s3 env` prints) and boto3 (`scripts/s3-contract-boto3.py`: `upload_file` of 20 MiB, copy, listing, a presigned upload, CORS, lifecycle). The gateway logs every request, the run fails on any 5xx and on any command that fails, and the report prints the defaults each client sent and every 501 (ADR112 § Not verified now holds them). `.github/workflows/s3-contract.yml` runs it weekly and on a change to the script, its pins or the gateway, not on every PR; `scripts/ci-schedule-drift.sh` has its 216 h window and `scripts.yml` shellchecks the script (`ci_test_inputs.py` needs nothing: the Go test reads no file outside its tree). **The first run found a bug, fixed here:** stock rclone sends `x-amz-bucket-object-lock-enabled: false` on every `CreateBucket`, and bex answered 501 to the header whatever its value, so `rclone mkdir` failed; `false` is now served (`headers.go`, `router_test.go`), any other value is still 501. **Known difference carried, not fixed:** boto3 reads user metadata back as `Mtime` (w21/113); the suite prints it and checks the value case-insensitively, to be made exact when that note is fixed. Run locally on macOS arm64 in about 35 s; the Linux paths (zip install, `uname` pins) and the workflow's first run on `main` are not observed until the push runs it. Terraform's AWS provider is untested and documented as such.
