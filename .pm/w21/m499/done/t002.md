## Objective

Give the rest of the S3 workflow its bex-owned commands: other tools, persistent keys, publishing and a bucket's details.

## Context

- ADR112 D3 (the command), D4. These five names are bex's (`s3`, `s3api` pass through to `aws`); everything else is passed on as typed.
- `bex s3 env` prints the variables for rclone, boto3, s5cmd and Terraform's AWS provider (`s3_use_path_style`); `bex s3 keys create|list|revoke` manages persistent keys (the secret is printed once); `bex s3 public <bucket> enable|disable|status` calls the publish route with the person's own token (it needs the admin role); `bex s3 info <bucket>` reads the bucket route (region, public host, objects and bytes from the last sweep).

## Steps

1. Add the four commands over the REST routes of m498/t003.
2. Add `--output json` support like the other bex-native commands.
3. Test each against a stub server, including the admin-only refusal of `public`.

## Files

- lego/cli/ (the S3 launcher package)

## Acceptance criteria

- [x] Each command's output and refusal paths are tested; a persistent key's secret is printed exactly once and never logged.

## Out of scope

- A dashboard UI for keys.

## Result

Done 2026-11-19. `internal/s3/tools.go` adds `bex s3 env` (the endpoint and the cached twelve-hour key as `export` lines for aws-sdk programs, boto3, rclone (`RCLONE_S3_*`; it defaults to path style) and s5cmd (`S3_ENDPOINT_URL`), with the expiry and the settings no variable carries, `s3_use_path_style = true` for Terraform and boto3's `addressing_style`; `-o json|yaml` as data), `bex s3 keys create|list|revoke` (create is persistent unless `--expires-in` up to 12h, `--permission read|readwrite`, the secret is printed in the create answer alone and `list` never shows one; revoke validates the `s3k-` shape before it reaches a URL and drops a cached copy of a revoked key), `bex s3 public <bucket> enable|disable|status` (PUT and GET of `.../buckets/{bucket}/public` with the person's own token; a 403 on enable or disable says the workspace admin role and a person's login are needed) and `bex s3 info <bucket>` (region, public host, objects and bytes as of the last count). A bucket argument is `photos` or `s3://photos` and must match ADR112 D1's name rule before it is placed in a path, and every path element is escaped. `-o json|yaml` prints the API's own answer for keys, public and info, like the other bex-native commands; usage errors exit 2. `internal/s3/s3_test.go` covers each command against a stub bex-api including the admin-only refusal.
