# A signed-in session whose `i18nextLng` cookie is missing while localStorage still says `zh` logs a React #418 hydration error on its first load and paints English for a fraction of a second before flipping to Chinese; the hook's own comment says it "can't cause a mismatch"

Why: `dashboard/AGENTS.md` and `use-language-hydration-sync.ts` promise the stored-preference sync runs "after hydration, never during the initial render, so it can't cause a mismatch", and production shows it does, so a Chinese user who loses only the cookie gets a console error and a visible English-then-Chinese flip on the next page load.

**Severity:** minor (one recoverable console error and a one-time flash; the page ends in the right language and the cookie is re-written; how often a real browser reaches this state is unverified). **Estimate:** 30m (one effect, one regression test). **Kind:** sibling of [w6/m103](../w6/done/m103/README.md) (SSR language versus client language, done 2026-09-05) and [w21/013](done/013.md) (#418 from a time zone default, done); this is the path m103 and the hook's comment treat as safe. **Source:** live `/qa-find-bugs` pass 71, 2026-11-11 07:0x UTC (2026-11-10 local), production `https://dashboard.bex.co`, workspace `bex`, pin `2f1c62c93f49`, filed to w21 per user direction; method: a language persistence differential (the `i18nextLng` cookie versus `localStorage`) on authenticated pages. **Status:** inbox.

## Reproduction (signed in; nothing created)

In the Playwright page: `ctx.clearCookies({ name: "i18nextLng" })`, optionally `ctx.addCookies([{ name: "i18nextLng", value: "zh", domain: "dashboard.bex.co", path: "/" }])`, `localStorage.setItem("i18nextLng", …)`, then `page.goto(...)` with a `pageerror` listener counting messages that match 418. A real user gets state (B) by deleting only the `i18nextLng` cookie in DevTools → Application while `localStorage.i18nextLng` is `zh`.

| State (cookie / localStorage) | Page | Result |
| --- | --- | --- |
| (B) none / `zh` | `/workspace/settings` | 1 × #418 at 1.15 s; `<html lang="en">` and the English `h1` "Workspace settings" for about 0.2 s, then `zh` and "工作区设置" |
| (B) none / `zh` | `/billing` | 1 × #418 at 4.4 s (same run); "Billing" for about 0.2 s, then "账单" |
| (A) `zh` / `en` | `/billing` | 1 × #418 at 5.4 s; SSR is Chinese and the page ends in English (the cookie is overwritten with `en`; the stored preference wins, as the hook documents) |
| (C) `en` / `zh` | `/workspace/settings` | ends in `zh`; the sync ran (an earlier untimed run of A, A, B, B, C logged 4 #418 in total; which loads they belong to was not recorded) |
| controls: `zh` / `zh` and `en` / `en` | `/billing` | 0 × #418 in 2 of 2 |
| plain English loads (no manipulation) | `/workspace/settings` ×3, `/billing` ×2, `/`, `/webhooks`, `/env-groups`, `/notifications`, `/blueprints`, `/settings` | 0 × #418 in 11 of 11 |

After (B) the cookie is re-written as `zh` and the next load is clean.

**First sighting:** the first load of this run, after injecting a `zh` cookie while this browser profile's localStorage still held `en`, logged `Minified React error #418; … args[]=text` at 2.05 s and ended in English.

## Root cause (inferred, not confirmed in a development build)

- `dashboard/src/i18n/use-language-hydration-sync.ts:17-33` runs in a `useEffect` once the root commits and calls `switchLanguage(storedLang)` (`dashboard/src/i18n/init.ts:130-133`: `ensureLanguage`, then `i18n.changeLanguage`). It is mounted at `dashboard/src/common/root-route/root-component.tsx:14`.
- The root effect fires before every suspended or lazy boundary below it has finished hydrating. Those boundaries then hydrate against the new language while their server HTML is in the old one, which is the text mismatch #418 reports.
- The timing fits: in (B) the error lands at the same instant the heading flips, and the two same-language controls never log it.
- `detect-language/client.ts` deliberately leaves localStorage out of the initial render for the same reason, so the render and the effect disagree about when the stored language may take effect.

## Fix (target behavior)

- The stored-language switch must not run while any boundary is still hydrating. The reproduction above then logs no #418 on `/workspace/settings` and `/billing`, and still ends in `zh` with the cookie re-written.
- Candidate mechanisms: run the switch after the root's hydration (and its Suspense boundaries) has completed, or inside a transition. The implementer picks the one that a `hydrateRoot` test over a lazy boundary proves.
- The English flash is inherent while the server cannot read the language (no cookie). Shortening it is optional; removing the #418 is the target.

## Blast radius (counted by grep)

- 1 call site for `useLanguageHydrationSync` (`root-component.tsx:14`) and 1 effect in it that calls `switchLanguage`.
- The language switcher and user-nav paths (`ensureLanguage` before `changeLanguage`) run on a click, long after hydration, and need no change.

## Adjacent classes

- Scenario A (a fresh cookie loses to an older localStorage value) is a design choice recorded in the hook's comment, not filed here.
- `?lang=` is applied to both server and client, so it never diverges.
- Whether auth pages mount the same hook (RootComponent's bare routes) is unprobed.

## Unverified (not probed this run)

- How often a real browser keeps localStorage but loses the cookie: the script-written cookie's 365-day expiry against a Safari-style cap, or a user clearing cookies only, was not measured.
- The mechanism in a non-minified build, and which boundary throws.
