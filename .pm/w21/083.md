# 083 — Enforce the dashboard CSP's narrowed `connect-src` once a QA sweep shows no report-only violation

Why: w21/081 ships the narrowed `connect-src` (the page, Kratos, bex-api, the agent stream, the Web Shell WebSocket, the attachments bucket, `https://api.stripe.com`, `https://cloudflareinsights.com`) as `Content-Security-Policy-Report-Only` beside the enforced `connect-src 'self' https: wss:`. Narrowing it blind would silently break whichever flow's origin was missed, and the code cannot prove a flow it never runs (Stripe's Payment Element can reach `link.com` when Link is enabled on the account; the live-log SSE and the agent stream have their own URLs). Report-only turns each miss into a `[Report Only] Refused to connect` console message with no user-visible effect, so this note is the dated step that makes the narrowing real.

- **Source:** w21/081, 2026-11-14. Stripe's documented Stripe.js list, read the same day at `https://docs.stripe.com/security/guide`: `connect-src https://api.stripe.com https://maps.googleapis.com` (the Address Element, not used here), and for Link `https://link.com https://*.link.com`.
- **Due:** after the first production deploy that carries the report-only header, in the next `/qa-find-bugs` rounds (which already read the console), and no later than 2026-12-14; a violation names the origin to add, or proves the call is gone.
- **Size:** about 45m: the sweep (sign in as the QA user with `bash scripts/qa-login.sh`; open the home, a service with live logs, the web shell, a database page, an agent session with an attachment upload, billing and the add-card panel in a test workspace, the device and consent pages), then the switch.

## Steps

1. On production after the deploy, run the sweep above with the console open and collect every `[Report Only]` violation.
2. Add each origin a real flow needs to `narrowedConnectSources` (and its test), or explain why not; for Stripe check whether Link is enabled and add `https://link.com https://*.link.com` only if so.
3. Replace the enforced `connect-src 'self' https: wss:` by the narrowed list in production (dev keeps its wide one), delete the report-only header and its tests, and update `dashboard/AGENTS.md`.

## Acceptance

- Production enforces a `connect-src` that names origins, a sweep of every flow above shows no refusal, and the report-only header is gone.
