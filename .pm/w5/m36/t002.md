## Objective

Live Render's Logs page exposes a time-range selector; bex supports bounded log queries but the dashboard has no user control for the range, and the chosen window cannot be deep-linked or restored. Add a compact range selector backed by URL search state, applied consistently to the history query, keeping live-tail behavior explicit.

## Context

- Absorbed from `w5/016` (dashboard walk — Logs, 2026-07-15; `render-walk-service-logs.png` vs `bex-walk-service-logs.png`).
- Does NOT own the backend host/path filter work — that's `w3/m18`.
- The backend enforces `BEX_MAX_QUERY_HOURS` (default 30 days) — the selector's windows must fit inside it.

## Steps

1. Add the range selector (Render-relevant recent windows) with URL-owned state (the m23 filter-UI patterns).
2. Feed the selected bounds into the history query; define live-tail interaction explicitly.
3. Tests for parsing/defaults/restore.
