## Objective

Valkey log lines get a level from their severity marker, and the Key Value log contract accepts `level` on REST, GraphQL and MCP, returning only matching lines — as Postgres has since w8/m48.

## Context

- `lego/backend/internal/datastorelogs/logs.go:179-189` — `ParseLine` returns a level only for `KindPostgres` (via `CNPGLine`/`postgresLevel`, `:217-256`).
- Valkey's line format: `<pid>:<role> <date> <time> <marker> <message>`, where the marker is `.` (debug), `-` (verbose), `*` (notice), `#` (warning).
- `lego/backend/internal/logs/service.go:779-781` — `validateKeyValue` returns 400 for `Level`.
- Map onto the level vocabulary Postgres already emits (check `postgresLevel` and the REST level enum), documenting the mapping (e.g. `.`/`-` → debug, `*` → info, `#` → warning).

## Steps

1. Add a `KindKeyValue` branch in `ParseLine` that parses the marker and strips nothing else from the message.
2. Allow `Level` in `validateKeyValue`; apply it in the existing line-level filter.
3. Lines without a recognizable marker keep an empty level and are excluded only when a level filter is set.

## Files

- lego/backend/internal/datastorelogs/logs.go
- lego/backend/internal/logs/service.go
