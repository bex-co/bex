## Objective

Confirm the create-entry flow now matches Render's, and that no surface silently diverges. This milestone is dashboard-only UX — the backend surfaces (REST/GraphQL/MCP) already accept `type` at create — so parity scope here is the dashboard create-entry IA plus the Render deep-link contract.

## Context

- Render surfaces cron creation as a distinct action and its create URL is per-type (`/environment/.../cron/new`). bex resolves Render-shaped URLs via `render-alias.ts` and creates through the unified wizard.
- bex-api create already accepts `type`/`schedule`/`command` across REST (`POST /v1/services`), GraphQL (`createService`), and MCP (`create_cron_job`) — see `docs/ADR006-bex-api.md` and `docs/ADR038-cron-jobs.md`. No backend change is expected; verify no drift was introduced.

## Steps

1. Walk the create flow for each type: Render deep-link alias → wizard preselection → successful create. Compare the entry IA to Render's per-type create actions.
2. Confirm REST/GraphQL/MCP create semantics are untouched (this milestone changed only the dashboard entry flow).
3. Record any residual divergence (e.g. Render's project/environment-scoped create context) as a follow-up note rather than silently diverging; update the ADR018 dashboard cell if warranted.
