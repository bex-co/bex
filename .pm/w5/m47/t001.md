## Objective

Make the create wizard deep-linkable to a service type: accept a `type` search param and initialize the wizard's `serviceType` from it, so `/services/new?type=cron_job` opens with **Cron Job** preselected instead of the hard-coded Web-Service default.

## Context

- `dashboard/src/features/services/lib/create-context.ts` — `parseNewServiceSearch` currently returns only `projectId`/`environmentId`; `NewServiceSearch` type is defined here too.
- `dashboard/src/routes/services.new.tsx:451` — `const [serviceType, setServiceType] = useState<ServiceType>("web_service")` ignores the URL entirely; `search = Route.useSearch()` is already read at line 445.
- The 5 valid types are enumerated in `services.new.tsx:90-95` / `SERVICE_TYPE_DEFS` (`services.new.tsx:173-209`): `web_service`, `private_service`, `background_worker`, `cron_job`, `static_site`.

## Steps

1. Add an optional `type` field to `NewServiceSearch` and to `parseNewServiceSearch`, accepting only the 5 known `ServiceType` values (anything else omitted).
2. In `services.new.tsx`, initialize `serviceType` from `search.type` when present and valid, else `web_service` (lazy `useState` initializer or a guarded default).
3. Keep `projectId`/`environmentId` behavior unchanged.

## Files

- `dashboard/src/features/services/lib/create-context.ts`
- `dashboard/src/routes/services.new.tsx`

## Acceptance criteria

- [ ] `/services/new?type=cron_job` renders with Cron Job selected and the schedule/command fields visible.
- [ ] `/services/new?type=static_site` (and web/worker/pserv) preselect their type.
- [ ] `/services/new` and `/services/new?type=bogus` both default to `web_service` (no regression).

## Out of scope

- The render-alias URL mapping (t002) and New-menu entries (t003).
