## Objective

Stop dropping the service type when resolving Render's per-type create URLs. Map each `/{web,worker,pserv,static,cron}/new` alias to a **type-carrying** `/services/new?type=<serviceType>` so a Render-shaped `/cron/new` deep link preselects Cron Job (relies on t001's `?type=` handling).

## Context

- `dashboard/src/common/lib/render-alias.ts:34-38` currently maps every create alias to the bare `/services/new`:
  ```ts
  web: "/services/new",
  worker: "/services/new",
  pserv: "/services/new",
  static: "/services/new",
  cron: "/services/new",
  ```
- This is the create-side counterpart to the detail deep-link routes (`/cron/$` etc.) shipped in w5/m39; the detail side already redirects correctly — only the create side loses the type.
- Segment→type mapping: `web → web_service`, `worker → background_worker`, `pserv → private_service`, `static → static_site`, `cron → cron_job`.

## Steps

1. Update the create-alias map so each entry is `"/services/new?type=<serviceType>"` (or construct the query in the resolver if the alias map is consumed structurally — match the file's existing pattern).
2. Verify sub-path/query preservation still holds for the detail aliases (unchanged).

- [ ] Detail-route aliases (`/web/$`, `/cron/$`, `/d/$`, `/r/$`) are unchanged.
