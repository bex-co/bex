## Objective

Surface cron creation as a first-class action, matching Render's distinct "New Cron Job". Add at least a "Cron Job" entry (ideally all service types) to the "New" menu(s) that links to `/services/new?type=cron_job`, so users don't have to open a generic "New service" wizard and hunt for the type radio.

## Context

- `dashboard/src/common/components/dashboard-layout/new-resource-menu.tsx:29` — the New-resource menu currently has a single `<Link to="/services/new">{t("services.createTitle")}</Link>` for services, plus database/key-value entries.
- `dashboard/src/routes/index.tsx:176` — the services-list "New" dropdown mirrors this: generic "New service" (`projects.newService`) + database + key value.
- `dashboard/src/features/projects/` — the project New-resource menu (`projects.newService`) has the same shape.
- Render surfaces per-type create actions (Web Service, Private Service, Background Worker, Cron Job, Static Site) rather than one generic entry.

## Steps

1. Decide the least-noisy IA that reaches parity: either (a) a "Service" submenu listing the 5 types, or (b) at minimum a dedicated "Cron Job" item. Prefer (a) if it stays clean; keep the generic entry only if it still makes sense.
2. Each per-type item links to `/services/new?type=<serviceType>`.
3. Apply consistently across the dashboard-layout New menu, the services-list New dropdown, and the project New-resource menu (avoid drift between the three).
4. Add en + zh locale strings for any new labels (e.g. `services.typeCron` already exists — reuse type labels where possible).
