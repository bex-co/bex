## Objective

Add the client-side data layer for the Environments feature: TanStack Query hooks wrapping the `environments`/`environment` GraphQL queries and `createEnvironment`/`renameEnvironment`/`deleteEnvironment`/`setEnvironmentServices` mutations already shipped in `w1/m32` (`lego/backend/internal/environments/graphql.go`).

## Context

- Backend GraphQL surface: `lego/backend/internal/environments/graphql.go` (full CRUD + `setEnvironmentServices`).
- Mirror the existing `dashboard/src/features/projects/hooks/use-projects.ts` pattern (query keys, cache invalidation, optimistic update shape) — Environments layers directly on Projects (`docs/ADR032-environments.md`).
- New feature directory: `dashboard/src/features/environments/`.

## Steps

1. Add `dashboard/src/features/environments/api/environments.graphql` operations (list/get/create/rename/delete/setEnvironmentServices) and generate types via the existing codegen pipeline.
2. Add `dashboard/src/features/environments/hooks/use-environments.ts` (list/get) and `use-create-environment.ts`/`use-rename-environment.ts`/`use-delete-environment.ts`/`use-set-environment-services.ts`, following `use-projects.ts`'s cache-invalidation approach.
3. Add `dashboard/src/features/environments/types.ts` for the shared TS shape.
