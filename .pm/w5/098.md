# A Blueprint resource conflict names its kind in display text, not the manifest kind

Why: the takeover dialog maps the conflict's kind to a localized label, and today it must accept bex-api's display spelling `"key value"` as a lookup key, so rewording that text would leave zh users an untranslated kind again.

- **Where:** `lego/backend/internal/apps/blueprint_ownership.go` records the claim kind as `"key value"` (~`:121`) and maps `key_value` to it (~`:218`) before it reaches GraphQL `extensions.kind`. The dashboard accepts both spellings in `dashboard/src/features/blueprints/lib/kind-labels.ts` (`KIND_LABEL`), and `"database"` likewise.
- **Fix:** put the manifest kind (`service`, `postgres`, `key_value`, `env_var_group`) in `extensions.kind` and keep the display wording in the message only; then drop the display-text keys from `KIND_LABEL`. Check REST and MCP carry the same field.
- **Size:** about 30 minutes. Found by w5/m125's quality review.
