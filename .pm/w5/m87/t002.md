## Objective

Project public instance IDs consistently from current, ranged, and limit metrics and from INSTANCE discovery.

## Context

- metrics/service.go returns u.Pod or pod.Name as instance on snapshot and limit paths.
- metrics/source.go returns raw pod labels from Prometheus; MetricsFilters also returns Pod names.
- The current resource selection and cAdvisor dedup behavior must remain correct while labels change.

## Steps

1. Apply t001's mapping at the common public projection boundary for current and historical metric series.
2. Update INSTANCE discovery with the same identity rule, without per-series Kubernetes requests.
3. Keep values, units, time-window bounds, and resource authorization intact; expose missing history honestly.

## Files

- `lego/backend/internal/metrics/service.go`
- `lego/backend/internal/metrics/source.go`
- `lego/backend/internal/metrics/graphql.go`

## Acceptance criteria

- [ ] Snapshot, ranged, limit, and discovery outputs use the canonical public IDs.
- [ ] A deleted historical pod does not lose its samples because it cannot be fetched from Kubernetes.
- [ ] Metric values and authorization behavior are unaffected by identity projection.
