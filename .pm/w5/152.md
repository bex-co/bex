# A public repository's build can pin a branch tip up to five minutes old

Why: the build of a Public Git URL service now checks out the commit bex-api resolves for it. The unauthenticated resolver caches `owner/repo@branch` for five minutes across the process, so a create or deploy right after a push can build the commit from before it, and the clone's commit check passes.

- **Where:** `lego/backend/internal/github/service.go` `resolvePublicCommit` (`publicCommitMemo`, five-minute TTL, singleflight). Its result pins `spec.BuildCommit` on create (w5/138), on `deploys.Service.Trigger` and on a Blueprint redeploy. Before w5/138 only the deploy row's provenance could be stale on create.
- **Fix:** don't serve a cached branch tip when the result becomes a build input, or cache only for seconds. The cache protects the unauthenticated rate limit (60 requests an hour per IP), so either keep a short memo for bursts or fall back to building the branch when a fresh lookup is refused.
- **Test:** a resolution after the cached tip has moved returns the new commit once the cache window allows it, and a refused lookup leaves the build unpinned.
- Found by w5/138's quality review (2026-10-07).
