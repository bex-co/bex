## Objective

Render's `postgresPATCHInput.readReplicas` works on bex: the PATCH body's replica array replaces the database's replica set (omitted = unchanged, `[]` = remove all), validated exactly as create validates it, with dry-run support.

## Context

- `lego/backend/internal/postgres/rest.go:454-474` — `handleUpdatePostgres`' strict request struct; no `readReplicas` field, so the decoder returns 400 today.
- `lego/backend/internal/postgres/service.go:1096-1119` — `PostgresPatch` (pointer fields, nil = unchanged) and its `validate()`; `UpdatePostgres`/`UpdatePostgresDryRun` at `:1441,1448`.
- Create maps `ReadReplicaInput` → `appv1alpha1.DatabaseReadReplica{Name}` at `service.go:764-767`; reuse the same mapping and the create path's name validation.
- `lego/backend/internal/postgres/admission.go:38-89` already compares desired vs current `ReadReplicas` and refuses by name (plan CPU, `MaxReadReplicas`, `PostgresReadReplicaMinStorageGB`) — make sure the patched set is what it sees.
- Replica ids are derived from the primary id + name (`ReadReplicaID`, `service.go:218`), so a rename is a remove + add.

## Steps

1. Add `ReadReplicas *[]ReadReplicaInput` to the REST request struct and to `PostgresPatch`; map it in the REST handler.
2. Validate in `PostgresPatch.validate()` (names, duplicates) and apply it in the update path onto `d.Spec.ReadReplicas`, so admission checks the patched set.
3. Combined patches (plan + replicas, storage + replicas) are judged against the patched values together, not the stored ones.

## Acceptance criteria

- [ ] A REST PATCH with `readReplicas: [{"name":"r1"}]` on an eligible database sets `spec.readReplicas`, and the response's `readReplicas` lists it.
- [ ] `[]` removes every replica; an omitted field leaves the set unchanged.
- [ ] Each refusal (plan CPU, count, storage, invalid/duplicate name) answers the same named error and code as create, and writes nothing.
- [ ] `dryRun: true` previews the replica change without writing.
