## Objective

Match Render's static-site IA: a static service lands on **Events** (not Deploys), Events is a top-level sidebar item, and there is **no Deploys tab** for static sites. Web/worker/pserv/cron keep their current Deploys-first IA.

## Context

- Render's static sidebar (live capture 2026-07-28): top-level **Events** + **Settings**; **Monitor**: Metrics; **Manage**: Environment, Redirects/Rewrites, Headers. The bare `/static/<id>` URL lands on Events; there is no separate Deploys tab (deploy history/detail is reached from the Events feed).
- bex today: `dashboard/src/features/services/components/service-nav.tsx` `serviceNavGroups()` (lines 93-115) puts **Deploys** + Settings top-level and **Events** under Monitor for all types (static included). The service root redirect `dashboard/src/features/services/lib/service-root-redirect.ts` sends every service root to `/deploys`, called from `dashboard/src/routes/services.$serviceId.index.tsx`.
- Deploy detail routes (`/deploys/dep-…`) stay reachable from the Events feed — only the top-level Deploys **tab** is dropped for static.

## Steps

1. In `serviceNavGroups()`, when `type === "static"`: top-level `[EVENTS, SETTINGS]`, Monitor `[METRICS]`, Manage `[ENVIRONMENT, REDIRECTS, HEADERS]`. Leave every other type's groups exactly as they are. Guard the `type === null` (loading) state so a static site never flashes a Deploys tab (mirror the existing `manageTail` null handling).
2. Make the static-service root land on Events: branch `redirectServiceRoot` (or its callers) so a static-typed service redirects to `/events` (under the t001 canonical base) instead of `/deploys`. Keep non-static → Deploys.
3. Confirm the Deploys route still exists (deep links from Events work) but is absent from the static sidebar.
