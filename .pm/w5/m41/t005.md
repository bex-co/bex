## Objective

Replace the Project table's Created-only operational metadata with the populated Render view's Runtime, Region, and Updated facts, generalized honestly across bex's supported resource kinds.

## Context

- `ResourceTable` currently renders `Name · Type · Status · Created · Actions` and uses `formatRelativeAge(createdAt)`.
- Render's populated Project renders `Name · Status · Runtime · Region · Updated · Options`.
- T002 supplies nullable server facts. T001 pins exact per-kind labels; static/global and datastore-version presentation must come from real data or an explicitly documented type/version mapping, never guesswork.

## Steps

1. Extend `ResourceRow` normalization with the t002 metadata and t001's evidence-backed per-kind runtime label rules.
2. Render responsive Runtime, Region, and Updated columns while retaining enough type identity for mixed bex resources.
3. Feed Updated only from `updatedAt`; use the shared relative-age formatter and an em dash/accessible unknown state when absent.
4. Keep links, status badges, row actions, loading skeletons, mobile layout, and search/type filtering intact.
5. Cover web/native/Docker/static, Postgres, Key Value, configured/unconfigured region, and missing timestamp cases.

## Acceptance criteria

- [ ] Populated rows expose Runtime, Region, and authoritative Updated values where available.
- [ ] No row labels `createdAt` as Updated or fabricates runtime/region.
- [ ] All supported resource kinds remain distinguishable and actionable on desktop and mobile.
- [ ] Skeleton/header/body column shapes remain aligned.

## Out of scope

- A region picker or multi-region scheduling.
- Adding unsupported Render resource families.
