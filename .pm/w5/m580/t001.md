## Objective

Fix the four verified multi-value query-parameter parsing bugs on served Render list endpoints so comma-separated (`explode=false`) and repeated query parameters work as declared in the pinned Render OpenAPI contract.

## Context

- `GET /v1/notification-settings/overrides` (`list-notification-overrides`): pinned OpenAPI declares `ownerId` as `type=array, style=form, explode=false`, but `lego/backend/internal/apps/rest.go:1910-1936` calls `q.Get("ownerId")` and wraps it in a 1-element slice for `core.ListForCaller`.
- `GET /v1/build-sources` (`list-build-sources`): pinned OpenAPI declares `name` as `type=array, style=form, explode=false`, but `lego/backend/internal/apps/build_sources.go:838` passes raw `q["name"]` instead of `core.QueryNameList(r.URL, "name")`.
- `GET /v1/services/{id}/jobs` (`list-job`): pinned OpenAPI declares `status` as `type=array, style=form, explode=false`, but `lego/backend/internal/jobs/rest.go:93` passes raw `q["status"]` to `FilterFromStrings`, which rejects `"pending,running"` as an unknown status.
- `GET /v1/services/{id}/events` (`list-events`): `lego/backend/internal/events/rest.go:569` passes `[]string{q.Get("type")}` to `FilterOf`, silently dropping repeated `?type=` keys after the first.

## Steps

1. Update `listOverrideApps` and `registerNotificationOverrideRoutes` in `lego/backend/internal/apps/rest.go` to parse `ownerId` with `core.QueryList(q, "ownerId")` and pass the slice to `core.ListForCaller`.
2. Update `registerBuildSourceRoutes` in `lego/backend/internal/apps/build_sources.go` to parse `name` with `core.QueryNameList(r.URL, "name")`.
3. Update `filterFromQuery` in `lego/backend/internal/jobs/rest.go` to parse `status` with `core.QueryList(q, "status")` so comma-separated and repeated statuses both parse and validate each member.
4. Update `filterFromQuery` in `lego/backend/internal/events/rest.go` to pass `q["type"]` to `FilterOf` so repeated `?type=` parameters and comma lists both apply.
5. Add unit/handler tests in each touched package proving both comma-separated and repeated forms work and invalid enum values still fail with 400.

## Acceptance criteria

- [ ] `GET /v1/notification-settings/overrides` honors both `?ownerId=a,b` and `?ownerId=a&ownerId=b` across caller-authorized workspaces.
- [ ] `GET /v1/build-sources` honors `?name=a,b`, `?name=a&name=b`, and percent-encoded literal commas `?name=a%2Cb`.
- [ ] `GET /v1/services/{id}/jobs` honors `?status=pending,running` and `?status=pending&status=running`, rejecting unknown members with 400.
- [ ] `GET /v1/services/{id}/events` honors `?type=deploy_ended,server_failed` and `?type=deploy_ended&type=server_failed`.
- [ ] Package tests in `apps`, `jobs`, and `events` pass.
