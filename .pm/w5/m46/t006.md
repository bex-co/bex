## Objective

Add meaningful automated coverage that fails when the PTY contract, `pgcli` child handoff, bounded-exit behavior, or credential-redaction guarantees regress.

## Context

- Tests can use stub Render/API/client processes for deterministic failure modes; the real non-production SQL smoke remains the acceptance layer.
- Important failures include one standard stream not being a TTY, `CI=true`, `TERM=dumb`, forced `RENDER_OUTPUT`, absent binaries, empty/malformed external URI, wrong passthrough arguments, child failure, and a child that never exits.
- A planted secret must be checked against all durable stdout/stderr/evidence artifacts, not merely omitted from the happy-path echo.

## Steps

1. Add deterministic PTY tests for all-stream TTY detection, terminal sizing, marker exchange, exit propagation, timeout, and descendant cleanup.
2. Add verifier tests for id/name agreement, exactly-once child invocation, passthrough argument order, empty/malformed URI rejection, and non-zero real-client exit.
3. Plant sentinel token/password/URI values and assert they appear in no durable output or artifact, including failure paths.
4. Run Python/shell syntax checks, focused tests, Markdown formatting, and `git diff --check`.

- `scripts/render-cli-pty.test.sh`
- `scripts/pgcli-compat-verify.test.sh` (new)

## Acceptance criteria

- [ ] Tests fail if any standard stream is not a TTY in the interactive child or if `CI`/forced output causes a false pass.
- [ ] Tests fail on hang, leaked descendant, missing/multiple child invocation, malformed handoff, wrong passthrough order, or swallowed child exit.
- [ ] Planted credentials are absent from all captured output and files on both success and failure.
- [ ] Syntax checks, focused tests, Prettier, and `git diff --check` pass.

## Out of scope

- Tautological snapshots, tests that merely restate fixture output, or requiring a live public database in the fast deterministic test suite.
