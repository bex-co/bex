# An unavailable Key Value says why, as a sentence and a code the dashboard translates

Why: w5/079 gave unavailable databases a fixed sentence plus a code the dashboard translates, but an unavailable Key Value says nothing about why, although the operator records a reason for each of its ~15 failure paths.

- **Where:** `lego/backend/internal/keyvalue/service.go` `kvStatus` (~`:217`) turns `KVPhaseFailed` into "unavailable", but `KeyValueView` (~`:78`) has no reason. The operator calls `kvFail` with literal reasons (`lego/operator/internal/controller/keyvalue_controller.go`, `keyvalue_persistence.go`, `keyvalue_persistence_live.go`): `SecretFailed`, `ServiceFailed`, `StatefulSetFailed`, `PVCResizeFailed`, `BackupCronJobFailed` and others. The dashboard's Key Value Details card has no reason row.
- **Fix:** follow w5/079 exactly. Add `Reason*` constants to `lego/types/v1alpha1/keyvalue_types.go` (it already holds `ReasonConnectionSecretRebuilding`) and use them in the operator. Add `statusReason` and `statusReasonCode` to `KeyValueView` on REST, GraphQL (`OptionalStrField`) and MCP, with a fixed sentence per reason and never the raw condition message. Translate them in en and zh in the dashboard, with a vocabulary guard like `features/databases/lib/__tests__/status-reason-vocabulary.test.ts`.
- **Size:** about 1–2h across operator, backend and dashboard; promote to a milestone when taken. Found by w5/079's reuse review.
