## Objective

Remove the fake-LanguageModel detour from the driver's turn loop. Instead of `@mcpc-tech/acp-ai-provider` → `streamText` → `toUIMessageStream()` (drops `raw`) + `.fullStream` raw re-drain → generic `data-acp`, drive the official `@agentclientprotocol/sdk` `ClientSideConnection` directly and map every ACP `session/update` to a typed UI-message part in one `sessionUpdate()` handler, framed by `ai@6`'s `createUIMessageStream` writer. Stay on AI SDK v6.

## Context

- `@agentclientprotocol/sdk@0.14.1` (already a dependency) exports `ClientSideConnection(toClient, stream)` with `initialize`/`newSession`/`loadSession`/`prompt`/`cancel`, and a `Client` interface we implement: `sessionUpdate(params: SessionNotification)` (the mapping hook), `requestPermission(...)`, optional `readTextFile`/`writeTextFile`/`createTerminal`/`terminalOutput`/`waitForTerminalExit`/`releaseTerminal`/`killTerminal`.
- ACP `session/update` discriminated by `update.sessionUpdate`: `plan`, `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update` (content items `type:"diff"|"terminal"|"content"`, plus `rawInput`/`rawOutput`/`status`), `available_commands`, etc. (see `fixtures/acp-agent.mjs`).
- `ai@6.0.237` exposes `createUIMessageStream({execute})` + `UIMessageStreamWriter` supporting `type:"data-${NAME}"` parts — use it to emit protocol-correct frames without `streamText`.
- The driver already frames its own SSE (`stream-hub.ts` `frame()`); `server.ts` sets `x-vercel-ai-ui-message-stream: v1`. Keep both. `publish`/`redactPart`/`hub` fan-out, the status/`session.jsonl` logging, timeout/abort, delivery/evidence/scrub, and resume (`adoptPersistedSession` + `loadSession` gating on the `loadSession` capability) must be preserved.
- Files today: `session.ts` (`runHeadlessTurn`, dual consume at :189-202, `rawUIMessagePart` :84-97), `acp.ts` (`createSessionProvider`/`createACPProvider`, `probeAgentCapabilities`, `spawnRawACP`).

## Mapping (ACP update → typed UI part)

- `agent_message_chunk` → `text` (start/delta/end as today).
- `agent_thought_chunk` → `reasoning`.
- `tool_call` / `tool_call_update` → a proper `tool-*` (or `dynamic-tool`) part carrying the **real** `title`/`kind`/status/input/output — NOT collapsed into one synthetic tool. This deletes the client's `unwrapAcpTool` need.
- `tool_call_update` content `type:"diff"` → `data-acp-diff` (`{path, oldText, newText, toolCallId}`).
- `tool_call_update` content `type:"terminal"` → `data-acp-terminal` (`{terminalId, output?, toolCallId}`).
- `plan` → `data-acp-plan` (`{entries:[{content, status, priority}]}`).
- `available_commands` and any unrecognized variant → handled explicitly (log + optional typed part), never silently dropped.

## Steps

1. Rewrite `acp.ts`: spawn the agent child, wrap stdio as the SDK `Stream`, build `ClientSideConnection` with a `Client` impl (permission auto-approve per current sandbox-confined policy; terminal/fs handlers as required by the agent). Expose `initialize`/`newSession`|`loadSession`/`prompt`/`cancel` + `getSessionId`/`cleanup`. Keep the `loadSession`-capability gate for resume.
2. Rewrite `session.ts` `runHeadlessTurn` to: open the connection, create/load the session, run one `createUIMessageStream({execute})` whose `execute` awaits `prompt(...)` while the `sessionUpdate` handler writes typed parts through the writer; pipe the writer's stream into `publish`/hub. Delete `consumeUI`/`consumeRaw`/`rawUIMessagePart` and the `streamText` import.
3. Keep `publish`→`redactPart`→hub + `logPart`, status writes, timeout/abort (`cancel()` on deadline), delivery/evidence/scrub, resume provenance.
4. `package.json`: drop `@mcpc-tech/acp-ai-provider`; keep `ai@6` + `@agentclientprotocol/sdk`; regenerate `package-lock.json`; keep `Dockerfile` runtime deps working.
5. Build (`tsc`) + run the offline fixture turn (`test/driver.test.ts`, extended in t006) green.
