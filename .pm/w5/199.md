# The REST OpenAPI gate joins repeated keys for `explode=false` enum queries only on datastore `region`, letting invalid second values slip past validation on other lists

Why: `kin-openapi`'s `explode=false` query decoder validates only the first repeated key, so requests like `GET /v1/services?region=frankfurt&region=BOGUS` or `GET /v1/services?type=web_service&type=BOGUS` bypass the Render OpenAPI gate and answer 200 instead of 400.

**Source:** `/pm-brainstorm one aspect of render parity in backend for w5` (2026-11-23, round 11 item 5), verified against `main@3854adf442`. **Estimate:** ~45m–1h.

## Evidence

- `lego/backend/internal/api/render_openapi.go:894-904` explicitly notes `kin's explode=false decoder validates only the first repeated value`, but only joins repeated query keys for `region` on `list-postgres` and `list-key-value`.
- Every other served operation with an `explode=false` array query parameter — `list-services` (`type`, `env`, `region`, `suspended`), `list-postgres` (`suspended`), `list-job` (`status`), `list-sandboxes` / `list-sandbox-builds` / `list-sandbox-snapshots` (`status`), `list-routes` (`type`), `list-registry-credentials` (`type`), and `list-events` (`type`, rewritten to `explode=false` by `renderCommaListQueryCompatibility`) — hits the same `kin-openapi` single-key bypass.
- Handlers that rely on the OpenAPI gate for enum validation (for example `list-services` `type`, `env`, and `region` in `lego/backend/internal/apps/rest.go:928,937-938`) do not re-validate those enums, so a bogus second repeated value silently succeeds with HTTP 200 instead of 400.

## Fix

1. At contract load time in `lego/backend/internal/api/render_openapi.go`, precompute per-operation `explode=false` array query parameter names (excluding `name`, which preserves raw percent-encoded literal commas per `w8/m55`).
2. Replace the hardcoded `list-postgres`/`list-key-value` `region` special case (`render_openapi.go:898-904`) with a general join of repeated values for any precomputed `explode=false` non-`name` parameter on `validationRequest` before `validateRenderRequest`.
3. Add composed-server regression tests in `lego/backend/internal/api/` covering repeated invalid second values on `list-services` (`region`, `type`, `env`), `list-events` (`type`), `list-routes` (`type`), and `list-sandboxes` (`status`) — proving each returns 400 (and fails if the join is reverted) while `list-services?name=a%2Cb` literal commas remain intact.
4. Update `docs/ADR018-render-parity.md` § List-query census / `docs/render-artifacts/openapi-request-validation.md` if applicable.
