# Log, forbidden and protected-environment refusals carry no error code, so the dashboard matches message text

Why: w5/m125 moved Blueprint takeovers onto `errorDetails{code}`, but four dashboard decisions still substring-match server copy, so rewording a message in bex-api silently changes what the dashboard shows.

- **Where (dashboard):** `"durable log store"` in `dashboard/src/features/logs/hooks/use-log-history.ts:23`, `features/deploys/hooks/use-deploy-logs.ts:41` and `features/metrics/lib/graphql-series.ts:20`; `"logs source not configured"` in `features/logs/components/datastore-log-viewer.tsx` (the `unavailable` check); `"forbidden"` in `common/lib/graphql-error.ts:34` `isForbiddenError`; `"protected environment"` in `features/services/lib/protected-confirmation.ts:18`.
- **Where (bex-api):** these refusals have no code. `core.ErrLogsUnavailable` and `core.ErrLogStoreUnavailable` (`lego/backend/internal/core/errors.go:58`, `:65`) are plain `Unavailable(...)` sentinels, `core.ErrForbidden` (`:105`) is a bare error, and the protected-environment refusal wraps `ErrBadRequest` (`internal/core/confirmation.go:99`). Only a `core.CodedError` reaches GraphQL `extensions.code` (`internal/api/server.go:1549`).
- **Fix:** give each a stable code on GraphQL `extensions.code` and in the REST and MCP error bodies. Then branch on `hasGraphQLErrorCode` (`common/lib/graphql-error.ts:39`) and delete the markers. Keep the messages unchanged, since Render CLI users read them.
- **Size:** about 1–2h across backend and dashboard; promote to a milestone when taken. Found by w5/m125 t001–t002.
