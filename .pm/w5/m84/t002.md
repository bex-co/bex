## Objective

Agent-native resume works where the adapter supports it: the hibernation snapshot includes each reviewed profile's on-disk session state (ADR059 D3 continuity amendment), and on rehydrate the driver attempts ACP `session/load` when the adapter advertises `loadSession` and the state is present — falling to rung 2 otherwise.

## Context

- Snapshot tar roots: the hibernate mutable-mount list (ADR059 D3-B implementation) — add the per-profile state dirs (e.g. `claude-code-acp`'s HOME state; consult `lego/backend/internal/agentsession/agent-profiles.json` for per-agent paths and record them there declaratively, per the m77 profile-manifest direction).
- `loadSession` capability probe + `session/load` call: official `@agentclientprotocol/sdk` (driver already speaks it, w5/m66); ADR047 D7 lists `loadSession` support as an agent selection criterion.
- Credential-scrub interaction: `bex-pre-snapshot` must not strip the session state, but the state dirs must be scanned by the existing scrub (they can contain pasted secrets like any file).

## Acceptance criteria

- [ ] Hibernate→resume with a real prior conversation: `session/load` path restores agent memory (verified by a context-dependent prompt) when the adapter advertises it.
- [ ] Missing/corrupt state degrades to rung 2 with a logged reason, never a cold prompt.
- [ ] Scrub still covers the state dirs.

## Out of scope

- Memory-level (CRIU) resume — ADR059 non-goal.
