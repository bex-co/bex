## Objective

Env var and secret-file names are validated by the rule Kubernetes applies to Secret keys, with one vector file shared by Go and TS.

## Context

- `lego/backend/internal/core/config.go:58-68` defines `MaxConfigKeyLength = 253` and a length check. Names starting with `..` (e.g. `..data`) pass it, but Kubernetes' `validation.IsConfigMapKey` rejects them (`hasChDirPrefix`). `PUT …/secret-files/..data` writes the store, fails the projection, restores, and returns a generic 400.
- The fake client in `secrets/longname_test.go` hard-codes `len > 253`, so it can't catch this.
- TS: `dashboard/src/features/services/lib/environment-draft.ts:3` `VALID_ENV_KEY`; `dotenv-import.ts:1` redeclares the same regex.

## Steps

1. `ValidSecretFileName` becomes `len(validation.IsConfigMapKey(n)) == 0`, and `ValidEnvKey` a C identifier that also passes `IsConfigMapKey`. Delete `MaxConfigKeyLength`.
2. Make the fake client call `IsConfigMapKey`.
3. Add a shared `config-key-vectors.json` read by the core tests and `environment-draft.test.ts`; `dotenv-import.ts` imports `VALID_ENV_KEY`.
