## Objective

Make the workflow validator fail closed when a job that holds production credentials prints raw `kubectl` output, so a new diagnostic step cannot reintroduce the leak.

## Context

- `scripts/github-actions-validate.sh` and its fixture tests in `scripts/github-actions-validate.test.sh`.
- A production-credentialed job: one that runs `scripts/fetch-app-kubeconfig.sh` or uses a `production-*` environment.

## Steps

1. Add a check: in such a job, a `run:` that invokes `kubectl get`, `describe`, `logs` or `top` directly fails, unless it writes to a file that is not printed or goes through `scripts/cluster-diagnose.sh --public-log`.
2. Add a failing and a passing fixture.
3. Run the validator over the repository's workflows.

## Files

- scripts/github-actions-validate.sh
- scripts/github-actions-validate.test.sh

## Acceptance criteria

- [ ] The validator fails the raw-`kubectl` fixture and passes the repository.

## Out of scope

- Checking `psql` or `curl` output (record any t001 found as a follow-up if they print tenant data).
