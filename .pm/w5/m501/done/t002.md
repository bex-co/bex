## Objective

Move Cluster diagnose's reads into one script that prints full detail for an operator's local run and hashes tenant identifiers when its output goes to a public log, and make the workflow call it in that mode.

## Context

- `.github/workflows/cluster-diagnose.yml` steps: Service pods, Pending pods cluster-wide, Nodes and allocation, Cluster autoscaler.
- Tenant namespaces are workspace ids (`tea-…`) and `<ws>-sandbox`; platform namespaces are listed in `TenantRegistryImagePullFailing`'s exclusion (`deploy/gitops/base/rules/alerting_rules.yml`).
- Operators reach production locally with `bash scripts/fetch-app-kubeconfig.sh <path>` (AGENTS.md).

## Steps

1. Write `scripts/cluster-diagnose.sh <srv-id> [--public-log]` that runs the same reads.
2. In `--public-log` mode, replace tenant namespaces, tenant pod and service names, service ids, node names and IPs with short stable hashes (for example `ws#1a2b`), print tenant pod events as their reason only, and keep platform namespaces, counts, phases, waiting reasons and allocation figures readable.
3. Make the workflow call the script with `--public-log`; keep its credential scrubbing steps.
4. Add `scripts/cluster-diagnose.test.sh` that feeds recorded `kubectl` output and checks that no tenant identifier or IP survives `--public-log`.

## Files

- scripts/cluster-diagnose.sh
- scripts/cluster-diagnose.test.sh
- .github/workflows/cluster-diagnose.yml

## Acceptance criteria

- [ ] A run on `main` shows no `tea-` string, no service name and no IP address in its log, and still names failing pods' reasons and node readiness.
  - Checked live after the push, under the closeout (t009).
- [x] A local run with the production kubeconfig prints the full detail.
- [x] `bash scripts/cluster-diagnose.test.sh` passes.

## Out of scope
