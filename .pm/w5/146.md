# The projects list reads each project's environments separately

Why: `renderProjects` (`lego/backend/internal/projects/rest.go`) resolves owners in one batch, then calls `environmentIDs` once per project, so a page of N projects makes N store reads for its `environmentIds`.

- **Where:** `projects/rest.go` `renderProjects`, around :101; `environmentIDs` reads one project's environments.
- **Fix:** read every listed project's environment ids in one store query keyed by project id (an `EnvironmentIDsForProjects` returning a map), and render from it.
- **Test:** listing three projects makes one environment read, and each project keeps its own `environmentIds`.
