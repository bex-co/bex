# Render user ids are `usr-`; bex answers `own-`

Why: Render's pinned spec pins every `userId` (members list, member mutations, `GET /v1/users`) to `^usr-[0-9a-v]{20}$`, while bex answers its opaque `own-` id (w6/m7). A Render client that validates ids, or a script that builds a `usr-` id, does not round-trip, and no ADR018 row records a signed divergence.

- Where: `id.Owner` (`lego/backend/internal/id/id.go:72`, prefix `own`), `store.OwnerIDsForSubjects`, `workspaces/render.go` `toRenderTeamMember` (`UserID: m.OwnerID`), `GET /v1/users`.
- w5/m267 widened the member-mutation `userId` path pattern to `^(?:usr|own)-…$` so the ids bex hands out are accepted; the response side still answers `own-`.
- Fix shape (as w2/m269 did for Blueprints `blp-` → `exs-`): answer a `usr-` public alias on every surface while still resolving stored `own-` ids; keep the widening.
- Check first: ADR020 and w6/m7 for a recorded reason, and how Render's own CLI uses `userId` (`render whoami`, workspace members).
- Source: w5/m267 Render parity pass, 2026-11-05.
