## Objective

Wire the write half of the page: a create-database flow (name, plan picked from the postgres-family tier catalog, version, diskSizeGB, public) calling `createDatabase`, and a delete action with an explicit cascade-warning confirm calling `deleteDatabase`, with the list converging as the operator reconciles.

## Context

- Create body fields per `docs/bex-api.md`: `name`, `plan`, `version`, `diskSizeGB`, `public` (REST `POST /v1/postgres`; GraphQL `createDatabase` mirrors it).
- Plan options come from t002's postgres-family catalog read — radio cards or select per the t001 Render capture; no prices (Metronome's, per the w1/m8 decision).
- Delete cascades CNPG Cluster + PVC + route — the confirm must say data is destroyed; use the repo's `AlertDialog` idiom (w5/m7's picker confirm, m4's suspend confirm).
- After create, poll/refetch until the new row converges to ready (m4's lifecycle-convergence pattern).

## Steps

1. Create dialog/form with validated fields; plan options from the catalog hook; submit → `createDatabase` → toast → list refetch/poll to ready.
2. Row/detail delete action → cascade-warning `AlertDialog` → `deleteDatabase` → toast → row removed.
3. In-flight disabling on both mutations; error toasts surface API messages.
