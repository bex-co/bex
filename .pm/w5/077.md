# Native build failure text: drop the legacy loader branch and unescape the step-header path

Why: w8/052's error rewrite carries three problems: a branch for builds generated before w8/052, a `(:?)` that reads like a typo of `(?:`, and a step-header path that leaves JSON escapes in the user's command while the verdict path unescapes them.

Source: Last-24h code review, 2026-10-05 (user handed all fixes to w5). Follow-up to `8f58b933d` (w8/052). No secret risk found: env values arrive only through the secret mount, and `$VAR` stays unexpanded in the quoted command. The exit code is regex-parsed from BuildKit's text and fails safe (text left unchanged).

## Fix

1. `lego/operator/internal/build/build.go:711`: settle `(:?)` (decide whether an optional literal colon was intended) and cover it with a test either way.
2. Delete the pre-w8/052 inline-loader branch (`build.go:717-733`). It only matters for Jobs that failed during the rollout window, which have aged out.
3. Unescape JSON in the step-header path the same way the verdict path does.
4. Optional, decide here: `ARG BASH_ENV=/opt/bex/load-env`, with the loader ending in `unset BASH_ENV` (`build/native.go:224-250`). BuildKit's own message would then name only `/bin/bash -c <cmd>` and the exit code, and both regexes could go. Only do this if build semantics are unchanged.

Done: a failed native build names the user's unescaped command and its exit code on both paths; build tests green.
