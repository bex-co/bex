## Objective

Pin, from Render's own sources, what `aggregationMethod` (REST) / `cpuUsageAggregationMethod` (MCP) does and how `aggregateBy=host` labels its series, and record the bex decision the rest of the milestone implements. The two Render wordings disagree. REST says "the aggregation method to apply to multiple time series", which reads as across instances. Render's MCP server describes "aggregating metric values over time intervals". bex already has a cross-instance knob, `aggregateAllMethod` (REST/MCP/GraphQL → `parseReplicaAggregate`, `select.go:73`).

## Context

- Pinned REST contract: `lego/backend/internal/api/openapi/render-public-api-1.json` (`aggregationMethod` enum `AVG|MAX|MIN`; `aggregateBy` enum `statusCode|host`).
- Pinned MCP argument names only: `lego/backend/internal/api/openapi/render-mcp-tools.json` (`get_metrics`).
- Render's MCP server is open source (`render-oss/render-mcp-server`). Its `get_metrics` handler shows whether `cpuUsageAggregationMethod` is passed straight through to REST `aggregationMethod`, which would make the REST meaning authoritative for both.
- Current bex refusals: `lego/backend/internal/metrics/mcp.go:111-145` (`cpuAggregation`, `requestGroupBy`).
- A live Render probe is not available (`w10/002` is blocked on a real `RENDER_API_KEY`), so the decision rests on the published contract and the MCP server source.

## Steps

1. Read Render's metrics API reference and the MCP server's `get_metrics` source. Record the exact descriptions, defaults and the pass-through mapping, with fetch dates.
2. Pin the MCP descriptions (not just names) into `render-mcp-tools.json` or a `docs/render-artifacts/metrics-page.md` section, matching how other MCP descriptions are pinned.
3. Decide, in `metrics-page.md`, between two meanings:
   - **(a) Interval:** MAX/MIN within each resolution step → `max_over_time`/`min_over_time`.
   - **(b) Cross-series:** collapse per-instance series → the existing replica aggregate.
   If MCP passes through to REST, both surfaces get the same meaning. Also record what omitted vs explicit `AVG` returns, and how a combination with `aggregateAllMethod` behaves.
4. Record the host breakdown's series label (`host`) and its refusal when the request-log store is unavailable.
