## Objective

A closed deploy row can't keep `pre_deploy_status = 'running'` (w4/187), and Postgres enforces it rather than app code alone.

## Context

- w4/187 (`b7f56dc56`) fixed the app code; old rows may still violate it. A backfill is decidable, because `deactivated` can only follow `live` (`deploy_lifecycle.go`).

## Steps

1. Count the violating rows with a read-only query and backfill them in a migration.
2. Add a CHECK constraint (e.g. `finished_at IS NULL OR pre_deploy_status <> 'running'`), verifying the exact predicate against current data first.

## Files

- A new migration in the backend store migrations

## Acceptance criteria

- [ ] The migration applies to a copy with violating rows, and inserting a violating row fails.
