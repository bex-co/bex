## Objective

The Key Value detail page sends the display name (`keyValue.name`, the human name from `Spec.Name`) as `datastoreMetrics.query.resource`, but bex-api resolves that field as the KeyValue CR name — the typed id (`red-…`). Every lookup therefore misses, the GraphQL error is swallowed by `errorPolicy: "all"`, and all three charts render "No data in range". Pass the id, like every sibling usage already does.

## Context

- `dashboard/src/routes/keyvalue.$keyValueId.tsx:155` — `<DatastoreMetricsPanel kind="keyvalue" resource={keyValue.name} />` (the bug).
- Sibling precedent: `dashboard/src/routes/databases.$databaseId.tsx:166` passes `resource={database.id}`; the Key Value page's own log viewer (`keyvalue.$keyValueId.tsx:138`) passes `keyValue.id`.
- Backend contract: `findKeyValue` matches CR `metadata.name` only (`lego/backend/internal/core/base.go:1097`); CRs are named `id.New(id.KeyValue)` (`lego/backend/internal/keyvalue/service.go:398`).
- Root-cause record: `w5/done/044.md`.

## Steps

1. Change `resource={keyValue.name}` to `resource={keyValue.id}` in `keyvalue.$keyValueId.tsx`.
2. Add/extend a route test (`dashboard/src/routes/__tests__/keyvalue.$keyValueId.test.tsx`) asserting the metrics panel receives the id, not the display name (mirror however the databases page is covered).
3. `yarn test` in `dashboard/` green.
