## Objective

`DatastoreMetrics` authorizes and resolves the Database/KeyValue CR, then still builds every Prometheus matcher (PVC pattern, pod regex, CNPG cluster label) from the raw caller-supplied `DatastoreMetricQuery.Resource`. Any caller that sends a resolvable-but-different string gets silent empty series. After authorization, derive the matchers from the resolved CR's `metadata.name` so the identity the query authorizes is the identity it measures.

## Context

- `lego/backend/internal/metrics/datastore.go` — `DatastoreMetrics` sets `namespace = kv.Namespace` / `db.Namespace` from the resolved CR but passes `Resource: q.Resource` into `DiskUsageRequest`, `DBConnectionsRequest`, `ReplicationLagRequest`, `KeyValueStatsRequest`, and `pvcPattern(q.Kind, q.Resource)`.
- The ADR043 comment at `datastore.go:175-178` already fixed the same silent-empty class for **namespace**; this is the resource-name half of that seam.
- Sources consuming the field: `lego/backend/internal/metrics/source.go` (`NewPrometheusDiskUsageSource`, `NewPrometheusKeyValueStatsSource`, `NewPrometheusDBConnectionsSource`, `NewPrometheusReplicationLagSource`) — they take `req.Resource`/`req.Cluster` as given; no change needed there.
- REST (`parseDatastoreMetricParams`) and GraphQL (`datastoreMetricsQueryInputFromArgs`) adapters pass `resource` straight through — unchanged; the fix is in the shared service.

## Steps

1. In `DatastoreMetrics`, after `AuthorizeDatabase`/`AuthorizeKeyValue` returns the CR, use `db.Name` / `kv.Name` for `pvcPattern`, `DiskUsageRequest.Resource`, `DBConnectionsRequest.Cluster`, `ReplicationLagRequest.Cluster`, and `KeyValueStatsRequest.Resource`.
2. Regression tests in `lego/backend/internal/metrics/datastore_test.go`: fake the sources and a CR whose name differs from the input (e.g. authorize via a stub that resolves a display name to `red-…`) and assert the sources receive the CR name and the `^data-<cr-name>-\d+$` / `<cr-name>-[0-9]+` patterns.
3. `cd lego/backend && go test ./...` green.
