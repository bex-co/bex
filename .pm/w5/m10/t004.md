## Objective

Extend the custom-domains core so every domain carries the DNS record the tenant must create — record type derived from `domainType` (subdomain → CNAME to the app's platform host; apex → the captured Render guidance), host, and target — and add the Render-compatible verify verb (`POST /v1/services/{id}/custom-domains/{name}/verify` re-checking cert/DNS state now). One change in the core, surfaced identically by all three adapters.

## Context

- `lego/backend/internal/apps/domains.go` — `DomainView` (has `domainType`/`verificationStatus`/`serverStatus`; lacks any DNS-target field) and the core list/add/get/delete verbs the adapters share.
- The CNAME target is the platform hostname the app already exposes (`<name>.<BEX_BASE_DOMAIN>` / the app URL the `server` query returns) — no new operator work needed.
- Adapters: `apps/rest.go` (custom-domains routes), `apps/graphql.go` (`customDomains` field resolvers), `apps/mcp.go` (4 domain tools). Render's REST has `…/custom-domains/{idOrName}/verify` (confirmed in the 2026-07-09 API re-audit).
- Follow `docs/bex-api.md`'s one-core/thin-adapters rule; field spelling per the t003 capture.

## Steps

1. Add DNS-record fields to the domain core view (type/host/target per `domainType`), derived from the app's platform host.
2. Add the verify verb to the core (re-evaluate TLS-secret/cert state now) and expose it: REST `POST …/verify`, GraphQL mutation, MCP tool.
3. Regenerate/extend adapter wiring; update `docs/bex-api.md`'s domain section.
