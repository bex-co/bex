## Objective

Give release and date gates one form the guard can check, and make the board validator enforce it.

## Context

- Gates live in the workstream README's `**BLOCKED (…)**` summary (`.claude/skills/pm/SKILL.md`, `.claude/skills/loopx/worker.md` § blocked).
- w9's lines already use the form ``production's pin must carry `<sha>` ``; w5's m369, m371 and m372 say "the next batched production deploy pins this code" with the commits only in their READMEs.

## Steps

1. Define the forms: ``pin must carry `<sha>`[, `<sha>`…]`` for a release gate, and `date gate: <YYYY-MM-DD>` (optionally `THH:MMZ`) for a date gate. Document them in the pm skill and in `worker.md`'s blocked outcome.
2. Make `scripts/pm-board-validate.py` fail a BLOCKED summary that mentions a pin, release gate or production deploy without the commit form (and a date gate without a date).
3. Migrate the existing release gates: take each item's commits from its README or note and rewrite its workstream line in the new form.
