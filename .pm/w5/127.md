# Identity lookups fetch every member's TOTP secret just to learn whether MFA is on

Why: `KratosIdentities.Lookup` and `LookupMany` ask Kratos for `include_credential=totp` so that `MFAEnabled` can see a TOTP credential. That include returns the credential's config, which holds the TOTP secret, for every member on every Team-page poll. Only the credential's presence is read.

- **Evidence** (Kratos v26.2.0 on dev-5, 2026-10-07): once any `include_credential` is given, the list endpoint lists every credential type, with config only for the included ones. A single GET lists them all without config. So `include_credential=webauthn` alone should still show a TOTP credential's presence. The webauthn config is still needed, because its stub entry only counts with registered keys (w4/020).
- **First, check the premise** with an identity that has TOTP enrolled. No dev-5 identity had one, so the presence of an unrequested `totp` entry was not observed directly.
- **Fix:** drop `include_credential=totp` from both reads in `lego/backend/internal/workspaces/kratos.go`, and keep the presence check.
- **Test:**
  - the fake Kratos in `kratos_test.go` lists a TOTP credential without config and is never asked for it;
  - `MFAEnabled` stays true;
  - a live check on a stack where an identity has TOTP enrolled.
- Found by w5/116's efficiency review (2026-10-07).
