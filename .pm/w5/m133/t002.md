## Objective

Every other service lookup on the Blueprint path resolves inside the deploy's workspace by manifest name, as t001's does, and reuses the request's snapshot where no write has happened yet.

## Context

The w5/132 efficiency review found `GetApp` also called by:

- `lookupSlug` (`deploy.go`), once per `fromService` host target;
- `previewBlueprintHosts`, once per service with domains, in both validate and the apply preflight;
- `validateWorkspaceReferences` (`blueprint_ownership.go`).

## Steps

1. For each call site, decide whether a displayed-name or cross-workspace match is ever intended. A reference to another service in the same stack is not.
2. Resolve through the snapshot where the read happens before the request's first write. After a write, list for yourself.
3. Tests: a `fromService` reference and a host preview each resolve the deploy's workspace's service, not a same-named one elsewhere or a renamed one.

## Files

- `lego/backend/internal/apps/deploy.go`, `blueprint.go`, `blueprint_ownership.go`, and tests.
