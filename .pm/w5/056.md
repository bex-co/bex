# 056 — Blueprint-created Postgres and Key Value record no product-activity event

Why: the creation-surface panel (w5/m97) will show zero Blueprint-created datastores forever, which reads as a finding ("nobody provisions Postgres from a manifest") rather than the collection gap it actually is.

- **What is missing.** `RecordDatabaseEffect` / `RecordKeyValueEffect` — the helpers that call `ObserveProductActivity` (`lego/backend/internal/core/audit.go:538,653`) — are invoked only from the interactive services (`internal/postgres/service.go:657`, `internal/keyvalue/service.go:492`). The Blueprint apply path creates the CRs directly in `internal/apps/deploy.go` (`applyDatabase`, `applyKeyValue`) and never calls them, so no creation fact is recorded on any surface.
- **Pre-existing, not introduced by m97.** The gap dates from the product-analytics v1 work (`a99e13750`); m97 only makes it legible, because the surface panel now invites the reader to compare slices. Services are unaffected — the Blueprint path reaches `ObserveProductActivity` through the shared `materializeNewApp` tail.
- **Do:** call the existing effect helpers on the create branches of `applyDatabase`/`applyKeyValue` so Blueprint datastore creations land like every other creation, then drop the "known gap" sentences from the `Creations by surface` panel description and the runbook's surface definition.
- **Size it deliberately.** This is not purely additive: new creation events will appear in the existing creation counts, feature-adoption table and activation funnel, so the change needs its own before/after note rather than riding m97. If it grows past an hour, promote it.
- **Out of scope:** any other missing effect hook; this note is scoped to the two datastore create branches.

Filed from the w5/m97 review, 2026-09-11.
