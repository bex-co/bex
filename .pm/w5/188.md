# 188 — Agent delivery hardening: unique session branches, verified head SHA, protection re-check before a takeover fast-forward

Why: three defense-in-depth gaps in agent-owned delivery that are not exploitable across a tenant or role today, but each widens what one session's sandbox can affect.

- **Source:** security review round 24 (w5/m371, ADR107), agent-plane hardening notes H-2, H-4, H-5.
- **Branches:** create accepts any `bex-agent/*` branch and `spawn_session` passes the branch through (`agentsessions/spawn.go`), so a child can be spawned onto another live session's branch, push to it and re-sync its PR. Refuse a branch another non-archived session holds on the same repo, or limit a child to its parent's branch or `bex-agent/<child-id>`.
- **Head SHA:** the sandbox's self-reported `RemoteHead` becomes `session.HeadSHA` (`agentsessions/completion.go`) and drives CI-failure steering; confirm it against the branch on GitHub before recording it.
- **Takeover:** branch protection is checked when a `/bex` takeover starts (`pr_takeover.go`) but not before each fast-forward (`agentsession/pullrequest.go`); re-check it.
- **Size:** about 1h30m across the three, so promote to a milestone if worked together.
