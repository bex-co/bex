## Objective

Make credential-cleanup and other turn failures transition through one guarded failure path: persist a readable failed status, keep the minimal status/stream service observable until the Completer acknowledges it, and never repeat the same failing cleanup as an uncaught top-level error.

## Context

- `main.ts` catches the original turn failure and calls `markTurnFailed`, then invokes `scrubPersistedState()` again outside a protective boundary.
- For the reported session the second scrub repeats `persisted credential scan exceeded byte limit`, exits Node with code 1, and defeats the comment promising the driver will stay alive for the Completer.
- Security still requires fail-closed delivery and prompt in-memory credential forgetting even when persisted cleanup cannot complete.

## Steps

1. Give the turn one cleanup verdict and one status transition; remove duplicate uncoordinated scrub calls across `session.ts`, `main.ts`, and `server.ts`.
2. Persist a bounded, non-secret failure code/message before entering the observable failed state.
3. Put in-memory credential revocation/forgetting in `finally`, and prevent delivery/push on any non-clean scrub verdict.
4. Keep only the minimal driver endpoints required for replay/status until normal control-plane teardown; if even that cannot start, exit with a machine-classifiable terminal reason.

## Acceptance criteria

- [ ] A forced scrub failure writes one `failed` status with a safe reason and does not produce an unhandled rejection/exception from a second scrub.
- [ ] In-memory credentials are forgotten in every success/failure/cancel path, and unsafe output is never delivered.
- [ ] The Completer can read the failed status before sandbox teardown and advances the database row exactly once.
- [ ] ACP spawn/exit and cleanup exceptions share the same terminal contract without masking the original cause.

## Out of scope

- Treating a failed scrub as successful.
- Keeping a failed sandbox alive beyond the bounded Completer acknowledgement window.
