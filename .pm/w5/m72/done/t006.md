## Objective

Add a belt-and-suspenders terminal signal at the gateway/control-plane boundary so a failed or terminated sandbox Pod cannot remain a live agent session even if OpenSandbox status projection regresses or lags.

## Context

- The gateway has Kubernetes Pod access; bex-api deliberately does not have `pods/exec`.
- `KubePodIPResolver` currently accepts any non-deleting Pod with a PodIP, including `Failed` Pods.
- `sandboxsse` logs raw exec-upgrade failures, `sandbox/exec.go` maps them to generic unavailable, and the Completer retries every tick because only `core.ErrNotFound` is terminal.
- Two bex-api replicas run the Completer, multiplying the retry log flood; the transition must remain idempotent under concurrent observers.

## Steps

1. Inspect Pod phase and container termination before attach or exec; return a stable internal terminal/gone error without exposing Kubernetes internals to the browser.
2. Carry that coded result through sandbox SSE/client to `core.ErrNotFound` or a dedicated terminal error understood by `ReadSessionStatus` and the Completer.
3. Make terminal conversation attach replay durable history and finish without dialing a dead driver.
4. Make the database transition compare-and-set/idempotent so concurrent Completers record one terminal outcome and stop polling.
5. Add bounded retry/staleness metrics for ambiguous transient errors, with labels that cannot contain tenant/session ids.

## Acceptance criteria

- [ ] A Failed/Succeeded/terminated container is never treated as a live attach/exec target solely because it retains a PodIP.
- [ ] Durable transcript replay for a terminal session ends cleanly without a network dial to the driver.
- [ ] A stale-Pending BatchSandbox plus Failed Pod advances one active session to a named terminal failure within a bounded interval.
- [ ] Repeated `container not found` exec attempts stop after convergence, including with two Completer replicas.
- [ ] Genuine startup/transient failures retain bounded retry behavior and are not prematurely mislabeled terminal.

## Out of scope

- Granting bex-api direct Pod or `pods/exec` permissions.
- A broad distributed scheduler/leader-election redesign unrelated to idempotent completion.
