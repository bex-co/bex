## Objective

Make every platform rollout converge the existing gateway role to the grant surface compiled into that release after bex-api migrations finish, without coupling routine grants to password rotation, and fail gateway readiness with an actionable message when a required privilege is absent.

## Context

- `dbrole.sql` is single-sourced for the provisioning script and CI, but `.github/workflows/deploy.yml` never applies it.
- The existing integration test creates a fresh role and applies the newest grants before exercising it, so it cannot detect a deployed role left behind by a later migration.
- The gateway's attach `Store` interface now includes `AgentSessionTurns`, but the completeness reflection covers only `nativessh.Store` and `sshgateway.NonceStore`.

## Steps

1. Split role creation/password rotation from an idempotent grants-only operation in `scripts/ssh-gateway-db-role.sh`.
2. Add the least-privilege grant reconciliation at the correct post-migration/pre-readiness point in the production deploy workflow.
3. Add a gateway privilege preflight covering every table/method the running process needs; expose only table/operation names, never connection data.
4. Extend the scoped-role integration proof to call `AgentSessionTurns` and cover the complete `agentattach.Store` surface while retaining negative sensitive-table assertions.
5. Add script/workflow tests proving a grant-only rerun preserves the credential Secret and is idempotent.

## Files

- `scripts/ssh-gateway-db-role.sh`

- `lego/backend/cmd/ssh-gateway/main.go`

## Acceptance criteria

- [ ] A deploy after a schema migration applies the release's grants before conversation traffic is considered ready.
- [ ] Grants-only mode neither changes the role password nor rewrites/restarts the gateway Secret/Deployment.
- [ ] Removing the turn-table grant in a test makes preflight/readiness fail with an actionable privilege error.
- [ ] The integration test invokes every attach-store method, including `AgentSessionTurns`, under the scoped role and still proves unrelated sensitive tables are inaccessible.

## Out of scope

- Broadening the gateway role for speculative future methods.
- Moving schema migration ownership from bex-api to the gateway.
