## Objective

Restore conversation replay immediately by applying the already-declared `SELECT ON agent_session_turns` grant to the production `bex_ssh_gateway` role without rotating its password or rewriting its Kubernetes Secret, then prove the scoped role can execute the exact attach-store read that failed.

## Context

- Production gateway log for `ags-da1prbt040bc73aj5230`: `permission denied for table agent_session_turns (SQLSTATE 42501)`.
- Migration 0081 created `agent_session_turns`; `lego/backend/internal/sshgateway/dbrole/dbrole.sql` contains the grant, but production grants are applied only by the out-of-band role script.
- `scripts/ssh-gateway-db-role.sh` currently rotates the password on every normal run, so the incident repair must use an explicit grant-only path or exact SQL rather than creating avoidable credential/rollout risk.

## Steps

1. Capture `has_table_privilege('bex_ssh_gateway', 'agent_session_turns', 'SELECT')` before the change and confirm the failure under the scoped role.
2. Apply only the current least-privilege grant delta transactionally; do not print a URI, password, Secret, or kubeconfig.
3. Re-run the scoped `AgentSessionTurns` read and an authenticated conversation replay for a safe known session.
4. Record timestamped, redacted recovery evidence and confirm the gateway no longer emits SQLSTATE `42501` for new stream attempts.
