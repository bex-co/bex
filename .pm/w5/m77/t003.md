## Objective

Remove PostgreSQL transaction latency from the browser-facing part loop. Forward each accepted part immediately, persist bounded batches through the existing batch store API, and preserve transcript ordering, idempotency, quotas, terminal flush, and ADR051 recovery.

## Context

- `spliceDriverStream` and `forwardAgentTurn` await one `AppendAgentSessionTranscript` call before forwarding every part.
- Each append opens a transaction, takes a per-session advisory lock, queries `max(seq)`, and inserts one row even though the store API already accepts a slice.
- The Completer's full bounded driver-log harvest is the universal suffix-recovery backstop.
- Batching must be bounded by both part count and elapsed time so sparse output is durable promptly and dense token output amortizes database work.

## Steps

1. Introduce a small bounded transcript batcher owned by one attach/turn stream.
2. Forward validated in-quota payloads before awaiting persistence; enqueue their exact turn-local indexes and bytes.
3. Flush on count/time thresholds, `[DONE]`, EOF, cancellation, and handler return; define and test the error policy without corrupting client order.
4. Keep store allocation under its existing advisory lock, but persist each batch in one transaction and avoid redundant cumulative-byte/max-index queries where safe.
5. Preserve reconnect prefix suppression and concurrent gateway-replica idempotency.

## Acceptance criteria

- [ ] Browser forwarding no longer waits for a PostgreSQL append per part.
- [ ] A dense N-part stream performs bounded batch transactions rather than N transactions; the deterministic fixture proves the reduction.
- [ ] Sparse output flushes within the configured bound and terminal paths flush all queued parts.
- [ ] Reconnect, concurrent tee, quota, disconnect, store-failure, and Completer-harvest tests preserve exact order and no duplicate durable parts.
- [ ] Memory is bounded and no tenant-controlled label/cardinality is added.

## Out of scope

- Replacing PostgreSQL transcript authority.
- Removing live tee durability in favor of completion-only harvest.
