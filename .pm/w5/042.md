# Mobile composer cannot request a draft PR (w5/m65 follow-on)

Surfaced by the `w5/m65` `/simplify` review (2026-08-09).

Since m65, draft-PR delivery is opt-in (`agentConfig.openPr`, default off). The **dashboard** composer got a Configuration toggle for it; the **mobile** composer (`mobile/src/features/agent-sessions/composer/session-composer-screen.tsx`) did not, so every mobile-created session is branch-only and mobile's own "Pull request" card is unreachable for sessions it creates.

This is currently **deliberate**, not a bug: ADR048 makes mobile supervision-first and keeps configuration on the desktop, and the card is `prUrl`-gated so it degrades cleanly (no dead UI). Filed so the decision is recorded rather than implicit.

Re-open if either becomes true:

- users actually create sessions from the phone often enough that branch-only delivery is a surprise, or
- the PR opt-in stops being "configuration" (e.g. it becomes the common case again).

Fix if re-opened is small: one Switch in the composer + `openPr` on the mobile `MobileCreateAgentSession` mutation + en/zh strings (~30m, an inbox note, not a milestone).
