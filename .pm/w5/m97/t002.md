## Objective

Map facts the request already carries onto the closed set, with precedence rules that are explicit and tested; never infer from workspace, plan, or actor type.

## Context

- Transport classification: `rest | graphql | mcp | auth | internal` (`api/httpmetrics.go`).
- Identity: `core.IdentityFrom(ctx)` → `Method ∈ {session, oauth2, system}` (`api/auth.go:525,640`, `core/audit.go:345`).
- Upstream CLI User-Agent prefix `render-cli/` (`pkg/cfg/cfg.go:75`); the bex launcher does not alter it (m94 adds only a header).
- Blueprint: creates issued by the Blueprint apply/sync engine (`internal/blueprints`) flow through the same App/Postgres/Key Value create tails; the sync engine runs both from HTTP (manual sync) and from the webhook auto-sync worker.

## Steps

1. Rules, in precedence order: (1) Blueprint apply context flag → `blueprint`; (2) `mcp` transport → `mcp`; (3) `rest` + `User-Agent` starts with `render-cli/` → `cli`; (4) `graphql` + `Method == "session"` → `dashboard`; (5) any other `rest`/`graphql` product request → `api`; (6) otherwise `unknown`.
2. Set the Blueprint flag once in the sync engine's apply entry point so every nested create inherits it.
3. Table-driven unit tests: one case per rule, plus precedence collisions (Blueprint over MCP; MCP over UA) and a bare context → `unknown`.

- `lego/backend/internal/blueprints/` (apply flag)
