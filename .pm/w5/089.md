# Generate Blueprint exports a service's registry credential

Why: a service bound to a private registry credential exports without its `registryCredential`, so the service a sync creates from the file falls back to the newest credential for the image host, or to none, and a private pull can fail.

- **Today:** `generateServiceEntry` (`lego/backend/internal/apps/blueprint_generate.go`) never emits `registryCredential` or `image.creds`, though the parse resolves both by name (`fromRegistryCreds: {name}`, w8/m19 t005).
- **Fix:** resolve `spec.registryCredentialId` to the credential's name through the `RegistryCreds` seam and emit `registryCredential: {fromRegistryCreds: {name}}`; an explicit empty binding (no credential) has no render.yaml spelling, so list it as not exported.
- **Test:** add a bound credential to `TestGenerateBlueprintRoundTripsRealCreates` with a fake credential store; its create probes clear `RegistryCredentialID` today because the test runs without one.
