# Re-enabling autoscaling resumes from the count it last chose, not the service's own

Why: the autoscaler keeps its last decided count in `app.bex.co/autoscale-replicas` and seeds every autoscaled pass from it, but nothing clears it when autoscaling is turned off. Turning autoscaling back on later starts from that stale count. A service set to 1 replica whose autoscaler last chose 4 jumps to 4, and the scale-down window then holds it there for about five minutes.

- **Where:**
  - written by `applyAutoscaling` (`lego/operator/internal/controller/autoscale.go`);
  - read by `desiredReplicas` (`app_controller.go`) to seed `current`;
  - nothing else reads it, in the operator, bex-api or the dashboard.
- **Decide first:** suspend takes the same non-autoscaling path in `desiredReplicas`. Today a resumed service restarts at its last autoscaled count, which is probably right for resume. Clear the annotation only when autoscaling itself is turned off, not on suspend.
- **Fix:** when `desiredReplicas` runs for an App whose autoscaling is disabled or unset, clear `app.bex.co/autoscale-replicas` along with the scale-down window (w5/120's `dropScaleDownWindow` path), through `patchAppMeta`.
- **Test:**
  - an App whose autoscaler chose 4, with autoscaling turned off and then back on, resumes from its configured count;
  - a suspended and resumed App keeps 4.
- Found by w5/120's reuse review (2026-10-07).
