## Objective

Protect the pinned ops workspace from its own product lifecycle: deleting or suspending it must be refused loudly (it would lock every operator out of Grafana at once), and invite-time seat/plan gating must exempt it (a seat cap must never silently block onboarding an operator) — ADR088 §4.

## Context

- `BEX_OPS_WORKSPACE` config lands in t004; guards read the same value. Unset ⇒ no behavioral change anywhere.
- Workspace deletion/teardown: `lego/backend/internal/workspaces` service (see ADR086's use of its teardown path); account-deletion's sole-member `delete` disposition must also refuse if it would tear down the ops workspace.
- Invite seat/plan guards: the accept-time checks referenced in ADR024 (`AcceptInviteByToken` / `AcceptInvitesForEmail` shared redemption core).
- Errors follow the repo's coded-error convention (typed causes, stable codes), not prose matching.

## Steps

1. Add the refusal in the workspace delete/suspend verbs (typed error, stable code) when the target is the pinned ops workspace.
2. Exempt the ops workspace in the invite redemption seat/plan check.
3. Tests: delete/suspend refused with the coded error; invite into the ops workspace succeeds past a seat cap that blocks an ordinary workspace; unset env ⇒ all guards inert.

## Files

- `lego/backend/internal/workspaces/` (delete/suspend verbs)
- invite redemption core (locate via `AcceptInviteByToken`)
- adjacent `_test.go` files

## Acceptance criteria

- [ ] Delete/suspend of the ops workspace returns a stable coded refusal (tested)
- [ ] Seat/plan gate exemption covered by a test that fails for an ordinary workspace
- [ ] `BEX_OPS_WORKSPACE` unset ⇒ zero behavior change (tested)

## Out of scope

- Any UI for the guards (a coded API error suffices; operators are the only audience)
