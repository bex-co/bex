## Objective

Add a server-only bex-api verb answering "what is subject S's role in the pinned ops workspace" — one OpenFGA read, guarded by a static bearer, reachable only in-cluster — so the consent acceptor can gate the obs client without the dashboard talking to OpenFGA directly (ADR087 §4).

## Context

- Config: `BEX_OPS_WORKSPACE` (the designated `tea-*` id) + `BEX_OPS_ROLE_TOKEN` (static bearer) in `lego/backend/cmd/api/config.go`; both unset ⇒ the route answers 404/503 (feature absent), byte-identical prior behavior.
- Role source: OpenFGA tuples per ADR024 (`user:<kratos-id> <role> workspace:tea-<id>`); reuse the existing OpenFGA client wiring in `internal/` (see `core.Base.Authorize` usage) — do not invent a second authz path.
- Response: the caller's highest role among `admin`/`developer`/`viewer`, or non-member; `contributor`/`billing` report as non-qualifying (the deny decision itself lives in the consent acceptor, but the verb should expose the raw role so policy stays in one place — return the role, let t005 map it).
- Auth: constant-time compare of the static bearer; this endpoint must NOT ride `api.IdentityFrom`/session auth (it is machine-to-machine from dashboard SSR).
- Not a tenant-facing surface: no REST/GraphQL/MCP parity obligations; keep it out of the public OpenAPI/GraphQL schemas.

## Steps

1. Add config fields + env parsing; document in `lego/backend/CLAUDE.md` env inventory.
2. Add the internal route/handler (path under an internal prefix, e.g. alongside existing non-public routes) with the bearer guard and the OpenFGA role read.
3. Tests in the `internal/api` suite: no token configured ⇒ absent; wrong token ⇒ 401; member roles map correctly; non-member ⇒ explicit non-member answer (real-Postgres/OpenFGA CI path where the existing suite uses them).
