## Objective

Register Grafana as a first-party Hydra OIDC client the same way `bex-mobile` is provisioned: idempotent upsert, confidential, `skip_consent`, exact redirect — no dynamic client registration (ADR087 §3).

## Context

- `scripts/auth-bootstrap-client.sh` already upserts `bex-mobile` idempotently against Hydra admin; extend it, don't fork it.
- Client shape: `authorization_code` + `refresh_token`, response type `code`, scopes `openid profile email`, **no access-token audience** (identity-only — a Grafana token must carry zero bex-api authority), `token_endpoint_auth_method: client_secret_basic` (confidential; secret from env), redirect exactly `https://obs.bex.co/login/generic_oauth`, `skip_consent: true`.
- Secret handling per repo rules: name in `.env.example` (no value), pushed via `scripts/gh-secrets.sh`; prod delivery as SealedSecret (ADR016).
- The client id joins `OAUTH_OPS_CLIENTS` (t005 consumes it); it does NOT need `OAUTH_PLATFORM_CLIENTS`/`BEX_OAUTH_PLATFORM_CLIENTS` (no API audience/scope vocabulary involved) — leave that registry untouched.

## Steps

1. Extend `scripts/auth-bootstrap-client.sh` with the obs client upsert (fixed client id, env-supplied secret), matching the existing idempotency behavior.
2. Add the secret env name to `.env.example`; document the variable in the relevant CLAUDE.md inventory.
3. Run the script against the local/dev Hydra to verify idempotent create + re-run.
