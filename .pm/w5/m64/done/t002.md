## Objective

Move every affordance w3/m45 t004 built into the bespoke `<aside>` onto the t001 sidebar group, so t003 can delete the old rail without losing behavior. Nothing here is new product surface — it is a re-hosting of shipped behavior on the shared primitives.

## Context

- Source of truth for what must survive: `dashboard/src/features/agent-sessions/components/session-sidebar.tsx` (and its test `.../__tests__/session-sidebar.test.tsx`). Inventory as shipped:
  - **New session** entry + the bare `O` keyboard shortcut, guarded by `isEditableTarget` so it never fires while typing, and deliberately bare so it cannot collide with ⌘K search or ⌘B sidebar toggle. It navigates to `/agents` then calls `requestAgentComposerFocus()` (`lib/composer-focus.ts`).
  - **Search** — a toggled `Input` filtering via `fuzzyMatch` (`lib/mention.ts`) over `sessionTitle(s)` **and** `s.repo`.
  - **More** — the view-all target, `/agents?view=list` (validated in `agents.tsx`'s `validateSearch`).
  - **Status phrases** — `agentSessionStatusPhraseKey` (`lib/mapper.ts`), plus the `GitPullRequest` icon and the GitHub PR link.
  - **Active highlight** via the `activeId` prop — now derived from the route param instead of a prop.
- Devin's equivalents, for shape: section header carries Search / Filter / More as 24px icon buttons; row hover reveals per-item actions (`data-slot="sidebar-menu-action" data-show-on="hover"`); the More menu holds `New folder` / `View all sessions` / `More actions`. Evidence `.playwright-mcp/devin-recent-menu.png`, `devin-home.png`.
- Our `ui/sidebar.tsx` already provides `SidebarGroupAction` and `SidebarMenuAction` — use those for the header icon buttons and any row action rather than hand-rolled absolutely-positioned buttons.
- **Do not invent** Devin's `New folder` or `Filter`: session folders and filtering are not shipped bex capabilities. Port only what exists; note the gap in t005 if it seems worth a future note.

## Steps

1. Rebuild the section header (label + Search toggle + More) on `SidebarGroupLabel` / `SidebarGroupAction`.
2. Move the `O` shortcut listener to the new component — verify only **one** listener is registered once t003 removes the old rail (two live listeners would double-navigate; a test should assert a single navigation per keypress).
3. Reuse `fuzzyMatch`, `sessionTitle`, `agentSessionStatusPhraseKey` as-is — no reimplementation.
4. Derive the active row from `useParams({ strict: false }).agentSessionId` instead of the `activeId` prop.
5. Keep the loading state (`Skeleton`) and the degraded/empty states the old rail had — a 503/unconfigured backend must degrade the list without breaking the nav above it.
6. Reuse the existing i18n keys from `features/agent-sessions/locales/{en,zh}.ts` (e.g. `agentSessions.sidebarLabel`); add keys to **both** locales if any new string is genuinely needed.

## Acceptance criteria

- [ ] Search filters the sidebar list by title **and** repo, as before.
- [ ] `O` opens the composer from a non-editable focus and does nothing while typing in an input/textarea/contenteditable; exactly one navigation fires per press.
- [ ] More reaches `/agents?view=list` and that page still renders the standalone table.
- [ ] Rows show the human status phrase and the PR link, and the PR link opens GitHub without also activating the row's navigation.
- [ ] The row for the open session is marked active on `/agents/<id>`.
- [ ] Loading and backend-unavailable states render without breaking the nav groups above.
- [ ] Both locales carry every key used.
