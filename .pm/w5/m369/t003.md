## Objective

Every accepted Suspend followed by a Resume records exactly one `service_suspended` and one `service_resumed`, however short the suspension, so push and webhooks deliver both (the rule w4/527 set).

## Context

- w4/604 (now `w4/done/604.md`): probes, root cause and the recommended mechanism.
- The pair comes only from `observedStateFacts` (`lego/backend/internal/store/event_facts.go`, the w4/527 quick-undo branch, needing a checkpoint with `suspended=true`), and the flag is observed only by a pass (`observedServiceStateFor`, `reconciler.go`).
- `setSuspended` (`lego/backend/internal/apps/service.go`) never calls `s.Kick()`.
- Delivery reads only the observed pair: push (`notifications/push_worker.go`), webhooks (`webhooks/service.go`).

## Steps

1. When the Suspend's row write commits, record the suspension on the event checkpoint as well (`suspended=true`, the write time), only when the checkpoint is not already suspended.
2. Mind w4/562's sleeping-Free branch (`!previousSuspended && obs.Suspended` on a Hibernated checkpoint): leave a Hibernated checkpoint to the pass, or emit the fact from the same write.
3. Kick the reconciler from `setSuspended` too, so a long suspension's phase edge is prompt (a kick alone is not enough: a running pass coalesces it).
