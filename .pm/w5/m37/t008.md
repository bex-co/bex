## Objective

Display which stored registry credential an image-backed service is bound to on the read-only service detail/overview — without it, a credential attached via API (or via t003's settings editor) is invisible until the user opens settings.

## Context

- Backend already resolves `registryCredentialId` on the GraphQL `Service` type (`lego/backend/internal/apps/graphql.go:340-344`) and builds an `{id, name}` summary for the REST render view (`apps/render.go:352-358`) — the human-readable name is available.
- The `Server($id)` query powering the detail page (`dashboard/src/features/services/api/server.graphql`) enumerates ~40 fields but not `registryCredentialId`; no detail/overview component references it (verified by the round-17 dashboard mine).
- Filed as an add-task because m37/t003 scopes only the settings editor, not the read-only display.

## Steps

1. Add the field to the `Server` query (regenerate `dashboard/src/graphql/definitions.ts`).
2. Render the credential (name, linking to the settings credential panel) in the overview's image-source section, only for image-backed services with a binding.

## Files

- `dashboard/src/features/services/api/server.graphql`, the service overview/detail component, `dashboard/src/graphql/definitions.ts`, locale files (`en.ts`/`zh.ts`)

## Acceptance criteria

- [ ] A bound service shows the credential name on its detail page; unbound and repo-backed services show nothing new.

## Out of scope

- Attach/detach controls (t003); create-flow selector (t002).
