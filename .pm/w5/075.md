# Postgres Insights redaction misses password literals it doesn't parse

Why: w4/m167 redacts the value after a `PASSWORD` keyword, but four forms still show the secret in Insights query text: `PASSWORD /*c*/ 'x'`, `PASSWORD U&'x'`, a quoted conninfo value `password=''x''` (only the `''` is redacted), and a URI conninfo `postgresql://u:x@h`.

Source: Last-24h code review, 2026-10-05 (user handed all fixes to w5). Each case reproduced on a scratch copy of the function from `4acf2a96c` (w4/m167). Readers already hold `can_view_sensitive`, so the exposure is display-only.

## Fix

1. In `lego/backend/internal/postgres/insights.go` (`secretKeyword` at `:55-59`, the conninfo branch, `positionalParam` at `:65-66`), stop parsing password syntax. Instead redact every string literal, skipping comments:
   - `'…'` with `''` escapes;
   - `E'…'`;
   - `U&'…'`;
   - dollar-quoted `$tag$…$tag$`.

   Top-queries DML is already normalized to `$n`, so this costs nothing there, and it covers every utility statement.
2. Keep b0082ed80's (w4/185) separate `pg_settings` read. Nit: pass the skip-session-settings flag from its two callers instead of comparing `sql == sqlParameterOverrides`.
3. Table test: the four leak cases plus the original w4/m167 cases; SQL without literals is unchanged.

Done: no string literal survives into Insights query text for those cases; existing Insights tests green.
