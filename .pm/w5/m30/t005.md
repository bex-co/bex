## Objective

Add an optional Dockerfile-path field to the service-create wizard's Docker-runtime branch and send it through the existing create-service GraphQL flow.

## Context

- `dashboard/src/routes/services.new.tsx` already renders `startCommand` for repo-backed services and exposes `runtime: "docker"`.
- The current `CreateService` document and `CreateServiceInput` do not thread `dockerfilePath`, although bex-api's create mutation accepts it.
- The field must reset or be omitted when the user changes away from the Docker runtime.

## Steps

1. Add localized field copy and render the input only in the Docker-runtime branch.
2. Thread the optional value through `CreateServiceInput`, `useCreateService`, and `services.graphql`.
3. Regenerate definitions and test runtime switching plus submitted variables.

## Files

- `dashboard/src/routes/services.new.tsx`
- `dashboard/src/features/services/hooks/use-create-service.ts`
- `dashboard/src/features/services/hooks/__tests__/use-create-service.test.ts`
- `dashboard/src/features/services/api/services.graphql`
- `dashboard/src/features/services/locales/{en,zh}.ts`
- `dashboard/src/graphql/definitions.ts`

## Acceptance criteria

- [ ] Docker creation sends a trimmed non-empty `dockerfilePath` and omits an empty value.
- [ ] Switching to a non-Docker runtime hides the field and cannot submit a stale Dockerfile path.
- [ ] The mock cluster builds a service from a non-default Dockerfile selected in the wizard.

## Out of scope

- Repository browsing/autocomplete and Dockerfile existence checks before submission.
