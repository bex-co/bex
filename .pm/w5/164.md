# Failed actions in dialogs show translated messages, not raw "Failed to fetch"

Why: on a network error or 5xx, ten dialog flows show the browser's raw English error text (e.g. "Failed to fetch") instead of the app's own copy, even in the Chinese UI, because the shared error helper returns any Error's message.

- **Where:** `graphQLErrorMessage` (`dashboard/src/common/lib/graphql-error.ts:4-8`) returns `err.message` for any `Error`, contradicting its own comment at `:16-17`. Sites using `graphQLErrorMessage(err) ?? t(…)`:
  - `use-update-database-version.ts:24`, `account-deletion-card.tsx:162`, `self-host-exit.tsx:93`
  - `use-change-workspace-plan.ts:41`, `use-workspace-creation-billing.ts:143/186/215`, `use-create-workspace.ts:68`, `use-rename-workspace.ts:36`, `use-delete-workspace.ts:39`
  - via `refusalReason`: `use-invite-member.ts:84`, `use-custom-domains.ts:97`
- **Fix:** switch these sites to the existing `mutationErrorMessage` (`graphql-error.ts:146`), and make `refusalReason` return `""` for anything that isn't a GraphQL error so callers fall back to their translated copy. A server refusal (a GraphQL error) still shows the server's message.
- **Test:** extend `mutation-error-toast-invariant.test.ts` to cover these sites: a network failure shows the translated fallback in en and zh, and a GraphQL refusal still shows its message. `yarn typecheck && yarn lint && yarn test` green.
