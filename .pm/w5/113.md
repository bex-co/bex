# Without a control-plane database the audit log is unmounted, not the documented 503

Why: `Deps.Audit`'s comment says a nil audit service makes the read verb answer 503 `AUDIT_LOG_UNAVAILABLE`, but a nil feature is never mounted. The dashboard's "audit log unavailable" state can therefore never show, and on a deployment without the database its audit query fails GraphQL validation.

- **What happens now:**
  - `lego/backend/internal/api/server.go` skips a nil feature (`appendFeature`), so REST answers 404 and GraphQL has no `auditLogs` field.
  - `cmd/api/main.go` builds `audit.Service` only alongside the control-plane store, so production never sends the code.
- **Fix, one of two:**
  - mount `audit.Service{Base: base}` with no store when the database is not configured. This follows the env-vars and deploy-history precedent of a refusal that is omitted, not faked, and makes the comment and the dashboard state true.
  - or correct the comment and drop the dashboard state.
- **Test:** a server without the database answers `AUDIT_LOG_UNAVAILABLE` on REST and GraphQL. `api/refusal_codes_test.go` wires a store-less service by hand today.
- Found by w5/m128's cross-surface test (2026-10-06).
