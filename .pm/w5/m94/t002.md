## Objective

Store the launcher release on every ingested telemetry row and make it queryable by the restricted CLI analytics reader, so the board can slice by bex release independent of the upstream pin.

## Context

- Ingestion: `lego/backend/internal/clitelemetry/rest.go` (`RegisterREST`, `core.DecodeJSON` into the Render-shaped input), `clitelemetry/service.go` (`Record`, `truncate(..., maxTelemetryFieldBytes)`), `store/clitelemetry.go` (`InsertCLITelemetryEvent`).
- Schema: `store/migrations/0113_cli_telemetry_events.up.sql`. Migrations `0114`/`0115` are claimed by the still-uncommitted product-analytics work in the working tree — take the **next free number at implementation time**, never reuse.
- Reader: `scripts/cli-analytics.sql` (`cli_analytics.events` view, `upstream_version` column at line 39; GRANTs on the view only) and `scripts/test_cli_analytics.py` (fixtures + column allowlist).
- Prometheus: `api/httpmetrics.go` `ObserveTelemetry(command, completionKind, cliVersion, outputFormat)` — do **not** add `bex_version` as a label; the view is the version axis (cardinality discipline from m93).
- Account deletion: `cli_telemetry_events` rows are hard-deleted (ADR086 table) — unchanged by an extra column.

## Steps

1. Migration: `ALTER TABLE cli_telemetry_events ADD COLUMN bex_version text NOT NULL DEFAULT ''` (+ down).
2. `rest.go`: read `r.Header.Get("X-Bex-CLI-Version")` into a new `EventInput.BexVersion`; `service.go`: sanitize to a version-like charset (`[0-9A-Za-z.+-]`, else `''`) and truncate; `store`: insert the column.
3. `scripts/cli-analytics.sql`: expose `COALESCE(NULLIF(bex_version,''),'unknown') AS bex_version`; update the Python suite's fixtures, allowlist, and a query asserting the value round-trips.
4. Real-Postgres tests: header present → stored; absent → `''`; oversized/garbage → sanitized; full-chain migration up/down.
