# Email-only identity reads still make Kratos load every credential

Why: `ownerEmails` (every REST service, Postgres, Key Value and project list's owner metadata) and `memberWithEmail` read only an email from `IdentityReader.LookupMany`, but its webauthn include makes Kratos' list endpoint load the batch's credentials: one extra query inside its transaction, and webauthn configs on the wire, on hot paths that never read MFA.

- **Where:** `lego/backend/internal/workspaces/kratos.go` `LookupMany` always sends `include_credential=webauthn` (w5/127); without an include, Kratos v26.2.0's list endpoint skips credentials entirely. Only `ListMembers` (`workspaces/service.go`) and `members/service.go`'s member views read `MFAEnabled`.
- **Fix:** give email-only callers a batch read without the include — a separate `IdentityReader` method (e.g. `LookupEmails`) or an option on `LookupMany` — and keep the MFA callers on the include.
- **Test:** an owner list's Kratos request carries no `include_credential`; a member list's still carries only webauthn and keeps MFA.
- Found by w5/127's efficiency review (2026-10-07).
