# MCP `create_static_site` defaults omitted `publishPath` to `"public"`, retiring the last non-`DO_NOT_DO` MCP tool divergence

Why: Render's MCP `create_static_site` (`render-oss/render-mcp-server@a18ef3ee` `pkg/service/tools.go:424-427,480-484`) and Render's OpenAPI (`staticSiteDetailsPOST.publishPath`) both make `publishPath` optional and default it to `"public"`, and bex's own REST handler (`lego/backend/internal/apps/rest.go:751-756`) already defaults omitted `publishPath` to `"public"` — yet MCP `create_static_site` (`lego/backend/internal/apps/mcp.go:578`) still marks `publishPath` required and `api/mcp_parity.go:95-98` still excuses the divergence with the stale claim `"no default publish dir"`.

**Source:** `/pm-brainstorm one aspect of render parity in backend for w5` (2026-11-23, round 12 item 5), verified against `render-oss/render-mcp-server@a18ef3ee` (`pkg/service/tools.go:424-427,480-484`), `lego/backend/internal/api/openapi/render-public-api-1.json` (`staticSiteDetailsPOST.publishPath`), and `main@7c27a28992`. **Estimate:** ~45m–1h.

## Evidence

- Upstream `render-oss/render-mcp-server@a18ef3ee` `pkg/service/tools.go:424-427`: `mcp.WithString("publishPath", ..., mcp.DefaultString("public"))` (NOT `mcp.Required()`).
- Pinned OpenAPI `render-public-api-1.json` `staticSiteDetailsPOST.properties.publishPath`: `"description": "Defaults to \"public\""` (not in `required`).
- Bex REST (`lego/backend/internal/apps/rest.go:751-756`) already fills `publishPath = "public"` at the wire boundary when `r.Type == appv1alpha1.TypeStaticSite && strings.TrimSpace(publishPath) == ""` (leaving Blueprint and GraphQL requiring it).
- Bex MCP (`lego/backend/internal/apps/mcp.go:578`) has `PublishPath string` with `json:"publishPath"` (no `omitempty`), causing `tools/list` to list `publishPath` in `required` and `apps/service.go:3850` to reject calls that omit it.
- `lego/backend/internal/api/mcp_parity.go:95-98` excuses `create_static_site` in `mcpAcceptedDivergences` with the outdated reason `"publishPath is genuinely required in bex (no default publish dir)"`. Removing it leaves `list_logs` (`task`/`taskRun`, recorded `.pm/DO_NOT_DO.md` Workflows non-goal) as the sole remaining entry in `mcpAcceptedDivergences`.

## Fix

1. In `lego/backend/internal/apps/mcp.go`:
   - Change `createStaticSiteArgs.PublishPath` tag to `json:"publishPath,omitempty"` and update its description + struct comment to state that omitted/blank `publishPath` defaults to `"public"` (matching Render's MCP and REST).
   - In `createStaticSiteArgs.toCreateRequest()`, default `publishPath` to `"public"` when `strings.TrimSpace(a.PublishPath) == ""` (matching `apps/rest.go:754-756`, keeping Blueprint and GraphQL unchanged).
2. Remove `"create_static_site"` from `mcpAcceptedDivergences` in `lego/backend/internal/api/mcp_parity.go`.
3. Update `TestMCPParityInventory` expected class counts (`lego/backend/internal/api/mcp_parity_test.go`) — `create_static_site` moves from `Divergent` to `Superset` (1 `Divergent` left: `list_logs`), and update any stale test that asserted `create_static_site` rejects omitted `publishPath`.
4. Add a regression test in `lego/backend/internal/apps/` (or `internal/api/`) proving `create_static_site` succeeds through MCP when `publishPath` is omitted and persists/returns `publishPath: "public"`, while an explicit `publishPath: "dist"` is preserved.
5. Update `docs/ADR018-render-parity.md` (and `docs/ADR006-bex-api.md` if it still cites `create_static_site` as divergent) to record the retired divergence.
