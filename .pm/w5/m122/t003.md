## Objective

Classify by source: kubelet API error bodies never enter a tenant pipeline, and Go direct reads treat untimestamped lines as platform lines.

## Context

- Build pods already tail log files from `/var/log/pods` (w6/m123). The kubelet's "logs gone" answers are API bodies, not container output.
- `lego/backend/internal/logs/service.go` already states the rule "no timestamp ⇒ platform line" near `kubeletLogsGonePrefixes`.
- ADR010 describes the logs pipeline.

## Steps

1. Check whether file tailing works for app, Postgres and Key Value pods in the shipper, and what the direct-read path needs.
2. Implement it for the shipper. For direct reads, apply the no-timestamp rule and delete `kubeletLogsGonePrefixes` and the three kubelet regexes.
3. Where file tailing isn't viable, record why and keep the shared fixtures as the drift guard.
