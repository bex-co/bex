## Objective

Complete the registry-credential lifecycle in the dashboard: an Edit affordance on an existing credential (rename, change username, rotate token) via the unconsumed `updateRegistryCredential` mutation, with `registryCredential` providing the detail readback — matching Render's ability to edit/rotate a stored credential.

## Context

- w5/m37 shipped create/attach/clear/delete only; `dashboard/src/features/registry-credentials/api/registry-credentials.graphql` has `RegistryCredentials` (list), `CreateRegistryCredential`, `DeleteRegistryCredential`.
- **The token is write-only**: the `.graphql` file's own header comment records that the server structurally never returns the secret past create — the edit dialog must show the token field empty with "leave blank to keep" semantics, never echo a stored value.
- The credential picker (`dashboard/src/features/services/components/registry-credential-select.tsx`, m37) and any credentials management surface are the natural homes for the Edit entry point — follow where m37 put management affordances.

## Steps

1. Add `UpdateRegistryCredential` + `RegistryCredential` operations; splice types.
2. Build the edit dialog: name/registry/username prefilled from the detail read, token blank with keep-if-empty semantics; wire the mutation and refresh the list/picker.
3. en + zh strings; tests for prefill, keep-token-on-blank, rotate, and server-error surfacing.

## Files

- `dashboard/src/features/registry-credentials/` (api, components, hooks, locales)
- `dashboard/src/features/services/components/registry-credential-select.tsx` (entry point, if the picker hosts management)

## Acceptance criteria

- [ ] An existing credential can be renamed and its token rotated; the change is verified on read (list/detail reflect it) and an attached service keeps working.
- [ ] The stored token is never rendered; blank token on save preserves the existing secret.
- [ ] Dashboard suite passes.
