## Objective

Add Render's Trigger Run interaction to the cron-job runs panel: a button that calls the existing `runCronJob` GraphQL mutation, confirms before firing (a run executes the job's command), and refreshes the history so the new run appears with live status.

## Context

- The runs hook is `dashboard/src/features/services/hooks/use-cron-runs.ts` — today it wires only the list query and `CancelCronJobRunDocument`; the backend `runCronJob` mutation (ADR038, `docs/ADR038-cron-jobs.md` §GraphQL) is unconsumed.
- Render's cron page shows a prominent Trigger Run button; the pinned contract is `docs/render-artifacts/cron-runs.md` — match its placement/affordance, including the at-most-one-active-run semantics (`ForbidConcurrent`): triggering while a run is active should surface the backend's rejection, not pretend success.
- Add the mutation to the services feature's `.graphql` operations and splice generated types per `dashboard/CLAUDE.md` (never full-codegen `definitions.ts`).

## Steps

1. Add the `RunCronJob` operation and extend `use-cron-runs.ts` with a trigger mutation that refetches/updates the runs list on success.
2. Add the Trigger Run button to the runs panel (cron services only), with a lightweight confirm and a disabled/explanatory state while a run is active.
3. Surface the backend's active-run rejection as an inline error, not a toast-and-swallow.
4. en + zh strings; component test for trigger→appears-in-history and the active-run rejection.
