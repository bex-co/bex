## Objective

End-to-end verify the workspace-level Env Groups surface against the mock cluster: create a group, add vars and a secret file, link it to a service, confirm the service's Environment tab reflects the group, then unlink and delete.

## Context

- Local cluster: `bash scripts/mock-cluster.sh` (kubeconfig `infra/local/bex.kubeconfig`); dashboard runs against bex-api's GraphQL.
- Cross-check point: the existing service Environment tab (`routes/services.$serviceId.env.tsx`) env-groups section must show the same group after linking.

## Steps

1. Stand up / reuse the mock cluster and run the dashboard.
2. Create an env group → add ≥1 var + ≥1 secret file → link to a running service.
3. Open that service's Environment tab; confirm the linked group + its vars/files appear.
4. Unlink from the detail page, then delete the group; confirm both reflect immediately.
