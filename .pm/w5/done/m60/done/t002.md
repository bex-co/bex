## Objective

Let a run-history row open its detail via the unconsumed single-run read `cronJobRun(serviceId, runId)` — status, started/finished timing, and duration — so a user can inspect a specific run without correlating it by eye against the events feed.

## Context

- The read returns `CronRun { id status startedAt finishedAt }` (ADR038 §GraphQL); the list already renders rows, so the detail is an expansion/popover on the existing panel, not a new route.
- Render's run history exposes per-run inspection; keep the affordance shape consistent with what `docs/render-artifacts/cron-runs.md` records (and note any divergence for t006 rather than inventing structure).
- Deep-linking run logs: the logs page already supports filters — if a one-line link (run window → pre-filtered logs range) is trivial, include it; if it needs new plumbing, note it as follow-up instead.

## Steps

1. Add the `CronJobRun` operation; extend `use-cron-runs.ts` with a lazy detail fetch.
2. Make history rows expandable (or popover) showing status + timing + duration from the read.
3. en + zh strings; test for expand→detail-rendered and the not-found error path.
