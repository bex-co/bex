## Objective

Expose the per-service notification override in the service Settings Notifications section as Render's dropdown (workspace default / all notifications / failures only / none — per the pinned artifact), wired to the unconsumed `setNotifyOnFail` mutation, with the current effective value read back.

## Context

- The workspace-level page (`dashboard/src/features/notifications/`) calls only `NotificationSettings` + `UpdateNotificationSettings`; the per-service `setNotifyOnFail` has zero consumers. The services feature already carries `notifyOnFail` strings in `types.ts`/locales — find where the value is (or was meant to be) displayed and make it editable rather than adding a parallel control.
- Render's contract is `docs/render-artifacts/notify-on-fail.md` — mirror its option vocabulary and the "default (workspace setting)" indirection; the m52 Settings IA (Render's section order) determines where the Notifications section sits.
- Settings edit idiom: the w5/m50 `EditableFieldRow` disabled-input+pencil pattern with a select variant (the m53 `autoDeployTrigger` select is the precedent).
