## Objective

`newBlueprintActionResolver` also resolves a workspace service that so far exists only in the shared namespace (mid ADR043 D8), so the plan names the object the apply updates. Twins still resolve to the workspace's own copy, and two copies in one namespace are still refused.

## Context

- Since w5/132 the resolver takes the workspace's Apps from the snapshot and keeps only those in the workspace's own namespace. A probe on 018254503 showed a workspace App only in `default` planned as "create", while the apply's `GetApp` found and updated `default/web`.
- `foldWorkspaceApps` prefers the own-namespace copy across namespaces. The w6/m125 refusal (`TestValidateBlueprintCurrentStatePlanRejectsDuplicateServiceName`) covers two copies in the same namespace.
- `TestAnActionPlanReadsAServicesCopyInItsWorkspaceNamespace` (w5/132) pins the twin case.

## Steps

1. Key the resolver across namespaces: prefer the own-namespace copy, and refuse two copies in one namespace.
2. Make t001's apply lookup agree on the same rule. One helper should serve both.
3. Tests:
   - a shared-only service plans as an update or no-op with its resource id;
   - twins and the w6/m125 refusal keep passing.
