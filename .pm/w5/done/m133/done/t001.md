## Objective

`applyCreateWithFields` finds a declared service's existing App the way the plan does. It looks the manifest name (`core.AppPublicName`) up among the deploy's own workspace's Apps, read from the request's `workspaceSnapshot`, then gets that one object fresh to update it. It must not resolve by displayed name or in another workspace, and it must not list the workspace per service.

## Context

- `applyCreateWithFields` (`lego/backend/internal/apps/deploy.go`) calls `s.GetApp(ctx, core.RelCanCreate, req.Name)`. `core.Base.GetApp` (`lego/backend/internal/core/base.go`):
  - lists by app id cluster-wide;
  - then lists by displayed name (`appByDisplayedName`), across every member workspace when the request names none (`global`);
  - checks `IsMember` once per same-named App found elsewhere.
- `DeployStack` already authorizes `RelCanCreate` for the workspace before applying, so the per-service lookup does not need to authorize again. Confirm that this holds on the create and sync paths too.
- The w5/132 snapshot holds the workspace's Apps (`snap.apps`), and `foldWorkspaceApps` keys them by public name with own-namespace twin preference. The plan's resolver filters them to the workspace's namespace.
- Probe tests reproducing both bugs: `/tmp/w5-132-eff/eff_probe2_test.go` (cross-workspace) and `eff_probe4_test.go` (displayed name). Re-create them as real tests if /tmp is gone.

## Steps

1. Give `applyCreateWithFields` the request's snapshot, and resolve `req.Name` against the deploy's workspace's Apps the way the plan's resolver keys them.
2. Get the matched object fresh by key before updating, so the update carries a current resourceVersion.
3. Keep authorization: a deploy with no resolved workspace must still be refused or scoped exactly as today.
4. Tests:
   - a member of two workspaces deploys a stack naming `web` without an ownerId, while `web` exists only in the other workspace. `web` is created in the deploy's workspace, and the other workspace's `web` keeps its spec;
   - a service created as `api` and displayed as "web", beside one created as `web`: the manifest's `web` updates the one created as `web`, the object the plan names;
   - a sync with two existing services and a new one lists the workspace's Apps once before its first write.
