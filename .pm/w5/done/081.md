# workspaces_e2e's OpenBao purge assertions never run in CI

Why: `TestWorkspace…` in `lego/backend/internal/api/workspaces_e2e_test.go:365` only checks that deleting a workspace purges its secrets when `BEX_TEST_OPENBAO_URL` is set. No CI job sets it: backend CI provides `BEX_TEST_OPENBAO_KV_URL` and `BEX_TEST_OPENBAO_KV_TOKEN` (a dev OpenBao with a root token). So that block silently does nothing on every run, and `testenv.Skip` (w5/m112) can't see it, because it is a branch inside a test that otherwise runs.

Source: w5/m112's `/simplify` review, 2026-10-05.

## Fix (~45m)

1. The block builds its store with `secrets.NewOpenBaoStore(url, jwtPath)`, which needs JWT auth that CI's dev OpenBao doesn't have.
2. Add an exported test-only constructor for a token-authenticated store with a fresh KV v2 mount. `batch_openbao_test.go` builds the same thing from the unexported `openBaoStore`.
3. Run the block from `BEX_TEST_OPENBAO_KV_URL` and `BEX_TEST_OPENBAO_KV_TOKEN`, with `testenv.Skip` when they are absent.

Done: in backend CI the workspace-delete e2e seeds a secret and an env group in OpenBao and asserts they are purged; locally `scripts/backend-test-deps.sh` runs it too.

## Outcome (2026-10-06)

Done. `secrets.NewOpenBaoTestStore(ctx, addr, token)` (`lego/backend/internal/secrets/test_store.go`) builds a token-authenticated store on a fresh KV v2 mount and waits for the mount's upgrade; `batch_openbao_test.go` now uses the same constructor. `TestWorkspaceLifecycleE2E` declares OpenBao beside Postgres and OpenFGA (`BEX_TEST_OPENBAO_KV_URL`/`_TOKEN`, `testenv.Skip` when absent, so it is fatal in CI), and the secrets block always runs.

Running it against real dependencies showed the secret assertion was vacuous even with OpenBao present. It read `default/services/worker/env`, but a service's secrets live under its own workspace's prefix (w7/m70), so the test passed with the secrets purger removed. It now reads at `WithTenant(dsID)`, and first asserts both seeds (secret and env-group meta) are readable at the paths it checks, so it cannot pass on an empty path. With real Postgres, OpenFGA and OpenBao (`scripts/backend-test-deps.sh`), removing the secrets purger fails it ("secret not purged") and so does removing the env-group purger. The secrets, envgroups and api packages are green, and `make lint` is clean.
