## Objective

Every close path records the same pre-deploy step status and cancel reason for the same outcome.

## Context

- A pre-deploy step that hits the gate closes the deploy as `pre_deploy_failed`, but its step status is set to `canceled` (the pre-deploy close mapping in `lego/backend/internal/store/store.go`). The page shows "Pre-deploy failed" next to "Pre-deploy command canceled".
- `cancelPendingDeploys` (`store.go:2067`) leaves `cancel_reason` empty.

## Steps

1. Map the gate-closed pre-deploy step to `failed`.
2. Route `cancelPendingDeploys` through the same UPDATE so it records a cancel reason.

- lego/backend/internal/store/store.go
