## Objective

Add Render's contextual New Service path to the Project overview and carry the selected Project/Environment into the existing create wizard.

## Context

- The workspace overview has a New menu and `/services/new` has Project/Environment selectors.
- The Project overview has no create-resource control. The wizard initializes both selector values to null and has no route search schema for preselection, so a user must reselect context even when they start inside a Project.
- **New Environment** already exists and is not part of this gap.

## Steps

1. Add a visible New Service action to the Project overview, associated with the selected Environment when one exists.
2. Give `/services/new` validated, shareable Project/Environment search state and initialize the existing selector from it.
3. Reject or safely clear stale/foreign mismatched Environment context using the same selector data, while keeping manual selection possible.
4. Preserve the contextual selection through the wizard and send it in `createService` exactly once.
5. Add en/zh copy and route/component coverage for selected, project-only, stale, and direct-navigation cases.

## Files

- `dashboard/src/routes/project.$projectId.index.tsx`
- `dashboard/src/routes/services.new.tsx`
- `dashboard/src/features/services/components/project-environment-selector.tsx`
- affected locale and test files

## Acceptance criteria

- [ ] New Service from a selected Environment opens the wizard with that Project and Environment selected.
- [ ] Project-only and direct `/services/new` entry continue to work.
- [ ] Stale or mismatched URL context cannot submit an invalid Project/Environment pair.
- [ ] Successful creation lands in the requested Project/Environment through the existing server-authoritative contract.

## Out of scope

- A new create API or a second service wizard.
- Region selection.
