## Objective

Make the Project overview an operating view over one selected Environment at a time, preserving bex's full environment-management capability without rendering every Environment table plus a duplicate All-resources table.

## Context

- `EnvironmentsPanel` currently maps every Environment to a full `EnvironmentCard`, each with filters and a `ResourceTable`; the route then renders another `All resources` table.
- The URL already owns `env`, `q`, and `kind`, but only the matching Environment card consumes the active query/filter; every other card remains visible with reset filters.
- Render's populated Project selects `Production` and renders one resource table. Existing bex search/type filters from `w5/m36` must remain URL-owned and Environment-scoped.

## Steps

1. Add an accessible Environment selector driven by the existing `env` search param, with a deterministic default and a truthful unassigned/all-resources state based on t001's evidence.
2. Render one selected resource view instead of stacked full Environment cards followed by a duplicate table.
3. Add accurate pre-filter counts to the selected Environment's type filters, including zero-count categories; search may narrow visible rows without falsifying the category totals.
4. Keep create/rename/delete/settings/Manage resources reachable next to the selected Environment; reuse existing dialogs/hooks.
5. Preserve no-environment, empty-environment, unassigned-resource, loading, error, and unknown-`env` states.
6. Ensure back/forward, refresh, copied URLs, search, and type filters retain coherent state when the selected Environment changes.

## Acceptance criteria

- [ ] Exactly one selected Environment resource view is visible at a time; resources are not duplicated below it.
- [ ] Type-filter counts are accurate for the selected Environment, including zero-count categories.
- [ ] Selection/search/type state survives refresh/share and browser navigation.
- [ ] Environment management and unassigned-resource access remain available.
- [ ] Unknown/deleted Environment ids fall back explicitly without a blank or stale table.

## Out of scope

- Removing bex-only Database/Key Value filters.
- Changing Environment backend membership semantics.
