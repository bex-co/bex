## Objective

Teach the guard's `board` call which parked items are ready because production now carries their commits.

## Context

- `scripts/loopx-guard.py` `blocked_review` and the `board` JSON (`"blocked": {"review": …, "unchanged": …}`); tests in `scripts/test_loopx_guard.py`.
- The production pin is the newest `chore(deploy): pin platform images to <sha>` commit on `origin/main`; `git merge-base --is-ancestor <commit> <sha>` answers whether it carries a commit (as w3's routine does).

## Steps

1. Parse each parked item's workstream line for the t001 form.
2. Find the newest pin on `origin/main` and report `blocked.ready`: items whose every named commit is an ancestor of it.
3. Keep `blocked.review` as it is; an item in `ready` is not repeated in `review`.
4. Add tests with a fixture repository: pin ahead, pin behind, an unknown commit.

## Files

- scripts/loopx-guard.py
- scripts/test_loopx_guard.py

## Acceptance criteria

- [x] `board` lists a gated item under `blocked.ready` exactly when the pin carries all its commits.

## Out of scope

- Checking that the deploy actually rolled out (the pin commit is the repository's record of it).
