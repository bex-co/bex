## Objective

Use the PTY runner with the pinned unmodified Render CLI and a redaction-safe `pgcli` shim to prove that a live bex Postgres resolves by opaque id and by display name and hands the correct external connection contract to the child process.

## Context

- `cli/pkg/tui/views/psql.go` prefers a valid 24/26-character `dpg-…` id, otherwise lists with `?name=`, requires exactly one match, checks the caller's public IP against `ipAllowList`, fetches `/v1/postgres/{id}/connection-info`, and execs `pgcli` with the external URI followed by arguments after `--`.
- bex already mints compatible `dpg-…` ids and supports exact-name filtering, sensitive connection info, public endpoints, and description-carrying IP allow lists.
- The verifier needs a non-production database with `public:true`, a configured `BEX_DB_DOMAIN`/Postgres SNI edge, and an allow-list entry covering the runner. An empty external URI is a failed precondition, not a pass.
- URI credentials are intentionally sensitive and may appear in the child's argv. The shim must validate in-process and write only redacted facts/markers.

## Steps

1. Add an opt-in verifier that accepts a pinned Render CLI binary, bex API URL/token/workspace, and either creates a disposable public database or targets an explicitly disposable one.
2. Put a purpose-built `pgcli` shim first on `PATH`; have it parse and validate the URI and passthrough args without persisting or printing raw arguments.
3. Run `render pgcli <dpg-id> -- --csv -q` and the equivalent exact-name command through the PTY driver.
4. Assert both paths select the same immutable id/host/database/TLS contract and that unknown/ambiguous names fail before child invocation.

## Files

- `scripts/pgcli-compat-verify.sh` (new)
- `scripts/pgcli-verify-client.sh` (new)
- `scripts/cli-compat.sh`

## Acceptance criteria

- [x] Both id and exact-name runs cross the interactive guard and invoke the shim exactly once.
- [x] The shim accepts only a non-empty PostgreSQL URI with the expected host/database and required TLS mode, and sees `--csv -q` in order.
- [x] Unknown or ambiguous names do not invoke the child; id/name success resolves to the same `dpg-…` identity.
- [x] Logs and temporary artifacts contain none of the planted token, username/password URI, password field, or raw child argv.

## Out of scope

- Treating an empty external endpoint or skipped IP gate as successful, changing bex connection-info behavior, or using production.
