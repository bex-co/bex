# bex-api's sanitized "internal error" carries a code, so the dashboard shows its own copy

Why: bex-api hides an unclassified resolver failure behind `message: "internal error"`, with no `extensions.code` (`lego/backend/internal/api/server.go:1707`). The dashboard's shared helpers (`relayableReason` / `mutationErrorMessage`) treat it as a server refusal. So a Loki or database outage reads "Couldn't load logs: Internal error" (or a bare "Internal error" toast), in English even in the Chinese UI. That is the same class of problem w5/164, w5/166 and w5/167 removed for "Failed to fetch".

- **Fix:**
  - Backend: tag the sanitized error with `extensions: {code: "INTERNAL"}` via a new `core.CodeInternal`, and assert it in the existing GraphQL error-mapping tests. REST's `core/http.go:324` already answers a 500, whose status the dashboard never relays.
  - Dashboard: `relayableReason` returns "" for `INTERNAL`, keyed on the code, not the wording (the w5/m128 rule), so every caller falls back to its translated copy.
- **Render parity:** Render's GraphQL is not public, so this changes no Render-compatible surface. MCP tool errors: check whether `internal error` reaches them the same way, and keep their text.
- **Test:**
  - A Go test: an unclassified resolver error answers `code: INTERNAL`.
  - A dashboard unit test: `relayableReason(codedGraphQLError("INTERNAL"))` is "".
  - One panel test: an `INTERNAL` read shows `common.loadErrorRetry` in en and zh.
- Source: the /simplify review of w5/167 on 2026-10-20. Sizing: one backend constant plus one helper branch and tests, so an inbox note.

**Done 2026-10-20.**

- **Backend:** `core.CodeInternal` ("INTERNAL") is set as `extensions.code` on GraphQL's sanitized resolver failure. REST keeps its 500 and MCP its bare text, which `mcputil` pins and agents read. The GraphQL-only scope matches `QUERY_TIMEOUT` / `WRITE_OUTCOME_UNKNOWN`, the other codes the sanitizer adds, and ADR006 now says so.
- **Dashboard:** `graphQLErrorMessage` reads nothing from a first error coded INTERNAL. So `refusalReason`, `relayableReason` and `mutationErrorMessage` fall back to translated copy, and a refusal ahead of a later INTERNAL still reads.
- **Tests:**
  - Go: the redaction unit test, and the metrics-router lookup on every surface.
  - Dashboard: helper unit cases and a usage-page INTERNAL read.
  - Two fixtures that paired INTERNAL with a non-redacted message (disk snapshots, service delete) now use the real shape.
  - `go test ./internal/api ./internal/core ./internal/mcputil`, plus dashboard tsc, eslint and vitest: all green.
