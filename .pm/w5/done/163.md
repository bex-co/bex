# The registry-credentials list honors Render's filters

Why: `GET /v1/registrycredentials` reads only `ownerId`, so Render's `name`, `username`, time-window, `cursor` and `limit` filters pass the request validator and are silently dropped. `?name=nomatch` returns every credential, and API users and agents get a confidently wrong list.

- **Where:** `lego/backend/internal/registrycreds/rest.go:120-127` calls `s.List(ctx, ownerId)` and ignores every other query parameter. Render's pinned contract (`lego/backend/internal/api/openapi/render-public-api-1.json`, `GET /registrycredentials`) declares `name`, `username`, `type`, `createdBefore/After`, `updatedBefore/After`, `cursor` and `limit`.
- **Fix:** follow the disks list (`lego/backend/internal/apps/disks.go:390-460`). Filter by `name` and `username` (exact match, repeatable), apply the created/updated windows, and page with `cursor`/`limit` using the shared cursor helpers. An invalid value gets the same named 400 the other lists give.
- **Test:** one composed-server case per filter (each must fail on the old handler), plus paging across two pages.
- **Docs:** correct ADR018 row 203 (Registry credentials), which says ✅.
- **Out of scope:** the `type` filter and Render's `registry` request/response field. Accepting `registry` reverses w8/135's decision, so it needs the user to reopen it.
- Source: fourth `/pm-brainstorm for w5` (2026-10-20), item 2, chosen by the user the same day; found by the round-3 REST diff (confirmed against the composed server). Sizing: one handler and its tests, so an inbox note.

2026-10-20: **DONE** (w5 loopx). `GET /v1/registrycredentials` now honors `name`, `username` (comma or repeated), created/updated windows, `cursor`/`limit` and repeated `ownerId` (`core.ListOwners`), using the same helpers and order as the disks and Key Value lists. `type` (Render's registry enum, which bex replaces with a host) is a named 400 instead of being ignored. `TestRESTListHonorsRenderFilters` covers each filter, a malformed window, both pages via the cursor, and the `type` refusal. ADR018 row 208 updated. GraphQL/MCP need nothing: Render's MCP has no registry-credential tools and the GraphQL list is bex-only.
