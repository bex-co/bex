# Unify destructive confirmations on Render's sudo-command dialog pattern

Implemented 2026-07-17 from a user request against the live service-delete
dialog (`/services/srv-…/settings`), generalizing Render's captured sudo gate
(`docs/render-artifacts/workspace-lifecycle.md`,
`docs/render-artifacts/protected-environments.md`,
`docs/render-artifacts/key-value.md`) to every dashboard type-to-confirm gate.

- New shared `dashboard/src/common/components/sudo-command-field.tsx`: the
  "Type <phrase> below to confirm." instruction is body copy with the exact
  phrase in `<strong>`; the input itself is labeled "Sudo Command"
  (`common.sudoCommandLabel`, en+zh). The input label never carries the
  instruction — matching Render's live dialog anatomy.
- Service delete now requires Render's `sudo delete <type words> <name>`
  (`serviceSudoPhrase` in `lib/service-type.ts`: web service / private
  service / background worker / cron job / static site) instead of typing the
  service id; the dialog body is Render's "This action cannot be undone. Are
  you sure you want to delete this <type>?".
- Adopted by all other gates: protected-environment retry dialogs (backend
  phrase shown bold), Key Value delete + suspend (body now Render's verbatim
  copy), Postgres delete (`sudo delete postgres <name>`, was bare name),
  workspace delete card, and env-group delete (`sudo delete env group <name>`,
  was typing the group id).
- Locales updated en+zh across services / keyvalue / databases / workspaces /
  env-groups / common; tests updated across 7 suites. Full dashboard suite
  green (225 files / 1,384 tests), typecheck + lint clean; visually verified
  via `yarn dev:local` + Playwright
  (`.playwright-mcp/delete-service-sudo-dialog.png`).

Kept out of a milestone because the shared field made this a bounded,
single-session sweep; the backend's protected-environment phrase contract
(`sudo <verb> service <name>`) is unchanged.
