# Tenant request logs keep only the Traefik access-log fields something reads

Why: w8/047 removed platform-internal fields one at a time on top of `defaultMode: keep`, so every Traefik upgrade that adds a field leaks it to tenants again.

Source: Last-24h code review, 2026-10-05 (user handed all fixes to w5). Follow-up to `c41d1aa91` (w8/047). Platform GitOps change.

## Fix

1. In `deploy/gitops/base/values/traefik.values.yaml:95-96`, change `fields.defaultMode: keep` to `drop` and keep only these fields:
   - read by the log shipper: `ServiceName`, `KubernetesIngressName`, `RequestMethod`, `DownstreamStatus`, `RequestHost`;
   - read by backend LogQL: `RequestPath`, `Duration`;
   - useful to tenants: `StartUTC`, `ClientHost`.

   Confirm the reader list by grepping `deploy/gitops/base/log-shipper.yaml` and `lego/backend/internal/logs/`. Check that the prod overlay (`deploy/gitops/overlays/prod/values/traefik.values.yaml`) doesn't widen it again.
2. Add a consumer-scan test asserting every kept field has a reader and every read field is kept, in the style of `keyvalue_exporter_test.go`'s drift guard. Run it from `scripts/gitops-validate.sh` or the scripts test job.
3. Live check on dev-5 or canary: request-log lines still show method, path, status, duration and host.

Done: access-log JSON carries only the allow-listed fields; the tenant request-log view is unchanged.

## Outcome (2026-10-06)

Done, keeping today's tenant view. `accessLog.fields.defaultMode` is `drop`, with every field tenants already see named `keep` (Traefik v3.7's core fields, its Kubernetes Ingress fields and `entryPointName`). The four w8/047 internals are explicitly `drop`. A field a Traefik upgrade adds now stays out of tenant logs until it is reviewed. Step 1's 9-field list would have removed fields tenants read today, against ADR010's "losing nothing a tenant may see" and this note's own "view unchanged". Trimming is filed for a user decision as w5/099.

- Step 2: `lego/backend/internal/logs/access_log_fields_test.go` pins the allowlist, requires the internals to be dropped, and fails if a field read by the shipper (its request-pipeline JSON stage and access-line filter) or by bex-api's LogQL (`logs/loki.go`, `metrics/lokisource.go`) is not kept. 6 mutants each fail it. It runs in the backend suite, which deploy.yml runs on every main push; `backend-test.yml` now also triggers on PRs that touch the two GitOps files.
- Step 3: dev-5 runs no Traefik, and canary is production, which this session cannot read. The check was done on the pinned Traefik itself instead.
