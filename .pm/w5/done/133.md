# Email-only identity reads still make Kratos load every credential

Why: `ownerEmails` (every REST service, Postgres, Key Value and project list's owner metadata) and `memberWithEmail` read only an email from `IdentityReader.LookupMany`, but its webauthn include makes Kratos' list endpoint load the batch's credentials: one extra query inside its transaction, and webauthn configs on the wire, on hot paths that never read MFA.

- **Where:** `lego/backend/internal/workspaces/kratos.go` `LookupMany` always sends `include_credential=webauthn` (w5/127); without an include, Kratos v26.2.0's list endpoint skips credentials entirely. Only `ListMembers` (`workspaces/service.go`) and `members/service.go`'s member views read `MFAEnabled`.
- **Fix:** give email-only callers a batch read without the include — a separate `IdentityReader` method (e.g. `LookupEmails`) or an option on `LookupMany` — and keep the MFA callers on the include.
- **Test:** an owner list's Kratos request carries no `include_credential`; a member list's still carries only webauthn and keeps MFA.
- Found by w5/127's efficiency review (2026-10-07).

**Result (2026-10-07):**

- **An email-only batch read.** `IdentityReader` and the members `IdentityLookup` gain `LookupEmails(ctx, subjects) map[string]string`.
  - `KratosIdentities` serves it from the same batched list read as `LookupMany`, sent without `include_credential`, so Kratos loads no credentials.
  - It returns plain emails, so a caller cannot misread an `MFAEnabled` that was never fetched.
  - An identity without an email maps to "", which `ownerEmails` stored before as well.
- **Callers.**
  - Owner metadata (`ownerEmails`: every REST service, Postgres, Key Value and project list, ListOwners, ResolveResourceOwners) uses it.
  - So does the invite's already-a-member check.
  - Member lists, which report MFA, keep `LookupMany` with webauthn only.
- **Simplify.** Reuse and quality were reviewed together, and efficiency separately.
  - The review removed a now-dead counting `LookupMany` and a duplicate `emailLookup` fake, and shared `emailsOf`.
  - The Kratos test fake now returns credentials only when one is included, as real Kratos does.
  - Efficiency confirmed one request per 100 owner subjects with no include, and no duplicate reads on the list paths.
- **Tests.**
  - The Kratos fake asserts each read's include. The email read and an owner list send none; the member list sends webauthn only and keeps MFA.
  - The w5/126 owner test and the w5/116 member-check test count email reads apart from full reads.
  - Four mutants each fail a test. The workspaces, members and api suites and `make lint` pass.
- **Follow-ups.**
  - w5/145: the single email-only reads and the notification fan-out.
  - w5/146: the projects list's per-project environment read.
  - Not filed, as optional: a constant-cost invite check through `credentials_identifier`, paging owners before resolving emails, and a short email cache.
