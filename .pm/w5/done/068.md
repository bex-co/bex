## Original finding (historical evidence)

# A GraphQL request with no query answers "internal error", and MCP answers bad JSON-RPC with plain text

Why: a client that posts `{}` (or forgets `query`) to `/graphql` is told the server failed. The response is `200 {"data":null,"errors":[{"message":"internal error"}]}`, and bex-api logs it as an internal fault. So the caller has nothing to fix from, and ops gets a false alarm. Every other GraphQL client mistake (syntax, unknown field, malformed body, oversized query) gets a specific message.

Found live in `/qa-find-bugs` pass 256 on 2026-09-28 (w4-targeted, `muse.env` credentials) against the deployed `6b6d99ea8`. Read-only: an authenticated request client.

| request | response |
| --- | --- |
| `POST /graphql` body `{}` | **200 `{"data":null,"errors":[{"message":"internal error","locations":[]}]}`** ❌ |
| control: `{"query":"{ services( }"}` | 200, `Syntax Error GraphQL request (1:13) Expected Name, found }` with location ✅ |
| control: `{"query":"{ nosuchfield }"}` | 200, `Cannot query field "nosuchfield" on type "Query".` ✅ |
| control: body `{"query":` (malformed JSON) | 400 `{"id":"bad_request",…}` ✅ |
| control: 3,000 selected fields | 200, `query rejected: selects more than 2000 fields` ✅ |

## Mechanism

- `lego/backend/internal/api/server.go:1547` `sanitizeGraphQLErrors` keeps an error only when `resolverError` returns nil (a parse or validation error) or a public error. Otherwise it logs it and rewrites the message to `"internal error"`.
- `resolverError` (l.1571) returns the **original** error when it is not a `*gqlerrors.Error`. An error graphql-go raises for an empty or missing operation, before any resolver runs, is therefore treated as a resolver failure and redacted. **Unverified:** the exact error type graphql-go returns for an empty `RequestString` at the pinned version was not opened. The redaction path is the only one that yields this message.

## Fix

Target: a request with no operation answers the way other client mistakes do, and never logs as an internal error. The preferred shape is `400 {"id":"bad_request","message":"query is required"}` before `graphql.Do`, matching the malformed-body branch. The alternative is a GraphQL error with the library's message.

- Reject an empty or whitespace-only `body.Query` in `graphqlHandler` (`server.go:~1470`) before parsing.
- Tighten `resolverError`/`sanitizeGraphQLErrors` so an error with no resolver origin is classified as a request error, not redacted (keep the redaction for real resolver errors).
- Tests: `{}` and `{"query":""}` → the named client error, with no `internal error` log line. The existing redaction tests stay green.

Adjacent, not bex code: `/mcp` answers an unknown JSON-RPC method with `400 text/plain` "JSON RPC not handled", and malformed JSON with `400 text/plain` "malformed payload: …". JSON-RPC 2.0 wants a JSON `error` with `-32601` / `-32700`. Both strings come from the pinned upstream `github.com/modelcontextprotocol/go-sdk` (`internal/jsonrpc2`, `mcp/streamable.go`). Fixing them in bex would need a wrapper around the transport, so they are recorded here rather than scheduled. An unknown **tool** already gets a proper `-32602` JSON error.

Render: n/a for the GraphQL half (bex extension); Render's MCP was not compared.

Estimate: ~20m.
