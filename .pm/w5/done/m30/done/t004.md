## Objective

Add a localized Dockerfile-path inline editor beside the existing build settings, driven by persisted runtime/builder data so it appears only for repo-backed Dockerfile-built services.

## Context

- `dockerfilePath` is relative to `rootDir`; empty means the default `Dockerfile`.
- Do not infer Docker applicability from a filename or repository contents. Use `runtime: docker`, with `builder: dockerfile` as the compatibility signal for older Apps whose runtime is empty.
- Follow the same mutation-hook and editor conventions as t003 while keeping each field's busy/error state independent.

## Steps

1. Add the GraphQL document and tested Dockerfile-path mutation hook.
2. Thread runtime/builder/path into `BuildDeploySection` and render the editor only for an effective Dockerfile build with a repository source.
3. Add localized label, relative-path hint, empty/default state, and validation/error copy.

## Acceptance criteria

- [x] Docker services display the persisted path or an honest default-Dockerfile state and can set or clear it.
- [x] Native-runtime, image-backed, cron, and static services do not show an inapplicable Dockerfile-path control.
- [x] Invalid paths surface the backend error without losing the draft.

## Out of scope

- Dockerfile content editing or automatic repository file discovery.

## Resolution

Added the localized Dockerfile Path editor gated strictly by repository source plus Docker runtime or legacy Dockerfile builder, with default-path, clear, validation-error, and inapplicable-service coverage.
