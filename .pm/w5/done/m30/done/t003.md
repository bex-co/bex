## Objective

Add a localized inline editor for `startCommand` in Settings → Build & Deploy so an applicable service can change or clear its command after creation.

## Context

- Mirror the established `use-root-dir.ts` / `root-dir.graphql` hook and mutation pattern.
- Use the current value projected by t002 and the mutation from t001.
- Cron jobs already edit `command` in `CronDeploySection`; static sites have no running command. Do not create a duplicate control for either.
- Every new label, hint, empty state, toast, and accessibility label needs `en` and `zh` locale entries.

## Steps

1. Add the GraphQL document and tested mutation hook.
2. Thread the current value through the Settings route into `BuildDeploySection` for applicable service types.
3. Add pencil → input → save/cancel behavior, including an explicit empty state and clear operation.

## Acceptance criteria

- [x] The editor initializes from the persisted value, saves changed text, clears to empty, and keeps edit mode open on mutation failure.
- [x] The control is absent for cron and static services and does not duplicate their existing settings.
- [x] User-visible copy is localized and keyboard/save/cancel controls have accessible labels.

## Out of scope

- Changing build commands or the cron-specific command editor.

## Resolution

Added the localized Start/Docker Command inline editor with persisted values, save/cancel/clear behavior, accessible controls, independent errors, and failure-draft retention; cron and static services remain excluded.
