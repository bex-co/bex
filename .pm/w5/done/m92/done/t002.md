## Objective

Make the telemetry endpoint safely callable by real CLIs (human device-flow tokens and CI `client_credentials` tokens) while bounding its abuse and volume profile.

## Context

- Scope matrix: `lego/backend/internal/api/scope_matrix*.go`; every human token needs a granular capability (w8/m27 precedent).
- Rate limiting: `lego/backend/internal/api/ratelimit.go`.
- Upstream sends at most ~1 event per invocation via a detached subprocess; a malicious client could flood.

## Steps

1. Grant the endpoint a minimal scope covering human and machine tokens (CI signal is among the most valuable telemetry).
2. Apply rate limiting appropriate for per-invocation volume (generous per-token burst, firm sustained cap).
3. Cap request body size; reject unauthenticated requests.

## Files

- `lego/backend/internal/api/scope_matrix*.go`
- `lego/backend/internal/api/ratelimit.go` (or route-local limits)
- Handler from t001

## Acceptance criteria

- [ ] Authenticated human-token POST succeeds; unauthenticated POST is rejected.
- [ ] Flood test (rapid repeat POSTs) is throttled without affecting other routes.
- [ ] Oversized body is rejected.
