## Objective

Prove the whole loop on the worker's own stack: tree-built `bex` emits one attributable event per invocation into dev-5 bex-api, and both opt-outs stay silent.

## Context

- Dev stack: `bash scripts/dev-env.sh 5 up` (isolated ports, never shared-cluster defaults) — see `.pm/w5/README.md`.
- Upstream debug knob `RENDER_LOG_ANALYTICS=1` dumps the event payload to stderr without changing send behavior.

## Steps

1. Bring up dev-5; point a tree-built `bex` at it via `BEX_HOST`.
2. Run a normal command with `RENDER_LOG_ANALYTICS=1`; assert the payload shape and that exactly one row lands attributed to the calling identity/workspace.
3. Repeat with `BEX_CLI_DISABLE_ANALYTICS=1` and `DO_NOT_TRACK=1`: no row, command still succeeds (telemetry never fails the command).
4. Add the telemetry row to `docs/cli-compatibility-checklist.md`.

## Files

- `docs/cli-compatibility-checklist.md` (new row)
- `scripts/bex-cli-auth-e2e.sh` only if extending the live gate is trivial; otherwise manual evidence

## Acceptance criteria

- [ ] One invocation → one attributed row; payload matches Render field names.
- [ ] Both opt-outs → zero rows, zero user-visible errors.
- [ ] Checklist row added with live evidence pointer.

## Out of scope

- Load testing, read-side aggregates.

## Evidence (2026-09-10)

- `TestBexEmitsTelemetryToBexAPI` (`lego/cli/main_test.go`): tree-built `bex workspaces` emits the exact upstream payload to a capturing stub (command `bex workspaces`, upstream version, install id, exit 0); `TestBexOptOutSuppressesTelemetry` proves silence under opt-out.
- Manual `RENDER_LOG_ANALYTICS=1` run confirmed the logged payload plus a captured `POST /v1/cli-telemetry-events` → 202 on both success (exit 0) and failure (exit 1, `execution_error`) paths.
- Server acceptance proven at handler level (`TestRESTIngestUpstreamShapeReturns202`) plus a real-Postgres insert/purge round-trip (`TestPGStoreCLITelemetryInsertAndPurge`, throwaway PG17 cluster).
- Live dev-5 leg not run: no container runtime in this environment (kind present, docker absent), so no kind cluster or Postgres containers; CI `backend-test.yml` covers migration + pg tests on push.
