## Objective

Persist telemetry events in their own table with user/workspace attribution from auth, a bounded retention policy, and no coupling to billing or product events.

## Context

- ID convention: mint via `lego/backend/internal/id` (`id.New(kind)`), hyphen separator (`lego/CLAUDE.md`).
- Product events live in `lego/backend/internal/events/` (user-visible lifecycle vocabulary) — telemetry must NOT ride that table: different volume, retention, and PII profile.
- Billing metronome (`docs/ADR040-billing-metronome.md`) aggregates for money; telemetry rows are per-invocation diagnostics — keep the reads separate.

## Steps

1. Add a `cli_telemetry_events`-style table + migration: event fields, `installation_id`, reporter user id + workspace id from auth, received-at timestamp.
2. Wire t001's handler to insert; keep the insert off the request critical path budget (small bounded write, no fan-out).
3. Declare retention (e.g. N days, enforced by scheduled delete) and document it; treat stable install UUID as personal data.

## Files

- `lego/backend/internal/` new store package + migration files
- Handler from t001

## Acceptance criteria

- [ ] Authed POST persists a row carrying the reporter's user/workspace ids plus payload fields.
- [ ] `id` values pass the repo's id-guard test conventions.
- [ ] Retention rule is implemented (or filed as a dated follow-up with enforcement, not just docs).

## Out of scope

- Read-side aggregates/dashboards, launcher changes.
