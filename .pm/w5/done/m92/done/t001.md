## Objective

Add a declared `POST /v1/cli-telemetry-events` route to bex-api that accepts the upstream `CliTelemetryEventPOSTInput` JSON shape so the imported CLI's sender stops getting 404s once consent is ever enabled.

## Context

- Upstream sender: `pkg/analytics` in `render-oss/cli` v2.27.0 (module cache), endpoint `POST /cli-telemetry-events`, operationId `CreateCliTelemetryEvent`, schema in `pkg/client/clitelemetry/clitelemetry_gen.go`.
- Route registration patterns: `lego/backend/internal/api/server.go`; scope matrix: `lego/backend/internal/api/scope_matrix*.go`.
- bex-api deliberately validates declared input strictly — the new route must be declared, not a silent catch-all.

## Steps

1. Mirror the upstream JSON field names (`command`, `duration_ms`, `exit_code`, `completion_kind`, `installation_id`, `current_workspace_id`, tty flags, agent/ci signals, `cli_version`, `os`/`arch`, `output_format`, `started_at`, `launched_full_screen_tui`).
2. Accept-and-ignore unknown fields so future upstream pins that add fields do not 400.
3. Return 2xx without persistence in this task (storage is t003); record receipt in a way t003 can adopt.

## Files

- `lego/backend/internal/api/server.go` (or the file that registers REST routes)
- `lego/backend/internal/api/scope_matrix*.go` (placeholder scope entry if required to route)
- New handler + request type files under `lego/backend/internal/`

## Acceptance criteria

- [ ] `curl -X POST localhost:<dev-5-port>/v1/cli-telemetry-events` with the upstream sample body returns 2xx (auth behavior covered in t002).
- [ ] A body with an extra unknown field still returns 2xx.
- [ ] `go test` for the touched packages passes.

## Out of scope

- Auth scope decisions (t002), persistence (t003), launcher consent flip (t004).
