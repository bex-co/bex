## Objective

Let the launcher send telemetry to bex-api under a bex-named opt-out, and disclose it honestly — replacing the current force-off plus hostile upstream notice.

## Context

- Bridge: `lego/cli/internal/bridge/bridge.go` currently force-sets `RENDER_CLI_DISABLE_ANALYTICS=1`; upstream consent (`pkg/analytics/consent.go`) grants by default and honors `DO_NOT_TRACK` + `RENDER_CLI_DISABLE_ANALYTICS` only.
- Upstream one-time notice copy is Render-branded and invites re-enabling Render telemetry — it cannot be reworded (unexported `buildNotice`); our disclosure must live in our own surfaces.
- Docs: `docs/bex-cli.md` (bridge telemetry paragraph + branding-limits residuals), `lego/cli/UPSTREAM_RENDER_CLI.md` (pin-bump re-diff seams).

## Steps

1. Add a bex-named opt-out (e.g. `BEX_CLI_DISABLE_ANALYTICS`) mapped onto `RENDER_CLI_DISABLE_ANALYTICS`; only set the upstream var when the user opts out (keep honoring `DO_NOT_TRACK` untouched).
2. Document in `docs/bex-cli.md`: what is collected (command path, duration, exit code, install UUID, workspace id — no args, no secret values), where it goes (bex-api, never Render), opt-outs, retention pointer from t003.
3. Record the sender endpoint as a load-bearing upstream seam in `UPSTREAM_RENDER_CLI.md` step 4 so pin bumps re-check the schema.
