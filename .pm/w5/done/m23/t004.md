## Objective

Give `type=request` lines their own rendering — method/status/path chips derived from the line's labels, with the raw JSON access line collapsed — instead of reusing the app-line renderer, which currently shows the raw JSON as-is (honest but ugly, per `w5/008`'s observed drift).

## Context

- `w5/008`'s note: "The Request type option now returns real lines... the message is the raw JSON access line... A request line probably wants its own rendering (method/status/path chips from the labels, JSON collapsed), not the app-line treatment."
- `LogEntry { timestamp message type instance level method statusCode }` — the fields available to render chips from.

## Steps

1. Branch the log-line renderer on `type === "request"`.
2. Render method/status/path as chips; collapse the raw JSON body behind an expand toggle.

## Files

- `dashboard/src/features/logs/` (log-line renderer component)

## Acceptance criteria

- [ ] A request-log line shows method/status/path chips, with the raw line available but not the default view.
- [ ] App-log lines are unaffected.
