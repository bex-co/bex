# Failed actions in dialogs show translated messages, not raw "Failed to fetch"

Why: on a network error or 5xx, ten dialog flows show the browser's raw English error text (e.g. "Failed to fetch") instead of the app's own copy, even in the Chinese UI, because the shared error helper returns any Error's message.

- **Where:** `graphQLErrorMessage` (`dashboard/src/common/lib/graphql-error.ts:4-8`) returns `err.message` for any `Error`, contradicting its own comment at `:16-17`. Sites using `graphQLErrorMessage(err) ?? t(…)`:
  - `use-update-database-version.ts:24`, `account-deletion-card.tsx:162`, `self-host-exit.tsx:93`
  - `use-change-workspace-plan.ts:41`, `use-workspace-creation-billing.ts:143/186/215`, `use-create-workspace.ts:68`, `use-rename-workspace.ts:36`, `use-delete-workspace.ts:39`
  - via `refusalReason`: `use-invite-member.ts:84`, `use-custom-domains.ts:97`
- **Fix:** switch these sites to the existing `mutationErrorMessage` (`graphql-error.ts:146`), and make `refusalReason` return `""` for anything that isn't a GraphQL error so callers fall back to their translated copy. A server refusal (a GraphQL error) still shows the server's message.
- **Test:** extend `mutation-error-toast-invariant.test.ts` to cover these sites: a network failure shows the translated fallback in en and zh, and a GraphQL refusal still shows its message. `yarn typecheck && yarn lint && yarn test` green.
- Source: fourth `/pm-brainstorm for w5` (2026-10-20), item 3, chosen by the user the same day; flagged as a follow-up in `w1/done/m145/done/t005.md:35`, never filed. Sizing: a helper change plus call-site swaps, so an inbox note.

**Done 2026-10-20.**

- `graphQLErrorMessage` now reads only a GraphQL response, and is private to `graphql-error.ts`. So `refusalReason` returns "" for a transport failure, and the invite-member and custom-domain dialogs fall back to their translated copy.
- These mutation sites now call `mutationErrorMessage(err, t(…))`. It strips the "bad request:" prefix and keeps the generic copy when the request was throttled:
  - database version upgrade, account deletion, self-host exit
  - change plan, create, rename and delete workspace
  - workspace-creation prepare/finalize
- The parameter editor's save error goes through `refusalReason` too.
- The workspace-creation page's failed plan or attempt reads show a new `workspaces.creationLoadError` (en + zh).
- **Tests:**
  - Hook tests now use real GraphQL refusals. The create-workspace test "falls back to a generic error message" had been asserting the raw text.
  - A network `TypeError("Failed to fetch")` shows the translated fallback, in en and zh, for create-workspace and the billing load.
  - The w1/m145 invariant now flags any catch-block toast/setter that reads the caught error's `.message`. The 11 calls it still finds are allowlisted against follow-up w5/166.
  - Page-level load errors that render a read's raw `.message` are filed as w5/167.
- **Verified:** dashboard tsc, eslint and the full vitest suite. On the way, `datastore-log-filters.test.tsx` was hardened against a cold-import timeout: it awaits `router.load()` before mounting, as `deploys-history-filters.test.tsx` does.
