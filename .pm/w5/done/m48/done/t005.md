## Objective

Make Branch editable in Build & Deploy settings, matching Render's searchable branch picker; bex currently renders Source and Branch read-only. Changing the branch should follow Render semantics (persists to the service; next deploy builds the new branch; auto-deploy pushes match the new branch).

## Context

- Render evidence: `.playwright-mcp/page-2026-07-19T05-25-48-576Z.yml` lines 148–159 — Branch is a combobox with search; Source is also editable there, but source-repo changes interact with the GitHub App installation flow (w2/m8–m9), so this task is branch-only and records Source-edit as drift if not trivially safe.
- Backend check first: does bex-api REST `PATCH /v1/services/{id}` already accept `serviceDetails`/`branch` (Render's API does)? Inspect `lego/backend/internal/apps` update path. If yes, add the narrow GraphQL setter (w5/m30 precedent: `SetDockerfilePath`/`SetStartCommand` narrow setters) and wire the UI; if no, add branch to the update path across REST/GraphQL/MCP consistently.
- Branch listing for the picker: the GitHub App integration (docs/ADR026) can list branches for connected repos; for plain-URL repos a free-text input is acceptable (Render degrades similarly for credential-less sources). Don't build a new provider surface.
- Guard test: `lego/backend` depguard/id conventions per CLAUDE.md; new Go files need the Apache-2.0 header.

## Steps

1. Verify the REST PATCH branch path; implement if missing (REST + GraphQL + MCP parity in the same change).
2. Add GraphQL `SetBranch` (or extend the existing update mutation) + generated types.
3. Replace the read-only Branch row with an edit control (searchable picker when the repo is GitHub-App-connected; free-text otherwise).
4. Confirm a branch change marks the docs-documented redeploy behavior (auto-deploy respects the new branch).
