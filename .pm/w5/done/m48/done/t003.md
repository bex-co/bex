## Objective

Every service with a platform subdomain — and static sites in particular — shows its `https://<slug>.<base-domain>` URL from the moment it's created, as Render does (`https://eden-cms.onrender.com` is visible in the header before any successful deploy). Today bex's header shows no URL until the App's `status.url` materializes after the first successful publish; the fresh static site srv-d9e5sbd5qe4s73b1mjq0 (build failed) shows only "The platform URL is assigned once the service is running."

## Context

- The URL is deterministic at creation: slug + `BEX_BASE_DOMAIN` (operator env; bex-api mirrors via its own `BEX_BASE_DOMAIN`, see CLAUDE.md env table). Nothing about it depends on the deploy succeeding.
- Decide the layer: (a) operator sets `status.url` at admission/first reconcile, or (b) bex-api derives a fallback URL in core when `status.url` is empty and the platform subdomain is enabled. Prefer whichever keeps REST `serviceDetails.url` / GraphQL / MCP consistent with the least mechanism change — note that (b) leaves `kubectl get apps` URL-less until publish while (a) makes the CR self-describing; record the choice.
- Dashboard surfaces: service header (no URL row exists today — Render shows URL + copy under the repo line) and `platform-subdomain-section.tsx` ("assigned once the service is running" copy).
- Respect the subdomain toggle: URL hidden/absent when the platform subdomain is disabled (`SetSubdomainPolicy`).
- Render header also links the last successfully deployed commit — check whether bex's header already has an equivalent (w5/m40 separated service/latest-deploy header facts); if missing for static, fold the link in here.

## Steps

1. Pick the derivation layer (operator vs bex-api core), implement, and propagate to REST `serviceDetails.url`, GraphQL `Server.url`, and MCP service payloads identically.
2. Add the header URL row (link + copy button) to the dashboard service header for all URL-bearing types, present from creation.
3. Update `platform-subdomain-section.tsx` to show the concrete URL instead of the "assigned once running" placeholder when derivable.
4. Verify against a never-successfully-deployed static site.

## Decision record (2026-07-18)

**Layer: bex-api derives (option b).** `Service.pendingPublicURL` (`lego/backend/internal/apps/service.go`) fills `AppView.URL` in `s.view()` whenever `status.url` is empty — the CR's status stays the operator's observed truth (what is actually served); the API projects the deterministic intent. It mirrors the operator's `effectiveHosts` ordering (spec.host → platform subdomain when `Expose` + `BEX_BASE_DOMAIN` + policy enabled → spec.hosts[0]) and applies only to `web_service`/`static_site`. All four surfaces flow through `s.view`, so REST `serviceDetails.url`, GraphQL `Server.url`, MCP `get_service`, and the dashboard agree by construction. Live proof on dev-5 (2026-07-18): `POST /v1/services` for a fresh static site returned `serviceDetails.url: https://m47-pending-site.onbex.co` in the create response, and GraphQL `server(id).url` matched, with the App never having deployed. Unit coverage: `pendingurl_test.go` (REST/GraphQL/MCP + host/policy/type/status matrix).
