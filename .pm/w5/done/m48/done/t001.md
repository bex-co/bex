## Objective

Make the service sidebar and header stop presenting runtime-instance affordances for `static_site` Apps. Render's static sidebar is Deploys, Settings | Monitor: Events, Metrics | Manage: Environment, Previews, Redirects/Rewrites, Headers — bex currently shows Logs, Shell, Scaling, and Plan for a static site, and the header meta line shows "Instances 1".

## Context

- Sidebar: `dashboard/src/features/services/components/service-nav.tsx`. It already receives service context; cron gating precedent exists (w5/m11).
- Header meta (Slug · Instances · Revision · Created): the service detail shell `dashboard/src/routes/services.$serviceId.tsx`.
- Render evidence: `.playwright-mcp/page-2026-07-19T05-25-48-576Z.yml` (static) vs `page-2026-07-19T05-27-07-997Z.yml` (web). Render static sites have **no** Logs, Shell, Scaling, Plan/Instance concept.
- **Logs decision (recorded 2026-07-18): hidden for static sites.** Render's static sidebar has no Logs entry; a static site has no pods, so the live tail and `type=app` logs are structurally empty — a Logs tab would mostly render dead states. Build logs stay on the deploy detail page (w5/m29). Request logs for a static site's hosts do exist in Loki (`type=request`, attributed via the App-named Ingress) and remain queryable over REST/GraphQL/MCP — hiding the tab drops only the UI entry point, matching Render. Direct `/logs` URLs redirect to Deploys via the shared `NonStaticRoute` guard.
- Previews is an explicitly rejected non-goal (`.pm/DO_NOT_DO.md`) — do not add it.

## Steps

1. Add a `static_site` gate in `service-nav.tsx`: drop Shell, Scaling, Plan entries (mirror the existing cron gating pattern).
2. Investigate request-log attribution for static sites (Loki `type=request` labels vs static-server host); hide or keep Logs accordingly and record the decision.
3. Hide the "Instances" meta item in the header for static sites.
4. Guard the routes themselves (`/shell`, `/scaling`, `/plan`) so a direct URL for a static site redirects to Deploys or renders a type-not-applicable state.
5. Update en/zh locales if any labels change.
