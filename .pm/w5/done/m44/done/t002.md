## Objective

Add one leak-disciplined Core operation that applies a mixed env-var/secret-file patch, preserves untouched masked values, projects the resulting Kubernetes Secrets, and chooses no rollout or exactly one rollout. Expose the same semantics through thin REST, GraphQL, and MCP adapters while preserving today's immediate-roll defaults on existing endpoints.

## Context

- `secrets.SetEnvVars` already replaces all env vars but always calls `materializeEnv`, which rolls pods; secret files only expose per-file writes.
- A dashboard draft must not reveal every unchanged secret merely to resubmit it. Model explicit set/generate/delete operations for env vars and set/delete operations for files.
- Split Secret projection from the App restart annotation. `save_only` writes OpenBao + Kubernetes Secrets without rolling; `deploy` projects both sets then rolls once. The rebuild path is composed in t006.
- Existing REST/GraphQL/MCP writes keep their current immediate-roll behavior unless the new mode is explicitly requested.

## Steps

1. Define and validate a typed batch patch and save mode in `internal/secrets`; reject duplicate/conflicting operations before any write.
2. Apply env and file changes against current OpenBao maps, compensate on a late projection failure, and avoid secret values in errors/audit/events.
3. Refactor materialization so both projected Secrets update before zero or one App rollout.
4. Add equivalent REST, GraphQL, and MCP inputs/results; keep old routes/mutations/tools byte-compatible.
5. Test no-op, generate, delete, mixed patch, save-only, deploy-once, forbidden/unavailable, validation, and compensation paths.

## Acceptance criteria

- [ ] One mixed patch preserves omitted secrets, never returns secret material, and causes zero or one rollout according to mode.
- [ ] Save-only projects new Secret data without restarting current pods; the next rollout consumes it.
- [ ] Existing single-item and replace-all clients retain immediate-roll behavior.
- [ ] REST, GraphQL, and MCP share the same validation/error semantics and meaningful backend tests pass.
