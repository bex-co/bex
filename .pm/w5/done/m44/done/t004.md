## Objective

Complete Render's high-throughput env-var affordances: import multiple rows from pasted dotenv text or a local `.env` file, add a cryptographically generated value that is visible before commit, and export all current values by copy or download with fail-closed sensitive reads.

## Context

- Reuse `generateEnvValue`/Web Crypto patterns already shipped by the create wizard; never use `Math.random`.
- Existing `formatEnvExport` and download tests provide the canonical quoting/order. Add clipboard beside download; both reveal every value network-only and fail entirely if one reveal fails.
- The importer must parse text, never execute or interpolate shell syntax. It needs comments, blank lines, optional `export`, quoted values, embedded `=`, CRLF, duplicate-key policy, invalid-key diagnostics, and a bounded file size.
- Render's modal supports paste, Choose a file, Add variables, Cancel, and Command/Ctrl+Enter.

## Steps

1. Add a pure dotenv parser with line-numbered errors and deterministic duplicate handling.
2. Build the import dialog with paste/file paths, keyboard submit, validation preview, and staged-row insertion.
3. Add Generated secret to the add-options menu and focus/select its previewable value.
4. Convert Export to a Copy env vars / Download `.env` menu with fail-closed loading and toasts.

## Acceptance criteria

- [ ] Paste and file import produce the same staged rows and never write before the parent save action.
- [ ] Parser errors identify the bad line without echoing unrelated secret values.
- [ ] Generated values use Web Crypto, are visible/copyable before save, and remain stable within the draft.
- [ ] Copy/download are deterministic and fail closed when any reveal fails.

## Out of scope

- Datastore URL selection.
- Persisting import drafts or revealed/generated values outside component memory.
