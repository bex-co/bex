## Objective

Give Secret Files the same coherent staged workflow as env vars: masked read state, add/rename/delete draft rows, a focused content editor, multi-file upload, global Cancel, and commit through the shared batch patch.

## Context

- Current `SecretFilesPanel`/`SecretFileRow` immediately upsert/delete one file and roll pods per action.
- Render's card explains `/etc/secrets/<filename>`, adds one blank filename row, edits contents behind a dedicated control, and offers Upload files from its options menu.
- Browser file names must be reduced to safe basenames and validated by the existing backend-compatible rule. Reject duplicates, directories, oversized files, unreadable/binary policy violations, and `.`/`..` without leaking other contents.

## Steps

1. Add typed secret-file draft rows and diffs that keep untouched contents opaque.
2. Implement staged add/rename/delete plus an accessible dialog/drawer for reveal/edit contents.
3. Add a multiple-file chooser with size/type/error handling and deterministic duplicate resolution.
4. Feed the resulting operations into the t002 batch mutation and share the t006 save footer.

## Acceptance criteria

- [ ] Multiple file operations remain local until one parent save and Cancel discards all of them.
- [ ] Unchanged contents are neither revealed nor resubmitted.
- [ ] Upload accepts valid files, reports invalid/duplicate/oversized entries, and never treats a path as a server path.
- [ ] Keyboard and screen-reader users can open, edit, close, and return focus from the content dialog.

## Out of scope

- Directories and binary-secret UX.
- Changing the `/etc/secrets` projection contract.
