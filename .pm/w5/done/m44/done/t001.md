## Objective

Build the milestone from direct evidence: walk every safe Render Environment state without committing changes, compare the current bex route in source and a local browser build, and preserve the interaction contract and exclusions in a durable artifact.

## Context

- Render page: `https://dashboard.render.com/web/srv-d1iai4be5dus739h1gmg/env` (authenticated Playwright capture, 2026-07-17).
- bex target: `https://dashboard.bex.co/services/srv-d9bj8s3eg85c7390eb9g/env`; the Playwright profile was not authenticated to bex, so the same route component was verified from source and `local-bex` rather than bypassing login.
- Evidence artifact: `docs/render-artifacts/service-environment-page.md`; raw screenshots/snapshots live under gitignored `.playwright-mcp/`.

## Findings

1. Render separates masked read mode from one staged edit mode and offers three save/deploy choices plus global Cancel.
2. Export is copy or dotenv download; import accepts pasted dotenv or a file; generated secrets are previewable before save.
3. Secret files support staged rows and multi-file upload; linked groups use a complete separate create flow.
4. bex has the underlying data verbs but mutates each row immediately and rolls pods every time.
5. bex's 390px CardAction layout crushes copy and the add-variable controls overflow the viewport.
6. Render now shows `Datastore URL`, but the repository anti-goal still forbids that picker; the drift is documented and excluded.

## Steps

1. Walk the Render page's view, edit, menu, dialog, secret-file, group-create, and mobile states without saving.
2. Inspect the current bex components, hooks, GraphQL operations, Core semantics, and ADR018 claims.
3. Run the same bex route against `local-bex` at desktop and 390px, including the opened add-variable state.
4. Record the side-by-side behavior, save-mode contract, responsive defect, and anti-goal exclusion.
