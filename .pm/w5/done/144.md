# An App without a service-name label still reaches a Blueprint apply's env and maintenance verbs by name

Why: w5/m133 made the apply address the service it wrote by its public id. An App without a service-name label (pre-w4/m19 bare-named, or created with no workspace) keeps its object name, because the secrets store keys its path by that name. `AuthorizeApp` then resolves the name through its displayed-name lookup, which searches every workspace the caller belongs to when the deploy names none.

- **Where:** `lego/backend/internal/apps/deploy.go` `stackServiceRef` returns `app.Name` when `LabelServiceName` is empty. `LinkEnvGroup`, `SeedEnvVars` and `ConfigureMaintenanceMode` resolve it through `core.Base.AuthorizeApp`.
- **Fix:** either name the App's own workspace in the context for those calls (`core.WithWorkspace(ctx, app.Labels[core.LabelTenant])`), or have the secrets store's key fall back to `a.Name` rather than the passed string, so the public id always works.
- **Test:** a label-less App in workspace A, plus an App displayed under its name in workspace B the caller also belongs to. An ownerless deploy's link, seed and maintenance change reach the App in A.
- Found by w5/m133's quality review (2026-10-07). It is rare: the projector stamps the label on managed Apps.

## Result (2026-10-07)

- **Fix:** the apply's by-name verbs (env-group link, env seeding and both maintenance-mode calls) now run with the App's own workspace named in their context (`stackServiceTarget`). A label-less App's object name is then resolved in its workspace only, never through the names displayed in the caller's other workspaces. Naming it is safe for every caller. It equals the acting workspace in every apply: created Apps are stamped with it, and existing ones come from `services()`, which filters by it. It costs no membership round trip, and the autosync worker already named it.
- **Before:** an ownerless deploy by a member of two workspaces either refused, with "several visible services are named web", or silently wrote the link, the generated seed and maintenance mode to the other workspace's service displayed as `web`.
- **Narrow behavior change:** a hand-applied label-less App with a tenant label that sits only in the shared namespace, mid ADR043 D8, now fails its seed (not found) after being patched. A deploy naming its workspace already failed this way; the projector labels managed Apps.
- **Tests:** `TestALabellessServicesLaterVerbsStayInItsWorkspace` covers the ambiguous and the silent case. Three deploys exercise link, seed, maintenance alone, and maintenance with an image change. It fails at HEAD, and fails with any one of the three call sites unscoped.
- **Gates:** backend `go test ./...`; `make lint`.
