# Redirect successful Postgres creation to its detail page

Render redirects a successful New Postgres submission to `/d/{dpg-id}` while the instance is still provisioning (live capture: `https://dashboard.render.com/d/dpg-d9dhmev7f7vs738lrf5g-a`). Bex's `createDatabase` mutation already returns the minted `dpg-*` id and `CreateDatabaseDialog` passes it to `onCreated`, but the overview currently discards the id and only refetches its resource lists.

Update `dashboard/src/routes/index.tsx` to preserve the existing `refetchAll()` call and navigate with the returned id to bex's canonical `/databases/$databaseId` detail route; keep `/d/{dpg-id}` as the Render-compatible inbound alias per w5/m39. Add a route-level regression test in `dashboard/src/routes/__tests__/index.test.tsx` proving the returned immutable id becomes the final URL after the dialog's search-param close navigation. Done when a successful create lands immediately on the creating detail page, which already polls to Available, while failed creates do not navigate and the dashboard typecheck/tests pass. Estimated 45m; this tightens ADR018's already-✅ Postgres CRUD + connection-info UI behavior.

> Promoted to **w5/m45** on 2026-07-17 after the user expanded the scope from this Postgres defect to an exhaustive post-create landing contract for every resource-creation action exposed by the dashboard.
