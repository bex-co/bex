## Objective

Audit all extension tools whose verb falls through `mcputil.DefaultAnnotations` to the conservative `DestructiveHint: true, IdempotentHint: false` default, and set accurate behavior hints for genuinely non-destructive / read-like and idempotent tools.

## Context

- `mcputil.DefaultAnnotations` (`lego/backend/internal/mcputil/mcputil.go:226-236`) handles `get/list/query/describe/search/preview/estimate/validate` (read-only) and `create/add/generate` (additive, `DestructiveHint: false`), and falls everything else through to `DestructiveHint: true, IdempotentHint: false, OpenWorldHint: true`.
- Verified scan of all static `mcputil.AddTool` registrations surfaced misclassified extension tools:
  - `verify_custom_domain` (`apps/mcp.go`): triggers DNS verification check — non-destructive and idempotent (`DestructiveHint: false, IdempotentHint: true`).
  - `attach_agent_session` (`agentsessions/mcp.go`): inspect its exact handler behavior; if it only attaches/reads a session without destroying state, mark non-destructive accordingly.
  - `archive_agent_session` / `unarchive_agent_session` (`agentsessions/mcp.go`): idempotent state toggles (compare `pause_agent_automation` / `resume_agent_automation` in `agentsessions/automations_mcp.go:92-97` which already set `DestructiveHint: false, IdempotentHint: true`).
  - Audit every other extension tool registered without explicit `Annotations:` (including `set_*`, `enable_*`, `disable_*`, `suspend_*`, `resume_*`, `link_*`, `unlink_*`, `clone_*`, `upload_*`, `import_*`, `restore_*`, `join_*`, `accept_*`, `edit_*`, `move_*`, `rename_*`, `update_*` — carefully distinguishing truly destructive writes like `delete_*`/`remove_*`/`revoke_*`/`suspend_*` that interrupt running workloads vs genuinely non-destructive/idempotent operations).
  - Note: `wait_agent_sessions` (`agentsessions/wait.go:257`) ALREADY sets explicit `ReadOnlyHint: true, IdempotentHint: true, DestructiveHint: false, OpenWorldHint: false` — do not regress it.

## Steps

1. Inspect the handlers of `verify_custom_domain`, `attach_agent_session`, `archive_agent_session`, `unarchive_agent_session`, `clone_env_group`, and any other extension tools with non-standard verbs or clear idempotent semantics (`set_*`, `enable_*`, `disable_*`, `resume_*`, `link_*`, `unlink_*`, etc.).
2. Add explicit `Annotations` on tools whose semantics differ from their verb's default (e.g. `verify_custom_domain`, `attach_agent_session`, `archive_agent_session`, `unarchive_agent_session`, and any other clearly misclassified tools) and refine `mcputil.DefaultAnnotations` ONLY for verb prefixes that are 100% consistent across every tool with that prefix (verify against all 28 shared tools so `TestMCPAnnotationsMatchUpstream` stays green!).
3. Ensure every MCP tool registered on the composed server still has non-nil `Annotations` with explicit `DestructiveHint` and `OpenWorldHint` pointers (never relying on nil defaults).
