## Objective

Guard all four MCP behavior hints (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) against `render-mcp-tools.json` in `TestMCPAnnotationsMatchUpstream` and narrow `list_workspaces`'s exemption to `readOnlyHint` alone.

## Context

- `lego/backend/internal/api/openapi/render-mcp-tools.json` already captures all four hints (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) for all 28 shared tools from `render-oss/render-mcp-server@a18ef3ee`.
- `TestMCPAnnotationsMatchUpstream` (`lego/backend/internal/api/mcp_parity_test.go:463-489`) checks ONLY `readOnlyHint` and `destructiveHint`, completely ignoring `idempotentHint` and `openWorldHint`.
- Furthermore, `mcpAcceptedAnnotationDivergences["list_workspaces"]` skips the entire tool, leaving `list_workspaces`'s `destructiveHint`, `idempotentHint`, and `openWorldHint` unchecked.
- Verified upstream state at `a18ef3ee`:
  - All 28 shared tools set `openWorldHint` (`false` for reads and `list_workspaces`; `true` for writes/creates/triggers/blueprints).
  - 24 of 28 shared tools set `idempotentHint` explicitly (`get_metrics`, `get_service`, `list_services`, and `update_environment_variables` omit `idempotentHint`; for `update_environment_variables` MCP spec defaults `idempotentHint` to `false`, matching bex; for read-only tools `readOnlyHint: true`, checking `idempotentHint` when upstream sets it avoids false positives on those 3 older reads while locking all 24 pinned values).
  - Also check `destructiveHint` even on read-only tools if upstream sets `destructiveHint: false` and bex explicitly sets `DestructiveHint` (pointer must be `false`, never `true` or `nil` defaulting to `true`).

## Steps

1. Update `TestMCPAnnotationsMatchUpstream` in `lego/backend/internal/api/mcp_parity_test.go` to check:
   - `readOnlyHint` (when set in `up.Annotations`)
   - `destructiveHint` (when set in `up.Annotations`, treating `nil` pointer as MCP spec default `true`)
   - `idempotentHint` (when set in `up.Annotations`)
   - `openWorldHint` (when set in `up.Annotations`, treating `nil` pointer as MCP spec default `true`)
2. Narrow `mcpAcceptedAnnotationDivergences` to per-hint keys (e.g. `"list_workspaces.readOnlyHint"`) and add a stale-entry check so an accepted divergence that no longer diverges fails the test.
3. Fix any shared-tool annotation mismatch surfaced by the tightened check (if any).
4. Run `cd lego/backend && go test -v ./internal/api -run TestMCPAnnotationsMatchUpstream`.
