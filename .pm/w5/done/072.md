# Blueprint apply skips the card requirement for free-only stacks

Why: production runs `BEX_REQUIRE_PAYMENT_METHOD=all`. ADR075 D7 says every Service, Postgres and Key Value create _or Blueprint apply_, free plans included, needs a bound card. A cardless workspace can still create free services, Postgres and Key Value through a Blueprint (REST or MCP `deploy`).

Source: Last-24h code review, 2026-10-05 (user handed all fixes to w5). Pre-existing; found while reviewing the w8/045–046 dry-run billing work. Code-verified at `4baa77e02`.

## Mechanism

- `lego/backend/internal/apps/deploy.go:1233` `requireStackPaymentMethod` calls `RequirePaymentMethod` only when `stackHasPaidPlan(st)`; it never reads `PaymentAllPlans`.
- The core gate it claims to mirror, `lego/backend/internal/core/base.go:518` `RequirePlanBilling`, requires the card when `PaidPlan(plan) || b.PaymentAllPlans`.
- Nothing else on the Blueprint path checks all-mode:
  - Blueprint services go `createFromStack` (`deploy.go:2869`) → `createNewApp`, which skips `create()`'s `RequirePlanBilling` (`apps/service.go:1943`).
  - Blueprint datastores are written as CRs directly with `s.Client.Create` (`applyDatabase` `deploy.go:3101`, `applyKeyValue` `deploy.go:3171`).
- The comment at `deploy.go:1223-1232` says the helper exists so "the interactive and Blueprint paths cannot drift apart again"; they drifted when ADR075 D7 added the all mode.
- `apps/payment_gate_test.go` covers all-mode only for `svc.Create`.

## Fix

1. Make `requireStackPaymentMethod` use the same predicate as `RequirePlanBilling`: a card when any resource is paid **or** `PaymentAllPlans` is set. Prefer calling the core helper over re-deriving it.
2. Tests:
   - all-mode with a rejecting gate refuses a free-only Blueprint apply with 402 `PAYMENT_REQUIRED` and writes nothing;
   - all-mode with an accepting gate applies;
   - paid-intent mode still lets a free-only stack through.
3. Fix the comment.

Done: in all-mode a cardless workspace gets the same 402 from a Blueprint apply (REST and MCP `deploy`) as from `POST /v1/services`; bound workspaces are unaffected.

Follow-up (not here): routing every billing check through one plan step is [w5/m116](m116/README.md).

**Done 2026-10-05.** core gained `RequireBillingFor(ctx, workspace, paidIntent)`, which owns the all-plans widening and the dunning check. `RequirePlanBilling` delegates to it, and the Blueprint gate, renamed `requireStackBilling`, now passes it `stackHasPaidPlan(st)` instead of re-deriving the policy.
- In all-plans mode, a cardless workspace now gets 402 `PAYMENT_REQUIRED` from Blueprint deploy (REST/MCP `deploy`), sync and connect, and nothing is written.
- Bound workspaces and paid-intent mode behave as before.
- Tests: `TestBlueprintApplyHonorsAllPlansCardGate` covers deploy, sync, connect and a bound workspace. A mutation check confirms the old paid-only predicate fails it.
- The remaining hand-rolled gate, `UpdatePostgres`'s plan change, stays with w5/m116 t003.
