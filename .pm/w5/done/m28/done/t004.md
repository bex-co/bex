## Objective

Protect against runaway or destructive queries: a statement timeout, a row-limit cap on results, and a confirmation step in the dashboard before running non-SELECT statements.

## Steps

1. Backend: apply a statement timeout (e.g. `statement_timeout` session setting) and cap returned rows.
2. Dashboard: detect non-SELECT statements client-side (best-effort) and require an explicit confirmation before sending.

## Files

- `lego/backend/internal/postgres/*.go` (t001's endpoint)
- `dashboard/` (SQL console component)

## Acceptance criteria

- [x] A long-running query is killed by the timeout, not left hanging.
- [x] Result sets are capped, not unbounded.
- [x] Running `DELETE`/`DROP`/etc. requires explicit confirmation in the dashboard.

## Out of scope

- Full SQL parsing/validation (best-effort detection is sufficient).
