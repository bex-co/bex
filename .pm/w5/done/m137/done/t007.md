## Objective

Close ADR005's named dangling-DNS residual without any tenant-visible step, or record why it stays accepted. Candidate: a deleted service's platform slug is never re-minted, so a forgotten `CNAME → <old-slug>.onbex.co` can never again satisfy the traffic predicate for a new claimant.

## Context

- The takeover chain needs the exact old slug: `CreateApp` (`lego/backend/internal/store/store.go`) mints `slug = name`, suffixing only on a live `apps_slug_idx` conflict — so recreating a same-named service today re-mints the deleted service's slug, and a stale tenant CNAME to it then verifies for whoever claims the host.
- ADR005 §Accepted residuals bounds this task: invisible mitigations only (never a TXT, a waiting period the tenant must serve, or a new DNS record). A recreated service getting `<name>-xxxx` instead of `<name>` is a visible URL change for the recreator — weigh it honestly against the takeover it prevents, check what (if anything) is publicly known about Render's subdomain-reuse behavior, and record the decision in ADR005 either way.
- Check where slugs are released: app deletion path and any workspace-deletion cascade, plus whether a tombstone table/migration is needed vs. retaining deleted rows' slugs in the unique index's scope.

## Acceptance criteria

- [ ] A written decision in ADR005: either "slug non-reuse implemented" with the mechanism named, or "accepted" with the reasoning — not silence.
- [ ] If implemented: delete-then-recreate-same-name yields a suffixed slug; a stale CNAME to the old slug no longer verifies for the new service; live services' slugs and URLs are untouched.
- [ ] If accepted: the milestone's parity task (t008) re-confirms no tenant step was added anywhere as a substitute mitigation.

## Out of scope

- Re-verifying already-verified domains whose DNS later moves (durability is per ADR005); wildcard support.
