## Objective

The `domains` claim lifecycle runs with no challenge secret: writers insert `pending` without one, promotion keys on the traffic predicate (t001), and storeless bex-api pre-checks traffic instead of the deterministic app-bound TXT. The unverified-never-routes gate is untouched.

## Context

- `lego/backend/internal/store/store.go`: `newDomainChallenge`, `AddDomainClaim` (48h expired-pending reclaim — keep), `PromoteDomainClaim` (CAS on `id` + expected challenge), `ReplaceDomainClaims`; migration `0086_domain_claim_state` added `challenge`/`challenge_version` (latest migration is `0151`, so this is `0152` if still free at landing).
- ADR005 §Persistence and rollout (amended): verified rows never lose traffic; TXT-pending rows become traffic-unverified; challenge columns are cleared/dropped only once no running replica reads them — pick the rolling-safe order and state it in the migration.
- `lego/backend/internal/apps/domains.go`: `requireDomainOwnership`/`domainOwnershipChallenge` (storeless synchronous TXT, app-id-bound) and `VerifyDomain`'s `DOMAIN_OWNERSHIP_PENDING`/`DOMAIN_CLAIM_STALE` conflicts. Under the new contract a failed check leaves the domain unverified (REST `202` in t004; GraphQL/MCP return the fresh unverified view in t005) — a stale-row race likewise leaves the replacement unverified, with no named conflict surfacing for it.

## Steps

1. Store: stop generating/storing challenges; `PromoteDomainClaim` CAS on `app_id` + `id` + `claim_state='pending'`; same-App retry stays idempotent; cross-App conflict and the 48h reclaim stay byte-identical in behavior.
2. Migration per the rolling plan (verified rows untouched; pending rows keep state, challenge ignored/cleared).
3. Storeless: replace the deterministic-TXT pre-proof with the traffic predicate before writing the App spec; delete `domainOwnershipChallenge` and the `_bex-challenge` name machinery.
4. `DomainView`: retire `OwnershipStatus`/`OwnershipDNSRecord` as concepts (surface deletions land in t004/t005 — coordinate the intermediate compile state so each task's suite stays green).
