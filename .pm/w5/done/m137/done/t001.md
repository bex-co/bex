## Objective

One core predicate answers "does this host's traffic DNS point at this service?" — per ADR005 (amended 2026-10-19): (a) the host's CNAME chain includes the service's platform host `<slug>.<BEX_BASE_DOMAIN>`, or (b) the host's resolved address set intersects the platform host's resolved address set (ALIAS/ANAME/flattening, direct apex `A`). This replaces the `_bex-challenge` TXT check everywhere.

## Context

- `lego/backend/internal/apps/domains.go`: `DomainOwnershipVerifier`/`systemDomainOwnershipVerifier` (`LookupTXT`, 5s timeout), `ownershipDNSRecordName`, `domainOwnershipChallenge`, `requireDomainOwnership`, and `VerifyDomain`'s TXT branch are the machinery being replaced; `platformHost` already derives the CNAME/ALIAS target.
- Production evidence 2026-10-19: `block-eden-mono-1.onbex.co` resolves to one direct edge `A`; a Cloudflare-proxied tenant record resolves to Cloudflare anycast and must satisfy neither branch (Render's Cloudflare guide requires DNS-only until verified).
- `domains_test.go` already fakes the resolver behind the verifier seam — keep a seam of the same narrowness so DNS stays deterministic in tests.

## Steps

1. Replace the verifier interface with a traffic checker (`host, platformHost → pointed bool`) over a minimal resolver seam (CNAME + address lookups, bounded chain, same timeout discipline); empty results, resolver errors, and timeouts are "not pointed", never an internal error.
2. Implement the branches: CNAME chain includes the platform host; else address-set intersection with the platform host's addresses. Case/trailing-dot-insensitive (reuse `normalizeHostname`).
3. Point `VerifyDomain`'s core check at the predicate (promotion wiring itself lands in t002/t003; keep this task to the predicate + its tests if the seam allows).
