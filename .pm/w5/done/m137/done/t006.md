## Objective

The Settings → Custom Domains panel and the post-add dialog show Render's setup and nothing else: one traffic record per domain (Type/Host/Target with copy), Render's short guidance, a Verified column that flips on its own when the sweep promotes, and the existing Certificate column. Every TXT-serving artifact — the ownership panel, the keep-the-sibling values list, the `_bex-challenge` relative-host helper, "Domain claim created" copy — is deleted, not hidden.

## Context

- `dashboard/src/features/services/components/custom-domains-section.tsx`: `DnsRecordFields` renders the ownership block + `txtSiblings` (w6/055) ahead of the traffic record; `ownershipSiblings`/`ownershipHostKey` (`lib/dns-instruction-host.ts`) exist only for the shared TXT host. `hooks/use-custom-domains.ts` maps `ownershipStatus`/`ownershipDnsRecord`; `types.ts` carries both.
- Locales `features/services/locales/{en,zh}.ts` hold the long ownership guidance ("First, add this TXT record… keep any bex-domain-verification values already there") — replace with guidance at Render's length: create this record; apex uses ALIAS/ANAME (or the shown `A` fallback); Cloudflare records stay DNS-only until verified; bex issues the certificate automatically. The zone-relative Host discipline (w4/092/w5/m121) still applies to the traffic record — keep that one clarifying clause, drop the rest.
- The unverified row stays expanded with its record visible and a Re-check action (manual trigger of t003's path); list polling/refetch already in the hooks should let auto-verification land without interaction — verify the interval story and state it.
