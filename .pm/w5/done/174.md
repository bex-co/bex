# Widen public image registries to every workspace once the node pools carry the containerd deny

Why: w5/171 shipped Render's "any public registry" behind `BEX_PUBLIC_IMAGE_REGISTRIES=false` in production (`lego/operator/config/api/deployment.yaml`). Nodes that existed before the change lack the containerd link-local deny, because CAPI applies a bootstrap only to new machines. Until the flag flips, production tenants still get the old allowlist, so the parity gap stays open there.

- Roll every node pool onto the new bootstrap (tenant, build, sandbox, platform, control plane): a MachineDeployment rollout, or the normal scale-down/up churn.
- On each node, verify `nft list table inet bex_containerd_egress` shows the `169.254.0.0/16` reject. Then attempt a pull of `<host that resolves to 169.254.169.254>/x` and watch the rule's counter rise.
- Remove the `BEX_PUBLIC_IMAGE_REGISTRIES` entry from `lego/operator/config/api/deployment.yaml` (the default is Render's behavior), and update ADR018's image row.
- Target: within a week of w5/171 shipping (by 2026-10-30), per ADR008's widen-to-every-workspace rule.

Closed 2026-10-24.

- The control plane rolled itself on the bootstrap change (KubeadmControlPlane re-rolls on a kubeadmConfigSpec change). `rolloutAfter` (98d97f365) rolled tenant-0, tenant-lg and platform, surge-first. tenant-burst was at 0, and the sandbox pool (out of band; it never runs tenant App images) was left as is.
- The rule is verified on bex-control-plane-ghhxf and on all four tenant nodes (`nft list table inet bex_containerd_egress`), through short-lived `kubectl debug` pods in kube-system that were deleted afterwards.
- Two fallouts the rotation caused, both handled:
  - The control plane's new SSH host keys broke the pinned kubeconfig fetch (ADR019, by design). The pin was re-captured through the Kubernetes API and an independent ssh-keyscan; the two matched. It was pushed to the four production GitHub environments and stored in `.env`.
  - OpenBao (Shamir seal) came back sealed on each rescheduled pod, which held the platform drain behind its PDB. `scripts/bao-init.sh` unsealed openbao-1 and then openbao-2. app-cluster run 40068611129 timed out at its rollout wait while the drain was held; the rollout then completed.
- `BEX_PUBLIC_IMAGE_REGISTRIES=false` was removed from `lego/operator/config/api/deployment.yaml`, so any public registry is now accepted in every workspace.
