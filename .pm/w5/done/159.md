# A billing notice still re-mails the owners it reached when one owner's send fails, and never stops retrying

Why: since w5/153 an owner without an address no longer fails a billing notice. A failed send still fails the whole notice, though, and the retry mails every owner again. Claims also never cap attempts, so an address the mail server rejects for good repeats the notice to everyone indefinitely.

- **Where:**
  - `lego/backend/internal/notifications/service.go` `notifyBilling` sends to every owner on each attempt.
  - `internal/billing/worker.go` `drainNotifications` fails or completes the notice as a whole.
  - `internal/store/billing_lifecycle.go` `ClaimBillingNotifications` (:744) retries any undelivered notice with backoff, and nothing caps `attempt_count`.
  - `last_error` is written but never read.
- **Fix:**
  - Record on the notice the owners it reached, in a `billing_notifications` column, and on a retry mail only the rest.
  - Cap attempts, or classify permanent SMTP rejections (5xx) as skipped owners.
  - Give `EmailLookup` an error signal. A Kratos batch that fails is dropped silently today (`api/kratos.go` :161-177), so "no address" and "lookup failed" look the same. Expose it in a way the members, workspaces and webhooks callers can share.
  - Also check the billing worker's wiring with `BEX_KRATOS_ADMIN_URL` unset. The identity adapter is always installed, so every notice fails forever rather than taking the "identity lookup unavailable" return.
- **Test:**
  - a notice where one owner's send fails transiently mails the other owner once across two worker ticks and retries only the failing owner;
  - a permanently rejected address stops being retried.
- Found by w5/153's review (2026-10-07). Likely more than an hour, since it needs a migration plus store, worker and notifier changes. Promote it if so.
