## Objective

Scope the network controls the way Render does: the Status Code filter moves from the page-level bar into the Network Metrics card header, and the quantile control becomes a `Percentile` dropdown on the Response Times section (options p50/p75/p90/p99, **default p90**), replacing the page-level combobox and the "(0.95)" heading suffix. Show the aggregate request count next to the Total Requests heading (Render: "7,266 requests").

## Context

- Captured live 2026-07-17 (Render): Network Metrics card header = heading + "Aggregated across all instances" + filter buttons `Status Code | Host | Path`; sections: Total Requests (count + `Group by` dropdown), Response Times (`Percentile` dropdown: All/p50/p75/p90-default/p99), Outbound Bandwidth (hourly-resolution note + "Usage this month").
- bex today: Status Code + quantile (default p95) sit in the page-level `metrics-filters.tsx`; `network-metrics-card.tsx` titles Response Times with `(quantile)` and already has Group by (all/status/method) and the month-to-date bandwidth footer.
- **Host/Path filters are excluded:** bex's metrics API rejects HOST/PATH filters (w3/m12) and `useMetricsFilterValues` documents STATUS_CODE as the only discoverable field — record as drift in t006, do not build dead dropdowns.
- **Percentile "All" is excluded:** the `metrics` GraphQL query carries a single `quantile` parameter; an overlay of four series is a follow-up if ever wanted (drift note in t006).
- Status Code values keep coming from `useMetricsFilterValues(serviceId, "STATUS_CODE")` — the hook call moves with the control (route → card).

## Steps

1. Move the Status Code select into the Network card header (`network-metrics-card.tsx`), relocating the `useMetricsFilterValues` call; delete it from `metrics-filters.tsx` and the route props.
2. Replace the page-level quantile combobox with a `Percentile` dropdown on the Response Times section header: p50/p75/p90/p99 mapping to quantile 0.5/0.75/0.9/0.99, default **p90**; heading becomes plain "Response Times".
3. Add the aggregate count beside Total Requests (sum of the visible requests series buckets, locale-formatted; omit when the series is empty).
4. Verify on dev-5: filter + percentile change the queries; count matches the plotted window.
