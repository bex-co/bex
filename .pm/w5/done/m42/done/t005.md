## Objective

Give every service tab Render's title shape — `<service name> · <service type label> · bex dashboard` (Render: `backend-v2 ・ Web Service ・ Render Dashboard`) — instead of today's `<srv-id or name> · <Tab> · bex dashboard`. The raw `srv-` id may appear only as the SSR/first-paint fallback and must be replaced once the service resolves; the type label (Web Service / Background Worker / Cron Job / Private Service / Static Site) comes from the loaded service.

## Context

- Captured live 2026-07-17: Render's title is identical across a service's tabs — name + type + brand, no tab segment, never the raw id. bex's metrics tab first paints `srv-d9dd16roviqs738quds0 · Metrics · bex dashboard`.
- `routes/services.$serviceId.tsx:44-55` already swaps the leading id for `service.name` in `document.title` post-load (`pathname` dep re-fixes on tab switches) — extend that effect to write the full Render shape (name + type label) rather than a prefix swap.
- Each tab's `head()` (e.g. `routes/services.$serviceId.metrics.tsx:16-18`) templates `${params.serviceId} · <Tab> · bex dashboard`; align them to the fallback shape the effect completes (the param is all `head()` can know server-side — the name/type arrive with the Apollo query).
- Type labels likely already exist for the service header chrome (`features/services`' locales) — reuse those keys, don't mint duplicates.

## Steps

1. Extend the layout title effect to set `document.title = "<name> · <type label> · bex dashboard"` once `service` resolves, re-applying on tab navigation.
2. Update each service-tab route's `head()` to the agreed SSR fallback (id-based, same `· bex dashboard` suffix) so the effect's replacement stays seamless.
3. Confirm non-service routes (databases, keyvalue, blueprints, env-groups) are untouched.
4. Verify on dev-5: browser tab reads `bex · Web Service · bex dashboard` on every tab of a web service after load; view-source/first paint shows the id fallback only.
