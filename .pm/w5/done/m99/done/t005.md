## Objective

Make an orphaned sandbox impossible to miss for 16 days again: publish the divergence between the live sandbox inventory and what sessions claim, and alert on it.

## Context

- `lego/backend/internal/sandbox/metrics.go` already registers sandbox lifecycle observations (`observeTerminate`), and `w5/m95` shipped `bex_sandbox_create_total{rejected}` plus a `SandboxProvisionFailing` alert onto the platform Prometheus, so the wiring and the Grafana/alert conventions exist.
- The existing signals cover provisioning failures, not lifetime. Nothing today would have fired on a sandbox running 403 hours past a canceled session.
- `docs/ADR088-platform-observability-ui.md` and `docs/runbooks/` hold the alert/panel conventions; `w5/m95` is the closest precedent to copy.

## Steps

1. Emit from `t003`'s reconcile: a gauge of live sandboxes by classification (claimed by a live session / terminal-session orphan / no-row orphan / inside an explicit timeout), and the age of the oldest sandbox in each class.
2. Count durable teardown failures (from `t004`) as their own series.
3. Add an alert that fires when any orphan class is non-empty for longer than one reconcile interval, and a second one on an oldest-sandbox age exceeding the `t001` bound.
4. Add the panels to the existing sandbox board and record the metric definitions in the runbook alongside `w5/m95`'s.

## Files

- `lego/backend/internal/sandbox/metrics.go`

## Acceptance criteria

- [ ] A unit test asserts each classification increments its own series with the intended labels.
- [ ] The alert rule loads on the platform Prometheus and its expression is verified against a recorded sample, not only linted.
- [ ] Panels render on the sandbox board with the new series populated.
