## Objective

Stop a steer from blanking `sandbox_id` before the previous sandbox is confirmed gone, so the handle is never lost between the row and the teardown.

## Context

- `lego/backend/internal/agentsessions/service.go:1442-1479`: steer captures `previousSandboxID := record.SandboxID`, the store write blanks the column (`internal/store/agentsessions.go:212`), then `CleanupAgentDispatches` runs and a failure is only logged — "agent-session steer: teardown of previous sandbox failed (session=%s sandbox=%s): %v" — before continuing.
- The same log-only shape appears on the completion path (`internal/agentsessions/completion.go:613`, "failure is only logged (the reaper retries next tick)"), which is sound only while the reaper can still see the row — the gap `t002` closes.
- `agent_session_dispatches` already persists `previous_sandbox_id` and has a due-time column (`internal/store/agentdispatch.go:39,58`), so a durable retry has a home.

## Steps

1. Keep the dispatch row (or an equivalent durable teardown intent) alive until the previous sandbox is confirmed terminated or confirmed absent — do not consume it on a failed terminate.
2. Ensure the teardown intent is retried on the Completer tick with backoff, and that `t003`'s inventory reconcile is the backstop if the intent is lost entirely.
3. Replace the bare log lines with a counted failure (feeding `t005`) so a persistent teardown failure is observable.

## Acceptance criteria

- [ ] A steer whose previous-sandbox terminate fails leaves a durable teardown intent; a later tick retries and succeeds, asserted by a test that fails the first terminate.
- [ ] The session's `sandbox_id` is never blanked in a way that loses the only reference to a live sandbox — either the row keeps it until confirmation, or a durable intent holds it.
- [ ] A steer whose terminate succeeds leaves no intent behind (no unbounded growth).

## Out of scope

- Changing steer's user-visible latency contract (w2/m64: steer returns fast with `phase: redispatching`).
