# 187 — HMAC ticket flavors that share a secret are not domain-separated

Why: a ticket of one flavor would verify as another that shares its secret if it ever carried the right claims; today only disjoint required claims keep them apart, so a future claim change could make them interchangeable.

- **Source:** security review round 24 (w5/m371, ADR107), agent-plane hardening note H-1.
- **Evidence:** `hmacticket.mac` signs only the claims body (`lego/backend/internal/hmacticket/hmacticket.go`); shellticket and agentsessionticket share `BEX_SHELL_TICKET_SECRET`, sandboxexec and sandboxfiles share `BEX_SANDBOX_EXEC_SECRET`. The sandbox connect tokens already derive per-flavor keys (`sandbox/connect.go`).
- **Fix:** MAC over `flavor + "\n" + body` (or derive a per-flavor key as connect.go does). Tickets live seconds to minutes, so a deploy that accepts both forms for one ticket lifetime is enough; bex-api and the ssh-gateway roll together.
- **Size:** ~1h with tests (a ticket minted for one flavor is refused by the other).
- **Done 2026-11-13:** `hmacticket.Codec` binds its flavor name into every MAC (`HMAC(secret, flavor + "\n" + body)`), so flavors that share a secret refuse each other's tickets whatever their claims. Verification still accepts the previous release's body-only MAC so tickets minted before the deploy stay valid for their lifetime (a disk snapshot key lives 24 hours); it is refused for a body holding a newline, so a current ticket re-wrapped as `<flavor>\n<body>.<mac>` cannot pass as a previous-release one (found by /simplify; a base64-only flavor name would otherwise have decoded), and w5/191 removes it once the deploy has been live 24 hours plus the clock skew. `New` panics on an empty name or one holding a newline. Only the Go backend signs or verifies these tickets, and bex-api and the ssh-gateway ship in one image. Tests: `hmacticket.TestFlavorsSharingASecretRefuseEachOthersTickets`, `TestOpenAcceptsTheBodyOnlyMACOfThePreviousRelease`, `TestOpenRefusesACurrentTicketRewrappedAsAPreviousReleaseOne`, `TestNewRefusesANameThatCouldShiftTheMACBoundary`; the flavor and ssh-gateway suites pass unchanged.
