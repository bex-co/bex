## Objective

Flip bex-api's emitted `dashboardUrl` from bex-shaped (`/services/…`, `/databases/…`, `/keyvalue/…`) to Render-shaped: `/{web|worker|pserv|static|cron}/<srv-id>` chosen by service type, `/d/<dpg-id>` for Postgres, `/r/<red-id>` for Key Value — consistent across REST, GraphQL, and MCP (all flow through the same service methods).

## Context

- Construction: `resourcemeta.Config.DashboardURL(route, id)` (`lego/backend/internal/resourcemeta/metadata.go:96`); callers `internal/apps/render.go:281` (+`AppView` at `internal/apps/service.go:736`), `internal/postgres/rest.go:69`, `internal/keyvalue/rest.go:106`.
- Service type → segment mapping needs the App's service type at construction time (web_service/private_service/background_worker/cron_job/static_site); default `web` for anything else (mirrors the Render CLI's fallback).
- Tests asserting the old shape: `internal/api/resource_metadata_test.go`, `internal/postgres/metadata_rest_test.go`, `internal/keyvalue/metadata_rest_test.go`, `internal/apps/*` — update expectations.
- `internal/apps/service.go:312` comment ("DashboardURL is the control-plane detail route") needs updating.

## Steps

1. Add a type-aware segment helper (in `resourcemeta` or `apps`) with the five-segment mapping + `web` fallback; wire the three callers.
2. Update the affected tests to expect Render-shaped URLs; add a case per service type.
3. `cd lego/backend && go build ./... && go test ./...`; `make lint-backend` from `lego/operator/`.
