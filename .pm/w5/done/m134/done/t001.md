## Objective

Point every kpack Image of an App at one registry cache tag in the App's image repository, so a release restores what the previous release cached and the image repository holds one cache tag instead of one per release.

## Context

- `lego/operator/internal/build/kpack.go` `KpackImage`: `"cache": {"registry": {"tag": o.KpackImageRef() + "-cache"}}`.
- `build.go` `KpackImageRef` (kpack host alias plus `RepoPath():revision`) and `CachePath` (`identity.ForApp(...).CacheRepo()`, which BuildKit uses with tag `cache`).
- `registry/creds.go` grants the App's Zot user read-write on `Repo()` and `CacheRepo()`. kpack authenticates with the App's push credential (`ensureKpackRegistrySecret`).

## Steps

1. Add a `KpackCacheRef` next to `KpackImageRef`: the same host alias, `RepoPath()`, and a per-App tag no release tag uses (decided over `CachePath()`; see the milestone's Decisions).
2. Use it in `KpackImage`.
3. Unit tests: two releases share the ref; two Apps, an App named `<app>-cache` and two workspaces' namesakes do not.
