## Objective

`ScopeByID` picks the workspace, the verb's own Authorize decides membership and writes the audit row, and one core policy chooses among candidate workspaces.

## Context

- `requireMember` refusals bypass `authorizeAndAudit`. An outsider's `DELETE /v1/webhooks/whk-X` records nothing, while the same call with `?ownerId=` records a denial.
- Per-package candidate pickers: `events.preferredWorkspace` (`events/service.go:889`), the GitHub IsMember loop (which duplicates the log/ErrAuthzUnavailable mapping), and notifications' default-or-first (`notifications/inbox.go`).
- Dead branches: `errInstallationNotVisible`/`forbiddenAs` in `scopeInstallation`, and inbox.go's ErrForbidden branch (rows cascade-delete with tenant_members, migration 0063).
- `sandboxOwner` lists every member namespace, without trying the default first, before the verb lists again. An outage in any member namespace fails calls for a sandbox in the default workspace.

## Steps

1. Drop `requireMember` from `ScopeByID`, and let the verb's Authorize refuse and audit.
2. Have `ResourceOwner` return candidate workspaces; core picks the default, else the sole member workspace, else ErrConflict. Delete the per-package pickers and the dead branches.
3. Probe sandboxes default-first and stop at the first hit.
