## Objective

Add a build-failing guard so a route module can never silently reintroduce a named component export (which would re-bloat the bundle).

## Context

- The regression is easy to reintroduce: the scaffold habit is `export function XPage()`. Nothing catches it today except the (easily-ignored) TanStack build warning.
- Precedent: `dashboard/src/routes/__tests__/one-rail-invariant.test.ts` is a structural route-tree assertion in the same directory — mirror its shape.
- Pairs with existing note `w5/041` (dashboard tests excluded from typecheck) — same "structural guard for a route-file convention" class.

## Steps

1. Add a `routes/__tests__` assertion (or an ESLint rule) that scans `src/routes/*.tsx` and fails if any module has a named component-style export beyond `Route` (allow `export const Route`).
2. Verify it fails when a component export is reintroduced and passes on the t001 tree.
3. Keep the matcher precise so it doesn't flag legitimate non-component exports (e.g. `validateSearch` helpers), or assert specifically on exported `function`/`const` whose name matches the page-component convention.

## Files

- `dashboard/src/routes/__tests__/no-route-component-export.test.ts` (new), or an ESLint rule in `dashboard/eslint.config.*`

## Acceptance criteria

- [ ] The guard fails on a route module with a named component export and passes on the current tree.
- [ ] It does not false-positive on `export const Route` or other legitimate route exports.

- The broader tests-excluded-from-typecheck fix (`w5/041`).
