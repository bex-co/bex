## Objective

Remove the `export` keyword from the route-file-local page components so TanStack's automatic per-route code-splitting can lift each page body into its own lazy chunk instead of eagerly bundling all 25 in the initial JS.

## Context

- 25 route files under `dashboard/src/routes/*.tsx` do `export function XPage()` (or `export const`) alongside `export const Route = createFileRoute(...)`. The named component export is what defeats the code-splitter (it prints `"these exports … will not be code-split and will increase your bundle size"`).
- `grep -rlE "^export (function|const) [A-Z][A-Za-z]*(Page|Route|Detail|Pane|Layout|Component)" dashboard/src/routes/*.tsx` enumerates them (HomePage, AgentSessionsPage, BlueprintsPage, DatabaseDetailPage, ServicePlanPage, …).
- **0** test files import these symbols from route files (`grep` for `from "@/routes/…"` in `*.test.tsx` returns none) — the exports are vestigial.
- The component stays referenced locally via `component: XPage` in the same file, so only the `export` keyword is removed.

## Steps

1. For each route module, change `export function XPage(` → `function XPage(` (and `export const XPage =` → `const XPage =`), leaving the `component:`/`pendingComponent:` references intact.
2. Do **not** touch `export const Route` — only the component export.
3. `yarn build` and confirm the per-route "will not be code-split" warnings are gone.

## Files

- `dashboard/src/routes/*.tsx` (the ~25 modules the grep lists)

- [ ] No route module has a named component export.
