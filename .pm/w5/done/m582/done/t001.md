## Objective

Implement Render's `environmentId` field on Postgres PITR recovery (`POST /v1/postgres/{id}/recovery`, plus GraphQL and MCP recovery) so a recovered database can be placed in a specified environment of the same workspace, defaulting to the source database's environment when omitted.

## Context

- Render's pinned OpenAPI for `recover-postgres` defines `environmentId`: `"The environment to create the new database in. Defaults to the environment of the original database."`
- `lego/backend/internal/postgres/rest.go:314-319` currently refuses `environmentId` with `400 recovery field environmentId is unsupported`, while `lego/backend/internal/postgres/recovery.go:438` already resolves `sourceEnvironment(ctx, src, tenantID)` and attaches the new CR to an environment.
- `POST /v1/postgres` (`Create`) already validates `environmentId` (resolving `evm-`/`env-` alias, checking workspace ownership, and enforcing protected-environment Admin authorization).

## Steps

1. Add optional `EnvironmentID string` to `RecoverRequest` in `lego/backend/internal/postgres/`.
2. In `Service.Recover` (`lego/backend/internal/postgres/recovery.go`), when `req.EnvironmentID` is non-empty, resolve and authorize that target environment using the exact same workspace-ownership and protected-environment Admin gate as `Create`; when omitted, keep `s.sourceEnvironment(ctx, src, tenantID)`.
3. Remove `environmentId` from the unsupported-field refusal loop in `lego/backend/internal/postgres/rest.go:314-319` (keeping `datadogApiKey` and `datadogSite` refused as recorded non-goals) and wire `req.EnvironmentID` into `RecoverRequest` on REST (`/recovery` and native `/recover`), GraphQL, and MCP.
4. Add unit/service tests covering: explicit `environmentId` in same workspace, omitted `environmentId` inheriting source environment, foreign-workspace `environmentId` refusal, and protected target environment requiring Admin.

## Acceptance criteria

- [x] `POST /v1/postgres/{id}/recovery` with `environmentId` creates the recovered Postgres in that environment and echoes the `evm-` id on readback.
- [x] Omitting `environmentId` preserves the source database's environment.
- [x] Foreign-workspace and non-Admin protected target environments are refused with the same errors as `POST /v1/postgres`.
- [x] GraphQL and MCP recovery accept the same optional `environmentId`.

## Out of scope

- Datadog recovery fields (`datadogApiKey`, `datadogSite`), which remain recorded non-goals.
