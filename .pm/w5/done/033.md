# en/zh locale key-parity static test (CI-enforced)

The i18n tooling only `console.warn`s in dev when a key is missing from the `en` resources (`dashboard/src/common/hooks/use-translations.ts`); nothing fails CI when `zh` lags `en` (or vice versa) as features add strings — a recurring drift class, since every milestone adds per-feature `dashboard/src/features/<name>/locales/{en,zh}.ts` merged in `src/i18n/index.ts`.

Add a static vitest that imports every locale pair (per-feature + `src/common/locales/`) and asserts identical key sets, with an explicit allowlist for intentional gaps. Locale drift then becomes a CI failure (`yarn test` already gates `deploy.yml`), not a dev-console warning nobody sees.
