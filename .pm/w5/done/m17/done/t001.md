## Objective

Before building anything, capture how render.com's dashboard actually presents service-type selection and the per-type create forms, so the bex wizard mirrors real Render IA — not a guess. This capture is the binding comparison baseline for t002–t005.

## Context

- Render's `/new` offers separate entries per type (New Web Service, Static Site, Private Service, Background Worker, Cron Job); each type's create form differs (static: publish directory + no instance type; cron: schedule + command).
- Existing capture from w5/m15: `docs/render-artifacts/new-service-wizard.md` — covers the web-service flow only; extend, don't duplicate.
- Playwright MCP writes to `.playwright-mcp/` — pass bare filenames for screenshots.

## Steps

1. Log in to dashboard.render.com via Playwright MCP; navigate to the New/`+` menu and capture the type-entry list (names, descriptions, ordering, icons).
2. Open each of static site, cron job, background worker, private service create forms; record field lists, labels, defaults, validation messages, and which web-service fields are absent per type.
3. Write the findings (with screenshots) to `docs/render-artifacts/` as an extension of the new-service-wizard capture; note anything bex cannot honor (e.g. build command) as documented divergence candidates.

## Files

- `docs/render-artifacts/new-service-wizard.md` (extend) or a sibling `new-service-types.md`
- `.playwright-mcp/` screenshots
