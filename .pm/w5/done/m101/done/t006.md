## Objective

Write the rule down once, as a matrix, so the next verb of this shape cannot be added without meeting it — the same job `m68_executable_selection_test.go` does for the contributor boundary.

## Context

- `docs/ADR024-members.md` § Guardrails today lists seat cap, plan-gated roles, last-admin refusal, atomic membership — it has no owner or self rule.
- ADR086 already documents the account-deletion offboarding matrix; this amendment must agree with it and say explicitly why that path may remove an owner (it clears the binding in the same transaction) when the member verbs may not.
- The onboarding coupling is the reason the owner rule exists: `EnsureTenant` resolves by `owner_identity_id` and never re-mints, so a removed owner is either resurrected or workspace-less.

## Steps

1. Add a § to ADR024 with the actor → target matrix (owner, self, last admin, ordinary member, machine binding) and the coded error each refusal returns.
2. State the onboarding coupling as the rationale, with file references.
3. Note that the owner's only exit is ownership transfer, still deferred in `.pm/FUTURE-MAYBE.md`, and link `w5/m102` for the non-owner exit.
4. Run `npx prettier@3.4.2 --write "**/*.md"`.
