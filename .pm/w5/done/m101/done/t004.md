## Objective

Give the three refusals one identical, machine-readable shape on every surface, the way `MEMBER_ALREADY_EXISTS` and the `INVITE_*` codes already are: `OWNER_CANNOT_BE_REMOVED`, `CANNOT_REMOVE_SELF`, `CANNOT_CHANGE_OWN_ROLE`.

## Context

- Adapters: `lego/backend/internal/members/rest.go`, `graphql.go`, `mcp.go` — thin fragments over the one service verb (`lego/backend/internal/api/CLAUDE.md`).
- The precedent for typed codes over prose matching is ADR024's invite terminal codes (`INVITE_INVALID`, `INVITE_EXPIRED`, …): typed store/service causes drive the code, never string matching.
- REST status choice: the conflict class already used for `MEMBER_ALREADY_EXISTS` is 409; pick deliberately and record the choice.

## Steps

1. Define the three codes next to the existing member codes and map the service sentinels onto them.
2. REST: correct status + code + human message on `DELETE /v1/workspaces/{id}/members/{subject}` and `PATCH .../members/{subject}`.
3. GraphQL: the same codes in the error extensions of `removeWorkspaceMember` / `changeWorkspaceMemberRole`.
4. MCP: the tool errors carry the code and an actionable sentence (an agent must be able to tell "not allowed" from "transient").
5. Extend the surface-parity test so a code added on one adapter and missed on the others fails CI.
