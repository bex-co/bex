## Objective

Stop a terminally-**failed** session's sandbox from holding plan quota for the full 30-minute completed-session editor-idle grace. A failed session (especially a fast-failing bad-key one) has no successful result to SSH into, so give it a bounded short reclaim grace — while keeping the full grace for **completed** sessions a user may still open in an editor, and keeping the never-kill-a-live-edit guarantee.

## Context

- `dev-5` showed 3 failed-session sandboxes still `Running` 4–21 minutes after their sessions failed.
- `teardown` (`lego/backend/internal/agentsessions/completion.go:486`) applies the ADR059 D2 Active-tier idle grace uniformly: the sandbox is kept alive while an editor SSH is connected AND for `IdleTTL` (~30m) past the last interaction — designed for completed sessions the user may reuse.
- `failLostSandbox` (`completion.go:449`) already reclaims immediately for dead-target failures; the gap is the ordinary driver-reported failure (e.g. model-auth) that routes through `teardown` and waits the full idle TTL.
- Idle reclaim/reaper: `reapIdleSandboxes` (`completion.go:317`), `reclaim` (`completion.go:532`); SSH activity check `AgentSessionSSHActivity` gates teardown.

## Steps

1. Distinguish terminal **failed** from **completed** in the teardown/reap path and apply a shorter reclaim grace to failed sessions with no open editor SSH (per t001's target — bounded minutes, not 30m; not necessarily zero).
2. Preserve the safety invariants: never reclaim while an editor SSH session is open; keep completed sessions on the full grace; keep an explicit Cancel's immediate teardown unchanged.
3. Update ADR059 to record the failed-vs-completed reclaim-grace distinction.
4. Verify on `dev-5` that a failed session's `BatchSandbox`/pod is reclaimed on the short grace while a completed session with an open SSH is left alone.

## Files

- `lego/backend/internal/agentsessions/completion.go` (teardown, reapIdleSandboxes, reclaim, grace config)

## Acceptance criteria

- [ ] A terminally-failed session with no open editor SSH reclaims its sandbox on a bounded short grace (verified on `dev-5`), not the 30m completed-session TTL.
- [ ] A completed session keeps the full idle grace and a session with an open editor SSH is never reclaimed.
- [ ] Explicit Cancel's immediate teardown path is unchanged.
- [ ] ADR059 records the failed-vs-completed reclaim policy.

## Out of scope

- Changing hibernation/snapshot behavior for completed sessions.
- The turn-timeout (t002) and auth fast-fail (t003) that produce the failure in the first place.
