## Objective

Stop a never-converging agent turn from tying up a sandbox for up to 4 hours. Set a sane default turn timeout (per t001's target, e.g. ~30m) that bex-api injects into the sandbox driver env, and change the driver's own fallback so an unset value is no longer 4h. Document the knob.

## Context

- Driver fallback today: `lego/agent-image/driver/src/config.ts:129` — `positiveMilliseconds(value)` returns `Number(value || 4*60*60*1000)`, i.e. 4h when `BEX_AGENT_TURN_TIMEOUT_MS` is unset.
- bex-api builds the sandbox driver env in `driverEnv` (`lego/backend/internal/agentsessions/service.go` ~1228) and does not currently set `BEX_AGENT_TURN_TIMEOUT_MS`; it should set it from an operator-configurable env with a sane default.
- Env wiring for agent sessions lives in `lego/backend/cmd/api/main.go` (`wireAgentSessions`); the inventory is `.env.example` + `lego/backend/CLAUDE.md`.
- The turn timeout is enforced in `session.ts:248` (aborts the ACP turn, SIGKILLs the child) — so lowering it makes a hung turn converge to `failed` at the bound.

## Steps

1. Add an operator-configurable timeout (e.g. `BEX_AGENT_TURN_TIMEOUT_MS`) read in `wireAgentSessions`/the Service, defaulting to the t001 target; have `driverEnv` inject it into the sandbox env for every dispatch (create, steer, rehydrate).
2. Change the driver fallback in `config.ts` so an unset value defaults to the same sane bound rather than 4h (keep it overridable; keep the positive-integer validation).
3. Add `BEX_AGENT_TURN_TIMEOUT_MS` to `.env.example` (name only) and the backend env inventory in `lego/backend/CLAUDE.md`.
4. Confirm the timeout produces a clean terminal `failed` with a timeout `failureReason` (feeds t005's completeness check).

## Acceptance criteria

- [ ] bex-api injects `BEX_AGENT_TURN_TIMEOUT_MS` into every sandbox dispatch with a sane default (not 4h).
- [ ] The driver's unset-value fallback is the sane bound, still overridable, still positive-integer-validated.
- [ ] `.env.example` and the backend env inventory list the knob.
- [ ] A turn that does not converge is bounded by the default and lands `failed` with a timeout reason.

## Out of scope

- Fast-failing auth errors before the timeout (t003) — this task only bounds the worst case.
- Per-session or plan-tiered timeout policy (single global default here).
