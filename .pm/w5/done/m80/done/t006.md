## Objective

Verify the user-facing surface this milestone touches — the agent-session `failureReason`/`reason` string and the fast-fail terminal behavior — is consistent across REST, GraphQL, MCP, and the dashboard (and mobile where it renders). Agent sessions are a bex-original feature with no render.com equivalent, so this is **cross-surface consistency + error-shape** verification, not render.com parity.

## Context

- `failureReason` is exposed on the `AgentSessionView` across REST (`render* `-shaped), GraphQL, and MCP, and rendered in the dashboard failed-session callout (and mobile session view).
- ADR006 defines the one-core / thin-adapter contract; the reason string and terminal `phase`/`status` must be byte-for-byte equivalent across the three adapters.

## Steps

1. Confirm the same `failureReason` value and terminal `phase`/`status` come back on REST, GraphQL, and MCP for each failure class (auth, capacity, timeout).
2. Confirm the dashboard (and mobile) render the reason identically and that the fast-fail timing is reflected in the surfaced `updatedAt`/terminal timestamps consistently.
3. Flag any drift (a surface that drops or reshapes the reason, or renders a blank card) as follow-up work rather than silently diverging.
4. Note in the milestone that there is no render.com equivalent to compare against (bex-original feature).

## Files

- Read/verify across `lego/backend/internal/agentsessions/{rest,graphql,mcp}.go` and `dashboard/src/features/agent-sessions/`

## Acceptance criteria

- [ ] `failureReason` + terminal `phase`/`status` are equivalent across REST/GraphQL/MCP for auth, capacity, and timeout failures.
- [ ] Dashboard (and mobile) render the reason consistently; no blank card.
- [ ] Any residual drift is filed as a follow-up note, not left silent.

## Out of scope

- New functionality; this is a consistency verification of t002–t005.
