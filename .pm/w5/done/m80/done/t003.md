## Objective

Turn the common bad/expired-BYO-key failure from a ~192s wait into a seconds-fast terminal failure. The gateway model proxy is the one component that observes every upstream vendor response; when it relays a non-transient authentication failure (401/403) **after** a successful credential mint, drive the session to `failed` promptly rather than letting the vendor CLI burn its full retry/backoff schedule.

## Context

- Model proxy: `lego/backend/internal/sshgateway/modelproxy/modelproxy.go` — mints the real BYO credential (`mintWithRetry`, `modelproxy.go:161`), forwards to the vendor, and relays the upstream status back to the sandbox. It already has `MaxRequestsPerSession`/`MaxRequestsPerWorkspace` accounting, so per-session state exists.
- A 401/403 here is the **vendor** rejecting the minted BYO key (bad/expired) — non-transient — distinct from bex's own authz (`ErrForbidden`) which `mintWithRetry` already handles as the create-race.
- The retry loop that produces the ~192s lives in the vendor CLI/SDK (per t001), which bex does not control — but bex owns the sandbox lifecycle and session state, so the gateway/completer can terminalize the session regardless of what the SDK does.
- Session terminalization + sandbox kill: `lego/backend/internal/agentsessions/completion.go` (`fail`, `failLostSandbox`, `teardown`); the gateway reaches bex via the reverse-hop credential/session APIs (`cmd/ssh-gateway/main.go` mint URLs).

## Steps

1. In the model proxy, classify a post-mint upstream **401/403** as a non-transient auth failure and record it per session (counter or first-seen flag), distinct from transient (429/5xx) and from bex authz forbidden.
2. On the first (or a small N of) such auth failures for a session, signal a terminal auth failure: either return a non-retryable terminal marker the driver maps to `failed`, or drive the completer/session to `failed` (kill sandbox) via the existing terminalization path — pick the mechanism t001 identified as reliable given the SDK's retry behavior.
3. Set a clear `failureReason` naming the authentication failure (feeds t005).
4. Preserve the existing transient-retry semantics (429/5xx still relay for the SDK to retry) and the create-race `mintWithRetry` behavior; do not fast-fail those.
5. Verify on `dev-5` that a bad-key session now fails in single-digit seconds with the auth reason.

## Files

- `lego/backend/internal/sshgateway/modelproxy/modelproxy.go`
- `lego/backend/internal/agentsessions/completion.go` (and `service.go` if a new terminal signal is threaded)
- `lego/backend/internal/sshgateway/` supporting types as needed

## Acceptance criteria

- [ ] A session whose BYO key is invalid/expired reaches `failed` in single-digit seconds on `dev-5` (was ~192s).
- [ ] Only non-transient auth failures (401/403 post-mint) fast-fail; 429/5xx still relay for normal retry, and the create-race `mintWithRetry` path is unchanged.
- [ ] The fast-fail sets a `failureReason` that names the authentication failure.
- [ ] The sandbox is killed as part of the terminalization (no orphaned pod from the fast-fail path).

## Out of scope

- Bounding genuinely hung turns (t002's timeout covers the non-auth case).
- Changing the vendor CLI/SDK retry policy.
- Reclaim-grace policy for already-failed sandboxes (t004).
