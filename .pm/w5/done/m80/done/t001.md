## Objective

Pin down, with evidence, the three failure-latency defects this milestone fixes so the later tasks target the right lever: (1) the default turn timeout, (2) the ~192s bad-key retry and which layer produces it, and (3) which terminal-failure classes leave `failureReason` empty. Produce a short characterization note with target latencies that gates t002–t005.

## Context

- `dev-5` run 2026-08-26/27: create ~100ms; sandbox running 3–10s; agent ready <1s (`initialize` 132ms, `session/new` 736ms); then `session/prompt` = 191,677ms culminating in a single instant upstream 401 ("API key is invalid"). A direct in-pod ACP probe reproduced the same ~192s single-prompt cost.
- Turn timeout default is 4h: `lego/agent-image/driver/src/config.ts:129` (`positiveMilliseconds` falls back to `4 * 60 * 60 * 1000` when `BEX_AGENT_TURN_TIMEOUT_MS` is unset); bex-api's `driverEnv` (`lego/backend/internal/agentsessions/service.go` ~1228) does not set it.
- ACP connect is capped at `min(turnTimeoutMs, 60_000)` (`lego/agent-image/driver/src/acp.ts:271`); the prompt turn itself is bounded only by `turnTimeoutMs` (`session.ts:248`).
- Model proxy is the choke point that sees every upstream response: `lego/backend/internal/sshgateway/modelproxy/modelproxy.go` (relays upstream status; has per-session/workspace caps but no auth-failure short-circuit).
- Sandbox-create failure with empty `failureReason` is inbox note `w5/048` (`ags-da51u99jg4reds94nrv0`).
