# Dashboard test files are excluded from typecheck — stale fixtures rot silently

> **PROMOTED → `w9/m85`** (2026-08-17, `/pm-brainstorm` "what to do for w9"): materialized as the "Dashboard typecheck covers test files" milestone. This note is retained for history and moved to `done/`.

Surfaced by the `w5/m65` `/simplify` review (2026-08-09), independently by two reviewers.

`dashboard/tsconfig.app.json` excludes `**/*.test.tsx` from `tsc -b`, and vitest does not typecheck. So a test fixture can drift out of sync with the type it claims to build and **nothing fails** — not `yarn typecheck`, not `yarn lint`, not `yarn test`.

Proven live: m65 changed `AgentSessionView` (dropped `evidence`, added required `agentConfig.openPr`) and one of seven fixture copies — `src/common/components/dashboard-layout/__tests__/agent-sessions-nav-section.test.tsx` — kept setting a field that no longer exists and omitted the new one. Every gate stayed green. (m65 fixed that instance and collapsed the seven copies onto a shared `src/test/mocks/agent-session.ts` builder, which narrows the blast radius but does not close the hole: the next fixture is just as unchecked.)

Options, roughly in cost order:

- add a `tsconfig.test.json` including `src/**/*.test.*` + `src/test/**`, and a `yarn typecheck:tests` step in `dashboard-test.yml`;
- or fold tests into the existing `tsconfig.app.json` include and fix whatever falls out.

Unknown how many pre-existing errors surface — size it before committing. ~30–60m if the tree is close to clean, a milestone if it isn't.
