## Objective

Prove the fix end-to-end: an authenticated dashboard page's SSR HTML contains real data before any client-side JS runs.

## Steps

1. Log in, then request an authenticated page with JS disabled (or view-source / curl with the session cookie attached).
2. Confirm the initial HTML contains real, correctly-scoped data — not an empty/loading shell.
3. Confirm the same page still works normally with JS enabled (hydration doesn't double-fetch incorrectly or flash stale content).

## Acceptance criteria

- [ ] View-source of an authenticated page shows real SSR-rendered data.
- [ ] Normal (JS-enabled) browsing is unaffected.
