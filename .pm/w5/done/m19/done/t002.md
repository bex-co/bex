## Objective

Replace the dead `bex-dashboard-token` Bearer-token path in `factory.server.ts` with forwarding the incoming request's session cookie to bex-api — the same mechanism the client-side Apollo instance uses via `credentials: "include"`, adapted for server-to-server (SSR has no browser to auto-attach cookies).

## Context

- `dashboard/src/common/apollo/factory.server.ts:33-44` — `createApolloSsrClient`, currently reads `getCookie("bex-dashboard-token")` (always undefined) and sends it as `Authorization: Bearer`.
- `lego/backend/internal/api/auth.go:149,246` — bex-api's `whoami` already forwards the incoming `Cookie` header to Kratos; no Bearer token required, a raw `Cookie` header with `ory_kratos_session` works.
- `@tanstack/react-start/server`'s `getCookie`/request-header access — need the *raw* `Cookie` header (or at least the `ory_kratos_session` value) from the incoming SSR request, not a single named cookie.

## Steps

1. Read the incoming request's `Cookie` header (or the specific `ory_kratos_session` cookie) in `createApolloSsrClient`.
2. Set it as the `Cookie` header on the SSR `HttpLink`'s outgoing request to bex-api (not `Authorization: Bearer`).
3. Remove the dead `bex-dashboard-token` code path and its stale TODO comment.
