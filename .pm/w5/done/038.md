# age backup-key rotation runbook (ADR050 follow-up)

ADR050 §1 accepts a rotation wrinkle that has no runbook yet: unlike an access credential, an old `age` **private** key must be retained until every backup it encrypted has aged out of retention (7–30 days per ADR031's table), not deleted the moment rotation completes.

Write a rotation runbook mirroring `docs/ADR036-ca-rotation-runbook.md` / `docs/ADR037-openbao-rekey-runbook.md`:

- generate the new keypair; append the new **public** key to the enabling surfaces (`BEX_BACKUP_AGE_PUBLIC_KEY` + the `bex-backup-age` ConfigMaps in `kube-system`/`secrets`);
- keep the previous **private** key in `.env`/CI under a `_PREVIOUS` suffix so `scripts/restore-*.sh` can still decrypt older `*.age` objects (extend the restore decrypt helper to try the previous key on failure);
- only after the old retention window closes, drop the previous key from `.env`, CI, and any documentation.

Also decide whether to encrypt to _both_ recipients during the overlap (age supports multiple `-r`) to shorten the dual-key window.

## Completed — 2026-09-06

`docs/runbooks/backup-age-key-rotation.md` specifies current/previous identity custody, single-recipient cutover, old/new restore proofs, inventory-based retirement and rollback. The shared restore helper accepts optional `AGE_BACKUP_PRIVATE_KEY_PREVIOUS` in a mode-0600 age keyring, with both restore-drill workflows and `gh-secrets.sh` wired. Environment-name inventory is synchronized.
