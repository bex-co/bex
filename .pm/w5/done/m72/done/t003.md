## Objective

Replace the aggregate 1 GiB persisted-state scan failure with a bounded, credential-aware scrub contract that handles large legitimate repositories while continuing to remove every platform-injected credential from writable persistence locations.

## Context

- `credentials.ts` defaults `maxScannedBytes` to 1 GiB and sums candidate file sizes across `/workspace`, HOME, tmp roots, logs, and status.
- `bex-co/beancount-cms-v2` is approximately 1.57 GiB, so cleanup throws before delivery even though the model turn itself ran.
- Blindly raising the limit or excluding `.git/objects` would weaken the fail-closed guarantee: secrets may be copied into ordinary files, Git config/logs, staged blobs, or object storage.

## Steps

1. Inventory every injected credential needle, writable persistence root, Git storage path, and the existing delivery secret scan; document which mechanism covers each persistence form.
2. Implement streaming/bounded scanning with per-file, depth, file-count, time, and cancellation controls that do not reject a tree solely because unrelated bytes exceed a global total.
3. Treat unreadable/oversized security-relevant candidates explicitly: scrub a known needle safely or fail the turn with a precise reason; never silently skip an unproven path.
4. Keep cleanup idempotent and ensure delivery cannot run until the required scrub verdict is clean.

## Acceptance criteria

- [x] A sparse/fixture repository larger than 1 GiB completes cleanup without unbounded memory use or an aggregate-byte-limit error.
- [x] Injected needles placed in workspace files, HOME/tmp, Git config/log/ref/index paths, and reachable/unreachable Git objects are removed or cause an explicit fail-closed result according to the documented contract.
- [x] Per-file/pathological inputs remain bounded by tested size, count, depth, timeout, and abort controls.
- [x] Delivery is impossible after an incomplete or failed required scrub.

## Out of scope

- General-purpose repository malware scanning.
- Disabling, globally bypassing, or merely increasing the credential scan limit.
