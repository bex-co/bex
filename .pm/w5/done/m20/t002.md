## Objective

Close the create-surface asymmetry: REST and MCP accept `envVars` at create but GraphQL `createService` has no such argument — which is exactly why the wizard can't offer env-at-create. Add the argument, threading to the same create path the other adapters use, and settle (with a test) whether create-time vars are visible in the Environment tab afterwards.

## Context

- GraphQL `createService` args: `lego/backend/internal/apps/graphql.go:462-480` — no `envVars`.
- REST create parses `envVars` at `lego/backend/internal/apps/rest.go:80` (`[]keyValue`) and maps them at `:156`; the bex.yml deploy path does the same (`apps/deploy.go:66,124-125`) — both land on the App CR's **`spec.Env`** (`appv1alpha1.EnvVar`).
- MCP `create_web_service`/`create_cron_job` accept `envVars` (`apps/mcp.go:96-171`, `toEnvVars`) → also `spec.Env`. MCP's jsonschema calls them "literal (non-secret) environment variables".
- The dashboard Environment tab (`dashboard/src/routes/services.$serviceId.env.tsx`) reads the **OpenBao-backed** secrets service (`lego/backend/internal/secrets/`, ADR013) — a *different store* than `spec.Env`. Open question this task must answer: does the env-var list surface `spec.Env` vars? If not, wizard-created vars would silently vanish from the Environment tab post-create — a support trap.
- Input shape precedent: `internal/secrets/graphql.go:73` (`envVarInputGQLType`, `{key, value}`), matching Render's env-var shape.

## Steps

1. Trace the env-var read path: confirm whether `secrets` list/get include `spec.Env` entries or only OpenBao ones.
2. Add `envVars: [EnvVarInput!]` to `createService`, threading to the same create verb REST/MCP use (adapter parity — ADR006 "one core, thin adapters"). Reuse/share the `{key,value}` input type rather than minting a new one.
3. Resolve the read-back: either the env list surfaces `spec.Env` (preferred if cheap and Render-consistent), or record the chosen semantics explicitly (code comment + ADR006/ADR018 note) and make t005 verify Render's actual behavior for create-time vars in its Environment tab.
4. Unit tests: GraphQL create-with-envVars produces the same `spec.Env` as the REST body; empty/duplicate-key handling matches REST.
