# The local mock cluster has no `bex-build` namespace, so every App deletion on a dev-N stack stalls

Why: deleting a service on any dev-N stack leaves its App CR stuck at `app.bex.co/finalizer`. The shared operator's build-artifact reclaim is forbidden in `bex-build` (`list Secrets ... cannot list resource "secrets" ... in the namespace "bex-build"`), so it keeps the finalizer and logs "App finalization cleanup blocked; preserving registry credentials" every reconcile. The namespace and its RBAC come from `deploy/gitops/base/build-boundary.yaml`, which Argo CD applies in production but nothing applies on the mock (`scripts/mock-cluster.sh` does not install Argo).

Source: w5/m113 t004's dev-5 replay, 2026-10-05. Fixture `tea-db22qs9jg4r9qfb28kog-m113-hc` is still pending finalization: the API deleted it (204, then GET 404), but the CR waits.

## Fix (~30m)

1. Have `scripts/mock-cluster.sh` apply the build boundary (namespace, Role and RoleBinding) the way it already installs the other production pieces Argo would. Keep it idempotent.
2. Check that the stuck CRs then finalize on the next reconcile, with no manual finalizer edits (those would orphan the copied registry Secrets the operator is protecting).
3. Add the namespace to `mock-cluster.sh`'s `verify_substrate` checks.

## Outcome (2026-10-06)

Done.
1. `scripts/mock-cluster.sh` applies `deploy/gitops/base/build-boundary.yaml` as is, as a required, idempotent stage beside the other production pieces it installs in place of Argo CD: the `bex-build` namespace, the operator's and bex-api's Roles and RoleBindings, and its NetworkPolicies. The local operator already ran with `BEX_BUILD_NAMESPACE=bex-build`, so on the mock it had neither the namespace its builds expect nor the RBAC its finalizer needs.
2. Applied to the live local cluster (2026-10-06 16:21Z, the same manifest). The operator's next backoff retry finalized both stuck w5 fixtures, `tea-db22qs9jg4r9qfb28kog-m113-hc` and `tea-db23k9pjg4rfl4t4bkg0-m114-suspend`, at 16:25:40Z, with no finalizer edits. `kubectl auth can-i list secrets -n bex-build` as `bex-controller-manager` now answers yes.
3. `verify_substrate` checks the operator's `bex-build-credentials` RoleBinding. `mock-cluster.test.sh` and `bash -n` pass.
