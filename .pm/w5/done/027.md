# w5/027 — Account / workspace settings: parity walk vs Render (investigation)

Source: `/pm-brainstorm` 2026-07-27 ("还有哪些 inconsistency 值得做的？"), as the low-priority third item after m55/m56.

Sub-hour **investigation**, not committed build work: walk bex's account settings (`dashboard/src/routes/settings.tsx`, Kratos/Ory-Elements-driven) and the workspace/user-nav settings against Render's account + workspace settings pages. Record any concrete IA/interaction drift as its own follow-up note (or promote to a milestone only if the walk finds a real, sized gap).

Expected to be minimal: the auth surface is intentionally Ory-Elements-driven and bex does not restyle it (`dashboard/CLAUDE.md`), and API keys (w4/security), notification settings (w4/m21), and members/roles (w4/m12/m24) already have dedicated surfaces. So this is a scoping check to confirm there's no hidden gap — not a decision to build one.

Guardrails: do **not** propose OAuth2-izing the dashboard or a custom login/consent provider (`.pm/DO_NOT_DO.md`); SSO/SAML/SCIM stay non-goals.

## Outcome (investigated 2026-07-27 — no build work)

Walked Render's account settings (`/u/<id>/settings`, authenticated) against bex. As expected, **no missing capability — the only drift is IA consolidation**, a conscious divergence, not a sized gap.

Render consolidates into one Account settings page: **Profile** (Full Name, Email + Edit), **Appearance** (Dashboard Theme, Log Explorer Theme), **Account Security** (Update Password, Login Methods, Git Deployment Credentials, Two-Factor Authentication + Backup Codes), **CLI Tokens**, **API Keys**, **Connections**, **SSH Public Keys**.

Each has a bex home, just not one page:

- Profile / Email / Password / 2FA (TOTP) / Login Methods → the **Ory-Elements Settings flow** (`/settings`, `features/auth/pages/settings-page`) — intentionally Ory-driven and not restyled (`dashboard/CLAUDE.md`).
- Dashboard Theme → the **UserNav** avatar dropdown theme submenu (bex's placement). Render's separate "Log Explorer Theme" has no bex analogue and isn't worth one.
- API Keys (w4/security), SSH Public Keys (ADR035 `sshkeys`), Git Deployment Credentials / Connections (`ConnectGithubCard`, the self-hosted GitHub App, ADR026) → dedicated surfaces.
- CLI Tokens → bex's CLI auth is the device-flow + API keys (w4/m31), not a distinct token type.

Conclusion: the account/workspace settings surface is at capability parity; Render's single-page consolidation vs bex's dedicated-surface split is an accepted IA difference (the same "don't restyle the Ory surface" stance the dashboard already documents). **No milestone or follow-up build proposed.** Any future consolidation would be cosmetic and is explicitly out of scope here.
