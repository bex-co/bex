# DatastoreMetricsPanel swallows every error into "No data in range"

> **PROMOTED → `w9/m86`** (2026-08-17, `/pm-brainstorm` "what to do for w9"): materialized as the "Honest error states for datastore metric charts" milestone. This note is retained for history and moved to `done/`.

Found by w5/m73 (the keyvalue display-name bug; renumbered from the colliding w5/m71 2026-08-18): the panel's only error state is the exact `"metrics source not configured"` message; with `errorPolicy: "all"` every other GraphQL/network/404 error yields `data === undefined` and renders as the empty-chart state, indistinguishable from a genuinely empty window. That's what hid the wrong-identifier bug for months.

Decide the error UX for datastore charts (a generic error card like the logs/metrics pages have, or at least surfacing `result.error` which `useDatastoreMetrics` already returns but the panel ignores). Files: `dashboard/src/features/metrics/components/datastore-metrics-panel.tsx`, `dashboard/src/features/metrics/components/metric-section.tsx`, `dashboard/src/features/metrics/lib/graphql-series.ts`.
