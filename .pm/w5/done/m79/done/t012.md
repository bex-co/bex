## Objective

Audit `/auth/login`, `/auth/sign-up`, `/auth/forgot-password`, `/auth/reset-password`, and `/auth/verification` sequentially so each keeps `AuthPageShell` stable while its Ory flow initializes.

## Context

- Ory Elements determines enabled fields dynamically; skeletons must not hard-code a guessed form.
- Public auth pages must remain SSR/hydration-safe and localized.

## Steps

1. Delay each flow create/fetch path, including expired and browser-redirect cases.
2. Align the shared auth skeleton with final card geometry and eliminate indefinite-loading branches.

## Files

- `dashboard/src/routes/auth.*.tsx`
- `dashboard/src/features/auth/pages/`
- auth tests

## Acceptance criteria

- [ ] Each of the five URLs has stable shell/card loading UI and a terminal error/redirect path.
- [ ] No guessed auth fields, hydration mismatch, or endless skeleton remains.

## Shared shape-parity gate

- [ ] At desktop and narrow-mobile widths, every rendering route this task owns has pending-versus-ready evidence showing the same outer bounds, padding, max-width, responsive columns, heading/action slots, tabs, and always-present major content regions with stable heights. A shared skeleton is acceptable only when that geometry actually matches; routes explicitly classified as redirects or server-only render no skeleton.

## Out of scope

- Changing enabled Kratos methods or auth architecture.
