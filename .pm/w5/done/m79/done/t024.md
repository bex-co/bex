## Objective

Drive the authenticated dashboard one rendering route at a time under deterministic delay on desktop and narrow mobile, recording evidence that the route matrix is truthful.

## Context

- Use `QA_EMAIL`/`QA_PASSWORD` from `.env` without printing them.
- Use live tenant resource ids for each detail family and preserve `.playwright-mcp/` output rules.

## Steps

1. Walk every screen-bearing route in manifest order at desktop and mobile widths.
2. Capture pending and post-loading states at the same viewport, compare their outer bounds and major-region geometry, and record shell persistence, layout shift, console/hydration errors, and terminal state.
3. Re-run any corrected route before marking it passed.

## Files

- `.pm/w5/m79/evidence/route-sweep.md`
- `.playwright-mcp/` screenshots only when they materially prove a finding

## Acceptance criteria

- [ ] Every rendering route has a pass/fail evidence row at both widths.
- [ ] Sidebar/auth chrome persists, no duplicate mount occurs, and no route remains blank or indefinite.

## Shared shape-parity gate

- [ ] At desktop and narrow-mobile widths, every rendering route this task owns has pending-versus-ready evidence showing the same outer bounds, padding, max-width, responsive columns, heading/action slots, tabs, and always-present major content regions with stable heights. A shared skeleton is acceptable only when that geometry actually matches; routes explicitly classified as redirects or server-only render no skeleton.
