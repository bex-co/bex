## Objective

Compute supported replica aggregates in the shared backend at each timestamp, with explicit handling of gaps and limits.

## Context

- The existing AggregateMax path serves legacy limit queries; general instance selection must precede aggregation.
- This is aggregation across replicas, not the separate MCP cpuUsageAggregationMethod interval parameter.
- The dashboard currently derives percentage display from raw and limit series, which needs a defined contract when selected replicas have different limits.

## Steps

1. Generalize only the needed shared aggregation seam to raw/MIN/MAX/AVG while retaining existing MAX callers.
2. Combine samples with equal timestamps from the selected instances; retain absence and define deterministic result labels/units.
3. Define Percentage/Total pairing for selected instances and mixed limits so the UI consumes authoritative results rather than inventing its own aggregate.

## Acceptance criteria

- [x] Replica values 10 and 30 produce MIN 10, MAX 30, and AVG 20 at the same timestamp.
- [x] Missing values are not replaced with zero or borrowed from another timestamp.
- [x] Mixed limits and existing MAX limit-query callers follow explicit, compatible semantics.

## Out of scope

- New time-window sampling/CPU interval aggregation semantics.
- Changing tenant metering or pricing.
