## Objective

Make `rendertest.CheckRenderMCPResult` inspect `res.StructuredContent` so array/text tools can never accidentally emit `structuredContent` and object tools that emit `structuredContent` never drift from their `Content[0].Text` JSON, while honestly reconciling `ADR018:16` with `get_metrics`.

## Context

- `lego/backend/internal/rendertest/mcpresult.go:116-155` checks only `res.Content[0]` (`*mcp.TextContent`) and never inspects `res.StructuredContent`.
- Upstream `render-oss/render-mcp-server@a18ef3ee` uses `mcp.NewToolResultText(...)` everywhere (no `structuredContent`).
- In bex (`docs/ADR018-render-parity.md:16`), array, `arrayCursor`, and plain-text tools return `Out = any` via `mcputil.RenderText` / `RenderPlainText` / `RenderListWithCursor` so `StructuredContent == nil`. Typed object tools return a Go struct so the MCP Go SDK emits both `Content[0].Text` and matching `StructuredContent`.
- Exception already enforced in `lego/backend/internal/metrics/mcp_render_test.go:37`: `get_metrics` returns `mcputil.RenderText` (`StructuredContent == nil`) because its legacy multi-`resource` array mode returns a JSON array while single-`resourceId` returns a JSON object. `trigger_deploy` queued (`emptyText`, 202) deliberately carries the queued deploy in `StructuredContent` (`ADR018:15`, `w8/378`) — handle that documented exception explicitly!

## Steps

1. Inspect `deploys/mcp.go` (`trigger_deploy` 202 queued case) and every other shared tool's `StructuredContent` behavior to make sure all intentional cases are accounted for.
2. Extend `CheckRenderMCPResult` in `lego/backend/internal/rendertest/mcpresult.go` to check `res.StructuredContent`:
   - For `form: "array"`, `"arrayCursor"`, and `"text"`: fail if `res.StructuredContent != nil`.
   - For `spec.EmptyText` matches: fail if `res.StructuredContent != nil`, except for `trigger_deploy`'s documented queued-deploy `structuredContent` (`w8/378`), where it must validate against `Deploy`.
   - For `form: "object"` (non-emptyText): if `res.StructuredContent != nil`, marshal it to JSON and fail if its decoded JSON value does not deeply equal `Content[0].Text` (and assert `StructuredContent != nil` for every object tool except `get_metrics`, or document/pin `get_metrics` explicitly as text-only so no other object tool silently drops `StructuredContent`).
3. Add unit tests in `lego/backend/internal/rendertest/mcpresult_test.go` covering every `structuredContent` rule (array with non-nil `StructuredContent` fails; object with mismatched `StructuredContent` fails; `get_metrics` text-only passes; `trigger_deploy` queued passes).
4. Reconcile `docs/ADR018-render-parity.md:16` so it explicitly notes `get_metrics`'s text-only single/multi-resource exception alongside `trigger_deploy`'s queued-deploy exception.
