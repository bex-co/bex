## Objective

Check the new fields against Render's Key Value API and the three surfaces' consistency, and record any drift.

## Context

- Render's Key Value object (docs/render-artifacts, ADR018's Key Value row).

## Acceptance criteria

- [x] The fields are consistent across REST, GraphQL and MCP; ADR018/ADR021 note them as a bex extension if Render has no counterpart.

## Result (2026-10-07)

- Render's keyValue object has no reason field, so `statusReason` and `statusReasonCode` are a bex extension, as they are for Postgres.
- The three surfaces agree, pinned by `TestStatusReasonCodeParityAcrossSurfaces`. That test found REST missing both fields, now fixed.
- ADR018's Key Value row records the extension. Neither Postgres's nor Key Value's reason fields were documented anywhere before.
