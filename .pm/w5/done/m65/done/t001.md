## Objective

Make draft-PR creation opt-in: a session opens a PR at completion only when the caller explicitly asked for one when creating the session. Default (flag absent/false) ⇒ the driver still pushes the `bex-agent/*` branch, the session finalizes `completed` with its `headSha`, but no PR is opened.

## Context

- The PR is opened by the backend Completer, not the driver: `lego/backend/internal/agentsessions/completion.go` `complete()` calls `c.GitHub.OpenDraftPullRequest(...)` at line ~207. The no-op path (nothing pushed) already finalizes with empty PR URL/number — `FinalizeAgentSession(ctx, id, PhaseCompleted, headSha, "", 0, evidenceJSON, "")` is a valid call shape to reuse.
- `AgentConfig` (`models.go` ~line 70) is the per-session config carried as JSON — prefer adding `openPr bool` there (no store migration) over a new column; verify at implementation time that the create path persists AgentConfig verbatim and the Completer can read it back.
- Per the backend rules (`lego/backend/CLAUDE.md`): one verb implementation in `service.go`, thin REST/GraphQL/MCP fragments — the new field must land on all three create surfaces in one change.
- Steer/redispatch reuses the session's stored choice; no per-turn override.

## Steps

1. Add `openPr` (default false) to the session create input on REST, GraphQL (`createAgentSession`), and MCP; persist it with the session (prefer `AgentConfig` JSON).
2. In `Completer.complete()`: when the session did not opt in, skip the git-connection lookup + `OpenDraftPullRequest` and finalize `PhaseCompleted` with `headSha` and empty PR URL/number.
3. Update `docs/ADR047-cloud-coding-agent-sessions.md` § D8: draft-PR delivery is now opt-in at create; branch push remains unconditional.
4. Extend the Completer unit tests (`completion_test.go`): opted-out + pushed ⇒ completed, no PR call; opted-in ⇒ unchanged PR path.
