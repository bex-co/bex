# Page-level load errors show translated copy, not a query's raw "Failed to fetch"

Why: when a page's read fails, ten error panels print the Apollo error's `.message` straight into the page. A network failure therefore shows the browser's untranslated "Failed to fetch" (or "Response not successful: Received status code 502"), even in the Chinese UI, where the panel's own copy should be.

- **Where:** each of these renders a query error's `.message` directly. They are outside w5/164's catch-block invariant because they are reads, not catch blocks.
  - `features/usage/components/usage-page.tsx:118`
  - `features/deploys/components/deploy-log-panel.tsx:162`
  - `features/deploys/components/deploys-list-page.tsx:164`
  - `features/deploys/components/deploy-detail-page.tsx:94`
  - `features/logs/components/log-viewer.tsx:249` and `:272`
  - `features/logs/components/datastore-log-viewer.tsx:270`
  - `features/services/components/disk-section.tsx:141` and `:587`
  - `routes/agents_.$agentSessionId.tsx:123`
- **Fix:** show `refusalReason(error)` when it is non-empty (a GraphQL refusal the user can act on), and otherwise the panel's translated copy. The copy may need a new key such as `common.loadErrorRetry`; reuse one if an existing key fits. Check what the logs viewer does for REST-backed reads: its errors may not be Apollo errors, and their messages may be bex-api's own.
- **Test:** for each panel, a `TypeError("Failed to fetch")` read shows the translated copy in en and zh, and a GraphQL refusal still shows its message. Optionally, add a structural guard next to `mutation-error-toast-invariant.test.ts` that flags `{error.message}` / `message={….error.message}` in JSX.
- Source: found by the /simplify review of w5/164 on 2026-10-20. Sizing: about an hour of call-site swaps plus one copy key, so an inbox note.

**Done 2026-10-20.** The ten panels now render `mutationErrorMessage(error, t("common.loadErrorRetry"))`: the server's refusal when bex-api answered with one, else "Something went wrong while loading. Refresh the page to try again." ("加载时出错，请刷新页面重试。"). The panels:

- usage
- the deploy list, detail and log panel
- the service and datastore log viewers
- both disk panels
- the agent-session page

Along the way:

- `LogEmptyState`'s failed variant now takes the error itself, so no log view can pass raw text.
- The service log viewer's inline banner uses a localizable `logs.errorTitleWithReason`.
- `mutation-error-toast-invariant.test.ts` gained a JSX guard: no component renders an error's raw `.message`. It catches props, children and `||`/`??` fallbacks. Stripe.js's self-localized confirmation errors are excluded.
- **Tests:** each panel test uses a network failure; the usage page also checks zh and a server refusal. Dashboard tsc, eslint and vitest are green.
- **Left out:** the root route error page still shows a thrown error's own message; that is deliberate and pinned by its tests.
- **Follow-up filed:** w5/168, so the backend's sanitized "internal error" gets a code and translated copy.
