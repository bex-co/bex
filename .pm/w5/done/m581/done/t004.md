## Objective

Record every Render operation validated during the `internal/api` suite (in `rendertest`) and add a suite-level guard failing if any served non-streaming Render operation is never exercised by a response-conformance test, then update `docs/ADR018-render-parity.md`.

## Context

- `rendertest.Wrap` already records `hits` per allowlist entry and `rendertest.RunSuite` checks `Unexercised` in `TestMain` (`lego/backend/internal/api/conformance_main_test.go`).
- Tracking validated `operationId`s across the suite (or explicitly classifying exemptions like `subscribe-logs`) prevents newly mounted Render operations from shipping without response-schema conformance coverage.

## Steps

1. Record exercised `operationId`s in `rendertest` (or add a dedicated coverage test in `lego/backend/internal/api/`) and verify that every non-omitted served operation in the pinned OpenAPI document is either exercised by a conformance pass or explicitly listed in a small `conformanceExemptions` table (e.g., `subscribe-logs` SSE stream).
2. Confirm `TestAllowlistOnlyShrinks` and `TestMain` pass cleanly in both single-test and full-package runs (do not break focused `go test -run Foo` invocations — mirror `rendertest.RunSuite`'s full-run check!).
3. Update `docs/ADR018-render-parity.md` § Allowlisted response-schema divergences to record the expanded coverage and any defects fixed in `t001`–`t003`.
4. Run `npx prettier@3.4.2 --write docs/ADR018-render-parity.md` and `bash scripts/docs-links-validate.sh`.

## Files

- `lego/backend/internal/rendertest/rendertest.go` (and `main.go` if suite-tracked)
- `lego/backend/internal/api/conformance_test.go`

- [ ] A new mounted Render operation without conformance coverage fails the guard.

- [ ] `docs/ADR018-render-parity.md` is updated, formatted, and link-validated.
