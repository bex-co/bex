## Objective

Fix `DELETE /v1/build-sources/{buildSourceId}` so it returns a valid HTTP 204 No Content response with no body and no `Content-Type` header, and teach `rendertest.Validate` to fail any 204 response that writes a body or sets `Content-Type`.

## Context

- `lego/backend/internal/apps/build_sources.go:861` registers `DELETE /v1/build-sources/{buildSourceId}` with `core.HandleJSON(http.StatusNoContent, …)`, which invokes `core.WriteJSON(w, 204, nil)` (`lego/backend/internal/core/http.go:256-269`), setting `Content-Type: application/json` and writing `null\n` on HTTP 204.
- `lego/backend/internal/rendertest/rendertest.go:199-203` skips validation whenever `!documentsBody(responses, status)`, allowing a 204 response carrying a body to pass unnoticed.

## Steps

1. Switch `DELETE /v1/build-sources/{buildSourceId}` in `lego/backend/internal/apps/build_sources.go` from `core.HandleJSON(http.StatusNoContent, …)` to `core.HandleNoBody(http.StatusNoContent, …)`.
2. Check for any other 204 handlers across `lego/backend/internal/` that write a body or `Content-Type` header.
3. Update `rendertest.Validate` in `lego/backend/internal/rendertest/rendertest.go` so `status == http.StatusNoContent` reports a violation if `len(body) > 0` or `header.Get("Content-Type") != ""`.
4. Add unit tests in `lego/backend/internal/rendertest/rendertest_test.go` and an HTTP REST test for `DELETE /v1/build-sources/{buildSourceId}` verifying status 204, empty body, and absent `Content-Type`.
