## Objective

A gzip-encoded `git-receive-pack` (push) body is decompressed before branch-confinement validation, so medium-size pushes (body 1 KiB–1 MiB — git's gzip band below the chunked `http.postBuffer` threshold) stop being rejected 403 "push is not confined to the session branch" by `validateReceivePack` parsing raw gzip bytes as pkt-lines.

## Context

- `validateReceivePack` (`lego/backend/internal/sshgateway/agentcred/agentcred.go:393`) reads the request body directly; a gzipped preamble fails `strconv.ParseUint` on the pkt-line header → `ErrForbidden` → 403. Pushes < 1 KiB (plain) and > 1 MiB (`large_request` → chunked, never gzipped) pass, which is why past small deliveries worked — the middle band is the landmine.
- Simplest correct shape: when the client sends `Content-Encoding: gzip` on receive-pack, wrap the body in a `gzip.Reader`, validate the **decompressed** stream, and forward the decompressed body upstream **without** the header, `ContentLength = -1` (chunked to GitHub — GitHub accepts chunked receive-pack). Avoids re-compressing and keeps the validated bytes and the forwarded bytes the same stream (the existing `io.MultiReader(prefix, reader)` replay pattern).
- Decompression-bomb bound: the raw body is already capped by `http.MaxBytesReader` (`maxRequestBodyBytes`, 256 MiB) but gzip expands — bound the **decompressed** preamble via the existing `maxReceivePackPrefixBytes` budget (already enforced) and the decompressed total via an `io.LimitReader` consistent with `maxRequestBodyBytes` semantics.
- Reject a malformed gzip stream fail-closed (403/400), never fall through to forwarding raw bytes.

## Steps

1. In `serveGit`'s receive-pack branch, detect `Content-Encoding: gzip`, wrap `r.Body` in `gzip.NewReader` (+ decompressed-size limit), and feed that to `validateReceivePack`.
2. Forward the validated decompressed stream upstream with the `Content-Encoding` header stripped and `request.ContentLength = -1` (skip the `r.ContentLength` copy in this branch).
3. Unit tests: gzipped push confined to the session branch → forwarded decompressed and accepted by the stub upstream; gzipped push naming another ref → 403; truncated/corrupt gzip → fail-closed; oversized decompressed preamble → fail-closed.
