## Objective

The milestone's shipped behavior is pinned by meaningful tests that assert real wire behavior and failure modes — a future header-allowlist "hardening" pass cannot silently reintroduce this bug class.

## Context

- t001/t002/t003 each add point tests; this task closes the gaps into a coherent suite. The regression that motivates it: `e91d5be8` narrowed forwarded headers with tests that only exercised sub-1 KiB (plain) bodies, so the gzip band was invisible.
- Real-behavior bar (board rule): tests must encode the *git wire contract* — e.g. build the gzipped fetch/push bodies the way git does (gzip of valid pkt-lines), not synthetic strings that happen to pass.

## Steps

1. Add an end-to-end-shaped proxy test: stub upstream asserting, per service, the exact received headers + decompressed body for (a) plain upload-pack, (b) gzipped upload-pack, (c) plain receive-pack, (d) gzipped receive-pack.
2. Cover the retry-visible failure modes: upstream 400 → sandbox-visible 502 with no body reflection; corrupt gzip → fail-closed.
3. Assert the header allowlist as a contract: exactly `Accept`, `Content-Type`, `Git-Protocol` (+ `Content-Encoding` where designed) reach upstream — nothing else (e.g. no `Authorization` passthrough from the sandbox side).
