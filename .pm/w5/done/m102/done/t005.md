## Objective

Give the dashboard a deliberate Leave action — in workspace settings, not on the Team row — with a confirmation that names the workspace and the consequence, and a landing path that puts the caller in a workspace they still belong to.

## Context

- Team panel lives on `/workspace/settings` between the details card and the danger zone (ADR024 § Parity completion); the danger zone is the natural home for Leave.
- `w5/m101/t005` disables the self-row Remove control and should point here.
- Post-leave navigation: the workspace provider's stale-list fallback is a known hazard — ADR024's invitation journey records the same ordering rule (refresh the workspace list, wait until the provider observes the change, then select). Reuse that path.
- Skeleton rule: any settings-page geometry change must keep the loading skeleton matching the ready state at desktop and narrow-mobile widths (root `AGENTS.md`).

## Steps

1. Add the Leave action with an explicit confirmation naming the workspace.
2. Hide or disable it with a reason for the owner and the last admin (server still refuses; the UI must not offer a dead action).
3. After success: refresh the workspace list, wait for the provider, select a remaining workspace, land on its overview.
4. Render server refusals inline.
5. Add en/zh strings and component tests; verify pending/ready geometry at both widths.

## Files

- `dashboard/src/features/team/` and the workspace-settings route
- corresponding `__tests__` files and locale files

## Acceptance criteria

- [ ] Leave is reachable from workspace settings with a confirmation, and absent/disabled-with-reason for owner and last admin.
- [ ] After leaving, the caller lands in a workspace they belong to — never a dead page or the stale-list fallback.
- [ ] Server refusals render inline.
- [ ] Skeleton matches the ready state at desktop and narrow-mobile widths.

## Out of scope

- Account deletion (ADR086 owns that flow).
