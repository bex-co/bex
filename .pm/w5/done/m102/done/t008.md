## Objective

Cover Leave's real behavior and real failure modes: the happy path with row+tuple both gone, both refusals, the partial-failure ordering, and the post-leave resolution with no stale-cache window.

## Context

- Real Postgres and OpenFGA run in backend CI (`BEX_TEST_DB_URI`, `BEX_TEST_OPENFGA_URL`).
- The stale-cache regression is the one most likely to reappear (the w5/m13 blank-switcher finding) — assert the caller's next resolution directly, not just the store state.
- Useless-test rules apply: no tautologies, no mock-echoing, no trivially-true polling.

## Steps

1. Happy path: member leaves; `tenant_members` row gone, OpenFGA tuple gone, workspace absent from their workspace list.
2. Refusals: owner and last admin, each with its code, each leaving state untouched.
3. Ordering: forced revoke failure leaves the row present and no live tuple; a retry converges.
4. Resolution: the caller's next request resolves elsewhere immediately.
5. Adapter tests: the three surfaces refuse any attempt to name another subject.
6. Dashboard tests from t005 count here; confirm they run in `yarn test`.
