# Docker Hub's anonymous pull limit fails tenant image deploys

Why: since w5/174 any public registry is allowed in every workspace, and Docker Hub is the one most tenants use. A deploy of `docker.io/traefik/whoami:v1.10` in production `bex-canary` failed on 2026-10-27 with "image metadata request returned status 429". bex fetches Docker Hub metadata and pulls anonymously from a few shared egress IPs, so every tenant shares one anonymous quota.

- **Check Render first:** how Render avoids Docker Hub limits for public images (authenticated pulls, a mirror, or a cache). Record the answer in ADR018.
- **Likely fix:**
  - Authenticate bex-api's image metadata reads and containerd's Docker Hub pulls with a platform Docker Hub account, through a pull-through mirror or `hosts.toml` credentials.
  - Or put a pull-through cache in front of `registry-1.docker.io`.
  - Either way, the w5/171 metadata-endpoint deny stays in place.
- **Evidence:** service `qa-m114`, deploy `dep-dbg3m4tn83uc738uud4g`, `deploy_ended.failureReason` "image metadata request returned status 429".
- **Size:** probably more than 1 hour across infrastructure and bex-api, so this may become a milestone.

**DONE 2026-11-04** (`/loopx w5`, already fixed by someone else): `e3e0f9eea` (w4/m243 t008, 2026-10-26 20:22 PDT; live in the 2026-10-27 09:13Z platform pin `4bb1e44e2`) makes a registry 429 a `registry.TransientError` — the deploy stays open as `ImageRegistryRateLimited` and retries on `Retry-After` (30s–5m) instead of failing (`lego/operator/internal/controller/image_network.go` `imageRegistryWait`). The failing `qa-m114` deploy ran ~05:5xZ on 2026-10-27, before that pin. Render check ([deploying-an-image](https://render.com/docs/deploying-an-image)): Render pulls from the registry on every deploy/restart and lists a 429 with three remedies — wait for the limit to reset, use a credential for an account with a higher limit, or mirror the image. bex already has the first two (automatic retry; a workspace docker.io registry credential is used for both the metadata read and kubelet's pull, `externalImageAuthHeader`), recorded in ADR018. The shared anonymous quota across tenants (few egress IPs) is bex-specific hardening, not a parity gap, filed as [w5/177](../blocked/177.md).
