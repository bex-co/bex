# Images from any public registry deploy, as on Render

Why: Render pulls a public image from any registry. bex refuses hosts outside a fixed allowlist (`trustedImageRegistry` in `lego/backend/internal/store/image.go`: docker.io, ghcr.io, quay.io, gcr.io, registry.k8s.io, public.ecr.aws, mcr.microsoft.com, \*.pkg.dev). So Render's own `minio` and `langfuse4-template` templates (images on `cgr.dev`) fail on bex.

- The allowlist is a security control. The kubelet pulls on the node network, outside pod egress policy, and `ValidateImage`'s comment says private and reserved hosts must stay blocked. The parity-sufficient shape keeps the private/reserved-IP and localhost refusals, and accepts any public DNS host. That needs its own security review (DNS rebinding at kubelet pull time is the open question the comment names), so it is too big for a quick fix.
- Likely more than an hour once the review is done; promote to a milestone if so.
- Guard: `knownBlueprintGaps` lists `"is not trusted"` for this note. Remove it when this ships.
- Found by w5/m149's corpus run (2026-10-20): these templates also set `PORT`, which used to stop them earlier.

Closed 2026-10-23 (user decision: Render parity plus a containerd-only link-local deny): `store.ValidateImage` accepts any public registry and refuses the platform's own network names. Every node bootstrap rejects containerd's cgroup traffic to 169.254.0.0/16, re-applied on each containerd start, and `scripts/clusterapi-validate.sh` guards it. Production stays on the allowlist until the node pools roll (w5/174). render-examples: 90 -> 92 of 170 valid.
