## Objective

A missing pod-log source and a missing durable log store each answer their code on REST, GraphQL and MCP, with the same 503 and message as today.

## Acceptance criteria

- [x] Both refusals carry their codes on all three surfaces, and `errors.Is` against the sentinels still holds.

## Result (2026-10-06)

- `core.ErrLogsUnavailable` and `core.ErrLogStoreUnavailable` are coded package sentinels: `LOGS_UNAVAILABLE` and `LOG_STORE_UNAVAILABLE`, built by `NewUnavailableError`. The 503 and messages are unchanged. `errors.Is` still holds, because a sentinel is one pointer.
- The other "not configured" refusals the dashboard branches on got codes the same way:
  - `METRICS_UNAVAILABLE`, used by the metrics charts;
  - `SECRETS_UNAVAILABLE`, used by the env-var, secret-file and env-group editors;
  - `AUDIT_LOG_UNAVAILABLE`, used by the audit log.
- Evidence: `internal/api/refusal_codes_test.go` `TestTheDashboardsRefusalsAreCodedOnEverySurface` pins the code and message on REST, GraphQL and MCP for:
  - the pod-log source;
  - the durable log store;
  - metrics;
  - the secret store;
  - the audit store, on REST and GraphQL only, since it has no MCP tool.
- Mutants: reverting each of the five sentinels to an uncoded one fails its case.
