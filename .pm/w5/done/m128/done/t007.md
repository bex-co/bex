## Result (2026-10-06)

Three review agents (reuse, quality, efficiency) read the whole diff.

Fixed:

- **A regression.** `webhooks.observeResend` counted a denied resend as `"error"`: `ErrForbidden` is now coded, and its code branch ran before the forbidden check.
  - Fix: the class sentinels go first. `metrics_test.go` now pins `denied` (bare and wrapped) and `unavailable`, and the old order fails it.
  - Audit of all 14 `errors.As(…, *CodedError)` sites found no other regression. Three changes are benign:
    - a forbidden row write passes through without the internal `update source of truth:` prefix;
    - a Blueprint's errorDetails names a forbidden refusal `FORBIDDEN`, as its apply does;
    - onboarding would answer a forbidden error with 403, but no path returns one.
- **Tests that could pass for the wrong reason.** The "old wording decides nothing" negatives were plain `Error`s, which the code readers reject on type alone. They are now `uncodedGraphQLError`s carrying the old wording, and three mutants that fall back to the message text fail them.
- **Duplication:**
  - One `classifyRefusal(error, unavailableCode)` in `common/lib/graphql-error.ts` serves the secret store, the audit log and the datastore log viewer. The secret store's binding lives in `features/services/lib/secret-store.ts`.
  - One `isLogStoreUnavailable` in `features/logs/lib/log-store.ts` serves the Logs tab, the deploy logs and the metrics charts. It replaces three spellings of the same decision.
  - One backend check, `core.RequireProtectedConfirmation`, serves both protected guards.
  - The Go tests share `codedRefusal` (REST, GraphQL and MCP assertions), and the resource-name test uses it too. The table's setup hooks shrank to `deny` and `setup`.
- **Smaller fixes:**
  - The takeover, sync-blueprint and editor tests use `codedGraphQLError`.
  - `RefusalKind` replaces a repeated union type.
  - A stale test comment is gone.
  - `ErrAgentSessionsUnavailable` is typed `error` like the other coded sentinels.
  - The "messages are unchanged" claim now names the protected refusal's prefix exception, in the test and in ADR006.

Recorded, not fixed:

- Sharing one test server across rows would save about 0.3s; w5/107 already covers the suite's MCP rebuild.
- A `stringExtension` helper would serve only two sites.
- Older local error builders outside this diff were left alone.
- Reading the refusal's `name` param instead of parsing the phrase moved to w5/111.
- Efficiency was otherwise clean: everything new is on error paths and costs a constant.
