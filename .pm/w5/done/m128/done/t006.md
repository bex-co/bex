## Objective

Check the codes are consistent across REST, GraphQL and MCP. Messages stay byte-identical, so Render CLI output does not change. Record the codes in ADR006's coded-refusal list.

## Acceptance criteria

- [x] Same code and params on every surface; ADR006 lists them.

## Result (2026-10-06)

- **Same code and params on every surface:** `TestTheDashboardsRefusalsAreCodedOnEverySurface` asserts the code, the exact message and every param on REST, GraphQL and MCP for all eight refusal cases. The audit log has no MCP tool.
- **Messages:** byte-identical, with one exception. The protected-environment refusal loses its `bad request: ` transport prefix, which every coded 400 omits (`NewBadRequestError`, as t001 recorded). The explanation and the `confirm="…"` phrase are unchanged, and the dashboard's `refusalReason` already stripped the prefix.
- **Render:** Render's REST error body is `{id, message}` with no `code`, so `code` and `params` are extensions a Render client ignores. Nothing diverges from Render's behaviour.
- **Docs:** ADR006 gains the paragraph "Refusals a client branches on carry codes (w5/m128)", listing every code and its params. ADR018 has no error-envelope row to update.
