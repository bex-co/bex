## Objective

List every place each refusal is made in bex-api and every dashboard decision that substring-matches it, then choose one code per refusal and how each surface carries it.

## Context

- **Backend sources:**
  - `core.ErrLogsUnavailable` and `core.ErrLogStoreUnavailable` are plain `Unavailable(...)` sentinels.
  - `core.ErrForbidden` is a bare error used by every authorization refusal.
  - The protected-environment refusal is built in `core/confirmation.go` and again in `apps/protection.go`.
- **How codes reach clients today:**
  - GraphQL carries `extensions.code` only for a `core.CodedError` (`api/server.go` `sanitizeGraphQLErrors`).
  - REST writes `code`/`params` only for a `CodedError`.
  - MCP prefixes the text with `CODE: ` only for a `CodedError` (`core.MCPError`).
- **Dashboard markers:**
  - `features/logs/hooks/use-log-history.ts`
  - `features/deploys/hooks/use-deploy-logs.ts`
  - `features/metrics/lib/graphql-series.ts`
  - `features/logs/components/datastore-log-viewer.tsx`
  - `common/lib/graphql-error.ts` `isForbiddenError`
  - `features/services/lib/protected-confirmation.ts`

## Acceptance criteria

- [ ] A recorded decision per refusal: its code, its params, and how each surface carries it.
- [ ] The decisions keep every existing `errors.Is` check and message.

## Result (2026-10-06)

All four become `core.CodedError`s. A `CodedError` already reaches every surface: REST writes `code` and `params`, GraphQL flattens the params into `extensions`, and MCP prefixes the text with `CODE: `.

| Refusal | Code | Params | How |
| --- | --- | --- | --- |
| pod-log source missing (`ErrLogsUnavailable`) | `LOGS_UNAVAILABLE` | none | a coded package sentinel, 503 via `ErrUnavailable`; same message |
| durable log store missing (`ErrLogStoreUnavailable`) | `LOG_STORE_UNAVAILABLE` | none | the same |
| forbidden (`ErrForbidden`) | `FORBIDDEN` | none | the sentinel itself is coded. Its message and 403 are unchanged, and `errors.Is` still holds. A more specific forbidden code (`INSUFFICIENT_SCOPE`, `EMAIL_VERIFICATION_REQUIRED`) wraps it and stays outermost. |
| protected environment, no confirmation | `PROTECTED_ENVIRONMENT_CONFIRMATION_REQUIRED` | `confirm`, `verb`, `name` | one constructor in core, used by `core/confirmation.go` and `apps/protection.go`. The message drops only the `bad request: ` prefix, as every coded 400 does. |

Dashboard:

- The three `"durable log store"` markers become `hasGraphQLErrorCode(err, "LOG_STORE_UNAVAILABLE")`.
- `"logs source not configured"` becomes `LOGS_UNAVAILABLE`.
- `isForbiddenError` becomes `FORBIDDEN`.
- `protectedConfirmationFromError` reads `extensions.confirm` from `PROTECTED_ENVIRONMENT_CONFIRMATION_REQUIRED`.
- The panels `isForbiddenError` serves (API keys, webhooks, registry credentials, logs) run on session auth, where the more specific forbidden codes do not arise.
