## Objective

A change to a protected environment's member without the confirmation phrase answers a stable code, with the required phrase and verb as params, from one constructor. Today `core/confirmation.go` and `apps/protection.go` build it separately.

## Acceptance criteria

- [x] Both refusal sites answer the code and params on all three surfaces, with the message unchanged.

## Result (2026-10-06)

- `core.ProtectedEnvironmentConfirmationRequired(name, verb, confirm)` is the one constructor. It returns 400 `PROTECTED_ENVIRONMENT_CONFIRMATION_REQUIRED` with params `confirm`, `verb` and `name`.
- Both sites use it: `core.RequireEnvironmentConfirmation` (Postgres and Key Value) and `apps.requireUnprotected` (services and deploys).
- The message drops only the `bad request: ` prefix, as every coded 400 does.
- Evidence: `TestTheDashboardsRefusalsAreCodedOnEverySurface/protected_service` and `/protected_Postgres` pin the code, message and all three params on REST, GraphQL and MCP. An uncoded mutant at each site fails only its own case.
