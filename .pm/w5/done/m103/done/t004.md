## Objective

Stop inferring ownership from row order. Where a workspace has an owner binding, surface that identity; where it has none (every workspace created through `CreateWorkspace`), keep the oldest-admin fallback but present it as a fallback rather than as ownership.

## Context

- `workspaces.Service.ownerEmail` (`lego/backend/internal/workspaces/service.go:760`) walks `ListTenantMembers` oldest-first and returns the first admin's email — so removing a founding admin silently reassigns the workspace's displayed owner email with no event.
- Only personal workspaces carry `tenants.owner_identity_id` (`internal/store/store.go:748`); `CreateWorkspace` (`internal/store/workspaces.go:44`) leaves it NULL by design.
- Consumers to check before changing the projection: the owners read API (`ListOwners`, `ResolveResourceOwners`), notification recipients, and anything billing-facing (`internal/billing`) that reads an owner email.
- `w5/m101/t005` wants an owner flag on the member view — align the two rather than adding a second notion of owner.

## Steps

1. Inventory every consumer of `ownerEmail` / owner attribution and record what each expects.
2. Resolve the owner from `owner_identity_id` when present; fall back to the oldest admin otherwise.
3. Make the fallback legible on the surfaces that show it (an owner field that is honestly empty or marked derived, rather than a wrong assertion).
4. Expose the owner flag the Team row needs, consistently on REST/GraphQL/MCP.

## Files

- `lego/backend/internal/workspaces/service.go`
- `lego/backend/internal/members/service.go` (the member view's owner flag)
- `lego/backend/internal/store/workspaces.go`

## Acceptance criteria

- [ ] A personal workspace reports its actual owner; removing another admin does not change it.
- [ ] A workspace with no owner binding reports the fallback as a fallback, not as ownership.
- [ ] One notion of owner is shared by the Team row, the owners API and billing-facing reads.
- [ ] Every inventoried consumer still behaves correctly.
