## Objective

Cover the reshaped projections with tests that would actually fail on regression — particularly the invariant that the displayed seat count and the invite refusal are computed from the same set.

## Context

- Real Postgres in CI (`BEX_TEST_DB_URI`) lets a test bind a real API key row and assert the projections directly.
- The drift-guard shape matters more than line coverage here: seat display vs `CanAddMember` is exactly the "two implementations of one formula" case ADR024 calls out.
- Useless-test rules apply.

## Steps

1. Fixture: a workspace with human members (one unresolved), bound API keys, and a known plan cap.
2. Assert the member list, seat usage, invite refusal threshold and Team page count all agree.
3. Assert member mutations against a machine subject are refused and the key still works.
4. Assert owner attribution with and without an owner binding, including that removing another admin does not move it.
5. Add the drift guard tying the seat display to the refusal formula.
