## Objective

Capture the unmodified Render CLI v2.21.0's exact redacted POST and PATCH image payloads and turn the observed production failure into a narrow regression at the OpenAPI-plus-handler boundary before changing the decoder.

## Context

- Production image create with `--image traefik/whoami` reached the handler and failed with `request body contains unknown field "ownerId"`.
- Render's pinned OpenAPI `image` schema requires `imagePath` and nested `ownerId`; both service POST and PATCH reference that schema.
- `lego/backend/internal/apps/rest.go` re-decodes the already OpenAPI-validated body with a strict decoder, but `imageRef` omits `OwnerID`.
- PATCH is strongly implicated by the shared schema/model but was not mutated in production; capture its exact official-CLI wire rather than treating inference as proof.

## Steps

1. Pin and record the official CLI version, then use the existing redaction-safe service parity harness or a local request recorder to capture the exact image portions of create and update payloads.
2. Add exact-wire handler regressions for POST and PATCH, passing through the real OpenAPI middleware and strict request decoder.
3. Prove the OpenAPI layer accepts the CLI fields and localize any remaining rejection to the adapter model.
4. Keep a negative control showing an actually unknown nested image field is still rejected.
