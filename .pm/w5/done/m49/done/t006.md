## Objective

Confirm the fixes match Render's official REST/CLI behavior and keep bex's shared ownership and deletion lifecycle truthful across GraphQL, MCP, and dashboard consumers.

## Context

- `image.ownerId` is a Render REST wire detail; it should map to existing core workspace ownership, not create a second field on other adapters.
- Deletion-in-progress and final absence are shared tenant-visible semantics even though finalizer mechanics are operator-internal.
- `docs/cli-compatibility-checklist.md` currently claims service cleanup converges through `w2/m61`; the 2026-07-20 production observation makes that claim stale until this milestone passes.

## Steps

1. Compare exact image POST/PATCH and DELETE/read-after-delete behavior with Render's pinned OpenAPI and unmodified CLI.
2. Verify REST, GraphQL, MCP, and dashboard expose the same service workspace, image, `Deleting`, and final-absence facts from the shared core model.
3. Keep REST-only owner-shaping out of GraphQL/MCP unless a real consumer contract requires it.
4. Update the parity ledger, CLI checklist, and service-create/update evidence to distinguish schema validation, handler validation, cleanup acknowledgement, and cleanup convergence.
5. File any deliberate or unrelated drift as separate follow-up work rather than silently expanding this milestone.
