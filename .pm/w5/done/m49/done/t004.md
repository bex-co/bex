## Objective

Fix the proven operator/configuration regression so deleting a repo-backed App while its initial build is pending remains idempotent, retryable, observable, and residue-free.

## Context

- `w2/m61` introduced UID-scoped artifact inventory and wait-until-absent finalization; this task preserves those guarantees rather than shortening deletion by skipping cleanup.
- The production sequence is create → first build starts or queues → REST DELETE → store deploy rows disappear → App remains in `Deleting`.
- A pending cleanup stage without enough structured context is operationally indistinguishable from a stalled controller.

## Steps

1. Reproduce the exact timing deterministically with an App that has in-flight or partially-created build artifacts in a separate build namespace.
2. Correct the root cause found in t003, including stale inventory selection, deletion observation, retry/adoption, credential revocation, or deployment configuration as applicable.
3. Emit bounded structured reconciliation evidence naming the cleanup stage and retry cause while preserving secret redaction; do not expose internal cleanup jobs as a new public API.
4. Cover transient failure, operator restart, repeated DELETE/reconcile, and same-name recreation after cleanup.
5. Keep the finalizer until every required artifact class is freshly observed absent.

## Acceptance criteria

- [x] A repo-backed App deleted during its first build reaches Kubernetes absence within a bounded test deadline after all cleanup dependencies are healthy.
- [x] Injected transient cleanup failure or manager restart keeps the finalizer and later converges without residue or duplicate destructive work.
- [x] Build Jobs/Pods/Secrets/ServiceAccounts/NetworkPolicies, kpack objects, registry manifests/credentials, TLS material, and workloads are absent for the deleted App UID.
- [x] Structured logs/events identify a still-pending cleanup stage and retry cause without leaking secret material.

## Out of scope

- Removing the durable finalizer, hiding `Deleting` resources before cleanup, or building a generic workflow engine.
