## Objective

Bring the dedicated Deploys history up to the information density observed on Render: client-side text search over loaded results, an honest loaded/total label, duration, and a stable row hierarchy that uses the metadata already returned by `deploys(serviceId, ...)`.

## Context

- `deploys-list-page.tsx` already renders status, trigger, id, optional commit text, pre-deploy state, and created time, and `use-deploys` already provides keyset pagination.
- The GraphQL selection already carries `commitId`, `commitMessage`, `startedAt`, `finishedAt`, `rollbackOf`, and status fields. This task should not add a duplicate deploy endpoint.
- Rollback mechanics and confirmation behavior already exist from w5/m21/w5/m29; the list must reuse the shared action and its eligibility rules.

## Steps

1. Add a debounced or local text search over loaded deploy id, commit SHA, and first-line commit message; combine it predictably with the existing status filter.
2. Add an honest count label: distinguish “N deploys” only when the complete result is known from “N loaded” while another page exists.
3. Refactor the row into a responsive hierarchy for status, commit/message, trigger, deployed date, duration, and optional pre-deploy state; omit unavailable metadata rather than inserting fake values.
4. Reuse the shared deploy action for rollback-eligible successful historical rows without making the row link and action fight for click/keyboard events.
5. Add English and Chinese strings and focused component coverage for filtering, count semantics, duration, and action eligibility.

## Acceptance criteria

- [ ] Search matches loaded deploy ids, full/short commit SHAs, and commit-message text case-insensitively while the status filter remains active.
- [ ] The count never presents a loaded-page count as a server-wide total when `hasMore` is true.
- [ ] Duration is derived from valid start/finish timestamps and omitted or labeled in progress when no completed interval exists.
- [ ] Only a genuinely eligible historical deploy exposes the existing rollback action; failed/current/in-progress deploys do not.
- [ ] Rows remain fully keyboard-navigable and usable at narrow widths.

## Out of scope

- A new backend total-count field, new rollback mechanics, commit-author timestamp, or synthetic commit metadata.
