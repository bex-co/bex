# Owner lists resolve each workspace's owner email with its own store read and Kratos lookup

Why: w5/116 batched the member lists, but `ListOwners` (GET /v1/owners, the CLI and MCP) still resolves each workspace's owner one at a time. For each workspace it makes one store read for the owner binding and one Kratos admin GET, in sequence, often for the same owner many times. `ResolveResourceOwners` does the same once per distinct workspace on every REST resource list.

- **Where:** `lego/backend/internal/workspaces/service.go` `ListOwners` → `ownerEmail`, and `ResolveResourceOwners` → `ownerEmail`. The comment at `apps/render.go:605` ("at most one query per page") understates this.
- **Fix:**
  - read the workspaces' owner subjects in one store query; `store.Tenant` does not carry them today;
  - resolve them with one `IdentityReader.LookupMany`;
  - keep the oldest-admin fallback and the honest omit.
- **Test:** listing W workspaces makes one owner read and one Kratos request, and a workspace whose owner does not resolve keeps an empty email without falling back to another admin.
- Found by w5/116's reuse and efficiency reviews (2026-10-07).

**Result (2026-10-07):**

- **One store read, one identity lookup.** `store.TenantContactSubjects(ids)` answers each workspace's contact subject in one query: its owner binding, else its oldest user admin, ties broken by subject. `workspaces.ownerEmails(ids)` resolves those subjects with one `IdentityReader.LookupMany`.
  - `ListOwners` resolves every name-filtered workspace at once.
  - So does `ResolveResourceOwners`, which runs on every REST resource list.
  - `ownerEmail` is the one-workspace case, used by the single-owner read and `CurrentUser`'s fallback. Each makes one query, where it used to make one or two.
  - The honest omit is unchanged: a bound owner whose identity does not resolve answers empty, never another admin.
- **Simplify.**
  - `WorkspaceStore` loses `TenantOwnerSubject`, which nothing in `workspaces` read any more. The member guards keep the store method through their own interface.
  - The redundant subject dedupe went, since `LookupMany` already dedupes.
  - The policy doc moved onto `ownerEmails`, and `CurrentUser`'s stale "earliest-admin" doc was fixed.
  - The Postgres test now cleans up its workspaces. A `defer pool.Close()` had run before the deletes, so every run leaked; other store tests share that pattern.
- **Tests.**
  - `TestOwnerListsReadEveryContactAtOnce`: `ListOwners` and `ResolveResourceOwners` each make one contact read and one identity batch. A bound owner answers, an unbound workspace answers its oldest admin, and an unresolvable owner stays empty.
  - `TestPGTenantContactSubjects` on real Postgres:
    - a bound owner answers even beside an older admin;
    - an older machine admin and an older viewer are passed over;
    - the oldest admin sorts last by name, so the creation order decides;
    - a workspace with no admin and an unknown id are absent.
  - Seven mutants each fail a test.
  - The workspaces, api, members and apps suites pass, and `make lint` is clean.
