## Objective

Prove end-to-end through the composed `Server.MCPServer()` that enum validation, union-typed arguments, and `envVars[].generateValue` work as expected on the wire, and record the new schema parity guards in `docs/ADR018-render-parity.md`.

## Context

- Schema-only assertions verify `tools/list`, while composed `tools/call` tests prove the MCP Go SDK's own JSON Schema validator accepts valid Render calls, accepts documented bex extensions (`runtime: "image"`, `version: "16"`, `clearCache: "clear"`, `envVars[].generateValue: true`), and rejects invalid enum/type values cleanly.

## Steps

1. Add composed-server MCP tests in `lego/backend/internal/api/` (or package MCP tests) covering:
   - `create_web_service` with `envVars: [{key: "SECRET", generateValue: true}]` succeeds through MCP SDK validation, while `{key: "SECRET"}` and `{key: "SECRET", value: "a", generateValue: true}` fail.
   - `create_web_service` / `create_cron_job` with `runtime: "image"` (bex extension) and Render runtimes (`"node"`, `"docker"`) pass schema validation, while an unknown runtime (e.g. `"cobol"`) is rejected.
   - `create_postgres` accepts `version: 16` (number) and `version: "16"` (string) and rejects `version: true`.
   - `trigger_deploy` accepts `clearCache: true` (boolean) and `clearCache: "clear"` (string) and rejects `clearCache: 123`.
   - Enum rejection on `list_logs.direction`, `list_log_label_values.label`, `get_metrics.cpuUsageAggregationMethod`, `create_blueprint.existingResources`, and `create_key_value.persistenceMode`.
2. Update `docs/ADR018-render-parity.md` § Types and behavior hints to document the 21-enum schema guard, explicit union types for `version`/`clearCache`, and `envVars[].generateValue` schema fix.
3. Run `npx prettier@3.4.2 --write docs/ADR018-render-parity.md` and `bash scripts/docs-links-validate.sh`.
