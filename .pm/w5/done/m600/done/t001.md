## Objective

Advertise Render's 21 pinned argument enums on the 9 shared MCP tools and replace the untyped `{}` schemas on `create_postgres.version` and `trigger_deploy.clearCache` with explicit union types in `tools/list`.

## Context

- `lego/backend/internal/api/openapi/render-mcp-tools.json` pins 21 `enum`-constrained arguments across 9 shared tools:
  1. `create_blueprint.existingResources` (`adopt`, `create_new`)
  2. `create_cron_job.{autoDeploy, plan, region, runtime}`
  3. `create_key_value.{maxmemoryPolicy, persistenceMode, plan, region}`
  4. `create_postgres.{plan, region}`
  5. `create_static_site.autoDeploy`
  6. `create_web_service.{autoDeploy, plan, region, runtime}`
  7. `get_metrics.{aggregateHttpRequestCountsBy, cpuUsageAggregationMethod}`
  8. `list_log_label_values.{direction, label}`
  9. `list_logs.direction`
- `google/jsonschema-go` v0.4.3 infers plain `string` fields with no `"enum"` constraint, and infers `any` fields (`postgres/mcp.go:65` `Version any`, `deploys/mcp.go:76` `ClearCache any`) as `{}` (no `"type"`).
- **Important compatibility constraint:** The MCP Go SDK validates incoming `tools/call` arguments against `InputSchema` before invoking the handler. Therefore, every emitted `"enum"` MUST be a **superset** of upstream's pinned values that also includes any extra values bex intentionally accepts on MCP:
  - `create_web_service.runtime` / `create_cron_job.runtime`: upstream values + `"image"` (`apps/mcp.go:361`).
  - `list_log_label_values.label`: upstream values + `"build"` (`ADR018` round 8, if accepted by `DiscoverableLabels`).
  - `plan` args (`create_web_service`, `create_cron_job`, `create_key_value`, `create_postgres`): upstream's pinned enum values PLUS any legacy/hyphenated aliases or bex tiers the handler accepts (verify exact accepted sets in each package's plan validator, e.g. `core` / `apps` / `postgres` / `keyvalue`, and avoid breaking existing tests that send hyphenated aliases like `basic-256mb` or `pro_max` or `3g`).
  - `maxmemoryPolicy` / `persistenceMode`: check whether hyphenated forms are accepted in `create_key_value`; include them if accepted, or keep exact accepted spellings.
  - `create_postgres.version`: union `["number", "string"]` (or `anyOf` accepted by `mcp-go` SDK + `jsonSchemaTypes`).
  - `trigger_deploy.clearCache`: union `["boolean", "string"]` (matching `mcputil.BoolOrEnum`).

## Steps

1. Add a clean reusable schema-builder helper in `lego/backend/internal/mcputil/` (e.g. setting `InputSchema` from `jsonschema.For[In]` and mutating property `Enum` / `Types` cleanly without duplicating boilerplate across feature packages, or using `jsonschema.ForOptions.TypeSchemas` with named Go types).
2. Wire the 21 enum constraints across `apps`, `keyvalue`, `postgres`, `metrics`, and `logs` MCP tool registrations, ensuring each enum is derived from or drift-checked against the package's accepted values and is a superset of upstream's pinned enum.
3. Wire explicit union schemas (`["number", "string"]` and `["boolean", "string"]`) for `create_postgres.version` and `trigger_deploy.clearCache`.
4. Verify all existing unit tests in `apps`, `keyvalue`, `postgres`, `deploys`, `metrics`, `logs`, and `api` continue to pass (no existing valid call rejected by overly narrow enums).
