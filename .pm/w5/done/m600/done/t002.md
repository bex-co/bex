## Objective

Remove leaked struct-tag directives (`required,`, `,enum=...`) from `jsonschema` tags across all MCP tools, and make `envVarInput.Value` optional in MCP JSON Schema so `{key, generateValue: true}` passes SDK input validation.

## Context

- `google/jsonschema-go` v0.4.3 treats the entire `jsonschema:"..."` struct tag value as the property's `description` string rather than parsing comma-separated directives.
- Verified leaks in production schemas:
  - `lego/backend/internal/apps/blueprint_onboarding.go:862`: `,enum=adopt,enum=create_new` appended to description text.
  - `lego/backend/internal/events/mcp.go:94`: `required,the evt-… id...`.
  - `lego/backend/internal/webhooks/mcp.go:63-65`: `required,the webhook endpoint id...`, `required,the failed or delivered attempt id...`, `required,8 to 128 safe characters...`.
  - Audit all other `jsonschema:"..."` tags in `lego/backend/internal/` for any remaining `required,`, `,enum=`, `enum=`, `omitempty`, or similar leaked directive syntax.
- `lego/backend/internal/apps/render.go:34-43` defines `envVarInput`:
  - `Value string` has `json:"value"` (no `omitempty`), causing `jsonschema-go` to emit `"required": ["key", "value"]` on `envVars.items`.
  - `envVarInput.UnmarshalJSON` already tracks `ValueSet bool` explicitly to enforce the oneOf rule (`value` XOR `generateValue`) in `toEnvVars`. Adding `omitempty` to `Value` (`json:"value,omitempty"`) only affects schema inference (making `value` optional in JSON Schema) and does not affect `UnmarshalJSON` or `ValueSet` (double-check any serialization callers of `envVarInput` to confirm none rely on marshaling an empty `Value: ""` via `envVarInput` — `envVarInput` is an input-only struct).
  - Note: Render's upstream MCP server (`a18ef3ee`) does not expose `generateValue`; this repairs bex's own REST↔MCP extension schema-vs-handler mismatch while keeping `{key, value}` calls identical.

## Steps

1. Search all `jsonschema:"..."` tags under `lego/backend/internal/` for leaked directive tokens (`required,`, `,enum=`, `minimum=`, `maximum=`, `default=`, etc.) and clean them into plain English descriptions (note: non-omitempty struct fields are already inferred as required by `jsonschema-go`).
2. Check every reference to `envVarInput` across `lego/backend/internal/apps/` (and any other package) to confirm adding `omitempty` to `Value` breaks no marshaling assumptions, then update `lego/backend/internal/apps/render.go:36` so `envVars[].value` is optional in MCP JSON Schema while `toEnvVars` continues rejecting entries with neither `value` nor `generateValue` or with both.
3. Verify `apps/mcp` tests (including `create_web_service`, `create_cron_job`, `create_static_site`) pass with both `{key, value}` and `{key, generateValue: true}`.
