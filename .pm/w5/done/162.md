# Native Ruby gets Render's remaining runtime defaults

Why: a Rails app moved from Render can 404 its CSS/JS and never send its app log lines to the Logs tab on bex, because bex sets only `RAILS_ENV` and the Bundler variables while Render also sets the variables Rails' `production.rb` keys static serving and stdout logging on.

- **Gap:** `nativeBuildDefaults`'s Ruby case (`lego/operator/internal/build/native.go:360-363`) supplies `RAILS_ENV=production` and `BUNDLE_DEPLOYMENT`/`BUNDLE_PATH`/`BUNDLE_BIN` only, and `nativeRuntimeDefaults` (`native.go:368-379`) supplies nothing for Ruby. Render's [default environment](https://render.com/docs/environment-variables) also gives a Ruby service `RAILS_SERVE_STATIC_FILES=true`, `RAILS_LOG_TO_STDOUT=true`, `MALLOC_ARENA_MAX=2` and `PIDFILE=/tmp/puma-server.pid`. `w8/done/114.md:49` recorded these as "not supplied", and no item picked them up. `docs/ADR060-build-worker-reliability-and-performance.md:355` still lists the Bundler paths as missing, which is stale (w8/117 added them).
- **Fix:** first re-confirm the exact list and values against render.com/docs/environment-variables and record the fetch date. Then add them as runtime image ENV in `nativeRuntimeDefaults`, after the build RUN, so they yield to every value the service configures (literal, linked group, explicit empty), as Node's `NODE_ENV` does (w8/111). Add any that Render documents as build-visible to the build defaults instead. Primary Ruby images only; no other runtime gets them.
- **Test:** extend `TestNativeRubyImageRailsEnvironment` (`lego/operator/internal/build/nativeruntimeenv_test.go:301`) so the running Rails app reports each default, and a service value (including an explicit empty one) overrides it. It must fail on the old image. `make test` and `make lint` green.
- **Docs:** fix ADR060:355 (Ruby's runtime defaults now match Render; drop the stale Bundler note).

2026-10-20: **DONE** (w5 loopx). Render's Ruby list re-fetched today: build and runtime alike. The native Ruby image now adds `RAILS_SERVE_STATIC_FILES=true`, `RAILS_LOG_TO_STDOUT=true`, `MALLOC_ARENA_MAX=2`, `PIDFILE=/tmp/puma-server.pid`, `PASSENGER_ENGINE=builtin`, `PASSENGER_ENVIRONMENT=production` and `BUNDLE_APP_CONFIG` next to `RAILS_ENV` and the Bundler settings (`build/native.go`). Two are deliberately not set: `PASSENGER_PORT` (Render pins its own default port, bex uses `PORT`) and `GEM_PATH` (it hides Ruby's bundled gems: `rake --version` failed with it on the pinned image). `TestNativeBuildDefaultsPrecedeTheBuild` covers placement. `TestNativeRubyImageRailsEnvironment` ran on a real Rails 8 app (`BEX_BUILDKIT_INTEGRATION=1`, 163 s): the defaults reach the app, a service's explicit empty value wins, and `rake` stays reachable. ADR060 updated.
