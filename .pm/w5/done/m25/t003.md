## Objective

Give users the write-side controls: create a new Environment within a Project, rename it, delete it, and assign/unassign a service to/from it — mirroring the existing Project dialog patterns.

## Context

- Mirror `dashboard/src/features/projects/components/new-project-dialog.tsx` and the "Move to project" row action (`move-to-project-menu.tsx`) for the equivalent Environment actions.
- Mutations from t001 (`createEnvironment`/`renameEnvironment`/`deleteEnvironment`/`setEnvironmentServices`).

## Steps

1. Add `new-environment-dialog.tsx` (create, scoped to a parent Project) and a rename inline-edit / delete confirm (mirror project's danger-zone pattern).
2. Add a service row action "Assign to environment" (segmented menu like `move-to-project-menu.tsx`) calling `setEnvironmentServices`.

## Files

- `dashboard/src/features/environments/components/new-environment-dialog.tsx`
- `dashboard/src/features/environments/components/assign-to-environment-menu.tsx`
- `dashboard/src/features/environments/components/environment-danger-zone.tsx` (rename/delete)

## Acceptance criteria

- [ ] Creating an Environment from a Project's page immediately shows it as a new group.
- [ ] Assigning a service via the row action moves it into the target Environment's group without a full page reload.
- [ ] Deleting an Environment moves its services back to "Ungrouped", not deleting the services.

## Out of scope

- Empty/loading/error states (t004).
