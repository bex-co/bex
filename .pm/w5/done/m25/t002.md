## Objective

Render Environments as a grouping layer inside the existing Project unified page: services assigned to an Environment show grouped under it (e.g. staging/production), with an "Ungrouped" bucket for project services with no environment, reusing the existing resource-table rendering.

## Context

- Existing unified page: `dashboard/src/routes/index.tsx` + `dashboard/src/features/projects/components/project-section.tsx` + `resource-table.tsx`.
- Environments are services-only (no Database/KeyValue membership) per `docs/ADR032-environments.md` — the grouping only applies to the services subset of a project's resource table.
- Hooks from t001.

## Steps

1. Extend `project-section.tsx` (or a new `environment-section.tsx` nested under it) to partition a project's services by `environmentId`, rendering one `resource-table.tsx` per Environment plus one for unassigned services.
2. Add a lightweight Environment label/badge on grouped service rows.

## Files

- `dashboard/src/features/projects/components/project-section.tsx`
- `dashboard/src/features/environments/components/environment-section.tsx` (new)
- `dashboard/src/features/projects/hooks/use-grouped-resources.ts` (extend grouping logic)

## Acceptance criteria

- [ ] A project with 2 environments and unassigned services renders 3 distinct groups (env A, env B, ungrouped) with correct service placement.
- [ ] Component test covers the grouping logic with a project fixture spanning all three buckets.

## Out of scope

- Create/rename/delete dialogs (t003).
