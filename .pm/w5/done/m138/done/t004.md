## Objective

The database page's HA panel lets a tenant add a named read replica and remove an existing one, with the same eligibility rules and refusal messages the API gives, instead of only listing replicas.

- Follow `dashboard/AGENTS.md` (Apollo mutation patterns, both locales, skeleton rule if any pending state changes).

## Steps

1. Add an "Add read replica" action (name input, client-side name check mirroring the API) calling the t002 mutation; disable it with the API's reason when the plan or storage does not qualify or the limit is reached.
