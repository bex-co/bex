## Objective

A replica-set change and a disk-autoscaling toggle are recorded and announced like the other Postgres settings: one audit effect each, delivered as Render's `postgres_read_replicas_changed` and `postgres_disk_autoscaling_enabled_changed` webhook events and shown in the Events feed.

## Context

- `lego/backend/internal/core/audit.go:758-787` — `RecordDatabaseHighAvailabilityChanged` and the pooler effect are the pattern; `AuditVerbPostgresHAChanged`/`AuditVerbPostgresDiskSizeChanged` sit near `:237-239`.
- `lego/backend/internal/postgres/service.go:1214` — PATCH writes `spec.DiskAutoscaling` but records no effect.
- `lego/backend/internal/eventvocab/datastore.go` and `lego/backend/internal/webhooks/service.go:123` — `postgres_read_replicas_changed` is marked unsupported there.
- `lego/backend/internal/postgres/webhook_effects_test.go:292-302` — the guard that fails once `PostgresPatch` gains `ReadReplicas`; it tells you to advertise the event.
- The dashboard webhook event picker reads the catalog from the API; check it shows the new keys without a UI change.

## Steps

1. Add audit verbs and `Record…` effects for a replica-set change (before → after names) and a disk-autoscaling toggle; call them only after a successful, changed write (a no-op PATCH records nothing).
2. Advertise both keys in the event vocabulary and the webhook catalog; replace the absence guard with positive tests.

- [ ] Changing the replica set delivers exactly one `postgres_read_replicas_changed`; an unchanged set delivers none.

- [ ] Both keys appear in the webhook catalog on REST, GraphQL and MCP.
