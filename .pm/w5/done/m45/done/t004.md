## Objective

Verify the post-create policy through real browser navigation for representative standalone, contextual, and one-time-secret flows, and turn the results into durable evidence rather than relying only on component behavior.

## Context

- The known Render Postgres success path redirects to `/d/{dpg-id}` while provisioning continues.
- Services, Postgres, Key Value, Projects, Environment Groups, workspace selection, webhooks, and API keys exercise the distinct outcome classes.

## Steps

1. Run representative successful creates for each outcome class at desktop and narrow-screen widths and record the final URL and visible state.
2. Exercise at least one rejected create to prove the route does not change and the error remains actionable.
3. Confirm provisioning detail pages tolerate the creating state and continue polling to their eventual state.
4. Update `docs/render-artifacts/post-create-landings.md` with dated bex evidence and remove all temporary resources.
