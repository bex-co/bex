## Objective

Make every standalone resource created from the dashboard navigate immediately to its most useful canonical detail or deploy route using the id returned by the successful mutation, without disrupting provisioning or cache refreshes.

## Context

- `CreateDatabaseDialog` already returns the new `dpg-*` id, but `dashboard/src/routes/index.tsx` currently discards it and only refetches lists.
- Service creation already prefers `/services/$serviceId/deploys/$deployId` when a deploy id is returned and otherwise uses `/services/$serviceId`.
- Key Value, Project, and Environment Group create paths already navigate to their detail routes; they still belong in the contract and regression matrix.
- Workspace creation has no standalone detail route, so the correct outcome is selecting the new workspace and returning to its home context.
- Render-shaped inbound aliases remain compatibility redirects from w5/m39; internal navigation stays on canonical bex routes.

## Steps

1. Fix each mismatch identified by t001, beginning with the Postgres overview callback, while retaining required list/cache refetches.
2. Use only the mutation's returned immutable resource and deploy ids; do not reconstruct ids from names or URLs.
3. Sequence modal/search-param cleanup and final navigation so an intermediate close navigation cannot overwrite the detail destination.
4. Ensure rejected mutations leave the user on the form with actionable error state and never navigate.

## Files

- `dashboard/src/routes/index.tsx`
- `dashboard/src/routes/services.new.tsx`
- `dashboard/src/routes/keyvalue.new.tsx`
- `dashboard/src/routes/env-groups.tsx`
- `dashboard/src/routes/new.workspace.tsx`
- Other standalone create routes identified by t001

## Acceptance criteria

- [x] Successful Postgres creation lands on `/databases/{returned-dpg-id}` while the resource is still provisioning.
- [x] Service, Key Value, Project, Environment Group, and Workspace outcomes match the t001 contract without name-derived identities.
- [x] Existing refetches and workspace selection still occur where needed.
- [x] Failed creation never changes the route.

## Out of scope

- Adding detail pages, changing backend create-response shapes, or changing Render alias routes.
