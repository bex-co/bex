## Objective

Check the completed landing contract against Render and against bex's REST, GraphQL, and MCP create responses, documenting deliberate differences and filing any newly discovered capability gap.

## Context

- This milestone changes dashboard behavior but relies on immutable ids returned by bex-api's shared create core.
- Render uses resource-shaped dashboard destinations such as `/d/{dpg-id}` and `/r/{red-id}`; bex keeps canonical internal routes and accepts Render aliases through w5/m39.
- Secret-bearing flows may deliberately differ where bex enforces mint-once retrieval.

## Steps

1. Verify that REST, GraphQL, and MCP create surfaces expose the identities needed by every dashboard landing covered by the milestone.
2. Compare final dashboard outcomes with current official Render documentation and captured live evidence.
3. Update ADR018 and the evidence matrix with shipped parity, deliberate drift, and separately sized follow-ups.
