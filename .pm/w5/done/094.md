# Check a custom host against one claimed-host set, not every App's hosts

Why: every claimed host is checked by walking every App in the cluster and running a public-suffix lookup per stored host, which grows with the platform rather than the request.

- **Today:** `hostClaimedInApps` (`lego/backend/internal/apps/domains.go`) loops over the memoized cluster-wide App list for each host checked. It builds a host slice per App and calls `wwwSibling` (a public-suffix lookup) on every stored host. A create checks its hosts in the plan and again at the write.
- **Measured:** about 0.54 ms and 3,000 allocations per checked host at 1,000 Apps (benchmark in the w5/m121 efficiency review).
- **Fix:** build, once per request beside `allApps`, a map from each claimed host and its www/apex sibling to the claiming App's identity (`appClaimIdentity`); a check is then one lookup that skips the owner's own claims. Keep the defensive `normalizeHostname` of stored values.
- **Test:** the existing collision tests (`hostClaimedElsewhere`, the cross-tenant host tests) stay green; add one for a sibling claimed by another App.
- **Size:** about 30 minutes. Found by w5/m121's efficiency review.

## Done (2026-10-06)

- Host checks now use one index of the platform's host claims, `hostClaimIndex`, built once per request and memoized.
  - Each normalized stored host maps to the App storing it, or to a "contested" marker when several Apps store it.
  - A check looks up the host and its www/apex sibling, skipping the owner's own claims.
- `wwwSibling` is its own inverse for every pair an App can claim, so a sibling lookup at check time matches the old "stored host's sibling equals the query" scan.
  - The efficiency review compared both against the whole public-suffix list.
  - The only divergences are unclaimable `www.` forms that are themselves public suffixes, such as `www.kawasaki.jp`.
- Measured at 1,000 Apps with 2 hosts each:

  | | Time | Allocations |
  |---|---|---|
  | Old, per checked host | ~0.54 ms | ~3,000 |
  | Index build, once per request | ~0.13 ms | ~1,000 |
  | Lookup | 23–200 ns | 0–1 |

- Three paths now share one index per request instead of listing every App per check: `AddDomain` (primary and auto-paired sibling), the Blueprint apply preflight, and a stack update of an existing service.
- A maintenance URI whose host canonicalizes to nothing (`http://./`) is refused as not an absolute URL. It used to be checked as a host, with an answer that depended on unrelated Apps.
- Tests:
  - `TestHostClaimsIndexAHostAndItsSibling` covers exact host, sibling both ways, `spec.host`, a host shared with Apps listed before and after the owner, a legacy unnormalized value, a deep subdomain reserving no apex, owner exemption, and an identity-less claimant.
  - The empty maintenance host is pinned.
  - The REST, GraphQL and MCP sibling-conflict tests are unchanged and green.
  - 8 mutants, each killed.
