# A Blueprint's resources leave out services and datastores still in the shared namespace

Why: `resolveBlueprintResourcesFromIR` (`lego/backend/internal/apps/blueprint.go`) lists Apps, Databases and Key Values only in the workspace's own hosting namespace (`InNamespace(s.AppNamespace(tenantID))`). `core.DatastoreNamespaces` says un-migrated datastores still live in the shared apps namespace (ADR043 D8), so a Blueprint whose resources were not migrated reads with them missing from `resources[]`, and its dashboard page does not list them.

- Every other Blueprint path lists cluster-wide by tenant label (`listWorkspaceDatabases` / `listWorkspaceKeyValues` via `DatastoreListOptions`, and the ownership preflight's App list), and folds mid-cutover twins (`core.DedupDatabaseTwins`).
- **First, check the premise:** does any production workspace still have an App, Database or Key Value in the shared namespace (`docs/runbooks/datastore-namespace-cutover.md`)? If none does, record that and close this as a latent mismatch only.
- **Fix:** list the same way the apply does (`listWorkspaceDatabases`, `listWorkspaceKeyValues`, and the tenant-labelled App list), which also folds twins.
- **Test:** a Blueprint whose Postgres lives in the shared namespace reads it in `resources[]`, once even with a twin in the tenant namespace.
- Found by w5/114's reuse review (2026-10-07).

**Result (2026-10-07):**

- **Premise check.** No production workspace is affected today. On 2026-09-05 a cluster-wide Database listing held only the three tenant-namespace forum Databases (`.pm/w7/done/040.md`): w7/m77 cut over the only tenant with shared-namespace datastores, and the old instances were retired. The mismatch was still real for the next cutover and for a self-hosted install upgrading past ADR043 D8, and the fix was small, so it shipped rather than closing as latent only.
- **The read lists as the apply does.** `resolveBlueprintResourcesFromIR` lists each kind the manifest declares by tenant label across namespaces.
  - Databases and Key Values go through `listWorkspaceDatabases` and `listWorkspaceKeyValues`, which fold twins to the copy in the workspace's own namespace.
  - Apps go through a new `listWorkspaceApps`. It keys them by public name with the same twin rule (`core.AppInOwnWorkspaceNamespace`), so a legacy bare-named App and its store-managed twin read as the live copy.
- **The ownership check uses the same App list.** Its last-write-wins fallback could take a stale twin's Blueprint label and report a false conflict when no claim row exists.
- **Simplify.**
  - The read no longer lists a kind the manifest does not declare.
  - The test runs with the shared namespace sorting both before and after the workspace's. One fixed order let last-wins and an undeduplicated list pass.
- **Tests.**
  - `TestABlueprintReadsResourcesOutsideItsWorkspaceNamespace` covers both namespace orders. It reads shared-only Apps, Postgres and Key Value, and reads App and Postgres twins as the live copy. Another workspace's same-named Key Value stays out.
  - `TestAnOwnershipCheckReadsAnAppTwinsLiveCopy` checks that a stale twin listed last raises no conflict.
  - Six mutants each fail a test.
  - The apps suite passes, and `make lint` is clean.
