# An invalid `?type=` survives the create route's search validator

Why: TanStack sets `match.search = {...raw, ...validated}` (`router-core/dist/esm/router.js:688-691`). The validator omits an invalid `type` instead of returning `undefined`, so the raw value survives and every reader of `Route.useSearch()` needs its own guard; w4/182 added one.

Source: Last-24h code review, 2026-10-05 (user handed all fixes to w5). Follow-up to `1d331d334` (w4/182).

## Fix

1. `dashboard/src/features/services/lib/create-context.ts:104-108` `parseNewServiceSearch`: replace the conditional spread `...(isServiceType(search.type) ? { type: search.type } : {})` with an explicit `type: isServiceType(search.type) ? search.type : undefined`.
2. Delete the w4/182 guard and its comment in `dashboard/src/features/services/hooks/use-new-service-form.ts`.
3. Test: `/services/new?type=bogus` opens the default wizard, and `Route.useSearch().type` is `undefined`.

Done: no reader sees an invalid `type`; route tests green.

## Outcome (2026-10-06)
