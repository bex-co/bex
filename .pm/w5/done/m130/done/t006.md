## Objective

Check the new codes are consistent across REST, GraphQL and MCP, and against Render's error behavior for the same refusals. Record any drift as follow-up work.

## Acceptance criteria

- [ ] Each code is identical on the three surfaces; any Render drift is filed.

**Result (2026-10-07):** `api/refusal_codes_test.go` pins each code identically on REST, GraphQL and MCP. The exceptions: the shell refusal has no MCP tool, SSH keys are pinned in `sshkeys_surface_test.go`, and last-admin is pinned in the members unit tests and the REST end-to-end test.

The REST envelope keeps Render's `{id, message}` and adds `code` and `params`, which Render clients ignore. Coded refusals drop their sentinel prefix, as every coded error does: `bad request: ` from the workspace cap and last-admin, `conflict: ` from the SSH key. MCP's text gains a `CODE: ` prefix for not-found and the GitHub and shell refusals.

Render has no equivalent codes. Its own refusals for the same cases are plain 404/409/400 messages, which these keep, so there's no drift to file.
