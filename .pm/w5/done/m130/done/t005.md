## Objective

Every decision t001 lists branches on the code, and the protected-confirmation dialog takes the resource name from the refusal's `name` param.

## Steps

1. Switch each decision to `hasGraphQLErrorCode` / `graphQLErrorExtensions` (or the REST equivalent where the call is REST).
2. Pass `{confirm, name}` through `ProtectedActionResult` and the protected-retry hooks; drop `protectedServiceName`'s regex.
3. Convert the tests to `codedGraphQLError`, adding a negative case for the old wording.

**Result (2026-10-07):**

- **Missing resources.** `isNotFoundError` moved to `common/lib/graphql-error.ts` and decides by code: `NOT_FOUND`, or a feature's own `*_NOT_FOUND`. Every such code wraps the shared sentinel, and each existing one names a missing resource. A transport 404 is not a missing resource, because bex-api answers one with 200 plus a coded error. So a proxy 404 keeps the Retry card; only the log viewer still treats a 403/404 status as denied.
- **The other decisions.**
  - `logReadAccessDenied` lost its regex.
  - Both rename hooks use `isNameConflictError`. `CONFLICT` has meant a taken name since w6/m49, so the datastores keep that code.
  - The SSH key, the three create hooks (through `workspaceCapMessage`), both team hooks, git and the shell decide by `hasGraphQLErrorCode`.
- **Agent sessions.** The legacy `/not configured/` fallback and `AgentSessionsUnavailableError` are gone, because the coded `AGENT_SESSION_NOT_CONFIGURED` path already showed the unavailable copy.
- **Protected retry.** `protectedRefusalFromError` reads the refusal's `confirm` and `name` in one lookup; `name` falls back to the phrase. `withProtectedRetry` passes the name to `AskForConfirmation`, and the provider and the Blueprint dialog show it. The `protectedServiceName` regex parser is gone.
- `graphQLErrorCodes` is shared with the invite-redemption classifier.
