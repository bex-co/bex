**Worker:** worker5 **Goal:** a new "Build & Deploy" section on the service Settings tab showing Repo/Branch/Root Directory, wired to the `rootDir` field `w1/m18` adds — so setting a monorepo subdirectory is a dashboard flow instead of a curl/MCP-only capability. **Status:** done (2026-07-10)

## Render reference (captured live 2026-07-10, srv-cr1aprdds78s739qrbg0)

- **Settings page** → **Build** heading (separate from **General**'s Name/Region/Instance Type, and **Deploy**'s Pre-Deploy/Start Command/Auto-Deploy/Deploy Hook): **Source** (repo URL, read-only + edit-pencil), **Branch** (searchable combobox + edit-pencil), **Root Directory _Optional_** (plain textbox + edit-pencil; helper text: "If set, Render runs commands from this directory instead of the repository root. Additionally, code changes outside of this directory do not trigger an auto-deploy. Most commonly used with a monorepo."), **Build Command** (shows the resolved `<rootDir>/ $` prompt prefix inline), **Git Credentials**, **Build Filters** (Included/Ignored Paths — bex non-goal, no `spec.buildFilter` field). Screenshot: `.playwright-mcp/render-build-deploy-settings.png`.
- **bex deltas, deliberate:** Render edits each field independently (click the pencil → inline edit → its own save); bex's Settings tab instead follows `w5/m7`'s plan-picker confirm-dialog pattern (view → Edit → confirm dialog warning of a rebuild → mutation → toast) since a Root Directory change triggers a rebuild, the same rollout-cost class as a plan change. Repo/Branch are shown read-only (fixed at create, no bex `PATCH` support for them yet — out of scope here); only Root Directory is editable. No Build Filters/Git Credentials/Build Command/Deploy section fields — those have no `spec` field yet and are future milestones.
