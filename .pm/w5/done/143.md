# A Blueprint apply links a new service's env groups twice

Why: creating a service already links its `fromGroup` env groups (`WithInitialEnvGroups` in the create path). The apply's link loop then links them again, so each group costs one more `AuthorizeApp` list, a group-store scan, a group fetch and a fresh OpenFGA check, all to reach the no-op path.

- **Where:** `lego/backend/internal/apps/deploy.go` `applyStackServices` runs the `LinkEnvGroup` loop for every service with group links. `service.go` `materializeNewApp` already linked them through `WithInitialEnvGroups`, and `envgroups/service.go` returns early for an existing link.
- **Fix:** skip the link loop for a service this pass created. A service absent from the request's `appsByName` was created, so the guard is exact.
- **Test:** a deploy that creates a service with `fromGroup` links each group once. Three tests that rely on the fake's link log need updating: `TestDeployStackAppliesEnvGroupsLinksAndSeeds`, `TestDeployStackFromGroupPreexistingGroup` and `TestBlueprintEmptyEnvironmentSerializedReapply`.
- Found by w5/m133's efficiency review (2026-10-07).

## Result (2026-10-07)

- **Fix:** `applyStackServices` links a service's `fromGroup` groups by name only when the service existed before the apply. A service absent from the apply's `appsByName` is created, and `materializeNewApp` already links its groups through `WithInitialEnvGroups` as it is written, with the store on or off, or the create fails. A listed service that vanished before its fresh read is created and then relinked, which is harmless.
- **Tests:** the fake's `WithInitialEnvGroups` now records its links, after the creation completes, in the same log as `LinkEnvGroup`. So `TestDeployStackAppliesEnvGroupsLinksAndSeeds`, `TestDeployStackFromGroupPreexistingGroup` and `TestBlueprintEmptyEnvironmentSerializedReapply` assert each group is linked once. `TestTheApplysLaterVerbsReachTheServiceItWrote` expects a link by name only for the updated service, and the created worker's link as it was written. All four fail against the shipped loop.
- **Review:** the reviewer confirmed with the real `envgroups.Service` and the store off that a create links its groups with no `LinkEnvGroup` call.
- **Gates:** backend `go test ./...`; `make lint`.
