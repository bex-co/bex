# Billing, payment-gate, sandbox-exec and Postgres-CA refusals carry their dependency's error text

Why: w5/112 stopped the metrics reads from sending a failed lookup's text inside METRICS_UNAVAILABLE. Eleven more sites in five files wrap a dependency's error into a public unavailable sentinel with `%v`. `core.WriteErr`, GraphQL and MCP then send that text to the client: provider responses, store errors that can name a database host, and stream errors that can name internal addresses.

- **Sites** (`fmt.Errorf("%w: %v", core.Err…Unavailable, err)` or a near variant):
  - `lego/backend/internal/billing/service.go`: three in `Status` (provider readiness, onboarding and lifecycle reads), plus the hosted-session provider error near line 278, which already logs its cause;
  - `lego/backend/internal/billing/payment_gate.go:47`: "read payment-method marker", a store error;
  - `lego/backend/internal/workspaces/service.go:420, 448, 488, 504`: workspace-creation billing setup, verify and contract calls;
  - `lego/backend/internal/sandbox/exec.go:422`: "sandbox exec stream failed";
  - `lego/backend/internal/postgres/service.go:919`: a malformed server CA's parse error.
- **Not a leak:** `agentsession/model.go:298`. Its internal HMAC endpoint writes only the status text (`serveSignedMint`), and `TestModelMinterFailsClosedOnStoreError` pins the classification (checked in w5/112).
- **Fix:** log the cause and return the refusal without its text. For each site, decide between two answers:
  - keep the code and drop the text. A billing provider outage is "unavailable", and the dashboard decides by `BILLING_UNAVAILABLE`.
  - return the error unclassified, so it is logged and answered as "internal error", as w5/112 did for a failed router lookup.
- **Test:** each site's failure answers a message without the dependency's text on REST, GraphQL and MCP, and keeps its code where the code stays.
- Found while closing w5/112 (2026-10-07).

**Result (2026-10-07):**

- **One helper.** `core.HideCause(refusal, cause)` logs the cause server-side and returns the refusal alone. It does not wrap the cause, so `errors.Is` and `errors.As` see only the refusal, and it does not log a canceled request.
- **The eleven sites keep their status and drop the text.**
  - Billing fails closed as one unit, so every billing site answers `billing integration unavailable` (503):
    - billing status's provider readiness, payment-method marker and lifecycle reads;
    - the hosted-session provider error;
    - the paid-intent gate's marker read;
    - workspace creation's payment setup, its resume, the verification and the contract.
  - The note's first option assumed a `BILLING_UNAVAILABLE` code, but none exists. These refusals are uncoded, so "keep the code" here means keep the sentinel's fixed sentence and its 503. `onboardingRequired` already documented a marker failure as the same refusal as the rest of status, so store failures did not become 500s.
  - An exec stream that breaks mid-command answers `sandbox runtime not configured: sandbox exec stream failed`.
  - A malformed Postgres server CA answers that it is malformed, without the parse error.
  - Each logged cause names its read or call, and workspace creation names the workspace.
- **Left alone on purpose.**
  - `classifyProviderError`'s 400 and 409 branches carry bex's own input and state sentences.
  - The exec gateway's error-event message is the gateway's own fixed sentence; `TestBufferExecReadsPinnedAndTransitionalShapes` pins it.
- **Simplify.**
  - Billing status no longer logs a marker failure twice: the payment gate's already-hidden refusal passes through.
  - `ErrBillingUnavailable`'s doc covers store failures.
  - The three-surface test moved to the api package's `codedRefusal`, which also runs the real GraphQL sanitizer.
- **Tests.**
  - `api.TestABillingFailureAnswersWithoutItsCause`: REST, GraphQL and MCP answer the bare sentence, and the provider is asked on each surface.
  - `TestABillingStatusFailureAnswersWithoutItsCause`: the three reads, through the real payment gate, each log the cause exactly once.
  - Also: the hosted-session failure, the payment gate's message, the four workspace-creation calls, a stream that fails mid-exec, the CA parse text, and `HideCause`'s logging including the canceled case.
  - Fourteen mutants each fail a test.
  - The core, billing, workspaces, sandbox, postgres and api suites pass, and `make lint` is clean.
- **Follow-up:** w5/131. The ssh-gateway's sandbox-files endpoint writes any executor error's text to the client.
