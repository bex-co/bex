# A failed router lookup answers "metrics source not configured" with the lookup's internal error text

Why: three metrics reads wrap a failed `TraefikRouterNames` lookup as `core.ErrMetricsUnavailable`. A transient Kubernetes error therefore reaches clients as a 503 `METRICS_UNAVAILABLE` that carries the internal error text. Since w5/m128, the dashboard also shows "Metrics source not configured" for it.

- **Sites:** `lego/backend/internal/metrics/service.go` wraps the lookup with `fmt.Errorf("%w: %v", core.ErrMetricsUnavailable, err)` in three reads:
  - request metrics;
  - month-to-date bandwidth;
  - metric filter values.
- **The leak:** `core.WriteErr` writes `err.Error()`, so the REST body reads `metrics source not configured: resolve Traefik routers: get Ingress <ns>/<name>: <Kubernetes error>`. GraphQL and MCP carry the same text.
- **Same shape elsewhere:** `agentsession/model.go` wraps a failed model-key read into `core.ErrSecretsUnavailable` with `%v`.
- **Fix:** log the cause and return a refusal without its text.
  - Decide whether a Running App's missing Ingress is "unavailable" or an internal fault.
  - Keep metering's rule: fail closed rather than charge another App's bytes.
- **Test:** a failing router lookup answers a message without the lookup's text, on every surface.
- Found while checking w5/m128's metrics code (2026-10-06).

**Result (2026-10-07):**

- **Metrics reads.** The three reads (request and bandwidth metrics, month-to-date bandwidth, a static site's status-code filter values) return a failed router lookup unclassified, so the cause is logged.
  - The client gets an uncoded `internal error` on REST (500), GraphQL and MCP, never METRICS_UNAVAILABLE or the Kubernetes text.
  - The source is configured, so the failure is the platform's, not a missing backend.
  - The reads still fail closed: no source runs without the App's routers.
- **A missing Ingress is legitimate when the App has no public hosts.** The router lookup expected an Ingress whenever an App was exposed. The operator keeps one only while the App has hosts. A service whose subdomain was disabled and whose last custom domain was then deleted (nothing guards that delete) has none.
  - The lookup now asks `AppSpec.HasPublicHosts`, a new CRD-contract method built on `EffectiveHosts`.
  - Such an App reads zero bandwidth, not an error. The usage meter records a healthy zero for its HTTP egress, where it used to log "unavailable" every hour.
- **Not changed:** `agentsession/model.go`'s `ErrSecretsUnavailable` wrap. Its internal HMAC endpoint writes only the status text (`serveSignedMint`), the minter logs the cause itself, and `TestModelMinterFailsClosedOnStoreError` pins the classification on purpose.
- **Tests.**
  - `TestAFailedRouterLookupAnswersWithoutItsText` (api) covers a web service and a static site with public hosts but no Ingress: REST, GraphQL and MCP each answer an uncoded `internal error`, and no metrics source is read. `codedRefusal` now accepts an empty code to mean an uncoded answer.
  - Each site reverted alone, all three reverted, and a fail-open read each fail it.
  - `TestHasPublicHosts` (types) and a new case in `TestTraefikRouterNamesDistinguishPrivateZeroFromMissingPublicIngress` (core) each fail against the old predicate.
  - The touched packages pass and `make lint` is clean.
- **Docs:** ADR006 separates METRICS_UNAVAILABLE from a failed router lookup. ADR023 states the zero for an App without public hosts.
- **Follow-up:** w5/123. Eleven more sites in five files put a dependency's error text inside a public unavailable code: billing, the payment gate, workspace creation, sandbox exec and the Postgres CA.
- **Noted, not filed:**
  - `MetricsWithQuantiles` repeats the router lookup once per quantile.
  - An ambiguous router-label collision answers `internal error`, though renaming would fix it.
