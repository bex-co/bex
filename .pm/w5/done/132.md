# A Blueprint sync and preview still list the workspace's Apps two or three times

Why: w5/124 made a Blueprint request list each datastore kind once before it writes, but the Apps beside them are still listed by each reader, and bex-api's client is uncached, so each list is an API-server round trip returning every App.

- **Sync:** the action plan's resolver lists the App namespace (`lego/backend/internal/apps/blueprint_state_plan.go` `newBlueprintActionResolver`), and the ownership check lists Apps by tenant label (`blueprint_ownership.go` `blueprintOwnershipConflicts`). A sync that detaches a resource builds a second resolver, which lists them a third time (`blueprint_detach.go`).
- **Preview:** the resolver and the ownership check list them twice.
- **Fix:** give `datastoreSnapshot` a lazy Apps list, the tenant-label list, and have the resolver filter it to `AppNamespace(tenantID)` (the same set when scoped). Let the sync's detachment resolver share the plan's resolver where both run.
- **Test:** extend `TestABlueprintRequestListsEachDatastoreKindOnceBeforeItWrites` to count App lists: once each for a sync and a preview before the first write.
- Found by w5/124's efficiency review (2026-10-07).

**Result (2026-10-07):**

- **One App list per request.** The request snapshot, renamed `workspaceSnapshot` since it now holds Apps too, lists the workspace's Apps once on first use, as it lists each datastore kind (`DatastoreListOptions`). Three readers share it:
  - the action plan's resolver;
  - the sync's detachment resolver, rebuilt from the cached lists with no I/O;
  - the ownership check, through `foldWorkspaceApps`, now shared with `listWorkspaceApps`.

  The resolver keeps its old set exactly. It takes the workspace's own namespace, and the tenant label for a scoped request, so twins still resolve to the own copy and w6/m125 still refuses two in one namespace. An empty namespace setting filters nothing.
- **Measured before the first write (test):**
  - a preview lists Apps once, down from two;
  - a sync lists them once, down from three among its readers;
  - a create lists them twice, plan and post-admission apply, as it does each datastore kind.
- **Also:** the post-write ownership stamp lists Apps only when the manifest declares a service.
- **Simplify.**
  - Reuse folded the scoped and unscoped split into `DatastoreListOptions`.
  - Quality found the empty-namespace case and the "datastore" wording left over from the rename. It also suggested a Key Value in the test's sync, so its first write precedes the apply's per-service lookups.
  - Efficiency confirmed the savings.
- **Tests.**
  - The w5/124 test, now `TestABlueprintRequestListsEachResourceKindOnceBeforeItWrites`, counts Apps beside datastores.
  - New tests: twins resolve the own copy; the default workspace skips another workspace's App; a plan without a namespace still resolves; a datastores-only stamp lists no Apps.
  - Ten mutants each fail a test, across two rounds. The apps suite and `make lint` pass.
