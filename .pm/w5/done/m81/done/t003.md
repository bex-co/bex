## Objective

Register the new histograms/signals on the bex-api Prometheus registry so they appear on `/metrics`, and record the observed latency SLOs in ADR047 so the numbers have a documented baseline the sibling milestone `w5/m80` can be verified against.

## Context

- The existing agent-session counters are registered via the metrics registry wired in `lego/backend/internal/api/server.go` (and the CP server's `metricRegistry`); the new series must register the same way to be scraped.
- Observed baselines to record: create-accept ~100ms; sandbox-provision 3–10s warm (cold image pull ~23s per ADR059); agent-ready <1s (`initialize` 132ms + `session/new` 736ms); prompt-turn (happy path ≈ model latency; the ~192s bad-key case is the m80 target to eliminate).

## Steps

1. Register the t001/t002 series on the same Prometheus registry as the existing agent-session metrics; confirm they render on `/metrics`.
2. Add an SLO/baseline subsection to ADR047 with the observed numbers and their source (the dev-5 investigation).
3. Add a lightweight assertion that the series exist and carry the expected labels (a metrics-registration/emit test), not a value-snapshot test.
