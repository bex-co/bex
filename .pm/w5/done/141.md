# A Blueprint create lists each declared kind twice after its apply

Why: after a create's apply, the post-write ownership stamp (`stampBlueprintOwnership`) and then the resources view (`resolveBlueprintResourcesFromIR`) run the same lists back to back. That is up to three wasted API-server round trips per Blueprint create.

- **Where:** `lego/backend/internal/apps/blueprint_ownership.go` `stampBlueprintOwnership` lists the declared kinds. `blueprint.go` `CreateBlueprint` then resolves the resources (`resolveBlueprintResourcesFromIR`), which lists them again (`listWorkspaceApps`, `listWorkspaceDatabases`, `listWorkspaceKeyValues`).
- **Fix:** the stamp is the create's last write. Have it record the lists it read, which are already patched with the new labels, on a snapshot that the resources view then reads.
- **Test:** count lists after a create's last write: each declared kind once.
- Found by w5/132's efficiency review (2026-10-07).

## Result (2026-10-07)

- **Reuse:** `stampBlueprintOwnership`, an apply's last write, now takes the apply's `workspaceSnapshot`. It drops what that snapshot cached (`forget`) and lists the declared kinds through it, and its label patches land on the objects it listed. `CreateBlueprint` passes the same snapshot to the resources view (`resolveBlueprintResourcesFromIR`, which now takes one), so the view lists nothing. A create lists each declared kind three times instead of four: the plan, the apply before its writes, and the stamp after them. The view is only built after a successful apply, since `completeAdmittedSync` returns a failed apply's error.
- **Behavior change, pinned:** the stamp labels the copy of each declared service the apply resolved (`snap.services`, as plan and apply use since w5/m133). It no longer labels every same-named App, so a stale twin in the shared namespace keeps the label it had.
- **Tests:**
  - `TestABlueprintCreateReadsTheWorkspaceOnceAfterItsWrites`: 3 lists per kind, and every declared resource is still reported.
  - `TestTheOwnershipStampLabelsTheCopyTheApplyResolved`: only the resolved copy is stamped.
  - Both fail against the shipped code. A stamp that skips `forget` fails the count test and several ownership tests.
- **Gates:** backend `go test ./...`; `make lint`.
