## Objective

Extend `deploy/gitops/base/log-shipper.yaml`'s `build_pods` discovery so pods labelled `app.bex.co/component=predeploy` are tailed the same file-based way as build pods and land in Loki with `type=build`, attributed to the service via `app.bex.co/predeploy` (or `app.bex.co/build` when present).

## Context

- Build pipeline today keeps only `component=build` and sets `app` from `app.bex.co/build` (`log-shipper.yaml` ~471–543).
- Pre-deploy Jobs already stamp `component=predeploy` and `app.bex.co/predeploy=<name>` (`lego/operator/internal/predeploy`).
- Do **not** stamp `app.bex.co/build` on predeploy pods — `BuildPods` selects on that label alone and live `type=build` SSE would follow migration pods as builds.

## Steps

1. Widen the keep regex to `build|predeploy`.
2. Set `app` from `app.bex.co/build` when non-empty, else from `app.bex.co/predeploy` (order the relabel rules so empty sources do not clobber).
3. Comment the dual-source intent (CLI reachability / w5/m100).

## Acceptance criteria

- [ ] Alloy config keeps both components and attributes `app` for each.
- [ ] Live build follow still only lists true build pods.
