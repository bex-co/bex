## Objective

ADR075 §7: refuse `StartConnect` and `StartClaim` up front with a bounded, actionable error when the installation-admin verifier is unconfigured (`Verifier == nil`), and log a startup warning when the GitHub App is configured but the verifier is not — production ran half-configured (Secret missing `client-id`/`client-secret`, `optional: true` env refs) and every binding 503'd only at the callback.

## Context

- `connectFromCallback` already fails closed on `Verifier == nil` (service.go:194-196) — too late. Add the same check at the top of `StartConnect`/`StartClaim` before minting the transaction, with an error that names the missing configuration class (no secret values).
- Startup warning: `cmd/api/main.go` `wireGitHubApp` — when the three core vars are set but the OAuth pair is not, `log.Printf` a loud warning.

## Steps

1. Preflight check in both start verbs; reuse/extend `core.ErrGitHubUnavailable` with a distinct message (or a coded error) so the dashboard can render "ask your operator".
2. Startup warning in `wireGitHubApp`.

## Files

- `lego/backend/internal/github/service.go`, `lego/backend/cmd/api/main.go`

## Acceptance criteria

- [ ] With Verifier nil: StartConnect/StartClaim error immediately; no `github_connect_transactions` row minted.
- [ ] Startup log warns on the half-configured state; silent when fully configured or fully off.
