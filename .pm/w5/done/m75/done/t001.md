## Objective

Implement ADR078 §3a: a `StartClaim` service verb that mints the standard connect transaction and returns a GitHub OAuth authorize URL, plus a claim branch in `connectFromCallback` that — when the callback arrives with `code` + `state` but **no** `installation_id` — resolves the installation server-side from the authorizing user's reachable installations and binds exactly one unbound, user-administered candidate.

## Context

- `lego/backend/internal/github/service.go`: `StartConnect` (:139) is the template — same authz (`RelCanManage`), same subject requirement, same `mintConnectState` transaction. The claim URL is `https://github.com/login/oauth/authorize?client_id=<id>&state=<token>` — needs the client id threaded into the Service (today only the `Verifier` holds it, inside `client.go`).
- `lego/backend/internal/github/client.go`: `VerifyInstallationAdmin` (:303) exchanges the code and checks admin (personal owner or org `role=admin`). Refactor: split into `ExchangeUserCode(code) → userToken` + `UserAdministersInstallation(userToken, inst)` so the claim path exchanges once and checks N candidates. Add `ListUserInstallations(userToken)` (`GET /user/installations` — returns only THIS app's installations reachable by the user; paginate like `ListRepos`).
- `lego/backend/internal/github/rest.go` callback (:46): today `installation_id` parse-fails into `invalid_installation`. The claim branch keys on **absent** `installation_id` (empty string), not a malformed one — a present-but-garbage id stays `invalid_installation`.
- Candidate filter: user-administered AND unbound (`GitConnectionByInstallation` → ErrNotFound). Exactly one ⇒ `connectWithWorkspace` (conflict gate + quota + login refresh reused). Zero ⇒ bounded `no_claimable_installation`; >1 ⇒ bounded `ambiguous_installation` (extend the `git_error` vocabulary + `writeCallbackFailure`).
- All three proofs preserved: nonce consume + subject match + fresh `can_manage` run before any GitHub exchange, exactly as the install branch.

## Steps

1. Client: add `ClientID()` accessor, `ExchangeUserCode`, `UserAdministersInstallation`, `ListUserInstallations`; reimplement `VerifyInstallationAdmin` over the split pieces (behavior-identical).
2. Service: `StartClaim(ctx, ownerID)` → `{claimUrl}`; extend the `InstallationVerifier` seam (or a new `ClaimResolver` seam) for the fakes.
3. Callback: claim branch on absent `installation_id` — proofs, resolve, bind; bounded failure codes.
4. Wire in `internal/api/server.go` (no new deps — reuses the existing client).

## Acceptance criteria

- [ ] `StartClaim` mints a transaction and returns an authorize URL carrying the signed state; refused for non-admins and (t002) when the verifier is unconfigured.

- [ ] Install branch behavior byte-identical (existing tests unmodified).
