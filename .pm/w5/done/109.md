# A stale scale-down stamp lets a later dip skip the autoscaler's stabilization window

Why: when the desired replica count returns to the current count, nothing clears a pending scale-down stamp, so a later brief dip scales down at once against the old stamp, without waiting out the window.

- `lego/operator/internal/controller/autoscale.go`:
  - when `want < current`, the first dip stamps `annotAutoscaleScaleDown`, and the scale-down commits once the window has elapsed since that stamp;
  - when `want > current`, the stamp is cleared;
  - when `want == current`, nothing happens, so the stamp outlives the dip that set it.
- The order: a dip at T0 stamps T0. Load returns, so `want == current` and the stamp stays. A one-tick dip at T0 + 20 min reads a stamp older than the window and scales down immediately. The window exists to require a sustained low signal.
- Fix: clear a pending stamp when `want >= current`. While there, fold the clear and the replica-count patch on a transition into one `patchAppMeta` call, so a failure between them cannot restart the window.
- Test: dip, recover, dip again within one tick. The second dip holds for the full window instead of scaling down at once.
- Found by w5/096's efficiency review (2026-10-06).

**Result (2026-10-07):**

- **The stamp is settled.** `applyAutoscaling` keeps a pending scale-down stamp only while it is holding a dip.
  - Any other decision clears it. That covers the downscale committing, a signal back at the current count (the case that used to leave the stamp), and a signal above it.
  - The clear and the new `annotAutoscaleReplicas` count go in one `patchAppMeta`, so a failed write leaves both as they were. Before, the clear could land without the count, and the retry stamped a fresh window.
  - The doc comment now states the rule and no longer claims to update `spec.replicas`.
- **Writes.** A commit or a scale-up is now one patch instead of two. Steady state still writes nothing, and a voided dip costs one metadata patch. That patch doesn't bump the generation or trigger a reconcile.
- **Tests.**
  - `TestARecoveredSignalVoidsAPendingScaleDown`: a stale stamp, then a recovery back to the current count or above it, then a one-tick dip. The dip holds and re-stamps.
  - `TestACommittedScaleDownSettlesInOneWrite`: the write carrying the stamp's clear fails once, and the retry commits.
  - Both fail on the original code. Each split order of the old two writes fails the second test, and clearing only on a change of count fails the first. Clearing only at or below the current count is an equivalent mutant, since a scale-up always writes the new count and that patch clears the stamp.
  - The tests reuse the package's `wakeScheme()`.
- **Follow-up:** w5/120, three older window gaps: an unreadable stamp holds forever, depth isn't tracked across a window, and a stamp outlives passes that skip autoscaling.
