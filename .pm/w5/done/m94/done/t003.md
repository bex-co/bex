## Objective

Emit one Render-shaped telemetry event for each launcher-owned command the upstream hook cannot see — `bex --version` (exits before `cmd.Execute()`), `bex upgrade`, and the `bex code` / `bex glm` provider launches that replace the process — under exactly the upstream consent resolution, carrying the command path only.

## Context

- Exec point: `lego/cli/internal/code/launch.go:116` (`syscall.Exec(claudePath, …)`); root version path: `lego/cli/main.go` (`update.IsRootVersionRequest` branch); upgrade: `lego/cli/internal/upgrade/`.
- Upstream exports `analytics.New(apiClient *client.ClientWithResponses) *Sender`, `(*Sender).Send(result command.ExecutionResult, stderr io.Writer)`, `analytics.ResolveConsent()` (`pkg/analytics/analytics.go`, `consent.go`). Consent already folds `DO_NOT_TRACK` and `RENDER_CLI_DISABLE_ANALYTICS`; `bridge.Apply()` maps `BEX_CLI_DISABLE_ANALYTICS` onto the upstream variable beforehand (`bridge.go:97-106`).
- Upstream gates its own post-run hook on a cobra annotation (`cmd/execution.go` `render.analytics.eligible`). First verify whether bex's native cobra commands (`code.Commands()`, `upgrade.Command`) already emit through that hook for the non-exec case; only fill the real holes (exec launches, root version) and never double-emit.
- The detached send is a separate process (setsid launcher), so spawning it **before** `syscall.Exec` is safe; the exec'd `claude` never inherits it.
- Privacy floor from m92/t004 and `docs/bex-cli.md` § CLI usage telemetry: command path (`code`, `glm`, `upgrade`, `version`), duration, exit code, installation id, workspace — never args, prompts, repo paths, or provider names beyond the command word.

## Steps

1. Determine the upstream vocabulary for `completion_kind` and the `command.ExecutionResult` shape; synthesize a result for each native command (exec launches: duration = launcher setup time, exit code 0, `completion_kind` = the closest upstream value or a documented bounded bex value accepted server-side).
2. Prefer `analytics.New(client).Send(...)` so consent, event file, backoff, and the detached subprocess are all upstream's; fall back to the generated `CreateCliTelemetryEvent` only if `Send` cannot be driven for a non-cobra path — record which.
3. Wire: root version (after printing), `upgrade` (after completion), `code`/`glm` (immediately before `syscall.Exec`, non-blocking).
4. Tests with a stub HTTP server: one event per native command; zero when opted out by each variable; the body never contains argv beyond the command word; no upstream command emits twice.
