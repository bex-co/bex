## Objective

Make the launcher's own release identity travel with every request the upstream CLI (and its detached analytics sender) makes to bex-api, without touching upstream code: wrap `http.DefaultTransport` in the launcher process so requests to the configured bex host carry `X-Bex-CLI-Version: <bexVersion>`.

## Context

- `lego/cli/main.go` declares `var bexVersion = "dev"` and calls `bridge.Apply()` before `cmd.Execute()`; `scripts/bex-cli-build.sh:13` injects it with `-X main.bexVersion=$bex_version` alongside `-X github.com/render-oss/cli/pkg/cfg.Version=$upstream_version`.
- The upstream client is `&http.Client{}` with a nil Transport (`render-oss/cli` `pkg/client/client.go:41`, module cache `github.com/render-oss/cli@v1.1.3-0.20260909214233-a764810a7682`), so it uses `http.DefaultTransport`. The analytics send subprocess re-executes the same binary (`pkg/analytics/subprocess.go:86` `os.Executable()`), so `main()` runs again and installs the wrapper there too.
- The bex host is resolved by `lego/cli/internal/bridge/bridge.go` (`BEX_HOST` → `RENDER_HOST`, default `https://api.bex.co/v1/`). Scope the header to that host only — never to third-party hosts (GitHub release checks in `internal/update`, provider endpoints in `internal/code`).
- Upstream already sets `User-Agent: render-cli/<cfg.Version> …` (`pkg/cfg/cfg.go:75`); leave it untouched — the compatibility ledger depends on it staying truthful.

## Steps

1. Add `lego/cli/internal/bridge/transport.go`: a `RoundTripper` that adds `X-Bex-CLI-Version` when `req.URL.Host` equals the resolved bex host, delegating to the wrapped transport otherwise unchanged; an `InstallVersionHeader(version string)` that wraps `http.DefaultTransport` once (idempotent).
2. Call it from `main()` right after `bridge.Apply()` (before `printVersion` / `cmd.Execute()`), passing `bexVersion`.
3. Unit-test with `httptest` servers: header present on the bex host, absent on another host, value equals the injected version, wrapper is not double-installed.

## Files
