## Objective

Add Host and Path filter dropdowns to the Network Metrics card, populated by t003's discovery and driving t004's GraphQL filters, matching Render's card-level filter placement (the m42 capture) and degrading honestly when the store is unavailable.

## Context

- The Network card is `dashboard/src/features/metrics/components/network-metrics-card.tsx`; it already owns card-level controls (Status Code filter, per-section Percentile picker — the w5/m42 layout). Filter-control precedent: `metrics-filters.tsx`; data hook: `dashboard/src/features/metrics/hooks/use-metrics.ts`.
- Store-unavailable rendering precedent: `metric-unavailable.tsx` and the Logs-tab 503 state (w5/m23) — a Loki-less deployment must show "store unavailable", never a silently unfiltered chart.
- Render's capture (`docs/render-artifacts/metrics-page.md`) shows Host and Path as Network-card filters — keep them card-level, not page-level (m42 moved all controls onto their owning cards).
- Locales: `dashboard/src/features/metrics/locales/en.ts` / `zh.ts` (both required).

## Steps

1. Extend `use-metrics.ts` (and the feature's `.graphql` operations) with the `host`/`path` arguments and the discovery query; splice the generated types per `dashboard/CLAUDE.md`.
2. Add the two dropdowns to `network-metrics-card.tsx` beside the Status Code filter; empty-discovery and store-unavailable states render explicit copy, and an active filter is clearable.
3. Wire the store-unavailable error from the metrics read into the card's per-section unavailable state.
4. Add en + zh strings; component tests for populated, empty, store-unavailable, and clear-filter behaviors.
