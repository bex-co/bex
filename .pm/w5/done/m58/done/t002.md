## Objective

Extend the one core request-metrics verb in `lego/backend/internal/metrics/` to accept optional `host` and `path` filters per t001's pinned matrix, querying Prometheus (router-scoped) and/or Loki as decided, and returning an explicit store-unavailable error (never a silently unfiltered result) when a required store is unconfigured.

## Context

- One-core-many-adapters rule (`docs/ADR006-bex-api.md`): the filter lands in the core service; REST/GraphQL/MCP adapt it in t004.
- Today the metrics API rejects host/path filters outright (w3/m12); the reject must become either a real filter or a typed store-unavailable error, per t001's matrix.
- The m56 multi-quantile read (`multiquantile_test.go`) is the closest precedent for extending the read shape without breaking existing callers.
- Loki-side querying precedent: `lego/backend/internal/logs/service.go` (the w5/m23 structured filters).

## Steps

1. Add optional `Host`/`Path` fields to the request-metrics query options in the core service, threaded to the source layer.
2. Implement the Prometheus router-scoped host matching and/or the Loki range aggregation exactly as t001 pinned; keep unfiltered queries byte-identical.
3. Return the typed store-unavailable error for Loki-sourced cells when `BEX_LOKI_URL` is unset; keep rejecting any combination t001 marked unsupported, with a named error.
4. Unit-test the new query construction and both failure modes alongside the existing metrics tests.

## Files

- `lego/backend/internal/metrics/service.go`
- `lego/backend/internal/metrics/source.go`
- `lego/backend/internal/metrics/metrics_test.go`

## Acceptance criteria

- [ ] A request-metrics read with `host` and/or `path` set returns the filtered series per t001's matrix; without them, queries and results are unchanged.
- [ ] Loki-dependent filters with no `BEX_LOKI_URL` produce the typed store-unavailable error; unsupported combinations produce a named reject — neither ever returns silently-unfiltered data.
- [ ] `cd lego/backend && go test ./internal/metrics/...` passes.

## Out of scope

- Adapter wiring (t004), discovery (t003), UI (t005).
