## Objective

Expose t002's `host`/`path` filter options on all three machine surfaces with identical field names, semantics, and error shapes: the REST request-metrics endpoints, the GraphQL metrics read the dashboard consumes, and the MCP metrics tool.

## Context

- Adapters live beside the core: `lego/backend/internal/metrics/rest.go`, `graphql.go`, `mcp.go`; `render.go` holds the Render wire shapes — check how Render's own metrics API spells host/path filters (it offers them on its metrics endpoints) and match the REST spelling.
- The m56 precedent added `quantiles` across all three surfaces in one pass — mirror that structure.
- Error parity: the store-unavailable and named-reject errors from t002 must keep one shape per surface dialect (REST error JSON, GraphQL error, MCP tool error), the same way the Logs filters do.

## Steps

1. Add the filter parameters to the REST endpoint(s), matching Render's parameter names where Render defines them (`render.go`).
2. Add the arguments to the GraphQL metrics field and regenerate/splice the dashboard schema types per `dashboard/CLAUDE.md` (definitions.ts is partly hand-maintained — splice per-feature, never full-codegen).
3. Add the parameters to the MCP metrics tool schema.
4. Adapter tests: same input ⇒ same core call; error shapes per dialect.
