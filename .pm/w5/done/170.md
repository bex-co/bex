# A Blueprint service can copy a sibling's `sync: false` variable

Why: Render's own templates (e.g. `AEO-analytics`) declare a secret once with `sync: false` on one service and copy it into a sibling with `fromService.envVarKey`. bex refuses the copy ("has no such plainly-defined variable"), so the template fails on bex while deploying on Render.

- `resolveRef` (`lego/backend/internal/apps/deploy.go`) copies only plainly-defined values. A `sync: false` variable has no value in the manifest: the user enters it in the dashboard after the first sync.
- Render resolves the copy from the source service's stored value. bex already copies generated values and seeded group values through the env store (`stateCopies`/`generatedCopies`), so a `sync: false` source can take the same deferred path.
- Guard: `knownBlueprintGaps` in `blueprint_render_examples_corpus_test.go` lists `"which has no such plainly-defined variable"` for this note. Remove it when this ships.
- Found by w5/m148's corpus run (2026-10-20): the old `"RENDER_"` deliberate-divergence entry had been hiding it, because the copied key was `RENDER_API_KEY`.
