## Objective

Route each backup signal to Render's event names: scheduled base backups to `postgres_pitr_checkpoint_started/_completed/_failed`, tenant exports to `postgres_backup_completed/_failed` (its `_started` already comes from `CreateExport`).

## Context

- `backupFacts` in `lego/backend/internal/store/datastore_lifecycle_facts.go:41-76` turns `lastBackup` into `postgres_backup_completed/_failed`.
- `ObservedDatastoreState` (`store/datastore_observations.go:157-196`) doesn't read `status.exports[]`.
- Facts are recorded once per edge against a checkpoint (`store/datastore_event_facts.go`); a fact type must be in migration 0107's `fact_type` CHECK (widened in t003).

## Steps

1. Read the in-flight backup (t001) and `status.exports[]` into the observed state.
2. Emit `pitr_checkpoint_started` on a new in-flight backup and `_completed/_failed` on its finish; stop emitting `postgres_backup_*` from base backups.
3. Emit `postgres_backup_completed/_failed` once per export reaching `available`/`failed`, with its reason.
