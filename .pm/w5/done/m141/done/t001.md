## Objective

Give the store the two signals it lacks: the scheduled base backup currently running (name, start time) beside `status.lastBackup`, and whether CNPG continuous archiving is working, as a Database condition `WALArchiving` set only when backups are enabled.

## Context

- `DatabaseStatus` (`lego/types/v1alpha1/database_types.go:418-591`) has `lastBackup` and `exports[]` but no in-flight backup or archiving field.
- Backup status is projected in `database_controller.go:994-1080`; cluster status is read in `readClusterStatus` (`database_controller.go:1541`).
- CNPG reports `ContinuousArchiving` on the Cluster; today only `datastore_metrics.go:105-123` reads it.

## Steps

1. Add an in-flight scheduled backup field (name, startedAt) to `DatabaseStatus`, set while a scheduled CNPG Backup runs, cleared when it finishes.
2. Project `ContinuousArchiving` into a `WALArchiving` condition (True/False + reason/message) when the database has backups; omit it otherwise.
3. Regenerate CRDs (`make manifests generate` in `lego/operator/`).

## Files

- lego/types/v1alpha1/database_types.go

- lego/operator/config/crd/

- [ ] Envtest: a running scheduled Backup sets the in-flight field and a finished one clears it.
- [ ] Envtest: `ContinuousArchiving` False → `WALArchiving` False with CNPG's reason; no condition on a database without backups.
