## Objective

Use the shared identity contract for live App enumeration and SSH targets, and complete the Postgres/Key Value projection and selection variants.

## Context

- apps.ListInstances and live SSH resolution must remain consistent with one another and with telemetry.
- Postgres and Key Value log/metric paths share the raw-name problem, but their pod replacement rules differ from Deployment replicas.
- The official CLI remains an unmodified client to verify, not a codebase to fork.

## Steps

1. Wire the canonical identity and legacy-live-selector resolution into App listing and SSH target selection.
2. Apply the resource-specific mapping to datastore metric/log variants and handle same-name pod replacement explicitly.
3. Retain existing readiness, revision, paid-plan, and instance eligibility gates.

## Acceptance criteria

- [ ] Listing and targeting an eligible live instance refer to the same exact pod, including through the documented old-ID compatibility path.
- [ ] A stale selector cannot silently connect to a replacement instance.
- [ ] Postgres and Key Value log/metric instance fields follow the declared resource-specific rule.

## Out of scope

- Datastore SSH, new shell eligibility, SFTP/SCP, forwarding, or ephemeral shells.
- A first-party CLI implementation or changes to the accepted gateway trust boundary.
