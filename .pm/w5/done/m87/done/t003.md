## Objective

Make public log instance IDs work as input as well as output across Loki history and pod-log fallback/live paths.

## Context

- logs/loki.go maps instance directly to Loki's pod label.
- logs/service.go filters live pods by raw name; changing only emitted labels would make a clicked instance filter return no lines.
- Raw-name links already exist in the dashboard and need the compatibility policy from t001.

## Steps

1. Project canonical IDs from log entries and logLabelValues(instance).
2. Translate authorized public IDs back to bounded internal selectors before the Loki query or pod stream opens.
3. Apply the same mapping to history, discovery, fallback, and live subscriptions; preserve query validation, pagination, and reauthorization.
4. Support the documented legacy-input policy without returning raw pod names in new instance fields.

## Files

- `lego/backend/internal/logs/service.go`
- `lego/backend/internal/logs/loki.go`
- `lego/backend/internal/logs/graphql.go`
- `lego/backend/internal/logs/rest.go`
- `lego/backend/internal/logs/mcp.go`

## Acceptance criteria

- [ ] A discovered or emitted public instance ID can be used to retrieve only that instance's log lines.
- [ ] History and live-tail selectors agree; unknown, foreign, or ambiguous selectors never broaden the query.
- [ ] Translation stays within the requested resource and bounded query window.

## Out of scope

- New log transports, external log drains, or a new logging backend.
- Global enumeration to reverse opaque IDs.
