## Objective

Make the dashboard display and round-trip the public identities provided by the backend without reconstructing Kubernetes identity in the browser.

## Context

- Application/datastore metric legends render series instance labels.
- Service and deploy log chips write instance filters into existing queries and URLs.
- The new selection/aggregation controls are a separate dependent milestone.

## Steps

1. Audit service/deploy/datastore log chips and metric legends for assumptions about raw pod names.
2. Carry backend-provided IDs through labels, filter chips, and URL restoration using the existing shared components.
3. Preserve compact readable presentation and map legacy bookmarked inputs through the server's compatibility contract.

## Files

- `dashboard/src/features/metrics/components/application-metrics-card.tsx`
- `dashboard/src/features/metrics/components/datastore-metrics-panel.tsx`
- `dashboard/src/features/logs/`
- `dashboard/src/routes/services.$serviceId.logs.tsx`

## Acceptance criteria

- [ ] The same instance displays consistently in service/deploy logs and metric legends.
- [ ] Clicking an instance chip and reloading the resulting link preserves the intended filter.
- [ ] The browser does not compute its own competing instance identity.

## Out of scope

- Instance multi-select and aggregation controls scheduled in w5/m89.
- Unrelated page layout changes.
