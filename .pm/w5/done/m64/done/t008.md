## Objective

Cover the behavior this milestone shipped, with the **one-rail invariant** asserted structurally so the defect cannot silently return.

## Context

- The two-sidebar bug shipped and reached production because nothing asserted how many rails a page renders. The highest-value test here is a count, not a snapshot.
- Existing suites to extend rather than duplicate: `dashboard/src/common/components/dashboard-layout/__tests__/dashboard-sidebar.test.tsx`, and the cases inherited from `features/agent-sessions/components/__tests__/session-sidebar.test.tsx` (t003 repoints them — port the assertions, do not drop them).
- Tests must assert real behavior and failure modes; no tautologies, no snapshot-everything.

## Steps

1. **One-rail invariant:** render `/agents` and `/agents/<id>` through the layout and assert exactly one sidebar landmark (`getAllByRole("complementary")` / the rail's `aria-label`) — length 1, not "at least one".
2. **Contextual scoping:** the `Recent` group renders on `/agents*` and does **not** render on `/`, `/project/$id`, `/services/$id`, `/usage`, `/workspace/settings`.
3. **Ported affordances:** search filters by title and by repo; `O` navigates once from a non-editable target and not at all from an input/textarea/contenteditable; More reaches `?view=list`; the PR link renders and does not trigger row navigation.
4. **Active state:** on `/agents/<id>` the matching row is marked active and others are not.
5. **Degraded states:** loading renders skeletons; a backend error degrades the sessions group while the nav groups above still render (the regression this rail's isolation used to hide).
6. **Single poller:** assert `useAgentSessions` polling is owned by exactly one component on `/agents`.
7. Run the full dashboard suite.
