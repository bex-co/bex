## Objective

List every refusal a Blueprint apply can return before its first write, say whether preview already returns it, and decide how preview gets each missing one.

## Context

- Preview: `apps/blueprint.go` `PreviewBlueprint` → `blueprintValidationFor`. Validate (`can_view`) and preview (`can_view_sensitive`) share it.
- Apply: `apps/deploy.go` `deployParsedStack`. Its preflight covers registry credentials, `validateBlueprintServices`, ownership, `requireStackBilling`, references and env groups. The per-resource upserts are `applyCreateWithFields` → `createFromStack` → `planNewApp`, plus `applyDatabase` and `applyKeyValue`.
- w5/m116's inventory and the `core.PreviewOf` rule: billing shows only to a caller who holds the real verb's relation, probed without an audit row.

## Steps

1. Walk `deployParsedStack` and record each refusal before the first write, with file:line.
2. Mark each one previewed, skipped, or apply-only by design (`fromGroup`, races).
3. Decide each skipped one:
   - the count cap across the whole stack (one dry-run per resource sees today's count, not the stack's);
   - how a changed service in a protected environment reads in preview: an error, or a located confirmation requirement;
   - the relation preview uses for billing.
