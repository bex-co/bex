## Objective

Stack datastore creates build and check their objects in one plan step that ends in a server-side dry-run create, shared by apply and preview.

## Context

- `apps/deploy.go` `applyDatabase` and `applyKeyValue` refuse a duplicate display name, run `CheckDatabaseAdmission`, build the object, then `Client.Create` it.
- Interactive creates (`postgres.CreatePostgres`, `keyvalue`) end their plan in `DryRunCreate` with the count-cap mapping (`postgresCountCap.CreateError`).

## Steps

1. Factor each create into a plan step returning the object to create, and have apply create what the plan returns.
2. End the plan in `DryRunCreate`, mapping a count cap to the same error the interactive create gives.
3. Preview runs the plan for each new datastore, located at its path.

## Files

- `lego/backend/internal/apps/deploy.go`, `blueprint.go`

## Acceptance criteria

- [x] A Blueprint with a CRD-invalid datastore field or a datastore over the cap previews with that refusal and the apply's code.

## Out of scope

- Updates to existing datastores.
