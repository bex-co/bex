## Objective

The `HeadSHA` bex records when a turn completes, and on which CI-failure steering keys, is the session branch's head on GitHub rather than the sandbox's own report.

## Context

- `lego/backend/internal/agentsessions/completion.go` `complete`: `report.Git.RemoteHead` → `FinalizeAgentSession(..., headSHA, ...)`.
- `lego/backend/internal/agentsessions/pr_feedback.go` compares `item.HeadSHA` with `session.HeadSHA` and finds sessions by head.
- `lego/backend/internal/github/feedback.go` (installation-token client: `FastForwardBranch`, `BranchProtected`).

## Steps

1. Add a GitHub read of a branch's head commit (installation token).
2. In the completer, record GitHub's head when it can be read; when GitHub cannot be read, record none rather than the self-reported value. Log a mismatch.

## Acceptance criteria

- [x] Test: a report whose `RemoteHead` differs from GitHub's head records GitHub's; an unreadable GitHub records none; a matching report records it.

## Outcome (2026-11-13)

`github.Client.BranchHead` and `agentsession.BranchHeads` (the installation the session's git token comes from) feed `Completer.Heads`; `verifiedHead` records GitHub's head, none when GitHub cannot be read (bounded by `statusReadTimeout`; the previous head stays). ADR090 and `TestCompleterHasNoGitHubDependency` now say the Completer's one GitHub access is that read, through a one-method interface. Tests: `TestCompleterRecordsGitHubsHeadNotTheSandboxs`, `TestBranchHeadsReadsThroughTheOwnersConnection`, `TestFastForwardBranch` (BranchHead).
