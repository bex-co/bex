## Objective

`fastForwardTakenOver` refuses to update a taken-over pull request's branch that GitHub now protects, instead of relying on GitHub to refuse the write (an installation on a ruleset bypass list would not be refused).

## Context

- `lego/backend/internal/agentsessions/pr_takeover.go:196` checks `GitHub.BranchProtected` when a `/bex` takeover starts.
- `lego/backend/internal/agentsession/pullrequest.go` `fastForwardTakenOver` re-reads the pull request's default-branch and repository rules but not protection.

## Steps

1. Call `BranchProtected` for `pr.HeadRef` before `FastForwardBranch`; protected → `PullRequestBranchProtected`; an error reading it → `PullRequestUpstreamError` (fail closed).

## Acceptance criteria

- [x] Test: a branch protected after the takeover began is refused before any fast-forward call; a read failure refuses; an unprotected branch fast-forwards as before.

## Outcome (2026-11-13)

`fastForwardTakenOver` calls `BranchProtected` before `FastForwardBranch`; protected → `pr_branch_protected`, unreadable → upstream error, both before any write. Tests: `TestPullRequesterTakeoverRefusals` ("the PR branch became protected", "GitHub cannot say whether it is protected").
