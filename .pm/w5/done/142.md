# Each new service with domains lists every App on the platform during a Blueprint apply

Why: `hostClaimIndex` (`lego/backend/internal/apps/domains.go`) lists every App on the platform with no filter, to index host claims. A Blueprint apply builds it once in the preflight and again for each new service that declares domains (`deploy.go`), which makes it the heaviest list in an apply. bex-api's client is uncached.

- **Where:** `hostClaimIndex` in `domains.go`, and its callers on the create path in `deploy.go`, around the per-service domain checks.
- **Fix:** build the index once per request, invalidating it when the apply claims a host. Better, find a narrower query than every App, such as one keyed by host label.
- **Test:** an apply creating two services with domains builds the index once.
- **Also:** `validateMaintenanceMode` runs on the update path (`updateStackService`) before the no-op return, so a service with `maintenanceMode.uri` builds the index on every re-apply, even when nothing changed. Run it only when the maintenance spec changed; the preflight has already checked the manifest (found by w5/m133's efficiency review).
- Found by w5/132's efficiency review (2026-10-07).

## Result (2026-10-07)

- **One index per apply:** `deployParsedStack` arms a host-claim scope (`withHostClaimScope`). Its preflight and every service it writes share one index of the platform's host claims. Creates (`createFromStack`) and updates (`patchChangedStackService`) record their claims in it as they write (`hostClaims.replace`): a later check sees hosts an earlier service claimed, and no longer the ones it gave up. An apply creating two services with domains sweeps the platform once instead of three times.
- **Review fixes (two regressions in a first cut, both reproduced):**
  - Sharing the whole request memo across the apply let a service's protection answer outlive a move into a protected environment. Its deferred second write was no longer refused. Only the index is shared now; creates and updates keep their own request memos, as before.
  - Recording claims without dropping the old ones refused a later service whose stored maintenance page, which the manifest need not restate, names a host an earlier service gave up. That left the apply half done.
- **Maintenance re-check:** a no-op re-apply with a maintenance URI used to sweep twice (preflight and update), and now sweeps once, since the update reuses the apply's index. The update path still validates the merged spec, because it alone sees the App's stored tier, hosts and an undeclared maintenance page.
- **Tests:**
  - `TestABlueprintApplyIndexesThePlatformsHostsOnce`: one sweep, 3 at HEAD.
  - `TestABlueprintApplyIndexKnowsItsOwnWrites`: a maintenance page naming a host created or given earlier in the apply is refused.
  - `TestABlueprintApplyFreesTheHostsItsWritesDrop`.
  - `TestABlueprintApplyRechecksProtectionAfterAMove`.
  - Five mutants fail them, including both first-cut regressions.
- **Gates:** backend `go test ./...`; `make lint`.
