# Remove the pre-w5/187 body-only MAC fallback from hmacticket once the previous release's tickets have expired

Why: w5/187 binds each ticket flavor's name into its MAC, and `hmacticket.Codec.signedBy` still accepts the body-only MAC the previous release minted, so tickets issued just before the deploy stay valid for their lifetime. Once those have expired the fallback admits nothing and is dead code; until it is removed it keeps the old cross-flavor acceptance alive for any previous-release ticket that is still in date.

**Gate (release, then date):** the first production deploy that pins w5/187 has been live for 24 hours plus the 30 s clock skew (`snapshotticket.TTL` + `hmacticket.ClockSkew`, the longest acceptance window). No user action.

Steps:

1. Drop the second comparison from `Codec.signedBy` (`lego/backend/internal/hmacticket/hmacticket.go`), so only the flavor-bound MAC verifies.
2. Delete `TestOpenAcceptsTheBodyOnlyMACOfThePreviousRelease` and add its inverse: a body-only MAC is refused as `ErrSignature`.
3. Drop the hand-derived per-flavor keys the codec's flavor binding now makes redundant: `connectKey` (`sandbox/connect.go`), `fileConnectKey` (`sandbox/file_connect.go`) and `key` (`sandboxfiles/ticket.go`). Their tokens live a minute to a few minutes, so changing their MAC costs at most one re-mint across the deploy. Leave `drivergrant`'s Ed25519 seed derivation alone (a different signature).
4. Run the ticket suites (`hmacticket`, `shellticket`, `agentsessionticket`, `sandboxexec`, `sandboxfiles`, `snapshotticket`, `sandbox`, `sshgateway/...`).

- **Source:** w5/187 (2026-11-13), the transition it left behind.
- **Size:** ~30m.

**Unblocked 2026-11-19 (verified evidence, no user decision).** Affects w5/191 only. The w5/187 fix `bf7bf0653` was first pinned to production by `bb01526b8` (`chore(deploy): pin platform images to 3e30e291ed3c`, 2026-11-13 22:56 UTC); the pin before it, `1c4d721bc8dc`, does not contain it, and all 44 pin commits from `bb01526b8` through the current pin `4b2cebd0bd03` (`19faf35f3`) do (`git merge-base --is-ancestor bf7bf0653 <pin>`). The deploy has been live about five and a half days, far past the 24 h + 30 s acceptance window, so no previous-release body-only ticket is still in date. No gate remains. Next: a worker runs steps 1–4 above; acceptance is a body-only MAC refused as `ErrSignature` in `hmacticket` and every listed ticket suite passing.

**Done 2026-11-19:** `hmacticket.Codec.Open` accepts only the flavor-bound MAC (`HMAC(secret, flavor + "\n" + body)`); the body-only fallback and its newline guard are gone. `TestOpenAcceptsTheBodyOnlyMACOfThePreviousRelease` became `TestOpenRefusesABodyOnlyMAC` (it fails with the fallback restored), and `TestOpenRefusesACurrentTicketRewrappedAsAPreviousReleaseOne` went with the fallback it guarded. The sandbox connect token, file connect token and file gateway ticket now sign with `BEX_SANDBOX_EXEC_SECRET` directly, so `connectKey`, `fileConnectKey` and `sandboxfiles.key` are deleted; their flavor names keep them apart from each other and from the exec ticket. A token minted by the old build fails once against the new one, and the CLI mints a fresh one (they live at most a few minutes). The `hmacticket`, `shellticket`, `agentsessionticket`, `sandboxexec`, `sandboxfiles`, `snapshotticket`, `sandbox` and `sshgateway/...` suites pass, `make lint` is clean, and ADR107's w5/187 line records the removal.
