## Objective

Relax the `git_connections` cardinality from 1:1 to N-per-workspace at the schema and store layer: promote `installation_id` to PRIMARY KEY (one workspace per installation stays), index `workspace_id` non-uniquely, and add the `BEX_MAX_GIT_CONNECTIONS_PER_WORKSPACE` quota (default 10, `0` disables) with the coded `GIT_CONNECTION_LIMIT` refusal, per ADR075 §2.

## Context

- Current schema: `lego/backend/internal/store/migrations/0009_git_connections.up.sql` (`PRIMARY KEY (workspace_id)`) + `0069_git_connection_unique_installation.up.sql` (unique index on `installation_id`).
- Store methods: `lego/backend/internal/store/github.go` — `UpsertGitConnection` (upserts ON CONFLICT workspace_id — must become ON CONFLICT installation_id), `GetGitConnection` (by workspace — becomes list + by-owner lookup), `GitConnectionByInstallation`, `DeleteGitConnection`.
- Production holds exactly one row, so the migration is metadata-only: drop PK, promote the existing unique index (or re-create as PK), add `git_connections_workspace_idx`. No row rewrite/backfill.
- Quota pattern to copy: `BEX_MAX_ENV_GROUPS_PER_WORKSPACE` / `ENV_GROUP_LIMIT` (round-11 #3) — transactional check at insert, coded 409 identical across surfaces.
- Within a workspace `account_login` is unique by construction (GitHub: one installation of an App per account).

## Steps

1. Write the up/down migration (next free number): swap PK to `installation_id`, add non-unique `workspace_id` index; down restores today's shape (guarded: refuse down when any workspace holds >1 row).
2. Rework store methods: `UpsertGitConnection` conflicts on `installation_id`; add `ListGitConnections(workspace)` (ordered by `created_at`) and `GetGitConnectionByOwner(workspace, accountLogin)`; keep `GitConnectionByInstallation`; `DeleteGitConnection(workspace, installationID)`.
3. Add the quota: parse `BEX_MAX_GIT_CONNECTIONS_PER_WORKSPACE` in `cmd/api/main.go` wiring; enforce transactionally in the insert path; mint the coded error (`GIT_CONNECTION_LIMIT`, 409) in the shared error vocabulary.
4. Mirror the new env var name+comment into `.env.example` and the bex-api row of the CLAUDE.md env table.

## Acceptance criteria

- [ ] Two rows with the same `workspace_id`, distinct `installation_id`s insert cleanly; a duplicate `installation_id` (any workspace) is refused by the PK.
- [ ] Migration up/down round-trips a single-row table byte-identically; down refuses when a workspace holds >1 connection.
- [ ] Quota exceeded ⇒ coded `GIT_CONNECTION_LIMIT` (409); `0` disables; default 10.
