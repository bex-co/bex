## Objective

Move every consumer of the workspace's connection from `GetGitConnection(workspace)` to owner-scoped resolution against the connection set (ADR078 §4): `ListRepos` aggregates across all connections; every token mint selects the connection whose `account_login` equals the repo URL's owner; no match ⇒ exactly today's no-connection behavior.

## Context

- `lego/backend/internal/github/service.go`: `ListRepos` (:308), `ListBranches` (:338), `cloneToken` (:478 — the deploy-time clone-secret mint, NOT authz-gated), `blueprintFetcher.FetchBlueprintFile` (:603), `commitSource.ResolveCommit` (:526), `installationResolver` (:416 — webhook, **unchanged**: installation→workspace stays a function).
- `lego/backend/internal/agentsession/mint.go` `Minter.Mint` (:83) — owner-equals-`account_login` guard becomes owner-in-connection-set; everything else (lifecycle gate, branch validation, one-repo `contents:write` token) unchanged.
- The structural `githubOwnerRepo` origin gate (service.go:382, w1/m65 F1) is the ONLY parser used to extract the owner — do not reuse `core.CanonicalRepo`.
- `RepoAccessible` stays as the post-mint grant check on the clone path (never silently public-clone a private repo).
- Fan-out bound: the t001 quota caps connections at 10 by default; fetch per-connection repo pages concurrently.

## Steps

1. `ListRepos`: mint one fresh installation token per connection concurrently, merge, annotate each repo with `accountLogin` + `installationId`, stable-sort (account, then fullName). Partial per-connection failure: degrade that account's slice with a logged warning, never fail the whole list.
2. Add an internal `connectionForRepoURL(ctx, workspace, repoURL)` helper (owner parse → `GetGitConnectionByOwner`); route `ListBranches`, `cloneToken`, `FetchBlueprintFile`, `ResolveCommit` through it.
3. Agent mint: replace the single-connection owner equality with the same helper; refusal shape (`ErrForbidden`) unchanged.
4. Leave `installationResolver.WorkspaceForInstallation` byte-identical.

## Acceptance criteria

- [ ] With two connections, `ListRepos` returns both accounts' repos, each annotated with its `accountLogin`/`installationId`.
- [ ] `cloneToken` for a repo owned by account B mints from B's installation, never A's (test asserts the minted installation id).
- [ ] A repo whose owner matches no connection behaves exactly like today's no-connection case in every consumer (public fetch / clear failure / `[]`).
- [ ] Push-webhook scoping tests pass unchanged; agent mint refuses out-of-set owners with `ErrForbidden`.
