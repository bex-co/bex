## Objective

Retire both dashboard traps and surface the multi-connection model: the Settings card lists all connections with per-row disconnect + "Connect another account"; the `services/new` picker uses the **stateful** `connectGit` mutation (never the bare install URL) and groups repos by account; the `missing_state` dead end becomes a recovery page that finishes binding an already-installed installation (ADR075 §3/§5).

## Context

- The trap: `dashboard/src/features/services/components/service-source-picker.tsx:127-135` links `connection?.installUrl` from the `gitConnection` **query** — bare URL, no state ⇒ guaranteed `missing_state`. The correct path is the `connectGit` mutation (`use-connect-git.ts:28-30`, used by `connect-github-card.tsx`).
- Settings card: `dashboard/src/features/git/components/connect-github-card.tsx` + `use-git-connection.ts` — moves to the plural `gitConnections` query.
- Callback failures redirect to `/settings?git_error=<bounded-code>` (`rest.go:174-188`). The recovery UX keys off `git_error=missing_state`: explain "this installation isn't connected to a workspace yet" + render the stateful connect button. Codes are bounded — no new free-text params.
- Repo grouping: t003's `accountLogin` annotation on each repo. Read `dashboard/CLAUDE.md` before editing; hand-mirror codegen types if no live bex-api (see memory: technique_hand_mirror_codegen).

## Steps

1. Swap `use-git-connection.ts` to `gitConnections` (list); update the Settings card to render one row per connection (account, created, disconnect) + "Connect another account" via `connectGit`.
