## Objective

Make a successful callback **add** a connection to the workspace's set instead of replacing the sole row, enforcing the t001 quota, refreshing `account_login` from the app-JWT installation lookup, and preserving every proof of the existing flow (ADR078 §3: the three-proof flow itself is untouched).

## Context

- `lego/backend/internal/github/service.go`: `StartConnect` (:124), `connectFromCallback` (:175), `connectWithWorkspace` (:227) — the last currently upserts keyed on workspace (replacement semantics). Keep: `ConsumeGitHubConnectTransaction` first, initiator-subject match, `VerifyInstallationAdmin`, `AuthorizeFreshOn(RelCanManage)` (ADR073 #3), and the `GitConnectionByInstallation` cross-workspace `ErrConflict` (w1/m65 F2). Same-workspace re-connect stays idempotent (refreshes `account_login`).
- GitHub App setting "Redirect on update" must be enabled so configure-flow edits round-trip the Setup URL — record as an operator note in `docs/ADR026-github-integration.md` §2 or the runbook.
- `Disconnect` (service.go:290) gains an `installationID` parameter (0/absent ⇒ sole connection; ambiguous ⇒ error).

## Steps

1. `connectWithWorkspace`: after the app-JWT lookup + conflict gate, check the quota (t001) for NEW bindings (idempotent re-bind of an existing row is quota-exempt), then insert/refresh keyed on `installation_id`.
2. Thread `installationID` through `Disconnect` and delete exactly that row; keep idempotency (`ErrNotFound` ⇒ nil).
3. Refresh `account_login` on every touch (connect + idempotent re-connect) so account renames converge.
4. Note the "Redirect on update" app requirement in ADR026 (one-line amendment referencing ADR078).

## Acceptance criteria

- [ ] Second connect on a workspace with an existing connection binds a second row; the first row is untouched.
- [ ] Installation bound to another workspace still returns `ErrConflict`; same-workspace re-connect is idempotent and refreshes `account_login`.
- [ ] Quota-exceeded connect refuses with `GIT_CONNECTION_LIMIT` and the callback redirect carries a bounded error code (extend the `git_error` vocabulary — no free text).
- [ ] All existing `github` package tests (three-proof flow, replay, expiry, demotion) still pass unmodified in their assertions.
