## Objective

Expose the connection set on all three API surfaces over the one core (ADR006 one-core/thin-adapters), keeping the singular verbs as documented-deprecated compatibility aliases, per ADR075 §5.

## Context

- REST: `lego/backend/internal/github/rest.go` — add `GET /v1/git/connections` and `DELETE /v1/git/connections/{installationId}` (admin-only); keep `GET`/`DELETE /v1/git/connection` as aliases over the sole connection (ambiguous ⇒ 409 with a coded error).
- GraphQL: `lego/backend/internal/github/graphql.go` — `gitConnections: [GitConnection!]!`; `disconnectGit(installationId: …)` argument (omitted ⇒ sole connection); `@deprecated` on the singular `gitConnection`. Regenerate/hand-mirror the dashboard schema types as done in prior milestones.
- MCP: `lego/backend/internal/github/mcp.go` — `list_git_connections` replaces `get_git_connection` (keep the old tool name registered as an alias for one release or mark deprecated in its description); `list_repos` returns the account-annotated aggregate.
- ADR075 shape change: `GetConnection`/`gitConnection` **drop `installUrl` from the not-connected view** (the stateless bare URL stops being advertised); connected rows keep it as a "configure grants on GitHub" deep link.
- Whole surface is a bex extension (Render lists repos only via its private dashboard API) — flag supersets in-code as elsewhere.

## Steps

1. Core: `ListConnections` verb (`RelCanView`) + `Disconnect(installationID)` from t002; singular `GetConnection` becomes a thin alias (first/only connection).
2. REST routes + JSON shapes; bounded error codes for ambiguity and quota.
3. GraphQL schema + resolvers + deprecation directives.
4. MCP tool registration + descriptions (agent-facing: "which accounts are connected, which repos can I deploy").
5. Update `docs/ADR026-github-integration.md` §5's surface list with a pointer to ADR075.
