## Objective

Run `/simplify` over the code this milestone changed.

## Acceptance criteria

- [ ] Findings fixed or recorded.

## Result (2026-10-06)

Three reviewers (reuse, quality, efficiency) read the diff. Fixed:

- **Rollback on the revision-aware path.** It compared only the version annotation, so it took a delete's provisional projection of its version as its own. It overwrote it, re-mounting the revoked key, and left the provisional mark on a committed revision. It now requires its exact committed revision and restores through `stampProjection`.
- **Error privacy.** `projectSource`'s errors wrapped `core.ErrConflict`. A compensation that joined one with the write's cause made the whole join a public 409, carrying the cause's internal endpoint. The primitive now returns a private `errProjectionConflict`, and each caller maps it: the revision-aware patch to `ENVIRONMENT_REVISION_CONFLICT`, the setters and deletes to the plain "secret changed" 409.
- **Two deletes of one version.**
  - A delete that read the same version as one that had already committed overwrote its projection, so the committed delete's key was mounted again.
  - The Secret now keeps only the keys both keep.
- **Superseded projections.**
  - A delete whose provisional projection a newer write already supersedes now re-reads before it rolls the App. It used to run a whole rollout, which is a rebuild for source-built services, before a commit that could only conflict.
  - A superseded files removal no longer drops the App's files reference while the newer Secret is mounted.
- **Exhausted retries.** `projectSource` now reports the last attempt's `ExistedBefore` when its retries run out, not false.
- **Create-time preparation.**
  - It commits through `updateMapCAS`, so the Secret carries the exact version its write created.
  - The duplicated rollback after a separate version read is gone.
- **Smaller fixes.**
  - Revision helpers moved to `projection.go`: `provisionalAt`, `setProjectedRevision` (the inverse of `projectedRevision`), and the env annotation constant.
  - `secretChanged()` replaces three copies of the conflict answer.
  - `upsertSecret` uses `envBytes`.
  - Stale doc comments fixed.
  - The test helpers reuse `deleteFailureClient` and `newService`.

Declined:

- **Folding the rollback into `projectSource`.** It would delete a live Secret when the revision-aware patch failed before it looked.
- **Removing `projectCASEnv`'s store pre-check.** That changes the revision-aware contract.
- **Building the Secret bytes once per call.** Only matters under contention.
- **Promoting a successful delete's stamp to committed.** Keeping what both keep already closes the re-mount without a second write.
