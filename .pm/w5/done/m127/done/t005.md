## Objective

`deleteMapKeyAfterProjection` projects the reduced map first and commits after. Fit it into revision ownership as t001 decided, so neither its projection nor a racing writer's is lost.

## Acceptance criteria

- [ ] A delete racing a write converges on the store's latest map, in the store and the Secret alike.

## Result (2026-10-06)

- Deletes still project before they commit; the README's decision 3 is revised. Commit-first broke the contract `TestDeleteSecretFileRetryRollsAfterAppPatchFailure` pins: a delete whose App patch fails leaves the store holding the key, as the retry anchor, and the Secret without it.
- The projection carries the version the commit will create, marked `app.bex.co/source-revision-provisional`.
  - A write that commits that version replaces it, and the delete's commit then conflicts and re-reads.
  - A projection of that committed version already in the Secret supersedes the delete's.
  - A delete whose projection that version or a later one already supersedes re-reads before it rolls the workload, since its commit could only conflict.
  - Two deletes that read the same version: the Secret keeps only the keys both keep, so neither re-mounts the key the other revoked, even after one of them committed.
  - An absent key's repair projects the version it read.
- So a failed delete leaves its key revoked and blocks neither the next write nor the next delete. A first version that stamped the next version as committed did: the next write to commit that version failed its projection.
- `TestADeleteProjectsTheRevisionItsCommitWillCreate` pins five orders for env and secret files, plus the absent-key repair at version 0.
