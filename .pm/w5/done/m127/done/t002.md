## Objective

Generalize `projectCASEnv` by kind (store path, Secret name, revision annotation, App reference) into one primitive for both kinds.

## Steps

1. Refuse an older revision.
2. Treat the same revision with the same data as a no-op, and the same revision with other data as a conflict.
3. Create, update or delete under UID and resourceVersion preconditions.
4. Keep the unconditional path for a store without versions.

## Files

- `lego/backend/internal/secrets/{batch.go,service.go,files.go}`

## Acceptance criteria

- [ ] Unit tests: an older revision is refused, a newer one replaces, an equal one is idempotent, and a concurrent update loses safely.

## Result (2026-10-06)

- `projectSource` in `internal/secrets/projection.go` serves both kinds through `projectionKind`: the Secret name and its revision annotation (`app.bex.co/env-source-revision`, `app.bex.co/files-source-revision`).
- A projection a later revision already landed is left to it. The same revision with the same data writes nothing, and with other data it is a conflict. An update carries the read object's resourceVersion, a delete also its UID, and a conflict re-reads and judges again.
- A store without versions is recognized by its type, not by revision 0. A versioned path never written (version 0) is ordered like any other revision, so a repair at version 0 cannot overwrite a first write's projection.
- Unit tests: `TestAProjectionNeverMovesItsSecretToAnEarlierRevision` (11 orders) and `TestAProjectionRejudgesASecretChangedSinceItsRead` (update and delete).
