## Objective

`compensateEnvironment` puts a Secret back to the restored revision only while the failed write's revision still owns it. This generalizes `rollbackCASEnvProjection` to both kinds and closes ADR013's window.

## Acceptance criteria

- [ ] A restore racing a newer writer's projection leaves the newer projection and answers `ENVIRONMENT_RESTORATION_FAILED`, as a superseded store write does.

## Result (2026-10-06)

- `restoreMap` returns the version its CAS committed, and `compensateEnvironment` projects the restored map at that version, so it never lands over a newer writer's projection.
- The answer differs from the acceptance line in one case.
  - A store restore that is itself superseded still answers `ENVIRONMENT_RESTORATION_FAILED`, which is w5/m119's rule.
  - A restore whose CAS committed, but whose projection a newer write superseded, answers the write's own failure. Its change is gone from the store, and the newer projection is built from the restored map, so nothing of it survives.
- `TestARestoreNeverOverwritesANewerProjection` pins both kinds and that answer.
- The revision-aware path keeps `rollbackCASEnvProjection`'s exact-ownership rule.
