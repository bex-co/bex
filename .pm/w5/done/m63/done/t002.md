## Objective

Insert an `age`-encrypt step between the existing `compress` and `upload` steps in the `etcd-backup` CronJob, per ADR050 §2 Tier A.

## Context

- `deploy/gitops/charts/etcd-backup/cronjob.yaml` — current shape: `snapshot` (etcdctl) initContainer → `compress` (busybox gzip) initContainer → `upload` (aws-cli) container.
- Encrypt to the committed `AGE_BACKUP_PUBLIC_KEY` (t001); no secret material needed on this path.
- `docs/ADR050-encrypted-platform-backups.md` §2.

## Steps

1. Add an `encrypt` initContainer after `compress`, before `upload`: a small pinned `age` image running `age -r <public-key> -o /backup/etcd-snapshot.db.gz.age /backup/etcd-snapshot.db.gz`.
2. Change the `upload` container's `aws s3 cp`/`ls`/`rm` targets from `etcd-$ts.db.gz` to `etcd-$ts.db.gz.age` (upload, list-for-retention, and prune all need the new suffix).
3. Update the header comment block to mention the new encrypt step and the age image pin.

## Files

- `deploy/gitops/charts/etcd-backup/cronjob.yaml`

## Acceptance criteria

- [ ] A manual CronJob trigger (`kubectl create job --from=cronjob/etcd-backup`) produces a `.db.gz.age` object in `bex-tfstate/etcd-snapshots/`, not a bare `.db.gz`.
- [ ] Retention pruning (`s3 ls | grep … | head -n "-$retain"`) still keeps exactly 7 objects, now matching the `.age` suffix.
- [ ] Downloading the object and running `file`/`age -d` without the private key fails to produce plaintext.

## Out of scope

- The decrypt side (t008).
- Credential scoping for this CronJob's Secret (t006/t007).
