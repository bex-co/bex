## Objective

Add the same age-encrypt step to the operator-templated `kvbak-<id>` backup Job, where the pipeline is built in Go rather than a static GitOps manifest.

## Context

- `lego/operator/internal/controller/keyvalue_backup.go` — builds the Job spec programmatically: a Valkey `--rdb`-dump initContainer, a `busybox:1.37` `gzip -9` initContainer, then an `upload` container running `publish.DefaultAWSCLIImage` with an inline shell script (`aws s3 cp /backup/dump.rdb.gz "${prefix}${timestamp}.rdb.gz"`, list+prune).
- Unlike t002/t003 this is Go code constructing `corev1.Container`/`corev1.PodSpec` structs, not a YAML file — the public key must be baked in as a build-time constant or read from a ConfigMap/env the operator already has access to (it's not secret, so either is fine; prefer whatever is simplest given the existing `keyvalue_backup.go` structure).

## Steps

1. Add an `encrypt` initContainer between the existing `compress` (gzip) initContainer and the `upload` container, running `age -r <public-key> -o /backup/dump.rdb.gz.age /backup/dump.rdb.gz`.
2. Update the `upload` container's inline script: change `dump.rdb.gz` references to `dump.rdb.gz.age` in the `cp`, `ls`, and prune commands.
3. Decide and implement how the operator supplies the public key to the new initContainer (env var sourced from operator config, e.g. a new `BEX_BACKUP_AGE_PUBLIC_KEY` operator env var, or a baked-in default) — follow whatever pattern this file already uses for non-secret configuration (compare to how `BEX_KV_BACKUP_DESTINATION` etc. are threaded through).
4. Update/add unit or envtest coverage for the Job spec construction (this file already has backup/restore verification per ADR021 §Verification — extend it rather than adding a parallel suite).

## Files

- `lego/operator/internal/controller/keyvalue_backup.go`
- its existing test file(s) in the same package

## Acceptance criteria

- [ ] A newly reconciled `kvbak-<id>` Job spec contains the `encrypt` initContainer positioned between `compress` and `upload`.
- [ ] The `upload` container's script references `.rdb.gz.age`, not `.rdb.gz`, in cp/ls/prune.
- [ ] Existing keyvalue-backup unit/envtest coverage passes with the new step; a new test asserts the encrypt step's presence and ordering.
- [ ] A live paid KeyValue instance's backup produces a `.rdb.gz.age` object in `bex-tfstate/keyvalue/<id>/`.

## Out of scope

- Credential scoping for `bex-kv-backup-s3` (t006/t007).
