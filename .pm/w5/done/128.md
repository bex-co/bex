# Creating a service whose deleted namesake's Secrets await garbage collection answers 500

Why: create-time preparation creates the new service's `<service>-env` / `<service>-files` Secret before the App exists. When a deleted service of the same name left its Secret for garbage collection, `prepareProjection`'s `Create` meets `AlreadyExists` and rolls the store write back. The create then fails with the raw Kubernetes error, which bex-api answers as a 500 "internal error", until GC catches up.

- **Where:** `lego/backend/internal/secrets/files.go` `prepareProjection`, and `adoptPreparedSecret` after it.
- **Fix:** on `AlreadyExists`, take the name over only when the existing Secret is controlled by an App that no longer exists:
  - read the App by name, and replace the Secret only if it is absent or has another UID;
  - rewrite it ownerless with this create's map and revision, for adoption as today.
  - Leave anything else alone: a live App's Secret, or another create's prepared, ownerless one. That create must still fail, with a coded conflict rather than a 500.
- **Context:** w5/118 made post-create writes replace a predecessor's Secret (`controlledByAnother` in `projection.go`). This is the create-time half.
- **Test:**
  - a create that carries files, while the deleted namesake's Secret is still present, succeeds, mounts only its own files, and owns the Secret;
  - a Secret controlled by a live App, or an ownerless one, still refuses the create, with a 409.
- **Related:** `apps` `writeNewApp` returns on a prepare failure without aborting. When the env leg fails after the files leg, the prepared ownerless `-files` Secret and its store map are left behind. Run `AbortCreateSecrets` on that path too.
- Found while closing w5/118 (2026-10-07).

**Result (2026-10-07):**

- **Create-time takeover.** `createPreparedSecret` creates the prepared Secret. On `AlreadyExists` it reads the holder.
  - When the holder is controlled by the App that held this name and no longer exists (`ownedByDeletedNamesake`), the create takes it over. The Secret is rewritten ownerless with this create's map and revision until the new App adopts it. That is the create-time half of w5/118.
  - A live App's Secret, another create's unadopted one, a Secret already being deleted, or one an App of another name controls refuses the create with an uncoded 409 (`errSecretNameHeld`) instead of the 500.
- **Nothing left behind, nothing taken.**
  - A prepare whose env leg fails removes the files leg it wrote.
  - `AbortCreateSecrets` removes only the legs prepare wrote (`preparedLegs`, shared with Commit). It used to delete both legs' Secrets by name, which could take a namesake's.
  - Compensation runs detached from the request with its own timeout, so a client gone mid-create cannot strand prepared Secrets.
  - A failed rollback or abort is logged rather than joined into the refusal, whose text would otherwise carry the store's address (`core.HideCause`).
  - `writeNewApp` answers a public prepare error without its internal prefix.
- **Simplify.**
  - Review found the restamped revision untested; keeping the predecessor's 7 would have outranked every later write. The test now pins it.
  - Review also found the leak through `errors.Join` and the request-scoped compensation, and suggested sharing `preparedLegs`. The terminating-Secret case refuses rather than updating an object about to vanish.
- **Tests.**
  - Secrets-level:
    - the takeover holds only the new file at the new store's revision 1, and the new App owns it;
    - four refusals leave the holder untouched and roll the store back;
    - a refused create hides a failing rollback;
    - a failed env leg removes the files leg and leaves the live App's env Secret.
  - REST: 201 over a deleted namesake's Secret, mounting only the new file; an uncoded 409 for another create's Secret.
  - Twelve mutants each fail a test.
  - The secrets, apps and api suites pass, and `make lint` is clean. ADR013 documents the create-time half.
- **Follow-ups.**
  - w5/134: a refused create overwrites, then deletes, a namesake's store map in a concurrent same-name create. This is pre-existing.
  - w5/135: an ownerless Secret a crashed create left behind blocks the name for good.
