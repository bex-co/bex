## Objective

The Git proxy's streamed-response byte budget fits real repos and fails loudly when exceeded — never again a clean-EOF truncation that counts `accepted` and audits `allowed`.

## What shipped

- `defaultMaxResponseBodyBytes` 512 MiB → 4 GiB, overridable via `BEX_AGENT_GIT_MAX_RESPONSE_BYTES` (`Broker.MaxResponseBytes`, wired in `cmd/ssh-gateway/main.go`).
- `serveGit` now captures `io.Copy`'s outcome: over-budget → `failUpstream("response_cap", …)` + `panic(http.ErrAbortHandler)`; copy error → `failUpstream("stream", …)` + abort. Neither path reaches the `accepted` metric or the `allowed` audit event.
- Tests: `TestGitProxyResponseBudgetAbortsLoudly` (cap → abort, log, `response_cap` count, zero `accepted`), `TestGitProxyUpstreamStreamErrorAbortsLoudly` (mid-stream upstream break → abort, log, `stream` count); harness resolver extended to loopback sources for real-server abort tests.
- Env row documented in `lego/backend/CLAUDE.md`.

## Acceptance criteria

- [x] Over-budget stream aborts + logs + counts; no false success bookkeeping.
- [x] Broken upstream stream aborts + logs + counts.
- [x] `go test ./internal/sshgateway/...` + `make lint-backend` green.
