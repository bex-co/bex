## Objective

Extend the resource/request metrics read so a single call can return several quantiles (at least p50/p90/p99) together, feeding the dashboard's percentile "All" overlay — instead of today's single `quantile` per request. Keep REST, GraphQL, and MCP consistent (same field shape, same semantics, same store-less/over-window error behavior).

## Context

- bex-api metrics feature: `lego/backend/internal/metrics/` (`service.go` + `rest.go`/`graphql.go`/`mcp.go`); the read maps onto Prometheus (`BEX_PROM_URL`) histogram quantile queries.
- Today the `metrics` query takes a single `quantile` (w5/m42 shipped a p90 default). Add a way to request multiple quantiles (e.g. a `quantiles: [Float]` arg or a `percentile: "all"` sentinel) and return a series-per-quantile.
- Keep the single-quantile path working (backward compatible); `BEX_MAX_QUERY_HOURS` still bounds the window.

## Steps

1. Add the multi-quantile request shape + response (series keyed by quantile) to the metrics service verb.
2. Thread it through REST, GraphQL, and MCP identically; preserve the named 503 (no `BEX_PROM_URL`) and over-window 400.
3. Backend tests for the multi-quantile mapping.
