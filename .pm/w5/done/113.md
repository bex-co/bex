# Without a control-plane database the audit log is unmounted, not the documented 503

Why: `Deps.Audit`'s comment says a nil audit service makes the read verb answer 503 `AUDIT_LOG_UNAVAILABLE`, but a nil feature is never mounted. The dashboard's "audit log unavailable" state can therefore never show, and on a deployment without the database its audit query fails GraphQL validation.

- **What happens now:**
  - `lego/backend/internal/api/server.go` skips a nil feature (`appendFeature`), so REST answers 404 and GraphQL has no `auditLogs` field.
  - `cmd/api/main.go` builds `audit.Service` only alongside the control-plane store, so production never sends the code.
- **Fix, one of two:**
  - mount `audit.Service{Base: base}` with no store when the database is not configured. This follows the env-vars and deploy-history precedent of a refusal that is omitted, not faked, and makes the comment and the dashboard state true.
  - or correct the comment and drop the dashboard state.
- **Test:** a server without the database answers `AUDIT_LOG_UNAVAILABLE` on REST and GraphQL. `api/refusal_codes_test.go` wires a store-less service by hand today.
- Found by w5/m128's cross-surface test (2026-10-06).

**Result (2026-10-07):**

- **Mounted, as documented.** `NewServer` defaults a nil `Deps.Usage` or `Deps.Audit` to a store-less service (`cmp.Or`). Without the control-plane store both reads now mount and answer their 503:
  - the audit log: `AUDIT_LOG_UNAVAILABLE` on REST and GraphQL (it has no MCP tool);
  - usage: an uncoded "usage unavailable" on REST, GraphQL and MCP.

  Before, both were left out: REST answered 404, and GraphQL rejected `auditLogs` and `usage` as unknown fields. The dashboard's audit-log "unavailable" state, already tested in `use-audit-log.test.ts`, can now show.
- **Usage had the same bug.** Its `Deps` comment promised the same 503, so it is fixed alongside the audit log. Both verbs check for the store first (`usage.monthToDateAt`, `audit.List`), and nothing runs the store-less services' retention loops.
- **Comments.** The `Deps.Usage`/`Deps.Audit` comments and the `usage` package doc now describe the store-less mount. A duplicated `features()` doc line left above `sandboxService` is gone.
- **Tests.**
  - The refusal-code table and `TestAuditReadSurfaceAuthMatrix`'s store-less case now use the default server (`Deps{}`) rather than wiring a store-less audit service by hand.
  - New `TestStorelessUsageAnswersUnavailable`.
  - Dropping either default fails these tests. Against HEAD's server they answer 404 and "Cannot query field".
  - `schema_dump_test` and `scope_matrix_guard_test` no longer wire either service just to mount it.
  - The route inventories gain `list-owner-audit-logs` (Render's operation), and `GET /v1/usage` is classified as needing the database.
  - The api, usage, audit and cmd suites pass, and `make lint` is clean.
- **Not changed:** the sandbox's `Deps` comment also mentions an unavailable error, but its unmounted state is deliberate ("byte-identical to before pillar 5", ADR042).
