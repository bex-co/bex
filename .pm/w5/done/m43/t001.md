## Objective

Build against evidence, not guesses: capture exactly how dashboard.render.com marks service events on the metrics page.

## Findings (captured 2026-07-17, backend-v2 / srv-d2rnr3jipnbc73deuvgg)

- Charts are uPlot; each `.u-over` carries two overlay layers: a full-plot-height absolute div holding one **vertical dashed line** per event x, and a 30px strip above (`top:-30px`) holding one **24×24 icon button** per event.
- Kind treatments (`chart-event-*` classes): deploy started = dashed-border neutral, deploy live = green solid (`chart-event-success-*`), failures = red; same rocket-ish deploy glyph across deploy kinds.
- Overlapping events collapse into a **count badge** ("2"); clicking it zooms the time range to the cluster's window (~90s).
- Hover popover: timestamp, icon + "Deploy live for `a1318db`", footer "Click to view event details"; click navigates to the deploy.
- Toolbar has a searchable checkbox-tree event filter (Deploy / Service Status / Scaling / Maintenance / Edge Cache; defaults Deploy Started/Ended + Instance Failed) and a toggleable "Event timeline" sidebar.

## Acceptance criteria

- [x] Marker DOM structure, kind styling, clustering, tooltip, and click behavior captured (screenshots in `.playwright-mcp/`).
