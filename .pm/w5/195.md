# 195 — An App outside every workspace (`default/hello-static`) still serves on the platform domain

Why: ADR043 says workspace = namespace and the fleet migrated on 2026-07-28, but production's `default` namespace still holds a static site that no API, dashboard, billing or quota sees, and nothing reports such an App.

- **Evidence (production, read-only, 2026-11-19):** `kubectl get apps.app.bex.co -A` lists 27 Apps; 26 are in workspace namespaces and one, `default/hello-static` (`type: static_site`, `spec.image: hello-static:demo1`, created 2026-07-12 by `kubectl apply`, no workspace labels), is `Running` and serves `https://hello-static.onbex.co` (200) from the object-store origin, with an Ingress and an ExternalName Service in `default`. bex-api prunes orphaned App CRs only in workspace namespaces (`lego/backend/internal/workspaces/service.go`). Tests use its names only as fixture strings (`lego/backend/internal/logs/shipper_attribution_test.go`).
- **Recommendation (the proposal's, not a user decision):** delete it. It is a demo, and deleting it removes only its public URL. First check that nothing outside the repository links to `hello-static.onbex.co` (search the docs site and public pages), then `kubectl -n default delete app hello-static` and confirm the operator's finalizer removes its Ingress and Service.
- **Guard:** add a check that reports any App CR outside a workspace namespace (an alert on the operator's App metrics, or a `gitops-validate`-style production check), so a hand-applied App cannot hide again.
- **Done when:** production has no App outside a workspace namespace, and the check reports one in a test. ~45m.
