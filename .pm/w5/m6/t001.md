## Objective

Capture Render's Logs viewer as the design reference for this milestone — the filter bar, live toggle, and log-line layout — and record which Render log filters bex-api can and cannot honor over raw pod logs.

## Context

- Render dashboard Logs tab (log in via Playwright MCP; screenshots to `.playwright-mcp/`, bare filenames).
- bex-api logs contract (`docs/bex-api.md`, `docs/observability.md`): GraphQL `logs(resource, type, text, limit)` → `LogEntry { timestamp message type instance }`; application logs only — `type=request`/`build` return empty; structured filters (`level`, `statusCode`, `method`) omitted; live tail over SSE (`/v1/logs/subscribe`), not WebSocket.

## Steps

1. Navigate Render's Logs page; screenshot filter bar + live toggle + line list to `.playwright-mcp/render-logs.png`.
2. Note the IA: filter controls, live toggle placement, line layout (timestamp/instance/message), autoscroll behavior.
3. Record in the milestone README which Render filters bex-api honors vs. omits, so the UI doesn't offer controls the backend can't serve.
