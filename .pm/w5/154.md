# Workspace-wide environment reads scan the whole environments table

Why: `environments` has no index on `tenant_id`; its only index is `UNIQUE (project_id, name)` (`migrations/0019_environments.up.sql`). Every read scoped to a workspace therefore scans every workspace's environments, and the cost grows with the platform, not the workspace.

- **Where:** `lego/backend/internal/store/environments.go` `ListWorkspaceEnvironments` (`tenant_id = $1`, the workspace scope index) and `store/grouping_tx.go` `countWorkspaceGroupings` (the grouping-quota count every project or environment create runs). `apps` has `apps_tenant_id_idx` (`0001_core.up.sql`); environments never got one.
- **Fix:** a migration adding `environments_tenant_id_idx ON environments (tenant_id)`. Check whether the migration runner allows `CREATE INDEX CONCURRENTLY` (no repository migration uses it yet), and size the table in production first.
- **Test:** the migration's up/down round-trip, plus an `EXPLAIN` in the store's real-DB suite showing `ListWorkspaceEnvironments` uses the index.
