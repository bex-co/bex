## Objective

Add the missing GraphQL write path for cron fields: a mutation that updates `schedule` and/or `command` on an existing cron job, delegating to the same core update verb REST `PATCH /v1/services/{id}` already uses — one core, thin adapters (docs/ADR006-bex-api.md). No new business logic; the adapter only.

## Context

- REST `PATCH` already threads `schedule`/`command` (top-level or under `serviceDetails`) — find the core verb it calls in `lego/backend/internal/apps/` and reuse it verbatim.
- Naming precedent for narrow setters: `setRootDir` (w1/m18), `setAutoDeploy` (w2/m9) — follow that convention (e.g. `setCronSchedule(id, schedule, command)`) unless Render's captured dashboard operations suggest a name to mirror.
- Validation must be identical to REST's (same cron-expression check, same 4xx for non-cron services) — assert by delegation, not duplication.
- New Go files carry the Apache-2.0 boilerplate header.
