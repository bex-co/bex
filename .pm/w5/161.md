# `/auth/error` is a 404 — every Kratos self-service error lands on Not Found

Why: Kratos sends every self-service error (an expired login or sign-up flow, a CSRF mismatch, a used recovery link) to the dashboard's `/auth/error`, and no such route exists, so a user mid-sign-in sees the generic Not Found page with no message and no way back.

- **Where:** Kratos's `selfservice.flows.error.ui_url` is `https://dashboard.bex.co/auth/error` (`deploy/gitops/base/values/kratos.values.yaml:206`; local overlay `deploy/gitops/overlays/local/values/kratos.values.yaml:55`), and Ory Elements is configured with `error_ui_url: "/auth/error"` (`dashboard/src/common/lib/ory/config.ts:45`). `dashboard/src/routes/` has no `auth.error.tsx`, so the `$.tsx` catch-all renders `NotFoundPage`. This is ADR075 D4's leftover; nothing on the board owns it.
- **Fix:** add `dashboard/src/routes/auth.error.tsx` and `features/auth/pages/error-page`: read `?id=`, fetch `GET /self-service/errors?id=<id>` from Kratos through a server fn (the same-origin pattern the other auth pages use), and render the error's message inside `AuthPageShell` with a "Back to sign in" link (`/auth/login`). An unknown/expired id, or none, shows a generic "Something went wrong signing you in" with the same link. Add en/zh strings, a `translatedTitleHead`, and a `pendingComponent` skeleton that matches the ready state (AGENTS.md skeleton rule; follow `routes/auth.account-deleted.tsx`).
- **Test:** route/page tests for a Kratos error with a message, an unknown id (Kratos 404), and no id; each renders the shell with the link, never Not Found. `yarn typecheck && yarn lint && yarn test` green.
- **Live check:** on dev-5, open a stale login flow (`/self-service/login/browser` then expire or reuse it) and confirm the redirect lands on the new page.
