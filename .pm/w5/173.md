# A service, Postgres or Key Value created through the API can have a free-form name

Why: Render's REST create takes a free-form `name` (it labels the resource; Render derives the slug). bex's REST, GraphQL and MCP creates refuse anything outside ADR020's slug rule (`RESOURCE_NAME_INVALID`). So a Render client creating `My API` gets a 400 on bex. w5/m150 made Blueprint names free-form.

- Parity-sufficient shape: map a free-form create `name` onto a resource name with `blueprintResourceSlug` (`lego/backend/internal/apps/blueprint_names.go`). A service keeps the original as `spec.displayName`, as a Blueprint service now does.
- Datastores have no display name yet (`Database.spec.name` and `KeyValue.spec.name` are CRD-constrained slugs). Free-form datastore labels need a display-name field. This overlaps blocked w5/m118's naming work; under ADR008's parity-first rule, ship the parity-sufficient mapping and leave the stricter variant to m118.
- Guard: `TestAnInvalidResourceNameIsCodedOnEverySurface` (`lego/backend/internal/api/resource_name_code_test.go`) still asserts the refusal on REST, GraphQL and MCP. Flip it when this ships.
- Found by w5/m150 (2026-10-21).
