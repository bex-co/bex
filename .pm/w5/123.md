# Billing, payment-gate, sandbox-exec and Postgres-CA refusals carry their dependency's error text

Why: w5/112 stopped the metrics reads from sending a failed lookup's text inside METRICS_UNAVAILABLE. Eleven more sites in five files wrap a dependency's error into a public unavailable sentinel with `%v`. `core.WriteErr`, GraphQL and MCP then send that text to the client: provider responses, store errors that can name a database host, and stream errors that can name internal addresses.

- **Sites** (`fmt.Errorf("%w: %v", core.Err…Unavailable, err)` or a near variant):
  - `lego/backend/internal/billing/service.go`: three in `Status` (provider readiness, onboarding and lifecycle reads), plus the hosted-session provider error near line 278, which already logs its cause;
  - `lego/backend/internal/billing/payment_gate.go:47`: "read payment-method marker", a store error;
  - `lego/backend/internal/workspaces/service.go:420, 448, 488, 504`: workspace-creation billing setup, verify and contract calls;
  - `lego/backend/internal/sandbox/exec.go:422`: "sandbox exec stream failed";
  - `lego/backend/internal/postgres/service.go:919`: a malformed server CA's parse error.
- **Not a leak:** `agentsession/model.go:298`. Its internal HMAC endpoint writes only the status text (`serveSignedMint`), and `TestModelMinterFailsClosedOnStoreError` pins the classification (checked in w5/112).
- **Fix:** log the cause and return the refusal without its text. For each site, decide between two answers:
  - keep the code and drop the text. A billing provider outage is "unavailable", and the dashboard decides by `BILLING_UNAVAILABLE`.
  - return the error unclassified, so it is logged and answered as "internal error", as w5/112 did for a failed router lookup.
- **Test:** each site's failure answers a message without the dependency's text on REST, GraphQL and MCP, and keeps its code where the code stays.
