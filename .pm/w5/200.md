# MCP `get_metrics` accepts empty `metricTypes: []` without authorizing, and `workspaceId: null` reports empty instead of non-string

Why: Calling `get_metrics` with `metricTypes: []` skips the per-metric loop in `metrics/mcp.go:314-340`, bypassing resource authorization and returning a 200 `{metrics: []}` instead of upstream Render's `"at least one metric type must be specified"` error (`render-oss/render-mcp-server@a18ef3ee` `pkg/metrics/tools.go:145-147`); and passing `workspaceId: null` in `api/mcp_workspace.go:225-231` falls through Go's `json.Unmarshal("null", &s)` no-op to `"workspaceId cannot be empty"` instead of `"workspaceId must be a string"` (upstream `pkg/validate/params.go:41-44` rejects `null` as wrong type).

**Source:** `/pm-brainstorm one aspect of render parity in backend for w5` (2026-11-23, round 12 item 3 — verified core), verified against `render-oss/render-mcp-server@a18ef3ee` (`pkg/metrics/tools.go:145-147`, `pkg/workspace/tools.go:62-71`, `pkg/validate/params.go:35-47`) and `main@7c27a28992`. **Estimate:** ~45m–1h.

## Evidence

- **Empty `metricTypes: []` authz bypass + Render parity gap:**
  - Upstream `render-oss/render-mcp-server@a18ef3ee` `pkg/metrics/tools.go:145-147` explicitly rejects empty `metricTypes` with `mcp.NewToolResultError("at least one metric type must be specified")`.
  - In `lego/backend/internal/metrics/mcp.go:302-345`, `checkFanOut` uses `max(metrics, 1)` (`metrics/service.go:539-545`) so `len(in.MetricTypes) == 0` succeeds, then the `for _, metricType := range in.MetricTypes` loop executes zero iterations — skipping `s.MetricsWithQuantiles` / `s.activeConnections` / `s.datastoreAppMetric` (which perform resource authorization) and returning `{resourceId, timeRange, metrics: []}` even for an unauthorized or nonexistent `resourceId`.
- **`workspaceId: null` error classification:**
  - Upstream `pkg/workspace/tools.go:62` calls `validate.OptionalToolParam[string](request, "workspaceId")` (`pkg/validate/params.go:35-47`), which rejects JSON `null` as wrong type (`"parameter workspaceId is not of expected type: string"`), distinct from `""` (`"workspaceId cannot be empty"`).
  - In `lego/backend/internal/api/mcp_workspace.go:225-231`, `json.Unmarshal([]byte("null"), &workspaceID)` succeeds as a no-op leaving `workspaceID == ""`, so `{"workspaceId": null}` answers `"workspaceId cannot be empty"` instead of `"workspaceId must be a string"`.

## Fix

1. In `lego/backend/internal/metrics/mcp.go`, reject `len(in.MetricTypes) == 0` with `fmt.Errorf("%w: at least one metric type must be specified", core.ErrBadRequest)` before the fan-out/resource loop (and verify unknown metric types are also rejected cleanly before skipping authz).
2. In `lego/backend/internal/api/mcp_workspace.go` (`takeMCPWorkspaceID`), check `bytes.Equal(bytes.TrimSpace(raw), []byte("null"))` before `json.Unmarshal(raw, &workspaceID)` so `workspaceId: null` returns `"workspaceId must be a string"` (matching non-string types and upstream's type refusal).
3. Add regression tests:
   - In `lego/backend/internal/metrics/mcp_render_test.go`: `get_metrics` with `metricTypes: []` returns an MCP tool error mentioning `at least one metric type` (both for authorized and unauthorized/foreign `resourceId`), and fails if the guard is reverted.
   - In `lego/backend/internal/api/`: `tools/call` with `{"workspaceId": null}` returns an error containing `"workspaceId must be a string"`, while `{"workspaceId": ""}` still returns `"workspaceId cannot be empty"`.

## Acceptance criteria

- [ ] `get_metrics` with `metricTypes: []` returns an MCP tool error (`isError: true`) matching Render's `"at least one metric type must be specified"` and never returns 200 `{metrics: []}` without authorizing.
- [ ] `tools/call` with `{"workspaceId": null}` returns `"workspaceId must be a string"` while `{"workspaceId": ""}` still returns `"workspaceId cannot be empty"`.
