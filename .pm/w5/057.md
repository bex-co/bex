# 057 — A `dev-N` stack has no resource-metrics source, so the Metrics page cannot be walked locally

Why: three closed milestones (m89 instance selection, m90 CPU/memory percentages, m91 selection persistence) deferred their live walk to "the next QA pass", and `w5/m98` established that no such pass can happen on a `dev-N` stack as currently built — the walk needs enabling work first, not a retry.

- **CPU/memory/instances come from metrics-server**, not Prometheus (`lego/backend/internal/metrics/source.go:44`, `metrics.k8s.io`). The local kind/CAPD cluster has none: `kubectl get apiservice v1beta1.metrics.k8s.io` is **NotFound**.
- **Request metrics need Prometheus**, wired "only when `BEX_PROM_URL` is set" (`lego/backend/cmd/api/main.go:521`). `scripts/dev-env.sh` never sets it, and the cluster's `monitoring` namespace holds only Loki and log-shipper.
- **Do:** install metrics-server in `scripts/mock-cluster.sh` (that alone unblocks the m89/m90/m91 walk, which is about CPU/memory and instance selection). Optionally add a Prometheus plus `BEX_PROM_URL` in `dev-env.sh` if the request-metrics half is wanted too; keep it opt-in like the agent stack if it costs real resources on the shared cluster.
- **Then:** re-run `w5/m98` t002 against the equipped stack, or close those residuals against production instead and say so.
- **Out of scope:** the metrics code itself, which is not in question here.
