## Objective

Make REST, GraphQL, and MCP thin adapters over the same instance-selection and aggregation contract.

## Context

- GraphQL already accepts generic filters and aggregateAllMethod but consumes only part of that vocabulary.
- REST/MCP names must follow published Render shapes where they exist; additional bex fields require documented extension semantics.
- The dashboard consumes the generated backend schema.

## Steps

1. Map supported instance and aggregate parameters on each adapter into the shared query.
2. Use the same validation and error classification; record unsupported and extension shapes explicitly.
3. Regenerate the dashboard schema/operation types using the documented offline codegen flow after the backend schema is final.

## Files

- `lego/backend/internal/metrics/graphql.go`
- `lego/backend/internal/metrics/rest.go`
- `lego/backend/internal/metrics/mcp.go`
- `dashboard/src/features/metrics/api/metrics.graphql`
- `dashboard/src/graphql/definitions.ts`

## Acceptance criteria

- [ ] The same selection and aggregate returns equivalent values, labels, defaults, and errors across all three adapters.
- [ ] INSTANCE and MIN/AVG are honored where advertised; unsupported options are not silently ignored.
- [ ] Generated client types match the schema without manual-only drift.

## Out of scope

- Inventing undocumented Render endpoint behavior or changing unrelated MCP parameters.
- New backend logic inside an adapter.
