## Objective

Implement resource-scoped selection by canonical public instance IDs in the shared metrics query before aggregating values.

## Context

- MetricQuery has no instance-selection field, despite INSTANCE being advertised by discovery.
- metricsQueryInputFromArgs currently ignores INSTANCE filters.
- m87 supplies the identity and compatibility mapping and must close before this task starts.

## Steps

1. Add the smallest explicit selection contract to MetricQuery with bounded cardinality and safe validation.
2. Apply selection consistently to ranged and current CPU/memory and corresponding limit series after resource authorization.
3. Define all-instances omission, empty/unknown/foreign selections, and invalid inputs so no selection silently becomes all instances.
4. Expose historical choices using a bounded selected-window query or already-returned scoped series.

## Files

- `lego/backend/internal/metrics/service.go`
- `lego/backend/internal/metrics/source.go`
- `lego/backend/internal/metrics/graphql.go`

## Acceptance criteria

- [ ] Selecting one public instance yields only its CPU/memory and relevant limit data.
- [ ] Selection works for retained historical instances and remains inside the authorized resource.
- [ ] Invalid or oversized inputs have explicit errors; a foreign/unknown selection cannot broaden results.

## Out of scope

- Reopening m87's identity design.
- Per-instance HTTP instrumentation or a new global instance catalog.
