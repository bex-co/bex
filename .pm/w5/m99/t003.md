## Objective

Make the authority for "should this sandbox exist?" the **live sandbox inventory**, not the session row, so a sandbox is reclaimed even when no row references it.

## Context

- Every existing teardown path starts from a row that still carries `sandbox_id`: `Service.Cancel` (`lego/backend/internal/agentsessions/service.go:1169`), `Service.Delete` (`service.go:795` comment), resume (`service.go:971`), and the reaper (`completion.go:319`).
- A steer blanks the column before teardown is confirmed: `internal/store/agentsessions.go:212` (`SET sandbox_id='', phase=$2, status=$3, turns=turns+1`), with the old id carried only in `agent_session_dispatches.previous_sandbox_id` (`internal/store/agentdispatch.go:39`).
- `sandbox.CleanupAgentDispatches` (`internal/sandbox/agent_dispatch.go:40-86`) already does the right shape — it **lists** the workspace's sandboxes and terminates those matching a dispatch intent — but it only considers sandboxes named by a dispatch row, so an id no row remembers is invisible.
- Live proof: sandbox `271ec9ce-…` exists in `bex ea sandboxes list`, its session `ags-da9p720k98cs738k20c0` is `canceled` and returns no `sandboxId`, and no path reclaims it.

## Steps

1. Add a periodic per-workspace reconcile that lists live sandboxes through the OpenSandbox client (reusing the tenant-key scoping `CleanupAgentDispatches` already uses) and classifies each one against the session table by the `agentsession.LabelSession` metadata the create path stamps.
2. Terminate any sandbox whose session is terminal or absent, honoring the idle grace and the `t001` lifetime bound; leave untouched anything a live session still claims and anything created outside the agent path that is inside its own bound.
3. Make the classification conservative and observable: never terminate on an inconclusive read, and count each class so `t005` can alert on them.
4. Run it on the Completer's existing tick rather than adding a new scheduler.

## Acceptance criteria

- [ ] A sandbox whose session row exists, is terminal, and has `sandbox_id = ''` is reclaimed — the exact production shape; the test fails on `main`.
- [ ] A sandbox with **no** session row at all is reclaimed.
- [ ] A sandbox held by a session in a live phase, and one inside a user-set `timeoutSeconds`, are both left running.
- [ ] A list/read error terminates nothing and is retried on the next tick.

## Out of scope

- Reclaiming sandboxes in other workspaces' namespaces from a single tick without per-workspace key scoping.
- The workspace-delete purger (`internal/sandbox/purger.go`), which stays as-is.
