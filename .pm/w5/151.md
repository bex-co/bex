# Reclaim the build-cache trial's caches left under the old `<repo>-cache` names

Why: w5/m135 moved every App's build cache to `<repo>_cache`, and no App can reach or delete its old `<repo>-cache` content any more. Caches from builds during the w7/047 trial (2026-09-17 to 09-20) stay on Zot's volume until someone removes them. Where an App named `<name>-cache` owns that name, `<name>`'s cache layers stay readable in that App's image repository, and for unlabeled Apps that can be another tenant's.

- **Where:** Zot repositories `<workspace>/<name>-cache` and unlabeled `<name>-cache` that hold a `cache` tag (BuildKit's `cacheTag`). App deletion (`controller/app_controller.go` `deleteRegistryRepo`) no longer touches them, since a per-App credential is denied there.
- **Fix:** a one-time sweep with the registry's builder credential. Delete every `<x>-cache` repository whose name is no App's image repository (`identity.Repo()`, plus the legacy repository of a labeled App that is not yet tombstoned). Where an App owns the name, delete only the `cache` tag, by tag, and never that App's release tags. Record what was removed and its size against the Zot PVC.
- **Gate:** needs production registry access (the builder credential or `kubectl exec` into Zot) and a list of Apps from the production cluster.
- Found by w5/m135's reviews (2026-10-07).
