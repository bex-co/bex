## Objective

Add a branch-list read to bex-api for a GitHub-App-connected repository: given a service (or owner/repo), return branch names via the App installation token, paginated/bounded, with a clear "not connected" result when the App integration isn't configured or the repo isn't reachable through it. GraphQL is the primary consumer (dashboard); mirror on REST/MCP only if the parity check (t004) finds Render exposes an equivalent public verb.

## Context

- GitHub App plumbing: `docs/ADR026-github-integration.md`; existing repo-listing verb behind `use-repos.ts` (create wizard, w5/m15) shows the installation-token pattern to follow in `lego/backend/internal/` (github integration package).
- Env gating: `BEX_GITHUB_APP_ID`/`_PRIVATE_KEY`/`_SLUG` unset ⇒ 503 like other git-connect verbs.
- AuthZ: same `AuthorizeApp` scope as reading the service's settings.

## Steps

1. Add the branches call to the github integration client (list branches, cap + paginate).
2. Expose a GraphQL query (service-scoped) with a `connected: false` degrade signal.
3. Splice dashboard codegen types per-feature (never full-codegen `definitions.ts`).

## Files

- `lego/backend/internal/` github integration + GraphQL adapter
- `dashboard/src/features/services/api/` (new .graphql) + definitions splice
- backend tests alongside

## Acceptance criteria

- [ ] Connected repo returns real branch names; unconnected returns the degrade signal (not an error page).
- [ ] Unset GitHub App env ⇒ 503, matching the other git-connect verbs.
