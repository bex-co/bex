# Tier B upgrade: customer-key encryption for Barman-backed Postgres (ADR050 follow-up)

ADR050 Tier B (`docs/ADR050-encrypted-platform-backups.md`) leaves the Barman Cloud plugin-backed Postgres archives (`bex-db`, tenant Postgres, auth DBs) on provider SSE (`encryption: AES256`) only — weaker than the Tier A client-side `age` encryption on etcd/OpenBao/KeyValue, because SSE decrypts transparently on any authenticated `GetObject`.

True client-side / customer-managed-key encryption for that path needs one of:

- upstream `plugin-barman-cloud` support for SSE-C / customer-supplied keys (track the project), or
- an encrypting S3-compatible proxy in front of Wasabi for the Barman path only.

Confidentiality for Tier B currently rests on the write-only per-store credential (ADR050 §3), not on a key bex holds. Re-open when upstream adds a customer-key option or the proxy is judged worth its operational cost.
