# Every buildpack release builds with an empty cache

Why: kpack's registry cache exists to carry buildpack layers (dependencies, toolchains) from one build to the next, but its tag carries the release revision, so a release's build never finds an earlier release's cache. Every buildpack deploy pays a cold build.

- **Where:** `lego/operator/internal/build/kpack.go` `KpackImage` sets `cache.registry.tag` to `o.KpackImageRef() + "-cache"`, and `KpackImageRef` (`build.go`) ends in the release revision, so the tag is `<repo>:gen-N-cache`. Each release's Image builds once (webhook and deploy triggers pin a commit), so its cache is never read back. The Dockerfile/native path shares one per-App cache across releases (ADR060 §D3), and ADR060's context still describes kpack's cache as working.
- **Fix:** give the kpack cache one per-App tag, so release N+1 restores what release N saved, inside the App's own ACL-scoped repository. Check what Zot retention (`BEX_ZOT_RETENTION_COUNT`) does to it.
- **Test:** two releases of one App configure the same kpack cache tag; two Apps never share one.
