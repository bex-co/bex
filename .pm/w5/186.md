# 186 — A removed member's running agent turns keep pushing and spending for up to 4 hours

Why: removing a member revokes their API keys but not their in-flight agent sessions, so a removed developer's running turn keeps `contents:write` on its branch and keeps spending model credit until `BEX_AGENT_TURN_TIMEOUT` (4 h in production).

- **Source:** security review round 24 (w5/m371, ADR107), agent-plane hardening note H-3. Not an exploitable finding: everything after the turn (steer, spawn, resume, the next automation fire) is already refused.
- **Evidence:** member removal revokes keys (`lego/backend/internal/members/service.go`, `Remove`); the git and model mints check only the session phase (`lego/backend/internal/agentsession/mint.go`, `CurrentSandboxCaller`).
- **Fix:** when a member is removed (or leaves), cancel the live sessions whose `created_by` is that subject, through the same path as `POST /v1/agent-sessions/{id}/cancel`, and record it on each session. Devin ends a removed seat's sessions too.
- **Size:** ~45m plus a test (remove a member with a running session → the session is canceled and its next mint is refused).
