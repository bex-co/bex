# Two git-proxy tests read their captured log while the proxy may still be writing it

Why: `TestGitProxyResponseBudgetAbortsLoudly` and `TestGitProxyUpstreamStreamErrorAbortsLoudly` point the global logger at a `bytes.Buffer`, then assert on it once the client sees the truncated response. The proxy's handler can still be logging at that point, so `go test -race` fails both tests with a data race. Without `-race`, the log assertion can fail intermittently whenever the handler logs after the client has finished reading.

- **Where:** `lego/backend/internal/sshgateway/agentcred/agentcred_test.go` (the two tests, about lines 683–745), added with w5/m83.
- **Fix:** let the handler finish before reading the log. `front.Close()` waits for outstanding requests, so calling it before the assertions is enough; a mutex-guarded writer also works.
- **Test:** `go test -race -count=20 ./internal/sshgateway/agentcred/` passes.
- Found while verifying w5/131 under `-race` (2026-10-07).
