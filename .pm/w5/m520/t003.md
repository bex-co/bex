## Objective

Request lines, most of the busiest service's volume, are prefiltered too when a term can be proven to need bytes that are in the stored record; otherwise they are read raw and the Findings say what that costs.

## Context

- `requestLine` (`lego/backend/internal/logs/loki.go`) renders `clientIP="…" requestID="…" responseTimeMS=N responseBytes=N userAgent="…"` from Traefik's stored JSON record; values are `strconv.Quote`d where the stored record is JSON-escaped, and `responseTimeMS` is the stored `Duration` (nanoseconds) truncated to milliseconds, so `12` comes from `12345678` and `0` from any duration under 1 ms.
- A term can match a key name (`clientip`, `requestid`, `responsetimems`, `responsebytes`, `useragent`) on nearly every line, or span two fields (`12 user` across `responseBytes=12 userAgent`).
- A line that is not an access record, or carries none of the fields, is returned as stored.
- w5/m503 Findings cause 5: `| json` over every request line of a week is about 13 s of Loki time, so rendering the message in LogQL must beat reading raw lines in t001's timing before it is chosen.

## Steps

1. Define the terms that can only fall inside one quoted value, with no `"`, `=` or `\`, no key-name overlap and no field-spanning form, and match those against the stored record's bytes with t002's class sequence. Digit-only terms and every other shape read raw.
2. Or, if t001 shows a LogQL rendering is cheaper and provably a superset of `requestLine`'s output, use it instead.
3. Record the rule and its proof in the Findings.

## Files

- `lego/backend/internal/logs/loki.go`, `service.go`

## Acceptance criteria

- [ ] Every rendered request line Go matches unfiltered passes the request-stream filter, for a corpus that includes `responseTimeMS=12`, a duration under 1 ms, a user agent with `"` and `\`, a record with missing fields and a line that is not JSON.
- [ ] `go test ./...` in `lego/backend` passes.

## Out of scope

- Changing how a request line is rendered or stored.
