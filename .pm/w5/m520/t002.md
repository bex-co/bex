## Objective

A `text` read sends Loki a line filter that keeps every stored line whose message Go's matcher could accept, and drops the rest, so bex-api decodes only candidates. Go's matcher still decides each line.

## Context

- `NewLokiSource` and `lokiPipelineFor` (`lego/backend/internal/logs/loki.go`) build the query; today the pipeline only carries the `path`/`host` stages, and `localTextSearch()` (`service.go`) sends every `text` read to Loki unfiltered.
- `matchesText` lowercases the message with `strings.ToLower` and tries each normalized term (`normalizeLogText`, `textMatcher` in `filterpattern.go`): a literal is a substring of the lowercase message, a value with `*` is a wildcard over it, `/…/` is an RE2 regex over the message as written. The terms are ORed.
- Go's `strings.ToLower` maps exactly two non-ASCII runes to ASCII: U+0130 to `i` and U+212A to `k` (checked 2026-11-19 over every rune). Invalid UTF-8 becomes U+FFFD. So an ASCII-only literal `t` matches a lowercase message exactly when the stored text matches the sequence of classes `[cC]` per letter, `[iI\x{0130}]` for `i`, `[kK\x{212A}]` for `k`, and the byte itself otherwise.
- The message is the stored line, or the stored line less one trailing `\n` and `\r` (`canonicalHistoryMessage`), except: a message over `maxLogMessageBytes` (64 KiB) is cut and gains ` …[truncated]` (`capLogMessage`), so a term can match across the cut or inside the marker without the stored bytes containing it; a request line's message is rendered from JSON (t003).
- `scanLokiWindow` decides coverage from what Loki returns (`textScanPage`'s saturation and edge rules count the lines read); check that they still hold when those lines are prefiltered.

## Steps

1. Build the filter from the normalized terms: ASCII-only literals and wildcard parts as class sequences (a wildcard keeps its longest literal part, or all parts in order), ORed across terms.
2. Send no filter when any term is outside the proven set: non-ASCII, a `/…/` regex (unless t001 shows a safe rule), `textMode=display`, or a term that can match the cap marker or across the cut. Write the reason next to each case.
3. Apply it only to the non-request streams until t003 lands (for example, by reading request and other streams as separate selectors, or by leaving the read unfiltered when request lines are in scope).

## Files

- `lego/backend/internal/logs/loki.go`, `service.go`, `filterpattern.go`

## Acceptance criteria

- [ ] For a corpus of stored lines and terms (including U+0130, U+212A, invalid UTF-8, a line over the cap, ANSI text in display mode), every line Go matches unfiltered passes the filter, checked with Go's `regexp` and on the pinned Loki.
- [ ] A read's matches, order and paging fields are unchanged; `go test ./...` in `lego/backend` passes.

## Out of scope
