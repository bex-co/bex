## Objective

Tests prove the prefiltered read returns exactly what the unfiltered Go match returns, and fail when the filter drops a line Go would keep.

## Steps

1. A property or fuzz test: for random stored lines and terms (ASCII, U+0130, U+212A, invalid UTF-8, wildcards, regexes, display mode, over-cap lines, rendered request lines), any line Go's matcher accepts passes the LogQL filter, evaluated with Go's `regexp` (Loki's engine).
2. Read-level tests on the fake frontend and on the pinned Loki (`BEX_TEST_LOKI_URL`): a prefiltered search returns the same lines, order and paging fields as an unfiltered one, including across a split cut and a saturated raw page.
3. Prove each test is real: weaken the filter (drop the U+212A class, or filter request lines by key name) and watch it fail.

## Acceptance criteria
