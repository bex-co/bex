## Objective

Generate the one `age` keypair ADR050 §1 specifies, commit the public half, and custody the private half exactly like `BAO_ROOT_TOKEN`/`BAO_UNSEAL_KEY_*`.

## Context

- `docs/ADR050-encrypted-platform-backups.md` §1.
- `.env.example` currently mirrors `.env`'s variable names value-less (CLAUDE.md sync rule).
- `scripts/gh-secrets.sh:32-38` lists the credential keys it pushes into GitHub Actions secrets.
- `docs/ADR019-infra-credentials.md` §`.env`: the out-of-band bootstrap store — the custody pattern to mirror.

## Steps

1. `age-keygen -o /tmp/age-backup-key.txt` (never commit the raw output file).
2. Add `AGE_BACKUP_PUBLIC_KEY` (the `age1…` value, safe to commit) to `.env.example` with a comment pointing at ADR050.
3. Add `AGE_BACKUP_PRIVATE_KEY` to `.env.example` as a value-less placeholder line, and to `scripts/gh-secrets.sh`'s credential list (same `for s in … ; do` loop).
4. Write both values into the operator's local `.env` (out of band — never printed, never committed).
5. Run `scripts/gh-secrets.sh` to push the private key into GitHub Actions secrets.

## Files

- `.env.example`
- `scripts/gh-secrets.sh`

## Acceptance criteria

- [ ] `AGE_BACKUP_PUBLIC_KEY` and `AGE_BACKUP_PRIVATE_KEY` both appear in `.env.example`, value-less, with an ADR050 pointer comment.
- [ ] `scripts/gh-secrets.sh`'s credential list includes `AGE_BACKUP_PRIVATE_KEY`.
- [ ] The private key never appears in git history, command output, or logs.
- [ ] `gh secret list` (or equivalent) confirms the key landed in GitHub Actions secrets.

## Out of scope

- Baking the public key into the CronJob manifests (t002–t004).
- Key rotation tooling (ADR050 Follow-ups).
