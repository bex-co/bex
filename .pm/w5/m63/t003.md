## Objective

Insert the same `age`-encrypt step into the `openbao-backup` CronJob, ahead of its `upload` container.

## Context

- `deploy/gitops/charts/openbao-backup/cronjob.yaml` — shape: `snapshot` (bao raft snapshot save) initContainer → `compress` (busybox gzip) initContainer → `upload` (aws-cli) container.
- `docs/ADR050-encrypted-platform-backups.md` §Recovery flow notes OpenBao restore is now three secrets deep (reader credential → age key → original Shamir unseal keys) — this task only adds the transport-encryption half; the Raft snapshot underneath is already encrypted by OpenBao's own master key (ADR015) and is unaffected.

## Steps

1. Add an `encrypt` initContainer after `compress`, before `upload`, mirroring t002's shape: `age -r <public-key> -o /backup/openbao-snapshot.snap.gz.age /backup/openbao-snapshot.snap.gz`.
2. Change the `upload` container's `s3 cp`/`ls`/`rm` targets from `openbao-$ts.snap.gz` to `openbao-$ts.snap.gz.age`.
3. Update the header comment to note the added transport-encryption layer sits on top of OpenBao's own at-rest encryption, not in place of it.
