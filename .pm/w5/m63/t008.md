## Objective

Add the age-decrypt step ADR050 §Recovery flow specifies to the three Tier A restore scripts, sourcing the new reader credential and the custodied private key from `.env`.

## Context

- `scripts/restore-etcd.sh`, `scripts/restore-openbao.sh`, `scripts/restore-keyvalue.sh` each currently: fetch the latest object from S3 (today via the shared root credential), check gzip/integrity, then run their store-specific recovery mechanics.
- Post-t007, fetching must use the `<store>-backup-reader` credential; post-t002/t003/t004, the fetched object is `.age`-wrapped and must be decrypted (`age -d -i <private-key-file>`) before the existing gzip/integrity check.
- **OpenBao is three secrets deep, not one**: reader credential (fetch) → age private key (unwrap transport) → original `BAO_UNSEAL_KEY_1..3` (unseal the restored target, unchanged from ADR015). `restore-openbao.sh` must apply these in this order and the runbook prose in `docs/ADR015-openbao-backup-restore.md` should make that explicit.
- `DRY_RUN=1` must still cover the new fetch+decrypt step as read-only/local-only, consistent with every other step in these scripts (`docs/ADR031-platform-data-backup.md` §Restore runbooks' shared contract).
- Never place the private key or any credential value in argv; source from `.env`/environment only, matching every existing pattern in these scripts.

## Steps

1. In each script, replace the S3 fetch step's credential source with the new `<store>-backup-reader` values from `.env`.
2. Insert an `age -d` decrypt step immediately after fetch, before the existing gzip/integrity check, writing to the same local scratch dir these scripts already use and clean up.
3. Update `restore-openbao.sh`'s prose/step-ordering (and `--help` text if present) to make the three-secret sequence explicit.
4. Update the `docs/ADR011-etcd-backup-restore.md` / `docs/ADR015-openbao-backup-restore.md` / `docs/ADR021-keyvalue-management.md` restore sections' example commands if they show literal step sequences that are now stale.

## Acceptance criteria

- [ ] `DRY_RUN=1` for each of the three scripts fetches with the reader credential, decrypts, and reports the same read-only guarantees as before — no Kubernetes or S3 mutation.
- [ ] A confirmed run (`--confirm …`) for each store successfully restores from a live `.age`-encrypted backup produced by t002/t003/t004.
- [ ] `restore-openbao.sh`'s three-secret order is explicit in its own output/comments, not just in ADR050.
- [ ] No credential or key value appears in argv, stdout, or logs during any of the three restores.
