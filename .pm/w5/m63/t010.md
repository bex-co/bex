## Objective

Prove the whole ADR050 mechanism end-to-end in production (or a faithful staging equivalent), mirroring the rigor of the existing 2026-07-31 all-store restore drill (`docs/drills/2026-07-31-scripted-restore-e2e.md`).

## Context

- `docs/ADR031-platform-data-backup.md` §Drill records / §Re-drill cadence is the precedent to extend: this drill adds a decrypt-then-restore proof for Tier A and a reader-credential proof for Tier B on top of what that record already covers.
- Every recovery target must be a new `restore-*` namespace with the existing confirm-token gate; no live/in-place restore mode exists or should be added.
- Never put personal/secret data in drill markers or records (existing convention across all drill docs).

## Steps

1. For etcd, OpenBao, and paid KeyValue: trigger a fresh backup, confirm the uploaded object is `.age`-encrypted and unreadable without the private key (attempt a decrypt with a wrong/absent key and confirm failure), then run each store's `restore-*.sh` to a confirmed completion using only the reader credential + the custodied age key.
2. For `bex-db`, one tenant Database, and one auth DB (e.g. `kratos-db`): confirm the fresh backup object carries the SSE header, then run `restore-postgres.sh` to a confirmed completion using only the reader credential.
3. Confirm every writer credential used above genuinely cannot `GetObject` (attempt one, expect denial) as a final belt-and-suspenders check alongside t006's `verify`.
4. Tear down every drill resource (source markers and recovery targets) per the existing scripts' `--teardown-on-success` contract.
5. Write the drill record following the existing format (`docs/drills/YYYY-MM-DD-….md`) and link it from ADR031 §Drill records.

## Acceptance criteria

- [ ] All five stores show a confirmed restore using only reader credentials (never a writer Secret).
- [ ] Tier A backups are demonstrated unreadable without the age private key.
- [ ] Writer credentials are demonstrated unable to `GetObject`.
- [ ] Every drill resource (source and recovery target) is removed by drill's end; the platform ends healthy.
- [ ] The drill record is committed and linked from ADR031.

## Out of scope
