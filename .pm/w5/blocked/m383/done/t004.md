## Objective

Imports across all workspaces together cannot fill the shared registry: a new import that would take the platform's imported bytes past a budget is refused.

## Context

- `lego/backend/internal/store` `CreateSandboxBuild` (round 24: declared size, workspace advisory lock, `SandboxStorageLimitError`); `sandbox/storage_cap.go`.
- `deploy/gitops/base/zot.yaml` (`storage: 100Gi`); `lego/backend/cmd/api/config.go` (env), `lego/operator/AGENTS.md`/`lego/backend/AGENTS.md` env inventories, `.env.example` if a secret.

## Steps

1. Add `BEX_SANDBOX_IMPORT_PLATFORM_BUDGET_BYTES` (default 80 GB, below the 100 Gi volume) and document it with the backend env inventory.
2. In `CreateSandboxBuild`, under a platform-wide advisory lock, sum the declared sizes of non-failed imports in every workspace and refuse one that would pass the budget.
3. Map it to 429 with a named code on REST, GraphQL and MCP.
4. Confirm the production registry volume's live size (it may have been grown out of band) and record it; adjust the default if needed.

## Acceptance criteria

- [x] Real-Postgres test: imports in two workspaces together past the budget are refused; a failed import frees its bytes; a repeated import is not refused.
- [ ] The production volume's size is recorded.

## Outcome (2026-11-13)

`BEX_SANDBOX_IMPORT_PLATFORM_BUDGET_GB` (default 80; 0 disables) and a per-workspace share (a quarter): `CreateSandboxBuild` sums imported bytes under the workspace lock, then the platform lock, and refuses past either; the service answers 429 `SANDBOX_IMPORT_CAPACITY` and counts it (`bex_sandbox_concurrency_refusals_total{limit="platform",op="import"}`). Documented in `lego/backend/AGENTS.md` and `.env.example`; ADR018 records the divergence awaiting sign-off. Test: `TestImportStaysUnderThePlatformBudget` (real Postgres). Step 4 (the production volume's size) is open; see README § Findings.
