## Objective

A scope table that names, per surface, its entry points, trust boundaries, assets and the attacker it must withstand, so the audits are complete and not anchored on one area.

## Context

- The surface list in the milestone README § Source + Goal linkage; ADR085 and ADR084 for the previous rounds' shape.
- Exclusions: ADR103's rewrite proxy (reviewed 2026-11-10); the accepted residuals in `.pm/DO_NOT_DO.md` (#PSL, #CI-RUNNERS, #RUNNER-HOSTS, #ENV-REVIEWERS, #APPROVAL-MODE); repository settings (w3/m365).

## Steps

1. One row per surface: code paths, entry points (REST/GraphQL/MCP routes, gateway, GitHub webhooks, scheduler), the identity it runs as, the secrets it touches and the tenant boundary it must keep.
2. Mark the questions each audit must answer (for example: cross-workspace access by id, token scope and lifetime, secrets in transcripts or logs, run-as identity of scheduled work, untrusted input from PR comments, SSRF from image import, path traversal in attachments).
3. Put the table in the milestone README under `## Scope`.

## Acceptance criteria

- [ ] Every surface in the README is either in the table or excluded with a reason.
