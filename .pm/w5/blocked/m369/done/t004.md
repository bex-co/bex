## Objective

A deploy with no build window (prebuilt image, restart, rollback, config-change rollout, reuse of the active artifact) has `started_at` equal to the operator's dispatch of its own release generation, `status.releaseStart.startedAt`; the observing pass's clock is used only when that record is absent.

## Context

- w4/609 (now `w4/done/609.md`): probes, consumers and blast radius.
- `recordDeploy`'s evidence-backed start (`lego/backend/internal/store/reconciler.go`) uses only `buildRunStart` for `DeployPreDeployInProgress`/`DeployUpdateInProgress`; `releaseDispatchStart` is used only for `DeployLive` (w4/449).
- `TransitionDeploy` stamps `COALESCE(started_at, $9, clock_timestamp())` (`lego/backend/internal/store/store.go`; `DeployStatusStampsDispatch`, `deploy_lifecycle.go`).
- The operator writes `status.releaseStart` in `stampReleaseStart` (`lego/operator/internal/controller/release_identity.go`).

## Steps

1. In the pre-deploy and update-in-progress cases, fall back to `releaseDispatchStart(cur, open)` when `buildRunStart` is nil, as the live case does.
2. Clamp the start to no earlier than the row's `createdAt` (second precision); apply the same clamp to the live-case fallback.
3. Leave `DeployBuildInProgress` alone.

## Files

- `lego/backend/internal/store/reconciler.go` (and its tests)

## Acceptance criteria

- [ ] `update_in_progress` first seen with a matching `releaseStart` → that start, clamped to `createdAt`; another generation's `releaseStart` → the clock; a row with a build window keeps `buildRunStart`; an already-stamped `started_at` never moves.
- [ ] w4/449's live-close and w4/316's pre-deploy-failed cases stay green.

## Out of scope
