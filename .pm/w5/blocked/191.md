# Remove the pre-w5/187 body-only MAC fallback from hmacticket once the previous release's tickets have expired

Why: w5/187 binds each ticket flavor's name into its MAC, and `hmacticket.Codec.signedBy` still accepts the body-only MAC the previous release minted, so tickets issued just before the deploy stay valid for their lifetime. Once those have expired the fallback admits nothing and is dead code; until it is removed it keeps the old cross-flavor acceptance alive for any previous-release ticket that is still in date.

**Gate (release, then date):** the first production deploy that pins w5/187 has been live for 24 hours plus the 30 s clock skew (`snapshotticket.TTL` + `hmacticket.ClockSkew`, the longest acceptance window). No user action.

Steps:

1. Drop the second comparison from `Codec.signedBy` (`lego/backend/internal/hmacticket/hmacticket.go`), so only the flavor-bound MAC verifies.
2. Delete `TestOpenAcceptsTheBodyOnlyMACOfThePreviousRelease` and add its inverse: a body-only MAC is refused as `ErrSignature`.
3. Drop the hand-derived per-flavor keys the codec's flavor binding now makes redundant: `connectKey` (`sandbox/connect.go`), `fileConnectKey` (`sandbox/file_connect.go`) and `key` (`sandboxfiles/ticket.go`). Their tokens live a minute to a few minutes, so changing their MAC costs at most one re-mint across the deploy. Leave `drivergrant`'s Ed25519 seed derivation alone (a different signature).
4. Run the ticket suites (`hmacticket`, `shellticket`, `agentsessionticket`, `sandboxexec`, `sandboxfiles`, `snapshotticket`, `sandbox`, `sshgateway/...`).

- **Source:** w5/187 (2026-11-13), the transition it left behind.
- **Size:** ~30m.
