## Objective

Retiring a login (after a leak, say) ends what it can do now, not only what it can do at its next connection, and a restore does not bring it back.

## Context

- `lego/operator/internal/controller/database_controller.go` `managedRoles` (retired users: `ensure: present`, `login: false`, NULL password, applied by CNPG).
- `lego/backend/internal/postgres/recovery.go` (recover to a new instance at a point in time), `postgres/query.go` (bex-api's existing SQL connection to a managed database).

## Steps

1. Find the privileged path to run `pg_terminate_backend` for the retired role's backends (the CNPG superuser Secret from the operator, or a role with `pg_signal_backend`), and run it once the role is NOLOGIN.
2. Carry the retired-login list into a recovery's new Database so the restored instance projects them retired from its first reconcile.

## Acceptance criteria

- [ ] Tests: retirement terminates the role's sessions (envtest or a real Postgres); a recovery's spec carries the retirements.
