# The dashboard still decides four refusals by their wording

Why: w5/m128 moved the log, metrics, secret-store, audit, forbidden and protected-environment decisions onto codes. The dashboard still matches server copy for four more refusals, so rewording one of those bex-api messages still changes what the dashboard shows.

- **Not found.** `isNotFoundError` (`dashboard/src/common/lib/document-head/index.ts`) tests `/\bnot[ -]?found\b/i` against the message.
  - `isEnvGroupNotFound` and the resource-title loaders read it.
  - `logReadAccessDenied` (`features/logs/hooks/use-older-log-pages.ts`) also tests `not found|unauthenticated|unauthorized|session expired`.
  - `core.ErrNotFound` carries no code; only `NewNotFoundError` refusals do.
- **Name conflicts.** These refusals carry only the generic `CONFLICT` code, so the dashboard matches their text:
  - `use-rename-database.ts` and `use-rename-key-value.ts` match `"already exists"`;
  - `use-ssh-keys.ts` matches `"already registered"`.
- **GitHub integration unavailable.** `isGitHubUnavailable` (`features/git/lib/errors.ts`) matches `"not configured"` or `"unavailable"` (`core.ErrGitHubUnavailable`).
- **Shell unavailable.** `use-shell-session.ts` matches `/not configured/i` (`ErrShellUnavailable`).
- **Also: the protected-confirmation dialog's resource name.** `protectedServiceName` (`features/services/lib/protected-confirmation.ts`) regex-parses the name out of the confirm phrase. Since w5/m128, the refusal sends `name` (and `verb`) as params. Reading it means passing `{confirm, name}` through `ProtectedActionResult` and every protected-retry hook, rather than only the phrase.

  - switch each dashboard decision to the code, with `codedGraphQLError` tests and a negative case for the old wording.
  - Expect more than 1h across several refusals, so promote this note when taken.
