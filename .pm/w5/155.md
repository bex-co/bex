# The projects list reads every project's services before it pages

Why: `projects.Service.List` builds a full view of every project in the workspace before any surface filters or pages. A REST page of 20 still makes one `ListProjectServices` query per project, up to the 1000-grouping cap, plus a Postgres and a Key Value list. REST then discards all three: Render's project shape carries none of them.

- **Where:** `lego/backend/internal/projects/service.go` `views` (:295, one `ListProjectServices` per project at :309) under `List` (:330). REST pages after `List` (`rest.go`, `core.StablePage`), and so do GraphQL (`graphql.go:50`) and MCP (`mcp.go:71-77`), which do return `serviceIds`. `apps.project_id` has no index, so each of those queries scans `apps`.
- **Fix:**
  - REST reads the store's projects after the same `AuthorizeWorkspace`, filters and pages them, and renders only the page.
  - GraphQL and MCP batch the services read with `project_id = ANY($1)`, following `ListWorkspaceEnvironmentServices`, or page before `views`.
  - Consider an index on `apps (project_id)`.
- **Test:** a page of two from a workspace of five projects makes no services read on REST, and one batched read on GraphQL and MCP.
