# A `PATCH` of an image service that carries `rootDir: ""` answers 400 "has no repo to build", where Render accepts it

Why: Render's Terraform provider sends every service's `rootDir` on update, `""` for an image service. bex reads any `rootDir` as a request to set a build root, so every update of an image-backed `render_web_service` (and the other image service types) fails.

- **Found by:** w9/m474, dev-9, 2026-11-18 ([checklist](../../docs/terraform-compatibility-checklist.md), class 9). It stops `TestWebServiceResource_Image` at its second step.
- **Render:** `webservice/resource/testdata/web_service_image_cassette.yaml`. `PATCH /v1/services/{id}` with `{"image":{"imagePath":"docker.io/library/nginx:stable-perl",…},"rootDir":"",…,"serviceDetails":{…,"runtime":"image"}}` answers 200.
- **bex:** `400 service "srv-…" has no repo to build (root directory only applies to build-from-git)`, from `lego/backend/internal/apps/settings.go`'s `RootDir` patch field through `settings_check.go` `checkRootDir`, which refuses an image service before comparing the value with the service's own empty root.
- **Done when:** a `rootDir` equal to the service's current one (`""` for an image service) is a no-op on PATCH, a different one is still refused by name, a test covers both, and `TestWebServiceResource_Image` passes its second step.
