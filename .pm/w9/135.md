# Every Key Value proxy roll refuses new internal connections for about a second

Why: a client that connects while a store's `kv-internal-proxy` rolls (enabling internal authentication, a plan change, a credential rotation, an override bump) gets `Connection refused` instead of a connection, although the Deployment surges and the old pod drains.

- **Found by:** w9/m521 t001's dev-9 check, 2026-11-19, on the shared mock cluster with the operator built from the tree. A loop in a same-workspace pod ran `valkey-cli -h <id> -p 6379 PING` every 200 ms while `POST /v1/key-value/<id>/internal-auth` rolled the store's proxy. 29 `PONG`, then 3 `Could not connect to Valkey at <id>:6379: Connection refused` within about 0.6 s, then `NOAUTH` from the new client-mode proxy. The Valkey pod did not restart.
- **Cause, likely:** the proxy pod stops accepting on `SIGTERM` (w6/m512's drain) while its endpoint is still in the dataplane's rules for a moment. w6/m515 found the same on the SNI DaemonSets and gave each old pod a 5 s `preStop` pause before `SIGTERM` ([w6/m515](../w6/done/m515/README.md)). The proxy Deployment (`reconcileKeyValueInternalProxy`, `lego/operator/internal/controller/keyvalue_internal_proxy.go`) has no `preStop`.
- **Careful:** adding a `preStop` changes the proxy's pod template, so it must arrive with the store's own next roll or a reviewed override bump (`kvInternalProxyRollRevision`, w6/m517), never by itself on an operator deploy.
- **Done when:** the same loop during a proxy roll reads no `Connection refused`, the grace period covers the pause plus the drain, and `TestKeyValueInternalProxyRenderingIsPinned` records the change.
