## Objective

The checklist's value is that its cells are re-checkable. Make the ✅ claims reproducible: if a harness script shipped, give it assertable exit behavior for the ✅ rows (a `verify` mode that re-runs them and fails loudly on regression, the `scripts/webhooks-verify.sh` pattern); otherwise ensure the checklist's documented re-run procedure is complete enough that a fresh session can reproduce every cell. Never game this — no tautological checks; a ✅ row's verification must actually exercise the CLI against bex-api.

## Acceptance criteria

- [ ] The ✅ rows are re-verifiable by script or by a complete documented procedure, demonstrated by one actual re-run.
