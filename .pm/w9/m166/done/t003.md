## Objective

Confirm that rejected and successful updates retain the contract each user-facing surface exposes.

## Context

The pinned upstream request and 400 consumer are documented in t001. REST and MCP share one compound patch; GraphQL/dashboard normally save separate settings. RFC 5789 establishes PATCH atomicity, but this hunt did not observe Render production.

## Steps

1. Recheck the same-pin upstream builder/parser and compare equivalent Render API behavior using authorized disposable resources if available; otherwise state the precise evidence gap.
2. Verify REST 400/401/non-disclosing denial/not-found behavior and MCP error semantics, plus valid response shape and CLI stdout/stderr/exit.
3. Check GraphQL and dashboard direct setters keep validation/permission/error behavior. Record any cross-surface drift as a specific follow-up, without inventing an all-or-nothing guarantee across separate mutations.

## Files

- `lego/cli/UPSTREAM_RENDER_CLI.md`, `docs/cli-compatibility-checklist.md`, `docs/ADR006-bex-api.md`
- `lego/backend/internal/apps/{rest,mcp,graphql,settings}.go` and affected dashboard setting forms

## Acceptance criteria

- [x] Valid and invalid compound CLI journeys agree with the pinned consumer; no request rewriting or CLI fork.
- [x] Every exposed API/UI surface is assessed, and unobserved Render behavior is labeled.

## Out of scope

- Adding new API fields or changing upstream flag semantics.

## Result (2026-09-22)

### CLI / pinned upstream

**No CLI change of any kind**: `git status lego/cli/` is empty. The pinned
`render-oss/cli` builder and 400 consumer documented in t001 are untouched, so
there is no request rewriting, no launcher workaround and no fork. The CLI
suite passes.

The pinned-CLI wire contract is pinned by existing tests that still pass:
`TestRESTPatchAcceptsOfficialCLIServiceBody`,
`TestRESTPatchAcceptsOfficialCLISourceFields`, and — directly on point —
`TestRESTPatchRejectsConflictingOrUnknownCLIImageFieldsWithoutMutation`, which
already asserted "reject **without mutation**" for a neighbouring class of bad
PATCH body. This milestone makes that property general rather than special-cased.

### REST

400 body is byte-identical to the one the CLI already consumes —
`TestRESTPatchRejectsBeforeApplyingAnyField` asserts both the status and the
`health check path must start with /` text. Authorization denial and
missing-service responses stay indistinguishable to a stranger
(`TestPreflightKeepsUnauthorizedAndMissingIndistinguishable`), so the earlier
authorization did not add an existence oracle. The success shape is unchanged
(the apply pass and its response envelope were not touched).

### MCP

`update_service` reduces to the same table and is asserted directly:
`TestMCPUpdateServiceRejectsBeforeApplyingAnyField` (error result, no rename),
plus the pre-existing `TestMaintenanceModeMCPPlanTransitions` and
`TestUpdateServiceLeavesOmittedFieldsAlone` still pass.

### GraphQL and dashboard

GraphQL does **not** use the patch table — it drives 24 individual setters
(full list in t002), which is what the dashboard's per-setting Settings forms
consume. Those keep their own policy and error contracts, and no all-or-nothing
guarantee was invented across separate mutations.

The risk the refactor introduced here is drift: the guards now live in
`settings_check.go`, called by BOTH the setter and the preflight. Two things
contain it — the shared function makes rule-level drift structurally impossible
(one body, two callers), and `TestEachRowsCheckAndVerbAgree` pins the wiring
per row: for the same input, a row's preflight check and its own verb must
agree on refusal AND on the exact message. That test is mutation-checked
(rewiring one row's check to `return nil` fails it with the
"preflight ACCEPTS what its own verb refuses" message).

### Evidence gap, stated rather than papered over

**Live Render production behavior was not observed**, then or now. RFC 5789 §2
requires a PATCH document to be applied atomically, and that is the contract
this milestone implements; it is NOT evidence about what Render itself does on
a mixed valid/invalid compound PATCH. No claim is made either way.

Equally, **no live bex run** was performed for this record: no `.env` exists in
this checkout, and t005's acceptance explicitly needs an environment already
running the fix. See t005.
