## Result (2026-09-22)

`/simplify` run over the full milestone diff with its three review passes
(reuse, quality, efficiency). Findings applied:

### A real bug in the fix, caught by all three reviewers independently

The first version of the "don't probe the source twice" optimization keyed a
context marker on the service id and matched it against `metadata.name` and
`LabelServiceName`. But both surfaces address a service by its **srv- id**,
which lives in `LabelAppID` — so on the real request path the marker never
matched, and `GitHub.ValidateRepo` plus the registry-credential resolve ran
**twice** per source-repointing patch. The preflight had doubled bex's outbound
load on someone else's API and nothing noticed, because no test covered the
skip.

Fixed by removing the identity guess entirely: the marker now carries the
resolved `sourceFields` and the skip is gated on **value equality**, so the
probes are reused only for a source byte-identical to the one probed.
`TestSourcePatchProbesOutboundCallsExactlyOnce` pins it, addressed by srv- id
for exactly this reason, and is mutation-checked (2 calls without the fix).

### Duplicated work the preflight had introduced

Validating twice meant asking request-invariant questions twice — and, within
the preflight alone, once per guarded row:

- `GetAppProtectedStatus` — up to 7 guarded rows x 2 passes = **14 identical
  Postgres round trips** for one boolean.
- `hostClaimedElsewhere` — a **cluster-wide List of every App CR on the
  platform**, unbounded in tenant count, now run twice per maintenance-URI patch.

Both now go through a per-request memo (`requestmemo.go`), armed by
`ApplyServicePatch`. `TestPatchAsksProtectedStatusOncePerRequest` pins it:
**8 store reads before, 1 after** (mutation-checked). `RequirePlanBilling`'s
two local reads are also repeated; left alone as negligible.

### Duplication removed

- `sourceFields.applyTo` — the four-field source projection existed in **three**
  places (the credential probe, the preflight probe, the real write). One writer
  now, so a fifth source field cannot reach the write while the probes still
  validate the old four.
- `presentServicePatchRows` — both passes now derive their row set from one
  function, which is the invariant the whole milestone rests on.
- `maintenanceModeSpec` — the view→spec literal was written twice.
- The MCP test boilerplate now uses the package's existing `callAppsMCPError`.

### Tests strengthened

- `TestPreflightAuthorizesEveryRelationTheApplyPassUses` asserted only that the
  verb did not return `ErrForbidden`, which silently stops covering a row if the
  verb ever validates before authorizing. It now records the relations the verb
  actually asks OpenFGA about and asserts they are the declared one (or
  `can_view`). Still mutation-checked per row.
- `TestEachRowsCheckAndVerbAgree` was not covering the source or autoscaling
  rows in the ALLOWED direction — the two most complex checks. Both added.
- `ptrInt32`'s `-1` sentinel conflated "unset" with "set to -1" (and collided by
  name with an inverse helper in `store`); replaced with `sameInt32Ptr`.

### Comments

Cut the rationale that had been retold four times down to one canonical telling
on `preflightServicePatch`, with pointers from the others; deleted a guard
comment that had been copied to `setMaintenanceMode` rather than moved with its
guard; dropped two per-row restatements of the struct doc, the task-id prefixes,
and a comment hard-coding table row ordinals that would rot on the next insert.

### Not applied

- Dropping `id` from the `check` signature (suggested: derive the name from the
  probe). The 5 rows that use `id` use it in error text, and the verb builds the
  same text from the caller-supplied name — deriving it differently would break
  the byte-identical-message property `TestEachRowsCheckAndVerbAgree` pins.
- A `discard[T]` generic to collapse 7 four-line adapters, and bundling the
  check parameters into a struct. Both trade explicitness for brevity against
  the surrounding style.
- `AuthorizeAppFresh` to save one App fetch on the second relation: it skips the
  denial audit, so it would need an audited variant for a 1-fetch saving.

### Verification after simplifying

Full backend suite, CLI suite and `make lint` (all four modules, incl.
whole-program dead-code) green. The whole regression set was re-mutation-checked
after the cleanup: with the preflight removed, **11 cases across 5 test
functions fail**, so none of them was weakened by the refactor.
