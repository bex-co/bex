## Objective

When the platform pauses an automation — `repeated_failures`, `creator_lost_access` or `template_invalid` — notify its creator by push, an inbox entry and an email, whatever the email setting. Today both pause sites only write a log line.

## Context

- ADR101 D7 (`docs/ADR101-agent-automations.md:135`): 'The creator gets the existing push notification, and the dashboard shows the reason and a Resume button.'
- Pause sites: `lego/backend/internal/agentsessions/automation_scheduler.go:142` (`retireUnschedulable`, `template_invalid`) and `:276-283` (`repeated_failures`, `creator_lost_access`) — each only calls `log.Printf`.
- No notification code mentions automations (`grep -rni automation lego/backend/internal/notifications` → nothing, checked 2026-11-12).

## Steps

1. Add one `notifyAutomationPaused(ctx, automation, reason)` called from both sites after `SetAgentAutomationPaused` succeeds (not for a schedule that merely finished).
2. Push through the existing push adapter, write an inbox entry, and send the email with the reason in words and a link to the automation's page (where Resume is).
3. Idempotent per (automation, pause transition), so a recovery pass or a second replica does not notify twice.

## Files

- `lego/backend/internal/agentsessions/automation_scheduler.go`
- `lego/backend/internal/notifications/push_adapter.go`, `inbox.go`, the email worker

## Acceptance criteria

- [ ] Three consecutive `failed_create` runs pause the automation and produce exactly one push, one inbox entry and one email to the creator.
- [ ] A schedule that ends (`errScheduleFinished`) notifies nothing.
- [ ] A creator who lost access is still notified at their email (the inbox entry is skipped if they can no longer see the workspace).

## Out of scope

- Notifying other workspace members.
