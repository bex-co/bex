## Objective

Give every agent automation a `notifications.email` setting that says which run outcomes email its creator, readable and writable the same way on REST, GraphQL and MCP. The default is `on_failure`, Devin's default for scheduled sessions.

## Context

- Devin Automations have an Email notification action with Always / On failure / On success; Devin scheduled sessions offer Always / On failure only (default) / Never (docs.devin.ai/product-guides/automations, docs.devin.ai/product-guides/scheduled-sessions).
- Automation input and view: `lego/backend/internal/agentsessions/automations.go` (validation, view), `automations_rest.go`, `automations_graphql.go`, `automations_mcp.go`.
- Store: `lego/backend/internal/store/agentautomations.go`; the latest migration is `0235_*` (rescan before numbering).
- Existing automations (including the user's eight daily `rt-*` automations created 2026-11-11) take the default on migration.

## Steps

1. Add a `notify_email` column (text, check-constrained to the four values, default `on_failure`) with up/down migrations.
2. Thread it through the store row, the automation view and the create/update input as `notifications: {email: …}`; an omitted field on update keeps the stored value, an unknown value is `AGENT_AUTOMATION_INVALID` with `field: notifications.email`.
3. Expose it identically on REST, GraphQL (input + type) and the MCP create/update/get tools.

## Files

- `lego/backend/internal/store/migrations/0236_agent_automation_notify_email.{up,down}.sql` (next free number)

- `lego/backend/internal/agentsessions/automations.go`, `automations_rest.go`, `automations_graphql.go`, `automations_mcp.go`

## Acceptance criteria

- [ ] A create without `notifications` reads back `email: on_failure` on REST, GraphQL and MCP.
- [ ] An update that sets `on_success` reads back `on_success` on all three; an update that omits it keeps it.
- [ ] `email: sometimes` is refused with `AGENT_AUTOMATION_INVALID` naming `notifications.email`.
- [ ] The real-Postgres store test covers the column default and the check constraint.

## Out of scope

- Slack, other recipients or per-recipient lists (Slack is DO_NOT_DO; Devin's `email.recipients` is a follow-up if wanted).
- Outbound webhook events for runs (ADR101:234 naming decision).
