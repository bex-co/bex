## Objective

Apply the new CRD/operator/API and legacy backfill to every isolated developer environment, then prove each environment can execute a Postgres rename without data-plane identity churn.

## Context

- `.pm/w1/dev-1` through `.pm/w10/dev-10` share the local kind/CAPD cluster and operator but run separate bex-api binaries, control-plane DBs, auth stacks, app namespaces, and ports.
- Reinstalling the shared CRD/operator once is insufficient: each environment's local bex-api must be rebuilt/restarted, and each namespace's legacy Database inventory must be migrated/verified.
- These scripts contain kubeconfig paths and local credentials; outputs must not print kubeconfig or Secret contents.

## Steps

1. Install the generated Database CRD and deploy/restart the shared local operator with the identity-safe code.
2. Sequentially bring up/rebuild `dev-1` … `dev-10` using each environment's own scripts and port block; do not disrupt another namespace while moving to the next.
3. Run the legacy-name dry-run/apply/verifier against every `dev-N` namespace, recording counts and non-secret identity evidence.
4. In every environment, create or select a safe test Database, run the official CLI name update, assert id stability/new-name resolution, then remove only throwaway resources.
5. Record any environment-specific drift as a fix in this milestone rather than accepting partial rollout.

## Acceptance criteria

- [ ] `dev-1` through `dev-10` each report a healthy rebuilt bex-api against the upgraded CRD/operator.
- [ ] Every legacy Database in all ten namespaces has an explicit display name after idempotent migration.
- [ ] Official-CLI rename succeeds in every environment and preserves the resource id/uid and data-plane object names.
- [ ] No other `dev-N` namespace, port, process, or resource is modified while operating on the selected environment.
- [ ] Verification evidence contains no API keys, passwords, `.env` values, or kubeconfig contents.

## Out of scope

- Recreating the shared mock cluster or deleting dev namespaces merely to obtain a clean test state.
