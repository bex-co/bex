## Objective

Extend the PR feedback intake (w9/m344) so that a `/bex` comment on an open PR no session owns starts a session that takes the PR over (t001), as Devin's `/devin` does.

## Context

- `lego/backend/internal/agentsessions/pr_feedback.go`: `HandlePRFeedback` takes `issue_comment` deliveries. `queueHuman` returns early when `FindAgentSessionForPullRequest` finds no session; that is the new branch point. `steeringMember` already checks `write`/`admin` and the linked GitHub id.
- Devin (docs.devin.ai/integrations/gh, 2026-11-12): the command must begin the comment and is case-insensitive. The commenter needs write access and a linked account. Devin replies on the PR with the session link. Issues and closed or merged PRs are ignored.
- `github.CreateIssueComment` (w9/m344) posts the reply. The eyes reaction needs a reactions call.

## Steps

1. Detect `/bex` as the comment's first word, in any case. The rest of the comment is the task, quoted as untrusted text, plus the PR's number, title and URL.
2. Read the PR (head ref, head SHA, head repository). Skip closed and merged PRs. A fork PR (head repository ≠ base) gets a reply that bex cannot push to a fork, and no session.
3. Resolve the member: a linked, write-access commenter who holds `can_create` in a workspace connected to the repository. If several workspaces qualify, take the oldest connection, deterministically. Bots and unlinked commenters start nothing.
4. Create the session as that member with t001's takeover option and the workspace's defaults (agent, spend limit). The idempotency key is the comment id, so a redelivery starts nothing new.
5. React with 👀 and reply with the session's dashboard link. A refusal (spend, trust limit, no model key) is answered in the reply with its hint, and no session.
