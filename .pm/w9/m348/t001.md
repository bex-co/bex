## Objective

Give the service an internal way to create a session that owns an existing pull request: its branch is the PR's head branch, its PR number and head commit are recorded at creation, and the sandbox checks that branch out instead of cutting `bex-agent/<id>` from the default branch.

## Context

- Today every session branch must start with `bex-agent/` (`lego/backend/internal/agentsessions/service.go:491-495`, `agentsession.ValidateBranch`, `agentsession.BranchPrefix` in `contract.go:70`). The store picks `bex-agent/<ags-id>` when the branch is omitted (ADR094 D3).
- The gateway authorizes git pushes and the PR verb for exactly the session's branch (branch-scoped label digests, `sshgateway/agentcred` `authorizeBranch`), so one extra allowed branch keeps the same confinement.
- The PR verb (`agentsession/pullrequest.go`) opens or updates the draft PR for the session's head branch. For a taken-over PR it must update that PR, not open a second one, and must not flip a ready PR back to draft.

## Steps

1. Add an internal create option, not accepted from REST, GraphQL or MCP input: take over PR `number` on `repo`, with head branch `ref` and head commit `sha`. Validate the ref as a git branch name, but skip the `bex-agent/` prefix rule for this path only.
2. Record `pr_number` and `head_sha` on the new session row, so the PR's feedback (w9/m344) finds it.
3. Have the sandbox clone and check out the existing branch at its head; never force-push.
4. In the PR verb, a session that took over a PR updates that PR's title/body only if it opened it; otherwise it leaves them and reports the PR.

## Files

- `lego/backend/internal/agentsessions/service.go` (create path), `lego/backend/internal/store/agentsessions.go`

## Acceptance criteria

- [ ] A takeover session's row carries the PR's branch, number and head SHA; a REST/GraphQL/MCP create with a non-`bex-agent/` branch is still refused.
- [ ] The gateway lets that session push only its PR's branch (tested).
- [ ] The PR verb on a taken-over PR neither opens a second PR nor overwrites a human's title and body (tested).
