## Objective

Verify the unified error shape is consistent across REST, GraphQL, and MCP, and compare against Render's documented error responses (`{"id","message"}` family) — flag any remaining drift as follow-up rather than silently diverging.

## Context

- docs/ADR006-bex-api.md — one core, thin adapters; error shapes listed as part of the compatibility contract.
- docs/cli-compatibility-checklist.md — the official CLI renders API `message` fields on failure; a login with a bad key is the cheapest live probe.

## Steps

1. Exercise representative error paths on each surface (REST 401/400/404/405; GraphQL decode + resolver error; MCP tool error) and record shapes.
2. Run `render` CLI with an invalid key against bex-api; confirm the failure output shows the message (not a raw body dump).
3. File follow-up notes for any drift found; update the CLI checklist row evidence if it changes.
