# 065 — The CLI branding residual inventory in `docs/bex-cli.md` is incomplete

Why: a standing "leave this class alone" decision is only sound if it was taken against the real scope, and the documented sample makes the residual set look like two error strings when it is at least nine — including the single most common error a user hits.

`docs/bex-cli.md:145-156` lists the upstream runtime strings branding deliberately does not rewrite: "They do not rewrite upstream `RunE` bodies, so these residuals remain until an explicit upstream-hook or fork decision." The listed set is the login TUI copy, `ErrLogin`, `ErrNoWorkspace`, the User-Agent, the OAuth client id, the skills path, the login-view update banner, and the analytics notice.

Missing from that list, all verified live on a HEAD build at `7b3ba5b42` against production on 2026-09-21:

| invocation                                  | output                                                                                                                                                | upstream source              |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `bex services update qa-nosuch --name x`     | `… No service named 'qa-nosuch' in workspace tea-…. To search another workspace, run ` + "`render workspace set <name\|ID>`" + `, or pass the service ID instead.` | `pkg/service/repo.go:233`    |
| `bex postgres get qa-nosuch`                 | same shape, "No Postgres database named …"                                                                                                              | `pkg/postgres/resolve.go:186`  |
| `bex keyvalues get qa-nosuch`                | same shape, "No Key Value named …"                                                                                                                      | `pkg/keyvalue/resolve.go:187`  |
| `bex psql <id> -- -c 'SELECT 1'` (no `--command`) | `Usage: render psql <postgresID> --command "SELECT ..." -o json`                                                                                   | `cmd/psql.go:96`             |

Also unlisted, found by grep but not exercised live: `pkg/command/wrapper.go:20` (`ErrTokenExpired` — "run `render login` to get a new one"), `pkg/validate/workspace.go:17` (cross-workspace mismatch), `pkg/tui/views/pgcreate.go:797` ("Run `render pg get <id>` to check if it's ready yet").

The first three are the ordinary consequence of mistyping a resource name, which is a far more frequent path than "no workspace set".

**This is not a request to rewrite them.** The decision to leave the `RunE`-body class alone until an explicit upstream-hook or fork decision is explicit, and nothing here reopens it. The ask is accuracy: make the inventory complete — either enumerate it, or state it by class with the grep recipe that reproduces it (`rg '"[^"]*\brender [a-z]' "$(go list -m -f '{{.Dir}}' github.com/render-oss/cli)"` filtered for non-`Example`/`Short`/`Long`/`Use` sites) — so that if the fork/hook decision is ever taken, it is taken against the real scope rather than a two-line sample.

~30m, docs only (`docs/bex-cli.md`). Worth folding into the next pin bump's step-4 re-diff rather than done standalone.
