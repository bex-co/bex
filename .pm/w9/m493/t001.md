## Objective

Configure `XDG_CACHE_HOME=/opt/render/.cache` in every native build recipe generated by `lego/operator/internal/build/native.go` while ensuring the cache directory stays build-only and never inflates the final runtime image.

## Context

- `XDG_CACHE_HOME` and `/opt/render/.cache` currently appear nowhere in `lego/operator/internal/build/`.
- Render documents `XDG_CACHE_HOME` pointing to `/opt/render/.cache` during builds (`render.com/docs/deploy-nextjs-app`, `render.com/docs/deploy-gatsby`, `render.com/docs/deploys`).
- Multi-stage native Dockerfiles copy only the application artifacts and runtime directories into the final stage; `/opt/render/.cache` must stay strictly in the build stage (or be cleaned/excluded before final image export).

## Steps

1. Define `nativeXDGCacheHome = "/opt/render/.cache"` in `lego/operator/internal/build/native.go` and set `ENV XDG_CACHE_HOME=/opt/render/.cache` for the build stage across all native runtimes (Node, Python, Ruby, Go, Rust, Elixir, and static-site native builds).
2. Ensure `/opt/render/.cache` is created writable before the authored build command runs and is excluded from the final runtime stage (and never leaked into static-site published output).
3. Add recipe unit tests in `lego/operator/internal/build/native_test.go` asserting `XDG_CACHE_HOME=/opt/render/.cache` in every native build recipe and its absence from the runtime stage.

## Files

- `lego/operator/internal/build/native.go`
- `lego/operator/internal/build/native_test.go`

## Acceptance criteria

- [ ] Every native build recipe sets `XDG_CACHE_HOME=/opt/render/.cache` during the build command.
- [ ] The runtime container stage does not contain `/opt/render/.cache`.
