## Objective

Add a backend test that drives every service build-strategy shape bex's create
API can persist through create → read, and asserts the read carries a build
contract sufficient for the official CLI to reconstruct a no-op `services
update`. This is the class-level guard for the w4/052 failure ("read output
insufficient to reconstruct a valid write"). Fix — or explicitly, with captured
Render evidence, accept — any residual gap the matrix surfaces (notably the
prebuilt-image web-service round-trip).

## Context

- w4/052 fix: `lego/backend/internal/apps/service.go` `effectiveRuntime()` +
  `view()` wiring; guards `TestEffectiveRuntimeReadBack` /
  `TestDockerfileServiceRuntimeIsConsistentAcrossSurfaces` in
  `internal/apps/builder_test.go`.
- Build-strategy matrix (from `resolveBuildStrategy` / `effectiveBuilder`):
  docker-via-builder (`runtime:"" builder:auto|dockerfile|""`, repo),
  docker-explicit (`runtime:docker`), image-no-runtime (`image` set, no repo,
  no runtime), image-explicit (`runtime:image`), native (`runtime` in
  go/node/python/ruby/rust/elixir, `builder:native`), buildpack
  (`builder:buildpack`), static_site.
- The CLI's client-side guard (docs/render-artifacts/cli-services-create-update.md):
  it reads `serviceDetails.runtime` and refuses an empty value or a value that
  differs from the current one ("cannot switch runtimes via the CLI").
- Read serializer: `internal/apps/render.go` `renderServiceDetails` /
  `envSpecificDetails`; the same `toRenderService(view)` feeds REST GET, MCP
  `get_service`, and GraphQL.

## Steps

1. Table-drive the matrix above. For each shape, persist it (a direct App CR
   fixture like `repoApp`, or `svc.Create` where it exercises normalization)
   and read it back via `GET /v1/services/{id}`.
2. Assert the round-trip contract: for every runnable (non-static) type,
   `serviceDetails.runtime` and `serviceDetails.env` are present, non-empty, and
   equal; the value equals `effectiveRuntime(spec, type)` (so a resend is never a
   switch); and `envSpecificDetails` is the shape that matches that runtime
   (docker keys for docker, native keys for a language, absent/none where bex
   emits none). Static site asserts no runtime, as today.
3. If the image-no-runtime (or image-explicit) shape fails the round-trip
   contract, resolve it: capture Render's `env:"image"` serviceDetails /
   envSpecificDetails shape into `docs/render-artifacts/`, then either extend
   `effectiveRuntime` + `envSpecificDetails` to emit it correctly, or record the
   divergence as accepted with that evidence in the checklist. Do not leave it
   silently empty.
4. Run `cd lego/backend && go test ./internal/apps/... ./internal/api/...` and
   `make lint-backend`.

## Files

- `lego/backend/internal/apps/builder_test.go` (or a new
  `round_trip_test.go`) — the matrix test.
- `lego/backend/internal/apps/service.go` / `render.go` — only if step 3 fixes
  the image (or another) shape.
- `docs/render-artifacts/cli-services-create-update.md` +
  `docs/cli-compatibility-checklist.md` — evidence/disposition if step 3 lands.

## Acceptance criteria

- [ ] A backend test covers every build-strategy shape in the matrix.
- [ ] Each runnable shape reads back a non-empty `runtime`/`env` equal to
      `effectiveRuntime` with a matching `envSpecificDetails` shape.
- [ ] Any surfaced gap is fixed or accepted-with-evidence, never left silent.
- [ ] backend suite + `make lint-backend` green.

## Out of scope

- The live-CLI end-to-end leg (t003).
- Changing bex's internal representation (dropping `spec.builder` or normalizing
  `spec.runtime` on write) — a larger, separate decision.
