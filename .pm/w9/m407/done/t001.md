## Objective

Record how a repository environment becomes a snapshot that sessions boot from, matching Devin's builds, and close ADR109 D2's divergence.

## Context

- Devin ([Blueprints § Builds and sessions](https://docs.devin.ai/onboard-devin/environment/blueprints), [Blueprint reference](https://docs.devin.ai/onboard-devin/environment/blueprint-reference), checked 2026-11-14): statuses queued, building, success, partial, failed, cancelled; sessions use the latest successful build; rebuild on a blueprint save, a repository secret added, a manual "Build snapshot" and about every 24 h; one build at a time, a new trigger cancels the queued one; a step times out after 3 h; at session start "the latest code is pulled" and `maintenance` is shown to the agent but not run.
- Devin secrets: "injected before every step runs during builds" and "scrubbed from the snapshot image itself"; files a step writes "will be baked into the snapshot".
- bex pieces (research 2026-11-14): agent sandboxes share the user-sandbox substrate (`sandbox/service.go:1042`); the pause path commits a sandbox to `snapshots/<ws>-sandbox/...` (`client.go:490`, the OpenSandbox controller's commit Job); imported images live at `snapshots/<ws>-sandbox/images/<id>` and a create can swap the template image for one (`images.go:829-872`); the workspace sandbox storage cap counts imported images (ADR104 D11).

## Steps

1. Write `docs/ADR<next>-agent-repo-environment-snapshots.md` (take the next free number when writing; register it in docs/AGENTS.md).
2. Decide: build = an agent sandbox in a setup-only driver mode → pause/commit → copy into the workspace's images repository → terminate; statuses (no `partial`: one repository per build); triggers (environment save, a repo-scoped secret added or changed, manual, daily); one build per (workspace, repository) at a time; the newest successful build whose environment version matches is the one sessions boot from; while none exists, phase 1 runs setup per turn.
3. Secrets: the build receives the secrets a session on that repository receives unnamed (workspace- and repo-scoped, ADR098 D9), never explicit ones; environment variables are not kept; files a step writes are kept, and the dashboard says so as Devin does.
4. Boot: the driver fetches and resets the checkout to the latest base, skips setup, and the overlay names the setup commands as already run.
5. Retention and limits: keep the newest successful build and the one before it; step and build time limits; a compressed size cap like imports' 10 GB; builds count toward the workspace storage cap, uncharged as imports are.
6. Amend ADR109 D2 (divergence closed by this milestone) and D3 (build limits), and the ADR018 agent row.

**Done 2026-11-14.** [ADR111](../../../../docs/ADR111-agent-repo-environment-snapshots.md) records phase 2:
- **Build:** an agent sandbox in build mode is paused to commit an image, which is copied into `snapshots/<ws>-sandbox/images/<build-id>`.
- **Statuses and failure codes:** Devin's statuses without `partial`, plus failure codes.
- **Triggers:** an environment save, a repo-scoped secret, Build now and a daily refresh. One build at a time per repository and two per workspace, sharing the workspace's agent sandbox slots, with 12 starts per repository per 24 h.
- **Boot:** sessions boot from the newest success matching the setup steps' SHA-256 version, fetch the latest code, and skip setup. Phase 1 is the fallback.
- **Limits:** Devin's 3 h per step and per build.
- **Secrets:** a session's unnamed set (workspace and repo scope). Files written stay in the image, with a warning.
- **Retention:** the newest two successes.
- **Storage:** the 10 GB image cap and the storage cap, uncharged.
- **Surfaces:** REST, GraphQL, MCP and the dashboard.
- **Security:** D11 reviews the commit Job's new triggers under ADR104 D4.

ADR109 D2 now records the divergence as closed and D3 points at the build limits. docs/AGENTS.md lists ADR111 and its D11 in the security lineage. ADR018 has no agent-environment row (agent parity is Devin's, ADR047), so it is unchanged. `adr-registry-validate.sh` passes.
