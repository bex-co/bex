## Objective

Give agent sessions the three sandbox operations a build needs, reusing the user-sandbox code.

## Context

- `CreateAgentSessionSandbox` picks only a template (`sandbox/service.go:1058-1064`); the imported-image override exists only in the user `Create` (`:844-852`).
- Agent sandboxes are never suspended now (`idle.go:171-175`, `lifetime.go:204-207`); a sandbox's snapshot images are deleted when it ends (`meter.go:421`), so a commit must be copied out first (`Images.copy`, `images.go:1049`).

## Steps

1. `CreateAgentSessionSandbox` takes an optional image from a build, resolved to `snapshots/<ws>-sandbox/images/<id>@sha256:…`.
2. `CommitAgentBuildSandbox`: pause the builder (with the storage-cap check), wait for the commit, copy the image into the images repository, record its size, terminate the builder.
3. Delete a build's image on retention, on environment delete and with the workspace.
