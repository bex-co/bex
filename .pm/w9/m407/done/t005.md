## Objective

The driver can run only the checkout and setup for a build, and can boot from a prebuilt image without rerunning setup.

## Context

- `main.ts:43-50` runs `ensureRepo`; `session.ts:270-286` runs `runRepoSetup` (`repo-setup.ts:94`) once per sandbox; `ensureRepo` tolerates an existing checkout (`git-setup.ts:223-242`).

## Steps

1. Build mode: `ensureRepo` + `runRepoSetup`, write a status file the orchestrator reads (exit, per-step results, redacted tail), then idle for the commit — no model turn, no transcript.
2. Prebuilt mode: fetch and reset the checkout to the latest base (Devin pulls the latest code), skip setup, and have the overlay name the setup commands as already run so the agent can rerun one if dependencies changed.
3. Clear per-build scratch (e.g. the driver's own state) before the commit so nothing session-specific is kept.

**Done 2026-11-14.** Driver build mode (`src/build.ts`):
- clones single-branch with no tags and runs the setup steps;
- enforces the 3 h per-step limit (`step_timeout`); the build limit is bex-api's;
- scrubs Git credentials, auth headers and the build proxy (origin becomes the public URL, refspec reset) and the driver logs;
- writes `{state, build:{head, steps}}` or `{state:failed, code:checkout_failed|setup_failed|step_timeout|internal_error}`;
- stays up for the commit.

Prebuilt mode (`BEX_REPO_PREBUILT`) skips setup when the image held a checkout, checks out the session branch at the latest base (`--force`, with `origin/<base>` refreshed), and lists the steps in the overlay as already run. An empty `/workspace` falls back to phase 1. 234 driver tests and the typecheck pass, and mutation checks confirmed the key tests fail when their behaviour is broken.
