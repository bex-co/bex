## Objective

Persist builds and the environment version they were built from.

## Context

- `agent_repo_environments` (migration 0255) holds setup and checks; nothing records a version or a build.
- Check `git ls-tree origin/main lego/backend/internal/store/migrations/` for the next free number before writing.

## Steps

1. Add a version (hash of the setup steps) to each environment row, set on every write.
2. Add `agent_repo_environment_builds` (id minted with `id.New`, workspace, repo, version, trigger, status, image reference and digest, size, failure code and reason, redacted log tail, created/started/finished, heartbeat).
3. Store methods: queue (cancelling a queued build for the same repository), claim, heartbeat, finish, newest success for a version, list, retention delete; an advisory lock serializes per (workspace, repository).
4. A sweeper fails a build whose heartbeat stopped.

**Done 2026-11-14.** Migration `0269_agent_repo_environment_builds` adds:
- `agent_repo_environments.version`: SHA-256 of the setup steps, computed in SQL, backfilled, and returned as `changed` from the upsert's CTE under the workspace lock;
- `agent_repo_environment_builds`, with partial indexes for the claim, building, sweeper, rate-limit and pending-purge queries;
- `agent_sessions.environment_build_id`.

Store methods cover queue (cancels a queued build), claim (SKIP LOCKED, counts first, busy repositories filtered in SQL), heartbeat, finish, the newest matching image (id and digest only), list (without `steps`), the rate count, retention and purge claims with backoff, and the stale sweep. Real-Postgres tests are in `store/agent_repo_environment_builds_pg_test.go` and `agentsessions/repo_environment_builds_pg_test.go`.
