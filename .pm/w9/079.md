# 079 — ADR095 residuals: attachment storage metering and malware scanning

Why: ADR095 deliberately shipped without storage metering or malware scanning (D8, D9). Both should be revisited once real usage exists, so they don't silently become permanent gaps.

- **Metering.** Measure actual attachment bytes per workspace (the `bex-agent-attachments` bucket) after a few weeks. If archived sessions accumulate storage, add an ADR023 meter (e.g. `agent_attachment_gb_seconds`) or a retention cap for archived sessions.
- **Scanning.** Decide whether uploads and agent outputs need malware or content scanning. Files are delivered only to the uploader's own workspace sandbox and members, never to third parties. Record the decision in ADR095 as a residual for the next security review.
- **Trigger.** Re-evaluate on 2026-12-05 or at the first 10 GB of stored attachments, whichever comes first.
