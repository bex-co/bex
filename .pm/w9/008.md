# Unify the `/v1/oauth/revoke` failure dialect

The new revoke handler (`lego/backend/internal/cliauth/service.go`, `RevokeHandler`) mixes two error dialects on different failure branches of the same endpoint: Render's `{"message"}` shape via `core.WriteErr` (~lines 86, 108, 112, 116) and the OAuth `{"error":"temporarily_unavailable"}` shape via `writeOAuthError` (~lines 93, 103). A client parsing logout failures sees two different bodies depending on which branch fails.

`w9/m38` unified the REST error dialect but closed before this handler was swept (cliauth shipped the same day, 2026-07-15). Decide per-branch which contract applies — `/v1/oauth/revoke` sits between RFC 7009 revocation semantics and bex's Render-shaped REST — unify accordingly, and annotate any deliberate survivor per m38's convention. The RFC 8628 device endpoints' OAuth-shaped errors (`deviceGrant`/`deviceToken`/`refreshToken`, `writeOAuthError` at ~135–210) are **correct** — the CLI expects OAuth-shaped bodies there; leave them.
