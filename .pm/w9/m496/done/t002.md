## Objective

Implement t001's catalog as one Go table (areas, permissions, levels, Render's names, the role each needs) and persist a key's grant at mint, read back on list and on every request through a cached lookup.

## Context

- t001's ADR024 section.
- `lego/backend/internal/apikeys/service.go` (`Create`, `createBoundAPIKey`, Hydra metadata keys), `lego/backend/internal/twofactor` (`APIKeyCreator`'s cached lookup), `lego/backend/internal/store` if t001 picks Postgres.
- New ids only through `lego/backend/internal/id`; boilerplate header per `lego/operator/hack/boilerplate.go.txt`.

## Steps

1. Add the catalog (one source of truth the operation map, the mint validation and the dashboard's GraphQL read all use).
2. Persist the grant at mint and on edit; a key minted before this change reads as t001's default.
3. Expose a cached grant lookup beside `APIKeyCreator`, failing closed when it cannot answer (I7).
4. Return the grant on list (REST, GraphQL, MCP) so the dashboard can show it.

## Files

- `lego/backend/internal/core/` (catalog), `lego/backend/internal/apikeys/`, `lego/backend/internal/twofactor/` or `lego/backend/internal/store/` (+ migration if Postgres)

## Acceptance criteria

- [x] The catalog lists every Render permission with its levels and required role; a test pins it against t001's table.
- [x] A key minted with a grant reads it back on all three list surfaces; an old key reads as the default.
- [x] An unreadable grant fails closed; tested.
- [x] `cd lego/backend && go test ./...` and `make lint` pass.
