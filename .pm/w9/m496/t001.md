## Objective

Settle the model before any code: the catalog bex offers (Render's areas, permission names and levels), where a key's grant lives, where it is enforced, and what a key with no recorded grant does. Record it in ADR024 as a new section after § An API key acts with its creator's role.

## Context

- Render's page ([render.com/docs/api-keys](https://render.com/docs/api-keys)) and its quotes are in the milestone README. Re-read it; record what changed since 2026-11-18.
- m481's mechanism (`lego/backend/internal/core/keyrole.go` `keyCeiling`; ADR024 § An API key acts with its creator's role) and invariants I1–I5.
- The dispatch gate every surface calls: `lego/backend/internal/api/scope_matrix.go` `requireScopeClass`, over the operation table `classifiedOps` in `scope_matrix_ops.go`. API keys are `CapabilityExempt` today.
- Key metadata is Hydra client metadata (`lego/backend/internal/apikeys/service.go`, `bex.co/created-by`); key rows are `tenant_members` machine rows (migration 0297's `created_by`).

## Steps

1. List Render's 14 areas with every permission and the levels each offers (Read, Write, Read & write, Run, Execute), with Render's exact names.
2. Decide the stored shape: one entry per permission, or one level per area as the picker presents it. Prefer what lets Render's own "Write without Read" rows (set secret values without reading them) be expressed.
3. Decide storage: Hydra metadata (immutable stamp, read through the two-factor gate's cached lookup) or a Postgres table keyed by key id. Weigh the edit verb (I8) and cache staleness.
4. Decide enforcement: per operation through the dispatch gate (operation id → permissions), and how the operation check composes with the relation-level `keyCeiling` (I6). Name every entry point a key reaches outside the three dispatch gates (log streams, shell and snapshot tickets, the object gateway) and how each is covered.
5. Decide keys minted before this milestone and a mint that names no permissions (expected: All, so existing scripts and Terraform keep working; Render's classic keys "continue to work as usual").
6. Map bex-only surfaces with no Render area (cloud agents and their automations, skills and secrets; registry credentials; custom domains; disks; organizations) to a Render area where Render's docs place them, or to a named bex extension area that All grants.
7. Decide how the picker shows a permission no bex key may exercise yet (w9/116, w9/117): offered and recorded, but refused by I4 and I5 until those land, or hidden.
8. Amend ADR024 (new section), ADR012 §8e (a key's bearer carries a grant), and plan ADR018's API keys row.
