# 045 — Log-list virtualization (deferred from w9/m63 t001)

**Filed:** 2026-08-16, during w9/m63. **Type:** deferred perf work (needs a testable harness + profiling).

m63 t001 shipped its **safe, dominant half** — ANSI is now parsed **once at ingest** (`makeLogLine` sets `line.spans`; `LogLineList` reads it) instead of re-parsing the whole retained buffer on every SSE frame, which was the named per-frame jank source. The **row virtualization** half was attempted (`@tanstack/react-virtual`, spacer approach, follow/pin preserved) but **reverted**: it would not render a visible range under jsdom (0-height viewport; tried `initialRect`, a state-backed scroll ref, and ResizeObserver/getBoundingClientRect stubs), so the change could not be verified, and virtualizing the platform's **most-watched screen** (live log tail during deploys) without a working test harness — including the cross-buffer text-selection tradeoff — was too risky to land in an autonomous pass.

Do it as a focused milestone with room to get it right:

- Stand up a real virtualization test harness (jsdom geometry that makes `@tanstack/react-virtual` render a range — a scoped setup helper, not global `getBoundingClientRect` stubbing, so it can't perturb other tests), or drive it with Playwright against a busy tail.
- Virtualize `log-line-list.tsx` preserving follow-to-bottom, scroll-up-breaks-follow, jump-to-latest, instance chips, request chips, and both wrap/nowrap modes; decide the cross-buffer text-selection tradeoff explicitly (visible-row selection works; whole-buffer copy is the known virtualization cost).
- Assert only-visible-rows-in-DOM for a 1,000-line buffer; profile a busy live tail before/after.
- Unblocks raising the retained-line cap (`DEFAULT_MAX_LINES`).

Low urgency now that per-frame ANSI re-parsing is gone — that was the dominant cost. This is the remaining DOM-reconciliation cost on very busy tails.
