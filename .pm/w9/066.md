# 066 — Cut a bex CLI release: two shipped fixes are on main but unreleased

Why: `w4/m116` t001 is recorded as DONE, but every user who installs bex today still hits the bug it fixed — shipped-to-main is not shipped-to-users, and the gap is now two user-visible fixes wide.

The released binary is `bex v0.2.1` (`git rev-list -1 bex-cli/v0.2.1` → `423855d55`). Verified 2026-09-21 by building HEAD (`7b3ba5b42`) and diffing its behavior against the installed release, same config, same workspace, same production API.

**1. `34484344f` — "fix(cli): brand cobra usage errors as bex, not render" (2026-09-15).** Not an ancestor of the v0.2.1 tag. On the released binary a flag error on a late-added command prints raw cobra usage on stderr (exit 1) carrying upstream `render …` example lines:

```text
$ bex services update --bogus-xyz
Error: unknown flag: --bogus-xyz
Usage:
  bex services update <service> [flags]

Examples:
  # Rename a service
  render services update my-service --name my-new-name --output json
```

Count of bare `render ` lines on stderr, released vs HEAD:

| command                        | v0.2.1 | HEAD |
| ------------------------------ | ------ | ---- |
| `bex services update --bogus-xyz`  | 2      | 0    |
| `bex logs --bogus-xyz`             | 3      | 0    |
| `bex keyvalues create --bogus-xyz` | 6      | 0    |
| `bex workflows list --bogus-xyz`   | 1      | 0    |

Those are exactly the four canaries `lego/cli/UPSTREAM_RENDER_CLI.md` step 4 names as must-not-regress ("stderr must not contain a bare `render ` command line"). The `--help` path was correctly branded on both binaries — only the UsageFunc error path was affected, which is why help-graded checks missed it. Same release gap: `bex postgres create --help` on v0.2.1 says `(set via 'render workspace set')`; HEAD says `'bex workspace set'`.

**2. `6208c7500` (`w4/m116` t001) — `lego/cli/internal/pgtrust`.** On v0.2.1, with no `~/.postgresql/root.crt` and no `PGSSLROOTCERT`:

```text
$ bex psql <dpg-id> --command 'SELECT 1 AS probe' -o json
Error: exit status 2: psql: error: … root certificate file "…/.postgresql/root.crt" does not exist
```

On HEAD the CA is provisioned automatically and the same command returns `{"output":" probe \n-------\n     1\n(1 row)\n\n"}`. That is `w4/m116` t001's DoD bullet — it holds on main and not for users.

**Also for the next pin bump (not part of this release):** `bex login` printed `render v2.28.0 is available. Current version is 2.27.0. / Installation instructions: https://render.com/docs/cli#1-install-or-upgrade`. That is the documented un-interceptable `pkg/tui/views/login.go` banner (`UPSTREAM_RENDER_CLI.md` step 3), whose only mitigation is bumping the pin — and upstream v2.28.0 now exists, so the pin is one release stale.

This is release scheduling, not a code bug: run `/release cli`, which owns version choice, tagging and channel verification. No implementation task is needed.
