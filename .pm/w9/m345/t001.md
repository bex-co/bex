## Objective

Give the two edge-cache verbs the service events Render defines for them, so the Events feed and webhooks report cache changes as on Render.

## Context

- Render's event enum lists `edge_cache_enabled`, `edge_cache_disabled` and `edge_cache_purged` (`docs/render-artifacts/webhooks-api.md:93-95`).
- Verbs: `SetCacheProfile` and `PurgeCache` in `lego/backend/internal/apps/edge_cache.go:72,90` (shipped in w5/m151).
- They are excused from the event guard on a false premise: `lego/backend/internal/events/vocabulary_test.go:54-55` ('Render's event vocabulary has no edge-cache event').
- Event constants: `lego/backend/internal/events/service.go` (e.g. `TypeDeployStarted` at :173).

## Steps

1. Capture Render's `details` shape for the three types from the pinned OpenAPI artifact before writing them.
2. Add the three types; emit `edge_cache_enabled`/`_disabled` when the profile turns caching on or off (a profile change that keeps it on records nothing new unless Render documents otherwise), and `edge_cache_purged` on a purge.
3. Remove both entries from `excusedVerbs` so the guard enforces them.
4. Expose them on the Events REST/GraphQL/MCP reads with Render's field names.
