## Objective

When a workspace has used its plan's included pipeline minutes and a build is prevented from starting, record Render's `pipeline_minutes_exhausted` event on the service.

## Context

- Render documents `pipeline_minutes_exhausted` ('prevented a service build from starting'); it is item 24 in `docs/render-artifacts/webhooks-api.md:81`.
- Pipeline minutes shipped in w6/m308: `lego/backend/internal/buildminutes/buildminutes.go:18-19`, the refusal in `lego/backend/internal/api/free_hours.go:44`.
- The docs still call it 'no truthful producer' (`webhooks-api.md:149`) and `docs/render-artifacts/service-events.md:99` says 'no pipeline-minute billing'.

## Steps

1. Find every path where a build is refused for exhausted minutes (push-to-deploy, manual deploy, Blueprint sync, build sources).
2. Record one `pipeline_minutes_exhausted` service event per refused build with Render's `details` shape; do not record repeats for the same refused trigger.
3. Expose it on the Events REST/GraphQL/MCP reads.

## Files

- `lego/backend/internal/api/free_hours.go`, `lego/backend/internal/buildminutes/buildminutes.go`
- `lego/backend/internal/events/service.go`

## Acceptance criteria

- [ ] A build refused for exhausted minutes records exactly one event on the service; a build that starts records none.
- [ ] A real-Postgres test covers the refusal path.

## Out of scope

- Changing pipeline-minute billing.

## Done (2026-11-12)

When the reconciler closes a deploy `build_failed` and the release's Build condition reads `BuildMinutesExhausted`, it first writes one `pipeline_minutes_exhausted` fact per refused deploy (`pipelineMinutesExhaustedFact`, `store/reconciler.go`). It follows the `image_pull_failed` pattern: the source key is idempotent, a failed write leaves the deploy open for the next pass, and a `CanTransitionDeploy` guard applies. The fact is dated when the refusal is seen. The condition's own transition time is not used: the operator keeps the Build condition at False, so that time would be the first failure's. Details are `buildId` (the deploy) and the deploy's trigger. A pre-deploy refusal records nothing, since Render's event names a build. Test: `TestPGPipelineMinutesRefusalRecordsOneEventBesideTheFailedDeploy`, including an old condition timestamp.
