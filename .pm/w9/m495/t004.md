## Objective

Verify own-workspace private-service reach during a build and cross-workspace denial live on production in `bex-canary`, then update ADR018 (`Pre-Deploy Command` row) and ADR022.

## Context

- Use the QA user (`bash scripts/qa-login.sh`) in `bex-canary` and a second workspace for the negative control.
- Park with the self-clearing pin gate if production's operator pin does not yet carry t001–t003.

## Steps

1. Deploy a disposable `private_service` fixture in `bex-canary` serving a known HTTP marker on its internal address (`<slug>:10000`).
2. Deploy a second service (or Blueprint) in `bex-canary` whose `buildCommand` curls that sibling's `fromService` `hostport` and asserts the marker; verify it succeeds and goes live, and that both per-build NetworkPolicies are removed after the build finishes.
3. Negative control: run a build in a different workspace probing the same internal DNS name and pod IP; verify it fails/times out.
4. Delete all fixtures (`GET 404`) and update `docs/ADR018-render-parity.md` (`Pre-Deploy Command` row) and `docs/ADR022-tenant-isolation.md` with the production pin SHA and evidence.
