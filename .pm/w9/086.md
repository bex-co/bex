# An automation link opens in the browser's current workspace, not the automation's

Why: every link to an automation (the w9/m343 pause push and email, and since w9/084 the mobile tap) is `https://dashboard.bex.co/automations/<aut-id>` with no workspace. The page looks the id up in the cookie-selected workspace (`dashboard/src/features/agent-automations/hooks/use-agent-automation.ts:34-36`), so a member of several workspaces whose browser has another one selected gets "not found".

- The dashboard has no URL workspace switch. Either the page finds the workspace from the `aut-` id (for example, a by-id read across the caller's workspaces) and switches to it, or links carry the workspace and the page switches before it reads.
- Check how Render's dashboard deep links pick the workspace (its URLs carry the owner id) and match it for every resource link the notifications send.
- Cover: a member of two workspaces opens a link to the other workspace's automation and lands on it.
