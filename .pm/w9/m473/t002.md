## Objective

Read an image-backed service's `serviceDetails.envSpecificDetails` in the shape Render sends, which matches the pinned `dockerDetails` member, instead of omitting it or sending only the commands the CLI clones.

## Context

- Render: image-backed background worker recordings (`internal/provider/backgroundworker/resource/testdata/*_cassette.yaml`, 2025-01) answer `"env":"image","envSpecificDetails":{"dockerCommand":"","dockerContext":"","dockerfilePath":"","preDeployCommand":"…"},"runtime":"image"`. The pinned `dockerDetails` requires `dockerCommand`, `dockerContext`, `dockerfilePath`.
- bex: `lego/backend/internal/apps/render.go:618` `envSpecificDetails` returns nothing for an image service without a command, and only `dockerCommand`/`preDeployCommand` (or a cron's `startCommand`) with one. Allowlisted by `imageCommands` (`rendertest/allowlist.go:152-156`).
- Must keep the CLI clone behavior: the pinned client reads an image cron's command from `envSpecificDetails.startCommand` (w1/m167) and an image service's `dockerCommand` (w4/188, w4/209).

## Steps

1. Emit `dockerCommand` (empty when none), `dockerContext: ""`, `dockerfilePath: ""` and, when set, `preDeployCommand` for every image service; keep a cron's `startCommand` beside them.
2. Drop the `imageCommands` allowlist entry if the read now matches the documented union.
3. Re-run the pinned CLI's `create --from` clone of an image web service, an image worker and an image cron (`docs/cli-compatibility-checklist.md` rows) to confirm nothing regresses.

## Files

- `lego/backend/internal/apps/render.go`, `lego/backend/internal/rendertest/allowlist.go`, tests

## Acceptance criteria

- [ ] An image service read carries all three docker keys, with empty strings where unset.
- [ ] The pinned CLI still clones image services and image crons with their commands.

## Out of scope

- Build-source-linked services' `runtime`/`env` (stays an open m373 entry).
