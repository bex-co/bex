# A `/bex` comment on any pull request starts an agent session on it

Why: Devin's `/devin <task>` comment on any open PR in a connected repository starts a session with the PR as context and replies with its link (docs.devin.ai/integrations/gh); bex's PR feedback loop (w9/m344, ADR047 D11) only steers sessions that already own the PR.

- Same intake as m344: `issue_comment` / `pull_request_review` events, a write-access commenter linked to a member who can create sessions, bots ignored, comments on closed PRs ignored.
- A comment whose first word is `/bex` on a PR no session owns creates a session on the PR's head branch (`repo`, `branch` = head ref) with the rest of the comment as the task (quoted), as that member; the App replies with the session link (an eyes reaction, as Devin adds).
- A `/bex` comment on a PR a session already owns is ordinary feedback for that session (Devin sends it to the existing session).
- Code: `lego/backend/internal/agentsessions/pr_feedback.go` (`queueHuman`), `Service.Create`, `github.CreateIssueComment`.
