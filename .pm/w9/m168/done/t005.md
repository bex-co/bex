## Objective

Implement ADR095 D3: `attachmentIds` on create/steer and resolved `bex-attachment:` file parts on live turns.

## Context

- `CreateRequest`/`SteerRequest` in `agentsessions/models.go:112-128`; turn record `agent_session_turns` (migration 0081); replayed `data-user-prompt` part in `sshgateway/agentattach/agentattach.go:537-548`; live turn body limit 256 KiB there.
- Steer always redispatches (`service.go:1265`).

## Steps

1. Add `attachmentIds` to REST create/steer bodies and GraphQL args; validate (ready, same workspace, unbound or this session, ≤10/turn, session quota) and bind in the turn transaction → `400 AGENT_ATTACHMENT_INVALID` naming the id.
2. Add `attachment_ids` to the turn row and `attachments:[{id,name,mediaType,size}]` to `data-user-prompt` replay.
3. Gateway: accept AI SDK `file` parts with `url: bex-attachment:att-…` on live turns, resolve/authorize them via bex-api, drop any other file URL.

## Files

- lego/backend/internal/agentsessions/models.go, service.go, rest.go, graphql.go
- lego/backend/internal/store/agentsessions.go (+ migration)

## Acceptance criteria

- [x] Binding is atomic with the turn (failed bind records no turn).
- [x] Cross-workspace and foreign-session ids are refused; replay shows attachments identically on every client.
