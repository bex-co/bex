## Objective

Give bex-api a dedicated object store for agent attachments: config, client, credential install script, and a clean 503 when unconfigured.

## Context

- Wasabi via `aws-sdk-go-v2` precedent: `lego/backend/internal/apps/disk_snapshots.go` (S3DiskSnapshotLister), `lego/operator/internal/disksnapshot/store.go`; presign precedent `lego/backend/internal/postgres/export_signer.go`.
- Credential precedent: out-of-band k8s Secret + optional secretKeyRefs in `lego/operator/config/api/deployment.yaml`; scripts like `scripts/disk-snapshot-secret.sh`; Wasabi policies in `infra/wasabi/*.json` (writer/reader split, ADR050).
- ADR095 D1: bucket `bex-agent-attachments`, key `<ws>/<session|unbound>/<att-id>`, env `BEX_AGENT_ATTACHMENTS_S3_{ENDPOINT,BUCKET,REGION,ACCESS_KEY,SECRET_KEY}`.

## Steps

1. Add config fields in `lego/backend/cmd/api/config.go` and an `AttachmentStore` interface (Put stream, Delete, Presign GET with content-type/disposition overrides) with an S3 implementation.
2. Add `infra/wasabi/agent-attachments-{writer,reader}.json` policies and `scripts/agent-attachments-s3-credentials.sh` (idempotent, reads `.env`, never prints values); `.env.example` names; deployment.yaml optional secretKeyRefs.
3. Add the ADR019 inventory row and the env vars to `lego/backend/AGENTS.md`.
4. Unconfigured store → every attachment verb returns `503 AGENT_ATTACHMENTS_UNAVAILABLE` (core error code).
