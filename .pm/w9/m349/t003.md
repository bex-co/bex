## Objective

When a sandbox's container really died, say why.

## Steps

1. Before `failLostSandbox` deletes the sandbox, read the pod's last terminated state (reason, exit code), through the sandbox client or the gateway's target check.
2. Put it in `failureReason`, e.g. "the sandbox ran out of memory (OOMKilled, exit 137)" or "the sandbox's agent exited with code N"; fall back to today's text.
3. Use a `failureReasonCode` if the session API already has a code set for these reasons.

## Acceptance criteria

- [ ] An OOM-killed fake records its reason; a missing pod keeps "sandbox terminated before completion" (tested).
