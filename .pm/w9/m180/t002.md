## Objective

The fan-out of a successful carrier build to auto-deploy linked services runs in a goroutine that only logs failures (`lego/backend/internal/store/reconciler.go:1002-1005`). A restart mid fan-out leaves services on the old build for good. Make it durable: either an outbox row per (build, service) drained by the existing reconcile loop, or a periodic resync that compares each linked service's `build_source_image` with its carrier's latest live build and opens the missing deploy. It must be idempotent, so it never opens two deploys for one build.

## Acceptance criteria

- [ ] A test simulates a crash after the build row and before the deploys, and the next reconcile opens exactly one deploy per auto-deploy linked service; real-Postgres test.
