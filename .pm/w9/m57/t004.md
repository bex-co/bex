## Objective

`fromService: {property: host}` injects the sibling's **slug** (and `hostport` ⇒ `<slug>:<port>`), fixing the t002 repro and landing Render's shape in the same move — ADR041 D3.

## Context

- Today: `resolveRef` injects the bare bex.yml name (`lego/backend/internal/apps/deploy.go:1426,1430`); `stack_test.go:242` asserts it.
- Slugs are minted at create (w4/m19, `apps.slug` column; `service.go:1567` round-trips into `spec.subdomain`). DeployStack resolves env before/while creating siblings — the resolver needs each referenced sibling's slug at resolve time (mint-before-resolve, or resolve-after-create; pick what fits DeployStack's current ordering).
- Re-deploy of an existing stack must reuse the existing slug (slugs are immutable — ADR018 w8/m8 rename row).
- Legacy path (store off / hand-applied): no slug exists; `PlatformSubdomain` falls back to CR name — the injected value must remain today's working bare name there.

## Steps

1. Thread sibling slugs into `resolveRef`'s inputs (`names`/`ports` maps grow a slug map or become a struct).
2. Inject `<slug>` / `<slug>:<port>`; keep `port` unchanged.
3. Update `stack_test.go` + blueprint tests: store-managed ⇒ slug injected; slug-less ⇒ bare name (unchanged); re-deploy reuses the existing slug.
4. `cd lego/backend && go test ./...`.
