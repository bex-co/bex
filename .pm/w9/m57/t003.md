## Objective

The operator reconciles a **second, slug-named ClusterIP Service** (same selector/port, App-owned) for every addressable App (web + private), making bare `<slug>` resolve in-cluster — ADR041 D2. The CR-named Service stays untouched.

## Context

- Slug source: `AppSpec.PlatformSubdomain(app.Name)` (`lego/types/v1alpha1/app_types.go:511`) — `spec.subdomain` when minted (w4/m19, globally unique), else CR name. Fallback case ⇒ slug Service coincides with the existing CR-named Service: reconcile must detect that and skip (never fight over one object).
- Existing Service reconcile: `app_controller.go:1114–1117`. Ownership/GC pattern: `SetControllerReference` like every sibling resource (cf. the maintenance ExternalName alias, `app_controller.go:1861`, and the per-App NetworkPolicy).
- Addressable = web_service + private_service only (`deploy.go:1424`'s rule); workers/cron/static get nothing.
- Isolation invariant: NetworkPolicies select pods, not Services (ADR022) — no policy change needed, but the DoD asserts it.

## Steps

1. Add slug-Service reconcile alongside the existing Service reconcile: name = `PlatformSubdomain`, skip when equal to CR name, delete stale slug Services on suspend/type-change the same way the primary Service is handled.
2. Cover deletion/GC via owner refs; ensure the App finalizer path leaves nothing behind.
3. envtest: slug ≠ name creates both Services; slug == name creates one; type change / suspend cleans up; two Apps in different tenants with the same display name get non-colliding slug Services.
4. Run `make test` from `lego/operator/`.

## Files

- `lego/operator/internal/controller/app_controller.go`
- `lego/operator/internal/controller/*_test.go` (envtest)

## Acceptance criteria

- [ ] Store-managed App ⇒ slug-named Service exists, App-owned, same endpoints as the CR-named Service.
- [ ] Legacy slug-less CR ⇒ byte-identical behavior (one Service, as today).
- [ ] `make test` green; no NetworkPolicy changes.

## Out of scope
