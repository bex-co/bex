## Objective

Implement the `BEX_BUILD_CACHE=s3` build Job phase behavior so `cache-restore`, `cache-purge`, and `cache-save` sync BuildKit's local OCI cache layout to and from `<tea-id>/<app-uid>/layer-cache/` in S3 while keeping BuildKit 100% credential-free.

## Context

- `lego/operator/internal/build/build.go:1718-1771` defines `cacheRestoreContainer`, `cachePurgeContainer`, `cacheSaveContainer`, and `cachePhase`, currently using `skopeo` against Zot (`o.CacheRef()`).
- ADR060 D3 Correction 1 requires the restored layout in `/cache-in` to carry the `latest` ref tag (`index.json` `org.opencontainers.image.ref.name: latest`) so BuildKit `--import-cache type=local,src=/cache-in` actually gets cache hits.
- Cache phases must remain best-effort (`cacheRestoreBestEffort`, `cachePurgeBestEffort`, `cacheBestEffort`), bounded by `cacheCommandTimeout` and `cacheEphemeralLimit` (`8G`), and must never fail a build on cache miss or corrupt archive.

## Steps

1. Extend `build.Options` to distinguish cache backend (`off` / `registry` / `s3`) and carry S3 cache settings (endpoint, bucket, prefix `<tea-id>/<app-uid>/layer-cache/`, secret name) without altering the gate-off byte-identical Job spec.
2. Implement S3-backed `cache-restore`, `cache-purge`, and `cache-save` container builders: restore downloads and unpacks/places the OCI layout into `/cache-in` preserving `index.json` refs; save compresses/uploads `/cache-out` (enforcing the per-App size cap); purge deletes the App's S3 prefix before a `SkipCacheImport` build.
3. Confirm BuildKit receives zero S3 credential mounts or env vars, and keep `BEX_BUILD_CACHE=registry` working unchanged for backward compatibility.
4. Add unit tests in `lego/operator/internal/build/build_cache_test.go` covering S3 Job spec generation, credential isolation, `SkipCacheImport` purge-vs-restore switch, and gate-off byte-identity.

## Files

- `lego/operator/internal/build/build.go`
- `lego/operator/internal/build/build_cache_test.go`

## Acceptance criteria

- [ ] `BEX_BUILD_CACHE=s3` produces a Job whose `cache-restore`/`cache-save`/`cache-purge` phases mount the S3 cache Secret and target only `<tea-id>/<app-uid>/layer-cache/`, while the `buildkit` container mounts no S3 or registry Secret.
- [ ] Restored layout preserves BuildKit's `latest` manifest ref annotation so `--import-cache` hits on warm builds.
- [ ] `BEX_BUILD_CACHE` unset produces a byte-identical Job spec (`TestBuildCacheAddsOnlyWhatItClaimsToAdd`).

## Out of scope

- `$XDG_CACHE_HOME` persistence (w9/m493) and native runtime dependency caches (w9/m494).
