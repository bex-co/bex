## Objective

Implement the `BEX_BUILD_CACHE=s3` build Job phase behavior so `cache-restore`, `cache-purge`, and `cache-save` sync BuildKit's local OCI cache layout to and from `<tea-id>/<app-uid>/layer-cache/` in S3 while keeping BuildKit 100% credential-free.

## Context

- `lego/operator/internal/build/build.go:1718-1771` defines `cacheRestoreContainer`, `cachePurgeContainer`, `cacheSaveContainer`, and `cachePhase`, currently using `skopeo` against Zot (`o.CacheRef()`).
- ADR060 D3 Correction 1 requires the restored layout in `/cache-in` to carry the `latest` ref tag (`index.json` `org.opencontainers.image.ref.name: latest`) so BuildKit `--import-cache type=local,src=/cache-in` actually gets cache hits.
- Cache phases must remain best-effort (`cacheRestoreBestEffort`, `cachePurgeBestEffort`, `cacheBestEffort`), bounded by `cacheCommandTimeout` and `cacheEphemeralLimit` (`8G`), and must never fail a build on cache miss or corrupt archive.

## Steps

1. Extend `build.Options` to distinguish cache backend (`off` / `registry` / `s3`) and carry S3 cache settings (endpoint, bucket, prefix `<tea-id>/<app-uid>/layer-cache/`, secret name) without altering the gate-off byte-identical Job spec.
2. Implement S3-backed `cache-restore`, `cache-purge`, and `cache-save` container builders: restore downloads and unpacks/places the OCI layout into `/cache-in` preserving `index.json` refs; save compresses/uploads `/cache-out` (enforcing the per-App size cap); purge deletes the App's S3 prefix before a `SkipCacheImport` build.
3. Confirm BuildKit receives zero S3 credential mounts or env vars, and keep `BEX_BUILD_CACHE=registry` working unchanged for backward compatibility.
4. Add unit tests in `lego/operator/internal/build/build_cache_test.go` covering S3 Job spec generation, credential isolation, `SkipCacheImport` purge-vs-restore switch, and gate-off byte-identity.

## Acceptance criteria

- [x] `BEX_BUILD_CACHE=s3` produces a Job whose `cache-restore`/`cache-save`/`cache-purge` phases mount the S3 cache Secret and target only `<tea-id>/<app-uid>/layer-cache/`, while the `buildkit` container mounts no S3 or registry Secret.
- [x] Restored layout preserves BuildKit's `latest` manifest ref annotation so `--import-cache` hits on warm builds.
- [x] `BEX_BUILD_CACHE` unset produces a byte-identical Job spec (`TestBuildCacheAddsOnlyWhatItClaimsToAdd`).

## Out of scope

- `$XDG_CACHE_HOME` persistence (w9/m493) and native runtime dependency caches (w9/m494).

## Result — 2026-11-18

- `lego/operator/internal/build/s3cache.go`: `build.Options.CacheStore` selects the S3 backend when `BuildCache` is on; the BuildKit side is the registry backend's, unchanged. `cache-restore`, `cache-purge` and `cache-save` run the pinned aws-cli image with the cache Secret as an **optional** `envFrom`, every value as env, one phase-wide 5-minute deadline, and a termination-log outcome (`hit`, `miss`, `incomplete`, `saved`, `skipped`, `purged`, `error`). The layout travels verbatim, so `index.json` keeps its `ref.name: latest` annotation; restore offers a layout only when every blob its manifest names arrived; save uploads blobs first (`--size-only --no-follow-symlinks`), then `oci-layout` and `index.json`, then prunes; a symlinked `index.json`/`blobs`, or a layout over 8 GB, is not saved.
- A build with no App UID runs uncached rather than falling back to the registry. Gate off is byte-identical (the existing `TestBuildCacheAddsOnlyWhatItClaimsToAdd` plus its S3 twin).
- Tests: `s3cache_test.go` (credential isolation, prefix scoping, seams-only, clear-cache purge, bounds, and the scripts themselves run against a fake store: round trip, missing blob, every failure exits 0, symlink attacks, prune, size bound, purge). Mutation checks: dropping `--no-follow-symlinks`, the completeness check, the prune, the symlinked-index guard or the optional `envFrom` each fails a test.
- Drill against the real bucket with BuildKit `v0.30.0` (results in the ADR060 amendment): miss → saved → warm hit with byte-identical `index.json` → all 4 steps `CACHED`; symlinked blob not stored; a deleted layer gives `incomplete` and the next save heals it.
