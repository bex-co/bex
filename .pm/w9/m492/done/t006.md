## Objective

Verify that build-cache behavior and `clearCache: "clear"` are consistent across REST, GraphQL, MCP, CLI, Build Sources, and the dashboard, match Render's documented Docker/native caching semantics, and update ADR018 and ADR060.

## Context

- Compare against `render.com/docs/docker` and `render.com/docs/deploys` ("Clear build cache & deploy", `clearCache: "clear"` / `--clear-cache`).
- Check [ADR018-render-parity.md](../../../../docs/ADR018-render-parity.md) (`Runtime, build strategy + Root Directory` and `Trigger a deploy`) and [ADR060](../../../../docs/ADR060-build-worker-reliability-and-performance.md) § D3.

## Steps

1. Verify REST `POST /v1/services/{id}/deploys`, `POST /v1/build-sources/{id}/builds`, GraphQL `triggerDeploy`/`triggerBuildSourceBuild`, MCP `trigger_deploy`/`trigger_build_source_build`, CLI `bex deploys create --clear-cache`, and the dashboard "Clear build cache & deploy" button all stamp `AnnotationClearCacheReleaseGeneration` and trigger S3 cache purge + cold rebuild.
2. Update `docs/ADR018-render-parity.md` and `docs/ADR060-build-worker-reliability-and-performance.md` with the production-verified S3 layer cache status and any remaining drift as follow-ups.

## Files

- `docs/ADR018-render-parity.md`
- `docs/ADR060-build-worker-reliability-and-performance.md`

## Acceptance criteria

- [x] Every surface's `clearCache: "clear"` path reaches the S3 cache purge identically.
- [x] ADR018 and ADR060 accurately reflect the shipped production behavior.

## Out of scope

- Implementing `$XDG_CACHE_HOME` (w9/m493) or per-runtime dependency caches (w9/m494).

## Result — 2026-11-18

- Surfaces: REST `POST /v1/services/{id}/deploys`, GraphQL `triggerDeploy`, MCP `trigger_deploy`, the Render CLI's `--clear-cache` (REST), the dashboard's "Clear build cache and deploy" (`manual-deploy-button.tsx` → `trigger(…, { clearCache: "clear" })`) and REST/GraphQL/MCP `trigger-build-source-build` all reach `stampClearCacheRelease` (`lego/backend/internal/deploys/service.go`), which stamps `app.bex.co/clear-cache-release-generation`; the operator turns it into `SkipCacheImport`, which under `s3` dispatches `cache-purge` instead of `cache-restore` (envtest covers a service and a Build Source carrier). Render documents the same: "Clear build cache & deploy" rebuilds without the cache (render.com/docs/deploys).
- The MCP `clearCache` description no longer says it is a no-op with the gate off; it now says what production does. The backend and dashboard comments name the S3 backend.
- ADR018 (`Runtime, build strategy + Root Directory` and `Trigger a deploy`) and the ADR060 D3 amendment record the shipped behavior, with production proof pointed at t005; t009 updates them if the production check finds drift.
