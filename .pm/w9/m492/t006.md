## Objective

Verify that build-cache behavior and `clearCache: "clear"` are consistent across REST, GraphQL, MCP, CLI, Build Sources, and the dashboard, match Render's documented Docker/native caching semantics, and update ADR018 and ADR060.

## Context

- Compare against `render.com/docs/docker` and `render.com/docs/deploys` ("Clear build cache & deploy", `clearCache: "clear"` / `--clear-cache`).
- Check [ADR018-render-parity.md](../../../docs/ADR018-render-parity.md) (`Runtime, build strategy + Root Directory` and `Trigger a deploy`) and [ADR060](../../../docs/ADR060-build-worker-reliability-and-performance.md) § D3.

## Steps

1. Verify REST `POST /v1/services/{id}/deploys`, `POST /v1/build-sources/{id}/builds`, GraphQL `triggerDeploy`/`triggerBuildSourceBuild`, MCP `trigger_deploy`/`trigger_build_source_build`, CLI `bex deploys create --clear-cache`, and the dashboard "Clear build cache & deploy" button all stamp `AnnotationClearCacheReleaseGeneration` and trigger S3 cache purge + cold rebuild.
2. Update `docs/ADR018-render-parity.md` and `docs/ADR060-build-worker-reliability-and-performance.md` with the production-verified S3 layer cache status and any remaining drift as follow-ups.
