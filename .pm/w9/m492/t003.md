## Objective

Wire `BEX_BUILD_CACHE=s3` configuration through the operator manager into `AppReconciler`, ensure both ordinary services and Build Source carriers honor `clearCache: "clear"`, and sweep the App's S3 build-cache prefix during App finalization.

## Context

- `lego/operator/cmd/manager/main.go` and `lego/operator/internal/controller/app_controller.go` parse `BEX_BUILD_CACHE` and stamp `SkipCacheImport` from `AnnotationClearCacheReleaseGeneration`.
- Build Source carriers (`lego/operator/internal/controller/build_source.go`, `lego/backend/internal/deploys/build_sources.go`) build through the same pipeline and already accept `clearCache` (`w3/m367`).
- App deletion (`lego/operator/internal/controller/app_deletion*.go`) must leave zero residue in S3 when an App or Build Source is deleted.

## Steps

1. Parse `BEX_BUILD_CACHE=s3` and S3 cache env vars in `lego/operator/cmd/manager/main.go` (fail closed at startup if `BEX_BUILD_CACHE=s3` is set without required bucket/endpoint/secret configuration) and document them in `lego/operator/AGENTS.md`.
2. Pass the S3 cache configuration into `build.Options` in `app_controller.go` for both service builds and Build Source carrier builds, ensuring `clearCache` clears the cache for both.
3. Add S3 prefix cleanup (`<tea-id>/<app-uid>/`) to App finalization so deleting an App removes its layer cache (best-effort bounded or retried cleanly without stalling deletion forever if already empty).
4. Add envtest coverage in `lego/operator/internal/controller/build_cache_envtest_test.go` and deletion tests.

## Files

- `lego/operator/cmd/manager/main.go`
- `lego/operator/internal/controller/app_controller.go`
- `lego/operator/internal/controller/build_cache_envtest_test.go`
- `lego/operator/AGENTS.md`

## Acceptance criteria

- [ ] Manager starts cleanly with `BEX_BUILD_CACHE=s3` and fails fast on incomplete S3 cache config.
- [ ] Both standard Apps and Build Source carriers dispatch S3 cache phases and honor `AnnotationClearCacheReleaseGeneration`.
- [ ] Deleting an App deletes its `<tea-id>/<app-uid>/` cache objects in S3.
