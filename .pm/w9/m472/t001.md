## Objective

Accept an empty `serviceDetails.previews` object, the body Render's Terraform provider sends for every service whose configuration has no `previews` block, as Render's default `generation: off`, on `POST /v1/services` and `PATCH /v1/services/{id}`.

## Context

- Provider (render-oss/terraform-provider-render tip `06af456`, 2026-11-16): `internal/provider/common/previews.go` `PreviewsObjectToPreviews` returns `&client.Previews{}` when the plan has no generation; `client.Previews.Generation` is documented as defaulting to `off` (`internal/client/types_gen.go`).
- Render accepted it: 53 recorded requests in the provider's test cassettes carry `"previews":{}` and were answered 2xx.
- bex: `lego/backend/internal/apps/rest.go:451` `previewsDisabled` requires `generation == "off"`, so `{}` fails `unsupportedPreviewsField` (`:439`) and create answers `400 services previews is not supported by this platform` (`:1261`, PATCH `:1122`).

## Steps

1. Treat an object with no `generation` (and no other field) as disabled in `previewsDisabled`.
2. Keep refusing `automatic`/`manual` and any unknown preview option by name (PR previews stay a `DO_NOT_DO` non-goal).
3. Unit-test `{}`, `{"generation":"off"}`, `{"generation":"automatic"}` on create and PATCH.

- `lego/backend/internal/apps/rest.go` and its tests

## Acceptance criteria

- [ ] `POST /v1/services` with `serviceDetails.previews: {}` creates the service.
- [ ] `previews: {"generation":"automatic"}` is still refused by name.
