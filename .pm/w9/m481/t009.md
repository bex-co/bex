## Objective

Every surface this milestone touched agrees with the others and with render.com's API keys. Each remaining divergence is filed rather than left silent.

## Context

- Surfaces: REST, GraphQL and MCP in `lego/backend/` (the four Admin writes, webhook create and repoint, the API key read fields) and `dashboard/src/features/api-keys/`.
- Render: [render.com/docs/api-keys](https://render.com/docs/api-keys) (permission tables, FAQ). ADR018's members and API keys rows.

## Steps

1. Check that the same key gets the same answer and error shape on REST, GraphQL and MCP for each of the four writes.
2. Walk every other `AuthorizeMintClass` verb that Render's API serves to a key. Expect members (Render: "Update member roles and remove members"), Postgres users and deploy hooks. File each one that refuses a key as its own inbox note.
3. File the variants this milestone did not take, each as its own note:
   - Render's scoped keys with per-resource permissions;
   - a Viewer or Contributor minting a key capped at their role (bex requires `can_manage_keys` to mint).
