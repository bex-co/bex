## Objective

When a creator's role in a workspace changes, every key they minted in that workspace moves to the new role. A failed write converges exactly as the member's own role does.

## Context

- `members.Service.ChangeRole` (`lego/backend/internal/members/service.go:930`) commits the row, then converges OpenFGA through `RoleReconciliationStore` (`:211`) and `reconcileQueuedRole` (`:1054`). The exact-role reconcile revokes every other role tuple that exists (codex round-4 #4).
- Other writers of a member's workspace role: find every caller of `GrantWorkspaceRole`, `RevokeWorkspaceMember` and the reconciliation enqueue. Expect organization role changes (`members/organizations.go` `ChangeOrganizationRole`), joins (`join`, `JoinWorkspaceAsAdmin`) and the reconciliation worker.
- Removal and account deletion already revoke the creator's keys (`members/service.go` around `:1237`, `:1330`; w2/m163).
- `apikeys` lists keys by workspace. Its `CreatedBy` filter is how removal finds a member's keys.

## Steps

1. List every path that changes a member's role in a workspace.
2. On each one, enqueue the same role intent for each key the member minted in that workspace, in the same transaction as the member's own intent. On a demotion, order the key's revoke no later than the member's.
3. Make the reconciliation worker converge key subjects exactly as it converges members (exact role, check-before-write).

## Files

- `lego/backend/internal/members/service.go`, `members/organizations.go`, the role-reconciliation store and worker, tests beside them

## Acceptance criteria

- [x] Real-DB tests: Admin → Developer → Admin moves the creator's keys with them in `tenant_members` and OpenFGA. Another member's keys do not move.
- [x] Fault test: an OpenFGA revoke that fails on the key's tuple leaves an intent that the worker converges. A retry of the role change converges it too.
- [x] An organization-level change that changes a workspace role moves the keys as well.
