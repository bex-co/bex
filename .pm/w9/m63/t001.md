## Objective

The log viewer renders every retained line into DOM and re-runs the ANSI-parse memo over the whole buffer on each SSE frame — the dominant CPU/jank cost while watching a busy build. Virtualize the row list and move ANSI parsing to ingest so per-frame work is O(1)-ish.

## Context

- `dashboard/src/features/logs/components/log-line-list.tsx:113` — maps the full `lines` array (up to 1000 live + 100 history, `use-live-logs.ts:82`); `:73` — `parsed` `useMemo` keyed on `lines` identity re-parses everything per append (`needsAnsiParse` short-circuits plain lines but the O(n) map + full reconciliation remains).
- No virtualization dependency exists in the app; add `@tanstack/react-virtual` (already-in-family with TanStack Router/Start).
- Must preserve: follow/autoscroll-to-bottom during live tail, breaking follow on user scroll-up, line selection/copy, instance-slug chips, the deploy-detail log panels (same component).

## Steps

1. Move ANSI parsing into the ingest path (`fromRenderLog`/`toLogLines` or the `use-live-logs` append) so each line is parsed exactly once; keep the parsed form on the line object.
2. Virtualize `log-line-list.tsx` with `@tanstack/react-virtual` (dynamic row heights for wrapped lines); reimplement follow-to-bottom on top of the virtualizer (scroll to last index on append while following).
3. Profile before/after on a busy live tail (React profiler or frame timings); record the observation in the milestone README.

## Files

- [ ] Follow/scroll-up-breaks-follow, selection, and instance chips behave as before (existing tests + a follow-behavior test pass).
