## Objective

Prove the guardrail works and keeps working: a deliberately type-incorrect fixture must fail `yarn typecheck`. This is the meaningful test of the behavior this milestone shipped (the build config itself).

## Context

- The whole value of the milestone is that drift fails the command; without a tripwire, a future config regression could silently re-exclude test files and no one would notice.

## Steps

1. Add a controlled negative check (e.g. a fixture file behind an intentional type error asserted via a `tsc --noEmit` expectation, or a documented CI check) proving the pass rejects drift.
2. Keep it isolated so it doesn't break the normal green run — assert the failure, don't leave a broken fixture in the tree.

## Files

- a small guard test/fixture under `dashboard/` + any CI note

## Acceptance criteria

- [ ] A deliberately-wrong type in a test fixture is demonstrated to fail the typecheck pass
- [ ] The normal `yarn typecheck && yarn test` run stays green

## Out of scope

- Broad new unit tests unrelated to the guardrail
