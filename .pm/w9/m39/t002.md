## Objective

The revoke handler mixes two error dialects on different failure branches of the same endpoint: Render's `{"message"}` shape via `core.WriteErr` and the OAuth `{"error":"temporarily_unavailable"}` shape via `writeOAuthError`. A client parsing logout failures sees two different bodies depending on which branch fails. Decide per-branch which contract applies — `/v1/oauth/revoke` sits between RFC 7009 revocation semantics and bex's Render-shaped REST — unify accordingly, and annotate any deliberate survivor per m38's convention.

## Context

- `lego/backend/internal/cliauth/service.go`, `RevokeHandler` — `core.WriteErr` at ~lines 86, 108, 112, 116; `writeOAuthError` at ~93, 103.
- The RFC 8628 device endpoints' OAuth-shaped errors (`deviceGrant`/`deviceToken`/`refreshToken`, `writeOAuthError` at ~135–210) are **correct** — the CLI expects OAuth-shaped bodies there; leave them, they are the annotated deliberate survivors.
- `w9/m38` unified the REST dialect but closed before this handler was swept (cliauth shipped the same day). Absorbs note `w9/008`.

## Steps

1. Read RFC 7009 §2.2.1 (revocation error responses) and the official CLI's logout path to pin what the client actually parses.
2. Pick one dialect per branch with a one-line comment justifying any OAuth-shaped survivor; convert the rest to `core.WriteErr`/`WriteErrStatus`.
3. Add/extend a test asserting each failure branch's body shape.
