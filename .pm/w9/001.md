# Per-deploy commit hash/message

Render's deploy page header shows the commit hash + message for a repo-backed deploy. bex has no per-deploy commit metadata today (`deploys.DeployView.Commit` was left out on purpose per w2/m5's original scope note: "stays empty until w1/m5 tracks build-from-git commits"). The deploy detail page (w9/m1) ships without it — flagged as an accepted gap during that milestone's Render parity check (t006), not built there.

- Needs a place to persist it: either a `commit_hash`/`commit_message` column on the `deploys` store row (written when the operator resolves `spec.BuildCommit`/Branch HEAD to an actual SHA) or a read-through to the git provider at request time.
- Would thread onto REST/GraphQL/MCP's `DeployView` (`deploys.graphql.go`'s `deployGQLType`) and the dashboard's `deploy-header.tsx`.
- Gated on knowing exactly which commit a build ran (today `App.spec.BuildCommit` is a ref, not a resolved SHA, when unset it's Branch HEAD with no captured commit at all) — needs the build pipeline to report back the resolved SHA once a build starts.
