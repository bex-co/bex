## Objective

Choose how bex stops silently dropping dual-stack clients, and write the decision down with its rationale before any code moves. The three candidates trade off differently and are not all exclusive.

## Context

Candidate (a) — **stop publishing AAAA** for `*.db.bex.co` / `*.kv.bex.co`, matching Render's IPv4-only datastore data path. Makes the pinned CLI's IPv4-only gate correct by construction and needs no protocol work. Costs: no IPv6 reachability for datastores; find and own the record (`lego/operator/config/manager/manager.yaml:208-211` documents the wildcard as DNS-only to a node IP — the actual Cloudflare/Hetzner record was not inspected).

Candidate (b) — **make the denial legible**: have the SNI proxies carry the handshake far enough to emit a real Postgres `ErrorResponse` (and the RESP equivalent) naming the allow list. Costs: the proxies deliberately make an unusable name fall through for anti-enumeration reasons (`pg-sni-proxy/main.go:240-242`), so a denial message is only safe once the route is already known to that source — the distinction between "no such host" and "your IP is not allowed" must not become an existence oracle.

Candidate (c) — **surface both families**: the API and dashboard report the caller's v4 **and** v6, and the allowlist UI warns when only one family is listed. Today the dashboard's Access-control copy is "Only these CIDR ranges can reach the external endpoint. Empty means open to all source IPs." — no "your IP is X" hint at all. Costs: user-facing surface change across REST/GraphQL/MCP/UI (hence the Render-parity task).

(a) and (c) are not exclusive; (b) is valuable independently of both because a genuinely-refused client should always be told.

## Steps

1. Establish what Render actually does — does `*.render.com` datastore DNS publish AAAA? That settles whether (a) is parity or divergence.
2. Find the record that publishes the AAAA and who owns it (DNS provider, Terraform, or the operator).
3. Weigh (a)/(b)/(c) against the anti-enumeration constraint and the parity question, pick, and record the decision plus the rejected options and why.
4. Write the decision into the governing ADR (ADR009 for Postgres, ADR021 for Key Value, or a new one if it spans both) and update this milestone's DoD if the chosen shape changes it.
