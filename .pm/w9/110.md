# An image service reads `imagePath` back as written (`nginx`), where Render normalizes it (`docker.io/library/nginx:latest`), so Terraform loses `image_url`

Why: Render's Terraform provider parses `image_url` and the tag out of `imagePath` only when it holds a `:` or `@`. bex echoes a bare `nginx`, so the provider reads `image_url` as null and Terraform aborts the create with "Provider produced inconsistent result after apply".

- **Found by:** w9/m474, dev-9, 2026-11-18 ([checklist](../../docs/terraform-compatibility-checklist.md), class 6). It affects every image-service test that names a bare image (worker, cron, private and web).
- **Render:** a create with `image.imagePath: "nginx"` answers `imagePath: "docker.io/library/nginx:latest"` (`backgroundworker/resource/testdata/env_var_cassette.yaml`, `scaling_cassette.yaml`). The provider's parser is `internal/provider/common/models.go` `ImageRuntimeSource`.
- **bex:** `lego/backend/internal/apps/render.go` sets `ImagePath: a.SourceImage`, the string as written. `lego/backend/internal/store/image.go` already normalizes with `reference.ParseNormalizedNamed`; Render's form adds the default `latest` tag (`reference.TagNameOnly`) and keeps a digest.
- **Done when:** REST, GraphQL and MCP read an image service created as `nginx` back as `docker.io/library/nginx:latest` (and `ghcr.io/o/i@sha256:…` unchanged), the deployed image is unchanged, a test covers it, and `TestEnvVarsResource` (web service) gets past its first step.
