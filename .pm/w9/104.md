# A new image private service reads no `serviceDetails.url` and `openPorts: []` until its ports are discovered, where Render's create answers `<slug>:10000`

Why: since w9/m473 a private service reads its `<slug>:<port>` as `url`, as Render's recorded responses show, except in the first moments after create. Render's own Terraform provider reads `url` from that create response, and this is the last private-service case `rendertest.Allowlist`'s `url` entries still excuse (w10/m373 gate 1).

- **Render:** `render-oss/terraform-provider-render` `06af456`, `internal/provider/privateservice/resource/testdata/private_service_cassette.yaml`. The `POST /v1/services` that creates `private-service-tf` from the `nginx` image with no port answers 201 with `serviceDetails.url` `"private-service-tf:10000"` and `openPorts` `[{"port":10000,"protocol":"TCP"}]`. `nginx` listens on 80, so Render reports its default `PORT` of 10000 before it has scanned anything. Every later read in the recording says the same.
- **bex:** an image-port private service (`AppSpec.UsesImagePorts`) has no port until its image's metadata is read. `App.ServicePort` returns `Status.EnvPort`, 0 when no `PORT` is set (`lego/types/v1alpha1/image_network.go`). `App.InternalAddress` is then `""`, `OpenPorts` is `[]`, and `renderServiceDetails` (`lego/backend/internal/apps/render.go`) sends no `url` or `internalAddress`. ADR089 § Port slice decisions chose this ("never a guessed 3000") before bex's default `PORT` became Render's 10000 (w8/168). Reproduced by `TestRESTCreatePrivateService` (`lego/backend/internal/apps/deploy_test.go`) with the allowlist's `url` entry removed.
- **Open question:** whether bex can answer `<slug>:10000` honestly before discovery, which depends on whether the process is given `PORT=10000` then and whether the slug Service routes 10000 before the image's ports are known (`lego/operator/internal/controller/app_controller.go` `appEnv`, `port_detect.go` `processPort`). If so, `ServicePort`, `InternalAddress` and `OpenPorts` answer 10000 together, as Render does, and ADR089 records the amendment. If not, record why the pending state stays.
- **Done when:** a REST create of `{"type":"private_service","name":"p","image":{"imagePath":"nginx:1"}}` answers `serviceDetails.url` as Render's does, or ADR018's "Partial serviceDetails projection" row records why it cannot. A test covers the answer.
