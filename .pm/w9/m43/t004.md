## Objective

Ship the fix to production and re-run the exact failure scenario from 2026-07-17: a brand-new App created through the official Render CLI must reach `live` on its first deploy with zero manual zot intervention.

## Context

- The 2026-07-17 repro: `render services create --name <fresh> --type web_service --repo https://github.com/bex-co/bex --branch main --root-directory examples/hello-go --runtime docker --plan free --health-check-path / --confirm` against `https://api.bex.co/v1/` — build succeeds, then (pre-fix) `ImagePullBackOff` 401 → `update_failed`. The operator's laptop CLI (`~/.render/cli.yaml`) is already logged into prod, or mint a throwaway key (memory `prod-zot-stale-creds-first-deploy.md`).
- Crucial precondition for a valid test: prod's zot pod must have been running since **before** the test App is created (do not restart zot as part of the rollout after the new operator image is live — or restart it first, then wait, then test).
- Prod operator deploys via the standard image build + `make deploy IMG=…` / GitOps path; all three CI test suites must pass before `deploy.yml` pushes images.

## Steps

1. Deploy the new operator image (and any `deploy/gitops` change from t001/t003) to prod.
2. Ensure zot has been up-and-unrestarted, then create a fresh throwaway App via the official CLI and watch `deploys list` to `live`; curl the `*.onbex.co` URL.
3. Delete the throwaway App; confirm zot Secrets were garbage-collected per existing `RemoveCreds` behavior.
4. Update `docs/ADR022-tenant-isolation.md` § Per-App pull credentials with the activation mechanism, and update/retire the workaround note in memory `prod-zot-stale-creds-first-deploy.md`.
