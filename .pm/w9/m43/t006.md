## Objective

Add meaningful regression tests for the behavior this milestone shipped: the operator verifies a freshly minted credential against zot and triggers exactly one reload when the running zot serves stale auth state.

## Context

- Existing envtest harness: `lego/operator/internal/controller/per_app_registry_envtest_test.go`, unit tests in `lego/operator/internal/registry/`.
- The probe's HTTP client is injectable (t002) — fake a zot that 401s until "reloaded", then accepts.
- Tests must assert real behavior and failure modes: no Deployment roll while unverified; single rate-limited bounce; non-auth zot failure (connection refused) requeues without bouncing.

## Steps

1. Unit tests for the probe/reload state machine against a fake zot (401-until-reload, always-401, connection-refused).
2. Envtest: reconcile a new App → credential Secrets written → probe verified ⇒ Deployment created; probe stuck ⇒ no Deployment, requeue, one bounce.
3. `make test` green from `lego/operator/`.

## Files

- `lego/operator/internal/registry/*_test.go`
- `lego/operator/internal/controller/per_app_registry_envtest_test.go`

## Acceptance criteria

- [ ] Failure modes covered (stale-401, zot-down, verified) — not just the happy path
- [ ] Tests fail if the verify-before-Deployment ordering or the bounce rate-limit is removed
- [ ] `make test` passes
