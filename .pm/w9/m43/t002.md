## Objective

Make the operator guarantee that freshly written per-App credentials are actually accepted by the running zot before the tenant Deployment is left to pull with them — implementing t001's chosen mechanism (default design: verify-then-reload).

## Context

- Call path today: `AppReconciler.Reconcile` → `ensurePerAppRegistryCreds` (`app_controller.go:256,552`) → `registry.Creds.EnsureCreds` (`creds.go`) writes the pull Secret + `zot-htpasswd` + `zot-config`, then reconcile proceeds straight to the Deployment; nothing ever checks zot accepted the credential.
- Default design (adjust per t001): after `EnsureCreds`, probe zot over HTTP (`GET /v2/` or `HEAD /v2/<app>/tags/list` with the per-App basic auth, registry host from `Creds.Registry`). On 401: within a grace window (Secret volume propagation is ≤ ~1min) requeue; past it, trigger a zot reload (delete the zot pod by label in `Creds.ZotNamespace` — a StatefulSet recreates it) and requeue until the probe passes. Only a verified credential lets the reconcile proceed to create/update the tenant Deployment, so the deploy window isn't burned on doomed pulls.
- Idempotent + conflict-safe like the rest of `creds.go` (`ErrConflictRequeue` pattern); rate-limit the bounce (never bounce-loop zot if the probe keeps failing for another reason).
- Existing Apps must be untouched: probe only when the credential was just created/rotated, or make the probe cheap and unconditional — decide in review.

## Steps

1. Add a credential-verification probe to `lego/operator/internal/registry` (injectable HTTP client for tests).
2. Wire it into `ensurePerAppRegistryCreds`: verified ⇒ proceed; unverified-in-grace ⇒ requeue; unverified-past-grace ⇒ reload zot once, requeue.
3. Implement the reload trigger chosen in t001 (default: delete pod `zot-0`-by-label in `ZotNamespace`), with a per-App or global cooldown.
4. Emit K8s events / log lines on probe-fail and reload so the failure mode is observable from `bex-system`.
5. `make test` green from `lego/operator/`.
