# Dedicated Deploys list tab

Render's service nav has a standalone **Deploys** tab (a filterable list of every deploy, separate from the Events feed). bex folds deploy history into the Events tab instead (`services.$serviceId.events.tsx`), which already lists deploy rows — now linking to the per-deploy page (w9/m1/t004) — interleaved with other activity. Flagged as an accepted parity gap during w9/m1's Render parity check (t006), not built there since the milestone's scope was the per-deploy page, not a new list surface.

- If picked up: a new `services.$serviceId.deploys.tsx` route reusing `deploys(serviceId, status[], createdBefore/After, cursor, limit)` (already GraphQL-parity'd since w2/m31) with the existing pagination filter bar pattern.
- Low urgency — the Events tab already surfaces deploy history; this is additive polish, not a functional gap.
