# A private Key Value has no external connection string, where Render answers one for every store

Why: Render's Terraform provider, CLI and dashboard read `externalConnectionString` for every Key Value. Render answers it even for a store created with `ipAllowList: []`, whose endpoint exists and admits nothing, so a client that copies Render's strings finds an empty one on a private bex store.

- **Found by:** w9/m521 t007 (Render parity), 2026-11-19. In the provider's cassettes at pin `06af456`, three of the nine Key Value stores were created with `ipAllowList: []`, and each answered its first `connection-info` read with `rediss://red-…:<password>@oregon-keyvalue.localhost.render.com:6377`.
- **bex:** a store with `spec.public` false (an empty allow list since w4/m116 and w4/m315) has no `status.externalHost`, no external Service port and no Certificate, so `KeyValueConnectionInfo` (`lego/backend/internal/keyvalue/service.go`) answers `externalConnectionString: ""` and a CLI command over the internal host. The dashboard says "Not public. Add an inbound IP rule under Networking".
- **To decide first:** whether bex reserves and answers `<id>.<BEX_KV_DOMAIN>` for a private store (the SNI edge refuses every source while the list is empty) or ADR018 records the empty string as a divergence with the user's sign-off. Answering it means issuing a certificate for every store, which costs Let's Encrypt budget (w4/m357), and opening the TLS listener only on the first rule.
- **Done when:** a private store's connection info matches whichever choice is recorded in ADR018's Key Value row and ADR021 §2, on REST, `/v1/redis`, GraphQL and the dashboard, with a backend test.
