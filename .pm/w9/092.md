# A Blueprint sync records no instance-count, autoscaling or disk change events

Why: w9/091 made a Blueprint sync or deploy record `plan_changed`. The same path also applies `numInstances`, `scaling` and `disk:` changes to existing services and records none of Render's matching events (`instance_count_changed`, the autoscaling configuration change, the disk events), while the REST and dashboard paths for the same settings do. A team that manages services through `render.yaml` sees a feed with gaps.

- Mirror each REST setter's audit recording in `persistBlueprintIntent` (`lego/backend/internal/apps/deploy.go`), using 091's pattern: record once the store row takes the change, with the syncing member, the approver, or no caller for auto-sync.
- Cover each change with a sync test, and check the event names against `docs/render-artifacts/service-events.md`.
