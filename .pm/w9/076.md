- **Rerun.** All sessions ran on claude over the platform model route, with schema `{tests_passed: boolean, files_changed: integer}` (required, no additional properties).
  - **PASS, repo-less** (`ags-dbmml52g3cdc73a60p9g`):
    - The deliberately invalid `submit_result` (final false) was bounced with `schema_mismatch`, "/files_changed: must be integer; /tests_passed: must be boolean", plus the fix-and-retry hint.
    - The valid final submission returned `{"accepted":true,"final":true}`.
    - `outcome.result` = `{"files_changed":0,"tests_passed":true}`, the last valid final submission.
  - **PASS, on a repo** (`bex-co/onefx`, `ags-dbmml5gts0lc739ecjtg`): read-only task, no PR opened. `outcome.result` = `{"files_changed":0,"tests_passed":false}`.
  - **PASS, one reminder recovers a missing result** (`ags-dbmmo3qg3cdc73a60q00`): the agent was told not to call tools. It replied HELLO, received the in-turn reminder, submitted final, and the turn succeeded.
  - **PASS, `STRUCTURED_OUTPUT_MISSING`** (`ags-dbmmpaots0lc739eckjg`): only `final:false` submissions were allowed. The transcript shows two submissions with exactly one reminder between them. The turn failed with `failureReasonCode: STRUCTURED_OUTPUT_MISSING`, `outcome.result` null and the draft kept on the transcript turn. The "PR kept" variant was not run live, to avoid a PR on a customer repo; tests cover it.
- **Surfaces.**
  - **PASS.** REST returns an object in `outcome.result`. GraphQL `agentSession(id){outcome{result}}` returns JSON text, as the schema documents. MCP `/mcp/cloud-agents` `get_agent_session` returns the object in `structuredContent.outcome.result`. All three carry the same value.
  - **PASS, gateway.** `POST /agent-results/...` is live: the submissions above were accepted through it. The sandbox image validates with Ajv (it produced the `schema_mismatch` text above).
- **FAIL, dashboard.** `/agents/<id>` shows no Result block for a succeeded session (s1: no `[data-testid=agent-session-result]`). The failed s6 does show "Draft result".
  - Cause: `dashboard/src/features/agent-sessions/components/structured-result-callout.tsx:24-29` renders `session.outcome.result`, or a draft only when it is **not** final.
  - The session object in the Apollo cache carries `outcome {result: null, summary: null, cost: null}`, because only the single-session read computes them (ADR094). `AgentSessionTurnResults` does return `result` with `resultFinal: true`.
  - So a final result reaching the page through the turn query is dropped. Fix: fall back to the turn's final result as well, or stop the list payload from overwriting the detail outcome in the cache. Filed as a follow-up for the parent.
