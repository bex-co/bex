# After `DELETE …/autoscaling`, a service read still carries `serviceDetails.autoscaling`, where Render omits it, so Terraform cannot remove autoscaling

Why: Render's Terraform provider reads `serviceDetails.autoscaling` into its optional `autoscaling` attribute. bex keeps the turned-off policy in the service read, so a configuration that drops the block reads it back non-null, and Terraform aborts with "Provider produced inconsistent result after apply".

- **Found by:** w9/111's recheck on dev-9, 2026-11-18 ([checklist](../../docs/terraform-compatibility-checklist.md), class 11). This is where the three scaling tests stop next once w9/113 is fixed: `TestWebServiceResource_Autoscaling` (step 2 of 2), `TestBackgroundWorkerScalingResource` and `TestPrivateServiceScalingResource` (step 2 of 4). Each step sends `DELETE …/autoscaling` before the `PATCH` that w9/113 refuses today.
- **Render:** `webservice/resource/testdata/web_service_autoscaling_cassette.yaml`, and the worker and private service `scaling_cassette.yaml`. After `DELETE /v1/services/{id}/autoscaling` (204), no service read has an `autoscaling` key in `serviceDetails`: not the `PATCH` response, and not any later `GET`. The test then checks `TestCheckNoResourceAttr(resourceName, "autoscaling")`. Render's disable event still keeps the config with `enabled: false` (w4/597's evidence), and Render has no `GET …/autoscaling`.
- **bex:** `lego/backend/internal/apps/render.go` `renderServiceDetails` emits `serviceDetails.autoscaling` whenever the App has `spec.autoscaling`. Since w4/597, a disable keeps those settings with `enabled: false`. On dev-9, `DELETE …/autoscaling` answered 204, then `GET /v1/services/{id}` answered `serviceDetails.autoscaling: {"enabled":false,"min":2,"max":3,…}`.
- **Provider:** `internal/provider/common/models.go` `AutoscalingFromClient` returns a model for any non-nil `serviceDetails.autoscaling`. The `autoscaling` attribute is optional and not computed.
- **Done when:**
  - While autoscaling is off, `serviceDetails.autoscaling` is absent from every Render-shaped service read (REST get, list and `PATCH` responses, MCP `get_service`).
  - The kept settings still read on `GET …/autoscaling`, GraphQL and the Scaling page (w4/597).
  - ADR018's w4/596 and w4/597 sentences say so, and a test covers it.
  - After w9/113, the three scaling tests get past their remove-autoscaling step.
