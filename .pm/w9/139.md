# A native build's version line reads `Using Ruby 3.3.14 (from Gemfile.lock)`, where Render's reads `Using Ruby version 3.3.14 via /opt/render/project/src/Gemfile.lock`

Why: the build log is where a user learns which interpreter their service runs, and a log scraper or a person comparing a Render and a bex build of the same repository finds a different sentence. Render's narration says "version", names the signal by its full path under `/opt/render/project/src`, and uses "via"; bex's says "(from Gemfile.lock)" and "(default)".

- **Found by:** w9/133's production check on pin `7e481dece7ac`, 2026-11-21 (b2ab0ef065): `render-examples/sidekiq` logged `==> Using Ruby 3.3.14 (from Gemfile.lock)` at head and `==> Using Ruby 3.2.0 (from Gemfile.lock)` at `73f3ab4db`. Render's form, `==> Using Ruby version 3.4.1 via /opt/render/project/src/Gemfile.lock`, is quoted in ADR018's runtime row (w9/133) from Render's own build logs. w4/668 left Render's wording for the default case unverified (`==> Using Python version 3.14.10 (default)` from memory, no capture).
- **bex:** the narration lines in `lego/operator/internal/build/` (`nativeversion.go` and the per-runtime resolvers), for every native runtime (Python, Node, Ruby, Elixir/Erlang, Bun) and every signal kind (env var, version file, lockfile, Gemfile, `engines`, default).
- **Done when:** capture Render's exact line for each runtime and signal kind from its docs, changelog or public build logs (record the sources in `docs/render-artifacts/`), and bex's narration prints the same sentence with the same path form for each, with unit tests per runtime; a case Render's sources do not show keeps bex's line and is named as unmeasured in ADR018's runtime row.
