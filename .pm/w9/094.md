# In a Blueprint that waits for approval, a change that only moves a service never applies

Why: w9/093 found that the Blueprint planner compares a service's settings but not its grouping. In a Blueprint whose syncs wait for approval, a `render.yaml` change whose only effect is to move a service into another project or environment plans as `no_changes`, so it is never offered for approval and never applied. A sync without approval applies the move. On Render, a Blueprint applies every change it declares.

- Make the plan diff include project and environment placement, so a move-only change plans as a change, is approved, and then applies (recording `service_moved` per w9/093).
- Cover it with an approval-mode test whose only change is a move (`TestBlueprintPlanApprovalRegroupNamesTheApprover` currently also changes the plan to get past this).
