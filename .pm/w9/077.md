# 077 — Live completion webhook and spend ceiling on a dev stack (m260 definition of done)

Why: m260's definition of done asks for a live run; it was verified by backend (real Postgres + OpenFGA), gateway and webhook tests only. `scripts/dev-env.sh` takes N 1-10, so there is no `dev-21` harness. This note keeps `w9/m172/t007` (closeout) open.

- On a dev stack with the agent leg up and a platform model route for the workspace, subscribe a webhook endpoint (for example a request catcher) to `agent_session_turn_succeeded` and `agent_session_turn_failed`, run one session that succeeds and one that fails, and confirm one signed delivery each with `data: {id, state, outcome}` (no `summary`), `id` = the session id, and nothing for a workspace without a subscription.
- Create a session with a tiny `maxSpendUSD` (for example `0.01`) on the platform model, let it run past the ceiling, and confirm the next model request gets the Anthropic-shaped 429 with `code: AGENT_MODEL_SPEND_CAP_REACHED` and `scope: "session"`, the turn ends `failed` with that `failureReasonCode`, and `outcome.cost.modelUSD` equals the `agent_model_usage_events` sum. Also confirm a session on the workspace's own model key is refused `400 AGENT_SESSION_SPEND_LIMIT_UNAVAILABLE`.
- Confirm migrations 0201/0202 applied on the rolled-out bex-api and that the webhook worker's `ListWebhookEvents` plan stays cheap with the new `agent` arm (the arm is filtered by `workspace_id = ANY($5)` and read by `(recorded_at, session_id, turn)`).

## Live verification (2026-11-06 05:45–06:10 UTC, production, workspace bex)

- **First attempt (2026-11-06 ~04:30 UTC): blocked** by the mint incident (see 076). It was fixed by `ac9d5d484` plus clearing the stale `bex` model-key flag.
- **Receiver.** A free echo service in the QA canary workspace (`srv-dbmmjo2g3cdc73a60p6g`, `mendhak/http-https-echo:35`). The webhook was `whk-dbmmkv2g3cdc73a60p8g` in `bex`, subscribed to `agent_session_turn_succeeded` and `agent_session_turn_failed`.
- **FAIL, REST create.** `POST /v1/webhooks` with those event types answers `400 invalid request body at /eventFilter/0`, although `GET /v1/webhooks/event-types` lists them.
  - Cause: the Render request validator checks `eventFilter` against the pinned Render enum.
  - `applyRenderSchemaCompatibility` (`lego/backend/internal/api/render_openapi.go:452`) never extends create-webhook/update-webhook with the bex agent event types (`internal/webhooks/service.go:178-180`).
  - GraphQL `createWebhookEndpoint` accepted the same input, so it was used here.
- **PASS, delivery.**
  - Every turn end in `bex` produced exactly one delivery, HTTP 200: 3 succeeded (`ags-dbmml52g3cdc73a60p9g`, `ags-dbmml5gts0lc739ecjtg`, `ags-dbmmo3qg3cdc73a60q00`) and 3 failed (`ags-dbmml6ots0lc739ecjvg`, `ags-dbmmo48ts0lc739eck8g`, `ags-dbmmpaots0lc739eckjg`).
  - The Standard Webhooks `webhook-signature` verified locally against the create-time secret for all 6.
  - `data` keys are exactly `{id, outcome, state}`, with `id` equal to the session id. There is no `summary`. `outcome` carries `result` on succeeded turns and `failureReasonCode` on failed ones.
  - "Nothing for an unsubscribed workspace" was not observable live; tests cover it.
- **PASS, spend ceiling** (`ags-dbmmo48ts0lc739eck8g`, `maxSpendUSD` 0.01):
  - The turn failed `AGENT_MODEL_SPEND_CAP_REACHED`, "this session reached its maxSpendUSD ceiling (… scope session)". bex-api logs show the mint refused "session ceiling: agent model spend cap reached".
  - `outcome.cost.modelUSD` 0.010892 equals the `agent_model_usage_events` `sum(price_microusd)` of 10892 over 3 requests (read-only SQL). s1 also matched: 0.005292 = 5292.
  - `/model-cost` reports 0.01, rounded to the cent by design. The agent-visible 429 body could not be read because the transcript of that session was empty (0 parts).
- **PASS, off-route ceiling.** A codex session (not on the platform route) with `maxSpendUSD` was refused with `400 AGENT_SESSION_SPEND_LIMIT_UNAVAILABLE` before create. No model key was set on `bex`.
- **PASS, migrations and plan.**
  - `schema_migrations` is at 202, so 0201 and 0202 are applied.
  - `EXPLAIN ANALYZE` of the webhook feed query (workspace `bex`, 1 h window) reads the agent arm through a Bitmap Index Scan on `agent_session_turn_events_feed_idx`, in 1.5 ms.
- **Bugs seen in the logs during the spend-cap failure:**
  - `schedule sandbox reap failed: column "sandbox_reap_after" is of type timestamp with time zone but expression is of type interval (SQLSTATE 42804)`. In `lego/backend/internal/store/agentsessions.go:731`, `$2 + make_interval(...)` makes Postgres infer `$2` as interval; it needs `$2::timestamptz`. Only a fake store tests it.
  - `terminate sandbox failed: delete session egress policy: … not found`. In `lego/backend/internal/sessionegress/policy.go:374`, the Delete after Get does not tolerate a concurrent delete.
- **Cleanup.** Sessions, webhook (DELETE 204, GET 404) and receiver deleted. The canary workspace is back to 7 services. Kratos sessions logged out, CLI grant revoked, run dir removed.
