## Objective

Replace bex's `secrets.*` names for env var writes with Render's three events, one row per kind of change a write made: `CreateEnvVarsEvent` for keys it added, `UpdateEnvVarsEvent` for keys whose value changed, `DeleteEnvVarsEvent` for keys it removed. A write that changes nothing records no `success` row.

## Context

- Render's reference: `CreateEnvVarsEvent` (variables created), `UpdateEnvVarsEvent` (variables modified), `DeleteEnvVarsEvent` (variables deleted); all in the pinned enum.
- ADR018's Audit logs row says env var writes other than a single delete keep bex's names because "one patch can create, update and delete keys at once, and splitting it into Render's three events is not a 1:1 mapping". No user sign-off is recorded, so under the AGENTS.md parity rule the divergence cannot stand.
- Verbs: `secrets.SetEnvVars` (replace-all), `secrets.SetEnvVar`, `secrets.PatchEnvironment` (`lego/backend/internal/secrets/batch.go:96`), `secrets.SeedEnvVars`, and the env-group writes (`lego/backend/internal/envgroups/patch.go:125`). `core.AuditVerbDeleteEnvVar` already maps to `DeleteEnvVarsEvent`.
- Values never enter an audit row; metadata may name keys. Secret files have no Render event and keep bex's names.

## Steps

1. In each write verb, compute the added, changed and removed key sets (the write already knows them).
2. After the write commits, record up to three rows with the keys in metadata (`metadata.service` or `metadata.envGroup` as today).
3. Amend ADR018's Audit logs row and ADR006 § Audit log.

## Acceptance criteria

- [ ] A patch that adds `K1` and changes `K2` records exactly one `CreateEnvVarsEvent` (keys `K1`) and one `UpdateEnvVarsEvent` (keys `K2`).
- [ ] A replace-all write records the applicable Create/Update/Delete rows; a no-op save records no `success` row.
- [ ] No row ever contains a value (test).
