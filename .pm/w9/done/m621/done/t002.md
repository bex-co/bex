## Objective

A Billing member is refused service events, deploy history and metrics on REST, GraphQL and MCP, while service lists, names and other non-sensitive details stay readable (Render: Billing "Can also view non-sensitive details of the workspace's resources (such as members and service names)").

## Context

- Events: `lego/backend/internal/events/service.go:1144,1283` on `can_view`.
- Deploys: `lego/backend/internal/deploys/service.go:483` (`List`) and `:534` on `can_view`.
- Metrics: `lego/backend/internal/metrics/service.go` (`:594`, `:1422`, `:1571`, `:1653`–`:1678`, `:1932`, `:1943`), `metrics/datastore.go`, `metrics/project.go`, `metrics/retention.go`: the 18 REST `GET /v1/metrics/*` operations, GraphQL `metrics`, `datastoreMetrics`, `projectMetrics`, `metricsFilters`, MCP `get_metrics`.
- Project observability views (saved searches, w3/m505) read logs and metrics; check them too.
- API key catalog: the monitoring level (`core/keygrant.go:317`) already requires `can_view_logs`, which a Billing member lacks.

## Steps

1. Move each read to the new relation.
2. Leave service, datastore and project lists and details on `can_view`.
3. Run `cd lego/backend && go test ./...`.

## Acceptance criteria

- [ ] A Billing member's events, deploys and metrics reads answer 403 on every surface; their service list still answers 200 with names.
- [ ] A Viewer still reads events and metrics and is still refused logs.

## Record (2026-11-24)

- **Moved to `can_view_activity`:** `events.List` and `events.Get` (REST `/v1/services/{id}/events`, `/v1/events/{eventId}`, GraphQL `serviceEvents`/`serviceEvent`, MCP `list_events`/`list_service_events`/`get_service_event`); `deploys.List` and `deploys.Get` (REST `/v1/services/{id}/deploys[/{deployId}]`, GraphQL `deploys`/`deploy`, MCP `list_deploys`/`get_deploy`); every authorization in `internal/metrics` (the REST `GET /v1/metrics/*` operations, GraphQL `metrics`, `datastoreMetrics`, `projectMetrics`, `metricsFilters`, `metricsPathFilterSuggestions`, `metricsRetention`, month-to-date bandwidth, MCP `get_metrics`/`get_datastore_metrics`); and a cron job's run history, `apps.ListCronRuns`/`GetCronRun` (REST `/v1/cron-jobs/{id}/runs[/{runId}]`, MCP `list_cron_job_runs`), because a cron run's start and end are Render's `cron_job_run_started`/`cron_job_run_ended` service events.
- **Project scope:** a project- or environment-scoped metrics read skips each resource the caller cannot read, so a Billing member got an empty 200. `resolveMetricScope` and `projectMetrics` now authorize `can_view_activity` on the scope's workspace first (`authorizeScopeActivity`), so the read answers 403 like every other surface.
- **Stays `can_view`:** service, Postgres, Key Value, project and environment lists and details; a project's saved views (names and filters, not data); the deploy action projection; Postgres database sizes and table scans (`postgres` package, not metrics). Logs stay `can_view_logs`.
- `cd lego/backend && go test ./...` passes; the real-deps runs of the e2e tests below pass.
