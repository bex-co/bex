## Objective

Create a repeatable test harness in which `@tanstack/react-virtual` actually renders a non-empty visible range, so the virtualization change in t002 can be verified. The m63 attempt reverted precisely because jsdom reports a 0-height viewport and the virtualizer rendered nothing (tried `initialRect`, a state-backed scroll ref, and `ResizeObserver`/`getBoundingClientRect` stubs).

## Context

- Reverted m63 attempt: `.pm/w9/045.md` (this milestone's source).
- Viewer under test: `dashboard/src/**/log-line-list.tsx` (path to confirm at start).
- Constraint (repo rule + note): the geometry helper must be **scoped** to this test — not a global `getBoundingClientRect`/`ResizeObserver` stub — so it can't perturb the other ~2,140 dashboard tests.
- Two acceptable approaches: (a) jsdom + a scoped setup helper that gives the scroll container + rows real geometry; (b) a Playwright walk against a busy tail. Pick one and justify.

## Steps

1. Reproduce the 0-height-viewport failure with a trivial virtualized list test.
2. Build a scoped helper (e.g. a `renderWithVirtualGeometry` wrapper or a per-test `Element.prototype` patch installed/removed in `beforeEach`/`afterEach`) that makes the virtualizer render a bounded visible range; OR wire a Playwright fixture that mounts the viewer with a seeded busy buffer.
3. Prove the harness works on a throwaway virtualized list (visible rows < total rows).
4. Confirm the full dashboard suite still passes with the helper present (no global leak).
