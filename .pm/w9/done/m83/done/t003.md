## Objective

Prove virtualization holds (only visible rows in the DOM for a large buffer), capture a before/after profile of a busy live tail, and raise the retained-line cap now that DOM size no longer grows with the buffer.

## Context

- `DEFAULT_MAX_LINES` bounds the retained buffer (path to confirm — likely near the log store / viewer). It was kept low partly because every retained line was a live DOM row.
- The dominant per-frame cost (ANSI re-parse) was already removed in m63; this milestone removes the remaining DOM-reconciliation cost on very busy tails.

## Steps

1. Add a test that seeds a 1,000-line buffer and asserts DOM rows << 1,000 (only the visible range + overscan), using the t001 harness.
2. Profile a busy live tail before/after (React Profiler or Playwright trace) and record the reconciliation-cost delta in the milestone README / a note.
3. Raise `DEFAULT_MAX_LINES` (or document why it stays) and confirm the viewer stays smooth at the new cap.
