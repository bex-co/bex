## Objective

Add one cleanup-safe, non-interactive verifier that drives the unmodified official Render CLI through supported service create/update flags and proves exact readback, including the paths the minimal dev-9 stack could not exercise.

## Context

- `scripts/cli-compat.sh verify` proves broad service CRUD but not the full flag matrix. `scripts/registry-credential-cli-verify.sh` and `scripts/samples-lifecycle.sh` contain reusable credential and lifecycle legs.
- dev-9 intentionally lacks OpenBao, the registry-credential store, and build infrastructure, so the new verifier must declare its capability prerequisites and fail/skip explicitly rather than converting dependency failures into product grades.
- The verifier must be safe against a non-local configured environment: unique names, recorded IDs, traps for cleanup, no token/secret printing, and no production default.

## Steps

1. Add `scripts/cli-services-parity-verify.sh` (or a clearly named mode under `cli-compat.sh`) that accepts an explicit bex endpoint/auth context and refuses an undeclared production target.
2. Create representative web, native cron, image/registry-credential, and static services; update every mutable supported field; GET each resource and assert whole values rather than exit codes alone.
3. Exercise `--env-var`, `--secret-file`, `--registry-credential`, native cron `--cron-command`, structured IP allowlist descriptions, and clear/replace behavior in an environment with required dependencies.
4. Exercise clone according to t001's truthful region contract: bare `--from` when the configured REST region is in the official enum, otherwise assert the documented explicit-`--region` workaround and client-side error.
5. Assert `update --runtime` never reaches bex and `--previews` returns the documented explicit platform rejection; neither may appear as a silent server no-op.
6. Wire a narrower dependency-free subset into `scripts/cli-compat.sh verify` and document how to run the configured-capabilities leg.

## Files

- `scripts/cli-services-parity-verify.sh` (new, or equivalent)
- `scripts/cli-compat.sh`
- `scripts/registry-credential-cli-verify.sh`
- `scripts/samples-lifecycle.sh`
- adjacent verifier fixtures/docs

## Acceptance criteria

- [ ] One command drives official CLI v2.21.0 create/update/readback across web, cron, and static service types and exits nonzero on any dropped supported field.
- [ ] Configured-dependency checks distinguish unavailable capability from failed semantics; a fully configured run proves env vars, secret files, registry credentials, and native cron command.
- [ ] The allowlist assertion compares descriptions as well as CIDRs.
- [ ] Cleanup runs on success, assertion failure, and interrupt; auth tokens, secret contents, and registry passwords never print.
- [ ] The regular `cli-compat.sh verify` suite retains a deterministic dependency-free regression leg.

## Out of scope

- Starting OpenBao/build/registry infrastructure inside the verifier.
- Editing or vendoring the official CLI.
