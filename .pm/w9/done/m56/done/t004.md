## Objective

Upgrade the service Settings networking editor from flat CIDRs to description-carrying entries so a user opening and saving an allowlist created by the official CLI does not erase its labels.

## Context

- `dashboard/src/features/services/components/service-networking-panel.tsx` and `use-service-networking.ts` currently read/write only `string[]` through `setServiceIpAllowList(cidrs:)`.
- The Database and KeyValue networking editors already use `IPAllowListEntry` with CIDR and description; reuse their form model, validation, and GraphQL operation patterns where practical.
- Existing entries synthesized from legacy App CRs have an empty description and must remain editable.

## Steps

1. Query `ipAllowListEntries` for services and submit the description-aware mutation input added by t003.
2. Adapt or extract the existing Database/KeyValue entry editor so service Settings exposes both CIDR and optional description without three divergent implementations.
3. Preserve order, empty descriptions, add/remove/clear behavior, validation errors, loading state, and success/error toasts.
4. Regenerate GraphQL definitions and update service fixtures/tests.

## Acceptance criteria

- [ ] Opening and saving a CLI-created `{cidrBlock, description}` pair preserves both values.
- [ ] Users can add, edit, reorder/remove, and clear entries; invalid CIDRs stay client-visible and are not submitted.
- [ ] Legacy entries with empty descriptions render and save correctly.
- [ ] `yarn typecheck`, `yarn lint`, and relevant dashboard tests pass.

## Out of scope

- A new standalone Networking page or redesign beyond the existing Settings panel.
- Changing environment-level ACL intersection behavior.
