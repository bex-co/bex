## Objective

Give service allowlist entries a description-preserving storage path while retaining byte-compatible reads and enforcement for existing `App` CRs that store `spec.ipAllowList` as flat CIDR strings.

## Context

- `lego/types/v1alpha1/app_types.go` currently defines `AppSpec.IPAllowList []string`; REST accepts Render's `{cidrBlock, description}` objects but `lego/backend/internal/apps/rest.go` immediately reduces them to strings.
- Database and KeyValue already use `v1alpha1.IPAllowEntry {cidr, description}`. Reuse that type and its description-agnostic enforcement pattern.
- Changing the existing App field's structural type in place would make old stored CRs fail decoding/admission. Prefer a parallel description-carrying field (for example `ipAllowListEntries`) with deterministic precedence, retaining the legacy flat field as a compatibility fallback.
- `lego/operator/internal/controller/app_controller.go` builds Traefik middleware source ranges from `AppSpec.IPAllowList`; descriptions must never influence enforcement.

## Steps

1. Add an optional structured service allowlist field to `AppSpec` using `IPAllowEntry`, leaving the existing flat field intact and documenting precedence/fallback.
2. Add shared helpers that return effective entries and effective CIDRs: structured entries win when present; legacy flat CIDRs synthesize empty descriptions.
3. Update App reconciliation and any spec comparison/copy code to enforce effective CIDRs only and avoid reconcile churn between old and new shapes.
4. Regenerate deepcopy and CRD manifests through the repository's make targets.
5. Prove old flat-only Apps, new structured Apps, empty lists, and clear operations all preserve existing reachability semantics.

## Acceptance criteria

- [ ] Existing flat `spec.ipAllowList: ["203.0.113.0/24"]` Apps still decode and render the same Traefik source ranges.
- [ ] New structured entries preserve `description` in the CR while enforcement consumes exactly their CIDRs.
- [ ] Structured entries have documented deterministic precedence over the legacy field; clear does not resurrect legacy values.
- [ ] Generated deepcopy/CRD artifacts are current and `make test` passes from `lego/operator/`.

## Out of scope

- Changing `EnvironmentIPAllowList`; it is an enforcement projection with no per-service user descriptions.
- A destructive fleet migration or in-place type change of the legacy field.
