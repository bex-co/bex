## Objective

Turn the checklist's mixed `[~]`, `[ ]`, and intended-divergence notes into an evidence-backed contract for this milestone before changing storage or adapters. Separate bex bugs and missing live evidence from behavior enforced inside the unmodified CLI or explicitly rejected by the platform.

## Context

- `docs/cli-compatibility-checklist.md` was graded with official CLI v2.21.0 on dev-9. Its service rows mix a real loss (allowlist descriptions), dependencies absent from dev-9, and deliberate limitations.
- The read-only upstream checkout at `cli/` shows `services create --from` copying the source service's `serviceDetails.region` and then validating it through `pkg/types/region.go`'s closed Render enum before sending Create. A source reported as `local-capd` or `fsn1` therefore cannot be cloned without an explicit allowed `--region`.
- `cli/pkg/types/service/serviceupdate.go` rejects `--runtime` before an API request. Fixing that would require changing/forking the official CLI, which `.pm/DO_NOT_DO.md` forbids.
- `--previews` is an explicit platform anti-goal and must remain `[-]`, not become implementation work.

## Steps

1. Capture the create/update flag inventory, client-side validation point, emitted REST field/path, expected bex readback, and current grade in `docs/render-artifacts/cli-services-create-update.md`.
2. Record a disposition for every non-green service row: bex bug, configured-dependency verification, upstream CLI guard, fixed-region compatibility limitation, or deliberate bex non-goal.
3. Capture representative request/response bodies through a logging proxy or test server, redacting tokens, env values, registry credentials, and secret-file contents.
4. Freeze the milestone boundary: no edits to `cli/`; no preview-environment implementation; no fabricated mapping from an arbitrary `BEX_REGION` to a Render enum. If a deployment deliberately configures a Render-enum region, bare clone must be included in t005; otherwise the explicit `--region` workaround remains a truthful limitation.

## Files

- `docs/render-artifacts/cli-services-create-update.md` (new)

## Acceptance criteria

- [ ] Every `services create` and `services update` flag has a captured client/API/readback contract and one disposition.
- [ ] The artifact proves which failures happen before any bex request (`update --runtime`, invalid cloned region) and which reach bex.
- [ ] Secrets and credentials are redacted; no `.env` or kubeconfig content is recorded.
- [ ] Scope contains no first-party CLI work, preview-environment work, or fake region metadata.

## Out of scope

- Implementing the allowlist fix (t002–t004).
- Claiming a platform-specific region is one of Render's regions when it is not.
