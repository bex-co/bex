## Objective

Thread the structured service allowlist through Core and all bex-api adapters so Render REST create/update/readback preserves descriptions and GraphQL/MCP expose the same semantic entries without breaking existing flat-CIDR consumers.

## Context

- `lego/backend/internal/apps/rest.go` owns the Render `{cidrBlock, description}` wire shape but its `fromIPAllowListEntries` helper currently discards descriptions.
- `AppView.IPAllowList`, GraphQL `ipAllowList`/`setServiceIpAllowList(cidrs:)`, and MCP `create_web_service.ipAllowList`/`set_service_ip_allow_list` use flat strings today.
- Database, KeyValue, and Environment already expose backward-compatible `ipAllowListEntries` GraphQL fields/input objects. Reuse their `core.IPAllowListEntry` conversions rather than inventing another entry type.
- Existing GraphQL and MCP callers using flat CIDRs must continue to work; new description-aware inputs need explicit precedence/conflict rules.

## Steps

1. Extend the service Core request/view and mutation verb to carry structured entries while retaining a flat-CIDR compatibility projection.
2. Change REST create and PATCH decoding to retain both `cidrBlock` and `description`; return the preserved values from service GET/list/create/update.
3. Add `ipAllowListEntries` to the service GraphQL type and description-aware mutation input, retaining the existing `ipAllowList` field and `cidrs` mutation argument as compatibility aliases.
4. Add description-aware fields to the MCP create and set tools, retaining the flat input alias with deterministic precedence and an error on conflicting simultaneous values.
5. Preserve Blueprint `ipAllowList: [{source, description}]` labels when it creates or updates a service through the same Core request.
6. Update audit/activity/webhook diffs, if they include this field, so descriptions are neither silently discarded nor logged as secrets.

- [ ] GraphQL and MCP can create/read/replace descriptions; their existing flat-CIDR inputs and outputs remain compatible.
- [ ] Conflicting legacy and structured inputs fail with Render-shaped `400`/equivalent adapter errors instead of choosing silently.
- [ ] Legacy flat-only App CRs project as structured entries with empty descriptions on REST/GraphQL/MCP.
