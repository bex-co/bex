# Cron detail page: surface last-run / next-run (Render parity gap)

Found 2026-08-20 comparing bex vs Render cron detail.

- **Render** cron details carry `lastSuccessfulRunAt` (per `docs/render-artifacts/cron-runs.md` + the ADR018 cron row) and the UI shows when the job last ran / next runs.
- **bex** cron detail header shows Schedule / Service ID / Slug / Instances / Revision / Created — but **no "last run" and no "next run"** readout. The run history lives only under the Events tab's Recent Runs table.

## Scope (likely a milestone — multi-surface feature, promote before building)

- **lastSuccessfulRunAt** is already derivable: the operator writes `App.status.runs[]` (capped terminal history). Project the most-recent `Succeeded` run's finish time.
- **next run** requires evaluating the cron expression — the `github.com/robfig/cron/v3` dep added in `w9/m91` exposes `Schedule.Next(time.Now())`, so bex-api can compute it server-side (UTC).
- Surfaces to keep consistent (Render-compatible, `docs/ADR006-bex-api.md`): REST `serviceDetails`/`cronJobDetails`, GraphQL, MCP, and the dashboard cron detail header.
- Watch the honesty rule from ADR038: omit a field rather than fake it (no runs yet ⇒ `lastSuccessfulRunAt` absent).

Render-parity-relevant; sits alongside the existing ✅ cron row in `docs/ADR018-render-parity.md`.

## DONE (2026-08-21)
