## Objective

A rerunnable harness that drives one sample through deploy → verify-up → suspend → verify-down → resume → verify-up → delete → verify-gone against a bex deployment, using the official Render CLI for every verb it has and raw Render-compatible REST for the rest, with per-leg pass/fail output (the `scripts/cli-compat.sh verify` style).

## Context

- CLI auth against prod: the operator's laptop CLI is logged in (`~/.render/cli.yaml`, host `https://api.bex.co/v1/`), or mint a key per `docs/cli-compatibility-checklist.md` harness notes; the script should take `RENDER_HOST`/`RENDER_API_KEY` like `scripts/cli-compat.sh` does.
- The official CLI has `services create/update/delete`, `deploys list`, `logs`; **service** suspend/resume are dashboard-only in Render's CLI — use REST `POST /v1/services/{id}/suspend|resume` (ADR007) and note the CLI gap per leg.
- Verify-up: poll `https://<name>.onbex.co` for the sample's expected body (each sample's `MESSAGE`/known output). Verify-down after suspend: the app response stops (suspended interstitial or non-200 — pin the actual prod behavior, ADR007). Verify-gone after delete: service absent from `services -o json`, URL dead, no pods/`reg-pull-*` Secret/htpasswd user left (kubeconfig optional — degrade to API-only checks when absent).
- Per-sample parameters: name, create flags (repo/rootDir/runtime/image/publish-directory/schedule), expected body, health path. Data-driven so t003/t004 add samples without editing legs.

## Steps

1. Write `scripts/samples-lifecycle.sh <sample>` + a small per-sample spec table; wire evidence logging (timestamps, deploy ids, HTTP codes).
2. Smoke it end-to-end against prod with `hello-go` (known-good from m43).
