## Objective

Check every surface this milestone touched (REST, GraphQL, MCP, dashboard, CLI) for consistency, compared with the reference product (Devin for agent surfaces, render.com for hosting); record matches and deliberate divergences in the README, file drift.

## Done (2026-11-06) — parity check

- **Surfaces agree.**
  - REST `/v1/agent-skills`, GraphQL `agentSkills`/`agentSkill` plus mutations, MCP `*_agent_skill` and the dashboard card all expose the same fields: name, description, triggers, enabled, body/content and version.
  - Every surface uses the same `skills: [{name, arguments}]` on create/steer and the same error codes.
  - The CLI flag `--skill` is owed by the m175 CLI follow-through note.
- **Against Devin Skills** ([docs](https://docs.devin.ai/product-guides/skills)):
  - Matches:
    - SKILL.md format (name, description, `triggers` user-only, body);
    - repo skills discovered by the engine;
    - workspace skills (Devin's Organization scope);
    - explicit invocation with arguments (`@skills:` / `$ARGUMENTS`, `$1`–`$9`);
    - API invocation (Devin's `playbook_id`).
  - Gaps, recorded as ADR099 follow-ups and not regressions:
    - Personal and Enterprise scopes;
    - plugins/marketplace distribution;
    - "Devin writes a skill from this session";
    - per-save version history;
    - `allowed-tools`/`permissions` enforcement, which depends on m176.
