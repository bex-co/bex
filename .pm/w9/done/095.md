# A render.yaml change to an environment's own settings plans as no change

Why: w9/094 found that a Blueprint whose only change is an environment's own setting (for example `protection`) plans as `no_changes`, so in an approval-mode Blueprint it is never offered or applied. On Render a Blueprint applies every change it declares, environments included.

- Extend the planner to diff the declared environments' own settings (protection, and any other environment-level fields the sync applies) against the stored ones, and list them in the plan.
- Cover it with an approval-mode test whose only change is an environment's `protection`, plus an unchanged file that still plans `no_changes`.

## Done (2026-11-12)

The plan lists declared environments the sync will create or change (`kind: environment`, `changedFields` `permissions.protection` / `networking.isolation`), sharing the comparison with the sync. Unchanged environments are not listed, so the output and `totalActions` for an unchanged file are as before. Render's CLI ignores plan actions on validate and only prints `rawPlan`. Approval applies the setting. The dashboard counts environments separately (en and zh).

Tests:

- approval-mode protect, unprotect and isolation changes, plus a new empty environment;
- an unchanged file;
- a real-Postgres plan → approve → re-plan `no_changes`;
- the dashboard summary.
