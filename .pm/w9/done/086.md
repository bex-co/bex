# An automation link opens in the browser's current workspace, not the automation's

Why: every link to an automation (the w9/m343 pause push and email, and since w9/084 the mobile tap) is `https://dashboard.bex.co/automations/<aut-id>` with no workspace. The page looks the id up in the cookie-selected workspace (`dashboard/src/features/agent-automations/hooks/use-agent-automation.ts:34-36`), so a member of several workspaces whose browser has another one selected gets "not found".

- The dashboard has no URL workspace switch. Either the page finds the workspace from the `aut-` id (for example, a by-id read across the caller's workspaces) and switches to it, or links carry the workspace and the page switches before it reads.
- Check how Render's dashboard deep links pick the workspace (its URLs carry the owner id) and match it for every resource link the notifications send.
- Cover: a member of two workspaces opens a link to the other workspace's automation and lands on it.

Triage (2026-11-12):

- bex-api already resolves an automation's workspace from an `aut-` id when `ownerId` is omitted: `scopeAutomation` (`lego/backend/internal/agentsessions/automations.go:524-534`) goes through `core.ScopeByID`, as blueprints and webhooks do.
- The dashboard already has `useAdoptResourceWorkspace` (`dashboard/src/features/workspaces/hooks/use-adopt-resource-workspace.ts`, used by service pages), which follows a resource to its workspace once and checks membership.
- The fix:
  - make `$ownerId` optional in the `AgentAutomation` query and omit it for an id (`^aut-[0-9a-v]{20}$`; a name is per workspace and keeps it);
  - call `useAdoptResourceWorkspace` from the detail and edit pages, not from the shared hook, so the session header's automation line never switches workspace.
- Render's dashboard URLs (`/web/srv-…`) carry no workspace either; the page follows the resource.

## Done (2026-11-12)

An automation link now opens in the automation's own workspace.

- **Reads and writes by id:** the `AgentAutomation` and `AgentAutomationRuns` queries and the by-id mutations (update, delete, pause, resume, take over, run now) send no `ownerId` for an `aut-` id (`isAutomationId`), so bex-api resolves the workspace from the id. A name keeps the selected workspace.
- **Switching:** the detail and edit pages call `useAdoptResourceWorkspace`, which now reports when adoption is pending. They keep their skeleton until the owner's workspace is selected, so role-gated actions never render for the wrong one.
- **The session header** reads the automation by id with no switch.
- **Tests:** `use-agent-automation.test.tsx` (an id reads with no owner, even before a workspace is selected; a name waits for one and reads within it); page tests for adoption behind the skeleton on both pages. The dashboard's `yarn lint` passes and `yarn test` passes 6873.
