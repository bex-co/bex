# A plan change that turns edge caching on or off records no event

Why: caching needs a non-free tier, so `SetPlan` from paid to Free silently stops a service's edge cache, and back to paid restarts it, with no `edge_cache_*` event (w9/m345 records only `apps.SetCacheProfile` saves). The feed can keep showing `edge_cache_enabled` for a cache that is off.

- Check Render: does a downgrade to Free emit `edge_cache_disabled` (with `trigger.system: true`?), or refuse the downgrade while caching is on?
- `apps.SetPlan` is already its own `plan_changed` event, so a toggle needs its own row or fact. Match whatever Render does.

## Done (2026-11-12)

When `apps.SetPlan` crosses Free for a cached service, it records `edge_cache_disabled` or `edge_cache_enabled` with `trigger {manual: false, user, system: true}` beside `plan_changed`. Both rows are written in one transaction, and the profile is kept. This is recorded as the Render-parity-first recommendation (Render's own behaviour is unverified).
