## Objective

Surface clear, Render-familiar build-log lines for cache restore/clear/upload, emit size/hit metrics, and add security/resilience guards against symlinks, path traversal, oversized archives, and corrupt payloads.

## Context

- Render's build logs show cache restore and upload progress (`render.com/docs/deploys`).
- Tenant build commands control every file written under `$XDG_CACHE_HOME`, so archive creation and extraction must resist symlink escape, `..` traversal, special device nodes, and zip/zstd bombs.

## Steps

1. Emit concise user-visible build-log lines in `cache-restore`, `cache-purge`, and `cache-save` (`==> Restoring build cache...`, `==> Build cache cleared`, `==> Uploading build cache...`) and update `native_log_display_test.go` so they display cleanly.
2. Harden archive pack/unpack: strip or refuse symlinks escaping `/opt/render/.cache`, enforce `--no-same-owner`/size cap on unpack, and treat any extraction failure as an empty cache with a log warning rather than a failed build.
3. Extend `bex_build_cache_bytes` / `bex_build_cache_phase_seconds` labels to distinguish `kind="xdg"` from `kind="layer"`.

## Done — 2026-11-18

- **Build log, as Render's:** a restored cache prints `==> Downloading cache...` (cache-restore) and `==> Transferred 200KB in 1s. Extraction took 0s.` (the wrapper, before `==> Running build command`); an unusable one prints `bex: no usable build cache; building clean`. **Deviation:** no `Uploading build cache` / `Build cache cleared` lines. Render's log prints none for saving or clearing (its build logs show only the restore pair), so bex stays silent there too. No bucket or endpoint reaches the log.
- **Guards:** the archive is made and unpacked only inside BuildKit's sandbox, which already runs tenant code. The seed unpacks at most 7 GB (`head -c` on the decompressed stream), checks gzip's own status, and empties the mount on any failure (`..` members, a symlink written through, a corrupt or truncated stream). The save refuses a directory, tar stream or archive over 7 GB and archives with `--remove-files`. cache-save stores only a regular file.
- **Metrics:** `bex_build_cache_phase_seconds{phase,kind,outcome}` and `bex_build_cache_bytes{phase,kind}`, with `kind` `layer` or `xdg`. The Builds dashboard splits by kind, and `BuildCacheStoreErrors` counts both kinds.
- Tests: `xdgcache_test.go` (phase scripts against the fake store, the wrapper against a fake buildctl, the seed and save steps on GNU userland), `TestCachePhaseSignalsReadOnlyOurOwnOutcomes`, `TestRecordBuildSignalsMetersEachCachePhase`, promtool `alerts_test.yml`.
