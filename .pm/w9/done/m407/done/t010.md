**Done 2026-11-14.** The surfaces agree (t009): GraphQL, REST and MCP list the same builds with the same statuses, triggers and failure codes, and show the same `environmentBuildId` on a session; the dashboard card and builds dialog read the same fields. Against Devin's [Blueprints § Builds and sessions](https://docs.devin.ai/onboard-devin/environment/blueprints) and [Blueprint reference](https://docs.devin.ai/onboard-devin/environment/blueprint-reference) (checked 2026-11-14):
- **Statuses:** queued, building, success, failed and cancelled. Devin's `partial` is omitted because a bex build covers one repository (ADR111 D2).
- **Sessions use the latest successful build** and "the latest code is pulled" at start (t009: the image at `9bf6ccf2b` booted onto `83562b154`). Setup is not rerun, and the overlay names the steps, as Devin shows `maintenance`.
- **Triggers:** a blueprint save, a repository secret, a manual build and a ~24 h refresh. A newer trigger replaces a queued build.
- **Limits and secrets:** steps time out after 3 h. Secrets are injected during the build and not kept as environment; files a step writes are kept, with the same warning.

Structural difference already recorded in ADR111: Devin builds one organization snapshot at a time, while bex builds per repository, one at a time per repository and two per workspace. Not adopted: pinning (ADR111). No unrecorded divergence.
