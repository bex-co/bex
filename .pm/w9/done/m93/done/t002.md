## Objective

Prove `effectiveRuntime` is **total**: no `(type, source, builder)` combination
the create API accepts yields an empty runtime for a runnable type except the
explicitly enumerated no-runtime shapes (buildpack, static site). This is the
belt-and-suspenders that a future build strategy added to the CRD/create path
can't compile-pass while silently returning "" the way the builder-vs-runtime
seam did in w4/052.

## Context

- `lego/backend/internal/apps/service.go` `effectiveRuntime(spec, svcType)` — the
  single spec→runtime projection.
- The accepted inputs are bounded by the CRD enums:
  `Runtime` ∈ {docker,elixir,go,image,node,python,ruby,rust} ∪ {""},
  `Builder` ∈ {auto,buildpack,dockerfile,native} ∪ {""} (kubebuilder default
  `auto`), and `Type` ∈ the five service types — plus the source axis (repo set /
  image set). Cross-check against `resolveBuildStrategy` so the test's accepted
  set matches what create actually persists.
- Enumerated no-runtime shapes: `builder:buildpack` (bex extension, no Render
  runtime) and `static_site` (bex's runtime enum has no "static").

## Steps

1. Enumerate the accepted `(type, repo?/image?, runtime, builder)` combinations
   the create path can persist (a small generated cross-product filtered by
   `resolveBuildStrategy`'s acceptance rules).
2. Assert: for every runnable (non-static) combination that is NOT an enumerated
   no-runtime shape, `effectiveRuntime` returns a non-empty value in the CRD
   runtime enum; for the enumerated no-runtime shapes it returns "".
3. Keep the enumerated exception list explicit in the test so adding a new
   builder/type without a runtime mapping fails here loudly (a maintenance
   tripwire, not a silent skip).
4. Run `cd lego/backend && go test ./internal/apps/... && make lint-backend`.
