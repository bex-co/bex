## Objective

When the GitHub App delivers a `pull_request` event for a session's PR, update the state at once instead of waiting for the next reconcile. The reconciler stays the source of truth.

## Context

- `lego/backend/internal/apps/webhook.go:443` answers every event but `push` and `check_suite` with `{"ignored": event}`; PR feedback already parses PR payloads (`lego/backend/internal/agentsessions/pr_feedback.go:193-218`).
- Subscribing the production App to Pull request events is a GitHub settings action for the user (as for m344); this task must not depend on it.

## Steps

1. Route `pull_request` events to a handler that maps `closed` (+`merged`), `reopened`, `ready_for_review` and `converted_to_draft` onto the session's state.
2. Add Pull request to ADR026's list of events the App should subscribe to, marked optional.

## Files

- `lego/backend/internal/apps/webhook.go`
- `lego/backend/internal/agentsessions/` (PR state handler)
- `docs/ADR026-github-integration.md`

## Acceptance criteria

- [ ] Signed `pull_request` deliveries update the state; unsigned ones are refused as today; an event for a PR no session owns changes nothing.

## Out of scope

- Subscribing the production App (a user action).

## Done (2026-11-14)

`apps/webhook.go`: `pull_request` deliveries go through one `deliveryScopes` helper shared with PR feedback — only state-changing actions (opened, closed, reopened, ready_for_review, converted_to_draft) reach the workspace lookup — and `PRStates.HandlePullRequestEvent` records the state in the installation's workspaces (`RecordPullRequestState`). ADR026 marks the Pull request event optional (it only makes a merge or close show at once).
