# 070 — One guard for "a service's read must be re-sendable as a create"

Why: the same invariant has now been broken three times, each in a different
field, and each guard written for it was scoped narrowly enough to miss the
next one. Filed and closed 2026-09-21 by `/loopx w9` as the named next step of
[`069`](069.md).

## The class

`services create --from <id>` reads a service and sends it back. Every field a
read publishes that its own create refuses breaks that journey — and the bug is
invisible from inside bex, because each surface looks self-consistent:

| defect    | field                                | why the existing guards missed it                          |
| --------- | ------------------------------------ | ---------------------------------------------------------- |
| `w4/052`  | `serviceDetails.runtime`              | fixed by `w9/m93`, whose guard covers **build-strategy** shapes |
| `w9/068`  | `serviceDetails.maintenanceMode`      | m93's guard does not reach plan-gated fields                |
| `w9/069`  | top-level `branch`                    | 068's guard echoes only `serviceDetails`, one level too low |

## What landed

`internal/apps/readback_resend_test.go` —
`TestEveryServiceShapeReadsBackReSendable`. For nine service shapes (free and
paid repo-backed web, prebuilt image, docker web, docker cron, native cron,
static site, private service, background worker) it GETs the service, echoes
**every top-level key the create API accepts** plus `serviceDetails` back into a
`dryRun` create, and requires acceptance.

The echoable set is derived by reflecting over `createServiceRequest`'s json
tags rather than hand-listed, so a create-settable field added tomorrow is
covered without anyone remembering to extend a list. Two deliberate exceptions,
both documented in the test: identity fields a clone replaces (`name`,
`ownerId`, `environmentId`), and the one spelling the pinned client itself
translates — a read publishes a prebuilt image as top-level `imagePath` while
create takes Render's nested `image` object, exactly as `pkg/service/clone.go`
maps it.

**Mutation-checked against real history:** reverting `068`'s and `069`'s fixes
makes it fail on the free web service, the prebuilt image, and the docker web
service. It is a `dryRun` guard by design — the subject is whether the request
is **accepted**, not what it builds.

Full backend suite + `make lint-backend` (0 issues) green.

## Not covered

- Datastores (`postgres`/`keyvalues`) have their own read/create shapes and are
  not in this matrix.
- Acceptance only. A field that is accepted but silently dropped is the
  `w9/m165` class, which the live parity verifier's legs cover instead.
