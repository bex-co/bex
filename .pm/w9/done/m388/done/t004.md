## Objective

When a workspace's rules change, write them to every eligible App, Database and KeyValue in the workspace; resources created later get them at create.

## Context

- The environment layer's membership sync and fan-out (ADR032 § Membership sync; `lego/backend/internal/environments/`).
- `core/environment.go:162-177` projects the environment layer onto a resource.

## Steps

1. Fan out on change with retries; project the layer at every create path (services, Postgres, Key Value, Blueprint).

## Files

- `lego/backend/internal/workspaces/`, `lego/backend/internal/environments/`, `lego/backend/internal/core/environment.go`

## Acceptance criteria

- [ ] Tests: a change reaches every eligible resource; a new resource is born with the layer; ineligible types are untouched.

## Out of scope

- Rate-limiting the fan-out beyond the existing writers.

## Done (2026-11-14)

A save fans out with `core.PatchEach` (patch from the listed objects, skip unchanged, re-read only on conflict, 8 at a time, under `core.WithWorkspace`) to every App, Postgres and Key Value in the workspace, then re-reads the stored rules so concurrent saves converge on the last one. Every create path projects the current layer: service create, Blueprint creates (one read per stack), Postgres create and recovery, Key Value create, and the control-plane projector's create branch (one read per workspace per pass, fail closed).
