# Cron create/deploy small copy + UX gaps vs Render

Two low-severity divergences found 2026-08-20 (bex vs Render cron), both dashboard-side, sub-hour:

1. **Name not auto-filled from the image/repo.** Render's cron create pre-fills the service Name from the chosen image (e.g. `busybox:latest`) or repo; bex leaves Name blank (placeholder `my-service`). Pre-fill a sensible default from the Existing-Image tag / selected repo so the form starts submittable, matching Render. (The create form already derives a name draft via `useServiceNameDraft` — check whether it just needs the image tab to seed it.)

2. **Generic "Your service is live 🎉" deploy copy for a cron.** A `cron_job` reconciles to a CronJob with no long-running instance, so "your service is live" is misleading — a cron isn't "live", it's scheduled. Render frames cron deploys as scheduled, not "live". Adjust the deploy-log / status copy for `cron_job` (and likely `background_worker`, which is also not a served "live" URL) to something like "scheduled" / "deployed". Backend deploy-log text + dashboard status framing.

Neither is on the board yet. Related pricing/tier/entry-point items are in `w9/054`; validation + chrome + schedule-preview shipped in `w9/m91`.

## DONE (2026-08-21)

Item 1 (name auto-fill) was a **false positive** — the create form already fills the name from the image/repo via `useServiceNameDraft` (`imageSlug`/`repoNameSlug`); the blank Name seen earlier was just the fresh form before a source was chosen (matches Render). Item 2 implemented: `terminalLine` in `internal/logs/progress.go` is now service-type-aware — a successful `cron_job` deploy narrates "==> Cron job deployed — runs on schedule 🎉" instead of "your service is live" (background workers keep "live").
