## Objective

Write `scripts/terraform-provider-verify.sh`: run `render-oss/terraform-provider-render`'s own acceptance tests in record mode against a bex API, one resource package at a time.

## Context

- The provider's test helper (`internal/provider/testhelpers/provider.go`) records with go-vcr; `UPDATE_RECORDINGS=true` switches to record-only mode and requires `RENDER_HOST` and `RENDER_API_KEY` (plus `RENDER_OWNER_ID`). `GNUmakefile` runs `TF_ACC=1 go test ./... -timeout 120m`.
- The packages: backgroundworker, cronjob, dedicatedip, envgroup, keyvalue, logstreams, metricstream, notifications, postgres, privateservice, project, redis, registrycredential, staticsite, webhook, webservice.
- AGENTS.md "No build artifacts or evidence dumps in git": re-recorded cassettes are run output. Keep them under a temp directory; record only their sha256 and an object-storage link.
- Target: the worker's dev-9 stack (`scripts/dev-env.sh 9 up`) built from the tree, or bex-canary as the QA user. Tests create real resources; every run must destroy what it created.

## Steps

1. Pin the provider commit (start from `06af456`, 2026-11-16) and a Terraform version.
2. Clone into a temp dir, export the bex host, key and owner, run each package with `TF_ACC=1 UPDATE_RECORDINGS=true`, and collect pass/fail per test.
3. After each package, list and delete anything left in the workspace whose name the tests use.
