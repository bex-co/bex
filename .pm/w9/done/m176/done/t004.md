## Done (2026-11-06) — parity check against Devin

| Devin (v3 sessions API) | bex (ADR100) |
| --- | --- |
| `status: running`, `status_detail: waiting_for_approval` | `state: needs_input`, `waitingFor: approval` |
| `status_detail: waiting_for_user` | `waitingFor: user` (the agent's `ask_user` tool) |
| `bypass_approval` on create | `bypassApproval` on create, gated by the workspace's `approvalBypassAllowed` |
| answering: send a message to the blocked session | an explicit decision answer (REST `POST …/decisions/{id}`, GraphQL `answerAgentSessionDecision`, MCP `answer_agent_session_decision`, dashboard callout, `bex agent answer`) |
| org deny/ask rules override member settings and Bypass | the workspace mode is the floor; lowering it needs `approvalBypassAllowed` |

- REST, GraphQL, MCP, the dashboard and the CLI expose the same fields (`waitingFor`, `outcome.pendingDecision`, `approvalMode`) and the same refusals (`AGENT_SESSION_DECISION_*`, `AGENT_SESSION_APPROVAL_*`).
- **Deliberate superset:** an explicit decision id makes an answer idempotent (409 on a second answer). Sending a free-text message still works through steer once the turn ends.
- **Gaps, recorded as ADR100 follow-ups:**
  - Devin's "Smart" fast-model auto-approval;
  - org-level deny rules (`security_profile`);
  - a GraphQL count of open decisions (the callout shows the oldest).
