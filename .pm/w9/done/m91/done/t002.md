## Objective

Make the cron **Settings** edit-form Schedule field validate like the create form: disable "Save changes" and show an inline error while the crontab is invalid, so a bad schedule can't be submitted in the first place. The server rejects it after t001, but the client should never let the user submit it.

## Context

- Today the create form (`/services/new?type=cron_job`) marks the Schedule field invalid, shows "Enter a valid 5-field cron expression, e.g. 0 0 * * *", and disables Deploy. The Settings edit form (`/services/<id>/settings`) has neither — Save changes stays enabled and the bad value posts.
- Reuse the create form's existing cron-validation helper/component rather than duplicating it.
- Keep the error message consistent with t001's server-side message where practical.

## Context files

- `dashboard/` cron create form component (schedule field + validation)
- `dashboard/` service Settings "Edit schedule" component

## Steps

1. Find the shared schedule-input validation used by the create form.
2. Apply it to the Settings "Edit schedule" field: invalid → field marked invalid, inline error, Save disabled.
3. Verify valid edits still save and the success toast still fires.

## Files

- `dashboard/src/...` cron settings edit component
- `dashboard/src/...` shared schedule validation helper

## Acceptance criteria

- [ ] Typing `99 99 * * *` in Settings marks the field invalid and disables Save changes.
- [ ] A valid schedule re-enables Save and persists.
- [ ] The validation helper is shared with the create form, not copy-pasted.
