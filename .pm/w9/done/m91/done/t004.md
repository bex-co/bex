## Objective

Bring the cron Schedule field up to Render's UX on both create and edit: a live human-readable translation of a valid cron expression, a sensible pre-filled default on create, and an explicit note that schedules run in UTC.

## Context

- Render's Schedule field shows a live translation next to the input (e.g. `*/5 * * * *` → "every 5 minutes"), pre-fills `*/5 * * * *` on create, and links to a cron reference. bex shows only the static "5-field crontab" hint, no pre-fill (placeholder `0 0 * * *`), and no timezone statement.
- bex cron runs are UTC (run-pod logs are UTC); Render documents cron schedules as UTC. Stating it on the field removes a common footgun.
- Use a small, dependency-light cron→English helper (or an existing one already in the dashboard) — keep it consistent with the t002 validity check so "valid" and "has a preview" agree.

## Steps

1. Add a live human-readable preview beside the Schedule field on create and edit, shown only when the expression is valid.
2. Pre-fill a default schedule on the create form (match Render's `*/5 * * * *` or the current placeholder value — pick one and make it the actual value).
3. Add a short "Runs in UTC" note to the field helper text.

## Files

- `dashboard/src/...` cron schedule field component (shared by create + edit)

## Acceptance criteria

- [ ] A valid schedule shows a human-readable description; an invalid one shows no (stale) description.
- [ ] The create form starts with a valid default schedule value, not an empty field.
- [ ] The field states schedules run in UTC.

## Out of scope

- Backend timezone handling (schedules already run UTC — display only).
