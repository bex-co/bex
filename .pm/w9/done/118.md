# Render's classic API keys act in every workspace their user belongs to; a bex key acts in one

Why: a Render user holding a classic key reaches all their workspaces with it; a bex key is bound to the workspace it was minted in, so a multi-workspace script needs one key per workspace.

- **Render** ([render.com/docs/api-keys](https://render.com/docs/api-keys), read 2026-11-18): classic keys "have the same permissions as your member role in every workspace you belong to" and "continue to work as usual"; scoped keys, the newer form, "can only access the workspace you create it in", and a workspace without scoped keys yet should "continue creating classic API keys".
- **bex** (w9/m481): a key acts with its creator's current role in its own workspace only (invariant I2), which is Render's scoped key.
- **Decide first:** whether bex offers the classic form at all, given Render is moving to scoped keys. If yes, the request-time ceiling (`core.keyCeiling`) is the safe mechanism: the key's decision in each workspace is its creator's there, and its home-workspace check widens to "any workspace the creator belongs to". Record the choice in ADR018's API keys row.
- **Done when:** the choice is recorded with Render evidence, and, if taken, a classic key lists and acts in each of its creator's workspaces with that workspace's role, on every surface.
- Filed by w9/m481 t009.
- **Decided 2026-11-19 (w9 `/loopx`): bex offers no classic key, because Render no longer mints one.** Render's changelog "Fine-grained API keys now generally available" (2026-11-18, [render.com/changelog](https://render.com/changelog)): "Newly created Render API keys are now scoped to a single workspace", and "API keys created before this release have access to every workspace you belong to, with permissions matching your member role". [render.com/docs/api-keys](https://render.com/docs/api-keys), re-read 2026-11-19: classic keys are "API keys you created before Render rolled out scoped API keys", they "continue to work as usual", Render recommends "replacing your classic keys with scoped API keys", "Can scoped API keys access multiple workspaces? No.", and the create form asks to "Select the workspace your key can access". The "continue creating classic API keys" advice this note quoted is gone. No bex key was ever multi-workspace, so Render's legacy form has nothing in bex to keep working. Recorded in ADR018's API keys row, ADR012 §8e and ADR024 I2. Proven on every surface: `requireOneWorkspaceKey` in `lego/backend/internal/api/apikey_creator_role_e2e_test.go` (real Postgres and OpenFGA) shows a key whose creator is in two workspaces lists only its own on `GET /v1/owners`, GraphQL `workspaces` and MCP `list_workspaces`, and is refused the other on each; a mutation that lists the creator's workspaces for a key fails all three.
