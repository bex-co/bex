# `PUT /v1/services/{id}/env-vars` and `…/secret-files` with a `null` body answer 400, where Render clears the list

Why: Render's Terraform provider clears a service's environment variables or secret files by sending `null`, for example when a configuration drops `env_vars`. bex refuses that request, so the update fails after the service itself was already patched.

- **Found by:** w9/m474, dev-9, 2026-11-18 ([checklist](../../../docs/terraform-compatibility-checklist.md), class 5). 9 provider tests stop on it in run B (cron, worker, private and web services).
- **Render:** the provider's cassettes hold 66 such requests (32 `env-vars`, 34 `secret-files`, body `null`), all answered `200 []`. Example: `backgroundworker/resource/testdata/docker_cassette.yaml`.
- **bex:** the Render request gate answers `400 request body does not match the Render API schema`. `lego/backend/internal/api/render_openapi.go` `nullableProperties` made `envVars`/`secretFiles` nullable inside the create body only (w9/m472 t004), and its comment assumes PUT's own body must stay non-null; the recordings show otherwise.
- **Done when:** both PUTs with a `null` body answer 200 `[]` and leave the service with no variables or files, a test covers each, and `TestBackgroundWorkerDockerResource` passes its second step.

## Resolution

**DONE 2026-11-18.** The Render request gate now takes a JSON `null` body on `update-env-vars-for-service` and `update-secret-files-for-service` as the empty list (`renderNullableBodyOperations` in `lego/backend/internal/api/render_openapi.go`). The body schema is replaced by a nullable copy (`nullableCopy`), so `create-service`'s `envVars`, `create-env-group`'s and the build-source PUTs, which share it by `$ref`, keep their own non-null contracts. The handlers already decoded `null` as a nil list, which `SetEnvVars` and `SetSecretFiles` store as an empty set.

Tests, each failing with the change reverted (400, or "body is not nullable"):

- `TestEnvVars_NullReplaceAllClearsTheList` (`internal/api/envvars_test.go`) drives the composed server: a service with a variable and a file, each `PUT … null` answers 200 `[]`, the `GET` reads `[]` and the store holds nothing. A `{}` body keeps its 400.
- `TestRenderValidatorAcceptsTerraformProviderNulls` gains both PUTs and two controls (an object body, a `null` file item), and `TestTerraformProviderNullsLeaveSharedSchemasStrict` now checks both PUT bodies are nullable and the build-source PUTs and `create-env-group`'s `envVars` are not.

ADR018's env-vars and secret-files rows and the [checklist](../../../docs/terraform-compatibility-checklist.md) (class 5, run D) record the change.
