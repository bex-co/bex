# CORS failure on api.bex.co/graphql during cron delete

Observed 2026-08-20 (Playwright QA of cron jobs on dashboard.bex.co). Deleting a cron job succeeded, but the browser console logged:

```
Access to fetch at 'https://api.bex.co/graphql' from origin 'https://dashboard.bex.co'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present...
Failed to load resource: net::ERR_FAILED @ https://api.bex.co/graphql
```

- The delete itself worked (SSR/mutation path), so this is a secondary browser-side GraphQL call to `api.bex.co` being rejected by CORS.
- Investigate: which call fires client-side to `api.bex.co/graphql` on the settings/delete flow, and why CORS lacks `Access-Control-Allow-Origin` for the `dashboard.bex.co` origin. Compare with `withCORS` handling (see w9/m61 which already touched the CORS `Vary` header).
- Likely sub-hour once located; may just be a stray client fetch that should go through the same-origin/BFF path. Confirm no functional impact beyond console noise.

---

## Resolution — 2026-08-22

**Status: DONE (no code defect — operational/transient).** The cross-origin browser call to `https://api.bex.co/graphql` is the designed topology (`factory.client.ts` uses `VITE_API_URL` with `credentials: "include"`; credentialed CORS per ADR006), not a stray fetch. Verified live against prod 2026-08-23: preflight `OPTIONS` → 204 with correct `access-control-allow-origin: https://dashboard.bex.co` + `allow-credentials`, and even 401 error responses carry full CORS headers; the w9/m61 `Vary` fix is deployed and correct. The observed block was a Cloudflare/edge-generated error response during a platform roll (deploy-image pins bracket the QA window; sibling note 053's "Live tail disconnected" from the same session corroborates a momentary api.bex.co blip) — edge errors carry none of the app's CORS headers, which Chrome reports exactly as observed. Functional impact: none (the `RetryLink` retries transport failures; the delete succeeded). If the console noise itself is ever worth eliminating, that's a platform-ops follow-up (CORS headers on Cloudflare error pages), not a codebase change.
