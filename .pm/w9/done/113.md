# A `PATCH` of an image service that carries `rootDir: ""` answers 400 "has no repo to build", where Render accepts it

Why: Render's Terraform provider sends every service's `rootDir` on update, `""` for an image service. bex reads any `rootDir` as a request to set a build root, so every update of an image-backed `render_web_service` (and the other image service types) fails.

- **Found by:** w9/m474, dev-9, 2026-11-18 ([checklist](../../../docs/terraform-compatibility-checklist.md), class 9). It stops `TestWebServiceResource_Image` at its second step.
- **Render:** `webservice/resource/testdata/web_service_image_cassette.yaml`. `PATCH /v1/services/{id}` with `{"image":{"imagePath":"docker.io/library/nginx:stable-perl",…},"rootDir":"",…,"serviceDetails":{…,"runtime":"image"}}` answers 200.
- **bex:** `400 service "srv-…" has no repo to build (root directory only applies to build-from-git)`, from `lego/backend/internal/apps/settings.go`'s `RootDir` patch field through `settings_check.go` `checkRootDir`, which refuses an image service before comparing the value with the service's own empty root.
- **Done when:** a `rootDir` equal to the service's current one (`""` for an image service) is a no-op on PATCH, a different one is still refused by name, a test covers both, and `TestWebServiceResource_Image` passes its second step.

## Resolution

**DONE 2026-11-18.** A `rootDir` equal to the service's own is no change. `checkRootDir` (`lego/backend/internal/apps/settings_check.go`) now reports whether the value changes the root directory. The protected-environment guard still runs first, as the source's does. An unchanged value then returns before the repo check, so the patch row folds nothing into its probe and `SetRootDir` writes nothing, records no audit row and bumps no `restartedAt`. That holds on the REST `PATCH`, MCP `update_service` and GraphQL `setRootDir`, which share the row and the verb. A different root directory on an image service is still `400 … has no repo to build (root directory only applies to build-from-git)`.

`TestPatchKeepsTheServicesOwnRootDir` (`internal/apps/terraform_provider_test.go`) sends the provider's recorded bodies through the strict Render gate. The image service's step-2 update and the runtime-update test's repo-to-image step both answer 200 and apply. `rootDir: "api"` on an image service is refused and writes nothing. A repo service's own root directory, spelled as stored or as `./services/api/`, starts no build. GraphQL and MCP accept `""` and refuse `api`. With the no-op return removed, four of its five subtests fail.

**Live on dev-9** (bex-api built from main `47a81cb0d` plus this change, OpenFGA on, a Scale workspace's owner's API key as minted; checklist run H): `TestWebServiceResource_Image` passes all three steps, and both recorded `PATCH`es with `rootDir: ""` answer 200. The four service packages pass 16 of 27 tests, where run F passed 8. No request is refused for its `rootDir`. The three scaling tests now stop at w9/123, and the rest stop at recorded omissions and non-goals. The sweep found nothing left behind, the workspace read empty on every collection, and the key was revoked.
