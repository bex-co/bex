# A Contributor and a Viewer still see the workspace's agent model spend in USD

Why: w9/m620 made billing details Admin, Developer and Billing only (Render's "View billing details"), and the Billing page's agent model card is gated with them, but the agent environment shows the same month's agent model spend in dollars to every member.

- bex-api: `agentsessions.Service.Environment` (GraphQL `agentEnvironment`, `lego/backend/internal/agentsessions/environment.go:409`) authorizes `can_view`, and its spend position carries the month-to-date agent model spend and the cap.
- Dashboard: Workspace Settings → Agents → "Agent model spend" (`dashboard/src/features/agent-environment/components/spend-cap-section.tsx`) reads "$0.00 of $10.00 this month" for a Contributor and a Viewer (seen on dev-9 on 2026-11-24 as a Contributor of a disposable Scale workspace), and the session composer's spend banner (`features/agent-sessions/components/composer-spend-banner.tsx`) shows the same figures.
- Reference: agent surfaces follow Devin (ADR047); the spend figure is also a workspace billing figure. Decide which reference governs (Devin's usage visibility per role, or Render's billing row), then either gate the spend position on `can_view_billing` (and hide the figure with the role's reason) or record why it stays with `can_view`.
- Done when: a Contributor and a Viewer see no dollar figure of the workspace's agent model spend on Workspace Settings or in the composer, or ADR091 records why they do, with the reference product's behavior cited.

## Done (2026-11-24)

- **Reference.** Both products checked on 2026-11-24. Devin shows an organization's ACU consumption to its org admins ("Organization admins view Organization ACU consumption at Settings > Consumption Analytics"; "View Consumption" is a separate custom-role permission; the default Member covers using Devin "but not membership, organization settings, or other administrative configuration"), while "any user can see the ACU cost of a specific session from Session Insights" and a member blocked by a limit sees that it was exceeded (docs.devin.ai/admin/billing/enterprise, /enterprise/security-access/custom-roles, /enterprise/features/usage-policies). Render's "View billing details" is Admin, Developer and Billing (w9/m620). Both hide the workspace-wide spend from a default non-admin member. Render's row decides the roles, because bex's roles are Render's and the same spend is already on the Billing page behind `can_view_billing`. Recorded in [ADR091 D6](../../../docs/ADR091-agent-model-pricing.md#d6--what-the-customer-sees), ADR012's billing details table and ADR018's agent environment row.
- **bex-api.** `agentsessions.Service.spendFor` (`spend.go`) fills the spend figures, caps, trust tier, credit and unbilled spend only for a caller holding `can_view_billing` whose key grant (if a key) holds Workspaces Read, on `Environment` and `UpdateEnvironment`. Everyone else reads them `null` on REST `GET /v1/agent-environment`, GraphQL `agentEnvironment` and MCP `get_agent_environment`, and keeps `agentModelSpendCapReached` and `billingBalanceDue`, so the composer still refuses what the mint would refuse.
- **Dashboard.** Settings → Agents shows a Contributor and a Viewer "Your role can’t view billing details. Ask a workspace admin." in the spend summary's place, with an empty disabled cap field and blank tier and help lines; the card and route skeletons draw the same. The composer refuses at the cap with "Agent model spend limit reached" and no figure, gives no 80% warning, and drops the Billing link from the balance-due and payment-hold refusals for them.
- **Tests.** `TestEnvironmentSpendFiguresAreBillingDetails` (five roles on the service, REST, GraphQL and MCP) and the real-OpenFGA e2e `TestBillingDetailsPerRoleE2E`, extended with the agent environment for the five roles and their keys plus a Developer key narrowed to Agents Read. Both fail with `spendFor` reverted, and the e2e fails with its key-grant check removed. Dashboard: the spend section and its skeleton per role, `composerSpendGate`'s `reachedHidden`, and the composer's figure-free refusals; each fails with its fix reverted.
- **Live, dev-9** (bex-api rebuilt from this tree; a throwaway script outside the repo): in a Scale workspace (disposable), 90 of 90 checks passed. Admin, Developer, Billing and their All keys read the figures (Admin: `$0` of a `$10` T0 cap, plan `$2,000`) on REST, GraphQL and MCP. Contributor, Viewer and their keys read every figure `null`, and all ten read both verdicts. As the Contributor, `yarn dev` showed Settings → Agents with the role's reason, no dollar figure and an empty cap field at 1280 px and at 390 px with no horizontal overflow. dev-9 has no platform model route, so the composer's refusals are proven by the component tests. Both walk workspaces were deleted.
