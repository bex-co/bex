## Objective

Add `startTime`/`endTime` arguments to the GraphQL `logs` (and `logLabelValues`) fields. REST (`?startTime=…&endTime=…`, `lego/backend/internal/logs/rest.go:217`) and MCP (`mcp.go:55`) already accept an RFC3339 window; GraphQL's `logFilterArgs()` omits it — but the deploy detail page must scope its query to the deploy's `createdAt..finishedAt` window, and today it can't.

## Context

- `lego/backend/internal/logs/graphql.go` — `logFilterArgs()` (line 47) builds the shared arg set; `logQueryFromArgs()` (line 107) maps args → `LogQuery`. `LogQuery` already carries the window fields (REST fills them); only the GraphQL adapter is missing the plumbing.
- Parse/validation contract: malformed RFC3339 errors naming the field (mirror `rest.go`'s message and MCP's `core.Err("startTime: …")`), window capped by `BEX_MAX_QUERY_HOURS` in the shared verb — do not duplicate the cap in the adapter.
- Dashboard side of the plumbing: `dashboard/src/features/logs/api/logs.graphql` gains the two variables (consumed by t003; regenerating `src/graphql/definitions.ts` needs `CODEGEN_SESSION_TOKEN` — hand-extend the typed document if codegen is unavailable, matching how the file is maintained).

## Steps

1. Add `startTime`/`endTime` string args to `logFilterArgs()`; parse them in `logQueryFromArgs()` into the `LogQuery` window fields exactly as `rest.go` does (shared helper if one falls out naturally).
2. Extend `dashboard/src/features/logs/api/logs.graphql`'s `Logs` query with the two optional variables and pass-through.
3. `cd lego/backend && go test ./internal/logs/...`; dashboard `yarn typecheck`.
