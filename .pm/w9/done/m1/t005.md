## Objective

Teach `dashboard/scripts/local-bex.mjs` the new reads so the deploy detail page is fully exercisable under `yarn dev:local`: a `Deploy` operation (single deploy by id), `startTime`/`endTime` honoring on the `Logs` operation, and synthetic `type=build`/`type=predeploy` lines inside a seeded deploy's window.

## Context

- The stub already keeps per-service deploy events (`EVENTS_BY_SERVICE`) and mutates them on `TriggerDeploy`/`CancelDeploy`/`RollbackService`; it has no deploy-by-id read and its `Logs` handler ignores time bounds and serves only `app` logs.
- `TriggerDeploy` already simulates `update_in_progress → live` over 5s — the deploy page's poll-until-terminal loop should be visible offline.
- Keep the stub honest: unknown deployId → `null` (the 2026-07-09 phantom-service lesson recorded in the file).

## Steps

1. Track deploys (not just events) per service — reuse the objects `TriggerDeploy`/`RollbackService` build, plus one seeded finished deploy per seeded service whose window contains scripted build/predeploy/app lines.
2. Add a `Deploy` (single) resolver case; extend `Logs` to filter by `startTime`/`endTime` and to serve `type=build`/`type=predeploy` lines for a deploy window when asked.
3. Update the stub's header comment; click-verify the full flow: Manual Deploy → deploy page → logs stream in → status flips to live.
