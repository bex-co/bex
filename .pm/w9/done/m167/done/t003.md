## Objective

`bex edit ags-<id>` fetches the session through bex-api and hands bex desktop the session's SSH remote (`ssh://…/workspace`). It is the terminal equivalent of the dashboard's Open-in-Zed (ADR054).

## Context

- REST `GET /v1/agent-sessions/{id}` returns `sshAddress` (the View in `lego/backend/internal/agentsessions/models.go`). SSH into the sandbox needs `can_view_sensitive` (ADR054) and the user's registered SSH key.
- The CLI imports no sibling module. Hand-write the minimal response struct and pin it with a golden contract test (precedent: `lego/cli/sandbox_contract_test.go` and `testdata/`).
- The CLI's authenticated HTTP client comes from the upstream config (`internal/bridge`). Reuse it rather than minting tokens.

## Steps

1. Detect a single argument with the `ags-` prefix in `bex edit`.
2. GET the session with the active workspace header.
   - 404 and 403 surface the API's message.
   - An empty `sshAddress` gives "this session's sandbox is not running; send it a message to start one".
3. Build the same remote target the dashboard Open-in-Zed link uses (`ssh://<sshAddress>/workspace`) and exec it through t001.

## Files

- `lego/cli/internal/desktop/session.go`, `lego/cli/testdata/agent-session-ssh-contract.json`

## Acceptance criteria

- [x] Against an httptest server, a running session execs the editor with the exact `ssh://` argument. Closed, forbidden and missing sessions exit nonzero with the API's message.
- [x] The golden contract file mirrors the backend View field names it consumes.

## Out of scope

- Starting a sandbox from the CLI (`bex agent …`, an ADR092 follow-up).
