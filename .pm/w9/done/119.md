# Production holds 16 leaked `m35-*` API keys and 8 fixture workspaces from `verify-sandbox-isolation-live.sh` runs on 2026-11-15

Why: four runs of the sandbox isolation matrix left live Hydra clients, Admin and Developer bindings and their workspaces behind; their secrets are gone with the runners, but they are still credentials and the next leak may not be harmless.

- **Found by** w9/m481 t001/t007 (read-only, 2026-11-18): production Hydra lists 16 bex API keys named `m35-owner-a-*`, `m35-member-b-*`, `m35-admin-a-*`, `m35-owner-b-*`, all created 2026-11-15, none with a creator stamp; `tenant_members` holds them as 4 admin and 12 developer machine rows in 8 workspaces, plus 8 `m35-*` bootstrap clients as Admin rows. The script's `cleanup` trap (revoke through the API, delete the workspaces, delete the Hydra clients) did not run or did not finish for those runs. Since w9/m481 the keys cannot act above a Developer (ADR117), but they still authenticate.
- **Paths:** `scripts/verify-sandbox-isolation-live.sh` (`create_bound_principal`, `cleanup`), `.github/workflows/isolation-matrix.yml`.
- **Done when:** the 16 keys, the 8 bootstrap clients, their bindings and tuples, and the 8 fixture workspaces are gone from production (checked by a Hydra list and a `tenant_members` count of `m35-%` subjects that answer zero); the script removes what an earlier interrupted run left (e.g. a sweep of `m35-*` clients older than an hour at start) so a killed runner cannot leak again; ADR117's residual is marked closed.
- Filed by w9/m481 t007.

**Done 2026-11-18.**

- **Cause.** The four leaking runs were `sandbox-measure.yml` 43690660848, 43691298476, 43693931198 and 43696023922. Each failed 17–28 minutes after minting the bootstrap token, and Hydra's access tokens live 15 minutes. The trap's API calls were refused, and `graphql_call`'s `fail` exited the trap before its Hydra and OpenFGA deletes and its port-forward kill. The runner's "Terminate orphan process … (kubectl)" lines show the forwards were never killed.
- **Removal.** The targets were listed, and each was checked against the `m35-*` pattern and the 2026-11-15 window before anything was removed. No fixture workspace held a human member or an App.
  - Each leaked bootstrap was re-keyed and deleted its own two workspaces through `deleteWorkspace`, so the sandbox, billing and secret purgers ran.
  - The 20 Hydra clients (16 keys, 4 bootstraps) were deleted.
  - The 20 tuples `deleteWorkspace` left were deleted: the keys' 16 and 4 on `workspace:default`.
  - Hydra lists 0 `m35-*` clients (40 others, unchanged). `tenant_members` holds 0 `m35-%` subjects and `tenants` 0 `m35-%` rows. OpenFGA holds 0 tuples for the 20 subjects, and all 16 fixture namespaces were pruned.
  - The note's "8 bootstrap clients" were 4 clients holding 8 Admin rows.
- **Prevention.** `scripts/verify-sandbox-isolation-live.sh` changed in three ways:
  - Its cleanup mints a fresh bootstrap token and never exits mid-trap.
  - It removes every tuple naming a fixture principal.
  - Before provisioning, it sweeps `m35-*` clients and `m35-[ab]-` workspaces older than six hours.
  - Run against the pre-removal snapshot of production's 60 clients, the sweep's filter selected exactly the 20 fixtures.
  - `scripts/verify-sandbox-isolation-live.test.sh` covers this in CI. Against the old script it fails 14 checks.
  - The isolation matrix's leftover audit now reads the fixture rows, not only namespace names.
- **Records.** ADR117's residual is marked closed. The product gap it surfaced, a deleted workspace's API keys staying live, is w9/120.
