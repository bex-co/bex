## Objective

Replace the auth middleware's and GraphQL server's hand-rolled error writers with `core.WriteErr` so the highest-traffic error paths (every unauthenticated request, auth-upstream outage, malformed GraphQL body) emit Render-shaped JSON.

## Context

- `lego/backend/internal/api/auth.go:140` — `http.Error(w, `{"error":"auth upstream unavailable"}`, 503)`: JSON-in-a-text/plain wrapper, no `message`.
- `lego/backend/internal/api/auth.go:151` — onboarding 503, same pattern.
- `lego/backend/internal/api/auth.go:303` — `unauthorized()`: fires on **every** unauthenticated request.
- `lego/backend/internal/api/server.go:740` — GraphQL body-decode 400 via `http.Error`.
- The correct dialect: `core.WriteErr` (`lego/backend/internal/core/http.go:73-79`) writes `{"id","error","message"}` with `Content-Type: application/json`.
- `http.Error` always sets `Content-Type: text/plain; charset=utf-8` — the body being JSON-shaped doesn't help clients that check the header or key on `message`.

## Steps

1. Swap each of the four sites to `core.WriteErr` (or a thin local helper if import cycles bite — check whether `internal/api` already imports `internal/core`).
2. Preserve status codes and message text exactly; only the envelope/content type changes.
3. `cd lego/backend && go build ./... && go test ./...`.

## Acceptance criteria

- [ ] `curl -s -o /dev/null -w '%{content_type}'` on an unauthenticated `/v1/services` request returns `application/json`.
- [ ] The 401 body contains a `message` key.
- [ ] The GraphQL decode 400 and both 503 paths emit the `{"id","error","message"}` shape.
