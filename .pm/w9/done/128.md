# A Ruby service whose Gemfile.lock names a newer Bundler than its Ruby ships builds, then fails `bundle exec` at start

Why: a Rails app on Ruby 3.3 whose lockfile says `BUNDLED WITH 2.6.9` deploys on bex with a green build and then cannot start, while the same app starts on Render.

- **Found by:** the w9/m494 BuildKit drill, 2026-11-19, on the generated native Ruby recipe with `FROM ruby:3.3-bookworm@sha256:ae098d…` (Ruby 3.3.13, Bundler 2.5.22) and a Gemfile (`bcrypt`, `puma`, `rack`) locked by Bundler 2.6.9.
- **What happens:** `bundle install` prints `Bundler 2.5.22 is running, but your lockfile was generated with 2.6.9. Installing Bundler 2.6.9 and restarting using that version.` and the build succeeds. Bundler puts 2.6.9 under `BUNDLE_PATH`'s own layout, `/opt/render/project/.gems/ruby/3.3.0/gems/bundler-2.6.9`, and writes a `bundle` binstub into `BUNDLE_BIN` (`/opt/render/project/.gems/bin`, first on `PATH`). At runtime, `bundle exec ruby app.rb` runs that binstub, which activates `bundler (~> 2.6)` through RubyGems, and RubyGems looks only in `GEM_PATH=/opt/render/project/.gems:/usr/local/lib/ruby/gems/3.3.0`, not in `.gems/ruby/3.3.0`: `Could not find 'bundler' (~> 2.6) - did find: [bundler-2.5.22]`, exit 42. The same happens for any Ruby line whose bundled Bundler is older than the lock's.
- **Where:** `nativeBuildDefaults` (`lego/operator/internal/build/native.go`, the Ruby case: `BUNDLE_PATH`, `BUNDLE_BIN`, `GEM_PATH`, `GEM_HOME`). w9/m494 keeps `.gems/bin` out of the dependency cache for this reason, so the cache does not carry the binstub into the next build (`nativeDependencyDirs`, `depscache.go`).
- **Done when:** that fixture builds and its `bundle exec ruby app.rb` and `bundle exec puma` start, both cold and after a cached rebuild, and the build log says which Bundler it used, as Render's does. First check how Render resolves it (its build log names the Bundler it installs) and match that: installing the lock's `BUNDLED WITH` Bundler into a directory `GEM_PATH` reads before the build command runs is one way. Add a test for the fixture's shape.

**DONE 2026-11-20** by `/loopx w9`. Render runs the lockfile's Bundler from `GEM_PATH` (published tracebacks run `/opt/render/project/.gems/gems/bundler-<BUNDLED WITH>`: 2.4.21 and 2.5.5 on Ruby 3.2.2, 2.5.11 on 3.3.3, 2.6.7 on 3.4.3), and its log names no Bundler of its own beyond Bundler's lines. bex now does the same before the build command: the env loader's last step (`nativeLockedBundler`, `lego/operator/internal/build/nativebundler.go`) finds the lockfile as Bundler does, and unless RubyGems already has its `BUNDLED WITH` version, installs it into the first `GEM_PATH` directory (`/opt/render/project/.gems` on a Ruby build, RubyGems' own on a Gemfile static site's Ruby). The log says `==> Using Bundler 2.6.9 (from Gemfile.lock)` or `==> Installing Bundler 2.6.9 (from Gemfile.lock)`; a failed install prints RubyGems' reason and the build goes on as before. Ruby's dependency directories gain `.gems/gems`, `.gems/specifications` and `.gems/extensions`, so a rebuild finds the Bundler; `.gems/bin` stays out. [ADR060 D3 w9/128 amendment](../../../docs/ADR060-build-worker-reliability-and-performance.md#d3-amendment-w9128--the-bundler-a-lockfile-names).

Drilled on BuildKit `v0.30.0` with this item's fixture (bcrypt, puma, rack, Bundler 2.6.9, Ruby 3.3) on the resolved production recipe (`linux/amd64`, the common base), under `render-v1`. Before the change the cold image's `bundle exec ruby app.rb` and `bundle exec puma --version` exited 42. After it, the cold build printed `Installing Bundler 2.6.9` and no restart line, and the rebuild after a source-only commit printed `Using Bundler 2.6.9` and installed nothing (1.3 s). Both images start `app.rb` on Bundler 2.6.9 and serve through `bundle exec puma`. The 3.4 line (its own 2.6.9), 4.0 (Bundler 4.0.20) and 3.0 with a 2.4.22 lock start too, and a Gemfile static site on 3.3 now builds where it failed with exit 42. `nativebundler_test.go` covers the step's rules and the recipe; `TestNativeRubyImageStartsOnTheLockedBundler` is the opt-in BuildKit gate for the fixture, cold and rebuilt. A limit is recorded in the ADR: a lockfile whose Bundler needs a newer Ruby (2.6.9 on Ruby 3.0) still cannot start, now with the reason in the build log. Not yet observed on a production build log; it shows once the pin carries this change.
