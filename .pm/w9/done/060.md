# name-conflict-e2e.sh pins Hydra v2.2.0, which cannot pass auth-bootstrap-client.sh's lifespan assert

Why: the bootstrap script asserts `device_authorization_grant_access_token_lifespan` round-trips on the Render CLI client, and empirical probing (w5/m86 t007, 2026-09-07) shows neither Hydra v2.2.0 nor v2.3.0 stores that client field (only `refresh_token_grant_access_token_lifespan`); v26.2.0 round-trips both — so `scripts/name-conflict-e2e.sh`'s bootstrap step (Hydra pin at its line ~112) fails today and needs the pin bumped to v26.x, then a full run of that script to confirm nothing else in it depends on v2.x behavior. Surfaced while building `scripts/auth-obs-e2e.sh`, which pins v26.2.0 for this reason; `auth-oauth21-e2e.sh` (v2.2.0) is unaffected because it never runs the bootstrap script's lifespan assert.

Cleanup confirmed after the run: no `app.app.bex.co` in any namespace, no
`beancount-*` Ingress, no `bex-m19-*` containers, and all five ports
(24491/24492/25491/18291/18293) released.

**Clearing the cluster blocker.** The app cluster was never broken — CAPI
reported `bex` Provisioned with all three machines Running. What was broken was
the *published* kubeconfig: it had been rewritten to the in-network
`172.22.0.3:6443`. Republishing it with `mock-cluster.sh`'s own validated,
atomic procedure (`clusterctl get kubeconfig bex` → rewrite the server to
`bex-lb`'s published port → reject insecure TLS → prove `/readyz` → atomic `mv`)
restored host access with no reprovision and no risk to another session. The App
CRD was already installed.

**Four real drifts the run then surfaced** — the pin bump alone was never enough,
which is exactly why the note refused to accept startup as evidence:

1. **bex-api would not start.** With the control-plane store on and no OpenFGA it
   now refuses (authorization would be fail-open). The harness deliberately runs
   without OpenFGA and seeds `tenant_members` directly, so it takes the
   documented local-dev override `BEX_ALLOW_INSECURE_AUTHZ=1` — the same one
   `scripts/webhooks-verify.sh:291` uses.
2. **Create bodies were not Render-shaped.** `image.ownerId` is required by the
   schema bex validates against (the official CLI always serializes it); omitting
   it 400s at `/image/ownerId` long before any name-conflict assertion. The
   fixture now sends `"ownerId":""`, matching the pinned-CLI fixtures in
   `lego/backend/internal/apps/cli_compat_test.go`.
3. **App CRs no longer live in `default`.** ADR043 per-tenant namespace isolation
   puts a workspace's Apps and Ingresses in the workspace's own namespace (the
   workspace id verbatim). Every CR/Ingress read and the cleanup list are now
   scoped to the owning tenant (`CREATED_CRS` entries carry `<ns>/<name>`).
4. **The MCP tool's schema gained required fields.** `create_web_service` now
   requires `runtime`/`buildCommand`/`startCommand` (non-pointer, no omitempty),
   so the leg failed argument validation instead of exercising the duplicate
   check. The image shape is `"runtime":"docker"` with empty commands.

Plus one genuine environment prerequisite: **Traefik's `Middleware` CRD**.
`reconcileIngressWithMiddlewares` upserts the websocket egress-meter middleware
for every App with a host, so without that CRD every App fails with
`no matches for kind "Middleware"` and leg [5] can never pass.
`scripts/mock-cluster.sh` does not install Traefik, so the harness now installs
**only the CRDs** (chart 41.0.0, the version `scripts/verify-egress-meter.sh`
pins) when the kind is absent — no proxy, since this scenario asserts Ingress
objects, not served traffic.

Two diagnosability repairs came out of the same session, because each of the
failures above initially reported nothing usable: `wait_http` takes an optional
log to tail on timeout, and an Ingress-reconcile timeout dumps the operator log.
Both logs previously died with `$bindir` in the EXIT trap.
