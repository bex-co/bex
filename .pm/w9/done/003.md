# Deploy-page log-viewer polish: `?r=` URL time-range param, maximize/options

Render's deploy page log viewer carries a `?r=<range>` URL param (so a shared link reopens the same time window) and maximize/options affordances. bex's deploy detail page (w9/m1) ships without either — the log window is implicit (the deploy's own createdAt..finishedAt), not a URL-addressable range, and there's no maximize/options menu. Flagged as an accepted gap during w9/m1's Render parity check (t006).

- `?r=` is lower value for bex: the deploy page's window IS the deploy's own lifetime, not an arbitrary user-picked range like the general Logs tab would need — there's nothing for a URL param to override yet.
- Maximize/options (font size, wrap, timestamps toggle) are pure UI polish — pick up alongside any future general Logs-tab viewer polish rather than one-off for this page.

**Done (2026-07-14):** `?r=` (15m/1h/6h/24h/7d) validated via `validateSearch`, owned by the URL (replace-navigation), overriding the deploy window with a relative [now-r, now) window; options menu (time range + wrap + timestamps toggles, new `LogLineList` props) and a maximize/full-screen toggle on the deploy log panel.
