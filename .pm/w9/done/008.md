# Unify the `/v1/oauth/revoke` failure dialect

The new revoke handler (`lego/backend/internal/cliauth/service.go`, `RevokeHandler`) mixes two error dialects on different failure branches of the same endpoint: Render's `{"message"}` shape via `core.WriteErr` (~lines 86, 108, 112, 116) and the OAuth `{"error":"temporarily_unavailable"}` shape via `writeOAuthError` (~lines 93, 103). A client parsing logout failures sees two different bodies depending on which branch fails.

`w9/m38` unified the REST error dialect but closed before this handler was swept (cliauth shipped the same day, 2026-07-15). Decide per-branch which contract applies — `/v1/oauth/revoke` sits between RFC 7009 revocation semantics and bex's Render-shaped REST — unify accordingly, and annotate any deliberate survivor per m38's convention. The RFC 8628 device endpoints' OAuth-shaped errors (`deviceGrant`/`deviceToken`/`refreshToken`, `writeOAuthError` at ~135–210) are **correct** — the CLI expects OAuth-shaped bodies there; leave them.

~30m. Source: `/pm-brainstorm` round 15, 2026-07-15 — consistency-mine over 57f146d2..441d6040; was proposed as an add-task to m38, which a concurrent session closed mid-round.

## Resolved 2026-07-15

`/v1/oauth/revoke` is a Render-shaped REST endpoint (Render's logout), not an OAuth
token endpoint — 4 of its 6 failure branches already spoke Render's
`{error,message,id}` dialect via `core.WriteErr`. Unified the two remaining
`temporarily_unavailable` 503 branches (adminURL unwired / Hydra unreachable) to
the same dialect behind a new `core.ErrLogoutUnavailable` sentinel (503,
`id:"unavailable"`), registered in `core.WriteErr`'s status switch.

The RFC 8628 device endpoints (`deviceGrant`/`deviceToken`/`refreshToken`/`proxyForm`)
keep their OAuth `{"error"}` bodies — annotated `writeOAuthError` as the deliberate
survivor per m38's convention (the unmodified CLI parses those as OAuth token
responses). Test `TestLogoutFailsClosed/admin unavailable` now asserts the
revoke 503 body is Render-shaped. `go build`, full `go test ./...`, and
`make lint-backend` (0 issues) green.
