## Objective

Move every service setting t001 classified to `can_create`, so a Contributor's write is refused with 403 on REST, GraphQL and MCP before anything is written.

## Context

- `lego/backend/internal/apps/settings.go` (`canOperate` → `canCreate` on the setting rows, including the three notification-override rows).
- `lego/backend/internal/apps/service.go`: `Scale`, `SetAutoscaling`, `DeleteAutoscaling`, `SetCronJob` (drop the schedule-only `can_operate` branch), the maintenance-mode setters; `lego/backend/internal/apps/edge_cache.go` `SetCacheProfile`.
- Existing pins that encode the old line: `lego/backend/internal/api/roleladder_test.go`, `lego/backend/internal/api/m68_executable_selection_test.go`.

## Steps

1. Change each relation; keep `Restart`, `Suspend`/`Resume`, `TriggerCronRun`, `CancelCronRun`/`CancelCurrentCronRun` and `PurgeCache` on `can_operate`.
2. Update the role-ladder pins to the new line.
3. Run `cd lego/backend && go test ./...`.

## Files

- `lego/backend/internal/apps/settings.go`, `lego/backend/internal/apps/service.go`, `lego/backend/internal/apps/edge_cache.go`, the role-ladder tests

- [ ] A Contributor's `PATCH /v1/services/{id}` naming any moved field, `POST …/scale`, `PUT`/`DELETE …/autoscaling` and a cron schedule change answer 403 and change nothing; a Developer's succeed.
