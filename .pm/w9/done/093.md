# A Blueprint that regroups a service into another project or environment records no `service_moved`

Why: since w9/092 a Blueprint sync records every setting change the REST setters record, except placement. A `render.yaml` that moves an existing service into another project or environment changes its grouping, while the REST/GraphQL move records `service_moved` (Render's event). The feed and webhooks miss the move.

- Record `service_moved` with the same details as the REST move (from/to environment), once the move lands, using w9/092's actor rule (the member, the approver, or no caller for auto-sync).
- Cover it with a sync test that regroups a service, and one that keeps the grouping (no event).

## Done (2026-11-12)

A Blueprint sync, approval or deploy that regroups an existing service records `service_moved` with the REST move's details, exactly once: `SetAppEnvironment` writes only on a change and returns the move. Tests cover moves between environments and projects, a move out of every grouping, a move back, a kept grouping, retries with and without a resync, a store-less service, the actors, the store setter and a real-Postgres feed. Follow-up: w9/094.
