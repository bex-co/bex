## Objective

Stand up a reproducible harness that runs Render's official CLI against bex-api instead of api.render.com: install the CLI, determine how its API base URL can be overridden (env var, config file, or build-time — read the `render-oss/cli` source; do NOT fork/patch the CLI itself beyond a documented override), and authenticate with a bex-minted API key.

## Context

- The CLI is open source: `github.com/render-oss/cli` (Go). Docs: https://render.com/docs/cli.
- `render login` uses a browser dance against Render's dashboard — expected to be inapplicable; the CLI also honors an API-key env var (`RENDER_API_KEY`) for non-interactive use. bex mints Render-shaped API keys (`docs/ADR012-auth.md`, `internal/apikeys`) validated via Hydra introspection.
- bex-api serves the Render-compatible REST surface on `:8090` (`BEX_API_ADDR`); the mock cluster (`bash scripts/mock-cluster.sh`) or `env/dev-alpha/` provides a live instance.
- If the base URL turns out to be hardcoded with no override, document the least-invasive workaround (e.g. `HOSTALIASES`/hosts-file redirect + TLS consideration, or a local reverse proxy) — the point is a repeatable harness, and its shape is itself a checklist finding.

## Steps

1. Install the CLI (brew/`go install`) and pin the version used in the harness notes.
2. Read `render-oss/cli`'s config/client setup to find the host override; verify it by pointing the CLI at a locally running bex-api.
3. Mint a bex API key (dashboard or REST) and confirm an authenticated CLI call reaches bex (e.g. workspace/service list returning bex data).
4. Record the harness as a script (`scripts/cli-compat.sh` or similar) or exact steps in the checklist's header.
