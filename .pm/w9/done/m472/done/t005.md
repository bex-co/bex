## Objective

Prove the definition of done with the real client: Terraform and Render's provider against production bex, as the QA user, once the production pin carries this milestone.

## Context

- w7/m426 t006 ran only a read-only `terraform plan` with `render-oss/render` v1.9.1 (`RENDER_HOST`, `RENDER_API_KEY`, `RENDER_OWNER_ID`).
- QA credentials: `QA_EMAIL` / `QA_PASSWORD` (`.env` / `muse.env`); mint a bex API key for the run and revoke it after.

## Steps

1. Pin Terraform and `render-oss/render` (record both versions).
2. Apply three minimal configurations: a `render_web_service` from a public repo with no `previews` block, a Docker `render_cron_job` with no registry credential, a `render_webhook` with no `event_filter` (the workspace must be on a plan that allows webhooks).
3. Run `terraform plan` again: it must show no changes.
4. `terraform destroy`, and confirm the resources are gone.
5. Record versions, commands and results (no raw logs in git).

## Acceptance criteria

- [x] All three applies succeed, the second plan is empty, and destroy leaves nothing behind.

## Out of scope

- The full provider acceptance suite (w9/m474).

  - `render_cron_job` `qa-20261119-m472-cron`, `runtime_source.docker` from `render-examples/bun-docker`, no registry credential;

**Finding (filed as w9/129).** An explicit `previews = { generation = "off" }` is how Render's own `render_background_worker` example writes it. Applied the same way, it created `srv-dbvdb2nh83kc738vm2n0` and then aborted with _Provider produced inconsistent result after apply: .previews.generation: was cty.StringVal("off"), but now null_. bex's service read has no `serviceDetails.previews`, where Render reads `{"generation":"off"}`. That configuration is outside this milestone's definition of done.

The repro used its own key, `qa-20261119-m472-tf2`, and its own session. The tainted service was destroyed (`GET` 404), the key revoked and the session logged out.
