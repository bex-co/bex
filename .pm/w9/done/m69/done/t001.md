## Objective

Give the top-level list routes a content-shaped skeleton (table/card placeholders) during their pending phase, instead of the bare centered spinner they inherit from `RoutePending`.

## Context

- Post-persistent-shell (`da6b55b2`), a pending top-level route paints `RoutePending` (a centered `Loader2` spinner) inside the shell's content region.
- Target routes: `agents.tsx`, `blueprints.tsx`, `blueprints.new.tsx`, `env-groups.tsx`, `webhooks.tsx`, `webhooks_.new.tsx`, `notifications.tsx`, `usage.tsx`, `static.index.tsx`, `static.new.tsx`.
- Reuse existing skeletons where present (the overview/table/card skeletons already used for in-page loading, e.g. `ResourceTable`'s `loading` state) rather than inventing new ones.

## Steps

1. For each list route, supply a `pendingComponent` (or in-content skeleton) that renders the page's content shape with placeholders.
2. Keep it inside the persistent shell (content region only) — never a full-viewport element.
3. Match the real content's layout so the skeleton→data swap doesn't jump.

## Files

- The ~8 list route modules under `dashboard/src/routes/`
- reuse: existing skeleton components (`ResourceTable` loading, card skeletons)

## Acceptance criteria

- [ ] Each target route shows a content skeleton (not a centered spinner) while pending.
- [ ] The skeleton renders within the shell; sidebar/header stay put.
- [ ] No layout jump on skeleton→data.

## Out of scope

- Detail routes (they already use component-as-pending skeletons).
- The pending-config audit (t002).
