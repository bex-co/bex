# After `DELETE …/autoscaling`, a service read still carries `serviceDetails.autoscaling`, where Render omits it, so Terraform cannot remove autoscaling

Why: Render's Terraform provider reads `serviceDetails.autoscaling` into its optional `autoscaling` attribute. bex keeps the turned-off policy in the service read, so a configuration that drops the block reads it back non-null, and Terraform aborts with "Provider produced inconsistent result after apply".

- **Found by:** w9/111's recheck on dev-9, 2026-11-18 ([checklist](../../../docs/terraform-compatibility-checklist.md), class 11). This is where the three scaling tests stop next once w9/113 is fixed: `TestWebServiceResource_Autoscaling` (step 2 of 2), `TestBackgroundWorkerScalingResource` and `TestPrivateServiceScalingResource` (step 2 of 4). Each step sends `DELETE …/autoscaling` before the `PATCH` that w9/113 refuses today.
- **Render:** `webservice/resource/testdata/web_service_autoscaling_cassette.yaml`, and the worker and private service `scaling_cassette.yaml`. After `DELETE /v1/services/{id}/autoscaling` (204), no service read has an `autoscaling` key in `serviceDetails`: not the `PATCH` response, and not any later `GET`. The test then checks `TestCheckNoResourceAttr(resourceName, "autoscaling")`. Render's disable event still keeps the config with `enabled: false` (w4/597's evidence), and Render has no `GET …/autoscaling`.
- **bex:** `lego/backend/internal/apps/render.go` `renderServiceDetails` emits `serviceDetails.autoscaling` whenever the App has `spec.autoscaling`. Since w4/597, a disable keeps those settings with `enabled: false`. On dev-9, `DELETE …/autoscaling` answered 204, then `GET /v1/services/{id}` answered `serviceDetails.autoscaling: {"enabled":false,"min":2,"max":3,…}`.
- **Provider:** `internal/provider/common/models.go` `AutoscalingFromClient` returns a model for any non-nil `serviceDetails.autoscaling`. The `autoscaling` attribute is optional and not computed.
- **Done when:**
  - While autoscaling is off, `serviceDetails.autoscaling` is absent from every Render-shaped service read (REST get, list and `PATCH` responses, MCP `get_service`).
  - The kept settings still read on `GET …/autoscaling`, GraphQL and the Scaling page (w4/597).
  - ADR018's w4/596 and w4/597 sentences say so, and a test covers it.
  - After w9/113, the three scaling tests get past their remove-autoscaling step.

## Resolution

**DONE 2026-11-19.** `renderServiceDetails` (`lego/backend/internal/apps/render.go`) emits `serviceDetails.autoscaling` only while autoscaling is on, so the REST get, list, create and `PATCH` answers and MCP `get_service` omit it after any disable: `DELETE …/autoscaling`, `PUT` with `enabled: false`, GraphQL `disableAutoscaling`, MCP `disable_autoscaling`. w4/597's behavior is unchanged: a disable keeps the settings with `enabled: false`, and `GET …/autoscaling`, GraphQL, MCP `get_autoscaling` and the Scaling page (which reads GraphQL) still read them. The top-level bex-dialect `service.autoscaling` extension also keeps reading them. Turning autoscaling back on brings the key back. ADR018's w4/596 and w4/597 sentences now say so, and its autoscaling row records that Render's pinned OpenAPI has `PUT` and `DELETE` only, which makes bex's `GET …/autoscaling` an extension.

`TestTurnedOffAutoscalingLeavesTheServiceRead` (`internal/apps/terraform_provider_test.go`) creates the provider's recorded autoscaled worker through the strict Render gate and turns autoscaling off each of those four ways. It then sends the provider's recorded post-DELETE `PATCH` and checks that the `PATCH` answer, REST get, list and MCP `get_service` carry no key, that the kept settings read on `GET …/autoscaling`, GraphQL and MCP `get_autoscaling`, and that a re-enable brings the key back. With the `Enabled` check removed, all four subtests fail.

**Live on dev-9** (run J in the [checklist](../../../docs/terraform-compatibility-checklist.md): bex-api built from main `0b7e42736` plus this change, OpenFGA enforced, a Scale workspace's owner's API key used as minted). `TestBackgroundWorkerScalingResource` and `TestPrivateServiceScalingResource` pass all four steps, and `TestWebServiceResource_Autoscaling` passes both of its steps. None of the 12, 12 and 2 service reads recorded after the DELETE carries the key, and the same holds for Render's 11, 11 and 2. A hand probe of a web service on the same stack gave the same reads: after the DELETE (204), GET, list and `PATCH` had no key, `GET …/autoscaling` read `{enabled: false, min: 2, max: 3, …}`, and GraphQL read the same range turned off. After the probe, a `PUT` turned it back on and `serviceDetails.autoscaling` read again. The sweep found nothing left behind, and the workspace read empty on every collection. The key was revoked (then 401) and the session logged out. With run H's results for the other tests, the four service packages pass 19 of 27, and the other eight stop at recorded omissions and non-goals.
