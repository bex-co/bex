# Every Key Value proxy roll refuses new internal connections for about a second

Why: a client that connects while a store's `kv-internal-proxy` rolls (enabling internal authentication, a plan change, a credential rotation, an override bump) gets `Connection refused` instead of a connection, although the Deployment surges and the old pod drains.

- **Found by:** w9/m521 t001's dev-9 check, 2026-11-19, on the shared mock cluster with the operator built from the tree. A loop in a same-workspace pod ran `valkey-cli -h <id> -p 6379 PING` every 200 ms while `POST /v1/key-value/<id>/internal-auth` rolled the store's proxy. 29 `PONG`, then 3 `Could not connect to Valkey at <id>:6379: Connection refused` within about 0.6 s, then `NOAUTH` from the new client-mode proxy. The Valkey pod did not restart.
- **Cause, likely:** the proxy pod stops accepting on `SIGTERM` (w6/m512's drain) while its endpoint is still in the dataplane's rules for a moment. w6/m515 found the same on the SNI DaemonSets and gave each old pod a 5 s `preStop` pause before `SIGTERM` ([w6/m515](../../w6/done/m515/README.md)). The proxy Deployment (`reconcileKeyValueInternalProxy`, `lego/operator/internal/controller/keyvalue_internal_proxy.go`) has no `preStop`.
- **Careful:** adding a `preStop` changes the proxy's pod template, so it must arrive with the store's own next roll or a reviewed override bump (`kvInternalProxyRollRevision`, w6/m517), never by itself on an operator deploy.
- **Done when:** the same loop during a proxy roll reads no `Connection refused`, the grace period covers the pause plus the drain, and `TestKeyValueInternalProxyRenderingIsPinned` records the change.

## Park record (2026-11-21, `/loopx w9`)

- **Verdict: work, then parked for the production check.** The premise held on `827263fca`: the proxy container (`reconcileKeyValueInternalProxy`, `keyvalue_internal_proxy.go`) had no `preStop`, so a deleted pod closed its listeners on `SIGTERM` while its endpoint was still in the node's rules. The SNI DaemonSets already pause 5 s (`config/kv-sni-proxy/daemonset.yaml`, w6/m515).
- **Shipped in `8ef3a2951`.** The proxy container sleeps 5 s in `preStop` (`kvInternalProxyPauseSeconds`) and the grace period is 40 s (pause + 30 s drain + 5 s). `TestKeyValueInternalProxyDrainsWithinItsGracePeriod` checks the sleep and that the grace period outlasts the pause and the drain. `TestKeyValueInternalProxyRenderingIsPinned` records the four new template pins; the roll inputs digest is unchanged. Without the pause both tests fail and the old pins come back exactly. The hold envtest drops the pause from its older rendering, so a running proxy without it stays held through operator deploys and takes it with the store's own change. `make test` and `make lint` passed with a fail-fast `docker` shim on `PATH` (Docker Desktop on the dev host has been hung since about 2026-11-20 20:15 PST, so no local cluster or dev-9 roll was possible).
- **No override bump** (`kvInternalProxyRollRevision` stays 1). The pause is neither a security fix nor needed by a held template, so, as **Careful** asks, it reaches each store only with its own next roll. That first roll can still refuse for a moment, because its old pod was written without the pause. ADR021 § 10 and `lego/operator/AGENTS.md` say so.
- **What the production check does** once the pin carries `8ef3a2951`, as the QA user (`bash scripts/qa-login.sh`) in `bex-canary`:
  1. Check that the shipping deploy rolled no existing proxy: with `bash scripts/fetch-app-kubeconfig.sh <path outside the repo>`, each `*-internal` Deployment in the tenant namespaces keeps its generation and ReplicaSet across the deploy.
  2. Create a free Key Value, so its proxy carries the pause from birth. Its `<id>-internal` Deployment must read `preStop.sleep.seconds: 5` and `terminationGracePeriodSeconds: 40`.
  3. In the same workspace, run a background worker from a Valkey image whose start command loops `valkey-cli -h <id> -p 6379 PING` every 200 ms with a timestamp. Then `POST /v1/key-value/<id>/internal-auth`. Across the roll its logs must read `PONG`, then `NOAUTH`, and no `Connection refused`.
  4. Delete the worker and the Key Value, check each by-id `GET` answers 404, revoke any key you minted, log the QA session out, and close this note.
