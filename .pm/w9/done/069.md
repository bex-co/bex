# 069 — A prebuilt-image service cannot be cloned: bex refuses the `branch` it just emitted

Why: `services create --from <image service>` is impossible, for the same reason
`068` made every free web service uncloneable — bex publishing a value its own
write side rejects.

Found 2026-09-21 by `/loopx w9` while live-verifying `068`'s fix on dev-9: with
the maintenanceMode blocker cleared, the clone of an image-backed service moved
on to a second refusal.

```text
$ bex services create --from srv-… --name …-clone --region frankfurt --confirm
Error: received response code 400: bad request: prebuilt image services cannot
declare branch; remove it or deploy from repo instead
```

## The contradiction

`GET /v1/services/<prebuilt-image service>` (dev-9, created with
`--runtime image --image docker.io/library/nginx:alpine`, no repo):

```text
branch    : 'main'
repo      : None
imagePath : 'docker.io/library/nginx:alpine'
runtime   : image
```

The `branch` is the CRD's default, meaningless without a repo — and echoing it
back, which is exactly what the pinned client's clone does, is refused by the
deliberate shared `prebuiltImageSourceFields` policy
(`internal/apps/blueprint_compiler.go:279-288`, message at `:294`).

## Which side was wrong

The **read**. The create-side refusal is correct and intentional: the App
controller skips all build and git-push behavior for a prebuilt-image service,
so retaining source fields would make an apply a silent no-op. And
`AppView.Branch` already documents the contract the read was breaking —
"Repo/Branch are the build-from-git source, empty for an image-backed App"
(`internal/apps/render.go:131-133`).

## Fix (done)

`internal/apps/service.go` — the view now reports the branch through
`imageBackedBranch(a)`, which returns none when the App has an image and no
repo. A repo-backed service is untouched.

**Live on dev-9:** the same clone now succeeds, `branch: None`, image preserved.
**Guard:** `TestImageBackedServiceReadsNoBranch` (image-backed reads no branch;
repo-backed still reads `release`), mutation-checked — restoring `a.Spec.Branch`
fails it. Full backend suite + `make lint-backend` green.

## Note for the next reader

This is the second instance of one class in a single sweep (`068` was the
first). The general guard added with `068`
(`TestFreeWebServiceReadShapeIsReSendableAsCreate`) echoes a read's
`serviceDetails` back as a create; it did **not** catch this one because
`branch` is a **top-level** service field, not part of `serviceDetails`.
Extending that guard to the whole read object — top-level fields included — is
the obvious next hardening step and is not done here.
