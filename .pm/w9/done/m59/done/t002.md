## Objective

Exercise the imported command against the existing Bex Render-compatible device-flow adapter and prove interactive credentials stay exclusively in the Bex config directory through login, automatic refresh, and logout revocation.

## Context

- `lego/backend/internal/cliauth` already adapts the unmodified Render CLI's device-grant, device-token, refresh, and authenticated revoke routes to Hydra.
- The browser verification surface is `dashboard`'s existing `/auth/device` flow; the first-party dashboard remains Kratos-session based.
- Bex machine API keys are Hydra client-credentials pairs; a raw client secret must never be put into `cli.yaml` or treated as a bearer token.

## Steps

1. Run the new binary through the existing device-login harness against a Bex environment.
2. Assert the generated YAML host, access expiry, and refresh token are Bex-only and the file permissions are safe.
3. Force/observe refresh rotation, then logout and verify the revoked credential is rejected.
4. Verify a pre-existing `~/.render/cli.yaml` is neither read nor mutated.

## Files

- `scripts/render-cli-auth-e2e.sh` or a Bex-specific successor
- `cli/` tests and test helpers
- `docs/cli-compatibility-checklist.md`

## Acceptance criteria

- [ ] Browser device login, refreshed authenticated request, and logout pass against Bex.
- [ ] `~/.bex/cli.yaml` is `0600`; no Render config file is created, read, or changed.
- [ ] Logout invalidates the current Bex bearer under the existing bounded introspection-cache behavior.
- [ ] Tests never print an access token, refresh token, API-key secret, or kubeconfig.

## Out of scope

- Replacing the legacy Render-client compatibility OAuth client with a dedicated Bex public client.
