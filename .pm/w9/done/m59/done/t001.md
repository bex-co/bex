## Objective

Create a small `cli/` Go entrypoint that imports a pinned `github.com/render-oss/cli/cmd` package and translates Bex-owned environment/config defaults before invoking its exported command runner; do not copy upstream command code.

## Context

- Upstream reads `RENDER_HOST`, `RENDER_CLI_CONFIG_DIR`, `RENDER_CLI_CONFIG_PATH`, `RENDER_WORKSPACE`, and `RENDER_API_KEY` before creating its API client.
- Its config directory may be redirected to `~/.bex`, preserving the upstream `cli.yaml` schema and file-mode handling without touching `~/.render`.
- `lego/go.work` owns the product Go workspace; the launcher module must be deliberately isolated or explicitly added without disturbing its three-module dependency boundary.

## Steps

1. Add the smallest viable `cli` module/entrypoint and pin the tested upstream CLI version.
2. Map `BEX_CLI_CONFIG_DIR`, `BEX_CLI_CONFIG_PATH`, `BEX_HOST`, `BEX_WORKSPACE`, `BEX_OUTPUT`, and an explicit short-lived Bex bearer-token override to upstream inputs only when the upstream input is absent.
3. Default to `~/.bex` and the production Bex REST origin; preserve explicit test/local overrides.
4. Record the intentional first-release limitation that upstream help/TUI strings remain Render-branded.

## Files

- `cli/main.go`
- `cli/go.mod`
- `cli/go.sum`
- root build/release metadata as needed

## Acceptance criteria

- [ ] `go build` produces a `bex` executable that delegates command parsing and requests to the pinned upstream CLI package.
- [ ] A clean environment resolves config to `~/.bex/cli.yaml` and REST requests to the Bex API, never Render's API.
- [ ] Explicit Bex local-dev values override only defaults and do not require `RENDER_*` variables.
- [ ] No upstream CLI command implementation is copied into this repository.

## Out of scope

- Rebranding upstream command help, TUI, User-Agent, docs, or update checks.
- A downstream fork or a new Bex-specific OAuth client protocol.
