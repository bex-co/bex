## Objective

Turn the launcher into a maintainable dependency rather than an accidental fork by making every upstream bump deliberate and preserving the existing unmodified-Render-client API oracle.

## Context

- `w9/m2` and `w9/m4` established `scripts/cli-compat.sh` and `docs/cli-compatibility-checklist.md` as the official-client compatibility evidence.
- The launcher changes process bootstrap only; upstream command behavior should remain upstream-owned and pinned.

## Steps

1. Lock the imported upstream version and make dependency updates visible in review/CI.
2. Add launcher-specific hermetic checks for Bex-to-Render environment mapping and config-directory isolation.
3. Run the suitable existing CLI compatibility and device-auth checks through the released/imported `bex` executable.
4. Record the supported upstream version and known server-side non-goals in the compatibility evidence.

## Files

- `cli/` tests
- CI workflow configuration
- `scripts/cli-compat.sh` or Bex launcher wrapper
- `docs/cli-compatibility-checklist.md`

## Acceptance criteria

- [ ] CI fails when the pinned upstream dependency changes without the launcher and compatibility checks running.
- [ ] The release candidate passes launcher config tests plus the relevant official CLI REST/device-flow regression suite.
- [ ] An upstream command/API feature absent from bex remains explicitly listed as unsupported rather than silently claimed as compatible.

## Out of scope

- Implementing deliberate Bex API non-goals such as workflows, ephemeral SSH, or `ea objects`.
