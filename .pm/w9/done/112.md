# A service notification override with `previewNotificationsEnabled: "false"` answers 400, where Render stores it

Why: a `notification_override` with `preview_notifications_enabled = "false"` is a valid Render configuration and harmless on bex, which has no previews. bex refuses it, so `render_web_service` and the other service resources with that override cannot be created.

- **Found by:** w9/m474, dev-9, 2026-11-18 ([checklist](../../../docs/terraform-compatibility-checklist.md), class 8). It stops `TestWebServiceResource`, whose example configuration sets it.
- **Render:** `PATCH /v1/notification-settings/overrides/services/{id}` with `{"notificationsToSend":"failure","previewNotificationsEnabled":"false"}` answers 200 and the GET reads `"false"` back. Render's cassettes send `"false"` 50 times.
- **bex:** `400 bad request: previewNotificationsEnabled is not supported; use default`. ADR018's notifications row records `default`-only overrides. `"true"` stays refused by name: preview notifications belong to PR previews, a `DO_NOT_DO.md` non-goal.
- **Done when:** an override accepts and reads back `"false"` on REST, GraphQL and MCP, `"true"` is still refused by name, ADR018's row says so, and `TestWebServiceResource` gets past its notification override.

## Resolution

**DONE 2026-11-18.** A service's notification override keeps `previewNotificationsEnabled` `"default"` or `"false"` in a new optional `App.spec.previewNotificationsEnabled` (enum `default`/`"false"`, empty reads `default`) and reads it back. Nothing reads it: bex has no previews.

- **REST** (`lego/backend/internal/apps/rest.go`): `PATCH /v1/notification-settings/overrides/services/{id}` now runs the service patch's own rows (`ApplyServicePatch`), so both fields are checked before either is written. The `GET`, the `PATCH` answer and the workspace-wide list read the stored value. The service object carries `previewNotificationsEnabled` as an extension beside `notificationsToSend`, omitted at `default` so the pinned CLI goldens are unchanged.
- **`"true"`** answers `400 NOTIFICATION_PREVIEWS_UNSUPPORTED` naming the field on every surface, the owner object's refusal, now one constructor (`core.NewPreviewNotificationsUnsupportedError`).
- **GraphQL** `Service.previewNotificationsEnabled` and `setPreviewNotificationsEnabled(id, value)`; **MCP** `update_service(previewNotificationsEnabled:)` and `get_service` (recorded in `rendertest.MCPResultExtensions`). The dashboard does not show it, as Render shows the setting only for services with previews.
- [ADR018](../../../docs/ADR018-render-parity.md)'s notifications, Terraform and MCP rows, the [compatibility map](../../../docs/render-artifacts/notify-on-fail.md) and the checklist (class 8, run G) record it.

`TestNotificationOverrideKeepsPreviewNotificationsDisabled` (`internal/apps/notification_policy_test.go`) sends the provider's recorded body through the strict Render gate and reads `"false"` back on the `PATCH`, `GET`, list, REST service, MCP `get_service` and GraphQL; a `PATCH` with `"true"` and `notificationsToSend: all` is refused and writes neither; GraphQL and MCP refuse `"true"`; `default` drops the extension. Reverting the read-back, the preflight check or the service extension each fails it.

**Live on dev-9** (bex-api and the operator built from main `568b388ce` plus this change, OpenFGA on, a Scale workspace's owner's API key as minted): `TestWebServiceResource`'s recorded `PATCH` answered 200 with `"false"`, and the test now stops at the next request, `PUT /v1/logs/streams/resource/{id}` 404 (`log_stream_override`, a recorded omission). A probe service held `previewNotificationsEnabled: "false"` in its App after the operator reconciled it, and REST, GraphQL and MCP read it back; a `PATCH` with `"true"` answered the 400 and left `notificationsToSend: failure`. The key was revoked and the workspace left empty.
