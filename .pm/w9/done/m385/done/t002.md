## Objective

Store a scope and optional repository for each workspace agent secret. Values stay in OpenBao and names are still listed from OpenBao; the scope lives beside them so a list reads names and scopes without touching values.

## Context

- `lego/backend/internal/agentsessions/secrets.go:137` `AgentSecrets`, `:158` `SetAgentSecret`, `:187` `DeleteAgentSecret`, `:211` `workspaceSecretNames`: values in OpenBao, one path per secret; Postgres holds names only.
- Migrations live in `lego/backend/internal/store/migrations/` (next free number at write time; 0250 was the newest on 2026-11-13).
- A secret with no scope row reads `explicit` — that is how pre-existing secrets keep today's behavior without a backfill across OpenBao.

## Steps

1. Add a table keyed by (workspace, name) with `scope` (`workspace`|`repo`|`explicit`) and `repo`, plus its down migration.
2. `SetAgentSecret` writes the scope with the value; a new secret without a scope gets `workspace`; an update without a scope keeps the stored one.
3. `DeleteAgentSecret` removes the row; a repo scope requires a well-formed `owner/name`.

## Files
