## Objective

Amend ADR098 with a decision for three scopes — `workspace` (every session in the workspace), `repo` (sessions whose `Repo` is that `owner/name`) and `explicit` (only sessions that name it, today's behavior) — the session origins a scope reaches, and the defaults for new and existing secrets.

## Context

- ADR098 D1 (`docs/ADR098-agent-session-secrets.md:28-36`): workspace agent secrets are referenced by name in `secretNames` (Devin's `secret_ids`); inline secrets win over a same-named workspace secret.
- Devin: organization secrets "apply to the entire organization"; repository secrets are available "when it works in that repository" ([Secrets](https://docs.devin.ai/product-guides/secrets), checked 2026-11-13). bex has no per-user secrets (ADR098 D1), so Devin's personal secrets have no counterpart.
- Names are unique in a workspace, so a scope decides only whether a secret applies; the inline-wins rule is unchanged.
- Recommendation recorded by the brainstorm (not a user decision): new secrets default to `workspace` (Devin); existing secrets read as `explicit`, so a value stored under "only sessions that name it" is not widened without its owner acting. That keeps one divergence from Devin for pre-existing secrets and needs the user's sign-off; migrating them to `workspace` instead is one default in t002.

## Steps

1. Write the decision: scopes, the origins each reaches (create, steer, automation run, `/bex` takeover, PR-feedback steer, child spawn), resolution at every turn's dispatch so a new workspace secret reaches the next turn, and the inline-wins rule.
2. State the defaults and the open sign-off as above.
3. Note that every scoped name joins the driver's scrub list (`BEX_AGENT_SECRET_NAMES`, ADR098 D6), so its value is redacted like a named one.
