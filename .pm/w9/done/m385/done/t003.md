## Objective

At every turn's dispatch, the applied secrets are the names the session attached plus every `workspace` secret plus every `repo` secret for the session's repository; an inline secret still wins on its name. The applied set and each name's source are recorded for the session view.

## Context

- `secrets.go:261` `attachSecrets`, `:404` `withSessionSecrets`, `:445` `attachSteerSecrets`; `agent_sessions.secret_names` keeps the attached-by-name set.
- Origins: API/dashboard create and steer; automation runs pass only the template's `secretNames` (`automation_scheduler.go:232`, `automations.go:635`); the `/bex` takeover creates its session with none (`pr_takeover.go:210-217`); children inherit the parent's names (`lineage.go:149-150`).
- The driver scrubs the values of the names in `BEX_AGENT_SECRET_NAMES` (`secretNamesEnv`, ADR098 D6).

## Steps

1. Resolve scoped secrets in `withSessionSecrets` for every turn rather than freezing them into `secret_names`.
2. Include every applied name in `BEX_AGENT_SECRET_NAMES` so its value is redacted.
3. Record the applied names with their source (`inline`, `explicit`, `repo`, `workspace`) for t004.
4. A secret deleted or rescoped since the last turn is absent from the next one.

## Files

- `lego/backend/internal/agentsessions/secrets.go`
- `lego/backend/internal/agentsessions/automation_scheduler.go`, `pr_takeover.go`, `lineage.go` (only if they bypass the shared path)

## Acceptance criteria

- [ ] Tests: a `workspace` secret reaches an unnamed create, a steer, an automation run, a takeover and a child; a `repo` secret reaches only its repository; `explicit` reaches only sessions naming it; an inline secret of the same name wins.
- [ ] Every applied name is in the scrub list.

## Out of scope

- Changing which members may create sessions.

## Done (2026-11-13)

`withSessionSecrets` (lego/backend/internal/agentsessions/secrets.go) now applies named secrets plus every workspace-scoped and same-repository repo-scoped secret at every dispatch, puts every applied name on `BEX_AGENT_SECRET_NAMES`, skips a scoped secret with no value, and returns the applied list; `recordAppliedSecrets` writes it only when it changed. A scope-list failure fails the dispatch before any sandbox starts. Tests: `TestDispatchAppliesScopedSecretsWithoutNames`, `TestDispatchSourcesNamedInlineAndScopedSecrets`, `TestScopeReadFailureFailsTheDispatch`.
