## Objective

Rewrite the Contributor's deploy line to Render's: "Trigger service deploys" and "Trigger rollbacks" are ✅ for a Contributor.

## Context

- ADR024 § The contributor boundary (w1/m68, codex round-5 F2) made a deploy that names `commitId`, `imageUrl` or `buildId`, and every rollback, need `can_create`. Its parity note said Render's Contributor boundary was "not verified" and called a Render-permitted swap "a deliberate divergence to keep". That was written before the parity rule, and ADR018 records no user sign-off.
- Render's rollback restores the target deploy's build artifact, start command, health check path, Docker command, instance count and environment variables (render.com/docs/rollbacks, read 2026-11-23), and Render still gives it to a Contributor.
- bex already limits a deploy's `imageUrl` to another tag or digest of the configured image (`lego/backend/internal/deploys/service.go:869`).
- Pre-deploy command, cron command, build and start commands, and the image setter are service configuration and stay `can_create` (w9/m619).

2. Amend ADR024 § The contributor boundary: what a Contributor deploys, what stays configuration, why (Render's table, the same-image rule), and the open sign-off below.
