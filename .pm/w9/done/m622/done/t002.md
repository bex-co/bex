## Record (2026-11-24)

- **Triage:** the premise held: `deploys/service.go` gated a deploy naming `imageUrl`, `commitId` or `buildId` on `LifecycleOrCreate(true)` (`can_create`) and `Rollback` on `can_create`, while `core/keygrant.go`'s Run deployments level granted `deploys.rollback` on `can_operate`. `clearCache` was never part of the override, so it was already `can_operate`.
- `Trigger` (and so `TriggerManual`, GraphQL `triggerDeploy`, MCP `trigger_deploy`, REST `POST …/deploys`) and `Rollback` (REST `POST …/rollback`, GraphQL `rollbackService`, MCP `rollback_deploy`) authorize `core.RelCanOperate`. The same-image rule (`sameImageRepository`, 400 for every role), the commit and build validation and the protected-environment behavior (no phrase for a chosen image, w8/187) are unchanged.
- The deploy projection's `rollback` decision reads `can_operate` like `deploy` and `cancel_deploy`, so `ActionCapabilities` makes one OpenFGA check instead of two.
- `core.LifecycleOrCreate` had only `false` callers left; they read `core.RelCanOperate` and the helper is deleted.
- `m68_executable_selection_test.go`: the class now ends at commands, build inputs and one-off jobs; the table pins `can_operate` for a bare deploy, a commit, another tag of the configured image, another image (refused later by the same-image rule, not by the role), a build, a cleared cache and a rollback. `roleladder_test.go` pins `Trigger` and `Rollback` on `can_operate`. Reverting either verb to `can_create` turns both tests red (checked).
- Mobile follows: `use-action-access.ts` no longer asks for `can_create` before a rollback (creating an agent session still does).
