## Objective

Send `serviceDetails.url` on every private service read and create answer, with the value Render sends: the service's internal `<slug>:<port>`.

## Context

- Render: all 7 private-service recordings in `render-oss/terraform-provider-render` (`internal/provider/privateservice/resource/testdata/*_cassette.yaml`, 2025-05) carry `"url":"<slug>:10000"` (e.g. `"private-service-tf:10000"`). Render's pinned `privateServiceDetails` has required `url` since 2026-07-20. The provider stores it as the resource's `url` attribute (`internal/provider/privateservice/models.go:65`).
- bex omits it: `lego/backend/internal/apps/render.go:527` (`svcType != renderPrivateService`), on a 2026-07-26 docs reading with no live capture (`docs/render-artifacts/service-addresses.md`, ADR041 D4). The value is already `AppView.InternalAddress`.
- `rendertest.Allowlist` excuses it (`lego/backend/internal/rendertest/allowlist.go:68-82`, `details(SuiteAPI, "envSpecificDetails", "url")`).

## Steps

1. Emit `url` = `InternalAddress` for a private service in `apps/render.go`.
2. Drop `url` from the private-service allowlist entries.
3. Record the recordings as evidence in `docs/render-artifacts/service-addresses.md`, superseding the docs reading.

## Files

- `lego/backend/internal/apps/render.go`, `lego/backend/internal/rendertest/allowlist.go`, `docs/render-artifacts/service-addresses.md`, tests

## Acceptance criteria

- [x] `GET /v1/services/{id}` for a private service carries `serviceDetails.url` = `<slug>:<port>`.
- [x] The rendertest suites pass with `url` removed from the private-service entries.

## Out of scope

- A web service with no URL (no platform subdomain and no custom domain), which stays an open m373 entry.

**Done 2026-11-18:** `renderServiceDetails` (`lego/backend/internal/apps/render.go`) sends a private service's `InternalAddress` as `url` on REST and MCP (create, retrieve, list, update). `TestPrivateServiceURLIsItsInternalAddressOnEveryOperation`, `TestInternalAddressOnAllThreeSurfaces` and `TestM124_InternalAddressIsNeverReportedAsThePublicURL` pin it. They fail with the fix reverted. `docs/render-artifacts/service-addresses.md` §3, ADR041 D4 and ADR018's Internal address row now cite the recordings. **Deviation:** the allowlist's `url` entries are per operation, and a web service or static site with no public host (out of scope here) still reproduces them, so they stay. A new image-port private service also names no port until the operator reads its image (ADR089 D3).
