## Objective

Close the confirmed MEDIUM finding: the Blueprint apply path omits the dunning /
billing-enforcement gate that every interactive create runs, so a payment-enforced
(delinquent) workspace can provision unlimited new paid resources via `render.yaml`. Route the
Blueprint path through the same combined gate the interactive paths use.

## Context

- `lego/backend/internal/apps/deploy.go:1060` `requireStackPaymentMethod` calls **only**
  `s.RequirePaymentMethod` (payment-method presence), never `s.RequireBillingMutation`. It is the
  sole billing check on `deployParsedStack` (`deploy.go:608`, reached from `DeployStack` /
  `POST /v1/blueprints/deploy` + GraphQL + MCP). The sync/prepare entrypoints call it too
  (`blueprint.go:415`, `blueprint.go:568`).
- The create/apply helpers write resources with no gate: `createFromStack → createNewApp →
  materializeNewApp` (Service), `applyDatabase` (`deploy.go:2786`), `applyKeyValue` (`~:2803`).
- Interactive paths gate correctly via `core.Base.RequirePlanBilling` (`core/base.go:414`), which
  runs `RequirePaymentMethod` **and** `RequireBillingMutation`: Service `service.go:1588`, Postgres
  `postgres/service.go:516`, KeyValue `keyvalue/service.go:424`.
- `RequireBillingMutation` (`core/base.go:382`) → `store.CheckBillingMutationAllowed`
  (`store/billing_lifecycle.go:721`) returns `ErrBillingEnforced` for `enforcing`/`enforced`/
  `recovering`. The payment-method marker (`payment_method_bound_at`) is monotonic and never cleared
  on delinquency, so `RequirePaymentMethod` passes for a failing-card tenant.
- `Enforcer.Enforce()` (`billing/worker.go:106`) runs once per lifecycle transition; an already-
  `enforced` row is never re-claimed, so resources created afterward are never suspended, and the
  operator is billing-free.
- Detail: `~/security-audit-skill/bex9/run-1/FINDINGS-DETAIL.md`.

## Steps

1. In `requireStackPaymentMethod` (`deploy.go:1060`), after the paid-plan payment-method check, call
   `s.RequireBillingMutation(ctx, tenantID)` unconditionally so an enforced/recovering workspace is
   refused regardless of plan tier.
2. Prefer the fuller fix: route each per-resource Blueprint apply — `createFromStack` (service),
   `applyDatabase`, `applyKeyValue`, and the update branches — through `RequirePlanBilling(ctx,
   tenantID, plan)` per resource, so Blueprint shares the one universal gate rather than a patched
   single entrypoint. Confirm the returned error is the same coded `ErrBillingEnforced` shape the
   interactive paths surface (dialect handled in t006).
3. Ensure the refusal happens before any `s.Client.Create`, so no partial stack is created.
