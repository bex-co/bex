## Objective

Stop raw internal error strings (pgx/Kubernetes messages: constraint names, connection strings,
internal paths) from reaching clients on unexpected failures. `core.WriteErr` currently emits
`err.Error()` verbatim for any error not wrapped in a known sentinel.

## Context

- `lego/backend/internal/core/http.go:248` `WriteErr` maps known sentinels (`ErrNotFound`,
  `ErrForbidden`, …) to statuses, but any unclassified error falls through to `code = 500` with
  `msg := err.Error()` in the JSON body.
- Many verbs `return err` on raw store/k8s failures (e.g. `postgres/service.go:376-532`), so internal
  detail can surface. Info-disclosure only (no injection/auth impact) — this is a hardening note.
- The GraphQL surface (graphql-go) has the same passthrough for non-`CodedError` errors — check
  whether it should be aligned (coordinate with t006's parity check).
- Keep server-side logging of the full error (observability must not regress); only the client body
  changes.

## Steps

1. In `WriteErr`, for the unclassified 5xx path emit a generic stable message (e.g.
   `"internal error"`) and keep the real error in server logs.
2. Confirm all intentional coded/sentinel errors still surface their client-facing message (no
   regression on 4xx dialect — that is m38's shipped contract).
3. Check the GraphQL non-`CodedError` path for the same leak and align if needed (record the decision
   for t006).

## Files

- `lego/backend/internal/core/http.go`
- (check) the GraphQL error formatter in `lego/backend/internal/api/`

## Acceptance criteria

- [ ] An unclassified store/k8s error produces a generic 500 body with no internal string; the full
      error is still logged server-side.
- [ ] Known coded/sentinel errors are unchanged (4xx dialect intact).
- [ ] Test asserts the generic body for an unmapped error and the preserved message for a coded one.

## Out of scope

- Re-classifying specific errors into new sentinels (only the fallthrough body changes).
