## Objective

Make every PromQL/LogQL query builder escape the `"` that terminates a query string literal, so no
builder can be broken out of a quoted literal if a future caller ever routes a less-constrained value
through it. Defense-in-depth (not exploitable today — `req.App`/`req.Namespace` are server-resolved
and DNS-constrained).

## Context

- `egressquery.RegexEscape` / `regexp.QuoteMeta` (used in `lego/backend/internal/metrics/source.go`
  and the egress query builders) do **not** escape `"`; `regexp.QuoteMeta` escapes regex metachars
  but leaves the double-quote intact.
- `lego/backend/internal/logs/loki.go` already does this correctly — it interpolates filter values
  via `%q` (Go double-quote escaping) or `regexp.QuoteMeta` inside a `%q`-quoted matcher.
- The safe pattern: quote the whole matcher value with `%q` (or an equivalent quote-safe escaper) so
  the terminating `"` is always escaped, then apply `regexp.QuoteMeta` only for regex-matcher
  semantics.

## Steps

1. Audit `metrics/source.go` and `egressquery` (and any other PromQL/LogQL builder) for values
   interpolated into a `"..."` literal without `%q`.
2. Route each through a quote-safe escaper (use `%q`, matching `loki.go`), keeping `regexp.QuoteMeta`
   where regex-matcher semantics are intended.
3. Add a unit test that a value containing `"` (and `\`) is emitted escaped and cannot terminate the
   literal.

## Files

- `lego/backend/internal/metrics/source.go`
- `lego/backend/internal/egressquery/` (the `RegexEscape` helper and its callers)

## Acceptance criteria

- [ ] No PromQL/LogQL builder interpolates an unescaped value into a quoted string literal.
- [ ] A test proves a `"`-bearing input is escaped and stays inside the literal.
- [ ] `make lint-backend` green.

## Out of scope

- Widening what values reach these builders (they stay server-resolved/DNS-constrained).
