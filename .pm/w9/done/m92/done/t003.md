## Objective

Two bugs in the `/agents` list's filter-tab chrome:

1. The `<h2>` above the Recent/Archived/All tabs always reads "Recent",
   regardless of which tab is active.
2. The Archived tab's URL is `/agents?archived=%22true%22` (decodes to the
   JSON-stringified `archived="true"`, literal quotes and all) instead of the
   clean `archived=true` the All tab's sibling (`archived=all`) demonstrates is
   achievable.

## Context

- Bug 1: `dashboard/src/routes/agents.tsx:131-133` (`SessionListSection`):
  ```
  <h2 id="session-list-title" className="text-base font-semibold">
    {t("agentSessions.listTitle")}
  </h2>
  ```
  `t("agentSessions.listTitle")` is a static i18n key
  (`dashboard/src/features/agent-sessions/locales/en.ts:9`) with no
  interpolation. The active tab is already computed correctly a few lines
  above (`agents.tsx:122-123`, `activeKey`) but is only used to style the tab
  buttons (line 143), never fed into the heading.
- Bug 2: `dashboard/src/routes/agents.tsx:109-121` defines
  `{ key: "archived", ..., archived: "true" }` (a plain string literal, not
  `JSON.stringify`), rendered via `<Link to="/agents" search={{ archived:
  tab.archived, phase }}>` at line 146. The quoting is injected by TanStack
  Router's default search serializer
  (`node_modules/@tanstack/router-core/dist/esm/searchParams.js:43-61`,
  `stringifySearchWith`): it treats any string search value that *looks like*
  a JSON literal specially — `"true"` starts with `tr`, matches the
  `jsonStart` regex, round-trips through `JSON.parse`/`JSON.stringify`, and
  comes out as the quoted literal `"true"` → URL-encoded `%22true%22`.
  `"all"` doesn't match the regex, so it passes through raw — that's why only
  the Archived link is affected. The exact same collision exists a second
  place: `dashboard/src/common/components/dashboard-layout/agent-sessions-nav-section.tsx:139`
  (`search={{ archived: "true" }}` on the sidebar's own Archived link).

## Steps

1. Fix the heading: derive the tab label from `activeKey` (e.g. per-tab i18n
   keys already exist as `filterArchived`/`filterAll`/`filterActive`-style
   strings for the tab buttons — reuse or mirror them) so `<h2>` reads
   "Recent" / "Archived" / "All" to match the active tab.
2. Fix the query param: rename the archived filter's string value away from
   the literal `"true"` (which collides with the router's JSON-ish
   auto-detection) to something that can't be mistaken for a JSON literal,
   e.g. `"archived"`. Update both call sites (`agents.tsx:114`,
   `agent-sessions-nav-section.tsx:139`) and wherever the `archived` search
   param is read back out (the loader/route search-param parsing in
   `agents.tsx`) to match the new value. Confirm this value is purely a
   dashboard-side filter key and isn't passed verbatim to the backend's
   GraphQL `archived: String` variable in a way that would break — check
   `hooks/use-agent-sessions.ts` and `agent-sessions.graphql` for how
   `archived` flows to the `AgentSessions` query, and keep the backend
   contract (`"true"` / `"all"` / unset) unchanged if it's relied upon
   server-side, translating the dashboard's new UI-local key back to
   whatever value the query expects.
3. Confirm archived-tab active-state styling still works with the renamed key.
