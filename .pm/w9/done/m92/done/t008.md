## Objective

The sidebar's `AgentSessionsNavSection` re-fires the full, unbounded
`AgentSessions` GraphQL query (every field, `limit: null`, no `cursor`) on a
5-second interval whenever any session is non-terminal — including while a
session detail page is open, which already has its own dedicated SSE stream
(`GET /v1/agent-sessions/:id/stream`) for that session's live data. This is
wasteful: every 5 seconds it refetches the entire session history's full field
set instead of a bounded/paginated slice, duplicating work the stream already
covers for the actively-viewed session.

  poll still duplicates work for the single actively-viewed session's status
  fields, which the stream (or a lighter targeted query) could instead push.

## Steps

1. Cap the poll's `limit` to a reasonable page size (matching whatever the
   sidebar actually renders, e.g. the same number as its `Load more` initial
   page) instead of `null`, and/or pass a `cursor` so repeated polls don't
   keep re-requesting the full historical set.
2. Evaluate whether the actively-viewed session's status update can instead
   ride its existing SSE connection (a status/phase event alongside the
   conversation stream) rather than a separate poll — if that's a larger
   change, it's acceptable to defer and note as a follow-up; the minimum bar
   for this task is capping the poll's scope (step 1).
3. Confirm the "Load more" pagination path (`fetchMore`, lines 122-123) still
   works correctly once a `limit`/`cursor` is introduced to the base poll
   query.
