# Agent sessions die mid-run: sandboxes are deleted minutes in, and a rollout fails running sessions

Why: the bex workspace's nightly rt-* automations mostly end `failed` without doing their work. On 2026-11-12, every session that ran after 10:00 UTC failed. Render's and Devin's long-running work survives a platform rollout.

- **13:00 session:** `ags-dbqrgmrk98kc7399u9dg` (rt-remove-dead-code, created 13:00:11 UTC) failed at 13:06:41 with "sandbox terminated before completion", at $0.03. Its BatchSandbox `7224297b-…` was deleted around then with no pod `Killing` event, so the custom resource was deleted, not the pod evicted.
- **After the 12:17 UTC rollout:** bex-api's completer logged `read status failed (session=ags-dbqosai6krac73d83mm0 …): sandbox runtime not configured: exec failed to start in this sandbox` (the same for `ags-dbqpofa8vjhs73do9c40`) from 12:21. Then it logged `terminal fallback converged … reason="sandbox status remained unavailable beyond the retry window"`, and both sessions (running 1–2 h) failed at 12:24 and 12:26.
- **2026-11-11:** five of seven automation runs failed with "ACP turn exceeded 1800000ms". The 30-minute wall-clock turn cap from w5/m80 kills turns that are still working (an rt-* routine routinely runs longer). The other two failed with "sandbox terminated before completion".
- **Look at:**
  - what deletes a running agent sandbox: `lego/backend/internal/sandbox/idle.go`, `lifetime.go` (expireTime) and the completer's terminal fallback;
  - why exec into an existing sandbox fails after a bex-api, gateway or controller restart;
  - whether the turn cap should be an inactivity timeout, so a turn that is still making progress is never killed.
- **Also:** the T0 limit (2 concurrent platform-model sessions) refuses runs that overlap (`failed_create` at 12:00).
