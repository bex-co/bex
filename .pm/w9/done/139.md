# A native build's version line reads `Using Ruby 3.3.14 (from Gemfile.lock)`, where Render's reads `Using Ruby version 3.3.14 via /opt/render/project/src/Gemfile.lock`

Why: the build log is where a user learns which interpreter their service runs, and a log scraper or a person comparing a Render and a bex build of the same repository finds a different sentence. Render's narration says "version", names the signal by its full path under `/opt/render/project/src`, and uses "via"; bex's says "(from Gemfile.lock)" and "(default)".

- **Found by:** w9/133's production check on pin `7e481dece7ac`, 2026-11-21 (b2ab0ef065): `render-examples/sidekiq` logged `==> Using Ruby 3.3.14 (from Gemfile.lock)` at head and `==> Using Ruby 3.2.0 (from Gemfile.lock)` at `73f3ab4db`. Render's form, `==> Using Ruby version 3.4.1 via /opt/render/project/src/Gemfile.lock`, is quoted in ADR018's runtime row (w9/133) from Render's own build logs. w4/668 left Render's wording for the default case unverified (`==> Using Python version 3.14.10 (default)` from memory, no capture).
- **bex:** the narration lines in `lego/operator/internal/build/` (`nativeversion.go` and the per-runtime resolvers), for every native runtime (Python, Node, Ruby, Elixir/Erlang, Bun) and every signal kind (env var, version file, lockfile, Gemfile, `engines`, default).
- **Done when:** capture Render's exact line for each runtime and signal kind from its docs, changelog or public build logs (record the sources in `docs/render-artifacts/`), and bex's narration prints the same sentence with the same path form for each, with unit tests per runtime; a case Render's sources do not show keeps bex's line and is named as unmeasured in ADR018's runtime row.
- Filed by the `/loopx w9` orchestrator from w9/133's result.

**Render's lines captured first (2026-11-21):** [docs/render-artifacts/native-version-narration.md](../../../docs/render-artifacts/native-version-narration.md) quotes Render's line for each runtime and signal from build logs that Render users published (GitHub issues and PRs, Render's community forum and feedback board, the GoRails and Elixir forums). No Render account was used. Every line has the form `==> Using <Name> version <version> <how>`. `<how>` is `(default)`, `via environment variable NODE_VERSION`, or `via` the version file's path in the build (`/opt/render/project/src/.nvmrc`). That path includes the service's root directory (`…/backend/.python-version`). Node's name has been `Node.js` since about October 2024. An Elixir default prints `==> Using Erlang version 26.2.2 (default)` on its own line, before the Elixir line. Render's logs show Node's `NODE_VERSION`, `.node-version`, `.nvmrc`, `engines.node` and default lines, Python's `PYTHON_VERSION`, `.python-version` and default lines, and Ruby's `Gemfile.lock`, `.ruby-version`, Gemfile and default lines. They also show the default lines for Elixir with Erlang, Bun, Poetry and uv (a `uv.lock` with no `UV_VERSION`). The default form w4/668 left unverified is now cited: `Using Python version 3.14.3 (default)` (2026-09-28).

**Fixed 2026-11-21 (loopx w9):** `NativeChoice.NarrationIn` (`lego/operator/internal/build/nativeversion.go`) prints Render's form for exactly those signals (`renderSignals`). Examples: `==> Using Ruby version 3.3.14 via /opt/render/project/src/Gemfile.lock`, `==> Using Node.js version 22.23.5 via environment variable NODE_VERSION`, and, for a service on Render's default Erlang/OTP, `==> Using Erlang version 28.0.2 (default)` before `==> Using Elixir version 1.18.4 (default)`. A Bun or uv lockfile names no version, so its line reads `(default)`, as Render's does. The operator passes the service's source directory in the image (`NativeSourceDir`) to the resolve phase as `BEX_NATIVE_PROJECT_DIR`, so a version file is named under the root directory. Signals that no Render log shows keep bex's line, and ADR018's runtime row names them as unmeasured: Ruby's `gems.locked` and `.tool-versions`, `ELIXIR_VERSION`/`ERLANG_VERSION`, `BUN_VERSION`/`.bun-version`, `POETRY_VERSION`, `UV_VERSION`, every Rust signal, and Go. Render's only Go line on record (2023, `==> Using Go version go version go1.20.5 linux/amd64`) embeds `go version`'s output, which only the build step knows. `TestNativeChoiceNarration` (`nativeversion_test.go`) covers every runtime and signal, measured and unmeasured, plus the root-directory path and the Erlang line. `TestRunNamesAVersionFileUnderTheProjectDir` (`cmd/native-resolve`) covers the path the entrypoint prints, and the resolver job test covers `BEX_NATIVE_PROJECT_DIR`. The existing narration tests now expect Render's strings. With the Render form switched off, 17 tests in the two packages fail. ADR060's D7 addendum and ADR018's runtime row record the change. No CI script pins the lines. Local Docker was hung, so the suites ran with a fail-fast `docker` shim on `PATH`; no build in them needs Docker. The next production native build prints the new lines; no live check was run here.

**Seen in Render's logs but not printed yet (candidates for follow-ups):** `==> Docs on specifying a Node.js version: https://render.com/docs/node-version` after each version line, `==> Requesting Node.js version >=20.15` before an `engines.node` range, and Render's Go line.
