## Objective

Record a cron job's create and delete as Render does (`CreateCronJobEvent`, `DeleteCronJobEvent`), while web services, private services, background workers and static sites keep `CreateServerEvent`/`DeleteServerEvent`.

## Context

- Render's reference: `CreateServerEvent` covers "web service, private service, background worker, or static site created"; cron jobs have their own `CreateCronJobEvent`/`DeleteCronJobEvent` pair; a cron rename is `UpdateServiceNameEvent` (already mapped). Both cron names are in the pinned enum.
- `renderEvents` maps by verb only: `apps.Create` → `CreateServerEvent`, `apps.Delete` → `DeleteServerEvent`, for every type. The create row is written once the service exists (`lego/backend/internal/apps/service.go` ~2216, w4/m321 t011).
- Other consumers read the same rows: the events feed and webhooks (`lego/backend/internal/eventvocab`, `lego/backend/internal/store/event_facts.go`).

## Steps

1. Recommended: record a cron job under distinct verbs (for example `core.AuditVerbCreateCronJob`/`AuditVerbDeleteCronJob`, chosen at record time from the App's type), so the mapping stays per verb and no column is needed. Map them in `renderEvents`.
2. Make every consumer that keys on `apps.Create`/`apps.Delete` (events feed `service_created`/`service_deleted`, webhook verb events) treat the new verbs the same, so those surfaces do not change.
3. Cover REST, GraphQL, MCP and Blueprint-created cron jobs.

## Files

- `lego/backend/internal/core/audit.go`, `lego/backend/internal/apps/service.go`, `lego/backend/internal/audit/service.go`, event-feed/webhook verb tables, tests

## Acceptance criteria

- [x] A cron job created through REST, GraphQL, MCP or a Blueprint records `CreateCronJobEvent`; its delete records `DeleteCronJobEvent`.
- [x] A web service create still records `CreateServerEvent`.
- [x] The events feed and outbound webhooks still report the cron job's creation and deletion as before (test).

## Out of scope

- Other cron job edits (Render documents no event for them).

**Shipped 2026-11-16 (deviation):** REST, GraphQL and MCP creates and every delete record `apps.CreateCronJob`/`apps.DeleteCronJob`. A Blueprint-created service of any type records no per-service create row: `ApplyBlueprintEvent` covers it, as the existing Blueprint audit tests (`blueprint_setting_events_test.go`, `blueprint_regroup_events_test.go`) require; the cron job is no exception. A delete's allowed row now lands once the service is gone.
