## Objective

Record the remaining 1:1 actions under Render's names: custom domains, auto-deploy, and build-source links.

## Context

- Render's reference (read 2026-11-16): `CreateCustomDomainEvent`, `DeleteCustomDomainEvent`, `UpdateAutoDeployEvent` (auto-deploy toggled), `UpdateAutoDeployTriggerEvent` (trigger settings such as branch or path filters changed). These four are documented but **not** in the pinned enum; bex already emits non-enum event values as a documented extension (ADR018 Audit logs row), so they ride the same allowance.
- Pinned enum, bex has the verbs: `LinkBuildSourceEnvGroupEvent`, `UnlinkBuildSourceEnvGroupEvent`, `UpdateServiceBuildSourceEvent`.
- bex verbs: `core.AuditVerbAddDomain`/`AuditVerbDeleteDomain` (recorded only after the claim changed, w4/m122), `AuditVerbSetAutoDeploy`, `AuditVerbSetBuildFilter` (`lego/backend/internal/core/audit.go`); env-group links (`envgroups.LinkService`/`UnlinkService`, which may target a build source, `lego/backend/internal/envgroups/service.go` ~1302); a service's build-source link (`apps.LinkBuildSource`, `lego/backend/internal/apps/build_sources.go:1013`, and update-service `buildSourceId`).
- `apps.VerifyDomain` has no Render event and keeps bex's name.

## Steps

1. Map add/delete domain to Render's names.
2. Read how `SetAutoDeploy` carries the on/off value versus the trigger and branch; record `UpdateAutoDeployEvent` when on/off changed and `UpdateAutoDeployTriggerEvent` when the trigger, branch or build filter changed (one row each when one call changes both).
3. Record an env-group link/unlink whose target is a build source under the build-source names; a service-to-build-source link under `UpdateServiceBuildSourceEvent`.
4. Add the four docs-only names to whatever allowlist the REST response-conformance test uses for non-enum event values, citing render.com/docs/audit-logs.
