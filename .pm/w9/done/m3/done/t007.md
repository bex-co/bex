## Objective

Ship the compatible CRD/operator/API to production, backfill all existing managed Postgres display names, and live-verify rename without recreating any database-bearing object.

## Context

- Production deploys the operator and bex-api from one digest-pinned image through `deploy/gitops/base/bex.yaml` and `.github/workflows/deploy.yml`; Argo applies the generated CRD with server-side apply.
- The production namespace may contain irreplaceable CNPG data. A rollout is successful only if the before/after Database uid and CNPG/PVC/Secret identities are identical.
- This task is an external-state change and must use the repository's authorized ship/deploy workflow when executed; creating this PM task does not itself authorize a commit or push.

## Steps

1. Capture a non-secret preflight inventory and confirm backups/readiness before deployment; abort on unhealthy databases or ambiguous legacy names.
2. Roll the digest-pinned image/CRD through the normal production workflow and wait for both `bex-controller-manager` and `bex-api` Ready.
3. Run the migration dry-run, review it, apply it to every production Database, and rerun to prove idempotence.
4. Execute a safe official-CLI create/rename/get lifecycle (or an explicitly approved existing-resource rename-and-restore) and verify stable id/name resolution.
5. Compare the pre/post identity inventory, CNPG readiness, connection reachability, backup status, and API health; record sanitized evidence in the milestone README.
