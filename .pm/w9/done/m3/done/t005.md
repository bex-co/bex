## Objective

Provide a repeatable migration/runbook that adopts existing name-keyed Database CRs into the new display-name contract without changing immutable identity or touching their data plane.

## Context

- Existing production and dev Database CRs have no `spec.name`; compatibility reads can fall back, but explicit backfill makes the new intent observable and removes indefinite schema ambiguity.
- A legacy CR's metadata name remains its grandfathered stable API id. It cannot safely be converted to `dpg-…` without moving owner-referenced state, so the migration must not attempt that.
- Rollout must prove absence of delete/create behavior using metadata uid plus CNPG Cluster/PVC/Secret names, not just a successful API response.

## Steps

1. Add a repo-level migration script with dry-run by default, explicit apply mode, namespace selection, and safe handling of zero/multiple Database CRs; never print Secret data.
2. Backfill only missing `spec.name` from `metadata.name`; make reruns byte-for-byte no-ops and fail before writes on incompatible/ambiguous state.
3. Add a verifier that captures non-secret identity inventory before/after (Database uid/name, owned CNPG Cluster, PVC, Secret names, routes/poolers/backups where present) and fails on recreation or disappearance.
4. Document rollout ordering: CRD/schema and compatible code first, backfill second, then rename smoke test; include rollback behavior that does not erase `spec.name` or revert CRDs destructively.

## Acceptance criteria

- [ ] Dry-run lists only non-secret planned patches; apply sets `spec.name` only on legacy CRs.
- [ ] A second apply performs no writes and exits successfully.
- [ ] Before/after verification fails if a Database uid or any data-plane object identity changes.
- [ ] The script supports the production apps namespace and `dev-1` through `dev-10` without hard-coding credentials or kubeconfig contents.
- [ ] Legacy resources remain addressable under their pre-migration ids and can be renamed through the new display-name field.

## Out of scope

- Re-keying existing CR metadata names to `dpg-…`; only new resources receive opaque ids.
