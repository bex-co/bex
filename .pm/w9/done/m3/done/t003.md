## Objective

Turn the current explicit rename rejection into a real `PATCH /v1/postgres/{id}` update that obeys Render's optional-field semantics and works through the pinned official CLI.

## Context

- `handleUpdatePostgres` decodes `name` but rejects any changed value because the old architecture used it as the id.
- `PostgresPatch` already models pointer fields and powers both real and dry-run updates; `name` must join that shared validation/apply path rather than becoming a one-off handler mutation.
- The route is authorized against the target Database. Error behavior must distinguish invalid name, duplicate name, unknown id, and forbidden cross-workspace access.

## Steps

1. Add `Name *string` to the core partial-update model and validate the same constraints on live and dry-run paths.
2. Apply a rename as a merge patch to `spec.name` only; keep the same Database metadata name/uid and return the same `id` with the new `name`.
3. Preserve same-name updates as successful no-ops and make mixed patches (`name` plus plan/disk/HA/IP allow list) atomic from the caller's perspective.
4. Replace the architectural rejection in the REST handler and update Render-shaped error envelopes/status codes.
5. Extend `scripts/cli-compat.sh` (or its verifier) to run `render postgres update <old-name> --name <new-name>`, then resolve/get/update the resource by its new name while asserting the id did not change.

## Acceptance criteria

- [ ] A name-only PATCH succeeds without requiring `plan`; mixed partial updates change exactly the fields supplied.
- [ ] `dryRun=true` returns the new name and same id without writing the CR.
- [ ] Duplicate, invalid, missing-id, and cross-workspace rename attempts fail with specific Render-shaped errors and no partial write.
- [ ] The official `render postgres update --name` command exits 0, subsequent name resolution works, and the CLI verifier asserts the id stayed identical.
- [ ] The Database CR uid/name and every existing CNPG/PVC/Secret identity are unchanged by the operation.

## Out of scope

- CLI source changes or a bex-specific CLI; the official `render-oss/cli` remains unmodified.
