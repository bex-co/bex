# 096 — Repository environment phase 2: sessions boot from a snapshot built from the setup steps, as Devin's do

Why: phase 1 (w9/m387, ADR109 D2) runs a repository's setup steps at the start of every turn, so each turn still waits for them; Devin builds a snapshot when the blueprint changes and about every 24 hours and boots every session from it, which removes the wait and closes ADR109's recorded divergence.

- **Devin:** `initialize` and `maintenance` run at snapshot build; "at the start of every session, `maintenance` commands are not auto-executed"; builds rerun when the blueprint changes and about every 24 h ([Blueprint reference](https://docs.devin.ai/onboard-devin/environment/blueprint-reference), checked 2026-11-13).
- **bex today:** `BEX_REPO_ENVIRONMENT` setup runs in the driver after `ensureRepo` on every sandbox (ADR109 D2); the sandbox image build path already builds and stores per-workspace images (ADR104, w2/m358, budget per workspace since w5/m383).
- **Shape of the work:** build a per-(workspace, repository) agent image from the base agent template plus the checkout and setup steps; rebuild when the environment changes and on a daily schedule; dispatch from the newest successful build and skip the in-sandbox setup when the image matches the environment's version; fall back to phase 1 while no build exists; count builds against the workspace's image budget; show build status and logs next to the environment in the dashboard.
- **Size:** milestone (several tasks across store, sandbox builds, dispatch, driver and dashboard); promote when picked up.
