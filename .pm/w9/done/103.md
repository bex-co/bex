# `PATCH /v1/webhooks/{id}` with `eventFilter: null`, which Render's Terraform provider sends on every update of an all-events webhook, answers 400

Why: once w9/m472 lets `terraform apply` create a `render_webhook` with no `event_filter`, the next change to that webhook (a rename, a URL, `enabled`) fails on bex, though the same configuration updates on Render.

- **Provider:** `render-oss/terraform-provider-render` `06af456`, `internal/provider/webhook/resource/resource.go` `webhookUpdate` always sends `EventFilter: &eventFilter`; with no `event_filter` in the configuration the slice is nil, so the body carries `"eventFilter": null` (`internal/client/webhooks/webhooks_gen.go` `WebhookPATCHInput`, pointer with `omitempty`, which omits only a nil pointer).
- **bex:** the pinned `update-webhook` schema's `eventFilter` is a non-nullable array, so the Render request gate answers `400 invalid request body at /eventFilter` (`lego/backend/internal/api/render_openapi.go` `applyRenderSchemaCompatibility`; w9/m472 widened only `create-webhook`). Past the gate, `updateEndpointRequest.EventFilter *[]string` would read null as "unchanged" (`lego/backend/internal/webhooks/rest.go`).
- **Open question:** the provider's recordings never PATCH a webhook, so Render's meaning of `null` there is unrecorded: "leave the filter as it is" or "every event". The provider sends null exactly when the configuration has no `event_filter`, and reads `[]`/`null` back as unset, so only "every event" lets a configuration that drops `event_filter` converge on a clean plan. Check Render's behavior (a real Render workspace, or w9/m474's re-recorded suite) before choosing; if it cannot be observed, the provider's meaning is the parity-sufficient choice (ADR008).
- **Done when:** `PATCH /v1/webhooks/{id}` with `{"name":"renamed","eventFilter":null}` answers 200 with the chosen meaning, a test covers it, and ADR018's Outbound event webhooks row records it.

**Done 2026-11-18.** Render's meaning could not be observed: there is no Render workspace credential, and the provider's recordings never PATCH a webhook. So bex takes the provider's own meaning, which the note names as the parity-sufficient choice. At `06af456`, `webhookUpdate` sends null for both a missing `event_filter` and `event_filter = []`, then stores the PATCH response as its state, so `null` means every event. The pinned Render CLI's `WebhookPATCHInput` omits a nil pointer and never sends null. `update-webhook`'s `eventFilter` is nullable at the gate, as `create-webhook`'s is (`render_openapi.go` `applyRenderSchemaCompatibility`). `rest.go` `decodeEventFilter` keeps the filter when the key is omitted and stores the all-events `[]` for a null. Tests: `TestRenderRESTPatchWithNullEventFilterSubscribesToEveryEvent` (a filtered webhook keeps its filter when the key is omitted; `{"name":"renamed","eventFilter":null}` answers 200 and stores `[]`; a string filter answers 400). Also the `webhook update eventFilter` rows of `TestRenderValidatorAcceptsTerraformProviderNulls`, and `TestTerraformProviderNullsLeaveSharedSchemasStrict`, which keeps the webhook object's `eventFilter` non-null. Both fail with the fix reverted. ADR018's Outbound event webhooks row records it, marked unverified against Render.
