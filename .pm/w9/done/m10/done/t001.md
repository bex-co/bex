## Objective

Add `generateValue` to the env-var write verb in `internal/secrets`: when true (and no explicit value given), mint a cryptographically random value server-side and store it in OpenBao exactly like a user-supplied one. Match Render's field semantics (their OpenAPI: `generateValue` on env-var input; base64-ish random string).

## Context

- `lego/backend/internal/secrets/` — env-vars verbs are OpenBao-backed (`docs/ADR013-secrets.md`); 503 without `BEX_OPENBAO_URL`.
- Verify Render's exact generated-value shape/length from their OpenAPI spec before picking a format; document any divergence rather than guessing silently.
- An explicit `value` alongside `generateValue: true` must be rejected or resolved per Render's documented behavior — check, don't invent.

## Steps

1. Extend the write request type + validation; mint via `crypto/rand`.
2. Return the minted value in the write response (the caller must be able to see what was generated), stored thereafter like any env var.

## Files

- `lego/backend/internal/secrets/service.go` (+ request types)

## Acceptance criteria

- [ ] A write with `generateValue: true` stores a non-empty random value readable back through the existing reveal flow; format matches Render's documented shape or the divergence is written down.

## Out of scope

- Adapter threading (t002); bex.yml acceptance (w1/m35/t005).

## Done (2026-07-14, landed alongside w1/m35)

Implemented as the shared prerequisite for `w1/m35/t005`. The `generateValue` core verb lives in `internal/secrets` (`SetEnvVars` honors a new `EnvVarView.Generate` field; `value`+`generateValue` is rejected) and mints Render's documented shape — a base64-encoded 256-bit value (32 random bytes → 44-char std-base64) — via a new shared `core.GenerateValue()` (also used by env groups). The minted value is returned in the write response and stored in OpenBao like any env var. Verified: `internal/secrets/generate_test.go` (`TestSetEnvVarsGenerateValue`, `TestSetEnvVarsValuePlusGenerateRejected`) + `internal/core` (base64 256-bit shape). **Remaining w9/m10 work is untouched:** t002 (adapter threading — the REST/GraphQL/MCP env-var write fragments don't yet populate `Generate`), t003 (pagination), t004+ still open; the ADR006 env-vars divergence note still lists pagination + generateValue and should be trimmed to pagination-only when t002 lands.
