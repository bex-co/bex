# A new image private service reads no `serviceDetails.url` and `openPorts: []` until its ports are discovered, where Render's create answers `<slug>:10000`

Why: since w9/m473 a private service reads its `<slug>:<port>` as `url`, as Render's recorded responses show, except in the first moments after create. Render's own Terraform provider reads `url` from that create response, and this is the last private-service case `rendertest.Allowlist`'s `url` entries still excuse (w10/m373 gate 1).

- **Render:** `render-oss/terraform-provider-render` `06af456`, `internal/provider/privateservice/resource/testdata/private_service_cassette.yaml`. The `POST /v1/services` that creates `private-service-tf` from the `nginx` image with no port answers 201 with `serviceDetails.url` `"private-service-tf:10000"` and `openPorts` `[{"port":10000,"protocol":"TCP"}]`. `nginx` listens on 80, so Render reports its default `PORT` of 10000 before it has scanned anything. Every later read in the recording says the same.
- **bex:** an image-port private service (`AppSpec.UsesImagePorts`) has no port until its image's metadata is read. `App.ServicePort` returns `Status.EnvPort`, 0 when no `PORT` is set (`lego/types/v1alpha1/image_network.go`). `App.InternalAddress` is then `""`, `OpenPorts` is `[]`, and `renderServiceDetails` (`lego/backend/internal/apps/render.go`) sends no `url` or `internalAddress`. ADR089 § Port slice decisions chose this ("never a guessed 3000") before bex's default `PORT` became Render's 10000 (w8/168). Reproduced by `TestRESTCreatePrivateService` (`lego/backend/internal/apps/deploy_test.go`) with the allowlist's `url` entry removed.
- **Open question:** whether bex can answer `<slug>:10000` honestly before discovery, which depends on whether the process is given `PORT=10000` then and whether the slug Service routes 10000 before the image's ports are known (`lego/operator/internal/controller/app_controller.go` `appEnv`, `port_detect.go` `processPort`). If so, `ServicePort`, `InternalAddress` and `OpenPorts` answer 10000 together, as Render does, and ADR089 records the amendment. If not, record why the pending state stays.
- **Done when:** a REST create of `{"type":"private_service","name":"p","image":{"imagePath":"nginx:1"}}` answers `serviceDetails.url` as Render's does, or ADR018's "Partial serviceDetails projection" row records why it cannot. A test covers the answer.

## Done 2026-11-18

- **Verdict: work.** The premise held (`ServicePort` returned `Status.EnvPort`, `ownPorts` `[]`, `InternalAddress` `""`). The open question resolves to yes. Before the image is read bex runs nothing and routes nothing: `dispatchRuntime` runs only after `resolveImageNetwork` succeeds (`app_controller.go`), and `privateServiceProjection` refuses an unresolved network, so no process gets any `PORT` and no slug Service exists. Render's create is answered before anything runs too, and every read in the 26 s recording says `:10000` for `nginx`. The image read then gives 10000 again to an image that declares no port.
- **Change.** `App.ServicePort` (`lego/types/v1alpha1/image_network.go`) answers the service's own port (`PORT` or a configured primary) before the image is read, else Render's default 10000; `InternalAddress`, `OpenPorts` and REST/MCP `url` follow, and GraphQL `port`/`openPorts`/`internalAddress` with them. A web image service reads `openPorts` `[10000]` then too, as `web_service_image_cassette.yaml` does. `App.ResolvedServicePort` keeps ADR089 D4: a Blueprint `port`/`hostport` reference to an unread target stays omitted, and the Settings port stays blank. The dashboard's "Ports are detected from the image after the first build" state can no longer occur and is removed. ADR089 § Port slice decisions item 6 records the amendment; ADR018's Internal address, Open ports and Partial serviceDetails projection rows and `service-addresses.md` §3 follow. w10/m373's gate list drops the case.
- **Done when, met.** A REST create of `{"type":"private_service","name":"p","image":{"imagePath":"nginx:1"}}` answers `url` = `internalAddress` = `<slug>:10000` and `openPorts` `[{"port":10000,"protocol":"TCP"}]` (`TestRESTCreatePrivateService`). `TestResolvedServicePort`, `TestOpenPortsFollowTheServingNetwork`, `TestRenderServiceDetailsOpenPorts` and `TestGraphQLOpenPortsNullVersusPending` cover the other surfaces; `TestBlueprintPortReferencesToAnImagePortTargetNeverGuess` still holds.
- **Checks.** `cd lego/types && go test ./...`, `cd lego/backend && go test ./...`, `make test` (operator; its one failure, `TestImageNetworkLeavesLegacyServicesUnchanged`, asserted the old empty address and now asserts the default), `make lint` (0 issues), `dashboard` `yarn lint` and `yarn test` pass. With the old `lego/types` code back, `TestRESTCreatePrivateService`, `TestRenderServiceDetailsOpenPorts` and `TestPrivateServiceURLIsItsInternalAddressOnEveryOperation` fail.
