# An image service reads `imagePath` back as written (`nginx`), where Render normalizes it (`docker.io/library/nginx:latest`), so Terraform loses `image_url`

Why: Render's Terraform provider parses `image_url` and the tag out of `imagePath` only when it holds a `:` or `@`. bex echoes a bare `nginx`, so the provider reads `image_url` as null and Terraform aborts the create with "Provider produced inconsistent result after apply".

- **Found by:** w9/m474, dev-9, 2026-11-18 ([checklist](../../../docs/terraform-compatibility-checklist.md), class 6). It affects every image-service test that names a bare image (worker, cron, private and web).
- **Render:** a create with `image.imagePath: "nginx"` answers `imagePath: "docker.io/library/nginx:latest"` (`backgroundworker/resource/testdata/env_var_cassette.yaml`, `scaling_cassette.yaml`). The provider's parser is `internal/provider/common/models.go` `ImageRuntimeSource`.
- **bex:** `lego/backend/internal/apps/render.go` sets `ImagePath: a.SourceImage`, the string as written. `lego/backend/internal/store/image.go` already normalizes with `reference.ParseNormalizedNamed`; Render's form adds the default `latest` tag (`reference.TagNameOnly`) and keeps a digest.
- **Done when:** REST, GraphQL and MCP read an image service created as `nginx` back as `docker.io/library/nginx:latest` (and `ghcr.io/o/i@sha256:…` unchanged), the deployed image is unchanged, a test covers it, and `TestEnvVarsResource` (web service) gets past its first step.

## Resolution

**DONE 2026-11-18.** The app view reads the configured image through `store.RenderImagePath` (`lego/backend/internal/store/image.go`): `reference.ParseNormalizedNamed`, then `reference.TagNameOnly`. `nginx` reads `docker.io/library/nginx:latest`, and an explicit tag or digest is kept (`ghcr.io/o/i@sha256:…` unchanged). REST and MCP (`toRenderServiceWithMetadata`) and GraphQL (`imagePath`) all read `AppView.SourceImage`, so one change covers the three. The App's `spec.image`, and so the image it runs, stays as written. A provider update re-sends the configured `nginx`, so it is no spurious change.

Tests, each failing with the change reverted (`"nginx"` on all four surfaces):

- `TestImagePathReadsBackInRendersQualifiedForm` (`internal/apps/terraform_provider_test.go`) sends the provider's recorded worker create through the strict Render gate, and reads `imagePath` back from the create response, `GET /v1/services/{id}`, GraphQL `service(id)` and MCP `get_service`. It also checks the stored `spec.image`, for `nginx`, a qualified tag and a digest.
- `TestRenderImagePathQualifiesLikeRender` (`internal/store/image_test.go`) covers the normalization table. `TestRenderServiceSupportsOfficialCLICloneAndRename` now expects the qualified form.

ADR018's Get service and Terraform rows and the [checklist](../../../docs/terraform-compatibility-checklist.md) (class 6, run E) record the change.

**Live check on dev-9** (bex-api from main `dc41a1a90` plus this change, OpenFGA on, a Scale workspace and its owner's API key as minted):
