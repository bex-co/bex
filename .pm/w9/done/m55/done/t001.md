## Objective

Build the one shared mechanism every detail route will use: when a route's resource settles as **not-found** (never on **error**), redirect to a target route (default `/`) and surface a "not found" toast so the user knows why they landed home.

## Context

- All detail routes already load through `loadRouteResource` (`dashboard/src/common/lib/document-head/index.ts:106-121`), which returns a serializable `{state: "ready"|"not-found"|"error"}` and deliberately distinguishes a missing row from a failed query (`isNotFoundError`). That distinction is load-bearing: an outage/401 must keep the existing inline error/retry UI, not bounce the user to `/`.
- Two moments need covering: (a) the route **loader** settling not-found on direct visit / navigation — handle with TanStack Router's `redirect()` (works on SSR and client); (b) the **component**'s cache-first hook settling not-found after mount (e.g. resource deleted while viewing) — handle with a small client hook that `navigate({ to })`s once when the settled state is not-found.
- Toast: sonner is already mounted via `RootProvider` (`dashboard/src/common/components/ui/sonner.tsx`). New user-visible strings go through i18n (`common.*` locale keys, `dashboard/CLAUDE.md` Internationalization).
- The redirect target must be a parameter (default `/`) because t004 needs the nested deploy route to target the parent service's Deploys tab.

## Steps

1. Add a helper in `dashboard/src/common/lib/document-head/` (or a new sibling `common/lib/route-resource/` module if head/title concerns shouldn't grow) — e.g. `redirectIfNotFound(result, { to })` that `throw redirect({ to })` when `result.state === "not-found"`, for use at the end of route loaders after `loadRouteResource`.
2. Add a client hook — e.g. `useNotFoundRedirect(settledNotFound: boolean, to = "/")` — that fires `router.navigate` once and triggers the toast (i18n key like `common.resourceNotFoundToast`).
3. Decide where the toast fires so both the loader path and the hook path show it exactly once (e.g. the hook owns the toast and the loader redirect passes a search flag or the target route reads a one-shot flag — keep it simple, no new global state if a plain module-level latch or search param suffices).
4. Add `en`/`zh` locale entries for the toast copy.
5. Unit-test the helper: not-found ⇒ throws redirect to target; ready/error ⇒ no throw. Hook test: navigates + toasts once on settled not-found, never on loading or error.

## Acceptance criteria

- [ ] A loader returning `{state:"not-found"}` piped through the helper redirects to the given target on both SSR and client navigation.
- [ ] `{state:"error"}` and `{state:"ready"}` pass through untouched — no redirect.
- [ ] The client hook navigates + toasts exactly once; toast copy is i18n'd in en + zh.
- [ ] Vitest covers all three states for the helper and the hook.
