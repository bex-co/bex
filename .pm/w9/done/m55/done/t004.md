## Objective

When the service exists but the deploy id does not (`/services/<live>/deploys/<garbage>`), redirect to that service's Deploys tab — the nearest live parent — rather than all the way to `/`. Bouncing to home from inside a valid service context would be hostile; this is the one route where the redirect target is not `/`.

## Context

- `dashboard/src/routes/services.$serviceId.deploys.$deployId.tsx` → `DeployDetailPage` (`dashboard/src/features/deploys/components/deploy-detail-page.tsx:47-74`): its own `useDeploy` with a `notFound` EmptyState (`:47-55`) and a distinct `error` EmptyState (`:57-65`) that must stay.
- The dead-service-id case is already covered by t003 at the layout — this task only handles service-alive + deploy-dead.
- t001's helper/hook take a target route parameter for exactly this case.

## Steps

1. Replace the `notFound` EmptyState branch with the t001 redirect (hook and, if the route has its own loader through `loadRouteResource`, the loader helper), targeting `/services/$serviceId/deploys`.
2. Keep the `error` EmptyState and loading skeleton unchanged.
3. `yarn typecheck && yarn lint && yarn test`.
