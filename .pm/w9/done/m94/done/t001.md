## Objective

Sandboxes minted after this change carry a bex typed ID (`sbx-<xid>`, minted only via `lego/backend/internal/id`), surfaced verbatim as `Sandbox.ID`, while every read path keeps resolving pre-existing substrate UUIDs.

## Context

- Live repro 2026-09-20: `bex ea sandboxes create --plan=starter --timeout=600 -o json` → `"id": "c372c97e-980b-4573-9aae-4c82b8ad1c4b"` (substrate UUID); `bex ea sandboxes copy ./f <uuid>:/tmp/f` fails client-side: `one of <src> and <dst> must be a sandbox path like sbx-abc123:/app/file`.
- Pinned parser: `cmd/sandboxcopy.go:18` — `sandboxRemoteArg = ^(sbx-[A-Za-z0-9]+):(.*)$`; no alias, no fallback.
- Pass-through: `lego/backend/internal/sandbox/service.go` `sandboxFromOpenSandbox` copies `raw.ID` (substrate-minted, `client.go:158` `Create` → OpenSandbox `POST /sandboxes`).
- The `id` package has no `Sandbox` kind (only `SandboxExecution` `exe-`, `lego/backend/internal/id/id.go:121`); `models.go:64` already documents `sbx-<xid>`.

## Steps

1. Add a `Sandbox` (`sbx-`) kind to `lego/backend/internal/id` per the id-convention (hyphen, boilerplate header).
2. Decide the mapping point: prefer passing the minted `sbx-` ID to OpenSandbox create when the substrate accepts client IDs; otherwise persist a bex-side UUID↔`sbx-` mapping (store) and translate at the REST boundary.
3. Translate every ID read path (`sandboxFromOpenSandbox` + list/get envelopes) to the canonical `sbx-` form.
4. Dual-accept: resolve both `sbx-` IDs and legacy UUIDs on input (shared resolver, not per-route ad-hoc parsing); unmapped IDs return the existing non-enumerating `SANDBOX_NOT_FOUND` 404.

## Acceptance criteria

- [ ] `bex ea sandboxes create -o json` → `"id"` matches `^sbx-`.
- [ ] `bex ea sandboxes copy ./f <new-sbx-id>:/tmp/f` reaches the server (404 until w7/m150 ships, never the client-side `must be a sandbox path` error).
- [ ] A pre-existing UUID sandbox still resolves on get/exec/stop (or 404s cleanly — never 500).
- [ ] `go test ./...` in `lego/backend` green.

## Out of scope

- File-transfer routes/streaming (w7/m150 owns them; this milestone only unblocks addressing).
- Sandbox groups (deliberate non-goal per w7/m150's approved scope decision).
- Backfilling `sbx-` IDs onto already-minted UUID sandboxes beyond dual-accept.

## Outcome (2026-09-20)

Implemented. `ids.Sandbox` (`sbx-`) added to `lego/backend/internal/id`; the EA
create path mints the public id and stamps it as `bex.co/sandbox-id` sandbox
metadata (`service.go` `create`), so OpenSandbox stays the single source of
truth and no bex-side mapping table can drift. `canonicalID` is the one read of
an id; `resolveSandbox` dual-accepts (substrate id → direct Get, `sbx-` id →
tenant-key-scoped list match), and an unmatched id keeps the existing
non-enumerating `SANDBOX_NOT_FOUND`. The substrate never accepted a
client-supplied id, so step 2's first option was not available.
