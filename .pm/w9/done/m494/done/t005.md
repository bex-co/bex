## Done — 2026-11-19

- Render's behavior: "Render already caches well known paths for all native language environments. No other directories are cached." (Anurag Goel, feedback.render.com). A Render staff list on community.render.com names `/opt/render/project/.gems`, `nodes`, `src/.venv`, `.render`, `rubies` and `src/node_modules`. For Rust: "We're caching any target directory at your repo root." "Clear build cache & deploy" means "the new deploy doesn't reuse any artifacts generated during a previous build" (render.com/docs/deploys). Render's docs name no Go or Elixir path; bex keeps Go's module cache and Mix's `deps`/`_build` at Render's own `GOPATH` and service root.
- Every native service type gets it (web, private, worker, cron, static: the recipe is shared). No REST, GraphQL, MCP or dashboard surface changes: `clearCache: "clear"` reaches the archive through `stampClearCacheRelease` on every surface, as for w9/m492 and w9/m493.
- Recorded in [ADR018](../../../../../docs/ADR018-render-parity.md) (`Runtime, build strategy + Root Directory`) and [ADR060 D3](../../../../../docs/ADR060-build-worker-reliability-and-performance.md#d3-amendment-w9m494--native-dependency-directories-across-builds). Node's `node_modules` stays w8/m161's, which can ride the same mount and archive.
- Drift filed: [w9/127](../../127.md) (Python's `.venv`, which Render keeps) and [w9/128](../../../128.md) (a lock's newer Bundler breaks `bundle exec` at runtime, found by the drill).
