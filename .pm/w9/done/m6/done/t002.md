## Objective

Give every KeyValue a typed opaque `red-<xid>` id minted through `lego/backend/internal/id`, stored on the CR and control-plane row, with a backfill path for existing stores — the w9/m3 Postgres pattern.

## Context

- `lego/backend/internal/id` registry + guard test (docs/ADR020-identifiers.md); hyphen separator, DNS-safe.
- w9/m3's `dpg-` migration is the template (CR annotation/field + store column + backfill).
- KeyValue CRD: `lego/types` (`keyvalue_types.go`).

## Steps

1. Add the keyvalue `id.Kind` (`red-` prefix) to the registry.
2. Add the identity field to the KeyValue CR types + codegen (`make manifests generate` from lego/operator).
3. Store migration: stable id column on the keyvalue rows; backfill mints ids for existing rows/CRs.
