# Revoke per-build NetworkPolicies immediately when a build is canceled

Why: Canceling a running build leaves `bex-build/bld-<app>-datastore-egress` and `<ws>/<app>-build-ingress` in the cluster until the next build finishes or the App is deleted; revoking them on build cancel closes the last lingering NetworkPolicy leak from `w8/m129` and keeps `w9/m495`'s widened build reach tight.

- **Source:** `/pm-brainstorm for one aspect of render parity` (Build Caching & Build Environment Parity, 2026-11-18, item 5); explicitly flagged as open follow-up #3 in [w8/done/m129/README.md](../../w8/done/m129/README.md).
- **Evidence:** `lego/operator/internal/controller/build_datastore_reach.go:244-251` (`endBuildDatastoreReach`) revokes only when `phase == build.PhaseSucceeded || phase == build.PhaseFailed`, ignoring cancel settle paths in `lego/operator/internal/controller/app_controller.go:1376`.
- **Estimate:** ~45m (sub-hour inbox note; too small for a milestone).
- **Done when:** Canceling an in-flight build deletes both `bex-build/bld-<app>-datastore-egress` and `<ws>/<app>-build-ingress` on the cancel settle pass, and `lego/operator/internal/controller/build_datastore_reach_envtest_test.go` proves both policies are absent after cancel without waiting for a subsequent build.

**DONE 2026-11-19.** A settled cancel now ends the canceled build's reach on the same pass: `settleCanceledRelease` calls `endCanceledBuild` (`lego/operator/internal/controller/app_controller.go`), which stops the release's build Job as before and then `revokeBuildReach` removes all three per-build policies, `bex-build/bld-<app>-datastore-egress`, `<ws>/<app>-build-ingress` and w9/m495's `<ws>/<app>-build-service-ingress`. That covers a user's cancel, a suspend that ends the rollout (bex-api stamps the same cancel), and the build of a release a cancel settled below (`stopAbandonedBuild`). The release a cancel leaves running (`survivorInFlight`) never settles there, so its build keeps its grant until it ends. The App finalizer (`reclaimAppExecution`) now deletes both workspace halves on its first pass with the build-namespace half, instead of leaving them to garbage collection after a possibly long finalization. A timeout already revoked at the terminal observation (`endBuildReach` on `PhaseFailed`). Every delete is ownership-gated and names only this App's policies.

`build_datastore_reach_envtest_test.go` ("Build reach ends with a canceled or settled build (w9/124)") runs two Apps building in one workspace next to a Starter private service, so each holds all three policies. It cancels, supersedes and then ends, times out or deletes one of them, and checks that its three policies are gone on that pass with no later build dispatched, while the other App keeps all three. In the superseded case, the release the cancel left running keeps its grant until bex-api ends it too. With the operator change reverted, the cancel, superseded and delete specs fail, and the timeout spec passes either way. ADR022's "stale grant" row is now Closed and its w9/124 residual is gone, and ADR060's build network line names the new paths. A canceled native build's Managed OIDC token copy (`endBuildManagedOIDC`) still waits for a terminal observation. It is not a NetworkPolicy, so it was left out of this note's scope.
