## Objective

Settle where `LoginEvent` and `LogoutEvent` come from, since sign-in and sign-out happen in Kratos, not bex-api.

## Context

- Render (render.com/docs/audit-logs, read 2026-11-16), workspace member events: `LoginEvent` (member logged in), `LogoutEvent` (member logged out). Both are in the pinned enum.
- `deploy/gitops/base/values/kratos.values.yaml` has no `web_hook`; the after-login hooks are `require_verified_address`, `show_verification_ui` and `session`, and its comments note that recovery mints a session outside those hooks.
- bex-api sees a session only through Kratos `whoami` (`lego/backend/internal/api/auth.go` ~699). The dashboard signs out directly against Kratos (`dashboard/src/common/lib/ory/logout.ts`, `createBrowserLogoutFlow`). The CLI's logout goes through bex-api's authenticated logout endpoint (`lego/backend/internal/cliauth/service.go`).

## Steps

1. Confirm on the deployed Kratos version that `whoami` returns the session `id`, `authenticated_at` and `devices[]` (`ip_address`, `user_agent`).
2. Recommended: a sign-in is the first time bex-api sees a Kratos session id, timestamped at `authenticated_at`, with IP and user agent from that session's device entry. It covers every method, recovery included, and needs no Kratos change. Alternative: a Kratos after-login `web_hook` (a platform config change, and it misses recovery).
3. Recommended: write one row in each workspace the identity belongs to at that moment.
4. Recommended: `LogoutEvent` from a bex-api call the dashboard makes just before starting the Kratos logout flow, plus the CLI's authenticated logout. Kratos has no logout hook, so a session that simply expires records none; state that as a known gap.
5. Recommended: a CLI device-flow login is not a `LoginEvent`; Render documents "member logged in" without naming the client, so record it as an unverified assumption.
6. Write the decisions into ADR012 and ADR006 § Audit log, marked as recommendations.
