# A Blueprint sync that changes a service's plan records no `plan_changed` or edge-cache toggle event

Why: `apps.SetPlan` records `plan_changed`, and since w9/088 an `edge_cache_enabled`/`_disabled` toggle when the change crosses Free. A Blueprint (`render.yaml`) sync that changes `plan:` goes through `persistBlueprintIntent` (`lego/backend/internal/apps/deploy.go` ~3960) instead and records neither. The service's Events feed and webhooks miss a plan change that Render reports.

- Check what Render's events feed shows for a plan changed by a Blueprint sync (`plan_changed` with a Blueprint trigger?), and record the same through the shared recorder that w9/088 added.
- Cover it with a test that syncs a Blueprint across Free on a cached service.

## Done (2026-11-12)

A Blueprint sync, approval or deploy that changes an existing service's plan records `plan_changed`, plus the edge-cache toggle across Free, through `RecordPlanChanged`. For a managed App it records once the store row takes the new tier, so retries record once. The actor is the member, the approver, or none for auto-sync. `SetPlan` now decides by tier too.
