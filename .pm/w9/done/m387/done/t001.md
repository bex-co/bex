## Objective

Decide the repository environment: its shape (ordered setup steps, named checks), where it is stored, when it runs (phase 1: in the session's sandbox after the clone, before the agent, every turn), its limits, which secrets it sees, how it fails, and how the agent learns the checks. File phase 2 — snapshots built from the setup — as its own w9 inbox note.

## Context

- Devin: blueprint `initialize` (tools, runtimes) and `maintenance` (dependencies) run at snapshot build, not at session start; `knowledge` holds `lint`/`test`/`build` that Devin uses to verify its work; builds run when the blueprint changes and about every 24 h; repo-level commands run from the repository root; each step has a 3-hour timeout ([Blueprint reference](https://docs.devin.ai/onboard-devin/environment/blueprint-reference), checked 2026-11-13).
- bex: the workspace agent environment holds network tier, custom hosts and model only (`lego/backend/internal/agentsessions/environment.go:67-80`); every turn runs in a fresh sandbox (`docs/ADR098-agent-session-secrets.md:10`); a re-clone plus reinstall costs about 30–60 s (`docs/ADR059-agent-sandbox-hibernation.md:157`).
- The driver clones in `ensureRepo` (`lego/agent-image/driver/src/git-setup.ts:217`); `install-profiles.ts` runs only at image build.
- Divergence to record (needs the user's sign-off): phase 1 runs setup at every turn's start instead of from a prebuilt snapshot, so the per-turn wait remains until phase 2; a per-turn time limit far below Devin's build-time 3 h follows from that.
