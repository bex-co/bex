## Objective

`GET /auth/device` without a `user_code` must render dashboard auth chrome with a human message, not a bare `text/plain` 400 body.

## Context

- Live repro: `hunt-device.png` / `hunt2.json` — status 400, `content-type: text/plain`, body `missing or expired device code`, empty title.
- `dashboard/src/common/server-fn/hydra-device.ts` — `error("missing or expired device code", 400)` when `!userCode`.
- Consent already degrades missing `consent_challenge` to home (`handleConsent` → `home()`); device should at least be human-readable. Prefer AuthPageShell / DeviceConfirmPage-shaped error over a silent home redirect so a broken CLI link is understandable.
- Routes: `auth.device.tsx`, `auth.device.index.tsx`; UI: `features/auth/pages/device-confirm-page/`.

## Steps

1. Stop returning raw `text/plain` for the missing/expired user_code GET case (and review sibling `error()` call sites that a browser hits as a document navigation).
2. Hand a typed error view into the route loader/component (mirror `DeviceView` / consent pattern) or redirect to a small branded page with i18n copy.
3. Keep POST confirmations and cross-site refusals as non-HTML API-style errors where appropriate (same-origin form POSTs).
4. Add a locale string for the missing/expired device code message.
