## Objective

When a visitor with no Kratos session opens `/auth/logout` and clicks **Sign out**, do not show the red "Sign-out failed / You may still be signed in" state — treat missing/unauthorized logout flow as already signed out and send them to login.

## Context

- Live repro: Playwright `hunt4.json` — confirm Sign out → console `401` from Kratos → body "Sign-out failed…".
- `dashboard/src/features/auth/pages/logout-page/index.tsx` — confirmation UX (codex #12 CSRF logout).
- `dashboard/src/common/lib/ory/logout.ts` — `endBrowserSession()` throws on any non-OK `createBrowserLogoutFlow` / logout fetch.
- Existing tests: `dashboard/src/common/lib/ory/__tests__/logout.test.ts` (today asserts 500 keeps caches).

## Steps

1. Detect "no session" / 401 (and any Kratos "no active session" class) from `createBrowserLogoutFlow` or the logout URL fetch.
2. On that path: clear local caches the same as success (or no-op safely), then navigate to `/auth/login` — do **not** set `status: "error"`.
3. Keep true provider failures (5xx, network) on the error + retry UI (codex #6 still holds for those).
4. Extend unit tests for the 401 / no-session case.

## Acceptance criteria

- [ ] Unauthenticated `/auth/logout` → Sign out → lands on login (or already-signed-out success), never the red failure copy.
- [ ] Real logout failure (e.g. 500) still shows error + Try again and does not clear caches prematurely.
- [ ] Unit test covers the no-session / 401 path.

## Out of scope

- Changing UserNav's immediate `endBrowserSession()` path beyond shared helper behavior.
- Auto-logout on GET (still forbidden — CSRF).
