## Objective

An open Metrics tab fires ~10 independent GraphQL queries every 30s even when the tab is hidden. Add the existing `skipPollWhenHidden` gate inside the shared metrics hooks so every card is covered by one edit per hook.

## Context

- `dashboard/src/features/metrics/hooks/use-metrics.ts:150` — `pollInterval` with no `skipPollAttempt`. Call sites multiply it: `application-metrics-card.tsx:61-76` (7 calls), `network-metrics-card.tsx:122-132` (3 + filter values), `scaling-recent-metrics.tsx:49-59` (5).
- `use-datastore-metrics.ts:57` (up to 6 via `datastore-metrics-panel.tsx:64-79`) and `use-month-to-date-bandwidth.ts:24` — same gap.
- The pattern to copy: `skipPollAttempt: skipPollWhenHidden` from `dashboard/src/common/lib/polling.ts:16` (already used by the resource-list hooks).

## Steps

1. Add `skipPollAttempt: skipPollWhenHidden` in `use-metrics.ts`, `use-datastore-metrics.ts`, and `use-month-to-date-bandwidth.ts`.
2. Grep `pollInterval` across `dashboard/src` and confirm every remaining ungated occurrence is owned by t002/t003 (deploy/usage) — anything else found, gate it here and note it.
3. Manual check: Metrics tab open, background the tab, devtools network quiet; foreground, polling resumes.
