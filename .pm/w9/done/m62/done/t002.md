## Objective

The deploy detail page blank-waits on the header `deploy` query before mounting the timeline and log panels (whose queries then start a full round trip later), and while a build is in flight it fires ~5 requests every 3–5s even from a hidden tab. Start the regions in parallel and gate the pollers on visibility.

## Context

- `dashboard/src/features/deploys/components/deploy-detail-page.tsx:76` — returns a skeleton until `loading || !deploy`, so `DeployTimeline` + `DeployLogPanel` (and their queries) don't mount until the `deploy` query resolves. The children need `deploy.createdAt`/`finishedAt` as their window — they can mount immediately and accept an `undefined` window (render their own skeletons, fire as soon as the window arrives, or fire windowless where the query allows).
- Ungated pollers: `use-deploy.ts:54` (3s), `use-deploy-timeline.ts:49` (3s), `use-deploy-logs.ts:74` (5s × up to 3 legs). Terminal settling already works (stopPolling on terminal / `endTime` / 15s settle) — keep it.
- Gate pattern: `skipPollAttempt: skipPollWhenHidden` (`common/lib/polling.ts:16`).

## Steps

1. Add the visibility gate to the three deploy hooks.
2. Restructure `deploy-detail-page.tsx` so timeline + log panels mount unconditionally with their own loading skeletons; verify no query fires with a nonsense window (guard with `skip` until the minimum inputs exist, but don't serialize behind the full header render).
3. Manual check on dev-9: open an in-flight deploy — header, timeline, and logs load in parallel; background the tab mid-build — network quiet; foreground — resumes; terminal deploy still settles its polling.
