# A native build prints only Render's version line, not the `Docs on specifying …`, `Requesting Node.js version …` and Go lines Render prints around it

Why: w9/139 gave bex's native version narration Render's exact `==> Using <Name> version <v> …` form, but Render's build logs carry more lines around it that bex does not print, so a log read side by side with a Render build of the same repository still differs.

- **Found by:** w9/139's worker, 2026-11-21 (fe19f4e05a). Its sources (public Render build logs in GitHub issues and PRs, Render's community forum and feedback board) are quoted in `docs/render-artifacts/native-version-narration.md`.
- **Render prints, bex does not:**
  - a `==> Docs on specifying a <runtime> version: https://render.com/docs/…` line after each version line;
  - a `==> Requesting Node.js version <range>` line before the version line when `engines.node` names a range;
  - a Go version line, whose only public capture (2023) includes the raw output of `go version`, which only the build step knows.
- **bex:** `NativeChoice.NarrationIn` in `lego/operator/internal/build/nativeversion.go` and the resolve entrypoint's narration; Go's toolchain step.
- **Done when:** each line whose Render form `native-version-narration.md` cites prints in the same place and wording on bex, with unit tests per runtime; a line with no current public capture (Go's, if 2023's is all there is) stays out and is named as unmeasured in ADR018's runtime row.
- Filed by the `/loopx w9` orchestrator from w9/139's result.

**Render's lines captured (2026-11-21):** [docs/render-artifacts/native-version-narration.md](../../../docs/render-artifacts/native-version-narration.md) § Lines around the version line quotes them from published build logs (GitHub issues, Render's community forum through the Wayback Machine, the Elixir forum). No Render account was used. After each runtime's version line Render prints its docs line, such as `==> Docs on specifying a Ruby version: https://render.com/docs/ruby-version`. The logs show it after a default, an environment variable and a version file alike. Bun's reads `a Bun version` since 2025 (`a bun version` in 2024), and Elixir and Erlang share `==> Docs on specifying Elixir and Erlang versions: https://render.com/docs/elixir-erlang-versions` after the Elixir line. A Node range or alias is echoed first, as written: `==> Requesting Node.js version >= 20.4.0` (`engines.node`), `20.x` (`NODE_VERSION`), and `lts/*` (`.nvmrc`, in the wording from before the rename). An exact version is not echoed (`NODE_VERSION=22.22.3`, 2026-06-12). Go's 2023 line is still the only one on record, and no docs line follows it.

**Fixed 2026-11-21 (loopx w9):** `NativeChoice.NarrationIn` (`lego/operator/internal/build/nativeversion.go`) prints the request line, the version line, then the runtime's docs line (`renderDocs`), with bex's own notes after it, where Render's `Installing …` line goes. The docs line follows bex's own line for an unmeasured signal too, and Go and Rust get none. `renderNodeRequest` echoes a Node range or alias from any Node signal (trimmed, cut at 120 characters). It echoes no plain version. **Unmeasured, named in ADR018's runtime row:** Go's line; any Rust line; whether Render echoes a partial Node version (`22`); and the current wording for an alias. `TestNativeChoiceNarration` covers every runtime with its docs line, the Node request for a range, an alias, `engines` as written and an exact version, the note order and a declined companion. `TestRunEchoesANodeRangeBeforeItsVersion` (`cmd/native-resolve`) covers the entrypoint's output. Tests that pin exact narration now expect the docs line. With the docs line off, 22 tests fail (98 counting subtests). With the request line off, 4 fail (12 with subtests). Echoing plain versions too fails 4 (10 with subtests). No CI workflow or script pins these lines. Local Docker was hung, so the suites ran with a fail-fast `docker` shim on `PATH`. The next production native build prints the new lines; no live check was run here.
