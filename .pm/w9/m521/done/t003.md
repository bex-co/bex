## Objective

`cliCommand`, and `redisCLICommand` on `/v1/redis`, take Render's shape. For a public store that is ` REDISCLI_AUTH=<password> valkey-cli --user <user> -h <externalHost> --sni <externalHost> -p 6379 --tls`:

- the leading space keeps the command out of shell history under `HISTCONTROL=ignorespace`;
- the password travels in the environment, not in argv, where `ps` would show it;
- the `--sni` placement keeps Render's ` -p <port> --tls` tail.

## Context

- `lego/backend/internal/keyvalue/service.go:1465-1480` builds today's `redis-cli -u …` and `redis-cli --sni <host> -u …`. The `/v1/redis` spelling is at `rest.go:156-190`.
- valkey-cli 8.1.1 sends a TLS server name only with `--sni` (`src/cli_common.c:111`, `src/valkey-cli.c:2799`), and bex's shared kv-sni-proxy routes only by it (ADR021, the `redis-cli --sni` paragraph). valkey-cli reads `REDISCLI_AUTH` (`src/valkey-cli.c:87`).
- The Render CLI's `kv-cli` (`render-oss/cli` `pkg/tui/views/rediscli.go`, `loadDataRedisCLI`) splits `cliCommand` on spaces. The words before `valkey-cli`/`redis-cli` become the process's whole environment, and the words after it its arguments. When `valkey-cli` is not installed it runs `redis-cli` with the same arguments.
- Render has no private-store form: every Render store has the external endpoint. For a bex private store, use the same shape over the internal host:
  - ` valkey-cli -h <id> -p 6379` while the internal URL is credential-free;
  - ` REDISCLI_AUTH=<password> valkey-cli --user <user> -h <id> -p 6379` with internal authentication.

## Steps

1. Build both forms in one place, from the user, host, port and password, never by splicing a URL.
2. Run the public form verbatim against a dev-9 store with an allow-listed source, with both `valkey-cli` and `redis-cli`, and get `PONG`.
3. Run `bex kv-cli <id>` (the pinned Render CLI) against it and get `PING`/`PONG`. Record the run in the [CLI checklist](../../../../docs/cli-compatibility-checklist.md) `kv-cli` row (`scripts/cli-compat.sh kv-cli-verify` where it applies).
4. Amend ADR021's `redis-cli --sni` paragraph.

## Done (2026-11-19)

- `TestCLICommandRunsAsTheRenderCLISplitsIt` replays the pinned CLI's `loadDataRedisCLI` split for the three forms, with a password that starts with `-`: the environment is exactly `REDISCLI_AUTH`, and no password reaches argv. The kv-cli diagnostic sanitizer now redacts `REDISCLI_AUTH=…`.
- dev-9: both private forms, run verbatim from a pod in the store's workspace, answered `PONG` (the credentialed one as the store's id, `ACL WHOAMI`).
- The public form needs an issued certificate and the shared edge, which dev-9 lacks. Running it verbatim with valkey-cli and redis-cli, and `bex kv-cli`, is t006 step 2 on production.
