# 132 — The API keys table is wider than its card on Account Settings, so a key's revoke button starts off-screen, and the loading frame is narrower than the table it stands for

Why: on a 1,280 px desktop window the API keys panel scrolls sideways with one key in it: Last used and the revoke button sit past the card's right edge, so revoking a key needs a horizontal scroll nobody expects, and the panel's loading frame (which fits the card) is a different width, and at desktop a different header height, from the ready table.

- **Source:** w9/m514 t004/t006 browser pass on dev-9, 2026-11-19 (headless Chromium, signed in as a Viewer and as a Developer of a Scale workspace, the `apiKeys` query held to catch the pending state). Unchanged by m514: the table and its frame are the w4/686 and w9/m496 components, the same for every role.
  - The card is 694 px wide at a 1,280 px viewport (356 px at 390 px). The card header (title, description, Create) is the same size pending and ready at both widths, for both roles.
  - The ready table is 769 px wide for a key named `m514-geom-viewer` (778 px for a Developer seeing two keys), so it overflows the card; the pending frame's table is 654 px wide at 1,280 px and 568 px at 390 px. At 1,280 px the pending header row is 36 px tall and the ready one 41 px.
  - A key name wraps to three lines (`m514-` / `geom-` / `viewer`) while the client id, created-by email and Last used keep their width.
