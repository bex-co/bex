## Objective

Round-trip each native runtime's dependency cache directory through the S3 build-cache phases (`<tea-id>/<app-uid>/deps-cache.tar.zst` + metadata) with toolchain-key checking, size bounds, and `clearCache: "clear"` purge.

## Context

- Reuses the S3 cache bucket, credentials, and named BuildKit context pattern established by w9/m492 and w9/m493.
- BuildKit remains 100% credential-free; only `cache-restore`, `cache-purge`, and `cache-save` touch S3.

## Steps

1. In `cache-restore`, read `<tea-id>/<app-uid>/deps-cache.meta.json`; when its toolchain+arch key matches the current build (and `!SkipCacheImport`), download and safely extract `deps-cache.tar.zst` into a dedicated named BuildKit context. On mismatch, miss, or error, leave the context empty and log a concise notice.
2. In `native.go`, copy/seed the restored runtime dependency directory before running the authored build command and export the updated dependency directory to the cache-out volume after the build succeeds.
3. In `cache-save`, archive and upload `deps-cache.tar.zst` + `deps-cache.meta.json` within the configured size cap; in `cache-purge` (`SkipCacheImport`), delete both objects.
4. Emit `kind="deps"` on `bex_build_cache_bytes` and `bex_build_cache_phase_seconds`.

## Acceptance criteria

- [ ] Matching toolchain+arch builds restore and reuse the cached dependency directory across source-only commits.
- [ ] Mismatched toolchain versions or `SkipCacheImport` start cold without error and overwrite with the new cache.
- [ ] Oversized or corrupt archives degrade cleanly to a cold build without failing the deploy.
