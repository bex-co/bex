# A disabled autoscaling criterion reads back percentage 0, where Render keeps the percentage that was sent

Why: Render's Terraform provider sends both criteria with their percentages (`memory: {enabled: false, percentage: 70}`) and stores the response. bex answers 0 for the disabled one, so the apply aborts with "Provider produced inconsistent result after apply: .autoscaling.criteria.memory.percentage".

- **Found by:** w9/m474, dev-9, 2026-11-18 ([checklist](../../docs/terraform-compatibility-checklist.md), class 7). It hits the worker, private-service and web-service autoscaling tests.
- **Render:** `backgroundworker/resource/testdata/scaling_cassette.yaml`. The create carries `criteria: {cpu: {enabled: true, percentage: 60}, memory: {enabled: false, percentage: 70}}`, and the response and `PUT …/autoscaling` echo `memory.percentage: 70`.
- **bex:** `lego/backend/internal/apps/render.go` `setAutoscalingRequestFromRender` keeps a percentage only for an enabled criterion, and `renderAutoscalingConfigFromView` answers `{enabled: false, percentage: 0}` for the other.
- **Done when:** a disabled criterion's percentage is stored and read back on create, `PUT …/autoscaling` and GraphQL/MCP, scaling still ignores it, a test covers it, and `TestWebServiceResource_Autoscaling` gets past its first step.
