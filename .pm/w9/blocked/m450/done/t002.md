## Objective

The REST audit log answers Render's optional `actor.email` for a person, and `metadata.source_ip`/`metadata.user_agent` when the row has them.

## Context

- Pinned `auditLogActor`: `{type, email?, id?}`, `email` "Email address of the actor (if applicable)". Render's CSV `actor` column is "user email, or a deleted user's ID".
- `renderAuditActor` omits email by design ("the audit row deliberately stores only the subject (redaction-by-structure)", `lego/backend/internal/audit/rest.go` ~53-61). The `usr-` id is already resolved at read time through `Service.UserIDs` (`core.UserIDLookup`, w5/m277).

## Steps

1. Add an email lookup seam beside `UserIDs`, batched per page, resolving a `user` actor's subject to the identity's email. Storage keeps only the subject.
2. Omit `email` for `rest_api`/`system` actors and when the identity no longer exists (a deleted user keeps the `usr-` id only).
3. Emit `metadata.source_ip`/`metadata.user_agent` only when non-empty.

## Files

- `lego/backend/internal/audit/rest.go`, `lego/backend/internal/audit/service.go`, the composition root wiring the lookup, tests

## Acceptance criteria

- [x] A session-authenticated row answers `actor: {type: "user", id: "usr-…", email}`; an API-key row has no `email`; a deleted user's row has the id only.
- [x] The REST response validator against the pinned `auditLog` schema is green.
