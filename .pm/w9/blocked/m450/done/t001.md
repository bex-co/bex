## Objective

Every audit row written for an HTTP request (REST, GraphQL, MCP) stores the caller's source IP and user agent; rows with no request (sweeps, webhooks, operator commands) store neither.

## Context

- Render's audit log adds "`source_ip` and `user_agent` metadata for audit events when available" (render.com/docs/audit-logs, read 2026-11-16; changelog 2026-03-25).
- `audit_events` has no such columns (migrations under `lego/backend/internal/store/migrations/`). The write side is `core.Base.Audit` with `core.AuditEvent` (`lego/backend/internal/core/audit.go` ~49).
- Trusted client IP: `core.TrustedProxies.ClientIP` (`lego/backend/internal/core/clientip.go`), the same trust list the rate limiter uses (`lego/backend/internal/api/ratelimit.go`), so a spoofed `X-Forwarded-For` from an untrusted peer is ignored.
- Migration numbering: take the next free number at write time; `0281` was claimed by w9/m448's in-flight work on 2026-11-16.

## Steps

1. In bex-api's HTTP stack, derive the client IP and the `User-Agent` (truncated to a bounded length, e.g. 512 bytes) once per request and put them on the context.
2. Add `SourceIP`/`UserAgent` to `core.AuditEvent`, filled where the event is built from the context; add nullable `source_ip`/`user_agent` columns and write them.
3. Leave system rows empty.

## Files

- `lego/backend/internal/api/` (request middleware), `lego/backend/internal/core/audit.go`, `lego/backend/internal/store/` (new migration, audit insert/select), tests

## Acceptance criteria

- [x] Rows from REST, GraphQL and MCP requests carry both values; system rows carry neither.
- [x] An untrusted peer's `X-Forwarded-For` never becomes the source IP (unit test); an over-long user agent is truncated.
