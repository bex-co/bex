# 081 — Approval mode for codex sessions: gate in-sandbox risky commands

Why: ADR100 gates risky actions for claude sessions, but a codex session in `risky`/`all` mode still runs `sudo` or force-pushes inside the sandbox without asking. That makes the workspace setting misleading for codex users.

- codex-acp 1.4.0 applies its own approval policy per turn from the session mode. The default `agent` mode is on-request plus workspace-write, and `CODEX_CONFIG` cannot override it. So it only sends `session/request_permission` for out-of-sandbox actions (ADR100, "Production finding and fix").
- Options to evaluate:
  - switch the ACP session mode to codex's read-only/"untrusted" mode via `session/set_mode` for non-autonomous sessions, if codex-acp exposes one that asks per command;
  - or gate at the driver through a codex exec hook, if available.
- Verify with the opt-in real-adapter harness: `lego/agent-image/driver/test/real-adapter-approval.test.ts` has the pattern.
- Until then the dashboard and API should say approvals cover claude only. Check where the approval picker is shown for a codex agent.

## Implemented (2026-11-06)

- **Cause:** codex-acp 1.4.0 forces its mode's approval policy every turn (`dist/index.js` AgentMode ~26423–26516, `sendPrompt` ~27561), so on-request asks only for out-of-sandbox actions.
- **Fix:** the driver writes codex exec-policy `prefix_rule(... decision = "prompt")` rules into `$CODEX_HOME/rules/bex-approval.rules` before spawning codex in risky/all sessions, and removes them for autonomous ones. Codex then asks for every matching command whatever the per-turn policy, and the driver's risky-command table decides.
  - risky: every program the table can match.
  - all: every PATH executable except a read-only list.
- **Tests:** verified end to end against the real codex-acp 1.4.0 and codex 0.147.0 (opt-in `test/real-codex-approval.test.ts`, 5 cases). `test/codex-rules.test.ts` pins table↔rules coverage.
- **Limits** (ADR100): in all mode, programs not on PATH at session start are not caught; risky prompts only for listed programs.

## Parked (2026-11-06)

- **Then:** run a codex session in risky mode on production told to run `sudo true`, and expect `needs_input`/approval; deny it, and expect "rejected by user". The code is shipped in 5ffbe82b3.
