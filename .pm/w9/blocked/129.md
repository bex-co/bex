# A service read carries no `serviceDetails.previews`, where Render reads `{"generation":"off"}`, so Terraform's `previews = { generation = "off" }` aborts the apply

Why: Render's own provider example (`examples/resources/render_background_worker/resource.tf`) writes `previews = { generation = "off" }`. On bex that configuration creates the service and then fails, because the read-back has no previews to match it.

- **Found by:** w9/m472 t005 on production pin `4b2cebd0bd03`, 2026-11-19, as the QA user in `bex-canary`, with Terraform 1.17.2 and `render-oss/render` v1.9.1.
  - A `render_web_service` (image `docker.io/library/nginx:latest`, `previews = { generation = "off" }`) got `POST /v1/services` 201 (`srv-dbvdb2nh83kc738vm2n0`).
  - Terraform then aborted: _Provider produced inconsistent result after apply: .previews.generation: was cty.StringVal("off"), but now null_.
  - `terraform destroy` removed the tainted service, and `GET` answered 404.
  - With no `previews` block (t005's own run), apply and a second plan are clean, because the attribute is optional and computed.
- **Render:** the provider's 46 cassettes at `06af456` hold 300 service responses with `serviceDetails.previews: {"generation":"off"}` and 22 each with `automatic` and `manual`. Counted per package:
  - web service 64, private service 113, background worker 113 and static site 12;
  - cron job 0, since Render's cron details have no previews.
  - The same responses carry `pullRequestPreviewsEnabled` (`"no"`, or `"yes"` on the previews tests).
  - The static site test checks `previews.generation` = `off` after its update step (`staticsite/resource/resource_test.go:113`).
- **bex:** `lego/backend/internal/apps/render.go:495` `renderServiceDetails` never emits `previews` or `pullRequestPreviewsEnabled`. bex builds no previews (`.pm/DO_NOT_DO.md`, PR preview environments), so the true value is always `off` / `"no"`. w9/m472 t001 already accepts `{}` and `off` on create and PATCH.
- **Provider:** `internal/provider/common/previews.go` `PreviewsToPreviewsObject` maps a missing `previews` to a null `generation`, and `webservice/models.go:76` stores it.
- **Done when:**
  - Every Render-shaped read of a web service, private service, background worker or static site answers `serviceDetails.previews: {"generation":"off"}` and `pullRequestPreviewsEnabled: "no"`: REST get, list and PATCH responses, and MCP `get_service`. Cron jobs answer neither, as on Render.
  - A test covers the read, and ADR018 records it.
  - On production, the same `previews = { generation = "off" }` configuration applies, plans clean and destroys.

**Fixed 2026-11-20 in `c346a2e7e` (loopx w9):** `renderServiceDetails` now emits `previews: {"generation":"off"}` and `pullRequestPreviewsEnabled: "no"` on web, private, worker and static reads, and neither on a cron job. That covers the REST create, get, list and `PATCH` answers and MCP `get_service` and `list_services`. Render's cassettes at `06af456` were recounted for every generation bex accepts: 283 web, private, worker and static responses read `off` with `"no"`, and 78 cron responses carry neither. `TestServiceReadsStateRendersPreviewsOff` replays the provider's recorded creates and updates for each type, with `{}` and with `off`, through the strict Render gate. With the fix removed, every subtest of the four preview-bearing types fails. The shared CLI clone goldens (`lego/cli/testdata/*-clone-source*.json`) now carry the key, so `services create --from` copies `off`, which bex accepts. ADR018 (PR previews and Terraform rows) and the Terraform checklist (class 12, fixed) record it.
