# 078 — `outcome.cost.sandboxSeconds`: attribute sandbox compute to a session

Why: ADR094 D7 sketches `cost: {modelUSD, sandboxSeconds}`. m260 shipped `modelUSD` only, because there is no honest per-session sandbox figure: sandbox compute is metered per OpenSandbox sandbox in weighted milli-vCPU seconds (`sandbox_meter_states`, `usage_hourly` rows keyed by sandbox id) and every turn runs in a fresh sandbox whose id the session does not keep.

- Decide the unit first: metered weighted seconds (what is billed) or wall-clock seconds the sandbox was running; the ADR example says "seconds" but the bill is weighted.
- Needs a durable session-to-sandbox attribution (for example a `session_id` on `sandbox_meter_states`, set at dispatch) before the meter can be summed per session. Then add `sandboxSeconds` next to `modelUSD` in `agentsessions.Cost` on all three transports and amend ADR094 D7's "As built".

## Moved from w21/006 to w9/078 (2026-11-05): still a user decision

**Decision needed (owner: user).** Should `outcome.cost` expose sandbox compute at all, and if so in which unit?

**Recommendation, with Devin as the reference.** Devin shows a single consumption figure per session (ACUs), with no separate compute seconds. Report sandbox compute folded into **one USD total** in `outcome.cost`, alongside the existing `modelUSD` (e.g. `computeUSD` and `totalUSD`, priced from the existing `sandbox_compute_seconds` meter). Do not expose a raw `sandboxSeconds`.
- Customers get one number to compare against their bill.
- It needs a per-session attribution of sandbox compute, so the billing-adjacent schema change (session ↔ sandbox meter attribution) is still required, and is the part that needs the user's approval.

**Alternatives.**
- Wall-clock seconds the sandbox ran: easy to compute, but it is not what is billed.
- Weighted milli-vCPU seconds: what is billed, but opaque to customers.
- Leave cost as model USD only (status quo).

**Release condition.** The user picks the option. The worker then files the implementation milestone.
