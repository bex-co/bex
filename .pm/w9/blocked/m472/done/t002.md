## Objective

`POST /v1/webhooks` with `"eventFilter": null`, which Render's Terraform provider sends for a `render_webhook` with no `event_filter`, creates an all-events webhook instead of answering `400 WEBHOOK_EVENT_FILTER_REQUIRED`.

## Context

- Provider: `internal/provider/webhook/resource/resource.go:68` builds a nil `webhooks.EventFilter`, serialized as `null` (no `omitempty`, `internal/client/webhooks/webhooks_gen.go:20`).
- Render: `internal/provider/webhook/resource/testdata/*_cassette.yaml` records the create `{"enabled":true,"eventFilter":null,…}` answered `201` with `"eventFilter":null`, and reads answering `"eventFilter":null`.
- bex: `lego/backend/internal/webhooks/rest.go:172` refuses a nil filter; the pinned create-webhook schema does not mark `eventFilter` nullable (`api/render_openapi.go:549` `widenWebhookEventFilter` already clones it). bex reads an all-events webhook back as `[]` (`webhooks/rest.go:46`).

## Steps

1. Mark the create (and PATCH, if Render's recording shows it there too) `eventFilter` nullable in `widenWebhookEventFilter`.
2. Store `null` as the same all-events subscription an explicit `[]` gives.
3. Check with the provider whether reading back `[]` for a webhook created with `null` causes a diff on the next plan. If it does, answer `null` for such a webhook (record the distinction); otherwise keep `[]` and note why.

## Files

- `lego/backend/internal/webhooks/rest.go`, `lego/backend/internal/api/render_openapi.go`, tests

## Acceptance criteria

- [x] A create with `eventFilter: null` answers `201` and the webhook receives every event type.
- [x] Omitting `eventFilter` entirely keeps today's behavior (record whether Render's provider ever omits it).

## Out of scope

- GraphQL/MCP webhook creation (unchanged; the Render parity task confirms).

## Result (2026-11-18)

- The Render request gate marks `create-webhook`'s `eventFilter` nullable (`nullableProperties`, `lego/backend/internal/api/render_openapi.go`). The handler keeps `eventFilter` raw (`lego/backend/internal/webhooks/rest.go`): `null` decodes to no types, which `Create` stores as the same empty all-events filter `[]` gives. The worker delivers every event type to an empty filter (`TestEmptyFilterSubscribesToNewlyIntroducedEvents`).
- **Read-back (step 3):** kept `[]`. The provider's `WebhookFromClient` (`internal/provider/webhook/models.go`) loops over the list, so `[]` and `null` both become an unset `event_filter`, and the next plan has no diff. t005 confirms it live.
- **Omitted:** the provider never omits the key (`WebhookPOSTInput.EventFilter` has no `omitempty`). An omitted filter is still `400 WEBHOOK_EVENT_FILTER_REQUIRED`.
- **PATCH:** no Render recording PATCHes a webhook, so `update-webhook` stays non-nullable. The provider does send `"eventFilter": null` on every update of such a webhook; filed as w9/103.
- Tests: `TestRenderRESTCreateWithNullEventFilterSubscribesToEveryEvent` (webhooks) and `TestRenderValidatorAcceptsTerraformProviderNulls` (api). Both fail with the fix reverted.
