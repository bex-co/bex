## Objective

Accept JSON `null` for the optional list fields Render's recorded requests send as `null`, treating each as omitted, as bex already does for `buildFilter`'s lists (`nullableBuildFilterLists`, w8/m54).

## Context

- Render accepted these nulls in the provider's recordings: `POST /services` with `"envVars":null`, `"secretFiles":null`, `"serviceDetails.routes":null`; `POST`/`PATCH /postgres` with `"readReplicas":null` (all answered 2xx).
- bex validates every Render request against the pinned schema (`api/render_openapi.go`), where these properties are not nullable, so kin-openapi refuses `null`; `applyRenderSchemaCompatibility` (`:487`) already widens `buildFilter` for the same reason.
- Whether the provider at tip still sends each of these as `null` is not confirmed statically (its request structs use pointer + `omitempty`); Render's acceptance is what makes this a parity item either way.

## Steps

1. Extend the schema compatibility pass to mark these properties nullable on create-service, update-service, create-postgres and update-postgres (clone the components, as `nullableBuildFilterLists` does, so responses stay non-null).
2. Confirm each domain decoder reads `null` as omitted (`*[]…` nil), not as a clear.
3. Test each null on its operation.

## Files

- `lego/backend/internal/api/render_openapi.go`, `lego/backend/internal/apps/rest.go`, `lego/backend/internal/postgres/rest.go`, tests

## Acceptance criteria

- [x] Each of the four nulls is accepted and changes nothing.
- [x] Responses keep their non-null lists (the shared response components are untouched).

## Out of scope

- Nulls Render's recordings do not show it accepting.

## Result (2026-11-18)

- `applyRenderSchemaCompatibility` marks nullable, on request-only copies, the following: `create-service` `envVars` and `secretFiles`, a static site's `serviceDetails.routes` (the `staticSiteDetailsPOST` anyOf branch is cloned), and `create-postgres`/`update-postgres` `readReplicas`. `nullableBuildFilterLists` now uses the same `withNullableProperties` helper.
- The domain decoders already read each `null` as omitted (`[]envVarInput`, `[]secretFileInput`, `[]StaticRouteView`, `[]ReadReplicaInput`, PATCH `*[]ReadReplicaInput`), so a PATCH null leaves the replica set unchanged.
- `update-service` gained nothing: its recordings carry only the `buildFilter` nulls, which w8/m54 already accepts.
- Evidence: all 108 recorded create and update bodies to `/v1/services`, `/v1/postgres`, `/v1/webhooks`, `/v1/key-value` and `/v1/redis` that Render answered 2xx now pass the request gate. Before, 21 were refused at `/envVars`, 8 at `/readReplicas` and 1 at `/eventFilter`.
- Tests: `TestRenderValidatorAcceptsTerraformProviderNulls` and `TestTerraformProviderNullsLeaveSharedSchemasStrict`. The second checks that the PUT `/env-vars` body, `readReplicasInput`, `staticSiteDetailsPOST.routes` and `update-webhook`'s `eventFilter` stay non-null. Both fail with the fix reverted.
