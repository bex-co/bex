## Objective

Check every surface this milestone touched (REST, GraphQL, MCP, dashboard, CLI) for consistency, compared with the reference product (Devin for agent surfaces, render.com for hosting); record matches and deliberate divergences in the README, file drift.

## Done (2026-11-06) — parity check against Devin

Devin's reference for scripted and CI use is the v3 sessions API. Devin's own `devin` CLI is a local agent, not a cloud-session client. `bex agent` is compared with that API:

| Devin v3 create / session op | `bex agent` |
| --- | --- |
| `prompt`, `repos`, `title`, `tags` | `run <task>`, `--repo`/`--branch`, `--title`, `--tag` |
| `attachment_urls` | `--attach FILE` (uploaded, ADR095) |
| `secret_ids`, `session_secrets` | `--secret`, `--secret-from-env` (ADR098) |
| `structured_output_schema` | `--output-schema` |
| `max_acu_limit` | `--max-spend` (USD, ADR094 D8) |
| `playbook_id` / `knowledge_ids` | **gap:** `--skill name[:args]` lands with w9/m175 (ADR099 D4) |
| `bypass_approval` | **gap:** `--approval-mode` / `--bypass-approval` lands with w9/m176 (ADR100 D3) |
| messages (`POST …/messages`) | `send` |
| poll `status` / `status_detail` | `wait` (exit codes by state, including 5 needs input) |
| attachments read | `files --download` |
| terminate / archive | `cancel` (archive stays dashboard/API only) |

- REST, GraphQL and MCP are untouched by this milestone. The CLI rides the REST contract, so there is no adapter drift.
- The two gaps are added as CLI tasks to m175 and m176, which own those request fields. There is no separate follow-up note.
