## Objective

A build source delete writes exactly one audit row, Render's `DeleteBuildSourceEvent`, once the source is gone and naming it. It writes no `DeleteServerEvent` for the App that carries the source, and no success row for a delete refused because a service is still linked.

## Context

- Found by t010's production replay (2026-11-18): deleting build source `bds-dbulo7g7ud6s739sdnng` in `bex-canary` wrote `DeleteBuildSourceEvent` and also `DeleteServerEvent` with `metadata.service` and `targetName` both `bds-dbulo7g7ud6s739sdnng`. Render's audit log has only the build-source event for this action.
- t002 moved `apps.Service.Delete`'s allowed row to after the delete and skips it only when the caller deferred allowed rows. `DeleteBuildSource` (`lego/backend/internal/apps/build_sources.go`) did not defer, so the carrier's delete recorded `apps.Delete`. Its own row was written when it was authorized, before the linked-service check, so a delete refused with `BUILD_SOURCE_LINKED` (409) still wrote a success row.

## Steps

1. Authorize `DeleteBuildSource` with deferred allowed rows, so the carrier's `Delete` records nothing.
2. Once the delete succeeds, record `apps.DeleteBuildSource` with the source's workspace, `service:bds-…` target and name. Skip it when the caller itself deferred allowed rows, as the undo of an unrecorded create does.
3. Add a regression test.

## Acceptance criteria

- [x] `TestBuildSourceDeleteRecordsOneNamedRowOnlyOnceItIsGone` (`lego/backend/internal/apps/create_audit_test.go`) checks four things. A delete refused for a linked service records nothing. A successful delete records exactly one row (`apps.DeleteBuildSource`, `workspace:tea-a`, `service:<bds id>`, `targetName` "Mono"). A denied delete records its denial. The undo test (`TestBuildSourceCreateRecordsOneNamedRowOnlyForASourceThatExists`) still sees no delete rows.
- [x] The test fails on the code before the fix (the refused delete's success row). It also fails when `Delete` records regardless of the deferral, reporting "recorded 2 rows".

**Done 2026-11-18:** the fix is in `DeleteBuildSource`. `apps`, `audit`, `core` and `api` unit suites pass. The production check of a build source delete runs with t010's replay, once the pin carries this commit.
