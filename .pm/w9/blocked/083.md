# 083 — A service linked to a private image build source cannot pull the image

Why: a linked service deploys its build source's external image, but its pods carry only the service's own registry pull secret. A private image therefore fails to pull, even though the build source has the credential.

- Found by the w9/m180 production fix (2026-11-08). `lego/operator/internal/controller/app_controller.go:2125` `imagePullSecrets(app, image)` adds only `app.Spec.ExternalRegistryPullSecret`.
- Port discovery now reads with the carrier's credential (`externalImageCredentials`, `image_network.go:157`), but the kubelet pull does not.
- The carrier and the service share the workspace namespace, so the pod can reference the carrier's `ExternalRegistryPullSecret` directly.
- Fix options:
  - pass the carrier's pull secret when the deployed image is `Spec.BuildSource.Image` (resolve the carrier with ctx at the five `imagePullSecrets` call sites);
  - or project the carrier's secret name into `spec.buildSource` (CRD field, backend projection, codegen).
- Done when a web service linked to an image build source with a private image (registry credential set on the source) deploys `live` on production, with an operator test covering the pull secrets.

## Implemented (2026-11-08, 95f1e1f39)

When the deployed image is the linked carrier's external image, the Deployment, cron pod template and pre-deploy Job reference the carrier's `ExternalRegistryPullSecret` (`withLinkedSourcePullSecret`, `image_network.go`), without duplicates. Unlinked apps and git-built sources are unchanged. Tests: `TestLinkedServicePullsAPrivateSourceImageWithTheSourceCredential` (fails without the fix) and `TestLinkedSourcePullSecretSkipsPlatformBuildsAndMissingSources`.

## Parked (2026-11-08)

- **Gate:** the live check needs a private image and a registry credential that can read it, stored in the QA workspace (`bex-canary`). The worker has none of its own and must not store the operator's personal GitHub token in production on its own.
- **Owner:** the user. Provide or authorize a read-only credential, for example a fine-grained GHCR read token for one private test package, or a private test image with its credential.
- **Then:** link a web service to an image build source using it, and expect the deploy to go `live` (no ErrImagePull). Delete the fixtures.
