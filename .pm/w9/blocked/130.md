# 130 — A person's OAuth-token audit rows export as their raw Kratos subject, where the table names them by email

Why: the CSV export and REST name the QA user `c73bb20d-…`, an internal Kratos subject no other surface shows, on every row they caused through `bex login`'s OAuth token, while the dashboard table names the same rows by email. The table and the export still name one person two ways (w9/101's Why), on 935 of 2,222 rows in `bex-canary` over three days.

- **Source:** w9/101's production check, 2026-11-19, pin `4b2cebd0bd03`. In `bex-canary` (`tea-daif693dqjvc73e7as3g`), from 2026-11-17 00:00Z to 2026-11-19 11:10Z, Workspace Settings → Audit Log and its **Export as CSV** agree on every row's actor except the QA user's OAuth-token rows (`metadata.oauthClientId` `429024F5E608930E2A65EF92591A25CC`, the CLI's). For example REST row `aud-dbvctsgnl4hs73cv7qe0` (`LogoutEvent`, 2026-11-19 10:26:58Z) reads `actor {type: rest_api, id: c73bb20d-40ff-42df-8597-c9a428697d12}` with no email. GraphQL has the same `actorId`, no `actorEmail` and `actorMethod: oauth2`, and the export's `actor` column reads `c73bb20d-…`. The table's actor cell reads the QA user's email.
- **Today:** `actorType` (`lego/backend/internal/audit/rest.go:79`) types every `oauth2` bearer `rest_api`, and `resolveActors` (same file) gives a `usr-` id and an email only to a `user` actor. A person's OAuth token therefore keeps the stored Kratos subject. The table's `useWorkspaceSubjectLabel` (`dashboard/src/common/hooks/use-workspace-subject-label.ts`, w4/069) matches that subject against the roster's `subject` and shows the member's email. `csvActor` (`dashboard/src/features/audit/lib/audit-csv.ts`) prints REST's id.
- **Do:** resolve an `oauth2` row whose subject is a person (`core.PublicUserIDs` finds a `usr-` id for it; an API key's client id has none) the way a session row is resolved: REST `actor.id` is the `usr-` id and `actor.email` the email, and GraphQL `actorId`/`actorEmail` follow, so the export's `actor` column is the email the table shows. Keep `type: rest_api`, as ADR018's Audit logs row records for an OAuth token, unless Render's observable behavior says a person's CLI token is a `user`. An API key's rows keep its client id and no email. Amend ADR018's Audit logs row.
- **Accept:** a backend test pins an `oauth2` row with a person's subject to their `usr-` id and email, and a client-credentials key's row to its client id with no email. On production, an export over a day with `bex login` rows in `bex-canary` names them by the QA user's email, as the table does.
