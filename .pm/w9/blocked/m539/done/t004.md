## Objective

No harness or QA script silently stops seeing, or stops removing, the keys it relied on the workspace-wide list for.

## Context

- `scripts/auth-e2e.sh:129` lists keys with the bootstrap client and expects the key it minted. Under I10 a machine caller owns nothing, so it needs `allMembers=true` (the bootstrap holds Admin rows) or a person's session.
- `scripts/verify-sandbox-isolation-live.sh:370` revokes fixture keys minted directly through Hydra with no creator stamp. Those are creator-less, so the revoke now needs an Admin principal. Its bootstraps hold Admin rows; confirm it, and run `scripts/verify-sandbox-isolation-live.test.sh`.
- `scripts/render-cli-auth-e2e.sh:236` and `scripts/auth-oauth21-e2e.sh:554` read the list as a person or with a key. Check what each asserts still means what it meant.
- `scripts/qa-mcp.py` revokes only the key it minted, as the QA user. Confirm, and run `scripts/test_qa_mcp.py`.
