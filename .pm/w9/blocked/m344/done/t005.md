## Objective

Give the in-sandbox agent a way to answer the comment that steered it, so feedback closes the loop on GitHub as with Devin. The sandbox has no GitHub token; the gateway posts on its behalf with owner, repo and PR fixed server-side.

## Context

- Draft-PR delivery uses the gateway `pull-request` verb: `lego/backend/internal/agentsession/pullrequest.go`, `lego/backend/internal/sshgateway/agentcred/agentcred.go`, `lego/backend/internal/github/pulls.go`.
- The driver's tool registry: `lego/agent-image/driver/src/mcp-bex.ts` (`open_or_update_draft_pr`).

## Steps

1. Add a `pr-comment` verb (or extend `pull-request`) that posts an issue comment or a review-comment reply on the session's own PR only; body length-bounded and marked as written by the bex agent.
2. Add the driver tool and a line in the platform overlay telling the agent to reply after a PR-feedback turn.
3. Refuse any other PR or repo.

## Files

- `lego/backend/internal/agentsession/pullrequest.go`, `lego/backend/internal/sshgateway/agentcred/agentcred.go`, `lego/backend/internal/github/pulls.go`
- `lego/agent-image/driver/src/mcp-bex.ts`, `lego/agent-image/driver/src/acp.ts` (overlay)

## Acceptance criteria

- [ ] The agent posts a reply on its own PR; a call naming another PR number is refused.
- [ ] The reply is visibly attributed to the bex agent.

## Out of scope

- Resolving review threads.

## Done (2026-11-12)

Agent reply verb: driver tool `reply_on_pull_request({body})` (repo sessions only) → gateway `POST /git/<ns>/<sid>/<repo>/<branch>/pull-request/comment` (Pod-bound, nonce, limiter) → bex-api internal `/v1/agent-session-pull-request-comments` (MAC domain `pull-request-comment`, live-sandbox check, the session's own PR only, `no_pull_request` before a PR exists, the agent footer) → `CreateIssueComment` with a `pull_requests:write` token; audited as `agentsessions.PullRequestComment`. Overlay step 6 tells the agent to reply after a feedback turn. Env `BEX_AGENT_PULL_REQUEST_COMMENT_API_URL` (default to bex-api :8091).
