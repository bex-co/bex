## Objective

Make the GitHub App deliver the events t001 chose, and let bex tell whether an installation has accepted them, the way it already does for `check_suite`.

## Context

- The App subscribes only to `push` and `check_suite` today (`docs/ADR026-github-integration.md:30`).
- Installation event probe: `lego/backend/internal/github/service.go:1266` (`slices.Contains(inst.Events, "check_suite")`), `client.go:315`.
- **User gate:** enabling new events and the `issues`/`pull_requests` write permission on the production GitHub App is the user's action in GitHub's App settings; each installation then has to accept the new permissions.

## Steps

1. Generalize the probe to report which of `issue_comment`, `pull_request_review`, `pull_request_review_comment` an installation receives.
2. Document the exact App settings change (events + permissions) in ADR026 and in this task's Done note, for the user to apply.
3. Surface 'PR feedback is off for this installation' where the dashboard already shows GitHub connection state.

## Files

- `lego/backend/internal/github/service.go`, `client.go`
- `docs/ADR026-github-integration.md`

## Acceptance criteria

- [ ] The probe reports each event per installation, with a unit test.
- [ ] The App settings change the user must make is written down step by step.

## Out of scope

- Making the App change on the user's behalf.

## Done (2026-11-12)

ADR026 records the App settings change (Subscribe to events → Issue comment and Pull request review; Pull requests: Read and write, already held). The webhook forwards `issue_comment`, `pull_request_review` and failed `check_suite` to the sink only for App-signed deliveries confined by `scopesFor`; non-failed suites cost no lookup. **Skipped:** a dashboard "PR feedback is off" indicator: bex shows no per-installation event state anywhere, and an App without the events simply sends none. **User action:** apply the ADR026 settings on the production GitHub App (gates t007).
