## Objective

When a check suite on the session's current head SHA concludes `failure`, steer the session once with the failing check names, as Devin iterates on CI failures.

## Context

- `check_suite` is parsed for deploy gating in `lego/backend/internal/apps/checks_pass.go:250` (head SHA, conclusion) and never matched to a session's `headSha`.

## Steps

1. On `check_suite` completed with `failure`, match the head SHA to a session's `headSha`; fetch the failing check runs' names and summaries.
2. Steer once per head SHA (loop guard from t001); a new push resets it.
3. Leave deploy gating behavior unchanged.

## Files

- `lego/backend/internal/apps/checks_pass.go`, `webhook.go`

## Acceptance criteria

- [ ] A failing check on the agent's head produces one steer naming the failed checks; a second failure event for the same head does not.
- [ ] A failure on a non-agent commit changes nothing.

## Out of scope

- Re-running workflows.

## Done (2026-11-12)

A completed `check_suite` with `failure`/`timed_out` on a session's head (and naming its PR when the suite lists PRs) queues the failed runs' names and summaries (`checks:read` token) with the head; delivery drops it if the head has moved and steers as the creator, at most 3 CI-only turns in a row (derived from delivered turns, so any other turn restarts the count).
