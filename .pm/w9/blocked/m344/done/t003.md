## Objective

Handle the new events in the GitHub webhook: find the session that owns the PR, apply t001's authorization, and steer it with the comment as quoted data.

## Context

- `lego/backend/internal/apps/webhook.go:346-358` handles `delete` and `check_suite`, then answers `{"ignored": event}` for everything else.
- Sessions are found by repo and PR number (`store/agentsessions.go:175`, `:1022`); `Service.Steer` (`service.go:1668`).

## Steps

1. Dispatch `issue_comment` (PR only), `pull_request_review` and `pull_request_review_comment` to a new handler.
2. Look up the active session by (repo, PR number); ignore PRs no session owns, closed/merged PRs and canceled/archived sessions.
3. Check the commenter's repo permission and bex account link; ignore bots and the agent's own comments.
4. Build the steer prompt: the comment (and for a review, every comment with file:line), quoted line by line as untrusted text, plus who wrote it; call `Steer` as the session creator. Debounce a burst into one steer.
5. Record a delivery id so a GitHub redelivery does not steer twice.

## Files

- `lego/backend/internal/apps/webhook.go` (or a new `pr_feedback.go` beside it)
- `lego/backend/internal/store/agentsessions.go` (lookup by repo + PR)
- `lego/backend/internal/agentsessions/service.go`

## Acceptance criteria

- [ ] A comment from a write-access, linked member on an agent PR starts exactly one new turn on the same branch.
- [ ] A comment from an unlinked user, a read-only user or a bot does nothing (200, logged).
- [ ] A redelivered webhook does not steer twice; a review with five comments steers once.

## Out of scope

- Starting new sessions from PRs no session owns.

## Done (2026-11-12)

`apps.GitWebhook.PRFeedback` → `agentsessions.PRFeedback.HandlePRFeedback`: bots ignored, the session found by repo + PR number (indexed, migration 0237), canceled or archived sessions and closed PRs ignored, the commenter checked (collaborator permission via a repo-scoped `metadata:read` token, 404 = none; the GitHub id matched through `workspaces.KratosIdentities.GitHubUserIDs`; the member's `can_create` asked via the steer's own check), a review's inline comments read with a `pull_requests:read` token, every line quoted, queued in `agent_session_feedback` (idempotent by object id). The `PRFeedback` worker (every replica, 10 s, leased) delivers one member's items per turn as that member.
