## Objective

A background reconciler reads the state of every session PR that is not settled and stores it; it backfills sessions that already have a PR. This is the source of truth, so the feature works with the App subscribed only to `push` and `check_suite`.

## Context

- `github.Client.GetPullRequest` already returns `State` and `Merged` (`lego/backend/internal/github/feedback.go:154-170`) through the installation token.
- The production App subscribes to `push` and `check_suite` only (`docs/ADR026-github-integration.md:30`); m344/m348 are blocked on enabling more events.

## Steps

1. Poll open and draft PRs on a short interval (minutes) and closed ones at a lower cadence for a bounded period so a reopen is seen; stop at merged.
2. Bound requests per installation and back off on rate limits and 404s (a deleted repository or revoked installation leaves the last known state).
3. Backfill: the first pass reads every session with a PR and no state.

## Files

- `lego/backend/internal/agentsessions/` (reconciler + wiring in bex-api's background workers)
- `lego/backend/internal/github/feedback.go` (only if a field is missing)

## Acceptance criteria

- [ ] Tests with a fake client: draft→open→merged, open→closed→reopened, a 404 keeps the last state, rate-limit back-off.
- [ ] Exactly one replica runs a given pass (same claim pattern as the other bex-api workers).
