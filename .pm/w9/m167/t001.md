## Objective

Add a Bex-native `bex edit [path…]` command. It finds the bex desktop editor CLI and `syscall.Exec`s it with the arguments passed through unchanged, following the `bex code` launcher pattern.

## Context

- **Launcher precedent:** `lego/cli/internal/code/launch.go` (`exec.LookPath("claude")`, `syscall.Exec`, a `beforeExec` telemetry hook). Commands attach in `lego/cli/main.go:52`.
- **Telemetry:** `internal/telemetry` `EmitLaunch(commandPath, startedAt, stderr)`, which sends the command path only.
- **bex-desktop contract**, from its `docs/adrs/ADR002`, which is being shipped in that repo now. Re-read the shipped ADR and adjust the lookup to it.
  - PATH command: `bex-desktop`.
  - macOS: the bundle-internal CLI (Zed layout `Bex*.app/Contents/MacOS/cli`).
  - Linux: `~/.local/bex*.app/bin/bex-desktop` (older builds use `bin/bex` or `bin/cli`).
  - Argument passthrough supports paths, `path:line:col`, `-n`/`-e`/`-a`, `--wait`, and `ssh://` URLs.
- **Never look up `bex` on PATH.** Pre-rename desktop links resolve to `bex`, and the current binary is also `bex`, so a lookup would recurse.

## Steps

1. New package `internal/desktop`. Add `Locate()`:
   - check PATH for `bex-desktop` first;
   - then check the known bundle locations: `/Applications` and `~/Applications` on macOS; on Linux `~/.local/bex*.app/bin/{bex-desktop,bex,cli}`, accepted only inside a `bex*.app` directory;
   - refuse any candidate that resolves to `os.Executable()`.
2. `bex edit [args…]` uses `DisableFlagParsing`, so editor flags pass through. With no arguments, pass nothing; the editor opens its default window.
3. Non-interactive guard: if stdout/stderr is not a TTY, or `CI` is set, exit nonzero with "bex edit opens the bex desktop editor; not available in a non-interactive session".
4. Not found: exit nonzero with a hint that gives the download URL or install script and mentions `bex-desktop`.
5. Call `EmitLaunch` before exec.

## Files

- `lego/cli/internal/desktop/*.go`, `lego/cli/main.go`

## Acceptance criteria

- [ ] With a fake `bex-desktop` on PATH, `bex edit a b:1:2 -n` execs it with exactly those args.
- [ ] With only a bundle candidate, that candidate is used; a candidate equal to the running executable is skipped.
- [ ] The missing-editor and non-interactive cases exit nonzero with the documented messages and exec nothing.

## Out of scope

- Windows: the platform CLI is not built for Windows.
