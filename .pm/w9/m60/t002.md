## Objective

The ~305 KB of `description` strings in the locale catalogs are translator/dev documentation — `extractMessages()` keeps only `message` at runtime — yet they ship in the entry chunk. Remove them from the production bundle without losing them as authoring docs.

## Context

- Every `dashboard/src/**/locales/{en,zh}.ts` entry is `{ message, description }` (e.g. `src/common/locales/en.ts:4-9`).
- `dashboard/src/i18n/index.ts` — `extractMessages()` discards `description`; proof of shipping: a known description string ("Title for the retry dialog…") is present in the built entry chunk.
- ~155 KB en + ~150 KB zh of description source ≈ 60–90 KB gzip dead weight.

## Steps

1. Pick the mechanism: a small Vite transform that strips `description:` properties from `**/locales/*.ts` modules at build time is least invasive (no authoring-format change); alternatively restructure catalogs so descriptions live in a dev-only sibling never imported by `init.ts`. Prefer the build-time strip unless it proves fragile.
2. Implement it and verify dev mode still works (descriptions may remain in dev).
3. `yarn build`; confirm a known description string is absent from all emitted chunks while its `message` sibling is present.

## Files

- `dashboard/vite.config.ts` (transform) or the locale-file layout
- `dashboard/src/i18n/index.ts` (only if the extraction shape changes)

## Acceptance criteria

- [ ] Production chunks contain no locale `description` strings (spot-check ≥ 2 known strings).
- [ ] All locale-parity tests (`locale-parity.test.ts`, 24 namespaces) still pass — authoring format for translators preserved or migrated consistently.
- [ ] Dev-mode i18n unaffected.

## Out of scope

- Per-locale lazy-loading (t003).
