## Objective

`react-intl` (a second i18n stack alongside i18next) sits in the entry chunk solely because the always-mounted `OryToaster` needs `useIntl()` for Ory's `DefaultToast`. Move it behind a lazy boundary (or a lighter shim) so formatjs ships only if/when an Ory toast can render.

## Context

- `dashboard/src/common/providers/root-provider.tsx:2` — `import { IntlProvider } from "react-intl"`; used only by `OryToaster` (lines ~29-45).
- Confirmed in the built entry chunk (formatjs/IntlProvider references present). `react-intl` is 372 KB in node_modules; est. 15–30 KB gzip in the entry.

## Steps

1. Extract `OryToaster` (with its `IntlProvider` wrapper) into its own module and mount it via `React.lazy` + `Suspense fallback={null}` in `root-provider.tsx`.
2. If the toaster must be available synchronously for auth-flow toasts, check whether a minimal `useIntl` shim satisfies Ory's `DefaultToast` instead, and prefer whichever keeps behavior identical.
3. `yarn build`; confirm formatjs identifiers left the entry chunk; exercise an Ory toast (e.g. a settings-flow success) to prove it still renders.

## Files

- `dashboard/src/common/providers/root-provider.tsx`
- new `dashboard/src/common/providers/ory-toaster.tsx` (or similar)

- [ ] Entry chunk contains no `IntlProvider`/formatjs references.
