## Objective

An SSH session into a service instance records `StartShellEvent` when it opens and `EndShellEvent` when it closes, with Render's shell metadata keys.

## Context

- Render (render.com/docs/audit-logs, read 2026-11-16): `StartShellEvent` (SSH session started), `EndShellEvent` (SSH session ended), from the CLI or the service's Shell page; metadata "can include `service`, `instance`, `source_ip`, and `user_agent`". Both are in the pinned enum.
- `lego/backend/internal/sshgateway/nativessh/server.go` (~399-420) resolves `auditTarget` (workspace, service, instance) and calls `Store.StartSSHSession` with a 2 s timeout, then records the end.

## Steps

1. At the existing start point, write a `StartShellEvent` row in the target's workspace: actor = the authenticated user, metadata `service` (the `srv-` id), `instance`, `source_ip` (the remote address via `sshgateway.RemoteIP`).
2. At close, write `EndShellEvent` with the same metadata.
3. A connection refused after the caller is identified (authorization denied, 2FA requirement) records `StartShellEvent` with `status: error`; an unidentified connection records nothing.
4. Use a derived event id per session and phase, so a retried write records once; a failed write is logged and never blocks or ends the session.
5. Native SSH has no user agent; omit it (Render: "when available").

## Files

- `lego/backend/internal/sshgateway/nativessh/server.go`, `lego/backend/internal/store/`, gateway fakes in `lego/backend/internal/sshgateway/gatewaytest/`, tests

## Acceptance criteria

- [ ] A test session produces one start and one end row with the four-key metadata minus `user_agent`; a refused identified session produces one `error` row.
- [ ] No command, environment or terminal content reaches either row (test).
