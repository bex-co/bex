## Objective

t005's production walk (2026-11-18) found that every native SSH `StartShellEvent`/`EndShellEvent` row records `metadata.source_ip: 10.10.0.7`, the Hetzner load balancer's private address, instead of the SSH client's. Render's `source_ip` is the address the session came from, and the web shell already records it. Carry the client address through the `:22` edge so native SSH rows name the client as well.

## Context

- `infra/terraform/main.tf` `hcloud_load_balancer_service.ssh` sends no PROXY header (`proxyprotocol = false`), and Traefik's `ssh` entrypoint (`deploy/gitops/overlays/prod/values/traefik.values.yaml`) trusts none. So Traefik sees every SSH client as `10.10.0.7`, and its own PROXY v2 hop to the gateway (`lego/operator/config/ssh/ingressroutetcp.yaml`, w4/m82) forwards that address. w1/m150 kept `:22` plain on the belief that this second hop carried the client. It carries only what Traefik knows.
- `:80`/`:443` solved the same problem in w1/m150 with a two-step rollout: Traefik trusts `10.10.0.7/32` first, then the listener sends the header. The reverse order breaks the edge. In this repo a push to `infra/terraform/**` is an apply (`infra.yml`, no reviewers on `production-infra`).
- Local lab (Traefik v3.7.17, the production build): an entrypoint that trusts PROXY headers holds the backend's banner until the client sends bytes when its peer sent no header. OpenSSH sends its identification at once and connects. The repository's KEXINIT liveness probe read the banner first and timed out, so it must speak first.

## Steps

1. Ship 1: Traefik `ssh` entrypoint `proxyProtocol.trustedIPs: [10.10.0.7/32]`. `ProbeKEXINIT` sends its identification before it reads the server's. `scripts/edge-proxyprotocol-validate.sh` requires the `ssh` trust.
2. Once Argo CD has rolled Traefik, check live that `bex ssh` and the KEXINIT probe still pass.
3. Ship 2: Terraform `ssh` listener `proxyprotocol = true`, the validator expecting it, and the ADR035 amendment.
4. Once `infra.yml` has applied, check live that a `bex ssh` session's rows carry the client's public address, and that a client-written PROXY line cannot set it.

## Acceptance criteria

- [ ] On production, a `bex ssh` session's `StartShellEvent` and `EndShellEvent` carry `metadata.source_ip` equal to the client's public address, not `10.10.0.7`.
- [ ] A client that prefixes its own PROXY line does not get that address recorded.
- [ ] `bash scripts/edge-proxyprotocol-validate.test.sh` and the KEXINIT probe tests pass; the scheduled `ssh-edge-liveness` probe passes against the live edge.
