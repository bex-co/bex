## Objective

Expose the calling user's effective workspace role and permitted verbs through the GraphQL surface the dashboard already queries, so the client can gate controls the server would refuse. Mirror the ADR024 contributor rule authoritatively on the server — the dashboard consumes, never re-derives, the policy.

## Context

- `lego/backend/internal/members/graphql.go` already exposes `members[].role` (UPPERCASE enum) for the Team page — the caller's role is derivable but there is no viewer-capabilities projection yet.
- `docs/ADR024-members.md` § "The contributor boundary: lifecycle, not code" — the source-of-truth for which verbs each role holds.
- `w1/m68` moved four verbs from `can_operate` to `can_create`: set pre-deploy command, set cron `command`, create a one-off job, deploy with `imageUrl`/`commitId`, set Postgres statement-logging params.
- Other standing boundaries: `can_view_sensitive` (connection strings / env values), `can_manage_billing`, `can_manage` (members).

## Steps

1. Add a `viewer`/`capabilities` GraphQL field resolving the caller's role in the active workspace plus the effective boolean capabilities the dashboard needs (at minimum: `canCreate`, `canOperate`, `canViewSensitive`, `canManageBilling`, `canManage`).
2. Resolve from the same authz source the write paths use (OpenFGA / `tenant_members`), not a hand-maintained table, so the UI can never disagree with a real refusal.
3. Keep it read-only and cheap (one lookup); surface a sane default when authz is allow-all (`BEX_OPENFGA_URL` unset ⇒ all-true).

## Files

- `lego/backend/internal/members/graphql.go` (or a new `viewer`/`capabilities` resolver file under `lego/backend/internal/`)
- wire into the composition root that registers GraphQL types

## Acceptance criteria

- [ ] A GraphQL query returns the caller's role + effective capability booleans for the active workspace
- [ ] Booleans derive from the live authz source (a contributor gets `canCreate:false`, an admin `canCreate:true`)
- [ ] Backend build + `go test ./...` + `make lint-backend` green

## Out of scope

- Dashboard consumption (t002+)
- REST/MCP mirroring of the projection (handled in the Render-parity closing task if warranted)
