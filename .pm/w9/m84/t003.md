## Objective

Apply disable-with-reason to the four controls `w1/m68` moved to `can_create`, so a contributor sees them disabled with a role explanation instead of an editable field that 403s on save.

## Context

- Affected controls: set pre-deploy command (`dashboard/src/features/services/components/build-deploy-section.tsx`), set cron `command`, create a one-off job, deploy with `imageUrl`/`commitId`, set Postgres statement-logging params.
- Pattern decision (from `.pm/w1/047.md`): **disable-with-reason**, not hide — a hidden control makes the role model invisible; "your role cannot change what this service runs" teaches it.

## Steps

1. Read `canCreate` (t002) at each affected control; when false, render it disabled with a role-reason tooltip/hint.
2. Keep the copy specific and instructive (name the capability, not a generic "forbidden").
3. Ensure the disabled state is accessible (aria-disabled + reason text reachable by keyboard/screen reader).

## Files

- `dashboard/src/features/services/components/build-deploy-section.tsx`
- the cron `command`, one-off job, image/commit deploy, and Postgres statement-logging control components

## Acceptance criteria

- [ ] Contributor: each of the four controls renders disabled with a role reason; admin: enabled
