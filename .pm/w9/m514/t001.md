## Objective

Settle the rule before any code and record it in ADR024 as a new section after § An API key carries a chosen set of permissions.

## Context

- Render's page and quotes are in the milestone README; re-read [render.com/docs/api-keys](https://render.com/docs/api-keys) and [team-members](https://render.com/docs/team-members) and record what changed since 2026-11-19.
- Today every key verb gates on `can_manage_keys` (`developer or admin`, `deploy/gitops/authz/model.fga`): `CreateAPIKey`, `ListAPIKeys`, `RevokeAPIKey`, `UpdateAPIKeyPermissions`, `PermissionCatalog` (`lego/backend/internal/apikeys/service.go`). `router/service.go` gates its own access keys on the same relation; leave its meaning unchanged.
- `store.BindClientForCreator` (`lego/backend/internal/store/store.go`) admits only `admin` and `developer` creators. A key already follows its creator to any role (`enqueueRoleReconciliation`).
- `core.KeyGrantCap` asks the relations each catalog level names; `KeyLevelRequiredRole` ranks only viewer, contributor, developer and admin, so Billing's grantable set and its "required role" text need a rule (Workspaces' "settings, plan and usage" needs `can_manage`, yet Billing reads billing figures through `can_manage_billing`).
- `members.Capabilities.CanManageKeys` drives the dashboard's capability policy (`dashboard/src/features/capabilities/lib/capability-policy.ts`).

## Steps

1. Decide the mint relation: a new derived relation (for example `can_mint_keys: viewer or contributor or developer or admin or billing`) or an existing one every member holds. Name the trade-offs (audit rows, scope class in `core/scope.go`, the dashboard capability).
2. Decide own-key scoping for list, edit and revoke below `can_manage_keys`: the key's `created_by` (migration 0297) equals the caller, in the key's own workspace. A key with no recorded creator is never anyone's own.
3. Decide Billing's grant cap: which catalog levels a Billing member may grant, and how the picker names the role a level needs.
4. Decide the dashboard capability that shows the mint button and the own-keys list.
5. Amend ADR024 (new section, invariants I9 and I10 with their tests to be), ADR012 §8e, and plan ADR018's API keys row (replace "Not offered yet … w9/115").
