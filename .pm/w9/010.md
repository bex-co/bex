# No-Dockerfile static-site publishing (Render parity)

Filed by `w9/m44/t005` (sample lifecycle sweep, 2026-07-17). Running `examples/static-site` through the lifecycle harness on **production** failed at deploy:

```
error: failed to solve: failed to read dockerfile: open Dockerfile: no such file or directory
==> Build failed
```

**Root cause:** bex's static-site build plane is **Dockerfile-only** (`docs/ADR029-static-sites.md` §Build: "reuses the in-cluster BuildKit build plane (`internal/build`, Dockerfile-only today): a `static_site` App must build to an image whose `spec.publishPath` directory holds the built site"). The publish Job then extracts `publishPath` from that image (`lego/operator/internal/publish/publish.go:232`, `cp -a "$PUBLISH_PATH"/. /out/`). A repo with only `index.html` and no Dockerfile has nothing to build, so the deploy fails — even though the sample's `bex.yml` advertised "No Dockerfile or build command needed — files in publishPath are served as-is."

**In-milestone stopgap (done in t005):** added a minimal `examples/static-site/Dockerfile` (`FROM busybox; WORKDIR /site; COPY index.html .`) so the sample builds and the publish Job extracts it; fixed the misleading `bex.yml` comment. Validated locally (the extract copies exactly `index.html`).

**The real fix (this follow-up):** support publishing a static directory with **no Dockerfile**, the way Render does — a `static_site` with a publish directory (and optional build command) but no Dockerfile should publish the repo's `rootDir/publishPath` directly to the object-store origin. Sketch: when the build plane detects no Dockerfile and no build command for a `static_site`, skip the image build and run a publish Job that git-clones the repo context and `s3 sync`s `rootDir/publishPath` straight to `s3://<bucket>/<app-id>/<rev>/` (revision-prefixed, same atomic-cutover keys as today). Optionally support a build command (native/nixpacks) that produces `publishPath`, then extract as today.

**Scope:** operator build/publish plane change + envtest coverage; touches `internal/build` build-path selection and `internal/publish`. Moderate — a milestone, not a task. **Evidence:** the harness (`scripts/samples-lifecycle.sh static-site`) reproduces; re-run it green after the stopgap ships, and again after the real fix (dropping the sample Dockerfile).

~1 milestone. Source: w9/m44 prod sweep, 2026-07-17.
