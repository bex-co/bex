## Objective

Relocate the overview page's primary data fetch from the component body into the route `loader` so `defaultPreload: "intent"` prefetches it on hover and it participates in SSR dehydration.

## Context

- `dashboard/src/routes/index.tsx` fetches via `useServices`/`useDatabases`/`useKeyValues`/`useProjects` in the component body.
- The router (`dashboard/src/router.tsx`) already dehydrates/hydrates the Apollo cache and sets `defaultPreload: "intent"`; a loader `context.client.query(...)` warms that cache before render (the detail routes' title loaders are the precedent).
- Follow the existing `titleLoaderFetchPolicy(cause)` pattern: `network-only` on entry/preload, `cache-first` on `stay` re-runs, so polling/tab-switches don't refire.

## Steps

1. Add a `loader` to `/` that primes the primary query (services/projects at minimum) via `context.client.query` with the cause-aware fetch policy.
2. Have the component read from the warmed Apollo cache (the existing hooks will hit cache-first), keeping the current polling behavior for live updates.
3. Confirm SSR dehydration includes the primed data and the client hydrates it without a refetch flash.

## Files

- `dashboard/src/routes/index.tsx`
- (reference) `dashboard/src/common/lib/document-head` (`titleLoaderFetchPolicy`), `dashboard/src/router.tsx`

## Acceptance criteria

- [ ] Hovering a link to `/` starts the primary fetch before click (devtools).
- [ ] `/` renders with data on mount in the warm case (no initial skeleton).
- [ ] Polling / background refetch still works; no hydration mismatch.
