## Objective

Verify — field-by-field, not by id/name presence — that `owner` (nested `{id,name,email,type}`), `region`, `dashboardUrl`, and `updatedAt` are emitted identically across postgres, apps, and keyvalue on **every** REST read path: list, single-item get, and the create/update/suspend/resume response bodies. Fix any path that silently drops a field; record the paths verified clean.

## Context

- Shared source: `internal/resourcemeta/metadata.go` — `ResolveOwners`, `Config.PlatformRegion()`, `Config.DashboardURL(route,id)`, `UpdatedAt(obj)`.
- postgres: `internal/postgres/rest.go` — `renderPostgres` (owner/region/dashboardUrl) + `PostgresView` (updatedAt at `service.go`); `renderPostgres`/`renderOnePostgres` wrap list + single.
- apps: `internal/apps/render.go` — `renderService`/`toRenderServiceWithMetadata`/`ownerToRender`; region falls back to `a.Region`.
- keyvalue: `internal/keyvalue/rest.go` — `renderKeyValues`/`toRenderKeyValue`/`keyValueOwner`.
- The failure mode to hunt: a single-item mutation handler (create/update/suspend/resume) that returns a bare `*View` (or a wrapper that skips the `render*` enrichment) instead of routing through the `render*`/`toRender*` path — the exact class that produced the original KeyValue nested-`owner` and Postgres flat-`ownerId` bugs.

## Steps

1. For each of the three packages, enumerate every REST handler that writes a resource object to the response (list, get, create, update/PATCH, suspend, resume, and any rename/plan/version verbs).
2. Confirm each handler serializes through the package's Render wire-shaping layer (`renderPostgres`/`renderService`/`renderKeyValues` or their single-item wrappers), not a bare `View`.
3. For any handler that bypasses enrichment — route it through the wrapper so `owner`/`region`/`dashboardUrl`/`updatedAt` appear. Where a field is genuinely unavailable (e.g. `owner` when `OwnerID` is empty, `region` when `BEX_REGION` unset), confirm it is `omitempty`-omitted consistently across all three siblings, never faked.
4. Record the audit result (clean vs fixed, per path) in the milestone README's closeout or a task note.
5. `cd lego/backend && go build ./... && go test ./...`; `make lint-backend` from `lego/operator/`.

## Files

- `lego/backend/internal/postgres/rest.go`
- `lego/backend/internal/apps/render.go` (+ `service.go` handlers if any bypass)
- `lego/backend/internal/keyvalue/rest.go`

## Acceptance criteria

- [ ] Every REST read/mutation-response path in postgres, apps, keyvalue routes through its Render wire-shaping layer — verified handler-by-handler.
- [ ] `owner`/`region`/`dashboardUrl`/`updatedAt` are present (or consistently `omitempty`-omitted where source data is absent) identically across the three siblings on list, get, and create/update/suspend/resume responses.
- [ ] Any drift found is fixed; `go build ./... && go test ./...` and `make lint-backend` green.

## Out of scope

- GraphQL/MCP surface changes (t003 Render-parity verifies cross-surface consistency; the wire shape is REST-boundary-only by design).
- Adding a per-resource `region` concept where none exists — do not fabricate region strings (per w6/016's design note).
