## Objective

Add a cross-sibling parity test that locks the audited invariant: `owner`/`region`/`dashboardUrl`/`updatedAt` are present and identically-shaped on every REST read path across postgres, apps, and keyvalue — so a future handler that bypasses the `render*` layer fails the build.

## Context

- The bug class this guards is exactly the one that produced the original KeyValue nested-`owner` and Postgres flat-`ownerId` drops: a mutation handler returning a bare `View`. A test that asserts by id/name presence alone would NOT have caught it — assert the four metadata fields' presence and shape.
- Seed a resolvable owner + set `Metadata.PlatformRegion()`/`DashboardURL` so the fields are non-empty and assertable.

## Steps

1. Add a table-driven test exercising list, single get, and create/update/suspend/resume response bodies for each of postgres/apps/keyvalue, asserting nested `owner` `{id,name,email,type}`, `region`, `dashboardUrl`, `updatedAt`.
2. Assert the `omitempty` behavior too: with no resolvable owner / `region` unset, the fields are omitted identically across siblings (never zero-valued/faked).
3. `go test ./...` + `make lint-backend` green.

## Files

- Test files in `lego/backend/internal/postgres/`, `internal/apps/`, `internal/keyvalue/` (or one shared cross-package test where practical).

## Acceptance criteria

- [ ] A parity test asserts the four metadata fields' presence/shape on list + get + create/update/suspend/resume for all three siblings.
- [ ] The test asserts consistent `omitempty` omission when source data is absent.
- [ ] Test fails if a read path is routed around the `render*` layer; `go test ./...` green.

## Out of scope

- Tautological/snapshot-everything assertions — test the metadata contract and its failure mode, not the whole object.
