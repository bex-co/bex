## Objective

A new Kratos session produces exactly one `LoginEvent` per workspace the user belongs to, without slowing or failing any request.

## Steps

1. On a successful `whoami` in `lego/backend/internal/api/auth.go`, check a per-replica seen set; for an unseen session id, record asynchronously with a bounded timeout.
2. Dedupe across replicas with a unique key on the Kratos session id (an insert-on-conflict-do-nothing table purged with the audit retention, or a derived audit event id per session and workspace).
3. Write `LoginEvent` rows timestamped at `authenticated_at`, with `source_ip`/`user_agent` from the session device and the user as actor, into every current membership's workspace.
4. A failed write is logged and retried on the next request of that session; it never fails the request.

## Files

- `lego/backend/internal/api/auth.go`, `lego/backend/internal/core/audit.go`, `lego/backend/internal/store/` (next free migration), tests

## Acceptance criteria

- [ ] Two replicas seeing the same new session at once write one row per workspace (real-DB test).
- [ ] Later requests on that session write nothing; a session minted by recovery is recorded too.
