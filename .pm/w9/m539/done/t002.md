## Objective

Change `apikeys.Service` so I10 (every role) and I13 hold, with unit tests.

## Context

- `ListAPIKeys` (`lego/backend/internal/apikeys/service.go:546`) filters to `mintedByCaller` only when `Can(ctx, core.RelCanManageKeys)` is false (`:560`).
- `keyRelation` (`:662`) picks `relOwnKeys` for the caller's own key and `core.RelCanManageKeys` otherwise. `RevokeAPIKey` (`:623`) and `UpdateAPIKeyPermissions` (`:717`) make their one `Authorize` with it. `UpdateAPIKeyPermissions` then admits a non-creator Admin through `HoldsFresh(core.RelCanManage, …)` (`:754`).
- `mintedByCaller` (`:682`): a machine caller and a creator-less key own nothing.
- `can_manage_keys` keeps other consumers (`lego/backend/internal/router/service.go`, `members/service.go:489`'s capability probe), so the relation and `model.fga` do not change.

## Steps

1. Add an `allMembers` option to `ListAPIKeys`, either a parameter or a small options struct that the three adapters pass. By default, filter to `mintedByCaller` for every caller. With `allMembers`, make one audited `Authorize(ctx, core.RelCanManage)`, so a non-Admin gets 403, and return every key bound to the workspace.
2. `keyRelation`: another member's key, a creator-less key and an unknown key are decided with `core.RelCanManage` (Admin), not `can_manage_keys`.
3. `UpdateAPIKeyPermissions`: refuse anyone but the key's creator with `KeyEditorForbiddenCode`, Admins included, and reword its message. Keep the "records no creator" 400 for a creator-less key, so its order relative to the 403 stays as tested today.
4. Update the doc comments, then the unit tests in `member_keys_test.go` and `apikeys_test.go` that pin the old Developer and Admin view.

## Acceptance criteria

- [x] Each of the five roles lists only its own keys by default. An Admin's `allMembers` lists every key, including a creator-less one. A Developer's `allMembers` is 403, audited once against `can_manage`.
- [x] A Developer revoking or editing another member's key is 403. An Admin revokes it. An Admin editing it is 403 `api_key_permissions_editor_forbidden`. The creator edits and revokes their own.
- [x] An API key's default list is empty. An Admin's All key passes `allMembers`. A Developer's All key gets 403 for it.
- [x] `cd lego/backend && go test ./internal/apikeys/...` passes (run `scripts/backend-test-deps.sh up` first).

## Record

**Done 2026-11-20.** `ListAPIKeys(ctx, ownerID, allMembers bool)`: the default filters to `mintedByCaller` for every caller (the audit-silent `Can(can_manage_keys)` view probe is gone); `allMembers` makes the one `Authorize` against `core.RelCanManage` instead of the own-keys relation, so a non-Admin gets 403 with one denied audit row (a read verb records only denials). `keyRelation` decides another member's key, a creator-less key, an unknown key and a missing store with `core.RelCanManage`. `UpdateAPIKeyPermissions` refuses anyone but the creator with `KeyEditorForbiddenCode` ("only the key's creator may change its permissions; a workspace Admin may revoke it"); the `HoldsFresh(can_manage)` Admin bypass is gone, and the creator-less key's "records no creator" 400 still comes before the 403.

**Deviation (kept on purpose):** a key revoking itself, the CLI's logout with a key (`cliauth`, `POST /v1/oauth/revoke`), keeps its pre-milestone gate `can_manage_keys` (`isCallerKey`), so a Developer's key still logs out and a Viewer's still cannot. Deciding it with `can_manage` would have made `bex logout` with a Developer's key answer 403, a narrowing no task asked for.

Tests: `TestEveryMemberListsOnlyTheirOwnKeys` (six people, a creator-less key, a key minted by a key and another workspace's key; each default list, each `allMembers` answer and its audit row; the Admin's, Developer's and Viewer's keys), `TestOnlyTheCreatorEditsAndOnlyAnAdminRevokesAnothersKey` (replaces the two below-Developer tests), `TestAKeyRevokesAnotherKeyOnlyAsAnAdmin`, and the updated `TestEditNarrowsAndWidensWithinTheCreatorsRole` (the Admin's edit is the editor code, another Developer's a plain 403, an unknown key 403 for a Developer). The identity-less legacy-mode tests (`TestAPIKeyVerbs`, `TestRESTAPIKeyLifecycle`, `TestGraphQLAPIKeys`, `TestCreateAnswersTheBearerKeyOnEverySurface`) now pin that an anonymous caller's own list is empty and read the workspace list with `allMembers`. `go test ./internal/apikeys/` passes on real deps.
