## Objective

Make workspace selection the drawer's primary scrollable context list, retaining m2's exact persistence and tenant-isolation behavior while showing the status metadata already returned by the workspace query.

## Context

- `WorkspaceProvider` already normalizes the API list, restores the session-scoped AsyncStorage selection, and calls `resetWorkspaceBoundary` before publishing a new workspace.
- `MobileWorkspace` already carries `name`, `plan`, and `role`; the current Picker shows only the name and is mounted only on Status.
- The Beancount drawer preserves source ordering, marks the selected context, supports pull-to-refresh, and closes after selection.

## Steps

1. Render `useWorkspace().workspaces` in the drawer with name, localized plan/role status, and selected semantics/checkmark, preserving API order.
2. Keep refresh, loading, empty, error, offline, and switching states truthful; use `retry()` rather than inventing a second query.
3. Route selection only through `switchWorkspace` and close only after a no-op selection or successful boundary reset; never expose the target before reset completes.
4. Remove the page-local `WorkspaceSwitcher` from `ResourceStatusScreen` and retire the component if no remaining caller needs it.

## Acceptance criteria

- [ ] Every accessible workspace appears once in API order with name, role, plan, and exactly one selected marker when ready.
- [ ] Workspace switching still clears/aborts old-workspace state before the new selection renders, persists per session, and closes the drawer only at a safe terminal point.
- [ ] Offline/error/empty/loading/switching states never display another workspace's cached tenant data and leave retry/logout reachable where applicable.
- [ ] The Status page no longer owns a duplicate workspace Picker.

## Out of scope

- Workspace creation/settings/membership management, changing persistence keys, or caching tenant resource data for offline display.
