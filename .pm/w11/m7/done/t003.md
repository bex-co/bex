## Objective

Model waiting-for-input, structured elicitation, security permission, and prompt-turn acceptance durably instead of inferring a decision request from transcript text.

## Context

- Extend the one `agentsessions` core and REST/GraphQL/MCP adapters; preserve phase-1 steering and optimistic concurrency/idempotency.
- A decision carries an opaque ID, type, allowed response schema/actions, expiry, version, and pending/resolved/canceled state. Sensitive elicitation uses an external URL contract rather than transcript form fields.

## Steps

1. Define decision state transitions, metadata, prompt-turn idempotency, audit, authorization, and adapter fields/errors without weakening cancel or live-sandbox limits.

## Acceptance criteria

- [ ] Invalid phase, duplicate turn, stale/expired decision, invalid schema response, cross-workspace access, cancel race, and resume failure are named/tested.
- [ ] Clarification/elicitation and security permission are distinct API states; no client derives them from assistant text.

## Out of scope

- Agent permission bypass, `always allow`, or client-defined permission modes.
