## Objective

Make a session's original task and follow-up prompts durable so a new or killed client reconstructs the same ordered user/assistant conversation and a retried POST cannot execute a prompt twice.

## Context

- The driver skips ACP `user_message_chunk` because the initiating client already rendered it, and `agent_session_transcripts` stores only emitted UI stream parts.
- Client-local optimistic messages are insufficient for another phone, process death, or storage eviction.
- Submission acknowledgment must come from the durable control plane; seeing an assistant stream part is not proof that a turn committed.

## Steps

1. Add a durable turn ledger with client idempotency key, role/prompt, accepted/completed/failed status, timestamps, and assistant sequence boundaries; expose complete assembled history/cursor through the shared conversation contract and reconcile POST retries against it.

## Acceptance criteria

- [ ] A fresh client reconstructs the original task, every accepted follow-up, and corresponding assistant output without client-local persistence.
- [ ] Retrying the same idempotency key after timeout/process death returns the same durable turn and never executes it twice.
- [ ] Accepted, completed, failed, canceled, and redispatched turns have explicit ordered state and assistant sequence boundaries.
- [ ] Prompt text never enters tickets, notification payloads, or logs and follows the transcript retention/deletion lifecycle.

## Out of scope

- ACP elicitation and permission decisions (t003/t012).
- Offline creation of new turns.
