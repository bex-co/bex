## Objective

Convert ACP clarification/elicitation and security permission callbacks into the durable decision contract so web/mobile clients can answer them safely instead of the sandbox driver auto-approving or inferring intent from transcript text.

## Context

- The current driver uses an older ACP SDK generation and auto-approves permission requests.
- ACP is terminated inside the sandbox driver; neither mobile nor dashboard becomes a raw ACP client.
- Structured elicitation and security permission have different semantics. Sensitive input must use a server-declared external URL opened by the system browser.

## Steps

1. Upgrade and conformance-test the ACP adapter as needed, declare supported client capabilities, suspend the exact running prompt on an opaque decision ID, publish the durable request, validate one idempotent response, and resume or deny the same ACP call.

## Acceptance criteria

- [ ] Clarification, structured elicitation, URL elicitation, and security permission map to distinct typed decisions with expiry/version and explicit allowed responses.
- [ ] The driver no longer silently auto-approves permission requests; stale, duplicate, malformed, or unauthorized responses cannot resume the ACP call.
- [ ] Deny, cancel, timeout, driver exit, and sandbox redispatch settle the decision and prompt deterministically.
- [ ] An ACP agent lacking the newer capability degrades explicitly without breaking ordinary text/tool streaming.

## Out of scope

- Raw ACP transport in Expo.
- Persistent `always allow`, bypass mode, or collection of secrets inside transcript forms.

## Completion evidence (2026-08-16)

- Upgraded the exactly pinned official ACP TypeScript SDK from 0.14.1 to 1.3.0 and retained ordinary text/tool streaming conformance.
- Replaced sandbox auto-approval with a Pod-authenticated gateway broker on the existing internal Git-proxy listener; the driver blocks the exact ACP callback on the durable row and maps its one terminal response back to ACP.
- Permission, clarification, structured form, and external HTTPS URL elicitation are distinct. Only `allow_once`/`reject_once` are exposed; missing broker/capability or unsupported modes fail explicitly.
- Driver typecheck and all 37 tests pass, including capability negotiation, absent-broker/unsupported-mode failure, permission filtering/resume, and typed form/URL elicitation. Gateway broker tests prove source-Pod binding, durable suspension/resume, contract reuse, expiry, and driver-disconnect cancellation; backend focused suites pass for service, store, API, gateway attach, and gateway wiring.
