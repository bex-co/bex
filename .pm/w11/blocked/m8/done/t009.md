## Objective

Add the dedicated HTTPS invite handoff, fail-closed OS association plumbing, dashboard fallback, and explicit native bearer-token acceptance flow safely across OAuth.

## Context

- Direct `acceptWorkspaceInvite` tokens are intentionally single-use bearer capabilities independent of the caller's email; login-time email redemption remains verified-email gated.
- Custom schemes are development-only. Production needs exact iOS Universal Link and Android App Link associations for `/invite`.

## Steps

1. Add the dedicated dashboard fallback route and email link without changing invite authorization semantics.
2. Add exact iOS/Android association configuration plus SecureStore bootstrap, OAuth round-trip, explicit redemption, terminal clearing, retry retention, and workspace refresh.
3. Fail closed until the real distribution identities are configured; share signed physical-device qualification with `w11/m5/t007`.

## Acceptance criteria

- [x] Email uses `https://dashboard.bex.co/invite?invite=<token>`; the dashboard fallback strictly validates, tab-stashes, applies no-referrer, scrubs, and enters the existing sign-up/session flow.
- [x] Mobile validates and device-only SecureStore-stashes the token, removes it from the visible route before storage I/O, requires explicit acceptance, refreshes workspaces, clears success/terminal failures, and retains only retryable transport failures.
- [x] Invalid, expired, reused, and seat/plan-refused tokens fail safely through stable codes; direct redemption remains email-agnostic and login-time email redemption remains verified-email gated.
- [x] Exact iOS/Android association documents and app claims are generated from real signing identifiers, with disabled output when both are absent and a build refusal for partial/malformed configuration.

- Signed physical-device Universal/App Link proof; it is consolidated into the existing real-device release gate `w11/m5/t007`.
