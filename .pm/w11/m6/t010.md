## Progress (2026-08-16) — focused composer pass

Expo MCP is now connected to the local SDK 57 app and its iOS XCTest automation
driver was used on an iPhone 17 Pro simulator (iOS 26.5). The repo composer was
opened from the Sessions route, interacted with, and re-viewed in both light and
dark themes.

- Finding: the full repository set was rendered inline inside one card, pushing
  Branch, Agent, and Task far below the initial viewport. The modal header also
  duplicated the app drawer/bell actions and overlapped the iOS status area.
- Initial fix: use a compact repository field rather than rendering every repo
  inline. Make the composer a full-screen safe-area modal with a focused title
  and close action.
- Follow-up Expo MCP finding: the shared wheel picker was the wrong list pattern.
  With the real repository set it reserved five centered wheel rows, left a large
  blank region below the title, pushed choices toward the bottom, and made long
  owner/repo labels difficult to scan.
- Follow-up fix and recheck: replace the wheel with a dedicated bottom sheet that
  has a compact, left-aligned, virtualized repository list, search field, selected
  checkmark, 44pt+ targets, and middle ellipsis for long labels. Expo MCP reopened
  the composer and picker, focused search, selected
  `bex-co/web-onefx-boilerplate`, observed the sheet close, and confirmed `main`
  filled in. The obsolete blank wheel space was gone.
- Automated recheck: the full `yarn test` gate passes (`format:check`,
  `typecheck`, `lint`, 333 unit tests, and `expo:check`); both `yarn bundle:ios`
  and `yarn bundle:android` export successfully.

This is partial evidence only. The task remains open for its compact-phone,
Chinese, keyboard/text-scale, detail/evidence, degraded, cancel, and GitHub
handoff matrix; it does not replace t009's physical-device/live-substrate proof.
