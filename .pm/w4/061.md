# 061 — Reject empty registry tokens before saving metadata

Why: An invalid credential update must not change a registry username or other metadata before returning an error, so private-image deployments keep using the last accepted credential.

**Estimate:** 45m. **Status:** todo. **Source:** user-approved `$pm-brainstorm for w4`, 2026-09-08; verified by source inspection, with runtime reproduction still pending. This is a sub-hour fix, so it stays in the inbox rather than becoming a milestone. It is independent of m97/m98.

## Finding

`lego/backend/internal/registrycreds/service.go:309` calls `UpdateRegistryCredential` before rejecting a non-nil empty secret at line 314. For example, an update containing a changed `name` or `username` together with `authToken: ""` reaches the metadata write and then returns a bad-request error. Metadata, expiry, and `updatedAt` may have changed despite rejection; the old token remains stored.

The REST, GraphQL, and MCP update adapters delegate to this Core method. `TestUpdateRejectsEmptySecretOrUsername` currently checks the returned error but does not assert unchanged stored state. The completed [w5/029](../w5/done/029.md) dashboard proof covers a blank form field being omitted to preserve the token; it does not cover an explicitly supplied empty API token.

## Work

1. Validate the complete update request, including an explicitly empty token, before any metadata or secret persistence in the shared Core method. Preserve omission as leave-unchanged.
2. Extend the existing rejection coverage with a request that attempts simultaneous name, username, expiry, and empty-token changes; assert both stores and `updatedAt` remain unchanged.
3. Verify the invariant through REST, GraphQL, and MCP, and retain successful metadata-only updates and non-empty token rotation. Run the focused package/surface tests and required applicable checks.

## Acceptance

- [ ] A rejected empty-token update leaves name, username, expiry, timestamps, and the stored token unchanged.
- [ ] Omitting `authToken` still preserves the stored secret; a valid non-empty token still rotates it.
- [ ] All existing update surfaces share the corrected behavior, and no response or test artifact discloses stored credentials.

**Files:** `lego/backend/internal/registrycreds/service.go`, `service_test.go`, and the existing REST/GraphQL/MCP adapter tests.
