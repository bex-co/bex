# 479 — A static-site rule refusal reads "Row 6: destination references :nobody, which routes[5].source does not declare"

Why: the dashboard turns the server's zero-based wire index into a person's row number, but only the first one. The undeclared-`:name` refusal names the index twice, so the same toast calls one rule both "Row 6" and "routes[5]".

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 44, 2026-11-05 05:14 UTC (`muse.env`, `bex-canary`, pin `dcdc774c1a6b`); **minor** (copy); ~20m.
- **Probe:** owned static site `qa-20261105-static` (`srv-dbm0uv0iff5c739puubg`, `examples/static-site`, deleted at 05:16). It had five saved routes. On `/static/<id>/redirects`, click **Add rule**, set Source `/u/:user` and Destination `/people/:nobody`, then click **Save**. The toast reads exactly: `Row 6: destination references :nobody, which routes[5].source does not declare`. `GET /v1/services/<id>/routes` still holds five routes, so the refusal itself is correct.
  - The same journey also showed that redirects (`/old` → 301), rewrites (`/app/*` → 200), `:postid` captures (`/blog/posts/42` → 301 `/b/42`), splats (`/docs/a/b.html` → 301 `/manual/a/b.html`), external redirects, and a header edit via **Save headers** all took effect on the served response within about 10 s.
- **Root cause:**
  - Backend `lego/backend/internal/apps/service.go:5558` formats the index twice: `routes[%d].destination references :%s, which routes[%d].source does not declare`. It is the only routes/headers message with two indices: `grep -nE '(routes|headers)\[%d\][^"]*(routes|headers)\[%d\]' lego/backend/internal` → 1 hit.
  - Dashboard `dashboard/src/features/services/lib/static-rule-validation.ts:165-173` `humanizeRuleError` replaces the first match only (the regex has no `g` flag). It has one caller, `hooks/use-static-site.ts:67-73`.
- **Fix (target behavior):** the toast reads `Row 6: destination references :nobody, which this rule's source does not declare`.
  - Change the backend message to name the source without a second index (`…, which the rule's source does not declare`). REST, GraphQL, MCP and Blueprint `routes:` share this validator, so every surface gets the clearer text.
  - Leave `humanizeRuleError` single-match. Add a dashboard test, and update any backend test that pins the old string.
  - Doc drift seen in the same pass: `docs/ADR029-static-sites.md:136` still says bex retains "no named-placeholder expansion". `:134` (w4/m240) and the live probe show `:name` captures are served. Delete that clause.
- **Blast radius:** one backend message, plus a dashboard helper with one caller. Other single-index refusals already read "Row N: …".
- **Unverified:** the GraphQL/MCP and Blueprint error text was not probed this round; it is inferred from the shared validator.
- **Render:** n/a (copy). Render's dashboard names the offending rule once.
- **Dedupe:** w4/145 (done) introduced the `Row {row}:` humanizer, and w4/m240 (done) added the `:name` refusal. Neither covered the two-index message. `grep -ril "source does not declare" .pm` hits only m240's spec text. No DO_NOT_DO item applies.
