# 512 — The service header's Connect panel is a Radix dropdown menu with no menu items, so keyboard focus stays on the menu and Tab or the arrow keys never reach its "Copy internal address" and "Copy SSH command" buttons

Why: Connect is where a customer copies the private address and the SSH command, and a keyboard-only or switch user can open it but cannot operate anything inside it. Mouse users can click the two Copy buttons, so the panel looks fine and the gap is invisible without a keyboard.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 108, 2026-11-05 UTC (`muse.env`, `bex-canary`); **minor** (accessibility, keyboard; the internal address also has a keyboard-reachable Copy in the header, see Adjacent); ~30m.
- **Probe:** read-only, signed in, on the existing production web service `agentmarketcap-1` (`srv-d9bkcspg9s7c73d0n8ug`), `/services/<id>`:
  - Focus the **Connect** button and press `Enter`. The menu opens; `document.activeElement` is the menu container (`role=menu`), not an item.
  - Then `ArrowDown`, `Tab`, `Tab`, `Shift+Tab`. After each key the menu is still open and `document.activeElement` is still the same container (`menu:Internalagentmarketcap-1:3000SSH`). Focus never lands on a Copy button.
  - `Escape` closes the menu and returns focus to **Connect**.
  - The menu's accessibility tree: `menu "Connect": text: Internal · code: agentmarketcap-1:3000 · button "Copy internal address" · text: SSH · code: ssh srv-d9bkcspg9s7c73d0n8ug@ssh.bex.co · button "Copy SSH command"`. It contains no `menuitem` at all: its only focusable-looking descendants are two plain `<button>`s.
  - Control in the same session: the **New**, **Help and resources**, **Account menu** and **Manual Deploy** menus each open with focus on a `menuitem`, expose named items (for example `Deploy latest commit`, `Restart service`), and return focus to their trigger on `Escape`.
- **Root cause:** the Connect panel is built with `DropdownMenu` / `DropdownMenuContent` (`dashboard/src/features/services/components/service-detail-header.tsx:373-462`) but its children are a `DropdownMenuLabel`, `ConnectCodeRow`s (a `code` plus a `CopyButton`) and, in other states, plain `Link`s (remedies, the add-key call to action, the browser terminal), not `DropdownMenuItem`s. The probe above shows the menu content keeping focus and `Tab` and the arrow keys doing nothing, so a menu with no items leaves focus nowhere to go (inferred from that behavior: I did not read Radix's source). The same container is why the tree has a `menu` role with no `menuitem`.
- **Fix (target behavior):** every control in Connect can be reached and activated with the keyboard, and the panel is announced for what it is.
  - Replace the dropdown with a non-modal Popover (`common/components/ui/popover.tsx`, already used by `logs/components/log-filter-bar.tsx`, `events/components/service-event-filter.tsx` and `agent-sessions/components/session-model-cost.tsx`). Tab then walks the Copy buttons and links in order, `Escape` closes it and returns focus to **Connect**.
  - Keep the controlled `open` state and the close-on-link behavior (`onClickCapture` at `:381-383`, w4/m183) so a remedy link still dismisses the panel.
  - Keep the content and copy of the existing rows; only the container changes.
  - The alternative of turning each row into a `DropdownMenuItem` that copies on select would also work but would make the code and link rows non-selectable text inside a menu; the Popover is the smaller change.
- **Tests:** a component test with `userEvent`: open Connect with `Enter`, `Tab` to `Copy internal address` and to `Copy SSH command` (assert `toHaveFocus()`), activate one with `Enter`, and assert `Escape` returns focus to the Connect button. Keep the existing w4/m183 test that a remedy link closes the panel.
- **Blast radius:** one component, one mount (`ServiceDetailHeader`); the Connect panel's states (running paid, Free, suspended, image ports pending) all share the same container, so all of them move together. Whether the Postgres and Key Value pages use a similar panel was not checked.
- **Adjacent classes:** the header already shows the internal address with its own Copy button (`service-detail-header.tsx:522`, `services.internalCopy`), so the address stays keyboard-reachable today. I did not find a keyboard-reachable copy of the SSH command: the Shell tab was not checked for one. The remedy links inside Connect in the Free and suspended states (w4/m183) sit in the same menu container and are expected to have the same problem; this run only exercised the paid, running state.
- **Unverified:** Free, suspended and no-key states of the panel (cause inferred from the shared container); screen-reader announcement (only the accessibility tree and focus were observed); behavior on touch.
- **Render:** n/a (keyboard operability of bex's own control).
- **Dedupe:** w4/143 and w4/m183 (done) made the panel's text and remedy links truthful and dismissable; neither tests keyboard focus inside it. `grep -rli "connect" .pm/w4` filtered by keyboard terms finds nothing about this panel. No DO_NOT_DO item applies.
