## Objective

Every App pod template carries `app.bex.co/environment-id=<env>`, the label Database and Key Value pods already carry, whether or not the environment is isolated. The label changes only when the service moves to another environment. That gives the network policies a peer identity that a toggle never has to rewrite.

## Context

- Today an App carries only `app.bex.co/network-isolation`, and only while its environment is isolated (`lego/operator/internal/controller/app_controller.go:222-233`). The comment there says "Apps don't carry that one at all, only their own environment_id store column."
- The backend stamps App labels through `applyAppEnvironmentLabels` (`lego/backend/internal/environments/service.go:1842-1861`). The environment id comes from the store's `environment_id` column, so the App CR needs a stable `core.LabelEnvironment` stamped wherever membership is written: create, `SetServices` and environment delete.
- The operator copies policy labels onto the template in `syncPolicyLabels` (`app_controller.go:7578-7583`).

## Steps

1. **Backend:** stamp `core.LabelEnvironment` on the App CR wherever its environment membership is written, and clear it when the service leaves every environment.
2. **Operator:** copy `environment-id` onto the pod template next to the plan label.
   - It changes only when membership changes, so a move rolls the service once, as it does today. That roll is expected.
   - An isolation toggle must not change any template label.
3. Keep `network-isolation` on the App CR, since the policies read the environment's state from it. Stop copying it onto pod templates once t002 no longer selects by it.

## Acceptance criteria

- [ ] A new service in an environment has `environment-id=<env>` on its pods. A service in no environment has none.
- [ ] Moving a service between environments changes the label, with one rollout.
- [ ] Toggling isolation changes no pod template.

## Outcome (2026-11-14)

Done. `applyAppEnvironmentLabels` now stamps `core.LabelEnvironment` with the isolation label on every membership write: `SetServices`, environment delete, the project clear, and `SetACL`. The create and Blueprint paths and the projector already stamped it. `appPodLabels`, the cron Job template and pre-deploy pods carry `environment-id`. The template never carries `network-isolation`. A move does not roll the service: the template holds the stored value (`holdIsolationLabel`) and `relabelAppPods` moves the running pods in place. Tests: `isolation_test.go`, `deployment_projection_test.go`, `acl_test.go`.
