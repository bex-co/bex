## Objective

All 11 tabs of a service share one `document.title`, so a tab switch gives assistive technology and browser history no signal. Prefix each tab's translated name to the existing service title.

## Context

- Live probe: deploys, logs, metrics, settings, env, events, scaling, shell, disk, plan (and the index) all have `document.title` exactly "reverse-proxy-poc ・ Web Service ・ bex Dashboard".
- `dashboard/src/routes/services.$serviceId.tsx:45-55` sets the title once via `titleHead(routeResourceTitle(...))`; none of the 11 child routes `services.$serviceId.*.tsx` defines `head:`.
- The sidebar already sets `aria-current="page"` on the active tab, so the tab names exist in the i18n catalog; reuse those labels so they cannot drift.

## Steps

1. Add a `head` to each child route (deploys, logs, metrics, settings, env, events, scaling, shell, disk, plan, headers, redirects, index) that prefixes the translated tab name, reusing `titleHead` / `translatedTitleHead`.
2. Add one test asserting every registered service tab route yields a distinct title that starts with the tab's name.
3. Probe whether Postgres, Key Value and static-site detail pages have the same pattern and record the result here (do not change them unless the pattern is confirmed and in scope).

## Files

- `dashboard/src/routes/services.$serviceId.*.tsx`
- the route/title test

## Acceptance criteria

- [ ] The tab URLs under one service have distinct `document.title` values, each starting with the tab name.
- [ ] The sidebar `aria-current="page"` label matches the title's first segment.
