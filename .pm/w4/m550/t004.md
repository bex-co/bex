## Objective

A member never clicks a bulk Suspend or Resume only to read 403: rows the caller cannot act on are disabled with the reason the service page already gives.

## Context

- Role-aware controls consume the GraphQL `serverActions` capability (w6/m143, w6/m146): `dashboard/src/features/capabilities/hooks/use-resource-actions.ts`, `dashboard/src/features/capabilities/lib/resource-actions.ts`, `dashboard/src/features/capabilities/hooks/use-bound-action-confirm.ts`.
- Render: in a protected environment only Admins suspend or resume. bex's `SuspendService` takes `confirm` for a protected environment's confirmation phrase.

## Steps

1. Read each selected row's capability; when any selected row is denied, disable the action (or exclude the row, per t001) and show the localized reason.
2. A selection in a protected environment asks for the protected confirmation once and passes it to each call.
3. A capability that changed between selection and confirmation is rechecked before sending (the w6/m146 freshness rule).

## Files

- the shared toolbar from t002
- `dashboard/src/features/capabilities/hooks/use-resource-actions.ts`

## Acceptance criteria

- [ ] On dev-4, a Developer in a protected environment sees Suspend/Resume disabled with a reason; an Admin is asked for the confirmation once and all rows change.
- [ ] A Viewer gets no enabled lifecycle action in the toolbar.
