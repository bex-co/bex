# 520 — The `/blueprints` header ("Blueprints" + Generate Blueprint + New Blueprint Instance) does not wrap and widens the whole page horizontally at 375 px and narrower

Why: on a phone-width window the Blueprints page scrolls sideways as a whole (the header buttons sit past the right edge), while every other list page I measured fits; a customer on a narrow screen has to pan to reach "New Blueprint Instance".

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 123, 2026-11-05 UTC (`muse.env`, `bex-canary`); **minor** (layout, narrow viewports); ~20m.
- **Probe:** read-only, signed in. Viewport 360×740, then each route loaded and `document.documentElement.scrollWidth` compared with `clientWidth`, plus a scan for elements whose right edge is past the viewport and that have no clipping ancestor. 19 routes: `/`, `/services`, `/databases`, `/keyvalue`, `/blueprints`, `/env-groups`, `/projects`, `/webhooks`, `/settings`, `/billing`, `/agents`, `/members`, `/audit-log`, `/api-keys`, `/account`, `/notifications`, `/templates` and two redirects. Only `/blueprints` overflows:

  | Viewport width | `/blueprints` `scrollWidth` |
  | --- | --- |
  | 320 | 382 |
  | 360 | 382 |
  | 375 | 382 |
  | 390 | 390 (fits) |
  | 414 | 414 (fits) |

  - At 360 the button row (`div.flex.items-center.gap-2`, "Generate Blueprint" + "New Blueprint Instance") spans left 29 → right 382, 22 px past the 360 px viewport; the "New Blueprint Instance" button alone is left 187 → right 382.
  - The page's table (left 17 → right 515) is wider than the viewport too, but it did not widen the page in this measurement (the page width stays 382, set by the button row); whether the table scrolls inside its own container was not inspected.
  - Control, round 124 (same method, 360 px): 22 further routes fit (`scrollWidth` 360/360) — `/blueprints/new`, the blueprint detail, Postgres, Key Value and env-group details, every service tab (deploys, events, logs, metrics, environment, settings, scaling, shell) for a web and a private service, `/keyvalue/new`, `/services/new`, `/webhooks/new`, `/projects/new`.
  - Screenshot (local, gitignored): `.playwright-mcp/qa-blueprints-1.png`.
- **Root cause:** `dashboard/src/routes/blueprints.tsx:87-105`: the header is `flex items-center justify-between border-b px-4 py-4 sm:px-6` with an `<h1>` and a `div.flex.items-center.gap-2` holding two `size="sm"` buttons. Neither flex item can shrink or wrap (no `flex-wrap`, no `min-w-0`, and the button labels are `whitespace-nowrap`), so below about 380 px the row is wider than the content box and the page grows. The longer labels "Generate Blueprint" and "New Blueprint Instance" (`blueprints.generateButton`, `blueprints.createButton` in `features/blueprints/locales/en.ts:39,442`) are why this page overflows and the others do not.
- **Fix (target behavior):** the header fits at 320 px and up with no page-level horizontal scroll.
  - Let the header wrap (`flex-wrap gap-2`) so the buttons drop below the title on narrow widths, keeping the one-row layout from `sm` up.
  - Check the zh labels at the same widths, since they have different lengths.
- **Tests:** a render/layout check at 320 and 360 px asserting `scrollWidth <= clientWidth` for the page, with a wide-viewport control that keeps the single row; the existing page tests stay.
- **Blast radius:** one route header. The same `flex items-center justify-between border-b px-4 py-4` header string occurs once in `dashboard/src/routes` (`grep -c` → 1 match), so no sibling needs the same change; other headers with two action buttons were not individually measured beyond the 19 routes above.
- **Adjacent classes:** none (layout only).
- **Unverified:** the zh rendering; the table's own horizontal scroll inside its container; widths between 376 and 389 px.
- **Render:** n/a (dashboard layout).
- **Dedupe:** `grep -rli` over `.pm` finds w4/239 (done), which is the Generate Blueprint _dialog_ widening, a different element; no item covers the page header. No DO_NOT_DO item applies.
