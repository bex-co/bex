# A static site created with routes keeps each route's `priority`, as Render's create contract says

Why: Render parity — Render's create contract gives each route a `priority` ("Redirect and Rewrite Rules are applied in priority order starting at 0. Defaults to last in the priority list"), and bex silently drops it at create, ordering rules by array position only.

- **Render:** the pinned OpenAPI (`lego/backend/internal/api/openapi/render-public-api-1.json`): `staticSiteDetailsPOST.routes` items are `routePost`, which carries `priority`. The bulk replace (`PUT /services/{id}/routes`) takes `routePut`, which has no `priority`, so array order is right there.
- **bex:** `StaticRouteView` (`lego/backend/internal/apps/service.go:883-887`) has no `priority`; the create request embeds it and service decoding is lenient, so the field is ignored. The single-rule add endpoint already honors it (`lego/backend/internal/apps/rest.go:1563-1567`).
- **Do:** at REST create, order routes by `priority` (routes without one keep their array order, after those with one; ties keep array order), apply the same in MCP create if it takes routes, and leave GraphQL's `StaticRouteInput` (no `priority`) and the bulk PUT unchanged. Add a test and note it in ADR018's static-site row.
- **End state:** `POST /v1/services` for a static site with routes `[{…, priority: 1}, {…, priority: 0}]` stores and applies the second rule first.
- **Size:** about 1h.
