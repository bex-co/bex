# 550 — The webhook event picker lists `disk_snapshot_restored` raw under "Other" instead of as "Disk Snapshot Restored" in the Disk group

Why: every other event in the picker has a human label inside its group. This one appears as a raw API key under a catch-all "Other" group, so a user choosing disk events misses it, and the zh UI shows English snake_case.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 22, 2026-11-10 13:41–14:00 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor** (wrong English / i18n gap). A residual of [w2/064](../w2/done/064.md). ~15m.
- **Fixtures:** both deleted (GET 404, URL 404).
  - Echo receiver `qa-20261110-hook` (`srv-dbphuu45ngvc73e8tqpg`, `docker.io/mendhak/http-https-echo:35`).
  - Webhook `qa-20261110-wh` (`whk-dbpi04tme2kc73f2l6cg`), subscribed to the Deploy group, URL `https://qa-20261110-hook.onbex.co/qa-hook`.
- **The delivery journey itself was clean:**
  - A manual deploy delivered Deploy Started and Deploy Ended. Recent deliveries showed each as `Delivered · 1 · HTTP 200`.
  - The receiver logged Render's payload shape, `{"type":"deploy_ended","timestamp":…,"data":{"id":"evt-…","serviceId":"srv-dbphuu45ngvc73e8tqpg","serviceName":"qa-20261110-hook","status":"succeeded"}}`, with a `webhook-signature` header.
- **Probe:** on `/webhooks/new`, under "Events to send", every group is human-labeled except the last: `listitem: checkbox "Other" … checkbox "disk_snapshot_restored"`.
- **Root cause:**
  - The webhook catalog's `GROUPS.disk` is `["disk_created", "disk_updated", "disk_deleted"]` (`dashboard/src/features/webhooks/event-catalog.ts:38`).
  - `eventLabelKey` (`:96-101`) only knows types in `GROUPS` and `SINGLES`, so it returns null for `disk_snapshot_restored`.
  - The picker then renders the raw key under "Other", the fallback documented at `components/event-picker.tsx:35`.
  - There is no `webhooks.event.disk_snapshot_restored` key in `locales/en.ts` (the other disk labels are at `:607-618`) or `zh.ts` (`:594-605`).
  - w2/064 (done) made the backend record and serve `disk_snapshot_restored` as a webhook type (`events/service.go:299`, `TypeDiskSnapshotRestored`). Its Do list included "dashboard event label (en/zh)", but that label landed only in the service Events catalog (`features/events/service-event-catalog.ts:107,173`, `services.eventsTypeDiskSnapshotRestored`), not the webhook catalog.
- **Fix:**
  - Add `disk_snapshot_restored` to `GROUPS.disk`.
  - Add `webhooks.event.disk_snapshot_restored`: "Disk Snapshot Restored" in en, plus zh.
  - Add a catalog test that every type in the served webhook vocabulary fixture has a label, so the next backend addition fails a test instead of shipping raw.
- **Blast radius:** `eventLabelKey` has three callers: `webhook-event-chips.tsx`, `webhooks-panel.tsx` and `webhook-deliveries-card.tsx`. All three pick up the label. The picker's "Other" group disappears whenever no unknown type is served.
- **Unverified:**
  - Whether any other served type also falls to "Other" in another workspace; only this one was seen.
  - Render's dashboard label wording for this type.
- **Dedupe:**
  - `grep disk_snapshot_restored .pm` finds only w2/064 (done) and the w2 README. No open item.
  - Not deploy lag: `git log c12cd57facb1..origin/main -- dashboard/src/features/webhooks` is empty.
- **DoD (live):**
  - `/webhooks/new` lists "Disk Snapshot Restored" inside the Disk group, in en and zh, and shows no "Other" group.
  - A webhook subscribed to this event shows the human label in its event chips.
