# 377 — A static-site directory requested without a trailing slash serves the homepage

Why: a static site that publishes `blog/index.html` answers `/blog` with **200 and the site's root `index.html`**, not the blog page. Any link written without a trailing slash, which directory-format generators such as Astro and Docusaurus routinely emit, silently shows the wrong page. ADR029's own justification for the implicit SPA fallback is that "it never hides a real asset", and here it hides one.

**Severity:** major (the request completes and the site shows other content). **Estimate:** ~50m. **Source:** live `/qa-find-bugs w4` loop run d4e2, 2026-10-20 UTC, `muse.env`, workspace `bex-canary`. Fixture static site `qa-20261020-d4e2-static` (`srv-dbbh16mcbnls73997bjg`) was deleted in-run; the session was revoked.

## Repro (production, all run this pass)

Static site from Public Git URL `https://github.com/bex-co/bex`, branch `main`, root `examples/static-site`, publish directory `.`, auto-deploy off. Build command:

```sh
mkdir -p blog docs && printf 'blog-index-d4e2\n' > blog/index.html && printf 'docs-page-d4e2\n' > docs/page.html && printf 'custom-404-d4e2\n' > 404.html && printf 'body{}\n' > app.css
```

It reached Live; the first-deploy 503 then 200 behaved as `w4/m235` intends. Then:

```
GET /blog/            -> 200 etag "9wdI7WY9G84i38FxT1FrHg"  body: blog-index-d4e2
GET /blog/index.html  -> 200                                body: blog-index-d4e2
GET /blog             -> 200 etag "HrQEHhF0qvX8DRncUE_Myg"  body: <!doctype html> <html lang="en"> …   (root index.html)
GET /blog?ref=x       -> 200 etag "HrQEHhF0qvX8DRncUE_Myg"  (same)
GET /                 -> 200 etag "HrQEHhF0qvX8DRncUE_Myg"
md5(GET /) = md5(GET /blog) = md5(examples/static-site/index.html) = 582b88ddc23f770e96d6ddfb8bf603ca
```

A saved rewrite rule `/bloghome → /blog` (dashboard Redirects/Rewrites, "Routes updated") also served the root page: `GET /bloghome -> 200`, etag `HrQEHhF0…`. With a header rule `/blog/*` → `X-QA-D4E2: blog-scope`, `GET /blog` carried the blog-scoped header on the homepage body.

The controls behave as documented: an extension-bearing miss `/missing.css` → 404; extensionless misses with no directory index (`/missing`, `/docs`, `/docs/page`) → root `index.html` (ADR029's deliberate SPA fallback); redirect `/legacy/* → /blog/:splat` → 301 `/blog/`.

## Root cause

- `lookupPath` (`lego/operator/internal/staticserver/staticserver.go:443-450`) defaults to `index.html` only for `/` or a path ending in `/`, so `/blog` is looked up as the object `blog` and misses.
- The miss goes through the rules (`:281`), then the SPA fallback (`:326-334`). `spaFallback` (`:455-465`) serves the root `index.html` for any extensionless miss without first checking whether `<path>/index.html` exists.
- The rewrite branch (`:309-324`) has the same gap: its `h.fetch(fallbackPath)` resolves `/blog` the same way, so a rewrite to a directory without a slash also falls back to the root.

## Fix (target behavior)

- When a GET/HEAD request path has no trailing slash and no file extension, misses as an object, and `<path>/index.html` exists, answer **301** to `<path>/`.
  - Preserve the raw query string.
  - Apply the matching custom headers, as every resolved-site response class does (`w4/m101`).
  - This is a published-object hit, so it takes precedence over the ordered rules and the SPA fallback, in line with ADR029 "an existing published object wins over every rule".
  - A redirect rather than serving the index in place keeps relative links inside `blog/index.html` resolving under `/blog/`. That matches nginx `try_files`/S3 website endpoints/GitHub Pages directory semantics.
- A **rewrite** whose decoded destination is such a directory serves `<dest>/index.html` with 200, as a rewrite should. It does not redirect.
- Unchanged:
  - extensionless misses with no directory index keep the SPA fallback;
  - extension-bearing misses keep 404;
  - overlong paths keep 404;
  - origin errors keep their classes (502/413/503);
  - the cache keys and `defaultCacheControl` behave as today.
- Record the redirect in ADR029 next to the "Default SPA fallback" section and the ADR018 static-site row. Render's static-site and redirect docs (checked 2026-10-20) are silent on directory resolution, so this is named as bex's directory semantics, not a claimed Render capture.
