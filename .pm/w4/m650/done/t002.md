## Objective

For the native builder, give BuildKit the bounded repository root as its build context, copy it to `/opt/render/project/src`, and keep the build, pre-deploy and start commands' working directory at `/opt/render/project/src/<rootDir>`. Dockerfile builds keep today's context (`dockerContext`, else Root Directory).

## Context

- `dockerContextDir` (`lego/operator/internal/build/dockerinputs.go:180`) is `boundedSourceDir(cmp.Or(o.DockerContext, o.RootDir))`, and `build.go:1551-1556` passes it as `--local context=` for every builder.
- The native Dockerfile runs `COPY . .` (`lego/operator/internal/build/native.go:529`) into `NativeSourceDir` (`native.go:651`), which is `nativeRootDir(rootDir)` under `NativeWorkdir` (`native.go:663`). So a native image holds only the Root Directory.
- `boundedSourceDir` (`build.go:1484`) refuses a directory that escapes the checkout; keep that guard.
- Autodeploy decisions (Root Directory and Build Filters, w7/m428) are separate from the build context and do not change here.

## Steps

1. Choose the context by builder: native → the bounded repository root, with `.git` excluded; Dockerfile → unchanged.
2. Make the native Dockerfile copy the whole repository into `NativeWorkdir` and set `WORKDIR` to `NativeSourceDir(runtime, repo, rootDir)` for the build, pre-deploy and start commands.
3. Add unit tests that generate the native build for an empty Root Directory and for `cmd/api`, and a Dockerfile build with a Root Directory.

## Result (2026-11-25)

- `nativeContextDir` (`lego/operator/internal/build/native.go`) gives a native build `--local context=/source`, the whole checkout; `BuildJob` uses it for `BuilderNative` and keeps `dockerContextDir` for Dockerfile builds. A native build ignores `dockerContext`, a Dockerfile-only field.
- `nativeSourceCopy` writes `WORKDIR <repo dir>`, `COPY . .`, `WORKDIR <root dir>` (then Go's link), so the build command and every workload start in the Root Directory: `/opt/render/project/src/cmd/api`, or `/opt/render/project/go/src/github.com/<owner>/<repo>/cmd/api` for Go. Without a Root Directory the lines are unchanged.
- `.git` stays out: the clone step already removes the checkout's, and the preparer now writes `/native/Dockerfile.dockerignore` (`.git`, `**/.git`), which BuildKit reads in place of the repository's `.dockerignore`.
- A Root Directory that escapes is still contained (`../../apps/web` is the repository's `apps/web`) and a link out is still refused by the clone step (`TestCloneRefusesALinkThatLeavesTheRepository`, unchanged). A Root Directory the `WORKDIR` line cannot take as is (`my app`, `a/$HOME`) keeps its root-directory-only context and its old Dockerfile.
- Tests: `TestNativeBuildReadsTheWholeRepository`, `TestNativeRootDirectoryWithNoPlaceKeepsItsOwnContext`, `TestDockerfileBuildContextIsItsRootDirectory` (nine `rootDir` × `dockerContext` combinations), `TestNativePreparerWritesTheDockerfilesIgnoreFile` in `nativerepo_test.go`; `TestNativeRootDirectoryIsTheWorkdir` updated.
