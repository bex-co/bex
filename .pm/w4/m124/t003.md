## Objective

`changedFields` currently answers "what does this manifest declare", which is information the caller already has. Make it answer "what differs", which is the only reason to return it.

## Context

- `blueprint_state_plan.go:188,206,217,225` — all four branches assign `blueprintPlanFieldChanges(resource.Fields)`. Nothing compares.
- `blueprint_ir.go:306` — `changedBlueprintFields(resource.Fields, current.Fields)` is the shape that does compare, already in this package. Check whether it is reusable here or whether the state plan needs its own, since it diffs against a live spec rather than a previous IR.
- Live symptoms: `databases:` with a changed `plan` reports `["name","plan"]` — `name` is the key the resource was matched by; two `services:` manifests differing in `healthCheckPath` and `startCommand` report the same ten paths.
- The appliers already compute the answer implicitly: each one copies field by field and then `DeepEqual`s. Recording which assignment changed something is a small extension of that loop, not a new comparison engine.
- Values must stay out. `w6/m125` notes `changedFields` carries paths and no values for a reason — a manifest field can be a secret.

## Steps

1. Extend the appliers (or wrap them) so each records the field paths whose assignment actually changed `dst`.
2. Return those instead of the declared set, for all four kinds.
3. Keep the env-group branch's deliberate always-`update` behavior, but make its field list honest about being declarations rather than diffs, or empty.
4. Confirm no value ever enters the payload.

- [ ] A one-field change reports exactly that field.

- [ ] `noop` actions report an empty list.
- [ ] No field value appears in the payload.
