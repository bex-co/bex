# Unchanged image sources enable Update source and report a successful change

Why: opening the Source editor with no edits offers a save and reports “Source updated” even though the configured source is unchanged.

**Severity:** minor — false dirty state, redundant mutation and misleading confirmation. **Estimate:** 35m (representation/caller audit 10m, local predicate 5m, parent behavior tests 15m, Simplify and live repeat 5m). **Status:** open. Source: continuous functional `$qa-find-bugs w4`, a285, 2026-10-12 UTC, muse.env login helper. Goal: reliable hosting configuration editing under [ADR008](../../docs/ADR008-vision.md) and [ADR026](../../docs/ADR026-github-integration.md).

## Reproduction and controls

Owned Free web service `qa-20261012-a285-source`, `srv-db6bdpkionnc73bk1en0`, public `docker.io/library/busybox:1.37.0`, port 3000. Its command writes the BusyBox version to a public index and starts httpd.

At **10:31:45.570Z**, the fresh API read returns `repo:""`, configured image 1.37.0, Running at rev-1 and one Live create deploy. Its native public GET returns 200 and the exact 1.37.0 version line. Open Settings → Source → Edit. Without changing the image or credential, **Update source is enabled**. Click it at **10:32:17.601Z**: the actual SetImage request resubmits the same image, the response retains it, the dialog closes and the toast says **Source updated.** Reopening at **10:32:17.928Z** again enables Update source without any edit.

Fresh **390×844** reload at **10:32:44.533Z** independently reproduces enabled Save with the unchanged image. Adding only outer spaces remains falsely dirty. Clearing the image disables Save correctly. Editing to 1.36.1, then Cancel and reopen, correctly restores the saved 1.37.0 draft but still enables Save. The dialog fits within the viewport (356 px dialog, 390 px document).

The real-change control passes: Save 1.36.1 at **10:32:45.680Z**. **Target:** a fresh or canceled image draft with unchanged trimmed image and unchanged credential has disabled Update source. A real image/credential/source-kind change enables it. Preserve save-without-deploy and subsequent manual deployment. No unintended automatic rollout or backend false-change event is claimed.

## Root cause and local fix

Baseline: current main `fd348ed1e7e44d6fac001edb332f12ff790e3b72`; clean pull remained up to date. Target history attributes the strict-null source-kind checks to `fa7b99932`, with no newer predicate fix.

- `dashboard/src/features/services/components/service-source-card.tsx:138–145` uses `repo !== null` to declare an image draft dirty, and `repo === null` for Git source transitions. The real no-repository value is an empty string, so the first condition is always true on an image-backed service. `:117,151` already uses repository presence to choose the source tab, and the card uses the same presence test for its label. The editor's dirty predicate disagrees with its own source-kind presentation.
- `features/services/lib/status.ts:69` preserves `""` through `s.repo ?? null`. The sole production caller at `routes/services.$serviceId.settings.tsx:189–195` also preserves it. Backend `apps/graphql.go:411–418` deliberately exposes repo/branch as empty strings for image-backed Apps; `gqlutil/gqlutil.go:34–44,55–61` projects that string unchanged. This representation is supported; changing the shared mapper/API to conceal the predicate error would widen the fix unnecessarily.
- `service-source-card.tsx:169–184,252–260` submits the enabled draft and closes on success. `use-set-image.ts:24–40` delegates to `useFieldMutation`, whose accepted response produces the normal success toast. The backend `apps/graphql.go:1570–1588` delegates to `service.go:4100–4122`; the latter explicitly returns the current view without a write when the resolved source is unchanged. The API is accepting an idempotent request, not promising that a field changed.
- Existing component tests at `__tests__/service-source-card.test.tsx:167–211` use `repo={null}` for image services. They exercise changed image and Git conversion, but omit the empty-string representation delivered by the real Server query.
- Installed React/react-dom 19.2.3, Apollo Client 4.1.3 and TanStack Router 1.170.25 are the same dependencies inspected in a284. The installed React state path retains state across updates; this editor explicitly resets its draft on open. Repeated open/reload receipts match that reset. The false dirty state comes from the application's strict-null expression, not retained framework state.

Use one local repository-presence predicate in both dirty branches, consistent with the existing tab/card source-kind checks. Keep current trimmed-image and credential comparison, default-branch behavior, validity gating and open/reset behavior. Scope the fix to SourceEditDialog; preserve public API empty-string output, shared view mapping and mutation/toast helpers. Empty and null repositories must both mean image source for this decision.

Production census: **one SourceEditDialog implementation and mount**, **one ServiceSourceCard implementation and production mount**, **one shared Settings page**. `features/services/lib/settings-sections.ts:59–70` mounts Source for web/private/background-worker services; cron and static use other source/build sections, and PostgreSQL/Key Value have separate pages. The static Settings alias reuses the shared page but does not mount this Source card. Live proof covers web only. Git transitions and credential changes remain implementation verification work, not claimed live evidence.
