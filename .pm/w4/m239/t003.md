## Objective

Make a release the operator adopts without a matching deploy row impossible, or at least visible and self-healing, so the next real deploy cannot be stranded at `created` (finding, deploy B).

## Context

- `recordDeploy` (`lego/backend/internal/store/reconciler.go:844-845`) matches a row only by generation.
- `supersededDeployStatus` (`:1578`, `:1647-1648`) returns "settled, no status" while the release is behind the row, until the 18-minute gate (`:120`) or a superseding deploy (`:1610-1620`) closes it `canceled`.
- B was `canceled` with "Superseded by …" although the site was serving its content. In fact it was serving the rowless rev-2.
- `w8/m117` (blocked) changes the same function for the cancel trigger. Coordinate with it and do not duplicate it.

## Steps

1. Choose one of the following and record it in ADR004:
   - (a) a backend guard that refuses or flags any CR write which changes the release identity without stamping a release generation; or
   - (b) the reconciler records an observed release that has no row as a system deploy row (Render-shaped trigger), so history is complete; or
   - (c) both.
2. Make sure that a row minted while a rowless release is in flight is adopted once its own generation is built, and is never left at `created` with null timestamps.

## Acceptance criteria

- [ ] A reconciler test: a rowless release N is in flight and row N+1 is minted. N+1 reaches `live` with timestamps and events, and no row is labeled `canceled` for a release that served.
- [ ] The `w8/m117` tests stay green.

## Out of scope

- The cancel trigger itself (`w8/m117`).
