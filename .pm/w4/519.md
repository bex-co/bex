# 519 — A sweep of every GraphQL query's string and ID arguments with a NUL byte finds ten more inputs that answer `INTERNAL` or "authorization service unavailable" (auditLogs, webhookEndpoint, webhookDeliveries, workspaceInvites, gitClaimSelection, workspaceCreationAttempt, agent ids), beyond w4/518 — one GraphQL-boundary guard closes the class

Why: w4/485-492 closed this input class route by route on REST, and w4/518 found it again on the agent routes; a mechanical sweep shows it is still open on a long tail of GraphQL fields because each resolver hands `p.Args[...]` straight to a service. Fixing them one at a time will keep missing the next field; a single check where GraphQL arguments are read closes all of them, including ones not yet written.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 117, 2026-11-05 UTC (`muse.env`, `bex-canary`); **minor** (crafted input yields a 5xx-class answer; no data effect); ~60m.
- **Probe:** read-only, signed in, from the page. Introspect `Query` (`__schema { queryType { fields … } }`), and for every root field that has a `String` or `ID` argument, send one query per such argument with `"\u0000"` in that argument and valid placeholders for the other required scalar arguments (the workspace id real, others `"x"` / `1`). 220 requests, 650 ms apart. 4 fields were skipped because they have required arguments that are not scalars. - **Root cause:** per-resolver, not one bug. The GraphQL resolvers pass the raw argument on: `lego/backend/internal/audit/graphql.go:119` (`s.List(p.Context, p.Args["ownerId"].(string), f)`), `members/graphql.go:150,157,164` (`p.Args["workspaceId"]` into the member, invite and seat-usage reads), and the stores bind caller strings with no `textBindable` guard or error mapping: `store/webhooks.go:244-249` (`GetWebhookEndpoint`), `store/workspace_creation.go:121-127` (`GetWorkspaceCreationAttempt` returns the raw error) and `store/audit.go:186+` (`ListAuditEvents`, cursor). w4/489's workspace-name check (`core/base.go:2293` `validWorkspaceName`) and the object check (`:2301` `validFGAObject`) sit in the REST workspace-resolution path and are not reached by these GraphQL fields; how each "authorization service unavailable" row gets there was not traced.
- **Fix (target behavior):** one check where GraphQL arguments are read, instead of N resolver patches.
  - A string or ID argument, literal or variable, that is not valid UTF-8 or contains NUL is refused before any resolver runs, with a GraphQL error that names the argument and carries a stable code (REST's wording for the same case is `invalid query parameter "<name>"` with a 400, w4/489; use the equivalent so a client branches on the code). No store or authorization call sees the value. It depends only on the string's validity, never on membership or existence, so it is no existence oracle.
  - The natural place is the GraphQL request handler (scan the parsed literals and the variables map) or the shared argument helpers in `gqlutil`; both cover queries, mutation arguments and input-object fields, which this sweep did not exercise.
  - This makes the per-field answers in w4/518 for ids, filters and cursors a 400-class refusal at the boundary rather than the "empty page" / `FORBIDDEN` it proposes field by field; whichever lands first, the two notes must not leave the surfaces disagreeing, and REST (the `audit-logs` cursor above, 518's REST filters) needs the same early refusal in its own boundary.
  - Keep the store-level `textBindable` guards from w4/518 as defense in depth for non-GraphQL callers.
- **Tests:** a GraphQL handler test over the introspected schema: for every `String`/`ID` query argument, send `"\u0000"` and an invalid-UTF-8 variable and assert the refusal code and that no resolver ran; a legal control (an emoji, a 256-character name, a real id) passes untouched; a mutation with a NUL in an input field refuses too.
- **Blast radius:** all GraphQL queries and mutations (one handler). REST needs its own boundary check (not part of this note's fix). Callers that currently answer a legal id with `NOT_FOUND` / `FORBIDDEN` are unaffected, since only NUL and invalid UTF-8 are refused.
- **Adjacent classes:** unauthenticated (401) and rate limit keep their place ahead of it; a well-formed foreign id keeps `FORBIDDEN` / `NOT_FOUND`; a real outage keeps `UNAVAILABLE` (assert with a failing store).
- **Unverified:** mutations and input-object fields; the 4 skipped queries; MCP tools (separate argument parsing); REST routes other than the two probed (`audit-logs` cursor, `webhooks` `ownerId`); the exact path by which each "authorization service unavailable" row reaches that error; invalid UTF-8 (only NUL was swept for GraphQL, because a JSON request body cannot carry a lone invalid byte and the escape `\ud800` was not tried).
- **Render:** n/a (internal error shapes); Render's API answers a malformed parameter with a 400 naming it.
- **Dedupe:** w4/489, 490, 491 and 492 (done) and w4/518 (open) are the neighbours; none names `auditLogs`, `webhookEndpoint`, `webhookDeliveries`, `workspaceInvites`, `gitClaimSelection` or `workspaceCreationAttempt`, and none proposes the boundary guard. No DO_NOT_DO item applies.
