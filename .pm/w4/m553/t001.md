## Objective

A check, in the style of the other Render drift scripts, that fails when Render's changelog has an entry bex has not dispositioned.

## Context

- Existing drift scripts check, never update: `scripts/render-schema-drift.sh` (Blueprint schema, webhook events, OpenAPI, CLI release) and `scripts/render-mcp-drift.sh`, each with a `.test.sh`. None reads the changelog, so dashboard-only features go unseen (bulk suspend/resume 2025-08-27, Postgres admin apps 2024-06-04, log line detail view 2025-12-17: w4/m550–m552).
- Render publishes an Atom feed at `https://render.com/changelog/feed.xml` (checked 2026-11-20: HTTP 200, `application/atom+xml`, the latest 10 entries, each `<id>` the entry's URL).

## Steps

1. Fetch the feed into a temporary directory; parse each entry's `<id>`, title and date.
2. Read the disposition table from t002 (`docs/render-artifacts/render-changelog.md`, a Markdown table keyed by entry URL).
3. Exit non-zero listing every feed entry with no row; exit 0 otherwise. Never write the table.
4. `scripts/render-changelog-drift.test.sh` runs the script against local fixture feeds: all known → 0; one unknown → non-zero naming it; a malformed feed → non-zero with a clear message.
