# Multiline .env import drops whitespace inside the opening quoted line

Why: importing a working configuration silently changes a quoted value before it is saved, so a pasted or uploaded file can configure a service differently from the original.

**Minor functional bug · estimate 50m.** Found on dashboard.bex.co on 2026-10-12, continuous QA pass a281, filing to w4 as requested. One shared parser correction plus behavioral checks; no product implementation in this filing. Own unlinked group `evg-db6aolcm5k5s73edf440` (`qa-20261012-a281-dotenv`) was created, used, and deleted.

**Reproduce.** Environment Groups → New Environment Group → Import from .env. Paste `QA_A281_DOUBLE="first  ` followed by a physical newline and `second 雪  `, another newline, and `last  "`. The exact input and character-preserving draft are below. A single-quoted equivalent loses its first-line tab and space. An equivalent double-quoted assignment using newline escapes keeps the two spaces. All six values were then read freshly from the owned group's API; storage retained exactly the already-altered request values.

**Independent replay.** Edit the owned group → Add variable → Import from .env → choose the 181-byte synthetic file below. Save only returns HTTP200, revision 1→2, no rollout, and fresh reads confirm both losses. A mobile390 pasted import repeats `line1  \nline2` → `line1\nline2`; that draft was canceled. This is whitespace inside quotes, not the intentional trimming of an unquoted value.

**Cause.** `dashboard/src/features/services/lib/dotenv-import.ts:66` applies `lines[index].trim()` to an assignment before determining whether its quoted value continues on the next line. That destroys opening-line whitespace inside the still-open quote. Lines78–86 subsequently append continuation lines unchanged, explaining why later whitespace survives. `parseValue:103` trims the assembled source outside its enclosing quotes; the incomplete preliminary parse does not mutate `raw`, so retaining the raw assignment's tail until assembly is enough.

`EnvImportDialog:58–62` calls this parser for both paste and file; `chooseFile:68–76` reads the file text without trimming. The captured textarea equals the input, ruling out input normalization as the cause. The creation host `new-env-group-dialog.tsx:245–265` and existing editor `service-environment-editor.tsx:453–478` copy parsed values into drafts. Actual mutation requests already have the loss, and fresh stored values equal those requests. No backend value normalization change is indicated.
