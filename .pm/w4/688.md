# 688 — A free service's Scaling tab shifts when its autoscaling read settles: the Autoscaling card's loading block is 56 px taller than the ready card, and the manual-scaling slot is a 126 px generic card where a 210 px Manual Scaling card lands (+124 px at 390)

Why: the dashboard rule ([AGENTS.md](../../AGENTS.md), "Dashboard preloading skeletons must match their post-loading contents") asks for a stable frame. Two done tasks promised it on this page: w9/m63 t003 ("Scaling tab has no layout shift when the manual card appears") and the shape gate of w5/m79 t018. On a free plan, the ready layout is fully known before the autoscaling read returns: autoscaling cannot be on, so the Manual Scaling card always shows. The plan comes from the service, which is already loaded.

- **Source / severity / estimate:** live `/qa-find-bugs w4` round 495, 2026-11-16 07:45–07:55 UTC, pin `3c6654df60a2`, workspace `bex-canary`, the canary `hello-go` (`srv-dbkq3hdhhjfs73eiahe0`). It is free, with autoscaling `{"enabled": false}`, and was viewed only. **Minor:** a layout shift, and nothing is lost. A regression of w9/m63 t003. ~40m.
- **Probe:**
  - Open the service's overview and hold every `/graphql` request 4 s with a Playwright route.
  - Click the Scaling tab (at 390, through the Toggle Sidebar drawer).
  - Read the page's cards at 1.8 s, and again 5 s after the hold is released.
  - The service is cached, so the route's `ServiceScalingSkeleton` does not mount. Only `useAutoscaling` is pending.
- **Card heights, pending → ready:**

  | Card | 1440 | 390 |
  | --- | --- | --- |
  | Autoscaling | 178 → 122 (header 40 → 44, content 80 → 20) | 198 → 202 (header 60 → 104, content 80 → 40) |
  | manual slot | 126 untitled → **Manual Scaling** 210 | 126 → 250 |
  | Recent Metrics top | 627 → 655 | 732 → 860 |

  - Pending, the Autoscaling card is a title, the description and an `h-20` block, with no switch.
  - Ready, it carries the "Autoscaling off" switch in the header and the one-line hint "Autoscaling is available on paid plans. Upgrade to enable it."
  - The manual slot is a generic card skeleton. Ready, it holds the title, the description "Free services run a single instance…", the Instances field (`1`) and Save Changes.
- **Cause:**
  - `AutoscalingSection`'s loading branch draws the header without the switch, then one `h-20` skeleton (`dashboard/src/features/services/components/autoscaling-section.tsx:300-312`).
  - Its ready card puts the switch in the header (`:316-330`) and, when `!eligible`, the paid-plans hint (`:340-358`). `eligible` is `plan !== "free"` (`:247`) and is known while the read is pending.
  - The page reserves the manual slot with `CardSkeleton rows={2}` (`routes/services.$serviceId.scaling.tsx:76-78`; `common/components/detail-skeletons.tsx:169`). That card has no title and is shaped unlike `ManualScalingSection` (`features/services/components/manual-scaling-section.tsx`).
- **Fix:**
  - While `useAutoscaling` loads, draw the autoscaling-off frame:
    - the Autoscaling header with the switch slot;
    - for a free plan, the hint line;
    - a Manual Scaling placeholder at that card's geometry: title, description, the Instances label and field, and the button.
  - Shape the placeholder from `service.plan` the way the ready cards are.
  - For a paid service whose autoscaling turns out to be on, the swap to the expanded form depends on data and stays a residual.
  - Pin it with a route test next to `routes/__tests__/services.$serviceId.scaling.test.tsx`.
- **Blast radius:**
  - `AutoscalingSection` renders only on this tab.
  - `CardSkeleton` has other callers, so leave it unchanged and replace only this use.
- **Unverified:**
  - a paid service's off-state geometry (no paid `qa-` service was created);
  - the route-level `ServiceScalingSkeleton` (`common/components/route-skeletons.tsx:2447`), which this path does not mount;
  - zh widths.
- **Render:** n/a (loading layout).
- **Done when:**
