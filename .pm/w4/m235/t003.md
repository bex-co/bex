## Objective

A static site's host is routed from creation and answers t001's first-publish response until its first revision is published. It never answers Traefik's `404 page not found` or the static-server's `no static site for host` in that window.

## Context

- `reconcileStaticSite` halts while the first publish Job runs (`app_controller.go:3866-3870`, via `publishStaticRevision` at `:3947`), before `reconcileStaticIngress` (`:4011`).
- The suspended static path already routes the host to the activator's responder (the comment at `:3969`, w3/m46 and w2/m98). Reuse that backend for the never-published state.
- The static-server answers `no static site for host` (`internal/staticserver/staticserver.go:229`) until its resolver lists the site.

## Steps

1. Before the first publish halts, ensure the host Ingress exists, routed to the activator responder while no revision is active.
2. Swap to the static-server alias only once the resolver can serve the new revision, so the static-server's 404 window disappears too.

- `lego/operator/internal/controller/app_controller.go`, `internal/staticserver/` (if a readiness signal is needed)
- Tests beside each

## Acceptance criteria

- [ ] An envtest shows the Ingress exists, routed to the responder, during the first publish, and then to the static-server once the revision is active.
- [ ] A failed first publish ends on the agreed failed response (t001).
