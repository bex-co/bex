# Datastore log text and instance filters disappear on reload

Why: a saved or shared datastore log URL silently broadens the view, discarding the search that explained the selected logs.

**Severity:** minor. **Estimate:** 55m, including the two-route audit and focused regression checks. Filed by `/pm add w4` from the user’s live `$qa-find-bugs` loop, 2026-10-10 pass a36, using muse.env. Functional QA; this note schedules the fix.

## Reproduction and target behavior

Owned Free Valkey 8 store `qa-20261010-loop-a36-kv`, renamed `qa-20261010-a36-renamed`, `red-db4u78bvjfbs73b08h40`, workspace `tea-d98210cbbpdc73dcrkvg`:

1. Open `/keyvalue/<id>?tab=logs`. Search **Ready to accept connections**. Four matching startup lines appear. Reload: the search is empty and startup/shutdown history returns. Reproduced again from a fresh page.
2. In the second reproduction select **Last 7 days** and instance `red-db4u78bvjfbs73b08h40-931irt8468joti9ne4fj`, retaining that search. The URL is only `?tab=logs&range=7d`. Reload: range survives, text is empty, instance is **All instances**. Recheck after logs settle gives the same reset; this is not a pending-state artifact.
3. Read-only Postgres sibling `/databases/dpg-d9nqg95cavls73fp8m20?tab=logs`: set **checkpoint starting**, reload, and the text resets too. Postgres instance selection was not separately exercised.
4. Read-only service control `/services/srv-d9nqg9dcavls73fp8m2g/logs`: changing text to **QA_A36_FILTER_CONTROL_CHANGED** writes `?range=7d&text=QA_A36_FILTER_CONTROL_CHANGED&live=0`; reload restores both text and paused state. This controls URL persistence, not matching log contents.

Expected: datastore text and instance live in their host route’s URL, survive reload and a copied link, and clearing either removes its key. Defaults stay absent. Existing `tab`, range preset and custom range bounds retain their meanings. The exact filtered query below already returns four correct rows; filtering itself is not broken.

## Cause and bounded fix

- `dashboard/src/features/logs/components/datastore-log-viewer.tsx:98–120` accepts controlled range only; `text` and `instance` start as local `useState("")`. Neither reads nor writes search params. UI callbacks at :192–229 update that local state.
- Exactly **2 production mounts**, exhaustively searched: `routes/keyvalue.$keyValueId.tsx:196` and `routes/databases.$databaseId.tsx:228`. Their validateSearch contracts (:62–72 and :103–113) expose only tab/range, and their viewer props thread only range callbacks. Fix both routes and the shared viewer together; do not expand the service filter vocabulary onto datastore logs.
- The working service route, `routes/services.$serviceId.logs.tsx:24,40–87`, parses `LogSearch`, reads initial filters, and writes them through a guarded callback. `log-viewer.tsx:105–123` skips the initial synchronization to avoid the previously observed hydration reload loop. Reuse that proven seam without changing its callers.
- Actual installed **@tanstack/react-router 1.170.25 / router-core 1.171.21** was opened: `router.ts:1573–1581` merges validated search over raw params; `:2822–2867` runs search middleware and functional updates; `searchParams.ts` decodes/JSON-parses and serializes; `qss.ts:30–36` omits explicit undefined. Unknown raw params are retained by the framework, so this is missing controlled state, not a claim that the router strips unrecognized keys. Return explicit undefined when clearing owned keys. String-like numeric text must round-trip through JSON parsing.
- Debounce text once (existing 300ms), preserve stable pagination identities, and reconcile URL changes/back-forward without issuing a stale unfiltered first query. Before labels settle, retain an instance supplied by the URL; absence from a pending discovery result cannot clear it. Keep empty, failed, timed-out and existing coded refusal states distinct; this fix changes no API access behavior.

Resource family: web/private/worker/cron use the service Logs route; static has no runtime log viewer; Postgres and Key Value use the two mounts above. `/d/<id>` and `/r/<id>` redirect to the canonical datastore routes through `common/lib/render-alias.ts:18–19`; query/hash suffixes are preserved. Verify those aliases. Creation aliases `/new/database`, `/d/new`, `/new/redis`, `/r/new` do not host logs.
