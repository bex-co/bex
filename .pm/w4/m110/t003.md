## Objective

`w4/m108/t004` closed with the acceptance criterion "The rollback confirmation dialog names the commit being restored" and the milestone DoD repeats it ("The 'Roll back to this deploy?' dialog names the commit it restores") — but the dialog on `main` is generic: "The service will redeploy from the image used in this deploy." Name the commit so the last checkpoint before an irreversible rollout answers "rollback to *what?*".

## Context

### The observation (production, 2026-09-17, confirmed on `main`)

Service `qa-20260917-web` (`srv-dalo003ssesc73e0la40`; deleted at the end of the QA run). With a `deactivated` first deploy carrying commit `039c347 Add Render deployment configuration`, **Rollback** opens:

> **Roll back to this deploy?**
> The service will redeploy from the image used in this deploy.

No SHA, no subject — while the row behind the dialog shows both. Evidence screenshot: `.playwright-mcp/qa-deploys-rollback-dialog.png` (gitignored, local to the QA session).

This is a closeout gap, not a regression and not deploy lag: the m108 implementation commit (`8f46d3119`) never touched `dashboard/src/features/deploys/components/deploy-actions.tsx` (verified via `git show --stat`), and `main` still renders the static locale string `services.eventsRollbackConfirmBody` (`dashboard/src/features/services/locales/en.ts:3944`) with no commit interpolation. `DeployActions` takes no commit prop, and all three call sites already hold the data the dialog needs:

- `dashboard/src/features/deploys/components/deploys-list-page.tsx:290` (the row renders `<short-sha> <subject>` from the same query),
- `dashboard/src/features/deploys/components/deploy-detail-page.tsx:85` (via `DeployHeader`),
- `dashboard/src/routes/services.$serviceId.events.tsx:282` (event rows carry commits).

### Fix shape

Add optional commit props (`commitId`, `commitMessage`) to `DeployActions`; when present, the rollback confirm body interpolates `<short-sha> <subject>` (matching the row rendering, including the short-sha helper the list already uses); when absent (unresolvable repo per the `w9/001` contract), keep today's generic body. Update the three call sites, the `en` + `zh` locale strings, and `dashboard/src/features/deploys/components/__tests__/deploy-actions.test.tsx` (commit shown when present, generic body when absent).

### Acceptance

- The milestone DoD's "rollback dialog names the code" bullet passes live on all three surfaces (Deploys list, deploy detail, Events): the dialog names the commit; a commit-less deploy keeps the generic body.
- Both locales render the interpolated string (no raw `{placeholder}` in either language).
- No other dialog changes: the cancel/deploy confirm copy is byte-identical.
