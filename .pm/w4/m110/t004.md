## Objective

Every repo-backed deploy log prints `==> Build queued` and `==> Building from <repo>@<sha>` — including reuse rollouts and rollbacks that perform no build. Those lines are synthesized from the deploy row's timestamps, not observed from a build, and they actively mislead: during this QA run they were the reason three buildless config-change deploys each looked like a 14–30s build. Emit build narration only when a build ran.

## Context

### The observation (production, 2026-09-17)

The three config-change deploys from t001 (`dep-daloaq300vpc73cofreg`, `dep-daloc1300vpc73cofrh0`, `dep-dalohe52r12c73cngh9g` on `srv-dalo003ssesc73e0la40`) each logged:

```text
11:17:40 PM  [4na49] ==> Build queued
11:17:54 PM  [4na49] ==> Building from https://github.com/render-examples/express-hello-world@039c347
11:18:08 PM  [4na49] ==> Your service is live 🎉
```

No build steps, no Build started/ended events (the Events tab confirms none exist for these deploys), same image digest — no build ran, yet the log tells a build story. The rollback deploy tells the same story for its intentional reuse.

Root cause: `lego/backend/internal/logs/progress.go:219-265` `progressLines` fabricates the lines from `d.CreatedAt` ("Build queued") and `d.StartedAt` ("Building from …") for every repo-backed deploy. The doc comment claims "Only observed moments produce lines" — the timestamps are observed, but the *wording* asserts a build. The `container: progressContainer` label marks these as synthetic, but no UI surface distinguishes them from real BuildKit output.

This is not `w6/m123` (failed-build error surfacing, verified live and truthful in this same run): that milestone made real builds report honestly; this task stops buildless deploys from claiming a build at all.

### Fix direction (not a prescription)

Gate the two build lines on evidence that a build ran — e.g. the deploy having Build started/ended events, or a build-instance id distinct from the progress container — and otherwise narrate the rollout (`==> Deploy queued` / `==> Rolling out <image>` already exist for the non-repo path and read correctly for reuse). Keep the terminal `live` line (t001's deploys earned it) and keep line ids deterministic across reads so the tail's dedupe behavior is unchanged. The CLI's `type=build` narration (`terminalLines`, same file) inherits whatever rule is chosen — keep it consistent rather than special-cased.

### Acceptance

- The milestone DoD's "No build, no build narration" bullet passes live: a config-change reuse rollout and a rollback show no `Build queued`/`Building from` lines; a real build (first deploy, manual rebuild, hook rebuild) keeps them byte-identical.
- The deploy Events and the deploy log agree: no log line claims a build the Events tab has no record of, on all four deploy triggers (create, manual/hook, config change, rollback).
- Existing `progress.go` unit coverage is extended for the gated lines (buildless deploy omits, build deploy keeps), and no snapshot of a real build's log changes.
