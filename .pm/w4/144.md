# A Key Value or Postgres placed in a project shows no project in its breadcrumb, only "Key Value red-…"

Why: services get the Render-style Project › Environment › resource breadcrumb with switchers (`w5/026`), but a datastore page says only its type and raw id, even when the store sits in a project and environment. There is no way back to the project from a datastore, and the leaf is an id instead of the name the heading shows.

Found live, `/qa-find-bugs` pass 165, 2026-09-25 (w4-targeted, `muse.env` credentials), journey 1. Fixtures: project `qa-20260925-proj` (`prj-darm0sa9slkc73bequ6g`) with environment `staging` (`env-darm0v29slkc73bequ80`), and Free Key Value `qa-20260925-kv2` (`red-darm13muag9c73eddbtg`) created into that project and environment. All three were deleted this pass; a final `qa-` sweep of services, databases, key values, and blueprints was empty.

- **Repro:** open `/keyvalue/red-darm13muag9c73eddbtg` while GraphQL reports `keyValue{projectId:"prj-darm0sa9slkc73bequ6g", environmentId:"env-darm0v29slkc73bequ80"}`. The topbar's `navigation "Breadcrumbs"` accessible name is exactly **"Key Value red-darm13muag9c73eddbtg"**. The Postgres page in pass 160 read the same shape: "Database dpg-darl85bthimc73a1m01g".
- **Root cause:** `dashboard/src/common/components/dashboard-layout/dashboard-breadcrumbs.tsx:53-61` routes only `serviceId` (→ `ServiceBreadcrumbs`, which renders Project › Environment › service with switchers, `:65-150`) and `projectId`. Everything else falls to `PageBreadcrumb`, which prints the page label plus the raw id from `DETAIL_ID_PARAMS` (`:385-392`, which includes `databaseId` and `keyValueId`).
- **Fix:** give `databaseId`/`keyValueId` the service treatment: read the store's `projectId`/`environmentId` (both already on the datastore queries, for example `features/databases/api/databases.graphql:265-266`) and render Project › Environment › **name**, falling back to the type crumb only for an ungrouped store. Keep the switchers consistent with `ServiceBreadcrumbs`.

Unassigning from the environment kept the project (`environmentId:null`, listed under "Unassigned"). Deleting the project left the store `available` and ungrouped, exactly as its confirm dialog states.
