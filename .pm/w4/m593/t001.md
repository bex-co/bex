## Objective

Capture Render's current Settings → Source ("Update Source") behavior from its public dashboard bundle into `docs/render-artifacts/update-source.md`, so the backend, dashboard, and parity tasks share one verified reference.

## Context

- Initial inspection on 2026-11-23 from `https://dashboard.render.com/` (`assets/index-BR2q8yex.js`, `assets/server-8p_bC2pd.js`, `assets/cronjob-DfrSsyzb.js`) located the full flow:
  - `rF` / `EP` — Settings Source row and **Update Source** modal, rendered for `Server` (web, worker, private, static; omitting PR previews) and `CronJob`.
  - `TP` — source tabs (`Git Provider`, `Public Git Repository`, `Existing Build Source` when non-static, `Existing Image` when non-static).
  - `wpe` → `Cpe` (static site: Branch, optional Build Command, required Publish Directory), `vpe` (Docker: Branch, Runtime), `xpe` (native: Branch, Runtime, required Build Command, required Start Command / `Command` for cron). Footer `eP` with `Cancel`, `Back`, `Deploy` (`Deploying`).
  - `sme` — Existing Image (`Image URL`, optional `Credential`, button `Connect` / `Connecting`).
  - `rme` → `nme` — Existing Build Source picker (`Next`) + confirmation step (native `Start Command` / cron `Command`, protected-environment note, `Back` / `Cancel` / `Deploy`).
  - `updateServer(id, patch)` returning `deploy { id }` and `updateCronJob(id, patch)` returning `build { id }`, with `onMutationCompleted` navigating to the new deploy/build.
- Compare with Render's changelog entry of 2026-05-11 ("Change your service's backing repo or image in the Render Dashboard") and REST `PATCH /v1/services/{id}` (which saves without deploying).
