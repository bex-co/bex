# Environments partial-update semantics live in the REST adapter; AuthorizeApp fallback loop re-resolves a loop-invariant workspace

← filed by `w4/m23/t006`'s simplify pass 2026-07-15 (findings judged real but beyond a behavior-preserving inline fix).

Two related depth findings from the `/simplify` review of `cc2156b8`:

1. **Environments create-with-ACL + PATCH merge are adapter-owned business logic.** `environments/rest.go`'s POST sequences validateACL → `Create` → `SetACL` (non-atomic: a failed SetACL leaves an environment with an open ACL), and PATCH implements the read-modify-write merge (current triple + pointer overrides + the `""→unprotected` pre-migration default) before calling the full-replace `SetACL`. ADR006's one-core/thin-adapters rule — and the codebase's own `postgres.UpdatePostgres`/`PostgresPatch` precedent — puts this in the service layer: an `EnvironmentPatch` + `Update(ctx, id, patch)` core verb, and `Create` accepting the optional ACL triple (the keyvalue create-request shape). As shipped, GraphQL `createEnvironment` / MCP `create_environment` can't create with an ACL in one verb, and any future partial-update surface must re-implement the merge (the pre-migration default will drift). Fixing this also collapses the composed verbs' duplicate authorize/fetch round-trips (each of `Get`+`SetACL` independently runs Authorize + `requireEnvironment`), and lets create-with-ACL skip `SetACL`'s guaranteed-no-op member fan-out (`ListEnvironmentServices`/`applyAppEnvironmentLabels`/`propagateIPAllowList`/member-id scans) for an id minted milliseconds earlier.

2. **`AuthorizeApp`'s name-collision fallback loop re-runs a loop-invariant store query per candidate.** `resourceWorkspace(ctx, labels)` calls `resolveWorkspace(ctx)` first — dependent only on ctx — so N colliding candidates issue N identical `Workspace.Tenant` queries before their (strictly sequential) FGA checks. Hoist the acting-workspace resolution above the loop (a `resourceWorkspace` variant taking the pre-resolved workspace), and consider OpenFGA BatchCheck for the per-candidate authorization. Denial-path-only, so latency not correctness; the w4/015 cap already bounds the audit side.
