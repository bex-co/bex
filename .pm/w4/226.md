# w4/226 — Existing Image creation sends a hidden Git Root Directory

Why: choosing an image after preparing a repository should produce a usable image deployment; the wizard currently blocks it on a field the selected source hides.

**Severity:** major. **Estimate:** 55m. **Status:** open. Source: live `$qa-find-bugs w4`, 2026-10-09 pass a26, QA workspace `bex` (`tea-d98210cbbpdc73dcrkvg`). Filing only; no product code changed.

## Reproduction and observed result

1. Open `/services/new?type=web_service` at 1440×1000. Choose Public Git URL, enter `https://github.com/bex-co/bex`, and set Root Directory to the valid repository path `examples/hello-go`.
2. Switch to Existing Image. Set Name to `qa-20261009-loop-a26-source`, Docker Image to `docker.io/library/busybox:1.37`, Port 3000, and Free ($0.00). Set Docker Command to the synthetic marker server shown in the capture below. Leave project/environment unset.
3. Deploy Service is enabled, and there are **zero accessible Root Directory inputs** on the image form. Submit.
4. At **10:41:23.537 UTC**, GraphQL HTTP 200 returns `createService: null` with `bad request: prebuilt image services cannot declare rootDirectory; remove it or deploy from repo instead`. The toast repeats the refusal and the wizard stays open. The actual image mutation contains `rootDir: "examples/hello-go"`; repository, branch, build command, Dockerfile path, and auto-deploy are correctly omitted.
5. Fresh page loads with the same sequence reproduce at **10:42:21.962 UTC** (desktop) and **10:43:21.164 UTC** (390×844 mobile). This is not a lost response, a rate-limit error, or a deliberately incompatible image request entered by the user: the obsolete field is injected from a hidden draft.
6. At **10:43:52.684 UTC**, before the positive control, the service's name read returns 404 and the service list still has the original five IDs. Failed submissions created no service.
7. Switch back to Public Git URL: Root Directory still reads `examples/hello-go`. Clear **only that field**, switch back to Existing Image, and submit the retained image/name/command/port/Free settings. At **10:43:57.714 UTC**, creation succeeds. Comparing the complete variable objects below, the only difference is omission of `rootDir`.

This has a recovery path through another source tab, but the selected source provides no control matching the error's remedy. Classify as major; plain image creation and Git creation remain usable.

## Root cause and consumer trace

- `dashboard/src/features/services/hooks/use-new-service-form.ts:145`: `setTab` changes tab and resets selectedRepo/branch, retaining rootDir. Retention is useful for switching back.
- `dashboard/src/routes/services.new.tsx:223`: Branch and Root Directory controls render only for `shape.isGitSource`. `:102–117` lets the valid image form submit, calls `buildCreateServiceInput(form)`, and redirects only for a returned service ID.
- **`dashboard/src/features/services/lib/create-service-input.ts:190`** sends `rootDir: form.rootDir || undefined` unconditionally. Other source fields already use the derived build shape. Gate rootDir with the existing **`shape.isGitSource`**. Do not use `isBuildableGit`: it excludes static sites, which also use repository roots.
- `dashboard/src/features/services/hooks/use-create-service.ts:111–160` forwards input variables with ownerId, and displays the server refusal. `dashboard/src/features/services/api/services.graphql:93–151` declares optional `$rootDir: String` and forwards it to createService; no query/generated-type change is needed.
- Actual pinned Apollo **4.1.3** implementation `dashboard/node_modules/@apollo/client/link/batch-http/BaseBatchHttpLink.js:66–83` filters variables by the declared query and JSON-serializes the batch body. The query declares rootDir, so the nonempty string survives. An undefined rootDir disappears on the wire. Regression assertions should test serialized variables, not require the builder's object to lack an undefined own property.
- `lego/backend/internal/apps/graphql.go:718,1364` maps the optional argument to CreateRequest.RootDir; `gqlutil.Str` at `lego/backend/internal/gqlutil/gqlutil.go:388–393` returns empty when omitted. `apps/service.go:2800–2810,2933–2942` validates the source before creation writes. `apps/blueprint_compiler.go:354–382` lists RootDir among prebuilt-image incompatibilities and names it `rootDirectory` in create errors. The backend correctly handles both captures.
- REST `apps/rest.go:565,1034–1053` and MCP `apps/mcp.go:268,690–697` map to the same CreateRequest/core Create path. MCP workspace middleware `api/mcp_workspace.go:90–118` validates and scopes the explicit workspaceId used in the dry-run control. No transport or backend policy change is needed.

## Contracts, history, and dedupe

- ADR049 D7 (`docs/ADR049-render-yaml-parity.md:166–168`) deliberately rejects Git-only build settings for prebuilt images. The GraphQL create contract likewise labels branch/rootDir/autoDeploy Git-only. This proposed frontend omission preserves that contract.
- Official Render [prebuilt-image deployment](https://render.com/docs/deploying-an-image) selects Existing Image and configures the image/command; [monorepo support](https://render.com/docs/monorepo-support) scopes Root Directory to a repository's files, builds, and linked branch. This supports source-specific input. Render's exact cross-tab draft behavior was not observed; do not claim an identical Render UI defect or API refusal.
- Open/done keyword searches, all **72 non-done README scopes**, the anti-goals, latest 40 dashboard/lego commits, and targeted symbol history were checked. No open item owns this hidden-root create case, and main still contains the unconditional assignment.
- `w5/done/m15` promised wizard creation from all three sources to Running/public URL. This pass verifies plain image and public Git with root; connected-GitHub creation and the disconnected connect prompt were not recertified. Its DoD did not specify cross-tab draft filtering. The predecessor route before refactor `086cc3692` already used unconditional `rootDir: rootDir || undefined`: file this as an uncovered composition case, not a new refactor regression or a claim that m15's entire DoD was audited.
- `w5/done/090` owns correct prebuilt-image/build-setting validation, which stays intact. `w9/done/069` owns CLI clone's synthetic image branch, a different field/caller. `w4/blocked/218` owns upstream CLI clone Docker Command loss. `w5/done/m76` concerns Settings source PATCH with save-before-deploy semantics; this finding is wizard Create, not that setter. Their relevant records were opened, including m76's entire current DoD and closeout evidence.
- The initial image deploy's absent startedAt is already `w4/blocked/m156`; do not file it here. No anti-goal, non-goal, or unreleased existing root-field fix matched.
