## Objective

When a member approves an OAuth client on the dashboard consent page (or a client is auto-accepted for the first time), bex-api records `GrantOAuthAccessEvent` in each workspace the member belongs to, after confirming the grant at Hydra.

## Context

- `dashboard/src/common/server-fn/hydra-consent.ts:510` `acceptConsent` is the only accept call; it runs on the interactive POST (around line 836) and the headless GET path (around line 664, trusted or `skip`/`skip_consent` clients, line 301).
- The revoke path already calls bex-api with the user's cookie: `hydra-connected-agents.ts:156` → `POST /v1/oauth/revocations` → `lego/backend/internal/cliauth/service.go:164` `recordRevocation` (session-authenticated humans only).
- bex-api can read Hydra's consent sessions: `oauthgrant.Revoker.Grants(ctx, subject)` (`lego/backend/internal/oauthgrant/oauthgrant.go:279`) returns `Grant{ClientID, Scopes, HandledAt}`; `BEX_HYDRA_ADMIN_URL` (`lego/backend/cmd/api/config.go:448`, used at `main.go:319`).
- Audit seam: `core.AuditEvent` + `audit.Service` `renderEvents` (`lego/backend/internal/audit/service.go`); w9/m452 needs the same "one row per current workspace" write, so reuse a shared helper if it has landed.

## Steps

1. Add `POST /v1/oauth/grants` beside `recordRevocation`: body `{clientId}`, session-authenticated humans only, bounded like the revoke.
2. bex-api confirms Hydra holds a consent session for (subject, client) handled within the last few minutes; otherwise it records nothing and answers 404 (no forged rows).
3. Record `GrantOAuthAccessEvent` (verb mapped in `renderEvents`) once per workspace the subject belongs to: actor the user, target the client, metadata `client_id`, `client_name` (Hydra's client name), `scopes` (space-joined). Never a token. Use a derived event id per (subject, client, handled_at, workspace) so a retried call records once.
4. In `acceptConsent`, call the route after Hydra's accept succeeds, only when Hydra did not `skip` (a remembered consent is not a new grant) and the client is not one of the platform's own sign-in clients (the bex CLI human client, `isPlatformHumanClient` in `cliauth`; the ops Grafana client). A failed call is logged and never fails the consent.

## Acceptance criteria

- [ ] An approve records one row per workspace; a remembered consent, a refresh and a CLI device-flow login record none.
- [ ] A `POST /v1/oauth/grants` for a client with no Hydra consent session records nothing (test).
- [ ] An audit write failure never changes the consent's redirect.
