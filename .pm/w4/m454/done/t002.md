## Objective

Revoking an agent under Connected agents, or with the operator `revoke-oauth-grant` command, records `RevokeOAuthAccessEvent`.

## Context

- `dashboard/src/common/server-fn/hydra-connected-agents.ts:124` `revokeConnectedAgent` revokes at Hydra, then calls `POST /v1/oauth/revocations`.
- `lego/backend/internal/cliauth/service.go:164` `recordRevocation` bumps the marker only.
- `lego/backend/internal/oauthgrant/oauthgrant.go`: `AuditVerb = "oauth.RevokeGrant"`, system actor, the ops workspace (`auditEvent`, line 226).

## Steps

1. In `recordRevocation`, after the marker bump succeeds, record `RevokeOAuthAccessEvent` once per workspace the subject belongs to, with the same actor, target and metadata keys as t001 (`client_id`, `client_name` when Hydra still knows the client). A failed audit write is logged; the revoke still answers 204.
2. Map `oauth.RevokeGrant` to `RevokeOAuthAccessEvent` in `renderEvents`; keep the operator row's system actor and ops-workspace placement.
3. The CLI's `/v1/oauth/revoke` (logout) is not this event; it belongs to w9/m452's `LogoutEvent`.

- `lego/backend/internal/cliauth/service.go`, `lego/backend/internal/oauthgrant/oauthgrant.go`, `lego/backend/internal/audit/service.go`

## Done (2026-11-16)

- `recordRevocation` calls `Access.RecordRevoke` once the marker is written: one `oauth.RevokeAccess` row per workspace of the member, with the same actor, target and `client_name`. Hydra already revoked the grant, so it is asked only for the client (`GET /admin/clients/{id}`): a client Hydra does not know records nothing, and one Hydra cannot answer for is recorded without its name. An audit or lookup failure is logged and the revocation still answers 204. The dashboard's call now forwards the browser's User-Agent and True-Client-IP with the cookie, so the rows' `source_ip`/`user_agent` are the member's.
- The operator's `revoke-oauth-grant` now writes `core.AuditVerbRevokeOAuthAccess` (`oauth.RevokeAccess`), keeping its system actor, ops-workspace placement and `oauth-grant:<client>` target named after the subject; `oauthgrant.AuditVerb` (`oauth.RevokeGrant`) is gone. `renderEvents` maps the old verb to `RevokeOAuthAccessEvent` as well, so the rows written before read as the same event until the retention sweep removes them.
