## Objective

Make the Settings → Notifications panel say which workspace its toggles apply to, and act on the workspace the user is actually in.

## Context

- The panel currently presents three toggles with no workspace context, which is truthful only if t001 chose per-user.
- If per-workspace: the panel must send the current workspace and label itself accordingly, so a user switching workspaces sees that workspace's values. Without the label the fix is invisible — the same three toggles would show different values after a workspace switch with no explanation.
- The dashboard already has the workspace switcher and passes `ownerId` on every other workspace-scoped read, so this is wiring, not new machinery.

## Steps

1. Pass the active workspace to the settings read/write.
2. Label the panel with the workspace the preferences apply to (or state they are account-wide, if per-user).
3. Confirm switching workspaces re-reads rather than showing the previous workspace's values.

## Files

- `dashboard/src/features/notifications/`

## Acceptance criteria

- [ ] The panel names the scope its toggles apply to.
- [ ] Switching workspaces shows that workspace's stored values.
- [ ] Saving writes the workspace shown, not the default one.

## Out of scope

- Redesigning the panel.
