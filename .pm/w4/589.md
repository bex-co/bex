# 589 — `lego/types` tests run in no CI job: ten test files, including the ID, host and release-snapshot contracts, never gate a push

Why: a regression in the shared CRD contract (`lego/types`) passes CI as long as the operator and backend still compile against it. w4/m329 had to place its template tests in `lego/backend/internal/gqlutil` so that a CI job runs them.

- **Source / severity / estimate:** w4/m329 `/simplify` review, `/loopx w4` 2026-11-11. **Minor–major** (gate gap). ~30m.
- **Evidence:**
  - `make test` (`lego/operator/Makefile:67`) runs `go list ./...` inside the operator module only.
  - `backend-test.yml` runs `go test -p 1 ./...` from `lego/backend`. It triggers on `lego/types/**` but does not test that module.
  - `go-lint.yml` lints `lego/types` but runs no tests, and no other workflow runs `go test` there.
  - The untested files are `lego/types/v1alpha1/*_test.go`: `app_hosts`, `database_identifiers`, `image_network`, `ipallowlist_types`, `jobnames`, `maintenance_mode`, `release_config`, `releasesnapshots`, `resourcename`, plus any under `lego/types/tiers`.
- **Fix:** run `go test ./...` for `lego/types` in CI, either as a step in `backend-test.yml` (which already triggers on `lego/types/**`) or in `make test`. Make `scripts/ship-gates.sh` run it for a push touching `lego/types/**`. First check that the current tests pass, and fix any that rotted.
- **Dedupe:** none. `grep -rn "lego/types" .github/workflows` shows trigger paths and caches only.
