## Objective

Make supported Docker creation in the already-enabled canary converge to a runnable workload with a narrowly bounded admission profile.

## Context

See [finding.md](finding.md) for two live failures, a native control and root file:line. Read ADR089 and the full existing admission validations before choosing a marker; CEL does not look up App.spec.

## Steps

1. Trace the persisted policy through all workload templates and the live admission predicate; choose an operator-owned marker/provenance contract the consumer can validate.
2. Update the producer and admission consumer together to admit only the bounded image-v1 set while keeping strict, host-access, identity, namespace and seccomp rules intact.
3. Verify existing persisted image-v1 Apps as well as fresh creation; document deployment order and fail-closed behavior if producer and policy roll out separately.

## Acceptance criteria

- [ ] The failing web creation and manual-retry fixture reaches Live/Running and serves HTTP 200 after rollout.
- [ ] An existing persisted image-v1 App can recover; removing the create allowlist is not treated as a migration.
- [ ] No extra capability, privileged container, host access or non-RuntimeDefault profile is admitted through the new exception.

## Out of scope

- Widening the workspace allowlist, rewriting tenant isolation, or changing managed-data security profiles.
