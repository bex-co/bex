## Objective

Extend the Alloy log-shipper so `dashboard` namespace container logs reach Loki under a platform (non-tenant) label set, without inventing a fake `app.bex.co/app` App identity.

## Context

- `deploy/gitops/base/log-shipper.yaml` `discovery.relabel "app_pods"` drops every pod lacking `app.bex.co/app` — by design for tenant cardinality — so `dashboard` never appears in Loki (`label/namespace/values` today: build + tenant namespaces only).
- Tenant log API (`BEX_LOKI_URL` / bex-api logs) must keep selecting on App labels; platform streams must not collide with that contract.
- Prefer a dedicated relabel pipeline (e.g. `type=platform` + `service=dashboard` or namespace/pod/container) rather than stamping a synthetic App label.

## Steps

1. Add a `discovery.relabel` + `loki.source.kubernetes` + process stage for namespace `dashboard` (and only that ns unless a one-line comment documents a deliberate sibling).
2. Label streams so they are queryable (`namespace`, `pod`, `container`, `type=platform` or equivalent) and reuse the existing JSON `level` parse where present.
3. Confirm via a Loki label/query after deploy that dashboard lines appear; document the LogQL selector in a one-line comment or ADR010 cross-link if needed.

## Files

- `deploy/gitops/base/log-shipper.yaml`
- `docs/ADR010-observability.md` (short note if the platform-stream contract needs recording)

## Acceptance criteria

- [x] Pods in namespace `dashboard` are no longer dropped solely for missing `app.bex.co/app`.
- [x] Loki exposes the new streams without adding a fake tenant App name.
- [x] Tenant App shipper rules and bex-api's App log selectors remain unchanged.

## Out of scope

- Shipping all of `bex-system` / `auth` (follow-up unless trivial); Traefik host retention (t003); changing the dashboard UI Logs viewer.
