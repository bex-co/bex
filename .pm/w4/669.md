# 669 — For about 35 s after Suspend, a static site answers the static-server's `503 static site temporarily unavailable`, not the suspended page; the static-server already knows the site is suspended

Why: Suspend promises visitors "This service is suspended." The activator serves that page once the operator has moved the site's Ingress to it. Until that reconcile, requests still reach the static-server. Its snapshot already sees `spec.suspended`, so it answers a bare `static site temporarily unavailable` with `Retry-After: 5`. That reads like an outage, not a deliberate suspension. w4/636's round saw it for 5–9 s once and could not reproduce it. Round 374 reproduced it for 35 s.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 374, 2026-11-14 16:53–16:56 UTC (`muse.env`, workspace `bex-canary`; pin `c99e7815ebec`). **Minor** (wrong page and wording for a transition window; nothing is lost). ~40m.
- **Fixture:** static site `qa-20261114-r374-st` (`srv-dbs93hfla3oc73cu7rc0`) from `https://github.com/bex-co/bex` `examples/static-site`, publish path `.`, auto-deploy off. Deleted afterwards (`DELETE` 204, then `GET` 404).
- **Probe:** `curl` of `https://qa-20261114-r374-st.onbex.co/` every second, classified by body:

  ```
  16:54:28 POST /v1/services/{id}/suspend → 202
  16:54:29 503 "static site temporarily unavailable"     (static-server)
  16:55:04 503 "This service is suspended." page          (activator)
  16:55:09 POST /v1/services/{id}/resume → 202
  16:55:10 200 the site's own index.html, for the next 60 s  (w4/636 holds)
  ```

  The window ran 35 s, every poll the same 503. Round 301 (w4/636 § "Also seen once") saw 5–9 s. The window is the operator's reconcile latency, and w4/665 (done) found the App controller saturated, which would stretch it.
- **Root cause:**
  - The static-server's resolver sets `Unavailable: app.Spec.Suspended` on a site's snapshot (`lego/operator/internal/staticserver/resolver.go:105`).
  - `ServeHTTP` answers every request for an unavailable site with `serveSiteUnavailable` (`staticserver.go:272-275`). That is `503`, `Cache-Control: no-store`, `Retry-After: 5`, body `static site temporarily unavailable` (`:1114-1119`).
  - Its comment names both transitions it covers: a suspend before the activator takes over, and a resume before the next Refresh (`:1109-1113`).
  - The Ingress moves to the activator's suspended responder only on the operator's next reconcile (`lego/operator/internal/controller/app_controller.go:4913-4921`, a content-negotiated 503 with `Retry-After`).
  - The activator's answer is `suspendedPage`, "This service is suspended." plus an explanation (`lego/operator/cmd/activator/main.go:976-991`, plain `suspendedText` at `:425`).
- **Fix (target behavior):** a request that reaches the static-server for a site its snapshot sees suspended gets the same response the activator gives a suspended service: the same status and page, HTML or text by `Accept`, still `no-store` and with custom headers applied.
  - Share the page (and the HTML/text choice) between the activator and the static-server, so the wording cannot drift.
  - The same branch also answers a resume whose snapshot has not refreshed yet. There the suspended page is still truer than "temporarily unavailable", and Refresh ends it. Round 374 saw no such window: the site served at the first poll after Resume.
- **Blast radius:** one branch in the static-server (`serveSiteUnavailable`, one caller at `staticserver.go:273`), and the shared page constant. Tests: a suspended snapshot serves the suspended page with `no-store` (HTML and text). The busy-shedding path (`serveSiteBusy`) and the no-site 404 are unchanged.
- **Unverified:** whether a web service has a similar window between Suspend and the activator taking over (its pods scale to 0, so the old pods may answer until they stop); what Render serves during its own suspend transition.
- **Render:** a suspended service's URL shows Render's suspended page.
- **Dedupe:** w4/636 (done) records this as "Also seen once, not reproduced" and did not file it. `grep -rl "static site temporarily unavailable" .pm` finds only w4/636.
