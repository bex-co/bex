## Objective

Every Postgres pod and Key Value pod carries the same region label as the services, from its CR's region, without a rollout. Postgres pods include instances, replicas and any pooler pods.

## Context

- The Database and KeyValue CRs carry `app.bex.co/region` from creation (`lego/backend/internal/postgres/service.go:1031`, `lego/backend/internal/keyvalue/service.go:746`, and a recovery keeps its source's: `postgres/recovery.go:567`).
- Datastore pods already carry `environment-id` as their network identity (`lego/backend/internal/core/base.go:244-248`), and are relabelled in place (`lego/operator/internal/controller/keyvalue_isolation.go`, `datastore_priority.go`).
- Datastore control and proxy paths keep working: `allow-datastore-control-ingress` (`lego/backend/internal/store/namespaces.go:1138`), and the pg/kv SNI proxies for external URLs.

## Steps

1. Derive the label from each CR, using t001's rule when the annotation is absent.
2. Put it on new datastore pods and relabel running ones in place.

## Files

- `lego/operator/internal/controller/*.go` (Postgres and Key Value reconcilers)

## Acceptance criteria

- [ ] New and existing Postgres and Key Value pods carry the label with unchanged pod UIDs.

## Out of scope

- External datastore access, which goes through the SNI proxies and stays as it is.
