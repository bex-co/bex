# 084 — All five `RevokeIconButton` callers name their destructive control with a bare verb, so every multi-row list exposes N identical "Sign out" / "Revoke" buttons

Why: `w4/m101/t014` fixed exactly this shape for `CopyButton` and `t013` fixed it for the environment editor's rows — `RevokeIconButton` is the same component shape with the same defect at **every one of its five call sites**, and here the ambiguous control is the destructive one.

Record from the live `/qa-find-bugs` loop, 2026-09-14 pass 32. **Read-only on production — nothing created, changed, revoked or signed out.** Severity: **major** — the journey completes, but a screen-reader user choosing among identically-named destructive controls cannot tell which session or key they are about to destroy.

## Live evidence, one page

`https://dashboard.bex.co/settings`, real accessibility tree (not a DOM heuristic — `m101` recorded that trap):

```js
const snap = await page.locator("main").ariaSnapshot();
snap.split("\n").filter((l) => /button/.test(l));
```

returns, among others, **122 × `- button "Sign out"`** and **2 × `- button "Revoke"`**, every one of them a separate row's destructive action. Cross-checked against the DOM: the buttons carry no text, only `aria-label`, and the identifying data sits in the row beside them —

```json
{ "innerText": "", "ariaLabel": "Sign out", "rowText": "curl/8.7.1\tUS\t18m\t" }
```

So the distinguishing information (device, location, last-active) is already rendered and simply never reaches the control's name.

## Root cause, and the exhaustive blast radius

`common/components/revoke-icon-button.tsx:36` renders its caller's label verbatim as the whole accessible name:

```tsx
<Button size="icon" variant="ghost" aria-label={label} disabled={pending}>
```

That is the identical shape `copy-button.tsx:31` had before `w4/m101/t014`. Every caller — grepped, **5 of 5**, none behaving differently:

| call site | label | message |
| --- | --- | --- |
| `features/sessions/components/session-row.tsx:38` | `activeSessions.revoke` | "Sign out" |
| `features/api-keys/components/api-key-row.tsx:53` | `apiKeys.revoke` | "Revoke" |
| `features/ssh-keys/components/ssh-keys-panel.tsx:200` | `sshKeys.delete` | "Delete" |
| `features/registry-credentials/components/registry-credential-row.tsx:49` | `registryCredentials.delete` | "Delete" |
| `features/connected-agents/components/connected-agent-row.tsx:67` | `connectedAgents.revoke` | "Revoke" |

There is **no** correct caller to hold up as the in-repo convention — unlike `CopyButton`, where `m101` measured 8 of 15 call sites already saying "Copy &lt;thing&gt;". The convention to follow is the one `t013`/`t014` established elsewhere in the same codebase, not a sibling of this component.

## The fix

Target behavior: **each row's destructive control names the row it destroys**, in the verb-leading shape `m101` settled on — e.g. `"Sign out curl/8.7.1, US, last active 18m ago"`, `"Revoke API key <name>"`, `"Delete SSH key <name>"`. Not "make them unique": a name must say what the action does *and* which record, because that is what a screen-reader user hears in isolation.

Keep the fix at the **call sites**, not inside `RevokeIconButton`. The component cannot know what identifies a row, and it already does the right thing with what it is handed; changing it would either force a new required prop on all five or invent a naming scheme the callers can't express. This matches how `t013` fixed the environment rows.

Per the dashboard's i18n rules (`dashboard/CLAUDE.md`):

- Interpolation is **single-brace** — `t("activeSessions.revokeNamed", { device, location, lastActive })` against `"Sign out {device}, {location}, last active {lastActive}"`.
- Every new key needs a sibling entry in **`zh.ts`** as well as `en.ts`; `locale-parity.test.ts` fails otherwise. That is 5 new keys × 2 locales.
- `session-row.tsx` already has `session.userAgent`, `session.location ?? session.ipAddress`, and `session.authenticatedAt` in scope (`:22`, `:30`, `:33`), so no new data plumbing — and it must keep the `activeSessions.unknownDevice` fallback for a session with no recorded user agent.

Adjacent classes: the **current** session renders no button at all (`session-row.tsx:36`, `session.current ? null : …`), so it needs no name and the "This device" badge stays the only marker. The bulk `"Sign out other sessions"` control is already unambiguous and is out of scope.
