## Objective

Prove on `.pm/w4/dev-4/` that a service created with both fields deploys once, with both in effect from its first deploy.

## Context

- `bash scripts/dev-env.sh 4 up` brings up dev-4 (pre-approved; AGENTS.md).
- Deploy events: `pre_deploy_started` and `pre_deploy_ended` (ADR018 § Services & lifecycle, Service events).

## Steps

1. From the create page, create a paid web service from a public repository that serves `/healthz`, with Health Check Path `/healthz` and a pre-deploy command that prints a marker.
2. Check its first deploy: the pre-deploy marker is in the deploy log, `pre_deploy_started`/`pre_deploy_ended` are in its events, and the deploy goes live only after the health check passes.
3. Check `GET /v1/services/{id}/deploys` lists exactly one deploy, and GraphQL `server { healthCheckPath preDeployCommand }` reads both values.
4. Open the create page on the Free plan and check that Pre-Deploy Command is disabled with its reason.
