## Objective

Render's hook never runs the CLI: after an edit to `render.yaml`/`render.yml` it only adds context suggesting `render blueprints validate <file>` (since commit `7b6aba9aaf`). bex's must do the same with `bex blueprints validate`, safely.

## Context

- `bex blueprints validate` is served and graded live (`docs/cli-compatibility-checklist.md:375`); it needs `bex login`.
- Render's script: `render-oss/render-plugin-claude-code` `scripts/validate-render-yaml-hook.sh`.

## Steps

1. Write the hook script: parse the tool input with `jq`, match only `render.yaml`/`render.yml`/`bex.yaml`, emit context naming `bex blueprints validate <path>` and bex's CLI install guide; never execute file content or the CLI.
2. Shell tests: matching paths, other paths, odd characters in paths, missing `jq`.

## Files

- `plugins/claude-code/bex/hooks/**` (via its packgen override)
- a `*.test.sh` next to it

## Acceptance criteria

- [x] The tests pass and show the hook never executes anything but `jq`.

## Done 2026-11-25

The hook is one `jq` program: it matches the edited file's basename against `render.yaml`, `render.yml` and the legacy `bex.yml` (not `bex.yaml`, which is no Blueprint name and is the platform manifest `deploy/gitops/base/bex.yaml`, ADR049 D1), emits `additionalContext` naming `bex blueprints validate '<path>'` (shell-quoted with `@sh`) and `https://bex.co/docs/cli#install-bex`, and always exits 0; without `jq` it prints nothing. Tests are Go tests next to the generator (`plugin_test.go`, run by `cli-test.yml`'s `go test ./...`) rather than a `*.test.sh`: they run the script under `bash` with a PATH holding only a logging `jq` shim (matching paths, Windows separators, `$(touch pwned)`/quotes/newline in a path with no file created, 12 non-matching or malformed payloads, no `jq`). Mutations (unquoted path, matching `bex.yaml`, no `exit 0`, a `cat`, no backslash split) each failed a test. In a headless `claude -p --plugin-dir plugins/claude-code/bex` run that wrote a `render.yaml`, the model reported the hook's `bex blueprints validate` suggestion and ran nothing.
