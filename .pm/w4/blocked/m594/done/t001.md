## Objective

On a Postgres or Key Value in a protected environment, only a workspace Admin reads its password or connection URLs. Every other member who holds `can_view_sensitive` (a Developer) is refused with a `403` coded `PROTECTED_ENVIRONMENT_ADMIN_REQUIRED`, on REST, GraphQL and MCP alike, before anything is assembled or audited as viewed.

## Context

- `PostgresConnectionInfo` (`lego/backend/internal/postgres/service.go:1145`) and `KeyValueConnectionInfo` (`lego/backend/internal/keyvalue/service.go:1483`) check `can_view_sensitive` and re-assert it fresh. Every transport reaches them: REST `GET …/connection-info`, GraphQL `databaseConnectionInfo` / `keyValueConnectionInfo`, and the MCP tools.
- `CreateUser` (`postgres/access.go:133`) returns the new role's password once. It is a password view too. `CreateCredential` echoes nothing, so it stays open (its password is read back through the connection info).
- Reuse the w4/m578 gate, not a parallel one: `core.RequireEnvironmentAdmin` with a verb added to `core.ProtectedVerbRestricted` (for example `"view credentials"`), through each package's `requireUnprotected` (`postgres/protection.go`, `keyvalue/protection.go`). Its admin check is the fresh workspace `can_manage`.
- The coded refusal exists for placement only (`core.ProtectedPlacementRefusal`, `core/confirmation.go`). Add a generic coded refusal for a restricted verb (same code, `params.environmentId`, a message naming the action) and use it here. Whether suspend, resume and delete move to it too is t007's call; do not change them here.

## Steps

1. Add the verb to `core.ProtectedVerbRestricted` and its doc comment, and the coded refusal helper beside `ProtectedPlacementRefusal`.
2. Gate `PostgresConnectionInfo`, `KeyValueConnectionInfo` and `CreateUser` after their own authorization, before any secret is read or a view is recorded.
3. Tests in each package: Admin allowed, Developer refused with the code, unprotected Developer allowed, a protection-read failure refused (fail closed), and no `ViewConnectionInfo` audit row for a refused read.
