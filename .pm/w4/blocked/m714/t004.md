## Objective

The Zot registry that stores every service's built images keeps them on an encrypted volume, as Render's "OCI images" are, and every image that existed before the move still pulls.

## Context

- `deploy/gitops/base/zot.yaml`: `persistence: true`, `pvc.storage: 100Gi`, no class, so the StatefulSet's claim takes the cluster default (`hcloud-volumes`). The claim template is immutable, and Argo ignores its `resources.requests` only.
- Kubelets pull through NodePort 30500 whenever a pod starts or moves, so a registry without its images breaks every reschedule, not just new deploys.
- Secret material never goes into git: the passphrase Secret is minted out of band, as `scripts/registry-secrets.sh` does for the registry credentials.

## Steps

1. Mint the registry volume's passphrase Secret in `bex-registry` with an idempotent script that never rewrites an existing one.
2. Set the chart's storage class value to the encrypted class.
3. Write a runbook (`docs/runbooks/`) for moving the live claim: freeze pushes (pause kpack builds), copy the data to a new encrypted claim, swap the StatefulSet onto it, unfreeze, and roll back by swapping back. Measure how long the copy of the current data takes before choosing the window.
4. Run it on production and keep the old volume until t008 passes.

## Files

- `deploy/gitops/base/zot.yaml`, `scripts/registry-secrets.sh` (or a sibling), `docs/runbooks/<new>.md`, `scripts/gitops-validate.sh`.

## Acceptance criteria

- [ ] `bash scripts/gitops-validate.sh` pins the registry's class.
- [ ] On production the Zot PVC is on the encrypted class, an image pushed before the move pulls on a fresh node, and a new build of a first-party service pushes and deploys.
