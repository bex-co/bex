## Objective

Give the operator one encrypted class for Postgres and Key Value volumes on production, and one helper that mints a volume's passphrase Secret the way service disks get theirs ([ADR082](../../../../../docs/ADR082-persistent-disks.md) D3), so t002 and t003 only wire their controllers to it.

## Context

- `deploy/gitops/base/disk-storageclass.yaml` (`hcloud-volumes-luks`, node-publish secret `${pvc.name}-luks` in `${pvc.namespace}`) and `disk-bounded-storageclass.yaml` (adds node-expand). The hcloud CSI driver bundles `cryptsetup` and the kubelet reads the Secret under the node authorizer (verified on production in w2/m86).
- `ensureDiskPassphrase` (`lego/operator/internal/controller/disk.go:366`): random passphrase, key `encryption-passphrase`, created once, never rewritten, fails closed on an empty key, read and written through `uncachedSecretClient` because the tenant namespace is outside the manager's Secret informer.
- Disks pick their class from `BEX_DISK_STORAGE_CLASS` (prod overlay sets it; unset on the CAPD mock). Datastores hard-code `hcloud-volumes` (`database_controller.go:76`, `keyvalue_controller.go:60`), which `scripts/dev-env/hcloud-volumes-storageclass.yaml` aliases onto `local-path`.
- CNPG's PVC names change with instance serials (milestone README, Notes for the worker).

## Steps

1. Pick how a CNPG PVC finds its Secret: per-PVC `<pvc>-luks` minted when the PVC appears, or a class templating `${pvc.annotations['<key>']}`. Prove the choice on dev-4 or the CAPD mock where possible, and on production's CSI driver with a disposable PVC in `bex-canary` (disposable) if the template form is new to it.
2. Add the class if a new one is needed (sync-wave `-3`, `WaitForFirstConsumer`, `allowVolumeExpansion: true`, node-expand secret like the bounded class if a grow needs it).
3. Make the datastore class configurable (for example `BEX_DATASTORE_STORAGE_CLASS`, default `hcloud-volumes` so dev-N and the mock keep working), set it in `lego/operator/config/prod/kustomization.yaml`, document it in `lego/operator/AGENTS.md`, and pin the prod value and the class's secret template in `scripts/gitops-validate.sh`. Update `scripts/dev-env.test.sh:556` to the new source of the class name.
4. Factor the passphrase mint out of `ensureDiskPassphrase` so disks, Postgres and Key Value share it, with the owner reference each caller needs (the Secret must outlive its PVC: never garbage-collected before the PVC is gone).

## Done 2026-11-28

- **Choice: a per-claim Secret minted when the claim appears.** `DatastoreVolumeKeyReconciler` (`lego/operator/internal/controller/volume_key.go`) watches Postgres claims (`cnpg.io/cluster` plus the `app.bex.co/component=database` label every tenant Cluster's `inheritedMetadata` carries, which the platform's own CNPG clusters never set) and Key Value claims (`app.bex.co/keyvalue`) on the datastore class. It mints `<pvc>-luks` for each, with the claim as its only owner, neither controlling nor blocking it, so the garbage collector removes the Secret only after the claim is gone. The annotation template was not used: through `inheritedMetadata` it would give every instance of a Cluster one shared passphrase.
- **No new class.** Datastores use `hcloud-volumes-luks`, the disks' whole-volume LUKS class. Its `${pvc.name}-luks` template was already proven on production in w2/m86. The bounded class would cap a database's filesystem at its request, where `hcloud-volumes` gives it the whole provider volume.
- **Configuration.** `BEX_DATASTORE_STORAGE_CLASS` is read in `cmd/manager/main.go`. Unset, it defaults to `hcloud-volumes` (`defaultDatastoreStorageClass`), which dev-N aliases onto local-path. The prod overlay sets it to `hcloud-volumes-luks`, and it is documented in `lego/operator/AGENTS.md`. `scripts/gitops-validate.sh` § "datastore LUKS class contract" pins three things: the prod value equals the pinned whole-volume LUKS class, the operator's `claim + DiskLUKSSecretSuffix` derivation, and the local render leaving the variable unset. With the prod env renamed, and with the derivation changed to `claim + "-key"`, the section printed its FAIL lines and `fail=1`. `scripts/dev-env.test.sh` reads the default from `volume_key.go`.
- **Shared mint.** `ensureLUKSPassphrase` is now the one mint for disks, Postgres and Key Value. It makes 32 random bytes, creates the Secret once and never rewrites it. A Secret that exists without its key fails closed. `ensureDiskPassphrase` calls it with the App as controller owner, as before. The disk tests pass unchanged apart from the key constant's rename (`luksPassphraseKey`). ADR082 D3 has the datastore paragraph.
