# 286 — Generated secret adds a duplicate variable key after padding an existing key

Why: the generator should choose an available name so its own addition leaves an otherwise valid draft savable.

**Severity:** minor. **Estimate:** 40m. Functional `$qa-find-bugs w4` a356, 2026-10-13 UTC, production dashboard/workspace bex. Research main `4f03e81f1`, unchanged after pull. Filing only. [Complete safe requests/responses and UI receipts](evidence/286-generated-key-collision.json).

## Reproduce and controls

- Cancel, independently reload at 390px, and repeat. The initially padded key is clean at **13:34:35.776Z**. At **13:35:00.676Z** the same two keys/errors and disabled Save reproduce; width remains 390px. No failing save was submitted.

Expected: the padded case chooses `NEW_SECRET_2`, just as the untouched-key control does, and retains the existing row/value.

## Cause and bounded correction

`dashboard/src/features/services/components/service-environment-editor.tsx:425–430` implements `addVariable(generated)`. Its occupied-name set at `:427` takes `row.key` verbatim. The loop therefore regards `NEW_SECRET` as available when the existing row is `NEW_SECRET`.

The two consumers disagree with that raw set: `features/services/lib/environment-draft.ts:219–229` trims names before duplicate validation, and its serializer at `:347–358` trims names before deciding whether a stored key has moved. That explains both the clean padding-only control and the generated duplicate. The inline error and disabled Save are correct protections; the generator should honor their name identity.

Trim each occupied draft key when building this existing set. Keep the current row reservation set, including its handling of deleted and manifest-owned rows; changing membership or the sparse delete/rename protocol is not required. Preserve case-sensitive environment keys, suffix order (`NEW_SECRET`, `NEW_SECRET_2`, …), literal additions and the service/group generation mechanisms.

The shared `EnvironmentEditor` has two production adapter JSX mounts: service adapter `service-environment-editor.tsx:124`, and `features/env-groups/components/env-group-editors.tsx:30`. Their production route mounts are `routes/services.$serviceId.env.tsx:58` and `routes/env-groups_.$groupId.tsx:212`. The generator callback is wired at `service-environment-editor.tsx:778`; a repository search finds this one production automatic-name allocator. The group adapter generates on the server; the service adapter generates its draft value locally. Apply the name correction to this shared allocator, not either value generator or API uniqueness rules. Group behavior is live-proven; service/static/cron/private/worker wrappers are source-scoped and remain verification work. The create forms' manual key + Generate controls are separate behavior.

Budget: 5m correction; 15m actual editor/menu regressions covering a padded base name, padded occupied suffixes, ordinary suffix order and both adapters; 10m owned desktop/mobile replay and dashboard checks; 5m Render contract comparison; 5m simplification. Assert a valid generated draft and successful intended write while retaining the original value, rather than testing an isolated Set/trim expression. Preserve actual duplicate refusal and the same-name delete/re-add behavior from w4/243.
