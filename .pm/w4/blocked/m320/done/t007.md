## Objective

Check that the change is consistent on every surface it exposes, and against render.com.

## Context

- Render's sequence (render.com/docs/deploys, zero-downtime deploys): the original instance receives all traffic while the new one starts. Once the new one is healthy, all traffic moves to it, and the original is sent SIGTERM after 60 s.
- Surfaces:
  - REST `GET /v1/services/{id}/deploys` and `/deploys/{id}`, and `POST …/cancel`;
  - GraphQL deploys;
  - MCP `list_deploys`/`get_deploy`/`cancel_deploy`;
  - the dashboard deploy list, header, detail page and cancel dialog (`services.eventsCancelConfirmBody`);
  - Events `deploy_started`/`deploy_ended`.

## Steps

1. Confirm each surface reports `live` and `canceled` at the new moments, with the same fields and error shapes.
2. Update ADR004 and the ADR018 deploy rows to say traffic moves at promotion. Add a w4/405 note that the accepted gap is closed.
3. File any drift as follow-up work.

## Files

- `docs/ADR004-app-deployment.md`
- `docs/ADR018-render-parity.md`

## Acceptance criteria

- [x] Every surface agrees. The ADRs state that traffic moves at promotion, and that a cancel before promotion means the candidate never answered.

## Out of scope

- New deploy fields.

## Result (2026-11-11)

Render: "your original instance continues to receive all incoming traffic while the new instance is spinning up … Once the new instance becomes healthy, Render updates its networking configuration so that your new instance begins receiving all incoming traffic" (render.com/docs/deploys). bex now matches for image changes: traffic stays on the serving release until promotion, moves in one Service write, and the row turns live at the first settling pass. ADR089 records it ("A web image change takes no traffic before promotion"). REST, GraphQL, MCP and dashboard shapes are unchanged; only when rows turn `live` or `canceled` moves. The dashboard's cancel copy "If an earlier deploy succeeded, it stays live" is now literally true for a held release. Multi-instance capacity during promotion differs from Render's full-set swap: w4/571.
