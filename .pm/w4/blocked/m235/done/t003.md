## Objective

A static site's host is routed from creation and answers t001's first-publish response until its first revision is published. It never answers Traefik's `404 page not found` or the static-server's `no static site for host` in that window.

## Context

- `reconcileStaticSite` halts while the first publish Job runs (`app_controller.go:3866-3870`, via `publishStaticRevision` at `:3947`), before `reconcileStaticIngress` (`:4011`).
- The suspended static path already routes the host to the activator's responder (the comment at `:3969`, w3/m46 and w2/m98). Reuse that backend for the never-published state.
- The static-server answers `no static site for host` (`internal/staticserver/staticserver.go:229`) until its resolver lists the site.

## Steps

1. Before the first publish halts, ensure the host Ingress exists, routed to the activator responder while no revision is active.
2. Swap to the static-server alias only once the resolver can serve the new revision, so the static-server's 404 window disappears too.

## Acceptance criteria

- [x] An envtest shows the Ingress exists, routed to the responder, during the first publish, and then to the static-server once the revision is active.
- [x] A failed first publish ends on the agreed failed response (t001).

## Done 2026-10-19 (loopx w4)

A static site's host routes to the activator from its first reconcile (`routeFirstDeploy`, with the static middleware set so the handover removes nothing the Ingress names). The first publish records its revision with the host still on the activator and requeues `staticHandoverDelay` (2 s); the next pass hands the host to the static-server, whose resolver now rebuilds on every static-site watch event, so it serves the site by then. A newer deploy arriving inside that window moves the host to the static-server first, so the served revision answers through the new build. A failed first publish stays on the activator's failed `503`. An unsuspended static site with a served revision that reaches the activator (the handover, or a resume) gets the neutral not-ready answer. **Tests (envtest):** "a static site's first publish (w4/m235)": activator during the publish, revision recorded still on the activator, static-server on the next pass; a second deploy right after the handover moves the host to the static-server; a failed first publish stays on the activator. `TestRunReloadsOnAnAppChange` covers the resolver.
