## Objective

Implement deletion of a KeyValue's generated TLS Certificate and Secret, including Free instances, without changing backup eligibility or purge semantics.

## Context

See [the finding and complete evidence](finding.md). This is a filing from production QA; the fix is not implemented yet.

## Steps

1. Use finding.md's source trace and both recorded public Secret UIDs as the failing case. The current free CR has no finalizer; registering today's backup finalizer everywhere would incorrectly enter backup purge for Free when the backup store is configured.
2. Register a durable TLS cleanup obligation before creating a Certificate. Keep it for a resource that was public and later becomes private, and cover existing instances. A separate TLS finalizer can preserve the existing backup finalizer unchanged.
3. Quiesce the owned Certificate and observe absence, then delete the exact issued Secret through secretClient() and observe absence before releasing the TLS obligation. Reuse delete/observe mechanics without treating those helpers as ownership checks.
4. Verify canonical namespace, current KeyValue lifetime and artifact provenance before deletion. New Certificate secretTemplate labels can carry provenance; the pinned type cannot carry ownerReferences. Define a conservative legacy-ownerless path using the exact reserved name and cert-manager issuance metadata, with conflicting ownership rejected rather than adopted or removed.
5. Preserve retries, manager-restart durability, namespace teardown handling and DeletionStalled reporting. Missing artifacts succeed; Forbidden/transient failures and pending deletes retain cleanup state. Do not bypass a backup obligation or schedule new backup work merely to clean TLS.

## Acceptance criteria

- [x] A public Free KeyValue has its TLS cleanup obligation before Certificate issuance can leave an artifact.
- [x] An owned Certificate is observed absent before issued-Secret deletion, and the matching Secret is observed absent before the TLS finalizer is removed.
- [x] Private, never-issued, historical-public and legacy instances have explicit tested dispositions; foreign/ambiguous artifacts are not deleted.
- [x] Backup-disabled and never-backed-up Free resources do not gain a backup purge Job; existing paid backup and preserve-backups behavior is retained.

## Out of scope

Global cert-manager defaults, broad namespace Secret sweeps, API redesign and unrelated resource cleanup.
