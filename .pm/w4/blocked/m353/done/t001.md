## Objective

A liveness restart sends SIGTERM as soon as the kubelet decides to restart. A healthy instance being retired still gets the full 60 s drain before SIGTERM.

## Context

- Probes and timing: [README § Finding](../README.md#finding-round-229).
- The drain: `drainSeconds`, `drainSecondsFor`, `applyDrain` and `terminationGracePeriodSeconds` (`lego/operator/internal/controller/deployment_projection.go:490-561`).
- The probe binary already runs as the exec probe for services with a Health Check Path:
  - `lego/operator/cmd/health-probe/main.go` has the subcommands `install` and `check`;
  - `healthProbeExecHandler` is at `lego/operator/internal/controller/health_probe.go:49-57`;
  - `usesHealthProbeBinary` is at `deployment_projection.go:202-204`.
- Disk-attached services and workers carry no drain and are unchanged.

## Steps

1. Add a `drain` subcommand to `health-probe`. It runs one check with the probe's own arguments.
   - If the check fails (the instance is out of rotation, or the restart is a liveness kill), it exits 0 at once.
   - Otherwise it sleeps the drain seconds (60), then exits 0.
   - It never exits non-zero, so a preStop error cannot block termination.
2. For pods that use the probe binary, project `lifecycle.preStop` as an `exec` of `health-probe drain --seconds 60 <check args>` instead of `sleep`. Keep `terminationGracePeriodSeconds` = drain + `maxShutdownDelaySeconds`.
3. Adoption follows the existing lazy rule: a stored template changes on its next roll, never on operator upgrade (ADR004 § Rollout headroom).

## Files

- `lego/operator/cmd/health-probe/main.go`, `lego/operator/internal/healthprobe/`
- `lego/operator/internal/controller/deployment_projection.go`, `health_probe.go`

## Acceptance criteria

- [ ] Unit: `health-probe drain` returns immediately when the check fails (500, refused, timeout), and after the configured seconds when it passes.
- [ ] Projection test: a web service with a Health Check Path gets the exec preStop with the same path, port and Host as its probes. One without a path is unchanged until t002.
- [ ] Envtest or kind check: a pod whose check fails is restarted within the liveness window plus 5 s; deleting a healthy pod still delays SIGTERM by the drain.

## Outcome (2026-11-14)

Done.

- `health-probe drain --seconds N CHECK…` (`lego/operator/cmd/health-probe/main.go`) runs one of the helper's checks (`check`, `open-port`, or the new `tcp`) and sleeps N seconds only when it passes. A failing check, an unknown check and bad arguments return at once, and it has no failure exit.
- The projection (`deployment_projection.go`, `health_probe.go`) writes the preStop as an exec of that drain whenever the operator knows its own image. `healthProbeDrainHandler` derives the check from the container's own liveness handler (`healthProbeCheckArgs`), so path, port and Host can never disagree with the probes. `terminationGracePeriodSeconds` stays drain + `maxShutdownDelaySeconds`. An operator without its own image (`make run`) keeps the plain sleep.
- Adoption is lazy. `deploymentParams.drainCheck` is kept from the stored template (`storedDrain` now also reports whether the drain is checked), so a stored sleep is reproduced until the template changes for another reason.
- Kubelet check: there is no kubelet in envtest, so it ran on a throwaway kind v1.36.1 cluster, with the linux/arm64 helper on a hostPath and the projected probe and preStop shapes. whoami with `/health` flipped to 500 was restarted 51 s after the flip under the checked drain (liveness kill at 12:36:43, container finished 12:36:43). The same pod with the plain sleep took 121 s (kill at 12:36:53, finished at 12:37:53). Deleting a healthy pod still took 61 s.
