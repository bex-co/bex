# A legacy Free cron job's Plan page pre-selects nothing and never says it runs on Free

Why: ADR030 §7 tells owners of existing Free workers, private services and cron jobs to "choose the transition" on the Plan page, but that page shows no current plan and no reason Free is missing, so the owner cannot tell what they are on or why.

- **Severity:** minor (the page misleads by omission; nothing is lost or mis-billed).
- **Source:** live functional `/qa-find-bugs w4`, pass 65314e, 2026-10-19 UTC, `muse.env`, workspace `bex-canary`, production pinned to `f3871ba9fd44` (contains `bed5e2c32`, w8/048). Read-only on a fixture this run did not create. Screenshot `.playwright-mcp/qa-cron-plan-legacy-free-65314e.png` (local, gitignored).
- **Repro:** open `/services/srv-dap3r714dm7c7390q91g/plan`. That is `qa-20260922-cd9361-nativecron`, a cron job created on Free on 2026-09-22, before w8/048. It is still running: a successful run every minute in `GET /v1/cron-jobs/<id>/runs` and Events.
  - `GET /v1/services/<id>` reads `serviceDetails.plan: "free"`, and the header chip reads **Free**.
  - The radiogroup "Pick an Instance Type" has a single **Paid** group, Starter through Pro Ultra, and **no radio is checked**. No text on the page mentions Free, that Free is not available to cron jobs, or that the job keeps running.
  - Save Changes stays disabled until a card is picked.
- **Control:** `/services/srv-dbalgb8eir4c73eq4fr0/plan` (Free web service `qa-20261018-f4cfb1-echo`) shows a **Free** group with `radio "Free 512 MB (RAM) 0.1 CPU" [checked]`.
- **Root cause:**
  - `dashboard/src/features/services/components/instance-type-picker.tsx:58` seeds `selected` from `currentPlan` (`"free"`).
  - `:61` builds `offered` with `offeredInstanceTypes(serviceType, …)`, which drops `free` for a paid-only type (`features/services/lib/instance-type.ts:28-32, 43-51`).
  - No offered card matches `selected`, and the picker has no branch that renders a current plan absent from `offered`. The component's own contract (`:42-48`, "the current plan pre-selected") does not hold for this case.
  - Keyboard access is fine: `use-card-radio-group.ts` falls back to the first card as the Tab stop.
- **Fix (target behavior):** when `currentPlan` is not among `offered`, the picker states the current plan above the cards. It names the plan and the type, for example "This cron job is on Free, which cron jobs can no longer use. It keeps running. Choosing a paid instance type moves it off Free, and it cannot return."
  - Keep Free unselectable (ADR030 §7's one-way door).
  - Keep no card pre-selected, so Save stays disabled and nothing paid is one click away.
  - Word the type from the service's type: worker, private service or cron job.
  - Ship `en` and `zh` strings together (w4/310–313 precedent).
  - Do not change `offeredInstanceTypes` or the create form.
- **Blast radius:**
  - `InstanceTypePicker` is rendered once (`routes/services.$serviceId.plan.tsx:46`, `currentPlan={service?.plan ?? null}`).
  - `offeredInstanceTypes` has 2 callers: the picker and `hooks/use-new-service-form.ts:131`. The create form is unaffected, because a new service has no current plan.
  - Affected types: `background_worker` (Free before w6/025, 2026-09-06), `private_service` (before w1/111, 2026-09-28), `cron_job` (before w8/048, 2026-10-15).
- **Adjacent classes:**
  - An untiered service (`currentPlan` null, `tier: ''`, which ADR030 §7 groups with Free) also pre-selects nothing. It should get the same notice, without naming a plan it does not have.
  - A current plan the catalog does not carry should keep today's behavior.
  - A Free web service is unchanged (the control above).
- **Unverified:**
  - No legacy Free worker or private service exists in bex-canary, so those two are shared code only, not probed.
  - The 390 px layout was not checked.
  - The owner notice that ADR030 §7 and w8/048 require was not observed.
- **Dedupe:**
  - `w8/blocked/048.md` covers the server rule and the owner inventory and notice, not this page.
  - `rg -i 'legacy free|no longer offered|currentPlan' .pm` found no open item.
  - No change to the picker or `instance-type.ts` since `e09c97706` (w4/329).
- **Render:** n/a. Render never sold Free for these types, and its picker always pre-selects the current plan.
- **Acceptance:**
  - A picker test with `serviceType="cron_job"` and `currentPlan="free"` renders the notice and no checked card. It fails on the current code.
  - Controls: a Free web service still pre-checks Free, and a paid cron still pre-checks its tier.
  - Live: the repro URL shows the notice at 1440 and 390 px.
- **Estimate:** 30m.

**Implemented 2026-10-19 (loopx w4):** `InstanceTypePicker` now states the current plan when a paid-only type's plan matches no offered card. A worker, private service or cron job still on Free reads "This cron job is on Free, which cron jobs can no longer use. It keeps running. Choosing a paid instance type moves it off Free, and it cannot return." (worded per type). An untiered one says it has no instance type, without naming a plan.
- **Unchanged:** Free stays unselectable, no card is pre-selected, and Save stays disabled. `offeredInstanceTypes` and the create form are not touched. A plan the catalog does not carry keeps today's behavior.
- **Copy:** en and zh.
- **Simplify follow-up:** the rule lives in `legacyFreeNotice()` beside `PAID_ONLY_SERVICE_TYPES`, tested to cover exactly the paid-only types. The notice is the shared `Alert` (role `note`) describing the radio group. It also renders over the catalog skeleton and in the route's pending skeleton (its copy needs no data), so the cards never jump. An untiered service is told it "can no longer use Free" rather than "cannot return".
- **Tests:** the cron-on-Free notice with no checked card fails on the old code (mutation: hiding the notice fails 4 tests); per-type and untiered wording; controls for a Free web service and a paid cron job (no notice, current card checked).
- **Remaining:** the live check at the repro URL at 1440 and 390, after the release pipeline deploys the dashboard.
