- the add and verify verbs;
- Blueprint `domains:` and `hosts`;
- the operator projection;

## Result (2026-11-11)

**`canonicalHostname` callers** (all in `lego/backend/internal/apps`):

| Caller | Wildcard behavior |
| --- | --- |
| add (`addOne` → `claimableHostname`) | accepted, then gated (`wildcardsAvailable`), reserved and overlap checks |
| verify (`VerifyDomain`) | lookup, then `domainPointsAtService` |
| delete (`DeleteDomain`) | lookup |
| create / Blueprint `domains:` (`canonicalHosts` → `claimableHostname`) | same gate, reserved and overlap checks as add (`checkHostsClaimable`) |
| Blueprint preview (`previewBlueprintHosts`) | now gives a new service's probe its namespace, so the same-workspace rule applies |
| `ParseReservedDomains` | refuses a wildcard entry |
| `ParseACMEDelegationZone` | refuses a wildcard entry |

**Other readers:**

- The www/apex pairing never pairs a wildcard (`wwwSibling` is empty).
- Pending claims never reach the spec.
- The operator projection, activator and static server: see t003.
- `pendingPublicURL` and `status.URL`/`URLs` leave wildcards out.
- The health-probe Host skips a wildcard.
- Certificate diagnostics match a wildcard's Challenge by base name and `spec.wildcard`.

**Plan limits:** a wildcard counts as one domain against the per-service and per-workspace caps, as on Render.

**Regression:** the existing domain suites (concrete add, pairing matrix, reserved hosts, public suffixes, cross-tenant collisions) all pass.
