## Objective

`canonicalHostname` (`lego/backend/internal/apps/domains.go:297-302`) accepts exactly one leading `*.` label, and keeps refusing every other wildcard. Add answers Render's `201` array. The domain's `dnsRecord` carries the wildcard CNAME and the `_acme-challenge` record. Verification uses the same verify and sweep path as concrete domains.

## Context

- The hijack concern in the code comment must hold under t001's collision rules. A wildcard that covers another workspace's concrete or wildcard domain is refused, and a concrete host under a wildcard routes to its own service.
- Unchanged refusals: reserved platform hosts (`*.onbex.co`), bare public suffixes (`*.co.uk`) and multi-level wildcards.

## Acceptance criteria

- [x] **Tests:** add, list, verify and delete a wildcard; each collision case; each unchanged refusal.
- [x] REST, GraphQL and MCP return the same result for each case.

## Result (2026-11-11)

- **`canonicalHostname`** accepts one leading `*.` label over a valid host. `claimableHostname` applies the label, numeric-TLD and public-suffix rules to the base, so `*.co.uk` stays invalid. `*.onbex.co` and anything under the platform zones are `CUSTOM_DOMAIN_RESERVED`.
- **Records:** `dnsRecord` is CNAME `*` to `<slug>.onbex.co`. The new `challengeRecord` (REST `challengeRecord`, GraphQL `challengeRecord`, MCP via REST's shape) is CNAME `_acme-challenge` to `<slug>.<BEX_ACME_DELEGATION_ZONE>`.
- **Verification** (`domainPointsAtService`) needs a fresh random name below the base to point at the service, and the `_acme-challenge` delegation (`DelegatesChallenge`). `PointsAtService` now refuses a host whose CNAME chain ends at another service's platform host. Before this, a name under someone's wildcard record verified for anyone through the shared edge addresses.
- **Collisions:** `hostClaims` records each claimant's workspace (its tenant id, else namespace). `coveredElsewhere` refuses cross-workspace overlap at any depth, as a DNS wildcard answers at any depth: a wildcard over another workspace's names, or a name under another workspace's wildcard. It runs at add, create and Blueprint, and again at promotion. Same-workspace overlap is allowed. The verification sweep shares one claim index per tick.
- **Gate:** without `BEX_ACME_DELEGATION_ZONE` every wildcard is `CUSTOM_DOMAIN_WILDCARD_UNAVAILABLE` (t011).
- **Tests:**
  - `domains_wildcard_test.go`: lifecycle, the reserved code, the overlap matrix including depth and tenant identity, refusal at verification, and the refusal without a zone.
  - The resolver-scripted `PointsAtService` and `DelegatesChallenge` cases.
  - `TestLoadConfigACMEDelegationZone`.
  - The old refusal tests are narrowed to malformed wildcards.
