## Objective

Two things had to hold before t011 turns wildcards on.

- **Overlap at the write.** A claim that another workspace's verified wildcard covers, or a wildcard over another workspace's verified name, stays pending. The promote path checked that only on its host-claim index. Each bex-api replica builds its own index (one per sweep tick, one per request for a manual Verify). An index loaded before another replica promoted its half of an overlapping pair let both halves verify, and the store's promotion was a plain compare-and-set.
- **Which record verifies.** A wildcard and every name under it could verify on edge addresses. If a wildcard's `*` record answered with the edge addresses, another workspace's pending name under it could verify first, by polling Verify. The wildcard was then refused as in use.

## Decision

**User decision 2026-11-21: follow Render's record rules where a wildcard is involved.** Render sets a wildcard up only through CNAME records and offers an A record only for an apex.

- A wildcard verifies only through a `*` CNAME to its own service's platform host.
- A non-apex name under another workspace's pending or verified wildcard verifies only through a CNAME to its own service.
- Every other host keeps today's proof, so no existing domain changes.
- The refusal message names the CNAME target.

There is no ADR018 entry, because it is Render's documented record type.

## Acceptance criteria

- [x] `PGStore.PromoteDomainClaim` checks and writes in one transaction, under `pg_advisory_xact_lock` keyed on the host's registrable domain (`domain-overlap:<shortest registrable suffix>`, shared by a wildcard and every name under it). A verified domain of another workspace that overlaps the host is `store.ErrDomainCovered`. `checkAndPromoteClaim` records an attempt and leaves the claim pending, as for its index pre-check, which stays.
- [x] The traffic checker's CNAME branch stands alone as `CNAMEsToService`. A wildcard's `*` probe uses it, and so does a non-apex name that `PGStore.ForeignWildcardCovers` finds under another workspace's wildcard. A failed read requires the CNAME.
- [x] The storeless gate's refusal names the CNAME and its target.
- [x] REST, GraphQL and MCP all verify through `Service.VerifyDomain`, and the sweep through the same `checkAndPromoteClaim`, so the change is the same on every surface.
- [x] ADR005 § Wildcard domains records the rule and the serialized check.

## Result

- **2026-11-22:** done.
- **Tests.**
  - `TestOverlappingClaimsVerifyOnceAcrossTwoReplicas`: two replicas run the real sweep tick over one due list. Replica 1's whole tick runs after replica 2 has loaded its index, in both list orders. Only the first claim verifies, and the other stays pending after two attempts.
  - `TestPGConcurrentOverlappingPromotionsVerifyOne`, on real Postgres: two goroutines promote `*.<base>` (one workspace) and `api.<base>` (another). Both wait on the one overlap lock, and exactly one row ends `verified`.
  - `TestPGPromoteDomainClaimRefusesAnotherWorkspacesVerifiedOverlap` and `TestPGForeignWildcardCovers` cover depth, pending versus verified, the same workspace, the base and a sibling domain.
  - `TestWildcardRecordsFollowRender`: an address-answering `*` record verifies neither half, whichever is checked first. Once the `*` CNAME is in place, only the wildcard verifies.
  - `TestOnlyANameUnderAnotherWorkspacesWildcardNeedsACNAME`, `TestCNAMEOnlyRefusalNamesTheTarget`, `TestCNAMEProofRefusesAddresses`, `TestDomainOverlapDomainIsSharedUnderAWildcard`.
- **Mutation checks.** Each new test fails when its rule is switched off: the store's overlap refusal, the overlap lock, the `*` CNAME rule, and the CNAME rule for a name under another workspace's wildcard.
