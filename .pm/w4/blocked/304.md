## Cause, consumer and scoped fix

`dashboard/src/routes/env-groups_.$groupId.tsx:112–115` computes the scoped label with `environmentNameIn(scope,id) ?? t(unknownEnvironment)` without consulting scope loading/ready/error. The helper at `features/env-groups/lib/scope.ts:30–45` correctly returns undefined when the current index does not yet contain the ID.

The producer `hooks/use-env-group-scope-index.ts:29–43,50–96` starts a scoped snapshot and a one-shot Apollo query; `:99–130` explicitly exposes loading, ready and error. During the initial read the map is empty, so this route converts “not loaded” into “unknown.” Its Linked Services consumer already separately receives scope.loading/error/ready at `routes/env-groups_.$groupId.tsx:224–227`; do not change its existing candidate rules.

The exact display consumer is `features/env-groups/components/env-group-metadata.tsx:12,19–24,50–73`: environmentLabel is an optional **string**, and MetadataItem prints the string verbatim into a native dd and its title. React does not reinterpret that fallback as loading. There is no Radix or other label resolver in this path.

**Target:** retain the single-line, truncating metadata value's stable geometry and the real Project / Environment label once available. For a non-null environment ID without a last-good label, show localized **“Loading environment…”** with status semantics while the index is unresolved; show localized lookup-failure copy when its read fails. Reserve **Unknown Environment (id)** for a completed successful lookup that lacks the ID. A genuinely null assignment continues to show Workspace. Keep a last-good label during an ordinary refresh and distinguish that from a failed initial read. Never show Workspace, Unknown, or an old ID as a pending-state fallback.

Add optional local environment-state information to EnvGroupMetadata/its environment row, or another equally bounded string/status mapping. Preserve the current string title contract: do not pass a ReactNode into the string-typed prop/title and assume it works. If the component renders a status node, guard title accordingly. Its default state keeps other rows unchanged. Add en/zh copy through the existing typed locale files. Keep the existing grid, font/line height and truncation, so the status replaces only this value slot. No scope-index cache/poll rewrite, new query, assignment mutation or global formatter change is needed.

**Census:** one production EnvGroupMetadata JSX mount, this detail route. Its local MetadataItem has four unconditional rows plus optional Availability; state belongs only to Environment. Two production environmentNameIn callers exist: detail and collection. The collection is a source-traced sibling, not a live failure claim; audit its equivalent fallback before broadening. Three ScopeSelect mounts (Create/Move/Clone) and the two NewEnvGroupDialog mounts keep their existing states, values and gates. The canonical group-detail route is unchanged; no resource-kind alias is introduced.

**Adjacent controls / verification:** workspace-null, successful found ID, successful genuinely absent ID, initial query error, retry/refresh with last-good label, ID/owner transitions and en/zh remain meaningful local behavioral cases. Only successful found-ID pending→ready was induced live. Preserve existing missing-group/route errors and mutation controls; do not infer that a scope-index error deleted an environment.
