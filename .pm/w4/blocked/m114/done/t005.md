production incident step by step (trigger → cancel manual → cancel unrelated →
resume), asserting the canceled run stays settled at every step, plus:

- `TestManualRunSettledCoversEveryTerminalStatus` — Succeeded/Failed/Canceled
  settle, Running does not (so an in-flight run is still recreated if its Job
  vanishes, and still pauses the schedule).
- `TestManualRunSettledIsSilentWithoutAMatchingRecord` — no runAt, no history,
  and another run's terminal record each leave the gate open.

  predicate fixes: `manualCronRunActive`'s NotFound branch used to read a
  canceled run's deleted Job as "about to be created" and pause the recurring
  schedule indefinitely.
- The in-test control: a fresh trigger (new `runAt`) is NOT settled, so the
  guard cannot become always-on.
