# Chinese dialogs keep an English accessible Close label

Why: users choosing Chinese still encounter an English action name on the shared dialog close button, even when the dialog's heading and other controls are translated.

**Severity:** minor localization defect. **Estimate:** 25m. Functional `$qa-find-bugs w4`, a595, 2026-10-15 UTC; source checked on synced main `b0b4d70fc`. Filing only.

## Reproduction and evidence

1. Sign in through the QA helper. Avatar → Language → 中文.
2. At 1440px, New → 新建项目. Its accessibility tree has a Chinese title, fields, Cancel and Create labels, followed by **button "Close"**. This was observed before creating the owned Unicode-name project.
3. From a fresh navigation at 390px, New → 新建 Postgres 数据库. At **14:54:34.056Z**, `<html lang="zh">` and the dialog's Chinese labels were present, but the close button's accessible name was again **Close**. Clicking it closes the dialog normally.

**Passing control:** select English and reopen New Project. At **14:59:30.897Z**, its Close name is appropriate and the native close action works. A later check confirms the dialog has unmounted; the immediate count during its exit animation is not a failure. The defect is the selected-language mismatch, not a missing name or a broken close action. No screen-reader audio behavior was measured.

[Durable accessibility trees, language controls, replay instructions, caller census and cleanup](evidence/310-311-shared-control-labels.json). The local screenshot `.playwright-mcp/qa-localization-a595-postgres-mobile.png` is supplementary; the accessible-name evidence is in the durable JSON.

## Cause and bounded fix

`dashboard/src/common/components/ui/dialog.tsx:43–80` owns the default close button; **line 75 hardcodes `<span className="sr-only">Close</span>`**. The feature dialog's translated children cannot replace that child. `dashboard/src/features/projects/components/new-project-dialog.tsx:81` and `dashboard/src/features/databases/components/create-database-dialog.tsx:196` both use this component.

Use the existing `useTranslations` hook from `common/hooks/use-translations.ts` and add a namespaced common key in **both** `common/locales/en.ts` and `zh.ts`, with English **Close** and Chinese **关闭**. Render that key in the shared close span. Its value remains a string accepted by the existing React child type. No new close-label prop, per-dialog workaround, provider, dependency update or API change is needed.

The actual checkout dependencies were inspected: React/React DOM **19.2.3**, Radix Dialog **1.1.15**, react-i18next **17.0.8**. Radix's installed Close forwards caller props/children to a button and changes open state; the English name comes from Bex's span. [React's portal contract](https://react.dev/reference/react-dom/createPortal) preserves parent context. The translated Cancel button inside the same live dialog independently confirms that localization reaches the portal. Preserve the existing Radix close behavior and focus management.
