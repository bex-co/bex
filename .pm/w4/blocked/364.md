# 364 — A Postgres save that restarts nothing may still read `config_restart`

Why: w4/m233/t008 fixed this for Key Value. t001's verdict there found that a Postgres external-access change restarts nothing (CNPG v1.30.0 re-signs the server certificate and reloads), so `dbStatus` probably over-reports the same way. Status reads `config_restart` until the database controller observes the generation, though nothing restarts.

## Shape of the fix if it reproduces

Mirror the Key Value rule (`keyvalue/service.go`: `markRestartFree`, `restartFreePending`, `patchKeyValueLocked`). The update path marks a generation restart-free under an optimistic lock, and the status reads `available` while it is the only unobserved generation of a Ready database. **Premise settled from code 2026-10-19 (loopx w4); implementation done the same day.** No live probe was needed to prove the reading: `dbStatus` had no restart-free exception and `patchDatabaseObj` returns the view of the just-patched CR (generation bumped, Ready's `ObservedGeneration` behind), so a restart-free save's own response read `config_restart` — the shape w4/m233 measured live on Key Value at 1–3 s per save through the identical `core.DatastoreReadyStatus`. The database controller stamps Ready with the current generation only at the end of a successful reconcile (`database_controller.go:1381`), which is the gap. Placement and environment fan-out writes stay unmarked, exactly as shipped for Key Value.
