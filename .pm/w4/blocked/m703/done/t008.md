## Objective

Make sure tests hold each answer's status and the `rndr-id` rule, and their failure modes, beyond what t001, t002 and t004 added.

## Steps

1. Plugin: every method on every kind of route, a caller's own `Cf-Cache-Status` or `Rndr-Id`, and the old-spec case.
2. Static server: each answer kind, a cache eviction between two reads, a collapsed flight, and a header rule that names the header.
3. Revert each change once and watch its test fail.

## Acceptance criteria

- [x] Each rule has a test that fails with its change reverted, and the plugin tests, `make test` and `make lint` pass.

## Record — 2026-11-27

Each rule was reverted once and its test failed, then restored byte for byte: the redirect keeping `Rndr-Id` (`TestHTTPSRedirectAnswersRendersEdgeHeaders`, `TestStaticSiteRedirectReadsTheStoredCopy`), the redirect setting no status, the fallback's passed-through answer left unmarked (`TestFallbackMarksItsPassedThroughAnswer`), a static site's `301` reading `DYNAMIC`, the memo never expiring (`TestRedirectMemoExpiresAsCloudflareDoes`) or never evicting (`TestRedirectMemoIsBounded`), the operator writing the plain spec for a static site (`TestAStaticSiteGetsTheStaticSiteRedirect`), the static server's `cached` flag dropped (four tests, among them the eviction and the collapsed flight), a header rule allowed to set the status on a file or an error path, an external rewrite keeping its destination's status, opt-out headers ignored, and no default status.
