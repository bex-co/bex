## Objective

`https://<unknown>.onbex.co/` answers its `404` with `cf-cache-status: DYNAMIC`, `server: cloudflare`, a `cf-ray` and no `rndr-id`, as Render's `no-such-service-w4-736.onrender.com` did on 2026-11-27.

## Context

- The fallback route (`lego/operator/config/activator/platform-host-fallback-ingress.yaml`) sends an unknown host to the activator's `404` behind `platform-host-fallback-https`.
- The sanitizer sets `Rndr-Id` on the response before the route runs, and Traefik's proxy adds the backend's headers to it, so the activator cannot remove it. Only a plugin instance on the route can.
- Under Yaegi a wrapped `ResponseWriter` loses `Flush` for compiled code after it (`originServerWriter`'s comment). The fallback's chain has only the redirect instance, and a `404` page does not stream.

## Steps

1. Pick where the change lives: the fallback's redirect instance, with a config field that also edits a passed-through answer, or a separate instance on the fallback route. Prefer the smaller change that adds no writer wrapper to tenant routes.
2. Set `Cf-Cache-Status: DYNAMIC` and remove `Rndr-Id` on the fallback's answers. A tenant App's route keeps its `rndr-id`.
3. Check what bex answers for a suspended service and a suspended static site (the activator's suspended responder) against Render, if a Render capture can be had. File any difference as a follow-up note rather than widening this task.
4. Tests: a plugin test for the passed-through `404`, and the fallback's case in the redirect Traefik gate.

## Files

- `deploy/gitops/charts/traefik-plugins/clientipheaders/`
- `lego/operator/config/activator/platform-host-fallback-https.yaml` or a new fallback Middleware, with its Ingress annotation

## Acceptance criteria

- [x] `http://` and `https://` to an unknown host answer `DYNAMIC` and no `rndr-id`, in a plugin test and on the Traefik gate.
- [x] A tenant App's `https://` answer still carries its `rndr-id`.

## Record — 2026-11-27

- **Where (step 1):** the fallback's own redirect instance, with a `platformFallback` field: on a passed-through request it deletes `Rndr-Id` and sets `Cf-Cache-Status: DYNAMIC` on the response before the activator answers, with no writer wrapper, and no tenant route changes. `platform-host-fallback-https.yaml` sets it; the `pub-` bucket hosts' plain-HTTP route shares that Middleware and only ever redirects.
- **Suspended answers (step 3):** Render's differ by who suspended a service (`suspend-by-user` static site `BYPASS` and no `rndr-id`, web service `BYPASS` with one, `suspend` `DYNAMIC` with none); bex answers each with `suspend` and a `rndr-id`. Filed as [w4/755](../../../755.md).
- **Tests:** `TestFallbackMarksItsPassedThroughAnswer` (a tenant route keeps its `rndr-id` and gets no status), `TestPlatformHostFallbackRouteIsTheLowestPriorityCatchAll` pins the manifest's spec, and the Traefik gate's `unknown_host` case checks HTTP and HTTPS.
