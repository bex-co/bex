# 288 — A Git-to-image source switch leaves Blueprint export unable to generate

Why: a working image service cannot be exported because the generator includes a saved Git root directory that its own image-manifest contract rejects.

**Severity:** major · **Estimate:** 55m · **Worker:** worker4 · **Status:** todo

## Producer, consumer and correction

- `lego/backend/internal/apps/service.go:4206–4214`, `sourceFields.applyTo`, changes repo/image/branch/registry credential while retaining native settings, including RootDir. That retained configuration is intentional and is proven useful by the successful staged-Git export.
- `blueprint_generate.go:347–356` explicitly emits `runtime: image` and image.url when spec.Image is present; `exportedBuilder` (:597–608) similarly omits a build strategy for it. The runtime choice is already correct.
- **Missing boundary:** `blueprint_generate.go:370–375` emits any nonempty RootDir unconditionally. Its neighboring buildFilter emission is also unconditional and warrants review against the same image policy; a retained-filter failure was not live exercised in this pass.
- `blueprint_compiler.go:360–366` lists rootDir among Git-only fields; its prebuilt-image loop (:413 onward) rejects the property's **presence**. `docs/ADR049-render-yaml-parity.md:166–168` documents that restriction. Do not widen the compiler or emit an empty placeholder.
- `blueprint_generate.go:230–244` marshals the entry and self-checks with CompileBlueprintIR then parseCompiledStack. The emitted rootDir triggers its coded failure. Keep this gate and its truthful resource-specific error.
- Scope the omission to the image branch the generator already chose. Git builds, static sites and source-switch-back behavior keep rootDir. Review neighboring Git-only fields against prebuiltImageSourceFields; buildCommand, Dockerfile settings and exported builder already have build/source gates. Any additional retained-field case must be tested and identified as source-only unless independently reproduced.

Caller census: **one production generateServiceEntry call** at `blueprint_generate.go:199`, inside the selected App loop. It covers web, private, worker, cron and static; the image/rootDir case applies to the four image-capable kinds, while static is Git-only. PostgreSQL, Key Value and environment-group entries have separate emitters. **Three public adapters** call the same GenerateBlueprint verb: REST `apps/rest.go:1368–1387`, GraphQL `apps/graphql.go:1263–1281`, MCP `apps/mcp.go:1037–1048`. One dashboard dialog uses it (`generate-blueprint-dialog.tsx:128–143`); its existing failure handling is honest. No adapter-specific field deletion or UI-only repair is needed.
