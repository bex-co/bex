## Objective

The Postgres Access control panel must not say a public database has no IP rules while its own allowlist read is still in flight. Until the list lands it previews the rule rows at the ready geometry, as Key Value Networking already does (w4/303).

## Context

- Found by the 2026-11-16 t003 replay (pin carrying `06cc3b02c`) on a public Free Postgres with no saved rules. After a reload, `#access-control` read "No IP rules. Save an empty list to block external connections." from about 1.7 s to 8.3 s. Only then did the batched `DatabaseIpAllowList` response (batched with `DatabaseProcesses`, `DatabaseTopQueries` and the other insight queries) arrive and the two rows `0.0.0.0/0` and `::/0` replace the text.
  - That transient text is the m315 bug in UI form: it says blocked while the store is open.
  - It also breaks DoD 5's skeleton bullet: the pending frame is an empty state, not a preview.
- `useAccessControl` (`dashboard/src/features/databases/hooks/use-access-control.ts`) mapped a missing `data` to `[]`. `AccessControlPanel` never read the hook's `loading`.

## What shipped

- `useAccessControl` returns `allowListPending` (the first allowlist read is in flight with no data yet).
- `IPAllowListEditor` takes `pendingRows`. It renders that many `RuleRowSkeleton` rows (`data-preview="ip-rule-rows"`) where the rules go, and keeps the add row's inputs disabled. The hint and add row are the ready ones, so they keep their exact geometry.
  - `RuleRowSkeleton` moved here from `workspace-ip-rules-card-skeleton.tsx`, which now imports it, so the two previews share one row shape.
- `AccessControlPanel` passes `pendingRows={2}` while pending. A dashboard-created Postgres is public by default (`create-database-dialog.tsx:106`), so the default ready state is the effective allow-all pair.
  - A private store's ready state (the internal-only line and the empty text) is not assumed, matching the w4/303 choice for Key Value.
