## Objective

Every Key Value and Postgres allowlist read returns effective external access:

- a public store with no saved rules reads `0.0.0.0/0` + `::/0`, each with the "Allow all (default)" description;
- a private store reads `[]`;
- a store with rules reads exactly its rules.

One shared core helper serves every read path, including the Blueprint export, which already applies this rule on its own.

## Context

- **Views.** `kvView` (`lego/backend/internal/keyvalue/service.go:312-325`) and `pgView` (`postgres/service.go:579-604`) read `core.AllowListOrEmpty(core.AllowListFromSpec(spec.IPAllowList))`. The REST Key Value wrapper repeats it (`keyvalue/rest.go:104`).
- **`GetIPAllowList`** (`keyvalue/service.go:936-944`, `postgres/access.go:47-56`) has these callers:
  - REST: `keyvalue/rest.go:240-241`, `postgres/rest.go:355-356`
  - GraphQL: `keyvalue/graphql.go:140`, `postgres/graphql.go:483`
  - MCP: `postgres/mcp.go:367-374`
- **Export.** `datastoreAllowListEntries` (`apps/blueprint_generate.go:922-933`) already applies the rule, but on CR types (`appv1alpha1.IPAllowEntry`).
- **Wildcard rules.** `core/cidr.go:214-215` defines them with the "Allow all (default)" description.
- **Writes stay unchanged.** `SetIPAllowList` and PATCH map a nonempty list to public and an empty list to private. A store that reads back wildcards therefore stays public when that list is written back.
- **Aliases.** The Render `/v1/redis/*` family runs the `/key-value` handlers (ADR018, legacy Redis spelling).

## Steps

1. Add a core helper, e.g. `core.EffectiveAllowList(public bool, entries []IPAllowListEntry) []IPAllowListEntry`: empty when private, the two wildcard rules when public with no entries, otherwise the entries. It never returns nil.
2. Use it in `kvView`, `pgView` and both `GetIPAllowList` functions, so REST GET and list, the `/redis` alias, `GET …/ip-allow-list`, GraphQL and MCP all read through it.
3. Switch `datastoreAllowListEntries` to the same rule. Convert types at the edge, or make the helper generic.
4. Grep every other datastore allowlist read (connection-info, environment projections, audit diffs) and decide each case explicitly. Note the decisions in the PR.

## Result (2026-11-11)

- `core.EffectiveAllowList(public, specEntries)` (`lego/backend/internal/core/cidr.go`): `[]` when private, `core.UnrestrictedAllowList()` (`0.0.0.0/0` + `::/0`) when public with no saved rules, otherwise the saved rules; never nil. It replaces `AllowListOrEmpty(AllowListFromSpec(…))` in `kvView` and `pgView` and the raw return of both `GetIPAllowList` functions, so REST get/list/PATCH responses, `/v1/redis`, `GET …/ip-allow-list`, GraphQL (`keyValue`, `keyValueIpAllowList`, `database`, `databaseIpAllowList`) and MCP (`get_key_value`, `get_postgres`, `get_postgres_ip_allow_list`) all read through it. `AllowListOrEmpty` had no caller left and is gone.
- The Blueprint export's `datastoreAllowListEntries` now calls the same helper; its output is byte-identical (the existing `blueprint_roundtrip_test.go` "legacy unrestricted public" and datastore-access tests pass unchanged).
- **Deviation, deliberate:** the wildcard rows carry **no** description, not "Allow all (default)". That is how REST Postgres create (w2/038) and Blueprint create (w8/157) already save the same default, and what the export emits, so one effective state reads identically whichever path created it, and the export stays byte-identical as this task requires. `UnrestrictedAllowList` now backs REST create and Blueprint create too.
- Other reads checked: connection-info reads `public`/the external host, not the list; `recovery.go` copies the spec (a write); environment projections use `spec.environmentIPAllowList`. No other datastore allowlist read exists.
- The MCP tool description no longer tells agents to combine the list with `public`.
