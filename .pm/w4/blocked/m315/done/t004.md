## Objective

Confirm that REST, GraphQL, MCP and the dashboard expose the same allowlist read semantics for both datastores, and compare them with render.com.

## Context

- Render documents an empty list as external access disabled, and a public Postgres default as `0.0.0.0/0`. Render has no separate `public` toggle.
- Related ADRs: ADR009 (lines 244–275), ADR021 (lines 34, 52–62), ADR018 (datastore access rows).

## Steps

1. Diff the four surfaces' readback for public with no rules, private with no rules, and explicit rules.
2. Check the Render dashboard or docs wording for an allow-all row. If it can't be seen, record that.
3. Update ADR009, ADR021 and ADR018 so they describe the read projection, and supersede the "public/empty retains its saved representation" readback wording where it applies to reads.
4. File any remaining drift as a follow-up.

## Result (2026-11-11)

- REST, `/v1/redis`, GraphQL, MCP, the dashboard and the export now agree for public/no rules (`0.0.0.0/0` + `::/0`), private (`[]`, whatever inactive rules it keeps) and explicit rules (those rules), pinned by `TestAllowListReadsReportEffectiveAccess` in both packages.
- Render: an empty list means external access is disabled, and a public Postgres's documented default is `0.0.0.0/0` (render.com/docs/key-value#enabling-external-connections, render.com/docs/postgresql-creating-connecting#restricting-external-access). The Render dashboard's wording for an allow-all row was not seen this session; recorded as unverified.
- ADRs: ADR009 (create matrix readback column, a "Reads report effective access" paragraph, the pinned-CLI note), ADR021 (§ Datastore allowlist update intent: the read projection supersedes "the dashboard reads public intent together with entries"), ADR018 (Postgres access and Key Value rows, the CLI-compatibility paragraph).
- Remaining drift: GraphQL/MCP/dashboard Postgres creates stay private by omission, so a GraphQL create with rules reads `[]`; that default is w4/553's scope, not a read drift.
