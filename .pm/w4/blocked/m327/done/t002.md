## Objective

`reportKubernetesRunning` (`lego/operator/internal/controller/app_controller.go:3315`, `rolloutDone` at `:3336`) and `reportRolloutProgress` (`:3699-3709`) stop stamping `PhaseDeploying` when the Deployment's template revision is the active revision and no newer release is stamped, requested or rolling. Ready stays `False` with the existing `HealthCheckFailing` / stall / quota / node-loss diagnosis.

## Context

- The deadline helper already follows this rule: "A served release is excluded, because its pods going unready is not a deploy" (`:3798`).
- The worker path (`:3661-3665`) uses the same helper.
- Unchanged: a newer template rolling, a pre-deploy step (`:6994`), the wake or resume start (`release_plan.go:463`), and `web_image_http.go:234`.

## Acceptance criteria

- [x] **envtest:** a live web service whose pod loses readiness reads `Running`, Ready=False/HealthCheckFailing, and recovers to Ready=True.
- [x] **envtest:** a newer template rolling still reads `Deploying`, and so does a wake.
- [x] The same holds for a worker and a private service.

## Result (2026-11-11)

- `reportRolloutProgress` keeps phase Running when `servedReleaseOutage` holds: the App was Running, and the Deployment runs the active revision, which is also the release (`runsActiveRelease`). Ready stays False with the diagnosis (`HealthCheckFailing`, `CrashLoopBackOff`, quota or node loss).
- **Unchanged:** a newer release rolling, a first release, and the live release starting after a wake or a resume (it was Hibernated) all read Deploying, as does a pre-deploy step.
- **Spec writes during the outage** (found in `/simplify`): `rolloutPending` no longer stamps Deploying when a Running App's spec write leaves it on its live release with the same image, such as a scale, a domain, or a setting that waits for a deploy. Without this, the first such write during an outage brought "Deploying" back until recovery.
- **Tests:** `TestServedReleaseOutageIsNotADeploy` (four cases) and `TestRolloutPendingOnlyForANewRelease`. The envtest `app_child_health_envtest_test.go` now expects Running with Ready `CrashLoopBackOff`.
