## Objective

A metrics outage or a permission regression can never again disable autoscaling invisibly.

## Steps

1. In `applyAutoscaling` (`autoscale.go:306-309`), log the read error with the App name, rate-limited per App.
2. Set an App condition (e.g. `AutoscalingMetricsAvailable=False`, with a tenant-safe reason) while reads fail, and clear it on the first good read.
3. Expose it where the Scaling page already reads autoscaling state: GraphQL, and the REST autoscaling read as a bex extension. The Scaling page then says "Autoscaling is paused: utilization metrics are unavailable" instead of implying it is active. en and zh.
4. Add an operator metric (failed reads per App) and an alert on sustained failure across Apps.

## Acceptance criteria

- [ ] An envtest with a `MetricsReader` that returns an error sets the condition and logs once per window. A later success clears it.
- [ ] The Scaling page shows the paused state from that condition.

## Outcome (2026-11-14)

- `applyAutoscaling` → `metricsReadFailed` (`lego/operator/internal/controller/autoscale.go`): increments `bex_autoscaling_metrics_read_failures_total{namespace,app}`, sets `AutoscalingMetricsAvailable=False` (reason `MetricsUnavailable`, tenant-safe message, constants on the CRD contract in `lego/types/v1alpha1/app_types.go`) and logs `autoscaling metrics read failed; holding the instance count` with `app`/`namespace` and the error: at once when the condition appears, then at most every 10 minutes per App. The first good read removes the condition (and logs the recovery); a pass that skips autoscaling (off, suspended, unwired) removes it too. The count is still held.
- Exposure: `AutoscalingView.MetricsUnavailable` → REST `GET`/`PUT …/autoscaling` and `serviceDetails.autoscaling` as the bex extension `metricsUnavailable` (response-only type, so a request carrying it is still refused), GraphQL `Autoscaling.metricsUnavailable`, MCP `get_autoscaling`. The Scaling page shows "Autoscaling is paused: utilization metrics are unavailable" (en + zh) while autoscaling is on and the flag is set.
- Alert `AutoscalingMetricsUnavailable` (warning; any App with failed reads in 10 m, held 15 m; value = number of Apps) in `deploy/gitops/base/rules/alerting_rules.yml` with promtool tests (`autoscaling_metrics_alerts_test.yml`), the series added to the `bex-operator` scrape keep-list, and a "Autoscaling metrics read failures" panel on the cluster-capacity dashboard (ADR088 §6). `bash scripts/gitops-validate.sh` passes.
- Tests: `TestAFailedMetricsReadIsVisibleAndClearsOnRecovery`, `TestSkippingAutoscalingClearsTheMetricsCondition` (unit), the envtest "Autoscaling with a refused metrics read (w4/m364)", the dashboard `autoscaling-section.test.tsx` paused cases, backend `TestAutoscalingReadReportsAPausedAutoscaler`.
- Not done: a nil (unwired) `MetricsReader` still skips silently, as before; production always wires it.
