## Objective

Establish the actual reason the autoscaler holds steady on production, then remove it.

## Context

- Probes and mechanism: [README § Finding](../README.md#finding-round-265).
- Reader: `NewMetricsServerReader` (`lego/operator/internal/controller/autoscale.go:83-93`). The error path: `autoscale.go:306-309`.
- The controller's ClusterRole is generated from `+kubebuilder:rbac` markers into `lego/operator/config/rbac/role.yaml` (`make manifests`). Today it has no `metrics.k8s.io` rule.

## Steps

1. On production, run `kubectl auth can-i list pods.metrics.k8s.io --as=system:serviceaccount:<operator-ns>:controller-manager -n <a workspace ns>`, and grep the operator log for the metrics GET error. Record the answer.
2. If refused: add `// +kubebuilder:rbac:groups=metrics.k8s.io,resources=pods,verbs=get;list` beside the core `pods` marker (`app_controller.go:491`), run `make manifests`, and check the generated rule.
3. If permitted: find the real reason before touching RBAC. Check whether metrics-server returns items for `labelApp=<app>` in the App's namespace, and whether `tierLimits(app.Spec.Tier)` returns non-zero CPU and memory. Record it in the README and re-plan t002.
4. Deploy and confirm DoD 1 on production.

## Files

- `lego/operator/internal/controller/app_controller.go`, `lego/operator/config/rbac/role.yaml`

## Acceptance criteria

- [ ] The README records the `can-i` answer (or the log line) before and after.
- [ ] An idle Starter service with autoscaling min 1 scales from 3 to 1 within 7 minutes on production.

## Outcome (2026-11-14)

- **Before (coordinator, 2026-11-14 03:19 UTC, read-only on production):** `kubectl auth can-i list pods.metrics.k8s.io -A --as system:serviceaccount:bex-system:bex-controller-manager` answers `no`, while APIService `v1beta1.metrics.k8s.io` (kube-system/metrics-server) is `Available=True`. The finding's mechanism is confirmed: every autoscaler read is refused, so `applyAutoscaling` holds every service at its count.
- **Fix:** `// +kubebuilder:rbac:groups=metrics.k8s.io,resources=pods,verbs=get;list` beside the core `pods` marker (`lego/operator/internal/controller/app_controller.go`); `make manifests` adds the rule to `manager-role` (`lego/operator/config/rbac/role.yaml`). Production renders that ClusterRole from `lego/operator/config/prod` through the `bex-operator` Argo Application, so no `deploy/gitops` RBAC file changes. A ClusterRole grant covers every tenant namespace; no tenant-namespace Role is needed (bex-api's own namespace-scoped grant in `bex-api-apps-rbac.yaml` is unrelated).
- **After:** not yet answerable; `can-i` must answer `yes` once a production pin carries this commit. Acceptance criterion 2 (3 → 1 within 7 minutes on production) is the t007 live replay.
