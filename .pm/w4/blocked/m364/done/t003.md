## Objective

Match Render's "Render ignores this value as long as autoscaling is enabled for the service". `POST …/scale` (and GraphQL `scaleService`, MCP `scale_service`) answers 202 and stores the count. The running count stays the autoscaler's, and the stored count applies when autoscaling is turned off.

## Context

- `Scale` writes `spec.replicas` (`lego/backend/internal/apps/service.go:4545-4580`). The operator seeds the autoscaler from `annotAutoscaleReplicas` when present, else from `spec.replicas` (`app_controller.go:3158-3172`). With t001 fixed, the annotation is normally present, so a manual scale is already ignored in steady state.
- The remaining gap is the first pass after autoscaling is turned on, while the first scale-down window holds and no count is recorded. A manual scale in that window still changes the running count.

## Steps

1. When autoscaling turns on, seed `annotAutoscaleReplicas` from the Deployment's current replica count, clamped to `[min, max]`, so the autoscaler always owns a recorded count. Do it in the operator's first autoscaling pass, or in the backend's `SetAutoscaling` (`service.go:6326`).
2. Leave `Scale` writing `spec.replicas`: that is the stored `numInstances` the service returns to when autoscaling is turned off (w5/130's rule).
3. Record `instance_count_changed` only when the running count changes. With autoscaling on, a manual scale changes the stored count only. Decide whether Render emits an event for it, and record the decision in the README.

## Acceptance criteria

- [ ] An envtest: autoscaling on with no recorded count, then a manual scale to 3 leaves the Deployment at the autoscaled count, while `spec.replicas` reads 3.
- [ ] Turning autoscaling off then runs 3.

## Outcome (2026-11-14)

- Operator: the first autoscaled pass with no recorded count (`annotAutoscaleReplicas`) seeds it from what runs (`autoscaleStart`: the Deployment's `spec.replicas`, else `spec.replicas`), clamped to `[min, max]` (`seedAutoscaler`). A count the clamp moves records an autoscaling transition, so it reports `autoscaling_started`/`autoscaling_ended`. From then on `spec.replicas` is only the stored count; turning autoscaling off still forgets the record (w5/130) and runs it.
- Backend: `Scale` keeps writing `spec.replicas` (REST 202, GraphQL `scaleService`, MCP `scale_service` all go through it).
- **Event decision:** with autoscaling on, a manual scale records no `instance_count_changed` (and therefore no audit row or webhook): no instance count changed, and Render documents no event for a scale it ignores ([scale-service](https://api-docs.render.com/reference/scale-service), re-read 2026-11-14). Trade-off: the stored-count change leaves no audit row; when autoscaling is later turned off, the disable's `autoscaling_config_changed` is recorded and the operator moves to the stored count.
- Tests: `TestAManualScaleUnderAutoscalingLeavesTheRunningCount`, `TestTheSeedIsClampedToTheRangeAndRecordsTheMove` (unit), the envtest (manual scale to 3 leaves the Deployment at 2 while `spec.replicas` reads 3; off runs 3), backend `TestScaleUnderAutoscalingStoresTheCountWithoutAnEvent` (REST/GraphQL/MCP) and `TestScaleWithAutoscalingOffStillRecordsTheChange`.
