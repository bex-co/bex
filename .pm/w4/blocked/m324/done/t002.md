## Objective

A native build's `failureReason` quotes the build command's output as the command printed it: `QA84 failing on purpose`, not `2.413 QA84 failing on purpose`. It names the cause in the user's terms. This finishes w4/485's expected shape: "`build failed in the docker build step:` + the command's output (`compiling`) + `error: build command '…' exited with code 3`".

## Context

- **Live, round 84.** `failureReason` was `build failed in the docker build step:\n2.331 13 packages are looking for funding\n2.331   run \`npm fund\` for details\n2.344 \n2.344 6 vulnerabilities … \n2.413 QA84 failing on purpose\nerror: build command 'npm install && echo QA84 failing on purpose && exit 3' exited with code 3`.
- **The same string is read by** the Deploys row, the deploy page, `deploy_ended` details, GraphQL and MCP. The log's `==> Build failed:` block splits it into one `==> ` line per line.
- **`buildkitFailureSummary`** (`lego/operator/internal/build/build.go:815-839`) keeps the `------` block's body lines verbatim, with the elapsed-seconds prefix BuildKit adds to each.

## Steps

1. Strip a leading `^\d+\.\d+ ` from each quoted body line, but only for the native user step (`buildkitNativeRunStep`).
2. **Decide the lead phrase.** For a native runtime, replace "in the docker build step" with one naming the build command (for example "while running the build command"), or keep it and record why. Docker-runtime reasons keep today's wording.
3. Update `TestBuildkitFailureSummaryNamesTheCauseOnce` and the reason tests that pin the old text.

## Acceptance criteria

- [x] A test: the round-84 transcript yields a reason with `QA84 failing on purpose` unprefixed and the `error: build command … exited with code 3` line.
- [x] A Docker-runtime `RUN` failure keeps its current reason.

## Result (2026-11-11)

- `buildkitFailureSummary` strips the `^\d+\.\d+ ?` stamp from the quoted body only when the `------` block's header is the build command's step (`nativeCommandStep`, the header `nativeCommandFailure` writes). A Dockerfile's own `RUN` keeps BuildKit's text (`TestBuildkitFailureSummaryNamesTheCauseOnce`'s new Docker case).
- **Lead phrase decided:** a native build's buildkit phase is now `build command` when `nativeCommandFailure` named the command's verdict, else `build environment` (`nativeBuildCommandStep`/`nativeBuildEnvironmentStep`). The reason reads `build failed in the build command step:\nQA84 failing on purpose\nerror: build command '…' exited with code 3`. "docker build" was wrong for a service with no Dockerfile. Docker-runtime reasons keep "docker build".
- `nativeCommandFailure` now returns whether it rewrote the verdict, so the step name never depends on text surviving `failureTail`'s 800-byte cut.
