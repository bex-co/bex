## Result (2026-11-11)

**Producers:**

- **Native runtimes** (Node, Python, Ruby, Go, Rust, Elixir) and **static sites' native builds** all run `BuildJob` with `Builder == native`, so all of them get `nativeLogDisplay`. Static sites put `nativeStaticInstallStep` inside the same RUN, so the dependency install prints under the command, as Render's does. A static site with no build command skips the `Running build command` line.
- **Service types:** web, private, worker, cron, static and build-source carriers share that path. `BuildOnly` and `StaticSite` change only the Dockerfile's tail.
- **Docker runtime:** `bex_display` stays `cat`, so the log is byte-identical (`TestDockerfileBuildLogIsBuildKitsOutput`).
- **Buildpacks (kpack):** unchanged. A separate pod and log format, and its reason is `buildpack build` (`kpack.go:176`).
- **Pre-deploy:** unchanged. A separate Job.
- **Every other `bex_run` phase** (clone, cache restore/save, the native preparer): the stream now passes through `cat`. The output and the classification are the same, and they write no termination message (`bex_message` empty), so their reasons still come from the log fallback.

**Readers:**

- **Stored logs (Loki `type=build`)** and the **live tail (`/v1/logs/subscribe`, `PodLogStream`)** read the same container log, so they read the same filtered lines.
- **REST, GraphQL, MCP and the deploy page** all read those two.
- **`failureReason`** (deploy row, Events, GraphQL, MCP, the failure email): from the termination message, now the raw transcript tail. `TestNativeBuildLogNamesAFailedCommand` and `TestNativeBuildLogNamesAToolchainFailure` run the real phase and feed the message it left to `EnsureBuild`.
