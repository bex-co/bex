## Objective

`dbStatus` should return the restart value (t004 confirms `config_restart`) for a once-Ready database in `Provisioning`, and `creating` only before first readiness.

## Context

- `lego/backend/internal/postgres/service.go:381-392` (`dbStatus`), with its one caller at `:416` (`pgView`).
- The operator sets `DBPhaseProvisioning` with reason `Provisioning` for every not-ready state (`lego/operator/internal/controller/database_controller.go:1305`), and `DBPhaseReady` at `:1063`/`:1290`.
- Find an existing persisted "has been Ready" signal in `DatabaseStatus` (for example, a host or credential field populated only after first Ready). If none is trustworthy, say so in this task and add the smallest status field in the operator, with a CRD regen via `make test`.

## Files

- `lego/backend/internal/postgres/service.go` and its tests; possibly `lego/types/v1alpha1/database_types.go` + operator

## Acceptance criteria

- [ ] A table test covers never-Ready → `creating`, once-Ready Provisioning → restart value, Upgrading → `upgrading` (unchanged here), Ready, Failed, suspended, and deleting.

## Out of scope

- Renaming `upgrading` (parity drift, recorded by t004).

## Result (2026-09-26)

No existing `DatabaseStatus` field is trustworthy as "has served": `Host`, `CurrentVersion`, and `CurrentPrimary` are all written during first provisioning. Added `Status.Provisioned bool` (`lego/types/v1alpha1/database_types.go`), set on the Ready path and in `settleSuspended` and never cleared, and regenerated the CRD via `make manifests` (`make test` green). `dbStatus` uses the same core helpers, and `upgrading` is unchanged. Covered by `postgres/status_test.go` (8 rows) plus operator assertions in `database_upgrade_test.go` and the convergence envtest. Existing databases gain the flag on their next Ready reconcile after the operator deploy.
