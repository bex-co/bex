## Objective

Keep auxiliary execution pods out of both stable serving Services without rolling or replacing existing Deployments. Preserve the pre-deploy job's logging, admission, ownership and network-policy labels.

## Context

See [finding.md](finding.md). `privateServiceProjection` currently returns the shared app-name selector, which matches the job. Existing Deployment pods already carry `bex.co/app-id`; pre-deploy pods do not. Reuse `appIDOrName` to add that existing runtime identity to the Service selector, retaining the existing image-network revision constraint where applicable. Confirm the proposal against t002's family matrix before landing it.

## Steps

1. Narrow the shared ClusterIP projection so both primary and slug Services select the existing runtime identity and app name.
2. Preserve port projection, image-network revision selection and legacy/hand-applied App fallback.
3. Leave immutable Deployment selectors and the shared execution-label helper unchanged. A Service-only selector update should not roll every application on an operator upgrade.
