## Objective

Verify the shared selector correction globally across its actual Service callers, while leaving unrelated label consumers and resource families alone. This matrix is implementation work; the live hunt exercised an image-backed web service only.

## Steps

1. Re-enumerate `privateServiceProjection`'s one production caller and `applyClusterIPService`'s three production call sites, listed in finding.md. Verify primary, slug and image-network promotion paths converge on the same rule.
2. Check web/private, native/buildpack/Docker/prebuilt sources, configured legacy ports and image-discovery multiport/revision paths; preserve ready old/new runtime pods during ordinary rolling updates.
3. Check missing public-ID label fallback, changed/foreign app IDs, alias ownership conflicts, suspend/resume and same-image restart/rollback. Audit retained/restored templates and older runtime pods for the required identity label before tightening selectors; a missing label must not silently disconnect the healthy release. Confirm selectorless platform ExternalName aliases remain untouched.
4. Place static/worker/cron/Postgres/Key Value explicitly. Cron pods also carry `bex.co/app-id`: it is not a universal serving-role marker. Verify the existing non-addressable/type-change cleanup removes serving Services, and do not claim the new selector excludes all cron pods by itself.
5. Review existing tests that insist on a single-key legacy selector (`TestImageNetworkLeavesLegacyServicesUnchanged`). Replace the implementation assertion with traffic-membership and preserved-port behavior; do not weaken its real compatibility contract.
