## Objective

Count an incoming HTTP request as activity before its response finishes, across HTTP and HTTPS, so a first streaming response cannot be terminated before its configured idle window since request arrival.

## Context

[Two independent a664 failures, dependency research and exact evidence](stream-request-start-a664.md). A native 300-second fixture auto-hibernates 154.1 seconds after request arrival; an independent API-TTL-120 fixture does so after 45.5 seconds. The existing completed-response counter has not advanced yet. The TLS-only start primitive does not cover the configured plain HTTP listener.

## Steps

1. Add a bounded per-App HTTP-start counter to the existing edge plugin, incremented before forwarding without wrapping ordinary streaming responses; reuse its App identity, cap and metrics listener. Preserve both WebSocket directions and current request/billing metrics.
2. Allow the signal through Prometheus's 9101 metric-name keep filter and include it in the existing reset-safe first-positive/current-instant activity expression. Preserve missing-signal compatibility, fail-awake reads, optimistic stamp conflicts and eventual idle expiry.
3. Arrange and verify plugin-code rollout with the static-name ConfigMap; demonstrate an actual start sample while a blocking response remains open. Run renewed Simplify/test coverage in t005/t006 before closeout.

## Acceptance criteria

- [ ] A blocked HTTP/HTTPS downstream handler produces a per-App start sample before returning, once per inbound request, without another App's activity leaking into it.
- [ ] The real query advances the stamp from start-only traffic while completed-response traffic is absent/flat; it cannot keep a service awake forever from one positive flat counter.
- [ ] Both captured quiet-window bounds pass after deployment; missing metrics, counter resets, HTTP/HTTPS, previous HTTP/WebSocket controls and other resource-type eligibility retain correct behavior.
- [ ] Changed plugin code is loaded and the new counter survives the scrape keep filter before live acceptance is claimed.

## Out of scope

- Indefinite keep-awake from outgoing-only SSE bytes, new sleep eligibility, new API fields, global open-connection gating, billing-counter redesign, paid changes or foreign-resource mutations.
