## Objective

Make the Python lines, Render's dated defaults and the `PYTHON_VERSION` → `.python-version` → default resolution callable from outside the operator, so an agent session and a native build resolve from one table. The backend may never import the operator (depguard `module-dag`, `lego/backend/.golangci.yml`), and `lego/types` already holds shared Render logic (`types/renderenv`, `types/tiers`).

## Context

- Callers today: `ResolveNativeVersionAt` only from `lego/operator/internal/build/nativeresolve.go` (~:71), `ResolveNativeVersion` only from `nativecommon.go` (~:182); entrypoint `lego/operator/cmd/native-resolve/main.go`.
- To move (Python first): the Python lines in `native.go` (~:205-215: 3.7 bullseye, 3.8-3.15 bookworm, digest-pinned) with `nativeToolchain`/`nativeLine`/`find`; `pythonCreationCutoff`, `pythonDefaultLine`, the dated defaults (`renderDefaults20261103` = 3.14.10) and `exactDefault`/`datedDefault`/`exactDefaults`/`defaultExact` in `nativeversion.go` (~:140-295); the signal core (`resolver`, `first`, `firstFound`, `fromEnv`, `fromFile`, `firstMeaningfulLine`, `minorLine`, `boundedRequest`, `UnsupportedVersionError`) and the exact-patch helpers (`exactRequest`, `exactImage`, `lineImageVariant`).
- Stays in the operator: `NativeChoice` (embedding an exported `toolchains.Choice`), narration, Bun/Poetry/uv, `DockerHubResolver`, the Dockerfile rewrite.
- `lego/types/go.mod` gains `github.com/Masterminds/semver`; `scripts/lib/toolchain-freshness.py` `CANONICAL_PIN_SITES` must name the new file.
- `nativeversion.go` ~:131-132 says "a requested patch is not reproduced", contradicting ADR060's w8/175 amendment (exact patches are built); fix it in the move. Other sessions edit `lego/operator/internal/build/` often: rebase onto `origin/main` right before you ship.

## Steps

1. Create `lego/types/toolchains` with the Python table and resolver; make the operator derive its Python entry from it.
2. Keep every existing operator test green unchanged in meaning; move the pure-resolution tests next to the new code.
3. Update the freshness pin sites and the stale comment.

## Outcome

Done 2026-11-20 (w4/m544). `lego/types/toolchains` holds the Python table (`toolchains.Python`), the creation cutoff and Render's dated defaults (`PythonDefaults`), `ResolvePython`, and the shared primitives the operator now calls for every runtime (`UnsupportedVersionError`, `Unsupported`, `BoundedRequest`, `FirstMeaningfulLine`, `RequestLine`, `ExactVersion`, `DatedDefault`/`DatedDefaultAt`, `ImageVariant`, `ReadVersionFile`, `RenderDefaults20261103`). The operator derives its Python entry from the table (`nativeToolchainOf`) and resolves Python through `toolchains.ResolvePython`; no copy of the table remains. Deviations: `NativeChoice` is built from the choice's fields rather than embedding `toolchains.Choice` (66 literals would change for nothing), and the signal core for Node, Ruby, Elixir and Bun stays in the operator on top of the shared primitives. The stale comment was already fixed. `toolchain-freshness.json` and `CANONICAL_PIN_SITES` name `lego/types/toolchains/python.go`; the native-common qualification lists gained `types/toolchains`. Checks: `go test ./types/toolchains/` (the five acceptance cases and more), operator `go test ./internal/build/`, `make lint`, backend `go build ./...`.
