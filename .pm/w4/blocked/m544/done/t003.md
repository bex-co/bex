## Objective

Render's default depends on when the service was created; a session's default must depend on when the session was created. Pass `BEX_AGENT_SESSION_CREATED_AT` (RFC 3339) to the driver for sessions and for snapshot builds, as the native build passes `BEX_SERVICE_CREATED_AT` (`nativeresolve.go` ~:45-47). A missing value falls back to the legacy line, which is wrong for every new session.

## Context

- Session dispatch: `lego/backend/internal/agentsessions/service.go` (~:889-983).
- Snapshot builds: `lego/backend/internal/agentsessions/repo_environment_builder.go` (~:402-416).
- Agent environments carry no plain env vars: `PYTHON_VERSION` reaches the sandbox as a workspace- or repo-scoped secret (`secrets.go` ~:669-671), which the resolver reads from the environment like any other variable.

## Steps

1. Add the variable to both env builders from the session's (or build's) creation time.
2. Test both.

## Files

- `lego/backend/internal/agentsessions/service.go`, `repo_environment_builder.go`, tests

## Acceptance criteria

- [x] Backend tests assert the RFC 3339 value in the session and build environments.
- [x] The variable is not tenant-overridable (a secret of the same name does not replace it).

## Out of scope

- Any change to how secrets are injected.

## Outcome

Done 2026-11-20. `driverEnv` sets `BEX_AGENT_SESSION_CREATED_AT` from the session's `CreatedAt` (UTC RFC 3339, omitted when unknown) for every dispatch, steer and resumed wait; `builderEnv` sets it from the build's. The `BEX_` prefix is reserved for secret names, so none can replace it. Tests: `session_created_env_test.go` (session, repo-less later turn, unknown time, build, reserved name) and the real-DB build test's env assertion.
