## Objective

Let gVisor's `devpts` canonical input queue process typed-ahead input immediately while one or more complete lines wait unread, so echo, signals (`Ctrl-C`/`Ctrl-\`/`Ctrl-Z`), IXON flow control (`Ctrl-S`/`Ctrl-Q`), and line editing on the new line happen at once as in Linux's `n_tty`.

## Context

- `bex-co/gvisor` branch `bex/line-discipline` (`b66db2b09`, stacked on `w4/m545`) and release branch `bex/release-20260622.0-echo-signal-chars` (`44a08e148`).
- `pkg/sentry/fsimpl/devpts/line_discipline.go:650`: `if l.termios.LEnabled(linux.ICANON) && q.readable { return 0, false }` stops processing input as soon as one canonical line is complete.
- `pkg/sentry/fsimpl/devpts/queue.go:45-69, 104-169, 299-306`: `readBuf []byte` + `readable bool` represent at most one line; `read()` drains all of `readBuf` and clears `readable` only when `readBuf` is empty; `readableSize()` reports `len(q.readBuf)`.
- Repro (`w4/m574` harness case `c6a`): write `ls\n`, then `ab`, then `\x03` with no reader. Native Linux echoes `ls\r\n`, `ab`, `^C`, delivers `SIGINT`, and flushes both lines so a subsequent read gets nothing. `release-20260622.0-bex.2` echoes only `ls\r\n` and leaves `ls\n` unread.

## Steps

1. Redesign canonical buffering in `queue.go` and `line_discipline.go` so `inQueue.readBuf` can hold multiple lines up to `canonMaxBytes`, recording each completed line's end offset (including zero-byte EOF markers) with full `stateify` save/restore support.
2. Remove the early `if l.termios.LEnabled(linux.ICANON) && q.readable` return in `inputQueueTransformer.transform()` so later writes continue through echo, signals, IXON, and editing.
3. Make canonical `queue.read()` return at most up to the first recorded line end (consuming an EOF marker and returning 0 bytes for an empty EOF line), advancing subsequent line-end offsets.
4. Make `FIONREAD` (`readableSize`) match Linux's `inq_canon()` when multiple lines, a partial trailing line, or an EOF marker are queued.
5. Constrain `VERASE`, `VWERASE`, `VKILL`, and `VREPRINT` to the line currently being typed (bytes after the last committed line end) so completed unread lines are never erased or reprinted.
6. Ensure signal flushes, `TCFLSH`, and switching `ICANON` off update or clear the line-end metadata cleanly (turning `ICANON` off makes all buffered bytes immediately readable).
7. Add `test/syscalls/linux/pty.cc` tests (and `devpts` unit tests) for typeahead echo, `Ctrl-C` and `Ctrl-S` after an unread line, two lines read one per `read()`, an EOF between two lines, editing bounded to the current line, and `FIONREAD`. Verify on native Linux, on patched `runsc`, and confirm failure with this fix reverted.
