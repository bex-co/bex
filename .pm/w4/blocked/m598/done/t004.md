## Objective

Implement the `TCXONC` ioctl (`tcflow()`) in gVisor's `devpts` so programs can suspend and resume output (`TCOOFF`, `TCOON`) and transmit `VSTOP`/`VSTART` (`TCIOFF`, `TCION`) on a PTY just as on Linux.

## Context

- `bex-co/gvisor`: neither `pkg/sentry/fsimpl/devpts/master.go` (`:147-315`) nor `pkg/sentry/fsimpl/devpts/replica.go` (`:137-209`) handles `linux.TCXONC`; calls currently return `ENOTTY`.
- `w4/m574` t005 already added IXON `outputStopped`, write blocking/waking, and `TIOCPKT_STOP`/`TIOCPKT_START` packet-mode signaling in `line_discipline.go`.
- Recorded in `docs/ADR104-sandbox-render-parity.md` § Terminals in a sandbox and `docs/ADR018-render-parity.md` as a known difference.
- Check Linux's exact behavior for `TCXONC` on both replica and master fds: `TCOOFF`, `TCOON` (whether they depend on `IXON`, packet mode `TIOCPKT_STOP`/`TIOCPKT_START` updates, waking blocked writers on `TCOON`), `TCIOFF`/`TCION` (sending `VSTOP`/`VSTART` into the output queue when not disabled), and invalid action values (`EINVAL`).

## Steps

1. Verify Linux's `TCXONC` semantics on a PTY (replica and master, `TCOOFF`, `TCOON`, `TCIOFF`, `TCION`, `IXON` on/off, `TIOCPKT`, invalid action).
2. Wire `linux.TCXONC` in `pkg/sentry/fsimpl/devpts/replica.go`, `master.go`, and `line_discipline.go` (plus `pkg/abi/linux/tty.go` if any `TC*` constant is missing), reusing t005's stop/start machinery.
3. Add `test/syscalls/linux/pty.cc` tests covering `TCOOFF`, `TCOON`, `TCIOFF`, `TCION`, `TIOCPKT`, and `EINVAL`; verify pass on native Linux and patched `runsc`, and failure with only this fix reverted.

## Files

## Acceptance criteria

- [x] `tcflow(fd, TCOOFF)` holds replica output and `tcflow(fd, TCOON)` resumes it, matching Linux.

## Out of scope
