## Objective

Implement screen erasure of tab characters (`\t`) under `VERASE`, `VWERASE`, and `VKILL` in gVisor's `devpts` line discipline so the cursor moves back to the column where the tab began, matching Linux's `n_tty` (`ECHO_OP_ERASE_TAB`).

## Context

- `bex-co/gvisor`: `pkg/sentry/fsimpl/devpts/line_discipline.go:795-796` currently has `else if toErase == '\t' { // Not implemented }`, echoing nothing when erasing a tab.
- Recorded in `docs/ADR104-sandbox-render-parity.md` § Terminals in a sandbox and `docs/ADR018-render-parity.md` as one of the three differences left by `w4/m574`'s 71-case harness.
- Linux's `n_tty` tracks output column and `canon_column` so erasing a tab emits `\b` back to the start column of the tab (without overwriting with spaces, since a tab occupied spaces up to the next 8-column tab stop; verify exact behavior against native Linux for tabs at column 0, columns 1–7, multiple tabs, control characters before a tab, and `VKILL`).

## Steps

1. Measure native Linux's exact echo bytes for erasing a tab under `VERASE`, `VWERASE`, and `VKILL` at multiple starting columns (including after normal chars, control chars under `ECHOCTL`/`-ECHOCTL`, output written by the replica before input, and multiple consecutive tabs).
2. Implement column tracking (with `stateify` fields) and tab-erase echo in `pkg/sentry/fsimpl/devpts/line_discipline.go`.
3. Add `test/syscalls/linux/pty.cc` and `devpts` unit tests covering each case; verify pass on native Linux and patched `runsc`, and failure with only this fix reverted.
