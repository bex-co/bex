# 695 — A reset pooled connection to OpenFGA fails the request with `503 authorization service unavailable`; the Check is never retried

Why: a read-only OpenFGA Check (`POST /stores/{id}/check`) that lands on an idle keep-alive connection the peer has already dropped fails at once. The caller gets a 503 for an authorization service that is up. Go's transport does not replay a reused-connection failure for a `POST` with no `Idempotency-Key`, and nothing above it retries.

- **Source / severity / estimate:** w4/m352 live DoD replay, `/loopx w4`, 2026-11-16 22:32–22:49 UTC, pin `284b83e1f540`; **minor**, but it fails closed on any authorized route; ~45m.
- **Probe:** in-page `GET https://api.bex.co/v1/services/srv-dbto96gbme1s73ed2veg/deploys?limit=1` (QA session, workspace `bex-canary`) answered `503` at about 22:37:13. The calls before and after it, every 2–3 s, answered 200.
- **Server side (read-only logs):** `kubectl -n bex-system logs bex-api-6cc7cfb6b8-dkw4v` logs `core: authorization unavailable: Post "http://openfga.auth.svc:8080/stores/01KWWX67MJCH7X3GC0JT93JD5R/check": read tcp 10.244.43.57:…->10.96.206.201:8080: read: connection reset by peer` at 22:20:40, 22:36:26 and 22:37:42 (3 in 80 min). The other replica logged none, and both `openfga` pods ran with 0 restarts.
- **Mechanism:**
  - `NewOpenFGAChecker` (`lego/backend/internal/authz/authz.go:64-68`) uses `core.OryTransport` (`lego/backend/internal/core/http.go:603-607`), a `DefaultTransport` clone: `IdleConnTimeout` 90 s, `MaxIdleConnsPerHost` 32.
  - `checkUpstream` (`authz.go:144`) sends one `core.DoJSON` `POST`. Any error reaches `core/base.go:1017-1019` as `ErrAuthzUnavailable`, which becomes a 503 (the same arms are at `:1052` and `:1185`).
  - Cause of the resets unverified: an OpenFGA server or Cilium/kube-proxy idle timeout shorter than the client's 90 s is the prime suspect.
- **Possible reach (unverified):** the web shell re-runs `ResolveSSHSession`, which checks authorization, every minute, and any check error cancels the stream (`core/revalidate.go:52-55`). In the same window, an open Web Shell on that fixture was replaced by a fresh `/ #` prompt between 22:36:39 and 22:37:21 with no user action. That is not traced to this; t006 of w4/m352 records it.
- **Fix direction:** replay a Check once on a connection-level error from a reused connection (Check is a read: set `req.GetBody` and an `Idempotency-Key`, or retry in `checkUpstream` on `ECONNRESET`/`io.EOF`). Also set the FGA client's `IdleConnTimeout` below the server's idle timeout. Never turn the error into an allow: still fail closed after the retry.
- **Done when:** a unit test with a server that resets the first reused connection sees one successful Check and no 503. Over a 2 h window, production `bex-api` logs no `authorization unavailable … connection reset by peer`.

## Fix shipped (2026-11-16, `/loopx w4`)

- `checkUpstream` now sends through `core.DoJSONRead` (`lego/backend/internal/core/http.go`), which marks the Check replayable (`Idempotency-Key` present with a nil value, so nothing goes on the wire). net/http then resends a Check that failed on a reused connection, on a fresh one. Writes stay on `DoJSON`, which is not replayed. An error after the replay still fails closed.
- `core.OryTransport`'s `IdleConnTimeout` is now 30 s, down from 90 s.
- `TestCheckSurvivesAResetReusedConnection` (`lego/backend/internal/authz/authz_test.go`) resets the second Check on its kept-alive connection with a RST, then sees two denies and three upstream calls. With the header line reverted, it fails with the production error: `read: connection reset by peer`.
- **Remaining (release gate):** once a production deploy carries this commit, a worker reads 2 h of every `bex-api` replica's logs and confirms there is no `authorization unavailable … connection reset by peer`. The check is `git merge-base --is-ancestor <fix sha> <deployed sha>`.
