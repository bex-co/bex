# 595 — Does Render's API refuse a GitHub folder or file page (`…/tree/main/examples/hello-go`) as a service's `repo`? bex accepts it and fails at checkout

Why: w4/576 made the dashboard split a pasted GitHub folder page into the repository, branch and root directory, and refuse a file page. REST, GraphQL, MCP and Blueprints still accept such a URL as `repo`. The service is then created, and its build fails two minutes later at checkout with "repository … not found". A 400 that names the repository URL would be clearer, but bex adds no refusal Render may not have (ADR008, Render parity first).

- **Source / severity / estimate:** w4/576 `/simplify` review, `/loopx w4` 2026-11-12. **Minor**. ~20m after the answer.
- **Gate:** Render's answer is unknown. Its docs say nothing about the `repo` field's validation. Checking it means creating a service on the Render reference account, which is a write that the read-only rule forbids. Either the user runs `POST /v1/services` with a `/tree/` repo against Render, or allows a one-time write probe there.
- **If Render refuses it:** reapply the refusal drafted in w4/576 (`store.RepoRefusal`: a 400 naming `https://github.com/<owner>/<repo>`, called from `apps/service.go` create validation and the source update, and from `store/api.go` create, with the same case-insensitive host and a required ref). Mirror Render's status code and wording.
- **If Render accepts it:** leave the API as it is, and record in ADR018 that both platforms fail at build.
- **Dedupe:** w4/576 (done: the dashboard split).
