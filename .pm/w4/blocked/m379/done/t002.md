## Objective

The three Postgres change events that Render describes as transitions carry both sides.

## Context

- Audit recorders (`lego/backend/internal/core/audit.go:1058-1096`) store only the resulting value. The read-replica row stores none (`lego/backend/internal/eventvocab/datastore.go:84-88`).
- Render requires:
  - `postgres_disk_size_changed`: `fromDiskSize`, `toDiskSize` (integers, GB);
  - `postgres_ha_status_changed`: `fromStatus`, `toStatus` (strings);
  - `postgres_read_replicas_changed`: `fromReplicas`, `toReplicas` (integers).

## Steps

1. At each PATCH, pass the pre-change value into the recorder beside the new one, as the disk recorders (`DiskSizeFromGB`) and `RecordDatabasePlanChanged` do. Add the audit columns or JSON keys the store needs.
2. Pick the HA status vocabulary. Render's values are unverified, so use `disabled`/`enabled` unless a Render artifact shows otherwise, and record the choice in ADR018.
3. Render the pairs in `toRenderEvent`.
4. Correct the comment at `eventvocab/datastore.go:84-88`: Render's replica event is not thin. Disk autoscaling has no Render variant and stays as it is.
5. Rows recorded before this change have no from-value. Render them with the to-side only, and do not invent a from-value.

## Acceptance criteria

- [x] Tests cover each event's pair, plus an old row with no from-value.
- [x] A no-op PATCH still records nothing.

## Result (2026-11-14)

- **Recorders** (`lego/backend/internal/core/audit.go`):
  - `RecordDatabaseDiskSizeChanged(ctx, d, fromGB, toGB)` writes the existing `disk_size_from_gb` column. The from-side is `EffectiveStorageGB(before.Plan, before.StorageGB, status.allocated)`, the high-water size before the PATCH, mirroring how the to-side is computed.
  - New `RecordDatabaseReadReplicasChanged(ctx, d, from, to)` writes the counts into new `audit_events.read_replicas_from/_to` columns (migration **0263** `postgres_read_replicas_event`). They are read through `AuditChanges`, so the by-id query selects them with no new join.
- **HA.** No new column. The recorder fires only when the toggle changed (true since w3/m82), so the value before is always the opposite of the recorded one. `fromStatus`/`toStatus` are rendered as `enabled`/`disabled` from it (`haStatuses`, `events/rest.go`), and ADR018 records the vocabulary. This is a deliberate deviation from step 1 ("pass the pre-change value"): for a change-only boolean the pre-change value adds nothing. It also means HA rows recorded before this change render both sides, without inventing anything.
- **Old rows.** A disk-size row from before carries `toDiskSize` only, and a replica row from before carries neither. Nothing is invented.
- **Comment.** `eventvocab/datastore.go` now says the replica row carries both counts. Disk autoscaling stays without details, as Render has no variant for it.
- **Tests:**
  - `TestPostgresConfigurationEffectsProjectRenderNames` asserts `diskSizeFromGB 20` and replicas `0 -> 1` on a real `UpdatePostgres`.
  - `TestUnchangedReplicaSetAndAutoscalingRecordNoSettingEffect` passes unchanged: a no-op PATCH records nothing.
  - `TestDatastoreEventDetailsOnRetrieve` covers each pair and the old rows.
  - `TestPGDatastoreEventFromValuesHydrate` (new) runs against real Postgres. The resize, the replica change and both upgrade edges hydrate by evt- id with both sides.
