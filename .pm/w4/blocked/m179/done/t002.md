## Objective

Apply the fix globally to the four DeleteUser adapter calls and the shared CNPG role projection while protecting the live owner, other active users, and previously fixed issuance behavior.

## Context

- [Live finding, durable probes and consumer trace](finding.md).
- This QA run files work only; it did not implement or deploy a fix.

## Steps

1. Enumerate REST DELETE users/{user}, REST DELETE credentials/{user}, GraphQL deleteDatabaseUser and MCP delete_postgres_user; follow their accepted-intent/error mapping. managedRoles has one production consumer but also projects owner and live-user controls.
2. Verify reserved identifiers remain refused before issuance, owner/active-role precedence prevents accidental retirement, and non-disclosing authorization/not-found behavior stays unchanged.
3. Verify a retired same-name role can be recreated with the fresh returned password and that the previous password fails. Keep the ADR085 stranded-Secret and optimistic-locking regression family.
4. Record private/public, pooler/replica and slow/outage paths as observed or unverified. Cover role-owned objects as a data-preservation control; the live finding exercised grants only. NOLOGIN is a new-authentication boundary and does not assert termination of already-connected sessions.

## Acceptance criteria

- [ ] Four aliases share retirement intent with preserved status/body contracts and authorization.
- [ ] Owner and other active roles still connect, table data survives, and same-name recreation cannot resurrect a prior password.
- [ ] Scope and unverified endpoint/session controls are explicit; a deferred verification is not represented as a passing live observation.
