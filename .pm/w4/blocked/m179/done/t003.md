## Objective

Make the retirement semantics and asynchronous acceptance consistent across REST, GraphQL, MCP and the dashboard, with the remaining differences from Render documented.

## Context

- [Live finding, durable probes and consumer trace](finding.md).
- This QA run files work only; it did not implement or deploy a fix.

## Steps

1. Check the current primary Render credential documentation and compare both REST delete aliases, native GraphQL/MCP booleans and dashboard copy to the Core intent.
2. Update ADR009 and ADR018 plus adapter descriptions: deleted Bex additional credentials retire the login and preserve objects; a NOLOGIN role may remain. Keep the additional-user/default-owner model distinct from Render default-user rotation.
3. Document accepted intent versus completed authentication revocation, preserve existing status/body and non-disclosure behavior, and list any further parity gap as separate follow-up work.
