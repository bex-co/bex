## Objective

Make a deleted additional login converge to NOLOGIN with a NULL password even when ACL or ownership dependencies prevent DROP ROLE. Keep retirement as declared CNPG state and make acceptance copy honest.

## Context

- [Live finding, durable probes and consumer trace](finding.md).
- This QA run files work only; it did not implement or deploy a fix.

## Steps

1. Read finding.md and the pinned CNPG1.30 consumer. Change the existing tombstone projection to ensure:present, login:false, disablePassword:true, no passwordSecret; adding loginfalse to ensureabsent still selects DELETE and is insufficient.
2. Retain tombstones as retirement intent; update DatabaseSpec comments and keep active/owner precedence, reserved-name filters, generation-specific Secrets and optimistic locking. Do not add a SQL/control-plane DB dependency to the operator.
3. Keep native success values as accepted asynchronous intent and change the dashboard deletion toast to Revocation requested for {name}, through translations. A CR patch cannot claim an observed SQL drop. Do not relabel runtime failure as completion.
4. Preserve same-name recreation: remove retirement intent, restore LOGIN with the newly referenced issuance, and invalidate the former password without adopting a surviving Secret.
