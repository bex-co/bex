# A mistyped plan on a cron job, worker or private service is told `free` is a valid choice

Why: a caller who sends `FREE` or ` free ` for a paid-only type is told "plan must be one of free|starter|…". If they follow that hint, the next call is refused with "a cron_job requires a paid plan", so the first error points at the one plan that cannot work.

- **Severity:** minor (error wording; enforcement is correct).
- **Source:** live functional `/qa-find-bugs w4`, pass 65314e, 2026-10-19 UTC, `muse.env`, workspace `bex-canary`, production pinned to `f3871ba9fd44`. Every probe is a dry run, sent from inside the signed-in dashboard page (`fetch(…, {credentials:'include'})`), and nothing was written.
- **Probes (responses verbatim, truncated only where noted):**
  - GraphQL `createService(name:"qa-20261019-65314e-dry", ownerId:"tea-daif693dqjvc73e7as3g", type:"cron_job", image:"python:3.13-alpine", schedule:"*/5 * * * *", startCommand:"echo hi", plan:<P>, dryRun:true)`:
    - `P="free"` → `bad request: a cron_job requires a paid plan; plan must be one of starter|standard|pro|pro_plus|pro_max|pro_ultra`
    - `P="FREE"` and `P=" free "` → `bad request: plan must be one of free|starter|standard|pro|pro_plus|pro_max|pro_ultra`
  - REST `POST /v1/services?dryRun=true` with the same `type`/`serviceDetails.plan` gives the same two messages with `400 {"id":"bad_request",…}`.
  - The plan-change path: on legacy Free cron `srv-dap3r714dm7c7390q91g`, `updateServicePlan(plan:"free", dryRun:true)` → the per-type "requires a paid plan" message, while `plan:"FREE"` → `plan must be one of free|starter|…`. The plan read `free` before and after.
  - Workers and private services answer `free` the same per-type way. Their mistyped-plan branch is the same code, not probed.
- **Root cause:** two producers emit the whole compute ladder for an unrecognized plan without consulting the service type they already know.
  - Create: `lego/backend/internal/apps/service.go:3436` (`normalizeTierOrPlan`), reached from `normalizeTierForType` (`:3449`), which checks `paidOnlyServiceType` only after a plan resolves (`:3453-3454`).
  - Plan change: `internal/apps/settings_check.go:271-273` (`checkPlan`) returns the same ladder message before its paid-only check at `:279-281`.
  - The paid-only list already exists in `freePlanForTypeMessage` (`service.go:3505-3513`); `errFreePlanForType`'s comment says every path should list "only the plans that type may use".
- **Fix (target behavior):** for a paid-only type (`paidOnlyServiceType`), an unrecognized plan gets the same per-type message an explicit `free` gets: `a <type> requires a paid plan; plan must be one of starter|standard|pro|pro_plus|pro_max|pro_ultra`.
  - A web service keeps the full list including `free`.
  - Matching stays case-sensitive, like Render's enum.
  - The fix lives in `normalizeTierForType` and `checkPlan`, so REST, GraphQL and MCP move together.
- **Blast radius:**
  - `normalizeTierForType` has 3 callers: create `service.go:2867`, Blueprint deploy `deploy.go:1294`, Blueprint pricing `blueprint_pricing.go:43`.
  - `checkPlan` has 2 callers: `SetPlan` `service.go:3830` and the settings path `settings.go:228`, which also serves the dry run.
  - Blueprint validation goes through the pinned upstream enum (w8/048), not these paths.
- **Adjacent classes:**
  - A static site's plan handling is unchanged.
  - `postgres`/`keyvalue` have their own ladders (`postgres/service.go:1004`, `keyvalue/service.go:745`) and no paid-only rule, so they are out of scope.
- **Unverified:** the MCP `create_cron_job` error text (MCP not driven this run). Its schema description already says "a cron job cannot use free" (`apps/mcp.go:315`).
- **Dedupe:**
  - `w8/blocked/048.md` and `w1/done/111.md` cover the free refusal itself, not the unknown-plan wording.
  - `rg -i 'plan must be one of' .pm` found no open item on it.
- **Render:** Render's public API types cron, worker and private-service plans as `paidPlan`, so its own refusal lists no `free` (`internal/api/openapi/render-public-api-1.json`).
- **Acceptance:**
  - Table tests in `apps`: `cron_job`/`background_worker`/`private_service` × `FREE`/`" free "`/`nope` on create and on `SetPlan` give the per-type message with no `free` in it. `web_service` × `nope` still lists `free`.
  - Live: the two `FREE` probes above return the per-type message.
- **Estimate:** 20m.

**Implemented 2026-10-19 (loopx w4):** one helper, `errUnknownPlanForType`, now answers an unrecognized plan on create (`normalizeTierForType`) and on plan change (`checkPlan`), so REST, GraphQL and MCP move together.
- **Paid-only types:**
  - A mistyped free (`FREE`, ` free `) gets the type's free refusal: "a cron_job requires a paid plan; plan must be one of starter|…".
  - Any other unknown plan names itself: `plan "nope" is not a cron_job plan; plan must be one of starter|…`. Free is never offered.
- **Other types:** a web service keeps the full ladder, `free` included. Matching stays case-sensitive.
- **Tests:** `TestAMistypedPlanOnAPaidOnlyTypeIsNeverToldFree` covers cron_job, background_worker and private_service × `FREE`, ` free ` and `nope`, on create and on SetPlan, plus the web-service control. It fails with the fix reverted (10 subtests).
- **Blueprint:** unaffected. Its schema enum refuses unknown plans first, and pricing and deploy skip the error.
- **Remaining:** the live dry-run probes after the release pipeline deploys bex-api.
