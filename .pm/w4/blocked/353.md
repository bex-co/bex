# Custom domains accept hostnames DNS cannot hold (a 64+ character label, an all-numeric TLD)

Why: such a claim can never verify. bex still says "Domain claim created — set up DNS", tells the user to create a CNAME that no DNS provider will accept, and on every Re-check answers "DNS may still be propagating".

- **Severity:** minor. The input is a mistake, but the product accepts it and then promises progress it can never make.
- **Source:** live functional `/qa-find-bugs w4`, pass b68857, 2026-10-19 UTC, `muse.env`, workspace `bex-canary`, production pinned to `f3871ba9fd44`.
  - Fixture: owned Free web service `qa-20261019-b68857-dom` (`srv-dbaogm8u2drc73bm0pn0`), since deleted (404).
  - Every probed host sat under the reserved `example.com`/`.net`/`.org` and was deleted in the same call sequence, leaving 0 domains.
  - Screenshot: `.playwright-mcp/qa-domains-1.png` (local, gitignored).
- **Probes:** `POST /v1/services/<id>/custom-domains {"name": <host>}` from inside the signed-in page, then `DELETE …/<host>`:
  - **Accepted, `201` `verificationStatus: "pending"`:**
    - `"a"×64 + ".example.com"` (76 characters) and `"a"×200 + ".example.com"` (212 characters): a 64- and a 200-octet label.
    - `qa-b68857.example.123`: an all-numeric TLD.
    - GraphQL `addCustomDomain(id, name)` returned the same for `"g"×64 + ".example.com"` and `qa-b68857.example.123`.
  - **Controls, correctly accepted:** `"a"×63 + ".example.com"`, and a 253-character name of 63-octet labels.
  - **Correctly refused** with `400 CUSTOM_DOMAIN_INVALID`: a URL, `*.…` wildcard, raw IDN `bücher-…`, `203.0.113.7`, `localhost`, `..`, `_`, `:8080`, leading or trailing `-`, trailing `..`. Platform hosts (`*.onbex.co`, `onbex.co`, `api.bex.co`, `dashboard.bex.co`) are refused with `CUSTOM_DOMAIN_RESERVED`.
  - Case, a single trailing dot and surrounding spaces are normalized.
  - The apex `example.net` paired `www.example.net` (`redirectForName: example.net`), and deleting the apex removed both (ADR005 pairing holds).
- **Dashboard:** Add Custom Domain → Name `"a"×64 + ".example.com"` → Add Domain.
  - The dialog accepts it with no client-side check and opens "Domain claim created — set up DNS". It asks for TXT `_bex-challenge` in the `example.com` zone and **CNAME host `aaaa…` (64 characters) → `qa-20261019-b68857-dom.onbex.co`**.
  - Re-check toasts `info` "…example.com isn't verified yet — DNS may still be propagating." and the row stays `pending`.
  - Delete via "Open domain actions menu" → Delete works ("Removed …").
- **Root cause:** `lego/backend/internal/apps/domains.go:227` (`canonicalHostname`) validates with `validation.IsDNS1123Subdomain`. At the pinned `k8s.io/apimachinery v0.35.0` (`pkg/util/validation/validation.go:198-207`), that checks only the 253-character total and the pattern; it never applies `DNS1123LabelMaxLength = 63` (`:161`) to each label.
  - RFC 1035 §2.3.4 caps a label at 63 octets, so the CNAME the instructions ask for cannot exist.
  - The numeric case passes because `claimableHostname`'s `registrableDomain` (`:249`) treats an unlisted TLD as a public suffix under the PSL default rule. RFC 1123 §2.1 notes that the highest-level label of a host name is alphabetic, so an all-numeric TLD cannot be a host.
- **Fix (target behavior):** a host being **claimed** is refused with `400 CUSTOM_DOMAIN_INVALID` when:
  - any label exceeds 63 octets (`invalid hostname "…": each label must be at most 63 characters`), or
  - its last label is all digits (`invalid hostname "…": the top-level domain cannot be numeric`).
  - Put both in `claimableHostname` (`domains.go:244-255`), not `canonicalHostname`, so lookups (Verify `:718`, Delete `:1478`) can still read and remove any such host already stored. That is the same split ADR005 records for the public-suffix rule.
- **Blast radius:**
  - `claimableHostname` has 2 callers: AddDomain (`domains.go:1335`, shared by REST, GraphQL `addCustomDomain`, MCP and the dashboard dialog) and `canonicalHosts` (`service.go:3259`). The latter is reached from `service.go:3232` for create/update `spec.hosts`, including Blueprint `domains`.
  - `canonicalHostname`'s other callers must stay permissive: Verify, Delete, and `ParseReservedDomains` (`:879`, operator config).
  - Other `IsDNS1123Subdomain` users (`sessionegress/policy.go:149,237,261`, `agentsessions/service.go:1661`, `keyvalue/service.go:985,1003`, `apps/service.go:1195`, `store/reconciler.go:591`) validate other kinds of names and are out of scope. Note them for the implementer, but do not change them here.
- **Adjacent classes:** the error code stays `CUSTOM_DOMAIN_INVALID` (it is not reserved and not a conflict), and `params.hostname` echoes the raw input as today. Single-letter or other unlisted alphabetic TLDs (`example.c`) stay accepted: they are syntactically valid, and refusing them needs a TLD list, a separate decision.
- **Unverified:**
  - What cert-manager/ACME does with a 64-octet label after ownership verifies (the TXT sits in the parent zone, so ownership alone could pass). Not reached.
  - MCP `add_custom_domain` was not driven; it shares AddDomain.
  - Blueprint `domains:` was not probed; it shares `canonicalHosts`.
- **Dedupe:**
  - `w4/done/190.md` added the IP-literal and single-label refusals to the same function; label length and numeric TLDs were not in its scope.
  - `w8/done/055.md` covers Blueprint validate parity for reserved hosts.
  - `rg -i 'label.{0,30}63|numeric TLD|DNS1123Label' .pm` found no domain item.
  - No change to `domains.go`'s validators since `af963dd73` (w5/m121).
- **Render:** not probed this run; Render's API documents `name` as a domain string. The DNS limits are protocol facts, not a parity choice.
- **Acceptance:**
  - A table test in `apps` covers both cases. 64- and 200-octet labels and `x.example.123` are refused on AddDomain and on create `spec.hosts`. A 63-octet label and a 253-character name are accepted. Verify and Delete still find a stored 64-octet host.
  - Live, the three accepted probes above return `400 CUSTOM_DOMAIN_INVALID`, and the dialog shows that message inline.
- **Estimate:** 25m.

**Implemented 2026-10-19 (loopx w4):** `claimableHostname` (`apps/domains.go`) now refuses a host being claimed with `400 CUSTOM_DOMAIN_INVALID` in two cases:
- any label over 63 octets: `invalid hostname "…": each label must be at most 63 characters`;
- an all-numeric last label: `…: the top-level domain cannot be numeric`.

The rule covers AddDomain (REST, GraphQL, MCP and the dashboard dialog) and `canonicalHosts` (create/update `spec.hosts`, Blueprint `domains`).
- **Lookups stay permissive:** `canonicalHostname`, used by Verify, Delete and `ParseReservedDomains`, is unchanged, so an already-stored host can still be read and removed.
- **Accepted, as ADR005 records for public suffixes:** a Blueprint that still lists such a stored host fails validation until the host leaves it.
- **Tests:** `TestAddDomainRefusesNamesDNSCannotHold` covers 64- and 200-octet labels and `qa.example.123`, with controls of a 63-octet label and a 253-character name of 63-octet labels. The Blueprint validate rows pin the wording and the `services[0].domains[0]` location. Each rule's mutation is caught.
- **Docs:** ADR005.
- **Remaining:** the live probes after the release pipeline deploys bex-api.
