# 389 — Custom-domain objects omit Render's `server {id, name}`, and the hostname-as-`id` divergence is recorded only in ADR020, not ADR018

Why: Render clients read a custom domain's owning service from `server`, and AGENTS.md lets a parity divergence stand only when ADR018 records it with the user's sign-off.

**Severity:** minor. **Estimate:** 45m. **Source:** live `/qa-find-bugs w4` loop run r7k2, 2026-10-22 UTC (`muse.env`, `bex-canary`, pin `b3cd5bc74de8`). Fixture domain `qa-20261022-r7k2.example.com` on `srv-dbd9mq1ml1cs73dkbfcg` (Free web service from a Blueprint), added through the dashboard's Add Custom Domain dialog and deleted in the same visit (list → `[]`); the service was deleted too.

## Probe

`GET /v1/services/srv-dbd9mq1ml1cs73dkbfcg/custom-domains` →

```json
[{"customDomain":{"id":"qa-20261022-r7k2.example.com","name":"qa-20261022-r7k2.example.com","domainType":"subdomain","publicSuffix":"com","verificationStatus":"unverified","createdAt":"2026-10-22T23:37:42.953347Z","certificateStatus":"pending","serverStatus":"pending","redirectForName":"","dnsRecord":{"type":"CNAME","name":"qa-20261022-r7k2","value":"express-hello-world.onbex.co"}},"cursor":"qa-20261022-r7k2.example.com"}]
```

There is no `server` object. Render's customDomain schema (api-docs.render.com, list-custom-domains) carries an optional `server: {id, name}` beside the required `id`, `name`, `domainType`, `publicSuffix`, `verificationStatus`, `createdAt` and `redirectForName`.

## Root cause

- `lego/backend/internal/apps/domains.go:1682-1701` `toRenderCustomDomain` sets `ID: d.Name` and has no server field.
- `docs/ADR020-identifiers.md:87` records the hostname id as deliberate. `docs/ADR018-render-parity.md` has no row or sign-off for it (`grep -n cdm docs/ADR018-render-parity.md` → none).

## Fix

- Add `server {id, name}` to the REST custom-domain object. Check that GraphQL and MCP expose the same owner.
- For the id, either record the user's sign-off in ADR018, or return the minted `cdm-` id while `{customDomainIdOrName}` lookups by hostname keep working. Ask the user; ship `server` regardless.

**Unverified:** Render's actual id format; the docs schema says only "string".

## Loopx w4 verdict (2026-10-25)

`server {id, name}` shipped on REST, GraphQL and MCP (one `DomainView.ServiceID/ServiceName` from the owning App). **BLOCKED on the id half:** recording hostname-as-`id` in ADR018 needs the user's sign-off, or the switch to the minted `cdm-` id (lookups by hostname keep working) — a decision only the user can make.
