## Objective

The Web Shell panel tells the user what happened.

- When the ticket mint is refused, the panel shows the server's sentence ("shell access is unavailable while the service is suspended; resume it first", …), not "Couldn't start a shell session.".
- When the gateway ends a stream, the error frame says why: access revoked, service suspended, plan changed, instance gone, or session time limit. The panel shows it localized, under a status that is not "Connection error".

## Context

- Round 226 saw the mint refused with `conflict: the service has no running instance yet; …`, shown as "Connection error" + "Couldn't start a shell session.". It also saw the watchdog's end shown as "Connection error" + the raw `session closed`.
- Dashboard:
  - `dashboard/src/features/services/components/web-shell-terminal.tsx:92-104` maps every non-`SHELL_UNAVAILABLE` mint error to `services.shellErrorGeneric`;
  - `:166-174` prints an `error` frame's raw `message`;
  - `StatusBadge` (`:209-233`) labels every `error` "Connection error".
- Gateway:
  - `bridgeShell` sends `ws.fail("session closed")` for any canceled context (`lego/backend/internal/sshgateway/webshell/websocket.go:370-373`). It cannot tell the watchdog's end (`execCtx`) from the session timeout (`timedCtx`) or the browser's own close.
  - `handle` can (`:285-287`).
- `ResolveSSHSession`'s refusals are already one sentence per cause (w4/506). Authorization failures are decided before them.

## Steps

1. Gateway: carry the watchdog's error to the end frame. Send a stable `code` (`revoked`, `suspended`, `ineligible`, `instance_gone`, `timeout`) plus the sentence.
   - Never disclose more than the caller's own `GET /v1/services/{id}` would: a caller who lost access gets "your access to this service ended", not the reason they lost it.
2. Dashboard: show the mint refusal's message without the `conflict: ` prefix, as other dashboard errors do. Keep `SHELL_UNAVAILABLE`'s own copy.
3. Dashboard: add an "ended" status (for example "Session ended"), distinct from "Connection error", for a server-sent end. Map each `code` to en and zh copy, with the server's sentence as the fallback.
4. Keep the existing "exit" path (the shell exited) as it is.

## Out of scope

- Native SSH's end message: an SSH client has no such channel, beyond the exit status and stderr. Note the gap in ADR035 if it remains.

## Outcome (2026-11-14)

- Gateway: `core.WithRevalidation` now cancels with the failed check's error as `context.Cause`; the web shell classifies it into an error frame `{"type":"error","reason":…,"message":…}`. Reasons: `revoked` (any authorization failure, only "your access to this service ended"), `suspended`, `ineligible`, `instance_gone` (also when the executor sees the attached pod terminate), `timeout` (session cap), and `unverified` (resolver failing closed on an unreachable store — added so a store blip is not reported as a revocation).
- **Deviation:** the reason rides a `reason` field, not `code`: `code` is already the numeric exit status of an `exit` frame, and a field whose type depends on the frame would break every decoder. ADR035 records it.
- Dashboard: a refused mint shows the server's sentence (`mutationErrorMessage`; `refusalReason` now strips `conflict:` as it did `bad request:`), `SHELL_UNAVAILABLE` keeps its copy. A frame with a `reason` shows status "Session ended" / "会话已结束" with en + zh copy per reason, falling back to the gateway sentence for an unknown reason; a transport failure stays "Connection error". The exit path is unchanged.
- Native SSH end message: gap noted in ADR035 (an SSH client sees only the connection end).
- Tests: `webshell/end_reason_test.go` (suspended and Free over the real resolver, revoked ×3 without detail, unverified, timeout, terminated target), `web-shell-terminal.test.tsx` (409 sentence, generic fallback, each reason in en and zh, unknown reason, transport error), `graphql-error.test.ts`.
