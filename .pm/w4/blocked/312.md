# Chinese search lists retain an English Suggestions name

Why: Chinese screen-reader users should hear the search results list named in the same language as its input and results.

**Severity:** minor. **Estimate:** 25m. Functional `$qa-find-bugs`, read-only pass a606, 2026-10-15, user-selected w4. Research HEAD `e84ee60cc55cc44f4eb3b47ee62a3df38b4f406d`; no product fix. Goal: ADR008 usable hosting and the dashboard's en/zh contract (`dashboard/AGENTS.md:174–186`).

## Reproduction and controls

1. Sign in, switch Avatar → Language → 中文, then open topbar 搜索. Filter `qa-a606-no-such-fixture`.
2. At **16:49:22.538Z**, document language is `zh`. The actual accessibility tree has dialog/heading/input **搜索**, translated groups and empty status, but **listbox "Suggestions"**.

4. The Chinese Blueprint branch popup independently exposes the same list name at **16:51:38.866Z**, and a fresh desktop page repeats it at **16:52:18.619Z**.
5. Fresh English controls at **16:54:14–16Z** appropriately retain Suggestions. Escape from Search returns focus to its opener. Chinese clearing and selecting a real branch work; this is a language defect, not a disabled results list.

[Durable evidence](evidence/312-313-shared-search-labels.json) includes complete relevant accessibility trees, exact UI steps, caller/installed-library research and cleanup. No assistive-technology audio session was run.

## Root cause and bounded fix

`dashboard/src/common/components/ui/command.tsx:79–93` forwards props to `CommandPrimitive.List` without supplying a localized **label**. The checkout's **cmdk 1.1.1** List type (`dist/index.d.ts:143–150`) supports `label?: string`; its installed implementation defaults that prop to Suggestions and assigns it to `aria-label` **after** spreading other props. Merely supplying an `aria-label` attribute is therefore ineffective.

Localize the wrapper's default through `useTranslations` and common en/zh catalogs, e.g. Suggestions / 建议. Pass the result through the actual **label** prop and preserve an explicitly supplied label. Leave Command's separate root label intact: it correctly names the Search input today. No cmdk patch, API/schema change or per-resource route change is needed.

Exhaustive production TSX census: **2 CommandList render sites in 2 files**:

- `common/components/dashboard-layout/global-search-dialog.tsx:95`.
- `common/components/ui/combobox.tsx:245`.

Neither supplies a label. GlobalSearchDialog has **1 production render site**, `dashboard-layout/global-search.tsx:103`. The nested Combobox has 3 render sites and 4 concrete repository/branch contexts, enumerated in [313](313.md). Apply the default globally across these two list sites; keep caller overrides. Global Search is shared dashboard chrome, including hosting and datastore pages; Postgres/Key Value need no separate list fix. Service Settings aliases share their existing components.
