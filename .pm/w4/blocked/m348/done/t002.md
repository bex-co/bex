## Objective

While old and new dashboard pods both serve (`replicas: 1`, `maxSurge: 1`, `minReadySeconds: 5`, `dashboard/deploy/deployment.yaml:9-18`), a document from either build still loads its chunks. Failing that, the one module-load error a user can meet recovers on Try again (w4/269's document reload), because t001 keeps the miss out of every cache.

## Steps

1. Decide, and record the decision in the milestone README:
   - **(a)** ship the previous release's `assets/` beside the new one, for example a build stage that copies it out of the previous image, so either pod can serve either build's chunks;
   - **(b)** serve `/assets` from storage that keeps old files;
   - **(c)** rely on t001 plus w4/269's reload, accepting one error page in the overlap.
   - (a) or (b) gives no error at all, and is preferred unless it costs more than it saves.
2. Implement it, or for (c) prove it: on the mock cluster or a local two-version setup, load an old document and request a chunk only the new build has, and the reverse. The miss answers 404 `no-store`, and Try again shows the page.
3. If the choice keeps old assets, bound how many generations are kept.

## Acceptance criteria

- [ ] A local or mock-cluster rollout: a browser that keeps its cache loads a service page every 5 s through the overlap, and no load ends on "Something went wrong" (a/b), or each one that does recovers on Try again (c).
- [ ] Afterwards no script URL the page uses holds `text/html` in that browser's cache.

## Out of scope

- Changing the Deployment to more replicas or a different strategy, unless that is the chosen mechanism.

## Outcome (2026-11-14)

- **Decision: (c)**, recorded in the milestone README § Rollout overlap decision. (a) does not deliver "no error at all": an old pod can never hold the new build's chunks, so a new document whose chunk request reaches the old pod misses either way. It would also add a build-time dependency on the previously pushed image and an unbounded carry-over to prune.
- **Local two-version proof** (two builds with different hashes on :5391/:5392 behind a proxy that pins one or alternates, Playwright, cache kept throughout):
  - an old document on the new pod: `import('/_assets/invite-CDmlFIIZ.js')` failed with `Failed to fetch dynamically imported module`, the response was `404 no-store text/plain`; a client navigation to `/invite` recovered by itself (TanStack's `lazyRouteComponent` reloads once on a missing module) onto the new build's `index-CCXLvSZW.js`;
  - a new document on the old pod: the same, recovered onto the old build;
  - alternating every request (the overlap): one full load of `/invite?i=1` ended on "Something went wrong"; with the old pod gone, **Try again** showed the page;
  - afterwards none of the page's 9 script URLs answered `text/html` from the browser cache, and the old chunk answered `404`.
