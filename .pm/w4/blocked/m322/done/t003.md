## Objective

A cron App's zero `instance_seconds` for a window is healthy only when no run overlapped the window. When the App's run history shows a run inside the window and the read is zero, record the source as degraded, the way w6/m110's Defect A guard does for Deployments. The next selector gap then shows in usage coverage instead of passing silently.

## Context

- **Every cron App counts as idle.** `expectsRunningPods` (`lego/backend/internal/usage/service.go:1417-1419`) returns false for every cron App, so a zero is always "honest".
- **Run history is on the CR.** It is `status.runs` (`appv1alpha1.CronRun` with `StartedAt`/`FinishedAt`), already read by the backend (`cronRunsOf`, `lego/backend/internal/apps/service.go`).
- **Live, round 81.** All seven cron jobs metered in 2026-11 read `instance_seconds` 0 with no degraded signal.

## Steps

1. Extend `expectsRunningPods`, or add a cron-specific check: a cron App expects pods for a window when a `status.runs` entry overlaps it.
2. **Decide historical repair.** Either recompute the unmetered cron hours within `catchupLimit` (48h), or record "accepted as history" with the reason. Paid exposure follows w4/m173 t002's read-only method.

## Acceptance criteria

- [x] A test: a cron App with a run inside the window and a zero read records `degraded`. One with no run in the window records `healthy`.
- [x] The repair decision is recorded in the milestone README.

## Result (2026-11-11)

- **The check.** `expectsRunningPods` takes the window end. A cron App now expects pods for a window when a recorded `status.runs` entry spent at least `cronRunScrapeFloor` (30 s, two cAdvisor scrapes) inside it, counting a run still in flight up to the window end. A zero for such a window is recorded `degraded`; no recorded run, or only a sub-scrape run, stays `healthy`.
- **Tests.** Three new rows in `TestInstanceSecondsZeroFromRunningAppIsDegraded`.
- **Repair decision.** Not repaired by this milestone. Hours already rolled up stay as recorded. Measuring the unmetered seconds read-only and deciding a backfill (a billing decision, as w4/m173) is filed as w4/580.
