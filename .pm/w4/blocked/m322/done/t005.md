## Objective

REST, GraphQL, MCP and the dashboard report the same per-run series and usage for a cron job, and the result matches Render's cron job billing and metrics.

## Steps

1. **Compare the surfaces.** For one window, compare REST `/v1/metrics/cpu`, GraphQL `metrics(CPU)` and MCP `get_metrics` for a cron job with manual runs. Compare `GET /v1/usage` with the Billing page.
2. **Compare with render.com/docs/cronjobs.** Runs are billed per second. Check whether Render's cron Metrics tab charts per-run CPU and memory, and record the answer in ADR018's metrics row.

## Acceptance criteria

- [x] The surfaces agree, and the Render comparison is recorded, with a follow-up filed for any drift.

## Result (2026-11-11)

- **Billing.** Render bills cron jobs per second of run time, and a triggered run is a run (render.com/docs/cronjobs). bex now meters and charts triggered runs and long-name runs like scheduled ones, on every surface that reads the shared selector: REST, GraphQL and MCP metrics and usage, and the dashboard Metrics and Billing pages.
- **Unverified:** Render's own cron Metrics tab per-run charting. To be checked in the live replay (t004).
- **Docs.** ADR038 records the Job names and the skew behavior. ADR010 records the selector and the degraded-zero rule.
