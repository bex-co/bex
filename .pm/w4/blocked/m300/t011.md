## Objective

In Recent Runs, a run that is `pending` with no `startedAt` gets a status badge that says it is waiting, for example "Pending" or "Starting". Today it reads **Running**, next to a Started cell of "—" and a toggle named "not started yet". A pending run that has started keeps "Running". Render's API has no `running` status, so its `pending` covers both.

## Context

- **Live, round 244 of the `/qa-find-bugs w4` loop, 2026-11-13** (`bex-canary`, pin `764072bb8e8a`). The fixture was Starter cron `qa-20261113-r244-cron` (`srv-dbr59rhs0kvs73brgb9g`): busybox, schedule `*/5 * * * *`, command `echo …; sleep 45`. It was deleted afterwards.
  - The scheduled run `crr-1ji553bpa1bag401rhsc` started at 00:10:00Z.
  - Events → Recent Runs → Trigger Run at 00:10:06. The dialog read "…cancels any active run before the replacement starts", and the toast "Cron run triggered.". The scheduled run then read `canceled` (7 s).
  - From 00:10:09 to 00:10:59 the new row read `— | Run details, not started yet (row 1) | — | Running | Cancel`, while `GET /v1/cron-jobs/srv-dbr59rhs0kvs73brgb9g/runs?limit=5` returned `{"id":"crr-kr0e6npi2vfp9oindloj","status":"pending"}` with no `startedAt`.
  - `startedAt` 00:10:56Z appeared about 50 s after the trigger. The run read `successful` at 00:11:44Z, and the row "48s Succeeded".
- **The cause.** `RUN_STATUS` maps both `pending` and `running` to `services.cronRunStatusRunning` (`dashboard/src/features/services/components/cron-runs-section.tsx:45-46`). The badge (`CronRunStatusBadge`, `:73-77`) never looks at `startedAt`, although the toggle beside it does (t003, t009).
- Render's `cronJobRun.status` enum is `["pending","successful","unsuccessful","canceled"]` (the pinned `lego/backend/internal/api/openapi/render-public-api-1.json`). So REST reporting a running run as `pending` is parity, and only the dashboard label is in question.

## Steps

1. Pass the run to the badge. Label it "Pending" (en and zh) when the status is active and `startedAt` is empty; keep "Running" once it has started.
2. Keep the Cancel action on both.

## Acceptance criteria

- [ ] Component test: a `pending` run without `startedAt` shows "Pending"; with `startedAt` it shows "Running"; `canceled` without `startedAt` keeps "Canceled" (and t009's toggle name).
- [ ] Live, in the t008 replay: Trigger Run over an active run. The new row reads "Pending" until its `startedAt` appears, then "Running", then "Succeeded".
