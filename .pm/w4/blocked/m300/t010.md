## Objective

DoD P2 and P3 promise that a run canceled before it started "never executes". Live, every such run executed: a `DELETE …/runs` within a second, a `POST …/runs/{id}/cancel`, and a second trigger that replaced the first. Make a run whose cancellation lands before its Job runs never start a container. A run canceled after its Job started stops promptly, as today. The record must never show a run starting after it was recorded `canceled`.

## Steps

1. On the mock cluster, replay P2 and P3 with the same command. Record, per pass: `spec.runAt`, `spec.cancelRun{Name, Unmaterialized}`, `status.cancelRunRecorded`, the Job's creation time and deletion timestamp, and the pod's start time.
2. Close the window so that a cancellation recorded before a Job exists keeps that Job from ever being created. For a replaced run, the operator must not materialize A once B's request carries A's cancellation.
3. For a Job that already exists when the cancel lands:
   - delete it with a pod deletion that doesn't let a not-yet-started container start (for example, delete with grace 0 while the pod is Pending);
   - set `startedAt` only from a pod that actually started;
   - never record a `startedAt` later than the run's `finishedAt`.
4. Tests (operator envtest, and the store reconciler for the row):
   - cancel before materialization → no Job is ever created;
   - replace before materialization → only B's Job exists;
   - cancel after the Job exists → the row reads `canceled`, and `startedAt ≤ finishedAt` or is empty.
