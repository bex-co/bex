## Objective

Make a completed Service Name save publish the latest authoritative label after older detail/list metadata reads, preserving the successful write independently of refresh failures.

## Context

Four controlled real-response replays in [finding.md](../finding.md) restore the old field/heading after a successful SetDisplayName. The hook awaits only the mutation; onChanged fires router invalidation without awaiting ordered fresh data. The field follows persisted props correctly.

## Steps

1. Add a service-name publication step using native Apollo primitives. Settle relevant same-resource Server and workspace Services work individually before the final network-only Server read with queryDeduplication:false. Account for multiple observers and one-shot loader reads rather than relying on a UI loading flag. Use project/cron ordering as references and verify the actual application defaults.
2. Hold busy/draft or an honest refreshing presentation until publication completes; then invalidate the retained route/head against fresh data. Publish the final read's label, including a newer concurrent edit, rather than permanently pinning the submitted value.
3. Separate write rejection from post-commit publication failure. Keep stale editing unavailable, warn truthfully and offer a read-only retry. Do not repeat SetDisplayName to repair a read. Guard resource/workspace changes and unmounts.
4. Preserve existing error classes, trim/empty behavior, validation, identity and no-rollout semantics. Keep the change local to this writer and an audited helper if needed.
