# 538 — The Logs search box treats Render's documented `status_code:`, `method:`, `path:`, `host:`, `level:` and `instance:` search operators as literal text, so every one returns "No matching logs"

Why: a Render user types Render's own documented searches (`status_code:/4../`, `method:/(GET|POST)/`, `path:api/*`) and bex answers with a confident empty state, although the matching lines exist and the API can filter them.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 4, 2026-11-10 08:31–08:42 UTC (`muse.env`, workspace `bex-canary`, pin `4630a48a765e`). **Minor** (documented queries return a silent empty result; the Filters popover is a workaround). ~60m.
- **Fixture:** Free web service `qa-20261110-logs` (`srv-dbpdcqqj0hgs73eavnh0`, `examples/hello-go`; deleted, GET 404). Curling `/qa-alpha-1`, `/qa-alpha-2`, `/qa-beta-1`, `/QA-Gamma-Upper` and `/qa-missing/deep/path` at 08:35:23–08:35:31 produced 5 app lines (`GET /<path>`) and 5 `type=request` lines (`GET`, `200`).
- **Render:** [render.com/docs/logging](https://render.com/docs/logging), fetched 2026-11-10. The log explorer's search accepts the field operators `level`, `instance`, `method`, `status_code`, `host` and `path`, with `*` wildcards and `/RE2/` regex. Documented examples: `status_code:/4../`, `method:/(GET|POST)/` and `path:api/resource/*/subresource`.
- **Probes:**
  - In the dashboard's Search logs box (`/services/srv-dbpdcqqj0hgs73eavnh0/logs`), `status_code:/2../`, `method:/(GET|POST)/` and `path:qa-alpha*` each rendered "No matching logs — No logs match these filters." and put the whole string in `?text=`.
  - REST `GET /v1/logs?ownerId=tea-daif693dqjvc73e7as3g&resource=srv-dbpdcqqj0hgs73eavnh0&startTime=2026-11-10T08:30:00Z&endTime=2026-11-10T08:45:00Z&text=<same>` answered `200` with 0 logs for each.
- **Controls** (the API's filters work; only the search box's operator syntax is missing):
  - `text=qa-alpha` → 4 lines; `text=/qa-(alpha|beta)-1/` → 4; `text=qa-gamma` → 2 (case-insensitive); `text=zzzz-nothing` → 0.
  - The Filters popover's Request path `/qa-alpha*` showed exactly the 2 `/qa-alpha-*` request lines, with `?path=%2Fqa-alpha*`.
- **Root cause:**
  - `dashboard/src/features/logs/components/log-viewer.tsx:123-133` builds `queryFilters` with `text: committedText` verbatim (`:130`). The live tail gets the same raw text (`:203`).
  - Nothing parses operators: `git grep -n "status_code:" dashboard/src/features/logs` has no hits outside tests and locales.
  - `LogFilters` (`features/logs/types.ts:84-92`) has no `host` field, so the dashboard cannot filter by host at all, although REST, GraphQL and MCP accept `host` (ADR018 row 245).
- **Fix (target behavior):**
  - The search box parses `name:value` tokens for `level`, `instance`, `method`, `status_code` (→ `statusCode`), `host` and `path` into the matching structured filters.
  - Values keep their literal / `*` / `/RE2/` semantics, which the server already implements (`lego/backend/internal/logs/filterpattern.go`, w8/176).
  - Each parsed operator shows as a removable chip, as the Filters popover's filters do, and only the remaining words are sent as `text`.
  - Add `host` to `LogFilters` and `STRUCTURED_FILTER_KEYS`, which gives it a URL key, a popover row and a chip.
  - An unknown `name:` stays literal text.
  - REST `text` stays a literal search, because Render's API takes separate filter params.
- **Blast radius:**
  - `STRUCTURED_FILTER_KEYS` (`types.ts:99`) drives the URL schema (`lib/log-search.ts:46`), the popover rows and chips (`log-filter-bar.tsx:163`), the filtered-empty check (`log-viewer.tsx:373`), and the store-only and active-filter predicates (`types.ts:120`, `:150`).
  - The live tail's `requestFilters` (`log-viewer.tsx:208-213`) must receive the parsed filters too.
  - The Postgres and Key Value log viewer (`datastore-log-viewer.tsx`) has its own search (`lib/datastore-log-search.ts`) and only imports `LiveToggle` from the bar. Decide separately whether `level:` and `instance:` apply there.
- **Unverified:** how Render handles a query that combines an operator with free text, or an unknown operator; neither was probed.
- **Not filed (context):** Render's documented `/responseTimeMS=\d{3}\d+/` (requests slower than 1 s) also returns 0 on bex. bex's request message is Traefik's JSON (`"Duration":<ns>`), not Render's rendered `key=value` summary. ADR018 row 245 lists that divergence, and w8/176 noted it has no sign-off and needs a captured Render request line to state the target format.
