# Static sites send no validator, so every revalidation re-downloads the whole file

Why: the default `public, max-age=0, must-revalidate` (w4/m160) makes browsers revalidate on every view. With no ETag or Last-Modified, a revalidation can never be a 304, so returning visitors re-download every file, and the owner is billed for those bytes as bandwidth. Render answers the same revalidation with a header-only 304.

- **Severity:** minor (performance and billed bandwidth; content stays correct). **Estimate:** 60m.
- **Source:** live functional `/qa-find-bugs w4`, pass b52e07, 2026-10-19 UTC, `muse.env`, workspace `bex-canary`. Production was pinned to `d5c3373ed`; research is on main `7d60da3a3`. The probes are in the [durable evidence](evidence/341-static-validators-b52e07.json). The owned fixture was deleted at the end of the pass.
- **Repro:** create an owned Free Static Site from `https://github.com/bex-co/bex`, root `examples/static-site`, publish `.`, with no header rules. Then:
  - `curl -sS -D - -o /dev/null https://<slug>.onbex.co/` → 200 with `cache-control: public, max-age=0, must-revalidate`, `content-type: text/html` and `content-length: 1548`, and **no `etag` or `last-modified`**. HEAD returns the same headers.
  - `If-Modified-Since: <now>` → **200, 1548 bytes**.
  - Chromium goto → reload → goto: each response is a full 200. The last navigation shows `transferSize 889 > encodedBodySize 589`, meaning the body crossed the network again.
- **Render control (same probes):**
  - Six live `*.onrender.com` static demos (hugo, jekyll, gatsby, cra, vue, svelte) send `cache-control: public, max-age=0, s-maxage=300` together with a weak `etag` and a `last-modified`.
  - `If-None-Match: <etag>` on `hugo.onrender.com` and `cra.onrender.com` returns **304, 0 bytes**.
  - In Chromium, the third `hugo.onrender.com` navigation shows `transferSize 300 < encodedBodySize 985`: a header-only revalidation.
  - Render's static-site docs (fetched 2026-10-19) do not document the header policy, so the comparison is the live behavior above.
- **Root cause:** `lego/operator/internal/staticserver/staticserver.go:366-368` sets only Content-Type and `defaultCacheControl` (`:733`). `:400-404` calls `http.ServeContent` with `time.Time{}`. Go's `ServeContent` evaluates `If-None-Match` only against an `ETag` header already on the response, and `If-Modified-Since` only for a non-zero modtime, so without an owner rule nothing can ever match. This was not a product decision. `w4/272` scoped it out of its fix ("Do not invent … an automatically generated ETag"; its test `conditional_test.go:110-127` encodes that boundary), and `w4/m160`'s finding lists HTTP validators as "outside that milestone".
- **Fix (target behavior):** every successful static response carries a server-generated strong ETag derived from the identity bytes it represents.
  - Compute it once per object at cache fill. Revision objects are immutable (`get`, `staticserver.go:455-488`), so this costs one hash per fetch, not per request. A content digest or the origin's S3 `ETag` would both satisfy the contract.
  - **304:** a matching `If-None-Match` returns a bodyless 304 for GET and HEAD.
  - **m160's guarantee:** a republish that changes the bytes yields a different ETag, so the next revalidation returns 200 with the new bytes. A republish with identical bytes may keep its 304.
  - **Precedence:** set the default before `applyHeaders`, so an owner's saved `ETag` rule still wins (w4/272). The Brotli variant keeps using `weakenETag`, so `br` and identity responses still validate against each other under weak comparison.
  - **Last-Modified:** keep omitting it; do not invent a time.
- **Blast radius:**
  - `serveObject` has 3 callers: the direct object (`:266`), a rewrite target (`:315`) and the SPA fallback `index.html` (`:325`). All gain the default.
  - One static-server binary serves every static site.
  - Tests that must change deliberately: `TestNoSavedETagOnlyWildcardMatches` (`conditional_test.go:110-127`), which asserts no generated ETag. Rewrite it to assert the generated tag, and keep its wildcard case.
  - Tests that must keep passing: `TestSavedETagPreconditions` and `TestConditionalFramingOverHTTP` (the saved rule wins), and `revalidation_test.go`'s `TestRepublishedURLServesNewBytesAndRevalidates` (m160).
- **Adjacent classes:**
  - Non-success responses (404 page, 503 busy, 416) keep no default validator, consistent with `TestNonSuccessResponsesCarryNoDefaultCachePolicy`.
  - A failed `If-Match` against the generated tag returns 412.
  - `If-Range` with the strong tag may now resume ranges.
  - An owner Cache-Control rule is independent of the tag.
- **Unverified:** CDN/edge behavior in front of the static server (none observed: no `age` or `cf-*` headers on bex responses). Larger assets and custom domains were not probed. Whether the `egress_bytes` meter counts headers was not checked.
- **Dedupe:**
  - `w4/272` (done) fixed preconditions for owner-saved ETags only.
  - `w4/blocked/m160` set the freshness policy and left validators out.
  - `DO_NOT_DO.md` excludes only a CDN cache-purge API, which this does not add.
  - No open item mentions a generated ETag or Last-Modified.
  - `git log` up to `origin/main`: the later `staticserver.go` changes (`5a39b80ff` automatic Brotli, `538058566` w4/307) add no default validator.
- **Render parity:** static-site delivery is tenant-facing. Record the default validator in `docs/ADR029-static-sites.md` and the ADR018 static-site row.
- **Acceptance:**
  - Handler tests cover all three `serveObject` callers, HEAD, `br`, saved-rule precedence, republish-changes-tag and non-success responses; they fail on the current code.
  - Live, on a fresh owned site: the default response carries an `etag`; `If-None-Match` with it returns 304 / 0 bytes; the Chromium reload shows `transferSize < encodedBodySize`; after a republish with changed bytes, the old tag returns 200 with the new bytes.

## Implementation done 2026-10-19 (loopx w4)

- `Handler.get` stamps each fetched object with `contentETag`: a strong tag, base64url of the first 128 bits of SHA-256 over its bytes. It is computed once per fetch and stored on the cached `Object.etag`.
- `serveObject` sets it before `applyHeaders`, so a saved `ETag` rule still wins (w4/272), and `http.ServeContent` answers 304 (GET/HEAD), 412 and If-Range from it. Brotli keeps `weakenETag`, so the br and identity tags validate against each other under weak comparison, and If-Range never splices br bytes onto identity bytes. `Last-Modified` is still omitted. A 416 and a live-body shed carry no tag: Go strips it on errors, and the shed returns before the header is set.
- Tests, in the new `etag_test.go` plus the rewritten `TestGeneratedETagValidatesWithoutASavedRule`, which replaces `TestNoSavedETagOnlyWildcardMatches`:
  - all three `serveObject` callers (direct object, rewrite target, SPA fallback), and HEAD;
  - br/identity cross-validation;
  - If-Range resume (current tag gives 206, stale gives 200, br gives a full 200);
  - a republish that changes the tag only when the bytes change;
  - 416 and shed responses carry no tag.
  - The four behavior tests fail on the pre-fix code. `TestSavedETagPreconditions` and `TestRepublishedURLServesNewBytesAndRevalidates` pass unchanged.
- ADR029 and the ADR018 static-site row record the validator.
- Operator `make test`, golangci-lint and deadcode pass.
- `/simplify` findings applied: the field is unexported, the comments are corrected, the shed path has a test, and the failing-direction If-Match assertion is gone. Skipped: skipping the live-body lease for a 304, which is not a regression and would duplicate ServeContent's entity-tag parser.
