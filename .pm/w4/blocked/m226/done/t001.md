## Objective

Publish current maxmemoryPolicy and persistenceMode to the mounted editors whenever the existing Key Value detail poll succeeds.

## Context

[finding.md](../finding.md) records main polls that update status/updatedAt but omit both configuration fields. The focused hooks read on mount and after a local save. Their stale known persistence mode can classify an actual Off-to-durable save as a durable conversion and skip the existing typed deletion confirmation.

## Steps

1. Select maxmemoryPolicy and persistenceMode in the existing KeyValueDocument and regenerate its definitions through the repository's offline codegen workflow. Keep the detail page as the polling owner and breadcrumbs as poll:false.
2. Verify the normalized main result updates both focused observers without extra editor timers or redundant prop-mirroring state. Preserve known underscore-to-hyphen normalization and nullable/unknown mode behavior.
3. Ensure the persistence row's decision and pending confirmation use the newly delivered mode. Preserve an active draft while updating its saved baseline; do not remount the row on every poll or replay a mutation to refresh data.
4. Preserve existing load errors, unknown-mode disabling, same-client post-save refresh and transition copy. Do not infer Off/durable/default values from an absent or failed field.

## Acceptance criteria

- [ ] A successful existing main poll publishes both configuration properties to untouched rows without reload.
- [ ] The recorded stale-Off cases now require the typed deletion confirmation before any persistence write.
- [ ] Cancel sends no mutation and preserves Off-mode marker data.
- [ ] One polling owner, retained drafts, dirty/no-op semantics and truthful Updating/Restarting remain intact.
- [ ] No operator transition, schema/API expansion, global cache policy or unrelated setting change.

## Out of scope

Changing intentional Off discard, disabling the setting, compare-and-swap API design and unrelated configuration writers.
