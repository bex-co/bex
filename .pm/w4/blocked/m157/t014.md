## Objective

Preserve supported finite PostgreSQL date/timestamp values outside Go JSON's year 0–9999 range without failing the whole SQL result. Normalize only those values into the signed expanded Gregorian strings specified in [finite-year evidence](finite-year-finding.md), before encoded budgeting and across native arrays. Keep all existing normal-year and special-value representations.

## Context

- Functional live QA a208, 2026-10-11 UTC: fresh desktop/mobile native year-10000 DATE fails; five REST native-value cases return 500, paired text/normal controls and recovery SELECT succeed.
- The pinned pgx finite codecs return time.Time; the unchanged value reaches query.go's whole-result json.Marshal and fails before any adapter.
- Earlier t007 explicitly excluded BC/far-future formatting. This task adds the verified finite class, preserving that prior completion.

## Steps

1. Audit the collector's Query/ExecuteQuery and Insights consumers and the existing typed adapters using the counted boundary in the finding.
2. Add one bounded query-local finite-time policy: preserve year 0–9999; use signed expanded year strings outside it with exact fractional precision/offset and no clipping/null substitution.
3. Reuse native-array recursion. Preserve raw/encoded caps, row/column truncation and existing error handling.
4. Add real pgx/Postgres regressions for the captured scalar and array failures, BC conversion, normal boundaries, codec formats and affected consumers; carry unexercised live variants to t003.
5. Document the explicit Bex representation; include the change in t012/t013 rather than treating prior closing work as coverage.

## Acceptance criteria

- [ ] Captured native scalar and DATE-array queries return their actual values successfully; the year-10000 date is +010000-01-01T00:00:00Z, and PostgreSQL 0002 BC is -000001-01-01T00:00:00Z.
- [ ] Timestamp/timestamptz preserve the captured .123456 precision and their existing timezone meaning; arrays preserve dimensions and SQL NULL elements.
- [ ] Existing year-0–9999 encoding, SQL NULL, infinity, finite numeric, UUID, bytea, JSON and Insights contracts remain unchanged.
- [ ] The new strings pass GraphQL's string branch without extra quotes and serialize as strings on REST and both exact-MCP result forms.
- [ ] Real size-limit/timeout/error outcomes remain existing outcomes; no normalizing patch weakens a budget.
- [ ] Unverified live/MCP/boundary/RETURNING cases remain assigned to t003/t013, and no full m157 closeout is inferred from a208.

## Out of scope

Global driver changes, platform timestamp redesign, SQL or access-policy changes, extending JavaScript Date's range, normal-year wire changes, production table writes, and unrelated product fixes.
