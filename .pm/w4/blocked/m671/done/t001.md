## Objective

Decide and write down the check's rules before building it: which services, which image reference, the interval, the request, the failure rule, the registry load, and what a recovery does.

## Context

- Render publishes no interval or rule (render.com/docs/deploying-an-image).
- The causes come from w4/m669 t001 (not found, authentication, registry unavailable, rate limited).
- External metadata reads, with their token auth and SSRF guard, live in `lego/operator/internal/registry/image_config.go`; bex's own registry HEAD is `ResolveDigest` (`registry/digest.go:131`).
- Docker Hub's pull limit counts manifest `GET`s, not `HEAD`s (Docker's "Usage and limits" page; re-check it when writing the note). Anonymous reads share bex's egress quota (w4/blocked/429).

## Steps

1. Propose: every 6 hours with jitter, for every non-suspended image-backed service whose served image is outside bex's registry, a `HEAD` on the served reference (the digest when the release is pinned to one) with the service's credential.
2. Count a failure only for not found or authentication on two consecutive checks; never for 429, 5xx or a network error.
3. Bound the load: a per-registry concurrency cap and a per-run budget.
4. Record the note in ADR004 (image-backed services) and link it from the milestone README.
