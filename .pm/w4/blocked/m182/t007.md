## Objective

Complete m182's existing no-unresolved-backend guarantee at the public edge. Live QA on 2026-10-11 still saw a generic routing404 immediately after a supported port save, including a fresh replay against an always-healthy /info route. Confirm the deployed operator and edge versions first: this run did not inspect production Kubernetes objects or operator provenance. If deployment lag explains the replay, deploy the existing fix and repeat the original DoD rather than changing working code. If the gap survives the deployed fix, preserve a resolvable edge binding at every supported transition, including adoption of an existing numeric Ingress.

Why: naming a pod's targetPort preserves its listener but does not by itself preserve the Ingress's independently observed Service-port reference. This is a follow-up within the existing milestone, not a duplicate availability milestone or a claim of a new regression.

## Source trace and proposed fix

Reviewed checkout:044d2614d during reproduction; source rechecked after pulling0acf2187e, which changed only the Alloy image workflow. Existing m182 fix:f763c19a0. No additional binding fix was found on main.

- lego/operator/internal/controller/app_controller.go:3044–3060: applyClusterIPService replaces the Service ports. For configured services it assigns the stable name bex-http and resolves the per-pod named target through servingTargetPort; the public Service port number still changes.
- app_controller.go:2515 then2543: the primary Service write and Ingress write are separate operations.
- app_controller.go:504–516: appendIngressHostRoute still writes ServiceBackendPort.Number. Kubernetes permits either Number or Name; merely adding a Service-port name does not change this consumer.
- app_controller.go:3546 and3669: the helper has exactly two production call sites, normal and host-redirect Ingress projection. Both need the selected-backend policy.
- app_controller.go:6016: ingressRoutes compares Number in the held-release poll path; a named writer without a matching reader continues to fail this predicate.
- lego/types/v1alpha1/image_network.go:57–58: UsesImagePorts is limited to private image-port modes, not this web fixture. Preserve those numeric tcp-N projections.

[Traefik v3.7.5's Kubernetes Ingress consumer](https://github.com/traefik/traefik/blob/v3.7.5/pkg/provider/kubernetes/ingress/kubernetes.go#L514), the version referenced by ADR010, matches a Service port by number or nonempty name at531–539; if no match exists it errors, and the path loop at345–352 skips that backend. This establishes the reviewed consumer mechanism. Independently observed Service/Ingress updates can therefore leave a numeric reference temporarily unresolved. **That ordering is an inference from source and the404; no intermediate production objects were captured.** The production version and OCI chart appVersion remain unverified; the read-only chart metadata lookup did not complete and was stopped. Confirm the actual dependency version before implementing.

Target behavior: each public request to the healthy route reaches the ready old listener until the new listener is ready, then reaches the requested listener, with a tracked Live configuration deploy. A stable named binding on configured App routes is a candidate approach. Specify adoption/partial writes explicitly: changing an old numeric Ingress after removing its referenced Service number still leaves a gap. Handle old/new independently observed objects and retained templates; a one-line writer change or a desired-object snapshot cannot prove availability.

Allowlist the normal configured App backend; preserve numeric bindings for the selected activator, maintenance and shared static-server backends. Update ingressRoutes and paired redirects consistently with the writer. Keep internalAddress's advertised numeric port, both CR-name/slug Service identities, named targetPort and legacy unnamed-pod compatibility, release snapshots, readiness, and disk Recreate policy.
