# 647 — Retire w4/m342's transitional isolation pieces once bex-api and the operator both run it: the `-legacy` boundary, the blanket's `network-isolation` clause, the per-App protected policy and the in-place `network-isolation` pod mirror

Why: w4/m342 kept four belt-and-braces pieces so either deploy order (operator first or bex-api first) kept the boundary and intra-environment traffic. Once both run the m342 release and every App pod carries `environment-id`, they only add NetworkPolicy objects and selectors that no pod needs.

- **Source / severity / estimate:** `/loopx w4` closeout of w4/m342 (2026-11-14). **Minor** (cleanup, no behavior change). ~50m.
- **Prerequisite:** the production deploy that carries w4/m342 has run, and w4/m342 t006's live replay passed. Check that no running App pod in a hosting namespace lacks `app.bex.co/environment-id` while its App CR carries one (`kubectl get pods -A -l 'app.bex.co/app,!app.bex.co/environment-id'`, filtered to Apps in an environment).
- **Retire:**
  - `isolate-<env>-legacy` in `environmentIsolationPolicies` (`lego/backend/internal/store/namespaces.go`) and the `network-isolation NotIn` clause in `sameNamespaceNetworkPolicy`;
  - the operator's per-App protected policy (`reconcileProtectedAppNetworkPolicy`, `environment_network_policy.go`), deleting existing ones once;
  - the in-place `network-isolation` mirror on App pods (`relabelAppPods`). That also means re-keying the non-isolated Key Value client selector (`keyvalue_internal_network.go`) and build datastore reach (`build_datastore_reach.go`), which still read it.
- **Keep:** the App CR's `network-isolation` label if anything else still reads it; check with `grep -rn LabelNetworkIsolation lego`.
- **Tests:** the w4/m342 envtests and `namespaces_isolation_test.go` still pass with the pieces gone; an isolated environment's pods reach each other and nothing else.
- **DoD:** after deploy, replay w4/m342's DoD 1–3 on production.

## Worker record (2026-11-16)

**Verdict: work, minus the pod mirror.** Retired:

- bex-api: `isolate-<env>-legacy` is gone from `environmentIsolationPolicies`, and `allow-same-namespace` now selects only by `environment-id NotIn [isolated]` (`lego/backend/internal/store/namespaces.go`). A leftover `-legacy` carries `app.bex.co/isolated-environment`, so the boundary prune deletes it (`TestLeftoverLegacyBoundaryIsPruned`).
- operator: `reconcileProtectedAppNetworkPolicy` is replaced by `deleteProtectedAppNetworkPolicy`. It creates no per-App policy and deletes one this App owns or that selects `app.bex.co/app=<name>`, never a same-named policy the App does not own (`isolation_test.go`, `network_isolation_label_envtest_test.go`).
- ADR043's isolation section is amended to match.

**Kept: the in-place `network-isolation` pod mirror (`relabelAppPods`).** Re-keying its readers needs the list of isolated environments, which only bex-api has:

- `buildReachTargets` (`build_datastore_reach.go`): the build-ingress policy is the only enforcement point for a build pod in `bex-build`. An ordinary App's build must not reach an isolated environment's datastore or App pods. Without the per-pod label, the operator would have to learn which environments are isolated, and re-converge every build policy on each toggle.
- The non-isolated Key Value client selector (`keyvalue_internal_network.go`) could fall back on the isolated pods' own egress boundary. The build path cannot, so both keep the label for one consistent rule.

The mirror is a metadata patch and restarts nothing, so keeping it costs no behavior. ADR043 now records it as permanent rather than transitional.

Also check `kubectl get networkpolicy -A | grep -- '-legacy\b'`, and that no per-App policy named after an App exists in a `tea-*` namespace.
