## Objective

A single-key write that cannot be projected into Kubernetes must leave the store as it was, so source always equals projection.

## Context

- `lego/backend/internal/secrets/files.go:118-155` `SetSecretFile`: `updateMapCAS` writes OpenBao first, then `materializeFiles` projects. On projection failure it returns the error with NO compensation, so the bad key stays stored. Live: REST 500, and the name was then listed.
- The same shape applies to the single `SetEnvVar` path (`internal/secrets/service.go`). Live: a 254-character key returned 500 and persisted, and every later env write returned 500 while still writing the store.
- `PatchEnvironment` already compensates (`internal/secrets/batch.go:548` `compensateEnvironment`), so mirror that contract.

## Steps

1. On projection failure in `SetSecretFile`/`SeedSecretFiles`/`SetEnvVar` (and the per-key env/file setters), CAS the pre-write map back. On success return the original error; if the restore itself fails, join both errors.
2. Map the projection error class to a client error when it is a Kubernetes validation rejection (`apierrors.IsInvalid`), not a bare 500.

## Files

- `lego/backend/internal/secrets/files.go`, `lego/backend/internal/secrets/service.go`

## Acceptance criteria

- [ ] A forced projection failure leaves the store map byte-identical to before (unit test with a failing fake client).
- [ ] REST/GraphQL/MCP single-key writes report the failure without persisting.

## Out of scope

- Length validation itself (t001).
