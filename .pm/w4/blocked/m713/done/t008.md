## Objective

Add meaningful tests for what this milestone shipped, covering these failure modes:

- an hour priced on both kinds;
- a Key Value storage event after the cutover;
- a resize billed retroactively on catch-up;
- the GiB-versus-GB unit;
- compaction losing a reading.

Prove each important test is real: revert the change and watch it fail.

## Acceptance criteria

- [ ] Each listed failure mode has a test that fails without the fix.

## Outcome (2026-11-28)

Each failure mode has a test, and each was proven real by breaking the code and watching it fail:

- **An hour priced on both kinds:** `TestStorageCapacitySwitchPG` fails when the hourly read drops `storageShown` (November's capacity and December's used bytes read billed) and when the outbox drops it (both kinds sent).
- **A Key Value storage event after the cutover:** the same outbox check, `TestStripeMeterEventMapping`'s Key Value cases, and `TestDatastoreWindowWritesCapacityForPostgresOnly` (fails when a Key Value gets the capacity meter).
- **A resize billed retroactively on catch-up:** `TestStorageCapacityCatchUpReadsEachWindow` (10 GB windows before the resize, 20 GB from it).
- **GiB versus GB:** `TestQueryStorageCapacityGBSeconds` fails with decimal GB (38,654 instead of 36,000).
- **Compaction losing a reading:** `TestStorageCapacitySwitchPG` fails when the monthly read is not classified and when compaction drops the shown reading.
