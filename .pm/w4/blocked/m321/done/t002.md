## Objective

Every request that returns one or more env var values records one `ViewEnvVarValuesEvent`, on every surface. This is Render's event: "logs when environment variable values are viewed" ([render.com/docs/audit-logs](https://render.com/docs/audit-logs)). The metadata names the service or environment group. A keys-only listing records nothing.

## Context

- **Value-returning service reads:**
  - `secrets.ListEnvVars` (`lego/backend/internal/secrets/service.go:329`), which serves REST `GET /v1/services/{id}/env-vars` with values;
  - `GetEnvVar` (`:437`);
  - the single-key reveal behind the dashboard's Reveal and Export (Copy env vars, Download .env), which uses `readAuthorizedEnv` at `:787`.
- **Do not record at `readAuthorizedEnv` itself.** It is shared with the keys-only `EnvVarKeys` (`:767`), which the Environment tab loads every time.
- **Env-group value reads:** `lego/backend/internal/envgroups/service.go:392`, `:886` and `:998`, and `render.go:132` (the REST env-group object with values). Check which return values and which return keys.
- **MCP:** the env var and env group tools that return values go through the same verbs. Confirm by grepping `mcp.go` in both packages.
- **Prior art for an audited reveal:** w5/m285 (webhook secret reads).

## Steps

1. Add `ViewEnvVarValuesEvent` to `renderEvents` (`lego/backend/internal/audit/service.go:135`) through a typed recorder in `core/audit.go`, as `RecordDatabaseEffect` is.
2. Call it once per successful value-returning request: per request, not per key. Metadata is `service: <srv-id>` (or `envGroup: <evg-id>`) plus `targetName`.
3. Leave `EnvVarKeys` and the masked GraphQL list silent.

## Out of scope

- Secret files. Render's docs name env var values only, so decide in t006 whether a secret-file content read maps to the same event.

## Result (2026-11-11)

- `core.AuditVerbViewEnvVarValues` ("secrets.ViewEnvVarValues") maps to `ViewEnvVarValuesEvent`, and `core.RecordSecretsViewed` writes it once per successful request. It is never written at the shared `readAuthorizedEnv` boundary.
- **Service env vars** record from:
  - `ListEnvVars`: REST list, and `ListEnvVarsPage` for REST and MCP pages;
  - `GetEnvVar`: REST and MCP get;
  - `EnvVarValue`: the dashboard's Reveal, Copy env vars and Download .env, and GraphQL `service{envVar(key)}`.
  - Metadata `service: <srv-id>` and `targetName`.
- **GraphQL `envVars`** records only when the query selects `value`, through fragments too (`gqlutil.Selects`). The dashboard's Environment tab lists keys through that field, so opening the tab records nothing.
- **Never recorded:** `EnvVarKeys`, `ListEnvVarNames` (the Blueprint generator and plan) and the Blueprint `envCopier` use unrecorded internal reads (`listEnvVars`, `envVarValue`).
- **Env groups** record from `GetEnvGroupVar` (REST, GraphQL, MCP) and the REST group read that returns values (`revealGroups`, read responses only, not write echoes), with metadata `envGroup: <evg-id>`. The keys-only view and `ExportEnvGroup` record nothing.
- **Secret-file contents** have no Render view event and are not recorded. Whether Render audits them is filed as w4/578.
- **Tests:**
  - `TestValueReadsRecordOneViewEnvVarValuesEvent` (list, page, get, reveal → 1; keys, names, copy → 0; denied → denial only);
  - `TestGraphQLEnvVarsRecordsAViewOnlyWhenValuesAreSelected`;
  - `TestEnvGroupValueRevealRecordsOneViewEvent`.
