## Objective

A user action that has a Render audit event records it under that name, once. Today two mapped names are never emitted. The mapping (`lego/backend/internal/audit/service.go:135-161`) keys on `projects.Create` and `environments.Create`, but REST, GraphQL and MCP all call `projects.CreateWithEnvironments` and `environments.CreateWithACL`. Several more actions have an exact Render event and no mapping.

- **Callers of the create verbs:**
  - `projects.CreateWithEnvironments` (`lego/backend/internal/projects/service.go:421`) is called by `rest.go:175`, `graphql.go:89` and `mcp.go:103`.
  - `environments.CreateWithACL` is at `lego/backend/internal/environments/service.go:643`.
- **The guard test checks the wrong thing.** `TestRenderEventVerbsExist` checks that a mapped method exists, not that the surfaces call it.
- **Prefixes.** Render's enum is the pinned `components.schemas.auditLog.properties.event` (87 values). Render's names are verb-first: `Create…`, `Delete…`, `Move…`, `Apply…`.

## Steps

1. **Fix the two dead mappings.** Map the verbs the surfaces actually call, or emit from the shared inner verb. Add a test that drives REST `POST /v1/projects` (with environments) and `POST /v1/environments` and asserts `CreateProjectEvent` and `CreateEnvironmentEvent`.
2. **One event per action.** A delete records one `DeleteProjectEvent` or `DeleteEnvironmentEvent` row. An environment move records one `MoveEnvironmentResourceEvent`, with the resource and the source and destination environment, not four rows.
3. **Map the exact 1:1 actions:** webhooks create and delete, env group delete, disk add and delete, Blueprint approve and sync, which become `ApplyBlueprintEvent`.
4. **Env var writes.** Decide the `secrets.*` mapping. One patch can create, update and delete keys, so either emit one event per kind present, or record the decision to keep `secrets.PatchEnvironment` in ADR018 (t004).
5. **Extend `TestRenderEventVerbsExist`,** or add a sibling test, so each mapped name is reachable from a REST handler.

## Result (2026-11-11)

- **Dead mappings fixed.** `projects.CreateWithEnvironments` → `CreateProjectEvent` and `environments.CreateWithACL` → `CreateEnvironmentEvent`. Those are the verbs REST, GraphQL and MCP actually call.
- **One row per action.**
  - Project and environment creates and deletes now record one row, through `RecordAllowedWrite`, only once the change has landed. Their authorizations run under `WithDeferredAllowedWriteAudit`.
  - A refused `DeleteIfEmpty` (not empty), or a create refused by validation, quota or a name conflict, records no allowed row.
  - The delete cascades' membership clear adds no rows. Each datastore and service delete still records its own event.
  - `environments.SetServices` and `projects.SetServices` record only their typed move rows, now `MoveEnvironmentResourceEvent`. One move had recorded four rows.
- **1:1 maps added:**
  - `webhooks.Create`/`Update`/`Delete` → `Create`/`Update`/`DeleteWebhookEvent`;
  - `envgroups.DeleteEnvGroup` → `DeleteEnvGroupEvent`;
  - disks → `CreateServerDiskEvent`, `DeleteServerDiskEvent`, `RestoreDiskSnapshotEvent`;
  - `apps.ApproveBlueprint`/`SyncBlueprint` → `ApplyBlueprintEvent`;
  - build sources → `Create`/`Update`/`DeleteBuildSourceEvent`;
  - `secrets.DeleteEnvVar` → `DeleteEnvVarsEvent`.
- **Env var writes.** `secrets.SetEnvVar`, `SetEnvVars` and `PatchEnvironment` keep bex's names. One patch can create, update and delete keys at once, so there's no 1:1 Render event. Recorded in ADR018.
- **Tests:**
  - `TestRenderEventNamesAreInThePinnedEnum` validates every name against the pinned enum;
  - `TestRenderEventVerbsExist` keeps the keys real;
  - `TestOneMoveAndOneDeleteRecordOneRowEach`, `TestEnvironmentCreateRecordsOneRowOnlyWhenItHappens`, `TestProjectMoveAndDeleteRecordOneRowEach`.
