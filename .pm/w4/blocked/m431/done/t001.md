## Objective

A deploy trigger can carry `DisableAutoDeploy`: the same release write that pins the commit sets `spec.autoDeploy = false`, and the event feed records `auto_deploy_disabled` with Render's `reason: manual_deploy` and the `fromTrigger` it replaced. A trigger without the flag is unchanged.

## Context

- `core/audit.go:636-642` defines `AutoDeployReasonSettingChange` and `AutoDeployReasonRollback` and says bex has no path that writes `manual_deploy` (w3/m317).
- Rollback already does this in one write: `RollbackOptions.DisableAutoDeploy` (`deploys/rollback_config.go:36-40`), applied inside `openSelectedRelease` (`:132`), recorded by `RecordAutoDeployDisabled(…, core.AutoDeployReasonRollback)` (`deploys/service.go:1331`).
- `TriggerParams` (`deploys/service.go`) carries `CommitID`, `ImageURL`, `BuildID`, `DeployMode`.
- Render (render.com/docs/deploys § Manual deploys, read 2026-11-16): "Deploying a specific commit through the Dashboard or a deploy hook disables auto-deploys. The CLI and API don't."

## Steps

1. Add `AutoDeployReasonManualDeploy = "manual_deploy"` beside the other reasons and correct the comment above them.
2. Add `DisableAutoDeploy bool` to `TriggerParams`; honor it only together with a `CommitID` (refuse it otherwise with a named 400, since Render ties it to a specific commit).
3. Set `spec.autoDeploy = false` in the release write the trigger already makes, and record the event once, only when auto-deploy was on (no event for a service already off).
4. Unit-test: flag + commit on an auto-deploying service → one write, `autoDeploy` false, one event with `manual_deploy`; flag on a service already off → no event; no flag → unchanged.
