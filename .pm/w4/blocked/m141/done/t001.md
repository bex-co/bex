## Objective

Make static-site rollback real, or make its absence explicit. Read `lego/operator/internal/publish` and the deploy row: a no-build publish is keyed by revision (`<app>/<revision>/…`, ADR029), so the earlier revision's objects may still exist and the static-server could be pointed back at them. If so, record that revision as the rollback target and let `RollbackEligible` accept it for static sites. If not, make the capability answer a named precondition (for example `static_rollback_unsupported`) that the UI explains.

## Acceptance criteria

- [ ] On a throwaway no-build static site with two deploys of different commits, rollback to the earlier one serves the earlier bytes (curl), **or** the control is disabled with the named reason.
- [ ] The rollback and Restart dialog copy matches the static-site behavior (no "image" or "instances" for a no-build site).

## Result (2026-09-27)

**Decision: real rollback.** A no-build publish is a clone of the repository at a commit (ADR029, `internal/publish` `clone` path), and the commit-pinned trigger ("Deploy a specific commit") already republishes a commit. `RollbackEligible(app, deploy)` now also accepts a live or deactivated deploy of a `static_site` with a repo, no `ResolvedImage`, and a recorded commit (`rollbackRepublishes`). `RollbackActionable` refuses the live deploy whose commit is `spec.buildCommit`. `Rollback` routes such a target through `triggerFetched` with `CommitID: target.Commit`, recording the row with `CreateRollbackDeploy` (`trigger: rollback`, `rollbackOf`, the target's commit). Image-backed and built static sites are unchanged. Copy: the static rollback dialog now reads "The site will be published again from this deploy, <sha subject>." and the static Restart dialog reads "<name> is published again from the commit it is serving now…" (no image or instances). The Control section's "Clear build cache & deploy" is now offered only on repo-backed services. Live curl proof on a throwaway static site is part of t007.
