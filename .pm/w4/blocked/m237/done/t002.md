## Objective

The Log Explorer stops pausing live tail for the views the store producer now serves: HTTP Requests (with its structured filters) goes live over the subscribe stream, and the subscribe URL carries those filters so streamed lines match the history rows they merge with.

## Context

- `dashboard/src/features/logs/types.ts`: `usesStoreOnlyFilters` / `storeOnlyFilterKey` gate `liveSupported` in `components/log-viewer.tsx`.
- `dashboard/src/features/logs/hooks/use-live-logs.ts`: `subscribeUrl` sends resource/type/text/textMode/instance/startTime only — the structured request filters never reach the stream.
- The new live-supported predicate must mirror the server's acceptance exactly: request-typed queries (any structured filters) and unfiltered app/all queries are live; store-only filters over app lines still pause the tail.

## Steps

1. Replace the store-only live gate with the mirrored acceptance predicate; keep the reader-identity semantics (a filter change clears the previous query's lines).
2. Send the structured filters on the subscribe URL for the views the producer honors.
3. Live status copy stays truthful: request lines stream; nothing claims a view is live while it only refreshes on the range clock.

## Files

- `dashboard/src/features/logs/types.ts`, `components/log-viewer.tsx`, `hooks/use-live-logs.ts`

## Acceptance criteria

- [ ] HTTP Requests + Live tail subscribes (no paused-tail fallback) and shows new lines as they stream.
- [ ] A status-code/method/path filter narrows live request lines identically to history.
- [ ] A level filter over app lines still pauses the tail (server refuses it).

## Out of scope

- The range refetch itself (it stays the history mechanism).

**Done 2026-10-19 (loopx w4).** `liveTailUnsupported` in `types.ts` mirrors the server acceptance (request views live with any structured filters; store-only filters over app lines still pause). `useLiveLogs` sends the structured filters on the subscribe URL (`requestFilters` — a `Pick<LogFilters,...>` slice of the one filter state) and folds them into the subscription identity inside the hook; the viewer passes its filter state through. Comments that claimed the tail cannot serve request logs are corrected in types, log-viewer and the hook.
