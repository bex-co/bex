## Objective

Before changing anything, record which value a rollback of a prebuilt-image service puts in `spec.releaseConfig.image`, where the target deploy's original reference (`store.Deploy.Image`) and resolved one (`ResolvedImage`, `ImageSHA`) live, and how the operator turns a tag into the digest it runs.

## Context

- `deploys/rollback_config.go:46` and `:84` select `target.ResolvedImage`.
- `store.Deploy` (`lego/backend/internal/store/store.go:380-392`): `Image` (as deployed), `ResolvedImage`, `ImageSHA` (w8/m122).
- `rollout.SelectServedImage` (`lego/backend/internal/rollout/served_image.go`) and blocked w4/m418 select the served image for configuration-only releases. m418's README warns against selecting a digest blindly (`image_network.go:211`, `reusableImageNetwork`). That release reruns the running image, which is Render's rule for configuration changes, not for rollbacks.
- The operator resolves and verifies the image's OCI config (w6/095).

## Findings (2026-11-16, loopx worker)

- **Selection path.** `deploys.Service.Rollback` → `rollbackFetched` (`lego/backend/internal/deploys/service.go:1273`) → `targetReleaseConfig` (`rollback_config.go:45`) put `target.ResolvedImage` into `spec.releaseConfig.image`, with `SourceGeneration` = the target's generation. `openSelectedRelease` then opens the row through `CreateRollbackDeploy` (`store/store.go:2973`), which stamps that image as both `image` and `resolved_image`.
- **Stored fields.** `store.Deploy.Image` is the reference the deploy was created from: `spec.image` or the `imageUrl` override for a prebuilt image (`deploys/service.go:986-993`), `""` for a repository build, and the selected image for a rollback, restart or config-change row. A digest-pinned deploy keeps `…@sha256:…` in `Image`. `ResolvedImage` and `ImageSHA` are overwritten on the live close from the operator's `status.image` and `status.imageDigest` for the row's own generation (`store/reconciler.go:1067-1085`, `TransitionDeploy` `COALESCE`).
- **Operator resolution.** `reusableArtifactImage` (`release_identity.go:721`) takes `ref.Image`. For an image-port service, `resolveImageNetwork` (`image_network.go:234`) re-reads a tag once per release (`reusableImageNetwork` reuses only the same revision) with the service's bound credential (`externalImageCredentials`, w4/m301), and pins `repo@digest`. A refusal goes to `failBeforeDispatch` (ImagePullFailed, the serving release held, w32/m419). A transient error waits (w32/031). A configured-port service runs the tag with `imagePullPolicy: Always`.
- **No security binding.** Cosign admission (`internal/webhook/pod_admit.go:41-55`) verifies only images in the platform registry (`BEX_REGISTRY`), which are bex's own builds. External registry images carry no bex signature, so nothing is bound to the recorded digest. The milestone does not stop for sign-off.
- **The m418 trap does not apply.** It concerns a `SourceGeneration: 0` digest selection. A rollback keeps `SourceGeneration > 0`, so `undeployedChangesReason` reads `historical_release`, and `releaseImageSource` records the tag the network resolved from.
- **Constraint for t002.** Keep `ResolvedImage` for a platform-registry reference (a source build's `gen-N` tag is mutable across incarnations, ADR004) and for Restart.
