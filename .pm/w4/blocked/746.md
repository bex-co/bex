# The user decides whether every workspace gets a GDPR DPA and compliance documents on a Documents page, as on Render, and ADR018 records the answer

Why: Render parity. Render's Compliance and Documents page gives every workspace a SOC 3 report and a GDPR Data Processing Agreement, and Pro workspaces more. bex has no such page, and the "non-goal" two bex documents give it cites a `DO_NOT_DO.md` line that does not exist.

- **Render (read 2026-11-27):** [certifications-compliance](https://render.com/docs/certifications-compliance): every workspace can download the SOC 3 report and the GDPR DPA from the dashboard's Compliance and Documents page; Pro and higher add the SOC 2 Type 2 report, the ISO 27001 certificate and the security policy under NDA.
- **bex:** `dashboard.bex.co/documents` has no page. [dashboard-routes.md](../../docs/render-artifacts/dashboard-routes.md) lists `/documents` among "non-goals (… compliance docs — `.pm/DO_NOT_DO.md`)", but `DO_NOT_DO.md`'s managed-infra line names only SSO/SAML, SCIM, maintenance runs and dedicated outbound IPs. [ADR030](../../docs/ADR030-pricing.md) calls the certifications a "Commercial term, not a product surface", with no user sign-off and no ADR018 row. bex.co's privacy policy does not mention a DPA.
- **Do:** ask the user two questions: does bex offer every workspace a DPA (and which audit reports, if any, it has or will obtain), and should the dashboard have Render's Documents page for them? Record the answer as an ADR018 row (built, or a divergence with the user's sign-off), correct `dashboard-routes.md`'s citation, and file the page if the answer is to build it.
- **End state:** ADR018 has a compliance documents row with the user's decision, and `dashboard-routes.md` cites it instead of a missing `DO_NOT_DO` line.
- **Size:** about 20m after the decision; the page itself is its own item.
