## Objective

Whenever a writer adds a group's refs to a service, it inserts them at the group's place in creation order, not at the end. `spec.envFromSecrets` and `spec.filesFromSecrets` then list linked groups oldest-created first, so the newest-created group is last among the groups and wins. The service's own Secret is still placed last by the operator (ADR013 rule 1).

## Context

- Probes and mechanism: [README § Finding](../README.md#finding-round-247).
- The three writers that append today:
  1. `rollLinked` link branch (`lego/backend/internal/envgroups/service.go:1194-1195`, `addString` at `:1824-1829`), reached through `linkFetched` by `LinkService` (`:1047`), `LinkEnvGroup` (`:1584`), `apps/deploy.go:1224`, `apps/blueprint_build_sources.go:380` and `apps/build_sources.go:250`;
  2. create-time links (`lego/backend/internal/envgroups/initial_links.go:103-104`);
  3. staged links for gated services (`rollout.StageGroupLink` → `refDelta.apply`, `lego/backend/internal/rollout/grouplinks.go:60-68`, `:106-128`).
- The creation time is `store.EnvGroup.CreatedAt` (`lego/backend/internal/store/envgroups.go:55`). The writers already hold the group row, or can read it in the same mutation.
- Ids are xids (`lego/backend/internal/id/id.go:179-183`), which are k-sortable. Still, use `CreatedAt` with the id as tie-break, since a deterministic id (`id.go:187`) carries no creation time.
- `spec.envFromSecrets` may also carry non-group refs. Reorder only `evg-*-env` / `evg-*-files` entries among themselves, and keep every other entry's position.

## Steps

1. Add one helper in `rollout` (or `envgroups`), e.g. `InsertGroupRef(list []string, ref string, created func(gid string) (time.Time, bool)) []string`. It places `ref` after every group ref whose group is older, and before every newer one.
   - A group whose creation time cannot be read (deleted, or a read error) keeps its current position.
   - A missing time must never fail the link.
2. Use it in all three writers. `refDelta.apply` needs the creation-time lookup at fold time. Pass it in, or have `FoldStagedGroupLinks` callers supply it, so that a staged link folds into creation order too.
3. `linkedEnvGroupIDs` (`lego/backend/internal/apps/service.go:6411-6420`) keeps reporting spec order. It now is precedence order by construction.

## Acceptance criteria

- [ ] Unit: linking A (older) after B (newer) yields `[A-env, B-env]`. Unlink A then relink A → still `[A-env, B-env]`. The same holds for `filesFromSecrets`.
- [ ] Unit: a staged link of A on a gated service, folded by the next release, yields `[A-env, B-env]`.
- [ ] Unit: a non-group ref keeps its position, and a group whose `CreatedAt` is unreadable keeps its place without an error.
- [ ] The existing w2/m94 precedence tests still pass: the service's own value beats every group, for env vars and files.

## Result

- **2026-11-14 (worker4):** done. One helper pair in `lego/backend/internal/rollout/grouplinks.go`: `SortGroupRefs` sorts only well-formed `evg-*-env`/`evg-*-files` refs, within the slots they hold, so every other ref (the service's own `<name>-files`, legacy refs) keeps its position; `InsertGroupRef` replaces the append. Used by `rollLinked` (every link path: `LinkService`, `LinkEnvGroup`, Blueprint/deploy/build-source links, create-with-services), `WithInitialEnvGroups`, and staged links through `EffectiveGroupSecrets`/`PrepareGroupRefsForRelease`. `linkedEnvGroupIDs` is unchanged and now reports creation order by construction.
- **Deviation:** creation order is the group **id's** order, not a `CreatedAt` read. Both env-group mint paths use `id.New(id.EnvGroup)` at the same instant they set `CreatedAt`, and an xid string sorts by its creation second, then machine, process and counter (the tie-break). This keeps the release fold in `Snapshot.Stamp` pure (it has no store handle) and gives one rule on every path, so a release can never reorder what a link wrote. No env group has a deterministic id, so an "unreadable creation time" cannot arise; a malformed ref keeps its place.
- Tests: `rollout/grouplinks_test.go` (link order, unlink and relink, files, non-group refs, staged fold) and `envgroups/creation_order_test.go` (LinkService B then A, unlink and relink, gated staged links, `WithInitialEnvGroups`, own Secrets untouched). All fail with the old append.
