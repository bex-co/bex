## Objective

Find every env-group write that changes a gated service's `envFromSecrets`/`filesFromSecrets`, and route each one through t001's staging. Then verify the behavior per resource type.

## Context

- `UnlinkService` (`envgroups/service.go`, after `rollLinked`) is documented as "drop the group's Secret refs from the service, roll it".
- `DeleteEnvGroup` → `detach` does a bulk unlink over every linked service.
- Group secret files are linked through `FilesFromSecrets`.
- Types: web, private, worker, cron and static. `EnvFromSecrets` is in the release identity for every type (`release_identity.go:207`).

## Steps

1. Grep every writer of `EnvFromSecrets`/`FilesFromSecrets` in `lego/backend`. Paste the count and list them in this task.
2. For each writer, decide whether it is gated and staged, or deliberately rolls, and state why. For example: unlinking a group whose values must stop applying may be a security-relevant removal, so say whether removal waits too.
3. Add a regression test per writer on a gated service: no release identity change and no deploy row.

## Acceptance criteria

- [ ] An enumerated writer list, each with its decision.
- [ ] Tests for link, unlink and delete on gated web and static services.

## Out of scope

- Auto-Deploy-on behavior.

## Outcome (2026-10-21)

Writers of `EnvFromSecrets`/`FilesFromSecrets` in `lego/backend`: `envgroups` create-with-services (`CreateEnvGroup`), `linkFetched`, `detachFetched` (unlink and group delete), `initial_links.go` (create-time, App not yet existing, ungated), and `secrets/files.go` + `secrets/batch.go` (the service's own file Secret, through `Rollout.PatchLocked`, recorded). The first three route through `rollLinked`; a gated service stages all of them, removal included (a deleted group is safe: group Secret sources are optional and each release serves an immutable snapshot). Tests: link/unlink and detach (group delete) on a gated service in `autodeploy_gate_test.go`; the types are one code path (`EnvFromSecrets` is identity for all).
