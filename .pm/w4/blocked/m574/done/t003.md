## Objective

In canonical mode, VKILL (Ctrl-U by default) erases the pending line, and its echo follows ECHO, ECHOK, ECHOKE and ECHOE as in Linux's `eraser()`. Typing `abc`, Ctrl-U, `def`, Enter then reads `def\n`. Today gVisor queues the byte and, since w4/m545, echoes it as `^U`.

## Context

- Linux `drivers/tty/n_tty.c` `eraser()`, KILL branch:
  - Without ECHO, the line is dropped silently.
  - If any of ECHOK, ECHOKE or ECHOE is clear, the line is dropped and the KILL character is echoed (`^U` under ECHOCTL), followed by `\n` when ECHOK is set.
  - With all three set (Linux's default `tty_std_termios`), each character is visually erased as VERASE does with ECHOE. Control characters shown as `^X` take two columns, and tabs need care.
- VKILL needs no IEXTEN. `n_tty_receive_char_special()` handles ERASE, KILL and (with IEXTEN) WERASE through `eraser()` only when `icanon` is set.
- gVisor (fork `bex/echo-signal-chars`): the VERASE/VWERASE erase loop (~:640-735) already handles UTF-8 continuation bytes and ECHOCTL widths. Extend it with a kill type instead of writing a second loop. Its existing "Not implemented" branches (ECHOPRT, `-echoe`, tab) also matter for VKILL's visual erase: implement what VKILL needs or leave each as an explicit known difference.

## Steps

1. Add the VKILL case, guarded by t001's disabled-character helper.
2. Add syscall tests in `test/syscalls/linux/pty.cc`:
   - The default flags read `def\n` and echo `abc` erased.
   - `-echoke` echoes `^U` then `\n` (with ECHOK on).
   - `-echok -echoke` echoes `^U` alone.
   - `-echo` drops the line silently.
   - A noncanonical PTY queues `\x15` unchanged.

   Take the exact echo bytes from the native run.
3. Run them natively, on runsc, and on runsc with the fix reverted.
