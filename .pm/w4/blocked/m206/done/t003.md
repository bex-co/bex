## Objective

Make the serial full-replace group move report a consistent or explicit recoverable outcome; reconcile actual source/target placement before another write and remove selections that have left the canonical source.

## Context

- setResourceMembers mutates each group then returns immediately on a later failure.
- Desktop timed out with a split and one source row/Selected:2; mobile timed out but eventually moved both.

## Steps

1. Define owned compensation or explicit partial-outcome handling that survives a superseding writer without overwriting it.
2. On an uncertain mutation result, read source and target after older active reads settle; mark reconciliation pending and block another Move until authoritative state resolves.
3. Prune only departed canonical membership IDs on ready data; preserve hidden-by-search selections and give a failed placement read a read-only retry.

## Acceptance criteria

- [x] Settled normal move has both target IDs, empty source and no source selection.
- [x] A failure after the first write is not presented as unchanged placement; remaining selections match ready canonical membership.
- [x] The observed filtered-select-all control continues selecting both after clearing search.

## Out of scope

- Unspecified distributed atomicity, blind mutation retry, global Apollo policy changes and clearing selection using filtered or transient-loading rows.

Done 2026-10-13: Backend: `setResourceMembers` records which members it changed and, when a later change fails, answers `ENVIRONMENT_MEMBERSHIP_PARTIAL` (409) with `changedIds` and `failedId`; the internal cause is logged, not returned; a failure before any change keeps its own error. Earlier changes are not compensated — the outcome is explicit and recoverable by retrying the same replacement, not atomic. A GraphQL mutation that exhausts the execution budget now answers `WRITE_OUTCOME_UNKNOWN` instead of `QUERY_TIMEOUT`'s narrow-and-retry advice. Dashboard: `useSetEnvironmentEnvGroups` re-reads Environments and EnvGroups after a failed write and stays busy until that read settles (a failed read warns, and its retry only reads); `EnvironmentCard` counts, moves and passes down only selections whose resource is still in the environment, judged against full membership so search-hidden rows stay selected; `createGroup` re-reads the group list after a failed create.
