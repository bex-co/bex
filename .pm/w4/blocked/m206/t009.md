## Objective

A native clone of the recorded small group returns its actual created ID inside the existing 25s GraphQL budget. Remove redundant create-admission metadata work while retaining the CAS name claim, quota semantics, source snapshot lock and deletion fences. This is m206's remaining shared create-path timing work, not a new timeout protocol.

## Evidence and cause boundary

[Durable a633 receipts and executable probe](evidence-a633-clone.json), 2026-10-15, main `c11f86235`: two native CloneEnvGroup requests returned WRITE_OUTCOME_UNKNOWN; the second measured 25.223s. The first clone committed and the second was absent in settled inventories. The same source's REST clone succeeded in 24.772s; a later empty create used 24.035s. The source had two small variables and two files, including empty entries.

The confirmed extra work is in `createEnvGroupAuthorized` (`lego/backend/internal/envgroups/service.go:520,537`): quota and name admission each enumerate and resolve metadata. Clone enters this core at `clone.go:113`. `DeleteEnvGroup` deliberately replants a non-editable fence (`service.go:921–950`), so historical IDs remain discoverable through `tenant.go:120–161`. A local overlay probe used real create/delete calls against the repository fake: with one active source and 0/20/100 retired groups, scoped clone metadata Gets grew 7/87/407 (unscoped: 3/43/203). The clone and no-link guarantees passed.

**Production stages and retired-entry counts were not measured.** The probe proves repeated history-dependent reads, not that those reads alone consumed the production 25s. Profile before claiming the complete cause. t001's completion note already says its name sweep was untouched and may dominate; the owner-only environment lookup is bypassed by this Workspace-scope control.

## Steps and acceptance

1. Capture value-free stage timings on a controlled local fixture for authorization, source-lock work, quota, name claim, persistence and response hydration. Re-run the preserved probe in workspace and legacy modes. Do not add production load or inspect foreign contents.
2. Share one fresh, correctly scoped metadata discovery/read snapshot between create quota and the legacy-name compatibility check, leaving the CAS name reservation authoritative. Confirm timing first; if another stage dominates, revise the scoped fix with that evidence. A single admission must not resolve each historical ID independently for both checks. Preserve the existing best-effort quota contract, real duplicate-name conflicts, concurrent-create behavior and the delete/recreation fence; deleting fences or globally raising deadlines is not an acceptable shortcut.
3. Audit all **six** production `listGroupIDs` consumers: `listScopedMeta`, `GroupIDsByName`, `findGroupByName`, `groupsNamed`, `envGroupQuota`, and `WorkspacePurger.PurgeWorkspace`. There are **three** direct `claimGroupName` callers: create, rename and new Blueprint group creation. Prefer the create-only change; preserve the other consumers and never make purge omit tombstones it must remove.
4. Repeat the closing checks for this delta without reopening completed t005–t007: meaningful behavioral/read-count regressions across retired history, live/legacy metadata, true conflict, concurrent writes, source-lock recovery and failed-name recovery; simplify; verify REST `POST /v1/env-groups` and `POST /v1/env-groups/{id}/clone`, GraphQL create/clone and MCP create_env_group/clone_env_group retain the same response and error semantics. Keep WRITE_OUTCOME_UNKNOWN for genuine uncertainty and the 25s/30s transport margin.
5. Replay the recorded native clone from fresh desktop and 390px views: one click returns a new ID within budget, once in the owner inventory, with exact values/files and no copied service links. An independent clone edit leaves the source service unchanged; linking the clone delivers that edit and its files. Clean all owned fixtures and revoke only the QA session. Feed dated receipts into t008.
