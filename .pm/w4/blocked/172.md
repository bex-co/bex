# Cron suspend and resume copy describes a stopped web service

Why: a customer using Suspend to stop a cron command is told it stops running, although the supported operation pauses future scheduling and lets the current execution finish.

**Severity:** minor (misleading lifecycle copy). **Estimate:** 55m. **Source:** live `$qa-find-bugs`, 2026-10-02, muse sweep 4, filed to w4 as requested. **Goal:** accurate hosting controls under ADR008/ADR038. This is a dashboard wording fix; preserve the existing runtime contract.

## Reproduction and observed result

Create a free Go cron from `https://github.com/bex-co/bex`, branch `main`, root `examples/cron-demo`, build `go build -o app .`, command `echo qa-20261002-r4-start; sleep 45; ./app`, schedule `*/2 * * * *`, auto-deploy off. Fixture: `srv-davmb1k5o9vs73dt7o10`, workspace `tea-d98210cbbpdc73dcrkvg`.

1. Open Settings while a scheduled run is active. The Suspend card says it will “shut it down and stop it from running.” Its confirmation says “The service scales to zero and stops running. You can resume it at any time.”
2. Accept Suspend at **08:09:28 UTC**. The schedule becomes suspended; the existing container continues from **08:09:20 to 08:10:05**, exits 0, and its run `crr-8vs12061u30hb6rhkogu` becomes successful. No new Job starts at the suspended 08:10 tick.
3. While suspended, the Resume card says it will “start serving traffic again,” although this cron has no serving URL.
4. Resume, then **reload Settings** and repeat. At **08:10:47** the fresh confirmation has the same text. Suspend is accepted at **08:10:58**; the scheduled container runs **08:10:33–08:11:18**, exits 0, and `crr-pdpsjv3jlsmkovrn672v` becomes successful.
5. At **08:13:10**, Overview → this resource's actions → Suspend shows the same false scale-to-zero confirmation. Dismissed without another mutation.

The operator behavior is correct under [ADR038](../../../docs/ADR038-cron-jobs.md): service suspension pauses the schedule, not existing Jobs. This finding does **not** request that Suspend terminate active jobs. The existing per-run Cancel action is how a customer requests termination.

Evidence: `.playwright-mcp/qa-cron-r4-suspend-copy.png`, `qa-cron-r4-row-suspend-copy.png`, `qa-cron-r4-evidence.json`, and `qa-cron-r4-runtime.jsonl` / `qa-cron-r4-runtime-summary.json`. All paths are under `.playwright-mcp/`. The following exact API record is retained here because those artifacts are local and ignored.

## Root cause and bounded fix

Research baseline: `1287ee5bf`, including current origin/main; no intervening fix to these components or keys.

- `dashboard/src/features/services/components/suspend-service-card.tsx:65,119–124,164–167` chooses suspend copy only by `publiclyRoutable` and uses one unconditional resume description. That predicate correctly classifies cron as non-public, but non-public does not mean a continuously running process.
- `dashboard/src/features/services/components/service-row-actions.tsx:56–70,233–237` repeats the same public/non-public selection for the row confirmation.
- The selected English strings are `features/services/locales/en.ts:336–340,2756–2760,2767–2770`; Chinese counterparts are `locales/zh.ts:329,2700,2710`. `ConfirmDialog` accepts the supplied description as a React node; no transport or serializer change is needed.
- The contract is explicit in `docs/ADR038-cron-jobs.md:28,39`. Backend `lego/backend/internal/apps/service.go:4316–4318` writes only suspension intent. Operator `lego/operator/internal/controller/app_controller.go:3771–3782` pauses the CronJob schedule; `:3725–3729` describes the resulting state as “cron schedule suspended.” Existing jobs are not canceled by that operation.

**Implementation task (25m):** add cron-specific suspend-card, confirmation, and resume wording in both locales. Suspend should say future scheduled runs are paused, an active run continues, and Cancel in Recent Runs stops it. Resume should say scheduling resumes. Use the existing cron type predicate and keep the shared public/private/worker/static wording choices scoped; do not globally replace the non-public string with cron semantics.

**Blast-radius task (15m):** cover both consuming components. `SuspendServiceCard` has one production caller, `routes/services.$serviceId.settings.tsx:438`; static Settings delegates to that route component. `ServiceRowActions` has one production caller, `features/projects/components/resource-table.tsx:342`. That ResourceTable is used in exactly three production components: Overview `routes/index.tsx:285`, `features/environments/components/environments-panel.tsx:323`, and `environment-card.tsx:379`. The latter two reach project/environment resource lists. `common/lib/render-alias.ts:12–20,58–70` sends `web/worker/pserv/static/cron` aliases to the service family, preserving the suffix; the actual resource type must choose copy. Database and Key Value use separate action components. Require focused regression coverage that cron copy reaches both consumers and web/private/worker/static controls retain their appropriate semantics; do not change the global predicate or generic dialog.

**Verification task (15m):** repeat the live clicks above, run the relevant dashboard checks, and review the final diff with Simplify. REST/GraphQL/MCP semantics remain unchanged. [Render's cron documentation](https://render.com/docs/cronjobs), checked 2026-10-02, documents manual replacement and single-run behavior but does not establish suspension behavior; do not claim verified Render suspension parity. Bex's documented schedule-only contract is the target.
