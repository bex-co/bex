## Objective

Make saved header patterns select the documented request paths in both normal and resolved-error responses.

## Context

The full reproductions and API captures are in [finding.md](../finding.md). `staticserver.go:482–497` implements route capture matching, which cannot match `/*.yaml`, `/**/*.yaml` or `/**/*`. Both header consumers reuse it.

## Steps

1. Specify a bounded header matcher using the Render table: exact paths; `/*` all; subtree `/blog/*`; `/**/*` nested paths including a trailing directory slash; `/*.css` root files only; `/**/*.css` nested files only. Treat the root/nested distinction explicitly, rather than inheriting zero-directory globstar behavior accidentally.
2. Use the header matcher from both `applyHeaders` and `applyErrorHeaders`. Keep routes and `expandDest` on their existing contract.
3. Preserve request-path normalization, ordering/last-matching-name behavior, the 100-rule/2048-path limits, and bounded public-request work. Do not introduce filesystem interpretation, backtracking regex, an upstream fetch path or a new route grammar.
4. Verify the failing cases and the same-rule exact control after the new catch-all marker proves snapshot refresh. Configuration saves must not republish the site.
