## Objective

Prove on production that a restart no longer ships an undeployed port or shutdown-delay change.

## Context

- Production `bex-canary`, an owned free web service on a small fixture that logs its port and its SIGTERM time, deleted afterwards (by-id `GET` 404).

## Steps

1. Save a new port and shutdown delay without deploying; restart: the instance still listens on the old port and the old delay applies; the undeployed notice remains.
2. Deploy: the new values apply and the notice clears.
3. Roll back to the first deploy: the old values run again; saved settings still read the new ones.
4. Record ids and the pin here; delete the service.
