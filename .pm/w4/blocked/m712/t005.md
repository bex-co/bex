## Objective

Prove the boundary in envtest and on production. A `frankfurt` and an `oregon` resource in the same workspace cannot reach each other privately, two `frankfurt` ones can, and no pod restarted.

## Context

- `make verify-tenant-isolation` checks NetworkPolicy reachability (ADR041 notes it).
- `bex-canary` is a first-party workspace. Disposable resources there are created and deleted by id, with a 404 proof, and marked `(disposable)` on the board.

## Steps

1. Add envtest cases for the policy set across region, environment, isolation and pod kind.
2. Deploy to production. In `bex-canary`, create these resources (disposable):
   - two private services in `frankfurt`;
   - one private service in `oregon`;
   - a Key Value instance in `frankfurt`.
3. Check reachability by internal address, by pod IP and by Key Value internal URL, from each service. Compare pod UIDs from before and after the operator upgrade on one existing first-party service.
4. Delete the disposable resources and record the 404s.

## Files

- `lego/backend/internal/store/*_test.go`
- `.pm/w4/m712/README.md` (record)

## Acceptance criteria

- [ ] envtest covers every case in the definition of done.
- [ ] The production record shows the refused and admitted connections and the unchanged UIDs.

## Out of scope

- A Postgres in the production check, when Key Value already proves the datastore path.

If a first-party site fails, revert the code commit at once (`git revert`, ship it alone) before anything else.
2. **Unchanged UIDs.** Compare with the pods recorded before the upgrade (README, Production check baseline). A changed UID must be explained by that service's own deploy or restart event.
3. **Fixtures in `bex-canary` (disposable),** with a QA session (`scripts/qa-login.sh`) and a run-minted key (`scripts/qa-mcp.py mint-key`, `rest`): a Key Value `w4-m712-kv` with `region: frankfurt`; a Starter private service `w4-m712-fra-a` with **no** region (it reads back `frankfurt`); a Starter private service `w4-m712-ore` with `region: oregon`; and a Starter private service `w4-m712-fra-b` with `region: frankfurt`. Image `docker.io/library/busybox:1.37`; each serves `httpd -f -p 10000` and the two probers loop `nc -z -w 3` against the others' internal addresses (`<slug>:10000`), the pod IP their `<slug>-discovery` name resolves to, and the Key Value's internal host on 6379, printing `open`/`refused`, read back through `GET /v1/logs`. 5. Delete each fixture by id and record the 404s; revoke the key and log the session out.
