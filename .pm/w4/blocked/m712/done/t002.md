## Objective

Every App pod carries the region label that t001 designed, with the value from the App's region, and running pods get it without a rollout. Covered: a service's pods, a cron job's run pods and a pre-deploy pod.

## Context

- The App CR's `app.bex.co/region` annotation is written at creation (`lego/backend/internal/apps/service.go:2664,3000`) and never changed afterwards.
- Pod labels:
  - `lego/operator/internal/execution/security.go:47` (execution labels);
  - `lego/operator/internal/predeploy/predeploy.go:283` (pre-deploy);
  - the App's Deployment and the cron run Jobs in `lego/operator/internal/controller/`.
- In-place relabel: `relabelPodsInPlace` (`lego/operator/internal/controller/environment_network_policy.go:114`), as `LabelNetworkIsolation` does.

## Steps

1. Derive the label from the App's annotation, using t001's rule for an App without one.
2. Put it on pods created from now on, in a way that does not change an existing Deployment's pod template hash. If that is impossible, apply it in place as `LabelNetworkIsolation` does.
3. Relabel running pods in place on reconcile.

## Files

- `lego/operator/internal/controller/*.go`
- `lego/operator/internal/execution/security.go`, `lego/operator/internal/predeploy/predeploy.go`

## Acceptance criteria

- [x] A new service's, cron run's and pre-deploy's pods carry the label.
- [x] After the operator upgrade, an existing service's pods carry it with unchanged pod UIDs.

## Out of scope

- Build pods. Render's private network is for services, and bex's build pods leave through egress (w4/741).
