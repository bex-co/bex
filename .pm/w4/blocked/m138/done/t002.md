## Objective

Render the backend's per-resource classification in `BlueprintPlanSummary`, used by both the New Blueprint review step and the Sync dialog, so a user can tell create from update from no-change before applying.

## Context

- `dashboard/src/features/blueprints/components/blueprint-plan-summary.tsx`: name groups only, and `actions` is used just for `detach`.
- The fields are already fetched (`api/blueprints.graphql:100-110`) and mapped (`lib/views.ts:132`).
- The headline `blueprints.previewValid_*` uses `plan.totalActions`, which includes `noop`.
- Call sites: `routes/blueprints.new.tsx:369`, `routes/blueprints.$blueprintId.tsx:641`.
- Env groups plan conservatively as `update` because their values are write-only (`w6/m125` t002 decision). Show that honestly rather than hiding it.

## Steps

1. Group or annotate resources by `operation` (create / update / noop / detach), listing `changedFields[].path` for updates.
2. Headline: count non-`noop` actions. Zero reads as "no changes".
3. en + zh strings (`locale-parity.test.ts`).
4. Produce a live `update` case (for example, `validateBlueprint` with an edited copy of the fixture manifest) and paste the request/response here.

## Acceptance criteria

- [ ] An unchanged blueprint's Sync dialog says there are no changes.
- [ ] A create, an update (with field paths), and a detach each render distinctly.
- [ ] The existing detach alert keeps working.

## Result (2026-09-26)

`BlueprintPlanSummary` lists each action by the backend's `operation`, in the order create, update (with `changedFields[].path`), can't-apply (with its message), and no change, plus a resource kind label. An env group update notes that write-only values are always re-applied (the w6/m125 decision). The headline counts non-`noop` actions and reads "no changes" at zero. A plan without `actions` (an older API) falls back to the name groups. The detach alert is unchanged. en + zh. **Update-case evidence:** backend plan tests already produce `update` with changed field paths (`TestValidateBlueprintCurrentStateActionPlan`, `TestValidateBlueprintCurrentStatePlanPredictsStoreManagedApply` in `lego/backend/internal/apps/blueprint_test.go`). A live `update` probe on production is part of t007's re-probe (the fixture file cannot be edited from the dashboard).
