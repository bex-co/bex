## Implementation verdict — 2026-10-02

Audit (code-read, 2026-10-02). publishStaticRevision has four failure exits: credential validation (`StaticCredentialUnavailable`), clone-secret relocation, `publish.Ensure` error, and terminal Job observation. Only the terminal observation is a tenant publication verdict; the other three are setup/infrastructure and **keep `r.fail` → Failed** (no global healthy fallback; the other 52 `r.fail` and 5 `failStep` sites are untouched). The new path is allowlisted to terminal publication **and** `releaseHasServed` (ActiveRevision, not Status.Image — a direct publish has no image). Matrix: static (changed path only); web/private/worker/cron (never call publishStaticRevision; unchanged); Postgres/Key Value (separate controllers; unchanged). First publish (no ActiveRevision) → Failed as before. Suspension → `settlePriorRelease(parked = spec.suspended)` → Hibernated/Suspended; the resolver already excludes suspended sites, so no content is served. Persistence: ConditionRollout + Ready + phase ride one `updateStatusRetrying` write (conflict re-applies the whole status). Attribution: verdict stamped `releaseGeneration(app)`; bex-api's `recordedRolloutFailure` requires an exact match, so metadata churn (suspend/resume) keeps it readable and another release never reads it. Consumer order: `supersededDeployStatus` precedes `recordedRolloutFailure`, so a publish verdict whose release was superseded before bex-api observed it closes canceled — the same documented one-slot bound web rollouts already carry; not widened here.
