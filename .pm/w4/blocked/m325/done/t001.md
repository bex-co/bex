## Objective

Write down the exact request-log message Render shows and serves, so t002 builds to evidence: field names, order, quoting, time unit and the request-id key. Replace the unsigned divergence in ADR018 and ADR010 with that target.

## Context

- **What is known.** w8/176 cites Render's logging docs search example `/responseTimeMS=\d{3}\d+/`: the message is a `key=value` summary.
- **Which fields.** w5/099 trimmed bex's record to the fields Render documents (method, status code, host, path, response time) plus the request id (`Rndr-Id`).
- **The divergence to replace:** `docs/ADR018-render-parity.md:247` ("the request-log message is the raw JSON access line, not a rendered summary") and `docs/ADR010-observability.md:193`.

## Steps

1. Capture a Render request-log line, from Render's docs or a Render log stream or API sample, with its source URL. Store it in `docs/render-artifacts/`.
2. Update ADR018's row and ADR010 § request logs with the target line. Remove the divergence bullet.

## Acceptance criteria

- [x] A captured Render line and its source are recorded, and ADR018/ADR010 state the target.

## Result (2026-11-11)

- **Captured live from Render's API**, read-only `GET /v1/logs?…&type=request` on two web services in the reference Render workspace, plus `statusCode=404` and `method=POST` reads. Redacted and recorded in [`docs/render-artifacts/request-logs.md`](../../../../../docs/render-artifacts/request-logs.md).
- **Message:** `clientIP="<ip>" requestID="<id>" responseTimeMS=<int> responseBytes=<int> userAgent="<ua>"`. Method, status, host and path are not in it.
- **Labels, in order:** `resource`, `method`, `statusCode`, `host`, `path`, `level` (`info`, `warning` for 4xx, `error` for 5xx), `type`. There is no `requestID` label. An app line reads `resource`, `instance`, `level`, `type`.
- **Render's dashboard row** (docs): `11:24:03 [GET] example.com/api/orders clientIP="198.51.100.3" requestID="8ebfa3c3-8929-4885" ...`.
- **Static sites:** Render returned no request lines, as its docs say.
- ADR018's Request row and ADR010 § Request logs now state this target, and the "raw JSON access line" divergence is gone from both.
