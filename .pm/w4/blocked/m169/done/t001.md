## Objective

Make every by-id Blueprint verb find the Blueprint by id first, then authorize on the Blueprint's own workspace, as `envgroups.fetchGroup` does.

## Context

- `lego/backend/internal/apps/blueprint.go:1052` `GetBlueprintByID` and its siblings `ListBlueprintSyncs`, `UpdateBlueprint`, `DisconnectBlueprint` and `SyncBlueprint` call `s.Blueprints.GetBlueprint(ctx, id, resolveTenantID(ctx))`. They are scoped to `ownerId` or the default workspace.
- Pattern to mirror: `internal/envgroups/service.go:1667-1679` (`requireGroup` → `AuthorizeLabeled(relation, {tenant: m.workspace})`).

## Steps

1. Add a store lookup by id that returns the row and its `tenant_id`. If `ownerId` is supplied and disagrees, keep returning 404.
2. Authorize the relation on that tenant. Map "not a member" to the same 404 as missing (no existence oracle). Keep the `can_view_sensitive` manifest gate.
3. Apply this to all five verbs on REST/GraphQL/MCP (shared service functions).

## Files

- `lego/backend/internal/apps/blueprint.go`, `lego/backend/internal/store/` (blueprint lookup), `lego/backend/internal/apps/rest.go` if owner handling changes

## Acceptance criteria

- [ ] Each verb works without `ownerId` for a Blueprint in a non-default workspace the caller belongs to.
- [ ] A non-member id returns a 404 identical to a missing id.

## Out of scope

- List endpoints (they are workspace-scoped by design).
