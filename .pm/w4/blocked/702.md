# 702 — A service's Deploys tab grows ~260 px at 1440 (~480 px at 390) when its list loads: the loading state is three 56 px bars with no column header, where each ready row is a three-line ~83 px table row

Why: the dashboard rule ([AGENTS.md](../../../AGENTS.md), "Dashboard preloading skeletons must match their post-loading contents") asks a pending state to keep the ready panel's regions at stable heights. The Deploys card keeps its real title, search and status filter while it loads. Below them it draws three generic `h-14` bars, then swaps in a table with a column header and taller rows. Same class as [w4/684](../done/684.md) (the audit log) and w4/680/686.

- **Source / severity / estimate:** live `/qa-find-bugs w4` round 682, 2026-11-17 11:27–11:35 UTC, pin `6984548a30f8`, workspace `bex-canary`. Read-only on the canary `hello-go` (`srv-dbkq3hdhhjfs73eiahe0`, 5 deploys). **Minor:** a layout shift, and nothing is lost. ~40m.
- **Probe:** headless Chromium. Start on `/services/srv-dbkq3hdhhjfs73eiahe0/events` (at 390, open the sidebar), hold every `/graphql` request 4 s with a Playwright route, then click the sidebar's `Deploys` link. Read the `main` card heights 1.5 s after the click, and again 4 s after the hold is released.

  - No console error and no 4xx/5xx request.
- **Cause:**
  - `dashboard/src/features/deploys/components/deploys-list-page.tsx:172-178`: while `loading`, the body is `[0, 1, 2].map(… <Skeleton className="h-14 w-full" />)`. There is no `TableHeader` and no row geometry. The ready body (`:194-…`) is a `Table` with a `TableHeader` (`:195-208`, where Trigger and Duration show at `@3xl/deploys`) and three-line `TableRow`s (`:229-…`).
  - The count line (`:375-381`) renders only when `!loading`, so the search row also moves down ~2 px when it appears.
  - The first page is `PAGE_SIZE = 20` (`features/deploys/hooks/use-deploys.ts:20`).
- **Fix:**
  - Target behavior: while the first page loads, draw the ready table's frame.
    - The column header row, with the same container-query columns.
    - Placeholder rows at the ready row's three-line height.
    - The count line's slot, as a fixed-height placeholder.
  - Reserve `PAGE_SIZE` rows, as [w4/684](../done/684.md) did for the audit log (`AUDIT_PAGE_SIZE`). An active service fills its first page; a service with fewer deploys shrinks once, but the header and per-row geometry no longer jump.
  - Share the frame with the route skeleton `DeploysListSkeleton` (`common/components/route-skeletons.tsx:1847-1863`, `TableCardSkeleton rows={3} columns={4} controls`), so the route-level and in-view pending states match.
  - Add a test like w4/684's: the pending frame has the header cells and `PAGE_SIZE` rows at the row height.
- **Blast radius:**
  - `DeploysListPage` has one caller, `DeployHistoryView`. Three routes mount that view: `/services/$serviceId/deploys/` (web, private, worker), `/static/$serviceId/deploys/`, and `/services/$serviceId/builds` (a cron job's Builds page). The fix moves all three.
  - `DeploysListSkeleton` is the pending component of the first two.

  - The Environment shift's cause.

**2026-11-17 — code shipped; BLOCKED on the release gate (no user action).**

- **The frame.** While the first page loads, `DeploysListPage` keeps its real title, search and status filter, and draws `DeploysTableFrame` (`dashboard/src/features/deploys/components/deploys-list-frame.tsx`):
  - the shared `DeploysTableHeader`;
  - `DEPLOYS_PAGE_SIZE` (20) placeholder rows at a ready row's lines: the 22 px badge line, the text-sm commit line, the text-xs time line, and below `@3xl/deploys` the folded Trigger · Duration line. An image-backed service's rows draw no commit line;
  - the Load more slot, and `DeploysCountSlot` for the count line.
- **The route skeleton.** `DeploysListSkeleton` draws the same card (`DeploysListCardSkeleton`), titled Builds on a cron job's page.
- **One-line rows.** Each line of a ready row is now one line at any width. The id, the pre-deploy status and a rollback trigger truncate in a `minmax(0,auto)` grid track instead of wrapping, so the 390 rows no longer grow with the data, and the column is no wider than before.
- **Measured locally** (`local-bex` + Vite, held navigation from Events, a stubbed 20-deploy first page, both in-view and route pending):
  - 1440: the card is 1871.5 → 1871.5 px, rows 83 px pending and ready.
  - 390: 2391.5 → 2391.5 px, rows 107 px. Before the fix, the same 390 probe went 358 → 3327.5 px, with ready rows of 127–171 px.
- **Tests.** Four new cases in `deploys-list-page.test.tsx` fail without the fix. `yarn lint` and `yarn test` pass.
- **Remaining.** The next production deploy must pin the `w4/702` fix commit (`git log --grep 'w4/702' origin/main`, then `git merge-base --is-ancestor <sha> <deployed sha>`). Then a worker replays the held navigation at 1440 and 390 and closes this note.
- **Residuals, not in this fix.**
  - A service with fewer than 20 deploys still shrinks once (this note's chosen trade-off).
  - Failed, canceled and stalled rows add their one-line reason.
  - At 390 the ready table still scrolls sideways, because the commit line keeps a 16rem minimum. That was already so before this change.
