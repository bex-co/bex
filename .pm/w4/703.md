# 703 — A datastore's Metrics range is lost on reload and can't be linked: the Key Value, Postgres and Disk metrics keep the picked window in component state, where service Metrics and the datastore's own Logs tab keep it in the URL

Why: w6/065 moved the service Logs and Metrics ranges into the URL (`range`, `rangeStart`/`rangeEnd`), so a picked window survives a reload and can be shared with a teammate. A Key Value's or Postgres's Logs tab follows that rule too (`parseDatastoreLogSearch`). w7/072 (`b533aedd3`) then gave the datastore Metrics panel the same `RangeSelect`, but kept the picked range in `useState`. Picking "Last 4 hours" on a datastore's Metrics tab works until the page reloads; after that it is back to "Last 12 hours", and a copied link never carries the range.

- **Source / severity / estimate:** live `/qa-find-bugs w4` round 837, 2026-11-17 19:03 UTC, pin `e0a5ba20aac8`, workspace `bex-canary`. Read-only. **Minor:** a lost selection; the data is right. ~40m.
- **Probe** (headless Chromium at 1440, en):
  - `/keyvalue/red-dbpf5q5me2kc73f2l0og?tab=metrics` opens with `combobox "Time range"` reading `Last 12 hours`. Picking `Last 4 hours` makes it read `Last 4 hours`, but the URL stays `?tab=metrics`. After `page.reload()` it reads `Last 12 hours` again.
  - **Control:** `/services/srv-dbkq3hdhhjfs73eiahe0/metrics`, with the same pick, changes the URL to `?range=4h`, and after a reload it reads `Last 4 hours`.
  - No console error and no 4xx/5xx request.
- **Cause:**
  - `dashboard/src/features/metrics/components/datastore-metrics-panel.tsx:143` holds the range in `useState<RangeSelection>(DEFAULT_RANGE_PRESET)`, and `RangeSelect`'s `onRangeChange` is that setter (`:298-300`). No caller can pass a range in.
  - The service page threads the range through its route instead: `routes/services.$serviceId.metrics.tsx:36` declares `validateSearch: parseRangeSearch`, and `:46-52` passes `rangeFromSearch(search, DEFAULT_RANGE_PRESET)` with an `onRangeChange` that runs `navigate({ search: () => rangeToSearch(range), replace: true })`.
- **Fix:**
  - Target behavior: a datastore's Metrics range persists to the URL in the w6/065 shape (`range`, `rangeStart`/`rangeEnd`), exactly as service Metrics does. `?tab=metrics&range=4h` opens on "Last 4 hours", a custom window round-trips through `rangeStart`/`rangeEnd`, and a reload keeps it.
  - Give `DatastoreMetricsPanel` controlled `range`/`onRangeChange` props, keeping its current local state only as a fallback when no caller passes them.
  - Wire the props from each route through `rangeFromSearch` and `rangeToSearch`, using the functional `navigate` form as the service route does. That form is needed so that explicit undefineds clear stale custom bounds, the w7/m42 lesson.
  - The Key Value and Postgres routes already parse these keys for their Logs tab (`parseDatastoreLogSearch`). The tab links reset the search (`navigate({ search: { tab: "metrics" } })`, `keyvalue.$keyValueId.tsx` around line 165), so one tab's range never leaks into the other.
  - The service Disk route (`routes/services.$serviceId.disk.tsx`) has no `validateSearch` and needs `parseRangeSearch`.
  - Tests: per route, a `?range=4h` URL opens on that preset, a pick writes it, and a custom window round-trips.
- **Blast radius:** `DatastoreMetricsPanel` has three callers, and all three move:
  - `routes/keyvalue.$keyValueId.tsx:207`;
  - `routes/databases.$databaseId.tsx:308`;
  - `features/services/components/disk-section.tsx:183`, the service Disk tab.
- **Unverified:** I probed only the Key Value Metrics tab live. The workspace has no Postgres, and its Free services have no disk. The Postgres and Disk claims come from the shared component and its three call sites.
- **Render:** not checked, and the note does not rest on parity. It rests on bex's own rule (w6/065) and on the datastore Logs tab beside it.
- **Done when:** on production, picking `Last 4 hours` on a Key Value's Metrics tab sets `range=4h` in the URL and survives a reload, and `?tab=metrics&range=4h` opened fresh reads `Last 4 hours`. The service Metrics control keeps passing.
