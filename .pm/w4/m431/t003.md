## Objective

GraphQL `triggerDeploy` takes `disableAutoDeploy: Boolean = false`, the argument `rollbackService` already has, and the dashboard's **Manual Deploy → Deploy a specific commit** sends it in the trigger instead of calling `setAutoDeploy` afterwards.

## Context

- `deploys/graphql.go:284-290` is the `rollbackService` argument to mirror.
- `dashboard/src/features/services/components/manual-deploy-button.tsx:188-191` triggers with `commitId`, then calls `setAutoDeploy` when `service.autoDeploy !== false` (w1/m148 t002). A push landing between the two writes can still redeploy the branch head, and the event reads `setting_change`.
- `dashboard/src/features/services/hooks/use-trigger-deploy.ts` builds the mutation.

## Steps

1. Add the argument and pass it to `TriggerParams.DisableAutoDeploy`; regenerate `lego/backend/internal/api/testdata/schema.graphql`.
2. Send `disableAutoDeploy: true` from the specific-commit dialog and drop the follow-up `setAutoDeploy`; keep the dialog's sentence that the deploy turns auto-deploy off.
3. Update the dashboard tests that asserted two writes.
