# 365 — The API enables autoscaling on a Free service while the Scaling page says "Autoscaling off… available on paid plans"

Why: REST, GraphQL and MCP accept and report `autoscaling.enabled: true` for a Free web service, and Events records "autoscaling enabled". The dashboard's Scaling card (w7/048) shows it Off and disabled, so the stored config is invisible and cannot be turned off there. It goes live unannounced the moment the service moves to a paid plan.

**Source:** live `/qa-find-bugs w4` pass 305022, 2026-10-19 UTC, pin `108cdb3acca8`, workspace `bex-canary`. Owned Free image web service `qa-20261019-305022-scale` (`srv-dbatfohkv6rc73en2c70`), deleted afterwards (`DELETE` 204, then `GET` 404). Only that run's session was revoked. Every probe ran from inside the signed-in page.

## Probes

| Request on the Free service | Response |
| --- | --- |
| `POST /v1/services/{id}/scale {"numInstances":2}` | `400 the free plan is limited to 1 instance(s) and cannot scale to 2` (control) |
| `PUT /v1/services/{id}/autoscaling {"enabled":true,"min":1,"max":3,"criteria":{"cpu":{"enabled":true,"percentage":70},…}}` | `400 the free plan is limited to 1 instance(s) and cannot scale to 3` |
| the same with `"min":1,"max":1` | **`200 {"enabled":true,"min":1,"max":1,"criteria":{"cpu":{"enabled":true,"percentage":70},…}}`** |
| `GET /v1/services/{id}/autoscaling` | `200 {"enabled":true,"min":1,"max":1,…}` |
| GraphQL `server(id){plan autoscaling{enabled minInstances maxInstances targetCPUPercent}}` | `{"plan":"free","autoscaling":{"enabled":true,"minInstances":1,"maxInstances":1,"targetCPUPercent":70}}` |
| GraphQL `setAutoscaling(id, minInstances:0, maxInstances:1, targetCPUPercent:50)` | **`{"enabled":true,"minInstances":0,"maxInstances":1,"targetCPUPercent":50}`** |
| `GET /v1/services/{id}/events` | `autoscaling_config_changed {"previous":{"enabled":false},"current":{"enabled":true,"minInstances":1,"maxInstances":1}}` |
| `DELETE /v1/services/{id}/autoscaling` | `204`, then `GET` → `enabled:false` |

Meanwhile, `/services/{id}/scaling` (reloaded) showed `switch "Autoscaling off" [disabled]` with "Autoscaling is available on paid plans. Upgrade to enable it." (`.playwright-mcp/qa-scaling-1.png`, local to that session).

## Root cause

- `lego/backend/internal/apps/service.go:5413-5459` `autoscalingSpec` bounds the range by `checkInstanceCap(tier, …)` only. On Free (cap 1), every `min ≤ max ≤ 1` passes, and nothing refuses autoscaling for a Free tier. It has two callers, so one fix covers every entrypoint:
  - `SetAutoscaling` (`:5494`, via `checkAutoscaling`, `settings_check.go:261-266`), behind REST `PUT …/autoscaling`, GraphQL `setAutoscaling` and the MCP autoscaling tool.
  - Create (`service.go:3244`), including a Blueprint `scaling:` block. Not probed.
- `dashboard/src/features/services/components/autoscaling-section.tsx:234-241` rests on the premise "setAutoscaling refuses a free service server-side". That is untrue for `max ≤ 1`: w7/048 inferred it from a `max: 3` refusal. It renders `enabled = plan !== "free" && …`, so a stored config reads Off with the only toggle disabled.
- **Runtime effect:** while the Free service is awake, the operator runs `applyAutoscaling` for it (`lego/operator/internal/controller/app_controller.go:2878-2884`). Auto-hibernation still wins (`planRelease`), so nothing extra runs, but the autoscaler polls metrics for a service that cannot scale.

## Fix (target behavior)

- `autoscalingSpec` refuses enabling autoscaling on a Free-tier service with a coded `400` naming the requirement, e.g. "autoscaling requires a paid instance type". It checks the plan before the range, so `max: 3` gets the same reason. This matches the dashboard's copy and Render, which offers no autoscaling on free instance types (w7/048).
- `DELETE …/autoscaling` stays allowed on every plan.
- A Free service that already holds an enabled config (only reachable through this gap) reads the same on every surface. The Scaling card shows it as stored but inactive on Free, with a working Turn off (the existing DELETE), instead of "Autoscaling off".
- The `autoscaling_config_changed` event is emitted only for writes that are accepted.
- Fix the dashboard comment's premise.
- Tests:
  - Backend: free with `1..1`, `0..1` and `1..3` is refused; paid is accepted; create/Blueprint free + `scaling:` is refused.
  - Dashboard: a free service with a stored enabled config renders it and can disable it.

**Unverified:** MCP (same core path) and the Blueprint `scaling:` block (same helper), neither driven this pass.

Estimate: 45m.

**Sibling check (pass cc398c):** the two other paid-only gates the dashboard shows refuse Free on the server explicitly.

- Maintenance mode: `validateMaintenanceEligibility`, `lego/backend/internal/apps/service.go:805-807`, "maintenanceMode requires a paid web service plan".
- Disks: `validateDisk`, `lego/backend/internal/apps/disks.go:322-323`, "disks require a paid instance type".

Autoscaling is the only one that relies on the instance cap alone. Copy their shape (a plan check before any range check).
