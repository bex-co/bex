## Objective

Ship a Claude Code plugin from `bex-co/bex`, generated from the same pack `bex skills` embeds plus Render's plugin files (MIT), so `/plugin marketplace add bex-co/bex` then `/plugin install bex` works.

## Context

- Render's plugin `render-oss/render-plugin-claude-code` (main `2df0bc02ef`, v0.4.1): `.claude-plugin/{marketplace,plugin}.json`, `.mcp.json` (`https://mcp.render.com/mcp`, `oauth.clientId: "claude"` because Render has no DCR), `agents/render-assistant.md`, `commands/deploy-to-render.md`, `commands/check-render-status.md`, `hooks/hooks.json` (PostToolUse `Edit|Write|MultiEdit` → `scripts/validate-render-yaml-hook.sh`), 22 skills. bex keeps its 20.
- packgen's `Generate` walks only upstream `skills/` and `sync-skills.sh` clones upstream, so CI cannot regenerate offline: compare the plugin's skills byte-for-byte with `lego/cli/internal/skills/pack/skills/`, and bex's own plugin files with checked-in overrides (Render's agent, commands and hook are about 100 lines; vendor them as overrides with the MIT notice).
- Use a subdirectory `source` (`./plugins/claude-code/bex`), never `"./"`: the root `.mcp.json` is the maintainers' Playwright config and `.claude/skills/` holds maintainer skills. Keep skills as real copies, not symlinks into `lego/`, so a sparse clone works. Skills appear as `bex:bex-deploy`, as Render's appear as `render:render-deploy`.

## Steps

1. Emit `plugins/claude-code/bex/`: `.claude-plugin/plugin.json` (`name: bex`), `.mcp.json` with server `bex` at `https://api.bex.co/mcp` and **no** `oauth.clientId` (bex uses DCR, w4/m629), `agents/bex-assistant.md`, `commands/deploy-to-bex.md`, `commands/check-bex-status.md`, `hooks/hooks.json` plus the hook script, the 20 skills, LICENSE/notice.
2. Add root `.claude-plugin/marketplace.json` (`bex-plugins`) listing it.
3. Add the equality test.
