## Objective

New Private Service → Existing Image matches the backend's create default since w6/095:
- Port is blank, with "From the image" and the image-port help.
- A blank port sends no `port`, so the service takes its image's declared TCP ports.
- An explicit port is still sent.

## Context

- **The stale predicate.** `dashboard/src/features/services/lib/create-service-input.ts:94-107` (`imagePortShape`) returns `isDockerBuild` for `private_service`. Its doc still says "A private service on a prebuilt image keeps the configured port".
- **The backend rule it should mirror.** `lego/backend/internal/apps/service.go:2725-2733` stamps `PortModeImageV1` for `TypePrivateService && (source.Repo != "" || source.Image != "")` (w6/095, `d65c5638f`). With `port` sent, it stamps `PortModeImageConfiguredV1`.
- **The consumers** of the shape:
  - `portDraft` (`:145`);
  - `portIsValid` (`:151`);
  - the payload (`:277-278`);
  - `dashboard/src/routes/services.new.tsx:510-537` (placeholder and hint).
- **The existing test** `dashboard/src/routes/__tests__/services.new.test.tsx` "defaults the port to 10000 for %s" covers `/Private Service/i` on the default (Git) tab. Keep it for native sources and add the image case.
- **Live, round 82:** the dashboard create stalled on TCP 10000 for over 7 minutes. The REST control with no `port` went live on 80 in about 45 s.

## Steps

1. Make `imagePortShape` return `isDockerBuild || isImageSource` for `private_service`, as for `web_service`. Better, derive both from one helper named after the backend's rule.
2. Update the doc comment, and the en/zh descriptions of `createFieldPortFromImage` and `createFieldPortImageHint`, to list the prebuilt-image private service.
3. **Tests.** private + image: blank draft, blank is valid, no `port` key; an explicit `8080` is sent. private + Git Docker and web + image: unchanged. private + native: still pre-fills 10000.
