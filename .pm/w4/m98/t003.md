## Objective

Keep a clone's source readable and editable after an interrupted process while copying a single consistent source revision.

## Context

- `CloneEnvGroup` marks the source busy and currently keeps the claim while creating the target.
- Clone already enforces fresh sensitive source access and target create authorization.

## Steps

1. Use the durable ownership/recovery protocol for clone source protection, distinguishing its read-only intent from a content mutation.
2. Capture one stable server-side source snapshot and release source protection as soon as consistency permits.
3. Preserve target validation, zero copied links, secret masking, and existing creation compensation on normal failures.

## Files

- `lego/backend/internal/envgroups/clone.go`
- `lego/backend/internal/envgroups/revision.go`
- `lego/backend/internal/envgroups/recovery.go (if introduced by t002)`

## Acceptance criteria

- [ ] A process exit during source capture or target creation cannot leave the source permanently busy.
- [ ] A clone never combines env vars and secret files from different committed revisions.
- [ ] Recovery does not modify source contents, weaken cross-workspace authorization, or reveal copied values.

## Out of scope

- Ongoing synchronization between clones.
- Generalizing clone target creation into a new cross-workspace transaction product.
