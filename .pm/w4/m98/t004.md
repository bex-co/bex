## Objective

Let users access unaffected environment groups and understand a recovering group's state without presenting incomplete configuration as current.

## Context

- `viewFromMeta` returns a conflict for busy and repair-required states.
- `ListEnvGroupsFiltered` returns that error for the whole list, so one stranded group blocks workspace navigation.

## Steps

1. Choose a coherent committed view or explicit per-group unavailable state that keeps unaffected list entries usable and preserves pagination/filter behavior.
2. Expose the same status/error and actionable retry semantics through REST, GraphQL, MCP, and dashboard detail/list/editor consumers; refresh generated contracts only where needed.
3. Keep pending, recovering, conflict, and repair-required presentation distinct, with no silent omission, false success, or secrets in client state.

## Acceptance criteria

- [ ] One busy or repair-required group does not prevent listing and opening healthy groups.
- [ ] A recovering group's visible names, metadata, and revision describe a coherent committed snapshot or an explicit unavailable state.
- [ ] All existing surfaces agree on retry/conflict behavior; the dashboard cannot claim an unfinished save or rollout succeeded.

## Out of scope

- A public force-unlock endpoint.
- Changes to unrelated dashboard resource lists.
