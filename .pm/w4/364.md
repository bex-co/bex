# 364 — A Postgres save that restarts nothing may still read `config_restart`

Why: w4/m233/t008 fixed this for Key Value. t001's verdict there found that a Postgres external-access change restarts nothing (CNPG v1.30.0 re-signs the server certificate and reloads), so `dbStatus` probably over-reports the same way. Status reads `config_restart` until the database controller observes the generation, though nothing restarts.

**Source:** split from w4/m233/t008 step 2, loopx w4, 2026-10-19. Not seen live: no Postgres fixture was probed in passes 8be45a or 0a57a8.

## What to check first

- Probe on an owned Free Postgres: toggle `ipAllowList` empty and back (and a rename). Poll `GET /v1/postgres/{id}` at 1 s, including the PATCH response itself. Record whether `config_restart` appears and for how long. If it never does, close this as invalid with the probe.
- `lego/backend/internal/postgres/service.go` `dbStatus` reads `core.DatastoreReadyStatus` (`config_restart` while Ready's `ObservedGeneration` trails the generation, w4/m137).
- The database controller's Ready handling while it applies `serverAltDNSNames` and the proxy route (`lego/operator/internal/controller/database_controller.go`).

## Shape of the fix if it reproduces

Mirror the Key Value rule (`keyvalue/service.go`: `markRestartFree`, `restartFreePending`, `patchKeyValueLocked`). The update path marks a generation restart-free under an optimistic lock, and the status reads `available` while it is the only unobserved generation of a Ready database. Keep w4/m137: a plan, disk, version or HA change still reads `config_restart` until served.
