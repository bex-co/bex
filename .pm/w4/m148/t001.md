## Objective

Make a new Blueprint service's first deploy represent the complete initial fromGroup configuration, so its returned deploy ID reaches Live when that service serves the requested value.

## Context

applyStackServices creates the App and generation-1 deploy before calling LinkEnvGroup. For a repo-backed service with auto-deploy off, rollLinked patches the group's Secret references without opening a replacement deploy. The operator adopts the first configuration, queues the changed fingerprint, then serves generation 2; the store cancels the only row. Both live repetitions and the literal control are in finding.md.

## Steps

1. Use an internal, authorized initial-composition seam to resolve and attach group references before the first App release can be dispatched. Assemble the complete initial spec and membership under the existing create/rollback protocol, or implement an equivalent explicit initialization barrier with coherent deploy identity.
2. Keep the returned latestDeployId associated with that completed initial intent. Avoid a second build of an incomplete configuration, synthetic success for a superseded generation, or silent history omission.
3. Preserve group order, service-over-group precedence, environment scope and the first-deploy generation stamp. Do not expose arbitrary Kubernetes Secret names in public create input.
4. Preserve failure compensation for the App identity, resources and group metadata if preparation or creation fails. Do not publish partial success.
5. Keep ordinary existing-service group updates governed by w2/m94; do not globally bypass autoDeployGated or weaken the projector's legitimate supersede/terminal rules.

## Acceptance criteria

- [ ] New-group and existing-group initial creations each yield one attributable initial deploy that becomes Live with the group value.
- [ ] An operator observation between creation stages cannot publish an incomplete initial release or strand the returned deploy as Canceled.
- [ ] Literal creation, legitimate supersede/cancel and existing gated group updates keep their documented behavior.
- [ ] Preparation/creation failures do not leave unauthorized or orphan group membership.

## Out of scope

Changing the deployment projector to call an actually superseded row Live; a dashboard-only workaround; changing the existing group auto-deploy policy.
