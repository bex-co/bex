# Removing a service from its environment over REST leaves it in the project with no environment, so the dashboard lists it nowhere

Why: a Render API client, agent or IaC tool that calls `DELETE /v1/environments/{id}/resources` loses the removed services from every dashboard list. They show neither under the Overview's Ungrouped Resources nor in any environment card. Found by the w4/m550 dev-4 replay on 2026-11-22.

- **Repro (dev-4, fixtures created and deleted by the run):** move two ungrouped image services into a project's `staging` with the Overview's bulk Move. Then call `DELETE /v1/environments/<staging>/resources?resourceIds=<a>&resourceIds=<b>` → 204. `GET /v1/services/<a>` now reads `projectId: prj-…` with no `environmentId`. The Overview's Ungrouped Resources section is gone, and neither of the project's environment cards lists them. Only `PUT /v1/projects/<id>/service-links` without them made them ungrouped again.
- **Where:** the DELETE route (`lego/backend/internal/environments/rest.go`, `DELETE /v1/environments/{id}/resources`) calls `ChangeResources(…, false)` (`environments/resources.go`), which clears the environment but keeps the service's project stamp. w8/188 added the route.
- **Render:** a resource belongs to a project only through one of its environments, so a resource removed from its environment is ungrouped. Confirm this against Render's `DELETE /environments/{environmentId}/resources` reference before choosing the fix.
- **End state:** after the DELETE, each removed service, Postgres, Key Value and env group has no project and no environment. REST, GraphQL, MCP and the Overview all read it as ungrouped. An environments test pins it for every kind.
