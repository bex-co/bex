# Switching source tabs discards the Public Git Branch draft

Why: a user returning to the same repository loses an entered deployment setting while the URL and other settings remain, leaving Deploy enabled with a different source configuration.

**Severity:** major — silent loss of an entered Branch draft. No deployment from the cleared-branch state was submitted, and no wrong-code rollout or persisted service change is claimed. **Estimate:** 55m (caller audit 10m, scoped state fix 15m, behavioral tests 20m, Simplify and live replay 10m). **Status:** open. Source: functional `$qa-find-bugs w4`, pass a64, 2026-10-10 UTC, signed in through the muse.env login helper.

Goal: keep the selected Git source usable through the dashboard's creation journey ([ADR008](../../docs/ADR008-vision.md), [ADR029](../../docs/ADR029-static-sites.md)); fix an existing input-loss path rather than add a hosting feature.

## Reproduction and target

1. At `https://dashboard.bex.co/services/new?type=static_site`, choose Public Git URL. Enter Repository URL `https://github.com/bex-co/bex`, Name `qa-20261010-loop-a64-preview`, Branch `copilot/fix-inconsistent-outdated-docs`, Root Directory `examples/static-site`, and Publish Directory `.`.
2. Click GitHub, then Public Git URL. Do not pick a GitHub repository or edit the URL.
3. Branch's DOM value becomes the empty string, with gray `main` placeholder text. URL, Name, Root Directory and Publish Directory keep their values. Deploy Service is enabled before and after.
4. Fresh-page replays reproduced this at 14:56:00Z and 14:57:33Z; a further 15:09:34Z replay also retained Branch through an ordinary Root Directory edit but cleared it through the source-tab round trip. An explicit `main` draft also cleared in the first replay.

**Target:** returning to Public Git URL with the same URL restores the Branch value entered for that draft. Keep the existing abandonment of a selected GitHub repository and the image-to-static compatibility reset. Do not restore one repository's branch to a different URL or override a newly selected GitHub repository's default branch. Blank Branch remains an intentional valid choice when the user entered none.

The loss happens before submission: there is no server-owned draft or failed API response to repair. Preserve the value in the creation form's local state.

Viewed and checked support: `.playwright-mcp/qa-static-a64-branch-before-fresh.png` and `.playwright-mcp/qa-static-a64-branch-after-fresh.png` show the Branch control centered at 1440×1000. Their exact input values, rather than the placeholder's appearance, are recorded below. These screenshots are ignored local support; the durable reproduction and DOM capture are in this note.

## Root cause and fix boundary

- `dashboard/src/features/services/hooks/use-new-service-form.ts:145–149`: `setTab` explicitly merges `{ tab, selectedRepo: null, branch: "" }`. Its generic setter at 89–100 merges into the existing state, so gitUrl/rootDir/publishPath survive. This explicit reset explains the observed discriminator; it is not an input remount or a lost asynchronous response.
- `dashboard/src/routes/services.new.tsx:86,151–153,227–230`: the one form hook supplies the picker callback and the controlled Branch value.
- `dashboard/src/features/services/components/service-source-picker.tsx:135` forwards controlled Tabs changes to that callback. The wrapper `common/components/ui/tabs.tsx:10–20` forwards Root props. Actual installed Radix Tabs **1.1.13** (`dist/index.mjs:34–46`) calls controlled `useControllableState`; its dependency **1.2.2** (`dist/index.mjs:34–40`) invokes onChange when the new tab differs. The library successfully delivers the change; fix the form's draft policy.
- `dashboard/src/features/services/lib/create-service-input.ts:31,129–156,173–179`: Branch can hold a string, submission allows empty Branch, and the Public Git producer uses `branch: form.branch || undefined`. Consequently the cleared value would omit the chosen branch. This is a source-derived consequence, not a captured failed deployment or mutation from this draft.

**Work:** retain a Public Git Branch draft associated with its unchanged URL when leaving/returning, using the existing hook's state. Keep source payload shaping and server defaults intact. Add a meaningful hook/route regression for the round trip and verify the serialized create input retains the restored nonempty branch. Do not change shared Tabs or globally remove branch clearing.

**Shared-code audit (10m):** exhaustive production `useNewServiceForm(` search excluding tests found **one caller**, `routes/services.new.tsx:86` (plus its declaration). This route serves web, static, cron, background worker and private service creation through the five `type` choices. Allowlist the fix to this creation hook. The shared ServiceSourcePicker also serves Blueprint creation and Update Source; their independent callbacks are outside this reset and must not receive a global retention change. Postgres and Key Value use separate creation forms. Live reproduction covers static only; verify the other four service types as implementation work, with no paid resource creation needed.
