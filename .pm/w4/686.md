# 686 — Account Settings grows ~840 px at 1440 (~1870 px at 390) as its six panels load: each panel's loading state is two bars or one block, so every section below Account moves

Why: the dashboard rule ([AGENTS.md](../../AGENTS.md), "Dashboard preloading skeletons must match their post-loading contents") applies here. This page's done milestone, w5/m79 t011 ("Account settings skeleton"), gates "always-present major content regions with stable heights" at desktop and narrow-mobile widths. On production, every panel below Account changes height when its read settles.

- **Source / severity / estimate:** live `/qa-find-bugs w4` round 493, 2026-11-16 07:15–07:25 UTC, pin `3c6654df60a2`, `bex-canary` admin. **Minor:** a layout shift, and nothing is lost. A regression of w5/m79 t011 and the same class as [w4/684](blocked/684.md). ~1h.
- **Probe:**
  - From `/`, hold every `api.bex.co/graphql` request and every `dashboard.bex.co/api/**` request 4 s with Playwright routes.
  - Open the avatar menu and choose **Account Settings**.
  - Read each card at 1.8 s, and again 6 s after the hold is released.
  - The Account section renders from the Kratos flow, which is not held, and keeps its height (1704 px at 1440, 1950 px at 390).

  - Total growth is 837 px at 1440 and 1865 px at 390.
  - Danger zone's top moved 3046 → 3790 at 1440 and 4203 → 5430 at 390. Those two figures come from a first pass that held only GraphQL.
- **Cause:**
  - Each panel draws one loading shape whatever its ready layout is. `PanelTableSkeleton` (`common/components/panel-states.tsx:34-45`) is two `h-6` bars with no header row.
  - Connect GitHub's loading state is one 40 px block in place of its hint, action row and footnote.
  - `PreviewSkeleton`'s header is 76 px where the ready card's is 60 px at 1440 (92 → 100 px at 390). That difference does not depend on data.
- **Fix:**
  - Each panel's loading state draws the frame that is present whatever the data:
    - a table panel draws its column header row;
    - Active sessions also draws one row, for the current session, which is always listed;
    - Connect GitHub draws its action row and footnote at ready geometry (first confirm they also show when a connection exists);
    - Delete account draws its header, the confirm field and the button at ready geometry.
  - Row counts that depend on data stay a residual: API keys, SSH keys, connected agents and workspace lists.
  - Test each frame, as w4/680's `notifications-page-skeleton.test.tsx` does.
- **Blast radius:**
  - `PanelTableSkeleton` has 9 non-test users. [w4/684](blocked/684.md) changes the audit pair.
  - Either give the helper an optional header row and leave its other callers as they are, or make the change per panel.
- **Unverified:**
  - Connect GitHub's ready layout with a connection;
  - the route-level `AccountSettingsPageSkeleton` (`common/components/route-skeletons.tsx:1474`), which this probe did not mount;
  - zh widths.
- **Render:** n/a (loading layout).
- **Done when:**
  - Production pins the fix.
  - The same held navigation at 1440 and 390 shows the following at their ready heights (±4 px): Connect GitHub, Delete account, and Active sessions with one session.
  - Every table panel shows its header row while pending.
