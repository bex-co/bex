# w4/184 — Database detail minor UI nits (disk-autoscaling SR dupe + stale password alert)

Why: two tiny dashboard defects found in the Loop7 sweep erode trust in the database detail page; both are minutes to fix.

## 1. Disk-autoscaling "plan unsupported" text is announced twice to screen readers

On a Free database (`#metrics` → Disk autoscaling), the sentence "This plan does
not support disk autoscaling. An existing setting can be turned off." renders in
two elements: the visible `<span>` and the `sr-only` `aria-describedby` hint,
which resolves to the same locale string when the plan is blocked. Sighted users
see it once; screen-reader users hear it twice.

- Visible: `dashboard/src/features/databases/components/database-disk-autoscaling-control.tsx:46-50`
- Hint: `dashboard/src/features/databases/components/database-disk-autoscaling-control.tsx:59-65`
- Fix sketch: when blocked, point `aria-describedby` at the visible message (or
  render the hint only when it differs from the visible text).

Repro: open any Free Postgres → Overview → Metrics section; inspect the
`#database-disk-autoscaling-hint` content vs the visible note.

## 2. "Password shown once" alert survives the user's deletion

`#access-control` → Database users: after creating a user, deleting that same
user returns the list to "No additional users." but leaves the "Password for
<name> — shown once" alert (with the now-dead password) on screen.

- `dashboard/src/features/databases/components/access-control-panel.tsx:153-172`
  (`revealed` state is never cleared by the delete path at `:145`).
- Fix sketch: clear `revealed` when its user is deleted (or when the users list
  no longer contains it).

Repro: add user `x` → delete `x` → the password alert for `x` remains.
