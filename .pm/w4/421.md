# 421 — REST services omit Render's required `rootDir` whenever it is empty (every image service and every repo-root Git service)

Why: Render's `service` object lists `rootDir` as a required string. bex's REST view drops the key when the value is empty, so a schema-strict Render client rejects or misreads every image-backed service and every Git service built from the repository root.

**Severity:** minor (Render response-shape parity; lenient clients default to `""`). **Estimate:** ~20m. **Source:** live `/qa-find-bugs w4` loop run 1046, 2026-10-27 UTC (`muse.env`, `bex-canary`, pin `b4726243e74f`), a read-only schema-conformance sweep of REST responses against the pinned `render-public-api-1.json`. Nothing was created.

## Probe

- `GET /v1/services?ownerId=tea-daif693dqjvc73e7as3g&limit=50` → 14 services; **11 lack `rootDir`** (all the image-backed ones). `GET /v1/services/<an image service>` → no `rootDir` key.
- Control: `GET /v1/services/srv-daif6dsmg29s73d1umvg` (Git, `rootDir: examples/hello-go`) carries it.
- Render's `service` schema: `required` = `autoDeploy, createdAt, dashboardUrl, id, name, notifyOnFail, ownerId, rootDir, serviceDetails, slug, suspended, suspenders, type, updatedAt`; `rootDir: {"type":"string"}`.

The same sweep found every other resource clean: deploys (list and detail), env vars, custom domains, events, instances, owners, Postgres list, env groups (the `{envGroup, cursor}` envelope is deliberate, `envgroups/rest.go:49-51`), projects, blueprints and registry credentials. It also checked `owners/{id}` and `postgres/{id}`, apart from Postgres `project`, which Render lists as required but never defines.

## Root cause

`lego/backend/internal/apps/render.go:197`: `RootDir string \`json:"rootDir,omitempty"\`` on `renderService`. The same struct also tags five other Render-required fields `omitempty` — `dashboardUrl`, `createdAt`, `updatedAt`, `serviceDetails`, `ownerId`. They were always populated in this sweep, but would equally vanish if ever empty.

## Fix (target behavior)

- Emit `rootDir` on every REST service read (get, list, create/update responses), `""` for the repo root and image services, as Render does.
- Audit the other five required-but-`omitempty` fields: drop `omitempty` where the value can legitimately be empty, or prove it never is.
- GraphQL and MCP keep their own shapes (MCP's `rootDir,omitempty` is not bound to Render's object).

## Tests

Extend `TestRenderConformance` (`internal/api/conformance_test.go`), or the service-response conformance test, to seed an image service and a repo-root Git service and validate both against the pinned `service` schema's `required` list. That test would have caught this.

**Unverified:** what Render's live API emits for an image service's `rootDir` (assumed `""` per the schema); Postgres `project` (undefined in Render's spec, left alone). **Dedupe:** w8/165 is `rootDir` input validation (trailing slash), a different bug; no item covers the response shape. No `DO_NOT_DO.md` conflict.
