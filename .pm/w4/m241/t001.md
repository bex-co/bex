## Objective

A create (or dry-run) of a **free** Postgres or Key Value is refused when the workspace already has an active free one of that kind, on every workspace plan. A paid create is never refused by this rule.

## Context

- [finding.md](finding.md): probes, root cause, blast radius.
- Kubernetes object-count `ResourceQuota` cannot select by label (`store/namespaces.go:501-517`), so this is an app-level admission check: count the workspace's Database / KeyValue CRs whose plan is `free`, mid-deletion ones included (the w6/m129 rule).
- Create paths: `postgres/service.go` `CreatePostgres` (`:734`) and the Key Value create, plus their dry-run variants.

## Steps

1. Add a shared free-instance admission for Postgres and Key Value, run before any write and inside dry-run.
2. Refuse with a dedicated, stable code (e.g. `FREE_INSTANCE_LIMIT`) and copy that names the free rule ("This workspace already has a free Postgres database (<name>). Delete it or choose a paid instance type."). Never point the user at a workspace-plan upgrade.
3. Close the race: two concurrent free creates must not both pass. Use a store row/lock or a re-check after write with rollback, and record which.

## Acceptance criteria

- [ ] Real-Postgres backend tests: free create refused with one free present; a paid create admitted; concurrent free creates admit exactly one; dry-run reports the same answers.
- [ ] `cd lego/backend && go test ./...` and lint pass.
