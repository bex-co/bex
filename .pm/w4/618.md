# 618 — Adding a custom domain toasts the name as typed ("Added Qa-R238.Example.COM"), while the list, the DNS dialog and the API all use the normalized name `qa-r238.example.com`

Why: the toast is the one place that names the domain the user just added, and it shows a spelling that appears nowhere else. With a pasted mixed-case or trailing-dot name, the user can't tell whether that exact string was saved.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 238, 2026-11-12 22:38 UTC (`muse.env`, workspace `bex-canary`; pin `764072bb8e8a`). **Minor** (copy). ~10m.
- **Fixture:** Free web service `qa-20261112-r238-dom` (`srv-dbr3vj9s0kvs73brg890`, `traefik/whoami:v1.10`). Deleted afterwards. The test domain was added and removed in the same visit.
- **Probe:** Settings → Custom Domains → Add Custom Domain → Name `Qa-R238.Example.COM.` → Add Domain at 22:38:32.
  - The toast read **"Added Qa-R238.Example.COM"**, with the description "DNS and the TLS certificate propagate in the background.". The trailing dot was dropped and the case kept.
  - `GET /v1/services/srv-dbr3vj9s0kvs73brg890/custom-domains` → `[{"customDomain":{"id":"cdm-dbr3vq697s4s7399kdh0","name":"qa-r238.example.com","domainType":"subdomain",…,"dnsRecord":{"type":"CNAME","name":"qa-r238","value":"qa-20261112-r238-dom.onbex.co"}}}]`.
  - The "Domain added — set up DNS" dialog, the table row and the later "Removed qa-r238.example.com" toast all use `qa-r238.example.com`.
- **Root cause:** `dashboard/src/features/services/hooks/use-custom-domains.ts:203` toasts `t("services.domainAddSuccess", { name })` with the submitted string. The normalized record is already in hand on the line above (`primary = mapRaw(res.data?.addCustomDomain)`, `:202`).
- **Fix (target behavior):** the toast names the domain as saved, `primary?.name ?? name`.
  - When the add auto-paired a sibling (apex ↔ www, `pairedSibling`, `:207`), consider naming both, for example "Added example.com and www.example.com". That needs its own en and zh string; the apex case was not probed.
- **Tests:** `use-custom-domains` test: adding `Qa-Example.COM.` with a mocked response `name: "qa-example.com"` toasts "Added qa-example.com".
- **Unverified:** an apex domain and its auto-added `www` sibling.
- **Render:** n/a (copy).
- **Dedupe:**
  - `grep -rliE "domainAddSuccess|Added .*custom domain" .pm` finds nothing.
  - w4/574 (done) covers deleting by hostname versus by id.
  - Not deploy lag: `git log 764072bb8e8a..origin/main -- dashboard/src/features/services/hooks/use-custom-domains.ts` is empty.
- **Also verified this round (all pass), custom domain add, verify and delete (journey 5):**
  - **Validation.** The add dialog refuses `https://qa-r238.example.com/` ("Enter a valid domain, e.g. www.example.com."), `localhost` (the same message) and `qa-r238.onbex.co` ("qa-r238.onbex.co is a reserved platform hostname").
  - **DNS instructions.** "Domain added — set up DNS" gives the CNAME `qa-r238` → `qa-20261112-r238-dom.onbex.co` in the `example.com` zone. The row reads Verified Pending and Certificate Pending.
  - **Platform subdomain.** The toggle says the custom domain must verify before it can be turned off.
  - **Re-check.** It toasts "qa-r238.example.com isn't verified yet — DNS may still be propagating.", and REST `POST …/custom-domains/qa-r238.example.com/verify` answers `202`.
  - **Delete.** The dialog says nothing was served and no certificate was issued. The toast reads "Removed qa-r238.example.com", and the list is then `[]`.
- **DoD (live):** on an owned web service, adding `Qa-<ts>.Example.COM.` toasts "Added qa-<ts>.example.com" (en and zh), matching the row and the API. Then remove it.
