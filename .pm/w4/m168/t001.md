## Objective

Refuse any env-var key or secret-file name longer than 253 characters (the Kubernetes Secret-key limit, `IsConfigMapKey`) with a 400 before anything is written, on every surface, and stop the dashboard from submitting one.

## Context

- `lego/backend/internal/core/config.go:141` `ValidSecretFileName` checks charset and `.`/`..` only; `config.go:62` `ValidEnvKey` checks charset only. Neither caps length.
- Live boundary: a 253-character group file name saved; 254 failed at the Secret write (`ENV_GROUP_UPDATE_RESTORED`, 409). On services the same input gave a 500 and persisted (see t002/t003).
- Dashboard mirrors: `dashboard/src/features/services/lib/environment-draft.ts:387` (`isValidSecretFileName`) and `dashboard/src/features/env-groups/lib/validation.ts:14,20`, plus the key validator behind `services.envInvalidKey` (`dashboard/src/features/services/locales/en.ts:816`, `918`/`922`).

## Steps

1. Add `len(name) <= 253` to both core validators. `CheckEnvKey` and every secret-file refusal then return `ErrBadRequest` naming the rule (never the value).
2. Mirror the cap in the dashboard validators, with en/zh copy that states the limit.
3. Unit-test 253 accepted / 254 refused on both validators and the dashboard helpers.

## Files

- `lego/backend/internal/core/config.go`
- `dashboard/src/features/services/lib/environment-draft.ts`, `dashboard/src/features/env-groups/lib/validation.ts`, services/env-groups locales (en + zh)

## Acceptance criteria

- [ ] REST/GraphQL writes of a 254-character key or file name return 400 on services and env groups; 253 still succeeds.
- [ ] The dashboard blocks Save with the length message before submit.

## Out of scope

- Repairing existing poisoned stores (t004).
