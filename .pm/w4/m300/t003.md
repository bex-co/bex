## Objective

After Trigger Run, the Recent Runs table shows the returned run as pending within a second, offers Cancel on it, and polls at the converging cadence until it settles. Today the table can miss a short run entirely, because the list arrives at the 25 s baseline poll (README P4).

## Context

- `dashboard/src/features/services/hooks/use-cron-runs.ts`:
  - `trigger()` awaits `runCronJob`, then calls `refetch()`.
  - `hasActiveRun` is derived from the list only.
  - `toRuns` keeps `startedAt: ""` as `""`.
- `useConvergingPoll` is in `dashboard/src/common/lib/polling.ts:56`: 3 s while converging, 25 s otherwise.
- `dashboard/src/features/services/components/cron-runs-section.tsx` builds the row's accessible name with `runToggleWhen`, which returns `run.id` whenever `absoluteTime(run.startedAt)` is `—`.

## Steps

1. Seed the triggered run from the `RunCronJob` result until the list carries its ID. That way `hasActiveRun` is true, and polling converges at 3 s, even if a stale list read answers first.
2. Treat an empty `startedAt` as absent: `""` becomes `null`.
3. For a run that hasn't started, the Started cell and the accessible name say something like "not started yet", localized in en and zh. Never the `crr-` ID.
4. Check the pending and ready states side by side at 1440 and 390 px.
