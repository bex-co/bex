## Objective

Each release record also stores the service's `maxShutdownDelaySeconds`, its port configuration and its pre-deploy command as the release ran them, so a later restart or rollback can select them.

## Context

- `ReleaseRecordSpec` (`lego/types/v1alpha1/releasesnapshots.go:100-130`) records start command, command, health-check path, replicas, env and secret-file sources, but not these three.
- ADR004 § Settings saves wait for a deploy (w8/m135), Residual: "The remaining saved fields (shutdown delay, pre-deploy command, port) still come from the saved spec".
- Older records lack the fields; missing stays unknown, never an invented default (ADR004 rule).

## Steps

1. Add the three fields (optional, pointer or omitempty) to `ReleaseRecordSpec` and write them where the operator writes a record.
2. Regenerate CRDs/deepcopy as `make test` requires.
3. Envtest: a new release's record holds the values; a record written before the change reads them as absent.

## Files

- `lego/types/v1alpha1/releasesnapshots.go`
- `lego/operator/internal/controller/` (release record writer)
- `lego/operator/config/` (generated)

## Acceptance criteria

- [ ] New records carry the three values; old records still parse.
- [ ] `make test` passes.
