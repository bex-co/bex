## Objective

t001 closes the two nested fields this hunt found. This task proves that two is the whole list — and makes it impossible to add a third without classifying it.

## Context

- The hunt's own grep found exactly two value-returning nested resolvers: `grep -rn "EnvVarsFrom\|SecretFilesFrom" lego/backend/internal --include='*.go' | grep -v _test` → `apps/graphql.go:691` (`envVarKeysResolve`, names only), `:703` (`envVarValueResolve`, **value**), `:727` (`secretFileNamesResolve`, names only), `:739` (`secretFileContentResolve`, **value**). That grep keys on two specific context readers and is therefore **not** exhaustive over "fields that return something sensitive".
- `TestMintAndSensitiveHeuristics` (`scope_matrix_guard_test.go:158-201`) already encodes the project's intent — "env-var value read must be sensitive", "secret-file value read must be sensitive", "env-group value read must be sensitive", "live SQL text must be sensitive" — but evaluates it over `classifiedOps`' keys, which are root fields only.

## Steps

1. Enumerate every GraphQL field whose resolver can return a credential, secret, connection string, or live SQL text — not just the two found. Candidates to check by name and by resolver: env groups (`envGroupVar`, `envGroupSecretFile` exist as roots — do they also nest under an `EnvGroup` type?), datastore connection info (`databaseConnectionInfo`/`keyValueConnectionInfo` are roots — is there a nested `Database.connectionInfo`?), API keys, SSH keys, deploy-hook URLs, registry credentials, agent-session credentials. Paste the grep and the count.
2. Do the same sweep for **mutations**: the collector treats Query and Mutation identically, so a sensitive nested selection under a write-classified mutation root has the same shape of gap. State whether any exists.
3. Extend the guard so the audit cannot rot: a field reachable from a root classified below sensitive, whose resolver reaches a sensitive reader, fails the test with a message naming the field.
4. Record the resulting registry (or classification table) somewhere a reviewer will look — `docs/ADR012-auth.md` §7 is where the scope vocabulary lives.

## Acceptance criteria

- [ ] An exhaustive enumeration with its grep and count, covering queries **and** mutations, and the whole resource-type family (service · static · cron · worker · private · Postgres · key-value · env group · agent session).
- [ ] Adding a new nested sensitive field without classifying it fails the guard test, and the failure names the field.
- [ ] The registry/table is documented where the scope vocabulary is defined.

## Out of scope

- Changing what any resolver returns. This task classifies; it does not redact.
