## Objective

The dashboard's New Project dialog asks for the first environment's name (default `Production`) and creates both in one transaction. GraphQL `createProject` and MCP `create_project` accept the same input and go through `CreateWithEnvironments`.

## Context

- `dashboard/src/features/projects/components/new-project-dialog.tsx:31-35`, `:61`; `features/projects/hooks/use-create-project.ts`; `features/projects/api/projects.graphql:33`.
- `lego/backend/internal/projects/graphql.go:70-78`, `mcp.go:94-99`, `service.go:409-414`, `rest.go:166-177`.

## Steps

1. Add an `environments: [{name}]` arg to GraphQL `createProject` and MCP `create_project`, delegating to `CreateWithEnvironments`.
2. Add the environment-name field to the dialog, prefilled `Production`, required and validated like the Environment create dialog. Land on `/project/<id>?env=<new env id>`.
3. Regenerate the GraphQL types; en and zh copy.

## Acceptance criteria

- [ ] A dashboard create yields exactly one environment with the typed name, and the page opens on it.
- [ ] GraphQL and MCP create with an environment are transactional (a failing environment insert leaves no project).

## Out of scope

- Making REST reject an omitted `environments` (a separate follow-up if wanted).
