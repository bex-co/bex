## Objective

Dashboard, GraphQL and MCP environment and project deletes delete the contained services, as Render documents ("Deleting an environment deletes all of its associated services"; a project delete deletes all of its environments and services). The confirmation lists exactly what will be deleted.

## Context

- Today's teardown: ADR032:27, :35, :41 (detach), w4/m214 (datastore clears), w8/188 (REST 409).
- Dashboard environment delete (environments panel More actions) and `routes/project.$projectId.settings.tsx`, `features/projects/hooks/use-delete-project.ts`.
- GraphQL `deleteEnvironment`/`deleteProject` (`projects/graphql.go:81-92`), and the MCP delete tools.
- Protected environments keep the Admin gate (ADR032:73).

## Steps

1. Decide datastores and env groups. Default (parity-sufficient): delete services; keep detaching datastores and groups until Render's dashboard behavior is verified. Record the decision in the README.
2. Delete services through the normal service delete path (authz, audit, billing retire), then the grouping row. A partial failure leaves the grouping for retry.
3. Rewrite both dialogs to name the services being deleted and what is detached; use the typed-phrase confirm when any service would be deleted.

## Acceptance criteria

- [ ] An environment with a service: delete → service 404, environment 404; Cancel sends nothing.
- [ ] A project delete covers services in every environment.
- [ ] REST non-empty delete still answers 409.

## Out of scope

- Deleting datastores or groups, unless step 1 verifies Render does.
