# 403 — An invalid secret-file name is refused in Kubernetes' wording ("a valid config key… regex used for validation is…"), unlike env-var keys

Why: an API or MCP user who names a secret file `dir/x.txt` is told about a "config key" and shown a Go regex. Neither concept exists in bex's product. An invalid env-var key gets bex's own plain rule ("use letters, digits, '-', '_' and '.', at most 253 characters"), so the two siblings read differently for the same rule.

**Severity:** minor (copy on an API error path; the dashboard validates names client-side first). **Estimate:** ~15m. **Source:** live `/qa-find-bugs w4` loop run s5f7, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `29d63e1f7bea`). Fixture: Free image web service `qa-20261024-s5f7-sf` (`srv-dbe4m0em3f6s73cuqgf0`). It was deleted (`DELETE` → `204`, `GET` → `404`); session revoked.

## Probe

- `PUT /v1/services/<id>/secret-files/dir%2Fx.txt` `{content:"x"}` → `400 {"code":"SECRET_FILE_INVALID","error":"invalid secret file name \"dir/x.txt\": a valid config key must consist of alphanumeric characters, '-', '_' or '.' (e.g. 'key.name',  or 'KEY_NAME',  or 'key-name', regex used for validation is '[-._a-zA-Z0-9]+')", …}`. `..%2Fetc` gets the same wording.
- Controls on the same fixture, all matching the pinned Render spec:
  - `GET …/secret-files` → `[{secretFile:{name,content},cursor}]`.
  - `PUT …/secret-files/b.txt` → `201 {name,content}`; a repeat PUT is an upsert.
  - Bulk `PUT …/secret-files` replaces the list.
  - `DELETE` → `204`, then `404 NOT_FOUND`.
  - Unknown name `GET` → `404`.

## Root cause

`lego/backend/internal/core/config.go:73-76`: `envVarKey` carries `rule: EnvKeyRule`, but `secretFileKey` has no `rule`. `problem` (`:86-95`) therefore joins `validation.IsConfigMapKey`'s raw Kubernetes messages. `CheckSecretFileName` (`:197-201`) has 7 non-test callers across services, env groups, GraphQL, MCP and Blueprint, so one change fixes every surface.

## Fix

- Give `secretFileKey` a plain rule of its own, e.g. `SecretFileNameRule = "letters, digits, '-', '_' and '.', at most 253 characters"`, so the refusal reads `invalid secret file name "dir/x.txt": use letters, digits, '-', '_' and '.', at most 253 characters`.
- Use the same string in the dashboard's secret-file name hint, if it states the rule.
- Keep the over-long-name branch, which already omits the name.
- Test: `dir/x.txt`, `..data` and `a b` each produce the plain rule and never the substring `config key` or `regex`.

**Unverified:** Render's own secret-file naming rule and wording (not probed).
