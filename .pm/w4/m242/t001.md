## Objective

Make `POST /v1/env-groups` answer the created group with its real values every time, as w8/182 intended. When a reveal genuinely cannot be authorized, the masked fallback must omit `value` rather than send `""`.

## Context

- `lego/backend/internal/envgroups/render.go:128-188` (`revealGroups`, `revealedOne`, `committedRevealed`); `rest.go:101-107`.
- Production evidence: 4 of 7 creates blank, immediate `GET` always correct ([finding.md](finding.md) §1).

## Steps

1. Read the bex-api log line `reveal values for the write response` for a blank create, or reproduce with the real-deps backend suite (Postgres + OpenFGA + OpenBao) by creating in a tight loop. Name the failing step.
2. Fix it at the cause. For example, reveal from the contents the create itself just wrote (it already holds them), authorize on the workspace the create authorized, or wait for the FGA write's consistency token. Don't paper over it with a retry loop.
3. Masked fallback: serialise `envVars` without `value` and `secretFiles` without `content`, so `""` is never invented.

## Acceptance criteria

- [ ] A backend test that creates 50 groups back to back gets values in every response, under the real-deps suite.
- [ ] A forced reveal failure answers a body with no `value` keys, and logs.
