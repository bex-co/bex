# 407 — The account menu button's only accessible name is the avatar initial ("P")

Why: the top-bar avatar opens the account menu: settings, theme, language and **Log out**. A screen-reader or voice-control user hears and must say "P, button", with nothing telling them it is the account menu or whose account it is. It is one of the dashboard's primary controls, on every page.

**Severity:** minor (accessible name on a primary control). **Estimate:** ~15m. **Source:** live `/qa-find-bugs w4` loop run a2n5, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `c5583c80bef9`). Read-only; session revoked.

## Probe

- `await page.locator('main').ariaSnapshot()` on `/` (and every dashboard page) contains `button "P"` beside `button "Search"`, `button "New"` and `button "Help and resources"`. Every other top-bar control has a descriptive name.
- An accessibility-tree sweep of 14 pages found no unnamed controls. This one is named, just not meaningfully.

## Root cause

`dashboard/src/common/components/user-nav.tsx:52-69` `UserAvatarButton` renders an icon-size `Button` whose only content is `<AvatarFallback>{userInitial}</AvatarFallback>`. There is no `aria-label`, so the initial becomes the name. It is the `DropdownMenuTrigger` at `:170-172`.

## Fix

- Give the trigger `aria-label={t("common.userMenuOpen", { name })}`, e.g. "Account menu for puncsky@gmail.com". Fall back to "Account menu" when no identity is loaded. en + zh.
- Mark the avatar initial `aria-hidden` so it isn't read twice.
- Keep the visible initial unchanged.
- Test: the trigger's accessible name contains "Account menu", and the menu still opens by keyboard (Enter/Space).

**Unverified:** what Render names its avatar button (not compared live).
