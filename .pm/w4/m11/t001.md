## Objective

Turn on the second-factor credential methods in Kratos configuration: `totp` (issuer named for bex), `webauthn` in passkey mode, and `lookup_secret` (recovery codes), with the session/settings AAL policy set so enrolling a second factor makes login require it (`highest_available`) — configuration only, no custom code.

## Context

- Kratos values live at `deploy/gitops/base/values/kratos.values.yaml` (m1's ADR: identity is bought — docs/auth.md).
- WebAuthn needs an RP ID + origins; local values target the local dashboard origin, prod values `dashboard.bex.co` (t004 finishes prod).
- `session.whoami.required_aal` / settings-flow `required_aal` set to `highest_available` so a user with a second factor must present it, while password-only users are untouched.
- Watch for local-overlay quirks (the m7 pattern: control-plane pin + PSA) if any new component is involved — none should be; this is values-only.

## Steps

1. Enable the three methods in `kratos.values.yaml` with sane parameters (TOTP issuer "bex"; passkey display name).
2. Set AAL policy (`highest_available`) for whoami + settings.
3. Local overlay values for RP ID/origin; Argo sync on the mock cluster; Kratos healthy.
