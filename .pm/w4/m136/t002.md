## Objective

Establish with a real probe whether the deploy detail page's log panel silently drops lines past the newest 100 per type. If it does, make it page or warn like the Logs tab.

## Context

- `dashboard/src/features/deploys/hooks/use-deploy-logs.ts:127` queries each type (`build`, `predeploy`, app) with `limit: LOGS_LIMIT` over the deploy's window and merges them. It never reads `hasMore`.
- Not observed live in pass 159. This is reasoned from code only, so start by reproducing it.
- A native build of `examples/hello-go` or any real repo usually emits well over 100 build lines. The build SSE stream (w3/m14) covers in-flight deploys, so the gap, if real, shows on a **finished** deploy.

## Steps

1. On a finished deploy with a long build, run the `logs(type:"build", startTime, endTime, limit:100)` probe from the page and record `hasMore` and the first/last timestamps.
2. Compare against the panel's oldest visible build line after scrolling to the top.
3. If they are truncated, page each type or show the truncation notice. Otherwise record the evidence and close this as not reproducible.
