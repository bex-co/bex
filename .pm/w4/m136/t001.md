## Objective

Make the Key Value and Postgres Logs tabs reach the whole selected range. They should reuse `w4/m107`'s `useLogHistory` (load older on scroll-to-top, driven by `nextEndTime`/`hasMore`) and its truncation notice, not grow a second paging implementation.

## Context

- `dashboard/src/features/keyvalue/hooks/use-key-value-logs.ts:34-42` and `dashboard/src/features/databases/hooks/use-postgres-logs.ts:41` each run a single `LogsDocument` query with `limit: 100` and read only `data.logs.logs`.
- `dashboard/src/features/logs/hooks/use-log-history.ts:55` already pages, and `features/logs/components/log-viewer.tsx:135,194` renders the notice from `history.hasMore`.
- Datastore filters are window, text, and instance only. Service-only filters (`type`, level, and so on) return a named 400 for `red-`/`dpg-` (`docs/render-artifacts/keyvalue-logs.md`), so the history hook's variables must not add them.
- Both viewers are virtualized. Verify with `scrollTop = 0`, not a DOM row count.

## Steps

1. Read `useLogHistory`'s variable contract and confirm it can take a datastore resource with only window/text/instance, or generalize it minimally.
2. Switch both hooks (or both viewers) to it, and render the same truncation notice and load-older behavior as the service tab.
3. Keep the empty/filtered-empty/unauthorized/unconfigured states intact.
4. Check pending and ready states at desktop and narrow-mobile widths (dashboard skeleton rule).
