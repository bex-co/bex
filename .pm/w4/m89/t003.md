## Objective

Stop describing a session that is starting normally as one that is broken.

## Context

Observed in `dev-1` on a freshly created session, all on screen at once:

- phase chip: `Creating`
- banner: "Starting the sandbox…"
- steering composer: "The conversation stream is unavailable, so live steering is paused."

The stream is not unavailable — it does not exist yet, because the sandbox is still being created. The UI has two states (have stream / no stream) where the domain has at least four.

Separately, the send button renders **"Sending…"** while disabled during a turn the user never initiated; it should read as its normal label while disabled, with the explanation carried by the helper text ("Wait for the current turn to finish before sending a follow-up", which is already correct).

- `session-conversation-impl.tsx:307` picks the unavailable copy off `isTerminal` only, which is why a starting session and a genuinely failed one look the same.

## Steps

1. Derive an explicit state from session phase + transport status: not-started (pre-sandbox), connecting, live, broken, ended.
2. Render distinct copy per state; "unavailable" language only for broken.
3. Fix the send button label so it reflects its own action, not the session's.
4. Check the terminal-session case still explains why steering is closed.

- [ ] A session in `Creating` shows no failure-shaped copy anywhere on the page.
- [ ] "Unavailable" appears only when the stream genuinely failed.
- [ ] The send button never says "Sending…" unless this user's message is in flight.
- [ ] Each state is covered by a test asserting the rendered copy.
