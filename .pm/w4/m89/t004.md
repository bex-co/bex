## Objective

Tell a workspace it is missing a model key or a GitHub connection **before** it writes a prompt, using data the API already returns.

## Context

- `GET /v1/agent-sessions/capabilities` (+ GraphQL/MCP twins, ADR048/`w11/m6`) already returns exactly this: selectable agent profiles plus GitHub and model-key readiness, deliberately secret-free.
- In `dev-1` a workspace with no model key returned `{"enabled":true,"github":{"connected":false},"modelKeyReady":false,"ready":false}` — the information was already there and the composer did not use it; the user only found out after submitting.
- A repo-less session needs `modelKeyReady` but **not** `github.connected` (per `validateCreate`, no repo ⇒ no clone, no PR), so a blanket "not ready" gate would wrongly block the chat-only path this dashboard already supports.

## Steps

1. Read `capabilities` where the composer already loads its data.
2. Show what is missing, and what to do, before submission.
3. Gate only what is genuinely required for the composed session: missing GitHub blocks a repo-backed session, not a repo-less one.
4. Keep the t002 error path as the backstop for races.

## Acceptance criteria

- [ ] With `modelKeyReady: false`, the composer says so before submit.
- [ ] With `github.connected: false`, a **repo-less** session can still be started.
- [ ] With `github.connected: false` and a repo attached, the gap is explained at the repo control.
- [ ] Tests cover all three combinations.

## Out of scope

- Building the flows that fix the gaps (connecting GitHub, storing a model key).
