# A registry-credential link from another workspace reads "not found", though the API resolves credentials by id

Why: w4/m172 made registry-credential by-id verbs resolve their own workspace, but the dashboard's credential detail read, update and delete still send the selected workspace as `ownerId`. A credential link opened under another of the user's workspaces is therefore "not found", the same class as w4/443 (webhooks) and w4/m169 (Blueprints).

- **Source / severity / estimate:** w4/443's sweep, loopx w4, 2026-10-31; **minor**, ~25m.
- **Code:** `dashboard/src/features/registry-credentials/hooks/use-registry-credential.ts:27` (`variables: { id, ownerId: currentWorkspaceId }`), `use-update-registry-credential.ts:48` and `use-delete-registry-credential.ts:31`. m172 verified the REST by-id verbs live without `ownerId` (GET/PATCH/DELETE 200/204).
- **Fix:** follow w4/443: drop `ownerId` from the by-id read, update and delete; keep it on list and create. Hook tests should assert no `ownerId`. Confirm GraphQL `registryCredential(id:)` resolves without `ownerId` before changing.
- **Dedupe:** no open item covers registry-credential deep links. No DO_NOT_DO item applies.
