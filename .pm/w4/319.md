# Searching datastore logs keeps the page's old time cutoff

Why: a new search under “Last hour” can report no matching logs for an error already stored, because its query still ends when the page opened.

**Severity:** major. **Estimate:** 55m (reader anchor 20m; behavioral tests 15m; sibling controls 5m; Simplify 5m; live replay/cleanup 10m). **Status:** inbox. Source: continuous functional `$qa-find-bugs w4`, pass a662, 2026-10-16 UTC. Research main: `45d809f99c41a0426b9bcbf9eefd95237e08ff04`. This schedules a fix; no product implementation is included.

## Cause and bounded fix

- `dashboard/src/features/logs/components/datastore-log-viewer.tsx:155–173` commits text after 300ms and updates the predicate, but **:170 memoizes rangeWindow(range) with only [range]**. Neither committed text nor instance changes its window.
- `features/logs/lib/datastore-log-range.ts:19–29` correctly uses a new Date when called for a relative range and passes Custom strings through. The helper is not called again for the failing predicate commits.
- `features/logs/lib/datastore-log-search.ts:45–63` obtains the range through `features/metrics/lib/range.ts:147–158`; a relative preset comes from the shared preset table (:35). A text/instance URL write retains that preset identity.
- `features/logs/hooks/use-log-history.ts:78–110` sends the changed text with the unchanged window to LogsDocument, using cache-and-network. The **actual network request bounds** are wrong; clearing Apollo's cache cannot repair them.
- Inspected lock-resolved **React/ReactDOM 19.3.1**, including the Yarn-cached `react-dom/cjs/react-dom-client.development.js:9173` updateMemo and :7969 areHookInputsEqual: equal dependencies reuse the stored memo. Older local node_modules were excluded from the pinned-version explanation. The lock and native request both identify Apollo 4.3.3.

**Target:** the first history query for a newly committed datastore resource/text/instance predicate in a relative range ends at that commit's current clock sample, with the selected span. Resample the component's window synchronously with the committed reader identity, before useLogHistory constructs that first query. Include changed/cleared text, instance, and resource; preserve the 300ms debounce and URL adoption. A passive-effect update after a stale first request is insufficient.

Keep this viewer's **one-shot historical reader**: no periodic auto-refresh, SSE, new timer, route remount, or global useLiveRange change is requested. Explicit Custom bounds remain exactly fixed even when predicates change. Preserve paging/cursors for an unchanged reader, URL echoes, loaded older pages, literal matching, raw record bytes, instance retention, and existing loading/error/refusal/timeout states. Before a new reader settles, retain its truthful loading behavior and geometry; do not show an old-window empty result as its completed answer. API, schema, storage, and timestamp semantics remain unchanged.
