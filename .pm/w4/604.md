# 604 — A Suspend undone within ~5 s records neither `service_suspended` nor `service_resumed`, so no push or webhook goes out; whether the pair appears depends on whether a 30 s reconcile pass happened to start in between

Why: the outbound "Service suspended" / "Service resumed" notifications and webhooks are fed only by the observed `service_*` pair. A quick Suspend → Resume, for example a misclick undone at once, therefore notifies nobody, while the same action held 10 s does. w4/527 set the rule that both are recorded however quickly they follow each other.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 189, 2026-11-12 10:56–11:01 UTC (`muse.env`, workspace `bex-canary`; pin `a5be11e4e517`). **Minor** (lost lifecycle notifications in a narrow window; the Events tab still shows the intent rows). ~45m.
- **Fixture:** Free image service `qa-20261112-r189-m` (`srv-dbqple28vjhs73do9bn0`, `traefik/whoami:v1.10.1`), deleted afterwards (DELETE 204, then GET 404).

- **Root cause:**
  - **The pair is sampled.** `service_suspended` / `service_resumed` come only from `observedStateFacts` (`lego/backend/internal/store/event_facts.go:735`, the w4/527 quick-undo branch). That branch needs a checkpoint that recorded `suspended=true` (`previousSuspended`) followed by an observation with `suspended=false`.
  - **The flag is observed only by a reconcile pass.**
    - `observedServiceStateFor` reads `Suspended: app.Spec.Suspended` (`lego/backend/internal/store/reconciler.go:2300`). The pass has just copied it from the desired row (`applyOwnedSpec(&cur.Spec, want)` at `:769`, then `recordObservations` at `:778`).
    - So the suspension is seen only if a pass reads the desired rows between the Suspend and the Resume.
  - **Suspend and Resume never kick that pass.**
    - `setSuspended` (`lego/backend/internal/apps/service.go:5485-5527`) writes the row and the CR through `writeThroughStoreFetched` / `patchFetched`, and neither calls `s.Kick()`.
    - The only `s.Kick()` calls in `lego/backend/internal/apps` are create (`service.go:2839`, `:2913`), deploy (`deploy.go:3918`) and domains (`domains.go:1067`, `:1899`). `srv.Apps.Kick = rec.Kick` is wired (`cmd/api/main.go:1510`).
    - Passes therefore run on the 30 s resync (`defaultResyncPeriod`, `reconciler.go:83`) or when an unrelated platform write kicks them (`Kick` coalesces, `:461`).
    - Run 2 was seen within a second, by luck of timing; runs 1 and 3 were not seen at all.
  - **Outbound delivery reads only the observed pair.**
    - push: `notifications/push_worker.go:831-834`;
    - webhooks: `webhooks/service.go:234-235`, with the comment at `:83-84`: "outbound notifications use observed service\_\*".
    - A missed pair is therefore a missed notification and a missed webhook.
- **Fix (target behavior):**
  - Every accepted Suspend that is followed by a Resume records exactly one `service_suspended` and one `service_resumed`, however short the suspension. This is the rule w4/527 set ("Render records both actions however quickly they follow each other").
  - `service_suspended` is dated no earlier than its `suspender_added` and `service_resumed` no earlier than its `suspender_removed`. The resume stays at least 1 µs after the suspend and lists above it (w4/555's ordering).
  - Push and webhooks then deliver both. The REST, GraphQL and MCP events lists and the dashboard read the same pair.
  - **Recommended mechanism:** do not make the pair depend on sampling. When the Suspend's row write commits, record the suspension on the event checkpoint as well: `suspended=true`, `updated_at` = the write time, and only if the checkpoint is not already suspended. The next pass then sees `previousSuspended` and `obs.Suspended=false` and takes the existing quick-undo branch, dated by `quickSuspendPair`.
    - Kick the reconciler from `setSuspended` too, so a long suspension's phase edge is recorded promptly.
    - A Kick alone is not sufficient: a pass already running when it fires coalesces the kick and can read the rows after the Resume.
  - **Mind the sleeping-Free branch** (w4/562, `event_facts.go:742-749`). It records `service_suspended` when the flag rises on a Hibernated checkpoint (`!previousSuspended && obs.Suspended`). Pre-setting the checkpoint there would skip that fact. Either leave a Hibernated checkpoint to the pass, or emit the fact from the same write.
