## Cause and bounded correction

`dashboard/src/features/deploys/components/deploy-actions.tsx:314–316` selects the special warning only for `trigger === "create"`. A manual retry has `trigger:"api"` even if nothing ever served, so it selects `services.eventsCancelConfirmBody`. Its English text at `features/services/locales/en.ts:4300–4305` assumes a previous deploy is serving; the Chinese definition at `locales/zh.ts:4199–4204` makes the same unconditional promise. This is the directly observed branch, not stale history or a backend cancellation failure.

**Target:** make the generic body truthful without needing to know the service's complete history. For example: “The in-progress deploy will be stopped. A previous successful deploy stays in place if there is one; otherwise, nothing will be serving. Saved changes stay saved for the next deploy.” Give en/zh the same conditional meaning and update their translator descriptions. Preserve the existing explicit `create` warning. Unknown triggers must also get this conditional generic body.

The existing optional nullable trigger and string-description interface already express this fix. No new has-live field, history fetch, status inference or pre-query delay is needed. `common/components/confirm-dialog.tsx:132` renders the selected description through `ui/alert-dialog.tsx:99–109`.
