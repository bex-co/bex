# 233 — File contents dialog grows and moves its controls when loading finishes

Why: the loading state should reserve the editor's ready geometry so users can read and reach the same controls while their file is fetched.

- **Severity:** minor. The dialog grows by 64 CSS pixels and its footer moves down 32 pixels at desktop and mobile widths. Reveal, edit, Save only, Cancel and narrow-screen scrolling work; no lost contents or inaccessible control was observed.
- **Estimate:** 45m: local geometry correction 15m, shared callers and behavioral/browser controls 25m, live replay 5m. One bounded inbox fix.
- **Source:** user-requested functional qa-find-bugs loop, 2026-10-10 UTC pass a47, muse profile, workspace `tea-d98210cbbpdc73dcrkvg`. Research HEAD `367223e57`. Filing only.
- **Goal linkage:** [ADR018 parity](../../docs/ADR018-render-parity.md), [ADR004 deployment](../../docs/ADR004-app-deployment.md), and the dashboard AGENTS.md requirement that loading placeholders preserve ready-state structure. This is an existing file-editing surface; correct its initial loading geometry without changing stored data or save semantics.

## Root cause and bounded fix

- `dashboard/src/features/services/components/secret-file-content-dialog.tsx:30–55` initializes loading for an absent content string with a reveal callback, fetches the contents in an effect, and clears loading in finally. At **68–79**, its spinner branch reserves `min-h-48` (192px), while its ready Textarea reserves `min-h-64` (256px). The same header and footer surround both branches, accounting for the measured 64px growth.
- `dashboard/src/common/components/ui/dialog.tsx:63` centers the box with top/left 50% and negative half translations, so half of that growth moves each edge. Its 200ms entry zoom/fade is a separate effect; the selected failing frames have `transform:none`.
- `dashboard/src/common/components/ui/textarea.tsx:10–17` defaults to `field-sizing-content`. The live computed style is `content`; merely increasing the spinner's minimum to 256px would match this short file but still leave larger auto-sized contents able to expand the dialog when the read settles.
- The installed Tailwind **4.1.18** utility code in `node_modules/tailwindcss/dist/chunk-CT46QCH7.mjs` emits actual `field-sizing:content` and `field-sizing:fixed` declarations. `cn` at `common/lib/utils/utils.ts:17` uses installed **tailwind-merge 3.4.0**; its `src/lib/default-config.ts:2027` puts fixed/content in the same conflict group. A local fixed-sizing override can therefore replace the shared content default. Radix Dialog **1.1.15** `dist/index.mjs:204–231` forwards content props to its dismissable dialog layer; geometry is supplied by the local classes. The complete successful Apollo **4.1.3** responses above contain the correct bytes: this finding needs no query/cache/API correction.
- **Target:** give pending and initially ready content the same bounded 256px editor region inside this dialog. A local height/fixed-field-sizing override or equivalent container can reserve that region before fetching and keep longer text scrollable. Deliberate user resizing after load can remain available. Preserve long-title wrapping, max-90vh dialog scrolling, the spinner and disabled Done during loading, failed-read protection, explicit Cancel, and the exact contents/save flow. Do not display an empty ready editor as though a fetch succeeded.
- **Scope:** change this dialog locally, rather than the global Dialog/Textarea primitives. REST/GraphQL/MCP data shapes and save modes remain valid; no transport changes are needed. Loading and failed reads must keep Done disabled; successful reads enable it; supplied-content opens ready immediately. Broader query error classification is outside this layout correction.
