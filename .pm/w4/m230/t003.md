## Objective

Every neighbor of the changed rule has a written, tested landing place, so the fix neither silences real outages nor leaves a sibling wrong.

## Context

- Single caller: `observedServiceStateFor` → `reconciler.go:476`. `makeFact` serves four phase facts (`event_facts.go:522-534`).
- Consumers of `server_available`:
  - push: `notifications/push_worker.go:647-651`, "Service recovered", Important
  - webhooks: `webhooks/service.go:200`
  - events REST/GraphQL/MCP: shared `events.Service`
  - dashboard: `features/events/service-event-catalog.ts`, `services/locales/en.ts:3928`
  - mobile: `mobile/src/features/events/timeline.ts`, `notifications/deep-link.ts`
- Not probed live: a woken instance that crash-loops. Reasoned from `event_facts.go:543-549`: from the `""` baseline it would record no `server_failed` at all.

## Steps

1. **Failed wake.** Decide and implement where a concrete container failure (`concreteContainerFailure`: CrashLoopBackOff, ImagePullBackOff, …) during a wake lands. Recommended: `server_failed` at its transition time, so a later recovery pairs with it. A service that cannot wake is down to every caller.
2. **Running, no deploy, unready.** Confirm and test that it stays `server_failed` → `server_available`.
3. **User Resume.** Confirm it shares t001's rule, with a test.
4. **Siblings.** Write a timestamp disposition for `service_suspended`, `service_hibernated` and `service_resumed`: adopt t002's rule or keep `obs.At`, with the reason. Pass 7d3e19 measured `service_resumed` at 00:18:10, 1 s after its first 200.
5. **Datastores.** Check whether `datastore_event_facts.go` has an analogous startup path. If it does, file it separately; do not fix it here.
6. **Docs.** Record the decisions in ADR052's lifecycle-facts section.
