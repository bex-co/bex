## Objective

Confirm that the REST events, GraphQL `serviceEvents`, MCP `list_events`/`list_service_events`, webhooks, push and the dashboard Activity feed all report the corrected lifecycle identically. Confirm that `server_failed`/`server_available` match Render's documented pair.

## Context

- render.com/docs/webhooks (fetched 2026-10-19):
  - `server_failed`: "A service became unavailable, usually due to a runtime error."
  - `server_available`: "A previously unavailable service became available."
  - No spin-up/spin-down events.
- `service_hibernated`/`service_woken` are bex extensions. Record them as such in `docs/ADR018-render-parity.md` (service events row).

## Steps

1. Exercise all three API surfaces against one store fixture, or cite the shared core plus one cross-surface test.
2. Update the ADR018 service-events row with the wake/recovery rule and the date.
3. File any drift found as follow-up rather than fixing it here.
