# An unmatched API route or method answers Go's plain-text `404 page not found` / `Method Not Allowed`, not bex's JSON error envelope

Why: every other bex-api error is `{"error","id","message"}` JSON, and Render-shaped clients (the official CLI, SDKs, agents) decode that body. A mistyped path, a Render path bex does not mount, or a wrong verb instead returns a 19-byte `text/plain` body, so the client reports a JSON decode failure rather than "not found" / "method not allowed". The `w4/167` and `w4/168` misses reached users exactly this way.

Found live in `/qa-find-bugs` pass 255 on 2026-09-28 (w4-targeted, `muse.env` credentials) against the deployed `6b6d99ea8`. Read-only: an authenticated request client with `Origin: https://dashboard.bex.co`.

| request | response |
| --- | --- |
| `GET /v1/nonexistent`, `GET /v1/services/<srv>/nonexistent`, `GET /v2/services` | **404 `text/plain`**, body `404 page not found\n` ❌ |
| `PUT /v1/services`, `DELETE /v1/owners`, `POST /v1/services/<srv>/deploys/<dep>` | **405 `text/plain`**, body `Method Not Allowed\n`, `Allow:` correct (e.g. `GET, HEAD, POST`) ❌ body / ✅ header |
| control: `GET /v1/services/srv-d0000000000000000000` | 404 `application/json` `{"error":"not found","id":"not_found","message":"not found"}` ✅ |
| unauthenticated, any of the above | 401 `application/json` (the auth gate answers before routing) ✅ |

A browser `fetch` from the dashboard origin with a JSON `Content-Type` to an unmatched path failed outright (`TypeError: Failed to fetch`), which suggests the CORS preflight on an unmatched route also fails. That is unverified; the non-browser request above did carry `Access-Control-Allow-Origin`.

## Mechanism

- `lego/backend/internal/api/server.go:1143` (root) and `:1340` (`restHandler`) build plain `http.NewServeMux()`. With Go 1.22 method patterns, an unmatched path falls through to the mux's built-in `NotFound` and a path matched under another method to its built-in 405 writer. Both write `text/plain` via `http.Error`.
- Nothing wraps the mux to translate those two cases. `core.WriteErr` / `core.WriteErrStatus` (`internal/core/http.go:286,355`) produce the envelope everywhere else.

## Fix

Target: an unmatched route answers `404 {"error":"not found","id":"not_found","message":"not found"}`, and a wrong method answers `405 {"id":"method_not_allowed",…}` with the existing `Allow` header preserved. Both are `application/json`, carry the same CORS headers as a matched route, and appear on REST only (GraphQL and MCP have single endpoints).

- Wrap the REST mux: detect the fallback with `mux.Handler(r)` returning an empty pattern (unmatched), or with a `ResponseWriter` that intercepts the 404/405 plain-text write. Re-emit through `core.WriteErrStatus`. Keep `Allow`.
- Make sure an `OPTIONS` preflight on an unmatched path gets the normal CORS preflight answer, so the browser can read the JSON 404.
- Tests: through the gated server, `GET /v1/nonexistent` → JSON 404, `PUT /v1/services` → JSON 405 with `Allow`, and the matched control is unchanged.

Blast radius: only the fall-through branch; matched routes are untouched. `/healthz` and `/mcp` stay as they are.

Render: its public API documents a JSON error object for 4xx responses. The exact body Render returns for an unknown path was not captured (no Render account in this run).

Estimate: ~30m.
