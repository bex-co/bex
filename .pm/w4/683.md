# 683 — Opening Workspace Settings writes an `agentsessions.RepoEnvironments` success row to the audit log every time: the repository environment reads arrived after w4/m321's `readVerbs` list, and nothing fails when a read is missing from it

Why: [w4/m321](blocked/m321/README.md) DoD 1 is "Admin reads leave no row". Render's audit log records actions plus two views (`ViewEnvVarValuesEvent` and `ViewConnectionInfoEvent`). m321 kept the dashboard's own reads out of it. Three reads arrived three days later: repository environments (w9/m387) and their builds (w9/m407). Each call records a success row. So every visit to Workspace Settings records one, because its Agents section carries the Repository environments card.

- **Source / severity / estimate:** live `/qa-find-bugs w4` round 492, 2026-11-16 07:00–07:07 UTC, pin `3c6654df60a2`, workspace `bex-canary` (Scale, admin). **Minor:** each row is a true read and nothing is lost. But the log and its CSV export fill with reads Render does not record. A follow-up of w4/m321. ~45m.

- **Cause:**
  - `core.Base` records every allowed check of a write relation unless the verb is in `readVerbs` (`lego/backend/internal/core/base.go:963`; the list is at `core/audit.go:1329-1360`).
  - The three reads authorize with `core.RelCanCreate`, and none is in the list:
    - `RepoEnvironments`: `agentsessions/repo_environment.go:165-166`
    - `RepoEnvironmentBuilds`: `agentsessions/repo_environment_builds.go:182-183`
    - `RepoEnvironmentBuild`: `:207`, authorized at `:221`
  - m321's list landed 2026-11-11 (`0e5a309c0`). These verbs landed 2026-11-14 (`e13dd1e96`, `5e420ffeb`).
  - No test catches a missing entry:
    - `TestReadVerbsNameServiceMethods` (`core/audit_test.go:472`) checks that every listed name is a real method. It does not check that every read is listed.
    - w21/087's sweep drives every route, MCP tool and GraphQL field allowed (`api/audit_verbs_test.go:159`, `:283`, `:376`), but it checks only the verb's spelling.
- **Fix:**
  - Add the three verbs to `readVerbs`. Their denials stay recorded, because `auditsDenial` holds for `RelCanCreate`.
  - Make the next omission fail. In w21/087's allowed sweep, assert that these record no success row: a `GET` REST route, a GraphQL query field and a read MCP tool. The only exceptions are the views Render records, `ViewEnvVarValuesEvent` and `ViewConnectionInfoEvent`.
  - Reverting any one of the three entries must fail the new assertion.

- **Blast radius:**
  - A scan of `lego/backend/internal` found 75 `(s *Service)` methods outside `readVerbs` whose first direct `Authorize…` call uses a write relation.
  - The only reads among them are these three. The rest create, change, delete or start a flow.
  - The scan does not see verbs that authorize through a package wrapper, such as `billing`'s `s.authorize`. The sweep assertion above is what covers those.
