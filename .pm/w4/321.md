## Root and concrete repair

`lego/operator/internal/build/native.go:89–91,243–269` selects the reviewed Go image and generates the native image. `nativepnpm.go:42–46` installs the primary-Node tools only for runtime node. In `nativeresolve.go:83–91,114–119`, the JS companion allowlist contains **ruby and python**, so Go receives no Node/npm/Yarn/pnpm layer before its authored build. The live and exact-image executions agree with that code.

Extend the existing **Go** companion eligibility and reuse `addNativeJSTools/nativeJSToolLines` (`nativeresolve.go:133–146`) before source/build. Keep primary Go and its paths intact; copy the selected reviewed Node line and its npm, the existing Yarn1.22.22 supplier, and reviewed pnpm10.34.6. Reuse existing NODE_VERSION → .node-version → .nvmrc → package engines precedence and deterministic refusal rules rather than an installer, a new runtime, or a Go-version selector. This changes previously ignored Go-side Node-version signals; document that behavior as m77 does.

The predicate can express Go without an API/schema change. Reviewed Go and Node bases are Bookworm images; prove the copied tools actually execute beside Go, including at runtime, rather than accepting generated-text assertions alone. Preserve exact authored PATH/env handling, command quoting, optional Bun, primary compiler behavior and stable/changed cache inputs. Treat Rust/Elixir separately until probed; they are source-traced exclusions, not observed failures or scope expansion.

The current regression guard explicitly forbids the needed repair: `nativeversion_test.go:510–522` asserts Go/Rust/Elixir do not gain `/usr/local/bin/node`. Replace the Go expectation with companion execution/selection coverage and retain the untouched Rust/Elixir controls. Extend the existing real-image gate `native_test.go:1056` (`TestNativeImageRunsJSToolsBesideRubyAndPython`) to cover Go and retain its Ruby/Python controls.
