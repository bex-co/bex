# Create forms promise Project membership when No environment creates an ungrouped resource

Why: the shared hint sends a newly created datastore somewhere it never appears, reviving w6/m48's placement-copy bug while confusing creation with the separate, working Move to project action.

**Status:** todo · **Worker:** worker4 · **Severity:** minor · **Estimate:** 55m. Source: live `qa-find-bugs`, 2026-10-02 sweep 9, using `muse.env` in workspace `tea-d98210cbbpdc73dcrkvg`; user selected w4. Research HEAD and fetched origin/main: `889f9ac128f245cb253e2c3c0ecf5bf1433a18d0`. Goal linkage: ADR008's dependable hosting flows and ADR032's Project/Environment placement contract.

## Reproduce and target behavior

1. Create a disposable Project with no Environments. This run used `qa-20261002-proj-r9` / `prj-davo2rude41s73canu60`.
2. Open the New Postgres dialog from a fresh Overview, choose that Project and leave **No environment**. The hint says: “or leave it on No environment — the resource then sits in the Project under Unassigned.”
3. Create a **Free** Postgres. The actual request has neither placement ID; the response has `projectId:null, environmentId:null`. Independent REST/GraphQL/MCP reads show it outside the Project.
4. Independently open `/keyvalue/new`, select the same Project and No environment, and create a **Free** Key Value. The same promise and outcome reproduce.
5. Control: on the Overview, use the Postgres row's **Move to project** action, choose the Project, then freshly open its page. It now appears under **Unassigned**, with `projectId` set and `environmentId:null`.

**The current create behavior is the accepted contract** (w6/m48/t003). Correct the hint in English and Chinese to explicitly describe creation: choosing a Project filters the Environment picker; leaving No environment creates the resource outside any Project. Selecting an Environment adds the resource to its parent Project. Retain the instruction to create a missing Environment on the Project page. Do not restore the old global claim that Project-only membership is impossible: the Move control proves otherwise. No new create-time `projectId` input or backend behavior change is requested.

Suggested wording: “When creating a resource, selecting a Project filters its Environments. Choose an Environment to add the resource to that Project. If you leave No environment selected, the resource is created outside any Project. Create an Environment from the Project's page first if needed.”
