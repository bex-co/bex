# 511 — Every row of the Overview resource table has a button named just "Open actions menu" (12 identical on the live page), and each API client row's "Copy client ID" is equally bare while the Revoke button beside it names its client

Why: on the page a customer opens first, a screen-reader user listing buttons, or a voice-control user saying "click Open actions menu", gets one identical target per service, database and Key Value row with no way to tell which resource a menu belongs to; the Settings API-client table has the same defect on its Copy button although the row's own Revoke button already names its client.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 106, 2026-11-05 UTC (`muse.env`, `bex-canary`); **minor** (accessibility); ~25m.
- **Probe:** read-only, signed in, `await page.locator('main').ariaSnapshot()` on existing production pages, counting buttons, links and form controls by accessible name (a name repeated three or more times):
  - `/` (Overview): `button "Open actions menu"` ×12, one per resource row. I did not record how each row names its resource, only the button names.
  - `/settings`: `button "Copy client ID"` ×3, one per API client row (a client's name is the row's first cell; its Revoke button is named `Revoke <name>`).
  - Not new: `/env-groups/<id>` read `button "Reveal"` ×4 and `/settings` `button "Save"` ×3 on the same sweep. The Reveal one is w4/499 (done on main, not yet live), and the Save ones are w4/510.
  - Every other page in the sweep (`/blueprints`, `/blueprints/<id>`, `/env-groups`, `/webhooks`, `/billing`, `/keyvalue/<id>`) had no unnamed control and no name repeated three times.
- **Root cause:** the row menus' trigger has a fixed `aria-label` with no resource name:
  - services: `aria-label={t("services.actionsMenu")}` at `dashboard/src/features/services/components/service-row-actions.tsx:267`; `services.actionsMenu` is `"Open actions menu"` (`features/services/locales/en.ts:355`),
  - databases: `database-row-actions.tsx:127`, `databases.actionsMenu` (`features/databases/locales/en.ts:104`),
  - Key Value: `key-value-row-actions.tsx:88`, `keyvalue.actionsMenu` (`features/keyvalue/locales/en.ts:209`),
  - the three are mounted per row by `features/projects/components/resource-table.tsx:350`, `:359` and `:368`.
  - API clients: `components/api-key-row.tsx:33` passes `label={t("apiKeys.copyClientId")}` (`"Copy client ID"`, `features/api-keys/locales/en.ts:113`) while the same row's Revoke button uses `t("apiKeys.revokeNamed", { name: entry.name })` (`:53`).
- **Fix (target behavior):** each button names its row, in en and zh.
  - Row menus: `Actions for {name}`, the form w4/436 already gave the custom-domain rows (`Actions for <domain>`). Add `{name}` to the three message keys (zh twins are `打开操作菜单`), and pass `service.name` / the database name / the Key Value name at the three `aria-label` sites. Keep the icon-only look.
  - API clients: `Copy client ID for {name}` (zh twin `复制客户端 ID`), passing `entry.name` as `revokeNamed` does.
- **Tests:** a resource-table test with a service, a database and a Key Value row asserting `getByRole("button", { name: "Actions for <name>" })` for each and that no two buttons share a name; an API-key-row test asserting the Copy button's name contains the client's name.
- **Blast radius:** the three row-action components each have one list mount (`resource-table.tsx`) and the database one has a second mount in the detail header (`routes/databases.$databaseId.tsx:177`, a single button, so it only changes wording). `apiKeys.copyClientId` has 2 non-test uses: the row (`api-key-row.tsx:33`) and the one-off created-key dialog (`create-api-key-dialog.tsx:81`), which has no row to name and keeps the bare label. Tests that select the menu by the old name must follow it; they were not grepped for this note.
- **Adjacent classes:** none beyond the two sites; the Copy buttons elsewhere (`Copy service ID`, `Copy 116.202.29.102`, `Copy Deploy Hook URL`) name their value or target.
- **Unverified:**
  - Only the live accessibility tree was read: the Overview list was not opened with a different filter or at narrow width, and the zh strings were read from the catalogs, not rendered.
  - Other pages that mount `resource-table.tsx` (for example a project's page) were not opened.
- **Render:** n/a (naming of bex's own controls).
- **Dedupe:** w4/436 and w4/482 (done) named the custom-domain row and DNS-panel buttons, w4/499 (done) the Reveal/Hide toggle, w4/510 (open) the Settings Save/Add buttons; none touches these keys. `grep -rli "Open actions menu" .pm` hits only old evidence dumps (w4/266, w4/263 and others) that quote the control and file nothing about its name; `grep -rli "Copy client ID" .pm` finds nothing. No DO_NOT_DO item applies.
