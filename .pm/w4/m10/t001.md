## Objective

Add audit recording where every verb already passes exactly once: `Base.Authorize`/`AuthorizeOn` in the feature-package kernel (`lego/backend/internal/core/base.go`, which all feature `Service`s embed) — **not** the raw OpenFGA `Checker` (`lego/backend/internal/authz/authz.go`), which also serves read/list filtering and would over-record. Each authenticated **write** verb and each authz **denial** produces one `AuditEvent{caller, verb, resource, outcome, at}` — with no way for a future verb to forget to log.

## Context

- Caller identity is already on the request context (`core.IdentityFrom`, `lego/backend/internal/core/identity.go` — OAuth2 `client_id` or Kratos identity id; the `api` package only attaches it via `core.WithIdentity` in its auth middleware; `docs/bex-api.md` §Auth).
- _2026-07-11:_ there is **no post-write kernel hook** — the only universal choke point is `Base.Authorize`/`AuthorizeOn` at verb start (every verb calls it exactly once; `core/base.go`), and the REST/GraphQL/MCP adapters call verbs directly, so "success events fire after the verb's write succeeds" cannot be captured at one point as originally written. Decide the semantics up front: either (a) authorize-time events with `outcome=allowed/denied` — one true interception point, accepting that a post-authorize k8s failure still records `allowed` — or (b) a tiny per-verb emit helper, with t004's `TestAuthzGuardsEveryVerb`-based inventory test (`lego/backend/internal/api/server_test.go`) as the "no verb forgets" enforcement instead of the kernel. Record the choice in this task on execution.
- Recording must be non-blocking for the verb path (best-effort async or short-timeout write); an audit-store outage must not take down writes — log-and-continue, never fail the verb.
- Read verbs are out of scope by default (volume); the event shape should carry `outcome` so denials of reads can be added later without a schema change.

## Steps

1. Define `AuditEvent` + an `AuditSink` seam in `internal/core`; no-op sink when the store is absent.
2. Emit from `Base.Authorize`/`AuthorizeOn` (denials always; successes per the chosen semantics — authorize-time `allowed`, or the per-verb helper), tagging verb + resource id.
3. Ensure event payloads never carry request bodies or values (env-var writes log key names at most).

## Files

- `lego/backend/internal/core/base.go` (the `Base.Authorize`/`AuthorizeOn` seam — the denial hook lives here)
- `lego/backend/internal/authz/authz.go` (the `core.Checker` over OpenFGA — reference only; do not emit from it)
- `lego/backend/internal/core/` (new audit types file)

## Acceptance criteria

- [ ] Every existing write verb emits exactly one event on success; a 403 emits one denial event; unit-verifiable with a fake sink.
- [ ] A sink error never fails the verb.
- [ ] No values/secrets in any event payload.

## Out of scope

- Persistence (t002); read surface (t003); auditing read verbs.
