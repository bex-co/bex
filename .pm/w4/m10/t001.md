## Objective

Add audit recording where every verb already passes exactly once: the feature-package kernel (`lego/backend/internal/core/base.go`, which all feature `Service`s embed) and/or the authz path (`internal/api/authz.go`), so each authenticated **write** verb and each authz **denial** produces one `AuditEvent{caller, verb, resource, outcome, at}` — with no per-feature code and no way for a future verb to forget to log.

## Context

- Caller identity is already on the request context (`api.IdentityFrom` — OAuth2 `client_id` or Kratos identity id; `docs/bex-api.md` §Auth).
- The OpenFGA checker (w4/m4) sees every verb + resource + relation — a denial there is the "denied" event; success events fire after the verb's write succeeds.
- Recording must be non-blocking for the verb path (best-effort async or short-timeout write); an audit-store outage must not take down writes — log-and-continue, never fail the verb.
- Read verbs are out of scope by default (volume); the event shape should carry `outcome` so denials of reads can be added later without a schema change.

## Steps

1. Define `AuditEvent` + an `AuditSink` seam in `internal/core`; no-op sink when the store is absent.
2. Emit from the authz checker (denials) and from the base kernel's write path (successes), tagging verb + resource id.
3. Ensure event payloads never carry request bodies or values (env-var writes log key names at most).

## Files

- `lego/backend/internal/core/base.go`
- `lego/backend/internal/api/authz.go`
- `lego/backend/internal/core/` (new audit types file)

## Acceptance criteria

- [ ] Every existing write verb emits exactly one event on success; a 403 emits one denial event; unit-verifiable with a fake sink.
- [ ] A sink error never fails the verb.
- [ ] No values/secrets in any event payload.

## Out of scope

- Persistence (t002); read surface (t003); auditing read verbs.
