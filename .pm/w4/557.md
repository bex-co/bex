# 557 — Postgres Insights' Top queries is still led by the platform: the CloudNativePG exporter's login `cnpg_metrics_exporter` isn't in w21/026's role list, and Insights' own queries run as the owner

Why: Top queries should show the customer's own work. On a fresh database it shows only CloudNativePG's metric scrapes and the Insights panel's own introspection queries, so w21/026's fix leaves the panel describing itself.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 50, 2026-11-10 22:53–23:05 UTC (`muse.env`, workspace `bex-canary`, pin `a0d5802594e9`). **Major**: a residual of w21/026, whose first DoD item fails. ~40m.
- **Fixture:** Free Postgres `qa-20261110-pg50` (`dpg-dbpq0sthi5vc738gissg`), with no application connected. Deleted afterwards.
- **Probe 1: the Insights section.**
  - **Active processes reads "No active processes"**, so w21/026's processes half holds.
  - **Top queries shows CNPG exporter scrapes**, exactly the statements w21/026's DoD says must not appear:
    - `SELECT sa.datname , sa.usename , sa.application_name , states.state …` (the `pg_stat_activity` backends metric);
    - `SELECT pg_catalog.current_database() as datname, name as extname … pg_available_extensions`;
    - `SELECT datname , pg_catalog.pg_database_size(datname) AS size_bytes , pg_catalog.age(datfrozenxid) …`.
  - It also shows bex's own Insights SQL.
- **Probe 2: the SQL console on the owned database.** Query: `SELECT r.rolname, s.calls, s.total_exec_time, s.query FROM pg_stat_statements s JOIN pg_roles r ON r.oid = s.userid WHERE r.rolname NOT IN ('postgres','streaming_replica','cnpg_pooler_pgbouncer') ORDER BY total_exec_time DESC`.
  - **Rows from `cnpg_metrics_exporter`:** backends (4 calls, 98.0 ms), `pg_settings` CASE (97.6 ms), `pg_available_extensions` (95.5 ms), `pg_database_size` (9.5 ms), `pg_locks blocked_locks` (1.3 ms), and more.
  - **Rows from the owner `dpg_dbpq0sthi5vc738gissg_user`, which are bex's own Insights statements:**
    - `SELECT name, setting, COALESCE(unit, $1) … FROM pg_settings WHERE source NOT IN …`, ranked first at 174 ms;
    - the Top queries `SELECT` itself;
    - `SELECT current_database() AS dbname, pg_database_size(…)`;
    - the table sizes and table scans queries;
    - the `pg_stat_activity` processes query;
    - `SET LOCAL search_path = $1, public, pg_temp`, 52 calls.
  - **`pg_roles` lists `cnpg_metrics_exporter`** with `rolsuper = false`, as a member of `pg_monitor`.
- **Root cause:**
  - **The role list misses the exporter.** `lego/backend/internal/postgres/insights.go:317-323` hard-codes `platformRoles = ('postgres', 'streaming_replica', 'cnpg_pooler_pgbouncer')`.
    - w21/026's closing note says the set was inferred from query text, because `userid` couldn't be read.
    - CNPG's exporter has its own login, `cnpg_metrics_exporter`.
  - **The right predicate already exists.** `ReservedPostgresRole` (`lego/types/v1alpha1/database_types.go:52-62`) covers `postgres`, `streaming_replica`, and the `cnpg_` and `pg_` prefixes.
  - **bex's own reads count as the customer's.** The Insights reads run with the owner's credentials through `runInsight`/`runAuthorizedInsight` (`:395`, `:442`): `sqlProcesses` (`:326`), `sqlTopQueries` (`:341`), the settings, size, table sizes and table scans queries.
    - Together with the SQL console wrapper's `SET LOCAL search_path`, they land in `pg_stat_statements` as the customer's own statements.
    - On a quiet database, the panel ends up showing the panel.
- **Fix (target behavior):**
  - **Exclude every reserved role.** Top queries and Active processes leave out every role `ReservedPostgresRole` names, in SQL: `rolname IN ('postgres','streaming_replica') OR rolname LIKE 'cnpg\_%' OR rolname LIKE 'pg\_%'`. Share the operator's rule rather than keeping a second list.
  - **Exclude bex's own introspection statements.** Tag them with a leading SQL comment such as `/* bex:insights */` (`pg_stat_statements` keeps it in the stored text), or with a dedicated `application_name`, and filter on that tag.
  - **Customer statements stay.** That covers the owner, any customer-created role, and SQL console queries the user typed.
  - REST, GraphQL and MCP share these statements, so one change covers all three.
  - **Test:** seed one `cnpg_metrics_exporter` statement, one tagged Insights statement and one owner statement, and assert only the owner's comes back.
