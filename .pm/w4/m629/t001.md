## Objective

Real MCP clients (Claude Code's MCP SDK, Codex's rmcp, Cursor) ask for the MCP resource with RFC 8707 `resource=`, never Hydra's `audience=`. Make a matching `resource` end up as the granted access-token audience, so a token minted for a self-registered client passes bex-api's audience check instead of answering 401, without reopening the empty-audience escalation w1/m67 F1 closed.

## Context

- Hydra v26.2.0 reads only `audience` (`fosite/audience_strategy.go`); ADR012 § Audience discipline already says Hydra ignores RFC 8707 `resource`.
- The consent acceptor grants only what the client asked for: `grant_access_token_audience: consent.requested_access_token_audience ?? []` (`dashboard/src/common/server-fn/hydra-consent.ts:586-587`).
- Production runs `BEX_OAUTH_REQUIRE_AUDIENCE=1` (`lego/operator/config/api/deployment.yaml:137-138`); `lego/backend/internal/api/auth.go:648-662` rejects an audience-less human token from a non-platform client (`w1/m67 F1`), and `:649` also rejects a non-granular human token from one (`w8/m27`).
- bex-desktop met the same wall (w9/m177 t002).
- w31/001 (separate note) makes Hydra advertise `registration_endpoint`; without it no spec-following client gets this far.

## Steps

1. Read Hydra's consent request for what it keeps of the authorize URL (`request_url`) and confirm a `resource=` parameter is there.
2. Decide the mechanism and record it in ADR012 §7: the candidate is that the consent acceptor grants `BEX_OAUTH_RESOURCE` (or its `/mcp/cloud-agents` path) as the audience when `resource` equals it exactly. Check whether Hydra accepts granting an audience the client did not register; if it refuses, choose another route (for example a registration default) and say why.
3. Never grant an audience for a `resource` that is not bex's own; a mismatched or absent `resource` keeps today's behavior.
4. Unit-test the acceptor: matching `resource` → granted; other `resource` → not granted; `audience=` clients unchanged; platform clients unchanged.

## Files

- `dashboard/src/common/server-fn/hydra-consent.ts` and its tests
- `docs/ADR012-auth.md` §7

## Acceptance criteria

- [ ] A token minted for a DCR client that sent `resource=https://api.bex.co/mcp` carries that audience and passes `/mcp`'s audience check (tested).
- [ ] A token for a `resource` that is not bex's own carries no granted audience and is still refused.
- [ ] `BEX_OAUTH_REQUIRE_AUDIENCE=1` and the w1/m67 F1 rule are unchanged.

## Out of scope

- Advertising `registration_endpoint` (w31/001).
- Pre-registered client ids such as Render's `claude`/`codex`/`cursor` (withdrawn from the proposal; bex's documented path is DCR).
