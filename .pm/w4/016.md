# `GET /v1/users` (Render's `whoami`) is unimplemented — 404

`w9/m2`'s Render CLI walk found bex-api has no route at all for Render's `GET /v1/users` (the current-caller-identity endpoint `render whoami` calls). Every other identity surface (session/API-key resolution, tenant membership) already exists internally — this is exposing it: name + email for the caller's Kratos identity, or an equivalent machine-caller shape for an API-key/OAuth2-client caller. Not in ADR018's ledger today (no Users/whoami row). Likely sub-hour once the identity-resolution plumbing (`core.Identity`, `internal/api/auth.go`) is reused rather than rebuilt — size it properly before starting in case the machine-caller shape needs real design.

Evidence + full repro harness: `docs/cli-compatibility-checklist.md` (root cause RC6).

Source: `w9/m2` (Render CLI compatibility), 2026-07-15.
