# 521 — The password show/hide button on the sign-in and Settings password fields is named "Show password" / "Hide password" in English even when the dashboard is in Chinese

Why: a Chinese-language user with a screen reader hears an English button name inside an otherwise Chinese form; every other label on the page follows the language, and this one is the bex-owned component that does not.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 125, 2026-11-05 UTC (`muse.env`, `bex-canary`); **minor** (i18n gap in an accessible name); ~20m.
- **Probe:** read-only, signed in. A text-and-attribute scan of 28 routes under `?lang=zh` (English phrases of ten or more characters in text nodes, `aria-label`, `title` and `placeholder`) found only three kinds of hits outside the filter below. Fresh-load check on `/settings`, the password toggle's accessible name:

  | URL | `<html lang>` | `<h1>` | password toggle `aria-label` |
  | --- | --- | --- | --- |
  | `/settings?lang=zh` | `zh` | `设置` | `Show password` |
  | `/settings?lang=en` | `en` | `Settings` | `Show password` |

  - The other hits were not filed: `delete my account` is the literal confirmation phrase the user must type (intentional); `Unlink github` (a `title`) is not in the dashboard source (`grep -rniE "unlink github" dashboard/src` → none), so it comes from Ory Elements' settings card; `Terminal input` on the shell tab is the terminal widget's own helper textarea.
  - The bex agent page also shows English sample prompts (`run a simplify skill`, `routine simplify`, a "Reply with a one-paragraph summary…" prompt); those are example task text and were not judged.
- **Root cause:** `dashboard/src/common/lib/ory/auth-form-overrides.tsx:57`: `UniqueIdPasswordInput` (the bex replacement for Ory Elements' password field, kept to give the input and the toggle distinct ids) sets `aria-label={visible ? "Hide password" : "Show password"}` as string literals. The file has no `useTranslation` call (`grep -n "useTranslation" common/lib/ory/*.tsx` → none), and the app's other strings come from the locale files (`common/locales/en.ts`, `zh.ts`). `common/lib/ory/config.ts:62-74` already passes the i18next language to Ory Elements for its own bundled strings, so the stock component would follow the language; the replacement lost that.
- **Fix (target behavior):** the toggle's accessible name follows the dashboard language in both states.
  - Read the two labels through the app's i18n (new keys in `common/locales/en.ts` and `zh.ts`, for example the `Show password` / `Hide password` pair with their Chinese equivalents), not literals. Keep the `aria-controls`, the distinct ids and the icon behavior.
  - The same component serves every Ory password field in the dashboard (sign-in, registration and Settings > change password), so one change covers all of them.
- **Tests:** a render test for `UniqueIdPasswordInput` under `zh` and `en` asserting the button name in both the hidden and the visible state; the existing override tests stay as controls.
- **Blast radius:** one component, two strings. Other hardcoded English in `common/lib/ory/` was not searched beyond this component.
- **Adjacent classes:** none (accessible name only; the `type`/visibility behavior is unchanged).
- **Unverified:** the sign-in and registration pages in zh (not signed out in this run; the component is shared, the same literal applies); a screen reader's reading; Ory Elements' own strings on the Settings card in zh (for example `Unlink github`), which are upstream and not this note's scope.
- **Render:** n/a (dashboard language).
- **Dedupe:** `grep -rliE "hide password|show password" .pm` finds no board item on this component (hits are unrelated databases-panel notes: `Show password` there is a translated string in `features/databases/locales/en.ts:559`). No DO_NOT_DO item applies; Ory Elements' own cosmetics are excluded and this is bex code.
