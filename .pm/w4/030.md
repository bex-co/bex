# `bex upgrade` — self-update command (update-channel phase 2)

Idea captured 2026-08-14 (CLI update-channel research session); promote to a milestone when w4/m34's notice ships and release cadence justifies it.

Built-in self-update for raw-binary installs, following the researched mature pattern:

- Library: `creativeprojects/go-selfupdate` (maintained fork; per-target asset selection, rollback on failure, hash/signature validators).
- Source: this repo's GitHub releases, filtered by the `bex-cli/v*` tag prefix (monorepo — `/releases/latest` is unreliable).
- Verification: `checksums.txt` (CI already produces it) at minimum; reuse the platform's cosign infrastructure to sign release assets and verify before replace.
- **Channel detection (gh lesson):** if the running binary lives under a package-manager path (brew Cellar), print the `brew upgrade` hint instead of overwriting files the package manager owns; never persist versioned paths into user config.
- Companion: a brew tap so mac users get the package-manager channel at all.

Prereqs from m34: bex-native `bexVersion` injection, release-listing/filter code (shared with the passive notice).
