# 616 — Saving the Health Check Path, Max shutdown delay or Pre-Deploy Command in Settings starts a deploy with no warning: no confirm, and a toast that says only "… updated."

Why: these rows look like plain saves. Their siblings (Start and Docker Command, Build Command, Root Directory, Dockerfile Path, Docker Build Context, Runtime, Port) say "The service redeploys…" before they save. Here a "Save changes" rolls the service at once, and for the Pre-Deploy Command that also runs the new command — typically a migration — immediately. The same field saved through REST `PATCH` only saves (w8/m135), so the two surfaces disagree about what a save does.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 230, 2026-11-12 20:41–20:52 UTC (`muse.env`, workspace `bex-canary`; pin `33e1b1e6117c`). **Minor**: the deploy itself is harmless for these two probed fields. For the Pre-Deploy Command, an unannounced run of a migration is worse, but that row is paid-only and was not probed. ~40m.

- **Root cause:**
  - The GraphQL setters behind these rows deploy by design. `SetHealthCheckPath` (`lego/backend/internal/apps/service.go:5101`), `SetMaxShutdownDelay` (`:5119-5130`) and `SetPreDeployCommand` (`:4732`) go through `recordedPatch` → `patchFetched` (`:5695-5702`), a tracked rollout.
  - w8/m135 t004 kept that on purpose — "The dashboard's GraphQL Settings saves stay an explicit save-and-deploy (the rows already say 'Saving starts a new deploy')" — but these three rows say nothing of the kind. `grep -rn "starts a new deploy" dashboard/src` finds only the Port and Runtime copy.
  - The dashboard rows give no `confirm`:
    - `dashboard/src/features/services/components/health-check-path-row.tsx:32-49`;
    - `max-shutdown-delay-row.tsx:35-60`;
    - the Pre-Deploy Command `EditableFieldRow` in `deploy-card.tsx:125-143`. Its sibling Start/Docker Command row in the same card passes `confirm={{ title, body: "services.startCommandConfirmBody" … }}` (`:146-175`, confirm at `:163`).
  - The toasts are bare (`dashboard/src/features/services/locales/en.ts:1322`, `:1362`, and `services.preDeploySuccess`).
- **Fix (target behavior):** a Settings save that starts a deploy says so before and after, like its siblings.
  - Each of the three rows passes `confirm` to `EditableFieldRow` (the existing prop, `editable-field-row.tsx:88`).
  - The titles: "Change the health check path to {value}?", "Change the max shutdown delay to {value} seconds?", "Change the Pre-Deploy Command to {value}?".
  - Each body states the redeploy. The pre-deploy body also says the new command runs before the new release goes live. Use the existing never-live variant when nothing has served yet.
  - Toasts: "… updated. A new deploy has started."
  - en and zh.
  - REST, GraphQL and MCP behavior is unchanged.
