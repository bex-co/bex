## Objective

Make gVisor's devpts line discipline echo like Linux's n_tty: when ISIG turns VINTR, VQUIT or VSUSP into a signal and ECHO is on, echo the character (`^` + `c ^ 0100` under ECHOCTL, the raw byte otherwise) before discarding it; and apply ECHOCTL on the normal echo path, so other typed control characters echo as `^X` (except TAB and NL, and START/STOP as Linux handles them).

## Context

- gVisor `pkg/sentry/fsimpl/devpts/line_discipline.go`: the signal branches (master ~:611-633) call `SignalForegroundProcessGroup` and `continue` with no echo; the echo path (~:747-751) writes raw bytes; ECHOCTL is read only for erase (~:689).
- Linux reference: `drivers/tty/n_tty.c` `n_tty_receive_signal_char` (~:1182-1192) and `echo_char` (~:895), which writes the ECHOCTL marker printed as `^` + `c ^ 0100` (~:644).
- gVisor compares PTY behavior against Linux in its syscall tests (`test/syscalls/linux/pty.cc`); add the cases there so they run on both.

## Steps

1. Patch against bex's pinned release (`release-20260622.0`) and against master.
2. Add syscall tests: cooked `^C`/`^\`/`^Z` echo with signals, `-echoctl` raw echo, `-echo` silence, ECHOCTL on a typed control character.
3. Run the tests on runsc and on native Linux.
