## Objective

Put the fix on the sandbox pool. Prefer the first stock gVisor release that contains it; until one exists, build runsc and `containerd-shim-runsc-v1` from the pinned release tag plus the patch, publish both to object storage with their sha512 (never into git: `DO_NOT_DO.md` #NO-ARTIFACTS-IN-GIT), and pin them in the machine template.

## Context

- runsc is installed at machine creation by `infra/clusterapi/overlays/hetzner-caph/sandbox-pool.yaml` (~:251-277: release URL, `RUNSC_SHA512`, `SHIM_SHA512`, containerd runtime config). CAPI reads a machine template only when it creates a machine; nothing applies the file automatically (`infra/clusterapi/overlays/hetzner-caph/README.md`), so the change lands with a sandbox-pool roll.
- Sandbox Pods must keep the gVisor RuntimeClass (`deploy/gitops/base/sandbox-pod-admission.yaml`).

## Steps

1. Build (or pick the upstream release), publish, record sha512s.
2. Update the machine template and roll the sandbox pool per the overlay README.

## Files

- `infra/clusterapi/overlays/hetzner-caph/sandbox-pool.yaml`, the overlay README if the procedure changes

## Acceptance criteria

- [ ] Every sandbox node runs the pinned runsc (`runsc --version` on the node matches the pinned build).
- [ ] A new sandbox starts and runs under `runtimeClassName: gvisor` as before.

## Out of scope

- Upgrading gVisor for unrelated reasons.
