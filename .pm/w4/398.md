# 398 — The Environment tab shows "Saved changes aren't live yet" twice: once in the service header, once above the editor

Why: the same sentence is printed twice on one page, about 200 px apart at 390 px. It reads as two separate problems and takes a second look to dismiss, on exactly the page where the user just saved.

**Severity:** minor (cosmetic duplication; the notice itself is correct and clears on deploy). **Estimate:** ~15m. **Source:** live `/qa-find-bugs w4` loop run e3v9, 2026-10-23 UTC (`muse.env`, `bex-canary`, pin `29d63e1f7bea`). Fixture: Free image web service `qa-20261023-e3v9-echo` (`srv-dbdua6r17lic73al6nv0`, `mendhak/http-https-echo:35`). It was deleted (`GET` → `404`); session revoked.

## Probe

1. Environment → Edit:
   - "Add variable ▸ Import from .env" with a tricky dotenv (`export`, double quotes with `\n`, single quotes with `$HOME`, inline `#` comment, empty value, duplicate key). It parsed correctly.
   - A key rename and a secret file (27 bytes).
   - Then "Environment save options ▸ Save only". The toast said "Environment saved without a deploy…", no deploy row was opened, and the running process was unchanged.
2. `/services/<id>/env` at 390 × 844 then shows two `role="status"` paragraphs with identical text "Saved changes aren't live yet. Use a standard deploy to apply them.", at `top=345` (service header) and `top=558` (above the editor). Screenshot (local): `.playwright-mcp/qa-env-dup-1.png`. The overview and Deploys tabs show it once.
3. Manual Deploy ▸ Deploy latest image → `live` in about 70 s. The process then saw every saved value exactly (`QA_IMP_B` with a real newline, `QA_IMP_E=""`, `QA_REN=k1`, `QA_KEEP=from-import`), and both notices cleared. Everything except the duplication worked.

## Root cause

Both renderings came in `649df6ca8` (w4/m184):

- `dashboard/src/features/services/components/service-detail-header.tsx:307-313`: the header, shown on every service tab.
- `dashboard/src/routes/services.$serviceId.env.tsx:51-57`: the Environment route, which renders the same `undeployedChangesHintKey(service)` again.

## Fix

Keep the header notice, the one every tab shares, and drop the route-level copy. Or, if the Environment tab needs its own wording (e.g. naming the save), make it distinct and hide the header copy on that tab. Add a test that the env route renders the notice exactly once. Check the suspended variant (`services.undeployedChangesSuspendedHint`) too.
