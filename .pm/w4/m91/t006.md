## Objective

Pin the fixed behavior with meaningful tests that fail if `disk_capacity` reverts to the physical kubelet series.

## Context

- The bug survived because `disk_capacity` was wired to `kubelet_volume_stats_capacity_bytes` with no assertion tying capacity to the logical `StorageGB`.

## Steps

1. Backend: assert `disk_capacity` equals the logical `StorageGB` (as bytes) for a Postgres and a KeyValue fixture, and that `disk` (used) still comes from the kubelet used series.
2. Assert REST/GraphQL/MCP return identical `disk_capacity`.
3. Assert the `PersistentVolumeFillingUp` alert expression still references `kubelet_volume_stats_capacity_bytes` (guard against the fix leaking into ops alerting).
4. Dashboard: a test that the panel's capacity label/reference line reflect the provided logical value.

## Acceptance criteria

- [ ] A test fails if `disk_capacity` is sourced from `kubelet_volume_stats_capacity_bytes` again.
- [ ] Postgres + KeyValue both covered; used-series and ops-alert regressions guarded.

## Out of scope

- Trivial/tautological coverage padding.
