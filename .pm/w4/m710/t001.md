## Objective

Build one component that shows a higher level of inbound IP rules read-only, as Render's "Affected by:" section does, and mount it in the service Networking panel above the service's own editor: the workspace level always, and the environment level when the service belongs to one.

## Context

- Render's bundle `index-D5V4ZgbE.js`. Find it by the string "Affected by:".
  - The header has the label "Affected by:", a breadcrumb of Workspace and (when the resource is in an environment) Environment, and a "View rules" link that opens in a new tab. The link goes to the environment's page for the environment level and to the workspace's rules for the workspace level.
  - Below the header is a table with the columns Source (mono) and Description. When the level's list is empty, an inline warning replaces the table: "All internet traffic is blocked by `<Workspace|Environment>` inbound IP rules."
  - Render shows a level whenever its list was read. The workspace level is read on everything but the workspace itself. The environment level is read on everything but an environment, and only when the resource has an environment.
- bex reads:
  - `features/workspaces/hooks/use-workspace-ip-allow-list.ts` (`Workspace.ipAllowList`). A workspace that never set rules reads Render's seeded allow-all.
  - The environment's `ipAllowListEntries` (`features/environments/api/environments.graphql`).
  - The service's `environmentId` (`features/services/api/server.graphql:104-108`).
- `dashboard/src/features/services/components/service-networking-panel.tsx` holds today's panel. `routes/services.$serviceId.settings.tsx` mounts it.
- Where each level is edited:
  - The workspace: `/network-access`, which redirects to `/workspace/settings#inbound-ip-rules` until w3/155 ships its page.
  - The environment: its settings page's Networking card (`features/environments/components/environment-networking-card.tsx`).

## Steps

1. Write the component in `dashboard/src/common/components/`. It takes a level, the level's entries, and an optional environment link target.
2. Read the workspace and environment lists for the service and render one block per level above the editor. A service with no environment gets only the workspace block.
3. While a level is still loading, claim nothing about it, as the panel already does for the service's own list.

## Files

- `dashboard/src/common/components/` (new component)
- `dashboard/src/features/services/components/service-networking-panel.tsx`
- `dashboard/src/routes/services.$serviceId.settings.tsx`

## Acceptance criteria

- [ ] A service in an environment shows a workspace block and an environment block, each with its rules or the blocked warning, above its own editable rules.
- [ ] A service outside any environment shows only the workspace block.
- [ ] Each View rules link opens where that level is edited, in a new tab.

## Out of scope

- Moving the workspace's own rules to a Network Access page (w3/155).
