# 611 — Saving a maintenance page URL toasts "Maintenance mode enabled." or "Maintenance mode disabled." although the save changed only the URL

Why: the toast should confirm what the click did. After saving only the custom page URL, it announces a mode change that did not happen. When maintenance mode is off, it reads "Maintenance mode disabled." for a URL the user just set, which suggests the save turned something off.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 217, 2026-11-12 18:09–18:14 UTC (`muse.env`, workspace `bex-canary`; pin `3c07e6784552`). **Minor** (copy; the saved state and the served page are right). ~20m.
- **Fixture:** Starter web service `qa-20261112-r217-maint` (`srv-dbr01nup7tds73fq63ig`, `traefik/whoami:v1.10`). Deleted afterwards.
- **Probe** (Settings → Maintenance Mode):
  1. **Enable.** Toggle → "Enable maintenance mode?" → Enable. The toast reads "Maintenance mode enabled." (18:11:16).
     - REST `serviceDetails.maintenanceMode` reads `{"enabled":true,"uri":""}`.
     - `curl https://qa-20261112-r217-maint.onbex.co/` → `503`, `cache-control: no-store`, the default page.
  2. **Save a URL while enabled.** Edit maintenance page URL → `https://example.com/` → Save changes.
     - The toast reads **"Maintenance mode enabled."** (18:12:16, 60 s after the enable toast, so it is this save's).
     - REST reads `{"enabled":true,"uri":"https://example.com/"}`; `curl …/some/path` → `503` with `<title>Example Domain</title>`.
     - Events record `maintenance_mode_uri_updated {"fromURI":"","toURI":"https://example.com/"}` and no new enable event.
  3. **Disable.** Toggle off → "Maintenance mode disabled." (correct), and `curl` → `200`.
  4. **Save a URL while disabled.** Edit URL → `https://example.org/` → Save changes.
     - The toast reads "Maintenance mode disabled." (the same text as step 3's toast, so this one is confirmed by the code rather than by timing).
     - REST reads `{"enabled":false,"uri":"https://example.org/"}`, and the event is `maintenance_mode_uri_updated`.
- **Root cause:**
  - `useMaintenanceMode` picks the toast from the `enabled` argument alone (`dashboard/src/features/services/hooks/use-maintenance-mode.ts:44-48`: `enabled ? maintenanceModeEnabledSuccess : maintenanceModeDisabledSuccess`).
  - The URL editor's save re-applies the current on/off state with the new URL (`dashboard/src/features/services/components/maintenance-mode-section.tsx:95-97`, `onSave={(value) => setMaintenanceMode(serviceId, enabled, value)}`). So a URL-only save reports the mode it kept.
- **Fix (target behavior):**
  - The toggle keeps "Maintenance mode enabled." / "Maintenance mode disabled." (`:77`, `:111`).
  - A URL save says what changed:
    - "Maintenance page saved." for a URL set or changed;
    - "Default maintenance page restored." when it is cleared.
  - Let the caller pass the success message, or add a `kind: "toggle" | "uri"` argument. The hook has 1 production consumer (the section), with 3 call sites.
  - en and zh.

  - the toggle's two messages are unchanged.
