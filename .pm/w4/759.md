# The inbound IP rules editors offer Render's "Use my IP address", which fills in the viewer's own address

Why: Render parity. On Render, allowing yourself is one click on any inbound IP rules editor; on bex you have to look your address up elsewhere and type it.

- **Render (dashboard bundle `index-D5V4ZgbE.js`, read 2026-11-27, the Networking component's editor):** on mount the editor asks `https://api.ipify.org` for the viewer's address and keeps it only when it is a dotted IPv4 address. A rule row whose CIDR is empty shows a "Use my IP address" button inside its CIDR field, unless some row already starts with that address. The button fills the row with `<address>/32` and its description with the signed-in user's `name (email)`, or the email alone. It is the same editor on a web service, a static site, a Postgres primary, a Key Value instance, an environment and the workspace's Network Access page. The address is used for nothing else: the Validate IP address field does not prefill it.
- **bex:** `IPAllowListEditor` (`dashboard/src/common/components/ip-allow-list-editor.tsx`) has no such button. Its new rules go through the add row (`203.0.113.0/24` placeholder), not an empty table row, so the button belongs in the add row's CIDR field.
- **Decide while building, and record in ADR018:** where the address comes from. `api.ipify.org` is a third party and would need adding to the dashboard's CSP `connect-src` (`dashboard/server/security-headers.ts`). bex's own edge already knows the address (`https://dashboard.bex.co/cdn-cgi/trace` answers `ip=`; or a bex-api echo). Either way the address must be the one the edge sees, which is what the rules match.
- **End state:** every editor that mounts `IPAllowListEditor` for inbound rules shows "Use my IP address" in its add row while the viewer's IPv4 address is known and not already listed, and one click fills `<address>/32` with Render's description. A test covers the shown, hidden and filled states, in all 8 locales.
- **Size:** about 45m.
- **Source:** w4/m710 t005's parity check, 2026-11-27.
