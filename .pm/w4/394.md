# 394 — Creating a protected (or isolated) environment through the API silently blocks all public traffic to it: an omitted `ipAllowList` is written as `[]`, which is deny-all

Why: `POST /v1/projects` with Render's required `environments` array, or `POST /v1/environments`, setting only `protectedStatus: "protected"` is how a Render CLI/Terraform/API user creates a production environment. On bex every public service and static site placed in it then answers `403 Forbidden`, with nothing telling the caller why.

**Severity:** major (a whole environment's public traffic is refused after a create the API reported as 201; nothing warns except the environment settings card). **Estimate:** ~1h. **Source:** live `/qa-find-bugs w4` loop run p2q8, 2026-10-23 UTC (`muse.env`, `bex-canary`, pin `fa8ac5bba24a`). Fixtures:

- Project `qa-20261022-p2q8-proj` (`prj-dbdee8fsf6rc738q75lg`).
- Environments `production` (`evm-dbdee8fsf6rc738q75m0`), `staging` (`evm-dbdef088dkas73a0v470`), `prot2` (`evm-dbdeg7nsf6rc738q75o0`) and `iso2` (`evm-dbdeg7g8dkas73a0v4c0`).
- Static sites `qa-20261022-p2q8-site` and `qa-20261022-p2q8-site2` (`srv-dbdef008dkas73a0v45g`; public Git `bex-co/bex` `main`, root `examples/static-site`).

All were deleted (`GET` → `404`); session revoked.

## Probe

1. `POST /v1/projects {"name":"qa-20261022-p2q8-proj","ownerId":"tea-daif693dqjvc73e7as3g","environments":[{"name":"production","protectedStatus":"protected"}]}` → `201`. `GET /v1/environments/evm-dbdee8fsf6rc738q75m0` → `"protectedStatus":"protected","ipAllowList":[]`.
2. `POST /v1/environments {"name":"staging","projectId":"prj-dbdee8fsf6rc738q75lg"}` (no ACL fields) → `ipAllowList: [0.0.0.0/0, ::/0]` (the seed), as expected.
3. `POST /v1/environments {"name":"prot2",…,"protectedStatus":"protected"}` → `ipAllowList: []`. `{"name":"iso2",…,"networkIsolationEnabled":true}` → `ipAllowList: []`.
4. Control: `PATCH /v1/environments/<staging> {"protectedStatus":"protected"}` → the allow-all pair is kept. Only the create paths lose it.
5. Served behavior, with the same live static site (`deploy live` at `04:50:48Z`):
   - In `production` (`[]`): `GET /` → `403 Forbidden`, and `GET /index.html` → `403`.
   - Moved to `staging` (`POST /v1/environments/<staging>/resources`): `200`.
   - Moved back: `403` again.
6. The dashboard's environment settings card does say "No rules — public members of this environment will DENY all traffic. Add 0.0.0.0/0 and ::/0 to allow everything." No create response or Render client ever sees that.

## Root cause

- An empty list means deny-all since w4/m28 (`core/cidr.go:207-217` `DefaultEnvironmentAllowList`). The store seeds new environments with it (`store/environments.go:85-92`).
- **Environment create:** `environments/service.go:232-237` `hasACL` is true for any of `protectedStatus`, `networkIsolationEnabled` or a non-nil list. `CreateWithACL` (`:599-646`) then calls `applyACL` (`:1295-1302`), which turns a nil list into `[]` and full-replaces the seed. REST `POST /v1/environments` (`environments/rest.go:185`), GraphQL (`graphql.go:132`) and MCP (`mcp.go:103`) all share this.
- **Project inline environments:** `projects/service.go:477-485` calls `g.SetEnvironmentACL(…, input.IPAllowList)` with the nil list whenever `protectedStatus`/isolation is set.
- The Blueprint grouping path already avoids this on purpose. `apps/deploy.go:1823-1829` passes the environment's existing list, with the comment "passing nil would full-replace to empty, which is deny-all".

## Fix (target behavior)

- On every create path (REST/GraphQL/MCP environment create, REST project inline environments), an **omitted** `ipAllowList` keeps the seeded allow-all pair, exactly like PATCH. Only an explicit `[]` is deny-all.
- Mirror the Blueprint path: pass `nil`-means-unchanged into the ACL write, or have `SetEnvironmentACL` accept a nil list as "leave as is".
- Regression tests for both inline and standalone creates with `protectedStatus` only and `networkIsolationEnabled` only (expect the seed). Add an explicit `[]` control (expect deny-all) and the Blueprint path (unchanged).
- Existing environments created this way can't be told apart from a deliberate `[]` in the data. Decide whether to surface them (e.g. an audit query listing environments with an empty list and a public member) rather than silently rewriting them. Record the choice.

**Unverified:** GraphQL `createEnvironment` and MCP `create_environment` with `protectedStatus` only (they share `CreateWithACL`, so reasoned, not probed); the dashboard's own New Environment dialog (it sends no ACL fields, so it is reasoned unaffected); datastores in such an environment (the same layer applies per `w4/018`, not probed).
