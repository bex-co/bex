## Objective

`w4/m8` shipped this surface with "no live-cluster browser check of the mint→authenticate round trip" and `w4/m13` with "the TTL's live-introspection check needs a running Hydra". Those two gaps are why a credential you cannot use went unnoticed for two months. Close them with a test rather than another QA pass.

## Context

The round trip, as measured this run: mint → (client_id + secret) → `POST /oauth2/token` `client_credentials` → `Authorization: Bearer <token>` → 200 → revoke → issued token 401s **and** re-exchange fails `invalid_client`.

Both halves of revocation matter and both worked live, so both are worth pinning: the token dies because the introspection cache honours `w4/m31`'s revocation epoch, and re-exchange dies because Hydra no longer knows the client.

`lastUsedAt` moved from `""` to a timestamp after the authenticated calls (`w4/m13`'s throttled `TouchAPIKey`), which is also worth an assertion since it is the only evidence a user has that a key is in use.

## Steps

1. A backend test for the whole round trip against a Hydra test double or the real one where CI has it. If a true Hydra is unavailable in CI, assert the parts that do not need it (client creation args including whatever `Scope` t002 decides, revocation path, `TouchAPIKey`) and say plainly which leg stays uncovered rather than implying full coverage.
2. A dashboard test that the mint dialog exposes both id and secret and that the table exposes the id.
3. Assert the secret's one-time discipline: absent from every list read.
4. Assert `lastUsedAt` advances on use.
