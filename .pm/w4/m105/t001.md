## Objective

The dashboard shows a minted key's secret once and never shows the `client_id` it must be paired with, so the credential cannot be used without querying GraphQL by hand. Surface the id, and say what the credential is.

## Context

- The one-time dialog, read from the live accessibility tree: `dialog "API key created"` → `paragraph: Copy this key now — you won't be able to see it again.` → one `code` element (26 chars) → `Copy`, `Done`, `Close`. No id, no endpoint, no grant type.
- The keys table columns are Name / Created / Created by / Last used / Actions; the only per-row control is `Revoke`. The third column is the *creator's* subject, not the client id (and is itself raw — `w4/069`).
- The id is not a secret and is already available: `apikeys/service.go:482` builds `APIKey{ID: c.ClientID, Name: c.ClientName, Secret: c.ClientSecret}`, `:539` clears the secret on list reads only, and GraphQL `apiKeys { id }` returns a 36-char UUID today.
- Using the secret as a bearer — the natural reading of "API key" — returns a bare `401 unauthorized`, which gives the user nothing to work from.

## Steps

1. Add the `client_id` to the mint dialog beside the secret, with its own copy button, clearly labelled as the id rather than the secret.
2. Add it to the table (a column, or a copy-id action) so a key minted earlier is still usable. This is the half that matters for keys that already exist — including the two currently in this workspace.
3. Say what the credential is, once, where it is minted: an OAuth2 `client_credentials` client, the token endpoint (`https://oauth.bex.co/oauth2/token` in production — take it from configuration, not a literal), and the exchange. The existing "Set up the CLI." link stays, but the CLI uses a device flow and does not help someone scripting against the API.
4. Consider whether the 401 for a raw-secret bearer can name the problem. It must not become an oracle — do not confirm that a presented value is a real client secret — but "this looks like a client secret; exchange it at the token endpoint first" is safe if it is emitted for *any* unrecognised bearer shape rather than only for real ones. Decide and record.
5. Keep the secret's one-time discipline exactly as it is: shown once, never returned by list.
