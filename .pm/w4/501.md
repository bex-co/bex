# 501 — The Web Shell instance picker has no accessible name

Why: a screen-reader user who lands on the Shell tab hears an unnamed combobox ("Any ready instance") and cannot tell that it chooses which instance the terminal attaches to. The visible "Instance" text beside it is not associated with it.

**Severity:** minor (a11y) · **Estimate:** 15m · **Worker:** worker4 · **Status:** todo

- **Source:** live `/qa-find-bugs w4`, production, 2026-11-05 19:38–19:44 UTC, round 96. Workspace `bex-canary`. Prod pin `cc3c51e12952`; research on main `03e850853`.
- **Probe:**
  1. Created the background worker `qa-20261105-shell96` (`srv-dbmdmi4rv9ic73d23fm0`, busybox `sleep 3600`); its deploy went Live.
  2. On `/services/srv-dbmdmi4rv9ic73d23fm0/shell`, `page.locator('main').ariaSnapshot()` shows `text: … Instance` · `combobox: Any ready instance` (no name) · `text: Connected` · `textbox "Terminal input"`.
  3. Control (the Shell journey itself is healthy): typing `echo qa96-$((6*7)); hostname` into the terminal printed `qa96-42` and the pod hostname.
- **Root cause:** `dashboard/src/features/services/components/web-shell-panel.tsx:39-49`.
  - The label `services.shellInstanceLabel` ("Instance") is a bare `<span>`.
  - The Radix `SelectTrigger` has no `id`/`aria-labelledby`/`aria-label`, so the combobox's name is empty and only its value is announced.
- **Fix:**
  - Target name: "Instance".
  - Give the span an id (`useId`) and set `aria-labelledby` on `SelectTrigger`, or render a `<Label htmlFor>`.
  - Add a test asserting `getByRole('combobox', { name: 'Instance' })`.
- **Blast radius:**
  - One component, `WebShellPanel`, mounted once at `service-shell-page.tsx:62`.
  - `grep '<SelectTrigger'` without `aria-label`/`id` returns 22 sites across the dashboard; many may be labelled through a wrapping form field.
  - Cause unverified for those: audit them with the accessibility tree in the same change, and file any unnamed ones separately rather than assuming.
- **Unverified:** the other 22 `SelectTrigger` sites; the narrow-mobile Shell layout.
- **Render:** n/a (accessibility).
- **Dedupe:**
  - `grep -ril "web shell\|shellInstance" .pm` with label/accessible-name terms found no item on this control.
  - DO*NOT_DO #18 concerns ephemeral shells, not this picker. No fix on main (`git log -- web-shell-panel.tsx` last touched by the prettier pass `52da6913c`).
