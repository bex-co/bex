# Untouched static-rule editors become dirty on refresh and can overwrite newer saved rules

Why: an untouched editor presents old rules as an unsaved change after receiving a newer saved configuration, and its enabled Save can undo that configuration.

**Severity:** major — unintended configuration rollback after an explicit stale Save. **Estimate:** 55m (caller/baseline audit 10m, guarded synchronization 15m, behavior tests 20m, Simplify and owned live replay 10m). **Status:** open. Source: continuous functional `$qa-find-bugs w4`, pass a267, 2026-10-11 local / 2026-10-12 UTC, muse.env login helper.

Goal: dependable hosting configuration editing under [ADR008](../../docs/ADR008-vision.md) and [ADR029](../../docs/ADR029-static-sites.md). This repairs existing rule editors.

## Reproduction and observed impact

Owned Free static fixture: `qa-20261011-a267-static`, `srv-db6711c5c1ms739bus7g`; public repository `https://github.com/bex-co/bex`, branch main, root `examples/static-site`, publish directory `.`, no build command, Auto-Deploy off. The original deploy `dep-db6711c5c1ms739bus80` stayed Live at `rev-1`; rule edits did not republish.

1. Save two harmless response-header rules, in order: `/*.yaml / X-QA-A267-Overlap / qa-a267-root-first` and `/* / x-qa-a267-overlap / qa-a267-other-tab-last`.
2. Fresh-load tab A at `/static/<id>/headers`. At **05:40:17.319Z**, A displays those saved rows and Save headers is disabled. Make no edit in A.
3. Open the same owned site's Headers in ordinary tab B. Change only the second value to `qa-a267-other-tab-repeat` and Save. The actual SetStaticHeaders request returns HTTP 200 with that new value at **05:40:19.172Z**. Close B and bring A to the foreground.
4. A's actual Server refresh returns the new saved value at **05:40:56.938Z**. At **05:40:56.939Z**, A still displays `qa-a267-other-tab-last`, Save headers is enabled, and Cancel appears. A received the right server data; its untouched draft remained old.
5. An independent read at **05:41:22.094Z** and native public GET at **05:41:49.043637Z** confirm the new saved value. Without changing any input in A, click its now-enabled Save. The actual SetStaticHeaders request submits the old value and returns it at **05:42:09.102Z**. Native public GET at **05:42:49.520525Z** now emits the old header. The 795-byte body and SHA-256 are unchanged. **A stale explicit Save rolled back B's successful configuration; no spontaneous server write is claimed.**

Headers was reproduced from three freshly loaded editor starts: the initial desktop observation at **05:35:09.817Z** became stale/dirty by **05:39:53.408Z** (its exact transition was not captured), the fully observed desktop replay above, and fresh **390×844** mobile at **05:42:51.453Z**. In the mobile replay B saves `qa-a267-mobile-latest` at **05:42:52.664Z**; A's observed poll returns it at **05:43:22.407Z**, while A retains the previous value and enables Save. Explicit Cancel at **05:43:22.476Z** adopts the latest saved value, disables Save, and removes Cancel.

The sibling Redirects/Rewrites editor was independently reproduced once from a fresh desktop load. Seed one Rewrite `/qa-a267-alias → /render.yaml`; A is clean at **05:44:27.997Z**. B saves destination `/qa-a267-missing.yaml` at **05:44:29.726Z**. A's actual Server poll returns that destination at **05:44:59.066Z**, but A still shows `/render.yaml`, enabled Save routes and Cancel. Cancel adopts the new destination at **05:44:59.621Z** and returns to clean. A stale Routes Save was not submitted; the confirmed public rollback belongs to Headers.

**Expected:** an untouched draft adopts a newly received saved rule set and stays clean. A genuinely edited draft survives refresh. Cancel restores the latest saved rows. Retain acknowledged local-save normalization and newer edits typed while Save is pending.

## Root cause and bounded fix

Research baseline: current main `ad36a7521`. Pulling from the previous filing `f74be0540` changed no target editor, shell or useServer code.

- `dashboard/src/features/services/components/static-site-section.tsx:190–192,337–339`: each editor initializes local draft from saved props only on mount, then compares the unchanged draft directly against the current props. New authoritative rows make an untouched old draft look dirty. There is no guarded adoption of incoming saved props.
- `static-site-section.tsx:304–313,430–439`: the false dirty state exposes Cancel and enables the bulk replacement Save; Cancel's explicit adoption of current props works. `:72–78` adopts accepted rows only after a local Save, preserving a newer local array by reference. That existing successful-save behavior must remain.
- `static-edge-rule-page.tsx:44–45,63–66` consumes the cached Server document with `poll:false` and keeps the editor mounted with ready data. The designated polling owner is `service-detail-layout.tsx:44`; `use-server.ts:49–61,68–76` reads the same document and converts updated cache data. `common/lib/polling.ts:3–11,47–60` promises external freshness and uses a 30-second settled cadence. The secondary page's lack of its own timer does not prevent incoming props.
- `routes/services.$serviceId.headers.tsx:19–29` and `services.$serviceId.redirects.tsx:19–29` key editors by service identity. That stable key correctly preserves drafts through a poll; keying by saved rows would instead discard real edits.
- Installed/locked **React/react-dom 19.2.3**, **Apollo Client 4.1.3**, **TanStack Router 1.170.25** were checked. React's installed `react-dom/cjs/react-dom-client.development.js:8264–8296` initializes state on mount; its update dispatcher at `:26505–26511` uses retained state. [React's primary useState reference](https://react.dev/reference/react/useState) also explains that later initial-state arguments do not reset state. This is the application's synchronization policy, not a framework defect.
- `features/services/lib/status.ts:146–168` already maps headers/routes into the editable view shape. `hooks/use-static-site.ts:75–115` correctly sends the complete submitted list, refetches, and returns accepted mapped rows. Backend `lego/backend/internal/apps/graphql.go:1744–1763` delegates to `apps/service.go:5126–5142,5164–5180`, whose contract is replacement of the whole ordered set. The payload and backend result agree.

Implement guarded saved-baseline synchronization locally for both editors: distinguish a draft that still matches its previous accepted baseline from real local edits before adopting a newly received rule set. Update untouched rows to the newest saved set; preserve dirty rows and focus through refresh; keep the latest saved set available to Cancel. Preserve identity reseeding, accepted normalization, exact header values, add/remove/order, empty/invalid-row blocking, pending-save newer-draft protection and refused-save retry. Reuse the existing local save helper or a small local helper where useful. Do not add timers, remount on rule values, or use unconditional prop-to-draft reset effects.

The existing full-set API contract is sufficient for this fix; no server revision, compare-and-swap feature, backend change, global Apollo change or input-primitive change is required.

## Caller audit, dedupe and verification work

Production census: **two editor implementations**, **one production mount of each**, **two page wrappers**, **four route entrypoints**. `static.$serviceId.headers.tsx` and `static.$serviceId.redirects.tsx` reuse the two Service pages. Both pages use the same StaticEdgeRulePage shell. The static-site Settings card is the other useStaticSiteMutations consumer, using the separate publish-path callback; preserve it. Non-static services retain the existing static-only route guard. The live reproductions above use canonical `/static` URLs; the `/services` entrypoints, other resource families, REST/MCP rule writes, unavailable/refused reads and transport failures were source traced rather than independently induced.

Searched open/blocked/done board text across all workstreams for static/header/redirect draft, dirty, refresh, external and concurrent edits; scanned the titles of all **26** active non-blocked milestone READMEs and read DO_NOT_DO. Target history plus the last 40 product commits show no landed pristine-sync fix.

- **w4/done/136** fixes canonical-row adoption after a successful local whitespace-normalized Save. That behavior works here. Its note explicitly leaves concurrent external edits unprobed and warns against unconditional resets. This finding is a separate original synchronization gap, not a claimed regression of its accepted-save contract.
- **w1/done/m153** preserves mounted ready editors and drafts through loading refreshes. The editor stays mounted here; retaining an untouched stale draft after changed saved data is the additional gap.
- **w4/253** owns lost dirty PostgreSQL parameter edits caused by a saved-value key. This item's stable static editor instead retains an untouched stale draft. Share the preservation principle, not the product implementation scope.
- **w4/done/m150** owns runtime header matching; **w4/done/235** owns readable mobile fields. Their observed serving and layout controls remain working. The active static publication milestone **w8/m59** is unrelated.

[Render header documentation](https://render.com/docs/static-site-headers) and [redirect/rewrite documentation](https://render.com/docs/redirects-rewrites), checked 2026-10-12 UTC, establish these editable rule surfaces and request-path behavior. They do not specify cross-tab draft synchronization or duplicate-header ordering. No authenticated Render UI comparison or ordering parity claim is made.

Verification for the fix:

1. With real editor parents and the installed Apollo cache, refresh a clean Header and Routes editor to a changed saved list; expect the new exact rows, disabled Save and no Cancel. The original code must fail these assertions.
2. Refresh a genuinely dirty draft with both unchanged and changed saved lists; retain draft values, focus and controls. Cancel must adopt the latest saved set. Cover empty→nonempty and nonempty→empty saved sets, row order, and identity navigation.
3. Preserve accepted-normalized Save, a newer draft typed while Save is pending, refused Save retaining a retryable draft, and successful read with no saved rows leaving the draft intact. A naive unconditional reset or saved-value key should fail preservation cases.
4. Verify all four route entrypoints with their shared consumers and static-only guard. Run appropriate dashboard tests/typecheck/lint, Simplify the changed code, and replay desktop plus mobile against a new owned Free static fixture. Keep native header and rewrite response controls; clean up the fixture/session.
