# The sidebar jumps 12 px when the workspace switcher finishes loading

Why: on every dashboard page the left nav (Projects, Blueprints, …) first renders 12 px lower than its settled position and then snaps up when the workspace list arrives. This breaks the repo rule that a preloading skeleton matches its loaded state.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop run 6a49, 2026-10-30 UTC (`muse.env`, pin `25b99d8a373a`); **minor**, ~15m. Dashboard chrome; AGENTS.md "Dashboard preloading skeletons must match their post-loading contents".
- **Repro:** at 1440×900, open `https://dashboard.bex.co/` while holding the GraphQL requests (Playwright: `page.route('**/graphql', r => held.push(r))`, then reload) and measure. Then release the requests and measure again.

  | state | sidebar header height | "Projects" nav link y |
  | --- | --- | --- |
  | loading (switcher placeholder, 151×32) | 60 px | 64 |
  | loaded (switcher button, 32 px) | 48 px | 52 |

  Screenshots (session-local): `.playwright-mcp/qa-overview-pending-1440.png` and `qa-overview-ready-1440.png`. Every nav item sits 12 px lower in the first one.

- **Root cause:** `dashboard/src/features/workspaces/components/workspace-switcher.tsx:78-83`. The loading branch renders `<div className="flex items-center gap-2 px-2 py-1.5"><Skeleton className="h-8 w-full" /></div>`. The `py-1.5` wrapper adds 6 px above and below the 32 px placeholder. The loaded branch is a bare `SidebarMenu > SidebarMenuItem > SidebarMenuButton` (default `h-8`) with no vertical padding, so the header grows from 48 to 60 px only while loading. `SidebarBrand` (`common/components/dashboard-layout/sidebar-brand.tsx`) is the switcher's only caller, and it renders on every sidebar variant (dashboard, project, service).
- **Fix:** make the loading branch the loaded button's box. Drop `py-1.5`, and either drop `px-2` or keep it only if the loaded button has the same inset, so the placeholder occupies exactly the `SidebarMenuButton` footprint: 32 px tall, same width. Optionally add the initial-badge and chevron placeholders so the row reads like the loaded switcher.
- **Tests:** a component test that both branches render a root of the same height class (`h-8`) with no extra vertical padding on the loading branch. Manual check at 1440×900 and 390×844 (inside the mobile Sheet) that the nav link y is identical before and after load.
- **Not covered here:** the Overview content skeleton (`700be10e8`) was not exercised on this account. The Overview body came from the server-rendered or cached response, so only the switcher was in a loading state.
- **Dedupe:** `.pm` has no switcher-skeleton item. `w9/done/m88` covered the `/new/workspace` page skeleton, not the sidebar. The last change to the switcher's layout was `053afd020` ("compact 48px topbar + matching sidebar header"), which set the 48 px header but left the loading branch's padding. No DO_NOT_DO item applies.
