# 582 — A native build's `==> Build successful 🎉` prints before the image push, and a build command BuildKit served from its cache still reads "Running build command"

Why: w4/m324 made a native build's log read like Render's, but two lines still say something that isn't so. The success line prints when BuildKit finishes, so a push that then fails reads "Build successful" followed by a failure. Render prints it after `==> Uploading build...` and `==> Uploaded in …`. A build command step BuildKit served from its layer cache (a redeploy of the same commit and env with the build cache on) prints `==> Running build command '<cmd>'...` and no output, though nothing ran.

- **Source / severity / estimate:** w4/m324 t005 and t006 (`/loopx w4`, 2026-11-11). **Minor** (log wording). ~45m.
- **Where:** `nativeBuildSucceeded` is appended to the buildkit phase's script (`lego/operator/internal/build/build.go`, `BuildJob`). The push phase is a bare `skopeo` command with no shell, so moving the line means wrapping it, or printing it from the last phase that succeeds. The cached step shows as `#N CACHED` right after its header in `nativeLogDisplay`'s input.
- **Fix sketch:**
  - Print the success line (and Render's `==> Uploading build...` / `==> Uploaded in Ns`, if they're wanted) from the push phase, after `skopeo copy` succeeds, for native builds only.
  - For a cached command step, defer the narration until the step's first output or `DONE`. On `CACHED`, print Render-consistent wording, or nothing; capture Render's behaviour on an unchanged redeploy first.
- **Dedupe:** w4/m324 (the filter itself); `grep -rn "Uploading build" .pm` finds no item.
