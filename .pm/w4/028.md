# Extract a shared keyed-token-bucket rate limiter — three near-identical hand-copies now exist

← filed by w4/m31/t004's `/simplify` pass (reuse + simplification review), 2026-07-16.

Three packages now each hand-roll the identical shape — `mu sync.Mutex` + `entries map[K]*entry{lim *rate.Limiter; last time.Time}` + `lastSweep time.Time`, identical idle/sweep constants (`10m`/`5m`), identical `New*(rpm, burst)` zero/negative-rpm and `burst<=0 → ceil(rpm)` defaulting, identical `bucket()` lazy-create + periodic sweep, identical `Reserve()`/`Cancel()`/wait-seconds logic:

1. `lego/backend/internal/deploys/deployhook.go` — `DeployHookRateLimiter`, token-keyed (pre-existing, predates this milestone).
2. `lego/backend/internal/api/ratelimit.go` — `RateLimiter`, identity/IP-keyed (pre-existing).
3. `lego/backend/internal/cliauth/ratelimit.go` — `DeviceRateLimiter`, IP-keyed (new in w4/m31/t002).

`internal/core` is the leaf every one of the three already imports (it already hosts the analogous `TTLCache[V]` generic, `internal/core/http.go:184`), so a `core.KeyedRateLimiter[K comparable]` (or similar) has zero import-cycle cost and would let all three derive from one implementation, keeping only their genuinely different bits — the keying strategy and the throttled-response dialect — in their own packages.

**Declined to fix inline in w4/m31**: touches `internal/deploys/deployhook.go`, a feature package outside this milestone's scope, and this milestone's own guidance (security-critical auth-adjacent code) was to prefer caution over cleverness. Not a blocking defect — all three copies are independently correct and tested.
