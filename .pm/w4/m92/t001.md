## Root cause and proposed fix

Independent repeated build: Manual Deploy → Deploy latest commit opened `dep-daf1skd6p8mc739aop60`, which reached Live at 19:17 PDT. Its fresh RUN logged `#10 0.108 QA_BUILD_BYTES=8` at 19:16:12 and the new pod logged `QA_RUNTIME_BYTES=9` at 19:17:00. This confirms the discrepancy is not stale display data from the previous revision.

- `lego/operator/internal/build/native.go:86-89` reads `KEY=BASE64` with `IFS='=' read -r key encoded` and exports decoded output through command substitution. The latter removes trailing newlines, even within double quotes. [GNU Bash documents this behavior](https://www.gnu.org/s/bash/manual/html_node/Command-Substitution.html). The former can trim terminal Base64 padding, accounting for the control's warning.
- Preserve each encoded record by reading the whole line with empty IFS and splitting at its first equals sign. Decode with a sentinel or another byte-preserving mechanism; propagate decoding failure, not a silently partial export. Avoid logging values and avoid eval.
- The producer matters: `nativeBuildPreparer` at :157-166 encodes Secret file bytes directly, but literal values pass through `printenv`, which adds one newline. t002 must remove that one formatting byte before a preserving decoder lands. Do not strip the user's trailing newlines.
- Consumer chain: `nativeDockerfile` → `nativeBuildPreparer` :141 → `BuildJob` in build.go:1010 → BuildKit's mounted render-env and generated RUN. Generated shell is JSON encoded as `/bin/bash -c` (:119-122), preserving commands; no login-shell change.
- Correct control: backend `secrets/service.go:350-385` stores the exact value, :712-720 projects it, :731-736 converts it directly to bytes. Runtime `deployment_projection.go:209` / `app_controller.go:3546` inject the Secret through EnvFrom. Keep these paths byte-preserving.
