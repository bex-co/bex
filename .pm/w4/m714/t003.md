## Objective

A new Key Value instance's `data-<name>-0` claim (`keyValuePVCName`, `lego/operator/internal/controller/keyvalue_controller.go:1342`) is on the encrypted class, and its passphrase Secret exists before the Valkey pod mounts it.

## Context

- The StatefulSet's `volumeClaimTemplates` are set once at create with `StorageClassName: kvStorageClass` (line 913) and are immutable afterwards, so only new instances pick the class up here; t006 moves existing ones.
- The online-expansion path refuses a class without `allowVolumeExpansion` (`ReasonStorageClassNotExpandable`, line 1473).
- Render keeps no data on disk for a free Key Value ("Data persistence is not available for free Key Value instances", [key-value](https://render.com/docs/key-value)). Check whether a free bex instance has a PVC at all; if it does, it gets the encrypted class too.

## Steps

1. Use t001's class and passphrase mint in the StatefulSet create path. The PVC name is fixed, so the Secret name is known up front.
2. The Secret outlives the StatefulSet until the PVC is deleted (the retention policy deletes the PVC with the StatefulSet).
3. Confirm a grow still applies online on the encrypted class.
