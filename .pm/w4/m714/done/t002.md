## Objective

Every PVC CNPG creates for a Database, now or later, lands on the encrypted class with its passphrase Secret in place before the instance pod mounts it.

## Context

- `cnpgClusterSpec` (`lego/operator/internal/controller/database_controller.go:523`) sets `storage.storageClass: dbStorageClass`; read replicas are clusters of their own (`readReplicaClusterSpec`); a restore-to-new and PITR bootstrap through `bootstrap.recovery` (line 583).
- CNPG names PVCs `<cluster>-<serial>`; an HA standby, a replaced instance and a replica cluster each bring new names.
- The operator reapplies the Cluster spec every reconcile, so the class flips for existing Clusters too.

## Steps

1. Wire the class from t001 into `cnpgClusterSpec` and every replica and recovery path.
2. Implement t001's Secret mechanism for CNPG PVCs (a PVC watch or the Cluster's `inheritedMetadata` annotation), with RBAC markers regenerated (`make manifests`).
3. Check what CNPG does with a changed `storage.storageClass` on an existing Cluster. If it refuses, keep each existing Cluster's current class until t005 moves it; if it accepts, confirm only new PVCs take it.
4. Check that disk autoscaling and a manual storage increase still grow a LUKS-backed instance online (the resize must reach the LUKS mapping and the filesystem).
5. A Database delete removes its Secrets only after CNPG has removed the PVCs.

## Files

- `lego/operator/internal/controller/database_controller.go` (+ tests), `lego/operator/config/rbac/` (generated).

## Acceptance criteria

- [x] envtest: a Database, an HA Database, a read replica and a recovery each produce Clusters on the encrypted class, and every CNPG PVC gets a non-empty passphrase Secret that a second reconcile never rewrites.
- [x] On dev-4 a new Postgres becomes available, accepts writes, and survives an HA switchover.
- [x] `make test` and `make lint` (from `lego/operator/`) pass.

## Out of scope

- Moving existing databases (t005).

## Done 2026-11-28

- **Wiring.** `cnpgClusterSpec` names `datastoreStorageClass(p.storageClass)`, which comes from `DatabaseReconciler.StorageClass`. Read replicas copy the primary's `storage` (`readReplicaClusterSpec`), and a restore or PITR goes through the same spec. CNPG claims get their Secrets from `DatastoreVolumeKeyReconciler` (t001). The PVC watch needs only the operator's existing `persistentvolumeclaims get;list;watch`, so `make manifests` changed no RBAC.
- **Existing Clusters (step 3).** CloudNativePG 1.30.1 accepts the change, and it lands only on new claims. Its webhook refuses only a storage shrink (`internal/webhook/v1/cluster_webhook.go` `validateStorageConfigurationChange`). Its existing-claim reconciler patches only the size and the VolumeAttributesClass (`pkg/reconciler/persistentvolumeclaim/existing.go`). The class is read once, in `build.go`, when a claim is created. `clusterPodsRoll` ignores `storage`, so the flip rolls no pod. The flip therefore applies to every Cluster: an existing database's next standby, replacement or replica is encrypted, and its live volumes stay where they are until t005.
- **Grow (step 4).** CNPG grows a claim by patching its request, and the hcloud driver grows an open LUKS mapping and its ext4 online. The w2/m86 production drill on this same class grew 10→11 Gi online with the pod running (ADR082 Verification). `hcloud-volumes-luks` has `allowVolumeExpansion: true`, and `scripts/gitops-validate.sh` pins that.
- **Delete (step 5).** Each Secret's only owner is its claim. The garbage collector deletes it once CNPG's claims are gone, and nothing in the Database finalizer deletes it.
- **Tests.** `datastore_encryption_envtest_test.go` covers four cases. A single-instance Database and an HA one, each with a read replica, put both Clusters on the class. An existing Cluster's spec moves onto it. Each CNPG claim gets a stored, distinct passphrase that three passes never rewrite. `volume_key_test.go` covers the primary, a standby, a replacement and a replica claim, plus the class on new, HA, restore, PITR and unset specs. `make test` passed (controller suite 757 s), and `make lint` passed after a `prealloc` fix in the new test.
- **dev-4 (2026-11-28, operator built from this tree with `bash scripts/mock-cluster.sh operator`).** The drill used a `basic-1gb` HA Database, created directly as a CR in a dev-4 workspace namespace (disposable).
  - It was Ready 77 s after the CR was created. Its claims `-1` and `-2` each had `<pvc>-luks`, owned by the claim; the standby's Secret was written in the same second as its claim (08:45:55Z).
  - A row written on `-1`, then `failoverAt` bumped: `-2` became primary, both instances ready. It read the first row, took a second write, and `pg_is_in_recovery()` was `f`.
  - Deleting the Database removed its claims and both Secrets.
  - dev-4's class is local-path, which ignores the node-publish Secret, so encryption itself is checked on production (t008).
