## Objective

A new Key Value instance's `data-<name>-0` claim (`keyValuePVCName`, `lego/operator/internal/controller/keyvalue_controller.go:1342`) is on the encrypted class, and its passphrase Secret exists before the Valkey pod mounts it.

## Context

- The StatefulSet's `volumeClaimTemplates` are set once at create with `StorageClassName: kvStorageClass` (line 913) and are immutable afterwards, so only new instances pick the class up here; t006 moves existing ones.
- The online-expansion path refuses a class without `allowVolumeExpansion` (`ReasonStorageClassNotExpandable`, line 1473).
- Render keeps no data on disk for a free Key Value ("Data persistence is not available for free Key Value instances", [key-value](https://render.com/docs/key-value)). Check whether a free bex instance has a PVC at all; if it does, it gets the encrypted class too.

## Steps

1. Use t001's class and passphrase mint in the StatefulSet create path. The PVC name is fixed, so the Secret name is known up front.
2. The Secret outlives the StatefulSet until the PVC is deleted (the retention policy deletes the PVC with the StatefulSet).
3. Confirm a grow still applies online on the encrypted class.

## Files

- `lego/operator/internal/controller/keyvalue_controller.go` (+ tests).

## Acceptance criteria

- [x] envtest: a new KeyValue's StatefulSet claims the encrypted class and its passphrase Secret is minted once and never rewritten; an existing StatefulSet's claim template is left untouched.

## Out of scope

## Done 2026-11-28

- **Wiring.** A new StatefulSet's claim template names `datastoreStorageClass(intent.storageClass)`, the value of `KeyValueReconciler.StorageClass`. `ensureKeyValueVolumeKey` mints `data-<name>-0-luks` before the StatefulSet is created, with the KeyValue as controller owner. `DatastoreVolumeKeyReconciler` then adds the claim as an owner, so the Secret outlives both: the StatefulSet's retention policy deletes the claim with it. An existing StatefulSet keeps its immutable template and its class, and gets no Secret.
- **Free.** A free bex Key Value has a claim: `storageGB: 1` in `lego/types/tiers/tiers.yaml`, and the same StatefulSet template. It therefore gets the encrypted class too, even though Render keeps no data on disk for free instances.
- **Grow.** `expandKeyValuePVC` requires `allowVolumeExpansion` on the claim's class, and `hcloud-volumes-luks` has it (pinned by `scripts/gitops-validate.sh`). The driver grows the open LUKS mapping online (w2/m86). dev-4's local-path cannot expand, so the grow is not repeated there (`scripts/dev-env.sh` `ensure_tenant_storage_class`).
- **Tests.** The envtest "gives a new Key Value an encrypted claim whose passphrase exists first" checks three things: the template's class, the passphrase stored after the first pass and unchanged after two more, and the template left alone when the configured class changes. `TestVolumeKeyAddsTheClaimToAPreMintedKeyValueSecret` covers the second owner, and also that an existing StatefulSet gets no Secret.
- **dev-4 (2026-11-28).** The drill used a Starter Key Value, in the same disposable namespace as t002's.
  - It was Ready in under 80 s, and its claim's Secret existed from 08:45:34Z, the same second as the claim, owned by `KeyValue,PersistentVolumeClaim`.
  - A key written, `SAVE`d, and the pod deleted: the new pod returned it.
  - Deleting the KeyValue removed the claim and the Secret within the same second, at 08:51:10Z.
