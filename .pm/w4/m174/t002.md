## Objective

Move the `app_pods` pipeline (at minimum cron Job pods; preferably every tenant App container) to the node-file tailer the build and pre-deploy pipelines already use. A container that exits before or between tailer attachments still ships every line with its CRI timestamp.

## Context

- `deploy/gitops/base/log-shipper.yaml:174-205` (app_pods discovery + `loki.source.kubernetes`), `:646-688` (file-tail pattern with `stage.cri`, `alloy.mounts.varlog`).
- Keep: labels `namespace/app/pod/container`, the `level` stages (`:208-280`), the two kubelet-placeholder drops (`:218-227`; with file tailing they may become dead and can be removed), and node scoping (`K8S_NODE_NAME`).
- Request logs (Traefik) are a separate pipeline and must not change.

## Steps

1. Replace or augment `loki.source.kubernetes "app_pods"` with `local.file_match` + `loki.source.file` over `/var/log/pods/<ns>_<pod>_<uid>/<container>/*.log` for the same discovered targets, followed by `stage.cri`.
2. Make sure each line ships exactly once across log rotation and Alloy restarts (positions file), and that no tenant container logs from the other pipelines are double-shipped.
3. Apply on dev-4 and run the DoD command 20× with zero missing lines.

## Files

- `deploy/gitops/base/log-shipper.yaml`
- `docs/ADR010-*.md` (pipeline description)

## Acceptance criteria

- [ ] 20/20 fast-exit runs ship all 5 lines with CRI timestamps on dev-4.
- [ ] Long-running service tail latency and `level` labels unchanged.
- [ ] No duplicate lines after an Alloy pod restart.

## Out of scope

- Loki retention or limits.
