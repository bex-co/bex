## Objective

`GET /v1/logs`, `GET /v1/logs/values` and `GET /v1/logs/subscribe` read a whole project or one of its environments when given Render's `project` (and `environment`, `region`), with `resource` narrowing it. They refuse what Render refuses, with Render's codes.

## Context

- Render, live OpenAPI of 2026-11-23, on all three operations:
  - `resource` is "Required unless `project` is provided."
  - `project`: "The query covers the project's services, cron jobs, Postgres databases, and Key Value instances. Combine with `resource` to narrow the query to specific resources in the project."
  - `environment`: "The ID of an environment in the project … Requires `project`."
  - `region`: "Requires `project`. Required when the project's or environment's resources are in more than one region."
  - The 400 documents `multiple_regions` ("provide `region` to query one") and `too_many_resources` ("provide `resource` to narrow the query").
- bex today:
  - `parseLogParams` refuses `project` on the list and values reads ("project is taken only by /v1/logs/subscribe", `lego/backend/internal/logs/rest.go:810-813`).
  - The tail's `project` is the bex project-view tail of w3/m505 (`projectSubscribe`, `rest.go:325`). It is resolved by `resolveProjectView` (`logs/project.go:139-189`), which also reads a `filterDocument`.
  - The project read caps at `maxProjectLogResources` (20) with a codeless 400 (`project.go:157-159`).
  - GraphQL `logs` and `logLabelValues` take exactly one of `resource` and `project` (`logs/graphql.go:245-256`). Render's `resource` narrows a project instead.
- bex runs one region (`BEX_REGION`). Decide what `region` answers, following how other operations normalize Render's region names (w8/415: a refused region lists Render's five). Decide whether `multiple_regions` can ever fire. If it cannot, keep it in `notApplicableRenderErrorCodes` with the new reason.

## Steps

1. Parse `project`, `environment` and `region` once for all three reads: `environment` or `region` without `project` is 400, and an environment outside the project is 404 or 400, as Render answers.
2. Resolve the project's or environment's readable services, cron jobs, Postgres and Key Value (`ProjectLogResources`), intersected with `resource` when it is given. A named resource outside the project is refused.
3. Over the cap, answer 400 with `"code": "too_many_resources"` and a message telling the caller to provide `resource`. Register the code where w5/m583's guard expects it.
4. Keep the w3/m505 tail's `filterDocument` and `textMode` working beside Render's parameters. The dashboard's project log view must read exactly as before.
5. Give GraphQL and MCP `list_logs`/`list_log_label_values` the same `project`/`environment`/`region` semantics, or record the divergence where an upstream MCP tool's arguments fix them (`render-mcp-tools.json`).
