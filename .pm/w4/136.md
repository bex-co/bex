# Static Headers and Redirects editors remain dirty after a successful whitespace-normalized save

Why: a successful edge-rule save leaves the editor displaying values different from the stored configuration, with Save and Cancel still enabled, so users cannot tell that their change has already persisted without canceling or reloading.

**Severity:** minor. **Estimate:** 55m. **Source:** continuous `$qa-find-bugs`, new loop pass 3, 2026-09-21 local / 2026-09-22 UTC; filed in w4 at the user's direction. This is a dashboard draft-state defect; the saved rules and public static responses worked. It advances ADR008's usable hosting management and ADR029's live static-rule editing contract.

## Root and exact scope

- `dashboard/src/features/services/components/static-site-section.tsx:146–147,270–271`: `RoutesEditor` and `HeadersEditor` seed local draft state from props only on mount, then determine dirty state with `JSON.stringify(draft) !== JSON.stringify(savedProps)`. After the server normalizes an accepted path, the refetched props differ from the unchanged padded draft.
- The same file at `249,359` calls `void onSave(draft)` and ignores the result. Neither editor adopts accepted rows on success. Cancel at `245,355` explicitly adopts the current saved props in both implementations; the Headers workaround was verified live, while the Routes Cancel behavior is code-established only.
- `dashboard/src/features/services/hooks/use-static-site.ts:23–29,44–79`: `setRoutes` and `setHeaders` expose only `Promise<boolean>`. Each awaits its mutation and `refetch()`, discards both returned payloads, and reports success. The needed canonical data already exists: `use-server.ts:74–77` returns freshly mapped `ServiceView` rows from its refetch.
- Backend `lego/backend/internal/apps/service.go:4361–4389` correctly trims route type/source/destination and header path/name when converting input to CR fields. Header values are preserved unchanged. `SetRoutes` at `4567–4583` and `SetHeaders` at `4605–4621` use those converters; REST, GraphQL, and MCP share these core setters. Header-name whitespace is rejected by raw HTTP-name validation before conversion, so the accepted header-path case is the live trigger here.
- **Two editor implementations, one production JSX call site each:** `routes/services.$serviceId.redirects.tsx:23` and `routes/services.$serviceId.headers.tsx:23`. Their `key={service.id}` intentionally resets drafts when the service changes, but does not reset the same service after a save. The two `static.$serviceId.{redirects,headers}.tsx` routes reuse these pages: four URL entry points total. The `/static` pair was live-tested; the `/services` aliases are code-confirmed shared consumers, not independently live-probed.
- **Two production hook call sites:** `static-edge-rule-page.tsx:45` supplies both edge-rule pages; `static-site-section.tsx:58` supplies Publish Directory. Only `setRoutes`/`setHeaders` need the accepted-row result; preserve the publish-directory boolean callback and its existing behavior. No shared input, Apollo client, backend validator, or static-server change is required.

## Scoped fix and verification

Return the accepted `StaticRouteView[]` / `StaticHeaderView[]` from the existing successful refetch, or an explicit failure result, and let each editor adopt that saved list. Use the result for the requested service id; an absent or failed read must not be reported as an empty saved list. Preserve a newer draft entered while the request was pending: capture the submitted draft and replace it only if the current draft is still that submission. Existing inputs and row actions remain editable while the Save button is busy, so an unconditional success reset would otherwise lose later input.

Keep normalization in the existing read mapping. `features/services/lib/status.ts:133–153` already removes null entries, fills nullable strings, strips GraphQL `__typename`, and builds stable view-field order. Raw generated mutation rows include `__typename` and nullable members (`graphql/definitions.ts:1812,1820`); casting them into a draft can preserve a false JSON-stringify difference or send response-only keys back as mutation input. Do not duplicate backend trimming in the dashboard, trim header values, add unconditional prop-to-draft effects that overwrite unsaved edits on detail refresh, or reset to props captured before the await.

Extend the existing tests in `features/services/components/__tests__/static-site-section.test.tsx` and `routes/__tests__/services.$serviceId.redirects.test.tsx`, which currently cover labels and submitted callbacks but not post-save synchronization:

- For both editors, reproduce accepted padded paths with a canonical server/refetch result; assert the canonical displayed values, disabled Save, and absent Cancel. Cover real nullable/typename response mapping at the hook/read boundary rather than casting raw payloads into the component fixture.
- A refused save preserves the draft and existing saved baseline. Editing again while a save is pending preserves the newer input when that earlier save completes.
- Preserve add/remove order, Cancel restoring accepted rows, and service-id navigation resetting drafts. Header value bytes must remain unchanged. Check the Publish Directory sibling still receives its existing boolean result.
- Run the affected dashboard tests and required type/lint checks, then repeat both live saves after deployment, reload, and confirm the already-working rewrite/header responses remain correct. No new backend contract probe is required for this UI-only correction; preserve the successful shared setter behavior already established by the captured query and public-response controls.
