# 374 — Service breadcrumbs run under the topbar's Search at tablet and small-laptop widths

Why: from about 768 to 1200 px wide with the sidebar open, the service breadcrumb paints underneath the Search button. The two labels overlap into an unreadable smear, for example on an iPad in landscape at 1024.

**Severity:** minor. **Estimate:** ~30m. **Source:** live `/qa-find-bugs w4` loop run c7a1, 2026-10-20 UTC, `muse.env`, workspace `bex-canary`. Measured on an owned service's deploy page (`qa-20261020-c7a1-proj › Production › qa-20261020-c7a1-web`); the fixture was deleted in-run. Evidence: `.playwright-mcp/qa-topbar-c7a1-1024.png` (local).

## Probe

These are DOM rects of the breadcrumb `<nav>`'s buttons and the Search button, sidebar expanded:

| viewport | crumb rects (left–right)        | nav right | Search left | overlap |
| -------- | ------------------------------- | --------- | ----------- | ------- |
| 1280     | 272–464 · 482–593 · 611–803     | 803       | 978         | none    |
| 1024     | 272–464 · 482–593 · 611–803     | 714       | 722         | 81 px   |
| 820      | 272–464 · 482–593 · 611–803     | 551       | 559         | 244 px  |

At 934 px the nav measured `scrollWidth 552 / clientWidth 393`, with `overflow: visible`. The crumb rects are identical at every width: they never shrink. Search stays clickable, because `elementFromPoint` on it returns Search; this is visual only.

## Root cause

- The shared shadcn button's base class includes `shrink-0` (`dashboard/src/common/components/ui/button.tsx:8`). The crumb buttons add `min-w-0 max-w-48`, but `flex-shrink: 0` still pins each at its content width (≤ 192 px). Their inner `truncate` spans therefore never get a narrower box to truncate into.
- The affected buttons are the service crumb (`dashboard/src/common/components/dashboard-layout/dashboard-breadcrumbs.tsx:134`), `ProjectMenu` (`:356`) and `EnvironmentMenu` (`:414`, shown from `md`). The header row (`dashboard-header.tsx:47-51`) gives the left group `min-w-0`, but the nav itself never clips.
- This is the same `shrink-0` family as `w4/244`, `w4/251` and `w4/323`, at a different site.

## Fix (target behavior)

- The crumb buttons may shrink (`shrink` overriding the base `shrink-0`). Their labels truncate with an ellipsis, and the leaf keeps at least a short readable prefix.
- The breadcrumb nav's painted width never exceeds its box, so the right-hand actions are never overlapped.
- Desktop at ≥ 1280 renders exactly as today.
- Apply this to every consumer of `ProjectMenu`/`EnvironmentMenu`: service, Postgres/Key Value (`DatastoreBreadcrumbs`) and environment-group crumbs. Below `sm` the project crumb is already hidden; keep that.

## Acceptance

- At 820, 1024 and 1280 with the sidebar open, on a service whose three crumb labels are ≥ 20 characters: nav `scrollWidth ≤ clientWidth`, and the last crumb's right edge ≤ Search's left edge. At 1280 the crumb geometry is unchanged.
- Run the same check on a Key Value page in a project/environment.
- A dashboard component test asserts the crumb buttons carry a shrinkable class.
- Dashboard `yarn lint` and `yarn test` pass.

## Unverified

Datastore and environment-group crumbs at these widths (their leaf is a shrinkable span; the two menu buttons are not); 390 px is out of scope since `sm` hides crumbs.
