# An image service's Docker Command is invisible on REST reads, and Blueprints spell it `startCommand` (refusing Render's `dockerCommand`)

Why: since w4/188 a REST/CLI caller can create an image-runtime web/private/worker service with `envSpecificDetails.dockerCommand`, but `GET /v1/services/{id}` never returns it. A Render-CLI `services get` hides the override and `create --from` clones the service onto the image's default entrypoint, the same class w1/m167 (image cron command) and w2/042 (image pre-deploy) already fixed. Separately, Generate Blueprint exports the command as `startCommand`, and validate refuses the Render spelling `dockerCommand` on `runtime: image`.

- **Severity:** minor to major (silent drop on clone; a parity divergence on Blueprints).
- **Repro (loop67, 2026-10-06, pin `b0a2e85d7` ⊇ w5/m117, `bex-canary`):** owned Free `qa-20261006-l67-rt` (`srv-db28s68j423c73crjkb0`; deleted afterwards), created by `POST /v1/services` with `{"type":"web_service","port":8080,"image":{"imagePath":"docker.io/traefik/whoami:latest",…},"serviceDetails":{"runtime":"image","plan":"free","healthCheckPath":"/health","maxShutdownDelaySeconds":45,"envSpecificDetails":{"dockerCommand":"/whoami --port 8080 --verbose"}},"envVars":[…]}`.
  - The command **was stored**: GraphQL `service { startCommand }` → `"/whoami --port 8080 --verbose"`, `imagePath` and `runtime: image` correct; `healthCheckPath`, `maxShutdownDelaySeconds`, `port` and both env vars read back. An unknown `serviceDetails.totallyUnknownField` is refused with 400 (w5/m117's guard holds).
  - `GET /v1/services/<id>` → `serviceDetails` keys `env, healthCheckPath, internalAddress, maintenanceMode, maxShutdownDelaySeconds, numInstances, plan, port, region, renderSubdomainPolicy, runtime, url`. There is **no `envSpecificDetails`**, so the Docker Command appears nowhere on the REST read.
  - `POST /v1/blueprints/generate {"serviceIds":[<id>]}` → manifest `runtime: image`, `image: {url: …}`, **`startCommand: /whoami --port 8080 --verbose`**, which `validateBlueprint` accepts. The same manifest with `dockerCommand:` → `valid: false`, "dockerCommand requires runtime: docker".
- **Root cause:**
  1. REST read: `lego/backend/internal/apps/render.go:506-529` (`envSpecificDetails`) returns nothing for `runtime: image`, except an image **cron** command (w1/m167) or a pre-deploy command (w2/042). A web/private/worker image service's `StartCommand` is never projected.
  2. Blueprints: `lego/backend/internal/apps/blueprint_compiler.go:297-301` refuses `dockerCommand` unless `runtime == "docker"`, pinned by `blueprint_compiler_test.go:166-170` ("image docker command"). `blueprint_generate.go:341-355` exports an image service's command as `startCommand`.
- **Render:** the pinned REST spec carries an image runtime's command only as `dockerDetails.dockerCommand` (w4/188's reading of `render-public-api-1.json`). Render's Blueprint spec documents `dockerCommand` as "The command to run when starting the Docker-based service. If omitted, Render uses the `CMD` defined in the `Dockerfile`." **Unverified:** whether Render's own `render.yaml` loader accepts `dockerCommand` and/or `startCommand` for `runtime: image` (docs fetched 2026-10-06; no authenticated Render probe). w4/188's note that "Blueprints already accept `runtime: image` + `dockerCommand`" is contradicted by the live validate above and by the test.
- **Fix:**
  1. Emit `envSpecificDetails: {dockerCommand: <StartCommand>}` (plus `preDeployCommand` when set, as today) for image web/private/worker services with a non-empty command. Keep it absent when empty so the entrypoint stays the default. This matches what REST create/update accept.
  2. Decide the Blueprint spelling from Render's actual behavior: if Render accepts `dockerCommand` for `runtime: image`, accept it (alias to the same field), export `dockerCommand`, and keep reading `startCommand` for compatibility. Record the decision in ADR049 either way.
- **Blast radius:** `envSpecificDetails` feeds every REST service read (GET, list, PATCH/create responses) and the Render CLI clone path. The Blueprint compiler and generator are shared by REST/GraphQL/MCP validate, apply and generate.
- **Estimate:** ~45m.
