# Custom-domain copy ignores the pending state: "without at least one custom domain" while one is listed, and a delete that removes an Ingress that never existed

Why: a user whose only custom domain is still verifying is told they have none (in a toast that leaks the internal field name `RenderSubdomainPolicy`), and is warned about removing routing and a certificate that were never created. Both misstate what the product did and what the user must do next.

Found live, `/qa-find-bugs` pass 162, 2026-09-25 (w4-targeted, `muse.env` credentials), journey 5. Fixture `qa-20260925-dom` (static site `srv-darll729slkc73beqtm0`, from `https://github.com/bex-co/bex` `examples/static-site`) with the throwaway domain `qa-20260925.example.com` (pending, removed in the same visit). Both were deleted this pass, and a `qa-` sweep of services, databases, key values, and blueprints came back empty.

## 1. Disabling the platform subdomain with only a pending domain

- **Repro:** Settings → Custom Domains → Add `qa-20260925.example.com`. The row reads Verified `Pending`, Certificate `Pending`. Then click the "Toggle platform subdomain" switch.
- **Actual:** the switch stays on, and the toast reads **"RenderSubdomainPolicy cannot be disabled without at least one custom domain"**, directly under a table listing one custom domain. GraphQL still shows `renderSubdomainPolicy: "enabled"`, so the refusal itself is correct.
- **Root cause:** `lego/backend/internal/apps/service.go:4123-4126` (`SetSubdomainPolicy`) and the create-time twin at `:2681` test `a.Spec.Host == "" && len(a.Spec.Hosts) == 0`. Managed domain claims are projected into `Spec.Hosts` only once `ClaimState == "verified"` (`apps/domains.go` `addOne` → `projectDomainClaims`), so the rule is really "a **verified** custom domain", but the message says "at least one custom domain". The dashboard's `graphql-error.ts` capitalizes the first letter of the backend's camelCase field name into `RenderSubdomainPolicy`.
- **Fix:** say the rule that is enforced, in user terms, on all three surfaces (the message is shared). For example: "The platform subdomain can't be disabled until a custom domain is verified — qa-20260925.example.com is still pending." When no verified domain exists, the dashboard should explain beside the switch, before the click, instead of relying on a transient toast. Keep the existing test at `create_normalization_test.go:415` in step with the new wording.

## 2. Deleting a pending domain

- **Repro:** same fixture, domain actions menu → Delete.
- **Actual:** "The service stops serving this domain. Its Ingress rule is removed and the TLS certificate is left to expire. This can't be undone." The domain was never routed (ownership unverified, so it was never projected into `Spec.Hosts`) and no certificate was issued (Certificate `Pending`).
- **Root cause:** `dashboard/src/features/services/locales/en.ts:1466` (plus the sibling variants at `:1471` and `:1477`, and zh) is state-blind.
- **Fix:** for a domain that is not yet verified, say it removes the pending claim and nothing was being served. Keep the current copy for verified domains.
