## Objective

Give each custom-domain row durable ownership state and a stable random TXT challenge while treating every pre-migration domain as already verified so rollout cannot remove live traffic.

## Context

The `domains` table currently stores app, host, primary/redirect metadata only; `App.spec.hosts` is effectively both desired claim state and serving state. Main already checks a deterministic app-bound TXT before writing a new host, but a failed add leaves no pending object or reusable instructions. Migrations through `0084_webhook_attempts` are taken, so this milestone's next schema pair is `0085` unless another migration lands first.

## Steps

1. Add a closed `pending|verified` state, random challenge value, verification timestamp, and any version/attempt metadata required for atomic promotion.
2. Backfill existing rows as verified with no challenge requirement and preserve their primary/redirect ordering.
3. Keep canonical-host uniqueness global across both states; make same-App creation idempotent and cross-App collision non-enumerating.
4. Extend Store/PGStore domain reads and writes without leaking the challenge into unrelated desired-App projections.

## Acceptance criteria

- [ ] Existing rows are verified after migration and continue to project identically.
- [ ] New rows carry one cryptographically random challenge and begin pending.
- [ ] Concurrent claims for the same canonical host produce one owner and one conflict, never duplicate rows.
- [ ] Down migration has an explicit safe contract and migration version uniqueness remains green.
