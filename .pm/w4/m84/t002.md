## Objective

Make persisted verified claims the only input to `App.spec.hosts` so creating or syncing a pending claim can never create an Ingress host or Certificate.

## Context

`apps.addOne` currently verifies and immediately patches `App.spec.hosts`; store reconciliation reads every domain row into `DesiredApp.Hosts`. Service creation/`ReplaceDomains`, Blueprint sync, sibling pairing, and direct add must converge on the same claim state or one of them will become a verification bypass. The operator should remain mechanism-only: it projects verified desired state and must not own DNS/business transitions.

## Steps

1. Change Store desired-App reads and reconciler projection to include only verified domain rows.
2. Refactor direct add and sibling pairing to persist pending claims without patching serving hosts; retain authz-before-validation and reserved/global-claim checks.
3. Route service create, `ReplaceDomains`, and Blueprint sync through the same claim lifecycle. Preserve existing verified rows on unchanged declarations; new declarations become pending.
4. Make deletion clear pending or verified state and reconcile serving projection/redirect dependencies idempotently.
5. Keep storeless mode on the existing verify-before-add fail-closed path because it has nowhere durable to hold pending state.

## Acceptance criteria

- [ ] A pending row never appears in `App.spec.hosts`, `spec.host`, host redirects, Ingress rules, or Certificate DNS names.
- [ ] Direct add, create, and Blueprint sync cannot bypass pending state.
- [ ] Existing verified declarations remain served through migration and later syncs.
- [ ] Delete works for both states and cannot leave a redirect to a removed verified target.
- [ ] The operator gains no DNS resolver or domain-state business logic.
