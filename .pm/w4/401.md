# 401 — Metrics `host`/`path` filters honor only the first value: Render ORs repeated values, bex silently drops the rest and answers a wrong count

Why: a script asking Render's API for requests to `/nf` **or** `/err` gets a confident `200` holding only `/nf`'s count, and swapping the parameter order changes the answer. Nothing says the extra value was ignored, so the wrong number reaches the caller's charts or alerts as fact.

**Severity:** minor (REST/GraphQL read-path parity; the dashboard's single Path box and Host dropdown send one value and are unaffected). **Estimate:** ~45m. **Source:** live `/qa-find-bugs w4` loop run c5w2, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `29d63e1f7bea`). Fixture: Free image web service `qa-20261023-c5w2-met` (`srv-dbe1eab17lic73al6q90`, `mendhak/http-https-echo:35`). Traffic sent with `curl`: 40 × `/ok`, 10 × `/nf` (404), 5 × `/err` (500), 3 × `/slow` (1.5 s). The fixture was deleted (`DELETE` → `204`, URL → `404`); session revoked.

## Probe

All requests were `GET /v1/metrics/http-requests?resource=srv-dbe1eab17lic73al6q90&startTime=2026-10-24T02:20:00Z&endTime=2026-10-24T02:40:00Z&resolutionSeconds=300&…`:

| extra query                                                      | value | expected       |
| ---------------------------------------------------------------- | ----- | -------------- |
| `path=/nf`                                                       | 10    | 10             |
| `path=/err`                                                      | 5     | 5              |
| `path=/nf&path=/err`                                             | 10    | 15             |
| `path=/err&path=/nf`                                             | 5     | 15             |
| `host=qa-20261023-c5w2-met.onbex.co&host=nope.example.com`       | 81    | 81             |
| `host=nope.example.com&host=qa-20261023-c5w2-met.onbex.co`       | `[]`  | 81             |

The pinned Render spec (`lego/backend/internal/api/openapi/render-public-api-1.json`, `/metrics/http-latency` parameters 5–6, shared by `http-requests` and `filters/path`) says of both `host` and `path`: "When multiple … query params are provided, they are ORed together".

Controls from the same run were correct: `aggregateBy=statusCode` split exactly 10 × 404 and 5 × 500. `path=/slow` with `quantile=0.5` read 1.51 s. Repeated `resource` is already a list (`requestedResources`, `rest.go:94-102`).

## Root cause

- REST: `lego/backend/internal/metrics/rest.go:411-412` reads `v.Get("host")` / `v.Get("path")`, which keep only the first value.
- GraphQL: `graphql.go:400-403` passes `HOST`/`PATH` (and `STATUS_CODE`) filter lists through `firstValue` (`:512-519`, "Render models as a list but bex honors as a scalar").
- `MetricQuery`/`RequestMetricQuery.Host`/`Path` are scalars (`service.go:162-163`, `:276-277`), and the Loki builder emits one equality per field (`lokisource.go:165-170`).
- `TestNoMetricsArgumentIsAcceptedWithoutEffect` (`aggregation_test.go:382`) checks each parameter once, so a dropped repeat passes it. ADR018's metrics row records no "first value only" divergence.

## Fix (target behavior)

- `host` and `path` become lists on REST (`v["host"]`, `v["path"]`, with empty values dropped) and on GraphQL (`HOST`/`PATH` values). Values within one field are ORed and the two fields are ANDed, as in Render. A single value keeps today's LogQL byte-for-byte.
- Loki: emit `| request_path="a" or request_path="b"` (or an anchored `=~` built with `regexp.QuoteMeta`). Pin the result with the backend suite's real-Loki execution.
- GraphQL `STATUS_CODE` with several values: either OR them as well or refuse with a named `400`, but never silently use the first. The same rule applies to any other `firstValue` caller (grep the callers and list them in the change).
- MCP `httpHost`/`httpPath` are scalar in Render's MCP too, so they stay unchanged.
- Tests:
  - REST and GraphQL return the sum for two paths, and swapping the order gives the same answer.
  - A host plus two paths gives the AND of the host with the OR of the paths.
  - Extend the no-effect guard so a repeated parameter must change the query.
  - ADR018 metrics row note.

**Unverified:** the GraphQL multi-value path live (my probe used the wrong input shape and was refused; the GraphQL behavior is read from `graphql.go:400-403`); `http-latency` with repeated paths (same parser, not probed).
