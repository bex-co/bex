## Objective

New public databases and Key Value stores get a publicly trusted certificate within minutes, however many are created in a week. Round 254 showed a new public Key Value has no external TLS listener at all until its certificate issues (ADR021), so its external access is down for the whole stall.

## Steps

1. **If t001 shows the Let's Encrypt weekly limit:** issue one wildcard per datastore domain, `*.db.bex.co` and `*.kv.bex.co`, over DNS-01. ADR009 already names this follow-up.
   - It needs a Cloudflare API token scoped Zone:DNS:Edit on `bex.co`. That is a **user gate**: if the token is not available, move this task to `blocked/` with the exact ask.
   - Each database then serves the wildcard (the SNI proxy already routes by name), so creating a database orders nothing.
   - Keep per-database certificates only as a fallback, or drop them.
2. **If t001 shows a solver, routing or operator fault:** fix that path. Add a regression test that drives the Certificate to Ready on envtest's fake issuer.
3. Either way, add an operator metric or alert when a public Database stays `Pending` past 10 minutes, so a recurrence is seen before a QA round reports it.
4. Amend ADR009 § Publicly trusted server certificates: the chosen model, the budget, and the alert.
