## Objective

A user who reveals connection info while the trusted certificate is pending, or has failed, is told so and how to connect meanwhile. Today the card silently switches to the private-CA contract, which no client accepts without a download.

## Context

- `externalURLQuery` (`lego/backend/internal/postgres/service.go:1185-1186`) picks the contract from `status.externalCertificate`.
- The state is not readable through the REST read (keys: `public` only) or GraphQL `Database` (`Cannot query field "externalCertificate"`).

## Steps

1. Expose the state as a bex extension, e.g. `externalCertificate: "publiclyTrusted" | "pending" | "failed"`, with the condition's tenant-safe reason. Put it on the REST read, GraphQL `Database` and `KeyValue`, and the MCP reads.
2. Connections card:
   - while `pending`: "A publicly trusted certificate is being issued (usually a few minutes). Until then, connect with the CA below or `sslmode=require`.";
   - on `failed`: the reason, and that the CA path works.
   - en and zh.
3. Leave `publiclyTrusted` unchanged: no note, no CA.

## Acceptance criteria

- [ ] A dashboard test renders the pending note only for `pending`. REST, GraphQL and MCP return the same value.

## Key Value (added round 254)

- A new public Key Value has **no** external listener until its certificate issues (ADR021 lines 92–97). While its state is `pending` or `failed`, its Connections card must say the external URL is not reachable yet. It must not show the URL as ready, and the Details' "Public access: Yes" needs the same qualifier.
