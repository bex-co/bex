## Objective

`GET /v1/events/{eventId}` returns Render's `details` for each datastore event whose value bex already records.

## Context

- [README § Finding](README.md#finding-round-300).
- Mapper: `toRenderEvent` (`lego/backend/internal/events/rest.go:316-457`). Its only datastore arm is `postgres_cluster_leader_changed` (`:419-420`).
- Recorded values: `events/service.go:1372-1377` and `:1399-1401`. The caller is `r.Caller` on every audit row.

## Steps

1. Set `Details` from the audit row's caller for `postgres_created`, `postgres_restarted`, `postgres_connection_pool_enabled_changed`, `postgres_disk_size_changed` and `postgres_upgrade_started`. Resolve the caller to `usr-…` and an email through the same path as `suspendedByUser` (`userRefs`, `service.go:1150-1162`). Render it as `user: {id, email}`, and omit it when there is no caller, for example a system or Blueprint write.
2. `postgres_connection_pool_enabled_changed`: render `enabled` from `ConnectionPoolEnabled`.
3. `key_value_config_restart`: render Render's required `reason` and `message`.
   - `reason`: a stable code. Pick one, for example `config_change`, and record it in ADR018.
   - `message`: a sentence naming the restart and the configuration it restarted into, for example `Persistence mode changed to off; the instance restarted to apply it.`
   - Drop nothing bex records today. `maxmemoryPolicy`/`persistenceMode` may stay as recorded extras.
4. `postgres_upgrade_started`/`_succeeded`/`_failed`: surface `fromVersion`/`toVersion` from the fact's upgrade key (`store/datastore_event_facts.go:461`, `<current>-<spec>`). Carry them as typed fields on the fact row rather than reparsing the key in the events package.
5. Leave every service event and the empty datastore variants as they are.

## Acceptance criteria

- [ ] A test per type drives the verb or fact, fetches the event through the REST handler, and asserts the exact `details` JSON.
- [ ] The existing service-event golden tests pass unchanged.
