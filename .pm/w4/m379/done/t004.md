## Objective

Run `/simplify` over the change. One table maps each datastore type to its detail fields, rather than one `case` per type.

## Acceptance criteria

- [x] `/simplify` findings applied or explicitly declined in the README.

## Result (2026-11-14)

- **Applied:**
  - `callerRef` replaces four copies of the `if r.Caller != "" { … = &UserRef{ID: r.Caller} }` guard (deploy trigger, edge-cache trigger, cron run, and the new datastore arms).
  - `Details.User` is rendered once in the base struct, not per type.
  - The upgrade emit closure lost its one-use `keyFor` helper.
- **Declined: the separate type → fields table.** `toRenderEvent`'s `switch` already is that table for every service type, with one line per type. A second, datastore-only mechanism (a map of render funcs) would make readers look in two places and would add no type safety. The datastore arms are one line each, kept beside `postgres_cluster_leader_changed`.
- **Declined: a column for HA's from-value** (see t002): it is derivable and redundant.
