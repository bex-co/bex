## Objective

`GET /v1/events/{eventId}` returns Render's `details` for each datastore event whose value bex already records.

## Context

- [README § Finding](../README.md#finding-round-300).
- Mapper: `toRenderEvent` (`lego/backend/internal/events/rest.go:316-457`). Its only datastore arm is `postgres_cluster_leader_changed` (`:419-420`).
- Recorded values: `events/service.go:1372-1377` and `:1399-1401`. The caller is `r.Caller` on every audit row.

## Steps

1. Set `Details` from the audit row's caller for `postgres_created`, `postgres_restarted`, `postgres_connection_pool_enabled_changed`, `postgres_disk_size_changed` and `postgres_upgrade_started`. Resolve the caller to `usr-…` and an email through the same path as `suspendedByUser` (`userRefs`, `service.go:1150-1162`). Render it as `user: {id, email}`, and omit it when there is no caller, for example a system or Blueprint write.
2. `postgres_connection_pool_enabled_changed`: render `enabled` from `ConnectionPoolEnabled`.
3. `key_value_config_restart`: render Render's required `reason` and `message`.
   - `reason`: a stable code. Pick one, for example `config_change`, and record it in ADR018.
   - `message`: a sentence naming the restart and the configuration it restarted into, for example `Persistence mode changed to off; the instance restarted to apply it.`
   - Drop nothing bex records today. `maxmemoryPolicy`/`persistenceMode` may stay as recorded extras.
4. `postgres_upgrade_started`/`_succeeded`/`_failed`: surface `fromVersion`/`toVersion` from the fact's upgrade key (`store/datastore_event_facts.go:461`, `<current>-<spec>`). Carry them as typed fields on the fact row rather than reparsing the key in the events package.
5. Leave every service event and the empty datastore variants as they are.

## Acceptance criteria

- [x] A test per type drives the verb or fact, fetches the event through the REST handler, and asserts the exact `details` JSON.
- [x] The existing service-event golden tests pass unchanged.

## Result (2026-11-14)

- **Mapper.** `toRenderEvent` (`lego/backend/internal/events/rest.go`) gained the datastore arms: `postgres_connection_pool_enabled_changed` `enabled`, `postgres_upgrade_started/_succeeded/_failed` `fromVersion`/`toVersion`, and `key_value_config_restart` `reason` + `message`. `Details.User` is now rendered for every type (the projection in `view` decides which types carry one), so the cron arm's own line went.
- **User.** `view` (`events/service.go`) sets `Details.User` from the audit row's caller on `postgres_created`, `postgres_restarted`, `postgres_connection_pool_enabled_changed` and `postgres_disk_size_changed`, through the new `callerRef` helper (nil for a row with no caller). The id and email resolve through the existing `userRefs` path (`resolveUserEmails`, `resolveUserIDs`).
- **Key Value.** `reason` is `config_change`. `message` names the mode, for example `Persistence mode changed to off; the instance restarted to apply it.`, or reads `The configuration changed; the instance restarted to apply it.` for a row with no recorded mode. Both choices are recorded in ADR018. `maxmemoryPolicy`/`persistenceMode` were never rendered, and still are not.
- **Upgrades.** `datastore_event_facts` already had typed `version_from`/`version_to` columns (migration 0107), filled by `upgradeFacts`. `getServiceEventQuery` now selects them into `ServiceEventRow.VersionFrom/VersionTo` (by-id only, like `LeaderID`), so the key is not reparsed in the events package. **Bug found and fixed:** `upgrade_succeeded` recorded the new version twice (`17 -> 17`), because by success `status.currentVersion` has caught up with the spec. The success edge now takes the started edge's pair from the checkpoint key (`upgradeKeyVersions`, `store/datastore_lifecycle_facts.go`). The fix also changes its source key to `<id>:upgrade:16-17:succeeded`. Rows recorded before the fix keep their equal pair.
- **Not done:** `user` on `postgres_upgrade_started` (optional on Render). The upgrade facts are observed from the Database status and record no caller.
- **Tests:** `TestDatastoreEventDetailsOnRetrieve` (`events/datastore_details_test.go`) has one row per type. It drives the row through `GET /v1/events/{id}` on the REST handler and asserts the exact `details` JSON. `TestRenderEventDetailsMatchTheirMember` gained the datastore rows and validates them against Render's member. The api suites' `TestGetEventHonorsNamedWorkspace` and `TestGetEventSurfaceParity` now wire an identity reader, and the first asserts `user {id, email}` on `postgres_created`. Every service-event golden passes unchanged.
