## Objective

The three Postgres change events that Render describes as transitions carry both sides.

## Context

- Audit recorders (`lego/backend/internal/core/audit.go:1058-1096`) store only the resulting value. The read-replica row stores none (`lego/backend/internal/eventvocab/datastore.go:84-88`).
- Render requires:
  - `postgres_disk_size_changed`: `fromDiskSize`, `toDiskSize` (integers, GB);
  - `postgres_ha_status_changed`: `fromStatus`, `toStatus` (strings);
  - `postgres_read_replicas_changed`: `fromReplicas`, `toReplicas` (integers).

## Steps

1. At each PATCH, pass the pre-change value into the recorder beside the new one, as the disk recorders (`DiskSizeFromGB`) and `RecordDatabasePlanChanged` do. Add the audit columns or JSON keys the store needs.
2. Pick the HA status vocabulary. Render's values are unverified, so use `disabled`/`enabled` unless a Render artifact shows otherwise, and record the choice in ADR018.
3. Render the pairs in `toRenderEvent`.
4. Correct the comment at `eventvocab/datastore.go:84-88`: Render's replica event is not thin. Disk autoscaling has no Render variant and stays as it is.
5. Rows recorded before this change have no from-value. Render them with the to-side only, and do not invent a from-value.

## Acceptance criteria

- [ ] Tests cover each event's pair, plus an old row with no from-value.
- [ ] A no-op PATCH still records nothing.
