# 493 — A static site whose publish directory is missing fails as `update_failed` after a "succeeded" build, with the reason `clone: … (exit 2)`

Why: a user whose publish directory is wrong sees the build reported as successful, then a deploy failure prefixed with an internal container name and an exit code. Render reports the same mistake as a build failure ("Publish directory dist does not exist!"), which tells the user to fix their build settings rather than wonder what failed to deploy. w4/478 fixed the "clone" wording on the build path only.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 65, 2026-11-05 12:00 UTC (`muse.env`, `bex-canary`, pin `c8bbc07cbeeb`); **minor** (status and copy); ~40m.

- **Probe:** owned static site `qa-20261105-nodist` (`srv-dbm6vjqvcsds739ipac0`, `examples/static-site`, `publishPath: "dist"`, which does not exist; deleted after the probe). `GET /v1/services/<id>/deploys?limit=1` → `status: update_failed`, `failureReason: clone: the publish directory "examples/static-site/dist" does not exist in the repository at "ad13122c…" (exit 2)`. Events: `build_started` 12:00:15, then `build_ended` with `status: "succeeded"` at 12:00:23, then `deploy_ended` `fullDeployStatus: update_failed` at 12:00:39.
- **Cause:** a different code path from w4/478's build path. `lego/operator/internal/publish/publish.go:306` formats a failed publish container as `"%s: %s (exit %d)"` (container name `clone` plus exit code). The missing-directory check runs in that container (`:589`). The operator records `PublishFailed` (`controller/app_controller.go:140`), which `types/v1alpha1/app_types.go:257` `IsBuildFailureReason` does not count as a build failure, so `store/reconciler.go:1513-1520` closes the row `update_failed` after a `build_ended succeeded`.
- **Target:** the reason reads without the container name or exit code, for example `the publish directory "examples/static-site/dist" does not exist in the repository at "<sha>"`. A missing or unreadable publish directory is a user source error: the deploy closes `build_failed` and `build_ended` reports `failed`, as on Render, where "Publish directory dist does not exist!" fails the build. Platform faults in the same container (`:494`, a store read) stay `update_failed`.
- **Precedent:** w4/m155 (done) recorded this exact `update_failed` / `clone: … (exit 2)` outcome while fixing keep-serving; it did not decide the status or the copy. That milestone's guarantee, that the old revision keeps serving after a failed publish, must hold under the new status.
- **Blast radius:** `publish.go:306` formats every failed publish container (`clone`, `extract`, `fetch`, upload), so the copy change applies to all of them. Only the user-source checks should move to `build_failed`; keep the platform-fault messages (`:494-495`, store reads) as `update_failed`. `IsBuildFailureReason` has callers in `store/reconciler.go`, so changing its set needs regression tests for the Docker/native build failures that already map correctly.
- **Unverified:** the dashboard deploy page and notifications for this case were not opened this round. The `extract` path (a built image missing its publish directory, `publish.go:327`) was read from code only.
- **Dedupe:** w4/478 (done; fix `edc4b0a15` renamed only `buildStepNames[clone]` in `build/build.go`). w4/m155 (done) is precedent for the outcome, not a decision on it. `grep -ril "publish directory" .pm` finds m155, m163 and m197, none of which address the status or the copy. No DO_NOT_DO item applies.
