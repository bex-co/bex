# 697 — Postgres suspend, resume and restart answer 202 with the database object, where Render's pinned spec answers 202 with no body

Why: a Render-compatible client sees a body Render never sends on these three verbs, so bex diverges from the pinned contract on a customer-facing endpoint (Render parity first, ADR008).

- **Source / severity / estimate:** found by the w4/m379 worker while walking Render parity (2026-11-17) and left unfiled; filed by the w4/535 loopx worker. **Minor** (parity). ~30m.
- **Spec:** `lego/backend/internal/api/openapi/render-public-api-1.json`, `paths./postgres/{postgresId}/suspend.post`, `/resume.post` and `/restart.post`: each declares only `202` with a `description` and no `content`. `/postgres/{postgresId}/failover.post` is the same shape.
- **bex:** `lego/backend/internal/postgres/rest.go:275-277` route the three verbs through `verb(http.StatusAccepted, …)` (`:186-192`), which calls `respondPostgres` (`:172-178`) and writes `renderOnePostgres` as JSON. Failover at `:279` already uses `core.HandleNoBody(http.StatusAccepted, …)`, so the fix has a local model.
- **Fix (target behavior):** the three verbs answer `202` with an empty body, as failover does; errors keep their current shapes. Check the callers that read the old body first: the bex CLI (pinned Render CLI decodes Render's no-body response), the dashboard and MCP tools that may reuse the REST response, and REST tests asserting the body. GraphQL and MCP return types are their own contract and stay as they are unless they proxy REST.
- **DoD:** a backend test asserts each of `POST /v1/postgres/{id}/suspend|resume|restart` answers `202` with a zero-length body; live on production, the same three calls against a `qa-` Postgres in `bex-canary` answer `202` with `Content-Length: 0` (or no body), and the dashboard's Suspend/Resume/Restart controls still work.
- **Dedupe:** w4/m379 (done) changed restart from `200` to `202` (its README, "Noted, not filed: Restart status") but kept the body. `grep -rn "HandleNoBody" lego/backend/internal/postgres` shows failover only. No open item covers it.
