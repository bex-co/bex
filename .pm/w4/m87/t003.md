## Objective

Make activity-group durations prefer persisted source timestamps so the same transcript produces the same elapsed label live, after terminal replay, and after reconnect.

## Context

- `dashboard/src/features/agent-sessions/lib/stream-duration.ts` currently derives timing from client arrival and loses it when a transcript arrives in one replay frame.
- `session-conversation-impl.tsx` groups typed plan/tool/terminal/reasoning parts and renders the `Worked`/`Thought` labels.
- Replay followed by live tail may repeat already-seen parts; duration calculation must compose with the existing sequence/dedupe behavior.

## Steps

1. Prefer valid source timestamps when calculating group start/end duration, falling back to current live-arrival behavior only where persisted timing is absent.
2. Clamp or ignore out-of-order/invalid values so durations are never negative or unbounded.
3. Preserve calculation state across reconnect without double-counting replayed parts and render legacy fallback copy unchanged.

## Files

- `dashboard/src/features/agent-sessions/lib/stream-duration.ts`
- `dashboard/src/features/agent-sessions/components/session-conversation-impl.tsx`

- `dashboard/src/features/agent-sessions/components/__tests__/session-conversation-impl.test.tsx`

## Acceptance criteria

- [ ] One timestamped transcript renders the same elapsed durations during live streaming and terminal replay.
- [ ] Reconnect/replay does not inflate duration or duplicate activity groups.
- [ ] Out-of-order, invalid, and equal timestamps never produce negative or misleading values.
- [ ] Fully legacy and mixed transcripts retain a clear fallback presentation.

## Out of scope

- Wall-clock billing, token metering, session total-duration fields, or reconstructing timing for old parts.
