## Objective

Stamp each typed UI-message part once at the agent driver publication boundary using a documented UTC timestamp that survives live delivery and durable replay unchanged.

## Context

- `w5/m66` moves ACP updates into one typed mapper in `lego/agent-image/driver/src/acp-map.ts`; its closeout is the prerequisite for this task.
- `session.ts` publishes parts to the stream hub, turn mirror, session log, and gateway tee. Stamping after those branches would produce divergent times.
- ADR047 D3 and ADR051 require byte-transparent forwarding after the driver emits a part.

## Steps

1. Define an optional source-timestamp field and one UTC wire format for typed transcript parts.
2. Assign the timestamp at the single mapper/publication seam before any sink sees the part, preserving an existing timestamp on retry/replay.
3. Extend the ACP fixture assertions to cover representative text, reasoning, tool, plan, diff, and terminal parts.

- `lego/agent-image/driver/src/acp-map.ts`

- `lego/agent-image/driver/fixtures/acp-agent.mjs`
- `lego/agent-image/driver/test/`

## Acceptance criteria

- [ ] Every newly emitted typed part has one valid UTC source timestamp before publication to any sink.
- [ ] Re-publication or replay preserves the original value rather than stamping a new time.
- [ ] All supported ACP update classes retain their existing payload semantics.
- [ ] Driver tests prove the field reaches hub history and the persisted/logged stream identically.

## Out of scope

- Gateway timestamp synthesis, database columns, server receipt times, or changing ACP ordering semantics.
