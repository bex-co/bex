## Objective

Document durable transcript timing as a Bex agent-session extension and verify the additive field does not create drift across existing public session surfaces or consumers.

## Context

- ADR018 records agent sessions as a Bex extension because Render exposes no equivalent cloud-coding-agent product.
- Timestamps travel on the existing UI-message transcript stream, not the REST/GraphQL/MCP session metadata object.
- Dashboard and any active mobile transcript consumer must interpret the same additive stream field consistently or explicitly ignore it safely.

## Steps

1. Recheck ADR018's agent-session extension row and ADR047/ADR051 transcript contract.
2. Verify REST, GraphQL, and MCP session fields/error shapes remain unchanged and transcript transports remain byte-transparent.
3. Audit dashboard/mobile consumers for compatible optional-field behavior and record the extension evidence.
