## Objective

For an image-port service whose primary was chosen explicitly (a `port` on create or in Settings, or a `PORT` env), the stall reason says "Nothing accepted a TCP connection on port 10000, the primary port selected from the image's declared TCP ports (80, 10000). Bind the server to 0.0.0.0 on one of those ports …". In that case the image does not declare 10000; the user configured it. The advice is also already met: whoami was bound to `0.0.0.0:80`, "one of those ports", and the rollout still stalled. Target behavior: in a configured mode (`web-image-configured-v1` / `image-configured-v1`, or `status.envPort` set), the hint names the port as **the service's configured port** (or `PORT`), lists only the ports the image actually declares, and tells the user to set the service's port, or remove it, to one of those. The advice must not be to bind to a port the configured primary will not health-check. In a discovery mode, keep today's wording.

**Severity:** minor (misleading copy on a failing deploy). **Source:** live `/qa-find-bugs w4` loop run 828c, 2026-10-27 UTC, the same fixture as t010 (dashboard-created `traefik/whoami`, `port: 10000`).

## Context

- Live stall reason (GraphQL `deploys[0].stallReason`, `dep-dbg5opdn83uc738uui00`): "… Nothing accepted a TCP connection on port 10000, the primary port selected from the image's declared TCP ports (80, 10000). Bind the server to 0.0.0.0 on one of those ports, or set the service's port to the one it listens on." The app log at the same time said `Starting up on port 80`.
- `lego/operator/internal/controller/app_controller.go:5420-5435` `imagePortStallHint` prints `app.Status.ImageNetwork.Ports` verbatim as "the image's declared TCP ports". In configured mode that list already includes the configured primary (`resolveImageNetwork`, `image_network.go:95-101` `configured`/`configuredPrimary`).
- `configuredPortMode` (`image_network.go:56`) is the existing discriminator. The `EnvPort` branch must be included too.
- `detectBoundPort` (`port_detect.go:83`) deliberately skips image-port apps, so this hint is the only listener guidance these users get.

## Steps

1. Split `imagePortStallHint` on configured vs discovered primary. In the configured case, name the source (service port or `PORT`), list the declared ports without the configured primary, and point at Settings → Port.
2. Table tests: discovery mode is unchanged; explicit port not declared by the image; `PORT` env not declared; explicit port that **is** declared (reads as configured, with no duplicate in the list).
