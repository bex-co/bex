## Objective

Since m243, every new Docker/image web service serves on its image's port. When such a Free service is asleep, the activator holds a non-browser request (JSON, missing or wildcard `Accept` — API clients, curl, uptime monitors, webhook senders) through the cold start and should then serve it from the app (w8/178, "as Render does"). Instead it dials the wrong port and answers `502 {"error":"bad gateway"}` after the full 90 s, although the app woke within seconds.

**Severity:** major (every non-browser request to a sleeping image-port Free web service fails, which is most new image services). **Source:** live `/qa-find-bugs w4` loop run 5a85, 2026-10-27 UTC (`muse.env`, `bex-canary`, pin `b4726243e74f`), REST. Owned fixture `srv-dbg3aj4d3d3c73caqh7g` (`ghcr.io/nginxinc/nginx-unprivileged:stable-alpine`, `EXPOSE 8080`, `openPorts: [8080]`) with `PATCH … {"serviceDetails":{"idleTTLSeconds":60}}`. It was deleted (`GET` → 404).

## Context

| Probe | Answer | Events |
| --- | --- | --- |
| bare `curl https://<host>/` at ~05:25:57, asleep since 05:25:41 | `502 {"error":"bad gateway"}` after **90.9 s** | `service_woken` at **05:26:01** (4 s in) |
| `curl -H 'Accept: application/json'` at 05:36:14, asleep since 05:35:41 | `502 {"error":"bad gateway"}` after **92.1 s** | `service_woken` at **05:36:27** (13 s in) |
| control: `Accept: text/html` | `503` interstitial, then `200` once awake | — |
| control: 3.5 min of traffic every ~13 s while awake | stayed `Running`, so activity detection works | no `service_hibernated` until traffic stopped |

Root cause:

- `lego/operator/cmd/activator/hold.go:97-101` `serviceURL(app)` proxies held requests to `<app>.<ns>.svc:<app.ServingPort()>`.
- `lego/types/v1alpha1/image_network.go:103-111` `ServingPort()` excludes `HasImagePorts()` apps from its `EnvPort`/`DetectedPort` branches and returns `Spec.EffectivePort()` = 10000. But the app's Service exposes only the image network's ports (`tcp-8080`, `privateServiceProjection`).
- Every dial is refused. The proxy's dial loop (`hold.go:132-148`) retries until the 90 s bound, then the `ErrorHandler` answers `502`. Note that it is not even the documented `504` timeout.
- `ServicePort()` (`image_network.go:114-125`) already returns the serving network's `PrimaryPort` for image-port apps; it is the value the proxy needs.

Blast radius: production `ServingPort()` callers outside `types`. Each must be checked for image-port apps; the activity detector was empirically fine, the rest unverified:
- `operator/cmd/activator/hold.go:100` (this bug)
- `operator/internal/controller/activity.go:137` (Traefik activity label; empirically fine in this run)
- `backend/internal/metrics/service.go:1143` and `:1377` (HTTP metrics service-port filter, likely empty HTTP metrics for image-port services; unverified)
- `backend/internal/apps/blueprint_generate.go:686` and `:707` (Blueprint export port; unverified)

## Steps

1. Make the activator's proxy target the port the Service actually publishes: `ServicePort()` (serving network primary for image-port apps), not `ServingPort()`.
2. Audit the other callers above, and decide per caller between `ServingPort()` (container listener) and `ServicePort()` (published Service port). Test each for an image-port app.
3. When the dial bound expires, answer the documented `504 {"error":"service did not wake in time"}` rather than a generic `502`.

## Acceptance criteria

- [ ] Unit/envtest: `serviceURL` for an image-port App with serving network 8080 targets `:8080`; for a configured-port App it is unchanged.
- [ ] Live: a sleeping Free `ghcr.io/nginxinc/nginx-unprivileged` service answers a bare `curl` and an `Accept: application/json` request with the app's `200` within the wake time, not a `502` after 90 s.
