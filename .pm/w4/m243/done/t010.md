## Objective

m243 made a new Docker/image web service serve on its image's `EXPOSE`d port, but only when the create request carries **no** port. The dashboard's New Web Service form always sends one: it pre-fills **Port = 10000**, tells the user "Your container must listen on port 10000", and submits `port: 10000`. The backend then stamps `web-image-configured-v1` with primary 10000, so every image or Docker web service created from the dashboard skips discovery. An image that listens on its declared port (whoami :80, nginx :80, hello-go :3000) never goes live. Target behavior: for a web service whose source is a prebuilt image or a Git Docker build, the form behaves like the private-service image-port shape (w6/m148). The Port field is optional and blank by default, its placeholder and hint describe image discovery, and a blank field sends **no** `port`. Settings → Port shows the image-port copy for these services, never "(default 10000)".

**Severity:** major. The dashboard's default path for an image web service is a first deploy that stalls on a TCP check against 10000 until the user finds and changes the port. **Source:** live `/qa-find-bugs w4` loop run 828c, 2026-10-27 UTC (`muse.env`, workspace `tea-daif693dqjvc73e7as3g`, dashboard.bex.co).

Root cause:

- `dashboard/src/features/services/lib/create-service-input.ts:119` sets `imagePorts: form.serviceType === "private_service" && isDockerBuild`. This predicate predates m243 and was never widened, so web services, and image-tab sources of any type, get the configured-port shape.
- Consumers of `shape.imagePorts`: `portDraft` (`:129`, pre-fills `DEFAULT_SERVICE_PORT`), `portIsValid` (`:135`, blank invalid), the payload (`:259`, sends `parsePort(portDraft)`), and `routes/services.new.tsx:504-512` (placeholder and hint).
- Backend: `lego/backend/internal/apps/service.go:2549-2557` stamps `PortModeWebImageV1` for `TypeWebService && (Repo != "" || Image != "")`, or `…ConfiguredV1` whenever `req.Port > 0`. The UI must mirror **this** predicate (web + Git Docker build, or web + prebuilt image), as reached through `runsContainerPolicy`.
- Private + prebuilt image is **not** an image-port shape on the backend (`:2537` requires `spec.Repo != ""`), so it keeps the configured-port form. Do not widen it.
- Settings: `dashboard/src/features/services/lib/port.ts:58` `openPortsDisplay` returns `none` for anything that is not a private service. So `publishesImagePorts` (`:68`, read by `routes/services.$serviceId.settings.tsx:323`) is false for every image-port web service, and `ServicePortRow` shows the "default 10000" copy.

## Steps

1. Widen `buildShape().imagePorts` to the backend's predicate: `(private_service && isDockerBuild) || (web_service && (isDockerBuild || isImageSource))`. Prefer one shared helper over a third copy.
2. Check every consumer: blank draft, blank valid, no `port` on the wire, and the image-port placeholder and hint. Reword `services.createFieldPortImageHint` and `createFieldPortFromImage` (en + zh) so they no longer say "private service" in their descriptions.
3. Settings: make `openPortsDisplay`/`publishesImagePorts` cover image-port web services, or key it on the service's port mode if GraphQL exposes it. A single-port web image such as whoami shows the image-port hint, not "(default 10000)". Check the Service Address and open-ports rendering still holds for private services.
4. Unit tests in `create-service-input` for each shape: web+image, web+Git Docker, web+native (still pre-filled 10000), private+Git Docker (unchanged), private+image (unchanged). Cover a payload with a blank port (no `port` key) and one with an explicit port (sent).
