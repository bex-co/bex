## Objective

Clients can read the urgency every selectable push event is delivered at, from the same table the push worker projects, on REST and GraphQL.

## Context

- `lego/backend/internal/notifications/push_worker.go` assigns urgency inline per projection. Today `deploy_started`, `deploy_succeeded`, `service_suspended` and `service_resumed` are Routine; the other 14 selectable events are Important or Critical.
- `delivery_policy.go:288-289` drops an event below the effective minimum.
- Surfaces: REST `GET/PATCH /v1/notification-settings/push` (`rest.go:69-92`), GraphQL `pushNotificationSettings` / `updatePushNotificationSettings` (`graphql.go`). MCP has none.

## Steps

1. Lift the per-event urgency into one exported table (event → urgency) that `projectPushEvent` reads, so the projection and the published value cannot diverge.
2. Expose it as a read: either an `eventUrgencies` field on the settings view or a sibling catalog query. Keep the existing response fields unchanged.
3. Add a test that iterates every `DeliveryEvent` the projection can emit and asserts that the published urgency equals the projected one.

## Files

- `lego/backend/internal/notifications/push_worker.go`, `service.go`, `rest.go`, `graphql.go` and their tests

## Acceptance criteria

- [ ] REST and GraphQL return identical event → urgency tables covering all 18 selectable events.
- [ ] The drift test fails if any projection's urgency changes without the table.

## Out of scope

- Changing any event's urgency, or the drop rule.
