## Root cause and fix boundary

- `dashboard/src/features/services/components/editable-field-row.tsx:198–200` gives the control/actions a single unwrapped flex row. Its SelectTrigger at :224–229 is `flex-1` without `min-w-0` or wrapping, while shared Button (`common/components/ui/button.tsx:8`) is shrink-0. The trigger's auto minimum retains its selected label's intrinsic width, so adding fixed-size actions overflows the row.
- `common/components/ui/select.tsx:38` sets whitespace-nowrap, a fixed height, and conflicting line-clamp/flex value rules. Merely trimming or hiding the label would lose the setting or recommendation. The working Input primitive explicitly has min-w-0 (`input.tsx:15`).
- The editor's open SelectContent inherits height-only containment at `select.tsx:63`; its Viewport minimum at :77 tracks the trigger width. The notification menu repeats the same long-label width problem at360.
- Opened the **locked and installed** Radix Select2.2.6: `dist/index.mjs:218–241` strips SelectValue className/style, and :925 portals selected ItemText children into that value. Use a trigger descendant selector/wrapped child that reaches the rendered label; adding a class to SelectValue alone does not express the fix. Popper1.2.8 `dist/index.mjs:152` uses minWidth:max-content; Select exposes `--radix-select-content-available-width` at :697. Collision positioning alone cannot shrink its contents.

Target the **options Select variant inside EditableFieldRow**, preserving full option text. Allow its trigger/value to shrink and wrap with a height that accommodates the label; keep the pencil inside the card. On narrow edit rows, put the selector above a reachable Cancel/Save group or an equivalent bounded layout. Retain the existing desktop alignment. Bound this editor's open menu/viewport to available width and wrap long options; do not leave the trigger-width minimum wider than that cap.

DOM-only diagnoses establish feasibility, without changing the deployed app:

- At390, wrapping the edit row and giving the trigger a full-width basis/min-width0 moved notification Save from beyond right444 to x114.36–229.78; row client/scroll became316/316. Full failure label retained.
- At360, min-width0 and wrapping the default value kept the complete label in a58px trigger x37–279 and pencil x287–323; row286/286.
- After400ms settle, bounding the notification menu to340px and wrapping options yielded x10–350, client/scroll338/338; full default option wraps to52px and remains readable.
- Reload discarded all styles and reproduced the original overflow. An earlier menu diagnosis was measured during a Radix scale animation and is **discarded**; the400ms settled capture above is the evidence.
