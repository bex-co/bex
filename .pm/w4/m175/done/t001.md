## Objective

Make the Loki request-metrics source return a final bucket that covers `(lastBoundary, end]`, so `http_requests` (and host/path-filtered `http_latency`) never drop the newest partial bucket.

## Context

- `lego/backend/internal/metrics/lokisource.go:60-66` (query_range URL), `:89-110` (`lokiRequestQueryFor`).
- `lego/backend/internal/metrics/service.go:996-1023` (unfiltered `http_requests` → Loki), `:1062-1090` (`readRequestSeries`).
- Live numbers: milestone README (24h `end=now` → 0; `end=now+720` → 127 at `15:12:00`).

## Steps

1. Confirm where the epoch alignment happens (Loki `query_range` step handling at the pinned version versus our own window code) and record it.
2. Round `end` up to the next multiple of `step` for the Loki call, or add a separate instant `count_over_time` for the partial tail. Make sure the first bucket does not extend before `start`.
3. Unit test with a fake Loki that asserts the request bounds: `end` not on a boundary must still be covered.

## Files

- `lego/backend/internal/metrics/lokisource.go`, `service.go`, tests.

## Acceptance criteria

- [x] For each dashboard preset, 125 requests made just after a boundary are counted when read immediately.
- [x] No double counting across buckets; m119's 60 s exactness holds.

## Done 2026-10-05

- **Where the alignment happens:** Loki, not bex. The pinned loki chart 6.55.0 (Loki 3.6.7) renders `query_range.align_queries_with_step: true` (`values.yaml:290`). `pkg/querier/queryrange/queryrangebase/step_align.go` `StepAlignMiddleware` floors **both** `start` and `end` to the step. Every point `t` counts `(t-step, t]`, so a floored `end` dropped `(floor(end), end]`.
- **Fix:** `lego/backend/internal/metrics/lokisource.go` `lokiStepBounds` rounds both bounds **up** to the step (ns) before `query_range`. The last point is then the bucket containing `end`, and the first is the bucket containing `start` (before, it was the wholly pre-window bucket). Buckets stay contiguous `[step]` windows, so nothing is counted twice. This covers `http_requests` (unfiltered and host/path) and host/path `http_latency`, the same URL builder.
- **Test:** `TestLokiRequestCountsIncludeTheBucketContainingEnd` uses a fake Loki that applies the middleware's floor and `count_over_time` semantics. It covers all 8 dashboard presets, 125 requests 61 s after a boundary read 4 min later, plus one pre-window request. It asserts sum = 125 and last point ≥ newest request. It fails on 4 coarse presets before the fix and passes after.
