## Objective

`query_render_postgres` returns what Render's server returns for the same query, and keeps bex's read-only and timeout rails.

## Context

- [README § Round 299 extension](README.md#round-299-extension--query_render_postgres-answers-columns-and-rows-capped-at-500-rows-2026-11-13-14431452-utc-pin-5de3d5bcce8e).
- The tool: `lego/backend/internal/postgres/mcp.go:165-170`, registered with `mcputil.AddExactJSONTool` (`lego/backend/internal/mcputil/mcputil.go:90-114`). It returns `QueryResult` (`query.go:88-93`).
- The limits: `query.go:53-62`, enforced in `collectQueryRows` (`:262-300`).
- Render's tool: `pkg/postgres/tools.go`, `collectRows` and `truncatedResultMessage`, with `maxQueryResultBytes = 5 << 20`.

## Steps

1. Give the MCP path its own limits, passed through `queryLimits`:
   - no row cap;
   - a 5 MB bound on the encoded JSON array. Stop before the row that would pass it, and mark the result truncated;
   - keep the column cap and the wire cap as memory rails, but raise the per-cell and per-row caps to the 5 MB budget, so a row that fits Render's bound is returned;
   - keep the 10 s statement timeout, the read-only envelope and the single-statement rule.
2. Encode the text as Render does:
   - a JSON array of objects, one key per distinct column name, with the last column winning, as Render's map does;
   - each value goes through bex's exact encoder and value policy (w4/m157, w4/m158), so a bigint or numeric stays exact.
3. When the result is truncated, add Render's notice as a second `TextContent` (`truncatedResultMessage`), worded for the row count, including the "first row alone is over 5 MB" case. Do not set `isError`.
4. Drop `outputSchema` and `structuredContent` for this tool, since Render sends neither and an array cannot be `structuredContent`. Or keep an object beside the text, as t001 decides for the list tools. Record the choice.
5. Leave REST `POST /v1/postgres/{id}/query`, GraphQL `executeDatabaseQuery` and the insights reads on `QueryResult` and the console limits. They are bex's console extension.
6. Correct w4/m158's "advertised QueryResult output shape remain stable" note in ADR018 when t004 updates it.

## Acceptance criteria

- [ ] Unit tests decode the first text content as a JSON array of objects for: a single row, an empty result, a duplicate column name and a bigint above 2^53.
- [ ] A 600-row result returns 600 objects.
- [ ] A result over 5 MB returns the rows that fit, then the notice, without `isError`. A first row over 5 MB returns `[]` and the first-row notice.
- [ ] A write, a multi-statement input and a timeout still answer `isError`.
- [ ] The console tests (REST and GraphQL) are unchanged and pass.
