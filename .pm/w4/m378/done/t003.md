## Objective

Extend the w1/m70 MCP pin from names and arguments to result shapes, for every tool bex shares with Render's server.

## Context

- The pin today is `render-mcp-tools.json`, captured by `scripts/render-mcp-capture.py`, checked by `lego/backend/internal/api/render_mcp.go`. It excludes results.
- Render's formatting is plain `json.Marshal` of its client types, plus the cursor suffix on `list_deploys`/`list_events`.

## Steps

1. Record, per shared tool, the result form (object, array, or array + cursor) and the item type's key set, from Render's server at the pinned commit.
2. Add a test that drives bex's MCP handler per tool on a fake core and asserts its text matches the recorded form and keys. Allow additive keys only where ADR018 records them.
3. Note in ADR018's MCP paragraph that result shapes are now pinned.

## Acceptance criteria

- [x] Reverting t001, t002 or t011 fails the new test.
- [x] The capture script documents how to refresh the recorded shapes.

## Outcome (2026-11-14)

- `lego/backend/internal/api/openapi/render-mcp-results.json` (embedded as `openapi.RenderMCPResults`) records, for all 26 shared tools, the text form (`object`/`array`/`arrayCursor`/`text`, plus `emptyText`) and the JSON keys (required = no `omitempty`, optional, nested fields) of the 18 Go types upstream marshals, captured at `23fb336` (the tools pin's commit) by `scripts/render-mcp-capture.py --results` (the script's docstring says how to refresh it; `RESULT_FORMS`/`RESULT_TYPES` cite each handler).
- `rendertest.AssertRenderMCPResult(t, tool, res)` checks a bex answer: form, Render's always-present keys, and no key outside Render's type plus the ADR018-recorded `MCPResultExtensions`. It is called from the feature tests for every shared tool (apps creates/`list_services`/`get_service`/blueprint tools, deploys `list_deploys`/`get_deploy`/`trigger_deploy`, api `list_events`, logs, metrics, keyvalue, postgres incl. query, workspaces, secrets `update_environment_variables`).
- `TestRenderMCPResultsCoverEverySharedTool` keeps the capture in step with the tools pin (same commit, exactly the shared tools); `TestCheckRenderMCPResultCatchesTheOldShapes` shows each pre-m378 shape (wrapped list, cursor field, label map, flat datastore, `{columns, rows}`, `{series}`, bare create) fails, i.e. reverting t001/t002/t011 fails the guard; `TestMCPResultExtensionsAreNotRenderKeys`.
- ADR018 § "MCP result shapes are pinned too (w4/m378)" says result shapes are now pinned.
