## Objective

Each of the six tools returns, as its text content, exactly what Render's server returns for the same call.

## Context

- Shapes and sources: [README § Finding](../README.md#finding-round-295).
- The working pattern is `list_events` (`lego/backend/internal/events/mcp.go:148-155`): marshal the Render-shaped items, then set `CallToolResult.Content` to the text Render sends.
- go-sdk v1.8.0 fills `Content` from the typed `Out` only when `Content` is nil (`mcp/server.go:477-485`).

## Steps

1. For each tool, return a `CallToolResult` whose single `TextContent` is:
   - `list_services`, `list_postgres_instances`, `list_key_value`, `list_workspaces`: `json.Marshal(<items>)`, the bare array of the same item objects the tool returns today, in Render's item shape;
   - `list_log_label_values`: `json.Marshal([]string)`;
   - `list_deploys`: `json.Marshal(<deploys>)` + `"\n\n cursor: "` + the last cursor, or `""` when there is none, as `list_events` does.
2. Decide whether to keep a `structuredContent` beside it. An object is fine if the text is Render's; an array is allowed at this SDK version. Record the choice in the tools' comments, and drop the stale "MCP tool results are objects" reasoning at `logs/mcp.go:90-91`.
3. Keep every argument, default and error as it is.

## Acceptance criteria

- [x] Unit tests decode each tool's first text content and assert its top-level JSON type: an array, or an array plus the cursor suffix.
- [x] The `list_events` control test is unchanged and still passes.

## Outcome (2026-11-14)

- `list_services`, `list_workspaces` and `list_log_label_values` answer one text item, the bare JSON array, through `mcputil.RenderText` (handlers registered with `Out = any`, so no `outputSchema` and no `structuredContent`, as Render's server sends none). `list_workspaces` items are now REST's owner objects (`GET /v1/owners` items: `id`, `name`, `email`, `ipAllowList`, `type`), Render's `client.Owner`; bex's `slug`/`plan`/`role` are gone from the MCP item.
- `list_postgres_instances` / `list_key_value` answer the bare array, or Render's own sentence for an empty workspace (`No Postgres instances found` / `No Key Value instances found`, `pkg/postgres/tools.go:48-50`, `pkg/keyvalue/tools.go:44-46`), via `mcputil.RenderPlainText`.
- `list_deploys` answers `<array>\n\n cursor: <last deploy id>` (`""` on an empty page) through the new `mcputil.RenderListWithCursor`, which `list_events` now uses too.
- Decision on `structuredContent`: none for array/text answers; object answers keep the typed object beside the text. Recorded in the helpers' comments; the stale "MCP tool results are objects" reasoning at `logs/mcp.go` is gone with the struct it justified.
- Deviation, recorded in ADR018: an empty list is `[]` (upstream's own `list_events` writes `[]`), where upstream's `list_services`/`list_deploys` would marshal a nil slice as `null`.
- Tests: `TestMCPKeyValue`, `TestMCPPostgres`, `TestMCPListDeploysPagination` (via `callListDeploys`), `TestMCPListWorkspacesCarriesIPAllowList` (also equal to REST's `/v1/owners` item), `TestRenderListWithCursorIsRendersText`; the `list_events` control test is unchanged and passes.
