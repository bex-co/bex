## Objective

Know Render's `cf-cache-status` for every kind of answer a static site sends before t004 maps the static server's answers onto it.

## Context

- Already captured (milestone README): a first `GET /` `EXPIRED`, the next `HIT`, `HEAD` `HIT`, a missing file's `404` `BYPASS`, a route redirect `BYPASS`, the `http://` redirect `EXPIRED` then `HIT`.
- The static server's other answers (`lego/operator/internal/staticserver/staticserver.go`): `304` (`If-None-Match`, `If-Modified-Since`), `206` for a `Range`, a route rewrite to a local file, an external rewrite (`proxy.go`), a `405`-style answer to another method (`serveOtherMethod`), a custom `404.html`, a hashed asset with a long `Cache-Control` from a header rule, and a header rule that names `CF-Cache-Status` itself.

## Steps

1. Use Render's public static sites (`vue.onrender.com`, `create-react-app.onrender.com`, `sveltekit-static.onrender.com`, others whose rules show the case), with `curl` only and read-only requests. Repeat each request at least twice so a cached status shows.
2. Record each answer's status, `age` and whether it carries `rndr-id`, in `docs/render-artifacts/edge-headers.md` under a static-site section. Leave out client addresses.
3. Note each case no public site shows, as not captured.
