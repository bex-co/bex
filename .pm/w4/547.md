# 547 — The service header says "Instances: 1" for a suspended or sleeping service that runs none

Why: right beside "Service Suspended" or "Service Sleeping", the header says one instance is running. The instances API and the Metrics page both say none are, so the page contradicts itself about whether anything is running.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 18, 2026-11-10 12:44–13:00 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor** (UI honesty). ~20m.
- **Fixture:** Free image web service `qa-20261110-dom18` (`srv-dbph3e45ngvc73e8totg`, `docker.io/traefik/whoami:v1.10.1`). Suspended, resumed, then deleted (GET 404, URL 404).
- **Probes:**
  - **Suspended service:** after Settings → Suspend, the header read `Service Suspended` beside `term: Instances` / `definition: "1"`.
    - REST `GET /v1/services/srv-dbph3e45ngvc73e8totg/instances` → `[]`.
    - REST `serviceDetails.numInstances` → `1`.
    - GraphQL `service { replicas suspended }` → `{replicas: 1, suspended: "suspended"}`.
    - The URL answered `503` with `x-render-routing: suspend` and "This service is suspended."
  - **Sleeping service:** same result on the workspace's existing `hello-go` (`srv-dbkq3hdhhjfs73eiahe0`; viewed read-only, not touched). The header read `Service Sleeping` and `Instances 1`, while `GET …/instances` → `[]`.
- **Root cause:** `dashboard/src/features/services/components/service-detail-header.tsx:674-678` renders `services.colInstances` ("Instances") from `service.replicas`. That is the configured count, so it doesn't change when the service is suspended or sleeping. `isSleeping` is already imported at `:57` and used at `:318`.
- **Fix (target behavior):** the header's Instances fact reports how many instances actually run.
  - It reads `0` while the service is suspended or sleeping, matching REST `GET /v1/services/{id}/instances` and the Metrics "Total Instances" series. Otherwise it reads the configured count.
  - A short hint keeps the configured count visible, e.g. "Back to 1 when resumed" / "… when it wakes".
  - en and zh copy. Add a header test for suspended, sleeping and running.
  - REST `numInstances` and GraphQL `replicas` stay unchanged; Render keeps `numInstances` on a suspended service.
- **Blast radius:** one header component. `services.colInstances` is described as a services-table column header, but its only current caller is the header (`:676`), so no table changes.
- **Unverified:**
  - What Render's dashboard shows for instance count on a suspended service. Render's header has no instance count to compare against.
  - The Metrics "Total Instances" value while suspended was not read this round.
- **Dedupe:**
  - w4/m110/t002 (done) fixed Total Instances over-counting terminated pods. w4/258 and w4/059 cover metrics labels.
  - `grep` for the header Instances with suspended or sleeping finds nothing open.
  - Not deploy lag: `service-detail-header.tsx` is unchanged between `c12cd57facb1` and `origin/main`.
- **DoD (live):**
  - With an owned Free service suspended, the header reads Instances `0` beside "Service Suspended", in en and zh.
  - After Resume it reads `1` again, and the URL serves 200.
  - A sleeping service reads `0` until it wakes.
