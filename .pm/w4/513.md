# 513 — A Postgres disk card says "Capacity 1 GiB" beside "1 GB current · 16384 GB max"

Why: the same disk is sized in two unit systems on one card, so an owner reading "1 GiB" next to "1 GB" cannot tell whether autoscaling has already grown it. Render labels database disk sizes in GB.

**Severity:** minor (copy/units) · **Estimate:** 15m · **Worker:** worker4 · **Status:** todo

- **Source:** live `/qa-find-bugs w4`, production, 2026-11-05 23:42–23:48 UTC, round 112. Read-only, workspace `bex-canary`. Prod pin `cc3c51e12952`; research on main `cab9b7996`.
- **Probe:** `/databases/dpg-dbk3isgrv49s73eq43mg` → Metrics (`#metrics`). `page.locator('main').ariaSnapshot()` shows `text: Live resource usage for this instance Disk Capacity 1 GiB Disk autoscaling 1 GB current · 16384 GB max`. The disk chart axis reads `0 B 512.0 MiB 1.0 GiB`.
- **Root cause:**
  - `dashboard/src/features/metrics/components/datastore-metrics-panel.tsx:175-176` renders `metrics.diskCapacityLabel` with `formatMetricValue("bytes", diskCapacityValue)`, a binary formatter ("1 GiB").
  - The autoscaling sizes beside it come from `databases.diskAutoscalingSize` (`dashboard/src/features/databases/locales/en.ts:444`), hard-coded "{current} GB current · {cap} GB max".
- **Fix:**
  - Target: the capacity annotation uses the same unit the plan and autoscaling copy use, whole "GB" as Render shows it, so the two read "1 GB" and "1 GB current".
  - Format the capacity in GB (the value is the provisioned logical size, w4/m91) and leave the chart's byte axis alone.
  - Update en and zh if the zh string carries a unit.
- **Blast radius:**
  - `DatastoreMetricsPanel` has 3 mounts: `routes/databases.$databaseId.tsx:311`, `routes/keyvalue.$keyValueId.tsx:218` and `features/services/components/disk-section.tsx:182` (service disks).
  - Decide the unit for all three together; Key Value and service disks have no autoscaling line, but the capacity label should match their plan/disk-size copy too.
  - Add a test per mount for the label.
- **Unverified:**
  - The Key Value and service-disk panels were not opened this run.
  - Render's exact capacity label wording was not captured.
- **Render:** Render's database and disk sizes are stated in GB.
- **Dedupe:**
  - w4/m91 (done, via w4/071/074) fixed which capacity is shown (logical, not the PVC floor), not its unit.
  - `grep` for GiB with disk/capacity in open items found nothing. Not in `DO_NOT_DO.md`. No fix on main.
