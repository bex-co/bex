# `createProject`/`renameProject` accept an EMPTY or whitespace-only project name on GraphQL + MCP (REST rejects it) — name validation lives in the REST handler, not the shared service method

Why: the project-name non-empty check is enforced only in the REST handlers (`rest.go:122` create, `rest.go:144` rename), not in the shared service methods, so the GraphQL and MCP entrypoints bypass it and create/rename projects to a blank name. The sibling `createEnvGroup` validates in its **service** method, so it correctly rejects empty on every surface — projects is the inconsistent one. A nameless project renders blank in the dashboard project switcher/lists and diverges from Render (which requires a name). The fix belongs in the shared service method so all three surfaces enforce it.

Source: live QA 2026-09-07, `$qa-find-bugs w4` pass 33 (write-path input-validation fuzzing; cross-surface inconsistency).

## Symptom (reproduced live on prod, authenticated GraphQL past Cloudflare)

| operation | result |
| --- | --- |
| `createProject(name:"", ownerId:<team>)` | ❌ **OK** — creates `prj-…` with `name:""` (read-back confirmed on GraphQL `project(id){name}` **and** REST `/v1/projects` list → `name:""`) |
| `createProject(name:"   ", ownerId:<team>)` | ❌ **OK** — creates project with `name:"   "` (whitespace-only, not trimmed) |
| `renameProject(id:<valid>, name:"")` | ❌ **OK** — renames an existing project to `name:""` (read-back confirmed `""`) |
| **CONTROL (sibling, correct):** `createEnvGroup(name:"")` | ✅ `bad request: env group name is required` |
| **CONTROL (clean):** `createProject(name:"x", ownerId:"tea-!!")` / `"not-an-owner"` | ✅ `forbidden` (owner authz; unrelated to the name gap) |

All test projects were deleted; residual check returned **zero** qa-/blank projects.

Durable probe: `{"query":"mutation($n:String!,$o:String!){ createProject(name:$n, ownerId:$o){ id name } }","variables":{"n":"","o":"tea-d98210cbbpdc73dcrkvg"}}` → `{"data":{"createProject":{"id":"prj-…","name":""}}}` (HTTP 200, no error).

## Root cause (code-verified on `main` HEAD `77b414ec9` — not deploy-lag)

- GraphQL `createProject` (`lego/backend/internal/projects/graphql.go:80`) → `s.Create(ctx, ownerId, name)` — passes the raw name, no trim/validate.
- GraphQL `renameProject` (`graphql.go:83`, via `gqlutil.ArgMutation`) → `s.Rename(ctx, id, name)` — no guard.
- MCP `create_project` (`mcp.go:97`) → `s.Create(ctx, …, in.Name)`; MCP `update_project` (`mcp.go:128`) → `s.Rename(ctx, in.ID, *in.Name)` — no guard (code-traced, not live-probed).
- Service `Create` (`service.go:343`) → `CreateWithEnvironments` (`service.go:348`) trims/validates **environment** names (`service.go:357-360`) but **never the project `name`** — it goes straight to the store. `Rename` (`service.go:442`) passes `name` straight to `s.Store.RenameProject` with no trim/validate.
- REST `createProject` (`rest.go:122-123`: `if strings.TrimSpace(req.Name) == "" || req.OwnerID == "" { return core.ErrBadRequest }`) and REST `renameProject` (`rest.go:144-145`) **do** guard — so only the REST surface is protected; GraphQL/MCP bypass the guard because it lives **above** the service, not inside it.

**Control (code-verified, load-bearing):** envgroups validates in the **service** method — `envgroups/service.go:420-422` (`name := strings.TrimSpace(req.Name); if name=="" { return ErrBadRequest "env group name is required" }`) and the rename path at `:701-703` — so every envgroups surface (incl. GraphQL) rejects empty. That proves the correct pattern and why the sibling behaves while projects does not.

## Target behavior / fix

Move the project-name non-empty validation **into the shared service methods** so all surfaces enforce it identically — in `CreateWithEnvironments` (`service.go:348`, before the store create) and `Rename` (`service.go:442`, before `RenameProject`):

```go
name = strings.TrimSpace(name)
if name == "" {
    return ProjectView{}, fmt.Errorf("%w: project name is required", core.ErrBadRequest)
}
```

(mirror `envgroups/service.go:420-422`). Trim so whitespace-only (`"   "`) is also rejected and stored names are trimmed. The REST guards (`rest.go:122/144`) then become redundant defense-in-depth (keep or drop). Result: `createProject`/`renameProject` reject empty/whitespace names on REST + GraphQL + MCP, consistent with `createEnvGroup` and Render.

## Blast radius (exhaustive, grepped)

Two verbs × three surfaces = six entrypoints:

- **createProject:** REST `rest.go:122` (guarded), GraphQL `graphql.go:80` (bug), MCP `mcp.go:97` (bug).
- **renameProject:** REST `rest.go:144` (guarded), GraphQL `graphql.go:83` (bug), MCP `mcp.go:128` (bug).

The fix in the **two** shared service methods (`CreateWithEnvironments:348`, `Rename:442`) covers all six. Regression tests must cover: GraphQL/MCP now reject empty + whitespace (new), REST still rejects (unchanged), valid names still create/rename (unchanged), and the `createEnvGroup` control stays green.

## Adjacent classes

- valid name → created/renamed (unchanged).
- empty / whitespace name → **bad-request** (the fix; currently accepted on GraphQL/MCP).
- duplicate name → already `a project named %q already exists` conflict (`service.go:430-436`, unchanged).
- unknown / malformed `ownerId` → **forbidden** (unchanged).

## Render parity

Render requires a non-empty project name; bex REST matches, GraphQL/MCP diverge (accept empty/whitespace). Parity task applies (the fix moves REST/GraphQL/MCP into agreement).

## Severity

**Minor** — no data loss, no blocked journey (normal named creates work); but it lets GraphQL/MCP callers (agents, CLI) create or rename to a blank/whitespace project that renders as an empty entry in the dashboard project switcher and lists, is a cross-surface inconsistency (same operation: REST rejects, GraphQL+MCP accept), and diverges from the sibling `createEnvGroup` and from Render.

## Unverified this run

- **MCP** `create_project`/`update_project` were not live-probed (code-traced to the same `s.Create`/`s.Rename` calls at `mcp.go:97/128` with no guard — same bypass expected).
- Whether the dashboard UI blocks an empty name client-side was not checked; the defect is **server-side** API enforcement regardless.
- `createProject` empty + whitespace and `renameProject`-to-empty were **live-verified on GraphQL**.
