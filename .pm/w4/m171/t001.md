## Objective

When a user suspends an App, close any deploy row open for an unserved release as `canceled`, with a neutral cancel reason (for example "Canceled: the service was suspended"). Do this in the suspend verb or on the first reconcile pass that observes `spec.suspended` with a `Suspended` park. Leave auto-hibernate parks as w6/m147 defined them.

## Context

- `lego/backend/internal/apps/service.go:3514` `Suspend` → `setSuspended`.
- `lego/backend/internal/store/reconciler.go` around 700: the park keeps the row open. `deployCloseFailureReason` `:813` and `timedOutDeployReason` `:1533` produce the false failure at the gate.
- The reconciler already separates a user suspension via `app.Spec.Suspended` (`reconciler.go:1603-1606`, "The operator never writes spec.suspended").
- w4/089: the user-cancel path (`deploys.Cancel` / `CloseDeploy`) is the precedent for a non-supersede cancel.

## Steps

1. Pick the single place to close: prefer the reconciler (one path for REST/GraphQL/MCP/CLI suspends). Treat `Spec.Suspended && open row for generation > served` as `DeployCanceled` with the suspend reason.
2. Close the build lifecycle facts like a user cancel (no `superseded` reason code).

## Acceptance criteria

- [ ] Store-backed test: an open row plus suspend closes `canceled` on the next pass, with no `failureReason`. An auto-hibernate park keeps today's w6/m147 behavior. Suspend with no open row touches nothing.
