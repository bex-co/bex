# 629 — A service's process sees its hostname as the internal pod name (`tea-<workspace>-<slug>-<rs>-<pod>`), not the `srv-…` instance id the instances API, logs and metrics report; Render's hostname is `srv-…-<suffix>`

Why: frameworks name an instance by its hostname (`os.hostname()`, Celery's `celery@%h`, Sidekiq's `hostname:pid`, Sentry's `server_name`, Datadog and New Relic hosts). On bex that name matches nothing the platform shows. A user cannot tie an app's own log line or error report to the instance on the Logs, Metrics or Shell pages. w4/386 fixed `RENDER_INSTANCE_ID`, but the hostname still exposes the operator's naming.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 274, 2026-11-13 08:21–08:28 UTC (`muse.env`, workspace `bex-canary`; pin `4c3c68e6b05b`). **Minor** (parity and correlation; nothing breaks). ~45m.
- **Fixtures:** all created by REST and deleted afterwards (`DELETE` 204, then `GET` 404):
  - Starter private service `qa-20261113-r274-priv` (`srv-dbrchdov8soc73b22r2g`, `docker.io/mendhak/http-https-echo:35`, no port set);
  - Free web service `qa-20261113-r274-gw2` (`srv-dbrcif82er5s73bkikr0`, `docker.io/alpine/socat:1.8.0.3`, Docker Command `socat TCP-LISTEN:10000,fork,reuseaddr TCP:qa-20261113-r274-priv:8080`);
  - Starter background worker `qa-20261113-r274-wrk` (`srv-dbrchdo2er5s73bkikog`, busybox tick loop).
- **Probe:**

  - `curl https://qa-20261113-r274-gw2.onbex.co/h` went through the gateway to the private service. The echo's `os.hostname` was `tea-daif693dqjvc73e7as3g-qa-20261113-r274-priv-8644795866-dft7w`.

- **Render:** w2/m55 recorded Render's live Web Shell prompt as `render@srv-…-xc8cn`. A Render instance's hostname is therefore named after its service id, the identity Render shows for the instance.
- **Root cause:**
  - Tenant pods set no `spec.hostname`, so the kubelet uses the pod name: the App CR name `tea-<workspace>-<slug>`, then the ReplicaSet hash and 5 random characters.
  - `InstanceIDStamper.Handle` (`lego/operator/internal/webhook/instance_id.go:65-77`) already computes the public id at pod admission (`renderenv.PublicInstanceID`, `lego/types/renderenv/instance.go:38-41`), but it writes only the `app.bex.co/instance-id` annotation that `RENDER_INSTANCE_ID` reads (`platform_env.go`).
  - `grep -rn "Spec.Hostname\|Hostname:" lego/operator/internal --include="*.go"` (tests excluded) finds no assignment.
- **Fix (target behavior):** a tenant instance's hostname is its public instance id: the same `srv-…-<20 chars>` string as `RENDER_INSTANCE_ID`, `GET …/instances[].id`, and the logs and metrics `instance` label.
  - In the same admission patch, set `pod.Spec.Hostname = want` when it is empty.
  - Change the "already stamped" short-circuit (`:66-68`) so it only skips when both the annotation and the hostname are already set.
  - The id is 45 characters of `[0-9a-v-]`, a valid DNS-1123 label under 63.
  - The hostname is set at admission, not in the pod template, so nothing rolls. Each pod gets the new hostname when it is next created (deploy, restart, scale, eviction).
- **Blast radius:**
  - Every pod the mutating webhook selects (label `app.bex.co/app`): web, private and worker instances, cron runs and pre-deploy jobs.
  - **Elixir (w8/272):** `withElixirNodeHostname` (`elixir_node.go:41-45`) sets `subdomain: nodes`, so the FQDN becomes `<instance id>.nodes.<ns>.svc.cluster.local`, still unique per pod. `TestElixirPodsGetAHostnameWithADomain` must keep passing, and the long-name node must still start.
  - **Cron:** w4/m322's t009 saw cron pod names run past 63 characters, which the kubelet truncates for the hostname. The 45-character id removes that truncation.
  - **Webhook outage:** with `failurePolicy: Ignore` (`config/webhook/manifests.yaml:72`), an outage leaves the pod-name hostname. This is the same degradation as today's empty annotation.
  - No bex code reads a tenant pod's hostname. `grep -rn '"HOSTNAME"\|os.Hostname()' lego` finds only the agent-session env passthrough list (`agentsessions/secrets.go:61`).
- **Tests:**

  - Envtest: a web pod's `/etc/hosts` maps to the id.
  - An Elixir pod keeps its subdomain.
