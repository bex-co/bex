# qa-login.sh's shared session jar lets one hunt revoke another's session

Why: concurrent QA hunts in one checkout share `.playwright-mcp/qa-session.jar`. A run's Phase 8 `--logout` revokes whichever session is in that file, so a hunt can be signed out mid-sweep, or can leave its own session live while revoking someone else's. Both undermine the skill's "revoke only this run's session" rule.

- **Severity:** minor (QA tooling; no product impact). **Estimate:** 30m.
- **Source:** `/qa-find-bugs w4` pass e4a77c, 2026-10-19 UTC, in a checkout another session was also using (it committed `5e75de920` and pushed from this tree during pass 7d3e19).
- **Observed:**
  - The pass logged in at about 00:57Z with `--serve`, which installed the jar, switched workspace, and then loaded `/notifications`.
  - Within about a minute every API call returned 401 and the dashboard redirected to `/auth/login`.
  - `.playwright-mcp/qa-session.jar` was gone, although this run never removed it.
  - The cookie (`ory_kratos_session`) was still in the browser, so the session had been revoked server-side.
  - A re-login whose jar was immediately copied to a private 0600 path (hash-matched against the browser cookie) worked for the rest of the pass.
  - *Cause inferred:* consistent with a concurrent run's `--logout` + `rm -f` on the shared path; the other run was not observed directly.
- **Root cause:** `scripts/qa-login.sh:35` `DEFAULT_JAR=".playwright-mcp/qa-session.jar"`.
  - Every login installs its jar there (`install_logout_jar`, `:490-492`), overwriting any other run's.
  - `--logout` with no path revokes whichever of `DEFAULT_OUT`/`DEFAULT_JAR` exists (`:215-222`).
  - `--serve` gives the caller no other handle. `.claude/skills/qa-find-bugs/SKILL.md` Phase 8 tells every run to `--logout` with no argument and then `rm -f` both shared files.
- **Fix (target behavior):** each login gets its own logout handle, and `--logout` revokes only the handle it is given.
  - Install the jar at a unique 0600 path (for example `.playwright-mcp/qa-session-<random>.jar`) and print that path on the `ok` line next to the loopback URL. A path is not a secret.
  - Make `--logout` require an explicit path. Fail with a usage error instead of guessing a shared default.
  - Update SKILL.md Phases 1 and 8 and `qa-find-bugs-cli` if it uses the same helper.
- **Blast radius:** 4 callers (`grep -rn 'qa-login.sh' .claude scripts`): `.claude/skills/qa-find-bugs/SKILL.md` (Phases 1 and 8), `.claude/skills/qa-find-bugs-cli/SKILL.md:53,150`, `.claude/skills/loopx/SKILL.md:80`, and the script's own `scripts/test_qa_login.py`. The `--cookie-jar` seed option is unchanged.
- **Adjacent classes:**
  - The storage-state `OUT` file has the same shared default (`DEFAULT_OUT`, `:34`) and needs the same treatment.
  - The loopback `--serve` token is already per-run.
  - Kratos sessions from earlier hunts are untouched (`w4/085`).
- **Unverified:** whether pass 7d3e19's, b52e07's or c91d4a's own Phase 8 `--logout` revoked a concurrent run's session instead of its own. Each ran against the shared default path within minutes of its login. The operator may want to check the QA user's active sessions.
- **Dedupe:** `w4/done/085.md` introduced `--logout` for leftover `curl/…` sessions. No item covers concurrent runs sharing the jar.
