## Objective

When a Blueprint sync would update a service that is serving an image override (`servingImage` differs from the declared image), the plan lists `image` among `changedFields`. It also carries a message saying the sync replaces the running image with the declared one. The dashboard's Blueprint review shows that message for an update.

## Context

- `lego/backend/internal/apps/blueprint_state_plan.go:240-260` diffs the manifest against the saved spec, so an override kept in `Spec.ReleaseConfig` is invisible to it. `servingImage(a)` (`apps/service.go:1093`) already names the override.
- An unchanged manifest stays a `noop` (round 407 step 1, Render's behavior).
- `dashboard/src/features/blueprints/components/blueprint-plan-summary.tsx:93` shows `action.message` only for `error`.

## Steps

1. Backend: when the action is an `update` and `servingImage(live) != ""`, add the `image` path and set the message (keep any generated-copy message).
2. Dashboard: show an update's message in muted text. Add an `en` string only if needed.
3. Add a backend plan test, and a dashboard test in `blueprint-plan-summary.test.tsx`.

## Files

- `lego/backend/internal/apps/blueprint_state_plan.go`, its tests
- `dashboard/src/features/blueprints/components/blueprint-plan-summary.tsx`, its test

## Acceptance criteria

- [ ] A changed manifest over an override plans `image` with the message; an unchanged one stays a `noop`.
- [ ] `yarn lint` and `yarn test` pass.

## Out of scope

- Changing what the sync applies (deploying the declared image is correct).
