# 588 — Billing → Charges reads a deleted service as "beancount-api(deleted)", and two deleted services with the same name are indistinguishable except in a hover title

Why: the Charges tree answers "what am I paying for". A screen reader hears each deleted line item run together with its marker. When a name was reused, the month shows two identical rows with different amounts and no visible way to tell which service each was.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 153, 2026-11-12 00:53 UTC (`muse.env`, workspace `bex-canary`; pin `8330744bd643`). **Minor** (accessibility and clarity). ~20m.
- **Probe** (read-only): `/billing?lang=en` → Charges → **Services $4.89** expanded. The accessibility snapshot lists:
  - `button "beancount-gitea(deleted) $1.48"` … `button "beancount-gitea(deleted) $0.01"`: two rows with the same name;
  - `button "beancount-api(deleted) $1.10"`, `button "qa-m273-wp(deleted) $0.05"`, and so on;
  - the one live service reads `button "hello-go $0.00"`.
  - The `beancount-api` row's markup is `<span title="beancount-api (srv-dbk3isorv49s73eq43qg)">beancount-api<span class="… ml-1.5 …">(deleted)</span></span>`, and its `innerText` is `beancount-api(deleted) | $1.10`.
- **Root cause:** `dashboard/src/features/usage/components/charges-card.tsx:156-165`.
  - The deleted marker is a sibling `<span>` separated only by the CSS margin `ml-1.5`, so the accessible name and copied text have no space.
  - The service id that tells two same-named rows apart is only in the `title` attribute (`:156-158`), which keyboard and touch users never see.
  - w4/495 (done) moved this card's "Partial data" explanation out of a hover-only `title` for the same reason. Its closeout cleared this `title` (then `:149`) as one that "repeats visible text". That holds for the name, but not for the id.
- **Fix (target behavior):**
  - The marker is part of the name with a real space, read as "beancount-api (deleted)". Put the space in the text, or render the marker as `{" "}` plus the label.
  - **When two rows in one group share a display name,** each shows a short id suffix visibly, for example `beancount-gitea (deleted) · srv-…q43qg`. Rows with a unique name are unchanged.
  - en and zh. Add a render test for both.
- **Blast radius:** one component, `charges-card.tsx`. Every category's rows render through the same `ResourceRow` (`:130`, mapped at `:217-218`), including Postgres and Key Value. `grep -rn resourceDeleted dashboard/src` finds one use (`:163`), plus the en and zh keys (`locales/en.ts:512`, `zh.ts:504`).
- **Unverified:** how Render's billing view names a deleted service or two with the same name. It wasn't captured.
- **Render:** see Unverified.
- **Dedupe:**
  - w4/129 (done) made deleted resources carry `deleted: true` and their names; w4/495 (done) covered the partial-data caveat.
  - `grep -rli "resourceDeleted\|(deleted)" .pm --include="*.md"` finds 130, 198, 427, 456, 537, 451 and 190 (all done) besides 129. They use "(deleted)" only to describe fixtures; none is about this label.
  - Not deploy lag: `charges-card.tsx` has no newer change on `origin/main`.
- **DoD (live):** `/billing` → Charges → Services, expanded:
  - the accessibility snapshot reads `beancount-api (deleted) $1.10`;
  - the two `beancount-gitea (deleted)` rows each show a visible distinguishing id.
