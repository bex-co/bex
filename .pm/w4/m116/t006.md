## Objective

Empty list responses serialize as JSON `null` where Render's array contract says `[]`. The pinned CLI tolerates both, but `null` is a contract wart on every empty list. Match Render.

## Context

- Live repro 2026-09-17, `bex v0.2.1`, empty workspace scope:
  - `bex ea sandboxes list -o json` → `null` (no sandboxes), exit 0.
  - `bex workflows list -o json` → `null` (workflows stub), exit 0.
- Suspected Go nil-slice serialization on the list envelope(s); Render comparison UNVERIFIED at the wire level (Render documents arrays; confirm one empty-list response shape from Render's OpenAPI `render-public-api-1.json` in-repo or the recorded fixtures before changing the envelope).
- Blast radius: enumerate every list endpoint sharing the envelope — services, deploys, jobs, postgres, keyvalue, projects, environments, sandboxes, workflows — and prove each prints `[]` when empty (a table test over the serializers, not a per-route manual probe).

## Steps

1. Confirm Render's empty-list shape from the in-repo OpenAPI / fixtures.
2. Fix the envelope (likely nil → empty slice at the serialization boundary, once, not per handler).
3. Cover every list route with an empty-case assertion.
