# 668 — A new Python service's build log reads "Using Python 3.14 (default)" though it runs 3.14.10: since w4/620 the narration names the line, not the patch, whenever Render's default equals the line's reviewed patch

Why: the build log is where a user learns which interpreter their service runs. Render's narration names the exact version it chose. bex's did too until w4/620: round 246's build read `==> Using Python 3.14.8 (default)`. w4/620 correctly moved new services to Render's 3.14.10, which equals the 3.14 line's reviewed patch. That route skips the exact-image swap, and the narration falls back to the line. A user now reads "3.14", while `X-Render-Origin-Server` says `Python/3.14.10`. The same line-only narration applies to every native runtime whose default is the line's own patch (for example `==> Using Node 24 (default)`, Render's 24.22.1).

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 368, 2026-11-14 15:22–15:27 UTC (`muse.env`, workspace `bex-canary`; pin `c99e7815ebec`, which carries w4/620's `0e0c13f94`). **Minor** (log copy; the right version runs). ~30m.
- **Fixture:** Free native Python web service `qa-20261114-r368-py` (`srv-dbs7pbvla3oc73cu7qt0`, created 2026-11-14T15:22:23Z), from `https://github.com/bex-co/bex` `examples/hello-python` with `runtime: python`, build `pip install -r requirements.txt` and start `python main.py`. The repo has no `.python-version`, no `runtime.txt`, no `PYTHON_VERSION`, and an unpinned `requirements.txt` (`flask==3.1.3`). Deleted afterwards (`DELETE` 204, then `GET` 404).
- **Probe:**
  - `GET /v1/logs?resource=srv-dbs7pbvla3oc73cu7qt0&type=build` for deploy `dep-dbs7pbvla3oc73cu7qtg`:

    ```
    15:23:27 ==> Building from https://github.com/bex-co/bex@dad9d0e
    15:23:32 ==> Using Python 3.14 (default)
    15:23:32 ==> Using Poetry 2.1.3 (default)
    15:23:32 ==> Using Node 24 (default)
    …
    15:26:39 ==> Your service is live 🎉
    ```

  - `curl -sD - https://qa-20261114-r368-py.onbex.co/` → `200`, `x-render-origin-server: Werkzeug/3.1.9 Python/3.14.10`. So w4/620's runtime fix holds; only the log line is short.
  - Round 246 (w4/620 § Probe), before the fix: `Using Python 3.14.8 (default)` and `server: … Python/3.14.8`. In that build the default (3.14.8) differed from the line's patch, so the swap ran.
- **Root cause:**
  - `NativeChoice.Narration` (`lego/operator/internal/build/nativeversion.go:87-107`) prints `version := c.Line` (`:95`). It uses something else only for Rust's `narratedVersion` (w8/327) or an Erlang OTP suffix.
  - `defaultExact` (`:219-235`) returns `""` when the dated default equals the line's reviewed `version` (`:232-234`). For a service created since 2026-11-03 that is `3.14.10`, the `3.14` line's `version` (`native.go:126`). So no `Exact` is set, nothing swaps, and the narration has only the line.
  - The one caller is `cmd/native-resolve/main.go:73`, which writes each choice's `Narration()` into the build log.
- **Fix (target behavior):** the narration names the exact version the build runs.
  - With an exact request or a dated default that swaps the image, that is `Exact`.
  - Otherwise it is the chosen line's reviewed `version` (`3.14` → `3.14.10`, `24` → `24.22.1`).
  - The source stays as today: `(default)`, `(from .python-version)`, and so on.
  - Rust keeps its rustup toolchain (`narratedVersion`), and Elixir keeps its OTP suffix.
- **Blast radius:** `Narration()` has one caller (`cmd/native-resolve/main.go:73`), but every native runtime's line passes through it. The registry (`native.go:94-143`) holds Elixir, Go, Node, Python, Ruby and Rust lines, and each can narrate the line today.
  - The assertions to update are in `lego/operator/internal/build/nativeversion_test.go` and `nativeexact_test.go`: 5 lines match `Using Python 3|Using Node 2|Using Ruby 3|Using Go 1`.
  - Add a test that a default equal to the line's patch narrates that patch, and keep w8/327's Rust narration test.
- **Unverified:** Render's exact wording. From its build logs it reads `==> Using Python version 3.14.10 (default)`, but no capture was made in this run. The other runtimes' lines were not built in this run; only Node's line appeared in this log, as a secondary toolchain.
- **Render:** the build log names the exact interpreter version and its source ([Python version](https://render.com/docs/python-version) lists exact defaults by creation date).
- **Dedupe:** `grep -rlE "Using Python 3\.14 \(default\)|Using Node 24 \(default\)|narrat(ed|es|ion).{0,60}(patch|exact)" .pm/w4 .pm/w8 .pm/w5` → none. w4/620 (done) fixed the runtime version, not the narration. w8/327 (done) fixed only Rust's narration.
