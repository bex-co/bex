# Restored environment drafts reuse row IDs and overwrite or delete another unsaved row

Why: recovery of unsaved work must leave each variable and file independently editable; the current restore path makes a later edit destroy the very draft it recovered.

**Severity:** major — loss of unsaved input, with duplicate-name validation blocking Save. **Estimate:** 60m, one shared editor identity fix plus its two caller regression checks. **Source:** continuous `$qa-find-bugs`, pass 4, 2026-09-21 America/Los_Angeles / 2026-09-22 UTC, filed in w4 at the user's request. ## Root and consumer contract

- `dashboard/src/features/services/components/service-environment-editor.tsx:274` initializes `nextID = useRef(0)` on each mount. The restore effect at `330–336` reinstates stored row IDs unchanged, without advancing or reconciling the counter.
- Four allocation sites reuse that counter: added/generated variables at `395`, imported variables at `437`, added files at `458`, and uploaded files at `498`. Restoring an earlier row from one path and creating another through that same path can allocate the same ID. Generated-variable insertion shares `addVariable`; it is not a fifth allocator.
- `updateRow` at `363–386` updates or removes **every** row whose ID matches. That directly explains both overwritten values and the two-row deletion; React reconciliation is not required to cause that data loss. JSX also uses these IDs as keys at `747,842`, validation uses them as error-map keys, and the file-content dialog selects its row by ID at `589`.
- The actual pinned React DOM **19.2.3** implementation was read: `dashboard/yarn.lock:10345–10347`; installed `react-dom/cjs/react-dom-client.development.js:8626–8630` creates a new `{current: initialValue}` at mount, while `26500–26504` returns the mounted ref on update. Its duplicate-key warning at `6605` also establishes that duplicate render keys are unsupported. The observed overwrite is nevertheless the application's explicit multi-match update, not an inferred library behavior.
- `common/hooks/use-reauth-draft.ts:70–100` consumes any nonexpired stored draft on mount, with a one-hour TTL; it does not require an expired-session marker. Ordinary reload therefore exercises the real restoration path. `service-environment-editor.tsx:338–344` mirrors dirty drafts back to storage. No session revocation or authentication manipulation was needed for the reproduction.
- `features/services/lib/environment-draft.ts:34–65` types IDs as local strings. `isNewDraftRow` at `68–70` uses `originalKey`/`originalName`, not ID prefixes. `environmentDraftPatch` at `313–335` serializes domain fields and explicit operations, never row IDs. Correcting local identities can preserve the existing REST/GraphQL/MCP payloads and opaque-value behavior.

## Exact scope and fix

There are **two production `EnvironmentEditor` callers**: `ServiceEnvironmentEditor` in the same component file at `122`, and `EnvGroupEditors` at `features/env-groups/components/env-group-editors.tsx:30`. Each wrapper has one production route mount: `routes/services.$serviceId.env.tsx:47` and `routes/env-groups_.$groupId.tsx:209`. The static environment route reuses `ServiceEnvPage`. Thus the service editor covers web, private, worker, cron, and static services; Postgres and Key Value use separate surfaces. `/web/*`, `/pserv/*`, `/worker/*`, and `/cron/*` aliases preserve the suffix and redirect through `common/lib/render-alias.ts`; static services canonicalize to `/static/<id>/env`. Environment groups use `/env-groups/<id>`. Only the private-service route was live-probed for this defect.

Make restored and subsequently added rows use unique, stable **local** identities. A concrete scoped approach is a single component-local allocator used by all four creation sites: when consuming a restored draft, assign each restored row a fresh identity through that allocator before adopting the draft, leaving the counter past those identities. Keep the allocated IDs stable for subsequent edits. Do not regenerate IDs on every render, change keys to array indices or mutable names, or merely change React's `key` while leaving `updateRow` with colliding IDs.

Preserve all non-ID fields during restoration, including `originalKey`, `originalName`, values/content, changed/deleted flags, generation intent, and manifest-read-only ownership. The existing `current ?? saved` behavior must still avoid replacing an already-active draft. For an already-corrupted stored draft, giving rows distinct identities must preserve its remaining values and let ordinary duplicate-name validation guide correction; it cannot reconstruct text that was already overwritten. Do not discard the whole draft as a workaround.

The fix is global to this editor's two callers, not to unrelated inputs or backend identifiers. Preserve pre-settle loading/read-only gates, forbidden/unavailable/not-found handling, sensitive-read restrictions, failed-save draft retention, and the existing auth redirect. No extra server lookup, permission bypass, existence disclosure, token storage, or change to the one-hour persistence policy is needed.
