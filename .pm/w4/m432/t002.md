## Objective

A rollback of a prebuilt-image service selects the target deploy's original reference. A tag reference is resolved again by the operator, so the rollback runs whatever the tag names now and records that new digest on its own deploy; a digest reference runs exactly that image. Repo-built services are unchanged: their artifact is bex's own retained build.

## Context

- Render (render.com/docs/rollbacks § Registry-hosted Docker images, read 2026-11-16): "With a tag, Render pulls the latest image under that tag, which may differ from the original. A digest always refers to the same image. If the image is no longer available or reachable, the rollback fails."
- Restart is out of this rule: Render's Restart keeps the running instance's image.

## Steps

1. Select `target.Image` for a prebuilt-image rollback target, keeping `ResolvedImage` for repo-built targets and for restart.
2. Make sure the new rollback deploy records its own `ResolvedImage`/`ImageSHA` once the operator resolves it, so a later rollback to the rollback is exact.
3. Keep the registry credential the service selects (w4/m301) on the re-pull.
4. Envtest: deploy tag `:v1` (digest A), push B under `:v1`, deploy `:v2`, roll back to the first deploy → runs B. Digest-pinned target → runs A.
