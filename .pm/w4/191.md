# w4/191 — Key Value `default` user has `+@all`: tenants can `CONFIG SET` the plan cap and eviction policy, rotate the password, and `SHUTDOWN`

Why: the dashboard and API present maxmemory policy, the plan's memory budget and the connection password as platform-managed. Today a tenant connection silently overrides all three until the next restart, so what the control plane shows stops being true, and the metrics sidecar breaks along with it.

Live 2026-10-04 UTC (`/qa-find-bugs` loop10, muse.env, `bex-canary`). Owned Free public Key Value `qa-20261004-l10-kv` (`red-db1fcbpj8bls738hh28g`, deleted to 404). Connected over external TLS with the dashboard's `cliCommand` shape (`redis-cli --sni <host> -u rediss://default:…@<host>:6379`):

- `ACL LIST` → `user default on sanitize-payload #… ~* &* +@all`.
- `CONFIG SET maxmemory-policy volatile-lru` → `OK`, and `CONFIG GET` then reads `volatile-lru` while the dashboard and REST still show `allkeys-lru`.
- `CONFIG SET maxmemory 0` → `OK`. This lifts the 80%-of-plan budget the operator sets (`valkeyMaxmemory`); the pod then relies on the kernel OOM kill instead of eviction.
- `SHUTDOWN NOSAVE` → the server exits and Kubernetes restarts it (`uptime_in_seconds:12` a minute later). Writes since the last fsync are lost.
- Refused (good): `CONFIG SET dir /tmp` → "can't set protected config" (`enable-protected-configs no`), and `DEBUG` → not allowed.
- After the restart, `maxmemory` was back to `107374182`, so every override is transient. It is self-scoped (one tenant's own instance), not cross-tenant.

Root cause:

- `lego/operator/internal/controller/keyvalue_controller.go:214-233` `valkeyArgs` starts Valkey with only `--requirepass $(VALKEY_PASSWORD)` (and `keyvalue_persistence.go:179` writes `requirepass`). The implicit `default` user therefore keeps every command category.
- The redis_exporter sidecar authenticates with the same password (`keyvalue_controller.go:183-199`). So a tenant `CONFIG SET requirepass …` or `ACL SETUSER default >…` also blanks the Metrics tab, and the dashboard's revealed connection string stops working until the pod restarts. This is reasoned from the code, not probed.

Fix: define `default` explicitly instead of `requirepass`, keeping data commands and read-only introspection while dropping the control-plane-owned verbs, e.g. `user default on >$(VALKEY_PASSWORD) ~* &* +@all -config|set -config|rewrite -config|resetstat -acl|setuser -acl|deluser -acl|save -acl|load -shutdown -module -replicaof -slaveof -failover -debug`.

- Keep `CONFIG GET`, `INFO` and `CLIENT` (the exporter and tenants need them). Mirror the rule in the persistence-transition config path (`keyvalue_persistence.go`).
- Envtest/arg test: the rendered args contain the user rule and no bare `requirepass`.
- Live replay: the five probes above return `NOPERM` except `CONFIG GET`, and PING/SET/GET/FLUSHALL still work. Metrics keep scraping.

Unverified: whether Render disables these commands on Key Value (check its "unsupported commands" list before choosing the exact set; record any deliberate divergence in ADR021). Severity: minor. Estimate: ~45m.
