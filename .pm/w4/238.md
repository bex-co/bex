# Top queries loses timing columns on a narrow database page

Why: a database owner using a phone cannot read query timings: the query cell keeps 320px while the timing columns collapse into character-wide strips outside the visible card.

- **Severity:** minor; real data remains in the API.
- **Estimate:** 55m: shared table/caller audit 10m, local layout fix 20m, browser geometry regression and passing controls 15m, Simplify/live close 10m.
- **Source:** continuous functional `$qa-find-bugs w4`, pass a54, 2026-10-10 UTC, muse.env through the login helper.
- **Goal:** readable managed Postgres observability under [ADR008](../../../docs/ADR008-vision.md) and [ADR009](../../../docs/ADR009-postgresql-management.md), completing the calls/timing visibility guarantee in [w4/m115](done/m115/README.md).

## Root cause, library path and fix scope

- `dashboard/src/features/databases/components/insights-panel.tsx:197–235` renders a bare `<table className="w-full text-xs">`. Its Query cell at **217** has `max-w-xs truncate`, while the remaining headers/cells have no nowrap or minimum table width. `Section` at **388–408** adds spacing only, with no scroll region.
- Root shell `dashboard/src/common/root-route/shell-component.tsx:37` sets inherited `overflow-wrap:anywhere`. Actual pinned **Tailwind 4.1.18**, `node_modules/tailwindcss/dist/chunk-CT46QCH7.mjs`, defines truncate as overflow hidden + text-overflow ellipsis + **white-space nowrap**. The query column keeps its 320px constraint while other columns can break at every character. The recorded 320/20.7/22.7/10.7 split matches that mechanism.
- **Passing consumer opened:** the existing shared `common/components/ui/table.tsx:5–16` puts tables in a local `relative w-full overflow-x-auto` container. SQLConsole uses it at **175–207**, and its 120-row pagination passed. The Insights Non-default parameters table also has an explicit local scroll wrapper at **348–385**. No global root-shell or shared-Table change is needed.
- The GraphQL response retains the timing numbers. `hooks/use-database-insights.ts:54–60,126–130` consumes the query data; the table's `toFixed(1)` / `toFixed(2)` at **227–230** is correct on desktop. This is a CSS layout defect, not a conversion/serializer bug. No API or SQL changes.

**Shared-code audit (10m):** exhaustive source search found **one** InsightsPanel definition and **one** production mount, `routes/databases.$databaseId.tsx:319`. That component contains **five native tables**: Storage (86), Active processes (137), Top queries (197), Table scans (257), Non-default parameters (349). Only the last has an overflow wrapper today. Fix is **allowlisted to Top queries**; audit the four siblings and retain the currently passing short-data Storage/Active/Table-scan geometry and wrapped parameter behavior. Large/long sibling datasets are unverified, not automatically included findings. The separate ParameterOverridesEditor is not one of these five read tables.

Postgres detail and its `/d/<id>` alias share the page; no duplicated alias implementation. Web/static/cron/worker/private/key-value use other surfaces. Mobile's native app has separate components and does not consume this dashboard table. Alias navigation, native app, Chinese and masked/empty/error rows were not live exercised. Tests must retain the existing empty/error/masked treatment; those remain source boundaries.

**Work:** use the existing table scroll pattern locally, set a width suitable for four readable columns (verify 640px rather than blindly choosing it), and keep numeric headers/cells nowrap. Audit before sharing any new helper; do not strip the root shell's wrapping rule across unrelated pages. Verify pending and ready geometry at desktop and mobile; no new generic skeleton. Add a real browser layout assertion: page width stays at viewport width; the local table region can pan to the complete Mean time cell; numeric text remains on one line. jsdom class/snapshot assertions alone cannot detect this measured failure. Run relevant panel tests and typecheck, Simplify, then repeat the same owned-database journey and cleanup.
