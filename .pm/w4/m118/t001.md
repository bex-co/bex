## Objective

Make `cron_job_run_started` / `cron_job_run_ended` fact rows (recorded by `recordCronRunFacts` for every scheduled and manual run) visible in `GET /services/{id}/events` and the GraphQL/MCP equivalents, while keeping the existing audit-verb rows for manual Trigger Run / Cancel.

## Context

- `lego/backend/internal/events/service.go:162-163` — the two type constants already exist.
- `lego/backend/internal/events/service.go:294-296` — `eventTypes` maps `apps.TriggerCronRun` / `apps.CancelCronRun` / `appsCancelCurrentCronRun` audit verbs to these types, so manual actions show today.
- `lego/backend/internal/events/service.go:351-369` — `allFactTypes` lists `TypeJobRunEnded` but neither cron type: unfiltered queries exclude the fact rows.
- `lego/backend/internal/events/service.go:397-410` — `pushDown` has no fact case for the cron types, so a filtered query falls through to the verb loop and returns audit verbs only.
- `lego/backend/internal/store/reconciler.go:439-487` — the writer: started facts need `StartedAt`, ended facts need `FinishedAt` + terminal status; source keys are stable and idempotent.
- `lego/backend/internal/webhooks/service.go:211-212` — webhooks already consume both fact types; the feed is the only surface missing them.
- Dashboard already renders both types (`dashboard/src/features/events/lib/timeline.ts:8-9`, `service-event-catalog.ts:35-36`) — no dashboard change expected.

## Steps

1. Add `TypeCronJobRunStarted` and `TypeCronJobRunEnded` to `allFactTypes`.
2. Give `pushDown` an explicit case for both types that returns the matching audit verbs (trigger for started; both cancels for ended) **and** the fact type, so one type queries both sources. The current fallthrough returns verbs-only; the fact-only `case` at 397-403 returns facts-only — neither shape fits, so this needs a union case.
3. Check the store query joins facts correctly for the new types (same path `job_run_ended` already uses) and that `Details.Status` carries succeeded|failed|canceled on the ended rows.
4. Run the events package tests plus the backend suite; fix count/vocabulary assertions that enumerate feed types.
