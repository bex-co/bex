## Root cause and concrete target

1. `dashboard/src/routes/project.$projectId.index.tsx:93–108` destructures lists/loading/refetch from useServices/useDatabases/useKeyValues and drops all three `error` values. Its `showError` at150 concerns only the parent Project loader. At184–199 it passes lists and a combined loading flag to EnvironmentsPanel, with no resource error state.
2. The three hooks already expose `error` and `refetch` (`features/services/hooks/use-services.ts:45–70`, `features/databases/hooks/use-databases.ts:33–55`, `features/keyvalue/hooks/use-key-values.ts:36–58`). They use errorPolicy all. Their status mappers turn missing nodes into [] (`services/lib/status.ts:203`, `databases/lib/status.ts:51`, `keyvalue/lib/status.ts:56`). Those arrays alone cannot distinguish an empty success from an unread list.
3. `features/environments/components/environments-panel.tsx:103–104,228–255` handles errors of the Environments query itself, but has no resource-catalog errors. It also drops useEnvGroups loading/error/refetch. `resourcesLoading` only gates URL canonicalization at137; it does not gate the selected card's row/count readiness. This pending gap is source-traced verification work, not a second confirmed settled-error failure.
4. `environment-card.tsx:145–175` joins member IDs against those lists and filters unresolved objects out. Counts at188 and the empty branch at341 use the resulting rows. Thus successful membership containing both IDs becomes zero rows when catalogs are unavailable. Unassigned goes through `use-grouped-resources.ts:103–148`, then the same row-derived counts/empty choice at `environments-panel.tsx:283–335`; its failure variant was not live-probed.
5. Framework path was opened at actual Apollo4.3.3 (native request extension, lockfile and cached package version agree): `link/batch/batching.js:120–130` delivers per-slot results; `core/QueryInfo.js:42–95,373–380` keeps error-only incoming data empty and skips a cache write without usable data; `core/QueryManager.js:638–675` publishes loading false and CombinedGraphQLErrors for errorPolicy all. This is an available error signal discarded by the consumer, not a library treating the error as a successful empty list. Do not assume a warm-cache poll necessarily discards old data: that case is additional verification work.
6. Backend `lego/backend/internal/api/server.go:1555–1602` deliberately refuses later batch operations once the shared budget is spent and emits a structured error. `core/errors.go:379–393` distinguishes QUERY_TIMEOUT, WRITE_OUTCOME_UNKNOWN and OPERATION_NOT_STARTED. The read-only native failure is compatible with that design. No deadline increase, mutation retry or repair of the unrelated existing EnvGroup is proposed.

**Fix target:** carry each required resource family's availability/error/retry into this Project consumer. Before first usable data, render a card-shaped pending or localized unavailable state. After a failed refresh with usable prior data, keep mounted content and drafts, label it as not refreshed and provide a busy-aware read-only Retry. With a mixture of healthy and failed families, retain authorized healthy rows and identify unavailable families; totals must not assert a complete zero. A successful empty result retains the existing zero/empty view. Preserve selected environment, search/type draft and selected IDs while reads recover. Do not rewrite membership because a catalog is missing.

Use existing hook refetches with bounded, explicit read recovery; the dashboard default suppresses loading notifications during refetch, so Retry needs a reliable busy state. Avoid automatic loops or new independent polling owners. Keep existing cards/dialogs mounted across background failures. Block membership submissions that would depend on unresolved catalogs until a valid read settles; t002 must check the actual full-replace editor semantics rather than assume it currently loses membership.

## Error classes and pre-settle behavior

- Pending/unknown workspace or required catalog: neutral pending state; no invented zero or scope canonicalization from unavailable data. Preserve the ready state's geometry at desktop/mobile widths.
- QUERY_TIMEOUT, OPERATION_NOT_STARTED, transport failure or throttling: read unavailable/partial with read-only recovery; do not turn them into missing membership or replay any write.
- A returned authorized empty list: ordinary truthful zero. A successfully missing Project: existing parent not-found redirect. A missing catalog object without an error: reconcile only from settled authoritative reads; never infer that a resource was deleted from an error-shaped absence.
- Unauthenticated/forbidden: existing auth/refusal handling, without displaying unauthorized cached data or expanding discovery. Keep Project loader and route behavior unchanged. No auth or security changes are part of this finding.
- Failed refresh with last-good authorized data: inline explanation and recoverable stale view, preserving mounted draft/dialog/filter state. Partial-family errors must not let a partial count masquerade as the complete environment total.
