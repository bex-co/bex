# A rollback (or any image deploy) to an unreachable registry waits until the registry answers; Render fails it

Why: Render's rollbacks page says "If the image is no longer available or reachable, the rollback fails." bex fails a refused read at once (404/401/403, w32/m419) but waits on a transient one (network error, 5xx, 429) with no deadline (w32/031). A rollback, like any image deploy, can therefore stay open for hours while Docker Hub throttles or a self-hosted registry is down.

- **Found by:** w4/m432 t003/t006, 2026-11-16, in the envtest "waits on an unreachable registry with the live release serving" (`lego/operator/internal/controller/rollback_image_reference_envtest_test.go`).
- **Where:** `imageRegistryWait` / `holdRegistryWait` (`lego/operator/internal/controller/image_network.go`, `app_controller.go`). The wait backs off from 30 s to 5 min and repeats.
- **Open question for the fix:** Render documents no timeout. Pick a bounded wait, for example the deploy's own rollout budget, after which the release fails with an image-reason verdict over the serving release. Check what Render shows for a registry that times out before choosing.
- **Done when:** an envtest App whose rollback's registry read keeps failing transiently past the chosen bound ends with a Rollout verdict naming the registry, while the previous release keeps serving. The w32/031 behavior inside the bound is unchanged.
