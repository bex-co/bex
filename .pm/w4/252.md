# Sleeping Free web services promise wake on the next request beside an internal address

Why: a sibling service using Connect → Internal needs to know that its request cannot wake a sleeping Free web service and must use the public URL first.

**Severity:** minor (misleading functional guidance). **Estimate:** 55m. Source: continuous functional `$qa-find-bugs`, 2026-10-11, pass a163, production dashboard, workspace `tea-d98210cbbpdc73dcrkvg`. Governing behavior: ADR003:80 explicitly says **next public request**. Internal-only wake is not requested by this filing.

## Reproduction and target behavior

1. Create an owned Free image web service, BusyBox 1.37, port 3000, using the command below. Wait for its deploy to be Live. The fixture was `qa-20261011-a163-idle` / `srv-db5jmq54e4ts73f8i0t0`.
2. Copy Connect → Internal (`qa-20261011-a163-idle:3000`). Create an owned Free BusyBox cron job with the caller command below, schedule `0 0 1 1 *`, and wait for Live. Caller: `qa-20261011-a163-caller` / `srv-db5jna0mmd8c73drri30`.
3. Set the web service's existing bex idle-timeout extension to 60 seconds with the captured mutation. Wait until GraphQL phase is Hibernated and suspended is not_suspended. Do not request its public URL during the sleeping internal-call legs.
4. Fresh-load the web Settings page at 1440×1000, then 390×844. The header says “Sleeping to save resources — wakes on the next request.” Idle timeout says “Free services sleep after this long without inbound requests or WebSocket messages, then wake on the next request.” Open Connect: Internal exposes the copyable address with no sleep limitation or public-wake guidance.
5. On the caller's Events page, Trigger Run and confirm. It fails with Connection refused; the web service stays Hibernated. Fresh-load Settings/Connect again, then repeat the caller run: same failure and no wake.
6. GET the web service's public URL. Two probes returned 503 with Retry-After: 5 and the complete body `{"error":"service not ready","retryAfter":5}`; the third returned 200 and `qa-a163-ready`. GraphQL was Running after the public request. Trigger the unchanged internal caller again: it succeeds and prints the marker plus qa-a163-call-ok.

Expected: the header/status tooltip and idle-timeout hint qualify the wake promise as a **public request**. Idle guidance must describe public HTTP/WebSocket activity, without implying internal requests keep it awake. Connect → Internal should explain for an eligible Free web service that **internal requests cannot wake it when asleep**, and direct the user to its public URL first. Keep the correct internal address copyable. A concise explanation may remain visible while awake because the limitation will recur when it sleeps; do not imply an always-on guarantee.

Actual: the dashboard offers the internal address next to an unqualified request-wakes-service promise. Both internal failures are documented data-plane behavior; the defect is the dashboard guidance.

Web command:

```sh
sh -c 'mkdir -p /tmp/qa-a163; printf qa-a163-ready > /tmp/qa-a163/index.html; exec httpd -f -p "$PORT" -h /tmp/qa-a163'
```

Caller command:

```sh
sh -c 'set -eu; echo qa-a163-call-start; value="$(wget -T 10 -q -O - "http://qa-20261011-a163-idle:3000/")"; test "$value" = qa-a163-ready; echo "$value"; echo qa-a163-call-ok'
```

Use these existing predicates for Connect guidance; do not create a new backend state or infer sleep from the latest deploy.
- ADR003:80 explicitly limits wake/activity observation to the public path; ADR041 D4 defines the correct additive internal address. Preserve those contracts. No REST/GraphQL/MCP response or operator behavior needs changing.

**Blast radius:** exhaustive symbol searches found two direct statusSleepingHint consumers (detail header and ServiceStatusBadge), one settingsIdleTimeoutHint consumer (IdleTimeoutRow), one ServiceConnectButton invocation, and three ServiceStatusBadge JSX call sites (detail header:124, projects/resource-table.tsx:315, environments/manage-resources-dialog.tsx:165). Qualify the shared status hint globally; add Connect guidance only for eligible Free/untiered public web services. The resource family is web, static, cron, worker, private, Postgres, Key Value: static has no Connect button, private has its internal address but no public wake path, worker/cron have no serving internal address, and datastores use separate connection components. Regression checks should preserve private/paid-web wording and explicit-suspend remedies. Those sibling states are source-traced or prior passing controls, not new live claims in this pass.

**Adjacent classes:** sleeping means a Free public request can wake it; explicit suspension requires Resume and must not get automatic-wake copy. Paid/private/worker services must not inherit Free auto-sleep wording. Request failure and permission/error handling stay as they are.

**Unverified:** Chinese live rendering, paid/private services, WebSocket activity, bare-CR untiered services, internal-only steady-traffic sleep timing, raw App conditions and request counters. Carry these as regression work, not observed guarantees.

## Fix and acceptance (55m total)

1. **15m — Qualify both existing en/zh hints:** specify public inbound HTTP/WebSocket activity and wake on a public request. Preserve the default/custom-window and paid-plan text.
2. **20m — Explain the Internal limitation:** with the existing eligibility helper, show concise translated guidance next to the internal address for a Free public web service and a usable public URL. Keep Copy working and preserve paid/private Connect behavior. Use current service data before a query/poll settles; do not show a public-wake remedy for an explicitly suspended service.
3. **20m — Shared-consumer regression and live acceptance:** verify the two hint consumers, the three badge call sites, and the Settings consumer; exercise desktop/mobile Connect and retain truthful explicit-suspend/paid/private states. Use the documented sleeping internal-call failure → public wake → internal success journey above to verify the guidance, not to demand a new internal wake mechanism.

Acceptance: a fresh desktop/mobile sleeping Free web Settings page says **public request** in its header and idle hint; Connect explains the internal wake limitation and supplies the public remedy. The same internal address continues to work while awake. Explicit suspension says Resume; paid/private services retain their current behavior. No new internal-wake backend/operator verb is introduced.
