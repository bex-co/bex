# Service create silently drops cron-only `command`/`schedule` on non-cron types

Why: a GraphQL or REST caller that sends `command` for a web service, intending the Docker Command, gets a success response and a service that never runs that command. The busybox default `sh` exits, and the deploy stalls on a crash loop with no hint that the field was ignored.

Severity: minor (no dashboard path sends it; API and agent callers are misled). Source: live `/qa-find-bugs w4` loop run e9ba, 2026-10-27 UTC (`muse.env`, production).

## Evidence

- GraphQL `createService(name:"qa-20261027-e9ba-env", type:"web_service", image:"docker.io/library/busybox:latest", runtime:"image", port:10000, command:"sh -c '… exec httpd -f -p 10000 -h /w'", …)` → `200` with an id. A read back gives `server{command:"" startCommand:""}`. The deploy stalled with "container exited shortly after start and is restarting repeatedly (last exit code 0)". Setting the same text as Settings → Docker Command (`startCommand`) made it serve. The fixture was deleted.

## Cause

- `lego/backend/internal/apps/service.go:3351-3354` `applyOptionalCreateSpec` copies `Schedule`/`Command` only for `cron_job`, and drops them for every other type.
- `validateTypeSpecificCreate` (`service.go:3161-3176`) refuses inapplicable `healthCheckPath`, `preDeployCommand`, `startCommand`, IP allowlists and so on by type. It has no rule for `command` or `schedule` on a non-cron type.
- The same `CreateRequest` is reached from GraphQL (`graphql.go:1410` documents `command` as cron-only), REST (`rest.go:190`, the flat extension field) and the Blueprint path.

## Fix

- Refuse a non-empty `command` or `schedule` on a non-cron type with a named 400 (`field: command` / `schedule`), worded like the sibling `…NotApplicable` errors. Point `command` callers at `startCommand` (the Docker Command) for image and Docker services.
- Check the Render REST mapping: Render's image cron carries its command as `startCommand`, which bex bridges (`mcp.go:355-358`). Confirm REST's own `command` extension gets the same rule, so a Render-shaped web create is not newly refused.
- Tests: GraphQL and REST create with `command`/`schedule` on `web_service`, `private_service` and `background_worker` → 400. `cron_job` is unchanged.

Unverified: REST and MCP were read from code, not probed live.
