## Objective

A request under `/assets/` that names no file in the build answers `404`, with `Cache-Control: no-store` and a short non-HTML body, before the SSR renderer runs. Only a response that actually serves a build file carries `public, max-age=31536000, immutable`. Neither Cloudflare nor a browser can then keep a miss.

## Context

- `buildRouteRules` (`dashboard/server/security-headers.ts:72-97`) puts the immutable header on every `/assets/**` response.
- The Nitro Vite plugin serves the client build from one fallthrough directory at `/` (`dashboard/node_modules/nitro/dist/vite.mjs:711-716`), so a miss reaches the renderer and answers `200` HTML.
- Nitro answers 404 only for a non-root, non-fallthrough public-asset base (`dist/_chunks/nitro.mjs:118-124`, `dist/_build/common.mjs:22176`).
- Production probe (round 193): `/assets/qa-r193-missing-chunk-Xy12Ab.js` → `200 text/html`, `public, max-age=31536000, immutable`, `cf=MISS` then `HIT`.

## Steps

1. Choose the mechanism.
   - Either a Nitro server middleware (`dashboard/server/plugins/` or a `routes/assets/[...]` handler) that answers a `/assets/**` path with no file in the build output as `404` plus `no-store`.
   - Or register `/assets` as a non-fallthrough public-asset base with `maxAge` (Nitro then sets immutable on hits and 404s misses), and check that the route rule's headers do not land on the 404.
   - Read the pinned nitro-nightly's static handler before choosing.
2. Drop or narrow the unconditional `/assets/**` immutable rule, so that the header comes only with a served file.
3. Keep every other header the route rules set: the security headers on all responses, pages `private, no-cache`, the association documents `public, max-age=300`.

## Files

- `dashboard/server/security-headers.ts`, `dashboard/vite.config.ts`, and a server middleware if needed
- `dashboard/server/__tests__/security-headers.test.ts`

## Acceptance criteria

- [ ] Against a production build (`yarn build`, then the built server):
  - a missing `.js`, `.css` and nested asset answer `404`, `no-store`, not `text/html`;
  - a real chunk answers `200`, its JS content type and the immutable header;
  - a page answers `private, no-cache`;
  - both association documents keep `public, max-age=300`.
- [ ] The security headers are on all of the above.
