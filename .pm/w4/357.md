# The Docker Command editor's toasts say "Start Command"

Why: a Dockerfile or Existing Image service labels the field **Docker Command** everywhere: the label, the hint, the edit button and the confirm title. Saving it then toasts "Start Command updated.", which names a field the page never showed, and the error toast does the same.

- **Severity:** minor (copy).
- **Source:** live functional `/qa-find-bugs w4`, pass 2fe734, 2026-10-19 UTC, `muse.env`, workspace `bex-canary`, production pinned to `94a76a923136`. Owned Free image web service `qa-20261019-2fe734-zd` (since deleted).
- **Repro:** Settings → Deploy → **Edit Docker Command** → change it → Save changes. The dialog reads "Change the Docker Command to …? The service redeploys with the new command." Confirm, and the toast is `success` **"Start Command updated."** (04:55:46Z).
- **Root cause:**
  - `dashboard/src/features/services/components/deploy-card.tsx:23-47` `COMMAND_COPY` picks label, hint, placeholder, edit and confirmTitle per `DeployCommandKind` (`start` | `docker` | `image`).
  - The save goes through `useStartCommand` (`hooks/use-start-command.ts:10-20`), whose `useFieldMutation` messages are fixed to `services.startCommandSuccess` ("Start Command updated.") and `services.startCommandError` ("Couldn't update the Start Command. Please try again."), in both `en.ts:2210-2217` and `zh.ts:2160-2166` (启动命令已更新。).
- **Fix (target behavior):** the toasts name the field the card shows.
  - Add `success`/`error` to each `COMMAND_COPY` entry: the `docker` and `image` kinds get new `services.dockerCommandSuccess`/`dockerCommandError` keys (en + zh), and the `start` kind keeps the existing keys.
  - Let `useStartCommand` take those keys from its caller, defaulting to today's.
- **Blast radius:** `useStartCommand` has 1 caller (`deploy-card.tsx:88`). `use-build-settings.test.ts:43` asserts the current Start Command toast and stays valid for the `start` kind.
- **Acceptance:** a deploy-card test saves each kind and asserts its toast (Start for native, Docker for Dockerfile and image), plus the matching error toast. Live, an image service's save toasts "Docker Command updated."
- **Render:** Render's dashboard labels this field Docker Command for image and Docker services. The toast wording was not compared.
- **Estimate:** 15m.
