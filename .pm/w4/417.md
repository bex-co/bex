# 417 — A service create refuses an over-long or empty name with the slug rule ("lowercase … at most 30 characters"), and accepts a blank one

Why: since w5/m153 a service name is free-form (up to 100 code points), but a name that breaks the free-form rule is answered with the old resource-name rule, which tells the user something false, and a whitespace-only name creates a service with no display name.

**Severity:** minor (misleading error copy on REST, GraphQL and MCP create; one blank-label case). **Estimate:** ~45m. **Source:** live `/qa-find-bugs w4` loop run 94e0, 2026-10-26 UTC (`muse.env`, `bex-canary`, pin `b4726243e74f`), REST through the run's session jar. All probes used `?dryRun=true`; nothing was created (a follow-up list by name returned `[]`).

## Probes

`POST https://api.bex.co/v1/services?dryRun=true` with `{"type":"web_service","name":<N>,"ownerId":"tea-daif693dqjvc73e7as3g","image":{…"imagePath":"docker.io/traefik/whoami:v1.10.3"},"serviceDetails":{"plan":"free","runtime":"image"}}`:

| `name` | Answer |
| --- | --- |
| `"café ☕ api"`, `"AAAA…"` (31), `"My Api …"` (98), `"x x …"` (100) | `200`, slugified (`cafe-api`, `aaaa…-55ee74`, …) — the free-form rule holds |
| `"x x …"` (102), `"é"×101` | `400 RESOURCE_NAME_INVALID` "name must use lowercase letters, digits, and hyphens, be at most 30 characters, and not start or end with a hyphen" |
| `""` | the same slug-rule `400` |
| `" "` | `200`, slug `resource-36a9e7`, display name blank |

The expected answer for 101+ is the label rule's own error, `400 DISPLAY_NAME_TOO_LONG` "display name must be at most 100 Unicode code points" (`core/errors.go:375-378`). For `""` and `" "` it is a required-name refusal, as `core.CheckDatastoreName` (`errors.go:386-393`) already gives Postgres and Key Value: "name must be a non-empty label without leading or trailing spaces".

## Root cause

- `lego/backend/internal/apps/blueprint_names.go:106-114` `blueprintDisplayName` **swallows** `checkDisplayName`'s error and returns `""`.
- `Create` (`apps/service.go:2021-2024`) reads `""` as "this is already a resource name" and passes the raw name on, so `specFromCreate`'s `core.CheckResourceName` (`service.go:2964`) answers with `ResourceNameRule` (`core/errors.go:349`).
- `" "` is a valid label to `CheckLabel` (it trims to `""` without error), so it gets a generated slug, and `SetDisplayName` stores an empty display name.
- The second caller, Blueprint parsing (`apps/deploy.go:2208`), has the same swallow: an over-long Blueprint service name will also surface the slug rule (unverified live).

Related stale copy: the MCP rename tools still describe Postgres and Key Value names as "lowercase letters, digits, and hyphens; at most 30 characters" (`postgres/mcp.go:320`, `keyvalue/mcp.go:83`), though those names are free-form labels (`CheckDatastoreName`). An agent reading the schema will refuse valid names.

## Fix (target behavior)

- Service create (REST, GraphQL `createService`, MCP create tools, dashboard — one `Create`) returns the label rule's own coded error for a name that fails `CheckLabel`: `DISPLAY_NAME_TOO_LONG` / `DISPLAY_NAME_CONTROL_CHARACTER`, not `RESOURCE_NAME_INVALID` with the slug wording.
- An empty or whitespace-only name is refused with `400 RESOURCE_NAME_INVALID`, `params.field: "name"`, with the same wording as `CheckDatastoreName`.
- Blueprint service names get the same treatment through the shared helper.
- Fix the two MCP schema descriptions to say "free-form label, at most 100 characters".
