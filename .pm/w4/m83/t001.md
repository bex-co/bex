## Objective

Put a race-safe ceiling on each workspace's pending/retrying outbound-webhook rows without ever making the source service/deploy/resource mutation fail because its notification could not be queued.

## Context

`webhooks.Worker` composes durable events into `webhook_deliveries` and advances a watermark. Endpoint count is capped and terminal history is retained, but non-terminal rows can still grow without a workspace bound. The enqueue decision and watermark must remain one honest transaction: an overflowed event cannot be retried forever, and it cannot manufacture an unbounded second evidence queue.

## Steps

1. Trace `EnqueueWebhookDeliveries`/watermark transactionality and define the exact non-terminal states counted against the workspace ceiling.
2. Add `BEX_MAX_WEBHOOK_DELIVERIES_PER_WORKSPACE` with a documented safe default and `0` as the explicit disable value; wire it into the delivery worker.
3. Enforce the ceiling in Postgres under concurrent workers, not with a check-then-insert in Go.
4. On overflow, preserve the source mutation, advance the composed-feed watermark, and return a typed aggregate result that t003 can meter/log without creating one evidence row per dropped delivery.

## Acceptance criteria

- [ ] Concurrent enqueuers cannot exceed the configured workspace ceiling.
- [ ] A capped event does not fail or replay the originating mutation and does not stall the event watermark.
- [ ] `0` preserves the pre-milestone unbounded admission behavior intentionally; the default is documented.
- [ ] Overflow output is aggregate/bounded and contains no secret, payload, or destination URL.
