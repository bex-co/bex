## Objective

Prove the cap and fairness invariants under the concurrency and persistence conditions that motivated the milestone.

## Context

Pure unit tests cannot establish that concurrent Postgres claim/enqueue transactions stay within bounds or remain disjoint. The existing `BEX_TEST_DB_URI` suite is the load-bearing place for those assertions; worker unit tests should cover configuration and aggregate evidence around it.

## Steps

1. Add real-Postgres tests for boundary admission, concurrent enqueuers, noisy-plus-quiet ordering, and two claimers.
2. Add worker tests for disabled cap, aggregate overflow handling, metric increments, and unchanged retry/attempt semantics.
3. Add promtool alert tests and run the backend suite plus targeted race tests where Go concurrency is involved.
