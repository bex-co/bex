# 385 — A service name with no Latin letters or digits always becomes "resource", so a workspace can hold only one

Why: since w5/m153, create takes Render's free-form names, but any name with no `a–z`/`0–9` maps to the fixed resource name `resource`. So the first service named in Chinese, Japanese, Cyrillic, Arabic or emoji takes it, and every later one in that workspace is refused with `409 name "resource" is already in use`. The refusal names a value the user never typed. Accented Latin letters are dropped rather than kept (`Ünï` → `n`), so the URL reads wrong as well.

**Severity:** major (the create journey fails for every non-Latin name after the first; Render takes free-form names). **Estimate:** ~1h. **Source:** live `/qa-find-bugs w4` loop run n3m9, 2026-10-21 UTC, `muse.env`, workspace `bex-canary`, pin `a3f66521f93d`. Free image services (`docker.io/traefik/whoami`) were created by REST and all deleted in-run (by-id 404); the session was revoked. Evidence: `.playwright-mcp/qa-names-n3m9-preview.png` (local), the create form showing `Resource name: resource` for `中文名`.

## Probes (`POST /v1/services`, `type: web_service`, Free, same workspace)

| `name` | Result |
| --- | --- |
| `日本語のみ` | `201`, `slug: "resource"`, `url: https://resource.onbex.co`, `displayName: "日本語のみ"` |
| `中文名` | `409 name "resource" is already in use` |
| `🚀🚀` | `409 name "resource" is already in use` |
| `QA 20261021 Ünï Form!` | `201`, `slug: "qa-20261021-n-form"` (`Ü` and `ï` dropped) |
| the same name again | `409 name "qa-20261021-n-form" is already in use` (names the slug, not the typed name) |
| `qa-20261021-n3m9-` + 80×`x` | `201`, `slug: "qa-20261021-n3m9-xxxxxx-15e942"` (the long-name hash path works) |

The hostname is not at risk. `apps_slug_idx` (`store/migrations/0020_apps_slug.up.sql:28`) is global, and `CreateApp` (`store/store.go:983-1036`) suffixes a cross-workspace slug collision (`resource-xxxx`). The 409 is the per-workspace `(tenant_id, name)` constraint (`migrations/0001_core.up.sql:35`), which `apps/service.go:2420-2423` maps to `errServiceNameInUse`.

## Root cause

- `blueprintResourceSlug` (`lego/backend/internal/apps/blueprint_names.go:34-57`) keeps only `a–z0–9`, hyphenates everything else, and falls back to the constant `"resource"` when nothing is left (`:50-52`).
- A hash suffix is added only when the slug is too long (`:53-56`). So every name with no surviving characters maps to the same resource name, and partly-Latin names lose their accented letters.
- `Service.Create` applies it to every free-form create name (`apps/service.go:1984-1990`).
- The dashboard mirrors it exactly (`dashboard/src/common/lib/utils/resource-slug.ts`, "Keep the two in step") for the create form's "Resource name" preview.

## Fix (target behavior)

- **Empty fallback.** When the derived slug is empty, use a stable, name-specific resource name, for example `resource-<6-hex sha256 of the name>`, the same hash the long-name path uses.
  - Two different non-Latin names then get distinct resource names.
  - The same name maps to the same slug every time, so Blueprint matching stays stable.
- **Accented Latin.** Strip diacritics before filtering (Unicode NFKD, drop combining marks), so `Ünï` → `uni`. Alternatively, record the deliberate choice not to, in ADR020.
- **Conflict message.** When the typed name differs from its resource name, name both, for example `name "中文名" maps to resource name "resource-1a2b3c", which is already in use`.
- **Keep the mirror in step.** `resource-slug.ts` and its tests change with the Go function.
- **Blast radius.** `blueprintResourceSlug` has 5 call sites: `apps/deploy.go:2176`, `apps/service.go:1989`, `blueprint_names.go:64` (`blueprintDisplayName`), `:78` (`slugRefNames`) and `blueprint_ir.go:254`. A Blueprint service whose name maps to `resource` today would map to a different slug after the fix. The sync must keep matching that existing service and not plan a create plus an orphan. Either match on the recorded display name, or keep an existing `resource` match when exactly one exists. Add a test for that upgrade.

## Acceptance

- Unit tests (Go and TS):
  - `日本語のみ` and `中文名` map to distinct, stable names, and each is a valid resource name.
  - `Ünï` → `uni` (or the documented choice).
  - ASCII and long names are unchanged.
  - The Blueprint upgrade case keeps its existing service.
- Live: in one workspace, create `日本語のみ` and then `中文名` → both `201` with distinct `slug`/`url`. A true duplicate's `409` names the typed name.
- Backend `go test ./...`, dashboard `yarn test` and `make lint` pass.
