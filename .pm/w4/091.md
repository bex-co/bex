**This pass created no cron job** — only a project, an environment and an env group, all three confirmed deleted. Something else is operating in workspace `tea-d98210cbbpdc73dcrkvg` under the same `qa-<yyyymmdd>-` convention this skill mandates.

It was **not touched**: it is not this harness's resource, and it was `Building` at the time. Consequences for whoever runs the next pass:

- **`qa-` prefix matching is no longer sufficient to identify your own resources.** Track the ids you create and verify cleanup by **id**, as this pass did. A name-based sweep would either miss your own leftovers or, much worse, delete someone else's live work.
- If that cron job is still present and idle in a later pass, it is still not yours to remove — surface it to the operator instead.

## A second, independent deploy-lag discriminator

Every pass so far has confirmed the stalled deploy one way: Settings → API Keys has no Client ID column. There is now a second, from a completely unrelated part of the product.

The env-group detail page renders `services.envEmptyBody` / `services.secretFilesDescription` / `services.secretFilesEmptyBody` — "Add a variable to configure **this service**", "…mounted into **this service** at deploy time" — on a page describing an *environment group*, which is shared across many services and is not one.

That is **already fixed on `main` and merely undeployed**, so it is deploy lag and not a bug (Phase 5 rule 4). `EnvGroupEditors` (`dashboard/src/features/env-groups/components/env-group-editors.tsx:40-49`) passes all eight `EnvironmentEditorCopy` overrides, including `envEmptyBody: t("envGroups.varsEmptyBody")`, and the env-group strings are correct and well-written ("Add a variable now; the group doesn't need to be linked first."). The override landed in `99126d5ad` at **2026-09-14 00:58**, while `e6419af0b` — which production is still *behind* — is **2026-09-13 23:43**:

```text
git merge-base --is-ancestor 99126d5ad e6419af0b  →  NO — landed after the deployed build
```

So: **if the env-group page says "this service", the dashboard build is older than `99126d5ad`.** Cheaper to check than the Settings page and independent of it.
