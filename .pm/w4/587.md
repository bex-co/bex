# 587 — In Chinese, Account Settings still names the password toggle "Show password" (w4/521 closed without reaching this page) and labels the profile fields "E-Mail" / "Name", so their placeholders read "输入您的 E-Mail"

Why: w4/521 was found on `/settings?lang=zh` and closed as fixed, but that page still announces the toggle in English. The profile card beside it mixes languages in its labels and placeholders. A Chinese user changing their password or name meets English in the one card where they type credentials.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 142, 2026-11-11 22:08–22:20 UTC (`muse.env`, workspace `bex-canary`; release pin `f609163ada8e`, which includes w4/521's `9faf15141`). **Minor** (i18n). ~40m.
- **Probe** (read-only, signed in): `/settings?lang=zh`, accessibility snapshot of `main`, Account section:
  - `heading "个人资料设置"`, then `text: 更新您的个人资料信息 E-Mail`, `textbox "E-Mail"` with placeholder `输入您的 E-Mail`, then `text: Name`, `textbox "Name"` with placeholder `输入您的 Name`.
  - `heading "更改密码"`, then `textbox "密码"`, then **`button "Show password"`**.
  - `heading "关联的账户"`, then `button "Unlink github"`.
  - **Control:** an English-phrase scan of eight other `?lang=zh` pages found nothing: `/notifications`, `/webhooks`, `/env-groups`, `/workspace/settings`, `/blueprints`, and a service's `/metrics`, `/events` and `/logs`.
- **Root cause:**
  - **The toggle (w4/521 incomplete).**
    - w4/521 made `UniqueIdPasswordInput` read `auth.showPassword` / `auth.hidePassword` (`dashboard/src/common/lib/ory/auth-form-overrides.tsx:30-59`).
    - That component is reached only through `oryAuthFormOverrides.Node.Input` (`:267-279`). Those overrides are passed by the login, register and verification pages only (`grep -rln auth-form-overrides dashboard/src` → those three pages and the file itself).
    - The Settings page passes `settingsComponents = {...oryHideSettingsPageHeader, Message: {Toast: OryToast}}` (`dashboard/src/features/auth/pages/settings-page/index.tsx:26-29`). Its password field is therefore Ory Elements' default input, whose aria-label is the literal "Show password" (`@ory/elements-react` `dist/theme/default/index.js`).
    - w4/521's note said "the same component serves every Ory password field … Settings > change password". It does not.
  - **The profile labels.**
    - The labels are the identity schema's trait titles, `"title": "E-Mail"` and `"title": "Name"` (`deploy/gitops/base/values/kratos.values.yaml:29,41`). Ory Elements prints them as the label and inside its zh placeholder template "输入您的 {title}".
    - Nothing in the dashboard localizes them (`grep -rn "traits.name" dashboard/src/common/lib/ory` → none). `auth-form-overrides.tsx:12` knows `traits.email` only to choose an input type.
- **Fix (target behavior):** in zh, the Settings card reads entirely in the dashboard's language.
  - **The password toggle** is "显示密码" / "隐藏密码", as on sign-in.
    - Add `Node.Input` to `settingsComponents`, delegating password nodes to `UniqueIdPasswordInput` and every other node to the default. Don't reuse `AuthNodeInput` wholesale: its email and OTP behaviours are sign-in specific.
  - **The profile fields** are labelled "邮箱" and "名称" in zh ("Email" and "Name" in en), with placeholders "输入你的邮箱" and "输入你的名称".
    - Map `traits.email` and `traits.name` to new i18n keys in that same Settings override (label and placeholder).
    - Leave the schema titles as they are: Kratos uses them in emails and admin views.
    - Use 你, per w4/573's register rule.
  - **Out of scope:** "Unlink github" and the other strings Ory Elements renders from its own bundled locale. They are upstream; the dashboard already passes `intl.locale` (`common/lib/ory/config.ts:62-73`).
- **Blast radius:**
  - `settingsComponents` has one caller (the Settings page).
  - `UniqueIdPasswordInput` keeps its three current callers through `oryAuthFormOverrides`.
  - **Tests:**
    - a Settings page render test under zh and en asserting the toggle's name in both states and the two profile labels;
    - keep w4/521's `UniqueIdPasswordInput` test.
- **Unverified:**
  - The recovery landing (forgot-password → Settings), which renders the same Settings flow and so gets the same fix.
  - Whether Ory Elements' zh bundle lacks the unlink key or the button takes its title elsewhere. Not traced, and out of scope.
- **Render:** n/a (dashboard language).
- **Dedupe:**
  - w4/521 (done) is the parent. Its closure note covered sign-in only in effect, so this note completes it rather than re-filing it.
  - w4/573 (open) is the zh register rule (您/你); the placeholder template here is Ory's.
  - `grep -rli "输入您的 E-Mail\|identity schema title" .pm` finds nothing.
  - **Not deploy lag.** The only later change to these two files is `557f1cf90` (w3/m305, which moved the workspace panels off the page). It is already in the pin and touches no `settingsComponents`, `Node` or `Input` line.
- **DoD (live):** signed in, `/settings?lang=zh` → Account:
  - the password toggle reads `显示密码`, and after a click `隐藏密码`;
  - the profile fields read `邮箱` and `名称` with Chinese placeholders;
  - `/settings?lang=en` reads `Show password`, `Email` and `Name`.
