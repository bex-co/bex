# 223 — Events filter offers eight indistinguishable build-setting choices
Why: after changing a shutdown setting, a tenant cannot tell which of eight identically named checkboxes will show that event.

- **Severity:** minor. Filtering itself uses the correct wire types; the visible and accessible option names hide their distinctions. Searching a wire-name fragment such as `shutdown` is a working mitigation.
- **Source:** live `$qa-find-bugs` cycle 9, 2026-10-08 America/Los_Angeles (captures 2026-10-09 UTC), dashboard.bex.co, QA workspace `tea-d98210cbbpdc73dcrkvg`. Fixture `qa-20261008-loop-a9-wake` / `srv-db46j0kct93s73fr3c70`: owned Free web service, `docker.io/library/busybox:1.37.0`, port 3000, successfully serving `qa-a9-awake`. Fixture deleted and this hunt's Kratos session revoked before filing.
- **Repro:** Settings → Edit max shutdown delay → 30 → 31 → Save changes succeeds. Wait for the change's event to appear, then freshly load `/services/<id>/events`. Filter events → search `build and deploy settings changed` shows **eight** independent checkboxes with exactly that visible text and accessible name. Uncheck All events, select the first matching checkbox, close the popover: `Filter events (1)` and `No matching events / Choose more event types or load older history.` Uncheck that first choice and select the seventh identically named choice: the saved event appears. The catalog identifies the first as `root_directory_changed` and seventh as `max_shutdown_delay_changed`; the control exposes neither distinction.
- **Fresh replay:** the eight names reproduced after another full desktop reload at **1280×1200**, and a fresh mobile reload at **390×844**. The complete unsearched control also has three `Auto-deploy updated` choices and three `Static site settings changed` choices. These two additional label clusters were observed; their individual event-selection journeys were not run.
- **Passing control:** search `shutdown` leaves one checkbox, still generically named; selecting it shows the event. Search matches the raw wire type (`max_shutdown_delay_changed`) even though the option does not display it. All-events renders the saved event normally. This is a labeling defect, not a missing API event or a dishonest filtered empty state.

## Root cause and exact scope

- `dashboard/src/features/events/service-event-catalog.ts:172-184` maps **eight** distinct types to `services.eventsTypeBuildSettingsChanged`: root directory, Dockerfile path, build filter, commands, source, pre-deploy command, max shutdown delay and deploy-hook regeneration. `:155-157` maps enabled/disabled/legacy auto-deploy changes to one title; `:169-171` maps publish path/routes/headers to one static-site title.
- `dashboard/src/features/events/components/service-event-filter.tsx:27-32` reuses this feed-title helper for catalogued option labels. `:154-166` nevertheless renders a separate checkbox per type, dispatches `setMany([type], ...)`, and assigns that same generic string to both text and `aria-label`. Search at `:79-84` uses the generic label or raw type, explaining the passing `shutdown` control.
- The ready feed consumer at `dashboard/src/routes/services.$serviceId.events.tsx:118-120` correctly excludes only types in `hiddenTypes`; its row title at `:432` uses the same generic helper. No malformed serialization, empty API response or query timing is needed to produce this defect.
- The wrapper `dashboard/src/common/components/ui/checkbox.tsx:13-30` forwards the supplied label. Actual pinned Radix **react-checkbox 1.3.3** (`dashboard/yarn.lock:2685-2687`; `node_modules/@radix-ui/react-checkbox/dist/index.mjs:93-117`) renders `role="checkbox"` and spreads `checkboxProps`; it does not add a type discriminator. The real accessibility tree above verifies the result.
- **Exhaustive caller inventory:** `serviceEventLabelKey` has **two production call sites**, filter `optionLabel` and the Events row. `ServiceEventFilter` has **one production caller**, the service Events route, plus its test harness. The catalog has **63 unique types** across groups of 12/9/8/2/32, and exactly **three duplicated title clusters**, totaling **14 options**. Apply the label change to those filter options only. The shared service route serves web/static/cron/worker/private services; Postgres/Key Value routes do not import this filter. Those siblings and the separate Metrics timeline/marker taxonomy were not exercised for this finding.
