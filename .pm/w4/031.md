# Remote provider catalog for the coding launchers + drift detection (update-channel phase 3)

Idea captured 2026-08-14; the model/provider catalog for `bex glm`/`muse`/`kimi`/`deepseek` (`cli/internal/code/provider.go`) is baked into the binary, so model-id drift (glm-5.2 → next, kimi-k3 → next) waits on a binary release today. Escape valve already exists (`bex glm --model <id>` passes through to Claude Code), so this is important-not-urgent.

Three pieces when promoted:

1. **Remote catalog:** bex-served curated catalog JSON (bex-api or CDN-hosted static file), fetched async with a 24h cache under `~/.bex/code/`, embedded catalog as offline fallback. **Security is the hard requirement:** a catalog entry's `base_url` decides where provider API keys are sent — bex-controlled HTTPS origin only, and signature verification (reuse cosign/age infra) with a higher trust bar for `base_url` changes than for model-list changes. Forward path to sharing one catalog with ADR047 agent-session provider selection.
2. **CI drift probe:** weekly cron workflow reusing the launcher's `validateKey`-style minimal Messages request per provider (probe keys in repo secrets); distinguishes endpoint-dead / model-gone / all-green and opens an issue on drift. models.dev api.json as a build-time diff reference for new models (curation stays ours; no runtime dependency).
3. **`bex code doctor`:** user-side probe of all four providers (endpoint + configured key + default model) to separate "my key is bad" from "catalog is stale".
