# 373 — A service's `updatedAt` advances on every reconciler status write, contrary to ADR006

Why: ADR006 promises that `updatedAt` moves on a real API mutation and "later reads return the same value until the next write". Today a crash-looping service reads "updated" every ~20 s with nobody touching it. The dashboard's Updated column says `now`, and `updatedAfter` list filters return services that never changed.

**Severity:** minor. **Estimate:** ~45m. **Source:** live `/qa-find-bugs w4` loop run c7a1, 2026-10-20 UTC, `muse.env`, workspace `bex-canary`. The owned fixture was deleted in-run and the session revoked.

## Probes (production, session-authenticated REST/GraphQL from the dashboard page)

The fixture, Free web service `srv-dbbfv0r581vs73bjhh80`, had its last API write at 06:15:02Z: a Settings start-command save to a missing binary, which deploys a crash loop. With no further write:

```
06:29:13 GET /v1/services/srv-dbbfv0r581vs73bjhh80 -> updatedAt 2026-10-20T06:29:10Z
06:29:34 -> 06:29:30Z   06:29:55 -> 06:29:53Z   06:30:18 -> 06:30:14Z
GraphQL { service(id:"srv-dbbfv0r581vs73bjhh80") { updatedAt } } -> same values
after the deploy settled update_failed (06:33:39Z): 06:34:22 -> 06:33:34Z, 06:35:02 -> 06:35:00Z
GET /v1/services?ownerId=tea-daif693dqjvc73e7as3g&updatedAfter=<now-3m> -> includes qa-20261020-c7a1-web
```

Controls in the same window, all unchanged across 60 s:

- Key Value `red-dbbgc8b581vs73bjhi0g`: `06:12:19Z`.
- Another run's Postgres (read only): `03:01:30Z`.
- Healthy `qa-20261018-f4cfb1-echo`: `2026-10-19T02:54:30Z`.

The project page's resource table showed the service as Updated `now`.

## Root cause

- `resourcemeta.UpdatedAt` (`lego/backend/internal/resourcemeta/metadata.go:164-180`) returns the latest of the `app.bex.co/updated-at` annotation and **every** `metadata.managedFields[].time`. The operator writes App status through the status subresource (`r.Status().Update`, `lego/operator/internal/controller/app_controller.go:5695`). That gives it a managed-fields entry with `subresource: status`.
- Per `k8s.io/apimachinery@v0.35.0` `pkg/apis/meta/v1/types.go:1351-1357`, that entry's `time` "will also be updated if … the manager changes any of the owned fields value". So each status change during a crash loop, wake or stall moves `updatedAt`.
- The function comment (`:161-163`, "mutation/reconciliation time") contradicts the governing contract, `docs/ADR006-bex-api.md:105`. That contract says API writes stamp the annotation, and managed-field time is the fallback only for legacy objects that lack the annotation.

## Fix (target behavior)

- When the annotation is present, `updatedAt` is the annotation and nothing else.
- Without the annotation (legacy/hand-applied objects), fall back to managed-field times while ignoring `subresource: status` entries. A status change is never an update.
- A legacy object with neither source still omits `updatedAt`.
- Callers, all on this one function: `apps/service.go:1137`, `postgres/service.go:572` and `keyvalue/service.go:313`. That moves REST, GraphQL and MCP together, plus the `updatedBefore`/`updatedAfter` list filters (`apps/rest.go:704-709`, `postgres/rest.go:125`, `keyvalue/rest.go:261`). The 29 `resourcemeta.Touch` stamp sites are unchanged.
- **Adjacent:** system actions that are not API writes (free-tier wake/sleep, operator rollout progress, a datastore turning Available) stop advancing `updatedAt`. API-triggered deploys, restarts and suspends still do, through `Touch`.

## Acceptance

- A unit test in `resourcemeta` with an annotated object plus a newer `subresource: status` managed-fields entry returns the annotation. A legacy object with only a status entry and a main-resource entry returns the main-resource time; with neither, the result is empty.
- The existing `metadata_rest_test.go` tests (`w9/m41`) in apps/postgres/keyvalue still pass. One of them adds a reconcile-only status change and asserts `updatedAt` is unchanged.
- Live: replay the crash-loop probe above. Four reads 20 s apart return the start-command save time; `updatedAfter=<now-3m>` omits the service.

## Unverified

- Render's own `Service.updatedAt` semantics on deploy or status transitions (ADR006 is the contract applied here).
- Whether free-tier wakes advanced `updatedAt` (`hello-go` read `05:29:45Z`, which looks like a wake but was not traced).
- Postgres/Key Value status transitions beyond the steady-state controls.
