## Objective

A rollback deploy's trigger label renders as `Rollback To Dep-Dal3f2rkmutc73d7q9lg` — a CSS `capitalize` is applied to a string that interpolates a resource id, so the id is title-cased and no longer matches the real `dep-dal3f2rkmutc73d7q9lg`. Render the label as `Rollback to dep-…` with the id intact.

## Context

Live capture, 2026-09-16 (`srv-dal3f2rkmutc73d7q9l0`, after rolling back to its first deploy):

```js
// element under the deploy status badge
{
  innerText: "Rollback To Dep-Dal3f2rkmutc73d7q9lg",
  textContent: "rollback to dep-dal3f2rkmutc73d7q9lg",
  textTransform: "capitalize",
  outerHTML: '<span class="text-xs capitalize text-muted-foreground">rollback to dep-dal3f2rkmutc73d7q9lg</span>'
}
```

Both deploy surfaces do it:

- `dashboard/src/features/deploys/components/deploy-header.tsx:105-107` — `<span className="text-xs capitalize …">{triggerLabel(deploy.trigger, deploy.rollbackOf, t)}</span>`, with `triggerLabel` at `deploy-header.tsx:19-27` returning `t("deploys.triggerRollback", { deployId: rollbackOf })`.
- `dashboard/src/features/deploys/components/deploys-list-page.tsx:250` and `:255-256` — the same helper (`deploys-list-page.tsx:75-81`) inside `className="capitalize"` cells.

The locale string is lower-case and depends on that CSS to look right: `dashboard/src/features/deploys/locales/en.ts:123-127` → `message: "rollback to {deployId}"`. Its siblings do not — `deploys.triggerManual` etc. are already title-cased, so `capitalize` is a no-op for them and only damages the interpolated id.

This is the second member of a class `w4/036` already fixed once: that note (done) traced `new_commit` rendering as "New_commit" to the same `capitalize` wrapper and fixed it by adding a properly-worded locale key. It did not touch the rollback key, whose defect is the interpolated value rather than the enum. Fixing the wording alone is not enough here — the `capitalize` class must stop covering the id.

Verified in the same session: with the CSS removed the other labels must still read "Manual Deploy", "First Deploy", "Config Change", "New Commit" — confirm from their locale strings, not from the rendered page, since the page currently gets its casing from the CSS.

## Steps

1. Change `deploys.triggerRollback` to a properly-cased message ("Rollback to {deployId}") in the `en` locale, and make the `zh` counterpart consistent with how it handles the id.
2. Remove the `capitalize` class from the three sites above — or, if any sibling label genuinely depends on it, scope the class to the non-interpolated part so no id is ever inside a `capitalize` box.
3. Check every other `deploys.trigger*` key renders correctly with the class gone; `w4/036`'s `new_commit` fix is the one most likely to have been written against the CSS.
4. Grep the dashboard for other `capitalize` classes wrapping text that interpolates an id or a slug — the same mechanism will be wrong anywhere it occurs.
