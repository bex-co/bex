## Objective

The Metrics page's **Total Requests** section sums the raw series points into its heading count. Once `t001` makes those points real counts, confirm the heading, the bars and the zero-gate all tell the truth — and remove whatever compensating behavior was masking the rate.

## Context

`dashboard/src/features/metrics/components/network-metrics-card.tsx:150-158`:

```ts
// Render titles the section with the window's aggregate ("7,266 requests").
const requestCount = useMemo(
  () =>
    Math.round(
      requests.series.reduce(
        (sum, s) => s.points.reduce((acc, p) => acc + p.value, sum),
        0,
      ),
    ),
  [requests.series],
);
```

Summing per-second rates is what produced the two live symptoms captured 2026-09-16:

- `srv-dal3f2rkmutc73d7q9l0` (12 requests in the window): `Σ = 0.1777` → `Math.round` → `0` → the summary is suppressed entirely by the `requestCount > 0` gate, and the bar chart renders `0`. The page claims no traffic while the Logs tab on the same service shows the requests.
- `srv-d9bj8s3eg85c7390eb9g` (≈7 req/s): the heading reads "727 requests" for a 12h window that served roughly 300k.

The zero-gate is deliberate and documented — `.pm/w6/done/028.md` records `network-metrics-card.tsx:269-278` gating the whole summary on `requestCount > 0`, and the singular/plural keys it chooses between. That gate is correct **for a genuinely idle service**; this task must keep it working for that case while no longer hiding real traffic.

Note that `Response Times` on the same card already had data for the same service in the same window (`0–102ms`) — the card contradicting itself is the most user-visible form of this bug, and is the quickest thing to re-check after the fix.

## Steps

1. Re-check `requestCount` after `t001`: with real counts, the `reduce` is the right aggregate and should need no change. If it does need one, say why in a comment — the next reader will otherwise assume the sum was always correct.
2. Verify the bar chart's y-axis formatting renders integer request counts (`svg-bar-chart.tsx` and whatever formatter the card passes), not the fractional values the rate produced.
3. Verify the singular/plural keys (`w6/028`'s fix) still choose correctly at 1 and at N, and that the `> 0` gate now only suppresses the summary when the window truly had no requests.
4. Re-check the grouped view (`Group by` → status / method): the group totals must sum to the heading count.
5. Capture pending and ready states at desktop and narrow-mobile widths if the card's skeleton geometry shifts (repo rule for preloading skeletons).
