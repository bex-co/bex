# 620 — A new Python service with no version signal builds on Python 3.14.8, and a new Ruby service on 3.4.4; Render's defaults for services created since 2026-11-03 are 3.14.10 and 3.4.12

Why: Render picks a service's default runtime by its creation date, and on 2026-11-03 it moved both defaults to the patches bex already pins as its reviewed 3.14 and 3.4 lines. bex still swaps every new no-signal service onto the older exact patch. So a new service runs a different interpreter than on Render, and for Python that is the frozen `python:3.14.8` image without the Brotli fix (w8/222).

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 246, 2026-11-13 00:40–00:50 UTC (`muse.env`, workspace `bex-canary`; pin `764072bb8e8a`). **Minor** (a parity drift in the default patch). ~40m.
- **Fixture:** Free web service `qa-20261113-r246-py` (`srv-dbr5ov9s0kvs73brgbhg`). Created from the dashboard's Public Git URL tab: repo `https://github.com/bex-co/bex`, root `examples/hello-python`, runtime Python 3, start `python main.py`, no `PYTHON_VERSION`, no `.python-version`. Deleted afterwards.
- **Probe:**
  - Deploy `dep-dbr5ov9s0kvs73brgbi0`, created 00:40:29. The build log read `Using Python 3.14.8 (default)`, then `Using Poetry 2.1.3 (default)`, then `Build successful 🎉` at 00:44:05.
  - At 00:46:09, `https://qa-20261113-r246-py.onbex.co/` answered `200 hello from bex` with `server: Werkzeug/3.1.9 Python/3.14.8`.
- **Render (read 2026-11-13):**
  - [Python version](https://render.com/docs/python-version): "2026-11-03 and later → 3.14.10", "2026-10-12 to 2026-11-03 → 3.14.8".
  - [Ruby version](https://render.com/docs/ruby-version): "2026-11-03 and later → 3.4.12", "2025-06-12 to 2026-11-03 → 3.4.4".
  - [Node version](https://render.com/docs/node-version): "2026-10-21 and later → 24.22.1". bex's Node 24 line already pins that patch, so Node is not affected.
- **Root cause:** `exactDefaults` (`lego/operator/internal/build/nativeversion.go:166-174`) holds a single `{cutoff, version}` per runtime: Python `{pythonCreationCutoff (2026-10-23), "3.14.8"}` (`:124`, `:151`), Ruby `{rubyDefaultCutoff (2026-10-23), "3.4.4"}` (`:140-142`).
  - `defaultExact` (`:181-191`) returns that version for every service created on or after the cutoff, with no upper bound. The resolve phase (`nativeresolve.go:80`) then swaps in the official exact image.
  - The reviewed line patches already equal Render's new defaults: `native.go:125` (3.14 → 3.14.10) and `native.go:132` (3.4 → 3.4.12).
- **Fix (target behavior):** a service with no version signal builds on the exact patch Render's table gives its creation date:
  - created from 2026-10-23 until the new cutoff → Python 3.14.8, Ruby 3.4.4 (unchanged);
  - created on or after the new cutoff → Python 3.14.10, Ruby 3.4.12.
  - **How:** make each `exactDefaults` entry an ordered list of `{from, version}` steps. `defaultExact` picks the last step whose `from` ≤ `created`, and needs no image swap when that version equals the line's reviewed patch (`:187-189` already does this).
    - Keep the exact versions in the table rather than dropping the entry after the cutoff. Dropping it would make a later line-pin bump (3.14.11) silently move the default again — the w8/217 regression class.
  - **Cutoff date:** prefer Render's 2026-11-03. That moves a service bex created from 11-03 to the ship date from 3.14.8 to 3.14.10 (or 3.4.4 to 3.4.12) on its next build, which is what Render gives such a service.
    - The earlier cutoffs used bex's ship date so that an operator upgrade never moves a running service's toolchain (`:118-124`, `:135-142`).
    - If the worker keeps that rule, use the ship date and record the 11-03-to-ship window as a dated divergence in ADR018.
  - Update the comments at `:144-150` and `:176-180`, and ADR018's runtime row (`docs/ADR018-render-parity.md:90`) if it names the exact defaults.
- **Blast radius:**
  - `defaultExact` has 1 caller (`ResolveNativeVersionAt`, `:155`), which `nativeresolve.go:80` uses for every native build.
  - Tests that pin `pythonCreationCutoff.Add(time.Second)` → 3.14.8 stay valid, since that date falls inside the first step: `nativecommon_test.go:48`, `nativeutility_qualification_test.go:401`, `nativeutility_integration_test.go:207`, `nativeexact_test.go:312-332`, `nativeversion_test.go:684-704`.
  - Explicit signals are untouched (`choice.Source != ""`): `PYTHON_VERSION`, `.python-version`, Gemfile and the others.
- **Tests:** extend `TestPythonDefaultIsRendersExactPatch` (`nativeexact_test.go:292`) and `TestRubyDefaultIsRendersExactPatch` (`:244`) with three cases each:
  - created 1 h after the new cutoff → no swap, the line's reviewed image, version 3.14.10 / 3.4.12;
  - created 1 h before it (and after 2026-10-23) → still 3.14.8 / 3.4.4;
  - a test-only bump of the line pin past the default does not move the after-cutoff default.
- **Relation to w8/222 (blocked):** it keeps exact 3.14.8 and repairs Brotli on the m91 common base. After this fix, that path covers only services created in the 3.14.8 window; new services get 3.14.10 and its patched Brotli from the reviewed line image. A dated cross-reference is added there.
