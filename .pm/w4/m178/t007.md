## Objective

After a successful project Move or Remove, publish fresh source Environment memberships and row/count state without waiting for a poll or reload. Preserve the shipped source Project refresh and exactly one membership write.

## Context

- [Pass 155 live finding and durable probes](finding-environment.md).
- Selected Environment rows consume EnvironmentsDocument, independently of the source Project that the current hook refreshes.
- A fresh source Project returned within 0.5 seconds on the repeat; the ready Stage row/count still remained 20 seconds later. Remove reproduced the same separate list gap.
- The fresh Unassigned A→B control removed the row/count in 0.791 seconds.

## Steps

1. Extend the existing client/router singleton refresh seam with the known source project ID for both Move and Remove; refresh its typed EnvironmentsDocument.
2. Settle older matching source list results, then force a source-scoped network-only read with queryDeduplication false before completing freshness publication. Follow the existing rename-project ordering pattern; avoid unrelated-project refresh and late stale publication.
3. Retain cross-project source Project-before-invalidate ordering. Remove already returns the source Project: do not add a redundant singular Project read.
4. Keep previous data during pending refresh. Preserve mutation refusal separately from post-success refresh rejection; a freshness retry re-reads only.
5. Preserve source/target authoritative placement, existing polling/visibility and cache policies, menu-unmount safety and exactly one membership write.
