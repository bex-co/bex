# A Postgres recovery takes the plan's default disk and default parameters, not the source's

Why: `Recover` creates the new instance at the plan's default storage and with no parameter overrides. A source whose disk grew past that default (`DatabaseStorageHighWater`), or whose data needs a tuned setting to load, can fail to restore: CNPG restores the base backup and WAL into a volume too small to hold them, and nothing in the operator grows it first.

- **Source:** `w4/356` simplify review, 2026-10-19 (loopx w4). Reasoned from code; not reproduced live (bex-canary has no backed-up paid Postgres).
- **Path:** `lego/backend/internal/postgres/recovery.go` `Recover` builds `newDB.Spec` with `Plan`, `Version`, `DatabaseName`, `DatabaseUser` and `Recovery` only. `StorageGB` and `Parameters` are left unset. `CreatePostgres` sets `StorageGB: req.DiskSizeGB` and `Parameters: normalizeParameterOverrides(…)`.
- **Fix sketch:**
  - Copy the source's storage high-water mark (`DatabaseStorageHighWater(src)`) as the floor for `StorageGB`, so the restore always has room. Bill it as the create path bills disk.
  - Copy `src.Spec.Parameters`. Leave HA, the pooler, read replicas and disk autoscaling to an explicit opt-in: they change cost, and Render offers them as "copy existing settings" choices.
  - Test with a grown-disk source; record parity in ADR009 and ADR018 (Render's "copy existing settings" default).
- **Estimate:** 45m.
