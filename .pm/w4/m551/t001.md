## Objective

Settle what Render's **Apps** page creates, so bex deploys the same thing.

## Context

- [render.com/docs/postgresql-apps](https://render.com/docs/postgresql-apps): pgAdmin and PgHero; on the database's **Apps** page, **Deploy app** opens a dialog with autogenerated credentials (editable) and billing details; Render creates "a standard web service" in the database's region with "the smallest compute specs possible according to the app's requirements", "automatically connects it to your database over your private network"; credentials are env vars (`PGHERO_USERNAME`/`PGHERO_PASSWORD`, `PGADMIN_DEFAULT_EMAIL`/`PGADMIN_DEFAULT_PASSWORD`); the app appears in the service list; **Open app** logs in; editing its env vars can break the connection; pgAdmin's in-app password change does not update the env var.
- The docs do not name the image, plan, port, service name, the variable that carries the connection, or which database plans offer the page.
- Method: Render's public dashboard bundle, read without signing in, as [account-appearance.md](../../../docs/render-artifacts/account-appearance.md) did.

## Steps

1. Find the Apps page and its deploy dialog in the bundle.
2. Record: the app catalog and its copy; the image (and registry) or repository per app; the plan; the port; the service name pattern; every env var and secret file set, including the connection; the credential generator (length, alphabet, email default for pgAdmin); the billing line; the deployed state ("Open app", link to the service); which database plans and states show the page; the GraphQL operation and its arguments.
3. Write `docs/render-artifacts/postgres-admin-apps.md`.
