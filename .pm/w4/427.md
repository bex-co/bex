# A Free Postgres or Key Value is charged for storage: the storage meter reaches Stripe with no Free-tier exemption

Why: Render's Free Postgres costs $0 (a fixed 1 GB is included). bex reports the Free datastore's used bytes to Stripe as billable `storage_gb_hours`, so a Hobby workspace with nothing but Free resources accrues real metered charges, and the Billing page shows them.

Severity: major (billing parity: a "Free" resource generates charges; the amounts are small, but any non-zero invoice on a Hobby-only workspace is a trust problem). Estimate: ~45m. Source: live `/qa-find-bugs w4` loop run c5dd, 2026-10-27 UTC (`muse.env`, Hobby workspace `tea-daif693dqjvc73e7as3g`, pin `610021d1def6`).

## Evidence

- `/billing` → Charges → Expand all: **Postgres $0.02** = `qa-20261017-64552e-pg14` **$0.01** (a **Free** Postgres, `dpg-db9r654flioc739mcpbg`, "Free: 1 of 1" on the same page) + `qa-m141-202610262113` (deleted) $0.01. "Total month to date $2.20". This workspace shows "excluded from Stripe collection by an operator", so the charge only shows in the estimate here. A collected Hobby workspace would be metered.

## Cause

- `lego/backend/internal/billing/stripe.go:426-443` `stripeMeterEvent`: `instance_seconds` with `tier == "free"` is skipped ("nothing is owed"), but `UsageKindStorageGBSeconds` maps straight to `storage_gb_hours` with no tier or plan check.
- `lego/backend/internal/pricing/pricing.go:369-372`: the advisory estimate prices `storage_gb_seconds` for every Postgres/Key Value row at `storage.usdPerGBSecond`, whatever the tier. `pricing.yaml:57-58` already zeroes Free Postgres compute.
- `lego/backend/internal/usage/service.go:1206-1230` `queryStorageGBSeconds` meters every datastore's used PVC bytes. That is fine to keep as usage data; only pricing and billing must exempt Free.
- `docs/ADR030-pricing.md:42` defines storage pricing on used bytes and never addresses Free instances. `docs/ADR009-postgresql-management.md:112` records Render's fixed 1 GB Free storage.

## Fix

- Exempt Free-tier datastores from the storage charge on **both** paths: skip the Stripe meter event for a storage row whose datastore tier is `free` (use the same property the instance path reads), and price it at $0 in `Estimate`. Keep the usage row so the Billing page can still show the GB used.
- Record the rule in ADR030 (Free Postgres/Key Value include their fixed storage at $0, as on Render) and add an ADR018 billing row.
- Tests: in `billing/stripe_test.go`, a Free Postgres storage event is skipped and a `basic-256mb` one is sent. In `pricing_test.go`, Free storage costs $0 and paid storage keeps the rate. Free Key Value is covered the same way.

## Unverified

- Whether any collected Hobby workspace has actually been invoiced for Free storage. Check Stripe meter events for `storage_gb_hours` against Free datastores before deciding on credits.
- Render's treatment of Free **Key Value** storage. Render lists no Key Value storage line, and bex's Key Value storage charge is a deliberate extension (ADR030:42); the Free exemption should cover it too.
