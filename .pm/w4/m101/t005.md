## Objective

Both fixes change code shared across callers, and in both cases the callers that behave correctly today do so *because* of current behavior — so they need regression coverage as much as the broken paths. Enumerate, cover, and prove the guarantees that must survive.

## Context

### t001's shared validator — enumerate, do not estimate

`autoscalingSpec` (`lego/backend/internal/apps/service.go:4362`) is the shared gate. Its reachable entry points, from the grep recorded in t001: `specFromCreate` (`service.go:2579`, which also serves the Blueprint `scaling:` block from w2/m49), `SetAutoscaling` (`:4439`) via REST (`rest.go:1116`), GraphQL (`graphql.go:1683`) and the settings patch (`settings.go:295`), plus `DeleteAutoscaling` reached from `rest.go:1119`, `graphql.go:1692`, `mcp.go:865`. Re-run the grep and paste the count; if t001 put the check somewhere else, enumerate that function's callers instead.

Control cases that must not change: a **web service** enabling autoscaling; a **private service** doing the same; the plan-cap refusal (`checkInstanceCap`) and every bound already validated at `:4363-4394`; `w6/m118`'s instance-cap behavior.

### t003's shared handler — one handler, every static site

`staticserver.New` has one production registration (`cmd/staticserver/main.go:166`, recorded by `w4/m94` t003), so any change applies to **every** static site in the estate at once, including custom-domain hosts that resolve into the same `Site`. There is no allowlist and no per-site opt-in — say so, and treat it accordingly.

Guarantees from `w4/m94` that must keep holding, verbatim from its own summary: an existing published object beats redirect/rewrite rules; origin permission denials, timeouts, oversize and capacity failures keep their own 502/413/503 classes instead of degrading into a rule; custom headers match the visitor's **immutable request path** while the served path drives content type and default cache policy; the `/index.html`-scoped header does not leak onto rewritten requests. Plus `w4/m96`'s log-boundary work and `w2/m93`'s legacy-prefix dual read are in the same file — do not disturb them.
