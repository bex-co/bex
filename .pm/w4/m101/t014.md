## Objective

`CopyButton` renders its caller's `label` prop verbatim as the whole `aria-label`. Most callers pass an action ("Copy service ID", "Copy endpoint URL"); two **shared field wrappers** pass the field's column label instead, so the button announces itself as a noun. On the custom-domain DNS panel a screen-reader user hears `button "Host"`, `button "Target"`, `button "Host"`, `button "Target"` — neither what the control does nor which of the two records it belongs to.

## Context

### The observation (production, 2026-09-13 pass 19)

Fixture `qa-20260913-dom` with `qa-20260913.example.com` added, the DNS-setup dialog open, read from the **real accessibility tree** (`await page.locator('[role=dialog]').ariaSnapshot()`):

```text
- dialog "Domain claim created — set up DNS":
  - text: Type
  - code: TXT
  - text: Host
  - button "Host"                    ← copies _bex-challenge.example.com
  - code: _bex-challenge.example.com
  - text: Target
  - button "Target"                  ← copies bex-domain-verification=…
  - code: bex-domain-verification=pC-RTWFFVd4Tq3yoaspTHXqpAP03yEZw
  - paragraph: Traffic record
  - text: Type
  - code: CNAME
  - text: Host
  - button "Host"                    ← copies qa-20260913
  - code: qa-20260913
  - text: Target
  - button "Target"                  ← copies qa-20260913-dom.onbex.co
  - code: qa-20260913-dom.onbex.co
  - button "Done"
```

Two buttons named "Host" and two named "Target" in one dialog, and the visible column label beside each is the same word — so the name adds nothing a sighted user gets from position.

### Root cause

`dashboard/src/common/components/copy-button.tsx:31` — `aria-label={label}`, so the caller's string **is** the accessible name; the component adds no verb of its own. Two shared wrappers pass a field label into it:

| wrapper | line | what reaches `aria-label` |
| --- | --- | --- |
| `features/services/components/custom-domains-section.tsx` → `RecordField` | `:496-501` passes `label={label}`, fed by `DnsRecordFieldsRow`'s `domainRecordHost` / `domainRecordTarget` (`:431-441`) | "Host" / "Target" |
| `common/components/connection-field.tsx` | `:26-31` passes `label={label}` | the field's own label, e.g. `databases.connPassword` → "Password" |

### The convention is already the majority, which settles the target shape

`grep -rn "<CopyButton" dashboard/src --include='*.tsx' | grep -v __tests__` → **15** direct call sites. Their labels split three ways:

- **Action + object (correct), 8 sites:** `services.headerCopyServiceId` → "Copy service ID", `webhooks.copyUrl` → "Copy endpoint URL", `services.deployHookCopy` → "Copy Deploy Hook URL", plus `webhooks.copyId`, `services.internalCopy`, `services.headerCopyUrl` (×2), `agentSessions.sshCopy`.
- **Bare verb, no object, 2 sites:** `apiKeys.copy` → "Copy", `webhooks.copy` → "Copy".
- **Field label as the name, 2 wrappers:** the two above.

So **target behavior: a copy control's accessible name is a verb plus the thing it copies** — "Copy host record", "Copy TXT value", "Copy password" — never a bare column label and never a bare "Copy". Eight sites already do exactly this; this task brings the two wrappers and the two bare-verb sites onto it.

The cleanest fix is at the two wrappers — give each an explicit `copyLabel` (or derive "Copy {label}") rather than editing 14 call sites — but check each call site's label reads correctly under that template first: "Copy Password" is fine, "Copy Open to all source IPs" would not be.

## Steps

1. Add an explicit copy-label input to `RecordField` and `ConnectionField` (or derive `t("common.copyField", { field: label })`), so the accessible name carries a verb while the visible column label stays as it is.
2. For the DNS rows, distinguish the two blocks: the ownership TXT record's host/target and the traffic record's host/target must not produce two identically-named buttons. The record `type` (TXT / CNAME) is already in scope at `DnsRecordFieldsRow` and is the natural discriminator.
3. Decide the two bare-"Copy" sites (`apiKeys.copy`, `webhooks.copy`) in the same pass — same defect class, one word each.
4. Verify in the real accessibility tree, not the DOM: the DNS dialog must show four **distinct** button names.
5. Add the strings to `en.ts` and `zh.ts`.

## Journey 5 exercised the same run and found **correct**, so not filed

Custom domains came out clean; recorded so the next hunt skips it. Fixture `qa-20260913-dom` (`srv-dajj0d8gsm7s73f6404g`, free, image-backed) with `qa-20260913.example.com` — a documentation-reserved name nobody can register, so attaching it could not hijack a real host — added and **removed in the same visit**, service deleted.

- **The DNS instructions match `docs/ADR005-custom-domain.md:16-17` exactly.** Ownership `TXT` at `_bex-challenge.example.com` — the *registrable* domain, not the full subdomain — carrying `bex-domain-verification=…`; traffic `CNAME` with host `qa-20260913` (the label prefix) → `qa-20260913-dom.onbex.co` (`<service>.<BEX_BASE_DOMAIN>`). Both targets are the ones the ADR specifies.
- **The add dialog becomes an instruction step rather than closing.** "Domain claim created — set up DNS" with both records and a Done button, so the durable challenge is readable after the add — the recovery path ADR005:28 requires.
- **The copy warns about the shared TXT host:** "This host holds one TXT record per domain — add this value as an additional record and keep any bex-domain-verification values already there." That is the `w6/055` sibling-claims hazard, stated to the user before they can clobber a sibling.
- **The state machine does not stick, and the refusal is actionable.** Row shows `Pending` / `Pending`. `POST …/custom-domains/{id}/verify` → **409** `{"code":"DOMAIN_OWNERSHIP_PENDING","message":"domain ownership TXT record is not verified","params":{"recordName":"_bex-challenge.example.com"}}` — it names the record to fix. GraphQL returns the same via `extensions.code` + `extensions.recordName`.
- **The dashboard surfaces that refusal.** Re-check toasts "qa-20260913.example.com isn't verified yet — DNS may still be propagating." (`use-custom-domains.ts:252-257` branches on `DOMAIN_OWNERSHIP_PENDING`).
- **Deleting the domain returned 204 and the list went to 0** — no residue.
