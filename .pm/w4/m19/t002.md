## Objective

Give every service a stored, globally-unique subdomain slug, separate from its user-chosen name (Render's `slug` vs `name`). The slug is the plain name when free; on global collision it becomes `<name>-<xxxx>` (random short base36 suffix, hyphen-separated per ADR020). Today no slug exists anywhere — the operator derives the host from raw `app.Name` on the fly.

## Context

- `apps` table: `lego/backend/internal/store/migrations/0001_core.up.sql` has `UNIQUE (tenant_id, name)` but no slug column; only `domains.host` is globally unique today.
- `CreateApp` at `lego/backend/internal/store/store.go:377` (insert, `appColumns` `:399`, `scanApp` `:402`); PG `23505` → `store.ErrConflict` via `classify` (`store.go:691`).
- CRD types live in `lego/types/` (leaf module); codegen via `make manifests generate` from `lego/operator/`.
- Slug must remain a valid DNS label ≤ 63 chars combined with `BEX_BASE_DOMAIN`; name is already capped at 30 (`ValidAppName`, `lego/backend/internal/store/api.go:407`).
- Suffix minting: random 4-char base36, retry on the UNIQUE violation; never hand-rolled ids for the `id` column — that stays `id.New` (ADR020). The slug is a hostname fragment, not a resource id.

## Steps

1. New migration: add `apps.slug text` with a global `UNIQUE` index; backfill existing rows (`slug = name`, suffix any pre-existing global dupes).
2. Extend the store `App` struct, `CreateApp`, `appColumns`/`scanApp`; `CreateApp` mints the slug: try bare name, on slug-unique violation retry with `-<4 random base36 chars>`.
3. Add `spec.subdomain` (or `slug`) to the App CRD in `lego/types/`; run `make manifests generate` from `lego/operator/`.
4. Thread the slug through bex-api create (`lego/backend/internal/apps/service.go` create path) and the projector (`lego/backend/internal/store/reconciler.go` `projectApp`) into the CR spec.
5. Unit tests: bare-name slug when free; suffixed on collision; slug stays a valid DNS label at max name length.
