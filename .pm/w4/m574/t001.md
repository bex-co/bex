## Objective

In gVisor's devpts line discipline, a control character set to `_POSIX_VDISABLE` (0 on Linux) matches no input byte. With `stty intr undef`, a NUL byte is then queued for the reader like any other byte and sends no SIGINT, as on Linux.

## Context

- Linux `drivers/tty/n_tty.c` `n_tty_set_termios()` builds `char_map` from the special characters, then does `clear_bit(__DISABLED_CHAR, ldata->char_map)`. A NUL byte therefore never reaches `n_tty_receive_char_special()`.
- gVisor `pkg/sentry/fsimpl/devpts/line_discipline.go` `inputQueueTransformer.transform()`: the `switch cBytes[0]` cases on `ControlCharacters[VINTR|VSUSP|VQUIT|VWERASE|VERASE]` (fork `bex/echo-signal-chars` ~:615-645) match 0 when the character is disabled. m545's IXON echo case (~:801) already guards with `c != 0`.
- `pkg/abi/linux/tty.go` has an unexported `disabledChar = 0` (:24-26), which `IsTerminating` (:129) and `IsEOF` (:141) already use. Prefer one helper there or in devpts that t002–t005's new cases also use, over scattering `!= 0` checks.
- Work in the `bex-co/gvisor` fork. Stack a branch for upstream on `bex/echo-signal-chars` (`c69889c22`), and cherry-pick each commit onto `bex/release-20260622.0-echo-signal-chars` for the pool build. The fork's workflow `.github/workflows/bex-echo-signal-chars.yml` runs `syscall-tests` natively, `syscall-tests-without-fix` and `unit-test` on runsc, and `probe`. Its m545 runs: release branch 44956550082 (all jobs green), master-based branch `bex/echo-signal-chars-ci` 44956550326 (syscall jobs green, `probe` failed at its `Patched runsc` step with exit 128; read why before relying on that job).

## Steps

1. Add the helper and use it in every special-character case.
2. Add syscall tests in `test/syscalls/linux/pty.cc`. With VINTR set to 0 and ISIG on, writing `\0` to the master signals nothing and the replica reads a NUL. Add the same check for one canonical-mode character (VERASE at 0 erases nothing).
3. Run them natively and on runsc, and on runsc with the fix reverted.
