## Objective

When ISIG turns VINTR, VQUIT or VSUSP into a signal and NOFLSH is clear, discard the pending input and echoes as Linux's `isig()` does, and notify a packet-mode master. Typing `abc`, Ctrl-C, Enter then reads `\n`, not `abc\n`. With `stty noflsh` it still reads `abc\n`.

## Context

- Linux `drivers/tty/n_tty.c` `isig()`: without `L_NOFLSH`, it signals, then clears the echo buffer, calls `tty_driver_flush_buffer()`, resets the input buffer (`reset_buffer_flags()`), and calls `n_tty_packet_mode_flush()` (`TIOCPKT_FLUSHREAD` to a packet-mode master). For a pty, `tty_driver_flush_buffer()` is `pty_flush_buffer()` in `drivers/tty/pty.c`. It drops output the master has not read yet and reports `TIOCPKT_FLUSHWRITE` in packet mode. Read both functions in the kernel source and match them, or record what is left as a known difference.
- `n_tty_receive_signal_char()` flushes first and echoes after, so the `^C` m545 added stays on the screen. Under IXON it also calls `start_tty()` (t005).
- gVisor (fork `bex/echo-signal-chars`):
  - `receiveSignalChar` (~:780) is the place for the flush.
  - `tcFlush` (~:957) and `packetStatusForFlush` / `notifyPacketStatus` (~:891-922) already implement TCIFLUSH and the packet-mode status for `tcflush()`.
  - `transform` holds `q.mu` and the termios read lock. Check the lock order before reusing `tcFlush`.

## Steps

1. Flush in `receiveSignalChar` when NOFLSH is clear, with the packet-mode notification.
2. Add syscall tests in `test/syscalls/linux/pty.cc`:
   - Cooked mode: write `abc`, then `\x03`, then `\n`. The replica reads `\n`, and the master reads `abc^C\r\n` (or Linux's exact echo bytes; take them from the native run).
   - The same with NOFLSH set reads `abc\n`.
   - Packet mode: a TIOCPKT master sees `TIOCPKT_FLUSHREAD`.
3. Run them natively, on runsc, and on runsc with the fix reverted.
