## Objective

Use **SendGrid** as the prod mail provider (user decision 2026-07-06), integrated purely as an SMTP relay — no vendor SDK: Kratos's courier takes `smtps://apikey:<sendgrid-api-key>@smtp.sendgrid.net:465` (literal username `apikey`), so the mechanism stays a provider-agnostic connection URI that self-hosters can point anywhere. Plumb the secret the same way as the Ory secrets: a `KRATOS_COURIER_SMTP_URI` key in `.env` (names mirrored to `.env.example`/`.env.template`, never values), injected into the `auth/kratos` Secret by `scripts/auth-secrets.sh`, pushed to GitHub Actions by `scripts/gh-secrets.sh`.

## Context

- Pattern: docs/auth.md §5 — secrets out-of-band, composed/validated by `scripts/auth-secrets.sh`, `DRY_RUN=1` prints names only.
- Kratos courier config takes `courier.smtp.connection_uri`; the chart reads it from the existing `auth/kratos` Secret (key name per chart values).
- SendGrid deliverability prerequisites (account-side, document rather than automate): sender/domain authentication for the from-address domain (SPF + DKIM DNS records), and the from-address itself in the Kratos courier values.
- Local value will point at Mailpit (t002/t003) — the local overlay, not `.env`, decides that.
