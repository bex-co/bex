## Objective

The write side of the Environment tab: an Edit affordance that lets a user add a variable, change a value, and remove a variable, wired to the mutations (`setEnvVar` for add/update-one, `deleteEnvVar` for remove; `setEnvVars` for a bulk replace-all Save). Refetch/update the keys list after a write, and surface that a write **rolls the service's pods** so the user knows the change is deploying.

## Context

- Depends on t003's table + t001's mutation hooks.
- bex-api semantics (docs/bex-api.md#env-vars): every write stores to OpenBao, materializes the `<service>-env` Secret, and rolls the pods via `spec.restartedAt` — unlike Render, bex has no separate deploy step, so the value goes live once the rollout completes. Reflect this ("changes are deploying…") rather than implying an instant apply.
- 403 on write (tuple-less key) → surface as a permission error, not a silent failure.
- Keep values out of any logging/telemetry the dashboard emits; the API already never returns values except on explicit reveal.

## Steps

1. Add an Edit mode (add-row, editable value, delete-row) over the t003 table.
2. Wire add/update to `setEnvVar` and delete to `deleteEnvVar` (or `setEnvVars` for a batched Save); refetch keys after.
3. Show a "changes are deploying / rolling out" affordance; surface write errors (403).
