# In a protected environment a Developer is offered a service's Shell, which the server refuses

Why: Render lets only Admins open a shell in a protected environment, so a Developer must see Shell disabled with Render's reason, not a terminal that fails to connect. Found by w4/m578 t005 on 2026-11-22.

- **What the code does:** `CreateShellSession` and the native SSH path refuse a non-Admin on a protected member with `requireUnprotected(ctx, a, "shell")` (`lego/backend/internal/apps/service.go`, w8/193). The dashboard's Shell tab (`dashboard/src/features/services/components/service-shell-page.tsx`, `web-shell-panel.tsx`) reads no role or protection answer, so it offers the terminal to a Developer there.
- **Not yet seen live:** dev-4 runs no SSH gateway (its agent leg is off), so on 2026-11-22 the Shell tab read "Shell access isn't available" for every role. Replay it where the gateway runs (dev-4 with the agent leg up, or production with a second QA identity) before fixing.
- **End state:** the Shell tab and the terminal's connect control read the verb's rule (`core.RestrictedDecision` for `shell`) and show _This action is limited to admins._ for a Developer in a protected environment, before any connection is attempted; an Admin connects. Tests cover both roles.
