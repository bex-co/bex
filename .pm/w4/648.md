# 648 — An isolation toggle converges the whole workspace namespace synchronously (~60–90 API calls inside the PATCH): converge only the hosting NetworkPolicies, and skip writes that change nothing

Why: w4/m342 made `PATCH /v1/environments/{id} {"networkIsolationEnabled":…}` (and environment/project delete, project create, Blueprint isolation changes) call `EnsureWorkspace` before answering, so the boundary holds the moment the API says it does. `EnsureWorkspace` re-applies the namespace, quotas, LimitRange, every policy and every RoleBinding, and `applyObject` writes each one unconditionally. The toggle only needs the hosting NetworkPolicies.

- **Source / severity / estimate:** `/loopx w4` closeout of w4/m342 (2026-11-14). **Minor** (latency and API-server load on a rare action). ~40m.
- **Fix:**
  - a `EnsureEnvironmentIsolation(ctx, workspaceID)` on `NamespaceReconciler` that converges only `allow-same-namespace` and the `isolate-<env>` boundaries, with the same write order (boundaries before narrowing, prune after widening);
  - `applyObject` skips the update when the managed labels and spec already match (semantic equality), so the periodic resync stops rewriting unchanged objects too.
- **Tests:** the toggle path issues no quota/RoleBinding writes; an unchanged object gets no Update; the w4/m342 ordering tests still pass.
- **DoD:** the isolation PATCH answers within the usual API latency on production, and w4/m342's DoD 2–3 still hold.
