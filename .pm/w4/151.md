# The dashboard shows Blueprint errors without the line, column, or path the API already returns

Why: `w8/019` made every surface report each validation error with its source line/column (ADR049: "source line/column when known"), but the dashboard never asks for `errorDetails`. Its three Blueprint error lists print only the flat string, so "Blueprint is not valid YAML" and "fromDatabase references unknown database …" arrive with no location in the one UI that is showing the manifest.

Found live, `/qa-find-bugs` pass 182, 2026-09-26 (w4-targeted, `muse.env` credentials), read-only via GraphQL `validateBlueprint` (nothing applied). Selecting `errorDetails { line column path error }` alongside `errors` for three manifests:

| manifest mistake                         | `errors` (what the dashboard shows)                                          | `errorDetails` (what the API also returns)      |
| ---------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------- |
| tab-indented list (`services:\n\t- …`)   | `Blueprint is not valid YAML`                                                | line 2, column 1, path `""`                     |
| `fromDatabase` naming a missing database | `fromDatabase references unknown database "qa-missing-db" in this workspace` | line 7, column 9, path `services[0].envVars[0]` |
| typo `healthCheckPth`                    | `at '/services/0': additional properties 'healthCheckPth' not allowed`       | line 6, column 21, path `services[0].healthCheckPth` |

The error content itself was good in all eight cases probed: unknown/typo fields, invalid `plan` (listing Render's spellings), missing `name`, invalid `type`, duplicate names (with the first declaration), a missing `fromDatabase` target, bad YAML, and a string where an integer is expected.

- **Root cause:** the dashboard's queries select only `validation { errors }`. `dashboard/src/features/blueprints/api/blueprints.graphql:60-64` (`ValidateBlueprint`) and the preview's `validation { valid errors … }` never request `errorDetails` (`lego/backend/internal/apps/graphql.go:978`). All three renderers print strings:
  - `features/blueprints/components/validate-panel.tsx:58` (the blueprint page's Validate panel)
  - `routes/blueprints.new.tsx:108,147` (New Blueprint review)
  - `routes/blueprints.$blueprintId.tsx:661` (Sync dialog)
- **Fix:** select `errorDetails` and render `line:column` (and `path` when present) with each message in all three places, ideally through one shared component. Fall back to the plain string when a detail has no position.

Estimate: ~30m.
