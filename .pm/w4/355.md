# `aclBearing` treats the default allow-all as admin-managed and deny-all as not

Why: whether a move needs an admin is decided by `environments.aclBearing`, which reads any non-empty IP allow-list as ACL-bearing. Every new environment is seeded with the allow-all pair, so in production every environment counts as admin-managed. An explicitly emptied list, which denies all traffic and is a real restriction, counts as unmanaged. Developers are refused moves that remove nothing, and could lift a deny-all freely.

- **Source:** `w4/m232` audit, 2026-10-19 (loopx w4). Reasoned from code; Hobby workspaces have only an admin, so it is not observable live there.
- **Path:**
  - `lego/backend/internal/environments/service.go` `aclBearing`: `len(e.IPAllowList) > 0`.
  - `store/environments.go` `CreateEnvironment` seeds `core.DefaultEnvironmentAllowList()` (`0.0.0.0/0`, `::/0`).
  - `core.EnvironmentLayerCIDRs` projects an empty list as `DenyAllCIDR`.
- **Effect:**
  - The round-22 target check (`SetServices`/`setResourceMembers` on an environment) and the w4/m232 exit check both require `can_manage` for every seeded environment.
  - The m232 DoD control ("a developer still moves resources between bare environments") holds only for environments whose list was emptied, which are deny-all, the opposite of bare.
  - The dashboard's Manage resources dialog mirrors `aclBearing` for its role-aware disable, and shows markers only for real restrictions.
- **Decision needed:** define ACL-bearing as protected, isolated, or an allow-list that restricts anything (not the default allow-all pair, and including the explicit deny-all). Update `aclBearing`, the dashboard's mirror (`features/environments/lib/placement.ts`) and the tests that build "bare" environments with an empty list. This changes an administrator boundary, so it needs an explicit decision rather than a drive-by fix (m232 put `aclBearing` out of scope).
- **Related divergence:** Render lets only admins move resources *into* a protected environment as well (render.com/docs/projects). bex gates moves out (w4/m232); moves in stay `can_create`, except env `SetServices` on an ACL-bearing target. Recorded in ADR018; decide together.
- **Estimate:** 45m once decided.

## 解除阻塞记录（2026-11-01，`/unblock w4`）

- **涉及：** w4/355
- 来源：用户决定（D1）+ 现有规则（Render parity：只有管理员能把资源移入受保护的 Environment，见 render.com/docs/projects，原条目已引用）。
- **结论：** “ACL-bearing（受管理）”= Environment 受保护，**或**拥有真正有限制的 IP 白名单。默认预置的 allow-all（`0.0.0.0/0`、`::/0`）不算限制；显式清空（deny-all）算限制。同时对齐 Render：移入受保护 Environment 仅限管理员。
- **取舍：** 开发者在普通 Environment 间移动资源恢复正常；真正受限的 Environment 仍需管理员。
- **worker 下一步：** 改 `environments/service.go` 的 `aclBearing`、dashboard 镜像 `features/environments/lib/placement.ts`，以及用空列表表示“bare”的测试；在 ADR018 记录“移入受保护”已对齐。补开发者/管理员两种角色的回归测试。
- **剩余阻塞：** 无。**验收：** 原 DoD 不变。
