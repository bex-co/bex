## Objective

For native runtimes, the build log carries the user's build in Render's shape:

- bex's existing `==>` narration;
- `==> Running build command '<cmd>'…`;
- the command's own output lines, unprefixed;
- `==> Build successful 🎉` or the failure line.

BuildKit's progress for bex's generated recipe stays out of the tenant log. Docker-runtime builds are unchanged.

## Context

- **Live, round 84.** The native Node build logs held:
  - 187 lines on success, of which 132 were `#N` and 81 held `sha256:`;
  - 179 lines on failure, of which 122 were `#N` and 58 held `sha256:`.
  - They exposed `mwader/static-ffmpeg`, `[context bex-init]`, `/opt/bex/pnpm.tgz`, `/opt/bex/load-env` and `RUN --mount=type=secret,id=render-env,…`.
  - npm's output read `#23 2.411 added 80 packages, …`.
- **The generated Dockerfile** is `lego/operator/internal/build/native.go:310-345` (`nativeDockerfile`). The user's step is the one `RUN --mount=type=secret,id=render-env,…`, which `buildkitNativeRunStep` (`lego/operator/internal/build/build.go:772`) already matches.
- **buildctl runs with BuildKit's default progress**, which is plain without a tty (`build.go:1063-1083`). The log shipper forwards the build pod's stdout verbatim (`deploy/gitops/base/log-shipper.yaml`, `build_pods`).
- **The narration contract** is in `docs/render-artifacts/live-deploy-following.md` § Platform progress-line contract. Update it with the new lines.

## Steps

1. **Pick the mechanism and record the choice** in ADR010's build-log section. Either:
   - `--progress=rawjson` translated in the build container, keeping only the user `RUN` vertex's log stream; or
   - a plain-progress filter keyed on that step's `#N`.
2. Emit `==> Running build command '<cmd>'…` with the configured command, never the loader, and `==> Build successful 🎉` when the build stage ends successfully.
3. **Errors outside the user's step still surface.** A failure in a toolchain fetch, cache import or tool layer emits one `==> …` line naming the phase and BuildKit's error line. w6/m123's "the log carries the failing phase's error" still holds.
4. Leave the Docker-runtime path (user Dockerfile) byte-identical.
