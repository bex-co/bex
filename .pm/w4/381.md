# 381 — Metrics percentage axes can label two gridlines with the same value ("0%, 1%, 1%")

Why: on a service using about 1% of its memory limit, the Memory chart's y-axis reads `0%`, `1%`, `1%`. Two different gridlines carry the same label, so the axis cannot be read. The formatter's own comment promises distinct ticks.

**Severity:** minor. **Estimate:** ~25m. **Source:** live `/qa-find-bugs w4` loop run s1h8, 2026-10-20 UTC, `muse.env`, workspace `bex-canary`, on pin `9cace6b6e25d`. Read-only on the long-lived `hello-go` (`srv-daif6dsmg29s73d1umvg`) Metrics tab, range Last 12 hours, Application Metrics in Raw + Percentage. Evidence: `.playwright-mcp/qa-metrics-s1h8-axis.png` (local).

## Probe

The first card's `svg text` nodes, in order, were `["0%","1%","1%","0%","0.147%","0.293%","0","0.5","1"]`. The Memory chart (first three) labels its midpoint and maximum gridlines both `1%`. The CPU chart (next three) is readable only because its values are below 0.5%.

## Root cause

- `svg-line-chart.tsx:355` places exactly three ticks: min, midpoint and max.
- Each tick is formatted by `formatMetricShort` (`dashboard/src/features/metrics/lib/format.ts:21-37`). For `percentage` that is `toFixedNonzero(value, 0)` (`:30-31`).
- `toFixedNonzero` (`:39-52`) adds precision only when a nonzero value would round to **zero**. A midpoint of about 0.7% and a maximum of about 1.4% both round to `1%`.
- The same collision can occur for `cpu` (2 decimals) and `bytes` (1 decimal) when the range is narrow relative to the precision.

## Fix (target behavior)

- The three tick labels of one axis are always distinct whenever their values differ.
- Choose the smallest decimal count, per axis, that makes the formatted min/mid/max unique (cap at about 3 significant digits). Pass it to the formatter for all three ticks so they share one precision.
- A flat series, where min = max, keeps a single label.
- Gutter sizing (`axisLeftPad`, `:356`) uses the final strings.
- Tooltips and legends are unchanged.

## Acceptance

- A unit test over the tick-label helper: `[0, 0.7, 1.4]` percentage → three distinct labels (e.g. `0%`, `0.7%`, `1.4%`). Today's ordinary magnitudes stay unchanged (`[0, 50, 100]` → `0%`, `50%`, `100%`). The same distinctness holds for cpu and bytes ranges.
- Live: `hello-go` Metrics, Memory Percentage shows three distinct y labels.
- Dashboard `yarn lint` and `yarn test` pass.
