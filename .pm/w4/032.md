# Release-staleness reminder cron + `bex-cli/v*` tag ruleset

From the 2026-08-15 release-engineering discussion (docs/ADR058-release-engineering.md); do after `w4/m35` ships. Originally this note also planned a `workflow_dispatch` one-click bump — superseded the same day by the `/release` skill (`.claude/skills/release/SKILL.md`), which computes/confirms the version, pushes the tag, watches `cli-release.yml`, and verifies every channel. Two pieces remain:

1. **Weekly staleness cron:** open/update an issue when `cli/**`, `scripts/bex-cli-*`, `scripts/install-bex*`, or `.github/workflows/cli-release.yml` have commits newer than the latest `bex-cli/v*` tag — so releasing depends on the reminder, not on memory.
2. **Tag ruleset:** restrict `*/v*` (at least `bex-cli/v*`) tag creation to maintainers/CI — pushing a Class 2 tag is a public release; everything should flow through `/release`.

Graduation (unchanged): release-please manifest mode when ≥2 versioned components or cadence justifies release PRs; verify slash tag-separator support first.
