# 553 — A Postgres created in the dashboard (or over GraphQL or MCP) has no external access by default, while Render opens every new database to `0.0.0.0/0`

Why: on Render, a new database's External Database URL works right away with its credentials, and the docs and tutorials assume that. A bex user who creates one from the dashboard gets an empty external URL until they discover the Public access switch. Only bex's REST create matches Render today.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 37, 2026-11-10 19:48–19:53 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor** (a Render-parity default on a visible control). ~50m.
- **Fixture:** Free Postgres `qa-20261110-pg37` (`dpg-dbpnadc5ngvc73e8u21g`), in project `qa-20261110-p37`, environment Staging. Deleted with the sudo-phrase dialog (GET 404).
- **Probe:**
  - On `/?new=database`, the New Postgres dialog shows `switch "Public access"` unchecked (`aria-checked=false`). I created the database with every default.
  - `GET /v1/postgres/dpg-dbpnadc5ngvc73e8u21g` → `"public":false,"ipAllowList":[]`.
  - `GET …/connection-info` → 200 with `externalConnectionString: ""`. I inspected only which keys were present, never their values.
  - Access control reads: "External connections are disabled. Save one or more IP rules to enable access."
- **Render:** [render.com/docs/postgresql-creating-connecting](https://render.com/docs/postgresql-creating-connecting), "Restricting external access": "By default, your Render Postgres instance is accessible from any IP address (if the connection uses valid credentials)." and "The default block is `0.0.0.0/0`". Render's dashboard create form has no access option.
- **Root cause:**
  - **Dashboard:** `dashboard/src/features/databases/components/create-database-dialog.tsx:104` starts with `useState(false)`. It is reset to false at `:161` and sent at `:182` as `public: isPublic`.
  - **GraphQL:** `createDatabase`'s optional `public` argument is read with `gqlutil.Bool`, so omission means false (`lego/backend/internal/postgres/graphql.go:549`, `:573`).
  - **MCP:** `create_postgres` declares `Public bool`, which "defaults to false on this create tool" (`postgres/mcp.go:73-74`).
  - **Only REST applies Render's default.** With `ipAllowList` omitted, the database is public with `0.0.0.0/0` + `::/0` (`postgres/rest.go:226-236`, w2/038). w8/157 made Blueprints do the same.
  - **The docs record the split without the user's sign-off.**
    - [ADR009](../../docs/ADR009-postgresql-management.md) line 284: "Native create defaults remain private".
    - [ADR018](../../docs/ADR018-render-parity.md) line 442: "GraphQL, MCP, Blueprints, dashboard callers … remain private by omission". It still lists Blueprints, which w8/157 changed.
    - w2/038 (2026-10-02) scoped the native paths out before the 2026-10-17/20 Render-parity-first rule, which says to amend such ADRs.
- **Fix (target behavior):**
  - Every Postgres create path resolves omission the way REST does: public, with explicit `0.0.0.0/0` + `::/0` rules carrying the "Allow all (default)" description (`lego/backend/internal/core/cidr.go:214-215`).
  - An explicit `public:false` or `ipAllowList: []` stays private.
  - Move the REST defaulting into the shared create path, so GraphQL, MCP and the dashboard all inherit it.
  - The dashboard switch defaults on, or the form drops it as Render's does. Its hint says the database accepts connections from any IP with valid credentials until restricted under Access control.
  - Update ADR009 line 284 and ADR018 line 442.
- **Adjacent class:** Key Value stays private by default. Render documents new Key Value instances as externally disabled (ADR021 line 52), and bex already matches.
- **Blast radius:**
  - `create-database-dialog.tsx` (1 caller);
  - GraphQL `createDatabase`;
  - MCP `create_postgres`;
  - the shared Core create verb, including dry-run previews.
  - Existing databases are not migrated.
  - Tests:
    - GraphQL and MCP omission → public, with both rules;
    - explicit false → private;
    - the dashboard default sends `public: true`.
- **Unverified:**
  - Whether Render's official MCP `create_postgres` passes an `ipAllowList`. It is expected to omit it and so get the REST default.
  - How a public store with no rules reads back is [w4/m315](m315/README.md)'s scope, not this note's.
- **Dedupe:**
  - w2/038 (done) covered REST only.
  - w8/157 (done) covered Blueprints.
  - w4/m315 (open) covers reads of public stores with no rules, not the create default.
  - No item covers the native create default.
  - Not deploy lag: `git log c12cd57facb1..origin/main` on `create-database-dialog.tsx` shows only w2/m307's pooling and storage changes, and the defaults in `graphql.go` and `mcp.go` are unchanged on main.
- **DoD (live):**
  - New Postgres with every default: REST reads `public:true`, with `ipAllowList` set to `0.0.0.0/0` + `::/0`, and the copied External Database URL connects.
  - GraphQL `createDatabase` and MCP `create_postgres` without `public` behave the same.
  - The switch off, or `public:false`, still gives `[]` and no external URL.
  - New Key Value stays private by default.
