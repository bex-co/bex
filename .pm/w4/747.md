# Managed Postgres, Key Value and registry image volumes are encrypted at rest, as Render's are

Why: Render parity. Render promises "minimum AES-256 encryption at rest for database systems and OCI images", for primary and replica Postgres instances and Key Value alike. bex encrypts service disks and backups, but its Postgres and Key Value volumes and the registry's images sit on unencrypted Hetzner volumes, and no ADR018 row says so.

- **Render (read 2026-11-27):** [hipaa-best-practices](https://render.com/docs/hipaa-best-practices): AES-256 at rest for database systems and OCI images; [postgresql-creating-connecting](https://render.com/docs/postgresql-creating-connecting) and [key-value](https://render.com/docs/key-value) say each instance's data is encrypted at rest.
- **bex:** Postgres and Key Value volumes use the plain `hcloud-volumes` class (`dbStorageClass` in `lego/operator/internal/controller/database_controller.go`, `kvStorageClass` in `keyvalue_controller.go`). `deploy/gitops/base/disk-storageclass.yaml` notes "Hetzner Cloud volumes are not encrypted by the provider" and adds LUKS only for service disks ([ADR082](../../docs/ADR082-persistent-disks.md) D3). The Zot registry's volume takes the default class (`deploy/gitops/base/zot.yaml`).
- **Do:** give new Postgres and Key Value volumes the LUKS class pattern service disks use (one passphrase Secret per volume, in OpenBao or the tenant namespace as ADR082 D3 does), put the registry on an encrypted volume, and plan the move of existing volumes (a CNPG replica on an encrypted volume, then a switchover; a Key Value restore). Record the row in ADR018 § Managed Postgres and § Other datastores & storage.
- **End state:** a new Postgres or Key Value instance's PVC uses an encrypted StorageClass, the registry's does too, and ADR018 states encryption at rest for each.
- **Size:** a milestone (new volumes, the migration of existing ones, the registry); promote it.
- **Source:** w4/m688 t002, a full read of Render's hipaa-best-practices page, 2026-11-27.
