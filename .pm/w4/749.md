# A platform or runtime vulnerability that needs customers to act gets a bex security advisory, on its docs and to each affected workspace, as Render's do

Why: Render parity. Render published four advisories in October and November 2026, each naming the affected services, the fixed versions and a cutoff after which a redeploy picks the fix up. bex patches the same runtimes, but its customers hear nothing, so a service that has not redeployed keeps the vulnerable version unannounced.

- **Render (read 2026-11-27):** [advisory-emudhra](https://render.com/docs/advisory-emudhra), [advisory-php2shell](https://render.com/docs/advisory-php2shell), [advisory-ruby2shell](https://render.com/docs/advisory-ruby2shell) and [advisory-upload2shell](https://render.com/docs/advisory-upload2shell); [shared-responsibility-model](https://render.com/docs/shared-responsibility-model) lists "transparency about … any security breaches" as Render's duty and following Render's security communications as the customer's.
- **bex:** status.bex.co covers operational status only. bex.co publishes no advisory page, and no repository item mentions any of Render's four advisories. The same fixes did land in bex (the Ruby lines in w3/m635, the Ghostscript and CA store updates in the common image), with no notice to anyone.
- **Do:** write the practice down: when a fix needs a redeploy (or bex rebuilds for the customer), publish an advisory page with the affected runtimes or services, the fixed versions and the cutoff, and email the owners of the affected workspaces through the notification path ([ADR052](../../docs/ADR052-notifications.md)). Publish the first one for the Ghostscript fix (`w4/750`).
- **End state:** a written advisory practice, one advisory published on bex.co's docs, and its email reaching the affected workspaces' owners.
- **Size:** about 1h for the practice and the first advisory; the email path may need its own item.
- **Source:** w4/m688 t002, full reads of Render's four security advisories, 2026-11-27.
