# 505 — A static site whose publish directory is missing still reports `build_ended` `succeeded` before its deploy closes `build_failed`

Why: w4/493 made a missing publish directory close the deploy `build_failed` with a plain reason, as Render does. The Events feed still carries `build_ended` with `status: "succeeded"` for the same deploy, because the build step ended before the publish step ran and `build_ended` is emitted once, on the first later phase.

- **Source / severity / estimate:** found while landing w4/493, 2026-11-05; **minor** (events consistency); ~40m.
- **Root cause:** `lego/backend/internal/store/reconciler.go` `buildEndedStatus` stamps `succeeded` for `DeployUpdateInProgress`, and the fact's `source_key` is `deploy:<id>:build_ended`, so the later `build_failed` pass cannot replace it. For a static site the publish step runs in that `update_in_progress` window.
- **Fix (target behavior):** for a static-site deploy, withhold `build_ended` until the publish outcome is known (`update_in_progress` stays "still building"; `live`/`update_failed`/pre-deploy report `succeeded`; `build_failed` reports `failed`). `buildLifecycleFacts` needs the service type from `DesiredApp`. Dating `build_ended` at the publish end matches Render, whose build includes the publish step.
- **Tests:** a static deploy that goes `update_in_progress` then `build_failed` emits one `build_ended` with `failed`; one that goes `update_in_progress` then `live` emits `succeeded`; docker/native deploys are unchanged.
- **Dedupe:** residual of w4/493 (`.pm/w4/done/493.md`).
