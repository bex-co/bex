# `POST /v1/services/{id}/suspend`, `/resume` and `/restart` answer with no body, as Render's do

Why: Render parity. Found by the w4/738 worker (2026-11-27) after it moved `/scale` to a bodiless 202.

- **bex:** the three lifecycle verbs are mounted with `s.restVerb(...)` (`lego/backend/internal/apps/rest.go:1017-1019`), which writes the service back as JSON on success: suspend 202, resume 202, restart 200, each with a body.
- **Render:** its OpenAPI spec gives these operations the same status codes (suspend 202, resume 202, restart 200) and no response body, as w4/738 read for `/scale`. Confirm against the pinned spec before changing code.
- **How w4/738 did it:** `/scale` now uses `core.HandleNoBody` (`lego/backend/internal/core/http.go`), as Postgres's verbs have since w4/697, keeping 400/404 JSON error bodies. GraphQL and MCP kept returning the service.
- **End state:** on success the three REST verbs answer their current status codes with an empty body, error answers keep their JSON bodies, GraphQL and MCP are unchanged, and a REST test fails against the old handler (as `TestRESTScaleService` does for `/scale`). The comment above `RegisterREST` (`rest.go:884-887`) says the bodies match too.
