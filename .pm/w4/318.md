# Keep parameter-editor headings inside the table scroller

Why: adding a Postgres parameter draft on a phone lets the entire page slide sideways because its hidden Actions heading escapes the local table scrollbar.

**Severity:** minor. The draft and table controls still work, but the page gains 247px of horizontal overflow and can pan its navigation and content offscreen. **Estimate:** 45m (caller/scroll audit 5m, local containment fix 5m, real-browser geometry checks and controls 20m, inline simplify 5m, live acceptance 10m). Filing only.

## Root and bounded fix

`dashboard/src/features/databases/components/parameter-overrides-editor.tsx:184` creates an unpositioned `overflow-x-auto` wrapper. At:198 its Actions column uses an absolutely positioned `sr-only` span. The nearest positioning context is outside the scroller, so that heading contributes root overflow even though the visible table scrolls locally. The live offset-parent reading and reversible wrapper trial corroborate this mechanism.

Make this **existing local scroll wrapper** a containing block, following the repository's shared Table precedent (`dashboard/src/common/components/ui/table.tsx:5–10`, `relative w-full overflow-x-auto`). Preserve the hidden heading and its accessible name, input sizes, observation text, table's own scrolling, and all draft/save/discard semantics. Do not hide the label, shrink the form into unreadable columns, clamp root overflow globally, or rewrite the table components.

**Consumer audit:** one production editor mount, `insights-panel.tsx:336`, under the sole database detail Insights section (`routes/databases.$databaseId.tsx:323`). The editor is shared by saved and unsaved parameter rows; the reproduced minimal case is an unsaved row. Top queries and effective parameters have separate scroll wrappers and no Actions heading; they do not need changes for this fix. API reads and writes are unchanged; no REST/GraphQL/MCP schema or backend fix is proposed.
