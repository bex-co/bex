# 473 — A deleted build source answers `204` but stays readable and listed until its finalizer finishes (minutes), unlike every other resource

Why: a script or the CLI that deletes a build source and then lists or reads it to confirm sees it still there and may retry the delete or report a failure. Every other bex resource (services since w3/m81, Postgres, Key Value) reads `404` the moment its delete is accepted, as on Render.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 10, 2026-11-04 ~13:00 UTC (`muse.env`, `bex-canary`, pin `9d4e3a138783`); **minor** (read-after-delete consistency); ~30m.
- **Probe** (from the dashboard page, `credentials:'include'`):
  - `DELETE /v1/build-sources/bds-dblik36g3pks73ck0iq0` → `204`. About 2 s later, `GET /v1/build-sources/bds-dblik36g3pks73ck0iq0` → **`200`**, and `GET /v1/build-sources?ownerId=tea-daif693dqjvc73e7as3g` still lists `qa-20261104-bsrc2`.
  - At 13:02:50 UTC, about 2 min later, the same GET → `404`.
  - **Control in the same call:** `DELETE /v1/services/srv-dblik3kncp7s738f12jg` → `204`, and `GET` → `404` immediately.
  - Round 9's build source (`bds-dbliae4ncp7s738f118g`) happened to read `404` within 2 s, so the window depends on how quickly the finalizer runs.
- **Root cause:** a build source is a carrier `App` (`core.IsBuildSource`, `core/build_source.go:36-38`) torn down by a finalizer after `Delete`.
  - Service reads hide a deleting App with `core.NotFoundIfDeleting(a)` (`apps/service.go:1474-1483`; helper `core/base.go:1506-1514`).
  - The build-source guard `core.BuildSourceOrNotFound` (`core/build_source.go:88-93`) checks only the type.
  - `ListBuildSources` (`apps/build_sources.go:310-330`) skips non-carriers but not deleting ones.
- **Fix:** make `BuildSourceOrNotFound` also return not-found for a carrier with a `DeletionTimestamp` (via `NotFoundIfDeleting`), and skip deleting carriers in `ListBuildSources`.
- **Blast radius:** the guard has 3 direct callers plus `BuildSourceScope` (`core/build_source.go:100-120`). Together they cover the build source's get, patch and delete (`apps/build_sources.go:261`), builds list/get/trigger (`deploys/build_sources.go:107`), its env vars and secret files (`secrets/staged.go:103`), and env-group links (`envgroups/rest.go:245,255`). All are reached by REST, GraphQL (`buildSource`, `buildSources`, `builds`, `triggerBuild`…) and the nine MCP tools through the same verbs. A second DELETE during teardown should then answer 404 as services do.
- **Adjacent classes:** a deleting build source should look exactly like a missing one (404, `not_found`) to every caller who can view it, and the usual 404 to callers who cannot. No new "deleting" state is exposed.
- **Tests:** a carrier App with a `DeletionTimestamp` reads 404 on get, builds and env routes and is absent from the list. A live carrier and a deleting service keep today's behavior.
- **Render:** Render's delete-build-source returns 204, and the build source is gone from reads.
- **Dedupe:** no `.pm` item mentions build sources together with `NotFoundIfDeleting` or `DeletionTimestamp`. w3/m81 fixed only services. w2/m254 and w2/m262 cover the build-source feature, not this. No DO_NOT_DO item applies.
