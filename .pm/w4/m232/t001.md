## Objective

List every Core verb that can change a service's, Postgres database's, Key Value instance's or env group's environment away from its current one, with its REST, GraphQL and MCP aliases. Then decide, per writer, where the source-environment check goes.

## Context

- Known writers (see [finding.md](finding.md)):
  - `environments/service.go:954` `SetServices`
  - `:1048` `setResourceMembers` (via `:316, :352, :384`)
  - `projects/service.go:570` `SetServices`
  - `projects/service.go:613-660` `SetDatabases`/`SetKeyValues`. These only change the project label; confirm whether `SetProjectID` clears an environment label.
  - `envgroups/service.go:653` `MoveEnvGroup`
- Store writers of `apps.environment_id`: `store/environments.go:196, 205` and `store/projects.go:196, 209-213`. Datastore and env-group labels are written by `postgres/service.go:1725,1734`, `keyvalue/service.go:662,671` and `envgroups/service.go:644`.
- Also check: create paths that take an `environmentId` (no source, but confirm), Blueprint apply/sync placement, and any per-resource update that accepts an environment.

## Steps

1. `rg` every caller of the store and label writers above, and of `ClearServiceEnvironmentLayer`. Map each to its public verbs on REST, GraphQL and MCP.
2. For each writer, record whether it can remove a member from an environment it was not called on.
3. Write the list into this file's Done note with counts. Pick one shared seam, for example a helper that takes the placement diff and authorizes every distinct ACL-bearing source, so the rule cannot be skipped by a new writer.
