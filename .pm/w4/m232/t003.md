## Objective

Before Save, the Manage resources dialog tells the user which checked resources will leave another environment, and which of those environments is protected or isolated. A developer sees why such a row cannot be moved instead of meeting a bare 403.

## Context

- `dashboard/src/features/environments/components/manage-resources-dialog.tsx` lists the whole workspace's services, databases, key values and env groups (`ResourceChecklist`) with only name and status. Live, the row read `qa-20261019-9d7581-web Running` while the service sat in protected `production`.
- Placement is already on each view (`environmentId`), and environments come from `useEnvironments`.
- Role-aware control precedent: ADR024's "Role-aware dashboard controls" (disable definitive denials with a localized, keyboard-reachable reason).

## Steps

1. Show each candidate's current environment, or "No environment", and a protected/isolated marker when that environment is ACL-bearing.
2. When Save would move checked resources out of other environments, list them in the footer ("Moves out of production: …") before Save.
3. Where the viewer lacks `can_manage`, disable checking a member of an ACL-bearing environment, giving the reason (role-aware controls). Still surface a server 403 with the existing refusal handling.
4. Add `en` and `zh` strings, and keep the dialog skeleton matching (AGENTS.md skeleton rule).

## Files

- `dashboard/src/features/environments/components/manage-resources-dialog.tsx`, `resource-checklist.tsx`, locales, tests

## Acceptance criteria

- [ ] A test renders a candidate in a protected environment with its environment name and marker, and the pre-Save move summary.
- [ ] Live (admin): the repro dialog shows "production" and the protected marker on the row, and the move summary before Save.
