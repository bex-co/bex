## Objective

Every writer t001 lists refuses a non-admin before any store or projection change when the write would take a resource out of an ACL-bearing environment. Admins and bare-environment moves are unchanged.

## Context

- `authorizeACLBearingMutation` (`environments/service.go:1131-1136`) runs a fresh `can_manage` on the workspace, and `aclBearing` (`:876-880`) means protected, isolated or a non-empty allow-list.
- Today it runs only on the environment being edited (`:970`, `:1063`) and in the teardown seams (`:841`, `:892`).
- The store diff (`core.ServicePlacementChange`, `EnvironmentFrom`/`EnvironmentTo`) is computed inside the transaction, so the check must be decided **before** the transaction from the current placement. Re-reading after the transaction would be too late, because the store write is the authoritative change (w6/m134).

## Steps

1. Add a shared check that, given the resources a write will place and the current placement of each, loads every distinct source environment other than the target and calls `authorizeACLBearingMutation` on each ACL-bearing one.
   - Read the current placement with the same store rows the write uses.
   - A concurrent move between the check and the write must not let an unchecked ACL-bearing source through. Either take the check inside the write's transaction, or re-verify `EnvironmentFrom` in the diff and roll back on mismatch. Say which, and why.
2. Call it from env `SetServices`, env `setResourceMembers`, project `SetServices` (omitted members and incoming foreign-project members), `MoveEnvGroup` and every further writer t001 found.
3. Keep refusal shapes: `ErrForbidden` → REST `403`, GraphQL error, MCP tool error. Do not reveal a source environment the caller cannot view.

## Acceptance criteria

- [ ] A developer cannot remove a member from an ACL-bearing environment through any listed writer, and nothing changes when refused.
- [ ] Admin moves and bare-environment developer moves behave exactly as before.
- [ ] Adding to an ACL-bearing environment stays `can_create`.

## Out of scope

- Requiring the protected confirmation phrase for moves (not part of the round-9/22 rule).
- Changing `aclBearing`.

**Done 2026-10-19 (loopx w4):** `loadExitGuard` reads the workspace's environments and the caller's fresh `can_manage` up front. The guard it returns needs neither the database nor OpenFGA, so the store calls it inside its transaction. An environment the load did not see counts as ACL-bearing (fail closed). Step 1's choice, by writer:
- Service setters: inside the transaction. Candidate rows are locked `FOR UPDATE` in name order, the UPDATEs touch only locked ids, and the guard runs on the diff before commit.
- Datastore setters: checked before the first write. The label write compares the observed source under the optimistic lock (`core.PlacementChanged` → `RESOURCE_PLACEMENT_CHANGED`).
- `MoveEnvGroup`: inside its metadata CAS.
- Blueprint: under `SetAppEnvironment`'s row lock, or an optimistically locked datastore patch.
- Reclaim: counts env groups as members and locks the environment across the count and the delete.

Refusals are `core.ErrForbidden` (`FORBIDDEN`, `core/errors.go:115`), which every transport maps to 403, a GraphQL error and an MCP tool error. Wiring is in `api/server.go` (`environments.ExitGuards`). Recorded in ADR084 finding 3, follow-up.
