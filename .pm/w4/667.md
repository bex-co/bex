# 667 — An environment "Save and deploy" on a Git-backed service still replaces the deploy in progress, and picks the build that served at save time

Why: under Render's default Overlapping Deploy Policy, **Wait**, the deploy in progress finishes before "the most recently triggered deploy" runs ([render.com/docs/deploys](https://render.com/docs/deploys)). A "Save and deploy" of environment variables on a Git-backed service deploys without rebuilding. bex writes that deploy as a selection of the build serving at save time (`spec.releaseConfig`), and the operator lets a newer selection override the release in flight.

- **Source / severity / estimate:** `/loopx w4` closeout of w4/661 (2026-11-14), recorded open in ADR018's List / get deploy objects row. **Minor** (the final state is the newest request, as under Override, but it can run an older build). ~2h.
- **Gap, from the code:**
  - `secrets/batch.go` (`SaveModeDeploy`): `servedArtifact` reads the newest `live` row's resolved image and writes `ReleaseConfigReference{Generation: a.Generation + 1, Image: …}` with the save.
  - `heldReleaseView` (`lego/operator/internal/controller/release_view.go`) gives no view when the saved spec selects a newer release than the one in flight, so the source build or Rollback in flight is replaced.
  - Holding it behind the pin instead (drop that rule) would let the build in flight go live and then roll the older served build back over it, because the image is fixed at save time.
- **Fix (target):** resolve a "Save and deploy"'s build when its release starts, not when it is saved. Either hold it at the row level like a Rollback (w4/652's deferred deploy, re-reading the served build when it runs), or let the operator pin and have the selection name "the build serving when this release starts". Then the env save behind a deploy in progress waits, and runs the build that deploy left serving.
- **Tests:** an env "Save and deploy" behind a source build rolling out waits for it to go `live`, then runs the new build with the new env; behind nothing it deploys at once, as today.
- **DoD (live):** on a Free repo-backed service, push a commit, and while its deploy reads `build_in_progress` save an env var with "Save and deploy": the push's deploy goes `live`, then the env deploy runs on the pushed build. Delete the fixture.
