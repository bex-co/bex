# Padding an unchanged port starts unnecessary deployments

Why: typing a different spelling of the current numeric port enables Save and rolls a healthy service even though its port does not change.

**Severity:** minor; no outage observed. **Estimate:** 35m (trace 5m, row fix 5m, tests 10m, live controls/parity 10m, simplify 5m). Source: continuous functional `$qa-find-bugs`, user-directed w4, 2026-10-12 a294. Filing only.

## Reproduction and controls

Create an owned Free image web service listening on `$PORT`, port 3000. In fresh Settings → Edit Port:

- `3000` disables Save. Equivalent `03000` and `003000` enable it.
- Save `03000` at desktop: actual `SetPort` request carries integer 3000, returns 3000, and toasts “Port updated. A new deploy is rolling out.” The new deploy `dep-db6kd795i38c73fd5lr0` reaches Live at 20:44:34.541263Z, revision changes from rev-1 to rev-2, port remains 3000.
- Fresh 390×844 reload, save `003000`: another integer-3000 request succeeds; `dep-db6kdnh2s0sc73a8hihg` reaches Live at 20:45:34.516769Z, rev-3, port still 3000.
- Real `3000 → 3001` Save sends integer 3001; `dep-db6ke115i38c73fd5ls0` reaches Live at 20:46:21.706955Z, rev-4, port 3001, public GET remains 200 with the fixture marker. Editing back to 3000 and Cancel preserves 3001.
- Invalid 1023, 65536 and blank inputs show the range error and disable Save. The adjacent max-shutdown row correctly disables Save for `030` when its value is 30.

The two numeric-equivalent saves create actual deployments, not merely misleading toast text. Native responses captured before and during/after the checked rollouts were 200; no downtime is claimed.

## Root cause and bounded fix

`dashboard/src/features/services/components/service-port-row.tsx:29–57` passes a string value to the generic row, validates via `parsePort`, and saves its parsed number, but supplies no numeric `dirty` predicate. `editable-field-row.tsx:152–157` therefore compares normalized strings; `"03000" !== "3000"` enables Save, while `lib/port.ts:23–29` converts the accepted input to the same integer.

Use a **port-row-local** parsed-value comparison: a valid draft is dirty only when its parsed port differs from the persisted numeric port. Preserve valid input when the current port is absent, range errors, Cancel, busy state and real changes. The adjacent implementation at `max-shutdown-delay-row.tsx:34–42` demonstrates numeric-equivalence handling. Do not change the generic text row or remove leading-zero acceptance from `parsePort`.

The downstream mutation really restarts: `hooks/use-port.ts:19–29` passes the integer through `useFieldMutation` (:58–64) and the backend `lego/backend/internal/apps/service.go:4444–4448` stamps restartedAt when SetPort runs. Keep this API behavior, including explicit image port-mode configuration, intact; the fix prevents an unintended dashboard dispatch.

Exhaustive production search: **one ServicePortRow implementation, one hook consumer, one Settings mount** (`routes/services.$serviceId.settings.tsx:292–305`), shared by web/private across source modes. `/web/<id>/settings` and `/pserv/<id>/settings` redirect through `common/lib/render-alias.ts:13–17,58–70`; these aliases were traced, not separately replayed. Cron, worker, static, Postgres and Key Value do not mount this row. The unchanged shared parser has five production calls: wizard validation, two create-input calls, and this row's validation/save; create remains able to canonicalize valid padded input.
