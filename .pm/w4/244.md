# Key Value names push the status badge off the mobile page

Why: a valid datastore name can clip its lifecycle status on a phone even though the title already declares truncation.

**Severity:** minor. **Estimate:** 55m (audit 10m, local containment 15m, browser verification 20m, simplify/checks/closeout 10m). Functional `$qa-find-bugs w4`, 2026-10-10 pass a122; filing only.

## Reproduction and target

1. Create an owned Free private Key Value, then wait for Available. This fixture was `red-db5co7sjunsc73f11co0`, initially `qa-20261010-a122-kv-settings`.
2. At **390×844**, its original 28-character name plus Suspended badge made the page **390px client / 399px scroll**. The badge ended at **x398.84375**. A fresh reload reproduced it.
3. Resume, wait for Available, and rename through Details to **`qa-20261010-a122-cache-primary`**. This is exactly **30 characters**, accepted by both the form and mutation below. An earlier 48-character draft was correctly refused; that invalid draft is not evidence for this finding.
4. Fresh-load `/keyvalue/<id>`, wait for the named heading, and allow the layout to settle. The header is x0–390, but its name/status row is **400.1875px** wide, x16–416.1875. The Available badge is x346.640625–416.1875, partly beyond the viewport. The document is **390 / 416**; the name has no ellipsis because its own width equals its intrinsic width.
5. **Desktop control:** the exact saved name/status fits at **1440×1000**, document 1440 / 1440, row x280–680.1875.

No product source was edited.

**Target:** on these mobile reproductions, keep the complete current status inside the header's padded width; truncate the name when necessary while retaining its full accessible heading text. Keep the desktop name/status readable, the existing status semantics, and section-navigation scrolling. Do not hide page overflow to conceal the clipped badge.

## Cause, fix and audit

- `dashboard/src/routes/keyvalue.$keyValueId.tsx:118–126`: the outer header wraps flex items, but its inner name/status flex row has automatic minimum width and no maximum width. That row can keep its content width beyond the header. The h1's `truncate` at :122 only helps once the containing row gives it a smaller available width.
- Consumer: `features/keyvalue/components/key-value-status-badge.tsx:15–22` renders the derived translated status through the shared Badge. `common/components/ui/badge.tsx:8` intentionally keeps the badge nonshrinking and unwrapped. Preserve that behavior; give the name/status row an explicit zero minimum and viewport-relative maximum instead. The tested `min-w-0 max-w-full` on the local row expresses the successful control. Keep the pending title row (:128–134) structurally bounded as well.
- Framework check: the installed **Tailwind 4.1.18** compiler was run on these four classes. It emits `truncate` as overflow hidden / ellipsis / nowrap, `min-w-0` as a zero minimum width, `max-w-full` as 100%, and `shrink-0` as flex-shrink:0. The observed row's computed minimum is auto and maximum is none. [CSS Flexbox §4.5](https://www.w3.org/TR/css-flexbox-1/#min-size-auto) explains the content-based automatic minimum of a non-scrollable flex item. This mechanism agrees with the reversible browser control.
- Exact production census: **three KeyValueStatusBadge JSX mounts**: this route (:125), project `resource-table.tsx:319`, and environment `manage-resources-dialog.tsx:197`. Scope the change to the route row; leave the two other badge hosts and shared Badge unchanged. The canonical destination is `/keyvalue/$keyValueId`; `routes/r.$.tsx:7–10` and `common/lib/render-alias.ts:19` redirect the Render `/r/<id>` alias there.
- **Postgres sibling is source-traced, not live-proven:** `routes/databases.$databaseId.tsx:156–160` has an independently declared equivalent row plus an outer action button. DatabaseStatusBadge also has three production mounts: detail, project table and environment picker. Audit it with a new owned fixture before expanding this fix; do not infer its action/wrapping geometry from the Key Value capture. Web/static/cron/worker/private use the separate ServiceDetailHeader, whose title host already has `min-w-0 flex-wrap` at :119. No live claim is made for those families.

Implementation verification: repeat the accepted-name reload at 390px and the 1440px control; include the observed Available/Suspended states, a short name, the redirect alias, and pending/ready headers side by side at both widths. Verify full accessible heading text and status text, no document overflow, and retained section scrolling. Use actual browser geometry rather than a test that only asserts a class string. Apply /simplify and relevant dashboard checks; no API/schema change is required.

**Unverified:** Postgres, other service headers, live alias navigation, pending-header geometry, Chinese, other phone widths/touch gestures, cache commands/data retention, production Pod inventory, and authenticated Render pixel layout. The verified Key Value settings/lifecycle controls are not proof of those contracts.
