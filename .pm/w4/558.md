# 558 — A service can add its own `<slug>.onbex.co` platform host as a custom domain, which then stays Pending forever with DNS instructions to CNAME the name to itself in the onbex.co zone

Why: the claim can never verify, and the instructions tell the customer to edit a zone they don't control. The product accepts an impossible custom domain and shows it as an ordinary pending one.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 52, 2026-11-10 23:22–23:30 UTC (`muse.env`, workspace `bex-canary`, pin `a0d5802594e9`). **Minor**: an impossible claim with impossible instructions; serving is unaffected. ~25m.
- **Fixture:** Free image service `qa-20261110-cd52` (`srv-dbpqelthi5vc738gita0`, `nginx:1.27-alpine`). Deleted afterwards.
- **Probe:**
  - **The add is accepted.** Settings → Add Custom Domain → `qa-20261110-cd52.onbex.co` gives the toast "Added qa-20261110-cd52.onbex.co — DNS and the TLS certificate propagate in the background."
  - **REST stores a normal pending claim.** `GET /v1/services/{id}/custom-domains` returns `{"name":"qa-20261110-cd52.onbex.co","domainType":"subdomain","verificationStatus":"unverified","certificateStatus":"pending","dnsRecord":{"type":"CNAME","name":"qa-20261110-cd52","value":"qa-20261110-cd52.onbex.co"}}`.
  - **The DNS setup row is impossible to follow.** It reads "Create this record in the onbex.co zone at your DNS provider … CNAME qa-20261110-cd52 → qa-20261110-cd52.onbex.co": a zone the customer can't edit, with the name pointing at itself.
  - **It never verifies.** `POST …/custom-domains/qa-20261110-cd52.onbex.co/verify` returns 202, and 20 s later the claim is still unverified and pending.
- **Controls:**
  - `https://QA-…/`, `qa 20261110.example.com` and `localhost` are refused inline: "Enter a valid domain".
  - `qa-20261110-cd52.example.com` adds normally, with the "Domain added — set up DNS" dialog.
  - After deleting both claims, the platform URL still served 200.
  - Another service's `<x>.onbex.co` is refused by `reservedHost`. I read this from the code and didn't try a foreign platform host.
- **Root cause:**
  - **The own host is exempt from the reserved-host check.** `lego/backend/internal/apps/domains.go:946-957` (`reservedHost`) reserves every `*.<base>` host "unless it's this App's own auto host" (`ownPlatformHost`, `:921-932`).
  - **The AddDomain verb inherits that exemption.** `addOne` (`:1500`, `:1540`) applies `reservedHost`, so the own auto host passes into a managed claim.
  - **Why the exemption exists.** w7/m6 decided it (t002/t006: "the requesting App's own auto host … still succeed(s)"), so that a create or Blueprint re-stating legacy `spec.hosts` isn't rejected for its own host.
    - That path is `ensureHostsClaimable`/`previewHostsClaimable` (`:1317-1365`), used by `service.go:2362`, `service.go:2845` and `deploy.go:3796`.
  - **The file already names this outcome as the reason to reserve a host.** The comment on `platformHostReserved` (`:959-964`): "never verifiable and only produces a pending domain with nonsense DNS instructions".
- **Fix (target behavior):**
  - **The AddDomain verb refuses the service's own `<slug>.<base>`.** This covers REST `POST …/custom-domains`, GraphQL, MCP and the dashboard dialog.
    - Use a typed 400 that says the name is already this service's platform subdomain, e.g. code `CUSTOM_DOMAIN_PLATFORM_HOST`.
    - Show the message in the dialog, in en and zh.
  - **The create/Blueprint path stays idempotent.** `ensureHostsClaimable` keeps its legacy exemption, or silently drops the own host.
  - **Existing own-host claims** are cleaned up, or listed truthfully.
  - **Tests:**
    - AddDomain refuses the service's own host.
    - A Blueprint re-apply with the own host in `hosts` still succeeds.
    - A foreign `*.<base>` host is still refused.
- **Render:** the code comment and w7/m6 say Render reserves `*.onrender.com`. Whether Render refuses a service's own `onrender.com` host as a custom domain is unverified.
- **Dedupe:**
  - w7/m6 (done) introduced the exemption.
  - w5/m121 (done) covers public-suffix validation.
  - w2/m85 (done) covers TLS for unknown `*.onbex.co` hosts.
  - No open item.
  - Not deploy lag: `git log c12cd57facb1..origin/main` on `domains.go` is empty.
- **DoD (live):**
  - On an owned service, Add Custom Domain with its own `<slug>.onbex.co` is refused inline with the platform-subdomain message, in en and zh, and no claim row is created.
  - Adding an external host still works.
  - The platform URL keeps serving.
