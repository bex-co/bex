# The Disk tab (and Shell/Slug labels) render in English under the Chinese locale

Why: switching the dashboard to 中文 leaves the whole Disk feature (tab title, description, empty state, paid-plan notice, add/resize/delete/restore dialogs, every validation message) in English. The zh catalog holds the English strings verbatim, and the parity test only checks that keys exist.

- **Severity:** minor (i18n gap on a hosting surface).
- **Repro (loop50, 2026-10-05, pin `c7afefad5`, read-only):** open `https://dashboard.bex.co/services/<any free web service>/disk?lang=zh`. The page title localizes (`Web 服务`), but the main region reads "Disk", "Attach an SSD to persist your service's filesystem data across deploys…", "No disk attached", "Disks require a paid instance type. Upgrade this service's plan to attach one.", "Add Disk". The same sweep over events/deploys/settings/env/scaling/metrics/logs/plan/shell found only the header "Slug" label and the Shell page title "Shell" untranslated (plan tier names and server-supplied text excluded).
- **Root cause:**
  - `dashboard/src/features/services/locales/zh.ts` ≈ lines 3300–3400: every `services.disk*` message is a byte-for-byte copy of `en.ts`.
  - A scan of all `dashboard/src/features/*/locales/zh.ts` against their `en.ts` (multi-word English sentences, placeholders excluded) finds **37** such entries, all in `services`. Every other feature catalog is translated. The full identical set (69 including placeholders and product names) also includes `services.navDisk`, `services.diskTitle`, `services.navShell`, `services.shellTitle`, `services.shellWebTitle` and `services.colSlug`.
  - Introduced with the Disk feature in `691c1f52f` (w1/m86, 2026-08-23).
  - `dashboard/src/i18n/__tests__/locale-parity.test.ts` asserts key presence and parity only, so an English value in zh passes.
- **Fix:**
  - Translate the `services.disk*` family plus `navDisk`/`navShell`/`shellTitle`/`shellWebTitle`/`colSlug` in `zh.ts`. Placeholders, runtime and product names (`Node`, `Docker`, `npm run build`, `{size} GB`) stay as they are.
  - Add a parity guard: a zh message identical to en that contains a multi-word English sentence fails, unless the key is on an explicit allowlist (placeholders and brand names). That stops the next feature from shipping English into zh.
- **Blast radius:** dashboard only. REST/GraphQL/MCP are unaffected.
- **Unverified:** the disk add/resize/restore dialogs themselves; they are paid-only, so only the free-plan view was rendered. Their strings come from the same identical keys.
- **Render:** n/a (Render has no zh UI); repo rule: every user-facing string ships en + zh.
- **Estimate:** ~45m.
