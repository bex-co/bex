## Objective

Resolve the session's Python where both inputs are visible, the environment and the checked-out session branch, and make it the default before any setup step runs: in session mode after `ensureRepo` (`lego/agent-image/driver/src/main.ts` ~:64, ahead of `session.ts` ~:381-397), in snapshot builds before the steps (`build.ts` ~:97-100), and again in a session booted from a snapshot (its branch can differ from the one built).

## Context

- Repository files exist only after the clone; bex-api sees secrets but no files, and snapshot builds run only for repositories with setup steps (ADR111), so neither can decide alone.
- Default names (`python`, `python3`, `pip`, `pip3`) go in a driver-owned `/opt/bex-python/bin`, first on `PATH`; versioned names stay in `/usr/local/bin`; `/usr/bin/python3` stays Debian's 3.11.
- uv: with its default `python-preference = "managed"`, uv prefers an existing managed install but uses a compatible `python3.X` on `PATH` before downloading; `only-managed` always downloads. bex must set no global `UV_PYTHON*` variable, so a repository's own uv settings decide.

## Steps

1. Add `python-select.ts`: call `agent-toolchain`, repoint `/opt/bex-python/bin`, narrate `==> Using Python <version> (from <source>)` as a transcript step.
2. An unsupported request fails setup with `AGENT_SESSION_SETUP_FAILED` naming the version.
3. Wire it into session, build and prebuilt modes.

## Files

- `lego/agent-image/driver/src/python-select.ts` (new), `main.ts`, `session.ts`, `build.ts`, tests

## Acceptance criteria

- [x] Driver tests: `.python-version` `3.13` → 3.13 on `PATH`; `PYTHON_VERSION` beats the file; nothing → the dated default; `2.7.18` → named setup failure.
- [x] A setup step's `python3 --version` reports the selected version.
