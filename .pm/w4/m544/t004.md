## Objective

Carry the reviewed patch of each bookworm Python line (3.8 to 3.15) in the agent image, copied from the same digest-pinned official images the native build uses, so selecting a line costs nothing at session start and works on every network tier. The official builds link GNU readline (`readline.so` → `libreadline.so.8`); python-build-standalone links libedit and is not a substitute.

## Context

- Today one line is baked: `COPY --link --from=python-312 …` (`lego/agent-image/Dockerfile` ~:259-262, ARG ~:6), plus Debian's 3.11 as `/usr/bin/python3` (check ~:289).
- Measured (amd64, slim-bookworm Python layer, compressed): 3.11 16.0 MB, 3.12 13.7 MB, 3.13 12.6 MB (36.9 MB on disk), 3.14 13.1 MB (38.4 MB). Eight lines add roughly 110 MB compressed; the image already carries about 3.4 GB of Go cache (`lego/agent-image/README.md`).
- The official layout is relocatable for this purpose: RPATH `$ORIGIN/../lib`, `pip3.X` shebang `#!/usr/local/bin/python3.X`.
- 3.7 exists only on bullseye and needs OpenSSL 1.1, which bookworm lacks: refuse it by name (t005) rather than bake it.

## Steps

1. Add one stage per line, pinned to the digest `types/toolchains` names; copy `python3.X`, `pip3.X`, `libpython3.X.so*`, `lib/python3.X` and `include/python3.X`.
2. Add a drift test that fails when the Dockerfile's versions differ from `types/toolchains`.
3. Record the image size change in the commit message and README.

## Files

- `lego/agent-image/Dockerfile`, a drift test (Go or the image check), `lego/agent-image/README.md`

## Acceptance criteria

- [ ] In the built image, each `python3.X --version` equals the table's patch.
- [ ] `python3.X -c 'import readline; print(readline.backend)'` prints `readline` on 3.13+; on older lines `"libedit" not in readline.__doc__`.
- [ ] `ssl`, `sqlite3`, `ctypes`, `venv` and `pip` import and run on every line.
- [ ] The drift test fails when one ARG is changed by hand.

## Out of scope

- Selecting which line is `python3` (t005).
