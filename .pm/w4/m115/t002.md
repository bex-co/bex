## Objective

Even when a row is legitimately hidden, Insights explains instead of printing Postgres's raw mask literal 34 times.

## Context

- Same pass as t001: the dashboard rendered `<insufficient privilege>` verbatim in every Query cell with no hint, empty state, or tooltip.
- The Recovery section on the same page is the pattern to follow: "Backups aren't enabled for this plan, so recovery isn't available…" — honest, specific, actionable.
- After t001 the fully-masked case should be unreachable for owners, but partial masking stays possible (e.g. a non-owner viewer role, future least-privilege tightening) — the UI must degrade, not leak mask literals.

## Fix shape

- In `insights-panel.tsx` (copy in `features/databases/locales/en.ts`): detect masked query/user cells (exact `<insufficient privilege>` literal from the API) and render an explanatory row/section note instead — e.g. "Some sessions belong to other roles and are hidden." Keep unmasked rows visible (partial render, not whole-section hide).
- Prefer a typed signal if the backend can cheaply send one (e.g. `masked: true` on the view); string-matching the Postgres literal is acceptable only with a comment pinning the PG behavior + version range.

## Files

- `dashboard/src/features/databases/components/insights-panel.tsx`
- `dashboard/src/features/databases/locales/en.ts`
