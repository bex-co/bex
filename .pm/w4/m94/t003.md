## Objective

Audit the shared static serving handler so fixing precedence does not disguise origin failures, bypass bounded fetching, or break callers that already work.

Production grep at 4e6bd00ff: staticserver.New has one registration, `cmd/staticserver/main.go:166`, behind the shared host resolver. matchRoutes has one production call in ServeHTTP; applyHeaders has two (redirect and success). Both fixes apply globally to static sites only; web/private/worker/cron/Postgres/Key Value do not use this handler. Host aliases/custom domains resolve into the same static Site, although only the onbex.co host was probed.

API aliases: SetRoutes has three adapter callers (`apps/rest.go:1128`, `graphql.go:1624`, `mcp.go:933`); SetHeaders likewise (`rest.go:1142`, `graphql.go:1634`, `mcp.go:955`). Names are PUT /v1/services/{id}/routes and /headers, setStaticRoutes/setStaticHeaders, update_static_routes/update_static_headers; static create/Blueprint paths also supply these App spec fields. Dashboard use-static-site.ts dispatches both; /services/$serviceId and /static/$serviceId header/redirect route aliases share the editors. The public serving fix must work regardless of writer.

Read S3Origin.Get/isNotFound (`s3origin.go:90-140`): only typed NoSuchKey/NotFound or the enumerated S3 codes map to ErrNotFound; access denial and timeout propagate as origin failures. The current handler distinguishes unknown host404, method405, missing object404, oversize413, overload503+Retry-After, and other origin failure502. Preserve these classes when adding the first lookup; never fall through to redirect/SPA on permission denial, timeout or capacity failure. Keep long-key rejection before network work and safeRedirectTarget after wildcard expansion. Do not introduce an existence oracle outside the resolved public site.

Preserve no-rule implicit extensionless fallback, missing asset404, ordered rules on misses, literal/wildcard redirects, HEAD semantics, original request-path custom headers, revision-keyed cache, singleflight, origin budgets and live-body leases. Before a changed rule snapshot arrives, the previous valid snapshot serves; after refresh, apply the new rule set without rebuilding or blank intermediate content.

## Acceptance criteria

- [ ] Global-static scope and all named aliases are accounted for, with no unrelated API/schema/auth changes.
- [ ] Required origin failure classes and resource limits remain distinguishable and tested.
