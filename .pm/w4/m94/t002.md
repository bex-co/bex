## Objective

Custom response header patterns match the visitor's normalized request path, independent of the object selected by a rewrite. Keep MIME/cache defaults tied to the served object.

## Repro and evidence

Use t001's Live site and wildcard rewrite. Open Headers → Add header twice, then save:

- Path `/qa-route`, Name `X-QA-Path`, Value `request-path`.
- Path `/*`, Name `X-QA-All`, Value `all-paths`.

Fresh page load retains both entries; exact API read and complete response are in t001. `curl -sSI https://qa-20260906-staticrules.onbex.co/qa-route` at 21:47:53 PDT returned HTTP/2 200, Cache-Control public, max-age=0, must-revalidate, Content-Type text/html, X-QA-All all-paths, but **no X-QA-Path**. With routes cleared using t001's exact mutation, the same request at 21:48:37 returned the same HTML defaults and **both headers**. Restoring the wildcard rewrite and freshly reloading the Headers UI reproduced the omission at 21:49:04. Header values did not change. `.playwright-mcp/qa-static-headers-1.png` shows the saved exact-path and wildcard controls; it does not alone prove the missing HTTP header.

## Root cause and target behavior

`lego/operator/internal/staticserver/staticserver.go:191-194` overwrites reqPath with the rewrite destination; `:251` then passes that rewritten path to applyHeaders. applyHeaders (:396-403) correctly matches the path it receives, so changing the matcher would target the wrong layer. In the no-explicit-rule control, spaFallback sets servedPath=/index.html but leaves reqPath=/qa-route, explaining why that control works for the expected reason.

Keep an immutable requestPath and use it for both applyHeaders calls (:188 redirect and :251 success). Use a separate lookup/served path for origin keys, MIME type and default cache policy. Preserve current last-matching-header behavior and header validation; do not duplicate the rule onto every possible destination. [Render documents request-path matching](https://render.com/docs/static-site-headers); exact rewritten-path behavior was not exercised on an authenticated Render site.

Major: saved header configuration is silently omitted on rewritten pages. Only harmless X-QA headers were tested; security-header impact is reasoned from shared plumbing, not a separately confirmed vulnerability. No new error-response header policy is requested: preserve existing failure responses and API authorization.

## Acceptance criteria

- [ ] The wildcard rewrite and no-rule controls both emit both saved headers for GET/HEAD /qa-route while serving the same HTML.
- [ ] A header scoped only to /index.html is not incorrectly applied to a request for /qa-route merely because its content is rewritten there.
