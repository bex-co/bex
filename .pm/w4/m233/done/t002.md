## Objective

After a Key Value has had external access once, saving an empty allowlist and later re-allowing an address changes no pod-template field. Access is still refused while external access is off.

## Steps

1. Separate "the store has a TLS identity" from "external access is open". Keep the Certificate, the Secret and the TLS listener args/port/volume once issued. Gate on the proxy's routing and allowlist check and on the Service's TLS port, per t001.
2. Leave the pod-template inputs that legitimately restart unchanged (plan, persistence, maxmemory, version).
3. Keep the existing rollout for stores that have never been public. The first enable still rolls the pod once (t003 announces it).
4. Update `docs/ADR021-keyvalue-management.md` §External URL with the new lifecycle.

## Files

- `lego/operator/internal/controller/keyvalue_controller.go` and its tests
- possibly `cmd/kv-sni-proxy`
- `docs/ADR021-keyvalue-management.md`

## Acceptance criteria

- [ ] An envtest or controller test shows that toggling `spec.public` true→false→true after the first issuance leaves the StatefulSet pod template hash unchanged.
- [ ] A proxy test (or existing coverage) shows a non-public store is refused at the front door.
- [ ] A first enable still produces exactly one rollout.

## Out of scope

- Removing TLS from stores that were never public.

**Done 2026-10-19 (loopx w4):**
- **Listener decision.** `keyValueIntent.tlsListener = public || (listening && BEX_KV_DOMAIN set && !suspended)`. `listening` is true when the StatefulSet's template already mounts the TLS volume (`keyValueTemplateListens`), or when `status.tlsListener` says so (a cached read can lag a first enable). It drives the server args, port and mount.
- **Certificate.** `reconcileKeyValueTLS` keeps the Certificate while the listener runs. A private store leaves it as issued (cert-manager renews it), so a TLS fault cannot stall the store's other reconciles.
- **Unchanged gates.** The Service's 6380 port and `status.externalHost` still follow `public`, and the kv-sni-proxy still routes only public stores.
- **Status.** The new `status.tlsListener` (types plus the CRD) reports the listener.
- **Suspend.** A suspended private store drops the listener, since no process runs to restart.
- **Tests.**
  - `TestKeyValueExternalToggleKeepsThePodTemplate`: off → on leaves the template byte-identical and the Certificate in place.
  - `TestKeyValueFirstExternalEnableAddsTheListener`: the first enable adds the listener; private again it needs no issuer; suspended it drops the listener.
  - `TestKeyValueKeepsAListenerItsStatusReports`.
