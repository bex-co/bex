## Objective

Know every path that turns a Key Value's external access on or off, and whether each one rolls the Valkey pod. Choose the operator design that makes later toggles restart-free without weakening the IP gate. Settle whether the Postgres card has the same problem.

## Context

- Writers known so far ([finding.md](finding.md)):
  - `keyvalue/service.go:716` `SetIPAllowList` → `UpdateKeyValue`
  - REST `PATCH /v1/key-value/{id}` and the allowlist route
  - GraphQL `setKeyValueIpAllowList` and `setKeyValuePublic` (`graphql.go:258-280`)
  - MCP `update_key_value`
  - create with `public`
  - `SetEnvironmentIPAllowList` (`service.go:646`)
- Pod-template coupling: `operator/internal/controller/keyvalue_controller.go:711, 866-879`. The certificate is deleted when not public (`reconcileKeyValueTLS`). The proxy's allowlist check is in `cmd/kv-sni-proxy` (ADR021 §IP allowlist).
- Postgres: `database_controller.go:881-893` only changes CNPG `serverAltDNSNames`.

## Steps

1. `rg` every write of `Spec.Public` / `public` on KeyValue, and every caller. Record the REST, GraphQL and MCP aliases.
2. Decide whether an environment allow-list change can flip a member store's `public`. If it can, list it as a mass-restart path.
3. Decide the design: keep the Certificate and the TLS listener after the first issuance, and gate external access at the proxy and Service. Confirm the proxy refuses a non-public store even if its TLS listener is up (no bypass via direct Service access from outside the cluster). Record the cert-manager issuance cost of keeping certificates.
4. Postgres: read CNPG's behavior when `serverAltDNSNames` changes at the pinned version, or probe a dev cluster. Record whether instances restart. If they do, add a task here for the same treatment. If not, the Postgres card copy stays.

**Done 2026-10-19 (loopx w4):**
- **Writers.** 4 write sites of KeyValue `spec.public` from 17 public entry points:
  - A: create (`keyvalue/service.go` `CreateKeyValue`), from REST `POST /v1/key-value`, GraphQL `createKeyValue` and MCP `create_key_value`.
  - B: `KeyValuePatch.apply`, where a present `ipAllowList` sets public to "non-empty" and an explicit `public` wins. Reached from REST `PATCH /v1/key-value/{id}`, REST `PUT …/ip-allow-list`, GraphQL `setKeyValueIpAllowList`/`setKeyValuePublic` and MCP `update_key_value`.
  - C and D: Blueprint create (`apps/deploy.go` `parseKeyValue`) and Blueprint update (`apps/blueprint_plan.go:587-590` `ApplyBlueprintKeyValueSpec`, patched directly). These come from three Blueprint REST routes, GraphQL `createBlueprint`/`syncBlueprint`, MCP `deploy`/`create_blueprint`/`sync_blueprint` and the auto-sync worker.
  - D bypasses `updateKeyValue` and is filed as w4/358.
- **Environment fan-out: no.** `SetEnvironmentIPAllowList` writes only `spec.environmentIPAllowList`, and the operator never reads that field for the pod template. An environment change cannot roll member stores.
- **Postgres: no restart.** Production runs CNPG v1.30.0 (chart 0.29.0, `deploy/gitops/base/cnpg-operator.yaml`). A `serverAltDNSNames` change re-signs the server certificate in place (`cluster_pki.go` `ensureServerLeafCertificate` → `RenewLeafCertificate`). The instance manager rewrites the files and runs `pg_ctl reload` (`instance_controller.go` `RefreshSecrets`/`Reload`), and no rollout check looks at certificates. The Postgres card's copy stays.
- **Design.** Keep the TLS listener and its Certificate once the pod template carries them. External access stays gated where it already was: the Service's TLS port and the kv-sni-proxy route, which require `spec.public` (`cmd/kv-sni-proxy/main.go:92`). The listener is reachable in-cluster only, behind the same password as the plaintext port.
- **Issuance cost.** One renewing Certificate per store that was ever public. Re-enables no longer re-issue, which counts against Let's Encrypt's duplicate limit less than before.
