## Objective

The service Environment tab shows manifest-managed vars (from t001's flag) as read-only rows with a "managed by blueprint manifest" affordance, disables edit/delete/rename for them, and renders t002's refusal in the server's own words when a write is attempted.

## Context

- Environment editor is the shared component used by the service + env-group editors (per ADR018 Env vars row, `w5/m44` + `w2/m95`).
- Server-error passthrough precedent: `mutationErrorMessage` + `mutation-error-toast-invariant.test.ts` (per `w1/m145`).
- Pre-settle state: the tab must not flash the vars as editable before the flag arrives — gate the row actions on the flag, defaulting to read-only while loading if the flag is absent on old data.

## Steps

1. Thread the manifest-managed flag from `envVars` into the row model; render read-only rows with the manifest affordance (en + zh copy).
2. Disable edit/delete/rename/export-mutation actions on flagged rows (copy/download of the value stays allowed — fail-closed export already exists).
3. Surface t002's refusal message verbatim on attempted writes.
4. Component tests: flagged row renders read-only; unflagged rows fully editable; refusal toast shows server text.

## Acceptance

- A blueprint service's Environment tab shows manifest vars read-only; a regular service's tab is unchanged.
