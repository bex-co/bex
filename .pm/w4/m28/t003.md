## Objective

An environment's composed IP rules are enforced at member web services' and static sites' public endpoints — not just datastores — via the apps-rows→App-CR projector and the operator's ingress mechanism.

## Context

- The projector (ADR003) writes App CRs; the operator (mechanism-only, DB-free) reconciles Ingress — enforcement likely lands as a Traefik `ipAllowList`/`ipWhiteList` middleware per host, the same per-host middleware seam `w7/m32` established.
- Datastore fan-out (Postgres/Key Value SNI allow-lists) already exists — route it through the same composed evaluation so layers apply there too.
- Static sites route through the shared static-server's Ingress (docs/ADR029-static-sites.md) — confirm per-host middleware still applies.

## Steps

1. Project the composed CIDR list onto member Apps (CR field per t001's design).
2. Operator: reconcile the Traefik middleware onto the App's Ingress (and static-site host Ingress).
3. Re-route the existing datastore fan-out through the composed evaluator.

## Files

- `lego/backend/internal/` (projector), `lego/types/` (CR field if new), `lego/operator/internal/` (ingress middleware reconcile)

## Acceptance criteria

- [ ] Live on a dev-N stack: a disallowed source CIDR gets blocked at a member web service's public URL; an allowed one passes
- [ ] Datastore enforcement still works and now honors composition
- [ ] Operator remains DB-free (everything arrives via the CR)

## Out of scope

- SSH gateway (Render documents network isolation doesn't block SSH; ipAllowList scope decided in t001)
