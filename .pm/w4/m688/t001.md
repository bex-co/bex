## Objective

Write the script that reads Render's docs index and every page it lists, and fails when a page is new, gone, or changed since the ledger recorded it.

## Context

- `https://render.com/docs/llms.txt` listed 227 unique page URLs on 2026-11-26: 124 product pages, 74 deploy guides (`deploy-*`), 13 Workflows pages, 12 Sandboxes pages and 4 security advisories. Each page has a markdown form at `<url>.md`.
- Precedents: `scripts/render-changelog-drift.sh` (w4/m553), `scripts/render-dashboard-ops.sh` (w1/m645) and `scripts/render-version-drift.sh` with `scripts/lib/render_version_pages.py` (w3/m637), each with a `.test.sh`.
- No page body may be committed (`#NO-ARTIFACTS-IN-GIT`, and the text is Render's): the ledger keeps a hash per page, not the text.

## Steps

1. Fetch `llms.txt`, collect the `render.com/docs/` URLs, and fetch each `.md` with a bounded client and retries.
2. Normalize before hashing: drop the "For the complete documentation index" banner, image lines and trailing whitespace, so a re-render alone is no change.
3. Compare with the ledger's hash column (t002): fail on a page with no row, a row whose page is gone, or a changed hash, naming the page and its row's pointer. When an earlier fetch is available (the job's cache), print the changed paragraphs.
4. Write `scripts/render-docs-drift.test.sh` with fixtures for each failure and for a clean run.

- `scripts/render-docs-drift.test.sh` (new)

## Acceptance criteria

- [ ] The test script passes, and covers a new page, a gone page, a changed page and a banner-only change that must pass.

## Out of scope
