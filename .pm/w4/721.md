# A managed Postgres logs each statement that runs longer than 2 seconds, as on Render

Why: Render's Postgres logs have a `duration:` line for each slow query, which is where a user debugging a slow app looks first. bex's have none unless the user sets a parameter override. Found by w4/m553 t002 on 2026-11-22 from Render's changelog of 2023-06-30 ("We now log when a query takes longer than 2s") ([disposition table](../../docs/render-artifacts/render-changelog.md)).

- **Render:** [render.com/docs/postgresql-creating-connecting](https://render.com/docs/postgresql-creating-connecting) says "Queries that take longer than 2 seconds are logged with a line that starts with `duration:` followed by the SQL statement."
- **bex:** the operator's default parameters are `pg_stat_statements.track=all`, `log_lock_waits=on` and `max_connections` (`lego/operator/internal/controller/database_controller.go`). `log_min_duration_statement` can be set only as a tenant parameter override (`lego/types/v1alpha1/database_types.go`).
- **End state:** a new and an existing database log a statement that runs past 2 s with Render's `duration: … ms  statement: …` line in its Logs (REST, GraphQL, MCP and the dashboard), and a faster one does not. A user's own override still wins. An operator test covers the default and the override.
