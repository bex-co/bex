# Small nonzero Metrics readings render as zero

Why: a customer inspecting a lightly used service cannot read its CPU or memory scale because the axes, tooltips, and CPU headline round positive measurements to zero.

**Severity:** minor. **Estimate:** 55m. Source: continuous functional `$qa-find-bugs w4`, pass a431, 2026-10-14 UTC. Goal: truthful hosting diagnostics under ADR008's dashboard pillar and the board's basic operational observability goal. Filing only; no product implementation in this pass.

## Cause and scoped fix

`dashboard/src/features/metrics/lib/format.ts:22–31` formats compact CPU values with `toFixed(2)` and percentages with `toFixed(0)`. `SvgLineChart` builds actual min/midpoint/max ticks from the positive series (`svg-line-chart.tsx:329–374`) and renders those rounded strings directly into native SVG text (`:139`). Its data geometry remains nonzero. `chart-layout.ts:67–76` applies the same formatter to each tooltip row; `svg-line-chart.tsx:208` passes those rows into the directly rendered tooltip (`:230–249`). There is no chart-library or tooltip-library numeric conversion here.

The CPU headline is traced separately: `ApplicationMetricsCard` takes the latest value of its sole populated series (`application-metrics-card.tsx:403–407`), and `LatestValue` calls `formatMetricValue` (`:493`). That function rounds CPU to three decimal places (`format.ts:7`), independently producing `0.000 cores`. Both policies already exist in the original formatter commit `fde064959`; this is an uncovered small-value case, not a later regression or a normalization error.

**Target:** preserve readable nonzero CPU and percentage labels at low magnitudes, with distinct zero/midpoint/maximum labels for the captured domains. Apply adaptive precision to the CPU/percentage branches of the existing shared formatters. For example, three significant digits below the current compact precision can show memory ticks `0%`, `0.0355%`, `0.0710%` and CPU Total ticks `0.00`, `0.000125`, `0.000251`; these examples specify readable rounded measurements, not new API values. A small positive headline or tooltip must retain a positive number rather than an exact-zero label. Keep the existing compact conventions at ordinary magnitudes, true zero, units/suffixes, and bytes/seconds/count/default branches. Handle unusually tiny finite values with bounded significant digits or scientific notation rather than padding an unbounded label.

Do not change the API samples, percentage denominators, tick geometry, retained-history rules, query windows, or missing-data handling. Pending/errors must keep their current explicit states; this change formats settled numbers and must not fabricate zero samples while reads load.
