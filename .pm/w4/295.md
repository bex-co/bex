# Webhook Settings loading fields put help below inputs

Why: the pending form previews a different field order and compresses static text, so the actual controls and following sections move when the page becomes ready.

Severity: **minor**. Estimate: **50m** (Webhook Settings placeholders 15m, behavior/caller checks 20m, desktop/mobile verification and simplify 15m). Functional QA a429, 2026-10-13 Pacific / 2026-10-14 UTC, user-selected w4 and muse.env helper. Filing only; inspected main `f461d9d12`.

## Reproduction and target

Create an owned **disabled** endpoint with one subscribed event. Enter `/webhook/{id}/settings` while its WebhookEndpoint read is pending, then compare with the ready page at the same viewport.

The recorded production probe holds only that owned read's unchanged response for seven seconds and invokes the production router's public navigate method. The request succeeds with HTTP200 and identical endpoint data. No mutation or auth response is delayed; the handler is removed in `finally`.

Both **1440×1000** and a fresh **390×844** show:

- Pending Name/URL fields: label bar → 36px input placeholder → help bar.
- Ready Name/URL fields: label → help paragraph → 36px input.
- The pending status row adds a bordered, padded subpanel absent from the ready row.
- The General card's static explanatory note reserves one 16px line although its ready text wraps, especially on mobile.

The General card is **428px** tall in both pending captures, but **414px** ready on desktop and **494px** ready on mobile. Its content region grows **346 → 416px** on mobile. Relative to that card's top, the URL input moves from **283 to 315px**; the help moves from below that input to above it. The ready URL help occupies **40px** on mobile versus the single pending 16px hint line. These are static form/text regions rather than representative event-row counts.

Expected: Name and Destination URL preview label → help → input, status reserves the same plain row shape, and static text wraps/reserves the ready height at the same width. Keep the existing max-width, outer spacing, event-picker/action regions and inert pending controls.

Durable evidence: [DOM rectangles, exact reads and runnable delay probes](evidence/295-webhook-settings-skeleton.json). Desktop: **06:17:36.858 UTC**; mobile: **06:20:32.958 UTC**. All four `.playwright-mcp/qa-a429-{pending,ready}-{desktop,mobile}.png` screenshots were opened and visually checked. They supplement the durable measurements.
