# 470 — Retired REST aliases answer `text/plain` "404 page not found", while every other miss answers Render's JSON error

Why: an API client or the Render CLI that parses `{id, message}` on every non-2xx gets a decode error instead of "not found" for exactly the paths it is most likely to have hard-coded, the old aliases. Every other unknown path returns JSON.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 7, 2026-11-04 ~12:35 UTC (`muse.env`, `bex-canary`, pin `fb6098dd2e37`); **minor** (API error contract); ~20m.
- **Probe** (from the dashboard page, `fetch(url, {credentials:'include'})`, `GET`): status, `content-type`, then body.
  - Retired paths, all text: `/v1/apps`, `/v1/apps/srv-x`, `/v1/databases`, `/v1/registry-credentials`, `/v1/webhooks/endpoints`, `/v1/postgres/dpg-dbk3isgrv49s73eq43mg/exports` and `/v1/postgres/dpg-dbk3isgrv49s73eq43mg/recovery-info` each return `404 text/plain` `404 page not found`.
  - **Controls, all JSON:** `/v1/services/srv-x/zz`, `/v1/nonexistent-collection`, and `<id>/zz-nope` under each of services, postgres, key-value, redis, env-groups, owners, blueprints, projects, environments, deploys, webhooks, registrycredentials, disks, logs, metrics and notification-settings (16 of 16) return `404 application/json` `{"error":"not found","id":"not_found","message":"not found"}`. An unknown method (`DELETE /v1/owners`) returns `405` JSON.
- **Root cause:** `lego/backend/internal/api/render_openapi.go:629-632`. `renderRequestValidator.ServeHTTP` refuses `retiredPublicRESTAlias(r)` (`:710-727`, six path families) with **`http.NotFound(w, r)`**, Go's plain-text 404. The next branch serves misses through `serveMuxJSON` (`:638`), which writes the shared JSON error. The aliases were retired in `e1cf841c6` (ADR018 line 33: "retired public aliases are rejected before dispatch"). The rejection is intended; only its body is wrong.
- **Fix:** answer the retired aliases with the same JSON 404 the mux miss produces, through the shared `core` writer used by `serveMuxJSON`, so the status stays 404 and only the body and content type change. Add a test table over all six `retiredPublicRESTAlias` families, including the GET-only `recovery-info` case, that asserts `application/json` and `id: not_found`. Keep a control row for a live route.
- **Adjacent classes:** the rejection happens before authentication, so the JSON body must stay the generic `not_found`. It must not name the alias's replacement or reveal whether the resource exists.
- **Render:** Render's API answers unknown paths with a JSON error body.
- **Dedupe:** `grep -rl "retiredPublicRESTAlias" .pm` returns only w8 CLI-sweep evidence and a patch, with no item about the body. w4/168 (done) is about mounting Render's Postgres and notification paths, not this. No DO_NOT_DO item applies.
