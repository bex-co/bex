## Objective

Check that this milestone's changes are consistent across every surface the service-event feed is exposed on, and that nothing drifts from Render's behavior for the same surface.

## Context

- The feed is exposed on REST (`GET /v1/services/{id}/events`), GraphQL (`serviceEvents`, `serviceEvent`), MCP, the dashboard Activity tab, and outbound webhooks — five consumers of one query, per `docs/ADR006-bex-api.md`.
- `docs/render-artifacts/service-events.md` is the capture to compare against, including its note at line 114 that a previous fix here was a dashboard defect rather than an API one — so check which layer each change belongs in.
- `docs/ADR018-render-parity.md` is the ledger. A correction that makes bex *more* truthful than Render is still a divergence and is recorded as one.

## Steps

1. Exercise the same service's feed on REST, GraphQL and MCP and diff the rows.
2. Confirm the dashboard Activity tab and its event-type filter still render every type the API emits (the `w6/m122` fail-open rule at `service-events.md:114`).
3. Compare against Render's documented event behavior and record any deliberate divergence in ADR018.
4. Confirm the webhook payload shape did not change while its content did.

## Files

## Acceptance criteria

- [ ] The three API surfaces return the same rows for the same fixture.
- [ ] The dashboard renders every emitted type and its filter offers them.
- [ ] Any divergence from Render is recorded in ADR018 rather than left implicit.

## Out of scope
