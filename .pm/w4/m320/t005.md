## Objective

`privateServiceProjection`, `MinReadySeconds` and the probe projection are shared by every rollout. Enumerate each kind of rollout and decide whether it is pinned. Add regression tests for the kinds that behave correctly today, so the fix doesn't move them.

## Context

The rollout kinds that reach the shared code:

- port-changing image deploy (w4/428): pinned;
- env save, secret-file save, restart, and same-image redeploy: unpinned on purpose (w4/m243 t012);
- image tag change: REST `imageUrl`, deploy hook `imgURL`, and a settings image change;
- rollback to an older image;
- first deploy (w2/078: one ReplicaSet);
- private services (`PortModeImageV1`), which have no HTTP discovery;
- git-built Docker web services with no port (`PortModeWebImageV1`, `apps/service.go:2734-2746`). This one is unverified: a new commit has a new digest, and image `ENV PORT` may exempt it through `Status.EnvPort` (`web_image_http.go:44-47`).
- multi-instance services: the pin must hold for every replica.

## Steps

1. Grep every caller of `privateServiceProjection`, `changesImagePorts`, `webImageHTTPSelectionPending` and `webImageHTTPSelectionGuardsServing`. Write the count and the list into the PR.
2. For each rollout kind above, record pinned or unpinned and why. Add or extend a test for each.
3. Settle the git-built case from source: does a Docker repo service with image `ENV PORT` enter discovery?
