# Refresh log-filter discovery while the page remains open

Why: new request methods are already searchable in the API but cannot be selected in the dashboard until a full reload.

**Severity:** minor. **Estimate:** 55m (shared-hook refresh + focused regression tests + live acceptance). Source: user-requested qa-find-bugs sweep61, 2026-10-03; main checked at `2243a37ef`. ADR010 observability and ADR018 structured-log-filter promise. This is a filing, not an implementation.

## Live reproduction

Owned Free native Go web `qa-20261003-shell-r61` / `srv-db0oveg9ohsc73e5r8ig`, initial deploy `dep-db0oveg9ohsc73e5r8j0`, root examples/hello-go, public repo bex-co/bex main, build `go build -o app .`, start `./app`, port3000. It reached Live and external curl returned HTTP200.

1. Load its Logs page before traffic; method discovery initially has no values. Generate GET, POST and HEAD requests. The open Method picker continues offering only All methods. Full reload makes GET/POST/HEAD available. This initial observation is supporting context; the two independently captured cases below establish the finding.
2. With a freshly loaded page and populated picker, send `OPTIONS /qa-r61/options` to the owned public URL (200). Wait until REST label discovery includes OPTIONS. Open/reopen Filters → Method: OPTIONS is absent, although the API returns it. Reload: OPTIONS appears and selecting it yields the matching request log.
3. From that fresh page, send `TRACE /qa-r61/trace` (200 with the sample app's plain OK response). REST now includes TRACE; the open picker still does not. Reload: TRACE appears, selecting it yields the real TRACE200 row. REST, direct GraphQL and MCP all return the same five observed methods.

Expected: a visible page's discovery refreshes at the shared 30s cadence, so once the API indexes a new method it becomes selectable within the next successful poll without a reload. Preserve selection, filters, visible log rows, focus and any open picker. Do not turn on unsupported request-log Live tail or manufacture fallback options as the fix.

Controls: /qa-r61/alpha path matches that exact path, excluding /alpha-plus; adding MethodPOST returns honest No matching logs. Request Live tail is disabled with an explanation. Free shell and Connect menu correctly explain plan gating. No paid plan was selected.

## Cause, framework and fix

- `dashboard/src/features/logs/hooks/use-log-label-values.ts:35-49` calls useQuery with variables/errorPolicy only; there is no poll, explicit refetch or trigger when the menu opens. The plain-array wrapper at :54-55 inherits it.
- `dashboard/src/features/logs/components/log-filter-bar.tsx:77-103,142-158` merges static values with discovered values. METHOD_FALLBACK omits HEAD/OPTIONS/TRACE; a resolved empty set suppresses every fallback by design. Consequently a cached answer stays authoritative as traffic arrives.
- `dashboard/src/common/apollo/default-options.ts:24-26` only overrides notifyOnNetworkStatusChange; it does not supply a fetch policy or freshness timer. The singleton CSR factory uses InMemoryCache.
- Opened actual installed **@apollo/client4.1.3**: `core/QueryManager.js:708,1052-1069` defaults to cache-first and returns a complete cached result without using the link. `core/ObservableQuery.js:844-897` cancels polling without pollInterval; configured polling uses network-only and respects skipPollAttempt. Thus a mounted query does not spontaneously discover new values, and remounting against warm cache alone is not a reliable repair.
- Proposed fix: supply RESOURCE_POLL_INTERVAL_MS and skipPollWhenHidden from `common/lib/polling.ts:10,68` to the shared discovery query. Keep global notifyOnNetworkStatusChange false so background refresh does not replace ready content. Preserve prior usable values during a refresh/error and preserve the distinction between answered-empty and unavailable; never clear an active filter because its value disappears from discovery. Confirm no second timer owner is introduced for the same mounted query.

**Census:** six production call sites across three components: LogFilterBar calls useLogLabelDiscovery four times (level, method, statusCode, instance); DatastoreLogViewer:70 calls useLogLabelValues once (instance); NetworkMetricsCard:112 calls it once (host). Wrapper itself delegates once. Apply freshness globally to this shared hook. Test the existing correctly working host and datastore consumers as controls; backend host discovery is App-derived and must stay so. Exact family: generic service logs cover web/private/worker/cron; Postgres and Key Value use datastore viewers; static has no runtime Logs page, though shared network metrics may consume host discovery. Only web method discovery was reproduced live; other freshness impacts are inferred, not observed incidents.

Aliases: UI Logs route and its URL method/path filters consume the shared document; REST /v1/logs/values, GraphQL logLabelValues, MCP list_log_label_values already agree and need no wire changes. Keep per-resource backend authorization and scoping unchanged. Unauthenticated, forbidden and not-found remain their existing errors; store-unavailable/timeout must not become authoritative empty. While a poll is pending, show the current options and preserve selection; on a cold load keep the existing loading/unavailable fallback rules. Hidden tabs skip work and resume on the next visible tick.

## Acceptance

- On a fresh owned service, leave Logs open, generate new OPTIONS traffic, wait until the API exposes OPTIONS, then observe it selectable within one successful visible 30s poll; repeat with TRACE after a fresh page load.
- Selecting each new method returns matching request rows. Exact path and combined nonmatching filters retain current behavior; refresh keeps an already-selected method, open picker, typed search and log history intact.
- Meaningful hook/component tests cover empty→values, new value after mount, hidden-tab skip/resume, a transient discovery error and preserved selection; cover datastore instance and network host consumers without claiming their live failure was observed.
- Run relevant dashboard tests/typecheck/lint. Delete fixtures and revoke the QA session. Do not close on unit tests alone without the live reproduction passing.
