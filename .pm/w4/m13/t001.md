## Objective

API-key tokens currently live as long as Hydra's default `client_credentials` access-token TTL. Now that keys re-mint tokens freely (the m3 flow), a shorter TTL shrinks the blast radius of a leaked token at near-zero UX cost. Review the default, pick a deliberate value (agents' longest realistic single-session use as the floor), set it in values, and record the decision + rationale in docs/auth.md.

## Context

- `deploy/gitops/base/values/hydra.values.yaml` (`ttl.access_token`); Hydra token minting flow in docs/auth.md.
- Consider the MCP/agent session pattern (w4/m9's OAuth clients share Hydra) — verify the TTL knob scopes to `client_credentials` and doesn't shorten flows that need longer.

## Steps

1. Check the current effective TTL (values + Hydra default); pick and set the new value.
2. Verify live: mint a token, introspect, confirm `exp` reflects the new TTL; agents still work after expiry (transparent re-mint).
3. docs/auth.md paragraph.
