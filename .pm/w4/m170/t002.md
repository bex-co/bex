## Objective

A database whose spec already carries a reserved role, either as a user or as an `ensure: absent` tombstone, must reconcile again.

## Context

- `lego/operator/internal/controller/database_controller.go:365-400` `managedRoles` projects `Spec.Users` as present and `DeletedUsers` as absent, unfiltered.
- Live: add-user `postgres` → `unavailable`. Delete-user (204) → still `unavailable` after 2 min, while `select 1` keeps working.

## Steps

1. Never project reserved roles into `spec.managed.roles` (skip them, recording a warning condition). Drop reserved tombstones from `DeletedUsers` on the next reconcile.
2. Envtest: a Database with a reserved user, and one with a reserved tombstone, both reach Ready.

## Acceptance criteria

- [ ] The envtest above passes. Re-applying the operator heals any existing wedged database without manual edits.
