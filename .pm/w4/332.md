# Require a Publish Directory before enabling Static Site deployment

Why: the create wizard enables a request the API must reject, sending users through a failed submission instead of identifying the missing required field.

**Severity:** minor. **Estimate:** 50m. Functional `$qa-find-bugs w4` pass a802, 2026-10-16 UTC. Source HEAD `56ae9135aabc0d8d4510e476437868a297300776`. Filing only.

## Reproduction

1. Fresh-load `https://dashboard.bex.co/services/new?type=static_site` at1440px. Select Public Git URL, enter `https://github.com/bex-co/bex`, name `qa-a802-empty-publish`, branch main, leave Build Command and Publish Directory blank, and turn Auto-deploy off.
2. Publish Directory displays placeholder `dist`, but its actual value is empty and native required is false. Deploy Service is enabled. Click it.
3. The native CreateService variables omit publishPath. HTTP200 carries `data.createService:null` and the complete error `bad request: publishPath is required for a static_site`. The route and draft remain; after the response, Publish Directory still has aria-invalid false and no inline alert was observed.
4. Fresh-load at390px with name `qa-a802-space-publish` and three spaces in Publish Directory. Deploy is again enabled. The builder trims that to an omitted argument, and the second native request receives the same rejection.
5. Controls, without submission: entering `.` or `examples/static-site` leaves Deploy enabled. Switching to Web hides Publish Directory and permits an otherwise complete draft. Earlier same-pass Port/Schedule cases correctly stop blocking when their type hides them and restore validation when switching back.

Two failed create attempts, no created resource. No injected/delayed response or paid submission.

## Target fix and acceptance

- [ ] For static_site, treat `form.publishPath.trim() === ""` as incomplete in `isSubmittable`; Deploy stays disabled for empty and whitespace-only input. Show localized required-field guidance at Publish Directory using existing TextField error/hint capabilities. The placeholder must remain an example rather than become an implicit value.
- [ ] Preserve nonempty relative paths, including `.`, and existing trimming on submission. Do not invent a dist default or relax the backend requirement. Keep the optional no-build static path.
- [ ] Restrict this requirement to static_site. Preserve the observed hidden Port/Schedule behavior, all four non-static types, source selection and draft values. Verify the `/static/new` redirect alias reaches the same validation. The alias was source-traced, not live-probed.
- [ ] Add focused behavioral checks in `features/services/lib/__tests__/create-service-input.test.ts` and the create-route UI tests: otherwise-valid static drafts with empty/whitespace output cannot dispatch CreateService; valid paths enable the form; non-static forms ignore the hidden output field. Update otherwise-valid static test fixtures to supply their required path. Check desktop/mobile field guidance and the existing locales, then run relevant dashboard checks and /simplify.
- [ ] Repeat the two original click journeys: before a directory is entered, there is an actionable field explanation and no doomed create request. Preserve the backend/API contract across REST, GraphQL and MCP.

## Research

- `dashboard/src/features/services/lib/create-service-input.ts:133–164` checks source, commands, env/files, port, plan and cron schedule, but has no static publish-directory predicate. This helper has **one production caller**, `routes/services.new.tsx:104`; that shared route covers web/private/worker/cron/static. The fix is allowlisted to its static shape.
- The same module's `set` helper at112 trims blank to undefined; `buildCreateServiceInput:225` uses it for publishPath. Its **one production caller** is the same route at108. This explains why both empty and whitespace probes omit the argument. Preserve the producer's normalization.
- `routes/services.new.tsx:422–431` renders TextField without an error/invalid requirement. `common/components/text-field.tsx` already accepts localized error text, marks aria-invalid and renders a role=alert message; no global TextField rewrite is needed.
- GraphQL `lego/backend/internal/apps/graphql.go:732` maps the optional argument into the create request. Shared `apps/service.go:2837–2844` validates the source/type-specific fields, and `validateTypeSpecificCreate:3053–3054` correctly refuses a blank trimmed publishPath. The target is the dashboard's completeness predicate, not an API/schema relaxation.
- `use-create-service.ts` returns null on refusal and uses its existing server-message toast path for generic errors. The durable evidence records the API error; no ephemeral toast wording is claimed as observed. The issue is missing field validation, not a failed publish, hidden billing action or backend data loss.

No third-party mechanism is needed for this cause: the omission is in the project's plain predicate and string normalization. Adjacent source, name, plan, permission, unauthenticated and timeout states keep their existing handling. m218 catalog recovery and m219 startup readiness are separate defects despite sharing this route.
