## Objective

#81's workspace and Blueprint guidance does not flow into the files bex replaces whole, and those overrides still tell agents to call `get_selected_workspace()`, a tool bex removed in w1/m55 (a live bug in today's pack).

## Context

- Overrides replace upstream whole: `lego/cli/internal/skills/packgen/overrides/bex-mcp/SKILL.md` (`packgen.go:49-52`) and every `render-access.md` via `overrides/shared/bex-access.md`.
- `get_selected_workspace` appears in `overrides/bex-mcp/SKILL.md:78` and `overrides/bex-mcp/references/troubleshooting.md:68`; bex removed it (`lego/backend/internal/api/mcp_parity.go:114-119`).
- bex serves `create_blueprint`, `get_blueprint`, `plan_blueprint`, `approve_blueprint`, `update_blueprint` (`lego/backend/internal/apps/blueprint_onboarding.go:1039-1080`), returns `planningOutcome`, `notices`, `sync.requiredManualEnvVars` and `dashboardUrl`, takes `workspaceId` on every tool (`mcp_workspace.go:190`), and the CLI's `ea blueprints create|plan|approve|update` are served (`docs/cli-compatibility-checklist.md:389-392`). One difference: bex's `approve_blueprint` takes an optional `syncId` (w5/m384 t001) that Render's skill says approval does not take.

## Steps

1. In `bex-mcp/SKILL.md`, add an explicit-`workspaceId` section and a Blueprint capabilities section matching #81; add `workspaceId` to `shared/bex-access.md`.
2. Remove `get_selected_workspace` from every override; point to `list_workspaces` and per-call `workspaceId`.
3. Check every tool and argument the regenerated skills name against `lego/backend/internal/api/openapi/render-mcp-tools.json` and bex's tools; decide how the skill treats the `syncId` extension (recommended: optional, named as a bex extension).
4. Regenerate and test.
