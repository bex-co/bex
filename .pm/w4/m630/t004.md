## Objective

Show the regenerated skills drive a real create → plan → approve deploy, over MCP and over the CLI.

## Context

- The pack is embedded in the binary (`lego/cli/internal/skills/skills.go:42`) and `bex skills update` reinstalls that copy, so reaching users needs a CLI release. On precedent the release is the user's call (`/release cli`; w7/m426 t005, w10/m561 t006); this milestone was not given that approval.

## Steps

1. Build `bex` from `origin/main`; in a sandboxed HOME run `bex skills install`.
2. In a disposable QA workspace (deleted afterwards), let an agent follow bex-deploy through create → plan → approve once over MCP and once over `bex ea blueprints`; confirm the services reach a running deploy.
3. Record the run. If the user has approved a release by then, run `/release cli` and `bex skills update`; otherwise record "release pending the user's `/release cli`".
