## Objective

Pin the new guarantees with tests that fail against the pre-fix code, and protect the verbs that must keep working without a confirmation.

## Context

- The pre-fix behavior to encode as a failing test: `setImage` on a protected member succeeds today and changes the running image.
- The existing guard has tests from `w6/m19`/`w6/m37`; extend that file rather than starting a parallel one, so the guarded set lives in one table.
- A table-driven test over the verb set is the right shape here: the set is now written down in ADR032, so the test can mirror it and a future verb added without a decision shows up as a gap.

## Steps

1. Table test: for each verb in t001's set, a protected member refuses without the phrase and proceeds with it.
2. Negative table: Restart, Resume, and the webhook redeploy path stay ungated.
3. Regression: delete and suspend still refuse and still accept the phrase.
4. Cross-surface test asserting the refusal payload is identical on REST/GraphQL/MCP.
5. Unprotected-path test: no confirmation required, no argument needed.

## Files

- `lego/backend/internal/apps/protection_test.go` (or wherever `w6/m19` put it)
- the cross-surface test package

## Acceptance criteria

- [ ] The `setImage`-on-protected test fails before the fix and passes after.
- [ ] Every verb in the set is covered by the table, both directions.
- [ ] The deliberate exclusions are covered so a future change cannot silently guard them.
- [ ] No tautological assertions; each names the behavior it protects.

## Out of scope

- Live production verification — that is the milestone DoD, run by hand.
