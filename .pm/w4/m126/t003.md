## Objective

Apply t001's rule to the remaining verbs that change a running protected service — env vars and the release-relevant settings — and give each one the same `confirm` argument, or record why it stays out.

## Context

- Observed live on a protected member, all accepted with no confirmation: `setEnvVar`, `setEnvVars`, `scaleService`, `setIdleTimeout`. The env-var writes rolled a release — the deploy list shows `config_change` entries and the revision advanced to `rev-6`.
- The candidate set is already enumerated by the deploy-history gate. `patchFetched`'s comment (`service.go:4155-4170`) names the verbs that mint a deploy row because they move the operator's release identity: _"start/build command, root dir, Dockerfile path, pre-deploy command, health check path, plan, disks"_ — plus env vars and secret files through the secrets path. If t001 chose the "mints a release" rule, that list **is** the set, which makes this mechanical rather than a judgement call per verb.
- `scaleService` and `setIdleTimeout` do not mint a release; they are operational. Under the availability rule, a scale *down* still reduces capacity — decide per t001 and write it down either way.
- Env vars go through `internal/secrets`, not `internal/apps`, so the guard needs the App's protected status reachable from there. `appProtected` (`protection.go:62-81`) is the predicate half and is already shared with the capability projection (ADR087), so prefer reusing it over a second lookup.

## Steps

1. Take t001's set and add the guard at each site, reusing `requireUnprotected` / `appProtected`.
2. Add `confirm` to each affected adapter verb across REST, GraphQL and MCP.
3. For the secrets path, wire the App-protection predicate through rather than duplicating the store read.
4. Record in ADR032 any verb from the candidate list deliberately left ungated, with its reason.

## Files

- `lego/backend/internal/apps/service.go`
- `lego/backend/internal/secrets/` (env vars, secret files)
- the REST/GraphQL/MCP adapters for each verb

## Acceptance criteria

- [ ] Every verb in t001's set refuses on a protected member without the phrase and proceeds with it.
- [ ] Every verb outside the set is named in ADR032 with a reason.
- [ ] Env-var writes on a protected member follow the same rule as the rest of the set.
- [ ] No unprotected-path behavior changes.

## Out of scope

- Source repointing (t002).
- `restartServer` and `resumeService`, which ADR032 already excludes with stated reasons.
