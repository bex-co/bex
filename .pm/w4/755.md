# A suspended service's or static site's `503` carries Render's `cf-cache-status`, `rndr-id` and `x-render-routing`

Why: Render parity. w4/m703 gave every other answer of a bex host Render's `cf-cache-status`, but a suspended service's answer still differs from Render's in three headers, and uptime checks read them to tell a suspension from an outage.

- **Render (captured 2026-11-27 by w4/m703 t002, [edge-headers.md](../../docs/render-artifacts/edge-headers.md#every-answers-cf-cache-status-w4m703)):** a static site suspended by its owner answers `503` with `x-render-routing: suspend-by-user`, `cf-cache-status: BYPASS` to a `GET` (`DYNAMIC` to a `POST`) and no `rndr-id`. A web service suspended by its owner answers `503`, `suspend-by-user`, `BYPASS`, a `rndr-id` and `x-render-origin-server: Render`. One suspended by Render answers `503`, `x-render-routing: suspend`, `DYNAMIC` and no `rndr-id`. Each page is "This service has been suspended by its owner."
- **bex today:** a suspended web service or static site routes to the activator (`suspendedRoutable`, `lego/operator/internal/controller/app_controller.go`), which answers `503` with `x-render-routing: suspend` for every suspension (`routingSuspend`, `lego/operator/cmd/activator/main.go`). The entrypoint's sanitizer gives the answer a `rndr-id` (`deploy/gitops/charts/traefik-plugins/clientipheaders/clientipheaders.go`). A web service's chain ends in the plugin's `originServer` instance, so its answer reads `DYNAMIC`; a static site's activator route has no status at all. The static server's own suspended answer (`serveSiteUnavailable`, across the suspend handoff) reads `BYPASS` with a `rndr-id` since w4/m703.
- **Do:** decide which suspensions bex has (owner-requested from the dashboard or API, and platform ones such as billing or abuse, if any) and map them onto Render's two `x-render-routing` values; give a suspended answer Render's `cf-cache-status` (`BYPASS` to `GET`/`HEAD`, `DYNAMIC` otherwise, `DYNAMIC` for a platform suspension); and drop the `rndr-id` where Render's has none (a static site's, a platform suspension's), which needs a plugin instance on the suspended route because the sanitizer sets it before the route runs.
- **Done when:** on production, a disposable web service and a disposable static site in `bex-canary`, each suspended from the dashboard, answer `curl -sI` with the headers above, and plugin, activator and operator tests pin each one.
- **Size:** about 1h30m. Filed by w4/m703 t002.
