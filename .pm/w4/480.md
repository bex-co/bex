# 480 — A linked env group marks the keys a service overrides with strikethrough and a hover title only, so assistive technology reads them as active

Why: the "overridden" state tells a user which value the running process actually gets. A sighted mouse user sees the strikethrough and the hover title. A screen-reader or keyboard user hears the overridden key read exactly like an active one, so they may edit the group expecting the service to change and see nothing happen.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 47, 2026-11-05 05:53 UTC (`muse.env`, `bex-canary`, pin `dcdc774c1a6b`); **minor** (accessibility); ~20m.
- **Probe:** owned web service `qa-20261105-env` (`srv-dbm1gm0iff5c739puus0`, `examples/hello-go`, service var `MESSAGE=two`) and owned env group `qa-20261105-grp` (`MESSAGE=group`, `GRP_ONLY=g1`), linked via `POST /v1/env-groups/<evg>/services/<srv>`. Both were deleted at 05:56.
  - Behavior is right: after the link deploy went live, `curl https://qa-20261105-env.onbex.co/` kept returning `two`, so the service variable wins, as on Render.
  - `/services/<id>/env` → `await page.locator('main').ariaSnapshot()` under **Linked (1)** reads `text: Linked GRP_ONLY MESSAGE`, then the legend `Struck-through keys are overridden by this service's own environment variables.` Nothing marks which key is struck through.
  - The DOM is `<span data-slot="badge" title="Overridden by this service's own MESSAGE environment variable"><s>MESSAGE</s></span>`. `<s>` has no accessible semantics in Chromium's tree, and a `title` on a non-focusable generic span is neither announced nor reachable by keyboard.
- **Root cause:** `dashboard/src/features/services/components/env-groups-panel.tsx:541-551` (env var keys) and `:560-570` (secret file names) render the shadowed badge as `<Badge title={reason}><s>{key}</s></Badge>`. The legend (`services.envGroupOverriddenNote`, `locales/en.ts:1099`) points at a visual cue only.
- **Fix (target behavior):** the accessibility tree names each overridden key as overridden. For example, the snapshot reads `MESSAGE (overridden by this service)`. Keep the visible strikethrough, and add an `sr-only` suffix with the reason (en + zh) inside each shadowed badge, for both keys and secret files. Do not rely on `title`. Extend `components/__tests__/env-groups-panel.test.tsx` to assert that the accessible text of a shadowed key contains the reason and that a non-shadowed key does not.
- **Blast radius:** one component, two map branches. `grep -rn "<s>" dashboard/src/features` → these 2 hits only.
- **Unverified:** the secret-file branch (`:560-570`) was not exercised live. It is the same markup, read from code.
- **Render:** n/a (accessibility of bex's own override hint). Render's precedence rule, where the service variable wins, is matched.
