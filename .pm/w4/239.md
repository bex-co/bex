# Generate Blueprint lets YAML widen the dialog and push actions off-screen

Why: exporting an ordinary Docker Command moves the dialog's title, explanation and Download action outside its frame, so a user must pan the whole modal instead of scrolling the YAML preview.

- **Severity:** minor. The response and downloaded file remain correct; Download can still work after the browser scrolls the overflowing modal. This is not an export failure or lost manifest.
- **Estimate:** 55m — shared caller audit 10m, scoped layout change 15m, real-browser regression/controls 20m, Simplify and live close 10m.
- **Source:** functional `$qa-find-bugs w4`, pass a56, 2026-10-10 UTC; muse.env through the login helper.
- **Goal:** usable hosting-to-IaC export under [ADR008](../../../docs/ADR008-vision.md) and [ADR049](../../../docs/ADR049-render-yaml-parity.md), extending [w8/m22](../w8/done/m22/README.md)'s existing dashboard Generate flow.

## Exact cause, consumers and bounded fix

- `dashboard/src/features/blueprints/components/generate-blueprint-dialog.tsx:160` uses the shared grid DialogContent without a bounded column. Its preview's **non-scrolling wrapper** at **200–207** has the default automatic minimum width; its `pre` at **201** preserves whitespace and uses overflow-auto, but the wrapper's content contribution expands the parent track first. Footer at **209–237** shares that same expanded track.
- `common/components/ui/dialog.tsx:60–68` supplies `grid`, padding and maximum frame widths, with no explicit column. The computed native grid track is 632.875px. Modal overflow-x computes to auto; this is whole-modal horizontal scrolling, not absent scrolling. Radix still renders and handles the actions; no Radix defect is asserted.
- The [CSS Grid automatic-minimum rules](https://www.w3.org/TR/css-grid-1/#min-size-auto), checked 2026-10-10, explain why the non-scrolling wrapper contributes its content size to an auto track. The actual pinned Tailwind **4.1.18** implementation was opened at `dashboard/node_modules/tailwindcss/dist/chunk-CT46QCH7.mjs`: `grid` sets display only; the grid-cols utility emits an explicit grid-template-columns, with numeric columns using minmax(0,1fr). This is browser CSS sizing rather than Apollo data conversion or YAML corruption.
- **Passing consumer opened and driven:** `features/databases/components/create-database-dialog.tsx:196` already supplies `grid-cols-[minmax(0,1fr)]` (w4/179). At 390px this pass's New Postgres preview is client/scroll **356/356**, column **308**, and the full Free plan trigger is x41–349. Its localized wrapped-plan work stays intact.
- The downloaded bytes come directly from `handleDownload` at **144–147** and the generated manifest retained by `handleGenerate` at **122–142**. Layout must not change that data path.

**Local browser prototype, not a shipped fix:** temporarily set only this open dialog's grid-template-columns to minmax(0,1fr). Mobile became client/scroll **356/356**, column **308**, buttons x41–349, pre client/scroll **306/631**. Desktop became **574/574**, column **526**, Download x804.90625–983, pre **524/631**. The prototype was removed before cleanup; no source or production setting was changed.

**Shared-code audit (10m):** production JSX census excluding tests found **32 DialogContent sites in 30 files**. Allowlist the fix to **one GenerateBlueprintDialog definition / one production mount**, `routes/blueprints.tsx:169`; leave shared `ui/dialog.tsx` and New Postgres alone. Selection itself and the short generated result currently fit, so retain their correct layout.

Resource family disposition: web/static/cron/worker/private services, Postgres and Key Value can be selected in this one export dialog; they do not each have another instance of this layout. Only the owned web + Postgres + Key Value selection and Postgres-only control were live driven. Canonical entry is the Blueprints list's Generate button; service/datastore aliases do not mount this dialog.
