# Blueprint validate still stops at the first bad env group or database, hiding every service error behind it

Why: `w8/019` made `blueprints validate` report every independently actionable error, and it does for services and Key Value. A refused **env group** or **database** declaration still ends the pass, so every service below it goes unchecked. An author fixes the group, re-validates, and only then learns about the service's error: the one-round-trip-per-error loop `w8/019` set out to remove.

Found live in `/qa-find-bugs` pass 240 on 2026-09-27 (w4-targeted, `muse.env` credentials) against the deployed `4a0422577`. Read-only: `POST /v1/blueprints/validate` (multipart, `ownerId` = `tea-d98210cbbpdc73dcrkvg`).

| manifest | errors returned |
| --- | --- |
| service `envVars: [{key: BAD-KEY}]` **and** `envVarGroups: [{name: qa-20260927-g, envVars: [{key: 1BAD}]}]` | **one**: `env group "qa-20260927-g" envVars["1BAD"]: invalid environment variable name …` at `envVarGroups[0].envVars[0]`, line 13. The service's `BAD-KEY` is **not reported** ❌ |
| the same service alone | one, located: `qa-20260927-envbp envVars["BAD-KEY"]: …` at `services[0].envVars[0]`, line 8 ✅ |
| two services with `BAD-KEY` and `2BAD` | **two**, each located (lines 8 and 16) ✅ (the `w8/019` aggregation) |

## Mechanism

`lego/backend/internal/apps/deploy.go` `parseCompiledStack`:

- **l.1800**: the env-group loop returns `blueprintResourceErrors{{kind: BlueprintResourceEnvVarGroup, …}}` on the **first** refused group, before services are parsed.
- **l.1815**: the database loop does the same for the first refused Postgres.
- `w8/019` (`.pm/w8/done/019.md:86`) converted only the per-service and per-Key-Value refusals to collected errors. The two earlier loops kept their early return, so their failures still mask everything parsed after them.

## Fix

Target: a manifest with independent errors in env groups, databases and services returns all of them in one `validate`, each located, in declaration order.

- Collect env-group and database refusals into the same `blueprintResourceErrors` accumulator the service loop uses, instead of returning. Keep going so services and Key Value still run their own checks.
- Keep `w8/019`'s rule that cross-reference pass 2 is skipped when any declaration was refused. It would only add cascades such as a service's `fromGroup` naming the refused group.
- Tests: one manifest with a bad env-group key, a bad database field and a bad service key yields three located errors. A manifest whose only error is a service `fromGroup` to a refused group yields just the group error (no cascade).

Blast radius: `validate` (REST, GraphQL `errorDetails`, MCP) and the apply path, which reads the first error. The apply path's output is unchanged because the aggregate still unwraps as the first error, as `w8/019` arranged.

Estimate: ~30m.
