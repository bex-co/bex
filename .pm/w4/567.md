# 567 — A cron job's Metrics page links Total Instances to "Manage scaling", which opens "Scaling isn't available"

Why: the link sends the user to a dead end. A cron job has no replica count, and the sidebar doesn't list Scaling for it either.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 81, 2026-11-11 07:12 UTC (`muse.env`, workspace `bex-canary`; production runs the code of `348bd77a5`). **Minor**: a dead-end link. ~15m.
- **Fixture:** owned Starter cron job `qa-20261111-cr81-longname-0030` (`srv-dbq19cak10fs73dvos2g`, busybox). Deleted at the end of the round.
- **Probe:**
  - **The link is there.** `https://dashboard.bex.co/services/srv-dbq19cak10fs73dvos2g/metrics?range=1h` → the Application Metrics card shows `Total Instances` with `link "Manage scaling"` → `/services/srv-dbq19cak10fs73dvos2g/scaling`.
  - **It leads nowhere useful.** That URL renders `heading "Scaling isn't available"` with "Scaling applies to web, private, and background services with long-running instances. This service type has no replica count to adjust."
  - **The sidebar agrees.** For this cron job it lists Deploys, Settings, Events, Logs, Metrics, Environment, Shell and Plan, with no Scaling.
- **Root cause:** `dashboard/src/features/metrics/components/application-metrics-card.tsx:286-292` renders the `Link` to `/services/$serviceId/scaling` for every service type that gets the card. `dashboard/src/routes/services.$serviceId.metrics.tsx:108` hides the card only for static sites.
- **Fix (target behavior):** hide the "Manage scaling" link for cron jobs, for example by passing the card the result of `supportsScaling(service)`, the predicate the scaling page already uses (`dashboard/src/routes/services.$serviceId.scaling.tsx:55-56`). Web, private and background worker services keep it. en and zh are unaffected, since the string is only removed.
  - **Test:** the card for a cron job has no "Manage scaling" link, and for a web service it still has one.
- **Unverified:**
  - Whether Render's cron job Metrics tab shows request and response-time charts. bex's Network Metrics card (Status Code, Host, Path, Total Requests, Response Times) also renders for this cron job, which ADR038 says has "no network shape". Not filed until Render's page is checked.
  - Background workers do scale, so their link is correct and was not probed.
- **Render:** Render offers no scaling for cron jobs.
- **Dedupe:**
  - `grep -rl "Manage scaling" .pm` hits only w4/m236's and w4/m147's captured page text, not this defect.
  - w4/297 (done) translated the chart names.
  - No open item covers this.
- **DoD (live):**
  - On an owned cron job's Metrics page there is no "Manage scaling" link.
  - On an owned Free web service's Metrics page the link is still there and opens its Scaling page.
