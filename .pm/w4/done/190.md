# w4/190 — Custom-domain add accepts `api.bex.co`, `localhost` and IP literals

Why: the reserved-host check guards `*.onbex.co` and the dashboard host but not the platform's other public hosts. Hostname validation also lets non-domains through, so tenants get pending domains with nonsense DNS instructions (a CNAME named `127.0`) that can never verify.

Live 2026-10-04 UTC (`/qa-find-bugs` loop7, muse.env, `bex-canary`). Owned Free static site `qa-20261004-l7-static` (deleted). Each accepted name was deleted immediately (`deleteCustomDomain` → `true`). Probe from the dashboard origin: `mutation($id:String!,$name:String!){ addCustomDomain(id:$id, name:$name){ id name domainType verificationStatus dnsRecord{type name value} } }`.

- **Refused (correct):** `hello-go.onbex.co`, `x.onbex.co`, `onbex.co`, `dashboard.bex.co` ("reserved platform hostname"), `*.qa-l7.example.com` (wildcard), `qa_l7.example.com`, `qa-l7.example.com:8443`, `qa-l7.example.com/path`.
- **Accepted (wrong):**
  - `api.bex.co`: `verificationStatus: pending`, `dnsRecord {CNAME, name: "api", value: "qa-20261004-l7-static.onbex.co"}`.
  - `localhost`: CNAME name `localhost`.
  - `127.0.0.1`: `domainType: subdomain`, CNAME name `127.0`.
  - `QA-L7.Example.COM.` normalized to `qa-l7.example.com` (correct). `xn--…` punycode accepted (fine).

Root cause:

- `lego/backend/internal/apps/domains.go:796-807` `reservedHost` reserves only `BaseDomain`, its subdomains, and `DashboardHost` (`hostOf(d.DashboardURL)`, wired at `internal/api/server.go:897`). The API host, the auth/Kratos host and the platform apex (`bex.co`) are not reserved.
- `domains.go:221-231` `canonicalHostname` validates with `validation.IsDNS1123Subdomain`, which accepts IPv4 literals and single-label names.
- Not a routing hijack today: in store mode a claim starts pending and is only projected into `spec.hosts` once verified (`AddDomain`, `domains.go` ~1183). Verifying needs DNS control of the zone. So this is defence in depth plus honest validation, not an exploit.

Fix:

1. Reserve every platform-owned host: derive a set from the configured public URLs (API/BEX_API base, Kratos public, dashboard, SSH gateway host, base apex) and refuse any host equal to one of them or under the platform apex. Keep the `reserved platform hostname` 400.
2. In `canonicalHostname`, refuse `net.ParseIP(host) != nil` and single-label hosts (no dot) with `invalid hostname`.
3. Make sure create/update `spec.hosts` and Blueprint-declared hosts run the same check (they share `checkHostsClaimable`). Add table tests for each accepted case above becoming a 400 while the refused set stays refused.

Adjacent: a refusal must not reveal whether another tenant claims a host. The cross-tenant collision keeps its existing 409 wording; only platform-owned names get the reserved message. Unverified: the auth host and SSH host names were not probed. Render: refuses its own `onrender.com` names and IP literals. Severity: minor. Estimate: ~45m.

Done 2026-10-04 (loopx): (1) `apps.Service.PlatformHosts` (the API host from BEX_API_PUBLIC_URL and the SSH gateway host, wired in `api/server.go`) join `DashboardHost`; `platformHostReserved` refuses each exactly and everything under their registrable apex (`bex.co`, so `auth.bex.co` is covered without wiring Kratos), skipping the BEX_BASE_DOMAIN apex whose own rule exempts each App's auto host; the existing `reserved platform hostname` 400 is kept and cross-tenant collisions keep their 409. (2) `canonicalHostname` refuses IP literals and single-label names. (3) Create/update `spec.hosts` and Blueprint hosts share both checks. Table test: api/auth/apex/dashboard/ssh, localhost, 127.0.0.1, 10.0.0.8, ::1 → 400; the previously refused set stays refused; `QA-L7.Example.COM.` still adds. Behaviour change: the old sibling-skip test (dashboard www.foo.com, add foo.com) became a reserved-apex test, since foo.com is now platform-owned. Backend suite + lint green.
