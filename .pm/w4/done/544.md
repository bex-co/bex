# 544 — Create-flow variable and secret-file rows name every row's fields identically: the Create environment group dialog ("Key", "Value", "Generate", "File name", "Contents", while Remove is numbered) and the New Service form (where even Remove is unnumbered)

Why: a screen-reader or voice-control user filling in three variables hears "Key, Value, Generate" three times, with nothing to say which row they are in. The same rows already announce "Remove variable 1", "Remove variable 2", and so on.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 15, 2026-11-10 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor** (accessibility: every control has a name, but no name says which row it belongs to). ~35m (was ~20m before the round-16 extension below).
- **Fixture:** env group `qa-20261110-eg` (`evg-dbpfrfk5ngvc73e8tmeg`), created through this dialog and then deleted (GET 404).
- **Probe:** on `/env-groups`, choose New Environment Group and open two variable rows and one secret-file row. The accessibility tree lists:
  - first variable row: `textbox "Key"`, `textbox "Value"`, `button "Generate"`, `button "Remove variable 1"`
  - second variable row: the same three names again, then `button "Remove variable 2"`
  - secret-file row: `textbox "File name"`, `textbox "Contents"`, `button "Remove secret file 1"`
- **Root cause:** `dashboard/src/features/env-groups/components/new-env-group-dialog.tsx` names each field after its column heading. Only the Remove buttons get the row number.

  | Control | Line | Key | Name today |
  | --- | --- | --- | --- |
  | Variable key | `:372-374` | `envGroups.varKeyLabel` | "Key" |
  | Variable value | `:392-394` | `envGroups.varValueLabel` | "Value" |
  | Generate toggle | `:427` | `envGroups.generateValue` | "Generate" |
  | Remove variable | `:434` | `envGroups.removeVar` | "Remove variable {index}" |
  | File name | `:471-473` | `envGroups.fileNameLabel` | "File name" |
  | File contents | `:491-493` | `envGroups.fileContentLabel` | "Contents" |
  | Remove file | `:513` | `envGroups.removeFile` | "Remove secret file {index}" |

  The keys are defined at `features/env-groups/locales/en.ts:37,45,53,57,78,86,94` and `zh.ts:36,44,52,56,77,85,93`.

- **Fix:** name each field with its row number, matching the Remove buttons:
  - "Variable {n} key" and "Variable {n} value"
  - "Generate value for variable {n}" (keep `aria-pressed`)
  - "Secret file {n} name" and "Secret file {n} contents"

  The visible labels and placeholders stay unchanged. Add en and zh keys, with a test in `features/env-groups/components/__tests__/new-env-group-dialog.test.tsx`.

- **Related:** [w4/541](541.md) (open) is the same class of bug in a different component (static-site rule and header rows). The env group detail editor already names values per key ("Value for MESSAGE", "Delete MESSAGE").
- **Dedupe:** `grep -rlE "new-env-group-dialog|Remove variable|varKeyLabel" .pm` finds only done items, and none of them is about control names:
  - mobile layout: w4/242, w4/270
  - `.env` import: w4/159, w4/273
  - scopes: w4/215, w4/220

  `git log c12cd57facb1..origin/main -- dashboard/src/features/env-groups` is empty.

- **DoD (live):** with two variable rows and one file row open, the tree lists `textbox "Variable 1 key"` … `button "Generate value for variable 2"` and `textbox "Secret file 1 name"`, in both en and zh.

## Extension, 2026-11-10 round 16: the New Service form (same pin `c12cd57facb1`)

The service create form is a sibling component with the same defect, and a worse one: even its Remove buttons are unnumbered. Fixture: Free web service `qa-20261110-badstart` (`srv-dbpg8hc5ngvc73e8tnk0`), created through `/services/new`; deleted, GET 404, URL 404.

- **Probe:** on `/services/new`, Add Variable twice. The accessibility tree lists `textbox "Key"`, `textbox "Value"`, `button "Generate"`, `button "Remove"`, and then exactly the same four again.
- **Root cause:**

  | Control | Location | Key | Name today |
  | --- | --- | --- | --- |
  | Variable key | `create-env-var-editor.tsx:63` | `services.createFieldEnvVarsKey` | "Key" |
  | Variable value | `create-env-var-editor.tsx:76` | `services.createFieldEnvVarsValue` | "Value" |
  | Generate | `create-env-var-editor.tsx:86` | `services.envGenerate` | "Generate" |
  | Remove variable | `create-env-var-editor.tsx:93` | `services.createFieldEnvVarsRemove` | "Remove" |
  | File name | `create-secret-file-editor.tsx:57` | `services.createFieldSecretFilesName` | |
  | File contents | `create-secret-file-editor.tsx:70` | `services.createFieldSecretFilesContent` | |
  | Remove file | `create-secret-file-editor.tsx:79` | `services.createFieldSecretFilesRemove` | "Remove secret file" |

  Both files are in `dashboard/src/features/services/components/`. The keys are defined at `features/services/locales/en.ts:3799,3803,3807,3837,3841,3845`, with matching zh keys. Each editor has one caller, `routes/services.new.tsx`, which serves all five service types.

- **Fix:** use the same per-row naming as the env group dialog:
  - "Variable {n} key" and "Variable {n} value"
  - "Generate value for variable {n}"
  - "Remove variable {n}"
  - "Secret file {n} name" and "Secret file {n} contents"
  - "Remove secret file {n}"

  Visible labels stay unchanged. Add en and zh copy.

- **Unverified:** the secret-file row names in the create form were read from source this round. Only the variable rows were probed.
- **Additional DoD (live):** on `/services/new` with two variable rows and one file row open, the tree lists `textbox "Variable 2 key"`, `button "Remove variable 2"` and `button "Remove secret file 1"`.

- **2026-11-11 (loopx w4):** fixed: in the Create environment group dialog and the New Service form, each row names its fields "Variable {n} key/value", "Generate value for variable {n}", "File name for secret file {n}", "Secret file {n} contents" and "Remove variable/secret file {n}" (en/zh `services.envRow*`/`fileRow*`; the dialog's own remove keys folded into them). The file-name field reads "File name for secret file {n}" rather than the DoD's "Secret file 1 name" so the name keeps the dialog's visible "File name" label (label in name); zh likewise keeps "键名"/"文件名".
