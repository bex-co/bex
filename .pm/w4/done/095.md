## The reveal gate holds where it matters — the DOM

The database page advertises "Connection strings and the database password. Revealed only when you ask". That claim is only meaningful if the secret is absent from the document, not merely hidden by CSS. Tested by fetching the real value in-page and asking whether *that exact string* appears anywhere, returning only booleans:

```js
const c = (await q(`{ databaseConnectionInfo(id:"dpg-…"){ password internalConnectionString } }`)).data.databaseConnectionInfo;
return { passwordLen: c.password.length,
         passwordInDOM: document.documentElement.innerHTML.includes(c.password),
         passwordInVisibleText: document.body.innerText.includes(c.password),
         connStringInDOM: document.documentElement.innerHTML.includes(c.internalConnectionString) };
```

```json
{"passwordLen": 64, "passwordInDOM": false, "passwordInVisibleText": false, "connStringInDOM": false}
```

Before any reveal there is exactly one control — `button "Reveal connection info"` — and neither the 64-character password nor the credentialed `postgresql://` URI exists in the page at all. The gate is a genuine fetch-on-demand, not a mask.

## Three near-misses, all mine

Recorded because two of them share one root cause that will bite the next pass:

1. **"The database page is missing 8 of its 10 sections."** `main` innerText was 698 characters with only Details rendered. Wrong — sampled mid-load; once settled it is **15,574** characters and every section is present.
2. **"Backups stopped on 09-13."** The list showed 23 entries ending 09-13. Wrong, and the same cause — a fully-settled page shows **24**, newest `20260914030000`, on all three databases.
3. **"Latest restore point is ~23 hours stale, identically on all three databases."** Wrong — a timezone misread. `2026-09-14T03:01:04Z` renders as `September 13, 2026 at 8:01 PM` at UTC-7, and the three render identically because the UI truncates to minutes while the underlying values differ by seconds (`03:01:04` / `03:01:35` / `03:01:08`).

The lesson worth carrying: **this dashboard renders progressively, and a single `waitForTimeout` is not a settle signal.** Both content near-misses came from reading `innerText` once. Take a length measurement, wait, take it again, and only trust a stable read — and convert every displayed local time to UTC before calling it stale.

Also confirmed not-a-bug: `/databases/<id>/connections` returns a real 404 page, but **no product link points there** — the section nav uses in-page anchors (`#connection`, `#sql-console`, `#recovery`, `#access-control`). The URL was this harness's own invention.
