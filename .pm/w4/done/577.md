# 577 — A registry credential accepts a host with an impossible port (`registry.example.com:99999`), so a credential no pull can ever use is saved without a word

Why: a mistyped port (an extra digit) produces a credential that looks fine in the list. Every image pull it's meant to authorize then fails, far from where the typo was made. Both the dialog and the API take it.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 116, 2026-11-11 15:37–15:41 UTC (`muse.env`, workspace `bex-canary`; release pin `f609163ada8e`, which includes w21/053). **Minor**: input validation. ~20m.
- **Probe:**
  - **Dialog.** Workspace Settings → Registry Credentials → Add registry credential, with Username `qa` and a dummy token, typing each host and blurring:
    - marked invalid with "Enter a registry host such as ghcr.io or registry.example.com:5000, without a path.": `ghcr.io/owner`, `[::1]:5000`, `ghcr.io:`, `gh cr.io`, `-bad-.example.com`, `index.docker.io/v1/`;
    - accepted: `ghcr.io`, `https://ghcr.io` (the server strips the scheme), `registry.example.com:5000`, `localhost:5000`, `GHCR.IO`, and **`registry.example.com:99999`**.
  - **The bad port is stored.** Add with `registry.example.com:99999` and Display name `qa-20261111-r116-rc` → toast "Added a credential for registry.example.com:99999".
    - `GET /v1/registrycredentials/rgc-dbq8obfpvbns739s7an0` → 200 `{"host":"registry.example.com:99999","status":"active",…}`.
    - Deleted afterwards (DELETE 204, then GET 404).
- **Root cause:**
  - The server's `registryHostPattern` (`lego/backend/internal/registrycreds/host.go:36-38`) ends in `(:[0-9]{1,5})?`. Any 1–5 digits pass, including `0` and anything from `65536` to `99999`.
  - The dashboard mirrors the same regular expression (`dashboard/src/features/registry-credentials/lib/credential-fields.ts:20`), so the two agree on accepting it.
- **Fix (target behavior):**
  - A host's port, when present, must be 1–65535 with no leading zero, in both `canonicalRegistryHost` (`host.go:56-71`) and `credential-fields.ts`.
  - Outside that range: the server answers 400 with the existing "host must be a registry host such as …" message, and the dialog marks the field with the same text.
  - **Every entry point:** REST `POST /v1/registrycredentials`, GraphQL and MCP create go through `Service.Create` → `canonicalRegistryHost` (`registrycreds/service.go:225-248`), so one change covers all three.
  - **Stored rows:** `sameRegistryHost` (`host.go:76-81`) canonicalizes stored hosts. A stored `:99999` row must keep loading and stay deletable rather than erroring on read.
- **Unverified:** whether any existing credential in production stores an out-of-range port. Query before tightening the read path.
- **Render:** n/a. Render's registry credential names a registry type, not a host:port.
- **Dedupe:**
  - w21/053 (done) added the inline host marking that mirrors the server rule, and the rule itself is what lets the port through.
  - `grep -rln "99999" .pm` finds nothing about registry hosts.
  - Not deploy lag: `host.go:38` is unchanged on `origin/main`.
- **DoD (live):** in Workspace Settings → Add registry credential:
  - `registry.example.com:99999` and `registry.example.com:0` are marked invalid and Add stays disabled;
  - `POST /v1/registrycredentials` with either host answers 400;
  - `registry.example.com:5000` and `localhost:5000` are still accepted.

- **2026-11-11 (loopx w4):** done. A registry credential's host port must be 1–65535 with no leading zero, in bex-api's `registryHostPattern` and the dialog's `REGISTRY_HOST`, so `registry.example.com:99999`, `:65536`, `:0` and `:05000` answer the existing 400 and are marked in the dialog; `:5000`, `localhost:5000` and `:65535` still pass. Stored rows keep loading (list/get map an unparseable host to no Render registry). Tests: the shared host vectors in `host_test.go` and `credential-fields.test.ts`.
