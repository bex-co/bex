## Objective

`GET /v1/metrics/http-requests` (and the GraphQL/MCP/dashboard reads over the same verb) returns `[]` for a static site that just served dozens of requests, because the PromQL selector targets a per-App Kubernetes Service that static sites do not have. Route the static-site request-count query through the same Ingress-router attribution the bandwidth read already uses.

## Context

### The observation (production, 2026-09-17)

Static site `srv-dam398js0ils73bgp0lg`, ~25 requests over ~10 minutes (verified 200/301/404 at the edge with `curl -D`): dashboard Total Requests "No data in range"; GraphQL `metrics(name: HTTP_REQUESTS)` → `[]`; REST `/v1/metrics/http-requests?resource=…` → `200 []`. Same window, same service: `BANDWIDTH` → nonzero series, month-to-date 16 KiB. Not lag (bandwidth from the same scrape pipeline is current) and not rate-vs-count (m108): the series are absent, not zero.

### Root cause (read, not guessed)

`promQueryFor` (`lego/backend/internal/metrics/source.go:389-414`) builds the requests query as `sum(increase(traefik_service_requests_total{service="<ns>-<app>-<port>@kubernetes"}…))` via `traefikServiceLabel` — the per-App Service. Static sites have no Deployment/Service for served content (ADR029: each static host's Ingress points at the shared static-server's Service), so the selector matches nothing. Bandwidth works because it goes through `egressquery.App(AppID, Routers, Direct=false)` (`source.go:394`), which selects on the App's Ingress router names resolved by `TraefikRouterNames` — the exact mechanism ADR018 row 84 promises ("the static site's Ingress routers attribute Traefik series per App").

### Fix shape

- For `TypeStaticSite` (the `Direct=false` case `readRequestSeries` already computes at `service.go:998`), build the `http_requests` query on Traefik's per-router counters (`traefik_router_requests_total{router=~"<routers>"}`) with the already-resolved `req.Routers`, keeping the m108 per-bucket `sum(increase())` count semantics, unit `count`, and the `statusCode` matcher + `groupBy` behavior (router series carry `code`; verify, don't assume).
- Compute-service queries stay byte-identical (same PromQL as today); the branch is type-gated, not a shared rewrite.
- `req.Routers` is currently resolved only for bandwidth (`service.go:975-982`) — extend resolution to the requests path (or resolve once for all request metrics).

### Acceptance

- Unit coverage on the query builder: static input yields a router-scoped `traefik_router_requests_total` query; web-service input yields today's service-scoped query unchanged.
- The live re-probe in t007 is the semantic proof (no cluster access at filing time); the builder test is the regression guard.
