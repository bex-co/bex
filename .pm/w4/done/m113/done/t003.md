## Objective

`metricsFilters` returns `STATUS_CODE: []` (and `INSTANCE: []`) for a static site with real traffic, so the dashboard Status Code filter has nothing to offer. Discover filter values from the same router-scoped series t001/t002 query.

## Context

### The observation (production, 2026-09-17)

Same fixture: GraphQL `metricsFilters(resource, outputFilters: [INSTANCE, STATUS_CODE])` → both `[]`; the Metrics page Status Code dropdown consequently offers no values while the site served 200s, 301s, and 404s.

### Root cause (read, not guessed)

The filter discovery query at `lego/backend/internal/metrics/source.go:681` matches `traefik_service_requests_total{service="<traefikServiceLabel>"}`
— the same dead per-App-Service selector as t001. INSTANCE is honestly empty for static (no pods — the w5/m48 type-gating already drops instance UI), but STATUS_CODE must come back.

### Fix shape

- For static sites, discover status codes from the router-scoped request series (label values of `code` on the t001 selector). Keep the response shape (`field: STATUS_CODE`, sorted values) identical to compute.
- INSTANCE stays `[]` for static (no instances exist) — document that as intended in the code comment so the next reader doesn't "fix" it.
- REST `/v1/metrics/filters/http` rides the same verb — verify it returns the codes too (no separate fix expected).

### Acceptance

- Unit test: static discovery input emits the router-scoped label-values query; compute input unchanged.
- Dashboard Status Code dropdown offers the observed codes on a static Metrics page (verified in t007's live pass).
