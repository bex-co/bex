## Objective

Make `recheckBeforeDispatch` and the enable/disable decision use one rule, and never abort silently.

## Context

- `dashboard/src/features/deploys/components/deploy-actions.tsx:100-107` (`decisionForSelectedRollback`) and `features/capabilities/hooks/use-bound-action-confirm.ts:140-148` (raw decision, `{ok:false}`). `handleConfirm` returns with no feedback on `!ok`.
- The backend verb validates the exact named target, so the dispatch can either apply the same selected-row override or simply send the mutation and surface its named 409.

## Acceptance criteria

- [ ] A refused recheck shows a toast or alert with the reason. It is never a silent return.
- [ ] An eligible older row on a service whose latest-20 summary says `no_eligible_rollback_target` dispatches (the `w6/m143/t003` intent).
- [ ] Cancel's parallel override (`no_active_deploy`) gets the same treatment at dispatch.

## Result (2026-09-27)

`useBoundActionConfirm` takes an `adjustDecision(action, decision)` and applies it to the rechecked decision. `DeployActions` passes one `rowDecision`, the same function that enables its buttons (the rollback selected-row override and the cancel `no_active_deploy` override). Every refusal (stale binding, failed recheck, blocked or denied decision) is now toasted with its reason inside the hook, which also fixes the same silent return in `service-row-actions.tsx` and `suspend-service-card.tsx`.
