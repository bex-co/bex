## Objective

Write down the thing that was never true: the complete set of variables the platform puts in a tenant container.

## Context

- ADR004's `envVars` section and `appEnv`'s doc comment both say `PORT` is the only platform-injected variable. Live, the container had 185 variables and 5 of them were the user's or bex's.
- The supported way to reach a sibling is the private-network address `<slug>:<port>` (ADR041 D4, `w9/m58`), surfaced in the dashboard as Service Address. That is what replaces the link vars for anyone who was using them.
- `w2/m95`/ADR018 row 117 already documents `PORT` as reserved; this extends the same section rather than opening a new one.

## Steps

1. State the complete injected set in ADR004 — `PORT`, and nothing else — and note that service links are deliberately disabled and why.
2. Name the sibling-discovery path in the same place, so removal comes with its replacement.
3. Add a line to `docs/ADR018-render-parity.md` recording how the delivered environment compares with Render's.
4. Fix `appEnv`'s doc comment if t001–t003 made its claim true; if any site still injects, say which.
