# 049 — Workspace-wide Search palette collapses every service to a generic "Service" label + Globe icon, ignoring `service.type` (sibling entrypoint of w4/047)

Why: the Cmd-K search palette labels a cron job, a private service, and a web service all identically as "Service" with the same Globe icon — the same "type collapsed" symptom as 047, but in a different component 047's blast radius explicitly excludes, so a fix to 047 alone leaves this entrypoint wrong.

Found in a live `$qa-find-bugs w4` hunt of `dashboard.bex.co`, 2026-09-06, workspace `tian-personal` (`tea-da2isimlm39c739m4ofg`). Read-only for this finding.

Severity: minor (cosmetic label + wrong icon; search still functions).

## Symptom

The workspace-wide Search command palette (header "Search" button / Cmd-K) lists every service under "Resources" with the single generic label **"Service"** and a single **Globe** icon, regardless of the service's actual type. Live, the palette showed all three services identically labeled "Service": `tianpan-v4-web` (web_service), `qa-20260906-private` (private_service), and `qa-20260906-private-probe` (cron_job) — a cron job and a private service both read "Service" with a Globe glyph.

Same symptom class as **w4/047** (resource-list Type column), but a **different component and code path**: 047 is the projects resource-table (`ResourceTypeBadge`); this is the global search dialog, which 047's blast-radius note explicitly excludes ("`ResourceTypeBadge` has exactly 2 call sites, both in `resource-table.tsx`"). Filed separately so the fix reaches both entrypoints — whoever fixes should do 047 and this together.

## Repro

1. Sign in; press the header "Search" button (or Cmd-K) anywhere in the dashboard.
2. Under "Resources", read each service's kind label + icon — all read "Service" with a Globe, regardless of type.
3. Confirm via API the underlying types differ (this workspace): `srv-daf4utsrrsrs73ev9jb0` = cron_job, `srv-daf4sgcrrsrs73ev9j80` = private_service, `srv-da40m1qii7bs73drbqlg` = web_service.

## Expected / Actual

- Expected: each service result shows its specific type label (Web Service / Private Service / Background Worker / Cron Job / Static Site) and the matching type icon, consistent with the service detail header and Render's search.
- Actual: every service shows generic "Service" + Globe.

## Evidence

- `.playwright-mcp/qa-search-01-service-type-collapse.png` — palette open, three services all labeled "Service".
- Durable DOM read of the open dialog: `Resources / qa-20260906-private / Service / qa-20260906-private-probe / Service / tianpan-v4-web / Service`.
- Types confirmed live via GraphQL earlier this session (`query { service(id){ name type } }`): cron_job / private_service / web_service.

## Root cause

`dashboard/src/common/components/dashboard-layout/global-search-dialog.tsx` — the service results map (lines ~240-268) renders a hardcoded `<Globe2 />` (line 262) and a hardcoded kind label (line 265: `kind={t("common.topbarServiceResource")}`) for **every** service, even though `service.type` is in scope (already read at line 248, `serviceBaseForType(service.type)`, for routing). `common.topbarServiceResource` = "Service" (`src/common/locales/en.ts:136`, description "Service kind label in workspace-wide search results"). So the palette has the type but discards it for display.

## Fix (name the target behavior)

For each service result, derive the per-type label and icon from `service.type` via the existing shared helpers `deriveServiceType` / `SERVICE_TYPE_LABEL` / `SERVICE_TYPE_ICON` (`dashboard/src/features/services/lib/service-type.ts`) — the same helpers w4/047 proposes reusing for the resource-table. Replace the hardcoded `Globe2` (line 262) with `SERVICE_TYPE_ICON[deriveServiceType(service.type)]` and the hardcoded kind (line 265) with `t(SERVICE_TYPE_LABEL[deriveServiceType(service.type)])`. Dashboard-only; no backend change (`service.type` is already returned, verified live). Optional enhancement: fold the specific type words into the cmdk `value` string (line 243, currently `` `${name} ${id} ${t("common.topbarServiceResource")}` ``) so typing "cron"/"private" matches — but keep a generic token so "service" still matches all.

## Blast radius

`common.topbarServiceResource` is used in `global-search-dialog.tsx` at line 243 (the fuzzy-match `value`) and line 265 (the displayed kind). Changing the **display** (265) + icon (262) to per-type does not affect matching if line 243 retains a generic token. `grep -rn topbarServiceResource dashboard/src` to confirm the two sites. `Globe2` import may become unused if no other service row keeps it — check before removing. No shared helper beyond the service-type lib (already widely used). Add a global-search test asserting a cron/private service row renders its specific label + icon, not "Service"/Globe.

## Adjacent / unverified

- Databases and key-value rows in the palette use `t("databases.resourceType")` / `t("keyvalue.resourceType")`; whether those match Render's "PostgreSQL" / "Key Value" was not assessed (out of scope; same open question noted in 047).
- Static-site routing is already type-aware here (line 248), so only the label + icon are wrong, not navigation.

## Render

Render's global search / command palette shows each resource's specific type, not a single generic "Service".

Estimate: ~20–30 min (swap the two hardcoded values for the shared type helpers + a palette test; the label/icon maps already exist). Do together with **w4/047** — same symptom, two entrypoints.

## Resolution (2026-09-07)

Done. `global-search-dialog.tsx` now derives each service result's label and icon from the shared `deriveServiceType` / `SERVICE_TYPE_LABEL` / `SERVICE_TYPE_ICON` helpers instead of a hardcoded `Globe2` + `common.topbarServiceResource` — so the Cmd-K palette names a Cron Job / Private Service / Web Service by its kind with the matching glyph. The fuzzy-match `value` keeps the generic "Service" token AND appends the specific type words, so typing "service" still matches all while "cron"/"private" now match too. The now-unused `Globe2` import was removed. Dashboard-only; no backend change. New `global-search-dialog.test.tsx` asserts typed rows render their specific labels, the generic "Service" is gone, a clock icon renders for the cron row, and the old `lucide-globe-2` glyph is absent. `yarn typecheck`/`yarn lint`/dashboard tests green. Shipped with **w4/047** (same symptom, two entrypoints). Live re-probe of the deployed fix deferred to the next QA pass.
