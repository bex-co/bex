## Objective

Give operators a durable, audited record of each attack window and a bearer-guarded control-plane verb to declare, extend, withdraw and list them.

## Context

- The control-plane mux (`lego/backend/internal/store/api.go`, `Handler`) is served on bex-api's internal `:8091` listener behind `a.bearer`, beside `billing-override` (`BillingOverrideRequest` carries `actor` and `reason`), `billing-excluded` and `billing-export`. Never mount this on the public `:8090` mux (ADR088 §4's reasoning in `internal/opsrole`).
- Migrations live in `lego/backend/internal/store/migrations/` (the newest is `0353_*` at `b0474cf448`; take the next free number when you write it).
- Ids are minted only through `lego/backend/internal/id` (`id.New(kind)`) if the window gets a public id (lego/AGENTS.md).

## Steps

1. Migration: `egress_attack_windows` (or a name that fits the store) with workspace id, optional service ids, `starts_at`, `ends_at`, actor, reason, created and withdrawn timestamps. Index it for "windows of workspace W overlapping hours [a, b)".
2. Store methods: declare (refuse `starts_at >= ends_at`, an unknown workspace, a service outside the workspace, and a window over a bound you choose and record), extend, withdraw (keep the row, set `withdrawn_at`), list per workspace, and an overlap read for t003.
3. Control-plane routes, for example `POST|GET /v1/tenants/{id}/egress-attack-windows` and `PATCH|DELETE …/{windowId}`, with `actor` and `reason` required, as `billing-override` requires them. Log each change the way the billing overrides do.
4. Store tests against the real database (the backend suite's Postgres), plus handler tests for the refusals.
