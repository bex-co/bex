## Objective

Make every reader that turns `egress_bytes` into money, allowance or a spin-down treat an hour a live (not withdrawn) window overlaps as zero, while the usage row keeps the bytes it measured.

## Context

- `lego/backend/internal/billing/emitter.go`: `billedAboveAllowance` computes a row's owed quantity from `UsageBefore` and the plan's allowance and stores it as `BilledQuantity`. Rows seal `DefaultSealHours` (48 h) after their hour, so a window declared within that time is in place before the row ships.
- `lego/backend/internal/store/billing.go`: `UsageBefore` / `usageBeforeQuery` sums the month's earlier `egress_bytes` rows.
- `lego/backend/internal/store/usage.go`: `monthUsageByWorkspace` (used by `EgressBytesByWorkspace` for `lego/backend/internal/bandwidth`) unions `usage_hourly` with `usage_monthly`. Compaction writes `usage_monthly` around `usage.go:840`.
- `lego/backend/internal/bandwidth/bandwidth.go` resumes a spun-down workspace once `u.Quantity >= included` no longer holds, so a correct sum lifts the spin-down by itself.
- The usage read behind `GET /v1/usage`, GraphQL `usage` and MCP `get_usage` (`lego/backend/internal/usage`), and the Outbound Bandwidth footer `MonthToDateBandwidth` (`lego/backend/internal/metrics/service.go`). The footer reads Prometheus and sums the billed per-hour figure, so ended hours inside a window must be subtracted there too, or the footer and the bill disagree (ADR023 § New series count from zero says they agree).

## Steps

1. Pick one place the exclusion is computed. For example, a store helper that returns the excluded `(workspace, service, hour)` set, or a column on `usage_hourly` that a declaration and the rollup set. Make every reader below use it. Record the choice in ADR023's section from t001.
2. Emitter: a row inside a window sends 0 and is recorded as billed 0. A window withdrawn before the row ships leaves it billed normally.
3. `UsageBefore`: a window's hours use none of the allowance.
4. `monthUsageByWorkspace` and compaction: a window's hours stay out of the month's sum, including after compaction to `usage_monthly`.
5. Usage read and footer: report the billed bandwidth without the window's hours. The service's bandwidth chart is unchanged.

## Files

- `lego/backend/internal/billing/emitter.go`, `lego/backend/internal/store/{billing,usage}.go`, `lego/backend/internal/usage/`, `lego/backend/internal/metrics/service.go`, and their tests

## Acceptance criteria

- [x] Tests show, for an hour inside a window: Stripe quantity 0, the next hour billed as if the window's bytes never counted, no spin-down from those bytes (and a resume when they were the cause), the usage read and footer without them, and the same after compaction.
- [x] An hour outside every window, and a withdrawn window's hours, bill exactly as before (a test pins it).
- [x] `cd lego/backend && go test ./...` and `make lint` pass.
