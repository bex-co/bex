## Resolution (2026-08-15)

Already implemented via the `ensure:absent` tombstone the task's own steps proposed. `DeleteUser` (`lego/backend/internal/postgres/access.go`) removes the role from `spec.users` **and** appends it to `spec.deletedUsers`; the `Database` CR carries `DeletedUsers []string` (`lego/types/v1alpha1/database_types.go`), and the operator's `managedRoles` projects each as `{"name": …, "ensure": "absent"}` so CNPG drops the live role from PostgreSQL (`lego/operator/internal/controller/database_controller.go`). This closes the "removal from spec.managed.roles only stops managing, not drops" gap the finding named. Landed under the codex #8 pass. **This closeout backfilled the two missing test assertions** (t009): `TestUsersCRUD` now asserts the tombstone is recorded, and `TestCnpgClusterSpecManagedRoles` now asserts a deleted user projects `ensure:absent` (no `login`), even with no remaining present users.

Note: the chose-`ensure:absent`-over-`NOLOGIN` design drops the role outright and will fail if the role owns objects; `pg_terminate_backend` for already-open connections remains out of scope as the task specified.

## Objective

`DeleteUser` removes the user from `spec.users` and deletes the password Secret, then returns success. CNPG treats removal from `spec.managed.roles` as "stop managing", not "drop" — so the role keeps its password and `LOGIN`, and a supposedly revoked credential still opens a session.

## Context

- `lego/backend/internal/postgres/access.go` — the doc comment already names the gap ("dropping the role from Postgres outright would need an `ensure: absent` tombstone, out of scope for basic CRUD"). This task closes what that comment deferred.
- `lego/operator/internal/controller/database_controller.go` — `managedRoles` emits `"ensure": "present"` only, so nothing in the projection can express removal.
- Design choice to make: `ensure: absent` (CNPG drops the role — fails if the role owns objects) vs. `ALTER ROLE ... NOLOGIN` (always succeeds, leaves owned objects intact). `NOLOGIN` is the safer default for a tenant database; dropping is the more complete revoke.

## Steps

1. Add a tombstone to the `Database` CR contract (`lego/types/`) so a removed user can be projected as `ensure: absent` — or as a `NOLOGIN` role — rather than simply vanishing from the spec.
2. Project it in `managedRoles`.
3. Make `DeleteUser` wait for the operator/CNPG to confirm the role is gone or `NOLOGIN` before returning; only then delete the Secret and report success. A revoke that cannot be confirmed must not 204.
4. Reap the tombstone once confirmed so `spec.users` does not grow without bound.

## Acceptance criteria

- [ ] An integration test authenticates as a managed user, deletes it through the API, and proves the old credentials can no longer establish a session **before** the API returns success.
- [ ] The Secret is deleted only after revocation is confirmed.
- [ ] A role that cannot be revoked (owns objects, cluster unreachable) surfaces an error instead of a false success.

## Out of scope

- Session termination for already-open connections (`pg_terminate_backend`) — note it in the docs if not implemented.
