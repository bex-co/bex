# Project resource filters lose typed input and revert a just-selected resource type

Why: an ordinary search after opening a project can silently change the user's text and selected type, producing an empty result for a resource that exists.

**Severity:** minor (filter/navigation friction; resource data is unchanged). **Estimate:** 55m. Functional `$qa-find-bugs w4` pass a256, 2026-10-11 local / 2026-10-12 UTC. Researched on main `aeeba21e7cd5a56a0f59d5a0ffe7d17fa457aff0`. Filing only.

## Observed journeys and target

Owned project **qa-20261011-a256-filters** / `prj-db65cmeui45s738uptj0` contains two environments. First environment **qa-a256-first-雪** / `evm-db65cu6ui45s738uptk0` contains two empty Environment Groups: **qa-20261011-a256-first-雪** and **qa-20261011-a256-second**. The second environment is empty. Fresh API reads confirm that placement.

1. Freshly load `/project/prj-db65cmeui45s738uptj0?env=evm-db65cu6ui45s738uptk0&kind=services`. Wait for the search input and **Env Groups (2)** button. Services correctly gives no matches because this fixture contains only groups.
2. Click **Env Groups (2)**, focus the search input, and type **second** normally. Two complete fresh repeats used 80ms and 100ms per character. Each ends with **econd** in the input and URL, **kind=services**, Services still selected, and **No matching resources**. A third fresh screenshot repeat shows the same result.
3. The first repeat captures the intermediate contradiction: after the click the URL already has **kind=envgroups**, but Services still has the selected button styling. The subsequent input event sends the old kind back.
4. Independently, fresh-load the same environment with **kind=envgroups** already settled, then type **second** at 100ms per character. It still becomes **econd**; the group matches this suffix and is shown. This traces the input-loss symptom without needing a type change.
5. Passing controls: select Env Groups again and wait for its settled result; the second group is found by its ID fragment. A later warm-page Services→Env Groups→typing sequence retains **second** and **kind=envgroups**. Unicode search **雪** narrows to the first group; Select all visible selects one row. Selecting both unfiltered groups and switching to the empty environment clears query/type; switching back has **Selected: 0**.

**Target:** the controlled input synchronously retains the exact text entered, including its first character. Clicking Env Groups and then typing preserves **kind=envgroups** and **second**, immediately displays the matching group when data is available, and serializes that complete state to the shareable URL. Preserve the empty Services control, literal name/ID search, pre-search environment counts, visible-row selection, and the existing environment-switch reset. This is timing-dependent; the warm passing capture is retained. No interception or artificial network delay was used.

## Traced cause and installed framework

- `dashboard/src/routes/project.$projectId.index.tsx:52–59` derives the entire rendered filter from **Route.useSearch()**. `:61–69` replaces URL search through asynchronous navigate with no urgent local filter-state update.
- `dashboard/src/features/projects/components/project-resource-filters.tsx:50` handles a type click by spreading the rendered filter and replacing kind. `:60–62` controls the input with filter.query and handles each keystroke by spreading that same rendered filter and replacing query. During a pending route update that prop still has the previous kind/query. These are the separately traced producers of the kind reversal and input rollback.
- `features/environments/components/environment-card.tsx:323–329` forwards the callback and stamps its environment ID; `environments-panel.tsx:310–318` supplies the same component for Unassigned. Neither supplies independent urgent input state. `common/components/ui/input.tsx:5–21` forwards value/onChange to the native input.
- Actual installed **@tanstack/react-router 1.170.25** and **@tanstack/router-core 1.171.21**, verified from package.json and pinned at `dashboard/yarn.lock:4823–4825,4962–4964`: `react-router/src/useSearch.tsx:95–104` reads match.search through useMatch; `useMatch.tsx:145–184` subscribes to the match store. `Transitioner.tsx:31–45` runs the router publication inside **React.startTransition**. `router-core/src/router.ts:2145–2223,2270–2298` commits history separately and returns a completion Promise; `src/load-client.ts:1483,1717` publishes match state through router.startTransition. Browser URL change therefore is not proof that the rendered filter prop has committed.
- Actual installed **React/React DOM 19.2.3**, verified from package.json and lock resolutions at `:10353,10520`: `react-dom/cjs/react-dom-client.development.js:3178–3195` restores a controlled input using its current props.value; `:3251–3272` performs controlled-state restoration after the event batch. A route transition is not the synchronous controlled-input update required here. [React's input documentation](https://react.dev/reference/react-dom/components/input) explains that asynchronous value updates can revert typed input; [transition documentation](https://react.dev/reference/react/useTransition) excludes controlled input updates from transition state.

The fresh click capture shows the old button state after history changes, matching that split. The warm pass is possible when the route value commits before the next input event; the exact cache/scheduling contribution to that timing difference was not isolated. No claim that every keystroke or every filter edit fails is made.

## Concrete scoped fix and work

1. **20m — own urgent filter intent in ProjectPage.** Keep a synchronous local full filter draft (environment, query, kind) and render controls/results from it. Update it during each user event before navigating. Serialize the latest complete draft with replace semantics; do not reconstruct later edits from an older Route.useSearch snapshot. A local query-only fix still permits the kind reversal. Functional URL-search updates alone do not fix controlled-input restoration.
2. **15m — shared-state and URL synchronization audit.** Keep committed URL hydration/reload, direct navigation and Back/Forward authoritative when they are external navigation. A completion from an older self-issued replacement must not overwrite newer draft intent or resurrect old filters; associate pending intent/completion with its generation or equivalent exact-state acknowledgment. Environment selection must synchronously apply the existing query="" / kind="all" reset, and canonicalization must preserve the latest active query/kind. Do not add a generic router abstraction, globally force sync transitions, patch shared Input, or remove shareable search.
3. **20m — meaningful router tests and live acceptance.** Mount the real project filter with the actual TanStack router and React controlled input. Exercise a first asynchronous search/type transition, typing at normal event cadence, an older completion arriving after newer intent, and the warm passing control. Verify exact typed text and selected kind, correct filtered rows/URL, environment switch and the two shared mounts. Repeat the actual live journeys with owned groups, then delete fixtures and revoke the session.

Exhaustive production grep: **1 ProjectPage callback owner/mount**, **1 EnvironmentsPanel mount** in the project route, **1 EnvironmentCard mount** in that panel, and **2 ProjectResourceFilters mounts** (EnvironmentCard and UnassignedResources). EnvironmentsPanel has **2** callback-producing branches: default/missing-environment canonicalization at `:139–143` and explicit environment selection at `:175–179`. The fix is allowlisted to this project filter state and its callbacks; other route-backed search inputs need their own repro before being changed.

Resource family: the shared row matcher covers services (web/static/cron/worker/private), Postgres, Key Value, and Environment Groups; Projects and Blueprints are outside this environment's resource filters. The project overview canonical URL is `/project/<id>`; its q/kind/env search parameters must remain encoded, reloadable and shareable. No API field, membership write, REST/GraphQL/MCP semantics or resource-selection action changes.

Adjacent states: while membership lists load, preserve current loading/error presentation and entered intent. Successful complete no-match stays empty; an empty environment keeps its distinct empty-state copy. Failed reads, timeout and session/permission refusals retain current route/hook handling. Counts remain scoped to the environment before text filtering. Preserve literal trimmed case-insensitive matching and existing API data.
