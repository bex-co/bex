# The name a Blueprint manifest matches on is the one name the dashboard never shows

Why: a manifest's `services[].name` matches a service's **immutable** name, and `immutableName` is rendered on no dashboard surface — so a user writing IaC from what the UI shows can get a silent `create` (a duplicate service) where they meant `update`, and today only a coincidence keeps that from happening.

Found by live `/qa-find-bugs` 2026-09-21 pass 134 (w4-targeted, `muse.env` credentials). The blueprint probes were read-only `validateBlueprint` calls; the rename repro used two `qa-`-prefixed static sites, both deleted.

## The three names

`w6/m115` settled this deliberately and the contract is right — this note is not asking to reopen it:

- **`name`** — the mutable display label (`displayName` when set, else the immutable name). What every read surface returns and the dashboard headlines.
- **`immutableName`** — workspace-unique, addressable, minted at create.
- **`slug`** — the global public host fragment. Starts equal to the immutable name; gets a random `-xxxx` suffix if another **tenant** already holds the bare slug (`store/store.go:860-898`, `isSlugConflict` → retry).

A Blueprint manifest's `name` matches the **immutable** name: `blueprint_ownership.go:178-183` `appServiceName` reads `core.LabelServiceName`, documented at `core/base.go:177-184` as "the workspace-scoped name a caller creates and reaches it by, as opposed to metadata.Name".

## Live, on a real production service

`eden-dash-v3` was renamed at some point: `name: "eden-dash-v3"`, `immutableName: "block-eden-mono"`, `slug: "block-eden-mono"`, `url: https://block-eden-mono.onbex.co`.

```graphql
validateBlueprint(bexYaml: <services: - name: eden-dash-v3 …>)
→ plan.actions = [{ kind: service, name: eden-dash-v3, operation: "create" }]

validateBlueprint(bexYaml: <services: - name: block-eden-mono …>)
→ plan.actions = [{ kind: service, name: block-eden-mono, operation: "update" }]
```

The name the dashboard shows in the header, the breadcrumb, the service list, and the Service Name field plans a **create**. The name it does not put in any of those places plans the **update**. Nothing in the plan says the author probably meant the other one.

## What saves it today, and what doesn't

The settings page does render a `Slug` definition row (`Slug: block-eden-mono`) and the service URL, so for **every service in this workspace** the manifest key is on screen — just labelled something else. That is why this is a small note and not a milestone.

The gap is that `Slug` is not the same field as `immutableName`, and they diverge exactly when another tenant got the bare slug first. `grep -rn immutableName dashboard/src/` returns **2 hits**, neither a render: `features/services/lib/status.ts:35` (a local variable, not the API field) and `graphql/schema-types.ts:3463` (generated). So for a service whose slug carries a `-xxxx` suffix **and** whose name was changed, no dashboard surface shows the key a manifest must use.

## Fix

Small, and either half helps:

- Render `immutableName` where it differs from the display label — the existing `Slug` definition list is the natural place, as a sibling row labelled for what it is (the name the API and Blueprint manifests address the service by).
- Say in the Blueprint docs / `/blueprints/new` help text that `services[].name` matches the immutable name, not the display label.

Estimate: ~30m for the dashboard row plus the doc line.

The renamed-service half was confirmed live on `eden-dash-v3`.

## Also checked this pass, and found correct

The static-site serving surface (journey 9) was exercised end to end on a real `qa-` site and every promise held — worth recording so nobody re-runs it:

- **Routes and headers take effect on the served response, within seconds of the mutation and with no redeploy.** `curl` from outside the browser: `/old-page` → `301` with `location: /index.html`; a rewrite of `/rw-page` → `200` serving the index body; `X-QA-Pass: 134` present on every response.
- **`:splat` works.** `/blog/* → /posts/:splat` gives `/blog/hello-world` → `301 location: /posts/hello-world`, matching ADR029:116.
- **Header path scoping is exact.** A header scoped to `/index.html` appears on `/index.html` and **not** on `/`, even though `/` serves the same object.
- **Replacing the route set replaces it.** After `setStaticRoutes` with a new list, the old `/old-page` redirect stopped firing.
- **A 200 on an extension-less miss is deliberate**, documented at ADR029:120-124 as an accepted Render divergence; extension-bearing misses (`/missing.css`, `/a/b/deep/missing.png`) correctly `404`. Do not re-file this.
- **Rejecting an absolute redirect destination is deliberate too** — `routes[2].destination must be a path starting with /` is the open-redirect guard at `apps/service.go:4277-4294` and the ADR029:36 threat model. Not a parity bug.
- **Suspend/resume keeps the certificate.** A suspended static site answers `404 no static site for host` over the valid Let's Encrypt `*.onbex.co` certificate — no TLS error, which is the `w3/m46` regression this used to be. Resume restored `200` **and** the route/header rules intact.
- **Delete frees the name in the right order.** After `DELETE`, the by-id read is `app not found` within 500ms while `serviceNameAvailable` still reports the name taken, flipping to available ~10s later — conservative in the safe direction.

## Resolution — 2026-09-22

Done. The shared service detail header (including Settings) now shows **Blueprint name** beside Slug when `immutableName` differs from the display label. The Server query selects the existing API field and the mapper carries it independently of slug; localized keyboard-accessible help explains `services[].name`. ADR049 documents the immutable-name contract and why a suffixed slug is not a substitute. MCP already distinguishes mutable `displayName` from the immutable service name in update input, so no backend change was needed.

Verification: renamed-label plus suffixed-slug regression, equal-name omission, and mapper separation tests; 64 focused tests pass. Full dashboard: 436 files / 3596 tests pass (`/tmp/bex-w4-121-dashboard.log`); application and test TypeScript checks plus targeted ESLint pass. Codegen retained only the Server query/type fields. No production visual probe claimed.
