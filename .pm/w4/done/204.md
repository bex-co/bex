# A static-site header rule `Content-Length` is accepted and takes the site down

Why: `PUT /v1/services/{id}/headers` saves `{"name":"Content-Length","value":"1"}` with 200. From then on, every matching successful response aborts (HTTP/2 `INTERNAL_ERROR`, HTTP/1.1 empty reply), so one accepted setting silently takes a whole static site offline.

- **Severity:** minor to major. Self-inflicted, but the API reports success and nothing tells the user why the site died. The guard already exists on the error path (w4/m101).
- **Repro (loop48, 2026-10-05, pin `c7afefad5`):** owned Free static site `qa-20261005-l48-static` (`srv-db1sob8ti8qc73bltd60`, `bex-co/bex` `examples/static-site`, publish `.`; deleted afterwards).
  - `PUT /v1/services/<id>/headers` `[{"path":"/*","name":"Content-Length","value":"1"},{"path":"/*","name":"X-QA-L48","value":"cl-test"}]` → **200**, echoed back.
  - `curl --http2 https://qa-20261005-l48-static.onbex.co/` → `curl: (92) HTTP/2 stream 1 was not closed cleanly: INTERNAL_ERROR (err 2)`. `curl --http1.1 …` → `curl: (52) Empty reply from server`.
  - Scoped to `/app/cl` (the rewrite `/app/* → /index.html`): `/app/cl` → status 000, 0 bytes, while `/app/ok`, `/` and `/index.html` → 200, 1548 bytes. Only the matching path breaks.
  - Controls on the same site: `Transfer-Encoding: chunked` and `Connection: close` rules served 200 (stripped by the stack). `Content-Encoding: gzip` was emitted verbatim over a plain-HTML body (identity bytes `<!doctype html>`), which a browser cannot decode. CRLF in a value and `Bad Name:` were correctly refused with 400.
  - Restoring `[{"path":"/*","name":"X-QA-L48","value":"restored"}]` brought the site back.
- **Root cause:**
  - `lego/operator/internal/staticserver/staticserver.go:577-583`: `applyHeaders` sets every matching rule with `h.Set` on the success path (`:353`, after `Content-Type`/`Cache-Control`; also `:275`), including body-framing names. Go's server then writes a 1548-byte body against a declared length of 1 and aborts the stream.
  - The error path already blocks exactly these names: `errorBodyHeaderNames` (`:585-592`, `Content-Type`/`Content-Length`/`Transfer-Encoding`, w4/m101) used by `applyErrorHeaders`.
  - API side: `lego/backend/internal/apps/service.go:4816-4849` `validateHeaders` checks token/CRLF/length and cross-tenant `Set-Cookie` but no reserved names. Its callers are REST/GraphQL/MCP `setStaticHeaders` (`:4968`) and Blueprint/create (`:2861`), so one fix covers all four surfaces.
- **Fix (target behavior):**
  - Refuse framing and hop-by-hop names at validation with a 400 that names the header: `Content-Length`, `Transfer-Encoding`, `Connection`, `Keep-Alive`, `Upgrade`, `TE`, `Trailer`, `Proxy-Connection`.
  - Also skip them at the sink in `applyHeaders` (defense for hand-applied CRs and rows saved before the fix).
  - Keep `Content-Type`, `Cache-Control` and `Content-Encoding` allowed on the success path; they are legitimate overrides (for example pre-compressed assets). Note the `Content-Encoding` footgun in the dashboard help text rather than blocking it.
  - Existing saved rows with a reserved name should be reported, not silently dropped: the sink skip keeps sites up while the list still shows the rule.
- **Blast radius:** `applyHeaders` has 2 call sites (`:275`, `:353`). `validateHeaders` has 2 callers. The dashboard header-rule form should show the 400 inline.
- **Unverified:** the browser behavior of the `Content-Encoding: gzip` rule (decoding failure inferred from the plain body, not observed in Chromium); whether any existing tenant has such a rule saved.
- **Render:** Render's header docs list no reserved names; whether Render refuses `Content-Length` was not probed.
- **Estimate:** ~45m (validator plus sink skip plus tests on both).

**Done 2026-10-08:** `appv1alpha1.ReservedStaticHeader` (types, shared) names the server-owned framing/hop-by-hop headers (`Content-Length`, `Transfer-Encoding`, `Connection`, `Keep-Alive`, `Upgrade`, `TE`, `Trailer`, `Proxy-Connection`). `validateHeaders` refuses them with a 400 naming the header on every surface (REST/GraphQL/MCP `setStaticHeaders` + Blueprint/create share it); the static server's success-path `applyHeaders` skips them so a rule saved before this check or a hand-applied CR cannot abort responses (the rule still lists, nothing is silently deleted). `Content-Type`/`Content-Encoding`/`Cache-Control` stay allowed; the editor help text (en/zh) now says framing headers are server-owned and warns to set `Content-Encoding` only on genuinely compressed files. `TestReservedHeaderRulesCannotBreakResponses` uses a real HTTP server and reproduces the outage without the skip (200 with an empty body, `unexpected EOF`); validator test covers all eight names and the allowed overrides; backend apps, staticserver, dashboard services suites + `make lint` green. Whether any tenant currently has such a rule saved was not checked.
