# An apex domain's A-record fallback is one committed edge address, as Render's `216.24.57.1` is

Why: Render parity. A registrar with no ALIAS, ANAME or CNAME flattening gets one A record from Render that it can keep: Render's DNS pages name `216.24.57.1` as "Render's load balancer IP". bex shows whatever its platform host resolves to at that moment and warns that the address can change, so an apex domain on such a registrar looks fragile on bex and never does on Render.

- **Render (read 2026-11-27):** [configure-namecheap-dns](https://render.com/docs/configure-namecheap-dns) says to add an `A` record for `@` pointing to `216.24.57.1`, and [configure-other-dns](https://render.com/docs/configure-other-dns) says "you can use `216.24.57.1` to point your root domain to Render's load balancer IP". Neither says the address can change.
- **bex:** `edgeAddressesFor` (`lego/backend/internal/apps/domains.go`) resolves the platform host and lists what it finds. The dashboard then says "These addresses can change — an ALIAS/ANAME record keeps working when they do" (`services.domainDnsApexFallback`, `dashboard/src/features/services/locales/en.ts`, w4/378). [ADR005](../../docs/ADR005-custom-domain.md) says "bex has no committed-stable tenant-facing load-balancer IP". But production's edge address is the Terraform-owned `hcloud_load_balancer.traefik`, whose output is described as the "Stable public IPv4 for the production edge" (`infra/terraform/outputs.tf`), and `*.db.bex.co` is already a plain A record to it ([ADR009](../../docs/ADR009-postgresql-management.md)). ADR018 records no user sign-off for the warning.
- **Do:** commit to the load balancer's IPv4 as the tenant-facing apex address. Publish it as a setting (for example `BEX_EDGE_IPV4`, with a Terraform output feeding it), show that one address in the apex fallback on REST, GraphQL, MCP and the dashboard, and drop the "can change" warning. Amend ADR005's paragraph and the ADR018 § Custom domains: Verify / DNS instructions row. If the user would rather keep the warning, record the divergence with their sign-off in that row instead.
- **End state:** an apex domain's setup guidance shows one A-record address on every surface, with no "can change" warning, and ADR005 and ADR018 say the address is committed.
- **Size:** about 1h.
- **Source:** w4/m688 t002, a full read of Render's DNS pages, 2026-11-27.

**Done 2026-11-27 (loopx w4).** An apex domain's A-record fallback is one committed address, `BEX_EDGE_IPV4`, which bex-api reads at startup and refuses unless it is one public IPv4 (`lego/backend/cmd/api/config.go`). `edgeAddressesFor` (`lego/backend/internal/apps/domains.go`) returns that one address for an apex and nothing for a subdomain or an installation that commits none. It no longer resolves the platform host, which could also have listed an IPv6 address under an `A` label. REST and MCP now carry it as the additive `edgeAddresses` on every custom-domain object, as GraphQL `CustomDomain.edgeAddresses` already did; before, they carried no address at all. The dashboard's `A @` row now reads "No ALIAS/ANAME or CNAME flattening? Create this A record for @ instead. It points your root domain to bex's load balancer IP." in all eight locales. The "can change" warning is gone, and so is the apex guidance's "using the IP addresses the Target resolves to". The prod overlay (`lego/operator/config/prod/kustomization.yaml`) sets `49.12.20.236`. That is what `*.onbex.co` and `*.db.bex.co` resolve to on 2026-11-27, the address of the delete-protected `bex-traefik` load balancer. `infra.yml` now fails on every run, the daily schedule included, when that value and the Terraform output `traefik_load_balancer_ipv4` differ. `scripts/gitops-validate.sh` requires prod to declare one IPv4 and the local render to declare none. ADR005 (§ Projection and certificates, the tenant-workflow table, the divergence list), the ADR018 custom-domains Verify / DNS instructions row and `docs/render-artifacts/custom-domain-dns-instructions.md` now say the address is committed. Tests: `TestApexARecordFallbackIsTheCommittedEdgeAddress` covers REST list and get, GraphQL, MCP list and get, a subdomain and the unset case, and fails with either the REST mapping or the address reverted. `TestLoadConfigEdgeIPv4` covers the startup refusals, and the dashboard's `custom-domains-section` tests cover one `A` row, no change warning, and no row when no address is committed. Production shows the address once its pin carries this commit and Argo syncs the overlay.
