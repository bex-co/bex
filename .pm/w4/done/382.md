# 382 — Count axes label a midpoint gridline with half an instance or half a request ("0, 0.5, 1")

Why: the Total Instances chart on a one-instance service reads `0`, `0.5`, `1`, and Total Requests with a peak of 3 reads `0`, `1.5`, `3`. Instances and requests are whole things, so a fractional gridline label is noise on the chart a customer reads to decide how to scale.

**Severity:** minor (polish). **Estimate:** ~30m. **Source:** live `/qa-find-bugs w4` loop run k2m4, 2026-10-21 UTC, `muse.env`, workspace `bex-canary`, on pin `9cace6b6e25d`. The run was read-only on the long-lived `hello-go` (`srv-daif6dsmg29s73d1umvg`) Scaling and Metrics tabs. Evidence: `.playwright-mcp/qa-scaling-k2m4-instances-axis.png` (local).

## Probe

Each chart's `svg text` nodes on `/services/srv-daif6dsmg29s73d1umvg/metrics` (default range):

```
["Line chart with 7 data points","0|0.5|1"]    // Total Instances
["Bar chart with 2 data points","0|1.5|3"]     // Total Requests
```

The Scaling tab's Recent Metrics "Total Instances" card shows the same `0 0.5 1`.

## Root cause

- Both charts place exactly three ticks at min, midpoint and max: `svg-line-chart.tsx:355` and `svg-bar-chart.tsx:67`.
- For an odd maximum, the midpoint of a count axis is a half value.
- `formatCount` (`dashboard/src/features/metrics/lib/format.ts`, near the bottom) keeps one decimal on purpose for "rare fractional leftovers from increase() extrapolation". A midpoint tick is not rare: it lands on every odd maximum.
- `formatAxisTickLabels` (w4/381, on `main`, not yet deployed) only makes labels distinct, so it leaves `0.5` and `1.5` as they are.

## Fix (target behavior)

- For `unit === "count"`, an axis shows only whole-number gridlines:
  - Snap the midpoint to an integer.
  - Drop the midpoint when it would collide with min or max. For example, a 0–1 axis shows `0` and `1`, and a 0–3 axis shows `0`, `2` and `3`, or uses a "nice" max of 4 with `0`, `2`, `4`.
- Choose one rule and apply it in both the line chart and the bar chart.
- Fractional data points and tooltips are unchanged: an extrapolated `2.4` requests still reads `2.4` in the tooltip.
- Non-count units (percentage, cpu, bytes, seconds) are unchanged.

## Acceptance

- Unit test over the shared tick helper for count axes:
  - max 1 → no `0.5`
  - max 3 → no `1.5`
  - max 10 → `0`, `5`, `10`, unchanged
  - max 1500 → `K` labels, unchanged
  - an all-zero axis keeps its single label
- Live: on `hello-go` Metrics and Scaling, Total Instances and Total Requests show only integer y labels.
- Dashboard `yarn lint` and `yarn test` pass.
