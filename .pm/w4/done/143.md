# The service header's Connect menu says only "SSH isn't available": its reason lives in a hover-only tooltip

Why: on every Free (or suspended) service, the one place a user looks for SSH gives a bare refusal. The explanation already exists, but it sits in a `title` attribute that keyboard, touch, and screen-reader users never get, while the Shell tab states the same reason inline.

Found live, `/qa-find-bugs` pass 163, 2026-09-25 (w4-targeted, `muse.env` credentials), journey 8. Fixture: Free Docker web service `qa-20260925-web` (`srv-darlpfq9slkc73beqtq0`, `examples/hello-go`, served 200 `OK`), deleted the same pass.

- **Repro:** service header → **Connect**. The menu's SSH section reads "SSH isn't available". The accessibility tree contains only that text: no reason, no link.
- **Root cause:** `dashboard/src/features/services/components/service-detail-header.tsx:411-416` renders `services.sshUnavailable` in a `<p title={t("services.sshUnavailableHint")}>`. The hint ("SSH requires a running paid web, private, or background service and an active gateway.", `features/services/locales/en.ts:69-72`) is exposed only on mouse hover over a non-focusable element.
- **Control:** `/services/<id>/shell` renders "Shell access isn't available — Shell access requires a running paid web, private, or background service and an active SSH gateway." inline. Its only action is "Manage SSH public keys", which cannot help a Free service (the gate is the plan, not a key).
- **Fix:** render the hint as visible text in the menu (or `aria-describedby` plus visible text), and point to the actual remedy for the case at hand: the plan page for a Free service, Resume for a suspended one. Apply the same remedy-aware action on the Shell tab instead of the unconditional key-management link. en + zh.
- **Not changed:** the gate itself is correct and plan-consistent (autoscaling and manual scaling on the same Free service are likewise disabled, with inline "available on paid plans" copy).

Estimate: ~30m.

## Done (2026-09-27)

- The Connect menu's SSH section now shows "SSH isn't available" **with its reason as visible text**, not a hover-only `title`. A shared `sshRemedy` (`dashboard/src/features/services/lib/ssh-remedy.ts`) picks the case. A **suspended** service reads "This service is suspended. Resume it to connect over SSH." with a **Resume service** link (`settings#suspend`). A **Free** service reads "SSH needs a paid instance type. Free services don't include shell access." with a **Change instance type** link (`/plan`). Anything else keeps the general explanation. Static sites and cron jobs never get a remedy, since no plan or resume adds SSH.
- The Shell tab uses the same reason, and for those two cases replaces the unconditional "Manage SSH public keys" with the remedy link. Eligible services keep key management. en + zh.
- Tests: three new header cases (Free, suspended, general), and a Shell-page Free case. Dashboard `yarn lint` + `yarn test` are green.
