## Objective

Change `CardTitle` so a card's title is a heading by default, with an explicit `as="div"` escape hatch, without changing how it looks. Today 121 of 124 `<CardTitle` sites render a `div`, so a page like service Settings exposes one heading for 15 sections.

## Context

- `dashboard/src/common/components/ui/card.tsx:31-44`: `CardTitle({ as: Tag = "div" })`, with `as?: "div" | "h1" | "h2" | "h3"` added by w4/410.
- Only 3 sites pass `as=`: `features/webhooks/components/webhooks-panel.tsx:85` and `features/notifications/components/notification-settings-panel.tsx:60` (h1), `features/notifications/components/push-notification-settings-panel.tsx:223` (h2). They must not change.
- Tailwind preflight resets heading `font-size`, `line-height` and `font-weight`; the component's own classes (`leading-none font-semibold`) must still win so the title looks identical.

## Steps

1. Change the default `Tag` to `"h2"`; keep `"div"` accepted as the explicit opt-out.
2. Add a shared component test that pins the default (an `h2`), the `as="div"` escape hatch, and that the three explicit levels still render.
3. Assert computed `font-size`, `line-height` and `font-weight` of a default `CardTitle` equal those of an `as="div"` one (a test, or a live probe on service Settings "General").

## Files

- `dashboard/src/common/components/ui/card.tsx`
- `dashboard/src/common/components/ui/__tests__/` (new or existing card test)

## Acceptance criteria

- [ ] `CardTitle` with no `as` renders an `H2`; `as="div"` renders a `DIV`.
- [ ] The three existing `as=` sites render the same levels as before.
- [ ] Computed font metrics of the default title equal the `div` version.

## Out of scope

- Per-site levels and exceptions (t002).
- Page-level h1s (done in w4/410).
