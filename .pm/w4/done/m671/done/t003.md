## Objective

When `ImageAvailable` turns `False`, record one `image_pull_failed` fact with no deploy, keyed by the condition's transition so it is written once per outage, whose message names the cause and says the running instances are unaffected. Send one Image Pull Failed email whose lead fits a running service.

## Context

- The no-deploy fact shape exists for a failed live-release pull (`buildServedReleasePullFact`, `lego/backend/internal/store/reconciler.go:1871-1891`, w8/m156 t005); its source key uses the condition's transition time.
- Message plumbing comes from w4/m669 t003.
- Email lead: `lego/backend/internal/notifications/alert_email_worker.go:462-464`.

## Steps

1. Read the condition in the reconciler and write the fact with an `availability:<app>:<transition>` source key.
2. Word the message: the cause, its remedy, and that the running instances keep serving until a fresh pull is needed.
3. Give the email a running-service lead for this fact.

## Acceptance criteria

- [x] One outage writes one fact and one email, however many reconciles see it; a recovery followed by a new outage writes a second (test).
- [x] REST, GraphQL, MCP and the webhook answer the same message, with no deploy id (test).

## Out of scope

- Marking the service as not Running (w8/blocked/m156 t010 covers a release that actually cannot pull).
