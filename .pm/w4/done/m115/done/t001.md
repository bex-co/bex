## Objective

Insights → Active processes and Top queries show real query text instead of 34 `<insufficient privilege>` cells, while the insights path stays read-only.

## Context

### The observation (production, 2026-09-19; fixture `qa-20260919-p14-db`, `dpg-dan32k92dbts73fi28o0`, since deleted)

- Insights section on a live database with recent SQL-console activity: Active processes 9 rows (User blank or `postgres`, every Query cell `<insufficient privilege>`), Top queries 25 rows (every Query cell `<insufficient privilege>`).
- Refresh insights → identical 34 masked cells. Storage, Table scans, Parameter overrides, and Non-default parameters on the same page render real data.
- The masked literal is Postgres's own: `pg_stat_activity` / `pg_stat_statements` mask the query text (and `usename`) of other roles from callers without `pg_monitor` / superuser.

### The mechanism (nailed in code, not inferred)

- `runInsight` (`lego/backend/internal/postgres/insights.go`) dials the tenant database with the connection-secret `uri` — the unprivileged app user — then runs `sqlProcesses` / `sqlTopQueries` through the read-only envelope (`runReadOnlyQuery`: read-only txn + statement timeout).
- The backend passes rows through untouched (`strVal`), and the dashboard renders them untouched — so the Postgres mask strings reach the UI verbatim.
- The `transaction_read_only=on (session)` row in Non-default parameters confirms the same unprivileged connection serves the whole Insights section.

### Fix shape (implementation-owned, pick by review)

- Preferred: the operator grants `pg_monitor` (read-only stats visibility — no DDL/DML power) to the managed user at provisioning, plus a backfill for existing databases. Keeps one connection path and preserves the read-only envelope.
- Alternative: a dedicated insights role the backend dials only for the introspection queries. More moving parts (secret, rotation, authz) — justify if chosen.
- Do NOT "fix" by filtering masked rows client-side only — that hides the symptom while the feature stays blind (t002 covers honest degradation for genuinely-hidden rows).

### Acceptance

- On a throwaway database with SQL-console activity, Active processes and Top queries show the owner's real query text.
- `default_transaction_read_only` + statement-timeout rails still in effect on the insights path (assert, don't assume).
