## Objective

The three domain verbs are the ones proven wrong live; the other 45 share the same projection. Produce the table that says, for every entry, whether it can lie the same way — and place each one.

## Context

- `eventTypes` has **48** entries (`awk '/^var eventTypes = map\[string\]string\{/,/^\}/' lego/backend/internal/events/service.go | grep -c ':.*Type'`). The projection is unconditional: `ev.Type = eventTypes[r.Verb]` (`:806`), mirrored by the filter push-down at `:433`.
- Starting points, not conclusions — verbs with validation after authorization: `apps.SetIPAllowList`, `apps.SetPlan`, `apps.Scale`, `apps.SetAutoscaling`, `apps.SetSubdomainPolicy`, `secrets.SetEnvVar` (taught to refuse blueprint-owned keys by `w4/m120`), `apps.AddDisk`/`UpdateDisk`/`RestoreDiskSnapshot`, `jobs.Create`.
- A verb that is correct today is correct _because_ the projection is unconditional. Under Option A every one of them changes code path, so they need regression tests, not just a note.

## Steps

1. For each of the 48, read the verb's body and classify: cannot routinely fail after authorization / can fail and is now gated / is an intent verb and is now excused.
2. Record the table in the repo (next to `eventTypes`, or in the events ADR — pick one and link the other).
3. Fix any entry the audit shows is wrong in the same way the domain verbs were.
4. Extend the comment block above `eventTypes` so a newly added verb is placed correctly by default.
