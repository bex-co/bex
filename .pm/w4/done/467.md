# 467 — A build that fails a source check quotes `git fetch` progress ("From … * branch … -> FETCH_HEAD") in its failure reason, and blames "the clone step"

Why: the one sentence a customer reads when a build fails starts with git's transfer chatter. The real cause ("the Dockerfile … does not exist") is buried at the end, so the deploy page, Events and notifications all lead with noise.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 2, 2026-11-04 10:42 UTC (`muse.env`, `bex-canary`, pin `fb6098dd2e37`); **minor** (copy and diagnosability); ~25m.
- **Probe:** a Git-backed Docker web service (`qa-20261104-hello`, `srv-dblgjqrkom4c73e8d140`, repo `github.com/bex-co/bex`, root `examples/hello-go`, deleted afterwards). Run `PATCH /v1/services/<id>` `{"serviceDetails":{"envSpecificDetails":{"dockerfilePath":"./Nope.Dockerfile"}}}` → 200, then `POST /v1/services/<id>/deploys` `{}` → 201 `dep-dblgncemdnbc73eulmvg`. The deploy page shows **Build Failed** with:

  ```text
  build failed in the clone step: From https://github.com/bex-co/bex * branch 0c66aa83daa26d962fd7d3b3886b1e86e26a8da7 -> FETCH_HEAD the Dockerfile "examples/hello-go/Nope.Dockerfile" does not exist in the repository at "0c66aa83daa26d962fd7d3b3886b1e86e26a8da7"
  ```

  The build log repeats it in `==> Build failed:` lines.

- **Root cause:**
  - `lego/operator/internal/build/build.go:1544` runs `bex_run git "$@" fetch --depth 1 origin -- "$REF"` **without `-q`**, so git writes its `From …` and `* branch … -> FETCH_HEAD` progress to stderr.
  - `bex_require` (`:1551-1555`) then fails the same container with the real message.
  - `buildFailureMessage` (`lego/operator/internal/controller/build_failure.go:94-103`) quotes the failing container's stderr tail behind `" in the " + obs.FailedStep + " step"`, so the progress lines lead the reason.
  - **Control:** the static-site publish path already fetches with `-q` (`lego/operator/internal/publish/publish.go:587`).
- **Fix:**
  - Add `-q` to the build clone fetch, keeping `bex_run`'s error classification, which reads only real error output.
  - Check the submodule fetches in `cloneSubmodules` the same way.
  - Consider naming the step "source checkout" for a missing root directory, context or Dockerfile, since nothing failed to clone.
  - Test: the script test for a missing Dockerfile asserts that the tail has no `FETCH_HEAD` line and starts with `the Dockerfile`.
- **Render:** a missing Dockerfile on Render reports the Docker error itself, with no git transfer output in the failure reason.
- **Dedupe:** w6/m123 t003 (done) made buildkit output reach the log and quotes the same `FETCH_HEAD` lines as context, but never addressed the reason text. w8/053 (done) is the missing-root-directory message. No open item, and no DO_NOT_DO item applies.

- 2026-11-04: fixed by the loopx w4 drain: the build clone fetch now runs `git fetch -q` (`build.go` clone container), pinned by `TestCloneFetchIsQuiet`. Submodule fetches go through `execution.GitSubmoduleUpdate` and were left unchanged.
