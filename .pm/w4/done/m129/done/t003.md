## Objective

Implement t001's decision about rows that already exist, and make sure the fix covers every spelling of the name the old join accepted — otherwise the defect survives under an alias.

## Context

- `store/webhooks.go:723-727` enumerates three spellings the workspace-wide query must recognize: the current CR name `<tenantID>-<appName>`, the legacy `<tenantName>-<appName>`, and a bare app-name fallback. The per-service feed is handed the caller's spelling; the twin recognizes all three itself. A fix applied to one leaves the other two matching by name.
- `ListServiceEvents` also takes a `LegacyTarget` parameter (`events.go:483-485`), which is a fourth path into the same matching and must be placed.
- Whatever t001 decided, the honest outcome for pre-fix rows is probably that they cannot be attributed with certainty — a name may have been held by several services. Saying so in the code is better than a backfill that guesses.

## Steps

1. Enumerate every predicate that matches a service by name across both queries, including `LegacyTarget`, and list them in the commit message — the count, not an estimate.
2. Apply t001's treatment to each.
3. If rows are abandoned rather than backfilled, record at the site why, so the next reader does not "fix" it by widening the join again.
4. Confirm the datastore audit arm is unaffected: `webhooks.go:721-723` notes datastore rows carry the immutable `dpg-`/`red-` id in their typed target, so they were never name-keyed. State that rather than changing them.
