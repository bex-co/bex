# 410 — The Webhooks and Notifications pages have no heading at all: their visible titles are card `div`s

Why: screen-reader users jump by headings, and a page with none gives them nothing to land on. Every other dashboard page has exactly one `h1`: Overview, Environment Groups, Blueprints, Billing, both Settings pages, the database page and the create forms.

**Severity:** minor (accessibility structure). **Estimate:** ~15m. **Source:** live `/qa-find-bugs w4` loop run t9h2, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `c5583c80bef9`). Read-only; session revoked. Builds on w4/409, which covers the opposite case (a second `h1` on the service Environment tab).

## Probe

`[...document.querySelectorAll('h1,h2,h3,[role=heading]')]` per page:

- `/webhooks` → **none** (the page reads "Webhooks" visually);
- `/notifications` → **none**;
- controls with one `h1` each: `/`, `/env-groups`, `/blueprints`, `/billing`, `/workspace/settings`, `/settings`, `/databases/<id>`, `/services/new`, `/keyvalue/new`.

## Root cause

- `dashboard/src/features/webhooks/components/webhooks-panel.tsx:85` and `dashboard/src/features/notifications/components/notification-settings-panel.tsx:60` render the page title through `CardTitle`, which is a `div` (`common/components/ui/card.tsx:31`).
- The routes (`routes/webhooks.tsx`, `routes/notifications.tsx`) set only the document title (`translatedTitleHead`).

## Fix

- Render each page's title as an `h1`: give `CardTitle` an `asChild` or heading-level option, or wrap the title in `<h1>` with the same classes. Section titles further down stay at `h2`.
- Check `push-notification-settings-panel.tsx` (also `CardTitle`) sits under that `h1` as an `h2`.
- Test: each route renders exactly one `h1` with the translated title.

Not a finding: `/api/sessions` and `/api/connected-agents` answer `application/json`. They are the dashboard's own data endpoints, not pages.

## Loopx w4 verdict (2026-10-25)

Done: `CardTitle` takes an `as` heading level; the Webhooks and Notifications page titles render as the page's `h1`, and the push-settings card under Notifications renders as an `h2`, all with the same classes. Tests pin each heading level.
