## Root cause and target behavior

`dashboard/src/common/root-route/shell-component.tsx:11-16` destructures language from root route context and passes it straight into `i18nBootstrapScript`. `dashboard/src/i18n/client-bootstrap.ts:26-27` handles valid default language but passes an absent language to `getResourceBundle`. The installed/pinned i18next **26.3.4**, `dist/esm/i18next.js:326-332`, dereferences `lng.includes` unconditionally. Its caller at :413-415 forwards the same language. This exactly explains the captured stack.

The TypeScript promise is stronger than the pending runtime state. `use-root-context.ts:4` delegates to TanStack `useRouteContext`, which selects `match.context` directly (`@tanstack/react-router/src/useRouteContext.ts:25-30`, version **1.170.25**). Router `load-client.ts:373-407` rebuilds base context, then awaits beforeLoad and merges its returned fields only at :453-458. Our language comes from the async root beforeLoad (`routes/__root.tsx:21-49`); router initial context holds only the Apollo client (`router.tsx:35-37`). The shell wraps the root suspense/catch boundary (`react-router/src/Match.tsx:98-111`), so it must tolerate an unresolved context itself.

**Fix:** resolve a supported language locally in the shell throughout pending and settled states, preserving the current active language while root context is incomplete. Use the existing `asSupportedLanguage` helper and request-scoped/client-active i18n appropriately; default to en only when no supported active/request language exists. Pass that same concrete language to both html lang and bootstrap generation. Guard the bootstrap input at its actual boundary as needed. Do not change shared auth/session context or normalize every useRootContext caller.

Acceptance: repeat the exact fresh-load navigation with **zero** instances of this exception, then verify pending and ready states retain the session language. Add a focused missing-context test; keep default-en bootstrap omission, zh catalog/script escaping, and request-isolation tests. Preserve the original m103 guarantees (immediate language switch, non-English reload stability and concurrent-language SSR isolation) during implementation, not by deleting bootstrap behavior.
