# w4/263 — Completed Key Value environment move keeps the old source row

Why: a completed move should immediately leave the resource listed in its saved environment, so a user can trust the source count and continue managing the right placement.

**Severity:** minor. Placement is stored correctly; the ready source row/count temporarily lies until a later poll. No lost data or persistent wrong membership observed. **Estimate:** 55m (ordered Key Value membership refresh 20m, real Apollo regression plus passing controls 25m, live replay/closeout 10m). Filing only.

Source: continuous `$qa-find-bugs w4`, functional production pass a243, 2026-10-12 UTC; credentials consumed privately from muse.env. Research main `fbe83f632`. Workspace `tea-d98210cbbpdc73dcrkvg`. Only an owned empty project, two environments and a Free private Key Value instance were changed.

## Root cause and bounded fix

- `dashboard/src/features/environments/hooks/use-set-environment-keyvalues.ts:31–33,41–45` awaits named `Environments`/`Projects` refetches, then reports success. That does not guarantee a post-write Environments response.
- Pinned and installed **Apollo Client 4.1.3**: `core/QueryManager.js:905–919` refetches included watchers; `core/ObservableQuery.js:366–402` uses network-only but retains normal query deduplication; `core/QueryManager.js:514–515,555–578` shares an existing link observable keyed by printed query and variables. `core/QueryInfo.js:348–352` merely awaits those promises. An older read can therefore satisfy the awaited refresh. Apollo's default deduplication is true (`core/ApolloClient.js:76`), unchanged by the dashboard.
- The complete Environment objects normalize by typename/id (`cache/inmemory/helpers.js:4–24`); `dashboard/src/common/apollo/cache.ts:6–13` has no Environment ordering policy. In the second failing capture, the target mutation's newer membership is followed by an older list containing the opposite membership. That explains the observed target overwrite and retained source row.
- Consumer traced: `components/environments-panel.tsx:245–263` passes the selected list item into `EnvironmentCard`; `environment-card.tsx:157–160` builds Key Value rows from `environment.keyValueIds`, and :250–263 clears successful selections only after the hook resolves. The zero-selection/stale-row capture is therefore after the hook's completed refresh, not just an in-flight move.
- Backend `lego/backend/internal/environments/graphql.go:197–205` returns the target through `Service.SetKeyValues`; `service.go:1005–1006,1024–1090` applies membership and returns its full view. List :450–488 assembles memberships. The fresh read confirms the stored target is correct. Batched operations execute serially and the HTTP array is emitted at the end (`internal/api/server.go:1491–1505`), so HTTP receipt time alone is not a resolver-snapshot timestamp. Individual resolver timing was not measured.
- Existing local precedent: `use-create-environment.ts:37–50` settles older list results individually, then runs typed `EnvironmentsDocument` network-only with `queryDeduplication:false`. Adapt/reuse this ordering for the **Key Value membership hook only**, supplying the affected project's immutable ID. Resolve it from the successful target Environment response or pass known project context; the generated mutation fragment carries `projectId` (`graphql/definitions.ts:781`), and `EnvironmentsDocument`/:2250 already expresses the authoritative list. No API/schema change is needed. Preserve the current Projects refresh for auto-join placement.

Do not launch the non-deduplicated authoritative read alongside an older read that can publish after it. Settle prior matching reads first, then publish the fresh read. Separate mutation refusal from post-commit refresh failure: a refresh retry re-reads only, never repeats the move or claims the stored move failed. A failed refresh keeps usable rows and identifies refresh as incomplete. Existing unauthenticated/forbidden/not-found mutation handling remains; pending and timeout do not assert a completed refresh. Error cases were not induced live.
