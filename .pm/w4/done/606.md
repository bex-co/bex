# 606 — A cron job's header reads "Instances 1" between runs, while its instances API and Metrics count none, and REST gives cron jobs and static sites a `numInstances` Render's schemas don't have

**Absorbed 2026-11-13 into [w10/m373 t005](../../w10/m373/t005.md)** (`/pmx them all to w10`, from `/pm-brainstorm for w10`). **Not fixed yet:** the fix and its live DoD ship with that milestone; this note keeps the original evidence.

Why: a cron job runs nothing between runs, and the header's own rule (w4/547) is to show "what runs now, as the instances API and Metrics count it". "Instances 1" tells the owner something is running and billable all the time. Render's cron job has no instance count at all, as w5/m48 already decided for static sites.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 191, 2026-11-12 11:42–11:49 UTC (`muse.env`, workspace `bex-canary`; pin `a5be11e4e517`). **Minor** (a wrong count on the header, and an extra field on REST). ~30m.
- **Fixture:** Starter cron job `qa-20261112-r191-cron` (`srv-dbqqcc9n6kgc738373ug`, `busybox:1.36`, `*/5 * * * *`), in project `qa-20261112-r191-prj`. It was deleted with its environment (GET 404).
- **Probe at 11:46:58, between runs** (the last run ended 11:45:04; the header read "Next run: in 3m"):
  - Dashboard header (`/cron/srv-dbqqcc9n6kgc738373ug`): `Slug qa-20261112-r191-cron · Instances 1 · Revision rev-1 · Created 3m`.
  - `GET /v1/services/srv-dbqqcc9n6kgc738373ug/instances` → `200 []`.
  - `GET /v1/metrics/instance-count?resource=…` over the last 10 minutes → `[]`.
  - `GET /v1/services/srv-dbqqcc9n6kgc738373ug` → `serviceDetails` keys `command, env, envSpecificDetails, lastSuccessfulRunAt, nextRunAt, numInstances, plan, region, runtime, schedule`, with `numInstances: 1`.
  - GraphQL `service { type phase replicas }` → `cron_job`, `Running`, `1`.
- **Root cause:**
  - **The header.** `HeaderFacts` (`dashboard/src/features/services/components/service-detail-header.tsx:667-719`) omits Instances only when the service is a static site (`isStaticSite(service)`, `:691`).
    - For any other type, `instancesFact` (`:658-665`) prints `service.replicas` whenever `runsInstances` is true, i.e. not suspended and not Hibernated (`dashboard/src/features/services/lib/status.ts:350-354`).
    - A cron job's phase stays `Running` between runs, so the header prints its configured replica count, 1, though no pod runs.
  - **REST.** `renderServiceDetails` (`lego/backend/internal/apps/render.go:457-460`) starts every type's map with `"numInstances": int(a.Replicas)`, and nothing removes it for a cron job or a static site.
    - Render's pinned schemas (`lego/backend/internal/api/openapi/render-public-api-1.json`) define `numInstances` only on `webServiceDetails`, `privateServiceDetails` and `backgroundWorkerDetails`.
    - `cronJobDetails` is `buildPlan, env, envSpecificDetails, lastSuccessfulRunAt, plan, region, runtime, schedule`.
    - `staticSiteDetails` is `buildCommand, buildPlan, ipAllowList, parentServer, previews, publishPath, pullRequestPreviewsEnabled, renderSubdomainPolicy, url`.
  - **A stale comment.** The comment at `render.go:486` calls `command` "cronJobDetails.command (render-public-api-1.json)", but the pinned schema has no such key. Render carries the command in `envSpecificDetails`. Correct the comment, or record `command` as a bex extension like `nextRunAt`, rather than removing a field clients may read.
- **Fix (target behavior):**
  - **Header.** A cron job's header has no Instances fact, as a static site's has none (w5/m48/t001). Its schedule, last successful run and next run already describe it.
  - **REST.** `serviceDetails.numInstances` appears only on `web_service`, `private_service` and `background_worker`, matching Render's schemas. Cron jobs and static sites omit it.
  - **Unchanged.** GraphQL `replicas` stays (bex-native, read by the scaling surfaces). The instances API and the instance-count metric are already right.
  - en and zh are unaffected: no copy changes.
- **Blast radius:**
  - `HeaderFacts` renders on every service detail page. Add a test that a cron job shows no Instances. Keep the existing cases for web, private, worker, sleeping, suspended and never-served services (w4/547) green.
  - `renderServiceDetails` has one production caller (`render.go:415`). It feeds REST `GET`/`LIST /v1/services` and every REST reply that returns a service (`PATCH`, create, suspend/resume). Add a table test of which types carry `numInstances`.
