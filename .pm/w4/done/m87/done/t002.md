## Objective

Teach the dashboard's typed transcript parsers about the additive timestamp while accepting legacy and mixed histories without dropping or rewriting parts.

## Context

- `dashboard/src/features/agent-sessions/lib/acp-parts.ts` and the conversation data schemas validate typed driver parts.
- Existing durable transcripts contain no timestamp and must remain replayable indefinitely.
- The gateway and store persist verbatim text; compatibility belongs at the producer/consumer schema edges, not in transport rewriting.

## Steps

1. Add the optional timestamp to the relevant typed data-part schemas and TypeScript types.
2. Parse valid values into a shared time representation while treating missing or invalid optional timing as unavailable, never as transcript corruption.
3. Add fixtures for new, legacy, and mixed transcript sequences.

## Files

- `dashboard/src/features/agent-sessions/lib/acp-parts.ts`
- `dashboard/src/features/agent-sessions/types.ts`
- `dashboard/src/features/agent-sessions/lib/mock-stream.ts`
- `dashboard/src/features/agent-sessions/lib/__tests__/acp-parts.test.ts`

## Acceptance criteria

- [x] New timestamped parts validate and expose their source time to the duration layer.
- [x] Legacy parts without the field render exactly as before.
- [x] Invalid optional timing degrades to unavailable timing without dropping valid message content.
- [x] No gateway, backend store, REST, GraphQL, or MCP schema change is required.

## Out of scope

- Backfilling historical transcripts or inventing timestamps from database insertion time.
