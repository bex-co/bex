## Objective

Implement t001's decision on the read/write path so that no `notification_settings` row is unreachable by the member who owns it.

## Context

- If t001 chose **per workspace**: add the workspace argument to `GetSettings`/`UpdateSettings` and thread it from each adapter — GraphQL `notificationSettings(ownerId:)` / `updateNotificationSettings(ownerId:, …)`, REST `GET`/`PATCH /v1/notification-settings/owners/{ownerId}` (Render's exact path), and bind it on the context the way every `ownerId`-taking resolver already does (`ctx = core.WithWorkspace(ctx, ownerID)`; `apps.CreateBlueprint` is the pattern).
  - Keep the existing unscoped `/v1/notification-settings` working, defaulting to the caller's default workspace, so current clients and the pinned Render CLI do not break.
  - `Base.Tenant(ctx)` then resolves the named workspace, and `ValidateNamedWorkspace` already refuses one the caller is not a member of — so the membership check comes for free rather than needing a new one.
- If t001 chose **per user**: write the migration, change `ListNotifyRecipients`'s join to drop `tenant_id`, and apply the conflict rule t001 defined.
- Either way the acceptance test is the same shape: enumerate the caller's workspaces, read each one's settings, and assert the values match what the store holds for that `(tenant, subject)`.

## Steps

1. Implement the chosen scope in `notifications/service.go`.
2. Add or adjust the adapter arguments in REST, GraphQL and MCP.
3. Preserve the current unscoped behavior as the default-workspace case.
4. Confirm a member cannot read or write another member's row, and cannot name a workspace they do not belong to.

## Files

- `lego/backend/internal/notifications/service.go`, `rest.go`, `graphql.go`, `mcp.go`
- `lego/backend/internal/store/notifications.go` (only if collapsing to per-user)

## Acceptance criteria

- [x] For every workspace the caller belongs to, a read returns that workspace's stored values and a write updates that workspace's row.
- [x] No row a member owns is unreachable.
- [x] Naming a workspace the caller does not belong to is refused, not silently defaulted.
- [x] The existing unscoped route keeps working.

## Out of scope

- MCP's caller-scoped classification (t003) and the dashboard (t004).

## Outcome (2026-09-21)

GetSettings/UpdateSettings take an ownerID and bind it with core.WithWorkspace; ?ownerId= on REST and an ownerId argument on both GraphQL operations. Omitting it keeps the previous default-workspace behavior.
