## Objective

A Postgres create answers with the major it will run, as Render's does: `version` is in Render's `postgres` schema's `required` list.

## Found by the closeout replay (QA loop round 408, 2026-11-15 09:43 UTC, pin `89ac87445bec`)

- MCP `create_postgres {"name":"qa-20261115-r408-pg","plan":"free","workspaceId":"tea-daif693dqjvc73e7as3g"}` returned an object with every other Render-required key and **no `version`**.
- `GET /v1/postgres/dpg-dbsntv6oou4c73fdrngg` read `"version":"18"` about four minutes later, once the cluster reported it.
- REST `GET`, MCP `get_postgres` and the `list_postgres_instances` item all agree. Their extra keys (`ownerId`, `backupsEnabled`, `poolerEnabled`, `public`, `externalHost`, `externalCertificate`) are the same bex extensions on every surface.
- The fixture was deleted (`GET` 404).

## Cause

- `pgView` (`lego/backend/internal/postgres/service.go:600-603`) takes `Status.CurrentVersion`, falling back to `Spec.Version`.
- `CreatePostgres` writes `Spec.Version: req.Version` (`:944`), which is empty when the caller names none. So the field is omitted (`omitempty`) until the operator observes the cluster.
- The default lives only in the operator: `cnpgDefaultMajor = "18"` (`lego/operator/internal/controller/database_operand.go:98`).

## Fix (target behavior)

- Resolve the default major at create: move the default into `lego/types` (shared by the operator and bex-api) and write it into `Spec.Version`. The create then answers `version` on REST `POST /v1/postgres`, GraphQL and MCP alike.
- Unverified: whether REST `POST /v1/postgres` omits it too. It renders through the same `pgView`, so it should.

## Tests

- A create with no version answers `version` equal to the shared default; a create naming 16 answers 16.

## Resolution (2026-11-16, `/loopx w4`)

- Re-confirmed live first on pin `ef7e65cd3f46`: MCP `create_postgres {"name":"qa-20261116-m378-pg","plan":"free"}` answered no `version`; `GET` read `"version":"18"` once the cluster was up.
- **Fix:** `appv1alpha1.DefaultPostgresVersion = "18"` (`lego/types/v1alpha1/database_types.go`) replaces the operator's private `cnpgDefaultMajor`, and `CreatePostgres` (`lego/backend/internal/postgres/service.go`) writes `cmp.Or(req.Version, DefaultPostgresVersion)` into `spec.version`, so REST `POST /v1/postgres`, GraphQL and MCP `create_postgres` all answer `version`. The operator's image resolution is unchanged: a versioned 18 and an unversioned create both resolve `bexOperandImages["18"]`.
- **Test:** `TestCreatePostgresAnswersTheMajorItWillRun` (`lego/backend/internal/postgres/dryrun_test.go`): REST and MCP creates with no version answer `18` and store it in `spec.version`; a create naming 16 answers 16. With the default removed it fails (`REST create version = <nil>, want 18`).
- Blueprint-created and recovered databases keep their existing paths (a Blueprint's `postgresMajorVersion`, a recovery's source version); not part of this task.
