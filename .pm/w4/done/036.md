# Fix `new_commit` deploy-trigger label rendering as "New_commit"

Sub-hour bug found live-exploring `dashboard.bex.co/services/srv-d9ndt8hmcglc739fkp50/deploys` (`eden-dash-v3`) with Playwright MCP, 2026-08-21.

The Deploys list/detail "Trigger" column renders the `new_commit` trigger as the raw literal "New_commit" (wraps mid-word as "New_co"/"mmit" in the narrow column), while every other trigger renders as a clean humanized label ("Manual Deploy", "First Deploy").

Root cause (confirmed via code read):

- `dashboard/src/features/deploys/lib/deploy-status.ts:117-130`, `deployTriggerKey(trigger)` — switch handles `"create"`, `"api"`, `"deploy_hook"`, `"blueprint"` but has **no case for `"new_commit"`** (backend enum `TriggerNewCommit = "new_commit"`, `lego/backend/internal/store/store.go:187`), so it falls to `default: return null`.
- Both callers (`dashboard/src/features/deploys/components/deploys-list-page.tsx:72-76` and `deploy-header.tsx:19-26`) fall back to rendering the raw `d.trigger` string wrapped in a `capitalize` CSS class when `deployTriggerKey` returns null. CSS `capitalize` doesn't treat `_` as a word boundary, so `"new_commit"` becomes "New_commit" instead of "New Commit" — the other triggers avoid this because their translated strings are already space-separated ("manual deploy", "first deploy") before `capitalize` title-cases them.

Fix: add `case "new_commit": return "deploys.triggerNewCommit";` to `deployTriggerKey`, plus a matching locale entry (e.g. `message: "new commit"`) in `dashboard/src/features/deploys/locales/en.ts` alongside the existing `deploys.trigger*` keys, and the zh locale counterpart. Verify both the deploys list page and the deploy detail header (`deploy-header.tsx`) pick it up, since both call the same helper.

Optional/lower-priority, noticed in the same session (can be folded in or left for later): the "Duration" column header on the same table wraps awkwardly ("Dura"/"tion") because the column width is sized to the data values rather than the header text — a minor CSS width fix in the same table component.

Done when `new_commit` renders as "New Commit" (or equivalent humanized label) consistently on both the deploys list and deploy detail pages, with no raw-enum/underscore leakage, and existing deploy-trigger tests (or new ones) cover the `new_commit` case.
