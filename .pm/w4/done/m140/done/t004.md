## Objective

Run the same 7-day no-match search through REST `GET /v1/logs?resource=…&text=…&startTime=…&endTime=…`, GraphQL `logs`, and MCP `list_logs`, and confirm they return the same result or the same named timeout within budget. Compare with render.com's log search behavior over a week, and file drift.

## Result (2026-09-26)

REST `GET /v1/logs`, GraphQL `logs`, and MCP `list_logs` now all build their page with one `Service.queryLogPage`, so the same 7-day search returns the same partial page or the same `QUERY_TIMEOUT` on all three. REST never had an execution deadline, so the Loki scan budget is what protects its write deadline. Render's log API documents `hasMore` with next-window cursors, and a partial page stays inside that contract (a Render client just follows the cursor). No drift filed. Production probes are part of t007.
