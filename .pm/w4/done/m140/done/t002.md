## Objective

Read how `logs(text:)` builds its Loki query for a 7-day window, measure it against production (or a representative stream), and make broad searches finish inside the budget, for example by splitting the range newest-first and returning a page with `hasMore`/cursors as soon as `limit` lines are found or a time budget is spent.

## Context

- `lego/backend/internal/logs/` (service + Loki source). `w4/m107` added the paging envelope and cursors, which already give a way to return a partial window honestly.
- The filing probe used a zero-match term, so there was no early exit: the whole week must be scanned.

## Acceptance criteria

- [ ] The measured cause is written here (query shape, duration, Loki limits hit, if any).
- [ ] A no-match 7-day search returns within budget, with an honest `hasMore`/cursor for any unscanned remainder, or t001's named timeout if that is impossible.

## Result (2026-09-26)

**Cause (from code; production Loki timings were not measurable from this session):** `NewLokiSource` issued one `query_range` over the whole window, and a `|~ "(?i)…"` line filter with zero matches makes Loki read every line of the week before answering, with no early exit. **Fix:** a line-filtered read (text/path/host) is now scanned in doubling slices from the end the direction keeps (1h, 2h, 4h, …), stopping when the page fills, the window is covered, or `lokiScanBudget` (18s, capped at the caller's deadline − 2s) runs out. A budget-stopped read returns `*ScanIncompleteError{Entries, ScannedTo}`, which the shared `queryLogPage` turns into `{logs: <covered matches>, hasMore: true, nextEndTime: ScannedTo − 1ns}`, so the next page resumes exactly at the coverage edge. If not even the first slice finishes, the read returns a `QUERY_TIMEOUT` 503. Label-only reads stay a single request. A boundary line shared by two slices counts once. Tests: `loki_scan_test.go` (9 cases: early fill, contiguous doubling cover, budget partial, first-slice timeout, caller cancellation, forward slicing, label-only, boundary dedupe, and the multi-resource page edge).
