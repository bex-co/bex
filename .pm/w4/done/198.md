# w4/198 — Request logs expose the raw Traefik record: a platform-global `RequestCount`, pod IPs and internal router names, in every tenant's view

Why: a tenant's Request logs should describe that tenant's requests. Today each line carries the shared edge's global request counter, so any tenant can watch platform-wide traffic volume across all tenants, plus cluster internals (pod IP, router/service names). The UI also shows a ~1.5 KB JSON blob where a readable request summary should be.

Live 2026-10-05 UTC (`/qa-find-bugs` loop23, muse.env, `bex-canary`). Owned Free sink `qa-20261004-l23-sink` (`srv-db1h3ke8inbs73f0v740`, `mendhak/http-https-echo:35`, deleted to 404):

- Dashboard `/services/<id>/logs?type=request`: each line is `<time> POST 200 {"ClientAddr":…,"KubernetesIngressName":"tea-daif693dqjvc73e7as3g-qa-…","KubernetesIngressNamespace":…,"KubernetesServiceName":…,"RequestCount":7742403,…,"RouterName":"websecure-…@kubernetes","ServiceAddr":"10.244.90.76:8080","ServiceURL":"http://10.244.90.76:8080",…}` (`.playwright-mcp/qa-request-logs-traefik-1.png`).
- REST `GET /v1/logs?ownerId=…&resource=<id>&text=RequestCount` returns the same raw messages with labels `type=request`, `method`, `statusCode`.
- **`RequestCount` is global:** across three of my own requests minutes apart it read 7741750 → 7741896 → 7741988. The sink received only a handful of requests, so the counter tracks the edge's traffic across every tenant.

Prior passes noticed this and deliberately did not file it as "a product decision" (`.pm/w4/done/068.md` "Smaller things seen and not filed"; `.pm/w4/done/126.md:89`, which notes the dashboard test pins verbatim rendering at `log-line-list.test.tsx:79`). Neither weighed the **cross-tenant** counter, which moves this from presentation to information disclosure. Hence filing now, as a decision plus a fix.

Root cause: request lines are the Traefik JSON access-log record shipped verbatim into Loki. `lego/backend/internal/logs/loki.go:576` passes each message through `canonicalHistoryMessage` (`:607-613`), which only trims line terminators, so REST/GraphQL/MCP and the dashboard all render the full record.

Fix (decide, then implement):

1. Project request lines to an allowlisted, Render-shaped summary, e.g. `METHOD path status duration bytes clientIP userAgent host`. At minimum, drop `RequestCount`, `ServiceAddr`, `ServiceURL`, `RouterName`, `ServiceName`, `KubernetesIngress*`, `KubernetesService*`, `Overhead`, `entryPointName`, `TLS*`.
2. Prefer doing it at ingest (the log shipper's request pipeline) so Loki never stores the internals. Otherwise do it in the read projection, covering both history (`parseLokiStreams`) and the live tail.
3. Keep the existing `method`/`statusCode` labels and host/path filters working (w5/m58 path filter reads the access-log store).
4. Update the dashboard pin test and add a backend test asserting no internal field and no `RequestCount` survives on any read surface.

Unverified: whether the live-tail stream is a separate path from history (both must be covered); Render's exact request-log line format (record it in ADR018 when choosing the summary). Severity: minor (information disclosure, no tenant data crosses). Estimate: ~1h.

## Closure — duplicate of w8/047 (2026-10-05)

Closed without separate work. `w8/047` (filed 2026-10-04 by the parallel `/qa-find-bugs-cli` sweep, and not yet on `main` when this note was deduped) reported the same leak. Its fix `c41d1aa91` drops `RequestCount`, `ServiceAddr`, `ServiceURL` and `RouterName` at the source (`deploy/gitops/base/values/traefik.values.yaml` `accessLog.fields.names`) and records the dropped fields in ADR010.

`ServiceName` and `KubernetesIngressName` stay deliberately, because the log shipper attributes lines with them. The remaining ask here, a readable per-request summary instead of the raw record, is presentation only. It stays the product decision recorded in `w4/068` and `w4/126`.
