## Root cause and fix

`lego/operator/internal/staticserver/staticserver.go:180-194` normalizes the request then executes matchRoutes before attempting any object lookup. Redirects return immediately; rewrites replace reqPath. The first actual fetch is :205, so the handler cannot know an existing source object should win. `fetch:272-277` and lookupPath:280-285 already resolve directory index paths; get:301-330 reuses the immutable revision cache, singleflight and bounded origin gate.

Look up the normalized requested object first, with existing key-length bounds, directory handling and bounded fetch. Serve a successful object directly. Advance to ordered rules only on ErrNotFound, then apply the existing explicit/implicit fallback contract. Never treat permission errors, timeouts or overload as absence (t003). Preserve destination validation and avoid introducing arbitrary upstream fetches. Capture requestPath separately from resolved object path for t002.

Backend SetRoutes (`lego/backend/internal/apps/service.go:4141-4160` at 4e6bd00ff) correctly stores the list after can_create/type/validation gates. No API writer fix is needed. Routes apply on resolver refresh without a build; rev-1 stayed active in this experiment.

## Severity and limits
