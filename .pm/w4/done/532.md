# 532 — New Blueprint from a Public Git URL leaves Branch empty with no options and no hint; the preview never runs until the user types a branch

Why: on the New Blueprint page's Public Git URL tab, a workspace without a GitHub connection gets an empty Branch combobox. The list is empty, nothing is prefilled, and nothing says to type a branch. The preview and "Deploy Blueprint" stay blank and disabled, so the form looks stuck. The service create form handles the same public repo by resolving its default branch. Render pre-selects the repository's branch for a public Git URL.

**Severity:** minor (the flow completes once the user types a branch name; nothing is lost) · **Estimate:** 40m · **Worker:** worker4 · **Status:** done

- **Source:** live `/qa-find-bugs w4`, production, 2026-11-06 20:08–20:20 UTC, round 193, pin `cdad468d6` (`5ffbe82b3c2f`), workspace `bex-canary` (no GitHub connection). Read-only: only previews ran, nothing was created.

- **Root cause:**
  - `dashboard/src/routes/blueprints.new.tsx:85-87`: `branch` starts as `"main"` only for a linked repo (`?repo=` deep link); a Public Git URL typed into the tab starts at `""`.
  - `:121-128`: the effect that fills the default branch runs only for `tab === "github" && selectedRepo` (a connected repo's `defaultBranch`).
  - `:113` `useRepoBranches(sourceRepo)` feeds the picker, but `lego/backend/internal/github/service.go:901-904` (`ListBranches`) returns `[]` when the workspace has no connection for the repo's owner. The comment at `github/graphql.go:124-126` says this is so "the UI degrades to free text", but the UI gives no sign that free text is expected.
  - `useBlueprintPreview(sourceRepo, branch.trim(), …)` (`:119`) does not run with an empty branch, and the backend refuses it anyway: `lego/backend/internal/apps/blueprint.go:1090-1091` (preview) and `:1133-1134` (create) require a branch, unlike service create, which resolves the default branch through `ValidateRepo` (`apps/service.go:2190-2195`).
- **Fix — target behavior:** on the Public Git URL tab, a public GitHub URL with no branch typed previews and deploys the repository's **default branch**, and the Branch field shows that branch (editable).
  - Option A (smallest): prefill the field from the linked-repo path's existing `"main"` guess. This is wrong for `master` repos, so only as a stopgap.
  - Option B (preferred): when `branch` is empty, have preview resolve the default branch the way service create does (`ValidateRepo` → `DefaultBranch`, anonymous for public repos). Return it in the preview response so the UI fills the field. Apply the same to `CreateBlueprint` (`:1133`).
  - If no branch can be resolved (non-GitHub host, GitHub refusal), the field shows a placeholder such as "Type a branch name" rather than an empty list, and the preview names the reason.
  - Optional parity follow-up: list a public repo's branches anonymously so the picker has options, as Render's does.

  - Backend preview and create are shared by REST (`POST /v1/blueprints/preview`, `POST /v1/blueprints`), GraphQL and MCP, so an empty-branch default must behave the same on all three.
