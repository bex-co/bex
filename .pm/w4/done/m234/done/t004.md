## Objective

A release-rolling configuration write on a suspended service files no deploy that can only be canceled. Today every such write opens a config-change row that the store reconciler closes "Canceled: the service was suspended". That leaves one canceled deploy and a `deploy_started`/`deploy_ended` pair per save. The rule must not reopen w5/m114's bug: Resume must never roll a release without a deploy row.

## Context

- `lego/backend/internal/rollout/rollout.go:133` `Snapshot.Stamp` decides "rolls" from `SpecRollsRelease` alone. `Patch` (`:155`), `PatchLocked` (`:178`) and `Open` (`:234`) then stamp the release generation and file the row.
- The reconciler close is at `lego/backend/internal/store/reconciler.go:917`, `:1454` and `:1464` (`suspendEndsRollout`).
- Callers, counted with `grep` (non-test, excluding definitions):
  - 19 `apps` sites through `patch` / `patchFetched` → `patchTracked` (`apps/service.go:4975`, `:4998`, `:5019`).
  - 5 `secrets.rollApp` sites (`secrets/service.go:109`).
  - 2 `envgroups.rollLinkedService` sites (`envgroups/service.go:1101`).
- Probed live in pass 9d0542 (each opened and canceled a row): REST `PUT /env-vars/{key}` and `PATCH /v1/services/{id}` `healthCheckPath`.
- A precedent for "next deploy uses it": `SetSourceAndRegistryCredential` marks Update Source pending and bypasses this path (`apps/service.go` comment above `patchFetched`). Env saves have `stagePendingProjectionReferences`.
- w5/m114 (blocked): suspend stamps the canceled release, so Resume serves the prior live release. That is what pass 9d0542 observed (rev-2, `undeployedChanges:true`, no row on resume).

## Steps

1. Enumerate the 26 call sites and classify each field family: can it be staged as pending (like env and source), or does its value have to reach the App spec?
2. Decide global vs allowlisted. A global rule in `Stamp`/`Open` (suspended → no stamp, no row) only works if Resume then either serves the prior release or opens one row for what it rolls. Check what the operator does with an unstamped spec change on resume before choosing.
3. Implement the chosen rule. Record in ADR004 which of the two resume shapes applies: no rollout with `undeployedChanges` true, or one row with Render's `service_resumed` trigger.
4. Regression tests on writers that behave correctly today: operational verbs (scale, autoDeploy, domains, notifications) still mint no row, and not-suspended writes still mint exactly one.

## Acceptance criteria

- [x] On a suspended App, REST `PUT /env-vars/{key}`, a secret-file `PUT`, and `PATCH` `healthCheckPath` / start command each succeed with no new deploy row and no `deploy_started` event.
- [x] After Resume, nothing rolls without a row: either the prior release serves with `undeployedChanges:true`, or exactly one `service_resumed` row carries the changes. A test covers the operator/reconciler side.
- [x] Not suspended: each writer still opens exactly one row, and operational verbs still open none.
- [x] w4/m171's interrupted-deploy close keeps "Canceled: the service was suspended".

## Done 2026-10-19 (loopx w4)

Global, in the shared tracker: `rollout.Snapshot.Stamp` holds a release-rolling write on a suspended App with `AnnotationPendingSourceGeneration` (the source-update hold) instead of stamping a release, and reports false, so no `config_change` row opens. That covers the 19 `apps` setters, the `secrets.rollApp` sites and `envgroups.rollLinkedService`. The compound Settings publish re-decides with `Stamp` against the App it writes (`Stage.rebase`), so a suspend that races the publish is held too, not stamped with no row. After Resume the operator keeps the prior release serving until a deploy stamps a newer one: Resume is an operational generation and never consumes the hold (`TestPendingSourceWaitsForADeployGeneration`), so no row opens on resume. Staged environment values keep `undeployedChanges` true; t008 checks both live. Rows opened before a suspend still close "Canceled: the service was suspended" (w4/m171, reconciler unchanged). Tests: `TestARollingWriteOnASuspendedServiceIsHeldForTheNextDeploy` (suspended held, running stamped) and `TestCompoundPatchRacedBySuspendIsHeld`. Residual, documented in ADR004: a non-stageable field projects onto the parked template and applies on resume, and a Blueprint sync, which stamps its own release, still files a row (split to [w4/366](../366.md)).
