# Static-site rule errors name the row by its zero-based wire index ("Routes[1]") in a toast, with nothing marked in the table

Why: a user whose second redirect row is invalid is told "Routes[1].destination must be a path starting with /". That is the wrong row number to a human reader, it uses the API's field spelling, and it disappears after a few seconds with no row highlighted. On a multi-rule list the user has to guess which row to fix.

Found live, `/qa-find-bugs` pass 167, 2026-09-25 (w4-targeted, `muse.env` credentials), journey 9. Fixture: static site `qa-20260925-edge` (`srv-darm8puuag9c73eddc60`, `https://github.com/bex-co/bex` `examples/static-site`), deleted the same pass.

- **Repro:** Redirects/Rewrites → Add rule (Redirect `/blog/*` → `/posts/*`) → Add rule (Redirect `/old` → `https://example.org/landing`) → Save routes.
- **Actual:** the toast reads **"Routes[1].destination must be a path starting with /"**. The offending rule is the second row. No row is marked invalid, and the whole save is refused (correctly, since it is all-or-nothing).
- **Root cause:** the backend message uses the wire index (`lego/backend/internal/apps/service.go:4448,4454`, and `:4496` for `headers[%d].path`). The dashboard passes it through `mutationErrorMessage` (`dashboard/src/common/lib/graphql-error.ts:26` capitalizes its first letter) into a toast (`features/services/hooks/use-static-site.ts:80` routes, `:100` headers). There is no client-side check for the rule the server enforces, even though "must start with `/`" is trivially checkable in the row.
- **Fix:** validate source and destination (and the header path) per row before save, mark the row `aria-invalid` with an inline message, and disable Save while any row is invalid. If the server still refuses, map `routes[i]` / `headers[i]` to row `i + 1` in user-facing text. The server message itself can stay as the API contract.
- **Not a finding:** refusing an absolute-URL redirect destination is the deliberate open-redirect guard (ADR029:36, recorded in `w4/121`).
- **Checked and correct this pass:** a wildcard redirect substitutes the splat (`/blog/hello` → 301 `/posts/hello`, `/blog/a/b` → `/posts/a/b`). The rewrite `/app/*` → `/index.html` serves index. Header rules apply to 200, rewritten, 301, and 404 responses alike (`x-qa-test: qa1`), and the path-scoped `Cache-Control: no-store` overrides the default only under `/app/*`. Both editors reset to clean after a successful save (the `w4/136` fix holds).

Estimate: ~30m (row validation in one editor component used by both lists, and tests).

## Done (2026-09-27)

- New `dashboard/src/features/services/lib/static-rule-validation.ts` holds the row-checkable rules bex-api enforces: a source, destination, or header path must be a path starting with `/` (after the server's own trim), a destination must not be a `//host` network-path reference (the open-redirect guard), and a header name is required. Both editors mark the offending field `aria-invalid` with an inline, described error in its own row and disable Save with "Fix the marked rows to save.". A freshly added empty row is not flagged, but Save waits with "Fill in or remove the empty row to save.".
- If the server still refuses, `use-static-site.ts` rewrites the wire index into the row a person counts: "Routes[1].destination …" becomes "Row 2: destination …" (en + zh prefix). The server message itself stays the API contract.
- Tests: `static-rule-validation.test.ts` (rules, trimming, network path, index humanizing) and two editor cases (the pass-167 second-row absolute redirect is marked, Save is held, and onSave is never called; an empty added header row is not flagged). Dashboard `yarn lint` + `yarn test` (448 files / 3718 tests) are green.
