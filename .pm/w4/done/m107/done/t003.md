## Objective

Make the range control keep its promise. Selecting "Last 7 days" on a busy service currently shows about fifteen seconds, the pane stops at its oldest loaded line, and nothing says the view is incomplete. With t001's cursors available, load older entries when the user reaches the top of the pane, and state plainly when what is shown is less than what was asked for.

## Context

- Measured live 2026-09-14 on `srv-d9bj8s3eg85c7390eb9g`: the pane is a real scroll container (`scrollHeight` 39417 vs `clientHeight` 518 — all 100 rows are loaded and virtualized, which is why a naive DOM count sees only ~13). Scrolling it to the top moved the oldest visible entry from `08:06:24 AM` to `08:05:39 AM`, then stopped.
- `dashboard/src/features/logs/` contains **no** `direction`, `fetchMore` or `loadMore` today (grepped). This is new behavior, not wiring an existing path.
- The existing empty state is good and must survive: "No matching logs / No logs match these filters" correctly separates no-matches from no-logs. The truncation notice is a **third** state, distinct from both.
- The `Live` switch appends arriving lines at the bottom. Paging adds at the top. They must not fight: decide explicitly what happens if a page-back request is in flight when a live line arrives.
- Filter state already round-trips through the URL (`?text=…&range=7d&live=0`); decide whether a paged-back position should too, or deliberately should not.

## Steps

1. On reaching the top of the pane, request the next page using `nextEndTime` and prepend, preserving scroll position so the viewport does not jump.
2. Render a truncation notice whose wording distinguishes "this is everything in the range" from "this is the newest 100 of more" — drive it from `hasMore`, not from a row count.
3. Add the strings to `en.ts` **and** `zh.ts` (`locale-parity.test.ts` enforces both).
4. Verify pending and ready states at desktop and narrow-mobile widths per `dashboard/CLAUDE.md`'s skeleton rule.

## Files

- `dashboard/src/features/logs/` — the log pane component and its query hook
- `dashboard/src/features/logs/locales/en.ts`, `zh.ts`

## Acceptance criteria

- [ ] On the service above with range `Last 7 days`, scrolling to the top of the pane loads older entries, repeatedly, past the first 100.
- [ ] Scroll position does not jump when a page is prepended.
- [ ] A capped view says so; a complete view does not (both asserted — a notice that is always present is not a fix).
- [ ] Live tail still appends, and the interaction with an in-flight page-back is whatever step 1 decided, asserted by a test.
- [ ] `yarn test` and `locale-parity.test.ts` pass.

## Out of scope

- Infinite scroll for the **events** feed, which has its own pagination.
- Changing the default range or the 100-row cap.
