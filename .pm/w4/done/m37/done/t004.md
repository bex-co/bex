## Objective

Detect when the running binary is owned by a package manager and refuse to overwrite it, printing the correct upgrade hint instead (the gh lesson recorded in `w4/030.md`).

## Context

- Resolve the running executable path (`os.Executable`, resolve symlinks) and classify it: a Homebrew Cellar path (`.../Cellar/...` or the tap's opt prefix) means `brew` owns the file.
- On such a path, do **not** download/replace — print `brew upgrade <tap>/bex` (match the tap/formula name shipped in m35) and exit 0.
- Never persist versioned install paths into user config (the gh lesson's second half).

## Steps

1. Resolve the running binary's real path and classify package-manager ownership (start with Homebrew; leave the check extensible).
2. Short-circuit the upgrade for owned paths with the `brew upgrade` hint and a 0 exit.
3. Otherwise fall through to the t002/t003 download→verify→replace path.

## Files

- `cli/internal/upgrade/`

## Acceptance criteria

- [ ] A binary under a Homebrew Cellar/opt path prints the `brew upgrade` hint and does not attempt replace.
- [ ] A raw-binary path proceeds to the normal upgrade flow.

## Out of scope

- Non-Homebrew package managers beyond an extensible hook (raw binary + brew are the shipped install channels).
