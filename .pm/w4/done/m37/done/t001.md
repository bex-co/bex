## Objective

Add a `bex upgrade` subcommand that resolves the newest `bex-cli/v*` release and the asset matching the running host (OS/arch), or no-ops with a clear "already on the latest" message when the running `bexVersion` is current.

## Context

- `cli/main.go` — `bexVersion` (build-injected), `latestRelease()`, `printVersion`; the version path already intercepts `-v`/`--version`.
- `cli/internal/update/update.go` — `TagPrefix = "bex-cli/v"`, `Checker`, `update.Newer`, `update.Allowed`. **Reuse** this release listing/filter; do not duplicate it.
- Assets are named per m35's release pipeline (`scripts/bex-cli-build.sh` / `.github/workflows/cli-release.yml`) — confirm the exact OS/arch asset naming and match against `runtime.GOOS`/`runtime.GOARCH`.
- The command must register on the bex-owned command tree (same place `IsRootVersionRequest` is handled), not upstream `render-oss/cli`'s cobra tree.

## Steps

1. Add a `bex upgrade` command (bex-native, alongside the version interception in `main.go`).
2. Reuse `cli/internal/update` to list `bex-cli/v*` releases and pick the newest; compare with `bexVersion` via `update.Newer`.
3. When current: print an "already latest" line and exit 0.
4. When newer: resolve the release asset for `runtime.GOOS`/`runtime.GOARCH` (error clearly if no matching asset). Leave the download/replace to t002.

## Files

- `cli/main.go` (or a new `cli/internal/upgrade/` package)
- `cli/internal/update/` (reuse; extend only if listing needs the asset list)

## Acceptance criteria

- [ ] `bex upgrade` exists and resolves the newest `bex-cli/v*` release.
- [ ] Current-version run no-ops with a clear message and exit 0.
- [ ] Newer-version run resolves the correct per-OS/arch asset (or errors clearly when none matches).

## Out of scope
