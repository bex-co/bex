# 549 — A project's resource table reads an environment group's Status, Runtime and Region as "Not available"

Why: status, runtime and region don't apply to an environment group. A screen-reader user hears "Not available" three times, as if the dashboard failed to load them, on a row that has nothing missing.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 21, 2026-11-10 13:25–13:40 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor** (assistive-tech copy). ~15m.
- **Fixture:**
  - Project `qa-20261110-p21` (`prj-dbphnpk5ngvc73e8tqd0`), with environments Production (`evm-dbphnpk5ngvc73e8tqdg`) and Staging (`evm-dbphnpk5ngvc73e8tqe0`).
  - Env group `qa-20261110-eg21` (`evg-dbphnu45ngvc73e8tqf0`), moved from Production to Staging with Manage → Move group. The move itself was clean: the toast, details, breadcrumb, API and both environments' counts agreed.
  - All deleted (GET 404).
- **Probe:** `/project/prj-dbphnpk5ngvc73e8tqd0?env=<Staging>`.
  - The accessibility tree lists `row "Select qa-20261110-eg21 qa-20261110-eg21 Env Group Not available Not available Not available now"`.
  - Each of the three cells is `<span aria-label="Not available">—</span>`.
- **Root cause:**
  - `toEnvGroupRow` sets `runtime: null` and `region: null` (`dashboard/src/features/projects/hooks/use-grouped-resources.ts:67-78`).
  - `resource-table.tsx` renders every null value with `UnknownValue`: runtime at `:216`, region at `:219`, and status at `:328`, the fallback after the service, database and Key Value branches.
  - `UnknownValue` (`:378-380`) reads `projects.metadataUnavailable`, "Not available" (`features/projects/locales/en.ts:185-188`, `zh.ts:176`).
- **Precedent:** [w4/481](done/481.md) (done) fixed the same class of bug, but only for a static site's Runtime cell.
- **Fix (target behavior):**
  - An env-group row's Status, Runtime and Region cells read as not applicable: a visible "—" with an accessible "Not applicable", or no placeholder at all, letting the column header do the work.
  - Use a new locale key. `metadataUnavailable` stays for service and datastore values that are genuinely missing.
  - en and zh copy.
  - Add a test: the env-group row's cells don't say "Not available", while a service row with a missing region still does.
- **Blast radius:** `toEnvGroupRow` has two callers: the project table (`use-grouped-resources.ts`) and the environment card (`features/environments/components/environment-card.tsx:212`). Check how the card renders the same row.
- **Unverified:**
  - The environment card's env-group row.
  - Whether `aria-label` on a generic span is announced consistently across screen readers. Playwright and Chrome both expose it as the cell name.
- **Dedupe:**
  - w4/481 (done) covered only a static site's Runtime cell.
  - `grep -rlE 'metadataUnavailable|"Not available"' .pm` finds nothing open.
  - Not deploy lag: `git log c12cd57facb1..origin/main -- dashboard/src/features/projects` is empty.
- **DoD (live):**
  - On an owned project environment holding an env group, the row's Status, Runtime and Region read "Not applicable" (or carry no placeholder text), in en and zh.
  - A service row with a missing value still reads "Not available".

- **2026-11-11 (loopx w4):** fixed: `ResourceTable`'s dash for a value an env group doesn't have (Status, Runtime, Region) reads "Not applicable" (en/zh `projects.metadataNotApplicable`); a service or datastore value that is genuinely missing still reads "Not available". The environment card renders the same table, so it is covered too. Test asserts both.
