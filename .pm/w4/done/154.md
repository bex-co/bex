# After `w8/021`, a missing job, env var, secret file, or custom domain on a real service still reads as a bare "not found"

Why: `w8/021` fixed exactly this ambiguity for deploys ("a missing deploy on a real service read as a missing service"). Its own plan also named `job not found`, but on production the other child resources of an existing service still answer the neutral text, so a caller cannot tell "no such key/file/domain/job" from "no such service".

Found live, `/qa-find-bugs` pass 195, 2026-09-26 (w4-targeted, `muse.env` credentials), read-only against the deployed `726042a28` (pinned 06:50). Parent: the real service `srv-d9bj8s3eg85c7390eb9g`.

| REST probe (all 404, `id: not_found`) | message |
| --- | --- |
| `GET /v1/services/{srv}/deploys/dep-doesnotexist00000000` | `deploy not found` ✅ (the `w8/021` fix) |
| `GET /v1/projects/prj-doesnotexist00000000` | `project not found` ✅ |
| `GET /v1/blueprints/blp-doesnotexist00000000` | `blueprint not found` ✅ |
| `GET /v1/services/{srv}/jobs/job-doesnotexist00000000` | `not found` ❌ (`w8/021` step 2 names `job not found`) |
| `GET /v1/services/{srv}/env-vars/QA_NO_SUCH_KEY_ZZ` | `not found` ❌ |
| `GET /v1/services/{srv}/secret-files/qa-no-such-file.txt` | `not found` ❌ |
| `GET /v1/services/{srv}/custom-domains/qa-no-such.example.com` | `not found` ❌ |

Top-level misses (`/services/srv-…`, `/postgres/dpg-…`, `/key-value/red-…`, `/env-groups/evg-…`) stay neutral, which `w8/021` accepts. GraphQL matches REST (`project not found`; `database`/`keyValue`/`envGroup` → `not found`).

- **Fix:** return `core.NotFound("job" | "env var" | "secret file" | "custom domain")` from the child-lookup paths once the parent service has been authorized and found, as `deploys` now does. `grep -rn 'core.ErrNotFound' lego/backend/internal/{jobs,secrets,apps}` locates the call sites; count them in the fix.
- **Adjacent classes:** name the child only after the parent authorizes. A caller without access to the service must keep getting the parent-level answer, so child naming never becomes an existence oracle. Keep `id: not_found` and 404 unchanged.
- **Aliases:** the same lookups back GraphQL (`service{ envVar(key) / secretFile(name) }`) and MCP (`get_env_var`, custom-domain and job tools). One change in the shared verbs covers all three surfaces.

Estimate: ~30m.

## Done (2026-09-27)

`grep -rn 'core.ErrNotFound' lego/backend/internal/{jobs,secrets,apps/domains.go}` found 12 child-lookup returns, every one after the parent service authorized. They now return `core.NotFound(...)`: `jobs/service.go` Get and Cancel ("job", 2 sites), `secrets/service.go` GetEnvVar, DeleteEnvVar (both branches), and EnvVarValue ("env var", 4 sites), `secrets/files.go` GetSecretFile and DeleteSecretFile ("secret file", 2 sites), and `apps/domains.go` GetDomain and VerifyDomain ("custom domain", 4 sites). Each keeps `errors.Is(err, core.ErrNotFound)`, so status 404, `id: not_found`, GraphQL, and MCP are unchanged except for the message. A missing **service** still answers the neutral text, so naming the child never becomes an existence oracle. Tests: `jobs/notfound_test.go` (REST "job not found" vs the neutral service miss), plus strengthened `secrets_test.go` (env var, and neutral on a missing service), `files_test.go`, and `domains_test.go` message assertions. Backend jobs/secrets/apps/api tests and golangci-lint are green. No dashboard code matches on the bare "not found" text.
