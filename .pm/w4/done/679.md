# 679 — A refused workspace, build source or legacy Blueprint create still records a `success` row: these three create verbs write their audit row at authorization, before the write can fail

Why: a `success` row in the audit log should mean the action happened. w4/m321 t012 moved the service, env group, environment, webhook and Render Blueprint creates to record once the resource exists. These three still record at authorization, so a create refused after it leaves a row claiming a resource that never existed. This is the class w6/031 fixed for Key Value.

- **Source:** w4/m321 t012 step 2, `/loopx w4` 2026-11-16. Found by grepping every `RelCanCreate` authorization in `lego/backend/internal`. Not probed live.
- **The three verbs:**
  - `workspaces.Create` (`lego/backend/internal/workspaces/service.go`, `Authorize(ctx, core.RelCanCreate)` before the store write) maps to `CreateWorkspaceEvent`. It can still be refused after that by the payment gate (402) and by store errors.
  - `apps.CreateBuildSource` (`lego/backend/internal/apps/build_sources.go:189`) maps to `CreateBuildSourceEvent`. It can still be refused by validation and the link checks, and its undo path deletes the carrier again.
  - The legacy `apps.CreateBlueprint` (`lego/backend/internal/apps/blueprint.go:1300`) can still be refused by fetch, compile and apply.
- **Fix shape:** authorize under `core.WithDeferredAllowedWriteAudit`, then call `RecordAllowedWrite(ctx, verb, relation, workspaceID, target, targetName)` once the write has landed, naming the resource. Follow `apps.Create` and `envgroups.CreateEnvGroup` (w4/m321).
  - A build source is an App carrier, so choose its target kind with care: a `service:` target joins the per-service events feed.
  - The workspace create's row belongs to the new workspace.
- **Done when:** for each verb, one test shows that a create refused after authorization records no allowed row, and a successful create records exactly one row naming the resource.
- **DONE 2026-11-16:** all three creates authorize under `core.WithDeferredAllowedWriteAudit` and record once the resource exists. `workspaces.Create` records in the new workspace's log (`workspace:<tea->`, `targetName` its label) after the admin grant; `apps.CreateBuildSource` records `service:<bds->` + its name once its links landed (or when a later link fails and the source stays), and the undo of a refused create records no delete; the one-step `apps.CreateBlueprint` records `blueprint:<id>` + its name once its first apply completed, so a failed apply records none and the retry that succeeds records the one. Tests: `TestCreate_RecordsOneRowOnlyForAWorkspaceThatExists` (`lego/backend/internal/workspaces/workspaces_test.go`), `TestBuildSourceCreateRecordsOneNamedRowOnlyForASourceThatExists` and `TestCreateBlueprintRecordsOneNamedRowOnlyOnceItApplied` (`lego/backend/internal/apps/create_audit_test.go`), each failing with the fix reverted. Out of scope: the interactive `FinalizeWorkspaceCreation` path records under its own verb, not `CreateWorkspaceEvent`.
