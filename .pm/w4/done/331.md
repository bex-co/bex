# Blueprint source tabs discard the chosen Public Git branch

Why: returning to the same repository clears an entered deployment setting and replaces a successful review with a prompt to enter it again.

**Status:** done — the remaining desktop/fresh-mobile live gate and its GitHub/default and service-create controls pass in a884, 2026-10-17. See the acceptance below; the original finding and implementation notes remain historical.

**Severity:** minor. Deploy correctly becomes disabled after the loss, and re-entering the branch recovers; no wrong-branch deployment or persisted change was observed. **Estimate:** 55m (local draft policy 15m, caller/consumer audit 10m, regressions 20m, live replay/Simplify 10m). Functional `$qa-find-bugs w4`, a773, 2026-10-16 UTC. Research main `7a5a225df`; filing only. Goal: usable Blueprint review under ADR008, ADR049 and ADR018.

## Reproduce and target

1. Freshly open `/blueprints/new` and choose **Public Git URL**. Enter `https://github.com/bex-co/bex`, a disposable Blueprint name, Branch `main`, and Blueprint path `examples/hello-go/render.yaml`.
2. Wait for the successful review. It reports one Create action for `hello-go`; **do not deploy this example**. This pass submitted no Create or Sync. The native BlueprintPreview response is HTTP 200, found/valid true, commit `7a5a225df294de49d53765d7c3001ba1ca34bf3e`, one action and no validation errors.
3. Click **GitHub**, then **Public Git URL**, without selecting a GitHub repository or editing the URL. Branch's actual DOM value becomes `""`, while URL, Blueprint Name and path remain. Gray `main` placeholder text is not a retained value. The review becomes “Select a repository and branch…” and Deploy becomes disabled.
4. A fresh 390×844 page independently reproduces the same before/after state. Re-entering `main` restores the successful review and enabled Deploy without changing other fields.

[Complete native preview operation/response, DOM states, recovery, independent controls and cleanup](../evidence/331-a773.json). The screenshot pairs were viewed; the mobile before crop omits the footer, so the durable DOM state establishes its enabled button. Ignored images are supporting evidence.

**Target:** when a Public Git draft returns to its unchanged URL, restore its entered Branch exactly. Keep the current abandonment of a GitHub selection, correct default branch for a newly selected GitHub repository, intentional blank Branch, and existing name/path behavior. Associate retention with that Public Git URL; do not restore a different repository's branch or copy a GitHub branch into the Public Git draft. While a restored source's preview is unsettled, retain the existing preview-loading gate and review behavior; branch restoration alone must not enable unreviewed deployment.

## Root and consumer

- `dashboard/src/routes/blueprints.new.tsx:243–247` handles each real source-tab change with `setTab(next)`, `setSelectedRepo(null)` and unconditional **`setBranch("")`**. Its independent gitUrl/name/path states survive. This directly accounts for the discriminator.
- The Branch Combobox is controlled by that `branch` state at 275–281. `common/components/ui/combobox.tsx:63–73` synchronizes its input when the controlled value changes, so it correctly reflects the empty value supplied by the route.
- The route's auto-fill effect at 89–100 supplies a branch only for a selected GitHub repository; its Public Git branch merely derives the name. Returning with the original URL therefore does not restore `main`.
- `features/blueprints/hooks/use-blueprint-preview.ts:46–64` skips incomplete repo/branch inputs. The route checks `branch.trim() !== ""` at 120 and uses trimmed branch/path for creation at 130–132. The existing query/create declarations use string Branch fields (`features/blueprints/api/blueprints.graphql:76–86,168–180`), so the current local state/schema can express the retained value. No API, schema or preview-cache rewrite is needed.

Use the URL-bound Public Git draft policy already established for service creation, implemented locally in this Blueprint producer. Do not globally remove branch resets in ServiceSourcePicker or change Tabs/Combobox semantics.

**Actual dependency review:** lock-pinned Radix Tabs 1.2.1 and react-use-controllable-state 1.2.2 npm archives were integrity-verified and opened, with member hashes/excerpts in the evidence. Tabs forwards controlled changes through useControllableState; its controlled setter calls onChange when the next value differs. This agrees with the passing active-tab click control. Fix the application's reset, not the library. Exact hosted Radix patch provenance was not independently attested.

## Passing controls and shared scope

- Ordinary Blueprint Name editing retains `main`; clicking the already active Public Git tab retains it too.
- Re-entering `main` recovers the review. Selecting GitHub repository `onefx` correctly uses its `master` default. This is a branch-default control, not a claim that repository contains the selected Blueprint path.
- The independent service-create form preserves `main` and the same Public Git URL across the identical tab round trip, matching the completed [w4/240](../done/240.md) policy.

ServiceSourcePicker has **three** production mounts: Service Create, Blueprint Create and the existing-service Source card. They have independent callbacks. `useBlueprintPreview` has **two** production consumers: this create route and the detail page's pre-sync review. Scope the change to the one NewBlueprintPage producer; preserve the other source editors and the shared detail-preview behavior. The canonical `/blueprints/new` route and its New-menu entry share that producer. Postgres/Key Value have separate create forms.
