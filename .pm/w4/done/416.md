# 416 — Blueprint validation points paid-plan refusals at `services[N].type` instead of the field to change

Why: the validate response, the dashboard's Blueprint review and the CLI all send the author to the `type:` line, which is correct, while the thing to change is `plan:` (or the paid-only feature declared on a free plan).

**Severity:** minor (the refusal itself is correct; its location is wrong). **Estimate:** ~45m. **Source:** live `/qa-find-bugs w4` loop run d8cf, 2026-10-26 UTC (`muse.env`, `bex-canary`, pin `b4726243e74f`), REST through the run's session jar. Validation creates nothing; no fixtures.

`POST https://api.bex.co/v1/blueprints/validate` (multipart: `ownerId=tea-daif693dqjvc73e7as3g`, `file=@<manifest>`). The manifests are kept as [evidence/416-free-postgres.yaml](../evidence/416-free-postgres.yaml), [evidence/416-two-free-keyvalues.yaml](../evidence/416-two-free-keyvalues.yaml) and [evidence/416-free-scaling-disk.yaml](../evidence/416-free-scaling-disk.yaml).

## Root cause

`lego/backend/internal/apps/blueprint.go:2123-2144` `blueprintErrorField` guesses the field by substring-matching the message against a keyword list. "plan" is absent from these messages, and "instance **type**" matches `type` before `scaling` is reached; `disk` is not in the list at all. Its callers are `blueprint.go:800` (JSON pointer) and `:2117` (display path).

This is the fourth instance of the same guessing flaw. w8/055 (hostnames → `.name`), w8/100 (environment errors) and w8/101 (static rules) each patched one keyword. The free-limit case is new with w4/m241 (`core/quota.go:128,132`). The other two messages are `apps/service.go:5732` (autoscaling) and `apps/disks.go:323` (disks).

## Fix (target behavior)

- `FREE_INSTANCE_LIMIT` (both the existing-holder and the in-stack forms, `blueprint_preview_creates.go:93,118`) maps to the resource's `.plan` path by **error code**, not text.
- A paid-feature refusal on a free plan points at the feature field the author declared: `.scaling` for autoscaling, `.disk` for disks.
- No message containing "instance type" is attributed to `.type`. Prefer carrying the field from the refusal site (a typed field on the error) over extending the keyword list; at minimum, check `plan`, `scaling` and `disk` phrasing before `type`.
- One validator, so REST `POST /v1/blueprints/validate`, the dashboard review (GraphQL `blueprintPreview`) and the CLI's `blueprints validate` move together.
