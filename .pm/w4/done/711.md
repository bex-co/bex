# 711 — Search finds settings sections such as API keys, as Render's search shortcuts do

Why: Render's dashboard search jumps "directly to your API keys, webhook settings, compliance docs, and more", while bex's search finds no result for "API keys" and the member has to know it sits under Account Settings.

**Severity:** minor. **Estimate:** ~1h. **Source:** `/pm-brainstorm one more aspect of render parity for w4`, 2026-11-20, item 5; filed by `/pmx them to w4`.

## Evidence

- **Render:** changelog 2025-06-26, "Added shortcuts to Render Dashboard search results": "Jump directly to your API keys, webhook settings, compliance docs, and more—all with a few keystrokes."
- **bex:** the search palette's Navigation results (`dashboard/src/common/components/dashboard-layout/global-search-dialog.tsx` ~:145-168) are the sidebar's destinations (`dashboard-nav.ts`) plus Workspace Settings and Account Settings. Account Settings has section anchors (`dashboard/src/features/auth/pages/settings-page/index.tsx`: `#account`, `#appearance`, `#integrations`, `#access`, `#danger-zone`; `security-compliance-section.tsx`: `#security`), and none of them is a search result. Webhooks is already reachable as a sidebar page.

## Fix

1. Read Render's shortcut list from its public dashboard bundle (as `docs/render-artifacts/account-appearance.md` did) and record it in a short section of that capture or a new one.
2. Add one Navigation result per shortcut bex has a destination for, deep-linking to the section anchor (API keys and SSH keys under `#access`, and the Workspace Settings sections), behind the same feature gates as the sidebar; add the strings to every locale.
3. Record shortcuts with no bex destination (compliance docs: bex publishes none) as omissions in the capture, not as results.

## Acceptance criteria

- [x] Typing "API keys" in search and pressing Enter lands on Account Settings scrolled to the API keys card; the same holds for every shortcut recorded in step 1 that bex has.
- [x] Opening, filtering and closing the search palette keeps its existing focus and reset behavior (w4/265, w4/291).

## Outcome

**Done 2026-11-22.** Render's live bundle still carries the shortcut list (checked first, since w4/m552's feature had left Render's dashboard): 20 shortcuts, Render's keywords, and a match that needs 3 or more characters. The list is recorded in [search-shortcuts.md](../../../docs/render-artifacts/search-shortcuts.md) along with bex's omissions: compliance documents, HIPAA, metric and log streams, and the sandboxes docs. `search-shortcuts.ts` adds Git credentials, Audit Logs (Admins only), API Keys, SSH Keys, CLI Tokens and Container Registry Credentials as section links, and Environment variables, Custom domains and MCP Server as bex docs pages. The shortcuts that point at an existing page instead lend it Render's keywords ("home" finds Projects, "invoice" finds Billing). Names and descriptions are in all 8 locales. The API keys card gained Render's `#api-keys` anchor. On a live dev-4 check (1000 px and 375 px wide), Workspace Settings' Agents cards shrank by about 2,000 px after the router's hash scroll and left `#registry-credentials` scrolled past. `SectionNavigation` now holds the hashed section in place until the reader scrolls or 5 s pass. Every in-app shortcut then landed its card 73 px below the scroller top (the sticky bar's scroll margin). The regression tests are `global-search-dialog.test.tsx` (`Render's search shortcuts`), `section-navigation.test.tsx` (`holds the URL's section`) and `api-keys-panel.test.tsx` (`anchors settings#api-keys`).
