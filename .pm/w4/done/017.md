Render Environment REST still diverges on `ipAllowList`: Render documents an array of `{cidrBlock, description}` objects on create/retrieve/update, while `internal/environments` exposes string CIDRs and updates them through the bex-only `/acl` route. Align the standard POST/PATCH response/input wire shape without changing GraphQL/MCP's product-neutral string-list core; found during w4/m22's Render-parity closeout after its cursor-envelope fix.

## Resolution (2026-07-15) — done

The **read** side was already Render's object form (`rest.go`'s `renderCIDR`); the real gap was input. Closed by giving the standard routes Render's full documented body (re-verified live at api-docs.render.com create/update-environment — `ipAllowList` travels with `protectedStatus` + `networkIsolationEnabled`, so all three were aligned together, not just the ip list):

- **POST `/v1/environments`**: optional ACL triple, `ipAllowList` as `[{cidrBlock, description}]` (description accepted and discarded — the documented apps/postgres/keyvalue convention). Validated via a new shared `validateACL` (factored out of `SetACL`, one source of truth) BEFORE the row is created, so a bad CIDR is a clean 400 with no orphan environment; then applied through the same `SetACL` verb the `/acl` route uses.
- **PATCH `/v1/environments/{id}`**: every field optional (pointer-decoded so `networkIsolationEnabled: false` is appliable), per-field partial — absent ACL fields keep their current values, merged by the handler into the full-replace `SetACL` core; empty body stays 400.
- GraphQL/MCP string-list core and the bex-native `/acl` route unchanged, per the note's constraint.
- Tests: `TestREST_CreateAcceptsRenderACLObjects`, `TestREST_CreateRejectsBadACLWithoutOrphan`, `TestREST_PatchMergesRenderACLFields`. Docs: ADR018 Projects & environments row ◐ → ✅ (+ gap-backlog row closed), ADR032 §Protected-environment ACLs.
