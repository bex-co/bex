# 482 — Every expanded custom-domain DNS panel names its copy buttons "Copy CNAME host" / "Copy CNAME target", with no domain

Why: w4/436 gave each domain row's "Show DNS setup" and actions buttons the domain's name. The copy buttons inside the DNS panels, which are expanded by default, still share one name per record type. A screen-reader or voice-control user with two domains hears four "Copy CNAME …" buttons and cannot tell which domain's record they copy.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 49, 2026-11-05 06:14–06:17 UTC (`muse.env`, `bex-canary`, pin `dcdc774c1a6b`); **minor** (accessibility); ~20m.
- **Probe:** owned static site `qa-20261105-dom` (`srv-dbm1tboiff5c739puv5g`) with two throwaway domains, `qa-20261105.example.com` and `www.qa-20261105-apex.example.org`, added via `POST /v1/services/<id>/custom-domains` (`201`, CNAME → `qa-20261105-dom.onbex.co`). All were removed in the same visit (`DELETE` `204`, list `[]`, service `404`).
  - `/static/<id>/settings` → Custom Domains. Both rows' controls read `Show DNS setup for <domain>` and `Actions for <domain>`, so 436 holds. Both DNS panels are `[expanded]`.
  - The accessible names of the buttons inside the panels, in DOM order: `["Copy CNAME host","Copy CNAME target","Copy CNAME host","Copy CNAME target"]`.
- **Root cause:** `dashboard/src/features/services/components/custom-domains-section.tsx:378-400` `DnsRecordFieldsRow` labels its copy buttons `services.domainCopyHost` / `services.domainCopyTarget` (`"Copy {type} host"` / `"Copy {type} target"`, `locales/en.ts:1750-1757`, zh `:1715-1722`). It never receives the domain. `DnsRecordFields` (`:342`) renders it once for the record. For an apex domain it also renders it once per edge address (`:366-370`), so even a single apex domain gets several identical `Copy A host` / `Copy A target` buttons.
- **Fix (target behavior):** each copy button's accessible name names the domain, and for repeated A rows the value too. For example: `Copy CNAME host for qa-20261105.example.com`, `Copy A target 203.0.113.7 for example.com`. Pass `domain.name` from `DnsRecordFields` into `DnsRecordFieldsRow`, extend both message keys (en + zh), and keep the visible "Copy" icon unchanged. Cover the add-domain dialog's instruction panels (`:618`, `:628`, primary and sibling), which share the row component.
- **Tests:** a component test with two domains (and one apex with two edge addresses) asserts that all copy-button names are unique and contain the domain.
- **Blast radius:** `DnsRecordFieldsRow` has 2 call sites (`:354`, `:367`) and is reached from 3 `DnsRecordFields` sites (`:430` row panel, `:618` and `:628` add dialog). The single production caller of the section is the service Settings route (w4/436).
- **Unverified:** the apex A-row duplication and the add-dialog panels were read from code, not exercised live this round.
- **Render:** n/a (bex's own control naming); Render shows one record per domain section.
- **Dedupe:** residual of w4/436 (done), which named the row-level buttons only. `grep -ril "Copy CNAME" .pm` finds nothing. No DO_NOT_DO item applies.

Closed 2026-11-05: `DnsRecordFieldsRow` takes the domain (plus the edge address on apex A rows) as `subject`; copy buttons read e.g. "Copy CNAME host for api.example.com" / "Copy A target for foo.com (203.0.113.11)" (en + zh); test asserts all names unique.
