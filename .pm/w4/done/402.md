# 402 — The static-site Headers editor checks only path and name-required per row: a reserved or malformed header is refused by a toast with nothing marked

Why: w4/145 moved static-rule errors into the row, but the Headers editor checks only two of the server's rules in the row. The others are just as easy to check client-side: reserved names like `Content-Length`, invalid name characters, CR/LF in a value, and `Set-Cookie` with `Domain`. They still reach the user as a few-second toast ("Row 7: …") with no field marked, so on a long rule list the user has to find the row from the number.

**Severity:** minor (polish on an error path; the save is correctly all-or-nothing and no input is lost). **Estimate:** ~30m. **Source:** live `/qa-find-bugs w4` loop run h8d3, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `29d63e1f7bea`). Fixture: static site `qa-20261024-h8d3-hdr` (`srv-dbe3gbb17lic73al6qm0`, `bex-co/bex` `examples/static-site`). It was deleted (`DELETE` → `204`, `GET` → `404`); session revoked.

## Probe

1. Six header rules were added via `POST /v1/services/<id>/headers` → `201` each (Render's `{headers:{id,path,name,value}}`). Served behavior was correct:
   - `/docs/a.html` carried `/*`, `/docs/*` and exact-path headers.
   - The later `/docs/*` `X-Qa-All` rule overrode the `/*` one.
   - `/data.json` got `cache-control: no-store`.
   - A `404` (`/docs/`) still carried the matching headers.
2. `/static/<id>/headers`:
   - Editing row 3's value to `max-age=60`, then **Add header** `/*` · `Content-Length` · `5` → **Save headers**.
   - Result: toast only, **"Row 7: name "Content-Length" is set by the server and cannot be overridden (it frames the response body or the connection)"**. No input in row 7 has `aria-invalid`, and no inline message appears.
   - Save was not held beforehand. The stored list was unchanged (`all,docs,no-store,DENY,docs-override,exact`), and the typed rows stayed in the editor.

## Root cause

- `dashboard/src/features/services/lib/static-rule-validation.ts:86-94` `headerErrors` checks only `pathError` and an empty name.
- The server's `validateHeaders` (`lego/backend/internal/apps/service.go:5381-5411`) also refuses several row-local cases:
  - a name over `maxStaticHeaderNameLen`;
  - `!httpguts.ValidHeaderFieldName`;
  - `ReservedStaticHeader` (`lego/types/v1alpha1/static_headers.go:26-29`: `Content-Length`, `Transfer-Encoding`, `Connection`, `Keep-Alive`, `Upgrade`, `Te`, `Trailer`, `Proxy-Connection`; case-insensitive);
  - a value over `maxStaticHeaderValueLen`, or containing CR/LF/control characters (`ValidHeaderFieldValue`);
  - `Set-Cookie` whose value has a `Domain` attribute.

## Fix

- Extend `headerErrors` with those row-local checks:
  - a header-token name check (RFC 7230 `tchar`);
  - the reserved-name set, compared case-insensitively;
  - a value control-character check, which allows HTAB;
  - the `Set-Cookie` + `Domain=` check;
  - the path/name/value length limits.
- Each gets an en + zh message key, so the row is marked `aria-invalid` and Save is held with the existing "Fix the marked rows to save.".
- Keep the reserved list in one place the dashboard can't drift from. Mirror it in a dashboard test against the Go list, or generate it. The list-level rule ("must not exceed N items") stays server-only, still shown via the humanized toast.
- Tests: `Content-Length`/`content-length`, `Bad Name`, a value with `\n`, and `Set-Cookie: a=b; Domain=onbex.co` each mark their own row and hold Save. A valid `Set-Cookie: a=b; Path=/` is not flagged.

**Unverified:** the GraphQL `setStaticHeaders` and MCP paths (they share `validateHeaders`, read from code); Render's own header-rule validation messages.

## Loopx w4 verdict (2026-10-25)

Done: `headerErrors` now checks the reserved-name set (mirroring `lego/types/v1alpha1/static_headers.go`, pinned by a dashboard test), the RFC 7230 header-token name rule, value control characters (HTAB allowed), `Set-Cookie` with a `Domain=` attribute, and the 2048/256/4096 path/name/value limits — each with en + zh row messages, so the row is marked and Save is held. The list-count rule stays server-only.
