## Objective

Add dashboard server-fns (beside `hydra-consent.ts`, same pattern) that list the signed-in user's Hydra consent sessions and revoke one by client id. Revocation via Hydra's admin API also revokes the client's access/refresh tokens — that's the mechanism the Connected-agents card rides.

## Context

- Hydra admin API: `GET /admin/oauth2/auth/sessions/consent?subject=<subject>` (list grants: client, scopes, handled-at) and `DELETE /admin/oauth2/auth/sessions/consent?subject=<subject>&client=<id>` (revoke + kill tokens).
- `dashboard/src/common/server-fn/hydra-consent.ts` — existing `HYDRA_ADMIN_URL` plumbing (server-only env, never `VITE_`); follow its error handling (503 when unset).
- The subject is the caller's Kratos identity id from their session (`session.ts`) — never accept a subject from the client.

## Steps

1. Add `listConsentSessions` / `revokeConsentSession` server-fns; derive the subject from the session server-side.
2. Map Hydra's response to the card's shape: client id, client name (from the DCR client metadata), granted scopes, grant date.
3. 503-with-explanation when `HYDRA_ADMIN_URL` is unset (matching the consent route's behavior).

- [ ] Revoke removes the grant and Hydra reports the client's token inactive afterward (asserted in t004's e2e).
- [ ] Unit tests cover the mapping + the unset-env 503.
