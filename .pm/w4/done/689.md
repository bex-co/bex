# 689 — A deploy hook called without `key` answers 404; Render answers 401

Why: CI scripts tell a broken hook URL from a regenerated hook by Render's documented status codes, and bex answers both cases with 404.

- **Source:** `/pm-brainstorm for one aspect of render parity` (the Deploys aspect), 2026-11-16, item 5; filed by `/pmx them all to w4`.
- **Render reference:** render.com/docs/deploy-hooks, read 2026-11-16: `key` "Required. If it's missing, the response is 401. If it's invalid, the response is 404."
- **bex today:** `lego/backend/internal/deploys/deployhook.go:356` reads `key`; `appForDeployHookToken` (`:264-266`) returns `core.ErrNotFound` for any token `validDeployHookToken` refuses, the empty one included.
- **Fix:** an absent or empty `key` answers 401 in bex's standard error envelope before the lookup; an invalid key stays 404. Keep the rate limiter's place and the `Cache-Control: no-store` / `Referrer-Policy` headers. Table test for missing, empty, malformed, unknown and valid keys. Note it on ADR018's Secret deploy hook row.
- **Estimate:** ~20m. **Render parity:** applies (REST status code); GraphQL/MCP/dashboard have no hook route.

**Done 2026-11-16:** `DeployHookHandler` answers a missing or empty `key` with `401 unauthorized` (`core.WriteErrStatus`, "deploy hook key is required") ahead of the limiter, so keyless callers never share the empty key's bucket and see 429; malformed, unknown and rotated keys stay 404, and both headers are set first as before. `TestDeployHookKeyStatusesMatchRender` (missing, empty, malformed, unknown, rotated, other path, valid; GET and POST) and `TestDeployHookMissingKeyIsNotRateLimited` fail with the check removed. ADR018's Secret deploy hook row records the statuses and drops the stale "invalid key 401 / uniform 404" drift.
