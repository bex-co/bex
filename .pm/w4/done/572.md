# 572 — A Blueprint preview reports every database and Key Value it declares as already in the workspace, so a first-time stack is offered only as a suffixed copy (`mattermost-72wr`, …)

Why: a brand-new Blueprint should create its resources under the names in the file. Preview instead claims a database or Key Value that doesn't exist is "Already in your workspace". The dashboard then reviews the whole stack as a separate set and Deploy creates every resource with a random suffix.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 94, 2026-11-11 10:08–10:20 UTC (`muse.env`, workspace `bex-canary`; production runs the code of `7ca0227aa477`). **Major**: the first deploy of any Blueprint that declares a datastore gets renamed resources, and the preview misstates what exists. ~30m.
- **Fixture:** none created. Previews only, of public files in `https://github.com/bex-co/bex` on `main`.
- **Probe:**
  - **What the workspace holds.** At probe time it had one Postgres (`qa-w8m155-pre`, another session's) and one Key Value (`qa-20261110-81b5-kv`). `GET /v1/postgres?ownerId=tea-daif693dqjvc73e7as3g&name=db` returned `[]`.
  - **GraphQL `blueprintPreview(repo:"https://github.com/bex-co/bex", branch:"main", path:<path>, ownerId:"tea-daif693dqjvc73e7as3g") { existingResources matchedResources { kind name } … }`, from the signed-in page:**
    - `examples/stack-demo/render.yaml` → `matchedResources [{kind:"postgres",name:"db"}]`. Its services `web` and `worker` are not matched.
    - `lego/backend/internal/apps/testdata/render-mattermost/render.yaml` → `[{kind:"postgres",name:"mattermost"}]`, and the file is valid.
    - `lego/cli/internal/skills/pack/skills/bex-deploy/assets/python-django.yaml` → `[{kind:"postgres",name:"postgres"},{kind:"key_value",name:"redis"}]`.
    - **Control:** `examples/hello-go/render.yaml` → `[{kind:"service",name:"hello-go"}]`. This one is correct: the workspace has a service `hello-go`.
  - **Dashboard.** `/blueprints/new` → Public Git URL `https://github.com/bex-co/bex`, path `lego/backend/internal/apps/testdata/render-mattermost/render.yaml` shows:
    - "Matches existing resources — This Blueprint matches resources that already exist in your workspace. New resources will be created with the suffix “-72wr” added to each name";
    - "Already in your workspace: mattermost Postgres";
    - the plan "Create mattermost-72wr Postgres · Create mattermost-72wr Service · Create mattermost-minio-72wr Service", with Deploy Blueprint enabled.
  - **The suffix changes per preview** (`-vae3`, `-683m`, `-72wr` across reloads), because each create_new review draws a new one.
- **Root cause:**
  - **The flag is read backwards.** `blueprintMatchedResources` (`lego/backend/internal/apps/blueprint.go:1236-1254`) reads `uniqueDatabaseByDisplayName`'s and `uniqueKeyValueByDisplayName`'s second result as `unique` and matches on `found != nil || !unique` (`:1238`, `:1249`).
  - **What the helper returns.** `uniqueMatching` (`lego/backend/internal/apps/deploy.go:1435-1448`) returns `(nil, false)` for no match, `(item, false)` for one, and `(nil, true)` for duplicates. So the flag means **duplicate**, as every other caller names it (`deploy.go:1355`, `:1402`, `:4136`, `:4209`).
  - **The effect.** No match gives `!false`, which is a match: every declared database and Key Value that doesn't exist is "matched". A real duplicate gives `!true`, which is not a match, against the comment's own "a duplicated one included".
  - **Services are unaffected:** `services[svc.req.Name] != nil` (`:1225-1229`). Env groups use a map lookup (`:1254-1263`).
  - **The dashboard acts on it.** `use-blueprint-preview.ts:94-98` re-reviews as `create_new` whenever `matchedResources` is non-empty, and `blueprints.new.tsx:236-245` then deploys `existingResources: "create_new"` with that suffix.
  - **Introduced by** `b3668c607` (w8/m153, 2026-11-10), which added `matchedResources`. It is in production `7ca0227aa`, and still on `main`.
- **Fix (target behavior):**
  - **A declared database or Key Value is matched only when the workspace has one or more of that kind with that display name.** Rename the variable to `duplicate` and match on `found != nil || duplicate`.
  - **A file whose resources don't exist** previews with `matchedResources: []` and `existingResources: "adopt"`, and the dashboard shows no "Matches existing resources" notice.
  - **REST, GraphQL `blueprintPreview` and the MCP preview tool** (`apps/mcp.go:1041`) share this function, so one change covers all three.
  - **Tests,** beside `blueprint_connection_test.go:370-410`:
    - a new file declaring a database and a Key Value previews with no matches;
    - one existing database is matched;
    - two same-named databases are matched;
    - the service and env-group cases stay as they are.
  - **Also (separate cause, same view):** the "Already in your workspace" list item's accessible name runs name and kind together (`mattermostPostgres`). Two adjacent spans with only `ml-2` between them (`dashboard/src/routes/blueprints.new.tsx:357-361`). Add a real separator, for example `mattermost · Postgres`, or a visually hidden one.
- **Unverified:**
  - Applying such a Blueprint. That would create resources named by the file, not `qa-`, so it wasn't done here. The suffixed names come from the plan the preview showed.
  - Whether a Blueprint **sync** of an existing instance reads `matchedResources`. The function is used only by the preview (`blueprint.go:1160`).
- **Render:** Render's "Matches existing resources" notice (the w8/m153 flow) appears only when the file's resources already exist. A new stack is created under its declared names.
- **Dedupe:**
  - w8/m153 (done) introduced the field and tested only the service case.
  - w8/250 (open) reads `matchedResources` to prefill a Blueprint name. It isn't about the match being wrong.
  - `grep -rl "found != nil || !unique" .pm` finds nothing.
  - **Not deploy lag:** `blueprint.go:1238` and `:1249` are unchanged on `origin/main`.
- **DoD (live):** signed in to `bex-canary`, with no Postgres named `mattermost` and no Key Value named `redis` in the workspace:
  - GraphQL `blueprintPreview` for `render-mattermost/render.yaml` returns `matchedResources: []` and `existingResources: "adopt"`;
  - for `python-django.yaml` it returns `[]` as well;
  - for `examples/hello-go/render.yaml` it still returns the existing `hello-go` service;
  - the dashboard preview of the mattermost file shows no "Matches existing resources" notice, and its plan reads "Create mattermost Postgres" without a suffix.

It now matches on `found != nil || duplicate`; the helpers name their results (`found`, `duplicate`). Test `TestBlueprintMatchesOnlyExistingDatastores` (a new stack, another workspace's or name's datastores, one existing database, two same-named plus a Key Value; fails on the old code).
