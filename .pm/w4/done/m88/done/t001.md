## Objective

Make production dashboard failures visible in k9s/`kubectl logs` by writing JSON error lines for SSR/route failures — without enabling the DEV-only Apollo variable dump.

## Context

- Live pod `dashboard/dashboard-d8f788c5c-dbtbj` (2026-08-19) logged only `Listening on: http://localhost:3000/` even under `/healthz` and `/auth/login` traffic.
- `dashboard/src/common/apollo/factory.server.ts` mounts `loggingLink` only when `import.meta.env.DEV` — keep that; do not log operation variables in prod.
- Log-shipper later parses JSON `level`/`severity` into Render's five buckets — emit `level: "error"` (and optionally `info` for rare bootstrap) so Loki labeling stays honest.

## Steps

1. Add a tiny server-side logger helper that writes one JSON object per line (`level`, `msg`, `path`, `status` when known) to stdout/stderr; never cookies, Authorization, or GraphQL variables.
2. Wire it into SSR error boundaries / server route failure paths (consent, healthz upstream failures that already surface as errors, unhandled route errors) so a real failure produces a line.
3. Keep Apollo DEV logging unchanged; add at most an error-only hook if an SSR GraphQL transport failure would otherwise be silent.

## Files

- `dashboard/src/common/` (new logger helper)
- `dashboard/src/common/apollo/factory.server.ts` (error-only only if needed)
- `dashboard/src/routes/` and/or root error handling as appropriate
- `dashboard/src/**/__tests__/`

## Acceptance criteria

- [x] A forced SSR/route error in a unit/integration test (or local prod-mode smoke) emits a JSON line containing `level`=`error` and a non-secret `path`/`msg`.
- [x] Happy-path `/healthz` and static asset requests do not spam a line per probe.
- [x] Existing DEV Apollo variable logging remains DEV-gated.

## Out of scope

- Full access-log middleware for every request; shipping to Loki (t002); Traefik retention (t003).
