## Objective

Stop dropping Traefik JSON access logs for `dashboard.bex.co` as `not_a_tenant_app`; keep them under host/status labels so edge 4xx/5xx are durable in Loki.

## Context

- `deploy/gitops/base/log-shipper.yaml` Traefik pipeline regex-attributes only `default-<app>-<port>@kubernetes`, then drops empty `app` with reason `not_a_tenant_app` — the file itself names the dashboard as an example of a dropped non-App Ingress.
- Live Traefik already emits JSON access lines for `RequestHost=dashboard.bex.co` (verified 2026-08-19); they just never land in Loki.
- Do not invent a tenant App name for the platform Ingress; attribute by host (and status/method) instead.

## Steps

1. Before the empty-`app` drop, branch (or match) access lines whose `RequestHost` is `dashboard.bex.co` into a platform retention path that labels `host`/`status`/`method` and a non-App `type`.
2. Leave other non-matching edge hosts dropped unless explicitly allowlisted in the same rule with a comment.
3. Verify with a Loki query after a known request that a `dashboard.bex.co` access line is present with the correct status.

## Files

- `deploy/gitops/base/log-shipper.yaml`
- `docs/ADR010-observability.md` (if the request-log split needs a platform-host note)

## Acceptance criteria

- [x] A `dashboard.bex.co` Traefik access line is retained in Loki with host + status labels.
- [x] Tenant App Traefik attribution (`default-<app>-…`) behavior is unchanged.
- [x] Unlisted non-App hosts remain dropped (no accidental cardinality explosion).

## Out of scope

- Retaining every platform host (`api.bex.co`, `oauth.bex.co`, …) unless added to the same explicit allowlist with rationale; changing Traefik itself.
