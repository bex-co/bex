# 497 — The env editor's two file pickers leave a second, focusable "Choose File" control behind their visible button

Why: in the dotenv import dialog and the Secret Files card, the real `<input type="file">` is hidden with `sr-only` only. It stays in the tab order and in the accessibility tree as a separate "Choose File" button right next to the visible "Choose a file" / "Upload files" button. Keyboard and screen-reader users hit two controls for one action, and one of them carries the browser's default, untranslated name.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 76, 2026-11-05 14:40 UTC (`muse.env`, `bex-canary`, pin `c8bbc07cbeeb`); **minor** (accessibility); ~15m.
- **Probe:** owned image web service `qa-20261105-dotenv` (`srv-dbm9a33o6h3c73cauulg`, deleted at 14:44). `/services/<id>/env` → **Edit** → **Add variable → Import from .env**. The dialog's `ariaSnapshot` lists `button "Choose File"` and then `button "Choose a file"`. The `input[type=file]` has `class="sr-only"`, no `aria-hidden`, no `tabindex`, and is 1×1 px and visible. Round 47's snapshot of the Secret Files card showed the same pair: `button "Upload files"`, `button "Choose File"`.
  - The rest of the import behaved correctly. A bad line was refused with an announced `alert: Line 10 isn't a KEY=value assignment.` and the textbox marked `[invalid]`. Valid input parsed like dotenv: `export` stripped, comments and blank lines skipped, quotes removed, `a=b=c` kept, unquoted values trimmed, `"multi\nline"` unescaped. Nothing was saved until **Save**.
- **Root cause:** `dashboard/src/features/services/components/env-import-dialog.tsx:161-170` and `service-environment-editor.tsx:896-906` render the picker `className="sr-only"`. The control case is `features/agent-sessions/components/attachment-chips.tsx:37-44`, which uses `hidden`, so its input is neither focusable nor announced.
- **Fix (target behavior):** each picker exposes exactly one control, the visible translated button. Use `hidden` (as in the attachments picker), or `tabIndex={-1}` plus `aria-hidden="true"`, on both inputs. Keep `inputRef.current?.click()`, which works on hidden inputs. Add a test asserting one button per picker in the accessibility tree.
- **Blast radius:** `grep -rn 'type="file"' dashboard/src` (excluding tests) → 3 sites: these two with `sr-only`, and the attachments picker with `hidden`.
- **Render:** n/a (bex's own control markup).
- **Dedupe:** no `.pm` item mentions the hidden file input or a duplicate "Choose File". No DO_NOT_DO item applies.

Closed 2026-11-05: both native file inputs use `hidden` (as the attachments picker), so each picker exposes only its translated visible button; `env-import-dialog.test.tsx` and `service-environment-editor.test.tsx` assert the input is not visible.
