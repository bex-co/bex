## Objective

Give the binary a bex release identity separate from the pinned upstream version: a `main`-package `bexVersion` var injected from the `bex-cli/vX.Y.Z` tag at build time. `cfg.Version` stays at the pinned upstream release (it is also the User-Agent the server-side compatibility ledger relies on — never repoint it).

## Context

- `scripts/bex-cli-build.sh` currently injects only `-X github.com/render-oss/cli/pkg/cfg.Version=2.22.0`.
- `.github/workflows/cli-release.yml` triggers on `bex-cli/v*` tags; derive `X.Y.Z` from the tag there.
- Local/non-tag builds should show something honest, e.g. `dev`.

## Steps

1. Add `var bexVersion = "dev"` to `cli/main.go`; t001's version line consumes it.
2. Extend `scripts/bex-cli-build.sh` to accept/forward the bex version (second ldflags `-X`).
3. Pass the tag-derived version in `cli-release.yml`.

## Files

- `cli/main.go`
- `scripts/bex-cli-build.sh`
- `.github/workflows/cli-release.yml`

## Acceptance criteria

- [ ] A tag-built binary prints `bex vX.Y.Z (Render CLI v2.22.0 compatible)`; a plain `go build` prints `bex vdev …`.
- [ ] User-Agent behavior unchanged (`cfg.Version` still the pinned upstream release).
- [ ] `scripts/bex-cli-validate.sh` still passes.

## Out of scope

- Changing the pin or upstream version semantics.
