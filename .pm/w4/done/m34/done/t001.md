## Objective

Handle `-v`/`--version` in the bex launcher before `cmd.Execute()` so the upstream `printVersionWithUpdateCheck` (which queries `render-oss/cli` releases and points users at render.com upgrade docs) never runs. Print bex's own identity: `bex v<bexVersion> (Render CLI v2.22.0 compatible)`.

## Context

- Upstream `cmd/root.go` resolves the version request early via `isRootVersionRequest(os.Args[1:], rootCmd.PersistentFlags())` — only `-v`/`--version` **before the first subcommand token** counts, and values consumed by global flags (e.g. `-o text`) are skipped. Mirror those semantics or upstream behavior diverges for e.g. `bex services -v`.
- `cfg.RepoURL` is a **const** (`https://api.github.com/repos/render-oss/cli`) — not overridable via ldflags; interception is the only bex-side fix for this call site.
- `bexVersion` is a placeholder (`dev`) until t002 injects it.

## Steps

1. Add a small version-request detector to `cli/main.go` (or a bridge helper) matching upstream's pre-subcommand semantics.
2. When detected: print the bex version line and return before `cmd.Execute()`; the t003 update notice hooks in here later.
3. Keep every other invocation byte-identical (upstream Execute path untouched).

## Files

- `cli/main.go`
- `cli/internal/bridge/` (if the detector lands there)

## Acceptance criteria

- [ ] `bex -v` / `bex --version` print the bex identity line and make no request to `api.github.com/repos/render-oss/cli`.
- [ ] `bex services -v` (flag after subcommand) still reaches the upstream command unchanged.
- [ ] `bex -o text --version` is detected (global-flag value skipping works).

## Out of scope
