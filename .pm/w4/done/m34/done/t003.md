## Objective

A passive, non-blocking update notice modeled on the gh CLI: compare `bexVersion` against this repo's latest `bex-cli/v*` GitHub release and print a one-line stderr hint with the release URL when newer. Never self-update, never block, never nag.

## Context

- The repo is a monorepo — `/releases/latest` is unreliable; list releases and filter by the `bex-cli/v` tag prefix.
- Gating (all required): at most one check per 24h (cache under `~/.bex/cache/`), stderr is a TTY, `CI` env unset, `BEX_NO_UPDATE_NOTIFIER` unset, `bexVersion != "dev"`. Any check failure is silent.
- Show the notice on the t001 version path and (gh-style) after normal command completion; keep the check itself async/cached so no command waits on the network.

## Steps

1. Implement the cached release check (list + filter + semver compare) in `cli/internal/` with an injected HTTP layer for tests.
2. Wire it into `cli/main.go` behind the gating conditions.
3. Document `BEX_NO_UPDATE_NOTIFIER` in `docs/bex-cli.md`'s configuration table.

## Files

- `cli/internal/` (new package or bridge)
- `cli/main.go`
- `docs/bex-cli.md`

## Acceptance criteria

- [ ] Newer release + TTY + no CI ⇒ one stderr line with version and release URL; second run within 24h makes no network call (cache hit).
- [ ] `CI=1`, `BEX_NO_UPDATE_NOTIFIER=1`, non-TTY stderr, or `bexVersion=dev` ⇒ silent, no network call.
- [ ] Network/API failure ⇒ silent, exit code of the underlying command unchanged.

## Out of scope

- `bex upgrade` self-update (inbox note w4/030).
