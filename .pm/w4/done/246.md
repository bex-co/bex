# Static-site build confirmation describes replacing instances

Why: customers approving a static build should receive an accurate description of how their published site changes.

**Severity:** minor. **Estimate:** 45m. Source: user-requested continuous functional `qa-find-bugs`, w4, pass a134, 2026-10-10 local / 2026-10-11 UTC; QA login helper used muse.env privately. ADR008 understandable hosting, ADR029 static publication, ADR004 deploy outcomes and ADR018 parity. Filing only.

## Reproduce and target behavior

Create a static site from public repo `https://github.com/bex-co/bex`, branch main, root `examples/static-site`, publish directory `dist`, auto-deploy off. Build Command:

```sh
mkdir -p dist; cp index.html dist/index.html; printf 'qa-a134-version-1\n' > dist/marker.txt
```

Wait for Live and external HTTP 200. This pass's owned fixture was `qa-20261010-a134-static-cancel`, `srv-db5era19siac73f4sal0`; recreate it because it is deleted.

1. Hard-load `/static/<id>/settings`, select **Edit build command**, and replace version-1 with version-2 in the command. Select **Save changes** to open the confirmation.
2. At desktop 1440×1000, the body reads: “Service will redeploy with the new build command. Existing requests will be drained before old instances are replaced.”
3. Cancel, hard-load at 390×844, and repeat. The same body appears. Settled mobile confirmation has opacity 1, x16, y245, width358, height354; both actions are reachable. This is a copy defect, not the already-fixed long-command layout issue.
4. Repeat with the preview-only command below after the version-2 deploy is Live; Cancel dismisses it. The saved/deployed version-2 history remains at three deploys.

**Target:** select static-specific English and Chinese copy from the existing typed static-site discriminator. For example: “This starts a rebuild with the new command. Your site keeps serving its current published version until the new publication succeeds.” Preserve the existing native-service confirmation and all mutation/confirmation behavior. Do not introduce request draining or served-instance replacement to make the old text true.

Durable fresh-page modal text at both sizes:

```text
Change build command to mkdir -p dist; cp index.html dist/index.html; printf 'qa-a134-version-2\n' > dist/marker.txt; echo qa-a134-preview-only?

Service will redeploy with the new build command. Existing requests will be drained before old instances are replaced.

Cancel
Save changes
```

## Passing deployment controls

Version 1 reached Live at 02:02:15Z and `GET /marker.txt` returned HTTP 200 / `qa-a134-version-1\n`. A saved version-2 command printed its build-begin marker and slept 120s. While it built, the public URL still served version 1. **Cancel deploy → Proceed** returned canceled at 02:04:07Z; a fresh read retained canceled, service Running/rev-1, and the public marker remained version 1. The version-2 command stayed saved.

Changing the command to the fast version-2 command below was accepted, its config-change deploy `dep-db5etql6p5vc738lfml0` reached Live at 02:06:45Z/rev-3, and public GET plus external curl HEAD returned 200 with the new marker. Fresh Events showed the canceled build/deploy and subsequent Succeeded build/Live deploy. The serving and cancellation behavior worked.

Static `undeployedChanges:false` after cancellation was investigated and **not filed**: `lego/operator/internal/controller/saved_configuration.go:81–86` deliberately excludes static publications because they do not retain build-input configuration records. This note requests no change to that scope.

## Root cause and bounded fix

- `dashboard/src/features/services/components/build-deploy-section.tsx:229–250` supplies the same `services.buildCommandConfirmBody` for every shown Build Command editor. English `features/services/locales/en.ts:2205–2208` contains the observed instance/drain statement; Chinese `zh.ts:2157–2160` has the corresponding instance-replacement claim.
- `routes/services.$serviceId.settings.tsx:90` already computes `staticSite = isStaticSite(service)`, but its BuildDeploySection mount at `:200–228` does not pass that discriminator. Build Command visibility is `!cron && !isDockerBuild(service)`, which includes static and native compute services; visibility alone cannot select static copy.
- Consumer chain: `components/editable-field-row.tsx:306–311` forwards `confirm.body` as description; `common/components/confirm-dialog.tsx:132` renders it in AlertDialogDescription. The prop is a ReactNode (`:51`), so a translated conditional string is expressible without schema/API changes.
- Actual installed Radix Alert Dialog **1.1.15** `dist/index.mjs:97–102` forwards description props to Dialog.Description; installed Dialog **1.1.15** `dist/index.mjs:252–257` renders them into its paragraph. It does not invent the wording or infer the service type. This is application copy selection.
- ADR029 `:3,18–20` defines built output in revision-prefixed object storage and one shared static-server; serving content has no per-site Deployment/Service. Atomic prefix cutover is the applicable explanation. The observed version-1 → canceled build → successful version-2 responses support that explanation.
- Pass the existing static flag into BuildDeploySection and add a static-only body in en/zh. Keep the current body for native web/private/worker and leave the shared ConfirmDialog/EditableFieldRow primitives alone.

**Dedicated blast-radius work:** exhaustive production search found **one** rendering use of this translation key, **one** BuildDeploySection JSX mount, and two concrete Settings route entries sharing ServiceSettingsPage. Enumerate static native/direct-publish cases, native web/private/worker controls, hidden cron and Docker build rows, and Existing Image services that have no Build section. Postgres and Key Value have separate pages and do not mount it. `routes/static.$serviceId.settings.tsx:2,28` shares the page; a typed static resource opened through `/services/<id>/settings` reaches the static route. Legacy web/pserv/worker/cron aliases redirect to services (`common/lib/render-alias.ts:13–20`); their applicable native editor keeps its existing body. Do not change unrelated root-dir, start/Docker command, rollback or cancel confirmations.

**Pre-settle / adjacent outcomes:** the parent mounts the Build section only when service/repo data exists; keep its skeleton/capability gates. Cancel sends no save; confirmation still saves the exact command once. Refused, failed or timed-out saves retain current draft/error behavior. Build/publish failures and cancellation retain their existing serving outcome. No REST/GraphQL/MCP shape, permission policy, deploy taxonomy or runtime changes are required.

**Unverified:** live Chinese; live native web/private/worker confirmation siblings; direct-publish static and Docker-hidden controls; legacy aliases; injected save/refetch errors. Those are verification work, not additional observed failures.
