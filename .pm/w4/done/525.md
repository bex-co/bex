# 525 — The `/agents` repository/session picker stays open when keyboard focus leaves the Task box, so Tab lands on controls hidden under it and Escape no longer closes it

Why: a keyboard user who opens "Add repository or session" and then tabs on to the Agent selector or Attach files cannot see those controls (the open list covers them) and cannot dismiss the list with Escape, so the form is unusable by keyboard until they find their way back into the Task box.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 115, 2026-11-05 UTC (`muse.env`, `bex-canary`); **minor** (accessibility, keyboard); ~30m.
- **Probe:** read-only, signed in, `/agents` (1280×800 window), nothing selected or submitted. Keyboard sequence with the open state of `[role=listbox]` and `document.activeElement` after each step:

  | Step | Listbox open | Focus |
  | --- | --- | --- |
  | `Enter` on **Add repository or session** | yes | `combobox:Task` (stays in the editor) |
  | `Escape` | no | `combobox:Task` |
  | reopen, `ArrowDown` | yes | `combobox:Task` |
  | `Tab` | **yes** | `combobox:Agent` |
  | `Escape` | **yes (not closed)** | `combobox:Agent` |
  | `Tab` | **yes** | `button:Attach files` |
  | `Shift+Tab` ×2 | yes | `combobox:Task` |
  | `Escape` | no | `combobox:Task` |

  - Geometry with focus on **Attach files**: the listbox box is left 462 / right 844 / top 108 / bottom 364 and the focused button is left 579 / right 611 / top 185 / bottom 217, so the button lies inside the list. `document.elementFromPoint` at the button's centre returns an element inside the `listbox`, not the button. The focused control is covered by the open list.
  - A mouse click on the empty page does dismiss the list, so only keyboard users are stuck with it.
  - The picker's accessibility tree is sound otherwise: `listbox "Add repository or session"` with `option`s for the two categories, the repositories and the earlier sessions; focus stays in the editor as in an ARIA combobox.
- **Root cause:** the picker is the TipTap `@` suggestion popup. `dashboard/src/features/agent-sessions/components/inline-mention-editor.tsx:179-195` mounts it in `onStart`, routes keys to it from `onKeyDown` (`:187`; the key events reach it from the editor, so they stop once focus is elsewhere, as the Escape row above shows) and unmounts it only in `onExit`. The editor and its adapter register no blur handling (`grep -n "blur\|onBlur" inline-mention-editor.tsx lazy-mention-editor.tsx` → none), so leaving the editor does not end the suggestion and nothing else listens for Escape. The popup (`components/mention-picker.tsx:93-103`) is rendered over the toolbar row.
- **Fix (target behavior):** the list closes as soon as keyboard focus leaves the Task editor, and Escape closes it wherever focus is.
  - End the suggestion on editor blur (for example from the editor's `onBlur`, unless focus moves into the picker itself) so `onExit` runs, or add a `focusout` and `Escape` listener while it is open.
  - Keep the current mouse behavior (outside click closes) and the "focus stays in the editor while open" pattern.
  - Tabbing from the editor then moves to the Agent selector with the list gone, so the focused control is visible.
- **Tests:** a composer test: open the picker with the button, press `Tab`, assert `queryByRole("listbox")` is gone and the next control has focus; open again, move focus out by script, press `Escape`, assert closed; the existing open-and-select tests stay as the controls.
- **Blast radius:** one popup (`MentionPicker`) mounted by the new-session composer, and by the session page's steering composer if it uses the same `InlineMentionEditor` (not checked). `@`-typed mentions go through the same suggestion and get the same fix.
- **Adjacent classes:** the same shape (an editor-owned popup that outlives focus) was not looked for in other editors.
- **Unverified:** the steering composer on a session page (no session exists in the workspace to open); behavior on touch devices; narrow widths, where the list may not overlap the toolbar; a screen reader's reading of the open list.
- **Render:** n/a (the reference for the agent surface is Devin; its picker was not compared).
- **Dedupe:** `grep -rli "mention picker\|Add repository or session" .pm` finds no dashboard-accessibility item on it (hits are unrelated). w4/524 (open, same page) covers the Spend limit message and is a separate cause. No DO_NOT_DO item applies.

- **Closed 2026-11-06 (loopx w4):** while the `@` suggestion is open, `inline-mention-editor.tsx` listens on the document. Focus that lands outside the editor and the picker, or Escape pressed outside them, ends it through `exitSuggestion(view, mentionPluginKey)`, so `onExit` unmounts the list. The listeners are removed in `onExit`. Mouse selection is unchanged, since an option click moves no focus, as is "focus stays in the editor". The new composer test covers Tab out, Escape with focus elsewhere and a mouse pick afterwards; it fails on the old code. The steering composer shares `InlineMentionEditor`, so it gets the same fix.
