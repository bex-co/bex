## Objective

When a dashboard environment move would leave a service linked to a group scoped elsewhere, show a confirmation before writing. It names each such group with its Project / Environment and says its values keep applying until unlinked or moved. Cancel writes nothing; confirm performs today's single write.

## Context

- Live repro and probes: [finding.md](finding.md) steps 3–6.
- Writers: inline Move `dashboard/src/features/environments/components/environment-card.tsx:254` (`{ kind: "service", current: target.serviceIds, set: setServices }`) and Manage resources Save `dashboard/src/features/environments/components/manage-resources-dialog.tsx:261`. Both reach `use-set-environment-services.ts`, which calls GraphQL `setEnvironmentServices`.
- Data already on the client: `useEnvGroups()` (each group's `environmentId` + `serviceLinks`) and `useEnvGroupScopeIndex()` (services → environment). Use `serviceMatchesGroupScope` from `dashboard/src/features/env-groups/lib/scope.ts` against the **target** environment, so exact equality includes workspace/null.
- Scope-index pending or failed: do not move silently past an unknown. Show the existing error and retry, or wait for readiness, rather than skipping the check.
- Removing a service from an environment (Manage resources uncheck) also strands its links; treat the target as "no environment".

## Steps

1. Derive the set of linked groups whose scope would not match the destination for every selected service.
2. When non-empty, open a confirmation dialog listing them; Cancel aborts with no mutation; Confirm calls the existing writer once.
3. Verify both entrypoints live on owned fixtures (inline Move and Manage resources Save, including an uncheck-to-remove case) at 1440 and 390.
