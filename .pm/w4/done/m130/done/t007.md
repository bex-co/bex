## Objective

Pin both directions of the contract, with tests that fail before the fix.

## Context

- The defect is intermittent (~4 in 8 live), so a test that runs the loop once can pass on a broken build. Either drive the race deterministically or iterate enough that the observed rate would almost certainly show.
- The invariant to assert verbatim is already written in the code (`batch.go:177-180`): two submissions from one observed revision resolve to exactly one success and one conflict.
- The env-group path is the reference implementation and should get a parallel test, so the two cannot drift apart again.

## Steps

1. Test: a successful CAS patch returns no error, lands the value, advances the revision, and returns the new revision (t003).
2. Test: a stale-revision patch returns the conflict **and** leaves value and revision unchanged — assert the state, not just the error.
3. Test the concurrency invariant directly: two writers from one revision, exactly one success, and the loser's value provably absent.
4. Test the no-op CAS write: revision advances, no App write, no roll, no event.
5. Verify each assertion fails without the fix; record which fire.
6. Add the parallel env-group assertions so the sibling stays the reference.
