# The push panel offers "Agent needs a decision", which nothing sends

Why: a member can select an event that no producer emits, so the selection is inert. That is the same broken promise `w4/m231` fixed for urgency, but no notice can explain this one.

- **Source:** `w4/m231` t003 adjacent-class audit, 2026-10-19 (loopx w4).
- **Finding:** `agent_needs_decision` is a selectable push event in the dashboard (`dashboard/src/features/notifications/lib/push-policy.ts`, `pushEvents`), in the backend vocabulary (`lego/backend/internal/notifications/service.go`, `orderedDeliveryEvents`) and in GraphQL (`AGENT_NEEDS_DECISION`). No projection emits it: `projectAgentSessionPush` and `projectPushEvent` (`push_worker.go`) produce every other selectable event, and `TestProjectedPushUrgencyIsPublished` pins that `agent_needs_decision` is the only one without a producer. It is reserved for ADR048's needs-decision steering (`docs/ADR048-mobile.md`, w11/m7–m8), which has not shipped.
- **Decision needed:** either hide the event from the panel until a producer ships (keeping saved selections intact and the backend vocabulary unchanged), or keep it and mark it "Not sent yet" next to the urgency label. Either way, a saved selection must not be silently rewritten.
- **Estimate:** 30m once the choice is made (panel and locales, one test).

**Done 2026-10-19 (loopx w4):** I took the reversible default, label rather than hide, because it rewrites no saved selection and matches the per-event "Not pushed" label w4/m231 established. Hiding remains a one-line change if preferred.
- **Backend.** bex-api publishes `sent` on every `pushEventUrgencies` row (REST and GraphQL), false for `notifications.unsentPushEvents` (`agent_needs_decision`).
- **Panel.** The push panel labels such an event "Not sent yet: nothing sends this event today." (en and zh), at workspace and service-override level, and saves a selection of it unchanged. Such an event is never also flagged as dropped by the minimum urgency, since the minimum is not what stops it. The checkbox is named by event and urgency, with the note as its description.
- **Tests.** `TestProjectedPushUrgencyIsPublished` now pins `sent` to the projections; the parity test covers `sent` on both surfaces; a panel test covers the label and the saved selection.
- **Docs.** ADR052.
