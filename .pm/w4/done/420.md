# 420 — Registry credentials refuse Render's required `registry` field and never return it, so Render-shaped clients cannot create or parse one

Why: Render's `POST /registrycredentials` **requires** `registry` (`GITHUB|GITLAB|DOCKER|GOOGLE_ARTIFACT|AWS_ECR`) and its `registryCredential` read object requires it too. bex refuses the field and returns `host` instead. Any Render-shaped automation (an OpenAPI-generated client, a Terraform provider, an agent following Render's docs) therefore cannot create a credential, and a strict client cannot parse one bex created. Private-image services need these credentials to pull.

**Severity:** major (Render parity — the whole REST credential surface is unusable to a Render client; GraphQL and the dashboard work). **Estimate:** ~1h. **Source:** live `/qa-find-bugs w4` loop run dfe7, 2026-10-26/27 UTC (`muse.env`, `bex-canary`, pin `b4726243e74f`), REST through the run's session jar. The one owned credential, `rgc-dbg0fdsd3d3c73caq970`, was deleted (`GET` → 404).

## Probes

- `POST https://api.bex.co/v1/registrycredentials {"ownerId":"tea-daif693dqjvc73e7as3g","name":"qa-dfe7-dh","registry":"DOCKER","username":"qauser","authToken":"not-a-real-token"}` (Render's body exactly) → `400 {"error":"bad request: request body contains unknown field \"registry\""}`. The same for `"registry":"GITHUB"`.
- `POST … {"ownerId":…,"name":"qa-dfe7-cred","host":"ghcr.io","username":"qauser","authToken":"…"}` (bex's dialect) → `201 rgc-dbg0fdsd3d3c73caq970`.
- `GET /v1/registrycredentials/rgc-dbg0fdsd3d3c73caq970` → `{"id","name","host":"ghcr.io","username","ownerId","status","createdAt","updatedAt"}`: **no `registry`**. Render's pinned schema (`lego/backend/internal/api/openapi/render-public-api-1.json`, `registryCredential`) requires `["id","name","username","registry","updatedAt"]`.

## Root cause and history

- `lego/backend/internal/registrycreds/rest.go:29-40` documents a 2026-07-13 decision to "deliberately generalize" Render's `registry` enum to an arbitrary `host`, because the pull-secret mechanism is provider-agnostic. `createCredentialRequest` (`:74-82`) has no `registry` field, and the strict decoder refuses it (`:158-165`).
- w8/135 (done) fixed the contract so bex's dialect validates and `registry` is refused **by name**. w5/163 refuses the list filter `type` (the same enum) by name. ADR018's registry-credentials row records "Render's registry enum that bex replaces with a host", with no user sign-off.
- `AGENTS.md`: Render parity is the top principle, and a divergence stands only with sign-off recorded in ADR018. Accepting the enum costs nothing: it is a strict superset of `host`.

## Fix (target behavior)

- **Create:** accept Render's `registry` and map it to a host: `DOCKER` → `docker.io`, `GITHUB` → `ghcr.io`, `GITLAB` → `registry.gitlab.com`. `GOOGLE_ARTIFACT` and `AWS_ECR` have per-project/per-region hosts, so they are accepted with an explicit `host` (bex extension) or refused by name naming the missing `host`. `host` alone keeps working. Both present must agree, or the request is refused by name.
- **Read** (REST get/list, and the create/update responses): emit Render's `registry` alongside `host`, derived from the host (`docker.io`/`index.docker.io`/`registry-1.docker.io` → `DOCKER`, `ghcr.io` → `GITHUB`, `registry.gitlab.com` → `GITLAB`, `*-docker.pkg.dev`/`gcr.io` → `GOOGLE_ARTIFACT`, `*.dkr.ecr.*.amazonaws.com` → `AWS_ECR`). A self-hosted host has no Render value: decide and record whether to omit it or use a documented fallback.
- **List filter:** accept `type` with the same mapping instead of refusing it (w5/163).
- **PATCH:** Render's update body (`registry`, `name`, `username`, `authToken`) is accepted with the same mapping.
- GraphQL and MCP keep their `host` argument and may add `registry` for symmetry. Amend the ADR018 row and the `rest.go` header comment.

## Tests

- Conformance: Render's exact create body → 201 with `registry` echoed.
- Each mapped enum value round-trips (create → get → list `type=`).
- `GOOGLE_ARTIFACT` without `host` → named 400; mismatched `registry`/`host` → named 400.
- Bex-dialect controls are unchanged.
- The read response validates against the pinned `registryCredential` schema.

**Unverified:** which Render clients in practice send `registry` (the pinned Render CLI's command set was not checked); how the operator's pull path treats `docker.io` vs `index.docker.io` hosts. **Dedupe:** w8/135 and w5/163 (both done) chose the host-only dialect; this reopens that choice on parity grounds rather than duplicating a bug. No `DO_NOT_DO.md` conflict.

**Done 2026-10-26 (loopx w4).** New `registrycreds/registry.go` maps Render's enum to and from hosts. REST create accepts Render's exact body (`DOCKER`/`GITHUB`/`GITLAB` → fixed hosts; `GOOGLE_ARTIFACT`/`AWS_ECR` require `host`, named 400 otherwise) or `host` alone; a disagreeing pair is a named 400. Every REST read emits `registry`, derived from the host. **Decision:** a self-hosted host (no Render value) omits `registry` rather than inventing one. The list `type=` filter now filters on the derived enum (unknown value → named 400). PATCH accepts Render's `registry` when it matches the stored host, else a named 400 (a credential's host never changes). GraphQL and MCP keep `host` only; adding `registry` there was optional and is not done.
