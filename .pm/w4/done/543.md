# 543 — A new blank environment-variable row is announced as an error before anything is typed

Why: clicking Add variable shouldn't say you've already done something wrong. A screen reader announces the error alert the moment the row appears. w6/057 already fixed the same behavior for secret file names.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 15, 2026-11-10 11:15–11:45 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor** (UX and accessibility; nothing is lost). ~20m.
- **Fixtures:**
  - service `qa-20261110-envapp` (`srv-dbpfrlc5ngvc73e8tmg0`, `examples/hello-go`)
  - env group `qa-20261110-eg` (`evg-dbpfrfk5ngvc73e8tmeg`)
  - Both are deleted; GET returns 404 and the service URL returns 404.
- **Probe** (reproduced on fresh loads of both pages):
  - On `/services/srv-dbpfrlc5ngvc73e8tmg0/env`, choose Edit, then Add variable ▸ Add variable. Before anything is typed, the accessibility tree lists:
    - `textbox "Key" [invalid]`
    - `alert: Use up to 253 letters, digits, dots, dashes and underscores; not '.' or starting with '..'.`
  - `/env-groups/evg-dbpfrfk5ngvc73e8tmeg` → Edit → Add variable shows the same.
- **Root cause:** the shared editor's `EnvDraftItem` (`dashboard/src/features/services/components/service-environment-editor.tsx:1291`) renders the error unconditionally:
  - `aria-invalid={Boolean(error)}` at `:1347`, and the `role="alert"` paragraph at `:1351-1361`.
  - The error comes from `validateEnvironmentDraft` (`features/services/lib/environment-draft.ts:259-277`). Its `validateRows` (`:197-222`) marks an empty key `invalid`.
  - Two blank rows would both read `duplicate`.
- **Precedent:** [w6/057](../w6/done/057.md) (done) fixed exactly this for secret file names only.
  - `FileDraftItem` keeps a `touched` flag and sets `showError = Boolean(error) && (touched || row.name !== "")` (`:1421-1435`). A new row shows neutral hint text instead.
  - The test "shows the file-name rule as neutral help until the field is touched (w6/057)" pins it (`features/services/components/__tests__/service-environment-editor.test.tsx:832`).
- **Fix:** give `EnvDraftItem` the same behavior as `FileDraftItem`.
  - Until the key is typed in or blurred: no alert, `aria-invalid` false, and the key rule shown as neutral hint text.
  - After that, the real message.
  - Save and deploy stays disabled while the draft is invalid.
  - Add a test matching the w6/057 one.
- **Blast radius:** `EnvDraftItem` has one caller (the editor, `:818`). The editor is reached from `routes/services.$serviceId.env.tsx` and `features/env-groups/components/env-group-editors.tsx:3,30`, so both surfaces change together.
- **Dedupe:**
  - w6/057 covered only file names.
  - `grep -rlE "envInvalidKey|pristine|untouched row" .pm` finds nothing open.
  - `git log c12cd57facb1..origin/main` on the editor is empty, so this is not deploy lag.
- **DoD (live):** on both pages:
  - Add variable inserts a row with no alert and `aria-invalid="false"`.
  - Typing `bad key` then shows the alert.
  - Save and deploy stays disabled while a blank row is present.

- **2026-11-11 (loopx w4):** fixed: `EnvDraftItem` gives a new blank key a touched gate (as w6/057 did for secret files): the key rule is neutral help with no alert and `aria-invalid="false"` until the key is typed or left. A saved key that is cleared alerts at once, and two blank keys read as blank, not duplicate. Save and deploy stays disabled while a blank row is present. Editor tests cover all three.
