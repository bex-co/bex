## Objective

`deployActions` reports `precondition: "protected_confirmation_required"` for `rollback` (and for an override deploy, if the projection gains that action) on protected members. The dashboard Rollback and override-deploy dialogs ask for the `sudo repoint service <name>` phrase up front, as the delete/suspend dialogs do.

## Context

- `lego/backend/internal/deploys/actioncaps.go:106-133`; dashboard `features/capabilities/lib/resource-actions.ts` already knows `protected_confirmation_required`; `use-bound-action-confirm.ts` binds phrases.

## Acceptance criteria

- [x] On a protected member the Rollback dialog shows the phrase field and the request carries `confirm`; on an unprotected one nothing changes.

Done 2026-10-05: `deployPreconditions` reports `rollback: protected_confirmation_required` once a target exists, and `deploy` stays ready. The dashboard follows ADR032's no-precomputed-phrase rule: Rollback (`deploy-actions.tsx`) and "Deploy a specific commit" (`use-trigger-deploy.ts`) use `withProtectedRetry` and the shared retry dialog. Dismissing it is quiet. The GraphQL documents carry `$confirm`, and codegen was regenerated from the schema dump.
