## Root cause and proposed fix

`dashboard/src/common/components/dashboard-layout/dashboard-breadcrumbs.tsx:452–468` receives an already translated label, but `:463` renders an unlabeled Link and `:465` puts the label in `hidden truncate sm:inline`. At the exercised narrow width neither that hidden text nor the decorative icon supplies the link name.

Opened the actual installed dependency paths: **lucide-react 0.562.0**, `dist/cjs/lucide-react.js:44–73`, marks this childless unlabeled SVG aria-hidden; **@radix-ui/react-slot 1.3.0**, `dist/index.js:90–94,116–140`, merges and forwards child/slot props; **@tanstack/react-router 1.170.25**, `dist/esm/link.js:69–73,340–361,435–443`, forwards ordinary anchor props and creates the anchor. The local Button at `common/components/ui/button.tsx:65–80` uses Slot for asChild. None invents a label. Hidden content is excluded from ordinary name computation, while an explicit aria-label supplies the name. [W3C Accessible Name Computation1.1, steps2A/2C](https://www.w3.org/TR/accname-1.1/#step2A).

Set **`aria-label={label}` on the Link inside BreadcrumbLink**. Reuse the existing translated label; keep the icon decorative. Avoid changing all Button or SVG components.

**Blast radius:** exhaustive production-source search finds **two BreadcrumbLink mounts**, at `:110` (ungrouped service's Projects prefix) and `:312` (group's Environment Groups prefix), and **one DashboardBreadcrumbs mount**, `dashboard-header.tsx:36`. The service prefix is entirely wrapped in `hidden sm:contents`, so it is deliberately absent on narrow screens; preserve that visibility and its desktop Projects name. Web/static/cron/worker/private use that service branch. Project/environment switcher buttons, datastore static type text and generic PageBreadcrumb are separate renderers and do not need new labels from this fix.

**Pending and adjacent states:** the collection label comes from translations even before group/scope reads settle. Preserve the neutral group-name placeholder and existing route failure/deletion handling. No additional query or backend field is needed.
