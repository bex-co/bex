## Objective

A completed logical CRI record retains the first partial chunk's timestamp, while message assembly and bounds remain unchanged.

## Context

[finding.md](finding.md) verifies Alloy v1.11.2 from locked chart 1.3.1 and executes its production App pipeline. In upstream extensions.go:134–142 and 150–159, both merges keep the current entry's stamp. No supported first-timestamp config option exists. Current upstream main was inspected too; a blind version bump is insufficient.

## Steps

1. Run the exact pinned-image P/F replay from the finding and save the wrong final-stamped output.
2. Retain the buffered first timestamp on both repeated-P and completing-F merges. Preserve extracted time ownership if a subsequent timestamp stage requires it. A single F keeps its own stamp. Keep message concatenation, stream fingerprints, count/size bounds and overflow behavior.
3. Select an upstream artifact only after the replay proves that behavior. If unavailable, add a small reproducible build from the locked upstream source with only this correction under deploy/log-shipper/, recording source, patch and resulting image digest. Wire the artifact into the existing ordinary image build/publish workflow.
4. Pin the verified collector image in the existing Helm values, retain the chart's reviewed identity, and document the first-chunk rule in ADR010. No production rollout occurs until the artifact and replay are reviewable.
