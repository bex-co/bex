# 613 — A background worker's Metrics and Logs offer HTTP request views it can never have: a Network Metrics card with Total Requests and Response Times, and a "Request logs" type with request filters, each reading "No data in range" or "No logs match these filters"

**Absorbed 2026-11-13 into [w10/m374 t002](../../w10/blocked/m374/done/t002.md)** (`/pmx them all to w10`, from `/pm-brainstorm for w10`). **Not fixed yet:** the fix and its live DoD ship with that milestone; this note keeps the original evidence.

Why: a worker, cron job or private service gets no public HTTP traffic, so these views can only ever be empty. Their empty states read as "nothing happened in this range" or "your filters are too narrow", not "this service type has no requests". Render shows HTTP metrics and request logs for web services only.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 227, 2026-11-12 20:04–20:20 UTC (`muse.env`, workspace `bex-canary`; pin `33e1b1e6117c`). **Minor** (dishonest empty views; no data is wrong). ~45m.

  - Created from New → New Service → Background Worker → Existing Image: `docker.io/library/busybox:1.36`, a Docker Command that logs `qa227 tick N mode=$QA_MODE` every 3 s (stderr `qa227 warn N` every fifth), env `QA_MODE=r227`.

- **Render:**
  - [Service metrics](https://render.com/docs/service-metrics): HTTP request volume and response latency are "Web services only"; CPU and memory are "All services except static sites"; outbound bandwidth is "All service types".
  - [Logging](https://render.com/docs/logging): "Render generates a log entry for each HTTP request to your team's web services from the public internet", and "does _not_ generate request logs for HTTP requests sent from other services over your private network".
- **Root cause:** both pages are type-blind for HTTP.
  - `dashboard/src/routes/services.$serviceId.metrics.tsx:102-111` already reads the service's type to drop the Application card for a static site. It still mounts `NetworkMetricsCard` for every type (`:148-152`). The card queries `http_requests` and `http_latency` and polls status-code discovery (`dashboard/src/features/metrics/components/network-metrics-card.tsx:116-146`, plus host discovery at `:126`) on every service.
  - `ServiceLogsPage` passes only `resource` to `LogViewer` (`dashboard/src/routes/services.$serviceId.logs.tsx:118-125`).
  - `LogFilterBar` always lists `LOG_TYPE_FILTERS` (`dashboard/src/features/logs/types.ts:66-70`, rendered at `log-filter-bar.tsx:186-192`) and every structured filter, including method, statusCode, path and host (`types.ts:104`, popover `log-filter-bar.tsx:230-277`).
  - The request series and request lines come only from the edge (Traefik), which routes only publicly routable types. `publiclyRoutable` (`dashboard/src/features/services/lib/service-type.ts:136-142`, mirroring `AppSpec.PubliclyRoutable`) is false for `private_service`, `background_worker` and `cron_job`.
- **Fix (target behavior):** request views appear only where request data can exist, `publiclyRoutable(type)`.
  - **Metrics.** For a worker, cron job or private service, the Network card shows only Outbound Bandwidth (Render: all types), without Status Code, Host, Path, Total Requests, Response Times or their queries.
    - Split the card, or pass a `requests={publiclyRoutable(service.type)}` prop.
    - Pre-settle: the route already loads the service for the Application card. Hold the request sections until the type is known, so a worker never flashes them.
  - **Logs.** Pass the same flag through `ServiceLogsPage` → `LogViewer` → `LogFilterBar`. Without it:
    - drop the Request logs type and the method, status code, path and host filters, and keep level and instance;
    - a `?type=request` URL, or a stale method, status, path or host search param, reads as All logs with those filters cleared.
    - The route's `NonStaticRoute` already holds the viewer until the type loads.
  - API and MCP are unchanged: `type=request` and HTTP metrics for these types answer empty, which is honest for a programmatic read.
- **Tests:**
  - metrics route: a `background_worker`, `cron_job` and `private_service` render Outbound Bandwidth without the request sections and issue no `http_requests` or `http_latency` query; a `web_service` keeps all of them.
  - `log-filter-bar`: with `requests=false`, the type options are All and Application and the popover has Level and Instance; `?type=request` normalizes to all.
