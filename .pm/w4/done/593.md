# 593 — Saving a cron job's Command says "The operator will apply the new schedule on its next reconcile pass", while the schedule is unchanged and a deploy starts at once

Why: the toast is what a user reads after the save. It names bex internals ("the operator", "reconcile pass"), talks about a schedule they didn't touch, and hides that the save started a `service_updated` deploy.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 154, 2026-11-12 01:12–01:21 UTC (`muse.env`, workspace `bex-canary`; pin `8330744bd643`). **Minor** (copy). ~20m.
- **Fixture:** Starter cron job `qa-20261112-r154-cron` (`srv-dbqh3hiv3e1c73bps640`, image `docker.io/library/busybox:1.37.0`), deleted afterwards. The same fixture as w4/592.
- **Probe:**
  1. Settings → Deploy → **Edit command** → `sh -c 'echo qa154-start; sleep 90; echo qa154-end'` → **Save changes** (~01:12:30).
     - The toast reads `Cron job settings saved. The operator will apply the new schedule on its next reconcile pass.`
     - `GET /v1/services/srv-dbqh3hiv3e1c73bps640/deploys?limit=5` then lists `dep-dbqh4vqv3e1c73bps680`, `trigger: "service_updated"`, created 01:12:31.56Z and live by 01:12:48Z.
     - Events show `Deploy started` and `Deploy ended Live`.
  2. A second Command save at 01:15:11 gave the same toast and `dep-dbqh67tjiris73e60spg` (`service_updated`).
  3. **Control:** a schedule-only save (`*/2` → `*/3 * * * *`, 01:20:29) gave the same toast and no new deploy; the list was unchanged after 15 s. Header Schedule updated to `*/3 * * * *`.
  4. zh: `操作器将在下一次协调时应用新计划。` (`dashboard/src/features/services/locales/zh.ts:2150-2153`).
- **Root cause:**
  - `updateCronJob` (`dashboard/src/features/services/hooks/use-cron-job.ts:152-161`) always passes `t("services.deployConverging")` as the toast description, whichever field changed.
  - The string (`locales/en.ts:2196-2201`) describes the operator's mechanism rather than what the user will see.
  - **Not traced:** which layer opens the `service_updated` deploy row for a command change. A schedule change opens none.
- **Fix (target behavior):** the description names the outcome in product terms, chosen by what the save changed:
  - **Schedule only:** e.g. "The next run follows the new schedule."
  - **Command (with or without schedule):** e.g. "A deploy is applying the new command; runs after it use it."
  - Never "operator" or "reconcile". en and zh.
  - Extend the hook's test to assert the description per case.
- **Blast radius:**
  - `services.deployConverging` has one use (`use-cron-job.ts:158`).
  - `setStartCommand` (native cron, `:163-169`) passes no description and is unchanged. Whether it also opens a deploy is unverified.
  - `grep -rn -i reconcil dashboard/src/features/*/locales/en.ts` finds 2 lines. The other (`databases/locales/en.ts:996`) is a translator `description`, not shown to users.
- **Unverified:** Render's toast after saving a cron job's command or schedule.
- **Render:** see Unverified.
- **Dedupe:**
  - w4/227 and w4/276 (done) recorded this toast as incidental evidence without flagging it.
  - w4/137 (done) fixed clearing the command.
  - `grep -rli "deployConverging" .pm` finds nothing.
  - Not deploy lag: `git diff 8330744bd origin/main -- dashboard/src/features/services/locales/en.ts` doesn't touch `deployConverging`.
- **DoD (live):** on an owned cron in `bex-canary`:
  - a Command save shows a description that mentions the deploy and not the schedule;
  - a Schedule-only save shows the schedule wording;
  - neither shows "operator" or "reconcile", in en and zh.

- **2026-11-11 (loopx w4):** done. `updateCronJob` (`use-cron-job.ts`) takes which field the save changed, and its toast says what happens next. After a schedule change it reads "The next run follows the new schedule." (下一次运行将按新的计划执行。). After a command change it reads "A deploy is applying the new command; runs after it use it." (正在部署新的命令，之后的运行将使用它。). Neither mentions the operator or a reconcile pass. The old `deployConverging` copy is gone, the cron deploy section passes the changed field, and tests cover both toasts in en and zh.
