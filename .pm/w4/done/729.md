# 729 — `npx skills add bex-co/bex` lists bex's 20 product skills, not the repository's 24 maintainer skills

Why: Render's agent setup pages give `npx skills add render-oss/skills` as the skills fallback, but the same command against bex's public repository offers the 24 maintainer skills in `.claude/skills/` (ship, loopx, release, qa-find-bugs, rt-*, …) and none of the 20 `bex-*` product skills.

**Estimate:** ~1h. **Source:** `/pm-brainstorm one more aspect of render parity for w4`, 2026-11-24 (the aspect: how a coding agent connects to bex, as Render's agent docs describe), each item re-verified by an independent agent on 2026-11-24/25 before filing; filed by `/pmx them all to w4` at `origin/main` `50a5ddfdfc`.

## Evidence (verified 2026-11-25)

- **Render:** `render.com/agents/{claude,codex,cursor}.md` each say "Skills fallback command: `npx skills add render-oss/skills`".
- **bex today:** `skills@1.9.0 add bex-co/bex --list` (git clone, scratch HOME) and `add <local checkout> --list` both print "Found 24 skills", all maintainer skills. The six vendored skills (`security-audit`, `stripe-*`, `upgrade-stripe`) are already hidden because the repository's own `skills-lock.json` lists them; the `.agents/skills/*` symlinks add no duplicates.
- **Why the pack is invisible:** it lives at `lego/cli/internal/skills/pack/skills/` (20 `bex-*`, each with a matching frontmatter `name`), which is not a discovery location and is deeper than the CLI's recursive fallback (5 levels).
- **What fixes it (simulated in a scratch copy):** `metadata.internal` hides a skill unless `INSTALL_INTERNAL_SKILLS=1` (or `--skill <name>`); `skills.sh.json` `paths` **adds** a location to the standard ones. With both, the list shows exactly the 20 `bex-*`; with `INSTALL_INTERNAL_SKILLS=1`, 44.
- `metadata` frontmatter breaks nothing: Codex's parser accepts unknown keys, `stripe-docs` already carries `metadata:`, and `scripts/skill-layout-validate.sh` checks only `name` and `description`. The Agent Skills spec types metadata values as strings.

## Do

1. Add `metadata:` / `  internal: "true"` to the frontmatter of the 24 non-vendored `.claude/skills/*/SKILL.md`. Do not touch the six listed in `skills-lock.json` (their locked `computedHash` would change and `skills update` would drop the marker).
2. Add a root `skills.sh.json`: `{"paths": ["./lego/cli/internal/skills/pack/skills"]}`.
3. Extend `scripts/skill-layout-validate.sh`: every canonical skill is a `skills-lock.json` key or declares `metadata.internal: "true"`, and `skills.sh.json` exists with that path. Add `skills.sh.json` to both path lists in `.github/workflows/scripts.yml`.
4. One line in the `bex skills` section of `docs/bex-cli.md` naming `npx skills add bex-co/bex` as the no-CLI fallback; mention the marker in AGENTS.md's Skill layout rule.

## Done when

- `bash scripts/skill-layout-validate.sh` passes, and fails for a new maintainer skill without the marker.
