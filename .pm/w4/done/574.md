# 574 — Deleting a custom domain that doesn't exist answers 204 by hostname but 404 by `cdm-` id, though GET answers 404 and Render's spec declares 404

Why: a client that deletes a mistyped or already-removed hostname is told the delete succeeded when nothing was there. The same endpoint answers 404 when the same miss is spelled as an id, so a script can't rely on either answer.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 113, 2026-11-11 14:52–15:00 UTC (`muse.env`, workspace `bex-canary`; the release pin moved to `f609163ada8e` (`6ee0197c7`) just before this round). **Minor**: a mutation reports success that did nothing, on REST, GraphQL and MCP. ~45m.
- **Fixture:** Free image web service `qa-20261111-r113-new` (`srv-dbq82p7pvbns739s70v0`). Throwaway hostnames were added and removed in the same visit. The service was deleted afterwards (DELETE 204, then GET 404).
- **Probe** (signed-in page, `…/v1/services/srv-dbq82p7pvbns739s70v0/custom-domains/…`):
  - `DELETE never-existed-r113.example.com` → **204**, empty body.
  - `GET never-existed-r113.example.com` → `404 {"code":"NOT_FOUND","error":"custom domain not found",…}`.
  - **The id path disagrees.**
    - `POST {"name":"qa-r113-byid.example.com"}` → 201 `cdm-dbq84jfpvbns739s71f0`. `GET` and `POST …/verify` by that id answer 200 and 202.
    - `DELETE cdm-dbq84jfpvbns739s71f0` → 204, then `GET` by id → 404.
    - A **second** `DELETE cdm-dbq84jfpvbns739s71f0` → **404** `custom domain not found`.
  - **GraphQL agrees with REST.**
    - `deleteCustomDomain(id:"srv-dbq82p7pvbns739s70v0", name:"never-existed-r113.example.com")` → `{"data":{"deleteCustomDomain":true}}`.
    - The same mutation with `name:"cdm-dbq84jfpvbns739s71f0"` → `errors[0].extensions.code: "NOT_FOUND"`.
  - **A malformed id is a third answer.** `DELETE cdm-doesnotexist000000000` → `400 CUSTOM_DOMAIN_INVALID` "invalid hostname … use a fully qualified domain name", because a string that isn't a valid `cdm-` id is parsed as a hostname.
- **Root cause:**
  - **By name, delete is silently idempotent.** `DeleteDomain` (`lego/backend/internal/apps/domains.go:1600`) only *records* whether something was removed. On the managed path it asks `GetDomainClaim` (`:1633`), then calls `RemoveDomain` unconditionally and returns nil. The legacy path returns nil at `:1666` ("not present — idempotent, and no event").
  - **By id, the miss is a 404.** `domainHost` (`:784-799`) resolves a `cdm-` id to its claim and otherwise returns `core.NotFound("custom domain")`. That is the same answer `GetDomain` gives for an unknown hostname.
  - **Tests pin the 204.** `TestDeleteDomainIdempotent` (`domains_test.go:884`), the retry at `domains_test.go:380`, and `TestDeleteRecordsOnlyARealRemoval` (`domain_events_test.go:131-136`).
  - **No recorded decision.** ADR018's custom-domains row (`docs/ADR018-render-parity.md:169`) and ADR020:109 describe `{customDomainIdOrName}` "as on Render". Neither records idempotent delete as a divergence.
- **Fix (target behavior):**
  - `DELETE …/custom-domains/{customDomainIdOrName}` answers **404 `NOT_FOUND` "custom domain not found"** when the service has no such domain, whether it is named by hostname or by id, matching GET and Render's declared 404 (`internal/api/openapi/render-public-api-1.json`, `/services/{serviceId}/custom-domains/{customDomainNameOrID}` delete responses: 204, 400, 401, 403, 404, …).
  - **Unchanged:** deleting the primary of an apex/www pair removes the sibling in one call.
  - **The malformed id:** a string with the `cdm-` prefix that isn't a valid id also answers 404, not "invalid hostname".
  - **Surfaces:** `DeleteDomain` has exactly 3 callers: REST `apps/rest.go:1369`, GraphQL `deleteCustomDomain` (`apps/graphql.go:1939`) and MCP (`apps/mcp.go:965`). Changing `DeleteDomain` to return `core.NotFound` when nothing was removed covers all three.
  - **Dashboard:** `use-custom-domains.ts:225` deletes by name. A row deleted in another tab must then refresh the list rather than show an error, so treat `NOT_FOUND` on delete as already gone.
  - **Tests:** replace the three idempotence assertions with a 404 assertion, and keep the "no audit row for an absent host" check.
- **Adjacent classes:** a domain that belongs to **another** service, or to another workspace, must keep failing exactly as it does today, through `AuthorizeApp` and `domainHost`. That case wasn't probed this round, so it belongs in the tests.
- **Unverified:**
  - Render's live answer to deleting an unknown name. Only its spec's declared 404 was read.
  - MCP `delete_custom_domain`, which was read from source, not called.
- **Render:** the spec declares 404 for this operation. Render's GET of an unknown domain is 404, as bex's is.
- **Dedupe:**
  - `grep -rln "already-absent\|idempotent delete" .pm` finds nothing about domains.
  - w4/389 (done) added `cdm-` ids and the `{customDomainIdOrName}` resolution. w4/m122 (done) gated the audit row on a real removal.
  - Not deploy lag: `domains.go:1600-1668` is unchanged on `origin/main`.
- **DoD (live):** on an owned Free web service, signed in:
  - `DELETE …/custom-domains/never-existed.example.com` → 404 `NOT_FOUND`. So does GraphQL `deleteCustomDomain`.
  - Add `qa-<date>.example.com`; `DELETE` by its `cdm-` id → 204; a second `DELETE` by id or by name → 404.
  - Adding an apex, then deleting it, still removes its `www` sibling in one call.
  - The dashboard's Delete on a domain removed meanwhile in another tab refreshes the list without an error toast.

- **2026-11-11 (loopx w4):** done. `DeleteDomain` answers `core.NotFound("custom domain")` when the service has no such host (managed path: no claim and not in `spec.hosts` or the primary `spec.host`; legacy path), matching GET and Render's declared 404 on REST, GraphQL and MCP; a dotless `cdm-` reference that is no valid id is the same 404, not "invalid hostname"; another service's domain stays not found. The dashboard treats NOT_FOUND on delete as already gone (refetch, no error). Tests: `TestDeleteDomainOfAnAbsentHostIsNotFound`, `TestDeleteDomainOfAnotherServiceIsNotFound`, the pair-matrix retry and the audit test (an absent host records no row), `use-custom-domains-delete.test.ts`.
