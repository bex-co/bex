## Objective

The Definition of done says `404 page not found` never appears between the create `201` and the first `200`. On the live pin carrying t001–t006 it still does, for the first ~2.5 s: the host has no route until the operator's first reconcile writes the Ingress and Traefik loads it. A poll every 3 s from the 201 (the DoD's own method) usually lands in that window.

## Context

Live `/qa-find-bugs w4` loop run 8a59, 2026-10-27 UTC (`muse.env`, `bex-canary`, pin `b4726243e74f`; m235's `f4e383710` is in the pin). A Free image web service `ghcr.io/nginxinc/nginx-unprivileged:stable-alpine` was created with `POST /v1/services`, then its host was polled every 0.5 s from the 201:

```text
+0.6s  404  "404 page not found"          (Traefik, no route)
+3.2s  503  Retry-After: 10  "This service's first deploy is in progress. Try again in a few seconds."
+12.6s 200  nginx welcome page
```

A second fixture created a minute earlier showed the same `404 → 503 → 200` sequence on 8 s polling. Both fixtures (`srv-dbg2k6ln83uc738uuaqg`, `srv-dbg2kgtn83uc738uuatg`) were deleted (`GET` → 404).

Mechanism: `routeFirstDeploy` / `writeFirstRoute` (`lego/operator/internal/controller/app_controller.go:3023-3045`) run in the operator's reconcile, so the route exists only after the App CR is reconciled and Traefik's Kubernetes provider has loaded the new Ingress. Until then Traefik has no router for the host. **Static sites (run c1a8, same day and pin).** The route at creation (t003) holds: `qa-20261026-…-st` (`examples/static-site`, `publishPath: .`), polled every 0.5 s from the 201, answered the first-deploy `503` (`Retry-After: 10`) from +0.9 s, so there was no 404 window. But for ~1.7 s just before the first `200` (+20.4 s → +22.1 s) a bare request (`Accept: */*`) got a different answer: `503`, `Retry-After: 5`, `content-type: application/json`, `{"error":"service not ready","retryAfter":5}`. That is the activator's static-site handover branch (`lego/operator/cmd/activator/main.go:206-212` → `writeWakeResponse`, `:294-303`). It negotiates only HTML vs JSON, unlike `writeNotServing`'s HTML/JSON/text, so the DoD's "every pre-200 answer is bex's first-deploy response" fails for static sites too. The fixture was deleted (`GET` → 404).

## Steps

1. Make the host answered from the instant create returns. Options, roughly in order of preference:
   - a lowest-priority catch-all router for `*.<platform domain>` to the activator. The activator resolves the App by host, answers the t001 first-deploy `503` for an App that exists and never served, and a bex-branded `404` for an unknown host;
   - or have the backend's create write the first route (the activator Ingress) synchronously before returning `201`.
2. Make sure the catch-all can never shadow a real route (strictly lower priority than every App Ingress) and never wakes or touches an App.
3. Static-site handover: while a never-before-served static site's route moves to the static-server, answer the t001 first-deploy response (same wording, `Retry-After`, three-way negotiation), not the wake path's JSON. Or keep the handover branch but give it `writeNotServing`'s three-way negotiation and the first-deploy wording when `ActiveRevision` was just set by the first publish.
4. Re-run the DoD with a sub-second poll as well as the 3 s one.

## Files

- `lego/operator/internal/controller/app_controller.go` (first route) and/or the activator's host lookup
- platform Traefik values or a static IngressRoute for the catch-all (`deploy/gitops/…`), if that option is chosen

**Done 2026-10-26 (loopx w4), code + tests; the live 0.5 s poll is owned by t007's replay.** Option 1, the catch-all. The operator writes `bex-platform-host-fallback` (`EnsurePlatformHostFallback`, run once per leader start from `cmd/manager`) in the activator's namespace: host `*.<BEX_BASE_DOMAIN>` (domain-agnostic, #PSL), `router.priority: "1"`, TLS with no Secret so Traefik serves the TLSStore's default wildcard certificate, backend the activator. App routes never pin a priority, so Traefik's rule-length default always ranks them above it. The activator already indexes a new App's host from its spec on every watch event, so a just-created public App answers the t001 first-deploy `503`. A host no **public** App owns (unknown, or a private service's or worker's would-be host) now answers a negotiated bex `404` and never reaches the wake path. Tests: `internal/controller/platform_host_fallback_test.go`, `cmd/activator` `TestFallbackHostsNeverWakeANonPublicApp` + updated unknown-host test. `deploy/gitops/charts/onbex-default-tls/tlsstore.yaml`'s "deliberately no catch-all" comment updated. **Static-site handover (step 3, added by run c1a8):** the activator's static-site branch now answers the t001 first-deploy response (`writeFirstDeployResponse`: `Retry-After: 10`, page / JSON / text) instead of the wake path's HTML-or-JSON `service not ready`. **Residual:** a suspended static site's resume passes through the same branch for the second or two Traefik takes to reload its route, and reads "first deploy in progress" there. The activator has no first-served marker to tell the two apart. Test: `cmd/activator` `TestFirstDeployYieldsToEveryOwnerChoice/static_handover`, a bare request now gets the first-deploy text. **Unverified until the live replay:** Traefik's translation of the wildcard host and the priority on both the `web` and `websecure` routers.

**Correction 2026-10-28 (loopx w4):** the operator-written fallback Ingress never existed in production. The `bex-operator-object-namespaces` ValidatingAdmissionPolicy (`deploy/gitops/base/operator-workload-admission.yaml`) lets the operator write Ingresses only in tenant and bootstrap namespaces, so `EnsurePlatformHostFallback` was refused in `bex-system` at every leader start. The envtest suite has no admission policies, so it passed. The route is now a platform manifest, `lego/operator/config/activator/platform-host-fallback-ingress.yaml`, rendered as `bex-platform-host-fallback` → `bex-activator:8888`. The operator runnable is removed, and the test now checks the manifest. `scripts/gitops-validate.sh`'s anti-affinity count was fixed too: it joined per-document values into one octal number that overflowed, and the extra document flipped its verdict.
