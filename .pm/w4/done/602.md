# 602 — A cold load of a service's Events tab first shows the actor as a raw user id ("by usr-d9a5qasbt3bc73fiphn0"), then swaps it for the email, although the event already carries the email

Why: every deploy row of the Events tab briefly reads "Config Change by usr-…" before it reads "by puncsky@gmail.com". The id is an internal identifier, and the email it is replaced by was already in the response that painted the row.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 178, 2026-11-12 08:16–08:19 UTC (`muse.env`, workspace `bex-canary`; pin `3d66946c9e16`). **Minor** (pre-settle flash, cosmetic). ~25m.
- **Fixture:** Free web service `qa-20261112-r178-env` (`srv-dbqn5sqibtfs738vkq70`, `ealen/echo-server:0.9.2`), deleted afterwards.
- **Probe:** `https://dashboard.bex.co/services/srv-dbqn5sqibtfs738vkq70/events?lang=en`, loaded after `about:blank`. Once the first "Deploy started" row appeared, `main`'s text was sampled every 400 ms for the first `by …`:
  - load 1: `2299ms:usr-d9a5qasbt3bc73fiphn0`, then `2702ms:puncsky@gmail.com` and every later sample the email;
  - load 2, with the members query cached: `800ms:puncsky@gmail.com` from the first sample.
  - The first visit's accessibility snapshot of the same page read `text: In Progress Config Change by usr-d9a5qasbt3bc73fiphn0 Deploy dep-dbqnan2ibtfs738vkr6g` and `text: First Deploy by usr-d9a5qasbt3bc73fiphn0 …`.
  - After a reload, the same rows read `by puncsky@gmail.com`.
- **Root cause:**
  - **The row passes only the id.** The Events route takes the actor as `details?.suspendedByUser?.id || details?.resumedByUser?.id || details?.trigger?.user?.id || … || details?.triggeredByUser` (`dashboard/src/routes/services.$serviceId.events.tsx:314-323`), passes it to `useWorkspaceSubjectLabel` (`:443`), and renders `services.eventsActor` (`:543-545`).
  - **The email is already fetched.** The events query selects `email` on all three users: `suspendedByUser`, `resumedByUser` and `trigger.user` (`dashboard/src/features/services/api/events.graphql:81-88`, `:134-137`; GraphQL `EventUser { id email }`). REST `details.trigger.user` carries `{"id":"usr-d9a5qasbt3bc73fiphn0","email":"puncsky@gmail.com"}` too.
  - **The hook falls back to the raw subject while loading.** `useWorkspaceSubjectLabel` (`dashboard/src/common/hooks/use-workspace-subject-label.ts:14-33`) runs a cache-first `WorkspaceMembers` query and returns `member?.email || member?.userId || subject`. Until that query settles, `members` is `[]`, so the hook returns the raw subject.
- **Fix (target behavior):**
  - **Events:** the actor reads the event's own email from first paint (`trigger.user.email`, `suspendedByUser.email` or `resumedByUser.email`). The member list only fills in a subject that has no email on the event, such as `triggeredByUser` or `actor`.
  - **The hook:** while the members query is loading, it returns `null` for an unresolved subject, and its callers render a short placeholder of the label's width instead of the id. It returns the raw subject only after the query has settled without a match. That is the removed-member case w21/014 decided shows the id.
  - en and zh.
