## Objective

Prove the new financial and workspace-authority boundaries, including failure modes that happy-path UI tests cannot cover.

## Context

- This flow crosses Stripe, Postgres, OpenFGA, GraphQL, Kratos-derived email, SSR, redirect return, and browser Elements.
- Tests must fail when the code reuses the current workspace, trusts a client redirect/token without Stripe verification, creates twice, leaks an attempt across subjects, or leaves a visible tenant half-finished.

## Steps

1. Add store and service unit/real-Postgres tests for attempts, expiry, subject binding, caps, concurrent finalization, compensation, and cleanup.
2. Add Stripe transport tests for request shape, email/metadata/idempotency, dynamic payment methods, verification, mode mismatch, webhook replay, and sensitive-data redaction.
3. Add GraphQL cross-boundary tests for all/paid/off policy and stable coded errors.
4. Add dashboard component/hook/route tests for Kratos prefill, plan transitions, required/optional payment, Stripe errors, redirect resume, cancellation, duplicate clicks, and matching skeleton structure.
5. Run live Stripe test-mode browser success + cancel/retry and the full affected CI suites.

## Acceptance criteria

- [x] Mutation tests or equivalent prove guards fail closed for foreign/replayed/unverified setup and fail if current-workspace billing is consulted.
- [x] Provider/Postgres/OpenFGA failures at each boundary have an asserted recoverable or compensated outcome.
- [x] Browser tests assert no workspace is selected/visible before finalization and exactly one is selected after success.
- [x] Sensitive payment values never appear in captured GraphQL, logs, persisted rows, analytics payloads, or snapshots.
- [x] `make test`, backend `go test ./...`, relevant lint, `dashboard/yarn typecheck`, `dashboard/yarn lint`, and `dashboard/yarn test` pass.
