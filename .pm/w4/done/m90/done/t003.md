## Objective

Replace the current-workspace billing checkpoint with a resumable, server-verified create orchestration that returns the new workspace only after its own billing state is ready.

## Context

- `workspaces.Service.Create` currently accepts only `(name, plan)`, checks paid eligibility on `s.Tenant(ctx)`, inserts the tenant, then grants OpenFGA admin.
- `workspaces.GraphQLMutation` and `dashboard/src/features/workspaces/api/workspaces.graphql` expose only `createWorkspace(name, plan)`.
- Workspace create deliberately has no REST/MCP mutation because Render's `/v1/owners` is read-only. Keep this product boundary.
- Production `all` mode needs a card for every plan; `1` needs it for paid plans; billing-off must still work for self-hosters. The backend must expose this policy rather than letting the dashboard infer it from plan names.

## Steps

1. Add GraphQL prepare/resume/finalize shapes (or evolve `createWorkspace` compatibly) with coded, stable errors for payment required, stale attempt, setup incomplete, and provider unavailable.
2. Run mint-class authorization, name/plan/email validation, plan entitlement, and per-user cap checks before provider setup; repeat authoritative mutable guards at finalization.
3. After provider verification, atomically finalize the tenant/member/billing mapping/marker, establish the contract, and grant OpenFGA admin with compensation that cannot leave a visible half-created workspace.
4. Make retries return the already-created workspace to the same subject and refuse replay across subjects or changed name/plan/email.
5. Remove `RequirePlanBilling` against the current workspace from this path and define the compatibility behavior for non-interactive legacy callers.

## Acceptance criteria

- [x] No paid/all-mode create can succeed because some other workspace has a card.
- [x] `all`, paid-only, and billing-off policies are returned by the server and enforced identically at prepare and finalization.
- [x] Finalization returns one fully authorized, payment-ready workspace and is idempotent under concurrent/repeated requests.
- [x] Failure after any provider/Postgres/OpenFGA boundary has a tested compensation or resumable state; no visible tenant lacks its owner tuple or required payment marker.
- [x] Unknown/foreign attempt ids do not disclose existence or provider state.
- [x] REST and MCP remain read-only for workspace mutation, with the deliberate parity-by-absence documented.

## Out of scope

- Workspace rename/delete/change-plan behavior.
- A public REST payment-token API.
