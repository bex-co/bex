# The dashboard has no "skip to main content" link, so a keyboard user tabs through 13-16 sidebar and header stops on every page before reaching the content

Why: every page repeats the same sidebar (logo, workspace switcher, sidebar toggle, then 10+ nav links), so each navigation costs a keyboard or screen-reader user 13-16 Tab presses before the first control of the page they asked for (WCAG 2.4.1 Bypass Blocks, Level A).

Source: live `/qa-find-bugs w4` loop run, round 13, 2026-11-01 UTC (`muse.env`, QA workspace `bex`; read-only, nothing created). Severity: minor (keyboard accessibility, nothing is lost). Estimate: 30m.

## Repro (https://dashboard.bex.co, desktop, fresh load each)

Press Tab repeatedly and count presses until `document.activeElement.closest('main')` is truthy.

| Page | Tab presses to reach `main` | First stop inside `main` |
| --- | --- | --- |
| `/` | 13 | `BUTTON:Search` |
| `/services/srv-dbavjsm05jqs73cjk3og/deploys` | 16 | `A:Projects` |
| `/services/srv-dbavjsm05jqs73cjk3og/settings` | 16 | `A:Projects` |
| `/env-groups` | 13 | `BUTTON:Search` |

- The first Tab stops on a service page are `A:Go home`, the workspace switcher, `BUTTON:Toggle Sidebar`, `A:Dashboard`, then the nav links.
- `document.querySelectorAll('a')` filtered for `/skip/` in text, aria-label or href returns 0 on all four pages, and a grep of `dashboard/src` for skip-to-content / skip-link patterns finds nothing.
- After a sidebar navigation (Enter on the Logs link) focus stays on `A:Logs` in the sidebar, so a route change also leaves focus before the content.

## Root cause

`dashboard/src/common/components/dashboard-layout/index.tsx:40-52` renders `<DashboardSidebar />` before `<main className="flex flex-1 flex-col min-w-0 w-full">` (which starts with `<DashboardHeader />` and then `{children}`). There is no skip anchor ahead of the sidebar and no id/tabindex on `main` for one to target.

The layout is rendered by 29 page components (grep `<DashboardLayout` in non-test src) and short-circuits to `<>{children}</>` when already inside the persistent root shell (`inShell`, lines 36-39), so the fix belongs in whichever component renders the shell the first time. The invitation frame (`features/invites/invitation-frame.tsx`) has its own `<main>` outside this layout.

## Fix

Target behavior: the first focusable element on every dashboard page is a visually hidden link, visible on focus, labelled "Skip to main content" (through the existing i18n catalog, not a hard-coded string). Activating it moves focus to the page content (the `main` landmark or the first heading after the header); a second Tab leaves it for the normal order. Place it once in the shell, not per page.

- **Blast radius:** the one shell/layout component plus its tests (`dashboard-layout/__tests__/*` render `SidebarProvider` and a bare `<main>` and must not start finding two skip links). The 29 `DashboardLayout` pages need no change. The mobile drawer navigation (`__tests__/mobile-drawer-navigation.test.tsx`) must keep its own focus handling.
- **Adjacent classes:** auth and invitation pages have no sidebar and need no skip link. In-app focus order after route changes (focus left on the sidebar link) is a separate, larger decision and is deliberately not part of this note.
- **Unverified:** whether the persistent root shell (`inShell` provider) lives in `routes/__root.tsx` or elsewhere (not opened); behavior with a screen reader; the mobile (390px) menu, where the sidebar is a drawer and the tab count may be lower.
- **Render:** Render's dashboard exposes a skip link to main content (standard WCAG bypass block); verify against the live Render dashboard before copying wording.

## Dedupe

grep of `.pm`, `docs` and `dashboard/AGENTS.md` for skip link, skip to content and bypass blocks found only unrelated uses of the word "skip" (w4/282 is an Apollo option; w7/m34 and w2/m75 are unrelated). w4/408 (focus return for ConfirmDialog) and w4/459 (focus return for plain dialogs) are different defects on different components. No DO_NOT_DO item applies. Evidence is the measured Tab counts above; screenshots are session-local.

## Done 2026-11-02 (loopx w4)

`DashboardLayout` renders one visually hidden, visible-on-focus "Skip to main content" link (`common.skipToMainContent`, en + zh) as the first Tab stop; it focuses `main#main-content` (tabIndex -1). Placed in the shell only, so the 29 pages need no change and a nested layout adds none. Test `dashboard-layout/__tests__/skip-link.test.tsx`. Route-change focus order stays out of scope as the note says.
