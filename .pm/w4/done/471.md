# 471 — The workspace switcher marks the current workspace with an icon only, so assistive technology cannot tell which workspace is active

Why: before acting on a resource, a screen-reader or voice-control user opens the switcher to confirm which workspace they are in. Today every workspace row reads the same ("bex Scale", "tian-personal Hobby", "bex-canary Scale"), so they can't tell, and a destructive action can land in the wrong workspace.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 7, 2026-11-04 ~12:30 UTC (`muse.env`, `bex-canary`, pin `fb6098dd2e37`); **minor** (accessibility); ~25m.
- **Probe** (Playwright, desktop, read-only): open the sidebar switcher, then `page.getByRole('menu').ariaSnapshot()` → `menuitem "bex Scale"`, `menuitem "tian-personal Hobby"`, `menuitem "bex-canary Scale"`. None has `[checked]`. Evaluating each `[role=menuitem]`: `aria-checked`, `aria-current` and `data-state` are all `null`, and the role is `menuitem` for all three. Only the active row (`bex-canary`) contains an `svg.lucide-check`, which is visual only. Screenshot: `.playwright-mcp/qa-projects-1.png` (local).
- **Root cause:** `dashboard/src/features/workspaces/components/workspace-switcher.tsx:135-159`. Each workspace is a plain `DropdownMenuItem`, and the current one only adds `<Check className="size-4 shrink-0" />` (`:156-158`) with no state.
- **Fix:** render the workspace list as `DropdownMenuRadioGroup` with `DropdownMenuRadioItem`s (`common/components/ui/dropdown-menu.tsx:111-122`; Radix gives `role="menuitemradio"` and `aria-checked`) whose value is `currentWorkspace.id`, and keep `onSelect → switchTo`. Alternatively, add `aria-current="true"` to the current item. Keep the visible check.
- **Tests:** extend `features/workspaces/components/__tests__/workspace-switcher.test.tsx`. Opening the menu yields exactly one checked or current workspace item and it is the current workspace; after `switchTo`, the new one is checked. Keep the existing trigger and placeholder tests.
- **Render:** Render's workspace switcher marks the active workspace with a check.
- **Dedupe:** w4/440 (done) is about the switcher trigger's layout jump, and w4/140 (done) about Registry Credentials ignoring the switcher. w11/m9 is the native app's drawer. No item covers the menu's checked state. No DO_NOT_DO item applies.

- 2026-11-04: fixed by the loopx w4 drain: the switcher lists workspaces as `DropdownMenuRadioGroup`/`DropdownMenuRadioItem` (`menuitemradio`, `aria-checked`) with the visible check kept; `workspace-switcher.test.tsx` asserts exactly one checked item.
