# 391 — Suspend/resume and deploy events name the user as a raw identity UUID and omit Render's `suspendedByUser` / `resumedByUser` / `trigger.user` objects

Why: a Render client reading `GET /v1/services/{id}/events` to answer "who suspended this?" finds the pinned schema's `suspendedByUser {id, email}` absent. It gets an opaque Kratos subject in `actor`, a field Render's service model fills with a suspender kind (`suspenders: ["user"]`).

**Severity:** minor (attribution is present but in the wrong shape; nothing breaks). **Estimate:** ~1h. **Source:** live `/qa-find-bugs w4` loop run m9q4, 2026-10-23 UTC (`muse.env`, `bex-canary`, pin `b3cd5bc74de8`). Fixture: Free image web service `qa-20261022-m9q4-echo` (`srv-dbdbara8ohec73f9fueg`, `mendhak/http-https-echo:35`, port 8080), created in the dashboard. It was suspended and resumed from Settings, then deleted (`GET` → `404`); session revoked.

## Probe

`GET /v1/services/srv-dbdbara8ohec73f9fueg/events?limit=30` (the same service reports `"suspenders":["user"]` while suspended):

```json
{"type":"suspender_added","details":{"actor":"c73bb20d-40ff-42df-8597-c9a428697d12"}}
{"type":"suspender_removed","details":{"actor":"c73bb20d-40ff-42df-8597-c9a428697d12"}}
{"type":"deploy_started","details":{"deployId":"dep-dbdbara8ohec73f9fuf0","trigger":{"firstBuild":true,"envUpdated":false,"manual":false,"deployedByRender":false,"clearCache":false,"rollback":false,"deployHook":false},"image":"docker.io/mendhak/http-https-echo:35","finishedAt":"2026-10-23T01:16:46Z","triggeredByUser":"c73bb20d-40ff-42df-8597-c9a428697d12"}}
```

The pinned Render schema (`lego/backend/internal/api/openapi/render-public-api-1.json`, `/events/{eventId}` details `oneOf`) defines:

- **Suspender Added:** `{actor: string (required), suspendedByUser: {id, email}}`.
- **Suspender Removed:** `{actor, resumedByUser: {id, email}}`.
- **Deploy Started:** the trigger carries `user: {id, email}` ("User who triggered the action").
- **Server Restarted:** `triggeredByUser: string|null`. This is the only event where Render uses `triggeredByUser`.

## Root cause

- `lego/backend/internal/events/service.go:956-957` sets `Details.Actor = r.Caller` (the raw identity subject) for the suspender pair. The deploy branch sets `TriggeredByUser = r.Caller` (`service.go:930`, w4/072). `events/rest.go:182-200` `toRenderEvent` copies both verbatim and emits no `suspendedByUser`, `resumedByUser` or `trigger.user`.
- w4/072 (`.pm/w4/done/072.md:76`) concluded "Render's deploy object does not carry an actor … not a REST-parity gap". The pinned events schema says otherwise for the event **details**.

## Fix (target behavior)

- `suspender_added` / `suspender_removed` → `actor` is the suspender kind from Render's `suspenderType` enum (`user` for a dashboard/API suspend). They also carry `suspendedByUser` / `resumedByUser` `{id, email}` for the human, resolved through the same identity resolver the dashboard uses ("by puncsky@gmail.com").
- `deploy_started` → `trigger.user {id, email}` when a human triggered it. Leave it absent for git-push and deploy-hook triggers. Keep `triggeredByUser` only where Render defines it (`server_restarted`). If bex keeps it on deploys as an extension, say so in ADR018.
- GraphQL/MCP event fields and the dashboard Events row (`services.$serviceId.events.tsx`, which reads `details.actor || details.triggeredByUser`) must keep showing the email.
- Note in ADR018 (service events row) what `id` is: the identity id, or a Render-style user id if ADR020 mints one.

**Unverified:** Render's literal `actor` value on a user suspend (the schema types it as a string; `suspenderType` is the inferred vocabulary); MCP's event tool output.

## Loopx w4 verdict (2026-10-25)

Done: suspender events emit `actor: "user"` with `suspendedByUser`/`resumedByUser` {id, email} (email resolved best-effort at read), human-triggered deploys emit `trigger.user`, on REST, GraphQL, MCP and the dashboard events feed. `triggeredByUser` on deploy rows is kept as a bex extension and recorded as such in ADR018.
