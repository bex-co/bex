# 680 — The Notifications page's loading skeleton reserves about 490 px for content that renders about 1700 px tall at 1440 px (about 2600 px at 390 px): the Email card (154 → 348 px) and Mobile push card (210 → 1202 px) grow on load, so the Browser card jumps about 1190 px

Why: the dashboard rule ([AGENTS.md](../../AGENTS.md), "Dashboard preloading skeletons must match their post-loading contents") asks a pending state to keep the ready page's major regions at stable heights. On `/notifications` the skeleton draws three short generic cards.

- When the data lands, everything below the first card moves.
- A visitor who clicks "Browser notifications" in the section rail while it loads lands about 1190 px above the section.
- The ready layout is fixed, not data-shaped: Mobile push disables its controls when push is off; it does not hide them. So the skeleton can know its height in advance.

This regresses [w5/m79 t004](../w5/done/m79/done/t004.md), "Billing and Notifications skeletons", whose acceptance asked for pending-versus-ready evidence of the same outer bounds and major regions.

- **Cause:**
  - `NotificationsPageSkeleton` (`dashboard/src/common/components/route-skeletons.tsx:664-688`) fills the three regions with the generic `CardSkeleton` at `rows={3}`, `rows={5}` and `rows={2}`. That component (`dashboard/src/common/components/detail-skeletons.tsx:169-190`) is an `h-5` title plus `rows` × `h-4` lines with `space-y-3`.
  - The ready panels are much taller:
    - `NotificationSettingsPanel` (`dashboard/src/features/notifications/components/notification-settings-panel.tsx`, the rows at `:80`) renders a two-line description and three bordered `p-3` switch rows.

- **Fix:** the target is that each pending region has the ready panel's structure and height at the same width.
  - Replace the three `CardSkeleton`s with per-panel skeletons.
  - **Email:** the card title and description footprint, then three switch-row skeletons with the row's own chrome (`rounded-md border p-3`, title line + description line + switch pill).
  - **Mobile push:** title + badge + description, the enable row, the event-filter grid (two columns, one cell per entry of the same static event list the ready panel maps), then the urgency, delivery-hours and exceptions controls.
  - **Browser:** its rows.
  - Use the existing invisible-copy helper (`route-skeletons.tsx`, "Static copy's footprint without its ink") for titles and descriptions, so they wrap exactly as the ready copy does in every language.
  - Optional banners stay out of the skeleton: "unavailable" (`:234`), validation (`:367`) and dirty (`:373`).
