## Objective

A Key Value created private (the default) can never become public: `keyvalues update --ip-allow-list` stores the list but publishes nothing, and `bex kv-cli` then targets the unroutable internal host. Make post-create publishing work on every surface.

## Context

- Live repro 2026-09-17, `bex v0.2.1`, fixture `red-daloivj00vpc73cofrn0` (free, deleted after the sweep):
  - `bex keyvalues update <id> --ip-allow-list cidr=<caller>/32,description=qa-cli-probe` → exit 0, CIDR + description round-trip on read-back.
  - `connection-info` afterwards: `internalConnectionString` present (`.svc:6379`), `externalConnectionString` absent, `cliCommand` = `redis-cli -u <internal-uri>`.
  - `bex kv-cli <id> -- PING` (PTY) → `Could not connect to Redis at red-....svc:6379: nodename nor servname provided, or not known`.
- Root cause: `KeyValuePatch.apply` (`lego/backend/internal/keyvalue/service.go:771-787`) writes `Spec.IPAllowList` but never `Spec.Public`. Create derives public from a nonempty allow-list (`lego/backend/internal/keyvalue/rest.go:279-287`); no update path does, and no publish mutation exists on REST, GraphQL (`graphql.go` has create-only `public`), MCP, or the dashboard (the detail page renders `connExternalUnavailable` — "Not public. Enable public access…" — as plain text with no control, `connection-info-panel.tsx:101`).
- Render semantic (recorded in `docs/ADR021-keyvalue-management.md:43`): new stores are externally disabled *until an inbound IP rule is added* — rule-addition is the enabling event, and bex honors it only at create. The `w7/m45` regression test pins read-back only, never the publish effect.
- Consumer: pinned upstream `pkg/tui/views/rediscli.go:129` runs `connectionInfo.CliCommand` verbatim.

## Steps

1. Decide the target (state it in the code + ADR021): update mirrors the create rule (nonempty allow-list publishes), optionally symmetric on clear, or an explicit `public` control on PATCH plus `setKeyValuePublic` GraphQL/MCP plus a dashboard toggle. If clear unpublishes, prove no running workload loses its endpoint surprisingly.
2. Implement across REST PATCH, the dedicated PUT `ip-allow-list` route, `setKeyValueIpAllowList`, and MCP `update_key_value` (all converge on the same patch — grep the callers, count them, fix or allowlist each).
3. Fix the dashboard hint: either wire the promised "Enable public access" control or reword to the real path.
4. Extend the `w7/m45` test to assert the publish effect (external string appears, `cliCommand` targets it), not just read-back.
