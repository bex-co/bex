## Objective

`bex jobs create` is accepted (200 + `job-…` record) and then always lands on a bare `failed` ~16ms later with no reason anywhere. Either make one-off jobs runnable or refuse them honestly — and record the scope decision against the DO_NOT_DO tension below.

## Context

- Live repro 2026-09-17 (twice, second in isolation), `bex v0.2.1`, live free Docker web service (debian-slim image, has `/bin/sh`):
  - `bex jobs create <srv> --start-command 'echo <marker>' --plan-id free -o json` → `{"id":"job-…","status":"failed"}` with `finishedAt - createdAt ≈ 16ms`. `jobs list` agrees; no reason field exists.
- REST re-probe 2026-09-21 (live `/qa-find-bugs` pass 106, `qa-p106-jobs` since deleted): `POST /v1/services/{id}/jobs {"startCommand":"echo qa-p106-hello"}` → `job-daoc7ors0ils73bgpcfg`, `failed`, `finishedAt - createdAt ≈ 12ms`; detail GET carries no reason — same backend, all three surfaces affected.
- Root cause (two halves):
  1. `createK8sJob` (`lego/backend/internal/jobs/service.go:289-329`) submits a plain batch Job, but bex-api's grant is read-only: `deploy/gitops/base/bex-api-apps-rbac.yaml:52-54` allows `batch/jobs` `get,list` only ("created by the operator, never by bex-api"). The `Create` is Forbidden; no bex-api role grants `create` (checked `build-boundary.yaml`, `tenant-namespace-clusterroles.yaml`). So every one-off job fails at admission, on every service type.
  2. The failure reason is swallowed: `service.go:208-214` logs the k8s error server-side and records bare `failed`. Contrast the `failureReason` excellence on deploys (w4/m103).
- SCOPE DECISION REQUIRED: `.pm/DO_NOT_DO.md` lists "One-off jobs (`/services/{id}/jobs`) … remain off-roadmap". But the endpoint shipped with tests and checklist `[x]` rows (graded on dev-9 ACK shape, never a prod run). Step 1 resolves this — do not expand scope silently.

## Steps

1. Gate the endpoint: `POST /services/{id}/jobs` (REST/GraphQL/MCP) refuses with a named `405`/`410` error; re-grade the checklist rows; keep `jobs list/cancel` for history.
2. ~~Grant bex-api `batch/jobs` create and ship one-off jobs~~ — **struck 2026-10-02 (blocked-item triage):** `.pm/DO_NOT_DO.md` keeps "One-off jobs (`/services/{id}/jobs`) and ephemeral shell instances" off-roadmap; the 2026-07-27 pillar-5 re-open covers hosted sandboxes only and the parity-non-goals list says its sibling non-goals are unaffected. Re-open only on an explicit user decision.
3. Either way: surface creation failures to the caller (named error at create time; a `reason` on the job view for async failures). A 16ms `failed` with no text must become impossible.
4. Update `docs/cli-compatibility-checklist.md` (`jobs` rows) to the shipped behavior.

## Outcome (2026-10-02) — gated, implemented locally, awaits /ship

**Scope decision: gate, not grant.** One-off jobs stay off-roadmap per `.pm/DO_NOT_DO.md` (its line keeps "one-off jobs" among the still-excluded surfaces; the 2026-07-27 pillar-5 re-open covers hosted sandboxes only). `.pm/DO_NOT_DO.md` is unchanged — it already says exactly what the code now does. `deploy/gitops/base/bex-api-apps-rbac.yaml` stays `get,list` on `batch/jobs`.

- **Create refuses on every surface.** `jobs.Service.Create` (`lego/backend/internal/jobs/service.go`) authorizes first (`AuthorizeApp(can_create)`, so a caller without access or a missing service still gets 403/404 — no existence oracle, and the m68 executable-selection pins hold) and then returns `ErrOneOffJobsUnsupported`: a `core.CodedError` with code `ONE_OFF_JOBS_UNSUPPORTED` wrapping a new `core.ErrGone` sentinel that `core.WriteErr` maps to **410** (`id: "gone"`). No record is written and no Kubernetes Job is submitted, so a reason-less `failed` can no longer be produced. GraphQL `createJob` carries the code in `extensions.code`; MCP `create_job` prefixes it onto the tool error (`core.MCPError`). The schema/tool names are unchanged, so the dashboard's generated types and the scope matrix stay valid.
- **CLI contract.** The pinned upstream client's generic `ErrorFromResponse` (`render-oss/cli@a764810a7682 pkg/client/client.go`) reads Render's `{id,message,code}` body, so `bex jobs create` prints `received response code 410 (ONE_OFF_JOBS_UNSUPPORTED): one-off jobs are not supported on bex; run the command in the service itself (`bex ssh <service>`), as a pre-deploy command, or as a cron job — existing jobs remain listable` (verified by feeding the exact response body through the pinned client's parser).
- **History kept.** `jobs list/get/cancel` (REST, GraphQL `jobs`/`job`/`cancelJob`, MCP `list_jobs`/`get_job`/`cancel_job`) still serve pre-gate rows and still sync status from a surviving Kubernetes Job.
- **Dead submission code removed** (whole-program deadcode would flag it): `createK8sJob`, `jobSubmitError`, `jobTTL`, the `JobStore.CreateJob` seam, `store.(*PGStore).CreateJob`, and `submit_failure_test.go` (its 503 contract is superseded). `id.Job` stays — existing `job-…` ids remain valid.
- **Tests:** `lego/backend/internal/jobs/gate_test.go` — `TestCreateIsRefusedWithNamedGone` (410 + Render envelope + code; zero Job submits, zero record writes), `TestCreateRefusalComesAfterAuthorization` (denied ≠ 410; missing service = 404), `TestCreateRefusalIsIdenticalOnGraphQLAndMCP`, `TestHistoryVerbsStillServePreGateJobs` (list/get/cancel a pre-gate running job).
- **Docs:** `docs/cli-compatibility-checklist.md` `jobs` rows re-graded (`jobs` `[~]`, `jobs create` + flags `[-]` with the exact CLI output, list/cancel `[x]` as history); `docs/ADR018-render-parity.md` one-off-jobs row records the gate.
- **Verification:** `cd lego/backend && go test ./...` all packages green locally (no `BEX_TEST_DB_URI`/`BEX_TEST_OPENFGA_URL`, so the Postgres/OpenFGA integration tests skipped — CI runs them); `make lint` from `lego/operator` rc=0 (golangci-lint 0 issues ×4 modules + deadcode clean).
