## Objective

Add both fields to the dashboard's create mutation and input builder. Each is sent only when set: `healthCheckPath` for a web service, `preDeployCommand` for a paid web service, private service or background worker.

## Context

- `mutation CreateService` in `dashboard/src/features/services/api/services.graphql` and `dashboard/src/features/services/lib/create-service-input.ts` carry neither field; the builder's per-type gating pattern is `isStaticBuild` (`create-service-input.ts:169`, `:257`, `:421`).
- GraphQL `createService` already takes both (`lego/backend/internal/apps/graphql.go:1628`, `:1631`); REST and MCP accept them too.
- Pre-deploy is "available for paid web services, private services, and background workers" (render.com/docs/deploys); health check paths are for web services ("Private services only support default TCP checks", render.com/docs/health-checks).
- Command text: handle `preDeployCommand` exactly as the builder handles the build and start commands today; w8/m68 (blocked) owns whether command text is trimmed and changes them together.

## Steps

1. Add the variables to the mutation and regenerate the GraphQL types (`dashboard/AGENTS.md`).
2. Build them in `create-service-input.ts` with the type and plan gates; omit empty values.
3. Unit-test the builder.

## Files

- `dashboard/src/features/services/api/services.graphql`
- `dashboard/src/features/services/lib/create-service-input.ts` and its tests

## Acceptance criteria

- [x] A web service with a path sends `healthCheckPath`; a private service or worker never does (test).
- [x] A Free-plan service never sends `preDeployCommand` (test).
- [x] Empty values are omitted (test).
