## Objective

A deploy that ships a build-source build whose image cannot be pulled records Render's `artifact_fetch_failed` with the deploy's `buildId` and the pull failure as `message`. Image-backed services keep `image_pull_failed`.

## Context

- Render's member: Artifact Fetch Failed, `required: [buildId, message]`, `buildId` "The build published by the build source that could not be fetched."
- Today a pull failure records `image_pull_failed` (w2/072) from the reconciler (`lego/backend/internal/store/reconciler.go:1611`, `:1702`).
- A deploy's build id: `buildId` on the deploy object (`lego/backend/internal/deploys/rest.go:74`), `deploys.BuildID` (`lego/backend/internal/deploys/build_sources.go:88`).
- Adjacent, not duplicated: `w32/042` (a second pull failure of the same live release records nothing); coordinate so the fix lands once.
- Recommendation, not a user decision: a linked service records `artifact_fetch_failed` instead of, not beside, `image_pull_failed`; whether Render records both is unverified (`w10/blocked/002`). Record it in ADR018.

## Steps

1. In the pull-failure producer, tell a deploy that shipped a build-source build from an image deploy.
2. Record `artifact_fetch_failed {buildId, message}` for the former, once per failure, with a source key of its own.
3. Unit-test: build-source deploy pull failure → one `artifact_fetch_failed`; image service → `image_pull_failed` as before; a re-read → no duplicate.

## Outcome

- Extended migration `0306_artifact_events` to allow `'artifact_fetch_failed'` on `service_event_facts` and store `build_id` and `message`.
- Split all three pull-failure producers (`observedImagePullFailure`, `PGStore.TransitionDeploy`, and `servedReleasePullFailureFor` via `LiveDeployBuildID`) on whether the deploy/release ships a build-source build: build-source failures emit `artifact_fetch_failed` (`deploy:<id>:artifact_fetch_failed` / `release:<app>:<gen>:artifact_fetch_failed:<ts>`) with `buildId` and the pull failure `message` (falling back to `DefaultArtifactFetchFailedMessage`) instead of `image_pull_failed`; image-backed services keep `image_pull_failed`.
- Added unit and real-Postgres round-trip tests in `lego/backend/internal/store/artifact_events_test.go`.

## Out of scope

- The failure email: the deploy's own failure already notifies, as Render's "A service build or deploy fails" does.
