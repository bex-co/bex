## Objective

Linking a service to a build source, moving it to another, or unlinking it records Render's `artifact_source_changed` with `fromBuildSourceId`/`toBuildSourceId` (the absent side omitted), in place of bex's `source_changed`. A source change that does not touch the build source (repository, branch, image) keeps `source_changed`.

## Context

- Render's member (pinned `retrieve-event`): Artifact Source Changed, `fromBuildSourceId` ("The previously linked build source. Absent when the service was newly attached.") and `toBuildSourceId`, neither required.
- The link writes the audit row `apps.LinkBuildSource` (`lego/backend/internal/core/audit.go:471-474`; the audit log names it `UpdateServiceBuildSourceEvent`, `lego/backend/internal/audit/service.go:293`). The feed's row is `apps.SetSourceAndRegistryCredential`, projected as bex's `source_changed` (`lego/backend/internal/events/service.go:74`, `:455`), a type outside Render's enum.
- Link paths: PATCH `/v1/services/{id}` `buildSourceId` (`lego/backend/internal/apps/build_sources.go:868-890`), a build-source create with `serviceIds` (`:134`, `:287`), Blueprint `services[].buildSource` (`lego/backend/internal/apps/blueprint_build_sources.go:526-582`), and whatever unlinks a service.
- Events record only what happened (w4/m122: deferred allowed-write audit), so a refused or no-op link records nothing.

## Steps

1. Find every write that changes a service's build-source link, including unlinking.
2. Make sure the feed's row carries the previous and the new build source; add a migration if `audit_events` lacks a column for the previous one.
3. Project such a row as `artifact_source_changed`; keep `source_changed` for the other source changes.
4. Unit-test: new link (no from), relink (both), unlink (no to), repository change (still `source_changed`), refused and no-op writes (nothing).
