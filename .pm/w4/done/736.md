# A static site's answers, and the edge's HTTP-to-HTTPS redirects, carry no `cf-cache-status`, where Render's edge reports one on every answer

Why: Render parity. Since w4/m687 a web service's answers read `cf-cache-status: DYNAMIC` unless its edge cache set one, but every other answer the edge sends still has none, so a site moved from Render loses the header its CDN debugging and uptime checks read.

- **Render (captured 2026-11-27, [edge-headers.md](../../docs/render-artifacts/edge-headers.md)):** a static site answers its CDN's status: `EXPIRED` on a first `GET /`, `HIT` on the next, `BYPASS` on a missing file's 404. `http://httpbin.onrender.com/headers` answers its `301` with `cf-cache-status: DYNAMIC` and no `rndr-id`; a static site's `http://` redirect carries `cf-cache-status: EXPIRED`.
- **bex:** only the per-web-service `originServer` instance of `deploy/gitops/charts/traefik-plugins/clientipheaders` sets the header (`moveServer`). A static site's route has no such instance, and the `httpsRedirect` instance leads every tenant route, so a web service's redirect never reaches `originServer`; it also carries the `rndr-id` the entrypoint sanitizer set, which Render's redirect does not.
- **Do:** decide what a static site reports. Render's statuses come from Cloudflare's CDN in front of its origin; the static server caches immutable per-revision objects ([ADR029](../../docs/ADR029-static-sites.md)), so a first read of an object per static-server pod can read `MISS` and later reads `HIT`, with `BYPASS` for the 404, unless a closer mapping is found. Have the `httpsRedirect` instance answer `cf-cache-status: DYNAMIC` on a web service's route and the static site's status on a static site's, and drop its `rndr-id` as Render's redirect has none. Record each choice in the ADR018 "Edge headers a web service receives" row.
- **End state:** a static site's `GET /` reads a `cf-cache-status` on bex as on Render, and `curl -I http://<web service host>/` reads `301` with `cf-cache-status: DYNAMIC`, `server: cloudflare`, a `cf-ray` and no `rndr-id`; plugin tests cover each.
- **Size:** about 1h for the redirect half; the static-site half may need the static server's cooperation and a promotion.
- **Source:** w4/m687 t007's parity check, 2026-11-27.

**Promoted to [w4/m703](../m703/README.md) on 2026-11-27 by `/loopx w4`:** more than an hour across several tasks. The redirect needs a static-site variant of the operator's spec, the unknown host's `404` has the same gap (`no-such-service-w4-736.onbex.co` answered with `rndr-id` and no `cf-cache-status`, where Render's answers `DYNAMIC` and none), and the static site's statuses need the static server's own cache state. Render's static-site redirect reads `EXPIRED` and then `HIT`, because Cloudflare stores it.
