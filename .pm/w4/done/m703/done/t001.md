## Objective

The edge plugin's `httpsRedirect` instance answers a redirect as Render's edge does: `cf-cache-status: DYNAMIC` on a web service's route and the unknown host's, the static-site status on a static site's `GET` and `HEAD`, `DYNAMIC` on every `307`, the request's `cf-ray`, and no `rndr-id`.

## Context

- `deploy/gitops/charts/traefik-plugins/clientipheaders/clientipheaders.go`: `httpsRedirect.ServeHTTP` writes the redirect itself. The entrypoint's sanitizer has already set `Cf-Ray` and `Rndr-Id` on `w.Header()`; `server: cloudflare` comes from the `bex-edge-headers` Middleware (`deploy/gitops/base/values/traefik.values.yaml`).
- `lego/operator/internal/controller/app_controller.go`: `reconcileIngress` writes the same `httpsRedirectSpec` into every App's `<app>-https` Middleware. `lego/operator/config/activator/platform-host-fallback-https.yaml` is the unknown host's copy.
- Render (milestone README): a static site's `http://` `GET` read `EXPIRED` on the first request and `HIT` with an `Age` after, because Cloudflare stores the redirect. A web service's and an unknown host's read `DYNAMIC`. Every `307` reads `DYNAMIC`.
- Traefik v3.7.17 runs the plugin under Yaegi. A new Middleware field may reach a Traefik still running the old plugin code, and the new plugin may meet an old spec.

## Steps

1. Choose the static site's redirect status. A constant `EXPIRED` matches Render's first request and never its `HIT`. A bounded per-pod memo of hosts redirected in the last few minutes could read `EXPIRED` then `HIT` with an `Age`. Pick the closest mapping that stays bounded under any number of hosts, and record why in the ADR018 row (t005).
2. Plugin: on a redirect, delete `Rndr-Id` from the response, keep `Cf-Ray`, and set `Cf-Cache-Status`. Add a config field that tells the instance it fronts a static site; leave it unset for a web service and the fallback, which read `DYNAMIC`.
3. Operator: write the static-site variant of the spec into a static site's `<app>-https` Middleware, and keep `httpsRedirectSpec` for every other type. Update `https_redirect_test.go`, which pins the projected spec.
4. Prove the rollout is safe in either order on the deployed Traefik (`BEX_TRAEFIK_INTEGRATION=1`, Docker): the old plugin code with the new spec still redirects, and the new code with the old spec reads `DYNAMIC`. If Traefik refuses an unknown field, ship the plugin first and the operator after it has rolled out.
5. Extend `httpsredirect_test.go` and `https_redirect_traefik_test.go` to assert the headers for each method and each kind of route.
6. After the Traefik rollout, check `curl -sI https://beancount.io/ https://bex.co/ https://dashboard.bex.co/ https://api.bex.co/` at once, and roll back if any fails.

## Acceptance criteria

- [x] A web service's and the fallback's redirect answer `DYNAMIC`, a `cf-ray` and no `rndr-id`, for `301` and `307`.
- [x] A static site's `GET`/`HEAD` redirect answers the chosen status, and its `307` `DYNAMIC`.
- [x] Plugin tests, `make test` and the Traefik gate pass, and the gate shows both rollout orders redirect.

## Out of scope

- The answer behind a passed-through `https` request: `originServer` and the static server set those (t004).

## Record — 2026-11-27

- **Choice (step 1):** a static site's `301` reads `MISS` the first time a Traefik pod redirects a path, `HIT` with an `Age` for 120 minutes (Cloudflare's default for a `301` sent without `Cache-Control`), then `EXPIRED` once, from a memo shared by every static site's redirect instance in the pod and bounded at 8,192 paths (expired entries go first, then arbitrary ones down to three quarters). A URL with a query reads `BYPASS`. A constant `EXPIRED` matched only Render's first request. Render's own captures ([edge-headers.md](../../../../../docs/render-artifacts/edge-headers.md#every-answers-cf-cache-status-w4m703)) showed `MISS` for a new path, `HIT` with `age` counting seconds after, `vary: accept-encoding` on every static-site `301`, and `BYPASS` for a path with a query unless the CDN machine already held the path.
- **Plugin:** `httpsRedirect` deletes `Rndr-Id` from every redirect, keeps the sanitizer's `Cf-Ray`, and sets `Cf-Cache-Status` (`DYNAMIC` unless a static site's `301`). `staticSite` with `httpsRedirect` marks a static site's redirect, so a plugin from before reads the spec as a plain redirect.
- **Operator:** `reconcileIngress` writes `staticSiteRedirectSpec` (`httpsRedirect` + `staticSite`) for a static site, live or suspended, and `httpsRedirectSpec` for every other type; `TestAStaticSiteGetsTheStaticSiteRedirect` covers the earlier plain spec on a static site turning into the new one.
- **Either rollout order (step 4), on `traefik:v3.7.17` in Docker:** the plugin as on `main` at `445c2fa740`, given `{httpsRedirect, staticSite}` and `{httpsRedirect, platformFallback}`, still answered `GET`/`HEAD` `301`, `POST` `307` and HTTPS `200` (a scratch test, not committed: Traefik decodes plugin config with mapstructure, which ignores an unknown field). The new plugin with the old spec is `TestHTTPSRedirectOnTheDeployedTraefik/web_service`, which reads `DYNAMIC`.
- **Tests:** `TestHTTPSRedirectAnswersRendersEdgeHeaders`, `TestStaticSiteRedirectReadsTheStoredCopy`, `TestRedirectMemoExpiresAsCloudflareDoes`, `TestRedirectMemoIsBounded` (compiled and under Yaegi v0.16.1), and `TestHTTPSRedirectOnTheDeployedTraefik` for all three specs.
