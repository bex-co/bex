# New-service Source card grows ~95 px when the GitHub connections read settles, pushing the whole form down

Why: the repo rule says a loading preview matches its ready state. On `/services/new` the GitHub tab shows a 96 px `Skeleton h-24` while `GitConnections` loads. A workspace without GitHub then gets the ~190 px "Connect GitHub" card, so every field below Source (Name, Branch, … Instance Type, Project) jumps down.

Severity: minor (layout shift on every create-form visit). Estimate: ~30m. Source: loopx w4 replay of 329, 2026-10-29 UTC (`bex-canary`, pin `4128bfe0ad7f`).

## Evidence

Client navigation `/` → `/services/new?type=web_service`, with the `GitConnections` read held:

| Width | Name label top, pending | Name label top, ready | Shift |
| --- | --- | --- | --- |
| 1440×1000 | 695 | 789 | 94 px |
| 390×844 | 851 | 965 | 114 px |

Pending Source text is only the tab list. Ready adds "Connect GitHub / Connect your GitHub account to deploy from private or public repositories. / Connect GitHub". Apollo batches `InstanceTypes` with `Repos`/`GitConnections`, so a held plan catalog shows the same shift. The plan grid itself does not move (329).

## Fix (2026-10-29)

`ServiceSourcePicker` previews the connect prompt while the connections read is in flight. It is an inert, `aria-busy` box with the same container class (`CONNECT_PROMPT_CLASS`, shared with the ready card), an icon slot, a title line and a body line that wraps to two below `sm`, plus a button slot. Test: "previews the connect prompt's anatomy until the read settles" (`service-source-picker.test.tsx`; it fails without the fix). A workspace with GitHub connected still swaps to the repo list, a different state the preview cannot know in advance. Dashboard `yarn test` (5650), typecheck and lint pass. A live re-measure runs after deploy.
