# A service's Metrics page opens a dashboard shell on the instance it charts, as on Render

Why: Render's changelog of 2025-09-11 ("SSH into a specific instance of a scaled service") opens a dashboard shell on one instance straight from the log explorer and from service metrics. bex does it from a log line only, so a member who spots one hot instance on a chart has to find its slug elsewhere. Found by w4/m553 t002 on 2026-11-22 ([disposition table](../../../docs/render-artifacts/render-changelog.md)).

- **Render:** the entry shows "Opening a dashboard shell session from service metrics" next to the log explorer's. Render's docs ([render.com/docs/ssh](https://render.com/docs/ssh)) say an instance's slug comes from the service's logs and metrics.
- **bex:** the Shell page has an instance picker (`dashboard/src/features/services/components/service-shell-page.tsx`), SSH takes `srv-…-<slug>` hosts ([ADR035](../../../docs/ADR035-ssh.md)), and a log row's menu has SSH into instance (`dashboard/src/features/logs/components/log-row-menu.tsx`). The Metrics page charts one line per instance (`dashboard/src/features/metrics/components/svg-line-chart.tsx`) and links none of them to the Shell.
- **First:** read Render's current dashboard bundle for the metrics entry point (its chart legend or hover card). w4/m552 found a changelog feature Render has since removed. If the entry point is gone, close this note with that evidence.
- **End state:** where Render's metrics offer it, a running instance's series opens the Shell on that instance, on a service whose Shell can open, with the log row's rules for a stopped instance. A dashboard test covers the link and its absence for a stopped instance.
