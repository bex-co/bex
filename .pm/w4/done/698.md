# 698 — Every Logs and Metrics time-range control reads blank on a preset: since w4/619's fix, the trigger renders only a custom window, so the default "Last hour" and every other preset show an empty box

Why: w4/619 was filed because "the page never says which window it is showing". Its fix (`8842ddc56`, via w10/m376 t003) made a custom range state its window, but it also emptied the trigger for every preset. The default state of service Logs and Metrics now names no range at all. Picking a preset changes the URL and the data, but the control stays blank. Render's range pickers show the selected range.

- **Source / severity / estimate:** live `/qa-find-bugs w4` round 579, 2026-11-17 03:58–04:05 UTC, pin `b2704b688742`, workspace `bex-canary`. Read-only on the canary `hello-go` (`srv-dbkq3hdhhjfs73eiahe0`). **Minor:** UX, and the data is right. A regression of w4/619's goal. ~20m.
- **Probe** (headless Chromium at 1440, en):
  - `/services/srv-dbkq3hdhhjfs73eiahe0/logs`: the aria snapshot lists `combobox "Log history range"` with no value, and the trigger's `innerText` is `""`. Opening it lists `Last hour` with `aria-selected="true"`.
  - Picking `Last 4 hours` sets `?range=4h` and the lines change, but the trigger still reads `""`.
  - `/services/srv-dbkq3hdhhjfs73eiahe0/metrics`: `combobox "Time range"` reads `""`.
  - **Control:** on the same pages, `combobox "Log type"` reads `All logs` and the Metrics `Filter events` reads `All events`. Those Selects pass no children to `SelectValue`.
  - Search on the same page works: `?text=healthz` narrows to `GET /healthz` lines, and a nonsense term shows `No matching logs`.
- **Cause:**
  - `dashboard/src/features/metrics/components/range-select.tsx:135-139` passes `{customWindow && (<span …>{customWindow}</span>)}` as `SelectValue`'s children. Without a custom window that child is `false`.
  - `@radix-ui/react-select` (`^2.3.7`) sets `hasChildren = children !== void 0` (`dist/index.mjs:261`). `SelectItemText` portals the selected item's text into the trigger only when `!context.valueNodeHasChildren` (`:986`). `false` counts as children, so no preset label is ever portaled.
  - `8842ddc56` (2026-11-14, w4/619 → w10/m376 t003) introduced it by replacing `<SelectValue />`.
  - The test "shows the window in the trigger, and a preset's name otherwise" (`range-select.test.tsx:362-377`) asserts only that the preset render does not contain `3:39`, never that it reads `Last hour`. It passes on a blank trigger.
- **Fix:**
  - Pass `SelectValue` no children unless a custom window applies, e.g. `{customWindow ? <SelectValue><span …>{customWindow}</span></SelectValue> : <SelectValue />}`.
  - Tighten the test: a `DEFAULT_RANGE_PRESET` render reads `Last hour` (and its zh label), a `4h` render reads `Last 4 hours`, and the custom-window cases keep passing.
- **Blast radius:** `RangeSelect` has three callers, and the fix in the shared component moves all of them:
  - `dashboard/src/features/metrics/components/metrics-filters.tsx:78` (service Metrics);
  - `dashboard/src/features/logs/components/log-filter-bar.tsx:223` (service Logs);
  - `dashboard/src/features/logs/components/datastore-log-viewer.tsx:334` (Postgres and Key Value logs).
- **Unverified:** the datastore log viewer live (my probe did not reach a Key Value Logs view), and the zh trigger text.
- **Render:** Render's Logs and Metrics range pickers show the selected range, e.g. "Last hour".
- **Done when:** on production, a service's Logs and Metrics range controls read `Last hour` on load and `Last 4 hours` after it is picked, and a custom range still reads its window (w4/619's DoD).
