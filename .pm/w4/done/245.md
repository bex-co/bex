# Selected custom time ranges cannot reopen the picker

Why: a customer refining a log or Metrics investigation must switch to a preset and re-enter the custom bounds because the current window has no direct edit action.

**Severity:** minor. **Estimate:** 55m. **Source:** functional `$qa-find-bugs`, 2026-10-10 PDT / 2026-10-11 UTC, pass a129, filed through `/pm add w4` using the requested muse.env login helper. This schedules a dashboard fix; no product implementation is included.

The service Logs page correctly paged 100 + 60 unique lines and matched all 80 alpha lines. ## Root and bounded fix

- `dashboard/src/features/metrics/components/range-select.tsx:85–90,110` controls Select with `value={range.id}` and opens the picker only inside `onValueChange` for the `custom` value. When the range already is custom, selecting that same value cannot reach `openPicker`.
- The actual installed **@radix-ui/react-select 2.2.6** was opened. Its `dist/index.mjs:817–820` calls the value setter and then closes the menu. The package pins **@radix-ui/react-use-controllable-state 1.2.2**; that installed module's `dist/index.mjs:32–37` calls the controlled onChange only when the next value differs from the prop. Closing the menu while suppressing the picker callback predicts the capture exactly.
- `common/components/ui/select.tsx:6–10` forwards Root props unchanged. This is normal Select behavior, not a defect in the global primitive.
- `range-select.tsx:73–80` already knows how to seed the current custom bounds, but that branch is unreachable through this repeated selection. The dialog at :114–122 already supports a controlled open state and defers range changes until Apply.

**Target:** expose a visible, localized **Edit custom range** button when `isCustomRange(range)`, using the existing `openPicker` function. It must work with pointer and keyboard without first applying a preset. Keep the dropdown's normal value-change semantics; do not globally fire Select onChange for unchanged values or add pointer-only item handlers. Opening/Cancel must leave the selected range and query URL untouched. Apply must update only the chosen bounds while preserving the host's existing filters and paused state.

Implement in RangeSelect plus the metrics English/Chinese catalogs. Button is already imported in this file. All three consumers place controls in a wrapping flex toolbar, including `datastore-log-viewer.tsx:193`; verify the added action fits at 390px and 1440px. Preserve current minute-level picker precision and validation, preset selection, loading/error states, history pagination and live-range semantics. No API, serializer, backend or shared Select change is needed.
