## Objective

Keep a group's public name and Environment scope consistent with the metadata mutation that actually commits.

## Context

- `RenameEnvGroup` acquires and releases name claims around an unconditional metadata write.
- `MoveEnvGroup` validates links captured before the metadata commit; the group can change during validation.

## Steps

1. Route rename and scope changes through t001's conditional mutation boundary and validate the current group state.
2. Coordinate name-claim acquisition, metadata commit, and owned-claim compensation so concurrent renames cannot strand a false claim or restore an obsolete name.
3. Revalidate Environment membership on conflicts; update the existing Blueprint/Environment delegation seams to use the same rules.

## Files

- `lego/backend/internal/envgroups/service.go`
- `lego/backend/internal/envgroups/nameclaims.go`
- `lego/backend/internal/envgroups/clone.go`
- `lego/backend/internal/environments/service.go`

## Acceptance criteria

- [ ] Concurrent renames leave one committed name and the correct claim; another group's claim is never removed.
- [ ] Content edits cannot undo a successful rename or scope move.
- [ ] A move racing a new incompatible service link cannot return success with invalid membership.

## Out of scope

- Cross-group or cross-workspace transactional editing.
- New name policies, datastore pickers, or first-party authentication changes.
