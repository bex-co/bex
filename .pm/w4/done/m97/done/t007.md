## Objective

Prove that concurrent metadata/content operations cannot erase a successful change or diverge from App references.

## Context

- Existing patch tests cover content-versus-content CAS and ordinary compensation; this milestone adds cross-operation interleavings.
- Use deterministic barriers and real backing-service drills, not timing sleeps or assertions that only mirror the implementation.

## Steps

1. Add deterministic concurrency coverage for rename/content, competing links, scope/link, delete/delayed writer, and stale pruning/new metadata.
2. Inject failures between group metadata, claims, and App-reference writes and verify the surviving state, public error, and retry/compensation result.
3. Run focused race checks and the backend suite; run required lint/build/codegen and dashboard checks as applicable. Execute and record the dev-4 acceptance drill with fixture cleanup.

## Acceptance criteria

- [ ] New regressions fail against the old unconditional metadata behavior and pass with the fix.
