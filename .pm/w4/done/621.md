# 621 — A Git-built service's config-change and rollback deploys carry an `image` (bex's internal registry path) on REST, GraphQL and the Events tab, where Render omits `image` for every Git-backed deploy

**Absorbed 2026-11-13 into [w10/m373 t004](../../w10/m373/done/t004.md)** (`/pmx them all to w10`, from `/pm-brainstorm for w10`). **Not fixed yet:** the fix and its live DoD ship with that milestone; this note keeps the original evidence.

Why: Render's deploy schema says the `image` object is "Not present for Git-backed deploys". bex returns it on some of a Git service's deploys and not others, so a Render client that branches on `image` reads a Git service as image-backed. The Events tab also prints an internal path a user can neither pull nor use: `tea-…/tea-…-<service>:gen-1@sha256:…`.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 248, 2026-11-13 01:11–01:31 UTC (`muse.env`, workspace `bex-canary`; pin `c328714af1dd`). **Minor** (Render API shape; internal detail on a tenant surface). ~30m.
- **Fixture:** Free Go web service `qa-20261113-r248-rb` (`srv-dbr67g95t55c738j9oeg`). It was created by `POST /v1/services` from `https://github.com/bex-co/bex`, branch `main`, root `examples/hello-go`, with `MESSAGE=r248-v1`. Deleted afterwards (`DELETE` 204, then `GET` 404).
- **Probe** (`GET /v1/services/srv-dbr67g95t55c738j9oeg/deploys/<id>`):

  | Deploy | `trigger` / `bexTrigger` | `image` |
  | --- | --- | --- |
  | `dep-dbr67g95t55c738j9of0`, first build | `other` / `create` | absent |
  | `dep-dbr6a97oj40s73fktb8g`, Environment → Save and deploy | `service_updated` / `config_change` | `{"ref":"tea-daif693dqjvc73e7as3g/tea-daif693dqjvc73e7as3g-qa-20261113-r248-rb:gen-1@sha256:fc3c8761893f…","sha":"sha256:fc3c8761893f…"}` |
  | `dep-dbr6avfoj40s73fktba0`, rollback to the first | `rollback` | the same `image` |
  | `dep-dbr6em95t55c738j9pag`, Manual Deploy → Deploy latest commit | `manual` | absent |

  - The Events tab prints that ref under the "Deploy started" and "Deploy ended" rows of both reused-image deploys. `GET …/events` `deploy_ended.details.image` carries it too.
- **Root cause:** a deploy that reuses a built image stores that image's ref on its row, and every read passes it through.
  - `view` (`lego/backend/internal/deploys/service.go:169-175`): `Image: store.PublicImageRef(d.Image)`.
  - REST: `toRenderDeploy`, `if d.Image != ""` → `image` (`deploys/rest.go:143-145`). GraphQL: `Deploy.image` (`deploys/graphql.go:42`). MCP deploy reads use the same view.
  - Events: `ev.Details.Image = store.PublicImageRef(r.Image)` (`lego/backend/internal/events/service.go:1265`, `:1400`).
  - `PublicImageRef` (`lego/backend/internal/store/image.go:103-115`) strips only the internal registry host. That was w4/m236's choice, made without Render's schema (its Unverified line).
- **Fix (target behavior):** a deploy built from source (it carries a commit) has no `image` on any tenant read: REST, GraphQL, MCP, event `details.image`, the deploy header (`dashboard/src/features/deploys/components/deploy-header.tsx:180-182`) and the Events row (`dashboard/src/routes/services.$serviceId.events.tsx:445`).
  - Omit at the projection seams (`view`, the two event enrichments). The stored row keeps the ref, because rollback runs that exact image (`deploys.Rollback`, w4/m236 t002).
  - An image-backed service's deploys keep `image` byte-identical (the control).
  - Choose the predicate by the deploy's own source: a commit, or the service's repo. A commit-less row of a repo-backed service must not regain `image`. Count the readers first.
- **Blast radius:**
  - 3 projection sites: `deploys/service.go:174`, `events/service.go:1265` and `:1400`.
  - Also check `logs.DeployProgress.Image` (`lego/backend/internal/api/server.go:889`), which feeds the deploy log stream, and `apps/service.go:1176` (`AppView.Image`).
  - The dashboard only displays the field (2 readers above), and no action is gated on it. Grep `deploy.image` and `details?.image` again before changing types.
- **Tests:**
  - A Git service's config-change and rollback deploy reads have no `image` on REST, GraphQL and MCP, and no `details.image` in events.
  - An image-backed deploy keeps both.
  - Rollback still runs the stored image.
- **Unverified:** MCP was reasoned from the shared view, not probed. The deploy log stream's use of the image ref for Git deploys was not checked.
- **Render:** [Retrieve deploy](https://api-docs.render.com/reference/retrieve-deploy), read 2026-11-13: `image` — "Image information used when creating the deploy. Not present for Git-backed deploys".
- **Dedupe:**
  - w4/m236 (done) removed the internal registry host only, and named "omit `image`" as an option.
  - `grep -rlnE "gen-[0-9]+@sha256" .pm` finds only done items.
  - Not deploy lag: `git log c328714af1dd..origin/main -- lego/backend/internal/deploys lego/backend/internal/events lego/backend/internal/store/image.go` is empty.
- **DoD (live):** on a Git-built Free web service, after Environment → Save and deploy and then a rollback:
  - `GET /v1/services/<id>/deploys/<each id>` has no `image` key, and `GET …/events` has no `details.image`;
  - the Events tab shows commit lines only;
  - an image-backed service's deploy still reads its own `image.ref`.
