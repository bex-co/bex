## `dev-4` cannot be brought up on this machine — plan around it

`bash scripts/dev-env.sh 4 status` reports the whole stack down (`dial tcp 127.0.0.1:32770: connect: connection refused`, every HTTP check `000`, and `[FAIL] no default StorageClass`). The prerequisite is the shared kind/CAPD cluster, and that cannot be created here:

```text
$ bash scripts/mock-cluster.sh
ERROR: failed to create cluster: failed to get docker info:
  command "docker info --format '{{json .}}'" failed with error:
  exec: "docker": executable file not found in $PATH
$ echo $?
1
```

**Docker is not installed in this environment**, so `mock-cluster.sh` and therefore every `dev-N` stack are unavailable — not broken, just unbuildable here. The script itself behaves correctly (`set -euo pipefail` at `:9`, exits **1**). Consequently these remain untested after 21 passes, and **cannot** be tested from this harness:

- **Journey 8 — Shell / SSH into a running instance.** Needs a paid plan on prod; the cron-job refusal path was verified in pass 2 ("Shell access requires a running paid web, private, or background service and an active SSH gateway").
- **`w4/m101`'s background-worker half** (`app_controller.go:2294`'s `!worker` exclusion) — prod refuses a free worker outright, which m101 already records with "probe it on `dev-4` instead; do not burn time trying on prod".
- **Journey 10 — private service not publicly reachable**, the security-relevant half.
- **Journey 13's apply half** — `syncBlueprint`, unverified since pass 5 because `examples/` manifests use unprefixed names (`web`, `worker`, `db`) that cannot be namespaced to a `qa-` fixture on production.
- The secret-file **mount** at `/etc/secrets` (pass 18) and env-var delivery to a **Git-built** service, both of which need Shell to read from inside the container.

Whoever picks these up needs either Docker on the host, or a machine where `mock-cluster.sh` already runs.

## A near-miss, recorded because it looked like a repo bug

`mock-cluster.sh` appeared to exit **0** despite printing `ERROR: failed to create cluster`, which would have been a real defect — a bring-up script reporting success with no cluster wastes the next person's afternoon. It was my own measurement: I ran `bash scripts/mock-cluster.sh > log 2>&1; echo "EXIT=$?"; tail -12 log`, and the harness reported the **compound** command's status, which came from the successful `tail`. Run alone the script exits 1. Not filed; noted so the next reader does not re-chase it.
