# 634 — Postgres query insights leave out what Render's API names: `query/sizes` lists no index (Render: "List database, table, and index sizes"), and processes, top queries and table scans drop columns Render documents

Why: Render's Postgres insights endpoints are how a user, the official CLI and agents find the index that bloats a database, or the slow statement's ID and worst case. bex answers with Render's envelopes but a subset of their contents.

- A database with one table and one index reports the table at its total size, including the index, and no index row.
- `processes` cannot say where a connection came from or since when.
- `top-queries` has no `queryId` and no min/max/stddev.

ADR018 marks the row ✅ (`docs/ADR018-render-parity.md:209`).

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 286, 2026-11-13 11:23–11:30 UTC (`muse.env`, workspace `bex-canary`; pin `5de3d5bcce8e`). **Minor** (parity; missing detail, nothing wrong). ~1h.
- **Fixture:** Free Postgres 18 `qa-20261113-r286-pg` (`dpg-dbrf619ens8c73fghhug`), database `qa_r286`, public. Deleted afterwards (`DELETE` 204, then `GET` 404).
- **Probe:**
  - As the database user:

    ```
    create table qa_t(id int);
    insert into qa_t select generate_series(1,5000);
    create index qa_t_id on qa_t(id);
    select count(*) from qa_t where id%7=0;   -- run three times
    ```

    A `pg_sleep(25)` was kept running in another session.
  - `GET /v1/postgres/dpg-dbrf619ens8c73fghhug/query/sizes` →

    ```
    {"sizes":[{"Database":"qa_r286","Bytes":8631999},{"Database":"qa_r286","Schema":"public","Table":"qa_t","Bytes":352256}]}
    ```

    The same session's `pg_class` lists `qa_t | r | 352256` (total) and `qa_t_id | i | 131072`. There is no `Index` row, and the table's `Bytes` already includes the index.
  - `…/query/processes` → `{"pid":315,"username":"qa_r286_extra","applicationName":"psql","state":"active","query":"select pg_sleep(25)","waitEventType":"Timeout","waitEvent":"PgSleep","duration":9}`. It has no `databaseName`, `clientAddr`, `backendStart`, `queryStart` or `isLeader`.
  - `…/query/top-queries` → each row has only `query, calls, totalTimeMs, meanTimeMs, rows, sharedBlocksHit, sharedBlocksRead`. There is no `queryId`, `minTimeMs`, `maxTimeMs`, `stddevTimeMs`, or dirtied, written or local block counts.
  - `…/query/table-scans` → `{"Schema":"public","Table":"qa_t","Scans":6}`, with no `Database`.
- **Render** (pinned OpenAPI `lego/backend/internal/api/openapi/render-public-api-1.json`):
  - `GET /postgres/{id}/query/sizes` is "List database, table, and index sizes". Its item is `{Database, Schema, Table, Index, Bytes}`, "The size of an index, table, or database".
  - `processes` items: `pid, databaseName, username, applicationName, clientAddr, backendStart, queryStart, state, waitEvent, waitEventType, query, duration, isLeader`.
  - `topQueries` items: `queryId, query, calls, totalTimeMs, minTimeMs, maxTimeMs, meanTimeMs, stddevTimeMs, rows`, and the shared/local block counters.
  - `tableScans` items: `{Database, Schema, Table, Scans}`.
- **Root cause** (`lego/backend/internal/postgres/insights.go`, `insights_render.go`):
  - **Sizes:**
    - `sqlTableSizes` (`insights.go:406-414`) reads `pg_tables` with `pg_total_relation_size`, and nothing reads index sizes.
    - `renderSize` (`insights_render.go:66-71`) has no `Index` field.
    - `toRenderSizes` (`:76-83`) emits the database row plus one row per table.
  - **Processes:** `sqlProcesses` (`insights.go:369-380`) selects no `datname`, `client_addr`, `backend_start` or `query_start`. `renderProcess` (`insights_render.go`) has no field for them.
  - **Top queries:** `sqlTopQueries` (`insights.go:385-398`) selects no `queryid`, `min_exec_time`, `max_exec_time`, `stddev_exec_time` or block columns. `renderTopQuery` carries 7 fields.
  - **Table scans:** `renderTableScan` (`insights_render.go:85-89`) has no `Database`. `toRenderTableScans` (`:94`) gets only the rows, so the read must also return `current_database()`.
- **Fix (target behavior):** each REST view carries every column Render's item schema names that PostgreSQL provides for the database.
  - **Sizes:**
    - one row per user index, `{Database, Schema, Table, Index, Bytes}`, from `pg_stat_user_indexes`/`pg_relation_size`;
    - table rows sized without their indexes (`pg_table_size`: heap + TOAST), so the rows add up rather than double-count. Record that choice, since Render's own table measure is unverified;
    - keep the database row and the existing 50-row cap, sorted by size.
  - **Processes:** add `databaseName`, `clientAddr` (empty for a local socket), `backendStart`, `queryStart` (RFC 3339) and `isLeader` (false on a single instance, or the primary's from CNPG where known).
  - **Top queries:** add `queryId` (as a string, per Render), `minTimeMs`, `maxTimeMs`, `stddevTimeMs` and the dirtied, written and local block counters.
  - **Table scans:** add `Database`.
  - **Unchanged:**
    - the `masked`/sensitive gating (w4/m115) and the read-only transaction;
    - the GraphQL/MCP projections and the bare legacy paths keep their views, unless the worker extends them on purpose, since ADR018 says they share data.
  - **Dashboard:** the Insights panel can show the new index rows in Sizes. Its table today lists tables only.
- **Blast radius:**
  - `Sizes` (`insights.go:712`) and the `toRender*` mappers serve REST only. GraphQL `databaseSizes` and MCP `get_postgres_sizes` read `SizesView`, so adding an `Indexes` slice there is additive.
  - The rendertest response validator should now see these fields. Check its allowlist for any entry that masked them.
- **Unverified:**
  - Whether Render's table `Bytes` is total or heap-only.
  - Whether Render's `queryId` is the `pg_stat_statements.queryid` decimal string.
  - The dashboard Insights panel was not opened (the browser was held by another session).

- **Closed 2026-11-14 (/loopx w4):** Each Render insights view now carries every column its pinned item schema names that PostgreSQL provides. `query/sizes` lists one `{Database, Schema, Table, Index, Bytes}` row per user index (`pg_stat_user_indexes` + `pg_relation_size`, the 50 largest), ranked with the tables by size after the database row, and sizes a table without its indexes (`pg_table_size`, heap + TOAST) so the rows add up; recorded in ADR018 that Render's own table measure is unverified. `processes` adds `databaseName`, `clientAddr` (empty over a local socket), `backendStart`/`queryStart` (RFC 3339 UTC) and `isLeader` (true only for a backend on the primary of a database whose HA cluster is active, `status.highAvailabilityEnabled` + `NOT pg_is_in_recovery()`); `top-queries` adds `queryId` (`queryid::text`), min/max/stddev and the shared dirtied/written, local and temp block counters; `table-scans` adds `Database` (`current_database()`). Masking, redaction and the read-only envelope are unchanged. Choice: extended on purpose `SizesView.Indexes` (GraphQL `databaseSizes.indexes`, MCP `get_postgres_sizes`) and the dashboard Insights Sizes table, which lists index rows ("index on …") beside tables, since a table row now excludes its indexes; the legacy bare paths gain the new fields additively. Tests: render views validated against the pinned OpenAPI, mapper unit tests (leader only on an HA primary), real-Postgres integration (index row present, table bytes = `pg_table_size` != total, process timestamps parse, table-scan database), dashboard panel test; `go test ./internal/postgres/` against real deps, dashboard `yarn lint` + `yarn test`.
