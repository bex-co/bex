# A suspended static site answers `404 no static site for host`, as if it had been deleted

Why: since `w2/m98`, a suspended **web service** answers `503` with a bex "This service is suspended" response (HTML, JSON or text by `Accept`, `Retry-After: 3600`). A suspended **static site** on the same platform answers `404` with `no static site for host`, which tells a visitor, a monitor or a search crawler that the site is gone. A `404` also invites crawlers to drop the pages, where `503` + `Retry-After` asks them to come back. The two suspended states should say the same thing.

Found live in `/qa-find-bugs` pass 221 on 2026-09-26 (w4-targeted, `muse.env` credentials) against the deployed `726042a28`, during the `w2/m98` re-probe. The fixtures were static site `srv-dasau9psmc7s73cq5odg` (`qa-20260926-sst`, `bex-co/bex` `examples/static-site`) and web service `srv-dasau98d0qnc73d7a4fg` (`qa-20260926-susp`). Both were suspended with `POST …/suspend` → `202` (`phase: Hibernated`) and later deleted (`DELETE` 204, then `GET` 404).

| Suspended resource, `curl -i -H 'Accept: text/html' https://<slug>.onbex.co/` | Status | Body |
| --- | --- | --- |
| web service `qa-20260926-susp` | `503`, `retry-after: 3600`, `cache-control: no-store` | bex HTML page "Service suspended" ✅ |
| static site `qa-20260926-sst` | **`404`**, `content-type: text/plain`, no `Retry-After` | **`no static site for host`** ❌ |

Both served the valid `*.onbex.co` Let's Encrypt certificate, which is the half `w3/m46` fixed.

## Mechanism

- `w3/done/m46` t001 kept a suspended static site's Ingress and TLS pointed at the static-server. That fixed the certificate. Content was deliberately left to the resolver, which "drops suspended sites, so the static-server serves its ordinary 404" (`.pm/w3/done/m46/README.md:20`; `lego/operator/internal/controller/app_controller.go` `reconcileStaticIngress`). Its DoD allowed either a branded page or corrected dashboard copy, and it closed on the second.
- `w2/m98` routed suspended **web** services to the activator's suspended responder and explicitly left static sites on the `w3/m46` path (`.pm/w2/done/m98/done/t001.md:18,26`). Its why-now line counts the static 404 as a "real response". It is real, but it says the wrong thing.
- In the static server, a host whose site is suspended resolves the same as a host with no site, and both return `no static site for host`.

## Fix

Target: a suspended static site answers exactly as a suspended web service does. That means `503`, `Retry-After`, `cache-control: no-store`, and the same content-negotiated HTML / `{"error":"service suspended"}` / plain-text bodies, over the same certificate. A host with no site at all keeps `404 no static site for host`.

- Either route a suspended static site's Ingress to the activator's suspended responder, as `w2/m98` does for web services, or teach the static-server's resolver to tell "suspended" apart from "unknown host" and render the shared suspended body. Prefer the option that keeps one responder, so the two cannot drift.
- Resume restores the static site's own content.
- Tests: operator or static-server tests for suspended → `503` suspended body, unknown host → `404`, and resumed → the site's content. Extend `w2/m98`'s `suspended_route_test.go` controls, which currently pin the static site to the `w3/m46` backend.

Unverified: what render.com serves for a suspended static site. `w3/m46`'s parity walk recorded Render's suspend behavior only for certificates.

Estimate: ~45m.

## Done (2026-09-27)

**Shape chosen: one responder.** `suspendedRoutable` now covers static sites as well as web services, and the static suspended branch in `reconcileStaticSite` points the host Ingress at the activator alias (keeping the per-host TLS) instead of the static-server. The activator already resolves any App by its hosts and status URL, and answers `spec.suspended` with the `w2/m98` suspended body (`503`, `Retry-After: 3600`, `cache-control: no-store`, HTML/JSON/text by `Accept`) before any wake logic, so the two suspended states share one implementation. With no activator configured, the static-server's 404 over the managed certificate is the fallback. Resume points the Ingress back at the static-server on the next reconcile. The Hibernated condition message drops "serving 404". A host with no site at all is untouched (still the static-server's `404 no static site for host`). Tests: a new envtest case in `app_controller_staticsite_test.go` (suspended → the activator alias with TLS kept and the URL retained, resumed → the static-server alias), the existing no-activator case (still the static-server), and `TestSuspendedStaticSiteGetsTheSuspendedResponse` in the activator (a static App, no Deployment, returns a 503 suspended JSON and is never woken). ADR029's suspend paragraph is updated. Operator `make test` and golangci-lint are green. The live probe (`curl` a suspended static site) is for the next QA pass once deployed.
