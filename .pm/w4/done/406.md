# 406 — The New Web Service form doesn't check the Docker Image field: a malformed or private-registry image is refused by a toast, with nothing marked and Deploy enabled

Why: the image reference is the one required input on the Existing Image path, and its rules can be checked before submit: reference grammar, the 512-byte cap, and no `localhost` or private/link-local registry host. The same form already validates the service name (w4/m19) and the cron schedule (w9/m91) inline. A typo in the image instead costs a submit round trip and leaves only a few-second toast, with no field to fix highlighted.

**Severity:** minor (form polish; the server refuses correctly and nothing is created). **Estimate:** ~30m. **Source:** live `/qa-find-bugs w4` loop run u3f5, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `c5583c80bef9`). Nothing was created (`GET /v1/services?name=qa-20261024-u3f5-ui` → `[]`); session revoked.

## Probe

`/services/new?type=web_service` → **Existing Image** tab, Name `qa-20261024-u3f5-ui`:

| Docker Image             | Deploy Service | `aria-invalid` fields | After clicking Deploy                                        |
| ------------------------ | -------------- | --------------------- | ------------------------------------------------------------ |
| `not a valid ref!!`      | enabled        | none                  | toast "Image reference is malformed: invalid reference format" |
| `localhost:5000/x:1`     | enabled        | none                  | (server answers "image registry host \"localhost\" is private or reserved", the same path) |
| _(empty)_                | disabled       | none                  | n/a                                                           |

Controls on the same form:

- choosing Background Worker, Private Service or Cron Job drops Free from Instance Type and preselects Starter;
- a free-form name such as `Bad Name!!` is accepted, correctly (display names, w5/m153).

## Root cause

- The create form's image field (`dashboard/src/features/services/components/service-source-picker.tsx`, label key `services.createImageLabel`) has only an emptiness check.
- The rules live server-side in `lego/backend/internal/store/image.go:42-79` `ValidateImage`:
  - required, at most 512 bytes;
  - a valid digest suffix;
  - `reference.ParseNormalizedNamed`;
  - the registry host is not `localhost` and not an unsafe IP;
  - the registry is public, or on the trusted list.

## Fix

- Check in the field, before submit, the row-local rules the dashboard can mirror without the registry list:
  - 1–512 bytes;
  - Docker reference grammar (`[registry[:port]/]path[:tag][@sha256:<64 hex>]`, lowercase path);
  - host not `localhost`, not an IP literal in loopback / private / link-local ranges.
- Mark the field `aria-invalid` with an inline message (en + zh) and hold **Deploy Service**, as the name-availability and crontab checks do.
- Leave the public/trusted-registry decision to the server. If the server still refuses, show its message under the field, not only in a toast.
- Apply the same check to the service Settings "Image" edit and to the static/cron/worker variants of the form if they share the field.
- Tests: `not a valid ref!!`, `Nginx:latest` (uppercase path), `localhost:5000/x:1` and `169.254.169.254/x:1` are marked, and Deploy is held. `ghcr.io/traefik/whoami:v1.10` and `nginx@sha256:<64 hex>` pass.

**Settings path, verified (run v7q3, 2026-10-24):** Settings ▸ Source ▸ Edit opens **Update Source**. The **Existing Image** tab with `not a valid ref!!` leaves **Update source** enabled with no `aria-invalid` field. Clicking it gives the same toast-only "Image reference is malformed: invalid reference format". The dialog stays open and the stored image is unchanged (`docker.io/traefik/whoami:v1.10`). So the fix covers the create form and the Update Source dialog together.

**Unverified:** whether Render's create form validates the image inline (not compared live).
