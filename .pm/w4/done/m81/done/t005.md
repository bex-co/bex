## Objective

Every reconciliation/verification tool hard-refuses live keys (`scripts/lib/stripe-billing.sh:5-10`), so after cutover the operator is blind to quantity drift between `usage_hourly` and live Stripe beyond the eight Prometheus alerts. Allow the **read-only** paths of `stripe-billing-reconcile.sh` to run under a live key behind an explicit flag, keeping every mutating path refused.

## Context

- `stripe-billing-reconcile.sh` subcommands: `report` (compares local sealed quantities vs Stripe meter-event sums; read-only), `issues` (lists `billing_export_issues`; read-only), `repair TRANSACTION_ID` (re-emits; **mutating**).
- The blanket refusal was a w7/m53 safety fence for the prod-hosted *test* acceptance — appropriate then, an observability hole after graduation.
- Existing key-hygiene rules to preserve: key read from env/history-disabled shell, never passed on argv, never printed (runbook §5:181-191).

## Steps

1. In `scripts/lib/stripe-billing.sh`, replace the unconditional live refusal with: live keys permitted only when `BEX_STRIPE_ALLOW_LIVE=1` **and** the invoking script declares itself read-only; export a helper the scripts call with their mode.
2. `stripe-billing-reconcile.sh`: declare `report`/`issues` read-only; `repair` keeps the unconditional live refusal (add a TODO pointing at a future guarded live-repair decision).
3. `stripe-billing-verify.sh` and `stripe-billing-prod-test-fixtures.sh` keep their unconditional refusals (they create fixtures/charges — never live).
4. Hand t006 the §6 post-cutover verification step: run `report` under the flag during the staffed window and on a cadence after.

## Files

- `scripts/lib/stripe-billing.sh`
- `scripts/stripe-billing-reconcile.sh`

## Acceptance criteria

- [ ] `report`/`issues` proceed with a live-shaped key + `BEX_STRIPE_ALLOW_LIVE=1`; without the flag they refuse exactly as today.
- [ ] `repair` refuses a live key regardless of flags.
- [ ] Fixtures/verify scripts' refusals unchanged.
- [ ] No key material in argv or output in any path.

## Out of scope

- A guarded live `repair` path (needs its own decision — misfired re-emission bills real money).
- New drift alerting (the 8 PrometheusRules already cover the push side).
