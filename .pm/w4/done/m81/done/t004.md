## Objective

Creating the webhook endpoint is the only Stripe object provisioning still done entirely by hand — `stripe-billing-setup.py` never touches `webhook_endpoints`, and runbook §6 just says "create the live endpoint with the same permissions/version/events." A wrong API version, missing event, or wrong URL is a silent cutover failure (signature-valid events rejected or never delivered). Script it with the same drift-refusing idempotency the catalog already has.

## Context

- Required shape (runbook §3:89-103): URL `https://api.bex.co/v1/webhooks/stripe`, API version pinned to `2026-06-24.dahlia` (stripe-go v86), exactly ten events: `checkout.session.completed`, `invoice.payment_failed`, `invoice.payment_action_required`, `invoice.payment_succeeded`, `invoice.paid`, `customer.subscription.{created,updated,deleted,paused,resumed}`.
- Pattern to follow: `ensure_price` (`stripe-billing-setup.py:185-229`) — find existing, verify compatibility, hard-error on drift (`:196`), create only when absent; `--live` global args thread mode.
- The endpoint's `whsec_*` is only returned at creation; it must never appear in argv or logs (the script's existing secret hygiene: mode-0600 temp files, cf. `stripe-billing-secret.sh:178-205`).

## Steps

1. Add `ensure_webhook_endpoint(url)` gated behind a new `--webhook-url` flag: list endpoints, match by URL + mode; verify api_version and the exact event set; drift → `RuntimeError`; absent → create with the pinned version + ten events.
2. On creation, write the returned `whsec_*` to a mode-0600 file (path printed, secret never echoed) and instruct feeding it to `stripe-billing-secret.sh` as `BEX_STRIPE_WEBHOOK_SECRET`.
3. Second run must report `exists` (idempotency, consistent with the §6 double-run discipline).
4. Hand t006 the §6/§3 wording: live endpoint creation is now `--live --webhook-url …`, not a manual Dashboard step.

## Files

- `scripts/stripe-billing-setup.py`

## Acceptance criteria

- [ ] Double run against test mode: first creates (or verifies) the endpoint, second reports `exists`, exit 0.
- [ ] A deliberately drifted endpoint (extra/missing event or wrong version) → non-zero exit with the diff named.
- [ ] The `whsec_*` never appears in stdout, stderr, or argv; the 0600 file path is printed instead.

## Out of scope

- Rotating/deleting old endpoints (incident procedure stays runbook §7).
- The edge/Traefik routing of `/v1/webhooks/stripe` (already live).
