## Objective

Runbook §6's documented `--live` invocations omit `--dashboard-url`, so no live scoped portal configuration (`bpc_*`) is ever created, and nothing requires `BEX_STRIPE_PORTAL_CONFIGURATION_ID` in the live Secret. Without it, live portal sessions fall back to the Stripe account's default configuration (`billing/sessions.go:177-179`) — which either errors (no default activated) or **allows subscription cancellation/plan changes**, breaking the one-subscription-per-workspace invariant the scoped config exists to protect (`stripe-billing-setup.py:296-297` sets `subscription_cancel=false`, `subscription_update=false`). Close the gap at the installer layer.

## Context

- The prod test-mode Secret already omits `BEX_STRIPE_PORTAL_CONFIGURATION_ID` (observed live 2026-08-15) — tolerable in test, invariant-breaking in live.
- `stripe-billing-secret.sh:134-139` validates `bpc_*` format when set but treats the var as fully optional in every mode.
- `findSubscriptionObject` fail-closes on multiple subscriptions (`sessions.go:344-351`) — a customer-initiated cancel/resubscribe through an unscoped portal is exactly how that state arises.

## Steps

1. In `stripe-billing-secret.sh`, when the key classifies as `live`, refuse to proceed if `BEX_STRIPE_PORTAL_CONFIGURATION_ID` is unset (clear error naming the `--live --dashboard-url` provisioning step). Test mode stays optional.
2. Hand t006 the §6 amendments: run `python3 scripts/stripe-billing-setup.py --live --dashboard-url https://dashboard.bex.co`, capture the emitted `bpc_*`, and set it in the live `.env` before running the installer.
