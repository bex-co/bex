## Objective

Live mode today can invoice but cannot enforce non-payment: `BEX_STRIPE_DUNNING_ENABLED=1` with an `rk_live_*` key is refused by the secret installer and is a fatal startup error in the binary, so `OnLifecycle` stays nil and all nine invoice/subscription lifecycle webhook events are verified, 204'd, and dropped. A live customer whose card fails would never be put in grace or enforced. Remove the w7/m52 scope fence so the shipped dunning state machine runs under a live key as a deliberate opt-in.

## Context

- The two fences: `scripts/stripe-billing-secret.sh:93-96` ("Stripe dunning is test-mode only at w7/m52") and `lego/backend/cmd/api/main.go:831-834` (`log.Fatalf` on live+dunning). Wiring skipped at `main.go:845-847` when lifecycle is nil.
- The dunning code itself (grace → enforcement → recovery, reversible) shipped and was prod-test-verified in w7/m52 + w7/m53 — the fence was milestone scoping, not a technical limitation.
- The eight `bex_billing_*` PrometheusRule alerts (`deploy/gitops/base/prometheus.yaml:777-873`) key on `bex_billing_enabled == 1` and work identically in live mode.
- Mode-mismatch protection is independent of this fence: the webhook handler rejects events whose `livemode` differs from the runtime key's (`billing/webhook.go:71-75`).

## Steps

1. Remove the live refusal in `stripe-billing-secret.sh` (keep `BEX_STRIPE_ALLOW_LIVE=1` as the sole live gate; dunning stays opt-in via `BEX_STRIPE_DUNNING_ENABLED`). Update its comment to record that live dunning is now an operator choice.
2. Remove the `log.Fatalf` fence in `cmd/api/main.go`; keep the existing grace-period/reconcile-interval validation.
3. Add/adjust a config-level test asserting a live-shaped key + dunning enabled boots and wires `OnLifecycle` (and that test-mode behavior is unchanged).
4. Hand t006 the runbook §6 step-4 rewording: the operator explicitly decides dunning on/off at cutover; both are supported.
