## Objective

`payment_method_bound_at` on `billing_provider_mappings` survives a test→live key flip while everything else self-heals from live Stripe, silently reopening the ADR046 paid-intent gate and the usage-export gate for workspaces that have **no live card on file**. Make the marker mode-consistent at the store layer and give the cutover a documented one-time reset.

## Context

- Root cause: `UpsertBillingProviderMapping` (`lego/backend/internal/store/billing_lifecycle.go:130-141`) updates `customer_id`/`subscription_id`/`livemode` on conflict but never touches `payment_method_bound_at` — so a live-mode `EnsureCustomer` self-corrects the row to `livemode=true` yet keeps the test-stamped marker.
- Readers are mode-agnostic: `PaymentGate.RequirePaymentMethod` → `PaymentEligibility` (`billing/payment_gate.go:39-51`, `store/billing.go:72-88`) and the emitter outbox `SelectUnemittedUsage` (`store/billing.go:92-108`).
- The row already carries `livemode boolean NOT NULL` (migration `0051_stripe_billing_lifecycle.up.sql`); the marker column came from `0058_payment_method_bound.up.sql`. Writer: `SetPaymentMethodBound` (`store/billing.go:44-56`), reached only via the verified `checkout.session.completed` webhook (`billing/sessions.go:212`).
- The GraphQL readiness surface self-heals (live Stripe customer search, `billing/sessions.go:57-86`, `stripe.go:207-232`) — only this local marker does not. That asymmetry is the bug.

## Steps

1. In `UpsertBillingProviderMapping`'s `ON CONFLICT` clause, null the marker when the incoming `livemode` differs from the stored one (e.g. `payment_method_bound_at = CASE WHEN billing_provider_mappings.livemode <> EXCLUDED.livemode THEN NULL ELSE billing_provider_mappings.payment_method_bound_at END`). Leave `SetPaymentMethodBound`'s monotonic `COALESCE` semantics unchanged.
2. Add a PG regression test following `TestPGStorePaymentMarkerWithholdsThenBackfillsSealedUsage` (`store/billing_pg_test.go:297`): bind the marker under `livemode=false`, upsert the same workspace with `livemode=true`, assert the marker is cleared, `PaymentEligibility` no longer allows paid intent, and `SelectUnemittedUsage` withholds the workspace's rows.
3. Draft the one-time cutover reset for t006 to land in the runbook: `UPDATE billing_provider_mappings SET payment_method_bound_at = NULL WHERE livemode = false;` executed in the staffed window **before** the live secret rollout (belt-and-braces alongside the upsert clear).
