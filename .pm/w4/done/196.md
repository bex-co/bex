# w4/196 — `server_failed` / `server_available` are stamped when the reconciler notices, not when the service went down or came back, so the event feed understates outages ~3×

Why: the service Events feed (and every webhook and notification built from it) is what users read to learn how long they were down. Today an outage users experienced as ~45 s of 503s reads as a 13-second blip, because both edges carry the observation time after a two-tick debounce instead of the Ready transition time the reconciler already has.

Live 2026-10-04 UTC (`/qa-find-bugs` loop18, muse.env, `bex-canary`). Owned Free image service `qa-20261004-l18-hc` (`srv-db1g8hdmc5jc739qbrlg`, `traefik/whoami`, health check path `/health`; deleted to 404). At 02:00:36Z `POST /health` with body `500` made whoami's health endpoint fail; `curl` every ~10 s from outside:

- 02:00:46 and 02:00:57: root 200, health 500.
- **02:01:08 → 02:01:42: root 503, health 503** (readiness failed, traffic removed).
- **02:01:53 onward: 200/200.** The instance restarted (whoami's in-memory health reset to 200), in line with the Settings copy "60 seconds of consecutive failures restarts the instance".

`GET /v1/services/<id>/events` (and the dashboard Events tab, `.playwright-mcp/qa-health-events-timing-1.png`):

- `02:01:46 server_failed {"reasonCode":"readiness_failed"}`, which is **38 s after** the first observed 503.
- `02:01:59 server_available`, which is **6 s after** the observed recovery.
- So the feed shows a 13 s outage against ~45 s observed. It also records no restart, even though one occurred.

Root cause:

- `lego/backend/internal/store/reconciler.go:1624-1627` `observedServiceStateFor` sets `At: time.Now().UTC()` for each pass. It also fills `ReadyTransitionAt` from the Ready condition's `LastTransitionTime` (`:1648`, `:1683`).
- `reconciler.go:430` passes the observation through `debounceUnhealthy` (`:283-291`). This deliberately suppresses the first unhealthy pass, so the edge is emitted on the second.
- `internal/store/event_facts.go:451-454` then mints the edge fact with `At: obs.At`, the emitting pass's wall clock. Emission lag (operator status write, the reconciler poll, one debounce tick) therefore lands in the event's timestamp.

Fix: keep the debounce (it is the anti-flap guard), but stamp availability edges with `obs.ReadyTransitionAt` when it is non-zero and not after `obs.At`. Fall back to `obs.At` otherwise. The SourceKey stays unique (it can include both).

- Check: `rejectStaleUnhealthy` already orders on `ReadyTransitionAt`, so the ordering guard is unchanged.
- Datastore observations share the shape (`internal/store/datastore_observations.go:244`); apply the same rule there.
- Tests: an unhealthy edge emitted on the second pass carries the first transition time, and a healthy edge carries its transition time.

Unverified:

- How much of the 38 s is the operator's own Ready flip versus reconciler lag. Production `LastTransitionTime` was not read. The fix only helps by the part after the flip, so measure it in the replay.
- Whether a health-check-driven container restart should also emit an event (Render documents `server_failed`/`server_available`; restart events are user-initiated there).

Severity: minor (truthfulness of incident timing). Estimate: ~45m.

Done 2026-10-04 (loopx):
- **Fix.** Availability edges (`server_failed`/`server_available`, plus the datastore unavailable/available twins) are stamped by `availabilityEdgeAt` in `internal/store/event_facts.go`. The edge takes the operator's Ready transition (`ReadyTransitionAt`) when that is after the checkpoint's last change (`updated_at`, the state the edge leaves) and not after the observation. Otherwise it keeps the observation time. The debounce, the stale-unhealthy guard and the source keys are unchanged.
- **Why the lower bound.** Ready's `LastTransitionTime` only moves on status flips, so a Serving-backed healthy conclusion could otherwise let a later failed edge predate it.
- **Delivery checked.** Backdated `at` values are safe for delivery: the webhook and push feed pages by `recorded_at`, and `service_event_index` is filled by insert triggers.
- **Tests (real PG 17).** `TestPGAvailabilityEdgesCarryTheReadyTransitionTime` and its datastore twin replay the live timeline: the failed edge sits at the :68 flip, not the :106 debounced pass, and the available edge at the :113 flip. Stale and future transitions fall back to the observation time. The fake store now tracks a changed-at like PG's `updated_at`.
- **Checks.** Backend suite and `make lint` are green. The four `TestPGGitWebhookReplay*` tests fail only when re-run on a reused database (fixed epoch names); they pass on a fresh one.
- **Not done.** The restart-event question stays open, as noted in Unverified. No live replay was run.
