## Objective

Show a Docker Command field in the New Service wizard when the Existing Image tab is selected (non-cron types) and send it as `startCommand` on create.

## Context

- Today every command field is gated under `shape.isGitSource` (`dashboard/src/routes/services.new.tsx:220`), and `buildCreateServiceInput` forces `startCommand: undefined` for the image source (`dashboard/src/features/services/lib/create-service-input.ts:196-200`). Cron already sends `command` for image crons (`create-service-input.ts:209`) — extend the same idea to `startCommand` for web/private/worker.
- Backend accepts it: create projects `req.StartCommand` onto the spec unconditionally (`lego/backend/internal/apps/service.go:2701`), and `startCommand` is deliberately absent from the image-forbidden field list (`lego/backend/internal/apps/blueprint_compiler.go:339-348`). The operator applies `spec.startCommand` to any non-native/non-buildpack container (`lego/operator/internal/controller/deployment_projection.go:228`).
- Render's image-service create has a Docker Command override — this is the parity field.

## Steps

1. Add an optional Docker Command text field to the wizard's image-source settings block for non-cron, non-static types (reuse the `createFieldDockerCommand` label/copy used for docker builds).
2. Wire it through `buildCreateServiceInput` so an image create sends `startCommand` (blank stays omitted via the existing `set()` helper).
3. Keep the submit gate unchanged: the field is optional, so `isSubmittable` needs no new requirement.
