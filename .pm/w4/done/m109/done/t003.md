## Objective

Both of this milestone's defects passed every gate because the project conformance suite checks that the right **keys** are present, never that they hold meaningful **values**. Close that hole so a normalized-but-wrong field cannot ship green again.

## Context

`w6/m126` added `TestProjectResponsesConformToRenderSchema` and `TestProjectWriteResponsesMatchReadShape` in `lego/backend/internal/api`, and its own definition of done is written entirely in terms of key sets: _"returns a body containing `owner`, `environmentIds` and `updatedAt`, and containing none of `ownerId`, `serviceIds`…"_ and _"the key sets of POST and GET for the same project are identical"_.

That is exactly satisfied by `owner: {"id": "…", "name": "", "email": "", "type": "team"}` and by `updatedAt` being a copy of `createdAt` — which is why m126's own source capture quotes both wrong values without flagging them, and why they survived a milestone whose whole purpose was this file.

This task is the generalizable half of the milestone: the two field fixes are five lines, the reason they were invisible is worth more.

## Steps

1. Extend the project conformance tests so that, for a fixture whose owner is resolvable, `owner.name` and `owner.email` must be non-empty and must equal the fixture owner's values — not merely be strings.
2. Add a mutation-ordering assertion: render a project, mutate it, render again, and require `updatedAt` to have advanced. This is the assertion that would have caught `t001`, and it cannot be satisfied by a hardcoded copy.
3. Demonstrate the guard: revert each fix in turn and watch `cd lego/backend && go test ./internal/api/...` go red, the way `w6/m126` t003 demonstrated its own. Record the two failure messages in the task result — a guard nobody has seen fail is not known to work.
4. Look for the same value-blind pattern in the sibling conformance suites (services, postgres, key-value). They happen to be correct today; assert it, so they stay correct for a reason rather than by luck.
5. If a general helper falls out (assert a rendered resource's owner block is fully populated), put it where all four families can use it.

## Files

- `lego/backend/internal/projects/rest_test.go`

## Acceptance criteria

- [ ] A project response whose `owner.name` is `""` fails the suite.
- [ ] A project whose `updatedAt` does not advance after a mutation fails the suite.
- [ ] Both failures are demonstrated by reverting the fixes, and the messages are recorded.
- [ ] The sibling families' owner blocks are asserted non-empty too.

## Out of scope
