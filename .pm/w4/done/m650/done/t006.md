## Objective

Show that the autodeploy rule still matches Render's: a push that changes only a file outside the Root Directory deploys only when a build filter includes it, and that deploy's build reads the changed file.

## Context

- On production, in workspace `bex` with a temporary bex-co repository, as w7/m428 t004 did: `bex-canary` has no Git connection, so a push never reaches a service there. Delete the repository and the service afterwards.

- Render: "changes to those files don't trigger an autodeploy. To redeploy when files outside the root directory change, add their paths to your service's build filters" (monorepo-support, 2026-11-25).
- Build Filters ledger row: `docs/ADR018/services-lifecycle.md:30` (w7/m428).

## Steps

1. On t005's Node service, push a change to `packages/ui` only, with no build filter: no deploy starts.
2. Add `packages/ui/**` to the service's included paths, push another change there: a deploy starts and the served page shows the change.
