## m126 — the protected-environment guard covers the verbs that redefine a running service

Rig: project `qa-20260922-prot` → environment `qa-prod` (`protectedStatus: protected`) → private service `qa-20260922-pe`. All deleted.

```
setImage(no confirm)  → REFUSED: … retry with confirm="sudo repoint service qa-20260922-pe" to repoint it
setImage(with phrase) → ACCEPTED; imagePath becomes mendhak/http-https-echo:35
suspend control       → still REFUSED
```

The refusal wrote nothing — after it, `imagePath` was still `:latest` at `rev-1`. `setImage` now carries a `confirm` argument, so the phrase is expressible on the surface, which was the half of the DoD that a guard alone would not satisfy.

## m127 — a protected datastore is protected against the data plane too

Rig: free database `qa-20260922-db` + free key value `qa-20260922-kv` in the same protected environment. All deleted.

| probe                                          | result                                             |
| ---------------------------------------------- | -------------------------------------------------- |
| `executeDatabaseQuery` `CREATE TABLE` `allowWrites:true` | REFUSED — `sudo write to database qa-20260922-db` |
| `executeDatabaseQuery` `DROP TABLE` `allowWrites:true`   | REFUSED — same phrase                    |
| `executeDatabaseQuery` `allowWrites:false`     | **ACCEPTED** — the read path is correctly exempt   |
| `executeDatabaseQuery` + the phrase            | **ACCEPTED** — the confirm proceeds                |
| `setKeyValuePersistenceMode("off")`            | REFUSED — `sudo change durability of key value qa-20260922-kv` |
| `setKeyValueMaxmemoryPolicy(allkeys_lru)`      | REFUSED — `sudo change eviction on key value qa-20260922-kv` |
| `failoverDatabase`                             | REFUSED — `sudo fail over database qa-20260922-db` |
| `renameDatabase`                               | REFUSED — `sudo rename database qa-20260922-db`    |
| suspend DB / suspend KV (controls)             | REFUSED, unchanged                                 |

Both halves that matter are right: the write path is guarded and the **read-only** path is not, which was explicit in `m127/t003`'s acceptance criteria and is the easy thing to get wrong by guarding the verb instead of the effect. The phrase wording is per-verb rather than one generic sentence.

Teardown doubled as the last control: every delete had to carry its own phrase (`sudo delete database …`, `sudo delete key value …`, `sudo delete service …`) and was refused without it, so the guard was demonstrably armed for the whole window the fixtures existed. The workspace is back to its baseline of 5 services / 3 databases / 2 key values / 3 projects / 0 environments.
