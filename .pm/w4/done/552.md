# 552 — In the zh dashboard, a paused plan's reason (Pro Ultra, Key Value 50 GB) is an English sentence from the API, shown as its tooltip and screen-reader text

Why: the zh dashboard is otherwise fully translated on these pages. The one sentence explaining why a plan can't be chosen arrives in English, both in the hover tooltip and read aloud by screen readers.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 29, 2026-11-10 16:38–16:55 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor** (i18n gap). ~25m.
- **Probe:** with `?lang=zh`, I scanned 15 hosting pages for untranslated text nodes and for English `aria-label`/`placeholder` values:
  - `/`, `/services/new`;
  - a service's overview, settings, env, deploys, logs, metrics, scaling and shell pages;
  - `/env-groups`, `/billing`, `/webhooks/new`, `/keyvalue/new`, `/blueprints`.
- **Result:** everything was Chinese except user content (commit messages) and these strings:
  - `/services/new` → `"Pro Ultra" is temporarily unavailable; choose Pro Max or a smaller instance type.`
  - `/keyvalue/new` → `Key Value plan "Pro Ultra" is temporarily unavailable; choose Pro Max or a smaller plan.` and `Key Value plan "50 GB" is temporarily unavailable; choose Pro Max or a smaller plan.`
  - The visible card label itself is the localized `common.planUnavailable`.
- **Root cause:**
  - The sentence is composed server-side, in English only:
    - `pausedTierMessage` (`lego/backend/internal/apps/service.go:3835-3842`), exposed as GraphQL `InstanceType.unavailableReason` (`apps/graphql.go:658`);
    - `pausedPlanMessage` (`lego/backend/internal/keyvalue/tiers.go:57-63`), exposed as GraphQL `KeyValueInstanceType.unavailableReason` (`keyvalue/graphql.go:81`).
  - The dashboard renders that string verbatim in two components:
    - `PlanCardGrid` (`dashboard/src/common/components/plan-card-grid.tsx`): `title` at `:77`, sr-only span at `:93-94`. It is used by `routes/services.new.tsx`, `routes/keyvalue.new.tsx`, `database-plan-section.tsx` and `key-value-plan-section.tsx`.
    - `InstanceTypePicker` (`features/services/components/instance-type-picker.tsx`): `title` at `:230`, sr-only at `:249-251`.
- **Fix (target behavior):**
  - The dashboard composes the reason in the active language from data it already has: the tier's own name and the largest available tier in the same list.
  - Add en and zh keys, e.g. zh "{name} 暂不可用，请选择 {largest} 或更小的规格。"
  - Use the composed text for both the `title` and the screen-reader text, in both components. The dashboard stops reading `unavailableReason`.
  - No backend change: the API keeps its English `unavailableReason` for REST, MCP and GraphQL clients.
- **Blast radius:** the two components above (`PlanCardGrid` has 4 callers). No shared backend change. Add a zh render test for each component.
- **Unverified:**
  - Postgres plan cards: no paused Postgres tier was listed on `/?new=database` this round.
  - Any other backend-sourced English sentence rendered verbatim elsewhere. Deploy failure reasons and status reasons are log-like and out of scope.
- **Dedupe:**
  - `grep unavailableReason .pm` finds w2/m250, which is blocked on Hetzner capacity; it added the field and the "Unavailable" label but not localized reasons.
  - It also finds w5/m129/t002, which covers status reasons, not this string.
  - No item covers the language of this string.
  - Not deploy lag: `git log c12cd57facb1..origin/main` on both components is empty.
- **DoD (live):**
  - With `?lang=zh` on `/services/new` and `/keyvalue/new`, the paused cards' `title` and screen-reader text are Chinese and name the largest available tier.
  - In en, they read as they do today.
  - REST and GraphQL `unavailableReason` are unchanged.

- **2026-11-11 (loopx w4):** fixed: the instance-type and Key Value catalogs compose each paused tier's reason in the dashboard's language (`withPausedReasons`, `services.instanceTypePausedReason` / `keyvalue.planPausedReason`), naming the largest tier still offered as bex-api does; en reads exactly as bex-api's sentence, zh e.g. "“Pro Ultra”暂不可用，请选择 Pro Max 或更小的实例类型。". `PlanCardGrid` and `InstanceTypePicker` show it as the title and screen-reader text. bex-api's `unavailableReason` is unchanged and still used when no tier is left to suggest. Hook tests cover en, zh and the fallback.
