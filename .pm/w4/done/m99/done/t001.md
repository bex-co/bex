## Root cause and proposed fix

Pinned `cmd/servicecreate.go` declares `--auto-deploy`; `pkg/service/create.go:87-92` converts explicit false to `autoDeploy:"no"`. The backend `apps/rest.go:522-556` parses it into a non-nil false pointer; `apps/service.go:2388-2392` walks `prebuiltImageSourceFields`; `apps/blueprint_compiler.go:286` rejects any non-nil AutoDeploy, including false. The consumer receives the server's 400 and exits before creating a service. `apps/blueprint_plan_test.go:40` explicitly tests false as incompatible: change this characterization deliberately, not by deleting validation coverage.

Allow the disabled value in direct create validation and serialize it consistently as no/off. Keep explicit enablement and Git-only source/build fields rejected for an image. Decide and document the corresponding Blueprint `autoDeploy:false` / `autoDeployTrigger:off` policy in t003/t004; do not accidentally change it by weakening the entire shared registry. `checksPass` stays unsupported. PATCH/source-switch behavior must retain existing semantics.
