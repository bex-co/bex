## Objective

Stop presenting Stripe's subscription-period amount as "Total month to date" above a calendar-month tree. Name each figure's window, and either compute the tree over the rated window or say beside each figure what it covers.

## Context

- `dashboard/src/features/usage/components/charges-card.tsx:286-300` (total selection), `:396-398` (label), `:297-299` (the "tree explains it" claim).
- `usage-page.tsx:134-136` passes `currentCost.periodStart/periodEnd`. The window is already known client-side (`billingWindow`, used for the projection since `w6/050`).
- Filing values: headline $75.30 over 2026-09-16 → 10-16. Tree $292.85 over Sep 1–25.
- Option A (tree over the rated window) needs a backend window parameter on `estimatedCost`. Option B (disclose windows) is dashboard-only. Record the choice and why.

## Acceptance criteria

- [ ] The headline label names its window whenever the rated figure is shown. "Month to date" appears only for a calendar-month figure.
- [ ] A reader can see why the headline and tree differ, or they no longer differ beyond rounding.
- [ ] en + zh strings (`locale-parity.test.ts`).

## Result (2026-09-26)

**Option B (disclose windows), dashboard-only.** Option A (the tree over the rated window) would need a window parameter on `estimatedCost` and would still diverge whenever the subscription period spans two months, while the tree is the calendar-month view the period picker navigates by. So `charges-card.tsx` now labels a rated headline **"Total this billing period (Sep 16 – Oct 16)"** (UTC-formatted from `currentCost.periodStart/End`), adds a row **"Breakdown above: September to date"** with the tree's own sum under a rated headline, and keeps "Total month to date" only for the calendar-month estimate. It also no longer shows the current period's Stripe figure over a **past** month's tree (another window mismatch found while fixing this). en + zh.
