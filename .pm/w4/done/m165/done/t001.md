## Objective

Switching workspace via the dashboard switcher while on a workspace-scoped resource route navigates to the new workspace overview instead of showing stale cross-workspace content.

## Context

- Root cause at HEAD 0269ab5fc: `dashboard/src/features/workspaces/components/workspace-switcher.tsx:116` (`onSelect` only calls `setCurrentWorkspaceId`, no navigate) and `dashboard/src/features/workspaces/context/index.tsx:85-93` (`setCurrentWorkspaceId` persists/bumps/invalidates, navigates only on empty at 60-64).
- `setCurrentWorkspaceId` has 7 non-test callers (switcher, env-group-actions clone, delete-workspace fallback, leave-workspace fallback, invite-redemption, `w.$` route, new.workspace) — scope the navigate to the switcher path so the other six flows keep their own navigation.
- Backend by-ID reads (projects Get, environments List via `requireProject` against the resource tenant) are membership-scoped and correct — do not change backend authz.
- Evidence: `.playwright-mcp/qa-workspace-switch-stale-1.png`.
- Repro: bex workspace open /project/prj-..., switch to tian-personal, breadcrumbs degrade to prj- ID while main shows stale bex project+env.
- Target: after switch URL is / with new workspace content, never a cross-workspace resource view.
