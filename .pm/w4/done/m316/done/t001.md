## Objective

Make the Maxmemory Policy card behave like the plan card w4/m263 shipped.

- On a running Persistence Off store, Save opens a destructive confirmation that names the data loss and requires `sudo clear key value <name>`.
- On a persisted store, Save opens a restart-only confirmation.
- Cancel sends nothing.

## Context

- The card saves directly through `EditableFieldRow` with no `confirm` (`dashboard/src/features/keyvalue/components/key-value-maxmemory-policy-section.tsx:69-77`). The mutation hook is `useSetKeyValueMaxmemoryPolicy`.
- The card copy is `keyvalue.maxmemoryDescription` (`features/keyvalue/locales/en.ts:589`).
- Patterns to reuse:
  - the plan section's Off-aware confirmation and `keyvalue.planPickerConfirmDataLoss` (`en.ts:562-567`, w4/m263);
  - the persistence section's typed phrase (`key-value-persistence-mode-section.tsx:131`);
  - the shared `ProtectedConfirmationDialog`.
- A suspended store has no process to restart, so it gets no prompt. This is the same rule m263 used.

## Steps

1. Read the store's persistence mode and suspension state in the section.
2. Gate Save through a confirmation:
   - typed phrase when running with Persistence Off;
   - restart-only when persisted;
   - none when suspended.
3. Update the card copy in en and zh: the restart and outage, and that data survives according to the persistence mode while Off loses every key.
4. Keep the pending skeleton's geometry unchanged.

## Result (2026-11-11)

- `KeyValueMaxmemoryPolicySection` (`dashboard/src/features/keyvalue/components/key-value-maxmemory-policy-section.tsx`) no longer saves straight from the row. Save opens a `ConfirmDialog`: "Change the maxmemory policy to {policy}?" with the restart copy. On a running store whose persistence mode is not a known persisted mode it is destructive, adds "Persistence is Off, so the restart deletes every key in {name}…" (or, for an unread mode, "This store's persistence mode is unknown. If it is Off, …") and keeps its button disabled until `sudo clear key value <name>` is typed. A suspended store saves without asking. Cancel sends nothing; the row stays in edit mode with the draft.
- The persistence mode comes from the same cache-shared `useSetKeyValuePersistenceMode` read the plan and persistence cards use; the route passes `name` and `suspended`.
- Card copy (`keyvalue.maxmemoryDescription`, en and zh) now says data survives according to the persistence mode and Off loses every key. The pending skeleton (`datastore-overview-previews.tsx`) renders the same key, so it matches.
- Shared helpers in `features/keyvalue/lib/labels.ts`: `persistenceKeepsData(mode)` and `keyValueClearPhrase(name)`, now used by the plan, persistence and maxmemory cards. `keyvalue.planPickerConfirmDataLoss` became the neutral `keyvalue.restartConfirmDataLoss`, used by both restart confirmations.
