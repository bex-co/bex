# New Postgres clips its fields and plan prices on narrow mobile screens

Why: the default plan label forces the creation dialog wider internally than the viewport, hiding the right side of inputs and the Public access switch; the plan menu also extends offscreen.

**Severity:** minor. **Estimate:** 55m (10m blast-radius audit, 25m scoped layout fix, 20m browser regression/parity checks). `/qa-find-bugs` sweep 76, 2026-10-03 local / 2026-10-04 UTC, muse profile. This files work only; no product code changed.

## Reproduce and observable target

1. At `https://dashboard.bex.co/?new=database`, set the browser viewport to **360×800** and wait for the default Free plan label to load. The same dialog opens through New → New Postgres, `/new/database`, and `/d/new` aliases. Do not create anything.
2. At rest the dialog is x16–344, clientWidth326, but scrollWidth421. Its implicit grid column is **372.75px**, making the Name input and plan trigger extend from x41 to **413.75**, outside both the dialog and viewport. Screenshot `qa-mobile-r76-postgres.png` shows the right edges of text/inputs cut off; Public access is x364.75–400.75 and starts entirely beyond the viewport. Invalid database name `bad-name` correctly disables Create, but its explanation is clipped too. The clean default form repeats the same overflow: invalid input is not the cause.
3. Open Instance type: after animation settles, its listbox is x10–**439.84375**, width429.84375 at viewport360. The long selected/options labels include RAM/CPU/storage and monthly price. No paid option was submitted.
4. Fresh page reload at **320×800** repeats: clientWidth286 vs scrollWidth421. Before the catalog arrives the360px dialog fits (326/326); after it arrives it overflows. At settled **1280×900**, the512px dialog fits (510/510, grid462px). Do not measure during Radix entry or resize animation: an intermediate desktop width657.4 was discarded as transitional.
5. **Target:** at 320/360/390px, both the dialog and open plan menu stay within the viewport, with fields, complete validation text, Public access and footer actions reachable by vertical scrolling only. The selected plan and each option must keep their full tier/specs/monthly price readable by wrapping or an equally explicit nearby label. Do not solve this by hiding the price or clipping controls. At 1280px retain the current usable desktop layout. Compare catalog-pending and catalog-ready geometry at both widths per dashboard AGENTS; no growing horizontal track after the data arrives.

## Root cause, dependency and scope

- `dashboard/src/features/databases/components/create-database-dialog.tsx:185` uses the shared grid DialogContent with no bounded column override. At263–281, the width-full SelectTrigger renders a selected item made from tier name, specs and price. Its intrinsic width expands the dialog's implicit `auto` grid column.
- `dashboard/src/common/components/ui/dialog.tsx:62` declares `grid`, viewport max-width and vertical auto overflow, but no `minmax(0,1fr)` track/min-width containment for children. `common/components/ui/select.tsx:39` gives the flex trigger `whitespace-nowrap`, a fixed default height and a value selector with both line-clamp and flex rules; it does not constrain the selected label's intrinsic minimum. `select.tsx:67–90` bounds popover height but not width and gives the viewport a minimum trigger width. Both consumers need to remain readable within their own available width.
- Read the actual installed/locked dependency, **@radix-ui/react-select2.2.6** (`dashboard/yarn.lock:3523`): `dist/index.mjs:218–241` strips `className` and `style` from SelectValue rather than forwarding them, and line925 portals the selected ItemText children into that value node. Thus simply adding `className="truncate"` to the repository's SelectValue wrapper is not an effective fix. SelectPopperPosition at674–701 exposes `--radix-select-content-available-width`; **@radix-ui/react-popper1.2.8** `dist/index.mjs:152` uses `minWidth:"max-content"` on its floating wrapper. Position collision handling alone does not shrink these contents. Prefer an explicit bounded caller layout and parent selectors or wrapped children that actually reach the rendered value; test the opened menu too.
- A reversible **DOM-only diagnosis** on the owned draft set the dialog grid to `minmax(0,1fr)`, allowed its selected plan to wrap and grow vertically, and bounded that value's flex minimum. This changed scrollWidth 421→326, grid 372.75→278, Name input right 413.75→319 and plan height 36→58 while preserving the full label. Reload removed the diagnostic styles and reproduced the defect. This is mechanism evidence, not a shipped fix or proof that the menu is fixed.
- **Blast-radius task (10m):** audit the integration and keep this change scoped to CreateDatabaseDialog unless a wider shared fix is separately justified. Exhaustive production JSX census (excluding tests): DialogContent has **32 sites in 30 files**; SelectTrigger has **33 sites in 25 files**. Do not silently modify every caller for this one observed issue. CreateDatabaseDialog has **one production mount**, `routes/index.tsx:299`; route aliases land there. Correct controls: the360px New Project dialog fits 326/326 using the same DialogContent; Free Key Value creation fits documentWidth360 using PlanCardGrid, and the web-service create form also fits360. Their correct behavior has been checked live. Shared primitives are not universally broken.
- Resource family: observed issue is Postgres creation. Web/static/cron/worker/private use the service form; Key Value uses its own page. The three datastore card pickers (KV create, KV plan change, PG plan change) use PlanCardGrid, not this long Select integration. KV creation was live-probed; both plan-change pages and every other dialog/select caller were not. Preserve their behavior; do not claim they were all tested.
- APIs, authorization and mutation semantics remain unchanged. Catalog fetch errors keep their existing handling; validation still blocks malformed SQL names. No credentials or existence/error distinctions change. This is layout work, not a pricing or plan policy change.

## Closed 2026-10-04 (loopx)

Fixed scoped to `CreateDatabaseDialog`: the DialogContent column is `minmax(0,1fr)`, the plan trigger grows vertically and wraps its full label (`h-auto`, `whitespace-normal`, select-value `line-clamp-none`/`min-w-0`), and the plan menu is capped at `--radix-select-content-available-width` so its options wrap. Shared `dialog.tsx`/`select.tsx` untouched. Verified in real Chromium (Vite dev server + a temporary, uncommitted harness route rendering the open dialog with the GraphQL catalog intercepted): pre-fix the harness reproduced the QA geometry exactly (360px: scroll 421 vs client 326, column 372.7px, menu right 450); post-fix 360px → scroll 326/326, column 278px, Name right 319, plan 41–319 at 58px tall with the full "Free — 256 MB RAM, 0.1 CPU, 1 GB · $0.00/month", switch right 306, menu 10–350 with every option wrapped in full; 320px → 286/286, menu 10–310; 1280px → 510/510, column 462px (desktop unchanged apart from the trigger's 36→38px auto height). databases tests + dashboard lint green.
