# Key Value suspend confirmation promises data preservation with persistence Off

Why: users should know that suspending a non-persistent cache clears its keys before they accept the action.

**Severity:** minor (misleading confirmation copy). **Estimate:** 45m. Source: continuous functional `$qa-find-bugs`, 2026-10-10, pass a135, production dashboard, workspace `tea-d98210cbbpdc73dcrkvg`. This files a fix; the store's documented persistence behavior is correct.

## Reproduction and target behavior

1. Create an owned Free/public Valkey 8 store with Journal + Snapshot. The fixture was `qa-20261010-a135-kv-store` / `red-db5f1vp9siac73f4sap0`.
2. Complete the durable controls below, then edit Persistence mode → Off. Accept the correctly worded, typed `sudo clear key value <name>` confirmation and wait for Available. Verify earlier keys are absent.
3. Through its normal external TLS connection, set `qa:a135:off-only` to `qa-a135-off-only` and read it back exactly.
4. Freshly reload `/keyvalue/<id>`. Open **Suspend Key Value Instance**. Its description says: “Active connections will be dropped; data is preserved and you can resume it at any time.”
5. Type `sudo suspend key value <name>`, submit, and wait for Suspended. Resume and wait for Available. PING succeeds; the marker is absent, with the requested persistence mode still Off.
6. Repeat with a new marker from a fresh 390×844 page. The same claim appears and the marker again disappears after resume.

Expected: the confirmation describes data retention according to persistence and explicitly says **Off loses all data on suspension/restart**. It must not promise preservation of the whole in-memory dataset. Actual: the unconditional claim appears at both 1440×1000 and 390×844. Off's data loss is expected; the defect is the promise made before accepting suspend.

Use concise **mode-independent** copy for this small fix, for example: “Suspending {name} drops active connections. You can resume later. Data retention follows your persistence mode; Off loses all data. Durable modes retain persisted data.” Preserve Snapshot's last-snapshot limit and Journal's every-second journaling limit; do not replace the sentence with an unconditional durable-mode guarantee. Translate the same meaning in Chinese.
