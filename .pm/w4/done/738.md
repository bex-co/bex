# `POST /v1/services/{id}/scale` answers 202 with no body, as Render's does

Why: Render parity — Render's scale endpoint answers `202 Service scaled successfully` with no content, while bex returns the whole service, a drift ADR018 has recorded as "Known drift, not changed here" since w4/m364 without a sign-off or the follow-up that milestone promised.

- **Render:** the pinned OpenAPI (`lego/backend/internal/api/openapi/render-public-api-1.json`), `POST /services/{serviceId}/scale` → `202 {"description": "Service scaled successfully"}`, no content.
- **bex:** `lego/backend/internal/apps/rest.go:984-993` answers 202 with `s.restService(...)`.
- **Do:** answer 202 with an empty body. First confirm nothing in bex reads the body: the pinned Render CLI follows Render's contract, and the dashboard scales through GraphQL. Update the ADR018 services-lifecycle scaling row and the REST test.
- **End state:** `POST /v1/services/{id}/scale` with a valid count answers `202` and an empty body; errors keep their shapes.
- **Size:** about 30m.

**Done 2026-11-27 (loopx w4).** `POST /v1/services/{id}/scale` now goes through `core.HandleNoBody(http.StatusAccepted, …)` (`lego/backend/internal/apps/rest.go`), so a valid scale answers `202` with an empty body and no `Content-Type`; a 400 (out-of-range count) and a 404 (unknown service) keep their JSON `{id, message}` bodies. Nothing in bex read the old body: the pinned Render CLI (`render-oss/cli@09b7802aa379`) has no command that calls `ScaleService`, the dashboard scales through GraphQL `scaleService` (which, like MCP `scale_service`, still returns the service), and `scripts/events-verify.sh` checks only the status. `TestRESTScaleService` pins the spec's content-less 202 and the empty body (it fails with the old handler), and the ADR018 services-lifecycle "Manual scale" row records the change in place of its "Known drift" line.
