# 411 — Generate Blueprint drops a service's non-default port, so the exported manifest recreates it listening on 10000

Why: Generate Blueprint's promise (w8/m22, w4/040) is a no-op round trip: export a stack, apply it elsewhere, get the same stack. Both web services exported here run on port **3000**, yet the manifest carries no port signal. Re-applying it to the same workspace plans `noop` only because the services already exist with port 3000. Applied to a fresh workspace or project, each service would be created on the default port 10000 while its process listens on 3000. Runtime port detection doesn't rescue that on production (w4/393).

**Severity:** major (the exported stack does not reproduce; the failure is silent until the copy fails its health check). **Estimate:** ~45m. **Source:** live `/qa-find-bugs w4` loop run b8y1, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `c5583c80bef9`). Read-only: only `generate` and `validate` were called; nothing was created. Session revoked.

2. `GET /v1/services/<id>` for both → `serviceDetails.port: 3000`, `openPorts: [{port:3000}]`. Their env vars hold no `PORT`: `hello-go` has only `MESSAGE`, the echo service has none.
3. `POST /v1/blueprints/validate` with that manifest → `valid: true`, every action `noop`, `$0.00`. The round trip looks clean only against the existing resources.

## Root cause

- `lego/backend/internal/apps/blueprint_generate.go` (service entry built around `:490-495`) writes repo/image, runtime, plan, health check and env vars, but never the service's port.
- bex derives a new service's port from a literal `PORT` env var (`provisionalEnvPort`, `service.go:2244-2262`), Render's own convention: Render sets `PORT` and honours a user-set one. Without it, a create falls back to the default 10000.

## Fix (target behavior)

- When a service's port differs from the platform default and it has no `PORT` env var of its own, emit `envVars: [{key: PORT, value: "<port>"}]`. The port isn't secret, so it is a literal, not `sync: false`. An existing `PORT` var is exported as today.
- Image services whose ports come from the image (`UsesImagePorts`) emit nothing extra.
- Apply the same rule to private services and workers that have a port.
- Tests:
  - a port-3000 git service and a port-3000 image service each export `PORT: "3000"`;
  - a default-port service exports no `PORT`;
  - compiling the generated manifest into a new App yields port 3000 (round trip through the compiler, not just validate).

## Second export gap: unverified custom domains (run g4r6, 2026-10-24)

- **Fixture:** Free git service `qa-20261024-g4r6-gen` (`srv-dbegnp4oi59c73ajehf0`; deleted, `GET` → `404`), with `autoDeploy: no`, a `buildFilter`, `dockerfilePath`, `healthCheckPath: /healthz-qa` and env `QA_LIT`. `POST …/custom-domains {name:"qa-20261024-g4r6.example.com"}` → `201`, and `GET …/custom-domains` lists it.
- **Result:** `POST /v1/blueprints/generate` exported every other setting correctly (`autoDeployTrigger: "off"`, `buildFilter`, `dockerfilePath`, `healthCheckPath`, `QA_LIT` as `sync: false`), but **no `domains:` key**. That held on a second generate 10 s later.
- **Cause:** an unverified domain is stored as a claim. It returns through `domainClaimView` in `domains.go` before line 1486, and only enters `spec.Hosts` (`:1520-1522`) once verified. The exporter reads only the spec (`appDomains` → `blueprintDomainList`, `blueprint_generate.go:478-479`, `:632-646`), and the planner compares against the same list, so validate still reports `noop`.
- **Fix:** export the service's claimed (pending) domains as well, since Render's `domains:` lists every configured domain, verified or not. Have the planner compare against that same union, so the w4/m124 generate → validate `noop` guard still holds. Add a test with a pending claim.

**Unverified:** a live apply of the generated manifest into an empty project (would create resources); Render's own Blueprint generator output for a non-default-port service or a pending domain.

## Loopx w4 verdict (2026-10-25)

Done: Generate Blueprint now exports a literal `PORT` env var for web/private/worker services serving on a non-default port (never for image-port services, never duplicating an existing PORT), and pending domain claims join the exported `domains:` union. The planner and the stack apply compare against that same union, and a `PORT` literal that only restates the served port is dropped before planning/applying, so a generated manifest still validates `noop` against its own source. The round-trip harness folds the PORT spelling back to `spec.Port` and its stale "Port is not exported" gap is removed. Backend suite and lint green; live apply into an empty project remains unverified (would create resources).
