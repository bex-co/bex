# Postgres top-queries answers `[]` for a database that does not exist, and Render's `/query/*` insight paths 404

Why: `top-queries` is the one Postgres insight that turns every failure into an empty list. A typo'd id, a suspended database or a connection failure all read as "no slow queries", which is the answer an operator hunting a slow database most wants to believe. Its three siblings answer `404 not found` for the same id. Separately, a Render client calling Render's documented `GET /v1/postgres/{id}/query/top-queries` (and `processes`, `sizes`, `table-scans`) gets a bare `404 page not found`, because bex mounts them one segment shorter. ADR018 l.151 records these as "Render-compatible REST shapes" ✅.

Found live in `/qa-find-bugs` pass 246 on 2026-09-27 (w4-targeted, `muse.env` credentials) against the deployed `4a0422577`. Read-only: in-page `fetch`/GraphQL/MCP from `dashboard.bex.co`. Real database `dpg-d9rs3ee0ccis738kc7c0` (available, basic-1gb); dead id `dpg-d0000000000000000000`.

| request | real db | dead id |
| --- | --- | --- |
| REST `GET /v1/postgres/<id>/top-queries` | 200, rows | **200 `[]`** ❌ |
| REST `…/processes`, `…/table-scans`, `…/sizes` | 200 | 404 `not found` ✅ |

## Mechanism

- `lego/backend/internal/postgres/insights.go:334-347` `TopQueries`: on any `runInsight` error other than `ErrForbidden`/`ErrAuthzUnavailable` it returns `[]TopQueryView{}, nil`. The comment names the intent (unknown db, `pg_stat_statements` not installed, connection failure all mean empty). That intent predates `fetchDatabaseForRead` (`insights.go:217`) returning `ErrNotFound` for a dead id, which is now swallowed too. `Processes` (l.296) and the other insights return the error.
- `lego/backend/internal/postgres/rest.go:324-330` mounts `GET /v1/postgres/{id}/{processes,top-queries,sizes,table-scans}`. Render's embedded spec (`internal/api/openapi/render-public-api-1.json`) has only `/postgres/{postgresId}/query/{processes,sizes,table-scans,top-queries}` (grep: 4 `/query/` paths, 0 bare).

## Fix

Target: top-queries fails the way its siblings fail, and Render's paths work.

- `TopQueries`: return `ErrNotFound` for an unknown database and `ErrUnavailable` (503, a named reason) for a connection failure or a suspended database. Keep `[]` only for the one case that is truly empty: `pg_stat_statements` present with no rows. If the extension is missing, return a named `unavailable` reason (REST/GraphQL/MCP), so the dashboard panel can say why rather than render an empty table.
- Mount Render's `/v1/postgres/{id}/query/{processes,sizes,table-scans,top-queries}` as the canonical routes. Keep the short paths as aliases (the dashboard/CLI may use them; grep before removing). Add both spellings to `scope_matrix_ops.go`/`scope_matrix_overrides.go` (top-queries and processes are `Sensitive`, as `w4/082` requires), and run them through the Render OpenAPI gate test.
- Correct ADR018 l.151.
- Tests: dead id → 404 on all four insights across REST/GraphQL/MCP; a suspended database → 503 for top-queries; each `/query/*` path passes the gate and returns the same body as its alias.

Blast radius: the dashboard Insights panel (`dashboard/src/features/databases/…insights-panel`) reads `databaseTopQueries`, so it needs an error state for the new 404/503 (it currently shows an empty table). The scope-matrix guard tests from `w4/082` must list the new REST spellings.

Unverified: the suspended-database and missing-`pg_stat_statements` paths were reasoned from the code, not probed (no suspended QA database was created this pass). The short-path callers in the dashboard/CLI were not enumerated.

Render: `GET /v1/postgres/{postgresId}/query/top-queries` per its public OpenAPI. Its behaviour for an unknown id was not probed (no Render account in this run).

Estimate: ~50m.

Closed 2026-09-27: Top-query reads now preserve not-found/authorization failures and return unavailable for suspended or unreadable statistics. Render query paths use their required envelopes/field names; legacy short paths retain their bodies and all permissions match. Tests cover REST/GraphQL/MCP missing IDs, suspension, gated routes and populated OpenAPI-conformant wire mappings.
