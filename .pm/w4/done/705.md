# 705 — An events answer that isn't an events list (an edge's HTML 502) crashes the tenant-view canary's stage 4 as "3/4 metrics"

Why: w4/704 made stage 4 retry a read that fails in transport, but a read that answers with something other than an events list still ends the run, under the wrong stage's label, and reopens #167 as a metrics failure.

- **Source:** the `/loopx w4` worker for w4/704 (2026-11-17), which found this gap in the fix that shipped first (ad1761bf3) and reproduced it with a stub against that commit.
- **Today:**
  - `acurl` (`scripts/lib/canary-api.sh:88`) runs `curl -sS` without `-f`, so `fetch_events` (`scripts/tenant-view-liveness.sh`, about line 293) accepts any answer curl completes, including a 502 or 503 page, and moves it to `events.json`.
  - `poll_events` then runs `hit="$(jq -r "$@" "$TMP_DIR/events.json")"` (about line 315) under `set -e`. On HTML, jq exits 5, so the script exits 5.
  - `.github/workflows/ssh-edge-liveness.yml:430` labels exit 5 `3/4 metrics (empty series for a serving service)`.
  - A JSON error body doesn't crash, but it counts as a feed that answered, so the run can end as a stalled feed (6).
- **Do:**
  1. In `fetch_events`, accept an answer only if it is an events list: `jq -e 'type == "array"'` on `events.part`.
  2. Otherwise count it as a failed read, keep the first 200 bytes as the reason in `events.err`, and leave `events.json` (the last good answer) in place, so stage 4 retries within its budget and only a feed that never answered exits 8.
- **Prior work:** the worker's version of this fix and its test is in local stash `loopx/w4/704-nonlist` in the `/Users/tianpan/projects/bex7` checkout. It was written before ad1761bf3 landed, so take only the non-list check and its test from it, not its board edits or its own retry loop.
- **Accept:**
  - A stub that answers HTML once, then a good list, passes.
  - A stub that always answers HTML exits 8, and the error names the HTML.
  - A JSON error body followed by an empty feed still exits 6.
  - All three are added to `scripts/tenant-view-liveness.test.sh`, and the first two fail against ad1761bf3.
- **Render:** n/a (bex's own monitor).
- **Size:** about 20 minutes.

**DONE 2026-11-17:** `fetch_events` now accepts an answer only when `jq -e 'type == "array"'` holds on `events.part`; any other completed answer counts as a failed read, its first 200 bytes go to `events.err` as `the answer is not an events list: …`, and `events.json` keeps the last good answer, so stage 4 retries inside its budget and exits **8** only when no read ever returned a list. `ssh-edge-liveness.yml` labels 8 `4/4 events (the events read never answered with an events list)`. `scripts/tenant-view-liveness.test.sh` gained three cases: one HTML 502 page then `service_woken` passes; an HTML page on every read exits 8 naming the HTML; a JSON error body then an empty feed still exits 6. The first two exit 5 (`jq: parse error`) against ad1761bf3. The stash `loopx/w4/704-nonlist` is dropped; only its non-list check and HTML case were still needed.
