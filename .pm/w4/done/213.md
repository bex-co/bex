# Cron history buttons hide which run they open
Why: the Started column is the run-detail control, but identical accessible names replace its visible time, so keyboard/screen-reader users cannot choose a particular run by name.

- **Source / severity / estimate:** user-requested infinite `qa-find-bugs` loop, w4, 2026-10-07 cycle 2; **minor**, 25m. ADR008 pillar 1, ADR006 / ADR018 hosting usability. Filing only; no product changes.
- **Repro:** create a Free image cron from `alpine:3.20`, schedule `0 0 1 1 *`, command `sh -c 'echo qa-c2-start-9d34; echo "error: qa-c2-error-9d34" >&2; sleep 3; echo qa-c2-end-9d34'`. Open `/services/srv-db3icsk3a6ns73b87nkg/events`; confirm Trigger Run twice, waiting for each to finish. Reload at desktop and 390×844. Both Started cells contain `button "Toggle run detail"`; one visually says `1m`, the other `2m`, but neither button's accessible name contains its run's time or identity. At mobile after another reload the visible ages became `2m` and `3m`, with the same two names. Focus + Enter expands the correct selected run and returns real timing/ID; the naming is the defect, not the detail read.
- **Target:** the Started-cell control's accessible name includes the run's visible start-age text and a stable, localized absolute start time, plus expand/collapse intent. Names must distinguish rows; a same-start-time tie or missing/invalid start time uses the run ID as a fallback. Keep `aria-expanded`, keyboard activation, the visible aging time, polling, and table geometry. Do not make users open each run to learn which button they focused.
- **Root cause:** `dashboard/src/features/services/components/cron-runs-section.tsx:181` sets a constant `aria-label={t("services.cronRunDetailToggle")}` on a **native button** surrounding `RelativeAge`. `locales/en.ts:2729` is `Toggle run detail`; `locales/zh.ts:2672` is the same generic-purpose label in Chinese. `common/components/relative-time.tsx:53` puts the instant into `<time dateTime>`; this call supplies no title, and the outer name overrides its child text. The actual accessibility tree confirms the browser's name computation. [W3C naming guidance](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/) explains that an explicit button aria-label replaces descendant content; this is normal native naming behavior, not a router or component-library failure.
- **Expressible fix:** list data already provides `id` and nullable `startedAt` (`features/services/types.ts:315`); no additional fetch or API shape is needed. Compose a row-specific translated name or `aria-labelledby` from the visible time plus contextual text, formatted consistently with the existing detail timestamps. Preserve null/invalid timestamp fallbacks and avoid collisions when two ages round to the same value. Scope the fix to these row controls; do not change the shared relative-time component globally.
- **Blast radius / aliases:** one production `CronRunsSection` call, `routes/services.$serviceId.events.tsx:353`, behind the cron resource-type gate; one production use of the label key. `/cron/<id>/events` canonicalizes to the same service detail family (`routes/cron.$.tsx:4`, `common/lib/render-alias.ts:17`). Web/static/private/worker do not render this section; Postgres/Key Value have separate detail routes. Pending/running/terminal rows share the control. Cancel's generic name is not separately claimed here; one active run is allowed by the cron contract. Shared `RelativeAge` remains unchanged, so other hosting timestamps are outside scope.
- **Adjacent states / before-settle:** retain the existing first-load row skeleton and last-good data through polling. A pending run with no start timestamp gets a clear non-empty name using its stable run identifier. Keep missing/forbidden/unauthenticated detail errors in their current route-owned handling; labels use only the authorized list data and make no new existence probe. A failed detail fetch must not relabel a different row or lose expanded state/focus.
- **Acceptance:** repeat the two-run fresh-page desktop/mobile journey and inspect the real accessibility tree: each button names its own start time/visible age and intent. Tab to the desired row and Enter/Space opens that row's matching ID and dates; collapse still works. Add focused component coverage with distinct start times, equal rounded ages, a tie and null/invalid start time in en/zh; preserve `aria-expanded` and the existing detail error/loading paths. Run dashboard checks and the simplify skill on the changed code; no backend/operator behavior change.
- **Dedupe:** searched open, blocked and done items across workstreams, including exact label and cron accessibility terms; no owner or landed fix. `w7/done/050.md` mentions the label as proof the feature exists, without reporting its ambiguity. `w5/done/m60` introduced the detail affordance, with the same constant label since `c55a89e67`; this is an unaddressed naming gap, not a reappearance of an already-fixed bug. `w4/done/138.md` owns list freshness and preserves detail controls, not their names. No DO_NOT_DO anti-goal applies.
- **Render:** exact authenticated Render run-control accessible names were not available in this sweep. No Render-specific naming claim; the existing run history/detail workflow remains compatible.
- **Unverified:** real screen-reader speech beyond the browser accessibility tree, live Chinese UI, pending/null/tied-start rows, load-more and error paths. These are compatibility checks to execute, not additional live failures. Cron core behavior, detail expansion, successful statuses and log filters passed this run.
