## Objective

Add the Render-compatible endpoints the official CLI calls — `POST /v1/device-grant`, `POST /v1/device-token`, and `POST /v1/token/refresh/` — as thin translations onto Hydra's device authorization and token endpoints.

## Context

Match the pinned CLI's exact request/response and pending/slow-down/error behavior. The adapter should supply the fixed public client and `offline_access` where Render's wrapper omits them, translate JSON/form fields only where required, and otherwise preserve Hydra semantics. These endpoints must be reachable before bearer authentication but must not become a general auth bypass.

## Files

- `lego/backend/internal/api/server.go`
- `lego/backend/internal/api/auth.go`
- new focused package under `lego/backend/internal/cliauth/`
- backend route and adapter tests

## Acceptance criteria

- [ ] The unmodified CLI obtains a device code, polls pending authorization correctly, exchanges an approved code, and refreshes an expired access token.
- [ ] Only the three narrow protocol endpoints are unauthenticated; protected `/v1` resources still require a valid caller.
- [ ] Hydra errors map to the exact status/body shapes the CLI expects, with no tokens or secrets logged.

## Out of scope

- Browser verification UI (t003).
- Token-chain revocation (t004).

## Resolution (2026-07-15)

Shipped in `441d6040` (internal/cliauth: device-grant/device-token/token-refresh JSON→form adapters proxying Hydra verbatim, public-route mounts outside the gate); live on prod (`POST /v1/device-grant` public, returns a real device code). t007's simplify folded the revoke route into a cliauth `RegisterREST` fragment and deduped the proxy 503 path.
