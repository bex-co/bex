## Objective

Audit the one upload callback and two editor adapters. Bind completion to the active resource/edit; preserve Cancel, later Edit, resource change and unmount, masked originals, deleted-name replacement, normalization, format/size checks and all Save modes. Place unobserved lifecycle cases in tests without claiming a live failure.

## Out of scope

Paid features, foreign fixtures, decoder/BOM work owned by w4/285, backend replacement protocol and unrelated product behavior.

Done 2026-10-13: One `uploadFiles` call site, two adapters (`ServiceEnvironmentEditor`, `EnvGroupEnvironment` in `env-group-editors.tsx`). A batch carries the session it started in; `endEdit` (Cancel, save, both discard paths) and `startEdit` (Edit, restored draft) move the session, so obsolete results are dropped. Each adapter now passes `key` = its resource id, so a draft no longer survives onto another service or group (it did before for a clean draft; the dirty case was already blocked by the navigation blocker). Masked saved names still count as taken, a name staged for deletion is free, validity/size/NUL/UTF-8 refusals are unchanged, and the notice still clears when an Edit starts. Behavior kept as before: with overlapping batches the notice reflects the batch that landed last.
