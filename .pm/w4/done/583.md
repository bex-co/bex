# 583 — The edge's `Rndr-Id` is a 36-character UUID where Render's is 18 characters (`8-4-4` hex), so a request id never looks like Render's

Why: Render's request ids, in its `Rndr-Id` header and in a request line's `requestID="…"`, are 18 characters: `303516bf-4995-4cb9` (captured live 2026-11-11 for w4/m325) and `8ebfa3c3-8929-4885` and `74f98356-6f57-48a5` (Render's docs and blog). bex's `bex-client-ip-headers` plugin mints a full version-4 UUID (`ad8c2d92-90ac-42a8-8c03-c8b6f8776c79`). An app or log tool that validates or parses Render's shape sees a different one.

- **Source / severity / estimate:** w4/m325 t001/t010 (`/loopx w4`, 2026-11-11), from the capture in `docs/render-artifacts/request-logs.md`. **Minor**. ~30m.
- **Where:** `requestID()` in `deploy/gitops/charts/traefik-plugins/clientipheaders/clientipheaders.go`. Its ConfigMap is content-hashed, so a change rolls the edge pods (w4/m164).
- **Fix sketch:** mint 9 random bytes as `8-4-4` lowercase hex. Update `TestRndrID`, then ADR010 § Request correlation and ADR022's client-identity section. Check that nothing in bex parses the id as a UUID (`grep -rn "Rndr-Id\|requestID" lego dashboard`).
- **Dedupe:** w8/m125 (done) introduced the minted id with the UUID layout; no open item covers its length.

- **2026-11-11 (loopx w4):** done. The edge's `bex-client-ip-headers` plugin mints `Rndr-Id` in Render's 18-character `8-4-4` lowercase hex shape (8 random bytes, as in `303516bf-4995-4cb9`) instead of a 36-character UUID; nothing in bex parses the id as a UUID. `TestRndrID` pins the shape; ADR010 and the request-log record updated. The plugin ConfigMap is content-hashed, so the edge pods roll once.
