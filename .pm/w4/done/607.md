# 607 — The Logs "Filters" and Events "Filter events" panels open as dialogs with no accessible name, as do 5 of the dashboard's other 6 popovers

**Absorbed 2026-11-14 into [w21/m395 t004](../../w21/m395/t004.md)** (`/pmx them all to w21`, from `/pm-brainstorm for w21`). **Not fixed yet:** the fix and its live DoD ship with that milestone; this note keeps the original evidence.


Why: a screen reader announces each panel as just "dialog". The user has to explore it to learn that it holds the log level / method / status / instance / path filters, or the event-type list. WAI-ARIA requires a `dialog` to have an accessible name. The header's Connect popover already shows the pattern.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 192, 2026-11-12 11:58–12:01 UTC (`muse.env`, workspace `bex-canary`; pin `a5be11e4e517`). **Minor** (accessibility; the controls inside are named). ~30m.
- **Fixture:** Free image web service `qa-20261112-r192-logs` (`srv-dbqqhqq8vjhs73do9f90`, `busybox:1.36`), deleted afterwards (DELETE 204, then GET 404).
- **Probe:**
  - `/services/<id>/logs`, then "Filters":
    - `page.getByRole('dialog').ariaSnapshot()` → `- dialog:` with no name, holding `combobox "Level"`, `combobox "Method"`, `combobox "Status code"`, `combobox "Instance"`, `textbox "Request path"` and `textbox "Request host"`.
  - `/services/<id>/events`, then "Filter events":
    - `document.querySelectorAll('[role=dialog]')` → `{"label":null,"labelledby":null,"text":"All eventsDeployDeploy startedDeploy endedBuild started…"}`.
  - **Control:** the header's "Connect" popover reads `{"label":"Connect","labelledby":null,…}`, because it passes `aria-label={t("services.connect")}` (`dashboard/src/features/services/components/service-detail-header.tsx:387-389`).
- **Root cause:**
  - Radix Popover 1.3.1 (the dashboard's lockfile) renders `PopoverContent` with `role: "dialog"`, and sets `aria-labelledby` only when a `PopoverTitle` is mounted (`dashboard/node_modules/@radix-ui/react-popover/dist/index.mjs:280-283`).
  - The wrapper (`dashboard/src/common/components/ui/popover.tsx:18-40`) passes props through and adds no name.
  - So every caller that passes neither `aria-label` nor a `PopoverTitle` renders an unnamed dialog.
- **Fix (target behavior):** every popover panel has an accessible name.
  - The Logs panel is named for its trigger ("Filters", or a fuller "Log filters"), and the Events panel likewise ("Filter events", `services.eventsFilter`).
  - Make the wrapper's type require `aria-label` or `aria-labelledby`, so a new caller cannot omit it.
  - en and zh.
