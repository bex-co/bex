## Objective

Confirm that REST (`/v1/key-value`, `/v1/postgres`), GraphQL, and MCP all return the new status from the shared views, and that the pinned Render CLI renders it. Compare with render.com for a config-change restart and a manual Postgres restart. If Render uses `unavailable` for a manual restart, align t002. Record `dbStatus`'s non-Render `upgrading` value as follow-up drift.

## Result (2026-09-26)

REST, GraphQL, and MCP all read `kvView`/`pgView`, so the value changes on all three at once (`go test ./internal/api/...` conformance is green). `config_restart` is in the pinned `databaseStatus` enum (`render-public-api-1.json`), which Key Value and Postgres both reference, so the pinned CLI prints it verbatim. Render's value for a **manual** Postgres restart was not observed. `config_restart` is kept as the closest documented value (`unavailable` reads as a failure), recorded in ADR009. Drift recorded, not changed: `upgrading` and `deleting` are not in Render's enum (ADR009).
