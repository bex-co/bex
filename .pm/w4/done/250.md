# Escape keeps an unsaved select-field draft instead of canceling the edit

Why: keyboard users can discard text-field drafts with Escape, but the same shared editor leaves notification drafts active and ready to save; restore its promised cancellation behavior consistently.

Severity: **minor**. Estimate: **45m** (select-trigger fix, behavior tests, consumer and live checks). Functional live QA, 2026-10-11 pass a152, user-selected w4 and muse.env login helper. This files work; no product code changed.

## Reproduction and controls

On an owned Free image web service's Settings page, at 1440×1000:

1. Wait for Service Notifications to show its saved `Use workspace default (Only failure notifications)`, disabled with the pencil present.
2. Edit service notifications → select `None`. The popup closes and focus returns to the selector.
3. Focus that **closed** selector and press Escape, including a second press.
4. Actual: `None` remains visible, the selector is enabled, Save changes remains present, and the pencil is absent. Expected: discard the draft, restore the saved default and disabled selector, and show the pencil, with no mutation.

A fresh reload at 390×844, selecting `Only failure notifications`, reproduced the same failure with Save enabled. This is distinct from Escape **inside an open popup**: that correctly closes only the popup and returns focus; a subsequent Escape on the closed trigger should cancel the row.

Controls on the same fixture:

- All four notification modes save, survive a settled reload, and match REST `GET /v1/notification-settings/overrides/services/{id}`. No deploy or revision change: exactly one Live deployment and rev-1 throughout these edits.
- Global search finds the new fixture, then its renamed display name, original slug and uppercase service ID. This preserves w4/done/147.
- Captured cancellation checks contain zero SetNotificationsToSend mutations. Console: zero errors/warnings. Captured successful mutations and reads return HTTP 200; navigation-aborted reads do not establish a product failure.

## Root cause and bounded fix

`dashboard/src/features/services/components/editable-field-row.tsx:224–229` renders SelectTrigger with no cancellation key handler. Escape is wired only on the Input branch at :256–261. The select still shares `draft`, `editing`, and `cancel()`; calling the existing cancel restores the value and closes edit mode without touching onSave.

Actual pinned dependency opened: `@radix-ui/react-select` **2.2.6**, lockfile and installed `dist/index.mjs:202–210`: closed-trigger key handling covers opening/typeahead, with no Escape action. Its open Content uses DismissableLayer (:449–458), whose installed **1.1.11** handler prevents default and dismisses the highest open layer; Content restores focus to the trigger (:443–447). That explains the working open-popup control. The current online docs advertise a newer version, so they are not evidence for the pinned implementation.

Add cancellation to this editor's **closed select trigger**, only while editing and not busy. Preserve the first Escape's popup dismissal, ordinary option selection/typeahead and Enter-to-open behavior. Keep the disabled/busy state and persisted value untouched before editing; no optimistic API change or delayed query is required. Do not install a document-wide Escape listener or change the shared Select primitive. The searchable Combobox variant is separate, unprobed work; leave its keyboard policy out of this fix.

Source census: **22 production EditableFieldRow call sites in 15 files**, excluding tests/definition. Exactly **four use the Select options variant**:

- ServiceNotificationsRow, `service-notifications-row.tsx:34–40`.
- Auto-Deploy row, `build-deploy-section.tsx:175–181`, rendered only for a repo-backed service by `services.$serviceId.settings.tsx:197–200`.
- KeyValueMaxmemoryPolicySection, `key-value-maxmemory-policy-section.tsx:62–69`.
- KeyValuePersistenceModeSection, `key-value-persistence-mode-section.tsx:99–108`; preserve its existing confirmation for transitions involving Off.

The remaining 18 sites use Input (16) or searchable Combobox (2). Limit the behavioral change to the four Select sites. Services share `/services/{id}/settings`; `/static/{id}/settings` imports the same page. `/web/*`, `/worker/*`, `/pserv/*`, and `/cron/*` redirect to canonical service routes. Key Value mounts both editors on `/keyvalue/{id}` (`/r/*` redirects there); Postgres has only the shared name Input (`/d/*` redirects to `/databases/*`). Web/static/cron/worker/private settings can consume service select rows; Postgres does not. Live proof this pass is web notifications only.
