## Objective

With the fleet verified clean, return `spec.ipAllowList` to a structural object schema: required `cidr`, free-text `description`, no `Schemaless`, no `PreserveUnknownFields` — so the apiserver rejects malformed entries at admission again.

## Context

- `lego/types/v1alpha1/` — the CRD markers on `IPAllowEntry` / the `ipAllowList` fields for `Database` and `KeyValue`.
- Codegen: `make manifests generate` from `lego/operator/` regenerates `config/crd/bases/`.
- **Must land in a later deploy than t001** — the DoD's sequencing constraint.

## Steps

1. Remove the `Schemaless`/`PreserveUnknownFields` markers; add structural validation (required `cidr`).
2. `make manifests generate`; review the CRD diff.
3. envtest: applying a bare-string entry is rejected at admission; a valid `{cidr}` entry is accepted.

## Files

- lego/types/v1alpha1/database_types.go (and the KeyValue types file)
- lego/operator/config/crd/bases/
- envtest coverage

## Acceptance criteria

- [ ] `kubectl apply` with a bare-string or `cidr`-less entry is rejected by the apiserver.
- [ ] Valid entries and existing normalized CRs are unaffected.

## Out of scope

- Tightening `description` beyond free-text; CIDR-format validation beyond what m24's surfaces already enforce (keep admission and API validation consistent, not stricter).

## Resolution (2026-07-15)

Schemaless/PreserveUnknownFields markers removed from both types; regenerated CRDs are structural (`items` object schema, `required: [cidr]`). Envtest inverted: a bare-string entry and a cidr-less object are both REJECTED at a real apiserver; structured entries round-trip with descriptions. Sequencing honored: this landed a deploy after `fbfee9a7` (normalizer + fleet-verified-clean).
