## Definition of done

A service set to the captured "ignore" value emails nobody on deploy failure while a sibling service still does; the captured "default" value defers to each member's workspace-level w3/m9 preference; the field round-trips with Render's exact name/enum on REST, GraphQL, and MCP and is editable in the dashboard service Settings.

**Met.** Verified hermetically: `go build`/`go vet`/`go test ./...` (backend + operator, including a real envtest run and `make lint-backend` clean) and `yarn typecheck`/`yarn lint`/`yarn test` (dashboard, 1023 tests) all pass. The dashboard editability claim was also verified live: `yarn local-bex` + `yarn dev:local` in a real browser via Playwright — the Notifications card's select persists "Never notify" across a full page reload.

## What shipped

- **Render's real write path isn't mirrored, and that's stated, not hidden.** Render's `notifyOnFail` is read-only on its service object; the real toggle lives behind a separate `/notification-settings/overrides/services/{id}` endpoint with a richer `notificationsToSend`/`previewNotificationsEnabled` shape (Slack, workspace-level all/failure/none tiers) bex has no equivalent for. bex instead threads the one named field through the existing create/PATCH surface, matching `autoDeploy`/`healthCheckPath`'s placement — a deliberate, documented simplification (`docs/render-artifacts/notify-on-fail.md`), not an oversight.
- **`DeployNotifier` interface reshaped, not just extended.** `/simplify`'s altitude pass caught that this milestone was about to make `NotifyDeploy` the only "fan out an event" boundary in `lego/backend/internal` still using a growing flat positional-string-arg list — every comparable boundary (`core.AuditEvent`, the webhook worker's payload/`DueWebhookDelivery`) already uses a struct. Fixed before this shipped: `store.DeployNotification{TenantID, AppName, Status, NotifyOnFail}`, so the next Render field lands as one more struct field, not a sixth positional arg.
- **Documentation debt surfaced, filed as follow-ups.** Updating `docs/ADR006-bex-api.md`'s REST PATCH row and MCP tool table for `notifyOnFail` exposed that several earlier milestones' fields (`autoDeploy`, `healthCheckPath`, `rootDir`, `buildFilter`, `preDeployCommand` and their MCP tool counterparts) were never backfilled into those reference tables. The REST row was backfilled here (small, mechanical, already being touched); the MCP table's remaining gap is explicitly filed as a follow-up rather than silently left or scope-crept into a separate cleanup.
