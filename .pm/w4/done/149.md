# A registry credential saved as `https://ghcr.io/` is accepted with a success toast and can never be used

Why: pasting the registry's URL (scheme and/or trailing slash), which is how most registry docs and browser address bars present it, stores a credential that never matches any image. Auto-matching silently skips it, so a private pull later fails in the cluster. Binding it explicitly is refused with a message the user cannot act on from the form.

Found live, `/qa-find-bugs` pass 173, 2026-09-26 (w4-targeted, `muse.env` credentials), account → Registry Credentials. Fixture: credential `qa-20260926-reg` (`rgc-darmthpsmc7s73cq5fp0`, fake token), deleted the same pass. No service was created.

- **Repro:**
  1. Add credential with host `https://ghcr.io/`, a username, and a token → toast "Added a credential for https://ghcr.io/". GraphQL `registryCredentials` returns `host: "https://ghcr.io/"` verbatim.
  2. New Web Service → Existing Image `ghcr.io/bex-co/qa-nonexistent:latest`, pick the credential (listed as "qa-20260926-reg (https://ghcr.io/)"), then Deploy.
  3. Toast: **"Materializing registry pull secret for ghcr.io/bex-co/qa-nonexistent:latest: bad request: registry credential "rgc-darmthpsmc7s73cq5fp0" is for https://ghcr.io/, not ghcr.io"**.
- **Root cause:** `lego/backend/internal/registrycreds/service.go:214` (`Create`) only `TrimSpace`s the host, and `validateCredentialFields` (`:369-381`) checks lengths only. Every consumer compares the stored host with `strings.EqualFold` against `registryHost(image)` (`pullsecret.go:51-57`), which yields a bare hostname:
  - the explicit binding at `pullsecret.go:92`
  - the host auto-match lookup at `:104` (`GetRegistryCredentialByHost`)
  - the "which apps use this credential" scan at `:293`

  So a scheme, trailing slash, path, or `index.docker.io`/`registry-1.docker.io` alias for Docker Hub makes the credential inert.
- **Docker Hub alias, verified in pass 174 (2026-09-26):** a credential added with host `index.docker.io` (`rgc-darn08hsmc7s73cq5g5g`, deleted) was stored verbatim. Binding it to `docker.io/library/nginx:latest` was refused: "registry credential … is for index.docker.io, not docker.io". Nothing was created.
- **No repair path:** the Edit dialog disables the host ("The registry host can't be changed after creation"), so a mistyped host can only be deleted and re-created. That is one more reason to canonicalize on create, since Update never sees the host.
- **Fix:** canonicalize the host in one helper used by Create **and** Update. Strip the scheme and trailing slashes, reject a path or query, lowercase, and fold Docker Hub aliases to `docker.io` (the value `registryHost` returns). Refuse anything that still isn't a host[:port] with a named 400. Backfill existing rows through the same helper (or refuse to list them as usable). Show the canonical host in the success toast so the user sees what was stored.
- **Checked and correct this pass:** the dialog never shows the secret again, deletion removes the row, and the explicit-binding refusal happens before any App is written (no `qa-` service existed afterward).

Estimate: ~45m (helper + backfill + table tests for scheme, slash, case, Docker Hub aliases, port).

## Done (2026-09-27)

- New `lego/backend/internal/registrycreds/host.go`: `canonicalRegistryHost` strips a scheme and trailing slashes, lowercases, folds the Docker Hub aliases (`index.docker.io`, `registry-1.docker.io`, `registry.hub.docker.com`) to `docker.io`, and refuses a path, query, or non-host with a named 400. `Create` stores that value (the host is immutable, so Update never sees it). `registryHost(image)` folds the same aliases.
- **Backfill without a migration:** every comparison goes through `sameRegistryHost`, which canonicalizes the stored side too. The explicit binding and the "which apps use this credential" scan use it. The host auto-match keeps its exact SQL lookup and falls back to a canonical scan of the workspace's credentials on a miss. So rows stored as `https://ghcr.io/` or `index.docker.io` before this fix now match their images.
- Dashboard: the success toast names the host the server stored ("Added a credential for ghcr.io" after pasting `https://ghcr.io/`).
- Tests: `host_test.go` (a canonicalization table covering scheme, slash, case, port, localhost, the three Hub aliases, and five refusals; Create stores the canonical host; legacy `https://ghcr.io/` and `index.docker.io` rows match by auto-match and explicit binding for `ghcr.io/…`, `docker.io/…`, `index.docker.io/…`, and `nginx:latest`), plus `TestRegistryHost` alias cases and a hook toast test. Backend registrycreds + api tests, golangci-lint, and dashboard `yarn lint` + `yarn test` are green.
