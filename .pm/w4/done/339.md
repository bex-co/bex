# Workspace quota error says "limited to 1 Postgres databases" (broken plural at limit 1)

Why: the first limit a free-tier user ever hits greets them with broken English in the dashboard dialog and every API client, which reads as unpolished on a core create journey.

**Found live 2026-10-18** (dashboard QA hunt, w4 sweep 002): in `bex-canary` (one free Postgres already present), New → New Postgres → Create database shows "Postgres limit reached — workspace is limited to 1 Postgres databases; delete an existing Postgres database to create another". The limit itself works correctly; only the grammar is wrong.

**Root cause:** `lego/backend/internal/core/quota.go:117` formats the cap message as `workspace is limited to %d %ss; …`, blindly appending `s`. The three `CountCap` nouns are `Postgres database` (`lego/backend/internal/postgres/service.go:672`), `key-value store` (`lego/backend/internal/keyvalue/service.go:428`), and `service` (`lego/backend/internal/apps/service.go:2597`), so at limit 1 all three read wrong ("1 key-value stores", "1 services"). The message is the `WORKSPACE_RESOURCE_LIMIT` error body shared by REST/GraphQL/MCP and surfaced verbatim by the dashboard (`dashboard/src/features/databases/locales/en.ts:253` is only the dialog title).

**Fix (~20m):** pluralize properly in `quotaCapExceeded` — singular noun at `limit == 1`, plural otherwise. Nouns are multi-word, so either carry an explicit plural on `CountCap` ("Postgres databases", "key-value stores", "services") or special-case `limit == 1` to skip the appended `s` (sufficient today since every noun pluralizes by trailing `s`; the explicit-plural field is the safer shape). Target strings: "limited to 1 Postgres database", "limited to 2 Postgres databases". Update the two tests that currently assert the broken string: `lego/backend/internal/core/quota_test.go:97` and `dashboard/src/features/databases/hooks/__tests__/use-create-database.test.ts:224`. Add limit-1 and limit-2 cases for all three nouns.

**Verify:** `cd lego/backend && go test ./internal/core/`; live-check by creating a second free Postgres in a workspace that already has one and reading the dialog. No Render-parity risk: the error code and shape are unchanged; only the message text moves (clients key on `WORKSPACE_RESOURCE_LIMIT`, w5/m130).

**Implementation done 2026-10-18 (loopx w4):** `core.quotaCapExceeded` (`lego/backend/internal/core/quota.go`) now reads the noun in the singular at limit 1 and appends `s` otherwise. The deletion clause always names one resource. Admission refusals and Blueprint preview over-cap refusals (`CountCap.Exceeded`) share this one formatter, so all three caps are fixed. The note's explicit-plural `CountCap` field was tried and dropped in review: every noun pluralizes with a trailing `s`, and an unset plural on a future cap would silently render "limited to 2 ;". `core/quota_test.go` now covers Postgres and Key Value at limits 1 and 2, and the existing case covers services at 25. The three dashboard hook fixtures carry the corrected server text. The dashboard keys on `WORKSPACE_RESOURCE_LIMIT`, not on the wording. ADR006 § Per-workspace resource caps records the singular form. The full backend `go test ./...`, backend golangci-lint, deadcode and the three dashboard hook suites all pass. The live check waits on the bex-api deploy.
