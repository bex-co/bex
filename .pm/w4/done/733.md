# An environment group created in a brand-new workspace fails with an internal error until the namespace resync runs

Why: found during w4/731's dev-4 walk (2026-11-26). On Render, a new workspace can create an environment group at once; on bex the first try can fail for up to 60 s.

- **Symptom:** in a workspace whose namespaces the async reconciler has not created yet (up to 60 s after the workspace is made), creating an environment group answers an internal error, `namespaces "tea-…" not found`.
- **Cause:** a group's projection Secrets are written into the workspace's app namespace (`envGroupNamespace` → `AppNamespace`, `lego/backend/internal/envgroups/service.go:2020-2041`), but the create path (`CreateEnvGroup`, `service.go:424`) never calls `Base.EnsureWorkspaceNamespace` (`lego/backend/internal/core/base.go:516`). Service, Postgres and Key Value create do call it first (`lego/backend/internal/apps/service.go:3177`, `lego/backend/internal/postgres/service.go:1056`, `lego/backend/internal/keyvalue/service.go:777`).
- **End state:** `CreateEnvGroup` ensures the workspace's namespaces before its first Kubernetes write, as the other create paths do, and a test with a namespace that does not exist yet shows the create succeeding. On dev-4, a group created right after a new workspace is made succeeds on the first try.

## Record — 2026-11-26

**Triage: work.** `persistCreate` (`lego/backend/internal/envgroups/service.go`), the one write path behind `CreateEnvGroup`, `CloneEnvGroup` and a Blueprint's new group (`ApplyEnvGroup`), wrote the OpenBao maps and then the projection Secrets into the workspace's namespace without ensuring it.

**What shipped.** `persistCreate` calls `Base.EnsureWorkspaceNamespace` for the group's workspace after its quota checks and before its first write, so all three create paths ensure the namespace as service, Postgres and Key Value create do. `TestEnvGroupCreatesEnsureABrandNewWorkspacesNamespace` runs create, a clone into another workspace, and a Blueprint group against a client that refuses a namespaced create into a missing namespace, as the API server does. With the call removed, all three fail with `namespaces "tea-…" not found`.

**dev-4.** OpenBao ran alone in `dev-4-auth` for the walk and was removed afterwards. A disposable verified Kratos identity signed in. bex-api built from main before the fix: `createWorkspace` followed by `createEnvGroup` in the new workspace 0.12 s later answered `INTERNAL`, and the log said `namespaces "tea-…" not found`. Rebuilt from this tree, the same sequence created the group on the first try 0.28 s later, with its namespace and both projection Secrets present. Removed afterwards: the group, both workspaces (disposable) and the identity (it answers 404).

Closed 2026-11-26.
