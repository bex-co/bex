# `logLabelValues` (+ its datastore variants) is a MISSED ALIAS of w4/054 — the `start<end` guard must live in the shared `q.validate()`, not in `QueryLogs`, or the fix ships partial

Why: w4/054 proposes adding the inverted-range (`start<end`) guard "in the logs query validation path (`QueryLogs`, `service.go:460`)" and its blast radius names only `logs` / REST `/v1/logs` / `/v1/logs/subscribe` as funneling through `QueryLogs`. But `LogLabelValues` (`lego/backend/internal/logs/service.go:637`) is a **separate** method that never calls `QueryLogs` — so a fix placed in the `QueryLogs` body leaves `logLabelValues` still returning "internal error" for an inverted range. This corrects 054's fix **location** (and enumerates the aliases) before anyone implements it, so the fix is complete rather than partial.

Source: live QA 2026-09-07, `$qa-find-bugs w4` pass 27 (error-taxonomy fuzzing of the untested read-only GraphQL log surfaces; correction/extension of `w4/054`, batch with `w4/053`).

Originally filed as open `w4/055.md` after the CLI health-check note already occupied `done/055.md`; renumbered to **056** on closeout to clear the collision.

## Target behavior / fix (SUPERSEDES 054's fix location)

Put **one** `Since < End` guard, wrapped in `core.ErrBadRequest` (e.g. `startTime must be before endTime`), inside the shared `func (q LogQuery) validate()` — **not** in the `QueryLogs` body. That single placement covers `logs`, `logLabelValues`, `databaseLogs`, `keyValueLogs`, and both datastore label-value variants.

## Resolution — 2026-09-07

**Disposition: already fixed by w4/054; alias coverage pinned.** `LogQuery.validate` already calls `core.ValidateQueryRange` (same helper as metrics). `LogLabelValues`, `queryPostgresLogs`/`validatePostgres`, and `queryKeyValueLogs`/`validateKeyValue` all enter that shared validator; GraphQL `databaseLogs`/`keyValueLogs` ride `datastoreLogsAdapter` → `QueryLogs`. The open note was written against HEAD `5f15508c8` before 054 landed the shared placement.

This closeout extends `TestInvalidQueryRangesAcrossSurfaces` so the aliases the note enumerated cannot regress silently: GraphQL `logLabelValues` / `databaseLogs` / `keyValueLogs`, MCP `list_log_label_values`, REST `/v1/logs/values` (already present), and direct `LogLabelValues` for App + Postgres + Key Value ids — with a `LogLabelValues` source stub that fails if an invalid range reaches Loki.
