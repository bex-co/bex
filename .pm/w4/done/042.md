# 042 — Environment group service selector has no accessible name

Why: screen-reader users cannot identify the selector that chooses which service receives shared configuration.

**Severity:** minor. **Estimate:** 20m. Filed through `pm add w4` from repeated live `qa-find-bugs` passes on 2026-09-05. Workspace: `tian-personal` (`tea-da2isimlm39c739m4ofg`, Hobby). Governing contract: [ADR006, environment groups](../../docs/ADR006-bex-api.md#secret-files--environment-groups-w1m16).

## Reproduction and durable evidence

1. Create a QA environment group and have an unlinked service in the same scope.
2. Open `/env-groups/<group-id>`. In Linked Services, inspect the service selector using `await page.getByRole('combobox').ariaSnapshot()`.
3. Reload, repeat, then select a service without submitting the link.

Observed on the first group `evg-dae9253r12dc73ba7bag` and reproduced on a second group, `https://dashboard.bex.co/env-groups/evg-dae95n3r12dc73ba7bm0`, after reload:

```text
before selection: - combobox: Select a service
after selection:  - combobox: qa-20260905-static
```

The text after the colon is the value, not an accessible name. The complete supporting DOM probe was:

```js
await page.getByRole("combobox").evaluate((e) => ({
  role: e.getAttribute("role"),
  id: e.id,
  ariaLabel: e.getAttribute("aria-label"),
  ariaLabelledby: e.getAttribute("aria-labelledby"),
  labels: [...document.querySelectorAll("label")]
    .filter((l) => l.htmlFor === e.id && e.id)
    .map((l) => l.textContent),
}));
// {role:"combobox",id:"",ariaLabel:null,ariaLabelledby:null,labels:[]}
```

Control: on the same second group, Manage → Move group returned `combobox "Environment": Workspace (no Environment)`. That control has a real `Label htmlFor`/trigger `id` pair (`env-group-actions.tsx:366-369`). No console warnings/errors; captured GraphQL requests completed with HTTP 200. This is a DOM naming defect; API payloads cannot supply the absent ARIA relationship.

Local screenshot: `.playwright-mcp/qa-env-1.png` (existence verified). Screenshot is gitignored; the exact probes above are the durable evidence. Both groups and both QA services were deleted after the hunt.

## Root cause and fix

`dashboard/src/features/env-groups/components/linked-services-card.tsx:83-84` renders `SelectTrigger` with only a class, and puts the translated hint inside `SelectValue`. There is no associated label. The wrapper at `dashboard/src/common/components/ui/select.tsx:25-48` passes trigger props through. The pinned `@radix-ui/react-select` 2.2.6 implementation (`dist/index.mjs:169-185`, lock entry `dashboard/yarn.lock:3523`) sets `role="combobox"` but does not synthesize a name from the placeholder.

Give this trigger the translated accessible name **Select a service**, for example `aria-label={t("envGroups.selectService")}`. Preserve that name when a selection replaces the placeholder. Reuse the existing en/zh key. Assert `getByRole("combobox", {name: "Select a service"})` before and after selection; retain link-selection behavior and the existing scope tests.

**Blast radius:** one production `LinkedServicesCard` mount, `dashboard/src/routes/env-groups_.$groupId.tsx:215`. Local trigger fix only; the common Select wrapper should not gain a generic name. The route handles links to service resources; Postgres/Key Value are not its candidates. No REST/GraphQL/MCP schema or linking-policy change. `w6/m48`'s compatible/incompatible scope predicates remain covered.

**Adjacent classes / pre-settle state:** retain loading/busy disabling, the service-load error alert, missing-resource behavior, authentication and authorization handling. A control that is mounted while busy must retain its name; do not enable it before scope/service data settles.

**Unverified:** Chinese rendering, keyboard/screen-reader hardware, private/worker/cron candidates, and paid-workspace behavior were not exercised. The service value reached the live web process (`HTTP 200`, `qa-group-v1`), so no linking/runtime failure is alleged.

**Dedupe / deployment:** searched open and done board items for `linked-services-card`, unnamed selectors, accessible names, and env-group labels; scanned open milestones across workstreams. `w6/m48` fixes scope compatibility, not this label; `w6/done/059` concerns static-site row controls. `git log -S 'aria-label' -- .../linked-services-card.tsx` has no label fix, and HEAD still contains the defect. No DO_NOT_DO anti-goal applies.

**Render:** [Render's environment-group documentation](https://render.com/docs/configure-environment-variables#environment-groups) confirms linking shared configuration is a supported customer journey. Its live accessibility tree was not inspected; this filing asserts bex's missing name, not an unverified Render accessibility difference.

Added the existing translated Select a service name directly to the linked-service selector. The regression test finds the actual combobox by name before selection and after choosing api; the scope compatibility tests still pass. Dashboard typechecking/lint and all 2,995 tests passed. No production deployment or physical screen-reader test was performed.
