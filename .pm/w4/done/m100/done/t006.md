## Objective

Check that everything this milestone changed is consistent across every surface it exposes — REST, GraphQL and MCP in `lego/backend/`, plus the dashboard — and compare each against render.com's equivalent behavior, recording deliberate divergence as divergence.

## Context

- The deploy row is read by all three API surfaces and two dashboard pages, so t004's commit must appear identically everywhere (`docs/ADR006-bex-api.md`, `lego/backend/internal/api/CLAUDE.md` three-adapter parity rule).
- Render's deploy object carries `commit { id, message, createdAt }` for Git-backed deploys and its history rows show commit/message "without placeholders" — `docs/render-artifacts/deploy-detail-page.md:10,17`. Check whether Render populates the commit on its own configuration-triggered deploys and whether it exposes `createdAt` (the commit author timestamp, which `w2/m42` already wired for resolved commits) on a carried-forward commit.
- The 429 envelope is a Render-compatibility surface: `writeTooManyRequests` (`lego/backend/internal/api/ratelimit.go:143-159`) emits a GraphQL error envelope for `/graphql` and Render's plain JSON error body for REST/MCP. If t001 added a distinguishing code, confirm both shapes stay Render-compatible and that `docs/ADR006-bex-api.md` §Rate limits describes the new budget.
- `docs/ADR018-render-parity.md` is the ledger — update the rows this milestone moves, and open a note rather than silently diverging where bex now differs.

## Steps

1. Diff the deploy object across REST, GraphQL and MCP for a `config_change` deploy: same field, same name, same omission rule for image-backed services.
2. Confirm the dashboard's deploys list **and** deploy detail page both render it, and that the deploy-failure email's commit block (`docs/render-artifacts/notify-on-fail.md:70`) behaves sensibly now that config-change deploys have a commit — it includes the block "when the deploy has a commit", which is now true for a class of deploy where it previously was not. Decide whether that is right.
3. Review the 429 shapes and the new env knob against Render's documented rate-limit behavior.
4. Update `docs/ADR018-render-parity.md` and `docs/ADR006-bex-api.md`; file any residual drift as a w4 inbox note rather than fixing it here.
