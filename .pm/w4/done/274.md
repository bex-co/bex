# Untouched Build Filters keeps old paths after refresh and can undo a newer save

Why: an untouched editor presents old deployment filters as an unsaved change after receiving a newer saved configuration, and its enabled Save can overwrite that configuration.

**Severity:** major — explicit stale Save rolls back stored deployment configuration. **Estimate:** 55m (caller and baseline audit 10m, guarded draft synchronization 15m, behavior tests 20m, Simplify and owned live replay 10m). **Status:** open. Source: continuous functional `$qa-find-bugs w4`, pass a284, 2026-10-12 UTC, muse.env login helper.

Goal: dependable hosting configuration editing under [ADR008](../../docs/ADR008-vision.md) and [ADR004](../../docs/ADR004-app-deployment.md). Repair the existing Build Filters editor so newly received saved values update an untouched form while real local edits survive refresh.

## Reproduction and observed impact

Owned Free static fixture `qa-20261012-a284-filter`, `srv-db6b7bstcbqc73bkke30`: public repository `https://github.com/bex-co/bex`, main, root `examples/static-site`, publish `.`, harmless build command `printf qa-a284-build`, Auto-Deploy off.

2. Reload tab A at `/services/<id>/settings`. Its fresh API read returns the saved list. At **10:19:56.156Z**, the ready editor still shows those exact values with disabled Save. Make no edit in A.
3. Open ordinary tab B on the same owned service. Replace only the first included path with `examples/static-site/index.html`, then Save. The actual request and HTTP 200 response contain that newer path at **10:19:59.034Z**. Close B and foreground A.
4. A's ordinary Server poll returns the newer path. At **10:20:05.671Z**, its editor still displays `examples/static-site/**`, exposes Cancel, and enables Save. Correct fresh server data reached the mounted page; the untouched draft did not adopt it.
5. Without editing A, click its newly enabled Save. At **10:20:30.997Z**, the actual request submits the old wildcard and succeeds. An independent read at **10:20:32.108Z** confirms the saved filter has reverted. **An explicit stale Save overwrites B's successful configuration; no spontaneous write is claimed.**

Repeat from a freshly loaded **390×844** page: B uses the canonical `/static/<id>/settings` alias and changes only ignored paths from `**/*.md` to `docs/**` at **10:21:10.408Z**. ## Root cause and bounded fix

Research baseline: `a0b48d0401e4bb16d4175c58e0f97a37cc632904`. The preceding clean pull changed deployment pins and restart handling, with no Build Filters editor fix. Target history attributes the mount-only draft initialization to `f5eafcbaf`.

- `dashboard/src/features/services/components/build-deploy-section.tsx:413–419` derives current saved lists on each render but initializes draft only with `useState(current)`. After new saved props arrive, the old untouched draft differs from current and becomes falsely dirty. `:468–479` exposes Cancel and enables Save; `:421–425` submits that old draft as a complete replacement. Explicit Cancel's `setDraft(current)` works.
- The one production BuildFilterEditor mount at `:287–291` receives saved props from the one production BuildDeploySection mount in `routes/services.$serviceId.settings.tsx:200–212`. The page reads the Server document at `:93` with `poll:false`; the designated polling owner in `service-detail-layout.tsx:44` updates that same document. `use-server.ts:49–76` and `common/lib/polling.ts:3–18,47–60` provide 3-second converging and 30-second settled refreshes. The page correctly stays mounted and receives the new saved list.
- `features/services/lib/status.ts:173–181` maps nullable filter lists correctly. `use-build-filter.ts:24–36` sends the exact two lists through `useFieldMutation`; the actual mutation request, response and fresh API read agree. The shared mutation factory is not the draft owner. Its **15 production hook consumers** need no change for this fix.
- `lego/backend/internal/apps/graphql.go:1624–1637` delegates to `apps/service.go:4001–4021`, which replaces spec.buildFilter without a deployment bump. `:905–936` maps empty lists to null and normalizes valid globs. REST's update adapter in `rest.go:1000` and MCP's update adapter in `mcp.go:847` use the shared settings path (`settings.go:284–293`). Preserve these accepted replacement and clearing contracts.
- Installed React/react-dom **19.2.3**, Apollo Client **4.1.3**, and TanStack Router **1.170.25** were checked. React's installed `react-dom/cjs/react-dom-client.development.js:8264–8296` initializes the mount state; `:26503–26513` updates retained state rather than reusing the initial argument. The installed Apollo `react/hooks/useMutation.js:83–110` delegates to the client and returns accepted data; it supplies no editor synchronization. [React's primary reference](https://react.dev/reference/react/useState) confirms that later initial-state arguments do not reset state.

Implement guarded saved-baseline synchronization **locally in BuildFilterEditor**. An untouched draft matching its previous accepted baseline should adopt the latest received saved lists and remain clean. Preserve real local edits, focus, ordered rows and the latest saved value for Cancel. Keep trim/drop-empty normalization and successful local-save adoption, including protection for newer typing while a save is pending. Do not reset drafts unconditionally, key the editor by filter values, add another polling timer, change the API contract, or change the shared mutation factory. Verify identity reseeding and source-mode unmounting in the existing parent.

Production census: **one stateful editor implementation**, **one mount**, **one shared Settings page**, **two route entrypoints** (`/services/$serviceId/settings` and `/static/$serviceId/settings`). The static alias imports the same page at `routes/static.$serviceId.settings.tsx:2,27`. Repo-backed **web, static, cron, background worker and private service** use this editor through `lib/settings-sections.ts:59–70`; image-backed services have no build section. PostgreSQL and Key Value have separate settings and no BuildFilterEditor mount. PathList has **four production mounts**: two here and two controlled create-wizard lists at `services.new.tsx:387,400`. Keep those create lists unchanged. Both route entrypoints were used live on the static fixture; the other four service types and identity/source transitions were source-traced rather than live exercised.
