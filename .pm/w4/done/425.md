# A Hobby workspace's webhook create says "Fix the highlighted fields", highlights nothing, and drops the Pro-plan reason

Why: a Hobby user who fills in the webhook form can never succeed, and is told the form is wrong instead of that webhooks are a Pro feature. Nothing on the Webhooks pages mentions the plan.

Severity: major (the UI misstates why a core action fails and hides a coded, plan-named server answer). Estimate: ~45m. Source: live `/qa-find-bugs w4` loop run 42ca, 2026-10-27 UTC (`muse.env`, Hobby workspace `tea-daif693dqjvc73e7as3g`, dashboard pin `7d6ac874c51d`). Related: w8/m138 (the backend gate, t004 done). Its t011 is the request-logs sibling of this dashboard fix.

## Evidence

- `/webhooks/new`: Name `qa-20261027-42ca-hook`, URL `https://qa-20261027-42ca-echo.onbex.co/hook`, events Deploy Started + Deploy Ended, then **Create webhook**. The page shows `Fix the highlighted fields and try again.` plus `Couldn't create the webhook`. `document.querySelectorAll('[aria-invalid=true]')` is empty.
- The captured GraphQL response:

  ```json
  {"data":{"createWebhookEndpoint":null},"errors":[{"message":"webhooks require the Pro plan or higher; this workspace is on Hobby","path":["createWebhookEndpoint"],"extensions":{"code":"WEBHOOK_PLAN_LIMIT","plan":"hobby"}}]}
  ```

- `/webhooks` (empty list) reads "Add an endpoint to get notified when your services deploy, restart, or scale." It shows no plan notice, and the create form is fully enabled on Hobby.

## Cause

- `dashboard/src/features/webhooks/lib/errors.ts:18-60` `metadataByCode` has no `WEBHOOK_PLAN_LIMIT` entry. `toWebhookMutationError` makes it a `form`-field error, and `webhookErrorMessageKey` returns `null`. `use-webhook-form-feedback.ts:38-44` then shows the generic `webhooks.createError` fallback and discards `item.message`.
- `routes/webhooks_.new.tsx:139-143` and `components/webhook-settings-card.tsx:122-126` render `webhooks.formErrorsSummary` ("Fix the highlighted fields…") whenever `errors` is non-empty. That includes a lone `form` error, which highlights no field.
- Backend: `lego/backend/internal/webhooks/service.go:537` `PlanLimitCode`, which is correct and coded.

## Fix

- Map `WEBHOOK_PLAN_LIMIT` to a form-level message naming the plan ("Webhooks are available on the Pro plan and higher. This workspace is on Hobby."), with a link to Billing. Do the same for `WEBHOOK_ENDPOINT_LIMIT` if its copy doesn't already name the plan.
- Show the "Fix the highlighted fields" summary only when a **field** (name/url/events) has an error. A form-level error renders as its own alert. Apply this to both the create route and the settings card.
- On a Hobby workspace, `/webhooks` and `/webhooks/new` show the plan notice up front and disable Create, as w8/m138 t011 does for request logs. Render's dashboard gates webhooks to Professional and above ([features by plan](https://render.com/docs/platform-features-by-plan)). Read the workspace plan the way the other gated pages do.
- Tests: `WEBHOOK_PLAN_LIMIT` gives a plan message, no field summary and focus on the alert. A name conflict still gives a field error with the summary. A Hobby workspace renders the gated empty state.
