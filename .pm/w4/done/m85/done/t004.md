## Objective

Verify that role-aware disabled states preserve the existing cross-surface contract and align with Render's current role behavior wherever Render exposes an equivalent control.

## Context

- ADR018 marks Environment variables, Build Filters, managed Postgres lifecycle, and managed Key Value lifecycle as shipped capabilities.
- The server relations and error semantics are unchanged; the dashboard now prevents predictable unauthorized interaction earlier.
- Render may hide, disable, or omit controls by role. Any observed difference must be recorded rather than silently claimed as parity.

## Steps

1. Recheck the affected ADR018 rows and equivalent authenticated Render controls for a lower-privilege workspace role where available.
2. Confirm REST, GraphQL, and MCP continue to enforce the same relation and error shape while the UI derives its state from viewer capabilities.
3. Update durable parity evidence for the disabled-state behavior and file any larger drift as a bounded follow-up.

- [ ] Each affected UI control maps to the same server relation used by REST, GraphQL, and MCP.
- [ ] Equivalent Render role behavior is recorded from current evidence or explicitly marked unavailable for live comparison.
- [ ] No affected ADR018 cell overclaims parity and any substantive drift has an owning follow-up.

## Out of scope
