# 586 — A Postgres's revealed connection info keeps the Password field masked while the psql command and both connection strings print the same password in clear

Why: the masked Password field tells the user the secret is still hidden. Right below it, the psql command reads `PGPASSWORD=<the password> psql …`, and both connection strings carry it too. Anyone sharing a screen, or taking a screenshot, believes the password is covered when it isn't.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 136, 2026-11-11 20:38–20:50 UTC (`muse.env`, workspace `bex-canary`; release pin `8330744bd643`, pinned 20:02 UTC by `9126d59d7`). **Minor**: the user has asked to reveal, but the page contradicts itself about what is revealed. ~30m.
- **Fixture:** Free Postgres `qa-20261111-r136-pg` (`dpg-dbqd4iso6rds73e87ni0`), created in the dashboard with Public access switched on. It was available in about 2 minutes. Deleted afterwards (DELETE 204, then GET 404).
- **Probe:** `/databases/dpg-dbqd4iso6rds73e87ni0` → Connections → **Reveal connection info**. The accessibility snapshot reads:
  - `Password`, `button "Show password"`, `button "Copy Password"`, `code: ••••••••…` (masked);
  - `Internal connection string`, `code: postgresql://dpg_…_user:<password>@…` (in clear);
  - `External connection string`, `code: postgresql://dpg_…_user:<password>@dpg-dbqd4iso6rds73e87ni0.db.bex.co:5432/…` (in clear);
  - `psql command`, `code: PGPASSWORD=<password> psql -h dpg-dbqd4iso6rds73e87ni0.db.bex.co -U dpg_dbqd4iso6rds73e87ni0_user dpg_dbqd4iso6rds73e87ni0` (in clear).
  - This run's own transcript caught the password this way: a redaction aimed at the URLs missed the psql line. The database was deleted minutes later.
- **The rest of the journey worked:**
  - "Copy External connection string" → toast "Copied to clipboard".
  - The copied URL connected from outside: `psql "<url>"` → `current_user dpg_dbqd4iso6rds73e87ni0_user`, PostgreSQL 18, `pg_stat_ssl.ssl = t`.
  - The same URL with `sslmode=disable` was refused ("server closed the connection unexpectedly"). Refusal is correct (w9/m164); the bare close is not filed.
- **Root cause:** `RevealedInfo` (`dashboard/src/features/databases/components/connection-info-panel.tsx:78-109`).
  - `PasswordField` (`:150-`) keeps its own `shown` state, false by default.
  - The three `ConnectionField`s render `internalConnectionString`, `externalConnectionString` and `psqlCommand` verbatim, and each of those values embeds the password.
  - The masking rule therefore covers one of the four places the secret appears. w5/m8 t005 specified "masked password with show/copy" and copy buttons for the strings, but never said the strings must hide it too.
- **Fix (target behavior):**
  - **One state governs the password everywhere.** While the password is hidden, the connection strings render `postgresql://user:••••••••@host…` and the psql command renders `PGPASSWORD=•••••••• psql …`. Show password reveals every occurrence and Hide password masks every occurrence.
  - **Copy never changes:** each Copy button copies the full value whichever state is on.
  - **Masking is display-only:** replace the password substring when displaying, from `info.password`.
  - **Dashboard only.** The API keeps returning the full values behind `can_view_sensitive`; REST, GraphQL and MCP are unchanged.
  - en and zh are unaffected (no copy change).
- **Blast radius:**
  - `<ConnectionField` has 10 uses: 3 in this panel, 3 in `keyvalue/components/connection-info-panel.tsx`, 2 in `databases/components/access-control-panel.tsx`, 1 in `services/components/service-outbound-ips-panel.tsx` and 1 in `service-shell-page.tsx`.
  - Add the masking as an opt-in prop (for example `secret`) used only by this panel's three fields, so the other callers render as today.
  - **The Key Value panel is a separate decision.** It has no Password field (`keyvalue/connection-info-panel.tsx:32-33`), so it is consistent today. Whether Render masks its Key Value URLs belongs to the parity check, not this note.
  - **Tests:** `databases/components/__tests__/` — after Reveal, the password string appears in no text node until Show password; Copy on each field still copies the full value.
- **Unverified:** Render's dashboard masking of its Postgres Internal URL, External URL and PSQL Command. They are recalled as masked per field with an eye toggle, but this was not captured this run. If Render shows them in clear after one reveal, the alternative fix is to drop the separate Password mask, so that one Reveal reveals everything consistently.
