## Objective

Confirm the new refusal and the new read field are consistent across every surface that exposes them, and record the upstream comparison honestly in the parity ledger.

## Context

- bex-api is meant to be Render-compatible across REST, GraphQL and MCP ([docs/ADR006-bex-api.md](../../../docs/ADR006-bex-api.md)); the dashboard is the fourth surface ([dashboard/AGENTS.md](../../../dashboard/AGENTS.md)).
- The precedent to match exactly is `w8/m23`: one coded conflict, "identical across REST/GraphQL/MCP, naming the resource and owning blueprint", plus the server-issued confirm phrase and the dashboard's existing confirmation dialog. The blueprint-row conflict should be indistinguishable in shape from the resource conflict — same code family, same phrase mechanism, same preview surfacing — so callers handle one pattern.
- Upstream: Render permits multiple Blueprint instances per repository and does not enforce single-blueprint-per-resource either (it warns "max one Blueprint per resource; multi-Blueprint management ⇒ unpredictable behavior, last sync wins"). So both halves of this milestone are **deliberate bex divergences in the fail-closed direction**, which is the position ADR018's Blueprint row already states. The row's existing text is correct about resources and silently overstated about blueprints; update it so it covers the row-level guard too.
- The new resource field from t003 has no Render counterpart — label it a bex extension, as ADR018 does for `pushDeliveryMethod` and `generate_blueprint`.

## Steps

1. Diff the conflict payload across REST, GraphQL and MCP: code, message, the named blueprint, the confirm phrase. Assert them together, not in three per-surface tests.
2. Check the dashboard renders the refusal at `/blueprints/new` (preview) and offers the confirmation through the existing dialog rather than a new UI.
3. Diff the t003 field across REST/GraphQL/MCP, and against its list counterpart.
4. Update the ADR018 Blueprint row and the ADR006 field ledger; state the divergence as divergence.
5. Flag anything that cannot move together as follow-up rather than letting the surfaces drift.
