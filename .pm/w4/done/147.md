# Global search can't find a renamed service by its original name/slug, or a blueprint at all

Why: after a rename, the service's original name stays everywhere a user still sees it (its `.onbex.co` host, the `name:` a Blueprint manifest matches on, per `w4/121`), yet ⌘K finds it only by the new display name or the `srv-` id. Blueprints, a first-class sidebar resource, are not indexed.

Found live, `/qa-find-bugs` pass 171, 2026-09-25 (w4-targeted, `muse.env` credentials), read-only.

- **Repro:** ⌘K →
  - `block-eden-mono` → **no results**. That is the immutable name and slug of service `eden-dash-v3` (`srv-d9ndt8hmcglc739fkp50`), whose URL is `https://block-eden-mono.onbex.co`.
  - `discourse` → **no results**, although blueprint `discourse_docker` (`blp-d9nqg95cavls73fp8m10`) is listed on `/blueprints`.
- **Control, correct:** `beancount`, `forum-db`, `redis`, `eden`, `BEANCOUNT`, and exact ids (`srv-d9bj8s3eg85c7390eb9g`, `dpg-d9nqg95cavls73fp8m20`, `red-d9p49kdrtmes73c34ovg`) all narrow to true substring matches (the `w6/m50` fix holds). A nonsense term shows "No matching pages or resources."
- **Root cause:** `dashboard/src/common/components/dashboard-layout/global-search-dialog.tsx:175-180` matches services on `${r.name} ${r.id}` only, although the view already carries `immutableName` and `slug` (`features/services/lib/status.ts:40-41`). The dialog loads services, databases, key values, projects, and env groups (`:101-105`). Blueprints (and webhooks) are never fetched.
- **Fix:** add `immutableName`/`slug` to the service haystack (and to the option `value`, so cmdk's own filter agrees), showing the original name as secondary text when it differs. Add blueprints (name + `blp-` id) as a resource group. Decide explicitly whether webhooks belong.

Estimate: ~25m.

## Done (2026-09-27)

- The `Services` list query now selects `immutableName` and `slug`, regenerated offline via `TestDumpGraphQLSchema` + `SCHEMA_JSON=… yarn codegen`. The global-search service haystack and the cmdk item `value` include both. A renamed service found by its original name shows that name as muted secondary text beside the display name.
- Blueprints are a resource group (name + `blp-` id → `/blueprints/$blueprintId`).
- **Webhooks deliberately not indexed:** an endpoint is named by its URL, a workspace has a handful, and the Webhooks page is already a Navigation result.
- Tests: `dashboard-topbar.test.tsx` finds `block-eden-mono` → `eden-dash-v3`, and finds and opens `discourse_docker`. `global-search-dialog.test.tsx` mocks the new hook. Dashboard `yarn lint` + `yarn test` (448 files / 3722 tests) are green.
