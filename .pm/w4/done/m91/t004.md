## Objective

Confirm the `disk_capacity` change is consistent across REST, GraphQL, MCP, and the dashboard, and matches render.com's behavior for managed-datastore disk usage.

## Context

- bex-api is Render-compatible (ADR006). `disk_capacity` is exposed on REST `/v1/metrics/disk-capacity`, GraphQL `datastoreMetrics`, and MCP `get_datastore_metrics`.
- Render shows managed-Postgres disk usage against the plan's (logical) disk size, not the raw physical volume.

## Steps

1. Verify all three API surfaces return the logical capacity with identical values and shapes.
2. Verify the dashboard renders it consistently with Details "Storage" and autoscaling.
3. Compare against render.com's managed-Postgres/KeyValue disk metric; record any deliberate divergence in `docs/ADR018-render-parity.md`.

## Acceptance criteria

- [ ] REST/GraphQL/MCP agree on `disk_capacity` (logical bytes).
- [ ] Dashboard matches. Render comparison recorded; no silent divergence.

## Out of scope

- New metrics beyond `disk_capacity`.
