## Objective

Make the user-facing `disk_capacity` DatastoreMetrics value report the datastore's **logical** provisioned disk size (the plan/`StorageGB` the user is billed for and autoscaling uses), instead of the physical PVC capacity `kubelet_volume_stats_capacity_bytes`, which on Hetzner is a fixed 10 GiB floor regardless of the logical size.

## Context

- `lego/backend/internal/metrics/source.go:441-442` — `NewPrometheusDiskUsageSource`; the `MetricDiskCapacity` branch selects `kubelet_volume_stats_capacity_bytes`. The `disk` (used) branch selects `kubelet_volume_stats_used_bytes` and must stay as-is.
- The logical size is available on the datastore views: Database `diskSizeGB` (operator sets CNPG `spec.storage.size` from it — `lego/operator/internal/controller/database_controller.go:149`), KeyValue `StorageGB` (`lego/backend/internal/keyvalue/service.go:155`, `tiers.go:39`).
- Live proof of the bug: `dpg-d9nqg95cavls73fp8m20` (logical 1 GB) and `dpg-d9rs3ee0ccis738kc7c0` (logical 5 GB) both report capacity 10 GiB.
- The `PersistentVolumeFillingUp` Prometheus alert (referenced in the `source.go` comment) legitimately uses physical capacity — do NOT change it.

## Steps

1. Decide the shape: `disk_capacity` becomes the logical size sourced from the datastore spec/view rather than a Prometheus query. Keep it a `[]MetricSeries` (a flat/constant series at `StorageGB * 1 GiB`) so REST/GraphQL/MCP wire shapes are unchanged and the dashboard reference line still reads `latestValue(series)`.
2. Thread the logical size into the metrics service where the datastore is resolved (the caller already knows the resource id/kind), so `disk` stays kubelet-backed and only `disk_capacity` changes source.
3. Confirm REST `/v1/metrics/disk-capacity`, GraphQL `datastoreMetrics(metric: DISK_CAPACITY)`, and MCP `get_datastore_metrics` all return the logical bytes identically.
4. Leave `PersistentVolumeFillingUp` and any other ops alert on `kubelet_volume_stats_capacity_bytes` untouched.

## Files

## Acceptance criteria

- [ ] `disk_capacity` for a 1 GB Postgres returns ~1 GiB (bytes); for a 5 GB Postgres ~5 GiB — not 10 GiB.

- [ ] REST, GraphQL, and MCP return byte-identical `disk_capacity`.
- [ ] `PersistentVolumeFillingUp` still evaluates physical capacity (unchanged).
