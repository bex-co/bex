## Objective

Change the hosting namespace's same-namespace allow, and each isolated environment's boundary, so that a pod admits private traffic only from pods with the same region and environment scope, and sends private traffic only to them.

## Context

- `sameNamespaceNetworkPolicy` (`lego/backend/internal/store/namespaces.go:934-951`) is one `allow-same-namespace` policy. It selects every pod outside isolated environments.
- `environmentIsolationPolicies` (`:962`) writes one `isolate-<env>` per isolated environment.
- Pruning: `pruneManagedNetworkPolicies` and `isolatedEnvironmentLabel` (`:953-955`). A policy name that changes must be pruned only after its replacement exists, so traffic is never cut in between.
- The send-only and free-plan denials (`deny-send-only-private-ingress`, w6/m640 and w8/m130) stay as they are.
- Tenant admission control (ADR045) confines what bex-api may write in a tenant namespace. Check the new policies pass it.

## Steps

1. Write one allow per region present in the workspace, or per Render region, as t001 chose. A pod without a label falls in the platform alias's allow.
2. Split each isolated environment's boundary by region the same way.
3. Converge without a gap: create the new policies, then prune the old ones.

## Files

- `lego/backend/internal/store/namespaces.go`

## Acceptance criteria

- [x] Same region and same scope is admitted. Different regions are refused, with or without environments.
- [x] Environment isolation within a region is unchanged.
- [x] Converging from today's set never drops traffic between same-region pods.

## Out of scope

- Cross-workspace traffic, which stays refused as today.
