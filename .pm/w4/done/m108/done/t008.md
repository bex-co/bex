## Objective

Add tests that would have caught each of this milestone's findings, asserting real behavior and failure modes.

## Context

Every finding here survived because nothing asserted the property it violated — a rate was indistinguishable from a count in a unit test that only checked "a number came back", and the public-repo deploy path had no test that asked what a deploy row carries when no GitHub connection exists.

## Steps

1. **Query shape (`t001`, `t003`).** Assert the built PromQL/LogQL strings for `http_requests` (and bandwidth, per `t003`'s decision) use the count primitive over the step, for the grouped, status-filtered and host/path-filtered branches. A golden-string test is appropriate here — the bug was in the query text.
2. **Unit truthfulness.** A test that, given a synthetic source returning a known number of requests in a window, asserts the service returns that number and declares `unit: "count"` — so a future switch back to `rate` fails loudly.
3. **Cross-surface (`t006`).** Assert REST, GraphQL and MCP return identical values for the same window, in the style of the existing `TestPercentageCrossSurfaceParity`.
4. **Commit resolution (`t004`).** Cover, as separate cases: public repo with no connection → commit present; private repo with no connection → deploy opens, `commit` omitted; unknown ref → omitted; provider error/timeout → omitted and the deploy still opens and is not delayed. Include the create-path and blueprint-redeploy callers, not only `Trigger` — the callers that behave correctly today need regression cover too.
5. **Dashboard (`t002`, `t005`).** Test the Total Requests aggregate at 0, 1 and N requests (keeping `w6/028`'s singular/plural and zero-gate behavior), and assert the rollback label's text equals the literal deploy id with no CSS-dependent casing.
