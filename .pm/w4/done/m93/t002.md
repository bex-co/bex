## Objective

Make the new native environment projection safe for multiple services sharing a group, same-named Apps in different workspaces, and deletion/recreation. Keep changes limited to native build preparation.

## Steps

1. Use a deterministic App-lifetime/build identity for the merged destination, not the shared `<evg>-env` source name. Read only in the owning App namespace; retain protected-source checks. Never relax copyCloneSecret's foreign-owner rejection to make group copies work.
2. Inspect `execution.ArtifactIdentity` (`execution/artifacts.go:27-54`) and `copyCloneSecret` (`controller/app_controller.go:1594-1637`). Preserve App UID labels and checked overwrite. Group source secrets intentionally have no App owner (`backend/internal/envgroups/service.go:1720-1740`); do not adopt/delete that shared source.
3. Wire the merged secret into existing inventory: `build/artifacts.go:119-127` allows copied-secret components and :156-166 inventories Secrets by ownership; `reclaimAppExecution` (`app_controller.go:4430-4454`) invokes ReclaimAppArtifacts before the known-name loop. Check pending own-secret references, changed/unlinked group sets, cancelled/retried builds, and finalization for both same and separate build namespaces. Ensure old candidate cleanup cannot delete a newer candidate's mounted input.
4. Enumerate and exercise the shared native callers from t001. Scope globally within native builders; runtime envFrom's three consumers, clone credentials, Dockerfile and kpack contracts remain intact. Check release/artifact fingerprint classification for group-reference changes without encoding secret bytes.
