## Root cause and fix

- `lego/backend/internal/envgroups/service.go:959-995` linkFetched correctly appends `<group>-env` to App.Spec.EnvFromSecrets and rolls the service. Its `upsertSecret:1727-1740` projects exact bytes into the group's owner namespace. Runtime `envFromSources` in `lego/operator/internal/controller/app_controller.go:3546-3570` correctly orders group secrets before the own service secret.
- The native build path at `app_controller.go:800-821` instead selects only `runtimeEnvSecret(app)` (own spec reference or pending-own annotation, :3621-3626), relocates that single secret, and sets Options.RuntimeEnvSecret. Groups are not passed. `build.Options` at `build/build.go:338-342` has only that one secret; BuildJob :918-923 mounts it; nativeBuildPreparer `build/native.go:145-169` reads only that directory plus selected literal Env. No decoder can recover an omitted source.
- Kubernetes dependency inspected: `k8s.io/api v0.35.0/core/v1/types.go:2954-2958` defines ordered envFrom with later sources overriding earlier ones, and explicit Env overriding envFrom. App contract `lego/types/v1alpha1/app_types.go:519-527` names the group-before-own ordering and optional group-secret references. Thus the passing control has the expected cause, not a UI workaround.
- Project a native-build-only, App-owned merged secret from the same ordered group and own source references, using uncached reads in the App namespace. Preserve exact bytes, later-group ordering, own-secret precedence, and the existing explicit-literal precedence. Feed the merged reference through the current native secret transport; keep reserved PORT/BEX_NATIVE handling and the codec fixed by m92. A missing optional group follows the existing runtime optional-source contract; a missing required own secret, read denial, timeout, or invalid protected source is an explicit build failure, not an empty successful bundle.
- Do not use an env-group's globally shared name as an App-owned copied secret: `copyCloneSecret:1594-1637` checks destination App UID ownership. Two services linking one group would otherwise collide. t002 owns the naming, security, inventory and lifetime consequences.
- Group names also belong in native artifact-input semantics when referenced by a direct App edit; inspect `release_identity.go:124-132,155`. Existing API links already bump restartedAt and did rebuild in the live test. Do not put secret contents in fingerprints, App spec, image metadata, generated Dockerfiles, or logs. This is an operator projection fix; backend storage/reveal/link contracts remain authoritative.

## Blast radius, aliases, and limits

Exhaustive production grep: nativeDockerfile has one caller (nativeBuildPreparer); nativeBuildPreparer has one caller (BuildJob); Options.RuntimeEnvSecret has one controller initializer. Runtime envFromSources has three consumers: Deployment projection (:209), cronPodSpec (:3363), predeploy options (:4166). Those runtime consumers already include groups and should retain behavior.

Group linking reaches the same App projection from REST `POST /v1/env-groups/{id}/services/{serviceId}` (rest.go:176), GraphQL linkEnvGroup (graphql.go:370), MCP link_env_group (mcp.go:262), the Blueprint LinkEnvGroup seam (service.go:1265, apps/deploy.go:885), and create-time prelinks (service.go:625). linkFetched has two callers (LinkService and the Blueprint seam); create-time prelink is a separate App writer. Do not fix only a dashboard link action.

Native web/private/worker/cron/static use the build mechanism (static defaults to Node). Postgres and Key Value do not use native App builds. Dockerfile and explicit kpack builds retain their separate documented env contracts. Only Go web, dashboard group create/link, manual deploy, GraphQL own-value write/read, and external HTTP were live tested. Other runtimes, service kinds, multiple groups, optional missing sources, direct App edits, group-edit fanout, REST/MCP mutations and Blueprint prelinks remain verification work, not observed failures.

No API error taxonomy changes: existing unauthenticated/forbidden/not-found guards and fresh sensitive authorization on links remain; never broaden cross-workspace lookup to make a missing source resolve. During a rebuild, the old healthy revision keeps serving until the new revision is ready. A projection failure must fail the candidate build without replacing the old environment or claiming Live.
