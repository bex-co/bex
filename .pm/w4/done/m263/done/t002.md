## Objective

Every non-dashboard way to change a Key Value's plan states that it restarts the store and that a Persistence Off store loses its data. Behavior stays Render's: the change is accepted without a confirmation.

## Context

- REST `PATCH /v1/key-value/{id}` `plan`: `lego/backend/internal/keyvalue/rest.go:366`.
- GraphQL `updateKeyValuePlan`: `keyvalue/graphql.go:231`.
- MCP `update_key_value`: description at `keyvalue/mcp.go:173` says only "a plan change is billable".
- Blueprint `plan`: `apps/blueprint_plan.go:594-595`, reached by sync and the auto-sync worker.
- w4/358's Blueprint refusal (`keyvalue/service.go:1124-1130`) is the stricter precedent for an unattended data-emptying change.

## Steps

1. Extend the MCP and GraphQL descriptions.
2. Decide the Blueprint case against Render's Blueprint behavior for a plan change. If Render just restarts, describe it in ADR021. If you refuse, follow w4/358's shape and record why.
3. Add an ADR021 paragraph: what a plan change does per persistence mode, why the API takes no confirm (parity), and the dashboard's confirmation.

## Files

- `lego/backend/internal/keyvalue/mcp.go`, `keyvalue/graphql.go`
- `docs/ADR021-keyvalue-management.md`
