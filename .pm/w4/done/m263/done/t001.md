## Objective

The Key Value Instance type card and its confirm dialog say what a plan change does: the store restarts and is unavailable for a minute or two, and a Persistence Off store loses every key. An Off store's Save requires the typed `sudo clear key value <name>` phrase that the Persistence Mode card already uses.

## Context

- `dashboard/src/features/keyvalue/locales/en.ts:506-509` `keyvalue.planDescription`, `:523-526` `keyvalue.planPickerConfirmBody`, plus their `zh.ts` twins.
- `dashboard/src/features/keyvalue/components/key-value-plan-section.tsx:118-136`: a plain `ConfirmDialog`, `destructive={false}`.
- Precedent: `key-value-persistence-mode-section.tsx:131` (typed phrase), and the Maxmemory card's "Saving restarts the store, so connections drop for up to a minute".
- `KeyValueView` carries the persistence mode and suspended state. A suspended store gets no prompt.

## Steps

1. Rewrite `planDescription` and `planPickerConfirmBody` (en and zh) without "operator", "reconcile" or "preserves data".
2. For `persistenceMode === "off"` and not suspended, use the typed-phrase confirm, matching the persistence section's component and phrase, with destructive styling. Otherwise keep a plain confirm with the restart wording.
3. Keep the price line.
