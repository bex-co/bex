# 040 — Generate Blueprint cannot export env-group linkage (`fromGroup` / `envVarGroups`), breaking round-trip for stacks that use env groups

Why: w8/m22 shipped "Generate Blueprint" on the premise of a **no-op round trip** (export a stack → re-apply → same stack). That premise fails for any stack that uses environment groups: the generator emits no `fromGroup` links and no root `envVarGroups`, and offers no way to select env groups — so re-applying a generated manifest recreates services **without** their shared env-group config. Import supports env groups fully (ADR018:277 done); export does not — an undocumented import/export asymmetry on the ADR049 render.yaml parity surface.

Found in a live `/qa-find-bugs` hunt of `dashboard.bex.co`, 2026-09-02. **Code-confirmed; live symptom NOT reproduced** (repro needs linking a group to a service — a mutation on a resource this hunt didn't create, so out of bounds). Verify live, then promote to a milestone.

## What I verified live (control: a stack WITHOUT env groups round-trips fine)

On `/blueprints` → Generate Blueprint, exporting `tianpan-v4-web` produced a faithful `render.yaml` (name/type/runtime/repo/rootDir/buildCommand/startCommand/plan/healthCheckPath all matched the REST `GET /v1/services/{id}`; `branch` correctly omitted because it equals the default, `autoDeploy` correctly omitted because it's on). So the generator is faithful for the fields it emits — the gap is specifically env groups, which this service doesn't use.

## Root cause (code)

- `lego/backend/internal/apps/blueprint_generate.go`:
  - `GenerateBlueprintRequest` (lines 48-53) has `ServiceIDs` / `PostgresIDs` / `KeyValueIDs` — **no `EnvGroupIDs`**, so env groups can't be selected for export, and no root `envVarGroups` block is ever emitted (`GenerateBlueprint` builds `doc` with only `services` + `databases`, lines 144-154).
  - `generateEnvVars` (lines 292-324) iterates only `a.Spec.Env` (direct vars) + `s.EnvNames.ListEnvVarNames` (the service's own mutable-store names). It emits `fromDatabase`/`fromService` reference forms for **datastores** in the selection (lines 305-308) but has **no `fromGroup` branch** for env-group linkage.
- Env-group linkage is stored as `App.Spec.EnvFromSecret` and merged from the linked group's Secret at the operator level (`lego/backend/internal/secrets/files.go:445`), i.e. **not** projected into `a.Spec.Env` — so the group's vars are invisible to `generateEnvVars`. Result: the `fromGroup` linkage (and likely the group's var names) are dropped from the export entirely.
- Import supports both forms: `fromGroup` at `blueprint_compiler.go:471` + `deploy.go:399` (`FromGroup`), `LinkEnvGroup`/`applyStackEnvGroups` (`deploy.go`); root `envVarGroups` and `projects[].environments[].envVarGroups` are done (ADR018:277, w1/m35; ADR018:278, w2/m40). So this is a one-sided (import-only) capability.

## Fix (name the target behavior)

Make Generate Blueprint round-trip env groups: (1) add `EnvGroupIDs` to `GenerateBlueprintRequest` (REST `POST /v1/blueprints/generate`, GraphQL `generateBlueprint`, MCP `generate_blueprint`) and emit a root `envVarGroups` block for selected groups; (2) emit a per-service `envVars: - fromGroup: <name>` entry for each env group linked to an exported service whose group is in the selection (mirroring the existing `fromDatabase`/`fromService` reference handling); unselected linked groups degrade to a stated fallback (dangling-free), consistent with how unselected datastores degrade to `sync: false`; (3) add env-group multi-select to the dashboard Generate dialog. Keep the existing self-validation (the generated manifest must still pass the real compiler+parser).

## Blast radius

Backend `blueprint_generate.go` (generator + request struct) → REST/GraphQL/MCP `generate*` (one core change, three surfaces). Dashboard `blueprints` Generate dialog (add env-group selection). No import-side change (import already supports it). The self-validation gate at `GenerateBlueprint` (lines 162-170) already guards against emitting an unparseable manifest.

## Resolution (2026-09-03)

Generate Blueprint now exports env-group linkage end to end:

- `GenerateBlueprintRequest.EnvGroupIDs` on REST/GraphQL/MCP; `EnvGroupExportSource` seam (`envgroups.ExportEnvGroup`) returns name + key names (never values).
- Selected groups emit root `envVarGroups` (`generateValue: true` per key) and per-service `fromGroup: <name>` from `App.Spec.EnvFromSecrets`.
- Unselected linked groups degrade to `sync: false` keys (dangling-free, same pattern as unselected datastores).
- Dashboard Generate dialog gains env-group multi-select via `useEnvGroups`.
- Tests: round-trip / unselected degrade / env-group-only selection + dialog `envGroupIds` assertion; self-validation gate unchanged. Implemented as inbox (clear named fix) rather than promoting to a milestone.
