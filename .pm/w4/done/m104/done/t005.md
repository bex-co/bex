## Objective

Confirm the autoscaling contract now reads the same on REST, GraphQL and MCP, and that the canonical wire shape matches Render's published one.

## Context

- The pinned contract is the reference: `PUT /services/{serviceId}/autoscaling` requires `{enabled, min, max, criteria{cpu{enabled,percentage}, memory{...}}}`. bex's GraphQL uses `minInstances`/`maxInstances`/`targetCPUPercent`, which is a deliberate native dialect — that is fine, but it must be recorded as such rather than left looking like drift.
- The **response** shape needs the same check: `renderAutoscaling` (`internal/apps/render.go:182-190`) answers `minInstances`/`maxInstances`; compare against the pinned response schema for this endpoint and reconcile.
- `docs/ADR018-render-parity.md`'s autoscaling row currently rests on an implementation where only GraphQL works. Update it to say what is true after t001.

## Steps

1. Diff request and response shapes for autoscaling across REST, GraphQL and MCP against the pinned schema; record each intentional divergence.
2. Update `docs/ADR018-render-parity.md` and `docs/ADR006-bex-api.md`.
3. If t002 reclassified other routes, note any parity consequences in the same pass.
4. File residual drift as a w4 inbox note rather than fixing it here.
