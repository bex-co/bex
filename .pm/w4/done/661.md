# 661 — A git push, a configuration change that rolls a release, a Blueprint sync or a build-source fan-out still cancels a Rollback, Restart or image-override deploy in progress, where Render's Wait lets it finish

Why: under Render's default Overlapping Deploy Policy, **Wait**, "Only one deploy can run at a time per service" and the in-progress deploy finishes before "the most recently triggered deploy" runs ([render.com/docs/deploys](https://render.com/docs/deploys)). w4/652 holds a selected release (Rollback, Restart, an `imageUrl`/`imgURL` override) at the row level while another deploy is in flight, and holds bex-api's own deploy verbs (Manual Deploy, API, deploy hook, "Save, rebuild, and deploy") behind a selected release in flight. The other release writers still replace one.

- **Source / severity / estimate:** `/loopx w4` closeout of w4/652 (2026-11-14), recorded open in ADR018's List / get deploy objects row. **Minor** (the final state is the newest request, as under Override). ~4h; promote to a milestone if taken.
- **Gap, from the code:**
  - A git push (`apps/service.go`, the `new_commit` path), a rolling configuration save (`rollout.Tracker.Patch`/`PatchLocked`), a Blueprint sync and a build-source fan-out (`deploys/build_sources.go`, `TriggerParams.build`) write the App CR at once.
  - The operator never pins a selected release: `releaseInFlight` returns false when `status.selectedReleaseGeneration` is the release in flight (`lego/operator/internal/controller/release_identity.go`), and `heldReleaseView` has no view for one, so the newer release replaces it and the reconciler closes its row `canceled`.
- **Fix (target):** let the operator pin a selected release once adopted, as w4/635 does a saved image: the held view must carry the adopted `spec.releaseConfig` and keep `ActiveReleaseConfig` resolving to it while the saved spec has moved on. Then bex-api's row-level hold for deploys behind a selected release (w4/652) can go.
- **Tests:** a push, an env save and a Blueprint sync behind a rollback rolling out leave it to go `live`, then run; a selected release not yet adopted is still replaced.
- **DoD (live):** on a Free repo-backed service, roll back, and while the rollback reads `update_in_progress` push a commit: the rollback goes `live`, then the push's deploy runs. Delete the fixture.
- **Closed 2026-11-14 (/loopx w4):** Premise held (`releaseInFlight` refused a release whose `status.selectedReleaseGeneration` was the one in flight, and `heldReleaseView` gave none while the saved spec selected). The operator now pins a selected release (Rollback, Restart, image override, env reuse) once it has adopted it, as w4/635 does a saved image: `selectedRelease` joins `pinnableRelease`; a selection with a source generation records its adopted spec when `ensureSelectedReleaseConfig` materializes its record (`recordAdoptedRelease` no longer writes that record first); `heldReleaseView` gives a view to a selected release in flight and yields only to a saved selection of a newer release; and `App.ActiveReleaseConfig` (types) keeps resolving a selection the operator adopted and still runs while a newer requested release waits, so the view renders its own image and settings. A selection not yet adopted, one without a recorded view, and every release under the Override policy (w4/653) are still replaced. bex-api's row-level hold for its own deploys behind a selected release stays, since it also covers a selection the operator has not adopted yet; comments updated. ADR018's List / get deploy objects and Rollback rows amended. Follow-ups filed: w4/667 (an env "Save and deploy" on a Git-backed service selects the served build at save time and still replaces the release in flight) and w4/666 (canceling a deploy queued behind a selected release in flight still ends it too). Tests: `TestSelectedReleaseRollingOutWaitsForTheNewerDeploy` (pinned on its view; replaced with no view, once served, before adoption, under Override), envtest table "a Rollback rolling out serves before the newer deploy rolls out" (a deploy that clears the selection, and a configuration save that leaves it), the types expiry test extended. `GOWORK=off make -o test-tool-download test` and backend `go test ./...` pass. Live DoD replays after the next production deploy.
