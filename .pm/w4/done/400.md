# 400 — Changing a service's instance type never shows a price: the plan cards and the "Change instance type?" confirmation omit it, unlike create and the datastore plan pickers

Why: the service Plan tab is a purchase path. Moving a Free service to Pro Ultra starts billing at $315/month after a confirmation that only says the service "resizes and rolls with no downtime". The same dashboard shows the price on the service create form and in both datastore plan-change confirmations.

**Severity:** minor (billing transparency on a purchase path; the plan change itself is correct). **Estimate:** ~30m. **Source:** live `/qa-find-bugs w4` loop run g9b4, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `29d63e1f7bea`). Read-only on the pre-existing Free service `hello-go` (`srv-daif6dsmg29s73d1umvg`). No plan was selected or saved, and nothing was bought. Session revoked.

## Probe

- `/services/srv-daif6dsmg29s73d1umvg/plan` ("Pick an Instance Type"): the seven cards read `Free 512 MB (RAM) 0.1 CPU`, `Starter 512 MB (RAM) 0.5 CPU` … `Pro Ultra 32 GB (RAM) 8 CPU`, with **no price anywhere on the page**.
- `/services/new?type=web_service`: the same seven types read `Free $0.00/month …`, `Starter $4.90/month …`, `Standard $17.50/month …`, `Pro $59.50/month …`, `Pro Plus $122.50/month …`, `Pro Max $157.50/month …`, `Pro Ultra $315.00/month …`.
- The confirmation the Plan tab's Save opens (code, not clicked live because it would purchase): `services.planPickerConfirmTitle` "Change instance type to {name}?" plus `services.planPickerConfirmBody` "The service resizes and rolls with no downtime…". No price.

## Root cause

- `dashboard/src/features/services/components/instance-type-picker.tsx:44-50` deliberately omits price: "bex cards omit price (billing is separate from this resource catalog)". That rationale is stale, because the same catalog hook now carries `monthlyUsd` ("Always-on 730-hour estimate from bex-api's canonical price sheet", `features/services/hooks/use-instance-types.ts:13-14`).
- The confirm dialog (`instance-type-picker.tsx:180-193`) passes `planPickerConfirmBody` with no price.
- Controls already render it:
  - `databases/components/database-plan-section.tsx:162-163` appends `databases.planPickerConfirmPrice` to the Postgres plan confirm.
  - `keyvalue/components/key-value-plan-section.tsx:119` does the same for Key Value.
  - `databases/components/create-database-dialog.tsx:312-313` shows `common.pricePerMonth`.

## Fix (target behavior)

- Each service plan card shows its monthly price from `monthlyUsd` (`common.pricePerMonth`), as the create form and Render's instance-type picker do. The confirmation adds "This instance type costs {price}/month", mirroring the datastore confirm. en + zh.
- Remove the stale "omit price" comment. Card height must not shift (w4/m196's grouped skeleton reserves the row).
- Tests: the card and the confirm show the catalog price; a missing price renders no "$" (not "$undefined").

**Unverified:** Render's exact card wording (the picker comment says it was captured live; the public docs don't describe it).
