## Objective

Confirm the new refusal and its `confirm` argument are identical on every surface, and record the divergence honestly in the parity ledger.

## Context

- bex-api is Render-compatible across REST, GraphQL and MCP ([ADR006](../../../docs/ADR006-bex-api.md)); the dashboard is the fourth surface.
- **This whole mechanism is a documented bex divergence, not Render parity.** ADR032 records it: _"Render uses role enforcement for protected Environments, whereas bex's current backend uses an explicit typed retry for an authorized caller."_ So the parity work here is *internal* consistency plus keeping that ledger entry accurate as the verb set grows — the same shape as `pushDeliveryMethod`'s "parity is internal, not upstream" note in ADR018.
- The precedent to match is `suspendService(id, confirm)` and the existing protected error string, which the dashboard already parses.

## Steps

1. Diff the refusal payload for each newly guarded verb across REST, GraphQL and MCP: error class, message, the phrase. Assert them together, not per surface.
2. Diff the `confirm` argument's name and position against the existing guarded verbs.
3. Check the MCP tools carry the argument in their schema so an agent can discover it.
4. Update ADR032's `protectedStatus` bullet and the ADR018 Environments row with the final verb set.

## Files

- `lego/backend/internal/apps/` (REST, GraphQL, MCP)
- `docs/ADR032-environments.md`, `docs/ADR018-render-parity.md`

## Acceptance criteria

- [x] The refusal is byte-comparable across the three APIs for every newly guarded verb.
- [x] `confirm` is named and typed identically to the existing guarded verbs on all three.
- [x] The MCP tool schemas expose it.
- [x] Both ADRs name the final set.

## Out of scope

- Changing the confirmation mechanism to Render's role-based model — that is the documented divergence, not a defect.

## Outcome (2026-09-21)

Parity: confirm is optional on all three surfaces; TestM126_GuardedMutationsAcceptConfirm pins the GraphQL half so a guarded verb cannot ship unconfirmable. The CLI has no protected-confirmation surface at all (not even for delete), so nothing to mirror there.
