# Flaky deploy gate: `TestStatusWriterKeepsHijackerAndReaderFrom` reads metrics before the middleware records them

Why: deploy run `37422791965` (head `a006a7e32`, w5/m118, 2026-10-06 ~06:18Z) failed `test-backend / go test ./...` on this test alone, and w5/m118 changed nothing in the metrics middleware. A race in the test can fail any deploy at random until the next push re-runs it.

- **Evidence:** `httpmetrics_test.go:528: hijacked upgrade was not counted as 101 (samples: [bex_api_http_in_flight_requests{surface="internal"}])`; `FAIL github.com/bex-co/bex/lego/backend/internal/api 18.187s`. The only sample present is the in-flight gauge.
- **Root cause (test-side race):**
  - In `lego/backend/internal/api/httpmetrics_test.go:485-530` the handler writes the 101, closes the hijacked conn, and sends on `hijacked` while still inside `ServeHTTP`. The test unblocks on `<-hijacked` and gathers samples immediately.
  - The middleware (`lego/backend/internal/api/httpmetrics.go:217-246`) decrements in-flight (`:236`) and increments `bex_api_http_requests_total` (`:244`) only after `next.ServeHTTP` returns (`:234`). So the test can observe the pre-return state, exactly what the failing capture shows (in-flight still present, no requests sample).
- **Fix:** make the test wait for the middleware, not the handler. Either poll `gatherSamples` until the 101 sample appears (bounded, e.g. 2 s), or wrap `metrics.InternalMiddleware(mux)` in an outer handler that signals after it returns, and wait on that. No production change: counting after `ServeHTTP` is correct. Run `go test -race -count=200 -run TestStatusWriterKeepsHijackerAndReaderFrom ./internal/api` before and after to show the flake and its absence.
- **Blast radius:** test only. Other `httpmetrics_test.go` cases that gather samples after a hijack or stream should be checked for the same pattern.
- **Estimate:** ~20m.

**Already fixed by `7e1ae3642` (2026-10-05):** the test now wraps `metrics.InternalMiddleware(mux)` in an outer handler that signals after the middleware returns and waits on that before gathering samples (`httpmetrics_test.go`, comment cites w4/210). Re-verified 2026-10-08: `go test -race -count=50 -run TestStatusWriterKeepsHijackerAndReaderFrom ./internal/api` passes.
