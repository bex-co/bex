# 626 — A web service's REST read omits `serviceDetails.healthCheckPath` and `buildPlan`, two fields Render's schema marks required, so a schema-strict Render client cannot parse a bex service

**Absorbed 2026-11-13 into [w10/m373 t002](../../w10/blocked/m373/done/t002.md)** (`/pmx them all to w10`, from `/pm-brainstorm for w10`). **Not fixed yet:** the fix and its live DoD ship with that milestone; this note keeps the original evidence.

Why: Render's `webServiceDetails` lists `healthCheckPath` and `buildPlan` as **required**. bex drops `healthCheckPath` whenever it is unset, and never sends `buildPlan`. A typed client generated from Render's OpenAPI with required-field validation rejects every service read, or treats the service as malformed. ADR018 records the omission ("omits empty values rather than sending defaults it cannot state") without the user's sign-off. Both values are statable: an unset path is `""`, and Render's default build plan is `starter`.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 259, 2026-11-13 03:53–03:58 UTC (`muse.env`, workspace `bex-canary`; pin `8acf1d116941`). **Minor** (API shape; the pinned Render CLI and lenient clients ignore missing keys). ~30m.
- **Fixture:** Free web service `qa-20261113-r259-api` (`srv-dbr8jg2shdos73f2f6f0`), created by `POST /v1/services` (`docker.io/traefik/whoami:v1.10`, `dockerCommand: /whoami -port 10000`). Deleted afterwards (`DELETE` 204, then `GET` 404).
- **Probe:** `GET /v1/services/srv-dbr8jg2shdos73f2f6f0` →
  - `"serviceDetails":{"cache":{"profile":"no-cache"},"env":"image","envSpecificDetails":{"dockerCommand":"/whoami -port 10000"},"ipAllowList":[…],"maintenanceMode":{…},"maxShutdownDelaySeconds":30,"numInstances":1,"openPorts":[],"plan":"free","region":"frankfurt","renderSubdomainPolicy":"enabled","runtime":"image","url":"https://qa-20261113-r259-api.onbex.co"}`
  - so there is **no `healthCheckPath` and no `buildPlan`**.
  - Every other required key is present: `env`, `runtime`, `envSpecificDetails`, `plan`, `region`, `numInstances`, `openPorts`, `url`.
  - Top-level required keys are all present (`dashboardUrl` `https://dashboard.bex.co/web/srv-…` redirects to the service page).
- **Render:** [Retrieve service](https://api-docs.render.com/reference/retrieve-service), read 2026-11-13. `webServiceDetails` required: `env`, `runtime`, `envSpecificDetails`, `plan`, `region`, `numInstances`, **`buildPlan`**, **`healthCheckPath`**, `openPorts`, `url`.
- **Root cause:** `renderServiceDetails` (`lego/backend/internal/apps/render.go:457`).
  - It emits `healthCheckPath` from the `{key, value}` list (`:492`) only `if field.value != ""` (`:494`).
  - It has no `buildPlan` key at all.
  - The rendertest suite records both as allowed divergences (`lego/backend/internal/rendertest/allowlist.go:66-90`, `details(SuiteAPI, "buildPlan", …, "healthCheckPath", …)` on list, retrieve, create and update service), under ADR018's "Partial serviceDetails projection" row (`docs/ADR018-render-parity.md:296`).
- **Fix (target behavior):** every service read (list, retrieve, create and update responses) carries each key Render's union member for that type marks required.
  - `healthCheckPath: ""` when unset, on the types whose details declare it.
  - `buildPlan: "starter"`, Render's default build plan; bex has no others. Emit it on the types whose details declare it.
  - Leave optional keys (`previews`, `pullRequestPreviewsEnabled`, `sshAddress`) as they are.
  - Then remove `buildPlan` and `healthCheckPath` from the four `details(SuiteAPI, …)` entries. Lower `allowlistSize` (`rendertest/allowlist_test.go:40`) by however many entries empty, and amend the ADR018 row 296 to drop both fields.
- **Blast radius:**
  - One projection, `renderServiceDetails`, behind the 4 operations above.
  - GraphQL and MCP have their own shapes and are unaffected.
  - Check each type's union member: `privateServiceDetails`, `backgroundWorkerDetails`, `cronJobDetails` and `staticSiteDetails` (w4/606 lists `buildPlan` in the cron and static members) so each gets exactly its required keys.
- **Tests:** an apps unit test that a web service with no health-check path renders `healthCheckPath: ""` and `buildPlan: "starter"`. The rendertest suites pass with the shrunken allowlist.
- **Unverified:** what Render returns for `buildPlan` on an image-backed service (assumed `starter`); the other four types' required lists beyond what w4/606 quotes.
- **Dedupe:**
  - ADR018 row 296 and the rendertest allowlist record the omission without sign-off. Per AGENTS.md, an unsigned divergence is amended.
  - w4/606 (open) covers `numInstances` on cron and static, not these keys.
  - Not deploy lag: `git log 8acf1d116941..origin/main -- lego/backend/internal/apps/render.go lego/backend/internal/rendertest` is empty.
- **DoD (live):** `GET /v1/services/<id>` for a fresh Free web service with no health-check path returns `serviceDetails.healthCheckPath == ""` and `serviceDetails.buildPlan == "starter"`. `GET /v1/services?limit=1` does the same per row.

## The other service types — 2026-11-13 (round 260)

Answers the Unverified line, on pin `8acf1d116941`. Three fixtures were created by `POST /v1/services`, read, and deleted within a minute (`DELETE` 204, then `GET` 404):

- `qa-20261113-r260-cron` (`srv-dbr8qfkhd5js73auer5g`): image busybox, schedule `0 0 1 1 *`, Starter;
- `qa-20261113-r260-wrk` (`srv-dbr8qfishdos73f2f7g0`): image busybox, Starter;
- `qa-20261113-r260-st` (`srv-dbr8qg4hd5js73auer7g`): static site from `examples/static-site`.

A Free private service was refused ("a private_service requires a paid plan"), as on Render, so none was created.

Required keys per [Retrieve service](https://api-docs.render.com/reference/retrieve-service) (read 2026-11-13), against bex's `GET /v1/services/<id>` `serviceDetails`:

| Type | Render's required keys | Missing in bex |
| --- | --- | --- |
| `background_worker` | `env`, `runtime`, `envSpecificDetails`, `plan`, `region`, `numInstances`, `buildPlan` | **`buildPlan`** |
| `cron_job` | `env`, `runtime`, `envSpecificDetails`, `plan`, `region`, `schedule`, `buildPlan` | **`buildPlan`** |
| `static_site` | `buildCommand`, `publishPath`, `url`, `buildPlan` | **`buildPlan`** |
| `private_service` (not probed) | `env`, `runtime`, `envSpecificDetails`, `plan`, `region`, `numInstances`, `buildPlan`, `openPorts`, `url` | `buildPlan` by the same code; `url` deliberately omitted (`render.go` comment, captured 2026-07-26) |
| `web_service` (round 259) | … `buildPlan`, `healthCheckPath`, `openPorts`, `url` | **`buildPlan`, `healthCheckPath`** |

- **Scope of the fix, now measured.** Emit `buildPlan: "starter"` on all five types. Emit `healthCheckPath: ""` on `web_service` only; it is in neither the private, worker, cron nor static member.
- **Private service `url`.** Render's published schema requires it, while bex's 2026-07-26 capture saw Render omit it. Leave it until a fresh Render capture settles which is right. Note it in the ADR018 row rather than changing it here.
- **Not a gap:** an image cron reports its command as `envSpecificDetails.startCommand` and an image worker as `dockerCommand`. Both are deliberate, so the pinned Render CLI's `create --from` clones them (`render.go:593-626`, w1/m167, w4/209).
