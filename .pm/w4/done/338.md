# Local Traefik ignores its Recreate strategy, so an edge roll stalls

Why: on the hostNetwork local edge, any Traefik pod-template change (chart bump, args, the w4/m164 plugin digest) never reaches the running pod.

`deploy/gitops/base/values/traefik.values.yaml:10–14` sets `deployment.strategy: {type: Recreate}` and explains why: one hostNetwork edge pod owns the node's :80/:443, so a surge pod cannot bind them. The locked chart (traefik 41.0.0, `deploy/helm-artifacts.lock`) has no `deployment.strategy` key. Its strategy is the top-level `updateStrategy` (chart default `RollingUpdate`, `maxUnavailable: 0`, `maxSurge: 1`). `helm template` of the base values renders exactly that default, so the Recreate setting has no effect. Found 2026-10-18 while arranging the m164 plugin roll (loopx w4).

- **Local (base values):** a roll surges a second hostNetwork pod onto the pinned platform node. It stays Pending on the host-port conflict, and `maxUnavailable: 0` keeps the old pod serving, so the rollout stalls and new plugin code never loads.
- **Prod:** the prod overlay keeps 2 replicas behind the LB with required anti-affinity and a PDB, and wants a rolling update. It already renders `RollingUpdate`, so prod behaviour must stay byte-identical.

**Fix (~30m):** move base to the chart's real key: `updateStrategy: {type: Recreate, rollingUpdate: {maxUnavailable: null, maxSurge: null}}`. Check the chart omits `rollingUpdate` for Recreate, because the API rejects Recreate with rollingUpdate set. Set the prod overlay's `updateStrategy` back to today's `RollingUpdate 0/1`. Drop the dead `deployment.strategy`. Add a `gitops-validate.sh` assertion on the rendered base (Recreate) and prod (RollingUpdate 0/1) strategies. Verify with `bash scripts/mock-cluster.sh` that a Traefik values change rolls the local edge.

**Closed 2026-10-18 (loopx w4):** base values now set the chart's `updateStrategy: {type: Recreate}` (the template omits `rollingUpdate` for Recreate), and the prod overlay sets `updateStrategy: {type: RollingUpdate}`. The dead `deployment.strategy` is gone. Rendered against the locked chart, base changes from `RollingUpdate 0/1` to `Recreate` and nothing else, while the prod render is byte-identical to before. `gitops-validate.sh` now asserts base `Recreate` and prod `RollingUpdate:0:1` with the same capture as the operator manager rollout check. It fails on the previous values, and the full run passes. **Not exercised:** a live roll on the local mock cluster, which was down (kind nodes absent). The next local bring-up's first Traefik pod-template change, such as w4/m164's plugin ConfigMap name, will exercise it.
