# Updating a service's source in Settings deploys it, and a static site can update its source too, as on Render

Why: Render's changelog of 2026-05-11 ("Change your service's backing repo or image in the Render Dashboard") deploys the new source as soon as it is submitted, for every service type. bex saves the source and waits for the next deploy, and a static site has no Source section. ADR018 calls it a "verified divergence" with no user sign-off, and AGENTS.md lets a divergence stand only with one. Found by w4/m553 t002 on 2026-11-22 ([disposition table](../../../../docs/render-artifacts/render-changelog.md)).

- **Render:** the entry's Update Source dialog (Settings → Build → Source → Edit) asks again for the Runtime, Build Command and Start Command of a Git source, or a static site's Publish Directory, and "Render automatically triggers a deploy using the new backing source" on submit.
- **bex:** `dashboard/src/features/services/components/service-source-card.tsx` (w5/m76) saves source intent and never deploys it ("the next explicit/push deploy consumes it"). `dashboard/src/features/services/lib/settings-sections.ts` adds no `source` section for a static site. ADR018's "Change instance plan / type" row has the 2026-08-25 divergence note.
- **First:** read Render's current dashboard bundle for the Update Source dialog and confirm it still deploys on submit and covers static sites.
- **End state:** submitting a new source in Settings starts one deploy of it on every service type Render offers it for, with Render's confirmations. The REST `PATCH` keeps its save-without-deploy contract, as Render's API does. ADR018's row drops the divergence. Tests cover the deploy on submit and the static-site section.
