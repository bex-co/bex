## Objective

Upgrade `ServiceSourceCard` / `SourceEditDialog` and its GraphQL hooks so submitting a new source in Settings matches Render's Update Source dialog — reconfirming build settings for Git sources (including static sites' Publish Directory and non-static services' Runtime + Build/Start commands), deploying immediately on submit, and navigating to the new deploy — across all 8 supported dashboard locales.

## Context

- Render contract: `docs/render-artifacts/update-source.md` (t001).
- Current implementation:
  - `dashboard/src/features/services/components/service-source-card.tsx`: currently says *"Saving does not trigger a deploy"* (`services.sourceNoAutoDeploy`), shows all 4 tabs (`github`, `git`, `image`, `build-source`), asks for commands only when switching from an image back to a native Git service (`needsCommands`), and closes without navigating.
  - `dashboard/src/features/services/components/service-source-picker.tsx`: already omits the `image` tab when `image` prop is omitted and omits `build-source` when `buildSource` is `undefined`.
  - Hooks: `dashboard/src/features/services/hooks/use-set-repo.ts`, `use-set-image.ts`, `use-link-build-source.ts`, and GraphQL documents under `dashboard/src/features/services/`.
  - Offline codegen: `SCHEMA_DUMP_PATH=/tmp/schema.json go test ./internal/api/ -run '^TestDumpGraphQLSchema$' -count=1` + `SCHEMA_JSON=/tmp/schema.json yarn codegen`, splicing only the changed feature hunk into `dashboard/src/graphql/definitions.ts` (per `dashboard/AGENTS.md`).
  - Publish Directory validation: `publishDirectoryError` (`dashboard/src/features/services/lib/publish-directory.ts`, used by `static-site-section.tsx:196`).
  - Runtime list: reuse the existing native/Docker runtime list and labels from the service create/runtime components so runtimes cannot drift.
  - Locales: `en`, `zh`, `ko`, `ja`, `es`, `pt`, `ru`, `de` (`dashboard/src/features/services/locales/*.ts`), guarded by `locale-parity.test.ts` and `aria-label-literals.test.ts`.

## Steps

1. Update GraphQL documents and splice generated types into `dashboard/src/graphql/definitions.ts` (reconciled via offline codegen). Update `use-set-repo.ts`, `use-set-image.ts`, and `use-link-build-source.ts` (or the hook calling t002's deploy-on-submit mutation) to pass `deploy: true` and return the created deploy ID alongside success/error handling.
2. Update `ServiceSourceCard` and `SourceEditDialog` (`dashboard/src/features/services/components/service-source-card.tsx`):
   - **Static site (`static_site`):** pass `image={undefined}` and `buildSource={undefined}` to `ServiceSourcePicker` (GitHub + Public Git URL only). Use static-site modal description. Confirm **Branch**, **Build Command** (optional), and **Publish Directory** (required, prefilled with `publishPath`, validated with `publishDirectoryError`).
   - **Non-static Git source (`web_service`, `private_service`, `background_worker`, `cron_job`):** confirm **Branch** and **Runtime** (Docker + all supported native runtimes, defaulted from current runtime or sensible default when switching from image/build source). When Docker, omit Build/Start commands. When native, require **Build Command** and **Start Command** (for `cron_job`, label it **Command** and prefill from `command`).
   - **Existing Image (non-static):** Image URL + optional Registry Credential, primary button **Connect** / **Deploy** (triggers deploy on submit).
   - **Build Source (non-static):** build-source picker + native Start Command / cron Command, primary button **Deploy** (triggers deploy on submit).
   - Replace `services.sourceNoAutoDeploy` description with accurate deploy-on-submit copy and label the primary action **Deploy** (`Deploying` while in flight; or **Connect** on Image tab per t001).
   - On success, when a deploy ID is returned, navigate to the new deploy (`/{services|static}/$serviceId/deploys/$deployId` via `useServiceBase()`); when no deploy is returned (e.g., suspended service or build source with no succeeded build yet), show a clear toast and close the dialog cleanly.
   - Preserve keyboard accessibility, mobile layout (360–1440px), and `ResizeObserver` smoothness.
3. Update all 8 locale files (`en`, `zh`, `ko`, `ja`, `es`, `pt`, `ru`, `de`) for every added or changed string (remember `zh` uses `你`, never `您`).
4. Update `dashboard/src/features/services/components/__tests__/service-source-card.test.tsx` and run `cd dashboard && yarn lint && yarn test`.
