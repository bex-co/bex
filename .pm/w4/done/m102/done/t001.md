## Objective

The repository ships a static-site blueprint example that bex's own validator rejects. Fix the manifest and add the guard that would have caught it, so no shipped example can drift out of validity again.

## Context

### The probe (production, 2026-09-13)

```text
POST https://api.bex.co/graphql
query { blueprintPreview(repo:"https://github.com/bex-co/bex", branch:"main",
                         path:"examples/static-site/render.yaml") {
  found error validation { valid errors plan { totalActions mode } } } }

→ 200
{"data":{"blueprintPreview":{"found":true,"error":"","validation":{
  "errors":["at '/services/0': additional properties 'staticPublishPath' not allowed"],
  "plan":null,"valid":false}}}}
```

The same call on the six sibling manifests returns `valid: true`. Full enumeration — `find . -name "render.yaml" -o -name "bex.yml"` (excluding `node_modules`, `.git`) gives **7** files:

| manifest | valid |
| --- | --- |
| `examples/cron-demo/render.yaml` | ✅ (1 action) |
| `examples/hello-go/render.yaml` | ✅ (1 action) |
| `examples/hello-node/render.yaml` | ✅ |
| `examples/hello-python/render.yaml` | ✅ |
| `examples/hello-rust/render.yaml` | ✅ |
| `examples/stack-demo/render.yaml` | ✅ (3 actions: postgres `db`, services `web` + `worker`) |
| `examples/static-site/render.yaml` | ❌ |

### The actual offender is `plan`, not the field the error names

`examples/static-site/render.yaml:15-16`:

```yaml
    staticPublishPath: . # publish this directory as-is; set to "dist" for a real build step
    plan: free
```

Isolated probes (each the same manifest with one line changed):

| manifest | result |
| --- | --- |
| `staticPublishPath: .` **+** `plan: free` | invalid — "additional properties 'staticPublishPath' not allowed" |
| `staticPublishPath: .`, **no** `plan` | **valid** |
| `plan: free`, **no** `staticPublishPath` | invalid — "publishPath is required for a static_site" |

So `plan` is the disallowed key and `staticPublishPath` is the legal one. The schema agrees: `#/definitions/staticService` (`lego/backend/internal/apps/schema/render.yaml.json`) lists 21 properties including `staticPublishPath` and **no** `plan`, with `type` pinned `const: "web"` and `runtime` pinned `const: "static"`. The capability registry (`schema/capabilities.json`) carries **23** `staticService` entries and none for `plan`.

### This is Render's schema, so the schema is not what changes

`blueprint_schema.go:30-37` — the document is a reviewed snapshot of Render's own schema, pinned by `RenderBlueprintSchemaSHA256` (fetched 2026-08-02), and "a deliberate update must change both the bytes and this constant, then pass capability-registry exhaustiveness tests". Render has no per-instance plan for static sites, so rejecting `plan` there is correct parity. **Fix the example.**

## Steps

1. Delete the `plan: free` line from `examples/static-site/render.yaml`. Check the surrounding comment block, which explains the file as the static-site reference — if it mentions a plan, correct the prose too.
2. Re-probe `blueprintPreview` on the committed path and paste the `valid: true` response with its plan into this task.
3. Add the guard: a test that discovers every tracked `render.yaml`/`bex.yml` in the repo and runs it through the same validation entrypoint the API uses (`ValidateBlueprint` / the compiler), failing on any invalid one. Discovery must be by walk, not a hardcoded list, or the next example added escapes it.
4. Check the sibling consumer the file's own header names: `scripts/app-apply.sh examples/static-site` (and `scripts/deploy-sample.sh`) — confirm whether either path also rejects, or silently tolerates, the field the blueprint validator refuses. A script that accepts what the API rejects is its own inconsistency; record what you find either way.
