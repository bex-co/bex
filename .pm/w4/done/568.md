# 568 — The Events tab reports "Instance count changed" and "Autoscaling config changed" without the values, though GraphQL carries them

Why: these rows are the only record of what changed and when, and they don't say what changed. A user who scaled from 1 to 2, or turned autoscaling on at 1–2 instances, sees a bare label. w3/m16 promised the before/after values to "event consumers (dashboard Events tab, …)".

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 83, 2026-11-11 07:36–07:44 UTC (`muse.env`, workspace `bex-canary`; production runs the code of `348bd77a5`). **Minor**: the values are missing from the UI, not wrong. ~30m.
- **Fixture:** owned Starter background worker `qa-20261111-bw83` (`srv-dbq1ln2p92ls73cjjlgg`, busybox). Deleted afterwards (DELETE 204, then GET 404).
- **Probe:**
  - **The changes.** Scaling → Manual Scaling 1 → 2 → Save Changes (07:36:57Z). Then Autoscaling on, Minimum 1, Maximum 2, Target CPU on → Save Changes ("Autoscaling settings saved.", 07:42:54Z).
  - **REST has the values.** `GET /v1/services/srv-dbq1ln2p92ls73cjjlgg/events?limit=6` → `instance_count_changed` `{"fromInstances":1,"toInstances":2}` and `autoscaling_config_changed` `{"fromConfig":{"enabled":false},"toConfig":{"enabled":true,"min":1,"max":2}}`.
  - **GraphQL has the values too.** `{ serviceEvents(serviceId:"srv-dbq1ln2p92ls73cjjlgg", limit: 6) { type details { fromCount toCount instanceCountFrom instanceCountTo autoscalingMinFrom autoscalingMaxFrom autoscalingMinTo autoscalingMaxTo } } }` returns:
    - `instance_count_changed`: `instanceCountFrom 1`, `instanceCountTo 2`, `fromCount null`, `toCount null`;
    - `autoscaling_config_changed`: `autoscalingMinTo 1`, `autoscalingMaxTo 2`, all `…From` null.
  - **The Events tab does not.** It renders `paragraph: Instance count changed` and `paragraph: Autoscaling config changed`, each with only a relative time. There is no "Instances 1 → 2" and no range.
- **Root cause:**
  - **The query asks for the wrong fields.** `dashboard/src/features/services/api/events.graphql:40-110` asks only for `fromCount`/`toCount`. The backend fills those only for fact-sourced `autoscaling_started`/`autoscaling_ended` rows (`lego/backend/internal/events/service.go:1310-1311`).
  - **The values live in other fields.** For the audit-sourced types, the backend fills `instanceCountFrom`/`instanceCountTo`, `autoscalingMin…`/`autoscalingMax…` and `planFrom`/`planTo` (`events/service.go:1258-1259`; GraphQL fields `lego/backend/internal/events/graphql.go:216-226`).
  - **The page renders only `fromCount`/`toCount`** (`dashboard/src/routes/services.$serviceId.events.tsx:406-407`, `:533-539`, `services.eventsReplicaChange` "Instances {from} → {to}").
  - **The gap is old.** w3/m16 added the typed pairs, and its DoD checked only the API.
- **Fix (target behavior):** the Events tab shows each type's change in one line, en and zh:
  - `instance_count_changed`: "Instances 1 → 2", from `instanceCountFrom`/`instanceCountTo`. The existing `eventsReplicaChange` string can serve.
  - `autoscaling_config_changed`: before → after, each side "Off" or "{min}–{max} instances".
  - `plan_changed`: "Plan Starter → Standard", from `planFrom`/`planTo`, using the plan display names.
  - **Test:** add the fields to `events.graphql` and regenerate. The page test renders each type with its values. A legacy row with null values renders the bare label, never invented values.
- **Unverified:**
  - `plan_changed` live. Changing a paid service's plan is a purchase, so it wasn't probed; the gap is read from the code.
  - The Metrics event markers (`dashboard/src/features/metrics/lib/chart-events.ts:160`) and webhooks, which use their own paths.
- **Render:** Render's REST details for these types are `{fromInstances,toInstances}`, `{fromConfig,toConfig}` and `{from,to}` (pinned spec). The exact wording of Render's dashboard rows was not checked.
