## Objective

Create one machine-readable inventory and resolver for the builder, native-base, and helper images left digest-pinned by `w7/m85`, including the upstream reference and last-reviewed resolution time needed for freshness decisions.

## Context

- `w7/m85` owns pinning and its fail-closed no-floating-reference guard; this task starts only after its closeout and must not redo that inventory.
- Native base images are declared in `lego/operator/internal/build/native.go`; builder/helper refs span operator constants, Dockerfiles, and GitOps manifests.
- The resolver must be deterministic, credential-minimal, and suitable for both local verification and a scheduled GitHub workflow.

## Steps

1. Define a checked-in inventory format tying each logical image to its upstream tag/reference, committed digest, affected files, and resolution timestamp.
2. Implement a resolver that produces stable output and an exact old→new digest comparison without editing files.
3. Seed the inventory from the post-`w7/m85` tree and document how a reviewed digest update refreshes its metadata.

## Acceptance criteria

- [x] Every image pinned by `w7/m85` appears exactly once with upstream and committed-digest identity.
- [x] Repeated resolution against unchanged upstream state is byte-identical.
- [x] Digest movement is reported as structured exact replacements without changing the worktree.
- [x] Missing inventory coverage or malformed metadata fails closed.

## Out of scope

- Automatically committing image updates, weakening `w7/m85`'s guard, or managing application dependency versions.
