# Canceling an inline Settings edit loses keyboard focus

Why: keyboard users lose the field they were editing when Cancel or Escape disables it; returning focus to its restored Edit button keeps the settings workflow usable.

**Status:** done — the remaining desktop/fresh-mobile Health Check Path Escape/keyboard-Cancel, Port Escape and Enter-reopen gate passes in a888, 2026-10-17. Normal saves retain the existing focus policy. Original filing and implementation notes below are historical.

Severity: **minor**. Estimate: **55m** (shared cancellation change 10m, caller review 10m, behavior tests 20m, live verification and simplify 15m). Functional QA a416, 2026-10-13 Pacific / 2026-10-14 UTC, user-selected w4, muse.env login helper. Filing only. Inspected main: `94c22bec9`.

## Root cause and bounded fix

`dashboard/src/features/services/components/editable-field-row.tsx:143–150` focuses the newly enabled input when entering edit mode, but returns immediately when editing becomes false. `cancel():164–167` restores the draft and sets editing false without selecting a next focus target. The Input becomes disabled at :271, and Cancel/Save buttons are replaced by the pencil at :289–310; the restored Edit button has no ref or focus-restoration callback.

The inspected primitives are actual native elements: `common/components/ui/input.tsx:5–17` forwards props to an input, while `button.tsx:39–65` uses a native button when asChild is false, as here. This text/number cancellation path has no Dialog or Radix focus-return primitive. Existing `editable-field-row.test.tsx:112–136` asserts restored value and pencil presence after Escape, but never asserts the active element or reopening by Enter.

Restore focus to this row's mounted, enabled Edit button **after an explicit cancellation has committed**. A ref plus a cancellation-specific post-render action can express this without changing any save handler. Do not focus pencils on initial mount, ordinary server refreshes, rejected saves, or a later route after this row has unmounted. Keep dirty gating, persisted values, role/paid/busy gates, confirmation dialogs and API error handling. Successful-save focus is unprobed and is not a required new behavior in this filing.
