# In a protected environment a Developer can switch maintenance mode on, confirm it, and read "Forbidden"

Why: Render lets only Admins toggle maintenance mode in a protected environment, so a Developer must see the switch disabled with Render's reason, never a bare 403 after confirming. Found by w4/m578 t005 on 2026-11-22.

- **What happens (dev-4, OpenFGA enforced, 1440 and 390):** as a Developer, on a Starter service in a protected environment, the Settings **Maintenance mode** switch is enabled. "Enable maintenance mode?" confirms, then `SetMaintenanceMode` answers `FORBIDDEN`, a bare "Forbidden" toast shows, and the switch stays off. The verb refuses by `requireUnprotected(ctx, a, "take offline")` (`lego/backend/internal/apps/settings_check.go`).
- **Why the dashboard offers it:** `MaintenanceModeSection` (`dashboard/src/features/services/components/maintenance-mode-section.tsx`) gates the switch only on the plan (`eligible = plan !== "free"`), with no role or protection read.
- **End state:** turning maintenance mode on reads the verb's own rule (for example a `serverActions` row through `core.RestrictedDecision`, or the workspace `can_manage` in a protected environment): the switch is disabled with _This action is limited to admins._ for a Developer there, turning it off stays open as the verb allows, and an Admin keeps both. A raced 403 names the reason. Tests cover the switch for an Admin and a Developer, protected and not.

**Done 2026-11-23.** Render keeps "toggling maintenance mode for any service in the environment" to Admins in a protected environment ([render.com/docs/projects](https://render.com/docs/projects)), in both directions, and bex already restricts Resume beside Suspend on the same reading. So this goes one step past the end state above: turning maintenance mode **off** now needs an Admin there too (`core.VerbToggleMaintenanceMode`, `checkMaintenanceMode` in `lego/backend/internal/apps/settings_check.go`), and ADR032's "off stays open" residual is retired, with no ADR018 sign-off to keep it. A URL-only edit toggles nothing and stays open. The raced 403 already read _This action is limited to admins._ since w4/728.

- **Projection:** `serverActions` reports `toggle_maintenance_mode` for a web service (and an untyped one) by the verb's rule: `can_operate`, and on a protected member the fresh workspace-manage check (`core.RestrictedDecision`), sharing the one protection read and admin check. A Developer there reads `denied` / `protected_environment_admin_required`, a Viewer `insufficient_permission`, a failed protection read `unavailable`. Plan eligibility stays the client's (it reads the plan).
- **Dashboard:** `MaintenanceModeSection` reads that decision. Before, a Developer on a protected Starter service flipped the switch, confirmed "Enable maintenance mode?" and read "Forbidden". After, the switch is disabled in either direction with _This action is limited to admins._ in its tooltip and in place of its hint; an Admin, and a Developer outside a protected environment, keep it; a Viewer reads the role reason; a free service keeps the paid-plan hint; the page URL stays editable. The environment's Protected hint now says "toggle maintenance mode" in all eight locales.
- **Tests:** `TestActionCapabilities_MaintenanceToggleAgreesWithTheVerb` (Admin and Developer, protected and not, on and off, projection against `SetMaintenanceMode`), `TestActionCapabilities_MaintenanceToggleOnlyOnWebServices`, the Viewer and failed-read cases, `TestProtectedMemberMaintenanceModeNeedsAdmin` (both directions), `TestProtectedMaintenancePageEditStaysOpen`, the GraphQL `TestLifecycleProjectionsGraphQLProtectedAdminRule`, and `maintenance-mode-section.test.tsx` (both directions for a Developer in a protected environment and an allowed caller, a Viewer, checking, free plan, URL edit). Each fails with its fix reverted. Not replayed live on dev-4: its bex-api runs fail-open, and the OpenFGA-and-three-identities recipe of w4/m550 t005 was not kept as a script.
