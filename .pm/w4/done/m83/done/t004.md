## Objective

Confirm that fairness and overflow do not create contradictory webhook history or control-plane behavior across the Render-compatible surfaces, and document any deliberate bex extension.

## Context

Endpoint CRUD and delivery history share one core service across REST, GraphQL, MCP, and dashboard. The new queue policy is internal, but a capped delivery can affect what users observe. The contract must stay honest: never report a delivery as attempted when it was not admitted, and never make a source mutation appear failed because notification capacity was exhausted.

## Steps

1. Compare Render's current public webhook delivery/history semantics with the pinned artifacts and `docs/ADR018-render-parity.md`.
2. Walk REST, GraphQL, MCP, and dashboard history against the same admitted and capped event cases.
3. Record the bounded/fair scheduler as a bex operational extension and file any genuine surface drift separately.
