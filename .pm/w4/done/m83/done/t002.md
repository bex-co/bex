## Objective

Replace the global oldest-first claim batch with deterministic fair-by-workspace selection while retaining disjoint multi-replica leases and the existing retry ordering within each workspace.

## Context

`store.ClaimDueWebhookDeliveries` currently orders every due row together and locks a global batch with `FOR UPDATE SKIP LOCKED`. A workspace with a deep retry backlog can fill every batch before a quiet workspace is considered. The new query must create shares across eligible workspaces without serializing replicas or weakening claim leases.

## Steps

1. Define the fairness invariant: when batch capacity permits, take at least one due row from each eligible workspace before taking a second from any workspace.
2. Implement the ranking/selection in one Postgres claim transaction, with deterministic order by due time, creation time, and id inside each workspace.
3. Keep `SKIP LOCKED`, lease ownership, retry attempt accounting, endpoint enabled-state checks, and payload loading byte-compatible after selection.
4. Exercise two simultaneous claimers and a heavily skewed noisy/quiet dataset against real Postgres.

## Acceptance criteria

- [ ] A quiet workspace's due row appears in the next batch even when another workspace has more due rows than the batch size.
- [ ] Ordering remains deterministic within a workspace.
- [ ] Concurrent claimers receive disjoint delivery ids; no row is double-leased.
- [ ] Retry, disabled-endpoint, and claim-expiry behavior stays unchanged.

## Out of scope

- Weighted plan tiers, customer-configurable priority, a global FIFO promise, or a separate queueing service.
