## Objective

Replace the `revocationMu.RLock()` held across the Hydra introspection round trip with an atomic revocation epoch, so `invalidate` (CLI logout) stops stalling every new cache-miss introspection for up to the 5s client timeout, while preserving the invariant that an older in-flight positive result can never resurrect a revoked entry.

## Context

- Current code: `lego/backend/internal/api/auth.go` — `introspectUpstream` takes `RLock` at :227-228 and holds it through `a.client.Do` (:236) and cache population; `invalidate` takes the write lock (:129-130). `sync.RWMutex` blocks new readers once a writer is pending, so one logout during any in-flight introspection stalls the process.
- Proposed shape (from `w4/023`): snapshot an atomic epoch before the upstream call, run the HTTP round trip lock-free, and under one short lock `Put` only if the epoch is unchanged; `invalidate` bumps the epoch inside its delete critical section. This can also let the singleflight closure return the identity directly, removing `introspect`'s second cache lookup.
- This is the hottest path in the binary — not a drive-by edit; the change needs focused concurrency review.

## Steps

1. Introduce the epoch (atomic counter) alongside the cache; bump in `invalidate` under its existing critical section.
2. Rework `introspectUpstream`: snapshot epoch → lock-free RTT → short-lock conditional `Put` (skip if epoch changed).
3. Simplify `introspect`'s re-read if the singleflight closure can now return the identity.
4. Extend the existing cache-invalidation race tests (see t005 for the full matrix) enough to prove the invariant during development.

## Resolution (2026-07-16)

`invalidate`'s `sync.RWMutex` held across the Hydra RTT is gone; `introspectUpstream` snapshots an atomic `revocationEpoch` before the RTT and runs the round trip with no lock held. A first-cut design that only re-checked the epoch with a bare atomic Load immediately before `cache.Put` had a real, reviewer-confirmed race: `invalidate`'s `Add()` could land strictly between the check and the `Put`, resurrecting a just-revoked token. Fixed by adding a narrow `epochMu sync.Mutex` held only for (a) `invalidate`'s epoch bump and (b) `introspectUpstream`'s epoch-recheck-plus-`cache.Put`, as one atomic unit — never across any I/O, so the original stall (`invalidate` blocked on an in-flight Hydra RTT) cannot recur; verified in code by inspection and by `TestInvalidateDoesNotBlockDuringInFlightUpstreamRTT` (liveness) + `TestEpochBumpDuringRTTDiscardsStalePut` (the non-resurrection invariant, isolated from `invalidate`'s own `Delete`/`DeleteIf` calls by using an unrelated token/client/subject) + the pre-existing `TestLogoutCannotBeUndoneByInflightIntrospection`, all green under `go test -race -count=20`.
