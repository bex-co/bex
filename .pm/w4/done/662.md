# 662 — The zh env-group card still says 链接/已链接 for Link and Linked, under headings and an Unlink button that say 关联

Why: w4/646 gave each product term one zh rendering and chose 取消关联 for Unlink, but its glossary has no rule for Link and Linked. The service Environment page's Linked Environment Groups card now reads **已关联（2）** above groups badged **已链接**, and **可关联（1）** above a **链接** button. The card's own description says the groups 可**链接**到此服务, and the Events tab says 已**关联**环境组 for the same action. A Chinese reader sees two verbs for one action in one card.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 361, 2026-11-14 13:18 UTC (`muse.env`, workspace `bex-canary`; pin `c99e7815ebec`, which carries w4/646's `e548f0590`). **Minor** (zh copy only). ~20m.
- **Fixture:** Free busybox web service `qa-20261114-r361-bb` (`srv-dbs5rklv5sfs73boaigg`) with env groups `qa-20261114-r361-g1` and `-g2` linked. All deleted afterwards (`DELETE` 204, then `GET` 404).
- **Probe (dashboard, `i18nextLng=zh`, `/services/srv-dbs5rklv5sfs73boaigg/env?lang=zh`, `main` innerText):**

  ```
  已关联的环境组

  可关联（1）
  qa-20261025-b5p1-grp / GRP_A / 链接
  ```

- **Root cause:** eight zh messages render the env-group link verb as 链接 (`origin/main` line numbers):
  - `dashboard/src/features/services/locales/zh.ts`: `services.envGroupsDescription` (`:1029`, 可链接到此服务), `services.envGroupLinked` (`:1086`, 已链接), `services.envGroupLink` (`:1136`, 链接), `services.envGroupLinkAria` (`:1145`, 链接 {name}), `services.envGroupDeleteConfirmBody` (`:1163`, 所有链接到它的服务), `services.envGroupLinkSuccess` (`:1183`, 组已链接), `services.envGroupLinkError` (`:1187`, 无法链接该组);
  - `dashboard/src/features/env-groups/locales/zh.ts:415`: `envGroups.servicesLoadError` (现有链接仍显示在下方).
  - The same card and its siblings already say 关联: `services.envGroupUnlink` (`:1140`), `services.envGroupUnlinkSuccess` (`:1191`), `services.envGroupsLinkedTitle` (`:5753`), `services.envGroupsLinkedCount` (`:5757`), `services.envGroupsAvailableCount` (`:5761`), `services.eventsTypeEnvGroupLinked` (`:4905`) and the env-group page's 关联服务 strings (`env-groups/locales/zh.ts:94`, `:116`, `:120`, `:156`).
  - `locale-parity.test.ts`'s `GLOSSARY` (`dashboard/src/i18n/__tests__/locale-parity.test.ts:234-271`) checks Unlink (`/\bunlink/i` → 取消关联) but has no Link rule, so nothing catches these.
- **Fix (target behavior):** the env-group link verb is 关联 everywhere: Link → 关联, Linked → 已关联, Link {name} → 关联 {name}, Group linked → 组已关联, Couldn't link the group → 无法关联该组, "you can link to this and other services" → 可关联到此服务及其他服务, "removed from every service linked to it" → 所有关联到它的服务, "Existing links" → 现有关联.
  - Add a glossary rule scoped to env groups: for keys under `services.envGroup*` and the `envGroups` namespace, an en message matching `/\blink(s|ed)?\b/i` must not use 链接 in zh.
  - Keep 链接 where the English is a hyperlink (invite link 邀请链接, copy link). A blanket Link rule would wrongly hit those, which is why the rule needs the key scope.
- **Blast radius:** zh copy in two locale files (8 messages) plus one glossary rule. Tests that assert the old zh strings change with them; no en copy or behavior moves.
- **Render:** n/a (Render has no zh dashboard). This is w4/646's one-rendering-per-term rule.
- **Dedupe:** `grep -rln "已链接\|envGroupLinked\|envGroupLinkSuccess" .pm` finds nothing. w4/646 (done) fixed Unlink only and lists Link nowhere.

- **Closed 2026-11-14 (`/loopx w4`):** The eight zh env-group messages that rendered the link verb as 链接 now say 关联 (`services.envGroupsDescription`, `envGroupLinked`, `envGroupLink`, `envGroupLinkAria`, `envGroupDeleteConfirmBody`, `envGroupLinkSuccess`, `envGroupLinkError`, and `envGroups.servicesLoadError`), matching 取消关联 and the card headings. `locale-parity.test.ts` gains a rule scoped to `services.envGroup*` keys and the env-groups namespace: an en message naming link/linked must not use 链接 in zh, while hyperlink copy elsewhere (邀请链接) is untouched. en unchanged.
