# Events feed calls a deploy-hook deploy "Manual deploy" while the deploys list calls it "Deploy Hook"

Why: the same deploy shows two different triggers on two surfaces, and "Manual deploy" is factually wrong when nobody clicked anything — a CI system hit a secret URL. Sibling of `w4/100` (different trigger + flag; `w4/100` explicitly scoped its fix to the `envUpdated` mapping only).

## Resolution (2026-09-21)

**The verification the note asked for first: Render's trigger vocabulary has no hook flag.** Its public OpenAPI does not publish the events trigger object at all, and bex's `Trigger` models the six flags Render's dashboard shows (`firstBuild`, `envUpdated`, `manual`, `deployedByRender`, `clearCache`, `rollback`) — none of which names a hook. So this took the note's second branch: a bex extension.

`Trigger.DeployHook` is now set for `store.TriggerDeployHook` on REST (`deployHook`, additive — a Render client ignores the unknown key), GraphQL and the dashboard, and the events feed labels it **"Deploy Hook"** (en + zh), matching the deploys list. As the note required, `manual` was not relabelled: an `api` trigger keeps "Manual deploy".

**One judgment call worth stating.** `Manual` is now false for a hook deploy, rather than true alongside the new flag. The `Trigger` object documents its flags as mutually exclusive, and leaving `manual: true` would have kept telling a Render-only client that a person pressed something for a rollout a CI system triggered — moving the false statement rather than removing it. A Render client now sees every flag false for a hook deploy, which is this object's documented behavior for a cause Render's vocabulary cannot name ("leaves the rest false rather than guessing"). The only non-generated consumer of the flag is the events route, updated here.

The dashboard checks `deployHook` **ahead of** `manual`, so the correct label wins as soon as either side deploys, in whichever order that happens — pinned by its own test.

Covered by backend `TestDeployTriggerNamesTheCauseItActuallyHad` (every trigger's expected flag, plus an exactly-one-flag-set assertion that would catch a future double-set) and the dashboard trigger-label suite.
