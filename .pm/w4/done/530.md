# 530 — A brand-new service reads "Unknown" for its first 10–30 s, and its project card on Overview says "1 resource needs attention"

Why: right after a create, the operator has not yet written `status.phase`, so GraphQL serves `phase: ""`. The dashboard maps that to the generic "Unknown" badge, and the Overview roll-up counts "unknown" as a problem. So the first thing a customer sees after creating a service is that it needs attention. Render shows a create as in progress from the first moment.

**Severity:** minor (a transient false alarm for 10–30 s after every create; nothing is lost) · **Estimate:** 30m · **Worker:** worker4 · **Status:** done

- **Source:** live `/qa-find-bugs w4`, production, 2026-11-06 15:46–15:58 UTC, round 176, pin `ca9b90b8f` (`b8370c30c50e`), workspace `bex-canary`.
- **Probe:** Free image web services from `docker.io/traefik/whoami:latest`, all deleted afterwards (`204` → `404`).
  1. **Service header.** I created `qa-20261106-ph176` (`srv-dbmvfh7uqs1c73d5q0j0`) with `POST /v1/services`, opened `/services/<id>`, and polled GraphQL `service(id){phase}` and the header's status text every ~1.8 s:
     - 3.6 s through 19.6 s: `{"phase":""}`, and the header read `Service Unknown`.

  2. **Overview roll-up.** I created `qa-20261106-ph176b` (`srv-dbmvgj7uqs1c73d5q0mg`) in the only environment of project `qa-20261106-pj176b`, then reloaded `/`:

- **Root cause:**
  - `dashboard/src/features/services/lib/status.ts:249-269`: `PHASE_STATUS` has no entry for `""`, so `deriveStatus` (`:276-287`) returns `{key:"unknown"}`, which `services.statusUnknown` labels "Unknown".
  - The same file already treats `""` as the start of the first transition: `CONVERGING_PHASES` (`:312-318`) includes `""` with the comment "An empty phase counts — a first reconcile that has not landed is the start of the same transition" (`:295-296`). The display mapping disagrees with the polling rule.
  - `dashboard/src/features/projects/lib/resource-health.ts:14-24`: `classifyResourceHealth` maps every key other than running/suspended/sleeping/building/deploying/pending to `"attention"`, so `unknown` becomes "needs attention".
  - The backend passes the raw value through: `lego/backend/internal/apps/service.go:1088` sets `phase := string(a.Status.Phase)`, which is `""` until the first reconcile.
- **Fix — target behavior:**
  - A service whose phase is `""` displays as **Pending**: `services.statusPending`, the same `PENDING` status that `deriveStatus` already uses for an ineligible Hibernated service, with the outline variant.
  - It classifies as `converging` ("in progress") on the Overview card, never `attention`.
  - "Unknown" stays only for a non-empty phase bex does not recognize (keep the test at `status.test.ts:557-559`).
  - Fix this in the dashboard mapping (`PHASE_STATUS[""] = PENDING`, or an explicit `""` branch in `deriveStatus`). Do not change the backend: GraphQL `phase` is a bex extension, and the empty value is an honest "not yet reconciled".
- **Blast radius:** `deriveStatus` (services) has 3 importers outside its own file (grep):

  - The databases and Key Value siblings have their own `deriveStatus` and were not probed with a fresh create.
- **Tests:** `deriveStatus(svc({phase:""})).key === "pending"`, and `classifyResourceHealth` for a service row with `phase:""` returns `"converging"`. Keep the "unrecognized phase → unknown" and "deleting → Deleting" tests.
