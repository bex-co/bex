# Generate Blueprint promises value prompts for exported group keys that are generated

Why: the export preview tells users they will enter omitted values later, but selected environment-group keys are emitted as generateValue and missing values are generated automatically; the adoption instructions should describe the file the user actually downloads.

**Severity:** minor · **Estimate:** 45m · **Source:** user-requested continuous functional qa-find-bugs, w4 target, pass a142, 2026-10-11 UTC. Credentials were consumed by the QA login helper from muse.env. **Goal:** trustworthy click-ops-to-Blueprint adoption under ADR049/ADR018.

## Fresh reproduction and controls

1. Create an owned environment group with a synthetic QA_A142_MARKER value. On https://dashboard.bex.co/blueprints, open Generate Blueprint, select only that group, and Generate.
2. The 111-byte manifest declares envVarGroups → envVars → generateValue: true. Beneath it the English paragraph says: “Secret values are never exported — secret-backed variables appear as sync: false and are prompted for when the Blueprint is first created.”
3. Repeat from a fresh page at 1440×1000 and 390×844. Both produce the same manifest and misleading paragraph. The mobile dialog bounds are x=16, y=179, width=358, height=486; page width remains 390.
4. Copy equals the preview; Download render.yaml saves exactly the same 111 bytes (SHA-256 3a4db9bddcff66c99c82f03dd4b9c176ca269aaffc7669e770e375215a2de8a1). Back retains the selection; closing and reopening clears it and disables Generate.
5. Create a Free image-backed web fixture, link the owned group, and export both. The file includes root envVarGroups and the service's fromGroup link; validateBlueprint returns valid: true with empty errors/errorDetails for both group-only and combined exports. After linking, the actual service responds HTTP 200 with the synthetic variable and mounted-file markers.
6. Control: export the same linked web service without selecting its group. The same variable becomes a service-level sync: false entry. The generator correctly uses two different representations.

Owned IDs: group evg-db5g06ror3gs73903ie0 / qa-20261010-a142-export-group; web srv-db5g12nujt7s73fsjlc0 / qa-20261010-a142-export-web. No pre-existing resources were selected for generation or modified.

**Expected:** describe omitted values according to the generated markers, including group keys. **Actual:** the unconditional note promises sync:false + a later prompt even when the file contains only generateValue group keys. No creation failure or observed data loss is claimed.

Screenshots were verified on disk and visually opened: .playwright-mcp/qa-a142-export-note-desktop.png (91,046 bytes) and .playwright-mcp/qa-a142-export-note-mobile.png (50,675 bytes). Downloads: .playwright-mcp/qa-a142-group-render.yaml and qa-a142-linked-render.yaml. These artifacts are ignored/local; the complete requests and responses below are durable evidence.

## Cause, consumer and bounded fix

- **Wrong text:** dashboard/src/features/blueprints/locales/en.ts:475–479 and locales/zh.ts:458–462 both promise prompts. generate-blueprint-dialog.tsx:198–206 renders the key unconditionally beside every successful manifest; it receives no selection/representation information.
- **Correct producer:** lego/backend/internal/apps/blueprint_generate.go:303–312 emits generateValue: true for each selected group key. Its EnvGroupExportSource declaration at :52–57 returns name + key names. At :515–544, selected linked groups become fromGroup while unselected linked groups become service sync:false keys. Neither branch is the defect.
- **Actual generation consumer:** lego/backend/internal/envgroups/service.go:1509–1575 ApplyEnvGroup creates missing group keys through CreateEnvVarInput{GenerateValue:true}; prepareCreateEnv at :560–584 calls core.GenerateValue. Existing keys are skipped at :1571–1573 and preserved. No prompt collector is invoked by this group path.
- **Producer-to-consumer connection:** deploy.go:2157–2163 classifies group generateValue keys into parsedEnvGroup.generates and rejects group sync:false; :772 calls applyStackEnvGroups, whose :834–842 forwards those generates to EnvGroups.ApplyEnvGroup. The actual interface at :163 carries literals and generated-key names separately.
- **Actual prompt consumer:** lego/backend/internal/apps/blueprint.go:1896–1915 syncFalseVarsFromBlueprintIR considers only BlueprintResourceService with declared sync:false keys. dashboard/src/routes/blueprints.new.tsx:154 takes plan.syncFalseVars, and :387–423 renders those inputs. deploy.go:2405–2420 classifies generateValue and sync:false separately. These declared types can express both behaviors; changing the caption needs no response/schema change.
- **Framework path read:** useTranslations at dashboard/src/common/hooks/use-translations.ts:25–65 returns a string from i18next. Actual installed react-i18next 17.0.8 useTranslation.js:70–100 obtains the locale-fixed translator and subscribes to its snapshot; locale resources import the Blueprint strings in src/i18n/index.ts:21 and resources-zh.ts:21. The caption is a native paragraph containing that string. The captured paragraph exactly matches the locale; no framework serialization or modal behavior is blamed.

**Implementation:** update the English and Chinese generateSecretsNote messages to distinguish both modes. Suggested English: “Stored secret values are omitted. Supply values for service variables marked sync: false when creating the Blueprint. Variables marked generateValue keep an existing value or generate one if missing, including exported environment-group keys.” Review the Chinese equivalent and the existing locale-parity checks.

A mode-independent explanation is sufficient and avoids adding a YAML parser or another query to this dialog. Keep the existing generator/adoption semantics, selection handling, Copy, Download and value collectors. Do not turn group keys into sync:false to satisfy the old text. This filing does not expand export to include group-mounted files.

**Blast radius and aliases:** exhaustive production search finds one generateSecretsNote consumer, two locale definitions, one GenerateBlueprintDialog definition and one mount (routes/blueprints.tsx:169). The canonical entry is /blueprints → Generate Blueprint; service and datastore detail routes do not mount another copy. Its selection lists share the caption across web, static, cron, worker and private services, Postgres, Key Value and environment groups. Group-only, owned web-only and web+group selections were driven; other kinds remain consumer-review boundaries. Empty/pending/error states do not render this successful-preview note. Existing role, login, transport and validation errors retain their current paths; this wording change does not reclassify them.
