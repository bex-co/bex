# 709 — A webhook's `eventFilter` refuses the Render event types bex does not emit, so a Render configuration naming one fails with 400

Why: Render accepts any value of its event-type enum in a webhook's `eventFilter`; bex answers `400 unknown event type` for the eight it never emits, so a Terraform `render_webhook`, CLI call or API script copied from Render fails to apply.

- **Source:** `/pm-brainstorm one aspect of render parity for w4` (the service events and outbound webhooks aspect), 2026-11-18, item 3; filed by `/pm them to w4`, 2026-11-19. ~45m.
- **Render:** the pinned OpenAPI `POST /webhooks` `eventFilter` items are the `retrieve-event` type enum, 68 values ("An empty list means all event types will trigger the webhook"). render.com/docs/webhooks: "A given webhook can send notifications for any combination of supported event types."
- **bex:** `normalizeEventTypes` (`lego/backend/internal/webhooks/service.go:1093-1115`) refuses anything outside `EventTypes`, bex's emitted vocabulary, with `WebhookEventFilterInvalidCode` "unknown event type". REST, GraphQL and MCP share it. Render types outside it today: `artifact_fetch_failed`, `artifact_source_changed`, `maintenance_started`, `maintenance_ended`, `postgres_connection_pool_changed`, `postgres_read_replica_stale`, `zero_downtime_redeploy_started`, `zero_downtime_redeploy_ended`. w4/m504, w4/m510 and w4/m511 make five of them produced; `maintenance_*` (DO_NOT_DO: Maintenance runs) and `postgres_connection_pool_changed` (from/to unknowable without a Render capture) stay unproduced.
- **Fix:**
  1. Accept, store and read back every value of the pinned enum on create and PATCH (REST, GraphQL, MCP), in the canonical order used now. A value outside both the enum and bex's extensions still answers 400.
  2. Keep advertising only what bex emits: the dashboard picker (`dashboard/src/features/webhooks/event-catalog.ts`) lists the emitted vocabulary, shows a stored never-firing type as checked when editing, and never drops it on save.
  3. Amend `docs/render-artifacts/webhooks-api.md`: accepting a filter value is not advertising it, so m70's truthfulness rule keeps governing the vocabulary only. Update ADR018's Outbound event webhooks row.
- **Acceptance:** `POST /v1/webhooks` with `eventFilter: ["deploy_ended","maintenance_started"]` answers 201 and reads both back on REST, GraphQL and MCP; `["not_a_type"]` still answers 400; a dashboard edit of that webhook keeps `maintenance_started`; `cd lego/backend && go test ./...` and dashboard `yarn lint` + `yarn test` pass.
- **Done (2026-11-19):** `normalizeEventTypes` (`lego/backend/internal/webhooks/service.go`) now validates and canonically orders against `subscribableEventTypes` (emitted `EventTypes` plus Render's remaining three unemitted pinned OpenAPI enum values: `maintenance_ended`, `maintenance_started`, `postgres_connection_pool_changed`), while `EventTypes` and the dashboard create picker stay emitted-only. `editablePickerEventTypes` (`dashboard/src/features/webhooks/event-catalog.ts`) + `WebhookSettingsCard` show stored never-firing Render types checked (labeled in all 8 locales) and preserve them on save without false all-events compaction. Amended `docs/render-artifacts/webhooks-api.md` and `docs/ADR018-render-parity.md`. Verified with backend tests (`go test ./...`), `make lint`, and dashboard `yarn lint` + `yarn test`.
