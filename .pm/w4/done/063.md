## Finding 1 — workspace help documents Render's configuration path

- **Severity:** minor. **Attribution:** Bex launcher.
- **Repro:** `bex workspace set --help`; repeat with the HEAD-built binary under the same private configuration.
- **Actual:** exit 0, empty stderr, installed 0.04s; HEAD 2.24s. Exact relevant stdout excerpt (remaining usage/flags omitted):

```text
The active workspace is saved in cli.yaml in the bex CLI config directory. Set
the RENDER_CLI_CONFIG_DIR environment variable to override this directory. If
unspecified, the config file is saved in $HOME/.render/cli.yaml.
```

- **Expected:** describe `BEX_CLI_CONFIG_DIR`, exact-path `BEX_CLI_CONFIG_PATH`, and the actual default `$HOME/.bex/cli.yaml`. Any discussion of the intentional upstream override must accurately explain the bridge's real precedence, not present it as Bex's normal setup.
- **Wire/runtime evidence:** no HTTP request is involved. The observed isolated `workspace set` → `workspace current` round trip succeeded and wrote only its configured 0600 file. Default resolution is source-verified at `lego/cli/internal/bridge/bridge.go:56` (Bex exact path, then Bex directory, then `.bex/cli.yaml`).
- **Root cause:** pinned upstream `cmd/workspaceset.go:21` owns that `Long` text. `lego/cli/internal/branding/branding.go:72` applies `RewriteText` to it, but `RewriteText` at line 105 only changes selected product/command phrases. The output therefore changes “Render CLI” to “bex CLI” while retaining the incompatible path/instructions.
- **Fix:** override this specific exported command's help in the Bex overlay with the actual bridge contract. Preserve explicit upstream overrides and their implementation. Do not globally replace `.render` paths: the upstream skills path is an acknowledged residual.
- **Unverified:** no personal/default config was opened or changed, and no behavior of a supplied `RENDER_CLI_CONFIG_DIR` override is claimed from this probe.
- **Estimate:** 20m.

## Finding 2 — nested help still tells Bex users to run `render workspace set`

- **Severity:** minor. **Attribution:** Bex launcher.
- **Repro:** `bex postgres create --help`, `bex postgres get --help`, `bex postgres delete --help`, `bex keyvalues create --help`, `bex keyvalues delete --help`; repeat `postgres create --help` with HEAD.
- **Actual:** every command exits 0 with empty stderr. Installed `postgres create --help` took 0.10s; HEAD 0.10s. Exact relevant excerpts (other help omitted):

```text
--workspace <WORKSPACE> ... Defaults to the active workspace (set via 'render workspace set')
```

```text
Name lookup is scoped to your active workspace. If a name isn't found, switch
workspaces with 'render workspace set <name|ID>' and try again, or pass the
```

- **Expected:** these user-facing command examples invoke `bex workspace set`, preserving flags, selectors, protocol identifiers and behavior.
- **Wire/runtime evidence:** help-only, no HTTP. This is editable command metadata, not one of the documented unchangeable upstream `RunE`/error-message residuals.
- **Root cause:** `branding.go:72` walks `Example`, `Short`, and `Long` only; flag `Usage` is never visited. `RewriteText` at line 105 handles backtick-quoted commands and leading bare commands, but not the single-quoted command phrase in these `Long` strings. Producers at the pin: `cmd/pgcreate.go:53`, `cmd/kvcreate.go:51`, and the `Long` metadata of the ten `pg`/`kv` commands below. Cobra's help renderer prints this surviving metadata directly.
- **Fix:** narrowly rewrite the command-reference form and relevant flag usage in the existing overlay. Keep its repeated help-tree walk idempotent; avoid indiscriminate replacement of `render` substrings or upstream implementation bodies.
- **Estimate:** 20m.

## Resolution

The Bex overlay now overrides workspace-set help with the actual bridge default, Bex path/directory inputs, empty-value behavior, and explicit upstream path precedence. It rewrites single-quoted workspace command references and flag usage, visiting shared flag pointers once per help-tree walk. Runtime configuration and upstream command bodies are unchanged.

Fresh-process tests exercise the imported command tree: workspace set, Blueprint validation, and all twelve datastore help forms under both canonical names and pg/kv aliases. Existing root-help and bridge isolation/explicit-override checks pass; additional tests cover repeated flag walks and unchanged filenames, hostnames, environment identifiers, and the upstream skills path.

Validation: `cd lego/cli && go test ./...` (including branding and bridge), `bash scripts/bex-cli-validate.sh`, golangci-lint v2.13.2 built with Go 1.27 (`go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.13.2 run`, zero issues), and `bash scripts/bex-cli-build.sh /tmp/bex-task-063-build` (all four supported targets) passed. The cached operator lint binary was built with Go 1.26 and could not load the CLI; running the pinned linter with the CLI's toolchain resolved that local tooling mismatch.
