## Objective

Say the true thing for each cause, and reserve "ask your operator" for the case where an operator genuinely has to act.

## Context

- `new-session-composer.tsx:167` `handleCreateError` catches `AgentSessionsUnavailableError` and sets one flag, which renders `agentSessions.unavailableTitle` / `unavailableBody`: "Agent sessions aren't configured" / "This platform hasn't enabled cloud agent sessions. Ask your operator to configure the agent-session gateway."
- That copy is correct **only** for the not-configured group. For a transient OpenFGA blip it is wrong in both directions: it says the feature does not exist, and it sends the user to a person who has nothing to fix.
- The composer already has a general `submitError` path and `ERROR_FIELDS` field-mapping for coded errors — extend that rather than adding a parallel mechanism.

## Steps

1. Map each t001 code to its own title/body.
2. Keep the operator wording only for not-configured.
3. Give retryable faults language that says so and leaves the composer usable, rather than a permanent-looking banner.
4. Add the strings to `en.ts` and `zh.ts`.
