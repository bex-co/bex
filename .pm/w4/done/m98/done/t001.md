## Objective

Persist enough protected state for a different API instance to identify an interrupted save and recover it without guessing which writes completed.

## Context

- The current revision claim stores busy/generation only; `groupPatchTxn` keeps restoration snapshots solely in memory.
- m97 supplies the metadata and lifecycle coordination this record must respect.

## Steps

1. Define a backward-compatible operation record with owner identity, phase, committed revision, and the bounded liveness/reclamation policy.
2. Persist the necessary previous/proposed secret state or immutable version references in existing OpenBao custody before mutating live source/projection state.
3. Teach existing group cleanup and migration helpers about the added paths; define safe handling of legacy busy or repair-required records without recovery data.

## Acceptance criteria

- [ ] Another Service instance can reconstruct which operation owns the group and which source/projection recovery steps remain.
- [ ] A failure writing recovery state occurs before any live secret mutation.
- [ ] Recovery records are bounded, workspace-scoped, and removed with group artifacts; legacy states fail honestly rather than being blindly unlocked.

## Out of scope

- Running recovery and changing public list behavior (t002/t004).
- A new database containing plaintext env vars or secret files.
