# 370 — REST metrics with `resource=` (present but empty) answers 500 "internal error" instead of 400

Why: every sibling validation on the metrics endpoints names the bad input (`resource is required`, `invalid query parameter "startTime"`, a named 404 for an unknown id), but a present-but-empty `resource=` slips the count check and fails downstream as an opaque 500 — a client-caused error logged as a server fault, with no hint what to fix.

**Severity:** minor. **Estimate:** ~30m.

**Source:** live `/qa-find-bugs w4` loop run 23, 2026-10-20 UTC, `muse.env`, workspace `bex-canary`. Read-only probes against the pre-existing `hello-go` (`srv-daif6dsmg29s73d1umvg`); nothing was created, mutated, or deleted this run, and the session was revoked.

## Probes (production, session-authenticated REST)

- `GET /v1/metrics/cpu?resource=srv-daif6dsmg29s73d1umvg&startTime=…&endTime=…` → `200`, real series (control).
- `GET /v1/metrics/cpu` (no resource) → `400 {"message":"resource is required"}`.
- `GET /v1/metrics/cpu?resource=&startTime=…&endTime=…` → `500 {"error":"internal error","id":"internal_error","message":"internal error"}`.
- `GET /v1/metrics/cpu?resource=srv-0000000000000000000000&…` → `404` named `NOT_FOUND` (unknown-id handling is correct).
- `GET /v1/metrics/cpu?resource=<valid>&startTime=banana` → `400 invalid query parameter "startTime"` (time validation is correct).
- Same 500 from the `service=` alias spelling with an empty value.

## Root cause

`requestedResources` (`lego/backend/internal/metrics/rest.go:96-98`) returns the raw `resource`/`service` value slices. The three consumers only count entries — `parseMetricParams` (`rest.go:383-386`, `len == 0`), `parseDatastoreMetricParams` (`rest.go:359-362`, `len != 1`), `filterResource` (`rest.go:196-200`, `len != 1`) — so `[""]` passes as one resource. The empty id then flows into authz/lookup and the metrics source, whose error is not a `core.ErrBadRequest`, so `core.WriteErr` renders it as 500 `internal error`. GraphQL's sibling check (`lego/backend/internal/metrics/graphql.go:466`, wrapped in `%w: resource is required`) was fixed under w4/053; the REST count-based checks were not.

## Fix (target behavior)

- Drop empty values in `requestedResources` (one seam), so an all-empty `resource`/`service` list hits the existing count checks and returns the same `400 resource is required` / `exactly one resource is required` as a missing parameter, on the App-metric, datastore-metric, active-connections, and `filters/*` endpoints alike.
- A mixed list (`resource=&resource=<valid>`) resolves to the one real resource instead of a phantom empty entry.

## Acceptance

- Replaying the probes: `resource=` (and `service=`, and an empty datastore `resource=`) returns `400` naming the missing resource; valid, unknown-id, and bad-time probes are byte-unchanged.
- New unit coverage beside the existing metrics REST tests for empty/blank resource values on at least one App-metric and one datastore-metric route.
- `cd lego/backend && go test ./internal/metrics/...` passes.
