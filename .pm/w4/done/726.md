# In a protected environment a Developer is offered a service's Shell, which the server refuses

Why: Render lets only Admins open a shell in a protected environment, so a Developer must see Shell disabled with Render's reason, not a terminal that fails to connect. Found by w4/m578 t005 on 2026-11-22.

- **What the code does:** `CreateShellSession` and the native SSH path refuse a non-Admin on a protected member with `requireUnprotected(ctx, a, "shell")` (`lego/backend/internal/apps/service.go`, w8/193). The dashboard's Shell tab (`dashboard/src/features/services/components/service-shell-page.tsx`, `web-shell-panel.tsx`) reads no role or protection answer, so it offers the terminal to a Developer there.
- **Not yet seen live:** dev-4 runs no SSH gateway (its agent leg is off), so on 2026-11-22 the Shell tab read "Shell access isn't available" for every role. Replay it where the gateway runs (dev-4 with the agent leg up, or production with a second QA identity) before fixing.
- **End state:** the Shell tab and the terminal's connect control read the verb's rule (`core.RestrictedDecision` for `shell`) and show _This action is limited to admins._ for a Developer in a protected environment, before any connection is attempted; an Admin connects. Tests cover both roles.

**Done 2026-11-23.** `serverActions` now reports `shell` for a web service, private service or background worker by `CreateShellSession`'s own rule: `can_view_sensitive`, and on a protected member the fresh workspace-manage check (`core.RestrictedDecision`), so a Developer there reads `denied` / `protected_environment_admin_required` and a Viewer `insufficient_permission`. The Shell tab mints no ticket until that decision allows it: a refused caller reads the reason in the terminal's frame and in place of the SSH command, with the instance picker disabled, and the Connect menu shows it in place of the `ssh` command and the browser-terminal link. A terminal already open survives a routine re-check; a refusal closes it. ADR018 and ADR032 record it.

- **Replay on dev-4** (OpenFGA enforced, an ssh-gateway run on the host for the Web Shell, an Admin, a Developer and a Viewer of a Scale workspace with a protected `production` and an unprotected `staging`, a starter `nginx:alpine` web service in each, all disposable and deleted after). On main's dashboard the Developer's Shell tab on the protected service minted a ticket, then read "Connection error", Reconnect and _This action is limited to admins._ With the fix, at 1440 and 390: the Developer read _This action is limited to admins._ in the terminal's place, in the SSH card and in Connect, with no `createShellSession` request and no WebSocket. The Admin connected on the protected service and ran `echo admin-<width>-$((6*7))` (`admin-1440-42`, `admin-390-42`). The Developer connected on staging, and the Viewer read the role reason there with no mint. GraphQL `serverActions` and `createShellSession` agreed for all three roles on both services.
- **Tests:** `TestActionCapabilities_ShellAgreesWithTheVerb` (Admin and Developer, protected and not, projection against the verb), `TestActionCapabilities_ShellOnlyForTypesWithInstances`, the Viewer and failed-protection-read cases, the GraphQL `TestLifecycleProjectionsGraphQLProtectedAdminRule`, `use-shell-gate.test.tsx`, and the panel, Shell page and Connect cases; each fails with the fix reverted.
