## Objective

Give the TypeScript driver the Go resolver without a TypeScript port that could drift: a tiny static binary, `lego/backend/cmd/agent-toolchain`, importing `lego/types/toolchains`, built in an agent-image stage and called by the driver.

## Context

- The agent image already ships backend-owned files (`agent-profiles.json`, `lego/agent-image/Dockerfile` ~:30, :83, :311).
- Inputs: a directory (the checkout root) and the environment (`PYTHON_VERSION`, `BEX_AGENT_SESSION_CREATED_AT`). Output: JSON `{line, version, exact, source, narration}` or a named error.

## Steps

1. Write the command and its tests.
2. Add a build stage to `lego/agent-image/Dockerfile` and copy the binary to a fixed path.

## Files

- `lego/backend/cmd/agent-toolchain/main.go` (+ test), `lego/agent-image/Dockerfile`

## Acceptance criteria

- [x] Go tests cover each source (env, file, default) and an unsupported request.
- [x] The image build's check runs the binary in an empty directory and prints the dated default (3.14.10 for a 2026-11-20 creation time).

## Out of scope

- Selecting or installing the interpreter (t005, t006).

## Outcome

Done 2026-11-20. `lego/backend/cmd/agent-toolchain` (`agent-toolchain python [dir]`) prints `{line, version, baked, image?, source, narration, fallback?}`, exits 2 naming a refused request (3.7 included: its official build is bullseye's) and 1 on any other failure. An `agent-toolchain` stage builds it statically from `types/go.mod`, `types/toolchains` and the backend module; the image check runs it in an empty directory for a session created at build time and requires the result to be a baked patch (3.14.10 today) rather than hard-coding the value. Deviation: no `exact` boolean (it equals `image` being set). Tests: `main_test.go` (each source, the legacy line for an unknown time, refusals, a symlinked file ignored).
