# 080 — Coverage record: the credential-word sweep pass 26's audit could not do — tickets are clean, closing that audit's named limit

Why: `w4/m106` shipped on the strength of an audit whose own recorded limit was "it matched on field **names**, so a sensitive field with an unexpected name is invisible to it" — this closes that limit for the credential vocabulary, so the milestone's blast-radius claim does not rest on a sweep that could not see `ticket`.

Record from the live `/qa-find-bugs` loop, 2026-09-14 pass 28. **Read-only on production — nothing created, changed or deleted. No product defect found.**

## What pass 26's sweep could not see

Pass 26 walked the schema for leaves named `secret|password|content|value|*ConnectionString|psqlCommand|snapshotKey|authToken` and concluded the nested-secret gap was exactly `Service.envVar` and `Service.secretFile` — the finding `w4/m106` was built on and `36457c620` then fixed. That regex **omitted** `token`, `apiKey`, `credential`, `bearer`, `auth`, `ticket`, `signing`. Agent sessions mint attach tickets and the model proxy mints credentials, so the omission was not harmless in principle.

## The sweep, and its result

Full introspection over 150 object types, matching field names against `/token|apikey|api_key|credential|bearer|auth|ticket|signing|private/i`. Everything it found, with the disposition:

| field | disposition |
| --- | --- |
| **`AgentSession.ticket`** | reached from `Query.agentSessions`/`agentSession`, both **`core.OpClassRead`** (`scope_matrix_ops.go:192`, `:195`) — but **empty on every read**. Probed live across 50 sessions: `ticketLen: 0` on all sampled. The ticket is minted only by `attachAgentSession` (`agentsessions/graphql.go:302` → `AttachTicket`), classified `core.OpClassWrite` (`:31`). Same show-once shape as `apiKeys.secret` and `webhookEndpoints.secret`. **Clean.** |
| `ShellSession.ticket` | only reachable from `createShellSession`, already `core.OpClassSensitive` (`:59`). **Clean.** |
| `Query.apiKeys`, `Query.registryCredential(s)`, `Service.registryCredentialId` | ids and list roots, not secret values; `apiKeys.secret` verified masked in pass 26. |
| `AuditLog.oauthClientId` / `oauthAudience` / `oauthScopes` | audit metadata about a credential, not the credential — and `w2/m78` added them deliberately. |
| `Mutation.createApiKey` / `createRegistryCredential` / `updateRegistryCredential` / `setRegistryCredential` / `revokeApiKey` / `deleteRegistryCredential` | mint/write verbs, classification covered by `w4/079`'s survey (`createApiKey` is `OpClassMint`). |
| `AcceptedWorkspaceInvite.authorizationPending`, `Repo.private`, `MonthToDateBandwidth.privateLinkEgressBandwidthMB` | regex false positives on "auth"/"private". |

**So the credential vocabulary adds nothing to `w4/m106`'s blast radius**, and its "exactly two fields" claim survives a second, differently-shaped sweep. That is the useful outcome: not a new bug, but a load-bearing claim that is now harder to doubt.
