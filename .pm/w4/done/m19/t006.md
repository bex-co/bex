## Objective

The create-service form behaves like Render's: as the user types (or accepts the repo-derived auto-fill), a debounced availability check runs; a taken name shows **"Name is already in use"** inline under the input with the suggested free name offered as a one-click fix, and a create that still races into a 409 surfaces the same message instead of a generic toast.

## Context

- Form: `dashboard/src/routes/services.new.tsx` — name input `:476-492`, client validation `nameValid` `:239` via `isValidDnsLabel` (`dashboard/src/common/lib/utils/dns-label.ts`), auto-fill from repo/image slug `:225-237` (`nameEdited` gate `:201`).
- Create hook: `dashboard/src/features/services/hooks/use-create-service.ts:51-53` — currently a generic `toast.error` for every failure; must special-case the conflict error from t003.
- Known drift to fix while here: dashboard's `isValidDnsLabel` (leading letter, ≤63) vs backend `ValidAppName` (`[a-z0-9]`-start, ≤30) — align the client rule to the backend's.
- Locale keys: `dashboard/src/features/services/locales/{en,zh}.ts`.

## Steps

1. Add the debounced `serviceNameAvailable` query (Apollo) on the name field; on taken: inline "Name is already in use" + a suggestion chip/button that fills the input (`beancount-cms-v2-1`), disable submit while taken.
2. When the auto-filled repo slug is already taken (same repo → second service), prefill/offer the suggestion instead — the user's "same repo creates multiple services" case.
3. Map the create-mutation conflict error to the same inline message (race window), keep the generic toast for other failures.
4. Align `isValidDnsLabel` with backend `ValidAppName` (≤30, digit-start allowed).
5. Locale keys (en + zh); component test for the taken → suggest → accept → submit-enabled flow.

## Implementation notes (2026-07-13)

- New hook `dashboard/src/features/services/hooks/use-service-name-availability.ts`
  wraps the `serviceNameAvailable` GraphQL query (t005) with the existing
  `useDebounce` (400ms) + skips the query for an empty/already-invalid name.
- `use-create-service.ts` gained `nameConflict`/`clearNameConflict`, mirroring
  the existing `capLimit` pattern — the mutation error handler now
  special-cases an "already in use" message the same way it already
  special-cased the service-cap message.
- The auto-fill-to-suggestion swap (same repo connected twice) is done
  **during render** (React's "store info from previous renders" pattern, a
  `lastAutoSwappedName` state guard), not in a `useEffect` — the newer
  `eslint-plugin-react-hooks` `set-state-in-effect`/`refs` rules reject both a
  direct `useEffect` setState and a ref-guarded variant. Note: the
  **pre-existing** first auto-fill effect (`services.new.tsx`, `setName(repoNameSlug(...))`)
  already violates `set-state-in-effect` on `main`, unmodified by this
  milestone — `yarn lint` was already red before this work; flagged, not
  fixed here (out of scope, and risky to touch blind).
- `isValidDnsLabel` (`dns-label.ts`) now mirrors the backend's `ValidAppName`
  exactly (digit-start allowed, 30-char cap, was letter-start/63-char) — it's
  shared by the database and Key Value create forms too, so their
  `fieldNameError` locale strings and tests were updated in lockstep
  (`-bad`/`-invalid` replacing the old `1bad`/`1invalid` fixtures, which are
  now valid under the corrected rule).
- `dashboard/src/graphql/definitions.ts`: this repo has an established
  convention (predating this milestone — see the `scaleService`/
  `notificationSettings`/`datastoreMetrics`/Projects blocks already in the
  file) of **hand-splicing** codegen output rather than running a full
  `yarn codegen`, because a full regen against the current `src/**/*.graphql`
  sources drops several unrelated, already-shipped operations (no live
  bex-api session available to reconcile against in this environment). The
  `NameAvailability`/`ServiceNameAvailable*` additions follow that same
  pattern — verbatim output from an offline `SCHEMA_JSON`-driven codegen run
  (`SCHEMA_DUMP_PATH=... go test ./internal/api -run TestDumpGraphQLSchema`),
  hand-spliced with the same explanatory comment style.
- Caution for future work: running `yarn format` (bare, repo-wide) or a full
  `yarn codegen` in this dashboard reformats/regenerates a large number of
  unrelated pre-existing files — scope prettier/codegen invocations to the
  files actually touched.
