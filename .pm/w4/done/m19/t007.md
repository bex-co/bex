Proven against the real local CAPD mock cluster (`infra/local/bex.kubeconfig`) with a real operator + bex-api started on the host, a throwaway Docker Hydra + control-plane Postgres, OpenFGA left unset (allow-all, matching `scripts/environments-verify.sh`'s pattern), and two OAuth2 clients standing in for two workspaces. Wrote `scripts/name-conflict-e2e.sh` (leg-numbered, `trap cleanup EXIT`, exit-0 gate, mirrors `environments-verify.sh` + `auth-oauth21-e2e.sh`) — ran it twice (once mid-milestone, once after the t009 simplify-pass fixes) and both runs passed clean:

- **[1]** Workspace A creates `beancount-cms` → REST 201, CR `spec.subdomain=beancount-cms` (bare, no suffix).
- **[2]** Workspace A's repeat create → REST 409, GraphQL error, and MCP `create_web_service` tool error (real Go MCP client, streamable-HTTP, bearer-gated) — all three say `conflict: name "beancount-cms" is already in use`; never a silent redeploy, never a 500.
- **[3]** `serviceNameAvailable("beancount-cms")` in A → `{available:false, suggestion:"beancount-cms-1"}`; creating the suggestion → 201.
- **[4]** Workspace B's `serviceNameAvailable("beancount-cms")` → `{available:true}` — no cross-tenant existence leak. B then creates `beancount-cms` → 201, `spec.subdomain` mints a random 4-char-suffixed slug (`beancount-cms-1nwo` on the reproducing run), distinct from A's bare slug.
- **[5]** The operator reconciles both to Ingress objects with distinct hosts (`beancount-cms.e2e-m19.test` vs `beancount-cms-1nwo.e2e-m19.test`) — no collision.
