## Objective

Make `Service.Create` tell the truth about duplicates, Render-style: a name already used in the caller's workspace → clean **409** ("name is already in use" error shape) on all three adapters; the same name in a *different* workspace → creation succeeds (collision-free CR naming), with no existence leak.

## Context

Current behavior (mapped 2026-07-12):

- Same tenant + same name → silent update-in-place/redeploy (`Service.create` `default` branch, `lego/backend/internal/apps/service.go:520-522`); MCP tool docs advertise it ("Calling it again for the same name redeploys it", `apps/mcp.go:318/329/340`).
- Different tenant + same name → **403** from the tenant-label guard (`core/base.go:253-258`) because bex-api names the CR with the raw name in one shared namespace (`service.go:462`, `BEX_API_NAMESPACE`) — leaks that the name exists elsewhere.
- Store-row conflict → **500**: `store.ErrConflict` (`store/store.go:48`) is never converted to `core.ErrConflict` (`core/errors.go:62`) in the create path (`service.go:490-491`); `domains.go:293` shows the correct conversion pattern.
- Projector already uses collision-free `CRName(tenant, app) = "<tenant>-<app>"` (`store/reconciler.go:248`) — bex-api's raw-name scheme is the divergent one.

## Steps

1. Split create from upsert: `Create` on an existing same-tenant name returns `core.ErrConflict` with message "name is already in use"; redeploys keep flowing through the deploy/update verbs. Update the MCP tool descriptions accordingly.
2. Unify CR naming on the collision-free scheme (tenant-prefixed `CRName` or the t002 slug) so two tenants' `web` coexist in the shared namespace; stop keying the duplicate check on shared-namespace `GetApp(name)` — check within the caller's tenant (store lookup or label-scoped list).
3. Convert `store.ErrConflict` → `core.ErrConflict` in the create path (mirror `domains.go:293`) so the DB constraint surfaces as 409, never 500.
4. Confirm error shapes per surface: REST 409 `{"error": "..."}` (`core/http.go`), GraphQL `errors[]`, MCP tool error — same message.
5. Tests: same-tenant duplicate → 409 across REST/GraphQL/MCP; cross-tenant duplicate → both created, no 403; store-conflict race → 409 not 500.

## Implementation notes (2026-07-13)

- CR naming became collision-free by construction: a store-managed App's k8s
  object name is now `core.CRName(tenantID, name)` (`"<tenant>-<name>"`,
  `lego/backend/internal/core/base.go`), not the raw public name — the same
  scheme the projector already used, now shared via `store.CRName` delegating
  to `core.CRName`.
- `core.Base.GetApp` (the one shared by-name fetch every feature verb uses)
  resolves in three steps: the tenant-prefixed candidate, the bare name
  (hand-applied / pre-migration CRs), then — new — a `LabelServiceName`-scoped
  List across the caller's OTHER workspaces, authorizing each candidate in
  turn. That third step is what keeps the pre-existing w6/m11 guarantee alive
  ("reach your other workspace's App by bare name, no explicit selection")
  once two workspaces can legitimately share a name.
- The create-time duplicate check does **NOT** reuse `GetApp` — it would
  wrongly treat a sibling in one of the caller's OTHER workspaces as "taken"
  in the target workspace. `apps.Service.nameTaken` is a separate, narrowly
  tenant-scoped probe (tenant-prefixed object name, then bare-if-same-tenant).
- `store.ErrConflict` → `core.ErrConflict` conversion lives right after
  `s.Store.CreateApp` in `create()`, the race-safe backstop behind
  `nameTaken`'s pre-check.
- Several pre-existing tests encoded the OLD upsert/leak semantics and were
  rewritten to the new contract rather than left broken:
  `TestCreate_NameTakenByAnotherWorkspaceIsAConflict` →
  `TestCreate_NameTakenByAnotherWorkspaceStillSucceeds` (the milestone's whole
  point), `TestCreate_SameNameSameWorkspaceStillRedeploys` →
  `...IsAConflict`, `TestCreateIsUpsertRedeploy` →
  `TestCreateNeverUpsertsExistingApp`, plus the `TestRedeploy*` tests in
  apps_test.go that exercised `create()`'s removed redeploy branch.
