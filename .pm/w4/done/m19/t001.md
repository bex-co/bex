## Objective

Record the evidence for Render's duplicate-name model in `docs/render-artifacts/` so the milestone's design decisions trace to observed/documented Render behavior, the way other parity work does (e.g. `docs/render-artifacts/new-service-wizard.md`).

## Context

- Verified 2026-07-12: Render docs — "All of a workspace's services must have unique names—even services that belong to different project environments" (render.com/docs/projects).
- The `onrender.com` subdomain is an API-visible `slug` distinct from `name`; it is made globally unique with a random short suffix: docs example `helloworld-p9vq.onrender.com` (render.com/docs/your-first-deploy), user-observed `beancount-cms-bkxk.onrender.com`.
- User-observed dashboard behavior: entering an in-use name in the create form shows "Name is already in use"; the form suggests a free alternative (`beancount-cms-v2` taken → `beancount-cms-v2-1`).
- `docs/render-artifacts/new-service-wizard.md` already documents name auto-fill from the repo slug but nothing on duplicates/suffixing.

## Steps

1. Write `docs/render-artifacts/duplicate-service-names.md`: the workspace-uniqueness rule (with the docs quote + URL), the slug-vs-name distinction, the random-suffix examples, and the dashboard's reject + suggest UX.
2. Cross-link it from `docs/render-artifacts/new-service-wizard.md`'s name-field section.
3. `npx prettier@3.4.2 --write "**/*.md"`.
