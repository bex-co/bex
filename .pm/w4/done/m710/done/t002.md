## Objective

Mount the t001 block wherever Render mounts its Networking component. A primary Postgres database and a Key Value instance show the workspace level, plus the environment level when they belong to one. An environment shows the workspace level only.

## Context

- Render's bundle mounts the same Networking component on a primary database, a Key Value instance, an environment's settings and web and static services.
- The environment variant passes no environment, so it reads only the owner's list. Workspace Settings passes `entityType: Owner`, which reads neither.
- bex panels:
  - `features/databases/components/access-control-panel.tsx`
  - `features/keyvalue/components/key-value-networking-panel.tsx`
  - `features/environments/components/environment-networking-card.tsx`
- Both datastore queries carry `environmentId` (`features/databases/api/databases.graphql`, `features/keyvalue/api/keyvalue.graphql`).

## Steps

1. Mount the block in each of the three panels, above the resource's own editor.
2. Leave a read replica's panel as Render does (Render mounts the component on the primary only), and leave Workspace Settings unchanged.

## Files

- `dashboard/src/features/databases/components/access-control-panel.tsx`
- `dashboard/src/features/keyvalue/components/key-value-networking-panel.tsx`
- `dashboard/src/features/environments/components/environment-networking-card.tsx`

## Acceptance criteria

- [ ] A Postgres database and a Key Value instance in an environment show both levels. Outside one, they show the workspace level only.
- [ ] An environment's Networking card shows the workspace level, and Workspace Settings shows no "Affected by" block.

## Out of scope

- A datastore's below-Scale behavior. Rules for managed datastores are available on all plans, as Render's docs say, and nothing here changes that.
