# 476 — A workspace registry credential for docker.io is silently applied to every docker.io image service that selected none, so one unusable credential turns every public Docker Hub deploy into `update_failed: registry token request returned status 401`

Why: Render pulls a public image anonymously unless a credential is selected on the service, so on bex a stale or fixture credential in the workspace breaks unrelated services, and the failure text gives the owner nothing to act on. The host auto-match behind it is not recorded in ADR018 (AGENTS.md: a divergence stands only when ADR018 records it with the user's sign-off).

Source: live `/qa-find-bugs` w4 loop run, round 46, 2026-11-04 UTC (`muse.env`, workspace `bex`). Fixture service `qa-20261104-whoami` (`srv-dbljf7sncp7s738f14ug`), created and deleted in the same visit (DELETE 204, then GET 404, no `qa-` services left). Severity: major (a core journey, deploying a public image, fails with a misleading reason; a one-step workaround exists). Estimate: 60m.

## Repro (REST, in-page `fetch` from dashboard.bex.co)

The workspace already held a DOCKER credential `rgc-dblj0iug3pks73ck0kn0` named `qa-20261104-reg`, created minutes earlier by another session, not by this run. It was left untouched; its validity is unknown. The second repro below does not need it.

1. `POST /v1/services` with `{type:"web_service", name:"qa-20261104-whoami", ownerId:"tea-d98210cbbpdc73dcrkvg", image:{ownerId, imagePath:"docker.io/traefik/whoami:v1.10"}, serviceDetails:{plan:"free", runtime:"image", env:"image", region:"frankfurt"}}` returns 201 and `service.registryCredential` is null. The first deploy ends in 13 s with status `update_failed` and `failureReason: "registry token request returned status 401"`. The `deploy_ended` event carries the same text.
2. `PATCH` the image to `docker.io/library/nginx:1.27-alpine` and `POST /deploys`: `update_failed`, same reason.
3. `PATCH` the image to `ghcr.io/traefik/whoami:latest` and deploy: `live`. A registry with no stored credential works.
4. **Control.** `PATCH {image:{ownerId, imagePath:"docker.io/library/nginx:1.27-alpine", registryCredentialId:""}}` and deploy: `live`, and `curl -sSI https://qa-20261104-whoami.onbex.co` returns `HTTP/2 200`. Same image, same service; the only change is the explicit clear.

## Second repro with only this run's own fixtures (round 47, 2026-11-04 UTC)

1. `POST /v1/registrycredentials` with `{name:"qa-20261104-ghcr", ownerId:"tea-d98210cbbpdc73dcrkvg", registry:"GITHUB", username:"qa-nobody", authToken:<a fake ghp_ token of zeros>}` returns 201, id `rgc-dbljma4ncp7s738f1510`.
2. `POST /v1/services` with `{type:"web_service", name:"qa-20261104-ghcr", image:{imagePath:"ghcr.io/traefik/whoami:latest"}, serviceDetails:{plan:"free", runtime:"image", env:"image", region:"frankfurt"}}` returns 201 (`srv-dbljmaeg3pks73ck0la0`); no credential is selected.
3. The first deploy ends `update_failed` with `failureReason: "registry token request returned status 403"`. The same image deployed `live` in round 46 step 3 while the workspace had no GHCR credential, so the only change is the stored credential.
4. Cleanup: `DELETE` service 204, `DELETE` credential 204, `GET /v1/registrycredentials` lists only the other session's `qa-20261104-reg`.

What this adds:

- The behavior does not depend on the other session's credential or on Docker Hub; it reproduces on a second registry host (`ghcr.io`) with this run's own fixtures.
- The status code follows the registry (Docker Hub 401, GHCR 403), so the fix must treat 401 and 403 alike.
- Any workspace member who stores a credential for a host, even a mistyped one, breaks every unselected public image from that host.

## Root cause

- `lego/backend/internal/registrycreds/pullsecret.go:100-108` (`resolvePullCredential`): with `credentialID == nil` it falls back to `GetRegistryCredentialByHost(workspaceID, registryHost(image))` and materializes `<app>-registry-pull` from it (`:136-160`). A `""` id is the only way out (`:67-69`, "explicit clear: do not fall back to host matching").
- The operator then sends that credential as Basic on the Bearer realm exchange: `lego/operator/internal/controller/image_network.go:98-125` (`externalImageAuthHeader`) feeds `lego/operator/internal/registry/image_config.go:225-226`. The failure is reported at `:234` as `statusFailure("registry token request", 401)`, which names neither the registry nor the credential nor says a credential was used.
- w4/149 (done) treats the host auto-match as an intended feature ("Auto-matching silently skips it"), and `docs/ADR004-app-deployment.md:162` says an image is read "anonymously, or with the workspace registry credential bound to it". Nothing records that a credential the service never selected is bound by host.

## Fix (target behavior)

Recommended, the parity-sufficient choice: a stored credential is used only when the service selects it (`image.registryCredentialId` on REST, the credential picker in the dashboard, the matching GraphQL and MCP fields), as on Render. An image with none is read anonymously.

If removing the implicit match is judged too disruptive for existing private-image services, the minimum is:

- when an auto-matched (never selected) credential's token exchange returns 401 or 403, retry anonymously;
- when the deploy still fails, say which credential was used, e.g. "registry token request for docker.io with credential qa-20261104-reg returned status 401".

Either way, record the chosen rule in ADR018's Registry credentials row.

## Blast radius and adjacent classes

- `resolvePullCredential` is reached through `pullSecretSource` (apps create and update, `lego/backend/internal/deploys/service.go:745-794`) for every image-backed service and the Docker-build FROM binding. Callers that rely on the implicit match today are private-image services that never picked a credential, so they need regression tests: selected credential works, unselected public image is anonymous, unselected private image after the change.
- Aliases: REST `POST`/`PATCH /v1/services`, deploys with `imageUrl`, GraphQL `createService`/`setImage`, MCP `create_`/`update_service`, Blueprint image services.
- Adjacent classes: 401/403 from a credentialed exchange (bad credential); 429/5xx stay transient; a missing OpenBao secret already errors by name (`pullsecret.go:117-124`).
