# Project and custom-domain lists accept Render's `name` and time filters, then return everything

Why: `GET /v1/projects?name=zzz` answers 200 with every project, and `GET /v1/services/<srv>/custom-domains?name=zzz.example.com` answers with every domain. A script or CLI that resolves a project or domain by name gets the whole list back and, taking the first row, acts on the wrong resource. An unknown filter would be better refused than silently ignored. This is the same class as `w4/164` (services `env`), on two more operations.

Found live in `/qa-find-bugs` pass 243 on 2026-09-27 (w4-targeted, `muse.env` credentials) against the deployed `4a0422577`. Read-only: in-page `fetch` from `dashboard.bex.co`, `ownerId=tea-d98210cbbpdc73dcrkvg` (3 projects), service `srv-d9bkcspg9s7c73d0n8ug` (1 custom domain, verified).

| request | result |
| --- | --- |
| `GET /v1/projects?ownerId=…` | 200, 3 |
| `…&name=zzz` | 200, **3** ❌ (want 0) |
| `…&createdAfter=2030-01-01T00:00:00Z` / `…&updatedAfter=2030-01-01T00:00:00Z` | 200, **3** ❌ |
| `GET /v1/services/<srv>/custom-domains` | 200, 1 |
| `…?name=zzz.example.com` | 200, **1** ❌ |
| `…?createdAfter=2030-01-01T00:00:00Z` | 200, **1** ❌ |
| control: `…?verificationStatus=unverified` | 200, 0 ✅ |
| control: env-groups, postgres, owners, registry credentials `name=zzz` | 0 ✅ |

## Mechanism

- Render's embedded spec (`lego/backend/internal/api/openapi/render-public-api-1.json`) lists `name`, `createdBefore`, `createdAfter`, `updatedBefore` and `updatedAfter` on `list-projects`. It lists `name`, `domainType`, `verificationStatus`, `createdBefore` and `createdAfter` on `list-custom-domains`. The OpenAPI gate (`internal/api/render_openapi.go`) therefore admits them.
- `lego/backend/internal/projects/rest.go:119-141` reads only `ownerId`, `cursor` and `limit`.
- `lego/backend/internal/apps/rest.go:1098-1114` `listDomains` passes only `verificationStatus` and `domainType` to `filterDomains`. `name` and the time window are dropped.
- The siblings that work use `core.QueryList(q, "name")` + `core.QueryTimeWindow` (`apps/rest.go:682-702`, and postgres/keyvalue/env-groups).

## Fix

Target: each admitted Render filter narrows, with the same semantics its siblings use.

- `name`: exact match, OR'd across repeated values.
- Time window: RFC3339, a named 400 on malformed input.
- Projects: apply `name` + all four time params via the shared `core.QueryList`/`core.QueryTimeWindow`.
- Custom domains: apply `name` + `createdBefore`/`createdAfter`. `DomainView` needs a created time. If none is recorded, say so in ADR018 and pass the window through as the siblings do for an empty timestamp.
- Tests go through the gated server. The admitted-but-unread audit test from `w4/164` should list both operations until this lands, then drop them.

GraphQL (introspected in pass 244): `projects(ownerId, cursor, limit)` and `customDomains(id, verificationStatus, domainType, cursor, limit)` expose no `name`/time arguments, so the defect is REST-only. Unverified: `domainType=apex` returned the one domain, which may be correct if it is an apex host (not checked).

Render: its API docs list these as filters on both operations (per the embedded OpenAPI).

Estimate: ~40m.

Closed 2026-09-27: Projects now filter exact repeated names and created/updated time windows before pagination; custom domains filter names and creation windows using durable claim timestamps. Legacy domains without timestamps retain the shared missing-time behavior, documented in ADR018. Gated filter tests and full projects/apps suites passed. Shipped before 164 because its query census depends on these fixes. No live production re-probe performed.
