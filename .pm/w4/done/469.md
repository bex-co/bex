# 469 — The New Web Service "Existing Image" hint still says to set the port to the image's fixed port, which contradicts the Port field below it

Why: since w4/m243, bex publishes every port an image `EXPOSE`s and picks the primary itself, as Render does. But the hint directly under the Docker Image box still tells users to set the port manually. A user deploying `nginx` or `traefik/whoami` either does unneeded work or doubts the Port field's (correct) "Optional" text.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 6, 2026-11-04 ~12:05 UTC (`muse.env`, `bex-canary`, pin `fb6098dd2e37`); **minor** (copy); ~15m.
- **Repro:** `/services/new` → Existing Image tab. The tabpanel reads: _"If the image listens on a fixed port (for example :80), set the port below to it — bex routes there and injects it as $PORT."_ The Port field below it reads: placeholder _"From the image"_, help _"Optional. bex publishes every TCP port the image declares (EXPOSE); 3000 if declared, else the lowest declared, else 10000, becomes $PORT and the health-checked primary. Set a port to choose the primary yourself."_
- **Control (the Port help is the true one):** round 1 of this loop (10:00 UTC) created `docker.io/traefik/whoami:latest` (EXPOSE 80) over REST with no port. The deploy log said `==> Detected HTTP on port 80; serving it` and `curl` got 200. The fixture is deleted.
- **Root cause:** `dashboard/src/features/services/locales/en.ts:3396-3401` (`services.createImagePortHint`, written for w9/011 and w6/m149 before w4/m243 shipped detection) and its zh twin at `zh.ts:3325-3328`. It is rendered at `features/services/components/service-source-picker.tsx:355-358` when `showPortHint` is set, which happens only in the create wizard (`routes/services.new.tsx:199`). The Settings source card passes `false` (`service-source-card.tsx:312`).
- **Fix:** either reword the hint to match the Port help (for example: "bex uses the port the image declares (EXPOSE). Set a port below only if the image listens on a port it doesn't declare.") or drop it and let the Port help speak. Update en and zh, and any test that pins the old string.
- **Render:** Render detects the port an image binds to and, for an image, does not ask for a port up front.
- **Dedupe:** `grep -rl "listens on a fixed port" .pm` returns nothing. `git log -S"listens on a fixed port"` → `b01debc5d` (w6/m149 t006) only. w4/m243 (done) changed the Port help but not this hint. No DO_NOT_DO item applies.

- 2026-11-04: fixed by the loopx w4 drain: `services.createImagePortHint` (en, zh) now says bex uses the port the image declares (EXPOSE) and the Port field is only for undeclared ports; `services.new.test.tsx` updated.
