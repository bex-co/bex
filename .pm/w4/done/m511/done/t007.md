## Outcome

Verified parity across all surfaces against Render's webhook documentation and pinned `retrieve-event` schema:

- **Event type & payload:** `postgres_read_replica_stale` with `serviceId: "<dpg-...>"` and `details: {}` on REST retrieve (`GET /v1/events/{id}`), GraphQL (`serviceEvent`), MCP (`get_service_event`), and signed outbound webhook deliveries (plus `GET /v1/webhooks/{id}/events`). Matches Render's empty member (`TestDatastoreEventTypeContract` + `TestRestVocab` pass against the pinned Render OpenAPI fixture).
- **Lifecycle semantics:** one event per non-syncing episode past the 2-minute threshold, silent re-arm on recovery (no recovery event), no notification email, and no new public fields added to `/v1/postgres/{id}` (read-replica sync status stays internal on `Database.status.readReplicas`).
- **Feed placement:** datastore events stay out of `/v1/services/{id}/events` (enforced by `TestObservedDatastoreTypesStayOutOfTheServiceFeed`, matching Render's OpenAPI which has no `/v1/postgres/{id}/events` list endpoint).
- **Dashboard:** `postgres_read_replica_stale` appears in the webhook event picker under the Postgres group with matching Render description across all 8 locales (`de`, `en`, `es`, `ja`, `ko`, `pt`, `ru`, `zh`).
- **Drift:** none found.
