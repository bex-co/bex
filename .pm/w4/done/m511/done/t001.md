## Objective

Break a read replica's streaming on dev-4 and find the signal that says, without false alarms, that the replica has stopped syncing with its primary; fix the threshold and the recovery rule.

## Context

- Each named read replica is its own one-instance CNPG replica cluster streaming from the primary (`lego/types/v1alpha1/database_types.go:282-292`, `ReadReplicaClusterName`); its status is `ReadReplicaStatuses` (`:710-715`, `:832`).
- Replication lag is already charted from CNPG's `cnpg_pg_replication_lag` (`lego/backend/internal/metrics/datastore.go:67-71`); CNPG also exports `cnpg_pg_replication_is_wal_receiver_up` and reports instance state on the replica `Cluster` status.
- The operator writes datastore status the backend projects into facts (`lego/operator/internal/controller/database_controller.go`, readiness at `:1055-1063`); prefer a signal the operator reads from the cluster over a Prometheus query.

## Steps

1. Create a paid Postgres with one read replica on dev-4.
2. Stop its streaming (for example a NetworkPolicy that blocks the replica cluster from the primary) and record what each candidate signal shows, and how fast.
3. Restore streaming and record the recovery; check that a replica's initial sync and a primary failover do not look stale.
4. Write the chosen signal, threshold and recovery rule into `docs/ADR009-postgresql-management.md`'s read-replica section.

## Outcome

Verified on `dev-4` (2026-11-19) using a `1c-2g` HA PostgreSQL 17 database (`dpg-dbve0i9jg4r0onr4g71g`, workspace `tea-dbve08hjg4r0onr4g70g`) with one read replica (`reader`, cluster `dpg-dbve0i9jg4r0onr4g71g-r-3d0941964a`):

- **Eliminated candidates:**
  1. Replica CNPG `Cluster.status`: stayed `phase: "Cluster in healthy state"`, `readyInstances: 1`, `Ready=True` for the entire 95 s streaming outage while rows diverged (primary 9→17 vs replica 8).
  2. Prometheus `cnpg_pg_replication_*`: CNPG's `:9187/metrics` `pg_replication` query fails on replica clusters with `FATAL: database "app" does not exist (SQLSTATE 3D000)` because `bootstrap.pg_basebackup` leaves CNPG's application database name defaulted to `app` while bex's database is `dpg_…`.
- **Chosen signal:** Direct HTTPS poll of CNPG's instance-manager status endpoint `https://<pod-ip>:8000/pg/status` (pod IP from `Cluster.status.instancesReportedState`, TLS verified against `Cluster.status.certificates.serverCASecret`, admitted by `allow-operator-probe-ingress` / `allow-datastore-control-ingress`). Syncing predicate on standby (`isPrimary: false`): `isWalReceiverActive && !replayPaused`.
- **Observations:**
  - Initial sync: `readyInstances == 0` during `pg_basebackup`; once `readyInstances == 1`, `isWalReceiverActive: true`.
  - Streaming break (Calico `Deny` NetworkPolicy blocking replica → primary `:5432` + terminating the replica's walsender): `isWalReceiverActive` flipped to `false` within <1 s and stayed `false` for 95 s (`receivedLsn`/`replayLsn` frozen at `0/50506C0`).
  - Recovery (NetworkPolicy deleted): reconnected at `T+28s`, `isWalReceiverActive` flipped back to `true`, rows caught up (`22 == 22`).
  - HA primary failover (`POST /v1/postgres/{id}/failover`): switched in ~5.7 s; `isWalReceiverActive` dipped to `false` for ~10.6 s (`T+3.1s..10.8s`), back to `true` at `T+13.7s`.
- **Threshold & recovery rule:** Poll every 30 s when primary is settled and replica is ready; stamp `syncStoppedAt` on first non-syncing sample while holding `syncing: true`; flip `syncing: false` after 2 minutes (120 s) continuous non-syncing; preserve state on transient probe error; clear `syncStoppedAt` and set `syncing: true` on first syncing sample; skip/clear during suspension or non-settled primary. Recorded in `docs/ADR009-postgresql-management.md`.

## Out of scope
