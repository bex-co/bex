# 694 — After a rename, a custom domain's `server.name` still reads the service's creation name, not its name

Why: Render's `customDomain.server` is the owning service `{id, name}`, and `name` is the service's current name. On bex it stays the name the service was created with, so after a rename the custom-domain API names a service that no longer exists under that name, while `GET /v1/services/<id>` reads the new one.

- **Source / severity / estimate:** w4/m337 live DoD replay, 2026-11-16 20:32 UTC (`bex-canary`, pin `7aaa8700befa`). **Minor** (parity; nothing breaks). ~20m.
- **Fixture:** Free web service `qa-20261116-r337-web` (`srv-dbtmgonmufrc73b9vm60`, whoami), renamed in Settings to `qa-20261116-r337-renamed`, then `POST …/custom-domains {"name":"qa-20261116-r337.example"}`. Deleted afterwards (DELETE 204, GET 404).
- **Probe:** the POST answer and `GET …/custom-domains` both carry `"server":{"id":"srv-dbtmgonmufrc73b9vm60","name":"qa-20261116-r337-web"}`; `GET /v1/services/srv-dbtmgonmufrc73b9vm60` reads `"name":"qa-20261116-r337-renamed"`.
- **Root cause:** `DomainView.ServiceName` is set from `core.AppPublicName(app)` (the immutable creation-name label) at `lego/backend/internal/apps/domains.go:715` (storeless view) and `:739` (claim view). The displayed name is `core.DisplayedAppName` (`lego/backend/internal/core/base.go:1632`), which `registrycreds/service.go:399` and `envgroups/render.go:74` already use for the same `{id, name}` shape. REST, MCP and GraphQL `CustomDomain.server` all read `DomainView.ServiceName`.
- **Fix:** use `core.DisplayedAppName(app)` at both sites. Then audit the other 26 non-test `AppPublicName(` callers in `lego/backend/internal` for ones that render Render's service `name` to a client (as opposed to the slug, URLs or lookup keys), and switch those too.
- **Tests:** a domain-view test with `spec.displayName` set expects it in `ServiceName`; an unrenamed service still reads its creation name.
- **Dedupe:** `grep -rli "server\.name\|AppPublicName" .pm` finds no open item (w8/225, done, was a different site).
- **DoD (live):** rename an owned `qa-` service, add a throwaway `qa-` hostname: `server.name` on REST and GraphQL is the new name. Delete the fixture.

**Done 2026-11-16 (`/loopx w4`):** both `DomainView` builders (`lego/backend/internal/apps/domains.go` storeless and claim views) set `ServiceName` from `core.DisplayedAppName`, so REST, MCP and GraphQL `server.name` read the current name. Audit of the other `AppPublicName(` callers: the client-facing name strings also switched — the crash-loop and disk-usage alert emails (`crashloop.go`, `diskusage.go`), the suspended "Save and deploy" conflict (`secrets/batch.go`), the concurrent-update conflict (`rollout/rollout.go`), the Free-hours refusal (`apps/free_hours.go`) and the blueprint export's Free-plan refusal (`blueprint_generate.go`). Left on the creation name because it is a lookup key, URL path or sync key: deploy triggers and the deploy-started email (its logs URL is keyed on it), `AppView.Name`/`publicID`, blueprint export `name` and claim keys, name-availability/snapshot keys, the rename event's fallback and the secrets audit target. `TestDomainServerNameIsTheDisplayedName` (both views; renamed and unrenamed) fails with the old call. The live replay of the DoD rides the next production pin.
