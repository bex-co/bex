## Objective

Cover the behavior this milestone shipped with tests that assert real outcomes and real failure modes.

## Context

- The regression risk is asymmetric: the types that behave correctly today do so because the port could never change. They need coverage as much as the fixed path does (t005 owns the per-type table; this task owns the rest).

## Steps

1. Backend: update accepted and rejected (bounds, portless types), read-back agreement across REST/GraphQL/MCP, and agreement between `serviceDetails.port` and the `internalAddress` suffix.
2. Operator: a port change reaches the Service targetPort, Ingress backend port and probe port; `appEnv` still strips a user `PORT` and still beats `envFrom` (the unchanged control).
3. Dashboard: the create wizard sends `port`; the Settings control calls the update verb; the env editors still block `PORT` and their link resolves; no port control renders for worker/cron/static.
4. Show the key tests failing against the pre-fix code (stash-run) so they are known to be load-bearing.
