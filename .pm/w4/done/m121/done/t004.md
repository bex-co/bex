## Objective

Close the last two surfaces the refusal reaches. Blueprint (`render.yaml`) has no port key at all, so a manifest author who hits the `PORT` refusal during validation is told to change a setting their manifest cannot express. And the sentence itself — one shared string rendered by REST, GraphQL, MCP, Blueprint validation and both dashboard editors — must name a control each of those readers can act on.

## Context

- `lego/backend/internal/core/config.go:105-107` — `ReservedEnvKeySentence` is deliberately one wording for all surfaces ("so a caller who learns it on one surface recognizes it on the next"). Any change is a change everywhere; that is the point, and it is also the blast radius.
- `grep -w port lego/backend/internal/apps/blueprint.go` → **0** hits: no manifest port key today.
- Render's `render.yaml` has no port field either — Render detects the bound port. So adding one is a bex extension, and _not_ adding one is defensible; what is not defensible is the current state, where Blueprint validation emits a sentence naming a setting that surface cannot reach.
- `docs/ADR018-render-parity.md` row 117 records the `PORT` refusal as a deliberate divergence and explicitly **rejected** (2026-09-15) honoring a user `PORT` as `spec.port`, because "an env-group `PORT` would then silently re-route and re-health-check every linked service at once". That rejection is about env-group semantics and does not bar a first-class per-service port setting — say so explicitly in the updated row so the next reader does not mistake this milestone for a reversal.

## Steps

1. Decide: does `render.yaml` gain a per-service port key, or does Blueprint validation's refusal instead point the author at the API/dashboard control? Write the decision and the rejected alternative into ADR018 row 117 and `docs/ADR004-app-deployment.md`'s `envVars` note.
2. If the decision is "no manifest key": make the Blueprint-flavoured refusal (which renders the sentence with a manifest location instead of a code — `parseServiceEnv`, `parseEnvGroup`) say where the port _is_ changed.
3. Re-word `ReservedEnvKeySentence` if needed so it names the field/verb, and verify the new wording renders correctly on every surface that shares it: REST, GraphQL, MCP, Blueprint validation, service env editor, env-group editor.
4. Update `docs/ADR018-render-parity.md` row 117's factual claims: the alternative now exists, where it lives, and on which surfaces it can be read and written (t001/t002 results).
