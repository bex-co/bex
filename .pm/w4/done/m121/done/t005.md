## Objective

`spec.Port` is read by more than one consumer. Making it mutable for the first time means every reader has to follow the change, and every type that has no port has to keep not having one. Enumerate the readers, prove the rollout, and regression-test the types that behave correctly today _because_ the port could never change.

## Context

- `lego/operator/internal/controller/app_controller.go:3994-4026` — `appEnv` injects `PORT` from the resolved port and strips a user entry of the same name. That invariant is unchanged by this milestone and is the control case: it must still win over `envFrom`.
- `lego/types/v1alpha1/app_types.go:504-507,777-797` — `AppSpec.Port` and its `EffectivePort()` accessor (`<= 0` ⇒ default). `app_identity.go:75` classes `Port` as `IdentityRelease`, so a port change already participates in the release fingerprint — confirm what that implies for the rollout rather than assuming it.
- `lego/backend/internal/apps/deploy.go:1829,1910-1970` — `servicePorts` feeds Blueprint `fromService` host/port references. A service whose port changes is a service other manifests may be pointing at; say what happens to a stale reference.
- Consumers to enumerate and confirm by grep with counts, not estimate: the k8s Service targetPort, the Ingress backend port, the health/readiness probe port, `internalAddress`, the activator's wake path for free-tier sleep, and `servicePorts` above.
- Types with no port: `background_worker`, `cron_job`, `static_site`. `private_service` **does** have one and is the least-probed type in this milestone (see the milestone's Unverified list).

## Steps

1. Grep every reader of `Spec.Port` / `EffectivePort()` across `lego/operator` and `lego/backend`; paste the count and the list into the task's completion notes.
2. For each, state whether it follows a port change automatically (recomputed each reconcile) or caches it.
3. Run the live change end to end on a throwaway service: create at `8080`, change to `8081` with the container following, and confirm the Service targetPort, the Ingress backend port, the probe port, `internalAddress` and the served URL all move.
4. Confirm free-tier sleep→wake still works on a service with a non-default port (the activator is a port consumer that only shows up when the service is asleep).
5. Add regression tests for the portless types: a port on create and on update is refused or ignored identically, per type, across REST/GraphQL/MCP — a table test enumerating web · private · worker · cron · static.
