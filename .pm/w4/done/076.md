# Pre-w4/m105 API keys cannot request advertised scopes until reminted

Why: w4/m105 grants `scope=bex.read bex.write bex.sensitive` on **new** Hydra clients so discovery-driven exchanges succeed; keys minted before that change still have an empty Hydra `scope` and `invalid_scope` if the caller passes `scope=`. Omitting `scope` still works. Remint (or admin-patch the client) if a scoped exchange is required — not a silent migration.

## Residual from w4/m105/t004

No code change needed for existing keys; document for operators and anyone scripting against old credentials.
