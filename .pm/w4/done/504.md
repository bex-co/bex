# 504 — A registry credential read, rename or delete with an id that is not valid UTF-8 still answers `500 internal error` after the w4/490 fix, which guarded only `GetRegistryCredentialByID`

Why: w4/490 promised every Postgres-backed by-id route answers 404 for a malformed id, and live verification shows projects and environments do, but the three registry-credential routes still report a customer's typo as a server failure, which pollutes 5xx alerting and shows "internal error" instead of "not found".

- **Source / severity / estimate:** live `/qa-find-bugs w4` verification of w4/485–492, 2026-11-05 ~16:30 UTC (`muse.env`, workspace `bex`, deploy pin `e3211740a` → `cc3c51e12952`, which contains `edc4b0a15` and `ac622df36`); **minor** (a malformed id was never going to resolve; the defect is the status class and message, and the fix is partly shipped); ~20m.
- **Incomplete fix of w4/490** (done). 490's table listed `/v1/registrycredentials/{id}` with `%C0%80`, `%ED%A0%80` and `%FF%FE` all answering 500. After the deploy, the other rows moved and this one did not.
- **Probe** (in-page `fetch(..., {credentials:'include'})` against `https://api.bex.co`, 700 ms apart, read-only plus two writes on a non-existent id, so nothing real can change):

  | Request | Before the deploy (2026-11-05 ~13:00 UTC) | After (~16:30 UTC) |
  | --- | --- | --- |
  | `GET /v1/projects/%C0%80` | 500 | **404** `project not found` |
  | `GET /v1/environments/%C0%80` | 500 | **404** `environment not found` |
  | `GET /v1/postgres/a%2Fb`, `/v1/key-value/a%2Fb` | 500 | **404** |
  | `GET /v1/registrycredentials/%FF%FE` | 500 | **500** `internal error` |
  | `GET /v1/registrycredentials/%C0%80` | 500 | **500** |
  | `PATCH /v1/registrycredentials/%FF%FE` `{"name":"x"}` | not run | **500** |
  | `DELETE /v1/registrycredentials/%FF%FE` | not run | **500** |
  | `PATCH` and `DELETE` on `/v1/projects/%FF%FE` and `/v1/environments/%FF%FE` | not run | 404 (clean) |
  | `GET /v1/webhooks/%FF%FE`, `/v1/disks/%FF%FE` | 400 | 400 (clean) |
  | `GET /v1/env-groups/%FF%FE`, `/v1/build-sources/%FF%FE` | 404 | 404 (clean) |
  | `GET /v1/registrycredentials/rcr-nope` (valid, unknown) | 404 | 404 (control) |

  The `500` body is `{"error":"internal error","id":"internal_error","message":"internal error"}`.
- **Root cause (read at `origin/main` `e3211740a`):**
  - 490's fix added `if !textBindable(id) { return …, classify(…, pgx.ErrNoRows) }` to exactly three by-id readers: `GetProject`, `GetEnvironment` and `GetRegistryCredentialByID` (`lego/backend/internal/store/registrycredentials.go:122`). `GetRegistryCredentialByID` is only the resource-binding resolver used by `registrycreds/pullsecret.go:90` and `service.go:176`.
  - The public routes do not use it. `Service.Get` (`registrycreds/service.go:200`) calls the **workspace-scoped** `GetRegistryCredential` (`store/registrycredentials.go:108`), and the write paths call `GetRegistryCredential` again (`service.go:316`, `:395`) and then `UpdateRegistryCredential` (`:177`, called at `service.go:364`), `TouchRegistryCredential` (`:193`) and `DeleteRegistryCredential` (`:207`, called at `service.go:409`). All of them bind the raw id as `$1` with no `textBindable` guard.
  - 490's `classify` change maps SQLSTATE `22021` to `store.ErrInvalid`. But `registrycreds.mapStoreErr` (`service.go:434-442`) translates only `store.ErrNotFound` and returns every other error untouched, so the new `ErrInvalid` still reaches the handler as an unclassified error and renders as 500. (Projects and environments do not hit this because their guard returns before the query.)
- **Fix (target behavior):**
  - Put the same `textBindable` early-return in `GetRegistryCredential` (`:108`), and in `UpdateRegistryCredential`, `TouchRegistryCredential` and `DeleteRegistryCredential`, so a malformed id resolves to `ErrNotFound` exactly like `GetRegistryCredentialByID` now does. Result: `GET`, `PATCH` and `DELETE` of `/v1/registrycredentials/{id}` answer **404** `not found`, as a valid unknown id does.
  - Independently, make `registrycreds.mapStoreErr` translate `store.ErrInvalid` to `core.ErrBadRequest`, so the next SQLSTATE `22…` that reaches it is a 400 and not a 500. Keep both: the early return gives the right 404, the mapping covers the unguarded remainder.
- **Blast radius:** `GetRegistryCredential` has 4 non-test callers outside the store (`registrycreds/service.go:200`, `:316`, `:395` and `pullsecret.go:213`), and `Update`/`Touch`/`Delete` 1 or 2 each; REST, GraphQL (`registryCredential(id:)`) and MCP share `Service`. Regression tests must keep a real credential id reading, renaming and deleting exactly as today, and keep a foreign-workspace id answering the same 404 as an unknown one (no existence oracle: the check looks only at the string).
- **Adjacent classes:** a valid but unknown id stays 404; a credential in another workspace stays 404 (the workspace filter is unchanged); unauthenticated stays 401; a real database outage must still answer 5xx, so test with a failing store, not only with the new guard.
- **Unverified:**
  - GraphQL `registryCredential(id:)` and the MCP credential tools with these ids; reasoned from the shared `Service`, not called.
  - Whether `pullsecret.go:213` can be reached with a caller-supplied id (it takes a `credentialID` from a service's binding, so probably not).
  - A NUL in the path never reaches the API from a browser (`fetch` fails first), so only invalid UTF-8 is covered.
- **Render:** Render answers a malformed id with a JSON 404, never a 5xx.
- **Dedupe:** w4/490 (done) is the parent and states the registry-credential rows; w4/482 (done) is the earlier path-id family; nothing open covers this. `grep -rn textBindable lego/backend/internal` lists the three guarded readers and no registry-credential writer. Nothing in `.pm/DO_NOT_DO.md` applies. The fix is not on `main`.
- **Cleanup:** read-only plus two writes on a non-existent id (nothing created or changed). This run's Kratos session is revoked after the hunt.

Closed 2026-11-05: `GetRegistryCredential`, `UpdateRegistryCredential`, `TouchRegistryCredential` and `DeleteRegistryCredential` return not-found for a non-text-bindable id before any query (the same early return as `GetRegistryCredentialByID`), so GET/PATCH/DELETE of `/v1/registrycredentials/{id}` answer 404; `registrycreds.mapStoreErr` also maps `store.ErrInvalid` to `core.ErrBadRequest`, so a data exception that is not guarded is a 400 rather than a 500. Tests: `store.TestRegistryCredentialRoutesTreatMalformedIDsAsAbsent` (a nil pool proves no query runs), `registrycreds.TestMapStoreErrClassifiesMalformedAndMissing` (an outage still passes through).
