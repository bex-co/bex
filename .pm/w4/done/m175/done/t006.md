## Objective

Restore m175's existing exact-window guarantee without undoing the end-containing bucket. Round evaluation bounds as before, but exclude entries outside the normalized caller start/end before count_over_time and host/path latency aggregation. Include exact endpoints once.

## Context

Eight contained-preset controls and aligned zero/four controls pass. A synthetic pinned Loki 3.6.7 execution validates seconds/nanoseconds timestamp filtering and label removal.

## Steps

1. Extend the existing lokiRequestPipeline or a private helper it calls using RequestMetricsRequest.Start/End. Generate trusted seconds/nanosecond bounds as integers; format the entry's built-in timestamp into temporary seconds and nanosecond labels, apply the inclusive tuple comparison, and drop both labels before aggregation. Preserve exact filters, units, grouping and quantile behavior.
2. Preserve rounded evaluation bounds and the newest partial bucket. Do not filter whole sample points by their timestamp: that would discard valid partial-bucket data. Do not compare a full epoch-nanosecond value as float64, and do not use client clocks or parsed application timestamps.
3. Audit the two Loki pipeline branches and both service selection branches, preserving unfiltered Prometheus latency, bandwidth, approximation fallback and existing upstream errors. Check realistic execution cost and ensure temporary labels do not become result-series dimensions.
4. Keep this a Bex query correction; no Loki configuration, deployment, API-shape or dashboard-count workaround.
