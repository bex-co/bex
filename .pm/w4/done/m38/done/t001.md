## Objective

Add a durable, self-expiring control-plane store that maps a refresh-token **hash** to the token pair a prior refresh minted, so a repeated/concurrent refresh of the same token can return the same result instead of re-minting. The raw refresh token is never persisted.

## Context

- Control-plane Postgres migrations live in `lego/backend/internal/store/migrations/` (`NNNN_name.up.sql`/`.down.sql`); this work uses `0082` because upstream claimed `0081` before ship.
- The CLI-auth proxy is `lego/backend/internal/cliauth/service.go` (`refreshToken` at :211, `proxyForm` path). It currently forwards straight to Hydra with no dedupe.
- Look at the existing single-use nonce/claim mechanism already in the control-plane DB (agent-session attach nonces, shell-ticket nonces, git-webhook replay ledger) for the row-shape + sweep pattern to mirror — reuse it rather than inventing a new idiom if it fits.

## Steps

1. Add migration `0082_cli_refresh_idempotency` (up + down): a table keyed on `token_hash` (SHA-256 of the refresh token) with the cached response (access + refresh token, expiry) and a `created_at`; index/TTL support for a bounded sweep of expired rows.
2. Add the store methods (get-by-hash / put) alongside the other cliauth/control-plane store code, plus the periodic purge of expired rows (mirror the existing nonce sweep).
3. Never store the raw refresh token — only its hash.

## Files

- `lego/backend/internal/store/migrations/0082_cli_refresh_idempotency.up.sql` / `.down.sql`

## Acceptance criteria

- [ ] Migration applies and rolls back cleanly against a real Postgres.
- [ ] Store round-trips a cached pair by token hash and returns absent after expiry.
- [ ] No column holds the raw refresh token.
