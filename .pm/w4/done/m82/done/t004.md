## Resolution (2026-08-16)

`029.md`'s #10 bonus finding: `lego/operator/config/ssh/ingressroutetcp.yaml` set no `proxyProtocol`, and `nativessh/server.go` recorded `conn.RemoteAddr()` — Traefik's own pod IP, since Traefik terminates the TCP connection and opens a fresh one to the backend — into `ssh_sessions.remote_address`, breaking ADR035's audit-attribution trail. (The HTTP half of #10 was already fixed via `BEX_TRUSTED_PROXY_CIDRS`, confirmed unchanged this session.)

`lego/backend` can never import `lego/operator` (the repo's one-way `operator → types ← backend` dependency arrow), so the existing PROXY v1/v2 parser in `lego/operator/internal/sniproxy` (built for pg-sni-proxy/kv-sni-proxy) isn't reachable from the gateway. Ported it byte-for-byte into a new leaf package, `lego/backend/internal/proxyproto` (zero bex dependencies either side, so duplicating ~150 lines is cheaper and safer than a shared third module), and added a `Conn`/`Wrap` net.Conn adapter on top: `Wrap` peeks an optional PROXY header (only honored from a peer in a new `TrustedProxies` allowlist), and returns a `net.Conn` whose `Read` continues from the same buffered reader and whose `RemoteAddr` reports the resolved original client.

`nativessh.Server` gained a `TrustedProxies []netip.Prefix` field; `serveConn` wraps the raw connection with `proxyproto.Wrap` before handing it to `ssh.NewServerConn` (whose `ConnMetadata.RemoteAddr()` — and therefore the later `RemoteAddress: conn.RemoteAddr().String()` audit write — transparently picks up the wrapped value). Wired from `cmd/ssh-gateway/main.go` via a new `BEX_SSH_PROXY_PROTOCOL_TRUSTED_CIDRS` env var (documented in root `CLAUDE.md`'s env table and `.env.example`); unset (the default) skips all buffering/peeking and is byte-identical to before. `lego/operator/config/ssh/ingressroutetcp.yaml`'s service now sets `proxyProtocol: {version: 2}` so Traefik forwards the header on that hop.

Tests: `proxyproto`'s own suite (ported from `sniproxy`'s — parser edge cases, untrusted/malformed rejection — plus new `Wrap`/`Conn` coverage using real `net.Pipe` connections); two new `nativessh` gateway-level tests, `TestServeConnHonorsPROXYHeaderFromTrustedPeer` (a real PROXY v1 header from a trusted loopback peer ends up as the audited `RemoteAddress`) and `TestServeConnKeepsImmediatePeerWithoutTrustedProxies` (unconfigured default unchanged). Full `go build ./... && go vet ./...` and `go test ./internal/sshgateway/... -race` green.

## Objective

Close `029.md`'s SSH-audit sub-finding under #10: the gateway must record the real client address, not Traefik's pod IP, when Traefik is configured to forward it.

## Acceptance criteria

- [x] A PROXY v1/v2 header from a trusted peer makes `ssh_sessions.remote_address` record the original client.
- [x] An untrusted peer's PROXY header is rejected (connection refused), never silently trusted.
- [x] Unconfigured (no trusted CIDRs) is byte-identical to pre-existing behavior — no Peek, no buffering.
- [x] Traefik's `ssh` entrypoint IngressRouteTCP is configured to forward the header.
