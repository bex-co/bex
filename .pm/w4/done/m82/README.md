## What actually happened, item by item

### `029.md` — codex-security round-4 P2/P3 register

- **#16 Static server `ReadTimeout` — FIXED.** `lego/operator/cmd/staticserver/main.go` had `ReadHeaderTimeout`/`WriteTimeout`/`IdleTimeout` from an earlier pass but no `ReadTimeout`, so a declared-but-withheld request body could still pin a goroutine on Go's unread-body drain. Added `readTimeout = 30s`; `TestServerTimeoutsConfigured` now also asserts it.
- **#15 Mobile push unregister ordering — FIXED.** `mobile/src/features/notifications/registration-controller.ts`'s `unregisterCurrent` disabled the local preference (and reported `"disabled"`) **before** the remote unregister call — a failed remote call still left the app believing push was off while the server-side device row stayed bound to the old subject, and `inspectAndRepair` never re-registers a device whose local preference says disabled. Reordered: the remote `unregister` call now runs first; the local preference and state only flip on success. The existing test that encoded the old (buggy) order as intended behavior was rewritten to assert the fix, plus a new test for the success path. `yarn test:unit`/`typecheck`/`lint` all green.
- **#12 Registry-credential delete ≠ revoke — FIXED.** `registrycreds.Service.Delete` removed the Postgres row + OpenBao secret but never touched the derived `<app>-registry-pull` Kubernetes Secret(s) for any App still using that credential — those Secrets carry no ownerRef and are only reaped on the App's own delete, so a deleted credential's password lived on indefinitely. `Delete` now looks up every App in the credential's workspace/namespace and refuses (`core.NewConflictError("REGISTRY_CREDENTIAL_IN_USE", …)`, 409) if any App still resolves to it — either explicitly (`spec.registryCredentialId`) or implicitly (an image whose registry host matches with no explicit override), mirroring exactly the two paths `materializePullSecret` itself resolves through. New tests: explicit-binding refusal, host-match refusal, and a "explicit binding elsewhere doesn't false-positive via host match" case.
- **#10 (SSH audit sub-issue) — FIXED.** `lego/operator/config/ssh/ingressroutetcp.yaml` set no `proxyProtocol`, and the gateway recorded `conn.RemoteAddr()` — Traefik's own pod IP — into `ssh_sessions.remote_address`, breaking ADR035's attribution trail. Added a new self-contained `lego/backend/internal/proxyproto` package (backend can't import the operator's existing `internal/sniproxy` parser — modules never cross that boundary — so the ~150-line PROXY v1/v2 parser is a deliberate duplicate, ported byte-for-byte plus a new `Conn`/`Wrap` net.Conn adapter), a new `nativessh.Server.TrustedProxies` field, and `BEX_SSH_PROXY_PROTOCOL_TRUSTED_CIDRS` (documented in root `CLAUDE.md` + `.env.example`). The IngressRouteTCP's service now sets `proxyProtocol.version: 2`. Unconfigured (the default) is byte-identical to before — no CIDRs, no Peek, no behavior change. New unit tests in `proxyproto` (ported from `sniproxy`'s suite plus new `Wrap`/`Conn` coverage) and two new gateway-level tests (`TestServeConnHonorsPROXYHeaderFromTrustedPeer`, `TestServeConnKeepsImmediatePeerWithoutTrustedProxies`) proving the audited address end to end.
- **#10 (HTTP half), #13, #6 — confirmed already fixed, no new work.** Re-verified against HEAD via a dedicated code-audit pass: `api.RateLimiter`/`cliauth.DeviceRateLimiter` already derive the caller IP through `BEX_TRUSTED_PROXY_CIDRS` (`lego/backend/internal/api/ratelimit.go:95`, `cliauth/ratelimit.go:74`); `UpdateBlueprint`/`runSync` already call `approvedBlueprintPath` (`apps/blueprint.go:706,575`, landed by ADR057's round-6 finding 14); `databases`/`keyvalues` already carry the same `canonicalNamespace` reconciler guard as `App` and the same admission-policy resource list (`database_controller.go:249,539`, `keyvalue_controller.go:656`, `deploy/gitops/base/bex-api-app-admission.yaml:28`).
- **#11 deploy-hook token in the URL path — unchanged, accepted risk.** `docs/ADR060-security-review-round7.md` already dispositions this as an explicit accepted custody-note risk, not a bug; re-confirmed the Traefik access-log config (`deploy/gitops/base/values/traefik.values.yaml:87-93`) is unchanged. No action.
