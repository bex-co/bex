## Outcome

Checked Render parity across all five surfaces:
- REST (`GET /v1/services/{id}/events`, `GET /v1/events/{eventId}`) and MCP (`list_events`, `get_service_event`): `zero_downtime_redeploy_started` emits `details: {"trigger": "node_replacement"|"node_consolidation"}` and `zero_downtime_redeploy_ended` emits `details: {}`, matching Render's pinned `retrieve-event` members (`TestRenderEventDetailsMatchTheirMember` passes with 0 missing fields).
- GraphQL (`serviceEvents`, `serviceEvent`): exposes `details.redeployTrigger` without colliding with deploy `trigger` object; dashboard Events tab, Metrics markers, and Webhook picker share the same catalog and wording across all 8 locales.
- Outbound webhooks: thin signed payloads (`webhook-id == data.id == evt-*`) hydrate identically through `GET /v1/events/{id}`.
- Explicit unverified bex choices (`node_replacement`/`node_consolidation` trigger strings; closing expired holds as `zero_downtime_redeploy_ended`) are documented in ADR018, `webhooks-api.md`, and `service-events.md`; `maintenance_started`/`_ended` stay unsupported (`DO_NOT_DO`). No drift requiring a follow-up.
