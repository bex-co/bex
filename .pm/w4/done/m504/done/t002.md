## Objective

The control-plane reconciler turns each recorded transition into a `zero_downtime_redeploy_started` fact (with its trigger) and, once ended, a `zero_downtime_redeploy_ended` fact, each written once.

## Context

- `recordAutoscalingFacts` (`lego/backend/internal/store/reconciler.go:2608`) is the pattern: source keys built from the transition id, `InsertServiceEventFact` is idempotent on the key.
- Fact types and the allowed set: `lego/backend/internal/store/event_facts.go:36-88`. `ServiceEventFact.ReasonCode` (`:163`) is a closed set (`serviceEventReasonCodes`); the two trigger values can join it, so no migration is needed.

## Steps

1. Add `EventFactZeroDowntimeRedeployStarted`/`Ended` and the two trigger reason codes.
2. Record the facts from the App status transition, dated by its start and end times, with source keys `zdr:<app>:<transition>:started|ended`.
3. Unit-test: one started per transition, one ended once it ends, nothing on a re-read, nothing for a transition with no start time.
