# 658 — The create-service form checks secret-file names but not the 1 MiB total, and relies on the server's 400

Why: the Environment editor checks the 1 MiB total before saving (w4/m363); the create form does not, so a user learns of it only after submitting.

- **Source / estimate:** follow-up from w4/m363 (2026-11-14). **Minor**. ~25m.
- **Fix:** reuse the editor's total check in the create form (en + zh).
- **DoD:** a create form whose files exceed 1 MiB marks the field before submit.
- **Closed 2026-11-14 (/loopx w4):** the create-service form now checks the Environment editor's secret-files quota before Submit: `secretFilesOverLimit` (`dashboard/src/features/services/lib/environment-draft.ts`) shares `quotaBreach` with the editor's `flagOverLimit` (500 files, 1 MiB of contents in UTF-8 bytes, names not counted). `createFormErrors` reports `secretFilesLimit` and `isSubmittable` holds Submit on it; `CreateSecretFileEditor` marks every named file's content `aria-invalid`, described by a `role="alert"` line carrying the editor's existing en/zh `services.secretFileLimit` sentence (no new copy). The blank "add" row is never counted. Tests: `create-service-input.test.ts` (exact 1 MiB passes, one byte more, two-byte characters and a 501st file hold Submit) and `field-error-association.test.tsx` (the alert and its association, and none within the bound); `yarn lint` and `yarn test` pass. Live DoD replays after the next production deploy.
