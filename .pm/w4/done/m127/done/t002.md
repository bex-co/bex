## Objective

Bring the datastore verbs that change durability, eviction, topology or identity under `requireUnprotected`, and give each a `confirm` argument so the phrase can be supplied.

## Context

- Accepted live on protected datastores with no confirmation: `setKeyValuePersistenceMode("off")`, `setKeyValueMaxmemoryPolicy("allkeys_lru")`, `failoverDatabase`, `renameDatabase`.
- Two of those lose data rather than availability. `persistenceMode: "off"` means a restart discards the keyspace; `allkeys_lru` means the instance silently evicts the tenant's keys under memory pressure. Both are accepted on an instance whose *suspend* — which loses nothing — is refused.
- The guard is one line in each package and the call shape already exists twice per package:
  - `postgres/protection.go:32`, used at `service.go:684` and `lifecycle.go:55`
  - `keyvalue/protection.go:32`, used at `service.go:509` and `:541`
- Phrases are per-verb by design, so pick each verb word deliberately and keep it stable — callers type it. The existing ones read `sudo suspend key value <name>`, so the new ones should follow that spacing and casing exactly.
- `UpdatePostgres` (`postgres/service.go:1246`) is the shared patch verb behind plan, parameters, HA and disk autoscaling. t001 classifies those; if any are in the set, guard once at `UpdatePostgres` with the right verb word rather than at each adapter.

## Steps

1. Add `requireUnprotected` at each site t001 selected.
2. Add `confirm` to the matching REST, GraphQL and MCP verbs, mirroring `suspendDatabase(id, confirm)` exactly.
3. Thread the phrase onto the context at the adapter boundary, as the suspend path does.
4. Check `dryRun` cannot bypass the guard — several of these verbs take one, and a dry run of a refused operation should refuse too rather than reporting what it would have done.
5. Leave the unprotected path byte-identical.

## Files
