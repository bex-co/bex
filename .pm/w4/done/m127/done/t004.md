## Objective

Confirm the new refusals and their `confirm` arguments are identical on every surface, and keep the parity ledger accurate.

## Context

- bex-api is Render-compatible across REST, GraphQL and MCP ([ADR006](../../../docs/ADR006-bex-api.md)); the dashboard is the fourth surface.
- The mechanism itself is a **documented bex divergence**, not Render parity: ADR032 records that _"Render uses role enforcement for protected Environments, whereas bex's current backend uses an explicit typed retry for an authorized caller."_ So the work here is internal consistency plus keeping that entry accurate as the verb set grows.
- The shapes to match are already in these packages: `suspendDatabase(id, confirm)` and `deleteKeyValue(id, confirm)`, and the phrases observed live — `sudo suspend database <name>`, `sudo suspend key value <name>`, `sudo delete database <name>`, `sudo delete key value <name>`.
- `w4/m126` is doing the same exercise for service verbs; compare the two so one family does not end up with a different argument name or error class than the other.

## Steps

1. Diff the refusal payload for each newly guarded datastore verb across REST, GraphQL and MCP: error class, message, phrase. Assert them together.
2. Diff the `confirm` argument name and position against the existing guarded datastore verbs.
3. Check the MCP tool schemas expose it so an agent can discover it.
4. Cross-check against `w4/m126`'s service-side result for consistency.
5. Update ADR032 and the ADR018 Environments row with the final set.

## Files

- `lego/backend/internal/postgres/`, `lego/backend/internal/keyvalue/` (REST, GraphQL, MCP)
- `docs/ADR032-environments.md`, `docs/ADR018-render-parity.md`

## Acceptance criteria

- [x] Refusals are byte-comparable across the three APIs for every newly guarded verb.
- [x] `confirm` is named and typed identically to the existing datastore guards and to `w4/m126`'s service guards.
- [x] MCP tool schemas expose it.
- [x] Both ADRs name the final set.

## Out of scope

- Adopting Render's role-based protection model — that is the documented divergence, not a defect.
