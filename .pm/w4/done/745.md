# A Postgres database bills its provisioned storage, and a Key Value instance carries no storage charge, as on Render

Why: Render parity. Render's FAQ lists "Storage capacity for Render Postgres databases and persistent disks" as billed, and has no Key Value storage line. bex bills the average used bytes of both Postgres and Key Value volumes, so a Postgres invoice is lower than Render's and a Key Value invoice has a line Render's never has. ADR018 records this only as unsigned "Documented drift".

- **Render (read 2026-11-27):** [faq](https://render.com/docs/faq), "What does Render bill for?": storage capacity for Postgres databases and persistent disks. A Key Value instance's price is its plan.
- **bex:** `queryStorageGBSeconds` (`lego/backend/internal/usage/service.go`) prices `kubelet_volume_stats_used_bytes` for Postgres and Key Value alike (`storage` in `lego/backend/internal/pricing/pricing.go`, "$/GB-second of USED datastore volume"). [ADR030](../../docs/ADR030-pricing.md) and [ADR023](../../docs/ADR023-usage-metering.md) note that Render bills provisioned Postgres capacity, and ADR018 § bex ahead of Render: Usage metering calls it "Documented drift", with no sign-off and no owner.
- **Do:** bill a Postgres database's provisioned size (the PVC request, which disk autoscaling grows) instead of used bytes, and stop emitting a storage charge for Key Value. Keep the used-bytes reading on the Billing page and usage API. Amend ADR023, ADR030 and the ADR018 row. If the user prefers used bytes, record the divergence with their sign-off in ADR018 § Billing & invoicing instead.
- **End state:** a 10 GB Postgres with 2 GB used is billed for 10 GB a month, a Key Value instance's invoice has no storage line, and the ledgers say so.
- **Size:** about 1h; promote it if the meter migration needs more.
- **Source:** w4/m688 t002, a full read of Render's FAQ, 2026-11-27.
