# 627 — Import from .env keeps a backtick-quoted value's backticks: `QA_BT=`it's "both"`` is saved as `` `it's "both"` ``

Why: dotenv (≥ 15) treats backticks as a third quote, used when a value holds both `'` and `"`. A Node project's working `.env` therefore imports into bex with different values, silently: the backticks become part of the value the process reads, and nothing marks the row.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, run sf13, 2026-11-13 06:05–06:08 UTC (`muse.env`, workspace `bex-canary`; pin `4c3c68e6b05b`). **Minor** (silent value change on import; the user can fix the value by hand). ~30m.
- **Fixture:** Free web service `qa-20261113-sf` (`srv-dbragho2er5s73bkielg`), image `docker.io/library/python:3.12-alpine`, Docker Command writing `env | grep ^QA_ | sort` to a file it serves. Deleted afterwards (`DELETE` 204, then `GET` 404).
- **Repro:** Environment → **Edit** → **Add variable ▾** → **Import from .env** → paste the text below → **Add variables** → **Save and deploy**.

  ```text
  # comment line
  QA_SQ='a $HOME # not a comment'
  QA_BT=`it's "both"`
  QA_SP = spaced value
  QA_A=override
  QA_EMPTY=
  QA_HASH=abc#def
  QA_CMT=val # trailing
  ```

- **Result:**
  - The draft row for `QA_BT` held `` `it's "both"` ``.
  - `GET /v1/services/srv-dbragho2er5s73bkielg/env-vars` returned `"QA_BT"` = `` "`it's \"both\"`" ``.
  - The running process printed ``QA_BT=`it's "both"` ``.
  - Every other line matched dotenv.
- **Control:** the dashboard's own dependency, `dotenv@17.4.2` (`dashboard/package.json:115`), parses the same text to `"QA_BT": "it's \"both\""`.
  - The only other difference is `QA_HASH`: dotenv gives `abc`, bex gives `abc#def`.
  - bex's reading there (a `#` starts a comment only after whitespace, as python-dotenv and Compose read it) is a deliberate choice and is not part of this note.
- **Root cause:** `dashboard/src/features/services/lib/dotenv-import.ts`.
  - `parseValue` (`:101-138`) opens a quoted value only for `"` or `'` (`:107-108`). Anything else goes to `stripInlineComment` verbatim.
  - The multi-line continuation in `parseDotenv` (`:77-90`) keys on the same first character, so a backtick value can never span lines either.
  - The doc comment (`:43-56`) describes double- and single-quote rules only. No test covers a backtick.
- **Fix (target behavior):** a value that opens with a backtick reads like a single-quoted value.
  - It is verbatim, with no escapes.
  - It may span lines until the closing backtick, keeping the line breaks.
  - After the closing backtick, only a `#` comment may follow. Anything else is the existing `trailing` error, on the closing quote's line.
  - An unclosed backtick is the existing unterminated-quote error.
  - Update the doc comment.
  - `formatEnvExport` never emits backticks, so `parseDotenv(formatEnvExport(x)) === x` (`__tests__/env-round-trip.test.ts`) still holds.
- **Blast radius:**
  - `parseDotenv` has 1 caller, `dashboard/src/features/services/components/env-import-dialog.tsx:92`.
  - `<EnvImportDialog>` has 2 callers: `services/components/service-environment-editor.tsx` (service Environment tab and environment-group page) and `env-groups/components/new-env-group-dialog.tsx`.
  - Pasted text and **Choose a file** take the same path.
  - A pasted value that starts with a backtick and has no closing backtick anywhere below used to import verbatim, and will now be refused as an unclosed quote. Name that in the test and the copy.
- **Tests:**
  - `` QA_BT=`it's "both"` `` imports as `it's "both"`.
  - A two-line backtick value keeps its line break.
  - `` `a` b `` reports `trailing`.
  - An unclosed backtick reports `quote` with the opening line.
  - The round-trip property still passes.
- **Unverified:** which `.env` dialect Render's **Add from .env** uses. [configure-environment-variables](https://render.com/docs/configure-environment-variables) says only "Your file must use valid `.env` syntax", and its examples are not in the page's HTML. The target here is dotenv, the parser the board's earlier import fixes aimed at (w4/159, "quoted values span lines like dotenv's").
- **Related:** `w4/done/159.md` and `w4/done/273.md` (multi-line quoted values); `w2/done/m95` (the export/import escape contract).

- **Closed 2026-11-14 (`/loopx w4`):** A value opening with a backtick now reads like a single-quoted one in `parseValue` (`dotenv-import.ts`): verbatim, may span lines, only a `#` comment after the closing backtick (else `trailing`), and an unclosed backtick is the `quote` error naming its opening line — which also means a pasted value starting with a backtick and never closing is now refused instead of imported verbatim. Doc comment updated; `formatEnvExport` never emits backticks, and the round-trip test still passes. Tests: four backtick cases in `dotenv-import.test.ts`.
