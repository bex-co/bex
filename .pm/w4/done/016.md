# `GET /v1/users` (Render's `whoami`) is unimplemented — 404

`w9/m2`'s Render CLI walk found bex-api has no route at all for Render's `GET /v1/users` (the current-caller-identity endpoint `render whoami` calls). Every other identity surface (session/API-key resolution, tenant membership) already exists internally — this is exposing it: name + email for the caller's Kratos identity, or an equivalent machine-caller shape for an API-key/OAuth2-client caller. Not in ADR018's ledger today (no Users/whoami row). Likely sub-hour once the identity-resolution plumbing (`core.Identity`, `internal/api/auth.go`) is reused rather than rebuilt — size it properly before starting in case the machine-caller shape needs real design.

Evidence + full repro harness: `docs/cli-compatibility-checklist.md` (root cause RC6).

Source: `w9/m2` (Render CLI compatibility), 2026-07-15.

## Resolution (2026-07-15) — done

- **Route** shipped in `dfff3034`: `workspaces.CurrentUser` (`lego/backend/internal/workspaces/service.go`) behind `GET /v1/users` (`rest.go`) — a session caller's email comes off `core.Identity.Email`; a machine (API-key) caller falls back to `ownerEmail`, the same earliest-admin-via-Kratos lookup `GET /v1/owners` uses.
- **The "empty email for a machine caller" follow-up was not a resolution bug** — the dev harnesses simply never set `BEX_KRATOS_ADMIN_URL`, so `ownerEmail`'s documented `Identities == nil ⇒ ""` honest subset kicked in (the same reason `GET /v1/owners`' email was empty in the same harness). Wired the missing config into both harnesses (`.pm/w9/dev-9/` + `.pm/w4/dev-4/` `up.sh`: a `kratos-admin` port-forward at `KRATOS_ADMIN_PORT = 57000 + N*10` + `BEX_KRATOS_ADMIN_URL` in bex-api's env) and verified live: `render whoami` now prints the key-minting user's real email, and `render workspaces` populates the same field via the shared lookup. `Name:` stays empty by design (Kratos' default schema carries only email).
- Checklist row flipped ◐ → ✅; `verify.sh` (t006) now asserts the populated email so a regression fails loudly. Evidence: `.pm/w9/done/m2/evidence/log.md` §whoami populated-email case.
