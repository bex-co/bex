# Static sites return 404 for uppercase or mixed-case URL hostnames

Why: a published static site's valid HTTPS URL fails in native HTTP clients when the hostname's letter case changes.

**Severity:** minor. **Estimate:** 45m. Functional `$qa-find-bugs w4`, a585, 2026-10-15 UTC; source checked on synced main `44ac07f7f`. Filing only. Advances reliable static hosting under ADR029.

## Reproduction and controls

1. Create a Free static site from `https://github.com/bex-co/bex`, branch `main`, root directory `examples/static-site`, publish directory `.`, empty build command, Auto Deploy off. Wait for Live.
2. With ordinary certificate-verified requests, run `curl --http1.1 -i https://<owned-name>.onbex.co/`, then repeat with uppercase and mixed-case hostname spellings. Do not override Host or disable TLS verification.
3. Lowercase returns 200 and the published HTML; either other spelling returns **404** with complete body `no static site for host\n`. Repeat GET and HEAD from a fresh process. A Go HTTP client independently reproduces the same split over HTTP/2.

## Root cause and bounded fix

- `lego/operator/internal/staticserver/staticserver.go:212–215` passes `hostOnly(r.Host)` into the resolver and emits the observed 404 on a miss. `hostOnly:652–655` removes a port with `strings.Cut` but preserves letter case.
- `lego/operator/internal/staticserver/resolver.go:58–63` looks up `c.sites[host]` literally. `Refresh:94–97` stores effective hosts as literal keys. The owned platform hostname is lowercase.
- Canonicalize **only the incoming lookup hostname**, after existing port removal, at this boundary. Keep URL paths, queries, object keys, redirect captures and published content case-sensitive. Do not change the shared App host declaration contract or global domain configuration.
- `lego/backend/internal/apps/domains.go:205–206` already normalizes persisted custom domain inputs. That write-side behavior does not normalize incoming static HTTP requests. Go's inspected **client** toolchain is 1.26.5: `net/http/request.go:921,1149–1152` copies host strings without lowercasing; the independent client negotiated HTTP/2.0. The deployed server's Go patch version was not measured.

**Blast radius and aliases:** exhaustive production grep under staticserver finds **one hostOnly call and one resolver.Resolve call**, both in ServeHTTP. One production wiring in `lego/operator/cmd/staticserver/main.go:164–168` builds this cached resolver/handler. `AppSpec.EffectiveHosts` (`lego/types/v1alpha1/app_types.go:930–951`) supplies primary host, computed platform host (respecting subdomain settings), and additional hosts. These aliases share lookup before file/index serving, routes and header rules. The change is global within this static HTTP handler; it does not change web/cron/worker/private compute, PostgreSQL or Key Value handlers.

**Adjacent outcomes:** known hostname spellings resolve the same published site; an unknown hostname remains 404. Non-GET/HEAD methods retain the existing 405 and Allow header before lookup. Preserve unpublished/suspended resolver inclusion policy, origin errors, caching and content/path semantics. No authorization or API error mapping needs changing.

## Dedupe, parity and limits

Searched **9,170 board Markdown files**, reviewed **72 actual open/blocked milestone titles** and DO_NOT_DO, and checked the last 40 product commits plus targeted hostOnly/map-lookup history. Both targeted symbols trace to original static-site commit `84e221650`; no normalization fix is present on synced main. This is an omitted HTTP compatibility case, not a proven regression.

The two precise-term board matches are [w4/done/235](235.md), mobile rule-input sizing, and [w6/done/m23](../../w6/done/m23/README.md), custom-domain pairing and AddDomain write normalization. Neither covers inbound static HTTP hostname matching. Preserve m23's pairing, normalized declarations and DNS presentation. [307](../blocked/307.md) concerns resolver refresh after resume; this fixture was never suspended and the case-dependent failure persists while the lowercase URL works.

[RFC 9110 §4.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-4.2.3) specifies case-insensitive HTTP(S) scheme and host comparison while other URL components generally retain case significance. For a live Render control, the public Vue example linked by [Render's Vue deployment docs](https://render.com/docs/deploy-vue-js) returned **200** for both `https://vue.onrender.com/` and `https://VUE.ONRENDER.COM/` at **13:43:20.916Z / 13:43:21.021Z**, with matching 778-byte hashes and case-preserving curl Host metadata. Only public GETs were sent; no authenticated Render account or configuration was exercised. The durable artifact records Render hashes/metadata, not copied page content.

Unverified live: controlled custom domains, explicit ports, trailing-dot or IDNA spellings, case-distinct asset paths, unknown-host variants, conditional/range requests, CLI and authenticated Render. Do not broaden the fix to these unprobed normalization rules or change platform domain settings.
