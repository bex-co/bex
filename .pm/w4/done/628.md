# 628 — Secret-file upload says "Some files were skipped" without naming the files or the reason

Why: picking several files and getting fewer rows back, with a message listing four possible causes, leaves the user to work out which files are missing and why. A bad name, a size over 1 MiB, non-UTF-8 content and a duplicate name each need a different fix.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, run sf13, 2026-11-13 06:10 UTC (`muse.env`, workspace `bex-canary`; pin `4c3c68e6b05b`). **Minor** (copy and usability; nothing is lost silently). ~40m.
- **Fixture:** Free web service `qa-20261113-sf` (`srv-dbragho2er5s73bkielg`). Deleted afterwards (`DELETE` 204, then `GET` 404).
- **Repro:** Environment → **Edit** → **Upload files** → select three files at once:
  - `my key.pem`: 24 bytes, with a space in its name.
  - `plain.txt`: 3 bytes.
  - `big.txt`: 1,100,000 bytes.
- **Result:**
  - Only a `plain.txt` row was added.
  - The alert read: "Some files were skipped. Use unique safe names, UTF-8 text content, and files no larger than 1 MiB. For a binary file (keystore, .p12, DER certificate), upload it base64-encoded and decode it at start, e.g. base64 -d /etc/secrets/keystore.b64 > /tmp/keystore.p12."
  - Nothing said that `my key.pem` was refused for its name or `big.txt` for its size. The draft was cancelled.
- **Root cause:** the reasons are folded into one boolean.
  - `uploadFiles` in `dashboard/src/features/services/components/service-environment-editor.tsx:562-600` sets `rejected = true` for each kind of refusal:
    - an invalid name or a size over `MAX_SECRET_FILE_BYTES` (`:569-570`);
    - a NUL byte (`:585`);
    - a failed strict UTF-8 decode (`:597`).
  - `admitUploadedFiles` (`dashboard/src/features/services/lib/environment-draft.ts:521-548`) also drops names already in the draft. It stores only `uploadRejected: rejected || admitted.length < files.length` (`:546`).
  - The editor renders the one generic string `services.secretFileUploadError` (`service-environment-editor.tsx:890`).
- **Fix (target behavior):** the upload keeps one `{fileName, reason}` per skipped file. The reasons are `name`, `size`, `encoding` (including a NUL byte) and `duplicate`. The alert lists each skipped file with its own reason in `en` and `zh`, using i18next plurals:
  - For `name`: the allowed characters.
  - For `size`: the 1 MiB limit.
  - For `encoding`: the existing base64 hint.
  - For `duplicate`: that a file of that name is already in the draft.
  - A selection with no skips shows no alert, as today.
- **Blast radius:** one upload path, two pages. `EnvironmentEditor` renders the service Environment tab (`dashboard/src/routes/services.$serviceId.env.tsx`) and the environment-group page (`dashboard/src/features/env-groups/components/env-group-editors.tsx:3`, `:30`). `admitUploadedFiles` is the w4/m205 race fix: it must keep deciding duplicates against the current draft, with its tests intact.
- **Tests:**
  - A mixed selection (one valid file, one bad name, one oversized, one non-UTF-8, one duplicate) adds one row and names four files, each with its reason.
  - Two overlapping selections still report the duplicate from the second.
- **Unverified:** Render's secret-file editor (**+ Add Secret File**, a filename and a contents box) was not checked for a multi-file upload. If it has none, this is a bex extension and the note is usability, not parity.
- **Related:** `w4/done/m205` (overlapping uploads), `w8/done/029` (strict UTF-8 decode and the base64 hint), `w4/m363` (the 1 MiB per-file ceiling becomes the files total too).

- **Closed 2026-11-14 (`/loopx w4`):** Uploads now keep one `{fileName, reason}` per skipped file (`name`, `size`, `encoding` incl. a NUL byte, `duplicate` decided by `admitUploadedFiles` against the current draft, so the w4/m205 race fix holds), and the editor lists each as "<file>: <reason>" under "N files were skipped:" (i18next plural, en + zh); the base64 hint now shows only for an encoding skip. Applies to the service Environment tab and the environment-group page. Tests: a mixed five-file selection names four files with their reasons; the overlapping-selection test names the duplicate from the selection that landed second. Live DoD replays after the next production deploy.
