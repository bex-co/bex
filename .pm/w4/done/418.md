# 418 — A prebuilt-image service accepts `autoDeploy: yes` and `branch` on PATCH, though create refuses both

Why: an image service's settings can be edited into a state its own create refuses ("prebuilt image services cannot declare autoDeploy"), so it then reads `autoDeploy: yes`, `autoDeployTrigger: commit` with no repository to watch, and a `branch` PATCH answers `200` while doing nothing visible.

**Severity:** minor (misleading state and a silent no-op; nothing breaks while serving). **Estimate:** ~45m. **Source:** live `/qa-find-bugs w4` loop run 1fde, 2026-10-26 UTC (`muse.env`, `bex-canary`, pin `b4726243e74f`), REST and GraphQL through the run's session jar. Owned Free image fixture `srv-dbfuvd4d3d3c73caq5b0` (`docker.io/traefik/whoami:v1.10.3`) was deleted (`GET` → 404).

## Probes

| Request | Answer | Read back (`GET /v1/services/{id}`) |
| --- | --- | --- |
| `PATCH /v1/services/{id} {"autoDeploy":"yes"}` | `200`, `autoDeploy: "yes"` | `autoDeploy: "yes"`, `autoDeployTrigger: "commit"`, `repo: null` |
| `PATCH … {"branch":"main"}` | `200` | `branch: null`, unchanged as far as any reader can see |
| GraphQL `setAutoDeploy(id, enabled: true)` | `{"autoDeploy": true}` | — |
| Control — create with `autoDeploy: "yes"` and an image (w4/m99) | `400` "prebuilt image services cannot declare autoDeploy; remove it or deploy …" | — |

## Root cause

- `lego/backend/internal/apps/settings.go:365-380`: the `AutoDeploy` PATCH entry's `check` only assigns `probe.Spec.AutoDeploy` and returns `nil`, and `setAutoDeployFetched` (`service.go:4795-4815`) writes it. No `prebuiltImageSourceFields` guard runs on update. That policy (`blueprint_compiler.go:357-376`) is applied only at create (`service.go:3113`) and in the Blueprint compiler.
- A `branch`-only PATCH goes through `sourceFields.applyTo` (`service.go:4459-4466`), which writes `spec.branch` onto the image App, while the read view hides it (`imageBackedBranch`, `service.go:1186-1191`). Success is reported, and the value is unobservable but stored.
- That read-side comment states the rule this breaks: "never publish a value the write side rejects" (w9/068). After the PATCH, the service publishes `autoDeploy: yes`, which create refuses, so cloning it (`services create --from`) fails just as w9/068 described for `branch`.

## Fix (target behavior)

- On an image-backed service (no `repo`, and no `repo` in the same PATCH), REST `PATCH /v1/services/{id}`, GraphQL `setAutoDeploy`, MCP `update_service` and the dashboard refuse **enabling** auto-deploy and setting `branch`, `rootDir`, `buildFilter`, `buildCommand` and `dockerfilePath`. Use the create message and code from `prebuiltImageSourceFieldMessage`.
- The neutral value (`autoDeploy: "no"`) stays accepted, matching w4/m99's create rule.
- A PATCH that switches the source to a repo in the same request keeps working (source switch).
- Decide what reads report for an image service already stored with `autoDeploy: true`: report `no`, as `imageBackedBranch` does for branch, or migrate. Record the decision.
