## Objective

Stop dispatch when the shared budget has expired. A completed slot keeps its result; a dispatched mutation whose completion is uncertain keeps the existing `WRITE_OUTCOME_UNKNOWN` semantics; a later slot that was never dispatched receives stable `OPERATION_NOT_STARTED` with copy explicitly saying that operation did not start. Preserve a result slot for each input and use the existing graphql.Result/error-extension representation.

The actual graphql-go v0.8.1 executor launches work before selecting ctx.Done, so calling it with an already-expired context is not a no-write guard. Check admission immediately before entering execution. Preserve the existing single-query `QUERY_TIMEOUT` and mutation uncertainty handling; do not replay writes or imply rollback.

Model completed-prefix / interrupted-current / unstarted-suffix states with a third mutation that must never invoke its resolver. Cover late completion after timeout, canceled admission, empty/invalid documents, and telemetry/error classification without conflating ordinary refusals with timeouts. No new transaction or compensation design is requested.

The refused slot is `graphqlErrorResult(errOperationNotStarted)`: `core.CodeOperationNotStarted` (`OPERATION_NOT_STARTED`, unavailable class, telemetry outcome `unavailable`) with copy saying it did not start and earlier operations may have completed. Completed members keep results; the member running at the deadline keeps `WRITE_OUTCOME_UNKNOWN`/`QUERY_TIMEOUT`; no replay or rollback. Covered: completed prefix / interrupted current / never-entered third resolver (probe records starts, checked after the late completion), canceled admission, single-mutation timeout control.
