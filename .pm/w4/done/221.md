## Root cause and bounded fix

- `dashboard/src/routes/services.$serviceId.events.tsx:392,510–515` turns every nonempty `details.reasonCode` into `t("services.eventsReason." + reasonCode)`. The backend intentionally emits `superseded`: `lego/backend/internal/store/event_facts.go:110–132` defines ten nonempty closed codes; `internal/events/service.go:941–946` copies the supersession code beside its neutral cause. The captured response matches this mechanism.
- Both catalogs omit that key: `dashboard/src/features/services/locales/en.ts:3959–3997` and `zh.ts:3863–3898` contain the other nine reason keys. An exhaustive `services.eventsReason` search across `dashboard/src` found one dynamic renderer and nine definitions in each locale, with no superseded definition.
- `common/hooks/use-translations.ts:23–60` warns about missing keys only in development and forwards to i18next. The catalog is `Record<string,string>` (`i18n/index.ts:59`), so this dynamic string compiles. Adding the two entries is expressible without a schema or API change.
- Read the actual locked dependency: i18next **26.3.4** (`yarn.lock:7960–7962`, installed package matches). `node_modules/i18next/dist/esm/i18next.js:660–668` uses a default if supplied and otherwise assigns the missing key itself. This caller supplies only `exitCode`, no default. English fallback (`i18n/init.ts:23`) cannot resolve a key absent in English too.
- Control diagnostic with the installed i18next and the nine extracted current entries: `image_pull_backoff` renders “The runtime could not pull the configured image.” in en and “运行时无法拉取配置的镜像。” in zh; `superseded` renders its key in both. This is a local dependency/catalog control, not a claim that other event classes were live-replayed.

**Fix contract:** add `services.eventsReason.superseded` in en and zh with a neutral newer-deploy explanation. Keep status, API code and replacement-ID detail intact. Use the actual locale resources in an Events regression test for both `deploy_ended` and `build_ended`; assert the readable explanation and existing cause, and exercise one existing reason plus an empty-code user cancel. Apply no global fallback change to `useTranslations`.

**Blast radius / aliases:** one `EventSummary` definition, one JSX caller at events.tsx:265, and one dynamic reason renderer at :512. Two production route callers mount `ServiceEventsPage`: `/services/$serviceId/events` and `/static/$serviceId/events`. Web, static, cron, worker and private services share that page; static was observed live, the other four are compatibility checks. Postgres and Key Value use their separate detail/tab families and do not mount this page. The bounded fix touches two entries; the nine existing translations and other shared-wrapper callers keep their current behavior.

**Adjacent classes / pending state:** no backend authorization, not-found, timeout or error taxonomy changes. Empty reason code continues to omit the paragraph; a user cancel is not described as superseded. Loading, failed reads and unknown future codes retain current handling; this small fix does not assert a new unknown-code policy.
