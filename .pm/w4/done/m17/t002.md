## Objective

Fix the dead-end: when the JSON flow-init for a login with a `login_challenge` returns a null/empty flow (the signed-in case — Kratos satisfied the challenge without needing UI), navigate the browser to Kratos's HTML `self-service/login/browser` endpoint (no `Accept: application/json`), which 303s through to Hydra's continue URL, completing the authorization.

## Context

- `dashboard/src/common/hooks/use-ory-flow.ts`: the OAuth2 short-circuit (~line 221) only handles the *thrown* `browser_location_change_required` case; a `200 null` body falls through to the skeleton or the challenge-less redirect bootstrap (~line 295), abandoning the authorization.
- The fix belongs in the login page/hook, **not** the consent route (per `w4/010`'s analysis).
- Do not hand-roll any Hydra interaction here — Kratos's own HTML endpoint performs the challenge acceptance and redirect (DO_NOT_DO: no hand-built login/consent provider).

## Steps

1. In `use-ory-flow.ts`, detect the null/empty flow response when a `login_challenge` is present.
2. Navigate the browser (full-page navigation, not fetch) to `{kratos}/self-service/login/browser?login_challenge=…&return_to=…` in HTML mode.
3. Verify in the t001 browser setup that the signed-in authorize now completes through consent to the client redirect.
