## Objective

Lift aal2 step-up detection out of the login page (inbox `009`, the m11 `/simplify` altitude finding): `use-ory-flow.ts` currently rediscovers the step-up need by trial-and-error (mints a flow, checks whether it carries a second-factor node). Instead, surface `session_aal2_required` from `fetchSession`, propagate it through `requireAuth`, and redirect to login with an explicit `aal=aal2` param so the hook renders the step-up flow directly.

## Context

- `dashboard/src/common/server-fn/session.ts` — `fetchSession`, where Kratos's `session_aal2_required` error is visible.
- `dashboard/src/common/lib/auth/` — `requireAuth`, which decides the login redirect.
- The login route's search-param schema gains `aal`.
- The six m11 fixture-driven tests in `dashboard/src/common/hooks/__tests__/use-ory-flow.test.tsx` pin the current trial-and-error behavior and must be updated alongside.

## Steps

1. In `fetchSession`, distinguish "no session" from "session present but aal2 required" and return the latter as a typed signal.
2. In `requireAuth`, redirect to login with `aal=aal2` when the signal is set.
3. In `use-ory-flow.ts`, mint the second-factor flow directly from the explicit param; remove the probe-and-inspect path.
4. Update the six fixture tests to the new contract; keep the behavioral assertions (step-up renders for totp/webauthn/lookup_secret; navigates on when no second factor; non-login flows never step up).
