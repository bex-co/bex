# 387 — Push "Max deferral (hours)" says "between 1 second and 168 hours" while the field itself allows only 0.5-hour steps

Why: the field is in hours, and its own control declares `min="0.5" step="0.5"`. Its error says the bound is "1 second", a unit the field cannot express. The validator in fact accepts values the control's step forbids: any whole number of seconds, so for example 0.25 h. A user cannot tell what is allowed.

**Severity:** minor (copy and validation consistency). **Estimate:** ~15m. **Source:** live `/qa-find-bugs w4` loop run n4d1, 2026-10-21 UTC, `muse.env`, workspace `bex-canary`, pin `f64d4c85f2cd`. Only the QA user's own push settings were touched; they were restored to `UTC` / 8 h ("Push settings saved"), and the session was revoked.

## Probe (`/notifications` → Mobile push)

- `Max deferral (hours)` set to `-5`, `0`, `169` or `0.0001`, then **Save push settings**. Each shows the alert "Maximum deferral must be between 1 second and 168 hours." No request is sent.
- The input is `type=number min=0.5 max=168 step=0.5`.
- Controls behave correctly:
  - an invalid IANA timezone (`Mars/Phobos`) gets "Enter a valid IANA timezone such as America/Los_Angeles.";
  - `8` saves.

## Root cause

- `dashboard/src/features/notifications/components/push-notification-settings-panel.tsx:296-311` renders hours with `min="0.5" step="0.5"` and stores `Math.round(hours*3600)` seconds.
- `dashboard/src/features/notifications/lib/push-policy.ts:72-78` accepts any integer from 1 to 604800 seconds.
- `dashboard/src/features/notifications/locales/en.ts:385-388` (and zh) phrase the bound in seconds.

## Fix (target behavior)

Pick one unit and one bound, and use it in all three places:

- **Recommended:** a half-hour minimum, `0.5 h` (1800 s) to `168 h`. The message reads "Maximum deferral must be between 0.5 and 168 hours." `push-policy.ts` rejects values below 1800 s, and decimal steps off 0.5 h get either rounding or a refusal.
- **Alternative:** keep the backend's 1-second floor and change the control to `min` 0.01, `step="any"`, with a message in hours.

Whichever is chosen, check the bound bex-api enforces (`notifications/service.go:394`, "MaxDeferralSeconds is bounded by …") and make all three match it.

## Acceptance

- A unit test on `push-policy`: the bounds at 0.5 h and 168 h, rejection outside them, and the en and zh message in hours.
- Live: `0.25` is refused with the hours message, and `0.5` saves.
- Dashboard `yarn lint` and `yarn test` pass.
