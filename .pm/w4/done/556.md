# 556 — A Logs custom range that has already ended turns Live off but explains why only in a hover title, and the page still says live mode appends new lines

Why: a keyboard or screen-reader user meets a disabled "Live" switch with no explanation. Right below it, the page still promises "Live mode appends new lines as they arrive." w21/016 wrote the reason, but only into a `title` nobody can reach.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 46, 2026-11-10 21:54–22:00 UTC (`muse.env`, workspace `bex-canary`, pin `a0d5802594e9`). **Minor** (accessibility and copy). ~20m. A residual of w21/016.
- **Fixture:** Free image service `qa-20261110-rn46` (`srv-dbpp4vdhi5vc738girlg`, renamed to `qa-20261110-renamed-46`). Deleted (GET 404).
- **Probe:** `/services/srv-dbpp4vdhi5vc738girlg/logs?range=custom&rangeStart=2026-11-01T07%3A00%3A00.000Z&rangeEnd=2026-11-02T08%3A00%3A00.000Z`.
  - **w21/016's tail fix holds.** The page shows `switch "Live" [disabled]` (`aria-checked="false"`) and "No logs in this time range".
  - **The reason isn't exposed.** Chrome's accessibility tree (CDP `Accessibility.getFullAXTree`) gives the switch the name "Live" and no description.
    - The reason, "Live tail is off — this custom range has already ended, so no new lines can arrive in it.", exists only as `title` on the `<label>`.
    - `document.querySelector('main').innerText` contains no reason text.
  - **The visible note contradicts the state.** It still reads `logs.rangeHistoryNote`: "The range limits history. Live mode appends new lines as they arrive."
- **Root cause:**
  - **The reason is only a hover title.** `dashboard/src/features/logs/components/log-filter-bar.tsx:281-284` builds it as a `title`, and `:387` puts that on the `Label`. A disabled switch can't be focused, so keyboard and screen-reader users never get the title.
  - **The visible reason never renders in the empty state.** `StreamStatus` (`log-viewer.tsx:455-476`) is rendered only in the branch that has lines (`:364-369`). A closed window with no lines never shows it.
  - **The note is unconditional.** `logs.rangeHistoryNote` (`locales/en.ts:8-12`) is rendered right after `<LogFilterBar …/>` in every state.
- **Fix (target behavior):**
  - Whenever Live is unavailable (a closed window, or filters that can't be tailed), the reason appears as visible text next to the switch in every state, including the empty state.
  - The switch references that text with `aria-describedby`.
  - The history note doesn't promise "Live mode appends new lines" while Live is disabled.
  - en and zh. Test the empty closed-window state.
