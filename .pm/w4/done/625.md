# 625 — On a Postgres or Key Value Logs tab, a custom range that has already ended still lets Live be turned on, and the tail streams later lines into the window; w21/016 closed this on service Logs only

**Absorbed 2026-11-13 into [w10/m374 t004](../../w10/blocked/m374/done/t004.md)** (`/pmx them all to w10`, from `/pm-brainstorm for w10`). **Not fixed yet:** the fix and its live DoD ship with that milestone; this note keeps the original evidence.

Why: a custom range is how a user isolates an incident window. On a datastore's Logs tab, turning Live on (or leaving it on) adds every new line after the window's end to that window. A 02:02–02:03 view grew 20 lines from 02:05, with the range still applied in the URL and the trigger. Service Logs refuses this with "Live tail is off — this custom range has already ended…" (w21/016). The two log pages disagree, and the datastore one shows lines it says it excludes.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 251, 2026-11-13 02:03–02:07 UTC (`muse.env`, workspace `bex-canary`; pin `08c3c3fc3f0e`). **Minor** (Live is off by default on this tab, but a user can turn it on, and the result is a wrong window). ~30m.
- **Fixture:** Free Key Value `qa-20261113-r251-kv` (`red-dbr6t1p7ka5c7395bne0`), created from the dashboard with Public access on. Deleted afterwards (`DELETE` 204, then `GET` 404).

- **Root cause:** `DatastoreLogViewer` (`dashboard/src/features/logs/components/datastore-log-viewer.tsx`) never got w21/016's guard.
  - `useLiveLogs({ enabled: live, … startTime: win.startTime })` (`:215-225`) opens the tail whenever the switch is on, with no closed-window check and no end.
  - `mergeLogLines(history.lines, stream.lines, Date.parse(win.startTime))` (`:231`) passes only the floor, so tailed lines past the end are kept.
  - `<LiveToggle … disabled={!hydrated} />` (`:353-358`) is never disabled for a closed window and shows no reason.
  - Service Logs has all three: `windowClosed` = a custom end at or before the moment it was applied (`dashboard/src/features/logs/components/log-viewer.tsx:184-205`); `enabled: live && liveSupported && !planRefused` (`:246`); `mergeLogLines(…, customEndMs ?? Infinity)` (`:277-282`); and the `logs.liveWindowClosed` reason (`dashboard/src/features/logs/locales/en.ts:101-105`).
- **Fix (target behavior):** the datastore Logs tab follows the service Logs contract from w21/016.
  - A custom range that ended before it was applied never opens the tail. The Live switch is off and disabled with the `logs.liveWindowClosed` reason (en, zh).
  - A custom range ending in the future tails, bounded by its end (`notAfterMs`).
  - Presets are unchanged.
  - Lift the window-closed computation into a shared helper, so the two viewers cannot drift again.
- **Blast radius:**
  - `DatastoreLogViewer` has 2 entry points: `routes/databases.$databaseId.tsx` (Postgres) and `routes/keyvalue.$keyValueId.tsx` (Key Value), per w21/016's own count.
  - `mergeLogLines` already takes the optional bound. Its other callers (`use-deploy-logs.ts`, `use-log-history.ts`) stay unbounded.
- **Tests:** a `datastore-log-viewer` test with a custom range ending in the past: the Live switch is disabled with the reason and no subscription opens. With a range ending in the future: a streamed line after the end is not rendered.
