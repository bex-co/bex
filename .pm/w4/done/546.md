# 546 — The New Cron Job form prices every instance type at its always-on monthly rate ("Starter $4.90/month"), though a cron job is billed per second only while a run executes

Why: at the moment someone chooses a plan, a nightly 30-second job looks like it costs $4.90/month, about a thousand times what it actually bills. bex's own Blueprint estimate already treats cron as a variable cost, so the create form contradicts the platform's own billing.

- **Source / severity / estimate:**
  - Live `/qa-find-bugs w4` loop, round 16, 2026-11-10 11:45–12:05 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`).
  - **Minor–major.** Billing itself is correct, but the displayed price misleads the purchase decision.
  - ~45m.
- **Probe:** `/services/new` → Service Type "Cron Job" (URL `?type=cron_job`).
  - The radiogroup "Instance Type" lists `Starter $4.90/month 512 MB RAM · 0.5 CPU`, `Standard $17.50/month …`, `Pro $59.50/month …`, `Pro Plus $122.50/month` and `Pro Max $157.50/month`.
  - These are the same figures the Background Worker and Private Service forms show.
- **Root cause:** the price is the always-on monthly estimate, rendered the same way for every service type.
  - It comes from `InstanceType.monthlyUsd` (`lego/backend/internal/apps/graphql.go:651-653`), the only rate field on that GraphQL type.
  - The backend computes it with `pricing.Sheet.InstanceMonthlyUSD`, the "always-on 730-hour monthly estimate" (`lego/backend/internal/pricing/monthly.go:29-51`, `MonthSeconds` at `:27`). In `pricing.yaml:41-50`, starter is `usdPerSecond: 0.000001864535768645` with the comment `# $4.90/mo`.
  - The dashboard renders it through `common.pricePerMonth`, "${price}/month" (`dashboard/src/common/locales/en.ts:89-90`). It reaches the user through three components:
    - `PlanCardGrid` (`common/components/plan-card-grid.tsx:97-100`), used by `routes/services.new.tsx:553-558`.
    - `InstanceTypePicker` (`features/services/components/instance-type-picker.tsx:255-256`).
    - The picker's plan-change confirm (`:194-195`, `services.planPickerConfirmPrice`, "This instance type costs ${price}/month.", `features/services/locales/en.ts:1559`).
- **Internal contradiction:** other parts of bex already treat cron as billed by run time.
  - The pricing package marks cron as a variable cost: `VariableCron = "cron" // billed per-second only while runs execute` (`monthly.go:60`, applied at `:153`), "mirroring Render's blueprint estimate ('Excluding scaling and cron jobs')" (`:56-57`).
  - The usage service treats cron as having pods only while a run is in flight (`lego/backend/internal/usage/service.go:1391-1401`).
  - [ADR030](../../docs/ADR030-pricing.md) line 105 (w8/048): "bex's per-second compute billing applies as for any paid service; it adds no $1 monthly floor."
- **Render** (render.com/docs/cronjobs, fetched 2026-11-10):
  - "Billing is prorated by the second, based on active running time during a given month."
  - "There is a minimum monthly charge of $1 per cron job service."
- **Fix (target behavior):** every cron-job price surface shows each instance type's run-time rate from the same price sheet, not the always-on monthly figure.
  - **Surfaces:** the create grid, the Plan page picker and the plan-change confirm.
  - **Rate and copy:** per minute of run time (Starter: 0.000001864535768645 × 60 ≈ $0.00011/min), with "billed per second while a run executes".
  - **Other service types:** web services, workers and private services keep $/month.
  - **API:** add a rate field, e.g. `usdPerSecond`, beside `monthlyUsd` on GraphQL `InstanceType`, sourced from `pricing.Sheet`. The client shouldn't derive the rate by dividing a cent-rounded string.
  - **Copy:** en and zh.
- **Blast radius:**
  - `common.pricePerMonth` has 4 callers: `create-database-dialog.tsx:344`, `ha-panel.tsx:435`, `instance-type-picker.tsx:256` and `plan-card-grid.tsx:99`.
  - `PlanCardGrid` is also used by `database-plan-section.tsx:121`, `key-value-plan-section.tsx:89` and `routes/keyvalue.new.tsx`.
  - Postgres, Key Value and web services keep monthly pricing, so branch on service type rather than changing the shared string. Add regression tests that the non-cron callers still read "$…/month".
- **Adjacent:**
  - The Blueprint monthly estimate already excludes cron; keep it that way.
  - The $1 floor is ADR030's separate decision. It's noted here but isn't part of this item.
- **Unverified:**
  - Render's own dashboard and pricing-page wording for cron rates. render.com/pricing didn't render rates to the fetcher. I recall "$0.00016/min" for Starter ($7 / 43,800 min), but didn't confirm it this run.
  - The Plan page and plan-change confirm for an existing cron were read from source, not probed, because cron jobs are paid-only.
- **Dedupe:**
  - `grep -rlE "VariableCron|Excluding scaling and cron|billed per-second only while" .pm` finds nothing.
  - Cron price mentions appear only in w8/048 (the paid-only decision, no price display), w6/048 (the cron schedule description) and w4/m188/t006 (locale tests).
  - Not deploy lag: none of the cited files changed between `c12cd57facb1` and `origin/main`.
- **DoD (live):**
  - `/services/new?type=cron_job` lists Starter as ≈ "$0.00011/min of run time", in en and zh, and says billing is per second of run time.
  - The web-service form still reads "Starter $4.90/month".
  - The Postgres and Key Value create forms are unchanged.

- **2026-11-11 (loopx w4):** fixed: GraphQL `InstanceType.usdPerMinute` (`pricing.InstanceUSDPerMinute`, the tier rate × 60 at two significant digits through `formatDecimal`: Starter 0.00011, Standard 0.0004). The New Cron Job form prices its cards "$0.00011/min" under "A cron job is billed per second while a run executes." (the pending skeleton draws the hint too); the short form keeps the price beside the plan name inside a three-column card, so the DoD's "/min of run time" is carried by the hint. Change Instance Type on a cron job reads "$0.0004/min of run time" and its confirm quotes the per-minute price. Web, Postgres and Key Value forms keep monthly prices. ADR030 notes it.
