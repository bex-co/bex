# 415 — Manage resources keeps another tab's checked resources, then Save on the active tab closes the dialog and silently drops them

Why: the dialog visibly holds a selection made on another tab, then a successful Save closes it and discards that selection with a success toast — the user believes resources moved into the environment when they did not.

**Severity:** major (lost form input under a success message; no persisted data lost). **Estimate:** ~1h. **Source:** live `/qa-find-bugs w4` loop run c375, 2026-10-26 UTC (`muse.env`, `bex-canary`, live pin `2331a3dadbc1`; no change to `dashboard/src/features/environments` on `origin/main` since the pin, so this is not deploy lag). Fixtures (project `prj-dbfh12jl76bs73djv19g`, environment `evm-dbfh17povisc73fhqqh0`, `qa-20261026-c375-web`, `qa-20261026-c375-kv`) were deleted in-run (`GET` → `404`).

## Root cause

- `dashboard/src/features/environments/components/manage-resources-dialog.tsx:143-150` holds four drafts across tabs (w4/133), so a selection on one tab survives visiting another.
- Each tab mounts its own `ResourceChecklist`, whose Save writes only that kind: `:330` `saveServices`, `:352-354` `setDatabases`, `:376-378` `setKeyValues`, `:400-402` `setEnvGroups`.
- `resource-checklist.tsx:63-64` closes the dialog on success, which unmounts the form and the other three drafts.
- w4/133's close note chose this deliberately ("Save writing only the active tab's set and the other three discarded rather than silently written"), pinned by `__tests__/manage-resources-dialog.test.tsx:430-460`. Retaining the drafts made the dialog read as one form; per-tab Save then drops what it shows.

## Fix (target behavior)

- One dialog-level **Save** applies every kind whose draft differs from persisted membership, each through its existing full-replacement setter, in this order: services first (so its w4/m238 stranded-group confirmation runs before any write; Cancel there writes nothing), then databases, key values, env groups.
- Stop at the first failure and keep the dialog open with the remaining drafts; close only when every changed kind succeeded.
- One summary toast naming each kind that changed. A kind with no diff is not written.
- A tab with a pending diff carries a visible and accessible "unsaved changes" marker.
- Cancel/dismiss still discards all drafts; reopen reseeds from persisted membership.
- An unread family (w4/m227) is never written.

**Blast radius:** the four `ResourceChecklist` callers in this one dialog (single mount in `environment-card.tsx`). Backend and REST/GraphQL/MCP membership verbs are unchanged.

**Adjacent classes:** forbidden, not-found and timeout keep each hook's existing error message and `false` result, which now also halts the remaining kinds and keeps the dialog open.

**Tests:** replace `:430`'s "only the active tab" assertion with a multi-kind save; add failure-midway keeps the dialog and remaining drafts, no-diff kinds are not written, and stranded-prompt Cancel writes nothing.

**Unverified:** Render's exact dialog UX (Render documents Move, not this four-tab dialog); the Databases and Env Groups tabs were not live-probed (same code path).

**Dedupe:** only w4/133 (done; it created the current behavior). No open item; no `DO_NOT_DO.md` conflict.
