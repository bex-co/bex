# No-op environment saves falsely say a deployment started
Why: customers should be able to trust whether saving configuration started a release or left the current release running.

- **Source / severity / estimate:** user-requested continuous live `qa-find-bugs`, w4, 2026-10-08 cycle 9, credentials supplied privately through muse.env; **minor**, 50m. ADR008 pillar 1, ADR006 coherent Environment save, ADR004 release history, ADR018 parity. Filing only.
- **Repro:** create an owned Free prebuilt web service, add `QA_C9_EMPTY=""` and `QA_C9_VALUE="delta-b6d2\n\"quoted\"\n雪\n"`, and wait for Live. Environment → Export → Download .env. Edit → Add variable menu → Import from .env → choose the downloaded file → Add variables → Save and deploy. The import marks the opaque rows changed, so the save is enabled. Repeat after a fresh load at 390×844; desktop is 1440×1000. The synthetic fixture was `srv-db3kfd43a6ns73b87pd0`, `qa-20261008-c9-env-b6d2`; recreate it because this sweep deleted it.
- **Expected / actual:** HTTP 200 returns `rolledOut: false` on both submissions. The correct backend no-op leaves seven deploy IDs/statuses unchanged, `revision: "rev-7"` and `undeployedChanges: false`. Both toast **Environment saved and deployment started**. Show the existing nondeployment success message when no rollout occurred; keep deployment-started copy for a true response. Do not force a needless release to make the toast true.
- **Passing control:** change only `QA_C9_VALUE` to `epsilon-b6d2` through the same Save and deploy action. The response reports `rolledOut: true`, exactly one new `config_change` deploy (`dep-db3knpkhm7os73dpdbu0`) reaches Live at rev-8, and public HTTP 200 serves epsilon with the unchanged secret file. This independently checks the same UI path, not a different API workaround.
- **Root cause / consumer:** `dashboard/src/features/services/components/service-environment-editor.tsx:145` destructures only `refreshFailed` from `save`; `:153` manufactures `affectedServiceIds: [serviceId]` whenever the requested choice is deploy. The shared consumer `:613–620` selects the deployment toast from that nonempty array. `features/services/hooks/use-environment-draft-save.ts:27–43` already returns the actual mutation result including `rolledOut`. The adapter drops correct data; polling, localization and the toast library are not responsible.
- **Expressible fix:** in that service adapter, retain `rolledOut` and report an affected service only for `choice === "deploy" && rolledOut === true`. An ordinary false result uses `services.environmentSaveOnlySuccess`, already translated in en.ts:4489 / zh.ts:4384: “Environment saved without a deploy. Use a standard deploy to apply any pending changes.” It does not assert pending changes exist. Leave the server-owned pending indicator intact. GraphQL declares `rolledOut` required (`lego/backend/internal/secrets/graphql.go:114–119`); generated `dashboard/src/graphql/schema-types.ts:810–815` and the hook can express both values without a schema/codegen change. The mutation selects the field (`api/env-vars.graphql:54–72`).
- **Backend control:** `lego/backend/internal/secrets/batch.go:262–264` returns false when both stored maps are unchanged; changed deploy-mode saves set true at `:325`. Preserve that behavior and all REST/GraphQL/MCP aliases. Save, rebuild, and deploy is different: its preliminary save-only result is false, then the explicit trigger must still run once (`service-environment-editor.tsx:157–160`). Do not gate rebuild on the preliminary result.
- **Framework check:** actual installed Apollo **4.1.3** `@apollo/client/react/hooks/useMutation.js:86–112` returns the mutation response with its data. Actual Sonner **2.0.7** `dist/index.mjs:212–216` passes the supplied success message into create, which stores it as the title (`:142–174`). Neither infers deployment state or changes the boolean. The observed request also names Apollo 4.1.3.
- **Blast radius / aliases:** exhaustive production JSX search finds **two EnvironmentEditor mounts**: the service adapter (`service-environment-editor.tsx:124`) and group adapter (`features/env-groups/components/env-group-editors.tsx:30`). Allowlist the service adapter; do not change the shared success predicate globally. The service adapter has **one production mount**, `routes/services.$serviceId.env.tsx:57`; the static route shares that ServiceEnvPage (`routes/static.$serviceId.env.tsx:2,13`). Enumerate web, static, private, worker and cron, plus legacy `/web`, `/pserv`, `/worker`, `/cron` and `/static` aliases (`common/lib/render-alias.ts:13–18`; static has its concrete env route). Postgres and Key Value use their own pages and do not mount this editor. The group save hook (`features/env-groups/hooks/use-env-groups.ts:425–456`) forwards server-supplied affected/failed IDs rather than manufacturing them from choice; that is a code-traced sibling control, not a live group no-op claim.
- **Adjacent outcomes / pre-settle:** while saving keep the existing busy state; do not announce a deployment before the result. A refused/unauthenticated/forbidden/unavailable/timeout mutation must retain existing error/draft behavior, never enter success. A committed save with failed refetch must retain its warning without replaying the patch; explicit trigger failure retains deploy-only retry. Group revision conflicts and partial rollout failures keep their existing handling. A false result must not clear or manufacture pending changes.
- **Dedupe / history:** searched open/done/blocked notes and scanned open milestone READMEs across workstreams. Open `w4/m180` owns source rebuilds on genuinely changed Save and deploy, including a true result; its tasks do not own this false-result toast. `w4/done/m145` owns saved-versus-running pending state, `w4/blocked/m130` post-write CAS reporting, and `w4/blocked/m161` group draft revisions. Original `w5/done/m44/done/t006.md` requested truthful feedback and no-op drafts that cannot submit, but implementation commit `87a058334` already ignored the returned result and chose the toast solely from choice; `4f3619d1f^` still did so before extraction into the shared editor. File this as an unaddressed same-value-import case, not a previously fixed regression. Original structural draft no-op detection cannot compare masked stored values without a sensitive read; this fix must not add bulk reveals to disable imports. Recent 40 commits and targeted history show no landed fix. DO_NOT_DO excludes no part of this bounded reporting correction.
- **Unverified:** static/private/worker/cron and alias live replays; group no-op and partial failures; Chinese toast; injected mutation/refetch/trigger failures; rebuild on a repo-backed service. These are compatibility work below, not observed additional failures. This cycle passed Save only → reload → Restart (old runtime), standard deploy (saved runtime), mixed Save and deploy, masked variable/file rename round trip, paste/file imports, empty/quoted/Unicode/trailing-newline export round trip. Current-page console capture before cleanup contains zero errors; logout's expected whoami 401 is cleanup, not a finding.
- **Render:** [official environment-variable documentation](https://render.com/docs/configure-environment-variables) distinguishes the three save choices. Its exact authenticated same-value-import toast was not probed. The bex batch/rolledOut field is the governing internal contract; this is misleading bex feedback, not a claim about an observed Render no-op divergence.

## Work and live acceptance (50m)

1. **Adapter fix (10m):** consume the actual rolledOut result for ordinary deploy saves; false uses existing nondeployment copy, true keeps deployment-started copy. Leave save modes, mutation count, secret masking, backend no-op, pending state and rebuild composition unchanged.
2. **Dedicated blast-radius verification (15m):** enumerate the two shared editor mounts and service route/type/alias family above. Exercise the real service adapter with false/true results and Save only; preserve rebuild's one explicit trigger when its preliminary save returns false, deploy-only retry, refused-save draft retention and committed/refetch-failure warning. Guard group affected/failed-ID behavior without changing that adapter. Test real behavior rather than a copied conditional; sibling live replays remain explicitly unverified until run.
3. **Live replay (15m):** repeat the owned Free web export/file-reimport journey after a hard load on desktop and 390px mobile. False responses must show nondeployment copy, unchanged deploy history/revision and no pending flag on the unchanged fixture. Repeat the epsilon-style actual value change: true, one new Live release and public response containing that value. Verify Save only still saves without a release and leaves previous runtime serving. Remove the fixture and revoke only the test session.
4. **Review / closeout (10m):** run relevant dashboard checks and simplify the small adapter change; confirm API contract and locale reuse. Record the durable replay, refresh ADR018 only if the documented behavior changes, and close the inbox note through pm only after acceptance is observed.
