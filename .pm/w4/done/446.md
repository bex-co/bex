# Service Metrics loading frames sit 24 px per chart above where the charts land

Why: the repo's skeleton rule requires the loading preview to keep the ready layout. On a service's Metrics page every loading chart frame has the right 600:180 size, but each section is 24 px shorter than ready, so the page grows and every chart shifts down when the metrics arrive.

- **Source / severity / estimate:** w4/m209 t004 census, loopx w4, 2026-10-31 (`bex-canary`, pin `d147703d7657`); **minor**, ~30m. Untouched producer `ServiceMetricsSkeleton` / `MetricsCardSkeleton` (`common/components/route-skeletons.tsx:1809`); m209 fixed only the datastore producers.
- **Evidence:** Starter `traefik/whoami` service with traffic. In-app navigation to `/services/<id>/metrics` with the `Metrics` read held:
  - **1440:** pending plot frames at y 156/464/772 (Application) and 1233/1553/1861 (Network), each 854×256.2. Ready plots at 180/512/844 and 1329/1673/2005, also 854×256.2. Sections are spaced 308 px pending and 332 px ready. "Network Metrics" sits at 1095 pending and 1167 ready.
  - **390:** pending 200/347/494 and 832/991/1138 (316×94.8); ready 268/439/610 and 980/1163/1334. Same 24 px per section, plus a 68 px higher first chart.
  - Every plot's ratio is 0.300 in both states. Tick labels start at viewBox x ≥ 4.7 when ready.
- **Likely cause:** each ready `MetricSection` has a ~24 px row the skeleton section lacks. The service event-marker strip below each plot (CHART_PAD consumer `chart-event-markers`) is the prime suspect; on mobile, a taller ready filter/header block also contributes. Confirm by measuring the ready section's children.
- **Fix:** reserve the marker-strip row (and the ready header/filter height at 390) in the service metrics skeleton, without fake markers. Add a geometry test for section spacing.
- **Dedupe:** w4/m209 (datastore metrics) is done; no open item covers the service metrics skeleton. No DO_NOT_DO item applies.

**Done (loopx w4, 2026-10-31).** Two causes:

- **24 px per section:** `ChartEventStrip` (`h-6`) sat above each service plot only when event clusters existed, and every stand-in frame (loading, error, unavailable, empty) lacked it. Service chart sections (`MetricSection eventLane`, all five on the Metrics page) now always keep the 24 px lane. The strip renders an empty lane with no clusters; `EmptyChart` and the section's stand-in frames reserve it through `EventLaneContext`. The route skeleton (`ServiceMetricsSkeleton`) reserves the lane above a plot at the chart's own ratio instead of a fixed 180 px bar.
- **Extra 44 px at 390:** the multi-select instance filter (`h-9`) appeared only after the inventory read and wrapped onto its own header row. While that read loads for a service that runs instances, an invisible box of the same size holds its place.

Tests: `metric-section.test.tsx` "MetricSection event lane" (fails without the fix), `route-skeletons.test.tsx` "previews each service chart's event lane and ratio-sized plot", and `application-metrics-card.test.tsx` "holds the instance filter's box while the inventory read loads". Live pixel re-measure is not done.
