# 612 — A webhook's Recent deliveries name each row's event link "Open source event evt-…", so a screen reader never hears the visible event type ("Deploy Ended", "Deploy Started")

**Absorbed 2026-11-14 into [w21/m395 t004](../../w21/done/m395/done/t004.md) and fixed there (2026-11-14):** see that record for the change and its tests. The live DoD below is still owed after the next dashboard roll; this note keeps the original evidence.

Why: the Event column is how an owner tells deliveries apart. Its link's `aria-label` replaces the visible label, so assistive tech reads only an opaque event id, and speech-input users can't say "click Deploy Ended". That fails WCAG 2.5.3 (Label in Name), the class w4/466 fixed for the Rollback control.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 225, 2026-11-12 19:24–19:30 UTC (`muse.env`, workspace `bex-canary`; pin `33e1b1e6117c`). **Minor** (accessibility; the delivery data is right). ~15m.

- **Root cause:** `dashboard/src/features/webhooks/components/webhook-deliveries-card.tsx:415-426` puts `aria-label={t("webhooks.openSourceEvent", { id: delivery.eventId })}` on the anchor whose children are `{eventLabel}` and an `aria-hidden` icon. An `aria-label` replaces the content-derived name, so the visible event type never reaches the accessible name. The copy is `"Open source event {id}"` (`dashboard/src/features/webhooks/locales/en.ts:378-381`; zh likewise).
- **Fix (target behavior):** the link's accessible name starts with its visible label: "Deploy Ended — open source event evt-…", or "Deploy Ended" plus visually hidden " (opens event evt-… in a new tab)".
  - Either drop the `aria-label` and add `<span className="sr-only">` text after `{eventLabel}`, or change the message to `"{label} — open source event {id}"`.
  - en and zh. The rows without an event URL keep plain text.
