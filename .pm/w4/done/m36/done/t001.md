## Objective

Make the null-category (top) level of the mention state machine score **entities** (repo full names, session titles) alongside the category rows, so `@be` yields `bex-co/bex` without a `repos:` prefix. Pure-lib change in `mention.ts` plus its unit tests; no component edits yet.

## Context

- Current gate: `mentionStateFromQuery` (`dashboard/src/features/agent-sessions/lib/mention.ts:55-63`) returns `{category: null, query}` unless the query literally starts with `repos:`/`sessions:`; `mentionOptions` (`mention.ts:166-183`) then builds rows from only `MENTION_CATEGORIES` at the null level, scored via `optionSearchTexts` (`mention.ts:124-133`) against `["repos","Repositories"]`/`["sessions","Sessions"]`.
- The fuzzy scorer `matchQuality` (prefix/substring/subsequence) already ranks the second level — reuse it; do not invent a second scorer.
- Devin/Cursor model to implement: bare `@` → category rows plus a handful of top entities; `@<text>` → all entities + category labels scored and merged, grouped by type (Linear-style sections — Devin's exact grouping is undocumented, grouped sections is the deliberate choice with two types).
- Keep the explicit `repos:`/`sessions:` narrowing behavior byte-identical (it becomes a shortcut, not a gate).

## Steps

1. Extend `mentionOptions` so `state.category === null` builds candidate rows from categories **and** `source.repos` **and** `source.sessions`, each scored with `matchQuality` against the same search texts the second level uses (repo `fullName`, session title/id).
2. Define the ordering contract: for an empty query, category rows first then a small capped set of entities (e.g. top N repos + most recent sessions); for a non-empty query, matched entities grouped by type with category rows only when they themselves match. Encode grouping in the returned row structure (e.g. a `group` field or section markers) so t002 can render headers without re-deriving.
3. Preserve the empty/loading semantics: `mentionEmptyText` (`mention.ts:186-197`) currently only reports loading at the `repos` second level — extend it so a still-loading repo list at the top level is distinguishable from "No matches".
4. Update `dashboard/src/features/agent-sessions/lib/__tests__/mention.test.ts`: bare-`@` shape, `@be` → repo row present, category-prefix behavior unchanged, ranking stability.
