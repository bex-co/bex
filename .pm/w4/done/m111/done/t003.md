## Objective

Confirm the scoped-create change stays consistent across every surface it exposes (dashboard + GraphQL variables + REST/MCP shared request shape) and against Render's behavior, flagging drift as follow-up work rather than silently diverging.

## Context

- Render has no environments concept: env groups are workspace-wide, so there is no Render-native "scoped group create" to mirror — the parity question is that bex's extension stays uniform, not that it matches a Render endpoint.
- Backend `CreateEnvGroupRequest` (`lego/backend/internal/envgroups/service.go:167`) is shared by REST/GraphQL/MCP; this milestone changes only the dashboard's variables. Verify no surface changed semantics: same `environmentId`+`serviceIds` validation (`prepareCreateServices`, `service.go:554`), same `ENV_GROUP_SERVICE_ENVIRONMENT_MISMATCH` shape.

## Steps

1. Grep every `CreateEnvGroup` call site (REST handler, GraphQL resolver, MCP tool) and confirm all three still route through the one request struct with identical validation — no per-surface fork introduced.
2. Confirm the dashboard's new `$environmentId` variable matches the backend arg name/type and that omitting it preserves today's workspace-scoped behavior on the wire.
3. Compare the new picker/filter UX against render.com's env-group create (single-scope product): bex's Workspace default must feel identical for workspaces that use no environments.
4. File any drift found as follow-up board work; do not expand this milestone to fix it.

## Result, 2026-09-18 — no drift

1. **One validation path, no fork.** All three surfaces build the same
   `CreateEnvGroupRequest` and call `s.CreateEnvGroup`: REST via
   `core.DecodeBody[CreateEnvGroupRequest]` (`rest.go:84`), GraphQL via the
   resolver at `graphql.go:250`, MCP via `create_env_group` at `mcp.go:145`.
   All three land in `createEnvGroupAuthorized`, which runs
   `validateEnvironment` then `prepareCreateServices(…, req.EnvironmentID)`
   (`service.go:458-484`) → `validateLinkedServiceEnvironments` →
   `ENV_GROUP_SERVICE_ENVIRONMENT_MISMATCH`. Nothing per-surface.
2. **Omitted ≡ null on the wire.** The resolver reads the arg with
   `gqlutil.Str` (`gqlutil.go:362`), which returns `""` for both an absent arg
   and an explicit `null` — so the dialog now always sending `$environmentId`
   is indistinguishable from the pre-m111 mutation that declared no such
   variable. Pinned by `TestGraphQL_ExplicitNullEnvironmentIDIsWorkspaceScope`
   (`internal/envgroups/optional_environmentid_test.go`), which creates through
   the composed schema both ways and asserts workspace scope for each.
3. **Render comparison.** Render has no environments concept, so there is no
   Render endpoint to mirror — the requirement is that a workspace which uses
   no environments sees no change. It does: the picker defaults to Workspace,
   the candidate list under Workspace scope is exactly the environment-less
   services (which is all of them in such a workspace), and the mutation
   carries `environmentId: null`.
4. **No drift found**, so nothing filed and `docs/ADR018-render-parity.md` is
   unchanged (this milestone altered no Render-visible behavior).
