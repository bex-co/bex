## Objective

A failed lookup is unknown placement, not proof that the customer's chosen ID disappeared. Preserve that intent and expose a read-only way to recover.

## Context

- ProjectEnvironmentSelector reads lists/loading but ignores the two hooks' error/refetch fields.
- Both source predicates and actual create request are traced in [finding](../finding.md) and [evidence](../evidence.json).

## Steps

1. Model pending, failed, successful-empty and successful-populated reads locally for each lookup. Keep selected IDs/drafts during pending/error; only an error-free completed list can invalidate a missing selection.
2. Show localized lookup status and Retry in the existing responsive field frame. Do not display No project/No environment for a nonempty selection merely because its metadata failed; use real labels when known and honest unavailable status otherwise.
3. Retry metadata reads only. Preserve explicit clears, Project-change clearing, valid selection, caller defaults and backend validation. Do not reapply URL defaults over later user edits.
4. Keep global hooks/Select and API contracts unchanged; downstream creation must retain the intended environmentId.

## Files

- dashboard/src/features/environments/components/project-environment-selector.tsx
- Relevant environments locale entries and adjacent selector tests

## Acceptance criteria

- [ ] Both recorded errors preserve the selected IDs and other drafts, expose an inline explanation and read-only Retry, and resolve the same labels after recovery.
- [ ] Successful missing lists still clear stale IDs; explicit No environment still creates outside Project. A failed lookup cannot silently cause that omission.

## Out of scope

- Product/backend contract expansion, global hook or Select rewrites, paid fixtures and changes to existing resources outside the owned QA fixtures.
