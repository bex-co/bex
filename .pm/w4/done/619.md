# 619 — With a custom time range applied, the Logs and Metrics range selector reads only "Custom…", so the page never says which window it is showing

**Absorbed 2026-11-13 into [w10/m376 t003](../../w10/m376/t003.md)** (`/pmx them all to w10`, from `/pm-brainstorm for w10`). **Not fixed yet:** the fix and its live DoD ship with that milestone; this note keeps the original evidence.

Why: a custom range is chosen to look at a specific incident window. Once applied, the toolbar shows "Custom…" and an "Edit custom range" button, and nothing on the page states the start and end. A user comparing windows, or opening a shared `?range=custom&rangeStart=…` link, has to open the dialog to learn what the lines or charts cover.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 242, 2026-11-12 23:40–23:45 UTC (`muse.env`, workspace `bex-canary`; pin `764072bb8e8a`). **Minor** (UX; the data is right). ~25m.
- **Fixture:** Starter background worker `qa-20261112-r242-log` (`srv-dbr4ro697s4s7399kfi0`, busybox printing `r242 line N` each second and `r242 MARK N` to stderr every tenth). Deleted afterwards.
- **Probe:**
  1. **Logs.** Log history range → "Custom…" → Start `2026-11-12T15:39`, End `2026-11-12T15:39:20` (browser time, UTC−8) → Apply.
     - The URL became `…/logs?range=custom&rangeStart=2026-11-12T23%3A39%3A00.000Z&rangeEnd=2026-11-12T23%3A39%3A20.000Z`.
     - The list shows exactly that window: 22 lines, `r242 line 43` to `r242 line 62`, timestamps 03:39:00 PM to 03:39:19 PM.
     - Live is off and disabled, with "Live tail is off — this custom range has already ended…".
     - The toolbar reads `combobox "Log history range": Custom…`, then `button "Edit custom range"`. No text on the page gives 3:39:00–3:39:20.
  2. **Metrics.** `…/metrics?range=custom&rangeStart=2026-11-12T23%3A39%3A00.000Z&rangeEnd=2026-11-12T23%3A45%3A00.000Z` shows `combobox "Time range": Custom…` and `button "Edit custom range"`, the same.
- **Root cause:** `RangeSelect` (`dashboard/src/features/metrics/components/range-select.tsx:98-133`) renders `<SelectValue />`, the text of the selected item. A custom range's item is `t("metrics.rangeCustom")`, "Custom…" (`:124`; `dashboard/src/features/metrics/locales/en.ts:505-507`). `isCustomRange(range)` (`dashboard/src/features/metrics/lib/range.ts:53`) is only used to show the Edit button.
- **Fix (target behavior):** while a custom range is active, the trigger shows the window itself, for example "Nov 12, 3:39:00 PM – 3:39:20 PM".
  - Pass children to `SelectValue` when `isCustomRange(range)`, formatted with the dashboard's locale-aware date formatter. This must not repeat w4/600's English-in-zh gap.
  - Keep "Custom…" as the dropdown option, and keep the Edit button.
  - Give the trigger the full window in its accessible name, or as a `title`, if it is truncated (`w-40`, the w4/614 kind of clip).
  - en and zh.
- **Blast radius:** `RangeSelect` has 3 callers: `metrics-filters.tsx:70`, `log-filter-bar.tsx:209` and `datastore-log-viewer.tsx:315` (Postgres and Key Value logs). One change covers all three.
- **Tests:** a `range-select` test: with a custom `RangeSelection`, the trigger text contains the formatted start and end; with a preset, it reads the preset label.
- **Unverified:** the datastore logs page, which uses the same component and was not opened this round; Render's own picker label for a custom window, which was not captured.
- **Render:** n/a until captured; this is a UX gap regardless.
- **Dedupe:**
  - w4/328 (done) kept the seconds; w4/279 (done) fixed the dialog's stale errors; w4/306 and w4/319 (done) fixed search and cutoffs.
  - `grep -rliE "custom range|Custom…" .pm` finds none about the trigger label.
  - Not deploy lag: `git log 764072bb8e8a..origin/main -- dashboard/src/features/metrics/components/range-select.tsx` is empty.
- **Also verified this round (all pass), Logs (journey 7):**
  - **Live tail.** New lines appear within seconds (`r242 line 59` → `68` in 8 s, no reload).
  - **Search.** `MARK` narrows to MARK lines only, writes `?text=MARK` to the URL, and keeps live-tailing new MARK lines (`MARK 70` → `MARK 100` in 22 s, with 0 plain lines).
  - **Ranges.** The presets run from Last 30 minutes to Last 30 days, plus Custom.
  - **Custom range.** It bounds the history to the second and turns Live off with an honest note.
- **DoD (live):** on any service, apply a custom Logs range of 3:39:00–3:39:20 PM. The range control reads that window in en (and in zh with Chinese date formatting), and so does the Metrics Time range for a custom window. Presets still read "Last hour" and so on.
