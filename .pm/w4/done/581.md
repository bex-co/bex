# 581 — A static site serves `.webp`, `.woff`/`.woff2`/`.ttf`/`.otf`, `.map`, `.cjs`, `.yaml`/`.yml` and `.ogg` as `binary/octet-stream`, even where the server knows the right type

Why: a static site's images, web fonts and source maps go out under a type no browser recognizes, together with `nosniff`. `.ttf`/`.otf` also lose the Brotli compression the server already has set up for them.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 131, 2026-11-11 19:22–19:35 UTC (`muse.env`, workspace `bex-canary`; release pin `f609163ada8e`). **Minor**, but it reaches every static site that publishes one of these files. ~30m.
- **Fixture:** Free static site `qa-20261111-r131-static` (`srv-dbqc18g3u30c73cf993g`, `bex-co/bex`, rootDir `examples/static-site`).
  - Build command: `mkdir -p out && for e in <ext…>; do echo x > out/t.$e; done && cp index.html out/ && head -c 4096 /dev/zero | tr '\0' a > out/big.ttf && cp out/big.ttf out/big.yaml`, with publish path `out`.
  - Deleted afterwards (DELETE 204, then GET 404).
- **Probe:** `curl -sS -o /dev/null -w '%{http_code} %{content_type}' https://qa-20261111-r131-static.onbex.co/t.<ext>`.
  - `binary/octet-stream`: `.webp`, `.woff`, `.woff2`, `.ttf`, `.otf`, `.map`, `.cjs`, `.yaml`, `.yml`, `.ogg`.
  - Correct:
    - documents and scripts: `.html` `text/html`, `.css` `text/css`, `.js`/`.mjs` `text/javascript`, `.json` `application/json`, `.wasm` `application/wasm`;
    - images: `.svg` `image/svg+xml`, `.png`, `.jpg`, `.gif`, `.avif` `image/avif`, `.ico` `image/vnd.microsoft.icon`;
    - text: `.webmanifest` `application/manifest+json`, `.xml` `text/xml`, `.txt` `text/plain; charset=utf-8`, `.md` `text/markdown`, `.csv` `text/csv`;
    - media and archives: `.pdf`, `.mp4`, `.webm`, `.mp3`, `.zip`.
  - Every response also carries `X-Content-Type-Options: nosniff` (w8/194).
  - **No compression.** With `Accept-Encoding: br`, the 4096-byte `big.ttf` and `big.yaml` both answer `binary/octet-stream` with no `content-encoding` and `content-length: 4096`. The same site's `index.html` answers `content-encoding: br` (1548 → 589 bytes). The server compresses nothing under 1 KiB (`minBrotliBytes`, `staticserver/encoding.go:46`).
  - The rest of the HTTP semantics checked out and are not part of this bug:
    - Range: `0-99` → 206 `bytes 0-99/1548`, `-10` → 206, `5000-6000` → 416 `bytes */1548`, a mismatched `If-Range` → 200;
    - `If-None-Match` (strong and weak) → 304;
    - `Accept-Encoding: br` → `br` with a weak ETag, and `br` + Range → 206 over the encoded body;
    - POST, PUT, DELETE, OPTIONS and PATCH → 405 `Allow: GET, HEAD`.
- **Root cause:**
  - **Upload: unknown extensions get no type.** The publish Job uploads with `aws s3 sync` (`lego/operator/internal/publish/publish.go:489-498`, `amazon/aws-cli:2.22.35`). The CLI guesses each object's type from its bundled Python `mimetypes` table and sends none for an extension it doesn't know. The object store then reports `binary/octet-stream`.
  - **Serve: the fallback misses that spelling.** `contentType` (`lego/operator/internal/staticserver/staticserver.go:1059-1072`) treats only an empty type and `application/octet-stream` as unknown. The store's `binary/octet-stream` therefore bypasses the extension fallback.
    - That is why `.webp` stays wrong although Go's built-in table maps it to `image/webp`.
  - **Even the fallback is incomplete.** The static-server image is `gcr.io/distroless/static` (`lego/Dockerfile:68`), which has no `/etc/mime.types`. `mime.TypeByExtension` sees only Go's built-in table, which has no `.woff`, `.woff2`, `.ttf`, `.otf`, `.map`, `.cjs`, `.yaml`, `.yml` or `.ogg`.
  - **Compression follows the served type.** `compressibleType` (`staticserver/encoding.go:108-124`) already lists `font/ttf` and `font/otf`, but those types are never served, so `.ttf`/`.otf` (and the text-like `.map`/`.yaml`) go out uncompressed.
- **Fix (target behavior):**
  - **One served type per file.** The served `Content-Type` is the IANA type for the file's extension whenever the stored type is empty, `application/octet-stream` or `binary/octet-stream`.
  - **Register the missing extensions** in the staticserver package (`mime.AddExtensionType` at init, or a local table that `contentType` consults first):
    - fonts: `.woff` `font/woff`, `.woff2` `font/woff2`, `.ttf` `font/ttf`, `.otf` `font/otf` (RFC 8081);
    - scripts and maps: `.cjs` `text/javascript`, `.map` `application/json`;
    - data: `.yaml`/`.yml` `application/yaml` (RFC 9512);
    - media: `.ogg` `audio/ogg`;
    - keep Go's built-in `.webp` `image/webp`.
  - **Leave other types alone.** A stored type that is specific (`text/markdown`, `image/vnd.microsoft.icon`, …) still wins, a saved Content-Type header rule still replaces any of them, and an unknown extension still falls back to `application/octet-stream`. `binary/octet-stream` is never served.
  - **Compression follows from the type.** Once the types are right, `compressibleType` compresses `font/ttf`, `font/otf` and `application/json` (`.map`). Add `application/yaml` there, since it's text.
  - **No republish needed.** Serving-time only: already-published sites are corrected without one, and the uploader can stay as it is.
- **Blast radius:**
  - `contentType` has 2 callers: the miss page (`staticserver.go:449`, `/404.html`) and `serveObject` (`staticserver.go:495`), which every direct file, directory index and rewrite target goes through. Both get the change.
  - Tests that seed `binary/octet-stream`:
    - `TestExistingObjectWinsOverCatchAllRewrite` (`staticserver_test.go:384-394`) asserts `render.yaml` keeps `binary/octet-stream`. Flip it to `application/yaml`; it still proves the object wins over the rewrite.
    - `revalidation_test.go:49-50` seeds the same value as fixture data.
  - Add a table test over `contentType` for every extension above, with a stored type of `""`, `application/octet-stream` and `binary/octet-stream`, plus a specific stored type that must win.

  - Which store answers `binary/octet-stream`. The value was seen through the static-server only.

- **2026-11-11 (loopx w4):** done. The static server serves the extension's IANA type whenever the stored type says nothing (empty, `application/octet-stream`, or the store's `binary/octet-stream` for an upload the AWS CLI could not type), including web types Go's table lacks: `.woff`/`.woff2`/`.ttf`/`.otf` fonts, `.map` `application/json`, `.cjs` `text/javascript; charset=utf-8`, `.yaml`/`.yml` `application/yaml`, `.ogg` `audio/ogg` (plus Go's `.webp`); `binary/octet-stream` is never served, a specific stored type and header rules still win. `application/yaml` compresses with the other text types. The ETag now hashes the served type too, so a cache holding the old type revalidates into a 200 that carries the new one. Tests `TestContentTypeForUntypedObjects`, the flipped `render.yaml` case and the ETag tests.
