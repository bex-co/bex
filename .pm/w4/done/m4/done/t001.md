## Objective

Give OpenFGA its own CNPG Postgres cluster, `openfga-db`, following the exact shape of `kratos-db`/`hydra-db` — one component, one database, independent failover/backup — inside the existing `auth-dbs` Argo Application.

## Context

- `deploy/gitops/charts/auth-dbs/` already holds `kratos-db.yaml` + `hydra-db.yaml` (CNPG `Cluster`, ns `auth`, db/owner named after the component, `SkipDryRunOnMissingResource` annotation) — copy that shape.
- The local overlay (`deploy/gitops/overlays/local/kustomization.yaml`) patches ALL Clusters in the auth-dbs Application via a single `target: {kind: Cluster}` JSON6902 patch (1Gi, `local-path`) — a new Cluster in the same dir inherits it with zero overlay changes; verify, don't assume.
- CNPG generates Secret `openfga-db-app` + Service `openfga-db-rw` — t002's DSN composition depends on those names.

## Steps

1. Add `deploy/gitops/charts/auth-dbs/openfga-db.yaml` (db `openfga`, owner `openfga`, 5Gi hcloud-volumes, mirroring hydra-db.yaml).
2. Register it in `charts/auth-dbs/kustomization.yaml`.
3. `bash scripts/gitops-validate.sh` — renders must pass; confirm the local overlay patch hits the new Cluster (`kubectl kustomize` inspection).
4. Apply to the mock cluster (local sizing + control-plane pin, as docs/auth.md's local-bring-up notes describe) and wait for `Cluster in healthy state`.

## Files

- `deploy/gitops/charts/auth-dbs/openfga-db.yaml` (new)
- `deploy/gitops/charts/auth-dbs/kustomization.yaml`
