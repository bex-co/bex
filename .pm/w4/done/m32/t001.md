## Objective

Pulling a service out of its project must not strand it with a stale `apps.environment_id` and a frozen `spec.environmentIPAllowList`. Make `SetProjectServices` clear `environment_id` for departing rows (a store-level cascade — projects stay ignorant of environments), and add a one-shot sweep for rows already drifted before this fix, so the projector's LEFT JOIN clears the layer on recreation and the environments fan-out picks the app up correctly on the next mutation.

## Context

- `lego/backend/internal/store/projects.go:107` — `SetProjectServices` replaces a project's service list but never touches `environment_id` on departing rows.
- `lego/backend/internal/store/environments.go:195` — `ListEnvironmentServices` filters on **both** `environment_id` and `project_id`, so a departed app vanishes from every future environment fan-out while its stamped `spec.environmentIPAllowList` stays frozen (possibly deny-all, with no clearing path).
- Pre-m28 this staleness was label-only (documented in docs/ADR032-environments.md); m28's enforcement made it security-bearing.
- Fix sketch from `.pm/w4/done/025.md` item 1.

## Steps

1. In `SetProjectServices`, clear `environment_id` (NULL it) for rows leaving the project, in the same transaction as the membership replace.
2. Verify the projector clears `spec.environmentIPAllowList` for an app whose `environment_id` is NULL (the LEFT JOIN path); if it only stamps on non-NULL, add the clearing branch.
3. Add a one-shot idempotent sweep (migration or startup reconcile — follow the codebase's established pattern for one-shot data repairs) that NULLs `environment_id` where the app's project membership no longer matches the environment's project.
4. Unit/integration test: service leaves project ⇒ `environment_id` cleared ⇒ projected CR loses the environment layer.

## Resolution (2026-07-16)

`SetProjectServices` (`store/projects.go`) now SELECTs the departing-with-environment names then UPDATEs `project_id`+`environment_id` to NULL for every departing row, in one transaction, returning the repaired names. `projects.Service.SetServices` fans the App CR clear out via a new narrow `EnvironmentIndex` interface (`ClearServiceEnvironmentLayer`/`ClearMembersForProject`), satisfied by `environments.ProjectMemberClearer` — a thin wrapper (mirroring `apps.WorkspacePurger`'s shape) around unexported `environments.Service` methods, since these are internal system operations invoked after the caller already authorized, not independently-authorized verbs. The one-shot sweep for already-drifted rows shipped as `store.RepairDriftedEnvironmentIDs` + `environments.Service.backfill` (t003, `api environments-backfill`) rather than inline here, since it shares machinery with t003's broader pre-m28 backfill — see t003's resolution. Real-Postgres-verified (`store_pg_test.go`) + CR-level fake-client tests (`environments/acl_test.go`, `projects/projects_test.go`).
