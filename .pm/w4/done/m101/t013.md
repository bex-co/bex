## Objective

In the service Environment editor, every variable row exposes `textbox "Key"`, `textbox "Value"` and `button "Delete"` — the same three names on every row. A screen-reader user editing a service with a dozen variables hears "Key, Value, Delete, Key, Value, Delete…" and cannot tell which variable any control belongs to, including the destructive one. The same component already solves this for its Copy button by interpolating the variable name, so this is an unfinished application of its own convention rather than a missing one.

## Context

### The observation (production, 2026-09-13 pass 18)

Fixture `qa-20260913-env` with two variables, Edit mode open, read from the **real accessibility tree** (`await page.locator('main').ariaSnapshot()`, not a DOM scan):

```text
- button "Export"
- button "Add variable"
- textbox "Key":
  - /placeholder: NAME_OF_VARIABLE
  - text: QA_SECOND
- textbox "Value":
  - /placeholder: Unchanged (masked)
- button "Delete"
- textbox "Key":
  - /placeholder: NAME_OF_VARIABLE
  - text: WHOAMI_PORT_NUMBER
- textbox "Value":
  - /placeholder: Unchanged (masked)
- button "Delete"
- button "Add secret file"
- textbox "File name":
  - /placeholder: filename.ext
  - text: qa-secret.txt
- button "View contents"
- button "Delete secret file"
```

The variable name is present as the Key textbox's **value**, which is content, not an accessible name — so it does not name the sibling Value textbox or the row's Delete button.

### The control case is in the same file

`dashboard/src/features/services/components/service-environment-editor.tsx:1037` already does it right:

```tsx
aria-label={t("services.envCopyOne", { name })}    // → "Copy WHOAMI_NAME"
```

while these are bare, generic strings:

| line | label key | rendered name |
| --- | --- | --- |
| `:1117` | `services.envColKey` | "Key" |
| `:1143` | `services.envColValue` | "Value" |
| `:1155` | `services.envDelete` | "Delete" ← destructive |
| `:1205` | `services.secretFileColName` | "File name" |
| `:1239` | `services.secretFileDelete` | "Delete secret file" ← typed, but does not name the file |

`services.envDelete`'s own locale `description` is _"Environment row button to remove a variable"_ (`features/services/locales/en.ts:673-675`) — the string already knows it is per-row.

### Why this milestone

`w4/m101` is this loop's collection of accessible-naming work on live-observed controls (t004 autoscaling switches, t010 shared IP-allowlist/database-user inputs, t011 the cmdk search input, t012 the SSH-key dialog's unwired error). Same class, same verification method, so it rides along rather than opening a fifth note. The project's position is already settled by `w4/042`, `w4/043` and `w4/044`, all of which named controls that were generically labelled.

## Steps

1. Interpolate the row's variable into the Value textbox and the Delete button — e.g. `services.envValueFor` → "Value for {name}", `services.envDeleteOne` → "Delete {name}", mirroring `envCopyOne`'s existing shape. Keep the visible column headers as they are; this is the accessible name, not the label text.
2. **Decide the empty-row case explicitly.** A freshly added row has no key yet, so there is nothing to interpolate — keep the generic "Key"/"Value"/"Delete" for a row whose key is blank, and switch to the named form once it has one. Do not render "Delete " with a dangling empty name.
3. Do the same for the secret-file row: "Delete secret file" → name the file, and consider whether `View contents` should too (it opens a dialog already titled "Contents of qa-secret.txt", so the dialog is not the gap — the trigger is).
4. The **Key** textbox is the odd one out: its own value *is* the name, so "Key" is arguably correct and interpolating its own content would be circular. Decide and record which way it goes rather than leaving it inconsistent by accident.
5. Add the interpolated strings to both `en.ts` and `zh.ts`.

## Out of scope

- The masked-value button's `aria-label={visible ? value : …}` at `:1008`, which deliberately exposes the revealed value as the name — that is a separate decision (it puts a secret into the a11y tree on purpose, for copyability) and is not being changed here.
- Journey 4's data path, which this pass verified end to end and found **correct**. Recorded here so the next hunt spends its budget elsewhere; nothing below needs fixing:
  - **A saved value reaches the running process.** Fixture was image-backed `traefik/whoami:v1.11.0` (whose response echoes `WHOAMI_NAME`), so the loop could read what the container actually received. Setting the value through the dashboard editor → toast "Environment saved and deployment started" → a `config_change` deploy → a **new pod** (hostname changed `7b988fc4d6-c5dkv` → `645f4f89cd-9ttv7`) → `curl` returned `Name: qa-updated-1` within 12s of live.
  - **Values are byte-exact, with no shell interpolation.** `WHOAMI_NAME` set to `qa $HOME "dq" 'sq' <tag> & pipe| end ` (note the trailing space) read back identical on REST, and `od -c` of the served line confirms the container received every byte including the trailing space and an un-expanded `$HOME`.
  - **Deletion propagates.** `DELETE …/env-vars/WHOAMI_NAME` → 204, a `config_change` deploy, and within 90s the served response has **no** `Name:` line at all.
  - **Reveal is per-row and survives reload.** After a reload, revealing one variable showed `qa-updated-1` while its sibling stayed `••••••••••••`.
  - **Secret-file contents round-trip byte-exact and are not leaked in list reads.** `qa-secret.txt` with `qa-marker-line-1\nqa-marker-line-2\n` came back identical from both `service.secretFile(name:)` and `GET /v1/services/{id}/secret-files/{name}`, while the list read (`service.secretFileNames`) returns `content: ""`. The editor's dialog states the mount point ("read-only at /etc/secrets after the next deploy"), which matches Render's documented location.
  - **`w4/m100/t004`'s "image-backed services stay honest" bullet is now live-verified from the other side:** this image-backed service's `config_change` row has **no** `commit` key at all (`hasOwnProperty("commit") === false`), and both its rows carry `image.ref = docker.io/traefik/whoami:v1.11.0` — the caller's own path. t004's fix must preserve exactly this.
  - **Not verifiable on the free tier:** that the secret file is actually *mounted* at `/etc/secrets` in the container. Reading it needs Shell, which needs a paid plan — so the mount claim stays unverified, as does env-var delivery to a **Git-built** service (this fixture was image-backed by design, to make the value readable).
