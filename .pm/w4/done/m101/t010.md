## Objective

The shared IP-allowlist editor's two inputs, and the Postgres "add database user" input, have no accessible name — a screen reader announces the example value ("203.0.113.0/24", "reporting") instead of what the field is. One surface in this repo already solves it correctly with translated `aria-label`s; the shared component that replaced three hand-rolled copies did not follow.

## Context

### Verified against the real accessibility tree (production, 2026-09-13)

Postgres detail page, Access control section (`#access-control`), on `qa-0913c-db` (`dpg-daj8ht0gsm7s73f63o90`, deleted at end of run):

```text
- heading "IP allowlist" [level=4]
- textbox "203.0.113.0/24"              ← name is the example CIDR
- textbox "Description (optional)"
- button "Add" [disabled]
- button "Save allowlist" [disabled]
- heading "Database users" [level=4]
- textbox "reporting"                   ← name is the example username
- button "Add user" [disabled]
```

Probed directly, none of the three has any naming relationship at all:

```js
// every input under #access-control:
{ ph: "203.0.113.0/24",        ariaLabel: null, labelledby: null, hasLabelEl: false }
{ ph: "Description (optional)", ariaLabel: null, labelledby: null, hasLabelEl: false }
{ ph: "reporting",             ariaLabel: null, labelledby: null, hasLabelEl: false }
```

The Key Value detail page's Networking section shows the same two, and the control case is right beside them — the rename input **is** named:

```text
{ ph: "",               ariaLabel: "Name",  … }   ← named
{ ph: "203.0.113.0/24", ariaLabel: null,    … }   ← not
{ ph: "Description (optional)", ariaLabel: null, … }
```

### Cause, and the exhaustive call-site count

`dashboard/src/common/components/ip-allow-list-editor.tsx:150-172` renders both `<Input>`s with only a `placeholder` — no `aria-label`, no `<label>`, no `id`. `grep -rn "IPAllowListEditor" dashboard/src | grep -v __tests__` gives exactly **three** production call sites:

| surface | path |
| --- | --- |
| Postgres access control | `dashboard/src/features/databases/components/access-control-panel.tsx:15` |
| Key Value networking | `dashboard/src/features/keyvalue/components/key-value-networking-panel.tsx:8` |
| web / private service networking | `dashboard/src/features/services/components/service-networking-panel.tsx:8` |

Plus the database-user input, its own one-off: `dashboard/src/features/databases/components/access-control-panel.tsx:147` (`placeholder="reporting"`).

### The precedent is already in the repo — follow it

`dashboard/src/features/environments/components/environment-settings-dialog.tsx` renders the *same* CIDR fields **correctly**:

```tsx
aria-label={t("environments.ipAllowListRuleCIDR", { number: index + 1 })}   // :186-188
placeholder="203.0.113.0/24"                                                // :189
…
aria-label={t("environments.ipAllowListNewCIDR")}                           // :232
placeholder="203.0.113.0/24"                                                // :233
```

Translated name, placeholder as the example, and the per-row variant numbers the row. Note the irony worth keeping in mind while fixing: `w9/m56` unified service/Postgres/Key Value onto the shared `IPAllowListEditor` and deliberately left the Environments dialog on its own implementation — and the one left out is the one that got the labels right.

### Why this rides on m101 rather than its own item

m101/t004 is already the accessible-name task for this milestone (the autoscaling enable switches), and it is unshipped. This is the same fix class in the same codebase, so it belongs beside it rather than as a second board item doing the same work. Follow t004's shape and `w4/043`'s: a translated name per control, never one generic label reused across unrelated quantities.

## Steps

1. Give `IPAllowListEditor` a labelling contract. It already takes a `labels` prop (`labels.add`, `labels.save`, `labels.invalid`, `labels.descriptionPlaceholder`), so extend that rather than inventing a second mechanism — each of the three call sites passes names appropriate to its surface.
2. Decide whether the existing entry rows (the inline-edit inputs above the add row, `:130-148`) are also unnamed, and cover them the same way; `environment-settings-dialog.tsx`'s per-row `{ number: index + 1 }` pattern is the model if they need distinguishing.
3. Name the database-user input at `access-control-panel.tsx:147`.
4. Sweep the three call-site panels for any other unnamed interactive control while there, using `ariaSnapshot()` on each panel as the reference — not a DOM heuristic.
5. Every name goes through `t()` in both `en.ts` and `zh.ts`. Reuse the existing `environments.ipAllowList*` keys only if they read correctly outside an environment; otherwise add per-feature keys.
6. Assert with `getByRole("textbox", { name: … })`, not text presence — a test that finds the placeholder text passes today.
