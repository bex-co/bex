## Objective

Meet the DoD's "One instance per change" bullet. Today an image change on a web service that discovers its HTTP port starts two new instances. The first is the provisional `GET /` template. After detection, a second template carries the final probe.

## Context

- **Live, 2026-11-16 (`/loopx w4` replay, pin `06cc3b02c`).** Run A `dep-dbt6a6beh8gc738gofh0` on `srv-dbt69htp70ac73bdn10g` logged nginx `1.26.3` starting on `…h2gb2dg04o5644uueed2` at 02:06:38. A second instance, `…pbjuperfl04r2h2r8hbe`, started at 02:07:19 and took the traffic at 02:07:38. The git-built `examples/hello-go` case did the same: `…gimtp2ij5a5n0lh9gs50` at 02:42:42, then `…d3gvdvgp66b78e88n9b0` at 02:43:22. Rounds 121 and 123 measured it too.
- **t002 chose option (b):** keep the hold through the re-roll. Its reason was that the final probe had to differ from the provisional `GET /`. w4/m350 later gave a first release a template that does not depend on the chosen port: the any-open-port helper and no container port (`checksAnyOpenPort`). Only a release over a serving one kept the `GET /` guard.
- **The guard is redundant under the hold.** A held release has `minReadySeconds` 150, the held strategy (`maxUnavailable` 0), and Services pinned to the serving revision. A Ready candidate therefore drains nothing and takes no traffic before promotion. Promotion also waits for the HTTP selection, because `selectWebImageHTTP` returns before `promoteEarly` while the selection is pending.

## Result (2026-11-16)

- **Change.** `checksAnyOpenPort` (`lego/operator/internal/controller/deployment_projection.go`) now also returns true for a release over a serving one while its HTTP selection is pending. The stored-template clause keeps that choice for the release after detection and promotion, so its template never changes. Without the helper image the `GET /` guard still applies.
- **Tests:**
  - `TestFirstWebImageReleaseChecksAnyOpenPort` checks that a release over a serving one gets the open-port check, and that detection leaves its template unchanged. A release over a serving one whose port is retained keeps the TCP probe.
  - The w4/m350 envtest `rolls one template from dispatch to Running…` now carries the second release through pending discovery, detection and promotion. It asserts one template, the Services pinned to `rev-1` until then, the 150 s hold, and `rev-2` active afterwards.
  - With the fix reverted, the unit test fails ("want the any-open-port check").
