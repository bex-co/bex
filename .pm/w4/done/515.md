- **Root cause:** `lego/backend/internal/store/deploy_lifecycle.go:111`.
  - `deployTransitionPredecessors[DeployBuildFailed]` is `{created, queued, build_in_progress}`.
  - A static site's publish step runs in `update_in_progress`: the row moved there at 01:10:05.
  - w4/493 made the publish failure a `BuildFailedUserError` (`operator/internal/controller/app_controller.go` `publishStaticRevision`), so `reconciler.go:1539-1542` derives `DeployBuildFailed` on every pass.
  - `CanTransitionDeploy(update_in_progress, build_failed)` is false, so `TransitionDeploy` (`store/store.go:2774`, mirrored in `fake_test.go:860`) returns `false, nil` and the row never moves. The timeout path never applies, because the Failed branch returns `build_failed` before it.
  - `withholdBuildEndedWhilePublishing` (`reconciler.go:1198`, w4/505) keys on the computed status, not the stored one, so it emits `build_ended failed` for a row that is still open.
- **Fix:**
  - Target: a static site's missing publish directory closes the row `build_failed`, with the plain publish reason, within one reconcile of the failure; `build_ended failed` lands with it.
  - Add `DeployUpdateInProgress` to `deployTransitionPredecessors[DeployBuildFailed]`. Static publish is part of the build, as Render counts it.
  - Alternatively, keep a static deploy in `build_in_progress` until publish succeeds. The predecessor change is smaller and also covers rows already stuck.
  - Make `withholdBuildEndedWhilePublishing` (and the `build_ended` emission generally) depend on the row actually transitioning, so a refused transition cannot emit a terminal event.
  - Add a store/reconciler test: static deploy `update_in_progress` + operator `BuildFailedUserError` → row `build_failed` with reason. Check `TransitionDeploy` and `CanTransitionDeploy` callers so docker/native rows cannot regress `update_in_progress → build_failed` unexpectedly.
- **Blast radius:**
  - `CanTransitionDeploy` is the single transition gate (PG and fake store).
  - Widening `DeployBuildFailed`'s predecessors is global: any non-static App whose operator reports a build-failure reason after its row reached `update_in_progress` would now close `build_failed` instead of waiting. Decide whether to scope it to static sites via the caller, and add regression tests for docker/native deploys.
