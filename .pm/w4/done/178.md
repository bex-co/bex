## Cause, framework and fix

- `dashboard/src/features/logs/hooks/use-log-label-values.ts:35-49` calls useQuery with variables/errorPolicy only; there is no poll, explicit refetch or trigger when the menu opens. The plain-array wrapper at :54-55 inherits it.
- `dashboard/src/features/logs/components/log-filter-bar.tsx:77-103,142-158` merges static values with discovered values. METHOD_FALLBACK omits HEAD/OPTIONS/TRACE; a resolved empty set suppresses every fallback by design. Consequently a cached answer stays authoritative as traffic arrives.
- `dashboard/src/common/apollo/default-options.ts:24-26` only overrides notifyOnNetworkStatusChange; it does not supply a fetch policy or freshness timer. The singleton CSR factory uses InMemoryCache.
- Opened actual installed **@apollo/client4.1.3**: `core/QueryManager.js:708,1052-1069` defaults to cache-first and returns a complete cached result without using the link. `core/ObservableQuery.js:844-897` cancels polling without pollInterval; configured polling uses network-only and respects skipPollAttempt. Thus a mounted query does not spontaneously discover new values, and remounting against warm cache alone is not a reliable repair.
- Proposed fix: supply RESOURCE_POLL_INTERVAL_MS and skipPollWhenHidden from `common/lib/polling.ts:10,68` to the shared discovery query. Keep global notifyOnNetworkStatusChange false so background refresh does not replace ready content. Preserve prior usable values during a refresh/error and preserve the distinction between answered-empty and unavailable; never clear an active filter because its value disappears from discovery. Confirm no second timer owner is introduced for the same mounted query.

**Census:** six production call sites across three components: LogFilterBar calls useLogLabelDiscovery four times (level, method, statusCode, instance); DatastoreLogViewer:70 calls useLogLabelValues once (instance); NetworkMetricsCard:112 calls it once (host). Wrapper itself delegates once. Apply freshness globally to this shared hook. Test the existing correctly working host and datastore consumers as controls; backend host discovery is App-derived and must stay so. Exact family: generic service logs cover web/private/worker/cron; Postgres and Key Value use datastore viewers; static has no runtime Logs page, though shared network metrics may consume host discovery. Only web method discovery was reproduced live; other freshness impacts are inferred, not observed incidents.

Aliases: UI Logs route and its URL method/path filters consume the shared document; REST /v1/logs/values, GraphQL logLabelValues, MCP list_log_label_values already agree and need no wire changes. Keep per-resource backend authorization and scoping unchanged. Unauthenticated, forbidden and not-found remain their existing errors; store-unavailable/timeout must not become authoritative empty. While a poll is pending, show the current options and preserve selection; on a cold load keep the existing loading/unavailable fallback rules. Hidden tabs skip work and resume on the next visible tick.
