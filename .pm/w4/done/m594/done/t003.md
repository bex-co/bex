## Objective

For an environment group scoped to a protected environment, only a workspace Admin views or changes its variables and secret files, or deletes it, as Render documents ("Deleting a group and viewing or changing its variables or secret files are admin-only actions in a protected environment"). A non-Admin is refused with `403` `PROTECTED_ENVIRONMENT_ADMIN_REQUIRED`. A REST read of the group answers without `envVars` and `secretFiles`, Render's shape for a caller without permission to read the group's secret values.

## Context

- `authorizeGroup` (`lego/backend/internal/envgroups/service.go:1829`) is every by-id verb's gate. Reads use `can_view_sensitive` (`GetEnvGroupVar`, `GetEnvGroupFile`, `revealEnvGroupFile`, `ExportEnvGroup`, `revealGroups` in `render.go`, the source side of `clone.go`); writes use `can_create` (`SetEnvGroupVars`, `SetEnvGroupVarInput`, `DeleteEnvGroupVar`, `SetEnvGroupFile`, `DeleteEnvGroupFile`, `DeleteEnvGroup`, `:869-1065`). The group row carries `EnvironmentID`.
- `retrieved` (`envgroups/render.go:136`) already serves the group without values to a caller refused `can_view_sensitive`, from a probe that records nothing. Extend that branch to a non-Admin on a protected group, and keep the audited, fresh path for everyone else.
- `GroupWritesOwed` (`service.go:1736`) and `ApplyEnvGroup` are the Blueprint path: admit `core.BlueprintSync(ctx)` there, as t002 does.
- `LinkService` / `UnlinkService` change which values a service receives. A group can only link to services in its own environment (`validateGroupServiceEnvironment`). Decide whether link and unlink in a protected environment are "modifying environment variables" and record the choice with its Render basis.
- Protection lookup: `core.EnvironmentProtected` with the environments store, the predicate `core.RequireEnvironmentAdmin` uses. Use the same restricted verb as a protected service's env vars, and consider moving `secrets.Service.scopeAuthorized` (`secrets/service.go:234-245`, w8/193) to the same coded refusal so a service's and a group's Environment tabs read the same reason.
- ADR032:109's residual ("a linked environment group's content is workspace-scoped … stays editable by anyone who may edit the group") is rewritten in t007.

## Steps

1. Gate every group verb above on the group's environment after `authorizeGroup`, with the coded refusal.
2. REST read: omit values for a non-Admin on a protected group.
3. Admit a Blueprint's own sync.
4. Tests: per verb, Admin allowed, Developer refused with the code (and nothing written or revealed), unprotected allowed, Blueprint sync allowed, REST read without values for the Developer.
