# A blank service name over REST is refused as "already in use" while GraphQL and the dashboard clear it

Why: the same intent, clearing a service's display name back to its creation name, succeeds from the dashboard and GraphQL. REST and MCP callers get `409 CONFLICT name "" is already in use`, which names a collision that doesn't exist and gives the API its own answer.

- **Severity:** minor (API contract and wording; no data affected).
- **Source:** live functional `/qa-find-bugs w4`, pass 7094cb, 2026-10-19 UTC, `muse.env`, workspace `bex-canary`, production pinned to `69e925197b39`. Owned Free web service `qa-20261019-7094cb-a` (`srv-dbarkgkic9ks73e7hii0`), since deleted. Every probe ran from inside the signed-in page.
- **Probes:**
  - REST `PATCH /v1/services/<id>`:
    - `{"name":""}` and `{"name":"   "}` → **`409 {"code":"CONFLICT","error":"name \"\" is already in use",…}`**
    - `{"name":"\t"}` → `400 DISPLAY_NAME_CONTROL_CHARACTER`
    - `{"name":"qa-20261019-7094cb rest-renamed"}` → 200
    - `{"name":"hello-go"}` (another service's name) → 409 "already in use" (correct)
  - GraphQL `setDisplayName(id, displayName: "")` and `"   "` → **success**, `name` reads back as the creation name `qa-20261019-7094cb-a`. `"hello-go"` → `name "hello-go" is already in use`.
  - The dashboard's Settings → Edit service name lets Save through for a blank value (it calls `setDisplayName`), so the UI also clears.
- **Root cause:**
  - The REST/MCP patch table's `DisplayName` preflight (`lego/backend/internal/apps/settings.go:157-176`) calls `Store.ServiceNameTaken(tenant, id, trimmed)`.
  - That query is `SELECT EXISTS (… WHERE tenant_id = $1 AND id <> $2 AND (name = $3 OR display_name = $3))` (`store/store.go:1971-1977`). With `trimmed == ""`, `display_name = ''` matches every other service that has no custom display name, which in practice is all of them, so the preflight reports the name taken.
  - The write the preflight guards treats an empty display name as **clear** and skips uniqueness: `SetAppDisplayName` checks only `if displayName != "" && displayName != name` (`store.go:1892`), and `checkDisplayName` (`apps/service.go:4852-4870`) accepts the trimmed empty value. GraphQL `setDisplayName` calls `SetDisplayName` directly, without the preflight, so it clears.
- **Fix (target behavior):** an empty (or whitespace-only) display name clears the display name on every surface. REST and MCP return 200 with `name` = the creation name, exactly as GraphQL and the dashboard do.
  - Make the preflight mirror the write's own guard: skip `ServiceNameTaken` when `trimmed == ""` or `trimmed == probe.Name`.
  - Alternatively, have `serviceNameTaken` return false for `""`. That is narrower, but its create caller (`apps/service.go:2126`) never passes an empty name.
- **Blast radius:**
  - `ServiceNameTaken` has 2 callers: the patch-table preflight (`settings.go:167`), which serves REST `PATCH /v1/services/{id}` and MCP `update_service`, and the create plan (`service.go:2126`).
  - The table is shared by REST and MCP (`servicePatchTable`, pinned by `TestServicePatchTableOrderIsRESTApplicationOrder`), so one fix covers both.
- **Adjacent classes:**
  - A real collision keeps `409 CONFLICT`.
  - Control characters keep `400 DISPLAY_NAME_CONTROL_CHARACTER`, and more than 100 code points keeps `400 DISPLAY_NAME_TOO_LONG`.
  - A name shaped like a resource id keeps its reserved-name refusal.
- **Unverified:** MCP `update_service` (shares the table; not driven), and Render's answer to `PATCH name: ""` (likely a 400; if parity wants that, all surfaces should refuse together rather than diverge).
- **Dedupe:** `w4/done/m19` built the "Name is already in use" contract, and w8/m47 made renames unique. No item covers a blank rename. `git log` shows no change to the preflight since `ba000a2bb`.
- **Acceptance:**
  - An `apps` test: a patch with `DisplayName: ""` in a workspace with another default-named service succeeds and clears. It fails today.
  - A real-name collision still returns 409.
  - Live, `PATCH {"name":"   "}` returns 200 with the creation name.
- **Estimate:** 20m.

**Implemented 2026-10-19 (loopx w4):** the REST/MCP patch table's `DisplayName` preflight (`apps/settings.go`) now skips what the store's write skips: a blank name, which clears the display name, and the service's own creation name (`core.AppPublicName`). It no longer probes `ServiceNameTaken("")`, which matched every default-named service. REST `PATCH {"name":""}` and `{"name":"   "}` now clear and return the creation name, as GraphQL and the dashboard do.
- **Unchanged:** a real collision keeps `409 CONFLICT`; control characters, length and reserved-id refusals still come from `checkDisplayName`.
- **Tests:** `TestRESTBlankRenameClearsLikeGraphQL` fails with the guard removed. The test fake's write now skips a clear like the real store.
- **Remaining:** live, `PATCH {"name":"   "}` → 200 with the creation name, after the release pipeline deploys bex-api.
