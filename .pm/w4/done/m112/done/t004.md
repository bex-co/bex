## Objective

Place the new stall signal against Render's behavior and record whether bex matches, deliberately exceeds, or diverges — flagging drift as follow-up work rather than silently diverging.

## Context

- Render's own health-gated window is quiet: a deploy gated on a failing check shows an undifferentiated "Deploying" until its timeout, then fails the deploy. If that is still true on render.com, this milestone's signal is a deliberate bex exceeds-Render diagnosability improvement in the same family as the existing `stuckPodMessage` cases (crash/image-pull), not a parity fix — record it as such.
- The fix touches the shared deploy/events surface (operator condition → backend projection → dashboard), so REST/GraphQL/MCP must read the new reason identically; the events surface already does by construction.

## Result, 2026-09-18 — bex deliberately exceeds Render

1. **Render's behavior.** Render's health-check window is quiet by design.
   Its own docs describe the mechanism and the outcome — a deploy whose health
   check never passes is rolled back / fails after the check window — but
   Render surfaces no per-probe diagnosis during the window; the dashboard
   shows the deploy "In progress" until it resolves. bex's new signal has no
   Render counterpart to match, so this is an **exceeds-Render diagnosability
   improvement**, in the same family as the crash-loop and image-pull
   diagnoses `stuckPodMessage` already emitted (which likewise have no Render
   equivalent). No parity position changes, so
   `docs/ADR018-render-parity.md` is unchanged.
2. **No surface skew.** `stallReason` is a bex extra on the deploy object,
   carried on all three surfaces from one field: REST via the shared
   `renderDeploy` struct (`internal/deploys/rest.go`), which MCP's
   `list_deploys`/`get_deploy` return verbatim, and GraphQL via
   `Deploy.stallReason`. The events feed carries the same column
   (`ServiceEventDetails.stallReason`) on REST and GraphQL. Omitted when
   empty everywhere, exactly like `failureReason`/`cancelReason`.
3. **Wire compatibility.** An additive, omitempty field on a bex-extended
   object — the pinned Render OpenAPI validator is unaffected, and a client
   that ignores it sees today's payload byte-for-byte.
