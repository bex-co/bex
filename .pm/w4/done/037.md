# Hide Delete Workspace when it is the user's only workspace

Why: Offering last-workspace deletion creates a destructive dead end, so the settings page should expose the danger zone only when another workspace can become the user's remaining workspace.

On `/workspace/settings`, derive delete visibility from the caller's complete `useWorkspace().workspaces` list:

- when the list contains exactly one workspace, omit both the `DeleteWorkspaceCard` section and the **Danger Zone** navigation link;
- when the list contains two or more workspaces, keep both controls unchanged;
- cover both states with focused dashboard regression tests, including the navigation and card visibility.

Likely files: `dashboard/src/routes/workspace.settings.tsx`, `dashboard/src/features/workspaces/components/workspace-settings-navigation.tsx`, and their adjacent tests. Keep backend deletion semantics and GraphQL APIs unchanged. This is a sub-hour UI guard extending `w6/m3` and `w6/m5`, not a new lifecycle milestone.

Done 2026-08-29: `/workspace/settings` now derives `hasMultipleWorkspaces` from the complete workspace context and uses it for the navigation link, loading-region skeleton, and ready-state delete card.
