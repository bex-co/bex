# 541 — The static-site Redirects/Rewrites and Headers editors name every row's fields identically ("Type", "Source", "Destination" / "Path", "Name", "Value"), while each row's Remove button is numbered

Why: a screen-reader or voice-control user tabbing through three rules hears "Source, Destination, Source, Destination, Source, Destination" with no sign of which rule they are editing, while the same rows already announce "Remove rule 1", "Remove rule 2", and so on.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 10, 2026-11-10 09:52–10:05 UTC (`muse.env`, workspace `bex-canary`, pin `4630a48a765e`). **Minor** (accessibility; every control has a name, but the names don't say which row they belong to). ~20m.
- **Fixture:** static site `qa-20261110-static` (`srv-dbpejaa0mi5c73c5piu0`, `examples/static-site`, publish directory `.`; deleted, GET 404, and the URL answers 404).
- **The journey itself was clean:**
  - Redirect `/old-path` → `/index.html` answered `301`.
  - Rewrite `/app/*` served the index at `/app/dashboard` and `/app/deep/nested`.
  - Redirect `/blog/:slug` → `/posts/:slug` sent `/blog/hello-world` to `/posts/hello-world` (`/blog/a/b` correctly did not match).
  - Redirect `/docs/*` → `/guide/*` carried the captured path (`/docs/a/b/c` → `/guide/a/b/c`), as Render documents.
  - Header `X-QA-Test` on `/*` reached the 200, the 404 and the 301 responses. `X-Frame-Options: DENY` on `/app/*` appeared only there.
- **Probe:** with three route rows open on `/static/srv-dbpejaa0mi5c73c5piu0/redirects`, the accessibility tree listed, per row, `combobox "Type"`, `textbox "Source"`, `textbox "Destination"` and `button "Remove rule N"`. On `/headers`, each row listed `textbox "Path"`, `textbox "Name"`, `textbox "Value"` and `button "Remove header N"`.
- **Root cause:** `dashboard/src/features/services/components/static-site-section.tsx` gives the fields their column headings:
  - routes: `:268` (`aria-label={t("services.routeType")}`), `:287` (`label={t("services.routeSource")}`), `:299` (`services.routeDestination`);
  - headers: `:410` (`services.headerPath`), `:420` (`services.headerName`), `:429` (`aria-label={t("services.headerValue")}`).
  - Only the Remove buttons carry the row number (`:312` `services.routeRemove` "Remove rule {n}", `:438` `services.headerRemove` "Remove header {n}", `features/services/locales/en.ts:2964-2968`, `:3067-3069`).
  - w6/059 (done) chose the column headings as names because the six controls had none. Naming them per row was not part of that fix.
- **Fix:** name each field with its row, matching the Remove buttons: "Rule {n} type", "Rule {n} source", "Rule {n} destination", "Header {n} path", "Header {n} name", "Header {n} value". Add en and zh keys. Visible column headings and placeholders stay unchanged. Validation errors keep their existing association with the field.
- **Blast radius:** one component, `static-site-section.tsx`, six fields in two editors. No other caller uses these keys outside tests.
- **Dedupe:** w6/059 (done) fixed the missing names. w4/436 (done) applied the same per-row naming to custom domains, and w4/235 (done) is the mobile field width. [w4/537](537.md) and [w4/540](540.md) are other components. No open item. `static-site-section.tsx` is unchanged between `4630a48a765e` and HEAD.
- **DoD** (live): with three route rows and two header rows open, the accessibility tree lists `combobox "Rule 1 type"` … `textbox "Rule 3 destination"` and `textbox "Header 1 path"` … `textbox "Header 2 value"`. The zh locale names them too, and the visible headings are unchanged.

- **2026-11-11 (loopx w4):** fixed: every route row names its fields "Rule {n} type/source/destination" and every header row "Header {n} path/name/value" (en/zh `services.routeTypeAria` … `headerValueAria`, `aria-label` on each control); the visible column headings are unchanged. `static-site-section.test.tsx` and the redirects route test assert the per-row names.
