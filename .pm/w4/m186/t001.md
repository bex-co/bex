## Objective

After one successful RenameProject mutation, publish an authoritative project-name snapshot only after older active Projects reads have finished writing. Preserve the shared retained-navigation policy.

## Context

See [finding.md](finding.md): mutation acknowledged r4 at 1520 ms; a list read started before it and completed at 1533 ms with r3. Heading/title remained r3 after the resource table settled. The API had r4.

## Steps

1. Implement the bounded refresh in useRenameProject. Settle each active Projects refetch result with allSettled, then re-read typed ProjectDocument by ID network-only. Per-request queryDeduplication false can guarantee a fresh final operation; do not disable it globally. Validate this ordering against other writers in t002.
2. Ensure Overview and Settings invalidate only after that final read/cache write. Preserve the existing one-write API and title format.
3. Keep the saving state honest until refresh settles. Mutation failures retain their current refusal/form behaviour. Post-write refresh failures retain the acknowledged save, release busy state, and offer accurate refresh/retry feedback without a second rename or false failed-save toast. Use existing i18n and authz/error handling.
4. Do not treat a concurrently newer authoritative server name as stale merely because it differs from the submitted name.
