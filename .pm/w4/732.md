# A disk can be sized up to 10 000 GB on bex, where Render's dashboard stops at 1000 GB and sends larger sizes to support

Why: Render parity — w4/m652's parity check (t005, 2026-11-26) read Render's size control and found a cap bex does not have, with no ADR018 sign-off for the difference.

- **Render:** both of its dashboard disk forms (the create form's Advanced card and the Disk page) use a size stepper from 1 to 1000 GB, and above that the field says "For sizes larger than 1 TB, please email support@render.com" (public bundle `index-D5V4ZgbE.js`, read 2026-11-26; [render-artifacts/new-service-wizard.md](../../docs/render-artifacts/new-service-wizard.md#the-advanced-section-read-2026-11-25-w4m651-t001)). Render's docs state no maximum ([ADR082](../../docs/ADR082-persistent-disks.md) § Size), and what its API answers for `sizeGB` above 1000 was not checked: that is a write on the reference account.
- **bex:** every surface accepts 1–10 000 GB, Hetzner's volume cap (`diskMaxSizeGB`, `lego/backend/internal/apps/disks.go`; `DISK_MAX_SIZE_GB`, `dashboard/src/features/services/lib/disk.ts`). ADR082 states the 10 000 GB cap; ADR018's Persistent disks row does not list it as a divergence.
- **End state:** either the dashboard's size fields stop at 1000 GB with Render's support message (and REST/GraphQL/MCP/Blueprint follow whatever Render's API answers above 1000 GB), or ADR018's Persistent disks row records the larger cap as a divergence with the user's sign-off.
