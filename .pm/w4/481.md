# 481 — A project's resource table lists a static site's Runtime as "Not available —"

Why: every other row names its runtime ("Docker", "PostgreSQL 18", "Valkey 8"). The static-site row says the fact is unavailable, as if the dashboard failed to load it, although "static site" is the most certain fact about the row. The table already has a "Static" label that is never used.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 48, 2026-11-05 06:09 UTC (`muse.env`, `bex-canary`, pin `dcdc774c1a6b`); **minor** (copy/honesty of an empty state); ~15m.
- **Probe:** owned project `qa-20261105-proj` (`prj-dbm1qrgj8n6s73bagtm0`, environments staging and production) and static site `qa-20261105-pstatic` (`srv-dbm1quoiff5c739puv20`, `examples/static-site`, created with `environmentId` = staging). Both were deleted at 06:12.
  - `/project/<prj>?env=<staging>` → `ariaSnapshot()` row: `Select qa-20261105-pstatic qa-20261105-pstatic Static Site Running Not available frankfurt 1m`, and the Runtime cell is `cell "Not available": —`.
  - GraphQL from the page: `{ service(id:"srv-dbm1quoiff5c739puv20"){ id type runtime region } }` → `{"runtime":"","type":"static_site","region":"frankfurt"}`. REST `serviceDetails` has no `runtime`, which matches Render's static-site object.
  - The rest of journey 1 behaved correctly. `POST /v1/projects` with two environments listed both. The service landed in staging (`GET /v1/environments/<staging>` `serviceIds`). The table's **Move** to production updated `environmentId` and both environments' `serviceIds`, and the staging heading read "staging 0 resources". Deleting the project made its environments 404.
- **Root cause:** the backend deliberately returns no runtime for a static site (`lego/backend/internal/core/source_runtime.go:49-50`, Render parity). The dashboard row maps only `s.runtime` (`dashboard/src/features/projects/hooks/use-grouped-resources.ts:29`, `formatRuntime`), so its `static: "Static"` label (`:86`) is unreachable, and `resource-table.tsx:216` renders `UnknownValue`.
- **Fix (target behavior):** a static-site row's Runtime cell reads `Static`. In `toServiceRow`, fall back to `"Static"` when `s.type === "static_site"` and the server runtime is empty. Leave the backend unchanged, since Render's static-site object has no runtime. Add a case to `hooks/__tests__/use-grouped-resources.test.ts`.
- **Blast radius:** `toServiceRow` has two callers, the project table (`use-grouped-resources.ts:122`, `:146`) and the environment card (`features/environments/components/environment-card.tsx:181`). Both get the fix. Other types are unchanged: a service with no runtime for another reason still shows "Not available".
- **Unverified:** the environment card was not opened live. It is inferred from the shared `toServiceRow`.
- **Render:** Render's project view shows a runtime for every service row, and static sites read as static.
- **Dedupe:** `grep -ril -e RUNTIME_LABELS -e formatRuntime -e toServiceRow .pm` → nothing. w4/266 (done) is about project filters. No DO_NOT_DO item applies.
