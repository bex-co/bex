## Objective

Stop kubelet enumerating every Service in the workspace namespace into every tenant container. One field on the pod spec, placed where bex's own choices live.

## Context

- `lego/operator/internal/controller/deployment_projection.go:426` builds the App Deployment's pod template and calls `applyPodSpecServerDefaults` at the end. `EnableServiceLinks` is never set, stays `nil`, and the API server defaults it to `true`.
- **Do not put it in `applyPodSpecServerDefaults`.** That helper's documented contract is "what Kubernetes would have chosen", and its comment records that writing those defaults cannot roll a pod because the stored object stays byte-identical. `false` is not the server default, so it *does* change the stored template. Putting it there would both break the helper's invariant and hide the roll.
- `grep -rl 'EnableServiceLinks' lego dashboard` → 0. Nothing depends on the current value.
- Live baseline to beat: 185 env vars in the container, 174 of them service links, 25 sibling prefixes.

## Steps

1. Set `EnableServiceLinks: ptr.To(false)` in the Deployment projection, next to the other deliberate pod-level choices, with a comment naming the footgun it prevents.
2. Confirm the projection is still idempotent — a converged reconcile must remain a no-op after the first write (that is `w7/m84`'s guarantee and the reason the helper exists).
3. Verify against a live or envtest pod that the link vars are gone and `PORT` and the user's variables remain.
4. Confirm the private-network path still works: a sibling is still reachable at `<slug>:<port>` (ADR041 D4, `w9/m58`).
