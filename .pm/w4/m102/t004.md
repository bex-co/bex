## Objective

t002 changes one selector that every `anyOf` in the blueprint schema flows through. The branches that report correctly today do so by accident of leaf counts, so they need pinning as much as the broken one.

## Context

`appendBlueprintSchemaProblems` (`blueprint_compiler.go:1082`) is the single renderer of schema problems; `blueprintSchemaProblems` (`:1072`) is its only entry. Every validation error on every blueprint surface goes through it — `validateBlueprint`, `blueprintPreview`, the sync/apply path, and MCP. There is no per-surface variant, so the fix is global by construction; say so rather than implying an allowlist is possible.

The `anyOf` sites to cover, from the schema:

- `#/definitions/resources.properties.services.items.anyOf` → `[redisServer, cronService, serverService, staticService]` (const-discriminated on `type` / `runtime`)
- the env-var forms — `envVar`, `envVarFromDatabase`, `envVarFromService`, `envVarFromGroup`, `envVarFromKeyValue` (discriminated by which key is **present**, not by a const, which is why t002 must decide their rule separately)

Control cases that pass today and must keep passing, verified live this run:

| manifest | current behavior |
| --- | --- |
| `type: cron` + `schedule` + docker | valid |
| `type: nonsense` | `value must be one of 'web', 'worker', 'pserv'` (t002 changes the set, not the fact of an error) |
| duplicate service names | `duplicate name "qa-dup" for service (first declared at #/services/0)` |
| missing `name` | `at '/services/0': missing property 'name'` |
| unknown property | `at '/services/0': additional properties 'totallyUnknownField' not allowed` |
| non-YAML input | `Blueprint is not valid YAML` |
| empty document | `Blueprint must contain one YAML document` |
| `foo: bar` at root | `at '': additional properties 'foo' not allowed` |

## Steps

1. Write a table test over the eight control cases above, asserting the exact messages so a selection change cannot quietly reword them.
2. Add one case per service branch: a manifest of that kind with exactly one wrong key, asserting the reported property is the wrong key.
3. Add the multi-error case: two wrong keys on one service, and two services each with one wrong key — confirm both are reported rather than collapsed to one.
4. Cover the env-var forms per t002's decision: either a case per form, or a recorded reason why they stay on the leaf-count path.
5. Re-run t001's seven-manifest walk as part of this suite so validity and message quality are pinned together.
