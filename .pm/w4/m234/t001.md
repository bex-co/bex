## Objective

`secrets.PatchEnvironment` with `saveMode:"deploy"` on a suspended App writes the values exactly as `save_only` does and answers `rolledOut:false` with a product-English `rolloutError`. Today it bumps `restartedAt`, opens a config-change row the reconciler cancels, and answers `rolledOut:true`. Rebuild mode keeps its no-row shape and gets the same sentence.

## Context

- `lego/backend/internal/secrets/batch.go:87-147` `PatchEnvironment`.
  - `scopeForWrite(RelCanCreate)` is at `:91`.
  - The deploy precheck `servedArtifact` is at `:118`.
  - The rebuild error becomes `RolloutError` at `:139`.
- `batch.go:349` `finalizeEnvironmentPatch`: the deploy branch at `:371-372` activates the pending references and calls `bumpRestart`, and `:404` sets `result.RolledOut = saveMode == SaveModeDeploy`.
- `patchEnvironmentCAS` (the revision-aware path) reaches the same finalize step, so it needs the same treatment.
- `lego/backend/internal/deploys/service.go:630` `validateTrigger` refuses a suspended App with `conflict: service "<id>" is suspended`. Rebuild mode surfaces that raw string.
- One core path serves all three surfaces: REST `PATCH /v1/services/{id}/environment` (`secrets/rest.go:79-85`), GraphQL `patchServiceEnvironment` (`secrets/graphql.go:222`) and MCP `patch_service_environment` (`secrets/mcp.go:110-113`).

## Steps

1. After `scopeForWrite` and the manifest-key refusal, read `a.Spec.Suspended`. When it is set and the mode is `deploy` or `rebuild`, run the patch as `SaveModeOnly` and skip the rebuild call.
2. Set `RolloutError` to one sentence for both modes, e.g. "Saved. This service is suspended, so nothing was deployed. Resume it, then deploy to apply the changes." Keep it product English: no `conflict:` prefix and no raw id.
3. Keep `RolledOut:false`. Leave the not-suspended paths byte-for-byte unchanged.
4. Re-read the App inside the locked patch, so a suspend that lands between the read and the write also stages. Consider deciding inside `finalizeEnvironmentPatch` from the App it actually writes.

## Acceptance criteria

- [ ] On a suspended App, deploy mode writes the values and stages the references (`undeployedChanges` true afterwards), adds no `restartedAt` bump, opens no deploy row, and answers `rolledOut:false` with the sentence.
- [ ] Rebuild mode on a suspended App answers the same sentence and opens no row.
- [ ] The same holds through REST, GraphQL and MCP (handler-level tests).
- [ ] Not suspended: deploy mode still opens exactly one row and answers `rolledOut:true` (regression test).
