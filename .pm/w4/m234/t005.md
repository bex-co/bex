## Objective

Confirm REST, GraphQL, MCP and the dashboard agree on the suspended-save shape: a save that stands, `rolledOut:false`, the same `rolloutError` sentence, no row, and the Save only primary. Then compare with Render.

## Context

- Render: "Save and deploy" redeploys the existing build, and "Save only" waits for the next deploy (`render.com/docs/configure-environment-variables`). API env updates never deploy on their own (`api-docs.render.com/reference/update-env-vars-for-service`).
- Render's deploy trigger enum includes `service_resumed`.
- Nothing documents a dashboard save on a suspended Render service.

## Steps

1. Run the three surfaces against one suspended fixture (dev stack or production after deploy), and record the envelopes.
2. Add an ADR018 row note for the suspended-save behavior and the resume shape t004 chose, marked as parity or a documented divergence.
