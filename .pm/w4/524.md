# 524 — The `/agents` "Spend limit (USD)" field turns invalid and disables "Start session" without telling a screen reader why: the error is a plain paragraph, not a live region, and the input has `aria-invalid` but no `aria-describedby`

Why: a customer who types a bad ceiling hears nothing: the input flips to invalid and the send button goes disabled, but the explanation ("Enter an amount more than $0 and at most $100,000, or leave it blank.") sits in an unannounced paragraph that no control points to. The ceiling is the money bound on an agent run, so a silent rejection is worse here than elsewhere.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 114, 2026-11-05 UTC (`muse.env`, `bex-canary`); **minor** (accessibility); ~20m.
- **Probe:** read-only, signed in, `/agents`. I typed a draft task into the Task box, then filled the Spend limit box and blurred it for each value, reading the control state; nothing was submitted and the draft was cleared. Per value, `Start session` disabled / `aria-invalid` / `aria-describedby`:

  | Value typed | Start session | `aria-invalid` | `aria-describedby` | Visible message |
  | --- | --- | --- | --- | --- |
  | `5`, `0.001`, `5.555`, `  7  ` | enabled | `false` | none | the keyboard hint |
  | `-5`, `abc`, `0`, `1e9`, `999999999`, `٥` | **disabled** | `true` | **none** | `Enter an amount more than $0 and at most $100,000, or leave it blank.` |

  - The accessibility tree names the field `textbox "Spend limit (USD)"`; its placeholder is `Spend limit` and its hint is a `title` attribute (hover only).
  - Sub-cent values (`0.001`, `5.555`) are accepted on purpose: the meter records sub-cent digits (`features/agent-sessions/lib/spend-limit.ts:26-39`).
  - Control, same day: the Key Value name field on `/keyvalue/new` points its message with `aria-describedby="kv-name-error"` when invalid.
- **Root cause:** `dashboard/src/features/agent-sessions/components/new-session-composer.tsx`:
  - the input sets `aria-invalid={!spendLimit.ok}` (`:358`) and has no `aria-describedby`;
  - the message is a plain `<p>` (`:409-422`) whose text switches between `agentSessions.spendLimitInvalid`, the attachment states and the keyboard hint. It has no `id`, no `role` and no `aria-live`, so a change to the invalid text is not announced;
  - `Start session` is disabled by the same flag (`:393`) with no description either.
- **Fix (target behavior):** when the ceiling is invalid, a screen-reader user is told why, at the moment it becomes invalid and when they return to the field.
  - Give the paragraph an `id` and set `aria-describedby` on the Spend limit input (and on the disabled Start button) to it.
  - Make that paragraph a polite live region (`role="status"` / `aria-live="polite"`), so the switch to the invalid text, and the existing attachment states, are announced. Keep it always mounted so the first change is announced.
  - Leave the visible copy, `title` hint and validation rule unchanged.
- **Tests:** a composer test that types `-5` and asserts the input `toHaveAccessibleDescription(...)` equals the invalid message and that the live region contains it, then types `5` and asserts the description returns to the keyboard hint; the existing `parseSpendLimit` tests stay as they are.
- **Blast radius:** one component, one message paragraph, one input. `spendLimitInvalid` is also the only error string for the field. Whether the session page's steering composer carries a similar ceiling control was not checked.
- **Adjacent classes:** the `title` hover hint on the input is not available to keyboard or touch users; moving it into the described text would cover that, but is a separate wording choice.
- **Unverified:** a real screen reader's announcement (only attributes and the tree were read); the zh rendering; the steering composer.
- **Render:** n/a (accessibility of a bex control; the reference product for agent sessions is Devin, not compared).
- **Dedupe:** w21/005 (done) added the field and its validation; `grep -rli "spend limit" .pm` finds only that item and nothing on its accessibility. No DO_NOT_DO item applies.
