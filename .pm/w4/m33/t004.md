## Objective

An attacker starts the public CLI device flow and sends the victim its `verification_uri_complete`. If the victim is **signed out**, the dashboard pairs the attacker's device transaction before login; the victim then signs in and the trusted client's `skip_consent` completes authorization with no further human decision.

## Context

- `dashboard/src/common/server-fn/hydra-device.ts` — `handleDeviceVerification` renders a confirmation page when a session exists and otherwise calls `acceptDevicePairing` directly. Its own comment accepts this ("An unauthenticated visitor still pairs and is bounced through login"), reasoning only about a signed-in victim; the signed-out victim is the unclosed half.
- `dashboard/src/common/server-fn/hydra-consent.ts:219-232` — `isTrusted(consent)` auto-accepts, so nothing downstream re-asks.
- `scripts/auth-bootstrap-client.sh:154-164` — the Render CLI client is registered `skip_consent: true` with `offline_access`, so the grant includes a refresh token.

## Steps

1. Drop the `acceptDevicePairing` call from the signed-out GET branch. Carry `user_code` + `device_challenge` through the login redirect instead (they must survive the round trip without becoming forgeable — sign or session-bind them rather than trusting bare query params).
2. After login, render the same `deviceConfirmationPage` and require the existing same-origin, session-bound `handleDeviceConfirm` POST.
3. Confirm the CLI's polling cadence tolerates the extra step (it polls `/v1/device-token` until authorized; the grant simply stays pending longer).

## Acceptance criteria

- [ ] A device grant opened in a signed-out browser stays pending through login and is authorized only by the explicit confirmation POST.
- [ ] The confirmation page names the requesting client so the victim can recognize a device they did not start.
- [ ] `scripts/render-cli-auth-e2e.sh` still completes with the unmodified official CLI.

## Out of scope

- Reworking `skip_consent` for the trusted client — the fix is that device pairing is a separate human decision from OAuth consent, not that consent stops being skippable.
