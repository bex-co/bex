## Objective

`ResolveSSHSession` and `CreateShellSession` reach the same `pods/exec` sink but enforced different relations. Raise native SSH to `can_view_sensitive` and pin BOTH transports in the role-ladder guard so the asymmetry cannot come back.

## Context

- `lego/backend/internal/apps/service.go` — `ResolveSSHSession` authorized `core.RelCanOperate`; `CreateShellSession`, twenty lines below, authorizes `core.RelCanViewSensitive` with a `SECURITY (codex #1)` comment arguing a shell is `printenv` on the pod's env vars and mounted secrets.
- `deploy/gitops/authz/model.fga:67-73` — a contributor holds `can_operate` **and** `can_manage_ssh_keys`, so the cheapest bypass of the browser-shell boundary was to enroll a key and run `ssh`.
- The gateway re-runs `ResolveSSHSession` per connection (`lego/backend/internal/sshgateway/resolver.go`), so the fix lands on both the mint and the re-check.

## Acceptance criteria

- [x] `ResolveSSHSession` authorizes `core.RelCanViewSensitive`.
- [x] `representativeVerbRelations` pins `*apps.Service.ResolveSSHSession` **and** `*apps.Service.CreateShellSession` to `can_view_sensitive` — the guard errors if a pinned verb is absent from the sweep, so both are proven live.
- [x] The existing SSH authz test asserts the new relation for both the allow and the deny leg.

## Resolution (2026-08-09)

Changed the relation and left the security rationale in place at the call site: the relation belongs to the sink, not the transport. Renamed `TestResolveSSHSessionAuthorizesCanOperateOnTargetWorkspace` →
`...AuthorizesCanViewSensitiveOnTargetWorkspace` and updated both assertion legs. Added the `ResolveSSHSession` pin next to the existing `CreateShellSession` one with a comment naming why pinning only one is how this survived round 3. `go test ./...` green across the backend module.

**Behavior change:** a contributor who could previously `ssh` into a running instance now gets 403. That is the intended tightening, but it is user-visible — anyone relying on contributor SSH must be moved to developer.
