## Root cause, consumers and bounded fix

- `dashboard/src/features/env-groups/components/env-group-actions.tsx:207,240`: Move and Clone use DialogContent with no explicit bounded grid column. Shared `common/components/ui/dialog.tsx:63` provides grid, frame cap and padding; the scope's unbroken intrinsic width expands that auto track. The [CSS Grid automatic minimum rules](https://www.w3.org/TR/css-grid-1/#min-size-auto) explain this sizing. Add the scoped minmax(0,1fr) column to these two dialogs.
- `features/env-groups/components/scope-select.tsx:44–54`: the trigger, content and items supply no local width/wrapping override. `common/components/ui/select.tsx:38` defaults to w-fit, whitespace-nowrap, fixed36px height and a one-line value clamp. Its viewport at:77 retains a minimum equal to trigger width. A frame/grid fix alone would leave the trigger and popup overflowing, as live Create demonstrates.
- `new-env-group-dialog.tsx:108` already has the bounded column; its:562 scope mount explains the passing footer and separately clipped picker. Retain the done242 service-row fix.
- Pinned/installed Radix Select **2.2.6**: `dashboard/node_modules/@radix-ui/react-select/dist/index.mjs:674–705` delegates popper positioning and exposes available-width/trigger-width variables;:927–929 portals selected ItemText children into the trigger. Position collision handling does not shrink our805px text. The [Radix sizing documentation](https://www.radix-ui.com/primitives/docs/components/select#constrain-the-content-size) documents those sizing variables; current web docs display a newer version, so the mechanism here was checked in the installed2.2.6 code. Tailwind lock/install is4.1.18; no dependency upgrade is proposed.
- ScopeSelect can express the correction through its existing trigger/content/item className props: constrain the trigger to the containing width, allow a variable height and full wrapping rather than the inherited one-line clamp, cap the popup to available viewport width and allow each item text to wrap/break long segments. Confirm its viewport's trigger minimum and flex ItemText remain bounded. The already-landed four-selector fix in `services/components/editable-field-row.tsx:235–261` is a scoped precedent, not a reason to mutate shared primitives.
- Exhaustive production JSX census: **three ScopeSelect sites** (Create:562, Move:214, Clone:271); **two NewEnvGroupDialog mounts** (`routes/env-groups.tsx:123`, `services/components/env-groups-panel.tsx:319`); **one EnvGroupActions mount** (`routes/env-groups_.$groupId.tsx:158`).
