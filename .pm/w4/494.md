# 494 — An out-of-range Max shutdown delay just greys out Save, with no message saying why

Why: a user who types 0, 301 or 1.5 into Max shutdown delay sees Save go disabled and nothing else, so it looks like the form is broken. The shared row component already shows an inline, announced error for invalid input. This field does not use it.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 70, 2026-11-05 13:09 UTC (`muse.env`, `bex-canary`, pin `c8bbc07cbeeb`); **minor** (form feedback and accessibility); ~15m.
- **Probe:** owned Free image web service `qa-20261105-sd` (`srv-dbm80a3o6h3c73cauta0`, deleted at 13:11). On `/services/<id>/settings`, click **Edit max shutdown delay**:
  - Enter `301`. The `ariaSnapshot` is `spinbutton "Max shutdown delay": "301"`, `button "Save changes" [disabled]`, and there is no error text. The input has `min=1 max=300` and `validity.rangeOverflow: true`, but no `aria-invalid` and no `aria-describedby`. The only visible text is the hint "Wait 1–300 seconds after SIGTERM before force-stopping the process (default 30)."
  - Enter `0`: Save is disabled, again with no message. Enter `60`: Save is enabled.
- **Root cause:** `dashboard/src/features/services/components/max-shutdown-delay-row.tsx:35-43` encodes the 1–300 integer rule in `dirty`, so an invalid draft reads as "unchanged" and Save is simply disabled. `EditableFieldRow` has `validate?: (draft) => string | null` (`editable-field-row.tsx:82`), which blocks save, renders the message with `role="alert"` (`:354`) and links it through `aria-describedby` (`:305`). The control case `service-port-row.tsx:66` uses `validate` for its number field.
- **Fix (target behavior):** an out-of-range or non-integer draft shows an inline message such as `Enter a whole number of seconds from 1 to 300.` (en + zh). The message is announced, linked to the input, and blocks Save. Keep `dirty` as "differs from the current value". Add a component test for `0`, `301` and `1.5` (message shown, Save blocked) and for `60` (no message, Save enabled).
- **Blast radius:** one component. `grep` for `EditableFieldRow` with `type="number"` finds 2 files: this one (no `validate`) and `service-port-row.tsx` (has `validate`).
- **Unverified:** the API's own refusal for an out-of-range value was not probed this round.
- **Render:** Render's settings forms show an inline error for an invalid value.
- **Dedupe:** `grep -ril "max shutdown delay" .pm` finds w4/125 (GraphQL nullability, done) and m196 t001 (the field's introduction); neither covers validation feedback. w4/461 (done) is about messages that are visible but not announced; here no message exists at all. No DO_NOT_DO item applies.
