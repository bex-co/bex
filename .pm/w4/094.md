## The extensionless-200 behavior is ADR018's accepted divergence, not a bug

`/zzz/deep/thing` returns `200` with `index.html` while `/zzz/deep/thing.html` returns `404`. That looked like over-matching by the `/qa-spa/*` rule, so it was isolated properly rather than filed:

**Control — every route removed** (`setStaticRoutes(routes: [])`, confirmed `routes: []`), same paths re-requested:

| request | zero routes configured |
| --- | --- |
| `/zzz/deep/thing` | `200`, 355 bytes (index.html) |
| `/zzz/deep/thing.html` | `404`, 10 bytes |
| `/qa-spa/deep/link` | `200` (no rule left — the fallback, not the rewrite) |

So the behavior is **unconditional and has nothing to do with the rules**. It is the documented SPA fallback at `lego/operator/internal/staticserver/staticserver.go:295-300`:

> SPA fallback: if the miss (after any rewrite) is a bare path with no extension and an index.html exists at the root, serve it so client-side routing works even without an explicit route. A missing asset (has an extension) stays a 404.

And it is in the parity ledger verbatim — `docs/ADR018-render-parity.md:82`:

> **Default-serve divergence (accepted, w3/m46):** with no `routes` configured, bex serves the root `index.html` (200) for an **extension-less** miss (asset-like misses still 404), an SPA-friendly default; Render 404s unmatched paths until a `/* → /index.html` rewrite or a `404.html` is added. Deliberately kept.

Measured behavior matches that sentence exactly, in both the with-routes and zero-routes cases. **Not filed** — a deliberate divergence recorded in ADR018 is explicitly out of scope for this hunt.

The value here is the live evidence: ADR018's sibling row (`:174`, `w4/m94`) notes "Live authenticated Render execution of the rewritten-path edge was not performed; behavior follows Render's primary docs". The bex side of that edge is now executed and matches.

Worth knowing for anyone reading the dashboard: the redirects page says "an SPA fallback rewrites `/*` to `/index.html`", which reads as instruction. For extensionless paths it already happens without any rule. The rule is still needed to make **asset-like** misses (`/x.html`) fall back — that is the real difference, and the copy does not say so. Too small to file on its own; worth folding into any future edit of that page.
