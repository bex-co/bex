# 395 — The Protected environment toggle still promises "an explicit sudo confirmation" that w8/187 removed; it now means Admin-only delete/suspend/resume/maintenance

Why: a user turning protection on reads that it adds a typed confirmation, which no longer exists. What protection actually does since w8/187 (only workspace Admins may delete, suspend, resume or enable maintenance) is not said anywhere they can see.

**Severity:** minor (copy contradicts behavior). **Estimate:** ~30m. **Source:** live `/qa-find-bugs w4` loop run p2q8, 2026-10-23 UTC (`muse.env`, `bex-canary`, pin `fa8ac5bba24a`, which includes `f2333df02`). In a protected environment `production` (`evm-dbdee8fsf6rc738q75m0`), static site `qa-20261022-p2q8-site` (`srv-dbdee8g8dkas73a0v41g`) went through Settings → Suspend → `Suspend` (no phrase; `suspended: suspended`), then Delete with only the ordinary local `sudo delete static site …` field (`GET` → `404`). No server-issued protected phrase appeared at any step, as w8/187 intends. Everything was deleted; session revoked.

## What is stale

- `dashboard/src/features/environments/locales/en.ts:334` (and zh): the environment settings dialog's **Protected environment** switch says "Require an explicit sudo confirmation for destructive service actions."
- The server no longer issues `confirmation_required` in protected environments (w8/187 commit `f2333df02`: "Delete, suspend, resume and turning maintenance mode on now require the workspace Admin role (403 otherwise); every other verb needs no phrase"). The dashboard still carries the handshake UI and copy: `services.protectedConfirmationTitle/Body/Prompt` (`dashboard/src/features/services/locales/en.ts:4-16`), `capabilities.blockedProtectedConfirmation` (`capabilities/locales/en.ts:50-53`) and the `ProtectedConfirmationDialog` path. Check whether these are now dead, and remove them or keep them as an explicit back-compat path.

## Fix (target behavior)

- The switch's description states Render's rule: in a protected environment only workspace Admins can delete, suspend, resume or turn on maintenance mode for its resources (and, once w8/193 lands, read secrets and open a shell). en + zh.
- A non-Admin attempting one of those gets the 403's reason in the dashboard rather than a confirmation prompt. Verify with a Developer-role member if the QA workspace has one (not probed this run).
- Dead protected-confirmation UI and keys are removed, or kept with a comment naming the compatibility case. Locale parity tests are updated.
