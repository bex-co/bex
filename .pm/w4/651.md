# 651 — A dashboard load that meets a rollout's old/new pod overlap can still end on "Something went wrong": reload once, guarded, on Vite's `vite:preloadError`

Why: w4/m348 made a missing chunk answer `404 no-store`, so nothing poisons a cache any more and TanStack Router's one-shot reload recovers most loads. When several chunks of one load land on different pods during the few seconds of a rollout's overlap, the one-shot reload is already spent and the page ends on the error screen until the user clicks Try again.

- **Source / severity / estimate:** w4/m348's implementation report (2026-11-14), reproduced locally with two builds behind an alternating proxy: one load in that setup ended on "Something went wrong", and Try again recovered once the old server was gone. **Minor** (seconds per rollout). ~30m.
- **Fix:** listen for `vite:preloadError` (Vite's documented hook for a failed dynamic import) and reload the page once per build version, guarded by a `sessionStorage` key holding the build id so a persistent failure cannot loop. Keep w4/269's Try again and TanStack's own reload.
- **Tests:** a `vite:preloadError` event reloads once; a second one with the same build id does not; a new build id re-arms it.
- **DoD:** with two builds behind an alternating proxy (w4/m348 t002's harness), every load ends on the page, not the error screen.
