## Objective

The milestone keeps the labels unchanged, but they don't follow Render either.

- **`host` and `path` are filterable but never returned.** Render's pinned `logLabel.name` enum lists both. A request line carries neither, though both filters work on it.
- **`requestID` is returned outside the enum.** It is the one label bex emits that the enum doesn't list, and `container` was removed for exactly that reason (w3/m272).

Settle both from t001's Render capture and make REST, GraphQL and MCP return that label set.

## Context

- **Found:** live `/qa-find-bugs w4` loop, round 130, 2026-11-11 19:12 UTC (`bex-canary`, pin `f609163ada8e`).
  - Fixture: Free web service `qa-20261111-r130-logs` (`srv-dbqbq8o3u30c73cf96tg`, `bex-co/bex` `examples/hello-go`). It was deleted afterwards.
  - `GET /v1/logs?ownerId=tea-daif693dqjvc73e7as3g&resource=srv-dbqbq8o3u30c73cf96tg&type=request&method=POST&startTime=<now-15m>` returned one entry. Its labels were exactly `type=request`, `resource=srv-dbqbq8o3u30c73cf96tg`, `method=POST`, `statusCode=200` and `requestID=<uuid>`.
  - The filters work on the same lines:
    - `host=qa-20261111-r130-logs.onbex.co` → 5 lines, `host=nope.onbex.co` → 0;
    - `path=/qa-r130-alpha` → 1;
    - `statusCode=2xx` → 5, `4xx` → 0;
    - `text=<requestID>` → the one HEAD line;
    - `/v1/logs/values?label=host` → `["qa-20261111-r130-logs.onbex.co"]`.
- **Render's pinned contract.** In `lego/backend/internal/api/openapi/render-public-api-1.json`, the `/logs` log object's `labels[].name` enum is `resource, instance, host, statusCode, method, level, workflowService, workflowVeresion, task, taskRun, sandbox, type, text, path, blocked`.
  - `host` and `path` are in it; `requestID` and `container` are not.
  - w8/m125 cites render.com/docs/logging for `requestID` on request logs, so Render's live response may carry it beyond the pinned enum. That isn't captured.
- **Code:**
  - `renderLabels` (`lego/backend/internal/logs/render.go:40-48`) is the ordered REST label list. It has no `host` or `path`.
  - `LabelHost` is deliberately not a stream label (`logs/service.go:99-113`); the host and path filters parse the line (`lokiQueryFor`, `logs/loki.go:559`).
  - `requestID` is read from the line by `requestLineID` (`logs/loki.go:732`) and exposed as GraphQL `requestId` (`logs/graphql.go:46`).
  - The `container` removal, with its "closed enum" reasoning, is noted at `render.go:39`.

## Steps

1. From t001's capture (a Render request-log entry from its API, log stream or docs, with its source), record which label names a Render request line carries.
2. **`host` and `path`.** If Render carries them, add them for `type=request` lines only, with values from the line's `RequestHost`/`RequestPath`. Read them where `requestLineID` already parses the line. Never make them Loki stream labels (ADR010 § cardinality). GraphQL and MCP `list_logs` get the same fields.
3. **`requestID`.**
   - If the capture shows Render returning it, keep it, and record in ADR010 § Request correlation that the pinned enum is narrower than Render's live response.
   - If it doesn't, keep it as a recorded bex superset in ADR018, or drop it like `container` for the same closed-enum reason. Choose by Render-parity first ([ADR008](../../../../docs/ADR008-vision.md#render-parity-first)).
4. Tests in `logs/`: a request line's REST labels are exactly the decided set; an app line keeps `type`, `resource`, `instance` and `level` only.
