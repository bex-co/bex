## Objective

Make the port reachable from the dashboard: settable in the create wizard for the port-binding service types, editable afterwards in Settings, and linked from the inline `PORT` refusal so the sentence "change the service port instead" resolves to a control the reader can click.

## Context

- No file under `dashboard/src` reads or writes a service port today. The wizard's `CreateService` variables captured live on 2026-09-21 were `{image, name, type, registryCredentialId, runtime, plan, ownerId}` — no `port`.
- `/services/<id>/settings` renders eight sections (General, Source, Custom Domains, Networking, Image registry credential, Notifications, Health Checks, Maintenance Mode, Deploy Hook, Suspend, Danger Zone); its full `innerText` contains exactly one occurrence of "port", inside the Health Check helper text.
- `dashboard/src/features/services/components/service-source-picker.tsx:35-36,282` — `showPortHint` already knows which types bind a port ("only the port-binding types ever get one"); `service-source-card.tsx:216` passes `showPortHint: false`. Reuse that predicate for the new control rather than adding a second type list.
- `dashboard/src/features/services/locales/en.ts:2798` — `services.createImagePortHint`, "The container must listen on `$PORT` (default 3000) and cannot bind ports below 1024." The default-3000 claim becomes editable state once this task lands; the sub-1024 hardening claim stays and the control must enforce it.
- The refusal text lives in two places: `dashboard/src/features/services/locales/en.ts:740` (service Environment tab) and `dashboard/src/features/env-groups/locales/en.ts:43` (env-group editor); the gate is `dashboard/src/features/services/lib/environment-draft.ts:5-7` with the rationale comment at `components/create-env-var-editor.tsx:56`. Both editors must link, and the env-group editor's link has to cope with a group linked to many services — decide what it points at and say so.
- Mirror every string into `locales/zh.ts`; `zh.ts:2742` already carries the image port hint.

## Steps

1. Add a port field to the create wizard for the types `showPortHint` already identifies, defaulting to `3000`, refusing `< 1024` and `> 65535` inline, and sending it as the `port` argument on `CreateService`.
2. Add a port control to the service Settings page — placement next to Health Checks, which is the other routing-adjacent setting — calling t001's update verb and surfacing that it opens a deploy.
3. Render the port on the service detail header's metadata row (or state why not), so a service created through the API with a non-default port is not invisible in the UI.
4. Turn "change the service port instead" into a link to the Settings control in both editors; in the create wizard's env step, point at the wizard's own new field.
5. Hide the control entirely for `background_worker`, `cron_job` and `static_site` — the same types `showPortHint` excludes.
