## Objective

Give route matching Render's wildcard rule: each `*` in a source matches any string (including `/`) from its position, while header matching keeps its own rules.

## Context

- `lego/operator/internal/staticserver/staticserver.go`: `matchPattern` (`:898-909`), `matchRoutePattern` (`:916`, used at `:874`), `matchHeaderPattern` (`:1095-1106`, falls back to `matchPattern`).
- w8/325: `/x/*` never matches the bare `/x`. w4/m240: `:name` placeholders.
- Path size bounds already in the server; keep matching linear or bounded.

## Steps

1. Implement a bounded wildcard matcher for route sources that captures the `*` span(s) and still honors `:name` segments.
2. Use it in `matchRoutePattern` only; leave `matchPattern`'s behavior for the header fallback unchanged, or give headers their own copy.
3. Table-test `/blog*`, `/*/feed`, `/*.html`, `/x/*` vs `/x`, and a placeholder next to a `*`.

## Files

- `lego/operator/internal/staticserver/staticserver.go` and its tests

## Acceptance criteria

- [ ] `/blog*` matches `/blog`, `/blog-post` and `/blog/2024/x`; `/*.html` matches `/a/b.html`; `/x/*` does not match `/x` (test).
- [ ] Every existing header pattern test passes unchanged (test).

## Out of scope

- Header pattern syntax beyond Render's five documented forms.
