## Objective

Extend the idempotent auth bootstrap so every local and production environment has exactly one Hydra public client with Render's fixed id `429024F5E608930E2A65EF92591A25CC`.

## Context

The official CLI hard-codes this id. Configure `token_endpoint_auth_method=none`, device-code + refresh-token grants, and the scopes needed for identity plus `offline_access`. The registration is permanent and has no secret; normal access-token TTLs remain unchanged. Keep it separate from `scripts/auth-bootstrap-client.sh`'s confidential machine client and from tenant API-key records.

## Files

- `scripts/auth-bootstrap-client.sh` or a focused sibling bootstrap script
- `deploy/gitops/base/values/hydra.values.yaml`
- local auth harness bootstrap under `.pm/w4/dev-4/`
- `docs/ADR012-auth.md`

## Acceptance criteria

- [ ] Bootstrap create/update is idempotent; the exact fixed id exists once in local and production Hydra with no secret and the required grants/scopes.
- [ ] Re-running bootstrap preserves the client and does not mint or print credentials.
- [ ] The client is absent from `GET /v1/api-keys` and the dashboard API-key list.

## Out of scope

- Compatibility HTTP routes and browser authorization (t002–t003).
- Changing access-token TTLs or existing API-key clients.
