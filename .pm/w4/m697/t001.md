## Objective

Change the `routes` and `headers` appliers so a declared list modifies and adds rules and keeps the live rules it does not name, as Render's Blueprint spec says.

## Context

- `lego/backend/internal/apps/blueprint_plan.go:319-320`: the appliers in `blueprintServiceFieldAppliers`; `canonicalSlice` (`:124-129`) keeps an empty list nil.
- The spec types: `appv1alpha1.AppSpec.Routes` and `.Headers` (`lego/types/v1alpha1/`).
- Matching key (recommendation): routes by `type` + `source`, headers by `path` + `name`.

## Steps

1. Write a merge for each list: for each declared rule, replace the live rule with the same key in place, or append it; keep every other live rule in its current order.
2. Use it in both appliers; a declared empty list leaves the live list as it is.
3. Keep `canonicalSlice`'s nil/empty rule so an unchanged merge compares equal.

## Files

- `lego/backend/internal/apps/blueprint_plan.go` and its tests

## Acceptance criteria

- [ ] A live list `[A, B]` synced with a file declaring `[B', C]` (B' has B's key) becomes `[A, B', C]` (test).
- [ ] A file declaring `routes: []` leaves `[A, B]` (test). The same holds for headers (test).

## Out of scope

- Deleting a rule through a Blueprint, which Render does not document.
