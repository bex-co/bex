## Objective

Give every request that reaches a web service from a non-Cloudflare peer the Cloudflare headers a Render app receives, instead of removing them. A request from a genuine Cloudflare edge (a tenant custom domain behind its own Cloudflare proxy) keeps Cloudflare's values, as today.

## Context

- `deploy/gitops/charts/traefik-plugins/clientipheaders/clientipheaders.go`:88-95 lists `cf-connecting-ip`, `cf-ipcountry`, `cf-ray`, `cf-visitor` … as headers that survive only from a Cloudflare peer, and removes them otherwise; Rndr-Id and X-Request-Start are set at :177-185.
- w8/m123 (done) chose "absent" for these headers on a non-Cloudflare peer; [ADR022 § Client-identity headers](../../../docs/ADR022-tenant-isolation.md#client-identity-headers-a-tenant-app-receives-w8m123) records it. Under [ADR008 § Render parity first](../../../docs/ADR008-vision.md#render-parity-first) that choice is amended here, not preserved.
- Without the header, a PocketBase app configured as Render's article says reads no client address, and its rate limiter and logs key on the Traefik pod's address for every user.
- `core/proxiedhosts.go` holds the Cloudflare ranges the plugin trusts; `scripts/gitops-validate.sh` fails when the two drift.

## Steps

1. `CF-Connecting-IP`: the same address as `True-Client-IP` (the TCP peer after PROXY protocol).
2. `CF-Visitor`: `{"scheme":"https"}` or `{"scheme":"http"}` from the TLS state.
3. `CF-Ray`: 16 lowercase hex characters, `-`, and a three-letter code from configuration. Recommended: the IATA code of the nearest Cloudflare data center for the region (`FRA` for fsn1 and nbg1, `HEL` for hel1). Derive it from the same random value as `Rndr-Id` if that keeps one source of randomness.
4. `CDN-Loop: cloudflare; loops=1`, as the app on Render receives.
5. Keep the trusted-Cloudflare-peer branch unchanged, and keep `True-Client-IP`, `Rndr-Id`, `X-Request-Start` and `X-Forwarded-*` behavior as they are.

## Acceptance criteria

- [ ] A request from a non-Cloudflare peer reaches the app with the four headers in t001's shapes, whatever the caller sent in `CF-Visitor`, `CF-Ray` or `CDN-Loop`.
- [ ] A request from a pinned Cloudflare range with a valid `CF-Connecting-IP` reaches the app with Cloudflare's own values.

## Out of scope

- `CF-IPCountry` (t003), the 403 (t004), response headers (t005).
