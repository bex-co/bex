## Objective

Answer with the response headers Render's edge adds: `cf-ray` equal to the request's `CF-Ray`, and `cf-cache-status: DYNAMIC` on a web-service response the edge did not cache.

## Context

- Render's answer carried `cf-ray` and `cf-cache-status: DYNAMIC` on a service with no edge caching (t001). bex's edge cache already reports `CF-Cache-Status` HIT/MISS/EXPIRED/BYPASS/DYNAMIC for a service with a caching profile (`docs/ADR018/services-lifecycle.md`, Edge caching row).
- `server: cloudflare`: Render sends it because its edge is Cloudflare; bex's is not. The parity-sufficient choice is to send it; the alternative (keep no `Server`, as now) is a divergence that needs the user's sign-off in the ADR018 row.

## Steps

1. Set `cf-ray` on every tenant response to the request's `CF-Ray`.
2. Set `cf-cache-status: DYNAMIC` on a web-service response that carries no `CF-Cache-Status` from the edge cache.
3. Decide `server: cloudflare` as the parity rule says: send it, and record the choice; if the user signs off keeping no `Server`, record that divergence in the ADR018 row instead.
