## Objective

Pin the contract-vs-decoder agreement and the cross-surface agreement, so neither can drift back silently.

## Context

The defect was invisible to the existing suite because nothing asserted that a **schema-conformant body actually works** — only that malformed bodies are rejected (`w7/m49`'s goal). The missing assertion is the positive one.

The cross-surface control is what made this diagnosable: GraphQL `setAutoscaling` stored the config while REST `PUT` could not, on the same service seconds apart. That pair belongs in the suite.

## Steps

1. For autoscaling: a test that the exact pinned-schema body returns 200 and the stored spec matches; plus the negative cases with their field pointers.
2. A cross-surface test: the same intent through REST and GraphQL yields the same stored `AutoscalingSpec`. `internal/api`'s existing `TestSurfaceParityAndWiring` is the natural neighbour.
3. For each route t002 reclassified, a positive schema-conformant-body test. These are the assertions that would have caught all three known instances.
4. Keep MCP honest: if t001/`w4/m101/t001` establish whether an MCP setter exists, assert its behavior too; if it genuinely has none, assert that the delete-only surface is deliberate so a future reader does not treat it as an oversight.
