## Objective

Three routes have now been found where the pinned OpenAPI validator and the handler's decoder want different bodies, each discovered by QA rather than by a test. Audit the whole surface once instead of waiting for the fourth.

## Context

- `w7/m49` (done) mounted the strict, offline, pinned Render OpenAPI validator in front of the authenticated REST handlers. Its own goal was that "malformed and unknown input is rejected before side effects" — which it does. What it did not check is that a body the contract **accepts** is a body the handler can **read**.
- Instances found so far, all by live QA: `w4/038` (`GET /v1/projects`, opaque 400 on a spec-legal missing `ownerId`), `w4/041` (`POST /v1/projects`, opaque 400 on the Render-required `environments` field — "bex's own pinned contract advertises `environments` as acceptable"), and now autoscaling (t001), where **no** body satisfies both layers.
- Surface size, measured 2026-09-13: bex has **24** `DecodeBody[…]` sites across six REST adapters — `apps`, `envgroups`, `secrets`, `environments`, `projects`, `notifications` (`grep -rn "DecodeBody\[" lego/backend/internal/*/rest.go | grep -v _test | wc -l`). Render's pinned spec carries a `requestBody` on **58** paths. The audit surface is the intersection: every route bex implements that the validator gates.

## Steps

1. Enumerate the intersection mechanically rather than by eye: for each gated route, extract the pinned schema's required properties and compare them to the JSON tags of the struct the handler decodes. A small test or script that reports disagreements is worth more than a one-off spreadsheet, because it keeps working — consider landing it as a test so a future schema re-pin or struct rename fails loudly.
2. For each disagreement, classify: (a) handler should adopt the contract's shape (the `w4/041` precedent), (b) contract legitimately differs because the route is a bex extension outside Render's spec, or (c) the route is unreachable/unused. Record the classification per route.
3. Fix the (a) cases or file them, depending on count and risk. Say which you did and why.
4. Check the **response** direction too, at least for the routes you touch: a handler can answer in a shape the pinned contract does not describe, which breaks generated clients just as badly (autoscaling's `renderAutoscaling` is one candidate — see t001 step 4).
