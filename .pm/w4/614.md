# 614 — The Metrics page's Network filters cut off their own values: Percentile "p99" and "p90" both read "p9", Status Code "All" reads "A", and Group by "Status code" reads "Status"

Why: these triggers are the only place that shows which percentile, status class or grouping the chart is drawn with. In English the value is clipped mid-word, so p90 and p99 are indistinguishable and the user can't tell what the latency chart shows without opening the menu.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 227, 2026-11-12 20:15–20:20 UTC (`muse.env`, workspace `bex-canary`; pin `33e1b1e6117c`). **Minor** (cosmetic, but it hides state). ~15m.
- **Probe:** on `/services/srv-dbr1o22585js73afgigg/metrics` (any service's Metrics page; the fixture was a Starter background worker, deleted afterwards), viewport 1600×1000, en. For each `main button[role=combobox]`, the value span `[data-slot=select-value]` was measured as `clientWidth/scrollWidth`:

  | Trigger | Visible text | value width / needed | Trigger width |
  | --- | --- | --- | --- |
  | Status Code = All | "Status Code A" | 7 / 16 px | 142 px (`w-36`) |
  | Host = All | "Host All" | 16 / 16 px (fits) | 142 px (`w-36`) |
  | Group by = All requests | "Group by All req" | 43 / 76 px | 158 px (`w-40`) |
  | Group by = Status code | "Group by Status" | 43 / 77 px | 158 px |
  | Percentile = p90, p99 | "Percentile p9" (last digit cut) | 22 / 26 px | 142 px (`w-36`) |

  - The page's other triggers fit: Filter events 63/63, Time range 86/86.
  - In zh every trigger fits (状态码 28/28, 分组 56/56, 百分位 26/26).
  - Screenshots: `.playwright-mcp/qa-r227-percentile-p99.png`, `qa-r227-statuscode-all.png`, `qa-r227-groupby-status.png`, `qa-r227-metrics-clip.png`.
- **Root cause:**
  - `dashboard/src/features/metrics/components/network-metrics-card.tsx` gives each of its four label-prefixed triggers a fixed width: Status Code `className="w-36"` (`:227`), Host `w-36` (`:252`), Group by `h-7 w-40` (`:321`), Percentile `h-7 w-36` (`:367`).
  - Each trigger holds a muted label span, the `SelectValue` and the chevron.
  - The base `SelectTrigger` is `w-fit … whitespace-nowrap … *:data-[slot=select-value]:line-clamp-1` (`dashboard/src/common/components/ui/select.tsx:38`), so the fixed width wins and the value is clipped with no ellipsis.
- **Fix (target behavior):** each trigger shows its label and the full selected value.
  - Replace the fixed widths with the base `w-fit`, or keep a `min-w-36` for alignment.
  - Host can carry a long hostname, so give it `max-w-72` with an ellipsis and the full host in the trigger's `title`.
  - Keep the `aria-label`s.
- **Blast radius:** `grep -rn -B5 "<SelectValue" dashboard/src --include='*.tsx'` finds label-prefixed triggers only in this file (4). The Logs filter triggers were measured and fit: Log type "Application logs" 103/103, Level, Method, Status code and Instance all full.
- **Tests:** a `network-metrics-card` test asserting the triggers carry no fixed `w-36`/`w-40` width (or `min-w-*` only). Visual confirmation belongs to the live DoD.
- **Unverified:** a selected long Host value (the worker had none); widths below 1600 px.
- **Render:** n/a (cosmetic; Render's dashboard was not captured).
- **Dedupe:**
  - `grep -rliE "percentile.{0,80}(clip|cut|truncat)" .pm` finds nothing.
  - w4/446 (done, the last change to this file) fixed the event lane and instance box, not these triggers.
  - Not deploy lag: `git log 33e1b1e6117c..origin/main -- dashboard/src/features/metrics` is empty.
- **DoD (live):** on a web service's Metrics page at 1600 px and at 1024 px, in en and zh:
  - Percentile reads "p50", "p75", "p90", "p99" and "All" in full;
  - Status Code reads "All", "2xx", "4xx" and "5xx";
  - Group by reads "All requests", "Status code", "Method" and "Host";
  - a selected host shows in full or with an ellipsis and a title;
  - `value.clientWidth === value.scrollWidth` for every trigger except an ellipsized host.
