## Objective

Give the subscribe stream a second producer: a short-interval log-store (Loki) poll that emits new `type=request` entries, merged with the pod tail on the one stream. Request-only and mixed app+request subscriptions become subscribable; the acceptance rules fail closed exactly where no producer can honor the query.

## Context

- `lego/backend/internal/logs/service.go`: `tailSupports`/`liveSubscribable` (refusal), `followLogs` (app dispatch + producerless refusal), `followAppPods` (pod merge over one channel), `QueryLogs` (store read honoring every filter), `TailRelistInterval` + `tailRelistInterval()` (interval field pattern).
- `lego/backend/internal/logs/rest.go`: `logsSubscribe` pre-slot refusal via `liveSubscribable` (codex #3 — producerless subscriptions must never take a slot).
- Cursor discipline: `capToLimit` shares the w4/m107 rule — a timestamp cut inside a shared-timestamp group keeps the group whole. The poll cursor must neither drop nor duplicate a sibling at the boundary instant.
- Ship lag: the poll sees a line when the store has it; `shipper_lag_seconds` is the named place to look if a live replay measures the shipper, not the poll, dominating latency.

## Steps

1. Acceptance: a query is subscribable when every requested type/filter has a producer — request (with its structured filters, honored by the store query) alone or mixed with app/build and no store-only filters; store-only filters with app/build wanted stay refused, as do producerless types (`predeploy`). No store wired + request wanted fails closed before streaming headers.
2. Producer: on a short interval (Service field + default, test-shrinkable), query the store forward from a cursor at `Subscribe`'s `Since`/resume point, emit entries past the cursor, advance it. Enter it into the same merge channel the pod follows feed; app lines keep pod-tail behavior untouched.
3. Authz/lifetime: the poll rides the same revalidated ctx and subscription slot as the pod tail; the store query is scoped exactly as `QueryLogs` scopes it.

## Files

- `lego/backend/internal/logs/service.go`, `rest.go` (pre-slot check only if the acceptance seam requires it)

## Acceptance criteria

- [ ] `type=request` subscription streams new matching lines within one poll interval of them reaching the store; structured filters narrow it.
- [ ] Mixed app+request subscription emits both on one stream; app-only and build-only behavior unchanged.
- [ ] Boundary-instant siblings are emitted once each; resume (`Last-Event-ID`) does not replay emitted request lines.
- [ ] Producerless/store-filtered-app subscriptions still refused pre-slot; no store → failed closed before headers.

## Out of scope

- The Loki tail websocket API (poll reuses the authorized query path).
- Shipper ingest latency (measure and name it if it dominates; fixing it is its own item).

**Done 2026-10-19 (loopx w4).** `pollRequestLogs` joins the subscribe stream behind `followLogs`: every `RequestPollInterval` (2 s default, Service field like `TailRelistInterval`) it queries the store forward from an exactly-once cursor (`requestCursor`: newest emitted instant + identities emitted at it, w4/m107's group-whole rule) and feeds the same merge channel the pod follows feed, on the tail's revalidated ctx; a store error retries next tick like a failed pod re-list. The poll query is the subscription itself narrowed to `type=request` (structured filters, text, instance forwarded — the store applies them) with the scan window floored one minute back so a quiet subscription never re-scans its whole life. Acceptance split out of the old `tailSupports`: store-only filters are subscribable exactly for request-only queries; producerless types still refused pre-slot (codex #3); request-only with no store wired fails closed 503 in `FollowLogs` and pre-slot in `logsSubscribe`; mixed streams without a store still serve pod lines.
