# Audit Log dashboard placement — verify against Render's actual IA (Compliance, not Team-adjacent)

w4/m14 shipped the Audit Log panel on `/settings` directly below Team/API Keys, on the premise (stated in its own README) that "Render's own dashboard IA places Audit Log next to Team Members." Re-checked against Render's live docs while doing m14's t007 parity pass (render.com/docs/audit-logs, fetched 2026-07-11): that premise doesn't hold. Render's dashboard has **no in-app browsable audit-log table at all** — its only dashboard feature is a date-range **CSV export** button, located under **Workspace Settings → Compliance** (org-level logs live under the org's own Settings page instead), not anywhere near Team/Members.

Two things worth a look, neither blocking m14's DoD:

1. **IA placement.** bex's interactive, paginated Audit Log card lives beside Team/API Keys today. Whether that's the right long-term home, or whether it should move under a dedicated "Compliance"/"Security" grouping (there's already a whiff of this with w4/006's planned Settings→Security card for session management) is a product call, not a bug — flagging so it's a deliberate choice next time Settings gets restructured, not an accident of a mistaken premise.
2. **The panel itself is a genuine bex-ahead-of-Render superset**, not a parity mirror — Render gives operators a CSV they open elsewhere; bex gives an in-app, paginated, live table. Recorded in `docs/render-parity.md`'s "bex ahead of Render" section (t007) — no code change needed for that half.

**Promote to a milestone only if** the IA-placement question above is resolved as "yes, move it" — the move itself is a >1h dashboard-layout task (new Settings section/grouping), not a sub-hour fix.

Source: w4/m14 t007 (render-parity check), 2026-07-11 — drift found comparing the shipped panel against Render's actual (not assumed) dashboard behavior.
