## Objective

Confirm the settled phase reads the same on every surface and matches what Render shows for a service whose first deploy crash-loops.

## Context

- `phase` is projected on REST (`GET /v1/services/{id}`), GraphQL (`server(id:){ phase }`), MCP, and drives the dashboard header badge — all four showed `Deploying` during this run's observation, so all four must show the settled state.
- Render's equivalent: a service whose first deploy fails health checks shows a **failed** deploy and a service status that does not claim progress. Whether Render's header reads "Failed" or something softer is not captured in `docs/render-artifacts/` — if the fix leans on it, capture it there rather than asserting from memory.
- `docs/ADR018-render-parity.md` and `docs/ADR004-app-deployment.md` are the rows to update.

## Steps

1. Diff `phase` across REST, GraphQL and MCP for a crash-looped fixture; confirm identical values.
2. Confirm the dashboard header badge and the resource list's Status column both show it (the overview table has its own Status cell).
3. Capture Render's behavior into `docs/render-artifacts/` if the fix depends on it; otherwise record that bex's choice is a deliberate, reasoned one.
4. Update the ADR rows; file residual drift as a w4 note.
