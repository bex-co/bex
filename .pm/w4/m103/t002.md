## Objective

The phase taxonomy has five neighbours around the case t001 fixes, and two prior milestones exist because a fix in this area changed the wrong one. Pin every neighbour.

## Context

`lego/types/v1alpha1/app_types.go:1127-1149` is the taxonomy. The cases that must each land somewhere stated and tested:

| case | expected phase | precedent |
| --- | --- | --- |
| rollout fails, **no** prior release | t001's decision | this milestone |
| rollout fails, healthy prior release | the state describing what is serving (`Running`, or `Hibernated` when parked) | `w6/m124`'s `settleFailedBuildOverPriorRelease` |
| build fails, no prior release | `PhaseFailed` | `w6/m124` DoD ("first-build-fails control reports Failed") |
| build fails, prior release | unchanged, deploy fact only | `w6/m124` |
| user cancels first-ever deploy | `PhaseCanceled` | `w6/m52` |
| pre-deploy command fails | via `failPreDeploy` → `fail` → `PhaseFailed` | `app_controller.go:4434-4438` |
| suspended / free-tier hibernated | `Hibernated`, never swept into "running" | `settleFailedBuildOverPriorRelease`'s comment |

The last row carries a hard constraint: `.pm/DO_NOT_DO.md`'s auto-hibernate item (the deleted `w6/m120`) forbids "fixing" free-tier wake/sleep flapping by suppressing real wakes. A phase change must not touch the `Hibernated ⇄ Running` edges or the `service_woken` / `service_hibernated` facts.

## Steps

1. Write one test per row, asserting the phase and — where the row says so — that the deploy row still carries the failure independently.
2. Check the availability projection: bex-api derives service availability/readiness from phase + conditions. Confirm t001's new terminal phase does not make a *serving* service look down anywhere (`internal/store`'s projection and the `Ready` condition are the seam `settleFailedBuildOverPriorRelease` already guards).
3. Confirm the free-tier paths are untouched: an auto-hibernated service still reads `Hibernated`, and waking still works.
