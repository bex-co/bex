## Objective

Implement `ECHOPRT` in gVisor's `devpts` line discipline so canonical erasures (`VERASE`, `VWERASE`, `VKILL`) echo `\`, each erased character, and a closing `/` when typing resumes or the line completes, matching Linux's `n_tty`.

## Context

- `bex-co/gvisor`: `pkg/sentry/fsimpl/devpts/line_discipline.go:789-790` currently has `if l.termios.LEnabled(linux.ECHOPRT) { // Not implemented }`.
- Recorded in `docs/ADR104-sandbox-render-parity.md` § Terminals in a sandbox and `docs/ADR018-render-parity.md` as one of the three differences left by `w4/m574`'s 71-case harness.
- Verify Linux `n_tty`'s exact `ECHOPRT` transitions (`erasing` flag, `finish_erasing()`): starting on first erase (`\`), erasing multiple chars (including control chars and tabs), erasing down to an empty line, typing a new character (`/` before the echoed char), `VREPRINT`, newline/EOF, `VKILL` with `ECHOK`/`ECHOKE`, signal flush, and clearing `ICANON` or `ECHOPRT`.

## Steps

1. Measure native Linux's exact echo bytes for `ECHOPRT` across `VERASE`, `VWERASE`, `VKILL`, `VREPRINT`, newline, empty-line erase, and signal flush.
2. Implement `erasing` state (with `stateify` support) and `ECHOPRT` echo in `pkg/sentry/fsimpl/devpts/line_discipline.go`.
3. Add `test/syscalls/linux/pty.cc` and `devpts` unit tests; verify pass on native Linux and patched `runsc`, and failure with only this fix reverted.
