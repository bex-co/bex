# 419 — Environment group names accept control characters and unbounded length

Why: every other resource's name follows `core.CheckLabel` (no control characters or line separators, at most 100 code points; w8/034 closed this for service renames), but an environment group can be named `"line1\nline2"`, `"bell\aend"` or a 5,000-character string. These names then render in the dashboard, the CLI, Blueprints (`fromGroup:`) and every list.

**Severity:** minor (input hygiene; such names break list layouts and `fromGroup` references and can mislead in a table). **Estimate:** ~30m. **Source:** live `/qa-find-bugs w4` loop run 758c, 2026-10-26 UTC (`muse.env`, `bex-canary`, pin `b4726243e74f`), REST through the run's session jar. All nine owned groups were deleted (`DELETE` 204, `GET` 404).

## Probes

`POST https://api.bex.co/v1/env-groups {"name":<N>,"ownerId":"tea-daif693dqjvc73e7as3g","envVars":[{"key":"A","value":"1"}]}`:

| `name` | Answer | Stored name (list read) |
| --- | --- | --- |
| `""`, `" "` | `400` "env group name is required" | — |
| `" pad "` | `201` | `pad` (trimmed) |
| `"line1\nline2"` | `201` | `line1\nline2` |
| `"tab\tsep"` | `201` | `tab\tsep` |
| `"bell\u0007end"` | `201` | `bell\x07end` |
| `"g"×101` | `201` | 101 code points |
| `"z"×5000` | `201` | 5,000 code points |

Control: a service create or rename with the same names is refused by `core.CheckLabel` (`DISPLAY_NAME_CONTROL_CHARACTER` / `DISPLAY_NAME_TOO_LONG`, `core/errors.go:368-380`). The response JSON itself is correctly escaped.

## Root cause

The three env-group name writers check only `strings.TrimSpace` + non-empty, never `core.CheckLabel`:

- create, `lego/backend/internal/envgroups/service.go:423-426`
- rename, `:752-756`
- Blueprint `envVarGroups` apply, `:1404-1408`

## Fix (target behavior)

- Run `core.CheckLabel` in all three writers, after the existing trim and required-name check: refuse control characters and line separators with `DISPLAY_NAME_CONTROL_CHARACTER`, and names over 100 code points with `DISPLAY_NAME_TOO_LONG`.
- REST, GraphQL (`createEnvGroup` / rename), MCP and Blueprint validate/apply all go through these, so they move together. Blueprint validate should report the refusal at `envVarGroups[N].name`.
- Existing groups with such names: inventory them (production likely has none outside QA) and decide rename vs grandfather; reads must not break.

## Tests
