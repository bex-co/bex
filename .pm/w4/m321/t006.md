## Objective

REST, GraphQL, MCP and the dashboard agree on the new audit rules and match Render's documented audit log.

## Steps

1. **Same vocabulary everywhere.**
   - REST `event` and GraphQL `event` (and its `action`) carry the same event names for the same rows.
   - The CSV export carries the same rows as REST for the window.
   - The dashboard table renders the new events readably in en and zh.
2. **Compare with [render.com/docs/audit-logs](https://render.com/docs/audit-logs).**
   - Decide `StartShellEvent` and `EndShellEvent` for SSH and the web shell (ADR035), and whether secret-file content reads map to `ViewEnvVarValuesEvent`.
   - Record a decision or a follow-up for each; do not silently leave them out.
3. Run the REST response validator against the pinned `auditLog` schema for rows carrying the two new events.

## Acceptance criteria

- [ ] The surfaces agree, and the open Render read events each have a recorded decision or a filed follow-up.
