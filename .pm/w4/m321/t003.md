## Objective

Every successful connection-info read of a Postgres or Key Value records one `ViewConnectionInfoEvent`, with metadata naming the datastore. This is Render's event, which "tracks access to database connection URLs and passwords for both Postgres and Key Value instances".

## Context

- **The two verbs:**
  - `postgres.PostgresConnectionInfo` (`lego/backend/internal/postgres/service.go:1035`): REST `GET /v1/postgres/{id}/connection-info`, GraphQL, MCP, and the dashboard's reveal;
  - `keyvalue.KeyValueConnectionInfo` (`lego/backend/internal/keyvalue/service.go:1288`): REST `GET /v1/key-value/{id}/connection-info`, GraphQL, MCP, and the dashboard's "Reveal connection info".
- **Live:** `GET /v1/key-value/red-dbprkhfbq3ic73c0a7f0/connection-info` at 00:44:26Z and the dashboard reveal at ~00:44:34Z left no row.
- **Postgres credentials.** Check whether the Postgres credentials list (`postgres.ListUsers` or similar) also returns passwords. If it does, it records the same event.

## Steps

1. Add the event to `renderEvents` and a typed recorder, shared with t002's pattern.
2. Call it after the fresh re-authorization in both verbs, with metadata `postgres: <dpg-id>` or `keyvalue: <red-id>` plus `targetName`.
