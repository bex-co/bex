# Static UTF-8 text renders with the wrong charset

Why: an ordinary UTF-8 text file publishes successfully and retains its bytes, but visitors see garbled characters unless the owner adds a charset header.

**Severity:** minor. **Estimate:** 55m. Functional `$qa-find-bugs w4`, a895, 2026-10-17 UTC. Research HEAD `2a409e808edb19cf05756d2f071f80f061e80336`; filing only. Advances [ADR008](../../docs/ADR008-vision.md)'s usable hosting and [ADR029](../../docs/ADR029-static-sites.md)'s static publication contract.

## Cause and bounded correction

- `lego/operator/internal/publish/publish.go:48–52,442–451` pins AWS CLI **2.22.35** and runs `aws s3 sync` with default MIME guessing. The exact pinned uploader digest was also observed on this fixture's successful publish Job. At that tag, `s3handler.py:345–348` installs `ProvideUploadContentTypeSubscriber`, `subscribers.py:133–136` places the guessed MIME in `ContentType`, and `utils.py:335–336` uses `mimetypes.guess_type(...)[0]`. This supplies the media type without declaring a text charset.
- The pinned Go S3 SDK **1.107.3**, actual GetObject output deserializer `deserializers.go:6911–6913`, trims and copies that header. `lego/operator/internal/staticserver/s3origin.go:91–119` buffers the bounded body and copies its MIME into `Object.ContentType` unchanged.
- `lego/operator/internal/staticserver/staticserver.go:712–724` prefers any populated non-octet-stream origin MIME. Thus `text/plain` bypasses the MIME-by-extension fallback that can supply UTF-8. `serveObject:366–370` sets that value on the response, then applies the owner's custom headers. The observed header controls clear this exact consumer; they do not repair damaged bytes.

**Target:** a successfully fetched, unencoded, valid UTF-8 `text/plain` object with no declared charset should default to `text/plain; charset=utf-8`. Keep its bytes unchanged. Normalize this narrow case once after a successful bounded S3 body read, before the Object enters the immutable cache; a small helper at `S3Origin.Get` can parse the MIME parameters and check `utf8.Valid(body)`. Do not rescan the entire object on each GET, force UTF-8 onto invalid UTF-8/legacy bytes, replace an explicit charset, or change other MIME types. Preserve other MIME parameters and existing malformed/empty/octet-stream handling. The Object and SDK fields are strings, so this needs no API schema or type expansion.

Custom Content-Type rules must continue to win after normalization. `encoding.go:79–101` ignores MIME parameters when choosing eligible automatic encoding; preserve that behavior. Keep current byte ranges, saved-ETag preconditions, cache policy, body framing and resolved-error responses.

**Shared scope:** one production S3Origin construction and handler wiring (`cmd/staticserver/main.go:155–168`), one origin-fetch/cache insertion path (`staticserver.go:460–489`), and one serveObject MIME consumer (`:367`). Direct files, directory indexes, rewrites and implicit fallback share this static pipeline. Publisher staging has three branches (`publish.go:407–418`): image extraction, direct Git and retained publication; they converge on the same upload and serving path. REST/GraphQL/MCP/dashboard settings retain their existing shapes and header precedence. Web/private/worker/cron compute, PostgreSQL and Key Value handlers are outside this change.
