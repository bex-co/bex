## Objective

Make both remedy surfaces explain that a suspended Free service needs a resume for traffic and a paid plan for shell access. Resume must never be presented as sufficient to grant shell access.

## Context

`sshRemedy` checks suspension before plan and returns one suspension-only reason. Both production callers render that reason verbatim. The backend correctly retains its Free restriction after Resume.

## Steps

1. Add a combined Free/suspended reason before the suspension-only branch for the existing SSH-capable type family. Keep Resume as a lifecycle action with wording that names the remaining paid-plan requirement; an example is “This Free service is suspended. Resume it to restore service traffic. Shell access still requires a paid instance type.”
2. Keep the non-suspended Free plan remedy, supported paid suspension remedy, general unconfigured explanation, and unsupported-type exclusion. Preserve the existing backend gate and the `sshAddress` eligibility signal.
3. Update en and zh together, and check the actual Shell and Connect consumers rather than testing only a returned translation key.

## Acceptance criteria

- [ ] The combined state visibly names both blockers in Shell and Connect; Resume is described as restoring the service, not enabling Free SSH.
- [ ] Resuming retains `plan: free`, empty SSH address and the plan remedy; no fabricated command, shell ticket request or terminal is rendered.

## Out of scope

Changing plan eligibility, buying an upgrade, adding shell access to Free/cron/static/datastores, or changing native SSH/browser-shell authorization.
