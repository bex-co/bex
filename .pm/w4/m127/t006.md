## Objective

Pin the new guarantees with tests that fail against the pre-fix code, and protect the verbs that must keep working without a confirmation.

## Context

- The pre-fix behavior to encode as a failing test: `DROP TABLE` through `executeDatabaseQuery(allowWrites: true)` on a protected database succeeds today, as do `persistenceMode: "off"`, `allkeys_lru`, `failover` and `rename`.
- `w6/m37` already has protected-datastore tests; extend that file so the guarded set lives in one table rather than two.
- Table-driven is right here: t001 writes the set down, so the test can mirror it and a verb added later without a decision shows up as a gap.

## Steps

1. Table test over t001's datastore set: refused without the phrase, proceeds with it.
2. Data-plane test matching t001's answer — refusal for writable SQL, or an explicit assertion that it is deliberately allowed so the decision cannot be reversed silently.
3. Read-only regression: `Query` and `allowWrites: false` unaffected on a protected database.
4. Negative table: delete and suspend keep their existing behavior both directions.
5. `dryRun` on a guarded verb refuses rather than previewing.
6. Cross-surface test asserting the refusal payload is identical on REST/GraphQL/MCP.
