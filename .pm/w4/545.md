# 545 — The topbar "+ New" menu's accessible name is "New New"

Why: every screen-reader user who opens the global create menu hears "New New, menu" (zh "新建 新建"), on every page, because the label is rendered twice.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 15, 2026-11-10 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor** (accessibility copy). ~10m.
- **Probe:** on `/`, open the topbar New menu.
  - Chrome's own accessibility tree (CDP `Accessibility.getFullAXTree`) reports `role=menu`, `name="New New"`, with name source `aria-labelledby` pointing at the trigger.
  - Playwright's snapshot agrees: `menu "New New"`.
  - The trigger button itself is named "New".
- **Root cause:**
  - `dashboard/src/common/components/dashboard-layout/new-resource-menu.tsx:23-24` renders the label twice: `<span className="hidden sm:inline">` and `<span className="sr-only sm:hidden">`.
  - Radix labels the menu by the trigger. The menu's name is computed from the trigger's text through `aria-labelledby`, and that computation includes the `display:none` copy.
  - It is the only `sr-only <bp>:hidden` duplicate in `dashboard/src` (`grep -rnE 'className="sr-only [a-z0-9]+:hidden"'` count: 1).
- **Fix:** render one span, `className="sr-only sm:not-sr-only"`, so the button and the menu both read "New" at every width (zh "新建"). Add a test asserting the menu's accessible name.
- **Dedupe:** `grep -rlE "New New|sr-only sm:hidden|topbarNew" .pm` finds only w5/026 and w5/m47/t003. Both built the menu, and neither covers its name. `git log c12cd57facb1..origin/main` on the file is empty.
- **DoD (live):** at 1440 and 390 widths, the opened menu's name is "New" in the CDP accessibility tree, and the button still reads "New".
