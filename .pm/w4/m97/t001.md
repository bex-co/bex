## Objective

Make environment-group metadata mutations conditional on the state actually read, so two API replicas cannot silently replace each other's successful work.

## Context

- `service.go:1502` and `service.go:1650` persist full metadata snapshots; content and metadata currently use different concurrency boundaries.
- `tenant.go` and `core.VersionedSecretKV` supply the workspace-scoped versioned-store seam.

## Steps

1. Introduce the smallest shared conditional metadata mutation primitive using the existing versioned store; refresh current state before deciding or retrying a mutation.
2. Preserve workspace/legacy lookup behavior and distinguish an absent or deleted group from an editable group.
3. Return bounded, public conflict errors when an operation cannot safely merge; retain timestamps and content revision semantics.

## Files

- `lego/backend/internal/envgroups/service.go`
- `lego/backend/internal/envgroups/tenant.go`
- `lego/backend/internal/envgroups/revision.go`

## Acceptance criteria

- [ ] Two mutations based on the same metadata version cannot both overwrite the whole map successfully.
- [ ] Unrelated metadata changes survive an allowed retry; incompatible changes return a conflict.
- [ ] A delayed mutation does not recreate metadata for a deleted group; workspace attribution remains unchanged.

## Out of scope

- Crash-recovery records and stale-operation reclamation (m98).
- New storage systems or changes to the migration clean-window policy.
