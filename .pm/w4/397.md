# 397 — Blueprint validation drops the YAML parser's reason: every syntax error reads only "Blueprint is not valid YAML"

Why: a manifest author with a tab or a mis-indented key gets a line number and nothing else. The parser had already said "found a tab character that violates indentation" or "did not find expected '-' indicator", which is what tells them what to fix.

**Severity:** minor (developer experience on the validate/preview/apply error path). **Estimate:** ~20m. **Source:** live `/qa-find-bugs w4` loop run b8n4, 2026-10-23 UTC (`muse.env`, `bex-canary`, pin `fa8ac5bba24a`). The probes were all read-only `POST /v1/blueprints/validate` (multipart `ownerId` + `file`); nothing was created. Session revoked.

## Probe

| Manifest (abridged)                                                 | Response                                                                        | `yaml.v3` reason, dropped (local `yamlSyntaxLocation` probe) |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `services:\n  - type: web\n   name: bad-indent`                    | `{"code":"BLUEPRINT_YAML_SYNTAX","error":"Blueprint is not valid YAML","line":1,"column":1}` | `yaml: line 1: did not find expected '-' indicator`          |
| a `\t` before `runtime:` on line 4                                  | same message, `line 3`                                                          | `yaml: line 3: found a tab character that violates indentation` |
| unclosed `"` on line 3                                              | same message, `line 3`                                                          | `yaml: line 3: found unexpected end of stream`               |

Controls from the same run were all actionable: schema errors name the field and enum, duplicate keys and duplicate resource names give both locations, and an unknown field is named.

## Root cause

`lego/backend/internal/apps/blueprint_compiler.go:803-813` `parseBlueprintSource` replaces the decoder error with the fixed string "Blueprint is not valid YAML". `yamlSyntaxLocation` (`:927-943`) keeps only the line. The line imprecision (row 1 says line 1 for a line-3 problem) is `yaml.v3`'s own report, not bex's.

## Fix

- Keep the code `BLUEPRINT_YAML_SYNTAX` and the line, and append the parser's reason with the `yaml: line N:` prefix stripped: "Blueprint is not valid YAML: found a tab character that violates indentation".
- `yaml.v3` reasons don't echo manifest content, but confirm that, so no secret value from the file can surface.
- Update the compiler test that pins the message. The dashboard's Blueprint error lists (w4/151) show the new text without change.
