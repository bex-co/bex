# 388 — A stock image that listens on its declared port (nginx on 80) never goes live, because web services ignore the image's port and wait on 10000

Why: since `f53f623e5`, a web service created without a port defaults to Render's `PORT` 10000. bex then health-checks only that port. A public image that ignores `$PORT` and listens on the port it declares, as `nginx:alpine` and `httpd` do with `EXPOSE 80`, stalls in `update_in_progress` and fails at the 15-minute rollout limit. Render documents `PORT=10000` but also routes to the port a web service actually binds when that is a different one (unverified here). bex has the image's declared port in its metadata and does not use it for web services.

**Severity:** major (a common journey fails: "deploy an existing image" with a stock web server image, without knowing to set a port). **Estimate:** ~1h. **Source:** live `/qa-find-bugs w4` loop run p0d3, 2026-10-22 UTC, `muse.env`, workspace `bex-canary`, pin `21652364739c`. Fixture: `qa-20261022-p0d3-nginx` (`srv-dbctb2j4qics739psb50`), deleted in-run (404). The session was revoked.

## Probe

- `POST /v1/services {type: web_service, image: docker.io/library/nginx:alpine, plan: free, runtime: image}`, with no port and no `PORT` → `201`, `serviceDetails.port: 10000`.
- 90 s later the deploy reads `update_in_progress` with `stallReason`: "the container is running but its startup health check has not succeeded, so the rollout is waiting: a TCP connect to port 10000. Check that the path returns a 2xx or 3xx status on the service's own port — an unset Health Check Path falls back to a TCP connect…".
  - nginx is listening on 80, its declared `EXPOSE`.
  - The hint never mentions the port the process actually uses, or that setting `PORT`/the port to 80 would fix it.
- Control, from earlier runs on the same platform: the same image with `PORT=80` served `200` (loop k9v1/u5n2).

## Root cause

- `resolveImageNetwork` (`lego/operator/internal/controller/image_network.go:53-111`) reads the image's declared TCP ports (`registry.ReadImageConfig` → `metadata.TCPPorts`) only when `Spec.UsesImagePorts()` is true.
- `UsesImagePorts()` (`lego/types/v1alpha1/image_network.go:60-62`) is true only for **private services** in image port mode. Web services take `EffectivePort()`, which is the CRD default `10000` (`app_types.go:620`, `DefaultPort` `:927`).
- `ownImageReference` limits discovery to the service's own built repository, because "an arbitrary image host can never receive platform registry credentials". A **public** image's config is readable anonymously, so discovery for public images needs no platform credential.

## Fix (target behavior)

- A web service created from an image **without an explicit port** (neither `PORT` nor a `port` field set) serves on the image's declared TCP port when it declares exactly one. With several declared ports, prefer 10000 if declared, then the lowest. The resolved port appears in `serviceDetails.port`/`openPorts` once known, before or with the first deploy.
- **Unchanged cases:**
  - An image that declares no port keeps 10000.
  - An explicit port or `PORT` always wins (`w5/m149`).
  - Repo-built services are unchanged.
- **Discovery reads:**
  - Public image configs are read anonymously.
  - Private registries use only the service's own registry credential, never platform credentials.
  - A read failure falls back to 10000 and says so in the deploy's stall/failure text.
- **Stall hint:** when the TCP check waits on a port the image does not declare, name the declared port, for example "the image declares port 80; set the service port or PORT to 80".
- **Render parity:** record in ADR018/ADR041 whether this is parity (Render's port detection) or a bex rule (declared-port fallback). Render's exact detection is unverified here.
- **Blast radius:**
  - Existing services carry explicit ports (`f53f623e5`'s note) and must not move.
  - Apply the rule at create time (bex-api) or in the operator for new Apps only, and say which.
  - The dashboard's create form port hint (`dashboard/src/features/services/lib/port.ts`) must describe the same rule.

## Acceptance

- Live: `nginx:alpine` and `httpd:2.4-alpine` with no port reach `live` and serve 200 on Free. `traefik/whoami` with `WHOAMI_PORT_NUMBER=3000` and no port still waits on 10000, since it declares 80 while listening on 3000. Its hint names the declared port.
- Tests:
  - an operator test for declared-port selection on web services, with 0, 1 or many ports and an explicit override;
  - a test that a public-registry read uses no platform credential;
  - a test that existing Apps keep their port.
- Operator `make test`, backend `go test ./...` and `make lint` pass.

## Unverified

- Render's actual behavior for a stock nginx image with no `PORT`: either port detection or a failed deploy. There was no signed-in Render capture.
