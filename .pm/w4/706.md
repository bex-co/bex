# 706 — On a phone, the first org-tab navigation draws its pending frame without the Owner's parts: the skeleton reads the caller's role only from the workspace switcher's org list, and the switcher is not mounted below the sidebar breakpoint

Why: the root `AGENTS.md` rule says a pending skeleton previews the exact ready state at the same breakpoint, desktop and narrow mobile. The org pages' skeletons (w7/m464, w7/m466) draw an Owner's `New Workspace`, `Invite` and `Save` buttons and the Owner-only Audit Logs card only when they can find the caller's role. They look for it in one place: the `organizations` list that the sidebar's workspace switcher fetches. At 1440 the sidebar is always mounted, so the list is cached and the frames match. At 390 the sidebar is a closed `Sheet`, so the switcher never mounts and nothing fetches the list before the first org-tab click. On that first click the skeleton fires the list query itself, behind the same pending `/graphql` request, and draws the role-less frame.

- **Source / severity / estimate:** live `/qa-find-bugs w4` round 1092, 2026-11-18 01:45 UTC, pin `14eaa71b98e5`, org `org-cmgpjog5dlgngs3bk76a` (bex-canary; the QA user is its Owner). Read-only. **Minor:** a layout jump at phone width; no data is wrong. ~40m.

- **Cause:**
  - `dashboard/src/features/organizations/components/organization-route-skeletons.tsx:82-95`: `useCachedOrganization` takes `role` and `workspaces` only from `useOrganizations()` (`:86`), which is the `organizations` list query, `cache-first`.
  - Each Owner part branches on that role: Workspaces `New Workspace` (`:126`), Members `Invite` (`:221`), Settings `Save` and the Owners-only note (`:265`, `:271`), and the Audit Logs card (`:279`).
  - `useOrganizations` has two callers. One is `features/workspaces/components/workspace-switcher.tsx:124`, mounted by `common/components/dashboard-layout/sidebar-brand.tsx:35` inside the sidebar. The other is the skeleton.
  - Below the sidebar breakpoint, `common/components/ui/sidebar.tsx:254-256` renders the sidebar as a `Sheet` that is closed until the menu button is tapped, so the switcher is not mounted.
  - The org page's own reads (`Organization`, which carries `viewerRole` and `workspaces`) do not fill the `organizations` list field. So even an org page that has already loaded its org gives the next tab's skeleton nothing to read.
  - `features/organizations/lib/organization-route-loader.ts:46-52` reads the role the same way (`readQuery({ query: OrganizationsDocument })`). At 390 an Owner's Members entry therefore does not prime `OrganizationInvites` (`:63`); the page fetches it after mount instead.
- **Fix:**
  - Target behavior: at every width, an org page's pending frame draws the caller's role shape whenever the client already knows that role. For an Owner that means the reserved `New Workspace` / `Invite` / `Save` boxes and the Audit Logs frame; for a Member the Owners-only note; for a Guest the forbidden panel. The Members loader primes invites from the same role.
  - Read the role from the org itself first, then the list. Every org page's loader fetches `organization(id)` (`OrganizationFields` has `viewerRole` and `workspaces`). So `useCachedOrganization` and the loader should read that cache entry (`readQuery({ query: OrganizationDocument, variables: { id } })`) before falling back to the `organizations` list. Moving from one org tab to another then always has the role.
  - Fetch the `organizations` list from a component that mounts at every width, for example the dashboard layout shell rather than only the switcher, still `cache-first`. That gives a first entry from a non-org page on a phone (for example Workspace Settings' "Required by <org>" link, w7/m466) the role as early as on desktop.
  - Pre-settle state: if neither source has the role yet, the frame keeps today's role-less shape. With the shell fetch, that only happens on a cold cache before the list answers.
  - Tests: `src/test/setup.ts:86` mocks `useOrganizations` to `[]` for every test, and `__tests__/org-fixtures.tsx`'s `pageStructure` supplies a role, so no test renders a skeleton with an empty list while the org entry knows the role. Add that case for each of the three skeletons and for the loader's invites priming. Also assert that the list query mounts with the sidebar closed.
- **Blast radius:**
  - `useCachedOrganization` serves three skeletons: Workspaces, Members and Settings.
  - `useOrganizations` has two callers, the switcher and the skeleton. `readQuery(OrganizationsDocument)` has one, the loader at `:49`.
  - The switcher's own grouping keeps reading the list unchanged. The desktop frames already match, and they need a regression test so the new read order keeps them as they are.
- **Adjacent classes:** a Member's or Guest's pending frame goes through the same role read. With no role, a Guest's Members pending frame shows the table frame where ready shows the forbidden panel. This was not probed, because the QA user is Owner of both its orgs. Nothing new is disclosed: the role read is the caller's own, from data the client already fetched.
