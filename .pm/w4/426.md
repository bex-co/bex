# A digest-pinned private image cached on a shared node may start for another workspace without its registry credential (code-traced; verify first)

Why: if it reproduces, workspace B can run workspace A's private image, with A's source, baked secrets and binaries, by naming its digest. The registry credential that should gate the pull is skipped because the image is already on the node.

Severity: **major if confirmed** (cross-tenant confidentiality); unverified. Estimate: ~1h (controlled repro on a dev cluster, then the fix). Source: live `/qa-find-bugs w4` loop run b929, 2026-10-27 UTC (`muse.env`, pin `610021d1def6`). A service created with a deliberately wrong registry credential (`rgc-dbgaskl8euvs739hfl60`, `ghcr.io`, user `qa-user`) for `ghcr.io/nginxinc/nginx-unprivileged:stable-alpine` went `live` in 15 s (`srv-dbgasusgpltc73cngot0`). That image is public and was cached from earlier runs, so the observation proves nothing by itself. It prompted the code trace below. Both fixtures are deleted.

## Code trace

- `lego/operator/internal/controller/app_controller.go:1546-1552` `pullPolicyFor`: any reference containing `@` (digest-pinned) gets `imagePullPolicy: IfNotPresent`, and a tag gets `Always`. Both a user-supplied `image@sha256:…` and the digest that image-port discovery resolves (`image_network.go`, `prefix + "@" + digest`) land on `IfNotPresent` (`deployment_projection.go:290`).
- With `IfNotPresent`, a kubelet that already holds the image starts the container without contacting the registry, so the pod's `imagePullSecrets` (`deployment_projection.go:632`) are never checked. Production nodes run Kubernetes **v1.34.9** (`infra/clusterapi/overlays/hetzner-caph/cluster.yaml:887`), where the `KubeletEnsureSecretPulledImages` gate (KEP-2535, which re-verifies credentials for cached images) is alpha and off. `infra/`, `deploy/` and `lego/` contain no `AlwaysPullImages` admission or `imagePullCredentialsVerificationPolicy`.
- Tenant workloads share the node pool. ADR022 / ADR043 isolate namespaces, not image caches.
- Partial mitigation to check: since m243, a **web** service's prebuilt image is first read anonymously for its ports (`resolveImageNetwork`), and a private image fails that read before any pod exists. Types that skip image-port discovery (prebuilt-image private services, background workers, cron jobs) do not have that gate.

## Steps

1. Reproduce on a dev cluster (`scripts/dev-env.sh`). Workspace A deploys a private image with a valid credential. Workspace B deploys the same `@sha256:` digest as a background worker or cron job with **no** credential, pinned to the same node. Record whether B's container starts.
2. If it does, fix it in one of these ways: `imagePullPolicy: Always` for every tenant pod that carries a registry credential or a non-public image (registry `HEAD` cost only; layers stay cached), or enable `KubeletEnsureSecretPulledImages` with `imagePullCredentialsVerificationPolicy: NeverVerifyAllowlistedImages` on the node bootstrap, or the `AlwaysPullImages` admission plugin. Record the choice in ADR022 and its effect on t013's Docker Hub request budget.
3. Regression: a test that every tenant pod with `imagePullSecrets` gets the chosen guarantee. A live re-run of step 1 is refused.

## Unverified

- The cross-tenant start itself was never observed. Everything above is code and Kubernetes-documented behavior.
- Whether the platform's own registry (`r.Registry`) can be named by a tenant image reference. w7/m8 gates Zot reads, but a node-cached digest would bypass that too.
