# The create form links environment groups, as Render's Advanced section does

Why: on Render a new service can share an environment group's variables and secret files from its first deploy, chosen on the create page; on bex the group can only be linked after the service exists, and each link is a second write after the first deploy has already run without the group's values.

Found by the w4/m651 t007 parity check, 2026-11-26.

- **Render.** The service create form's Advanced card (Render's dashboard bundle, read 2026-11-25, [new-service-wizard.md § The Advanced section](../../docs/render-artifacts/new-service-wizard.md#the-advanced-section-read-2026-11-25-w4m651-t001), row 2) has **Linked Environment Groups**: one picker per group, listing the workspace's groups usable in the chosen environment, shown when such a group exists or one is already linked ("Environment groups are collections of environment variables and secret files that you can share across multiple services."). It is a dashboard feature: Render's public `POST /v1/services` (`servicePOST` in `lego/backend/internal/api/openapi/render-public-api-1.json`) has no environment-group field, and links go through `POST /v1/env-groups/{id}/services/{serviceId}` afterwards.
- **bex.** GraphQL `createService` (`lego/backend/internal/apps/graphql.go`, the `createService` field) takes no environment groups, and neither does `CreateRequest` (`lego/backend/internal/apps/service.go`). The dashboard's Advanced card (`dashboard/src/features/services/pages/new-service-page.tsx`) has no picker. Linking exists after create on every surface (ADR018 [Environment groups (+ link / unlink)](../../docs/ADR018/environment-config.md)).

Done when the create page's Advanced card, between Secret Files and Health Check Path, offers the workspace's groups usable in the chosen environment and the chosen ones are linked before the first deploy, so that deploy already carries their variables and the service has exactly one deploy (a test, and a dev-4 create that reads the group's key back from the running instance). REST and MCP stay as Render's (no create-time field); the GraphQL argument is the dashboard's, as Render's is its private GraphQL's. ADR018's Create service row (`docs/ADR018/services-lifecycle.md`) drops the "Still apart" sentence for groups.
