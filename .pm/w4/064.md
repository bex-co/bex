## Exact cause and bounded fix

`lego/operator/internal/publish/publish.go:600–603` first constructs `purge-<appName>-<8 hex UID hash>`. When that exceeds 63 characters it uses `fmt.Sprintf("purge-%.45s-%x", appName, sum[:6])`: **6 + 45 + 1 + 12 = 64**. Every parent name of length 49 or more enters the broken fallback. This fixture's tenant-prefixed CR name is 50 characters; its initial candidate is 65 characters and its fallback 64.

Producer `publish.PurgeJob` → sole production caller `controller/app_controller.go:4737` → `reconcileCleanupJob` → `cleanup_job.go:95` `cl.Create` → Kubernetes-generated Job labels reject the oversized name. `handleAppDeletion` at `app_controller.go:4598` retains the finalizer on that error. Backend `apps/service.go:2222` has already removed the store row and issued CR deletion, so detail/list hide the resource while ResourceQuota continues counting it. The CLI decoding and REST acknowledgment are behaving as specified.

Compute the fallback parent budget from `63 - len("purge-") - len(hashSuffix)` (44 with the current 12-hex suffix), preserving short existing names and UID-based lifetime separation. Keep object-store prefixes, identity/ownership labels, purge permissions, completion annotations and finalizer safety unchanged. Do not patch the CLI, loosen Kubernetes admission, remove the finalizer, or bypass object cleanup. No REST/GraphQL/MCP/UI schema change is required: every static-site deletion surface benefits from the shared operator fix.

Blast radius: one production `publish.PurgeJob` caller and five direct test calls. Postgres and Key Value use the separate `controller.cleanupJobName` via two production callers (`database_controller.go:1567`, `keyvalue_backup.go:443`); that helper already computes the budget correctly. `publish.JobName` uses `types.RevisionJobName` and is separate from terminal purge naming. Avoid turning this into the deferred broad purge-envelope abstraction work (`w1/done/061`).
