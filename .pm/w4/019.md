# w4/019 — Retire the ipAllowList legacy-string shim via a one-shot CR normalization

**Filed:** 2026-07-15, by w4/m24's simplify pass (altitude finding).

`w4/m24` made `Database`/`KeyValue` `spec.ipAllowList` a `[{cidr, description}]`
entry list. To keep pre-m24 CRs (bare CIDR strings) decoding without a
migration, the CRD field is marked `Schemaless` + `PreserveUnknownFields` and
`v1alpha1.IPAllowEntry.UnmarshalJSON` accepts both shapes. That trade has a
permanent cost: the apiserver no longer validates the field at admission
(anything is accepted; a malformed entry surfaces only as a typed-decode
failure in whoever reads the CR), and the union decoder can never be retired
because nothing rewrites legacy CRs.

**Proposal:** follow RC5's `spec.name` backfill precedent — an idempotent
one-shot normalization (operator first-reconcile or a backfill script) that
rewrites bare-string entries to `{cidr}` objects. Once no string-shaped CR
remains, restore a structural object schema (required `cidr`, description
free-text) on the CRD and demote the union decoder to a test fixture.

**Why not in m24:** the milestone's DoD required legacy CRs to keep working
untouched; the normalization + schema tightening is a separate, deliberately
sequenced step (normalize first, tighten one release later).
