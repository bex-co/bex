# 576 — A GitHub folder URL (`…/tree/main/examples/hello-go`) pasted as the repository is accepted, named after the folder, and fails two minutes later with "repository … not found"

Why: copying the browser URL of a folder in GitHub is the natural way to say "deploy this subdirectory". bex accepts that URL everywhere, queues a build, and only the checkout step says the repository doesn't exist. The service is left created and named after the folder.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 115, 2026-11-11 15:22–15:30 UTC (`muse.env`, workspace `bex-canary`; release pin `f609163ada8e`). **Minor**: the deploy fails honestly, but late, after the service is created under the wrong name. ~45m.
- **Probe:**
  - **Dashboard.** `/services/new` → Public Git URL → `https://github.com/bex-co/bex/tree/main/examples/hello-go`.
    - No alert. The Name fills in as `hello-go`, and Branch and Root Directory stay empty. Deploy Service is enabled.
    - Control: `not a url` and `ftp://github.com/a/b` are marked invalid ("Enter an https:// URL, or a GitHub SSH URL…", w21/052).
  - **REST.** `POST /v1/services?dryRun=true` with `repo: "https://github.com/bex-co/bex/tree/main/examples"` answers 200 and echoes that `repo` with `branch: "main"` and `rootDir: ""`.
  - **The real create** with `repo: "…/tree/main/examples/hello-go"` (`qa-20261111-r115-tree`, `srv-dbq8h1fpvbns739s78tg`) answered 201.
    - The deploy went `created` (15:23:50) → `queued` → `build_in_progress` (15:25:45) → `build_failed` (15:25:56).
    - `deploy_ended.failureReason` read "build failed in the source checkout step:\nfatal: repository 'https://github.com/bex-co/bex/tree/main/examples/hello-go/' not found".
    - The service was deleted afterwards (DELETE 204, then GET 404).
  - **The same failure locally:** `git ls-remote https://github.com/bex-co/bex/tree/main/examples/hello-go` → "fatal: repository … not found".
- **Root cause:**
  - **Prefix-only checks.** The dashboard accepts any `https://` prefix: `isValidGitUrl` (`dashboard/src/common/lib/utils/git-url.ts:7-10`), used by the create wizard (`features/services/lib/create-service-input.ts:234`), the source picker (`service-source-picker.tsx:105`) and the Source card (`service-source-card.tsx:206`). The backend's `store.ValidRepo` / `RepoRule` (`lego/backend/internal/store/api.go:622-640`) checks scheme, userinfo and length only.
  - **The name comes from the last path segment** of whatever was pasted, so the folder name becomes the service name.
  - **A parser already exists:** `parseDeployRepo` (`dashboard/src/features/blueprints/lib/deploy-link.ts:9,17-24`) already splits `…/tree/<branch>` for Deploy-to-bex links. The service forms don't use it.
- **Fix (target behavior):**
  - **Dashboard.** In the Public Git URL field (create wizard, source picker, Source card), a `https://github.com/<owner>/<repo>/tree/<ref>[/<path>]` URL is split on blur:
    - Repository URL becomes `https://github.com/<owner>/<repo>`;
    - Branch becomes `<ref>` and Root Directory becomes `<path>`, each only when that field is still empty;
    - the Name suggestion comes from `<repo>`.
    - A `/blob/…` URL (a file) is marked invalid: "Use the repository URL; set Branch and Root Directory below."
  - **Backend.** REST create and `PATCH`, GraphQL `createService` and `setRepo`, and the MCP create and update tools refuse a GitHub `repo` containing `/tree/` or `/blob/` with a 400 naming the repository URL to use. Today that URL can only fail at checkout.
  - **The ambiguity:** a branch name containing `/` (`feature/x`) can't be told apart from a path. Split at the first segment, and let the user correct Branch and Root Directory, which stay editable.
- **Blast radius:**
  - `isValidGitUrl` has 4 callers (the three forms above, plus `parseDeployRepo`).
  - `store.ValidRepo` has 3 callers: create validation (`apps/service.go:3362`), the source update (`apps/service.go:4829`) and the store's create API (`store/api.go:404`). Changing it covers REST, GraphQL and MCP together; check that the Blueprint `repo:` path reaches one of them.
  - A Blueprint `repo:` with `/tree/` must get the same refusal.
- **Unverified:** whether Render's API and dashboard accept, split or refuse a `/tree/` URL. Render's Deploy button splits `/tree/<branch>` (w8/163). Its service form and API weren't checked.
- **Render:** see Unverified.
- **Dedupe:**
  - w21/052 (done) added the invalid marking for non-https input. Its note lists "`…/tree/main` URLs" as "not filed".
  - w4/560 (open) is the Deploy-link default branch.
  - `grep -rln "tree/main/examples" .pm` finds nothing else.
  - Not deploy lag: `git-url.ts` and `store/api.go:622-640` are unchanged on `origin/main`.
- **DoD (live):** signed in to `bex-canary`:
  - Pasting `https://github.com/bex-co/bex/tree/main/examples/hello-go` into the wizard's Public Git URL leaves Repository URL `https://github.com/bex-co/bex`, Branch `main`, Root Directory `examples/hello-go` and Name `bex`. Deploying reaches Live and serves "hello from bex".
  - `POST /v1/services?dryRun=true` with that `/tree/` URL as `repo` answers 400 naming `https://github.com/bex-co/bex`.
  - `https://github.com/bex-co/bex/blob/main/README.md` is marked invalid in the wizard.
