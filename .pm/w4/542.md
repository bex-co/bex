# 542 — The Delete Project confirmation counts the services, databases and key value stores it deletes, but never names them, while the environment delete names each one

Why: a project delete destroys every service and datastore in every environment, and the dialog says only "the one service, database, or key value store" or "3 services, databases, and key value stores". It doesn't say which database is about to go, so the one irreversible decision on the page is made blind. The environment dialog already lists each name.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 14, 2026-11-10 UTC (`muse.env`, workspace `bex-canary`, pin `c12cd57facb1`). **Minor**: the copy is truthful and the typed phrase still guards the delete, but the confirmation names nothing. ~30m.

- **Probe:** on `/project/prj-dbpfics5ngvc73e8tlv0/settings`, Delete Project opened a dialog that read:

  > Delete project "qa-20261110-proj"? Deleting this project deletes all of its environments and the one service, database, or key value store in it. Its environment groups become unassigned, not deleted. This action cannot be undone. To continue, type sudo delete project qa-20261110-proj

  The dialog named no resource. The singular copy doesn't even say which kind of resource it is.
- **Root cause:**
  - `dashboard/src/routes/project.$projectId.settings.tsx:68-71` computes only `doomedResourceCount` from `project.serviceIds` / `databaseIds` / `keyValueIds`.
  - `:204-209` passes only `{count}` to `projects.deleteConfirmBodyResources` (`features/projects/locales/en.ts:324-333`, `zh.ts:314`).
  - The environment delete resolves names instead:
    - `features/environments/components/environment-card.tsx:172-191` builds an id→name map over `services` / `databases` / `keyValues`, falling back to the id.
    - `:565-568` passes `{resources: doomedNames.join(", ")}` to `environments.deleteConfirmBodyResources` (`features/environments/locales/en.ts:138-140`).
- **Fix (target behavior):** the project dialog names each service, database and key value store across every environment, in the same form the environment dialog uses ("…deletes all of its services, databases, and key value stores: a, b, c.").
  1. Load the name lists in the project settings route with `useProjectResourceCatalog()`, the hook `project.$projectId.index.tsx:92-100` already uses.
  2. Resolve names through a shared helper with environment-card's id→name fallback, so the two dialogs can't drift apart.
  3. `projects.deleteConfirmBodyResources` takes `{resources}` and drops the `_one` / `_other` count forms. Update en and zh.
  4. Before the lists settle, the dialog shows ids (the existing fallback). It never shows a count.
  5. The typed phrase `sudo delete project <name>` and the cascade stay unchanged.
- **Blast radius:** one route, plus the new shared helper; environment-card switches to the helper. `routes/__tests__/project.$projectId.settings.test.tsx` doesn't assert the copy today. Add a test that the names appear, and keep environment-card's "names the databases and key value stores a delete removes" test green. REST, GraphQL and MCP are untouched: the dialog copy is dashboard-only.
