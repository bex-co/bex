# Custom domains: every row's "Show DNS setup" and actions-menu buttons share one accessible name

Why: with an apex + www pair plus another domain, a screen-reader or voice-control user hears three identical "Open domain actions menu" buttons and three "Show DNS setup" buttons, and cannot pick the domain to delete or inspect without leaving the control.

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop run d25a, 2026-10-29 UTC (`muse.env`, pin `69f0b17d1fad`); **minor**, ~25m. ADR005 custom-domain surface; same class as the done `w4/213` (cron run buttons).
- **Repro:** in the QA workspace, create a Free image web service (`docker.io/traefik/whoami:v1.10`). On `/services/<id>/settings#domains`, add `www.qa-<date>-x.example.com`, then `www.qa-<date>-x-test.com`. The second add auto-pairs the apex, so the table has three rows. Read the rows' buttons from the accessibility tree, for example `page.locator('#domains').getByRole('row').filter({hasText: 'www.qa-…-test.com'}).getByRole('button')`. Each row returns `["Show DNS setup", "Open domain actions menu"]`, with the same names on every row. The visible row text names the domain, but the buttons' `aria-label` replaces it, so the domain is not part of any control's name.
- **Expected:** each control names its own domain, for example "Show DNS setup for www.example.com" and "Actions for www.example.com". `aria-expanded`, keyboard activation, the menu content and the table layout stay unchanged.
- **Root cause:** `dashboard/src/features/services/components/custom-domains-section.tsx:274` (`aria-label={t("services.domainDnsToggle")}`) and `:287` (`aria-label={t("services.domainActionsMenu")}`) are constant labels. They live in `locales/en.ts:1711` "Show DNS setup" and `:1611` "Open domain actions menu", with zh at `locales/zh.ts:1678` and `:1578`. The row already has `domain.name` in scope.
- **Fix:** make both keys take a `{domain}` placeholder in en and zh, and pass `domain.name`. Update `__tests__/custom-domains-section.test.tsx`, which queries these labels in 6 places, to query by the per-domain name. Add one assertion that two rows yield distinct names.
- **Blast radius / aliases:** the section has one production caller, `routes/services.$serviceId.settings.tsx:265`. Every service type that shows Custom Domains (web, static) renders it. No other component uses these two keys. The delete confirmation already names the domain, and the pair-cascade copy is unchanged.
- **Adjacent states:** a row whose delete is in flight keeps its disabled trigger and the new name. Before the list settles, nothing renders per row, so there are no labels to name.
- **Unverified:** the static-site Settings page was not opened this run; it reaches the same component through the same route.
- **Render:** n/a (accessibility).
- **Dedupe:** searched `.pm` for both label strings and for the per-row naming class. `w4/done/353.md` and `w4/done/142.md` mention the menu only as a repro step. `w4/done/213.md` and `w6/done/044.md` fixed the same class on other surfaces. No open owner, and no fix on `main`. No DO_NOT_DO item applies.
- **Live probe also passed:** www↔apex auto-pairing (`redirectForName`, ALIAS for `@` plus an A fallback), "Re-check" on an unresolved host (toast says it isn't verified yet), the pair-delete cascade with its disclosed copy, and the empty state after deletion. The REST list returned `[]`. The service and all three claims were deleted in the same visit.
