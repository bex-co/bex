# 224 — Env-group Save and deploy announces a deployment when every linked repo service was skipped

Why: A user changing shared configuration must know whether a release started or the saved value is waiting for their next deploy.

**Worker:** worker4. **Status:** todo. **Severity:** minor (false success feedback; the value is saved, the service's pending banner is accurate, and manual deploy applies it). **Estimate:** 55m, one bounded schema-to-editor reporting correction; keep as an inbox item.

**Source:** production `$qa-find-bugs`, 2026-10-09 pass 23, workspace `bex` (`tea-d98210cbbpdc73dcrkvg`), product/source HEAD `a668150912f4be248deab4d6b819df94d74f6182`. Native Go fixtures built `https://github.com/bex-co/bex`, branch `main`, root `examples/hello-go`, build `go build -o app .`, start `./app`, port 3000, Free. OFF `srv-db4ahcbjrdls73co06eg` had `autoDeploy:false`; ON `srv-db4ahkrjrdls73co06h0` had `autoDeploy:true`; group `evg-db4ahv3jrdls73co06ig`. All three were created and deleted within this pass.

## Repro and target

1. Create a Free repo-backed service with Auto-Deploy Off and a group containing `MESSAGE=qa-a23-group-base`; link the group. Wait for link reconciliation to settle and confirm the public service serves that baseline. Linking itself can rebuild the native artifact; this separate action was settled before the repro.
2. On `/env-groups/<id>`, Edit, change `MESSAGE` to `qa-a23-group-first`, then **Save and deploy**. The group revision/value advance, HTTP 200 reports the OFF ID as affected, no failed IDs and `rolledOut:true`, and the toast says **Environment saved and deployment started**.
3. Read the service, deploy history and public URL: `Running`, `rev-2`, only its original deploy ID, public 200 `qa-a23-group-base`, `undeployedChanges:true`. No deployment started. A fresh page load at 390×844 and another changed write (`qa-a23-group-fresh`) produced the same false toast and unchanged serving release.

**Target:** expose the existing `pendingServiceIds` through GraphQL and select it in the dashboard. For a group deploying save with no successful eligible service, show existing `services.environmentSaveOnlySuccess`: “Environment saved without a deploy. Use a standard deploy to apply any pending changes.” Preserve the gate and stored values. For a mixed group, a real ON deployment still warrants deployment-started copy. `rolledOut:true` means the fan-out completed without rollout failures; deliberate skips count as successful completion.

## Root cause and bounded fix

- `lego/backend/internal/envgroups/patch.go:57–70` defines `PendingServiceIDs` as a subset of affected IDs, distinct from failures. At `:317–326` skipped IDs remain affected and are added to pending, while `RolledOut` remains true when failed IDs are empty. This agrees with live REST/MCP and is correct.
- `lego/backend/internal/envgroups/service.go:1223` gates repo-backed services with Auto-Deploy Off; `:1361` returns skipped without rolling them. `patch.go:343` keeps explicit rebuild ungated. Retain both behaviors.
- `lego/backend/internal/envgroups/graphql.go:102–111` declares six result fields and drops `PendingServiceIDs`. Add `pendingServiceIds` using `gqlutil.StrsField` (`internal/gqlutil/gqlutil.go:121`, nullable `[String]`) to project the existing result. Live introspection has the same omission.
- `dashboard/src/features/env-groups/api/env-groups.graphql:129–149` selects no pending IDs. Add the field and refresh `src/graphql/{definitions,schema-types}.ts` against the updated local schema. `dashboard/codegen.ts` supports `SCHEMA_JSON` and documents a pre-existing partial-output workaround; inspect outputs rather than assuming the full-schema target regenerated.
- `dashboard/src/features/env-groups/hooks/use-env-groups.ts:446–461` passes the raw affected list to its editor. Normalize nullable lists, then return the successful deployment set `affected − pending − failed` from this editor adapter for a deploying save; a false `rolledOut` result reports no deployment. Preserve raw API affected semantics, failed IDs, committed revision and rollout-only retry behavior.
- `dashboard/src/features/services/components/service-environment-editor.tsx:618–623` chooses success copy from the adapter's affected-list length. Keep that predicate and the service adapter at `:148–165`; adding only the schema/query field leaves the toast wrong. If choosing another adapter contract, trace it through this predicate and prove the composed editor result.

**Framework mechanism opened:** graphql-go/graphql v0.8.1 `rules.go:207–230` validates selected fields against the declared schema; `executor.go:613` and `getFieldDef` at `:1023` resolve declared fields only. A Go JSON tag does not add a GraphQL field. Add the server field before selecting it. Installed Apollo 4.1.3 `useMutation.js:86–112` returns the mutation response; Sonner 2.0.7 `dist/index.mjs:140–174,212–216` renders the supplied success message. Neither invents a deployment.

**Blast radius and aliases:** exhaustive production searches found two `EnvironmentEditor` mounts: `EnvGroupEditors` and `ServiceEnvironmentEditor`. The group patch hook has one production caller (`env-group-editors.tsx:27`), rendered by `routes/env-groups_.$groupId.tsx:212`. Scope normalization to this adapter. The service adapter covers web/static/cron/worker/private through `/services/<id>/env`, the explicit `/static/<id>/env` route and `/web`, `/pserv`, `/worker`, `/cron` Render redirect aliases (`common/lib/render-alias.ts`); Postgres and Key Value have separate surfaces and do not mount this editor. Group API entrypoints are GraphQL `patchEnvGroupEnvironment`, REST `PATCH /v1/env-groups/{id}/contents` (`rest.go:118`), and MCP `patch_env_group_environment` (`mcp.go:203`). **`PATCH /env-groups/{id}/environment` moves group scope (`rest.go:125–132`), not contents.** Render per-key writes retain their established objects; do not add batch-only fields there.

**Adjacent states:** pending IDs must not become failed IDs or trigger automatic retries. Preserve genuine partial-failure feedback and empty-patch retry at the committed revision, stale-draft refusal, missing-revision fail-closed behavior, refresh-failed warnings, save-only and rebuild choices. Auth/forbidden/not-found/timeout paths retain their existing handling and disclosure boundaries. While saving, retain current saving controls; choose success feedback from the settled mutation result.
