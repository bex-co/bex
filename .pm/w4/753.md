# A disk-backed service's Compute page says scaling is not supported, as Render's does, instead of offering scaling the API refuses

Why: Render parity. On a service with a disk, Render's page draws neither scaling card, only a notice, while bex draws Autoscaling and Manual Scaling and then answers every save with a 400.

- **Render** (its public dashboard bundle, read 2026-11-26 by w4/m696; [manual-scaling.md](../../docs/render-artifacts/manual-scaling.md#autoscalings-confirmations-read-from-renders-dashboard-bundle-2026-11-26-w4m696)): when the service has a disk, the scaling page renders only an informative notice, "Scaling is not supported for servers with disks.", with a **Change disk settings** link to the service's Disks page. render.com/docs/disks: "You can't scale a service to multiple instances if it has a disk attached" (read 2026-11-26).
- **bex today:** `dashboard/src/features/services/components/service-compute-page.tsx` gates the scaling sections on the service type only (`supportsScaling`, `dashboard/src/features/services/lib/service-type.ts:155`), so a disk-backed web service, private service or worker shows the Autoscaling switch and the Manual Scaling slider. The API refuses both: `checkAutoscaling` ("detach the disk before enabling autoscaling", `lego/backend/internal/apps/settings_check.go:516`) and `Scale` ("a service with a disk cannot run more than one instance; detach the disk first", `lego/backend/internal/apps/service.go:5257`). `ServiceView.hasDisk` (`dashboard/src/features/services/types.ts:295`) is already read by the by-id query.
- **Do:** when `hasDisk` is true, replace the Autoscaling and Manual Scaling sections with Render's notice and its link to `/services/{id}/disks` in all 8 languages, keeping Recent Metrics. A stored autoscaling policy on a disk-backed service (none should exist; the API refuses one) needs a decision only if one is found.
- **Done when:** a test renders the Compute page for a disk-backed service and finds the notice and link and no scaling controls, and the page on a disk-backed fixture service on production shows the same.
