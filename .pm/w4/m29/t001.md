## Objective

Rewrite every legacy bare-CIDR-string `ipAllowList` entry in `Database`/`KeyValue` CRs to the `{cidr}` object shape, idempotently, so the union decoder has nothing legacy left to decode and the schema can later be tightened. Follow RC5's `spec.name` backfill precedent: an operator first-reconcile normalization or a one-shot backfill script — pick the same mechanism RC5 used unless there's a recorded reason not to.

## Context

- `w4/019` — the filed proposal; `w4/m24` made `spec.ipAllowList` a `[{cidr, description}]` entry list, keeping legacy strings decodable via `v1alpha1.IPAllowEntry.UnmarshalJSON` + a `Schemaless`/`PreserveUnknownFields` CRD field.
- The normalization must be a no-op on already-object-shaped entries and must not touch `description` values.
- Find RC5's backfill implementation (grep the operator for the `spec.name` backfill) and mirror its shape.

## Steps

1. Locate the RC5 `spec.name` backfill mechanism; mirror it for `ipAllowList` entries on both `Database` and `KeyValue`.
2. Rewrite bare strings to `{cidr: <string>}`; leave object entries untouched.
3. Unit-test: mixed-shape CR normalizes correctly; second pass is a no-op.

## Files

- lego/operator/internal/controller/ (Database + KeyValue controllers or the backfill site RC5 used)
- lego/types/v1alpha1/ (only if a helper belongs there)
- tests alongside

## Acceptance criteria

- [ ] A CR with mixed string/object entries comes out all-object with values preserved.
- [ ] Re-running the normalization changes nothing (idempotent).
