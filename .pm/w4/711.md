# 711 — Search finds settings sections such as API keys, as Render's search shortcuts do

Why: Render's dashboard search jumps "directly to your API keys, webhook settings, compliance docs, and more", while bex's search finds no result for "API keys" and the member has to know it sits under Account Settings.

**Severity:** minor. **Estimate:** ~1h. **Source:** `/pm-brainstorm one more aspect of render parity for w4`, 2026-11-20, item 5; filed by `/pmx them to w4`.

## Evidence

- **Render:** changelog 2025-06-26, "Added shortcuts to Render Dashboard search results": "Jump directly to your API keys, webhook settings, compliance docs, and more—all with a few keystrokes."
- **bex:** the search palette's Navigation results (`dashboard/src/common/components/dashboard-layout/global-search-dialog.tsx` ~:145-168) are the sidebar's destinations (`dashboard-nav.ts`) plus Workspace Settings and Account Settings. Account Settings has section anchors (`dashboard/src/features/auth/pages/settings-page/index.tsx`: `#account`, `#appearance`, `#integrations`, `#access`, `#danger-zone`; `security-compliance-section.tsx`: `#security`), and none of them is a search result. Webhooks is already reachable as a sidebar page.

## Fix

1. Read Render's shortcut list from its public dashboard bundle (as `docs/render-artifacts/account-appearance.md` did) and record it in a short section of that capture or a new one.
2. Add one Navigation result per shortcut bex has a destination for, deep-linking to the section anchor (API keys and SSH keys under `#access`, and the Workspace Settings sections), behind the same feature gates as the sidebar; add the strings to every locale.
3. Record shortcuts with no bex destination (compliance docs: bex publishes none) as omissions in the capture, not as results.

## Acceptance criteria

- [ ] Typing "API keys" in search and pressing Enter lands on Account Settings scrolled to the API keys card; the same holds for every shortcut recorded in step 1 that bex has.
- [ ] Opening, filtering and closing the search palette keeps its existing focus and reset behavior (w4/265, w4/291).
