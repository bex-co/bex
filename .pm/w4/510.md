# 510 — A service's Settings page has three buttons all named just "Save" (Runtime, Networking, Edge Caching), and the Networking card's "Add" is equally bare, while the sibling database and Key Value cards name the same buttons

Why: a screen-reader user listing the page's buttons, or a voice-control user saying "click Save", gets three identical targets with no section name, although the same shared editor already says "Save allowlist" on the Postgres and Key Value pages and most other Settings buttons name their target (`Save Build Filters`, `Save credential`, `Edit Port`).

- **Source / severity / estimate:** live `/qa-find-bugs w4` loop, round 105, 2026-11-05 UTC (`muse.env`, `bex-canary`); **minor** (accessibility); ~20m.
- **Probe:** read-only, on the existing production web service `agentmarketcap-1` (`srv-d9bkcspg9s7c73d0n8ug`), `/services/<id>/settings`, `await page.locator('main').ariaSnapshot()`:
  - The button counts by accessible name are `"Save": 3`, `"Add": 1`, `"Edit": 1`. The three `Save` buttons sit under the `Runtime`, `Networking` and `Edge Caching` level-2 headings (all three disabled while nothing is dirty).
  - The same page's other section buttons carry their target: `Edit service name`, `Edit max shutdown delay`, `Edit Root Directory`, `Edit Dockerfile Path`, `Edit Port`, `Edit Health Check Path`, `Save Build Filters`, `Save credential`, `Add Custom Domain`, `Purge cache`, `Reveal Deploy Hook URL`.
  - The snapshot contains no `region`, `group` or `form` roles, so the card headings are the only context and they are not part of any button's name.
  - The other tabs of the same service (`/events`, `/logs`, `/metrics`, `/scaling`, `/env`, `/deploys`, `/shell`, `/disk`, `/plan`) had no unnamed controls and no name repeated more than twice; this is the one repeated-name page.
- **Root cause:** three message keys whose value is just `Save`:
  - `services.runtimeSave` (`dashboard/src/features/services/locales/en.ts:2033`), rendered at `components/runtime-section.tsx:125`,
  - `services.edgeCachingSave` (`en.ts:1974`), rendered at `components/edge-caching-section.tsx:155`,
  - `services.networkingSave` (`en.ts:4859`) and `services.networkingAdd` (`:4940`, `"Add"`), passed as `labels.save` / `labels.add` to the shared `common/components/ip-allow-list-editor.tsx:265-276`, from `components/service-networking-panel.tsx:93`.
  - The same shared editor is named correctly by its other two callers: `keyvalue.networkingSave` and `databases.accessAllowListSave` are both `"Save allowlist"` (`features/keyvalue/locales/en.ts:735`, `features/databases/locales/en.ts:908`; their `Add` labels were not read).
- **Fix (target behavior):** each Settings button names its section in the accessibility tree, in en and zh, for example `Save runtime`, `Save edge caching`, `Save allowlist` (matching the two sibling pages) and `Add allowlist entry`. Change the message values, not the markup, and keep the visible text short if the design wants `Save`: use an `sr-only` suffix or `aria-label` so the visible label is unchanged. Update the zh twins in `features/services/locales/zh.ts`.
- **Tests:** extend the existing services Settings component tests to assert `getByRole("button", { name: "Save runtime" })` etc. and that no two buttons on the page share a name; `common/components/__tests__/ip-allow-list-editor.test.tsx:298` already looks the button up by `labels.save`, so it follows the label.
- **Blast radius:** 3 message keys plus 1 (`networkingAdd`) in `features/services`, one render site each (`runtime-section.tsx`, `edge-caching-section.tsx`, `service-networking-panel.tsx`). The shared `ip-allow-list-editor` has 3 non-test callers (services, Key Value, databases); only the services label changes. Tests that select these buttons by the bare name `Save` would need updating; I did not grep for them.
- **Adjacent classes:** the single bare `Edit` button on the same page and the other bare `Add` were seen in the snapshot but not traced to a source line (cause unverified); treat them as part of the same pass if they turn out to be section buttons.
- **Unverified:** the Chinese catalog and the narrow-mobile layout were not checked; the bare `Edit` and the non-Networking `Add` are untraced; other service types' Settings pages (static, cron, worker, private) were not opened.
- **Render:** n/a (naming of bex's own controls); Render's Settings page was not compared.
- **Dedupe:** w4/436 and w4/482 (done) gave the domain row and DNS-panel buttons their domain's name, and w4/499 (done) did the same for Reveal/Hide; none touches these three keys. `grep -rli 'button "Save"' .pm` finds no item on them. No DO_NOT_DO item applies.
