## Objective

Implement t001's check in the operator: a periodic, rate-bounded manifest `HEAD` per running image-backed service that writes an `ImageAvailable` condition (`True`, or `False` with w4/m669's cause and worded reason) and never touches the Deployment.

## Context

- Credential resolution for image services is already in the operator (`lego/operator/internal/controller/app_controller.go`, `RegistryPullSecret`/`PerAppRegistry` at `:501-510`).
- Token auth and the SSRF-guarded transport: `lego/operator/internal/registry/image_config.go`.
- Causes and templates: `lego/types/v1alpha1/deploy_reasons.go` after w4/m669.

## Steps

1. Add a `HEAD` variant of the metadata read that returns the registry's status.
2. Requeue each eligible App on t001's interval with jitter; skip suspended Apps and bex-registry images.
3. Apply the consecutive-failure rule and write the condition with its `LastTransitionTime`; set it back to `True` on success.
4. Envtest with a fake registry: present, deleted, refused, 429 and flapping.

## Files

- `lego/operator/internal/controller/` (a new `image_availability.go`)
- `lego/operator/internal/registry/image_config.go`
- `lego/types/v1alpha1/` (the condition type)
- their tests

## Acceptance criteria

- [ ] A deleted image flips `ImageAvailable` to `False` after the second failed check, and a 429 or 5xx never does (envtest).
- [ ] The Deployment's spec and generation are unchanged throughout (envtest).
- [ ] A suspended App and a bex-registry image are never checked (envtest).
