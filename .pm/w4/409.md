# 409 — The service Environment tab adds a second `h1`; every other service tab has one

Why: screen-reader users navigate by headings. On every service tab, level 1 is the service name. Only the Environment tab adds another level-1 heading, "Environment", so its outline differs from every sibling tab and from the w4/398 cleanup's intent of one shared header.

**Severity:** minor (heading structure). **Estimate:** ~10m. **Source:** live `/qa-find-bugs w4` loop run e3k7, 2026-10-24 UTC (`muse.env`, `bex-canary`, pin `c5583c80bef9`). Fixture: Free whoami service `qa-20261024-e3k7-env` (`srv-dbee0sk67tqc738jtucg`). It was deleted (`GET` → `404`); session revoked.

## Probe

`[...document.querySelectorAll('h1')]` on each `/services/<id>/<tab>`:

- `/`, `/deploys`, `/logs`, `/metrics`, `/events`, `/settings`, `/scaling`, `/plan`, `/shell`, `/disk` → only `qa-20261024-e3k7-env`;
- `/env` → `qa-20261024-e3k7-env`, plus **`Environment`**.

## Root cause

`dashboard/src/routes/services.$serviceId.env.tsx:35` renders its section title as `<h1>`, while the shared header (`features/services/components/service-detail-header.tsx:127`) already provides the page's `h1`.

## Fix

- Render the Environment title as `h2` (keep the visual style), matching how the other tabs title their sections.
- Test: the env route renders exactly one `h1`.

Also checked, no finding: the env editor marks an invalid key (`bad key`) and a duplicate key with `aria-invalid`, announces "Use up to 253 letters, digits, dots, dashes and underscores…" / "Each variable key must be unique." via `role="alert"`, and holds **Save and deploy**.
