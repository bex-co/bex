## Objective

When the logs query times out, show it immediately as a timeout with a suggestion (a shorter range or a more specific term) rather than retrying for ~90s and then printing the transport error.

## Context

- `dashboard/src/common/apollo/retry-link.ts:31,43-44`: retries network failures, 5xx, and 429 up to 3 attempts. A deterministic query timeout is not transient.
- `dashboard/src/features/logs/components/log-viewer.tsx:171-176` renders `history.error.message` verbatim ("Failed to fetch").
- After t001, the timeout arrives as a named GraphQL error, which the viewer can branch on (and which the retry link already does not retry).

## Acceptance criteria

- [ ] The 7-day no-match search settles into a timeout state within about the server budget, with en + zh copy suggesting a narrower range.
- [ ] Ordinary transient failures still retry.
