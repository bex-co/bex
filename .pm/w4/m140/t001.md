## Objective

A GraphQL document that exhausts its execution budget must still get a well-formed response (with CORS headers) instead of a severed connection that the edge turns into a 502.

## Context

- `lego/backend/cmd/api/main.go:1388-1389`: `ReadTimeout`/`WriteTimeout` are 30s.
- `lego/backend/internal/api/graphql_cost.go:30` `gqlExecTimeout = 30 * time.Second`, applied at `internal/api/server.go:1494`.
- Filing probe: a 7-day no-match `logs(text:)` query took 30 218 ms and ended as a Cloudflare 502 with no `access-control-allow-origin`.

## Steps

1. Give execution a budget with clear headroom under `WriteTimeout` (for example, derive it as `WriteTimeout - margin`, and assert the relation in a test so the two cannot drift back to equal).
2. Map `context.DeadlineExceeded` from a resolver to a stable GraphQL error code (for example `LOG_QUERY_TIMEOUT`, or a generic `QUERY_TIMEOUT`) with a message that names what to narrow.
3. Confirm with a slow fake resolver that the response is written, carries CORS, and returns within the write deadline.

## Acceptance criteria

- [ ] The 7-day no-match probe in the milestone DoD returns a GraphQL response (never an edge 502).
- [ ] A test pins `gqlExecTimeout < WriteTimeout`.
