# 193 — Pre-authorization input validation in `audit` (`auditLogs`, `organizationAuditLogs`, `GET /v1/{owners,organizations}/{id}/audit-logs`) and `projects` (`POST /v1/projects`, `PATCH /v1/projects/{id}`) returns `400 bad_request` instead of `403`/`404`

Why: `bex-api`'s authz-before-validation contract requires workspace/organization/resource authorization to run before caller-supplied arguments are validated so unauthorized or foreign-target callers receive `403 FORBIDDEN` / `404 NOT_FOUND` (and emit denied audit rows) instead of `400 bad_request`. Two remaining packages not covered by `w31/172`, `182`, `183`, `186`–`189` violate this ordering: (1) `audit/graphql.go:170-177` (`Query.auditLogs`, `Query.organizationAuditLogs`) and `audit/rest.go:364-370` (`GET /v1/owners/{ownerId}/audit-logs`, `GET /v1/organizations/{orgId}/audit-logs`) parse `startTime`/`endTime` via `FilterOf` before calling `s.List` / `s.ListOrganization` (`AuthorizeWorkspaceAuditLog` / `AuthorizeOrganizationAuditLog`); and (2) `projects/rest.go:172-175` (`POST /v1/projects`) and `:197-200` (`PATCH /v1/projects/{id}`) reject blank `name` before calling `s.CreateWithEnvironments` / `s.Rename`, directly contradicting MCP `update_project` (which returns `NOT_FOUND` on the same nonexistent project ID with `name: ""`).

- **Attribution:** server (`lego/backend/internal/audit`, `lego/backend/internal/projects`)
- **Root cause:**
  - `lego/backend/internal/audit/graphql.go:170-177` (`auditLogsField`) calls `FilterOf(...)` before `list(p.Context, p.Args[key].(string), f)`; `lego/backend/internal/audit/rest.go:364-370` (`serveAuditLogs`) calls `filterFromQuery(r.URL.Query())` before `list(r.Context(), r.PathValue(param), filter)`.
  - `lego/backend/internal/projects/rest.go:172-175` (`POST /v1/projects`) checks `strings.TrimSpace(req.Name) == "" || req.OwnerID == ""` before calling `s.CreateWithEnvironments`, and `:197-200` (`PATCH /v1/projects/{id}`) checks `strings.TrimSpace(req.Name) == ""` before calling `s.Rename` (even though `s.CreateWithEnvironments` and `s.Rename` already validate `requiredName` after authorization!).
