# 148 — Scoped `agents: read_write` API keys bypass `workspaces: read_write` on 6 Admin-only workspace-wide agent skill and repository-environment verbs across `/mcp`, `/mcp/cloud-agents`, REST, and GraphQL

Why: `agentsessions.Service` enforces Admin-only `core.RelCanManage` on all six workspace-wide cloud-agent configuration mutations (`CreateAgentSkill`, `UpdateAgentSkill`, `DeleteAgentSkill`, `SetRepoEnvironment`, `DeleteRepoEnvironment`, `BuildRepoEnvironment`), yet `lego/backend/internal/api/key_permission_ops.go` gates all 18 MCP, REST, and GraphQL routes solely on Developer-level `core.KeyAgentsManage` (`agents: read_write`), letting an admin-minted `agents: read_write`-only key without `workspaces: read_write` inject arbitrary shell `setup`/`checks` scripts into repository environments, trigger image builds, and overwrite or delete workspace-wide skills injected into every member's coding-agent sessions.

- **Attribution:** server (`lego/backend/internal/api/key_permission_ops.go` + `lego/backend/internal/core/keygrant.go`)
- **Root cause:**
  - All six service methods enforce Admin-only `core.RelCanManage`:
    - `agentsessions.Service.{CreateAgentSkill,UpdateAgentSkill,DeleteAgentSkill}` (`lego/backend/internal/agentsessions/skills.go:214,247,281`)
    - `agentsessions.Service.{SetRepoEnvironment,DeleteRepoEnvironment}` (`lego/backend/internal/agentsessions/repo_environment.go:189,232`)
    - `agentsessions.Service.BuildRepoEnvironment` (`lego/backend/internal/agentsessions/repo_environment_builds.go:247`)
  - Yet `lego/backend/internal/api/key_permission_ops.go` maps all 18 routes solely to `{core.KeyAgentsManage}` (part of `agents: read_write`, `rels(RelCanView, RelCanCreate)` = Developer role at `lego/backend/internal/core/keygrant.go:404`):
    - GraphQL: `key_permission_ops.go:74` (`buildAgentRepoEnvironment`), `:89` (`createAgentSkill`), `:121` (`deleteAgentRepoEnvironment`), `:124` (`deleteAgentSkill`), `:213` (`setAgentRepoEnvironment`), `:297` (`updateAgentSkill`).
    - MCP (`/mcp` and `/mcp/cloud-agents`): `key_permission_ops.go:515` (`build_agent_repo_environment`), `:525` (`create_agent_skill`), `:551` (`delete_agent_repo_environment`), `:555` (`delete_agent_skill`), `:749` (`set_agent_repo_environment`), `:776` (`update_agent_skill`).
    - REST: `key_permission_ops.go:803` (`DELETE /v1/agent-repo-environments/{owner}/{repo}`), `:807` (`DELETE /v1/agent-skills/{ref}`), `:1038` (`PATCH /v1/agent-skills/{ref}`), `:1072` (`POST /v1/agent-repo-environments/{owner}/{repo}/builds`), `:1082` (`POST /v1/agent-skills`), `:1179` (`PUT /v1/agent-repo-environments/{owner}/{repo}`).
  - Because `core.KeyAgentsManage`'s catalog copy (`lego/backend/internal/core/keygrant.go:266`) explicitly bundles `"skills, and repository environments"` under Developer-level `agents: read_write`, an admin who mints a scoped `agents: read_write` key for CI or session automation unknowingly grants workspace-Admin modification of shared agent skills and repo-environment build/check scripts.

  - Update all 18 entries in `lego/backend/internal/api/key_permission_ops.go` to require `core.KeyWorkspaceSettingsManage` (either `{core.KeyAgentsManage, core.KeyWorkspaceSettingsManage}` or `{core.KeyWorkspaceSettingsManage}`, matching the convention chosen for `w31/063` `update_agent_environment` and `w31/069`).

  - Keep read routes (`list_agent_skills`, `get_agent_skill*`, `list_agent_repo_environments*`, `get_agent_repo_environment_build`) on `core.KeyAgentsView`.
