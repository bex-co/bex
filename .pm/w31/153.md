# 153 — `metrics.Service.Metrics` and `metrics.Service.DatastoreMetrics` short-circuit on pre-creation, pre-retention, and diskless-service windows before validating metric names, `percentage`, and defaulted time ranges

Why: `lego/backend/internal/metrics/service.go:661-674` returns `[]MetricSeries{}, nil` when `[start, end]` precedes `core.AppNotBefore(app)` or the workspace plan's `withinRetention` floor before `switch q.Metric` (`:677-690`) rejects unknown metrics; `lego/backend/internal/metrics/datastore.go:456-459` returns `nil, nil` on pre-retention windows before `isDatastoreMetric(q.Metric)` (`:462-464`) and `if q.Percentage && !canPercentage` (`:465-468`); and `datastore.go:429-431` returns `nil, nil` for a service with `app.Spec.Disk == nil` before `q.normalized(s.Now())` (`:451`), `checkPointBudget` / `core.ValidateQueryRange` (`:452-454`), and the `percentage` check (`:466`). As a result, invalid metric names, disallowed `percentage: true`, and future-`startTime` queries silently succeed with `200 []` across MCP (`get_metrics`, `get_datastore_metrics`), GraphQL (`metrics`, `datastoreMetrics`), and REST (`/v1/metrics/disk-usage`) whenever the window is pre-creation / pre-retention or the service has no disk.

- **Root cause:**
  - `lego/backend/internal/metrics/service.go:661-674` short-circuits `metricsInWindow` on `q.Start.Before(created) && !created.Before(q.End)` and `!kept` (`s.withinRetention`) before `switch q.Metric` (`:677-690`) reaches `default: return nil, fmt.Errorf("%w: unknown metric %q", core.ErrBadRequest, q.Metric)`.
  - `lego/backend/internal/metrics/datastore.go:429-431` short-circuits `DatastoreMetrics` with `return nil, nil` when `app.Spec.Disk == nil`, skipping `q = q.normalized(s.Now())` (`:451`), `checkPointBudget(q.Start, q.End, q.Resolution)` (`:452-454`, which invokes `core.ValidateQueryRange`), and `if q.Percentage && !canPercentage` (`:465-468`).
  - `lego/backend/internal/metrics/datastore.go:456-459` short-circuits `DatastoreMetrics` on `!kept` (`s.withinRetention`) before `if !isDatastoreMetric(q.Metric)` (`:462-464`) and `if q.Percentage && !canPercentage` (`:465-468`).
- **Fix:**
  - In `lego/backend/internal/metrics/service.go` (`metricsInWindow`): validate `q.Metric` against the known service metrics (e.g. an `isServiceMetric(q.Metric)` helper before line `661`, right after authorization and before the `AppNotBefore` / `withinRetention` short-circuits), preserving the exact `unknown metric %q` error message (or without echoing untrusted values if preferred — check existing tests in `input_validation_test.go`).
  - In `lego/backend/internal/metrics/datastore.go` (`DatastoreMetrics`):
    1. Keep the `app.Spec.Disk == nil` state in a boolean (`noDisk := app.Spec.Disk == nil`) instead of returning at `:430`, so `q = q.normalized(s.Now())`, `checkPointBudget`, `isDatastoreMetric`, and `q.Percentage && !canPercentage` all run first; return `nil, nil` for `noDisk` only after all input validation passes (before `withinRetention` / Prometheus dispatch).
    2. Move `if !isDatastoreMetric(q.Metric)` (`:462-464`) and `if q.Percentage && !canPercentage` (`:465-468`) ABOVE `s.withinRetention` (`:456-459`), right after the per-kind `switch` / `checkPointBudget` checks so invalid metrics and disallowed `percentage: true` always fail with `core.ErrBadRequest` even on pre-retention windows.
