# 182 — Pre-authorization input validation across `sandbox` list/group-page endpoints, `GET /v1/disks`, and MCP `update_{service,postgres,key_value,environment}` returns `400 bad_request` instead of `403`/`404`

Why: `bex-api`'s authz-before-validation contract requires authorization to run before caller-supplied arguments are validated so unauthorized callers (foreign workspaces, unprivileged roles, or nonexistent IDs) receive `403 FORBIDDEN` / `404 NOT_FOUND` instead of `400 bad_request` (and denied attempts emit denied audit rows). Three endpoint families not covered by `w31/172` violate this ordering across MCP, REST, and GraphQL: (1) `sandbox.Service.listFilteredRules` (`service.go:1840-1859`, behind `GET /v1/sandboxes`, `GQL Query.sandboxes`, and `MCP list_sandboxes`) calls `parseStatusFilter` and `validateGroupID` before `s.List(ctx)` (`Authorize`), and 4 GraphQL sandbox group-page resolvers (`group_pages_surfaces.go:342-416`: `sandboxesForGroup`, `sandboxGroupRuns`, `sandboxEvents`, `sandboxSnapshotsForGroup`) parse timestamps via `timeArg` before calling their authorized service verbs; (2) `REST GET /v1/disks` (`apps/disks.go:463-496`) parses `createdBefore`/`createdAfter`/`updatedBefore`/`updatedAfter` via `core.QueryTimeWindow` before `ListForCaller` / `ListDisks`; and (3) all four folded MCP patch adapters (`apps/mcp.go:943-951`, `postgres/mcp.go:433-441`, `keyvalue/mcp.go:197-200`, `environments/mcp.go:136-140`) validate allowlist conflicts, `autoDeployTrigger`, and `connectionPool` before delegating to their authorized update verbs.
