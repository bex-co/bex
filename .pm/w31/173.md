# 173 — `logs.LogQuery.validateFilterPatterns` omits `q.Level`, returning `500` on invalid `/regex/` `level` filters across MCP, REST, and GraphQL and bypassing `maxFilterPatternLen`

Why: Every Render log filter (`text`, `host`, `statusCode`, `method`, `path`, `instance`, `level`) supports `*` wildcards and `/RE2/` regular expressions (`lego/backend/internal/logs/mcp.go:52`, `w8/176`), and `LogQuery.validateFilterPatterns` (`lego/backend/internal/logs/filterpattern.go:51-71`) enforces both `maxFilterPatternLen = 1024` and `regexp.Compile` before any query reaches Loki or opens a live tail. Because `validateFilterPatterns` omits `{"level", q.Level}`, a malformed `/regex/` in `level` slips past validation and reaches Loki as an invalid LogQL regex matcher — turning a caller typo into `500 internal_error` (`"internal error"`) on `list_logs`, `list_log_label_values`, `GET /v1/logs`, `GET /v1/logs/values` (for both services and managed datastores), and GraphQL `logs` / `logLabelValues`. On `GET /v1/logs/subscribe`, the bad `level` passes the pre-stream `q.validate()` gate (`logs/rest.go:257`), writes HTTP `200`, and fails mid-stream inside `compileLevelFilter` while leaking the internal wrapper regex suffix `).*)$` (as do pod-log datastore reads). Meanwhile, `level` completely bypasses the `1024`-byte pattern cap on every read and live stream.

- **Attribution:** server (`lego/backend/internal/logs`)
- **Root cause:**
  - `lego/backend/internal/logs/filterpattern.go:51-71` (`LogQuery.validateFilterPatterns`) checks `maxFilterPatternLen` (`1024`) and `regexp.Compile` on `{"text", q.Search}`, `{"host", q.Host}`, `{"statusCode", q.StatusCode}`, `{"method", q.Method}`, `{"path", q.Path}`, and `{"instance", q.Instance}` — omitting `{"level", q.Level}`.
  - `LogQuery.validate()` (`lego/backend/internal/logs/service.go:434-446`) relies solely on `validateFilterPatterns()` for filter-pattern validation; `logsSubscribe` (`lego/backend/internal/logs/rest.go:257`) relies on `q.validate()` to refuse bad queries before writing HTTP `200` / WebSocket `101`.
  - When a Loki-backed query runs (`lokiSelectorFor` at `lego/backend/internal/logs/loki.go:506` → `labelMatcher(lokiLabelFor(LabelLevel), q.storedLevels(), ...)` → `labelValuePattern` at `:711-717`), the unvalidated regex body is interpolated into `level=~"^(.*(?:<body)>.*)$"`. Loki rejects the malformed LogQL with HTTP `400`, which `bex-api` surfaces as `500 internal_error`.
  - On pod-log and live-tail reads (`compileLevelFilter` at `lego/backend/internal/logs/service.go:1409-1419`), `regexp.Compile(labelValuePattern(q.storedLevels()))` runs only after `q.validate()` (and after `logsSubscribe` has already written HTTP `200`), bypassing `maxFilterPatternLen` and surfacing the wrapped pattern's trailing `).*)$` in the error message.
- **Fix:**
  - Add `{"level", q.Level}` to the field list in `LogQuery.validateFilterPatterns()` at `lego/backend/internal/logs/filterpattern.go:56-58`.
  - Because `LogQuery.validate()` is called by `QueryLogs`, `LogLabelValues` (including `datastoreTarget` → `datastoreLogLabelValues`), `FollowLogs`, `logsSubscribe` (`rest.go:257`), and project-scoped log reads (`project.go` merges `savedsearch.FieldLevel` into `q.Level` before `QueryLogs` / `LogLabelValues`), this single shared fix covers MCP, REST (query, label values, and pre-stream subscribe), GraphQL, and dashboard project views simultaneously.
  - Keep `compileLevelFilter()` as defensive compilation on `q.storedLevels()`, since `storedLevels()` only adds static literal aliases (`warn`, `error`, `info`) alongside caller values that `validateFilterPatterns()` has already compiled and length-checked.
- **Blast radius:** `lego/backend/internal/logs/filterpattern.go` and `lego/backend/internal/logs/` unit tests. Zero changes needed in MCP, REST, GraphQL, or dashboard adapters because every surface already flows through `LogQuery.validate()`.
