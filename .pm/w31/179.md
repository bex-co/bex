# 179 — Scoped `sandboxes: read`/`read_write` API keys (zero `agents` permissions) bypass `agents.view`/`agents.manage` to list, inspect, read execution history/events of, suspend, resume, and terminate Cloud Agent session sandboxes

Why: `lego/backend/internal/sandbox/` contains zero `KeyGrantAllows` checks anywhere — `List` (`service.go:1705-1751`), `Get` (`service.go:1906-1939`), `GetDetailed` (`group_sandboxes.go:336-350`), `Suspend`/`Resume`/`Terminate` → `lifecycle` (`service.go:1943-2112`, which even deletes `SessionEgress` at `:2104-2110`), `ListExecutions`/`GetExecution` (`executions.go:215-293`), and `ListEvents` (`events.go:220-252`) all resolve sandboxes via `Client.List` / `ownedSandbox` (`service.go:771-788`) and `endedSandbox`/`endedSandboxes` (`records.go:132-208`) without gating `raw.Metadata[metadataAgentSession] != ""` on `core.KeyAgentsView` or `core.KeyAgentsManage` — letting a scoped API key granted only `sandboxes: read` or `sandboxes: read_write` (zero `agents` permission) discover, read command history/timeline events of, suspend, resume, and terminate Cloud Agent session sandboxes across MCP, REST, and GraphQL.

### Scoped `sandboxes`-only API keys cross from `sandboxes` into `cloud_agents` sessions without any `agents` grant

- **Expected / actual:**
  - **Expected:** Under `docs/ADR024-members.md` and `docs/ADR118-security-review-scoped-api-keys.md`, `sandboxes` (`KeySandboxesView`, `KeySandboxesHistory`, `KeySandboxesManage`) and `cloud_agents` (`KeyAgentsView`, `KeyAgentsManage`) are separate permission areas. A scoped API key without `agents: read` (`KeyAgentsView`) must never list or inspect Cloud Agent session sandboxes (`raw.Metadata[metadataAgentSession] != ""`) or read their execution history/events; and a scoped API key without `agents: read_write` (`KeyAgentsManage`) must never suspend, resume, or terminate a Cloud Agent session's sandbox (or delete its `SessionEgress` NetworkPolicy).
  - **Actual:** `lego/backend/internal/sandbox/` has zero `KeyGrantAllows` checks anywhere. Any API key granted only `sandboxes: read` (or `sandboxes: read_write`) created by a workspace admin (making `isWorkspaceAdmin` true for every sandbox in the workspace) or by a session's owner:
    1. Sees every live and ended Cloud Agent session sandbox (substrate ID, status, plan, owner, created timestamp) in `list_sandboxes` / `GET /v1/sandboxes` / `GQL Query.sandboxes` and `GET /v1/sandboxes/{id}` / `GQL Query.sandbox` (`List`, `Get`, `GetDetailed`).
    2. Reads command runs and file-transfer history plus timeline events of any agent-session sandbox via `list_sandbox_executions` / `GET /v1/sandboxes/{id}/execs{,/{execId}}` / `GQL Query.{sandboxExecutions,sandboxExecution,sandboxEvents}` (`ListExecutions`, `GetExecution`, `ListEvents`).
    3. Can suspend, resume, or **terminate** any running Cloud Agent session's sandbox — and delete its `SessionEgress` NetworkPolicy (`service.go:2104-2110`) — via `suspend_sandbox`, `stop_sandbox`, `POST /v1/sandboxes/{id}/{suspend,resume,terminate}`, `DELETE /v1/sandboxes/{id}`, and `GQL Mutation.{suspendSandbox,terminateSandbox}`.

- **Attribution:** server (`lego/backend/internal/sandbox`)
- **Root cause:**
  - `lego/backend/internal/sandbox/service.go:1728-1739` (`list`): iterates every OpenSandbox in the workspace's namespace, checking only `validOwnedSandbox` and `ownerCheck` — never checking `r.Metadata[metadataAgentSession] != ""` against `s.KeyGrantAllows(ctx, core.KeyAgentsView)`.
  - `lego/backend/internal/sandbox/service.go:771-788` (`ownedSandbox`): shared by `Get` (`:1922`), `GetDetailed` (`group_sandboxes.go:341`), `Suspend`/`Resume`/`Terminate` → `lifecycle` (`:2013`, with `:2104-2110` explicitly handling `metadataAgentSession` on terminate), `executionsTarget` (`executions.go:231` → `ListExecutions`/`GetExecution`), `ListEvents` (`events.go:225`), and `CreateSnapshot` (`snapshots.go:393`). It checks only `mayAccessSandbox` (`owner == caller || isWorkspaceAdmin`), never checking `KeyGrantAllows` when `raw.Metadata[metadataAgentSession] != ""`.
  - `lego/backend/internal/sandbox/records.go:132-208` (`endedSandbox` / `endedSandboxes`): persisted `SandboxRecord.View` (`sandboxFromOpenSandbox`, `service.go:812-841`) does not retain or enforce an agent-session marker for `KeyAgentsView` filtering after termination (`orEnded` / `status=terminated` lists).
- **Fix:**
  - Add a shared helper in `lego/backend/internal/sandbox/` (e.g., `requireAgentSessionKeyGrant(ctx, raw, action)`): when `raw.Metadata[metadataAgentSession] != ""`, check `s.KeyGrantAllows(ctx, action)` (using `core.KeyAgentsView` for `Get`, `GetDetailed`, `ListExecutions`, `GetExecution`, `ListEvents`, and `core.KeyAgentsManage` for `Suspend`, `Resume`, `Terminate`, `CreateSnapshot`; fail closed on lookup error, returning `core.NewKeyPermissionDeniedError([]core.KeyAction{action})` — or hiding from `List` / returning `SANDBOX_NOT_FOUND` on reads so an ungranted key cannot probe agent-session IDs as an existence oracle).
  - In `sandbox.Service.list` (`service.go:1730-1739`), skip any `r` with `r.Metadata[metadataAgentSession] != ""` when the caller's API key lacks `core.KeyAgentsView` (computing the key grant once before the loop alongside `ownerCheck`).
  - Persist whether a recorded sandbox belonged to an agent session (or check `box.ungrouped` / a dedicated field in `store.SandboxRecord` / view JSON) so `endedSandbox` and `endedSandboxes` (`records.go:132-208`) apply the exact same `core.KeyAgentsView` gate for terminated agent-session sandboxes.
  - Coordinate with `w31/168` (which adds `KeyAgentsManage` to `authorizeExecTarget`, `authorizeFileTarget`, `shell-ticket`, and native SSH) so **every** `sandbox.Service` verb consistently enforces `agents` permission boundaries on `metadataAgentSession` sandboxes across MCP, REST, and GraphQL.
