# 183 — Pre-authorization query/filter validation across `agentsessions` (MCP `list_agent_sessions`, GraphQL `agentSessions`, and 8 REST routes) and `GET /v1/notifications` returns `400 bad_request` instead of `403`/`404`

Why: `bex-api`'s authz-before-validation contract requires authorization to run before caller-supplied arguments are validated so unauthorized callers (foreign workspaces, unprivileged roles, or nonexistent targets) receive `403 FORBIDDEN` / `404 NOT_FOUND` instead of `400 bad_request` (and so denied attempts emit denied audit rows). Eleven non-OpenAPI bex-extension endpoints not covered by `w31/172` or `w31/182` violate this ordering across MCP, GraphQL, and REST: `MCP list_agent_sessions` (`agentsessions/mcp.go:254-261`), `GraphQL Query.agentSessions` (`agentsessions/graphql.go:871-882`), eight `agentsessions` REST routes (`GET /v1/agent-sessions`, `/transcript`, `/tool-outputs/{toolCallId}`, `/attachments`, `GET /v1/agent-automations`, `/runs`, `GET /v1/agent-skills/{ref}/versions`, `/versions/{version}`), and `GET /v1/notifications` (`notifications/rest.go:54-58`) all parse timestamps, `limit`, `afterSeq`, `mine`, `turn`, or `version` before calling their authorized service verbs.
