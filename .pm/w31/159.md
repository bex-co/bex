# 159 — `agentsessions.ListRequest.storeQuery`, `webhooks.Service.ListDeliveriesFiltered`, `audit.FilterOf`, `deploys.FilterOf`, and `jobs.FilterFromStrings` never reject inverted time ranges (`After > Before` / `startTime > endTime`), silently returning `200 []` across MCP, REST, and GraphQL

Why: Unlike `logs.Service` (`core.ValidateInclusiveQueryRange`) and `metrics.Service` (`core.ValidateQueryRange`), five shared list filters parse RFC 3339 lower/upper timestamp bounds without checking that the lower bound does not exceed the upper bound: `agentsessions.ListRequest.storeQuery` (`lego/backend/internal/agentsessions/service.go:1249-1317`, `createdAfter`/`createdBefore`), `webhooks.Service.ListDeliveriesFiltered` (`lego/backend/internal/webhooks/service.go:839-876`, `sentAfter`/`sentBefore`), `audit.FilterOf` (`lego/backend/internal/audit/service.go:399-409`, `startTime`/`endTime`), `deploys.FilterOf` (`lego/backend/internal/deploys/service.go:497-530`, `created*`/`updated*`/`finished*`), and `jobs.FilterFromStrings` (`lego/backend/internal/jobs/service.go:412-442`, `created*`/`started*`/`finished*`). Callers passing an inverted window silently receive `200 []` instead of `400 bad_request`, hiding swapped or misformatted filter bugs across MCP (`/mcp` and `/mcp/cloud-agents`), REST, and GraphQL.

- **Attribution:** server (`lego/backend/internal/{agentsessions,webhooks,audit,deploys,jobs}`)
- **Root cause:**
  - `lego/backend/internal/agentsessions/service.go:1249-1317`: `ListRequest.storeQuery` copies `CreatedAfter` and `CreatedBefore` without checking `!q.CreatedAfter.IsZero() && !q.CreatedBefore.IsZero() && q.CreatedAfter.After(q.CreatedBefore)`.
  - `lego/backend/internal/webhooks/service.go:839-876`: `ListDeliveriesFiltered` forwards `filter.SentAfter` and `filter.SentBefore` directly to `s.Store.ListWebhookAttempts` without checking `SentAfter` vs `SentBefore`.
  - `lego/backend/internal/audit/service.go:399-409`: `FilterOf` parses `f.Since` and `f.Until` via `core.ParseTime` without calling `core.ValidateInclusiveQueryRange(f.Since, f.Until)`.
  - `lego/backend/internal/deploys/service.go:497-530`: `FilterOf` parses `created*`, `updated*`, and `finished*` pairs without checking `after <= before`.
  - `lego/backend/internal/jobs/service.go:412-442`: `FilterFromStrings` parses `created*`, `started*`, and `finished*` pairs without checking `after <= before`.
- **Fix:**
  - Validate inverted time-range pairs in each shared filter/service entry point (after authorization where the check runs in the service method, so authz-before-validation stays intact):
    - `audit.FilterOf` (`lego/backend/internal/audit/service.go:408`): call `core.ValidateInclusiveQueryRange(f.Since, f.Until)` (or check inside `audit.Service.List` after `AuthorizeWorkspaceAuditLog`).
    - `agentsessions.ListRequest.storeQuery` (`lego/backend/internal/agentsessions/service.go:1254-1256`): reject `CreatedAfter.After(CreatedBefore)` with coded `AGENT_SESSION_FILTER_INVALID` `400`.
    - `webhooks.Service.ListDeliveriesFiltered` (`lego/backend/internal/webhooks/service.go:858-862`): reject `SentAfter.After(SentBefore)` with `core.ErrBadRequest`.
    - `deploys.FilterOf` (`lego/backend/internal/deploys/service.go:503-529`) and `jobs.FilterFromStrings` (`lego/backend/internal/jobs/service.go:430-434`): reject any `*After.After(*Before)` pair with `core.ErrBadRequest` naming both parameters.
