# 151 — Scoped `deploys_run: run`-only API keys bypass `services_env: read`, `services: read`, and `deploys: read` via GraphQL `rollbackComparison` (and `scope_matrix_ops` misclassifies it as `OpClassRead`)

Why: `lego/backend/internal/api/key_permission_ops.go:439` maps `GQL Query.rollbackComparison` solely to `{core.KeyDeploysRollback}` (`deploys_run: run`) — omitting `core.KeyServicesEnv`, `core.KeyServicesView`, and `core.KeyDeploysView` — while `lego/backend/internal/api/scope_matrix_ops.go:415` classifies it as `core.OpClassRead` instead of `core.OpClassSensitive`, and `secrets.Service.EnvironmentKeysAccess` (`lego/backend/internal/secrets/service.go:259-265`) checks only OpenFGA `core.RelCanViewSensitive` without checking `KeyGrantAllows(ctx, core.KeyServicesEnv)`. A scoped API key granted **only** `deploys_run: run` (zero `services`, `services_env`, `deploys`, or `env_groups` permissions) can therefore read service configuration (`plan`, `instances`, commands, health checks), linked env group names, deploy IDs, env var key names, and secret file names via `rollbackComparison`.

- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:439` maps `"GQL Query.rollbackComparison"` solely to `{core.KeyDeploysRollback}` (`deploys_run: run`), ignoring the file's own rule at `:33-36` that an operation reading multiple areas or sensitive environment metadata needs each area's action.
  - `lego/backend/internal/deploys/rollback_comparison.go:121-130` authorizes `core.RelCanViewActivity` on the service and calls `s.EnvironmentKeys(ctx, service)` → `secrets.Service.EnvironmentKeysAccess` (`lego/backend/internal/secrets/service.go:259-265`). `EnvironmentKeysAccess` checks only OpenFGA `core.RelCanViewSensitive` (inherited from the key creator's Developer/Admin role) and never checks `KeyGrantAllows(ctx, core.KeyServicesEnv)`.
  - `lego/backend/internal/api/scope_matrix_ops.go:415` classifies `"GQL Query.rollbackComparison"` as `core.OpClassRead` (missing an entry in `scope_matrix_overrides.go` alongside `GQL Query.envVars` and `GQL Query.secretFiles` at `:91-92`), even though `RollbackComparison` enforces `core.RelCanViewSensitive` and discloses env var keys and secret file names.
- **Fix:**
  - Update `lego/backend/internal/api/key_permission_ops.go:439` so `"GQL Query.rollbackComparison"` requires `{core.KeyDeploysRollback, core.KeyDeploysView, core.KeyServicesView, core.KeyServicesEnv}` (or `{core.KeyDeploysView, core.KeyServicesView, core.KeyServicesEnv}` — confirm whether a read-only deploy/service/env viewer without `deploys_run` may also preview a rollback; at minimum, `KeyServicesEnv`, `KeyServicesView`, and `KeyDeploysView` must be required).
  - Add `"GQL Query.rollbackComparison": core.OpClassSensitive` in `lego/backend/internal/api/scope_matrix_overrides.go` and regenerate/update `lego/backend/internal/api/scope_matrix_ops.go:415`.
  - Defense-in-depth in `secrets.Service.EnvironmentKeysAccess` (`lego/backend/internal/secrets/service.go:259-265`): enforce `core.KeyServicesEnv` on attributed scoped API keys (`KeyGrantAllows` / `RequireKeyActions`) so no future caller of `EnvironmentKeysAccess` can leak env var keys or secret file names without `services_env: read`.
