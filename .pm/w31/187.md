# 187 — MCP `create_blueprint` and `update_blueprint` validate inputs before authorization, and `apps.Service.UpdateBlueprint` omits `WithDeferredAllowedWriteAudit` and validates before `GetBlueprint`

Why: `bex-api`'s authz-before-validation and deferred-write-audit contracts require authorization to run before caller-supplied arguments are validated (so unauthorized callers receive `403 FORBIDDEN` / `404 NOT_FOUND` instead of `400 bad_request` and emit denied audit rows) and require failed writes not to emit `"allowed"` write audit rows. Both MCP Blueprint onboarding tools (`create_blueprint` at `blueprint_onboarding.go:973-996` and `update_blueprint` at `blueprint_onboarding.go:1003-1027`) validate `repoUrl`, blank `name`/`branch`/`path`, empty patches, and `approvedBlueprintPath` before calling `s.CreatePlannedBlueprint` (`Authorize(RelCanCreate)`) or `s.blueprintScopeAs` (`AuthorizeTargetAs(RelCanCreate)`). In addition, `apps.Service.UpdateBlueprint` (`blueprint.go:2138-2179`, shared by MCP, REST, and GraphQL) calls `s.blueprintScope` without `core.WithDeferredAllowedWriteAudit(ctx)` and validates the patch before `GetBlueprint`, returning `400` instead of `404` for nonexistent IDs in authorized workspaces and recording `"allowed"` write audit rows on `400`/`404`/`409` refusals (and `updateBlueprintTool` records duplicate `"allowed"` audit rows on real updates and on no-op updates).

- **Root cause:**
  - `lego/backend/internal/apps/blueprint_onboarding.go:973-996` (`createBlueprintTool`): calls `parseBlueprintRepoURL(in.RepoURL)` (`:974`) and `blankSetting` (`:978-986`) before `s.CreatePlannedBlueprint` (`:994`, which authorizes `core.RelCanCreate` at `:164`).

- **Fix:**
  - In `createBlueprintTool` (`blueprint_onboarding.go:973-996`), authorize `core.RelCanCreate` on `core.NamedWorkspace(ctx)` with `core.WithDeferredAllowedWriteAudit` (or move `parseBlueprintRepoURL` / `blankSetting` after `CreatePlannedBlueprint`'s `Authorize`) so unauthorized callers fail `403` before URL/field validation.
  - In `updateBlueprintTool` (`blueprint_onboarding.go:1003-1045`), move `s.blueprintScopeAs(core.WithDeferredAllowedWriteAudit(ctx), AuditVerbUpdateBlueprint, core.RelCanCreate, in.BlueprintID, owner)` and `GetBlueprint` ahead of `blankSetting`, empty-patch, and `approvedBlueprintPath` validation so foreign-workspace, unauthorized-role, and nonexistent-ID calls fail `403`/`404` first and neither `400`/`404` refusals nor no-op updates emit false `"allowed"` write audit rows.
  - In `UpdateBlueprint` (`blueprint.go:2138-2236`), pass `core.WithDeferredAllowedWriteAudit(ctx)` into `s.blueprintScope`, load `s.Blueprints.GetBlueprint` before patch validation so nonexistent IDs return `404` consistently, and call `s.RecordAllowedWrite` only after `s.Blueprints.UpdateBlueprint` succeeds.
