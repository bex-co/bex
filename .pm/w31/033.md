# 033 — MCP `get_metrics` skips all query validation when `project`/`environment` scope resolves to 0 resources (and GraphQL `metrics` skips `quantile` range validation on an empty scope)

Why: Unlike REST `GET /v1/metrics/*` (`metrics/rest.go:357-370`) and GraphQL `metrics` (`metrics/graphql.go:403-413`), MCP `get_metrics` (`metrics/mcp.go:313-357`) has no `len(resources) == 0` validation guard — so any `get_metrics` call scoped to an empty project or environment (or a project whose resources are all filtered out by `keep`) silently returns `200 []` on unknown `metricTypes`, inverted `startTime > endTime`, >720h windows, out-of-range `httpLatencyQuantile`, negative `resolution`, and `http_latency` on a Hobby workspace; GraphQL `metrics` also skips `quantile` range checks on an empty scope.

- **Expected / actual:**
  - **Expected:** Under ADR006 (shared service validation across REST, GraphQL, and MCP) and `w4/m596`, an empty `project`/`environment`/`region` scope must still reject invalid `metricTypes`, inverted or >720h time windows, out-of-range `httpLatencyQuantile`/`quantiles`, invalid `resolution`, and Hobby-gated `http_latency` — matching REST `GET /v1/metrics/*` (`metrics/rest.go:357-370`) and MCP `list_logs` (`logs/mcp.go:165-173`).
  - **Actual:**
    - MCP `get_metrics` returned `200 OK` with `[]` (`isError` unset) on all six invalid requests above.
    - GraphQL `metrics` returned `200 {"data":{"metrics":[]}}` for `HTTP_LATENCY` with `quantile: 5.0` on the empty project.
    - REST `GET /v1/metrics/*` on the exact same empty project/environment returned `400 bad_request` for every invalid window, resolution, and quantile.

- **Attribution:** server (`lego/backend/internal/metrics`)
- **Root cause:**
  - `lego/backend/internal/metrics/rest.go:357-370` and `lego/backend/internal/metrics/graphql.go:403-413` explicitly guard `if len(resolved.IDs) == 0` with `s.checkWindow(q.Start, q.End)` and `s.RequirePlanFeature(..., core.FeatureLatencyMetrics)` (and REST validates `quantile`/`resolutionSeconds` up front in `parseMetricParams`).
  - `lego/backend/internal/metrics/mcp.go:257-357` discards `resolved.WorkspaceID` and has no `if len(resources) == 0` validation at all: when `resources` is empty, the loop at `:314-351` runs zero iterations and returns `[]`, skipping unknown `metricTypes` checks, `s.checkWindow`, quantile bounds, resolution validation (general MCP/GQL resolution bounds are tracked separately in `w31/006`), and `FeatureLatencyMetrics` plan gating.
  - `lego/backend/internal/metrics/graphql.go:403-413, 620` (`parameterQuantiles`) never validates quantile bounds before returning `[]QuantileSeries{}` on `len(resolved.IDs) == 0` (deferring quantile range validation to `MetricsWithQuantiles` inside the resource loop).
- **Fix:**
  - In `lego/backend/internal/metrics/mcp.go`: validate every entry in `in.MetricTypes` against the known Render/bex metric types (plus `renderActiveConnections`) before returning, validate `q.Quantile` / `q.Quantiles` bounds whenever `http_latency` is requested (coordinating with `w31/007` on `0`/`1` handling), preserve `resolved.WorkspaceID` from `resolveMetricScope`, and add an `if len(resources) == 0` branch (matching `rest.go:357-370`) that calls `s.checkWindow(q.Start, q.End)` and `s.RequirePlanFeature(ctx, resolved.WorkspaceID, core.FeatureLatencyMetrics)` when `http_latency` is in `in.MetricTypes` and `resolved.WorkspaceID != ""`.
  - In `lego/backend/internal/metrics/graphql.go`: validate `q.Quantiles` bounds in `metricsQueryInputFromArgs` (or in the `len(resolved.IDs) == 0` branch at `:403-413`) using the same shared quantile validator used by `MetricsWithQuantiles` / REST `parseMetricParams`.
- **Blast radius:** `lego/backend/internal/metrics/mcp.go`, `lego/backend/internal/metrics/graphql.go`, and their unit tests. No breaking change for valid empty-project queries (valid queries still return `[]`).
