# 168 — Scoped `sandbox_execution: execute`-only API keys (zero `agents` permissions) bypass `agents.manage` to shell into, exec in, and transfer files on Cloud Agent session sandboxes across REST, GraphQL, MCP `sandbox_exec`, and native SSH

Why: `lego/backend/internal/api/key_permission_ops.go:88,1080` maps `GQL Mutation.createAgentSessionShellSession` and `REST POST /v1/agent-sessions/{id}/shell-ticket` solely to `{core.KeySandboxesExec}` (`agentsessions.ShellKeyAction`, `lego/backend/internal/agentsessions/terminal.go:42`), `terminalSandbox` (`terminal.go:130-146`) only checks `s.KeyGrantAllows(ctx, core.KeyAgentsManage)` in the closed-sandbox resume branch, `sandbox.Service.authorizeExecTarget` (`lego/backend/internal/sandbox/exec.go:281-285`) and `authorizeFileTarget` (`lego/backend/internal/sandbox/file_connect.go:145-149`) check only OpenFGA `RelCanViewSensitive` (no `KeyGrantAllows`) when a target sandbox carries `metadataAgentSession`, and `sshgateway/nativessh/server.go:1042-1044` holds `ags-…` SSH logins solely to `KeySandboxesExec` — letting an API key granted only `sandbox_execution: execute` (with zero `agents` permission) obtain interactive shells, run commands, and transfer files inside Cloud Agent sessions' credential-capable sandboxes.

- **Expected / actual:**
  - **Expected:** Under `docs/ADR024-members.md` and `docs/ADR118-security-review-scoped-api-keys.md`, `sandboxes` (`sandbox_execution: execute`) and `cloud_agents` (`agents: read` / `agents: read_write`) are separate permission areas. An agent session's sandbox is a credential-capable pod holding the Git-write proxy, model proxy, repository checkout, and agent workspace (`lego/backend/internal/sandbox/exec.go:273-280`), and `agentsession/session_wake.go:172` already requires **both** `core.KeyAgentsManage` and `core.KeySandboxesExec` to wake a closed session. A key with zero `agents` permission must receive `api_key_permission_denied` (requiring `agents.manage`, alongside `sandboxes.exec` / `sandboxes.files`) on `POST /v1/agent-sessions/{id}/shell-ticket`, GraphQL `Mutation.createAgentSessionShellSession`, native SSH to `ags-…`, and any `sandbox` exec or file-transfer call targeting an agent-session sandbox (`raw.Metadata[metadataAgentSession] != ""`).
  - **Actual:** A scoped `sandbox_execution: execute`-only API key (zero `agents` permissions) passes the API-key permission gate on `POST /v1/agent-sessions/{id}/shell-ticket` and `Mutation.createAgentSessionShellSession` — reaching `agentsessions.Service.CreateShellSession` → OpenFGA `RelCanViewSensitive` (which passes via creator ceiling for any running/starting agent session the key's creator can access, since `terminalSandbox` at `terminal.go:130-135` returns `ShellSandboxUp`/`ShellSandboxStarting` without checking `KeyGrantAllows`). The same missing `KeyAgentsManage` check affects `sandbox.Service.authorizeExecTarget` (`MCP sandbox_exec`, `REST POST /v1/sandboxes/{id}/exec`, `POST /v1/sandboxes/{id}/runs/{operation}/token`), `sandbox.Service.authorizeFileTarget` (`POST /v1/sandboxes/{id}/files/{operation}/token`), and native SSH (`ags-…`).

- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:88,1080` maps `"GQL Mutation.createAgentSessionShellSession"` and `"REST POST /v1/agent-sessions/{id}/shell-ticket"` to `{core.KeySandboxesExec}` only, driven by `lego/backend/internal/api/key_stream_ops_test.go:35-51` and `lego/backend/internal/agentsessions/terminal.go:42` (`const ShellKeyAction = core.KeySandboxesExec`), because `shellticket.Claims.KeyAction` (`lego/backend/internal/shellticket/shellticket.go:69`) and `agentsession.KeyGrantRequest.Action` (`lego/backend/internal/agentsession/key_grant.go:40-44`) only model a single `KeyAction` string.
  - `agentsessions.Service.terminalSandbox` (`lego/backend/internal/agentsessions/terminal.go:130-146`) only checks `s.KeyGrantAllows(ctx, core.KeyAgentsManage)` after falling through to the closed-sandbox resume path (`:142`); live (`openableSandbox`) and starting (`liveSandboxPhase`) sessions return immediately at `:132-135` without checking any `agents` grant.
  - `sandbox.Service.authorizeExecTarget` (`lego/backend/internal/sandbox/exec.go:281-285`) and `sandbox.Service.authorizeFileTarget` (`lego/backend/internal/sandbox/file_connect.go:145-149`) recognize `raw.Metadata[metadataAgentSession] != ""` and escalate OpenFGA to `AuthorizeFreshOn(ctx, core.RelCanViewSensitive, agentsession.SessionObject(sessionID))`, but never check `s.KeyGrantAllows(ctx, core.KeyAgentsManage)` (nor carry `KeyAgentsManage` into `sandboxexec.Claims` / `sandboxfiles` gateway revalidation).
  - `sshgateway/nativessh/server.go:1042-1044` (`keyOwnerAction`) likewise checks only `core.KeySandboxesExec` for `ags-…` native SSH logins (inconsistent with `agentsession/session_wake.go:172`, which checks `grant.Allows(core.KeyAgentsManage, core.KeySandboxesExec)`).
- **Fix:**
  - Require `{core.KeyAgentsManage, core.KeySandboxesExec}` in `lego/backend/internal/api/key_permission_ops.go:88,1080` for `"GQL Mutation.createAgentSessionShellSession"` and `"REST POST /v1/agent-sessions/{id}/shell-ticket"`.
  - In `sandbox.Service.authorizeExecTarget` (`lego/backend/internal/sandbox/exec.go:281-285`) and `sandbox.Service.authorizeFileTarget` (`lego/backend/internal/sandbox/file_connect.go:145-149`), when `sessionID := raw.Metadata[metadataAgentSession]; sessionID != ""`, require `s.KeyGrantAllows(ctx, core.KeyAgentsManage)` (returning `core.NewKeyPermissionDeniedError([]core.KeyAction{core.KeyAgentsManage})` on denial, fail-closed on lookup error).
  - Extend stream ticket/revalidation grant checks (`shellticket.Claims`, `sandboxexec.Claims`, `sandboxfiles` connect claims, `sshgateway.KeyGrantGate`, `sshgateway/nativessh/server.go:1037-1050`, and `api/key_stream_ops_test.go:35-51`) so multi-action streams (e.g., agent-session shell/exec/file/SSH requiring both `KeyAgentsManage` and `KeySandboxesExec`/`KeySandboxesFiles`) hold the open stream to **every** required action on redemption and every revalidation tick (calling `KeyGrantGate` per action or extending `KeyGrantRequest` with `Actions []string` while keeping backwards-compatible single-`Action` parsing for rolling upgrades).
