# 037 — Omitting `plan` (or Key Value `maxmemoryPolicy`/`persistenceMode`) on Postgres and Key Value create bypasses the `FREE_INSTANCE_LIMIT` pre-check/lock and returns empty `"plan": ""` / `"options": {}` on `dryRun: true` across MCP, REST, and GraphQL

Why: `postgres.Service.CreatePostgres` and `keyvalue.Service.CreateKeyValue` leave omitted `plan` (and Key Value `maxmemoryPolicy`/`persistenceMode`) as `""` instead of applying the CRD defaults (`free`, `allkeys-lru`, `journal-snapshot`), so every `req.Plan == core.FreePlanID` gate and `core.WithFreeSlotLock` is skipped, and `core.Base.DryRunCreate` discards the API-server-defaulted deep copy — letting `dryRun: true` with omitted `plan` return `200 OK` (`"plan": ""`, `"options": {}`) even when the workspace already holds a free instance.

### `create_postgres` / `create_key_value` (and REST / GraphQL equivalents) skip free-slot admission and drop defaulted `plan` and `options` when fields are omitted

- **Attribution:** server (`lego/backend/internal/postgres`, `lego/backend/internal/keyvalue`)
- **Root cause:**
  - `postgres.Service.CreatePostgres` (`lego/backend/internal/postgres/service.go:937,976,1005-1009,1026-1033`) and `keyvalue.Service.CreateKeyValue` (`lego/backend/internal/keyvalue/service.go:680,692-699,712,717-718,736-740,757-764`) leave empty `req.Plan` as `""` (and `CreateKeyValue` leaves empty `MaxmemoryPolicy` and `PersistenceMode` as `""`), relying on the Kubernetes API server applying `+kubebuilder:default` markers (`database_types.go:152`, `keyvalue_types.go:53,73,83`) at `Create` time.
  - Because `req.Plan == ""` does not equal `core.FreePlanID` (`"free"`), both services skip:
    1. The pre-dry-run free-slot check (`refuseSecondFreeDatabase` / `refuseSecondFreeKeyValue`),
    2. The tenant free-slot lock (`core.WithFreeSlotLock(..., req.Plan == core.FreePlanID, ...)`), and
    3. The pre-create check in `CreateResource` (`postgres/service.go:1053`, `keyvalue/service.go:780`).
    On a real create, a second free CR is therefore written to Kubernetes (receiving CRD default `plan: free`) before `rollbackSecondFree*` deletes it; on `dryRun: true`, `FREE_INSTANCE_LIMIT` is bypassed completely.
  - On `dryRun: true`, `core.Base.DryRunCreate` (`lego/backend/internal/core/dryrun.go:77-95`) runs `b.Client.Create(ctx, probe, client.DryRunAll)` on a `DeepCopyObject()` and discards `probe`, leaving `d.Spec.Plan`, `kv.Spec.Plan`, `kv.Spec.MaxmemoryPolicy`, and `kv.Spec.PersistenceMode` empty when `s.view(...)` renders the preview (and `toRenderKeyValue` at `lego/backend/internal/keyvalue/rest.go:101-104` omits empty fields from `"options": {}`).
- **Fix:**
  - In `postgres.Service.CreatePostgres` (`lego/backend/internal/postgres/service.go:937`), resolve omitted `req.Plan` to `core.FreePlanID` (`req.Plan = cmp.Or(tiers.Postgres.CanonicalID(req.Plan), core.FreePlanID)`), matching `DatabaseSpec.Plan`'s `+kubebuilder:default=free` (and check `CreateResource` treats empty `d.Spec.Plan` as free too, as defense in depth).
  - In `keyvalue.Service.CreateKeyValue` (`lego/backend/internal/keyvalue/service.go:680-699`), resolve omitted `req.Plan` to `core.FreePlanID`, omitted `maxmemoryPolicy` to `"allkeys-lru"`, and omitted `persistenceMode` to `"journal-snapshot"`, matching `KeyValueSpec`'s `+kubebuilder:default` markers (`lego/types/v1alpha1/keyvalue_types.go:53,73,83`). Do **not** synthesize defaults in `kvView` for already-stored empty specs, so legacy pre-default CRs keep their documented semantics (`keyvalue_types.go:68,78`).
  - Surface impact: fixes MCP `create_postgres` / `create_key_value`, REST `POST /v1/postgres` / `/v1/key-value` / `/v1/redis`, and GraphQL `createDatabase` / `createKeyValue` together.
