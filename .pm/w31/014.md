# 014 — MCP `clone_env_group` declares an unreachable `ownerId` field (stripped and rejected by `mcp_workspace.go`) and cannot clone an environment group into another workspace

Why: `cloneEnvGroupArgs` (`lego/backend/internal/envgroups/mcp.go:64-69,183-191`) exposes `ownerId` as the target workspace for cross-workspace cloning, but `mcp_workspace.go` deletes `ownerId` from `tools/list` and rejects any call carrying it, while passing `workspaceId` of the target workspace binds `ctx` to that workspace before `authorizeGroup` runs and fails with `ErrNotInNamedWorkspace` on the source group — making cross-workspace env-group cloning impossible over MCP.

### MCP `clone_env_group` cannot target another workspace: `ownerId` is stripped/rejected and `workspaceId` fails source lookup

- **Attribution:** server (`lego/backend/internal/envgroups` + `lego/backend/internal/api/mcp_workspace.go` interaction)
- **Root cause:**
  - `lego/backend/internal/envgroups/mcp.go:64-69` defines `cloneEnvGroupArgs.OwnerID` (`json:"ownerId,omitempty"`) and lines `183-191` read `in.OwnerID` with fallback to `core.NamedWorkspace(ctx)`.
  - `lego/backend/internal/api/mcp_workspace.go:188` (`workspaceInputSchema`) deletes `properties["ownerId"]` on every workspace-scoped tool, and `lego/backend/internal/api/mcp_workspace.go:218-220` (`takeMCPWorkspaceID`) rejects any call with `ownerId` before the handler runs, rendering `in.OwnerID` unreachable dead code.
  - Meanwhile, when a caller supplies `workspaceId` (for the destination workspace), `mcpBindCallWorkspace` (`mcp_workspace.go:115-119`) calls `ctx = core.WithWorkspace(ctx, workspaceID)` before invoking the tool. Inside `CloneEnvGroup` (`lego/backend/internal/envgroups/clone.go:37`), `authorizeGroup` (`envgroups/service.go:1876-1884`) calls `s.ScopeByID(ctx, "", s.groupOwner(gid))`; `core/byid.go:62` returns `ctx` unchanged whenever `WorkspaceFrom(ctx)` is already set; and `fetchGroup` → `AuthorizeLabeled` (`core/base.go:2336-2338`) returns `core.ErrNotInNamedWorkspace` whenever `g.TenantID != named`, failing every cross-workspace clone.
- **Fix:**
  - Replace the dead `OwnerID` field in `cloneEnvGroupArgs` (`lego/backend/internal/envgroups/mcp.go:67`) with `TargetWorkspaceID string` (`json:"targetWorkspaceId,omitempty" jsonschema:"optional authorized destination workspace id (tea-...); omit to clone into the active workspace"`).
  - In `clone_env_group`'s handler (`lego/backend/internal/envgroups/mcp.go:183-191`), compute `targetOwnerID := in.TargetWorkspaceID`; if empty, fall back to `core.NamedWorkspace(ctx)` (and validate `targetWorkspaceId` with the same non-empty/access rules `CloneEnvGroup` already enforces on `targetCtx := core.WithWorkspace(ctx, req.OwnerID)`).
  - Keep `workspaceId` as the optional source/active workspace binding (so `workspaceId` = source workspace and `targetWorkspaceId` = destination workspace, or omit `workspaceId` and let `ScopeByID` locate the source while `targetWorkspaceId` names the destination).
  - Also audit the other `OwnerID` fields in `lego/backend/internal/agentsessions/{mcp,automations_mcp}.go` and `lego/backend/internal/sandbox/mcp.go` to confirm none of them expects a second distinct workspace beyond `core.NamedWorkspace(ctx)` (and drop dead `OwnerID` fields if unused).
  - No REST, GraphQL, or UI change; brings MCP `clone_env_group` back into parity with REST `POST /v1/env-groups/{id}/clone` and GraphQL `cloneEnvGroup`.
