# 209 — `apps.Service.GenerateBlueprint` and `envgroups.Service.ExportEnvGroup` bypass protected-environment Admin enforcement and silently swallow `ListEnvVarNames` errors across MCP, REST, and GraphQL

Why: Under `docs/ADR032-environments.md:98,113` (`w8/193`, `w4/m594`), viewing environment variables or environment-group variables in a protected environment requires a workspace Admin (`403 PROTECTED_ENVIRONMENT_ADMIN_REQUIRED`), enforced on services by `secrets.Service.scopeAuthorized` (`lego/backend/internal/secrets/service.go:238-248`) and `secrets.EnvironmentKeysAccess` (`:253-265`, used even for key-name-only reads) and on environment groups by `envgroups.Service.requireGroupAdmin` (`lego/backend/internal/envgroups/render.go:172`, `clone.go:46`). However, `apps.Service.GenerateBlueprint` (`lego/backend/internal/apps/blueprint_generate.go:144-232,664-729`) never calls `s.requireUnprotected(ctx, a, core.VerbEnvironmentVariables)` on selected services — exporting every literal `a.Spec.Env` value and secret key name to non-Admin Developers — and `generateEnvVars` (`:684-694`) silently swallows every error from `s.EnvNames.ListEnvVarNames(ctx, a.Name)` (`if names, err := ...; err == nil`), turning both `403 PROTECTED_ENVIRONMENT_ADMIN_REQUIRED` and `503 ErrSecretsUnavailable` outages into `200 OK` partial manifests that drop all mutable env vars. Meanwhile, `envgroups.Service.ExportEnvGroup` (`lego/backend/internal/envgroups/service.go:397-416`) checks only `RelCanViewSensitive` and omits `s.requireGroupAdmin(ctx, g, core.VerbEnvironmentVariables)`, leaking protected environment-group env-var keys both directly (`envGroupIds`) and via unselected linked groups (`blueprint_generate.go:700-725`) across MCP (`generate_blueprint`), REST (`POST /v1/blueprints/generate`), and GraphQL (`Query.generateBlueprint`).

- **Root cause:**
  - `lego/backend/internal/apps/blueprint_generate.go:208-232` & `664-694`: `GenerateBlueprint` checks only `AuthorizeApp(ctx, core.RelCanViewSensitive, id)` and omits `s.requireUnprotected(ctx, a, core.VerbEnvironmentVariables)` before reading `a.Spec.Env`; then `generateEnvVars` (`:684-694`) writes `if names, err := s.EnvNames.ListEnvVarNames(ctx, a.Name); err == nil { ... }`, discarding every error from `ListEnvVarNames` instead of returning it.
  - `lego/backend/internal/envgroups/service.go:397-416`: `ExportEnvGroup` checks `s.authorizeGroup(ctx, core.RelCanViewSensitive, gid)` (`:398`) and omits `s.requireGroupAdmin(ctx, g, core.VerbEnvironmentVariables)` (unlike `revealGroups` at `envgroups/render.go:172` and `CloneEnvGroup` at `envgroups/clone.go:46`).
- **Fix:**
  - In `lego/backend/internal/apps/blueprint_generate.go`:
    1. In `GenerateBlueprint` (`:209-213`), right after `AuthorizeApp(ctx, core.RelCanViewSensitive, id)`, enforce `if err := s.requireUnprotected(ctx, a, core.VerbEnvironmentVariables); err != nil { return GenerateBlueprintResult{}, err }` (matching `secrets.Service.scopeAuthorized` / `secrets.EnvironmentKeysAccess`, and failing closed if protection lookup fails).
    2. In `generateEnvVars` (`:684-694`), propagate any error from `s.EnvNames.ListEnvVarNames(ctx, a.Name)` (`names, err := s.EnvNames.ListEnvVarNames(ctx, a.Name); if err != nil { return nil, err }`) instead of swallowing it (only ignoring `core.ErrNotFound` if a mutable secret path is genuinely absent, which `ListEnvVarNames` already maps to empty slice).
  - In `lego/backend/internal/envgroups/service.go:397-402` (`ExportEnvGroup`), right after `s.authorizeGroup(ctx, core.RelCanViewSensitive, gid)`, enforce `if err := s.requireGroupAdmin(ctx, g, core.VerbEnvironmentVariables); err != nil { return "", nil, err }`.
