# 184 — Non-OpenAPI REST write routes in `billing`, `workspaces`, `notifications`, `object_storage_admin`, and `sshkeys` omit `core.WithStrictJSONDecoding`, silently dropping unknown/misspelled fields and risking full-replace wipes

Why: Unlike Render OpenAPI routes (where `renderRequestValidator` automatically sets `core.WithStrictJSONDecoding` at `api/render_openapi.go:1028`) and hardened bex extensions (`agentsessions/rest.go`, `sandbox/credentials_rest.go`, `notifications/rest.go:70`), ten non-OpenAPI bex-extension REST write endpoints decode JSON via plain `core.DecodeJSON` / `core.DecodeBody` without `core.WithStrictJSONDecoding`. Unknown or misspelled JSON fields are silently dropped — turning a 1-character typo on full-replace `PUT /v1/workspaces/{workspaceId}/billing/info` (e.g. `{"company":"Acme"}` instead of `companyName`) into an empty `BillingInfoInput{}` that wipes stored company name, address, and VAT/tax ID on Stripe, and diverging from MCP (`update_billing_info`, `update_billing_email`, `add_ssh_key`) and GraphQL, which reject unknown fields immediately.

- **Attribution:** server (`lego/backend/internal/billing`, `lego/backend/internal/workspaces`, `lego/backend/internal/notifications`, `lego/backend/internal/api`, `lego/backend/internal/sshkeys`)
- **Root cause:**
  - `lego/backend/internal/api/render_openapi.go:1028` only wraps matched Render OpenAPI routes with `core.WithStrictJSONDecoding`; bex-only REST extension routes opt in per handler, and these 10 handlers omitted it:
    - `lego/backend/internal/billing/rest.go:39,61,75` (`checkout-session`, `billing/info`, `portal-session`)
    - `lego/backend/internal/workspaces/rest.go:110` (`billing/email`)
    - `lego/backend/internal/notifications/rest.go:114,124,142` (`notification-settings/push`, `notification-device-subscriptions`, `notification-webpush-subscriptions`)
    - `lego/backend/internal/api/object_storage_admin.go:126,172` (`access-keys`, `buckets/{bucket}/public`)
    - `lego/backend/internal/sshkeys/rest.go:39` (`ssh-keys`)
- **Fix:**
  - Wrap `r = r.WithContext(core.WithStrictJSONDecoding(r.Context()))` before `core.DecodeJSON` / `core.DecodeBody` in all 10 handlers above (or consider enabling strict decoding centrally in `core.DecodeBody` / REST middleware for all `/v1/` routes after auditing any legitimate open-object extension routes).
  - Surface the decode error on `billing/rest.go:39,75`, `sshkeys/rest.go:39`, and `object_storage_admin.go:172` (keeping `ENABLED_REQUIRED` solely for `req.Enabled == nil` after a clean strict decode, matching `w31/180`'s fix on `apikeys/rest.go`).
  - No MCP or GraphQL change needed (both already reject unknown fields via schema validation).
- **Blast radius:** `lego/backend/internal/{billing,workspaces,notifications,sshkeys}/rest.go`, `lego/backend/internal/api/object_storage_admin.go`, and their REST unit tests. Valid callers sending declared JSON fields are unaffected.
