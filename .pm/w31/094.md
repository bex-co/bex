# 094 — `sandbox.credentialActorSubject` stores an API key's raw Hydra client UUID as `updated_by`, leaking internal client UUIDs in `version.updatedBy` instead of public `usr-…` IDs across MCP, REST, and GraphQL

Why: `lego/backend/internal/sandbox/credentials.go:164-169` (`credentialActorSubject`) records `id.Subject` verbatim on credential create (`:326`), update (`:399`), and restore (`:554`) without resolving an attributed API key's human creator via `s.KeyCreator(ctx)`, so `credentialVersionViews` (`:171-198`) fails `core.PublicUserIDs` lookup on the Hydra OAuth2 client UUID and leaks the raw internal client UUID in `version.updatedBy` on MCP, REST, and GraphQL instead of the creator's public `usr-…` ID.

### Sandbox group credential versions written with an API key leak the key's Hydra client UUID in `updatedBy`

- **Attribution:** server (`lego/backend/internal/sandbox`)
- **Root cause:**
  - `sandbox.Service` embeds `*core.Base` (`lego/backend/internal/sandbox/service.go:150`), which already has `KeyCreators` wired in production (`lego/backend/cmd/api/main.go:1013`, `lego/backend/internal/api/server.go:1958`), so `s.KeyCreator(ctx)` (`lego/backend/internal/core/keyrole.go:127-138`) is directly available.
  - However, `credentialActorSubject(ctx)` (`lego/backend/internal/sandbox/credentials.go:164-169`, called at `:326`, `:399`, `:554`) is a package-level function that reads `id.Subject` verbatim without consulting `s.KeyCreator(ctx)`.
  - At read time, `credentialVersionViews` (`lego/backend/internal/sandbox/credentials.go:171-198`) calls `core.PublicUserIDs(ctx, s.UserIDs, ...)` which maps Kratos subjects to `usr-…` IDs; for a Hydra client UUID, `users[v.UpdatedBy]` misses and line 185 falls back to emitting the raw Hydra client UUID verbatim.
- **Fix:**
  - Make `credentialActorSubject` a method on `*sandbox.Service` (`s.credentialActorSubject(ctx) (string, error)`) that resolves an attributed API key's human creator via `s.KeyCreator(ctx)` when `id.IsAPIKey()` (failing closed on `ErrAuthzUnavailable` if creator lookup fails, and falling back to `id.Subject` only for non-key/unattributed machine callers).
  - Also audit `credentialVersionViews` (`credentials.go:185-188`) for existing rows already containing a Hydra client UUID: if `s.KeyCreators != nil`, optionally resolve legacy stored key UUIDs to their creator before calling `core.PublicUserIDs`, or avoid leaking raw non-`usr-` UUIDs if unresolvable.
  - Surface impact: aligns `version.updatedBy` across MCP (`create_sandbox_group_credential`, `update_sandbox_group_credential`, `restore_sandbox_group_credential`, `get_sandbox_group_credential`, `list_sandbox_group_credentials`), REST (`/v1/sandbox-groups/{id}/credentials…`), GraphQL (`sandboxGroupCredential` / `sandboxGroupCredentials`), and the dashboard credential version history UI.
- **Blast radius:** `lego/backend/internal/sandbox/credentials.go` and its tests (`lego/backend/internal/sandbox/credentials_test.go`, `lego/backend/internal/api/sandbox_credentials_e2e_test.go`); audit rows continue recording the calling key identity from `ctx`.
