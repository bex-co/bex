# 001 — Hydra OAuth discovery omits `registration_endpoint`, breaking MCP Dynamic Client Registration

Why: Hydra serves public RFC 7591 Dynamic Client Registration at `POST https://oauth.bex.co/oauth2/register`, but neither `/.well-known/oauth-authorization-server` nor `/.well-known/openid-configuration` advertises `registration_endpoint`, so standards-compliant OAuth 2.1 MCP clients (including Claude Code following [ADR025](../../docs/ADR025-connect-an-agent.md)) cannot self-register.

### Hydra `/.well-known/oauth-authorization-server` and `/.well-known/openid-configuration` omit `registration_endpoint`

- **Severity:** blocker
- **Versions:** deployed pin `4b533337ab` (`7b046987bcd8`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`; Hydra image/chart pinned in `deploy/gitops/base/hydra.yaml` (`oryd/hydra:v26.2.0` in E2E)
- **Context:** 2026-11-25, endpoints `/mcp` and `/mcp/cloud-agents` (`https://api.bex.co` → `https://oauth.bex.co`), anonymous (unauthenticated OAuth 2.1 discovery)
- **Repro:**
  ```sh
  python3 scripts/qa-mcp.py --anonymous initialize
  python3 scripts/qa-mcp.py get-url https://api.bex.co/.well-known/oauth-protected-resource
  python3 scripts/qa-mcp.py get-url https://oauth.bex.co/.well-known/oauth-authorization-server
  python3 scripts/qa-mcp.py get-url https://oauth.bex.co/.well-known/openid-configuration
  # Control proving the DCR route itself is mounted (invalid JSON, creates nothing):
  curl -sS -i -X POST -H 'Content-Type: application/json' -d '{invalid' https://oauth.bex.co/oauth2/register
  ```
- **Expected / actual:**
  - **Expected:** Per RFC 8414, RFC 7591, the MCP Authorization Specification (2025-06-18 / 2025-11-25), and [ADR025 § What happens on first connect](../../docs/ADR025-connect-an-agent.md#what-happens-on-first-connect-rfc-9728--dcr--pkce), `https://oauth.bex.co/.well-known/oauth-authorization-server` (and `/.well-known/openid-configuration`) must include `"registration_endpoint": "https://oauth.bex.co/oauth2/register"` so MCP clients can discover and call public Dynamic Client Registration without manual client setup.
  - **Actual:** Both `GET https://oauth.bex.co/.well-known/oauth-authorization-server` (`200`, 747 ms) and `GET https://oauth.bex.co/.well-known/openid-configuration` (`200`, 375 ms) omit `"registration_endpoint"` completely (and `scopes_supported` lists only `["offline_access", "offline", "openid"]`, though RFC 9728 protected-resource metadata lists the `bex.*` scopes). Meanwhile `POST https://oauth.bex.co/oauth2/register` with `{invalid` answers `400` (`Unable to decode the request body`), proving DCR is enabled and mounted, just unadvertised.
- **Wire evidence:**
  - `GET https://api.bex.co/.well-known/oauth-protected-resource` → `200`: `{"authorization_servers":["https://oauth.bex.co"],"bearer_methods_supported":["header"],"resource":"https://api.bex.co/mcp","scopes_supported":["bex.read","bex.write","bex.sensitive","bex.cloud_agents"]}`
  - `GET https://oauth.bex.co/.well-known/oauth-authorization-server` → `200`: includes `issuer`, `authorization_endpoint`, `device_authorization_endpoint`, `token_endpoint`, `jwks_uri`, `userinfo_endpoint`, `revocation_endpoint`, `end_session_endpoint`, `code_challenge_methods_supported: ["plain", "S256"]`, `scopes_supported: ["offline_access", "offline", "openid"]` — no `registration_endpoint` key.
  - `POST https://oauth.bex.co/oauth2/register` (`{invalid`) → `400`: `{"error":"The request was malformed or contained invalid parameters","error_description":"Unable to decode the request body: invalid character 'i' looking for beginning of object key string"}`
- **Attribution:** infrastructure/runtime (GitOps Hydra configuration + E2E test gap)
- **Root cause:**
  - `deploy/gitops/base/values/hydra.values.yaml:68-69` sets `hydra.config.oidc.dynamic_client_registration.enabled: true`, which mounts `POST /oauth2/register`, but Ory Hydra populates `registration_endpoint` in its discovery documents from `webfinger.oidc_discovery.client_registration_url` (`OAuth2ClientRegistrationURL`), not automatically from `dynamic_client_registration.enabled`.
  - Neither `deploy/gitops/base/values/hydra.values.yaml`, `deploy/gitops/overlays/local/values/hydra.values.yaml`, nor `scripts/dev-env/values/hydra.values.yaml` sets `webfinger.oidc_discovery.client_registration_url`.
  - `scripts/auth-oauth21-e2e.sh:142-152` starts `oryd/hydra:v26.2.0` without `WEBFINGER_OIDC_DISCOVERY_CLIENT_REGISTRATION_URL`, and `scripts/auth-oauth21-e2e.sh:279-280` hardcodes `REG_EP="$ISSUER/oauth2/register"` instead of discovering `registration_endpoint` from `$ISSUER/.well-known/oauth-authorization-server`, so CI/E2E never caught the omission.
- **Fix:**
  - Configure `webfinger.oidc_discovery.client_registration_url` in:
    - `deploy/gitops/base/values/hydra.values.yaml`: `https://oauth.bex.co/oauth2/register`
    - `deploy/gitops/overlays/local/values/hydra.values.yaml`: `http://oauth.bex.local/oauth2/register`
    - `scripts/dev-env/values/hydra.values.yaml`: `http://localhost:__HYDRA_PUBLIC_PORT__/oauth2/register`
    - `scripts/auth-oauth21-e2e.sh`: `-e WEBFINGER_OIDC_DISCOVERY_CLIENT_REGISTRATION_URL=$ISSUER/oauth2/register`
  - Update `scripts/auth-oauth21-e2e.sh:264-280` to fetch `$ISSUER/.well-known/oauth-authorization-server`, assert `registration_endpoint == "$ISSUER/oauth2/register"`, and drive DCR from that discovered URL instead of hardcoding it.
  - Add a rendered-manifest assertion in `scripts/gitops-validate.sh` (around line 1319 where `hydra-prod.yaml` is rendered) requiring `webfinger.oidc_discovery.client_registration_url` to be set whenever `oidc.dynamic_client_registration.enabled` is true.
  - Verify whether `webfinger.oidc_discovery.supported_scope` should also list `bex.read`, `bex.write`, `bex.sensitive`, `bex.cloud_agents` (optional companion for clients that consult AS metadata `scopes_supported` rather than RFC 9728 `scopes_supported`).
  - No REST, GraphQL, or UI API contract change; unblocks OAuth 2.1 discovery on both `/mcp` and `/mcp/cloud-agents`.
- **Blast radius:** Every discovery-driven OAuth 2.1 MCP client (Claude Code, VS Code, MCP Inspector, etc.) against production, `local-capd`, and `dev-N`. API-key bearers and the pre-registered Render CLI device client are unaffected.
- **Regression checks:**
  - `scripts/gitops-validate.sh` passes with the new Hydra `client_registration_url` guard (and fails if the key is removed).
  - `scripts/auth-oauth21-e2e.sh` passes while discovering `REG_EP` from `$ISSUER/.well-known/oauth-authorization-server`.
  - Post-sync live check: `python3 scripts/qa-mcp.py get-url https://oauth.bex.co/.well-known/oauth-authorization-server` and `/.well-known/openid-configuration` both return `"registration_endpoint": "https://oauth.bex.co/oauth2/register"`.
