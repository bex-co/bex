# 181 — `scope_matrix_overrides.go` omits `REST POST /v1/postgres/{id}/recovery-info`, misclassifying a pure read as `OpClassWrite` and blocking `bex.read`-only OAuth callers

Why: `lego/backend/internal/postgres/rest.go:329` mounts `POST /v1/postgres/{id}/recovery-info` directly on `s.RecoveryInfo` (pure read, `core.RelCanView`, zero writes — identical to `REST GET /v1/postgres/{id}/recovery`, `MCP get_postgres_recovery_info`, and `GQL Query.databaseRecoveryInfo`, all classified `core.OpClassRead`), and `key_permission_ops.go:1126` + `key_permission_ops_test.go:126` already classify it as a read-only POST route (`{core.KeyPostgresView}` in `writesThatOnlyRead`), yet `lego/backend/internal/api/scope_matrix_overrides.go` omits it — leaving `scope_matrix_ops.go:1101` at default `core.OpClassWrite` and blocking `bex.read`-only delegated OAuth callers at the API scope gate.
