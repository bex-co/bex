# 031 — `secrets.resolveValue` ignores `value` presence, so MCP `set_env_var` / `update_env_vars` and GraphQL `setEnvVar` / `setEnvVars` silently violate `value` XOR `generateValue`

Why: `secrets.resolveValue` and its `EnvVarView`/`EnvVarWrite` inputs drop whether `value` was actually present on the wire — so MCP `set_env_var` (on both services and build sources), MCP `update_env_vars`, and GraphQL `setEnvVar` / `setEnvVars` silently write `""` when both `value` and `generateValue` are omitted and silently mint a random secret when both `value: ""` and `generateValue: true` are sent, diverging from REST `PUT /v1/services/{id}/env-vars*`, REST `PUT /v1/build-sources/{id}/env-vars*`, MCP `patch_service_environment`, `create_web_service`, `create_build_source`, and all env-group write tools.

### MCP and GraphQL service/build-source env-var setters silently accept omitted and conflicting `value`/`generateValue` inputs

- **Context:** 2026-11-25, endpoints `/mcp` (`https://api.bex.co/mcp`), `/graphql` (`https://api.bex.co/graphql`), and REST `/v1/services/…` + `/v1/build-sources/…`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), run-minted all-permissions API key (revoked), disposable web service `srv-dc3hkjdksp0s73b5p1dg` and build source `bds-dc3hqbp5k4kc73dtaq8g` (both deleted and confirmed `404`)

- **Expected / actual:**
  - **Expected:** Under ADR006 (shared core semantics across REST, GraphQL, and MCP) and Render's `envVarInput` `oneOf` (`value` XOR `generateValue: true`), every env-var write path must reject entries that omit both `value` and `generateValue` (including `generateValue: false` without `value`) or pass both `value` (even `""`) and `generateValue: true` with `core.InvalidEnvVarValueInput` (`ENVIRONMENT_VALUE_INPUT_INVALID: provide exactly one of value or generateValue`), matching `patch_service_environment`, `create_web_service`, `create_build_source`, `create_env_group`, `set_env_group_var`, `update_env_group_vars`, and REST `PUT /v1/services/{id}/env-vars*` / `PUT /v1/build-sources/{id}/env-vars*`.
  - **Actual:**
    - MCP `set_env_var` (on both services and build sources) and `update_env_vars` return `200` (`isError` unset): omitting both writes `""`, and passing `value: ""` alongside `generateValue: true` silently generates and stores a random secret.
    - GraphQL `setEnvVar` and `setEnvVars` return `200` `{"data":{"setEnvVar":true}}` / `{"data":{"setEnvVars":true}}` with the exact same silent write / silent generation behavior.
    - Even when a non-empty `value` is combined with `generateValue: true`, `resolveValue` returns generic `bad request: env var "…" sets both value and generateValue — pick one` instead of the stable `ENVIRONMENT_VALUE_INPUT_INVALID` domain code used by every other env-var write surface.
    - REST `PUT /v1/services/{id}/env-vars*` and `PUT /v1/build-sources/{id}/env-vars*` reject all four invalid payloads with `400 bad_request` solely via the OpenAPI request validator, masking the same missing `ValueSet` tracking inside `secrets/rest.go`.

- **Attribution:** server (`lego/backend/internal/secrets`)
- **Root cause:**
  - `lego/backend/internal/secrets/service.go:65-82` (`EnvVarView`, `EnvVarWrite`) carry no `ValueSet bool` field to distinguish an explicit empty literal `value: ""` from an omitted `value`.
  - `lego/backend/internal/secrets/service.go:757-765` (`resolveValue(key, value string, generate bool)`) accepts `!generate` with an omitted `value` (passing `""` through) and only rejects `generate` when `value != ""` (missing explicit `value: ""`), and returns generic `core.ErrBadRequest` instead of `core.InvalidEnvVarValueInput(key)` (`lego/backend/internal/core/environmentpatch.go:55-63`).
  - `lego/backend/internal/secrets/mcp.go:52-56,71-76,151-158,201-204` (`envVarWriteArg.Value`, `setEnvVarArgs.Value`) declare non-pointer `string` instead of `*string` (compare `lego/backend/internal/envgroups/mcp.go:92`, which uses `Value *string` and sets `ValueSet: in.Value != nil`).
  - `lego/backend/internal/secrets/graphql.go:35-55,239-265` (`envVarsFromArgs`, `setEnvVar`) discard presence via `m["value"].(string)` and `gqlutil.Str(p.Args, "value")` instead of recording `_, valueSet := m["value"]` / `_, valueSet := p.Args["value"]` (compare `environmentPatchFromArgs` in the same file at `lego/backend/internal/secrets/graphql.go:136`).
  - `lego/backend/internal/secrets/rest.go:130-154` decodes `[]EnvVarView` and `{Value string; GenerateValue bool}` without tracking `ValueSet` (currently masked on `/v1/services/{id}/env-vars*` and `/v1/build-sources/{id}/env-vars*` only by the OpenAPI request validator).
- **Fix:**
  - Add `ValueSet bool` (`json:"-"`) to `EnvVarView` (with a custom `UnmarshalJSON` or pointer decode in `rest.go` like `core.EnvVarPatch.UnmarshalJSON` at `core/environmentpatch.go:42-52`) and `EnvVarWrite` in `lego/backend/internal/secrets/service.go`.
  - Update `resolveValue(key, value string, valueSet, generate bool)` so `hasValue := valueSet || value != ""` enforces `hasValue != generate` — returning `core.InvalidEnvVarValueInput(key)` (`ENVIRONMENT_VALUE_INPUT_INVALID`) when both are set or neither is set (matching `core.ApplyEnvVarPatch` and `apps.render.go:77-90`). Keep `SeedEnvVars` / internal callers that pass literal maps setting `ValueSet: true` (audit all callers of `SetEnvVar`, `SetEnvVars`, and `resolveValue`).
  - Switch `envVarWriteArg.Value` and `setEnvVarArgs.Value` in `lego/backend/internal/secrets/mcp.go` to `*string` (verify schema cleanliness under `TestMCPArgumentErrorsNeverEchoTheValue` and `TestMCPSchemasHaveNoLeakedTagDirectives`), pass `ValueSet: in.Value != nil` (treating explicit JSON `null` as unset / rejected when `generateValue` is false), and track `_, ok := m["value"]` (with non-nil value check) in `lego/backend/internal/secrets/graphql.go` (`envVarsFromArgs` and `setEnvVar`) and pointer decode in `lego/backend/internal/secrets/rest.go`.
