# 180 — `REST POST /v1/api-keys` and `PATCH /v1/api-keys/{id}` omit `core.WithStrictJSONDecoding`, silently accepting unknown/misspelled `permissions` fields as empty grants and wiping existing keys' permissions on `PATCH`

Why: `lego/backend/internal/apikeys/rest.go:39,85` decodes JSON request bodies via plain `core.DecodeJSON(r, &req)` without `core.WithStrictJSONDecoding(r.Context())` (and `/v1/api-keys` is a bex extension outside Render's OpenAPI spec, so `renderRequestValidator` never enables strict decoding on it). Any unknown or misspelled field inside `permissions` (for example `{"permissions":{"grant":[...]}}` instead of `grants`, or `{"permissions":{"services":"read"}}`) is silently dropped by `encoding/json`, unmarshaling `core.KeyGrant{All: false, Grants: nil}` (zero permissions) — returning `201 Created` on `POST` with a broken zero-permission key, and returning `200 OK` on `PATCH` while **silently wiping every permission on a live API key to `{"all":false,"grants":[]}`**; additionally `PATCH` at `:85-87` misreports any decode error as `"permissions: required"`.

- **Attribution:** server (`lego/backend/internal/apikeys`)
- **Root cause:**
  - `lego/backend/internal/apikeys/rest.go:32-49` (`POST /v1/api-keys`) calls `core.DecodeJSON(r, &req)` without `r = r.WithContext(core.WithStrictJSONDecoding(r.Context()))` and discards the decode error (`core.WriteErr(w, core.ErrBadRequest)` at `:40`).
  - `lego/backend/internal/apikeys/rest.go:81-95` (`PATCH /v1/api-keys/{id}`) calls `core.DecodeJSON(r, &req)` without `core.WithStrictJSONDecoding(r.Context())` and collapses `err != nil` and `req.Permissions == nil` into a single `"permissions: required"` error (`:85-87`).
  - Because `core.KeyGrant` (`lego/backend/internal/core/keygrant.go`) treats `{All: false, Grants: []}` as a valid empty grant ("Clear all"), silently dropping unknown JSON keys inside `permissions` turns any typo or wrong-shape object into a valid empty grant.
- **Fix:**
  - Wrap `r = r.WithContext(core.WithStrictJSONDecoding(r.Context()))` before `core.DecodeJSON(r, &req)` in both `POST /v1/api-keys` (`lego/backend/internal/apikeys/rest.go:39`) and `PATCH /v1/api-keys/{id}` (`:85`).
  - Surface the decode error on both routes (`fmt.Errorf("%w: %s", core.ErrBadRequest, err)` when `err != nil`), keeping `"permissions: required"` exclusively for `req.Permissions == nil` after a clean decode on `PATCH`.
  - While touching `apikeys/rest.go`, audit `sshkeys/rest.go` (same non-OpenAPI bex-extension family) to confirm whether `POST /v1/ssh-keys` also omits `core.WithStrictJSONDecoding`.
