# 191 — `github` browser-only connect/claim/selection verbs (`StartConnect`, `StartClaim`, `GetClaimSelection`, `SelectClaim`) accept API keys, minting uncompletable Hydra-client-bound transactions across REST and GraphQL

Why: `github/mcp.go:32-38` explicitly excludes `StartConnect`, `StartClaim`, `GetClaimSelection`, and `SelectClaim` from MCP because they are halves of a browser OAuth ceremony whose callback (`consumeCallbackProofs`, `github/service.go:327`) enforces `txn.Subject == caller` against the browser's Kratos session cookie (`identity.Subject`). Yet `StartConnect` (`github/service.go:217-243`), `StartClaim` (`:404-427`), `GetClaimSelection` (`:543`), and `SelectClaim` (`:595`) never reject API-key callers (unlike `accounts.directSession`), and `keyPermissionOps` (`lego/backend/internal/api/key_permission_ops.go:83,85,211,402,903,904,1106-1108`) maps all 9 connect/claim/selection/callback routes to `core.KeyGitManage`. Calling `POST /v1/git/connect`, `POST /v1/git/claim`, `connectGit`, or `claimGit` with an API key succeeds (`200 OK`), persists a `github_connect_transactions` row with `subject = <Hydra client UUID>`, and returns a signed GitHub install/OAuth URL that **can never succeed** in any browser (always failing with `403: this GitHub connect link was started by a different bex user`), while writing `"status": "success"` audit rows (`github.StartConnect`, `github.StartClaim`).

- **Attribution:** server (`lego/backend/internal/github`, `lego/backend/internal/api`)
- **Root cause:**
  - `lego/backend/internal/github/service.go:236-243` (`StartConnect`), `:416-423` (`StartClaim`), and `:666-688` (`loadSelection`, used by `GetClaimSelection` `:543` and `SelectClaim` `:595`) check only `id.Subject != ""` without checking `id.Method == core.MethodSession && id.Human` (or refusing `id.IsAPIKey()` / non-session identities). Because `GET /v1/git/callback` authenticates the returning browser strictly via the `SameSite=Lax` Kratos session cookie (`github/rest.go:143-146`) and compares `txn.Subject != caller` (`github/service.go:327`), any transaction minted by an API key (whose `id.Subject` is its Hydra client UUID) is permanently uncompletable.
  - `lego/backend/internal/api/key_permission_ops.go:83,85,211,402,903,904,1106-1108` maps all 9 browser-ceremony operations (`GQL Mutation.{connectGit,claimGit,selectGitClaim}`, `GQL Query.gitClaimSelection`, `REST POST /v1/git/{connect,claim,claim/selections/{id}}`, `REST GET /v1/git/{callback,claim/selections/{id}}`) to `core.KeyGitManage`, encouraging scoped keys to be granted `git: read_write` for flows they can never complete (`core/keygrant.go:270` describes `KeyGitManage` as "Connect and disconnect Git providers").
- **Fix:**
  - Require a signed-in human browser session (`id.Human && id.Method == core.MethodSession`, matching `accounts.directSession`) after `Authorize` in `StartConnect`, `StartClaim`, `GetClaimSelection`, and `SelectClaim` (returning a clear `403` coded error such as `GIT_SESSION_REQUIRED`, and deferring allowed-write audit per `w31/192` so refused API keys emit zero `"success"` rows).
  - Reclassify the 9 browser-only connect/claim/selection/callback operations in `lego/backend/internal/api/key_permission_ops.go` from `core.KeyGitManage` to `core.KeyNoGrant` (keeping `DELETE /v1/git/connection`, `DELETE /v1/git/connections/{installationId}`, and `Mutation.disconnectGit` under `core.KeyGitManage`, and updating `core.KeyGitManage`'s description in `core/keygrant.go:270` to "Disconnect Git providers" or matching what keys can perform).
  - Surface impact: REST and GraphQL fail fast with `403` for API keys and machine tokens instead of minting dead transaction rows and broken GitHub URLs; browser dashboard sessions are unaffected; MCP already omits these verbs.
