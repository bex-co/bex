# 102 — `postgres.Service.updatePostgres` and `keyvalue.Service.updateKeyValue` unconditionally patch Kubernetes CRs and bump `updatedAt` on empty (`{}`) and no-op updates across MCP and REST

Why: `postgres.Service.updatePostgres` (`lego/backend/internal/postgres/service.go:1836-1871`) and `keyvalue.Service.updateKeyValue` (`lego/backend/internal/keyvalue/service.go:1357-1445`) never check whether `PostgresPatch` / `KeyValuePatch` leaves the stored spec unchanged, unconditionally calling `resourcemeta.Touch(..., s.Now())` and `s.PatchObject(...)` on empty `{}` or identical-value patches — churning Kubernetes CR resourceVersions and advancing `updatedAt` on every call across MCP (`update_postgres`, `update_key_value`) and REST (`PATCH /v1/postgres/{id}`, `PATCH /v1/key-value/{id}`), diverging from `update_service` (`ApplyServicePatch`).

- **Root cause:**
  - `lego/backend/internal/postgres/service.go:1836-1871` (`updatePostgres`) calls `s.patchDatabaseToPlan` unconditionally, which invokes `resourcemeta.Touch(d, s.Now())` and `s.PatchObject(...)` even when `patch` has all `nil` fields or leaves `d.Spec` byte-equal.
  - `lego/backend/internal/keyvalue/service.go:1357-1445` (`updateKeyValue` → `patchKeyValueLocked`) similarly calls `resourcemeta.Touch(kv, s.Now())` and `s.PatchObject(...)` unconditionally even when `patch` has all `nil` fields or leaves `kv.Spec` unchanged.
- **Fix:**
  - In `postgres.Service.updatePostgres` (`lego/backend/internal/postgres/service.go:1836-1871`) and `keyvalue.Service.updateKeyValue` (`lego/backend/internal/keyvalue/service.go:1357-1434`), after running authorization (`fetchToChange`) and all pre-write validation/policy checks, apply the patch to a `DeepCopy()` and compare the candidate `Spec` against the current `Spec` (e.g. `reflect.DeepEqual` or explicit spec equality, also respecting `patch.EnableHighAvailability` dry-run echo). When nothing changes, return the current view without calling `resourcemeta.Touch`, `s.PatchObject`, or `recordUpdateEffects`.
  - Surface impact: fixes MCP (`update_postgres`, `update_key_value`), REST (`PATCH /v1/postgres/{id}`, `PATCH /v1/key-value/{id}`, `PATCH /v1/redis/{id}`), and any GraphQL single-field setters delegating to `UpdatePostgres`/`UpdateKeyValue`.
