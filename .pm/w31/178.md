# 178 — `sandbox.Service.authorizeExecTarget` omits uncached `AuthorizeFreshOn` on the workspace for non-agent sandboxes, diverging from `authorizeFileTarget` across MCP `sandbox_exec` and REST `/v1/sandboxes/{id}/{exec,runs}`

Why: `sandbox.Service.authorizeFileTarget` (`lego/backend/internal/sandbox/file_connect.go:118,134`) explicitly re-asserts `s.AuthorizeFreshOn(ctx, core.RelCanCreate, core.WorkspaceObject(ws))` uncached before minting a file upload/download token ("Both reading credentials and writing executable content require `can_create`; the fresh check makes a role revoked since mint effective at redemption"), yet sibling `sandbox.Service.authorizeExecTarget` (`lego/backend/internal/sandbox/exec.go:252,281-285`) — which gates arbitrary command execution via MCP `sandbox_exec`, REST `POST /v1/sandboxes/{id}/exec`, and `POST /v1/sandboxes/{id}/runs/{operation}/token` (and mints a signed gateway exec / connect token) — calls `AuthorizeFreshOn` **only** when `metadataAgentSession` is non-empty, leaving ordinary sandboxes on cached `s.Authorize(ctx, core.RelCanCreate)` alone.

### Non-agent sandbox command execution (`sandbox_exec`, `POST /v1/sandboxes/{id}/exec`, `POST /v1/sandboxes/{id}/runs/{operation}/token`) relies solely on cached OpenFGA authorization
