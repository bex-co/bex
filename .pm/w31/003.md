# 003 — MCP `list_logs` and `list_log_label_values` return `"internal error"` on invalid `startTime` or `endTime`

Why: `lego/backend/internal/logs/mcp.go:114,121` wraps `time.Parse` errors in unclassified `core.Err(...)` instead of `core.ErrBadRequest`, so invalid timestamps on `list_logs` and `list_log_label_values` are scrubbed to `"internal error"` instead of a readable bad-request message.

### `list_logs` and `list_log_label_values` return `"internal error"` for malformed `startTime`/`endTime`

- **Expected / actual:**
  - **Expected:** Per Render's MCP server (`render-oss/render-mcp-server` `pkg/logs/tools.go`) and bex's own sibling MCP tools (`list_deploys`, `list_events`, `get_metrics`, `list_agent_sessions`), a malformed `startTime` or `endTime` must return a tool error (`isError: true`) naming the bad argument and expected RFC3339 format without echoing the raw value — e.g. `bad request: startTime must be an RFC3339 timestamp (e.g. 2026-01-02T15:04:05Z)`.
  - **Actual:** All four calls (`list_logs` with bad `startTime`, `list_logs` with bad `endTime`, `list_log_label_values` with bad `startTime`, `list_log_label_values` with bad `endTime`) return `isError: true` with bare text `"internal error"`, misleading agents into retrying or treating a client timestamp formatting mistake as a server outage. Meanwhile REST `GET /v1/logs` and `GET /v1/logs/values` return `400 bad_request` (`invalid query parameter "startTime"`), GraphQL `logs` returns `bad request: startTime: …`, and MCP `list_deploys` / `list_events` / `get_metrics` / `list_agent_sessions` all return `bad request: <field> must be an RFC3339 timestamp (e.g. 2026-01-02T15:04:05Z)`.

  - `POST https://api.bex.co/mcp` (`list_log_label_values`, `endTime: "not-a-timestamp"`) → `200` (`rndr-id: cc08fbc4-1cf5-1720`): `{"jsonrpc":"2.0","id":1072832161,"result":{"content":[{"type":"text","text":"internal error"}],"isError":true}}`

- **Attribution:** server (`lego/backend/internal/logs`)
- **Root cause:**
  - `lego/backend/internal/logs/mcp.go:111-125` (`logFilters.query`) calls `time.Parse(time.RFC3339, f.StartTime)` and `time.Parse(time.RFC3339, f.EndTime)` and returns `core.Err("startTime: " + err.Error())` / `core.Err("endTime: " + err.Error())`.
  - `core.Err(...)` produces an unclassified `errors.New(...)` that does not wrap `core.ErrBadRequest`. The MCP error sanitizer (`mcpCallError` in `lego/backend/internal/api/mcp_workspace.go`) scrubs every unclassified error to `"internal error"` so internal faults cannot leak details.
  - A codebase-wide grep for `core.Err(` shows `logs/mcp.go:114,121` are the only two user-input validation sites using `core.Err(...)` instead of `core.ErrBadRequest`.
- **Fix:**
  - Replace the two hand-rolled `time.Parse` blocks in `lego/backend/internal/logs/mcp.go:111-125` with `core.ParseTime("startTime", f.StartTime)` and `core.ParseTime("endTime", f.EndTime)` (`lego/backend/internal/core/pagination.go:177-186`), which wrap `core.ErrBadRequest` and emit `bad request: <field> must be an RFC3339 timestamp (e.g. 2026-01-02T15:04:05Z)` without echoing the caller's raw input value.
  - Optional companion cleanup: check `core.ParseTimeWindow` (`lego/backend/internal/core/http.go:595-607`), used by GraphQL `logs` (`logs/graphql.go:380`) and datastore log tools (`get_postgres_logs`, `get_key_value_logs`), which currently wraps `core.ErrBadRequest` around Go's raw `time.Parse` error and echoes the caller's input string; delegating `ParseTimeWindow` to `ParseTime` unifies the non-echoing message across GraphQL and MCP datastore logs too.
  - REST is unaffected (already returns `400 bad_request`).
- **Blast radius:** `lego/backend/internal/logs/mcp.go` (`list_logs` and `list_log_label_values`, both shared Render MCP tools). If `core.ParseTimeWindow` is also updated, check callers in `logs/graphql.go`, `postgres/mcp.go`, and `keyvalue/mcp.go` and their unit tests.
