# 085 — `apps.Service.SetIdleTTL` and `checkIdleTTL` never validate service type or plan, so MCP `update_service`, REST `PATCH /v1/services/{id}`, and GraphQL `setIdleTimeout` accept and persist `idleTTLSeconds` on static sites and paid services

Why: `checkIdleTTL` (`lego/backend/internal/apps/settings_check.go:194-199`, called by `apps.Service.SetIdleTTL` at `lego/backend/internal/apps/service.go:5227-5248` and `servicePatchTable` at `lego/backend/internal/apps/settings.go:289-298`) checks only `0 <= seconds <= MaxIdleTTLSeconds` and never inspects `a.Spec.Type` or `a.Spec.Tier`, whereas the operator's `autoSleepWindow` / `autoSleepEligible` (`lego/operator/internal/controller/app_controller.go:2930-2948`) applies `idleTTLSeconds` exclusively to free-tier `web_service` apps — violating `settings_check.go`'s per-type applicability rule ("nothing accepted is ignored") across MCP, REST, and GraphQL.

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `checkIdleTTL` (`lego/backend/internal/apps/settings_check.go:194-199`) takes only `seconds int32` — not `a *appv1alpha1.App` — and validates only `seconds < 0 || seconds > MaxIdleTTLSeconds`.
  - Both `apps.Service.SetIdleTTL` (`lego/backend/internal/apps/service.go:5227-5234`) and `servicePatchTable`'s `IdleTTLSeconds` row (`lego/backend/internal/apps/settings.go:289-298`) call `checkIdleTTL` without checking `a.Spec.Type` or `a.Spec.Tier` (note `Plan` runs ahead of `IdleTTLSeconds` in `servicePatchTable`, so passing `probe` to `checkIdleTTL(probe, *p.IdleTTLSeconds)` automatically validates against the post-patch plan in multi-field updates).
- **Fix:**
  - Update `checkIdleTTL` (`lego/backend/internal/apps/settings_check.go:194-199`) to take `(a *appv1alpha1.App, seconds int32)`:
    1. Keep the range check `seconds < 0 || seconds > MaxIdleTTLSeconds`.
    2. When `seconds > 0`: refuse non-web services (`if t := effectiveType(a.Spec.Type); t != appv1alpha1.TypeWebService`) with `core.ErrBadRequest` (`"idleTTLSeconds applies only to a free web_service; a %s does not auto-sleep"`), and refuse paid plans (`if !freeTier(a.Spec.Tier)`) with `core.ErrBadRequest` (`"idleTTLSeconds applies only to a free web_service; paid services do not auto-sleep"`).
    3. Keep `seconds == 0` allowed on every service type and plan so any existing stored value can be cleared to the default without failing (and verify existing tests in `lego/backend/internal/apps/apps_test.go` and `compound_publication_test.go` — update any test fixture that sets `IdleTTLSeconds > 0` on a paid `sampleApp` if its default tier is paid, or ensure free-tier fixture matches the rule).
  - Pass `a` / `probe` from `SetIdleTTL` (`apps/service.go:5232`) and `servicePatchTable` (`apps/settings.go:293`).
  - Surface impact: protects MCP `update_service`, REST `PATCH /v1/services/{id}`, and GraphQL `setIdleTimeout` uniformly from one helper.
