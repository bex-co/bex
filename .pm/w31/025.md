# 025 — `core.ResolveAllowListPatch` names nonexistent `ipAllowListEntries` on conflict across all four MCP `update_*` tools (`update_service`, `update_postgres`, `update_key_value`, `update_environment`)

Why: Every folded MCP patch tool (`update_service`, `update_postgres`, `update_key_value`, `update_environment`) names its dual allowlist arguments `ipAllowList` and `ipAllowListCidrs`, yet `core.ResolveAllowListPatch` delegates directly to `core.ResolveAllowListInputs`, which hardcodes the GraphQL/create field pair `"ipAllowList and ipAllowListEntries are set to conflicting values"` — pointing MCP callers at a field (`ipAllowListEntries`) that does not exist in any of those tools' schemas.
