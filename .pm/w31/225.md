# 225 — `apikeys.Service.RevokeOrganizationAPIToken` omits `AuthorizeMintClass` and `OpClassMint`, allowing delegated third-party OAuth clients (`bex.write`) to revoke organization audit-log API keys

Why: Durable org-level and object-storage credential lifecycle verbs require human-only `AuthorizeMintClass(ctx)` and `core.OpClassMint` (`apikeys/organizations.go:128` `ProvisionOrganizationAuditLogToken` + `scope_matrix_overrides.go:62`; `api/object_storage_admin.go:200,259` `CreateAccessKey` / `RevokeAccessKey` + `scope_matrix_overrides.go:54-57`: "creating and revoking one are human-only, with the mint class"), yet `apikeys.Service.RevokeOrganizationAPIToken` (`lego/backend/internal/apikeys/organizations.go:213-227`) omits `s.AuthorizeMintClass(ctx)` and `scope_matrix_overrides.go` omits `"GQL Mutation.revokeOrganizationAPIToken"` (leaving it at `core.OpClassWrite` in `scope_matrix_ops.go:167`) — allowing any consented third-party OAuth client holding `bex.write` to revoke an organization's audit-log API keys and blind external SIEM/compliance collection.

### Delegated third-party OAuth clients (`bex.write`) bypass `AuthorizeMintClass` and `OpClassMint` on `Mutation.revokeOrganizationAPIToken`

- **Severity:** major
- **Versions:** deployed pin `682f8608ed` (`2bce5149f7e1`, active on production during run; zero diff in `lego/backend/internal/apikeys/organizations.go` and `lego/backend/internal/api/scope_matrix_overrides.go` vs `origin/main` `240dab3c42`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`

- **Expected / actual:**
  - **Expected:** Matching `ProvisionOrganizationAuditLogToken` (`apikeys/organizations.go:128`, `scope_matrix_overrides.go:62`) and `objectStorageAdmin.RevokeAccessKey` (`object_storage_admin.go:259`, `scope_matrix_overrides.go:55,57`), revoking an organization audit-log API key must enforce `s.AuthorizeMintClass(ctx)` and be classified `core.OpClassMint` in `scope_matrix_overrides.go` (unlike workspace `RevokeAPIKey`, which deliberately permits a workspace key to revoke itself during CLI logout, an organization audit-log token is read-only for audit logs and is never self-revoked — `key_permission_ops.go:65` maps `revokeOrganizationAPIToken` to `{core.KeyNoGrant}`). Calling it with an API key or a third-party delegated OAuth token must return `403 FORBIDDEN` before touching `authorizeOrganizationKeys` or Postgres.
  - **Actual:**
    - `lego/backend/internal/apikeys/organizations.go:213-227` (`RevokeOrganizationAPIToken`) calls `s.authorizeOrganizationKeys(ctx, orgID)` with no `s.AuthorizeMintClass(ctx)` check.
    - `lego/backend/internal/api/scope_matrix_ops.go:167` classifies `GQL Mutation.revokeOrganizationAPIToken` as `core.OpClassWrite` instead of `core.OpClassMint`.
    - Live production confirmed an API key bypassed `AuthorizeMintClass` and entered `authorizeOrganizationKeys`, returning `ORGANIZATION_NOT_FOUND` rather than `403 FORBIDDEN` — and a delegated third-party OAuth token with `bex.write` acting for an Org Owner passes `authorizeOrganizationKeys` and revokes live org audit-log tokens.
- **Wire evidence:**

- **Attribution:** server (`lego/backend/internal/apikeys`, `lego/backend/internal/api`)
- **Root cause:**
  - `w1/m657` added `AuthorizeMintClass(ctx)` and `OpClassMint` (`scope_matrix_overrides.go:62`) to `ProvisionOrganizationAuditLogToken` (`apikeys/organizations.go:128`) but omitted both from its paired revoke mutation `RevokeOrganizationAPIToken` (`:213-227`).
- **Fix:**
  - Call `if err := s.AuthorizeMintClass(ctx); err != nil { return err }` at the start of `RevokeOrganizationAPIToken` in `lego/backend/internal/apikeys/organizations.go:213` (before `s.authorizeOrganizationKeys`).
  - Add `"GQL Mutation.revokeOrganizationAPIToken": core.OpClassMint` to `scopeClassOverrides` in `lego/backend/internal/api/scope_matrix_overrides.go` and update `lego/backend/internal/api/scope_matrix_ops.go:167`.
  - Surface impact: GraphQL `Mutation.revokeOrganizationAPIToken` only (organization audit-log tokens have no REST or MCP revoke route); human browser sessions and platform-approved clients (`bex` CLI) continue to work unchanged.
