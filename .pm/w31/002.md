# 002 — RFC 9728 path-inserted metadata `GET /.well-known/oauth-protected-resource/mcp` returns 404

Why: `bex-api` serves RFC 9728 Protected Resource Metadata at root `/.well-known/oauth-protected-resource` and at `/.well-known/oauth-protected-resource/mcp/cloud-agents`, but returns `404` at `/.well-known/oauth-protected-resource/mcp`, the path-inserted well-known URI RFC 9728 § 3.1 defines for `https://api.bex.co/mcp`.

### `GET /.well-known/oauth-protected-resource/mcp` returns `404` while root and `/mcp/cloud-agents` return `200`

- **Severity:** major
- **Versions:** deployed pin `4b533337ab` (`7b046987bcd8`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-25, endpoints `/mcp` and `/mcp/cloud-agents` (`https://api.bex.co`), anonymous (unauthenticated OAuth 2.1 discovery)
- **Repro:**
  ```sh
  python3 scripts/qa-mcp.py get-url https://api.bex.co/.well-known/oauth-protected-resource
  python3 scripts/qa-mcp.py get-url https://api.bex.co/.well-known/oauth-protected-resource/mcp/cloud-agents
  python3 scripts/qa-mcp.py get-url https://api.bex.co/.well-known/oauth-protected-resource/mcp
  python3 scripts/qa-mcp.py --url https://api.bex.co/mcp/cloud-agents --anonymous initialize
  ```
- **Expected / actual:**
  - **Expected:** Per RFC 9728 § 3.1 ("Obtaining Protected Resource Metadata") and the MCP Authorization Specification (2025-06-18 / 2025-11-25), for a protected resource URL containing a path component (`https://api.bex.co/mcp`), inserting `/.well-known/oauth-protected-resource` between the host and path yields `https://api.bex.co/.well-known/oauth-protected-resource/mcp`, which must answer `200` with the same RFC 9728 protected-resource metadata document as the root fallback and `/mcp/cloud-agents`.
  - **Actual:**
    - `GET https://api.bex.co/.well-known/oauth-protected-resource` → `200` (238 ms)
    - `GET https://api.bex.co/.well-known/oauth-protected-resource/mcp/cloud-agents` → `200` (248 ms)
    - `GET https://api.bex.co/.well-known/oauth-protected-resource/mcp` → **`404`** (254 ms), `{"error":"not found","id":"not_found","message":"not found"}`
    - Also observed: anonymous `POST https://api.bex.co/mcp/cloud-agents` returns `401` with `WWW-Authenticate: Bearer resource_metadata="https://api.bex.co/.well-known/oauth-protected-resource"` (root URL, same as `/mcp`).
- **Wire evidence:**
  - `GET https://api.bex.co/.well-known/oauth-protected-resource/mcp` → `404` (`content-type: application/json`, `rndr-id: 3c3f784a-3288-15c6`): `{"error":"not found","id":"not_found","message":"not found"}`
  - Control `GET https://api.bex.co/.well-known/oauth-protected-resource/mcp/cloud-agents` → `200` (`rndr-id: ae1a32c5-963c-6780`): `{"authorization_servers":["https://oauth.bex.co"],"bearer_methods_supported":["header"],"resource":"https://api.bex.co/mcp","scopes_supported":["bex.read","bex.write","bex.sensitive","bex.cloud_agents"]}`
- **Attribution:** server (`lego/backend/internal/api`)
- **Root cause:**
  - `lego/backend/internal/api/server.go:1839-1860` registers only two protected-resource metadata routes:
    - `GET /.well-known/oauth-protected-resource` (`:1840`)
    - `GET /.well-known/oauth-protected-resource` + `cloudAgentsMountPath` (`:1852`)
  - It never mounts `GET /.well-known/oauth-protected-resource/mcp` (the path-inserted form for `BEX_OAUTH_RESOURCE = https://api.bex.co/mcp`).
  - `lego/backend/internal/api/alwayspublic_guard_test.go:124-125` mirrors that two-route census, and `lego/backend/internal/api/oauth_discovery_test.go:106-157` tests only the root endpoint.
- **Fix:**
  - Mount `GET /.well-known/oauth-protected-resource/mcp` in `lego/backend/internal/api/server.go:1839-1860` (using one shared handler helper for root, `/mcp`, and `cloudAgentsMountPath`) returning the identical RFC 9728 JSON document when `s.resourceMetadataURL() != ""` (and `404` when discovery is unconfigured).
  - Register `"GET /.well-known/oauth-protected-resource/mcp"` in `alwaysPublicInventory` (`lego/backend/internal/api/alwayspublic_guard_test.go:124-125`) and update the public-route inventory prose in `lego/backend/internal/api/AGENTS.md:16`.
  - Add unit tests in `lego/backend/internal/api/oauth_discovery_test.go` covering `GET /.well-known/oauth-protected-resource/mcp` (200 when configured, 404 when unconfigured) and assert it in `scripts/auth-oauth21-e2e.sh:264-273`.
  - Check whether `WWW-Authenticate` on `/mcp` and `/mcp/cloud-agents` should keep advertising root or advertise their path-inserted URLs (`server.go:1967-1976`, `auth.go:257`); serving `200` at all three well-known paths (root, `/mcp`, `/mcp/cloud-agents`) is safe and backward-compatible regardless.
  - No REST, GraphQL, or UI surface change; MCP discovery only.
- **Blast radius:** `lego/backend/internal/api/server.go`, `alwayspublic_guard_test.go`, `oauth_discovery_test.go`, `internal/api/AGENTS.md`, `scripts/auth-oauth21-e2e.sh`. Unauthenticated read-only metadata identical to the existing two routes.
