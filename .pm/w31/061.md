# 061 — Scoped resource-manage API keys bypass `services.env.set`, `buildsources.manage`, and `projects.move` via composite create inputs on services, sandbox groups, Postgres, and Key Value across MCP, REST, and GraphQL

Why: `apps.Service.Create` (`apps/service.go:2333-2450`), `sandbox.Service.CreateGroup` (`sandbox/groups.go:278-308`), `postgres.Service.CreatePostgres`/`Recover` (`postgres/service.go:925-966`, `postgres/recovery.go:420-442`), and `keyvalue.Service.CreateKeyValue` (`keyvalue/service.go:662-707`) perform no `KeyGrant` checks on their embedded cross-area arguments (`envVars`, `secretFiles`, `buildSourceId`, `environmentId`), letting scoped API keys holding only one resource's `read_write` grant write service secrets without `services.env.set`, link build sources without `buildsources.*`, and place resources into project environments without `projects.move` across MCP, REST, and GraphQL.

- **Attribution:** server (`lego/backend/internal/{apps,sandbox,postgres,keyvalue,core}`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go` checks only the primary manage action statically at dispatch time (`KeyServicesManage`, `KeySandboxesGroups`, `KeyPostgresManage`, `KeyKeyValueManage`).
  - `apps.Service.Create` (`apps/service.go:2333-2450`) never checks `s.KeyGrant(ctx)` for `req.Env`/`req.SecretFiles` (`KeyServicesEnvSet`), `req.BuildSourceID` (`KeyBuildSourcesManage`), or `req.EnvironmentID` (`KeyProjectsMove`).
  - `core.ResolveEnvironmentForCreate` (called by `apps/service.go`, `sandbox/groups.go:318`, `postgres/service.go:963`, `postgres/recovery.go:439`, `keyvalue/service.go:704`, and `envgroups/service.go`) checks workspace membership and protected-environment Admin role, but never checks `KeyProjectsMove` on scoped API keys.
- **Fix:**
  - Add a shared helper on `core.Base` (e.g. `RequireKeyActions(ctx context.Context, actions ...core.KeyAction) error`) that returns `nil` for non-key callers and `All` keys, and `core.NewKeyPermissionDeniedError(missing)` when any action is absent from the key's grant.
  - Enforce it in:
    - `apps.Service.Create` (`apps/service.go`): require `core.KeyServicesEnvSet` when `len(req.Env) > 0 || len(req.SecretFiles) > 0`, `core.KeyBuildSourcesManage` when `strings.TrimSpace(req.BuildSourceID) != ""`, and `core.KeyProjectsMove` when `strings.TrimSpace(req.EnvironmentID) != ""` (note: check whether Blueprint apply/sync internal calls should bypass via acting-tenant/internal context or already hold all 8 apply actions at dispatch — `approve_blueprint`/`sync_blueprint`/`deploy` already require all 8 actions including `KeyServicesEnvSet` and `KeyProjectsManage`, and `projects: read_write` bundles `KeyProjectsMove`; verify `keyPermissionOps` for Blueprints includes `KeyProjectsMove` too if needed).
    - `sandbox.Service.CreateGroup`, `postgres.Service.CreatePostgres`, `postgres.Service.Recover` (when `req.EnvironmentID != ""` differs from empty/inherited, or whenever explicitly placing into an environment), and `keyvalue.Service.CreateKeyValue`: require `core.KeyProjectsMove` when `strings.TrimSpace(req.EnvironmentID) != ""`.
  - Surface impact: protects MCP, REST, and GraphQL uniformly while preserving single-area scoped key creates when no cross-area composite field is supplied.
