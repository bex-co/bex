# 086 — MCP `update_environment` and `update_project` commit partial writes when a later membership field fails, and `update_environment` silently returns 200 on empty patches

Why: `environments.Service.applyEnvironmentPatch` (`lego/backend/internal/environments/mcp.go:136-165`) and `projects.Service.applyProjectPatch` (`lego/backend/internal/projects/mcp.go:132-146`) queue `Update`/`Rename` ahead of `SetServices`/`SetDatabases`/`SetKeyValues`/`SetEnvGroups` on `core.PatchOps` (`lego/backend/internal/core/patchops.go:46-59`) with zero preflight — so a failed multi-field patch permanently commits the rename, ACL change, and earlier membership replacements before failing on a later invalid ID, and an empty MCP `update_environment` falls through to `s.Get` (`200 OK`, `RelCanView`) instead of matching REST `PATCH /v1/environments/{id}` and GraphQL `updateEnvironment` (`400 bad request: nothing to update`).

### Multi-field `update_environment` and `update_project` persist partial mutations on error, and empty `update_environment` diverges from REST and GraphQL

- **Attribution:** server (`lego/backend/internal/environments` and `lego/backend/internal/projects`)
- **Root cause:**
  - `environments.Service.applyEnvironmentPatch` (`lego/backend/internal/environments/mcp.go:136-165`) and `projects.Service.applyProjectPatch` (`lego/backend/internal/projects/mcp.go:132-146`) pass independent write verbs (`Update`/`Rename`, `SetServices`, `SetDatabases`, `SetKeyValues`, `SetEnvGroups`) into `core.PatchOps.Run` (`lego/backend/internal/core/patchops.go:46-59`). `PatchOps.Run` executes each verb in order with no preflight pass, so any validation, workspace-ownership, or protected-environment refusal on a later field fires only after earlier verbs have already persisted to Postgres and Kubernetes.
  - When no field is supplied, `PatchOps.Run` invokes its fallback `s.Get(ctx, in.ID)` (`environments/mcp.go:164`, `projects/mcp.go:145`), bypassing both `environments.Service.Update`'s empty-patch `400` (`environments/service.go:975-977`) and `RelCanCreate` write authorization.
- **Fix:**
  - Add a read-only preflight before the first write in both `environments.Service.applyEnvironmentPatch` (`lego/backend/internal/environments/mcp.go:136-165`) and `projects.Service.applyProjectPatch` (`lego/backend/internal/projects/mcp.go:132-146`), mirroring `apps.Service.preflightServicePatch` (`lego/backend/internal/apps/settings.go:701-747`):
    1. Validate and authorize the container (`RelCanCreate`, plus `RelCanManage` when ACL-bearing on `update_environment`), name/ACL rules, plan gates (`RequireInboundIPRules`/`RequireNetworkIsolation`), and every supplied membership list (`serviceIds`, `databaseIds`, `keyValueIds`, `envGroupIds` — existence/ownership in the target workspace, exit/entry protected-environment guards) **before** executing any write.
    2. Only after every present field passes preflight, apply the writes in order.
  - On an empty `update_environment` patch (no field present), either return the same `core.ErrBadRequest` (`"nothing to update"`) that `environments.Service.Update` returns on REST and GraphQL, or ensure write authorization (`RelCanCreate`) is enforced consistently (documenting the choice if `PatchOps`'s read-only no-op contract is kept on MCP).
  - Surface impact: affects MCP `update_environment` and `update_project` directly (the two surfaces that combine container metadata/ACL with membership lists in one call); REST and GraphQL keep separate routes/mutations for membership and are unaffected.
- **Blast radius:** `lego/backend/internal/environments/mcp.go`, `lego/backend/internal/environments/service.go`, `lego/backend/internal/projects/mcp.go`, `lego/backend/internal/projects/service.go`, plus MCP tests in `lego/backend/internal/environments/` and `lego/backend/internal/projects/`.
