# 076 — `REST PATCH /v1/services/{id}` with `buildSourceId` bypasses `buildsources.manage`, letting `services: read_write`-only API keys link services to build sources

Why: `keyPermissionOps["REST PATCH /v1/services/{id}"]` (`lego/backend/internal/api/key_permission_ops.go:1044`) requires only `{core.KeyServicesManage}`, and `apps.Service.patchService` (`lego/backend/internal/apps/rest.go:1196-1199`) routes any PATCH carrying `buildSourceId` into `linkBuildSourcePatch` → `apps.Service.LinkBuildSource` (`lego/backend/internal/apps/build_sources.go:1108-1163`), which never checks `core.KeyBuildSourcesManage` — so a `services: read_write`-only scoped API key that is denied on MCP `link_service_to_build_source` and GraphQL `linkBuildSource` (`key_permission_ops.go:163,634`) still succeeds (`200 OK`) via REST `PATCH /v1/services/{id}` and links arbitrary workspace services to a build source.

### `REST PATCH /v1/services/{id}` with `buildSourceId` bypasses `buildsources.manage` while MCP `link_service_to_build_source` and GraphQL `linkBuildSource` enforce it

- **Severity:** major
- **Versions:** deployed pin `c767c1bbd9` (`9b91284a4a2e`, active on production during run; zero diff in `lego/backend/internal/apps/{rest,build_sources}.go` and `keyPermissionOps["REST PATCH /v1/services/{id}"]` vs `origin/main` `f056be3a93`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-26, endpoints `/mcp`, `/graphql`, and REST `PATCH /v1/services/{id}` (`https://api.bex.co`), workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), run-minted `services: read_write`-only scoped API key (`grants: [{"permission":"services","level":"read_write"}]`, revoked) + disposable web service `srv-dc3vm7hm1rus738gvok0` and image build source `bds-dc3vvnmsfruc73ft2430` (both deleted and verified `404`)
- **Repro:**

  # a disposable service <srv-id>, and a disposable build source <bds-id>:

    'mutation($s:String!,$b:String!){ linkBuildSource(serviceId:$s, buildSourceId:$b, dryRun:true){ id buildSourceId } }' \

- **Expected / actual:**
  - **Expected:** Linking an existing service to a build source via `REST PATCH /v1/services/{id}` (`{"buildSourceId": "bds-…"}`) must require `core.KeyBuildSourcesManage` in addition to `core.KeyServicesManage`, refusing a `services: read_write`-only key with `403 api_key_permission_denied` (`required: ["buildsources.manage"]` / `["buildsources.manage", "services.manage"]`), matching MCP `link_service_to_build_source` and GraphQL `linkBuildSource` (`lego/backend/internal/api/key_permission_ops.go:163,634`).
  - **Actual:**
    - MCP `link_service_to_build_source` and GraphQL `linkBuildSource` both refused the `services: read_write`-only key with `api_key_permission_denied` (`buildsources.manage`, `services.manage`).
    - REST `PATCH /v1/services/srv-dc3vm7hm1rus738gvok0?dryRun=true` and live `PATCH /v1/services/srv-dc3vm7hm1rus738gvok0` with `{"buildSourceId":"bds-dc3vvnmsfruc73ft2430"}` both returned `200 OK`, and MCP `get_service` readback confirmed `"buildSourceId": "bds-dc3vvnmsfruc73ft2430"` was persisted on the service.
- **Wire evidence:**
  - Control 1: `POST https://api.bex.co/mcp` (`link_service_to_build_source`, `rndr-id: ed6bcfd4-8b5f-6810`) → `200`, `isError: true`: `"api_key_permission_denied: this API key is not granted the permission this request needs: Create, update, and delete build sources; Create, update, and delete services"`.
  - Control 2: `POST https://api.bex.co/graphql` (`linkBuildSource`, `rndr-id: 8c80711e-a8f3-3306`) → `200`, `errors[0].extensions`: `{"code":"api_key_permission_denied","required":["buildsources.manage","services.manage"]}`.
  - Bypass 1: `PATCH https://api.bex.co/v1/services/srv-dc3vm7hm1rus738gvok0?dryRun=true` (`rndr-id: d68b8ff8-3697-02b4`) → `200 OK`.

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `keyPermissionOps` (`lego/backend/internal/api/key_permission_ops.go:163,634`) gates `GQL Mutation.linkBuildSource` and `MCP link_service_to_build_source` on `{core.KeyBuildSourcesManage, core.KeyServicesManage}`, while `REST PATCH /v1/services/{id}` (`:1044`) is gated only on `{core.KeyServicesManage}` because ordinary service PATCHes do not touch build sources.
  - `apps.Service.patchService` (`lego/backend/internal/apps/rest.go:1196-1199`) intercepts `req.BuildSourceID != nil && *req.BuildSourceID != ""` and delegates to `linkBuildSourcePatch` (`:423-474`) → `s.LinkBuildSource` (`lego/backend/internal/apps/build_sources.go:1108-1163`).
  - Neither `linkBuildSourcePatch` nor `LinkBuildSource` checks `s.KeyGrantAllows(ctx, core.KeyBuildSourcesManage)` (or `KeyServicesManage` when called from `CreateBuildSource`'s `serviceIds` loop — see `w31/060`).
- **Fix:**
  - Enforce `core.KeyBuildSourcesManage` (and `core.KeyServicesManage`, using the shared `RequireKeyActions` helper proposed in `w31/061` or `KeyGrantAllows` returning `core.NewKeyPermissionDeniedError`) at the top of `apps.Service.LinkBuildSource` (`lego/backend/internal/apps/build_sources.go:1108-1112`), before reading/validating the build source or returning a dry-run preview.
  - Surface impact: closes the REST `PATCH /v1/services/{id}` (`buildSourceId`) bypass while keeping ordinary `PATCH /v1/services/{id}` updates usable by `services: read_write`-only keys, and reinforces MCP `link_service_to_build_source` and GraphQL `linkBuildSource` at the shared service seam.
- **Blast radius:** `lego/backend/internal/apps/build_sources.go` (plus `lego/backend/internal/api/` scoped-key tests). Check `CreateBuildSource` (`build_sources.go:297`) and Blueprint tests to confirm callers that link services already hold both `KeyBuildSourcesManage` and `KeyServicesManage` (Blueprint apply does once `w31/065` adds `KeyBuildSourcesManage`).
