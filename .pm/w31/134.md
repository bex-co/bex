# 134 — `apps.Service.SetMaxShutdownDelay` (and sibling `apps/service.go` CR-only setters) omit no-op guards, flipping `undeployedChanges: true`, polluting `generate_blueprint`, bumping `updatedAt`, and writing spurious `apps.Set*` audit rows across MCP, REST, and GraphQL

Why: `apps.Service.SetMaxShutdownDelay` (`lego/backend/internal/apps/service.go:5954-5969`) only short-circuits when `hasDisk && a.Spec.MaxShutdownDelaySeconds == nil`, so echoing the platform default `maxShutdownDelaySeconds: 30` on a diskless service rewrites `a.Spec.MaxShutdownDelaySeconds` from `nil` to `&30` — tripping `SpecRollsRelease`, flipping `undeployedChanges: true` on save-only MCP/REST updates (and opening a `settings_change` deploy on GraphQL), polluting `generate_blueprint` output, advancing `updatedAt`, and writing `apps.SetMaxShutdownDelay` audit rows; nine sibling CR-only setters (`SetSubdomainPolicy`, `SetCommands`, `SetPreDeployCommand`, `SetHealthCheckPath`, `SetCronJob`, `SetNotifyOnFail`, `SetNotificationsToSend`, `SetPreviewNotificationsEnabled`, `SetIPAllowList`) likewise omit no-op guards and unconditionally patch `updatedAt` and emit audit rows on unchanged inputs.

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `lego/backend/internal/apps/service.go:5954-5969` (`SetMaxShutdownDelay`): checks only `if hasDisk && a.Spec.MaxShutdownDelaySeconds == nil { return s.view(a), nil }`. On a diskless service created with the default `30`s, `a.Spec.MaxShutdownDelaySeconds` is `nil` while reads report `30` via `effectiveMaxShutdownDelaySeconds` (`:4350-4358`). Writing `30` stores `&30` via `storedMaxShutdownDelaySeconds(false, &seconds)` (`:4343-4348`), which changes `a.Spec.MaxShutdownDelaySeconds` from `nil` to `&30`, makes `appv1alpha1.SpecRollsRelease` (`lego/backend/internal/rollout/rollout.go:260`) return `true` (flipping `undeployedChanges: true` under `WithSaveOnly`, or opening a `settings_change` deploy row on direct GraphQL calls), and causes `generate_blueprint` to emit the non-nil field. Even when `a.Spec.MaxShutdownDelaySeconds` already equals `&seconds`, it still calls `recordedPatch`.
  - Nine sibling CR-only setters in `lego/backend/internal/apps/service.go` likewise omit before/after equality checks before patching:
    - `SetSubdomainPolicy` (`:6229-6246`): never checks whether `normalized` matches the effective current policy (`a.Spec.SubdomainPolicy`, treating `""` as `"enabled"`).
    - `SetCommands` (`:5481-5508`): never checks whether `set` changed `a.Spec` (`BuildCommand`, `StartCommand`, `Command`, `Builder`) — even when `imageBuildCommandEcho(*spec, buildCommand)` (`settings_check.go:363`) explicitly skips writing `BuildCommand`, `SetCommands` still calls `recordedPatch`.
    - `SetPreDeployCommand` (`:5460-5475`): never checks `commandText(command) == a.Spec.PreDeployCommand`.
    - `SetHealthCheckPath` (`:5932-5944`): never checks `trimmed == a.Spec.HealthCheckPath`.
    - `SetCronJob` (`:5854-5874`): never checks whether `schedule`/`command` change `a.Spec.Schedule`, `a.Spec.Command`, or `a.Spec.StartCommand`.
    - `SetNotifyOnFail` (`:6162-6171`), `SetNotificationsToSend` (`:6175-6184`), `SetPreviewNotificationsEnabled` (`:6189-6197`): never compare normalized values against the effective stored fields (and call `s.patch`, which authorizes without `WithDeferredAllowedWriteAudit`).
    - `SetIPAllowList` (`:6254-6276`): never checks whether `saved` equals the current stored allow-list before `patchFetched`.
- **Fix:**
  - In `SetMaxShutdownDelay` (`service.go:5954-5969`), short-circuit `return s.view(a), nil` whenever `!hasDisk && effectiveMaxShutdownDelaySeconds(a.Spec.Type, a.Spec.MaxShutdownDelaySeconds) == seconds` (keeping the existing `hasDisk && a.Spec.MaxShutdownDelaySeconds == nil` guard so a legacy disk service carrying a non-nil delay still clears it to `nil`), and check whether `storedMaxShutdownDelaySeconds` should normalize default `30` or keep `nil` when unchanged so `generate_blueprint` stays clean.
  - Add matching no-op short-circuits (returning `s.view(a), nil` without patching or emitting an audit row) after validation in `SetSubdomainPolicy`, `SetCommands` (comparing `after` against `a.Spec` so `imageBuildCommandEcho` and identical commands are true no-ops), `SetPreDeployCommand`, `SetHealthCheckPath`, `SetCronJob`, `SetNotifyOnFail`, `SetNotificationsToSend`, `SetPreviewNotificationsEnabled`, and `SetIPAllowList` (still populating `v.IPAllowListProxiedDomains` on no-op return if callers expect it). Note: coordinate with `w31/120` on `WithDeferredAllowedWriteAudit` for `SetCronJob`, `SetHealthCheckPath`, and `SetIPAllowList`, and ensure `SetNotifyOnFail`, `SetNotificationsToSend`, and `SetPreviewNotificationsEnabled` defer allowed-write auditing too so no-ops emit zero audit rows.
