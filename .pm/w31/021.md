# 021 — Empty resource IDs (`""`) return `"internal error"` across `core.Base` App/Database/KeyValue lookups (20+ MCP tools and GraphQL `service`/`database`/`keyValue`)

Why: `AuthorizeApp`, `GetApp`, and `getInDatastoreNamespaces` guard `b.Client.Get` with `pathvalidation.IsValidPathSegmentName(name)`, which returns no errors for `""`, so an empty ID on MCP or GraphQL reaches Kubernetes `client-go` as `ObjectKey{Name: ""}` and fails with `"resource name may not be empty"` — surfacing as `"internal error"` (500-class) across 20+ MCP tools (including Render's core `get_service`, `get_postgres`, `get_key_value`, `list_deploys`, `list_events`, and `query_render_postgres`) and GraphQL `service`/`database`/`keyValue`.

- **Attribution:** server (`lego/backend/internal/core`)
- **Root cause:**
  - `AuthorizeApp` (`lego/backend/internal/core/base.go:1528-1549`), `GetApp` (`lego/backend/internal/core/base.go:2249-2270`), and `getInDatastoreNamespaces` (`lego/backend/internal/core/base.go:1991-2006`, shared by `AuthorizeDatabase` and `AuthorizeKeyValue`) guard `b.Client.Get` with `len(pathvalidation.IsValidPathSegmentName(candidate)) != 0`.
  - In `k8s.io/apimachinery/pkg/api/validation/path`, `IsValidPathSegmentName("")` returns `nil` (empty slice — it only rejects `.`, `..`, `/`, and `%`, not `""`).
  - For `name == ""`:
    - `appCandidateNames(acting, "")` (`core/base.go:2103-2108`) yields `[acting+"-", ""]`; the first returns `NotFound`, then `candidate == ""` passes `IsValidPathSegmentName("")` and calls `b.Client.Get(ctx, client.ObjectKey{Namespace: ns, Name: ""}, &a)`.
    - `getInDatastoreNamespaces(ctx, "", out)` (`core/base.go:1992-1997`) passes `IsValidPathSegmentName("")` and calls `b.Client.Get(ctx, client.ObjectKey{Namespace: ns, Name: ""}, out)`.
  - Kubernetes `client-go` rejects an empty resource name with `"resource name may not be empty"` — which is not `apierrors.IsNotFound`, so it bypasses the `!apierrors.IsNotFound(err)` check and surfaces out of `core.MCPError` and GraphQL as `"internal error"`.
  - Additionally, `validation.IsValidLabelValue("")` returns `nil` (`core/base.go:1460,2216`), so `AuthorizeApp` and `GetApp` also run empty-value label-selector `List` queries (`LabelAppID: ""`, `LabelServiceName: ""`) on `name == ""` before hitting `Client.Get`.
  - `TestAppLookupRejectsMalformedSelectorsWithoutLosingLegacyNames` (`lego/backend/internal/core/app_lookup_input_test.go:42,77`) missed this because `selectorCheckingClient.Get` only checked `path.IsValidPathSegmentName(key.Name)` (never rejecting `key.Name == ""` as real `client-go` does) and the test list omitted `""`.
- **Fix:**
  - In `lego/backend/internal/core/base.go`:
    - Reject `candidate == ""` alongside `len(pathvalidation.IsValidPathSegmentName(candidate)) != 0` in `AuthorizeApp` (`:1529`), `GetApp` (`:2250`), and `getInDatastoreNamespaces` (`:1992`) — e.g. via a shared `validCRLookupName(s string) bool { return s != "" && len(pathvalidation.IsValidPathSegmentName(s)) == 0 }`.
    - Also guard `validLabel := name != "" && len(validation.IsValidLabelValue(name)) == 0` in `AuthorizeApp` (`:1460`) and `GetApp` (`:2216`) so `name == ""` does not issue empty-value label-selector `List` calls (and never matches a CR missing that label), while still running the workspace `authorizeAndAudit` check on miss so unauthorized callers continue receiving `ErrForbidden`.
  - Update `selectorCheckingClient.Get` in `lego/backend/internal/core/app_lookup_input_test.go:40-46` to mirror real `client-go` (`if key.Name == "" { return errors.New("resource name may not be empty") }`) and include `""` in `TestAppLookupRejectsMalformedSelectorsWithoutLosingLegacyNames`, `TestMalformedAppLookupPreservesAuthorizationDenial`, and datastore lookup tests (`AuthorizeDatabase`, `AuthorizeKeyValue`).
  - Surface impact: fixes MCP and GraphQL together (REST never hits `id == ""` because `/v1/services/` routes to list); no wire breaking change.
