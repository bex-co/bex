# 203 — Pre-authorization input validation in `apps` build sources (`list_build_sources`, `GET /v1/build-sources`, `Query.buildSources`), `envgroups` (`GET /v1/env-groups`), `secrets` (`Query.envVars`, `Query.secretFiles`), and `jobs` (`Query.jobs`, `POST /v1/services/{id}/jobs`) returns `400 bad_request` instead of `403`/`404`

Why: `bex-api`'s authz-before-validation contract requires workspace/resource authorization to run before caller-supplied query filters, limits, or body fields are validated so unauthorized or foreign-resource callers receive `403 FORBIDDEN` / `404 NOT_FOUND` (and record denied audit rows) instead of `400 bad_request`. Four endpoint families not covered by `w31/172` or `w31/189` validate inputs before authorization: build-source list adapters across MCP, REST, and GraphQL (`apps/build_sources.go:857`, `apps/build_sources_graphql.go:162,340`), `REST GET /v1/env-groups` (`envgroups/rest.go:105`), GraphQL `Query.envVars` / `Query.secretFiles` (`secrets/graphql.go:175,201`), and GraphQL `Query.jobs` / `REST POST /v1/services/{id}/jobs` (`jobs/graphql.go:68-73`, `jobs/rest.go:128`).

  - `apps/build_sources.go:855-869` & `apps/build_sources_graphql.go:161-167,339-349`: authorize/resolve caller workspaces first (matching `GET /v1/services` at `apps/rest.go:915-945` and `GET /v1/projects` at `projects/rest.go:127-142`), then run `parseBuildSourceFilter` and filter the authorized result.
  - `envgroups/rest.go:103-117`: resolve/authorize `ownerId`s (`ListOwnerIDs` + `ListEnvGroupsFiltered` / workspace `Authorize`) before calling `envGroupListFilter(r.URL)` so malformed timestamps cannot preempt `403 FORBIDDEN`.
