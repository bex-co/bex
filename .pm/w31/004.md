# 004 — `deploys.Service.validateTrigger` never validates `deployMode`, so MCP `trigger_deploy` and GraphQL `triggerDeploy` silently trigger a deploy on arbitrary values

Why: `lego/backend/internal/deploys/service.go:786-869` validates `clearCache` but never rejects unknown `deployMode` values, so REST rejects them only via the OpenAPI request gate while MCP `trigger_deploy` and GraphQL `triggerDeploy` silently accept typos (like `"deploy-only"`) and launch a live deploy.

### MCP `trigger_deploy` (and shared `validateTrigger`) silently accepts arbitrary invalid `deployMode` values and triggers a live deploy

- **Severity:** major
- **Versions:** deployed pin `4b533337ab` (`7b046987bcd8`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-25, endpoint `/mcp` (`https://api.bex.co/mcp`), workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), run-minted all-permissions API key (revoked), owned disposable free web service (`qa-20261125-fbe624-web`, deleted after test)

- **Expected / actual:**
  - **Expected:** `deployMode` accepts only Render's documented enum (`"build_and_deploy"` or `"deploy_only"`, or omitted/empty). Any other value must be rejected before creating a deploy with `bad request` (on MCP, both at JSON Schema validation via `"enum": ["build_and_deploy", "deploy_only"]` and in shared `deploys.Service.validateTrigger` across REST, GraphQL, and MCP), matching REST's `400 bad_request` and `clearCache`'s shared validation (`deploys/service.go:865`).
  - **Actual:** MCP `trigger_deploy` with `"deployMode": "SECRET_ECHO_PROBE_42"` returned `isError: false` and **created and started a live deploy** (`dep-dc39f6guqmis73a84n1g`) on the owned web service. The REST control `POST /v1/services/<srv-id>/deploys` with `{"deployMode": "bogus_mode"}` returned `400 bad_request` (`invalid request body at /deployMode`), proving the rejection lives only in the REST OpenAPI validator and is absent from `deploys.Service.validateTrigger`.
- **Wire evidence:**
  - `POST https://api.bex.co/mcp` (`trigger_deploy`, `deployMode: "SECRET_ECHO_PROBE_42"`) → `200`, `isError: false`: `{"bexTrigger":"api","createdAt":"2026-11-25T08:08:58.538284Z","id":"dep-dc39f6guqmis73a84n1g","image":{"ref":"traefik/whoami:v1.10.3"},"serviceId":"srv-dc39aipa7e1c7381dhcg","status":"created","trigger":"api","updatedAt":"2026-11-25T08:08:58.538284Z"}`
  - Control `POST https://api.bex.co/v1/services/srv-dc39aipa7e1c7381dhcg/deploys` (`{"deployMode":"bogus_mode"}`) → `400` (`rndr-id: 400`, body): `{"error":"invalid request body at /deployMode","id":"bad_request","message":"invalid request body at /deployMode"}`
- **Attribution:** server (`lego/backend/internal/deploys`)
- **Root cause:**
  - `lego/backend/internal/deploys/service.go:786-869` (`validateTrigger`) checks `p.DeployMode == "deploy_only"` for incompatibility with build fields (`:811`) and repo-backed services (`:818`), and validates `p.ClearCache` against `"" | "clear" | "do_not_clear"` (`:865`), but never checks that a non-empty `p.DeployMode` is `"build_and_deploy"` or `"deploy_only"`. Any unknown value falls through as default `build_and_deploy` and is even persisted in `store.DeferredRequest.DeployMode` (`:976`).
  - `lego/backend/internal/deploys/mcp.go:194-196` sets `mcputil.PropTypes("clearCache", "boolean", "string")` on `trigger_deploy`'s `InputSchema` but does not add `mcputil.PropEnum("deployMode", "build_and_deploy", "deploy_only")`.
  - `lego/backend/internal/deploys/graphql.go:237,257` decodes `deployMode` as unconstrained `graphql.String` and forwards it to `s.TriggerManual` → `validateTrigger`, which likewise accepts any string.
- **Fix:**
  - In `lego/backend/internal/deploys/service.go` (`validateTrigger`, alongside the `clearCache` check at `:865`), reject any `p.DeployMode` other than `""`, `"build_and_deploy"`, or `"deploy_only"` with `fmt.Errorf("%w: deployMode must be one of build_and_deploy|deploy_only", core.ErrBadRequest)` (do not echo the caller's raw value in the error message).
  - In `lego/backend/internal/deploys/mcp.go:194-196`, add `mcputil.PropEnum("deployMode", "build_and_deploy", "deploy_only")` to `trigger_deploy`'s `InputSchema` so MCP clients advertise and validate the enum in `tools/list`.
  - All three adapters (REST, GraphQL `triggerDeploy`, MCP `trigger_deploy`) now enforce the same `deployMode` contract without drifting.
- **Blast radius:** `deploys.Service.Trigger`, `TriggerManual`, and `triggerFetched` — shared by REST `POST /v1/services/{id}/deploys`, GraphQL `triggerDeploy`, and MCP `trigger_deploy`. Note: check whether `validateTrigger`'s `clearCache` error at `service.go:866` (`unknown clearCache %q`) should also drop echoing the raw value to avoid leaking a misplaced secret; keep that scoped or leave as a clean one-line polish.
