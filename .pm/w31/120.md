# 120 — `apps.Service` cron-run and Blueprint write verbs (`TriggerCronRun`, `CancelCronRun`, `CancelCurrentCronRun`, `DeployStack`, `PlanBlueprint`, `ApproveBlueprint`, `UpdateBlueprint`, `DisconnectBlueprint`) omit `WithDeferredAllowedWriteAudit`, and MCP `update_blueprint` double-authorizes

Why: Unlike `apps.Service.Create`, `Update`, `Delete`, `AddDomain`, `AddDisk`, and `CreatePlannedBlueprint` (which defer allowed-write auditing until after validation and persistence succeed), `apps.Service.TriggerCronRun` (`lego/backend/internal/apps/service.go:4779`), `CancelCronRun` (`:4953`), `CancelCurrentCronRun` (`:4974`), `DeployStack` (`deploy.go:903`), `UpdateBlueprint` (`blueprint.go:2079`), `DisconnectBlueprint` (`blueprint.go:2177`), `PlanBlueprint` (`blueprint_onboarding.go:272`), `ApproveBlueprint` (`blueprint_onboarding.go:527`), and `updateBlueprintTool` (`blueprint_onboarding.go:998`) authorize without `core.WithDeferredAllowedWriteAudit(ctx)` — so `400`, `404`, and `409` refusals (and `update_blueprint` no-ops) write false `"status": "success"` rows into the workspace audit log across MCP, REST, and GraphQL, and a real MCP `update_blueprint` edit authorizes twice (`:998` and `blueprint.go:2079`).

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `lego/backend/internal/apps/service.go:4779` (`TriggerCronRun`), `:4953` (`CancelCronRun`), `:4974` (`CancelCurrentCronRun`) call `s.AuthorizeApp(ctx, core.RelCanOperate, name)` without `core.WithDeferredAllowedWriteAudit(ctx)` before type, suspension, billing, and active-run checks. Siblings `SetCronJob` (`:5859`), `SetHealthCheckPath` (`:5933`), and `SetIPAllowList` (`:6258`) likewise authorize without deferring before validation/staging checks.
  - `lego/backend/internal/apps/deploy.go:903` (`DeployStack`) calls `s.Authorize(ctx, core.RelCanCreate)` without `core.WithDeferredAllowedWriteAudit(ctx)` before `compileStack` and `blueprintActionPlan`.
  - `lego/backend/internal/apps/blueprint.go:2079` (`UpdateBlueprint`), `:2177` (`DisconnectBlueprint`), and `lego/backend/internal/apps/blueprint_onboarding.go:272` (`PlanBlueprint`), `:527` (`ApproveBlueprint`), `:998` (`updateBlueprintTool`) call `s.blueprintScope`/`s.blueprintScopeAs` (`blueprint.go:2378,2391`) without `core.WithDeferredAllowedWriteAudit(ctx)` before `GetBlueprint`, validation, state checks, or mutations. In addition, `updateBlueprintTool` calls `s.blueprintScopeAs` at `:998` (emitting one audit row even on a no-op or refusal) and then calls `s.UpdateBlueprint` at `:1015`, which calls `s.blueprintScope` a second time.
- **Fix:**
  - Authorize `TriggerCronRun`, `CancelCronRun`, `CancelCurrentCronRun`, `SetCronJob`, `SetHealthCheckPath`, `SetIPAllowList`, `DeployStack`, `PlanBlueprint`, `ApproveBlueprint`, `UpdateBlueprint`, and `DisconnectBlueprint` with `core.WithDeferredAllowedWriteAudit(ctx)` and emit the canonical allowed-write audit row only after the write commits (matching `CreatePlannedBlueprint` at `blueprint_onboarding.go:164,256` and `AddDomain` at `domains.go:1777`).
  - In `updateBlueprintTool` (`blueprint_onboarding.go:998`), pass `core.WithDeferredAllowedWriteAudit(ctx)` to the pre-read `s.blueprintScopeAs` check so a no-op or `404` writes zero rows and a real edit emits exactly one row from `UpdateBlueprint`.
