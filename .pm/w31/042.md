# 042 — `apps.Service.Scale` never checks `a.Spec.Type`, so MCP `scale_service`, REST `POST /v1/services/{id}/scale`, and GraphQL `scaleService` accept `static_site` and `cron_job`

Why: `apps.Service.Scale` (`lego/backend/internal/apps/service.go:5103-5155`) validates `numInstances` and the plan's instance cap without checking whether the service type supports manual scaling, so `static_site` and `cron_job` (which have no running service instances) return `200`/`202` on `numInstances: 1` (and paid `cron_job`s accept `numInstances > 1`, mutating `spec.replicas` and emitting bogus `instance_count_changed` audit/webhook events), while `numInstances: 2` on a `static_site` returns a misleading free-plan error instead of rejecting the service type.
