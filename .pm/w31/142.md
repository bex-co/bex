# 142 — Attributed API-key deploys, suspend/resume events, and cron runs record raw Hydra client UUIDs verbatim, leaking client UUIDs with missing emails in `events` across MCP, REST, and GraphQL (and blanking `cron_run` `triggeredBy`/`canceledBy`)

Why: `deploys` (`lego/backend/internal/deploys/service.go:1009,1515`, `restart_wait.go:188`, `rollback_config.go:259-263`, `build_sources.go:250`) and `apps/cron_run_actors.go:37,46` persist `core.SubjectFrom(ctx)` verbatim (the API key's raw Hydra OAuth2 client UUID) instead of resolving an attributed API key's human creator via `s.KeyCreator(ctx)`, and `events.Service` (`lego/backend/internal/events/service.go:1203-1273`) passes both deploy callers and audit-backed `r.Caller` values (`suspender_added`, `suspender_removed`, `server_restarted`, `disk_snapshot_restored`) straight into Kratos `LookupEmails` and `core.PublicUserIDs` without resolving `KeyCreators` — causing MCP (`list_events`, `list_service_events`, `get_service_event`), REST (`GET /v1/services/{id}/events`, `GET /v1/events/{id}`), and GraphQL (`serviceEvents`) to leak raw Hydra client UUIDs in `details.triggeredByUser`, `details.trigger.user.id`, `details.suspendedByUser.id`, and `details.resumedByUser.id` (with `email` omitted) and causing `withCronRunActors` (`cron_run_actors.go:98-101`) to return blank `triggeredBy`/`canceledBy` on API-key cron runs.

- **Attribution:** server (`lego/backend/internal/events`, `lego/backend/internal/deploys`, `lego/backend/internal/apps`)
- **Root cause:**
  - `deploys` writes `core.SubjectFrom(ctx)` verbatim into `deploys.triggered_by` at `lego/backend/internal/deploys/service.go:1009,1515`, `restart_wait.go:188`, `rollback_config.go:259,261,263`, and `build_sources.go:250` without resolving `s.KeyCreator(ctx)`.
  - `apps` writes `core.SubjectFrom(ctx)` verbatim into `cron_run_actors` at `lego/backend/internal/apps/cron_run_actors.go:37,46`, so `withCronRunActors` (`:87-102`) passes the Hydra client UUID to `s.ActorEmails.LookupEmails` (which knows only Kratos subjects) and writes empty strings into `TriggeredBy`/`CanceledBy`.
  - `events.Service` (`lego/backend/internal/events/service.go:1195-1196,1203-1273,1321-1322`) reads `r.Caller` from both `deploys.triggered_by` and `audit_events.caller` (`:1398,1444,1446,1450`), then runs `resolveUserEmails` and `resolveUserIDs` directly on `r.Caller` without resolving attributed API keys through `s.KeyCreators` (an older `w5/m277` comment at `:1237` and `docs/ADR020-identifiers.md:43` assumed API keys had no user creator).
- **Fix:**
  - In `deploys` (`service.go`, `restart_wait.go`, `rollback_config.go`, `build_sources.go`) and `apps/cron_run_actors.go`, resolve an attributed API key's human creator via `s.KeyCreator(ctx)` when recording `TriggeredBy` / `CanceledBy` (best-effort or fail-closed matching surrounding error handling, falling back to `core.SubjectFrom(ctx)` only for unattributed/non-key callers).
  - In `events.Service` (`lego/backend/internal/events/service.go`), resolve attributed API-key subjects via `s.KeyCreators` (already on embedded `*core.Base`) before `resolveUserEmails` and `resolveUserIDs` so both audit-backed events (`suspender_added`, `suspender_removed`, `server_restarted`, `disk_snapshot_restored`, `edge_cache_*`, where `audit_events.caller` keeps the key client ID) and historical `deploys` rows emit the creator's `usr-…` ID and email across MCP, REST, GraphQL, and webhooks. (Unattributed machine clients keep existing fallback behavior rather than acquiring fake user IDs.)
  - Amend `docs/ADR020-identifiers.md` § User public aliases to record that attributed API keys resolve to their creator's `usr-…` ID on events (while audit logs still record the acting key client ID).
