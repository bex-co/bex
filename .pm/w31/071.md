# 071 — Scoped API keys without `deploys_run: run` (`deploys.run`) trigger service deploys on linked services via `trigger_build_source_build` and GraphQL `linkBuildSource(deploy: true)`

Why: `lego/backend/internal/api/key_permission_ops.go:163,283,753,1130` maps `MCP trigger_build_source_build`, `REST POST /v1/build-sources/{buildSourceId}/builds`, and `GQL Mutation.triggerBuild` solely to `{core.KeyBuildSourcesBuild}`, and `GQL Mutation.linkBuildSource` solely to `{core.KeyBuildSourcesManage, core.KeyServicesManage}` — and neither `deploys.Service.TriggerBuild` (`lego/backend/internal/deploys/build_sources.go:211-339`) nor GraphQL `linkBuildSource` (`lego/backend/internal/apps/build_sources_graphql.go:254-268`) checks `core.KeyDeploysRun` when deploying linked services, letting keys explicitly denied `Trigger and cancel deploys` (and even denied `services: read`) trigger deploys on arbitrary linked services.

- **Attribution:** server (`lego/backend/internal/{deploys,apps,api}`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:283,753,1130` gates `triggerBuild` / `trigger_build_source_build` / `POST /v1/build-sources/{buildSourceId}/builds` only on `{core.KeyBuildSourcesBuild}`, and `deploys.Service.resolveBuildDeployTargets` (`lego/backend/internal/deploys/build_sources.go:278-339`) checks only `s.AuthorizeApp(origCtx, core.RelCanOperate, sid)` for `custom` (and checks neither `AuthorizeApp` nor `KeyDeploysRun` for `autodeploy_only`), never checking `s.RequireKeyGrant(origCtx, core.KeyDeploysRun)`.
  - `lego/backend/internal/api/key_permission_ops.go:163` gates `GQL Mutation.linkBuildSource` only on `{core.KeyBuildSourcesManage, core.KeyServicesManage}`, and the resolver (`lego/backend/internal/apps/build_sources_graphql.go:254-268`) calls `s.triggerSourceDeploy` when `deploy: true` without checking `s.RequireKeyGrant(p.Context, core.KeyDeploysRun)` before writing the link.
- **Fix:**
  - In `deploys.Service.TriggerBuild` / `resolveBuildDeployTargets` (`lego/backend/internal/deploys/build_sources.go:224-335`):
    - When `scope == BuildDeployScopeCustom` (explicit service targeting), require `s.RequireKeyGrant(origCtx, core.KeyDeploysRun)` before validating or probing any `serviceId` (also verify whether `autodeploy_only` when targeting linked services should require `core.KeyDeploysRun` or if Render treats `autodeploy_only` as build-side fan-out while `custom` explicitly deploys chosen services; at minimum enforce `core.KeyDeploysRun` on `custom` and document/verify `autodeploy_only` against Render's scoped key contract, and verify `autodeploy_only` respects protected-environment/creator permissions consistently).
  - In GraphQL `Mutation.linkBuildSource` (`lego/backend/internal/apps/build_sources_graphql.go:255-268`):
    - When `deploy && !dryRun`, call `s.RequireKeyGrant(p.Context, core.KeyDeploysRun)` BEFORE `s.LinkBuildSource(...)` so a refused key neither links nor deploys.
