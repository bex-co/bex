# 149 — `agentsessions` queued messages store raw Hydra API-key UUIDs as `author`, leak raw internal Kratos/Hydra UUIDs in `QueuedMessage.author`, lock out human creators on attachment-bearing edits, and bypass `keyCeiling` in `MessageQueue.deliver`

Why: `agentsessions.Service.enqueueSteer` (`lego/backend/internal/agentsessions/queue.go:196`) and `EditQueuedMessage` (`queue.go:348`) write and compare raw `core.SubjectFrom(ctx)` without resolving attributed API keys via `KeyCreator`, `queuedMessageOf` (`queue.go:149`) returns `row.Author` verbatim instead of a public `usr-…` ID ([ADR020](../../docs/ADR020-identifiers.md)), and `MessageQueue.deliver` (`lego/backend/internal/agentsessions/message_queue.go:140`) replays `message.Author` with `Method: "session"`, bypassing `core.Base.keyCeiling` (`lego/backend/internal/core/keyrole.go:79-82`) whenever a queued message was authored by an API key.

### Queued agent-session messages leak raw internal UUIDs, break creator ownership on API-key edits, and bypass `keyCeiling` on background delivery

- **Severity:** major
- **Versions:** deployed pin `9c76d4ae72` (`6ba91ca5b72f`, zero diff in `lego/backend/internal/agentsessions/{queue,message_queue}.go` or `lego/backend/internal/core/keyrole.go` vs `origin/main` `f511677827`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-27, surfaces `/mcp` and `/mcp/cloud-agents` (`send_agent_session_message`, `list_agent_session_queued_messages`, `edit_agent_session_queued_message`, `move_agent_session_queued_message`), REST `/v1/agent-sessions/{id}/queued-messages*`, and GraphQL (`queuedMessages`, `editQueuedAgentSessionMessage`, `moveQueuedAgentSessionMessage`); verified by code inspection against `lego/backend/internal/agentsessions/queue.go`, `message_queue.go`, and `core/keyrole.go` (not executed against a live session to avoid spending model credits).
- **Repro:**

  ```sh
  # With a running agent session (e.g. in an integration test or live session):
  # 1. Enqueue a steer message using an attributed API key (while the session is busy):
  python3 scripts/qa-mcp.py --key-file <api-key.json> call send_agent_session_message \
    '{"sessionId":"<agt-id>","prompt":"follow-up","attachmentIds":["<att-id>"]}'

  # 2. List queued messages via MCP, REST, or GraphQL:
  python3 scripts/qa-mcp.py --key-file <api-key.json> call list_agent_session_queued_messages \
    '{"sessionId":"<agt-id>"}'
  # -> QueuedMessage.author is the API key's raw Hydra client UUID (or the human's raw Kratos UUID for session calls), NOT usr-...

  # 3. Attempt to edit that attachment-bearing queued message as the human user who minted the API key:
  # -> EditQueuedMessage compares raw Kratos subject != stored Hydra client UUID -> ErrQueuedMessageAttachmentsOwned (forbidden).

  # 4. When the session goes idle and MessageQueue.deliver fires:
  # -> deliver builds core.Identity{Subject: message.Author, Method: "session"} -> IsAPIKey() == false -> core.Base.keyCeiling is skipped.
  ```

- **Expected / actual:**
  - **Expected:**
    1. Attributed API-key callers resolve to their human creator via `s.KeyCreator(ctx)` when writing `author` in `enqueueSteer` and checking ownership in `EditQueuedMessage`, so the human creator and sibling API keys share ownership of attachment-bearing queued messages.
    2. All wire responses (`QueuedMessage.author` across MCP, REST, and GraphQL) project internal Kratos subject UUIDs to public `usr-…` IDs (`core.PublicUserIDs` / [ADR020](../../docs/ADR020-identifiers.md)), never exposing raw Kratos or Hydra UUIDs.
    3. Background delivery in `MessageQueue.deliver` never bypasses `core.Base.keyCeiling` if a stored `author` is an API-key client UUID (including pre-fix rows already in `queued_agent_messages`).
  - **Actual:**
    1. `enqueueSteer` (`queue.go:196`) writes raw `core.SubjectFrom(ctx)` (the API key's Hydra client UUID) into `queued_agent_messages.author`.
    2. `queuedMessageOf` (`queue.go:149`) copies `Author: row.Author` straight onto the wire, leaking raw Kratos identity UUIDs (for human callers) and raw Hydra client UUIDs (for API-key callers) on MCP, REST, and GraphQL.
    3. `EditQueuedMessage` (`queue.go:348`) passes raw `core.SubjectFrom(ctx)` to `store.EditQueuedAgentSessionMessage`, whose ownership check (`store.ErrQueuedMessageAttachmentsOwned`, `queue.go:288`) rejects the human creator who minted the API key (and any other key minted by that creator).
    4. `MessageQueue.deliver` (`message_queue.go:140`) wraps `message.Author` in `core.Identity{Subject: message.Author, Method: "session"}`. Because `Method` is `"session"`, `id.IsAPIKey()` is `false`, so `core.Base.keyCeiling` (`core/keyrole.go:79-82`) returns immediately without checking whether the key's creator was downgraded or removed from the workspace.
- **Wire evidence:** Verified directly in source (`lego/backend/internal/agentsessions/queue.go:148-224,288,336-357`, `lego/backend/internal/agentsessions/message_queue.go:133-164`, `lego/backend/internal/core/keyrole.go:79-82`); live wire run skipped because starting a busy agent session spends model credits.
- **Attribution:** server (`lego/backend/internal/agentsessions`)
- **Root cause:**
  - `lego/backend/internal/agentsessions/queue.go:196` (`enqueueSteer`) and `:348` (`EditQueuedMessage`) use `core.SubjectFrom(ctx)` instead of resolving attributed API keys through `s.KeyCreator(ctx)` (the same pattern missed in `w31/040` and `w31/103`).
  - `lego/backend/internal/agentsessions/queue.go:148-151` (`queuedMessageOf`) emits `Author: row.Author` without mapping internal subjects via `core.PublicUserIDs` (same ADR020 omission as `w31/144` for `AgentSession.createdBy` / `AgentAutomation.createdBy`, and `w31/096` for skills).
  - `lego/backend/internal/agentsessions/message_queue.go:140` hardcodes `Method: "session"` when reconstructing `core.Identity` from `message.Author`, disabling `keyCeiling` whenever `message.Author` holds a Hydra API-key client UUID.
- **Fix:**
  - Extract/reuse a shared `actingSubject(ctx)` helper in `agentsessions` (resolving `s.KeyCreator(ctx)` for attributed API keys, coordinated with `w31/040` / `w31/103`) and use it in both `enqueueSteer` (`queue.go:196`) and `EditQueuedMessage` (`queue.go:348`).
  - Project `QueuedMessage.Author` to public `usr-…` IDs via `core.PublicUserIDs` at the `agentsessions` view boundary (batching across `ListQueuedMessages` and projecting single messages in `EditQueuedMessage`, `MoveQueuedMessage`, and `enqueueSteer`'s returned view).
  - In `MessageQueue.deliver` (`message_queue.go:140`), preserve API-key attribution or resolve legacy API-key `message.Author` values through `KeyCreators` before constructing the `Steer` context (or mark them `Method: "api_key"` when `message.Author` is a key client ID) so `keyCeiling` and creator revocation cannot be bypassed by pre-fix queued rows.
- **Blast radius:** `lego/backend/internal/agentsessions/queue.go`, `lego/backend/internal/agentsessions/message_queue.go`, and their unit/integration tests; wire shape of `QueuedMessage.author` changes from raw UUID to `usr-…` across MCP, REST, and GraphQL (matching ADR020).
