# 105 — Static site route and header validators accept non-canonical IPv4 rewrite destinations (`http://127.1/...`), malformed redirect hosts (`https://../...`), and CR/LF control characters in route `source` and header `path` across MCP, REST, and GraphQL

Why: `apps.validatePublicRewriteHost` (`lego/backend/internal/apps/service.go:6660-6684`) relies solely on Go's `net.ParseIP(host)`, which returns `nil` for non-canonical IPv4 forms such as shorthand dotted (`127.1`), octal (`0177.0.0.1`), or hex (`0x7f.0.0.1`) addresses; `validateExternalRedirect` (`service.go:6622-6654`) accepts any `[a-zA-Z0-9-.]+` hostname including `".."`; and `validateRoutes` (`service.go:6739`) / `validateHeaders` (`service.go:6836`) never check `routes[i].source` or `headers[i].path` for ASCII control characters (`\r`, `\n`, `\x00`). All three classes of invalid rules pass `validate_bex_yml`, `create_static_site`, REST `POST /v1/services`, and GraphQL `validateBlueprint`.

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `lego/backend/internal/apps/service.go:6669-6677` (`validatePublicRewriteHost`): `net.ParseIP("127.1")` returns `nil`, and `"127.1"` contains a dot and does not match the reserved suffix list, so it passes validation despite resolving as loopback `127.0.0.1` in `inet_aton`-compatible resolvers (and similarly for octal/hex dotted forms where every label is numeric or hex).
  - `lego/backend/internal/apps/service.go:6641-6643` (`validateExternalRedirect`): character-set loop permits any non-empty combination of `[a-zA-Z0-9-.]`, accepting `".."`, `"-"`, `".example.com"`, and `"example..com"`.
  - `lego/backend/internal/apps/service.go:6739-6743` (`validateRoutes`) and `service.go:6836-6841` (`validateHeaders`): validate only leading `"/"` and max length on `r.Source` and `h.Path`, omitting any control-character check (unlike `validateExternalRedirect` at `:6629` and `isNetworkPathReference` at `:6819`).
- **Fix:**
  - In `validateExternalRedirect` (`lego/backend/internal/apps/service.go:6622-6654`): validate `parsed.Hostname()` as either a canonical IP literal (`netip.ParseAddr`) or a syntactically valid DNS name (non-empty labels of `[a-zA-Z0-9-]`, no leading/trailing hyphen per label, no empty labels / consecutive dots, and reject all-numeric or `0x`-prefixed final/non-canonical IPv4 labels per RFC 1123 / WHATWG URL host rules). Note: invalid TCP ports in `validateExternalRedirect` are tracked separately in `w31/088`.
  - In `validatePublicRewriteHost` (`service.go:6660-6684`): parse IP literals with `netip.ParseAddr` (rejecting non-canonical/all-numeric dotted IPv4 forms such as `127.1`, `0177.0.0.1`, `0x7f.0.0.1`, and single-integer hosts, and rejecting any hostname whose final label is all-numeric or hex-prefixed).
  - In `validateRoutes` (`service.go:6739`) and `validateHeaders` (`service.go:6836`): reject ASCII control characters (`r < 0x20 || r == 0x7f`) in `source` and `path`.
  - Surface impact: fixes `validate_bex_yml`, `create_static_site`, `update_static_routes`, `update_static_headers`, REST `/v1/services` & `/v1/blueprints`, and GraphQL `validateBlueprint` / `setStaticRoutes` / `setStaticHeaders`.
