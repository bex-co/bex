# 202 — `apps.Service.{SetNotifyOnFail,SetNotificationsToSend,SetPreviewNotificationsEnabled,SetSubdomainPolicy,SetIPAllowList}` validate inputs before `AuthorizeApp`, returning `400 bad_request` instead of `403`/`404`

Why: `bex-api`'s authz-before-validation contract requires `s.AuthorizeApp` to run before caller-supplied settings values are validated so unauthorized callers (non-members, Viewers/Contributors, foreign workspaces) and nonexistent service IDs receive `403 FORBIDDEN` / `404 NOT_FOUND` (and record denied audit rows) instead of `400 bad_request`. Five setters in `lego/backend/internal/apps/service.go` validate inputs before calling `s.AuthorizeApp` (`s.patch`): `SetNotifyOnFail` (`:6169`), `SetNotificationsToSend` (`:6182`), `SetPreviewNotificationsEnabled` (`:6196`), `SetSubdomainPolicy` (`:6238`), and `SetIPAllowList` (`:6261`) — diverging from sibling `apps.Service` setters (and from `MCP update_service` / `ApplyServicePatch`, which authorizes in `preflightServicePatch` first and returns `NOT_FOUND` for the same invalid values on nonexistent services).
