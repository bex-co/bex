# 064 — Scoped `blueprints: read` + `services_env: read` API keys export full service, Postgres, Key Value, environment-group, and build-source configurations via `generate_blueprint` across MCP, REST, and GraphQL

Why: `lego/backend/internal/api/key_permission_ops.go:391,565,1069` maps `GQL Query.generateBlueprint`, `MCP generate_blueprint`, and `REST POST /v1/blueprints/generate` solely to `{core.KeyBlueprintsView, core.KeyServicesEnv}`, and `apps.Service.GenerateBlueprint` (`lego/backend/internal/apps/blueprint_generate.go:144-295`) performs zero `RequireKeyGrant` checks on the selected resource kinds — allowing an API key holding zero `services`, `postgres`, `key_value`, `env_groups`, or `build_sources` grants (which `get_service`, `get_postgres`, `get_key_value`, and `get_env_group` all refuse with `api_key_permission_denied`) to export the complete `render.yaml` configuration of every selected resource across MCP, REST, and GraphQL.

- **Attribution:** server (`lego/backend/internal/apps` and `lego/backend/internal/api`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:391,565,1069` maps `GQL Query.generateBlueprint`, `MCP generate_blueprint`, and `REST POST /v1/blueprints/generate` to `{core.KeyBlueprintsView, core.KeyServicesEnv}` only.
  - `apps.Service.GenerateBlueprint` (`lego/backend/internal/apps/blueprint_generate.go:144-295`) checks OpenFGA `core.RelCanViewSensitive` on each resource (which passes for any key whose creator is a Developer/Admin), but never calls `s.RequireKeyGrant` for `core.KeyServicesView` (`ServiceIDs`, `:208`), `core.KeyPostgresView` (`PostgresIDs`, `:162`), `core.KeyKeyValueView` (`KeyValueIDs`, `:176`), `core.KeyEnvGroupsView` (`EnvGroupIDs`, `:193`, or linked env groups resolved at `:700-720`), or `core.KeyBuildSourcesView` / `core.KeyBuildSourcesEnv` (linked build source carriers exported at `:214-222,252-256,547`).
- **Fix:**
  - Keep `{core.KeyBlueprintsView, core.KeyServicesEnv}` at the static route gate in `key_permission_ops.go:391,565,1069` (or require only `{core.KeyBlueprintsView}` statically and enforce `KeyServicesEnv` only when `ServiceIDs` is non-empty so exporting only Postgres/KV/env-groups doesn't needlessly demand `services_env: read`), and in `apps.Service.GenerateBlueprint` (`lego/backend/internal/apps/blueprint_generate.go:155-232`) enforce `s.RequireKeyGrant` per selected resource family before reading any resource:
    - `len(req.ServiceIDs) > 0` → `core.KeyServicesView`, `core.KeyServicesEnv` (and when a selected service links a build source carrier at `:214-222`, require `core.KeyBuildSourcesView`, `core.KeyBuildSourcesEnv`; when it links a project-scoped build source at `:257`, `core.KeyProjectsView`; when it resolves linked env groups at `:700-720`, `core.KeyEnvGroupsView`)
    - `len(req.PostgresIDs) > 0` → `core.KeyPostgresView`
    - `len(req.KeyValueIDs) > 0` → `core.KeyKeyValueView`
    - `len(req.EnvGroupIDs) > 0` → `core.KeyEnvGroupsView`
  - Surface impact: enforces least-privilege scoped API key grants uniformly across MCP, REST, and GraphQL `generate_blueprint` from a single service-layer check.
