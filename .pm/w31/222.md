# 222 — `scope_matrix_overrides.go` omits `OpClassSensitive` on all four sandbox exec and file-transfer operations (`MCP sandbox_exec`, `REST POST /v1/sandboxes/{id}/{exec,runs/{operation}/token,files/{operation}/token}`), and `sandbox` exec/file gates omit `RelCanViewSensitive` on non-agent sandboxes

Why: `lego/backend/internal/core/keygrant.go:299-301` classifies `sandbox_execution` (`KeySandboxesExec`, `KeySandboxesFiles`) under `core.RelCanViewSensitive` (`bex.sensitive`), and `lego/backend/internal/api/scope_matrix_overrides.go:25-26,143-150` classifies service and agent-session shell tickets (`POST /v1/services/{id}/shell-ticket`, `GQL Mutation.createShellSession`, `POST /v1/agent-sessions/{id}/shell-ticket`, `GQL Mutation.createAgentSessionShellSession`) as `core.OpClassSensitive` because arbitrary command execution in a workload is `printenv` / file exfiltration (`can_view_sensitive`). Yet `scope_matrix_overrides.go` (and `heuristicRequiredClass` in `scope_matrix_guard_test.go:232-234`) omits all four sandbox exec and file-transfer endpoints (`MCP sandbox_exec`, `REST POST /v1/sandboxes/{id}/exec`, `REST POST /v1/sandboxes/{id}/runs/{operation}/token`, `REST POST /v1/sandboxes/{id}/files/{operation}/token`), leaving all four at `core.OpClassWrite` (`bex.write`) in `scope_matrix_ops.go:713,1118,1119,1121`, while `sandbox.Service.authorizeExecTarget` (`exec.go:252`) and `authorizeFileTarget` (`file_connect.go:118,134`) only check `core.RelCanCreate` on non-agent sandboxes — allowing a `bex.write`-only OAuth 2.1 token (explicitly denied `bex.sensitive`) to run arbitrary commands and download/upload files in non-agent sandboxes and to bypass `requireScopeClass` on agent-session sandboxes before reaching OpenSandbox.

- **Root cause:**
  - `lego/backend/internal/api/scope_matrix_overrides.go` only overrides `shell-ticket` and `*ShellSession` (`:143-150`) to `core.OpClassSensitive`, omitting `"MCP sandbox_exec"`, `"REST POST /v1/sandboxes/{id}/exec"`, `"REST POST /v1/sandboxes/{id}/runs/{operation}/token"`, and `"REST POST /v1/sandboxes/{id}/files/{operation}/token"`, so `defaultScopeClass` assigned `core.OpClassWrite` (`scope_matrix_ops.go:713,1118,1119,1121`) and `scope_matrix_guard_test.go:232-234` (`heuristicRequiredClass`) never caught the omission.
  - `lego/backend/internal/sandbox/exec.go:252` (`authorizeExecTarget`) and `lego/backend/internal/sandbox/file_connect.go:118,134` (`authorizeFileTarget`) check only `core.RelCanCreate` (`bex.write`) on the workspace and only check `core.RelCanViewSensitive` when `metadataAgentSession != ""` (`exec.go:281-285`, `file_connect.go:145-149`), even though `deploy/gitops/authz/model.fga:92-93` grants both `can_create` and `can_view_sensitive` to the same roles (`developer` and `admin`) so adding `RelCanViewSensitive` preserves human role behavior while closing the `bex.write`-without-`bex.sensitive` OAuth gap.
