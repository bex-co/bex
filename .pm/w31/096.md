# 096 — `agentsessions` `AgentSkill.updatedBy` and `AgentSkillVersion.createdBy` persist an API key's raw Hydra client UUID and leak raw internal Kratos/Hydra UUIDs instead of public `usr-…` IDs across MCP, REST, and GraphQL

Why: `agentsessions.Service.CreateAgentSkill` (`lego/backend/internal/agentsessions/skills.go:228`) and `UpdateAgentSkill` (`:260`) write `core.SubjectFrom(ctx)` verbatim into `agent_skills.updated_by` (which `lego/backend/internal/store/agentskills.go:199-206,232-246` copies into `agent_skill_versions.created_by`) without resolving an attributed API key's human creator via `s.KeyCreator(ctx)`, breaking dashboard version-history author labels and account-deletion anonymization (`lego/backend/internal/store/accounts.go:446-447`); on reads, `skillView` (`skills.go:169-180`) and `skillVersionView` (`skills_versions.go:94-99`) emit those raw stored UUIDs verbatim instead of resolving human subjects through `core.PublicUserIDs`, leaking raw internal Kratos identity UUIDs even on human-session writes in violation of `docs/ADR020-identifiers.md`.

- **Root cause:**
  - `agentsessions.Service` embeds `*core.Base` (`lego/backend/internal/agentsessions/service.go:205`), which already carries `KeyCreators` in production (`s.KeyCreator(ctx)` at `lego/backend/internal/core/keyrole.go:127-138`), yet `CreateAgentSkill` (`lego/backend/internal/agentsessions/skills.go:228`) and `UpdateAgentSkill` (`:260`) write `core.SubjectFrom(ctx)` directly into `row.UpdatedBy` (which `store/agentskills.go:199-206,232-246` also copies into `agent_skill_versions.created_by`).
  - `store/accounts.go:446-447` anonymizes `agent_skills.updated_by` and `agent_skill_versions.created_by` by `WHERE updated_by = $1` / `WHERE created_by = $1` on the deleted human's Kratos subject, missing rows written with that user's API keys.
  - On reads, `agentsessions.Service` does not declare a `UserIDs core.UserIDLookup` field (compare `sandbox.Service` at `lego/backend/internal/api/server.go:1614`, `events.Service` at `:1458`, and `audit.Service` at `cmd/api/main.go:454`), and `skillView` (`skills.go:169-180`) + `skillVersionView` (`skills_versions.go:94-99`) pass `row.UpdatedBy` and `v.CreatedBy` through verbatim without calling `core.PublicUserIDs`.
- **Fix:**
  - Add a shared actor-resolution helper on `*agentsessions.Service` (or share with `w31/040`'s `actingSubject(ctx)`) using `s.KeyCreator(ctx)` so `CreateAgentSkill` (`skills.go:228`) and `UpdateAgentSkill` (`:260`) persist the attributed human creator's subject (failing closed on `ErrAuthzUnavailable` when creator lookup fails, falling back to `core.SubjectFrom(ctx)` only for non-key/unattributed machine callers).
  - Add `UserIDs core.UserIDLookup` to `agentsessions.Service` (`service.go:204`, wired via `userIDLookup(...)` in `lego/backend/internal/api/server.go` just like `sandbox.Service` and `events.Service`), and map `UpdatedBy` / `CreatedBy` through `core.PublicUserIDs` in `AgentSkills`, `AgentSkill`, `CreateAgentSkill`, `UpdateAgentSkill`, `AgentSkillVersions`, and `AgentSkillVersion` — preserving anonymized deleted-user markers and resolving any legacy stored key UUIDs via `KeyCreators` if available.
  - Surface impact: aligns `AgentSkill.updatedBy` and `AgentSkillVersion.createdBy` across MCP (`/mcp` and `/mcp/cloud-agents`), REST (`/v1/agent-skills*`), GraphQL (`agentSkills`, `agentSkill`, `agentSkillVersions`, `agentSkillVersion`), and the dashboard Version History UI (`useWorkspaceSubjectLabel` already matches `candidate?.userId === subject`).
