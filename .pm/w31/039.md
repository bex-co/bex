# 039 — Project and environment service-membership replacement silently wipes all existing services when given an unknown or foreign `serviceId` across MCP, REST, and GraphQL

Why: `projects.Service.SetServices` (`lego/backend/internal/projects/service.go:740-786`) and `environments.Service.SetServices` (`lego/backend/internal/environments/service.go:1345-1361`) never verify that every caller-supplied `serviceId` exists in the target workspace before `PGStore.SetProjectServices` / `PGStore.SetEnvironmentServices` clear all current members (`store/projects.go:215-220`, `store/environments.go:198-203`), so a single typo, stale ID, or foreign-workspace ID returns `200 OK` with `"serviceIds": []` and silently removes every existing service from the project/environment (and strips their environment ACL/network-isolation layer).

- **Attribution:** server (`lego/backend/internal/store`, `lego/backend/internal/projects`, `lego/backend/internal/environments`)
- **Root cause:**
  - `projects.Service.SetServices` (`lego/backend/internal/projects/service.go:740-786`) and `environments.Service.SetServices` (`lego/backend/internal/environments/service.go:1345-1361`) delegate directly to `PGStore.SetProjectServices` (`lego/backend/internal/store/projects.go:207-252`) and `PGStore.SetEnvironmentServices` (`lego/backend/internal/store/environments.go:190-216`).
  - Both store methods run inside `placementDiffAround` (`lego/backend/internal/store/projects.go:153-188`), which locks matching non-`build_source` `apps` rows in `tenantID` (`WHERE tenant_id = $1 AND (<pivot> = $2 OR id = ANY($3) OR name = ANY($3)) AND type <> 'build_source'`), then executes the clearing `UPDATE` (`store/projects.go:215-220`, `store/environments.go:198-203`) followed by the assignment `UPDATE` (`store/projects.go:227-236`, `store/environments.go:207-210`).
  - Neither the service layer nor `placementDiffAround` checks whether every requested entry in `serviceIDs` matched a locked row in `before`. Any unknown, build-source-carrier, or foreign-workspace ID matches 0 rows while the clearing `UPDATE` still unassigns all existing members and `projects.Service.SetServices` / `environments.Service.SetServices` subsequently strip their environment labels and IP allowlist layer on the `App` CRs.
  - In contrast, `projects.Service.setResourceMembers` (`lego/backend/internal/projects/service.go:818-828`) and `environments.Service.changeMembers` (`lego/backend/internal/environments/service.go:1608-1619`) validate every requested `databaseId`, `keyValueId`, and `envGroupId` against the workspace's known resources before mutating anything.
- **Fix:**
  - Inside `placementDiffAround` (`lego/backend/internal/store/projects.go:153-188`), add a `requireAllMatched bool` parameter (set `true` by `SetProjectServices` and `SetEnvironmentServices`, and `add` by `ChangeEnvironmentServices`; `false` for `ReturnEnvironmentServices` and `ChangeEnvironmentServices` removals where removing a non-member is a documented no-op, mirroring `environments/service.go:1614-1617`).
  - When `requireAllMatched` is `true`, before calling `mutate(locked)`, index the locked `before` rows by both `p.id` and `p.name` (preserving backward compatibility for legacy service names while excluding `TypeBuildSource` carriers already filtered out by the `SELECT`) and check every entry of `serviceIDs`. If any requested ID/name is missing, return `fmt.Errorf("%w: %q does not belong to workspace %q", core.ErrForbidden, badID, tenantID)` without running `mutate` (so the transaction rolls back with zero rows changed and never distinguishes nonexistent from foreign-workspace IDs, matching `projects/service.go:825` and `environments/service.go:1616`).
  - Update the stale "silently skipped" doc comments in `lego/backend/internal/store/projects.go:204-206` and `lego/backend/internal/store/environments.go:186-187`, and update `TestPGProjectServicesNeverMoveACarrier` (`lego/backend/internal/store/build_source_webhook_events_pg_test.go:81-113`) so passing a build-source carrier ID to `SetProjectServices` is asserted to fail with `core.ErrForbidden` while leaving both the carrier and existing/named services untouched.
  - Keep `environments.Service.patchApps` (`lego/backend/internal/environments/service.go:2183-2192`) intact: skipping a missing k8s CR during post-commit fan-out handles concurrent CR deletion races, not invalid caller input.
  - Surface impact: fixes MCP `update_project` / `update_environment`, REST `PUT /v1/projects/{id}/service-links` / `PUT /v1/environments/{id}/service-links`, and GraphQL `setProjectServices` / `setEnvironmentServices` together.
