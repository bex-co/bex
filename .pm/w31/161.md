# 161 — `envgroups.Service.{CreateEnvGroup,DeleteEnvGroup}` bypass protected-environment Admin enforcement when linking or detaching a workspace-scoped environment group on a protected-environment service across MCP, REST, and GraphQL

Why: `docs/ADR032-environments.md:113` (`w4/m594`) establishes that "Linking or unlinking a group to a service in a protected environment is a change to that service's environment variables, so it needs an Admin too", and `envgroups.Service.LinkService` (`lego/backend/internal/envgroups/service.go:1196-1200`) and `UnlinkService` (`:1405-1411`) both enforce `s.requireEnvironmentAdmin(ctx, g.TenantID, serviceEnv, core.VerbEnvironmentVariables)` on the service's environment even when the group itself is workspace-scoped (`g.EnvironmentID == ""`). However, `CreateEnvGroup` → `prepareCreateServices` (`service.go:465-484,561-595`) never calls `requireEnvironmentAdmin` on services in `req.ServiceIDs`, and `DeleteEnvGroup` (`service.go:881-918`) checks only `g.EnvironmentID` (`requireGroupAdmin`) and never checks the environments of services in `g.ServiceLinks` — allowing a non-Admin Developer who is refused `set_env_var`, `set_secret_file`, `link_env_group`, and `unlink_env_group` to inject arbitrary env vars/secret files into a protected-environment service via `create_env_group(serviceIds: [...])`, strip/unlink a workspace-scoped group from a protected-environment service via `delete_env_group`, and trigger immediate rollouts across MCP, REST, and GraphQL.

- **Expected / actual:**
  - **Expected:** Matching `LinkService` (`envgroups/service.go:1196-1200`), `UnlinkService` (`:1405-1411`), and `docs/ADR032-environments.md:113`, both `CreateEnvGroup` (for every service in `req.ServiceIDs`) and `DeleteEnvGroup` (for every linked service in `g.ServiceLinks`, before deleting the row or detaching) must call `s.requireEnvironmentAdmin(ctx, workspace, serviceEnv, core.VerbEnvironmentVariables)` and refuse a non-Admin Developer with `403 PROTECTED_ENVIRONMENT_ADMIN_REQUIRED` (leaving the protected service and group untouched and opening no rollout).
  - **Actual:**
    - `CreateEnvGroup` → `prepareCreateServices` only checks `validateEnvironment(ctx, "", workspace)` (no-op for workspace-scoped groups), `findCreateService` (`RelCanCreate`), and `validateGroupServiceEnvironment("", key, env)` (allowed for workspace-scoped groups), then calls `persistCreate` which mounts the group's env/files Secrets on the protected-environment service, triggers a `config_change` rollout (`rollLinked(..., ownerLink)`), and records `AuditVerbLinkService`.

- **Attribution:** server (`lego/backend/internal/envgroups`)
- **Root cause:**
  - `lego/backend/internal/envgroups/service.go:465-484` & `561-595`: `prepareCreateServices` resolves each `serviceID`'s environment via `s.serviceEnvironment(ctx, a)` (`:583`) and validates placement compatibility (`:587`), but omits `s.requireEnvironmentAdmin(ctx, workspace, env, core.VerbEnvironmentVariables)` (unlike `linkFetched` at `:1196-1200`).
  - `lego/backend/internal/envgroups/service.go:881-918`: `DeleteEnvGroup` checks only `s.requireGroupAdmin(ctx, g, "delete")` (`:886`, which checks `g.EnvironmentID` only) before deleting the row (`:892`) and detaching every service in `deleted.ServiceLinks` (`:900-910`), omitting any `requireEnvironmentAdmin` check on linked services' environments (unlike `UnlinkService` at `:1405-1411`).
- **Fix:**
  - In `envgroups.Service.prepareCreateServices` (`lego/backend/internal/envgroups/service.go:587-590`), right after `validateGroupServiceEnvironment`, call `if err := s.requireEnvironmentAdmin(ctx, workspace, env, core.VerbEnvironmentVariables); err != nil { return nil, nil, err }`.
  - In `envgroups.Service.DeleteEnvGroup` (`lego/backend/internal/envgroups/service.go:886-895`), before deleting the group row (and ideally inside or re-checked with the content lock before `DeleteEnvGroup` so a concurrent `LinkService` cannot slip in between check and delete), iterate over `g.ServiceLinks` (resolving each live App with `core.WithBuildSources(ctx)` and `s.serviceEnvironment(ctx, a)` — ignoring already-deleted services) and refuse with `s.requireEnvironmentAdmin(ctx, g.TenantID, serviceEnv, core.VerbEnvironmentVariables)` if any linked service sits in a protected environment.
  - Also update `envGroupActions` (`lego/backend/internal/envgroups/protection.go`) if `delete` capability projection for a workspace-scoped group linked to a protected-environment service should agree with `DeleteEnvGroup`'s refusal (`core.RestrictedDecision`).
