# 005 — MCP `trigger_build_source_build.clearCache` emits an untyped JSON Schema property (no `"type"`), bypassing SDK validation

Why: `trigger_build_source_build` is the only tool out of all 290 tools in live `tools/list` with an untyped input schema property (`clearCache` has no `"type"`), which breaks strict JSON Schema MCP/LLM tool validators and lets wrong types bypass SDK validation.

### `tools/list` emits `trigger_build_source_build.inputSchema.properties.clearCache` without a `"type"` field

- **Severity:** minor
- **Versions:** deployed pin `4b533337ab` (`7b046987bcd8`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-25, endpoint `/mcp` (`https://api.bex.co/mcp`), workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), run-minted all-permissions API key (revoked)

- **Expected / actual:**
  - **Expected:** Matching `trigger_deploy.clearCache` (fixed in `w5/m600`, `lego/backend/internal/deploys/mcp.go:194-196`), `trigger_build_source_build.inputSchema.properties.clearCache` must declare `"type": ["boolean", "string"]`, and passing an integer (`12345`) must fail at MCP SDK schema validation before invoking the handler.
  - **Actual:** Live `tools/list` emits `"clearCache": {"description": "true (or the REST string clear) builds without importing prior cached layers, as trigger_deploy's clearCache does"}` with no `"type"` field (the sole untyped input property across all 290 registered tools). Calling `trigger_build_source_build` with `clearCache: 12345` bypasses SDK schema validation and reaches the Go handler (`bad request: clearCache must be a boolean (or "clear"/"do_not_clear")`), whereas `trigger_deploy` rejects `clearCache: 12345` at SDK validation (`validating "arguments": validating /properties/clearCache: type: the value has type "integer", want one of "boolean, string"`).

- **Attribution:** server (`lego/backend/internal/deploys` + `lego/backend/internal/api` schema guard gap)
- **Root cause:**
  - `triggerBuildArgs.ClearCache` (`lego/backend/internal/deploys/build_sources.go:841`) has Go type `any`, and `registerBuildTools` (`:863-866`) registers `trigger_build_source_build` without `InputSchema: mcputil.InputSchema[triggerBuildArgs](mcputil.PropTypes("clearCache", "boolean", "string"))`.
  - `TestMCPArgumentTypesMatchUpstream` (`lego/backend/internal/api/mcp_parity_test.go:446`) rejects empty `{}` property schemas only for the 28 Render-pinned shared tools, so extension tools registered with `any` fields are not guarded by `mcp_schema_test.go`.
- **Fix:**
  - Add `InputSchema: mcputil.InputSchema[triggerBuildArgs](mcputil.PropTypes("clearCache", "boolean", "string"))` to `trigger_build_source_build` in `lego/backend/internal/deploys/build_sources.go:863-866` (matching `trigger_deploy` at `deploys/mcp.go:194-196`).
  - Add a server-wide guard test in `lego/backend/internal/api/mcp_schema_test.go` (alongside `TestMCPSchemasHaveNoLeakedTagDirectives`, using `walkBexToolSchemas`) asserting every property in every registered tool's `inputSchema` declares a JSON Schema type constraint (`type`, `anyOf`, `oneOf`, `allOf`, `enum`, `const`, or `$ref`), so no future extension can ship an untyped `any` property.
  - No REST, GraphQL, or UI change; MCP schema only.
- **Blast radius:** `lego/backend/internal/deploys/build_sources.go` and `lego/backend/internal/api/mcp_schema_test.go`. A recursive audit of all 290 live tools confirmed `trigger_build_source_build.clearCache` is the sole untyped input property (and zero untyped output properties exist).
