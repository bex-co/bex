# 017 — Build-source-linked services publish bogus `"branch": "main"` on MCP, REST, and GraphQL while write verbs refuse `"branch": "main"`

Why: When a service is linked to a Build Source (including an image-backed Build Source), `linkBuildSourceSpec` clears `spec.Repo`, `spec.Image`, and `spec.Branch`, Kubernetes CRD defaulting (`+kubebuilder:default=main`) re-populates `spec.Branch = "main"`, and `imageBackedBranch` (`lego/backend/internal/apps/service.go:948-953`) only suppresses `spec.Branch` when `spec.Image != ""` — so MCP, REST, and GraphQL all read back `"branch": "main"` even though the service has no repository and every write verb (`update_service`, `PATCH /v1/services/{id}`, `create_web_service` with `buildSourceId`) rejects `"branch": "main"` with `400`.

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `linkBuildSourceSpec` (`lego/backend/internal/apps/build_sources.go:1087-1093`) clears `spec.Repo`, `spec.Image`, and `spec.Branch` when linking a Build Source.
  - `AppSpec.Branch` (`lego/types/v1alpha1/app_types.go:703-706`) carries `// +kubebuilder:default=main`, so the API server stamps `spec.Branch = "main"` back onto the App CR when `spec.Branch == ""`.
  - `view(a)` (`lego/backend/internal/apps/service.go:1316`) computes `Branch: imageBackedBranch(a)`, and `imageBackedBranch` (`lego/backend/internal/apps/service.go:948-953`) only returns `""` when `prebuiltImageSource(a.Spec)` (`lego/backend/internal/apps/build_strategy.go:160-162`: `spec.Image != "" && spec.Repo == ""`). Because a Build-Source-linked service has both `spec.Image == ""` and `spec.Repo == ""`, `prebuiltImageSource` returns `false`, letting CRD-default `"main"` leak onto every read surface.
- **Fix:**
  - In `imageBackedBranch` (`lego/backend/internal/apps/service.go:948-953`), return `""` whenever `a.Spec.Repo == ""` (or explicitly `prebuiltImageSource(a.Spec) || a.Spec.BuildSource != nil`, noting `a.Spec.Repo == ""` covers both and matches `resolveSourcePatch`'s `next.repo == ""` rule from `w32/110`).
  - Confirm whether any other view helper (`viewRootDir`, `viewDockerfilePath`, `viewDockerContext`, `imageBackedAutoDeploy`) relies on `prebuiltImageSource` where `a.Spec.BuildSource != nil` is also affected (note `autoDeploy` IS valid for build-source-linked services as `autodeploy_only`; `linkBuildSourceSpec` already clears `RootDir`/`DockerfilePath`/`DockerContext` and none of them has a CRD `+kubebuilder:default`).
  - Applies uniformly to MCP (`get_service`, `list_services`, `link_service_to_build_source`, `update_service`, create tools), REST (`GET`/`POST`/`PATCH /v1/services`), GraphQL (`service`/`server`/`services`), CLI (`bex services get` / `create --from`), and the Dashboard because all read through `apps.view(a)`.
- **Blast radius:** `lego/backend/internal/apps/service.go:948-953` (single helper called only at `service.go:1316`), plus any tests in `lego/backend/internal/apps/build_sources*test.go` that assert `Branch` on a linked service. Affects all four linkable service types (`web_service`, `private_service`, `background_worker`, `cron_job`) when linked to either a git-backed or image-backed Build Source.
