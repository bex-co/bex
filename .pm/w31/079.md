# 079 — GraphQL `Mutation.setImage(deploy: true)` and `Mutation.setRepo(deploy: true)` trigger manual service deploys without `deploys_run: run` (`deploys.run`), letting `services: read_write`-only keys bypass `trigger_deploy`

Why: `lego/backend/internal/api/key_permission_ops.go:238,260` maps `GQL Mutation.setImage` and `GQL Mutation.setRepo` solely to `{core.KeyServicesManage}`, and neither their resolvers (`lego/backend/internal/apps/graphql.go:1855-1857,1890-1892`) nor `apps.Service.triggerSourceDeploy` (`lego/backend/internal/apps/service.go:5491-5501`) / `deploys.Service.TriggerManual` (`lego/backend/internal/deploys/service.go:650-652`) checks `core.KeyDeploysRun` — letting a `services: read_write`-only API key explicitly denied `Trigger and cancel deploys` trigger manual service deploys even on a no-op image save.

### GraphQL `setImage(deploy: true)` and `setRepo(deploy: true)` bypass `deploys_run: run`

- **Expected / actual:**
  - **Expected:** Under `core/keygrant.go:284-287,306-314`, `services: read_write` grants `"Create, update, and delete services"` (`core.KeyServicesManage`), not `"Trigger and cancel deploys"` (`core.KeyDeploysRun`, `deploys_run: run`). Calling `Mutation.setImage` or `Mutation.setRepo` with `deploy: true` must require `core.KeyDeploysRun` BEFORE mutating the service source or starting a deploy, and return `api_key_permission_denied` when the key lacks `deploys_run: run` (while keeping `deploy: false` / omitted working with `services: read_write` alone).
  - **Actual:**
    - Control confirmed `key-svconly` (`services: read_write`, zero `deploys_run`) was refused `MCP trigger_deploy` with `api_key_permission_denied` (`Trigger and cancel deploys`).
    - `POST /graphql` `Mutation.setImage(id: "srv-dc40jo6sfruc73ft2890", image: "traefik/whoami:v1.10", deploy: true)` succeeded (`200 OK`) even though the service's image was already `traefik/whoami:v1.10`, returned `"latestDeployId": "dep-dc40qnmsfruc73ft29a0"`, and `list_deploys` confirmed a brand-new `trigger: "manual"`, `bexTrigger: "manual"` deploy `dep-dc40qnmsfruc73ft29a0` (`status: "created"`).

- **Attribution:** server (`lego/backend/internal/{apps,deploys}`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:238,260` statically maps `GQL Mutation.setImage` and `GQL Mutation.setRepo` to `{core.KeyServicesManage}` only.
  - Both GraphQL resolvers (`lego/backend/internal/apps/graphql.go:1855-1857` for `setRepo` and `lego/backend/internal/apps/graphql.go:1890-1892` for `setImage`) invoke `s.triggerSourceDeploy(ctx, id, updated)` when `deploy` is true without checking `s.RequireKeyGrant(ctx, core.KeyDeploysRun)`.
  - `s.triggerSourceDeploy` (`lego/backend/internal/apps/service.go:5491-5501`) delegates to `deploysSvc.TriggerManual` (`lego/backend/internal/api/server.go:1283-1289` → `lego/backend/internal/deploys/service.go:650-652`), which authorizes `core.RelCanOperate` (role) but never checks `core.KeyDeploysRun`.
- **Fix:**
  - In `lego/backend/internal/apps/graphql.go:1812-1895`, when `deploy` is true in `Mutation.setRepo` and `Mutation.setImage`, call `s.RequireKeyGrant(ctx, core.KeyDeploysRun)` **before** calling `ApplyServicePatch` / `SetSourceAndRegistryCredential` so a denied key neither changes the source nor starts a deploy.
  - As defense-in-depth, also enforce `s.RequireKeyGrant(ctx, core.KeyDeploysRun)` inside `apps.Service.triggerSourceDeploy` (`lego/backend/internal/apps/service.go:5491`) and `deploys.Service.TriggerManual` (`lego/backend/internal/deploys/service.go:650`) — this protects `setRepo`, `setImage`, and `linkBuildSource` (`w31/071`) together from a single choke point.
- **Blast radius:** `lego/backend/internal/apps/{graphql,service}.go`, `lego/backend/internal/deploys/service.go`, and scoped-key tests in `lego/backend/internal/{apps,api}/`. Callers with `All` keys, human dashboard sessions, or `setImage`/`setRepo` with `deploy: false` (default) are unaffected.
