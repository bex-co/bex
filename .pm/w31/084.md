# 084 — `postgres.Service.Recover` skips checking the source database's protected/isolated environment when an explicit `environmentId` is passed, regressing `w4/356`

Why: `w5/m582` (`55bc18e6c7`) wired optional `environmentId` into `postgres.Service.Recover` (`lego/backend/internal/postgres/recovery.go:439,653-664`), replacing `sourceEnvironment` with `recoveryEnvironment`. When a caller supplies an explicit `environmentId`, `recoveryEnvironment` ignores `src.Labels[core.LabelEnvironment]` completely and checks only the target environment — letting a non-Admin Developer bypass a protected source environment's Admin gate (`PROTECTED_ENVIRONMENT_ADMIN_REQUIRED`) and copy a protected/isolated/allow-listed database's data into an unprotected environment with looser network boundaries, directly violating `inheritBoundary`'s documented invariant (`recovery.go:666-673`, `w4/356`).

### Explicit `environmentId` on `recover_postgres` (and REST/GraphQL twins) bypasses the source environment's protection and isolation boundary

- **Severity:** major
- **Versions:** deployed pin `c767c1bbd9` (`9b91284a4a2e`, active on production during run; zero diff in `postgres/recovery.go` vs `origin/main` `0177bc40ad`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-26, endpoint `/mcp` (`https://api.bex.co/mcp`), workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), disposable free Postgres `dpg-dc41ekesfruc73ft2bo0` placed in disposable protected environment `evm-dc41ip9m1rus738h06ng` (`protectedStatus: "protected"`) and targeted at disposable unprotected environment `evm-dc41ipesfruc73ft2cq0` under project `prj-dc41ip1m1rus738h06mg` (all deleted and verified `404`)
- **Repro:**
  ```sh
  # 1. Place a backed-up Postgres database <src-dpg> in a protected (and/or network-isolated / IP-allow-listed)
  #    environment <evm-prot> (protectedStatus: "protected").
  # 2. As a non-Admin Developer (can_create, without can_manage):
  #    Control — omitting environmentId inherits <evm-prot> and is refused with PROTECTED_ENVIRONMENT_ADMIN_REQUIRED:
  python3 scripts/qa-mcp.py --key-file <dev-key.json> call recover_postgres \
    '{"workspaceId":"tea-daif693dqjvc73e7as3g","postgresId":"<src-dpg>","name":"qa-rec-1"}'

  #    Bypass — passing an unprotected environmentId <evm-unprot> skips <evm-prot> completely in recoveryEnvironment():
  python3 scripts/qa-mcp.py --key-file <dev-key.json> call recover_postgres \
    '{"workspaceId":"tea-daif693dqjvc73e7as3g","postgresId":"<src-dpg>","name":"qa-rec-2","environmentId":"<evm-unprot>"}'
  #    (Same across REST POST /v1/postgres/{id}/recovery, REST POST /v1/postgres/{id}/recover, and GraphQL recoverDatabase.)
  ```
- **Expected / actual:**
  - **Expected:** Consistent with `inheritBoundary`'s security invariant (`lego/backend/internal/postgres/recovery.go:666-673`, `w4/356`: *"it is the source's data, so it must not land outside the protected, isolated or allow-listed environment that guards it"*) and `environments`'s move semantics (leaving a protected environment requires Admin), supplying an explicit `environmentId` that differs from `src`'s environment must ALSO resolve and authorize `src`'s environment — refusing non-Admin Developers with `PROTECTED_ENVIRONMENT_ADMIN_REQUIRED` whenever `src` resides in a protected environment (and preserving or Admin-gating departure from an isolated/protected source environment rather than silently dropping the source's `EnvironmentIPAllowList` and network isolation).
  - **Actual:**
    - `recoveryEnvironment` (`lego/backend/internal/postgres/recovery.go:653-664`) only checks `src.Labels[core.LabelEnvironment]` when `requestedID == ""`. When `requestedID != ""`, `src`'s environment is never resolved or checked at all: `RequirePlacement` runs only on `requestedID`, and `inheritBoundary` (`recovery.go:674-680`) stamps the target's `EnvironmentIPAllowList` and labels onto `newDB`, dropping the source's environment protection, isolation, and allow-list.
    - Live probe on `bex-canary` confirmed that calling `recover_postgres` on `dpg-dc41ekesfruc73ft2bo0` (inside protected `evm-dc41ip9m1rus738h06ng`) with explicit unprotected `environmentId: evm-dc41ipesfruc73ft2cq0` passed `recoveryEnvironment` (`recovery.go:439`) cleanly and only stopped later at `recovery.go:447` (`"dpg-dc41ekesfruc73ft2bo0" has no backups to recover from`, because the disposable fixture is on the free plan).
    - `lego/backend/internal/postgres/recovery_environment_test.go:246-271` tests only `"protected target environment requires Admin"` and has no test for a protected source environment with an explicit unprotected `environmentId`.
- **Wire evidence:**
  - Live setup & probe on `bex-canary` (fixtures deleted and verified `404`):
    - Placed `dpg-dc41ekesfruc73ft2bo0` in protected `evm-dc41ip9m1rus738h06ng` (`protectedStatus: "protected"`), then called `POST /mcp` `recover_postgres` targeting unprotected `evm-dc41ipesfruc73ft2cq0` (`rndr-id: 077fc1c5-9d33-dcf5`) → passed `recoveryEnvironment` (`recovery.go:439`) and reached line 447: `isError: true`, `"bad request: \"dpg-dc41ekesfruc73ft2bo0\" has no backups to recover from"`.
- **Attribution:** server (`lego/backend/internal/postgres`)
- **Root cause:**
  - Commit `55bc18e6c7` (`w5/m582`) replaced `sourceEnvironment(ctx, src, tenantID)` with `recoveryEnvironment(ctx, src, req.EnvironmentID, tenantID)` (`lego/backend/internal/postgres/recovery.go:653-664`):
    ```go
    environmentID := requestedID
    if environmentID == "" {
        if srcEnv := src.Labels[core.LabelEnvironment]; srcEnv != "" {
            environmentID = id.EnvironmentPublicID(srcEnv)
        }
    }
    if environmentID == "" {
        return core.EnvironmentAssignment{}, nil
    }
    return core.ResolveEnvironmentForCreate(ctx, s.Environments, environmentID, tenantID)
    ```
  - `Recover` (`recovery.go:420-442`) only checks `core.RelCanCreate` on `src` via `fetchLiveDatabase` (`recovery.go:421`) and never checks `src`'s environment when `requestedID != ""`. As a result, a non-Admin Developer who is blocked from moving `src` out of `evm-prot` (and even blocked from recovering `src` with omitted `environmentId`!) can clone `src`'s entire backup into any unprotected environment by passing `environmentId`.
- **Fix:**
  - In `postgres.Service.recoveryEnvironment` (`lego/backend/internal/postgres/recovery.go:653-664`), whenever `srcEnv := src.Labels[core.LabelEnvironment]` is non-empty:
    1. Resolve the source environment (`core.ResolveEnvironmentForCreate(ctx, s.Environments, id.EnvironmentPublicID(srcEnv), tenantID)`) **before** (or alongside) resolving `requestedID`, so leaving a protected source environment enforces the same `PROTECTED_ENVIRONMENT_ADMIN_REQUIRED` Admin gate as moving a resource out of a protected environment or recovering in place.
    2. If `requestedID != ""` resolves to a different environment than `srcEnv`, also check whether `src`'s environment has `networkIsolationEnabled` or environment-level boundary protections — if moving data out of a protected/isolated source environment is allowed only for Admins (consistent with `environments` move semantics and Render's `environmentId` recovery option), the Admin check on `srcEnv` already gates protected sources, and consider also documenting/deciding whether non-Admin recovery across an isolated or IP-allow-listed source environment boundary should be refused or Admin-only (preserving `w4/356`'s intent while keeping Render's `environmentId` parity for authorized callers).
  - Update the stale comment on `inheritBoundary` (`recovery.go:666-673`) so code and security invariants agree.
  - Surface impact: protects MCP `recover_postgres`, REST `POST /v1/postgres/{id}/recovery`, REST `POST /v1/postgres/{id}/recover`, and GraphQL `recoverDatabase` uniformly.
- **Blast radius:** `lego/backend/internal/postgres/recovery.go` and `lego/backend/internal/postgres/recovery_environment_test.go`.
- **Regression checks:**
