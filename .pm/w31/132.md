# 132 — `apps.resolveCreateSubdomainPolicy` accepts `renderSubdomainPolicy: "disabled"` with unverified create-time custom domains, creating unreachable services with zero hosts across MCP `deploy`, `validate_bex_yml`, Blueprints, and REST `POST /v1/services`

Why: `w4/142` updated `SetSubdomainPolicy` / `checkSubdomainPolicy` (`lego/backend/internal/apps/settings_check.go:481-485`, `service.go:6208`) to refuse disabling the platform subdomain until a custom domain is actually verified (since `materializeNewApp` strips unverified create-time claims from `a.Spec.Host`/`a.Spec.Hosts` via `applyVerifiedDomainClaims` at `service.go:3335`), but `resolveCreateSubdomainPolicy` (`service.go:4176-4185`) still checks only `len(req.Hosts) == 0` — letting new services be created with `renderSubdomainPolicy: "disabled"` and zero verified hosts (`url` and `urls` omitted, completely unreachable), while immediately refusing `update_service` with the exact same value on that service.

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `lego/backend/internal/apps/service.go:4176-4185`: `resolveCreateSubdomainPolicy` checks only `if subdomainPolicy == appv1alpha1.SubdomainPolicyDisabled && len(req.Hosts) == 0`, treating any unverified create-time `req.Hosts` entry as sufficient.
  - `lego/backend/internal/apps/service.go:3328-3335`: in production (`s.managedDomainClaims(a)` is true), `materializeNewApp` inserts `req.Hosts` as `pending` (`unverified`) domain claims and calls `applyVerifiedDomainClaims(&a.Spec, rows)`, which clears `a.Spec.Host` and `a.Spec.Hosts` while leaving `a.Spec.SubdomainPolicy == "disabled"` intact.
  - Existing unit tests (`subdomain_policy_test.go:98`, `create_normalization_test.go:284`) ran without managed domain claims (`newService(nil)`), so `a.Spec.Host` remained populated in unit tests and masked the production mismatch.
- **Fix:**
  - When managed domain claims are active (`s.Store != nil` / `s.managedDomainClaims` enabled), refuse `SubdomainPolicyDisabled` on **new** service creation in `planNewApp` (`apps/service.go:2760`) and Blueprint create/validate planning (`blueprint.go` / `deploy.go`) with `subdomainNeedsVerifiedDomain`, because a brand-new service cannot yet have a verified custom domain.
  - Keep `specFromCreate` (`resolveCreateSubdomainPolicy`) compatible with Blueprint **updates** of an existing service (`updateStackService` in `deploy.go`) and `blueprint_export_roundtrip_test.go` by checking `existing.Spec.Host != "" || len(existing.Spec.Hosts) > 0` (verified hosts already present on `existing`) on updates, and refusing create-time `renderSubdomainPolicy: "disabled"` when no verified custom domain exists yet.
  - Surface impact: aligns MCP (`deploy`, `validate_bex_yml`, `create_blueprint`/`plan_blueprint`/`approve_blueprint`), REST (`POST /v1/services`, live and `?dryRun=true`), and GraphQL Blueprint validation with `SetSubdomainPolicy` / `update_service` (`w4/142`).
