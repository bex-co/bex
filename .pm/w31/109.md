# 109 — `core.KeyPermissionCatalog` advertises `agent_secrets: write` (`agents.secrets.set`) with `requiredRole: "developer"`, even though every operation using it (`SetAgentSecret`, `DeleteAgentSecret`) requires Admin (`RelCanManage`)

Why: `lego/backend/internal/core/keygrant.go:406-408` sets `agent_secrets: write` (`KeyAgentsSecretsSet`) to `rels(RelCanCreate)` (`requiredRole: "developer"`), contradicting the catalog's own rule (`keygrant.go:277-281`: "the relation bex's own verbs decide its actions with") — because every single operation mapped to `KeyAgentsSecretsSet` (`SetAgentSecret` at `agentsessions/secrets.go:257` and `DeleteAgentSecret` at `:399`, across MCP, REST, and GraphQL) authorizes `core.RelCanManage` (Admin only), so a Developer is shown `agent_secrets: write` as `grantable: true` and can mint a key with it, yet every verb it purports to unlock unconditionally fails `403 FORBIDDEN`.

- **Root cause:**
  - `lego/backend/internal/core/keygrant.go:406-408`:
    ```go
    {ID: "agent_secrets", Name: "Agent secrets", Levels: []KeyPermissionLevel{
        lvl(KeyLevelWrite, rels(RelCanCreate), KeyAgentsSecretsSet),
    }},
    ```
    uses `RelCanCreate` (`developer`) instead of `RelCanManage` (`admin`), even though every consumer of `KeyAgentsSecretsSet` (`lego/backend/internal/api/key_permission_ops.go:121,213,548,746,800,1176` → `agentsessions/secrets.go:257,399`) authorizes `core.RelCanManage` (and `w31/063` proposes also using `KeyAgentsSecretsSet` for admin-only `modelApiKey` writes on `UpdateEnvironment`).
- **Fix:**
  - Change `lego/backend/internal/core/keygrant.go:407` from `rels(RelCanCreate)` to `rels(RelCanManage)` so `agent_secrets: write` advertises `requiredRole: "admin"`, sets `grantable: false` for non-Admin Developers, and refuses Developer minting in `RequireGrantableKeyGrant`.
  - Add a unit test in `lego/backend/internal/core/keygrant_test.go` / `lego/backend/internal/apikeys/` verifying a Developer cannot grant `agent_secrets: write` while an Admin can (and verify all other Admin-only single-action catalog permissions match their verbs' relations).
