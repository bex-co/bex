# 091 — `agentsessions.Service.UpdateAgentSkill` never detects empty or no-op updates, bumping `version` and appending duplicate zero-diff revisions across MCP, REST, and GraphQL

Why: `agentsessions.Service.UpdateAgentSkill` (`lego/backend/internal/agentsessions/skills.go:246-276`) unconditionally stamps a new version and writes to `agent_skills` / `agent_skill_versions` even when zero fields are provided (`{}`) or every supplied field matches the stored value — bumping `version`, advancing `updatedAt`, and appending identical zero-diff `"Update skills/<name>/SKILL.md"` entries toward the 200-version retention cap, contrary to `skills_versions_test.go:416-418` and `sandbox.Service.UpdateGroupCredential` (`lego/backend/internal/sandbox/credentials.go:436-459`).

- **Attribution:** server (`lego/backend/internal/agentsessions/skills.go`)
- **Root cause:**
  - `agentsessions.Service.UpdateAgentSkill` (`lego/backend/internal/agentsessions/skills.go:246-276`) mutates `row` via `applySkillInput(&row, in, false)` without comparing the post-input state against the pre-input `row`, and always calls `stampSkillVersion(&row, false)` and `s.Skills.UpdateAgentSkill(ctx, row, version, skillLimits)`.
- **Fix:**
  - In `UpdateAgentSkill` (`lego/backend/internal/agentsessions/skills.go:246-276`), keep a copy of the loaded `before := row` (and `slices.Clone(row.Triggers)`), run `applySkillInput(&row, in, false)` so invalid inputs are still refused, check `if in.IfVersion != nil && *in.IfVersion != before.Version` (returning `errSkillConflict` so stale optimistic locks are still refused even on a no-op), and if `row.Name == before.Name && row.Description == before.Description && row.Body == before.Body && row.Extra == before.Extra && row.Enabled == before.Enabled && slices.Equal(row.Triggers, before.Triggers)`, return `skillView(before, true), nil` without writing a new version or bumping `updatedAt`.
  - Surface impact: fixes MCP (`/mcp` and `/mcp/cloud-agents`), REST, and GraphQL together from the single service method.
