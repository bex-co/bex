# 095 — `webhooks.Service.Create` records an API key's Hydra client UUID as `created_by`, so `webhooks.Worker.notifyFailure` fails `SubjectIsWorkspaceAdmin` (`kind = 'user'`) and silently drops all failure and auto-disable emails

Why: `webhooks.Service.Create` (`lego/backend/internal/webhooks/service.go:582,607-612`) explicitly allows attributed workspace API keys (`AuthorizeExportClass`, `w9/m481`) and then persists `id.Subject` verbatim into `webhook_endpoints.created_by` — which for an API key is its Hydra OAuth2 client UUID rather than its human Admin creator — while `webhooks.Worker.notifyFailure` (`lego/backend/internal/webhooks/worker.go:820-826,871`) checks `store.PGStore.SubjectIsWorkspaceAdmin` (`lego/backend/internal/store/members.go:161-167`, filtering `AND kind = 'user'`) and calls Kratos `w.Emails.LookupEmails(ctx, []string{d.CreatedBy})`, unconditionally skipping every 3rd-failure warning and final auto-disable email for API-key-created webhooks.

- **Attribution:** server (`lego/backend/internal/webhooks`)
- **Root cause:**
  - `webhooks.Service.Create` (`lego/backend/internal/webhooks/service.go:607-612`) copies `id.Subject` directly into `createdBy` without calling `s.KeyCreator(ctx)` (`lego/backend/internal/core/keyrole.go:127-138`), even though `webhooks.Service` embeds `*core.Base` (`KeyCreators` is already wired in `lego/backend/cmd/api/main.go:1013`) and line 582 already calls `s.AuthorizeExportClass(ctx)` which itself calls `s.KeyCreator(ctx)`!
  - `webhooks.Worker.notifyFailure` (`lego/backend/internal/webhooks/worker.go:820-826`) calls `w.Store.SubjectIsWorkspaceAdmin(ctx, d.TenantID, d.CreatedBy)`, whose SQL (`lego/backend/internal/store/members.go:164-166`) checks `WHERE tenant_id = $1 AND subject = $2 AND role = 'admin' AND kind = 'user'`. An API key's Hydra client UUID is stored with `kind = 'machine'` (never `kind = 'user'`) and has no Kratos email record (`worker.go:871`), so failure and auto-disable emails can never be sent.
  - Note also sibling `webhooks.Service.Resend` (`lego/backend/internal/webhooks/service.go:912-915`), which records `requestedBy = identity.Subject` on `webhook_deliveries.requested_by`, and GraphQL `webhookEndpoint.createdBy` (`lego/backend/internal/webhooks/graphql.go:43`), which exposes `createdBy` directly on the wire.
- **Fix:**
  - In `webhooks.Service.Create` (`lego/backend/internal/webhooks/service.go:607-610`), resolve an attributed API key's human creator via `s.KeyCreator(ctx)` when `id.IsAPIKey()` (failing closed on `ErrAuthzUnavailable`) and persist the human creator's Kratos subject as `created_by` — preserving round-14 #6's security property (a demoted or removed creator stops receiving notices, while an active Admin who created the webhook via an API key actually receives failure/auto-disable alerts).
  - Check whether `webhooks.Service.Resend` (`service.go:912-915`) should resolve `requestedBy` the same way or keep key attribution distinctly, and check whether GraphQL `webhookEndpoint.createdBy` should resolve to a public `usr-…` ID (per `ADR020`) rather than exposing a raw Kratos/Hydra UUID.
  - Surface impact: fixes webhook failure and auto-disable email delivery for every webhook created via MCP (`create_webhook_endpoint`), REST (`POST /v1/webhooks`), and GraphQL (`createWebhookEndpoint`) using an API key.
