# 215 — `apps.Service.GenerateBlueprint`, `envgroups.Service.ExportEnvGroup`, and `secrets.Service.ListSecretFiles` omit uncached `AuthorizeFresh` on `RelCanViewSensitive` reads across MCP, REST, and GraphQL

Why: Every `OpClassSensitive` / `RelCanViewSensitive` secret and manifest read in `lego/backend/` is expected to re-assert authorization uncached before touching sensitive state (`core/base.go:1093-1161`, `codex round-8 #8`, `round-15 #4`) — e.g. sibling `apps.Service.PreviewBlueprint` calls `s.AuthorizeFresh(ctx, core.RelCanViewSensitive)` (`lego/backend/internal/apps/blueprint.go:1276`), `envgroups.Service` has `authorizeGroupSensitiveFresh` (`lego/backend/internal/envgroups/service.go:1948-1950`), and even key-names-only `secrets.Service.ListEnvVarNames` / `EnvVarKeys` calls `s.AuthorizeAppFresh(ctx, core.RelCanViewSensitive, a)` (`lego/backend/internal/secrets/service.go:445-446,506`) before reading OpenBao. Three `RelCanViewSensitive` read paths omit that uncached re-check: `apps.Service.GenerateBlueprint` (`lego/backend/internal/apps/blueprint_generate.go:153,163,177,209,217`, backing MCP `generate_blueprint`, REST `POST /v1/blueprints/generate`, and GraphQL `Query.generateBlueprint`, which exports literal `Spec.Env` values and full service/datastore/env-group wiring), `envgroups.Service.ExportEnvGroup` (`lego/backend/internal/envgroups/service.go:397-416`, called by `GenerateBlueprint`), and `secrets.Service.ListSecretFiles` (`lego/backend/internal/secrets/files.go:69-84`, backing MCP `list_secret_files` and GraphQL `Query.secretFiles`, which reads OpenBao `s.readMap(ctx, filesPath(service))` after only cached `s.scope`).

### `generate_blueprint` (`apps.GenerateBlueprint` / `envgroups.ExportEnvGroup`) and `list_secret_files` (`secrets.ListSecretFiles`) omit uncached `AuthorizeFresh`

- **Expected / actual:**
  - **Expected:** Matching `apps.Service.PreviewBlueprint` (`lego/backend/internal/apps/blueprint.go:1276`), `envgroups.Service.authorizeGroupSensitiveFresh` (`lego/backend/internal/envgroups/service.go:1948-1950`), and `secrets.Service.readScopedEnv` / `ListSecretFilesWithContentPage` / `GetSecretFile` (`secrets/service.go:506`, `secrets/files.go:109,132`):
    1. `apps.Service.GenerateBlueprint` must re-assert uncached `RelCanViewSensitive` via `s.AuthorizeFresh(ctx, core.RelCanViewSensitive)` (workspace gate) and `s.AuthorizeDatabaseFresh` / `s.AuthorizeKeyValueFresh` / `s.AuthorizeAppFresh` on each exported resource (including linked build-source carriers) before reading `Spec.Env` or emitting the manifest.
    2. `envgroups.Service.ExportEnvGroup` must call `s.authorizeGroupSensitiveFresh(ctx, g)` right after `s.authorizeGroup(ctx, core.RelCanViewSensitive, gid)`.
    3. `secrets.Service.ListSecretFiles` must call `s.AuthorizeAppFresh(ctx, core.RelCanViewSensitive, a)` right after `s.scope(ctx, core.RelCanViewSensitive, service)` before calling `s.readMap(ctx, filesPath(service))`, matching sibling `ListEnvVarNames` / `EnvVarKeys`.
  - **Actual:** All three methods authorize exclusively via cached OpenFGA checks and never call their `Authorize*Fresh` helpers, allowing a recently revoked/demoted member to export service `Spec.Env` literals, datastore/env-group wiring manifests, and OpenBao secret-file inventories during OpenFGA's `PositiveTTL` window.
- **Wire evidence:**
  - Live execution against disposable service `srv-dc595k0tfgsc73euc0n0` in `bex-canary` confirmed both MCP tools are live and execute these exact service paths:

- **Attribution:** server (`lego/backend/internal/apps`, `lego/backend/internal/envgroups`, and `lego/backend/internal/secrets`)
- **Root cause:**
  - `lego/backend/internal/apps/blueprint_generate.go:153,163,177,209,217`: `GenerateBlueprint` calls cached `s.Authorize`, `s.AuthorizeDatabase`, `s.AuthorizeKeyValue`, `s.AuthorizeApp`, and `s.buildSourceApp`, omitting `s.AuthorizeFresh`, `s.AuthorizeDatabaseFresh`, `s.AuthorizeKeyValueFresh`, and `s.AuthorizeAppFresh` (unlike sibling `PreviewBlueprint` at `blueprint.go:1276`).
  - `lego/backend/internal/envgroups/service.go:397-416`: `ExportEnvGroup` calls cached `s.authorizeGroup(ctx, core.RelCanViewSensitive, gid)` (`:398`) and omits `s.authorizeGroupSensitiveFresh(ctx, g)` (`:1948-1950`).
  - `lego/backend/internal/secrets/files.go:69-84`: `ListSecretFiles` calls `_, ctx, service, err := s.scope(ctx, core.RelCanViewSensitive, service)` (`:70`), discards the `*appv1alpha1.App` return value, and reads OpenBao `s.readMap(ctx, filesPath(service))` (`:74`) without `s.AuthorizeAppFresh(ctx, core.RelCanViewSensitive, a)`.
- **Fix:**
  - In `lego/backend/internal/apps/blueprint_generate.go`:
    1. Right after `s.Authorize(ctx, core.RelCanViewSensitive)` (`:153`), call `if err := s.AuthorizeFresh(ctx, core.RelCanViewSensitive); err != nil { return GenerateBlueprintResult{}, err }`.
    2. Right after `s.AuthorizeDatabase` (`:163`), `s.AuthorizeKeyValue` (`:177`), `s.AuthorizeApp` (`:209`), and `s.buildSourceApp` (`:217`), call `s.AuthorizeDatabaseFresh(ctx, core.RelCanViewSensitive, d)`, `s.AuthorizeKeyValueFresh(ctx, core.RelCanViewSensitive, kv)`, and `s.AuthorizeAppFresh(ctx, core.RelCanViewSensitive, a/carrier)` respectively.
  - In `lego/backend/internal/envgroups/service.go:397-402` (`ExportEnvGroup`), right after `s.authorizeGroup`, call `if err := s.authorizeGroupSensitiveFresh(ctx, g); err != nil { return "", nil, err }`.
  - In `lego/backend/internal/secrets/files.go:70-74` (`ListSecretFiles`), capture `a, ctx, service, err := s.scope(ctx, core.RelCanViewSensitive, service)` and call `if err := s.AuthorizeAppFresh(ctx, core.RelCanViewSensitive, a); err != nil { return nil, err }` before `s.readMap`.
