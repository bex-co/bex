# 163 — `postgres.Service.{DeleteUser,DeleteCredential}` omit uncached `AuthorizeDatabaseFresh` re-authorization before revoking live database logins and retiring the owner role across MCP, REST, and GraphQL

Why: Every other credential and destructive-sink verb in `lego/backend/internal/postgres/` re-asserts authorization uncached via `s.AuthorizeDatabaseFresh` (`createUser` at `access.go:173`, `DeletePostgres` at `service.go:1107`, `GetConnectionInfo` at `service.go:1170`, `executeAuthorizedQuery` at `query.go:210`, `ListExports` at `recovery.go:710`, `Insights` at `insights.go:588,930`) per the `codex round-8 #8` / `round-9 #7` invariant so a member revoked within OpenFGA's `PositiveTTL` cache window cannot ride a cached allow into one last credential or destructive write. `DeleteUser` (`lego/backend/internal/postgres/access.go:262-269`) and `DeleteCredential` (`:315-330`, which can permanently retire the create-time owner login via `retireOwner` at `:332-347`) call only the cached `s.fetchLiveDatabase(ctx, core.RelCanCreate, name)` and never call `s.AuthorizeDatabaseFresh(ctx, core.RelCanCreate, d)` — allowing a recently revoked member to delete user password Secrets and retire active Postgres credentials across MCP (`delete_postgres_user`, `delete_postgres_credential`), REST, and GraphQL.
