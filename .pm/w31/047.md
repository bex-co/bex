# 047 — MCP `update_environment_variables` unconditionally fails on every build source (`bds-…`) with a contradictory `use saveMode "save_only"` error

Why: `update_environment_variables` (`lego/backend/internal/secrets/mcp.go:160-196`) wraps its handler in `mcputil.Scoped(s.envScope, …)` — which explicitly admits `bds-…` build sources and stamps `WithStagedWrite(ctx)` (`lego/backend/internal/secrets/staged.go:103-109`) — and `create_build_source`'s description (`lego/backend/internal/apps/build_sources_graphql.go:359`) instructs callers to edit build-source env vars with the env-var tools, yet `update_environment_variables` hardcodes `SaveMode: SaveModeRebuild` into `s.PatchEnvironment` (`secrets/mcp.go:176-178`), which `secrets/batch.go:115-117` unconditionally rejects for every build source while instructing the caller to pass `saveMode: "save_only"` — an argument `update_environment_variables` does not even accept.

- **Attribution:** server (`lego/backend/internal/secrets`)
- **Root cause:**
  - `lego/backend/internal/secrets/mcp.go:172` wraps `update_environment_variables` in `mcputil.Scoped(s.envScope, …)`. For any `bds-…` ID, `s.envScope` (`lego/backend/internal/secrets/staged.go:103-109`) resolves the carrier via `s.BuildSourceScope(ctx, id)` and returns `WithStagedWrite(ctx)`.
  - Inside the handler (`lego/backend/internal/secrets/mcp.go:176-178`), `update_environment_variables` ignores `stagedWrite(ctx)` and unconditionally passes `SaveMode: SaveModeRebuild` into `s.PatchEnvironment`.
  - `s.PatchEnvironment` (`lego/backend/internal/secrets/batch.go:115-117`) rejects any build source whose `patch.SaveMode != SaveModeOnly` with `"a build source saves its environment without building; use saveMode \"save_only\" and trigger a build"`.
  - Additionally, `lego/backend/internal/secrets/mcp.go:185-189` treats `!result.RolledOut` as `isError = true` (assuming every non-rollout is a failed deploy), which would still mark a staged build-source save as an error unless handled explicitly.
- **Fix:**
  - In `lego/backend/internal/secrets/mcp.go:176-195` (`update_environment_variables`), check `staged := stagedWrite(ctx)`:
    - When `staged` is true (a `bds-…` build source scoped by `s.envScope`), pass `SaveMode: SaveModeOnly` to `s.PatchEnvironment` (note: coordinate with `w31/048` so image-backed build sources are rejected in `secrets` before writing).
    - When `staged` is true and `err == nil`, return `isError: false` with clear text stating that the build source's environment variables were saved without building and to call `trigger_build_source_build` to apply them (skipping the `!result.RolledOut` error branch and the deploy-response formatting).
  - Keep service (`srv-…`) behavior byte-identical (`SaveModeRebuild`, Render's exact deploy/queued/error copy; note `w31/032` tracks the separate queued-deploy text bug).
  - Surface impact: MCP-only (`update_environment_variables`); brings it into agreement with `set_env_var`, `update_env_vars`, `patch_service_environment`, REST `/v1/build-sources/{id}/env-vars`, and `create_build_source`'s description.
