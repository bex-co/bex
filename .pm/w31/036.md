# 036 — Postgres credential rotation (`create_postgres_credential` / `POST /v1/postgres/{id}/credentials`) immediately breaks SQL queries, Postgres insights, and connection info with 500 / `"internal error"` until CNPG reconciles the role

Why: `DatabaseReconciler.reconcileDefaultConnectionSecret` (`lego/operator/internal/controller/database_default_credential.go:49-96`) writes `<id>-default-app` and advances `db.Status.SecretName` the instant the new user's password Secret exists — which `postgres.Service.createUser` creates before patching `spec.defaultUser` — without waiting for CloudNativePG to reconcile the new role into PostgreSQL (`cluster.status.managedRolesStatus.byStatus.reconciled`), causing immediate `FATAL: password authentication failed for user "<role>" (Role does not exist)` / HTTP 500 across every consumer of `db.CurrentConnectionSecretName()`.

- **Attribution:** server (`lego/operator/internal/controller`)
- **Root cause:**
  - `postgres.Service.createUser` (`lego/backend/internal/postgres/access.go:220-246`) creates the new role's Kubernetes Secret (`secretName`) *before* patching `d.Spec.Users` and `d.Spec.DefaultUser = role` on the `Database` CR.
  - `DatabaseReconciler.Reconcile` (`lego/operator/internal/controller/database_controller.go:1051-1081`) updates CNPG `Cluster.spec.managed.roles` via `reconcileCluster` and immediately calls `r.reconcileDefaultConnectionSecret(ctx, &db)` (`:1077`) in the same reconcile pass without passing `cluster` or checking whether CNPG has reconciled the role.
  - `reconcileDefaultConnectionSecret` (`lego/operator/internal/controller/database_default_credential.go:49-96`) only checks whether `<id>-app` and `userSecret` exist (`optionalSecret`). Because `userSecret` already exists, it immediately rewrites `<id>-default-app` with the unprovisioned `db.Spec.DefaultUser` and returns `target.Name`, so `stampConnectionStatus` (`database_controller.go:1314-1317`) switches `db.Status.SecretName` immediately (or, on a second rotation, `<id>-default-app` is overwritten in place while `status.secretName` already points at it).
  - Every consumer of `db.CurrentConnectionSecretName()` (`lego/types/v1alpha1/database_types.go:576-581`) — `query_render_postgres`, REST/GraphQL SQL console, `list_postgres_processes`, `list_postgres_table_scans`, `get_postgres_sizes`, `list_postgres_parameter_overrides`, `GET /v1/postgres/{id}/connection-info`, `reconcilePoolerConnectionSecret` (`database_controller.go:1569-1575`), and Blueprint `fromDatabase` — immediately connects as a role that PostgreSQL has not created yet. In `lego/backend/internal/postgres/query.go:413-416`, the `pgx.ConnectConfig` failure maps to `errQueryConnClose` (`query.go:85`), returning HTTP 500 / `"internal error"`.
- **Fix:**
  - Pass `cluster` into `reconcileDefaultConnectionSecret(ctx, &db, cluster)` (`lego/operator/internal/controller/database_controller.go:1077`, `lego/operator/internal/controller/database_default_credential.go:49`).
  - Before creating/updating `<id>-default-app`, verify that CNPG reports `db.Spec.DefaultUser` as reconciled in `cluster.status.managedRolesStatus.byStatus.reconciled` (read via `unstructured.NestedStringSlice(cluster.Object, "status", "managedRolesStatus", "byStatus", "reconciled")`, and if `status.managedRolesStatus.passwordStatus.<user>.secretVersion` is populated, check it matches `userSecret.ResourceVersion` when rotating an existing role's password).
  - While `db.Spec.DefaultUser` is not yet in `reconciled`, return `"", nil` *without* mutating `<id>-default-app`:
    - On the first rotation (`owner → rotated1`), `stampConnectionStatus` (`database_controller.go:1317`) already preserves `db.Status.SecretName` (`<id>-app`).
    - On a subsequent rotation (`rotated1 → rotated2`), `<id>-default-app` retains `rotated1`'s working credentials until `rotated2` is reconciled.
    - `DatabaseReconciler.SetupWithManager` (`database_controller.go:2265`) already watches owned CNPG `Cluster` objects with `predicate.ResourceVersionChangedPredicate{}`, so CNPG's status update immediately re-triggers reconcile, backed up by the existing `defaultCredentialRequeue` (`database_controller.go:1125-1128`).
  - Do **not** weaken `errQueryConnClose` sanitization in `lego/backend/internal/postgres/query.go` (per `w4/done/177.md`); fixing the operator cutover gate eliminates the broken credential window for all consumers (MCP, REST, GraphQL, pooler, and Blueprints).
