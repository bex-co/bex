# 011 — `events.FilterOf` never validates `eventTypes`/`type` and silently drops malformed `startTime`/`endTime`, so MCP `list_events` / `list_service_events` and GraphQL `serviceEvents` diverge from REST `400 bad_request`

Why: `lego/backend/internal/events/service.go:1074-1086` (`FilterOf`) neither checks event types against the known vocabulary nor returns an error on unparseable timestamps, so MCP `list_events` (a shared Render tool), `list_service_events`, and GraphQL `serviceEvents` silently return empty lists on unknown event types (like `"deploy_failed"`), and `list_service_events` / GraphQL `serviceEvents` silently ignore malformed `startTime`/`endTime` and return the default 1-hour window while REST returns `400 bad_request`.

### MCP `list_events` / `list_service_events` and GraphQL `serviceEvents` silently succeed on invalid event types and (on `list_service_events` / GraphQL) malformed `startTime`/`endTime`

- **Expected / actual:**
  - **Expected:** Per Render's pinned MCP server (`render-oss/render-mcp-server@a18ef3ee`, `pkg/event/tools.go`), `list_events` forwards `strings.Join(eventTypes, ",")` to Render's REST `GET /v1/services/{id}/events?type=...`, which returns `400` on unknown event types. Under Render parity (`AGENTS.md`) and ADR006's shared-service rule, passing an unknown event type to REST, MCP `list_events` / `list_service_events`, or GraphQL `serviceEvents` must return `core.ErrBadRequest` (accepting both Render's event-type enum and bex's own documented service event types), and passing a malformed `startTime` or `endTime` to `list_service_events` or GraphQL `serviceEvents` must return `core.ErrBadRequest` just like REST and MCP `list_events` already do.
  - **Actual:**
    - MCP `list_events` with `eventTypes: ["bogus_event_type"]` returns `200` (`isError` unset) `"[]\n\n cursor: \"\""`.
    - MCP `list_service_events` with `type: "bogus_event_type"` returns `200` `{"events":[]}`.
    - GraphQL `serviceEvents` with `type: "bogus_event_type"` returns `200` `{"data":{"serviceEvents":[]}}` with no errors.
    - MCP `list_service_events` with `startTime: "not-a-time"` returns `200` and silently falls back to the last-hour window (returning all recent events of the active service instead of an error).
    - GraphQL `serviceEvents` with `startTime: "not-a-time", endTime: "also-bad"` returns `200` `{"data":{"serviceEvents":[]}}` with no errors.
    - REST controls `GET /v1/services/srv-dbkq3hdhhjfs73eiahe0/events?type=bogus_event_type`, `?startTime=not-a-time`, and `?endTime=not-a-time` all return `400 bad_request`, and MCP `list_events` with `startTime: "not-a-time"` returns `bad request: startTime must be an RFC3339 timestamp (e.g. 2026-01-02T15:04:05Z)`.

- **Attribution:** server (`lego/backend/internal/events`)
- **Root cause:**
  - `lego/backend/internal/events/service.go:1074-1086` (`FilterOf`) silently ignores `time.Parse(time.RFC3339, startTime)` / `endTime` errors (leaving `Since`/`Until` zero so `Service.List` falls back to `DefaultWindow = 1h`), and copies `splitTypes(t)` into `f.Types` without validating any type name.
  - `pushDownOne` (`events/service.go:592-619`) returns an empty `ServiceEventFilter` for any unrecognized type name, so a filter of unknown types silently returns `[]`.
  - REST rejects unknown `type` and malformed `startTime`/`endTime` only because the REST OpenAPI request validator (`internal/api/openapi_validate.go`) checks query params before reaching `events/rest.go:567`. MCP `list_events` (`events/mcp.go:125-132`) added its own `parseListEventsTime` for timestamps only, leaving `eventTypes` unvalidated and leaving `list_service_events` (`events/mcp.go:157`) and GraphQL `serviceEvents` (`events/graphql.go:396-403`) on unvalidated `FilterOf`.
  - `events/mcp.go:56-58` and `events/service.go:1064-1073` carry older comments accepting the permissive fallback, which conflicts with Render parity (`AGENTS.md`) and `core.ParseTime`'s house rule.
- **Fix:**
  - Validate `filter.Types` inside `events.Service.List` (or a shared `ParseFilter` returning `(Filter, error)` used by REST, GraphQL `serviceEvents`, MCP `list_events`, and MCP `list_service_events`) against the closed union of Render's `eventTypeParam` enum plus bex's own documented service event types (every type `pushDownOne` recognizes: `deploy_started`, `deploy_ended`, `auto_deploy_enabled`, `auto_deploy_disabled`, `auto_deploy_changed`, `edge_cache_enabled`, `edge_cache_disabled`, `allFactTypes`, and `eventTypes` values — plus any Render enum value bex does not emit yet so Render clients filtering for valid Render types still receive an honest empty page rather than an error). Reject unknown names with `core.ErrBadRequest` without echoing the raw caller string (so secrets misplaced in `eventTypes`/`type` are never echoed).
  - Replace the silent `time.Parse` ignore in `FilterOf` (`events/service.go:1079-1084`) with `core.ParseTime("startTime", startTime)` and `core.ParseTime("endTime", endTime)` (retiring the stale comments at `events/service.go:1064-1073` and `events/mcp.go:56-58`), so `list_service_events` and GraphQL `serviceEvents` reject malformed timestamps consistently with REST and `list_events`.
  - Also check `limit` bounds consistency (`GET /v1/services/{id}/events?limit=0`, `-5`, `500` return `400 limit must be an integer between 1 and 100` on REST, while MCP `list_events` / `list_service_events` and GraphQL `serviceEvents` silently clamp via `core.PageLimitOrAbsent`): reject explicit negative or `> 100` limits if safe for existing `dashboard/` GraphQL `serviceEvents` callers (check `dashboard/` first so omitted/0 default behavior stays intact).
- **Blast radius:** `lego/backend/internal/events/{service,rest,graphql,mcp}.go` (`FilterOf` has 4 production callers: `rest.go:569`, `graphql.go:402`, `mcp.go:123`, `mcp.go:157`).
