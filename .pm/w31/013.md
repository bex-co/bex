# 013 — MCP `create_key_value` and GraphQL `createKeyValue` ignore non-empty `ipAllowList` / `ipAllowListEntries` when `public` is omitted, leaving `public: false` and `ipAllowList: []` while REST `POST /v1/key-value` enables external access

Why: `createKeyValueArgs.Public` (`lego/backend/internal/keyvalue/mcp.go:71,150-164`) and GraphQL `createKeyValue` (`lego/backend/internal/keyvalue/graphql.go:205,216-229`) still treat omitted `public` as `false` even when the caller supplies a non-empty `ipAllowList` / `ipAllowListEntries`, silently hiding the saved CIDR rules behind `ipAllowList: []` (`public: false`) in direct divergence from REST `POST /v1/key-value`, `update_key_value`, and `create_postgres`.

### MCP `create_key_value` and GraphQL `createKeyValue` silently drop caller-supplied `ipAllowList` / `ipAllowListEntries` behind `public: false` when `public` is omitted

- **Severity:** major
- **Versions:** deployed pin `4b533337ab` (`7b046987bcd8`, active on production during run; `d8d0713b48` / `9cc529d10432` newly pinned with zero diff in `internal/keyvalue/`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`

- **Expected / actual:**
  - **Expected:** Matching Render's Key Value external-access model (`https://render.com/docs/key-value#enabling-external-connections`), bex's own REST `POST /v1/key-value` (`lego/backend/internal/keyvalue/rest.go:365-373`), MCP `update_key_value` (`lego/backend/internal/keyvalue/allowlist_access_test.go:117`), and MCP `create_postgres` (`lego/backend/internal/postgres/mcp.go:92,162`), omitting `public` on `create_key_value` / `createKeyValue` should keep the store private when `ipAllowList` / `ipAllowListEntries` is omitted or empty, and enable external access (`public: true`) when a non-empty allowlist is supplied (while explicit `public: false` still forces private). Under `AGENTS.md` ("Render parity first"), `docs/ADR021-keyvalue-management.md:85,107`'s older private-regardless-of-allowlist exception on MCP/GraphQL has no user sign-off in `docs/ADR018/other-datastores-storage.md` and should be amended just as Postgres was aligned in `w8/157` / `w4/553`.
  - **Actual:**
    - REST `POST /v1/key-value?dryRun=true` with `ipAllowList` and no `public` returns `public: true` and `ipAllowList: [{"cidrBlock":"203.0.113.0/24","description":"office"}]`.
    - MCP `create_key_value` with `ipAllowList: ["203.0.113.0/24"]` (or `ipAllowListEntries`) and no `public` returns `public: false` and `ipAllowList: []`. Worse, `CreateKeyValue` writes the CIDRs into `kv.Spec.IPAllowList` while leaving `kv.Spec.Public = false`, so `kvView` (`core.EffectiveAllowList(false, ...)`) returns `[]` — silently dropping the caller's rules from every readback and leaving external access disabled.
    - GraphQL `createKeyValue` with `ipAllowList: ["203.0.113.0/24"]` and no `public` likewise returns `public: false` and `ipAllowList: []`.
    - Only when the caller passes bex's non-Render `public: true` flag does MCP `create_key_value` return `public: true` and `ipAllowList: [{"cidrBlock":"203.0.113.0/24","description":""}]`.

- **Attribution:** server (`lego/backend/internal/keyvalue`)
- **Root cause:**
  - `lego/backend/internal/keyvalue/rest.go:356-373` decodes `Public *bool` and computes `req.Public = len(req.IPAllowList) > 0` when `public` is omitted (shipped in `ac678aef19`, `w2/m57`).
  - `lego/backend/internal/keyvalue/mcp.go:71,150-164` kept `createKeyValueArgs.Public` as a non-pointer `bool` (zero value `false`), passing `Public: in.Public` directly to `CreateKeyValue`.
  - `lego/backend/internal/keyvalue/graphql.go:205,216-229` similarly reads `Public: gqlutil.Bool(p.Args, "public")`, collapsing omitted `public` to `false`.
  - `lego/backend/internal/keyvalue/service.go:362,715-716` writes `Spec.IPAllowList` alongside `Spec.Public = false`, and `kvView` projects `IPAllowList: core.EffectiveAllowList(kv.Spec.Public, kv.Spec.IPAllowList)` which returns `[]` whenever `Spec.Public` is `false`.
- **Fix:**
  - Add a shared `CreateExposure(public *bool, allowList []core.IPAllowListEntry) bool` helper in `lego/backend/internal/keyvalue/` (mirroring `postgres.CreateExposure`): if `public != nil` return `*public`, else return `len(allowList) > 0`.
  - Call `CreateExposure` from all three adapters:
    - `lego/backend/internal/keyvalue/rest.go:365-373` (replacing the inline `if wire.Public != nil` block);
    - `lego/backend/internal/keyvalue/mcp.go:71,150-164` (change `createKeyValueArgs.Public` from `bool` to `*bool`, update the field descriptions on `Public` and `IPAllowList`);
    - `lego/backend/internal/keyvalue/graphql.go:216-229` (extract `*bool` from `p.Args["public"]` when present and non-nil).
  - Amend `docs/ADR021-keyvalue-management.md:85,107` to record that GraphQL and MCP creates resolve omitted `public` identically to REST (private when `ipAllowList` is omitted/empty, public when non-empty; explicit `public` wins).
  - Check dashboard `createKeyValue` callers (`dashboard/src/features/keyvalue/` or similar) to confirm omitted/empty `ipAllowList` still creates private stores and supplying rules in the create form works cleanly.

No change when `ipAllowList` is omitted or `[]` (still `public: false`), and explicit `public: false` still overrides to private.
