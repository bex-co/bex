# 224 — Pre-authorization input validation in `postgres` and `keyvalue` log endpoints (`MCP get_postgres_logs`, `MCP get_key_value_logs`, `REST GET /v1/{postgres,key-value}/{id}/logs`, and `GQL Query.{databaseLogs,keyValueLogs}`) returns `400 bad_request` instead of `403`/`404`, and `core.QueryLimit64` echoes raw caller input

Why: `bex-api`'s authz-before-validation contract requires authorizing the target resource before validating caller-supplied query parameters so unauthorized or foreign-resource callers receive `403 FORBIDDEN` / `404 NOT_FOUND` (and emit denied audit rows) instead of `400 bad_request`. Across MCP, REST, and GraphQL, all six datastore-log entrypoints (`postgres/mcp.go:241`, `postgres/rest.go:410-417`, `postgres/graphql.go:623`, `keyvalue/mcp.go:217`, `keyvalue/rest.go:403-412`, `keyvalue/graphql.go:168`) parse `startTime`/`endTime` via `core.ParseTimeWindow` (and REST also parses `limit` via `core.QueryLimit64`) before calling `QueryDatabaseLogs` / `QueryKeyValueLogs` — and `core.QueryLimit64` (`lego/backend/internal/core/pagination.go:505-515`) wraps Go's raw `strconv.ParseInt` error verbatim, echoing caller-supplied strings and Go internals.

- **Root cause:**
  - `postgres/mcp.go:241`, `postgres/rest.go:410-417`, `postgres/graphql.go:623`, `keyvalue/mcp.go:217`, `keyvalue/rest.go:403-412`, and `keyvalue/graphql.go:168` all parse `limit` (`core.QueryLimit64`) and `startTime`/`endTime` (`core.ParseTimeWindow`) directly inside the transport adapter before delegating to `s.QueryDatabaseLogs` / `s.QueryKeyValueLogs` (which run resource authorization inside `s.DatabaseLogs` / `s.KeyValueLogs` or `fetchLiveDatabase` / `fetchLiveKeyValue`).

- **Fix:**
  - Carry raw `StartTime`/`EndTime` (and optional raw `LimitRaw` for REST, or parse inside the service after authorization) on `datastorelogs.Query` (or pass a `QueryRequest` to `QueryDatabaseLogs` / `QueryKeyValueLogs`), authorizing the target database / Key Value store (`RelCanViewLogs`) **first** — both in `datastoreLogsAdapter` (`logs.Service.QueryLogs`) and in the direct `fetchLiveDatabase`/`fetchLiveKeyValue` fallback — before calling `core.ParseTimeWindow` and validating `limit` / `direction`.
  - Update `core.QueryLimit64` (`lego/backend/internal/core/pagination.go:505-515`) to return a fixed message without echoing the caller's raw value (`fmt.Errorf("%w: %s must be an integer", ErrBadRequest, key)`), checking any tests that assert the old `strconv.ParseInt` wording.
