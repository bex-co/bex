# 221 — Scoped `workspaces: read` API keys bypass `core.KeyNoGrant` on API keys and SSH keys via GraphQL `workspaceLoginRequirementImpact`

Why: `lego/backend/internal/api/key_permission_ops.go:44-46` reserves all API key and SSH key operations to `core.KeyNoGrant` (no catalog permission covers API keys or SSH keys, so only an All-permissions key or human session may read them — enforced on `MCP list_api_keys`, `MCP list_ssh_keys`, `REST GET /v1/api-keys`, `REST GET /v1/ssh-keys`, `GQL Query.apiKeys`, `GQL Query.sshKeys`, and `GQL Query.organizationLoginRequirementImpact`). However, `GQL Query.workspaceLoginRequirementImpact` (`key_permission_ops.go:504`) is mapped to `{core.KeyWorkspaceSettings}` (`workspaces: read`, Viewer-level), allowing any Admin-minted scoped API key holding only `workspaces: read` to enumerate every workspace-bound API key (`id`, `name`, creator attribution, `unattributedApiKeys`) and every workspace member's personal SSH keys (`id`, `name`, SHA256 `fingerprint`).

- **Expected / actual:**
  - **Expected:** `GQL Query.workspaceLoginRequirementImpact` is mapped to `{core.KeyNoGrant}` alongside `apiKeys`, `sshKeys`, and `organizationLoginRequirementImpact`, refusing any scoped API key with `api_key_permission_denied` (`required: ["-"]`) so a scoped `workspaces: read` key cannot enumerate workspace API keys or other members' personal SSH keys.
  - **Actual:** All seven controls (`MCP list_api_keys`, `MCP list_ssh_keys`, `REST GET /v1/api-keys`, `REST GET /v1/ssh-keys`, `GQL Query.apiKeys`, `GQL Query.sshKeys`, `GQL Query.organizationLoginRequirementImpact`) refused the scoped key with `api_key_permission_denied` (`required: ["-"]`), whereas `GQL Query.workspaceLoginRequirementImpact` returned HTTP `200 OK` with all workspace-bound API keys (IDs, names, and creator attribution) and the workspace member's personal SSH key (ID, name, and SHA256 fingerprint).

- **Attribution:** server (`lego/backend/internal/api`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:504` maps `"GQL Query.workspaceLoginRequirementImpact"` to `{core.KeyWorkspaceSettings}` (granted by `workspaces: read`, a Viewer-level permission in `lego/backend/internal/core/keygrant.go:363-365`) instead of `{core.KeyNoGrant}`.
  - `lego/backend/internal/workspaces/login_requirement_impact.go:123-155,252-343` (`LoginRequirementImpact` → `assessLoginImpact`) calls `s.LoginImpactKeys.BoundAPIKeys` (`:253`) and `s.LoginImpactKeys.SSHKeysOf` (`:257`) to return every workspace API key and every member's personal SSH keys — the exact credential inventories `key_permission_ops.go:44-46` and lines `:348,431,481,664,708,879,1022` reserve to `core.KeyNoGrant`.
- **Fix:**
  - Change `"GQL Query.workspaceLoginRequirementImpact"` in `lego/backend/internal/api/key_permission_ops.go:504` from `{core.KeyWorkspaceSettings}` to `{core.KeyNoGrant}`.
