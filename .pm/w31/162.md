# 162 — All 19 by-session-ID verbs in `agentsessions` ignore `core.WorkspaceFrom(ctx)` (`workspaceId`), bypassing ADR072 workspace scoping for multi-workspace callers across MCP, REST, and GraphQL

Why: Unlike every other sub-feature in the same package (`agentsessions/attachments.go:267-295`, `automations.go:561-595`, `skills.go:298-333`, `repo_environment_builds.go:217`) and every other feature in `bex` (`core/base.go:918-928`, ADR072's by-id matrix), none of the 19 by-session-ID verbs in `lego/backend/internal/agentsessions/` ever inspects `core.WorkspaceFrom(ctx)` against `record.WorkspaceID`. Every session verb authorizes solely via `s.AuthorizeOn(ctx, relation, sessionObject(sessionID))` and fetches by raw `sessionID` without a workspace check — so a multi-workspace caller (such as an OAuth-authenticated MCP user or browser session belonging to both workspace A and workspace B) who explicitly binds an MCP call to `workspaceId: <workspace-A>` can read, wait on, steer, archive, cancel, or permanently delete a session belonging to `<workspace-B>` instead of receiving `NOT_FOUND` (`ErrNotInNamedWorkspace`).

### By-session-ID `agentsessions` tools ignore explicit `workspaceId` binding across `/mcp`, `/mcp/cloud-agents`, REST, and GraphQL

- **Severity:** major
- **Versions:** deployed pin `a6f9307d74` (`486e3f4afbf6`) and `origin/main` `c2663d1095` (zero diff in `lego/backend/internal/agentsessions/`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-27, endpoints `/mcp`, `/mcp/cloud-agents`, REST `/v1/agent-sessions/{id}...`, and `/graphql`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`)
- **Repro:**
  ```sh
  # Given a human OAuth/session caller who is a member of two workspaces (tea-A and tea-B),
  # and an agent session <ags-in-B> owned by tea-B:
  #
  # 1. MCP call explicitly scoped to workspaceId = tea-A reads/mutates tea-B's session:
  #    POST https://api.bex.co/mcp/cloud-agents (or /mcp) with OAuth/session auth:
  #    {"jsonrpc":"2.0","id":1,"method":"tools/call","params":{
  #      "name":"get_agent_session",
  #      "arguments":{"workspaceId":"<tea-A>","id":"<ags-in-B>"}
  #    }}
  #    (Same for wait_agent_sessions, get_agent_session_transcript, get_agent_session_tree,
  #     get_agent_session_model_cost, get_agent_session_tool_output, list_agent_session_attachments,
  #     list_agent_session_queued_messages, send_agent_session_message, steer_agent_session,
  #     set_agent_session_tags, update_agent_session, archive_agent_session, unarchive_agent_session,
  #     cancel_agent_session, resume_agent_session, attach_agent_session, interrupt_agent_session,
  #     edit/delete/move_agent_session_queued_message, and delete_agent_session.)
  #
  # 2. Control: calling get_service, get_agent_skill, get_agent_automation, or get_agent_attachment
  #    with workspaceId = tea-A and an ID belonging to tea-B returns NOT_FOUND (ErrNotInNamedWorkspace).
  ```
- **Expected / actual:**
  - **Expected:** Per ADR072's by-id workspace-scoping matrix (`lego/backend/internal/core/base.go:918-928`, `core/byid.go`, and `agentsessions`'s own `scopeAttachment`/`scopeAutomation`/`scopeSkill` helpers), when `core.WorkspaceFrom(ctx)` is explicitly set (as `mcpBindCallWorkspace` sets on every MCP tool call carrying `workspaceId`), any by-session-ID verb whose session belongs to a different workspace (`record.WorkspaceID != named`) must refuse with `AGENT_SESSION_NOT_FOUND` / `core.ErrNotInNamedWorkspace` (after confirming the caller is authorized in the named workspace) and must never read, steer, cancel, or delete another workspace's session.
  - **Actual:**
    - `mcpBindCallWorkspace` (`lego/backend/internal/api/mcp_workspace.go:115-119`) binds `ctx = core.WithWorkspace(ctx, workspaceID)`.
    - Every by-session-ID verb in `agentsessions` calls `s.AuthorizeOn(ctx, relation, sessionObject(sessionID))` (`core/base.go:908-910`), which checks OpenFGA on `agent_session:<sessionID>` without consulting `core.WorkspaceFrom(ctx)`, and then loads or mutates the row by raw `sessionID` without checking `record.WorkspaceID == named`.
    - For a multi-workspace OAuth/session caller, every read and destructive write succeeds against `<tea-B>`'s session despite the caller explicitly targeting `workspaceId: <tea-A>`.
- **Wire evidence:**
  - Verified live on `bex-canary` (`tea-daif693dqjvc73e7as3g`) that `mcp_workspace.go` injects `workspaceId` onto all session tools in `tools/list` on both `/mcp` and `/mcp/cloud-agents`, and that the QA user belongs to multiple first-party workspaces (`tea-d98210cbbpdc73dcrkvg`, `tea-da2isimlm39c739m4ofg`, `tea-daif693dqjvc73e7as3g`). None of those workspaces held a pre-existing finished agent session during the hunt (verified via read-only `list_agent_sessions` with `archived: "all"`, `rndr-id: dd779d9f-baaa-ff9e` → `{"agentSessions":[]}`), so cross-workspace session execution was proved directly from source across all 19 call sites.
- **Attribution:** server (`lego/backend/internal/agentsessions`)
- **Root cause:**
  - Every by-session-ID entry point in `lego/backend/internal/agentsessions/` calls `s.AuthorizeOn(ctx, ..., sessionObject(sessionID))` and queries Postgres by `sessionID` alone with zero `core.WorkspaceFrom(ctx)` check:

- **Fix:**
  - Add a shared helper on `agentsessions.Service` (e.g. `checkNamedSessionWorkspace(ctx context.Context, sessionID, workspaceID string) error`) called by `operableRecord` and every sibling by-session-ID verb (`setArchived`, `ReplaceTags`, `Delete`, `Transcript`, `ToolOutput`, `Steer`, `waitSnapshot`, `Tree`, `ModelCost`, `ListAttachments` — or unify all of them through one `loadAuthorizedSession` helper):
    - When `named, explicit := core.WorkspaceFrom(ctx); explicit && record.WorkspaceID != named`, return `sessionNotFound(sessionID)` (wrapped with `core.ErrNotInNamedWorkspace`, after verifying the caller is a member of `named` — or via `s.AuthorizeOnOwner`-equivalent semantics so a non-member of `named` gets `FORBIDDEN`, never an existence oracle, and a member of both `named` and `record.WorkspaceID` gets `AGENT_SESSION_NOT_FOUND`).
    - For `setArchived`, `ReplaceTags`, `Transcript`, `ToolOutput`, `ModelCost`, and `ListAttachments` (which currently skip loading the session row on the fast path), either load/verify `record.WorkspaceID` when `explicit` is true or pass `named` into the store query / `GetAgentSession` check before mutating or returning data.
- **Blast radius:** `lego/backend/internal/agentsessions/{service,wait,lineage,modelcost,attachments,queue}.go` and unit tests.
