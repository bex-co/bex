# 205 — `postgres.Service.DatabaseExtensions` runs untagged introspection SQL (polluting `pg_stat_statements` / `list_postgres_top_queries`) and omits uncached `AuthorizeDatabaseFresh`

Why: `lego/backend/internal/postgres/upgrade_run.go:238,251` runs `installedExtensionsSQL` (`SELECT extname FROM pg_catalog.pg_extension ORDER BY extname`) untagged via `s.sqlExecutor()` instead of tagging it with `tagInsight` (`/* bex:insights */`, `insights.go:366,383-386`) and registering it in `insightStatements` (`insights.go:509`), so every call to `GQL Query.databaseExtensions` (loaded on the dashboard's `/version-upgrade` page) or `checkUpgradeExtensions` pollutes the customer's `pg_stat_statements` (`MCP list_postgres_top_queries`, `REST GET /v1/postgres/{id}/top-queries`, `GQL Query.databaseTopQueries`) and `pg_stat_activity` with bex's own platform SQL. In addition, `DatabaseExtensions` (`upgrade_run.go:270`) calls `s.fetchLiveDatabase` instead of `s.insightDatabase` (`insights.go:583-592`), skipping `AuthorizeDatabaseFresh` (`codex round-15 #4`) before reading the tenant database's connection Secret and dialing it.

- **Attribution:** server (`lego/backend/internal/postgres`)
- **Root cause:**
  - `lego/backend/internal/postgres/upgrade_run.go:238` defines `const installedExtensionsSQL = "SELECT extname FROM pg_catalog.pg_extension ORDER BY extname"`, and `installedExtensions` (`:251`) executes it raw (`s.sqlExecutor()(ctx, uri, installedExtensionsSQL, consoleQueryLimits, true)`) instead of `tagInsight(installedExtensionsSQL)` (`insights.go:383-386`).
  - `lego/backend/internal/postgres/insights.go:509` (`insightStatements`) omits `installedExtensionsSQL`, so even once future calls are tagged, existing databases whose `pg_stat_statements` already recorded the untagged text for that `queryid` will continue to display it until `insightQueryIDSQL` (`:530-555`) excludes its `queryid` via `NOT IN`.
  - `lego/backend/internal/postgres/upgrade_run.go:270` (`DatabaseExtensions`) calls `s.fetchLiveDatabase(ctx, core.RelCanView, name)` instead of `s.insightDatabase(ctx, core.RelCanView, name)` (`insights.go:583-592`), omitting `s.AuthorizeDatabaseFresh(ctx, core.RelCanView, db)`.
- **Fix:**
  - In `lego/backend/internal/postgres/upgrade_run.go:251`, pass `tagInsight(installedExtensionsSQL)` to `s.sqlExecutor()` (or route through `s.runAuthorizedInsight`), so both `DatabaseExtensions` and `checkUpgradeExtensions` tag the query with `/* bex:insights */`.
  - In `lego/backend/internal/postgres/insights.go:509`, append `installedExtensionsSQL` to `insightStatements` so `insightQueryIDSQL` also filters out pre-existing untagged `pg_stat_statements` rows for the same `queryid` on databases that already ran `databaseExtensions` before this fix.
  - In `lego/backend/internal/postgres/upgrade_run.go:270`, switch `DatabaseExtensions` from `s.fetchLiveDatabase(ctx, core.RelCanView, name)` to `s.insightDatabase(ctx, core.RelCanView, name)` so uncached `AuthorizeDatabaseFresh` runs before loading the connection Secret and dialing the database.
