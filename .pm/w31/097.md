# 097 — `agentsessions.Service.UpdateAgentAutomation` unconditionally bumps `version` and `updatedAt` on empty (`{}`) and no-op updates, breaking `ifVersion` optimistic concurrency across MCP, REST, and GraphQL

Why: `agentsessions.Service.UpdateAgentAutomation` (`lego/backend/internal/agentsessions/automations.go:381-444`) never checks whether any field was supplied or whether the post-patch row differs from the stored row, unconditionally running `s.Automations.UpdateAgentAutomation(ctx, row, version)` (`lego/backend/internal/store/agentautomations.go:273-302`, `SET ..., version=version+1, updated_at=now()`) — so empty `{}` or identical-value updates bump `version` and advance `updatedAt`, causing concurrent callers holding the previous `ifVersion` to fail with `409 AGENT_AUTOMATION_CONFLICT` even though nothing changed.

- **Root cause:**
  - `agentsessions.Service.UpdateAgentAutomation` (`lego/backend/internal/agentsessions/automations.go:381-444`) applies each optional field pointer from `AgentAutomationInput` onto a copy of `row`, never checks whether all input fields were nil or whether the post-patch `row` equals the stored `row` (name, enabled, notifyEmail, overlapPolicy, normalized triggers JSON, normalized template JSON), and unconditionally calls `s.Automations.UpdateAgentAutomation(ctx, row, version)` at `:442`.
  - `store.PGStore.UpdateAgentAutomation` (`lego/backend/internal/store/agentautomations.go:278-286`) unconditionally executes `UPDATE agent_automations SET ..., version=version+1, updated_at=now() WHERE id=$1 AND version=$2 AND workspace_id=$9`.
  - MCP (`automations_mcp.go:76`), REST (`automations_rest.go`), and GraphQL `updateAgentAutomation` (`automations_graphql.go:400-412`) all delegate directly to `s.UpdateAgentAutomation`.
- **Fix:**
  - In `agentsessions.Service.UpdateAgentAutomation` (`lego/backend/internal/agentsessions/automations.go:381-444`), validate any supplied fields and check `ifVersion` against `row.Version` (returning `AGENT_AUTOMATION_CONFLICT` on mismatch even for a no-op), then compare the post-patch `row` (`Name`, `Enabled`, `NotifyEmail`, `OverlapPolicy`, `Triggers`, `Template`, `NextFireAt`) against the stored `row`. When nothing changed, return `automationView(row)` without calling `s.Automations.UpdateAgentAutomation` (and keep deferred write audit clean if nothing was written).
