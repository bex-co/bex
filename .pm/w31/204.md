# 204 — Pre-authorization input validation in `POST /v1/services/{id}/custom-domains`, `POST /v1/blueprints/deploy`, `POST /v1/postgres/{id}/recovery`, and GraphQL `Mutation.{createService,createBlueprint,createSandbox}` returns `400 bad_request` instead of `403`/`404`

Why: `bex-api`'s authz-before-validation contract requires workspace/resource authorization to run before caller-supplied write fields are validated so unauthorized callers (foreign workspaces, unprivileged roles, or nonexistent targets) receive `403 FORBIDDEN` / `404 NOT_FOUND` (and record denied audit rows) rather than `400 bad_request`. Three REST write routes (`apps/rest.go:1425`, `apps/rest.go:1793`, `postgres/rest.go:314`) and three GraphQL create mutations (`apps/graphql.go:1666,2188`, `sandbox/graphql.go:282`) validate request fields in their adapter layer before invoking their authorized service verbs — diverging from sibling MCP tools (for example, `MCP add_custom_domain` returns `NOT_FOUND` on `name: ""` where `REST POST /v1/services/{id}/custom-domains` returns `400`).

- **Attribution:** server (`lego/backend/internal/apps`, `lego/backend/internal/postgres`, `lego/backend/internal/sandbox`)
- **Root cause:**
  - `lego/backend/internal/apps/rest.go:1425-1427` (`POST /v1/services/{id}/custom-domains`): checks `if req.Name == ""` before calling `s.addDomainPair(r.Context(), r.PathValue("id"), req.Name)` (which authorizes the App first and then validates the domain name).
  - `lego/backend/internal/apps/rest.go:1793-1795` (`POST /v1/blueprints/deploy`): checks `if strings.TrimSpace(body.BexYAML) == ""` before calling `s.DeployStack` (which authorizes `RelCanCreate` on `body.OwnerID`).
  - `lego/backend/internal/postgres/rest.go:314-319` (`POST /v1/postgres/{id}/recovery`): rejects non-nil `datadogApiKey` / `datadogSite` before calling `s.Recover(r.Context(), r.PathValue("id"), ...)`.
  - `lego/backend/internal/apps/graphql.go:1666` (`Mutation.createService`): calls `gqlCreateRequest(p.Args)` (`:784-809`, validating `envVars`, `ipAllowList`/`ipAllowListEntries` conflicts, `autoDeploy`/`autoDeployTrigger` conflicts, and `replicas`) before `s.Create(p.Context, req)` authorizes `req.OwnerID`.
  - `lego/backend/internal/apps/graphql.go:2188` (`Mutation.createBlueprint`): calls `blueprintEnvVarValues(p.Args["envVarValues"])` (`:178-200`, rejecting empty or duplicate keys) before `s.CreateBlueprint(p.Context, ownerId, ...)` authorizes the workspace.
  - `lego/backend/internal/sandbox/graphql.go:282` (`Mutation.createSandbox`): calls `envFromArgs(p.Args["env"])` (`:152-174`, rejecting `generateValue: true` or duplicate keys) before `s.Create` authorizes the workspace.
- **Fix:**
  - `apps/rest.go:1425-1428`: remove the pre-authz `if req.Name == ""` check so `s.addDomainPair` authorizes the App first and then rejects blank domain names (matching `MCP add_custom_domain` and `GQL Mutation.addCustomDomain`).
  - `apps/rest.go:1793-1798`: move the blank `BexYAML` check inside `s.DeployStack` after `s.Authorize(core.WithDeferredAllowedWriteAudit(ctx), core.RelCanCreate)` (coordinating with `w31/120` so a `400` writes no `"success"` audit row).
  - `postgres/rest.go:314-325`: carry unsupported recovery-field refusal (or authorize the target database via `s.AuthorizeDatabase` with `WithDeferredAllowedWriteAudit`) after authorization inside `s.Recover` (coordinating with `w31/128`).
  - `apps/graphql.go:1665-1675`, `apps/graphql.go:2187-2202`, and `sandbox/graphql.go:281-290`: authorize the named `ownerId` workspace (`RelCanCreate` with `core.WithDeferredAllowedWriteAudit`) — or pass raw inputs into `Create` / `CreateBlueprint` / `sandbox.Create` so validation runs post-authorization — ensuring unauthorized workspaces/roles always receive `403 FORBIDDEN` (with a denied audit row) before input-validation errors.
  - Surface impact: aligns REST and GraphQL create/recovery handlers with MCP and the repo-wide authz-before-validation contract; authorized valid requests behave identically.
