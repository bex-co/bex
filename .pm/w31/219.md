# 219 — Blueprint planner (`PlanBlueprintResource`, `planBlueprintBuildSource`, and `envgroups.GroupWritesOwed`) is a secret-value guessing oracle across MCP `validate_bex_yml`, REST `POST /v1/blueprints/validate`, and GraphQL `validateBlueprint`, bypassing `RelCanViewSensitive`, scoped API key env permissions, and protected-environment Admin enforcement

Why: `PlanBlueprintResource` (`lego/backend/internal/apps/blueprint_state_plan.go:382-408`) and `planBlueprintBuildSource` (`lego/backend/internal/apps/blueprint_build_sources.go:458-471`) diff caller-supplied `envVars` literals directly against existing `App.Spec.Env` values via `ApplyBlueprintServiceSpec` without checking `core.RelCanViewSensitive`, `core.KeyServiceEnv`/`core.KeyBuildSourcesEnv`, or protected-environment Admin role (`core.RelCanManage`), and `envgroups.GroupWritesOwed` (`lego/backend/internal/envgroups/service.go:1803-1836`) checks `RelCanViewSensitive` and `KeyEnvGroupsValues` yet omits the protected-environment Admin check (`core.EnvironmentProtected` + `core.RelCanManage`). Because `ValidateBlueprint` (`apps/blueprint.go:738-744`) requires only `RelCanView`, `OpClassRead` (`scope_matrix_overrides.go:38-39`), and `KeyBlueprintsView`, a Viewer, a `bex.read` OAuth token, a `blueprints: read`-only API key (refused `list_env_vars` with `403 api_key_permission_denied`), or a non-Admin Developer on a protected service/environment group can probe exact plaintext secret values via `operation: "update"` (wrong guess) vs `operation: "noop"` (exact match) across MCP, REST, and GraphQL.

- **Expected vs actual:**
  - **Expected:** Matching `envgroups.GroupWritesOwed`'s own documented security invariant (`lego/backend/internal/envgroups/service.go:1796-1801` and `lego/backend/internal/apps/blueprint_state_plan.go:605-608`, `w8/376`: *"Whether a declared value matches the stored one is itself a fact about the value, so a caller who may not read the group's values … is refused with `core.ErrForbidden`, from a probe that records nothing; the plan then cannot tell, rather than learning whether a guess matched"*), any Blueprint validate/plan/preview diffing `envVars` against an existing service, build source, or environment group must check whether the caller is authorized to read that resource's secret values — including `core.RelCanViewSensitive`, the corresponding scoped API key permission (`core.KeyServiceEnv` / `core.KeyBuildSourcesEnv` / `core.KeyEnvGroupsValues`), and (in a protected environment) workspace Admin (`core.RelCanManage`). Whenever the caller cannot read the values, the planner must NOT compare against stored values and must deterministically report `operation: "update"` with `changedFields: [{"path": "envVars"}]` and an unread-values message (matching `envGroupValuesUnread`), giving byte-identical output for matching and non-matching guesses.

- **Attribution:** server (`lego/backend/internal/apps` and `lego/backend/internal/envgroups`)
- **Root cause:**
  - **Services (`lego/backend/internal/apps/blueprint_state_plan.go:382-408`):** `PlanBlueprintResource` (`BlueprintResourceService`) reads `served := r.services[resource.Name].Spec` (which holds plaintext `spec.Env` literals) and runs `ApplyBlueprintServiceSpec(&probe, want, svc.fields)` and `probeBlueprintServiceSpec` (`blueprint_plan.go:343-345`) with zero check for `core.RelCanViewSensitive`, `core.KeyServiceEnv`, or protected-environment Admin (`core.EnvironmentProtected` + `core.RelCanManage`). Because `ValidateBlueprint` (`apps/blueprint.go:738-744`) authorizes only `core.RelCanView`, is `OpClassRead` (`scope_matrix_overrides.go:38-39`), and maps solely to `KeyBlueprintsView` (`key_permission_ops.go`), any Viewer, `bex.read` OAuth token, `blueprints: read`-only key, or non-Admin Developer on a protected service can test arbitrary candidate values for any `spec.Env` key.
  - **Build sources (`lego/backend/internal/apps/blueprint_build_sources.go:458-471`):** `planBlueprintBuildSource` runs the identical `ApplyBlueprintServiceSpec(&probe, want, b.svc.fields)` / `probeBlueprintServiceSpec` pass over `current.Spec.Env` on existing build source carriers without checking `core.RelCanViewSensitive` or `core.KeyBuildSourcesEnv`.
  - **Protected environment groups (`lego/backend/internal/envgroups/service.go:1803-1836`):** `GroupWritesOwed` checks `RelCanViewSensitive` (`:1816`) and `KeyEnvGroupsValues` (`:1819`), yet omits the protected-environment Admin check added in `w4/m594` (compare `envgroups/protection.go:52-60` `valuesWithheld`). A non-Admin Developer (who holds `RelCanViewSensitive` in the workspace, while being refused `GetEnvGroupVar` and having `envVars` withheld on `GET /v1/env-groups/{id}`) passes lines `:1816-1823`, runs `blueprintVarWrites` against `envPath(g.ID)`, and distinguishes matching from non-matching guesses via `planEnvGroupVars` (`blueprint_state_plan.go:609-634`).
- **Fix:**
  - In `envgroups.GroupWritesOwed` (`lego/backend/internal/envgroups/service.go:1803-1836`): after verifying `RelCanViewSensitive` and `KeyEnvGroupsValues`, also check whether `g.EnvironmentID` is protected (`core.EnvironmentProtected(ctx, s.Protection, g.EnvironmentID)`); if protected (or the lookup fails) and `s.CanDecisionOn(ctx, core.RelCanManage, core.WorkspaceObject(g.TenantID)).Outcome != core.DecisionAllowed`, return `false, core.ErrForbidden` so `planEnvGroupVars` falls back to `owed = true` + `envGroupValuesUnread` without reading stored values.
  - In `apps` (`lego/backend/internal/apps/blueprint_state_plan.go:382-418` and `lego/backend/internal/apps/blueprint_build_sources.go:458-480`): add a read-only, zero-audit capability probe (matching `GroupWritesOwed`'s probe pattern):
    - For services: caller may compare `envVars` values only if `s.CanDecisionOn(ctx, core.RelCanViewSensitive, workspace)` is allowed, `s.KeyGrantAllows(ctx, core.KeyServiceEnv)` is true, and — if `current.Labels[core.LabelEnvironment]` is protected (fail-closed on lookup error) — `s.CanDecisionOn(ctx, core.RelCanManage, workspace)` is allowed.
    - For build sources: caller may compare `envVars` values only if `s.CanDecisionOn(ctx, core.RelCanViewSensitive, workspace)` is allowed and `s.KeyGrantAllows(ctx, core.KeyBuildSourcesEnv)` is true.
    - When `envVars` is declared in `fields` and the caller cannot read those values, exclude `"envVars"` from the `ApplyBlueprintServiceSpec` / `probeBlueprintServiceSpec` comparison (so stored `Spec.Env` never affects `changed` or `rolls` for secret values) and unconditionally mark `addChangedFields(&action, "envVars")` with an unread-values message analogous to `envGroupValuesUnread` (e.g., `"This plan cannot read the service's environment variable values, so envVars is listed as changed; a sync writes only those that differ."`).
  - Surface impact: closes the secret-value oracle uniformly across MCP (`validate_bex_yml`, `plan_blueprint`, `preview_blueprint`, `update_blueprint`), REST (`POST /v1/blueprints/validate`, `POST /v1/blueprints/preview`, `POST /v1/blueprints/{id}/syncs`), and GraphQL (`validateBlueprint`, `blueprintPreview`, `planBlueprintSync`).
