# 090 — `apps.isCrossTenantCookieValue` (and dashboard `setCookieHasDomain`) miss whitespace before `=` in `Set-Cookie` `Domain` attributes, allowing static sites to persist and serve `Domain` cookies across MCP, REST, and GraphQL

Why: `apps.isCrossTenantCookieValue` (`lego/backend/internal/apps/service.go:6871-6880`) and its dashboard mirror `setCookieHasDomain` (`dashboard/src/features/services/lib/static-rule-validation.ts:206-211`) check `strings.HasPrefix(strings.ToLower(attr), "domain=")` without trimming whitespace between the attribute name and `=`, whereas RFC 6265 §5.2 (browsers and Go's `net/http.ParseSetCookie`) trims whitespace on both sides of `=` — allowing `Set-Cookie: qa=1; Domain = onbex.co` (or `Domain\t= onbex.co`) to pass validation across MCP, REST, and GraphQL and be emitted verbatim by `staticserver.applyHeaders`.

### Static-site `Set-Cookie` validation misses `Domain` attributes containing spaces or tabs before `=`

- **Severity:** major
- **Versions:** deployed pin `ec6211f2ca` (`11695fb886cb`, active on production during run; zero diff in `lego/backend/internal/apps/service.go`, `lego/operator/internal/staticserver/staticserver.go`, and `dashboard/src/features/services/lib/static-rule-validation.ts` vs `origin/main` `33f407ff55`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`

- **Expected / actual:**
  - **Expected:** `validateHeaders` (`lego/backend/internal/apps/service.go:6859-6880`) enforces that static sites on shared hosting cannot set a `Set-Cookie` header carrying a `Domain` attribute. Because RFC 6265 §5.2 Step 5 splits each cookie attribute on the first `=` and strips leading and trailing `SP`/`HTAB` from both attribute name and attribute value, `Domain = onbex.co` and `Domain\t= onbex.co` are equivalent to `Domain=onbex.co` and must be rejected with `400 bad request` on every write surface (MCP, REST, GraphQL, Blueprint, and dashboard client-side validation).
  - **Actual:**
    - Control `Domain=onbex.co` was refused with `bad request: headers[0].value Set-Cookie with Domain attribute is not allowed on shared hosting (cross-tenant cookie injection)`.
    - `Domain = onbex.co` succeeded `200 OK` on MCP `update_static_headers` and GraphQL `setStaticHeaders`, and `Domain\t= onbex.co` succeeded `200 OK` on REST `PUT /v1/services/{id}/headers`.
    - Live `GET https://qa-20261126-r4k9m2-static.onbex.co/ADR008-vision.md` returned `HTTP/2 200` with `set-cookie: qa=1; Domain = onbex.co`.
- **Wire evidence:**

  - MCP `POST /mcp` `update_static_headers` (`Domain = onbex.co`, `rndr-id: f62a7641-0813-884a`) → `200 OK`, `{"headers":[{"name":"Set-Cookie","path":"/*","value":"qa=1; Domain = onbex.co"}]}`.

- **Attribution:** server (`lego/backend/internal/apps/service.go`, with dashboard mirror in `dashboard/src/features/services/lib/static-rule-validation.ts` and operator emit path in `lego/operator/internal/staticserver/staticserver.go`)
- **Root cause:**
  - `lego/backend/internal/apps/service.go:6871-6880` (`isCrossTenantCookieValue`) splits the value on `;`, trims surrounding whitespace on each segment, and checks `strings.HasPrefix(strings.ToLower(attr), "domain=")`. Any space or tab (`0x20` or `0x09`, both allowed by `httpguts.ValidHeaderFieldValue`) between `Domain` and `=` fails the literal `"domain="` prefix check while remaining a valid RFC 6265 §5.2 `Domain` attribute.
  - `dashboard/src/features/services/lib/static-rule-validation.ts:206-211` (`setCookieHasDomain`) has the identical `.trim().toLowerCase().startsWith("domain=")` check.
  - `lego/operator/internal/staticserver/staticserver.go:1114-1132` (`applyHeaders`) filters only `appv1alpha1.ReservedStaticHeader(rule.Name)` and emits any stored `Set-Cookie` rule verbatim.
- **Fix:**
  - Update `isCrossTenantCookieValue` (`lego/backend/internal/apps/service.go:6871-6880`) to split each attribute segment on the first `=` (`name, _, hasEq := strings.Cut(p, "=")`), trim whitespace around `name` (`strings.TrimSpace(name)`), and return `true` whenever `hasEq && strings.EqualFold(strings.TrimSpace(name), "domain")` (and consider also checking `http.ParseSetCookie(value)` for `c.Domain != ""` as defense in depth).
  - Mirror the same attribute-name split + trim in `setCookieHasDomain` (`dashboard/src/features/services/lib/static-rule-validation.ts:206-211`):
    ```ts
    const eq = attr.indexOf("=");
    return eq !== -1 && attr.slice(0, eq).trim().toLowerCase() === "domain";
    ```
  - Optional defense in depth in `lego/operator/internal/staticserver/staticserver.go:1114-1132` (or shared helper in `lego/types/v1alpha1/static_headers.go`) so already-persisted or direct-CR static sites also never emit a `Set-Cookie` with a `Domain` attribute on shared hosts.
  - Surface impact: fixes MCP `update_static_headers` / `create_static_site`, REST `PUT`/`POST /v1/services/{id}/headers` & `POST /v1/services`, GraphQL `setStaticHeaders` & `createService`, Blueprint deploy, and dashboard inline validation.
