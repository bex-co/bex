# 157 — `store.pageKeyset`, `store.ListAgentAutomations`, and `store.ListBlueprintSyncs` run unscoped `WHERE id = $N` cursor subqueries, creating a cross-workspace existence and timestamp ordering oracle across 7 paginated list endpoints (MCP, REST, GraphQL)

Why: `store.pageKeyset` (`lego/backend/internal/store/store.go:3746-3760`) resolves a caller-supplied pagination `cursor` via `AND (<sortCol>, id) < (SELECT <sortCol>, id FROM <table> WHERE id = $N)` without scoping the subquery to the caller's workspace or parent resource, `store.ListAgentAutomations` (`lego/backend/internal/store/agentautomations.go:246`) repeats the same unscoped subquery (`WHERE id=$3` without `AND workspace_id=$1`), and `store.PGStore.ListBlueprintSyncs` (`lego/backend/internal/store/blueprints.go:389-397`) repeats it a third time (`SELECT started_at, id FROM blueprint_syncs WHERE id = $2` without `AND blueprint_id = $1 AND state <> 'created'`). In direct contrast to `store.ListAgentSessions` (`lego/backend/internal/store/agentsessions.go:996-1000`, which explicitly scopes its subquery with `AND workspace_id = $1` so a foreign cursor is "never an ordering oracle"), any caller with read access to one resource can pass another resource's or another workspace's ID as `cursor` to probe whether that foreign ID exists and bracket its timestamp across 7 paginated list surfaces (`list_deploys`, `list_jobs`, `auditLogs`, `list_sandbox_executions`, `list_agent_session_attachments`, `list_agent_automations`, and `list_blueprint_syncs`).

- **Attribution:** server (`lego/backend/internal/store`)
- **Root cause:**
  - `lego/backend/internal/store/store.go:3746-3760` (`pageKeyset`) emits:
    ```sql
    AND (<sortCol>, id) < (SELECT <sortCol>, id FROM <table> WHERE id = $N)
    ```
    with no parent/workspace scope predicate in the subquery. Five list queries call it:
    1. `PGStore.ListDeploys` (`lego/backend/internal/store/store.go:3812`, `deploys`, scoped by `app_id = $1`) → MCP `list_deploys` (shared Render tool), REST `GET /v1/services/{id}/deploys`, GraphQL `deploys`.
    2. `PGStore.ListJobs` (`lego/backend/internal/store/jobs.go:110`, `jobs`, scoped by `app_id = $1`) → MCP `list_jobs`, REST `GET /v1/services/{id}/jobs`, GraphQL `jobs`.
    3. `PGStore.ListAuditEvents` (`lego/backend/internal/store/audit.go:275`, `audit_events`, scoped by `workspace_id = $1`) → REST `GET /v1/owners/{ownerId}/audit-logs`, GraphQL `auditLogs`.
    4. `PGStore.SandboxExecutions` (`lego/backend/internal/store/sandbox_executions.go:140-141`, `sandbox_executions`, scoped by `workspace_id = $1 AND sandbox_id = $2`) → MCP `list_sandbox_executions`, REST `GET /v1/sandboxes/{id}/executions`, GraphQL `sandboxExecutions`.
    5. `PGStore.ListAgentSessionAttachments` (`lego/backend/internal/store/agentattachments.go:211`, `agent_session_attachments`, scoped by `workspace_id = $1 AND session_id = $2`) → MCP `list_agent_session_attachments` (`/mcp` and `/mcp/cloud-agents`), REST `GET /v1/agent-sessions/{id}/attachments`, GraphQL `agentSessionAttachments`.
  - Independently, `PGStore.ListAgentAutomations` (`lego/backend/internal/store/agentautomations.go:246`) writes:
    ```sql
    AND ($3 = '' OR (created_at, id) < (SELECT created_at, id FROM agent_automations WHERE id=$3))
    ```
    omitting `AND workspace_id=$1` (and `AND ($2 = '' OR created_by=$2)` when `mine=true`) → MCP `list_agent_automations` (`/mcp` and `/mcp/cloud-agents`), REST `GET /v1/agent-automations`, GraphQL `agentAutomations`.
  - Independently, `PGStore.ListBlueprintSyncs` (`lego/backend/internal/store/blueprints.go:389-397`) writes:
    ```sql
    WHERE bs.blueprint_id = $1 AND bs.state <> 'created'
      AND (bs.started_at, bs.id) < (
          SELECT started_at, id FROM blueprint_syncs WHERE id = $2
      )
    ```
    omitting `AND blueprint_id = $1 AND state <> 'created'` inside the cursor subquery → MCP `list_blueprint_syncs`, REST `GET /v1/blueprints/{id}/syncs`, GraphQL `blueprintSyncs`.
  - Compare `PGStore.ListAgentSessions` (`lego/backend/internal/store/agentsessions.go:996-1000`), which already documents and enforces the fix (`WHERE id = $N AND workspace_id = $1`).
- **Fix:**
  - Extend `pageKeyset` (`lego/backend/internal/store/store.go:3746-3760`) to require a non-empty `scopeWhere` clause (referencing the outer query's already-bound parent/workspace placeholders, e.g., `"app_id = $1"`, `"workspace_id = $1"`, `"workspace_id = $1 AND sandbox_id = $2"`, `"workspace_id = $1 AND session_id = $2"`) and emit `WHERE id = $N AND (<scopeWhere>)` in the subquery.
  - In `PGStore.ListAgentAutomations` (`lego/backend/internal/store/agentautomations.go:246`), add `AND workspace_id=$1` inside the cursor subquery (and `AND ($2 = '' OR created_by=$2)` if `mine=true` should not let a member probe another workspace member's automation cursor).
  - In `PGStore.ListBlueprintSyncs` (`lego/backend/internal/store/blueprints.go:394`), scope the cursor subquery to `WHERE id = $2 AND blueprint_id = $1 AND state <> 'created'`.
  - Surface impact: fixes MCP (`/mcp` and `/mcp/cloud-agents`), REST, and GraphQL across all 7 paginated list families in one store-layer change.
