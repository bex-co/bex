# 058 — MCP `create_project`, `get_project`, `list_projects`, and `update_project` (and GraphQL `Project`) omit `environmentIds`, even when `create_project` creates an environment via `environmentName`

Why: `w4/m264` added `environmentName` to MCP `create_project` (`lego/backend/internal/projects/mcp.go:42,99-104`, "the name of the project's first environment, created in the same transaction") and `environments` to GraphQL `createProject` (`projects/graphql.go:117-129`), yet `ProjectView` (`projects/service.go:187-196`) has no `EnvironmentIDs` field — so REST `GET`/`POST`/`PATCH /v1/projects` enriches responses with `environmentIds` via `s.environmentIDsByProject`, while MCP `create_project`/`get_project`/`list_projects`/`update_project` and GraphQL `Project` omit `environmentIds`, forcing callers to issue a second `list_environments` call just to obtain the `evm-…` ID `create_project` just created.

### MCP project tools (and GraphQL `Project`) omit `environmentIds`, diverging from REST `/v1/projects` and hiding the environment ID created by `create_project(environmentName)`

- **Severity:** major
- **Versions:** deployed pin `2bd6e1f415d3` (active on production during run; zero diff in `lego/backend/internal/projects/` vs `origin/main` `2e193129fa`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-26, endpoints `/mcp` (`https://api.bex.co/mcp`) and REST `/v1/projects/{id}`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), disposable project `prj-dc3pr1cuikjc73dfh3sg` with inline environment `evm-dc3pr1cuikjc73dfh3t0` (deleted and verified 404), run-minted all-permissions API key (revoked)
- **Repro:**
  ```sh

  python3 scripts/qa-mcp.py --key-file <key.json> call create_project \
    '{"workspaceId":"tea-daif693dqjvc73e7as3g","name":"qa-prj-envids","environmentName":"dev"}'

  python3 scripts/qa-mcp.py --key-file <key.json> call get_project \

  python3 scripts/qa-mcp.py --key-file <key.json> call list_environments \
  ```

- **Expected / actual:**
  - **Expected:** Under ADR006 (same fields and semantics across REST, GraphQL, and MCP) and Render's `project` contract (which includes `environmentIds: string[]`), MCP `create_project`, `get_project`, `list_projects`, and `update_project` (and GraphQL `Project`) should include `environmentIds` (always an array, `[]` when empty), so an agent calling `create_project {"name":"…","environmentName":"dev"}` receives the newly created `evm-…` ID directly in the response and `get_project`/`list_projects` agree with REST `GET /v1/projects/{id}`.
  - **Actual:**
    - MCP `create_project` and `get_project` returned `{"createdAt":…,"databaseIds":[],"id":"prj-dc3pr1cuikjc73dfh3sg","keyValueIds":[],"name":"qa-20261126-m7k4-prj","ownerId":"tea-daif693dqjvc73e7as3g","serviceIds":[],"updatedAt":…}` with no `environmentIds` field at all.
    - REST `GET /v1/projects/prj-dc3pr1cuikjc73dfh3sg` on the exact same project returned `"environmentIds":["evm-dc3pr1cuikjc73dfh3t0"]`.
    - MCP `list_environments` confirmed `evm-dc3pr1cuikjc73dfh3t0` (`name: "dev"`) existed under `prj-dc3pr1cuikjc73dfh3sg`.
- **Wire evidence:**
  - `POST /mcp` `create_project {"name":"qa-20261126-m7k4-prj","environmentName":"dev"}` (`rndr-id: 49afc54f-4aa1-1e86`) → `200 OK`, keys `createdAt, databaseIds, id, keyValueIds, name, ownerId, serviceIds, updatedAt` (no `environmentIds`).
  - `POST /mcp` `get_project {"id":"prj-dc3pr1cuikjc73dfh3sg"}` (`rndr-id: 55a45558-c0a6-4380`) → `200 OK`, same keys (no `environmentIds`).
  - Control: `GET /v1/projects/prj-dc3pr1cuikjc73dfh3sg` (`rndr-id: 016c806d-54d6-cef0`) → `200 OK`, `"environmentIds":["evm-dc3pr1cuikjc73dfh3t0"]`.
  - Control: `POST /mcp` `list_environments {"projectId":"prj-dc3pr1cuikjc73dfh3sg"}` (`rndr-id: a19bbbb3-b516-7d99`) → `200 OK`, 1 environment `evm-dc3pr1cuikjc73dfh3t0` (`"name":"dev"`).
- **Attribution:** server (`lego/backend/internal/projects`)
- **Root cause:**
  - `ProjectView` (`lego/backend/internal/projects/service.go:187-196`) omits `EnvironmentIDs []string`.
  - `s.environmentIDsByProject(ctx, ps)` (`lego/backend/internal/projects/service.go:166-184`) already lives in the domain service specifically so any surface can reuse it (`"kept in the service (w1/m53) so the store access lives in the domain layer instead of a REST fragment and any surface can reuse it"`), yet only `projects/rest.go:101` (`renderProjects`) calls it.
  - `projects/mcp.go:71-114` (`list_projects`, `get_project`, `create_project`, `update_project`) and `projects/graphql.go:28-40` (`projectGQLType`) return bare `ProjectView`, so neither populates or exposes `environmentIds`.
- **Fix:**
  - Add `EnvironmentIDs []string `json:"environmentIds"`` to `ProjectView` (`lego/backend/internal/projects/service.go:187-196`), initialized to `[]string{}` (never `null`) and populated via `s.environmentIDsByProject(ctx, ...)` in `Get`, `List`, `CreateWithEnvironments` (and `Rename`/`SetServices`/`SetDatabases`/`SetKeyValues` via `Get`/enrichment). Note `projects/rest.go:128` uses `listBare` + `renderProjects` so REST avoids double-fetching (`renderProjects` can read `p.EnvironmentIDs` or keep its single batch lookup when `listBare` is used).
  - Add `"environmentIds": gqlutil.StrsField(func(p ProjectView) any { return p.EnvironmentIDs })` to `projectGQLType` (`lego/backend/internal/projects/graphql.go:28-40`).
  - Surface impact: additive field on MCP (`create_project`, `get_project`, `list_projects`, `update_project`) and GraphQL (`Project`); REST wire shape is unchanged.
- **Blast radius:** `lego/backend/internal/projects/{service,rest,graphql,mcp}.go` and `lego/backend/internal/projects/*_test.go`. Additive only; preserves `serviceIds`, `databaseIds`, `keyValueIds`, and `ownerId` for existing MCP/GraphQL/dashboard callers.
