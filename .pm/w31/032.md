# 032 — MCP `update_environment_variables` never returns Render's queued-deploy response because `secretsSvc.RebuildService` marshals `DeployQueued` instead of returning `nil`

Why: `secrets/mcp.go:190-194` implements Render's queued-deploy sentence (`"Environment variables updated. A deploy was requested to pick up the changes; the request was accepted but the deploy has not been created yet. Use list_deploys to check on the service's deploys."`) behind `case result.Deploy == nil:`, but production wiring in `lego/backend/internal/api/server.go:1242-1248` unconditionally marshals `deploysSvc.Rebuild` via `deploys.RenderJSON(d)` even when `d.Status == store.DeployQueued` — making the Render-parity queued branch unreachable dead code in production and diverging from `trigger_deploy` (`w8/378`).

- **Root cause:**
  - `lego/backend/internal/secrets/mcp.go:190-194` relies on `result.Deploy == nil` to emit Render's queued-deploy sentence, and its unit test (`lego/backend/internal/secrets/update_environment_variables_test.go:135-147`) only injects a fake `RebuildService` that returns `nil, nil`.
  - Production wiring in `lego/backend/internal/api/server.go:1242-1248` always marshals the returned deploy:
    ```go
    secretsSvc.RebuildService = func(ctx context.Context, serviceID string) (json.RawMessage, error) {
        d, err := deploysSvc.Rebuild(ctx, serviceID)
        if err != nil {
            return nil, err
        }
        return deploys.RenderJSON(d)
    }
    ```
  - When `w8/378` (`f90bb33d5f`) updated `deploys/rest.go` (202 empty body) and `deploys/mcp.go:215-217` (queued sentence) for `d.Status == store.DeployQueued`, it missed `secretsSvc.RebuildService` in `server.go:1242-1248`. Because `deploysSvc.Rebuild` returns a non-nil `*store.Deploy` with `Status: store.DeployQueued`, `result.Deploy` is never `nil` in production.
- **Fix:**
  - In `lego/backend/internal/api/server.go:1242-1248`, check `if d == nil || d.Status == store.DeployQueued { return nil, nil }` before calling `deploys.RenderJSON(d)` (mirroring REST's 202 empty body and `deploys/mcp.go:215`).
  - Audit all consumers of `EnvironmentPatchResult.Deploy` (`lego/backend/internal/secrets/batch.go:150` — `Deploy` is tagged `json:"-"` and only read by `secrets/mcp.go:183,190`, so REST/GraphQL `PatchEnvironment` behavior is unchanged).
