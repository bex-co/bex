# 040 — Cloud-agent automations and sessions created with an API key record the key's client ID as `createdBy`, locking out the human creator, breaking email/push notices, and bypassing `keyCeiling` in background workers

Why: `agentsessions.Service.CreateAgentAutomation` (`lego/backend/internal/agentsessions/automations.go:325,340`), `TakeOverAgentAutomation` (`:497-512`), and `Create` (`lego/backend/internal/agentsessions/service.go:767`) persist `core.SubjectFrom(ctx)` verbatim into `created_by` — which for an API key is the key's Hydra client UUID rather than the human member who minted it — while background workers (`automation_scheduler.go:210`, `spawn.go:119,281`, `pr_feedback.go:791`) re-authorize `created_by` by synthesizing `core.Identity{Subject: createdBy, Method: "session"}`, which sets `IsAPIKey() == false` and skips `core.Base.keyCeiling` (`lego/backend/internal/core/keyrole.go:79-82`).

### API-key-created automations record the key's client ID as `createdBy`, locking out their human creator and breaking background authorization/notifications

- **Severity:** major
- **Versions:** deployed pin `8b9d780f45` (`cdaa0a248615`, active on production during run; zero diff in `lego/backend/internal/agentsessions/{automations,automation_scheduler,spawn,pr_feedback,service}.go` vs `HEAD` `5ef2b31e0d`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-25, endpoints `/mcp` (`https://api.bex.co/mcp`) and REST `/v1/agent-automations`, workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), disposable automation `aut-dc3l45nfct6s73fs0a30` (deleted after run), run-minted all-permissions API key (revoked) + the same QA user's Kratos session (logged out)
- **Repro:**
  ```sh
  # 1. Create an automation via MCP (or REST/GraphQL) with a workspace API key:
  python3 scripts/qa-mcp.py --key-file <key.json> call create_agent_automation \
    '{"workspaceId":"tea-daif693dqjvc73e7as3g","name":"qa-aut-own","enabled":false,"triggers":[{"type":"schedule","schedule":{"frequency":"custom","cron":"0 0 1 1 *","timezone":"UTC"}}],"template":{"task":"noop","agentConfig":{"agent":"claude"},"maxSpendUSD":1}}'

  # 2. As the exact human member who minted <key.json> (Kratos session), list mine=true and attempt to update it:
  curl -sS -b <jar> -H 'Accept: application/json' \
    'https://api.bex.co/v1/agent-automations?ownerId=tea-daif693dqjvc73e7as3g&mine=true'
  curl -sS -i -X PATCH -b <jar> -H 'Accept: application/json' -H 'Content-Type: application/json' \
    -d '{"name":"qa-aut-own-edited"}' \
    'https://api.bex.co/v1/agent-automations/<aut-id>?ownerId=tea-daif693dqjvc73e7as3g'
  ```
- **Expected / actual:**
  - **Expected:** An attributed bex API key acts as its human creator (`docs/ADR024-members.md` I1/I11/I13). An automation (or session) created by an attributed API key should attribute `createdBy` to the human creator (or resolve the attributed creator consistently for ownership, `mine: true`, notifications, and background re-authorization) so that:
    1. The human creator sees the automation in `mine: true` and can edit, pause, resume, or delete it from the dashboard/CLI/MCP.
    2. Automation failure/pause emails (`notifications/automation_email.go:139-146`) and push notices (`notifications/push_worker.go:622-626`) resolve the human creator's email and push devices.
    3. Rotating or revoking a short-lived API key does not orphan scheduled automations under `creator_lost_access`.
    4. Background re-authorization in `decideAutomationRun`, `SpawnChild`, and `PRFeedback` never skips `core.Base.keyCeiling` by synthesizing `Method: "session"` for a key subject.
  - **Actual:**
    1. `create_agent_automation` recorded `"createdBy": "e1f46fd0-644c-47de-9b13-b53a661b9ed6"` (the run-minted API key's Hydra client UUID, not the QA user's Kratos subject).
    2. The QA user's Kratos session received `{"ownerId":"tea-daif693dqjvc73e7as3g","automations":[]}` from `GET /v1/agent-automations?mine=true`.
    3. The QA user's Kratos session received `HTTP/2 403 AGENT_AUTOMATION_NOT_CREATOR` (`"only the member who created an automation can change what it runs; a workspace admin can pause, resume, delete or take it over"`) when trying to edit the automation their own key created.
- **Wire evidence:**
  - MCP `create_agent_automation` (`POST https://api.bex.co/mcp` -> `200`) returned `"id":"aut-dc3l45nfct6s73fs0a30","createdBy":"e1f46fd0-644c-47de-9b13-b53a661b9ed6"`.
  - Human Kratos session `GET /v1/agent-automations?ownerId=tea-daif693dqjvc73e7as3g&mine=true` -> `200`: `{"ownerId":"tea-daif693dqjvc73e7as3g","automations":[]}`.
  - Human Kratos session `PATCH /v1/agent-automations/aut-dc3l45nfct6s73fs0a30?ownerId=tea-daif693dqjvc73e7as3g` -> `403`: `{"code":"AGENT_AUTOMATION_NOT_CREATOR","error":"only the member who created an automation can change what it runs; a workspace admin can pause, resume, delete or take it over","id":"forbidden","message":"only the member who created an automation can change what it runs; a workspace admin can pause, resume, delete or take it over"}`.
- **Attribution:** server (`lego/backend/internal/agentsessions`)
- **Root cause:**
  - `agentsessions.Service.CreateAgentAutomation` (`lego/backend/internal/agentsessions/automations.go:325,340`), `TakeOverAgentAutomation` (`:497,502,512`), `AgentAutomations` (`mine` filter, `:283-287`), `UpdateAgentAutomation` (`:386`), `scopeAutomationManaged` (`:605`), `Create` (`lego/backend/internal/agentsessions/service.go:767`), and `List` (`mine` filter, `:1334-1340`) all use `core.SubjectFrom(ctx)` directly without resolving an attributed API key's creator via `Base.KeyCreator(ctx)` (`lego/backend/internal/core/keyrole.go:127-138`).
  - Downstream consumers assume `created_by` is a human Kratos user subject:
    - `decideAutomationRun` (`lego/backend/internal/agentsessions/automation_scheduler.go:210`), `SpawnChild` / `CancelChild` (`lego/backend/internal/agentsessions/spawn.go:119,281`), and `PRFeedback` (`lego/backend/internal/agentsessions/pr_feedback.go:791`) synthesize `core.Identity{Subject: createdBy, Method: "session"}`. Because `Method` is `"session"`, `id.IsAPIKey()` is `false`, so `core.Base.keyCeiling` (`lego/backend/internal/core/keyrole.go:79-82`) is completely bypassed when `createdBy` is an API key ID: a demoted creator's key with a lagging/stale FGA tuple is not capped by the creator's current role.
    - `notifications/automation_email.go:139-146` passes `a.CreatedBy` to Kratos `EmailLookup` (which has no entry for a Hydra client UUID, silently dropping failure/pause emails), and `notifications/push_worker.go:622-626` looks up push recipients by `a.CreatedBy` (no device is registered to an API key UUID).
- **Fix:**
  - Add a shared helper on `agentsessions.Service` (e.g. `actingSubject(ctx) (string, error)`) using `s.KeyCreator(ctx)`:
    - For a human session or human OAuth token (`!isKey`), return `core.SubjectFrom(ctx)`.
    - For an attributed bex API key (`isKey && creator != ""`), return `creator` (the human member's subject) — failing closed on registry lookup error (`ErrAuthzUnavailable`) and deciding explicitly how unattributed legacy keys (`isKey && creator == ""`) are handled (refuse automation create/takeover or keep explicit non-session identity).
  - Use `actingSubject(ctx)` for `CreateAgentAutomation`, `TakeOverAgentAutomation`, `UpdateAgentAutomation` creator check, `scopeAutomationManaged` creator check, `AgentAutomations(mine: true)`, `Create` (`row.CreatedBy`), and `List(mine: true)` (keeping `InitialAttachments.Caller` consistent with `UploadAttachment`'s caller resolution so an API key can attach its own uploaded files).
  - For pre-existing rows whose `created_by` is already a Hydra client UUID (or any non-human subject), ensure `decideAutomationRun` (`automation_scheduler.go:210`), `SpawnChild` (`spawn.go:119,281`), and `PRFeedback` (`pr_feedback.go:791`) do not bypass `keyCeiling` by blindly stamping `Method: "session"` on a key subject (resolve via `KeyCreators` or check whether `createdBy` is an API key and enforce `keyCeiling` / resolve to its creator).
  - Surface impact: fixes MCP (`/mcp` and `/mcp/cloud-agents`), REST, GraphQL, dashboard `Mine` views/edit permissions, and email/push delivery for automations and sessions created with an API key.
- **Blast radius:** `lego/backend/internal/agentsessions/{automations,automation_scheduler,spawn,pr_feedback,service,attachments}.go` and tests; audit rows continue recording the actual calling key subject from `ctx` (`AuthorizeWorkspaceTarget`).
