# 125 — `apps.Service.UpdateDisk` unconditionally writes to Postgres, patches the App CR (`updatedAt`), and records `apps.UpdateDisk` / `disk_updated` events on empty (`{}`) and no-op updates across MCP, REST, and GraphQL

Why: `apps.Service.UpdateDisk` (`lego/backend/internal/apps/disks.go:224-260`) never checks whether `name`, `mountPath`, and `sizeGB` are all `nil` or identical to the current `store.Disk` values, so an empty `{}` or unchanged update unconditionally updates Postgres, patches the App CR (advancing `updatedAt`), and emits a bogus `apps.UpdateDisk` audit row and `disk_updated` service event across MCP `update_disk`, REST `PATCH /v1/disks/{diskId}`, and GraphQL `updateDisk`.

### Empty or identical `update_disk` / `PATCH /v1/disks/{diskId}` / `updateDisk` calls mutate `updatedAt` and emit bogus `disk_updated` events

- **Severity:** minor
- **Versions:** deployed pin `918667a83f` (`410850e80281`, active during run; zero diff in `lego/backend/internal/apps/disks.go` vs `origin/main` `d51d161de8`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-26, MCP `update_disk`, REST `PATCH /v1/disks/{diskId}`, and GraphQL `updateDisk`; verified by code inspection (live disk creation requires a paid compute plan and was skipped under the QA free-only rule)
- **Repro:**

  ```sh
  # Given an existing disk dsk-... with name "data", mountPath "/var/data", sizeGB 10:
  # 1. Empty MCP update_disk call:
  python3 scripts/qa-mcp.py --key-file <key.json> call update_disk '{"diskId":"<dsk-id>"}'

  # 2. Unchanged REST PATCH call:
  python3 scripts/qa-mcp.py --key-file <key.json> rest PATCH /v1/disks/<dsk-id> \

  # 3. Inspect service events / audit logs — each no-op call bumped updatedAt and wrote disk_updated / apps.UpdateDisk.
  ```

- **Expected vs actual:**
  - **Expected:** After authorization, billing check, and field validation, an empty patch (`name == nil && mountPath == nil && sizeGB == nil`) or a patch whose normalized fields equal the current `disk.Name`, `disk.MountPath`, and `disk.SizeGB` must return `diskView(disk)` cleanly with zero Postgres writes, zero Kubernetes App CR patches (`updatedAt` unchanged), and zero `apps.UpdateDisk` / `disk_updated` audit or event rows.
  - **Actual:** `UpdateDisk` (`disks.go:247-259`) unconditionally executes `s.Store.UpdateDisk(ctx, diskID, name, mountPath, sizeGB)`, `s.patchFetched(ctx, a, ...)` (which stamps `updatedAt` via `resourcemeta.Touch`), and `s.RecordDiskChanged(ctx, a, core.AuditVerbUpdateDisk, updated.ID, &disk.SizeGB, &updated.SizeGB)` even when every field is `nil` or identical to the stored disk.
- **Wire evidence:** Code-traced through the shared `apps.Service.UpdateDisk` (`lego/backend/internal/apps/disks.go:224-260`) invoked by MCP `update_disk`, REST `PATCH /v1/disks/{diskId}`, and GraphQL `updateDisk`; live read-only control `update_disk` on nonexistent `dsk-nonexistent0000000000` (`rndr-id: 27aa9209-586a-e552`) confirmed the deployed handler reaches `authorizeDisk` (`NOT_FOUND: disk not found`).
- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:** `lego/backend/internal/apps/disks.go:224-260` validates `name`, `mountPath`, and `sizeGB` (`:232-246`) and immediately proceeds to `s.Store.UpdateDisk` (`:247`), `s.patchFetched` (`:251`), and `s.RecordDiskChanged` (`:258`) with no equality/no-op check against `disk` (`name == nil || *name == disk.Name`, `mountPath == nil || *mountPath == disk.MountPath`, `sizeGB == nil || *sizeGB == disk.SizeGB`).
- **Fix:**
  - After validation at `lego/backend/internal/apps/disks.go:246`, check whether any requested field differs from `disk`:
    ```go
    unchanged := (name == nil || *name == disk.Name) &&
        (mountPath == nil || *mountPath == disk.MountPath) &&
        (sizeGB == nil || *sizeGB == disk.SizeGB)
    if unchanged {
        return diskView(disk), nil
    }
    ```
  - Because `authorizeDisk` already runs under `core.WithDeferredAllowedWriteAudit(ctx)` (`:225`), returning early before `s.Store.UpdateDisk` avoids any store write, CR patch, `updatedAt` bump, or bogus `apps.UpdateDisk` / `disk_updated` audit/event row.
  - Surface impact: fixes MCP `update_disk`, REST `PATCH /v1/disks/{diskId}`, and GraphQL `updateDisk` together.
