# 034 — MCP `get_metrics` with `project`/`environment` scope and >1 `metricTypes` fails on any mixed-resource project

Why: `metrics/mcp.go:240-247` only builds a resource-kind `keep` filter when `len(in.MetricTypes) == 1`. On any real project or environment that mixes resource kinds (e.g., a web service + a Postgres database, or a web service + a static site), calling `get_metrics` with two or more `metricTypes` such as `["cpu_usage", "http_request_count"]` or `["cpu_usage", "active_connections"]` passes `keep = nil` and then queries every metric on every resource, failing the whole call on the first resource/metric mismatch.

### Multi-metric `get_metrics` scoped by `project` or `environment` aborts on mixed web + Postgres / static-site / Key Value projects

- **Expected / actual:**
  - **Expected:** Consistent with single-metric project/environment scoping (`w4/m596`, `keepMetricResource` / `keepActiveConnectionsResource` in `metrics/project.go:61-90`), a multi-metric `get_metrics` scoped by `project`, `environment`, or `region` (with no explicit `resourceId`/`resource`) returns each applicable metric for each resource that supports it (skipping resource/metric pairs that do not apply to that resource's kind, and omitting resources with zero applicable metrics), while explicit `resourceId`/`resource` calls stay strict and reject unsupported pairs.
  - **Actual:** Both multi-metric calls failed with `isError: true`:

- **Attribution:** server (`lego/backend/internal/metrics`)
- **Root cause:**
  - `lego/backend/internal/metrics/mcp.go:240-258` only sets `keep` when `len(in.MetricTypes) == 1`; for `len(in.MetricTypes) > 1`, `keep` stays `nil`, so `resolveMetricScope` returns every resource in the project/environment regardless of kind.
  - `lego/backend/internal/metrics/mcp.go:314-347` then iterates every requested `metricType` for every resolved resource ID without consulting `keepMetricResource` / `keepActiveConnectionsResource` (`metrics/project.go:61-90`) for that resource's kind, aborting the entire response on the first incompatible `(resource, metricType)` pair.
- **Fix:**
  - Expose each resolved resource's `savedsearch.Resource` metadata (or a `map[string]savedsearch.Resource` / slice of `savedsearch.Resource`) on `resolveMetricScope`'s result (`lego/backend/internal/metrics/project.go`).
  - In `lego/backend/internal/metrics/mcp.go:240-258`, build a per-metric predicate helper `metricKeep(metricType string) func(savedsearch.Resource) bool` (reusing `keepActiveConnectionsResource` and `keepMetricResource(metricIDFor(metricType))`), and pass the union predicate (`any metricType in in.MetricTypes matches r`) to `resolveMetricScope` whenever `len(in.MetricTypes) > 0`.
  - Inside `mcp.go:314-351`, when `skipUnreadable` (`scoped && len(explicit) == 0`) is true and the resource has known `savedsearch.Resource` metadata, skip any `metricType` where `!metricKeep(metricType)(res)` (and omit `resp` if `len(resp.Metrics) == 0`). Keep explicit `resourceId`/`resource` calls strictly returning the bad-request error when a caller explicitly asks for an unsupported metric on a specific resource.
