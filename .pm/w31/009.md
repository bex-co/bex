# 009 — `deploys.FilterOf` never validates `status`, so MCP `list_deploys` and GraphQL `deploys` silently return empty results on unknown statuses

Why: `lego/backend/internal/deploys/service.go:452-477` (`FilterOf`) passes caller-supplied `statuses` straight to the store without checking them against `store.DeployStatuses()`, so REST rejects invalid statuses only via the OpenAPI request validator while MCP `list_deploys` and GraphQL `deploys` silently return `[]` on typos like `"running"` or `"failed"`.

### MCP `list_deploys` and GraphQL `deploys` silently return empty results on invalid `status` values while REST returns `400 bad_request`

- **Expected / actual:**
  - **Expected:** Per Render's OpenAPI `deployStatus` enum (`created|queued|build_in_progress|update_in_progress|live|deactivated|build_failed|update_failed|canceled|pre_deploy_in_progress|pre_deploy_failed`) and ADR006's shared-service parity rule, passing an unknown `status` filter on REST, MCP `list_deploys`, or GraphQL `deploys` must fail with `core.ErrBadRequest` naming the allowed statuses — never silently return an empty list that misleads an agent (e.g. passing `"running"`, `"succeeded"`, or `"failed"`) into concluding no deploys exist.
  - **Actual:**
    - REST `GET /v1/services/<srv-id>/deploys?status=not_a_real_status` returns `400 bad_request`: `"status must be one of created|queued|build_in_progress|update_in_progress|live|deactivated|build_failed|update_failed|canceled|pre_deploy_in_progress|pre_deploy_failed"`.
    - MCP `list_deploys` with `status: ["not_a_real_status"]` returns `200` (`isError` unset) with `"[]\n\n cursor: \"\""`.
    - GraphQL `deploys` with `status: ["not_a_real_status"]` returns `200` with `{"data":{"deploys":[]}}` and no errors.
- **Wire evidence:**

  - `POST https://api.bex.co/graphql` (`deploys`, `status: ["not_a_real_status"]`) → `200` (`rndr-id: 38f256d2-7f14-06bf`): `{"data":{"deploys":[]}}`
  - Control `GET https://api.bex.co/v1/services/srv-dc3aqepa7e1c7381dpl0/deploys?status=not_a_real_status` → `400` (`rndr-id: 5b81c7c4-1a95-6008`): `{"error":"status must be one of created|queued|build_in_progress|update_in_progress|live|deactivated|build_failed|update_failed|canceled|pre_deploy_in_progress|pre_deploy_failed","id":"bad_request","message":"status must be one of created|queued|build_in_progress|update_in_progress|live|deactivated|build_failed|update_failed|canceled|pre_deploy_in_progress|pre_deploy_failed"}`
- **Attribution:** server (`lego/backend/internal/deploys`)
- **Root cause:**
  - `lego/backend/internal/deploys/service.go:452-477` (`FilterOf`) copies `statuses` directly into `ListFilter{Statuses: statuses}` without validating entries against `store.DeployStatuses()`.
  - REST only rejects invalid statuses because `internal/api/openapi_validate.go` enforces `render-public-api-1.json`'s `deployStatus` enum on the query string before dispatch; MCP (`lego/backend/internal/deploys/mcp.go:46,128-134`) and GraphQL (`lego/backend/internal/deploys/graphql.go:187-201`) bypass the OpenAPI middleware and reach `FilterOf` directly.
  - `listDeploysArgs.Statuses` (`lego/backend/internal/deploys/mcp.go:46`) also emits no JSON Schema `items.enum` constraint, so the MCP SDK validator accepts any string array element.
- **Fix:**
  - Validate every element of `statuses` inside `deploys.FilterOf` (`lego/backend/internal/deploys/service.go:452-477`) against `store.DeployStatuses()`, returning `fmt.Errorf("%w: status must be one of %s", core.ErrBadRequest, strings.Join(store.DeployStatuses(), "|"))` (without echoing the raw caller string so secrets misplaced in `status` are never echoed).
  - Optionally add JSON Schema `items.enum` on `list_deploys.status` in `lego/backend/internal/deploys/mcp.go` (note `status` is a bex extension argument on `list_deploys` — upstream `render-mcp-tools.json` has `cursor`, `limit`, `serviceId`, `workspaceId` — so check `TestMCPParity*` and `TestMCPArgumentErrorsNeverEchoTheValue` stay green).
  - Verify REST, GraphQL `deploys`, and MCP `list_deploys` all reject unknown statuses and accept all 11 statuses from `store.DeployStatuses()`.
