# 135 — `apps.Service.GenerateBlueprint` fails to deduplicate resource IDs (and name+ID aliases), crashing self-validation with `503 BLUEPRINT_GENERATE_FAILED` across MCP, REST, and GraphQL

Why: `apps.Service.GenerateBlueprint` (`lego/backend/internal/apps/blueprint_generate.go:160-296`) iterates `req.PostgresIDs`, `req.KeyValueIDs`, `req.ServiceIDs`, and `req.EnvGroupIDs` without deduplicating by canonical resolved resource ID — so passing the same ID twice (or a service's display name alongside its `srv-…` ID) emits duplicate resource declarations into the generated `render.yaml`, fails `CompileBlueprintIR` (`:305-308`) with `"duplicate name …"`, and returns `503 BLUEPRINT_GENERATE_FAILED` claiming `"this is a bex bug, please report it"` across MCP, REST, and GraphQL.

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `apps.Service.GenerateBlueprint` (`lego/backend/internal/apps/blueprint_generate.go:160-296`) appends resolved resources straight into `databases` (`:162-173`), `keyValues` (`:176-186`), `services` (`:208-232`), and `doc["envVarGroups"]` (`:289-295`, iterating raw `req.EnvGroupIDs` even though `selectedGroups` at `:190-199` is already keyed by `gid`) with no deduplication by resolved canonical ID (`d.Name`, `kv.Name`, `core.AppPublicID(a)` / `a.Name`, `gid`).
  - Because `AuthorizeApp` accepts both `srv-…` IDs and display names, deduplicating only raw request strings would still miss `["hello-go", "srv-…"]`; deduplication must track the canonical resolved resource identity after authorization (while still authorizing each requested entry or canonicalizing once resolved).
  - Separately, `generatedResourceID` (`blueprint_generate.go:330-351`) only matches `#/services/(\d+)` and indexes into raw `req.ServiceIDs`/`req.KeyValueIDs` rather than the deduplicated emitted slices (and does not handle `#/databases/(\d+)` or `#/envVarGroups/(\d+)`).
- **Fix:**
  - In `apps.Service.GenerateBlueprint` (`lego/backend/internal/apps/blueprint_generate.go:160-296`), deduplicate resolved resources in insertion order using `seen` sets keyed on canonical IDs (`d.Name` for Postgres, `kv.Name` for Key Value, `a.Namespace + "/" + a.Name` or `core.AppPublicID(a)` for Apps, `gid` for EnvGroups) and emit `doc["envVarGroups"]` from the deduplicated `envGroupIDs` slice rather than raw `req.EnvGroupIDs`.
  - Update `generatedResourceID` (`blueprint_generate.go:330-351`) to read from the deduplicated emitted ID slices and map `#/databases/(\d+)` and `#/envVarGroups/(\d+)` in addition to `#/services/(\d+)`, so any future real self-check failure names the exact blocking database or env group too.
  - Surface impact: fixes MCP `generate_blueprint`, REST `POST /v1/blueprints/generate`, GraphQL `Query.generateBlueprint`, and the dashboard Generate Blueprint dialog through the single `apps.Service.GenerateBlueprint` seam.
