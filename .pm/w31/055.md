# 055 — `parseAutoDeployBool` collapses explicit `autoDeployTrigger: ""` to absent on MCP `update_service` and GraphQL `createService`, silently ignoring invalid empty values and bypassing `errAutoDeployBoth`

Why: `applyServicePatch` (`lego/backend/internal/apps/mcp.go:948`) dereferences `*string` via `ptr.Deref(in.AutoDeployTrigger, "")` and `gqlCreateRequest` (`lego/backend/internal/apps/graphql.go:794`) reads `gqlutil.Str(args, "autoDeployTrigger")` before calling `parseAutoDeployBool` (`lego/backend/internal/apps/rest.go:871-879`), collapsing an explicitly supplied `autoDeployTrigger: ""` to absent — so MCP `update_service` and GraphQL `createService` silently succeed on `autoDeployTrigger: ""` and bypass the `autoDeploy` + `autoDeployTrigger` mutual-exclusion guard (`errAutoDeployBoth`), diverging from REST `POST`/`PATCH /v1/services` (`400 bad_request`) and GraphQL `setAutoDeployTrigger` (`bad request: autoDeployTrigger is required`).

  - **Actual:**

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `parseAutoDeployBool` (`lego/backend/internal/apps/rest.go:871-879`) accepts `trigger string` rather than `trigger *string`, treating `""` as absent (`if legacy != nil && trigger != ""` and `if trigger != ""`).
  - `applyServicePatch` (`lego/backend/internal/apps/mcp.go:948`) already receives `in.AutoDeployTrigger *string` (`mcp.go:134`) — whose pointer explicitly distinguishes omitted from present — yet flattens it with `ptr.Deref(in.AutoDeployTrigger, "")` before calling `parseAutoDeployBool`, throwing away presence.
  - `gqlCreateRequest` (`lego/backend/internal/apps/graphql.go:794`) reads `gqlutil.Str(args, "autoDeployTrigger")` instead of `gqlutil.StrPtr(args, "autoDeployTrigger")` (already used on line `:831` for `registryCredentialId`), throwing away presence in GraphQL `createService` too.
  - `TestAutoDeployBothFieldsRefusedOnEverySurface` (`lego/backend/internal/apps/autodeploy_test.go:192-228`) only tested non-empty `"commit"`/`"off"` trigger strings and never passed `autoDeployTrigger: ""` (alone or with `autoDeploy`).
- **Fix:**
  - Change `parseAutoDeployBool` (`lego/backend/internal/apps/rest.go:871-879`) to accept `trigger *string`:
    - When `legacy != nil && trigger != nil`, return `errAutoDeployBoth` (even when `*trigger == ""`).
    - When `trigger != nil`, call `parseTrigger(*trigger)` unconditionally so `""` returns `bad request: autoDeployTrigger must be "off", "commit" or "checksPass"`.
  - Update its only two callers:
    - `lego/backend/internal/apps/mcp.go:948`: pass `in.AutoDeployTrigger` directly (drop `ptr.Deref`).
    - `lego/backend/internal/apps/graphql.go:794`: pass `gqlutil.StrPtr(args, "autoDeployTrigger")` instead of `gqlutil.Str(args, "autoDeployTrigger")`.
  - Optionally add `mcputil.PropEnum("autoDeployTrigger", "off", "commit", "checksPass")` on `update_service` if consistent with `update_service`'s schema conventions, while keeping the handler-level `parseAutoDeployBool` fix authoritative so direct callers and GraphQL both enforce it.
  - Surface impact: aligns MCP `update_service` and GraphQL `createService` with REST `POST`/`PATCH /v1/services` and GraphQL `setAutoDeployTrigger`; no wire breaking change for valid callers (`off`, `commit`, `checksPass`, or omitted).
