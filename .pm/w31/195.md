# 195 — `environments.Service.resolveForCreate` returns `403 FORBIDDEN` vs `404 NOT_FOUND`, creating a cross-tenant environment existence oracle across MCP, REST, and GraphQL

Why: `environments.Service.resolveForCreate` (`lego/backend/internal/environments/service.go:201-220`) fetches `s.Store.GetEnvironment(ctx, ids.EnvironmentStorageID(environmentID))` without scoping by `workspaceID`, returning `404 NOT_FOUND` when the ID does not exist and `403 FORBIDDEN` (`environment "<id>" does not belong to the target workspace`) when the ID belongs to another tenant's workspace. While `sandbox.Service.placeGroup` (`lego/backend/internal/sandbox/groups.go:313-333`) explicitly comments on this cross-workspace leak and collapses non-protected `ErrForbidden` into `core.NotFound("environment")`, every other caller of `core.ResolveEnvironmentForCreate` — service create/dry-run (`apps/service.go:2557,3027`), Blueprint apply (`apps/deploy.go:4265`), Postgres create/recover (`postgres/service.go:980`, `postgres/recovery.go:663`), Key Value create (`keyvalue/service.go:706`), and env group create/move/clone (`envgroups/service.go:2012`) — exposes the `403`-vs-`404` oracle across MCP, REST, and GraphQL.

- **Expected vs actual:**
  - **Expected:** Matching `sandbox.Service.placeGroup` (`sandbox/groups.go:313-333`) and ADR072's no-existence-oracle rule, supplying an `environmentId` that belongs to another workspace must return the same `404 NOT_FOUND` (`environment not found`) as a nonexistent `environmentId`, while keeping `403 FORBIDDEN` (`ProtectedPlacementCode`) only for a same-workspace protected environment.
  - **Actual:** Every non-sandbox resource creation surface returned `NOT_FOUND` for `evm-00000000000000000000` and `FORBIDDEN` (`resolving environment: forbidden: environment "<id>" does not belong to the target workspace`) for `evm-dbo052cvg1gs7387qoo0`, letting any workspace member probe arbitrary `evm-…` / `env-…` IDs for cross-tenant existence.

- **Attribution:** server (`lego/backend/internal/environments/service.go`)
- **Root cause:**
  - `lego/backend/internal/environments/service.go:205-211` (`resolveForCreate`): reads `s.Store.GetEnvironment(ctx, ids.EnvironmentStorageID(environmentID))`, maps missing rows to `404` (`store.MapError(err)`), and then explicitly returns `fmt.Errorf("%w: environment %q does not belong to the target workspace", core.ErrForbidden, environmentID)` when `workspaceID == "" || e.TenantID != workspaceID`.
  - `lego/backend/internal/sandbox/groups.go:313-333` (`placeGroup`) already works around this exact bug locally by checking `errors.Is(err, core.ErrForbidden)` and replacing non-`ProtectedPlacementCode` errors with `core.NotFound("environment")`, whereas all other callers (`apps/service.go:2557,3027`, `apps/deploy.go:4265`, `postgres/service.go:980`, `postgres/recovery.go:663`, `keyvalue/service.go:706`, `envgroups/service.go:2012`) return the raw error.
- **Fix:**
  - In `lego/backend/internal/environments/service.go:209-211`, return `core.NotFound("environment")` whenever `workspaceID == "" || e.TenantID != workspaceID` (matching `GetEnvironment` / ADR072's cross-tenant concealment and keeping `createResolver.RequirePlacement`'s `403 ProtectedPlacementCode` exclusively for same-workspace protected environments).
  - Remove the now-redundant cross-workspace `ErrForbidden` workaround comment/branch in `lego/backend/internal/sandbox/groups.go:313-333` (keep `ProtectedPlacementCode` propagation intact), and update any tests in `environments/`, `apps/`, `postgres/`, `keyvalue/`, and `envgroups/` that previously asserted `ErrForbidden` on a cross-workspace `environmentId`.
  - Surface impact: fixes MCP, REST, GraphQL, and Blueprint apply together because all share `environments.Service.resolveForCreate` via `core.ResolveEnvironmentForCreate`.
