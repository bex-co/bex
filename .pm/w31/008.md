# 008 — Blueprint plan (`update_blueprint` / `plan_blueprint` / `POST /v1/blueprints/{id}/syncs`) returns `no_changes` when `render.yaml` drops env vars, leaving them permanently locked as `managedBy: blueprint`

Why: `PlanBlueprintResource` (`lego/backend/internal/apps/blueprint_state_plan.go:385-428`) checks only whether `ApplyBlueprintServiceSpec` mutates `App.Spec` (where `mergeBlueprintEnv` deliberately keeps undeclared literals for Render parity) and never checks whether the manifest's declared env-var set (`core.AnnotationBlueprintEnv`, `bex.co/blueprint-env`) shrank — so dropping env vars from `render.yaml` through the Render-parity plan→approve workflow returns `planningOutcome: "no_changes"`, leaves `blueprints.manifest` stale, and leaves every dropped variable permanently locked (`409 ENV_VAR_MANIFEST_MANAGED`).

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `lego/backend/internal/apps/blueprint_state_plan.go:385-428` (`PlanBlueprintResource`, `BlueprintResourceService` case): computes `changed` from `ApplyBlueprintServiceSpec(&probe, want, svc.fields)`, which calls `mergeBlueprintEnv(dst.Env, want.Env)` (`lego/backend/internal/apps/blueprint_plan.go:339,525-560`). Because `mergeBlueprintEnv` intentionally preserves existing `spec.Env` literals omitted from `want.Env`, dropping variables from `render.yaml` leaves `probe` equal to `served` (`changed == false`).
  - `PlanBlueprintResource` never checks whether the live App's `core.AnnotationBlueprintEnv` (`bex.co/blueprint-env`, stamped by `stampBlueprintEnv` at `lego/backend/internal/apps/blueprint_ownership.go:324-335`) differs from `strings.Join(svc.ownedEnvNames(), ",")` (or is absent on a pre-`w21/m421` App carrying literals).
  - Therefore `action.Operation` remains `noop`, `planChangesAnything(actions)` (`lego/backend/internal/apps/blueprint_onboarding.go:331,406-410`) returns `false`, and `planBlueprintSync` calls `plans.SettleNoChangesPlan` (`lego/backend/internal/store/blueprint_plans.go:210-230`), which updates `manifest` only when `status = 'created'` and never patches `bex.co/blueprint-env`.
- **Fix:**
  - In `PlanBlueprintResource` (`lego/backend/internal/apps/blueprint_state_plan.go:385-428`), detect when `stampBlueprintEnv` would change `core.AnnotationBlueprintEnv` on `current` — i.e., when `have, ok := current.GetAnnotations()[core.AnnotationBlueprintEnv]; !ok || have != strings.Join(svc.ownedEnvNames(), ",")` (check whether an App with no `spec.Env` literals and no `ownedEnvNames()` should avoid spurious updates when `!ok` and `len(current.Spec.Env) == 0`). When ownership changes (e.g. manifest dropped one or more declared env vars), record `action.Operation = BlueprintPlanUpdate` with `addChangedFields(&action, "envVars")` so `planBlueprintSync` emits `planningOutcome: "planned"` and `ApproveBlueprint` runs `stampBlueprintOwnership` → `stampBlueprintEnv` and updates `blueprints.manifest` — without rolling pods unnecessarily (note `rolls` at `:414` stays `false` when `probe == current.Spec`).
  - Verify whether `SettleNoChangesPlan` should also handle comment-only manifest edits or if planning an `envVars` ownership update suffices for dropped vars across MCP (`update_blueprint` / `plan_blueprint` / `approve_blueprint`), REST (`POST /v1/blueprints/{id}/syncs` / `/approve`), GraphQL (`planBlueprintSync` / `approveBlueprintSync`), and the dashboard Blueprint UI.
