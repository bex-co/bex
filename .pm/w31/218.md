# 218 — `apps.Service.authorizeDisk`, `projects.Service.{authorizedProject,authorizedSavedSearch,ProjectScopeResources}`, and `metrics.Service.resolveMetricScope` skip OpenFGA authorization on missing IDs, creating a `404`-vs-`403` existence oracle and unaudited role-check bypass across MCP, REST, and GraphQL

Why: Every other by-ID resource family in `lego/backend/internal/api/byid_resolution_guard_test.go` (`services`, `postgres`, `key-value`, `env-groups`, `environments`, `blueprints`, `webhooks`, `registrycredentials`, `sandboxes`, `agent-*`, `events`, `notifications`, `api-keys`) authorizes `relation` on the caller's workspace even when an ID does not exist (via `core.Base.resolveAuthorizedApp`/`authorizeDatastore` at `core/base.go:1634-1638,1915` or `core.Base.ScopeByID` + leading `Authorize`), so an unauthorized caller (such as a `Viewer`, `Contributor`, or `Billing` member calling a write verb, or a revoked/non-member caller probing IDs) always gets `403 FORBIDDEN` and a denied audit row instead of `404 NOT_FOUND`. The two remaining fetch-then-gate families — `apps.Service.authorizeDisk` (`lego/backend/internal/apps/disks.go:286-307`), `projects.Service.authorizedProject` (`lego/backend/internal/projects/service.go:293-305`), `projects.Service.authorizedSavedSearch` (`lego/backend/internal/projects/savedsearches.go:106-119`), and `projects.Service.ProjectScopeResources` (`projects/savedsearches.go:373-384`, plus `metrics.Service.resolveMetricScope` at `lego/backend/internal/metrics/project.go:109-123`) — return `404 NOT_FOUND` (and `503` when unwired in `projects`) immediately on `store.ErrNotFound` without running OpenFGA authorization or denied-access auditing, exposing a `404`-vs-`403` existence oracle across Disks, Disk Snapshots, Projects, Saved Searches, and Project/Environment-scoped Logs & Metrics on MCP, REST, and GraphQL.

- **Root cause:**
  - `lego/backend/internal/apps/disks.go:286-307` (`authorizeDisk`): calls `s.Store.GetDisk(ctx, diskID)` before `s.AuthorizeApp(ctx, relation, disk.AppID)` and returns `store.MapError(err)` on `store.ErrNotFound` without calling `s.Authorize(ctx, relation)`. CI's `TestAuthzGuardsEveryVerb` / `TestRoleLadder` (`lego/backend/internal/api/server_test.go:1032`) wires `&apps.Service{Base: base}` with `Store: nil`, so it only exercised the `s.Store == nil` fallback (`disks.go:287-297`) and never the production `Store != nil` miss path.
  - `lego/backend/internal/projects/service.go:293-305` (`authorizedProject`), `lego/backend/internal/projects/savedsearches.go:106-119` (`authorizedSavedSearch`), and `projects/savedsearches.go:373-384` (`ProjectScopeResources` standalone `environmentID` branch): return `ErrProjectsUnavailable` (when unwired) or `store.MapError(err)` (on `store.ErrNotFound`) before `s.AuthorizeOnOwner` or `s.Authorize` ever runs. CI's `sweepProjectStore` (`lego/backend/internal/api/server_test.go:991-993,1014-1016`) hardcodes `GetProject` and `GetSavedSearch` to always return a row (`prj-sweep` / `svs-sweep`) and never `store.ErrNotFound`, hiding the bypass from the authz and role-ladder sweeps.
  - `lego/backend/internal/metrics/project.go:109-123` (`resolveMetricScope`): invokes `savedsearch.ResolveScope` (which calls `ProjectScopeResources` under `RelCanView`) before `s.authorizeScopeActivity` (`RelCanViewActivity`), returning `404` on absent `project`/`environment` IDs for `Billing` callers instead of `403`.
- **Fix:**
  - In `apps.Service.authorizeDisk` (`lego/backend/internal/apps/disks.go:286-307`), `projects.Service.authorizedProject` (`lego/backend/internal/projects/service.go:293-305`), `projects.Service.authorizedSavedSearch` (`lego/backend/internal/projects/savedsearches.go:106-119`), and `projects.Service.ProjectScopeResources` (`lego/backend/internal/projects/savedsearches.go:373-384`):
    - Either route through `core.Base.ScopeByID` + leading `Authorize` (matching `envgroups.Service.authorizeGroup` and `environments.Service.scopeEnvironment`), OR on `Store == nil` and `errors.Is(err, store.ErrNotFound)` run `s.Authorize(core.WithDeferredAllowedWriteAudit(ctx), relation)` (preserving the caller verb name for `AuditDenied` while emitting zero `"success"` rows on authorized misses, coordinating with `w31/119` and `w31/122`) before returning `ErrProjectsUnavailable` / `core.ErrNotFound`.
    - Keep `AuthorizeOnOwner` / `AuthorizeApp` semantics unchanged for authorized callers (preserving ADR072's by-ID matrix and `TestProjectScopeResourcesDecisionMatrix`).
  - In `metrics.Service.resolveMetricScope` (`lego/backend/internal/metrics/project.go:109-123`): when `savedsearch.ResolveScope` returns `core.ErrNotFound` (for a project or environment scope), re-check `s.AuthorizeAs(ctx, AuditVerbMetrics, core.RelCanViewActivity)` before returning `404` so a `Billing` or unauthorized caller gets `403 FORBIDDEN` (and an `AuditDenied` row) instead of `404`.
  - In `lego/backend/internal/api/server_test.go` / `roleladder_test.go`: add a missing-ID pass (a store returning `store.ErrNotFound` for `GetDisk`, `GetProject`, `GetSavedSearch`, `GetEnvironment`) to the negative-authz / role-ladder suite so `TestAuthzGuardsEveryVerb` and `TestRoleLadder` catch any future fetch-before-authz regression.
