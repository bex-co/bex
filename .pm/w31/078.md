# 078 — Scoped API keys without `deploys_run: run` (`deploys.run`) trigger full service rebuilds and supersede queued deploys via `update_environment_variables` and `saveMode: "rebuild"` environment patches

Why: `lego/backend/internal/api/key_permission_ops.go:770,1030` maps `MCP update_environment_variables` solely to `{core.KeyServicesEnvSet}` and `REST PATCH /v1/env-groups/{id}/contents` solely to `{core.KeyEnvGroupsValuesSet}`, and neither `deploys.Service.Rebuild` (`lego/backend/internal/deploys/service.go:688-697`) nor `secrets.Service.PatchEnvironment` (`lego/backend/internal/secrets/batch.go:126-165`) / `envgroups.Service.PatchEnvironment` (`lego/backend/internal/envgroups/patch.go:388-395`) checks `core.KeyDeploysRun` — letting keys explicitly denied `Trigger and cancel deploys` trigger full service rebuild deploys (and supersede/cancel queued deploys) even with an empty `envVars: []` payload.

- **Expected / actual:**
  - **Expected:** Under `core/keygrant.go:288-292,306-314,384-388` and `key_permission_ops.go:35` ("an operation that changes two areas needs both"), `services_env` and `env_group_values` grant only setting environment-variable/secret-file values — never `"Trigger and cancel deploys"` (`core.KeyDeploysRun`, `deploys_run: run`). On Render's own MCP server, `update_environment_variables` calls `PUT /v1/services/{id}/env-vars` (`services.env.set`) AND `POST /v1/services/{id}/deploys` (`deploys.run`), so a key lacking `deploys_run: run` cannot trigger a deploy. - **Attribution:** server (`lego/backend/internal/{api,deploys,secrets,envgroups}`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:770` maps `"MCP update_environment_variables"` solely to `{core.KeyServicesEnvSet}` even though `secrets/mcp.go:176-178` unconditionally executes `s.PatchEnvironment(..., SaveMode: SaveModeRebuild)`, which invokes `s.RebuildService` (`secrets/batch.go:150`) → `deploysSvc.Rebuild` (`api/server.go:1256-1262`).
  - `lego/backend/internal/api/key_permission_ops.go:1030` maps `"REST PATCH /v1/env-groups/{id}/contents"` solely to `{core.KeyEnvGroupsValuesSet}`, and `envgroups/patch.go:388-395` invokes `s.RebuildService` (`api/server.go:1251-1255` → `deploysSvc.Rebuild`) whenever `saveMode == SaveModeRebuild` (same path shared by `MCP patch_env_group_environment` and `GQL Mutation.patchEnvGroupEnvironment`, and the sibling `secrets.Service.PatchEnvironment` path shared by `MCP patch_service_environment`, `REST PATCH /v1/services/{id}/environment`, and `GQL Mutation.patchServiceEnvironment` once `w31/050` lands).
  - `deploys.Service.Rebuild` (`lego/backend/internal/deploys/service.go:688-697`) checks only `s.AuthorizeApp(ctx, core.RelCanOperate, service)` and never calls `s.RequireKeyGrant(ctx, core.KeyDeploysRun)`.
- **Fix:**
  - In `lego/backend/internal/api/key_permission_ops.go:770`, map `"MCP update_environment_variables"` to `{core.KeyServicesEnvSet, core.KeyDeploysRun}` (matching `key_permission_ops.go:35`'s two-area rule and Render's MCP server requiring both `PUT /env-vars` and `POST /deploys`).
  - In `lego/backend/internal/secrets/batch.go:126-133` (`PatchEnvironment`) and `lego/backend/internal/envgroups/patch.go` (before mutating contents in `PatchEnvironment`), when `patch.SaveMode == SaveModeRebuild`, require `s.RequireKeyGrant(callerCtx, core.KeyDeploysRun)` before writing any secrets or triggering any rebuild (and coordinate with `w31/050` so all five `patch_*_environment` verbs enforce `{KeyServicesEnvSet|KeyEnvGroupsValuesSet}` + `KeyDeploysRun` on `saveMode: "rebuild"`).
  - As defense-in-depth, enforce `s.RequireKeyGrant(ctx, core.KeyDeploysRun)` inside `deploys.Service.Rebuild` (`lego/backend/internal/deploys/service.go:688-697`).
  - Also audit `SaveModeDeploy` (`secrets/batch.go:466`, `envgroups/patch.go:396`) and non-staged `MCP set_env_var`/`update_env_vars`/`delete_env_var`/`set_secret_file`/`delete_secret_file` (which roll pods via `rollApp` unlike REST's `WithStagedWrite`) to decide whether their config rollouts should require `KeyDeploysRun` or remain staged under `services_env` without `deploys_run`.
- **Blast radius:** `lego/backend/internal/api/key_permission_ops.go`, `lego/backend/internal/deploys/service.go`, `lego/backend/internal/secrets/batch.go`, `lego/backend/internal/envgroups/patch.go`, and scoped-key tests in `lego/backend/internal/{api,deploys,secrets,envgroups}/`. Callers with `All` keys or human sessions are unaffected; scoped keys using `saveMode: "save_only"` or REST `/v1/services/{id}/env-vars` keep working with `services_env` / `env_group_values` alone.
