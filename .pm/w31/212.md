# 212 — `registrycreds.Service.IsDeployableImage` (`GQL Query.isDeployableImage`) omits uncached `AuthorizeFresh` before reading a workspace's stored OpenBao registry password and fetches the secret before validating `imageURL` or registry-host match

Why: `registrycreds.Service.IsDeployableImage` (`lego/backend/internal/registrycreds/imagecheck.go:41-92`) authorizes only through cached `s.Authorize(ctx, core.RelCanView)` (`:49`) before reading the workspace's private registry password from OpenBao (`s.storedSecret(ctx, workspace, row.ID)` at `:65`) and dialing external container registries (`:91`) — letting a member revoked on another replica within OpenFGA's positive-decision cache TTL still authenticate to private registries with the workspace's stored secret (`codex round-15 #4`, sibling of `w31/205`) — and executes `s.storedSecret` (`:65`) before checking `store.ValidateImage(imageURL)` (`:74`) and `sameRegistryHost(credHost, host)` (`:79`), touching OpenBao unnecessarily and turning invalid/mismatched inputs into 5xx errors if the stored secret is unavailable.

- **Expected / actual:**
  - **Expected:**
    1. Whenever `credentialID != ""` causes `IsDeployableImage` to read a workspace's stored OpenBao registry password and authenticate to a remote registry on the caller's behalf, it must re-assert authorization uncached via `s.AuthorizeFresh(ctx, core.RelCanView)` (matching `codex round-15 #4` and `w31/205`'s fresh-authorization requirement before reading tenant Secrets and dialing downstream services).
    2. `store.ValidateImage(imageURL)` and `sameRegistryHost(row.Host, registryHost(imageURL))` must run **before** `s.storedSecret(ctx, workspace, row.ID)` so malformed/private-IP image URLs and wrong-host credentials never fetch the password from OpenBao (and always return `FAILURE_INVALID_INPUT_URL` / `FAILURE_INVALID_REGISTRY_CREDENTIAL` cleanly even if OpenBao is degraded).
  - **Actual:**
    1. `IsDeployableImage` (`imagecheck.go:49-65`) relies solely on cached `s.Authorize(ctx, core.RelCanView)`, allowing a member revoked within OpenFGA's positive-decision cache TTL to authenticate against private container registries using the workspace's stored OpenBao password and probe private repository/tag existence (`deployable` vs `FAILURE_DOES_NOT_EXIST` vs `FAILURE_UNSUPPORTED_PLATFORM` vs `FAILURE_IMAGE_TOO_LARGE`).
    2. `s.storedSecret` (`imagecheck.go:65`) runs before both `store.ValidateImage(imageURL)` (`:74`) and `sameRegistryHost(credHost, host)` (`:79`), reading the OpenBao secret even for invalid URLs or mismatched registry hosts (and failing with a 5xx error instead of the refusal verdict if the secret read fails).

- **Root cause:**
  - `lego/backend/internal/registrycreds/imagecheck.go:49-82` placed `s.storedSecret(ctx, workspace, row.ID)` inside the initial `if credentialID != ""` block immediately after `GetRegistryCredential` (`:61-71`) rather than validating `imageURL` and host match first, and never called `s.AuthorizeFresh(ctx, core.RelCanView)` before reading the stored secret from OpenBao.
- **Fix:**
  - In `lego/backend/internal/registrycreds/imagecheck.go`:
    1. When `credentialID != ""`, fetch metadata `row, err := s.Store.GetRegistryCredential(ctx, workspace, credentialID)` first (preserving exact `registryCredential(id)` error parity for missing/unreadable credentials, as pinned by `TestIsDeployableImageAnswersAnUnreadableCredentialAsRegistryCredentialDoes`).
    2. Run `store.ValidateImage(imageURL)` and, when `credentialID != ""`, `sameRegistryHost(row.Host, registryHost(imageURL))` **before** touching OpenBao.
    3. Immediately before `s.storedSecret(ctx, workspace, row.ID)`, call `if err := s.AuthorizeFresh(ctx, core.RelCanView); err != nil { return registryread.Verdict{}, err }` (or enforce `AuthorizeFresh` right after `s.Authorize` whenever `credentialID != ""`) so a revoked member cannot exercise the workspace's stored registry secret off a cached allow.
  - Also evaluate whether `IsDeployableImage` with a stored `credentialID` should additionally be documented or tightened if non-deploying `Viewer` members should not probe private registries with workspace credentials (keep `RelCanView` if dashboard parity requires Viewers to read `isDeployableImage`; `AuthorizeFresh` is unconditionally needed either way).
  - Surface impact: fixes GraphQL `Query.isDeployableImage` cleanly with zero breaking change to valid callers.
