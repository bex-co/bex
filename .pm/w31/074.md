# 074 — Resuming (or restarting) a configured-port tag-based image service permanently marks `undeployedChanges: true` (`historical_release`) and sets a bogus `servingImage` digest across MCP, REST, and GraphQL

Why: `deploys.Service.targetReleaseConfig` (`lego/backend/internal/deploys/rollback_config.go:49-54`) pins `spec.releaseConfig.image` to `target.ResolvedImage` (a `@sha256:…` digest) while `servesSavedImage` (`lego/operator/internal/controller/saved_configuration.go:361-384`) unconditionally returns `false` whenever `!app.Spec.HasImagePorts()`, `releaseImageSource` (`release_config_snapshot.go:922-941`) cannot inherit a tag from a non-image-port source record, and `apps.servingImage` (`lego/backend/internal/apps/service.go:1177-1182`) compares `ref.Image != a.Spec.Image` as raw strings — so calling `resume_service` (now opening a `service_resumed` deploy since `w3/m643`) or `restart_service` on any tag-based existing-image service with a configured port (or any `background_worker`/`cron_job`) permanently corrupts its status to `undeployedChanges: true`, `undeployedChangesReason: "historical_release"`, and `servingImage: "<repo>@sha256:…"` with zero saved changes or rollbacks.

- **Attribution:** operator (`lego/operator/internal/controller/{saved_configuration,release_config_snapshot}.go`) + server (`lego/backend/internal/apps/service.go`, `lego/backend/internal/deploys/rollback_config.go`)
- **Root cause:**
  - `deploys.Service.ResumeRelease` (added in `w3/m643`, `18d2615235`) and `Restart` call `targetReleaseConfig(ctx, a, target, true)` (`lego/backend/internal/deploys/rollback_config.go:49-54`), which sets `spec.releaseConfig = {Generation, SourceGeneration: target.Generation, Image: target.ResolvedImage}` where `target.ResolvedImage` is the pod's resolved digest (`docker.io/traefik/whoami@sha256:…`) rather than the saved tag (`docker.io/traefik/whoami:v1.10`).
  - In the operator, `servesSavedImage` (`lego/operator/internal/controller/saved_configuration.go:361-384`) checks `if served == app.Spec.Image { return true }` and then immediately returns `false` when `!app.Spec.HasImagePorts()` (`:365-367`). Any service with a configured port (`PortMode` not image-port) — as well as every `background_worker` and `cron_job` — cannot match a resolved digest against its saved tag, even if `recordedSource` were set.
  - Compounding that, `releaseImageSource` (`lego/operator/internal/controller/release_config_snapshot.go:922-941`) only populates `rec.spec.ImageSource` from `app.Status.ImageNetwork`/`ServingNetwork` (which are `nil` when `!app.Spec.HasImagePorts()`) or by matching `appContainerImage(rec.template) == image` on `ref.SourceGeneration` (which fails when the source generation's pod template stored the tag `:v1.10` while the resumed release's template stores the digest `@sha256:…`).
  - Because `servesSavedImage` returns `false`, `servingConfigurationDiffers` (`saved_configuration.go:331-338`) marks `different = true`, and `undeployedChangesReason` (`:397-400`) sees `ref.SourceGeneration > 0` and stamps `"historical_release"`.
  - In `bex-api`, `servingImage(a)` (`lego/backend/internal/apps/service.go:1177-1182`) returns `ref.Image` whenever `ref.Image != a.Spec.Image`, emitting the digest as a bogus `"servingImage"` override on MCP, REST, and GraphQL even when `a.Status.UndeployedChanges` is false or the digest came from `a.Spec.Image`.
- **Fix:**
  - Allow `servesSavedImage` (`lego/operator/internal/controller/saved_configuration.go:361-384`) to check `recordedSource != "" && recordedSource == app.Spec.Image` **before** the `!app.Spec.HasImagePorts()` gate (so any service kind — configured-port web/private, `background_worker`, `cron_job` — recognizes a digest resolved from `spec.image`).
  - Record and propagate the source tag on non-image-port releases:
    - When `targetReleaseConfig` (`lego/backend/internal/deploys/rollback_config.go:49-87`) builds a selected release from a target deploy whose `target.Image` (or source record's `ImageSource` / container image) was a tag resolved to `target.ResolvedImage`, or in `releaseImageSource` (`lego/operator/internal/controller/release_config_snapshot.go:922-941`) when `ref.SourceGeneration > 0` and the source record's container image is a tag in the same repository as `image` (or carries `ImageSource`, or `ReleaseConfigReference` carries the resolved-from source tag), preserve that source tag in `rec.spec.ImageSource` so `servesSavedImage` matches `app.Spec.Image` without treating genuine tag overrides (`whoami:v1.10.2` vs `whoami:v1.10`) as equal.
  - Gate `servingImage(a)` (`lego/backend/internal/apps/service.go:1177-1182`) so it does not surface a digest resolved from `a.Spec.Image` as a bogus override when `!a.Status.UndeployedChanges` (or when the active release's recorded source equals `a.Spec.Image`), while keeping genuine `image_override` and rollback-to-different-image `servingImage` projections intact.
