# 152 — `avatars.PresignedUpload` and `avatars.DeleteAvatar` record bogus `"status": "success"` workspace audit log rows on `400 AVATAR_SIZE_INVALID`, store failures, and no-op deletes

Why: `avatars.Service.owner` (`lego/backend/internal/avatars/service.go:107`) calls `s.AuthorizeWorkspace(ctx, core.RelCanManage, ownerID)` **without `core.WithDeferredAllowedWriteAudit(ctx)`**, committing an immediate `"status": "success"` workspace audit row before `PresignedUpload` validates `avatarSizeBytes` (`:151`) or inserts the upload slot (`:160`), and before `DeleteAvatar` calls `s.Store.DeleteAvatar` (`:175`, which also discards its `deleted bool` return value). Failed `AVATAR_SIZE_INVALID` requests and no-op deletes on workspaces with no avatar therefore pollute workspace audit logs with false `"success"` events, while `avatars.Service.UploadHandler` (`lego/backend/internal/avatars/http.go:50-105`) records no audit entry when an upload actually replaces the workspace avatar.

- **Attribution:** server (`lego/backend/internal/avatars/service.go`, `lego/backend/internal/avatars/http.go`)
- **Root cause:**
  - `lego/backend/internal/avatars/service.go:105-115` (`owner`) calls `s.AuthorizeWorkspace(ctx, core.RelCanManage, ownerID)` directly without `core.WithDeferredAllowedWriteAudit(ctx)`. Because `RelCanManage` is a write relation, `core.Base` writes an allowed (`"status": "success"`) audit row immediately on entry before any downstream validation or persistence.
  - `PresignedUpload` (`:146-166`) then checks `sizeBytes < 1 || sizeBytes > store.MaxAvatarBytes` (`:151`) and calls `s.Store.CreateAvatarUpload` (`:160`) after the audit row has already been committed.
  - `DeleteAvatar` (`:170-179`) discards the `deleted bool` from `s.Store.DeleteAvatar(ctx, owner)` (`:175`) and has already committed an allowed audit row before checking whether the store write succeeded or removed anything.
- **Fix:**
  - In `lego/backend/internal/avatars/service.go:107`, pass `core.WithDeferredAllowedWriteAudit(ctx)` to `s.AuthorizeWorkspace` so authorization denials are still audited immediately while allowed rows are deferred to the caller verb.
  - In `PresignedUpload` (`:146-166`), call `s.RecordAllowedWrite(ctx, "avatars.PresignedUpload", core.RelCanManage, owner.ID, "", "")` only after `CreateAvatarUpload` succeeds (and only for `owner.Kind == core.AvatarTypeWorkspace`).
  - In `DeleteAvatar` (`:170-179`), capture `deleted, err := s.Store.DeleteAvatar(ctx, owner)` and call `s.RecordAllowedWrite(ctx, "avatars.DeleteAvatar", core.RelCanManage, owner.ID, "", "")` only when `err == nil && deleted && owner.Kind == core.AvatarTypeWorkspace`.
  - Optional follow-up in `avatars/http.go` (`UploadHandler`): consider recording a workspace audit event when `PutAvatar` actually commits a workspace image (using the stored slot's subject/actor), so completed workspace avatar changes are distinguishable from abandoned presigned URLs.
