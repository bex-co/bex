# 111 — `sandbox.Service.UpdateGroupCredential` (unchanged `value`) and `RestoreGroupCredential` (current version) mint unbounded duplicate versions with identical fingerprints that `pruneSandboxCredentialVersions` never prunes

Why: `sandbox.Service.UpdateGroupCredential` (`lego/backend/internal/sandbox/credentials.go:456-462`) skips its `errCredentialNoOp` check whenever `req.Value != nil` and never checks `fp == cur.CurrentVersion.Fingerprint`, `PGStore.RestoreSandboxGroupCredential` (`lego/backend/internal/store/sandbox_credentials.go:840-900`) never checks whether the target version already matches the current configuration, and `pruneSandboxCredentialVersions` (`lego/backend/internal/store/sandbox_credentials.go:341-371`) only deletes rows whose `fingerprint NOT IN (kept_fingerprints)` — so repeated idempotent updates with the same secret value or restores of the current version mint unbounded duplicate version rows with identical fingerprints across MCP, REST, and GraphQL, inflating version history indefinitely and consuming the 1 MiB group storage cap (`version_meta_bytes`).

- **Expected vs Actual:**
  - **Expected:** Matching `UpdateGroupCredential`'s existing no-op check for config-only updates (`errCredentialNoOp`, `lego/backend/internal/sandbox/credentials.go:436-459`), an update whose resulting `(config, secretValue)` produces the exact same `fingerprint` as `cur.CurrentVersion.Fingerprint` should return the unchanged current credential without minting a duplicate version row, and restoring the already-current version (or a version with the identical current fingerprint) should either return the current version as a no-op or be rejected cleanly — and `pruneSandboxCredentialVersions` must bound duplicate rows per retained fingerprint so version history cannot grow without bound or exhaust the 1 MiB group storage cap (`SandboxCredentialMaxTotalBytes`).
  - **Actual:** Every identical-value update across MCP (`v2`), REST (`v3`), and GraphQL (`v4`) plus restoring the current version `4` (`v5`, `restoredFromVersionId: 4`) minted a brand-new version ID with the identical fingerprint `75cfaf3657ecb4d5bf43067f66d5f3e29b45a1e418d9d6769c9c74bfa3490974`. `list_sandbox_group_credential_versions` returned all 5 rows `[5, 4, 3, 2, 1]` with zero pruning.
- **Evidence:**

- **Root cause (researched):**
  - `lego/backend/internal/sandbox/credentials.go:456-462`: the no-op guard checks `if req.Value == nil && credentialConfigsEqual(merged, cur.Config)`, skipping no-op detection whenever `req.Value != nil`. Immediately below (`:461`), it computes `fp := store.SandboxCredentialFingerprint(salt, merged, secretVal)` — which hashes `(salt, canonicalConfig, secretVal)` — without checking `fp == cur.CurrentVersion.Fingerprint`.
  - `lego/backend/internal/store/sandbox_credentials.go:840-900` (`RestoreSandboxGroupCredential`): queries `next_version_id` without selecting `current_version_id` or current `fingerprint`, so restoring the already-current version unconditionally inserts a duplicate row with `restored_from_version_id = current_version_id`.
  - `lego/backend/internal/store/sandbox_credentials.go:341-371` (`pruneSandboxCredentialVersions`): deletes only `WHERE fingerprint NOT IN (SELECT fingerprint FROM kept_fingerprints)`. Because every duplicate shares `currentFingerprint` (`$4`), zero duplicate rows are ever deleted, and `checkSandboxGroupCredentialStorageCaps` (`:323-332`) sums `version_meta_bytes` across every row in `sandbox_group_credential_versions` against the 1 MiB group cap.
- **Fix direction:**
  - In `sandbox.Service.UpdateGroupCredential` (`lego/backend/internal/sandbox/credentials.go:461-462`), after computing `fp`, check `if fp == cur.CurrentVersion.Fingerprint && credentialConfigsEqual(merged, cur.Config)` and return `errCredentialNoOp` (preserving `unchangedCurrent = cur`) so re-applying the exact same config and secret value is a true no-op across MCP, REST, and GraphQL.
  - In `PGStore.RestoreSandboxGroupCredential` (`lego/backend/internal/store/sandbox_credentials.go:846-875`), select `current_version_id` and `current_fingerprint`; when `targetVersionID == currentVersionID` or `targetFingerprint == currentFingerprint`, return the unchanged current credential without minting a redundant version row (or verify against Render's restore contract if self-restore is expected to be a no-op vs `400`).
  - Also bound per-fingerprint duplicate rows in `pruneSandboxCredentialVersions` (e.g., keeping at most the latest row per kept fingerprint — or a small cap if audit lineage of historical oscillation is intentionally kept per `sandbox_credentials_test.go:223-234`) so oscillating between two values cannot exhaust `SandboxCredentialMaxTotalBytes`.
  - Surface impact: fixes MCP (`update_sandbox_group_credential`, `restore_sandbox_group_credential`), REST (`PATCH /v1/sandbox-groups/{id}/credentials/{credId}`, `POST .../restore`), and GraphQL (`updateSandboxGroupCredential`, `restoreSandboxGroupCredential`) in one shared path.
- **Blast radius:** `lego/backend/internal/sandbox/credentials.go`, `lego/backend/internal/store/sandbox_credentials.go`, and their tests (`credentials_test.go`, `credentials_contract_test.go`, `sandbox_credentials_test.go`). Note `sandbox_credentials_test.go:223-234` tests restoring a *distinct* prior version (`v2` after `v5` → `v6`), which must continue minting `v6` with `restoredFromVersionId: 2`.
