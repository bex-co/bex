# 010 — Scoped API keys (and narrow OAuth tokens) return `api_key_permission_denied` ("create a key with All") on unknown MCP tools and GraphQL root fields instead of `-32602 unknown tool` / `"Cannot query field"`

Why: `mcpBindCallWorkspace` (`lego/backend/internal/api/mcp_workspace.go:106,121`) and `graphqlHandler` (`lego/backend/internal/api/server.go:2188`) run `requireScopeClass` / `requireKeyGrant` before checking whether the requested MCP tool or GraphQL root field actually exists, so any typo or unshipped Render tool (like `select_workspace`) returns `api_key_permission_denied` telling callers to "create a key with All" instead of `-32602 unknown tool` / `"Cannot query field"`, while writing spurious `scope_class` denial audit events.

### Unknown MCP tools and unknown GraphQL root fields return `api_key_permission_denied` ("a permission no scoped API key can hold (create a key with All)") for scoped API keys

- **Severity:** major
- **Versions:** deployed pin `4b533337ab` (`7b046987bcd8`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-25, endpoints `/mcp` (`https://api.bex.co/mcp`) and `/graphql` (`https://api.bex.co/graphql`), workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), comparing a run-minted read-only scoped API key (`services:read`, `deploys:read`, `monitoring:read`, `postgres:read`, `key_value:read`, `blueprints:read`, `projects:read`, `env_groups:read`, `workspaces:read`, `agents:read`, `git:read`) against a run-minted all-permissions API key (both revoked)
- **Repro:**
  ```sh
  # 1. MCP unknown tool (and unshipped Render tool select_workspace) with a scoped key vs All key:
  python3 scripts/qa-mcp.py --key-file <scoped-key.json> call nonexistent_tool_probe '{"workspaceId":"tea-daif693dqjvc73e7as3g"}'
  python3 scripts/qa-mcp.py --key-file <scoped-key.json> call select_workspace '{}'
  python3 scripts/qa-mcp.py --key-file <all-key.json> call nonexistent_tool_probe '{"workspaceId":"tea-daif693dqjvc73e7as3g"}'
  python3 scripts/qa-mcp.py --key-file <all-key.json> call select_workspace '{}'

  # 2. GraphQL unknown Query and Mutation root fields with a scoped key vs All key:
  python3 scripts/qa-mcp.py --key-file <scoped-key.json> graphql '{ nonexistentFieldProbe }'
  python3 scripts/qa-mcp.py --key-file <scoped-key.json> graphql 'mutation { nonexistentMutationProbe }'
  python3 scripts/qa-mcp.py --key-file <all-key.json> graphql '{ nonexistentFieldProbe }'

  # 3. REST control (same scoped key returns 404 not_found, matching All key):
  python3 scripts/qa-mcp.py --key-file <scoped-key.json> rest GET '/v1/does-not-exist-probe'
  ```
- **Expected / actual:**
  - **Expected:** Per the MCP JSON-RPC specification (protocol error `-32602` for unknown tool names), GraphQL schema validation (`"Cannot query field … on type Query/Mutation"`), and bex's own REST behavior (`404 not_found` via `withScopeClassREST`), calling a nonexistent MCP tool or GraphQL root field with a scoped API key (or a narrow OAuth token such as `bex.read`) must return the exact same unknown-tool / unknown-field error as an all-permissions key — never tell the caller to `"create a key with All"` for a tool or field that does not exist, and never emit a spurious `scope_class` `denied` audit record. (Tools and fields are already discoverable via `tools/list` and GraphQL introspection by any authenticated caller, so reporting unknown names leaks no private resource existence.)
  - **Actual:**
    - MCP `/mcp` with scoped key: `nonexistent_tool_probe` and `select_workspace` both return `200` with a tool error (`isError: true`) `"api_key_permission_denied: this API key is not granted the permission this request needs: a permission no scoped API key can hold (create a key with All)"`, instead of JSON-RPC protocol error `-32602` (`"unknown tool \"...\""`) returned for the All key.
    - GraphQL `/graphql` with scoped key: `{ nonexistentFieldProbe }` and `mutation { nonexistentMutationProbe }` both return `"this API key is not granted the permission this request needs: a permission no scoped API key can hold (create a key with All)"` (`extensions: {"code": "api_key_permission_denied", "required": ["-"]}`), instead of `"Cannot query field \"...\" on type \"Query\"."` / `"Mutation"` returned for the All key.
    - REST control `GET /v1/does-not-exist-probe` with the exact same scoped key returns `404 not_found`, identical to the All key.
    - `/mcp/cloud-agents` control (`list_services` with the same scoped key) returns `"unknown tool \"list_services\" on this endpoint"` because `mcpToolsetMiddleware` runs outside `mcpWorkspaceMiddleware`.
- **Wire evidence:**

- **Attribution:** server (`lego/backend/internal/api`)
- **Root cause:**
  - `lego/backend/internal/api/mcp_workspace.go:106,121` (`mcpBindCallWorkspace`) calls `mcpRequireScope(ctx, checkScope, call.Params.Name)` before `next(...)` reaches the MCP SDK's registered-tool dispatch.
  - `lego/backend/internal/api/server.go:2188` (`graphqlHandler`) calls `s.requireGraphQLScopeFrom` before `graphql.Do` validates top-level fields against `s.schema`.
  - `lego/backend/internal/api/scope_matrix.go:144-153` (`requireKeyGrant`) defaults any `op` absent from `keyPermissionOps` to `core.KeyNoGrant` (`"a permission no scoped API key can hold (create a key with All)"`), and `gateScopeClass` (`scope_matrix.go:72-77`) defaults any `op` absent from `classifiedOps` to `core.OpClassWrite` (so a `bex.read` OAuth token also receives `insufficient_scope: requires bex.write` instead of unknown tool/field).
  - By contrast, `withScopeClassREST` (`scope_matrix.go:208-214`) checks `_, pattern := mux.Handler(r)` first and only enforces `requireScopeClass` when `pattern != ""`, so unmatched REST paths naturally fall through to `404`.
- **Fix:**
  - In `buildMCPServerFor` (`lego/backend/internal/api/server.go:2414-2441`), capture the set of actually registered tool names (or let `mcpWorkspaceMiddleware` check whether `call.Params.Name` is registered on `srv`). When `call.Params.Name` is not a registered tool, skip `mcpRequireScope` (and workspace-binding checks that would mask `-32602`, keeping `invalidMCPText` first) and let `next(...)` return the MCP SDK's `-32602 unknown tool "..."` protocol error — while continuing to fail closed (`KeyNoGrant` / `OpClassWrite`) for every real registered tool that might ever lack a table entry.
  - In `requireGraphQLScopeFrom` (`lego/backend/internal/api/scope_matrix.go:370-401`), filter `topLevelOps` against `s.schema.QueryType().Fields()` and `s.schema.MutationType().Fields()` (when `s.schema` is initialized): skip any `GQL Query.<name>` / `GQL Mutation.<name>` that does not exist on the schema so `graphql.Do` fails validation with `"Cannot query field … on type Query/Mutation"` without executing any resolver, while still checking every real root field present in the same document (so a mixed query `{ deleteService(...) nonexistentField }` is still refused by the scope gate) and still failing closed for every real schema field missing from `keyPermissionOps` / `classifiedOps`.
  - Leave `requireScopeClass` and `requireKeyGrant` themselves fail-closed on unmapped ops so unit tests calling them directly and runtime defense-in-depth for registered ops remain intact.
  - Check REST (`withScopeClassREST` already handles unmatched routes cleanly) and `/mcp/cloud-agents` (`mcpToolsetMiddleware` already rejects tools outside its toolset before `mcpWorkspaceMiddleware`).
- **Blast radius:** `lego/backend/internal/api/server.go`, `mcp_workspace.go`, `scope_matrix.go`, plus scope/key-grant tests (`scope_matrix_enforcement_test.go`, `apikey_scoped_e2e_test.go`, `key_permission_ops_test.go`). Verify mixed GraphQL documents (one real unauthorized root field + one unknown field) still fail the scope/key-grant gate rather than bypassing it.
