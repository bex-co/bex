# 226 — `mcpBindCallWorkspace` runs `takeMCPWorkspaceID` and `ValidateNamedWorkspace` before `mcpRequireScope` (bypassing permission-first refusal and audit) and echoes arbitrary `workspaceId` values verbatim

Why: `mcpBindCallWorkspace` (`lego/backend/internal/api/mcp_workspace.go:111-123`) extracts `workspaceId` and calls `base.ValidateNamedWorkspace(ctx)` before calling `mcpRequireScope`, so a scoped read-only API key (or a narrow `bex.read`/`bex.cloud_agents` OAuth token) calling an unauthorized write/sensitive tool on `/mcp` or `/mcp/cloud-agents` with a foreign, empty, or `ownerId`-bearing payload hits membership/DB checks and returns `"cannot access workspace <raw>: forbidden"` / `"workspaceId cannot be empty"` / `"ownerId is not supported..."` with zero `scope_class` denial audit events instead of `api_key_permission_denied` / `insufficient_scope`, while line 118 formats arbitrary caller-supplied `workspaceId` strings verbatim outside `mcpArgumentValueRedaction` (echoing misplaced secrets, unlike REST and GraphQL).

- **Attribution:** server (`lego/backend/internal/api`)
- **Root cause:**
  - `mcpBindCallWorkspace` (`lego/backend/internal/api/mcp_workspace.go:97-125`) checks `mcpRequireScope` immediately for `mcpCallerScopedTools` (`:105-109`), but for every workspace-scoped tool (~286 tools across `/mcp` and `/mcp/cloud-agents`) it runs `takeMCPWorkspaceID(call)` (`:111`) and `base.ValidateNamedWorkspace(ctx)` (`:117`) **before** calling `mcpRequireScope(ctx, checkScope, call.Params.Name)` (`:121`).
  - `mcp_workspace.go:118` formats `fmt.Errorf("cannot access workspace %s: %w", workspaceID, err)`, interpolating arbitrary untrusted caller strings verbatim into the error returned by `mcpWorkspaceMiddleware`, which sits **outside** `mcpArgumentValueRedaction` (`lego/backend/internal/api/server.go:2528-2529`).
- **Fix:**
  - In `mcpBindCallWorkspace` (`lego/backend/internal/api/mcp_workspace.go:105-124`), run `mcpRequireScope(ctx, checkScope, call.Params.Name)` **before** `takeMCPWorkspaceID` and `base.ValidateNamedWorkspace` (coordinating with [w31/010](010.md) so unknown tool names are checked before `mcpRequireScope` and still return `-32602`). Note that `recordScopeClassDenial` (`lego/backend/internal/api/scope_matrix.go:178-181`) already uses `base.Tenant(ctx)` with a clean fallback to `scopeAuditUnscoped`, matching REST (`withScopeClassREST` before `withCLIWorkspace`) and GraphQL (`requireGraphQLScopeFrom` before resolvers).
  - At `lego/backend/internal/api/mcp_workspace.go:118`, stop interpolating arbitrary untrusted `workspaceID` strings into the error message — return `fmt.Errorf("cannot access workspace: %w", err)` (or only include `workspaceID` when it passes `ids.KindOf(workspaceID) == ids.Workspace` with canonical `tea-` syntax, though omitting the echoed input altogether matches REST, GraphQL, and `httpmetrics_test.go:600`).
  - No REST, GraphQL, or CLI changes needed; REST (`withScopeClassREST` + `cli_workspace.go`) and GraphQL already enforce scope/key-grant first and return plain `forbidden` without echoing caller values.
