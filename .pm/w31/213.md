# 213 — `api.objectStorageAdmin.CreateAccessKey` overflows `int64` `expiresInSeconds * time.Second`, silently minting permanent never-expiring S3 access keys on `POST /v1/object-storage/{ownerId}/access-keys`

Why: `objectStorageAdmin.CreateAccessKey` (`lego/backend/internal/api/object_storage_admin.go:217-223`) checks only `if req.ExpiresInSeconds < 0` before computing `Lifetime: time.Duration(req.ExpiresInSeconds) * time.Second` (`int64` nanoseconds), leaving the upper-bound check to `AccessKeys.Create` (`lego/backend/internal/objectstorage/accesskeys.go:172-186`) after the multiplication has already wrapped modulo 2^64. Passing `expiresInSeconds: 36028797018963968` (`2^55`) wraps `time.Duration(req.ExpiresInSeconds) * time.Second` to exact `0` (`0 <= MaxEphemeralKeyLife`), which `AccessKeys.Create` treats as a **persistent, never-expiring** S3 access key (`expiresAt: null`), bypassing `MaxEphemeralKeyLife` (`12h`) and ephemeral-vs-persistent quota accounting (`MaxEphemeralAccessKeys` vs `MaxPersistentAccessKeys`). Values such as `18446744074` wrap into `(0, MaxEphemeralKeyLife]` (~290 ms) and mint an immediately-expiring key instead of returning `400 ACCESS_KEY_INVALID` — contrast `lego/backend/internal/sandbox/snapshots.go:348`, which bounds `*req.TTLSeconds > int64(maxSnapshotTTL/time.Second)` before multiplying by `time.Second`.

- **Root cause:**
