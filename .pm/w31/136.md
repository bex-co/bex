# 136 — MCP `get_deploy_hook` advertises `readOnlyHint: true` and `idempotentHint: true` despite being `OpClassMint` and lazily minting a durable bearer secret on the App CR

Why: `deploys.Service.RegisterMCP` (`lego/backend/internal/deploys/mcp.go:94-100`) registers `get_deploy_hook` without explicit `Annotations`, so `mcputil.DefaultAnnotations` (`lego/backend/internal/mcputil/mcputil.go:259-263`) classifies it from the `"get"` prefix as `ReadOnlyAnnotations()` (`readOnlyHint: true, idempotentHint: true, destructiveHint: false, openWorldHint: false`) — even though `deploys.Service.GetDeployHook` (`lego/backend/internal/deploys/deployhook.go:121-221`) is `core.OpClassMint` (`scope_matrix_ops.go:570`), lazily mints a 256-bit durable bearer secret (`dhk-…`) and patches the App CR on first call, and reveals an unauthenticated deploy-trigger credential.

### `get_deploy_hook` is the sole `OpClassMint` MCP tool advertising `readOnlyHint: true`, causing MCP hosts to auto-approve a state-mutating secret mint

- **Expected vs actual:**
  - **Expected:** Per `lego/backend/internal/mcputil/mcputil.go:211-243` (where `ReadOnlyAnnotations()` is explicitly reserved for `"a pure read tool: no state changes, idempotent, non-destructive, closed-world"` and `NonDestructiveAnnotations` explicitly documents `"credential/ticket mints"`), `get_deploy_hook` — which is classified `core.OpClassMint` (`scope_matrix_ops.go:570`), mutates Kubernetes state on first call (`s.Client.Patch` writing `bex.co/deploy-hook-token` and `bex.co/deploy-hook-token-digest` at `deployhook.go:184-221`), and returns a durable bearer credential — must NOT advertise `readOnlyHint: true`. Setting `Annotations: mcputil.NonDestructiveAnnotations(true, false)` (non-read-only, non-destructive, idempotent once minted, closed-world) ensures MCP clients that auto-approve `readOnlyHint: true` tools prompt the user before minting/revealing a deploy-hook secret.
  - **Actual:** Live `tools/list` on `/mcp` advertises `get_deploy_hook` with `{"destructiveHint": false, "idempotentHint": true, "openWorldHint": false, "readOnlyHint": true}` — making it the **only** `OpClassMint` or `OpClassWrite` tool out of all 294 `/mcp` tools (and 41 `/mcp/cloud-agents` tools) that advertises `readOnlyHint: true`.
- **Wire evidence:**
  - `POST https://api.bex.co/mcp` `tools/list` (`rndr-id: 7850d6d7-5afb-f8e8`) → `200 OK` (294 tools):
    - `get_deploy_hook`: `annotations: {"destructiveHint": false, "idempotentHint": true, "openWorldHint": false, "readOnlyHint": true}`, description: `"Get (or lazily create) a service's secret deploy-hook URL. Anyone holding the URL can trigger a deploy without an API key; treat it as a credential and do not log it. bex extension: Render exposes this only in its dashboard."`
    - Cross-check across all 294 `/mcp` tools against `scope_matrix_ops.go`: every other `readOnlyHint: true` tool is `OpClassRead` or a pure-read `OpClassSensitive` tool; `get_deploy_hook` is the sole `OpClassMint` (or `OpClassWrite`) tool advertising `readOnlyHint: true`.
- **Attribution:** server (`lego/backend/internal/deploys`, `lego/backend/internal/api`)
- **Root cause:**
  - `deploys.Service.RegisterMCP` (`lego/backend/internal/deploys/mcp.go:94-100`) leaves `mcp.Tool.Annotations` nil on `get_deploy_hook`.
  - `mcputil.AddTool` → `annotate` → `DefaultAnnotations("get_deploy_hook")` (`lego/backend/internal/mcputil/mcputil.go:259-263`) inspects only the `"get"` prefix and assigns `ReadOnlyAnnotations()` (`readOnlyHint: true`).
  - `deploys.Service.GetDeployHook` (`lego/backend/internal/deploys/deployhook.go:121-146,184-221`) explicitly documents `"on a service that never had a hook this read is itself the mint"` and patches `DeployHookTokenAnnotation` + `DeployHookTokenDigestLabel` onto the App CR; `scope_matrix_ops.go:570` already classifies `"MCP get_deploy_hook"` as `core.OpClassMint`.
  - `TestMCPAnnotationsMatchUpstream` (`lego/backend/internal/api/mcp_parity_test.go:583-636`) only checks Render's 28 shared upstream tools and non-nil pointers; no guard test asserts that `OpClassWrite` / `OpClassMint` MCP tools never advertise `ReadOnlyHint: true`.
- **Fix:**
  - In `lego/backend/internal/deploys/mcp.go:94-97`, set explicit `Annotations: mcputil.NonDestructiveAnnotations(true, false)` on `get_deploy_hook` (`ReadOnlyHint: false`, `DestructiveHint: false`, `IdempotentHint: true`, `OpenWorldHint: false`).
  - Add a guard test in `lego/backend/internal/api/` (alongside `TestMCPAnnotationsMatchUpstream` / `scope_matrix_test.go`) asserting that no MCP tool classified `core.OpClassWrite` or `core.OpClassMint` in `classifiedOps` advertises `Annotations.ReadOnlyHint == true` (and that every `core.OpClassRead` tool advertises `ReadOnlyHint == true`), so prefix-inferred annotation drift cannot recur.
  - Surface impact: MCP-only (`tools/list` behavior hints); REST `GET /v1/services/{id}/deploy-hook` and GraphQL `Query.deployHook` are unaffected.
- **Blast radius:** `lego/backend/internal/deploys/mcp.go` and a new guard test in `lego/backend/internal/api/`.
