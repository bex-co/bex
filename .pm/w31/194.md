# 194 — `POST /v1/sandboxes/{id}/exec` (`sandbox/rest.go:161`) discards all JSON decode errors via `_ = core.DecodeJSON` and omits `core.WithStrictJSONDecoding` (along with `sandbox/connect.go:270` and `accounts/rest.go:38`)

Why: Unlike `POST /v1/sandboxes` (`sandbox/rest.go:68`) and the OpenAPI-validated `POST /v1/sandboxes/{id}/runs/{operation}/token` (which reject unknown fields with `400 request body contains unknown field "..."`), `POST /v1/sandboxes/{id}/exec` (`lego/backend/internal/sandbox/rest.go:161`) executes `_ = core.DecodeJSON(r, &body)` — both omitting `core.WithStrictJSONDecoding` and silently discarding **every** JSON decode error (including syntax errors and wrong field types). Sending unknown/misspelled fields (`{"command":"echo hi","unknownField":1}`) silently proceeds into `StreamExec`, and sending malformed JSON (`{not valid json`) silently decodes an empty `command` and misreports `400 bad request: sandbox id and command are required` instead of reporting invalid JSON. Two sibling non-OpenAPI REST routes also omit `core.WithStrictJSONDecoding`: `POST /v1/sandboxes/{id}/runs/{executionId}/stream` (`sandbox/connect.go:270`) and `DELETE /v1/users` (`accounts/rest.go:38`).
