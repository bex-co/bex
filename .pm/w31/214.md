# 214 — Object storage credential mint/revoke (`CreateAccessKey`, `RevokeAccessKey`), public-bucket publishing (`SetBucketPublic`), and sensitive object reads (`GET /v1/objects/...`, `s3gw` `GetObject`/`CopyObject`) omit uncached `AuthorizeFreshOn`

Why: Across `lego/backend/`, every credential-mint (`OpClassMint`), secret/data-reveal (`OpClassSensitive`), and destructive-exposure sink re-asserts authorization uncached via `AuthorizeFresh` / `AuthorizeFreshOn` (`core/base.go:1093-1107`) so a caller whose membership or role was revoked on another replica within OpenFGA's positive-decision cache TTL cannot mint replacement credentials, expose data publicly, or download customer bytes off a stale positive (`codex round-5 F4`, `round-8 #8`, `round-15 #4`; siblings `w31/169`, `w31/178`, `w31/205`, `w31/211`, `w31/212`). None of the object-storage paths do this: `objectStorageAdmin.CreateAccessKey` (`lego/backend/internal/api/object_storage_admin.go:203`, returns plaintext S3 `Secret`), `objectStorageAdmin.RevokeAccessKey` (`:262`), `objectStorageAdmin.SetBucketPublic` (`:321`, Admin `RelCanManage` exposing bucket contents on the public internet), `renderObjects` `GET /v1/objects/{ownerId}/{region}/{key...}` (`lego/backend/internal/api/objects_render.go:126,163`, `RelCanViewSensitive` minting a presigned Wasabi download URL for customer object bytes), and `s3gw` `request.authorize` (`lego/backend/internal/s3gw/router.go:103,264-273`, `handlers_object.go:401`, `GetObject`/`CopyObject`/`UploadPartCopy` on `RelCanViewSensitive`) all authorize solely through cached `AuthorizeWorkspaceAs` / `AuthorizeWorkspaceTargetAs` and never call `AuthorizeFreshOn`.
