# 167 — `apps.parseBuildSourceFilter` and `sandbox` group-page time filters (`ListGroupSandboxes`, `GroupRuns`, `SearchSnapshots`) never reject inverted time ranges (`After > Before`), silently returning `200 []` across MCP, REST, and GraphQL

Why: Complementing `w31/155` (`events`) and `w31/159` (`agentsessions`, `webhooks`, `audit`, `deploys`, `jobs`), the remaining two packages with `After`/`Before` RFC 3339 time-range query pairs also parse both bounds via `core.ParseTime` without verifying `after <= before`: `apps.parseBuildSourceFilter` (`lego/backend/internal/apps/build_sources.go:482-495`, `createdAfter`/`createdBefore` and `updatedAfter`/`updatedBefore`) and `sandbox`'s three group-page queries (`ListGroupSandboxes` at `lego/backend/internal/sandbox/group_sandboxes.go:111-138`, `GroupRuns` at `:183-236`, and `SearchSnapshots` at `lego/backend/internal/sandbox/group_pages.go:56-82`). Callers passing an inverted window silently receive `200 []` / `{total: 0, buckets: []}` instead of `400 bad_request`, hiding swapped filter bounds across MCP (`list_build_sources`), REST (`GET /v1/build-sources`), and GraphQL (`buildSources`, `sandboxesForGroup`, `sandboxGroupRuns`, `sandboxSnapshotsForGroup`).

- **Root cause:**
  - `lego/backend/internal/apps/build_sources.go:482-495` (`parseBuildSourceFilter`, shared by MCP `list_build_sources`, REST `GET /v1/build-sources`, and GraphQL `buildSources`) parses `createdBefore`/`createdAfter` and `updatedBefore`/`updatedAfter` via `core.ParseTime` without checking `!f.CreatedAfter.IsZero() && !f.CreatedBefore.IsZero() && f.CreatedAfter.After(f.CreatedBefore)` or `!f.UpdatedAfter.IsZero() && !f.UpdatedBefore.IsZero() && f.UpdatedAfter.After(f.UpdatedBefore)`.
  - `lego/backend/internal/sandbox/group_sandboxes.go:111-138` (`ListGroupSandboxes`), `group_sandboxes.go:183-236` (`GroupRuns`), and `lego/backend/internal/sandbox/group_pages.go:56-82` (`SearchSnapshots`) receive optional `*time.Time` bounds from `timeArg` (`group_pages_surfaces.go:47-53`) and compare them per row without rejecting `after != nil && before != nil && after.After(*before)`. (Note also: `ListGroupSandboxes` at `group_sandboxes.go:112` calls `parseStatusFilter(q.Statuses)` before `s.groupSandboxes(ctx, q.GroupID)` authorizes the caller; move both status and range validation right after `s.groupSandboxes` so unauthorized callers still receive authz errors first.)
- **Fix:**
  - In `apps.Service.ListBuildSources` (`lego/backend/internal/apps/build_sources.go:523-530`, after `s.Authorize`) or `parseBuildSourceFilter` (`:482-495`, ensuring authz-before-validation is preserved): reject `CreatedAfter.After(CreatedBefore)` and `UpdatedAfter.After(UpdatedBefore)` with `core.ErrBadRequest` naming both fields.
  - In `sandbox.Service.{ListGroupSandboxes,GroupRuns}` (`lego/backend/internal/sandbox/group_sandboxes.go`) and `SearchSnapshots` (`group_pages.go`): after authorization (`s.groupSandboxes` / `s.snapshotGroup`), reject `after != nil && before != nil && after.After(*before)` with `core.ErrBadRequest` naming both fields (`createdAfter`/`createdBefore` or `endedAfter`/`endedBefore`), and move `parseStatusFilter` in `ListGroupSandboxes` below `s.groupSandboxes`.
