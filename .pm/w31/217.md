# 217 — `postgres.Service.{ExecuteQuery,Query,ListExports}` bypass protected-environment Admin enforcement (`PROTECTED_ENVIRONMENT_ADMIN_REQUIRED`), leaving a dead `"write to"` guard at `query.go:190` and exposing owner-role SQL writes/reads and full `pg_dump` download URLs to non-Admin Developers

Why: `w4/m594` (2026-11-23, `docs/ADR032-environments.md`) restricted viewing Postgres passwords and connection URLs in a protected environment to workspace Admins (`core.VerbViewCredentials` → `403 PROTECTED_ENVIRONMENT_ADMIN_REQUIRED` in `postgres/service.go:1175` and `postgres/access.go:181`), invalidating `postgres/query.go:183-188`'s older assumption that any caller with `can_create` + `can_view_sensitive` can already read the connection string. Yet three in-cluster Postgres data/dump endpoints still authenticate with the protected database's owner connection Secret (`s.databaseSecret`) or mint presigned S3 backup URLs (`s.ExportSigner.Presign`) without enforcing `core.VerbViewCredentials`: (1) `ExecuteQuery(allowWrites: true)` (`lego/backend/internal/postgres/query.go:190`) calls `s.requireUnprotected(ctx, db, "write to")`, which is a dead no-op because `core.ProtectedVerbRestricted("write to")` (`lego/backend/internal/core/confirmation.go:79-86`) returns `false` — letting a non-Admin Developer run arbitrary DDL/DML as the database owner (`DROP TABLE`, `DELETE`, or `ALTER ROLE <user> WITH PASSWORD '…'`, directly defeating `VerbViewCredentials`); (2) `Query` (`query.go:142-148`, MCP `query_render_postgres`) and `ExecuteQuery(allowWrites: false)` read all tables via the owner Secret with no `requireUnprotected` check; and (3) `ListExports` (`lego/backend/internal/postgres/recovery.go:699-767`, MCP `list_postgres_exports`, REST `GET /v1/postgres/{id}/export`, GQL `databaseExports`) mints 15-minute presigned bearer download URLs for full logical `pg_dump` backups without checking `requireUnprotected(ctx, d, core.VerbViewCredentials)`.
