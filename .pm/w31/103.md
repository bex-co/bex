# 103 — `agentsessions` unbound attachments key ownership to raw `core.SubjectFrom(ctx)` instead of the API key's creator, locking out the human creator and sibling API keys across MCP and REST

Why: `agentsessions.Service.UploadAttachment` (`lego/backend/internal/agentsessions/attachments.go:169`), `readableAttachment` (`attachments.go:305`), and session attachment binding (`lego/backend/internal/agentsessions/service.go:769,2222`) store and compare raw `core.SubjectFrom(ctx)` (which is an API key's Hydra client UUID when authenticated by API key, and the Kratos user UUID when authenticated by session cookie) instead of resolving API keys to their creator via `s.KeyCreator(ctx)`. Consequently, an unbound attachment uploaded by an API key returns `404 AGENT_ATTACHMENT_NOT_FOUND` to its own human creator's session and to other API keys minted by the same member (and vice versa), breaks session binding across callers, and multiplies the per-user unbound attachment quota per minted key.

- **Attribution:** server (`lego/backend/internal/agentsessions`)
- **Root cause:**
  - `lego/backend/internal/agentsessions/attachments.go:169` (`UploadAttachment`) writes `CreatedBy: core.SubjectFrom(ctx)` directly without resolving API-key callers through `s.KeyCreator(ctx)`.
  - `lego/backend/internal/agentsessions/attachments.go:305` (`readableAttachment`, shared by `GetAttachment`, `AttachmentInline`, `AttachmentURL`, and `DeleteAttachment`) checks `subject := core.SubjectFrom(ctx); subject == "" || subject != row.CreatedBy`.
  - `lego/backend/internal/agentsessions/service.go:769` (`Create`) and `service.go:2222` (`SendMessage` / follow-up turn) pass `Caller: core.SubjectFrom(ctx)` in `store.AgentAttachmentBinding`.
  - Because `store.BeginAgentAttachment` enforces the per-uploader unbound attachment cap grouped by `created_by`, storing the raw Hydra client UUID also creates a separate quota bucket per minted API key.
- **Fix:**
  - Add a shared helper on `agentsessions.Service` (e.g. `attachmentOwnerSubject(ctx)` or the same creator-resolution helper used for `w31/040`) that resolves API-key callers to their human creator UUID via `s.KeyCreator(ctx)` (failing closed if creator lookup fails when `KeyCreator` is configured) and falls back to `core.SubjectFrom(ctx)` for human sessions.
  - Use that resolved subject consistently in `UploadAttachment` (`attachments.go:169`), `readableAttachment` (`attachments.go:305`), and `store.AgentAttachmentBinding{Caller: ...}` (`service.go:769,2222`).
  - Surface impact: fixes `/mcp/cloud-agents`, `/mcp`, and REST `/v1/agent-attachments` (plus session creation and message attachment binding).
- **Blast radius:** `lego/backend/internal/agentsessions/attachments.go`, `lego/backend/internal/agentsessions/service.go`, and their unit/integration tests.
