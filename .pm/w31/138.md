# 138 — `apps.Service.updateStackService` and `apps.Service.DeleteDomain` bypass `checkSubdomainPolicy`, bricking live web services with `renderSubdomainPolicy: "disabled"` and zero serving hosts (`404 Not Found`) across Blueprints, MCP, REST, and GraphQL

Why: `w4/142` added `checkSubdomainPolicy` (`lego/backend/internal/apps/settings_check.go:467-486`) so `SetSubdomainPolicy` and `PATCH /v1/services/{id}` refuse disabling the platform subdomain unless the service has at least one verified custom domain (`a.Spec.Host != "" || len(a.Spec.Hosts) > 0`), yet two post-create write paths never enforce that invariant: `updateStackService` / `patchChangedStackService` (`lego/backend/internal/apps/deploy.go:4044-4132,4320-4328`) applies `renderSubdomainPolicy: "disabled"` on an existing service when the Blueprint declares only unverified domains (or drops existing verified domains), and `DeleteDomain` (`lego/backend/internal/apps/domains.go:1935-2036`) never checks `app.Spec.SubdomainPolicy == SubdomainPolicyDisabled` before removing custom domains — leaving a live running web service with zero `EffectiveHosts`, omitted `url`/`urls`, its Ingress removed, and every HTTPS request returning `404 Not Found`.

### Updating an existing service via Blueprint `deploy` with `renderSubdomainPolicy: "disabled"` + unverified domain, or deleting the last custom domain while `renderSubdomainPolicy: "disabled"`, bricks the live service into permanent `404`

  - **Expected:** Matching `checkSubdomainPolicy` (`lego/backend/internal/apps/settings_check.go:467-486`, `w4/142`) and `docs/ADR018/custom-domains.md` (`"disabled"` guarded with `400` when no verified custom hosts remain):
    1. A Blueprint update (`deploy` / `sync_blueprint` / `validate_bex_yml`) targeting an existing service must refuse `renderSubdomainPolicy: "disabled"` unless the post-update service retains at least one **verified** custom domain (rejecting both disabling the platform subdomain when only unverified domains are declared and clearing the last verified custom domain while `renderSubdomainPolicy` remains `"disabled"`).
    2. `DeleteDomain` (`delete_custom_domain`, `DELETE /v1/services/{id}/custom-domains/{domainId}`, GraphQL `deleteCustomDomain`) must refuse deleting a custom domain (including cascade-deleting a primary plus its redirecting `www.` sibling) if `app.Spec.SubdomainPolicy == "disabled"` and zero verified serving custom domains would remain, returning `400 bad request` instructing the caller to re-enable the platform subdomain first.
  - **Actual:**

- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - **Path A (`lego/backend/internal/apps/deploy.go:4044-4132,4320-4328` & `blueprint_plan.go:321-323`):** Blueprint compilation/validation checks `resolveCreateSubdomainPolicy` (`apps/service.go:4176-4185`, which looks only at `len(req.Hosts) == 0` in the manifest — also noted for creates in `w31/132`). On updates to an existing service, `updateStackService` applies `final.Spec.SubdomainPolicy = want.SubdomainPolicy` (`blueprint_plan.go:321-323`) and `patchChangedStackService` calls `replaceBlueprintDomains` (`:4325`, which runs `applyVerifiedDomainClaims` and strips unverified domains from `final.Spec.Host`/`final.Spec.Hosts`) without ever checking `s.checkSubdomainPolicy(ctx, final, final.Spec.SubdomainPolicy)` against the post-update verified serving hosts. Dropping all verified domains in a Blueprint update (`domains: []`) while `existing.Spec.SubdomainPolicy == "disabled"` has the same gap.
  - **Path B (`lego/backend/internal/apps/domains.go:1935-2036` & `:940-949`):** `DeleteDomain` never checks `app.Spec.SubdomainPolicy == appv1alpha1.SubdomainPolicyDisabled` in either the managed-claim branch (`:1961-2001`, before `s.Store.RemoveDomain`) or the storeless branch (`:2002-2035`, before `s.Client.Patch`). Removing the last verified custom domain (or a primary whose redirect cascade `goes` removes the remaining verified domain) lets `projectDomainClaims` (`:940-949`) clear `app.Spec.Host` and `app.Spec.Hosts` while `app.Spec.SubdomainPolicy` remains `"disabled"`, causing `AppSpec.EffectiveHosts` (`lego/types/v1alpha1/app_types.go:1294-1324`) to return `[]` and the operator to tear down the Ingress.
- **Fix:**
  - In `apps.Service.DeleteDomain` (`lego/backend/internal/apps/domains.go:1961-2036`), when `app.Spec.SubdomainPolicy == appv1alpha1.SubdomainPolicyDisabled`:
    - Managed-claim branch (`:1975-1986`, before `s.Store.RemoveDomain`): simulate removing `goes` from `before` and check whether any verified custom domain remains; if zero verified custom domains would remain (and the target deletion actually removes a verified domain, or leaves the service with no verified host), refuse with `core.ErrBadRequest` (reusing `s.noVerifiedDomainError` / an explicit message directing the caller to re-enable `renderSubdomainPolicy` first).
    - Storeless branch (`:2008-2022`): if `len(updated) == 0` while `app.Spec.SubdomainPolicy == appv1alpha1.SubdomainPolicyDisabled`, return the same `core.ErrBadRequest` before deleting or patching.
  - In `apps.Service.updateStackService` (`lego/backend/internal/apps/deploy.go:4044-4132`, plus Blueprint planning in `validateBlueprintService` / `planBlueprint` so `validate_bex_yml` and `plan_blueprint` catch it ahead of apply): evaluate the surviving verified serving hosts of `final` (after simulating `applyVerifiedDomainClaims` against existing verified claims that remain declared) and call `s.checkSubdomainPolicy(ctx, &probe, final.Spec.SubdomainPolicy)` before `replaceBlueprintDomains` / `persistBlueprintIntent`.
  - Surface impact: protects MCP (`deploy`, `sync_blueprint`, `validate_bex_yml`, `delete_custom_domain`), REST (`DELETE /v1/services/{id}/custom-domains/{domainId}`, Blueprint sync/validate), GraphQL (`deleteCustomDomain`, Blueprint sync/validate), and the dashboard Custom Domains UI through the single `apps.Service` layer.
