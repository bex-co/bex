# 053 — `mcpArgumentValueRedaction` misses Go MCP SDK post-schema `json: cannot unmarshal` errors, echoing misplaced secrets, adjacent JSON bytes, and Go struct names

Why: `mcpArgumentValueRedaction` (`lego/backend/internal/api/server.go:2460-2495`) only redacts SDK errors starting with `validating "arguments": `, leaving post-schema Go `json.Unmarshal` errors (`"json: cannot unmarshal ... into Go struct field ..."`) untouched — echoing misplaced secret values, adjacent sibling JSON fields from the same call, and internal Go package/struct names across MCP tools with `*time.Time` fields (`create_sandbox_snapshot`, `create_agent_automation`, `update_agent_automation`) and any integer-overflowing argument (`list_deploys`, etc.).

### Post-schema Go MCP SDK unmarshal errors bypass `mcpArgumentValueRedaction`, leaking caller values, adjacent JSON payload bytes, and internal Go struct paths

- **Attribution:** server (`lego/backend/internal/api`, with `*time.Time` MCP arg structs in `lego/backend/internal/sandbox` and `lego/backend/internal/agentsessions`)
- **Root cause:**
  - `mcpArgumentValueRedaction` (`lego/backend/internal/api/server.go:2460-2472`) delegates to `redactArgumentValue` (`server.go:2484-2495`), which returns `text` unchanged unless `strings.HasPrefix(text, "validating \"arguments\": ")` (`server.go:2485`).
  - Inside `mcp.AddTool`, the Go MCP SDK validates `req.Params.Arguments` against JSON Schema first (`validating "arguments": ...`) and then unmarshals the raw JSON into the Go input struct `In`. When a value passes JSON Schema type checks (e.g. a string for `*time.Time`, which JSON Schema represents as `{"type":"string"}`, or a huge JSON number for `int`, which JSON Schema represents as `{"type":"integer"}`) but fails `json.Unmarshal`, the SDK returns `"json: cannot unmarshal ... into Go struct field ..."` directly as an `isError: true` tool result, bypassing `redactArgumentValue`.
  - In addition, `createSnapshotArgs` (`lego/backend/internal/sandbox/snapshots_surfaces.go:194-198`) embeds `CreateSnapshotRequest` (`lego/backend/internal/sandbox/snapshots.go:169`, `ExpiresAt *time.Time`), and `createAutomationArgs`/`updateAutomationArgs` (`lego/backend/internal/agentsessions/automations_mcp.go:39-48`) embed `AgentAutomationInput` containing `AutomationSchedule` (`lego/backend/internal/agentsessions/automation_schedule.go:83,86`, `RunAt *time.Time`, `EndsAt *time.Time`), whereas GraphQL `createSandboxSnapshot` (`sandbox/snapshots_surfaces.go:166-173`) parses `expiresAt` as a string and emits `SANDBOX_SNAPSHOT_INVALID`.
- **Fix:**
  - In `redactArgumentValue` (`lego/backend/internal/api/server.go:2484-2495`), also sanitize SDK JSON unmarshal errors (`strings.HasPrefix(text, "json: ")` or `strings.HasPrefix(text, "unmarshaling \"arguments\": ")`): strip the raw JSON snippet, adjacent payload bytes, and Go package/struct/type names, keeping at most the JSON field path (extracted from the trailing `.<field>` segment after `into Go struct field ...`, e.g., `invalid argument "expiresAt": invalid value`, or `invalid arguments` if no field path is present). Keep domain tool errors untouched (the existing assertion in `graphql_error_redaction_test.go:245`).
  - Optionally, for domain-code parity with GraphQL (`sandbox/snapshots_surfaces.go:166-173`), decode `expiresAt` as a `string` in `createSnapshotArgs` and return `SANDBOX_SNAPSHOT_INVALID` on invalid RFC 3339 timestamps.
  - Surface impact: protects all 294 MCP tools on `/mcp` and `/mcp/cloud-agents` uniformly against secret echoes, adjacent-field leaks, and Go internal type disclosure on post-schema `json.Unmarshal` failures.
- **Blast radius:** `lego/backend/internal/api/server.go`, `lego/backend/internal/api/graphql_error_redaction_test.go`, and optionally `lego/backend/internal/sandbox/snapshots_surfaces.go`. Only affects MCP SDK `json:` decode errors before handlers run; normal domain tool errors are unchanged.
