- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:468,781,1071` maps `GQL Query.validateBlueprint`, `MCP validate_bex_yml`, and `REST POST /v1/blueprints/validate` to `{core.KeyBlueprintsView}` only; lines `346,703,1070` map `GQL Query.blueprintPreview`, `MCP preview_blueprint`, and `REST POST /v1/blueprints/preview` to `{core.KeyBlueprintsView, core.KeyServicesEnv}`; lines `171,702` map `GQL Mutation.planBlueprintSync` and `MCP plan_blueprint` to `{core.KeyBlueprintsManage}` only.
  - `apps.Service.blueprintValidationWithSuffix` (`lego/backend/internal/apps/blueprint.go:816-941`) calls `s.newWorkspaceSnapshot(ctx)`, `s.resolveBlueprintRegistryCredentials`, `s.validateBlueprintServices`, `s.validateBlueprintBuildSources`, `s.validateWorkspaceReferences`, `s.blueprintProtectedPlacementProblems`, `s.blueprintActionPlan`, `s.previewStackCreates`, and `s.stackAtKeptPlans` without checking `s.RequireKeyGrant` / `s.KeyGrantAllows` for `core.KeyServicesView`, `core.KeyPostgresView`, `core.KeyKeyValueView`, `core.KeyEnvGroupsView`, `core.KeyBuildSourcesView`, `core.KeyProjectsView`, or `core.KeyWorkspaceRegistry`.
  - `apps.Service.previewBlueprintWith` (`lego/backend/internal/apps/blueprint.go:1235-1321`) and `apps.Service.PlanBlueprint` (`lego/backend/internal/apps/blueprint_onboarding.go:271-297`) call `discoverBlueprintFile(ctx, s.GitFetcher, ...)` (using the workspace's GitHub App installation, which can read private repos) without requiring `core.KeyGitView`, and `previewBlueprintWith` additionally calls `s.blueprintMatchedResources` (`:1279,1329-1360`) against live workspace inventory without checking any resource view grants.
- **Fix:**
  - In `apps.Service.blueprintValidationWithSuffix` (`lego/backend/internal/apps/blueprint.go:816-931`), enforce per-family scoped API key view grants for every resource kind referenced by the compiled stack before consulting live workspace state (or fail with `s.RequireKeyGrant` for missing grants):
    - Services declared or referenced → `core.KeyServicesView` (plus `core.KeyWorkspaceRegistry` when `registryCredential` is resolved)
    - Databases declared or referenced (`fromDatabase`) → `core.KeyPostgresView`
    - Key Value declared or referenced (`fromService` to KV) → `core.KeyKeyValueView`
    - Env groups declared or referenced → `core.KeyEnvGroupsView`
    - Build sources declared or referenced → `core.KeyBuildSourcesView`
    - Projects / environments declared or referenced → `core.KeyProjectsView`
    - Decide explicitly whether `validate_bex_yml` with only `blueprints: read` should refuse with `api_key_permission_denied` naming the missing `*.view` action(s) (consistent with `w31/064` `generate_blueprint`) or run purely structural validation (`mode: "structural"`, skipping all workspace snapshot reads and `FREE_INSTANCE_LIMIT`/plan-lookup probes). Refusing missing grants on `preview_blueprint` and `plan_blueprint` is mandatory since `plan_blueprint` explicitly requires `mode: "current_state"` (`blueprint_onboarding.go:326`).
  - In `apps.Service.previewBlueprintWith` (`blueprint.go:1235-1267`) and `apps.Service.PlanBlueprint` (`blueprint_onboarding.go:271-291`), also require `core.KeyGitView` (either statically in `key_permission_ops.go` or before `discoverBlueprintFile` / `s.GitFetcher`) so a scoped key without `git: read` cannot read private GitHub repositories through Blueprint preview/plan.
  - Surface impact: protects MCP, REST, and GraphQL uniformly from one shared service layer.
