# 169 — OpenBao secret and credential mutations in `sandbox`, `agentsessions`, `registrycreds`, and `webhooks` omit uncached `AuthorizeFresh` re-authorization across MCP, REST, and GraphQL

Why: Per the codebase's `codex round-8 #8` / `round-9 #7` invariant, every durable credential and secret-store mutation must re-assert authorization uncached (`AuthorizeFresh` / `AuthorizeFreshOn` / `AuthorizeAppFresh` / `AuthorizeDatabaseFresh`) so a member revoked or demoted within OpenFGA's `PositiveTTL` cache window cannot ride a cached positive check into one last secret write, rotation, or deletion (`postgres/access.go:173`, `secrets/service.go:244,506`, `envgroups/service.go:1936`, `apikeys/service.go`, `sshkeys/service.go`, `billing/{service,billing_info}.go`, `deploys/deployhook.go`, `sandbox/{exec,file_connect}.go`, `agentsessions/{editor,ssh}.go`). Four credential/secret-mutation families omit uncached re-authorization entirely: `sandbox` group credentials (`lego/backend/internal/sandbox/credentials.go:111-124`), `agentsessions` workspace secrets (`lego/backend/internal/agentsessions/secrets.go:256-260,398-402`) and BYO model API keys (`lego/backend/internal/agentsessions/environment.go:446-455,516-518,568-573`), `registrycreds` (`lego/backend/internal/registrycreds/service.go:234-238,312-319,395-402`), and `webhooks` (`lego/backend/internal/webhooks/service.go:572-584,783-790,807-814,959-966`) — letting a recently revoked or demoted Admin/Developer create, rotate, restore, repoint, or purge OpenBao secrets and webhook signing secrets across MCP, REST, and GraphQL.

- **Expected / actual:**
  - **Expected:** Matching `postgres.createUser` (`access.go:173`), `secrets` (`service.go:244,506`, `files.go:109,132`), `envgroups` (`service.go:1936`), `apikeys`, `sshkeys`, `billing`, `deploys/deployhook.go`, `sandbox/{exec,file_connect}.go`, and `agentsessions/{editor,ssh}.go`, every verb that writes, rotates, restores, repoints, or deletes OpenBao secrets or durable signing secrets must re-assert its workspace relation uncached via `AuthorizeFresh` / `AuthorizeFreshOn` before mutating secret storage or echoing a signing secret.
  - **Actual:** All four families authorize solely through cached `s.Authorize` / `s.AuthorizeWorkspaceTarget` / `s.AuthorizeTarget`, allowing a recently revoked or demoted member to execute OpenBao secret writes/rotations/deletions or mint/repoint webhook signing secrets throughout OpenFGA's `PositiveTTL` cache window.
- **Wire evidence:**
  - Verified live MCP paths on `bex-canary` disposable group `sbg-dc4qv90jnsts73b02t90` (deleted and confirmed `404` via `get_sandbox_group`, `rndr-id: cf217971-d141-6b24`):
    - `update_sandbox_group_credential` (`rndr-id: e04e5f07-ee0a-2289`) → `200` `isError: true` (`SANDBOX_CREDENTIAL_NOT_FOUND`, proving execution reached `credentialGroup` → `s.Credentials` after cached `s.Authorize`).
    - `restore_sandbox_group_credential` (`rndr-id: d1139981-cbde-cec3`) → `200` `isError: true` (`SANDBOX_CREDENTIAL_INVALID`).
  - Code-level contrast verified across the whole backend (`git grep -l "Authorize.*Fresh" lego/backend/internal/`): `sandbox/credentials.go`, `agentsessions/{secrets,environment}.go`, `registrycreds/service.go`, and `webhooks/service.go` are absent from the `AuthorizeFresh` set despite mutating OpenBao secrets or durable signing secrets.
- **Attribution:** server (`lego/backend/internal/sandbox`, `lego/backend/internal/agentsessions`, `lego/backend/internal/registrycreds`, `lego/backend/internal/webhooks`)
- **Root cause:**
  - `lego/backend/internal/sandbox/credentials.go:111-124`: `credentialGroup` calls only cached `s.Authorize(ctx, rel)` for all four OpenBao write verbs (`CreateGroupCredential` `:289`, `UpdateGroupCredential` `:365`, `DeleteGroupCredential` `:503`, `RestoreGroupCredential` `:544`), which call `s.CredentialVault.Put`, `Delete`, and `DeleteCredentialPrefix`.
  - `lego/backend/internal/agentsessions/secrets.go:257,399`: `SetAgentSecret` and `DeleteAgentSecret` call only cached `s.AuthorizeWorkspaceTarget(ctx, core.RelCanManage, ownerID, AgentSecretAuditTarget)` before `s.ModelKeys.Put` (`:314`) and `s.ModelKeys.Delete` (`:416`).
  - `lego/backend/internal/agentsessions/environment.go:452`: `UpdateEnvironment` calls only cached `s.AuthorizeWorkspaceTarget(ctx, core.RelCanManage, ownerID, target)` even when `keyChanged` is true and writes/deletes the workspace BYO model API key in OpenBao (`s.writeModelKey` → `s.ModelKeys.Put`/`Delete` at `:516-518,568-573`).
  - `lego/backend/internal/registrycreds/service.go:236,317,400`: `Create`, `Update`, and `Delete` call only cached `s.Authorize(ctx, core.RelCanManage)` before `s.Secret.Put` (`:284`, `:375`) and `s.Secret.Delete` (`:423`).
  - `lego/backend/internal/webhooks/service.go:576,788,812,964`: `Create` (mints and returns durable HMAC signing secret), `Update` (repoints destination / echoes secret), `SetEnabled` (echoes secret), and `Delete` call only cached `s.Authorize` / `s.AuthorizeTarget(ctx, core.RelCanManage, ...)`.
- **Fix:**
  - Re-assert authorization uncached before secret/credential mutation in each family (leaving read-only metadata lists on cached `Authorize`, and keeping deferred write audit clean — coordinate with `w31/116` and `w31/117`):
    1. `sandbox/credentials.go`: in `credentialGroup` (or a write-specific helper for `CreateGroupCredential`, `UpdateGroupCredential`, `DeleteGroupCredential`, `RestoreGroupCredential`), call `s.AuthorizeFresh(ctx, rel)` (or `s.AuthorizeFreshOn(ctx, rel, core.WorkspaceObject(group.WorkspaceID))`) before writing/purging OpenBao.
    2. `agentsessions/secrets.go` & `environment.go`: call `s.AuthorizeFreshOn(ctx, core.RelCanManage, core.WorkspaceObject(workspaceID))` in `SetAgentSecret`, `DeleteAgentSecret`, and in `UpdateEnvironment` when `keyChanged` is true.
    3. `registrycreds/service.go`: call `s.AuthorizeFresh(ctx, core.RelCanManage)` in `Create`, `Update`, and `Delete`.
    4. `webhooks/service.go`: call `s.AuthorizeFresh(ctx, core.RelCanManage)` (or `s.AuthorizeFreshOn(ctx, core.RelCanManage, core.WorkspaceObject(workspaceID))`) in `Create`, `Update`, `SetEnabled`, and `Delete` (and verify `mayManageWorkspace` secret echo agrees on revoked callers).
  - Surface impact: fixes MCP, REST, and GraphQL together because all three share these service verbs.
