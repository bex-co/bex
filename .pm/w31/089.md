# 089 — MCP `list_environments` and `list_env_groups` paginate on `cursor`/`limit` yet omit `cursor` from their result envelopes

Why: `list_environments` (`lego/backend/internal/environments/mcp.go:33-37,73-90`) advertises `cursor` as `"cursor from a previous list_environments call to fetch the next page"` and `list_env_groups` (`lego/backend/internal/envgroups/mcp.go:41-44,112-132`) advertises `cursor` as `"opaque cursor from the last group in the previous page"`, yet neither `environmentsResult` nor `listEnvGroupsResult` (nor the items inside them) includes a `cursor` field — diverging from `list_projects` (`lego/backend/internal/projects/mcp.go:61-85`), `list_env_vars`, `list_secret_files`, `list_custom_domains`, and `list_jobs`, and leaving MCP agents without the cursor field the tool schema promises.

### Paged `list_environments` and `list_env_groups` responses return no `cursor` field

- **Severity:** minor
- **Area:** Environments & Environment Groups MCP pagination (`list_environments`, `list_env_groups`; sibling `list_blueprint_syncs`)
- **Surface:** MCP (`environments/mcp.go`, `envgroups/mcp.go`, `apps/mcp.go`)

- **Expected vs actual:**
  - **Expected:** Matching sibling MCP list tools (`list_projects` at `projects/mcp.go:61-85`, `list_env_vars` at `secrets/mcp.go:78-81,133-136`, `list_secret_files` at `secrets/mcp.go:98-101,220-222`, `list_custom_domains` at `apps/mcp.go:1054-1057`, `list_jobs` at `jobs/mcp.go:43-46,78-80`) and its own `cursor` parameter description (`"cursor from a previous list_environments call to fetch the next page"`), `list_environments` and `list_env_groups` (and `list_blueprint_syncs`) must include `cursor` in their result envelope when returning a paged result (e.g. `Cursor string \`json:"cursor,omitempty"\`` set to the last item's public ID when paging is requested and items are non-empty, matching `list_projects`).
  - **Actual:**
    - Control `list_projects` (`limit: 1`) returned `{"cursor": "prj-dc43lc0478dc73995bl0", "projects": [...]}`.
    - `list_environments` (`limit: 1`) returned `{"environments": [...]}` with no `cursor` key on the envelope or items.
    - `list_env_groups` (`limit: 1`) returned `{"envGroups": [...]}` with no `cursor` key on the envelope or items.

- **Root cause & blast radius:**
  - `lego/backend/internal/environments/mcp.go:73-75,82-90`: `environmentsResult` declares only `Environments []EnvironmentView`, even though `listEnvironmentsArgs.Cursor` (`:35`) promises a cursor from a previous `list_environments` call and `list_environments` computes `paged := core.StablePage(...)`.
  - `lego/backend/internal/envgroups/mcp.go:112-114,125-132`: `listEnvGroupsResult` declares only `EnvGroups []renderEnvGroup` (neither `listEnvGroupsResult` nor `renderEnvGroup` carries a `cursor` field), even though `listEnvGroupsArgs.Cursor` (`:42`) says `"opaque cursor from the last group in the previous page"`.
  - Sibling by code inspection: `lego/backend/internal/apps/mcp.go:546-550,1186-1192` (`list_blueprint_syncs`) takes `cursor` (`"opaque cursor from a prior call for pagination"`) while `listBlueprintSyncsResult` and `BlueprintSyncView` (`apps/blueprint.go:527-538`) carry no `cursor` field either. (Also minor schema typo in `secrets/mcp.go:38`: `list_secret_files` shares `serviceEnvArgs` whose `cursor` description refers to `"previous list_env_vars result"`.)
  - REST is unaffected (`GET /v1/environments`, `GET /v1/env-groups`, and `GET /v1/blueprints/{id}/syncs` wrap every item in `{<resource>, cursor}`).
- **Proposed fix:**
  - Add `Cursor string \`json:"cursor,omitempty"\`` to `environmentsResult` (`lego/backend/internal/environments/mcp.go:73-75`), `listEnvGroupsResult` (`lego/backend/internal/envgroups/mcp.go:112-114`), and `listBlueprintSyncsResult` (`lego/backend/internal/apps/mcp.go`), populating it with the last returned item's public ID when paging is requested (or whenever the page is non-empty, matching `list_projects` at `projects/mcp.go:81-83`).
