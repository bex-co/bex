# 035 — MCP `create_static_site` advertises an unsupported `image` argument (and tells callers to omit `repo` when using `image`) that `apps.Service.Create` unconditionally rejects

Why: `createStaticSiteArgs` (`lego/backend/internal/apps/mcp.go:606-607`) exposes an `image` parameter described as `"a prebuilt OCI image whose publishPath holds the built site; omit if using repo"` and instructs callers on `repo` to `"omit if using image"`, but static-site prebuilt images were removed across the backend and CRD (`w8/done/m32/done/t008.md`, `apps/service.go:3877,5611`, `lego/types/v1alpha1/app_types.go:274`) and are not part of Render's pinned `create_static_site` MCP schema — so any agent following the live MCP tool schema hits an unconditional `bad request` failure.

### `create_static_site` schema misleads MCP clients into passing an unsupported `image` field

- **Severity:** minor
- **Versions:** deployed pin `8b9d780f45` (`cdaa0a248615`, active on production during run; zero diff in `lego/backend/internal/apps/mcp.go` vs `origin/main` `6c11e8ff95`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-25, endpoint `/mcp` (`https://api.bex.co/mcp`), workspace `bex-canary` (`tea-daif693dqjvc73e7as3g`), run-minted all-permissions API key (revoked), zero-side-effect `dryRun: true` probes
- **Repro:**
  ```sh
  # 1. Inspect live schema — advertises image and tells callers to omit repo when using image:
  python3 scripts/qa-mcp.py --key-file <key.json> tools | grep -A2 create_static_site

  # 2. Follow the schema's own guidance (dryRun: true — zero writes):
  python3 scripts/qa-mcp.py --key-file <key.json> call create_static_site \
    '{"workspaceId":"tea-daif693dqjvc73e7as3g","name":"qa-dry-ss-img","image":"docker.io/library/nginx:alpine","publishPath":"/usr/share/nginx/html","dryRun":true}'

  # 3. Working control with repo (dryRun: true):
  python3 scripts/qa-mcp.py --key-file <key.json> call create_static_site \
    '{"workspaceId":"tea-daif693dqjvc73e7as3g","name":"qa-dry-ss-repo","repo":"https://github.com/render-examples/create-react-app","dryRun":true}'
  ```
- **Expected / actual:**
  - **Expected:** Matching Render's pinned `create_static_site` tool (`lego/backend/internal/api/openapi/render-mcp-tools.json`, which has no `image` field), REST `POST /v1/services` static-site details, and GraphQL `createService` (`w8/done/m32/done/t008.md`), `create_static_site` must not advertise an unusable `image` parameter or tell callers to omit `repo` in favor of `image`.
  - **Actual:** Live `tools/list` emits:
    - `repo`: `"git repository URL to build from; omit if using image"`
    - `image`: `"a prebuilt OCI image whose publishPath holds the built site; omit if using repo"`
    And passing `image` (even with `dryRun: true`) unconditionally fails with `isError: true`: `"bad request: a static_site builds from a Git repo; a prebuilt image is not supported"`.
- **Wire evidence:**
  - `POST /mcp` `tools/list` → `create_static_site.inputSchema.properties.image.description == "a prebuilt OCI image whose publishPath holds the built site; omit if using repo"` and `properties.repo.description == "git repository URL to build from; omit if using image"`.
  - `POST /mcp` `create_static_site` (`image: "docker.io/library/nginx:alpine", dryRun: true`) → `200`, `isError: true`, `"bad request: a static_site builds from a Git repo; a prebuilt image is not supported"`.
  - Control `POST /mcp` `create_static_site` (`repo: "https://github.com/render-examples/create-react-app", dryRun: true`) → `200 OK` preview.
- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `createStaticSiteArgs` (`lego/backend/internal/apps/mcp.go:606-607`) and `createStaticSiteArgs.toCreateRequest` (`:653`) still carry `Image string` and the stale `"omit if using image"` description from before `w8/done/m32/done/t008.md` prohibited prebuilt images on `static_site` in `apps.Service.Create` (`apps/service.go:3877,5611`) and the `App` CRD (`lego/types/v1alpha1/app_types.go:274`).
- **Fix:**
  - Remove `Image` from `createStaticSiteArgs` (`lego/backend/internal/apps/mcp.go:607`) and `Image: a.Image` from `toCreateRequest` (`:653`).
  - Update `Repo`'s `jsonschema` description (`lego/backend/internal/apps/mcp.go:606`) to `"git repository URL to build from"` (keep `repo` optional in JSON Schema — i.e., keep `omitempty` — so `TestMCPParity` does not report an `AddedRequired` divergence against Render's pinned `create_static_site` schema whose `required` is `["buildCommand", "name"]`).
  - Check `lego/backend/internal/apps/create_transport_guard_test.go` (`mcpCreateRules`) and `lego/backend/internal/apps/static_site_mcp_test.go` for any rule or test referencing `create_static_site`'s `image` field (`create_web_service` and `create_cron_job` still use `image`, so `mcpCreateRules["image"]` stays live for them).
- **Blast radius:** `lego/backend/internal/apps/mcp.go` (and `apps` / `api` MCP schema parity tests). Removing a field that was unconditionally rejected with `400` cannot break any working caller.
