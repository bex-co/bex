# 088 — `webhooks.parseDestination` accepts hostless port-only HTTPS URLs (`https://:443/hook`) and out-of-range TCP ports (`https://example.com:99999/hook`) across MCP, REST, and GraphQL

Why: `webhooks.parseDestination` (`lego/backend/internal/webhooks/service.go:1027-1045`) checks `u.Host == ""` instead of `u.Hostname() == ""` and never validates `u.Port()`, so Go's `net/url.Parse` lets hostless URLs (`https://:443/hook`, where `u.Host == ":443"`) and impossible TCP ports (`https://example.com:99999/hook`) save and persist as webhook destinations across MCP, REST, and GraphQL (and the same `u.Host != ""` / unvalidated-port gap exists in `core.ValidAbsoluteHTTPURL` at `lego/backend/internal/core/httpurl.go:36-40`, while `parseMaintenanceURI` and `validateExternalRedirect` also accept `:99999`).

### Syntactically invalid HTTPS URLs with empty hostname (`https://:443/hook`) or out-of-range port (`:99999`) are accepted and stored by webhook create/update

- **Severity:** minor
- **Area:** Webhooks (`create_webhook_endpoint`, `update_webhook_endpoint` / REST `POST`, `PATCH /v1/webhooks` / GraphQL `createWebhookEndpoint`, `updateWebhookEndpoint`) + shared URL helpers (`core.ValidAbsoluteHTTPURL`, `apps.parseMaintenanceURI`, `apps.validateExternalRedirect`)
- **Surface:** MCP + REST + GraphQL (shared `webhooks.parseDestination` and `core.ValidAbsoluteHTTPURL`)

- **Expected vs actual:**
  - **Expected:** `parseDestination` must reject URLs with an empty hostname (`u.Hostname() == ""`, such as `https://:443/hook`) or a port outside `1..65535` (`https://example.com:99999/hook`, `https://example.com:0/hook`) with `400` `WEBHOOK_URL_INVALID`, matching `parseMaintenanceURI` (`apps/service.go:1052`) and `validateExternalRedirect` on empty hostnames and enforcing valid TCP port bounds across all URL validators.
  - **Actual:**
    - MCP `create_webhook_endpoint` accepted both `https://:443/hook` and `https://example.com:99999/hook`, returning `200 OK` and persisting the malformed URLs.
    - REST `POST /v1/webhooks` returned `201 Created` for `https://:443/hook`, and GraphQL `createWebhookEndpoint` returned `200 OK` for `https://example.com:99999/hook`.
    - Controls `http://example.com/hook` and `https://user:pass@example.com/hook` were rejected with `WEBHOOK_URL_INVALID`.
    - Sibling probes: `create_web_service` (`dryRun: true`) rejected `maintenanceMode.uri: "https://:443/maint"` (via `parseMaintenanceURI`'s `u.Hostname() == ""`) but accepted `"https://example.com:99999/maint"`; `update_static_routes` rejected `"https://:443/api/*"` but accepted `"https://example.com:99999/api/*"` and `"https://example.com:99999/new"`.
- **Evidence (live, 2026-11-26, `bex-canary`):**
  - MCP `create_webhook_endpoint` `https://:443/hook` → `200 OK`, created `whk-dc43d9hm1rus738h0fcg` with `"url": "https://:443/hook"` (immediately deleted).

- **Root cause & blast radius:**
  - `lego/backend/internal/webhooks/service.go:1027-1045` (`parseDestination`, called by both `Create` at `:595` and `Update` at `:984`) checks `err != nil || u.Scheme != "https" || u.Host == ""`. In Go's `net/url`, `url.Parse("https://:443/hook")` succeeds with `u.Host == ":443"` and `u.Hostname() == ""`, and `url.Parse("https://example.com:99999/hook")` succeeds with `u.Port() == "99999"` because `net/url` checks only that the port consists of ASCII digits, not that it fits in `1..65535`.
  - `lego/backend/internal/core/httpurl.go:36-40` (`ValidAbsoluteHTTPURL`) has the identical `u.Host != ""` + unvalidated-port check.
  - `lego/backend/internal/apps/service.go:1046-1059` (`parseMaintenanceURI`) and `validateExternalRedirect` (`lego/backend/internal/apps/service.go`) check `u.Hostname() != ""` (so they already block `https://:443/...`), but also omit a `1..65535` port check.
- **Proposed fix:**
  - Add a small shared port helper (e.g. `validOptionalPort(port string) bool`: empty, or `strconv.Atoi(port)` in `[1, 65535]`) in `lego/backend/internal/core/httpurl.go`, update `ValidAbsoluteHTTPURL` to require `u.Hostname() != ""` and valid optional port, and update `webhooks.parseDestination` (`lego/backend/internal/webhooks/service.go:1030`) to check `u.Hostname() == ""` and valid optional port (leaving private/loopback host handling untouched per `w21/blocked/055.md`).
  - Apply the same optional port range check in `apps.parseMaintenanceURI` (`apps/service.go:1052`) and `validateExternalRedirect`.
- **Acceptance checks:**
  - Extend `TestCreateValidatesURLAndEventTypes` (`lego/backend/internal/webhooks/service_test.go:271-292`) and `Update` tests to reject `https://:443/hook`, `https://example.com:0/hook`, and `https://example.com:99999/hook` with `WEBHOOK_URL_INVALID` while still accepting `https://example.com:8443/hook`.
  - Extend `TestValidAbsoluteHTTPURL` (`lego/backend/internal/core/httpurl_test.go:21-46`) with `https://:443/x`, `https://example.com:0/x`, `https://example.com:99999/x` (`false`) and `https://example.com:8443/x` (`true`), plus regression cases for `maintenanceMode.uri` and external static routes.
  - Post-deploy live check: replay the MCP/REST/GraphQL webhook commands above and confirm all return `WEBHOOK_URL_INVALID`.
