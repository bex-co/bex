# 063 — Scoped `agents: read_write` API keys bypass `workspaces: read_write` and `agent_secrets: write` via `update_agent_environment`, mutating workspace spend caps, BYOK `modelApiKey`, and admin environment settings across MCP, REST, and GraphQL

Why: `lego/backend/internal/api/key_permission_ops.go:290,758,1019` maps `MCP update_agent_environment`, `REST PATCH /v1/agent-environment`, and `GQL Mutation.updateAgentEnvironment` solely to `{core.KeyAgentsManage}` (`agents: read_write`), and `agentsessions.Service.UpdateEnvironment` (`lego/backend/internal/agentsessions/environment.go:446-538`) performs zero `KeyGrant` checks — letting a key with only `agents: read_write` (which `spendFor` at `agentsessions/spend.go:205-210` explicitly blocks from even *reading* billing spend-cap figures for lack of `workspaces: read`, and which `set_agent_secret` refuses for lack of `agent_secrets: write`) mutate workspace-wide admin settings (`networkTier`, `customHosts`, `githubCliEnabled`, `githubCliMandatory`, `idleTimeoutMinutes`, `enabledAgents`, `enabledModels`), raise `agentModelMonthlySpendCapUsd` up to 10× the plan cap (and leak `planCapUsd`/`maxUsd` via validation errors), and overwrite or clear the workspace's OpenBao BYOK `modelApiKey`.

- **Attribution:** server (`lego/backend/internal/api` and `lego/backend/internal/agentsessions`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:290,758,1019` maps `GQL Mutation.updateAgentEnvironment`, `MCP update_agent_environment`, and `REST PATCH /v1/agent-environment` solely to `{core.KeyAgentsManage}`. Per `lego/backend/internal/core/keygrant.go:266,404`, `KeyAgentsManage` covers only Developer-level (`RelCanCreate`) session/automation/skill/repo-environment operations (`"Start, steer, and delete agent sessions; create, update, and delete automations, skills, and repository environments"`), NOT admin-only workspace settings, billing spend caps, or BYOK secret keys.
  - `agentsessions.Service.UpdateEnvironment` (`lego/backend/internal/agentsessions/environment.go:446-538`) authorizes `core.RelCanManage` (which passes whenever the key's creator is a workspace admin) and performs zero `KeyGrant` checks — unlike `spendFor` (`lego/backend/internal/agentsessions/spend.go:207`), which checks `s.KeyGrantAllows(ctx, core.KeyWorkspaceSettings)` before revealing spend-cap fields.
- **Fix:**
  - In `lego/backend/internal/api/key_permission_ops.go:290,758,1019`, require `core.KeyWorkspaceSettingsManage` (alongside `core.KeyAgentsManage`, or `{core.KeyWorkspaceSettingsManage}` matching every other workspace-admin setting in `key_permission_ops.go`) on `MCP update_agent_environment`, `REST PATCH /v1/agent-environment`, and `GQL Mutation.updateAgentEnvironment`.
  - In `agentsessions.Service.UpdateEnvironment` (`lego/backend/internal/agentsessions/environment.go:446-458`), BEFORE returning `keyErr` or running `validateSpendCap`:
    - When `input.ModelAPIKey != nil || input.ClearModelAPIKey` (`keyChanged || keyErr != nil`), call `s.RequireKeyGrant(ctx, core.KeyAgentsSecretsSet)` so overwriting or clearing the OpenBao BYOK model key requires `agent_secrets: write`.
    - When `input.AgentModelMonthlySpendCapUSD != nil || input.ResetAgentModelMonthlySpendCap`, ensure `core.KeyWorkspaceSettingsManage` is enforced before `readSpend`/`validateSpendCap` (automatically satisfied if `KeyWorkspaceSettingsManage` is required statically at the route gate, and defense-in-depth inside `UpdateEnvironment`).
  - Surface impact: protects MCP, REST, and GraphQL uniformly from one static gate + service-layer check.
- **Blast radius:** `lego/backend/internal/api/key_permission_ops.go`, `lego/backend/internal/agentsessions/environment.go`, and scoped-key tests in `lego/backend/internal/api/` and `lego/backend/internal/agentsessions/`. `All`-permission API keys and human admin sessions are completely unaffected.
