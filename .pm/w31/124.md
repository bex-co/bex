# 124 — `apps.Service.{DeleteDisk,AddDisk,RestoreDiskSnapshot}` bypass protected-environment Admin enforcement (`requireUnprotected`), and `RestoreDiskSnapshot` panics on `nil` `a.Spec.Disk`

Why: `DeleteDisk` (`lego/backend/internal/apps/disks.go:265-280`), `AddDisk` (`disks.go:113-163`), and `RestoreDiskSnapshot` (`lego/backend/internal/apps/disk_snapshots.go:211-246`) never call `s.requireUnprotected`, letting a non-Admin Developer in a protected environment destroy a service's persistent volume ("All data on the disk will be lost"), attach a paid disk, or wipe the volume via snapshot restore across MCP, REST, and GraphQL; additionally `RestoreDiskSnapshot` dereferences `a.Spec.Disk.RestoreSnapshot` at `disk_snapshots.go:237` without checking `a.Spec.Disk == nil`.

### Non-Admin Developers can destroy, attach, or wipe persistent disks in protected environments, and `RestoreDiskSnapshot` nil-dereferences `a.Spec.Disk`

- **Severity:** blocker
- **Versions:** deployed pin `918667a83f` (`410850e80281`, active during run; zero diff in `lego/backend/internal/apps/{disks.go,disk_snapshots.go}` vs `origin/main` `d51d161de8`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`
- **Context:** 2026-11-26, MCP tools `delete_disk`, `add_disk`, `restore_disk_snapshot`, REST `/v1/disks` & `/v1/disks/{diskId}/snapshots/restore`, and GraphQL `deleteDisk` / `addDisk` / `restoreDiskSnapshot`; verified by code inspection across all three surfaces (live disk creation requires a paid compute plan and was skipped under the QA free-only rule)
- **Repro:**

  ```sh
  # With a paid service carrying a persistent disk inside a protected environment,
  # authenticated as a non-Admin Developer (can_create, without workspace can_manage):
  # 1. Control — deleting the service itself is refused 403 PROTECTED_ENVIRONMENT_ADMIN_REQUIRED:
  python3 scripts/qa-mcp.py --key-file <dev-key.json> rest DELETE /v1/services/<srv-id>

  # 2. Bug — deleting the service's persistent disk succeeds 204 and destroys all disk data:
  python3 scripts/qa-mcp.py --key-file <dev-key.json> call delete_disk '{"diskId":"<dsk-id>"}'

  # 3. Bug — attaching a new disk or restoring a snapshot (irreversible wipe + restart) also succeeds:
  python3 scripts/qa-mcp.py --key-file <dev-key.json> call add_disk \
    '{"serviceId":"<srv-id>","name":"data","mountPath":"/var/data","sizeGB":10}'
  python3 scripts/qa-mcp.py --key-file <dev-key.json> call restore_disk_snapshot \
    '{"diskId":"<dsk-id>","snapshotKey":"<signed-key>"}'
  ```

- **Expected vs actual:**
  - **Expected:** Per `docs/ADR032-environments.md` and `core.ProtectedVerbRestricted` (`lego/backend/internal/core/confirmation.go:79-86`), creating or deleting resources in a protected environment — and irreversibly wiping a protected service's persistent volume — must require a fresh workspace-Admin (`can_manage`) check via `s.requireUnprotected` and refuse non-Admins with `403 PROTECTED_ENVIRONMENT_ADMIN_REQUIRED` (matching `apps.Service.Delete` at `service.go:3663` and `postgres.Service.DeletePostgres`). Additionally, `RestoreDiskSnapshot` must guard against `a.Spec.Disk == nil` (returning a clean error or reconstructing from the authoritative `disk` row) rather than panicking.
  - **Actual:**
    - `DeleteDisk` (`disks.go:265-280`) checks only `RelCanCreate` via `s.authorizeDisk`, immediately deletes the `disks` row, clears `a.Spec.Disk = nil` (destroying the PVC/data), and returns `nil` for a non-Admin Developer in a protected environment.
    - `AddDisk` (`disks.go:113-163`) checks only `RelCanCreate`, creates the `disks` row, and patches `a.Spec.Disk` for a non-Admin Developer in a protected environment.
    - `RestoreDiskSnapshot` (`disk_snapshots.go:211-246`) checks only `RelCanCreate` with no `s.requireUnprotected` guard, and at line `:237` executes `a.Spec.Disk.RestoreSnapshot = claims.Object` inside `s.patchFetched` with no `a.Spec.Disk == nil` check — panicking with a nil-pointer dereference if the App CR has not converged `spec.disk` or drifted from the `disks` table.
- **Wire evidence:** Code-traced across the shared `apps.Service` methods behind MCP (`disks.go`, `disk_snapshots.go`), REST (`POST /v1/disks`, `DELETE /v1/disks/{diskId}`, `POST /v1/disks/{diskId}/snapshots/restore`), and GraphQL (`addDisk`, `deleteDisk`, `restoreDiskSnapshot`); no paid disk fixture was created on production (per free-only QA rule). Read-only control `update_disk` on nonexistent `dsk-nonexistent0000000000` (`rndr-id: 27aa9209-586a-e552`) confirmed the deployed disk route is live (`NOT_FOUND: disk not found`).
- **Attribution:** server (`lego/backend/internal/apps`)
- **Root cause:**
  - `lego/backend/internal/apps/disks.go:113-139` (`AddDisk`): authorizes `RelCanCreate`, checks billing and `validateDisk`, and creates the disk without calling `s.requireUnprotected(ctx, a, "create")`.
  - `lego/backend/internal/apps/disks.go:265-280` (`DeleteDisk`): calls `s.authorizeDisk(..., core.RelCanCreate, diskID)` and immediately calls `s.Store.DeleteDisk` + `s.patchFetched` without calling `s.requireUnprotected(ctx, a, "delete")`.
  - `lego/backend/internal/apps/disk_snapshots.go:211-246` (`RestoreDiskSnapshot`): calls `s.authorizeDisk(..., core.RelCanCreate, diskID)` without `s.requireUnprotected(ctx, a, "delete")`, and line `:237` dereferences `a.Spec.Disk.RestoreSnapshot = claims.Object` without checking `if a.Spec.Disk == nil`.
- **Fix:**
  - Call `s.requireUnprotected(ctx, a, "delete")` in `DeleteDisk` (`disks.go:265`, immediately after `authorizeDisk`, before `Store.DeleteDisk`) and in `RestoreDiskSnapshot` (`disk_snapshots.go:211`, immediately after `authorizeDisk`, before `SnapshotSecret`/`RequireBillingMutation` or right after `SnapshotSecret` so a non-Admin Developer gets `403 PROTECTED_ENVIRONMENT_ADMIN_REQUIRED`).
  - Call `s.requireUnprotected(ctx, a, "create")` in `AddDisk` (`disks.go:113`, immediately after `AuthorizeApp` / `Store == nil` check, before billing/create).
  - In `RestoreDiskSnapshot` (`disk_snapshots.go:234-241`), guard `a.Spec.Disk == nil`: either initialize `a.Spec.Disk = &appv1alpha1.DiskSpec{Name: disk.Name, MountPath: disk.MountPath, SizeGB: disk.SizeGB}` from the authoritative `store.Disk` row (mirroring `UpdateDisk` at `disks.go:252-254`) or fail cleanly before mutating if the disk is no longer attached, so `a.Spec.Disk.RestoreSnapshot` can never panic.
  - Check whether `apps/actioncaps.go` or dashboard disk controls need any matching capability note (no breaking API contract change — `PROTECTED_ENVIRONMENT_ADMIN_REQUIRED` is already the standard coded 403 on every surface).
  - Surface impact: fixes MCP (`add_disk`, `delete_disk`, `restore_disk_snapshot`), REST, and GraphQL together because all three delegate to `apps.Service.{AddDisk,DeleteDisk,RestoreDiskSnapshot}`.
