# 020 — MCP `set_workspace_privacy`, `join_workspace`, and `join_workspace_as_admin` are uncallable because `mcpBindCallWorkspace` strips their required `workspaceId` argument and blocks non-member workspaces

Why: `set_workspace_privacy`, `join_workspace`, and `join_workspace_as_admin` each declare a required `workspaceId` tool argument targeting the organization workspace to modify or join, yet none of the three is in `mcpCallerScopedTools` — so `mcpBindCallWorkspace` rejects non-member workspaces before the handler runs (defeating `join_workspace` / `join_workspace_as_admin`) and strips `"workspaceId"` from `req.Params.Arguments` on every call, making the Go MCP SDK reject 100% of calls with `missing properties: ["workspaceId"]`.

### Calling `set_workspace_privacy`, `join_workspace`, or `join_workspace_as_admin` over MCP always fails schema validation or `ValidateNamedWorkspace`

- **Expected / actual:**

  - **Actual:**

- **Attribution:** server (`lego/backend/internal/api`, `lego/backend/internal/workspaces`, `lego/backend/internal/members`)
- **Root cause:**
  - `setWorkspacePrivacyArgs` (`lego/backend/internal/workspaces/organizations_api.go:223-226`) and `joinArgs` (`lego/backend/internal/members/organizations_api.go:221-223`) declare `WorkspaceID string` (`json:"workspaceId"`) as a required input field so the Go MCP SDK's registered JSON Schema marks `"workspaceId"` required.
  - None of `set_workspace_privacy`, `join_workspace`, or `join_workspace_as_admin` is listed in `mcpCallerScopedTools` (`lego/backend/internal/api/mcp_workspace.go:58-67`).
  - As a result, `toolsWithWorkspaceID` (`mcp_workspace.go:190-204`) strips `"workspaceId"` from the advertised `required` list and overwrites its description with `mcpWorkspaceIDDescription`, while `mcpBindCallWorkspace` (`mcp_workspace.go:111-124`) calls `takeMCPWorkspaceID` — which deletes `"workspaceId"` from `req.Params.Arguments` (`mcp_workspace.go:236`) — and calls `base.ValidateNamedWorkspace(ctx)` (`mcp_workspace.go:117`).
  - Therefore, every call either fails `ValidateNamedWorkspace` (for non-member workspaces, which is the exact target of `join_workspace` / `join_workspace_as_admin`) or fails the SDK's own `required: ["workspaceId"]` check right after `takeMCPWorkspaceID` deletes `"workspaceId"`.
  - Two tests missed this: `TestOrganizationsE2E` (`lego/backend/internal/api/organizations_e2e_test.go:249-255`) only asserted `!res.IsError` on negative `join_workspace`/`join_workspace_as_admin` calls (passing on the middleware/schema error) without testing any positive MCP call or checking the error message, and `TestNoMCPToolRegistersARequiredOwnerID` (`lego/backend/internal/api/mcp_owner_required_test.go:71`) only guarded against registered `ownerId`/`ownerID`, not registered `workspaceId`.
- **Fix:**
  - Add `set_workspace_privacy`, `join_workspace`, and `join_workspace_as_admin` to `mcpCallerScopedTools` (`lego/backend/internal/api/mcp_workspace.go:58-67`) — or verify whether every org-scoped tool (`list_organizations`, `get_organization`, `create_organization_workspace`, `list_organization_members`, `list_organization_invites`, `invite_organization_member`, `revoke_organization_invite`, `change_organization_member_role`, `remove_organization_member`) should also be caller-scoped rather than accepting an unrelated `workspaceId` (for `set_workspace_privacy`, note that an API key scoped to a workspace still needs `SetWorkspacePrivacy` to enforce workspace-key boundaries — verify `SetWorkspacePrivacy` checks `core.WorkspaceFrom` or `ValidateNamedWorkspace` / `AuthorizeOn(ctx, RelCanManage, WorkspaceObject(workspaceID))` cleanly so an API key bound to workspace A cannot change privacy of workspace B).
  - Extend `TestNoMCPToolRegistersARequiredOwnerID` (`lego/backend/internal/api/mcp_owner_required_test.go`) to also fail if any non-`mcpCallerScopedTools` tool registers a `"workspaceId"` property in its raw schema (required or optional), preventing this class of middleware/schema collision from ever recurring.
  - No REST, GraphQL, or UI contract change; MCP-only fix (GraphQL already works).
