# 104 — `list_sandbox_groups`, `list_sandbox_images`, and `list_sandbox_snapshots` (and GraphQL twins) bypass `validateListCursor` and silently return `[]` on malformed cursors where REST returns `400 invalid_cursor`

Why: `sandbox.validateListCursor` (`lego/backend/internal/sandbox/groups.go:232-241`) is wired only into the REST OpenAPI query validator (`ValidateGroupListQuery`, `ValidateBuildListQuery`, `ValidateSnapshotListQuery` via `lego/backend/internal/api/render_openapi.go:1305-1307`), never inside `Service.ListGroups`, `Service.ListImages`, or `Service.ListSnapshots`. As a result, malformed or wrong-kind cursors (such as `"not-a-cursor"`) return `400 invalid_cursor` on REST, while MCP (`list_sandbox_groups`, `list_sandbox_images`, `list_sandbox_snapshots`) and GraphQL (`sandboxGroups`, `sandboxImages`, `sandboxSnapshots`) silently succeed with an empty list `[]`.

- **Expected / actual:**
  - **Expected:** Across MCP, GraphQL, and REST, passing a malformed or wrong-prefix `cursor` to sandbox group, image, or snapshot list verbs should return the same coded `invalid_cursor` bad-request error (`"\"not-a-cursor\" is not a cursor this list issued; they look like sbg-… / sbb-… / snp-…"`) so callers distinguish a broken pagination token from an empty end-of-list page.
  - **Actual:**
    - REST rejects all three with `400 invalid_cursor`.
    - MCP returns `200` with `{"sandboxGroups":[]}`, `{"sandboxImages":[]}`, and `{"sandboxSnapshots":[]}` (`isError` absent).
    - GraphQL returns `200` with `{"data":{"sandboxGroups":[]}}`, `{"data":{"sandboxImages":[]}}`, and `{"data":{"sandboxSnapshots":[]}}`.

- **Attribution:** server (`lego/backend/internal/sandbox`)
- **Root cause:**
  - `lego/backend/internal/sandbox/groups.go:232-241` (`validateListCursor`) is called only by `ValidateGroupListQuery` (`groups.go:227`), `ValidateBuildListQuery` (`images.go:403`), and `ValidateSnapshotListQuery` (`snapshots.go:304`), which are registered only on the REST OpenAPI validator table (`lego/backend/internal/api/render_openapi.go:1305-1307`).
  - The shared service methods `ListGroups` (`lego/backend/internal/sandbox/groups.go:344`), `ListImages` (`lego/backend/internal/sandbox/images.go:825`), and `ListSnapshots` (`lego/backend/internal/sandbox/snapshots.go:543`) — called directly by MCP (`groups_surfaces.go:175`, `images_surfaces.go:214`, `snapshots_surfaces.go:245`) and GraphQL (`groups_surfaces.go:64`, `images_surfaces.go:116`, `snapshots_surfaces.go:126`) — forward `after` to the store without validating its cursor ID format.
- **Fix:**
  - Extract a string-level helper `validateCursorID(after string, kind ids.Kind) error` (reused by `validateListCursor`) and call it inside `Service.ListGroups`, `Service.ListImages`, and `Service.ListSnapshots` after authorization checks (keeping the authz-before-validation rule intact).
  - Surface impact: fixes MCP (`list_sandbox_groups`, `list_sandbox_images`, `list_sandbox_snapshots`), GraphQL (`sandboxGroups`, `sandboxImages`, `sandboxSnapshots`), and keeps REST (`400 invalid_cursor`) identical.
