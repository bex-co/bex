# 075 — Idempotent `suspend_service` and `resume_service` (and REST/GraphQL twins) still emit bogus duplicate `suspender_added` / `suspender_removed` events into the Events feed

Why: Commit `93f80f9c82` added an idempotent early-return branch to `apps.Service.setSuspended` (`lego/backend/internal/apps/service.go:6316-6319`) intending to `"log no suspension event"`, yet still calls `s.RecordAppConfigChanged(ctx, a, verb)` (`core.AuditVerbSuspend` / `core.AuditVerbResume`) — and `events.Service` (`lego/backend/internal/events/service.go:436-438`) derives `suspender_added` and `suspender_removed` service events directly from those exact `audit_events` verbs, so every redundant suspend or resume call appends a spurious event to the service's Activity / Events feed across MCP, REST, and GraphQL.

- **Attribution:** server (`lego/backend/internal/apps/service.go`, `lego/backend/internal/api/audit_origin_test.go`)
- **Root cause:**
  - `apps.Service.setSuspended` (`lego/backend/internal/apps/service.go:6288,6316-6319`) defers the authorization audit row via `core.WithDeferredAllowedWriteAudit(ctx)` and on the `a.Spec.Suspended == suspended` early-return branch calls `s.RecordAppConfigChanged(ctx, a, verb)` (`lego/backend/internal/core/audit.go:1015`), which writes an `audit_events` row with `verb = "apps.Suspend"` or `"apps.Resume"`.
  - `events.Service` (`lego/backend/internal/events/service.go:436-438`) projects every `"apps.Suspend"` audit row as `TypeSuspenderAdded` (`suspender_added`) and every `"apps.Resume"` audit row as `TypeSuspenderRemoved` (`suspender_removed`).
  - Commit `93f80f9c82` restored `s.RecordAppConfigChanged` on the no-op branch only because `TestEverySurfaceRecordsWhereTheCallerActedFrom` (`lego/backend/internal/api/audit_origin_test.go:70-96`) invokes `suspend` three consecutive times (REST, GraphQL, MCP) against the same `sampleApp("web")` without resetting `Spec.Suspended` between subtests, so the 2nd and 3rd calls hit the no-op branch.
- **Fix:**
  - Remove `s.RecordAppConfigChanged(ctx, a, verb)` from the `if a.Spec.Suspended == suspended` no-op early return in `apps.Service.setSuspended` (`lego/backend/internal/apps/service.go:6316-6319`) so idempotent no-op calls write neither a spurious `audit_events` config-change row nor a duplicate `suspender_added`/`suspender_removed` Events-feed item (matching `secrets.Service.SetEnvVar` no-op behavior).
  - Update `TestEverySurfaceRecordsWhereTheCallerActedFrom` (`lego/backend/internal/api/audit_origin_test.go:70-96`) so each surface subtest starts from a non-suspended App (or alternates suspend/resume / uses a fresh `sampleApp("web")` per subtest) — testing real state-changing writes on REST, GraphQL, and MCP rather than relying on no-op writes emitting fake suspension events.
  - (Alternatively, if workspace audit logs must still record no-op suspend/resume calls separately from the Events feed, record them under a distinct non-event-mapped verb or flag so `events/service.go:436-438` never projects them as `suspender_added`/`suspender_removed`.)
