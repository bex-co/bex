# 119 — `core.Base` `AuthorizeApp`, `AuthorizeDatabase`, and `AuthorizeKeyValue` emit `"status": "success"` audit-log rows on `404 NotFound` miss paths (and deleting Apps)

Why: On every not-found miss, `core.Base.resolveAuthorizedApp` (`lego/backend/internal/core/base.go:1521,1628,1635`) and `core.authorizeDatastore` (`lego/backend/internal/core/base.go:1915`, shared by `AuthorizeDatabase` and `AuthorizeKeyValue`) call `b.authorizeAndAudit(ctx, relation, ...)` for 403-before-404 without `core.WithDeferredAllowedWriteAudit(ctx)` and then immediately return `ErrNotFound` — and `authorizeApp` (`:1472`) checks `NotFoundIfDeleting(a)` only after `resolveAuthorizedApp` has already audited. Any non-deferred write verb called with a nonexistent (or deleting) `srv-…`, `dpg-…`, or `red-…` ID therefore returns `404 NOT_FOUND` while writing a false `"status": "success"` row into the workspace audit log across MCP, REST, and GraphQL.

- **Root cause:**
  - `lego/backend/internal/core/base.go:1521`, `:1628`, and `:1635` (`resolveAuthorizedApp`): each miss branch performs the 403-before-404 check via `b.authorizeAndAudit(ctx, relation, ..., verb, ...)` without `WithDeferredAllowedWriteAudit(ctx)`, then unconditionally returns `nil, ErrNotFound`. Because `authorizeAndRecord` (`base.go:1005`) emits `"status": "success"` whenever `err == nil && writeRelations[relation] && !readVerbs[verb] && !defersAllowedWriteAudit(ctx)`, every authorized `404` on a non-deferred write verb records a false success row.
  - `lego/backend/internal/core/base.go:1468-1475` (`authorizeApp`): calls `NotFoundIfDeleting(a)` *after* `resolveAuthorizedApp` has already called `authorizeAndAudit` and emitted `"status": "success"`.
  - `lego/backend/internal/core/base.go:1913-1919` (`authorizeDatastore`, shared by `AuthorizeDatabase` and `AuthorizeKeyValue`): on `apierrors.IsNotFound(getErr)`, calls `b.authorizeAndAudit(ctx, relation, object, target, verb, resolveErr)` without `WithDeferredAllowedWriteAudit(ctx)` and unconditionally returns `zero, ErrNotFound`.
- **Fix:**
  - In `resolveAuthorizedApp` (`base.go:1521,1628,1635`) and `authorizeDatastore` (`base.go:1915`), pass `WithDeferredAllowedWriteAudit(ctx)` to the miss-arm `authorizeAndAudit` calls so `403` denials still audit via `AuditDenied` while `404` misses never record an allowed-write `"success"` row.
  - In `authorizeApp` (`base.go:1467-1476`), defer the allowed-write audit when the resolved App is deleting (or check `NotFoundIfDeleting` before emitting the allowed-write row, preserving 403-before-404 denial auditing).
  - Surface impact: fixes MCP, REST, and GraphQL together for every `App`, `Database`, and `KeyValue` write verb on `404` and deleting-App paths.
