# 100 — `apps.normalizeHealthCheckPath` accepts malformed URLs (`%ZZ`, CR/LF, `//host/path`) across MCP, REST, and GraphQL, and `healthprobe.Check` silently falls back to probing `/` on parse failure

Why: `normalizeHealthCheckPath` (`lego/backend/internal/apps/settings_check.go:186-192`) checks only `strings.HasPrefix(trimmed, "/")` — accepting invalid percent-escapes (`/health%ZZ`), CR/LF control characters (`/health\r\nBad: 1`), whitespace, and scheme-relative URLs (`//evil.com/health`) — and `healthprobe.Check` (`lego/operator/internal/healthprobe/healthprobe.go:100-103`) ignores `url.Parse(path)` errors (`if rel, err := url.Parse(path); err == nil`), silently leaving `req.URL.Path` empty so the operator probes `GET /` instead of the configured path (marking unhealthy services Ready whenever `/` answers 2xx/3xx) and silently strips the leading `//host` prefix on scheme-relative paths.

- **Attribution:** server + operator (`lego/backend/internal/apps`, `lego/operator/internal/healthprobe`)
- **Root cause:**
  - `lego/backend/internal/apps/settings_check.go:186-192`:
    ```go
    func normalizeHealthCheckPath(path string) (string, error) {
        trimmed := strings.TrimSpace(path)
        if trimmed != "" && !strings.HasPrefix(trimmed, "/") {
            return "", fmt.Errorf("%w: health check path must start with /", core.ErrBadRequest)
        }
        return trimmed, nil
    }
    ```
    Only the leading `/` is checked; there is no control-char, whitespace, length, `//`, `#`, or `url.ParseRequestURI` validation.
  - `lego/operator/internal/healthprobe/healthprobe.go:100-103`:
    ```go
    if rel, err := url.Parse(path); err == nil {
        req.URL.Path, req.URL.RawPath, req.URL.RawQuery = rel.Path, rel.RawPath, rel.RawQuery
    }
    ```
    When `url.Parse(path)` returns an error (as for `/health%ZZ` or `/health\r\nBad: 1`), the error is discarded and `req.URL.Path` stays `""`, causing `client.Do(req)` to send `GET /`! When `path` is `//evil.com/health`, `url.Parse` treats `evil.com` as `rel.Host` and sets `req.URL.Path = "/health"`, silently probing a different path than configured.
- **Fix:**
  - In `normalizeHealthCheckPath` (`lego/backend/internal/apps/settings_check.go:186-192`): when `trimmed != ""`, reject `strings.HasPrefix(trimmed, "//")`, any ASCII control char or whitespace (`r <= 0x20 || r == 0x7f`), `#` fragments, excessive length (e.g. `> 2048` bytes), and any value that fails `url.ParseRequestURI(trimmed)` or yields a non-empty `u.Scheme`/`u.Host` or invalid query escape (`url.QueryUnescape(u.RawQuery)`).
  - In `healthprobe.Check` (`lego/operator/internal/healthprobe/healthprobe.go:100-103`): return a clear failure error (`fmt.Errorf("%s: invalid health check path", HTTPFailed)`) when `path != ""` fails `url.ParseRequestURI` (or has `rel.Host != ""` / `rel.Scheme != ""`) instead of silently falling back to `GET /`.
