# 069 — Scoped `agents: read_write` API keys bypass `workspaces: read_write` on admin-only `githubCli` security-profile bindings and `take_over_agent_automation` across MCP, REST, and GraphQL

Why: `lego/backend/internal/api/key_permission_ops.go` maps `update_agent_session` (`:210,735,1165`) and `take_over_agent_automation` (`:281,752,1054`) solely to Developer-level `{core.KeyAgentsManage}` (`agents: read_write`), and `agentsessions.Service.refuseGitHubCLIBinding` (`lego/backend/internal/agentsessions/githubcli.go:82-101`, called by `Create`, `UpdateSession`, `CreateAgentAutomation`, and `UpdateAgentAutomation`) checks only `s.CanDecisionOn(ctx, core.RelCanManage, ...)` with zero `KeyGrant` check — letting an admin-minted `agents: read_write`-only key (zero `workspaces: read_write`) take over automations and set or flip admin-only `githubCli` security-profile bindings across MCP, REST, and GraphQL.

### Admin-only `githubCli` bindings (`update_agent_session`, `create`/`update_agent_automation`, `create_agent_session`) and `take_over_agent_automation` enforce only `agents.manage`, bypassing `workspace.settings.manage`

- **Versions:** deployed pin `043827a8e8` (`2bd6e1f415d3`, active on production during run; zero diff in `lego/backend/internal/api/key_permission_ops.go`, `lego/backend/internal/agentsessions/githubcli.go`, `lego/backend/internal/agentsessions/automations.go`, and `lego/backend/internal/agentsessions/service.go` vs `origin/main` `9b91284a4a`); `serverInfo`: `bex 0.1.0`; negotiated MCP protocol: `2025-06-18`; Render MCP pin: `render-oss/render-mcp-server@a18ef3ee866716933710fa5054323fd5c1ed0eb1`

- **Expected / actual:**
  - **Expected:** Per `lego/backend/internal/core/keygrant.go:404`, `agents: read_write` (`KeyAgentsManage`) is a Developer-level (`RelCanCreate`) grant, whereas workspace-admin operations (`RelCanManage`) require `workspaces: read_write` (`core.KeyWorkspaceSettingsManage`, `requiredRole: "admin"`, `keygrant.go:366-370`), as ADR094 D3 explicitly notes for `update_agent_session` ("Only a workspace admin changes the binding… It is an admin verb, so it stays off `/mcp/cloud-agents`") and `githubcli.go:74-76` notes for every `githubCli` binding ("only a workspace admin (`can_manage`, bex's 'Manage security profiles') chooses or changes one"). A scoped `agents: read_write`-only key must receive `403 api_key_permission_denied` requiring `workspace.settings.manage` on `update_agent_session`, `take_over_agent_automation`, and any create/update that changes a `githubCli` binding (while continuing to allow creates/updates that omit or keep the stored `githubCli` binding).
  - **Actual:**
    - Control `update_billing_info` was denied with `api_key_permission_denied` (`Update workspace settings, plan, and billing`).
    - `MCP update_agent_session`, `REST PATCH /v1/agent-sessions/{id}`, and `GQL Mutation.updateAgentSession` all passed the key-permission gate and reached OpenFGA session authorization (`FORBIDDEN` on the nonexistent session ID).
    - `MCP create_agent_automation` succeeded `200 OK`, persisting `"githubCli": false` on `aut-dc3t77o3teic73bl1ud0`.
    - `MCP update_agent_automation` flipped `"githubCli"` to `true` (`200 OK`, `version: 2`), and `REST PATCH /v1/agent-automations/{id}` flipped it back to `false` (`200 OK`, `version: 3`).

- **Attribution:** server (`lego/backend/internal/api` and `lego/backend/internal/agentsessions`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:210,735,1165` maps `GQL Mutation.updateAgentSession`, `MCP update_agent_session`, and `REST PATCH /v1/agent-sessions/{id}` to `{core.KeyAgentsManage}` instead of requiring `core.KeyWorkspaceSettingsManage`.
  - `lego/backend/internal/api/key_permission_ops.go:281,752,1054` maps `GQL Mutation.takeOverAgentAutomation`, `MCP take_over_agent_automation`, and `REST POST /v1/agent-automations/{id}/take-over` to `{core.KeyAgentsManage}` instead of requiring `core.KeyWorkspaceSettingsManage`, while `TakeOverAgentAutomation` (`lego/backend/internal/agentsessions/automations.go:493`) authorizes `core.RelCanManage` (which passes via creator ceiling whenever the key's creator is a workspace admin).
  - `agentsessions.Service.refuseGitHubCLIBinding` (`lego/backend/internal/agentsessions/githubcli.go:82-101`, called from `Create` at `service.go:710`, `UpdateSession` at `githubcli.go:193`, `CreateAgentAutomation` at `automations.go:354`, and `UpdateAgentAutomation` at `automations.go:430`) probes only `s.CanDecisionOn(ctx, core.RelCanManage, core.WorkspaceObject(workspaceID)).Allowed()` and never checks `s.RequireKeyGrant(ctx, core.KeyWorkspaceSettingsManage)` (or `s.KeyGrantAllows`) when a scoped API key changes the `githubCli` binding.
- **Fix:**
  - In `lego/backend/internal/api/key_permission_ops.go`, require `core.KeyWorkspaceSettingsManage` alongside `core.KeyAgentsManage` (or `{core.KeyWorkspaceSettingsManage}` matching `w31/063`'s chosen convention for admin-only agent verbs) on `update_agent_session` (`:210,735,1165`) and `take_over_agent_automation` (`:281,752,1054`) across MCP, REST, and GraphQL.
  - In `agentsessions.Service.refuseGitHubCLIBinding` (`lego/backend/internal/agentsessions/githubcli.go:82-101`), when `!sameBinding(stored, binding)` (after or before the `RelCanManage` check), call `s.RequireKeyGrant(ctx, core.KeyWorkspaceSettingsManage)` so any scoped API key changing `agentConfig.githubCli` or `template.agentConfig.githubCli` on `create_agent_session`, `update_agent_session`, `create_agent_automation`, or `update_agent_automation` (across MCP, REST, and GraphQL) must hold `workspaces: read_write`, while creates/updates that omit or keep the stored binding continue working with `agents: read_write` alone.
  - Note: check `delete_agent_automation` / `pause_agent_automation` / `resume_agent_automation` when acting as an admin on *another member's* automation (`scopeAutomationManaged` in `automations.go`) as well, to confirm whether admin cross-owner management should follow the same rule.
  - Surface impact: protects MCP, REST, and GraphQL uniformly while preserving `agents: read_write` keys for ordinary Developer-level session and automation workflows and keeping `All` keys and human admin sessions unaffected.
- **Blast radius:** `lego/backend/internal/api/key_permission_ops.go`, `lego/backend/internal/agentsessions/githubcli.go`, plus scoped-key tests in `lego/backend/internal/api/` and `lego/backend/internal/agentsessions/`.
