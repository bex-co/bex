# 150 — Scoped `objects: read_write` API keys bypass `workspaces: read_write` on Admin-only `SetBucketPublic` (REST & GraphQL), and `SetBucketPublic` records `"status": "success"` audit rows on `404 BUCKET_NOT_FOUND`

Why: `objectStorageAdmin.SetBucketPublic` (`lego/backend/internal/api/object_storage_admin.go:317-333`) enforces Admin-only `core.RelCanManage` because publishing private customer data to the public internet requires a workspace Admin, yet `lego/backend/internal/api/key_permission_ops.go:55,63` maps both REST `PUT /v1/object-storage/{ownerId}/buckets/{bucket}/public` and GraphQL `Mutation.setObjectBucketPublic` solely to Developer-level `core.KeyObjectsManage` (`objects: read_write`, `"Upload and delete objects"`) — and `SetBucketPublic` calls `AuthorizeWorkspaceTargetAs` without `core.WithDeferredAllowedWriteAudit`, writing bogus `"status": "success"` audit rows even on `404 BUCKET_NOT_FOUND`.

- **Expected / actual:**
  - **Expected:**
    1. `PUT /v1/object-storage/{ownerId}/buckets/{bucket}/public` and `Mutation.setObjectBucketPublic` must require Admin-level `core.KeyWorkspaceSettingsManage` (`workspaces: read_write`, matching `RelCanManage`) — an `objects: read_write`-only key (`"Upload and delete objects"`, Developer role) must fail before hitting the service with `403 api_key_permission_denied`.
    2. When `SetBucketPublic` fails (`404 BUCKET_NOT_FOUND` or `SetPublic` error), it must NOT write an `"objectstorage.SetBucketPublic"` audit row with `"status": "success"`.
  - **Actual:**
    1. Both REST and GraphQL pass the API-key permission check on an admin-minted `objects: read_write`-only key and inherit the creator's `RelCanManage` via OpenFGA, allowing an object-upload/delete key to flip any private customer bucket to public read on the internet (on a nonexistent bucket, both reach `BUCKET_NOT_FOUND` instead of `api_key_permission_denied`).
    2. Both `404 BUCKET_NOT_FOUND` failures write `"event": "objectstorage.SetBucketPublic", "status": "success"` rows into the workspace audit log.

- **Attribution:** server (`lego/backend/internal/api/key_permission_ops.go` + `lego/backend/internal/api/object_storage_admin.go`)
- **Root cause:**
  - `lego/backend/internal/api/object_storage_admin.go:321` explicitly guards `SetBucketPublic` with `core.RelCanManage` (comment: *"Publishing customer data needs the workspace's admin (can_manage)"*).
  - Yet `lego/backend/internal/api/key_permission_ops.go:55` (`GQL Mutation.setObjectBucketPublic`) and `:63` (`REST PUT /v1/object-storage/{ownerId}/buckets/{bucket}/public`) require only `{core.KeyObjectsManage}`, which `lego/backend/internal/core/keygrant.go:229,347` defines as `"Upload and delete objects"` under Developer-level `objects: read_write` (`rels(RelCanViewSensitive, RelCanCreate)`).
  - Furthermore, `object_storage_admin.go:321` invokes `a.base.AuthorizeWorkspaceTargetAs` without `core.WithDeferredAllowedWriteAudit(ctx)`, so `AuthorizeWorkspaceTargetAs` commits an `"status": "success"` audit row before `a.svc.GetBucket` (`:325`) or `a.svc.SetPublic` (`:329`) runs.
- **Fix:**
  - Change `lego/backend/internal/api/key_permission_ops.go:55,63` to require `core.KeyWorkspaceSettingsManage` (either `{core.KeyObjectsManage, core.KeyWorkspaceSettingsManage}` or `{core.KeyWorkspaceSettingsManage}`, matching other workspace-Admin mutations).
  - In `lego/backend/internal/api/object_storage_admin.go:317-333`, wrap `ctx` with `core.WithDeferredAllowedWriteAudit(ctx)` before `AuthorizeWorkspaceTargetAs` and call `a.base.RecordAllowedWrite(...)` only after `a.svc.SetPublic` succeeds. (Audit sibling write methods in `object_storage_admin.go`, e.g. `RevokeAccessKey` at `:262`, for the same missing deferred-audit pattern while in the file.)
