# 147 — `postgres.Service.ParameterOverrides` leaks its own `BEGIN READ ONLY` probe transaction as `transaction_read_only = "on"` (`source: "session"`) across MCP `list_postgres_parameter_overrides`, REST, and GraphQL

Why: `w4/185` added `queryLimits.serverSettings` (`lego/backend/internal/postgres/query.go:114-119,382-387`) so `ParameterOverrides` would stop publishing its probe session's startup parameters (`statement_timeout`, `default_transaction_read_only`, `source = 'client'`), yet `runSQLQuery` (`query.go:424-428`) still wraps the `pg_settings` read in `BEGIN READ ONLY` (which sets `transaction_read_only = 'on'` with `source = 'session'`) and `sqlParameterOverrides` (`lego/backend/internal/postgres/insights.go:494-502`) filters only `WHERE source NOT IN ('default', 'override')` — causing MCP `list_postgres_parameter_overrides`, REST `GET /v1/postgres/{id}/parameter-overrides`, and GraphQL `databaseParameterOverrides` to falsely report `transaction_read_only = "on"` (`source: "session"`) on every writable Postgres database.

- **Expected / actual:**
  - **Expected:** Matching `w4/185` (`query.go:114-119`) and `list_postgres_parameter_overrides`'s tool description (`postgres/mcp.go:603`: "List non-default postgresql.conf parameters for a managed Postgres database"), `ParameterOverrides` must report only the database server's own non-default configuration — never transient `source = 'session'` / `source = 'client'` artifacts injected by `bex-api`'s own read-only introspection probe (`BEGIN READ ONLY`). On a normal writable database, `transaction_read_only = "on"` (`source: "session"`) must not appear.
  - **Actual:** All three surfaces (`MCP list_postgres_parameter_overrides`, `REST GET /v1/postgres/{id}/parameter-overrides`, and `GQL Query.databaseParameterOverrides`) return 64 rows on a brand-new writable Postgres 16 database, including:
    `{"name": "transaction_read_only", "setting": "on", "source": "session", "description": "Sets the current transaction's read-only status."}` — misleading agents and operators inspecting database configuration into believing the instance is read-only. Meanwhile `query_render_postgres` confirms `transaction_read_only` has `boot_val = "off"` and `reset_val = "off"` on the database.

- **Attribution:** server (`lego/backend/internal/postgres`)
- **Root cause:**
  - `lego/backend/internal/postgres/insights.go:494-502` defines `sqlParameterOverrides` with `WHERE source NOT IN ('default', 'override')`.
  - `ParameterOverrides` (`insights.go:882-892`) and `ParameterSpec` (`insights.go:937`) call `s.runAuthorizedInsight(ctx, db, sqlParameterOverrides, true)` (`serverSettings: true`), which skips `default_transaction_read_only` and `statement_timeout` startup params (`query.go:382-387`, fixed in `w4/185` for `source = 'client'`).
  - However, `runReadOnlyQuery` → `runSQLQuery` (`lego/backend/internal/postgres/query.go:424-428`) still executes `conn.BeginTx(ctx, pgx.TxOptions{AccessMode: pgx.ReadOnly})` (`BEGIN READ ONLY`), which causes PostgreSQL to set `transaction_read_only = 'on'` with `source = 'session'` for that probe transaction — passing straight through `source NOT IN ('default', 'override')`.
  - `TestParameterOverridesIntegration` (`lego/backend/internal/postgres/insights_test.go:547-551`) only checked `if row.Source == "client" && (row.Name == "statement_timeout" || row.Name == "default_transaction_read_only")`, missing `source == "session"` (`transaction_read_only`).
- **Fix:**
  - Update `sqlParameterOverrides` in `lego/backend/internal/postgres/insights.go:494-502` to exclude probe-local session/client sources (`WHERE source NOT IN ('default', 'override', 'session', 'client')`, since `pg_settings` rows from `'session'` or `'client'` on an ephemeral introspection connection are always artifacts of `bex-api`'s own probe connection/transaction rather than database, role, or `postgresql.conf` configuration — `ALTER DATABASE … SET` and `ALTER ROLE … SET` report `source = 'database'` / `'user'` / `'database user'`, which remain preserved).
  - Note: keep `BEGIN READ ONLY` in `runSQLQuery` so the read-only safety envelope on the probe remains intact.
  - Surface impact: fixes MCP `list_postgres_parameter_overrides`, REST `GET /v1/postgres/{id}/parameter-overrides`, GraphQL `databaseParameterOverrides`, `ParameterSpec` live observation, and the dashboard Parameters view simultaneously through the single shared SQL constant.
