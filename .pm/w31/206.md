# 206 — Pre-authorization input validation in `apps` REST service write routes (`POST /v1/services`, `PATCH /v1/services/{id}`, `PUT /v1/services/{id}/autoscaling`) and MCP `create_{web_service,cron_job,static_site}` / `create_postgres` returns `400 bad_request` instead of `403`/`404`

Why: `bex-api`'s authz-before-validation contract requires workspace/resource authorization to run before caller-supplied write fields are semantically validated so unauthorized callers (foreign workspaces, unprivileged roles, or nonexistent service IDs) receive `403 FORBIDDEN` / `404 NOT_FOUND` (and record denied audit rows) instead of `400 bad_request`. Three `apps` REST write routes not covered by `w31/182`, `202`, `203`, or `204` validate semantic field conflicts and unsupported options in `lego/backend/internal/apps/rest.go` before invoking their authorized service verbs — `POST /v1/services` (`decodeCreateService` `:1335-1346`, `toCreateRequest` `:520-730`), `PATCH /v1/services/{id}` (`patchService` `:1195-1218` and its `buildSourceId` branch `linkBuildSourcePatch` `:423-474`), and `PUT /v1/services/{id}/autoscaling` (`putAutoscaling` `:1468`) — and the sibling MCP create adapters (`apps/mcp.go:308-334,411-426,623-636` and `postgres/mcp.go:158-161`) similarly validate before `s.Create` / `s.CreatePostgres`.

- **Expected vs actual:**
  - **Expected:** JSON decoding (syntax/type shape) may reject malformed bodies first, but all semantic/business validations (field conflicts such as `autoDeploy`+`autoDeployTrigger`, `buildSourceId`+other fields, unsupported `previews`, `maintenanceMode` completeness, `setAutoscalingRequestFromRender` criteria checks, `ipAllowList` conflicts, `dockerDetails().conflict()`, `optionalInstanceCount`) must run **after** workspace/resource authorization (`s.Authorize` / `s.AuthorizeApp`), so unauthorized callers receive `403 FORBIDDEN` (with a denied audit row) and nonexistent targets return `404 NOT_FOUND`.
  - **Actual:** All three REST routes return `400 bad_request` before authorization runs, directly contradicting their own controls (`403` / `404`) and sibling service-layer validation. On MCP, `create_web_service`, `create_cron_job`, `create_static_site`, and `create_postgres` pass `mcpBindCallWorkspace` for any workspace member (including Viewers/Contributors who lack `RelCanCreate`) and then return `400 bad_request` from adapter-layer checks before `s.Create` / `s.CreatePostgres` calls `Authorize(RelCanCreate)`.

- **Fix:**
  - Defer semantic adapter checks until after authorization: either run a read-only / deferred-audit authorization preflight before semantic translation (`Authorize(core.WithDeferredAllowedWriteAudit(ctx), core.RelCanCreate)` on target `ownerID` for creates; `AuthorizeApp(core.WithDeferredAllowedWriteAudit(ctx), core.RelCanUpdate, id)` for `patchService`, `linkBuildSourcePatch`, and `putAutoscaling`), or carry the raw/unvalidated wire intent into the service method (for example, `putAutoscaling` can pass `SetAutoscalingRequest` with both targets zero into `s.SetAutoscaling`, where `autoscalingSpec` already enforces at least one criterion after `AuthorizeApp`).
  - Apply the same preflight or deferred-validation ordering to `create_web_service`, `create_cron_job`, `create_static_site`, and `create_postgres` so a workspace Viewer/Contributor receives `403 FORBIDDEN` (and a denied audit row) rather than `400 bad_request` on invalid arguments.
  - Surface impact: aligns REST (`POST /v1/services`, `PATCH /v1/services/{id}`, `PUT /v1/services/{id}/autoscaling`) and MCP (`create_web_service`, `create_cron_job`, `create_static_site`, `create_postgres`) with `bex-api`'s authz-before-validation contract.
