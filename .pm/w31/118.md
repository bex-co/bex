# 118 — MCP `list_sandbox_groups` (and siblings `list_sandbox_images`, `list_sandbox_snapshots`, `list_agent_sessions`) accept `cursor`/`limit` pagination inputs yet omit `cursor` from their result envelopes

Why: `list_sandbox_groups` (`lego/backend/internal/sandbox/groups_surfaces.go:148-155,173-177`), `list_sandbox_images` (`images_surfaces.go:172-182,212-216`), `list_sandbox_snapshots` (`snapshots_surfaces.go:208-218,243-247`), and `list_agent_sessions` (`lego/backend/internal/agentsessions/mcp.go:80-81,234-236`) all advertise `cursor` and `limit` pagination inputs, yet return bare arrays wrapped in `{sandboxGroups}` / `{sandboxImages}` / `{sandboxSnapshots}` / `{agentSessions}` with no `cursor` (or `nextCursor`) field on either the envelope or the items — diverging from REST (`GET /v1/sandbox-groups` returns `[{sandboxGroup, cursor}]`) and from sibling MCP paginated tools (`list_projects`, `list_agent_automations`, `list_agent_skill_versions`).
