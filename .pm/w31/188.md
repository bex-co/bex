# 188 — Pre-authorization input validation in `logs` and `metrics` MCP, REST, and GraphQL adapters returns `400 bad_request` instead of `403`/`404`

Why: `bex-api`'s authz-before-validation contract requires workspace/resource scope resolution and authorization (`resolveLogScope` / `resolveMetricScope` / `Authorize`) to run before caller-supplied query filters, timestamps, aggregations, or windows are validated — so unauthorized or foreign-resource callers receive `403 FORBIDDEN` / `404 NOT_FOUND` (and emit denied audit rows) instead of `400 bad_request`. Across all three surfaces, `logs` (`logs/mcp.go:143-153,195-201`, `logs/rest.go:108-122,177-185,235-243`, `logs/graphql.go:188-202,255-265`) and `metrics` (`metrics/mcp.go:266-311,410-436`, `metrics/rest.go:230-237,305-312,351-356,423-428`, `metrics/bandwidth_sources.go:97-102`, `metrics/graphql.go:392-396,453-456,466-469,499-503`) parse and validate filter types, time windows, resolutions, and aggregations before authorizing or resolving the target resources.

- **Root cause:**
  - `logs`:
    - `lego/backend/internal/logs/mcp.go:143-153` (`list_logs`) and `:195-201` (`list_log_label_values`) run `in.query()` and `s.renderWindow(&q)` before calling `s.resolveLogScope` / resource authorization.
    - `lego/backend/internal/logs/rest.go:108-122` (`GET /v1/logs`), `:177-185` (`GET /v1/logs/values`), and `:235-243` (`GET /v1/logs/stream`) call `parseLogParams(r)` and `s.renderWindow(&q)` before `resolveLogScope`.
    - `lego/backend/internal/logs/graphql.go:188-202` (`Query.logs`) and `:255-265` (`Query.logLabelValues`) call `logQueryFromArgs(p.Args)` and `s.renderWindow(&q)` before `resolveLogScope`.
  - `metrics`:
    - `lego/backend/internal/metrics/mcp.go:266-311` (`get_metrics`) and `:410-436` (`get_datastore_metrics`) validate `startTime`, `endTime`, `resolutionSeconds`, `aggregateBy`, and metric types before `resolveMetricScope` / target authorization.
    - `lego/backend/internal/metrics/rest.go:230-237` (`applicationFilters`/`httpFilters`), `:305-312` (`pathFilters`), `:351-356` (metric series endpoints), `:423-428` (`activeConnectionsQuery`), and `lego/backend/internal/metrics/bandwidth_sources.go:97-102` (`bandwidthSources`) call `parseTimeWindow`/`parseMetricParams` before `resolveMetricScope`.
    - `lego/backend/internal/metrics/graphql.go:392-396` (`Query.metrics`), `:453-469` (`Query.datastoreMetrics`), and `:499-503` (`Query.metricFilters`) parse timestamps/options before `resolveMetricScope` / target authorization.
- **Fix:**
  - Split scope extraction (`ScopeRequest` from `ownerId`/`resource`/`project`/`environment`/`region`) from filter/time-window parsing in both `logs` and `metrics` so every MCP, REST, and GraphQL handler runs `resolveLogScope` / `resolveMetricScope` (and its workspace/resource `Authorize` check) **first**, and only then parses and validates `type`, `startTime`/`endTime`/`renderWindow`, `resolutionSeconds`, `aggregationMethod`, `groupBy`, and `quantiles`.
  - For `metrics/rest.go` and `metrics/graphql.go` handlers whose scope filter predicate depends on the requested metric (`keepMetricResource(metric)`), validate only the path/route-selected metric identity or run workspace `Authorize(RelCanView)` before validating caller-supplied filter arguments.
