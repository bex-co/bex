# 174 — Scoped `services: read_write`-only API keys (zero `services_env: read`) bypass `services.env.view` via `POST /v1/services/{id}/shell-ticket`, GraphQL `createShellSession`, and native SSH (`apps.ShellKeyAction`), and `CreateShellSession` omits `AuthorizeAppFresh`

Why: `scope_matrix_overrides.go:25,144-145` and `apps.Service.CreateShellSession` (`lego/backend/internal/apps/service.go:2055-2060`) both document that an interactive service shell yields arbitrary command execution inside the pod (`printenv` and `/etc/secrets/*`) and therefore equals `can_view_sensitive` (`OpClassSensitive`), yet `keyPermissionOps` (`lego/backend/internal/api/key_permission_ops.go:115,1167`), `apps.ShellKeyAction` (`apps/service.go:2030`), and native SSH (`sshgateway/nativessh/server.go:1041`) enforce only `core.KeyServicesJobs` (which `services: read_write` bundles without `services_env: read`) — and `CreateShellSession` authorizes only through cached `s.AuthorizeApp` rather than uncached `AuthorizeAppFresh`.

### Service shell ticket mint and native SSH bypass `services.env.view` (`services_env: read`) on scoped `services: read_write`-only API keys

- **Attribution:** server (`lego/backend/internal/api`, `lego/backend/internal/apps`, `lego/backend/internal/sshgateway`)
- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:115,1167` maps `GQL Mutation.createShellSession` and `REST POST /v1/services/{id}/shell-ticket` solely to `{core.KeyServicesJobs}`, which `core.KeyPermissionCatalog` (`lego/backend/internal/core/keygrant.go:286`) bundles inside `services: read_write` without `core.KeyServicesEnv` (`services_env: read`).
  - `lego/backend/internal/apps/service.go:2030,2090` defines `ShellKeyAction = core.KeyServicesJobs` (a single action carried in `shellticket.Claims.KeyAction` and re-checked by `sshgateway/webshell`), and `lego/backend/internal/sshgateway/nativessh/server.go:1041` checks only `string(apps.ShellKeyAction)` for service SSH — neither requires `core.KeyServicesEnv` (`services.env.view`), so even live stream revalidation never notices when `services_env: read` is missing or revoked.
  - `lego/backend/internal/apps/service.go:2060` authorizes `CreateShellSession` via cached `s.AuthorizeApp(ctx, core.RelCanViewSensitive, name)` and never calls `s.AuthorizeAppFresh(ctx, core.RelCanViewSensitive, a)` before `shellticket.Mint` (`:2086`), unlike sibling credential/ticket mints (`sandbox/file_connect.go:134`, `postgres/recovery.go:710`, `deploys/deployhook.go`).
- **Fix:**
  - In `lego/backend/internal/api/key_permission_ops.go:115,1167`, require `{core.KeyServicesJobs, core.KeyServicesEnv}` on both `GQL Mutation.createShellSession` and `REST POST /v1/services/{id}/shell-ticket`.
  - Hold live shell and native SSH streams to **both** `core.KeyServicesJobs` and `core.KeyServicesEnv` (either extend `KeyGrantGate` / `shellticket.Claims` to support checking a slice of required actions or require `KeyServicesEnv` alongside `KeyServicesJobs` in `webshell` and `nativessh/server.go:1037-1050` — coordinate with `w31/168` which has the parallel `KeySandboxesExec` + `KeyAgentsManage` requirement for agent-session shells).
  - In `lego/backend/internal/apps/service.go:2060`, add `if err := s.AuthorizeAppFresh(ctx, core.RelCanViewSensitive, a); err != nil { return ShellSessionView{}, err }` before minting the shell ticket.
  - Surface impact: enforces `services_env: read` consistently across REST `POST /v1/services/{id}/shell-ticket`, GraphQL `createShellSession`, Web Shell stream revalidation, and native SSH while keeping `All` keys and human sessions unaffected.
