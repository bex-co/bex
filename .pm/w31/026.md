# 026 — `AgentSkillVersion` never validates `version >= 1`, so MCP `get_agent_skill_version` and GraphQL `agentSkillVersion` return misleading `AGENT_SKILL_VERSION_NOT_FOUND` instead of REST's `400 AGENT_SKILL_INVALID`

Why: `GET /v1/agent-skills/{ref}/versions/{version}` (`lego/backend/internal/agentsessions/rest.go:333-339`) checks `version < 1` in the REST handler alone and returns `400 AGENT_SKILL_INVALID`, whereas `Service.AgentSkillVersion` (`lego/backend/internal/agentsessions/skills_versions.go:137-148`) skips that check — so MCP `get_agent_skill_version` (on both `/mcp` and `/mcp/cloud-agents`) and GraphQL `agentSkillVersion` query Postgres for `0` or `-1` and answer `AGENT_SKILL_VERSION_NOT_FOUND` ("it may have been dropped by the 200-version retention"), contradicting REST and misleading callers about invalid input.

- **Attribution:** server (`lego/backend/internal/agentsessions`)
- **Root cause:**
  - `lego/backend/internal/agentsessions/rest.go:333-339` checks `if err != nil || version < 1 { return nil, skillInvalid("version", "version is a positive whole number") }` inside the REST handler before calling `s.AgentSkillVersion`.
  - `lego/backend/internal/agentsessions/skills_versions.go:137-148` (`Service.AgentSkillVersion`) does not check `version < 1`; it passes `version` straight to `s.Skills.GetAgentSkillVersion(ctx, row.ID, version)` and maps `store.ErrNotFound` to `errSkillVersionNotFound(ref, version)`.
  - Both MCP (`lego/backend/internal/agentsessions/mcp.go:401`) and GraphQL (`lego/backend/internal/agentsessions/skills_graphql.go:198`) call `s.AgentSkillVersion` directly with the integer argument and never validate `version < 1`.
- **Fix:**
  - Add `if version < 1 { return AgentSkillVersion{}, skillInvalid("version", "version is a positive whole number") }` inside `Service.AgentSkillVersion` (`lego/backend/internal/agentsessions/skills_versions.go:137-142`), directly after `s.scopeSkill` (so authorization still runs before input-detail errors, keeping cross-workspace/unauthorized refusals unchanged).
  - Keep the `strconv.Atoi` check in `lego/backend/internal/agentsessions/rest.go:334-337` (or let `version < 1` be handled in `Service.AgentSkillVersion` after checking existing REST tests in `skills_versions_test.go` for whether unauthorized callers with `/versions/0` expect `400` or `403`).
  - REST, GraphQL `agentSkillVersion`, and MCP `get_agent_skill_version` (`/mcp` and `/mcp/cloud-agents`) then all agree on `AGENT_SKILL_INVALID` for `version <= 0`, while positive missing versions (e.g. `999`) continue returning `AGENT_SKILL_VERSION_NOT_FOUND`.
