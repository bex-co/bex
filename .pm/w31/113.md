# 113 — `agentsessions.Service.DeleteAgentSecret` and rescoping a repo-scoped secret away from its repository never trigger a `secret_changed` rebuild of the affected repository environment

Why: `agentsessions.Service.SetAgentSecret` (`lego/backend/internal/agentsessions/secrets.go:327`) only calls `s.triggerBuild(..., buildTriggerSecretChanged)` when `next.Scope == store.AgentSecretScopeRepo` (ignoring `stored.Repo` when a secret is rescoped away to `explicit`, `workspace`, or another repository), and `DeleteAgentSecret` (`lego/backend/internal/agentsessions/secrets.go:398-427`) deletes the secret and scope row without reading the previous scope or triggering a rebuild — leaving the repository's prebuilt environment image stale with artifacts built from a revoked or moved repo secret across MCP, REST, and GraphQL.

- **Expected vs Actual:**
  - **Expected:** Under `docs/ADR111-agent-repo-environment-builds.md` D3 & D6, a prebuilt repo-environment image runs setup steps with the repository's unnamed repo-scoped secrets (`trigger: "secret_changed"`). When a repo-scoped secret is deleted (`DeleteAgentSecret`) or rescoped away from `stored.Repo` (to `explicit`, `workspace`, or a different `repo`), the previous repository's build inputs have changed and must enqueue a `secret_changed` rebuild (cancelling any stale queued build and replacing any cached image that baked outputs derived from the removed secret).
  - **Actual:** Adding or re-attaching the repo-scoped secret immediately queued `trigger: "secret_changed"` (`arb-dc4a652r91cc73cuv5p0`, then `arb-dc4a65ar91cc73cuv5qg` on MCP; `arb-dc4a70cdplss73eg60e0` on REST). Rescoping the secret away to `explicit` queued zero builds, and deleting the secret on both MCP and REST queued zero builds — leaving the prior `secret_changed` build (`arb-dc4a65ar91cc73cuv5qg` / `arb-dc4a70cdplss73eg60e0`) queued and unchanged.

- **Root cause (researched):**
  - `lego/backend/internal/agentsessions/secrets.go:327`:
    ```go
    if next.Scope == store.AgentSecretScopeRepo && (in.Value != "" || next != stored) {
        s.triggerBuild(ctx, workspaceID, next.Repo, buildTriggerSecretChanged)
    }
    ```
    Only checks `next.Scope == store.AgentSecretScopeRepo`. When `stored.Scope == store.AgentSecretScopeRepo` and the update moves the secret to `explicit`, `workspace`, or a different `next.Repo`, `stored.Repo` is never rebuilt.
  - `lego/backend/internal/agentsessions/secrets.go:398-427` (`DeleteAgentSecret`): deletes the OpenBao entry (`:416`) and scope row (`:422`) without first reading the secret's stored scope and never calls `s.triggerBuild(ctx, workspaceID, stored.Repo, buildTriggerSecretChanged)`.
- **Fix direction:**
  - In `SetAgentSecret` (`lego/backend/internal/agentsessions/secrets.go:325-329`), also trigger `s.triggerBuild(ctx, workspaceID, stored.Repo, buildTriggerSecretChanged)` whenever `exists && stored.Scope == store.AgentSecretScopeRepo && (next.Scope != store.AgentSecretScopeRepo || next.Repo != stored.Repo)`.
  - In `DeleteAgentSecret` (`lego/backend/internal/agentsessions/secrets.go:416-426`), read the stored scope before deleting the scope row; if `stored.Scope == store.AgentSecretScopeRepo && stored.Repo != ""`, call `s.triggerBuild(ctx, workspaceID, stored.Repo, buildTriggerSecretChanged)` after the delete completes.
  - Surface impact: fixes MCP (`set_agent_secret`, `delete_agent_secret`), REST (`PUT/DELETE /v1/agent-secrets/{name}`), and GraphQL (`setAgentSecret`, `deleteAgentSecret`) through one shared service layer.
- **Blast radius:** `lego/backend/internal/agentsessions/secrets.go` and its tests (`lego/backend/internal/agentsessions/repo_environment_builds_test.go`, `secrets_test.go`). Note `triggerBuild` already no-ops cleanly when the repository has no repo environment configured.
