# 087 — Blueprint create/preview/read paths bypass `store.ValidRepo` and `store.RedactRepoURL`, storing and echoing plaintext HTTPS userinfo credentials across MCP, REST, and GraphQL

Why: `store.ValidRepo` (`lego/backend/internal/store/api.go:630-658`, codex-security round-6 #13) forbids embedded URL userinfo on every Git repo URL so a member's PAT can never be persisted and echoed to every workspace Viewer, and `store.RedactRepoURL` (`store/api.go:660-680`) scrubs stored repo URLs on read — yet `parseBlueprintRepoURL` (`lego/backend/internal/apps/blueprint_onboarding.go:917-934`), `CreatePlannedBlueprint` (`:157-263`), `CreateBlueprint` (`lego/backend/internal/apps/blueprint.go:1397-1470`), `previewBlueprintWith` (`:1240-1326`), and `toBlueprintView` (`:2698-2730`) all skip both checks, storing `https://user:<token>@github.com/...` verbatim in Postgres and echoing it across MCP, REST, and GraphQL reads.

- **Root cause & blast radius:**
  - `parseBlueprintRepoURL` (`lego/backend/internal/apps/blueprint_onboarding.go:917-934`) parses `raw` with `url.Parse` and strips `u.User` only on the `u.Scheme == "ssh"` branch (`:930-932`), leaving `u.User` intact for `https://` URLs.
  - `CreatePlannedBlueprint` (`lego/backend/internal/apps/blueprint_onboarding.go:157-263`), `previewBlueprintWith` (`lego/backend/internal/apps/blueprint.go:1240-1326`), and legacy `CreateBlueprint` (`lego/backend/internal/apps/blueprint.go:1397-1470`) never validate `repo` with `store.ValidRepo` (unlike `apps/service.go:3851,5653` for services and build sources).
  - `toBlueprintView` (`lego/backend/internal/apps/blueprint.go:2698-2730`, line `:2717`) copies `Repo: b.Repo` raw instead of `Repo: store.RedactRepoURL(b.Repo)` (unlike `appToView` at `lego/backend/internal/apps/service.go:1320`), so any Blueprint row stored with userinfo is echoed verbatim to every workspace Viewer across MCP (`get_blueprint`, `list_blueprints`), REST (`GET /v1/blueprints`, `GET /v1/blueprints/{id}`), and GraphQL (`blueprint`, `blueprints`).
  - Surface impact: affects MCP, REST, and GraphQL Blueprint onboarding, preview, and read paths identically.
- **Proposed fix:**
  - Reject `u.User != nil` on HTTPS URLs in `parseBlueprintRepoURL` (`lego/backend/internal/apps/blueprint_onboarding.go:917-934`) — and validate `repo` with `store.ValidRepo` in `CreatePlannedBlueprint` (`blueprint_onboarding.go`), `CreateBlueprint` (`blueprint.go`), and `previewBlueprintWith` (`blueprint.go`) before any Git fetch or store write, returning the same `core.ErrBadRequest` wording services use (without echoing the credentialed URL!).
  - Project `Repo: store.RedactRepoURL(b.Repo)` in `toBlueprintView` (`lego/backend/internal/apps/blueprint.go:2717`) as defense in depth for any previously stored Blueprint row, matching `appToView` (`apps/service.go:1320`).
