# 024 — Out-of-range pagination `limit` (`<= 0`, `> 100`) silently accepted on MCP and GraphQL across 11 REST-validated list surfaces (and `limit: 0` / `> 100` on env vars, secret files, and jobs)

Why: MCP input structs declare non-pointer `Limit int` and forward it straight into clamping helpers (`core.PageLimitOrDefault`, `core.PageLimitOrAbsent`, `pageEnvGroups`), while GraphQL resolvers pass `gqlutil.Int` without bounds checks — so `list_blueprint_syncs`, `list_webhook_deliveries`, `list_env_groups`, `list_projects`, `list_environments`, `list_custom_domains`, `list_sandbox_executions`, `list_sandbox_images`, `list_sandbox_snapshots`, `list_build_sources`, and `list_build_source_builds` (plus `limit: 0` and `> 100` on `list_env_vars`, `list_secret_files`, and `list_jobs`) silently succeed on `-1`/`-5`, `0`, and `500` where every matching REST endpoint returns `400 bad_request: limit must be an integer between 1 and 100`.
