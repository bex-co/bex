# 068 — `keyPermissionOps` maps GraphQL `Query.databaseParameterSpec` to `KeyAnyGrant` instead of `KeyPostgresView`, letting any scoped API key read Postgres parameters and probe database existence

Why: `lego/backend/internal/api/key_permission_ops.go:366` maps `"GQL Query.databaseParameterSpec"` to `{core.KeyAnyGrant}` (a copy-paste alongside static catalog `databaseInstanceTypes` at `:362`), whereas its MCP (`list_postgres_parameters`, `:671`) and REST (`GET /v1/postgres/{id}/parameters`, `:950`) counterparts require `{core.KeyPostgresView}` — letting a scoped API key with zero Postgres permissions (e.g. `services: read` or `agents: read_write` only) enumerate Postgres database existence and invoke `postgres.Service.ParameterSpec` (`lego/backend/internal/postgres/insights.go:920-939`), including its live CNPG `pg_settings` observation query.

- **Root cause:**
  - `lego/backend/internal/api/key_permission_ops.go:366` registers `"GQL Query.databaseParameterSpec": {core.KeyAnyGrant}` instead of `{core.KeyPostgresView}`.
  - Unlike static catalog queries (`databaseInstanceTypes` at `:362`, `instanceTypes` at `:395`, `keyValueInstanceTypes` at `:401`), `databaseParameterSpec` (`lego/backend/internal/postgres/graphql.go:564`) delegates to `postgres.Service.ParameterSpec` (`lego/backend/internal/postgres/insights.go:920-939`), which fetches a specific `Database` CR (`fetchLiveDatabase(ctx, core.RelCanView, dbID)`) and, when `db.Spec.Parameters` is non-empty, executes `sqlParameterOverrides` against the live CNPG instance.
- **Fix:**
