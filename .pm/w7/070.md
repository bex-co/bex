# Render's plan table limits workspaces per plan and keeps enforced 2FA to Pro and higher; bex does neither

Why: two rows of Render's plan comparison table disagree with what bex does today, and with an earlier reading of Render's docs, so either bex or ADR018 is wrong.

- Found by w7/m429 t005, 2026-11-16 (`lego/backend/internal/pricing/plan_table_test.go` names this note for both rows).
- Render (render.com/pricing comparison table, read 2026-11-16, captured in `docs/render-artifacts/pricing.md`):
  - "Workspaces: 1 | 1 | Unlimited | Unlimited". bex lets one user own five Hobby workspaces and unlimited paid ones (`store.LimitsFor` `MaxWorkspacesPerUser`, from `.pm/w6/RESEARCH-workspaces.md`). Render's row may count workspaces per organization (Scale and Enterprise "support managing multiple workspaces in a unified organization", render.com/docs/platform-features-by-plan) rather than per user.
  - "Enforce 2FA & Google login: — | ✓ | ✓ | ✓". bex lets any workspace admin on any plan require 2FA (w22/m402); ADR018's Workspace-enforced 2FA row says Render's login-settings page lists no plan requirement.
- To decide: read both rows against Render's own docs and, where possible, a Hobby workspace's settings page; then either gate enforcement to Pro and higher as a `core.PlanFeature` (a workspace that already enforces it keeps it, ADR030 §9), or record why the table row does not apply, in ADR018 with the user's sign-off. Same for the workspace count.
- Done when: each row has a verified disposition in ADR030 §9 and `plan_table_test.go`, and ADR018's rows say which Render source wins.
