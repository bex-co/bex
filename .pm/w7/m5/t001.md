## Objective

Give the `KeyValue` CR the same `ipAllowList` field the `Database` CR already carries, so the operator has something to project onto the public Valkey route. Field semantics mirror Render's `ipAllowList` and bex's Postgres field exactly: restricts the EXTERNAL (public) endpoint; empty ⇒ external endpoint open to all; only meaningful when `Public`.

## Context

- `lego/types/v1alpha1/database_types.go:66-71` — the reference field (`IPAllowList []string`, doc comment, `omitempty`).
- `lego/types/v1alpha1/keyvalue_types.go` — target; currently has no allowlist field.
- Codegen footgun (operator/CLAUDE.md): CRD types live in `types/`; run `make manifests generate` from `lego/operator/` after editing, keep the output (`zz_generated.deepcopy.go` + `config/crd/bases/`).

## Steps

1. Add `IPAllowList []string \`json:"ipAllowList,omitempty"\`` to the KeyValue spec, with a doc comment mirroring `database_types.go` (external-only, empty⇒open, meaningful only when Public).
2. From `lego/operator/`, run `make manifests generate`; keep the regenerated deepcopy + CRD YAML.
3. `cd lego/types && go build ./...` and `cd lego/operator && go build ./...`.
