## Objective

Cover the isolation, retention and gate-off properties, which are the ones a reviewer cannot verify by reading.

## Context

- t005 already covers the cache-loss invariant; this task covers the rest.
- The highest-risk untested property is **cross-workspace cache isolation** — a leak there is a confidentiality breach, not a performance regression.
- The second is the retention interaction, which only manifests after N builds and would otherwise be found in production.

## Steps

1. Test the gate: unset `BEX_BUILD_CACHE` produces a byte-identical Job spec.
2. Test cross-workspace denial on the `-cache` repository (both `BEX_REGISTRY_NS` set and unset).
3. Test the retention interaction with enough pushes to trigger a naive-policy eviction.
4. Confirm `make test` and the backend suite are green.

## Files

- `lego/operator/internal/build/build_test.go`, controller tests

## Acceptance criteria

- [ ] Gate-off byte-identity is asserted, not assumed.
- [ ] Cross-workspace cache access is denied under both credential modes.
- [ ] Retention interaction is proven by a test that would fail under a shared policy.
- [ ] No trivial or tautological tests; suites green.

## Out of scope

- Performance regression testing beyond t006's measurement.

## Outcome

Coverage for the properties a reviewer cannot check by reading, all mutation-tested — each assertion was proven to fail against a deliberately broken implementation before being kept.

- **Gate off is unchanged**, in the strong form: strip the cache seams from the enabled Job and it must deep-equal the disabled Job, across the whole Job rather than the pod template (an earlier version compared only the pod spec and missed `backoffLimit`/`activeDeadlineSeconds` — caught by mutation).
- **Cross-workspace cache isolation** under both credential modes, plus the ACL grant/revoke lifecycle and the converged-reconcile-writes-nothing property.
- **The wiring itself**, in envtest against a real API server: an unwired gate is completely silent, producing builds that work and never cache. Proven red by unwiring it.
- **Shell behaviour, executed rather than string-matched**: every generated script parses as `sh`, a failing cache step really does exit 0, and the import flag is only added when a restored layout is present.
- **The pod disk ceiling and the transfer timeouts** (see t007) — the first found a live regression the moment it was written.

On retention, the honest note: the task asked for a test proving the retention interaction after enough pushes to trigger a naive-policy eviction. That test was not written, because the premise it would encode is false — measurement showed cache and image live in separate repositories, so no number of cache pushes can evict a deployable tag. What is pinned instead is the property that actually bounds growth: the cache occupies one constant tag that does not vary with the revision, so a cache repository holds one manifest regardless of build count.
