## Objective

Extend the existing per-App registry isolation to the new `-cache` repository, so the cache inherits the tenant boundary instead of opening a hole beside it.

## Context

- `w7/m36` shipped per-App Zot pull credentials: the operator mints an `app-<name>` htpasswd user plus a per-repository ACL entry, and a `reg-pull-<name>` Secret. ADR060 D3 explicitly reuses that machinery so the cache adds "zero new authz surface".
- The isolation requirement is ADR034 §6: a workspace must never read another workspace's cache layers. Cache layers can contain build-time secrets and source-derived content, so this is a real confidentiality boundary, not bookkeeping.
- `BEX_REGISTRY_NS` gates the per-App credential path; when unset the shared-pull-secret path applies. The cache must behave correctly in both, or be refused in one — decide and state which.

## Steps

1. Extend ACL minting so `<app-repo>-cache` carries the same per-App scope as `<app-repo>`.
2. Extend the credential path used by whichever container writes the cache (per t001's decision).
3. Handle the `BEX_REGISTRY_NS`-unset case explicitly: either supported or refused, never silently shared.
4. Add a negative test: workspace A cannot read workspace B's cache repository.

## Files

- `lego/operator/internal/controller/` registry ACL/credential management
- `lego/operator/internal/build/build.go` if the credential mount changes

## Acceptance criteria

- [ ] `<app-repo>-cache` is ACL-scoped exactly like `<app-repo>`.
- [ ] A cross-workspace cache read is denied, proven by a negative test.
- [ ] The `BEX_REGISTRY_NS`-unset behavior is explicit and documented.

## Out of scope

- Retention policy for the cache repos — t004.
