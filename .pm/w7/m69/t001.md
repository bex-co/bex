## Objective

Turn ADR011's recommended restore path (Path A: fetch snapshot → throwaway etcd → extract CRs → re-apply to a fresh cluster) into one executable script with `DRY_RUN=1` support.

## Context

- Runbook: `docs/ADR011-etcd-backup-restore.md` (restore paths; Path A drilled 2026-07-14 on CAPD, w7/m29 — the drill record's exact commands are the script's skeleton).
- Snapshots: `s3://bex-tfstate/etcd-snapshots/` (nightly CronJob, 7 kept, gzip).
- Shape: parameterize snapshot selection (default latest), spin the throwaway etcd locally (Docker), extract `apps.app.bex.co`/`databases`/`keyvalues` CRs + chosen platform resources, emit them as manifests for review, apply only on explicit confirmation (never auto-apply without a flag).
- Safety rails: read-only against S3 + local container until the operator confirms the apply step; never touches the live cluster's etcd.
- Repo conventions: never print kubeconfig/credential contents; scratch under `mktemp -d`, cleaned on exit.

## Steps

1. Write the script (fetch → verify snapshot integrity via `etcdutl snapshot status` → throwaway container → extraction → gated re-apply).
2. Validate `DRY_RUN=1` end to end against a real prod snapshot (no writes).
