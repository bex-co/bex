## Objective

Turn `VerifyDomain` from an idempotent status re-read into a real ownership proof. When the tenant calls verify, resolve the challenge in DNS — a `TXT _bex-challenge.<host>` record equal to the domain's `challenge_token` (t001), or a `CNAME <host> → <app>.<base-domain>` proof for the subdomain case — and transition the store status `pending`/`verifying` → `verified` only when the DNS lookup confirms it. A failed lookup leaves the domain unverified and returns a well-typed "not yet verified" view (not an error the dashboard can't render).

## Context

- `lego/backend/internal/apps/domains.go:200-202` — `VerifyDomain` today just calls `GetDomain` (no proof).
- `lego/backend/internal/apps/domains.go:91-101` — `dnsRecordFor` already computes the `CNAME`/`ALIAS` record the tenant must publish; the challenge TXT record is the new complement.
- Use the Go stdlib resolver (`net.LookupTXT`/`net.LookupCNAME`) or the resolver already in the backend if one exists; keep lookups bounded (context timeout) so verify can't hang.
- t001 supplies `status` + `challenge_token` on the Domain read path.

## Steps

1. Define the challenge record shape (TXT name `_bex-challenge.<host>`, value = challenge token) and expose it to callers so t005 can display it.
2. In `VerifyDomain`: perform the DNS lookup with a bounded timeout; on match, transition store status to `verified`; on miss, set/keep `verifying` (or `pending`) and return the current unverified view.
3. Make verify idempotent — re-verifying an already-`verified` domain re-reads and stays verified; make the transition safe under concurrent verifies.

## Files

- `lego/backend/internal/apps/domains.go` — `VerifyDomain`, challenge-record helper.

## Acceptance criteria

- [ ] A domain with the correct `TXT _bex-challenge.<host>` (or the CNAME proof) transitions to `verified` on verify; a domain without it stays unverified.
- [ ] Verify uses a bounded DNS lookup (no unbounded hang) and returns a well-typed view on failure, not a 500.
- [ ] Re-verifying a verified domain is idempotent.

## Out of scope

- Gating routing on the verified state (t003); collision/reserved guard (t004); adapter/dashboard surfacing (t005). DNS is proof-of-ownership only — cert issuance stays cert-manager's job (t003 gates when the host reaches the Ingress).
