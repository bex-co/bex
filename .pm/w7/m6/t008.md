## Objective

Add meaningful tests asserting the real behavior and failure modes this milestone shipped: routing is gated on verification, the DNS proof works and fails correctly, and cross-App/reserved-host claims are rejected. Tests must exercise real behavior — not tautological or snapshot-everything checks.

## Context

- Backend service tests use the fake store (`lego/backend/internal/store/fake_test.go`) and can stub DNS resolution (inject the resolver or a lookup func so the DNS proof is deterministic in tests).
- Existing domain tests live alongside `lego/backend/internal/apps/` — extend them.

## Steps

1. Test that `AddDomain` records `pending` and does **not** put the host in `spec.hosts[]`; that a passing verify promotes it (Ingress/cert path) and a failing verify does not.
2. Test the DNS proof: matching TXT/CNAME → `verified`; missing/wrong → stays unverified; verify is idempotent and bounded.
3. Test rejection: a host already verified on another App is refused; the base-domain apex / dashboard host / foreign `<app>.<base>` are refused; the App's own auto host is allowed.
4. Test the adapter surface: `status` + `challengeRecord` round-trip on REST/GraphQL/MCP (at least one adapter-level test per field).

## Files

- `lego/backend/internal/apps/*_test.go`
- `lego/backend/internal/store/*_test.go` (migration / uniqueness)

## Acceptance criteria

- [ ] Tests assert the routing gate (pending ⇒ unrouted, verified ⇒ routed), the DNS proof (pass/fail/idempotent), and collision + reserved-host rejection.
- [ ] Adapter tests assert `status` + `challengeRecord` round-trip; `go test ./...` passes in `lego/backend`.

## Out of scope

- Live-cluster DNS/Ingress e2e (unit + fake-store level is the bar here); the Closeout DoD verification (t009).
