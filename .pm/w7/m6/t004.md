## Objective

Prevent one App from claiming a hostname that belongs to another App or to the platform. Two guards: (1) **cross-App uniqueness** — reject adding/verifying a host already `verified` on a different App (any tenant); (2) **reserved-host** — reject hosts that collide with platform infrastructure: the `BEX_BASE_DOMAIN` apex and its platform subdomains (e.g. `dashboard.<base>`, and any `<other-app>.<base>` auto host that isn't this App's own). Ownership verification (t002) already stops a tenant from proving a domain they don't control; these guards stop claiming/squatting and platform-host takeover regardless of DNS.

## Context

- `lego/backend/internal/apps/domains.go:207-221` — `AddDomain` only checks for a same-App duplicate; no cross-App or reserved check.
- `lego/backend/internal/apps/domains.go:66-73` — `platformHost`/`BaseDomain`: the operator mints `<app>.<BEX_BASE_DOMAIN>` auto hosts; a custom host matching `<some-other-app>.<base>` or `<base>` itself must be refused.
- The store (t001) is where cross-App verified-host uniqueness is enforced — a lookup "is this host verified on any App?" (consider a partial unique index on verified hosts, mirroring the `tenant_members` partial-unique-index pattern in `store/members.go`).
- Reserved set: the base-domain apex, the dashboard host, and the `<app>.<base>` platform-host namespace (only this App's own auto host is allowed).

## Steps

1. Add a store query for "host already verified on another App" and enforce it in `AddDomain` (reject with `core.ErrBadRequest`/conflict) and again at the verify transition (t002) to close the add-both-then-verify race.
2. Add a reserved-host predicate (base-domain apex, dashboard host, foreign `<app>.<base>` platform hosts) and reject those in `AddDomain`.
3. Return clear, typed errors the three adapters + dashboard surface as a validation message (not a 500).

## Files

- `lego/backend/internal/apps/domains.go` — `AddDomain`, verify-time re-check, reserved-host predicate.
- `lego/backend/internal/store/` — cross-App verified-host lookup / uniqueness (possibly a partial unique index).

## Acceptance criteria

- [ ] Adding or verifying a host already `verified` on another App is rejected with a typed conflict error.
- [ ] Adding the base-domain apex, the dashboard host, or a foreign `<app>.<base>` platform host is rejected; the App's own auto host is unaffected.
- [ ] The add-both-then-verify race is closed (the uniqueness check also runs at the verify transition).

## Out of scope

- The DNS proof (t002) and routing gate (t003); adapter/dashboard surfacing of the rejection (t005 wires the message through).
