## Objective

Store an org's two login settings, and make the one read the gate already makes, `LoginRequirements(workspaceID)`, return the effective requirement of a workspace in an org.

## Context

- `organizations` comes from migration `0293_organizations`. `tenants.organization_id` links a workspace to its org.
- `PGStore.LoginRequirements` (`lego/backend/internal/store/workspaces.go:208`) selects `require_two_factor, require_google_login` from `tenants` alone. The gate (`internal/twofactor/gate.go`), the SSH verb and the configuration reads all go through it.
- `PGStore.GoogleLoginWorkspaces` (`internal/store/workspaces.go:225`) names the workspaces that block an email change or a Google unlink in the Kratos settings guard (`internal/settingsguard/settingsguard.go:140`).
- `SetTenantRequireTwoFactor` and `SetTenantRequireGoogleLogin` are the conditional writes, so a no-op reports nothing changed. The org setters follow the same shape.

## Steps

1. Add a migration (the next free number after `0294`) with `organizations.require_two_factor` and `organizations.require_google_login`, both `boolean NOT NULL DEFAULT false`, plus its down migration.
2. Add `Organization.RequireTwoFactor` and `RequireGoogleLogin` to the store type and its reads. Add conditional setters that report whether anything changed.
3. Make `LoginRequirements` return, for each setting, the workspace's value OR its org's (`LEFT JOIN organizations`), and which of the two required it, so the refusal can name the org (t001's details rule). A workspace with no org reads exactly as today.
4. Make `GoogleLoginWorkspaces` count a workspace whose org requires Google login, named so the guard's message names the org (t001's wording).
5. Add an `OrgWorkspaceIDs(orgID)` read, or reuse an existing one, so t003 can invalidate each workspace's cached setting.

- [ ] Real-Postgres tests: a standalone workspace reads as before. An org workspace whose own setting is off reads the org's requirement, and its source names the org. Turning the org setting off restores the workspace's own value. `GoogleLoginWorkspaces` lists an org workspace when only the org requires Google. A setter's no-op reports no change.
- [ ] `cd lego/backend && go test ./internal/store/...` passes against real Postgres.

## Out of scope
