## Objective

Move existing `tenants/default/services/<name>/{env,files}` data onto the new tenant-scoped paths so the keying change does not silently orphan live tenant secrets, and ensure the OpenBao policy admits the new layout and forbids cross-tenant access.

## Context

- Pre-fix data lives under the single `default` tenant prefix in production OpenBao.
- The gateway/role path expectations live in `scripts/bao-k8s-auth.sh` and any checked-in policy HCL.

## Steps

1. Write a one-shot migration (a bex-api startup migration or a scripted `bao kv patch`/read-copy-write-delete) that, for each known App, copies `default/services/<name>/{env,files}` to `<tenant>/services/<name>/{env,files}` and removes the old path. Idempotent.
2. Gate it behind the same env that enables OpenBao (`BEX_OPENBAO_URL`); no-op when the old path is absent.
3. Update the OpenBao policy so the `bex-api` role can read/write only `<tenant>/services/*` for tenants it owns (or the per-request tenant), never a foreign tenant's prefix.
4. Record the migration in docs/ADR013-secrets.md (the `<tenant>` placeholder becomes real).

## Files

- Migration: new file under `lego/backend/internal/secrets/` (or `scripts/`).
- `scripts/bao-k8s-auth.sh` + policy HCL.
- `docs/ADR013-secrets.md`.

## Acceptance criteria

- [ ] Existing tenant secrets are reachable at the new tenant-scoped path after migration.
- [ ] The old `default/services/<name>/` path is empty post-migration.
- [ ] OpenBao policy denies a request scoped to tenant A from reading tenant B's prefix.

## Out of scope

- Cross-region backup of OpenBao (separate concern, `w7/015`).
