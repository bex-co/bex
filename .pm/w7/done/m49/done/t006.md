## Objective

Verify the new gate accepts valid requests produced by Render-compatible clients and records where bex intentionally rejects undeclared input more strictly than Render's open schemas.

## Context

- Standing closing task for a public REST behavior change.
- The official spec leaves object schemas open and kin ignores unknown query parameters, so unknown-input rejection is a bex security extension, not a claim about render.com's live rejection behavior.
- GraphQL/MCP do not consume the REST OpenAPI contract and should be unchanged; no artificial cross-surface validation parity is required.

## Steps

1. Exercise representative official CLI/API flows across services, deploys, Postgres, Key Value, env groups, projects, custom domains, and logs using valid spec-shaped parameters/bodies.
2. Verify bex extensions in the t002 matrix still round-trip and aliases retain their previous status/body.
3. Compare validation error status/envelope with the existing REST error dialect and document the stricter unknown-input policy.
4. Update ADR006/ADR018 and the CLI compatibility checklist only where the observable REST contract changed.

## Files

- `docs/ADR006-bex-api.md`
- `docs/ADR018-render-parity.md`
- `docs/cli-compatibility-checklist.md` (if a row/evidence changes)
- `docs/render-artifacts/openapi-request-validation.md`

## Acceptance criteria

- [ ] Representative unmodified Render CLI/API requests remain accepted on every enforced family; any regression is fixed before closeout.
- [ ] Stricter undeclared-input rejection is documented as a deliberate bex extension, not misreported as Render live parity.
- [ ] REST, GraphQL, MCP, SSE, and bex alias boundaries are documented accurately.

## Out of scope

- Adding missing Render endpoints or changing non-REST adapters.

## Resolution

The complete backend suite replayed the existing official-CLI/API fixtures through the new authenticated gate across services, deploys, datastores, groups/projects, domains, jobs, registry credentials, and logs. Positive boundary fixtures retain body/query extensions, missing Content-Type compatibility, defaults, aliases, public mounts, GraphQL/MCP, and SSE behavior. ADR006, ADR018, the CLI checklist, and the new artifact accurately label undeclared-input rejection as a bex security extension; no new live-CLI claim was made.
