## Objective

Prove the boundary both rejects malicious/malformed requests before side effects and stays transparent for valid Render and bex-extension requests.

## Context

- This is a security/compatibility gate; positive-only tests are insufficient.
- High-risk regressions found during research: unknown query/body input silently accepted, handler body consumed by validation, request defaults mutated, raw secret values exposed in kin errors, valid bodies rejected by `RejectWhenRequestBodyNotSpecified`, unsupported spec routes changing from 404 to 400, and SSE/aliases being wrapped accidentally.

## Steps

1. Add table-driven negative cases for required/type/enum/format/pattern/range/content-type, unknown query, unknown top-level/nested body fields, trailing JSON, and stray body.
2. Attach a side-effect spy to mutation handlers and assert every rejected request leaves it untouched.
3. Add positive cases for body byte preservation, no default injection, every bex extension, aliases/pass-through routes, valid empty-body verbs, and representative official CLI requests.
4. Add secrecy assertions: markers placed in body/query/header never appear in response or captured logs; malformed input never panics the server.
5. Run focused API tests, full `cd lego/backend && go test ./...`, and relevant lint.

## Files

- `lego/backend/internal/api/render_openapi_test.go`
- strict decoder unit tests under `lego/backend/internal/core/`
- affected feature REST tests
- conformance tests

## Acceptance criteria

- [ ] Every failure mode above has a negative test that proves handler/side-effect non-entry.
- [ ] Every documented extension/pass-through boundary has a positive regression test.
- [ ] Secret marker and no-panic tests pass; validation errors stay bounded and Render-shaped.
- [ ] Full backend tests and relevant lint pass.

## Out of scope

- Load testing beyond a small allocation/large-bounded-body regression check.

## Resolution

Added table-driven coverage for required/type/enum/format/pattern/range/media failures, unknown query/top-level/nested/custom-unmarshal fields, trailing JSON, stray body, malformed input/no panic, Render-shaped bounded/redacted errors, and zero mutations. Positive cases prove exact body bytes, no default injection, all reviewed extension classes, empty-body verbs, aliases, unsupported-route 404, auth-before-validation, and legacy bare-CIDR compatibility. Evidence: `go test ./...` passed for every backend package; `make lint-backend` reported `0 issues`.
