## Objective

Define exactly which requests the contract gate owns before enabling it: the intersection of routes actually registered by bex's authenticated REST mux and operations present in the pinned Render spec, plus every accepted bex-only field/query extension on those operations.

## Context

- The full Render file contains unsupported operations; validating every Render match would turn some current bex 404s into validation 400s.
- bex also registers aliases and extensions absent from Render (`/v1/apps`, `/v1/databases`, shell tickets, blueprints, usage, etc.); those must pass through unchanged.
- Render-covered mutation bodies also accept deliberate bex fields: `dryRun`, `builder`, `port`, top-level `plan`, `domains`, `publishPath`, `preDeployCommand`, `routes`, `headers`, `idleTTLSeconds`, and others represented by the current Go request structs.
- Query extensions include at least `dryRun` and protected-resource `confirm`; they need an explicit operation-keyed allowlist if unknown query keys are rejected.

## Steps

1. Inventory the shared `restHandler` registrations by method/path and match them to pinned Render operation IDs.
2. Classify each family as `enforce`, `bex-only/alias pass-through`, or `Render operation not implemented`; include public device/HMAC/deploy-hook routes as explicitly outside the authenticated gate.
3. Diff Render request/query properties against bex request structs and handler query reads; record every accepted extension and any intentional type/requiredness divergence.
4. Turn the matrix into table-driven fixtures/allowlists consumed by middleware tests, with a short human-readable artifact for spec refresh review.

## Acceptance criteria

- [ ] Every authenticated Render-compatible REST path family is classified; aliases, bex-only endpoints, and unsupported official operations have an explicit expected behavior.
- [ ] Every accepted bex query/body extension on enforced operations is recorded and covered by a positive fixture.
- [ ] The matrix is keyed by stable operation ID/method/path, not handler implementation names or map iteration order.

## Out of scope

- Expanding bex to implement unsupported Render operations; changing GraphQL/MCP surface parity.

## Resolution

Documented every Render tag/family, bex alias/public boundary, compatibility default, query extension, and body extension in `docs/render-artifacts/openapi-request-validation.md`. `TestRenderRouteIntersectionInventory` computes the real mux/spec intersection and pins all 119 stable operation IDs; operation-scoped tests guard requiredness and query compatibility maps.
