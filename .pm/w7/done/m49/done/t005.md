## Objective

Make the complete embedded pin the only Render contract asset, reuse kin for m30's response conformance tests, and turn upstream refresh into one explicit, reviewable workflow rather than a live dependency.

## Context

- m30's current `testdata/render-openapi.json` is a 12-operation/16-schema response subset even though its update comment permits either a full spec or subset. The milestone README records older 11/14 counts, demonstrating that hand-copied subsets drift.
- kin is now a production dependency, so retaining a separate ~150-line partial JSON-schema walker adds two validators and two interpretations of the same contract.
- Runtime response validation remains deliberately excluded; response conformance belongs in `go test ./...`, where buffering is harmless and the existing ADR018 divergence allowlist can remain explicit.

## Steps

1. Point `TestRenderConformance` at the shared embedded document and replace the partial schema walker with kin's response validation for the existing operation cases.
2. Preserve the ADR018-keyed divergence allowlist and its stale-entry negative guard; triage any newly exposed enum/format/constraint divergence explicitly.
3. Remove the response-only JSON subset and custom walker after equivalent-or-stronger coverage is green.
4. Document a manual refresh command/checklist: fetch to a temporary file, verify URL/date/size/SHA, validate with pinned kin/options, review route/extension matrix and diff, run conformance + backend tests, then deliberately replace the pin.
5. Add a guard that a changed pin cannot silently add external refs, broaden `$ref` sibling exceptions, or remove covered operations.

## Acceptance criteria

- [ ] One complete embedded JSON pin serves production request validation and CI response conformance; no response subset/custom schema walker remains.
- [ ] Existing response families and stale-allowlist guard remain green under kin, with any added divergence carrying an ADR018 citation.
- [ ] Pin refresh is offline-by-default, manual, reproducible, and fails review/tests on unexpected compatibility changes.
- [ ] No response validation runs in production.

## Out of scope

- A scheduled bot that auto-commits or auto-accepts Render spec changes.

## Resolution

Removed `internal/api/testdata/render-openapi.json` and the stdlib schema walker. `conformance_kin_test.go` now uses kin response validation over the shared complete document; response errors are split into narrow pointer/reason entries. Newly exposed existing response gaps have explicit ADR018-cited allowlist entries and the stale-entry negative test remains green. The manual offline pin-refresh workflow and failure guards are documented in `openapi-request-validation.md`; production performs no response validation.
