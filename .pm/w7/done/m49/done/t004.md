## Objective

Close the intentional OpenAPI gaps that kin cannot close from Render's open schemas: reject undeclared query keys and JSON properties on enforced routes while accepting the real bex request extensions.

## Context

- Research found 290 object schema nodes in the official pin: 287 omit `additionalProperties`, 3 use an additional-property schema, and zero set it to `false`. kin therefore accepted `notInSpec` in a valid service-create body.
- kin intentionally ignores unknown query parameters. Blanket strictness against Render alone would reject bex's `dryRun`/`confirm` queries and create/patch extensions.
- The existing Go request structs are already the authoritative accepted bex body shape. A shared strict decoder is smaller and safer than maintaining a second OpenAPI overlay or globally mutating shared Render schemas.

## Steps

1. For an enforced operation, derive allowed query names from path-level + operation-level OpenAPI parameters and merge the reviewed operation-ID extension allowlist from t002; reject any other query key before the handler.
2. Add one shared REST JSON decoder helper that calls `DisallowUnknownFields`, requires exactly one JSON value (reject trailing documents/tokens), preserves current empty-body semantics where a verb allows them, and returns a safe field-named error.
3. Migrate every Render-covered JSON mutation handler to the helper, including secondary decoding of nested `json.RawMessage` request fragments where their accepted shape is known.
4. Add positive tests for all documented bex fields and negative tests for top-level/nested unknown keys, unknown queries, and trailing JSON.

## Files

- `lego/backend/internal/core/http.go` or `lego/backend/internal/core/json.go`
- Render-covered `lego/backend/internal/*/rest.go` adapters identified by t002
- `lego/backend/internal/api/render_openapi_extensions.go`
- focused core/feature/API tests

## Acceptance criteria

- [ ] Unknown query keys and unknown top-level/nested JSON fields on enforced operations return a safe Render-shaped 400 and cause no side effects.
- [ ] Trailing JSON (`{} {}` or a valid value followed by a second token) is rejected.
- [ ] Every extension in t002's positive matrix remains accepted; bex aliases and non-intersection routes remain unchanged.
- [ ] No OpenAPI schema is globally rewritten to `additionalProperties:false`, and there is no generated overlay to refresh separately.

## Out of scope

- Rejecting unknown HTTP headers; Unicode/string canonicalization; duplicate-key detection; replacing business/domain validation.

## Resolution

Added the context-selected `core.DecodeJSON`/`core.UnmarshalJSON` strict helper and migrated every production REST body decoder in the authenticated router. It rejects unknown regular and custom-unmarshal nested fields, trailing values, and safe-names errors while preserving lenient behavior outside the Render intersection. Unknown query keys merge only declared parameters and the reviewed `dryRun`/`confirm` map; service nested RawMessages use the same strict context. Focused custom-unmarshaler, nested, trailing, extension, and zero-side-effect tests pass.
