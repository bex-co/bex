## Objective

Wrap the one authenticated REST mux with a thin kin-openapi request gate that validates only a real bex route that also matches a Render operation, before the feature handler can run.

## Context

- Integration seam: `mux.Handle("/v1/", auth(rl(s.restHandler(cliAuth))))` in `internal/api/server.go`.
- Required ordering: body limit (already outer) → auth → rate limit → validator → feature handler. Invalid credentials still answer 401 before validator work; validation failures consume the caller's normal rate budget.
- `http.ServeMux.Handler(r)` can establish the actual bex match before kin routing. A spec-only/unsupported route and any bex-only/alias route must fall through to the existing mux behavior.
- Render's document paths omit `/v1` because its server URL supplies it. Route a cloned request with exactly one `/v1` prefix removed and `doc.Servers=nil`; never mutate the handler's request.

## Steps

1. Make `restHandler` expose its `*http.ServeMux` to a private wrapper and construct the embedded validator once from `Handler()`.
2. Gate on the bex-route/Render-operation intersection; pass every non-intersection request to the existing mux unchanged.
3. Call `openapi3filter.ValidateRequest` with `NoopAuthenticationFunc`, `SkipSettingDefaults=true`, fail-fast (`MultiError=false`), and request-value format validation enabled. Keep `RejectWhenRequestBodyNotSpecified=false`; separately reject a present body only when the matched operation has no request body.
4. Preserve/restorably re-read the already bounded body so the existing feature decoder observes the exact original bytes.
5. Map typed validation failures to `core.WriteErrStatus(..., 400, safeMessage)`; include only a parameter name or JSON pointer, never `err.Error()`, submitted values, headers, request body, or schema dumps.

## Acceptance criteria

- [ ] Invalid declared path/query/body type, enum, format, pattern, range, or media type returns the Render-shaped 400 before the handler and causes zero store/Kubernetes side effects.
- [ ] A valid body remains byte-for-byte readable by the downstream handler; kin sets no defaults and performs no normalization.
- [ ] Bex-only routes/aliases and Render operations bex does not implement keep their current responses/statuses.
- [ ] Raw kin error strings and request values never enter responses or logs.
- [ ] A valid operation-defined request body is accepted despite the upstream `RejectWhenRequestBodyNotSpecified` regression; a body on a no-body operation is rejected.

## Out of scope

- Runtime response validation; SSE wrapping; public device, HMAC webhook, and deploy-hook routes; GraphQL/MCP.

## Resolution

Wrapped the authenticated REST mux in `renderRequestValidator` after auth/rate limiting. It validates only an actual bex mux match that kin also routes, adapts `/v1` on a clone, preserves the bounded body, disables defaults, validates formats, rejects stray bodies, and converts typed failures to bounded `core.WriteErrStatus` 400s without raw kin text or submitted values. Auth-order, 404/pass-through, body-preservation, media/type/enum/format/pattern/range, secrecy, and no-panic tests pass.
