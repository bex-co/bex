## Objective

Replace m30's hand-maintained response subset with one complete, offline Render OpenAPI snapshot and a shared kin-openapi v0.142.0 loader that both production request validation and conformance tests can reuse.

## Context

- Official source: `https://api-docs.render.com/openapi/render-public-api-1.json`; Render explicitly says the spec is unversioned and subject to change.
- Research snapshot (2026-07-20): 331,391 bytes; SHA-256 `2d27d5834d8bbc586e0aee62160cf996bb07f4be747112f15ec02c14fc11b315`; 130 paths / 207 operations / 58 request bodies / 163 schemas.
- kin v0.142.0 (Go 1.25-compatible) validates the exact snapshot with only `openapi3.AllowExtraSiblingFields("description", "default")`; there are exactly three such `$ref` siblings. Do not disable example validation.
- Keep external references disabled. The current official file uses internal references only.

## Steps

1. Add the exact kin version to `lego/backend/go.mod` and commit the complete JSON snapshot under an embeddable `internal/api/openapi/` asset path with source URL, fetch date, size, and SHA provenance.
2. Build a `go:embed` loader that parses and validates once at API construction/startup; invalid embedded data is a startup error, never a runtime fallback or live fetch.
3. Apply only the reviewed sibling-field exception and assert its expected count/names in a guard test so the exception cannot silently widen.
4. Clear the Render hostname/server from the in-memory document; leave `/v1` path adaptation to the request gate.

## Files

- `lego/backend/go.mod`, `lego/backend/go.sum`
- `lego/backend/internal/api/openapi/render-public-api-1.json` (new full snapshot)

- `lego/backend/internal/api/render_openapi_test.go` (new loader/provenance guards)

## Acceptance criteria

- [ ] API construction succeeds offline with the embedded full spec and fails deterministically if its integrity/schema guard is broken.
- [ ] Exactly the `description` and `default` `$ref` siblings are allowlisted; examples and all other document validation remain enabled.
- [ ] No runtime/ordinary-CI network fetch and no external `$ref` resolution are possible.
- [ ] Only one checked-in Render OpenAPI JSON asset remains after t005 completes.

## Out of scope

- Request middleware (t003); strict unknown-input behavior (t004); automatic upstream updates (deliberately never automatic).

## Resolution

Pinned the exact 331,391-byte Render snapshot at `lego/backend/internal/api/openapi/render-public-api-1.json`, added kin-openapi v0.142.0, and built the one embedded SHA-checked/external-ref-disabled loader in `render_openapi.go`. `render_openapi_test.go` guards 130 paths, 207 operations, 58 request bodies, 163 schemas, the three exact `$ref` sibling exceptions, no external refs, and deterministic tamper failure.
