## Objective

Verification must be enforced only when `BEX_TENANT_SIGNING_KEY_SECRET` is set (tenant-image signing enabled) — byte-identical (no enforcement, no rejected pods) when unset, matching bex's existing optional-hardening pattern (e.g. `BEX_REGISTRY_PUSH_SECRET`/`BEX_REGISTRY_PULL_SECRET` unset ⇒ unauthenticated dev default).

## Steps

1. Gate the admission policy/webhook's enforcement on the presence of the signing Secret (or an equivalent explicit flag).
2. Confirm that with signing disabled, pod admission is completely unaffected — no verification attempted, no failure mode introduced.

## Acceptance criteria

- [ ] With `BEX_TENANT_SIGNING_KEY_SECRET` unset, pod admission behavior is unchanged from before this milestone.
- [ ] With it set, verification enforces as designed.
