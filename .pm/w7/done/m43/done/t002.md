## Objective

Add Render's **Recent Metrics** section to the Scaling page: average CPU
utilization and average memory utilization across all instances plus total
instances, over the past 48 hours, with a "View all metrics" link to the
Metrics tab and honest empty states — the data a user needs to choose an
instance count or autoscaling target without leaving the page.

## Context

- Live Render capture (2026-07-16): "Recent Metrics — Showing metrics for the
  past 48 hours. View all metrics." followed by three blocks: Average Memory
  Utilization ("Across all instances"), Average CPU Utilization ("Across all
  instances"), Total Instances; empty state per block: "No data captured in
  the past 48 hours".
- The data already exists: GraphQL `metrics(query: …)` with `name: CPU` /
  `MEMORY` (percentage mode = % of limit — the same utilization definition the
  autoscaler targets) and `INSTANCE_COUNT`; REST equivalents
  `/v1/metrics/{cpu,memory,instance-count}` (`lego/backend/internal/metrics/`).
- The Metrics tab already renders exactly these charts — reuse its components/
  hooks (`dashboard/src/features/metrics/` — `ApplicationMetricsCard` etc.,
  which already carry the cpu/memory %-of-limit charts and empty states) with
  a fixed 48h window rather than building new chart code.
- 48h window: `resolveRange`-style fixed bounds; the metrics feature's range
  presets cap at 1d — pass explicit start/end (now-48h) rather than adding a
  preset, unless reusing a preset is cleaner.
- "Across all instances" = averaged across replicas: check what the Metrics
  tab does (per-instance series); Render shows a single averaged line — an
  average-of-instances transform on the client is acceptable.

## Steps

1. Build a `ScalingRecentMetrics` component with the three blocks, reusing
   the metrics feature's query hook + chart primitives; fixed 48h window.
2. Per-block empty state when the series has no points ("No data captured in
   the past 48 hours") — never a broken chart.
3. Header row: section title + "Showing metrics for the past 48 hours." +
   "View all metrics." link → `/services/$serviceId/metrics`.
4. Mount below the scaling cards on the Scaling page (rendered regardless of
   autoscaling state — Render shows it in both).
5. Locale keys in `dashboard/src/features/services/locales/{en,zh}.ts` (or the
   metrics feature's locales if the component lands there).
