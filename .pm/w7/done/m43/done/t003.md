## Objective

Fix the small divergences the live comparison surfaced in the existing
autoscaling card: the en locale credits "Render" on bex's own dashboard, the
instance-range slider stops at 25 where Render (and bex's own backend) allow
100, the first-enable default target is 75% where Render defaults 60%, and
disabling autoscaling should carry Render's "fixed number of instances under
Manual Scaling" explanation.

## Context

- `dashboard/src/features/services/locales/en.ts:329` —
  `services.scalingInstancesHint` says "Render scales the number of instances
  for this service within the range you specify." The zh sibling
  (`zh.ts:325`) already says "bex 将在你指定的范围内自动调整此服务的实例数量。"
  — en is the one with the leftover Render copy.
- `dashboard/src/features/services/components/autoscaling-section.tsx` — the
  min/max instances range slider caps at 25; the backend validates 1–100
  (`store.MaxReplicas`, `SetAutoscalingRequest`), and Render's slider runs
  1–100 (live capture). Raise the UI cap to 100.
- Default target on first enable: bex pre-fills 75%; Render's live capture
  shows 60% for both CPU and memory. Align to 60.
- Render's disable flow (live capture): a confirm dialog — "Disable
  Autoscaling? Your service will run the fixed number of instances specified
  under **Manual Scaling**." bex's card is draft-based (Save/Cancel), which is
  an acceptable divergence in mechanism, but the disable action should carry
  the equivalent explanation (in the existing confirm affordance or inline
  hint) so the user knows what instance count takes over. Coordinate wording
  with t001's Manual Scaling card.
