## Objective

Add Render's **Manual Scaling** card to the Scaling page: heading + explanatory
copy, an instance slider (1–100) with a numeric input, and a Save Changes
button enabled only when the draft differs from the live count. Shown exactly
when autoscaling is off (Render's mutual exclusion), replacing the Settings
page's "Instance count" stepper as the manual-scale home.

## Context

- Live Render capture (2026-07-16): `/scaling` shows "Manual Scaling — Run
  multiple instances that are automatically load balanced. All instances use
  the same instance type and are billed accordingly." + Instances slider
  (1–100) + spinbutton + Save Changes (disabled until dirty). The card
  disappears while autoscaling is on.
- bex's Scaling route: `dashboard/src/routes/services.$serviceId.scaling.tsx`
  mounts `AutoscalingSection`
  (`dashboard/src/features/services/components/autoscaling-section.tsx`).
- The existing manual stepper: `ScalingRow`
  (`dashboard/src/features/services/components/scaling-row.tsx`), mounted on
  the **Settings** page — w5/m16 placed it there from the docs-fallback
  reconstruction (`docs/render-artifacts/manual-scaling.md`); the live capture
  corrects the placement to the Scaling tab. Render's Settings has no instance
  control.
- Mutation already exists: `useScaleService()`
  (`dashboard/src/features/services/hooks/use-scale-service.ts`) →
  `scaleService(id, numInstances)`; backend validates 1–100
  (`store.MaxReplicas`).
- Current replica count: the service header shows `replicas` from `useServer`;
  the Scaling page has access to the service via the layout's data or its own
  query — check how `AutoscalingSection` gets its data (`useAutoscaling`)
  and reuse the pattern.
- The autoscaling on/off state that gates the card: `useAutoscaling(serviceId)`
  already exposes `enabled`.

## Steps

1. Build a `ManualScalingSection` component (slider + numeric input + Save,
   the same draft/dirty pattern as `ScalingRow`) using `useScaleService` and
   the current `replicas` value; range 1–100.
2. Mount it on the Scaling page above/below `AutoscalingSection`, rendered
   only when autoscaling is disabled (mirror Render's exclusivity both ways:
   enabling autoscaling hides it, disabling reveals it).
3. Remove the `ScalingRow` from the Settings page (and its section wiring);
   keep the component file if `ManualScalingSection` reuses it, otherwise fold
   the logic in and delete.
4. Type-awareness: only service types with a replica concept get the card
   (web/private/worker — mirror the existing `ScalingRow` gating; cron/static
   excluded).
5. Locale keys for the card copy in
   `dashboard/src/features/services/locales/{en,zh}.ts`.
