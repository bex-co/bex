# 042 — Locate recoverable forum uploads and establish durable storage

Why: the retirement preflight found database upload references whose files are already absent from the current forum container; database backups cannot reconstruct missing file bytes.

## Verified 2026-09-06

The three sites share the healthy gen-112 forum Deployment. Its Pod has no volumes. Both `/var/www/discourse/public/uploads` and `/var/discourse/shared/uploads` contain zero files. Database records include 29 custom `/forum/uploads/...` URLs (11 beancount, 8 tianpan, 10 blockeden), apart from built-in image assets — **15 unique SHA-1 objects (~1.7 MiB)**. Requests directly to the running application with each site's Host header returned 25 HTTP 500 and 4 HTTP 404 responses. Public requests returned HTTP 403, so they did not supply recoverable bytes. All three `/forum/site.json` requests returned 200.

The old gen-54 image was inspected across all 34 layers: no files under either upload directory. Keeping or rolling back to that image therefore does not recover these uploads. No application rollout or old-image deletion had happened when this baseline was captured.
