**Done 2026-11-16, ahead of t006 and t007** (the review had to precede the ship; rerun it if the production check changes code): `/simplify` over the milestone's diff through three reviewers (reuse, quality, efficiency). Applied:

- The gate's memory is three caches with their own bounds (tokens until their use ends, known keys for 24 h, refused keys for 60 s), where one cache had kept every key for 24 h and so reset at 4,096 keys a day. A key whose remembered token dies now stays known for the one retry, so a spent per-id budget cannot lock its owner out.
- A source with no failure budget left is shed before a per-client-id budget is allocated for the key it sent.
- What outlives a request (the key's id) is cloned, so it no longer pins the `Authorization` header, and with it the secret, in memory.
- The cache key is the raw SHA-256, the token response goes through `core.DecodeLimitedJSON`, `forget` uses `Identity.IsAPIKey`, the three key parts travel as one `presentedKey`, the failure counter is the nil-safe `*OriginMetrics`, the retry is a boolean, and `bearerKeyPrefix` is unexported.
- Tests read behavior through the fake Hydra instead of the gate's caches; a duplicated CLI case, a tautological dashboard test and three DOM-shape assertions are gone; the script's leg shares one extraction and the existing `assert_bearer_works`.

Dismissed: caching the five metric children and the second source-bucket lookup on a refusal (failure path only, nanoseconds); reusing `cliauth.postForm` or the dashboard's `ConnectionField` and `CodeBlock` (different semantics, per the reuse review).
