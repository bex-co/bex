## Objective

A request whose bearer is an API key string (t001's format) authenticates as that key's workspace machine identity on REST, GraphQL and `/mcp`. Every other credential behaves exactly as before.

## Context

- `lego/backend/internal/api/auth.go`: the bearer is read at `:73`, `middleware` is at `:337`, `introspect` at `:440`, `invalidate` at `:302`, the 401 writer `unauthorized` at `:738`.
- REST, GraphQL and `/mcp` sit behind this one middleware, so one change serves all three.
- `core.WithFreshBearerValidator` (`auth.go:410`) re-validates a bearer before a sensitive read. A key-derived token must pass through it too.
- Hydra's issuer is `BEX_OAUTH_ISSUER` and its admin URL `BEX_HYDRA_ADMIN_URL` (`lego/backend/cmd/api/config.go:439,457`).
- `w21/090` and `w21/091` also change `auth.go`; rebase on whichever has landed.

## Steps

1. Recognize the key prefix on the bearer. Anything else takes today's path unchanged.
2. Exchange the key for an access token at Hydra's token endpoint. Cache the token per replica under SHA-256 of the key, expiring before the token does. Collapse concurrent misses into one exchange.
3. Continue through `introspect` with that access token, so identity, tenancy, `TouchAPIKey`, audit attribution and rate-limit keys are those of the key's client id.
4. Revocation: a cached token fails introspection within `introspectionTTL`. Drop the cache entry on any introspection failure and in `invalidate`.
5. Every failure answers `unauthorized` unchanged. A Hydra outage answers the existing 503, never a 401.
6. Tests in `lego/backend/internal/api`: a valid key on REST, GraphQL and MCP; a wrong secret; an unknown client id; a malformed key; a revoked key refused within the window; cache expiry re-exchanges; Hydra down answers 503; a key of workspace A cannot read workspace B.

**Done 2026-11-16:** `lego/backend/internal/api/auth_apikey.go`: a bearer with the key prefix is parsed, exchanged at `{BEX_OAUTH_ISSUER}/oauth2/token` (form body, `client_secret_post`), and its access token remembered per replica under SHA-256 of the key until one minute before expiry; concurrent misses share one exchange; the token then takes `introspect` unchanged and the fresh-bearer validator uses it. `invalidate` and any introspection failure drop the remembered token; a dead token with a live client costs one more exchange, not a 401.
