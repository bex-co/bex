## Objective

Guessing at a key is bounded and visible to operators, and no key material reaches a log, a trace or a metric label.

## Context

- Each exchange makes Hydra hash a secret, so wrong keys cost CPU and are a guessing surface that the exchange-only model kept at Hydra's own endpoint.
- bex-api already has a per-caller token-bucket limiter (`BEX_RATE_LIMIT`, `BEX_RATE_BURST`; ADR018 § API contract).
- ADR012 §8: a failure must not tell a real client id from garbage.

## Steps

1. Negative-cache a failed key by its hash for a short interval, so repeats do not reach Hydra.
2. Bound failed attempts per client id and per source address. Past the bound, answer 429 with `Retry-After` and the same body whether or not the client id exists.
3. Count failures in a metric that has neither the key nor the client id as a label, and add an alert rule for a sustained failure rate.
4. Prove with a log-capture test that the key never appears in access logs, error logs, audit rows or error text.

## Acceptance criteria

- [ ] Repeated wrong keys are answered from the negative cache and then rate-limited; a valid key from the same source works again after the window.
- [ ] No log line, audit row or metric label carries key material (test).
- [ ] The alert rule passes its promtool test and `bash scripts/gitops-validate.sh`.

## Out of scope

- IP reputation or blocklists.

**Done 2026-11-16:** a refused key is remembered by SHA-256 for 60 s; every refusal spends the source's `BEX_AUTH_FAILURE_LIMIT` budget and a source with none left gets 429 with `Retry-After` and one body; refused exchanges are bounded at 10 a minute per client id per replica, with a key the replica already knows exempt so guesses at an id cannot lock its owner out; a valid key the replica holds a token for is never shed. `bex_api_apikey_bearer_failures_total{reason}` counts failures (no key or client-id label), `ApiKeyBearerFailuresSustained` warns above one a second for 15 minutes (`deploy/gitops/base/rules/api_key_bearer_alerts_test.yml`; three wrong thresholds each fail it), with a panel on the bex-api gateways dashboard. `TestAPIKeyBearerNeverLeavesTheGate` captures the log, the responses, an error and every metric label and finds no key or secret; the surfaces test checks the audit rows. `scripts/gitops-validate.sh` passes. Against a real Hydra: the 58th wrong attempt from one source answered 429.
