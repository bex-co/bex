## Objective

Make build Job pods carry the labels the log shipper needs to attribute their lines to the owning App and workspace: App name, tenant/namespace, and deploy identity (the Job is already named `bld-<name>-gen-<generation>`).

## Context

- Build Jobs are created by the operator (`lego/operator/internal/build/`) and run in `BEX_BUILD_NAMESPACE` (or the App's own namespace).
- The w3/m5 log-shipper (Alloy DaemonSet, manifests under `deploy/gitops/base/`) discovers pods and stamps stream labels; app pods are attributed today, build pods are not scraped.

## Steps

1. Add stable labels to the build Job's pod template: owning App name, App namespace/tenant, generation.
2. Keep label cardinality bounded — no per-build unique labels beyond the existing Job-name pattern.
3. Assert the labels in an operator envtest.

## Files

- `lego/operator/internal/build/`
- `lego/operator/internal/controller/` (Job creation call sites)

## Acceptance criteria

- [ ] A build Job's pod template carries App + tenant + generation labels, asserted by envtest.

- Shipper config (t002); backend serving (t003).
