## Objective

Prove build-log streams are scoped to the owning workspace exactly like app logs: a cross-tenant caller reads nothing, and `list_log_label_values` never surfaces another tenant's build labels.

## Context

- w3/m8's label discovery is "always scoped to the requested service's streams (no cross-tenant label leakage)" — build streams must inherit that property.
- Builds may run in a shared `BEX_BUILD_NAMESPACE`, so namespace alone is NOT the tenant boundary — the t001 App/tenant labels are.

## Steps

1. Verify the Loki selector for `type=build` keys on the App/tenant labels, not the namespace.
2. Add a test: two Apps in different workspaces, caller A queries `type=build` and label values — sees only their own.

## Files

- `lego/backend/internal/logs/`

## Acceptance criteria

- [ ] Cross-tenant `type=build` query and label discovery return nothing foreign, asserted by test.
