## Objective

Render the new event types end to end in the dashboard so they appear as filterable, labeled, icon-bearing rows on the Events page and as annotations on the metrics charts — consistent with how Render presents Build/Deploy/Pre-deploy lifecycle beats.

## Context

- Event catalog + filter groups: `dashboard/src/features/events/service-event-catalog.ts` (grouped multi-select, 5 categories — Deploy/Service Status/Scaling/Maintenance/Configuration; `serviceEventLabelKey` maps type → i18n key).
- Row rendering: `dashboard/src/routes/services.$serviceId.events.tsx` (`EventIcon` at ~lines 79-113 — Rocket/Check/X/Pause/Play/Refresh/Scale; status badge at ~433-437; expandable details at ~455-520).
- Metrics event-markers (already exist): `dashboard/src/routes/services.$serviceId.metrics.tsx` + `dashboard/src/features/metrics/locales/{en,zh}.ts` (`metrics.eventMarker*` keys) — add labels for the new types.
- GraphQL passthrough: `dashboard/src/features/services/api/events.graphql` reads a generic `type` + typed `details`, so new types need no query change; only catalog/label/icon/marker entries.

## Steps
