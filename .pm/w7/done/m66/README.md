## Definition of done

On the Events tab (`/services/<name>/events`) of a service, and equally over REST/GraphQL/MCP:

1. **Build lifecycle is its own pair of events.** A repo/Dockerfile-backed deploy produces a `build_started` event when its BuildKit build Job begins and a `build_ended` event (with `details.status` succeeded|failed|canceled) when it finishes — distinct rows from `deploy_started`/`deploy_ended`, matching Render's timeline. The events are derived from a durable source (the control-plane reconciler observing `App.status` build phase, the same path `image_pull_failed`/`server_failed` facts already ride), never faked; image-backed services with no build phase emit neither.
2. **Pre-deploy is its own pair of events.** When a service has a pre-deploy command, its Job start/finish surface as `pre_deploy_started` and `pre_deploy_ended` (`details.status`) events, in addition to the existing `preDeployStatus` still carried on `deploy_ended` (kept for back-compat). Services with no pre-deploy command emit neither.
3. **One-off jobs report completion.** A one-off job that finishes surfaces `job_run_ended` with `details.status`, alongside the existing `job_started`/`job_canceled`.
4. **`branch_deleted`** fires when the tracked git branch is deleted (auto-deploy disabled), _or_ — if the GitHub App delivers no clean branch-delete signal bex can key on — t004 instead records it as a documented non-goal in `service-events.md` + ADR018 with the exact reason (no silent omission).
5. **Every new type renders end to end:** it appears in the dashboard Events filter under the right group, with an icon, an i18n label (en + zh), status badge where applicable, and a metrics-chart event-marker label; it round-trips through REST (`type=` filter + bare `{event,cursor}` array), GraphQL `serviceEvents`, and MCP `list_service_events` with the same field set.
6. **The stale omission note is corrected.** `internal/events/service.go`'s package doc no longer claims `build_started/build_ended` "have no accepted bex mechanism or durable source"; `docs/render-artifacts/service-events.md` and the ADR018 parity rows reflect the newly-supported types and the still-true non-goals (`disk_*`, `artifact_*`, `server_hardware_failure`, `maintenance_started`/`_ended`, `pipeline_minutes_exhausted`, `zero_downtime_redeploy_*`, `initial_deploy_hook_*`, preview/workflow).
7. **Guards hold:** `TestEveryTargetedVerbIsNamedOrExcused`, `TestEventSurfaceParity`, and `scripts/events-verify.sh` pass with the new types; the events feed still admits no arbitrary value (facts remain structurally redacted — typed scalar columns only).
