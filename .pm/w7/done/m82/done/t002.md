## Objective

Replace the blunt `BackoffLimit: 1` — which spends a doomed second attempt on deterministic failures and still lets a node drain fail the deploy — with a `podFailurePolicy` that retries exactly the class where retrying can change the outcome.

## Context

- `lego/operator/internal/build/build.go:472` declares `backoff := int32(1)` ("one build attempt; a failed build is a user error, not a flake to retry"), applied at `:649`. Production contradicts the comment in both directions: deterministic failures **are** retried (two pods per failing build, measured 2026-08-17), and infra failures **are** fatal.
- `lego/operator/internal/build/build.go:586` — the `cluster-autoscaler.kubernetes.io/safe-to-evict: "false"` annotation is the current workaround; its comment records the symptom (a build pod evicted repeatedly until `BackoffLimitExceeded` "with no application-code fault"). It also blocks legitimate node consolidation.
- `podFailurePolicy` is GA since Kubernetes 1.31; the cluster runs v1.34.9.
- ADR060 D2: `Ignore` on the `DisruptionTarget` pod condition, `FailJob` on tenant-error exit codes, `backoffLimit: 2` for everything else. OOM (137) is deterministic at this size and must never retry — `DisruptionTarget` is not set for OOM so the policy already gets this right, but assert it.
- `lego/operator/internal/predeploy/predeploy.go:26` — pre-deploy keeps `BackoffLimit: 0` with no `Ignore` rule; a disruption mid-migration must not re-run a partially applied migration.

## Steps

1. Add `podFailurePolicy` to the build Job: `Ignore` on `DisruptionTarget`, `FailJob` on t001's tenant-error codes, `backoffLimit: 2` for the unclassified remainder.
2. Remove the `safe-to-evict: "false"` annotation and record in the comment why it is no longer needed (disruption is now absorbed, not prevented).
3. Assert OOM never retries.
4. Leave pre-deploy untouched and add a test pinning that it still has `BackoffLimit: 0` and no `Ignore` rule, so a future sweep does not generalize this change onto it.

## Acceptance criteria

- [ ] A pod failed with a tenant-error exit code produces exactly one attempt.
- [ ] A pod carrying the `DisruptionTarget` condition retries without consuming the backoff budget.
- [ ] An OOM-killed build does not retry.
- [ ] `safe-to-evict: "false"` is gone from the build pod annotations.
