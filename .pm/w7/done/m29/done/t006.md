## Objective

Automate what the drills made automatable: if a drill produced/changed a script, add a structural check (the `scripts/gitops-validate.sh` pattern) or a scripted verification step so the next drill is cheaper. Never fake coverage — if nothing is automatable, record why.

## Acceptance criteria

## Outcome

**Added: etcd image version guard in `scripts/gitops-validate.sh`**

The key drill finding was that `registry.k8s.io/etcd:3.5.15-0` lacks `etcdutl` (needed for `snapshot restore`). The CronJob image was updated to `3.6.8-0`, and a CI check now enforces that it stays ≥3.6.x:

```sh
etcd_minor="$(echo "$etcd_img" | grep -oE '3\.[0-9]+' | head -1)"
etcd_m="$(echo "$etcd_minor" | cut -d. -f2)"
if [ "$etcd_m" -lt 6 ]; then FAIL; fi
```

This runs in CI on every gitops change and prevents a future image downgrade from silently breaking the restore path.

**Not automatable:**
- The OpenBao fresh-node restore path requires a live OpenBao instance — no structural manifest check is feasible in CI.
- The bex-db `bootstrap.recovery` path already has the `bex-db backup guard` check from w2/m27 (`barmanObjectStore` must be present). No further structural check is possible without a live CNPG cluster.
- The S3 path correction (`bex-db/bex-db/`) is a documentation fix; a CI check would require live S3 access.
