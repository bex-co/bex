# 051 — A rollback deploy's trigger reads "Rollback To Dep-Dakvlk8dp28s73ek2h9g": CSS title-casing mangles the deploy id inside the label

> **WITHDRAWN 2026-09-16 — duplicate.** Another session's live QA run filed the same defect as **`w4/m108/t005`** ("The rollback trigger label stops title-casing the deploy id it names", committed in `879ba2aa9`), and that milestone's definition of done covers both render sites this note names plus the sibling-label re-check. `w4/m108` owns the fix; this note stays only as the second, independent reproduction. Do not schedule it.

Why: the one trigger label that embeds an identifier is wrapped in `capitalize`, so the id it names comes out title-cased and no longer matches the id printed everywhere else on the same page. A user comparing "which deploy did this restore?" — or copying the id into the CLI or a support message — is reading a string the platform never minted.

## Repro (run end to end this sweep)

1. Create a web service; let its first deploy go Live (`dep-dakvlk8dp28s73ek2h9g`).
2. Change any setting that redeploys (this run saved `MESSAGE=qa-rb-v2`) → second deploy `dep-dakvmv557grc738qmma0`, trigger **Config Change**.
3. On `/services/<id>/deploys`, press **Rollback** on the first deploy's row and confirm **Proceed** in the "Roll back to this deploy?" dialog.
4. Read the new deploy's **Trigger** cell.

**Actual** — the restored deploy's id is title-cased, so it no longer matches the `dep-…` id in the same row's identity column:

```text
Live         dep-dakvq5j3hm6c73bir82g   Rollback To Dep-Dakvlk8dp28s73ek2h9g   0s
Deactivated  dep-dakvmv557grc738qmma0   Config Change                          1m 11s
Deactivated  dep-dakvlk8dp28s73ek2h9g   First Deploy                           1m 13s
```

The underlying data is correct — `rollbackService` returned `{"id":"dep-dakvq5j3hm6c73bir82g","rollbackOf":"dep-dakvlk8dp28s73ek2h9g"}` — so this is presentation only.

**Expected:** the label reads `Rollback to dep-dakvlk8dp28s73ek2h9g` (or "Rollback" with the id in the same monospace treatment the page uses elsewhere). Ids are case-sensitive opaque strings (`docs/ADR020-identifiers.md`); `Dep-Dakvlk8dp28s73ek2h9g` is not one.

## Root cause

- `dashboard/src/features/deploys/locales/en.ts:123-127` — `deploys.triggerRollback` is `"rollback to {deployId}"`, the **only** trigger label that interpolates an identifier. The others are plain words (`first deploy`, `config change`, `manual deploy`, `deploy hook`, `blueprint sync`, `new commit`).
- Every render site wraps that label in Tailwind's `capitalize` (CSS `text-transform: capitalize`), which upper-cases the first letter of **every whitespace-separated word**, including the id:
  - `features/deploys/components/deploys-list-page.tsx:243` (the narrow-width fold) and `:248` (the wide table cell) — both `className="… capitalize"` around `triggerLabel(d, t)`.
  - `features/deploys/components/deploy-header.tsx:105-107` — `<span className="text-xs capitalize …">{triggerLabel(deploy.trigger, deploy.rollbackOf, t)}</span>` on the deploy **detail** page. Same shape, same `triggerLabel` (`:19-27`); observed live only on the list, so the header instance is code-verified rather than seen.
- The wrapper was harmless until a label carrying an id joined the set, which is why this survived `w2/done/016` (which added the humanized trigger words).

## Fix

Stop title-casing the interpolated label. Either drop `capitalize` from those three spans and ship the labels already capitalized in the locale files (en + zh), or split the rollback label so only the leading word is transformed and the id renders verbatim — ideally in the same `font-mono` the page already uses for `deploy.id` (`deploy-header.tsx:108-110`). Keep the other trigger words rendering exactly as they do now.

## Blast radius

- Three spans in two components, one shared `triggerLabel` helper per component (`deploys-list-page.tsx:75-80`, `deploy-header.tsx:19-27`).
- Other `capitalize` spans in the dashboard were checked and are **safe** — each wraps a single word, never an id: blueprint resource type (`routes/blueprints.$blueprintId.tsx:472-473`), charge tier (`features/usage/components/charges-card.tsx:79-81`), agent name (`features/agent-sessions/components/session-list.tsx:343-345`), service runtime (`features/services/components/service-detail-header.tsx:151`).
- Regression coverage should assert the rendered rollback label keeps the id's exact case, and that a non-rollback trigger still renders its capitalized word.

## Adjacent classes

- Nothing about rollback behavior changes: `w1/m152` (rollback restores the target's configuration) and `w2/done/m10` (rollback/cancel semantics) are untouched.
