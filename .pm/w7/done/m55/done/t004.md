## Objective

The t001–t003 matrices use an authz fake, so they catch wiring regressions but not FGA-**model** regressions (a schema change that makes `can_view` resolve true for non-members would pass them). Extend `TestMultiWorkspaceTargetingE2E` from its current 3 routes to a representative route per service, running against real OpenFGA tuples, so a model regression fails CI too.

## Context

- `lego/backend/internal/api/multiworkspace_e2e_test.go:54` — the existing E2E: real Postgres + OpenFGA, two workspaces, currently POST/DELETE/GET `/v1/services` only.
- These integration tests are **not skipped in CI**: `backend-test.yml` runs them against ephemeral Postgres + OpenFGA containers (CLAUDE.md), so added coverage is enforced, not optional.
- One route per service is the right depth — the fake-checker matrices (t002/t003) already cover breadth; this layer only needs to exercise each service's FGA object type + relation against the real model.

## Steps

1. Pick one representative read and one write route per service (each distinct FGA object type/relation at least once).
2. Extend the E2E fixture to provision the needed workspace-B resources.
3. Assert non-member deny on each; keep runtime reasonable (shared fixture, no per-case store re-seed).

## Acceptance criteria

- [ ] Every service (each FGA object type) has at least one real-FGA non-member deny assertion for a read and a write.
- [ ] Suite passes locally against `BEX_TEST_DB_URI`/`BEX_TEST_OPENFGA_URL` and in CI.

## Out of scope

- Exhaustive per-route E2E (breadth belongs to the fake-checker matrices).
