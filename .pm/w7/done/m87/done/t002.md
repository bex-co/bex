## Objective

Add the smallest durable, opaque environment revision needed by the confirmed cases, stable for unchanged effective input and invalidated when a build-relevant value changes.

## Context

- AppReconciler.projectNativeBuildEnv merges linked groups and service-owned values into the App-owned native environment Secret; literal spec.env values take precedence in nativeBuildPreparer.
- The revision must cover the inputs actually used by the build, including additions/removals and the no-environment state, while preserving source ownership and namespace checks.

## Steps

1. Use t001's reproduction to choose a revision mechanism and record its stability, secrecy, and update rules.
2. Carry a non-secret revision alongside the resolved build environment. Include literals and all effective Secret sources with the existing precedence; preserve exact bytes.
3. Keep the revision stable on repeated reconciliation and persist enough state to survive operator restarts and Secret replacement. Preserve fail-closed required-source reads.

- `lego/operator/internal/controller/app_controller.go (projectNativeBuildEnv and native dispatch)`

## Acceptance criteria

- [ ] Each confirmed build-input change invalidates the revision, including removal and replacement of a source.
- [ ] Unchanged input does not acquire a fresh revision merely because of reconciliation or a new deploy.
- [ ] Raw, reversibly encoded, or unkeyed hashes of secret values do not become cache metadata, logs, or image metadata.
- [ ] Existing optional-source behavior, required-source failure, literal-over-Secret precedence, and cross-App ownership checks remain intact.

## Out of scope

- A new secret-management system or per-workspace cache service.
- Changing save-only versus deploy/rebuild semantics or adding a backend import to the operator.
