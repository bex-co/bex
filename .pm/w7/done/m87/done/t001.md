## Objective

Establish the actual cache-enabled failure with the same source commit and two synthetic environment values before choosing an invalidation mechanism.

## Context

- lego/operator/internal/build/native.go passes the environment through the render-env BuildKit secret; nativeDockerfile does not include an environment-version input.
- lego/operator/internal/build/build.go imports the per-App cache when BEX_BUILD_CACHE=registry. Docker documents that secret contents do not invalidate cached RUN instructions.
- w7/done/m86 proves repeated-build speed and cache-loss fallback. w4/done/m92 and m93 prove environment bytes and group delivery, without this warm-cache transition.

## Steps

1. Extend the existing opt-in build drill with a fixed commit and a command that writes a synthetic MESSAGE value into a build artifact. Keep source/context bytes constant and prove the initial cache hit.
2. Build with MESSAGE=A, change only the effective environment to B, and rebuild normally with caching enabled. Compare the generated artifact and cache-step output, plus a cache-disabled control.
3. Repeat for a service-owned Secret and a linked group. Record which cases actually reproduce; if the premise is disproved, document the evidence and reshape the remaining scope instead of implementing an unnecessary mechanism.
