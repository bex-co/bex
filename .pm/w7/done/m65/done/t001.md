## Objective

Replace every third-party GitHub Action tag ref in `.github/workflows/*.yml` with its full 40-hex commit SHA plus a trailing `# vX.Y.Z` comment, so a retagged upstream release can never change what runs in bex's CI. Sync `scripts/github-actions-validate.sh`'s `expected_actions` inventory in the same change (its diff check would otherwise go red immediately).

## Context

- 42 third-party `uses:` entries across the 14 workflows: 16× `actions/checkout@v7`, 6× `aquasecurity/trivy-action@v0.36.0`, 5× `actions/setup-go@v7`, 3× `docker/build-push-action@v7`, 2× `actions/cache@v6`, 2× `actions/setup-node@v7`, and 8 singles (`anchore/sbom-action/download-syft@v0`, `azure/setup-helm@v5`, `azure/setup-kubectl@v5`, `docker/login-action@v4`, `docker/setup-buildx-action@v4`, `hashicorp/setup-packer@v3`, `hashicorp/setup-terraform@v4`, `sigstore/cosign-installer@v3`).
- 3 local reusable-workflow refs (`uses: ./.github/workflows/{operator,dashboard,backend}-test.yml`) are exempt — path refs to this repo, leave unchanged.
- Resolve each tag with `gh api repos/<owner>/<repo>/git/ref/tags/<tag> --jq '.object | .type + " " + .sha'`; when the type is `tag` (annotated), dereference to the commit via `gh api repos/<owner>/<repo>/git/tags/<sha> --jq .object.sha`. Pin the *commit* SHA, never the annotated-tag object SHA.
- Subpath action `anchore/sbom-action/download-syft` keeps its subpath: `anchore/sbom-action/download-syft@<sha> # v0.x.y`.
- The comment survives the guard's extraction (`[^[:space:]#]+` stops before `#`) and is the convention Dependabot understands and rewrites when updating SHA pins (t003).
- `scripts/github-actions-validate.sh:8-21` holds the reviewed inventory as tag refs; rewrite the entries as `owner/repo@<sha>` to match the new reality (t002 then adds the 40-hex invariant).

## Steps

1. For each of the 14 distinct action refs, resolve the current tag to its peeled commit SHA (record the exact version the tag pointed at for the comment — for major-version tags like `v7`, note the concrete `vX.Y.Z` the SHA corresponds to).
2. `sed`/edit every `uses:` entry in `.github/workflows/*.yml` to `owner/repo[/subpath]@<40-hex> # vX.Y.Z`; leave the 3 `./` refs alone.
3. Update `expected_actions` in `scripts/github-actions-validate.sh` to the new SHA-pinned refs (keep it sorted to match the `sort -u` extraction).
4. Run `bash scripts/github-actions-validate.sh` locally — must PASS.
5. Push/PR and confirm all workflows still resolve and run green at the pinned SHAs.
