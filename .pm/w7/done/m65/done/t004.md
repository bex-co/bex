## Objective

Give the dashboard's npm tree the vulnerability gate Go and images already have: a `yarn npm audit` step in `dashboard-test.yml` where CRITICAL advisories fail the job and HIGH advisories are reported without failing (the m10 Trivy policy: CRITICAL gate / HIGH warn). Because `deploy.yml` calls `dashboard-test.yml` as a reusable workflow (`workflow_call`), the gate automatically blocks image build+push too — no deploy wiring needed.

## Context

- `dashboard-test.yml` already sets up corepack/yarn 4.17.0 (`packageManager` pin) and runs `yarn install --immutable`; the audit step slots in after install, before typecheck+lint+test.
- Yarn 4's auditor: `yarn npm audit --all --recursive --severity critical` exits non-zero when matching advisories exist; run it twice — a `--severity high` reporting pass with `continue-on-error: true` (or `|| true`) for visibility, then the `--severity critical` gating pass. Verify the exact exit-code semantics of yarn 4.17.0's audit against a known advisory before trusting the gate (yarn audit exit behavior has shifted across majors).
- No new binary to checksum-pin (the m62 concern): the auditor ships inside the corepack-pinned yarn itself and queries the npm registry advisory DB. If yarn 4.17's audit proves unusable (flaky registry endpoint, wrong exit semantics), fall back to `osv-scanner` against `dashboard/yarn.lock` — but then it must be version+checksum-pinned like gitleaks in `deploy.yml`.
- False-positive escape hatch: document (in the step comment) that a non-exploitable CRITICAL is suppressed via yarn's `npmAuditExcludePackages`/advisory-ignore mechanism in `.yarnrc.yml` with a justification comment — never by removing the gate.

## Steps

1. Reproduce locally: `cd dashboard && yarn npm audit --all --recursive` — confirm output shape and exit codes at severity thresholds (temporarily add an old known-vulnerable dev-dep to see a hit, then drop it).
2. Add the two audit steps to `dashboard-test.yml` (HIGH warn pass, CRITICAL gate pass) with a comment naming the policy and the suppression mechanism.
3. Triage the current tree's existing advisories, if any: fix cheap upgrades now; suppress-with-justification anything non-exploitable so the gate lands green, and record leftovers for `w1/006` triage.
4. Confirm the job fails when a CRITICAL is present (re-use the step-1 known-vulnerable dep on a branch) and passes on main.
