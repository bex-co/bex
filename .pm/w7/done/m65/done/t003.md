## Objective

Add `.github/dependabot.yml` so the SHA pins from t001 stay fresh without manual tag-resolution toil (`github-actions` ecosystem — Dependabot rewrites SHA pins and their `# vX.Y.Z` comments in update PRs) and the dashboard's npm tree gets automated update PRs (`npm` ecosystem for `dashboard/`), which today has no dependency-update mechanism at all.

## Context

- `.github/dependabot.yml` does not exist (verified 2026-07-31).
- The w7 README's "Not in w7 (deliberate)" boundary: **Dependabot *triage* stays `w1/006`** (sub-hour alert triage; promote only if fixes need breaking upgrades). This task adds the *config*; reviewing/merging the resulting PRs is w1/006's lane — note that in the config file's header comment so the boundary is discoverable.
- Update PRs will trigger `scripts.yml`'s validator (t002): a Dependabot actions bump must also update `expected_actions` in `github-actions-validate.sh` or CI goes red on the PR — that is *intended* fail-closed behavior (the reviewed-inventory step from the script's header: check upstream action.yml/permissions before accepting), but it means actions PRs need a human touch; say so in the header comment.
- Keep noise low: weekly schedule, grouped updates where supported (e.g. group all `actions/*` minor/patch bumps; group dashboard dev-dependency patches).
