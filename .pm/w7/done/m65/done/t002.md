## Objective

Make the SHA-pinning property permanent: extend `scripts/github-actions-validate.sh` so any third-party `uses:` ref that is not a full 40-hex commit SHA fails CI, and add a self-test proving the guard actually goes red (the m60/m62 anti-tautology pattern) — the inventory diff alone would not catch a future entry that is added to both the workflow and the inventory as a tag.

## Context

- `scripts/github-actions-validate.sh` runs in `scripts.yml` ("GitHub Actions Node 24 inventory" step) on every PR touching `.github/workflows/**` or `scripts/**`.
- Its extraction already isolates refs: `grep -rhoE 'uses:[[:space:]]+[^[:space:]#]+' .github/workflows/*.yml | awk '{print $2}' | grep -v '^\./'` — the new check is: every extracted ref must match `@[0-9a-f]{40}$`.
- Self-test convention: sibling `*.test.sh` files in `scripts/` (e.g. `bao-init.test.sh`, `deploy-superseded.test.sh`) run in `scripts.yml`; the test should exercise the validator against a fixture tree (temp dir with a fake workflow) rather than mutating the real one — check how existing `.test.sh` files fake inputs and follow that shape (the validator may need an overridable workflows dir or a function-extraction seam to be testable; keep the seam minimal).
- Anti-tautology requirement: the self-test must prove both directions — a tag-pinned ref (`actions/checkout@v7`) turns the check red, and a 40-hex ref passes.

## Steps

1. Add the 40-hex check to `github-actions-validate.sh` after the inventory diff: fail with a named FAIL message listing each offending ref.
2. Make the workflows glob overridable (e.g. `WORKFLOWS_DIR` defaulting to `.github/workflows`) so the self-test can point it at fixtures without touching the real tree.
3. Write `scripts/github-actions-validate.test.sh`: fixture with one SHA-pinned ref → PASS path assertions; fixture with a tag ref → asserts exit 1 and the FAIL message; fixture with a `./` local ref → still PASS (exemption preserved).
4. Wire the self-test into `scripts.yml` next to the existing `.test.sh` steps.
