# Render's plan table limits workspaces per plan and keeps enforced 2FA to Pro and higher; bex does neither

Why: two rows of Render's plan comparison table disagree with what bex does today, and with an earlier reading of Render's docs, so either bex or ADR018 is wrong.

- Found by w7/m429 t005, 2026-11-16 (`lego/backend/internal/pricing/plan_table_test.go` names this note for both rows).
- Render (render.com/pricing comparison table, read 2026-11-16, captured in `docs/render-artifacts/pricing.md`):
  - "Workspaces: 1 | 1 | Unlimited | Unlimited". bex lets one user own five Hobby workspaces and unlimited paid ones (`store.LimitsFor` `MaxWorkspacesPerUser`, from `.pm/w6/RESEARCH-workspaces.md`). Render's row may count workspaces per organization (Scale and Enterprise "support managing multiple workspaces in a unified organization", render.com/docs/platform-features-by-plan) rather than per user.
  - "Enforce 2FA & Google login: — | ✓ | ✓ | ✓". bex lets any workspace admin on any plan require 2FA (w22/m402); ADR018's Workspace-enforced 2FA row says Render's login-settings page lists no plan requirement.
- To decide: read both rows against Render's own docs and, where possible, a Hobby workspace's settings page; then either gate enforcement to Pro and higher as a `core.PlanFeature` (a workspace that already enforces it keeps it, ADR030 §9), or record why the table row does not apply, in ADR018 with the user's sign-off. Same for the workspace count.
- Done when: each row has a verified disposition in ADR030 §9 and `plan_table_test.go`, and ADR018's rows say which Render source wins.

**Done 2026-11-17.** Both rows were read against Render's own pages (login-settings, team-members, organizations and platform-features-by-plan, all read 2026-11-17).

- **Enforce 2FA & Google login: gated to Pro and higher.** login-settings names a plan only for SAML SSO. The pricing table is the only Render source that states a plan for enforcement, so it wins. This is a recommendation under parity first, not a user decision, and a Hobby workspace's settings page could not be checked (no Render account).
  - Code: `core.FeatureTwoFactorEnforcement`. `setWorkspaceRequireTwoFactor` refuses to turn it on below Pro with 400 `PLAN_FEATURE_REQUIRED` (`feature` `twoFactorEnforcement`). A workspace that already enforces it keeps it, can re-send it and can turn it off.
  - Dashboard: below Pro the card shows the plan notice, the switch cannot be turned on, and an admin gets a Change plan link.
  - Production (read-only, 2026-11-17): no workspace on any plan enforces 2FA (74 Hobby, 4 Pro, 3 Scale, 1 Enterprise).
  - The Google-login half does not exist in bex: filed as 078.
- **Workspaces: per user is team-members' rule; the row counts an organization's workspaces.** team-members says "up to five Hobby workspaces" and "an unlimited number of paid workspaces", which is `store.LimitsFor` `MaxWorkspacesPerUser`, unchanged. The pricing row's "1 | 1 | Unlimited | Unlimited" is the workspaces one plan's account holds: organizations, on Scale and Enterprise, "can contain unlimited workspaces at no additional cost". bex has no organizations, so each paid workspace pays its own fee. Filed as 077 (needs a user decision).
- Recorded in ADR030 §9, ADR018 (the Workspace-enforced 2FA row and a new Workspaces per user row), ADR012 §9a and `plan_table_test.go` (`gate(core.FeatureTwoFactorEnforcement)`, and `checkWorkspaces` for the row's reading and the per-user caps).
