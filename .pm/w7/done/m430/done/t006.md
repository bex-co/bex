## Objective

Once the production pin and GitOps carry the milestone, prove definition-of-done items 1–4 on production with an owned database.

## Context

- The definition of done in `.pm/w7/m430/README.md`.
- A lock wait needs two sessions on the database's external URL: one holds a row lock in an open transaction, the other updates the same row and waits.

## Steps

1. Confirm the newest `pin platform images to <sha>` commit on main contains this milestone's commits and that the Prometheus change has synced. If not, park the milestone in `blocked/` with that release gate named.
2. In `bex-canary`, create a Postgres (free if the workspace's free slot is open, otherwise the smallest paid plan for under an hour). Run a few minutes of inserts, reads and a bulk write.
3. Hold a row lock in one session for about three seconds while a second session waits on it, then let it finish. Repeat once with a wait well under one second.
4. Read every new metric through REST, GraphQL and MCP and on the dashboard. The long wait is counted once after it completes; the short one is not.
5. On an existing canary Key Value and a canary service with a disk (create one only if none exists), read Disk Activity and Disk Operations.
6. Query the metrics store for one new series on an ordinary service pod: it must be absent.
7. Record the evidence in the milestone README, delete the fixtures with by-id `GET` 404 evidence, and update ADR018's Extended metrics row from ◐.
