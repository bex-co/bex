## Objective

The metrics store holds the series t001 chose for transactions, network and disk I/O, for tenant datastore pods and pods with a persistent disk only, attributable to one resource.

## Context

- `deploy/gitops/base/prometheus.yaml`: the `cnpg-tenant-db` job (`:863-889`) keeps `cnpg_backends_total|cnpg_pg_replication_.*|cnpg_collector_pg_wal_archive_status|cnpg_pg_stat_archiver_seconds_since_last_archival`; the `kubernetes-cadvisor` job (`:468-490`) drops rows whose `container` label is empty, which is where pod-level network counters sit; the kubelet job keeps `kubelet_volume_stats_(used|capacity|available)_bytes` (`:760`); the Valkey exporter is scraped by `valkey-instances`.
- Existing datastore queries select by namespace and the immutable `dpg-`/`red-` id (`lego/backend/internal/metrics/datastore.go`), and service queries by `app_id` (w8/m124).
- Cardinality is a standing concern: w4/m144 (replay memory) and `w7/m427` t001's sizing.

## Steps

1. Widen the keep lists for exactly the series t001 chose. For pod-level rows, keep them only for datastore pods and pods that mount a persistent disk (select on the pod labels the operator sets), so every other pod's rows stay dropped.
2. Make sure each kept series carries the labels the existing datastore and service selectors need, with no cross-tenant label.
3. Add promtool tests for any recording rule added, and keep `scripts/gitops-validate.sh` green.
4. After the rollout, read the head-series count before and after on production and record the growth in the milestone README and in `w7/m427`'s README (or its done copy), so the 30-day sizing can be re-checked.
