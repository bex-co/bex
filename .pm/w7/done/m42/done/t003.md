## Objective

Make a Render-shaped logs deep link prefill the bex Logs view: accept Render's
`t` (log type) and `r` (time range) query-string keys as inbound aliases and
normalize them to bex's canonical keys, so a user pasting a Render logs URL shape
(`?t=app&r=1h`) lands on the equivalent bex-filtered view. Mirrors the
w7/m39 Render-route-compat precedent (Render-shaped deep links resolve to bex's
own routes).

## Context

- Render's logs URL: `?t=app&r=1h` — `t` = type (`all`/`app`/`request`), `r` =
  range (`1h`, `6h`, …). Verified live on `dashboard.render.com/.../logs`.
- bex's canonical keys (from t001): `type`, `range`, etc. This task only adds
  inbound aliasing at parse time — bex still writes its own canonical keys.
- `dashboard/src/features/logs/lib/log-search.ts` — `parseLogSearch()` is the one
  place to accept the aliases (before validation), so both the route loader and
  any test go through it.
- Render's range tokens map 1:1 onto bex's `RANGE_PRESETS` (`1h`, `6h`, `1d`, …);
  `30m`/`3h`/`12h` are bex supersets — an `r` value bex doesn't have falls back
  to the default range (t001's bad-value rule).

## Steps

1. In `parseLogSearch`, before validating, fold `t`→`type` and `r`→`range` when
   the canonical key is absent (canonical wins if both present, so bex's own
   written URL is authoritative). Accept Render's `application` alias for `app`
   (bex-api already treats it as an alias — keep the UI consistent).
2. Do not re-emit `t`/`r` on navigation — bex writes canonical keys only, so the
   URL self-heals to bex's shape after the first interaction (the w7/m39
   redirect-normalization pattern).
3. Add a short comment in `log-search.ts` documenting the accepted Render aliases
   and that they are inbound-only.

## Files

- `dashboard/src/features/logs/lib/log-search.ts`

## Acceptance criteria

- [ ] Visiting the Logs route with `?t=app&r=1h` resolves to type=app + range=1h
- [ ] `?t=application` resolves to type=app (Render's alias honored)
- [ ] An `r` value bex has no preset for falls back to the default range without a crash
- [ ] When both `t` and `type` are present, the canonical `type` wins
- [ ] After any filter interaction, the URL uses bex's canonical keys (no lingering `t`/`r`)

## Out of scope

- URL round-trip for the full filter set (t001)
- Render-shaped dashboard **path** aliases for logs (`/web/srv-…/logs`) — that is the w7/m39 route-alias territory, already shipped for the resource roots; extending it to the `/logs` sub-path is separate follow-up if ever wanted
