## Objective

Confirm the Logs UX change stays consistent with Render's model and introduces no
REST/GraphQL/MCP drift. This milestone is dashboard-only (no backend change), so
the parity check is primarily: (a) the URL/filter model matches Render's `t`/`r`
shape and shareability, and (b) the backend log surface is untouched.

## Context

- Render logs URL contract (captured live 2026-07-16): `?t=app&r=1h`, primary
  toolbar = type · search · range, structured filters tucked away.
- ADR018 already marks "Application logs (query + live tail)" and
  "Request / HTTP logs + structured filters" ✅ across REST/GraphQL/MCP/UI. The
  UI ✅ note (w5/008) describes the old always-visible filter bar — update it to
  reflect the URL-shareable + progressive-disclosure UI.
- Backend log filters: `docs/ADR010-observability.md` § Log filters.

## Steps

1. Verify against the live dev-7 dashboard that: every filter round-trips through
   the URL, a copied URL reproduces the view, `?t=app&r=1h` prefills, and the
   Filters popover + chips preserve every filter.
2. Confirm no REST/GraphQL/MCP contract changed (this is UI-only: the same
   `logs(...)` query and `/v1/logs/subscribe` variables are sent). Note that the
   backend surface is deliberately untouched.
3. Update `docs/ADR018-render-parity.md`: extend the two Logs rows' UI note to
   record the URL-shareable full-filter state, the Render `t`/`r` deep-link
   prefill, and the simplified progressive-disclosure filter bar.
