## Objective

Add meaningful tests for the behavior this milestone shipped: the URL ↔ filter
round-trip (including default-omission and Render `t`/`r` alias prefill) and the
progressive-disclosure filter bar (structured filters behind the popover, active
chips, live auto-disable preserved).

## Context

- Existing tests: `dashboard/src/features/logs/components/__tests__/{log-viewer,log-filter-bar,log-line-list}.test.tsx`;
  `log-search` has a lib home for the parse/serialize unit tests.
- Assert real behavior, not snapshots.

## Steps

1. **`log-search` unit tests**: `parseLogSearch` round-trips each filter; defaults
   are omitted from the serialized query; a malformed value falls back; `t`/`r`
   aliases normalize to canonical keys; canonical wins when both present.
2. **`log-filter-bar` component tests**: the primary toolbar shows only
   type/search/range/live + the Filters trigger; opening the popover reveals
   level/method/statusCode/instance/path; the count badge matches active filters;
   a chip's ✕ clears just that filter; setting a store-only filter disables live
   with the note.
3. **`log-viewer` test**: changing a filter calls `navigate` with the expected
   search object (defaults omitted); initial filters derive from the URL search.
4. Run `yarn test` (dashboard) — all green.
