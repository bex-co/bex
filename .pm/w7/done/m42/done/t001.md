## Objective

Extend the Logs route's `validateSearch` schema and lift `LogViewer`'s local
filter state so that every filter — not just `range` — is read from and written
to the URL query string. After this, a filtered log view is shareable,
bookmarkable, and reload-stable.

## Context

- Today only `range` is URL-backed. Verified live: selecting "Request logs" left
  the URL at `?range=1h`. The other 8 filters are local `useState` only.
- `dashboard/src/routes/services.$serviceId.logs.tsx` — `validateSearch: parseLogSearch`
  (line ~14); reads `range` via `Route.useSearch()` and writes via
  `navigate({ search: { range: next.id }, replace: true })` (lines ~22–30).
- `dashboard/src/features/logs/lib/log-search.ts` — `parseLogSearch()` validator +
  `logRangeFromSearch()` resolver (the seam to extend).
- `dashboard/src/features/logs/components/log-viewer.tsx` — owns
  `[filters, setFilters]` (line ~48), `EMPTY_LOG_FILTERS` default; debounces
  text/path (lines ~53–58).
- `dashboard/src/features/logs/types.ts` — `LogFilters` interface (type, text,
  level, instance, method, statusCode, path) + `EMPTY_LOG_FILTERS`.
- `LogFilters` has no `live` field — the `live` boolean lives separately in
  `LogViewer`. Both need URL backing.

## Steps

1. Extend the search schema in `log-search.ts`: `parseLogSearch` validates and
   returns `{ range, type?, level?, method?, statusCode?, instance?, path?, text?, live? }`.
   Use bex's canonical field names as the query keys (`type`, `level`, …). Omit
   any field at its default/empty value so the URL stays clean (no `?type=all`).
   Validate `type` against the `all|app|request` set and `live` as a boolean
   (`"0"`/`"1"` or absent); unknown values fall back to the default rather than
   throwing (a bad link should still render).
2. In the route component, read the full search object and pass initial filter
   values + live into `ServiceLogsPage` → `LogViewer`.
3. In `LogViewer`, derive the initial `filters`/`live` from the URL search
   instead of `EMPTY_LOG_FILTERS`; on every filter/live change call
   `navigate({ search: <next>, replace: true })` (a small serializer that drops
   defaults). Keep the existing debounce so the URL isn't rewritten on each
   keystroke — write the debounced value.
4. Confirm the query + SSE hooks still receive the same variables (this task
   changes where state lives, not what's sent).

## Acceptance criteria

- [ ] Setting each of type/level/method/statusCode/instance/path/text/live writes the value into the URL query string
- [ ] Reloading the page restores the exact filter + live state from the URL
- [ ] Opening the copied URL in a fresh tab reproduces the same filtered view
- [ ] Default/empty filters are omitted from the URL (a no-filter view has a clean `?range=…`-only or empty query, byte-identical to today)
- [ ] A malformed query value falls back to the default without a crash
- [ ] The GraphQL history query and SSE subscription receive the same variables they do today
