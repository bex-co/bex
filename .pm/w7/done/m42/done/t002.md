## Objective

Simplify the Logs filter bar to read as cleanly as Render's by default: keep a
minimal always-visible primary toolbar (log type · search · time range · live)
and move the five structured filters (level, method, statusCode, instance, path)
behind a single progressive-disclosure "Filters" control, surfacing any active
structured filter as a removable chip so nothing is hidden when set.

## Context

- Render's logs toolbar (verified live) is 3 primary controls + 2 icon buttons:
  log-type dropdown · search · time-range dropdown · maximize · options. The
  structured filters are not in the always-visible bar.
- bex's `log-filter-bar.tsx` currently renders 9 controls in one wrapped row:
  6 range buttons + 5 dropdowns (type/level/method/status/instance) + 2 text
  inputs (path/search) + live toggle (`dashboard/src/features/logs/components/log-filter-bar.tsx`,
  ~lines 119–215).
- `FilterSelect` (level/method/statusCode/instance) is fed by `logLabelValues`
  discovery with static fallbacks; keep that wiring intact — only relocate the
  controls.
- Store-only filters (level/method/statusCode/path, and type=request) disable the
  live tail via `usesStoreOnlyFilters()` (`types.ts` ~lines 89–97); that behavior
  and its explanatory note must survive the reorg.
- shadcn `Popover`/`Sheet` + `Badge` primitives exist under
  `dashboard/src/common/components/ui/`.

## Steps

1. Split `LogFilterBar` into a primary row (range presets + type dropdown +
   search input + live toggle) and a **Filters** trigger (button with an
   active-count `Badge`) that opens a `Popover`/`Sheet` holding the level,
   method, statusCode, instance, and path controls.
2. Render active structured filters as removable chips in the primary row (label
   + value + ✕ that clears that one filter). The chip set is derived from the
   current `filters`, so it stays in sync with the URL state from t001.
3. Preserve the store-only-filter → live-auto-disable behavior and its hint;
   ensure the disabled-live explanation is still reachable when a structured
   filter set from the popover disables the tail.
4. Add/adjust i18n keys (`logs.filtersButton`, active-count, chip clear labels)
   in `dashboard/src/features/logs/locales/{en,zh}.ts`.
5. Keep all existing `onChange({ ... })` handlers — this task changes layout and
   disclosure, not the filter-change wiring.

## Acceptance criteria

- [ ] The always-visible toolbar shows only type + search + range + live (+ the Filters trigger and any active chips)
- [ ] level/method/statusCode/instance/path live inside the Filters popover/sheet
- [ ] The Filters trigger shows a count badge equal to the number of active structured filters
- [ ] Each active structured filter appears as a removable chip; clicking ✕ clears just that filter (and updates the URL via t001)
- [ ] Setting a store-only filter still auto-disables live with the explanatory note
- [ ] No filter capability is removed — every control still reaches the same query/SSE variables
