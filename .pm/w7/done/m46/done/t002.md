## Objective

Add a `psql-verify` leg to `scripts/cli-compat.sh` that drives the unmodified Render CLI's `psql` end-to-end against a disposable public bex Postgres, mirroring the existing `pgcli-verify` leg so the two database-shell rows share one acceptance shape.

## Context

- The sibling `pgcli [id|name]` row is already `[x]` — its harness (`scripts/cli-compat.sh` `pgcli-verify`, artifact `docs/render-artifacts/pgcli-cli.md`) is the template: bounded pseudo-terminal, one disposable public Postgres resolved by opaque id AND exact name, `SELECT 1` through the real binary, cleanup proof.
- `psql`'s non-TTY `-c` path is simpler than pgcli's PTY dance (no pseudo-terminal needed) but adds the client-side ipify + `hasAccessToPostgres` allowlist check (t001), so the disposable Postgres must carry an `ipAllowList` entry for the caller's `/32`.
- The leg must be cleanup-safe (delete the disposable Postgres on exit, even on failure) and gated on the environment prerequisites (`BEX_DB_DOMAIN` set, pg-sni-proxy reachable) so it skips cleanly on base dev-9 rather than false-failing.

## Steps

1. Add `psql-verify` to `scripts/cli-compat.sh` following the `pgcli-verify` structure.
2. Create a disposable Postgres with `spec.public: true` and an `ipAllowList` of the caller's public IP `/32` (resolve it the same way the CLI does, or accept it as an arg).
3. Drive the unmodified CLI: `render psql <id> -c "SELECT 1 AS bex_psql_probe;"` and `render psql <name> -c "SELECT 1 AS bex_psql_probe;"`.
4. Assert the returned probe row from both invocations.
5. Tear down the disposable Postgres on exit (trap-based cleanup).
6. Guard the leg to skip with a clear message when `BEX_DB_DOMAIN` / the SNI proxy are absent.

## Files

- `scripts/cli-compat.sh` (new `psql-verify` leg).

## Acceptance criteria

- [ ] `scripts/cli-compat.sh psql-verify` creates a disposable public Postgres with a self-IP `/32` allowlist and tears it down on exit.

- [ ] The leg skips cleanly (non-failing, explained) when `BEX_DB_DOMAIN` / pg-sni-proxy are unavailable.

## Out of scope
