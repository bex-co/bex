## Objective

Establish, with evidence from the real gVisor agent sandbox, how Muse Code must be configured to run headless there, and record the decisions in a new ADR before any code lands.

## Context

- Adapter: `@bex-co/muse-code-acp@0.11.0` (Apache-2.0, maintained in the `bex-co` org; source: https://github.com/bex-co/muse-code-acp). Requires Meta's native `muse` binary ≥ 1.1.1 (`muse serve`); CI verifies 1.1.1-R2514.1 and 1.4.14-R7309.1 from `https://lookaside.facebook.com/lookaside/muse/download/?channel=muse&version=<v>&file=muse-x86-linux` with SHA-256 from Meta's release manifest (`file=manifest.json`).
- The agent image is `linux/amd64` only (`.github/workflows/deploy.yml`, agent-image job) and runs as uid 10001 (`lego/agent-image/Dockerfile`).
- Muse on Linux sandboxes commands with bwrap; the adapter's CI notes bwrap failing under AppArmor. Sandbox-off needs `MUSE_CODE_ACP_ALLOW_YOLO=1` (`src/safety-settings.ts`).
- Model routing: `MUSE_CODE_ACP_GATEWAY_URL` + `MUSE_CODE_ACP_GATEWAY_KEY`, or the `muse/provider` ACP extension; Muse appends `/responses` to the base URL and sends `Authorization: Bearer`.
- Model ids on Meta's API: `muse-spark-1.3-contributor` ($0.10 input / $0.002 cached / $0.20 output per 1M tokens; 150 RPM / 3M TPM) — https://dev.meta.ai/docs/pricing-rate-limits.
- Sandbox lifecycle: no snapshot or restore; an idle sandbox is replaced and primed from the transcript (ADR047 D3).

## Steps

1. Build a throwaway image with the pinned binary + adapter (not pushed to production tags) and run it in an `agent` template sandbox on the production cluster or dev-7.
2. With a stub Responses upstream behind the gateway model-proxy URL, confirm: `initialize`, `session/new`, a prompt turn, sandbox-off behavior, whether Muse contacts any host other than the model URL (telemetry, update checks, login), where it writes session state (`XDG_*`, `~/.config/muse`, …), startup latency, and that the configured model id `muse-spark-1.3-contributor` is sent unchanged.
3. If a Meta API key is present in `.env`, run one real contributor-model turn through a local proxy to measure requests and tokens per typical turn (sizes m391/t004). If not, record the measurement as pending for m391/t005.
4. Write the new ADR at the next free number (`docs/ADR<next>-muse-code-agent.md`) and index it in `docs/AGENTS.md`: profile, binary supply (pin + SHA-256 + no self-update), sandbox-off, egress set, overlay channel (first-prompt preamble, since the adapter has no `systemPrompt`), state path, the contributor-tier data use, and the open question on Meta's terms for hosted use.
