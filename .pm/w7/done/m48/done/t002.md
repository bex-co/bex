## Objective

Read billing results back from Metronome: a customer's current-period (in-progress) cost and their finalized invoices, so bex can surface real spend (t003/t004).

## Context

- `docs/ADR040-billing-metronome.md` §8 Phase 2.
- Extends m47/t002's client wrapper with read methods over the Metronome invoices/cost API.
- Map by ingest alias (`tenant.id`) → customer. Distinguish current-period estimate-from-Metronome vs finalized invoices (Draft → Finalized → Sent lifecycle).
- Graceful degradation: Metronome unreachable ⇒ callers fall back (t003 keeps `estimatedCost`), never a hard 500.

## Steps

1. Add `CurrentCost(customerID)` + `Invoices(customerID)` to the client.
2. Normalize into a small bex-side type (amount, currency, period, status) the surfaces can render.
3. Handle not-found / no-contract (comped Mode A / excluded) → empty, not error.
4. Unit-test with stubbed responses incl. the degraded path.
