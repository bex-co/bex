## Objective

When the operator's Postgres disk-autoscale grow is rejected by the namespace ResourceQuota (API-server `exceeded quota` Forbidden), surface the block observably on the owning Database status (condition or status message, e.g. `DiskGrowthBlockedByQuota`) and back off, instead of hot-loop erroring the reconcile; growth resumes automatically once quota allows (plan upgrade or freed storage).

## Context

- `lego/operator/internal/controller/database_autoscale.go` — reads `kubelet_volume_stats_*` via `BEX_PROM_URL` and patches the CNPG Cluster storage size; today a quota rejection is just a reconcile error.
- `lego/operator/internal/controller/database_controller.go` — owns Database status writes.
- Quota rejections arrive as `apierrors.IsForbidden` with an `exceeded quota` message on the Cluster/PVC update.

## Steps

1. Detect the quota-rejection error shape on the storage patch path.
2. Set a Database status condition/message naming the quota block; requeue with backoff rather than returning a bare error.
3. Clear the condition and resume growth when a subsequent attempt succeeds.
4. Check whether the KeyValue PVC path has an equivalent grow seam; if it does, apply the same handling, if not, note why in the code.

## Files

- `lego/operator/internal/controller/database_autoscale.go`
- `lego/operator/internal/controller/database_controller.go` (status plumbing)
- `lego/types/v1alpha1/database_types.go` (only if a new condition type is needed)

## Acceptance criteria

- [ ] Envtest/unit simulating a quota-rejected grow: status condition set, reconcile backs off (no hot loop), no spurious error events.
- [ ] After the quota constraint lifts, growth proceeds and the condition clears.

## Out of scope

- Quota values themselves (t001); tenant-facing REST/GraphQL surfacing beyond the CR status (existing status fields already project).
