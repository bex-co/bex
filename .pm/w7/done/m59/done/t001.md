## Objective

Extend `quotaForPlan` with the missing resource dimensions ADR045 Finding 4 identified: an aggregate `requests.storage` cap derived from the tier catalog's per-plan storage sizes plus disk-autoscale headroom, a `persistentvolumeclaims` object-count cap, and zero-caps for `services.loadbalancers` and `services.nodeports` (the operator never creates either in a tenant namespace — defense-in-depth against operator bugs/compromise).

## Context

- `lego/backend/internal/store/namespaces.go:363` — `quotaForPlan` currently caps cpu/memory/pods/jobs + `count/{apps,databases,keyvalues}` only.
- `lego/types/tiers/tiers.yaml` — per-plan Database/KeyValue storage sizes; free tier anchors 1 DB + 1 KV, paid 25 + 25.
- The CNPG disk-autoscaling loop (`lego/operator/internal/controller/database_autoscale.go`, `BEX_PROM_URL`) grows PVCs automatically, so the storage cap must include documented growth headroom, not just the sum of initial plan sizes.

## Steps

1. Choose per-plan values: `requests.storage` = sum of the tier catalog's max plan storage × the plan's datastore count caps + a documented headroom factor; `persistentvolumeclaims` aligned to the datastore count caps; `services.loadbalancers`/`services.nodeports` = 0 for all plans.
2. Add the four keys to the `corev1.ResourceList` in `quotaForPlan` for both the free and paid branches; document the derivation in the function comment.
3. Extend the existing quota unit tests to assert the new keys per plan.

## Files

- `lego/backend/internal/store/namespaces.go`
- `lego/backend/internal/store/namespaces_test.go` (or the existing quota test file)

## Acceptance criteria

- [ ] `quotaForPlan("free")` and `quotaForPlan("paid")` include `requests.storage`, `persistentvolumeclaims`, `services.loadbalancers: 0`, `services.nodeports: 0` with documented values.
- [ ] Unit test asserts the full quota shape per plan and fails if a dimension is dropped.
