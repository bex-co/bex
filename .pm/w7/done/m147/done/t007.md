## Objective

Check that sandbox exec behaves consistently across REST (both the handshake and the legacy route), MCP `sandbox_exec`, GraphQL (if it exposes exec or sandbox status), and any dashboard sandbox surface. Compare against Render's documented connect-token flow.

## Context

- `lego/backend/internal/sandbox/{rest,mcp,graphql}.go`, `docs/ADR006-bex-api.md`, `docs/ADR014-sandboxes.md`.

## Steps

1. Compare exit-code and error semantics, and the `SANDBOX_NOT_FOUND` and forbidden shapes, across surfaces.
2. Check the `SandboxConnectResponse` field semantics (`expiresAt`, `executionId`) against Render's schema, and record any divergence (for example, token lifetime).
3. File any drift as follow-up rather than diverging silently.

## Files

- Notes in the milestone README; follow-up board items via `/pm`.

## Acceptance criteria

- [x] Parity table recorded; any drift filed.

## Out of scope

- Implementing drift fixes outside this milestone's routes.

## Done 2026-09-15

Parity table: REST handshake (pinned CLI) and REST legacy `/exec` (≤v2.21, MCP-free) both stream the same gateway SSE, so exit codes and `{status,message}` errors are identical; MCP `sandbox_exec` returns `{stdout, stderr, exitCode}` with a terminated target as `ErrNotFound` (404 dialect) — same decoder; GraphQL exposes no exec (`graphql.go` lists/reads only) and the dashboard has no sandbox exec surface, so nothing diverges there. `SandboxConnectResponse`: `executionId` `exe-` prefix and RFC3339 `expiresAt` match Render's schema; `method` is `POST` as the client expects. Divergences recorded, not silent: Render does not document its token lifetime (bex ≤60 s) and its `uri` targets a sandbox-proxy host, whereas bex's targets the API origin — both are opaque to the client, which follows `uri` verbatim. `SANDBOX_NOT_FOUND` 404 and 403 shapes are the same across REST and the redeem route. No drift to file.
