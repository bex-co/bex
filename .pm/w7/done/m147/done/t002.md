## Objective

Make `event: exit` and `event: error` decode correctly in the pinned Render CLI, so remote exit codes and error messages reach the user. Keep bex's own buffered consumers correct.

## Context

- Consumer (all pins v2.21 through v2.27): `execExitEvent{exit_code}` and `execErrorEvent{status, message}` in `pkg/sandbox/sse.go:23-31`.
- Gateway emitter: `lego/backend/internal/sshgateway/sandboxsse/sandboxsse.go:257-263` (`exitCode`, `{error, code}`). Its comment at `:250-253` is wrong.
- Internal reader: `lego/backend/internal/sandbox/exec.go:345-360` `bufferExecWithLimit` reads `exitCode` and `{error, code}`, including `sandboxexec.ErrorCodeTargetTerminated`. Callers: `ExecBuffered` (MCP `sandbox_exec`, `mcp.go:91`), `systemBufferedExec` (`service.go:965`, `clientSuspend`), `bufferExec` in `AgentSessionLifecycle.ReadSessionStatus` (`service.go:659`) and `HibernateAgentSessionSandbox` (`service.go:796`).
- The gateway and bex-api roll out independently, so for one release a reader may see either shape.

## Steps

1. Emit `{"exit_code":N}` on exit. During transition you may also keep `exitCode`; document when to remove it.
2. Emit `{"status":<http-ish status>,"message":"…"}` on error, keeping `error` and `code` for the internal reader. Map terminated-target to 404 and unavailable to 503.
3. Have `bufferExecWithLimit` accept both key forms until the transition ends, preferring the pinned form.
4. Fix the misleading comment.

## Files

- `lego/backend/internal/sshgateway/sandboxsse/sandboxsse.go`, `lego/backend/internal/sandbox/exec.go`, and their tests.

## Acceptance criteria

- [x] The pinned `readSandboxExecStream`, run over the gateway's real output, returns exit 7 for `exit 7` and a non-empty message plus non-zero status for a terminated target.
- [x] `ExecBuffered` and `systemBufferedExec` still return the correct exit code and the terminated-target `ErrNotFound`, with both old and new payloads.
- [x] `sandboxsse_test.go:111-115` and `exec_test.go` assert the pinned shape instead of pinning `exitCode`.

## Out of scope

- Route and handshake changes (t003, t004).

## Done 2026-09-15

Gateway `event: exit` now carries `{"exit_code":N,"exitCode":N}` and `event: error` `{"status":S,"message":M,"error":M,"code":C}` (404 terminated, 403 revoked, 503 failed to start); `bufferExecWithLimit` reads both key sets, preferring the pinned ones, and still maps the terminated target to `ErrNotFound`. The misleading emitter comment is replaced with the transition note (drop the legacy keys after one release). `sandboxsse_test.go` and every gateway stub in `exec_test.go` now assert/emit the pinned shape; `TestBufferExecReadsPinnedAndTransitionalShapes` covers both payloads for the buffered readers.
