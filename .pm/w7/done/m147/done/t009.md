## Objective

Add tests that fail if the pinned client's sandbox transport and bex drift apart again, especially on the next pin bump.

## Context

- The pinned module is importable from `lego/cli` (Go 1.27). The backend is on Go 1.26 and must not import `cli`. Put the client-driven contract test on the CLI side against a recorded bex handler transcript, or on the backend side against fixtures generated from the pinned client, with a CI check that regenerates them when `lego/cli/go.mod` changes.
- Existing gaps: the tests at `sandboxsse_test.go:111-115` and `exec_test.go` asserted bex's own `exitCode` instead of the consumer's struct, and m33's live check only used exit 0.

## Steps

1. Add a contract test that drives the pinned `sandbox.Repo.ExecSandboxStream` (handshake, redeem, SSE) end to end and asserts stdout, stderr, exit 7, and an error message.
2. Add negative tests: replayed, expired, cross-sandbox, and altered-command tokens; OAuth bearer at redeem; connect token at an authenticated route; foreign sandbox 404 parity.
3. Add a guard that fails when the pinned module's `ConnectSandboxRun*` path or `execExitEvent`/`execErrorEvent` tags change without a matching fixture update.
