# The Postgres, Key Value and service Disk metrics panels read a fixed hour, with no range picker

Why: w7/m430 added Render's Disk Activity, Disk Operations, Network Activity, Transaction Volume and Lock-Delayed Queries graphs to these panels, and a transaction or lock-wait history is read over days, not the last hour.

Found by w7/m430 t007 (Render parity), 2026-11-16.

- `dashboard/src/features/metrics/components/datastore-metrics-panel.tsx` calls `useDatastoreMetrics` with no `startTime`, `endTime` or `resolutionSeconds`, so every chart is bex-api's default: the last hour at 60 s (`defaultMetricSpan`, `defaultResolution` in `lego/backend/internal/metrics/service.go`). ADR010 § Retention records it ("the datastore metrics panel (one hour) read fixed windows … and have no picker").
- A service's Metrics page has Render's range presets bounded by the plan's metrics window (w5/m42, w7/m427). Render's documentation describes one Metrics page for services and databases; whether its database Metrics page offers the same presets was not checked live (a Render account is `w10/blocked/002`).
- The API already takes `start`, `end` and `resolution` on GraphQL `datastoreMetrics` and is floored per plan (w7/m427), so this is a dashboard change: reuse the service page's range select and `metricsRetention` bound on the datastore panel, with the skeleton unchanged.

End state: the Postgres, Key Value and service Disk metrics panels have the service Metrics page's range picker, bounded by the workspace plan's metrics window, and every graph on them reads the chosen range; or, if Render's database page is checked and has no picker, this note is closed with that evidence.

**Done 2026-11-17 (w7/072, the Work branch of the end state):** `DatastoreMetricsPanel` (the Postgres and Key Value Metrics, and a service's Disk tab) opens with the service Metrics page's `RangeSelect`, from Render's 12-hour default, bounded by `useMetricsRetentionBound(resource)` (the `dpg-`/`red-`/`srv-` id's plan window, wider presets disabled, the plans that keep more named). One `useLiveRange` window feeds every read, graphs, limits and capacity alike (`pollIntervalMs: 0`, the window's tick refetches), so a pick of Last 7 days asks bex-api for seven days at 5,040 s. `DatastoreMetricsSkeleton` holds the picker's `h-8 w-40` slot; pending and ready measured identical at 1280 px and 390 px on `yarn dev:local`. Render's database page itself was not checked live (`w10/blocked/002`): its documentation describes one Metrics page for services and databases, with "your selected time range" and the per-plan retention, which is the parity-sufficient reading. The range is not URL-persisted, unlike the service page's (w6/065). ADR010 § Retention and ADR018's extended-metrics row are updated. Tests: `datastore-metrics-panel.test.tsx` (every read's window at the default and after a pick, which fail with the fix removed; the plan bound; the skeleton's range row).
