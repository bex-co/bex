## Objective

Add a durable provider-event ledger and workspace billing state so webhook retries, restarts, and asynchronous enforcement converge deterministically.

## Context

- The current webhook verifies and logs `invoice.payment_failed` but stores no lifecycle state.
- Raw webhook bodies and secrets must not be retained; only necessary identifiers and normalized state belong in Postgres.

## Steps

1. Design migrations for unique Stripe event ids, normalized invoice/subscription state, deadlines, and enforcement ownership.
2. Add transactional store methods and retention/index strategy.
3. Keep provider ids out of tenant-editable state and redact sensitive payloads.

## Files

- `lego/backend/internal/store/migrations/`
- `lego/backend/internal/store/`
- `lego/backend/internal/billing/`

## Acceptance criteria

- [x] Duplicate event ids are transactionally idempotent.
- [x] State survives bex-api restart and supports deadline/recovery queries.
- [x] No API key, webhook secret, full payload, or payment detail is persisted.

## Out of scope

- Event processing and enforcement behavior.
