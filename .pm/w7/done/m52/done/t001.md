## Objective

Define exactly what bex changes after a payment grace period, what data-bearing resources remain untouched, and how the change is reversed before implementation begins.

## Context

- ADR040 requires grace → reversible suspension and explicitly defers eventual termination.
- Apps, managed Postgres, and Key Value have different safety and durability properties; a blanket delete/scale-to-zero rule is unsafe.

## Steps

1. Inventory existing suspend/resume and mutation-gate mechanisms for every billable resource kind.
2. Specify the safe enforcement matrix, ownership marker, exceptions, and recovery ordering.
3. Record the decision in ADR040, including why no tenant data is deleted.

## Acceptance criteria

- [x] Each resource kind has an explicit enforce/recover/no-touch decision.
- [x] Enforcement is reversible and eventual termination remains out of scope.
- [x] Recovery can distinguish billing changes from user-initiated suspension.

## Out of scope

- Implementing the policy before it is recorded.
