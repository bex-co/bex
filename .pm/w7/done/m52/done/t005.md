## Objective

Turn normalized payment failure into an explicit grace deadline and schedule due transitions using durable database state rather than in-memory timers.

## Context

- Multiple bex-api replicas run in prod; only one worker may claim a due transition.
- Test-clock verification needs an injectable clock and a short test-only grace without weakening production defaults.

## Steps

1. Add validated grace configuration and lifecycle transition rules.
2. Implement transactionally claimed due work with restart-safe retries.
3. Preserve the original reason/deadline and cancel pending enforcement on recovery.

## Files

- `lego/backend/internal/billing/lifecycle.go`
- `lego/backend/internal/billing/worker.go`
- `lego/backend/internal/store/`
- `lego/operator/config/api/deployment.yaml`

## Acceptance criteria

- [x] One failure creates one visible grace deadline across replicas.
- [x] Restart, duplicate events, and early payment do not produce late enforcement.
- [x] Invalid/zero grace configuration fails startup when enforcement is enabled.

## Out of scope

- The resource enforcement action itself.
