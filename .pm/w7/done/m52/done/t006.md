## Objective

Send deduplicated, actionable owner notifications for each billing lifecycle transition through existing email and outbound-event mechanisms.

## Context

- Notification delivery must not block webhook acknowledgement or state convergence.
- Messages must distinguish Stripe Test Mode in prod from real collection and must not include payment details.

## Steps

1. Define transition-specific email and outbound event payloads with invoice/Portal links where authorized.
2. Add durable deduplication and retry using existing mailer/webhook infrastructure.
3. Cover missing SMTP and delivery-failure behavior without reverting billing state.

## Files

- `lego/backend/internal/email/`
- `lego/backend/internal/notifications/`
- `lego/backend/internal/webhooks/`
- `lego/backend/internal/billing/`

## Acceptance criteria

- [x] Each transition produces at most one logical notification per recipient/channel.
- [x] Test-mode messages are unmistakable and contain no sensitive payment data.
- [x] Delivery failure is observable and retried without blocking lifecycle work.

## Out of scope

- Slack integration or new third-party notification channels.
