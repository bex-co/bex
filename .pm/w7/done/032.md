# 032 — The CNPG `Cluster` projection may still PUT every reconcile against a live CNPG, and envtest cannot see it

Why: this is the exact defect class m84 just fixed, one layer up and invisible to envtest — a minutes-long measurement on prod settles whether the convergence invariant is actually narrower than its green suggests.

Residual from `w7/m84/t003`, 2026-08-19. Recorded because the milestone's green is narrower than it looks, not because a defect was observed.

**What m84 proved.** A converged reconcile of an App, KeyValue or Database now issues zero writes, asserted by the convergence invariant in `lego/operator/internal/controller/reconcile_convergence_envtest_test.go`. The Database's CNPG `Cluster` is covered and passes.

**What it did not prove.** envtest applies _schema_ defaulting only — no admission webhooks, and `internal/controller/testdata/crds/postgresql.cnpg.io_clusters.yaml` is a stub with `x-kubernetes-preserve-unknown-fields: true` and no defaults. A live CNPG installs a **mutating webhook** that fills in `Cluster.spec` fields the bex operator does not set. `reconcileCluster` assigns `cluster.Object["spec"] = spec` wholesale, so every such field is dropped on each pass and re-defaulted by the webhook — the exact mechanism m84 fixed for pod templates, one layer up, and invisible to this repo's tests.

Cost, if real, is the same shape m84 measured: one redundant PUT per Database per reconcile. No etcd write and no requeue (the webhook re-defaults to a byte-identical object), so nothing user-visible — which is why nobody would report it.

**It is not only the Cluster.** `upsertOwned` replaces `spec` wholesale for four more kinds, all behind the same stub-CRD blind spot, and the first of them runs on **every App**:

| kind | projection | per-pass? |
| --- | --- | --- |
| Traefik `Middleware` | `cidrMiddlewareSpec`, the websocket meter, host redirects | yes — up to 3 per App |
| CNPG `Pooler` | `poolerSpec` | yes, per pooled Database |
| CNPG `ScheduledBackup` | `scheduledBackupSpec` | yes, per backed-up Database |
| cert-manager `Certificate` | `reconcileKeyValueTLS` | yes, per public KeyValue |

Real CRDs carry schema `default:`s and both CNPG and cert-manager register mutating webhooks, so any field these projections omit reproduces exactly the bug m84 fixed.

Two more per-pass paths the invariant's shapes never reach, for the same reason (they need config envtest does not have): `reconcileTenantBackupStore` (two live GETs plus a wholesale-`spec` `CreateOrUpdate` on a Barman `ObjectStore`, every backed-up Database reconcile) and `reconcileExecutionNetworkPolicy` (a live GET plus `CreateOrUpdate` on the uncached build-plane client, every App reconcile when `BEX_BUILD_NAMESPACE` differs).

**Before scoping any fix, measure it.** Minutes, not hours: on a settled App/Database, `kubectl get middleware <app>-ip-allow -o yaml` and `kubectl get cluster <name> -o yaml` against what the projection writes. If the stored spec has keys the projection never sets, it churns. Needs a prod (or local CNPG) kubeconfig; blocked on that, not on design.

**If it does churn, the fix is not obvious and should not be assumed.** Merging the owned keys into the fetched spec instead of replacing it would converge, but it also gives up the property wholesale replacement buys: a key the operator _stops_ setting (`spec.backup` when backups are disabled) would linger forever. Any fix has to enumerate the keys the operator owns and delete the ones it no longer wants — which is a real design task, not a one-liner. The same question applies to the CNPG `Pooler` and `ScheduledBackup` projections, which go through the same `upsertOwned` seam.

Sub-hour to measure. Promote to a milestone only if the measurement is positive _and_ the ownership enumeration turns out to be non-trivial.

## Review — 2026-09-05: live defaulting confirmed, fix still open

Production access is available in this review; the old kubeconfig blocker is stale. The stored tenant CNPG Cluster includes `enablePDB`, `failoverDelay`, `postgresUID`, `postgresGID`, `primaryUpdateMethod`, `primaryUpdateStrategy`, `probes`, `replicationSlots`, `smartShutdownTimeout`, `startDelay`, `stopDelay`, `switchoverDelay`, and nested PostgreSQL defaults. `reconcileCluster` still replaces the whole spec. This confirms the live-defaulting premise; the ownership-preserving fix and regression coverage remain required. No production object was changed.

## Closed — 2026-09-05: preserve defaults and withdraw owned fields

Added `spec_projection.go`: unstructured children retain the previous bex-authored spec in `app.bex.co/projected-spec`. Reconciliation merges the new projection into the live object, removes fields present in the previous projection but absent now, and preserves admission defaults outside bex's ownership. This includes arbitrary tenant PostgreSQL parameters, so removing a parameter does not leave its old value behind. CNPG roles/plugins/externalClusters preserve defaults within named entries while membership follows desired intent; scalar lists (CIDRs, DNS names, SQL) replace exactly.

Existing objects without the annotation receive one legacy whole-spec replacement to establish ownership, then converge. Malformed history fails without modifying spec. The annotation records only the projection, never the defaulted result. This mechanism covers `upsertOwned` (Middleware, Pooler, ScheduledBackup, Backup, Certificate), `reconcileCluster`, host redirects, and the namespace-shared ObjectStore projection. `reconcileExecutionNetworkPolicy` is already a legacy-policy cleanup path and no longer projects spec.

Verification: the complete operator `make test` passed. The CNPG envtest injects representative live top-level, PostgreSQL-parameter, and bootstrap defaults and asserts zero update requests on the next reconcile. Request-counting tests cover the other shared projection kinds, repair of owned-field drift, and both Secret/ObjectStore writes in the backup projection. Removal tests cover backup plugins, tenant parameters, role membership/tombstones, certificate names, and withdrawn ObjectStore policy. Final focused tests passed after adding ObjectStore coverage; `make lint` passed all four modules and whole-program dead-code analysis. No production operator deployment was performed in this review.
