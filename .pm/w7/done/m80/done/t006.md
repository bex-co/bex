## Objective

The standing parity task. `healthCheckPath` is exposed on every surface bex ships, and t004 changes what leaving it empty *means*. Check the change reads consistently everywhere, and compare against render.com rather than against our own assumptions.

## Context

- REST: `serviceDetails.healthCheckPath` on create/GET/PATCH (`lego/backend/internal/apps/render.go`).
- GraphQL: `Service.healthCheckPath` + `setHealthCheckPath`.
- MCP: `set_health_check_path` (`docs/ADR006-bex-api.md:371`).
- Dashboard: the Health & Alerts section (`lego/backend/internal/apps/service.go:405-408` names it).
- Render CLI: `--health-check-path` maps to `serviceDetails.healthCheckPath` (`docs/render-artifacts/cli-services-create-update.md:61,96`).

## Steps

1. Confirm all four surfaces can both set and **clear** the field, since clearing is now meaningful (it selects TCP). A surface that silently coerces `""` back to `/` would defeat t004 — check each one rather than assuming.
2. Check the dashboard communicates the two modes. An empty input that now means "TCP check" and not "default to `/`" needs to say so; propose copy if it does not.
3. Compare with Render's behavior for an empty health check path and note any remaining drift in `docs/ADR018-render-parity.md`.
4. Record the two known divergences as divergences (30s vs 15s rotation; no liveness) rather than letting the ledger imply full parity.
5. File anything found as follow-up work — do not widen this milestone.
