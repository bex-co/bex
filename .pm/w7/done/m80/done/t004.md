## Objective

Stop the platform from deciding, on the user's behalf, that "healthy" means `GET / → 2xx/3xx`. Render's default is a TCP socket probe; a path-based HTTP check is something the user opts into. bex's `+kubebuilder:default=/` makes the strict form mandatory and unavoidable, which makes an entire ordinary class of service undeployable.

## Context

- `lego/types/v1alpha1/app_types.go:349-356` carries `+kubebuilder:default=/`.
- `lego/operator/internal/controller/deployment_projection.go:111-113` additionally coerces `""` → `"/"`, so there are two layers of the same assumption.
- Kubernetes scores an HTTP probe healthy only for `200 ≤ code < 400`. **A service whose `/` returns 404 — an API with no root route, entirely normal — can therefore never become Ready on bex, and can never deploy.** The identical service deploys on Render, whose default TCP probe only asks whether the process is listening.
- bex-api only writes the field when non-empty (`lego/backend/internal/apps/render.go:295`), so the API server's default is what materializes `/`. Removing the marker is the lever.
- **Migration fact that must be stated, not discovered:** defaults are applied at write time, so every App already stored has `healthCheckPath: "/"` persisted (verified against the live `beancount-cms-v2` CR). Removing the marker does not alter stored objects — new services get TCP, existing ones keep HTTP until an owner clears the field. This task does not backfill.

## Steps

1. Remove `+kubebuilder:default=/` from `HealthCheckPath` and rewrite the field comment to state the two-mode contract.
2. Run operator codegen (`make manifests generate`) and commit the regenerated CRD.
3. In the probe constructor from t003: `healthCheckPath == ""` → `TCPSocket{Port: p.port}`; otherwise `HTTPGet` as today. Both keep `TimeoutSeconds: 5`.
4. Delete the `if path == "" { path = "/" }` coercion — with the CRD default gone it would silently restore the old behavior.
5. Fix `app_controller_test.go:226-228`, which currently asserts that an unset path yields `HTTPGet` on `/`. That assertion pins the behavior being removed; replace it with the TCP expectation and add an explicit-path case that still asserts HTTP.
6. Verify bex-api can actually *clear* the field (`SetHealthCheckPath` with `""`), since that is now the documented opt-in to TCP. If it cannot, note it as follow-up rather than widening this task.

## Acceptance criteria

- [ ] An App with no `healthCheckPath` projects a `TCPSocket` probe on the container port.
- [ ] An App with `healthCheckPath: /healthz` projects an `HTTPGet` probe, unchanged apart from the 5s timeout.
- [ ] The regenerated CRD carries no default for the field.
- [ ] A test covers the 404-root case: a service whose root is not 2xx/3xx is Ready under the default probe.
- [ ] Whether `SetHealthCheckPath("")` can clear the field is established and recorded either way.
- [ ] `make test` passes.
