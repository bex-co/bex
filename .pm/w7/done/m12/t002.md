## Objective

Grow the App finalizer from "sandbox only" into a structured delete-time teardown pass, and make its first job the build-artifact GC: delete the app's build Jobs (+ their pods) and kpack Images/Builds in `BEX_BUILD_NAMESPACE`, which ownerReference cascade can never reach (cross-namespace ownerRefs are invalid in k8s).

## Context

- `lego/operator/internal/controller/app_controller.go` — finalizer `app.bex.co/finalizer` (line ~52), delete handling ~155–165 currently only calls `r.Runtime.Delete(sandboxID)`.
- `lego/operator/internal/build/` — build Jobs are named `bld-<name>-gen-<generation>` and labeled; `build.CancelActiveBuilds` (called at `app_controller.go:216`) already lists/deletes *active* Jobs by label — the delete-time GC wants **all** of the app's Jobs and kpack `Image`/`Build` objects, not just active ones.
- `BEX_BUILD_NAMESPACE` unset ⇒ builds run in the App's own namespace and Jobs are ownerRef'd — GC must be a no-op-safe double delete there.
- Teardown must be idempotent and tolerate partial failure: requeue with error rather than dropping the finalizer early (a stuck teardown should block CR deletion visibly, but a NotFound is success).
- Structure the finalizer body as an ordered list of teardown funcs so t003/t004/t005 slot in cleanly.

## Steps

1. Refactor the finalizer branch into `teardown(ctx, app) error` running an ordered slice of cleanup funcs; remove the finalizer only when all succeed.
2. Implement build GC: list by the app's build labels in the resolved build namespace; delete Jobs (propagation Background/Foreground) and kpack Images/Builds; IgnoreNotFound.
3. envtest: create an App with fake build Jobs/Images in a separate ns, delete the App, assert they're gone and the finalizer released.
