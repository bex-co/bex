## Objective

Make `apps.Service.Delete` purge the deleted service's OpenBao env vars and secret files (and confirm the materialized `<app>-env` Secret in the apps namespace goes with them), so tenant credentials do not outlive the service. Today only **workspace** deletion reaches OpenBao (`secrets.WorkspacePurger`); single-service delete leaves everything.

## Context

- `lego/backend/internal/apps/service.go` — `Delete` (~line 790) already does out-of-cascade cleanup (store row, clone Secret, external-registry pull Secret); this adds the secrets purge alongside.
- `lego/backend/internal/secrets/purger.go` — the existing per-app purge machinery (`WorkspacePurger` iterates a tenant's Apps and purges each); expose/reuse the per-app unit for a single service.
- Wiring is structural seams at the composition root (`lego/backend/cmd/api/main.go`), same discipline as the store/clone-secret seams — `apps` must not import `secrets`.
- OpenBao may be unset (`BEX_OPENBAO_URL` empty ⇒ secrets feature disabled): delete must still succeed, purge becomes a no-op.
- Purge failure semantics: don't strand the CR — log + continue (or best-effort with error surfaced in the response) rather than failing the whole delete; match how `deleteCloneSecret` errors are handled today.

## Steps

1. Extract/reuse a `PurgeApp`-shaped method in `secrets` from the `WorkspacePurger` internals.
2. Add a purger seam to `apps.Service`, call it from `Delete` before/alongside the CR delete.
3. Wire in `cmd/api/main.go`; nil seam (OpenBao unset) ⇒ no-op.
4. Verify the operator-materialized env Secret disappears (ownerRef or explicit delete — check which) once the OpenBao source is gone; if it's not owned, delete it here too.
5. Unit test: delete with a fake purger asserts it's called with the app; delete with nil purger still succeeds.

## Acceptance criteria

- [ ] Deleting a service with env vars removes its OpenBao env-var and secret-file entries.
- [ ] The materialized env Secret is gone from the apps namespace after delete.
- [ ] Delete succeeds when OpenBao is unset and when the purge errors (logged, not fatal).
- [ ] `apps` does not import `secrets` (structural seam only).
