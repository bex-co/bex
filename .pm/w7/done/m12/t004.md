## Objective

On deletion of a `static_site` App, delete every object under the app's prefix in the static-content bucket. Today `publish.go` only `--delete`s within a single revision's prefix, so all published revisions (`<appID>/<revision>/…`) persist in S3 forever after the App is gone.

## Context

- `lego/operator/internal/publish/publish.go` (~181–246) — the publish path and prefix layout `<appID>/<revision>/`; teardown deletes the whole `<appID>/` prefix.
- Credentials/config: `BEX_STATIC_S3_ENDPOINT`/`_BUCKET`/`_REGION`/`_SECRET` (docs/ADR029-static-sites.md); the bucket is dedicated to static content — never `bex-tfstate` — so a prefix purge is safe by construction, but the code must still refuse to run with an empty appID prefix.
- Registers as a t002 teardown func, only for `static_site` Apps; idempotent (no objects ⇒ success); S3 unreachable ⇒ requeue.
- The static-server's host→site map refreshes on `BEX_STATIC_RESYNC` — deleting the App's CR already drops the host; this task is about the stored objects.

## Steps

1. Add a `purgePrefix(ctx, appID)` to the publish package (list + batch delete, paginated).
2. Guard: empty/blank appID ⇒ error, never a whole-bucket purge.
3. Register in the t002 hook for `static_site` type.
4. Test against a fake S3 (or the existing publish test harness): multiple revisions' objects all removed, other apps' prefixes untouched.

## Files

- `lego/operator/internal/publish/publish.go` (+ test)
- `lego/operator/internal/controller/app_controller.go` (registration)

## Acceptance criteria

- [ ] Deleting a static_site App removes every object under `<appID>/` across all revisions.
- [ ] Sibling apps' objects are untouched; empty-prefix purge is impossible.
- [ ] Non-static Apps skip this teardown; S3 misconfig/unreachable requeues rather than dropping the finalizer.

## Out of scope

- Purging prefixes of static sites deleted before this shipped (manual one-shot).
- Static-server cache invalidation (per-revision immutable objects age out on their own once unreferenced).
