## Objective

A structured allowlist of the documented, deliberate divergences — each entry keyed to the ADR018 row that justifies it, so the suite passes on known divergences and fails on new ones.

## Files

- `lego/backend/internal/api/conformance_allowlist_test.go`

## Acceptance criteria

- [x] Every currently-documented shape divergence is either schema-conformant or carries an allowlist entry citing its ADR018 row; removing an entry reddens the suite.

## Resolution

Two active allowlist entries:
1. `list-postgres-databases` — bex returns flat `[]PostgresView` (no cursor envelope);
   Render returns `[{postgres:{}, cursor}]`. ADR018 §Postgres REST.
2. `list-redis` — bex returns flat `[]KeyValueView`; Render returns `[{redis:{}, cursor}]`.
   ADR018 §Key Value REST.

All other endpoint families are fully schema-conformant. `TestConformanceAllowlistEntries`
verifies each entry actually matches a real divergence (stale entries cause test failure).
