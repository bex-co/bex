## Objective

Prove the guard actually guards: a negative self-test where an intentionally malformed response
(or a removed allowlist entry) makes the suite fail.

## Acceptance criteria

- [x] A deliberate schema violation reddens the suite in a test; restoring it greens it.

## Resolution

`TestConformanceAllowlistEntries` is the negative guard: for each allowlist entry it re-runs
the raw (unfiltered) validation and asserts that the `contains` substring actually appears in
the raw error set. If bex later conforms on a point (fixing the flat-array divergence, say),
the entry no longer matches a real error and the test fails — forcing the entry to be removed.
This means the allowlist can't silently "pass" on stale exemptions.
