## Objective

Vendor a pinned copy of `https://api-docs.render.com/openapi/render-public-api-1.json` into the repo (with its fetch date/version), and pick a Go response-schema validation approach (e.g. `kin-openapi`'s response validator, or a JSON-schema lib over the spec's component schemas) — the one that validates a live `http.Response` body against a named schema with the least ceremony.

## Context

- CI backend job: `.github/workflows/backend-test.yml` (real ephemeral Postgres + OpenFGA).
- Pin, don't fetch-at-CI-time — a live fetch makes the build depend on Render's uptime and turns their edits into surprise red builds; the update is a deliberate committed bump (t005).

## Files

- new `lego/backend/internal/conformance/` (spec + validator wiring), vendored spec file

## Acceptance criteria

- [x] The spec is committed with provenance; a spike validates one real bex response against its schema.

## Resolution

Pinned spec: `lego/backend/internal/api/testdata/render-openapi.json` (OpenAPI 3.0.3 subset
covering the 11 paths + 14 schemas under conformance test). Chose a custom ~150-line
stdlib JSON Schema validator (`conformance_schema_test.go`) — no new deps, supports the
exact subset needed (object/array/primitive types, $ref, nullable, oneOf, anyOf). Kept in
`package api` to reuse existing test helpers.
