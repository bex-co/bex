## Objective

Give a per-App registry credential a rotation path: a documented operator action that regenerates the password, updates the `reg-pull-<name>` pull Secret and the shared `zot-htpasswd` entry together, and leaves the App pulling with the new credential — so a compromised credential has a remediation short of deleting the App.

## Context

- `lego/operator/internal/registry/creds.go:84-120` — `EnsureCreds` generates the password exactly once at first create; every later reconcile re-derives it from the existing pull Secret (`extractPassword`) and `ensureHTPasswdEntry` short-circuits when the user exists. There is no re-issue path, no TTL.
- The CLI-auth work shipped the same day rotates OAuth refresh tokens; registry creds are the odd one out.
- Trigger design is part of the task: an App annotation (e.g. `bex.co/rotate-registry-credential: <nonce>`) or delete-the-Secret-to-reissue semantics — pick one, justify it in ADR022, and make it idempotent.
- kubelet reads the imagePullSecret at pull time, so updating the Secret content suffices for future pulls; no pod restart required.

## Steps

1. Decide the trigger (annotation vs Secret-deletion re-issue); record the decision in docs/ADR022-tenant-isolation.md § Per-App pull credentials.
2. Implement re-issue in `registry.EnsureCreds` (or a sibling `RotateCreds`): new password, update pull Secret + htpasswd entry under the existing optimistic-lock helpers, same ACL entry.
3. Write the operator runbook snippet (how to rotate one App's credential, how to verify old-rejected/new-accepted).
4. Unit-test: rotation changes the stored bcrypt hash and Secret content; a second rotation is idempotent per nonce.

## Acceptance criteria

- [ ] A documented action rotates one App's registry credential; old password rejected, new accepted (test or `scripts/verify-per-app-registry-isolation.sh` extension).

- [ ] ADR022 documents trigger + runbook.

## Out of scope

- Automatic TTL-based rotation (this ships the manual path; scheduled rotation is a follow-up if ever needed).
- Push-credential (`BEX_REGISTRY_PUSH_SECRET`) rotation — different minting path (`scripts/registry-secrets.sh`), owned by w7/m37's credential-chores territory.
