## Objective

Remove the command-injection vector: `kubernetes_version` is interpolated directly into the `run:` scripts inside double quotes in a job whose env contains `secrets.HCLOUD_TOKEN`, so a collaborator who can dispatch the workflow can break out of the packer `-var` argument and exfiltrate the token (codex-security #16, medium). `image_name` is already safe (funneled through an env var).

## Context

- `.github/workflows/snapshot.yml:54/61/88` — `${{ inputs.kubernetes_version }}` literal-interpolated into `packer validate`/`build` `-var "kubernetes_version=…"` and echoed unquoted on :88.
- `:39/40` — job env exposes `HCLOUD_TOKEN`; `IMAGE_NAME` env shows the safe pattern.
- w7/m65 SHA-pinned the GitHub *actions* — orthogonal, does not address input-to-shell.

## Steps

1. Add `KUBERNETES_VERSION: ${{ inputs.kubernetes_version }}` to the job env and reference it as `${KUBERNETES_VERSION}` (quoted) in the `run:` scripts.
2. Add a regex guard step before use: `[[ "${KUBERNETES_VERSION}" =~ ^v?[0-9]+\.[0-9]+\.[0-9]+$ ]] || { echo "bad version"; exit 1; }`.
3. Audit other `workflow_dispatch` inputs for the same expression-in-shell pattern.
