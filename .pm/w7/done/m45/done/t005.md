## Objective

Add meaningful tests that assert the exact failure mode this milestone fixed: `keyvalues update` of `maxmemoryPolicy` and `ipAllowList` (including clear) really mutates the instance and returns a non-empty diff — a regression guard against the silent `200`-empty-diff no-op returning.

## Context

- Backend tests live in `lego/backend/internal/keyvalue/` (unit + the integration suite gated on `BEX_TEST_DB_URI`/`BEX_TEST_OPENFGA_URL`, which CI runs against real ephemeral Postgres + OpenFGA — not skipped).
- The bug was silent success, so a test that only checks exit 0 / HTTP 200 would have passed against the broken code. Assert the **read-back value changed** and the **diff is non-empty**, mirroring the `checkFields` lesson in `.pm/w9/done/m2/verify.sh`.

## Steps

1. Add a test: update `maxmemoryPolicy` (e.g. `allkeys_lru` → `noeviction` via the `queue` alias and via a raw policy) and assert the persisted/read-back value changed and the response diff is non-empty.
2. Add a test: update `ipAllowList` replaces entries (asserting CIDR **and** description round-trip), and `--clear`/empty-list empties it; assert the main-PATCH path and the dedicated `PUT …/ip-allow-list` route produce the same result.
3. Add a negative test: an invalid policy / invalid CIDR is rejected (not silently ignored).
4. Run `cd lego/backend && go test ./...`.
