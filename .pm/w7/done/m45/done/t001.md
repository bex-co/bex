## Objective

Make `PATCH /v1/key-value/{id}` accept and apply `maxmemoryPolicy` so the unmodified Render CLI's `keyvalues update <kv> --memory-policy <policy>` actually changes the instance's eviction policy, instead of returning `200` with an empty diff and leaving it unchanged.

## Context

- `lego/backend/internal/keyvalue/rest.go` — `handleUpdateKeyValue` currently decodes only `name`/`plan`/`dryRun`; the `maxmemoryPolicy` key in the request body is dropped by the JSON decoder.
- `lego/backend/internal/keyvalue/service.go` — `KeyValuePatch` has no `MaxmemoryPolicy` field; `UpdateKeyValue` is the shared core behind REST/GraphQL/MCP/dashboard.
- The **create** path already maps `--memory-policy` correctly: the friendly aliases `cache` → `allkeys_lru` and `queue` → `noeviction`, plus the raw policies (`noeviction | allkeys_lru | allkeys_lfu | allkeys_random | volatile_lru | volatile_lfu | volatile_random | volatile_ttl`). Reuse that same normalization/validation — do not duplicate it.
- The value lands on the KeyValue CR `spec` (`app.bex.co/v1alpha1`), which the operator reconciles into the Valkey config. See [docs/ADR021-keyvalue-management.md](../../../docs/ADR021-keyvalue-management.md).

## Steps

1. Add `MaxmemoryPolicy *string` (pointer: absent vs. set) to `KeyValuePatch` and decode it in `handleUpdateKeyValue`.
2. Route it through the shared create-path policy-alias normalization + validation so `cache`/`queue`/raw values map identically on update and create; reject an invalid policy with a clear Render-shaped error.
3. Apply the normalized value to the KeyValue CR spec in `UpdateKeyValue` and include it in the response diff.
4. Manually verify against a live bex with the unmodified `render` CLI: `keyvalues update <kv> --memory-policy queue` then `keyvalues get <kv> -o json` shows `maxmemoryPolicy: noeviction`.

## Files

- `lego/backend/internal/keyvalue/rest.go`
- `lego/backend/internal/keyvalue/service.go`
- shared memory-policy normalization/validation helper (wherever the create path lives)

## Acceptance criteria

- [ ] `render keyvalues update <kv> --memory-policy queue` changes `maxmemoryPolicy` to `noeviction` on read-back (non-empty diff).
- [ ] Friendly aliases (`cache`/`queue`) and raw policies both apply on update, identically to create.
- [ ] An invalid policy is rejected with a clear error (not silently ignored, not a 500).
