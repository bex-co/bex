## Objective

Make `PATCH /v1/key-value/{id}` accept `ipAllowList` (and an empty list to clear) so the unmodified Render CLI's `keyvalues update <kv> --ip-allow-list …` and `--clear-ip-allow-list` actually mutate the instance's allow-list. Today both are accepted with `200` and an empty diff, changing nothing — the CLI sends the field on the main PATCH, but only the separate `PUT /v1/key-value/{id}/ip-allow-list` route honors it.

## Context

- `lego/backend/internal/keyvalue/rest.go` — `handleUpdateKeyValue` drops the `ipAllowList` key.
- A dedicated `PUT /v1/key-value/{id}/ip-allow-list` route already applies the allow-list correctly (shipped in w7/m5). The unmodified Render CLI's `update --ip-allow-list` does **not** use it — it sends the field on the main PATCH.
- Entries are `{cidrBlock, description}`; per-entry descriptions must persist and round-trip on read (w4/m24).
- CIDR validation exists as `core.ValidateCIDRs` (the w7/m5 gate). The KV allow-list feeds the KV network access-control mechanism from w7/m5 — reuse it; do not fork the apply logic.

## Steps

1. Add `IPAllowList *[]KeyValueIPAllowListEntry` (pointer so "absent" is distinguishable from "explicitly empty") to `KeyValuePatch`; decode it in `handleUpdateKeyValue`.
2. Route the apply through the **same** logic as the dedicated `PUT …/ip-allow-list` route so replace + clear behave identically across both entry points (single source of truth); validate via `core.ValidateCIDRs`.
3. `--clear-ip-allow-list` sends an empty list → empties the CR allow-list (distinct from an omitted field, which leaves it untouched).
4. Manually verify against a live bex with the unmodified `render` CLI: `keyvalues update <kv> --ip-allow-list cidr=203.0.113.0/24,description=hq` → `get` shows the entry with its description; `keyvalues update <kv> --clear-ip-allow-list` → `get` shows an empty list.

## Acceptance criteria

- [ ] `render keyvalues update <kv> --ip-allow-list cidr=203.0.113.0/24,description=hq` replaces the list and the CIDR **and** description return on `get`.
- [ ] `render keyvalues update <kv> --clear-ip-allow-list` empties the allow-list.
- [ ] The main PATCH and the dedicated `PUT …/ip-allow-list` route produce identical results (no divergence).
