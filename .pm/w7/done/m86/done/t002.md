## Objective

Implement t001's chosen shape, gated so that off is byte-identical to today.

## Context

- ADR060 D3's flags: `--export-cache type=registry,ref=<registry>/<app-repo>-cache,mode=max,image-manifest=true,compression=zstd` and the matching `--import-cache`.
- **`mode=max` is deliberate:** bex builds are typically multi-stage (the native path always is — build stage plus runtime copy), and the default `min` discards exactly the intermediate layers worth caching. `image-manifest=true` stores the cache as an OCI image manifest, required for OCI-strict registries and the safe choice for Zot.
- Env gate `BEX_BUILD_CACHE=registry`; unset must produce a byte-identical Job spec (the pattern used throughout the operator's optional features).
- `--import-cache` is best-effort by construction: a missing cache is a clean build, which is today's behavior.
- Both `BuilderNative` and the Dockerfile path go through the same arg construction at `build.go:436-455`.

## Steps

1. Add the cache flags per t001's shape, for both the Dockerfile and native builders.
2. Gate on `BEX_BUILD_CACHE`; document it in the `CLAUDE.md` env table and mirror the name into `.env.example` (repo rule).
3. Ensure the unset path produces an unchanged Job spec — assert it rather than eyeballing it.
4. Confirm the cache ref derives from the same per-App repository identity the image push uses, so it cannot drift.
