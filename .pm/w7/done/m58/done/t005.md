## Objective

Make the guard's failure mode a durable, repeatable regression proof — not just the one-time manual negative-check in t003. Demonstrate that the guard fails for **each** missing baseline field on a non-exempt workload, and that egress-meter's exemption does not accidentally whitelist a real regression elsewhere.

## Context

- t003 proves the guard goes red when the static-server fix is reverted. This task generalizes that into a reproducible check other maintainers can re-run.
- `scripts/gitops-validate.sh` is shell; the repo's pattern for guard self-tests is either a companion fixture the script asserts against (the alerts `promtool` unit-test pattern) or a documented reproducible negative case. Pick whichever fits the guard's shape without over-engineering.
- Assert the guard catches: (a) a workload with no `securityContext` at all (the static-server bug), (b) a workload missing exactly one baseline field (e.g. `readOnlyRootFilesystem` dropped), (c) that the egress-meter exemption still passes and does not mask a sibling regression.

## Steps

1. Add a reproducible negative-test harness for the guard: feed it a temporarily mutated copy (or an inline fixture) missing each baseline field in turn and assert it exits non-zero; assert the unmutated tree exits zero.
2. Cover the three cases above (no securityContext / one field missing / exemption still scoped).
3. Wire it so CI or a `make`/script target can run it, or document the exact reproduction if a harness is overkill for a shell guard.
4. Run the full `scripts/gitops-validate.sh` + the negative harness; confirm green on the fixed tree.

## Files

- `scripts/gitops-validate.sh` (or a companion `*-test` fixture/script alongside it)

## Acceptance criteria

- [ ] A reproducible negative proof exists showing the guard fails for a no-securityContext workload and for each individually-missing baseline field.
- [ ] The egress-meter exemption is shown to remain narrowly scoped (it does not mask an unhardened sibling).
- [ ] The guard + negative harness pass green on the fixed tree.

## Out of scope

- Behavior changes to the manifests (t001/t002) or the guard logic (t003) beyond what testing reveals as a real defect.
