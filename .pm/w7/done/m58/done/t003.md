## Objective

Add a structural guard to `scripts/gitops-validate.sh` that asserts **every** platform `Deployment`/`DaemonSet` under `lego/operator/config` carries the hardened securityContext baseline, with the t002 exemption list as the only allowed escapes. This is the milestone's durable fix — static-server slipped through precisely because the existing guard is per-component (egress-meter caps, opensandbox lifecycle-server), never universal.

## Context

- `scripts/gitops-validate.sh` already uses `yq`-based assertions (e.g. `egress_caps` at ~L308, `opensandbox_pod` hardening at ~L987). Follow that pattern; CI runs the script via `.github/workflows/gitops.yml`.
- The baseline to assert (per non-exempt workload): pod `.spec.template.spec.securityContext.runAsNonRoot == true` + `seccompProfile.type == RuntimeDefault`; each container `securityContext.allowPrivilegeEscalation == false` + `readOnlyRootFilesystem == true` + `capabilities.drop` contains `ALL`.
- The guard must **iterate all workloads under `config/`** (glob, so a newly added component is covered automatically — the m30 "coverage is enumerated, not hand-picked" principle), skipping only the t002 exemption list (egress-meter, and pg-sni-proxy only if t002 exempted rather than fixed it).
- Prefer failing on a **missing** field (fail-closed) so a component that omits securityContext entirely — exactly the static-server bug — is caught, not silently passed.

## Steps

1. Add a `gitops-validate.sh` section that globs every `Deployment`/`DaemonSet` under `lego/operator/config`, and for each non-exempt workload asserts the full baseline set on the pod and every container.
2. Encode the exemption list from t002 as an explicit, commented allowlist (component + exempted field + reason); egress-meter is the expected sole entry.
3. Make the check fail-closed: a workload with no `securityContext`, or missing any baseline field, fails.
4. Run `scripts/gitops-validate.sh` locally; confirm it passes against the t001/t002-fixed tree.
5. Negative-prove: temporarily revert the static-server securityContext, re-run, confirm the guard goes **red**, then restore.
