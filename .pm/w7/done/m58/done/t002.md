## Objective

Sweep every platform `Deployment`/`DaemonSet` under `lego/operator/config`, bring any below the hardened baseline up to it, and produce the documented exemption list the CI guard (t003) will encode — so the guard has an explicit, reasoned allowlist rather than a hardcoded skip.

## Context

- Confirmed 2026-07-30: pg-sni-proxy (`config/pg-sni-proxy/daemonset.yaml`) has `allowPrivilegeEscalation: false` + `capabilities.drop: [ALL]` + `readOnlyRootFilesystem: true` but is **missing** `runAsNonRoot: true` + `seccompProfile` that its sibling kv-sni-proxy (`config/kv-sni-proxy/daemonset.yaml`) has. Decide: close the gap, or exempt with a recorded reason (it binds `hostPort: 5432` — but hostPort binding is kubelet-side and does not require the container to run as root, so closing is likely correct).
- egress-meter (`config/egress-meter/daemonset.yaml`) is **deliberately** privileged: `hostNetwork: true`, `runAsNonRoot: false`, and `capabilities.add: [BPF, NET_ADMIN, PERFMON, SYS_ADMIN, SYS_RESOURCE]` for its post-policy L3 metering. This is the one legitimate exemption — it must be on the allowlist with its rationale, not "fixed."
- The baseline set (from the hardened siblings): pod `runAsNonRoot: true` + `seccompProfile: RuntimeDefault`; container `allowPrivilegeEscalation: false` + `readOnlyRootFilesystem: true` + `capabilities.drop: [ALL]`.

## Steps

1. Enumerate every `Deployment`/`DaemonSet` under `lego/operator/config` (api, ssh, manager, activator, staticserver, pg-sni-proxy, kv-sni-proxy, egress-meter, and any others).
2. For each, record which baseline fields are present/absent.
3. Close pg-sni-proxy's `runAsNonRoot`/`seccompProfile` gap (or exempt-with-reason if a real bind constraint is proven).
4. Write the exemption list (component name → exempted field(s) → rationale) into the milestone as the contract t003 encodes; egress-meter is the expected sole entry.
5. `kustomize build` to confirm all edited manifests still render.
