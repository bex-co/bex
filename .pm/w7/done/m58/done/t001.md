## Objective

Add the securityContext hardening every other bex platform pod already carries to the static-server Deployment — the one internet-facing platform component running with no securityContext at all — and verify it still serves static content and reads S3 under a read-only root filesystem.

## Context

- `lego/operator/config/staticserver/deployment.yaml` today has **no** pod-level or container-level `securityContext` (confirmed by sweep 2026-07-30). Its siblings all do:
  - bex-api (`config/api/deployment.yaml`), ssh-gateway (`config/ssh/deployment.yaml`), manager (`config/manager/manager.yaml`), activator (`config/activator/deployment.yaml`): pod `runAsNonRoot: true` + `seccompProfile`, container `allowPrivilegeEscalation: false` + `readOnlyRootFilesystem: true` + `capabilities.drop: [ALL]`.
- static-server runs the manager image with `command: ["/staticserver"]`, serves `:8080`, reads S3 via the `bex-static-read-s3` Secret, and already sets `AWS_EC2_METADATA_DISABLED=true`. It serves all tenant static-site content through the shared Ingress → internet-facing.
- `bex-system` is deliberately privileged-PSS (egress-meter needs BPF caps — see the comment at `config/manager/manager.yaml:9`), so there is no namespace PodSecurity backstop; the per-pod context is the only control.
- Read-only rootfs risk: the Go AWS SDK / net-http server may need a writable temp dir. If startup or an S3 read fails under `readOnlyRootFilesystem: true`, mount an `emptyDir` at the needed path (e.g. `/tmp`) rather than relaxing the rootfs.

## Steps

1. Add the pod-level `securityContext` (`runAsNonRoot: true`, `seccompProfile: { type: RuntimeDefault }`) and container-level `securityContext` (`allowPrivilegeEscalation: false`, `readOnlyRootFilesystem: true`, `capabilities: { drop: [ALL] }`) to `config/staticserver/deployment.yaml`, copying the exact shape from a hardened sibling.
2. If the image runs as root by default, set `runAsUser`/`runAsGroup` to a non-root uid consistent with the siblings (or confirm the base image already has a non-root user).
3. Build/run locally (or via envtest/kustomize render + a smoke deploy if a cluster is available) and confirm static-server starts, passes its `/healthz` readiness probe, serves content, and completes the startup S3 `ListBucket` check under the read-only rootfs; add an `emptyDir` for any writable path it needs.
4. `kustomize build` the config tree to confirm the manifest still renders.

## Files

- `lego/operator/config/staticserver/deployment.yaml`

## Acceptance criteria

- [ ] static-server carries the full hardened set (pod `runAsNonRoot` + `seccompProfile: RuntimeDefault`; container `readOnlyRootFilesystem` + `allowPrivilegeEscalation: false` + `drop: [ALL]`), matching a named sibling.
- [ ] static-server starts, passes readiness, and reads S3 under the read-only rootfs — writable paths (if any) are backed by `emptyDir`, not a writable rootfs.
- [ ] `kustomize build` over the config tree still renders.
