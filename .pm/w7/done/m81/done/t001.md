## Objective

`w7/027.md` conditioned promotion on "a decision on whether it should be opt-in" — this task makes that decision instead of assuming it. Pick one contract and record it with the rejected alternative: **(a) Render-parity unconditional** — the `livenessProbe` carries whatever handler the App already has, TCP default included, exactly as Render restarts any instance after 60s of failures with no per-service control; or **(b) explicit-path opt-in** — TCP default ⇒ no liveness (a dead-but-listening process is already down at the socket level and the readiness probe covers the routing half), explicit `healthCheckPath` ⇒ liveness, composing with m80's two-mode contract where setting a path is the user saying what healthy means.

## Context

- `lego/operator/internal/controller/deployment_projection.go:187-190` — the "deliberately no livenessProbe" comment this decision replaces.
- `lego/operator/internal/controller/deployment_projection.go:221-230` — `healthCheckHandler`: unset path ⇒ TCPSocket, set path ⇒ HTTPGet. The decision determines whether liveness exists in the TCP branch.
- Render gives no per-service control ([Health Checks](https://render.com/docs/health-checks)) — option (b) is a deliberate divergence and must be argued as one in the ledger, not slipped in.
- The restart-spiral hazard (slow SSR route → liveness restart → cold start → slower next probe) is the reason this was deferred from m80; weigh how each option bounds it now that the `startupProbe` owns boot.
- Note for the argument: a wedged event loop usually still completes the TCP handshake (the kernel accepts), so TCP liveness rarely catches the wedge this milestone is motivated by — that cuts toward (b), but (b) leaves TCP-mode services without the restart stage Render gives them.

## Steps

1. Walk both options against the failure modes (wedged process, slow-under-load SSR, dead socket) and against Render's documented behavior.
2. Pick one; write the decision, the rejected alternative, and the reasoning into the `deployment_projection.go` comment block that currently says "deliberately no livenessProbe".
3. Record the same decision in `docs/ADR004-app-deployment.md` (health-gating section) so the contract does not live only in code.
