## Objective

After cryptographic verification, parse the signed Cosign/Simple-Signing payload and require its digest and repository subject to exactly match the image being admitted. Today `verifyECDSA` only checks `ecdsa.VerifyASN1` over the payload bytes and never compares `critical.image.docker-manifest-digest` or `critical.identity.docker-reference` to the requested image (codex-security #8, medium) — so a registry writer can reattach a previously-valid signed payload under another digest's `<digest>.sig` tag.

## Context

- `lego/operator/internal/imagecheck/imagecheck.go:78-119` — `Verify` resolves the digest (used only to pick the `<digest>.sig` tag) and loops payload blobs through `verifyECDSA(l.sig, payload)` (:114, :319-325).
- `verifyECDSA` only does `ecdsa.VerifyASN1` over SHA256(payload); no `json.Unmarshal` of the payload.
- `lego/operator/internal/webhook/pod_admit.go:58` calls Verify.
- `imagecheck_test.go:140` — only a matching-payload positive case; no mismatched-digest/repo negative.

## Steps

1. Define a Simple Signing struct (`critical.image.docker-manifest-digest`, `critical.identity.docker-reference`).
2. After `verifyECDSA` succeeds, `json.Unmarshal` the payload and reject if the digest != resolved digest OR the reference != `host+"/"+repo`.
3. Add mismatched-digest and mismatched-repo negative tests.
