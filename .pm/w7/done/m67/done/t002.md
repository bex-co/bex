## Objective

Make `kratos-db`, `hydra-db`, and `openfga-db` WAL-archive continuously and take a nightly base backup through the `auth-dbs` ObjectStore.

## Context

- Pattern: `deploy/gitops/charts/bex-postgres/cluster.yaml:45-50` (`plugins:` block — `barman-cloud.cloudnative-pg.io`, `isWALArchiver: true`, `barmanObjectName`, `serverName`) and `deploy/gitops/charts/bex-postgres/scheduled-backup.yaml` (nightly `ScheduledBackup`, method plugin).
- serverName convention: `<name>-pg<major>` (e.g. `kratos-db-pg17`), matching the tenant-Postgres convention rather than `bex-db`'s plain name — a major-version upgrade needs a fresh server identity in the archive, and adopting the suffix now avoids a mid-upgrade rename later (record the convention in ADR031, t005). The auth Cluster manifests don't pin `imageName`, so read the actual running major from prod (`kubectl get cluster -n auth -o jsonpath` on the image/status) before hardcoding.
- Stagger the three ScheduledBackups after `bex-db`'s 04:00 UTC (e.g. 04:15 / 04:30 / 04:45) so base backups don't contend.

## Steps

1. Add the `plugins:` block to each of the three Cluster manifests in `deploy/gitops/charts/auth-dbs/`.
2. Add three `ScheduledBackup` manifests (or one file with three docs) to the same chart + kustomization.
3. Argo-sync; verify WAL archiving turns healthy (`Continuous archiving` condition) and trigger/verify a first base backup per cluster.

- [x] Rollout caused no auth outage (Kratos/Hydra/OpenFGA stayed serving — plugin attach is a rolling change; verify switchover behavior).
