## Objective

Prove the auth-DB backups actually restore: recover `kratos-db` from the bucket into a throwaway recovery cluster in prod and verify a known identity row, per the drilled `bex-db` runbook.

## Context

- Runbook: `docs/ADR031-platform-data-backup.md` § bex-db restore (CNPG `bootstrap.recovery` + `externalClusters` plugin reference; recovery always creates a NEW cluster, never in-place). Precedent drill: `drills/2026-07-28-barman-plugin-pitr.md`.
- Verification query: a known Kratos identity (e.g. the operator's own account email) present in the recovered `identities` table.
- The recovery cluster is throwaway: create in `auth` (or a scratch namespace), verify, delete — it must never be pointed at by Kratos.

## Steps

1. Write the recovery-cluster manifest referencing ObjectStore `auth-dbs` + serverName `kratos-db-pg<major>`.
2. Run the recovery in prod, wait for the cluster to reach healthy, run the verification query.
3. Delete the recovery cluster and its PVCs; confirm zero leftovers.
4. Record the drill as `drills/<date>-auth-dbs-restore.md` (commands, timings, verification evidence).
