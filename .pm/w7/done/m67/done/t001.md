## Objective

Create the shared Barman Cloud `ObjectStore` CR the three auth CNPG clusters will reference, plus the out-of-band S3 credential Secret it points at, following the `bex-db` pattern byte-for-byte where possible.

## Context

- Pattern: `deploy/gitops/charts/barman-cloud-objectstores/bex-db.yaml` — `barmancloud.cnpg.io/v1 ObjectStore`, `destinationPath: s3://bex-tfstate/bex-db`, Wasabi `endpointURL`, `s3Credentials` from Secret `bex-db-backup-s3`, wal+data gzip, `retentionPolicy: 7d`, Argo `SkipDryRunOnMissingResource` annotation.
- The ObjectStore must live in the `auth` namespace (same namespace as the Clusters that reference it); one ObjectStore is shared by all three clusters — each Cluster differentiates via its own `serverName` (t002). Barman requires serverNames to be unique within a destination.
- Credential Secret `auth/auth-dbs-backup-s3` (`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`) is out-of-band — same custody rules as `bex-system/bex-db-backup-s3` (never in git; documented in ADR031's one-time-setup section, amended in t005).

## Steps

1. Add `auth-dbs.yaml` to `deploy/gitops/charts/barman-cloud-objectstores/` (namespace `auth`, `destinationPath: s3://bex-tfstate/auth-dbs`, retention 7d) and register it in that chart's `kustomization.yaml`.
2. Provision the `auth/auth-dbs-backup-s3` Secret in prod out of band (reuse the bex-tfstate backup credential unless a scoped key is trivially mintable).
3. Argo-sync and confirm the ObjectStore CR is healthy in the `auth` namespace.

## Files

- `deploy/gitops/charts/barman-cloud-objectstores/auth-dbs.yaml` (new)
- `deploy/gitops/charts/barman-cloud-objectstores/kustomization.yaml`

## Acceptance criteria

- [x] `kubectl get objectstore -n auth auth-dbs` exists and is accepted by the plugin controller.
- [x] The Secret is present in prod and referenced by name only (no credential material in git).

## Out of scope

- Wiring the Clusters to it (t002); local-CAPD overlay behavior (backups stay prod-only, matching bex-db).
