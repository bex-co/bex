# livenessProbe — Render restarts an unhealthy instance after 60s; bex never restarts one

Split out of **m80** deliberately (see that milestone's Out of scope), not forgotten.

Render's documented steady-state behavior has two stages: after **15s** of consecutive health-check failures it stops routing traffic to an instance, and after **60s** it **restarts** the instance. bex implements only the first (readiness → out of rotation). A wedged instance — process alive, event loop blocked, deadlocked — is never restarted and stays broken until someone notices.

Kubernetes mapping: `livenessProbe` with the same handler, `timeoutSeconds: 5`, `periodSeconds: 10`, `failureThreshold: 6` → 60s.

**Why it is not in m80.** Liveness on a tenant's health path turns a slowdown into a restart, and a restart makes the next probe slower still — a spiral, on exactly the SSR-shaped apps that motivated m80. Render carries the same hazard, so shipping it is defensible parity, but bex should not adopt it as an unconditional default without:

- **m80/t003's `startupProbe` landed** — while startup runs, kubelet suspends liveness, which is what stops a slow boot from being killed. This is a hard precondition.
- **Guidance for pointing `healthCheckPath` at a cheap endpoint.** Probing an expensive SSR route every 10s and restarting on 6 failures is a different proposition from probing `/healthz`. Render's own docs warn about health-endpoint design; bex has no equivalent guidance today.
- **A decision on whether it should be opt-in.** Render gives no per-service control. bex could default it off and enable it with an explicit `healthCheckPath`, which composes well with m80's two-mode contract: TCP default → no liveness; explicit path → the user has said what healthy means, so restarting on it is reasonable. That option does not exist on Render and would be a deliberate divergence worth arguing rather than assuming.

Promote once m80 closes. Until then `docs/ADR018-render-parity.md` records this as a known divergence (m80/t006), so it is visible rather than silently missing.
