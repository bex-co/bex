## Objective

Prove the registry hole is closed and keep it closed: extend the live verification script with registry-auth probes (anonymous catalog/push refused, credentialed build round-trips), and add a structural guard to `scripts/gitops-validate.sh` that fails CI if the Zot values ever lose their auth/accessControl config.

## Context

- `scripts/verify-tenant-isolation.sh` already has the probe helpers (`http_reachable`, `probe_deny_url` from m4) and an idempotent probe-App pattern — registry probes belong there (or a small sibling script if scope fights).
- `scripts/gitops-validate.sh` already carries structural guards: default-deny policies (m1) and the RBAC guard (m7) — follow the same grep-the-manifest pattern for the Zot auth stanza in `deploy/gitops/base/zot.yaml`.
- The anonymous-push probe must run from a pod that can reach Zot at all (build-labeled, per `network-policies.yaml:64-68`) — otherwise the netpol, not auth, refuses it and the probe proves nothing about this milestone.

## Steps

1. Add registry probes to the verify script: anonymous `GET /v2/_catalog` and an anonymous blob/manifest push both refused (401/403) from a build-labeled probe pod; a credentialed build-from-git App round-trips (build → push → deploy → serve).
2. Add the `gitops-validate.sh` check: fail when the Zot Application values lack the auth/accessControl configuration (and when the chart pin regresses to a wildcard).
3. Run both against the local mock cluster; confirm the CI guard goes red on a deliberate local mutation (auth stanza removed), then restore.
