## Objective

Turn on authentication in the Zot deployment per the t001 design: an htpasswd Secret (sealed for prod, ADR016 flow), a custom Zot config enabling `http.auth.htpasswd` + `accessControl` (write always authenticated; read per t001), and pin the chart version (the existing TODO at `zot.yaml:13`).

## Context

- `deploy/gitops/base/zot.yaml` — Argo CD Application over the upstream Zot Helm chart, `targetRevision: "0.1.*"` (unpinned), values with `mountConfig: false`; a custom config needs `mountConfig: true` + the configuration block in values.
- Credential custody: prod htpasswd Secret via SealedSecrets (`kubeseal`, docs/ADR016-sealed-secrets.md); the local CAPD overlay needs the Secret to exist too — prefer a plain overlay Secret so auth stays ON locally and t005's probes exercise the real path (the `overlays/local` `$patch: delete` pattern from tenant-node-egress is the fallback if the chart fights it, but auth-off-locally weakens verification).
- The existing NetworkPolicies (`deploy/gitops/base/network-policies.yaml`) stay as-is — auth complements the network layer, it does not replace it.

## Steps

1. Pin the Zot chart to an exact version; flip to a mounted custom config with htpasswd auth + the t001 accessControl policies.
2. Create the htpasswd credential: sealed Secret for prod (`deploy/gitops/base/`), plain Secret for the local overlay.
3. Apply on the local mock cluster and confirm Zot comes up healthy with auth enforced.

## Files

- `deploy/gitops/base/zot.yaml`
- `deploy/gitops/base/` (new sealed-secret manifest) + `deploy/gitops/base/kustomization.yaml`
- `deploy/gitops/overlays/local/kustomization.yaml` (local credential)

## Acceptance criteria

- [ ] Anonymous `/v2/` requests are refused per the t001 policy (write always 401/403; read per the documented decision).
- [ ] Zot deploys healthy via kustomize/Argo with the pinned chart on the local mock cluster.
