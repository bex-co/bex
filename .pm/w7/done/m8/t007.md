## Objective

Add tests that assert the real behavior and failure modes m8 shipped — not tautologies. The high-value assertions: the build Job spec mounts the docker-config credential into the buildkit (and cosign, when signing) container and **nowhere a tenant `RUN` step can read it** (never a build-arg, never a declared BuildKit secret, never in the build step's env); unset env var ⇒ byte-identical unauthenticated Job (dev default preserved); the `gitops-validate.sh` zot-auth guard actually fails on a de-authed manifest.

## Context

- Follow the existing patterns: build-Job spec assertions live near `lego/operator/internal/build/` tests; structural-guard behavior can be exercised the way m7's `rbac_test.go` asserts manifest content.
- The isolation suite (`lego/operator/internal/controller/isolation_test.go`) shows the shape for spec-level security invariants.

## Steps

1. Build-Job spec tests: credential mount present + correctly placed with the env var set; absent and byte-identical without it; signing-enabled variant covered.
2. Negative-space test: assert the credential string/Secret name never appears in buildctl args or the build container's env.
3. Guard test: `gitops-validate.sh` red on a de-authed `zot.yaml` fixture, green on the shipped one.

## Files

- `lego/operator/internal/build/` tests
- `lego/operator/internal/controller/` (spec invariant tests, if placed with the isolation suite)

## Acceptance criteria

- [ ] Tests fail if the credential leaks into a tenant-readable location, if the unset-env default regresses, or if the CI guard stops guarding.
- [ ] `make test` (from `lego/operator/`) green.
