## Objective

Make the build Job's BuildKit push authenticate against Zot: mount a `dockerconfigjson` Secret into the buildkit container (`DOCKER_CONFIG` pointing at the mount), named by a new operator env var (e.g. `BEX_REGISTRY_CRED_SECRET`, following the `BEX_TENANT_SIGNING_KEY_SECRET` pattern — a Secret in the build namespace; unset ⇒ current unauthenticated behavior for dev). The credential must live only in the pod filesystem — never a build-arg and never a declared BuildKit secret, so tenant `RUN` steps cannot read it.

## Context

- `lego/operator/internal/build/build.go:184` — the push line (`registry.insecure=true` stays: it's TLS-off, not auth-off; buildctl reads registry creds from `$DOCKER_CONFIG/config.json`).
- Tenant `RUN` steps can mount declared BuildKit secrets (the `GIT_AUTH_TOKEN` precedent at `build.go:191-201`) but cannot read the pod fs — that asymmetry is the whole design.
- w6/006 signing split: when `BEX_TENANT_SIGNING_KEY_SECRET` is set, build+push runs as an initContainer and cosign as the main container — cosign also talks to the registry, so it needs the same docker-config mount.
- New env var ⇒ update the CLAUDE.md env-vars table and keep `.env.example`/`.env.template` in sync (repo rule) if it lands in `.env`.

## Steps

1. Plumb `BEX_REGISTRY_CRED_SECRET` from the operator env into `build.Options`; mount the Secret + set `DOCKER_CONFIG` on the buildkit container (and the cosign container when signing is enabled).
2. Verify against t002's authed Zot on the local mock: a build-from-git App builds, pushes, and deploys; with the env var unset against an authed registry, the push fails 401 (proving enforcement).
3. Update the CLAUDE.md env table (+ `.env.example`/`.env.template` if applicable).

## Acceptance criteria

- [ ] The credential appears nowhere a tenant `RUN` step can read it: not in build args, not as a declared BuildKit secret, not in container env of the build step.
- [ ] The cosign signing path (when enabled) still pushes signatures successfully.
