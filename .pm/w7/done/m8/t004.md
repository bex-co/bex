## Objective

Implement the read side of the t001 decision. If reads become authenticated: the operator ensures a pull Secret exists in the apps namespace and adds `imagePullSecrets` to tenant Deployments so kubelet pulls keep working. If reads stay anonymous: this task collapses to documenting the accepted residual (tenant build steps can still pull — but not modify — cross-tenant images) in the t001 design section and verifying nothing else breaks.

## Context

- Kubelet pulls reach Zot from node identity (`deploy/gitops/base/network-policies.yaml:71-84`), currently anonymous — turning on authenticated read without `imagePullSecrets` breaks every tenant deploy.
- The operator's `secrets` RBAC is namespace-scoped to the apps namespace since m7 (`deploy/gitops/base/operator-apps-rbac.yaml`) — creating a pull Secret there is already covered; no ClusterRole change.
- Prod caveat: some tenant images were `ctr`-imported directly into the tenant node's containerd (see `.pm/FUTURE-MAYBE.md` node bring-up entry) — confirm which pull path live Apps actually use before flipping read auth on prod.

## Steps

1. Read the t001 decision; branch accordingly.
2. Authenticated-read branch: operator ensures the pull Secret (apps namespace) and sets `imagePullSecrets` on tenant Deployments; verify a fresh deploy pulls successfully on the local mock.
3. Anonymous-read branch: write the residual into the t001 design section; spot-check that authenticated write + anonymous read is what Zot actually enforces.
