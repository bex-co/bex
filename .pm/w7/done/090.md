# The native SSH banner says "this workspace" when the org's login requirement refused

Why: every other surface names the org that refused (`organizationId`, `organizationName`, "the organization X requires two-factor authentication in all of its workspaces"), so a member refused over SSH looks for the setting on the wrong page.

- Found by w7/m466 t006's production walk (2026-11-17): with org 2FA on and the secondary's own setting off, `ssh srv-…@ssh.bex.co` printed "bex: this workspace requires two-factor authentication. Enable it in your account settings, then connect again." REST, GraphQL and MCP named the org for the same member.
- The banners are constants: `twoFactorBanner` and `googleLoginBanner` in `lego/backend/internal/sshgateway/nativessh/server.go:152-154`. The gateway learns the refusal from bex-api's verb (`agentsession.TwoFactorHandler`, `lego/backend/internal/agentsession/two_factor.go`), whose answer carries only `code`.
- End state: when the org's setting decided, the verb's answer carries the org's name, and native SSH prints a banner naming it ("bex: the organization <name> requires two-factor authentication in all of its workspaces. …", and the Google sibling). A workspace's own refusal keeps today's banner. A gateway test covers both, and the verb's test covers the new field.
- **Done 2026-11-18:** the verb's answer carries `organizationId` and `organizationName` beside `code` when the org's own setting decided (`agentsession.TwoFactorResponse`, read off the gate's refusal by `core.LoginRefusalOf`). The gateway caches the refusal as a `core.LoginRefusal` and rebuilds bex-api's own coded 403 from it (`LoginRefusal.Err`), so the gateway's refusal names the org on every gateway path (native SSH, web shell, agent attach, sandbox exec). Native SSH prints "bex: the organization <name> requires two-factor authentication in all of its workspaces. Enable it in your account settings, then connect again." and "bex: the organization <name> requires signing in with Google in all of its workspaces. Sign in to bex with Google, add this SSH key again, then connect again.", with the same wording as the channel reason. A workspace's own refusal, and an older bex-api's answer with no org, keep "this workspace". Covered by `TestTheBannerNamesTheOrganizationWhoseSettingRefused` (a real SSH client against the gateway: org 2FA, org Google and the workspace's own 2FA), `TestOnlyTheLoginRequirementCodesGetTheirMessage`, `TestTwoFactorGateNamesTheOrganizationThatDecided` (asked and cached), `TestTwoFactorVerbAnswersAnOrganizationsRequirement` (the real `twofactor.Gate` through the verb) and `TestALoginRefusalRoundTripsThroughLoginRefusal`. With the banner, the verb or the gateway's org naming reverted, each fails. ADR012 §9c updated. Production prints it once a pin carries the commit.
