## Objective

Stop `copyCloneSecret` from blindly overwriting an existing `bex-build` Secret whose name an App-controlled field happens to collide with. The destination is addressed solely by attacker-selected name and `CreateOrUpdate` rewrites type/data/labels without checking the destination's existing App UID / component ownership labels (codex-security #14, medium).

## Context

- `lego/operator/internal/controller/app_controller.go` `copyCloneSecret` (~:703/:908-922) — `buildClient.Get(src)` then `CreateOrUpdate(dst)` setting `dst.Type/Data/Labels` from source; destination name from `app.Spec` (CloneSecret / ExternalRegistryPullSecret / env-from / file-secret). Reached from `predeployPullSecrets` and `mirrorPreDeploySecrets` on every build when `BEX_BUILD_NAMESPACE` is set.
- Contrast `ReclaimAppArtifacts` (build.go) which filters by App UID via `ArtifactIdentity` — the model to mirror.
- `lego/types/v1alpha1/app_types.go:218/303` — the App spec fields that accept unconstrained Secret names.
- Existing label keys: `labelApp` / `labelWorkspace` (confirm exact constants in `internal/controller`).

## Steps

1. In the `CreateOrUpdate` mutate closure, when the destination already exists, assert its `labelApp == app.Name` and workspace label match; on mismatch return an error (or skip + log) instead of overwriting.
2. Ensure every mirror write stamps immutable ownership labels (App name + workspace + UID + component) onto the destination so the check is meaningful for future reconciles.
3. Optionally validate Secret-name fields at admission/CRD level (regex, length) as defense in depth.

## Files

- [ ] A same-named foreign/platform build Secret is not overwritten by a reconciling App.
- [ ] Ownership labels are stamped on every mirrored Secret.
