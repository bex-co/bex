# 033 — Status-subresource convergence: the other half of `m84`, on the CR itself

Why: the unconditioned status writes are the same order of magnitude as the Deployment PUT m84 removed (≈2,880/day per Ready KeyValue), so m84's zero-writes-when-converged property is only half real until the CR's own status is covered.

## Disposition — fixed and done, 2026-09-05

All 24 owner-status update sites across the App, Database, and KeyValue controllers now suppress unchanged status, directly or through `updateStatusIfChanged`, including the shared failure/conflict-retry paths. It compares the complete serialized status, so real deploy facts, phases, conditions, coordinates, and recovery state still persist. Empty `omitempty` slices and nil compare as the same persisted state; this matters for a cron with no run history. A failed comparison read never suppresses the original write, and existing conflict/error handling stays in place.

`reconcile_convergence_envtest_test.go` now records status Update/Patch requests for stable lifecycle fixtures. The initial test extension failed in all three controller cases before the fix. The passing tests cover cron, Database provisioning and Ready, KeyValue provisioning and Ready (with and without backups), and suspended KeyValue. The Ready fixtures explicitly supply the CNPG observation, StatefulSet status, and bound PVC that envtest's missing controllers cannot supply. Phase and suspension-condition assertions verify that actual transitions still persist before testing the next pass for zero writes. Web fixtures without kubelet progress retain their documented status exemption; their legitimate intermediate condition changes are not hidden.

Verification: `make test` passed, including all controller behavior and durable failure-marker conflict tests. All four module linters and whole-program dead-code analysis passed after removing a redundant test-helper namespace parameter; the operator linter and focused convergence suite were rerun after that adjustment. Production behavior was not changed during this review; deployment remains a separate ship action.

## Original finding

Surfaced by `w7/m84/t005`'s quality review, 2026-08-19, and measured before filing.

`m84` made a converged reconcile issue zero writes **to owned objects**. The owner's own `status` subresource was out of its definition of done and is still written unconditionally at several terminals:

- `keyvalue_controller.go` Ready branch — unconditional, then `RequeueAfter: childHealthRequeue` (30s): **≈2,880 status PUTs/day per Ready KeyValue**. That is the same order as the Deployment PUT m84 just removed, so this is the largest single item.
- `app_controller.go` `reconcileCronJob` — unconditional, then `RequeueAfter: time.Minute`. A settled cron App reaches `Running` without needing a pod: **≈1,440/day per cron App**.
- `database_controller.go` Ready branch — unconditional; not periodic, but the controller watches the CNPG Cluster on `ResourceVersionChangedPredicate`, so it fires on every Cluster status tick.

The App web/worker path is already gated (`markRunning` → `statusSettled`, and `setPhase` skips an unchanged phase+condition), which is the pattern the rest would follow: `AppReconciler.statusSettled` is a cached read plus `apiequality.Semantic.DeepEqual`.

**Why m84 did not just do it.** Two reasons, both worth knowing before someone picks this up:

1. **envtest cannot judge it.** No kubelet runs there, so a rollout never becomes ready and the App oscillates between `setPhase`'s "Deploying" condition and `reportRolloutProgress`'s — two status writes per pass that are an artifact of the test environment, not of the product. Any test for this has to construct a genuinely settled state (fake ready pods / a fake StatefulSet status), which is most of the work.
2. **~30 call sites across three controllers**, and skipping a status write that a consumer depends on is a real bug, not a cosmetic one — bex-api's deploy gate reads exactly this status. This is a diff-before-write sweep with a correctness edge on every site, i.e. a milestone, not a cleanup.

Sizing: ~2–3h, milestone-shaped. The durable half is the same as m84's — extend `reconcile_convergence_envtest_test.go`'s `writeRecorder` to wrap `Status()` (it currently names this as its one exemption) once a settled fixture exists, so the invariant covers both objects.
