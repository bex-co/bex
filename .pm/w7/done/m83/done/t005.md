## Objective

Make admission honest now that it is the only concurrency control the build plane has.

## Context

- ADR060 D6: after D1, admission — not reconcile threads — is the only logical concurrency control, "so it must be honest". D1 shipped as `w2/m72` (2026-08-16), so this is now live.
- Before D1, an overshoot in the per-workspace gate was masked by the global reconcile-worker count. It no longer is.
- Today `BEX_MAX_CONCURRENT_BUILDS` is per-workspace with a documented benign race (list-then-create). D6 asks for two cheap tightenings: **re-count after create and delete-newest on overshoot** (self-correcting, still not a distributed lock), and a **new global** `BEX_MAX_ACTIVE_BUILDS` cluster-wide ceiling so total fan-out is bounded across many workspaces — dispatch storms saturating shared capacity is the recurring theme of the 2026 GitHub Actions outages.
- Kueue is the designated escalation when strict plan-tier enforcement or priorities arrive; ADR060 D6 explicitly does **not** adopt it at current volume.
- t001's `bex_builds_active` gauge is what makes the ceiling observable, hence the dependency.

## Steps

1. Add `BEX_MAX_ACTIVE_BUILDS` (cluster-wide active-build ceiling, `0` = unlimited, byte-identical when unset).
2. Add re-count-after-create with delete-newest on overshoot to the existing per-workspace gate.
3. Document both in the `CLAUDE.md` env table and mirror the names into `.env.example` (repo rule).
4. Make the ceiling's effect visible via `bex_builds_active` / `bex_builds_queued`.

## Files

- `lego/operator/internal/build/` admission path
- `CLAUDE.md` env table, `.env.example`

## Acceptance criteria

- [ ] With `BEX_MAX_ACTIVE_BUILDS` set, cluster-wide active builds never exceed it; unset is byte-identical to today.
- [ ] A racing double-create is self-corrected by deleting the newest, not the running one.
- [ ] Both variables are in the env table and `.env.example`.

## Out of scope

- Adopting Kueue — ADR060 D6 keeps it as the designated escalation, not current work.
