## Objective

A Hobby workspace cannot turn autoscaling on, through any surface, and gets the plan refusal bex already uses for other Pro features. A policy that is already on keeps running and can be turned off.

## Context

- Render: "Autoscaling: Available only for Pro workspaces and higher" and "Autoscaling requires a Pro workspace plan or higher" (render.com/docs/scaling, read 2026-11-16).
- `lego/backend/internal/core/plan_gate.go`: `planFeatures` (`:55-61`), `PlanAllows`, `NewPlanFeatureError` (code `PLAN_FEATURE_REQUIRED`).
- Writers: `SetAutoscaling` (`lego/backend/internal/apps/service.go:6578`) behind REST `PUT /v1/services/{id}/autoscaling`, GraphQL `setAutoscaling` and MCP `update_service(autoscaling:)`; create with `serviceDetails.autoscaling` (`autoscalingSpec`, `service.go:6486`); a Blueprint `scaling` block (`lego/backend/internal/apps/blueprint_plan_limits.go` already reports plan limits at the authored path).
- ADR030 §9: existing state is never silently removed; an unreadable plan fails the write; with the plan reader unwired every feature is open.
- The free instance type's one-instance cap (w6/m118) is a separate, existing rule.

## Steps

1. Add `FeatureAutoscaling` (minimum Pro, key `autoscaling`) to `planFeatures`.
2. Refuse enabling in the one Core path every writer shares, and in create. Turning a policy off, and re-sending an enabled policy that is already stored, stay allowed.
3. Blueprint validate, plan and sync report the refusal at the service's `scaling` path with the code, for a service that does not already autoscale.
4. Update ADR030 §9's table and ADR018's Autoscaling row.
5. Tests: Hobby refusal on REST, GraphQL, MCP, create and Blueprint; an existing policy keeps working and can be disabled; Pro unchanged; unreadable plan; store off.
