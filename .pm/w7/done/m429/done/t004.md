## Objective

A workspace's custom domains beyond its plan's included count are metered and priced as on Render (at bex's standing discount), shown in usage and the cost estimate, and never refused for the count.

## Context

- Render pricing table (read 2026-11-16): custom domains "2 included then $0.25/domain/month" on Hobby, 15 on Pro, 25 on Scale, custom on Enterprise.
- ADR030 §2: bex's prices are Render's × 0.70, so $0.175 per domain-month.
- bex has no included count and no price. Its only limits are the abuse caps `MaxCustomDomainsPerService` and `MaxCustomDomainsPerWorkspace` (`lego/backend/internal/api/server.go:735-740`), which stay.
- Meters: kinds in `lego/backend/internal/store/usage.go`, the hourly rollup and the usage read in `lego/backend/internal/usage/`, prices in `lego/backend/internal/pricing/pricing.yaml` and `pricing.go`, the Stripe emitter in `lego/backend/internal/billing/stripe.go`, the live Stripe catalog in `scripts/stripe-billing-setup.py`.
- Custom-domain claims are rows in the control-plane store with a verified state (w5/m137). The custom-domain verbs live in `lego/backend/internal/apps/`.
- The milestone README's decision state: this charge is a recommendation, not a user decision. Live Stripe writes are the user's (`w2/blocked/070`).

## Steps

1. Decide what counts, from Render's docs where they say, and record what is unverified: verified domains only (recommended, since an unverified one never routes), and how a `www`/apex pair and a wildcard count.
2. Add an hourly usage row per workspace for the domains above the included count (domain-hours), and the included count by plan in one table. Enterprise is unlimited.
3. Price it in `pricing.yaml` at $0.175 per domain-month, prorated by the hour. `GET /v1/usage`, GraphQL `usage` and MCP `get_usage` return the row and its `estimatedCost`; the Billing page shows the line with "N of M included".
4. Map the new kind in the Stripe emitter and add its item to `scripts/stripe-billing-setup.py`, with the script's tests. Do not run the script against live Stripe. Record in the milestone README the one command the user runs to create the live item, and that no charge exists until then.
5. Update ADR030 (a new subsection for included custom domains), ADR023 and ADR018's Custom domains row.
6. Tests: the count by plan; proration; an unverified domain is not counted; adding a domain past the count succeeds; REST, GraphQL and MCP return the same row.
