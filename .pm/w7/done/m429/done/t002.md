## Objective

On a Hobby workspace the Scaling page explains that autoscaling needs the Pro plan and links to Billing, instead of letting the user fill the form and receive a 400.

## Context

- `dashboard/src/routes/services.$serviceId.scaling.tsx`, `dashboard/src/features/services/components/autoscaling-section.tsx`, `hooks/use-autoscaling.ts`.
- The model: the Request logs view's Pro-plan notice with a Billing link (w8/m138 t011) and the inbound IP rules editors' clear-only state below Scale (w8/m137).
- Root `AGENTS.md`: a loading skeleton must match the ready state's geometry.

## Steps

1. Read the workspace plan the way the other plan notices do. On Hobby with autoscaling off, show the notice and the Billing link and disable the enable control with the reason.
2. On Hobby with a policy already on, show the policy, allow turning it off, and say that turning it back on needs Pro.
3. Show the server's `PLAN_FEATURE_REQUIRED` message if it arrives anyway.
4. Add the strings to every locale file the services feature has.
5. Compare pending and ready states at desktop and narrow-mobile widths.
6. Component tests for Hobby off, Hobby on and Pro.
