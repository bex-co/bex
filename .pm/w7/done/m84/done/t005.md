## Result

Three reviews (reuse, quality, efficiency). Applied:

- **The predicted extraction landed, and then some.** `applyPodSpecServerDefaults` was
  already shared across the four pod-bearing projections, but the review found the Service
  side still hand-mirrored — `Protocol: TCP` spelled out with a prose comment at three
  sites, the third of which this milestone had just added. Now one
  `applyServicePortServerDefaults` in `server_defaults.go`, called from all three, so a
  fourth Service projection is convergent by construction. That is exactly the generality
  `w9/m57` lacked.
- `defaultTerminationGracePeriodSeconds` derives from `corev1.DefaultTerminationGracePeriodSeconds`
  instead of restating `30` under a comment naming the constant.
- The three new get-before-delete blocks: two now reuse the package's existing
  `deleteAndWait` primitive (which additionally skips a second Delete on an object already
  terminating). The third, `deleteOptionalObject`, keeps its own form — it alone must treat
  a missing CRD as "nothing to delete" — but split out `deleteTolerantly`, because its one
  App caller passes an object it just **listed**: the existence check there was pure waste,
  a guaranteed-hit live read before every prune.
- The `downwardAPI` volume branch was **deleted rather than kept**: the API server also
  defaults `fieldRef.apiVersion` on each item, so filling only the mode would have left the
  projection divergent anyway — a half-support worse than none. The remaining three branches
  (`projected`, `secret`, `configMap`) are now each exercised against the live API server.
  That change was not theoretical: adding the volumes to the oracle turned it **red** and
  is how the `downwardAPI` gap was found.
- Comment repairs where the milestone's own edits had made text wrong: `applyValkeyPodSpec`
  still claimed to leave `restartPolicy`/`dnsPolicy`/`terminationGracePeriodSeconds` to the
  server (the three fields it now writes); the probe-timing comment asserted a convergence
  constraint that does not exist (fill-if-empty means an explicit period converges fine);
  the `server_defaults.go` header pointed at the wrong test file for its own guarantee; and
  four call sites each restated the rationale the package doc already gives — now one-line
  pointers.
- Test scaffolding: `deleteOwner` hoisted to a package-level helper the sibling file reuses
  instead of re-implementing, and `stripServerPodDefaults` — the hand-written inverse the
  no-rollout proof depends on — is now **pinned as an exact inverse** rather than trusted to
  stay in step. Without that, a default added to the helper and forgotten in the stripper
  would have silently degraded the proof into a tautology.

The efficiency review's headline was a correction to **this milestone's own write-up**, not
to its code: of the six blind deletes, only one — the KeyValue backup CronJob — actually
loses its round trip. `deleteOptionalObject` is unstructured by signature and
`deletePoolerConnectionSecret` rides the deliberately uncached secret client, and
controller-runtime v0.23.3 serves neither from cache (`cluster.go` hardcodes
`CacheOptions{Unstructured: false}` and `cmd/manager` never overrides it). For those five
the fix converts a write into a read — off the mutating path and out of the write audit
stream — which is worth having but is not a saved request. Both the code comment and the
milestone write-up claimed more than that; both now state the accounting exactly. It also
found the probe loop allocating a 3-element slice per container per reconcile (now three
direct calls) and flagged that `RestartPolicy: Always` is invalid on a Job template, so a
future Job projection that forgets `Never` gets a 422 rather than silent churn — noted at
the line.

Not taken: making `reconcileToFixedPoint` stop as soon as a pass records no writes. It
would save ~25 reconciles of the ~5s the new specs add, but a pass can make progress
without writing an owned object (status-driven phase transitions), so an early break risks
measuring an unsettled state — a flaky invariant costs more than 5 seconds.

Filed rather than fixed:

- [`.pm/w7/033.md`](../033.md) — the same defect on the CR's own `status` subresource
  (several terminals write it unconditionally; a settled cron App PUTs status once a
  minute). Out of this DoD, ~30 call sites, and envtest cannot judge it because a rollout
  never becomes ready there. This is the invariant's one named exemption.
- [`.pm/w7/034.md`](../034.md) — cron and manual-run containers pull `IfNotPresent` where
  the Deployment path deliberately pulls `Always` against mutable `gen-N` tags
  (codex-security #29). Pre-existing and byte-identical under m84; fixing it changes a
  stored template, so it is a decision, not a cleanup.
- [`.pm/w7/035.md`](../035.md) — the controller envtest suite fails under
  `-ginkgo.randomize-all`. Verified pre-existing by stashing this milestone and reproducing
  on a clean tree.

Rejected: moving `applyPodSpecServerDefaults` into a `CreateOrUpdate` wrapper. It would make
"call it last" structural, but the projections are deliberately pure functions of their
inputs with no client calls, so the unit tests would stop seeing the shape they assert.
