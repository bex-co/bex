## Objective

Turn the reasoning in `028` into a failing test before changing any projection code, so the fix is proven rather than argued — and so the sweep in t003 has an oracle instead of a code review.

## Context

- The claim: the API server defaults embedded pod-template fields on the stored Deployment (container `terminationMessagePath`/`terminationMessagePolicy`, pod `dnsPolicy`/`restartPolicy`/`schedulerName`/`terminationGracePeriodSeconds`, probe `successThreshold`, readiness `periodSeconds`/`failureThreshold`), while `applyDeploymentSpec` rebuilds `Containers` wholesale and forces `TerminationGracePeriodSeconds` — so `DeepEqual` can never hold and `CreateOrUpdate` returns `Updated` on **every** reconcile.

- `lego/operator/internal/controller/app_controller.go:3398` — `Owns(&appsv1.Deployment{}, ResourceVersionChangedPredicate{})`, which is what closes the loop.

- Do not fix anything in this task. A red test is the deliverable.

## Measured result

`reconcile_convergence_envtest_test.go` (new) settles each owner, then records what one
further, entirely redundant reconcile does — through a `writeRecorder` client wrapper
(every Create/Update/Patch/Delete) **and** a resourceVersion snapshot of every owned
object. Red on the first run for all three controllers:

| owner | redundant write, every pass | mechanism |
| --- | --- | --- |
| App | `update Deployment/<name>` | `applyDeploymentSpec` rebuilds the container and clears `terminationGracePeriodSeconds` |
| App | `delete Middleware/<name>-ip-allow`, `-env-ip-allow`, `-ws-egress` | blind DELETE of optional objects that do not exist |
| KeyValue | `update StatefulSet/<name>`, `update Service/<name>` | container rebuild; `ServicePort.Protocol` unset |
| KeyValue | `delete Certificate/<name>-kv-tls`, `delete CronJob/kvbak-<name>` | blind DELETE |
| Database | `update Cluster/<name>` | `setLifecycleAnnotations` writes an empty annotations map |
| Database | `delete Pooler/…`, `delete ScheduledBackup/…`, `delete Secret/…-pooler-app` | blind DELETE |

**The list is different from `028`'s prediction in one load-bearing way: nothing churns.**
Not one `resourceVersion` moved. The API server re-defaults the incoming object, finds
the result byte-identical to what is stored, and skips etcd — so the redundant PUT fires
no watch event, and the self-sustaining `ResourceVersionChangedPredicate` requeue loop
`028` described **never actually closed**. What is real is the request: one full
decode/validate/admission round trip per object per pass, plus 2–3 blind DELETEs — so the
blind deletes were the larger half of the finding, and were not predicted at all.

That same fact is what makes the fix provably rollout-free (t002): if the stored bytes
never changed, the pod-template hash computed from them cannot change either.

A field-level diff of every projection against its stored object produced the exact
defaulted-field list t002/t003 fix: container `terminationMessagePath`/`Policy`,
`imagePullPolicy`, `ports[].protocol`, probe `successThreshold`/`failureThreshold`/
`periodSeconds`/`timeoutSeconds`, `httpGet.scheme`, projected-volume `defaultMode`, and
pod `terminationGracePeriodSeconds`/`dnsPolicy`/`schedulerName`/`securityContext`.
