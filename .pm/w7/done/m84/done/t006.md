## Objective

Cover what the t004 invariant does not: that a **real** change still produces a write, and that each fixed field is individually pinned.

## Context

- The invariant proves "no write when nothing changed". The complementary risk is over-correcting into "no write **ever**" — a projection that silently stops applying changes would pass the invariant and break deploys. That direction needs its own tests.
- Per-field regression tests matter because the fix depends on matching specific API-server defaults; a Kubernetes upgrade that changes one default should fail loudly here rather than silently resume churning.

## Steps

1. Test that changing the App spec (image, env, replicas, probe path) **does** produce an update and the expected object.
2. Pin each defaulted field the fix now sets, individually, so a changed upstream default fails a named test.
3. Test the no-rollout property explicitly (template hash stability across the fix).
4. Confirm `make test` is green.

## Files

- `lego/operator/internal/controller/deployment_projection_test.go` and sibling controller tests

## Acceptance criteria

- [x] A real spec change still produces exactly one update.
- [x] Each defaulted field is individually pinned by a named test.
- [x] Template-hash stability is asserted, not assumed.
- [x] No trivial or tautological tests; `make test` green.

## Result

`server_defaults_envtest_test.go`:

- **A real change still writes.** Changing `spec.image` on a settled App produces exactly
  `["update Deployment/<name>"]` — one write, nothing else — and the stored container image
  is the new one. This is the over-correction guard: a projection that stopped applying
  changes would pass the convergence invariant and break every deploy.
- **Every default pinned against a live API server.** A Deployment that sets nothing
  optional is stored, read back, and compared field by named field with what
  `applyPodSpecServerDefaults` writes — then the whole PodSpec is compared, so a default
  the helper does *not* know about is caught the first time a projection emits that field.
- **`imagePullPolicy` pinned for six reference forms** (tag, `:latest`, no tag, a
  registry with a port, that registry without a tag, a digest), each checked against what
  the API server actually stored, because that rule is the one piece of upstream
  defaulting the helper re-implements rather than copies.
- **No rollout, measured.** The stored pod template is `Equal` before and after the fix
  and the `resourceVersion` does not move, so the pod-template hash — a pure function of
  the stored template — cannot move.

## Out of scope

- Measuring the apiserver write-rate reduction in production — desirable but not a merge gate.
