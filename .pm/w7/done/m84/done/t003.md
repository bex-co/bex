## Objective

Fix every other owned object that churns, using t001's measured list rather than a guess.

## Context

- **25 `CreateOrUpdate` call sites** exist: `app_controller.go` (9), `keyvalue_controller.go` (5), `database_controller.go` (5), `build/kpack.go` (3), `build_registry_secret.go` (2), `keyvalue_backup.go` (1).
- Three controllers watch owned objects on `ResourceVersionChangedPredicate`, so each churning object is its own feedback loop: `app_controller.go:3398` (Deployment) and `:3403` (CronJob), `database_controller.go:1168` + `:1171`, `keyvalue_controller.go:1048` (StatefulSet) + `:1049` (CronJob).
- Objects watched on `GenerationChangedPredicate` (Ingress, NetworkPolicy, KeyValue's Service) do **not** feed back the same way — a spurious PUT still costs an etcd write but does not requeue. Fix them if they churn, but note the difference; the priority is the `ResourceVersionChangedPredicate` set.
- StatefulSet has its own defaulting surface (`podManagementPolicy`, `revisionHistoryLimit`, `updateStrategy`, volume-claim template defaults) — expect it to need different fields than the Deployment.

## Steps

1. Work through t001's measured churn list, highest-cost first (the `ResourceVersionChangedPredicate` owners).
2. Apply the same approach chosen in t002 for consistency, deviating only where the kind demands it — and say why when deviating.
3. Verify no workload rolls for any of them.
4. Note any site that legitimately must write every pass, with the reason, so the t004 invariant can exempt it explicitly rather than being weakened.

- [x] The `ResourceVersionChangedPredicate` feedback loops are all closed — see the note below on what they turned out to be.

## Result

Worked from t001's measured list, not the 25-site inventory: a site only churns if its
projection omits something the server fills in, and most of the 25 set every field they
own (`Type` on Secrets, `PolicyTypes` on NetworkPolicies) or run only during a build
(kpack, `build_registry_secret`, the publish/pre-deploy Jobs are Create-once, so they
cannot churn per-pass at all).

Fixed:

| site | fix |
| --- | --- |
| `cronPodSpec` (App CronJob + manual-run Job) | `applyPodSpecServerDefaults` — this one rebuilds the whole PodSpec, so it also needed `dnsPolicy`/`schedulerName`/`securityContext` |
| `applyValkeyPodSpec` (KeyValue StatefulSet, both containers) | `applyPodSpecServerDefaults` |
| `keyValueBackupCronJobSpec` | `applyPodSpecServerDefaults` |
| `reconcileKeyValueService` | explicit `Protocol: TCP`, matching `applyClusterIPService`'s w9/m57 fix |
| `setLifecycleAnnotations` (CNPG Cluster) | never set an empty annotations map — it is dropped on serialization, so writing one guarantees a diff |
| `deleteOptionalObject` (Traefik middlewares, CNPG Pooler/ScheduledBackup, cert-manager Certificate) | existence check before Delete |
| `reconcileKeyValueBackup` disabled branch, `deletePoolerConnectionSecret` | existence check before Delete |

**Exemptions: none.** Every measured write was removed rather than exempted, so the t004
invariant has no exemption list to rot.

Two things worth recording:

- **The blind deletes were the bigger half by count.** An App issued three DELETEs for
  middlewares it does not have on every pass, against one PUT. What the fix is worth was
  pinned down in t005 and is narrower than it first reads: only the KeyValue backup CronJob
  is a typed kind the controller already watches, so only there does the round trip
  disappear. `deleteOptionalObject` is unstructured by signature and
  `deletePoolerConnectionSecret` uses the deliberately uncached secret client, and
  controller-runtime v0.23.3 serves neither from cache — so those five convert a write into
  a read (off the mutating path, out of the write audit stream) rather than saving a
  request. Same trade `deleteStaleChildren` already made for typed children; the code
  comment now spells the accounting out so the next reader does not over-credit it.
- **The feedback loops were never closed in the first place.** t001 measured no
  `resourceVersion` movement anywhere, so `ResourceVersionChangedPredicate` never saw
  these PUTs. The loops are closed in the sense that the writes are gone; there was no
  requeue storm to stop.

**Residual, filed not assumed:** envtest applies schema defaulting, not admission
webhooks, and `testdata/crds` holds stubs with no defaults at all. So the green says
nothing about the five kinds whose `spec` is replaced wholesale through `upsertOwned` — the
CNPG `Cluster`, `Pooler` and `ScheduledBackup`, the Traefik `Middleware` (up to three per
App, every pass), and the cert-manager `Certificate` — each of which could reproduce the
exact bug just fixed against a real CRD or mutating webhook. Two per-pass paths no shape
reaches (`reconcileTenantBackupStore`, `reconcileExecutionNetworkPolicy`) are in the same
position. Not measurable in this repo; recorded in the invariant's "known limits" comment
and as [`032`](../../032.md), with the exact `kubectl` commands that settle it.
