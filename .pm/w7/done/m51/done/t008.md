## Objective

Add a dashboard Billing experience that clearly distinguishes estimate, test invoice state, payment readiness, tax readiness, and Stripe-hosted management actions.

## Context

- The dashboard authenticates with its Kratos HttpOnly session and calls bex-api through the existing GraphQL path.
- Stripe-hosted redirects must not place server keys, session secrets, or sensitive payment data in browser storage.

## Steps

1. Add status, Checkout, and Portal actions to the Usage/Billing surface.
2. Handle return states by re-reading authoritative readiness rather than trusting query parameters.
3. Label the environment visibly as Stripe Test Mode and provide honest degraded/unconfigured states.

## Files

- `dashboard/src/features/usage/`
- `dashboard/src/routes/`
- `dashboard/src/gql/`

## Acceptance criteria

- [ ] An authorized admin can complete test payment setup and open Portal from the dashboard.
- [ ] Test mode is unmistakable and no browser-readable Stripe server credential is stored.
- [ ] Loading, cancellation, retry, and degraded states are accessible and tested.

## Out of scope

- Custom Elements/card forms and dashboard OAuth conversion.
