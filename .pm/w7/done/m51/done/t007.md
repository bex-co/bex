## Objective

Expose one authorized core billing-onboarding contract through REST, GraphQL, and MCP with identical states and errors.

## Context

- ADR008 requires every human action to be API-operable; billing cannot be dashboard-only.
- The existing usage `billing` object is read-only and must remain backward compatible.

## Steps

1. Add create-Checkout-session, create-Portal-session, and billing-readiness core verbs.
2. Wire thin REST, GraphQL, and MCP adapters with the same workspace selection and authorization.
3. Regenerate schema/types and document bex-extension semantics.

## Files

- `lego/backend/internal/api/`
- `lego/backend/internal/billing/`
- `lego/backend/internal/core/`
- `lego/backend/internal/graphql/`
- `lego/backend/internal/mcp/`

## Acceptance criteria

- [ ] All three surfaces return equivalent readiness and session results.
- [ ] Non-admin and cross-workspace attempts are denied consistently.
- [ ] Existing usage and invoice reads remain compatible.

## Out of scope

- Live-mode activation.
