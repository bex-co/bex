# Registry in-cluster TLS residual (ADR022 §225–227)

**Type:** residual-risk record / defense-in-depth follow-up. **Not a milestone** (weak why-now).

In-cluster Zot is HTTP-only (`registry.insecure=true` on build push); build-push credentials cross the cluster network in plaintext. `docs/ADR022-tenant-isolation.md` §225–227 records this as accepted inside the trusted cluster network, the reason Zot stays **ClusterIP-only** (never externally exposed), and names "fronting Zot with TLS + public face" a prod-hardening follow-up.

**Largely mitigated already:** the shipped Cilium **WireGuard node-to-node encryption** (`w1/m19`, `encryption.enabled=true type=wireguard nodeEncryption=true`) encrypts the cross-node pod path, so the remaining plaintext exposure is **same-node** pod↔Zot traffic — where the kernel is the trust boundary anyway. So the marginal value is defense-in-depth, not a live hole.

**Trigger to promote:** a real driver appears — e.g. Zot is exposed beyond ClusterIP, a compliance/audit requirement lands, or WireGuard is ever disabled. Until then: recorded, not built.
