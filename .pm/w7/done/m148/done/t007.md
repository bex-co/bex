## Done 2026-09-17

Closed out after the local environment was rebuilt, which is what the milestone was parked on.

**The rotted cluster was reprovisioned.** `kubectl delete cluster bex` stalled — the control-plane machine held `machine.cluster.x-k8s.io` while CAPI tried to drain a node whose container no longer existed, so the finalizer was cleared (the infrastructure it guarded was already gone; nothing could leak). Teardown then completed in 275s and a fresh cluster provisioned.

**The rebuild surfaced a second, pre-existing bug and it is fixed here.** Every bring-up was aborting at metrics-server with `failed parsing --set data: key "Hostname" has no value` — helm treats a comma in `--set` as a list separator, so `--kubelet-preferred-address-types=InternalIP,Hostname,ExternalIP` parsed as three keys. The commas are now escaped. This had been latent: before t003 made required stages fatal, a run reached its success banner regardless of what failed, so a broken bring-up looked identical to a good one. t003 is exactly what exposed it.

**Healthy run recorded** (`EXIT=0`), with the banner gated on all seven checks:

```text
verifying the substrate this script installed:
  ok    apiserver reachable (TLS verified)
  ok    every node Ready (and at least one)
  ok    CNI (calico-node) rolled out
  ok    a default StorageClass exists
  ok    cert-manager Available
  ok    metrics API serving (metrics.k8s.io)
  ok    cluster-autoscaler Available (mgmt)
```

Independently confirmed: three nodes `Ready` (1 control-plane, 1 tenant, 1 worker) and `local-path (default)` bound.

**Environment rebuilt, as the DoD requires reporting:** the local CAPD app cluster `bex` was deleted and recreated. The mgmt cluster (`kind-bex-mgmt`) was reused. Nothing outside the local kind/CAPD substrate was touched, and the script continues to state that it publishes a substrate only — the bex operator and App CRD remain `make -C lego/operator deploy`.
