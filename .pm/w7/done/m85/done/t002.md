## Objective

Pin the managed Key Value data-path images, one of which carries no version at all.

## Context

- `lego/operator/internal/controller/keyvalue_controller.go:74` — `kvDefaultImage = "valkey/valkey:8-alpine"` (floating minor/patch).
- `lego/operator/internal/controller/keyvalue_controller.go:79` — `kvExporterImage = "oliver006/redis_exporter:alpine"` — **no version at all**, the worst case in the tree: two reconciles months apart can run different code with no record of the change.
- `lego/operator/internal/controller/keyvalue_backup.go:53` — `keyValueBackupAgeImage = "alpine:3.21"` (version tag, no digest).
- These run tenant data-path workloads (`valkey`) and touch backups, so an upstream compromise here reaches tenant data directly.
- The operator already has a pinned-constant convention to copy: `build.go:61-63`, `build.go:68`, `native.go:35`, `publish.go:49`.

## Steps

1. Resolve current multi-arch digests for all three.
2. Pin as `name:tag@sha256:…`, matching the existing constant style in `build.go`.
3. Check whether pinning `kvDefaultImage` changes the image any existing KeyValue would run — if a running instance would be restarted onto a different digest, say so explicitly rather than discovering it in prod.

## Files

- `lego/operator/internal/controller/keyvalue_controller.go`
- `lego/operator/internal/controller/keyvalue_backup.go`

- [x] All three constants carry digests.
