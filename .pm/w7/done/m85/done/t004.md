## Objective

Close the manifest-side remainder so the guard in t005 can be fail-closed rather than carrying a list of exceptions.

## Context

- `deploy/gitops` carries `plugin-barman-cloud:v0.13.0` — a version tag, not a digest. It sits in the Postgres backup/restore path, which ADR031's runbooks depend on.
- Sweep for siblings rather than fixing only the one named: CNPG, cert-manager, Traefik, Zot, kpack and the autoscaler all enter through gitops. Some arrive via Helm charts, where the pin lives in chart values or a chart version — record which mechanism applies to each rather than forcing them all into one shape.
- Placeholders like `controller:latest` (overridden by kustomize) and the `whoami`/`nginx` examples are **not** real refs; they must end up as explicit guard exemptions in t005, not silent misses.

## Steps

1. Enumerate every image reference under `deploy/gitops` and `lego/operator/config`.
2. Classify each: real ref to pin, chart-managed (pin the chart version + digest where supported), or placeholder/example to exempt.
3. Pin the real ones; record the exemption list with a reason per entry for t005 to consume.

## Files

- `deploy/gitops/**`
- `lego/operator/config/**`

## Acceptance criteria

- [x] Every manifest image reference is classified, with none left unexamined.
- [x] Real refs carry digests.
- [x] The exemption list has a reason per entry and is written where t005's guard reads it.

## Out of scope

- Upgrading any component — pin what is deployed.

## Outcome (2026-08-21)

Every image reference under `deploy/gitops` and `lego/operator/config` was enumerated and classified — and the sweep was widened past those two trees once the guard existed, because a boundary drawn at two directories is how the previous five reports each missed something.

**Already pinned by mechanism, verified not assumed:** the barman-cloud plugin AND its injected sidecar (kustomize patch over a byte-for-byte vendored upstream manifest, asserted on the RENDERED output by `scripts/gitops-validate.sh`); every Helm chart (OCI `targetRevision: sha256:…`); kpack's vendored release; the four backup-CronJob images; the kustomize `images:` write-backs for the operator, dashboard, OpenSandbox server and controller.

**Actually unpinned, and fixed here:** `axllent/mailpit:v1.21.8` (two manifests), plus three the two named trees would never have surfaced — `BEX_SANDBOX_IMAGE`'s default (`docker.io/library/alpine:3`, the one that actually runs since no deployment sets it), `BEX_AGENT_SESSION_IMAGE`'s `:latest` default, and CI's `postgres:17` + `openfga/openfga:latest`.

**Exemptions** live in `exemptions()` in `scripts/image-pin-validate.sh` — enumerated `<path>\t<reference>\t<reason>` rows, so the same string in a new file fails until someone writes a reason. The self-test asserts every row has one, and that exemptions do not apply to any tree but the canonical one.
