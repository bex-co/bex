## Objective

Build the durable half. Without a guard, this milestone becomes the sixth report of the same finding.

## Context

- The proven in-repo shape is `w7/m65`'s action-pinning guard: a fail-closed check plus a **red/green self-test**, which is why 42 SHA-pinned GitHub Actions have stayed pinned. `w7/m58`'s universal gitops guard is the second precedent (single-sourced `.yq` helper, durable self-test in CI).
- Scope: Dockerfile `FROM` lines, operator image constants in Go, and manifest `image:` fields — three different syntaxes, one policy.
- **Fail closed:** an unrecognized reference must fail, not pass. A guard that silently skips what it cannot parse is how the inventory drifted in the first place.
- Exemptions come from t004's list (kustomize placeholders, examples) and must be **enumerated with reasons**, never pattern-blanket.

## Steps

1. Implement the guard across the three syntaxes, reusing the existing guard helpers rather than adding a third idiom.
2. Wire in t004's exemption list with its reasons.
3. Add a red/green self-test proving a reintroduced floating tag turns CI red and the fixed tree is green.
4. Wire it into CI so it gates like the other structural guards.

## Files

- `scripts/` guard + self-test
