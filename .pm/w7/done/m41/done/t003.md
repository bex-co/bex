## Objective

Add a Build Command inline editor to the Settings → Build & Deploy section for
git-backed static sites, following the same pencil-edit pattern as other command
editors in `BuildDeploySection`. Render's static site settings page exposes this
field; bex currently shows no build command editor for any static site.

## Context

- `dashboard/src/features/services/components/build-deploy-section.tsx`
  - Has `showStartCommand`, `showDockerfilePath`, `showPreDeployCommand` props for per-type visibility
  - Has NO `buildCommand` prop or `showBuildCommand` prop — the field doesn't exist at all
  - `useStartCommand` hook pattern at lines 26, 100, 180–218 is the model to follow
- `dashboard/src/routes/services.$serviceId.settings.tsx`
  - Lines 149–167: `BuildDeploySection` is rendered for all git-sourced non-cron services (including static sites) with `showStartCommand={!staticSite}`, `showDockerfilePath={!staticSite}`
  - Does NOT pass a `buildCommand` or `showBuildCommand` prop (they don't exist yet)
- After t002: `server { buildCommand }` is queryable; `setBuildCommand` mutation exists
- `use-start-command.ts` is the exact model for a new `use-build-command.ts`

## Steps

1. Create `dashboard/src/features/services/hooks/use-build-command.ts` mirroring `use-start-command.ts`: calls the `SetBuildCommandDocument` mutation (regenerated by t002), returns `{ setBuildCommand, busy }`.
2. Add `buildCommand?: string | null` and `showBuildCommand?: boolean` props to `BuildDeploySectionProps` in `build-deploy-section.tsx`. Default `showBuildCommand` to `false` (no change to existing callers).
3. Import `useBuildCommand` and render an `InlineEditSetting` for Build Command (same shape as the Start Command editor at lines 180–218) when `showBuildCommand` is true:
   - Label: `t("services.buildCommandLabel")`
   - Hint: `t("services.buildCommandHint")`
   - `optional` (empty means no build step)
   - `onSave`: calls `setBuildCommand(serviceId, value)`
4. In `services.$serviceId.settings.tsx`:
   - Read `service.buildCommand` (available after the server query is updated in t002)
   - Pass `buildCommand={service.buildCommand}` and `showBuildCommand={staticSite}` to `BuildDeploySection` for the non-cron branch (lines 150–167); for the cron branch, leave `showBuildCommand` as the default `false` (ADR018 cron Build Command row is deferred).
5. Add locale keys `services.buildCommandSuccess`, `services.buildCommandError` to `src/features/services/locales/{en,zh}.ts` (the hook's toast messages).

## Acceptance criteria

- [ ] Settings → Build & Deploy for a git-backed `static_site` shows a "Build Command" row (same pencil-edit UX as other command editors)
- [ ] The row displays the current value from `service.buildCommand` (or a dash/empty placeholder if unset)
- [ ] Saving a new value calls `setBuildCommand` and toasts success; the row refreshes with the saved value
- [ ] Clearing the value sends an empty string and the field shows the empty placeholder on refetch
- [ ] The Build Command row is NOT visible for web/private/worker/cron services (existing behavior unchanged — those use `startCommand`)

## Out of scope

- Build Command in the create wizard (t001)
- Cron job Build Command (deferred per ADR018 cron row)
