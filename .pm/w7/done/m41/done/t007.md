## Objective

Add meaningful tests for the new create-wizard fields and settings editor —
both dashboard component tests and backend mutation tests.

## Context

- Dashboard tests live in `dashboard/src/**/__tests__/`; existing test patterns:
  - `use-build-filter.ts` tests in `__tests__/` (if they exist)
  - `services.new.tsx` does not have dedicated tests (wizard is large); add focused tests for the static site build command + build filter path
- Backend tests in `lego/backend/internal/apps/`; `graphql_test.go` or similar covers mutations

## Steps

1. **Backend (Go):** Add a `TestSetBuildCommand` test in `lego/backend/internal/apps/` that:
   - Creates a `static_site` App via `createService(buildCommand: "npm run build")`
   - Calls `setBuildCommand(id, "yarn build")` and confirms the returned value updated
   - Calls `setBuildCommand(id, "")` and confirms the field is cleared
2. **Backend (Go):** Add a `TestCreateServiceBuildFilter` test that creates a `static_site` with `buildFilter: {paths: ["src/**"], ignoredPaths: []}` and verifies `server { buildFilter }` returns it correctly.
3. **Dashboard:** Add a `use-build-command.test.ts` in `dashboard/src/features/services/hooks/__tests__/` that mocks `SetBuildCommandDocument` and verifies the hook calls the mutation with the right variables and handles errors.
4. **Dashboard:** Add a test for `build-deploy-section.tsx` that confirms `showBuildCommand=true` renders the Build Command editor and `showBuildCommand=false` (default) does not.
