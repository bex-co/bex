## Objective

Wire the two backend gaps that t003 and t004 depend on: a `setBuildCommand`
mutation (so settings can update the field), `buildCommand` in the `server`
GraphQL query response (so settings can read it back), and `buildFilter` in the
`createService` mutation args (so the create wizard can set filters at creation
time).

## Context

- `lego/backend/internal/apps/graphql.go`
  - Line 331: `buildCommand` is already a readable field on `AppView` in the `Service` type
  - Line 844: `createService` already accepts `buildCommand` as an arg
  - Line 897: `createService` maps it to `BuildCommand` in `AppSpec`
  - **Missing:** no `setBuildCommand` mutation
  - **Missing:** `buildFilter` is not in `createService` mutation args (it has `setBuildFilter` for post-create, but create-time arg is absent)
- `dashboard/src/graphql/definitions.ts`
  - `server` query (line 3809): does not include `buildCommand` in its selection set; the settings page cannot read it back
  - `SetBuildFilterDocument` exists but `createService` has no `buildFilter` variable

## Steps

1. **`setBuildCommand` mutation** in `lego/backend/internal/apps/graphql.go`:
   - Add `"setBuildCommand"` to the `Mutation` type (alongside `setStartCommand`, `setDockerfilePath`) taking `id: String!` + `command: String` → calls `apps.Service.SetBuildCommand` (a new `Core` verb mirroring `SetStartCommand`).
   - Add the `SetBuildCommand` resolver: `s.SetCommands(ctx, id, core.CommandsInput{BuildCommand: &command})` — `SetCommands` should already accept `BuildCommand` via the existing `CommandsInput` struct; if not, add the field.
   - Add the matching MCP `set_build_command` tool in `lego/backend/internal/apps/mcp.go` (bex extension — Render's official MCP has no equivalent).
2. **`buildCommand` in server query** — update `dashboard/src/graphql/server.graphql` (or whichever `.graphql` file defines the `Server` query) to include `buildCommand` in the `server` selection. Run `yarn codegen` to regenerate `definitions.ts`.
3. **`buildFilter` in `createService` mutation** — in `graphql.go` `createService` args, add `buildFilter: BuildFilterInput` (the same input type used by `setBuildFilter`). Map it to `AppSpec.BuildFilter` alongside the other create-time fields. Update the `CreateService` `.graphql` operation file to include `buildFilter` in the variables. Run `yarn codegen`.
4. Confirm `lego/backend/internal/apps/rest.go` already threads `buildCommand` on `POST /v1/services` for static sites (from `w1/m21` research — it does); no REST change needed.
