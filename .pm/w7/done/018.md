# Flip OpenFGA-absent default to fail-closed for store-backed mode

**Type:** optional hardening. **Not a milestone** (documented escape hatch; prod runs OpenFGA on).

codex-security scan #25 (low): when `BEX_OPENFGA_URL` is unset, `lego/backend/cmd/api/main.go` (~:246) warns and continues serving, and `lego/backend/internal/core/base.go:511` treats a nil checker as allow — so in a store-backed multi-user deployment (`BEX_CP_DB_URI` set), role relations go unenforced within a workspace (a viewer can manage/delete/read-secrets) even though cross-workspace membership filtering still holds. This is the documented w1/m53 single-member-workspace escape hatch.

**Mitigated in prod:** OpenFGA is on. The risk is a misconfigured/self-hosted multi-user deployment that forgets the var.

**Trigger to promote:** any store-backed multi-user deployment path that could ship without OpenFGA. Fix shape: fail startup (or disable multi-member verbs) when `BEX_CP_DB_URI` is set and OpenFGA is absent, gated behind a new opt-out env so documented single-user dev mode still works; or flip the default to fail-closed and require `BEX_ALLOW_NO_AUTHZ=1` to opt back in. Sub-hour → inbox until a real driver appears.

Source: codex-security scan `codex-security-bex-azfRGv`, finding #25.

> **Retired 2026-08-07** (w7 inbox cleanup): OBSOLETE — already shipped by w1/m65 F16 (`lego/backend/cmd/api/main.go:303-309`): bex-api now refuses to start when `BEX_CP_DB_URI` is set and OpenFGA is absent; `BEX_ALLOW_INSECURE_AUTHZ=1` is the loud single-member/dev override. Exactly the fix shape this note proposed.
