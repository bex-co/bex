## Objective

Make a session's tags editable after create with Devin's replace-all semantics, on every surface, under the same validation and authorization as the other session verbs.

## Context

- Devin v3: `PUT /v3/organizations/{org_id}/sessions/{devin_id}/tags`, "Replace all tags on a session."
- Limits and normalization: `agentsessions/title_tags.go` (`maxTitleChars = 200`, `maxTags = 20`, plus per-tag rules); today it runs only on create.
- `store/agentsessions.go:193`: "Title and Tags are the create-time display title and filter tags (ADR094 D3); read-only afterwards." ADR094 D3 says the same.
- Session verbs and authorization: `rest.go` (cancel, archive, steer routes) and `service.go`. Archived sessions refuse mutation verbs (ADR065 D1).

## Steps

1. Factor the tag validation in `title_tags.go` so create and replace share it.
2. Store: `UpdateAgentSessionTags(ctx, workspaceID, id, tags)` sets `tags` and `updated_at`, scoped by workspace.
3. Service `ReplaceTags(ctx, id, tags)`: authorize like the other session verbs, validate, persist, and return the `View`. Decide whether an archived session accepts a tag change: follow ADR065 D1 (refuse) unless Devin's observable behavior differs, and record the choice in the ADR.
4. REST `PUT /v1/agent-sessions/{id}/tags` with body `{"tags": [...]}` returns 200 with the session. Add the GraphQL mutation `setAgentSessionTags(id:, tags:)` and the MCP tool `set_agent_session_tags`; regenerate the MCP golden file.
5. Amend ADR094 D3 (tags are replaceable; the title stays create-time) and the store comment.

## Acceptance criteria

- [ ] PUT with `["a","b"]` and then `["c"]` leaves exactly `["c"]`; `[]` clears the tags.
- [ ] Over-limit or invalid tags return the same error shape as create.
- [ ] A caller without access gets the same response as for the other session verbs; an id from another workspace is not found.
- [ ] `GET ?tag=c` finds the session after the replace.

## Out of scope

- Editing the title (a separate follow-up once Devin's behavior is verified).

## Result (2026-11-09)

Archived sessions refuse the edit (`409 AGENT_SESSION_ARCHIVED`), matching Devin's "archived sessions can be viewed but not modified" that ADR065 D1 already cites; the check and the write are one statement. `set_agent_session_tags` is also on `/mcp/cloud-agents`. Tests: `TestReplaceTags*`, `TestRESTTagsAndMineValidation`, `TestPGReplaceAgentSessionTags`.
