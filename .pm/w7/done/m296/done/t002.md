## Objective

Let every surface list only the sessions a given person started: `mine=true` for the caller (the automations list's existing pattern) and a repeatable `createdBy` subject filter (Devin v3 `user_ids`).

## Context

- `agentsessions/models.go:395` `ListRequest`; REST parsing at `agentsessions/rest.go:47`; the store query in `store/agentsessions.go` (`ListAgentSessions`; filters at :582–611 bind through `arg(...)`, guarded by `textBindable`).
- Pattern to mirror: `AgentAutomations(..., mine bool, ...)` (`automations.go:218`) resolves `mine` to `core.SubjectFrom(ctx)` and refuses an empty subject with `core.ErrForbidden`. REST `mine` parsing is in `automations_rest.go:59`, the MCP `Mine` field in `automations_mcp.go:29`, the GraphQL `mine` arg in `automations_graphql.go:282`.
- Invalid filters already return 400 `AGENT_SESSION_FILTER_INVALID` (ParentSessionID, AutomationID).
- Devin v3 list sessions: `user_ids` (array) filter.

## Steps

1. Add `Mine bool` and `CreatedBy []string` to `ListRequest`. `mine` adds the caller's subject to the set; an empty subject is forbidden, as for automations. Cap the set (about 20 values) and reject non-bindable text with the existing filter error.
2. Store: `AND created_by = ANY($n)` when the set is non-empty. Add an index on `(workspace_id, created_by, created_at DESC)` in a migration so the dashboard default stays an index scan.
3. REST: `mine` (bool) and `createdBy` (repeatable, `core.QueryList`). GraphQL: `mine: Boolean` and `createdBy: [String!]` on `agentSessions`. MCP: `mine` and `createdBy` on `list_agent_sessions` with jsonschema descriptions; regenerate the golden file.
4. Document the filters next to the list's other filters (ADR094 or the API docs).
