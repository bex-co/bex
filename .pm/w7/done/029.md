# 029 — Decide `egress-meter`'s placement on the tainted build pools (its stated premise is now false)

Why: the DaemonSet placement is currently correct only by accident and its comment states a premise ADR060 D8 falsified — the next reader will be misled, and an undecided boundary here risks unmetered (unbillable) tenant egress.


## Disposition — done, 2026-09-05

Keep build-only nodes excluded. The manifest comment now describes the intended taint boundary. `internal/execution/security.go` reserves the build-only toleration for execution Jobs; serving App pods do not tolerate it. `internal/usage/service.go` counts build duration through the build Job meter. The `EgressMeterMissing` rule in `deploy/gitops/base/prometheus.yaml` explicitly compares targets with **untainted** tenant nodes, so the monitoring contract also excludes build-only pools. Build traffic is not a missing tenant-egress charge that warrants deploying the serving meter onto those pools. No scheduling change was needed.

Surfaced by `builder-issues.md` §3.11 (P10), 2026-08-17.

`lego/operator/config/egress-meter/daemonset.yaml:31` says:

> `# No tolerations: production tenant nodes are the only untainted pool.`

ADR060 D8 falsified that on 2026-08-15 by tainting `bex-tenant-lg` and `bex-tenant-burst` with `bex.co/build-only=true:NoSchedule`. **Measured on prod 2026-08-17:** the meter (48Mi) runs on both `bex-tenant-0` nodes and **not** on the tainted lg node.

The exclusion is probably **correct** — build nodes host no serving Apps, so there is no tenant App egress to meter there — but it is now correct by accident, and the comment actively misleads the next reader. Two things to confirm before choosing:

1. Build-time egress (git clone, package registries) is metered as `build_seconds`, not as tenant egress, so nothing billable is lost by the meter's absence.
2. Nothing else depends on the meter being present on every node labelled `bex.co/pool=tenant`.

Then either fix the comment (documenting the taint as the intended boundary) or add the toleration deliberately. Sub-hour either way; the decision is the work, not the edit.

Sibling case already handled: `build-image-prewarm` had the same gap but the opposite answer — it **must** reach build nodes, fixed in `w7/m83/t003`.
