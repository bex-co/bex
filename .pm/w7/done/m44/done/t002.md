## Objective

Rewrite the shared `deployEmail()` composer so the deploy-lifecycle emails
carry Render's context: an impact-framing sentence, the failing commit
message when present, and a "View Logs" deep link to the deploy detail page —
across started/succeeded/failed, so the three stay structurally consistent.

## Context

- `internal/notifications/service.go:274` — `deployEmail(appName, kind)` today
  returns one terse line per kind:
  - failed → subject `Deploy failed: <app>`, body `A deploy of "<app>" failed.`
  - succeeded → `A new deploy of "<app>" went live.`
  - started → `A deploy of "<app>" has started.`
- Render's captured failure email (source): "We encountered an error during the
  deploy process for `<service>`. This means your deploy didn't complete
  successfully and your latest changes may not be live." + `Commit: <message>`
  + a "View Logs" link.
- After t001 the composer has the deploy id, commit message, and dashboard
  base URL available (thread them into `deployEmail` or a small struct it takes).
- Link target: `<BEX_DASHBOARD_URL>/services/<service>/deploys/<deployId>` — the
  deploy-detail page, which renders build/deploy logs (confirmed route). Build
  it with the existing dashboard-URL joining helper pattern
  (`resourcemeta.Config.DashboardURL` style — trailing-slash-safe, omit when
  base URL empty).
- The mailer is **plain-text** (`internal/mailer` — `text/plain`), so the body
  is plain text (label + value lines, blank-line separated), not HTML.

## Steps

1. Give `deployEmail` the deploy id, commit message, and base URL (via t001's
   struct or extra params). Keep the subject lines (they already name the app +
   outcome — Render-adequate).
2. Rewrite each kind's body with framing that matches Render's register:
   - failed: the "encountered an error … latest changes may not be live" framing.
   - succeeded: a "went live" confirmation.
   - started: a "has started" line.
3. Append a **Commit** block when `CommitMessage != ""` (repo-backed); omit the
   block entirely for image-backed deploys (no commit) — no empty `Commit:` label.
4. Append a **View Logs** line with the deep link when the base URL is set;
   omit the line when unset (honest-omit, like the invite email's link).
5. Keep it plain-text and readable (blank lines between framing / commit /
   link); no HTML.
