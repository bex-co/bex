## Objective

Make the data the enriched email needs available at send time: extend the
`DeployNotification` struct with the failing deploy's id + commit message (and
whatever else the email will render), populate them at the reconciler seam
from the `Deploy` row that already carries them, and give the notifications
service the dashboard base URL so it can build a "View Logs" link.

## Context

- `internal/store/reconciler.go:94` — `DeployNotification` struct today carries
  only `TenantID`, `AppName`, `Status`, `NotifyOnFail`, `NotificationsToSend`.
- `internal/store/reconciler.go:308` — the seam that constructs it inside the
  reconciler, where the `Deploy` row `d` is in scope. `d` carries `ID`,
  `Commit`, `CommitMessage`, `CommitAuthorAt` (`internal/store/store.go` Deploy
  model; migrations `0026_deploy_commit`, `0040_deploy_commit_author_at`).
- The reconciler has the service name (`d.Name`) and the deploy id (`d.ID`) —
  both needed for the `/services/<service>/deploys/<deployId>` link.
- `internal/notifications/service.go` — the service that composes/sends; its
  constructor is where the dashboard base URL should be injected (like the
  members feature takes `InviteBaseURL`).
- `cmd/api/main.go` — `deps.DashboardURL = os.Getenv("BEX_DASHBOARD_URL")` is
  already read; wire it into the notifications service constructor (it may
  currently only reach the members/metadata paths).
- Keep the notifications service HTTP/clientset-free — it just needs the base
  URL string + the fields on the struct, no new client.

## Steps

1. Add the fields the email needs to `DeployNotification` (at minimum
   `DeployID string`, `CommitMessage string`; include `Commit`/`CommitAuthorAt`
   if t002 will render them). Keep them optional-friendly (empty = omit).
2. Populate them at the `reconciler.go:308` construction site from `d`.
3. Add a dashboard-base-URL field to the notifications service (constructor
   param + stored field), wired from `cmd/api/main.go`'s existing
   `BEX_DASHBOARD_URL` read. Preserve the honest-omit contract: empty base URL
   ⇒ no link (t002 consumes this).
4. Confirm the request-time started path (`NotifyDeployStarted`) still compiles
   / passes what it can (a just-opened deploy may or may not have a resolved
   commit yet — carry what's available, omit what isn't).
