## Objective

Implement metadata-keyed Stripe Customer provisioning and deterministic usage meter-event emission behind the existing billing `Ingester` seam.

## Context

- Workspace IDs use `tea-…` and map to Customer metadata key `bex_workspace`.
- Stripe meter-event timestamps accept at most 35 calendar days of backfill.
- Permanent 4xx failures must not hot-loop; retryable failures must leave outbox rows unstamped.

## Steps

1. Implement disabled-by-default Stripe client construction.
2. Resolve/create Customers idempotently and cache their Stripe IDs.
3. Map sealed usage dimensions to the provisioned meter event names and units.
