## Objective

Pin each signal with tests that assert it is specific, correct, and — equally important — silent when the dependency is satisfied.

## Context

- A reporting feature's characteristic failure is the false positive: a condition that fires during every normal rollout is worse than no condition, because users learn to ignore it. Every test here needs its negative case.
- Operator-side signals belong in envtest (`make test`); the projection to deploys/events belongs in the backend suite, whose integration tests run against real ephemeral Postgres + OpenFGA in CI.

## Steps

1. Cover t001: condition fires on an unresolvable Secret, names it, and clears on resolution.
2. Cover t001's negative: a healthy rollout never trips it, including the transient window.
3. Cover t003 and its by-design exclusions (workers, cron jobs, subdomain-policy-disabled).
4. Cover t002's projection: the reason reaches the deploy record and the event feed intact.
5. Confirm each test fails for its own reason.

## Files

- `lego/operator/internal/controller/`
- `lego/backend/internal/store/`, `lego/backend/internal/deploys/`, `lego/backend/internal/events/`

## Acceptance criteria

- [x] Every signal has both a positive and a negative test.
- [x] The by-design exclusions are explicitly covered.
- [x] `make test` and `cd lego/backend && go test ./...` green.
- [x] No tautological or snapshot-everything tests.

### Outcome (2026-08-09)

Coverage was written alongside each change rather than retrofitted, so this task was a review pass and a gap check.

| File | Pins |
| --- | --- |
| `operator/stuck_pod_test.go` (+2) | the config-error diagnosis names the missing object and the fix; a progressing rollout stays silent |
| `operator/public_routing_condition_test.go` | fires when unroutable; clears on a custom domain; **five** by-design exclusions; is not the `Ready` condition |
| `backend/store/unresolvable_dependency_test.go` | the deploy carries the diagnosis; the generic line survives when nothing was diagnosed; the failure classification in both directions; the debounce costs one tick and then records |
| `backend/apps/public_routing_notice_test.go` | the notice reaches the API; is absent when routed or unexplained; reads the operator's verdict over a spec that merely looks routable |
| `backend/notifications/deploy_reason_email_test.go` | the failure email names the cause and keeps its framing; started/succeeded never carry one; a blank reason leaves the mail byte-identical |
| `dashboard/service-detail-header.test.tsx` (+3) | the header explains a missing address; prefers a real url; stays silent with nothing to explain |

The negatives are the load-bearing half throughout. A reporting feature's characteristic failure is the false positive — a condition on every worker, a notice on every service, an alarm on every rollout — and a signal people learn to ignore is worse than the silence being replaced. Anti-tautology verified on the two operator changes: reverting each turns its test red with the message that explains the production symptom.

`lint` also caught what the tests could not: the dashboard's `ServiceView` is a hand-maintained type separate from the generated GraphQL types, so the component compiled against a field the prop type lacked while vitest (which does not typecheck) passed.
