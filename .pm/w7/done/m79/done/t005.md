### Outcome (2026-08-09)

The diff stayed small because both halves extended existing seams instead of adding parallel ones — the whole point of t001's "reuse that path" instruction. `stuckPodMessage` gained a case, `failureReasonFor` gained a case, and the debounce was reused rather than reimplemented.

Two things were worth changing:

- The concrete-failure list in `observedServiceStateFor` was an inline two-term boolean that now has three terms and a real rationale; extracted to `concreteContainerFailure` so the classification has one home and a test can address it directly.
- `publicRoutingNotice` hand-rolled a condition scan; replaced with `meta.FindStatusCondition`, which apimachinery already provides and which the operator side was already using.

Not changed: the condition-scanning loops in `store/reconciler.go` (`failureReasonFor`, `readyReasonForGeneration`, `observedImagePullFailure`) each filter on a different combination of type, generation, and reason, so a shared helper would take enough parameters to be less readable than the three loops.
