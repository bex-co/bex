# Dashboard: edit Key Value eviction policy (maxmemoryPolicy) after create

Follow-up surfaced by **w7/m45** (Key Value update parity). After m45, `maxmemoryPolicy` is updatable post-create on every programmatic surface — REST `PATCH /v1/key-value/{id}`, GraphQL `setKeyValueMaxmemoryPolicy`, MCP `set_key_value_maxmemory_policy` — but the **dashboard** still only sets it at **create** (`dashboard/src/features/keyvalue/hooks/use-create-key-value.ts`, `routes/keyvalue.new.tsx`). The KV detail page has a Networking section (IP allow-list) and a plan-picker, but no eviction-policy editor.

Add a memory-policy control to the KV detail/settings page:

- a `use-set-key-value-maxmemory-policy` hook over a new `SetKeyValueMaxmemoryPolicy` GraphQL op (backend mutation already exists),
- a settings section mirroring `key-value-plan-section.tsx` (dropdown of the Valkey eviction policies, Render-consistent copy in `locales/en.ts`/`zh.ts`),
- component test asserting the mutation fires with the selected policy.

Sub-hour-ish but net-new UI; promote to a small milestone if it grows (e.g. also surfacing persistenceMode edit). Backend + REST/GraphQL/MCP parity already shipped in m45, so this is dashboard-only.
