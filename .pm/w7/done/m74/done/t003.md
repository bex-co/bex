## Objective

Stop the process-wide browser Apollo cache from surviving logout and disclosing the previous account's cached data (workspace names/IDs/plans/roles, deploy-hook URLs) to the next account in the same tab (codex-security #24, low). A `useApolloCacheClear` hook already exists but is not called from login/logout.

## Context

- `dashboard/src/common/apollo/factory.client.ts:11-35` — `clientInstance` is a module singleton, never replaced.
- `dashboard/src/features/auth/pages/login-page/index.tsx:35-47` and `logout-page/index.tsx:21-46` — call only `invalidateSessionCache()` + `router.invalidate()` + navigate; no `client.clearStore()/resetStore()`.
- `dashboard/src/common/hooks/use-apollo-cache.ts:16-21` — `useApolloCacheClear` hook exists, unused on these transitions.
- `use-workspaces.ts` cache-first; `use-deploy-hook.ts` cache-and-network; `use-connection-info.ts` network-only (passwords safe).

## Steps

1. Call `client.clearStore()` (or the existing `useApolloCacheClear`) inside login `onSuccess` and the logout `finally`, before navigate.

## Files

- `dashboard/src/features/auth/pages/login-page/index.tsx`
- `dashboard/src/features/auth/pages/logout-page/index.tsx`

## Acceptance criteria

- [ ] After A-logout + B-login in the same tab, B cannot read A's cached account-scoped objects.

## Out of scope

- Reinitializing the singleton (clearStore is sufficient).
