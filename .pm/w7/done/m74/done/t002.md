## Objective

Stop `/auth/consent` from buffering an unbounded request body before authenticating the caller. `handleConsentDecision` runs a cheap same-origin header check, then immediately `await request.formData()` before fetching the session or checking CSRF/content-length (codex-security #11, medium). The dashboard pod is capped at 256 Mi.

## Context

- `dashboard/src/routes/auth.consent.tsx:14/27-32` → `dashboard/src/common/server-fn/hydra-consent.ts:263-285` — `request.formData()` at ~:273 before session fetch (~:290) and CSRF check (~:292); no Content-Length guard.
- `dashboard/deploy/deployment.yaml:116` — 256 Mi limit.
- `MaxBodyBytes` exists only on bex-api (`lego/backend/cmd/api/main.go:789`), never on the dashboard/Nitro layer.

## Steps

1. In `handleConsentDecision`, enforce a strict Content-Length/body-size cap (e.g. reject >64 KiB) before `request.formData()`.
2. Move the session fetch before the `formData()` await so unauthenticated huge bodies never buffer.
