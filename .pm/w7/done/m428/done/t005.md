## Objective

Check that the `commit_ignored` event and its reason read the same on REST, GraphQL, MCP and the dashboard's Events tab, that the dashboard's Root Directory and Build Filters hints describe the rule the webhook applies, that Blueprint `rootDir` and `buildFilter` reach the same decision, and that all of it matches Render's deploys and monorepo pages.

## Context

- REST, GraphQL and MCP in `lego/backend/` share one Core; the dashboard consumes GraphQL (`dashboard/AGENTS.md`).
- Render reference: render.com/docs/deploys, render.com/docs/monorepo-support, render.com/docs/blueprint-spec.

## Steps

1. Compare each surface's behavior and wording for this milestone's change against Render and against each other.
2. File any drift as follow-up work through `/pm`; record the outcome here.

## Files

- `lego/backend/internal/apps/`, `lego/backend/internal/events/`
- `dashboard/src/features/services/`
- `docs/ADR018-render-parity.md`, `docs/render-artifacts/auto-deploy-filters.md`

## Acceptance criteria

- [x] Every surface behaves and reads the same, and matches Render's documented behavior, or the drift is filed.

## Outcome (2026-11-17)

Done. No drift to file.

- **Events, live on production (t004's fixture).** All four surfaces return the same 13 `commit_ignored` events with the same reasons: 6 `skip_phrase`, 6 `build_filter` and 1 `root_directory`.
  - REST `GET /v1/services/{id}/events` and MCP `list_events` (`eventTypes: [commit_ignored]`) carry `details {reasonCode, id, url}`, Render's `id`/`url` pair for the commit.
  - GraphQL `serviceEvents` carries `details {reasonCode, commitId, commitUrl}`. That schema is bex's dashboard schema, not a Render surface.
  - The dashboard's Events tab, after loading the older pages, shows each as "Commit ignored" with its sentence and a commit link. The sentences are "The commit message requested that this deploy be skipped.", "The changed files did not pass the service's build filters." and "No changed file matched the service's root directory."
- **Dashboard hints** (`dashboard/src/features/services/locales/en.ts`) match the rule the webhook applies (`pathsIgnoredReason`):
  - Root Directory: "Code changes outside of it don't trigger an auto-deploy unless they match an included build filter path".
  - Included Paths: "A push deploys only when a changed file matches one of these, even outside the root directory. Empty means every path under the root directory is included".
  - Ignored Paths: "never triggers a deploy, even if it also matches an included path".
  - Build Filters: patterns are "relative to the repository root, even when a root directory is set".
- **Blueprint.** `rootDir` and `buildFilter` compile into the same App spec fields the webhook reads (`blueprint_compiler.go`). `TestBlueprintRootDirAndBuildFilterDecideAPush` (t007) proves that a Blueprint-declared service reaches the same four decisions.
- **Render.** Every observed decision matches a sentence on render.com/docs/deploys or render.com/docs/monorepo-support, as quoted in `docs/render-artifacts/auto-deploy-filters.md`. Cells A, B and C remain inferences from those pages. Capturing Render's own behavior, including its event wording for an ignored commit, still needs a Render account (`w10/blocked/002`). `reasonCode` on `commit_ignored` is a bex field from w4/m162, not changed here.
