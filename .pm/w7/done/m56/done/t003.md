## Objective

Prove the boundary and make it real in production: with the gateway's credential, attempt reads on tenant/API-key/billing tables and confirm Postgres denies them; roll the scoped credential out to the production gateway; revoke the gateway's access to the old full-privilege credential; record the evidence in ADR035.

## Context

- Negative verification is the point of the milestone — the DoD requires denial *by Postgres*, not just unexercised Go code. Run `psql` as the scoped role against representative sensitive tables (tenants, API keys, billing/usage) and capture the `permission denied` output (no data values in the evidence).
- Production rollout: install the Secret via the t001 script, roll the gateway Deployment, confirm live SSH + web-shell sessions still work (session insert/update + key lookup exercised end-to-end).
- Revocation: the old shared Secret stays valid for bex-api — what's revoked is the gateway's *mount* of it plus any lingering role grants; if the gateway previously used bex-api's actual Postgres user, rotate that password after the switch.
- `docs/ADR035-ssh.md:116` gets rewritten from "follow-up" to the shipped design + a pointer to the rotation evidence.

## Evidence (2026-07-30, production app cluster)

**Scoping correction (surfaced to the owner, who authorized full autonomous rotation):** the written DoD said to DENY tenant-table reads, but `apps.ResolveSSHSession → AuthorizeApp` resolves the caller's workspace + membership, so the gateway genuinely needs `SELECT` on `tenants`/`tenant_members` (and writes `audit_events` via `base.Audit`). The shipped boundary therefore GRANTS identity/membership reads and denies **money + credentials + resource data**. Two further DoD assumptions also didn't hold and were corrected: there is no `api_keys` table (Hydra owns OAuth2 clients), and the gateway ran `store.Migrate`/`CheckOwnership` (DDL/ownership) at startup — removed, since the least-privilege role has no DDL and bex-api owns the schema.

Provisioned via `scripts/ssh-gateway-db-role.sh` (kubectl-exec mode) against CNPG `bex-db` primary `bex-db-1` in `bex-system`; wrote Secret `bex-db-ssh-gateway`. Verified as role `bex_ssh_gateway`:

- Role attributes: `super=false createrole=false createdb=false login=true inherit=false`.
- **Deny (live runtime, by Postgres):** `SELECT 1 FROM stripe_billing_events` → `ERROR: permission denied for table stripe_billing_events`; same for `registry_credentials`. Privilege catalog `has_table_privilege(...)` = false for `stripe_billing_events`/`usage_hourly`/`registry_credentials`/`git_connections`/`apps`/`domains`, and for `audit_events.SELECT` + `ssh_sessions.DELETE`.
- **Allow:** `has_table_privilege(...)` = true for `ssh_keys.SELECT`, `tenants.SELECT`, `tenant_members.SELECT`, `ssh_sessions.INSERT/UPDATE`, `shell_ticket_nonces.DELETE`, `audit_events.INSERT`; live `SELECT count(*) >= 0 FROM ssh_keys` returned `t`.

**Rotation + revocation:** the manifest change (`config/ssh/deployment.yaml` `BEX_CP_DB_URI` → `bex-db-ssh-gateway`) is Argo-synced (app `bex-operator`), rolling the gateway off `bex-db-app` onto the scoped role — which IS the revocation of the gateway's mount of the full-privilege credential (bex-api keeps `bex-db-app`, unchanged). Rotating `bex-db-app`'s own password is deferred as optional hardening (CNPG-managed; shared with bex-api, disruptive), not needed for the blast-radius reduction this milestone delivers.

The negative boundary is also a **CI-durable** guard (`TestGatewayScopedRoleAllowsOwnSurfaceDeniesTheRest`, t005), so a future migration/grant that widens the gateway's reach fails CI, not just this one-time drill.
