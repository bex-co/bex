## Objective

Encode the boundary as a durable test instead of one-time drill evidence: an integration test that provisions the scoped role (t001's DDL) against the ephemeral test Postgres, runs the gateway `Store` through its full surface under that role (all operations succeed), and asserts that reads on sensitive tables fail with a Postgres permission error — so a future migration or store change that silently widens the gateway's needs (or a grant that silently widens its reach) fails CI.

## Context

- Integration tests gated on `BEX_TEST_DB_URI` run unconditionally in CI with a real ephemeral Postgres (`backend-test.yml`), so the role DDL can be applied for real in-test.
- Keep the role DDL single-sourced: the test should execute the same SQL the t001 script applies (extract the DDL to a shared file the script and test both read), so drift between script and test is impossible.
- Deny assertions must check the Postgres error class (insufficient_privilege), not just "an error".

## Steps

1. Extract the role DDL to a shared artifact consumed by both `scripts/ssh-gateway-db-role.sh` and the test.
2. Integration test: create role → run every gateway `Store` method under it → assert success; attempt sensitive-table reads → assert `insufficient_privilege`.
3. Add a completeness touch: the test enumerates the store's methods so a newly added store method is exercised or the test fails to compile/enumerate.

## Files

- `lego/backend/internal/sshgateway/` (new integration test + shared DDL artifact)
- `scripts/ssh-gateway-db-role.sh` (consume the shared DDL)

## Acceptance criteria

- [ ] CI-run integration test proves allow + deny under the actual role DDL.
- [ ] Script and test share one DDL source (no drift possible).
