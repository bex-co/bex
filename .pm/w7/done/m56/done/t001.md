## Objective

Design and script the least-privilege role: inventory exactly which tables/columns the gateway's `Store` touches (SSH public-key lookup, session metadata insert/update, audit writes), define a Postgres role granted only those operations, and ship an idempotent install/rotate script in the pattern of the existing out-of-band gateway secret scripts.

## Context

- `docs/ADR035-ssh.md:116` — the follow-up this milestone closes; documents that the narrow Go `Store` interface does not constrain a stolen credential.
- The gateway's store lives in `lego/backend/internal/sshgateway/` (key lookup + session/audit persistence against `BEX_CP_DB_URI`).
- Script precedents: `scripts/ssh-host-key-secret.sh` (out-of-band gateway secret install), `scripts/registry-secrets.sh` (credentialed-identity provisioning).
- The control-plane DB is a CNPG cluster; role creation is a SQL operation against it (script + runbook, not an app migration — migrations run as the app user, which must not own role management).
- Grants must survive schema migrations: prefer `ALTER DEFAULT PRIVILEGES` / explicit re-grant guidance in the script over one-shot grants that new tables silently escape.

## Steps

1. Enumerate the gateway store's SQL surface (tables + operations) from `internal/sshgateway/`.
2. Write the role DDL: `CREATE ROLE bex_ssh_gateway LOGIN`, grants limited to the enumerated surface, no CREATE, no other tables.
3. Script it: `scripts/ssh-gateway-db-role.sh` — idempotent create/grant + password (re)set → Kubernetes Secret, following the existing script conventions (never print the secret).
4. Document the migration-vs-grants interaction (what to re-run when the gateway's tables change).

## Files

- `scripts/ssh-gateway-db-role.sh` (new)
- `lego/backend/internal/sshgateway/` (read-only inventory)

## Acceptance criteria

- [ ] Role DDL grants exactly the enumerated operations; re-running the script is a no-op.
- [ ] Secret material never echoed/logged/committed.
