## Objective

A written, drilled restore path — including the AOF pitfall — and docs that state the durability contract honestly.

## Context

- **The pitfall:** ADR021 instances run with AOF enabled (`appendonly yes`). A Valkey with an AOF present ignores `dump.rdb` at boot — seeding a PVC with a restored RDB while the AOF dir survives silently restores nothing. The runbook must seed into a *fresh* PVC (or clear the AOF dir / start with `appendonly no`, then re-enable + `BGREWRITEAOF`).
- Restore shape: scale the StatefulSet to 0 (or create a fresh instance), place the chosen `dump.rdb` in the data dir before start, start, verify a known key, re-enable AOF.
- Docs: ADR021 gains the backup-design section (mechanism, `keyvalue/<id>/` layout, keep-7, plan gating, **RPO = snapshot cadence, not PITR; Free = PVC-only**) — the deferred-consequence line is replaced. ADR031's policy table gains the KeyValue row.

## Steps

1. Write the runbook (in ADR021 or ADR031, pointer from the other — follow where the Postgres restore runbook lives).
2. Drill on a dev/prod paid instance: write marker key → snapshot → destroy → restore per runbook → marker present. Record as `drills/<date>-keyvalue-restore.md`.
3. Amend ADR021 + ADR031; `npx prettier@3.4.2 --write "docs/*.md"`.
