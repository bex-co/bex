## Objective

Deleting a KeyValue leaves nothing behind: the backup CronJob goes with the owner reference, and the `keyvalue/<id>/` S3 prefix is purged by the finalizer — same contract w7/m12 established for CNPG S3 backups.

## Context

- Pattern: `lego/operator/internal/controller/database_controller.go` — the w7/m12 CNPG S3 backup-purge finalizer (purge Job/inline delete before releasing the finalizer; tolerate already-gone).
- The flat `keyvalue/<id>/` prefix (m68 README §Directory-structure decision) makes this a single prefix delete.
- Skip cleanly when the env contract is unset (nothing was ever written) — the finalizer must not block deletes when backups are disabled.

## Steps

1. Extend the KeyValue finalizer with the prefix purge (mirror the Database purge shape).
2. Verify live: create paid KV → snapshot lands → delete KV → prefix gone, CronJob gone, CR fully deleted.
