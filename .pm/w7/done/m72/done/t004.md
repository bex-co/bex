## Objective

Bound the fan-out of long-running pg_dump Jobs so repeated export requests cannot exhaust the database, scheduler, and tenant node resources (codex-security #13, medium).

## Context

- `lego/types/v1alpha1/database_types.go:226/289` — `Database.spec.exports` is a map with no `MaxItems`; request IDs unvalidated.
- `lego/operator/config/crd/bases/app.bex.co_databases.yaml:97` — CRD declares `exports` as a map, no `maxItems`.
- `lego/operator/internal/controller/database_exports.go:42-103/105-126` — `reconcileExports` iterates the full list and `reconcileExportJob` does `r.Create` per new entry with no per-Database concurrency cap; each Job up to 2h, guaranteed CPU/mem, unbounded emptyDir, bucket creds.
- Only build concurrency is capped today (`lego/operator/cmd/manager/main.go:241`).

## Steps

1. Add `x-kubernetes-list-maxItems` (or a validating webhook) to `spec.exports`; validate request-id shape/length.
2. In `reconcileExports`, count active `postgres-export-*` Jobs for this Database and refuse to create beyond a per-Database (and optionally per-workspace) limit; surface "export queue full" status rather than silently fanning out.
