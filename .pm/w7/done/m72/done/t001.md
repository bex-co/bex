## Objective

Set a short read deadline before consuming the PostgreSQL startup/TLS handshake so an attacker cannot hold each accepted connection's goroutine and file descriptor indefinitely (codex-security #2, medium). The sibling kv-sni-proxy already implements the missing control.

## Context

- `lego/operator/cmd/pg-sni-proxy/main.go` `handleConn` (~:318/329, 339-361) — blocking `sniproxy.ReadProxySource`, `io.ReadFull`, `sniproxy.ReadTLSRecord` with no `conn.SetReadDeadline`.
- `lego/operator/cmd/kv-sni-proxy/main.go:266/277` — sets `conn.SetReadDeadline(time.Now().Add(handshakeTimeout))` then clears at :294. Mirror this.
- `lego/operator/config/pg-sni-proxy/daemonset.yaml:33` — hostPort 5432, 96 MiB cap.

## Steps

1. At the top of `handleConn`, set the handshake read deadline; clear it once SNI is resolved / backend is dialed.
2. Keep the PROXY-protocol + TLS preamble path covered.

## Files

- `lego/operator/cmd/pg-sni-proxy/main.go`

## Acceptance criteria

- [ ] A connection that trickles no/partial handshake is dropped within the deadline.
- [ ] Legit handshakes still succeed.

## Out of scope

- Connection/concurrency budget beyond the deadline (capture in the task if cheap).
