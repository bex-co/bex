## Objective

Preserve the caller's validated reset request through the existing shared deploy trigger and control-plane projection until the operator dispatches the intended release.

## Context

- REST, GraphQL, and MCP already feed TriggerParams.ClearCache into one deploy service. triggerFetched currently patches release inputs and creates a deploy row without carrying ClearCache.
- The control-plane reconciler must not erase the new intent on a later pass or redirect it to a different generation.

## Steps

1. Thread reset intent through the existing triggerFetched mutation using the t001 contract and current release generation.
2. Update persistence/projection only where the existing source-of-truth path requires it; preserve the intent across API/operator restart and reconciliation.
3. Keep enum/source validation and authorization before mutation. Preserve commit selection, deploy history, image-only behavior, and omission defaults.

## Acceptance criteria

- [ ] The same release/reset association reaches the operator from REST, GraphQL, and MCP.
- [ ] Projection and process restart preserve pending reset intent without issuing an extra deploy.
- [ ] Invalid enum values and forbidden requests fail before changing the App, cache state, or deploy history.
- [ ] Ordinary deploys preserve their current defaults and commit selection.
