## Objective

Define the existing clearCache enum's behavior for every supported builder/source state and encode a durable reset request bound to the correct release.

## Context

- lego/backend/internal/deploys/service.go validates clearCache but intentionally discards its effect. m86's registry cache invalidates the old no-cache rationale.
- App release-generation annotations and release_identity.go already distinguish requested, active, pending, and canceled releases. Reuse that lifecycle contract.
- This task waits for m87 closeout to avoid competing edits to native dispatch and cache identity.

## Steps

1. Write the behavior table for clear, do_not_clear, and omission with native/Dockerfile registry cache on/off, kpack, and image-backed services.
2. Specify retry, failed-build, cancellation, superseding-request, and next-normal-deploy behavior; decide how old cache writers are prevented from reversing an effective reset.
3. Add the minimal shared types contract needed to carry reset intent without allowing it to become a sticky global/App boolean. Run codegen if CRD fields change.

## Acceptance criteria

- [ ] The behavior table has no silent reuse of prior artifacts for a supported clear-cache rebuild.
- [ ] Reset intent identifies the correct release and has explicit consumption/retry rules.
- [ ] The types contract preserves the workspace import DAG and current source/builder compatibility.
- [ ] No optional field is accepted and silently ignored where it promises an effect.

## Out of scope

- Changing the public enum to a boolean or inventing a new public cache-management API.
- Reopening repo-backed deploy_only artifact reuse or adding a kpack performance project.
