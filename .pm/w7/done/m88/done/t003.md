## Objective

Honor the reset in the existing credential-separated build pipeline so the requested rebuild cannot import prior artifacts and later normal builds can reuse its fresh result.

## Context

- build.go restores a per-App cache before BuildKit, imports a local OCI layout, and saves a fresh cache alongside image push.
- The registry phases own credentials; the tenant-executing BuildKit container must not gain output-registry credentials to perform a reset.
- m87 adds native environment-sensitive cache identity, which must compose with an explicit full reset.

## Steps

1. Apply t001's reset contract at dispatch and cache restore/import, scoped to the requested App and release.
2. Prevent old layers from entering the clear-cache build, then permit a successful build to replace/populate the fresh reusable cache.
3. Implement or prove the behavior-table entries for cache off, kpack, and image-backed services without manufacturing unsupported cache effects.
4. Preserve cache transport fallback and the single-tag retention assumptions, or explicitly update the retention proof if the chosen mechanism changes them.

## Acceptance criteria

- [ ] A proven warm build followed by clear recomputes the relevant artifact-producing steps.
- [ ] A subsequent normal deploy can reuse the fresh cache.
- [ ] The reset cannot read, remove, or overwrite another App/workspace's cache or deployable image.
- [ ] Registry credentials remain outside tenant-executing build steps and cache-disabled behavior stays correct.

## Out of scope

- Cluster-wide cache pruning, wildcard registry deletion, or extra cache infrastructure.
- Changing production BEX_BUILD_CACHE or weakening registry retention.
