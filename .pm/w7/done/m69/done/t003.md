## Objective

One parameterized script that bootstraps a CNPG recovery cluster from any Barman ObjectStore — covering `bex-db`, tenant Databases, and (post-m67) the auth DBs with the same code path — with optional PITR `targetTime`.

## Context

- Runbook: `docs/ADR031-platform-data-backup.md` § bex-db restore (CNPG `bootstrap.recovery` + `externalClusters` plugin reference; always a NEW throwaway cluster, never in-place). Drilled 2026-07-28 (`drills/2026-07-28-barman-plugin-pitr.md`) — that drill's manifests are the template.
- Parameters: ObjectStore name + namespace, serverName (e.g. `bex-db`, `<database>-pg<major>`, `kratos-db-pg<major>`), target namespace, optional `--target-time <RFC3339>` for PITR, verification query (SQL string or per-store default).
- ObjectStores: `bex-system/bex-db`, `default/bex-tenant-postgres`, `auth/auth-dbs` (once w7/m67 t001 lands — parameter-compatible either way, no code change needed).
- Safety rails: generated recovery cluster name is always prefixed (e.g. `restore-<ts>-`), never a name a live service resolves; teardown flag deletes cluster + PVCs and verifies zero leftovers.

## Steps

1. Write the script (render recovery-Cluster manifest → apply → wait healthy → run verification query → optional `--teardown`).
2. Validate against `bex-db` in prod (`DRY_RUN=1` first, then a real throwaway recovery + teardown).
