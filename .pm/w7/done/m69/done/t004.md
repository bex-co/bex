## Objective

Script the KeyValue restore: pick a snapshot from `s3://bex-tfstate/keyvalue/<id>/`, seed it into a target instance's fresh data volume with the AOF pitfall handled, verify, re-enable AOF.

## Context

- Design source: w7/m68 (README § Directory-structure decision + t005's runbook). **Coordination:** if m68 hasn't landed when this is picked up, implement against m68's recorded design and validate with a hand-uploaded snapshot; m68 t005's drill then adopts this script instead of ad-hoc commands (that intent is noted here so neither milestone duplicates the other).
- The pitfall (from m68 t005): AOF-enabled Valkey ignores `dump.rdb` at boot when an AOF exists — the script must seed into a fresh/cleared data dir with `appendonly no`, verify, then re-enable AOF + `BGREWRITEAOF`.
- Parameters: KeyValue id, snapshot key (default latest — RFC3339 names make that the last key), and a required fresh `restore-*` namespace. The milestone safety contract forbids the stale proposed `--in-place` mode.
- Auth from the instance's `<id>-auth` Secret; never echoed.

## Steps

1. Write the script (fetch → gunzip → scale-down/fresh target → seed → start with AOF off → verify marker/DBSIZE → re-enable AOF).
2. Validate against a dev paid instance end to end.
