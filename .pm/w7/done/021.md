# onbex.co PSL / tenant cookie isolation — track to closure

**Type:** owner-waived architecture decision, tracked to closure. **Not a milestone** (no code action now; closure is a DNS/PSL eligibility gate).

codex-security scan #12 (medium): `onbex.co` is absent from the browser-consumed Public Suffix List (unlike `onrender.com`), and a real-Chrome harness proved a `Secure;Domain=onbex.co` cookie set by tenant A's JS is delivered to sibling tenant B — enabling cookie tossing / session-fixation between mutually-untrusted tenant apps. Control-plane sessions were moved to `*.bex.co`, which limits blast radius but does not isolate tenant apps from each other.

**Owner-waived 2026-07-30** (`docs/drills/2026-07-29-static-site-trust-baseline.md:7-10,80`): PSL upstream eligibility needs ~2,000–3,000 distinct users; bex has ~17. Host-only/`__Host-` guidance is explicitly not treated as equivalent browser enforcement.

**Closure path (pick when eligible):** (a) submit `onbex.co` to the PSL once the distinct-user threshold is met; or (b) move tenant apps beneath a per-tenant suffix (e.g. `<tenant>.apps.onbex.co` with a PSL entry for `apps.onbex.co`). Until eligibility, this is accepted residual risk — no code change.
