## Objective

Add a regression test for every fixed-in-place finding that asserts the **pre-fix failure mode** — the test must fail against the pre-fix code and pass after. This is what makes the audit durable: a re-introduced defect becomes a CI failure. If the audit produced no code fixes, record that and confirm the follow-ups carry their own test obligations.

## Context

- The DoD requires a regression test per fixed-in-place finding; a snapshot or tautological test does not qualify (repo rule — assert real behavior/failure modes).
- Backend tests run in `backend-test.yml` with real ephemeral Postgres + OpenFGA; operator changes run under `make test` (envtest). Place each regression test in the suite matching the fixed code.
- Owned-follow-up findings are **not** tested here — their tests belong to their own milestones; note that so coverage isn't double-counted.

## Steps

1. For each fixed-in-place finding, write a test that reproduces the pre-fix failure (bad-signature webhook accepted, cross-tenant publish, label-spoof escape, etc.) and asserts the post-fix denial/behavior.
2. Verify each test is red against the pre-fix code (revert-and-run or a targeted assertion) and green after.
3. Run the relevant suite(s) (`cd lego/backend && go test ./...` and/or `make test`); confirm green.
4. If no code was fixed in-place, record the no-op and confirm each follow-up item names its own test obligation.

## Files

- test files alongside whatever t006 fixed (`lego/backend/internal/**/**_test.go`, operator suites)

## Acceptance criteria

- [ ] Every fixed-in-place finding has a regression test that is red pre-fix and green post-fix.
- [ ] No test games coverage (no snapshot-everything / tautological assertions).
- [ ] The relevant suite(s) pass; or a no-op is recorded with follow-up test obligations noted.

## Out of scope

- Tests for owned-follow-up findings (their own milestones own those).
