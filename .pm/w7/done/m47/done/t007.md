## Objective

Prove the event→metric→rate mapping is correct: for a chosen period, Metronome's computed billable-metric totals must equal the `usage_hourly` quantities bex exported. This is the acceptance gate before m48 exposes any real cost.

## Context

- `docs/ADR040-billing-metronome.md` §8 Phase 1 (reconcile Metronome's computed usage against `usage_hourly`).
- Needs the rate cards/metrics from t001 and a run of the emitter (t005).
- Compare per `(resource_kind, kind, tier)`: `SUM(usage_hourly.quantity)` over the period vs Metronome's billable-metric total for the same window/customer (read via the Metronome API).
- A script/harness (like `scripts/*-verify.sh` / `*-audit.sh` precedents), not a production code path.

## Steps

1. Pick a period + a test workspace with real sealed rows.
2. Query `usage_hourly` totals grouped by `(resource_kind, kind, tier)` for the period.
3. Query Metronome's billable-metric totals for the same customer/window.
4. Diff; assert equality within rounding; print a per-meter table and a pass/fail.
5. Document how to run it (README / runbook cross-link).

## Files

- `scripts/metronome-reconcile.sh` (or a Go test harness) (new)
- runbook/README note on usage

## Acceptance criteria

- [ ] The harness reports per-meter `usage_hourly` vs Metronome totals for a period and a clear pass/fail.
- [ ] On a correctly-mapped export it passes within rounding; a deliberately corrupted mapping fails loudly.

## Out of scope

- Real invoices/cost readback (m48/t002).
