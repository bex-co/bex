## Objective

Stop two Apps from claiming the same hostname. Today `AddDomain` only checks whether the host is a duplicate **on the same App**; a different App (any tenant) can register the same host, producing two Ingress rules and an undefined routing/cert-issuance outcome. Add a cross-App uniqueness check — mirroring Render's "This domain already exists on another site." — that rejects the add when the host is already registered on a different App.

## Context

- `lego/backend/internal/apps/domains.go:207-221` — `AddDomain`; the only current check is the same-App duplicate loop at 218-221.
- The control-plane store is the source of truth for which App owns which host — add a lookup "is this host registered on any other App?" A partial unique index on the host column is the durable enforcement (cf. the `tenant_members` partial-unique-index pattern in `lego/backend/internal/store/members.go:123`).
- Store-less (hand-applied App CR) mode has no cross-App index; in that mode the check degrades to best-effort (a CR list scan) or is skipped with the legacy caveat already documented for network policies — decide and note it.
- Return `core.ErrBadRequest` (the sentinel the existing custom-domain adapters already map to a 400) so the rejection surfaces like every other validation error; a dedicated conflict/409 is optional and pinned in t004 against Render's actual code.
- **Render-consistency:** Render blocks a duplicate at **add time** regardless of verification state ("already exists on another site"), so key the check on *registration* (present in `spec.hosts[]`/store), **not** on the cert-based `VerificationStatus`. Stay **per-host**: do not auto-reserve the www/apex sibling — bex deliberately omits Render's pairing (`domains.go:270-275`), so pairing-aware uniqueness is out of scope here.

## Steps

1. Add a store method + (partial) unique index enforcing host uniqueness across Apps; update the fake store.
2. In `AddDomain`, before writing, reject when the host is registered on a different App with a typed conflict error.
3. Handle the store-less path (best-effort CR scan or documented skip); keep the same-App idempotent re-add behavior intact.

## Files

- `lego/backend/internal/apps/domains.go` — `AddDomain`
- `lego/backend/internal/store/` — host-uniqueness lookup + migration/index + fake store

## Acceptance criteria

- [ ] Adding a host already registered on a different App is rejected with a typed 400-class/conflict error; adding a free host still succeeds; re-adding the same host to the same App stays idempotent.
- [ ] Store enforces uniqueness durably (index) where the store is present; the store-less behavior is decided and documented.
