# 057 — Destructive typed-phrase confirms disagree on what phrase to require

Why: four different delete confirmations ask the user to type four differently-shaped strings, so the muscle memory one builds on services does not transfer to webhooks or disks — and a confirmation the user has to re-read every time is a confirmation they will start pasting past.

**Estimate:** 30m to decide, then tens of minutes to apply · **Severity:** minor (consistency/UX; every gate works today) · **Attribution:** dashboard · **Worker:** worker7

## The disagreement

Split out of [`053`](done/053.md), which fixed the **role** axis (those confirms now announce as `alertdialog`). `053` argued at length that the two are separate — _"The role split is four call sites using the wrong primitive; the phrase split is a copy/convention disagreement that exists within the correct primitive as well. Fixing the first does not fix the second"_ — and fixing the first has now proved it: every site below still asks for a different shape.

| surface                   | required phrase                  | built by                                   |
| ------------------------- | -------------------------------- | ------------------------------------------ |
| web service / static site | `sudo delete <type> <name>`      | `SudoCommandField` consumers               |
| env group                 | `sudo delete env group <name>`   | `SudoCommandField`                         |
| Postgres                  | `sudo delete postgres <name>`    | `SudoCommandField`                         |
| key value                 | `sudo delete key value <name>`   | `SudoCommandField`                         |
| **webhook endpoint**      | **`delete webhook <name>`** — no `sudo` | `webhook-settings-card.tsx:311` (`ConfirmDialog` `phrase`) |
| **disks**                 | `diskSudoPhrase(verb, disk)` for **delete _and_ restore** | `disk-section.tsx:52` |

Both outliers were observed live: sweep 25 confirmed the webhook dialog rejects the sibling convention's phrase and accepts only its own.

## Why this is a decision, not a change

The mechanical part is trivial — change a template string. What is not trivial is **which** convention wins, and that is a product call with real consequences either way:

- **Standardise on `sudo delete <type> <name>`.** Consistent, and matches Render. But it changes a phrase users may have in runbooks, and `sudo` is arguably theatre for a webhook endpoint, which destroys a subscription rather than a running workload.
- **Keep per-surface phrasing.** Honest about severity — deleting a webhook really is less destructive than deleting a database — at the cost of the muscle memory that makes typed confirms work at all.
- **Decide what `restore` does.** Disks use the sudo shape for a *non-destructive* verb, which either dilutes the signal or correctly reflects that a restore overwrites live data. That one is genuinely unclear from outside.

There is no repository evidence that settles it: `docs/ADR018-render-parity.md` does not cover confirmation copy, and nothing in `.pm/DO_NOT_DO.md` applies.

## What to do once decided

Whichever way it goes, the convention belongs in one place rather than in each call site's string literal — `SudoCommandField` and `ConfirmDialog`'s `phrase` prop are both already shared, so a single `confirmPhrase(kind, name)` helper would keep the next surface from inventing a seventh shape.
