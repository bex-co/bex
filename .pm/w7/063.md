# Public sandbox create accepts the internal `agent` template, whose pod dies at once

Why: `POST /v1/sandboxes` with `template: agent` returns 201, but the agent image's driver exits 1 at start (`BEX_AGENT_MODEL_PROXY_URL is required`, since 7a2303ffc) and the public create refuses every `BEX_*` env name, so such a sandbox can never run. A caller gets a sandbox that is dead on arrival instead of a clear refusal.

- Found by w7/m390 t007 (isolation-matrix run 43570243129, readiness diagnostics from 30563ff17); see w7/m393.
- `lego/backend/internal/sandbox/rest.go` `POST /v1/sandboxes` resolves any registered template (`Service.Templates`, `service.go`); only `AgentSessionLifecycle.CreateAgentSessionSandbox` gives the agent template its env.
- Fix: the public create (REST, GraphQL, MCP) refuses the agent template as an unknown template (400), agent sessions keep using it; a test for each surface. Render has no agent template, so refusing it keeps parity.
