# A member of a workspace that requires Google login cannot unlink GitHub either; Render refuses only disconnecting Google

Why: Render says a member of an enforcing workspace "can't disconnect your Google account" ([login settings](https://render.com/docs/login-settings)); bex's settings guard refuses every unlink while Google is linked, which is stricter than Render for a GitHub unlink.

- Found by w7/m465 t006 and t009, 2026-11-17 ([ADR012 §9b](../../docs/ADR012-auth.md#9b-workspace-enforced-google-login-w7m465), the "Known drift" in [ADR018](../../docs/ADR018-render-parity.md)'s Google login row).
- Cause: Kratos's settings `web_hook` payload carries the identity as it would be saved but without its credentials, and the unlink request's body is not in it (probed on Kratos v26.2.0), so `internal/settingsguard` cannot tell which provider an unlink removes. It refuses every unlink from the settings POST while the identity has a `google:` oidc identifier.
- Options: the dashboard sends the provider in the settings flow's `transient_payload` (Kratos passes it to the hook as `ctx.flow.transient_payload`) and the guard allows an unlink that names a provider other than Google; a client that lies only unlinks its own Google account, and the gate still refuses it afterwards. A client that sends no payload stays refused.
- Done when: a member of an enforcing workspace unlinks GitHub from the dashboard, Google's unlink is still refused, and `scripts/auth-oidc-e2e.sh` pins both.
