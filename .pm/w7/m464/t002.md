## Objective

Give the control-plane database an organization: its id and name, its primary workspace, its members with an org role, and the workspaces it holds, each with a privacy setting. Production's existing Scale and Enterprise workspaces each become the primary of their own org, so no paid workspace is left outside one.

## Context

- `lego/backend/internal/store/workspaces.go`:
  - `CreateWorkspace` (:57) inserts the `tenants` row and makes the creator an `admin` in `tenant_members`;
  - `UpdateTenantPlan` (~:237) is every plan change's single write.
- Workspaces created through `CreateWorkspace` have no `owner_identity_id` (:99), so the store does not know who upgraded a workspace. The backfill has to pick its Owners from the current admins.
- Mint ids only with `id.New(kind)` (`lego/backend/internal/id/id.go`); add the `Organization` kind decided in t001.
- The latest migration on main when this was filed is `0292_workspace_audit_visible_from`. Take the next free number from `origin/main` when you write the migration.
- Production on 2026-11-17 had 3 Scale workspaces and 1 Enterprise workspace, and one admin held two or more of them (w7/070).

## Steps

1. Add migration `<next>_organizations` (with a down migration):
   - `organizations (id, name, primary_workspace_id, created_at, audit_visible_from)`;
   - `organization_members (organization_id, subject, role CHECK owner|member|guest, created_at)`;
   - `tenants.organization_id` (nullable FK) and `tenants.privacy` (`invite_only` default, or `public`);
   - org invites, either as their own table or as `tenant_invites` with an org scope, whichever t001's ADR chose.
2. Backfill in the same migration. For every `tenants` row on `scale` or `enterprise`:
   - create an org named after the workspace, with the workspace as primary;
   - make every current workspace admin an Owner, as t001 records (bex never recorded who upgraded, and an admin already controls the workspace);
   - make every other member a Member.
3. Add the store methods every later task needs:
   - create an org with its primary in one transaction;
   - get and list orgs for a subject;
   - list an org's workspaces and members;
   - add, remove and change an org member;
   - set a workspace's privacy;
   - attach a workspace to an org, and detach it;
   - delete an org.

   Each method locks the rows it reads, the way `UpdateTenantPlan` locks the tenant.
4. Keep every existing reader unchanged: `tenants.plan` stays the plan each feature gate reads.
