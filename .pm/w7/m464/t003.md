## Objective

Make the authorization model match Render's org roles:

- an Owner manages the org but is not an admin of its workspaces until they add themselves;
- a Member may join the org's public workspaces;
- a Guest reaches only the workspace they were invited to.

Write the tuples that the store's org changes imply.

## Context

- `deploy/gitops/authz/model.fga:52-61` today has `type org { admin, member }` and `workspace.admin: [user] or admin from org`. Render says Owners "are not automatically added to workspaces" (render.com/docs/organizations), so `admin from org` goes.
- `model.json` beside it is the applied artifact (`fga model transform --file model.fga`). `scripts/authz-model.sh` applies it, and `scripts/gitops-validate.sh` gates the pair against drift.
- `lego/backend/internal/authz/` (the client, `authz_property_test.go`) and the relation constants in `lego/backend/internal/core`.

## Steps

1. Model the org relations:
   - `org`: `owner`, `member: [user] or owner`, `guest`;
   - `can_manage_org: owner`, `can_create_workspace: owner`, `can_view_org: member or guest`;
   - `workspace`: keep `org: [org]`, drop `admin from org`. Add `can_join: member from org` for public workspaces (a `public` tuple or a condition, whichever the model keeps simplest) and `can_join_as_admin: owner from org`.
2. Regenerate `model.json`. Run `scripts/gitops-validate.sh`.
3. Write and delete tuples wherever t002's store methods change an org or its members: org create, member add, remove and role change, workspace attach and detach, privacy. Also write them for the backfilled orgs, with a one-shot reconcile at bex-api start that is idempotent, following the existing tuple backfills.
4. Update ADR012's model narrative and the model's header comment.
