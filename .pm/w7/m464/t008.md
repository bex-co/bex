## Objective

Record Render's org events and serve them:

- at Render's `GET /v1/organizations/{orgId}/audit-logs`, with the workspace audit log's parameters and shape;
- on GraphQL for the dashboard.

Only an Owner reads them.

## Context

- Render (render.com/docs/audit-logs, read 2026-11-17):
  - Org audit logs are on Scale and higher, and "Only org members with the Org Owner role can export these audit logs", 90 days per export.
  - Retention starts at the upgrade.
  - Events:
    - member management: `InviteToOrgEvent`, `AcceptOrgInviteEvent`, `AddOrgMemberEvent`, `RemoveOrgMemberEvent`, `JoinTeamEvent`, `ChangeOrgRoleEvent`, `ChangeOrgAllowedLoginMethodsEvent`, `ChangeOrg2FAEnforcementEvent`;
    - workspace management: `CreateWorkspaceEvent`, `DeleteWorkspaceEvent`, `ChangeWorkspacePrivacyEvent`;
    - IdP management: the SSO and SCIM events.
  - Org events appear in the org export, not in workspace exports.
- The workspace audit log: `lego/backend/internal/audit/` (`service.go`, `rest.go`, `graphql.go`).
  - `GET /v1/owners/{ownerId}/audit-logs` takes `startTime`/`endTime`/`direction`/`cursor`/`limit` (≤1000), uses `audit.FilterOf`, and floors history at `audit_visible_from` (w9/098).
  - `TestRenderEventNamesAreInThePinnedEnum` checks mapped names against the pinned enum.
  - `render_inventory_test.go` holds the workspace event inventory.
- `lego/backend/internal/api/render_operation_coverage_test.go:62` lists the operation as an omission.

## Steps

1. Store org events in their own scope: an `organization_id` on the audit row, or its own table, as t001's ADR chose. Write them from the t005–t007 verbs:
   - an org created by an upgrade: no Render event; bex records `CreateWorkspaceEvent` only for workspaces created in the org;
   - t006's create, delete, privacy and join verbs;
   - t007's invite, accept, add, remove and role verbs.
2. Mount `GET /v1/organizations/{orgId}/audit-logs`:
   - Render's `auditLogWithCursor` shape and parameters through the same `FilterOf`;
   - 403 for anyone but an Owner, 404 for an unknown org;
   - history floored at the org's `audit_visible_from`.

   Remove the omission entry.
3. GraphQL `organizationAuditLogs(organizationId, startTime, endTime, cursor, limit)` in the workspace log's dialect. Render's MCP has no audit-log tool, so bex adds none, as for workspaces.
4. Add an org inventory to `render_inventory_test.go` and `docs/render-artifacts/audit-logs-api.md`. The two login-settings events are follow-ups (t014), and the IdP events are non-goals (DO_NOT_DO SSO/SAML · SCIM).
5. Org events never appear in a workspace log, and workspace events never appear in the org log.
