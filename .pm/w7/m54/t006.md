## Objective

Close the tenant-facing parity loop by comparing bex's platform-hostname browser boundary with Render's `onrender.com` behavior and documenting any deliberate differences.

## Context

- This milestone changes no REST, GraphQL, MCP, or dashboard schema; the relevant user-facing surface is browser isolation on the shared platform domain.
- Public Suffix membership, host-only cookie behavior, Service Worker origin scope, redirects/rewrites, and custom domains are the observable contract.

## Steps

1. Capture current browser behavior for two controlled `onrender.com` sites where possible and the equivalent two `onbex.co` sites.
2. Compare parent-domain cookies, origin storage, Service Worker scope, redirects/rewrites, and custom-domain behavior.
3. Update the parity ledger and static-site ADR with evidence and explicit non-goals.
4. File any remaining divergence as a follow-up rather than silently accepting it.

## Files

- `docs/ADR018-render-parity.md`
- `docs/ADR029-static-sites.md`
- `docs/render-artifacts/`
- browser verification tests/scripts

## Acceptance criteria

- [ ] Evidence shows sibling `onbex.co` tenants have the same cookie/site boundary as sibling `onrender.com` tenants.
- [ ] Origin-local storage and Service Worker scope remain tenant-origin-specific.
- [ ] REST, GraphQL, MCP, and dashboard are explicitly confirmed unaffected.
- [ ] ADR018 and ADR029 cite reproducible evidence and record any remaining divergence.

## Out of scope

- Building Render's explicit static-site cache-purge API, which remains a documented non-goal.
