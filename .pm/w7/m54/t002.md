## Objective

Establish `onbex.co` as a browser-recognized multi-tenant public suffix so one tenant subdomain cannot inject a parent-domain cookie into sibling tenant sites.

## Context

- A site at `evil.onbex.co` can currently request `Domain=onbex.co`; host-only cookies remain unreadable, but sibling requests can receive an injected same-name cookie.
- Render's equivalent shared tenant domain, `onrender.com`, is present in the Public Suffix List.
- The dashboard and API remain on `bex.co`; this task must not move the first-party control plane onto the tenant content suffix.

## Steps

1. Prepare the upstream `publicsuffix/list` private-domain submission and required ownership/operational evidence for `onbex.co`.
2. Carry the submission through review and merge, recording the upstream reference and rollout expectations.
3. Verify with a current browser that parent-domain cookie setting is rejected and sibling tenant requests do not receive the attempted cookie.
4. Document the interim `__Host-` cookie guidance and final platform-domain contract.

## Files

- `publicsuffix/list` upstream private-domain section
- `docs/ADR029-static-sites.md`
- `docs/ADR012-auth.md`
- `scripts/`

## Acceptance criteria

- [ ] The canonical Public Suffix List contains `onbex.co` with an accepted upstream change reference.
- [ ] Chromium or Firefox rejects a tenant page's attempt to set `Domain=onbex.co`.
- [ ] An automated two-subdomain probe proves no attempted parent cookie crosses from tenant A to tenant B.
- [ ] Platform authentication remains on `bex.co`, and interim host-only/`__Host-` guidance is documented.

## Out of scope

- Moving dashboard or API origins, or introducing OAuth tokens into browser-readable storage.
