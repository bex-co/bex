## Objective

Turn the incident discussion into an evidence-backed threat model and repeatable baseline covering browser origins, Traefik/ExternalName routing, tenant and platform NetworkPolicies, static-server Kubernetes authority, and object-store credentials.

## Context

- Public requests flow through Cloudflare/Traefik to the shared `bex-system` static-server and then to a fixed S3 origin; static rewrites are object-key rewrites, not arbitrary upstream proxying.
- `providers.kubernetesIngress.allowExternalNameServices` is enabled for operator-owned maintenance and static-server aliases.
- `onrender.com` is in the Public Suffix List; `onbex.co` was absent when checked on 2026-07-28.
- `docs/ADR029-static-sites.md` currently provisions `static-s3` from the Terraform-state credential source.

## Steps

1. Document assets, trust boundaries, attacker capabilities, and explicit non-capabilities for a malicious static-site owner, tenant workload, public browser, and compromised static-server.
2. Capture non-secret production evidence for the current RBAC/NetworkPolicy/Ingress path, PSL status, and S3 permission matrix.
3. Add a repeatable verification entry point that fails clearly when any of those baseline assumptions changes.

## Acceptance criteria

- [ ] The threat model distinguishes browser-origin risk, Kubernetes routing authority, and server-side credential blast radius.
- [ ] Evidence proves no request-controlled static-site path becomes a server-side fetch to tenant ClusterIP/DNS targets.
- [ ] The baseline records exact allow/deny expectations without printing credentials, tokens, or kubeconfigs.
- [ ] A repeatable check detects drift in PSL membership, tenant alias authority, and object-store access assumptions.

## Out of scope

- Replacing namespace isolation or introducing a microVM runtime tier.
