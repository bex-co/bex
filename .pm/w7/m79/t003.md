## Objective

Tell the user when their service has no public URL and why. Today a web service created on bex gets no URL at all unless it carries a custom domain, and nothing anywhere says so — not at create, not on the service, not in the deploy.

## Context

**Corrected premise (w7/m78/t001, 2026-08-09).** This task was written believing production had a *bug* — a service that should have a route and did not. It does not. The behavior is deliberate and correct, and the defect is entirely the silence around it:

- Production runs with `BEX_BASE_DOMAIN` **unset**, a security decision recorded in three manifests (`config/manager/manager.yaml:151`, `config/api/deployment.yaml:68`, and `config/staticserver/deployment.yaml:53`, which carries an explicit `""` SSA tombstone to strip "the unsafe onbex.co value" from Deployments that previously had it). `onbex.co` is a registrable domain, so tenant JavaScript could set parent cookies a sibling tenant receives; `w7/m54` waived PSL inclusion, so this is the permanent state until a dedicated hosting suffix exists.
- With no base domain, `AppSpec.EffectiveHosts` contributes no platform host. A service with no custom domain therefore has **zero** effective hosts, and `reconcileIngress` takes its `len(hosts) == 0` branch: it deletes any stale Ingress and returns `nil`. Nothing fails, so no status reason ever names a cause.
- `w7/m78`'s reproduction (`internal/controller/tenant_namespace_routing_envtest_test.go`) pins all three cases: base domain set ⇒ routes; unset ⇒ deliberately does not; unset plus a custom domain ⇒ routes.

So the condition to report is **not** "expected a route and lost it" but "**exposed, and no public host is derivable**" — a configuration state, with an actionable cause.

Two triggers, one condition:

1. **At rest** — an exposed service with no derivable host. The user needs to know a custom domain is required.
2. **At disable time** — when `BEX_BASE_DOMAIN` was removed, the zero-host branch **deleted the public route of every service that had only a platform host**, fleet-wide and silently. Deleting is right (that was m54's point); doing it without a trace is not.

Also note the URL has two independent sources and both were empty in the incident:

- the operator writes `status.URL` only on the **Running** path (`app_controller.go:1262`), so a service that never becomes ready has none even with a working Ingress;
- bex-api's `pendingPublicURL` fallback (w5/m48 — "Render shows a service's URL from the moment it's created") depends on **bex-api's own** `BEX_BASE_DOMAIN`, which is also unset, so that compensation is inert in production.

`store/reconciler.go:952` sets `Expose: true` for every projected App, so "exposed" is the normal case and a derivable host is what varies.

## Steps

1. Compute the expectation (exposed type, effective hosts) and report a specific condition when a service is exposed but no public host is derivable.
2. Make the message name the actionable cause — the platform subdomain is unavailable, attach a custom domain — rather than a generic "no route". A condition the user cannot act on is barely better than silence.
3. Exclude the by-design cases: background workers, cron jobs, and `renderSubdomainPolicy: disabled` with no custom host (`w7/m31`) — that last one is a user's explicit choice and must stay quiet.
4. Decide whether the deletion in the zero-host branch should also emit an event, so a future platform-wide disable leaves a trace per affected service.
5. Confirm the condition clears when a custom domain is added.

## Files

- `lego/operator/internal/controller/app_controller.go` (the zero-host branch and the status write)
- `lego/backend/internal/apps/domains.go`, `lego/backend/internal/apps/service.go` (`pendingPublicURL`)
- `lego/types/v1alpha1/app_types.go` (`EffectiveHosts` — the one precedence rule)

## Acceptance criteria

- [ ] An exposed service with no derivable public host reports a specific condition naming the actionable cause.
- [ ] Workers, cron jobs, and subdomain-policy-disabled services never trip it.
- [ ] The condition clears once a custom domain makes a host derivable.
- [ ] A platform-wide disable leaves a per-service trace rather than silently unrouting the fleet.

- The operator/bex-api `BEX_BASE_DOMAIN` coherence hazard — `.pm/w7/026.md`.
