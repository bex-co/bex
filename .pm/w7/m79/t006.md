## Objective

Pin each signal with tests that assert it is specific, correct, and — equally important — silent when the dependency is satisfied.

## Context

- A reporting feature's characteristic failure is the false positive: a condition that fires during every normal rollout is worse than no condition, because users learn to ignore it. Every test here needs its negative case.
- Operator-side signals belong in envtest (`make test`); the projection to deploys/events belongs in the backend suite, whose integration tests run against real ephemeral Postgres + OpenFGA in CI.

## Steps

1. Cover t001: condition fires on an unresolvable Secret, names it, and clears on resolution.
2. Cover t001's negative: a healthy rollout never trips it, including the transient window.
3. Cover t003 and its by-design exclusions (workers, cron jobs, subdomain-policy-disabled).
4. Cover t002's projection: the reason reaches the deploy record and the event feed intact.
5. Confirm each test fails for its own reason.

## Files

- `lego/operator/internal/controller/`
- `lego/backend/internal/store/`, `lego/backend/internal/deploys/`, `lego/backend/internal/events/`

## Acceptance criteria

- [ ] Every signal has both a positive and a negative test.
- [ ] The by-design exclusions are explicitly covered.
- [ ] `make test` and `cd lego/backend && go test ./...` green.
- [ ] No tautological or snapshot-everything tests.
