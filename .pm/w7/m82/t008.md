## Objective

Pin every leg of the definition of done with tests that fail against the pre-milestone code, asserting real behavior and failure modes.

## Context

- The classification is the whole product here, so the tests must cover the **branches**, not the presence of a field.
- Anti-tautology matters: a test asserting only "a failed build produces `user_failed`" passes trivially if everything is labelled `user_failed`. Assert both directions.
- `make test` (operator, from `lego/operator/`) and `cd lego/backend && go test ./...` are the CI-enforced suites.

## Steps

1. Unit-test the exit-code table and each phase's mapping.
2. Envtest the `podFailurePolicy` branches: tenant code ⇒ one attempt; `DisruptionTarget` ⇒ retry without consuming budget; OOM ⇒ no retry; pre-deploy unchanged.
3. Test the classified outcome reaching the condition reason and the deploy record, in both the user and infra directions.
4. Test the push retry and the conditional TLS verify (HTTP path byte-identical, HTTPS path verified).
5. Confirm the headline legs are red against the pre-milestone tree.

## Files

- `lego/operator/internal/build/build_test.go`, operator envtests
- `lego/backend/internal/deploys/` tests

## Acceptance criteria

- [ ] Each DoD clause has a test that fails against the pre-milestone code.
- [ ] Both directions are asserted (a user failure is not labelled infra, and vice versa).
- [ ] No trivial, tautological, or snapshot-everything tests.
- [ ] `make test` and the backend suite are green.

## Out of scope

- Load or soak testing of the build plane.
