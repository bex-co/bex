## Objective

Give each build phase a distinct, documented exit code for "the tenant's input failed" versus its transient classes, so `podFailurePolicy` (t002) has something unambiguous to match on. Today every non-zero exit is indistinguishable: production shows `clone` exiting 128 and `buildkit` exiting 1, and nothing downstream can tell either from a node disruption.

## Context

- `lego/operator/internal/build/build.go:685-700` — the `clone` initContainer is `sh -eu -c` with our own script, so exit codes are ours to choose. Bare `git fetch` failures surface as 128 today.
- `lego/operator/internal/build/build.go:492-493` — `buildkit` runs `buildctl-daemonless.sh` directly; a Dockerfile or build-command failure exits 1. Wrapping must not turn the validated context string into a shell-interpolated argument (the comment at `:588` explains why the build was deliberately left unwrapped when signing was added).
- `lego/operator/internal/build/build.go:543` — `push` runs `skopeo` directly; `:597` — `sign` runs `cosign`.
- `lego/operator/internal/build/native.go` — the native preparer container.
- ADR060 D2 names the principle: never auto-retry a deterministic user failure, always absorb infrastructure disruption.

## Steps

1. Define the reserved code table in one place in `build.go` (constants + doc comment), covering per phase: tenant-input failure, transient/network failure, and anything else.
2. Apply it in the clone script (distinguish auth / bad-ref / not-found from network) without weakening the host-bound credential helper.
3. Apply it to buildkit, push, sign and the native preparer, keeping each container's argv structurally safe — no `sh -c` interpolation of tenant-controlled strings.
4. Set `terminationMessagePolicy: FallbackToLogsOnError` on the build containers so the failure tail is capturable for status messages.
5. Record the table in `docs/ADR060-build-worker-reliability-and-performance.md` so t002 and t003 reference one source.

## Acceptance criteria

- [ ] Every build phase exits with a code from the documented table; the table lives in exactly one place.
- [ ] A bad git ref, a failing Dockerfile, and a registry 5xx are distinguishable by exit code alone.
- [ ] No tenant-controlled string is newly interpolated into a shell command (structural check, not a comment).
- [ ] `terminationMessagePolicy: FallbackToLogsOnError` is set on the build containers.

## Out of scope

- Acting on the codes — that is t002.
- Pre-deploy Job exit codes; ADR004's zero-retry stance for pre-deploy is unchanged.
