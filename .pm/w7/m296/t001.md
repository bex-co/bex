## Objective

Expose the creator that ADR102 already records (`agent_sessions.created_by`) as `createdBy` on every session read, and fill it for older rows only where it can be derived exactly.

## Context

- Column: `lego/backend/internal/store/migrations/0212_agent_session_created_by.up.sql` (`text NOT NULL DEFAULT ''`), scanned into `store.AgentSession.CreatedBy`.
- Written at create: `agentsessions/service.go:646` (`core.SubjectFrom(ctx)`). Automation fires run as the automation's creator (`automation_scheduler.go:194`); spawns run as the parent's creator (`spawn.go:119`).
- Public model: `agentsessions/models.go:244` `View` (no creator today). GraphQL fields are in `agentsessions/graphql.go`; MCP tools in `agentsessions/mcp.go`, golden file `testdata/mcp_tools.golden.json`.
- Machine API keys have `Subject == ClientID` (`core/identity.go`), so a key-started session records the key's client id. Keep the raw subject; the dashboard labels it.
- Devin v3: each session carries `user_id`.

## Steps

1. Add `CreatedBy string` (`json:"createdBy,omitempty"`) to `View` with a doc comment, and map it wherever a `View` is built from a store row.
2. Add `createdBy` to the GraphQL `AgentSession` type and confirm MCP `get_agent_session` / `list_agent_sessions` output carries it; regenerate the MCP golden file.
3. Migration `NNNN_agent_session_created_by_backfill`: set `created_by` from `agent_automations.created_by` where the session's `created_by` is empty and `automation_id` names an automation (an automation always fired as its creator). Leave other empty rows empty: no turn records an author, so anything else would be a guess.
4. Add one line to ADR102 D9: the creator is now part of the public read model.

## Acceptance criteria

- [ ] A session created by a signed-in member returns that member's subject as `createdBy` on REST, GraphQL and MCP.
- [ ] An automation-started session returns the automation creator's subject, including rows created before 0212.
- [ ] A row with an empty `created_by` omits the field (no fabricated value).
- [ ] The MCP golden test passes with the new field.

## Out of scope

- Resolving the subject to a display name server-side (the dashboard does it from the member roster).
