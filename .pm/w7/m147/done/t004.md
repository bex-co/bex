## Objective

Serve the `uri` from t003. It authenticates with the connect token, not the caller's OAuth token, runs the bound command through the existing gateway path, and returns the SSE stream the pinned client parses.

## Context

- Client (pinned `repo.go:105-133`): sends `conn.Method` to `conn.Uri` with `Authorization: Bearer <conn.Token>`, body `{"command":…}`, and `Accept: text/event-stream`. It requires 200. Any other status goes through `errFromStreamResponse`: 401 and 403 become sentinels, otherwise it surfaces `{"message"}`.
- Because the bearer is not an OAuth token, the route must be mounted outside the auth gate. The composed mux's always-public census must classify it: `lego/backend/internal/api/alwayspublic_guard_test.go` `alwaysPublicInventory` (the deploy-hook precedent is at `server.go:1137`, and the prose inventory lives in `internal/api/CLAUDE.md`).
- Reuse `mintAndDial` or `StreamExec` (`internal/sandbox/exec.go:127-220`) so the gateway ticket, `pods/exec` confinement, and output caps stay as they are.

## Steps

1. Mount the route (for example `POST /v1/sandboxes/{sandboxId}/runs/{executionId}/stream`) outside the auth gate, behind an IP-keyed limiter that sheds load before verifying the token.
2. Verify the token: signature, expiry, sandbox and execution match, and the body command must equal the bound command. Consume it atomically and reject replay across replicas (store-backed single use, like the refresh-token idempotency cache).
3. Re-check at redeem time that the sandbox still exists in the bound workspace, then stream the exec through the existing gateway path. Every failure before the stream returns a JSON `{"message"}` body with a precise status.
4. Record the inventory entry and its credential/limiter classification.
