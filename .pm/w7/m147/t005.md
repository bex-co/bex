## Objective

Prove that the shared exec changes did not regress any other consumer of the gateway SSE stream or the sandbox route set.

## Context

- Buffered readers: `ExecBuffered` (MCP `sandbox_exec`, `internal/sandbox/mcp.go:91`), `systemBufferedExec` via `clientSuspend` (`service.go:965`; scrub-before-suspend, see `snapshot_test.go:34-75`), and the direct `bufferExec` calls in `AgentSessionLifecycle.ReadSessionStatus` (`service.go:659`) and `HibernateAgentSessionSandbox` (`service.go:796`).
- Streaming reader: legacy `POST /v1/sandboxes/{id}/exec` (`rest.go:97`) used by older Render CLIs (≤ v2.21).
- Guards: `TestScopeMatrixCoversLiveOperations`, `TestComposedMuxAlwaysPublicInventory`, and the OpenAPI boundary.

## Steps

1. Enumerate every non-test caller of `bufferExec`, `ExecBuffered`, `systemBufferedExec`, and `StreamExec`, and record the count in the milestone README.
2. For each caller, run or add a behavioral check with a non-zero exit and a terminated-target error, over both the new payload and the transitional old one.
3. Replay a v2.21-shaped `POST /exec` request (single-step) and confirm it still streams.
4. Run `cd lego/backend && go test ./...` and `make lint` from `lego/operator/`.
