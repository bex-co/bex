## Evidence (prod sweep 2026-07-17, `scripts/samples-lifecycle.sh`, api.bex.co)

All four run CLI-first (`services create`/`deploys`/`services delete`, `logs`) with
raw REST only for service suspend/resume (`POST /v1/services/{id}/suspend|resume`,
202 — the CLI has no service suspend/resume). verify-down requires 3 consecutive
non-serving checks (a single transient 502 during the suspend reconcile must not
count as "down"); verify-up asserts a unique per-run token so a cached response
can't pass.

- **hello-go** — ✅ GREEN. `srv-d9dceb3…`: deploy→build→live (~90s), served the run
  token; suspend→sustained-down (503 ×3); resume→served token again; delete→gone
  (URL 404, absent from list). Two green runs (the second on the strengthened
  verify-down).
- **hello-node** — ✅ GREEN. `srv-d9dbg96…`: built + live in ~90s (builds fine on
  Hetzner — resolves the "plausibly never built" concern); full 8 legs green.
- **hello-python** — ❌ found a real sample bug → **fixed** → needs push + re-run.
  Build succeeded, container crash-looped: `Error: Could not locate a Flask
  application` (deploy `dep-…` reached `update_failed`). `examples/hello-python/
  Dockerfile` ran `flask run` with no `FLASK_APP`/`app.py`. Fixed to
  `CMD ["python", "main.py"]` (matches the file's `__main__` block + the sibling
  samples). **Validated locally** (docker build+run: `GET /`→200 serving MESSAGE,
  `/healthz`→`ok`). Builds from `github.com/bex-co/bex` main, so the fix must land
  on origin/main (`/ship`) before the prod re-run — tracked in t005.
- **whoami** (prebuilt image) — ❌ found a real problem → **fixed** → ✅ GREEN.
  Crash-looped `listen tcp :80: bind: permission denied`: tenant pods drop ALL caps
  incl. NET_BIND_SERVICE (w7/m2, high-ports-only) + whoami ignores `$PORT` (uses
  `WHOAMI_PORT_NUMBER`) while bex routes an image service to its default 3000. Set
  `WHOAMI_PORT_NUMBER=3000` in the harness spec (and fixed `examples/whoami-app.yaml`
  to a high port) → full 8 legs green. Broader "no listening-port auto-detection"
  gap filed as `.pm/w9/011`.

Post-delete residue: verified at the API level (service absent, URL 404) for all;
pods/`reg-pull-<name>`/`app-<name>` htpasswd checks are opt-in (`RESIDUE_KUBE=1`)
and were not run (laptop kube context is not the Hetzner prod cluster). Prod
confirmed clean after the sweep (only the 3 pre-existing user resources remain).
