# `scripts/auth-oauth21-e2e.sh` fails at its trusted-client leg and leaves its servers running

Why: the script is ADR012 §7's stated end-to-end proof of the OAuth 2.1 provider (DCR, PKCE, consent, token, revoke), and it does not pass on main, so nothing currently proves those legs against a real Hydra and Kratos.

- Found by w7/m426, 2026-11-16, which added an API-key leg to the script and ran it on a throwaway kind cluster (`kind create cluster`, the CRDs from `lego/operator/config/crd/bases`, `KUBECONFIG` pointing at it).
- Leg 8 ("trusted client: PKCE authorize -> login -> HEADLESS consent -> token -> Bearer") reaches the callback with a code, and the code exchange at Hydra then answers `invalid_grant` ("The provided authorization grant … is invalid, expired, revoked, does not match the redirection URI … or was issued to another client"). Every leg after it is unreached. bex-api is not part of that call: it is curl against the script's Hydra (`oryd/hydra:v2.2.0`), after the dashboard's consent route.
- Two older breaks were fixed by w7/m426 because they stopped the script before its new leg: leg 5 asserted the advertised scopes equal three, and bex-api now advertises `bex.cloud_agents` too; and bex-api started without `BEX_REQUIRE_VERIFIED_EMAIL=0`, so the test user (this Kratos has no courier) was refused.
- The script's cleanup kills the `go run ./cmd/api` and `yarn dev` wrappers, not the bex-api binary and the Vite server they started. Both keep listening (`:8090`, `:5199`) after the script exits, and the next run finds `:8090/healthz` up and silently tests the stale bex-api.
- Production runs Hydra v26.2.0 (`deploy/gitops/base/values/hydra.values.yaml`); the script pins v2.2.0 and Kratos v1.3.1.
- Fix: find why the code exchange is refused (the redirect URI, the PKCE pair, or the consent accept), move the pins to the production versions if that is the cause, and make cleanup stop the processes it started (their process groups, or the ports' listeners).
- Done when: the script exits 0 from a clean machine twice in a row, and after it exits nothing listens on its ports.
