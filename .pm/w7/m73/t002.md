## Objective

Stop silently deploying a mutable `gen-N` tag when its digest can't be resolved. `pinBuiltImage` logs any resolution error and returns the mutable tag as a successful artifact; `gen-N` tags reset across App lifetimes and the workload lacks `imagePullPolicy: Always`, so a node may reuse a previous lifetime's cached tag (codex-security #29, low).

## Context

- `lego/operator/internal/controller/app_controller.go:509/544-549` — `pinBuiltImage` returns the mutable `image` (tag) on resolve error.
- `:553/562-568` — shared-secret path swallows Get/parse errors and proceeds anonymous.
- `lego/operator/internal/controller/pin_image_test.go:29` — locks in the fail-open behavior.
- No generated workload sets `imagePullPolicy` (grep confirms only `database_exports.go` sets PullIfNotPresent).

## Steps

1. For ModeKubernetes registry-hosted images, fail the reconcile when the digest cannot be resolved (do not fall back to the mutable tag), **or** set `imagePullPolicy: Always` on generated Deployment/CronJob pod templates so a re-pushed `gen-N` is always pulled. Pick the option that fits the dev-compat note and record the rationale.
2. Flip/remove the fail-open regression test; replace with a fail-closed assertion.
