# 033 — Status-subresource convergence: the other half of `m84`, on the CR itself

Surfaced by `w7/m84/t005`'s quality review, 2026-08-19, and measured before filing.

`m84` made a converged reconcile issue zero writes **to owned objects**. The owner's own
`status` subresource was out of its definition of done and is still written unconditionally
at several terminals:

- `keyvalue_controller.go` Ready branch — unconditional, then `RequeueAfter:
  childHealthRequeue` (30s): **≈2,880 status PUTs/day per Ready KeyValue**. That is the same
  order as the Deployment PUT m84 just removed, so this is the largest single item.
- `app_controller.go` `reconcileCronJob` — unconditional, then `RequeueAfter: time.Minute`.
  A settled cron App reaches `Running` without needing a pod: **≈1,440/day per cron App**.
- `database_controller.go` Ready branch — unconditional; not periodic, but the controller
  watches the CNPG Cluster on `ResourceVersionChangedPredicate`, so it fires on every
  Cluster status tick.

The App web/worker path is already gated (`markRunning` → `statusSettled`, and `setPhase`
skips an unchanged phase+condition), which is the pattern the rest would follow:
`AppReconciler.statusSettled` is a cached read plus `apiequality.Semantic.DeepEqual`.

**Why m84 did not just do it.** Two reasons, both worth knowing before someone picks this
up:

1. **envtest cannot judge it.** No kubelet runs there, so a rollout never becomes ready and
   the App oscillates between `setPhase`'s "Deploying" condition and `reportRolloutProgress`'s
   — two status writes per pass that are an artifact of the test environment, not of the
   product. Any test for this has to construct a genuinely settled state (fake ready pods /
   a fake StatefulSet status), which is most of the work.
2. **~30 call sites across three controllers**, and skipping a status write that a consumer
   depends on is a real bug, not a cosmetic one — bex-api's deploy gate reads exactly this
   status. This is a diff-before-write sweep with a correctness edge on every site, i.e. a
   milestone, not a cleanup.

Sizing: ~2–3h, milestone-shaped. The durable half is the same as m84's — extend
`reconcile_convergence_envtest_test.go`'s `writeRecorder` to wrap `Status()` (it currently
names this as its one exemption) once a settled fixture exists, so the invariant covers
both objects.
