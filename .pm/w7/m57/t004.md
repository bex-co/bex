## Objective

Audit the per-tenant-namespace plane (`w3/m31`, the NamespaceReconciler) for the authority and isolation questions `w3/m35 t013` did **not** cover. m35 t013 admission-confined the reconciler's dynamic namespace + `bind` authority to canonical tenant projections; this task audits the rest of the reconciler's cluster authority — the base ResourceQuota/LimitRange/default-deny NetworkPolicy contract, identity-label projection, and prune-on-workspace-delete.

## Context

- The NamespaceReconciler (control plane, `BEX_TENANT_NAMESPACES`/`BEX_TENANT_SANDBOX_NAMESPACES`) provisions `<ws>` (+ `<ws>-sandbox`) namespaces with identity labels, a base `ResourceQuota`/`LimitRange`, and a default-deny `NetworkPolicy`, and prunes them on workspace delete. It holds cluster-scoped namespace authority by necessity.
- Excluded (m35 t013-owned + verified): admission confinement proving the reconciler cannot bind a Secret role into a platform namespace, delete/relabel a platform namespace, downgrade a sandbox namespace's Pod Security labels, or install an arbitrary sandbox allow policy. Cite that evidence; do not redo the admission matrix.
- In scope here: (1) is the base per-namespace `ResourceQuota`/`LimitRange` the *sole* cap-enforcement path and correct (this is also the enforcement `w3/m34` will make unconditional — a mis-scoped quota is a real gap); (2) can prune-on-delete be triggered against or leak a non-tenant namespace, or fail to fully reclaim (orphaned quota/policy/labels); (3) are the identity labels the NetworkPolicy/quota select-on forgeable by a tenant workload such that it escapes its own default-deny or quota; (4) default-deny completeness for a freshly provisioned `<ws>` before any App lands.
- Cross-ref: `w3/m34` (retire ADR043 transitional flags) is blocked on a decision, not a defect — if this audit finds the quota path is *not* yet the sole/authoritative enforcement, that's evidence for m34's gate, filed as a cross-reference not a duplicate.

## Steps

1. Read the NamespaceReconciler provision + prune paths; confirm the ResourceQuota/LimitRange/default-deny NetworkPolicy set is complete and applied before workloads can schedule.
2. Probe prune-on-delete: can it select a non-tenant namespace, and does it fully reclaim quota/policy/labels/rolebindings (no orphans)?
3. Check whether the identity labels the quota/NetworkPolicy select on are tenant-settable on a workload (label-spoofing escape from default-deny or quota).
4. Record findings (severity + evidence) into the shared register draft for t006; cross-reference `w3/m34` for any quota-authority finding.
