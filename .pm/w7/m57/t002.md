## Objective

Adversarially audit the Stripe billing lifecycle (`w7/m50`–`m53`), the largest new attack surface in the window and the only one that both handles money and mounts an unauthenticated public endpoint. Probe the public webhook intake, the reversible enforcement/recovery paths, credential custody, and the sealed-usage outbox for confidentiality, integrity, authorization, and replay defects.

## Context

- Public route `POST /v1/webhooks/stripe` mounts **outside** the auth gate (route absent when `BEX_STRIPE_WEBHOOK_SECRET` unset); signature verification is the only gate. Confirm timestamp-tolerance/replay handling and that a bad/missing signature is rejected before any state change.
- Enforcement (`billing.KubernetesEnforcer`) suspends/recovers real Apps on payment failure — a mis-authorized or replayable enforcement transition is a tenant-impacting primitive. m52's DoD claims reversible, reorder-safe, audited controls; verify against the code, don't trust the claim.
- Secrets in play: `BEX_STRIPE_SECRET_KEY` (restricted key), `BEX_STRIPE_WEBHOOK_SECRET`, `BEX_SHELL_TICKET_SECRET`/`BEX_SANDBOX_EXEC_SECRET` are adjacent but sandbox-owned. Check no Stripe secret is logged, echoed in errors, or persisted to the control-plane DB in cleartext.
- Outbox/seal: `usage_hourly` → meter events via the `emitted_at` outbox; `BEX_STRIPE_SEAL_HOURS`/`BEX_STRIPE_EPOCH` bound rewrite/timestamp windows. Probe for a tenant being able to influence its own metered quantity, cross-workspace meter-event leakage, or a seal-window bypass that lets a row be rewritten after export.
- Owned/excluded: the operational proof (`m53`) already reconciled emitted rows against runtime in prod — cite it, don't redo it; this task is code-level adversarial review, not another reconciliation drill.

## Steps

1. Read the webhook handler end-to-end: signature verification, event dedup/idempotency, ordering assumptions; attempt a replay and an out-of-order enforcement event on paper (or with a crafted test if fast).
2. Trace every enforcement/recovery transition to its authorization + audit write; confirm no path suspends/recovers an App without both.
3. Grep the billing package for secret handling (logs, error strings, DB writes); confirm restricted-key + webhook-secret custody matches the out-of-band pattern and never lands in `audit_events`/logs.
4. Review outbox seal/export for tenant-influence on quantity, cross-workspace leakage, and post-seal rewrite; check the `BEX_STRIPE_EPOCH`/34-day clamp can't be walked.
5. Record each finding (severity + file:line/repro evidence) into the shared register draft for t006.
