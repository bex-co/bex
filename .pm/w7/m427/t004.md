## Objective

The dashboard never offers a metrics range the plan does not keep, and says which plan would extend it.

## Context

- The model: GraphQL `logRetention` and `logs.Service.LogRetention` (`lego/backend/internal/logs/service.go:628`), and the log range picker bounded by it (w9/m389 t005).
- `dashboard/src/features/metrics/lib/range.ts` lists presets up to 30d on every plan; its comment says "Render plan-gates it; bex offers it ungated". The picker is `range-select.tsx`; the datastore panel is `components/datastore-metrics-panel.tsx`.
- Render's REST API has no retention read, so REST and MCP only clamp (t003).

## Steps

1. GraphQL `metricsRetention(resource)`: the window, the plan, and the next plan with its window, mirroring `logRetention`.
2. Dashboard: presets beyond the window are disabled with the upgrade hint, and the custom range cannot start before the floor, on the service Metrics page, the Scaling page's recent metrics and the datastore metrics panel. Every locale file the metrics feature has gets the new strings.
3. Correct the comment in `range.ts`.
4. Compare pending and ready states at desktop and narrow-mobile widths.
5. Tests: the range picker per plan; the hook; the GraphQL field.
