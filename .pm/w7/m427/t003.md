## Objective

A metrics read never returns points older than the workspace plan's window (Hobby 7 days, Pro 14, Scale and Enterprise 30), on REST, GraphQL and MCP alike, because the floor is applied once in the core verbs.

## Context

- The model: `lego/backend/internal/core/plan_gate.go:148-196` (`LogRetention`, `LogFloor`) and how `lego/backend/internal/logs/service.go` applies them (w9/m389).
- Metrics core: `lego/backend/internal/metrics/service.go` (service metrics, the `BEX_MAX_QUERY_HOURS` window check), `datastore.go` (datastore metrics), `bandwidth_sources.go`; adapters `rest.go`, `graphql.go`, `mcp.go`.
- The workspace plan is read through `core.Base.Plans`. `metrics/plan_gate_test.go` already covers the latency plan gate.

## Steps

1. Add `core.MetricsRetention(plan)` beside `LogRetention`: one table, Hobby 7 days, Pro 14, Scale and Enterprise 30.
2. Clamp in the core verbs, not the adapters: a start before now minus the window moves to the floor, as log reads do; a range wholly before the floor returns empty series, not an error. Apply it to service metrics, datastore metrics, bandwidth, bandwidth-sources and filter discovery.
3. An unreadable plan follows the rule log reads use; with the store off there is no clamp.
4. Do not clamp usage and billing reads (`/v1/usage`, month-to-date bandwidth used for included-bandwidth accounting): they are billing records, not charts. Say so in ADR010.
5. Tests: each plan on REST, GraphQL and MCP; a range before the floor; datastore metrics; store off.
