# Flip unverified-invite-email default to fail-closed

**Type:** optional hardening. **Not a milestone** (prod runs the flag on; default-off is documented).

codex-security scan #26 (low): `BEX_REQUIRE_VERIFIED_INVITE_EMAIL` gates verified-email enforcement and defaults off (`lego/backend/cmd/api/main.go` ~:405). With it unset, `acceptInvites` passes the raw Kratos trait email into `AcceptInvitesForEmail` regardless of `EmailVerified` (`lego/backend/internal/api/tenancy.go:181/191`), so an attacker who registers a not-yet-signed-up invitee's address redeems the pending workspace invite without proving ownership.

**Mitigated in prod:** the flag is on (`BEX_REQUIRE_VERIFIED_INVITE_EMAIL=1`).

**Trigger to promote:** any path that ships the multi-member tenant service without the flag. Fix shape: flip the default to fail-closed — require the flag to explicitly opt *out* (e.g. `BEX_ALLOW_UNVERIFIED_INVITE_EMAIL=1`) — or refuse to start the multi-member service when the flag is unset and no verification route exists. Sub-hour → inbox.
