## Objective

Have the operator set `spec.enablePDB: false` on single-instance CloudNativePG Clusters so a zero-disruption PDB cannot pin autoscaled nodes.

## Context

- `cnpgClusterSpec` in `database_controller.go` sets `instances` but never `enablePDB`; live clusters keep CNPG default `true`.
- ADR060 D8: single-instance PDB blocks drains while protecting nothing (brief downtime either way).
- HA (≥2) must keep disruption protection.

## Steps

1. When projected `instances == 1`, set `enablePDB: false` in the Cluster spec map.
2. When HA raises instances ≥2, omit or leave default true — do not disable PDB for HA.
3. Preserve ownership/admission defaults per existing unstructured projection rules (w7/m84 / `032`).

## Files

- `lego/operator/internal/controller/database_controller.go`
- Related projection helpers if any

## Acceptance criteria

- [ ] Single-instance Clusters receive `enablePDB: false` on create/reconcile projection.
- [ ] HA Clusters are not forced to `false`.
- [ ] No whole-spec wipe of unrelated CNPG defaults.

## Out of scope

- Changing instance counts or HA plan semantics.
- KeyValue / non-CNPG PDBs.
