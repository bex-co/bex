## Objective

Record what each of Render's database and disk graphs means, which resource kinds show it, and where bex will read it from, before anything is scraped or built.

## Context

- render.com/docs/service-metrics § Disk storage and § Database activity (quoted in the milestone README).
- `docs/render-artifacts/metrics-page.md` already holds the captured service Metrics page (w5/m42, w4/m108).
- bex's sources today: CNPG's exporter (`cnpg-tenant-db` job), the Valkey exporter sidecar (`valkey-instances` job), cAdvisor, kubelet volume stats, and Loki for datastore logs (`{namespace, database=<dpg-id>}`).
- Render's REST API: the pinned OpenAPI (`lego/backend/internal/api/openapi/render-public-api-1.json`) has `/metrics/disk-usage`, `/metrics/disk-capacity`, `/metrics/active-connections` and `/metrics/replication-lag`, and none of the five new metrics.

## Steps

1. Add a section to `docs/render-artifacts/metrics-page.md`: each graph's name, Render's sentence, its unit, whether it has two series (read and written, in and out), and the kinds that show it (Postgres all five; Key Value Disk Activity; a service with a disk Disk Activity and Disk Operations).
2. For each graph, check on a live datastore pod which candidate series exist and are attributable to one datastore: the exporter's `pg_stat_database` counters for transactions; pod network counters or the exporter's own for network; per-volume read and write bytes and operation counts for the data volume; the Valkey exporter's counters for Key Value.
3. Choose one source per graph and record it, with the fallback where a source is missing for a kind.
4. Record what is not captured from Render: the graphs' resolution, and whether Transaction Volume counts commits only or commits and rollbacks. State bex's choice for each.
5. Add ADR018's Extended metrics row note, marked ◐ until t006.
