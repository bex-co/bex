## Objective

Check that the five new metrics carry the same names, units, per-bucket meaning, refusals and empty-window shape on REST, GraphQL `datastoreMetrics` and MCP `get_datastore_metrics`, that the dashboard's graph names and applicability match Render's Metrics page, and that the REST and MCP names are recorded as bex extensions.

## Outcome (2026-11-16)

- REST, GraphQL and MCP reach the five metrics through one verb, so names map one to one (REST kebab case, GraphQL upper case, MCP the snake-case id), units, per-bucket values, the `direction` label, refusals and the empty-window `[]` are identical; `TestActivityMetricsAgreeAcrossSurfaces` asserts it.
- Against Render: the dashboard uses Render's five graph names and shows each on the kinds Render's page does. Render publishes no REST path or MCP metric type for any of them (pinned OpenAPI `/metrics/*`, Render MCP `get_metrics` types), so the REST and MCP names are bex extensions, recorded in ADR010, ADR018 and the contract. Render's open points and bex's choices are in `docs/render-artifacts/metrics-page.md`; Disk Activity on a Free Key Value is a recorded divergence (bex's Free Key Value has a disk).
- Drift filed: w7/072 (`.pm/w7/072.md`), the datastore panels read a fixed hour with no range picker (pre-existing, now carrying these graphs).
