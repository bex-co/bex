# w7/011 — Namespace prune keys on config state, not workspace existence

**Source:** w7/m57 audit (ADR045 Finding 6), 2026-07-30. **Severity:** low.

With `BEX_TENANT_SANDBOX_NAMESPACES` off, `NamespaceReconciler.ReconcileOnce` omits `<ws>-sandbox` from the desired set, so `pruneOrphans` (`lego/backend/internal/store/namespaces.go:282-302`) deletes a still-live `<ws>-sandbox` namespace (and its running sandboxes) for an existing workspace — prune keys on the `Sandboxes` config toggle rather than workspace existence. Not cross-tenant; an operator flipping the flag off (or a rollback) reaps live sandbox namespaces.

**Fix when picked up:** gate `<ws>-sandbox` prune on workspace existence (only reap when the workspace is gone, regardless of the toggle), or treat the toggle as create-only. Low: the flag is operator-controlled and monotonic in practice.
