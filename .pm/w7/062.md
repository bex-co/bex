# SessionLimiter/ChannelLimiter: an unmatched Release is a no-op

Why: one stray `Release`/`ReleaseChannel` permanently raises the gateway-wide session or channel cap by one until the process restarts, and the sibling `SourceLimiter` already guards against it.

**Source:** `/code-review` of the closed PR #138 (2026-11-11, finding 3), scoped by `/pm-brainstorm for w7` 2026-11-13. Board revision `6b4a66748`.

**Evidence:**

- `lego/backend/internal/sshgateway/limiter.go`: `SessionLimiter.Release` and `ChannelLimiter.ReleaseChannel` both run `l.global--; l.perIdentity[subject]--` unconditionally and delete the entry only when it equals exactly `0`. `SourceLimiter.Release` in the same file deletes on `<= 0`.
- An unbalanced release for a subject with no held slot drives `global` to `-1` and stores `perIdentity[subject] = -1`. That entry is never deleted, and `Acquire`'s `global >= maxSessions` check then admits `maxSessions + 1` until restart.
- Every current caller is balanced, so this is latent hardening, not a live incident: `nativessh/server.go` (`defer s.Limits.Release`, and `ReleaseChannel` on the `Accept` error path and after `serveSession`), `webshell`, `sandboxsse`, `agentattach`, `sandboxfiles`, `modelproxy`/`egressproxy` (`defer limiter.Release(sourceIP)`) and `agentcred` (`sync.OnceFunc`).

**Fix (~30m):**

1. In both `Release` and `ReleaseChannel`, look up `l.perIdentity[subject]`. If the subject holds no slot, return without touching `global`. Otherwise decrement `global` and the entry, and delete the entry once it reaches `0`.
2. `limiter_test.go`: a `Release`/`ReleaseChannel` with no prior acquire leaves both caps intact. At `max` global slots, the next `Acquire` is still refused with `"global"` / `"channel_global"`, and the identity scope likewise.

**Acceptance:** the new test fails on the current code and passes with the fix; `go test ./internal/sshgateway/...` and `make lint` pass.

**Out of scope:** a duplicate release while the subject still holds another slot cannot be told apart without per-acquire tokens, so it is not addressed here. Merging the two limiter bodies into one was rejected with PR #138. Render parity does not apply: this is gateway-internal and changes no REST, GraphQL, MCP or UI surface.
