# Secret scanning in CI (gitleaks over pushed diffs/history)

Add a gitleaks (or trufflehog) step to `.github/workflows/deploy.yml` scanning the pushed diff/history for accidentally committed credentials. Warn-first on the initial baseline run, then tighten to fail-on-high-confidence-hit once tuned (same caution `w7/001` already applies to trivy severity) — an untuned scanner blocking every push on false positives is worse than not having one. Sub-hour.

Distinct from `w7/001` (image CVE scanning) and `w1/006` (Dependabot dependency CVEs) — this catches secrets in the repo itself, not vulnerabilities in built artifacts or dependencies.

**Not doing (withdrawn 2026-07-10):** image signing (cosign) + SBOM generation, originally proposed alongside this as one milestone. Withdrawn on review: signing without an admission-time verification gate (Kyverno/Sigstore policy-controller — a materially bigger, riskier lift, deferred for the same "not needed pre-GA" reason `w7`'s microVM entry is deferred) produces inert artifacts nobody's forced to check, and keyless signing would add a new external Sigstore/Fulcio/Rekor dependency into the deploy critical path (`deploy.yml` doesn't even carry `id-token: write` today). Revisit signing+SBOM together with enforcement, not before.
