## Objective

Give the gate a fact to read. Every principal the 2FA gate already resolves must also say whether it was signed in with Google.

## Context

- `lego/backend/internal/core/identity.go`: `Identity` has `Method` (`session`, `oauth2`, gateway tickets) but no sign-in method.
- Kratos's `/sessions/whoami` returns `authentication_methods`. bex-api resolves dashboard sessions through it.
- Human OAuth tokens (`bex login`, MCP clients) come from Hydra, through bex's Kratos login-challenge bridge (ADR012 §7). Hydra's accept-login body takes `amr`, which then appears in the token's claims.
- An API key is a Hydra client with a created-by stamp (`twofactor.KeyCreators`). SSH keys are stored per user.

## Steps

1. Add the sign-in method to `core.Identity`, filled from the Kratos session on the session path. Make it a closed value such as `password` or `oidc:google`, never free text.
2. Pass it through the login-challenge bridge as Hydra `amr`, and read it back on the OAuth path.
3. When an API key is created, stamp whether its creator was signed in with Google, next to the created-by stamp. Do the same for SSH keys. Keys that existed before follow t001's exemption rule.
4. Keep background identities (agent sessions, automation) honest. They act as the member who started them, so record what that member's sign-in was when they started, or refuse them as t001 decides.

## Files

- `lego/backend/internal/core/identity.go`, the session and OAuth middleware, the login-challenge bridge, the API key and SSH key stores, and a migration if a key stamp needs a column

## Acceptance criteria

- [x] Unit tests show a password session, a Google session, a token minted from each, and keys created from each carrying the right value.
- [x] A key created before this change reads as t001 says.

## Out of scope

- Refusing anything. That is t005.

## Result (2026-11-17)

- `core.SignIn` is the closed vocabulary (`oidc:google`, `oidc:github`, `password`, `other`, unrecorded), parsed only by `core.ParseSignIn` and `core.SignInFromKratos`; `core.Identity.SignIn` carries it.
- Sessions: `api/auth.go` whoami reads Kratos's `authentication_methods` (probed on Kratos v26.2.0: `{method: oidc, provider: google}`). Tokens: introspection reads `ext.bex_sign_in` for a human token only; the dashboard's consent acceptor stamps it (t007's dashboard work), and the fresh-bearer revalidation compares it. Keys: `bex.co/created-sign-in` on the Hydra client beside `bex.co/created-by` (`apikeys.KeyCreator` returns it), and `ssh_keys.created_sign_in` (migration 0294), both written from `core.KeySignInStamp`, which never stamps unrecorded.
- Background identities (automations, PR feedback, spawned children, queued messages) and gateway tickets keep an unrecorded sign-in; the gate decides them by the member's linked Google account (ADR012 §9b).
- Tests: `core/signin_test.go`, `api/auth_sign_in_test.go` (password, Google, GitHub, code and empty sessions; Google, pre-stamp and garbled human tokens; a machine token's ext ignored), `apikeys` (stamp on create, read back by `KeyCreator`, a garbled stamp reads `other`), `sshkeys` (stamp on create), `store` (`TestPGSSHKeyCreatedSignIn`, a pre-column key reads unrecorded). On dev-7 a password session's API key and SSH key were stamped `password`.
