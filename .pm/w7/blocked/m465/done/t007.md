## Objective

Give admins the switch and members a way out, mirroring the 2FA half screen for screen.

## Context

- `dashboard/src/features/workspaces/components/workspace-two-factor-card.tsx` and `hooks/use-set-workspace-require-two-factor.ts` are the 2FA switch, with its plan notice and Change plan link below Pro.
- The 2FA blocked page offers a link to enroll, a workspace switcher and a leave button. The member row shows "2FA required, not enabled".
- Skeletons must match the ready state (root `AGENTS.md` rule; `dashboard/AGENTS.md`).

## Steps

1. Add a "Require Google login" card beside the 2FA card, using the same plan notice, admin-only switch and lock-out error text.
2. Handle `WORKSPACE_GOOGLE_LOGIN_REQUIRED` with a blocked page that offers "Sign in with Google" (a fresh Kratos login with the `google` provider), the workspace switcher and leave.
3. Show a member row status for a member whose last sign-in was not Google, if t003's data supports it. Otherwise record why it is left out.
4. Update the GraphQL documents and generated types, and add translations for every locale.

## Result (2026-11-17)

- **The card.** One card serves both settings, driven by a table (`features/workspaces/lib/login-requirements.ts`: copy keys, refusal codes, which field it reads) and one mutation hook (`hooks/use-set-workspace-login-requirement.ts`), replacing `workspace-two-factor-card.tsx` and `use-set-workspace-require-two-factor.ts`. "Google login" sits after "Two-factor authentication" in Workspace Settings, its navigation and its loading skeleton (`workspace-login-requirement-card.tsx`, `…-skeleton.tsx`). Below Pro both cards show the plan notice and, to an admin, Change plan; `WORKSPACE_GOOGLE_LOGIN_ADMIN_NOT_SIGNED_IN` offers "Sign in with Google", and `WORKSPACE_GOOGLE_LOGIN_UNAVAILABLE` and `PLAN_FEATURE_REQUIRED` have their own text.
- **The blocked page.** The Apollo auth error link reports both refusal codes with the requirement each names; the block store maps a workspace to the latest one, so after a Google sign-in the 2FA page takes over if 2FA is still missing. `workspace-login-gate.tsx` picks the page; both pages share a frame, the workspace switcher and leave, each with a matching skeleton; account settings and new workspace stay reachable. "Sign in with Google" (`features/auth/lib/google-sign-in.ts`) links Google through Kratos's settings flow when it is not linked yet (which, probed on Kratos v26.2.0, adds the Google sign-in to the session at once) and otherwise signs in again through a refresh login with the `google` provider, returning to the page.
- **Member status: left out.** bex does not record a member's last sign-in method: the gate reads each request's own sign-in, and the per-member fact it reads (a linked Google account matching the email) would say "can sign in with Google", not "signed in with Google". A row status built on it would mislead, so there is none (ADR012 §9b).
- **Account settings, login and sign-up.** Ory Elements draws the Google logo from the provider id; the label comes from Kratos (`label: Google` in the fragment, t002), so the button reads "Sign in with Google" in every locale's template. Kratos's settings-guard refusals (4100001 on the email field, 4100002 on the form) are shown in the member's language with the workspaces listed (`common/lib/ory/ory-message-text.ts`, the `Message.Content` and toast overrides).
- **OAuth consent.** Every accept now stamps `session.access_token.bex_sign_in` from the consenting browser session's `authentication_methods` (the headless path asks Kratos too), and leaves it out with no session, another identity's, or a failed whoami (`common/server-fn/hydra-consent.ts`); bex-api reads it (t003).
- **Translations** for every new string in all 8 locales. `yarn lint` and `yarn test` pass (758 files, 9041 tests).
- **Pending and ready states:** compared in code and shape tests, not visually: the Playwright MCP server did not connect, so no browser was available. The card skeleton uses the ready card's classes and copy with no breakpoint-specific classes; below Pro it previews the plan notice (an admin's Change plan link is not previewed, at most one line at narrow width). The blocked-page skeletons keep the frame, header, regions and the picker's `w-full sm:w-72`.
