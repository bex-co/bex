## Objective

Check that the requirement behaves the same on GraphQL (the setting), REST, GraphQL and MCP (the refusals), the SSH gateway and the dashboard: the same codes, details and exempt reads. Compare it with Render's documented behavior, and file any drift as a follow-up.

## Result (2026-11-17)

Walked on `dev-7` (bex-api built from this tree, Kratos v26.2.0, Hydra, the dev-7 Postgres) as one member signed in with a password, with an API key and an SSH key added in that session:

- **Setting (GraphQL).** On Hobby, `setWorkspaceRequireGoogleLogin` answered 400 `PLAN_FEATURE_REQUIRED` (`feature` `googleLoginEnforcement`, `requiredPlan` `pro`). On Pro (plan set in the database), it answered 409 `WORKSPACE_GOOGLE_LOGIN_ADMIN_NOT_SIGNED_IN`: the lock-out guard read the real session's `password` method. Nobody can sign in with Google on dev-7 (no provider), so the requirement was then turned on in the database.
- **Stamps.** The API key's Hydra client carried `bex.co/created-sign-in: password` and the SSH key's row `created_sign_in = password`.
- **Refusals.** Once the 60 s settings cache passed, the password session and the API key each got `403 WORKSPACE_GOOGLE_LOGIN_REQUIRED` with the workspace id on REST (`GET /v1/services?ownerId=`), GraphQL (`services`, `extensions.workspaceId`) and MCP (`list_services`, `WORKSPACE_GOOGLE_LOGIN_REQUIRED:` prefix): the member's message says to sign in with Google, the key's to create a new key. The body has the 2FA refusal's shape (`code`, `error`, `id`, `message`, `params.workspaceId`), from the same constructor.
- **Exempt reads.** `GET /v1/owners`, `GET /v1/users`, GraphQL `workspaces { requireGoogleLogin }` (true) and MCP `list_workspaces` answered.
- **SSH gateway.** dev-7 runs no gateway; native SSH (a real handshake with a password-stamped key refused with the Google banner, a Google-stamped key admitted) and the verb are pinned by `nativessh`, `sshgateway` and `agentsession` tests.
- **Kratos.** The settings guard and Google sign-in were walked on Kratos v26.2.0 in `scripts/auth-oidc-e2e.sh` (t002, t006), not on dev-7.
- **Dashboard.** The card, blocked page and settings refusals are t007's; no browser was available here (the Playwright MCP server did not connect), so their look was checked in code and tests only.

Compared with Render's page ([render-artifacts/login-settings.md](../../../../../docs/render-artifacts/login-settings.md)), filed:

- [w7/084](../../../done/084.md): GitLab and Bitbucket sign-in, Render's other two providers.
- [w7/085](../../../done/085.md): a member of an enforcing workspace cannot unlink GitHub either (Kratos's hook cannot tell which provider an unlink removes); Render refuses only disconnecting Google.

No other drift: the codes and wording are bex's own (Render documents none), and REST and MCP have no setting mutation, as for 2FA.
