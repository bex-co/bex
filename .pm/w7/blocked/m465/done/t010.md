## Result (2026-11-17)

`/simplify` ran over the backend and scripts diff, and the same three lenses (reuse, quality, efficiency) over the dashboard diff.

Applied:

- **Gate:** the Google check's three principal kinds share one account-lookup tail instead of three copies (`twofactor.Gate.checkGoogle`).
- **Mutations:** the 2FA and Google settings share one body (`workspaces.Service.setLoginRequirement`, driven by a `loginSetting` table); each exported verb keeps its own authorization so the audit verb stays its own.
- **Kratos reader:** one UUID-gated admin read (`humanIdentity`) serves `MFAEnrolled`, `GoogleAccountMatches` and `SettingsFacts`.
- **SSH verb:** one `ErrForbidden` case maps the refusal code; the Google messages are inlined like the 2FA ones.
- **Dashboard:** one card, hook and settings table for both requirements; one blocked-page frame; `conjunctionList` shared by the plan dialog and the settings-guard text; the SDK's `isUiNodeInputAttributes` instead of a hand-written cast; `useOryMessageText` returns the string; `consentSignIn` is a pure function; a one-line component folded; comments that only named tasks removed. The dashboard's own provider relabel was dropped once Kratos's config labels the providers (t002).

Declined, with reason:

- Reading the workspace name through `Tenant.Label()` instead of SQL `COALESCE` in `GoogleLoginWorkspaces`: the member-kind sweep only sees a literal that holds both `SELECT` and `tenant_members`, so the query stays one literal.
- Sharing `withReturnTo` with `useOryFlow`'s retry, one list for the Workspace Settings sections, the card rendering its skeleton's header, merging the two blocked-page skeletons further, importing Ory's `DefaultMessage` (unresolvable under vitest), a parallel consent whoami, removing the gate's clear-on-exempt-path effect: each costs more than it saves, as the dashboard pass recorded.
