## Objective

Prove the definition of done on production, once a platform image pin carries the milestone's commits.

## Context

- Production needs a Google OAuth client in bex's Google Cloud project, with the redirect URI `https://auth.bex.co/self-service/methods/oidc/callback/google`. Its id and secret go into `.env` as `BEX_GOOGLE_OIDC_CLIENT_ID` and `BEX_GOOGLE_OIDC_CLIENT_SECRET`, and are applied by `scripts/auth-secrets.sh` and a Kratos rollout. If they are still missing, this task is the milestone's gate. Name exactly that step and who owns it.
- Sign in as the QA user with `bash scripts/qa-login.sh`. A Google sign-in needs a Google account, so record which one the walk used, never its password.

## Steps

1. Check that the newest "pin platform images to" commit on main carries the milestone (`git merge-base --is-ancestor`), and that the login page offers Google.
2. On a Pro fixture workspace, turn the requirement on as an admin signed in with Google. Show that a Hobby workspace is refused with `PLAN_FEATURE_REQUIRED`.
3. As a member signed in with a password, show the coded 403 on a REST route, a GraphQL query, an MCP tool and an SSH session. Show the blocked page in the dashboard. Then sign in with Google and show access returns within the cache bound.
4. Show that an API key created in the password session is refused and one created in the Google session works.
5. Show that the email change and the Google unlink are refused, and that both are allowed again after leaving the workspace.
6. Read `ChangeTeamAllowedLoginMethodsEvent` on `GET /v1/owners/{ownerId}/audit-logs`. Then turn the setting off, delete the fixture and its keys, and record the result here.

## Gate (2026-11-17)

Blocked on two steps, the first the user's:

1. **Production's Google OAuth client.** `.env` has no `BEX_GOOGLE_OIDC_CLIENT_ID` or `BEX_GOOGLE_OIDC_CLIENT_SECRET`, and a Web-application OAuth client with a redirect URI can only be created in the Google Cloud console (gcloud creates only IAP clients). Someone with access to bex's Google Cloud project creates an OAuth client ID of type "Web application" (APIs & Services → Credentials, with the OAuth consent screen published for external users), authorized redirect URI `https://auth.bex.co/self-service/methods/oidc/callback/google`, puts the pair in `.env` and runs `scripts/gh-secrets.sh`. The next deploy's `scripts/auth-secrets.sh` enables the provider; `KUBECONFIG=… bash scripts/auth-oidc-verify.sh` then lists `github google` and the settings guard.
2. **A production pin carrying the milestone** (clears by itself): `git merge-base --is-ancestor <the m465 commit> <the sha in the newest "pin platform images to" commit on main>`.

The walk also needs a Google account whose email is a bex account's email, as Render requires; record which account it used, never its password.
