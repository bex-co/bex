## Objective

Once production's image pin carries the milestone, walk an org's whole life on production and check that the migration backfilled the existing Scale and Enterprise workspaces.

## Context

- Production pin: the newest "pin platform images to" commit on main. Check `git merge-base --is-ancestor <the milestone's last commit> <that pin's sha>`.
- Sign in as the QA user with `bash scripts/qa-login.sh` (never read the credentials), following `.claude/skills/qa-find-bugs/SKILL.md`. Read-only database checks go through `scripts/fetch-app-kubeconfig.sh` (root `AGENTS.md`).
- A Scale upgrade needs a payment method on the fixture (`RequirePlanBilling`). Use the Stripe test-mode path the earlier plan walks used (w7/m429, `scripts/stripe-billing-prod-test-fixtures.sh`), or a workspace already on Scale that the QA user administers.

## Steps

1. Read-only: every Scale and Enterprise workspace on production is the primary of an org, and the admin who held two or more has two orgs.
2. On a fixture:
   - upgrade to Scale, which creates the org with the QA user as Owner;
   - create a Public and an Invite-only secondary;
   - invite a second account as Member, which joins the Public workspace and is refused on the Invite-only one;
   - invite a Guest to one workspace;
   - read the org log on REST, GraphQL and the CSV export (the same rows), and get 403 as the Member;
   - try to downgrade, which is refused with each precondition named;
   - clear the preconditions and downgrade, which deletes the org and leaves the primary standalone.
3. Delete the fixtures. Record the result, the pin and the check commands in this task; no evidence files.

## Acceptance criteria

- [ ] Every step's observed result is written here with the pin it ran on. Each failure is fixed in this milestone or filed with its id.
- [ ] The fixtures are deleted.

## Out of scope

- Moving the production admin's two workspaces into one org. That is the support path (t006), run only on that customer's request.
