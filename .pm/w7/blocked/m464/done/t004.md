## Objective

Let a caller see the orgs they belong to and what each one holds. The read is the same on GraphQL and MCP. REST keeps Render's shapes, because Render's public API has no org read besides the audit log.

## Context

- GraphQL: `lego/backend/internal/workspaces/graphql.go` (`workspaces`, `workspace` and the `workspaceType` object at :38).
- MCP: `lego/backend/internal/workspaces/mcp.go` (`list_workspaces`, `get_workspace_limits`).
- REST: `GET /v1/owners` and `GET /v1/owners/{ownerId}` (`workspaces/rest.go`) return Render's `owner` schema, which has no org field. Leave them unchanged, and keep them validating against the pinned spec.

## Steps

1. Add an org verb in `internal/workspaces`, or in a new `internal/organizations` package if that keeps the import DAG cleaner. It lists the caller's orgs and reads one, gated by `can_view_org`. A Guest sees only their own workspace.
2. GraphQL:
   - `organizations` and `organization(id)` with `id`, `name`, `plan`, `primaryWorkspace`, `viewerRole`, `workspaces { id name privacy primary viewerIsMember }` and `members` (paged; Owners and Members see members, a Guest does not);
   - on `Workspace`, `organization { id name }`, `primary` and `privacy`.
3. MCP: `list_workspaces` carries `organizationId` and `primary`. Add `list_organizations` and `get_organization` with the same fields as GraphQL.
4. Give one named error code for an unknown or unreadable org on both surfaces.
