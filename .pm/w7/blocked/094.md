# A non-admin's Workspace Settings pending frame draws the Admin's Inbound IP Rules editor and Save rows, so every card below lands up to 432 px lower than on the ready page

Why: the root `AGENTS.md` skeleton rule asks the pending frame to match the ready page at the same width. For a workspace Developer or Viewer, the frame draws the Admin's editors, and the page then jumps when it lands.

- **Found by:** w7/089's production walk, 2026-11-19 (pin `4b2cebd0bd03`). Fixture: a Developer of a Public Scale org secondary (since deleted). The Workspace Settings route chunk `_assets/workspace.settings-*.js` was held from the page load, and Settings was clicked in the sidebar from `/`. The frame was read 1.5 s in, then the ready page after release.
- **Observed, 1440** (section `@y+height`, pending against ready):
  - **Overlapping Deploy Policy** `@513+278` against `+266`. Pending has a Save bar where ready has "Only workspace Admins can change this policy."
  - **Inbound IP Rules** `+458` against `+186`. Pending has the editor: the hint, two seeded rows, the add row and Add source / Cancel / Save rules. Ready has only "Only workspace Admins can change these rules."
  - **Two-factor** `@1297` against `@1013`. Same height; it is pushed down by the cards above. Its control is already right (w7/089).
  - **Team** `+273` against `+326`. Pending has an Invite button and one member row; ready has no Invite and two rows with "2 seats used".
  - **Notifications** `+717` against `+761`. Pending has no "Only workspace admins can change these defaults." line.
  - **Agents** `+2500` against `+2528`. Pending has no "Only workspace admins can change agent settings." line.
  - **Danger zone** `@6928` against `@5402`.
- **Observed, 390:** the same pattern. Inbound IP Rules is `+686` against `+266`, and Two-factor is `@1866` against `@1434`.
- **Cause:** `dashboard/src/common/components/route-skeletons.tsx:1472-1509` (`WorkspaceSettingsSkeletonSections`) draws `OverlappingDeployPolicyCardSkeleton`, `WorkspaceIPRulesCardSkeleton`, `TeamPanelSkeleton`, `WorkspaceNotificationsCardSkeleton` and the agent cards with their Admin defaults for every caller. The first two already take `canManage` (and `belowScale` for IP rules: `workspace-ip-rules-card-skeleton.tsx:63`, `overlapping-deploy-policy-card-skeleton.tsx:67`), and the cards' own inline loading passes it (`overlapping-deploy-policy-card.tsx:45`, `workspace-ip-rules-card.tsx:74`). The route frame never does. Its comment says the role is not known yet, which holds for a cold load but not for an in-app navigation. `useWorkspaceSettingsSkeletonSections` already knows the role for its 2FA and Google login cards (`capabilities` loaded and not `canManage`, w7/089).
- **Fix:** when `useWorkspaceSettingsSkeletonSections` knows the caller cannot manage the loaded workspace, pass that to every role-dependent card skeleton:
  - the Admin-only note in place of Save (Overlapping Deploy Policy) and of the editor (Inbound IP Rules, with `belowScale` from the plan);
  - Team without Invite;
  - the Admin-only lines in Notifications and Agents.
  - An Admin and an unknown role keep today's frame.
- **Done when:**
  - A route-skeleton test compares pending against ready for a Developer (each card's kind and its note) and for an Admin.
  - On production at 1440 and 390, a non-admin's held Settings frame places every section at its ready y, within the Team table's member-count difference, which needs its own bound if it is not already reserved.
  - ~1h.

## Fixed in code, 2026-11-19 (parked for its production check)

- **Fix.** `useWorkspaceSettingsSkeletonSections` returns `canManage`: what capabilities say, or null while they are checking. It also returns `belowScale` from the workspace's plan. `WorkspaceSettingsSkeletonSections` draws each role-dependent card as the ready page draws it for that caller:
  - Overlapping Deploy Policy: the Admin-only note in place of Save, held as its own text so it wraps as the ready one does.
  - Inbound IP Rules: the read-only view with the Admin-only note, and the plan notice below Scale. Below Scale this is an Admin's frame too, as the card's own loading already drew it.
  - Team: no Invite, and the caller's own role as text.
  - Notifications and Agent environment: the Admin-only line. Their cards' own loading frames draw it too.
  - Agent secrets, Repository environments and Agent skills: only that caller's help line. While the role is unknown, both lines share one cell, as before (`AgentHelpLineSkeleton`).
  - An Admin and an unknown role keep the Admin's frame.
- **Audit Logs, the bulk of the 1526 px.** The workspace list's `role` is "admin" for every member (`lego/backend/internal/workspaces/service.go`, `view(t, "admin")`).
