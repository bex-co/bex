## Objective

Clear datastore environment references when environments are deleted and project references when projects are deleted. Design interruption and retry handling before changing teardown order.

## Context

## Acceptance criteria

- [x] Environment deletion preserves valid parent-project membership.
- [x] Project deletion leaves surviving datastores unassigned.
- [x] Interrupted cleanup can be retried without clearing a concurrent valid reassignment.

## Out of scope

No datastore deletion, ownership transfer, new grouping API, automatic foreign-resource adoption, or broad architecture refactor.

## Completion evidence — 2026-09-21

Environment teardown conditionally clears datastore environment membership and inherited rules while preserving project membership. Project deletion also clears every matching datastore project, including members with no environment, before deleting the row. Expected-id compare-and-clear seams plus resourceVersion preconditions preserve reassignment between listing and mutation. Failure leaves the grouping row available for retry; earlier successful member changes may remain because this is not a distributed transaction. Real CR regressions cover both kinds, failures, retries, authorization and interleaved reassignment.
