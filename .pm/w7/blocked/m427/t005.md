## Objective

Prove on production that a Hobby workspace sees 7 days of metrics and a Scale workspace sees more, once the store holds more than 7 days.

## Context

- Before t002 the store held three days, so nothing older exists at rollout. The check is possible eight days after the rollout time recorded in the milestone README.
- w9/m389 t006 ran the same kind of check for logs on a Hobby and a Scale workspace as the QA user.

## Steps

1. Until eight days have passed since t002's rollout, park the milestone in `blocked/` with that date named. No user action is needed.
2. On a Hobby workspace and a Scale workspace, pick a service that has run since the rollout. Read CPU with a start 14 days back through REST `/v1/metrics/cpu`, GraphQL `metrics`, MCP `get_metrics` and the dashboard's 14d preset (disabled on Hobby, so use the API there).
3. Hobby: the first point is no older than 7 days. Scale: the series starts at about the rollout time.
4. Check the store reports a 30-day retention and the fill alert is healthy.
5. Record the evidence in the milestone README, update ADR018's row for the windows observed, and file a dated inbox note in w7 for the 30-day check (rollout time plus 30 days).
