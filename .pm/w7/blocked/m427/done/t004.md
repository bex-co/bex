## Objective

The dashboard never offers a metrics range the plan does not keep, and says which plan would extend it.

## Context

- The model: GraphQL `logRetention` and `logs.Service.LogRetention` (`lego/backend/internal/logs/service.go:628`), and the log range picker bounded by it (w9/m389 t005).
- `dashboard/src/features/metrics/lib/range.ts` lists presets up to 30d on every plan; its comment says "Render plan-gates it; bex offers it ungated". The picker is `range-select.tsx`; the datastore panel is `components/datastore-metrics-panel.tsx`.
- Render's REST API has no retention read, so REST and MCP only clamp (t003).

## Steps

1. GraphQL `metricsRetention(resource)`: the window, the plan, and the next plan with its window, mirroring `logRetention`.
2. Dashboard: presets beyond the window are disabled with the upgrade hint, and the custom range cannot start before the floor, on the service Metrics page, the Scaling page's recent metrics and the datastore metrics panel. Every locale file the metrics feature has gets the new strings.
3. Correct the comment in `range.ts`.
4. Compare pending and ready states at desktop and narrow-mobile widths.
5. Tests: the range picker per plan; the hook; the GraphQL field.

## Files

- `lego/backend/internal/metrics/graphql.go`, `service.go`
- `dashboard/src/features/metrics/`

## Acceptance criteria

- [ ] On Hobby the 14d and 30d presets are disabled with a hint naming Pro and Scale; on Pro only 30d is; on Scale none is.
- [ ] A custom range cannot start before the plan's floor.
- [ ] `yarn lint` and `yarn test` pass in `dashboard/`.

## Out of scope

- The mobile app (it reads short snapshots only).

**Done 2026-11-16 (`ee88c6a4a` the GraphQL field, `781c66f31` the dashboard):** GraphQL `metricsRetention(resource)` answers the plan, its days and `upgrades`, each longer window with the cheapest plan that has it; null where no plan applies. The Metrics page's range picker (`MetricsFilters`, through `useMetricsRetentionBound`) disables the presets wider than the window, refuses a custom start before the floor and shows the hint. All eight locales carry the strings. `range.ts`'s comment no longer says bex offers every range ungated.

- **Deviation from step 1.** `logRetention` names one next plan (`upgradePlan`, `upgradeDays`). This task's acceptance asks for a Hobby hint naming Pro and Scale, so `metricsRetention` returns a list and the hint reads "Metrics are kept for 7 days on the Hobby plan. The Pro plan keeps 14 days. The Scale plan keeps 30 days."
- **Only the Metrics page has a picker.** The Scaling page's Recent Metrics reads a fixed 48 hours and the datastore metrics panel reads the default hour; both lie inside every plan's window, so there is nothing to bound on them.
- **A range already in the URL is not rewritten.** A `?range=30d` link opened on Hobby keeps its label and charts the seven days the server returns, as the Logs page does.
- **Step 4, not walked in a browser.** The bound changes only the items inside the open dropdown; the trigger and the page render the same before and after the retention read, so no pending state changed shape. The local mock cluster was down, so there was no browser walk here; t005 walks the picker on production.
