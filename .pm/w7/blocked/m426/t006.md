## Objective

Once the production pin carries t002–t004, prove definition-of-done items 1–5 on production with one owned key, and record the evidence.

## Context

- The definition of done in `.pm/w7/m426/README.md`.
- Render's Terraform provider reads `RENDER_HOST`, `RENDER_API_KEY` and `RENDER_OWNER_ID` from the environment (`render-oss/terraform-provider-render`, `internal/provider/provider.go`).
- The pinned Render CLI version is recorded in `docs/cli-compatibility-checklist.md`.

## Steps

1. Confirm the newest `pin platform images to <sha>` commit on main contains this milestone's commits. If not, park the milestone in `blocked/` with that release gate named.
2. As the QA user in `bex-canary`, mint a key. Call REST `GET /v1/services`, a GraphQL query and an MCP `tools/call` with the key as the bearer.
3. Run the unmodified `render` CLI at the pinned version with `RENDER_HOST=https://api.bex.co/v1` and `RENDER_API_KEY=<key>`: `services list -o json`.
4. Run Terraform with the `render-oss/render` provider, `RENDER_HOST`, `RENDER_API_KEY` and `RENDER_OWNER_ID`, and a configuration holding one data source for an existing canary service. `terraform plan` must succeed. Record the provider version. File any wire error the provider reports as a follow-up note through `/pm`; do not fix it here.
5. Exchange the same key's id and secret at the token endpoint and call the API with the token.
6. Send a wrong secret repeatedly: the same 401, then 429. Revoke the key: every surface answers 401 within the stated window.
7. Record timestamps, the pin and the status codes in the milestone README, with no key material. Update ADR018's API-key row from ◐ to its final wording.
