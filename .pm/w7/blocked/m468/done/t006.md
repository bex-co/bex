## Objective

The new providers look like the existing ones: the right logo, a readable label in every locale, on every page that shows social sign-in.

## Context

- The login and sign-up pages render Ory Elements' `<Login>`/`<Registration>` with `oryAuthFormOverrides` (`dashboard/src/common/lib/ory/auth-form-overrides.tsx`); account settings uses `orySettingsFormOverrides`.
- Ory Elements 1.2.1 picks a button's logo from the provider id (`DefaultButtonSocial`, `logos[node.attributes.value.split("-")[0]]`). Its map has `gitlab` and no `bitbucket`. `DefaultButtonSocial.WithLogos({...})` adds logos for `Node.SsoButton`, but the settings page's unlink row (`UnlinkRow` in `DefaultSettingsOidc`) reads only the built-in map, so it needs a `SsoSettings` override or equivalent.
- Ory Elements hides the button labels when there are 3 or 4 oidc nodes on login and registration (`showLabel`), and lays them out in a 3- or 4-column grid. Check what Render's login and sign-up pages show for four providers and keep labels if Render does.
- The login page's `LoginWidgetSkeleton` draws one social button row; the root rule says a skeleton matches its ready state at the same breakpoint.
- `dashboard/src/common/lib/telemetry-router.ts` labels the sign-in method from the session's oidc provider.

## Steps

1. Add a Bitbucket logo (brand SVG, like `dashboard/src/common/components/github-icon.tsx`) to the SSO buttons and the settings link and unlink rows, and check GitLab's built-in logo renders on all three pages.
2. Check the labels in all eight locales: Kratos's "Sign in with {provider}" text with the provider's `label`.
3. Match the four-provider layout to Render's, and make the login and sign-up skeletons match the ready state at 1440 and 390 for the providers the installation offers.
4. Make telemetry label GitLab and Bitbucket sign-ins by name.
5. Add tests for the logo map and the settings rows, and walk the pages pending against ready at both widths.
