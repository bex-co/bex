## Result (2026-11-16)

`/simplify` over the m453 diff (reuse, quality, efficiency):

- **Shared, not copied.** `LogFloor`, `LogsVisibleFromAfterPlanChange` and `LogRetentionUpgrade` now call the same `planRetention` methods (`floor`, `visibleFromAfterPlanChange`, `firstUpgrade`) as the PITR functions. `WorkspaceLogPlanOf` and `WorkspacePITRPlanOf` share `workspacePlanFloorOf`. The store reuses the package's `nullTime` instead of a second zero-to-NULL helper.
- **One query each.** A plan change reads both floors in its one `SELECT … FOR UPDATE` and writes both in its one `UPDATE`. A recovery read issues one tenants query (`WorkspacePITRPlan`), concurrent with the ObjectStore and Backup reads. A log read is unchanged.
- **Fixed.** The store-retention guard read the chart through a copied repo-walking helper; it now uses a fixed relative path, as `rendertest` does for ADR018. The panel's `backupsEnabled = true` default was redundant with `!== false`, so it was dropped.
- **Recorded as not worth it.**
  - The dashboard's plan-name closure (`workspacePlanNameKey` -> `t`) is now in three hooks (logs, metrics, recovery). Folding the other two in would touch code m453 did not change.
  - The ten-minute constant exists once in Go and once in TypeScript. That is inherent two-sided duplication, and both sides are pinned by tests.
- Re-run: core, postgres, pricing and store suites (real DB), `make lint`, the dashboard databases/i18n/routes tests and the typecheck.
