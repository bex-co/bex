## Objective

The database Recovery panel offers exactly the window bex-api allows. Its earliest bound is the floored `earliestRecoveryTime`, its latest selectable time is ten minutes before now, and it says how many days the workspace's plan keeps and which plan keeps longer, as the log viewer's retention hint does.

## Context

- `dashboard/src/features/databases/components/recovery-panel.tsx` builds the `datetime-local` picker from `restoreBounds(info.earliestRecoveryTime, openedAtMs)` (line 74, `min`/`max` at lines 236-237). The earliest bound follows bex-api once t002 floors it. The latest bound is the open time today, which Render refuses.
- `dashboard/src/features/databases/hooks/use-recovery.ts` and `api/databases.graphql` hold the query. Tests are in `components/__tests__/recovery-panel.test.tsx` and `hooks/__tests__/use-recovery.test.ts`.
- The precedent hint is the log viewer's: `dashboard/src/features/logs/hooks/use-log-retention.ts`, read from `logRetention { plan days upgradePlan upgradeDays }`.
- The root rule: a skeleton must match the ready state. If the hint adds a line, the panel's pending state reserves it (`dashboard/AGENTS.md` § Navigation pending states).

## Steps

1. Select t002's new `databaseRecoveryInfo` fields. Render a short line such as "Hobby workspaces can restore to any point in the past 3 days. Pro keeps 7." Drop the upgrade half on the longest window, and drop the whole line where no plan applies.
2. Clamp the picker's `max` to ten minutes before now. Keep `min` at the floored start. Handle the two refusal codes by showing their message in the existing error path, never as a generic failure.
3. Update the i18n strings the panel uses, every locale the repo carries.

## Result (2026-11-16)

- The panel shows "Hobby workspaces can restore to any point in the past 3 days. Pro keeps 7 days." from `retention`. The upgrade half is dropped on the longest window, and the line is dropped where no plan applies. Strings are in all eight locales, with each language's CLDR plural forms.
- The picker's `max` is the open time minus ten minutes (`restoreBounds`' `latestMs`, `RECOVERY_MIN_AGE_MS`). `min` is the floored start bex-api reports. The out-of-window message now says "ten minutes ago".
- The two refusal codes reach the restore toast with their own message through the existing `placementErrorMessage` -> `mutationErrorMessage` path (hook tests for both codes).
- Pending state: the panel's first-load "Loading…" line is now `RecoveryContentSkeleton`, which has the ready state's regions: the two bounds, the retention line, the actions, a backup row, the export-scope line and the empty export list. The route's Suspense fallback is `RecoveryPanelSkeleton` instead of a generic 3-row card. A database without backups loads as the single line it resolves to.
- **Side by side** (local browser, 2026-11-16): measured pending vs ready regions (offset/height in px) in the recovery card.
  - Desktop 1280: identical, 0/29, 45/20, 81/36, 133/68, 217/20, 253/48, card 399.
  - Narrow 375: identical, 0/106, 122/40, 178/80, 274/78, 368/60, 444/48, card 630.
  - In the dialog, `min` was now-3d and `max` was open time minus ten minutes.
- **Deviation:** the comparison ran against `dashboard/scripts/local-bex.mjs` with a temporary recovery fixture (a window, one backup, Hobby's retention, and a switch that held the recovery read). It did not run against `dev-7`: `scripts/dev-env.sh 7 status` found the local cluster's API server refusing connections, and a local stack has no backup store, so no database there can have a recovery window. The fixture was not committed.
