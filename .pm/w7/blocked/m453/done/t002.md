## Objective

`RecoveryInfo` and `Recover` apply the workspace's PITR floor. The offered start is the later of CNPG's `firstRecoverabilityPoint` and the plan floor. A target before that start, or within ten minutes of now (Render: "You can't restore to a time that's within ten minutes of the current time"), is refused before any billing gate or create. REST, GraphQL and MCP all read through `postgres.Service`, so one change covers the three surfaces, and each gets a test.

## Context

- `lego/backend/internal/postgres/recovery.go`:
  - `RecoveryInfo` (line 137) and `recoveryWindow` (line 174) read `status.serverRecoveryWindow[<server>]` off `ObjectStore/bex-tenant-postgres`.
  - `Recover` (line 232) refuses `RECOVERY_TARGET_BEFORE_WINDOW` (line 279) and `RECOVERY_TARGET_IN_FUTURE` (line 284), and only after the window is established (line 269).
- Surfaces:
  - REST maps `info` to Render's `recoveryStatus`/`startsAt` (`postgres/rest.go:285-301`).
  - GraphQL serves `databaseRecoveryInfo` and `recoverDatabase` (`postgres/graphql.go:496`, `:729`).
  - MCP serves `get_postgres_recovery_info` and `recover_postgres` (`postgres/mcp.go:~294`).
- The tenant is `d.Labels[core.LabelTenant]`. The log service resolves the plan and floor once per request in `logs/service.go:547-582`. Mirror that.
- The recovery window's latest bound stays `lastSuccessfulBackupTime` in the response (ADR009: bex-api never synthesizes "latest = now"). The ten-minute rule applies to the target, not to that field.

## Steps

1. Add a helper that resolves the database's workspace floor (t001's reader). `recoveryWindow` callers then clamp `earliest` to it. When no plan applies, the ObjectStore window alone stands.
2. Decide and test the edge where the floored start is later than `lastSuccessfulBackupTime` (backups stalled longer than the window). The start must still be the floor, the status must stay honest (`AVAILABLE` only while some point in the window can actually be restored), and the choice is written in ADR009 by t005.
3. In `Recover`, compare the target with the floored start, so `RECOVERY_TARGET_BEFORE_WINDOW`'s `earliestRecoveryTime` detail is the floored value. Add a coded refusal for a target within ten minutes of `s.Now()` (for example `RECOVERY_TARGET_TOO_RECENT`), kept apart from `RECOVERY_TARGET_IN_FUTURE`. An empty `targetTime` still means the latest point and is not refused.
4. For the dashboard hint (t004), give GraphQL `databaseRecoveryInfo` native fields with the shape `logRetention` uses (`plan`, `days`, `upgradePlan`, `upgradeDays`; null where no plan applies). Add the same to MCP's result. REST keeps Render's exact two fields.

## Result (2026-11-16)

- `postgres.Service.pitrWindowOf` reads the workspace plan and kept floor once (`core.WorkspacePITRPlanOf`) and rounds the floor up to the second. `RecoveryInfo` reads it beside the ObjectStore and the Backup list, in the same errgroup. `recoveryWindowBounds.flooredAt` starts the window at the later of `firstRecoverabilityPoint` and the floor. With no plan, the ObjectStore's window alone stands.
- **Stalled-backup edge (decided):** when `lastSuccessfulBackupTime` is older than the floor, the window is not established. Recovery info reports no bounds (REST `BACKUP_NOT_READY`), and `Recover` refuses with a plain 400 naming the floor, before billing. Reason: bex-api cannot vouch for a point past the last base backup, because the ObjectStore status does not report WAL. ADR009 records the edge.
- `Recover` compares the target with the floored start. `RECOVERY_TARGET_BEFORE_WINDOW` names the floored `earliestRecoveryTime`. A new `RECOVERY_TARGET_TOO_RECENT` (params `latestTargetTime`) refuses a target within ten minutes of now, separate from `RECOVERY_TARGET_IN_FUTURE`. An empty target is not refused. Both refusals run before `RequirePlanBilling` and before `Create`.
- GraphQL `databaseRecoveryInfo.retention` (`DatabaseRecoveryRetention { plan days upgradePlan upgradeDays }`, null where no plan applies) and the same `retention` object in MCP's result. REST's `GET /recovery` still has exactly `recoveryStatus`/`startsAt`. The schema golden and the dashboard's generated types were regenerated.
- Tests (`pitr_window_test.go`, fixed clock): Hobby/Pro/Scale/kept-floor/young-database/no-plan on REST, GraphQL and MCP; the stalled edge on Hobby and the same backups on Pro; both refusals on each surface with no payment-gate call and no new Database; targets inside the window reach billing; the floor rounds up. Reverting the clamp fails all four tests, and removing the ten-minute check fails the refusal test on every surface.
