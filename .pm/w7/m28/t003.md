## Objective

Stop special-casing `type=build` as empty: route it through `QueryLogs` to the Loki store like `type=request`, on all three adapters, with the established store-less 503 behavior.

## Context

- `lego/backend/internal/logs/` — w3/m8 shipped the filter set; `type=build` is currently documented as empty by design (`docs/ADR018-render-parity.md` §Logs).
- Store-only filters already 503 without `BEX_LOKI_URL` — `type=build` must join that contract, never return a silent empty set.

## Steps

1. Locate the `type` filter handling and include `build` in the store-backed selector.
2. Confirm REST `GET /v1/logs?type=build`, GraphQL `logs`, MCP `list_logs` all pass it through unchanged (thin adapters).
3. Store-less: 503 naming the missing store.

## Files

- `lego/backend/internal/logs/`

## Acceptance criteria

- [ ] `type=build` returns build lines with the store, 503 without — on REST, GraphQL, and MCP.
