## Objective

A test fails when a row of Render's captured plan table has no recorded disposition in bex, so the next row Render adds, or the next one bex forgets, is noticed.

## Context

- Render's plan table has two sources: render.com/docs/platform-features-by-plan and the workspace feature table on render.com/pricing (both read 2026-11-16).
- bex's dispositions today: `planFeatures` and the limit helpers in `lego/backend/internal/core/plan_gate.go`, `PlanLimits` in `lego/backend/internal/store/plans.go`, included pipeline minutes and bandwidth (ADR030 §13, §14), log retention (w9/m389), metrics retention (`w7/m427`), and the non-goals in `.pm/DO_NOT_DO.md` (previews, dedicated IPs, log and metric streams, SSO and SCIM, private links, HIPAA).
- `docs/render-artifacts/pricing.md` exists and is the place for the capture.

## Steps

1. Capture both tables, row by row with the per-plan values and the read date, into `docs/render-artifacts/pricing.md`, and as a small fixture file next to the test.
2. Write the test: every fixture row maps to exactly one disposition (a gate, a limit, a meter, a retention window, "same on every plan", or a non-goal with its `DO_NOT_DO.md` or ADR018 reference). A row with none fails, and so does a disposition for a row that no longer exists.
3. Where a disposition is a number (members, environments per project, included domains, kept builds, retention days), the test compares the fixture's number with the code's.
4. Add the table to ADR030 §9 so the document and the test list the same rows.

## Files

- `lego/backend/internal/core/plan_gate_test.go` (or a sibling test) and its fixture under `testdata/`
- `docs/render-artifacts/pricing.md`
- `docs/ADR030-pricing.md`
