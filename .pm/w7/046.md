# Decide `ea sandboxes copy` and `ea sandbox-groups list` for the pinned Render CLI

Why: w7/m147 t006 graded both as `[ ]` gaps in `docs/cli-compatibility-checklist.md` — the pinned launcher ships them in `bex ea --help`, and today each ends in a bex `404` — so the user should decide whether to close them or mark them non-goals.

**Worker:** worker7. **Estimate:** 30m to decide and file; implementing `copy` is a milestone (>1h). **Status:** todo.

## The gaps

- `ea sandboxes copy` mints a file connect token at `POST /v1/sandboxes/{id}/files/{operation}/token` (`upload` / `download`, body `{path}`) and streams a tar or octet-stream body to the returned `uri` — the same handshake shape m147 built for `runs/{operation}/token`, so the mint/redeem scaffolding (`lego/backend/internal/sandbox/connect.go`) is reusable; the transfer path (gateway file streaming into the pod) is new.
- `ea sandbox-groups list` calls `GET /v1/sandbox-groups?ownerId=`; bex has no sandbox-group concept (ADR014/ADR042).

## Options

1. Promote `copy` to a milestone (reuse the connect-token mint; add a file redeem route + gateway transfer). Leave `sandbox-groups` as `[-]` non-goal.
2. Mark both `[-]` non-goals in the ledger with the reason, and retire this note.

**Goal linkage:** ADR018 / `docs/cli-compatibility-checklist.md` (pinned-CLI truthfulness); pillar-5 sandboxes (ADR014, ADR042).

**Render parity:** applies if option 1 is taken — REST only (the CLI is the sole consumer); no GraphQL/MCP/UI surface today.
