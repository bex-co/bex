# w7/014 — Billing-role members cannot manage billing (verbs gate on `can_manage`, not `can_manage_billing`)

**Source:** w7/m61 role-ladder sweep, 2026-07-31.

**Finding.** `deploy/gitops/authz/model.fga` defines `can_manage_billing: billing or admin`, but **no Go verb checks it** — the billing feature verbs (`billing.Service.Checkout`, `Portal`, `Status`, `internal/billing/service.go:185`) all gate on `core.RelCanManage` (admin only). Consequences:

- A **billing-role** workspace member (Render's BILLING role) cannot reach any billing verb in bex — they are refused with 403 exactly like a viewer. Render grants the billing role billing management; bex does not.
- `can_manage_billing` is a modelled-but-dead relation.

**Severity:** functional gap / Render-divergence, **not a security hole** — the gating is too *strong* (fail-safe), never over-privileged. Confirmed live against the deployed model by `TestMultiWorkspaceTargetingE2E` (a billing member is denied resource mutations and sensitive reads, and would be denied billing verbs too).

**Decision needed (pick one):**

1. **Align to Render:** change the billing verbs' guard from `RelCanManage` to a new `RelCanManageBilling` constant, add the constant to `internal/core`, and let the billing role manage billing. Touches billing authz — needs a test pass + a real-FGA E2E case flipping billing→allowed on billing verbs.
2. **Drop the dead relation:** remove `can_manage_billing` from `model.fga` (and regenerate `model.json`) if bex intentionally keeps billing admin-only, and document the divergence in ADR012/ADR024.

**Why not now:** m61 is a test-only milestone (no production authz changes in scope); changing billing gating or the model is its own sized change. Filed for a future workstream decision.
