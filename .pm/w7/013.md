# govulncheck (Go source-level vuln scanning) in CI over the workspace

Wire `govulncheck` as a CI job over the Go workspace (`lego/types` + `lego/operator` + `lego/backend`). It's the source-level, call-graph-aware complement to what already exists:

- **Trivy** (w7/m10, `deploy.yml`) scans the built **images** — OS packages + bundled language deps — after the fact.
- **gitleaks** (w7/002, `deploy.yml`) scans the pushed **commits** for secrets.
- Neither does Go **call-graph vulnerability** analysis of the actual module dependencies. `govulncheck` reports only vulns in **reachable** code, so it's low-false-positive and safe to gate.

**Scope (sub-hour to wire):**

- Add a CI job (own workflow or a step in `go-lint.yml`/`backend-test.yml`) running `govulncheck ./...` over each workspace module (or the workspace).
- Pin the tool by version + sha256 (the gitleaks/trivy pattern in `deploy.yml`), not `@latest`.
- Choose gate semantics: **fail when a fixed version exists** (reachable vuln with an available upgrade); warn otherwise. Document the policy next to the job.
- Baseline-triage the current findings before turning the gate on.

**Sizing:** the mechanical work is one pinned CI job → inbox note, not a milestone. **Promote to a milestone** (or fold into `w7/m58` as an added task, citing m10's grouping of two sub-hour CI-hygiene items) **only if** the baseline scan surfaces vulns needing breaking dependency upgrades — the `w1/006` Dependabot-triage handling pattern.
