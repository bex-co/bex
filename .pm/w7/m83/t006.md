## Objective

Make the build plane's concurrency baseline auditable in git instead of depending on out-of-band environment.

## Context

- ADR060 D7: `BEX_APP_RECONCILE_WORKERS`, `BEX_MAX_CONCURRENT_BUILDS` and the new `BEX_MAX_ACTIVE_BUILDS` should be set explicitly in the deploy manifests / gitops path "rather than relying on out-of-band env, so the ADR034 baseline is auditable in git".
- D7 also notes that **after D1** (shipped as `w2/m72`), `BEX_APP_RECONCILE_WORKERS` returns to a pure responsiveness knob — the caps carry the policy. So the checked-in value should reflect that, not the pre-D1 "workers == builds" equation, and the comment should say which.
- The native base images D7 also listed are **already digest-pinned** (`lego/operator/internal/build/native.go:42-46`), so that half of D7 is done; do not redo it.

## Steps

1. Set the three variables explicitly in the operator's deploy manifest / gitops values.
2. Comment each with what it now governs post-D1, so the next reader does not restore the old coupling.
3. Confirm the values match what production is actually running before checking them in — a checked-in baseline that silently changes behavior on the next sync is worse than none.

## Files

- `lego/operator/config/` / `deploy/gitops/base/` operator manifest
- `CLAUDE.md` env table if wording changes
