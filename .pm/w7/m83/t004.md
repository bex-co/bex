## Objective

Guard the thin margin that makes a cx33 build slot work at all, so it cannot erode silently. This is the surviving residue of `.pm/w7/024.md` after measurement refuted that note's main hypothesis.

## Context

Measured on hetzner-prod 2026-08-17:

| quantity | value |
| --- | --- |
| cx33 allocatable memory | **7,834,836Ki (7.47 GiB)** |
| build pod effective request | `max(initContainers)` = **7Gi = 7,340,032Ki** |
| free after the build pod | **483 MiB** |
| DaemonSet requests on a tainted build node | **log-shipper only: 128Mi + 50Mi = 178Mi** |
| cilium · cilium-envoy · hcloud-csi-node · kube-proxy | **0Mi each** |
| **spare** | **305 MiB** |

- So a cx33 **does** fit a build — `024`'s branch 3 is refuted and **no pool rotation is justified** (that recommendation was withdrawn; see `builder-issues.md` §4).
- But 305 MiB is thin. If log-shipper's request grows, another DaemonSet gains the build toleration (t003 just added one at 8Mi), or the build request rises, a cx33 stops fitting — and cluster-autoscaler then declines to scale up **without emitting an error**. Invisible by construction.
- The CA hint (`capacity.cluster-autoscaler.kubernetes.io/memory: "8G"` = 7,812,500Ki) is currently slightly *below* real allocatable, so simulation is conservative — preserve that property.
- `scripts/clusterapi-validate.sh` already guards the build pools' bootstrap template and taint hints (lines ~227-231); extend it rather than adding a second script.

## Steps

1. Encode the floor: for every MachineDeployment carrying the build taint, `CA memory hint ≥ build request + the sum of DaemonSet requests that tolerate the taint`.
2. Source the build request from one place so the guard cannot drift from `build.go`'s constants.
3. Fail closed with a message that names the actual numbers and the shortfall, not just "check failed".
4. Add a red/green self-test: shrink the hint (or grow a DaemonSet request) and prove CI turns red.
5. Record the measured allocatable figures in `docs/ADR060` so the next reader does not have to re-measure.

- [ ] The guard computes the floor from the real build request, not a copied literal.
- [ ] Reducing the hint below the floor turns CI red with a message naming the shortfall.
- [ ] The self-test proves both directions.
- [ ] The measured cx33/cx43 allocatable numbers are recorded in ADR060.

## Out of scope
