## Objective

Make deleting a `KeyValue` actually delete its data volume: StatefulSet PVCs from `volumeClaimTemplates` are **not** garbage-collected with the StatefulSet by default, so the Valkey PVC (tenant data at rest) survives Key Value deletion. Set `persistentVolumeClaimRetentionPolicy: {whenDeleted: Delete, whenScaled: Retain}` on the StatefulSet the controller builds.

## Context

- `lego/operator/internal/controller/keyvalue_controller.go` — StatefulSet construction (~309); the controller comment claims PVCs are "GC'd via owner refs", which is wrong for StatefulSet template PVCs — fix the comment too.
- `StatefulSetAutoDeletePVC` is GA in recent k8s; the CAPD mock and Hetzner clusters are new enough — verify once on the mock cluster.
- Verify the same gap doesn't exist elsewhere: CNPG manages its own PVCs (Cluster delete removes them — confirm in t008's audit), and Deployments have no template PVCs.

## Steps

1. Add the retention policy to the StatefulSet spec.
2. Correct the stale GC comment.
3. envtest: assert the policy on the built StatefulSet; mock-cluster spot check: create KV → delete → `kubectl get pvc` shows none.
