## Objective

Expose low-cardinality Prometheus metrics and structured logs for emitter, provisioning, invoice-read, webhook, reconciliation, and lifecycle health without leaking secrets or tenant payment data.

## Context

- ADR040 requires alerts for backlog, provisioning failure, permanent rejects, invoice degradation, duplicates, and signature failures.
- Logs currently prove startup and trusted webhook intake but are not a complete operational signal set.

## Steps

1. Define bounded metric names, labels, counters, gauges, and age/backlog signals.
2. Add structured diagnostic events with safe workspace/provider identifiers where necessary.
3. Document cardinality and redaction constraints.

## Files

- `lego/backend/internal/billing/`
- `lego/backend/internal/api/metrics.go`
- `docs/ADR040-billing-metronome.md`

## Acceptance criteria

- [ ] Metrics cover every ADR040 failure class with bounded label cardinality.
- [ ] API keys, webhook secrets, payment details, and full payloads never enter logs/metrics.
- [ ] Stripe-disabled mode produces no misleading failure signal.

## Out of scope

- Alert routing configuration.
