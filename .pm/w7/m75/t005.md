## Objective

Stop the disaster-recovery bootstrap from piping the mutable `get.k3s.io` installer into `sh` as root with no integrity check (codex-security #27, low).

## Context

- `infra/terraform/cloud-init.yaml.tftpl:5/7` — `curl -sfL https://get.k3s.io | INSTALL_K3S_CHANNEL=${k3s_channel} sh -s - …`.
- `infra/terraform/variables.tf:42/45` — `k3s_channel` defaults to `stable` (mutable); `main.tf:57` passes it through.

## Steps

1. Default `k3s_channel` to a pinned version (e.g. `v1.30.5+k3s1`).
2. Verify the installer script's SHA256 against a recorded value before piping to `sh`; document the pin in the DR runbook.

## Files

- `infra/terraform/variables.tf`
- `infra/terraform/cloud-init.yaml.tftpl`
- DR runbook (docs/ADR031 / ADR001).

## Acceptance criteria

- [ ] Default channel is a pinned version; installer checksum-verified before root execution.

## Out of scope
