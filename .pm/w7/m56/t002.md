## Objective

Point the ssh-gateway deployment's `BEX_CP_DB_URI` at the scoped role's credential (its own Secret, separate custody from bex-api's control-plane URI) without touching bex-api's credential or any Go code paths — the store's interface is unchanged; only the identity behind the connection narrows.

## Context

- The gateway reads `BEX_CP_DB_URI` at startup (`lego/backend/cmd/ssh-gateway/main.go`); bex-api keeps its own full-privilege URI — the two must no longer share a Secret.
- Gateway deployment manifests live in `deploy/gitops/` (platform infra is Argo-reconciled); the Secret itself is installed out of band by the t001 script, never committed (repo rule: no secret values in git).
- `.env.example` mirrors env-var *names* — add the new variable name/comment there if a new name is introduced (keep names in sync per CLAUDE.md).

## Steps

1. Add the gateway-scoped Secret reference to the gateway Deployment env in `deploy/gitops/`.
2. Verify locally (dev cluster or compose) that the gateway starts, looks up a key, and records a session under the scoped role.
3. Update `.env.example` + the CLAUDE.md env table only if a distinct variable name is introduced (prefer keeping `BEX_CP_DB_URI` with a different Secret).

## Files

- `deploy/gitops/` (gateway Deployment)
- `.env.example`, `CLAUDE.md` (only if a var name changes)

## Acceptance criteria

- [ ] Gateway and bex-api consume different Secrets; gateway functions fully under the scoped role locally.
- [ ] No secret value appears in git or logs.

## Out of scope

- Production rotation + revocation of the old grant (t003).
