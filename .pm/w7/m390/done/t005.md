## Objective

Make the in-sandbox driver start and run a `muse` session under the same contracts as the other profiles.

## Context

- `lego/agent-image/driver/src/acp.ts`: per-profile bootstrap (Codex `providers/set`, overlay channel selection: `system-prompt` / `developer-instructions` / `preamble`), spawn env, `SessionStateUnavailable`.
- `lego/agent-image/driver/src/credentials.ts`: the placeholder key and model-proxy URL; the driver refuses anything but `bex-model-proxy-placeholder-<session id>`.
- The adapter has no `systemPrompt` capability, so the overlay rides the first-prompt preamble (as for Gemini). It supports stdio and HTTP MCP (SDK backend) and `loadSession`.
- Permission requests are answered automatically (`allow_always`); DO_NOT_DO `#APPROVAL-MODE` forbids surfacing them.

## Steps

1. Route Muse to the session model-proxy URL with the placeholder, via the gateway env pair or the `muse/provider` extension — whichever the ADR chose — and set the configured model to the pinned id.
2. Start Muse with its own sandbox off and approvals bypassed (`MUSE_CODE_ACP_ALLOW_YOLO=1` plus the adapter's mode/safety setting).
3. Register the `bex` stdio MCP server on `session/new` and `session/load`.
4. Map Muse authentication, endpoint and provider failures to a failed turn with a named reason, never a successful `end_turn`.
5. If the preamble proves too weak for the delivery contract in t007, record it and bump to an adapter release that advertises `systemPrompt`.
