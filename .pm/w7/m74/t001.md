## Objective

Stop a `verification_uri_complete` link from authorizing an attacker-controlled device grant without user confirmation. The public GET handler takes `user_code`+`device_challenge` from the URL and server-side accepts the pairing via Hydra admin API before any browser-session/subject binding; the trusted Render CLI client has `skip_consent=true` so consent is auto-accepted (codex-security #9, medium).

## Context

- `dashboard/src/routes/auth.device.tsx:7/11-17` + `dashboard/src/common/server-fn/hydra-device.ts:24/43-85` — GET handler unconditionally PUTs `/admin/oauth2/auth/requests/device/accept` with no session binding / confirmation / identity check.
- `scripts/auth-bootstrap-client.sh:158/163` — sets `skip_consent:true` on the Render CLI client.
- `dashboard/src/common/server-fn/hydra-consent.ts:222` — `isTrusted()` auto-accepts; consent subject-binding at ~:237 is the pattern to mirror.

## Steps

1. Before calling `/device/accept`, require an authenticated Kratos session and bind the accept's subject to it.
2. Render an explicit "Authorize this device?" confirmation page (display requesting client/device) and accept only on POST confirmation (CSRF-protected), mirroring the consent path's subject binding.
3. Keep the login-first bounce for unauthenticated victims.
