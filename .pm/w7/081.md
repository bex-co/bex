# An organization cannot enforce two-factor authentication or limit login methods, as a Render org can

Why: Render's org audit log names `ChangeOrg2FAEnforcementEvent` and `ChangeOrgAllowedLoginMethodsEvent`, and bex's organizations (w7/m464) record neither because the org has no login settings.

- Found by w7/m464 t014, 2026-11-17 (ADR115 D7 lists them as follow-ups).
- Render (render.com/docs/audit-logs, read 2026-11-17): "`ChangeOrgAllowedLoginMethodsEvent`: The org's set of allowed login methods was changed." "`ChangeOrg2FAEnforcementEvent`: Two-factor authentication enforcement was enabled or disabled for the org." Both are org events, in the org's own log.
- bex: a workspace can require 2FA (ADR012 §9a, `workspaces.SetRequireTwoFactor`, `core.Base.TwoFactor`), and an org has no setting at all. The Google-login half of "Enforce 2FA & Google login" is w7/078 for workspaces.
- Shape: probably a milestone. An org-level `require_two_factor` (and later allowed login methods) that the 2FA gate reads for every org workspace beside the workspace's own setting, an Owner-only GraphQL and MCP toggle on the org Settings page, the two org audit events (`renderOrganizationEvents` in `lego/backend/internal/audit/render_inventory_test.go` moves them from `notYet` to recorded), and the plan gate `core.FeatureTwoFactorEnforcement`.
- Done when: an Owner turns on org 2FA, a member without a second factor is refused in every org workspace with `WORKSPACE_2FA_REQUIRED`, and the org log lists `ChangeOrg2FAEnforcementEvent`.
