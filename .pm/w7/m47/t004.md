## Objective

Ensure every billable tenant has a Metronome customer keyed by its own id, and give operators an audited escape hatch (`billing_excluded`) so internal/superadmin/test workspaces never enter Metronome — while still seeing `estimatedCost`.

## Context

- `docs/ADR040-billing-metronome.md` §2 (one workspace = one customer via ingest alias) + §7 "Comped / exempt tenants" (Mode A).
- Customer = `tenant.id` (`tea-…`) registered as `ingest_aliases: ["tea-…"]`; usage events carry `customer_id: "tea-…"` and Metronome resolves the alias. Optionally persist the returned Metronome UUID on `tenants` for admin/audit.
- `tenants` table: `lego/backend/internal/store/migrations/0001_core.up.sql`; store types in `internal/store/store.go`.
- `billing_excluded` decides whether money is owed ⇒ **admin-only, set via the control-plane internal API, written to `audit_events`** (never tenant-editable). Excluded tenants: no customer, no events.
- Provisioning is lazy from the emitter (t005): first time a non-excluded tenant has a sealed row to ship, ensure its customer exists.

## Steps

1. Migration: `ALTER TABLE tenants ADD COLUMN billing_excluded boolean NOT NULL DEFAULT false;`
2. `EnsureCustomer(tenantID)` (via t002's client): idempotent create with the ingest alias; cache/persist so it is not re-created every cycle.
3. Add the admin-only control-plane verb (or internal-API field) to set `billing_excluded`, emitting an `audit_events` row on change.
4. Emitter integration point: skip excluded tenants entirely (no `EnsureCustomer`, no events).
5. Unit-test: excluded tenant ⇒ no customer/no events; non-excluded ⇒ customer ensured once.

## Files

## Acceptance criteria

- [ ] A non-excluded tenant gets exactly one Metronome customer with `ingest_aliases=[tenant.id]` (idempotent across cycles).
- [ ] Setting `billing_excluded` is admin-only and writes an `audit_events` row.
- [ ] An excluded tenant produces no Metronome customer and no events, yet its `estimatedCost` (existing usage API) is unchanged.
