## Objective

The core of m47: a loop inside bex-api that ships sealed `usage_hourly` rows to Metronome exactly once, deterministically, with a floor that prevents pre-billing backfill. Seal-then-emit sidesteps Metronome's 34-day dedup + non-retroactive-metric constraints by only ever emitting rows that can no longer change.

## Context

- `docs/ADR040-billing-metronome.md` §3 (seal-then-emit), §4 (outbox), §5 (mapping), §6 (`BEX_METRONOME_EPOCH`), §7 (epoch guard is essential).
- Runs in the bex-api process, which already runs `usage.Service` when `BEX_CP_DB_URI` is set (`lego/backend/internal/usage/service.go`). Wire the emitter beside it; env-gated by `BEX_METRONOME_TOKEN` (nil client ⇒ never starts).
- Selection: `window_start < now − BEX_METRONOME_SEAL_HOURS` (default 48h, aligned with ADR023 compaction horizon) `AND emitted_at IS NULL`.
- Floor guard: never emit `window_start < max(BEX_METRONOME_EPOCH, now − backfill_horizon)`; log a one-time gap warning. Stops the first-enable `4xx` flood and billing pre-epoch history.
- `transaction_id = sha256("<resource_kind>|<service_id>|<kind>|<tier>|<window_start RFC3339>")` — deterministic ⇒ retries/re-scans safe.
- Event: `event_type` = meter kind; `properties` = `{tier, resource_kind, service_id, value:"<quantity>"}` (all strings).
- Skip `billing_excluded` tenants (t004). Batch via t002's client; stamp `emitted_at` only after a successful ingest.

## Steps

1. Emitter loop: query sealed, un-emitted, above-floor rows for non-excluded tenants.
2. Ensure each row's tenant customer exists (t004), then map row → event with the deterministic `transaction_id`.
3. Batch-ingest via the t002 client; on success, stamp `emitted_at` (transactionally, so a crash re-emits safely under the same id).
4. Add `BEX_METRONOME_EPOCH` parsing + the floor guard with a one-time gap-warning log.
5. Wire startup/shutdown into bex-api beside `usage.Service`; no-op when the client is disabled.

## Acceptance criteria

- [ ] Each sealed, above-floor, non-excluded row is emitted exactly once (deterministic `transaction_id`), `emitted_at` stamped after success.
- [ ] Rows with `window_start` below `max(epoch, now − horizon)` are never emitted; a single gap-warning is logged.
- [ ] A simulated crash between ingest and stamp does not double-bill (dedup) and does not drop the row (re-scan).
- [ ] `BEX_METRONOME_TOKEN` unset ⇒ emitter never starts; behavior byte-identical.
