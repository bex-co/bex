## Objective

Settle what the tenant backup store keeps once bex-api offers at most 7 days, record the decision in ADR009 (t005 writes it), and add a guard that fails if the stored retention is ever shorter than `core.LongestPITRRetention()`. Without the guard, a later cut below 7 days would quietly break the Pro window.

## Context

- `deploy/gitops/charts/barman-cloud-objectstores/tenant-postgres.yaml:32` keeps `retentionPolicy: 30d`. The operator projects that ObjectStore into every tenant namespace (`lego/operator/internal/controller/datastore_secret_plane_test.go:190-266` pins the projection, using a `30d` fixture). bex-db and auth-dbs keep `7d`.
- Barman's retention is a recovery window. It keeps the base backups and WAL needed to restore to any point inside it, so `7d` still covers a 7-day window.
- The 23 days past the longest plan window can never be offered to a customer once t002 ships. They remain only as an operator's margin for incident recovery, and as Wasabi storage cost.
- Before choosing, check what else reads those days: deleted-database purge (ADR009 finalizer purge), logical exports (separate, 7 days), ADR031/ADR050's backup policy, and any runbook or drill (`docs/drills/2026-07-28-barman-plugin-pitr.md`).
- The metrics precedent: `scripts/metrics-retention-guard.sh` checks production's Prometheus against `core.metricsRetention`.

## Steps

1. Decide between keeping `30d` (operator margin; the floor alone gives Render's behavior) and `7d` (cost; nothing a customer can reach is lost). Write down what each one costs. Shortening removes recovery margin that only operators use, so if the decision needs the user, keep `30d`, file the shortening as its own w7 inbox note with the evidence, and continue. It does not gate this milestone.
2. Add a backend test that reads the chart's `retentionPolicy`, parses Barman's `<n>[dwm]`, and fails if it is shorter than `core.LongestPITRRetention()`. The test reads a file outside `lego/backend/`, so add that path to `backend-test.yml`'s `paths` (`scripts/ci_test_inputs.py` checks this).
3. If the value changes, update the chart and the operator test fixture's wording, and verify on production after Argo syncs. Use `scripts/fetch-app-kubeconfig.sh` and read `ObjectStore/bex-tenant-postgres` `spec.retentionPolicy` in a tenant namespace.
