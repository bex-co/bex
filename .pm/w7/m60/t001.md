## Objective

Meter the two unauthenticated webhook intakes with an IP-keyed token bucket (the `BEX_DEVICE_RATE_LIMIT` pattern), shedding **before** the body read and HMAC/signature computation. New env knobs `BEX_WEBHOOK_RATE_LIMIT` (req/min) and `BEX_WEBHOOK_RATE_BURST`, `0` disables. Defaults must be generous enough that legitimate GitHub/Stripe delivery bursts never shed — both senders retry, but throttling real deliveries would delay deploys/billing convergence; document the chosen default and the 429 body shape in the code.

## Context

- `lego/backend/internal/api/server.go:791-799` — the two mounts; chain assembled at `server.go:837`.
- `lego/backend/internal/cliauth/ratelimit.go` — the proven IP-keyed limiter to mirror (or lift into a shared helper if identical).
- The body-cap middleware already wraps everything (`ratelimit.go:123-146`); this limiter must sit inside the route handlers' path but **before** `io.ReadAll`/verification so shed requests cost ~nothing.

## Steps

2. Plumb the env knobs in `cmd/api` alongside the device-limiter wiring.
3. Unit tests: shed request never reaches the HMAC verifier; in-budget signed delivery passes; `0` disables.
