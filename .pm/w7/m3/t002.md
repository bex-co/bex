## Objective

One rate-limiting middleware at bex-api's shared router: token-bucket per caller — keyed by API-key/OAuth2-client id for key auth, Kratos session/identity id for sessions, remote IP for unauthenticated paths — returning the t001-captured Render-shaped 429 + `Retry-After` when exhausted. One middleware covers REST, GraphQL, and MCP because they hang off the same mux.

## Context

- The HTTP surface is assembled in `lego/backend/internal/api` (`:8090`); auth context (key/session identity) is resolved there per docs/auth.md — the limiter keys off the resolved caller, falling back to IP.
- `golang.org/x/time/rate` per-key limiters in a map with idle eviction is the standard shape; no external store (single-replica bex-api today — note the multi-replica caveat in the code where it bites).
- Exemptions: the HMAC git webhook (`/v1/webhooks/git`) and health/metrics endpoints get their own (higher or separate) budget so platform traffic can't be starved by tenant traffic.
- GraphQL surfaces the 429 as a top-level error with an extension code; MCP as a tool error — per the t001 mapping.

## Steps

1. Implement the keyed limiter + middleware; wire it into the router ahead of the adapters.
2. Apply per-class budgets (default API, webhook, unauthenticated) from t001's defaults.
3. Return the Render-shaped envelope + `Retry-After`; log limited requests with caller key (no secrets).

## Files

## Acceptance criteria

- [ ] Hammering with one key yields 429 + `Retry-After` while a second key stays 200
- [ ] REST, GraphQL, and MCP all surface the limit per the t001 mapping
- [ ] Webhook + health endpoints keep their own budget
