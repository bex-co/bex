## Objective

Before any code changes, ADR012 §8 states what the bearer form of an API key is and how bex-api verifies it, and ADR018's API-key row stops describing the exchange-only model as a standing divergence.

## Context

- ADR012 §8, last bullet: "A raw secret used as `Authorization: Bearer` still returns a generic `401 unauthorized`".
- ADR018 § Identity, workspaces & account, row "API-key management": "Credential model divergence (deliberate, ADR012)". No user sign-off is recorded for it.
- Render: render.com/docs/api (read 2026-11-16): every request authenticates with the API key; the key is shown in full only at creation; "Revoking an API key takes effect immediately." Render's Terraform provider sends `Authorization: Bearer <api key>`.
- Keys are Hydra `client_credentials` clients (`lego/backend/internal/apikeys/service.go`, `GrantTypes: []string{"client_credentials"}`). Hydra stores only a hash of the secret. Access tokens live 15 minutes. bex-api caches a positive introspection for at most 5 s (`introspectionTTL`, `lego/backend/internal/api/auth.go:60`).

## Steps

1. Define the key string: a fixed prefix that cannot collide with a Hydra access token, plus the client id and the secret, in one copyable string. This is the recommended shape because it needs no new secret store, and the owner of an existing key can compose the string from the id and secret they already hold.
2. Define verification: bex-api exchanges the key at Hydra's token endpoint (`client_credentials`), caches the access token per replica under a hash of the key until shortly before it expires, and then runs the existing introspection path. Identity, workspace binding, the last-used stamp, audit attribution and §8d revocation stay as they are. State the revocation latency that results.
3. Define the failure rules: one 401 body for every failure; a bound on failed attempts per client id and per source (t004); a short negative cache so a wrong secret does not make Hydra hash on every request; the key never in logs, traces, metric labels or error text.
4. Record the alternative considered (a bex-side table of hashed keys that bypasses Hydra) and why it was or was not chosen.
5. Rewrite ADR018's API-key row: the divergence paragraph becomes the bearer rule, marked ◐ until t006 passes. Keep the "bex ahead" note (keys over the API, workspace-scoped), and record the user-versus-workspace scope difference as a separate, unchanged difference.
6. Run `npx prettier@3.4.2 --write` on the changed docs.
