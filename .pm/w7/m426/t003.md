## Objective

Minting a key returns the bearer string once, on REST, GraphQL and MCP alike, and the dashboard dialog shows that one string with a working curl example, as Render's "Make your first request" step does.

## Context

- `apikeys.APIKey` carries `id`, `name` and, on create only, `secret` (`lego/backend/internal/apikeys/service.go:42-44`). `rest.go`, `graphql.go` and `mcp.go` return it.
- Dashboard: `dashboard/src/features/api-keys/components/create-api-key-dialog.tsx`, `api/api-keys.graphql`, `locales/*.ts`. `apiKeys.exchangeHelp` (`locales/en.ts:124`) reads "This is an OAuth2 client_credentials client, not a bearer token".
- Render shows the key in full only at creation, and its docs' first step is a curl that lists services.

## Steps

1. Add `key` (t001's bearer string) to the create result on REST, GraphQL and MCP. Keep `id` and `secret` so the exchange still works. Never return `key` from a list or a get.
2. Dialog: show the single key with a copy button and a curl example against the API origin (`GET /v1/services` with the bearer). Move the exchange into a secondary "OAuth client credentials" detail. Replace the "not a bearer token" copy in every locale file.
3. Keep the dialog's pending and ready states the same size at desktop and narrow-mobile widths.
4. Tests: the three create surfaces return the same `key`, and reads never do; the dialog test covers the key, the copy action and the curl text.

- `dashboard/src/features/api-keys/`
