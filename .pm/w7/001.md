# Fresh tenant nodes can't pull authed Zot images — App Deployments carry no `imagePullSecret` (w7/m8 follow-up)

`w7/m8` closed the anonymous-Zot hole (Zot now denies unauthenticated pull; `BEX_REGISTRY_PULL_SECRET` / the `bex-registry-pull` docker-config Secret exists, docs/ADR022 §Registry access control). But the tenant App **Deployments the operator generates carry no `imagePullSecret`** (verified live 2026-07-15: `eden-cms-v2`, `beancount-cms`, `agentmarketcap` — all `.spec.template.spec.imagePullSecrets` empty; all App-CR-owned). The cluster only kept pulling because every image was **cached on the long-lived tenant node from before auth was enabled** — nothing re-pulled.

**Exposed by `w1/m36`** (baked worker-image roll, 2026-07-15): rolling the tenant pool put the Apps on a **fresh** node with an empty containerd cache. Every git-built image then failed `authorization failed: no basic auth credentials` → `ImagePullBackOff`, a live (brief) tenant outage. **Any** fresh tenant node hits this — autoscaler scale-up, node failure/remediation, a k8s upgrade roll — not just this milestone's roll.

**Live fix applied (interim):** attached `bex-registry-pull` to the `default` namespace's **default ServiceAccount** `imagePullSecrets` (auto-injected into every pod at admission — node-agnostic, and doesn't fight the operator, which owns the Deployments). Apps recovered. **This is undeclared prod state (GitOps drift).**

**Proper fix — size + decide, don't just re-patch:**

1. **Operator attaches the secret per the documented design** — docs/ADR022 says `PULL_SECRET` is "attached to tenant Deployments/CronJobs as an `imagePullSecret`", but the operator isn't doing it (needs `BEX_REGISTRY_PULL_SECRET` wired into the Deployment/CronJob generation + the running operator's env). This is the design-aligned fix and makes it per-workload/auditable. **OR**
2. **Declare the ServiceAccount injection in `deploy/gitops`** — make Argo own the `default`-ns SA `imagePullSecrets` so the interim fix is durable + auditable. Simpler, namespace-wide, but Argo then owns the default SA.

Either closes the drift and makes fresh-node pulls work by design. Confirm no other tenant namespaces need the same. Evidence + timeline: `.pm/w1/m36/README.md` § Measurements ("Latent gap the roll exposed").

Source: `w1/m36` tenant-pool roll incident, 2026-07-15.
