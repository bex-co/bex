## Objective

Expose one machine-readable billing lifecycle result so users and agents can see healthy, grace, enforced, recovering, excluded, and comped states with reason and deadline.

## Context

- The existing usage billing object shows amounts/invoices but no lifecycle state.
- Dashboard presentation must not invent state from email or Stripe redirects.

## Steps

1. Extend the core billing result with normalized status, reason, deadline, and allowed actions.
2. Thread it through REST, GraphQL, MCP, and dashboard with identical semantics.
3. Add recovery/Portal links only when authorized and applicable.
