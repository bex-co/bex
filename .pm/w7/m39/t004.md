## Objective

The operator now owns the canonical Zot config as a hardcoded Go string literal — policy (`mostRecentlyPushedCount: 5` tag retention, GC intervals) and contract values (htpasswd mount path `/secret/htpasswd`, port `5000`) hand-sync with the deployed registry with no guard. Make retention a knob and guard the contract values against silent drift.

## Context

- `lego/operator/internal/registry/creds.go:477-520` — `baseZotConfig`; the comment at `:474` records it "replaces the Helm-embedded configFiles stanza (removed in w7/m36)", so the operator IS the single source now — the drift risk is against `deploy/gitops/base/zot.yaml` (Deployment mount paths, service port).
- Retention (5 most-recent tags) is a policy choice that will differ per deployment; hardcoding it forces an operator release to change it.
- New env vars must be mirrored into CLAUDE.md's env table and `.env.example`/`.env.template` (repo rule).

## Steps

1. Add `BEX_ZOT_RETENTION_TAGS` (default `5`) read by the operator and templated into the rendered config; document in CLAUDE.md's env table + `.env.example`/`.env.template`.
2. Add a drift guard: a test (or `scripts/gitops-validate.sh` check) that parses `deploy/gitops/base/zot.yaml` and asserts the mount path and port match what `baseZotConfig` renders — a change to either side fails until both agree.
3. Note the single-source arrangement in docs/ADR022-tenant-isolation.md § Per-App pull credentials.
