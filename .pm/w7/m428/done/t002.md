## Objective

Write down, from Render's own sentences, what decides an auto-deploy for every combination of root directory, included paths, ignored paths and where the change is, and mark which cells are inferred.

## Context

- render.com/docs/monorepo-support (read 2026-11-16) says, in order:
  - "If you set a root directory for your service, Render only triggers an autodeploy if your changes affect files anywhere under that directory."
  - "Changes that match an included path will trigger an autodeploy, unless those files also match an ignored path. If you specify at least one included path, all non-matching paths are automatically ignored". "If you don't specify any included paths, all file changes trigger an autodeploy unless they match an ignored path."
  - "Changes that match an ignored path will not trigger an autodeploy, even if those files also match an included path."
  - "Build filter paths are always relative to your repository root, even if you've set a different root directory. This means your build filters can include paths from other directories in your repo."
  - FAQ, on previews: a file "might be ignored because it's outside your service's root directory, or because it matches one of your build filter's ignored paths", and a preview is created when changed files "match the root directory or build filter paths".
- render.com/docs/blueprint-spec: `rootDir`: "Changes to files outside the root directory do not trigger a build for the service." `buildFilter` paths "are always relative to the repo's root directory."
- Recommended reading: included paths decide when set, wherever they point; the root directory decides when none are set; ignored paths always win.
- The one ambiguous cell: a root directory and included paths are both set, and the change is under the root directory but matches no included path. "All non-matching paths are automatically ignored" says no deploy; the FAQ's "match the root directory or build filter paths" could be read as deploy.
