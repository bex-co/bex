## Objective

The push decision follows t002's table: a change that matches an included path deploys even when it is outside the service's root directory, an ignored path always wins, and a service with no included paths keeps the root-directory rule.

## Context

- `redeployMatching` (`lego/backend/internal/apps/webhook.go:1027`) gates on `rootDirMatches` and `buildFilterMatches` together, at `:1046` (checks-pass path) and `:1081-1086` (push path). `rootDirMatches` is at `:1197`, `buildFilterMatches` at `:1223`.
- Ignore reasons: `EventReasonRootDirectory`, `EventReasonBuildFilter` (`lego/backend/internal/store/event_facts.go:122`).
- The AND is recorded on `AppSpec.BuildFilter` in `lego/types/v1alpha1/app_types.go` and in ADR018's Build Filters row. The dashboard's Root Directory hint says "Code changes outside of it don't trigger an auto-deploy" (`dashboard/src/features/services/locales/en.ts:2435`).
- Today a push deploys when it is under the root directory, matches an included path and is not ignored. Under the recommended reading it deploys when it matches an included path and is not ignored. So nothing that deploys today stops deploying.

## Steps

1. Replace the two gates with one decision function that takes the root directory, the filter and the changed paths and returns whether to deploy and, if not, the reason. Both call sites use it.
2. Reasons: included paths set and none matched, or an ignored match, is `build_filter`; no included paths and nothing under the root directory is `root_directory`.
3. Update the `AppSpec.BuildFilter` comment (regenerate the CRD with `make manifests` in `lego/operator/` if its description changes), ADR018's Build Filters row, and the dashboard's Root Directory and Build Filters hints in every locale.
4. Table test over every cell of t002's table. Update existing tests that pinned the AND. Add one property: for any input, a push that deployed under the old rule deploys under the new one.
5. Count production Apps that set both a root directory and included paths and record the number in the milestone README.
