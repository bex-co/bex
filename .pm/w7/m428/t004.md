## Objective

Once the production pin carries t001 and t003, prove definition-of-done items 1–4 on production with real pushes.

## Context

- The definition of done in `.pm/w7/m428/README.md`.
- The fixture is a GitHub repository the QA account can push to and that the production GitHub App can read, with `backend/` and `shared/` directories. w1/m181 t006 used a real repository for its checks-pass walk; reuse it or create one under the QA account.

## Steps

1. Confirm the newest `pin platform images to <sha>` commit on main contains this milestone's commits. If not, park the milestone in `blocked/` with that release gate named. If no pushable fixture repository is available, park it naming that resource.
2. Create a free web service in `bex-canary` on the fixture with Auto-Deploy on.
3. Push six commits, one per skip phrase, each changing a file that would otherwise deploy. Each must record `commit_ignored` and open no deploy. Then push an ordinary commit and see it deploy.
4. Set `rootDir: backend` and `buildFilter.paths: ["shared/**"]`. Push a change under `shared/` only: it deploys. Add an ignored path that also matches and push again: it does not.
5. Clear the included paths and push a change outside `backend/`: it does not deploy.
6. Record timestamps, the pin, the commit ids and the event rows in the milestone README. Delete the service and record the by-id `GET` 404.
