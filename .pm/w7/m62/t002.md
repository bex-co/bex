## Objective

Fix ADR045 Finding 6: with `BEX_TENANT_SANDBOX_NAMESPACES` off, `NamespaceReconciler.ReconcileOnce` omits `<ws>-sandbox` from the desired set, so `pruneOrphans` deletes a still-live sandbox namespace (and its running sandboxes) for an **existing** workspace — prune keys on the config toggle rather than workspace existence. Gate `<ws>-sandbox` reaping on the workspace being gone, regardless of the toggle (i.e. treat the toggle as create-only).

## Context

- `lego/backend/internal/store/namespaces.go:282-302` — `pruneOrphans`.
- `w7/011` (retiring into this task); severity low — the flag is operator-controlled and monotonic in practice — but a rollback today is destructive.

## Steps

1. Change the desired-set/prune logic so a `<ws>-sandbox` namespace for a live workspace is never a prune candidate when the toggle is off.
2. Regression test: toggle off + live workspace ⇒ sandbox namespace survives reconcile; workspace deleted ⇒ both `<ws>` and `<ws>-sandbox` pruned (toggle state irrelevant).
