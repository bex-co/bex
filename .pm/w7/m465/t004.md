## Objective

Give an admin a "require Google login" setting beside `require_two_factor`, with the same rules for who may change it and when.

## Context

- `require_two_factor` comes from migration `0261_workspace_require_two_factor`. It is read through `twofactor.Settings` and set by `setWorkspaceRequireTwoFactor` (`lego/backend/internal/workspaces/graphql.go:308`). The guards and plan gate are tested in `internal/workspaces/twofactor_test.go`.
- `core.RecordTwoFactorEnforcement` writes the audit row, and `internal/audit/service.go:219` maps the verb to `ChangeTeam2FAEnforcementEvent`.
- `internal/audit/render_inventory_test.go:44` lists `ChangeTeamAllowedLoginMethodsEvent` as a non-goal.
- `core.FeatureTwoFactorEnforcement` is in `internal/core/plan_gate.go`. The plan-table guard is `internal/pricing/plan_table_test.go`.

## Steps

1. Add a migration with `tenants.require_google_login` (default false) and the audit column for the value it was set to. Add the store read and write.
2. Add `Workspace.requireGoogleLogin` (readable by every member) and `setWorkspaceRequireGoogleLogin` (admins only) on GraphQL, plus the schema snapshot. Apply the plan gate t001 chose: below Pro, turning it on is 400 `PLAN_FEATURE_REQUIRED`, and a workspace that already enforces it keeps it.
3. Refuse to turn it on when the enabling admin is not signed in with Google right now (the lock-out 409), when no identity lookup is wired, and on the default workspace, as the 2FA setting does.
4. Record the change as `ChangeTeamAllowedLoginMethodsEvent` with the value it was set to. A no-op writes no row. Move the event from non-goal to mapped in `render_inventory_test.go`.
5. Invalidate the gate's cached setting on change, as `twofactor.Gate.Invalidate` does.
