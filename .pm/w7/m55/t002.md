## Objective

Extend the t001 harness from service verbs to the HTTP layer: enumerate every registered REST route via the `RegisterREST` seam (~186 routes across 24 register functions) and assert a non-member caller receives 403/404 on each — closing the route→verb binding gap (a route wired to the wrong verb, or an adapter that resolves the target workspace before authorization, currently escapes every test).

## Context

- Routes are registered per-service through `RegisterREST()` functions (24 sites across `lego/backend/internal/*`); the router assembly lives in `lego/backend/internal/api/server.go`.
- Credential-less routes that mount outside the auth gate (webhooks, deploy hooks, device flow, discovery, healthz) are principled exclusions — they were separately audit-verified 2026-07-30 and have no workspace-member semantics.
- The two-workspace fixture and allow-own/deny-other checker come from t001.

## Steps

1. Enumerate registered routes mechanically (walk the mux/router or the `RegisterREST` registrations) — no hand-maintained route list.
2. For each route, synthesize a minimal valid request as the workspace-A caller targeting the workspace-B resource; assert 403/404, never 2xx.
3. Add the completeness guard: a registered route missing from the matrix (and not on the documented exclusion list) fails the test.
4. Record exclusions (public/credential-less routes) in-test with one-line justifications.

## Files

- `lego/backend/internal/api/crossworkspace_matrix_test.go` (extend)
- `lego/backend/internal/api/server.go` — read-only reference for route registration; add an enumeration seam only if strictly necessary

- [ ] All ~186 registered routes are either asserted-denied for a non-member or on the justified exclusion list.
