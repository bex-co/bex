## Objective

Record how Kratos reaches Bitbucket, which speaks OAuth 2.0 but not OpenID Connect, before building it.

## Context

- Kratos v26.2.0 has no `bitbucket` provider (`selfservice/strategy/oidc/provider_config.go:186-214`), and its `generic` provider needs OIDC discovery, which Bitbucket does not serve (`https://bitbucket.org/.well-known/openid-configuration` is 404).
- Dex (dexidp.io) has a `bitbucketcloud` connector and is an OIDC provider, so Kratos's `generic` provider can point at it. `scripts/auth-oidc-e2e.sh` already runs `dexidp/dex:v2.41.1` as a stand-in.
- ADR012 §10 keeps social login "pure Kratos config + Ory Elements rendering — no custom auth code, and no custom login provider". A discovery document plus a userinfo shim in bex-api would be custom auth code.
- Kratos and Hydra keep their state in the CNPG clusters of `deploy/gitops/base/auth-dbs.yaml`. Kratos's public endpoint is `auth.<base-domain>`.

## Steps

1. Read the pinned Dex release's `bitbucketcloud` connector: the scopes it asks for, how it picks the email (primary, confirmed), what it sets as `email_verified`, `name` and the subject, and what the Bitbucket OAuth consumer needs (callback URL, the Account Email and Read permissions).
2. Decide, and write into ADR012 §10 as a recommendation under Render parity first:
   - the bridge: Dex, with Kratos's `generic` provider at its issuer as provider id `bitbucket`;
   - Dex's public issuer URL (for example `https://auth.<base-domain>/dex`), which the browser must reach for `/auth` and `/callback`;
   - Dex's storage (Postgres on the auth CNPG, Kubernetes CRDs, or memory with one replica) and what a restart loses;
   - how its secrets arrive: the Bitbucket pair, and the Dex static client's secret that Kratos uses, minted by `scripts/auth-secrets.sh` into out-of-band Secrets like every other auth secret;
   - that nothing renders, or no pod runs, while the Bitbucket pair is unset.
3. Name the rejected alternatives with one line each: a bex-api shim (custom auth code), and waiting on an upstream Kratos provider (none exists or is planned).
