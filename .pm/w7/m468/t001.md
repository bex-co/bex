## Objective

Offer "Sign in with GitLab" wherever the installation sets a GitLab OAuth application, the same shape as GitHub and Google.

## Context

- `scripts/lib/kratos-oidc-fragment.sh` writes the Kratos `oidc.yaml` fragment, one provider per `BEX_*_OIDC_CLIENT_ID`/`_SECRET` pair, `enabled: false` when no pair is set. Its login and registration hooks mirror the password flow and are emitted whenever any provider is on.
- Kratos v26.2.0's `gitlab` provider (`selfservice/strategy/oidc/provider_gitlab.go`) uses `https://gitlab.com` unless `issuer_url` is set, and reads claims from `<issuer>/oauth/userinfo`. GitLab's userinfo carries `email` and `email_verified`, so the mapper can mark a GitLab-verified email verified, as Google's does.
- The callback is `https://auth.<base-domain>/self-service/methods/oidc/callback/gitlab`. The application is created at gitlab.com → Preferences → Applications, with scopes `read_user openid email`.
- `scripts/auth-secrets.sh` calls the fragment and prints `providers ENABLED: …` in `DRY_RUN=1`. `deploy.yml` passes each pair to it. `scripts/auth-oidc-verify.sh` lists the providers.

## Steps

1. Add `kratos_oidc_gitlab_provider` (`id: gitlab`, `provider: gitlab`, `label: GitLab`, scopes `read_user openid email`, the verified mapper) and enable it on `BEX_GITLAB_OIDC_CLIENT_ID` + `BEX_GITLAB_OIDC_CLIENT_SECRET`. Keep the flows block's condition "any provider on".
2. Add a test-only `KRATOS_OIDC_GITLAB_ISSUER` that registers `gitlab` as a `generic` provider at that issuer, as `KRATOS_OIDC_GOOGLE_ISSUER` does for Google: the built-in provider calls `/oauth/authorize`, `/oauth/token` and `/oauth/userinfo`, which a Dex stand-in does not serve.
3. Add the pair to `.env.example` (with the callback URL and where to create the application), `deploy.yml`'s auth-secrets step, `scripts/auth-secrets.sh`'s header and `DRY_RUN` providers line, `scripts/auth-oidc-verify.sh`'s disabled hint and the local `kratos.values.yaml` comment.
4. Extend `scripts/kratos-oidc-fragment.test.sh`: GitLab only, all providers in a stable order, a client id without its secret, the provider, scopes and label, the mapper, and the hooks.
5. Update ADR012 §10 and ADR027 for GitLab.
