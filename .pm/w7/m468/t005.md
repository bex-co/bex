## Objective

Prove the two new providers end to end on production's Kratos version, as m465 proved Google.

## Context

- `scripts/auth-oidc-e2e.sh` runs Kratos v26.2.0 and Dex v2.41.1 in one network namespace, loads the fragment from `kratos_oidc_fragment`, and drives the browser dance in a cookie jar: the login flow's oidc nodes and labels, sign-up through the stand-in, `/sessions/whoami`, a fresh browser signing back in, and the settings guard.
- Dex can serve several static clients, so one Dex can stand in for more than one provider id.

## Steps

1. Register stand-ins under `gitlab` (through t001's issuer override) and `bitbucket` (through t004's), beside `google`.
2. Assert the login flow carries every enabled provider's node with its label ("Sign in with GitLab", "Sign in with Bitbucket").
3. For each new provider: sign a new person up, check the mapped email, its verified state and the session's `oidc` method with that provider, then sign back in from a fresh browser as the same identity.
4. Assert that with neither new pair set the login flow carries neither node.
