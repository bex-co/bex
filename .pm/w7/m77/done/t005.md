## Objective

Make every hostname bex hands a tenant resolve from where that tenant actually runs — the third failure leg. Co-location makes CNPG's bare `dpg-<id>-rw` correct again for in-namespace consumers, but the injected value should be correct by construction rather than by coincidence, and the external/pooler/public-SNI forms must be re-checked against the new namespace.

## Context

- `lego/backend/internal/apps/deploy.go:455` `dbPropertyKey` maps `host` → CNPG's `host` key (bare service name); `connectionString`/`connectionPoolString` → `uri`. The production failure was `PG::ConnectionBad: could not translate host name "dpg-<id>-rw"` from a pod in `tea-…`.
- `resolveDatabaseRef` (`deploy.go:1732`) uses `<id>-app`, and `<id>-pooler-app` for `connectionPoolString` — the pooler Secret is a separate object that must also be co-located.
- `resolveKeyValueRef` (~`deploy.go:1760`) points at the KeyValue CR-named Secret (`kv.Status.SecretName = kv.Name`, ADR021).
- Public forms are unaffected by namespace in principle — `lego/operator/cmd/pg-sni-proxy/main.go:120` routes from `db.Namespace` on the CR — but `BEX_DB_DOMAIN`/`BEX_KV_DOMAIN` hostnames and the reported `internalAddress`/connection-info surfaces must be re-verified, not assumed.
- Related contract: `docs/ADR041-service-addresses.md` owns the internal/public address rules and already fixed a bare-name resolution gap once.

## Steps

1. Verify what CNPG and the Valkey reconciler actually write into the `host` key and `uri` after the move, from an in-namespace consumer's point of view.
2. Decide short-name-plus-co-location versus explicit FQDN, and apply it consistently across `host`, `uri`, and the pooler variant — the injected value should not depend on the consumer happening to be co-located.
3. Re-verify the external/public hostnames still route through the SNI proxies for a datastore in a tenant namespace.
4. Re-verify the reported connection-info and `internalAddress` surfaces match what a pod would actually resolve.
5. Make t002's hostname test pass.
