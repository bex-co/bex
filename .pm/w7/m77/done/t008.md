## Objective

Check that this milestone's change is consistent across every surface it exposes — REST, GraphQL, and MCP in `lego/backend/`, plus the `dashboard/` UI — and against the equivalent render.com behavior, flagging any drift as follow-up work rather than diverging silently.

## Context

- The namespace move changes where a user-facing resource lives and what its connection info reports; `docs/ADR006-bex-api.md` is the one-core/thin-adapters contract.
- Surfaces to check: Postgres and Key Value connection info (internal/external URLs, `internalAddress`), the Blueprint `fromDatabase`/`fromService` contract (`docs/ADR049-render-yaml-parity.md`), and any place a namespace leaks into a user-visible identifier or error.
- Render exposes no namespace concept at all — so the parity question is whether bex now leaks one anywhere it previously did not.
- `docs/ADR018-render-parity.md` is the ledger to update if a cell's evidence changed.

## Steps

1. Compare the Postgres/Key Value connection-info fields across REST, GraphQL, and MCP for the same resource; confirm identical semantics and error shapes.
2. Confirm the dashboard's connection-info and Blueprint views still show correct, copyable values.
3. Check no namespace string leaks into a user-facing id, URL, or error message that did not carry one before.
4. Update the parity ledger where evidence changed; file genuine gaps as follow-up notes instead of widening this milestone.

### Outcome (2026-08-08)

Consistency here is structural rather than something to re-verify by hand: all three adapters resolve from the same `PostgresConnectionInfo` / KeyValue view (ADR006's one-core/thin-adapters rule), so there is no per-surface assembly that could drift, and `internal/api/conformance_test.go` is the standing guard. It passes.

No namespace leakage: grepping the REST/GraphQL/MCP model and adapter files for `Namespace` returns nothing, and the only "namespace" in `dashboard/src` is ADR047's `bex-agent/*` **git branch** namespace — unrelated. Render has no namespace concept, so the correct outcome was for this change to be invisible at the API boundary, and it is.

Two user-visible changes, both parity **improvements**:

- **Postgres/Key Value creation is now capped** (t006). Render's Hobby plan allows 1 Postgres and 1 Key Value; bex enforced neither because the quota dimensions counted nothing. All three caps now return the identical Render-shaped 400. `docs/ADR006-bex-api.md` § Per-workspace resource caps is updated; the parity ledger has no caps row, and ADR006 is its right home, so no ledger change.
- **`PSQLCommand` is namespace-qualified** (t003). It is copied out of the dashboard into arbitrary shells, so it must not depend on where the reader sits.

**Dashboard suite:** 1977/1977 tests that ran passed. Two test *files* failed to load — `agent-sessions/lib/transport.ts` and `session-conversation-impl.tsx` cannot resolve `ai` / `@ai-sdk/react`. Both are declared in `package.json` but absent from the local `node_modules`, i.e. a stale local install, not a regression: this milestone changes no dashboard file (`git status dashboard/` is empty) and no GraphQL schema. A fresh CI install resolves them.
