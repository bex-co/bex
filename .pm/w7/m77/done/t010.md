## Objective

Add meaningful tests for what this milestone shipped, beyond t002's three regression legs — asserting real behavior and failure modes, never gaming coverage with tautological or snapshot-everything tests.

## Context

- t002 pinned the three original legs. This task covers what the fix itself introduced: namespace placement on create, the legacy strategy, per-tenant backups, quota enforcement, and connection-string shape.
- The bug's defining property is that each leg was invisible until the previous one was fixed — so tests should be able to fail independently rather than through one composite path.
- Integration tests gated on `BEX_TEST_DB_URI`/`BEX_TEST_OPENFGA_URL` **do** run in CI against real ephemeral Postgres + OpenFGA (`.github/workflows/backend-test.yml`), so they are worth writing.

## Steps

1. Cover datastore CR placement on create, for both Postgres and Key Value.
2. Cover the t001 legacy strategy explicitly, including its removal condition if it has one.
3. Cover quota rejection (t006) and per-tenant backup wiring (t004).
4. Cover the connection-string forms from t005, including the pooler variant.
5. Confirm each new test fails for its own reason when its own behavior is broken.

### Outcome (2026-08-08)

Coverage added across the milestone, each file pinning one mechanism:

| File | Pins |
| --- | --- |
| `apps/datastore_namespace_test.go` | legs 1 + 3 (t002) — failed on `main` with the incident's exact symptoms |
| `store/datastore_reachability_test.go` | co-location is sufficient; out-of-namespace is denied; D8.3 control peers admitted; arbitrary namespaces still refused; sandbox unchanged |
| `store/datastore_quota_test.go` | every kind landing in the namespace is charged; free caps are genuinely tighter than paid |
| `core/quota_test.go` (+2) | both datastore cap messages; keys do not cross |
| `core/datastore_resolution_test.go` | D8.1 in all three positions — own namespace, shared namespace, another workspace's — plus NotFound shape, lookup order, list scoping, pod-namespace threading |
| `postgres/`, `keyvalue/namespace_placement_test.go` | direct-create placement, and the unbound path unchanged |
| `controller/datastore_secret_plane_test.go` | uncached Secret plane, nil-fallback, backup projection + no-op path, ownerReference absence, pre-deploy mirror |

Three verified **anti-tautologically** — revert the fix, watch the test fail with the message that explains the production symptom, restore it, watch it pass: the Secret-plane routing, the D8.3 allow, and the pre-deploy mirror. The `gitops-validate.sh` guard for `enableDefaultDeny.egress: false` was checked the same way.

Two deliberate choices worth recording:

- **Relationships, not literals.** Every placement assertion compares against `store.WorkspaceNamespace(tenant)` or the App's own namespace rather than a `"tea-a"` string, so renaming the namespace scheme cannot pass a test while breaking every link.
- **Negatives paired with positives.** The quota test has a "free is tighter than paid" companion (equal caps would satisfy the positive test while capping nothing — close to the state being fixed); the D8.3 allow has "arbitrary namespaces still denied"; the reachability test has the RFC1918-exception test the denial depends on. The corrected `PurgeByTenant` test likewise now separates *other namespace* from *other tenant*, which the original fixture conflated.

One test premise was wrong and the code was right: the cross-workspace resolution case returns `Forbidden`, not success, because the caller is not a member. Rewritten to assert **Forbidden and not NotFound** — which is the actual contract (403-before-404), and a stronger check than the one originally specified.
