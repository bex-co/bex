## Objective

Make managed Postgres and Key Value CRs (and the Secrets the operator derives from them) live in the workspace's `<ws>` namespace alongside its Apps, and update every caller that reads them, per the t001 checklist. This single change closes all three failure legs at once: co-location makes `secretKeyRef` resolvable, `allow-same-namespace` sufficient, and the CNPG short-name host correct — which is exactly why pre-migration tenants silently worked.

## Context

- Creation sites: `lego/backend/internal/postgres/service.go:493` and `lego/backend/internal/keyvalue/service.go:402` both use `s.Namespace` (`BEX_API_NAMESPACE`, i.e. `default`).
- `lego/backend/internal/core/base.go:264-274` — `AppNamespace(tenantID)` already resolves the per-tenant namespace for Apps; its doc comment explicitly carves out Databases/KeyValues and must be updated with the code.
- **Resolution contract (ADR043 D8.1, settled by t001):** creation computes the target (`AppNamespace(tenantID)`); every read resolves the CR's **actual** namespace by lookup, mirroring `Base.appNamespaceByName` + `preferOwnWorkspaceNamespace` for Apps. A caller holding the CR uses `d.Namespace`/`kv.Namespace` directly; only a name-only caller does the lookup. This is permanent, not transitional — so there is **no legacy branch to write**: a CR still in the shared namespace resolves there through the same code path.
- **No RBAC change needed** (verified t001): `lego/operator/config/api/rbac.yaml` already grants bex-api cluster-wide `get/list/watch/create/update/patch/delete` on `databases`/`keyvalues`, and `deploy/gitops/base/tenant-namespace-clusterroles.yaml`'s `bex-tenant-api` (bound per-`<ws>` by the NamespaceReconciler) already grants Secrets/pods/pods-log/jobs/ingresses there.

### Outcome (2026-08-08)

All three regression legs pass; the whole backend module is green and `make lint-backend` reports 0 issues.

Seams added in `core.Base`: `TenantNamespace` (the renamed `AppNamespace`, which always computed this — `AppNamespace` stays as a thin alias so App call sites keep reading naturally), `DatastoreNamespaces` (ordered lookup candidates), and `DatastoreListOptions` (cluster-wide + `LabelTenant`). `AuthorizeDatabase`/`AuthorizeKeyValue` now resolve through `findDatabase`/`findKeyValue`: the acting workspace's namespace, then the shared one, then a cluster-wide sweep for the cross-workspace case — mirroring `AuthorizeApp`'s direct-candidates-then-fallback shape, with a synthesized `apierrors` NotFound so callers' 403-before-404 handling is untouched.

**Three findings beyond the checklist, each a silent-empty failure rather than an error:**

1. **Datastore logs and metrics queried the shared namespace** (`logs/service.go` durable-store reads + label discovery, `metrics/datastore.go` disk/connections/replication-lag/KV-stats). Prometheus series and Loki streams are namespace-labeled, so a migrated datastore would have returned an empty series with no error — the exact shape of the known App-side logs bug. Now threaded from the CR.
2. **`core.ListByTenant` pinned `b.Namespace`**, so `PurgeByTenant` would have reclaimed nothing on workspace delete — leaving real CNPG clusters and Valkey volumes billing with no owner. It is now label-scoped cluster-wide (every caller passes an App/Database/KeyValue list, never Secrets). Its test asserted "stays in the base namespace" with a fixture that conflated *other namespace* with *other tenant*; rewritten to assert the invariant that actually matters — one tenant's resources are reclaimed wherever they live, another tenant's are spared.
3. **Usage metering listed datastores in one namespace**, so post-migration instances would have been silently **under-billed**. Now cluster-wide, with each CR's namespace carried into the Prometheus selectors.

`PSQLCommand` is now qualified with the Database's own namespace — it is copy-pasted by humans from anywhere, so it must not depend on where the reader happens to sit.

Eleven pre-existing tests asserted the old placement (`Namespace: "default"` on a workspace-resolved create); each was incidental to what the test actually checks, and was repointed rather than reinterpreted.
