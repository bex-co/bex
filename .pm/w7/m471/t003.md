## Objective

An Org Owner can ask who an org-wide requirement would block across the org: every person in an org workspace (Guests included) and the org's own members, with their keys.

## Context

- Org setters: `lego/backend/internal/workspaces/organizations.go`, `organizations_api.go` (GraphQL fields at lines 126-160). Owners only change the setting, so the read uses the same check as `setOrganizationRequireTwoFactor`.
- People: `store.PGStore.OrganizationMemberWorkspaces(orgID)` (subject → org workspace ids, `lego/backend/internal/store/organizations.go:247`) and `ListOrganizationMembers(orgID)`.
- ADR012 §9c, "Who is held to it": every person in an org workspace and their API keys and SSH keys, under the workspace key rules.

## Steps

1. Add `organizationLoginRequirementImpact(organizationId: String!, requirement: LoginRequirement!): LoginRequirementImpact!`, reusing t002's types and its per-member assessment. Each API key also names its workspace, so the Owner can tell which workspace a key belongs to. Add a `workspaceName` field to the key type, empty on the workspace read.
2. Assess against the requirement being turned on, ORed with the org's own settings. A member listed in two workspaces appears once.
3. Tests: a non-Owner is refused; one unenrolled Guest in one org workspace is listed with that workspace's key; an org where every person is enrolled lists nobody.
