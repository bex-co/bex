## Objective

On Workspace Settings, turning on "Require two-factor authentication" or "Require Google login" opens a confirmation that lists, from t002's read, each member who would lose access and each API key and SSH key that would stop working. Confirming writes the setting. Turning a requirement off still writes at once.

## Context

- `dashboard/src/features/workspaces/components/workspace-login-requirement-card.tsx:96` sends the mutation on toggle today.
- The org card's dialog is the pattern to follow (`organization-security-card.tsx:66-115`, `ConfirmDialog` from `common/components/confirm-dialog.tsx`, which takes `children` between the description and the footer).
- Render's sentences to mirror: "Each listed member will lose access … until they …" and "Each listed API key will be invalidated until its owner …" (docs/render-artifacts/login-settings.md § Organizations).
- Strings go through `useTranslations()` with entries in all eight `features/workspaces/locales/*.ts` (`locale-parity.test.ts`; use `_one`/`_other` plurals for counts, and 你 in zh).
- GraphQL documents live in `features/workspaces/api/workspaces.graphql`. Reconcile `src/graphql/definitions.ts` with the offline codegen in `dashboard/AGENTS.md` (`TestDumpGraphQLSchema`, then `SCHEMA_JSON=… yarn codegen`, keeping only this feature's hunk).

## Steps

1. Add a shared list component, for example `features/workspaces/components/login-requirement-impact-list.tsx`, that renders members (name or email, "loses access" or "keys only") with their key names, then keys with no recorded creator. The empty state reads that every member meets the requirement. Google login adds one line: members signed in another way will be asked to sign in with Google.
2. The dialog runs the query when it opens (`network-only`). While loading, a skeleton with the list region's bounds is shown, and confirm stays enabled. On failure, a "could not check who would lose access" line is shown and confirm stays enabled.
3. Wire the workspace card: toggling on opens the dialog; confirming calls `setRequired(true)`; cancelling leaves the switch off. A locked card (org requires it) and a below-Pro card never open it.
4. Component tests in `features/workspaces/components/__tests__/`: one unenrolled member with keys is listed; an empty answer shows the all-clear line; the loading skeleton; the error line; turning off does not ask.
