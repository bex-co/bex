## Objective

A workspace admin can ask, before turning a requirement on, who it would block in that workspace: members, their API keys bound to the workspace, their SSH keys, and keys with no recorded creator.

## Context

- Setter and lock-out guard: `lego/backend/internal/workspaces/service.go:1209-1404` (`SetRequireTwoFactor`, `SetRequireGoogleLogin`, `setLoginRequirement`, `guardLoginRequirement`). The gate reaches this service through `GoogleLogin` (wired at `lego/backend/internal/api/server.go:895-896`). The read needs the gate's new assessment from t001, so widen that dependency or add one beside it.
- Members: `WorkspaceStore.ListTenantMembers` (people are `Kind == store.MemberKindUser`). Emails and names come from `Identities.LookupMany`. Render's `userId` comes from `OwnerIDsForSubjects` (w6/m7). Never expose the raw subject.
- API keys: `apikeys.APIKeyStore.List` plus `KeyBinder.TenantForKey` (the scoping `ListAPIKeys` does, `lego/backend/internal/apikeys/service.go:431-462`), grouped by `CreatedBy`.
- SSH keys: `store.PGStore.ListSSHKeys(subject)` (`lego/backend/internal/store/sshkeys.go:84`). They belong to the account, not the workspace, but the gate blocks them in this workspace.
- GraphQL fragment: `lego/backend/internal/workspaces/graphql.go`. Golden schema: `lego/backend/internal/api/testdata/schema.graphql` (`UPDATE_SCHEMA_GOLDEN=1 go test ./internal/api -run TestGraphQLSchemaMatchesTheGolden`). Authz sweeps: `TestAuthzGuardsEveryVerb`, and `scope_matrix_ops.go` for the operation's scope.

## Steps

1. Add the verb `Service.LoginRequirementImpact(ctx, workspaceID, requirement)`. Authorize it with `core.RelCanManage` on the exact workspace, as the setter is authorized. Assess each person against the requirement being turned on, ORed with what the workspace already requires.
2. Return members who lose access, and members who keep access but have keys that would stop working. Each member has `userId`, `email`, `name`, `losesAccess`, `apiKeys {id name}` and `sshKeys {id name fingerprint}`. Also return `unattributedApiKeys`: workspace keys whose creator is empty or not a Kratos identity. The default workspace answers empty.
3. A lookup that cannot answer (Kratos, Hydra or the store) fails the whole read with `core.ErrAuthzUnavailable`. Never answer an empty list in that case.
4. Expose it as `workspaceLoginRequirementImpact(workspaceId: String!, requirement: LoginRequirement!): LoginRequirementImpact!`, with a `LoginRequirement` enum `TWO_FACTOR | GOOGLE_LOGIN`. Update the golden and the scope matrix (read scope).
5. Tests in `lego/backend/internal/workspaces/` with fakes: one unenrolled member with a bound API key and an SSH key is listed with both; an all-enrolled workspace lists nobody; an unattributed key is listed; Google login with an unstamped key does not list it; a non-admin is refused; a failed lookup is unavailable, not empty.
