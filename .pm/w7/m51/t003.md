## Objective

Create Stripe-hosted test-mode Checkout setup sessions for the workspace's existing Customer without creating a second Subscription or handling card data in bex.

## Context

- `internal/billing/stripe.go` resolves Customers by `bex_workspace` metadata.
- Dynamic payment methods must remain enabled; do not send `payment_method_types`.

## Steps

1. Resolve the unique Customer and complete bex Subscription before session creation.
2. Create a setup-mode Checkout Session with signed/scoped metadata and validated success/cancel URLs.
3. Add a random eight-letter suffix to the required `integration_identifier` and keep idempotency bounded to one request.

## Files

- `lego/backend/internal/billing/stripe.go`
- `lego/backend/internal/billing/sessions.go`

## Acceptance criteria

- [ ] Checkout accepts Stripe test payment methods and never exposes an API key to the caller.
- [ ] No `payment_method_types` field is sent.
- [ ] Cross-workspace and duplicate-Subscription cases fail closed.

## Out of scope
