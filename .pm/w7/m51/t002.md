## Objective

Define one provider-neutral core result for payment readiness plus short-lived Checkout and Portal session creation so every adapter shares authorization, ownership, and error semantics.

## Context

- m50 already guarantees one metadata-keyed Customer and one complete metered Subscription per billable workspace.
- The dashboard must remain a first-party Kratos-session client; it must not receive Stripe server credentials or become a Hydra OAuth client.

## Steps

1. Specify readiness states, allowed workspace roles, redirect-origin validation, and degraded behavior.
2. Define core request/result types for Checkout setup and Customer Portal sessions.
3. Record why setup-mode Checkout augments the existing Subscription instead of creating a duplicate subscription.
