# FUTURE / MAYBE — deferred ideas, revisit when the trigger is met

Not anti-goals (those live in [DO_NOT_DO.md](DO_NOT_DO.md)) and not committed roadmap (that's the `wN/mN` milestones). These are ideas that are **correct in principle but premature now** — each has a concrete **trigger** that should bring it back onto the board. When running `/pm-brainstorm` or `/pm`, don't schedule these unless their trigger is met; when a trigger _is_ met, promote the item to a real milestone/task.

## Deferred

- **Hetzner server-quota raise + full m19 target shape (3×CP · 3×platform · OpenBao 3/3).** The account's server limit (5) forced the w1/m19.1 interim: 1 CP + 2 platform + 1 tenant, self-managed, the bootstrap node destroyed (`bex-infra`, since renamed `bex-bootstrap`). Parked here by user decision 2026-07-11 — the interim shape serves prod. When picked up: request the limit (~10) in Hetzner Cloud Console → revert two TEMP numbers in [`infra/clusterapi/overlays/hetzner-caph/cluster.yaml`](../infra/clusterapi/overlays/hetzner-caph/cluster.yaml) (KCP `replicas: 1`→`3`, platform pool max `"2"`→`"3"` — both carry `TEMP (m19.1)` comments, grep for them) → push (CI applies; KCP webhook allows only odd counts) → machines self-materialize → `openbao-1` schedules and only needs an **unseal** (2026-07-11 update: the first prod init already happened via the 2 running pods — `BAO_ALLOW_INIT=1` + `BAO_ADDR` port-forward path; keys in `.env` + GH secrets via `gh-secrets.sh`; k8s auth + snapshot role configured; backup chain verified end-to-end; env-vars API live) → close out `w1/m19` t009's quorum/HA acceptance lines. **What the interim costs until then:** single etcd copy (machine loss = restore from nightly snapshot), no safe CP rolls (k8s upgrades blocked), OpenBao on a 2-member raft (both pods must be up for writes; third member joins at quota), one fewer platform-node failure domain. **Trigger: user decides to raise the quota, or any CP-touching change becomes necessary (k8s upgrade, cert config).**

- **Off-provider backup replica.** All backups (etcd snapshots, pg dumps, OpenBao snapshots) live in Hetzner Object Storage — same provider as the cluster; a provider-level failure or account lockout takes prod and its backups together. Cheap fix: nightly sync of the backup prefixes to a second S3-compatible provider (R2/B2, cents/month). Surfaced during the m19 rebuild's failure-domain review 2026-07-11. **Trigger: first paying tenant, or any compliance conversation.**

- **Subscription / invoices / payments (the billing half of pricing & spend).** The pricing/estimate half landed via `w8/m7` (see Done below); this half remains deferred — w6 declared billing/payments out of scope ("bex has no billing system"; Render's flat-subscription + inactivity-waiver model is documented in `.pm/w6/RESEARCH-workspaces.md` finding 6). **Trigger: a hosted bex offering becomes roadmap-worthy**, at which point start the subscription model from RESEARCH-workspaces.md and consider `lego/types/tiers/tiers.yaml`'s "prices are Metronome's" forward pointer.

- **Durable/shared state for bex-api's replica-local in-memory buckets.** Three shipped features hold correctness-relevant state in process memory, explicitly "adequate for the single-replica worker": the deploy-hook rate limiter (`lego/backend/internal/deploys/deployhook.go:190` — token bucket is replica-local), the outbound-webhook failure-notice suppression (`lego/backend/internal/webhooks/worker.go:160` — `emailedAt` map; a restart re-emails, a second replica double-emails), and the outbound-webhook **delivery worker** itself (single-replica caveat recorded in `w3/done/m11/done/t003.md` — "distributed delivery-worker scaling across replicas… a follow-up if it matters"; `worker.go:55` records that two bex-api replicas would **double-deliver every event** — a distributed claim (SKIP LOCKED) is the multi-replica follow-up; added by `/pm-brainstorm` round 17, 2026-07-15). Correct in principle to move all onto a durable/shared store or leader-elected/partitioned workers, premature while bex-api runs exactly one replica. Filed by `/pm-brainstorm` round 12, 2026-07-15. **Trigger: bex-api scales past one replica (HPA or manual), or a restart-duplicated failure email is actually observed.**

- **Build-artifact caching/reuse for repo-backed `deploy_only`.** `w2/done/m30/done/t003.md` deferred it explicitly: "Building real build-artifact caching/reuse to make `deploy_only` genuinely true for repo-backed services — a materially bigger feature… starts from this task's honest-rejection baseline." Real parity substance (Render caches builds by default; faster rebuilds would also cut build-minutes usage), and BuildKit's registry cache export/import is the natural mechanism given the ephemeral-worker pipeline (`docs/ADR034-scalable-build-pipeline.md`) — but the why-now is weak while builds work and nobody is blocked. Filed by `/pm-brainstorm` round 17, 2026-07-15. **Trigger: build times become a user complaint, or real `deploy_only` demand appears for repo-backed services.**

- **microVM runtime tier for tenant workloads (Kata / gVisor `RuntimeClass`).** The isolation ladder's next rung after w7's namespace tier ([DO_NOT_DO.md](DO_NOT_DO.md) §vcluster: "namespace (default) → microVM (Kata/Firecracker/gVisor, hard)"). Kernel-sharing is w7's accepted residual risk: NetworkPolicy + Pod Security baseline bound the blast radius, but a kernel exploit still crosses tenants on the same node. Deferred 2026-07-09 (w7 creation) because it's hard — node images must ship the runtime, CAPH node provisioning changes, and per-pod overhead fights bex's dense bin-pack economics — and the pre-GA threat model doesn't demand it. **Trigger: public GA / open signup with untrusted tenants** — revisit as an operator `RuntimeClass` knob per App or per plan tier.

- **OpenBao auto-unseal.** `w1/done/m38/done/t003.md` deferred auto-unseal as "a separate design decision, not this milestone" without filing it anywhere — recorded here by `/pm-brainstorm` round 16, 2026-07-15. Manual Shamir unseal is real toil: every platform-node roll or OpenBao pod restart needs an operator with `.env` keys (the platform-pool image roll was already deferred partly on this — see the node bring-up entry's `w1/022` pointer), and it's a 2-member raft until the quota raise. Design is non-trivial on Hetzner (no native KMS): candidates are a cloud-KMS auto-unseal (external dependency + credential), transit auto-unseal via a second small bao, or accepting scripted unseal with the existing GH-secrets custody (`docs/ADR013-secrets.md`, `docs/ADR037-openbao-rekey-runbook.md`). Correct in principle, premature while rolls are rare and rehearsed (`w1/m38` drill). **Trigger: the platform-pool roll is picked up, or a second manual unseal is needed within any single month.**

## Done (trigger met, work landed)

- **Pricing & spend estimation (price sheet on the tier catalog, $ estimates)** — deferred 2026-07-09 from `/pm-brainstorm w8` (w8 metered quantities only — instance-seconds by tier, egress bytes, build minutes — with no price sheet); **TRIGGERED 2026-07-13 by user request** for the pricing/estimate half, promoted to `w8/m7`, and **landed** (closeout done): 30% off Render's captured compute/Postgres/KeyValue/build-minute prices, 90% off bandwidth, surfaced as `estimatedCost` over the usage rows on REST/GraphQL/MCP + dashboard, with no payment collection anywhere in the path. See `.pm/w8/done/m7/`. The subscription/invoices/payments half stays in Deferred above.

- **Traefik LB survives cluster rebuilds (stable origin IP)** — TRIGGERED 2026-07-15 by the planned DR/rebuild work, promoted to `w1/m41`, and **landed 2026-07-15**. Terraform adopted the existing production `bex-traefik` LB in place, owns its stable identity, and applies both Hetzner API `delete_protection` and Terraform `prevent_destroy`; hcloud CCM v1.33.0 owns the dynamic cluster projection and adopts it through `load-balancer.hetzner.cloud/name`. Two scratch clusters reattached one temporary LB with the same ID/IP, then the live Traefik Service was deleted and self-healed with a new UID while production LB `7115248`, both public IPs, targets, and HTTP health stayed unchanged. See `.pm/w1/done/m41/` and [`docs/ADR002-architecture.md`](../docs/ADR002-architecture.md#stable-production-edge-load-balancer).

- **Node bring-up efficiency: baked snapshot image + trimmed preKubeadmCommands** — TRIGGERED 2026-07-13 (zot pullable end-to-end via `w1/m26`), promoted to `w1/m36` 2026-07-14, **landed 2026-07-15**. Baked a Hetzner `bex-worker` snapshot (packer + a `workflow_dispatch` CI bake) carrying runc/containerd/kubelet, pointed the worker `HCloudMachineTemplate`s at it, dropped the `kubeadm config images pull`, trimmed the apt list, and cached clusterctl in `app-cluster.yml`. The **tenant pool rolled live**: node Ready in 54 s vs ~101–218 s, zero github.com/pkgs.k8s.io downloads, apps healthy. The download was cheap on Hetzner's network — the real win is **fragility** (no external dependency in the autoscaler hot path). The **platform-pool** roll was deferred to `w1/022` (pre-flight found it blocked on CNPG single-instance HA + OpenBao Shamir unseal — a separate platform-resilience effort). The roll also surfaced a latent registry-auth gap (fresh nodes can't pull authed zot images — `w7/001`).

- **Cilium WireGuard node-to-node encryption** — deferred 2026-07-09 as a structural no-op on one node; the trigger ("cluster gains a second node") was met by the w1/m19 rebuild, which shipped multi-node with `encryption.enabled=true / type=wireguard / nodeEncryption=true` live (pinned to the CAPH private interface, `devices=enp7s0`). See `.github/workflows/app-cluster.yml` + m19 t006 op log.
