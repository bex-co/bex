# Shared native base images

`native-base-image.yml` publishes PostgreSQL-client-equipped derivatives of the official runtime images reviewed in `native.go`. `matrix.py` reads those pins directly, including historical lines, so the publishing list cannot silently retain the former 16-line inventory. Publication does not change the operator's runtime image pins.

The package recipe installs PostgreSQL 18 clients and their normal Debian library/resource closure. It selects PGDG's signed archive for Bullseye and the live signed repository for Bookworm/Trixie. The signing key is pinned by SHA-256. System packages are resolved during image publication; adopting the result requires reviewing the immutable image digest, SBOM, package inventory and tests. The workflow signs and attests candidates only after a real PG18 archive converts to the exact three expected rows, without network, on both amd64 and arm64. An invalid archive must fail. The fixture was generated by official PostgreSQL 18 (`archive.sql`), not fabricated archive bytes.

For a local candidate:

```sh
docker build --build-arg BASE_IMAGE='<reviewed official image@sha256:digest>' \
  -t bex-native-check deploy/native-base
docker build --build-arg NATIVE_BASE=bex-native-check \
  -f deploy/native-base/check.Dockerfile deploy/native-base
```

Candidates use `ghcr.io/bex-co/bex-native:<upstream-tag>-<commit>` and are published for `linux/amd64,linux/arm64`. Review the workflow's per-line digest and SBOM before a separate pin commit under ADR060 D7. Never substitute a mutable tag into tenant builds. A successful candidate build alone does not establish native-generator, exact-patch, companion, hosted-service or other-tool acceptance; w8/m91 and the individual tool milestones retain those checks.
