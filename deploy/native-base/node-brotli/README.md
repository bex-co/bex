# Brotli backport for existing Node lines

`patch.sh` rebuilds the exact four EOL Node releases currently reviewed in `native.go`, replacing only the bundled Brotli C tree with Google's matching security release and exposing the new format-error constant. It rebuilds [Render's two dated Node 24 defaults](#renders-dated-node-24-defaults-w3m672) with Node's own in-tree fix instead. It replaces `/usr/local/bin/node`, preserves npm, and refuses an unreviewed old Node patch. The Dockerfile inspects the primary's Node header without executing its binary; only Node 14/16/18/20 copy their original `/usr/local` into the pinned Bullseye compiler stage, after clearing the builder's prefix. All four compile with that baseline's GCC and Python 3.9. Only the repaired executable and source record are copied back into the original primary, whose environment remains authoritative. Other language images and modern Node primaries receive no replacement executable.

Bullseye is the oldest reviewed companion base. A Node 20 build on Bookworm required GLIBC 2.34 and GLIBCXX 3.4.30 and failed before startup on the Python 3.7 and Ruby 3.0 Bullseye images; the original portable binary ran there. The compiler baseline therefore applies to every backported Node line, including those whose primary image uses Bookworm. The shared publication check executes the exact candidate binary against the pinned Bullseye baseline as well as its own primary image.

Sources reviewed 2026-10-29:

- [Google's decoder fix](https://github.com/google/brotli/commit/0ed4268a4401abcb4472096340477cf4af7d1a2b), released as [1.0.10](https://github.com/google/brotli/releases/tag/v1.0.10) and [1.1.1](https://github.com/google/brotli/releases/tag/v1.1.1). Node 14/16 bundle 1.0.9; Node 18/20 bundle 1.1.0. The fixed archives are locked by SHA-256 in the script.
- Official Node source checksums: [14.21.3](https://nodejs.org/dist/v14.21.3/SHASUMS256.txt), [16.20.2](https://nodejs.org/dist/v16.20.2/SHASUMS256.txt), [18.20.8](https://nodejs.org/dist/v18.20.8/SHASUMS256.txt), [20.20.2](https://nodejs.org/dist/v20.20.2/SHASUMS256.txt).
- Node's [companion fix and regression](https://github.com/nodejs/node/commit/b5f41529df78a8af7b395abd6a97d2dcb6c52c61) supplies the malformed block-switch input used by `check.js`. Both synchronous and one-byte streaming decoders must reject it with error -17; ordinary compressed input must still round-trip.

Each candidate must compile and pass these checks on both amd64 and arm64 before adoption. Compilation also compares the original Node version, module ABI, N-API, V8, libuv, OpenSSL, zlib and ICU versions and verifies npm's version is unchanged. Its source record remains inside the image under `/usr/share/bex-node-brotli/sources.txt`; the shared image security gate installs and runs the network-free decoder probe separately. Copy only `patch.sh` into the compilation layer, so changing a probe does not invalidate an expensive Node rebuild. The malformed probe emits about 16 MiB before the expected error and caps output at 64 MiB. A system-package update alone cannot repair the statically bundled Node decoder. This backport addresses this Brotli issue; it does not claim all security issues in EOL Node have been repaired.

## Render's dated Node 24 defaults (w3/m672)

Render gives a Node service with no version signal 24.14.1 when it was created from 2026-04-21 and 24.21.0 from 2026-09-17 (`exactDefaults` in `lego/operator/internal/build/nativeversion.go`). Both bundle Node's own Brotli 1.2.0 tree from before the fix. Node 24.22.1, the line's first fixed release (w1/135), repaired it in-tree and still reports `1.2.0`, so Google's 1.0.10 and 1.1.1 archives do not fit. `patch.sh` applies Node's own cherry-pick instead and keeps every reported version, Brotli's `1.2.0` included:

- [nodejs/node@49dff6f57aa7](https://github.com/nodejs/node/commit/49dff6f57aa72cbbe13e480cd41ff4e46837c8fc) ("deps: brotli: cherry-pick 0ed4268a4401abcb44720963", CVE-2026-111497) changes only `deps/brotli/c/dec/decode.c` and `deps/brotli/c/include/brotli/decode.h`. Its `deps/brotli` diff is vendored as `node-24-brotli-49dff6f57aa7.patch`, SHA-256 `1e9ee182923958541a120582078b087380ab38e6850153cdc3cdec33cf331876`, because a generated GitHub diff is not a stable checksum input. Its pre-image blobs (`e87e7f5ea0f9`, `8d436db733c9`) are the files both releases ship. After it applies, the script checks that both files are byte-for-byte Node 24.22.1's, and the whole `deps/brotli/c` tree then equals 24.22.1's.
- [nodejs/node@b5f41529df78](https://github.com/nodejs/node/commit/b5f41529df78a8af7b395abd6a97d2dcb6c52c61) exposes the -17 constant. The script's `node_zlib.cc` edit is that one line, as for the EOL lines.
- Official Node source checksums: [24.14.1](https://nodejs.org/dist/v24.14.1/SHASUMS256.txt) `7822507713f202cf2a551899d250259643f477b671706db421a6fb55c4aa0991`, [24.21.0](https://nodejs.org/dist/v24.21.0/SHASUMS256.txt) `a6f54defb6fd7c84f41dba13d61e78e9b4e0961712cf61f29715c05f5ced94fc` (read 2026-11-26).

Node 24 needs GCC 12.2, which Bullseye lacks, so the publication Dockerfile compiles these two in a separate Bookworm stage with Bookworm's system Python. Final tenant images all start from the Bookworm common base, so a Bookworm-built executable runs wherever these releases run. The script refuses any other 24.x below 24.22.1 as unreviewed, leaves 24.22.1 and later alone, and refuses the `--common-bookworm` tenant-build mode for Node 24: these two are published donors (`nativeRuntimeArtifacts`), never compiled in a tenant build. Another exact 24.x patch a tenant selects with `NODE_VERSION` keeps its official image, with no repair claim (ADR060 D7 addendum).

The whitelist covers the four reviewed image releases and the two dated Node 24 defaults, not every historical exact patch a tenant can request. An exact-primary overlay copied from an unpatched official image can replace the repaired executable. Adopting these images must preserve the patched path for matching reviewed versions and explicitly account for other exact versions; never claim those are repaired by this recipe.
