## Reconciliation and asynchronous work

- Live capability grants, rather than role names, decide whether a notification's event and route are currently accessible. Confirmed denial removes matching persisted rows. Unknown/unavailable checks hide content and badges without converting an outage into deletion.
- The remote inbox is a bounded recent page. Missing rows alone do not prove global absence: merging preserves still-authorized older history and local read acknowledgments. An empty successful page is distinct from an error; confirmed destination removal is applied separately, including when no rows remain.
- Session, subject, workspace and data-boundary generation guard receipts, opens, registration and refresh results. Store mutations serialize across instances sharing a key; a write crossing a reset rolls back before a new store can reconcile. Badge writes serialize globally, with current-state checks.
- Initial responses remain available while startup is unresolved. Initial and listener paths dedupe by response identifier. Wrong binding, closed-envelope failures and confirmed denial terminate without routing; a notification never selects a workspace. Disposed listeners cannot overwrite a newer pending response.
- Logout hides protected state synchronously before scoped storage removal and best-effort remote unregister. Registration controllers belong to an effect lifetime, so cleanup/recovery cannot reuse a disposed controller.
