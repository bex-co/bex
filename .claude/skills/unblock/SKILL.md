# Task: 用中文帮助 worker 解除阻塞

`/unblock <wN>`（Codex：`$unblock wN`）。目标是让读者花最少的理解成本，作出足以让 worker 继续工作的决定：**读 blocked → 讲清情况 → 决策或行动 → 写回 board → 交给 loopx**。解释、选项、提问和交接用简体中文；保留任务 ID、代码名和必要的英文术语。

接受 `w4`、`.pm/w4/` 或该 workstream 的 `blocked/` 路径，归一化为仓库内 `.pm/wN/`。没有目标时询问，不默认选 w4；路径不明确或 workstream 不存在时说明问题，不新建队列。

## 1. 读全卡点，只展开有用的证据

- 先读 `.pm/AGENTS.md`、`.pm/DO_NOT_DO.md` 和 [pm](../pm/SKILL.md)。所有 board 写入均通过 pm；恢复待办使用其 `unblock` 子命令。
- **先对齐最新代码再判断过时。** 运行 `git fetch origin main`；在本地 main 上可安全快进时，运行 `git pull --ff-only origin main`。保留本地与其他会话的改动，不为核查而 reset、clean、stash 或提交。快进被拒或当前不是 main 时，用 `git show origin/main:<path>` / `git ls-tree` 读取最新 board 和代码，并对照本地相关 diff；fetch 失败则用可用 checkout 继续，明确尚未验证最新远端状态。记录核查的 commit SHA，不能凭旧 board 的描述下结论。
- 枚举目标 `blocked/` 下的 milestone 和 inbox note，跳过嵌套 `done/`。对照 workstream README 中的 BLOCKED 标记，指出目录与索引的漂移；目录不存在或为空时仍做这个核对。
- 阅读每个 blocked milestone 的 README、尚未完成的任务，以及每个 blocked inbox note；按需追溯代码、相关决定、部署版本和证据。不要把每个 evidence 文件或完成记录都塞给读者。大量条目分批读取，最后覆盖全部 blocked 项。
- 核实旧卡点是否仍成立。凭已有授权、仓库规则或只读检查能消除的不确定性，自己查清，不变成用户选择题。例如已部署的版本、已完成的上游任务、现有 QA 登录入口。不要打印凭据，外部操作仍遵守现有授权。
- **先清理过时项，再向用户提问。** 目标已实现且原 DoD 已验证 → 附 commit、代码或测试证据，通过 pm 关闭；重复、前提失效或已被替代 → 附证据和替代项 ID，通过 pm 清理，保留有价值的历史；只是旧卡点消失、仍有实现或验证工作 → 恢复待办交给 loopx。只需 worker 自行核实的事实不留作用户决策。仅有代码合入证据时，不能关掉仍要求线上验收的项。
- **按共同卡点归组，而非每个文件问一次。** 每组列出全部受影响的 ID；共享一次部署或同一个决定的条目只解释一次，但逐项核实它们各自的条件。跨 workstream 依赖可读取，写入只限目标 workstream。
- **对标产品决定推荐方向（用户偏好 2026-10-30）。** 托管（hosting）面向客户的行为对标 render.com（[ADR008 § Render parity first](../../../docs/ADR008-vision.md#render-parity-first)）。云端编码 agent（agent sessions、`/agents`、沙箱、PR 交付）对标 Devin（[ADR047](../../../docs/ADR047-cloud-coding-agent-sessions.md)）。
  - 推荐项必须是与对标产品一致的那一项。推荐前先核实对标产品的实际行为，不凭记忆；说明“Render / Devin 怎么做”，并作为推荐理由写出来。
  - 与对标产品不一致的选项可以列出，但不能作为推荐项，并要讲明它造成的偏离。偏离只有经用户签字、记录进 [ADR018](../../../docs/ADR018-render-parity.md)（Render）或相应 agent ADR（Devin）后才成立。
  - 可选增强不能挡住对齐所需的实现：先按对齐方案恢复，更严或更松的变体另开条目。已有规则或对标产品的行为能决定的做法，直接记为复核结论，不再要求用户拍板。确需产品取舍、外部资源或用户专属操作的才交给用户。

## 2. 先让人理解，再选择沟通方式

开场给一个能快速扫完的中文概览：多少条目、多少个共同卡点、哪些可直接恢复、哪些要决定、哪些要外部动作。按能释放的工作量和处理成本排序，先处理容易解开的共同卡点。

每组用短句回答：**本来要做到什么 → 现在差什么 → 为什么 worker 自己过不去 → 需要你决定或做什么 → 之后 worker 能做什么**。区分已证实事实与待核实推断。只保留支持判断的证据链接；不要只抄任务标题、历史日志或一串术语。

**从客户角度讲场景和选项。** 解释卡点和每个选项时，尽量描述 bex 的客户（在 bex 上托管服务或使用编码 agent 的开发者）实际会经历什么：在哪个页面、CLI 命令或 API 调用里做了什么，看到什么、等多久、出错时得到什么提示，之后能不能继续。例如写“客户在 dashboard 点 Deploy 后，状态一直停在 Building，十分钟后才报错，日志里看不到原因”，而不是“reconcile 超时未上报 condition”。对比选项时，写清每个选项下客户的体验有什么不同，以及 render.com 或 Devin 的客户在同一场景下看到什么；技术细节放在后面，作为补充说明。确实没有客户可见影响的（纯内部机制、CI、运维）要直说，并改从运营者或 worker 的角度描述后果。

按问题的理解成本选择方式，同一轮可以混用：

| 情况 | 方式 |
| --- | --- |
| 多个相互独立、背景短、后果明确的选择 | 小批量 wizard：一轮通常 2–3 题，给推荐项与实际代价 |
| 一个简单决定 | 直接问一个短问题，不搭多轮流程 |
| 有复杂背景、相互依赖的取舍或重要后果 | 每次专门讨论一个主题，先解释，再问最关键的问题 |
| 缺账号、权限、资源、部署或观察结果 | 给具体行动卡：谁、在哪里做什么、怎样确认完成 |
| 卡点已消失或规则已决定 | 附证据直接通过 pm 恢复或关闭，无需用户重复确认 |

### 简单项：批量 wizard

- 使用当前模式可用的提问工具；没有时用简短编号选项。每题给足独立理解所需的背景，通常 2–3 个互斥选项，推荐项放前面，用客户会经历的具体体验说明每个选项的结果或代价。推荐项按上文对标规则选：托管选与 render.com 一致的，编码 agent 选与 Devin 一致的，并在选项说明里写明对标依据。不要用无意义的选项凑数。
- 给决策稳定编号（如 D1），并映射到全部受影响的 board ID。允许 `D1=A，D2=B` 这样的快速回复。按用户答案调整后续题，不先抛完整长问卷。
- 相互依赖的决定依次问；不要把还没澄清的复杂问题混进“全部同意推荐项”。用户明确说“这批都按推荐”时，仅应用于已经展示且后果讲清的这一批。
- 推荐项、预选值、沉默和超时都不等于决定。等待答案时可继续独立核查，不能替用户写下尚未给出的答案。

### 复杂项：专门对话

先用一个具体的客户场景讲清现状、影响和真正的取舍（客户做了什么、现在会遇到什么、各条路径下会变成什么样），再给建议及理由（建议同样服从对标规则：托管对齐 render.com，编码 agent 对齐 Devin）；通常比较 2–3 条可行路径，每次只问推进讨论最关键的一件事。用户追问时先解释清楚，不急着收敛成选择题，也不让用户替 worker 做普通技术设计。

复杂讨论不拖住已确定的独立事项：及时记录已作决定。适合另开对话时提供可直接接续的短上下文（相关 ID、背景、证据、待决定问题），不声称已创建新会话。用户希望先实现已决定的部分时，先交接这一批，其余保留待讨论。

### 外部动作：行动卡

写清“需要谁在什么地方完成什么动作、最小需要什么信息、什么证据能证明就绪”。例如“管理员在现有 QA 环境配置登录凭据；worker 用 `scripts/qa-login.sh` 验证能登录”，而不是让用户把密码贴进对话。能由 worker 按已有授权完成的动作交给 worker，不让用户代劳；确认行动计划后仍要核实实际条件，不能把“同意做”当作“已经做完”。

## 3. 每个决定及时写回 board

收到明确答案或取得足够复核证据后，调用 **`/pm unblock <wN/item> <结论与证据>`**，按 pm 的规则记录并决定是否恢复。不等所有复杂项聊完才保存；未答问题保持待定，不凭空补齐。

让接手的 worker 只读 board 就能开工，不依赖本次对话。用中文在原条目中记录：

- 日期、涉及 ID、结论来源（用户明确决定 / 现有规则 / 本次复核证据）。
- 具体采用什么、适用范围和理由；写明对标依据（render.com 或 Devin 的实际行为，或不适用的原因）；必要时说明未采用的方案，避免再次争论。
- 剩余阻塞、责任人、解除条件；明确哪些仍待用户决定。
- worker 下一步的具体动作、依赖、验收条件和证据入口。若影响原步骤或 DoD，同步更新，不能为了移出 blocked 把未达成的验收删掉。

决定充分且实施条件已具备才恢复待办；还有真实外部门槛就留在 blocked。恢复的是待实施或待验证的工作，不能因此标记 done。已经满足原 DoD 的，附证据按 pm 关闭，不制造新的实现任务。重跑时复用已有决定，只处理新事实或仍未解决的部分。

## 4. 把实现交给 loopx

决策和写回完成后，核对实际路径、状态和链接，给出简短中文交接：**已恢复哪些 ID、worker 接下来做什么；仍阻塞哪些 ID、等谁做什么**。不能把只写了意见、仍留在 blocked 的条目算成交接成功。

有恢复项时，读取并接续 [loopx](../loopx/SKILL.md)，将实现与验证交给 **`/loopx <wN>`**（Codex：`$loopx wN`）；不在 unblock 阶段抢做实现。说明 loopx 会按其规则处理该 workstream 的全部开放队列，不只本次恢复项。

默认在本轮决策结束后实际接续 loopx，不只说“可以运行”。如果用户明确要求仅讨论、稍后执行，或仍在等本轮必要答案，先保存已确认决定并留下准确的交接命令，不擅自启动。没有恢复项时报告剩余条件，不为清空 blocked 而强行恢复。

接续时遵守 loopx 前置条件和仓库的提交授权规则；`/unblock` 本身不新增 `git commit` / `push` 权限。若当前会话缺少执行条件，明确交接尚未启动及具体原因，保留已经写好的 board。
