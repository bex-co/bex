# backend/CLAUDE.md

The **backend** module (`github.com/bex-co/bex/lego/backend`) is the **business-logic** layer. It builds **bex-api** (`cmd/api`, the `/api` entrypoint) — the Render-compatible REST/GraphQL/MCP surface plus OpenFGA authz, API-key auth, and metrics — and the separately deployed **SSH gateway** (`cmd/ssh-gateway`, the `/ssh-gateway` entrypoint). It imports the `types/` module (the CRD contract) and **never** the `operator/` module: it writes _intent_ (App CR spec patches), the operator converges it. Build/test from here (`go build ./... && go test ./...`); the shared `make` targets, `config/`, and codegen live in `../operator`.

## Layout

Organized **by feature** (one package per feature), not by technical layer. A feature = one Go package holding its **service** (business logic) + **models** + the **REST/GraphQL/MCP registration fragments** as files inside it.

- `cmd/api/` — the bex-api entrypoint. `api mcp-stdio` (or `BEX_MCP_STDIO=1`) serves only the MCP adapter over stdio for a local agent.
- `cmd/ssh-gateway/` — the isolated public-key SSH entrypoint. Its Deployment alone receives namespaced `pods/exec`; bex-api never does.
- `internal/core/` — the **leaf kernel** every feature imports: `Base` (client + namespace + clock + the `Authorize` gate + `AuthorizeApp`/`AuthorizeDatabase`/`AuthorizeKeyValue`/`AppPods`), the caller `Identity`, the error sentinels, the shared HTTP/cache helpers (`WriteErr`, `DoJSON`, `TTLCache`, …), and `Poll`/`PollWake`/`PollTicks` — the one background-worker loop, which every worker whose step **returns** its errors runs on (a worker that logs internally and returns nothing keeps its own loop; see the godoc). Imports the CRD types, nothing else in bex.
- `internal/hmacticket/` — the **one signed-token envelope** every ticket flavor shares (`internal/shellticket`, `internal/sandboxexec`, `internal/agentsessionticket`): wire format, constant-time signature check, clock skew, and single-use nonce. A flavor owns only its `Claims` shape and required-claim rules, and builds its sentinels with `hmacticket.New("<flavor> ticket")`. A leaf. The three flavors each carried their own copy until they drifted (one had silently lost the future-dated check); a conformance suite (`flavors_test.go`) now holds every flavor to one contract. Signed tokens that are **not** this scheme stay out on purpose: `internal/github/state.go` (different framing) and `internal/drivergrant` (Ed25519, so an in-sandbox driver verifies with a public key alone).
- `internal/id/` — the **one place** typed resource ids are minted + validated (`id.New(kind)`, `id.WellFormed`, `id.KindOf`): `<prefix>-<xid>`, hyphen-separated so ids stay valid DNS/k8s names. A leaf (imports only `xid`); the store delegates to it. ADR + the format guard test: [docs/ADR020-identifiers.md](../../docs/ADR020-identifiers.md).
- `internal/<feature>/` — one package per feature: `apps` (lifecycle + plans), `logs`, `metrics`, `apikeys`, `sshkeys`, `postgres` (managed Databases), `secrets` (OpenBao-backed env vars), `deploys` (rollout history), `events` (the per-service activity feed — a read-time VIEW over `deploys` + `audit_events`, writing nothing of its own). Each API feature has `service.go` (verbs, each starting with `s.Authorize`) + `models.go`/render shapes + `rest.go`/`graphql.go`/`mcp.go` fragments. `sshgateway` is the protocol-to-Kubernetes-exec boundary used only by its command — its root package is the shared kernel (`Executor`/`KubeExecutor`, `Metrics`, `SessionLimiter`, `NonceGuard`, `TargetResolver`, terminal helpers), with one sub-package per transport (`nativessh`, `webshell`, `sandboxsse`, `agentattach`, `agentcred`), the `dbrole` grant surface, and shared test fakes in `gatewaytest`; `cmd/ssh-gateway` shares ONE limiter + nonce guard across all transports so caps and ticket single-use stay process-wide. `authz` is the OpenFGA checker (satisfies `core.Checker`); `gqlutil` is the shared GraphQL resolver helper.
- `internal/store/` — the **control-plane store** (docs/ADR003-control-plane.md): Postgres migrations (`tenants`/`apps`/`domains`), the rows→App-CR reconciler, and the internal tenant API (`BEX_CP_ADDR`, default :8091). Opt-in: wired by `cmd/api` only when `BEX_CP_DB_URI` is set.
- `internal/billing/` — the backend-only Stripe Billing feature: sealed `usage_hourly` rows → metadata-keyed Customers and metered Subscriptions; invoice reads, comps, Stripe-hosted payment/Portal onboarding, fail-closed Tax activation, and signature-verified webhook intake; one authorized service with REST/GraphQL/MCP adapters. Opt-in via `BEX_STRIPE_SECRET_KEY`; the operator never imports it.
- `internal/api/` — the **composition root**: wires the feature services behind one auth gate (`auth.go`) and assembles the three surfaces as **single artifacts** — one REST router, one GraphQL schema, one MCP registry (`server.go`). It imports the features + `core`; features never import it (no cycle). See [`internal/api/CLAUDE.md`](internal/api/CLAUDE.md).

## Rules

- **Never import `operator/`** (mechanism). Cross-layer contact is only through `types/` and the `App` CR.
- **Mint resource ids through `internal/id` only** (`id.New(kind)`) — never concatenate a prefix by hand. Typed opaque `<prefix>-<xid>`, hyphen-separated (underscores are illegal in DNS/k8s names); a new id kind is registered in `internal/id` and the guard test holds it to the format + DNS-safety contract ([docs/ADR020-identifiers.md](../../docs/ADR020-identifiers.md)). This module is linted (`.golangci.yml`, run via `make lint` / `make lint-backend` from `lego/operator/`): depguard forbids importing `github.com/rs/xid` outside `internal/id`, so a hand-rolled id fails lint.
- **One service per feature, three adapter fragments, Render-consistent.** A verb has a single implementation in its feature's `service.go`; its REST/GraphQL/MCP fragments are thin presentation that _register into the single shared roots_. A change to one surface fans out to the other two. Never fragment the roots themselves (one schema / one router / one registry). Full rules in `internal/api/CLAUDE.md`.
- **A verb scoped to ONE named resource (App/Database/KeyValue) starts with `a, err := s.AuthorizeApp(ctx, core.Rel…, name)`** (or `AuthorizeDatabase`/`AuthorizeKeyValue`) — the single seam that authorizes AND fetches in one call, against the **resource's own workspace** (its `core.LabelTenant` label), never the caller's default one (w6/m17, [../../docs/ADR012-auth.md](../../docs/ADR012-auth.md) § Which workspace a resource-scoped verb authorizes against). **Never** pair a separate `s.Authorize`/`s.AuthorizeTarget` call with a fetch of the same resource — that reintroduces the exact bug this seam closed: two independent gates (caller's default workspace, then the resource's) make effective permission their INTERSECTION, so a caller who is admin of their OWN workspace but merely invited elsewhere could be wrongly refused on their own service. A verb with no single named resource (`List`, `InstanceTypes`, a create) still starts with plain `s.Authorize(ctx, core.Rel…)`. `TestAuthzGuardsEveryVerb` sweeps every verb for its guard; `TestFetchByNameUsesTheVerbsOwnRelation` (`internal/api/relationguard_test.go`) sweeps for a lingering two-gate split.
- **`AuthorizeApp`/`AuthorizeDatabase`/`AuthorizeKeyValue` always record a target** (`core.ServiceTarget`/`DatabaseTarget`/`KeyValueTarget(name)`) on the audit event, which is what puts a write verb in that service's events feed (`internal/events`, docs/ADR006-bex-api.md § Service events) — a write relation (`can_operate`/`can_create`/`can_manage_keys`/`can_manage_ssh_keys`/`can_manage`) always reaches the sink, allowed or denied; a read relation (`can_view`/`can_view_logs`/`can_view_sensitive`) reaches it only when DENIED (`core.Base.emit`'s `writeRelations`/`readRelations` gate, w4/m20/t001) — an allowed read stays unrecorded (volume). `internal/events` still filters to allowed-only, so a read denial never pollutes a service's activity feed; it's audit-log-only. `TestEveryTargetedVerbIsNamedOrExcused` forces a new WRITE verb to be named in the event vocabulary or excused with a reason, so it can't go silently missing from the feed. Pass a resource NAME, never a value — that is the whole reason no secret can reach an event.
- **A create takes its workspace from the request context.** REST binds Render's `ownerId`, GraphQL binds its `ownerId` argument, and MCP middleware binds the per-call `workspaceId` before the feature handler runs. Empty means the caller's default (oldest) workspace; a workspace the caller is not a member of is `ErrForbidden`, never a silent create in their own.
- The Postgres source of truth (control plane) lives here as `internal/store/`, **opt-in via `BEX_CP_DB_URI`** ([../../docs/ADR003-control-plane.md](../../docs/ADR003-control-plane.md)); with it unset the binary is bex-api alone.
