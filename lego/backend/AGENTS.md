# backend/AGENTS.md

The **backend** module (`github.com/bex-co/bex/lego/backend`) is the **business-logic** layer. It builds **bex-api** (`cmd/api`) — Render-compatible REST/GraphQL/MCP + OpenFGA + API keys + metrics — and the isolated **SSH gateway** (`cmd/ssh-gateway`). It imports `types/` and **never** `operator/` — it patches App CR _intent_, the operator converges it. Build/test from here (`go build/test ./...`); `make` targets + `config/` live in `../operator`.

## Layout — by feature, not layer

One package per feature: service (business logic) + models + REST/GraphQL/MCP fragments.

- `cmd/api/` — bex-api entrypoint (`api mcp-stdio` / `BEX_MCP_STDIO=1` → MCP over stdio)
- `cmd/ssh-gateway/` — isolated public-key SSH entrypoint; only Deployment with `pods/exec`
- `cmd/objectgw/` — the public bucket gateway (`pub-<obk-xid>.<BEX_BASE_DOMAIN>`, read-only, no database or write credential; [ADR112](../../docs/ADR112-object-storage.md) D4). Its environment is three credentials and nothing else.
- `internal/core/` — leaf kernel: `Base` + `Identity` + sentinels + `Authorize` gates + `TTLCache` + `Poll` workers. Imports CRD types only.
- `internal/hmacticket/` — one HMAC envelope for `shellticket`/`sandboxexec`/`sandboxfiles`/`agentsessionticket`; each flavor owns only `Claims`. Leaf.
- `internal/id/` — typed ids `<prefix>-<xid>` (`id.New(kind)`, `id.WellFormed`). Leaf. [ADR020](../../docs/ADR020-identifiers.md)
- `internal/<feature>/` — `apps`, `logs`, `metrics`, `apikeys`, `sshkeys`, `postgres`, `secrets`, `deploys`, `events` (read VIEW over `deploys`+`audit_events`). Each `service.go` + `rest.go`/`graphql.go`/`mcp.go`.
  - `sshgateway` — protocol→exec boundary; shared `Executor/SessionLimiter/NonceGuard/TargetResolver` + `nativessh/webshell/sandboxsse/sandboxfiles/agentattach/agentcred/modelproxy/egressproxy`; one limiter/guard across transports.
  - `authz` (OpenFGA `core.Checker`), `gqlutil` helper.
- `internal/store/` — control-plane Postgres + App-CR projector, opt-in via `BEX_CP_DB_URI` ([ADR003](../../docs/ADR003-control-plane.md))
- `internal/billing/` — Stripe Billing (opt-in `BEX_STRIPE_SECRET_KEY`), sealed `usage_hourly` → Customers/Subscriptions, invoices, webhooks.
- `internal/objectstorage/` — the object store of [ADR112](../../docs/ADR112-object-storage.md): workspace buckets as Postgres rows over one shared Wasabi bucket per region (region, name, key and cap constants; quota gate, stream limiter, presigned and streamed Wasabi client, CORS rules, the hourly sweep: four workspaces at a time, cut off at its interval, a region relisted only after a gap that grows with its last object count (one hour per 100 objects, at most 72, because Wasabi counts what a listing reads as egress; `sweepbudget.go`), `bex_usage_object_storage_sweep_*` metrics including `_listed_bytes_total`, every series exported at zero by each replica, watched by `ObjectStorageSweepStale` and `ObjectStorageSweepCutOff` with [a runbook](../../docs/runbooks/object-storage-sweep.md), ADR112 D8), with a fake S3 in `fakes3/`. Two thin adapters in `internal/api` call it: Render's `/v1/objects` routes (`objects_render.go`) and the Cloudflare-shaped routes `wrangler r2` calls under `/cloudflare/client/v4` (`cloudflare_r2*.go`, each answer Cloudflare's envelope; pinned by `testdata/wrangler-*/requests.json` and `scripts/wrangler-r2-contract.sh`); they are also served on the DNS-only host `objects.onbex.co` (`lego/operator/config/api/ingressroute-objects.yaml`, label reserved as `publichost.APILabel`) because Cloudflare's proxy in front of `api.bex.co` refuses a body over 100 MiB and wrangler puts up to 300 MiB. Environment variables carry only the credential (below). `internal/objectstorage/publichost/` is the leaf that knows a public bucket's host (`pub-<xid>` for `obk-<xid>`), shared by the routes, the gateway and `store.CreateApp`'s slug reservation.
- `internal/objectgw/` — the public bucket gateway's code ([ADR112](../../docs/ADR112-object-storage.md) D4), one package for both ends of its two calls: bex-api's `verbs.go` (host to bucket lookup and the egress report, on `:8091` only, behind a static bearer) and the gateway's resolver, Wasabi origin (signed GET/HEAD with the visitor's `Range` and conditional headers), CORS, caps, object cache, byte meter and metrics. A test forbids it from reading the environment.
- `internal/api/` — composition root: one auth gate (`auth.go`) + one REST router / one GraphQL schema / one MCP registry. See [`internal/api/AGENTS.md`](internal/api/AGENTS.md).

## Rules

- **Never import `operator/`**. Cross via `types/` + App CR only.
- **Ids via `internal/id` only** (`id.New(kind)`), hyphen-separated; depguard forbids `xid` elsewhere. [ADR020](../../docs/ADR020-identifiers.md)
- **One service per feature, three thin fragments, Render-consistent.** Verbs live in `service.go`; fragments map wire formats onto single roots (one schema/router/registry). See `internal/api/AGENTS.md`.
- **Authz seam:** single-resource verbs start `a, err := s.AuthorizeApp(ctx, core.Rel…, name)` (or `Database/KeyValue`) — fetches + authorizes against resource's OWN `LabelTenant`. Other by-id verbs route first with `ctx, err = s.ScopeByID(ctx, ownerID, owner)` (the resource's own workspace), then make their one `s.Authorize`; answers follow [ADR072's by-id matrix](../../docs/ADR072-security-review-round7.md#by-id-resolution-matrix-amendment-w5m115-2026-10-05). Bare `s.Authorize` with no routing only for `List` and for creates that take no parent id. Swept by `TestAuthzGuardsEveryVerb`, `TestFetchByNameUsesTheVerbsOwnRelation` and `byid_resolution_guard_test.go`. Never split into two gates. The audit verb is the verb method on the stack: a path that reaches the seam from a closure, a goroutine, a worker's step or a method value names it (`AuthorizeAs`, `AuthorizeAppAs`, … or `core.WithAuditVerb`), and `TestNoAuthorizationReachesAVerbThroughAClosureOrAMethodValue` fails one that does not (w21/093).
- Target always recorded (`ServiceTarget/DatabaseTarget/KeyValueTarget`; an object or bucket row `BucketTarget/ObjectTarget`) for events feed; write relations always emit, read only on denial. The reads that also record a success are the closed set `core.auditedViews` (env var values, connection info, an object's download); `core.recordView` refuses any other verb. `TestEveryTargetedVerbIsNamedOrExcused` enforces vocabulary.
- **Workspace from request context** (REST `ownerId`, GraphQL `ownerId`, MCP `workspaceId`). Empty → for a Render REST list, every workspace the caller belongs to (`core.Base.ListOwnerIDs`, w8/m149; an API key's machine identity keeps its single workspace), the default workspace for GraphQL/MCP lists, the resource's own for a by-id verb (ADR072's by-id matrix); non-member → `ErrForbidden`.
- **Workspace 2FA** (w22/m402, [ADR012 §9a](../../docs/ADR012-auth.md#9a-workspace-enforced-two-factor-authentication-w22m402)): `core.Base.TwoFactor` (`internal/twofactor`) is asked by the authorize funnel after every positive decision (workspace and `agent_session:` objects), so a member without a TOTP/WebAuthn factor — or an API key they created — gets `403 WORKSPACE_2FA_REQUIRED` on REST, GraphQL and MCP alike. A verb a blocked member must still reach (`workspaces.List`, `CurrentUser`, `members.LeaveWorkspace`) calls `core.WithTwoFactorExempt` first; nothing else may. Admin toggle: GraphQL `setWorkspaceRequireTwoFactor`, which turns it on only on Pro and higher (`PLAN_FEATURE_REQUIRED`, w7/070); a workspace that already enforces it keeps it. The SSH gateway has no Kratos client, so its own `core.Base.TwoFactor` is `sshgateway.TwoFactorGate`: it asks bex-api's HMAC verb `POST /v1/workspace-two-factor` (`agentsession.TwoFactorHandler` over the real gate; closed identity methods `ssh`/`shell`/`agent-attach`/`sandbox-exec`, never an API key) and caches answers 30 s (a setting-off workspace once for every member), failing closed on any error. That one hook covers native SSH (admission, every channel, every revalidation tick; the client's banner/channel refusal names the requirement), the web shell, agent attach and sandbox exec/files. A live session is cut within bex-api's 60 s cache + the gateway's 30 s + one `BEX_SSH_REVALIDATE_INTERVAL`.
- **Workspace Google login** (w7/m465, [ADR012 §9b](../../docs/ADR012-auth.md#9b-workspace-enforced-google-login-w7m465)) rides the same gate: `twofactor.Gate` reads both settings (`store.LoginRequirements`) and refuses the Google one first with `403 WORKSPACE_GOOGLE_LOGIN_REQUIRED`. What decides is `core.Identity.SignIn` (a closed `core.SignIn`: a Kratos session's `authentication_methods`, a human token's `ext.bex_sign_in` stamped by the dashboard consent acceptor) or, for a key, its creation stamp (Hydra `bex.co/created-sign-in`, `ssh_keys.created_sign_in`; unstamped keys predate the setting and are exempt), plus the member's linked Google account matching their email (`KratosIdentities.GoogleAccountMatches`, the stored ID token). Tickets and background work have no sign-in of their own and are decided by that account alone. New keys are stamped with `core.KeySignInStamp`, never unrecorded. The SSH verb carries a native key's stamp (`signIn`) and answers the refusal's `code`. Admin toggle: GraphQL `setWorkspaceRequireGoogleLogin`, Pro and higher (`core.FeatureGoogleLoginEnforcement`), lock-out guard `twofactor.Gate.SignedInWithGoogle`. Before an admin or an Org Owner turns either on, GraphQL `workspaceLoginRequirementImpact` / `organizationLoginRequirementImpact` list who it would block through the gate's own assessment (`twofactor.Gate.AssessMember`, `AssessAPIKey`, `AssessSSHKey`: `Check`'s rules and caches, no refusal counted; a lookup that cannot answer is `ErrAuthzUnavailable`, never an empty list; w7/m471). Kratos's settings flow asks `internal/settingsguard` (`POST /internal/kratos/settings-guard` on :8091) before saving an email change or an oidc unlink; an unlink naming a provider other than Google in the flow's `transient_payload` (the dashboard always names it) passes (w7/085).
- Store opt-in `BEX_CP_DB_URI`; unset → bex-api alone.
- **Operator-run verbs** carry no caller identity, so they never mount on :8090 and are excused from the authz/audit sweeps: `/api migrate-container-policy (<srv> | --all-native | --all) [--apply]` (one service, every native runtime service, or every service but a static site, onto `render-v1`), `/api platform-rebuild --since <RFC3339> [--apply] [--limit N]`, `/api revoke-oauth-grant <subject> (<client-id> | --all-clients) [--apply]`, and the Managed OIDC pair `/api oidc-rotate-key [--emergency] [--apply]` (adds a signing key that signs an hour later; `--emergency` signs at once and deletes every other key) and `/api oidc-test-token <tea-…> <srv-…>` (a token for the fixed audience `bex-oidc-verify`, which no provider accepts, for `scripts/oidc-issuer-verify.sh`; [runbook](../../docs/runbooks/oidc-key-rotation.md)). `platform-rebuild` rebuilds every source-built, non-Dockerfile, non-static service at its live commit as a `deployed_by_render` deploy, so a re-pinned toolchain (a runtime security patch) reaches running services. It is a client of the :8091 `POST /internal/platform-rebuild` verb behind `BEX_CP_TOKEN`. Run it through `.github/workflows/platform-rebuild.yml`: `plan` first, then `apply` in batches. `revoke-oauth-grant` cuts off one human's OAuth grant: it deletes the `(subject, client)` consent session at Hydra, advances the shared `oauth_revocations` marker for the pair (so every replica refuses the token at its next request, not after the 5 s cache window) and writes a `RevokeOAuthAccessEvent` audit row (verb `oauth.RevokeAccess`) in the ops workspace's trail (`internal/oauthgrant`; [runbook](../../docs/runbooks/oauth-grant-cutoff.md), [ADR012 §8d](../../docs/ADR012-auth.md#8d-revocation-latency-w21085)). It reads `BEX_HYDRA_ADMIN_URL`, `BEX_CP_DB_URI` and `BEX_OPS_WORKSPACE` from the pod's environment, so it needs no credential beyond the cluster access.
