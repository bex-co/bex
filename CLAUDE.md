# CLAUDE.md

bex is the open-source Render alternative — AI-native ([docs/ADR008-vision.md](docs/ADR008-vision.md)). A Go Kubernetes operator reconciles `App` CRs (`app.bex.co/v1alpha1`, namespace `bex-system`) into running services. All Go lives in **`lego/`** (Latin _legō_, "I assemble" — bex assembles bought bricks; the modules are the bricks): one image with multiple entrypoints from a Go workspace (`lego/go.work`) of four modules. **lego/types/** — the `App`/`Database` CRD contract (leaf; imports nothing); **lego/operator/** — the **manager** (`cmd/manager`), a mechanism-only, DB-free reconciler; **lego/backend/** — **bex-api** (`cmd/api`, the Render-compatible REST/GraphQL/MCP surface on :8090 + OpenFGA authz + API keys + metrics) and the isolated **SSH gateway** (`cmd/ssh-gateway`); **lego/cli/** — the `bex` CLI launcher (imports the pinned upstream Render CLI; released via the `bex-cli/v*` tag train, not the platform image). Dependency arrows point one way: `operator → types ← backend`; the operator never imports the backend, and `cli/` imports none of the three.

## Repo map

- `lego/` — **the product: all Go**, self-contained (workspace `go.work`, `Dockerfile` + `.dockerignore`; build context is `lego/`). Overview: [`lego/README.md`](lego/README.md); workspace commands + Go rules: [`lego/CLAUDE.md`](lego/CLAUDE.md).
  - `lego/types/` — the `App`/`Database` CRD types (`app.bex.co/v1alpha1`); leaf, imports nothing.
  - `lego/operator/` — the operator (kubebuilder): manager reconciles CRs → Deployment/Service/Ingress (mechanism, no DB). Owns codegen, `config/`, `hack/`. See `lego/operator/CLAUDE.md`.
  - `lego/backend/` — the business-logic services: **bex-api** (Render REST/GraphQL/MCP + authz + API keys + metrics) and the isolated SSH gateway. Imports `types/`, never `operator/`. See `lego/backend/CLAUDE.md`.
  - `lego/cli/` — the `bex` CLI launcher: imports the pinned upstream Render CLI (`render-oss/cli`, no fork) and maps Bex defaults; imports none of the other modules. Released as user-installed binaries via the `bex-cli/v*` tag train (`cli-release.yml`), excluded from the platform image and from `deploy.yml`'s trigger paths. See `lego/cli/README.md` + `docs/bex-cli.md`.
- `dashboard/` — the human-facing dashboard (TanStack Start + Apollo + shadcn), client of `bex-api`'s GraphQL. See `dashboard/CLAUDE.md` before editing.
- `infra/` — day-0 provisioning: Terraform + Cluster API; overlays `local-capd` (Docker) ⇄ `hetzner-caph`. The operator never references `infra/`.
- `deploy/gitops/` — day-1+: what Argo CD reconciles into the cluster (zot registry, opensandbox controller, CAPI, autoscaler, bex itself). GitOps is for platform infra, not user deploys.
- `examples/` — `whoami-app.yaml` (prebuilt image), `hello-go/` (build-from-git sample).
- `scripts/` — local-cluster and app helpers (below). `up.sh` / `start-opensandbox*.sh` are the legacy single-host path.
- `docs/` — the real documentation; one file per topic, indexed below.
- `.pm/` — internal PM notes and milestone logs. Not documentation; may be stale or aspirational.

## Commands

All Go is a workspace under `lego/`; the `make` targets live in **`lego/operator/`**. Full commands + workspace conventions (Go-version split, codegen, lint, the CLI tag train): [lego/CLAUDE.md](lego/CLAUDE.md). The CI-enforced suites are `make test` (operator, from `lego/operator/`), `cd lego/backend && go test ./...`, `make lint` (all four modules), and `cd lego/cli && go test ./...`. All three platform test suites (`make test`, backend `go test ./...`, dashboard `yarn test`) **must pass before `deploy.yml` builds or pushes any image**: `build-and-deploy` `needs:` all three test jobs.

## Local cluster workflow

- `bash scripts/mock-cluster.sh` — full local mock (kind infra cluster + Cluster API + CAPD app cluster). Writes kubeconfig to `infra/local/bex.kubeconfig` (gitignored credential — never commit or print it).
- `bash scripts/mock-cluster.sh scale N` — add/remove worker machines.
- `scripts/app-apply.sh <bex.yml>` — apply a `render.yaml`-shaped `bex.yml` as an App CR (`DRY_RUN=1` to preview).
- `scripts/deploy-sample.sh` — deploy the hello-go sample.
- `kubectl get apps.app.bex.co` — App status: phase / revision / url.

## Rules

- **Never `git commit` or `git push` unless the user runs `/ship` (Claude) or invokes `$ship` (Codex).** Leave work uncommitted otherwise.
- Never commit or print `.env` or `*.kubeconfig` contents.
- **Keep skill implementations canonical under `.claude/skills/<name>/SKILL.md`.** Every `.agents/skills/<name>` entry must be the relative symlink `../../.claude/skills/<name>`, the two directories must have identical names, and the retired `.claude/commands/` directory must remain absent. Run `bash scripts/skill-layout-validate.sh` after changing skills.
- **Keep `.env.example` in sync with `.env`'s variable names.** It's the single checked-in, value-less mirror of `.env`, serving both the local runtime env and the CI-secrets source (`bash scripts/gh-secrets.sh` pushes the filled `.env` into this repo's GitHub Actions secrets). Whenever a var is added, renamed, or removed, mirror the change (name + comment, never the value) so `cp .env.example .env` never falls out of date. (There is no longer a separate `.env.template` — the two were merged into `.env.example`.)
- Go-wide rules (Apache-2.0 boilerplate header, minting ids only through `lego/backend/internal/id`): [lego/CLAUDE.md](lego/CLAUDE.md) § Rules.
- Markdown is CI-checked: `npx prettier@3.4.2 --write "**/*.md"` before finishing doc changes.
- **`.pm` done items move to `done/` folders — move the entire folder, leave nothing behind.** Full conventions (task/milestone/inbox move rules, three-place status sync): `.pm/CLAUDE.md`.
- Playwright MCP writes to `.playwright-mcp/` (`--output-dir` in `.mcp.json`, gitignored). When taking screenshots, pass a **bare** filename (e.g. `render-logs.png`) so it lands there — never a path that resolves to the repo root. If an image ever appears at the project root, move it into `.playwright-mcp/`.
